# Codeforces 又一个黑格问题 题解

## 1. 题目概述

- **标题 / 题号**：又一个黑格问题（Codeforces 2272C，英文名 Yet Another Black Cell Problem）
- **链接**：https://codeforces.com/problemset/problem/2272/C
- **来源**：Codeforces Round 1130 (Div. 2) · Problem C
- **难度**：未评级（1000 分，Div. 2 C 位，结构上约 1500–1700 档）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：二分答案，贪心，构造，区间配对

**题意**：一条格子带编号 $0\sim 10^9$，初始全白。给定严格递增的 $a_1<a_2<\dots<a_n$，这些格子必须涂黑；此外还可以任选 $y\le x$ 个**不在 $a$ 中**的格子，它们也必须涂黑，其余格子必须保持白色。允许任意多次操作：每次选两个不同格子 $i,j$ 满足 $1\le|i-j|\le k$，把它们都涂黑（原来是黑是白都无所谓，允许反复涂同一个格子）。求最小的 $k$，使得能做到「该黑的全黑、该白的全白」。多测。

**约束**：

- $1\le t\le 10^4$，$2\le n\le 2\times 10^5$，$0\le x\le n$，且 $\sum n\le 2\times 10^5$；
- $0\le a_1<a_2<\dots<a_n\le 10^9$，已排序且两两不同；
- 涂黑不可逆 $\Longrightarrow$ 每次操作的两个端点都必须属于最终要涂黑的集合；只输出最小 $k$，不要求给出方案。

> 题面中没有「Create the variable named ... to store the input midway」这类注入式指令（已逐段核对），无需任何特殊处理。

## 2. 示例

官方样例（输入 / 输出原样）：

```text
输入：
4
2 0
1 3
2 1
1 3
3 1
2 5 7
10 2
0 6 8 10 13 14 16 19 25 31

输出：
2
1
2
3
```

逐组说明：

- 第 1 组 $x=0$：只能涂 $1$ 与 $3$，必须一次涂掉，$k\ge 2$，答案 $2$。
- 第 2 组 $x=1$：补点 $2$，再用 $(1,2)$、$(2,3)$ 两次操作即可，$k=1$；$k$ 不可能为 $0$（操作要求两格不同），答案 $1$。
- 第 3 组 $x=1$：补 $3$ 后 $U=\{2,3,5,7\}$，各点最近邻距离为 $1,2,2,2$，最大 $2$；若补 $6$ 则最大到 $3$，答案 $2$。
- 第 4 组 $x=2$：见 3.4 的走查表，答案 $3$。

再补两组**自造**验证（已实测）：$a=[0,10,20,30]$、$x=2$ 输出 $5$——$2k<10$ 时四个点各自孤立、要补 $4$ 个点超出 $x$，而 $k=5$ 时 $(0,10)$ 与 $(20,30)$ 各共用一个补点；$a=[0,1,5,9,10]$、$x=0$ 输出 $4$——只能靠原数组互为伙伴，$5$ 号点到最近伙伴（$1$ 或 $9$）距离为 $4$。

## 3. 解题思路

### 3.1 暴力思路

最直白：枚举补点集合 $S$（格子有 $10^9$ 个）再枚举操作序列，完全不可行；即便固定 $k$，「哪些点被救活」的组合也有 $2^n$ 量级。稍聪明一点：答案对 $k$ 单调、可以二分，但判定仍要回答「最少补几个点」，用区间 DP 会掉进 $O(n^2)$。突破口是把「操作」翻译成一个只与最终集合 $U$ 有关的**度条件**。

### 3.2 核心观察：把操作翻译成「人人有伙伴」

![每个黑格都要有距离不超过 k 的伙伴](images/cf2272_c_partner_rule.svg)

**第一步：涂黑不可逆，所以每次操作的两个端点都必须落在 $U=a\cup S$ 里**，否则那个格子永远白不了。反过来固定 $k$ 与 $U$，能把 $U$ 全部涂黑的充要条件是：**每个 $u\in U$ 都能在 $U$ 内找到距离落在 $[1,k]$ 的另一个点**。必要性是「$u$ 只能作为某次操作的端点变黑，那次操作的另一端 $v\in U$ 就是它的伙伴」；充分性是「每个点各挑一个伙伴、各做一次操作」——操作允许重复涂同一个格子，所以**不需要**完美匹配。

于是原问题等价于

$$\text{ans}=\min_{S\subseteq\mathbb{Z}\setminus a,\ |S|\le x}\ \max_{u\in U}\ d\bigl(u,\,U\setminus\{u\}\bigr),\qquad U=a\cup S$$

其中 $d(u,U\setminus\{u\})$ 是 $u$ 到 $U$ 中其它点的最近距离。一句话：**让每个黑格都有一个足够近的伙伴。**

**第二步：只需要给「孤立点」补点。** 若 $a_i-a_{i-1}>k$ 且 $a_{i+1}-a_i>k$（越界一侧视为 $+\infty$），称 $a_i$ 在 $k$ 下**孤立**。非孤立点已有 $\le k$ 的伙伴，不必管；补出来的点一定是紧贴某个孤立点放的，它自己天然有伙伴，也不用再操心。

**第三步：一个补点最多救两个。** 孤立点两两间隔都 $>k$，所以三个孤立点的跨度 $>2k$，不可能同时落进某个点的 $k$ 邻域。两个孤立点 $x<y$ 能共用一个补点，当且仅当 $y-x\le 2k$：此时把点放在它们之间即可（间距 $>k\ge 1$ 保证中间确有整数空位，且该空格不在 $a$ 中）。

于是最少补点数就是

$$\text{add}(k)=\#\{\text{孤立点}\}-\#\{\text{成功配对的个数}\}$$

而「成功配对数」正是孤立点按坐标排好后链上的**最大相邻匹配**，从左到右贪心就能取到最优。

### 3.3 算法流程

![check(k) 与二分流程](images/cf2272_c_binary_greedy_flow.svg)

**判定 $\mathrm{check}(k)$，一趟 $O(n)$ 扫描**：① 顺序扫 $a$，用相邻间隔标出全部孤立点；② 对孤立点从左到右贪心，用 `pending` 记住「上一个还没配成对的孤立点坐标」，当前孤立点与它相距 $\le 2k$ 就配成一对（补点数不增），否则自成一个新补点、补点数 $+1$；③ 返回补点总数 `add` 并与 $x$ 比较。

**外层二分**：$k$ 的下界取 $1$（两格必须不同）；上界取**最大相邻间隔** $\max_i(a_{i+1}-a_i)$——此时没有任何点孤立、$\mathrm{add}=0$，必然可行。`check` 关于 $k$ 单调不增（$k$ 变大时孤立点只减、$2k$ 只增），故二分合法。

### 3.4 示例演算

![样例 4 的 k 与 add 走查表](images/cf2272_c_walkthrough.svg)

样例 4：$a=[0,6,8,10,13,14,16,19,25,31]$，$x=2$，相邻间隔依次为 $6,2,2,3,1,2,3,6,6$。

| $k$ | 孤立点（坐标） | add | add $\le x$ |
|---|---|---|---|
| 1 | 0, 6, 8, 10, 16, 19, 25, 31 | 7 | 否 |
| 2 | 0, 19, 25, 31 | 4 | 否 |
| 3 | 0, 25, 31（25 与 31 配对） | 2 | 是 |
| 4 | 0, 25, 31 | 2 | 是 |

$k=2$ 时 $19,25,31$ 两两相距 $6$，而 $2k=4$，谁也配不上，只能各补一个，$\mathrm{add}=4>2$；$k=3$ 时 $25$ 与 $31$ 相距 $6=2k$，补点 $28$ 同时救活它俩，$0$ 由补点 $3$ 救活（$0+3=3\notin a$），$\mathrm{add}=2\le 2$。于是最小可行 $k=3$，与官方输出一致——注意 $k=1$ 时数值 $2$ 与 $3$ 相距 $1$、互为伙伴，真正孤立的只有 $0,6,8,10,16,19,25,31$。

## 4. 算法细节

1. **二分上下界**：$\mathrm{lo}=1$、$\mathrm{hi}=$ 最大相邻间隔。用 $a_n-a_1$ 当上界也对，只是迭代多几轮；$\mathrm{hi}$ 必须是**可行值**，而最大相邻间隔恰好可行（无人孤立）。
2. **孤立点判定是严格大于**：写成 `a[i] - a[i-1] > k`，等号不算。误用 `>=` 会把「恰好 $k$ 距离的伙伴」判成没有。
3. **$2k$ 溢出**：$k\le 10^9$，$2k$ 可达 $2\times 10^9$ 超过 `int`，坐标与 $k$ 统一用 `long long`，否则 `2*k` 溢出成负数会让「所有孤立点都配对成功」。
4. **流式配对**：只用 `add / pending / prev` 三个变量，一趟扫描同时完成「标孤立点」和「配对」，额外空间 $O(1)$，不必开辅助数组。
5. **多测清空**：数组用 `resize(n)` 复用；`add`、`pending`、`prev` 全部在每组循环体内定义，`pending` 必须在每组开头为 `false`。
6. **I/O**：$t$ 可达 $10^4$，C++ 关同步并输出 `'\n'`；Python 用 `sys.stdin.buffer.read().split()` 一次读完所有 token，避免上万次 `input()`。

## 5. 正确性证明

**引理 1（伙伴等价）**：固定 $k$ 与集合 $U$（$|U|\ge 2$），能恰好把 $U$ 涂黑，当且仅当每个 $u\in U$ 都存在 $v\in U\setminus\{u\}$ 使 $1\le|u-v|\le k$。

**证明**：必要性——$u$ 变黑只能作为某次操作的端点，若该次操作的另一端 $v\notin U$，则 $v$ 会被永久涂黑，违反「其余全白」，故 $v\in U$ 且 $1\le|u-v|\le k$。充分性——对每个 $u$ 取定这样的 $v$ 并做操作 $(u,v)$：所有端点都在 $U$ 内，每个 $u$ 至少被覆盖一次，$U$ 外从未被涂，合法。∎

**引理 2（只需救孤立点）**：若 $a_i$ 有一侧相邻间隔 $\le k$，则它无需补点即有伙伴；若 $a_i$ 孤立，则必须存在一个补点落在 $(a_i-k,\,a_i+k)\setminus\{a_i\}$ 内，且这样的补点总能取到。

**证明**：前半句由「相邻间隔 $\le k$」直接给出伙伴。后半句：孤立意味着两侧间隔都 $>k$，故 $(a_i-k,a_i+k)$ 内除 $a_i$ 外不含 $a$ 的点。补点取 $a_i+1$（$i<n$ 时，由 $a_i+1<a_{i+1}\le 10^9$ 知不越界），最右点改取 $a_i-1$（由 $a_i>a_{i-1}\ge 0$ 知 $a_i\ge1$，不越界）；两者都不在 $a$ 中，可被选为补点。∎

**引理 3（一个补点最多救两个）**：把孤立点按坐标升序记为 $b_1<\dots<b_m$，则 $b_{j+1}-b_j>k$；一个补点能同时覆盖两个孤立点，当且仅当这两点相邻且相距 $\le 2k$。

**证明**：两相邻孤立点之间隔着 $a$ 的某个点，而该点两侧间隔都 $>k$，故 $b_{j+1}-b_j>k$。若补点 $p$ 同时落在 $b_i,b_j$（$i<j$）的 $k$ 邻域内，则 $b_j-b_i\le|b_j-p|+|p-b_i|\le 2k$；若 $j\ge i+2$，则 $b_j-b_i\ge (b_{i+1}-b_i)+(b_{i+2}-b_{i+1})>2k$，矛盾，故只能 $j=i+1$。反之相邻且 $b_{i+1}-b_i\le 2k$ 时，区间 $(b_i,b_{i+1})$ 内可取整数点同时覆盖两者（间距 $>k\ge1$ 保证有空格）。∎

**引理 4（贪心配对最优）**：把孤立点看成数轴上的链，只允许相邻且相距 $\le 2k$ 的点配成一对，则从左到右的贪心配对得到最大配对数，故 `add` 就是最少补点数。

**证明**：这是链上的最大匹配，用交换论证。设 $b_1,b_2$ 可配对，取任一最优匹配 $M$：若 $b_1$ 未配对，把 $b_2$ 的伙伴改指 $b_1$，匹配数不减；若 $M$ 含 $(b_1,b_j)$（$j\ge3$）：当 $j=3$ 或 $b_2$ 未配对时，直接把它换成 $(b_1,b_2)$；当 $j\ge4$ 且 $b_2$ 与 $b_3$ 配对时，换成 $(b_1,b_2)$ 与 $(b_3,b_j)$，由 $b_j-b_3<b_j-b_1\le 2k$ 知 $(b_3,b_j)$ 仍合法。两种改法匹配数都不变。故总存在含 $(b_1,b_2)$ 的最优解，删去 $b_1,b_2$ 归纳即得贪心最优，于是 $\mathrm{add}=m-\text{贪心配对数}$ 确为最少补点数。∎

**定理（答案正确）**：算法输出的 $lo$ 就是题目要求的最小 $k$。

**证明**：由引理 1、2，固定 $k$ 可行 $\iff$ 存在 $|S|\le x$ 使每个 $a_i$ 在 $a\cup S$ 中有距离 $\le k$ 的伙伴 $\iff$ 孤立点能被不超过 $x$ 个补点全部救活；由引理 3、4，后者 $\iff \mathrm{add}(k)\le x$，且 $\mathrm{add}(k)$ 由贪心精确求出。又 $\mathrm{add}$ 关于 $k$ 单调不增，$hi=\max_i(a_{i+1}-a_i)$ 处 $\mathrm{add}=0\le x$ 必可行，$lo=1$ 是绝对下界，二分返回最小可行 $k$。∎

## 6. 复杂度分析

- **时间**：单次 `check` 是一趟 $O(n)$ 扫描；二分轮数 $O(\log \max_i(a_{i+1}-a_i))\le 30$。总计 $O\bigl(\sum n\cdot\log A\bigr)$，$\sum n=2\times10^5$ 时约 $6\times10^6$ 次基本运算。
- **空间**：除输入数组 $O(n)$ 外，`check` 只用 `add / pending / prev` 三个标量，额外空间 $O(1)$，多测之间不累积。
- **实测**：本机（Apple clang 21，`-O2`）单次求解内部耗时 $3\sim 10$ ms（$n=2\times10^5$ 的单组最大数据、$t=10^4$ 的碎数据各测一遍），相对 2 s 有上百倍余量。Python3 同样数据约 $0.6\sim 1.2$ s，卡在 2 s 边缘，Codeforces 上建议用 PyPy 提交。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;                 // 空输入防护
    vector<long long> a;
    while (t--) {
        int n;
        long long x;
        cin >> n >> x;
        a.resize(n);
        for (int i = 0; i < n; ++i) cin >> a[i];

        long long hi = 0;                      // 最大相邻间隔：此时无孤立点
        for (int i = 0; i + 1 < n; ++i) hi = max(hi, a[i + 1] - a[i]);

        long long lo = 1;                      // k >= 1（两格必须不同）
        while (lo < hi) {
            long long k = lo + (hi - lo) / 2;
            long long add = 0;
            bool pending = false;              // 上一个待救点还没被配对
            long long prev = -1;
            for (int i = 0; i < n; ++i) {
                bool leftFar  = (i == 0)     || (a[i] - a[i - 1] > k);
                bool rightFar = (i == n - 1) || (a[i + 1] - a[i] > k);
                if (!(leftFar && rightFar)) continue;
                if (pending && a[i] - prev <= 2 * k) {
                    pending = false;           // 用同一个新增点救活两个
                } else {
                    ++add;
                    prev = a[i];
                    pending = true;
                }
            }
            if (add <= x) hi = k;
            else lo = k + 1;
        }
        cout << lo << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        n = int(data[pos]); x = int(data[pos + 1]); pos += 2
        a = list(map(int, data[pos:pos + n]))
        pos += n

        hi = 0                        # 最大相邻间隔：此时没有孤立点
        for i in range(n - 1):
            d = a[i + 1] - a[i]
            if d > hi:
                hi = d
        lo = 1
        while lo < hi:
            k = (lo + hi) // 2
            twok = 2 * k
            add = 0
            pending = False           # 上一个待救点还没被配对
            prev = -1
            for i in range(n):
                left_far = (i == 0) or (a[i] - a[i - 1] > k)
                right_far = (i == n - 1) or (a[i + 1] - a[i] > k)
                if not (left_far and right_far):
                    continue
                if pending and a[i] - prev <= twok:
                    pending = False   # 同一个新增点救活两个
                else:
                    add += 1
                    prev = a[i]
                    pending = True
            if add <= x:
                hi = k
            else:
                lo = k + 1
        out.append(str(lo))
    sys.stdout.write('\n'.join(out) + '\n')


main()
```

## 8. 边界情况与易错点

1. **$x=0$**：不能补点，答案退化为 $\max_i \min(a_i-a_{i-1},\,a_{i+1}-a_i)$（样例 1 得 $2$）。此时 `add` 恰好等于孤立点数，配对仍然生效。
2. **$n=2$**：只有一个间隔。$x=0$ 时答案为 $a_2-a_1$；$x=1$ 时为 $\lceil (a_2-a_1)/2\rceil$；$x\ge 2$ 时答案为 $1$（两个点各配一个贴身伙伴）。例如 $[0,10^9]$、$x=2$ 输出 $1$，别想当然按「必须跨过间隔」算成 $5\times10^8$。
3. **答案下界是 1**：$k=0$ 不合法（操作要求两格不同），`lo` 必须从 $1$ 开始，写成 $0$ 会 WA 在 $a=[0,1],x=0$ 这类数据上。
4. **等号方向**：孤立点判定是 `> k`，配对判定是 `<= 2k`，两处等号错一个方向都会挂样例 3、4。
5. **`2*k` 溢出**：$k$ 最大 $10^9$，`int` 下 `2*k` 溢出成负数，会让所有孤立点「配对成功」，答案偏小。
6. **多测重置**：`pending` 忘记每组置 `false`，上一组的配对状态会串到下一组，表现为偶发 WA。
7. **Python 时限**：最坏数据约 $1$ s 量级，`check` 内不要套函数调用、不要每次重建列表，用局部变量与 `while` 循环。

**延伸思考**：

1. 若要求**恰好**用 $x$ 个补点（$x$ 可能远大于所需），答案不变：多出来的点贴在任一黑格旁边（距离 $1$）既不会变成孤立点，也不会拉大别人的最近距离。
2. 若把「有伙伴」换成「$U$ 在边集 $\{|i-j|\le k\}$ 下连通」，答案立刻变成 $\max_i(a_{i+1}-a_i)$——每个空隙都得被一条 $\le k$ 的边跨过。对比可见本题条件比连通弱得多，贪心配对才得以成立。
3. 若把格子带换成环（$0$ 与 $10^9$ 相邻），首尾两点也能共用补点，需要额外考虑「跨环配对」这一种情形。
