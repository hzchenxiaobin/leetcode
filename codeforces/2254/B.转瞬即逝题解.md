# Codeforces 转瞬即逝 题解

## 1. 题目概述

- **标题 / 题号**：转瞬即逝（Codeforces 2254B，英文名 Evanescent）
- **链接**：https://codeforces.com/problemset/problem/2254/B
- **来源**：Codeforces Round 1114 (Div. 3) · Problem B
- **难度**：900（Div. 3 B）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：实现，字符串，双指针（压缩成段 + 分情况判定）

**题意**：记 $f(s)$ 为 $s$ 的**压缩形式**——把每一段极长连续相同字符压成一个该字符；例如 $f(\text{"aabbcc"}) = \text{"abc"}$，空串长度为 $0$。现在给定长度为 $n$ 的小写字符串 $s$，你必须**恰好删掉一个**字符 $s_i$，且下标受限于 $2 \le i \le n-1$（即**首尾字符不能删**），得到 $s'$，求 $\lvert f(s')\rvert$ 的最小可能值。多测：第一行 $t$，每组给出 $n$ 与 $s$，逐组输出一个整数。

**约束**：

- $1 \le t \le 10^4$
- $3 \le n \le 2\times10^5$，且 $\sum n \le 2\times10^5$：必须单组 $O(n)$、整体线性，任何 $O(n\log n)$ 以上的做法都不必要
- $s$ 只含小写拉丁字母
- 删除位置限定 $2 \le i \le n-1$：这一条决定了「首尾段里的孤立字符删不掉」，是本题唯一的额外约束

## 3. 解题思路

### 3.1 暴力思路

枚举 $i = 2,\dots,n-1$，对每个 $i$ 真的构造 $s'$ 再扫一遍求 $\lvert f(s')\rvert$：单组 $O(n^2)$，$n = 2\times10^5$ 时约 $2\times10^{10}$ 次操作，2 s 完全不可能。即使改成「只检查 $s_{i-1}$ 与 $s_{i+1}$」的 $O(1)$ 增量，也还得回答一个必须先想清楚的问题：**删掉 $s_i$ 之后段数到底减少了多少？** 这正是本题的全部内容——一旦答完，连枚举都几乎不需要。

### 3.2 核心观察：答案只可能是 $k$、$k-1$、$k-2$

![删一个字符的三种结局](images/cf2254_b_run_model.svg)

把 $s$ 压缩成 $k$ 个**极大同色段** $r_1,\dots,r_k$，第 $j$ 段颜色为 $c_j$、占据区间 $[L_j, R_j]$。相邻段必然异色，即 $c_j \ne c_{j+1}$。

删掉 $s_i$ 之后，整条串里**唯一被改变的相邻关系**是 $s_{i-1}$ 与 $s_{i+1}$：它们原本被 $s_i$ 隔着，现在直接相邻了。于是只需按 $s_i$ 所在段的长度分两种情形：

- **情形 A：$\lvert r_j\rvert \ge 2$**（$j$ 为 $s_i$ 所在段）。删一个字符后这一段还剩至少一个字符，它与左右邻段仍然异色，**段数不变，仍是 $k$**。
- **情形 B：$\lvert r_j\rvert = 1$**。这个段整个消失了。又因为 $i \ne 1, n$，必有 $1 < j < k$，于是 $r_{j-1}$ 与 $r_{j+1}$ 由「隔着 $r_j$」变成**直接相邻**：
  - 若 $c_{j-1} \ne c_{j+1}$：两段各自成段，段数变成 $k-1$；
  - 若 $c_{j-1} = c_{j+1}$：两段同色合并，段数变成 $k-2$。

所以

$$\lvert f(s')\rvert \in \{\,k-2,\ k-1,\ k\,\}$$

**只需在这三个数里取最小**。注意「两侧同色」是可能的：相邻段异色只约束 $c_{j-1}\ne c_j$ 与 $c_j \ne c_{j+1}$，并不约束 $c_{j-1}$ 与 $c_{j+1}$（`aba` 这种形状正是 $k-2$ 的来源）。

还有一条容易漏的细节：**若唯一的那个字符属于第 $1$ 段或第 $k$ 段，它就是 $s_1$ 或 $s_n$，不允许删**，这种单元素段必须跳过。

### 3.3 算法流程

![判定流程](images/cf2254_b_decision_flow.svg)

1. **一趟压段**：`while` 把 $j$ 推到当前段末尾，记下起点 $st[j]$ 与段长 $sz[j]$，令 $i = j+1$ 继续；得到段数 $k$。
2. **初值**：$ans \leftarrow k$。
3. **枚举每个段 $j$**：若 $sz[j] \ne 1$，删它不会改变段数，`continue`；若 $st[j] = 0$ 或 $n-1$，该字符是首尾，不许删，`continue`。
4. **算候选**：$cand \leftarrow k-1$；若 $j-1 \ge 0$、$j+1 < k$ 且 $s[st[j-1]] = s[st[j+1]]$，则 $cand \leftarrow k-2$。
5. $ans \leftarrow \min(ans, cand)$，最后输出 $ans$。

**为什么初值可以放心取 $k$？** 因为 $k$ 不可达只有一种情况：所有段长都为 $1$。此时 $k = n$，而除首尾外的每个位置都是单元素段，第 3 步一个也不会漏，必定给出 $\le k-1$ 的候选把 $ans$ 压下去。换言之「$k$ 不可达」蕴含「枚举一定有更小的候选」，多写一个 $k$ 不会让答案偏大（详见 §5 引理 3 与定理）。

### 3.4 示例演算

![官方样例走查](images/cf2254_b_walkthrough.svg)

- `abb`：段为 `a | bb`，$k=2$。唯一的单元素段是段 1（字符 $s_1$），不可删；`bb` 段长 2，删一个还剩一个 ⇒ 答案 $k = 2$。
- `abaa`：段为 `a | b | aa`，$k=3$。段 2 是孤立的 `b`，删掉后左右两个 `a` 段直接相邻且同色 ⇒ 合并，$3-2 = 1$。这就是 $k-2$ 的来源。
- `goodluckandhavefun`：共 17 段，只有 `oo` 长度为 2。内部全是单元素段，但逐一看过去没有任何一处左右同色（`d` 的邻居是 `o`、`l`，`a` 的邻居是 `h`、`v`……）⇒ 只能取 $17-1 = 16$。

三组数据分别落在 $k$、$k-2$、$k-1$ 上，说明三个取值都真的会出现，不能图省事只判其中一种。

## 4. 算法细节

1. **压段的写法**：外层 `i`，内层把 `j` 从 `i` 推到该段末尾，再 `i = j+1`。不要用「`s[i] != s[i-1]` 就开新段」的写法，否则要额外维护每段的区间，反而容易错。
2. **0/1-indexed 对齐**：题面是 1-indexed（$2 \le i \le n-1$），代码统一 0-indexed，于是合法判据变成 `p != 0 && p != n-1`，段间判据变成 `j > 0 && j+1 < k`。这两个短路条件**必须写在取 `s[st[j-1]]` 之前**。
3. **只存两个数组**：`st`（每段起点）与 `sz`（段长）就够，右端点可以现算；再省一点可以边压段边判定，空间 $O(1)$ 也行，但没必要。
4. **$ans$ 初值只能是 $k$**：写成 `1e9` 时，遇到 `abba` 这种「没有可删的单元素段」的数据会直接输出 `1e9`；写成 `1` 则会漏掉 $k$ 与 $k-1$。
5. **多测重建**：`st`、`sz` 每组重新建（或声明在循环体内）。$\sum n \le 2\times10^5$ 保证总清理量也是线性的，不必担心 $t = 10^4$ 的开销。
6. **I/O**：C++ 关同步 + `cin` 足够；Python 一次性 `read().split()`，并直接用 `bytes`（`data[pos]` 本身就是字节串，`s[i]` 取到 `int`），比先 `decode` 成 `str` 略快。
7. **千万别真的删字符**：`s.erase(i,1)` 是 $O(n)$，套在 $O(n)$ 的枚举里就退化成 $O(n^2)$，白扔了「$O(1)$ 判定」这个结论。
8. **无需特判无解**：$n \ge 3$ 保证可删位置（0-indexed 的 $[1,n-2]$）非空，答案一定存在。

## 5. 正确性证明

沿用 §3.2 的记号：$s$ 压缩为 $k$ 段 $r_1,\dots,r_k$，颜色 $c_j$，区间 $[L_j,R_j]$，相邻段异色。

**引理 1（局部性）**：删除 $s_i$（$2 \le i \le n-1$）只让 $s_{i-1}$ 与 $s_{i+1}$ 由「隔着 $s_i$」变为直接相邻，字符串中其他所有相邻对保持原样。

**证明**：删除只移除位置 $i$ 上的字符，其余字符相对顺序不变；原本的相邻对里只有 $(s_{i-1},s_i)$、$(s_i,s_{i+1})$ 消失，取而代之的是 $(s_{i-1},s_{i+1})$，其余相邻对原样保留。而压缩只取决于「每一对相邻字符是否相同」，故除涉及 $s_{i-1},s_{i+1}$ 的那一处外段边界都不动。∎

**引理 2（三值性）**：对任意合法 $i$，$\lvert f(s')\rvert \in \{k-2,\,k-1,\,k\}$。

**证明**：设 $s_i$ 属于段 $r_j$。
- 若 $\lvert r_j\rvert \ge 2$：删后 $r_j$ 至少还剩一个字符，它两侧仍是 $c_{j-1} \ne c_j$ 与 $c_j \ne c_{j+1}$，由引理 1 段数仍为 $k$。
- 若 $\lvert r_j\rvert = 1$：因 $i \ne 1$ 且 $i \ne n$，必有 $1 < j < k$。该段消失，由引理 1，$r_{j-1}$ 与 $r_{j+1}$ 成为相邻字符。若 $c_{j-1} \ne c_{j+1}$，两段各自独立，总段数 $k-1$；若 $c_{j-1} = c_{j+1}$，这两段（连同它们各自的内部字符）合并为一段，总段数 $k-2$。
两种情形穷尽了所有合法 $i$，故结论成立。∎

**引理 3（$k$ 可达当且仅当存在长 $\ge 2$ 的段）**：

**证明**：
- ($\Leftarrow$) 设 $\lvert r_j\rvert \ge 2$。若 $j = 1$，取 $i = 2$：由 $n \ge 3$ 得 $2 \le n-1$ 合法，且 $\lvert r_1\rvert \ge 2$ 说明 $s_2$ 仍在段 1 内；若 $j = k$，对称地取 $i = n-1$；若 $1 < j < k$，取 $i = L_j + 1$（由 $\lvert r_j\rvert \ge 2$ 得 $L_j+1 \le R_j$，且该位置既非 $1$ 也非 $n$）。三种取法删的都是同一个长 $\ge 2$ 段内的字符，由引理 2 得 $\lvert f(s')\rvert = k$。
- ($\Rightarrow$) 若所有段长都为 $1$，则 $k = n$，任意合法 $i$ 都落在单元素段上，由引理 2 得 $\lvert f(s')\rvert \le k-1 < k$。∎

**引理 4（$k-2$ 的判据）**：存在合法 $i$ 使 $\lvert f(s')\rvert = k-2$ $\iff$ 存在 $j$ 满足 $1 < j < k$、$\lvert r_j\rvert = 1$ 且 $c_{j-1} = c_{j+1}$。

**证明**：
- ($\Leftarrow$) 取 $i = L_j$。由 $\lvert r_j\rvert = 1$ 得 $L_j = R_j$，且 $1 < j < k$ 保证 $L_j \ne 1, n$，故 $i$ 合法。代入引理 2 的第二种情形即得 $k-2$。
- ($\Rightarrow$) 由引理 2，取到 $k-2$ 只有「删掉单元素段且两侧同色」这一条路径，那个段就是所需的 $j$。∎

**定理（算法正确性）**：算法输出的 $ans$ 等于 $\min_{2 \le i \le n-1}\lvert f(\text{删掉 }s_i\text{ 后})\rvert$。

**证明**：由引理 2，目标值只能是 $k-2,k-1,k$ 之一，而算法给出的每个候选都精确：初值 $k$ 在存在长 $\ge 2$ 的段时由引理 3 确实可达；对每个 $\lvert r_j\rvert = 1$ 且 $L_j \notin \{1,n\}$ 的段，候选 $k-1-[c_{j-1}=c_{j+1}]$ 与引理 2 的公式逐项一致（$1<j<k$ 自动给出 $j-1 \ge 0$、$j+1 < k$）。若存在长 $\ge 2$ 的段，则 $k$ 可行且所有单元素段的候选都已枚举，取 $\min$ 即真实最优；若所有段长都为 $1$，则 $k = n$，每个 $i \in [2,n-1]$ 都属于某个单元素段，循环至少执行一次并产出 $\le k-1$ 的候选，故 $ans \le k-1$——而 $k$ 恰是唯一不可达的值（引理 3 的 ($\Rightarrow$)），多写上它不会让 $ans$ 偏大。两种情形下 $ans$ 都等于真实最小值。∎

## 6. 复杂度分析

- **时间**：压段一趟 $O(n)$；枚举段 $O(k) \le O(n)$，每次 $O(1)$；单组 $O(n)$，总计 $O(\sum n) \le 2\times10^5$ 次比较。没有排序、没有二分、没有哈希。
- **空间**：`st`、`sz` 各 $O(k) \le O(n)$ 个 `int`，其余 $O(1)$；C++ 约 $1.6$ MB，Python 除 `read().split()` 的 token 列表外也是 $O(n)$。
- **实测**（本机 Apple clang `-O2` / Python 3，含进程启动与读入）：$n = 2\times10^5$ 的五类数据（全同字母 / 完全交替 `abab…` / $t=10^4$ 且 $\sum n = 2\times10^5$ / `aabb…` 块状 / 26 字母随机）上，C++ 为 $0.01$–$0.02$ s，Python3 为 $0.06$–$0.19$ s。对 2 s 时限有 **100 倍以上**余量，不需要任何常数优化。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;
    while (t--) {
        int n;
        string s;
        cin >> n >> s;

        // 一趟扫描：压成极大同色段，st[j] 为起点，sz[j] 为段长
        vector<int> st, sz;
        st.reserve(n); sz.reserve(n);
        for (int i = 0; i < n; ) {
            int j = i;
            while (j + 1 < n && s[j + 1] == s[i]) ++j;
            st.push_back(i);
            sz.push_back(j - i + 1);
            i = j + 1;
        }
        int k = (int)st.size();

        int ans = k;                          // 存在段长 >= 2 时，删它一个字符就能保住 k
        for (int j = 0; j < k; ++j) {
            if (sz[j] != 1) continue;         // 删后该段仍非空，段数不变
            int p = st[j];
            if (p == 0 || p == n - 1) continue;   // s_1 / s_n 不允许删
            int cand = k - 1;                 // 这个单元素段整个消失
            if (j > 0 && j + 1 < k && s[st[j - 1]] == s[st[j + 1]])
                cand = k - 2;                 // 左右两段同色，删完合并
            ans = min(ans, cand);
        }
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        pos += 1                             # 跳过 n，用 len(s) 更稳
        s = data[pos]
        pos += 1                             # bytes：s[i] 直接是 int，比较更快
        n = len(s)

        st, sz = [], []                       # 每段的起点与段长
        i = 0
        while i < n:
            j = i
            while j + 1 < n and s[j + 1] == s[i]:
                j += 1
            st.append(i)
            sz.append(j - i + 1)
            i = j + 1
        k = len(st)

        ans = k                               # 有段长 >= 2 时 k 一定可达
        for j in range(k):
            if sz[j] != 1:
                continue
            p = st[j]
            if p == 0 or p == n - 1:
                continue                      # 首尾字符不可删
            cand = k - 1
            if 0 < j < k - 1 and s[st[j - 1]] == s[st[j + 1]]:
                cand = k - 2                  # 左右邻段同色，删完合并
            ans = min(ans, cand)
        out.append(str(ans))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n = 3$**：可删位置只有 $i=2$ 一个，但三种答案都可能出现——`abb` → 2（$k$）、`abc` → 2（$k-1$）、`aba` → 1（$k-2$）。别把答案硬编码成 $k-1$。
2. **所有字符相同**：$k=1$，循环里 $sz[0] = n \ge 3$ 被全部跳过，输出 $1$。若把初值写成 $k-1$ 就会输出 $0$。
3. **完全交替 `abab…`**：$k=n$，每个内部位置的左右邻居都同色，答案 $n-2$。漏掉 `s[st[j-1]] == s[st[j+1]]` 这一项会输出 $k-1$，直接 WA。
4. **首尾段的单元素段**：如 `aab`（$k=2$，段 2 的唯一字符就是 $s_n$）答案仍是 $2$；必须用 `p == 0 || p == n-1` 挡掉，否则会误判成 $k-1$。
5. **$ans$ 初值**：只能是 $k$。取 `1e9` 时遇到 `abba` 这类没有候选的数据会输出 `1e9`；取 $1$ 则漏掉 $k$ 与 $k-1$。
6. **下标越界**：`s[st[j-1]]`、`s[st[j+1]]` 必须先由 `j > 0`、`j+1 < k` 短路。C++ 读 `st[-1]` 是 UB；Python 更隐蔽，`st[-1]` 会悄悄取到末元素而不报错。
7. **多测串味**：$t$ 可达 $10^4$，`st`、`sz` 忘记清空会让上一组的段混进这一组。把容器声明在每组内部最省心。
8. **溢出**：全程只有加减与下标比较，$n \le 2\times10^5$，`int` 足够，不需要 `long long`。

**延伸思考**：

- **允许删 $k$ 个字符**（仍不删首尾）：单个字符最多让段数掉 $2$，$m$ 次删除的直觉上界是 $k-2m$，但合并会连锁——删掉 `aba` 中间的 `b` 后，若再删别的字符可能触发新的合并。能否用「把段序列当成权值 $1$ 的路径、删一段等于删一个点」的模型做成 $O(n)$ 的贪心？
- **删任意字符（含首尾）**：首尾段也能被整段删掉，答案可以一路降到 $1$，判据从「单元素段」扩展成「可删的整段前缀/后缀」，需要重新刻画。
- **改成求最大值**：删除字符只会让 $\lvert f\rvert$ 变小或不变，所以最大值就是 $k$（若可达）；但若所有段长都为 $1$，最大值未必是 $k-1$——`abab` 里每个内部位置都让两侧同色，最大值只有 $k-2 = 2$。这个对偶问题比本题更值得写一写。
- **要求输出方案**：取 $\min$ 时顺手记下 $j$（以及是否发生了合并），就能输出被删下标；判定与构造在此题里是一一对应的。
