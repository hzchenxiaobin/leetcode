# Codeforces 激流 题解

## 1. 题目概述

- **标题 / 题号**：激流（Codeforces 2254A，英文名 Riptide）
- **链接**：https://codeforces.com/problemset/problem/2254/A
- **来源**：Codeforces Round 1114 (Div. 3) · Problem A
- **难度**：800
- **限制**：时间 1 s / 内存 256 MB
- **标签**：实现，排序（官方 tag：implementation、sortings；本质是「排序后只盯两端 + 常数轮模拟」）

**题意**：三个人 Alice、Bob、Charlie 初始分别持有 $a$、$b$、$c$ 枚代币。游戏按轮进行，**每轮开始前**检查一次：只要有任意两人代币数**相等**，游戏立刻结束（这一轮不算）。否则三人的代币数严格互不相同，由**严格最多**的人把**恰好 1 枚**代币交给**严格最少**的人，然后进入下一轮。问游戏一共进行多少轮。多测：第一行是测试组数 $t$，每组一行三个整数，逐组输出轮数。

**约束**：

- $1 \le t \le 10^3$
- $1 \le a, b, c \le 10$，值域极小
- 每轮转移**守恒**：总代币数 $a + b + c$ 始终不变，因此局面天然有界
- 输出非负整数，每组一行

## 2. 示例

官方样例（输入 / 输出原样）：

```text
输入：
6
1 2 3
4 6 1
3 3 7
1 7 10
6 1 9
1 1 1

输出：
1
2
0
3
3
0
```

官方解释的三个关键过程：`1 2 3` 里 $3$ 给 $1$ 一枚后变成 `2 2 2`，只走了 1 轮；`4 6 1` 里 Bob 连给 Charlie 两枚，变成 `4 4 3` 后结束；`3 3 7` 和 `1 1 1` 一开始就有两人相等，答案是 0。

补一组自造数据（值域内最大答案，答案为 4；`1 5 10` 走 4 轮后变成 `5 5 6`）：

```text
输入：
2
1 5 10
1 5 9

输出：
4
4
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法就是「照着题面跑」：每轮先扫一遍三人判有没有相等，再找出最大值与最小值的位置，做一次 $+1/-1$，计数器加一。

难点不在写，而在**敢不敢写 `while (true)`**：若过程可能死循环，这个写法就永远无法结束。所以暴力思路必须先补一句终止性论证。另外直觉上「值域只有 10，答案应该很小」也需要量化，否则无法说明复杂度。

### 3.2 核心观察：排序后只有两端在动，两个间隙每轮各减 1

![排序后最多者给最少者一枚](images/cf2254_a_round_move.svg)

只看三人的**相对大小**，与他们的名字无关，于是每轮开始时把三个数排序记作

$$x \le y \le z .$$

- 若 $x = y$ 或 $y = z$，由排序立即得到「有两人相等」，游戏结束；
- 否则 $x < y < z$，**最多者必是 $z$、最少者必是 $x$**，一轮之后局面恰为 $(x+1,\ y,\ z-1)$，其中 $x+1 \le y$、$z-1 \ge y$，等号成立就意味着下一轮开始前出现平局。

定义两个**间隙**

$$d_1 = y - x, \qquad d_2 = z - y, \qquad d_1 + d_2 = z - x .$$

若这一轮结束后仍互异（即 $x + 1 \ne y$ 且 $z - 1 \ne y$），那么新局面的两个间隙是

$$d_1' = y - (x+1) = d_1 - 1, \qquad d_2' = (z-1) - y = d_2 - 1 .$$

也就是说：**每进行一轮，两个间隙同时减 1；哪个间隙先归零，游戏就在那一轮结束时结束**。于是

$$\boxed{\ \text{答案} = \min(d_1,\ d_2)\ }$$

本题 $1 \le a,b,c \le 10$，故 $d_1 + d_2 \le 9$，答案至多 $\lfloor 9/2 \rfloor = 4$——**轮数是个不超过 4 的常数**，死循环的担心被彻底排除。

> 💡 这个闭式很有用，但也可以用另一种更直观的方式理解：$x$ 每轮涨 1、$z$ 每轮跌 1，谁先撞上不动的 $y$，游戏就在哪里结束，所以是「两边谁的路更短」。

### 3.3 算法流程：排序 + 常数轮模拟

![模拟流程](images/cf2254_a_simulation_flow.svg)

1. 读入 $a, b, c$，`rounds = 0`；
2. 把三个数排序成 $x \le y \le z$；
3. 若 $x = y$ 或 $y = z$，输出 `rounds` 并结束本组；
4. 否则执行 `x += 1`、`z -= 1`、`rounds += 1`，回到第 2 步。

第 3 步只比较**排序后的相邻两对**就够了：若 $x = z$ 则三者全相等，必然也满足 $x = y$。循环次数由 3.2 节知道不超过 4，写成 `while (true)` 完全安全。

也可以直接写闭式：排序后若不等则答案 $= \min(y-x,\ z-y)$，否则 0。两种写法等价（第 5 节给证明），本文代码用模拟——它逐字对应题面，最难写错。

![样例 4 的逐步走查](images/cf2254_a_walkthrough.svg)

样例 4 为 $a = 1,\ b = 7,\ c = 10$，排序后 $x = 1,\ y = 7,\ z = 10$，$d_1 = 6$、$d_2 = 3$：

| 轮次 | 排序后的 $(x, y, z)$ | $d_1$ | $d_2$ | 本轮动作 |
|------|----------------------|-------|-------|----------|
| 0 | $(1, 7, 10)$ | 6 | 3 | $10 \to 1$ |
| 1 | $(2, 7, 9)$ | 5 | 2 | $9 \to 2$ |

| 3 | $(4, 7, 7)$ | — | — | $7 = 7$，结束 |

进行完第 3 轮后 $y = z = 7$，游戏结束，答案 3；与 $\min(6, 3) = 3$ 一致。

## 4. 算法细节

1. **排序用内置 `sort`**：只有 3 个数，`sort(a, a + 3)` 或 Python 的 `sorted(...)` 都够快，也不用写三个 `if` 交换，代码短且不易错。若想完全避免函数调用，也可手工三次比较，但没必要。
2. **判等只比相邻**：排序后只需 `a[0] == a[1] || a[1] == a[2]`。写 `a[0] == a[2]` 会漏掉 `(1, 7, 7)` 这种「最大两人相等」的情况——这是本题最容易掉进的坑。
3. **循环写法**：用 `while (true)` + `break`，或用闭式一次算完。**不要**写成 `while (a[0] != a[1] && a[1] != a[2])` 之后在循环外补 `++rounds` 之类的变体，容易把「最后一轮是否发生」算错。
4. **多测重置**：`rounds` 必须在每组开始时置 0，数组 `a` 每次重新读入；把它定义在 `while (t--)` 外面会让第 2 组起答案叠加。
5. **不需要 `long long`**：所有中间量都不超过 $a+b+c \le 30$，`int` 绰绰有余；但保留 `int` 的同时要保证转移是「一端 $+1$、另一端 $-1$」，否则总代币数不守恒。
6. **I/O 加速**：$t \le 10^3$、每组 3 个整数，输入量不到 10 KB，`sync_with_stdio(false)` 只是习惯性动作；Python 用 `sys.stdin.buffer.read().split()` 一次读完，避免 `input()` 的逐行开销。
7. **输出格式**：每组一行一个整数，行尾换行；不要在最后多打空格，也不要把 0 打成空行。

## 5. 正确性证明

**引理 1（局面刻画）**：若某轮开始前三人代币数严格互异，把它们排序为 $x < y < z$，则这一轮之后三人的代币数集合恰为 $\{x+1,\ y,\ z-1\}$。

**证明**：严格互异说明最大值与最小值都唯一，题面规定「严格最多者给严格最少者 1 枚」，即 $z \gets z-1$、$x \gets x+1$，中间者不动。∎

**引理 2（第 $r$ 轮后的局面）**：设初始排序为 $x < y < z$。若前 $r$ 轮都已经实际进行（没有提前结束），则第 $r$ 轮结束后三人的代币数集合为 $\{x+r,\ y,\ z-r\}$。

**证明**：对 $r$ 归纳。$r = 0$ 时就是初始状态。设 $r$ 时成立。由于前 $r+1$ 轮都进行了，第 $r+1$ 轮开始前三数互异，由引理 1 这一轮把最小值加 1、最大值减 1；而 $\{x+r, y, z-r\}$ 中最小者是 $x+r$、最大者是 $z-r$（互异性保证 $x+r < y < z-r$），于是结束后为 $\{x+r+1,\ y,\ z-r-1\}$，符合 $r+1$ 的形式。∎

**引理 3（终止性）**：设初始排序为 $x < y < z$，$d_1 = y - x$、$d_2 = z - y$，则游戏恰好进行 $\min(d_1, d_2)$ 轮后结束；若初始就有两数相等，则为 0 轮。

**证明**：记 $r^\ast = \min(d_1, d_2)$。

- 当 $0 \le r < r^\ast$ 时，$x + r \le x + r^\ast - 1 < x + d_1 = y$，且 $z - r \ge z - r^\ast + 1 > z - d_2 = y$，故第 $r+1$ 轮开始时三数互异（$x+r < y < z-r$），该轮必定进行。由引理 2，第 $r+1$ 轮结束后局面为 $\{x+r+1,\ y,\ z-r-1\}$。因此至少进行 $r^\ast$ 轮。
- 第 $r^\ast$ 轮结束后：若 $r^\ast = d_1$，则 $x + r^\ast = y$；若 $r^\ast = d_2$，则 $z - r^\ast = y$；若两者相等则同时成立。无论哪种，第 $r^\ast + 1$ 轮开始前都有两人相等，游戏结束。

两个方向合起来，轮数恰为 $r^\ast$。初始就有相等时，第 1 轮开始前即结束，为 0 轮。∎

**定理 1（模拟正确）**：3.3 节的模拟算法输出的 `rounds` 等于题面定义的游戏轮数。

**证明**：算法每一轮做的事与题面完全一致：先排序（不改变集合，只确定谁是最大、最小），再判「是否有两人相等」，相等则立即退出，否则执行引理 1 描述的转移并让计数器加一。因此算法退出时的计数器恰为「已经完整进行过的轮数」，即题目所求。由引理 3，退出必然发生，且轮数不超过 $\min(d_1,d_2) \le 4$，循环不会不终止。∎

**定理 2（闭式等价）**：排序后若两数相等则答案为 0，否则答案为 $\min(y-x,\ z-y)$。

**证明**：前者由题面「开始前检查」立即得到；后者就是引理 3 的结论。∎

## 6. 复杂度分析

- **时间**：单组 $O(1)$。排序 3 个数是常数，循环轮数由引理 3 不超过 $\min(d_1,d_2) \le 4$（值域 $1..10$ 内实测最大答案正是 4，例如 `1 5 9`、`1 5 10`），每轮只有一次排序与常数次加减。总计 $O(t) \le 1000$ 次基本运算。
- **空间**：$O(1)$。只存三个整数与计数器；Python 版本一次性 `split()` 全部输入，约 $3 \times 10^3$ 个短字符串，远在 256 MB 之内。
- **实测**：$t = 1000$ 的最大规模输入下，C++ 约 4.7 ms、Python 约 20 ms（含进程启动，5 次取最好），相对 1 s 的时限有 50 倍以上余量。即便值域放大到 $10^9$，改为闭式后仍是 $O(1)$。

## 7. 参考代码

### C++17

```cpp
#include <algorithm>
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;              // 空输入防御
    while (t--) {
        int a[3];
        cin >> a[0] >> a[1] >> a[2];
        int rounds = 0;                     // 每组重新初始化
        while (true) {
            sort(a, a + 3);                 // 排序后 a[0] <= a[1] <= a[2]
            if (a[0] == a[1] || a[1] == a[2]) break;  // 有两数相等，本轮不发生
            ++a[0];                         // 最少者 +1
            --a[2];                         // 最多者 -1
            ++rounds;
        }
        cout << rounds << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:                       # 空输入防御
        return
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        x = sorted((int(data[pos]), int(data[pos + 1]), int(data[pos + 2])))
        pos += 3
        rounds = 0
        # 三数严格互异时才进行一轮：最多者给最少者一枚
        while x[0] != x[1] and x[1] != x[2]:
            x[0] += 1
            x[2] -= 1
            rounds += 1
            x.sort()
        out.append(str(rounds))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **一开始就有两人相等**：`3 3 7`、`1 1 1` 都应输出 0。注意检查必须在**每轮开始前**做，第一轮也不例外——不要先转移再检查。
2. **只比较 `a[0] == a[2]` 会漏判**：排序后最大两人相等（如 `1 7 7`）时，答案同样是 0，正确写法是检查相邻两对。
3. **答案为 0 不是「无解」**：直接输出 `0`，不要输出空行或 `-1`。
4. **答案并不总是 0 或 1**：值域内最大答案是 4（`1 5 9`、`1 5 10` 等），只写「模拟一轮再判」会在这类数据上 WA。
5. **多测清空**：`rounds` 在每组内部初始化；写成全局变量且不归零，样例恰好每组独立也会过，但多测数据必错。
6. **不要只加不减**：若漏写 `--a[2]`（或两端的加减不对称），总代币数不守恒，`while (true)` 将无法结束——这既是逻辑错误也是死循环风险。
7. **排序与「原顺序」无关**：答案是轮数，与谁持有多少无关；不要试图按输入顺序记录「谁给了谁」，那只会增加出错面。
8. **Python 的 `sorted` 返回新列表**：`x = sorted(...)` 后原地 `x.sort()` 保持 `x` 始终有序，别写成 `sorted(x)` 却丢掉返回值。

**延伸思考**：

- **值域放大到 $10^9$**：模拟会 TLE，此时必须用闭式 $\min(y-x,\ z-y)$，本题因此也是「先证明轮数公式、再决定要不要模拟」的好例子。
- **推广到 $k$ 个玩家**：每轮仍是最多者给最少者 1 枚。排序后记为 $b_0 \le b_1 \le \dots \le b_{k-1}$，只有两端在动、内部相邻间隙不变，答案仍是 $\min(b_1 - b_0,\ b_{k-1} - b_{k-2})$，与 $k$ 无关，只取决于首尾两个间隙。
- **每次给 2 枚**：两个间隙每轮各减 2，答案变成 $\lceil \min(d_1, d_2) / 2 \rceil$ 一类带奇偶修正的式子，需要额外讨论「跨过 $y$」的情形，是很好的分类讨论练习。
