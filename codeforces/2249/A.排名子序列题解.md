# Codeforces 排名子序列 题解

## 1. 题目概述

- **标题 / 题号**：排名子序列（Codeforces 2249A，英文名 Rank Subsequence）
- **链接**：https://codeforces.com/problemset/problem/2249/A
- **来源**：Codeforces Round 1112 (Div. 1) · Problem A
- **难度**：1300（Div. 1 A，750 分）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：暴力枚举，贪心，实现

**题意**：$n$ 个元素排成一行，编号 $1..n$。可以删掉任意多个元素（也可以一个都不删），剩下的保持相对顺序构成子序列，设长度为 $m$。若原编号 $i$ 的元素在新子序列里排第 $j$ 个，则它的**左秩**为 $j$、**右秩**为 $m-j+1$。每个元素自带两条禁区：左秩禁区 $[l_i,r_i]$、右秩禁区 $[u_i,v_i]$，元素 $i$ 在长度为 $m$ 的子序列里**合法**当且仅当它落到的位置 $j$ 满足

$$j \notin [l_i,r_i] \quad\text{且}\quad m-j+1 \notin [u_i,v_i].$$

子序列合法指每个元素都合法。求**最长合法子序列的长度**，答案允许为 $0$（一个都不留——空子序列天然合法）。多测：第一行 $t$，每组先给 $n$，随后 $n$ 行每行 $l_i,r_i,u_i,v_i$，逐组输出一个整数。

**约束**：

- $1 \le t \le 5000$；$1 \le n \le 5000$，且**所有测试的 $n$ 之和不超过 $5000$**（这是复杂度的关键：$\sum n^2$ 最坏只有 $5000^2$）。
- $1 \le l_i \le r_i \le n$，$1 \le u_i \le v_i \le n$；答案落在 $[0,n]$。

- 第 1 组 $n=1$ 时区间只能是 $[1,1]$，唯一元素左右秩都是 $1$，全被禁掉，答案 $0$；第 2 组四元素全留，秩对依次为 $(1,4),(2,3),(3,2),(4,1)$，全部合规。
- 第 3、5 组最优分别保留下标 $2,3,5$ 与 $3,4,5$；第 4 组 $m=1$ 时无元素可用、$m=2$ 却可行——**可行性对 $m$ 不单调**。

补一组自造样例（★，"$m=2$ 不行而 $m=3$ 行"的反直觉情形）：

```text
输入（★自造）：
1
4
3 4 2 2
4 4 3 4
3 3 1 4
1 2 2 2

输出（★自造）：
3
```

这一组的可行长度集合恰为 $\{1,3\}$：$m=2$ 反而无解，$m=3$ 才有解。

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $2^n$ 个子序列、逐个 $O(n)$ 判合法，是 $O(n\cdot 2^n)$，$n\ge 25$ 就跑不动；改成"枚举长度 $m$ + 枚举元素到位置的排列"是 $O(n!)$，更差。但暴力漏掉了结构性事实：**元素 $i$ 能否坐在位置 $j$，只取决于 $(j,\ k=m+1-j)$ 和它自己的两条禁区，与其它被选中的元素无关**。所有元素放在一起时唯一的耦合只有"下标必须递增"。于是固定 $m$ 后，"贴下标"可以一次贪心扫完。

### 3.2 核心观察：固定 $m$ + 最小可用下标贪心

固定长度 $m$ 后，位置 $j$ 与右秩 $k=m+1-j$ 一一对应（$j+k=m+1$），可用性判定是 $O(1)$ 的：

$$\text{usable}(i,j,m) \iff j \notin [l_i,r_i] \ \wedge\ (m+1-j) \notin [u_i,v_i].$$

问题于是变成：给位置 $1,2,\ldots,m$ 依次挑下标 $i_1<i_2<\cdots<i_m$，要求 $i_j$ 在位置 $j$ 可用。**贪心**：从左往右处理 $j$，维护指针 $p$ = 下一个未考察的下标，把 $p$ 右推直到碰上第一个在位置 $j$ 可用的元素，贴上去后 $p$ 后移一位。

- **正确性**：位置 $j$ 能用更小的下标就绝不用更大的——留下更大的下标只会让后面位置的可选集合更大（交换论证，见 §5 引理 2）。
- **复杂度**：被跳过的元素 $i<p$ 在位置 $j$ 不可用，而后面位置要的下标都 $>p>i$，它**永远用不上**；$p$ 只增不减，一次检查 $O(n+m)=O(n)$。

![秩模型：固定 m 后第 j 个位置同时锁定左秩 j 与右秩 k=m+1−j](images/cf2249_a_rank_model.svg)

必须警惕：**可行性关于 $m$ 不单调**（官方样例 4：$m=1$ 无解、$m=2$ 有解）。所以不能二分，只能让 $m$ 从 $n$ 递减枚举，第一个通过检查的就是答案；全部失败则输出 $0$。

### 3.3 算法流程

1. 读入 $n$ 与 $n$ 组 $(l_i,r_i,u_i,v_i)$。
2. 令 $m$ 从 $n$ 递减到 $1$，对每个 $m$ 做贪心检查：$p\leftarrow 0$、$j\leftarrow 1$；取 $k=m+1-j$，把 $p$ 右推到第一个 `usable(p,j,m)` 为真的下标；若 $p$ 冲出 $n$，长度 $m$ 不可行，换更小的 $m$；否则贴上下标 $p$，$p\leftarrow p+1$、$j\leftarrow j+1$。
3. $j$ 顺利走完 $m$ 个位置即输出 $m$；$m$ 从 $n$ 试到 $1$ 全失败则输出 $0$。

![算法流程：m 递减枚举，每个 m 用单调指针扫一遍](images/cf2249_a_greedy_flow.svg)

### 3.4 示例演算

官方样例 5（$n=6$）走查，元素依次为 $[1,1]|[6,6]$、$[1,2]|[5,6]$、$[2,3]|[4,5]$、$[3,4]|[3,4]$、$[4,5]|[2,3]$、$[5,6]|[1,2]$。先试 $m=4$：$j=1,k=4$ 时要扫过下标 $1,2,3,4$ 才选中 $5$；$j=2,k=3$ 选中 $6$；到 $j=3,k=2$ 已无下标可用（$5,6$ 都被吃掉），中断。退回 $m=3$：$j=1,k=3$ 扫掉 $1,2$ 选中 $3$，$j=2,k=2$ 选中 $4$，$j=3,k=1$ 选中 $5$，三个位置全部落位，答案 $3$——与官方 note 的最优子序列 $3,4,5$ 一致。

![样例 5 走查：m=4 断粮、m=3 成功](images/cf2249_a_walkthrough.svg)

## 4. 算法细节

- **$m$ 必须从大到小枚举**：可行性不单调（样例 4），二分无效；只有"递减枚举后第一次成功"才保证取到最大值。
- **两个条件必须同时成立**：$j\notin[l_i,r_i]$ 与 $k\notin[u_i,v_i]$ 是**与**关系，写成 `or` 或只判一条会让答案偏大。
- **指针单调是复杂度关键**：`while (p < n)` 里被 `++p` 跳过的下标本轮不再回看；若每换一个位置都从头扫，单次检查退化成 $O(nm)$，总量 $O(n^3)$ 必挂。
- **下标体系**：$j,k$ 一律 $1$ 起算，$k=m+1-j$（不是 $m-j$）；C++ 侧元素按 $0$ 起算存放，两套下标别混。
- **空子序列兜底**：`ans` 初值取 $0$，循环成功与否都有定义，无需特判。
- **可选 $O(n)$ 剪枝**：用差分数组统计"秩 $j$ 被多少元素的 $[l_i,r_i]$ 覆盖"，若某秩被全部 $n$ 个元素禁止，则任何 $m\ge j$ 都不可行，枚举上界可压到 $j-1$；右秩同理（Python 版实现，纯常数优化）。
- **多测与 I/O**：$t$ 可达 $5000$ 而 $\sum n\le 5000$，整块读入 + 游标（Python）或 `cin` 关同步（C++）即可；C++ 用全局定长数组避免反复分配。

## 5. 正确性证明

**引理 1（可用性判定）**：固定长度 $m$，元素 $i$ 放在位置 $j$ 时左秩为 $j$、右秩为 $m+1-j$，故它合法当且仅当 $j\notin[l_i,r_i]$ 且 $m+1-j\notin[u_i,v_i]$。

**证明**：把左右秩直接代入合法条件即得。∎

**引理 2（贪心逐位不大于）**：固定 $m$。若存在合法下标序列 $i_1<i_2<\cdots<i_m$（$i_j$ 在位置 $j$ 可用），则贪心产出的 $g_1<\cdots<g_m$ 存在且 $g_j\le i_j$ 对一切 $j$ 成立。

**证明**：对 $j$ 归纳。$j=1$ 时 $g_1$ 是位置 $1$ 可用的最小下标，而 $i_1$ 可用，故 $g_1\le i_1$。设 $g_j\le i_j$ 且贪心已贴到第 $j$ 位：因 $i_{j+1}>i_j\ge g_j$ 且在位置 $j+1$ 可用，贪心从 $g_j+1$ 起找候选时**一定能找到**（$i_{j+1}$ 就是），于是 $g_{j+1}$ 存在且 $g_{j+1}\le i_{j+1}$。∎

**定理**：记 $F$ 为"贪心检查通过"的长度集合，则答案为 $\max F$（$F$ 为空时取 $0$），且它正是最长合法子序列长度。

**证明**：先看"贪心通过 $\Rightarrow$ 存在合法子序列"：贪心选出 $g_1<\cdots<g_m$，每个 $g_j$ 在位置 $j$ 可用，由引理 1 该子序列合法、长 $m$。再"存在合法子序列 $\Rightarrow$ 贪心通过"：由引理 2 贪心必能产出整套 $g_1,\ldots,g_m$，检查不会失败。故"长度 $m$ 可行"$\iff$"贪心检查通过"，两集合相等。算法从 $n$ 递减输出第一个通过值即 $\max F$；$F$ 为空时输出 $0$，此时任意长度无解、空子序列长 $0$ 仍是最大可行长度。∎

## 6. 复杂度分析

- **时间**：单次检查中 $p$ 单向前进至多 $n$ 步、位置循环 $m$ 步，为 $O(n+m)=O(n)$；对 $m=n,\ldots,1$ 逐一检查，最坏 $O(n^2)$。由 $\sum n\le 5000$ 得 $\sum n^2\le 5000^2=2.5\times 10^7$ 次判定，2 s 时限极宽松（实测 $n=5000$ 最坏构造约 $0.03$–$0.07$ s，含读入）。
- **空间**：四张长 $n$ 的数组（外加可选四个差分数组），$O(n)$，$n\le 5000$ 时不足 1 MB。
- **Python**：同一 $O(n^2)$ 算法在 CPython 下随机最大数据约 $1.6$ s、"每次检查都要扫满"的最坏构造约 $3.4$ s，都贴着时限；文中 Python 版加了 $O(n)$ 上界剪枝，可把后一类构造压到 $0.1$ s 以内，正式提交仍建议 **PyPy3**。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 5005;
static int L[MAXN], R[MAXN], U[MAXN], V[MAXN];

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T;
    cin >> T;
    while (T--) {
        int n;
        cin >> n;
        for (int i = 0; i < n; ++i) cin >> L[i] >> R[i] >> U[i] >> V[i];
        int ans = 0;                              // 空子序列总是合法
        for (int m = n; m >= 1; --m) {            // 从最长开始试，第一个成功即答案
            int p = 0;                            // 下一个候选下标（0-indexed），只增不减
            bool ok = true;
            for (int j = 1; j <= m; ++j) {
                int k = m + 1 - j;                // 位置 j 对应的右秩
                while (p < n) {
                    bool leftOK  = (j < L[p] || j > R[p]);   // 左秩 j 不在 [l, r] 内
                    bool rightOK = (k < U[p] || k > V[p]);   // 右秩 k 不在 [u, v] 内
                    if (leftOK && rightOK) break;
                    ++p;                          // 该元素在位置 j 及之后都不可能再用
                }
                if (p == n) { ok = false; break; }  // 元素用尽，长度 m 不可行
                ++p;                                // 把元素 p 贴到位置 j 上
            }
            if (ok) { ans = m; break; }
        }
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    pos, t = 1, data[0]
    out = []
    for _ in range(t):
        n = data[pos]; pos += 1
        L, R, U, V = [0] * n, [0] * n, [0] * n, [0] * n
        dl, dr, du, dv = [0] * (n + 2), [0] * (n + 2), [0] * (n + 2), [0] * (n + 2)
        for i in range(n):
            l, r, u, v = data[pos], data[pos + 1], data[pos + 2], data[pos + 3]
            pos += 4
            L[i], R[i], U[i], V[i] = l, r, u, v
            dl[l] += 1; dr[r + 1] += 1        # 差分：秩 j 被多少元素的 [l,r] 覆盖
            du[u] += 1; dv[v + 1] += 1
        ub, cur = n, 0                        # 剪枝：被全部元素禁止的秩给出长度上界
        for j in range(1, n + 1):
            cur += dl[j] - dr[j]
            if cur == n:
                ub = j - 1; break
        cur = 0
        for k in range(1, ub + 1):
            cur += du[k] - dv[k]
            if cur == n:
                ub = k - 1; break
        ans = 0
        for m in range(ub, 0, -1):            # 从最长开始试，第一个成功即答案
            p, ok = 0, True
            for j in range(1, m + 1):
                k = m + 1 - j
                while p < n and not ((j < L[p] or j > R[p]) and (k < U[p] or k > V[p])):
                    p += 1
                if p == n:
                    ok = False
                    break
                p += 1
            if ok:
                ans = m
                break
        out.append(str(ans))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n=1$**：区间只能是 $[1,1]$，唯一元素左右秩都是 $1$，必被禁掉，答案恒为 $0$；`ans=0` 兜底不会误输出 $1$。
2. **答案是 $0$**：空子序列合法，无解时输出 $0$（不是 $-1$、也不是 $n$），`ans` 初值必须为 $0$。
3. **可行性对 $m$ 不单调**：样例 4（$m=1$ 挂、$m=2$ 行）与 §2 的自造样例（$m=2$ 挂、$m=3$ 行）都是反例，任何二分答案或"找到可行再往上加"的写法都会错。
4. **判定写成 `and` 不是 `or`**：两条禁区必须都不命中；只判一条会让答案偏大。
5. **指针不能重置**：一次检查内 $p$ 只能单向前进；若在位置循环里把 $p$ 归零，会把已经贴在前面位置的元素再用一次。
6. **多测规模**：$t$ 可达 $5000$，其中多数 $n=1$；按 $n$ 而不是 $5005$ 初始化数组，Python 用整块 `data` + 游标比逐行 `input()` 稳。
7. **右秩公式是 $m+1-j$**（不是 $m-j$），差 $1$ 在样例 4 上立刻出错。

**延伸思考**：

1. 要输出**具体子序列**而非长度：贪心时记录被选中的下标即可（即 §3.4 走查图里"选中"一列），无额外代价。
2. 把"左秩不能落在 $[l_i,r_i]$"改成"必须落在 $[l_i,r_i]$"（右秩同理）：引理 2 只用到"位置 $j$ 的可用集合已知"，与它是否为区间的补无关，算法与复杂度完全不变。
3. 若 $n$ 放大到 $10^5$：瓶颈是"每个 $m$ 都要 $O(n)$ 检查"而可行性不单调使二分失效；能否复用相邻 $m$ 的匹配前缀做到 $O(n\log n)$，是个有意思的开放问题。
4. 若每个元素带收益 $w_i$、求最大收益合法子序列：长度不再是唯一目标，贪心失效，需要按 (位置, 下标) 建 DP。
