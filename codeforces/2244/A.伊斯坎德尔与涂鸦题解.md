# Codeforces 伊斯坎德尔与涂鸦 题解

## 1. 题目概述

- **标题 / 题号**：伊斯坎德尔与涂鸦（Codeforces 2244A，英文名 Iskander and Drawings）
- **链接**：https://codeforces.com/problemset/problem/2244/A
- **来源**：Codeforces Round 1109 (Div. 3) · Problem A
- **难度**：$\ast 800$
- **限制**：时间 1 s / 内存 256 MB
- **标签**：字符串、贪心、枚举、模拟（官方标签：dp, games, greedy, strings）

**题意**：一页纸用长度为 $n$ 的字符串 $s$ 表示，其中 `'#'` 表示画了 $1$ 厘米长的线段，`'*'` 表示空白；**连续的若干个 `'#'` 组成一条完整的线段**。现在两人同时擦**同一条**线段：每一秒 Iskander 从右端擦掉 $1$ 厘米、Yura 从左端擦掉 $1$ 厘米；特别地，当线段的**当前**长度已经是 $1$ 厘米或 $2$ 厘米时，下一秒不再各擦 $1$ 厘米，而是整条被擦干净、过程结束。Yura 可以任选一条线段去擦，问最多能擦多少秒；若纸上一条线段也没有，答案为 $0$。

多测：第一行是测试组数 $t$；每组先给 $n$，再给字符串 $s$；对每组输出一个整数（最多能擦的秒数）。

**约束**：

- $1 \le t \le 2500$
- $1 \le n \le 10$
- $s$ 仅由 `'#'` 与 `'*'` 组成
- $\sum n \le 2.5\times 10^{4}$，每组 $O(n)$ 甚至 $O(n^2)$ 都绰绰有余

## 3. 解题思路

### 3.1 暴力思路

直接照题面模拟：枚举每条线段，让它每秒缩短 $2$，一旦当前长度 $\le 2$ 就再花 $1$ 秒整条消失，全程取最大值。线段数不超过 $n$，每条线段最多撑 $\lceil n/2\rceil$ 秒，复杂度 $O(n^2)$，在 $n\le 10$ 时只有约 $100$ 次操作，**完全可以通过**。但暴力写法的价值仅在于对拍：它把「$1$ 或 $2$ 厘米时整条消失」这条特殊规则编码进循环，很容易多算或少算一秒；本题真正需要的是把这层循环**折叠成闭式**，一眼看出答案只依赖一个量。

### 3.2 核心观察：时长只由线段长度决定，且是上取整

![两端同时擦除：长度每秒减少 2](images/cf2244_a_line_erase.svg)

设一条线段当前长度为 $L$。把题面的规则翻译成两条：

- 若 $L \ge 3$：这一秒两端各擦 $1$ 厘米，一秒后长度变成 $L-2$，过程继续；
- 若 $L \le 2$：这一秒什么都不用细算，整条直接消失，过程结束。

于是长度以「每秒 $-2$」的节奏递减，直到落进 $\{1,2\}$ 这个收尾区间，再补最后一秒。分奇偶算清楚：

- $L = 2k$：前 $k-1$ 秒后长度恰为 $2$，第 $k$ 秒整条消失，共用 $k = L/2$ 秒；
- $L = 2k+1$：前 $k$ 秒后长度恰为 $1$，第 $k+1$ 秒消失，共用 $k+1 = (L+1)/2$ 秒。

两式合起来就是 $T(L)=\left\lceil L/2 \right\rceil=\left\lfloor (L+1)/2 \right\rfloor$，落到代码里就是整数除法 `(L + 1) / 2`。

**关键点在于 $L=2$ 只花 $1$ 秒而不是 $2$ 秒**（最后一秒是「整条消失」而不是「各擦 $1$ 厘米」），所以是上取整；$L=1$ 同理也只花 $1$ 秒。

还有一步消解：题目允许 Yura **任选**一条线段。由于 $\lceil L/2\rceil$ 关于 $L$ **单调不减**，选最长的那条一定不劣，于是

$$\text{答案} = \left\lceil \frac{M}{2} \right\rceil,\qquad M = \text{最长连续 \# 段的长度},$$

没有线段时 $M = 0$，公式自动给出 $0$。至此问题退化为一次线性扫描。

### 3.3 算法流程：单次扫描维护 cur 与 best

![一次线性扫描求最长连续 # 段](images/cf2244_a_scan_flow.svg)

对每组测试：

1. 读入 $n$ 与 $s$，令 `cur = 0`（当前连续 `'#'` 长度）、`best = 0`（历史最长）；
2. 从左到右扫 $s$ 的每个字符：
   - 若为 `'#'`：`cur += 1`，并**立刻** `best = max(best, cur)`；
   - 若为 `'*'`：`cur = 0`（一条线段到此结束）；
3. 扫描结束，输出 `(best + 1) / 2`（整数除法）。

注意 `best` 是在**遇到 `'#'` 的当下**更新的，而不是在「线段结束」时更新——这样字符串末尾那段没有右邻居的线段也不会被漏掉。

### 3.4 示例演算

![5 组官方样例的扫描走查](images/cf2244_a_walkthrough.svg)

| 用例 | 字符串 $s$ | 各段长度 | 最长 $M$ | 答案 $\lceil M/2\rceil$ |
|------|-----------|----------|----------|--------------------------|
| 1 | `#*##*##` | 1, 2, 2 | 2 | 1 |
| 2 | `########` | 8 | 8 | 4 |
| 3 | `********` | 无 | 0 | 0 |
| 4 | `#******##` | 1, 2 | 2 | 1 |
| 5 | `*#####` | 5 | 5 | 3 |

第 5 组最能说明「上取整从哪来」：长度 $5 \to 3 \to 1 \to$ 消失，共 $3$ 秒；若误按 $L/2$ 取整会算成 $2$，若把收尾也当成「各擦 $1$ 厘米」则会算成 $4$。

## 4. 算法细节

1. **`best` 的更新时机**：在读到 `'#'` 时立即更新，等价于「每扩展一格就看一眼」。若改成在 `'*'` 处更新，必须额外在循环结束后补一次判断，否则 `*#####` 这类以线段结尾的用例会漏算整段。
2. **不要用 $n$ 当循环上界**：第 4 组官方数据的串长与 $n$ 不一致，稳妥写法是遍历 `s`（C++ 用范围 for，Python 用 `for ch in s`），$n$ 只用来读入。C++ 里可写 `(void)n;` 消除未使用变量告警。
3. **多测清零**：`cur` 与 `best` 必须在每组开头重置为 $0$，否则上一组的答案会串到下一组；这是本题最常见的 WA。
4. **公式用整数运算**：`(best + 1) / 2` 在 C++ 中就是向下取整的整数除法，恰好等于 $\lceil \text{best}/2\rceil$；`best = 0` 时得到 $0$，无需特判「没有线段」。不要写 `ceil(best / 2.0)`，浮点数在本题是多余的。
5. **字符比较**：用 `c == '#'` 判线段，不要用 `c != '*'`——虽然本题字符集只有两种、两者等价，但前者语义明确，扩展字符集时不会出错。
6. **空间**：不需要存数组，只需 `cur`/`best` 两个 `int`，额外空间 $O(1)$；字符串本身 $O(n)$。
7. **I/O 与读入方式**：C++ 关同步 `ios::sync_with_stdio(false)` 与 `cin.tie(nullptr)`；Python 用 `sys.stdin.buffer.read().split()` 一次读完再按下标推进。`s` 中不含空格，`cin >> s` / `split()` 都能整串读入，不需要 `getline`，也就不会被上一行残留的换行符坑到。

## 5. 正确性证明

**引理 1（长度演化）**：若某秒开始时线段长度为 $L$，则该秒结束后长度为 $L-2$（当 $L\ge 3$），或为 $0$ 且过程结束（当 $L\in\{1,2\}$）。

**证明**：$L\ge 3$ 时，两端各擦 $1$ 厘米共减少 $2$，且剩余 $L-2\ge 1$ 说明这一步没有把线段擦没，特殊规则（当前长度 $1$ 或 $2$ 才会触发）尚未生效，故新长度为 $L-2$。$L\in\{1,2\}$ 时按规则整条被擦除，过程终止。∎

**引理 2（单条线段所需时间）**：长度 $L\ge 0$ 的线段被完全擦除所需时间为 $T(L)=\lceil L/2\rceil$（约定 $T(0)=0$）。

**证明**：对 $L$ 归纳。$L=0$ 时无需操作，$0=\lceil 0/2\rceil$；$L=1$、$L=2$ 时由引理 1 一秒后归零，$1=\lceil 1/2\rceil=\lceil 2/2\rceil$。设 $L\ge 3$，由引理 1 第一秒后长度为 $L-2$ 且过程继续，据归纳假设还需 $\lceil (L-2)/2\rceil$ 秒，于是 $T(L)=1+\lceil (L-2)/2\rceil=\lceil L/2\rceil$，最后一步用到了「$L\ge 3$ 时 $\lceil (L-2)/2\rceil=\lceil L/2\rceil-1$」这一恒等式（对偶数 $L$ 与奇数 $L$ 分别验证即得）。∎

**引理 3（最长段最优）**：设各线段长度中最大者为 $M$，则任选线段所能达到的最大时间就是 $\lceil M/2\rceil$。

**证明**：$\lceil \cdot/2\rceil$ 单调不减，故对任一线段长度 $L\le M$ 有 $\lceil L/2\rceil\le\lceil M/2\rceil$；取最长的那条线段即可取到等号。∎

**引理 4（扫描正确）**：3.3 的扫描结束时 `best` 恰好等于最长连续 `'#'` 段的长度 $M$。

**证明**：设某条线段占据下标区间 $[l,r]$。读到 $s[l]$ 时 `cur` 由 $0$ 变 $1$，之后每读一个 `'#'` 就加 $1$ 并同步刷新 `best`，故读到 $s[r]$ 时 `cur = r-l+1` 且 `best ≥ cur = r-l+1`；读到 $s[r+1]$（若存在且为 `'*'`）时 `cur` 归零。于是每条线段的长度都被 `best` 覆盖（下界），而 `best` 只记录真实出现过的连续段长度、不会超过 $M$（上界），故 `best = M`。∎

**定理**：算法输出的值等于题面所求的最大擦除时间。

**证明**：由引理 4，`best = M`；由引理 2，每条长度 $L$ 的线段耗时 $\lceil L/2\rceil$，由引理 3，其中最大值是 $\lceil M/2\rceil$。算法输出 `(M+1)/2`，在整数除法下等于 $\lceil M/2\rceil$；$M=0$ 时输出 $0$，与「没有线段答案为 $0$」一致。∎

## 6. 复杂度分析

- **时间**：每组只扫一遍字符串，$O(n)$；多测总计 $O\left(\sum n\right)\le 2.5\times 10^{4}$ 次字符比较，判定是 $O(1)$ 的整数除法，相对 $1$ s 时限可忽略不计。而必须读入整个字符串，$\Omega\left(\sum n\right)$ 已是输入下界，故本复杂度最优。
- **空间**：额外 $O(1)$（`cur`、`best` 与循环变量），不含输入字符串本身的 $O(n)$。
- **实测**：最大数据（$t=2500$、每组 $n=10$，共 $2.5\times10^{4}$ 字符）端到端 C++ 约 $9$ ms、Python 约 $30$ ms（多次测量在 $8\sim42$ ms 波动，几乎全是进程启动开销）；相对 $1$ s 时限余量在 $20$ 倍以上。

## 7. 参考代码

### C++17

```cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;
    while (t--) {
        int n;
        string s;
        cin >> n >> s;
        (void)n;                     // n 只用于读入：样例里出现了 n 与串长不一致的笔误

        int best = 0, cur = 0;       // best: 最长连续 '#' 段；cur: 当前连续长度
        for (char c : s) {
            if (c == '#') {
                ++cur;
                best = max(best, cur);   // 读到 '#' 的当下就更新，末尾线段不会漏
            } else {
                cur = 0;                 // 线段结束
            }
        }
        // 长度 L 的线段耗时 ceil(L/2) = (L+1)/2，L=0 时自动得 0
        cout << (best + 1) / 2 << '\n';
    }
    return 0;
}
```

import sys

    if not data:

    pos = 0

## 8. 边界情况与易错点

1. **没有任何线段**（全 `'*'`）：`best` 保持 $0$，`(0+1)/2 = 0`，公式自动给出正确答案，**不需要**特判；若写成 `max(1, ...)` 或先给 `best` 初值 $1$ 就会输出 $1$ 而 WA。
2. **$n=1$**：`'#'` 输出 $1$、`'*'` 输出 $0$，两种极端都被 §2 的自造样例覆盖。
3. **整串只有一段 `'#'`**：答案 $\lceil n/2\rceil$，例如 $n=8$ 输出 $4$、$n=7$ 输出 $4$，别把奇数情况写成 $n/2$。
4. **收尾规则写错**：$L=2$ 只花 $1$ 秒（最后一秒是「整条消失」，不是再各擦 $1$ 厘米）。若把收尾当成额外的一秒，$L=2$ 会算成 $2$、$L=8$ 会算成 $5$，样例第 1、2 组立刻挂。
5. **`best` 更新位置**：只在 `'*'` 分支里更新、或只在循环结束后更新，会漏掉「线段在字符串末尾」的情况（如 `*#####`），样例第 5 组就会挂。
6. **多测未清空**：`cur`、`best` 必须每组重置；上一组遗留的 `best` 会让后续组答案偏大。
7. **样例数据本身的 $n$ 与实际串长不一致**（第 4 组，$n=8$ 但串长 $9$）：按 `s` 的实际长度遍历即可，若用 `for (int i = 0; i < n; ++i)` 会漏掉最后一个字符——本题恰好不影响答案（最长段仍为 $2$），但换成别的数据就会错。
8. **整数除法方向**：`(best + 1) / 2` 依赖「正数向零取整」，`best ≥ 0` 保证了它与 $\lceil \cdot \rceil$ 一致；若改成 `best / 2 + 1` 则 `best=0` 时会错输出 $1$。
9. **I/O 与空输入**：本地对拍喂空文件时 `if (!(cin >> t)) return 0;` 与 `if not data: return` 可避免未定义行为；每行输出后记得换行。

**延伸思考**：

1. **两端速度变成每秒 $c$ 厘米**：每步减少 $2c$，收尾阈值仍是 $2$，结论变为 $T(L)=\lceil L/(2c)\rceil$；已对 $L\le 399$、$c\le 4$ 暴力模拟逐点校验。
2. **收尾阈值改成 $k$**（当前长度 $\le k$ 时下一秒整条消失）：令 $m=\left\lceil \max(0,L-k)/2\right\rceil$，则 $T(L)=m+\left[L-2m>0\right]$（$L\ge 1$），已对 $1\le k\le 7$、$L\le 399$ 校验；$k=2$ 时退化回 $\lceil L/2\rceil$。阈值一变，公式就不再是单纯的 $\lceil L/k\rceil$，因为「整条消失」这一步会跨过阈值。
3. **要求输出具体选哪条线段**：在 `best` 被刷新时同步记录起始下标即可（$O(1)$ 额外空间）；若再加「并列时取最短/最靠左」的约束，需要把 `best` 的更新条件从严格大于改成按附加键比较。
4. **两人速度不同**（左 $a$、右 $b$ 厘米每秒）：长度每步减少 $a+b$，但收尾时可能只擦掉一部分，时间要按 $\lceil L/(a+b)\rceil$ 再分剩余量讨论，不再有单一闭式；此时用暴力模拟（$O(L/(a+b))$ 步）反而更省心。
