# Codeforces 20A BerOS 路径规范化 题解

## 1. 题目概述

- **题目链接**：https://codeforces.com/problemset/problem/20/A
- **比赛来源**：Codeforces Alpha Round 20 (Codeforces format) · Problem A（UTC 2010-06-18）
- **难度**：1700
- **标签**：实现
- **评测类型**：普通
- **限制**：时间 2 s / 内存 64 MB

**题意**：BerOS 允许用**任意多个** `/` 作为路径分隔符（而不是恰好一个）。例如 `//usr///local//nginx/sbin//` 与 `/usr/local/nginx///sbin` 表示同一个路径。路径末尾的 `/` 只有"根目录"才需要保留，根目录写作单个 `/`。

"规范形式"指 `/` 字符个数最少的等价写法。给定一条路径（只含小写字母与 `/`，以至少一个 `/` 开头，长度不超过 100），输出它的规范形式。

**约束**：

- 长度 $\le 100$、字符集只有 `[a-z]` 与 `/`：直接按 `/` 切分再重组即可，$O(n)$。
- 输入以至少一个 `/` 开头，且保证非空；根目录可能写成 `/`、`//`、`///` 等任意形式。
- 题目**没有** `.`、`..` 这类相对路径分量（这一点常被误记），所以不需要做路径折叠。

## 2. 示例与观察

官方样例：

```text
输入：
//usr///local//nginx/sbin

输出：
/usr/local/nginx/sbin
```

把输入按 `/` 切开，得到空串、空串、`usr`、空串、空串、`local`、空串、`nginx`、`sbin`（末尾还有一个 `/`，切开后末尾也是空串）。丢掉所有空串，剩下的分量是

```text
usr  local  nginx  sbin
```

用单个 `/` 连接、并在最前面补一个 `/`，得到 `/usr/local/nginx/sbin` ✓。

**观察一**：路径的"语义"只由**非空分量序列**决定；连续斜杠与末尾斜杠都是可以删除的冗余。
**观察二**：规范形式一定是"`/` + 分量用单个 `/` 连接"，或者（没有分量时）单个 `/`。
**观察三**：规范形式的斜杠数 = 1 + (分量数 − 1)（分量数 ≥ 1 时），即恰好 分量数 个；这已经是下界，见第 4 节。

自造样例（标注"自造"）：

| 输入 | 输出 | 说明 |
|------|------|------|
| `/` | `/` | 根目录 |
| `///` | `/` | 根目录的另一种写法 |
| `/a//b///c/` | `/a/b/c` | 末尾斜杠去掉 |
| `//a` | `/a` | 开头多余斜杠合并 |
| `/abc` | `/abc` | 已经规范 |
| `//` | `/` | 只剩根 |

## 3. 解题思路

### 3.1 朴素做法与瓶颈

"不断把 `//` 替换成 `/`，再去掉末尾的 `/`"也能做，但要小心反复替换与根目录的特判，容易写错（例如 `//` 替换一次变成 `/` 后还可能再处理，末尾删斜杠时又把根删成空串）。

更稳的做法是**一次扫描切分**：把路径按 `/` 切成若干段，只保留非空段，然后重新拼接。

### 3.2 核心观察：路径 = 非空分量序列

![切分与重组](../../../images/cf20a_split_join.svg)

任何一条路径都可以唯一地分解成"根 + 若干个非空目录名"。连续斜杠只表示"这里至少有一个分隔符"，末尾斜杠不携带任何信息（根除外）。因此：

- 从输入中按 `/` 切分，扔掉空段，得到分量列表 $p_1, p_2, \dots, p_k$；
- 若 $k = 0$，输出 `/`（根目录）；
- 否则输出 `/` + $p_1$ + `/` + $p_2$ + … + `/` + $p_k$。

复杂度 $O(n)$，不需要任何字符串替换。

### 3.3 算法流程

![几种典型输入的处理](../../../images/cf20a_cases.svg)

1. 读入整行（可能含空格？题面保证只有小写字母与 `/`，用 `cin >> s` 即可）；
2. 令 `cur` 为空、`parts` 为空；
3. 扫描每个字符：遇到 `/` 时，若 `cur` 非空就把它加入 `parts` 并清空；否则把字符追加到 `cur`；
4. 扫描结束后若 `cur` 非空，再加入 `parts`；
5. 若 `parts` 为空输出 `/`，否则依次输出 `/` 与每个分量。

### 3.4 样例走查

输入 `//usr///local//nginx/sbin`：

| 步骤 | 读到的字符 | `cur` | `parts` |
|------|------------|-------|---------|
| 1 | `/` | （空） | — |
| 2 | `/` | （空） | — |
| 3–5 | `usr` | `usr` | — |
| 6 | `/` | （空） | `usr` |
| 7–8 | `/` `/` | （空） | `usr` |
| 9–13 | `local` | `local` | `usr` |
| 14 | `/` | （空） | `usr, local` |
| 15 | `/` | （空） | `usr, local` |
| … | `nginx`、`/`、`sbin` | | `usr, local, nginx, sbin` |

输出 `/usr/local/nginx/sbin` ✓。

## 4. 正确性证明

**引理 1（等价性）**：两条路径等价当且仅当它们的非空分量序列相同。

**证明**：BerOS 只把 `/` 当作分隔符，连续多个 `/` 与一个 `/` 等价，末尾的 `/` 不改变所指目录（根目录除外，它的分量序列为空）。因此路径所指的目录完全由分量序列决定。∎

**引理 2（下界）**：若分量序列为 $p_1,\dots,p_k$（$k \ge 1$），任何等价路径至少含 $k$ 个 `/`。

**证明**：路径必须以 `/` 开头（题面），且 $k$ 个分量之间各至少要有一个 `/` 才能把它们分开（少于 $k-1$ 个分隔符就至多分出 $k-1$ 段），故至少 $1 + (k-1) = k$ 个 `/`。$k = 0$ 时至少 1 个 `/`（根）。∎

**引理 3（构造达到下界）**：算法输出的 `/p_1/…/p_k` 恰好含 $k$ 个 `/`，且与输入等价。

**证明**：输出由输入的非空分量按原顺序拼接而成，由引理 1 与输入等价；斜杠个数为 $1 + (k-1) = k$，达到引理 2 的下界。$k = 0$ 时输出单个 `/`，也达到下界。∎

**定理**：算法输出的是规范形式（斜杠最少的等价路径）。

**证明**：由引理 1、3，输出等价且斜杠数达到下界；任何等价路径的斜杠数不少于它，故输出规范。∎

## 5. 复杂度分析

- **时间**：$O(n)$，$n \le 100$，每个字符访问一次。
- **空间**：$O(n)$ 存分量。
- **与时限的关系**：常数级操作，2 s 的余量在 $10^6$ 倍以上。

## 6. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    string s;
    if (!(cin >> s)) return 0;
    vector<string> parts;
    string cur;
    for (char c : s) {
        if (c == '/') {
            if (!cur.empty()) { parts.push_back(cur); cur.clear(); }
        } else cur += c;
    }
    if (!cur.empty()) parts.push_back(cur);
    if (parts.empty()) { printf("/\n"); return 0; }
    for (auto &p : parts) printf("/%s", p.c_str());
    printf("\n");
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    s = sys.stdin.read().strip()
    parts = [p for p in s.split('/') if p]
    sys.stdout.write(("/" + "/".join(parts) if parts else "/") + "\n")


main()
```

## 7. 边界情况与易错点

1. **根目录**：输入 `/`、`//`、`///` 都应输出 `/`；不要输出空行。
2. **末尾斜杠**：`/a/b/` 要输出 `/a/b`；但根目录的 `/` 必须保留——两者用"分量是否为空"区分最自然。
3. **只有斜杠**：`///` → `/`；若先做"把 `//` 换成 `/`"再"删末尾 `/`"，会得到空串，是常见错误。
4. **不能用 `cin >> s` 之外的读法把换行读进来**：本题输入只有一行，`cin >> s` 恰好跳过行首空白并读到行尾，安全。
5. **分量之间不会出现别的字符**：题面保证只有 `[a-z]` 和 `/`，所以不需要考虑 `.`、`..`、空格。
6. **输出不要多加斜杠**：拼接时每个分量前加一个 `/`，不要写成 `p + "/"` 再连接（那样末尾会多一个）。

**延伸思考**：

1. **如果加入 `.` 与 `..`**？就变成规范的"简化路径"问题：用栈保存分量，`.` 忽略，`..` 弹出栈顶，最后拼接；这与本题的"只切分"只差一个栈。
