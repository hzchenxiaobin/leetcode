# Codeforces 270B Multithreading 题解

## 1. 题目概述

- **题目链接**：https://codeforces.com/problemset/problem/270/B
- **比赛来源**：Codeforces Round 165 (Div. 2) · Problem B（UTC 2013-02-01）
- **难度**：1400
- **标签**：结论、模拟
- **评测类型**：普通
- **限制**：时间 2 s / 内存 256 MB

**题意**：刷新前后各有一个"最近活动"列表。列表按帖子最后回复时间从新到旧排列；有新消息的线程会被移到最上面。给出刷新后第 $i$ 位上是**刷新前第 $a_i$ 位**的那个线程。问**必然**有新消息的线程数。

**约束**：$n \le 10^5$，$a$ 是排列。

## 2. 示例与观察

官方样例 1：

```text
输入：
5
5 2 1 3 4

输出：
2
```

官方样例 2：

```text
输入：
3
1 2 3

输出：
0
```

官方样例 3：

```text
输入：
4
4 3 2 1

输出：
3
```

**观察 1**：有新消息的线程，其最后回复时间**晚于**所有旧消息 → 它们在新列表里占据一个**前缀**（按时间从新到旧排）。

**观察 2**：没更新的线程之间，相对顺序不变 → 它们在新列表的**后缀**里，对应的旧位置（$a_i$）严格递增。

**观察 3**：所以有消息的前缀长度 = $n$ 减去"最长严格递增后缀"的长度；这些前缀里的线程必然有新消息。

**样例 1 验证**：$a = 5,2,1,3,4$；后缀 $1,3,4$ 递增（长度 3）→ 前缀长度 2 ✓。

## 3. 解题思路

![找出最长的"旧位置递增"后缀](../../../images/cf270b_suffix.svg)

从末尾往前，只要 $a_{i-1} < a_i$ 就继续；答案 = 停下时的下标（0 基左端点）。

## 4. 正确性证明

**引理 1**：若前缀 $[1, L]$ 含全部已更新线程、后缀 $[L+1, n]$ 无更新，则 $a_{L+1} < a_{L+2} < \cdots < a_n$。

**证明**：未更新线程的相对顺序与旧列表一致，旧位置自然递增 ✓。∎

**引理 2**：对任意满足该条件的 $L$，"前缀 $[1,L]$ 的线程都必然有更新"成立当且仅当 $L$ 是最大可能的前缀分割点，即后缀是**最长**的递增后缀。

**证明**：若某个更长的后缀也递增，则可以把某线程移入"未更新"集合而仍满足顺序 → 它就不必然有更新 ✓。反之取最长递增后缀，其前面的线程无论怎么安排都必然更新（因为若某个不更新，后缀会更长，矛盾）✓。∎

**定理**：算法输出正确答案。

**证明**：算法求的正是最长递增后缀的补集大小 ✓。∎

## 5. 复杂度分析

- **时间**：$O(n)$。
- **空间**：$O(n)$。
- **与时限的关系**：时限 2 s，$n = 10^5$ 实测端到端 10.4 ms。

## 6. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;
int main(){int n;if(scanf("%d",&n)!=1)return 0;vector<int>a(n);
 for(int i=0;i<n;i++)scanf("%d",&a[i]);
 int k=n-1;                       // 从末尾找最长的严格递增后缀
 while(k>0 && a[k-1]<a[k]) k--;
 printf("%d\n",k);return 0;}
```

### Python3

```python
import sys
def main() -> None:
    data = sys.stdin.buffer.read().split()
    n = int(data[0]); a = [int(v) for v in data[1:1+n]]
    k = n - 1
    while k > 0 and a[k-1] < a[k]:
        k -= 1
    print(k)
main()
```

## 7. 边界情况与易错点

1. **完全有序**：答案 0（样例 2）。
2. **完全逆序**：答案 $n-1$（样例 3）。
3. **严格递增判断**：用 `<` 而不是 `<=`（$a$ 是排列，等价）。
4. **1 基下标**：输入就是旧位置，直接比较。
