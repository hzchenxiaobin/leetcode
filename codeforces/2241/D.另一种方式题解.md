# Codeforces 另一种方式 题解

## 1. 题目概述

- **标题 / 题号**：另一种方式（Codeforces 2241D，英文名 An Alternative Way）
- **链接**：https://codeforces.com/problemset/problem/2241/D
- **来源**：Codeforces Round 1107 (Div. 3) · Problem D
- **难度**：1100（$\ast 1100$）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：贪心、数学、动态规划（官方标签：dp, greedy, math）

**题意**：给定两个长度都是 $n$ 的数组 $a,b$。可以按下面的规则对 $a$ 操作任意多次（也可以是 $0$ 次）：

1. 选两个下标 $l,r$，满足 $1\le l\le r\le n$；
2. 对每个 $i\in[l,r]$：若 $i-l$ 是**偶数**，令 $a_i := a_i+1$；若 $i-l$ 是**奇数**，令 $a_i := a_i-1$。

问能否通过若干次操作把 $a$ 变成恰好等于 $b$。多测：第一行 $t$；每组三行——$n$、数组 $a$、数组 $b$；每组输出一行 `YES` / `NO`（大小写不敏感）。

也就是说，一次操作选出一段连续区间 $[l,r]$，在区间内**从左端开始交替地** $+1,-1,+1,-1,\dots$。

**约束**：

- $1\le t\le 10^4$
- $1\le n\le 2\cdot 10^5$，且 $\sum n\le 2\cdot 10^5$
- $1\le a_i,b_i\le 10^9$
- 答案只有 `YES` / `NO`；前缀和最大可达 $2\cdot 10^5\times 10^9 = 2\times 10^{14}$，**必须开 64 位整数**

> 💡 一句话本质：记 $d_i=b_i-a_i$、$S_k=\sum_{i\le k}d_i$，则**答案就是「所有 $S_k\ge 0$」**。因为每次操作只会把每个 $S_k$ 抬 $+1$ 或抬 $+0$，绝不会压下去；而反过来只要 $S_k$ 全部非负，就一定能用「向左搬 + 就地造」两块积木把 $a$ 捏成 $b$。

## 3. 解题思路

### 3.1 朴素想法，以及它们为什么不行

**想法一：直接搜索 / 模拟操作序列。** 状态是整个数组，取值范围是无界的（每次操作都在改数值），合法的操作有 $\frac{n(n+1)}{2}$ 种，$n=2\cdot10^5$ 时连「枚举一步」都做不到。$\sum n\le 2\cdot 10^5$ 也明确排除了按值域做 BFS/DP 的可能。

**想法二：只比较总和。** 一次操作对总和的改变量是区间内 $+1$ 的个数减去 $-1$ 的个数，即「区间长度为奇数时 $+1$，偶数时不变」。所以总和只增不减，$\sum b\ge\sum a$ 是**必要条件**。但它远不充分 —— 官方第 5 组 $\sum b-\sum a=+2>0$，答案却是 `NO`。

**想法三：逐位判 $a_i\le b_i$。** 立刻被官方第 2 组推翻：那里 $a_3=5>b_3=4$，照样能变过去（$a_3$ 的亏空由 $a_2$ 的 $+1$ 和 $a_1$ 的 $+0$ 一起「垫」起来）。

所以必须找到真正的不变量。关键是把「一次操作」看成一整段增量向量，而不是逐位看。

### 3.2 核心观察：一次操作把每个前缀和抬 $+1$ 或抬 $+0$

记 $d_i=b_i-a_i$（还需要补上的差值），并令

$$S_k=\sum_{i=1}^{k}d_i,\qquad S_0=0 .$$

一次操作 $[l,r]$ 给位置 $i\in[l,r]$ 的增量是 $(-1)^{i-l}$。来看它对前缀和的影响：前缀和只「看得见」$[l,r]$ 与 $[1,k]$ 的交集，即 $[l,\min(k,r)]$ 这一截，设其长度为

$$m=\max\bigl(0,\ \min(k,r)-l+1\bigr).$$

这一截内的增量是 $+1,-1,+1,\dots$ 交替的，求和恰好是「$\pm1$ 交替若干个」的结果：

$$\Delta S_k=\begin{cases}1,& m\ \text{为奇数}\\ 0,& m\ \text{为偶数}\end{cases}\;=\;m \bmod 2 .$$

也就是说：**每个 $S_k$ 每次只会被抬 $+1$ 或原地不动，永远不会被压下去**（见下图 A、B 两块）。初始时所有 $S_k=0$，因此

$$S_k\ge 0\quad\text{对一切 }k=0,1,\dots,n \tag{$\ast$}$$

是**必要条件**。图 1 用官方第 2 组把这件事画了出来：那次操作 $[2,4]$ 对四个前缀和的贡献分别是 $0,+1,0,+1$。

![一次操作对前缀和的影响：ΔS 只能是 0 或 +1](images/cf2241_d_prefix_invariant.svg)

### 3.3 充分性：操作可以拆成两块「积木」

必要性只用了「只抬不压」。真正漂亮的是反过来也成立。把任意区间操作拆开看：$[l,r]$ 的增量向量是 $+1,-1,+1,-1,\dots$，于是它可以写成若干**相邻两格**的积木加（可能的）一个**单格**积木：

$$[l,r]=\underbrace{[l,l+1]}_{+1,-1}+\underbrace{[l+2,l+3]}_{+1,-1}+\cdots+\begin{cases}[r,r],& r-l\ \text{为偶数}\\ [r-1,r],& r-l\ \text{为奇数}\end{cases}$$

例如 $[1,5]=[1,2]+[3,4]+[5,5]$（图 2 上半部分）。两种积木的含义极其明确：

- **搬运积木** $B_i=[i,i+1]$：给 $i$ 加 $1$、给 $i+1$ 减 $1$，即把 $1$ 个单位从 $i+1$ **向左搬**到 $i$，只能往左；
- **造点积木** $A_l=[l,l]$：给 $l$ 凭空 $+1$，在任何位置都能造，想要几个造几个。

所有积木在分解式里的系数都是 $+1$（非负），所以

> **一次操作能做的，恰好是「若干次向左搬运」加「至多一个造点」；反过来，任意多次向左搬运与任意多次造点，都对应若干次合法操作。**

由此充分性的构造思路就非常自然：（图 2 下半部分）从右往左扫，谁的差值 $d_i<0$（缺）就从左边借、往左推；$d_i>0$（多）就地造出来。推到 $d_1$ 时，条件 $(\ast)$ 恰好保证「推过来的亏空」不会超过 $d_1$，所以一定收得住 —— 这就是下面 3.4 的算法和 5 节的归纳证明。

![操作的积木分解：左移积木 + 造点积木](images/cf2241_d_generator_basis.svg)

### 3.4 算法流程

判据就一行，**根本不需要真的构造**：

```text
for each test:
    读入 n, a[1..n], b[1..n]          // 一定要读满 2n 个数
    pre ← 0
    ok  ← true
    for i ← 1 .. n:
        pre ← pre + b[i] - a[i]      // 即 S_i
        if pre < 0: ok ← false
    输出 ok ? "YES" : "NO"
```

如果要真的输出一组操作（本题不要求），可以用 3.3 的推法，每次把某个位置的亏空一次性推给左边：

```text
for i ← n down to 2:
    if d[i] > 0:  用 d[i] 次 A_i = [i,i]      // 就地造，然后 d[i] 归零
    if d[i] < 0:  用 -d[i] 次 B_(i-1) = [i-1,i]   // 亏空推给左边：d[i-1] += d[i]
// 最后 d[1] ≥ 0，用 d[1] 次 A_1 补齐
```

这两个写法是等价的（5 节引理 3 的归纳同时证明了「判据对」和「构造可行」）；判据版只有一次扫描，代码短、常数小，显然更好。

几组「真的动起来」的构造（把上面的积木落地，全部可以直接验算）：

- 第 2 组：$d=[0,1,-1,1]$ 正好就是 $[2,4]$ 的增量向量，**一次操作到位**。
- 第 4 组：$d=[1,-1,1,-1,1,-1]$ 正好是 $[1,6]$ 的增量，也是一次 `[1,6]` 到位 —— 可见 3.4 的推法并不是最优步数，它只保证「能做完」。
- 第 6 组：$d=[1,0,-1]$。从右往左：$d_3=-1<0$，用 $1$ 次 $B_2=[2,3]$，亏空推给左边得 $d_2'=0-(-1)$ 这一步记作 $d_2\leftarrow d_2+d_3=-1$；再用 $1$ 次 $B_1=[1,2]$，$d_1\leftarrow d_1+d_2=0$，完成。合计 $[2,3]+[1,2]$，验算：$[1,1,2]\xrightarrow{[1,2]}[2,0,2]\xrightarrow{[2,3]}[2,1,1]=b$ ✓。
- 第 7 组：$d=[0,-1]$，$S_2=-1<0$。想减 $a_2$ 只能用 $[1,2]$，可那会同时把 $a_1$ 加上 $1$，于是 $a_1$ 越界 —— 判据直接判 `NO`，和「$S_1=0$ 卡死」完全对应。
- 第 5 组：前 3 位攒了 $+2$，第 4 位一口气要减 $4$，$S_4=-2$。$S_k$ 只增不减，于是永远回不到非负 —— 尽管总和是 $+2$。

## 4. 算法细节

1. **不要真的模拟，更不要搜索**：判据就是一次前缀和扫描，$O(n)$；任何按状态搜索的做法在这个 $n$ 下都不可能。
2. **不要用「总和」代替「前缀和」**：官方第 5 组（总和 $+2$、答案 `NO`）和自造第 2 组都是反例。必须是「**每一个**前缀和」都非负。
3. **前缀和要开 64 位**：$|d_i|\le 10^9-1$，$n\le 2\cdot10^5$，$S_k$ 可以到 $\pm 2\times 10^{14}$，`int` 直接溢出。C++ 用 `long long`，Python 天然安全。
4. **读完再判，别在输入循环里 `break`**：如果边读 $b$ 边判断、一发现负就跳出，后面的数就留在了输入流里，从下一组开始全部错位。本解法先把 $a,b$ 读满再扫，天然没有这个问题。
5. **多测清零**：`pre`（和 `ok`）必须是每组内部的变量，或每组开头重置。$t$ 能到 $10^4$，一旦提到循环外累加，第 2 组以后全错。
6. **下标**：前缀和是「前 $k$ 个」，$k=1..n$；实现时用 0-based 下标累加即可，注意别把 $S_0$（恒为 $0$，永远非负）也写进循环。
7. **题面没有要求 $a_i\ge 1$**：操作过程中某些位置完全可能被减到 $0$ 甚至负数，题目并不禁止，构造也不需要这个限制 —— 别自己加一条「不能小于 $1$」的检查，那会误判。
8. **I/O**：$\sum n\le 2\cdot10^5$，总共约 $4\times10^5$ 个数，任何读入方式都够用；照例加 `ios::sync_with_stdio(false)` 与 `cin.tie(nullptr)`，Python 用 `sys.stdin.buffer.read().split()` 一次读完最省事。
9. **输出格式**：每组一行 `YES`/`NO`，大小写不敏感，按惯例大写即可，末尾换行。

## 5. 正确性证明

**引理 1（单步作用）**：对任意 $k$，一次操作 $[l,r]$ 使 $S_k$ 增加 $m\bmod 2$，其中 $m=\max\bigl(0,\min(k,r)-l+1\bigr)$；特别地 $\Delta S_k\in\{0,1\}$。

**证明**：$d$ 在 $[l,r]$ 上的增量是 $(-1)^{i-l}$，前缀和只累加 $i\le k$ 的部分，故 $\Delta S_k=\sum_{i=l}^{\min(k,r)}(-1)^{i-l}$。若 $m=0$ 该和为 $0$；若 $m\ge 1$，这是 $+1,-1,+1,\dots$ 共 $m$ 项的和，$m$ 为奇数时等于 $1$、为偶数时等于 $0$。两者合起来就是 $m\bmod 2\in\{0,1\}$。∎

**引理 2（必要性）**：若 $a$ 能变成 $b$，则 $S_k\ge 0$ 对一切 $k$ 成立。

**证明**：初始 $S_k=0$。由引理 1，每次操作每个 $S_k$ 至多增加 $1$、且永不减少，故任何时刻 $S_k\ge 0$。∎

**引理 3（充分性 / 构造）**：若 $S_k\ge 0$ 对一切 $k$ 成立，则存在操作序列把 $a$ 变成 $b$。

**证明**：对 $n$ 归纳。$n=1$ 时 $S_1=d_1\ge 0$，重复 $d_1$ 次操作 $[1,1]$ 即可。

设 $n-1$ 时命题成立，考虑长度 $n$：

- 若 $d_n\ge 0$：令 $d'=(d_1,\dots,d_{n-1})$，它的前缀和就是 $S_1,\dots,S_{n-1}$，全部非负，由归纳假设存在只作用在 $[1,n-1]$ 上的操作序列实现 $d'$；这些操作的区间不越过 $n-1$，放到长度 $n$ 的数组上效果完全相同，只把位置 $n$ 留在原处；最后再重复 $d_n$ 次 $[n,n]$，把位置 $n$ 补上 $d_n$。
- 若 $d_n<0$：令 $x=-d_n>0$，并令 $d'=(d_1,\dots,d_{n-2},\,d_{n-1}+d_n)$。它的前缀和是 $S_1,\dots,S_{n-2}$ 与 $d_1+\cdots+d_{n-2}+d_{n-1}+d_n=S_n$，按假设全部非负，故由归纳假设可用 $[1,n-1]$ 上的操作实现 $d'$。然后重复 $x$ 次操作 $[n-1,n]$：每次给位置 $n-1$ 加 $1$、位置 $n$ 减 $1$，共给位置 $n-1$ 加 $x=-d_n$、给位置 $n$ 减 $x=d_n$。于是位置 $n$ 恰好得到 $d_n$，位置 $n-1$ 得到 $(d_{n-1}+d_n)+(-d_n)=d_{n-1}$。

两种情形都构造成功，归纳完成。∎

**定理**：$a$ 能变成 $b$ 当且仅当 $\sum_{i\le k}(b_i-a_i)\ge 0$ 对一切 $k=1,\dots,n$ 成立。

**证明**：必要性由引理 2，充分性由引理 3。∎

> 注：引理 1 只用到「$+1$ 总在区间左端」这一件事；引理 3 的归纳里每次只动用 $[n-1,n]$ 与 $[n,n]$，两者恰好对应 3.3 的「搬运积木」与「造点积木」。所以本文的证明和积木直觉是同一件事的两种说法。

## 6. 复杂度分析

- **时间**：每组一次线性扫描，$O(n)$；总计 $O\bigl(\sum n\bigr)\le 2\cdot 10^5$ 次加法和比较。
- **空间**：存 $a,b$ 需要 $O(n)$ 的 `long long`（约 $3.2$ MB，远低于 $256$ MB）；判据本身只用 $O(1)$ 额外空间。也可以边读边判，只留 $O(1)$。
- **实测**：极限数据 $t=10^4$、$\sum n=2\cdot10^5$、$a_i,b_i$ 在 $[1,10^9]$ 内随机（约 $4.1\times10^5$ 个整数、4.3 MB），本机 Apple clang 21 `-O2` 连跑 10 次取最好成绩：手写 `fread` 读入约 $0.010$ s，`scanf` 约 $0.04$ s，Python3 约 $0.09$ s —— 算法本体（$4\times10^5$ 次加减）不到 $1$ ms，其余全是读入。
- **一个实测坑（与本机工具链有关，不是算法问题）**：Apple clang 配 libc++ 时 `cin >> long long` 退化得厉害，同样 $4.1\times10^5$ 个数要 $0.55$ s；换成 `scanf` 或手写 `fread` 立刻回到 $0.01\!-\!0.04$ s。Codeforces 用 GNU libstdc++，关闭同步的 `cin` 不会出现这种退化，所以下面的参考代码仍用 `cin`（也便于和本仓库其它题解统一）。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;            // 空输入防护
    while (t--) {
        int n;
        cin >> n;
        vector<long long> a(n), b(n);
        for (auto &x : a) cin >> x;       // 先把 2n 个数读满，避免提前 break 造成错位
        for (auto &x : b) cin >> x;

        bool ok = true;
        long long pre = 0;                // pre = S_i = sum_{j<=i} (b_j - a_j)
        for (int i = 0; i < n; ++i) {
            pre += b[i] - a[i];
            if (pre < 0) ok = false;      // 前缀和一旦为负就再也回不去
        }
        cout << (ok ? "YES" : "NO") << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:                          # 空输入防护
        return
    t = int(data[0])
    p = 1
    out = []
    for _ in range(t):
        n = int(data[p]); p += 1
        a = data[p:p + n]; p += n
        b = data[p:p + n]; p += n
        pre = 0
        ok = True
        for i in range(n):
            pre += int(b[i]) - int(a[i])  # bytes 直接 int() 转换，比解码更快
            if pre < 0:
                ok = False
        out.append("YES" if ok else "NO")
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n=1$**：判据退化成 $b_1\ge a_1$。这很符合直觉 —— 唯一可能的操作是 $[1,1]$，它只给 $a_1$ 加 $1$。官方第 3 组 $a=9,b=8$ 正是 `NO`。
2. **$a_1$ 永远无法变小**：任何覆盖位置 $1$ 的区间都必须以 $l=1$ 开头，$i-l=0$ 是偶数，只会 $+1$。所以 $S_1=d_1\ge 0$ 是独立的一条硬约束。
3. **总和判据必错**：官方第 5 组总和 $+2$ 却是 `NO`；自造第 3 组总和 $0$ 也是 `NO`。必须逐前缀判断。
4. **前缀和溢出**：$S_k$ 最坏 $\pm 2\times10^{14}$，`int` 会绕回，答案随机错。
5. **多测未清零**：`pre`/`ok` 定义在循环外累加是最常见的失分点，$t=10^4$ 时会连错一片。
6. **提前 `break` 漏读输入**：边读边判时若直接跳出，剩下的数字会喂给下一组，导致后面全部错位；本解法读满再判，天然规避。
7. **别加「$a_i$ 不能小于 $1$」的检查**：题面只约束初始值，不约束中间值；构造路径上出现 $0$ 或负数是允许的，多这条检查会误判（例如某些必须先把某位减到 $0$ 才能腾出空间的例子）。
8. **别把 $S_0$ 写进循环**：$S_0=0$ 恒非负，写进去无害但也无用；真正要判的是 $k=1..n$ 这 $n$ 个值。
9. **整组数据都要读完**：即使已经判定 `ok=false`，也要把本组的 $b$ 读干净（本解法先读后判，已保证）。

## 相关题目与扩展

- [Codeforces 1738B Prefix Sum Addicts](https://codeforces.com/problemset/problem/1738/B)：给出一串「前缀和」，还原原数组并判合法性 —— 与本题一样，把「前缀和序列」当成一等公民来推理。
- [Codeforces 1398C Good Subarrays](https://codeforces.com/problemset/problem/1398/C)：把「区间和为定值」转成「两个前缀和相等」，前缀和计数的经典操作。
- [LeetCode 1094. 拼车](https://leetcode.cn/problems/car-pooling/)：差分数组 + 前缀和判断容量约束，正是「$S_k$ 必须始终非负」的另一种场景（$+\!1$ 上车、$-\!1$ 下车）。
- [Codeforces 1791F Range Update Point Query](https://codeforces.com/problemset/problem/1791/F)：区间操作与单点询问的转换，用来体会「区间操作在差分/前缀和视角下长什么样」。

**延伸思考**：

1. **把符号颠倒**：若操作改成「偶数位 $-1$、奇数位 $+1$」，则每次操作把每个 $S_k$ 压 $0$ 或 $-1$，判据对称为「所有前缀和 $\le 0$」。
2. **只允许偶数长度区间**：此时 3.3 的分解里不会出现单格积木 $A_r$，只剩搬运积木，于是总质量守恒且只能向左流；判据变成「所有 $S_k\ge 0$ 且 $S_n=0$」。一个原本 1100 的题会立刻变成需要留心的细节题。
3. **只允许长度 $\ge 2$**：单格积木不再直接可用，但奇数长度的区间仍然「顺带」造出一个单位的质量。此时可达集不再是简单的半群，需要重新刻画 —— 值得动手试试判据会变成什么样。
4. **求最少操作次数**：本文只判可达性，构造出的方案步数是 $O\bigl(\sum|d_i|\bigr)$（最大到 $10^{14}$ 级别，当然不能真的输出）。但官方第 4 组一次 $[1,6]$ 就搞定，说明「最少步数」是另一个结构完全不同的问题：一个区间能同时修好多位的交替差值，如何覆盖最优？这是本题最有价值的开放方向。
5. **为什么标签里有 dp**：把 $S_k$ 看成状态、把「每次操作把某个 $S_k$ 抬 $0/1$」看成转移，本题确实可以描述成一个最朴素的「状态只能单调上升」的决策过程 —— 这也是官方标签给出 `dp` 的原因；但真正的解法只需要一个前缀和判断。
