# Codeforces 法国的首都是哪里 题解

## 1. 题目概述

- **标题 / 题号**：法国的首都是哪里（Codeforces 2261B，英文名 What's the Capital of France?）
- **链接**：https://codeforces.com/problemset/problem/2261/B
- **来源**：WorldQuant Round 1 (Codeforces Round 1128, Div. 1 + Div. 2) · Problem B
- **难度**：$\ast 1100$（1000 分）
- **限制**：时间 1.5 s / 内存 256 MB
- **标签**：位运算、贪心、数学

**题意**：$n$ 家餐厅排成一行，第 $i$ 家的评分是 $a_i$。一次操作选定相邻的两家 $i, i+1$：若两者评分不同，把**较低**的那家评分 $+1$；若相同则什么都不发生。可以进行零次或任意多次操作，操作后定义「美味度」为所有评分的**按位或**，求能得到的最大美味度。多测：第一行组数 $t$，每组给出 $n$ 与 $a_1,\dots,a_n$，逐组输出答案（$n=1$ 时无法操作）。

**约束**：

- $1 \le t \le 10^4$，$1 \le n \le 2\times 10^5$，且所有测试的 $n$ 之和 $\le 2\times 10^5$
- $0 \le a_i \le 10^9$，即数值位宽 $\le 30$ 位
- 时限 1.5 s：每组只允许近似 $O(n)$，不能模拟操作（单次操作链最长可达 $n \cdot M$）

## 2. 示例

官方样例（输入 / 输出原样）：

```text
输入
4
1
0
2
1 2
2
4 6
3
8 8 8

输出
0
3
7
8
```

官方解释要点：第 1 组无法操作；第 2 组不动最好（$1\mid 2=3$）；第 3 组把 $4$ 抬成 $5$，$5\mid 6=7$；第 4 组三家相等，操作无效，答案就是 $8$。

再补一组自造数据（非官方，用来验证「补低位」这一现象）：

```text
输入
3
2
10 8
3
5 1 5
4
12 9 12 9

输出
11
7
15
```

第 1 组把 $8$ 抬到 $9$ 得到 $10\mid 9=1011_2=11$；第 2 组把中间的 $1$ 抬到 $3$ 得到 $5\mid 3=111_2=7$；第 3 组把某个 $9$ 抬到 $11$ 得到 $12\mid 11=1111_2=15$。

## 3. 解题思路

### 3.1 暴力思路

直接 BFS 所有可达状态：每个值最多涨到 $\max a$，状态数最坏 $(M+1)^n$，$M = 10^9$ 时天文数字。即便只做「枚举把某个元素抬到某个值」的二维枚举，也是 $O(n \cdot M)$，同样不可行。必须找出**不需要搜索**的结构。

先明确三个量：$M = \max a_i$（全局最大）、$m = \min a_i$（全局最小）、$S = a_1 \mid a_2 \mid \cdots \mid a_n$（初始按位或）。

### 3.2 核心观察：只有「最大与最小的最高不同位」决定能补哪些 1

![最高不同位与可补的低位](images/cf2261_b_bit_split_concept.svg)

**观察 1（值域被夹住）**：操作只会抬高**较小**的那一个，所以取到 $M$ 的那家永远不会被抬（它不可能比邻居小），$M$ 全场不变；同时任何值只增不减，故所有终值都落在 $[m, M]$ 内。

**观察 2（高位锁死）**：令 $k$ 为 $M$ 与 $m$ 二进制下的**最高不同位**：$k$ 位以上两者完全相同，$M$ 的第 $k$ 位是 $1$、$m$ 的第 $k$ 位是 $0$。对任意 $v \in [m, M]$，若 $v$ 在某个 $j > k$ 的位上与 $M$ 不同，取两者**最高**的不同位 $t \ge j > k$：若 $v_t = 1, M_t = 0$ 则 $v > M$；若 $v_t = 0, M_t = 1$ 则（因 $t > k$ 有 $m_t = M_t = 1$，且更高位相同）$v < m$。两种情况都矛盾。于是：

> 所有可达值的所有 $> k$ 的位，都与 $M$ 的对应位相同。

换句话说，**答案在 $k$ 位以上只可能是 $S$ 里本来就有的位，一位也新增不了**；而 $0 \sim k-1$ 位最多就是全 $1$。因此上界是 $S \mid (2^k - 1)$。

**观察 3（上界可达）**：构造 $c$ = 「$M$ 的高位照抄，第 $k$ 位写 $0$，低 $k$ 位全写 $1$」，即

$$c = \bigl(M \gg (k+1) \ll (k+1)\bigr) \;\big|\; (2^k - 1)$$

则 $m$ 的每个为 $1$ 的位都落在 $c$ 里（即 $c \supseteq m$，等价于 $m \le c$），且 $c$ 与 $M$ 第一次不同就在第 $k$ 位、$c$ 取 $0$，故 $c < M$，于是 $m \le c < M$。从取到 $M$ 的位置出发向取到 $m$ 的位置逐个抬高：每一步都有值为 $c$（或本来就 $\ge c$）的邻居当梯子，于是能一路把最小值那家抬到 $c$。终态的或为 $M \mid c = S \mid (2^k - 1)$，上界取到。

把 $k$ 换成本文代码里的 $h = k+1$（即 $M \oplus m$ 的二进制位数）写法更省事：

$$\text{ans} = S \;\big|\; \bigl((1 \ll h) - 1\bigr),\qquad h = \operatorname{bitLength}(M \oplus m)$$

两种写法等价，因为第 $k$ 位本来就属于 $S$（$M$ 在这一位是 $1$）。

### 3.3 算法流程

![算法流程](images/cf2261_b_flow.svg)

每组数据只需要一遍扫描：

1. 读入 $n$ 与数组，同时求出 $M = \max$、$m = \min$、$S = $ 全部元素的或。
2. 令 $d = M \oplus m$，$h = d$ 的二进制位数（$d = 0$ 时 $h = 0$）。
3. 答案 $\text{ans} = S \mid ((1 \ll h) - 1)$，逐组输出。

$d = 0$ 表示所有元素相等（含 $n = 1$），此时 $(1 \ll 0) - 1 = 0$，答案就是 $S$，不需要任何特判。

### 3.4 示例演算

![示例演算表](images/cf2261_b_walkthrough.svg)

| 数组 | $M$ | $m$ | $S$ | $M \oplus m$ | $h$ | 答案 |
|------|-----|-----|-----|--------------|-----|------|
| $[0]$ | 0 | 0 | 0 | 0 | 0 | 0 |
| $[1,2]$ | 2 | 1 | 3 | 3 | 2 | $3\mid 3 = 3$ |
| $[4,6]$ | 6 | 4 | 6 | 2 | 2 | $6\mid 3 = 7$ |
| $[8,8,8]$ | 8 | 8 | 8 | 0 | 0 | 8 |
| $[10,8]$ | 10 | 8 | 10 | 2 | 2 | $10\mid 3 = 11$ |
| $[12,9,12,9]$ | 12 | 9 | 13 | 5 | 3 | $13\mid 7 = 15$ |

以 $[10, 8]$ 为例（$M = 1010_2$，$m = 1000_2$，$k = 1$）：把 $8$ 抬到 $9 = 1001_2$，此时或为 $1010\mid 1001 = 1011_2 = 11$，正好是上界；若继续把 $9$ 抬到 $10 = M$，或又退回 $1010_2 = 10$。所以「抬到最大」并不是最优，抬到 $c$ 就停才对。

## 4. 算法细节

1. **只统计，不模拟**：每组维护 $M, m, S$ 三个量即可，循环体 $O(1)$，绝不要真的去执行 $+1$ 操作。
2. **位宽用循环求**：C++ 里写 `while (d) { ++k; d >>= 1; }` 或 `31 - __builtin_clz(d)`（注意 `d = 0` 时 `clz` 未定义，必须先判空）；Python 直接 `(M ^ m).bit_length()`。
3. **掩码的安全写法**：`(1LL << h) - 1`，$h \le 30$ 时 `1 << h` 也安全，但用 `long long` 更保险（若题目值域到 $10^{18}$，$h$ 可能到 $60$，`int` 会 UB）。
4. **不开 `long long` 数组**：只需要 $M, m, S$ 三个标量，读一个处理一个，空间 $O(1)$，也顺带避免 $2\times 10^5$ 的额外开销。
5. **快读**：$t$ 最大 $10^4$、总元素 $2\times 10^5$，`std::ios::sync_with_stdio(false)` + `cin.tie(nullptr)` 足够；Python 用 `sys.stdin.buffer.read().split()` 一次性读入。
6. **输出格式**：每组一行，用 `'\n'` 而不是 `endl`，避免每次刷新缓冲区。
7. **不要对每组重新分配大容器**：本题用不到容器；若改用 `vector`，多测时注意 `clear()` 与容量复用。

## 5. 正确性证明

**引理 1（值域不变式）**：任何操作序列中，全局最大值恒为 $M$，且每个元素的值始终属于 $[m, M]$。

**证明**：一次操作只把两者中**较小**的那个 $+1$，且 $+1$ 后不超过另一个。设当前最大值为 $M'$，操作涉及 $x \le y$，则 $x$ 变成 $x+1 \le y \le M'$，最大值不增；而 $M'$ 对应的元素若没有被操作则不变，若被操作则它必然是较小的那个，与它是全局最大矛盾。故最大值恒为 $M$。值只增不减，故下界 $m$ 保持；上界由最大值恒为 $M$ 给出。∎

**引理 2（高位锁定）**：设 $k$ 是 $M$ 与 $m$ 的最高不同位，则对任意 $v \in [m, M]$ 与任意 $j > k$，$v$ 的第 $j$ 位等于 $M$ 的第 $j$ 位。

**证明**：因 $j > k$，$M$ 与 $m$ 在第 $j$ 位相同。反设 $v$ 与 $M$ 在第 $j$ 位不同，取二者**最高**的不同位 $t \ge j > k$。若 $v_t = 1, M_t = 0$：在 $t$ 位以上 $v$ 与 $M$ 相同，故 $v > M$，矛盾；若 $v_t = 0, M_t = 1$：由 $t > k$ 得 $m_t = M_t = 1$，且在 $t$ 位以上 $v$ 与 $M$（也就是 $m$）相同，故 $v < m$，矛盾。∎

**引理 3（上界）**：任何可达终态的按位或都不超过 $S \mid (2^k - 1)$。

**证明**：由引理 1，每个终值属于 $[m, M]$；由引理 2，每个终值在 $> k$ 的位上与 $M$ 相同，故或的这些位是 $M$ 的位的子集，而 $M$ 的位都在 $S$ 中。第 $k$ 位：$M$ 在该位为 $1$，也在 $S$ 中。$0 \sim k-1$ 位最多全为 $1$，即至多贡献 $2^k - 1$。三部分合起来，或 $\subseteq S \mid (2^k - 1)$（按位包含），数值上也就 $\le S \mid (2^k - 1)$。∎

**引理 4（上界可达）**：存在操作序列使终态按位或恰为 $S \mid (2^k - 1)$。

**证明**：取 $c = (M \gg (k+1) \ll (k+1)) \mid (2^k - 1)$。逐位看 $c$ 与 $m$：$k$ 位以上二者都等于 $M$ 的位，第 $k$ 位都是 $0$，低 $k$ 位 $c$ 全为 $1$，故 $c \supseteq m$，即 $m \le c$；而 $c$ 与 $M$ 的最高不同位是 $k$ 且 $c$ 为 $0$，故 $c < M$。设 $p$ 处取值 $M$、$q$ 处取值 $m$，沿 $p \to q$ 的顺序把下一个元素一路 $+1$ 抬到 $c$：这一步始终有值为 $c$ 或 $\ge c$ 的邻居可当梯子（邻居值 $>$ 当前值才可抬，抬到 $c$ 即停），因此可以做到。终态中该元素等于 $c$，其余元素值只增不减，故终态或 $\supseteq M \mid c$。另一方面每个初始值 $a_j \subseteq M \mid (2^k - 1) = M \mid c$（引理 2 的逐位论证），所以终态或 $\subseteq M \mid c$，两者相等，即等于 $S \mid (2^k - 1)$。∎

**定理**：算法输出的 $S \mid ((1 \ll h) - 1)$（$h = k+1$）就是最大美味度。

**证明**：$h = k+1$ 时 $(1 \ll h) - 1 = 2^{k+1} - 1 = (2^k - 1) \mid 2^k$，与 $2^k - 1$ 只差第 $k$ 位，而第 $k$ 位属于 $S$，故 $S \mid (2^{k+1} - 1) = S \mid (2^k - 1)$。由引理 3 它是上界、由引理 4 它可达，故为最大值。∎

## 6. 复杂度分析

- **时间**：每组一遍扫描 $O(n)$，总额 $O(\sum n) \le 2\times 10^5$ 次基本运算；求 $h$ 是 $O(\log A) \le 30$ 次移位。相对 1.5 s 时限有极大余量（实测见下）。
- **空间**：$O(1)$ 额外空间（只存 $M, m, S$），输入若整体读入则 $O(\sum n)$，C++ 流式读入时为 $O(1)$。
- **实测**：$t = 10^4$、$\sum n = 2\times 10^5$ 的最坏数据，本机 C++ 约 $0.45$ s（几乎全花在输入解析上，本机 `libc++` 的 `cin` 偏慢），Python 约 $0.12$ s；逻辑本身是线性的，远低于时限。

## 7. 参考代码

### C++17

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    if (!(cin >> T)) return 0;
    while (T--) {
        int n;
        cin >> n;
        long long mn = (long long)4e18, mx = -1, orAll = 0;
        for (int i = 0; i < n; ++i) {
            long long x;
            cin >> x;
            mn = min(mn, x);
            mx = max(mx, x);
            orAll |= x;
        }
        // k = 最高不同位下标，h = k + 1 = (mx ^ mn) 的二进制位数
        int h = 0;
        unsigned long long d = (unsigned long long)(mx ^ mn);
        while (d) { ++h; d >>= 1; }
        long long ans = orAll | ((1LL << h) - 1);   // h = 0 时掩码为 0
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    if not data:
        return
    t = data[0]
    pos = 1
    out = []
    for _ in range(t):
        n = data[pos]
        pos += 1
        a = data[pos:pos + n]
        pos += n
        s = 0
        for v in a:
            s |= v
        h = (max(a) ^ min(a)).bit_length()      # max = M，min = m
        out.append(str(s | ((1 << h) - 1)))     # h = 0 时掩码为 0
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n = 1$ 或所有元素相等**：$M = m$，$M \oplus m = 0$，$h = 0$，掩码为 $0$，答案就是 $S$。此时确实一步也动不了，不能凭空造出更大的或。
2. **$a_i = 0$**：如 $[0]$ 输出 $0$；$[0, 8]$ 时 $M = 8, m = 0$，$h = 4$，答案 $8\mid 15 = 15$（把 $0$ 抬到 $7$ 即可），注意别把 $0$ 当作「没有元素」跳过。
3. **编译器 / 溢出**：`1 << h` 中 $h$ 若到 $31$ 就是未定义行为，统一写 `1LL << h`；本题 $h \le 30$，但仍推荐 `long long`。
4. **不要抬过头**：$[10, 8]$ 抬到 $9$ 得 $11$，抬到 $10$ 反而退回 $10$ —— 最优解是抬到 $c$ 而不是最大元素。
5. **不要以为低位总能补**：$k$ 位以上的位是补不了的，例如 $[8, 9]$ 的答案是 $9$ 而不是 $15$（$k = 0$，掩码为 $0$）。
6. **多测的读入**：$\sum n \le 2\times 10^5$，但不能因为单组很小就对每组做与 $M$ 相关的循环；也不能用 `endl` 或每组重建大数组。
7. **Python 的 `bit_length()`**：$0$ 的 `bit_length()` 是 $0$，正好对应"不补位"，无需特判；切片 `a[pos:pos+n]` 只做一次，不会退化。

**延伸思考**：如果把操作改成「选任意两个（不必相邻），把较小者 $+1$」，答案会不会变大？本题的构造只依赖「最大值能沿链传递到最小值」，所以相邻性其实不是瓶颈。若要求**恰好** $k$ 次操作，则要额外讨论能否把多出来的步数「空转」（把两个相等元素互相比较即可消耗一步，但会破坏构造），这是另一个方向的分类讨论。若把「或」换成「与」，由于抬升只增不减，与只会变小，答案退化为不动；换成「异或」则完全不单调，需要重新建模。
