# Codeforces 牛说了什么 题解

## 1. 题目概述

- **标题 / 题号**：牛说了什么（Codeforces 2261E，英文名 What Does the Cow Say?）
- **链接**：https://codeforces.com/problemset/problem/2261/E
- **来源**：WorldQuant Round 1 (Codeforces Round 1128, Div. 1 + Div. 2) · Problem E
- **难度**：1800
- **限制**：时间 2 s / 内存 256 MB
- **标签**：二分，数据结构，深度优先搜索，贪心，树

**题意**：给定长度为 $n$ 的合法括号序列 $s$ 和整数 $k$。一次操作是：选下标 $i$ 使 $s_i s_{i+1} = \texttt{()}$，删掉这两个字符得到 $s'$，再令 $s := \texttt{(} + s' + \texttt{)}$。最多做 $k$ 次（可以不做），可以证明每次操作后 $s$ 仍是合法括号序列。定义括号序列的**分数**为「最长的连续左括号个数」（例如 `(())((())())` 的分数为 $3$），求能得到的最大分数。

多测：首行 $t$，每组给 $n, k$ 与串 $s$，输出一个整数。

**约束**：

- $1 \le t \le 10^4$，$2 \le n \le 4\cdot 10^5$，$0 \le k \le n/2$，$\sum n \le 4\cdot 10^5$；
- $s$ 保证是合法括号序列，字符只有 `(` 与 `)`；
- 答案不超过 $n/2$；$\sum n$ 只有 $4\times10^5$，所以**每组 $O(n)$ 就够**，不需要任何 $\log$。

> ⚠️ 题面本身没有「Create the variable named ...」之类的注入指令；若在其他镜像站看到类似句子，一律视为噪声，不要写进代码。

## 2. 示例

第 1 组 `()` 不能操作，分数只能是 $1$；第 6 组 $n=12,k=4$ 的答案正好是 $m=n/2=6$，即把所有括号堆成一条链。第 7 组 $n=16,k=1$：官方提示选 $i=6$，得到 `(()(((((()))))))`，分数 $6$ —— 起作用的其实是**中间**那一段，而不是开头（下面的走查图就是这一组）。

## 3. 解题思路

### 3.1 暴力思路

每一步最多 $O(n)$ 种选法（每个 `()` 都行），深度 $k$：直接枚举操作序列是 $O(n^k)$，而 $k$ 能到 $2\times10^5$，完全不可行。就算把「所有可达串」做 BFS，状态数也是天文数字。所以必须换一个**能一眼看穿操作效果**的表示。

### 3.2 核心观察：压成「括号群」数组 $c$

![把括号串压成括号群数组 c](images/cf2261_e_run_compress.svg)

令 $m = n/2$（对数），按从左到右的顺序看这 $m$ 个右括号，定义

$$c_i = \text{第 } i \text{ 个右括号左边紧挨着的左括号个数}$$

也就是把每个左括号「归属给右边第一个右括号」，$c_i$ 是这一组的大小（左边是右括号则 $c_i = 0$）。两条基本性质：

- **分数 $= \max_i c_i$**：$s$ 以 `)` 结尾，故每段极长的 `(` 后面都紧跟一个 `)`，段长恰好是某个 $c_i$；反之 $c_i > 0$ 就给出这样一段。
- **$\sum_i c_i = m$**：$c$ 只是把 $m$ 个左括号分了组，总质量恒定。

再把操作翻译过去。选中的 `()` 一定是「第 $j$ 段括号群的最后一个 `(` ＋ 第 $j$ 个 `)`」，要求 $c_j \ge 1$。删掉之后，原第 $j+1$ 个 `)` 顶上来成为第 $j$ 个，它前面的括号群变成 $(c_j - 1) + c_{j+1}$；然后最前面补一个 `(`（与原第一段连成一片，**首项 $+1$**）、末尾补一个 `)`（前面是 `)`，新项为 $0$）。于是

$$\bigl(c_1,\ \dots,\ c_j,\ c_{j+1},\ \dots,\ c_m\bigr)\ \longrightarrow\ \bigl(c_1+1,\ \dots,\ c_j + c_{j+1} - 1,\ \dots,\ c_m,\ 0\bigr)$$

说得直白一点：**① 吃掉右邻居**，$c_j \leftarrow c_j + c_{j+1} - 1$（合并两堆、自身少 $1$），后面的项整体左移一格、末尾补 $0$；**② 首堆 $+1$**，新加的那个 `(` 顶在最前面。当 $j = 1$ 时两步叠加成 $c_1 \leftarrow c_1 + c_2$，也就是**首堆的合并是无损的**。后面所有结论都由这条「无损 / 有损」的差别推出来。

> 💡 树视角：括号串对应森林（每个匹配对是一个点，嵌套是父子关系），分数就是「沿第一个孩子一路往下」的最长链。一次操作 $=$ 删一个叶子 $+$ 在最外面套一个新根；被删的叶子若是父节点的第一个孩子，父节点的 `(` 就和下一个兄弟的 `(` 接上——这正是引理 2 里的「$-1$ 合并」。树视角解释了「为什么会合并」，但真正好算的是 $c$ 数组，所以本篇不建树。

### 3.3 算法流程：答案只有两种落点

![两种落点以及滑动窗口求中间段](images/cf2261_e_two_cases.svg)

最终取到最大值的那一堆 $H$，只可能是两种情况。

**情况 A：$H$ 是首堆（前缀段）。** 首堆依次吞并 $c_2, c_3, \dots, c_{r+1}$，花 $r$ 次操作拿到完整的 $P_{r+1} = c_1 + \dots + c_{r+1}$；剩下的 $k-r$ 次操作只能在 $j \ge 2$ 上做，每次给首堆 $+1$。故 $\text{ans}_A(r) = P_{r+1} + (k - r)$，其中 $0 \le r \le \min(k,\ m-1)$。但总质量只有 $m$，还要截断；令 $Q_i = P_i - i$，则 $P_{r+1} + k - r = Q_{r+1} + k + 1$，于是

$$\text{ans}_A = \min\Bigl( (k+1) + \max_{1 \le i \le \min(k+1,\, m)} Q_i,\ \ m \Bigr)$$

**情况 B：$H$ 在中间（中间段）。** 它只能靠普通合并攒出来：把连续的一段 $c_L, \dots, c_R$ 压成一堆要 $R-L$ 次操作，每次自身 $-1$，于是

$$\text{val}(L,R) = \bigl(P_R - P_{L-1}\bigr) - (R-L) = Q_R - Q_{L-1} + 1, \qquad R - L \le k$$

即 $\text{ans}_B = \max\bigl\{Q_R - Q_{L-1} + 1\bigr\}$，其中 $0 \le L-1 < R \le m$ 且**下标差** $R-(L-1) \le k+1$。这是一维「窗口最值」：对每个 $b = R$，在窗口 $[b-k-1,\ b-1]$ 中取 $Q$ 的最小值，单调队列 $O(m)$。最后 $\text{ans} = \max(\text{ans}_A, \text{ans}_B)$。

> ⚠️ 情况 B 中若某区间从左端合并时中途被压成 $0$（例如 $c=[2,1,0,1,1]$ 的 $[2,4]$：第一步 $1+0-1=0$ 就再也合不动了），把左端右移一位即可，**值不变、代价更小**，故不影响 $\max$（见引理 4）。

### 3.4 示例演算

![样例 7 的走查表](images/cf2261_e_walkthrough.svg)

第 7 组 $s = \texttt{()(((()((())))))}$（$n=16,\ k=1$）：$m=8$，$c = [1,4,3,0,0,0,0,0]$，$P = [0,1,5,8,8,8,8,8,8]$，$Q = [0,0,3,5,4,3,2,1,0]$。

- 情况 A：$r=1$，首堆吞并 $c_2 = 4$，得 $1+4=5$；用公式 $\min(2+\max(Q_1,Q_2),\ 8)=\min(2+3,\ 8)=5$。
- 情况 B：区间 $[2,3]$，$(4+3)-1=6$，只花 $1$ 次操作；用公式 $Q_3-Q_1+1 = 5-0+1 = 6$。

$\text{ans} = \max(5,6) = 6$，与官方输出一致。串层面的操作正是提示里的 $i=6$：删掉第 $6,7$ 位的 `()` 后整体套一层，前两段括号群 $4$ 与 $3$ 拼成 $6$ 个连续 `(`。（第 6 组可自行验证：$c=[3,1,0,1,0,1]$，情况 A 得 $2+4+1=7$ 截断到 $m=6$，情况 B 只有 $3$，答案 $6$。）

## 4. 算法细节

1. **不必真的存 $c$**：扫一遍串，遇到 `(` 就 `run++`，遇到 `)` 就令 $P$ 多一项 `P[idx+1] = P[idx] + run`，$c$ 自然被前缀和吸收；$Q_i = P_i - i$ 也现算，省一个数组。
2. **$\text{ans}_A$ 的上界**是 $i \le \min(k+1, m)$：$i-1$ 是吸收次数，既不能超过 $k$，也不能超过 $m-1$。若错写成 $i \le k$，会漏掉 $i = k+1$（把 $k$ 次全用于吸收）的情形。
3. **$\text{ans}_B$ 的约束是下标差** $R-(L-1) \le k+1$，不是「区间长度 $\le k$」。单调队列里 $a$ 的下界是 $b-(k+1)$，错一位样例 7 就会答 $5$。
4. **单调队列的顺序**：先弹过期队首，再用队首更新答案，最后把 $b$ 入队（入队前弹掉尾部 $\ge Q_b$ 的元素）。若先入队再取 min，会取到 $a=b$，差值恒为 $0$。
5. **多测**：$k$ 用 `long long` 读入后 clamp 到 $m$；$P$ 每组 `vector` 重开（或复用且只清前 $m+1$ 项），不要 `memset` 整个 $4\times10^5$ 的固定数组，否则 $t=10^4$ 时白跑 $4\times10^9$。
6. **I/O**：C++ 用 `ios::sync_with_stdio(false)` + `cin`/`cout` 即可（$4\times10^5$ 级别完全够）；Python 一次性 `sys.stdin.buffer.read().split()`，并把 `(` 判成 `40` 省掉解码。

## 5. 正确性证明

**引理 1（分数与总和）**：任意时刻 $\text{score}(s) = \max_i c_i$，且 $\sum_i c_i = m$。

**证明**：$s$ 以 `)` 结尾，故每段极长的 `(` 必然紧跟一个 `)`，段长即对应位置的 $c_i$；反之每个 $c_i > 0$ 也对应一段，故分数 $=\max c_i$。又 $c_i$ 是把 $m$ 个左括号按「右边第一个右括号」分组后各组的大小，故和为 $m$。∎

**引理 2（操作在 $c$ 上的作用）**：对满足 $c_j \ge 1$ 的 $j$ 做一次操作，$c$ 变为 $(c_1+1,\ c_2,\ \dots,\ c_{j-1},\ c_j+c_{j+1}-1,\ c_{j+2},\ \dots,\ c_m,\ 0)$，项数仍为 $m$；$j=1$ 时首项为 $c_1+c_2$。

**证明**：被删的是第 $j$ 段的最后一个 `(` 与第 $j$ 个 `)`。删完后第 $j+1$ 个 `)` 顶上来成为第 $j$ 个，它前面的括号群是 $(c_j-1)+c_{j+1}$。最前面补的 `(` 与原来的第一段相邻，故首项 $+1$（$j=1$ 时首项正是 $(c_1-1)+c_2$，加 $1$ 后为 $c_1+c_2$）；末尾补的 `)` 前面是 `)`，新项为 $0$。右括号数不变，故项数不变。∎

**引理 3（两种合并的代价）**：(a) 把前缀 $c_1,\dots,c_{r+1}$ 合成首堆恰好要 $r$ 次操作，得到 $P_{r+1}$；(b) 把非首堆的连续区间 $c_L,\dots,c_R$ 合成一堆要 $R-L$ 次操作，得到 $\sum_{i=L}^{R} c_i - (R-L)$。

**证明**：(a) 反复做 $j=1$ 的操作，每步 $c_1 \leftarrow c_1 + c_2$（引理 2 的 $j=1$ 情形，无损失），$r$ 步后首项为 $c_1+\dots+c_{r+1}$。(b) 合并只发生在相邻两堆之间且保序，故任意时刻每一堆都是原数组某段连续区间的合并；把长度 $s=R-L+1$ 的区间压成一堆要 $s-1$ 次普通合并，每次使该堆 $-1$，共减 $R-L$。∎

**引理 4（上界与可合并性）**：设最终某个堆 $H$ 取到最大值。① 若 $H$ 是首堆，则存在 $r \le \min(k, m-1)$ 使 $H \le P_{r+1} + (k-r)$，且 $H \le m$；② 若 $H$ 在位置 $\ge 2$，则存在连续区间 $[L,R]$ 满足 $R-L \le k$ 且 $H = \sum_{i=L}^{R} c_i - (R-L)$；③ 若把 $[L,R]$ 从左端逐次合并时某一步把左端堆压成 $0$（位置 $t$），则 $\text{val}(L,R) = \text{val}(t+1,R)$，后者更短、代价更小。

**证明**：首堆只能靠「吞并此时的位置 $2$」增长，而每次吞并后原位置 $3$ 才顶上来，故它吞并的必是前缀 $c_2,\dots,c_{r+1}$；即使先用普通合并把它们并起来再吞，节省与损失正好抵消，仍是 $r$ 次操作换来 $P_{r+1}-c_1$。其余每次操作只能给首堆 $+1$，故 $H \le P_{r+1}+(k-r)$；又 $\sum c_i = m$ 且其它堆非负，故 $H \le m$。② 由引理 3(b) 得出，其 $R-L$ 次合并不能超过总操作数 $k$。③ 压成 $0$ 意味着 $\sum_{i=L}^{t} c_i - (t-L) = 0$，代入即得 $\text{val}(L,R) = \bigl(\sum_{i=L}^{t} c_i - (t-L)\bigr) + \sum_{i=t+1}^{R} c_i - (R-t) = \sum_{i=t+1}^{R} c_i - (R-t) = \text{val}(t+1,R)$，且 $R-(t+1) < R-L$，递归归纳即得结论。∎

**定理**：$\text{ans} = \max(\text{ans}_A, \text{ans}_B)$，其中 $\text{ans}_A$、$\text{ans}_B$ 如 3.3 所定义。

**证明**：上界由引理 4 的 ①② 给出（注意 $P_{r+1}+k-r = Q_{r+1}+k+1$、区间值 $= Q_R-Q_{L-1}+1$ 的改写，以及 $H \le m$ 的截断）。可达性：情况 A 取使 $P_{r+1}+k-r$ 最大的 $r$，先做 $r$ 次 $j=1$ 操作吞并前缀，再做 $k-r$ 次 $j \ge 2$ 的操作（只要首堆之外还有质量就一定做得动；一旦外部质量耗尽，首堆已等于 $m$，与截断一致）；情况 B 取使 $Q_R-Q_{L-1}$ 最大的区间，从左往右合并，若受阻则按引理 4 的 ③ 换成更短的同值区间，归纳可得同值的可合并区间。故两边都能取到，等号成立。∎

## 6. 复杂度分析

- **时间**：每组一次扫描构造 $P$（$O(n)$）＋一次单调队列扫描（$O(m)$），合计 $O(n)$，总计 $O(\sum n) \le 4\times10^5$。本机实测（含进程启动，worst of 3）：单组 $n=4\times10^5$ 约 $30$ ms，$t=10^4$ 满额约 $50$ ms；相对 2 s 仍有 $40$ 倍以上余量（若判题机的 iostream 偏慢，把 `cin`/`cout` 换成 `scanf`/`printf` 可再降到 $7$ ms 左右）。Python 约 $0.16$ s，同样安全。
- **空间**：$O(m)$ 的 $P$ 数组（$4\times10^5$ 个 `int`，约 1.6 MB）＋ $O(m)$ 的单调队列（存下标），远小于 256 MB。
- **不需要二分/线段树**：$\text{ans}_B$ 只是「窗口内 $Q$ 的最小值」，单调队列即可；用 ST 表 + 二分也能做，但那是 $O(n\log n)$，没必要。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int T;
    cin >> T;
    while (T--) {
        int n; long long k;
        string s;
        cin >> n >> k >> s;
        int m = n / 2;                       // 对数 = 右括号数 = c 的项数
        vector<int> P(m + 1, 0);             // P[i] = c[1] + ... + c[i]
        int run = 0, idx = 0;
        for (char ch : s) {
            if (ch == '(') ++run;            // 当前括号群还在变长
            else { P[idx + 1] = P[idx] + run; ++idx; run = 0; }
        }
        int K = (int)min<long long>(k, m), best = 0;   // 操作数封顶 m
        // 情况 A：答案是前缀段（首堆），吸收前缀 + 剩余操作各 +1
        int lim = min(K + 1, m), maxQ = INT_MIN;
        for (int i = 1; i <= lim; ++i) maxQ = max(maxQ, P[i] - i);
        best = max(best, min(K + 1 + maxQ, m));
        // 情况 B：答案是中间段，区间 [L,R] 满足 R-(L-1) <= K+1
        deque<int> dq;                       // 单调队列，维护 Q[a] = P[a]-a 的最小值
        for (int b = 0; b <= m; ++b) {
            while (!dq.empty() && dq.front() < b - (K + 1)) dq.pop_front();
            if (!dq.empty()) best = max(best, 1 + (P[b] - b) - (P[dq.front()] - dq.front()));
            int qb = P[b] - b;
            while (!dq.empty() && (P[dq.back()] - dq.back()) >= qb) dq.pop_back();
            dq.push_back(b);
        }
        cout << best << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys
from collections import deque


def main():
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0]); pos = 1; out = []
    for _ in range(t):
        n, k = int(data[pos]), int(data[pos + 1]); s = data[pos + 2]; pos += 3
        m = n // 2
        P = [0] * (m + 1)
        run = idx = 0
        for ch in s:
            if ch == 40:                  # ord('(')
                run += 1
            else:
                P[idx + 1] = P[idx] + run
                idx += 1; run = 0
        K = min(k, m)
        lim = min(K + 1, m)
        best = min(K + 1 + max(P[i] - i for i in range(1, lim + 1)), m)   # 情况 A
        dq = deque()                                                      # 情况 B
        for b in range(m + 1):
            while dq and dq[0] < b - K - 1:
                dq.popleft()
            if dq:
                best = max(best, 1 + (P[b] - b) - (P[dq[0]] - dq[0]))
            qb = P[b] - b
            while dq and P[dq[-1]] - dq[-1] >= qb:
                dq.pop()
            dq.append(b)
        out.append(str(best))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n=2$（`()`）**：$m=1$，$P=[0,1]$，$Q=[0,0]$。情况 A 给出 $\min(k+1,1)=1$，情况 B 给出 $1$，答案恒为 $1$。虽然 $k$ 的上界是 $n/2=1$，答案却不是 $2$。
2. **$k=0$**：情况 A 的 $i$ 只能取 $1$，得 $c_1$；情况 B 退化成 $\max_i c_i$，即原串分数。两条路都能兜住 $k=0$。
3. **完全嵌套 `(((...)))`**：$c=[m,0,\dots,0]$，$Q_1 = m-1$，情况 A 给出 $\min(k+m,\ m)=m$，情况 B 也给出 $m$：已经最优，操作全是白费。
4. **全平坦 `()()()...`**：$c$ 全是 $1$，$Q_i = 0$，情况 A 给出 $\min(k+1, m)$，情况 B 给出 $1$，答案 $\min(k+1,m)$：每次操作只能把一段接到首堆上、多 $1$ 个连续 `(`。
5. **下标差 vs 区间长度**：情况 B 的约束是 $R-(L-1)\le k+1$。写成 $\le k$ 会在样例 7 上答 $5$，写成 $\le k+2$ 会超用操作次数。
6. **截断 $m$**：$k$ 接近 $m$ 时 $P_{r+1}+k-r$ 会超过 $m$，必须与 $m$ 取 min，否则会输出大于 $n/2$ 的非法值。
7. **单调队列顺序**：必须「弹过期队首 → 用队首更新答案 → 弹尾 → 入队 $b$」。若先把 $b$ 入队，就等于允许 $a=b$，差值恒为 $0$，情况 B 直接失效；另外 $t$ 可达 $10^4$，别用 `memset` 清 $4\times10^5$ 的全局数组。

## 相关题目与扩展

- [LeetCode 32. 最长有效括号](https://leetcode.cn/problems/longest-valid-parentheses/)：括号串上的经典栈 / DP 题，同样靠「按右括号编号」压缩信息。
- [LeetCode 1614. 括号的最大嵌套深度](https://leetcode.cn/problems/maximum-nesting-depth-of-the-parentheses/)：注意「嵌套深度」与「最长连续左括号」不同（`(()(()))` 深度为 $3$，最长连续 `(` 只有 $2$），这正是本题不能用树高、必须用括号群的原因。
- [Codeforces 1821E. Rearrange Brackets](https://codeforces.com/problemset/problem/1821/E)：括号树 + 贪心，与本篇「合并代价」的思路相近。

**延伸思考**：

1. 若分数改成「最大嵌套深度」，答案会变成 $\min(D+k,\ m)$（$D$ 为原深度）：因为每层括号都是整棵子树一起加一层，不会被「合并代价」罚分。这解释了本题为何必须绕到括号群上——分数取的是「同一段里连续出现的 `(`」，合并会真的吃掉一个。
2. 若操作不是「套在最外层」而是「把 `()` 挪到任意位置」，则相当于删掉一段里的 `)` 并把 `(` 搬走，等价于求「含不超过 $k$ 个右括号的最大子段和」，需要 ST 表 + 二分做到 $O(n\log n)$ —— 这也正是本题 tags 里 binary search / data structures 的来源。
