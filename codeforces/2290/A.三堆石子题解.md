# Codeforces 三堆石子 题解

## 1. 题目概述

- **标题 / 题号**：三堆石子（Codeforces 2290A，英文名 Three Piles）
- **链接**：https://codeforces.com/problemset/problem/2290/A
- **来源**：Codeforces Round 1134 (Div. 4) · Problem A
- **难度**：未评级（无评分，Div. 4 签到题，约 800 档）
- **限制**：时间 1 s / 内存 256 MB
- **标签**：实现、数学

**题意**：有三堆石子，数量分别为 $a, b, c$。你**必须恰好做一次**移动：从某一堆取出 $1$ 颗石子，放到另外两堆中的某一堆上。不能跳过这次移动，也不能做第二次。问是否存在一种移动方式，使得移动后三堆石子数量完全相同；可以则输出 `YES`，否则输出 `NO`。多测，第一行是数据组数 $t$，之后每组一行三个整数，逐组输出一行答案。

**约束**：

- $1 \le t \le 1000$
- $1 \le a \le b \le c \le 10$ —— 输入**已经按非降序给出**，不必自己排序
- 移动次数必须**恰好为 $1$**：$0$ 次不行，$2$ 次也不行
- 总和 $a+b+c \le 30$，中间量全部落在 `int` 范围内，不需要 `long long`
- 答案大小写不敏感（`YES` / `yes` / `Yes` 都算对）

## 2. 示例

官方样例（输入 / 输出原样）：

```text
输入：
6
1 2 3
2 2 2
3 4 5
1 1 4
8 9 10
3 5 7

输出：
YES
NO
YES
NO
YES
NO
```

逐组解释：

| 用例 | 移动方式 | 结果 |
|------|----------|------|
| `1 2 3` | 第三堆给第一堆 $1$ 颗 | $2,2,2$ ✓ |
| `2 2 2` | 已经相等，但必须动一步 | 任何移动都会破坏相等 ✗ |
| `3 4 5` | 第三堆给第一堆 $1$ 颗 | $4,4,4$ ✓ |
| `1 1 4` | 需要给两堆各补 $1$ 颗，共 $2$ 次 | 一步不够 ✗ |
| `8 9 10` | 第三堆给第一堆 $1$ 颗 | $9,9,9$ ✓ |
| `3 5 7` | 总和 $15$ 能被 $3$ 整除，但差距是 $2$ | 一步跨不过 ✗ |

自造一组 $a=b$ 的极端数据（说明「必须恰好一步」的边界）：

```text
输入：
2
2 2 4
1 2 2

输出：
NO
NO
```

`2 2 4` 要把第三堆的两颗分别补给前两堆（$2$ 次）；`1 2 2` 要动两堆，共 $2$ 次。两者都不是一步能完成的。

## 3. 解题思路

### 3.1 暴力思路

每次移动只有 $3$ 种「取出」选择乘 $2$ 种「放入」选择，共 $6$ 种组合，逐一代入检查三堆是否相等即可，复杂度 $O(1)$。由于 $a,b,c \le 10$、$t \le 1000$，暴力本身完全跑得动，可以说是本题的合法解法之一。

但暴力有两个缺点：一是它只是「试」，没有解释**为什么**这组数据有解或没解；二是把题目规模放大（比如石子数到 $10^{18}$）后立刻失效。下面把枚举收敛成一个判据。

### 3.2 核心观察：从终态反推步前形态

![一步移动前后三堆形态的对应关系](images/cf2290_a_move_invariant_concept.svg)

关键有两点，都是「不变量 + 局部性」：

1. **总和不变**。一次移动只是把 $1$ 颗石子从一堆挪到另一堆，$S = a+b+c$ 在移动前后相同。若移动后三堆相等，则每堆必须等于 $m = S / 3$，于是 $S$ 必须是 $3$ 的倍数——这是**必要条件**。
2. **一次移动只碰两堆**。出石子的那堆在移动前是 $m+1$（交出去一颗才变 $m$），收石子的那堆在移动前是 $m-1$（收到一颗才变 $m$），第三堆被完全没碰，移动前后都是 $m$。因此移动前的三堆**被唯一确定**为

$$\{m-1,\ m,\ m+1\}$$

反过来这个条件也充分：若三堆恰是 $m-1, m, m+1$，只需从 $m+1$ 那堆取一颗放到 $m-1$ 那堆，三堆同时变成 $m$。

因为输入已保证 $a \le b \le c$，所以「三堆是连续的三个整数」等价于位置对应关系 $a = m-1,\ b = m,\ c = m+1$，即

$$b - a = 1 \quad \text{且} \quad c - b = 1$$

这就是最终判据：**两个相邻差都等于 $1$ 就输出 `YES`，否则输出 `NO`**。

> 💡 另一个等价写法是「$S \bmod 3 = 0$ 且 $c - a = 2$」。二者可互推：由 $c = a+2$ 知 $b$ 只能取 $a, a+1, a+2$，对应 $S \bmod 3$ 分别为 $2, 0, 1$，只有 $b = a+1$ 能让总和被 $3$ 整除。差值判据少一次加法与取模，也不涉及除法，更不容易写错。

### 3.3 算法流程

![每个测试用例只需一次比较的判定流程](images/cf2290_a_decision_flow.svg)

1. 读入 $t$；
2. 对每组数据读入 $a, b, c$（题面保证已非降序，**不要**再排序）；
3. 判断 `b - a == 1 && c - b == 1`：
   - 成立 → 输出 `YES`（从最大堆给最小堆一颗）；
   - 不成立 → 输出 `NO`；
4. 每组输出一行，直接进入下一组。

整个算法不保存任何跨组状态，每组恰好两次减法、两次比较。

### 3.4 示例演算

![六组官方样例的走查表](images/cf2290_a_walkthrough.svg)

| 组 | $a$ | $b$ | $c$ | $b-a$ | $c-b$ | 判定 |
|----|-----|-----|-----|-------|-------|------|
| 1 | 1 | 2 | 3 | 1 | 1 | YES |
| 2 | 2 | 2 | 2 | 0 | 0 | NO |
| 3 | 3 | 4 | 5 | 1 | 1 | YES |
| 4 | 1 | 1 | 4 | 0 | 3 | NO |
| 5 | 8 | 9 | 10 | 1 | 1 | YES |
| 6 | 3 | 5 | 7 | 2 | 2 | NO |

第 2 组是本题最典型的坑：三堆**本来就相等**，但规则要求必须移动一次，动完必然不相等，所以答案仍是 `NO`。第 6 组则说明「总和被 $3$ 整除」只是必要条件：$3+5+7 = 15$ 是 $3$ 的倍数，可两端的差是 $4$，一步只能补 $2$ 的差距。

## 4. 算法细节

1. **不要自己排序**：题面已保证 $a \le b \le c$。若额外排序但读入顺序搞反（比如把排序结果写回 `a,b,c` 后仍按原顺序使用），在 $a=c$ 之类的情形容易出错；直接用原始输入即可。
2. **多测无需清空**：判据只依赖当前三个整数，没有数组、没有累加器，循环内变量重新赋值即可，不存在「上一组残留」问题。
3. **优先用差值判断**：`b - a == 1 && c - b == 1` 不涉及除法与取模；若改写成 $m = S/3$ 的形式，务必先判 $S \bmod 3 = 0$ 再做整除，否则整数除法会把 $S = 5$ 截断成 $m = 1$，产生误判。
4. **严格的「恰好一步」**：判据本身就排除了「已经相等」的情形（此时两个差都是 $0$），所以不需要额外写 `if (a == b && b == c) NO;`；反过来说，如果题面改成「至多一步」，那么 `2 2 2` 必须输出 `YES`，答案要改成 `b-a==1 && c-b==1 || a==b && b==c`。
5. **I/O 开销**：$t \le 1000$，输出至多 $1000$ 行，`cout` 加 `std::ios::sync_with_stdio(false)` 后 $5$ ms 量级；Python 用 `sys.stdin.buffer.read().split()` 一次性读完、列表 join 后统一写出，比逐行 `print` 快一个数量级。
6. **输出格式**：每组恰好一行，不要输出多余空格或空行；`YES`/`NO` 大小写不敏感，但统一大写最稳妥。

## 5. 正确性证明

**引理 1（必要性：总和必被 $3$ 整除且三堆必为连续整数）**：若存在一次合法移动使三堆相等，则 $S = a+b+c$ 是 $3$ 的倍数，且移动前三堆的多重集合恰为 $\{m-1, m, m+1\}$，其中 $m = S/3$。

**证明**：设移动后三堆都为 $x$，则 $S = 3x$，故 $3 \mid S$ 且 $x = m = S/3$。移动只改变两堆：设从 $P$ 取 $1$ 颗放到 $Q$，剩下那堆记作 $R$、未被触碰。移动后三堆都是 $m$，于是 $R$ 移动前后都等于 $m$；$P$ 移动后为 $m$，故移动前 $P = m+1$；$Q$ 移动后为 $m$，故移动前 $Q = m-1$。$P, Q, R$ 是三堆的一个排列，故移动前的多重集合固定为 $\{m-1, m, m+1\}$。∎

**引理 2（充分性：连续整数一定可解）**：若三堆的多重集合为 $\{m-1, m, m+1\}$，则存在一次合法移动使三堆都等于 $m$。

**证明**：从值为 $m+1$ 的那堆取出 $1$ 颗（该堆有 $m+1 \ge 1$ 颗，取出后剩 $m \ge 0$ 颗，操作数合法），放到值为 $m-1$ 的那堆上（变成 $m$）。第三堆原本就是 $m$ 且未被触碰。移动后三堆均为 $m$。∎

**引理 3（判据等价性）**：在 $a \le b \le c$ 的前提下，$b-a = 1$ 且 $c-b = 1$ 当且仅当三堆多重集合为 $\{m-1, m, m+1\}$（某整数 $m$）。

**证明**：若两个差都为 $1$，取 $m = b$，则 $a = m-1,\ b = m,\ c = m+1$，且总和 $= 3m$ 被 $3$ 整除。反之若多重集合为 $\{m-1, m, m+1\}$ 且输入已排序，则 $a$ 是最小值必为 $m-1$、$b$ 是中间值必为 $m$、$c$ 是最大值必为 $m+1$，于是 $b-a = 1,\ c-b = 1$。∎

**定理**：对任意满足 $1 \le a \le b \le c$ 的输入，算法输出 `YES` 当且仅当存在一次合法移动使三堆相等。

**证明**：

- 若算法输出 `YES`，则两个相邻差都是 $1$，由引理 3 知三堆多重集合为 $\{m-1, m, m+1\}$，再由引理 2 存在一次合法移动使三堆都等于 $m$，故答案确为可行。
- 若算法输出 `NO`，假设存在一次合法移动使三堆相等，由引理 1 知移动前的三堆必为 $\{m-1, m, m+1\}$，由引理 3 推出两个相邻差都为 $1$，与算法输出 `NO` 矛盾。故不存在这样的移动。

两种情况合起来覆盖全部输入，判据与真值完全一致。∎

## 6. 复杂度分析

- **时间**：每组数据 $O(1)$——两次减法、两次比较、一次输出，总计 $O(t) \le 1000$ 次常数操作。C++ 实测（含进程启动）中位数约 $5.2$ ms，距 $1$ s 时限有三个数量级余量。
- **空间**：$O(1)$ 额外空间（三个整型变量）。Python 版一次性读入全部输入，缓冲区大小为 $O(t)$，约 $1000 \times 3$ 个短字符串，几十 KB 量级。
- **对照时限**：即便 $t$ 放大到 $10^6$，$O(t)$ 的读入输出也只需几百毫秒，瓶颈完全在 I/O 而非计算。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;              // 空输入防护
    while (t--) {
        int a, b, c;
        cin >> a >> b >> c;                 // 题面保证 a <= b <= c，无需排序
        cout << ((b - a == 1 && c - b == 1) ? "YES" : "NO") << "\n";
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        a = int(data[pos])
        b = int(data[pos + 1])
        c = int(data[pos + 2])
        pos += 3
        out.append("YES" if (b - a == 1 and c - b == 1) else "NO")
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **三堆本来就相等**：`2 2 2`（以及任何 `x x x`）必须是 `NO`，因为移动是强制的。这是本题最高频的 WA——直接把「三堆相等」当成 `YES`。
2. **$a = b$ 或 $b = c$**：如 `1 1 3`、`1 3 3`，两个差不可能同时为 $1$，答案一定是 `NO`；这类数据靠差值判据自动覆盖，不需要特判。
3. **最小的 `YES`**：`1 2 3`（移动后 $2,2,2$）。有人担心「取完石子会出现空堆」而额外加 $a \ge 2$ 的限制，这样会把 `1 2 3` 这类合法数据判错；出石子的是 $c = 3$ 那堆，取一颗后剩 $2$ 颗，$a = 1$ 只是接收方，完全合法。
4. **总和被 $3$ 整除但无解**：`3 5 7` 是最典型的反例，说明只看 $S \bmod 3$ 会漏判；另一侧的 `1 2 4`（$S = 7$）则连必要条件都不满足，同样 `NO`。
5. **把「恰好一次」写成「至多一次」**：多写一行 `if (a == b && b == c) YES;` 就会把 `2 2 2` 判错，务必只保留一条判据。
6. **多测输出**：每组一行，组间不加空行；`t` 次循环里不要把 `cout` 的换行写成空格。
7. **空输入**：个别评测环境会给空文件，C++ 用 `if (!(cin >> t)) return 0;`、Python 先判断 `if not data: return` 可避免异常。

**延伸思考**：

1. **至多一步**：若规则改为「最多移动一次」，判据变成「两个差都为 $1$，或三堆已相等」；若改为「恰好 $0$ 次」，答案就退化为「三堆相等」。
2. **一次搬多颗**：若一次可以从一堆搬 $k$ 颗（$1 \le k \le K$）到另一堆，条件变为：$c - a = 2d$、中间那堆正好等于 $m = S/3$（即 $a + d = m$）、且 $d \le K$；$d = 1$ 时退化成本题的判据。
3. **多堆推广**：$n$ 堆、只允许一次移动，则只有两堆被改动，其余 $n-2$ 堆必须已经等于 $m = S/n$，条件可以写成「总和被 $n$ 整除，且恰有两堆偏离 $m$ 一个单位、方向相反」。
4. **多步最优化**：允许任意多次移动时，只要 $S \bmod n = 0$，总能通过搬运达到平均；此时的问题是「最少需要搬几颗石子」，答案对所有堆取 $\sum \max(0, m - a_i)$，本题正是它的下界为 $1$ 的特例。
