# Codeforces 字母下移 题解

## 1. 题目概述

- **标题 / 题号**：字母下移（Codeforces 2290D，英文名 Letters Down）
- **链接**：https://codeforces.com/problemset/problem/2290/D
- **来源**：Codeforces Round 1134 (Div. 4) · Problem D
- **难度**：未评级（Div. 4 的 D 题，官方标签含并查集）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：数据结构，并查集，贪心，实现，字符串

**题意**：给定长度为 $n$ 的小写字符串 $s$。一次操作选定字母 $x\ne\texttt{a}$，把 $s$ 中**所有** $x$ 同时替换成字母表上的前一个字母 $x-1$（若 $x$ 不出现则操作不改变串）。求把 $s$ 变成**回文串**所需的最少操作次数。

关键点是操作的粒度是「**整个字母**」而不是「某个位置」：对 $x$ 的一次操作会把串中所有 $x$ 一起降一位，还会把此前已经降成 $x$ 的字母继续带着降。正是这种「批量传递」让答案呈现出区间合并的形状。

**约束**：

- $1 \le t \le 10^4$，$1 \le n \le 2\cdot 10^5$
- $\sum n \le 2\cdot 10^5$（多测总量受限，单组必须近 $O(n)$）
- 字符集只有 $26$ 个字母，且 $\texttt{a}$ 永远无法被修改

## 2. 示例

官方样例（$5$ 组）：

```text
输入
5
4
abca
4
abdc
7
racecar
4
cbad
4
zaza

输出
1
3
0
2
25
```

- `abca`：对称对只有 $(\texttt{a},\texttt{c})$ 冲突，做一次 $x=\texttt{c}$ 得 `abba`，答案 $1$。
- `abdc`：$\texttt{a}\leftrightarrow\texttt{c}$、$\texttt{b}\leftrightarrow\texttt{d}$ 两组都冲突，执行 $\texttt{d},\texttt{c},\texttt{b}$ 得 `aaaa`，答案 $3$。
- `cbad`：执行 $\texttt{d},\texttt{b}$ 得 `caac`，答案 $2$。
- `zaza`：$\texttt{z}$ 与 $\texttt{a}$ 必须对齐，只能把 $\texttt{z}$ 一路降到 $\texttt{a}$，执行 $\texttt{z},\texttt{y},\dots,\texttt{b}$ 共 $25$ 次。

自造样例（覆盖「区间重叠」这一坑点）：

```text
输入
3
4
dbec
3
cba
6
fedcba

输出
3
2
5
```

`dbec` 的两组冲突分别生成区间 $[\texttt{c},\texttt{d}]$ 与 $[\texttt{b},\texttt{e}]$：**长度相加是 $1+3=4$，但它们重叠，真正需要的边只有 $3$ 条**（详见 §3.4）。三组答案依次为 $3,2,5$。

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是 BFS：状态是当前字符串，边是「对某个 $x\in[\texttt{b},\texttt{z}]$ 操作一次」。状态空间上界是 $26^n$，$n$ 稍大就彻底爆炸；即便 $n=8$，可达状态也可能上万，而 $t$ 高达 $10^4$。另一条路是枚举操作序列，$25!$ 量级，同样不可行。

真正要抓的是：**操作的顺序和次数都不重要，重要的是「哪些字母被操作过」**。把这一点想清楚，问题立刻塌缩到只有 $25$ 条边的图上。

### 3.2 核心观察：操作 = 在字母表上合并一条相邻边

![字母链上的相邻边与强制合并区间](images/cf2290_d_edge_merge_concept.svg)

把 $26$ 个字母想成一条链，边 $i$ 连接字母 $i$ 与 $i+1$（$0\le i\le 24$，字母按 $\texttt{a}=0$ 编号）。**对 $x$ 操作一次，等于在 $x$ 与 $x-1$ 之间加一条边**：此后 $x$ 这个「池子」里的所有字母都流到了 $x-1$。

设最终执行的边集为 $E$。由于边只连接相邻字母，$E$ 的每个连通块都是**连续区间** $[l,r]$；而对 $x$ 的操作只会让字母变小，所以块内所有字母的最终值就是块内最小字母 $l$。于是

$$f(c)=l\ \ (c\in[l,r]),\qquad \text{打通块 }[l,r]\text{ 需要 } r-l \text{ 次操作}.$$

于是整个问题变成：**给字母链选一个区间划分，使得每个「必须相等」的字符对落在同一块里；代价是 $\sum (r-l)$，要求最小。**

而「$c$ 与 $d$（设 $c<d$）要落到同一个字母」这件事，中间字母是躲不掉的：要把 $d$ 降到 $c$，必须依次经过 $d\to d-1,\ d-1\to d-2,\ \dots,\ c+1\to c$，每一步都是一次独立操作，而且沿路的字母也会被一起卷进来。所以

> 💡 **冲突对 $(c,d)$（设 $c<d$）强制要求边 $c,c+1,\dots,d-1$ 全部执行**（共 $d-c$ 条）。

### 3.3 算法流程：差分标记 + 前缀和

![差分标记与计数流程](images/cf2290_d_diff_marking_flow.svg)

回文的充要条件是每个对称对 $(i,\ n-1-i)$ 的字符最终相等，也就是处在同一个连通块里。于是：

1. 枚举 $i=0,1,\dots,\lfloor n/2\rfloor-1$，令 $c=s_i$、$d=s_{n-1-i}$；
2. 若 $c=d$，这一对天然满足，跳过；否则取 $l=\min(c,d)$、$r=\max(c,d)$，把边 $l,\dots,r-1$ **整段**标记；
3. 统计被标记的边数即为答案。

「整段标记」用**差分**实现最省事：`diff[l]++ ; diff[r]--`，最后对 $i=0..24$ 做前缀和，`cur > 0` 就说明边 $i$ 被至少一个冲突对覆盖。

也可以从**并查集**的角度看（这正是题目标签的来源）：对每个冲突对把 $[l,r]$ 内相邻字母依次 `union`，一次成功的 `union` 就代表一条必须执行的边，答案 = 合并次数 = $26-\text{连通块数}$。两种写法完全等价，差分版是 $O(1)$ 标记，更快也更好写。

### 3.4 示例演算

![abdc 与 zaza 的走查表](images/cf2290_d_walkthrough.svg)

对 `abdc`（$n=4$）：

| 对称对 $(i,j)$ | 字符 | 区间 $[l,r]$ | 标记的边 |
|---|---|---|---|
| $(0,3)$ | $\texttt{a}\leftrightarrow\texttt{c}$ | $[\texttt{a},\texttt{c}]$ | $\texttt{a–b},\ \texttt{b–c}$ |
| $(1,2)$ | $\texttt{b}\leftrightarrow\texttt{d}$ | $[\texttt{b},\texttt{d}]$ | $\texttt{b–c},\ \texttt{c–d}$ |

两条区间在边 $\texttt{b–c}$ 处重叠，并集是 $\{\texttt{a–b},\texttt{b–c},\texttt{c–d}\}$，共 $3$ 条，答案 $3$；从高到低执行正好复现样例注释 `abdc → abcc → abbb → aaaa`。

再看 §2 的自造样例 `dbec`：冲突对生成 $[\texttt{c},\texttt{d}]$（$1$ 条边）和 $[\texttt{b},\texttt{e}]$（$3$ 条边），区间相加是 $4$，但并集只有 $\{\texttt{b–c},\texttt{c–d},\texttt{d–e}\}$ 三条边，答案 $3$——**这就是不能用 $\sum(r-l)$ 直接累加的原因**。

## 4. 算法细节

1. **只扫左半边**：$i$ 从 $0$ 到 $n/2-1$；$i=n-1-i$（奇数长度的正中字符）不可能与别人冲突，无需处理。
2. **差分数组开 $27$**：边 $i$ 覆盖 $i\in[0,24]$，但 `diff[r]--` 中 $r$ 最大取到 $25$，所以数组大小至少 $26$（下标 $0..25$），开 $27$ 最稳；前缀和只扫 $i<25$ 即可。
3. **不能累加区间长度**：重叠区间会被算多次。差分（或布尔标记 `need[i]=true`）保证每条边只贡献 $1$，这是本题唯一的「坑」。
4. **答案上界是 $25$**：最坏情况是 $\texttt{a}$ 与 $\texttt{z}$ 必须对齐，需要 $25$ 次操作，与 $n$ 无关；`int` 足够，无需 `long long`。
5. **$\texttt{a}$ 天然安全**：题目禁止对 $\texttt{a}$ 操作，而我们的边下端最小就是 $\texttt{a}$，标记过程永远不会要求「$\texttt{a}\to$ 前一个字母」，语义一致。
6. **多测清空**：$t$ 可达 $10^4$，`diff` 必须在每组内重新初始化（`int diff[27] = {0};` 或 `vector<int> diff(27,0)`），不要用上一组残留。
7. **读入方式**：用 `cin >> n >> s` / `sys.stdin.buffer.read().split()` 按 token 读；$n$ 保证与 `s.size()` 一致，用 `s.size()` 更稳。Python 里把 `bytes` 元素当 ASCII 码直接参与运算，省掉 `ord` 调用。
8. **I/O 优化**：$\sum n\le 2\cdot10^5$ 虽小，但 $t$ 大时换行输出次数多，C++ 用 `'\n'` 而非 `endl`，Python 用列表收集后一次 `join`。

## 5. 正确性证明

**引理 1（连通块给出最终值）**：设某操作方案里出现过的字母集合为 $X$（显然 $|X|\le$ 操作次数），边集 $E_X=\{(x,x-1):x\in X\}$，并设 $l$ 是字母 $c$ 在 $E_X$ 中所在连通块的最小字母。则 (a) 该方案结束后 $f(c)\ge l$；(b) 若把 $X$ 按**从大到小**各操作一次，则 $f(c)=l$。

**证明**：(a) 若 $l\in X$，则边 $(l,l-1)\in E_X$，块的最小字母会变成更小的值，与 $l$ 最小矛盾，故 $l\notin X$。而字母只有在「对 $l$ 本身操作」时才会降到 $l-1$ 及以下，所以任何方案下都不会有字母低于 $l$，得 $f(c)\ge l$。

(b) 在降序执行时，处理 $x$ 的那一刻，块内所有不小于 $x$ 的字母（原始字母与此前被降下来的字母）都恰好聚在 $x$ 上，被一次性送到 $x-1$；块外字母不会落在 $x$ 上——能降到 $x$ 的字母必经过边 $(x+1,x)\in E_X$，因而与 $x$ 同块。对块内字母归约可知：处理完 $l+1$ 之后块内所有字母都落在 $l$，此后 $l$ 不会再被操作（$l\notin X$），故最终值恰为 $l$。∎

**引理 2（区间强制）**：设 $c<d$。要使字符 $c$ 与 $d$ 最终相等，$(c,d]$ 中的每个字母都必须至少被操作一次。

**证明**：最终值 $f(d)\le d$ 且 $f(d)=f(c)\le c$。字母 $d$ 从 $d$ 降到 $c$ 的过程中必须经过 $d-1,d-2,\dots,c$ 每一个中间值，而每下降一位都需要一次「对当前值为 $k$ 的字母」的操作，即 $k\in X$。故 $(c,d]\subseteq X$。∎

**引理 3（可行性与代价）**：令 $E^*$ 为所有冲突对强制边的并集，则执行 $E^*$ 中每条边一次（按字母降序）恰好使每个对称对相等，代价恰为 $|E^*|$。

**证明**：由引理 2，对每个冲突对 $(c,d)$，$E^*$ 已包含 $c,\dots,d-1$ 全部边，故 $c$ 与 $d$ 在 $E^*$ 中连通，由引理 1 得 $f(c)=f(d)$，于是所有对称对相等，$s$ 成为回文。代价：每条边对应一次操作，共 $|E^*|$ 次。∎

**定理**：最少操作次数恰为冲突对强制边的并集大小 $|E^*|$。

**证明**：上界由引理 3 给出。下界：设某个 $k$ 次操作的方案成功，其操作字母集合为 $X$，$|X|\le k$。对每个冲突对 $(c,d)$，引理 2 给出 $(c,d]\subseteq X$，对所有冲突对取并即得 $E^*$ 的上端字母集合 $\subseteq X$，故 $|X|\ge |E^*|$，即 $k\ge|E^*|$。上下界重合。∎

## 6. 复杂度分析

- **时间**：每组扫描 $n/2$ 个对称对，$O(1)$ 差分标记；随后扫 $25$ 条边求前缀和。总计 $O(n+26)$ 每组，$O(\sum n + 26t)$，按 $\sum n\le2\cdot10^5$、$t\le10^4$ 估算不超过 $5\times10^5$ 次基本操作。
- **空间**：仅一个长度 $27$ 的差分数组与输入字符串，$O(n)$ 存串、$O(1)$ 额外空间，远低于 $256$ MB。
- **可行性**：本机（Apple clang + libc++）实测三组最大数据（$n=2\cdot10^5$ 随机串、$t=10^4$ 且 $\sum n=2\cdot10^5$、$n=2\cdot10^5$ 的 `azaz…`）均为 $0.01\sim0.02$ s（含进程启动），对 $2$ s 限时余量超过 $100$ 倍；Python3 同样数据 $0.12\sim0.17$ s，也在限时内。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;
    while (t--) {
        int n;
        string s;
        cin >> n >> s;

        // diff[i] 标记字母 i 与 i+1 之间的“边”是否必须被执行
        int diff[27] = {0};
        for (int i = 0; i < n / 2; i++) {
            int c = s[i] - 'a';
            int d = s[n - 1 - i] - 'a';
            if (c == d) continue;            // 这一对已经相等，不产生约束
            int l = min(c, d), r = max(c, d);
            diff[l]++;                       // 边 l, l+1, ..., r-1 全部要做
            diff[r]--;
        }
        int cur = 0, ans = 0;
        for (int i = 0; i + 1 < 26; i++) {
            cur += diff[i];
            if (cur > 0) ans++;              // 至少一个冲突对跨过这条边
        }
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys


def main():
    data = sys.stdin.buffer.read().split()
    p = 0
    t = int(data[p]); p += 1
    out = []
    for _ in range(t):
        n = int(data[p]); p += 1
        s = data[p]; p += 1              # bytes：元素就是 ASCII 码
        diff = [0] * 27
        for i in range(n // 2):
            c = s[i] - 97
            d = s[n - 1 - i] - 97
            if c == d:
                continue
            l, r = (c, d) if c < d else (d, c)
            diff[l] += 1                 # 边 l..r-1 必须全部执行
            diff[r] -= 1
        cur = 0
        ans = 0
        for i in range(25):
            cur += diff[i]
            if cur > 0:
                ans += 1
        out.append(str(ans))
    sys.stdout.write('\n'.join(out) + ('\n' if out else ''))


main()
```

## 8. 边界情况与易错点

1. **$n=1$ 或奇数长度的正中字符**：$i=n-1-i$ 时字符自己和自己配对，永远不产生约束，代码靠 `c == d` 自然跳过；$n=1$ 时循环 $0$ 次，输出 $0$。
2. **本身已是回文**（如 `racecar`）：所有对称对都相等，一条边都不标记，输出 $0$；注意不要因为「存在对称对」就贸然加边。
3. **重叠区间不能重复计数**：`dbec` 若写成 `ans += r - l` 会得到 $4$（正确是 $3$）。必须用差分/布尔标记，让每条边只计一次。
4. **`diff[r]--` 的下标**：$r$ 最大为 $25$（冲突对 $(\texttt{a},\texttt{z})$），数组开到 $26$ 就已在边界，开到 $27$ 更安全；前缀和循环只走到 $24$，不能走到 $25$。
5. **$\texttt{a}$ 不可操作**：所有边下端最小是 $0$，不会出现「把 $\texttt{a}$ 变成 $\texttt{-1}$」；若按字母编号误从 $1$ 开始会整体错一位。
6. **多测清空**：$t\le10^4$，`diff` 必须每组重建；跨组残留会让后面的小数据莫名输出大答案。
7. **答案范围**：最大 $25$、最小 $0$，用 `int` 足够；不要误以为答案与 $n$ 同阶而去开大数组。

**延伸思考**：

1. 若一次操作允许把 $x$ 直接替换成**任意更小的字母**（可跨多格），代价仍是 $1$：此时不需要中间字母，冲突图（顶点是字母、冲突对是边）的每个连通块只要打通成一棵树即可，答案变成 $V-C$（$V$ 为参与冲突的字母数，$C$ 为冲突图连通块数），与线性版本的 $|E^*|$ 完全不同。例如 `azbz` 的冲突图是 $\{\texttt{a},\texttt{b},\texttt{z}\}$ 一个块，$V-C=2$。
2. 若给每个字母 $x$ 的操作设代价 $w_x$，问题变成在字母链上选边集的**最小费用覆盖**，仍可用差分/前缀和结构，但需要按区间做 DP 或最短路。
3. 若把字母表首尾相接成环（$\texttt{z}$ 的前一个是 $\texttt{a}$），连通块不再是区间而是环上的圆弧，需要额外枚举「断开点」，答案可能小于线性版本。
4. 若字母表放大到 $k$ 个符号（如数字或自定义 charset），代码结构一字不改，只是 $O(n+k)$ 与答案上界 $k-1$；同时「输出方案」也顺手可得——把被标记的边按字母从大到小输出即可，那正是最优操作序列。
