# Codeforces SauSaGe 银行 题解

## 1. 题目概述

- **标题 / 题号**：SauSaGe 银行（Codeforces 2269A，英文名 SauSaGe Bank）
- **链接**：https://codeforces.com/problemset/problem/2269/A
- **来源**：Codeforces Round 1124 (Div. 2) · Problem A
- **难度**：800 分（Div. 2 签到题）
- **限制**：时间 1 s / 内存 256 MB
- **标签**：贪心，数学

**题意**：Hamed 在 SauSaGe 银行开户，账户初始余额为 1 美元。银行只在恰好 $n$ 天后永久关闭，而每天的事件顺序固定：

1. **早晨**：银行把账户余额翻倍，$x \to 2x$；
2. **晚上**：Hamed **可以**取出账户里的全部余额——这笔钱加到他的银行卡上，账户余额立刻重置为 1 美元，好让第二天的翻倍重新开始；他也可以选择不取，让钱继续留在账户里滚动。

他必须在**恰好 $k$ 个不同的日子**取款。银行关闭后账户里剩下的钱既取不出来、也不计入卡上金额。求第 $n$ 天结束后，卡上金额的最大值。**多测**：第一行 $t$，之后每组一行两个整数 $n,k$，逐组输出答案。

**约束**：

- $1 \le t \le 500$ 组测试数据；
- $1 \le k \le n \le 30$；
- 答案上界为 $2^{30} = 1073741824$（取 $k=1$），仍在 32 位有符号整数范围内，但实现时用 `long long` 更省心；
- $n$ 极小、答案却是指数级，这提示正解应是 $O(1)$ 的闭式公式，而不是枚举或模拟；
- 单组时间预算充裕，瓶颈完全在"想清楚结构"上。

第 5 组 $n=10,k=2$：前 9 天不动，第 9 天余额 $2^9 = 512$ 全部取走；第 10 天从 1 翻倍到 2 再取走，合计 $514$。

## 3. 解题思路

### 3.1 暴力思路

直接枚举"在哪 $k$ 天取款"：共 $\binom{n}{k}$ 种组合，$n=30,k=15$ 时约 $1.55\times10^8$ 种，每种还要 $O(k)$ 模拟算钱，单组就超时；$t=500$ 组更是灾难。

换成 DP 也不顺手：状态要记"第几天、已取几次、当前余额是多少"，而余额可达 $2^{30}$ 种取值，状态空间直接爆炸。真正可行的 DP 得先把"余额"这个量消掉——而一旦消掉，就会发现问题已经变成一道纯公式题。所以本题的关键是**建模**，不是优化枚举。

### 3.2 核心观察：段模型 + 集中原则

![段模型：n 天被 k 个取款日切成 k 段](images/cf2269_a_segment_model.svg)

设取款日为 $d_1 < d_2 < \dots < d_k$，并约定 $d_0 = 0$。第 $i$ 次取款到第 $i-1$ 次取款之间隔了

$$L_i = d_i - d_{i-1} \ \ge 1$$

天。这段区间里余额从 1 出发、每天早晨翻倍，共翻 $L_i$ 次，所以第 $i$ 次取到的钱恰好是 $2^{L_i}$ 美元。因此

$$\text{卡上总额} = \sum_{i=1}^{k} 2^{L_i}, \qquad L_i \ge 1,\quad \sum_{i=1}^{k} L_i \le n$$

**两个简化**：

1. **剩余天数一定并入最后一段**。若最后一次取款发生在编号 $d_k < n$ 的那一天，把这次取款挪到第 $n$ 天：前面各段金额不变，最后一段从 $2^{L_k}$ 涨到 $2^{L_k + (n - d_k)}$，取款天数仍是 $k$，只赚不亏。故可设 $\sum L_i = n$。
2. **收益只取决于各段长度**，与"哪天取"无关。于是问题化为：把 $n$ 拆成 $k$ 个正整数 $L_1,\dots,L_k$，最大化 $\sum 2^{L_i}$。

$2^{L}$ 是**凸**的（越往后涨得越猛），直觉上应该把天数尽量堆到一段里，而不是摊平。下一节把直觉变成严格论证。

### 3.3 算法流程：搬移论证与闭式答案

![集中原则：把一天从短段搬到长段](images/cf2269_a_concentrate.svg)

**搬移（exchange）论证**：设当前有两段长度 $a \ge b \ge 2$。从 $b$ 那段挪 1 天给 $a$ 那段，段数不变、总天数不变，总额变化为

$$\bigl(2^{a+1} + 2^{b-1}\bigr) - \bigl(2^{a} + 2^{b}\bigr) = 2^{a} - 2^{b-1} \ \ge\ 2^{b} - 2^{b-1} = 2^{b-1} > 0$$

所以只要存在"两段都 $\ge 2$"，就还能严格变大。于是最优方案中**至多一段长度 $\ge 2$**，其余 $k-1$ 段都只能是 1；再由 $\sum L_i = n$，那一大段只能是 $n - (k-1) = n-k+1$。方案（作为多重集）唯一。

**结论**

$$\boxed{\ \text{ans} = 2^{\,n-k+1} + 2(k-1)\ }$$

**算法流程**（每组测试数据）：

1. 读入 $n,k$；
2. 令 `shift = n - k + 1`（由 $1 \le k \le n$ 知 $1 \le \text{shift} \le 30$）；
3. 输出 `(1LL << shift) + 2LL * (k - 1)`。

![样例走查：公式一次算完](images/cf2269_a_walkthrough.svg)

|-----|-----|----------------|----------------------|------|------|
| 4 | 3 | 1, 2, 1 | $2+4+2$ | 8 | 官方 |
| 5 | 5 | 1, 1, 1, 1, 1 | $2\times 5$ | 10 | 官方 |

代入公式对照：$n=4,k=3$ 得 $2^{2} + 2\cdot 2 = 8$；$n=5,k=5$ 得 $2^{1} + 2\cdot 4 = 10$；$n=10,k=2$ 得 $2^{9} + 2 = 514$；$n=6,k=3$ 得 $2^{4} + 4 = 20$，与表格逐个吻合。

## 4. 算法细节

1. **复杂度目标**：化简成闭式后每组只需一次移位、一次乘法、一次加法，$O(1)$，不需要任何数组或容器，也无需按 $n$ 的大小循环。
2. **用位移而不是 `pow`**：`pow(2, shift)` 返回浮点数，虽有 $2^{30}$ 可精确表示，但类型转换与潜在精度问题都是隐患；`1LL << shift` 是整数运算，语义精确。
3. **$1$ 必须写成 `1LL`**：若写 `1 << shift`，`int` 左移在 `shift = 30` 时虽然仍是合法值，但 `1 << 31` 就已是未定义行为；统一 `1LL` 可以彻底避开这一类问题。
4. **移位量的取值范围**：$n - k + 1 \ge 1$ 且 $\le n \le 30$，永远不会出现负移位（负移位是 UB）。若把公式误写成 $2^{n-k}$，在 $k=n$ 时移位量为 0，答案会变成 $1 + 2(n-1)$ 而不是 $2n$。
5. **多测处理**：本题没有需要清空的全局结构，循环 $t$ 次、每次直接 `cin >> n >> k` 再打印即可；唯一要注意的是别把 $n,k$ 读反（题目顺序是先 $n$ 后 $k$）。
6. **I/O 细节**：关闭 `sync_with_stdio`，输出用 `'\n'` 而非 `endl`；$t \le 500$，这点开销可忽略，但保持良好习惯。
7. **可写的对照实现**：段划分 DP $f[s][j] = \max_{1 \le L \le s} \bigl(f[s-L][j-1] + 2^{L}\bigr)$，答案为 $\max_{s \le n} f[s][k]$，复杂度 $O(n^2k)$ 每组，$n \le 30$ 时轻松通过；本文的正确性验证就是拿它与闭式公式对拍。
8. **Python 无需担心溢出**：`1 << (n - k + 1)` 是任意精度整数；本题答案远小于 $2^{30}\cdot 2$，性能也完全不是问题。

## 5. 正确性证明

**引理 1（段模型）**：任一合法取款方案，其卡上金额等于 $\sum_{i=1}^{k} 2^{L_i}$，其中 $L_i = d_i - d_{i-1} \ge 1$、$d_0 = 0$，$d_1 < \dots < d_k \le n$ 为取款日。

**证明**：第 $i$ 段开始时（第 $d_{i-1}$ 天晚上取款后）余额被重置为 1。此后每天早晨翻倍，经过第 $d_{i-1}+1, \dots, d_i$ 天共 $L_i$ 个早晨，余额变为 $2^{L_i}$；第 $d_i$ 天晚上全额取出，故该次取款金额为 $2^{L_i}$。$k$ 次取款互不干扰，求和即得总额。∎

**引理 2（最后一段可以吃满剩余天数）**：存在最优方案使 $d_k = n$，从而 $\sum_{i=1}^{k} L_i = n$。

**证明**：取任一最优方案，若 $d_k < n$，把最后一次取款日改为 $n$：前 $k-1$ 段长度与金额都不变，最后一段由 $L_k$ 变为 $L_k + (n - d_k) > L_k$，金额由 $2^{L_k}$ 增至 $2^{L_k + n - d_k}$，严格变大，且取款天数仍为 $k$。这与"最优"矛盾，故 $d_k = n$。∎

**引理 3（搬移不等式）**：若整数 $a \ge b \ge 2$，则 $2^{a+1} + 2^{b-1} > 2^{a} + 2^{b}$。

**证明**：作差得 $2^{a+1} - 2^{a} + 2^{b-1} - 2^{b} = 2^{a} - 2^{b-1}$。由 $a \ge b$ 有 $2^{a} \ge 2^{b}$，故差值 $\ge 2^{b} - 2^{b-1} = 2^{b-1} \ge 2 > 0$。∎

**引理 4（最优形状）**：在 $L_i \ge 1$、段数恰为 $k$、$\sum L_i = n$ 的约束下，任一最优方案至多有一段长度 $\ge 2$；因此其多重集必为 $\{\,n-k+1,\ \underbrace{1,\dots,1}_{k-1}\,\}$（当 $n = k$ 时全部为 $1$，此时 $n-k+1 = 1$，结论同样成立）。

**证明**：反设最优方案中存在两段 $a \ge b \ge 2$。把 $b$ 的 1 天移给 $a$：段数仍为 $k$、总和仍为 $n$、每段仍 $\ge 1$（因 $b \ge 2$ 保证 $b-1 \ge 1$），但由引理 3 总额严格增大，与最优性矛盾。故不存在这样的两段，即至多一段 $\ge 2$，其余 $k-1$ 段全为 1。再由总和为 $n$ 解出唯一的大段长度 $n-(k-1) = n-k+1$。∎

**定理**：对任意 $1 \le k \le n \le 30$，答案恰为 $2^{n-k+1} + 2(k-1)$。

**证明**：由引理 1 把任意方案映射为满足 $L_i \ge 1$、段数 $k$、$\sum L_i \le n$ 的拆分并保持金额；由引理 2 可只在 $\sum L_i = n$ 的拆分中找最优；由引理 4，此类拆分中取到最大值的多重集必为 $k-1$ 个 $1$ 与一个 $n-k+1$。代入 $\sum 2^{L_i}$ 得 $2^{n-k+1} + (k-1)\cdot 2^{1} = 2^{n-k+1} + 2(k-1)$。该值由合法方案（前 $k-1$ 天每天取款、此后不再取，最后一次落在第 $n$ 天）取到，故它就是最大值。∎

## 6. 复杂度分析

- **时间**：每组 $O(1)$（两次读入、一次左移、一次乘法、一次加法），总计 $O(t)$；$t \le 500$ 时总运算量约 $10^3$ 次，相对 1 s 时限有 $10^6$ 倍以上余量。实测最大数据（$500$ 组 $n=30,k=1$）连进程启动一共约 $3$ ms，纯计算不足 $1$ ms。
- **空间**：$O(1)$。不使用数组、哈希表或递归栈，与 $n$、$t$ 都无关。
- **对照**：若采用 §4 的段划分 DP，则每组 $O(n^2k) = O(30^2\cdot 30) \approx 2.7\times10^4$ 次运算，同样能过，但比闭式公式多写二十行代码并多担一份出错风险。

## 7. 参考代码

### C++17

```cpp
#include <iostream>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;          // 稳健处理空输入
    while (t--) {
        int n, k;
        cin >> n >> k;
        // k-1 段取 1 天（各得 2 美元），剩下 1 段取 n-k+1 天（得 2^(n-k+1) 美元）
        long long ans = (1LL << (n - k + 1)) + 2LL * (k - 1);
        cout << ans << '\n';
    }
    return 0;
}
```

import sys

        n = int(data[pos])
        k = int(data[pos + 1])

main()

## 8. 边界情况与易错点

1. **$k = n$**：必须天天取款，答案是 $2^{1} + 2(n-1) = 2n$（如 $n=k=5$ 得 $10$）。此时移位量为 1，容易把公式写成 $2^{n-k}$ 而错算成 $1 + 2(n-1)$。
2. **$k = 1$**：只取一次，自然要等到第 $n$ 天才取，答案是 $2^{n}$（$n=30$ 时为 $1073741824$）。别漏掉"必须恰好取一次"这个约束就写成 $n$。
3. **$n = k = 1$**：最小规模，答案 $2$；此时段长只能是 1，公式给出 $2^{1} + 0 = 2$，正常。
4. **"没取的钱不算"**：账户关闭时剩下的余额不进卡。因此若最后一次取款早于第 $n$ 天，后面滚动出来的钱全部作废——这正是"最后一段必须拖到第 $n$ 天"的理由，也是 $k=1$ 时答案不是 $2^{d_1}$ 而是 $2^n$ 的原因。
5. **溢出与移位**：用 `1LL << shift`，不要用 `1 << shift` 或 `pow(2, shift)`；移位量恒在 $[1,30]$，不会出现负数移位。
6. **多测格式**：第一行是 $t$，之后每组一行 $n\ k$。用 `while (t--)` 逐组处理，输出每行一个整数；Python 用 `read().split()` 一次读入更稳，避免行尾空格导致的问题。
7. **读入顺序**：题目先给 $n$ 后给 $k$。一旦读反，移位量就变成 $k - n + 1 \le 0$（$k < n$ 时为负），而对负数做左移是未定义行为——本地也许"碰巧"输出个数，换台机器/换编译器就可能崩或错，务必按 $n,k$ 的顺序读入。

**延伸思考**：

1. 把"每天翻倍"换成"每天乘以 $r$"（$r > 1$），同样的搬移论证给出 $\text{ans} = r^{n-k+1} + (k-1)r$：因为 $r^{a+1} + r^{b-1} - r^{a} - r^{b} = (r-1)\bigl(r^{a} - r^{b-1}\bigr) > 0$，$r=2$ 只是特例。
2. 若把"恰好 $k$ 次"改成"至多 $k$ 次"，合并永不亏（$2^{a+b} \ge 2^a + 2^b$，等号仅在 $a=b=1$），最优就退化为 $k=1$ 的 $2^n$，题目瞬间变平凡——这说明"恰好"这个词才是本题的骨架。
3. 若允许在第 $n$ 天之后继续持有，或取款要交固定手续费 $c$，则每段净收益变为 $2^{L} - c$，最优段数需要重新权衡（段数不再固定为 $k$，而要在"多切一段多交一次费"与"集中带来指数收益"之间取平衡），此时贪心形状可能被打破，值得一试。
4. 若把 $n$ 放大到 $10^{18}$ 且不取模，$2^{n}$ 的十进制位数约 $3\times10^{17}$，输出本身就不可能；此时合理的问法是"答案对 $10^9+7$ 取模"，用快速幂 $O(\log n)$ 即可，公式结构完全不变。
