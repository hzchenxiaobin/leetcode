# Codeforces 最佳卡牌 题解

## 1. 题目概述

- **标题 / 题号**：最佳卡牌（Codeforces 2253A，英文名 The Best Card）
- **链接**：https://codeforces.com/problemset/problem/2253/A
- **来源**：Educational Codeforces Round 193 (Rated for Div. 2) · Problem A
- **难度**：800
- **限制**：时间 2 s / 内存 512 MB
- **标签**：贪心，数学，数论

**题意**：牌堆里有 $n$ 张牌，牌面分别是 $2, 3, 4, \ldots, n+1$。任取两张牌 $x$ 与 $y$ 比大小，胜负规则是：

1. 若其中一个数能被另一个整除，则**牌面较小**的那张赢（如 $2$ 与 $6$ 比，$2$ 赢）；
2. 若两者互不整除，则**牌面较大**的那张赢（如 $4$ 与 $6$ 比，$6$ 赢）。

注意规则 1 与「大小」是**反直觉**的：一旦出现整除关系，大牌反而输给小牌。问：是否存在一张牌，它能战胜其余所有牌？存在输出 `YES`，否则输出 `NO`。

多组数据：第一行一个整数 $t$，接下来 $t$ 行每行一个整数 $n$，逐组输出一行 `YES` / `NO`（大小写不敏感）。

**约束**：

- $1 \le t \le 10^4$
- $2 \le n \le 2 \times 10^5$，牌面取值范围 $3 \le n+1 \le 200001$
- 所有测试用例的 $\sum n \le 3 \times 10^6$
- 只输出 `YES` / `NO`，无需构造赢家

## 2. 示例

官方样例（输入 / 输出原样）：

```text
输入：
5
2
3
4
5
8

输出：
YES
NO
YES
NO
NO
```

逐组说明（官方 note 给了前两组的细节）：

- $n=2$：牌堆 $\{2,3\}$，$3$ 与 $2$ 互不整除，大牌 $3$ 赢 —— `YES`。
- $n=3$：牌堆 $\{2,3,4\}$，$2$ 赢 $4$、$3$ 赢 $2$、$4$ 赢 $3$，形成循环，无人全胜 —— `NO`。
- $n=4$：牌堆 $\{2,3,4,5\}$，$5$ 与 $2,3,4$ 都互不整除，靠「更大者赢」通吃 —— `YES`。
- $n=5$：$6$ 是合数，被 $2$ 整除，$2$ 赢 —— `NO`。
- $n=8$：$9=3\times 3$，被 $3$ 整除，$3$ 赢 —— `NO`。

补一组自造样例（压边界，用 ★ 标注）：

```text
输入（自造）：
3
6
10
200000

输出（自造）：
YES
YES
NO
```

$n=6$ 时 $7$ 是质数，故 `YES`；$n=10$ 时 $11$ 是质数，故 `YES`；$n=200000$ 时 $n+1=200001=3\times163\times409$ 是合数，故 `NO`。这三组正好覆盖「小质数」「中质数」「上界合数」三种边界。

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：枚举每张牌 $x$，再枚举每张 $y \ne x$ 验证 $x$ 是否获胜，复杂度 $O(n^2)$。单组 $n = 2\times10^5$ 就是 $4\times10^{10}$ 次比较，远超 2 s；而且 $\sum n$ 可达 $3\times10^6$，即便每组只花 $O(n)$ 也已经逼近极限，$O(n^2)$ 根本不用考虑。

更糟的是，暴力对「为什么某张牌会输」没有任何解释力 —— 我们无法从 $O(n^2)$ 的比较结果里读出规律。正确做法是**先分析结构**：到底哪些牌有资格争夺「全胜」？

### 3.2 核心观察：赢家只能是最大的 $n+1$，且它必须是质数

![卡牌对局规则与唯一候选王](images/cf2253_a_duel_rule.svg)

**第一步：排除所有 $x \le n$ 的牌。** 若 $x \le n$，则牌 $x+1$ 一定也在牌堆里。$x$ 与 $x+1$ 相邻，有

$$x \nmid (x+1)\quad(\text{余 }1), \qquad (x+1) \nmid x\quad(x+1 > x).$$

所以二者互不整除，按规则 2「更大者赢」，$x$ **输给** $x+1$。于是任何非最大的牌都至少有一个克星，全胜者只能是 $x = n+1$。

**第二步：$n+1$ 什么时候会输？** 只会输给它的某个**真因子**：若存在 $a$ 满足 $2 \le a < n+1$ 且 $a \mid n+1$，那么牌 $a$ 在牌堆中，且按规则 1「整除时小者赢」，$a$ 战胜 $n+1$。而「存在这样的 $a$」正是**合数**的定义。所以

$$n+1 \text{ 是合数} \implies n+1 \text{ 必输给某张更小的牌}.$$

**第三步：$n+1$ 什么时候全胜？** 若 $n+1$ 是质数，则任取牌堆里更小的 $y \in [2, n]$，都有 $y \nmid (n+1)$（否则 $y$ 是真因子，与质数矛盾），同时 $(n+1) \nmid y$（因 $y < n+1$）。两者互不整除，按规则 2 大牌赢，故 $n+1$ 战胜所有对手。

合并三步，得到本题的全部答案：

$$\boxed{\text{存在全胜牌} \iff n+1 \text{ 是质数}}$$

一个 800 分的签到题，就这样被压缩成了一次**质数判定**。

### 3.3 算法流程：一次筛法 + 每组 $O(1)$ 查询

![算法流程与复杂度](images/cf2253_a_prime_flow.svg)

1. 读入 $t$ 以及全部 $n_i$（**必须先读完**，因为筛表长度取决于最大值）。
2. 令 $M = \max_i (n_i) + 1 \le 200001$，用埃氏筛标记 $[0, M]$ 内每个数是否为质数。
3. 对每组输出：`isPrime[n+1] ? "YES" : "NO"`。

因为 $t \le 10^4$ 而 $\max(n+1) \le 200001$，筛表只建**一次**，所有测试用例共用；单组查询是数组下标访问，$O(1)$。如果不建表、改为每组对 $n+1$ 试除到 $\sqrt{n+1}$，单组最多约 $447$ 次除法，$t$ 组合计约 $4.5\times10^6$ 次，同样安全 —— 两种写法都可以，本文给筛法版本。

### 3.4 示例演算

![示例演算表](images/cf2253_a_walkthrough.svg)

以官方第 5 组 $n = 8$ 为例：牌堆是 $\{2,\ldots,9\}$。最大牌 $9 = 3 \times 3$ 是合数，真因子 $3$ 在牌堆里，$3 \mid 9$，按规则 1 小牌 $3$ 获胜，所以 $9$ 不是全胜者 —— 输出 `NO`。再看 $n=6$（自造）：牌堆 $\{2,\ldots,7\}$，$7$ 是质数，$2,3,4,5,6$ 中没有一个整除 $7$，也没有一个被 $7$ 整除，全部走「更大者赢」，$7$ 通吃 —— 输出 `YES`。

把 $n+1$ 是否质数与答案对齐，就得到一张「查表即出答案」的对照：$n = 2,4,6,10$ 时 $n+1 = 3,5,7,11$ 均为质数，答案 `YES`；$n = 3,5,8$ 时 $n+1 = 4,6,9$ 都是合数，答案 `NO`；$n = 200000$ 时 $n+1 = 200001 = 3\times163\times409$，答案 `NO`。

## 4. 算法细节

1. **必须读完全部输入再建表**：筛表长度是 $M = \max(n_i)+1$，边读边筛无法确定上界。所以先把 $t$ 个 $n_i$ 存进数组，拿到最大值后再筛；查询时再扫一遍数组输出。
2. **$0$ 和 $1$ 必须显式置为非质数**：`vector<char> isPrime(M+1, 1)` 会把下标 $0,1$ 也标成 $1$。虽然本题 $n \ge 2$ 保证查询下标 $n+1 \ge 3$，但只要有人把边界推广到 $n \ge 1$（查询下标 $2$）或误用下标，就会直接错。务必写 `isPrime[0] = isPrime[1] = 0`。
3. **筛法内层用 `long long`**：`for (long long i = 2; i * i <= M; i++)`，避免 $i \times i$ 以 `int` 溢出成负数（本题 $M \le 200001$ 时不会溢出，但这是筛法模板里最容易埋的雷）。
4. **表长要覆盖下标 $M$**：`vector<char> isPrime(M + 1)`，索引 $0 \ldots M$ 合法；写成 `M` 会让最后一组 $n = \max$ 的查询越界，读到随机值。
5. **多测共用一张表**：千万别在每组内重新筛（那会退化成 $O(t \cdot M)$ 甚至更糟），也别忘了筛本身与 $\sum n$ 无关 —— $\sum n \le 3\times10^6$ 只说明输入量大，不要求逐牌比较。
6. **输出要缓冲**：$t \le 10^4$ 行，用 `string` 拼接后一次 `cout`（或 `'\n'` 而非 `endl`），避免 $10^4$ 次刷新。
7. **Python 的切片筛要算准长度**：`is_prime[i*i::i] = b"\x00" * len(range(i*i, mx+1, i))`，右侧长度必须与切片**完全相等**，否则抛 `ValueError: attempt to assign bytes of size ... to extended slice`。用 `bytearray` 而不是 `list` 既省内存又快得多。
8. **不必特判 $n$ 的奇偶**：偶数 $n+1$ 一定是合数（$n \ge 3$），但奇数的 $n+1$ 也可能是合数（$9, 15, 21$），所以只能真正做质数判定，不能用奇偶走捷径。

## 5. 正确性证明

**引理 1（非最大牌必有克星）**：若 $2 \le x \le n$，则牌 $x+1$ 在牌堆中，且 $x+1$ 战胜 $x$。

**证明**：牌面范围是 $[2, n+1]$，故 $x+1 \le n+1$ 在牌堆中且 $x+1 > x$。相邻整数满足 $x \nmid (x+1)$（余数为 $1$），又 $x+1 > x$ 故 $(x+1) \nmid x$。两者互不整除，按规则 2「更大者赢」，$x+1$ 获胜。∎

**引理 2（合数最大牌必败）**：若 $n+1$ 是合数，则牌 $n+1$ 不战胜所有牌。

**证明**：$n+1$ 为合数，故存在分解 $n+1 = a \cdot b$ 且 $2 \le a \le b \le (n+1)/2 < n+1$。于是牌 $a$ 在牌堆中（$2 \le a \le n$），且 $a \mid n+1$、$a < n+1$。按规则 1「整除时小者赢」，$a$ 战胜 $n+1$，故 $n+1$ 至少有一个对手没赢。∎

**引理 3（质数最大牌全胜）**：若 $n+1$ 是质数，则牌 $n+1$ 战胜其余所有牌。

**证明**：任取对手 $y \in [2, n]$，即 $2 \le y < n+1$。若 $y \mid (n+1)$，则 $y$ 是质数 $n+1$ 的一个不小于 $2$、小于自身的因子，与质数定义矛盾，故 $y \nmid (n+1)$；又 $y < n+1$ 故 $(n+1) \nmid y$。两者互不整除，按规则 2 大牌 $n+1$ 获胜。对每个 $y$ 都成立，故 $n+1$ 全胜。∎

**定理**：存在战胜其余所有牌的牌 $\iff n+1$ 是质数。

**证明**：

- ($\Leftarrow$) 取 $x = n+1$，由引理 3 它全胜，故存在。
- ($\Rightarrow$) 设 $x$ 全胜。若 $x \le n$，由引理 1 它输给 $x+1$，矛盾，故必有 $x = n+1$。又 $n+1 \ge 3 > 1$：若 $n+1$ 是合数，由引理 2 它不全胜，矛盾；故 $n+1$ 既不是 $1$ 也不是合数，只能是质数。∎

因此算法输出 `YES` 当且仅当 $n+1$ 为质数，与定理完全一致。

## 6. 复杂度分析

- **时间**：预处理埃氏筛 $O(M \log\log M)$，其中 $M = \max_i(n_i) + 1 \le 200001$；读入 $O(t)$，查询 $O(1)$ 每组、合计 $O(t)$。总时间 $O(M \log\log M + t)$，与 $\sum n$ 无关。实测 C++17（`-O2`）在 $t = 10^4$、$\sum n = 3\times10^6$ 的数据上约 $13$ ms，Python3 约 $26$ ms，相对 2 s 时限有百倍以上余量。
- **空间**：素数表 $M+1$ 字节（`char` / `bytearray`），约 $200$ KB；$n$ 数组 $O(t)$ 个 `int`。总计 $O(M + t)$，远低于 512 MB。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;               // 空输入防护

    vector<int> n(t);
    int mx = 3;                              // n+1 的最大值，至少为 3
    for (int i = 0; i < t; i++) {
        cin >> n[i];
        mx = max(mx, n[i] + 1);
    }

    // 埃氏筛：isPrime[v] 表示 v 是否为质数，表长覆盖到下标 mx
    vector<char> isPrime(mx + 1, 1);
    isPrime[0] = isPrime[1] = 0;
    for (long long i = 2; i * i <= mx; i++)
        if (isPrime[i])
            for (long long j = i * i; j <= mx; j += i)
                isPrime[j] = 0;

    string out;
    out.reserve((size_t)t * 4);
    for (int i = 0; i < t; i++)
        out += isPrime[n[i] + 1] ? "YES\n" : "NO\n";
    cout << out;
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:                              # 空输入防护
        return
    t = int(data[0])
    ns = [int(x) for x in data[1:1 + t]]

    mx = max(ns) + 1
    is_prime = bytearray([1]) * (mx + 1)      # 1 表示质数，逐项筛掉
    is_prime[0:2] = b"\x00\x00"               # 0 和 1 不是质数
    i = 2
    while i * i <= mx:
        if is_prime[i]:
            # 切片长度必须与右侧 bytes 长度完全一致
            is_prime[i * i::i] = b"\x00" * len(range(i * i, mx + 1, i))
        i += 1

    sys.stdout.write("".join("YES\n" if is_prime[v + 1] else "NO\n" for v in ns))


main()
```

## 8. 边界情况与易错点

1. **$n=2$ 是下界**：牌堆只有 $\{2,3\}$，$n+1 = 3$ 是质数，答案 `YES`。不要因为「$n+1$ 太小可能不是质数」而写特判，$3$ 确实是质数（$1$ 才不是）。
2. **$n+1 = 200001$ 是合数**：$200001 = 3 \times 163 \times 409$，$n = 200000$ 时输出 `NO`。上界数据能顺带验证筛表是否真的覆盖了下标 $200001$。
3. **$0,1$ 的初始化**：`is_prime[0] = is_prime[1] = 0` 不能省。若表长恰好为 $4$（$n=2$），下标 $0,1$ 都在表内，漏初始化虽然不影响本题查询，却会让「把判据推广到 $n+1=1,2$」的改写悄悄出错。
4. **试除法的等号**：如果改用 $O(\sqrt{n+1})$ 试除，循环条件必须是 $i \cdot i \le n+1$（带等号）。写成 $i \cdot i < n+1$ 会把完全平方数（$9, 25, 49$）误判为质数，直接在 $n = 8, 24, 48$ 上 WA。
5. **不能只判奇偶**：偶数 $n+1$ 必为合数，但奇数 $n+1$ 也可能是合数（$9, 15, 21, 27$），必须真正判质数。
6. **多测不要重建筛表**：$t = 10^4$ 时每组重建一次表就是 $10^4 \times 2\times10^5$ 量级，白白超时；正确做法是建一次表、查 $t$ 次。
7. **必须先读完全部 $n$**：筛表长度依赖 $\max(n_i)+1$，边读边筛只能靠猜上界（比如固定开 $200005$），虽然本题可行但属于脆弱写法。
8. **输出格式**：每组一行、只输出 `YES` / `NO`（题目大小写不敏感，但别输出 `Yes!` 之类的多余字符）；C++ 用 `'\n'` 而非 `endl`，Python 一次性 `write`。

**延伸思考**：

1. **牌面换成任意集合 $S$**：全胜者 $x$ 必须满足「对所有 $y > x$ 有 $x \mid y$，对所有 $y < x$ 有 $y \nmid x$」。后一条说明 $x$ 在 $S$ 中不能有任何真因子，前一条极强 —— 只要 $S$ 中有一个比 $x$ 大的元素不被 $x$ 整除，$x$ 就出局。于是候选只剩「$S$ 中无真因子的元素」（通常只有最大元），再对每个候选花 $O(\lvert S\rvert)$ 逐张校验，整体仍是 $O(\lvert S\rvert^2)$ 的朴素实现，但候选集已被压缩到常数级。
2. **不要求全胜，只要求胜场最多**：统计每张牌 $x$ 的胜场数 $\text{wins}(x) = (x - \tau(x)) + \lfloor (n+1)/x \rfloor - 1$，其中 $\tau(x)$ 为 $x$ 的因子个数：比 $x$ 小的 $x-2$ 张牌里，$\tau(x)-2$ 张是它的真因子并赢它，其余全输给它；比它大的牌只有 $x$ 的倍数会被它「以小胜大」。用调和级数筛出所有 $\tau(x)$（$O(M \log M)$）后逐张统计，就能处理 $\sum n \le 3\times10^6$ 的全量数据。有趣的是此时 $n+1$ **不一定**是胜场最多的牌：$n=5$ 时无人全胜，但牌 $5$ 赢了 $3$ 场（胜过 $2,3,4$），比 $6$ 的两场还多 ——「最强」和「全胜」是两件事。
3. **把规则 1 改成「整除时大者赢」**：此时整除关系不再惩罚大牌，最大牌 $n+1$ 对所有更小的牌都满足「要么整除（大者赢）、要么互不整除（大者赢）」，于是答案恒为 `YES` —— 整个问题退化成读入输出。这说明本题的全部难度都来自那条「小者赢」的反直觉规则。
