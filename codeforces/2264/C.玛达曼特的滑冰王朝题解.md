# Codeforces 玛达曼特的滑冰王朝 题解

## 1. 题目概述

- **标题 / 题号**：玛达曼特的滑冰王朝（Codeforces 2264C，英文名 Madamant's Skating Dynasty）
- **链接**：https://codeforces.com/problemset/problem/2264/C
- **来源**：Codeforces Round 1121 (Div. 2) · Problem C
- **难度**：1400（1500 分）
- **限制**：时间 2 s / 内存 256 MB
- **标签**：组合计数、数学、排序

**题意**：有 $n$ 个带编号的滑冰选手，第 $v$ 个的评分是 $a_v$，所有 $a_v$ **互不相同**。一个「王朝」是这 $n$ 个点上的**有根树**，根记作 $r$，$p_v$ 表示 $v$ 的父亲。若对每个 $v \ne r$ 都有 $a_v < a_{p_v}$（父强于子），则称该王朝**合法**。合法王朝的代价为

$$\text{cost} = \sum_{v \ne r} \left(a_{p_v} - a_v\right).$$

两棵王朝不同 $\iff$ 根不同，或至少有一个点的父亲不同。求**所有合法王朝的代价之和**，对 $998244353$ 取模。

多测：第一行 $t$，每组先给 $n$，再给 $n$ 个整数 $a_i$，对每组输出一行答案。

**约束**：

- $1 \le t \le 10^4$，$\sum n \le 2 \cdot 10^5$
- $1 \le n \le 2 \cdot 10^5$，$1 \le a_i \le 10^9$，且 $a_i$ 两两不同
- 答案要取模；注意 $10^9 > 998244353$，$a_i$ 本身就可能超过模数

## 2. 示例

```text
输入

1
10

4

1 1000000000

输出

```

**官方说明摘录**：第 2 组里评分为 $3$ 的人必须是根，评分为 $2$ 的人父亲只能是 $3$，评分为 $1$ 的人可以选另外两人之一当父亲；两棵王朝的代价分别是 $2$ 与 $3$，和为 $5$。第 4 组只有唯一一棵王朝，代价 $10^9 - 1 = 999\,999\,999$，模 $998\,244\,353$ 得 $1\,755\,646$。

**自造补充**（非官方，覆盖「评分大于模数」）：$n=3$、$a=[998244353, 998244354, 1]$，降序为 $998244354, 998244353, 1$，$fact = 2$。第一轮 `pref` $= 998244354 \equiv 1$，贡献 $2 \cdot 1 = 2$；第二轮 `pref` $= 1996488707 \equiv 1$，贡献 $1 \cdot 2/2 = 1$，合计 $3$。再扣 $(S - a_{\max})\cdot 2 = ((0+1+1)-1)\cdot 2 = 2$，答案 `1`。若忘记对 $a_i$ 取模，第二、三轮的乘积会直接溢出。

## 3. 解题思路

### 3.1 暴力思路

按定义枚举：先枚举根 $r$（$n$ 种），再枚举每个非根点的父亲（朴素 $n^{n-1}$ 种），校验 $a_v < a_{p_v}$ 后累加代价。复杂度 $O(n^n)$，$n = 8$ 就已经有 $1.7\times10^{7}$，$n = 2\cdot10^5$ 完全不可行。

退一步，就算只枚举合法王朝也做不到：马上会算出合法王朝数是 $(n-1)!$（见 §3.2），$n = 13$ 就超过 $10^{9}$。所以必须走「**统计每个点在所有王朝中被算了多少次**」这条路，把 $\sum_{\text{王朝}} \text{cost}$ 拆成若干可独立计算的计数问题。

### 3.2 核心观察：根被钉死，代价对「计数」是线性的

![根固定 + 代价线性化 + 逐对统计](images/cf2264_c_pair_contribution.svg)

**第一层：树的结构约束整体塌缩。** 评分最大的点没有更大的点可选作父亲，它**只能是根**；反过来，其他每个点都至少有「最大点」这一个合法候选，所以一定能找到父亲。于是根根本不用枚举——根唯一确定，就是最大值。再注意：只要每个非根点都选了一个评分**严格更大**的点作父亲，得到的一定是**树**，而不是任意森林——沿父亲链评分严格递增，永远不可能成环，链必然终止于某个没有父亲的点，而唯一的无父亲点就是根，故所有点都连通到根。所以**约束完全退化**为：每个非根点独立地在其「更大的点」集合里任选一个父亲。

**第二层：代价可以写成顶点权重的线性组合。** 把代价按「谁被当成父亲」重排：

$$\sum_{v \ne r} a_{p_v} = \sum_{u} c_u\, a_u, \qquad \sum_{v \ne r} a_v = S - a_r,$$

其中 $c_u$ 是 $u$ 的儿子个数，$S = \sum_v a_v$。于是

$$\text{cost} = \sum_{u} c_u\, a_u - \left(S - a_r\right).$$

后一项对固定输入是常数，前一项对每个顶点是线性的。**线性意味着可以交换求和**：不必知道王朝长什么样，只要知道「$u$ 在多少棵王朝里当了 $v$ 的父亲」即可。

**第三层：逐对计数。** 把 $a$ 降序排列为 $v_0, v_1, \ldots, v_{n-1}$，则恰好有 $k_j = j$ 个点的评分比 $a_{v_j}$ 大，故合法王朝总数为

$$\prod_{j=1}^{n-1} j = (n-1)!.$$

固定「$u$ 是 $v$ 的父亲」这一条边后，其余 $n-2$ 个非根点仍各自独立地在自己的 $k$ 个候选里选，方案数是 $\prod_{w \ne r, w \ne v} k_w = \dfrac{(n-1)!}{k_v}$。因此

$$\sum_{\text{王朝}} c_u = \sum_{v:\, a_v < a_u} \frac{(n-1)!}{k_v}.$$

代回代价公式，并**按较低的那个端点 $v_j$ 分组**（这样前缀和可以边扫边累加）：

$$\boxed{\ \text{ans} = \sum_{j=1}^{n-1} \frac{(n-1)!}{j} \cdot \Bigl(\sum_{i<j} a_{v_i}\Bigr) \;-\; (S - a_{v_0})\cdot (n-1)!\ }$$

括号里「比 $a_{v_j}$ 大的所有评分之和」是降序前缀和，扫一遍就有；$\frac{(n-1)!}{j}$ 在模意义下用逆元算。整道题只剩排序 + 一趟扫描。

### 3.3 算法流程

![排序 + 前缀和 + 逆元的一趟扫描](images/cf2264_c_sweep_flow.svg)

```text
读入 n 和 a[]
把 a 降序排序                       # a[0] 即根；位置 j 的点有 j 个更大的点
fact = (n-1)! mod p                 # 王朝总数
预处理 inv[1..n-1]                  # 线性递推，O(n)
pref = 0; sum = 0; ans = 0
for j = 0 .. n-1:
    if j > 0:
        ans += pref * fact % p * inv[j] % p      # pref 是 a[0..j-1] 之和
    pref += a[j];  sum += a[j]                   # 都按模累加
ans -= (sum - a[0]) * fact                       # 扣掉每个王朝都要付的 Σ a_v
输出 ans mod p
```

**顺序是本算法的命门**：第 $j$ 轮必须**先**用旧 `pref`（只含 $a_0..a_{j-1}$）算贡献，**再**把 $a_j$ 并进去。否则 $a_j$ 会把自己算成「比自己大的点」，多出一批非法贡献。**为什么可以全程模运算**：$j \le n-1 < p$，故 $\text{inv}(j)$ 一定存在；且 $\frac{(n-1)!}{j}$ 本身是整数，模意义下 $\text{fact}\cdot\text{inv}(j)$ 与它同余，除法合法。

### 3.4 示例演算

![第 5 组样例的逐轮走查](images/cf2264_c_walkthrough.svg)

以第 5 组 $a = [2, 7, 1, 10, 4]$ 为例，降序后 $[10, 7, 4, 2, 1]$，$n = 5$，$fact = 4! = 24$：

| $j$ | $a_{v_j}$ | 已扫入的 `pref`（$j$ 个更大评分之和） | $(n-1)!/j$ | 本轮贡献 |
|-----|-----------|----------------------------------------|------------|----------|
| 1 | 7 | $10$ | $24/1 = 24$ | $240$ |
| 2 | 4 | $10+7 = 17$ | $24/2 = 12$ | $204$ |
| 3 | 2 | $10+7+4 = 21$ | $24/3 = 8$ | $168$ |
| 4 | 1 | $10+7+4+2 = 23$ | $24/4 = 6$ | $138$ |

四项相加得 $750$；再减去 $(S - a_{\max})\cdot fact = (24 - 10)\cdot 24 = 336$，答案 $750 - 336 = 414$，与官方输出一致。

**每项到底在数什么**（按「较低端点分组」的口径）：

- $240 = 24 \times 10$：评分为 $7$ 的点只有 $10$ 一个候选父亲，故边 $7 \to 10$ 出现在**全部** $24$ 棵王朝里，每棵贡献 $a_{10} = 10$。
- $138 = 6 \times 23$：最低分 $1$ 有 $4$ 个候选父亲，即 $\{10,7,4,2\}$ 中每个都在恰好 $24/4 = 6$ 棵王朝里当它的父亲，于是「$a_{p_1}$ 在 $24$ 棵王朝上的总和」为 $6 \times (10+7+4+2) = 138$。四项相加正是 $\sum_{\text{王朝}}\sum_u c_u a_u$ 的完全展开，不重不漏。

## 4. 算法细节

1. **逆元表一次预处理**：$\sum n \le 2\cdot10^5$，直接在程序开头用线性递推 `inv[i] = -(p/i) * inv[p%i] % p` 打出 $1..2\cdot10^5$ 的表（`inv[1] = 1` 起推），总代价 $O(\max n)$；比每组对每个 $j$ 做快速幂（$O(n\log p)$）快一个量级。分母只用到 $j \ge 1$，`inv[0]` 不会被访问。
2. **先取模再乘**：$a_i \le 10^9$ 可能大于 $p = 998244353$，累加 `pref`、`sum` 时必须用 $a_i \bmod p$，否则 $(S - a_{\max})\cdot fact$ 会到 $2\cdot10^{14}\times 10^9$ 量级，`long long` 也未必安全；取模后每步乘积 $< p^2 \approx 10^{18}$，`long long` 刚好装得下。
3. **减法取模**：C++ 的 `%` 对负数返回负值，`ans -= x` 之后必须 `((ans % p) + p) % p`；Python 的 `%` 天然非负，直接写即可。
4. **排序方向决定下标含义**：必须**降序**，这样 0-indexed 位置 $j$ 恰好等于「比它大的点数」，逆元下标就是 $j$；若升序排，分母要写成 $n-j$，容易和 $j$ 混。题目保证 $a_i$ 互异，降序后严格递减，$k_j = j$ 精确成立，无需去重。
5. **多测清空**：`pref`、`sum`、`ans`、`fact` 全部在每组内部重新声明；逆元表是全局常量，只建一次，别每组重建（$10^4$ 组会白跑 $2\cdot10^9$ 次）。
6. **I/O**：$t$ 可达 $10^4$，C++ 关同步 + `cin.tie(nullptr)`；Python 用 `sys.stdin.buffer.read().split()` 一次读完、`"\n".join` 一次写出，避免 $10^4$ 次 `print`。

## 5. 正确性证明

**引理 1（根唯一）**：合法王朝的根必为评分最大的点，且最大值作根时其余点都至少有一个合法候选。

**证明**：设 $m$ 为评分最大的点。若 $m \ne r$，则需 $a_m < a_{p_m}$，与最大性矛盾，故 $m = r$。反之，对任意 $v \ne m$ 有 $a_v < a_m$，故 $m$ 可作 $v$ 的父亲，候选集非空。∎

**引理 2（独立选父即得树）**：设根为最大值 $v_0$，每个 $v_j$（$j \ge 1$）在 $\{v_0, \ldots, v_{j-1}\}$ 中任选一个父亲，则所得无向图是以 $v_0$ 为根的合法树；且每个合法王朝都可由这种方式唯一生成。

**证明**：边数为 $n-1$。沿父亲链走，评分严格递增且下标严格递减，故链长 $\le n$ 且无环，必然终止于某个无父亲的点；由引理 1 只有 $v_0$ 无父亲，所以每个点沿父亲链都到达 $v_0$，图连通且 $n-1$ 条边，是树。合法性由「父亲取自更大的点」直接得到。反向：任一合法王朝的根是 $v_0$，每条父亲边都指向更大的点，即落在该点的候选集内。∎

**推论 1（王朝总数）**：合法王朝数为 $\prod_{j=1}^{n-1} j = (n-1)!$。

**证明**：由引理 2，各点独立选择，$v_j$ 有 $j$ 个候选，相乘即得。∎

**引理 3（代价恒等式）**：对任一合法王朝，$\text{cost} = \sum_u c_u a_u - (S - a_r)$。

**证明**：$\sum_{v \ne r}(a_{p_v} - a_v) = \sum_{v \ne r} a_{p_v} - \sum_{v \ne r} a_v$。前者按父亲 $u$ 归并，$u$ 被计入 $c_u$ 次，即 $\sum_u c_u a_u$；后者为 $S - a_r$。∎

**引理 4（单条边出现的王朝数）**：设 $a_v < a_u$，则「$p_v = u$」的合法王朝恰有 $\dfrac{(n-1)!}{k_v}$ 棵，其中 $k_v$ 为评分严格大于 $a_v$ 的点数。

**证明**：固定 $p_v = u$ 后（该选择合法），其余 $n-2$ 个非根点各自独立选父，$w$ 有 $k_w$ 个候选；由引理 2 的方案数与推论 1，总数为 $\prod_{w \ne r,\, w \ne v} k_w = \dfrac{(n-1)!}{k_v}$。∎

**定理（答案公式）**：$\text{ans} = \sum_{j=1}^{n-1} \dfrac{(n-1)!}{j}\Bigl(\sum_{i<j} a_{v_i}\Bigr) - (S - a_{v_0})(n-1)!$，其中 $v_0, \ldots, v_{n-1}$ 为降序排列。

**证明**：对全部王朝求和，由引理 3

$$\sum_{\text{王朝}} \text{cost} = \sum_{u} a_u \sum_{\text{王朝}} c_u - (S - a_{v_0})\cdot (n-1)!.$$

交换求和次序：$\sum_{\text{王朝}} c_u = \sum_{v:\, a_v < a_u} \#\{p_v = u\}$，由引理 4 等于 $\sum_{v: a_v < a_u} \frac{(n-1)!}{k_v}$。再按较低端点分组：$v = v_j$ 被比它大的 $v_i$（$i<j$）当作「儿子」，每对贡献 $a_{v_i}\cdot\frac{(n-1)!}{j}$，于是

$$\sum_u a_u \sum_{v: a_v<a_u}\frac{(n-1)!}{k_v} = \sum_{j=1}^{n-1}\frac{(n-1)!}{j}\sum_{i<j} a_{v_i}.$$

合并即得结论。至于代码与公式一致：第 $j$ 轮循环时 `pref` $= \sum_{i<j} a_{v_i} \bmod p$，累加值恰为上式；$j \le n-1 < p$ 保证 $\text{inv}(j)$ 存在，模除法与整数除法 $\frac{(n-1)!}{j}$ 同余。∎

## 6. 复杂度分析

- **时间**：每组 $O(n \log n)$，全部开销在排序；扫描 $O(n)$。逆元表一次性 $O(\max n)$。总计 $O(\max n + \sum n \log n)$，最坏约 $2\cdot10^5 \times 18$ 次比较。
- **空间**：$O(n)$ 存数组，$O(\max n)$ 存逆元表；无二维表。
- **实测**（本机 Apple clang + libc++，`-O2`）：$n = 2\cdot10^5$ 单组 $0.29$ s；$t = 10^4$、$\sum n = 2\cdot10^5$ 的极端多测 $0.34$ s。Python3 分别为 $0.20$ s / $0.16$ s。相对 $2$ s 时限至少 $5$ 倍余量。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

static const long long MOD = 998244353LL;
static const int MAXN = 200005;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    // 线性逆元表：inv[i] = i^{-1} mod MOD（MOD 为质数，且 i < MOD）
    vector<long long> inv(MAXN, 1);
    for (int i = 2; i < MAXN; i++)
        inv[i] = (MOD - (MOD / i) * inv[MOD % i] % MOD) % MOD;

    int T;
    cin >> T;
    while (T--) {
        int n;
        cin >> n;
        vector<long long> a(n);
        for (auto &x : a) cin >> x;

        sort(a.begin(), a.end(), greater<long long>());   // 降序：a[0] 是唯一的根

        long long fact = 1;                               // (n-1)!
        for (int i = 1; i <= n - 1; i++) fact = fact * i % MOD;

        long long pref = 0;      // 比当前位置「更高」的所有 rating 之和（模意义）
        long long sumAll = 0;    // 全部 rating 之和（模意义）
        long long ans = 0;

        for (int i = 0; i < n; i++) {
            long long v = a[i] % MOD;
            if (i > 0)                                        // 先算贡献
                ans = (ans + pref * fact % MOD * inv[i]) % MOD;
            pref = (pref + v) % MOD;                          // 再并入前缀
            sumAll = (sumAll + v) % MOD;
        }

        long long nonRoot = ((sumAll - a[0] % MOD) % MOD + MOD) % MOD;   // S - a_root
        ans = ((ans - nonRoot * fact % MOD) % MOD + MOD) % MOD;
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys

MOD = 998244353
MAXN = 200005


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return

    inv = [1] * MAXN                     # 线性逆元表，只建一次
    for i in range(2, MAXN):
        inv[i] = (MOD - (MOD // i) * inv[MOD % i] % MOD) % MOD

    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        n = int(data[pos])
        pos += 1
        a = list(map(int, data[pos:pos + n]))
        pos += n

        a.sort(reverse=True)             # 降序，a[0] 是唯一的根

        fact = 1
        for i in range(1, n):
            fact = fact * i % MOD

        pref = 0
        sum_all = 0
        ans = 0
        for i, x in enumerate(a):
            v = x % MOD
            if i:                                       # 先算贡献
                ans = (ans + pref * fact % MOD * inv[i]) % MOD
            pref = (pref + v) % MOD                     # 再并入前缀
            sum_all = (sum_all + v) % MOD

        non_root = (sum_all - a[0] % MOD) % MOD         # S - a_root
        ans = (ans - non_root * fact) % MOD
        out.append(str(ans))

    sys.stdout.write("\n".join(out) + "\n")


if __name__ == "__main__":
    main()
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一的人是根，没有任何边，答案为 $0$。代码中 $fact = 1$，循环只走 $j=0$ 一轮且 `if (i > 0)` 不成立，`nonRoot = 0`，输出 $0$；同时保证不会访问 `inv[0]`。
2. **$a_i > p$**：$10^9 > 998244353$，第 4 组样例就是反例——若不先取模，$S - a_{\max} = 10^9 - 1$，$\times 1$ 后再取模才恰好对上；但 $S$ 达 $2\cdot10^{14}$ 时再乘 $fact$ 会溢出。**所有 rating 一进来就 `% MOD`**。
3. **负结果**：`ans - nonRoot*fact` 可能为负，C++ 必须 `(x % MOD + MOD) % MOD`；漏掉会输出负数。
4. **下标 vs 计数**：逆元分母是「比当前点大的点数」，降序下 0-indexed 位置正好等于它；若分母误写成 $i+1$，首项会从 $240$ 变成 $120$，最终答案也不再是 $414$（第 5 组样例即可查出错）。
5. **先并入后计算**：若把 `pref += v` 写在贡献计算之前，当前点会把自己计入「更大者」，$j=1$ 时贡献变成 $7\cdot 24$ 而非 $10\cdot 24$，答案偏大。
6. **多测复用逆元表**：逆元表只与 $p$ 有关，全局建一次；而 `fact`、`pref`、`sumAll` 每组必须重算，$n$ 不同则 $(n-1)!$ 不同。答案恰为 $0$ 也是合法结果（$n=1$，或代价和恰为模数倍数），不能用 $0$ 当「无解」哨兵特判。

- [Codeforces 1540A. Great Graphs](https://codeforces.com/problemset/problem/1540/A)：把树上所有边权和排序后逐对贡献，也是「排序后每对 (i,j) 乘一个系数」的计数范式。
- [LeetCode 834. 树中距离之和](https://leetcode.cn/problems/sum-of-distances-in-tree/)：按「每条边被经过多少次」线性分解求和，与本篇引理 3 同一种线性性思维。

**延伸思考**：

1. 若允许**相同评分**当父亲（非严格），根不再唯一，$k$ 变成「大于等于」的计数，同分点之间会成环，必须按评分从大到小分组、组内用乘法原理与 $(1 + \ldots)$ 展开处理，答案结构立刻复杂一档。
2. 若要求的是 $\sum \text{cost}^2$，单点计数不够用，需要二阶量 $\sum c_u c_w$，即统计「两条边同时出现」的王朝数；只要两条边不冲突就是 $\frac{(n-1)!}{k_v k_{v'}}$，冲突时另行处理。
3. 若把「父亲必须更大」换成任意 DAG，且每个点向上候选数为 $d_v$、全图唯一汇点为 $r$，则所有结论原样成立：王朝数 $\prod d_v$，单边出现次数 $\prod_{w \ne v} d_w$，公式只依赖 $d_v$ 而与具体候选集无关。这也是本题最值得记住的一句话：**限制越强，结构越自动；结构自动了，计数就只剩乘法。**
