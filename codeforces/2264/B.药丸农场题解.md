# Codeforces 药丸农场 题解

## 1. 题目概述

- **标题 / 题号**：药丸农场（Codeforces 2264B，英文名 Knife's Pill Farm）
- **链接**：https://codeforces.com/problemset/problem/2264/B
- **来源**：Codeforces Round 1121 (Div. 2) · Problem B
- **难度**：1000（1250 分）
- **限制**：时间 1.5 s / 内存 256 MB
- **标签**：数据结构、贪心、数学

**题意**：给定长度为 $n$ 的整数序列 $a_1, a_2, \ldots, a_n$，元素**可以为负**。必须**按原有顺序**挑出恰好 $m$ 个，记作子序列 $b_1, \ldots, b_m$（也就是从 $a$ 中删掉若干元素，剩下的保持相对顺序）。分数初始为 $0$；发布第 $i$ 个时，分数变化 $i \cdot (b_i - b_{i-1})$，其中约定 $b_0 = 0$，即 $\text{score} = \sum_{i=1}^{m} i \cdot (b_i - b_{i-1})$。分数可以变负。求**最终分数的最大值**。

多测：第一行 $t$，每组先给 $n, m$，再给 $n$ 个整数 $a_i$，对每组输出一个整数答案。

**约束**：

- $1 \le t \le 10^4$，且 $\sum n \le 2 \cdot 10^5$（多测总量受控，可以每组单独 $O(n \log n)$）
- $1 \le m \le n \le 2 \cdot 10^5$
- $-10^7 \le a_i \le 10^7$
- 答案量级：$m \cdot b_m$ 可达 $2\cdot 10^{5} \times 10^{7} = 2 \cdot 10^{12}$，前缀和同量级，故**必须用 64 位整数**

## 2. 示例

```text
输入
6
5 3
0 8 1 7 3
4 3
0 -4 10 -2
4 2
0 5 -2 4
6 3
0 9 8 7 6 5
1 1
7
3 2
5 -100 4

输出
20
34
10
15

```

**官方说明摘录**：第 1 组选 $[0,1,7]$，得 $1\cdot(0-0)+2\cdot(1-0)+3\cdot(7-1)=20$；第 2 组选 $[0,-4,10]$，第 2 步虽然扣 $8$ 分，却把末项差分抬到 $10-(-4)=14$，乘 $3$ 后总共 $34$。

**自造补充**（非官方，覆盖「负数当前缀」）：$n=5$，$m=4$，$a = [-3, 10, -8, 2, -1]$ → 输出 `9`。末项只能取 $a_4=2$ 或 $a_5=-1$：前者前缀被迫全选（和 $-1$），候选 $4\times 2-(-1)=9$；后者前缀取最小的三个 $-8,-3,2$（和 $-9$），候选 $4\times(-1)-(-9)=5$。故答案为 $9$。

## 3. 解题思路

### 3.1 暴力思路

最直白：枚举所有 $\binom{n}{m}$ 个子序列，按定义逐步累加分数取最大——$n = 2\cdot 10^5$ 时子序列数是天文数字，只能拿来对拍。换 DP 也不行：状态至少要记「扫到第几个」与「已选几个」，共 $O(nm)$ 个状态，$n = 2\cdot10^5$ 就是 $4\times 10^{10}$。必须找到能**把相邻项解耦**的恒等变形。

### 3.2 核心观察：加权差分和化简为「末项 × m − 前缀和」

![把加权差分和化简成末项减前缀和](images/cf2264_b_sum_rewrite.svg)

把和式拆开，再对第二项换元：

$$S = \sum_{i=1}^{m} i\,b_i - \sum_{i=1}^{m} i\,b_{i-1}, \qquad \sum_{i=1}^{m} i\,b_{i-1} = \sum_{j=0}^{m-1} (j+1)\,b_j = b_0 + \sum_{j=1}^{m-1}(j+1)\,b_j.$$

两式相减，并用 $b_0 = 0$，同阶项系数为 $i - (i+1) = -1$：

$$S = m\,b_m - \sum_{i=1}^{m-1} b_i.$$

一句话：**只有最后一篇按 $+m$ 倍计入，前面 $m-1$ 篇每篇都按 $-1$ 倍计入。** 原来那个「相邻两项互相纠缠」的差分结构被彻底消掉了，分数只由两件事决定：

- 末项 $b_m$ 尽量大（乘上 $m$，权重最高）；
- 前 $m-1$ 项之和尽量小（负数越负越好）。

两者互不干扰，于是「选哪些元素」这件事失去了顺序上的耦合，只剩「在前缀里挑最小的若干个」这一种朴素贪心。

### 3.3 算法流程：枚举末项 + 大根堆维护最小的 $k$ 个

![枚举末项位置并用大根堆维护最小的 k 个](images/cf2264_b_heap_sweep.svg)

记 $k = m-1$。**枚举末项落在位置 $p$**（1-indexed），则前 $k$ 个只能从 $a_1, \ldots, a_{p-1}$ 里选。由化简式，要分数最大就必须让这 $k$ 个之和最小，也就是

$$\text{ans} = \max_{p \ge m}\Bigl(m\,a_p - \operatorname{sumMin}_k(a_1, \ldots, a_{p-1})\Bigr).$$

从左到右扫一遍 $p$，用**大根堆**维护「到目前为止最小的 $k$ 个」以及它们的和 $sum$。堆顶是这 $k$ 个里的最大者，也就是唯一可能被新元素顶替的那个，每次只需与堆顶比一次。

```text
k = m - 1; 堆 ← 空; sum ← 0; ans ← -∞
for i = 0 .. n-1:                                  # 0-indexed
    if i >= k:  ans = max(ans, m * a[i] - sum)     # ① 先更新答案
    if k > 0:                                      # ② 再把 a[i] 并入堆
        if 堆大小 < k:        压入 a[i];                       sum += a[i]
        elif a[i] < 堆顶:     sum -= 堆顶; 弹堆顶; 压入 a[i];   sum += a[i]
输出 ans
```

**① 与 ② 的次序是本算法的命门**：必须先更新答案、再插入 $a_i$。否则末项自己会混进「前缀」里，等于让同一个元素既当末项又当前缀，答案会偏大。

### 3.4 示例演算

![样例 1 的逐位置走查](images/cf2264_b_walkthrough.svg)

以第 1 组 $a = [0, 8, 1, 7, 3]$、$m = 3$ 为例，此时 $k = 2$（下表 $i$ 为 1-indexed 位置；$i=1,2$ 时前缀不足 $2$ 个，直接跳过，故只列 $i \ge 3$ 的行）：

| $i$ | $a_i$ | 前缀 $a_1..a_{i-1}$ | 最小的 2 个 | $sum$ | 候选 $m\,a_i - sum$ | ans |
|-----|-------|---------------------|-------------|-------|---------------------|-----|
| 3 | 1 | $[0,8]$ | $\{0,8\}$ | 8 | $3\cdot 1 - 8 = -5$ | $-5$ |
| 4 | 7 | $[0,8,1]$ | $\{0,1\}$ | 1 | $3\cdot 7 - 1 = 20$ | $\mathbf{20}$ |
| 5 | 3 | $[0,8,1,7]$ | $\{0,1\}$ | 1 | $3\cdot 3 - 1 = 8$ | $20$ |

$i = 4$ 时取到最优：选 $[0, 1, 7]$，分数 $20$，与官方输出一致。注意 $i = 5$ 时前缀虽然更长，但「最小的 2 个」仍是 $\{0,1\}$，$sum$ 没变，只是末项从 $7$ 掉到 $3$，候选随之变小。

再看第 6 组 $a = [5, -100, 4]$、$m = 2$（$k = 1$）：$i=2$ 时前缀只有 $\{5\}$，候选 $2 \times (-100) - 5 = -205$；$i=3$ 时前缀最小的是 $-100$，候选 $2 \times 4 - (-100) = 108$。最终 $108$。**这里最能体现化简式的价值**：$-100$ 自身只扣 $100$ 分，却把末项的差分从 $4$ 抬到 $104$，乘 $2$ 后净赚 $108$——在化简式里它不过是一个被减去的 $sum$，越负越好。

## 4. 算法细节

1. **$k = 0$ 必须加守卫**：$m = 1$ 时 $k = 0$，堆是空的。若写成 `else if (a[i] < pq.top())`，$k=0$ 时 `pq.size() < k` 恒假，紧接着就会对**空堆**调用 `top()`，是未定义行为。所以插入那一段整体包在 `if (k > 0)` 里。
2. **先更新、后插入**：见 §3.3 与 §8 第 3 条。这一条写错，小样例有时还能过，随机对拍必挂。
3. **64 位与初值**：$m\,a_p$ 与 $sum$ 各自可达 $2\cdot10^{12}$，差值可达 $4\cdot10^{12}$，`int` 必然溢出。同时 `ans` 要初始化为负无穷（`LLONG_MIN` / `None`），因为 $a_i$ 全负时答案本身是负数，用 $0$ 初始化会得到错误的 $0$。
4. **堆的方向与取等**：要淘汰的是「$k$ 个最小中的最大者」，所以用**大根堆**——C++ 的 `priority_queue<T>` 默认就是，Python 的 `heapq` 是小根堆，要**存相反数**，`heap[0]` 对应原来那 $k$ 个里最大的。只有 `a[i] < 堆顶` 才替换；取等不换也不会错（和没变），只是少一次 pop/push。
5. **多测与 I/O**：堆、$sum$、`ans` 都在每组内部重新声明，不要提到 `while (T--)` 外面；$\sum n \le 2\cdot10^5$ 保证了总复杂度按总量摊还是 $O(\sum n \log n)$。$t$ 可达 $10^4$，C++ 关同步 + `cin.tie(nullptr)`，Python 用 `sys.stdin.buffer.read().split()` 一次读完、`join` 一次写出，避免 $10^4$ 次 `print` 的开销。

## 5. 正确性证明

**引理 1（化简恒等式）**：对任意序列 $b_1,\ldots,b_m$（$b_0 = 0$），有 $\sum_{i=1}^{m} i\,(b_i - b_{i-1}) = m\,b_m - \sum_{i=1}^{m-1} b_i$。

**证明**：把和式拆成两项，第二项换元 $j = i-1$ 得 $\sum_{j=0}^{m-1}(j+1)b_j$。两式相减后，对 $1 \le i \le m-1$ 的同阶项系数为 $i-(i+1) = -1$，而 $i = m$ 这一项只出现在第一个和中、系数为 $m$，$b_0$ 项系数为 $-1$ 但 $b_0 = 0$。故结果为 $m\,b_m - \sum_{i=1}^{m-1}b_i$。∎

**引理 2（固定末项后，前缀的选择集是任意的 $k$ 元子集）**：设末项取在下标 $p$。则 $(b_1,\ldots,b_{m-1})$ 可以是 $a_1,\ldots,a_{p-1}$ 中任意 $k = m-1$ 个**互不相同**位置上的元素（按原序排列），反之每个这样的选择都可行；且由引理 1，其分数只依赖这 $k$ 个元素的和，与排列顺序无关。

**证明**：子序列保序，选出的下标满足 $i_1 < i_2 < \cdots < i_m = p$，于是前 $k$ 个下标都在 $1..p-1$ 内且互异；反之，任取 $p-1$ 个位置中的 $k$ 个下标，升序排列后接上 $p$，即构成合法的下标序列。分数表达式中前 $k$ 项只以 $\sum b_i$ 的形式出现。∎

**引理 3（贪心取最小的 $k$ 个最优）**：在候选集合 $a_1,\ldots,a_{p-1}$（$p-1 \ge k$）中选 $k$ 个使和最小，最优解恰为其中最小的 $k$ 个。

**证明**：交换论证。设某个最优解 $S$ 未取元素 $x$，而取了 $y$，且 $x < y$。把 $y$ 换成 $x$ 后仍是该前缀内的 $k$ 元子集（位置约束只要求互异且都在前缀内），而和减少了 $y - x > 0$，与 $S$ 最优矛盾。故最优解中不含任何「小于已选元素」的未选元素，即恰为最小的 $k$ 个。∎

**引理 4（堆不变量）**：设已并入 $a_1,\ldots,a_j$ 且 $j \ge k$，则堆内恰为这 $j$ 个元素中最小的 $k$ 个，$sum$ 等于它们的和。

**证明**：对 $j$ 归纳。$j = k$ 时前 $k$ 次插入都走「堆大小 $< k$」分支，堆即 $a_1,\ldots,a_k$，成立。设 $j$ 时成立，并入 $a_{j+1}$：若 $a_{j+1} \ge$ 堆顶 $M$，则 $M$ 仍是这 $j+1$ 个中第 $k$ 小的，最小 $k$ 个不变；若 $a_{j+1} < M$，则 $a_{j+1}$ 严格小于原最小 $k$ 个中的最大者，新的最小 $k$ 个恰为「原集合去掉 $M$ 再加入 $a_{j+1}$」，代码正是这么做的。∎

**定理**：算法输出等于题面所求的最大分数。

**证明**：任一可行解对应一个末项位置 $p \ge m$ 和一组前缀选择，由引理 1、2 其分数为 $m\,a_p - \sum$（$\sum$ 为前缀选择之和）；对固定 $p$，由引理 3 最优前缀和就是最小的 $k$ 个之和。算法求值末项 $a_p$ 的那一刻，恰好已并入 $a_1,\ldots,a_{p-1}$；取 $j = p-1$ 用引理 4，堆内恰为其最小的 $k$ 个且 `sum` 正确，故候选值 $m\,a_p - sum$ 正是该 $p$ 下的最优分数。算法对所有 $p \ge m$ 取最大值，覆盖了全部可行解，因此输出等于全局最优。∎

## 6. 复杂度分析

- **时间**：每组 $O(n \log k)$。每个元素至多一次压入、一次弹出，堆规模始终 $\le k \le m$，单次操作 $O(\log m)$；$k = 0$（$m = 1$）时退化为 $O(n)$。总计 $O(\sum n \cdot \log n)$，最坏约 $2\cdot10^5 \times 18 \approx 3.6\times10^6$ 次堆操作。
- **空间**：堆 $O(m)$，输入数组 $O(n)$，无二维表。
- **实测**：$n = 2\cdot10^5$ 时本机 C++ 最坏 $0.25$ s、Python3 约 $0.06$–$0.12$ s；$t = 10^4$、$\sum n = 2\cdot10^5$ 的多测压力下 C++ $0.26$ s。C++ 的耗时几乎全在 `cin` 读入——本机是 Apple clang + libc++，同一数据改用 `scanf` 仅需 $0.02$ s，而算法本身只有 $3.6\times10^6$ 次堆操作；换成 CF 的 libstdc++ 只会更快。即便按这个偏悲观的上界，相对 $1.5$ s 仍有 $6$ 倍余量。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int T;
    cin >> T;
    while (T--) {
        int n, m;
        cin >> n >> m;
        vector<long long> a(n);
        for (auto &x : a) cin >> x;

        int k = m - 1;                 // 需要先选出的「前面的」草稿数
        priority_queue<long long> pq;  // 大根堆：维护前缀中最小的 k 个，堆顶是其中最大者
        long long sum = 0;             // 这 k 个的和
        long long ans = LLONG_MIN;     // 答案可能为负，不能用 0 初始化

        for (int i = 0; i < n; i++) {
            // 前缀 a[0..i-1] 长度为 i，只有 i >= k 才凑得够前 k 个
            if (i >= k) ans = max(ans, (long long)m * a[i] - sum);

            // 把 a[i] 并入「最小的 k 个」；k == 0 时必须跳过，否则会访问空堆的 top()
            if (k > 0) {
                if ((int)pq.size() < k) {
                    pq.push(a[i]);
                    sum += a[i];
                } else if (a[i] < pq.top()) {
                    sum -= pq.top();
                    pq.pop();
                    pq.push(a[i]);
                    sum += a[i];
                }
            }
        }
        cout << ans << '\n';
    }
    return 0;
}
```

### Python3

```python
import sys
import heapq


def main() -> None:
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    pos = 1
    out = []
    for _ in range(t):
        n = int(data[pos])
        m = int(data[pos + 1])
        pos += 2
        a = list(map(int, data[pos:pos + n]))
        pos += n

        k = m - 1                              # 先选出的草稿数
        heap = []                              # 存 -v：堆顶是「最小的 k 个」中最大的那个
        s = 0
        best = None
        for i, x in enumerate(a):
            if i >= k:                         # 前缀 a[0..i-1] 已够 k 个
                cand = m * x - s
                if best is None or cand > best:
                    best = cand
            if k:                              # k == 0 时不碰堆，否则 heap[0] 会越界
                if len(heap) < k:
                    heapq.heappush(heap, -x)
                    s += x
                elif x < -heap[0]:
                    s += heap[0]               # 减去被淘汰的那个最大者
                    heapq.heapreplace(heap, -x)
                    s += x
        out.append(str(best))

    sys.stdout.write("\n".join(out) + "\n")


if __name__ == "__main__":
    main()
```

## 8. 边界情况与易错点

1. **$m = 1$（即 $k = 0$）**：此时只需发一篇，答案是 $\max_i a_i$。代码里 `k = 0` 会让堆一直为空，所以插入那段必须用 `if (k > 0)` / `if k:` 包住——C++ 对空 `priority_queue` 调 `top()`、Python 对空列表取 `heap[0]` 都会出错（前者是 UB，后者直接 `IndexError`）。
2. **答案全负**：$a$ 全为负且 $m = n$ 时，答案可低至约 $-2\cdot10^{12}$。`ans` 必须以负无穷起始，用 $0$ 初始化会把答案错答成 $0$；Python 里用 `None` 哨兵最省事。
3. **先插入后更新（最常见 WA）**：反例 $n=2, m=2, a=[10, -100]$。正确答案只有一种选法，分数 $2\cdot(-100) - 10 = -210$；若先插入再求值，$i=2$ 时堆里会先放进 $-100$，于是候选变成 $2\cdot(-100) - (-100) = -100$，把末项当成了自己的前缀，答案偏大。
4. **`int` 溢出**：$m \cdot a_i$ 最大 $2\cdot10^{12}$，`int` 上限约 $2.1\cdot10^9$。C++ 里 `m * a[i]` 必须先把 `m` 转成 `long long`（写作 `(long long)m * a[i]`），否则按 `int` 乘法溢出后再赋给 `long long` 已经晚了。
5. **多测复用变量**：`pq`、`sum`、`ans` 必须在每组开头重置，尤其别把 `sum` 提到 `while (T--)` 外面，否则上一组的前缀和会漏进下一组。$n = m$ 时 $p$ 只能是 $n$、前缀被迫全选，代码无需特判（`i >= k` 在 $i = n-1$ 恰好成立），由 $m \le n$ 可保证 `ans` 至少被更新过一次。

**延伸思考**：

1. 若把权重 $i$ 换成任意固定权重 $w_i$，化简给出 $w_m b_m + \sum_{i<m}(w_i - w_{i+1})b_i$。此时前缀各项系数**有正有负**，「取最小的 $k$ 个」不再最优，需要在系数为正的位置取最小、为负的位置取最大，得用两个堆按 $p$ 动态维护，问题立刻上一个难度档次。
2. 若要求选的篇数落在区间 $[L, R]$ 而非恰好 $m$，就要对每个长度各求一次「前缀最小 $k$ 个之和」，可借助可持久化/可查询结构，或用分治 + 归并把 $O(nR)$ 压下来。
3. 若允许 $b_0 \ne 0$，化简式会保留 $-b_0$ 这个常数项，答案整体平移而不影响贪心——本题结构对「起点偏移」是稳健的。
