# Codeforces 摧毁塔楼 题解

## 1. 题目概述

- **标题 / 题号**：摧毁塔楼（Codeforces 2237A，英文名 Destroying Towers）
- **链接**：https://codeforces.com/problemset/problem/2237/A
- **来源**：Order Capital Round 2 (Codeforces Round 1104, Div. 1 + Div. 2) · Problem A
- **难度**：800（500 分，题面标注 *800）
- **限制**：时间 1 s / 内存 256 MB
- **标签**：博弈、贪心、调度

**题意**：$n$ 座塔排成一列，第 $i$ 座高 $a_i$。鸭子 Quack 要**对每座塔恰好执行一次**操作，顺序自选。对第 $i$ 座塔的操作是：向右发射激光，命中**右侧第一座比自己高的塔**，把它削到与第 $i$ 座塔等高。形式化地，取最小的 $j > i$ 使当前 $a_j > a_i$；若存在则令 $a_j \leftarrow a_i$，否则什么都不发生。求所有操作顺序下，**最终塔高之和的最小值**。多测，每组输出一个数。

**约束**：

- $1 \le t \le 500$，$1 \le n \le 100$，$1 \le a_i \le 1000$；
- 每组独立求解，$\sum n \le 5\times 10^4$，$O(n)$ 或 $O(n \log n)$ 每组的做法都绰绰有余；
- 高度只减不增，且新高度一定来自原有的某个 $a_k$；
- 命中条件是**严格大于**，因此等高的塔互相"打不动"；
- 单组答案最大 $100 \times 1000 = 10^5$，`int` 足够，但用 64 位更省心。

## 3. 解题思路

### 3.1 暴力思路

"顺序任意"的第一反应是枚举 $n!$ 种操作顺序：每次模拟要 $O(n)$ 找目标、$O(n)$ 修改，总共 $O(n! \cdot n)$。$n = 8$ 已是 $4\times 10^4$ 次模拟，$n = 100$ 时天文数字，完全不可行。

另一类"看似合理"的贪心也要小心：比如先处理高塔——对 $[1,3,5]$ 按 $3,2,1$ 的顺序操作，结果是 $[1,1,3]$、和为 5，比最优的 3 差。无论走哪条路，都得先回答一个问题：**什么样的顺序才算最优**。本题的关键是：**最终结果与顺序无关地由一个简单量刻住**。

### 3.2 核心观察：每座塔的终值就是前缀最小值

![每座塔终值等于前缀最小值](images/cf2237_a_prefix_min.svg)

两个方向夹逼，就能把"最优化顺序"变成一道加法题。

**方向一（下界，谁也逃不掉）**：操作只会把某座塔改成**它左边**某座塔的当前高度（第 $j$ 座塔只能被某个 $i < j$ 的操作改写），而左侧塔的当前高度又始终不低于前缀最小值 $m_i = \min(a_1,\ldots,a_i)$。于是

$$a_j \ \ge\ \min\bigl(a_j,\ m_{j-1}\bigr) \ =\ m_j \qquad \text{（始终成立，约定 } m_0 = +\infty \text{）}$$

极端情形一眼可见：第 $1$ 座塔永远没有左边的塔能改它，所以答案的下界至少是 $a_1 = m_1$。

**方向二（上界，能做到）**：**按塔高从小到大**处理。轮到 $i$ 时它若还没被处理过，就以它为起点"连锁开火"：先 op$(i)$，它把右边第一座更高的塔 $j_1$ 压成 $a_i$；紧接着 op$(j_1)$（此时 $j_1$ 的高度已是 $a_i$）再把右边第一座高于 $a_i$ 的塔压成 $a_i$……如此一路向右，直到右边没有任何塔高于 $a_i$。

这条链**恰好扫过所有原高大于 $a_i$ 的右侧塔**：链上当前高度恒为 $a_i$；中间的塔要么原高 $\le a_i$（被跳过），要么已被之前的链压到某个 $\le a_i$ 的值（也被跳过）。因此一次"最矮塔开火"就能把一段上升阶梯整段拍平。

### 3.3 算法流程

![算法流程](images/cf2237_a_greedy_flow.svg)

既然答案只由 $m_i$ 决定，**根本不需要模拟开火**，一次左→右扫描即可：

$$\text{best} \leftarrow +\infty,\quad \text{sum} \leftarrow 0;\qquad \text{对每个 } a_i:\ \ \text{best} \leftarrow \min(\text{best}, a_i),\ \ \text{sum} \leftarrow \text{sum} + \text{best}$$

注意顺序：**先**用 $a_i$ 更新 best，**再**把 best 累加进 sum（这样第 $i$ 项加的是 $m_i$，而不是 $m_{i-1}$）。多测时每组把 best 重置为 $+\infty$。

### 3.4 示例演算

![样例 5 的走查](images/cf2237_a_walkthrough.svg)

对样例 5 的 $a = [4,1,3,5,2]$，按高度递增的处理序是 $2 \to 5 \to 3 \to 1 \to 4$（下标）：

| 步骤 | 操作 | 触发 | 当前塔高 |
|------|------|------|----------|
| ① | op(2) | 3 号塔 $3 \to 1$ | $[4,1,1,5,2]$ |
| ② | op(3) | 4 号塔 $5 \to 1$ | $[4,1,1,1,2]$ |
| ③ | op(4) | 5 号塔 $2 \to 1$ | $[4,1,1,1,1]$ |
| ④ | op(5) | 右边没有塔 | $[4,1,1,1,1]$ |
| ⑤ | op(1) | 右边都 $\le 4$ | $[4,1,1,1,1]$ |

②③④ 是 ① 引发的连锁（被压低的塔当场就地开火），一次开火压平整段上升阶梯。终态 $[4,1,1,1,1]$ 与前缀最小值 $4,1,1,1,1$ 逐位相同，和 $= 8$，正是官方输出。

## 4. 算法细节

1. **只维护一个前缀最小值**：`best` 初值取 $+\infty$（C++ 用 `INT_MAX`），或先读入 $a_1$ 再进循环，避免把第 $1$ 项错算成 $+\infty$。
2. **更新与累加的顺序**：必须先 `best = min(best, a[i])`、再 `sum += best`；写反会让第 $i$ 项用上 $m_{i-1}$，样例 1 立即变错。
3. **多测重置**：`best` 与 `sum` 在每组开头重置；`t` 组共用同一套循环体，不要在外层累加。
4. **不要真去模拟**：模拟需要为每次操作找"右边第一个更高的塔"，$O(n^2)$ 也能过（$n \le 100$），但完全没有必要；本题从结论出发是 $O(n)$、$O(1)$ 额外空间。
5. **绝不能用 $n \cdot \min a$**：只有右侧塔会被压低，左侧塔保留原高。反例 $[5,4,3]$：答案 12 而非 9；$[10,3,8,6,9]$ 答案 22 而非 15。
6. **读入效率**：$t \le 500$、$\sum n \le 5\times 10^4$，`scanf` / `cin`（关同步）都够；Python 用 `sys.stdin.buffer.read().split()` 一次读完最稳。
7. **越界检查**：每组只有一个 `n` 和恰好 $n$ 个整数，按格式读即可；`sum` 用 `long long`（`INT_MAX` 级别的 `best` 不会被累加，因为第一项就会被覆盖）。

## 5. 正确性证明

**引理 1（高度只沿下标向右传递）**：任意时刻第 $j$ 座塔的高度都是某个原始 $a_k$（$k$ 为原下标），且改写它的操作必来自某个 $i < j$。

**证明**：初始成立。每次操作只把 $a_j$ 赋成当前 $a_i$（$i < j$），由归纳假设当前 $a_i$ 又是某个原始 $a_k$（$k \le i < j$），故不变量保持。∎

**引理 2（下界）**：任意操作顺序、任意时刻，都有当前 $a_j \ge m_j$。

**证明**：对操作次数归纳。初始 $a_j \ge m_j$ 显然。设操作来自 $i < j$，则新值 $a_j \leftarrow$ 当前 $a_i \ge m_i$（归纳假设）$\ge m_j$（因 $i < j$，前缀最小值单调不增，$m_i \ge m_j$）。其余塔不变。∎

**引理 3（连锁开火恰好扫过所有更高的塔）**：按塔高非降序处理（同高任意），轮到 $i$ 时它尚未被操作（当前高度即原高 $a_i$），则以其为起点的连锁开火按从左到右的顺序，恰好把所有满足 $j > i$ 且原高 $a_j > a_i$ 的塔压成 $a_i$，并对它们各执行一次操作。

**证明**：链上每一步的端点 $\text{cur}$ 高度恒为 $a_i$，落点定义为 $\text{cur}$ 右侧第一个当前高度 $> a_i$ 的位置。夹在中间的塔只有两类，都不会被误选：其一未被改写，当前高度即原高——若原高 $> a_i$ 则它早已被本链访问并压成 $a_i$，否则原高 $\le a_i$；其二已被更早的链改写，其值为某个 $a_h$，而 $h$ 在处理序中早于 $i$，按排序假设 $a_h \le a_i$。故下一步落点就是 $\text{cur}$ 右侧第一个原高 $> a_i$ 的塔，链既不提前终止也不漏项，直到右侧全 $\le a_i$。∎

**引理 4（构造达到下界）**：按塔高非降序处理，轮到 $i$ 时若尚未被操作则以其为起点连锁开火，则最终每座塔的终值都是 $m_j$。

**证明**：任一塔被改写后紧接着就被操作（连锁），故**未被操作的塔仍等于原高**。取任意 $j$，令 $q$ 为使 $a_q = m_j$ 的最小下标，则 $q \le j$ 且 $a_q = m_q$。先验 $q$ 从未被改写：对任何 $i < q$，当前高度 $\ge m_i \ge m_q = a_q$，不满足"严格更高"，无法命中 $q$。于是轮到 $q$ 时它仍为原高 $m_j$，由引理 3，这次开火结束后 $q$ 右侧不再有当前高度 $> m_j$ 的塔，即 $a_j \le m_j$；若 $j = q$，则直接有 $a_j = a_q = m_j$。再由引理 2 得 $a_j \ge m_j$，两向夹逼给出 $a_j = m_j$。此后高度只减不增，且引理 2 始终保证下界，故终值恰为 $m_j$。∎

**定理**：最小最终塔高之和为 $\sum_{j=1}^{n} m_j$，其中 $m_j = \min(a_1,\ldots,a_j)$，且该值可由上述顺序达到。

**证明**：由引理 2，任何顺序的终值和都 $\ge \sum m_j$；由引理 4，存在顺序使其等于 $\sum m_j$。故最小值即 $\sum m_j$，而算法正是逐项累加 $m_j$。∎

## 6. 复杂度分析

- **时间**：每组一次线性扫描，$O(n)$；总时间 $O(\sum n) \le 5\times 10^4$ 次基本运算，1 s 限时下是毫秒级，余量三个数量级以上。
- **空间**：除输入本身外只用两个变量（`best`、`sum`），额外空间 $O(1)$；若把数组读进来也是 $O(n) \le 100$，远低于 256 MB。
- **对照时限**：最坏输入（$t = 500$，每组 $n = 100$，$a_i$ 取满 1000）实测 C++ 约 0.01 s、Python 约 0.05 s（含解释器启动），距 1 s 时限仍有两个数量级余量，Python 无需 PyPy 也能过。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    if (scanf("%d", &t) != 1) return 0;
    while (t--) {
        int n;
        scanf("%d", &n);
        int best = INT_MAX;          // 前缀最小值 m_i
        long long sum = 0;
        for (int i = 0; i < n; i++) {
            int x;
            scanf("%d", &x);
            if (x < best) best = x;  // 先更新 best
            sum += best;             // 再加进答案，保证第 i 项加的是 m_i
        }
        printf("%lld\n", sum);
    }
    return 0;
}
```

```python
import sys


def main() -> None:
    data = list(map(int, sys.stdin.buffer.read().split()))
    p = 0
    t = data[p]
    p += 1
    out = []
    for _ in range(t):
        n = data[p]
        p += 1
        a = data[p:p + n]
        p += n
        best = 10 ** 9              # 前缀最小值，初值取大于 a_i 上界的数
        s = 0
        for x in a:
            if x < best:
                best = x
            s += best
        out.append(str(s))
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n = 1$**：没有任何 `j > i`，操作恒为空，答案就是 $a_1$；`best` 初值必须能被第一项覆盖（用 `INT_MAX` 或 `10^9` 都可以）。
2. **严格递减数组**（如 $[5,4,3]$）：每座塔右边都没有更高的塔，所有操作都是空操作，答案 = 原数组之和 12，不能套"最小值 $\times n$"。
3. **严格递增数组**（如 $[1,3,5]$）：从最矮的塔开始的连锁把右侧全部压成 $a_1$，答案 3，是前缀最小值公式的极端形态。
4. **全部等高**（如 $[1,1,1,1]$）：命中条件是**严格大于**，等高的塔互相打不动，故保持原样，答案 = 原数组之和 4。这一条常被误读成"激光会一路削平所有右侧塔"，但压到等高本身不改变高度，所以"是否严格"不影响最优值，却决定了链从哪里拐弯——写模拟版时必须用严格大于。
5. **首元素极大**（如 $[10,3,8,6,9]$）：第 1 座塔永远无法被压低，它独占地贡献 $a_1 = 10$，其余塔由后面的前缀最小值 3 接管，答案 22；忘记"左侧塔无法被改写"就会误以为能到 15。
6. **更新顺序写反**：先 `sum += best` 再 `best = min(best, a[i])`，第 1 项会用上 $+\infty$，样例 1 直接报错——这是本题最容易踩的实现坑。
7. **多测未重置**：`best` 跨组残留会让后面每组的第一段沿用上一组的极小值，输出整体偏小。
8. **溢出**：本题单组答案 $\le 10^5$，`int` 也够；但 `best` 初值用 `INT_MAX` 时不要把它累加进 `sum`（第一项会立刻覆盖它），若把 $n$、$a_i$ 换成 $10^5$ 量级则必须用 64 位。

**延伸思考**：把操作改成"一次削平右侧**所有**更高的塔"，答案**仍然是**前缀最小值之和——变强的是操作，不是下界，引理 2 一个字符都没有变；这说明真正卡住答案的是"高度只能从左边来"，而不是链的长度。把方向镜像成"左侧第一个更高的塔"，则答案变成后缀最小值之和 $\sum_j \min(a_j,\ldots,a_n)$（由对称性直接得到）。若要求**输出一种最优操作顺序**，引理 4 的构造（按高度递增、连锁开火、跳过已操作的塔）本身就是答案，用栈即可在 $O(n)$ 内实现。再进一步：若第 $j$ 座塔削掉单位高度的代价是 $c_j$ 且各不相同，那么"全部压到 $m_j$"通常不再最优（代价高的塔宁可保留原高），问题从"求最小值"变成"在 $\{a_h : h < j\}$ 里为每座塔挑一个终值的带权选择"，需要用 DP 或费用流重新建模。
