# Codeforces 合并以匹配 题解

## 1. 题目概述

- **标题 / 题号**：合并以匹配（Codeforces 2248B，英文名 Merge to Match）
- **链接**：https://codeforces.com/problemset/problem/2248/B
- **来源**：Codeforces Round 1113 (Div. 2) · Problem B
- **难度**：1000
- **限制**：时间 1.5 s / 内存 256 MB
- **标签**：贪心，排序，匹配（Hall 计数）

**题意**：给定长为 $n$ 的数组 $a$ 与长为 $m$ 的数组 $b$，$n+m$ 个数两两不同。允许对 $a$ 反复执行一种操作：取出其中两个值 $x \le y$，把这两个元素删除，再往 $a$ 中放入**任意**一个满足 $x \le z \le y$ 的整数 $z$。每操作一次，$a$ 的长度恰好减少 1；操作次数任意（可以为 0），最后可以**任意重排** $a$ 的元素。问能否让 $a$ 恰好变成 $b$。多测：第一行给出组数 $t$，每组依次给出 $n, m$、数组 $a$、数组 $b$，逐组输出 `YES` / `NO`。

**约束**：

- $1 \le t \le 10^4$，$1 \le n, m \le 2\times 10^5$，$\sum n \le 2\times 10^5$，$\sum m \le 2\times 10^5$
- $1 \le a_i, b_i \le 10^9$，且 $a$、$b$ 共 $n+m$ 个数**两两不同**，特别地 $b_i \notin a$
- 必须恰好做 $n-m$ 次操作（长度从 $n$ 降到 $m$）；$n < m$ 时长度永远降不到 $m$，必然失败
- $z$ 可取 $[x,y]$ 内任意整数，不必是原数组中出现过的值，也不要求与别的元素不同
- 时限 1.5 s，规模允许 $O\bigl((n+m)\log(n+m)\bigr)$ 的排序，其余部分必须是线性

## 3. 解题思路

### 3.1 暴力思路

最自然的暴力是「枚举分组」：把 $a$ 的每个元素指派给某个 $b_j$（$m^n$ 种指派），再检查每组是否满足 $\min < b_j < \max$。正确，但 $n = 2\times10^5$ 时一组都跑不完。另一种是「逐操作搜索」：状态是当前多重集，每次挑一对 $x \le y$、再枚举 $z \in [x,y]$，仅 $z$ 就有 $10^9$ 种取法。暴力只提示了两件事：判定是**存在性**问题，应该找不变量；一次操作把两个元素"合成"一个，本质是在**分组** —— $n-m$ 次操作会把 $a$ 分成 $m$ 棵合并树，每棵树产出 $b$ 的一个元素。

### 3.2 核心观察：每个目标都被「组内最小值与最大值」夹住

![合并只会在组内区间里产生值](images/cf2248_b_group_interval.svg)

把操作看成合并树：叶子是 $a$ 的若干元素，内部结点是一次合并。区间不会扩大 —— 合并 $x,y$ 得到的 $z$ 落在 $[\min(x,y),\max(x,y)]$ 内，而子树产出的值本来就在其叶子值域内，因此树根的值 $v$ 满足

$$\min(S) \le v \le \max(S), \qquad S = \text{该树的叶子集合}.$$

反过来，只要 $\min(S) < b < \max(S)$，就一定能把 $S$ 合成 $b$：先用 $\min(S)$ 与 $\max(S)$ 合成 $b$（合法，$b$ 就在两端之间），再让当前值 $b$ 与组内其余元素 $e$ 逐个合并 —— 无论 $e<b$ 还是 $e>b$，都取 $z=b$，永远合法。

于是问题彻底变成**分组问题**：能否把 $a$ 分成 $m$ 个非空组，使第 $g$ 组同时含一个小于 $b_g$ 的元素和一个大于 $b_g$ 的元素。由此得到两条结构性结论：每组至少要 2 个元素（$b_g \notin a$，单元素组的产出不可能等于 $b_g$），故 $n \ge 2m$；而多余的那 $n-2m$ 个元素是"免费附赠"的，塞进任何一组只会把 $[\min,\max]$ 拉宽，不破坏可行性。

### 3.3 算法流程：排序后的两条「对齐不等式」

![判定流程与夹心结构](images/cf2248_b_check_flow.svg)

只需给每个 $b_g$ 配两个互不相同的 $a$ 元素，一个更小、一个更大。两个数组都排序后，这件事有干净的充要条件。

**下界计数**：最小的 $k+1$ 个目标 $b_0,\dots,b_k$ 各自的下界元素都小于自己、从而不大于 $b_k$，且互不相同，所以 $\#\{a_i < b_k\} \ge k+1$，等价于 $a_k < b_k$。

**上界计数**：最大的 $m-k$ 个目标 $b_k,\dots,b_{m-1}$ 各自的上界元素都大于等于 $b_k$ 且互不相同，故 $\#\{a_i > b_k\} \ge m-k$；这些元素必是排序后最靠右的那些，于是等价于 $a_{n-m+k} > b_k$。

**充分性**：$n \ge 2m$ 时下标集合 $\{0,\dots,m-1\}$ 与 $\{n-m,\dots,n-1\}$ 不重叠，直接取

$$G_k = \{\,a_k,\ a_{n-m+k}\,\}, \qquad k = 0, 1, \dots, m-1,$$

两条不等式恰好给出 $a_k < b_k < a_{n-m+k}$，由 3.2 的构造每组都能造出 $b_k$；剩下的 $n-2m$ 个元素全部并入 $G_0$ 即可。

于是算法只有三步：① 分别排序 $a$、$b$；② 若 $n < 2m$ 直接 `NO`；③ 否则对每个 $k \in [0,m)$ 检查 $a_k < b_k$ 与 $a_{n-m+k} > b_k$，全真输出 `YES`，否则 `NO`。

### 3.4 示例演算

![样例走查：YES 与 NO 各一例](images/cf2248_b_walkthrough.svg)

官方样例第 9 组：$a$ 排序为 $1,3,8,12,18,25,30$，$b$ 排序为 $2,15,28$，$n=7 \ge 2m=6$ 通过长度关，再逐列检查：

| $k$ | $b_k$ | $a_k$ | $a_{n-m+k}$ | $a_k < b_k$ | $b_k < a_{n-m+k}$ |
|-----|-------|-------|-------------|-------------|-------------------|
| 0 | 2 | 1 | $a_4 = 18$ | $1 < 2$ ✓ | $2 < 18$ ✓ |
| 1 | 15 | 3 | $a_5 = 25$ | $3 < 15$ ✓ | $15 < 25$ ✓ |
| 2 | 28 | 8 | $a_6 = 30$ | $8 < 28$ ✓ | $28 < 30$ ✓ |

三列全过输出 `YES`，对应分组 $\{1,18\}\to2$、$\{3,25\}\to15$、$\{8,30\}\to28$，多余元素 $12$ 并入任意一组。反例看第 8 组：$a=\{1,2,3,100\}$、$b=\{4,5\}$，$n=4 \ge 2m=4$ 通过，但 $k=0$ 时 $a_{n-m+0}=a_2=3>4$ 不成立 —— 比 4 大的元素只有 $100$，可它得留给 5，所以 4 拿不到上界，输出 `NO`。可见两条不等式必须**同时**成立。

## 4. 算法细节

1. **先判长度再判不等式**：$n<2m$ 时 $n-m+k$ 与 $k$ 会落到同一片区域（如 $n=5,m=3$ 时 $a_1$ 既当 $k=1$ 的下界又当 $k=0$ 的上界），含义已错乱；把不等式检查放进 $n \ge 2m$ 的分支里最清楚。
2. **从 0 开始编号**：排序后 $a_0 \le a_1 \le \dots$、$b_0 \le b_1 \le \dots$，枚举 $k = 0 \dots m-1$，不要混用 1-indexed。
3. **严格不等号**：题面保证 $b_i \notin a$，故 $a_k < b_k$ 与 $a_k \le b_k$ 等价；仍建议写严格不等号，因为若放宽成"值可重复"，$a_k = b_k$ 会让单元素组直接过关，条件要重写。
4. **多测重置**：每组用局部 `vector` 重新读入并在局部排序，切勿复用全局数组而不截断，否则上一组尾部元素会混进来。
5. **类型选择**：本题只有比较、没有算术，`int` 已够（$10^9 < 2^{31}$）；统一用 `long long` 只是省心。
6. **I/O**：$\sum n,\sum m$ 各 $2\times10^5$、$t$ 可达 $10^4$，必须 `ios::sync_with_stdio(false)` 并用 `'\n'`。本机（Apple clang + libc++）实测 iostream 解析 $4\times10^5$ 个整数要 $0.4\sim0.6$ s，属库实现问题；在同类环境担心超时可换 `scanf` 或 fread 快读，判定逻辑一字不改。

## 5. 正确性证明

**引理 1（区间不变量）**：设某棵合并子树的叶子集合为 $S$（$|S| \ge 1$），当前产出值为 $v$，则 $\min(S) \le v \le \max(S)$。

**证明**：对 $|S|$ 归纳。$|S|=1$ 时 $v$ 即该元素。设根由叶子集 $S_1,S_2$ 的两棵子树合并，$S=S_1\cup S_2$，产出 $z \in [\min(v_1,v_2),\max(v_1,v_2)]$，而 $\min(S) \le \min(v_1,v_2)$、$\max(S) \ge \max(v_1,v_2)$，故 $\min(S) \le z \le \max(S)$。∎

**引理 2（单组可行 ⟺ 夹住）**：设 $b \notin S$，能把 $S$ 合成 $b$ 当且仅当 $\min(S) < b < \max(S)$。

**证明**：必要性即引理 1（取 $v=b$）。充分性：记 $u=\min(S)$、$w=\max(S)$，先合并 $(u,w)$ 取 $z=b$（$u<b<w$，合法），组内当前值变为 $b$；再对 $S\setminus\{u,w\}$ 中每个 $e$，若 $e<b$ 合并 $(e,b)$、若 $e>b$ 合并 $(b,e)$，两种情况都取 $z=b$，值为 $b$ 保持不变。共用 $|S|-1$ 次操作。∎

**引理 3（下界不等式必要）**：若可行，则对每个 $k \in [0,m)$ 有 $a_k < b_k$。

**证明**：$b_0,\dots,b_k$ 这 $k+1$ 个目标属于不同的组，各有一个严格小于自身、互不相同的元素；由 $j \le k \Rightarrow b_j \le b_k$ 且 $b_k \notin a$，它们全都严格小于 $b_k$。故 $a$ 中至少 $k+1$ 个元素小于 $b_k$，即第 $k+1$ 小（下标 $k$）的 $a_k < b_k$。∎

**引理 4（上界不等式必要）**：若可行，则对每个 $k \in [0,m)$ 有 $a_{n-m+k} > b_k$。

**证明**：对称地，$b_k,\dots,b_{m-1}$ 共 $m-k$ 个目标各需要一个严格大于 $b_k$、互不相同的元素，故 $a$ 中大于 $b_k$ 的元素至少 $m-k$ 个；这类元素必是排序后最靠右的若干个，其中最小的一个是 $a_{n-m+k}$，故 $a_{n-m+k} > b_k$。∎

**引理 5（长度必要）**：若可行，则 $n \ge 2m$。

**证明**：由引理 2，每组至少 2 个元素（$b_g \notin a$，单元素组的产出等于该元素，不可能等于 $b_g$），$m$ 组至少需要 $2m$ 个元素，而元素共 $n$ 个。∎

**定理**：算法输出 `YES` 当且仅当能把 $a$ 变成 $b$。

**证明**：若算法输出 `YES`，则 $n \ge 2m$，取 $G_k=\{a_k,a_{n-m+k}\}$、剩余元素并入 $G_0$；由 $0 \le k \le m-1 < n-m$ 知这 $2m$ 个下标两两不同，确实是一个划分，且由引理 3、4 得 $\min(G_k) < b_k < \max(G_k)$（并入多余元素只会让区间更宽）。由引理 2，每组独立合成目标，总操作数恰为 $n-m$，得到 $b$。反之若可行，由引理 3、4、5 三条检查必然全部通过，算法输出 `YES`。∎

## 6. 复杂度分析

- **时间**：每组排序 $O(n\log n + m\log m)$，两条不等式扫描 $O(m)$；总计 $O\bigl(\sum (n\log n + m\log m)\bigr)$，在 $\sum n,\sum m \le 2\times10^5$ 下约 $10^7$ 次以内比较。
- **空间**：两个数组 $O(n+m)$，无额外数据结构；Python 一次性读入全部 token，约 $O(\sum n+\sum m)$ 个字节对象。
- **实测**：Apple clang / libc++、C++17 -O2 下，单组 $n=2\times10^5, m=10^5$ 端到端 $0.43$ s，$t=10^4$、每组 $n=m=20$（$\sum n=\sum m=2\times10^5$）端到端 $0.58$ s；同一逻辑改用 fread 读入只需 $0.01$ s，说明耗时几乎全在 iostream 解析，算法本身是几十毫秒级。Python3 在同样数据上 $0.10\sim0.14$ s。
- **对照时限**：1.5 s 有 2.5 倍以上余量；把 $\sum n$ 放大十倍，排序仍是唯一瓶颈。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;                  // 空输入防护
    while (t--) {
        int n, m;
        cin >> n >> m;
        vector<long long> a(n), b(m);
        for (auto &x : a) cin >> x;
        for (auto &x : b) cin >> x;

        sort(a.begin(), a.end());
        sort(b.begin(), b.end());

        bool ok = (n >= 2 * m);                 // 每组至少要 2 个元素
        for (int k = 0; ok && k < m; ++k) {
            if (!(a[k] < b[k])) ok = false;             // 至少 k+1 个 a 小于 b[k]
            if (!(a[n - m + k] > b[k])) ok = false;     // 至少 m-k 个 a 大于 b[k]
        }
        cout << (ok ? "YES\n" : "NO\n");
    }
    return 0;
}
```

### Python3

```python
import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0])
    p = 1
    out = []
    for _ in range(t):
        n, m = int(data[p]), int(data[p + 1])
        p += 2
        a = sorted(map(int, data[p:p + n]))
        p += n
        b = sorted(map(int, data[p:p + m]))
        p += m

        ok = n >= 2 * m
        if ok:
            for k in range(m):
                if not (a[k] < b[k] and a[n - m + k] > b[k]):
                    ok = False
                    break
        out.append("YES" if ok else "NO")
    sys.stdout.write("\n".join(out) + "\n")


main()
```

## 8. 边界情况与易错点

1. **$n=m$（零次操作）**：$b$ 与 $a$ 元素两两不同，$a$ 本身绝不可能等于 $b$，必须 `NO`；长度检查 $n \ge 2m$ 对 $m \ge 1$ 要求 $n \ge 2$，天然挡掉。
2. **$n<2m$（如 $n=3,m=2$）**：不是"差一个元素"的小误差，而是每组凑不出两个不同元素，直接 `NO`（官方第 2 组）。
3. **$m=1$**：条件退化为 $a_0 < b_0 < a_{n-1}$，即 $b$ 严格落在 $a$ 的最小值与最大值之间（官方第 1、10 组）。
4. **上界或下界整体缺失**：$b$ 比所有 $a$ 都大（第 5 组）或都小（第 4 组）时某条不等式必然失败；不必对最大/最小值特判，统一交给不等式更安全。
5. **下标越界**：$n<m$ 时 $n-m+k<0$，C++ 里 `a[n-m+k]` 是未定义行为，Python 里则静默取到末尾元素（负数索引），两种都可能掩盖错误。务必先判长度再进循环。
6. **多余元素不能丢**：$n-2m>0$ 时操作次数仍是固定的 $n-m$，多余元素必须并进某个组；并进去只会拉宽区间，不影响可行性（第 6、9 组都有多余元素）。
7. **多测残留与输出**：`vector` 定义在循环外又不 `clear` 会串组；输出用 `'\n'` 而非 `endl`，$t$ 大时差距明显；`YES`/`NO` 大小写任意，但不要带多余空格或空行。
