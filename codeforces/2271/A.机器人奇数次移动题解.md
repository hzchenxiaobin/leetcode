# Codeforces 机器人奇数次移动 题解

## 1. 题目概述

- **标题 / 题号**：机器人奇数次移动（Codeforces 2271A，英文名 Robot Odd Moves）
- **链接**：https://codeforces.com/problemset/problem/2271/A
- **来源**：DeepInfra Round 1 (Codeforces Round 1126, Div. 1 + Div. 2) · Problem A
- **难度**：800（Div. 1 + Div. 2 签到题，500 分）
- **限制**：时间 1 s / 内存 256 MB
- **标签**：数学，构造

**题意**：机器人在整数网格的原点 $(0,0)$，每次**操作**固定分两小步：

1. 向上或向下走一格：$(x,y) \to (x, y+1)$ 或 $(x,y) \to (x,y-1)$；
2. 再向右走一格：$(x,y) \to (x+1, y)$。

机器人「访问」某点是指它在某个时刻正站在这点上——包括第一次操作之前、某一小步与下一小步之间、以及每次操作结束时。给定目标 $(a,b)$，求**最少**需要多少次操作才能让机器人访问过它；永远不可能则输出 `-1`。多组数据：第一行组数 $t$，之后每组一行两个整数 $a,b$，逐组输出一个整数。

**约束**：

- $1 \le t \le 100$
- $0 \le a,b \le 1000$（注意 $b$ 也非负，负半轴不必处理，但推理会对一般情况成立）
- 每次操作**必然**让 $x$ 增加 $1$，而 $y$ 只改变 $\pm 1$，所以 $x$ 关于操作次数**严格单调**
- 答案上界为 $a+1 \le 1001$，`int` 足够；但用 `long long` 也不会有任何代价

## 2. 示例

官方样例共 $9$ 组：

```text
输入：
9
0 0
0 1
0 2
1 0
2 1
2 3
5 6
1000 999
1000 1000

输出：
0
1
-1
2
3
3
6
1001
1000
```

逐组说明：$(0,0)$ 是起点，$0$ 次操作即可；$(0,1)$ 在第 $1$ 次操作竖移后就被踩到，故为 $1$；$(0,2)$ 中 $x$ 从 $0$ 变成 $1$ 之前 $y$ 最多只能到 $\pm 1$，之后 $x$ 永远 $\ge 1$，所以不可能；$(1,0)$ 要先竖移到 $y=1$、右移、再竖移到 $y=0$，于是是在第 $2$ 次操作的竖移之后经过，答案 $2$。

再补一组自造示例（非官方），展示「奇偶不符但可达」与「高度超界」的差别：

```text
输入：
3
3 1
3 4
3 5

输出：
3
4
-1
```

$(3,1)$：$3-1$ 为偶数且 $1 \le 3$，第 $3$ 次操作结束即到达；$(3,4)$：$3-4$ 为奇数，只能落在「第 $4$ 次操作的竖移之后」；$(3,5)$：$b = a+2$，高度超出 $|y| \le a+1$，无解。

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是按定义搜状态：把「已完成的右移次数」当作层号，状态取 $(x, y, \text{是否已完成竖移})$，从 $(0,0)$ 出发做 BFS，直到第 $a+1$ 层。每层 $y$ 的取值范围是 $[-a-1, a+1]$，单组状态量约 $O(a^2) \approx 10^6$，$t=100$ 时是 $10^8$ 量级——C++ 勉强、Python 必然超时；而如果改成按 $2^k$ 枚举每步的上下选择，只能验证小数据，不能当作正解。

真正的问题是：暴力压根没利用「$x$ 单调」这条强约束。下面的分析会把它压成一次奇偶判断。

### 3.2 核心观察：x 单调递增 ⇒ 只有两个「候选时刻」

![x 单调递增，访问 (a,b) 只有两个候选时刻](images/cf2271_a_visit_window.svg)

**第一步：定位 $x$。** 第 $k$ 次操作结束时必有 $x = k$。而第 $i$ 次操作内部只有两个位置：竖移之后是 $(i-1, \cdot)$，右移之后是 $(i, \cdot)$。于是「站着时 $x = a$」只可能发生在：

- 第 $a$ 次操作**右移之后**：$x$ 恰好从 $a-1$ 跳到 $a$，此时 $y = y_a$；
- 第 $a+1$ 次操作**竖移之后**：$x$ 还没跳，仍是 $a$，此时 $y = y_{a+1}$。

注意第 $a+1$ 次操作右移之后 $x \ge a+1$，而 $x$ 单调不减，所以**再也回不到** $x=a$。这就是全部可能，不存在第三种时刻。

**第二步：刻画 $y_k$。** 设走完 $k$ 次操作后的高度为 $y_k$，则 $y_k$ 是 $k$ 个 $\pm 1$ 之和，因此

$$|y_k| \le k, \qquad y_k \equiv k \pmod 2 .$$

反过来这个条件也**充分**：取 $(k+y)/2$ 次向上、其余向下即可（$0 \le (k+y)/2 \le k$ 且为整数），路径中途高度不会越界（只需每步单调走向 $y$ 即可）。所以

$$y_k \text{ 可达} \iff |y| \le k \ \text{且}\ y \equiv k \pmod 2 .$$

**第三步：合并。** 目标 $(a,b)$ 可被访问当且仅当下面两条**至少一条**成立（$b \ge 0$，故 $|b| = b$）：

| 候选 | 条件 | 代价 |
|------|------|------|
| 第 $a$ 次操作结束 | $b \le a$ 且 $b \equiv a \pmod 2$ | $a$ |
| 第 $a+1$ 次操作竖移后 | $b \le a+1$ 且 $b \equiv a+1 \pmod 2$ | $a+1$ |

两条都不成立就输出 `-1`。

### 3.3 算法流程

![先卡高度上界，再判奇偶](images/cf2271_a_decision_flow.svg)

观察到「$b$ 的上界」和「奇偶」可以解耦，判定被压到三行：

1. 若 $b \ge a+2$：两个候选都给不出这么大的高度（上界分别是 $a$ 与 $a+1$），直接输出 `-1`。
2. 否则 $b \le a+1$。看 $a-b$ 的奇偶：
   - 偶数：则必有 $b \le a$（因为 $b = a+1$ 会让差为奇数），落在候选一，输出 $a$；
   - 奇数：则 $b \equiv a+1 \pmod 2$，落在候选二，输出 $a+1$。

即

$$\text{ans} = \begin{cases} -1, & b \ge a+2 \\ a, & b \le a+1 \ \text{且}\ (a-b) \text{ 为偶数} \\ a+1, & b \le a+1 \ \text{且}\ (a-b) \text{ 为奇数} \end{cases}$$

由于 $a+b$ 与 $a-b$ 同奇偶，写 `(a+b)%2` 判断也等价。

### 3.4 示例演算

![官方 9 组样例的走查表](images/cf2271_a_walkthrough.svg)

以 $(5,6)$ 为例：$b = 6 = a+1 \le a+1$，而 $5-6=-1$ 是奇数，故答案是 $a+1 = 6$。手工验证：前 $5$ 次全向上到 $(5,5)$（$y_5 = 5$ 满足 $|y|\le 5$、与 $5$ 同奇偶），第 $6$ 次操作先向上到 $(5,6)$ —— 这正是竖移之后，右移才把它带离 $x=5$，答案 $6$。

再看 $(1000,999)$：$999 \le 1001$，$1000-999 = 1$ 为奇数，故 $1001$。此时 $y_{1000}$ 只能取偶数，取 $y_{1000}=998$ 再竖移一步到 $999$，正好在 $(1000,999)$。

反面例子是 $(0,2)$：$b = 2 \ge a+2 = 2$，直接 `-1`。它虽然与 $a=0$ 同奇偶，但第 $0$ 次操作（即起点）只能提供高度 $0$，而第 $1$ 次操作竖移后 $x$ 已是 $0$、高度最多 $1$——两个候选都够不到 $2$。

## 4. 算法细节

1. **先判 $b > a+1$，再判奇偶**，顺序不能反。若先看奇偶，$(0,2)$ 会得到「偶数 ⇒ 答案 $0$」这种荒谬结果；高度上界是「硬约束」，必须最先过滤。
2. **奇偶判断的写法**：用 `(a - b) % 2 == 0`。在本题 $b \le a+1$ 的分支里这个差可能是 $-1$，C++ 的负数取模得到 $-1 \ne 0$，仍能正确判成「奇数」；但更稳妥的写法是 `((a - b) & 1) == 0`，或直接判 `(a + b) % 2`（两者同奇偶）。Python 的 `%` 天然非负，`(a-b) % 2` 直接可用。
3. **$a = 0$ 不需要特判**：公式自动给出 $(0,0) \to 0$、$(0,1) \to 1$、$(0,\ge 2) \to -1$，与「起点 + 第一步竖移终点」完全一致。
4. **$b$ 直接当 $|b|$ 用**：题面保证 $b \ge 0$；若换成允许负坐标的版本，把所有 $b$ 换成 $|b|$ 即可，因为可达高度集合关于 $0$ 对称。
5. **不要建 `vis` 数组、不要 BFS**：$a \le 1000$ 时开 $1000 \times 1000$ 的标记数组看似可行，但完全没有必要，而且多测清空的写法更容易出错。
6. **整数范围**：答案 $\le 1001$，`int` 足够；读入用 `int` 即可。写成 `long long` 也无害，但别把 `a-b` 放进 `unsigned`（负数会回绕成巨大正值，`% 2` 结果就不可信了）。
7. **多测无需清空状态，I/O 按规范提速**：全部变量都在循环体内定义，没有跨组共享的数组；$t \le 100$ 时瓶颈纯粹是进程启动，但仍加 `sync_with_stdio(false)`，Python 用 `sys.stdin.buffer.read().split()` 一次读完。

## 5. 正确性证明

**引理 1（$x$ 的轨迹）**：第 $k$ 次操作结束时机器人位于 $x = k$；第 $i$ 次操作内部（竖移之后、右移之前）位于 $x = i-1$。特别地，$x$ 在任何时刻都等于「已完成的右移次数」，随时间单调不减。

**证明**：对 $k$ 归纳。$k=0$ 时起点 $x=0$。每次操作的唯一改变 $x$ 的步骤是第 2 小步的 $(x,y)\to(x+1,y)$，它把 $x$ 加 $1$ 且发生在该次操作末尾，故第 $k$ 次操作结束后 $x=k$，而操作内部竖移后仍是上一次操作结束时的 $x = k-1 = i-1$。单调性由「每一步 $x$ 只增不减」直接得到。∎

**引理 2（$y_k$ 的充要刻画）**：走完 $k$ 次操作后的高度 $y$ 可达，当且仅当 $|y| \le k$ 且 $y \equiv k \pmod 2$；并且对每个满足条件的 $y$，存在一条走法在第 $k$ 次操作的**竖移之后**恰好位于 $(k-1, y)$。

**证明**：必要性：$y$ 是 $k$ 个 $\pm 1$ 之和，绝对值不超过 $k$，且模 $2$ 与 $k$ 同余。充分性：设 $u = (k+y)/2$，由 $|y| \le k$ 与同奇偶知 $u$ 是 $0..k$ 之间的整数；取前 $u$ 次向上、其余向下，则第 $k$ 次结束后高度为 $u - (k-u) = y$。并且这条走法第 $k$ 次的竖移终点就是 $(k-1, y)$，因为竖移恰好完成第 $k$ 个 $\pm 1$ 而右移尚未发生。∎

**引理 3（只有两个候选时刻）**：若机器人某时刻访问 $(a,b)$，则该时刻落在第 $i$ 次操作内且 $i \in \{a, a+1\}$；进一步 $i = a$ 时必是右移之后且 $b = y_a$，$i = a+1$ 时必是竖移之后且 $b = y_{a+1}$。

**证明**：设该时刻属于第 $i$ 次操作（含其末尾），由引理 1，此时的 $x$ 只能是 $i-1$（竖移后）或 $i$（右移后）。$x = a$ 故 $a \in \{i-1, i\}$，即 $i \ge a$；又 $i \le a$ 时只能 $i=a$（$x=a$ 最早在第 $a$ 次操作末尾出现）。若 $i = a$：$x=a$ 只能由本次的右移产生，此时高度就是走完 $a$ 次后的 $y_a$。若 $i = a+1$：右移后 $x = a+1 \ne a$，故只能在竖移之后，高度为走完 $a+1$ 次后的 $y_{a+1}$。∎

**引理 4（充分性）**：若 $b \le a$ 且 $b \equiv a \pmod 2$，则存在走法在第 $a$ 次操作结束时位于 $(a,b)$；若 $b \le a+1$ 且 $b \equiv a+1 \pmod 2$，则存在走法在第 $a+1$ 次操作竖移之后经过 $(a,b)$。

**证明**：第一种情形直接对 $k=a$ 用引理 2 的充分性（$y_a = b$ 可达）。第二种对 $k=a+1$ 用引理 2 的后半段：存在走法第 $a+1$ 次竖移之后位于 $(a+1-1, b) = (a,b)$。∎

**定理**：算法的输出等于最小操作次数；输出 `-1` 当且仅当无论如何都访问不到 $(a,b)$。

**证明**：分三种情形，与算法的三个分支一一对应。

- $(a-b)$ 为偶数且 $b \le a+1$：由「$b=a+1$ 时差为奇数」知此时其实 $b \le a$，由引理 4 用 $a$ 次操作可达；由引理 3 任何访问都发生在第 $a$ 或第 $a+1$ 次操作，$a$ 是两者中较小的，故最小值就是 $a$。
- $(a-b)$ 为奇数且 $b \le a+1$：候选一要求 $b \equiv a \pmod 2$，与奇数差矛盾，不可达；候选二条件恰为 $b \le a+1$ 且 $b \equiv a+1$，由引理 4 可达。由引理 3，候选只有 $a$（不可达）与 $a+1$（可达），最小值是 $a+1$。
- $b \ge a+2$：候选一要求 $b \le a$、候选二要求 $b \le a+1$，二者皆不满足；由引理 3 不存在其他访问时刻，故永远不可达，输出 `-1` 正确。三种情形互斥且穷尽（$b \le a+1$ 时差只能为奇或偶），且三种情形下算法都取到了候选中的最小值，故定理成立。∎

## 6. 复杂度分析

- **时间**：每组 $O(1)$——一次比较加一次取模。全部测试 $O(t) \le 100$ 次基本运算，相对 $1$ s 时限有 $10^7$ 以上余量（实测 $t=100$、全部 $a=b=1000$ 时 C++ 含进程启动约 $3$ ms，Python 约 $24$ ms，几乎全是解释器与进程开销）。
- **空间**：$O(1)$，只用几个标量，远低于 $256$ MB。

## 7. 参考代码

### C++17

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    if (!(cin >> t)) return 0;              // 空输入防护
    while (t--) {
        long long a, b;
        cin >> a >> b;
        long long ans;
        if (b > a + 1) {
            ans = -1;                       // 高度上界：|y_{a+1}| <= a+1 都够不到
        } else if ((a - b) % 2 == 0) {
            ans = a;                        // 第 a 次操作结束，右移之后落在 (a, b)
        } else {
            ans = a + 1;                    // 第 a+1 次操作竖移之后经过 (a, b)
        }
        cout << ans << '\n';
    }
    return 0;
}
```

import sys


def main() -> None:
    data = sys.stdin.buffer.read().split()
    if not data:
        return
    t = int(data[0])
    out = []
    for i in range(t):
        a = int(data[1 + 2 * i])
        b = int(data[2 + 2 * i])
        if b > a + 1:
            out.append("-1")
        elif (a - b) % 2 == 0:
            out.append(str(a))
        else:
            out.append(str(a + 1))
    sys.stdout.write("\n".join(out) + "\n")


main()

## 8. 边界情况与易错点

1. **$a = 0$**：只有起点 $(0,0)$ 与第一步竖移终点 $(0,1)$ 在 $x=0$ 上。公式自动给出 $0,1,-1$，不要额外写 `if (a == 0)` 的分支，容易漏掉 $(0,1) \to 1$ 或把 $(0,0)$ 判成 $-1$。
2. **$b = a+2$ 不是答案 $a$**：它与 $a$ 同奇偶，非常容易被「奇偶对上就行」的错觉误判成 $a$。正确做法是先卡 $b \le a+1$，本题最大的 WA 来源就在这里（样例里 $(0,2)$ 就是专门来卡这一点的）。
3. **$b = a+1$ 必然是 $a+1$**：差恒为 $1$（奇数），不可能落在候选一。
4. **奇偶不符 ≠ 无解**：$(1,0)$、$(2,1)$、$(5,6)$ 都是奇偶不符但可达，只是要多一次操作。把「$b \equiv a$」当成充要条件会漏掉一半答案。
5. **$b \le a$ 但奇偶不符时答案是 $a+1$ 而不是 $-1$**：例 $(1,0) \to 2$、$(3,2) \to 4$、$(5,2) \to 6$——起点太矮时只是「晚一步」，不是「走不到」；反之 $(3,1)$ 是偶数差，答案才是 $3$。
6. **负数取模**：$(a-b)$ 在 $b = a+1$ 时为 $-1$，C++ 里 `(-1) % 2` 得 $-1$，判定「是否为 $0$」仍然正确；但若有人写成 `(a-b) % 2 == 1` 就会漏掉这个分支，必须用 `== 0` 或 `((a-b) & 1) == 0`。
7. **无符号数陷阱**：把 $a-b$ 存进 `unsigned` 后 $-1$ 会变成 $2^{64}-1$，奇偶判断随之错乱——本题所有量都用有符号类型。
8. **多测输出格式与「不要去模拟」**：每组输出一个整数并换行，`-1` 不要写成 `−1`（U+2212）；也不要真去模拟 $1001$ 步——模拟要额外处理「竖移中间点」这个最易写错的时刻，直接套公式更短更快。

**延伸思考**：

1. **计数版本**：在候选一成立时，有多少条走法会在第 $a$ 次操作结束时恰好停在 $(a,b)$？答案为 $\binom{a}{(a+b)/2}$（选哪些步向上）；候选二同理为 $\binom{a+1}{(a+1+b)/2}$。把「最少步数」换成「方案数」时，判定条件不变，只多一个组合数。
2. **若坐标允许 $b<0$**：把 $b$ 换成 $|b|$，公式不变——可达高度集合关于 $0$ 对称；这也说明本题把 $b$ 限制在 $[0,1000]$ 只是为了避免负数输入。
3. **若两小步顺序互换（先右移再竖移）**：此时在 $x=a$ 上能踩到的高度是 $y_{a-1}$（第 $a$ 次操作右移后、竖移前）与 $y_a$（操作结束），两者奇偶不同、上界分别是 $a-1$ 与 $a$，合起来恰好覆盖 $b \le a$ 的全部高度——于是答案退化成「$b \le a$ 就是 $a$，否则 $-1$」，奇偶条件彻底消失。
4. **若一次操作允许上下左右任选一格**：问题退化成曼哈顿距离，与「奇偶 + 上界」的分析完全无关，可作为对照——本题的特殊性全部来自「右移强制且必发生」。
