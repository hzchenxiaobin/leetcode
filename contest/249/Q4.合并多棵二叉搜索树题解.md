# LeetCode 合并多棵二叉搜索树 题解

## 1. 题目概述

- **标题 / 题号**：合并多棵二叉搜索树（#1932，hard）
- **链接**：https://leetcode.cn/problems/merge-bsts-to-create-single-bst/
- **来源**：LeetCode 第 249 场周赛 Q4
- **难度**：困难
- **标签**：树、二叉搜索树、深度优先搜索、哈希表、重构与验证

**题意**：给定 $n$ 棵**互不相同**的二叉搜索树的根节点数组 `trees`，每棵树**至多 3 个节点**且不存在孙节点（根的直接孩子必为叶子）。一步操作：选定两个不同下标 $i, j$，若 `trees[i]` 的某个**叶节点**值等于 `trees[j]` 的**根值**，就把 `trees[j]` 整棵替换掉那片叶子，并从数组中移除 `trees[j]`。执行 $n - 1$ 次操作后若恰好剩下一棵**合法 BST**，返回其根节点；否则返回 `null`。

**约束**：

- $1 \le n \le 5 \times 10^4$
- 每棵树节点数 $\in [1, 3]$，输入数据的每个节点可能有子节点但不存在子节点的子节点
- `trees` 中不存在根值相同的两棵树
- 输入的每棵树都是合法 BST
- $1 \le \text{TreeNode.val} \le 5 \times 10^4$

> 💡 本题在本仓库另有[每日题解 1932](../../solution/1901-2000/1932_合并多棵二叉搜索树.md)：侧重面试问答与「拼接-验证」范式梳理。本篇按周赛复盘视角，聚焦「合并零自由度」的引理-定理化证明、贪心重构的确定性论证与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：trees = [[2,1],[3,2,5],[5,4]]
输出：[3,2,5,1,null,4]

解释：
Tree1 的左叶 2 命中 Tree0 的根值 → Tree0 整棵挂到左叶；
Tree1 的右叶 5 命中 Tree2 的根值 → Tree2 整棵挂到右叶。

      3
     / \
    2   5
   /   /
  1   4        ← 全局合法 BST ✓
```

**示例 2**

```text
输入：trees = [[5,3,8],[3,2,6]]
输出：[]

解释：只能把 [3,2,6] 挂到 Tree0 的左叶 3 上：

      5
     / \
    3   8
   / \
  2   6        ← 6 在 [3,2,6] 内部合法，但住进 5 的左子树后 6 ≥ 5 ✗
```

**示例 3**

```text
输入：trees = [[5,4],[3]]
输出：[]

解释：叶 4 无根可命中；单节点树 [3] 自身是叶，但下标必须不同，无法命中自己
—— 一步操作都做不了。
```

## 3. 解题思路

### 3.1 暴力思路：枚举操作顺序

最朴素的做法：把「选哪两棵、先合谁」当成搜索问题，枚举所有可能的操作顺序，逐个模拟到只剩一棵树后验证 BST。操作顺序最坏 $O(n!)$ 种，$n \le 5 \times 10^4$ 下天文数字，完全不可行。

> ⚠️ 更关键的洞察是：这个搜索空间根本是**假象**。根值互不相同 ⟹ 一片叶子的值至多命中**一棵**树的根，「挂哪棵树」没有任何选择。结合 §5 引理 2，每片叶子的**命运**都被数据唯一锁定，操作顺序只影响中间过程、不影响最终结构。于是整个问题塌缩成一次确定性的「贪心重构 + 全局验证」。

### 3.2 核心观察：合并是一张零自由度的拼图

![核心观察：叶值命中根值定位挂接，根值不在叶值集合定位最终根](images/wc249_q4_root_leaf_concept.svg)

**观察 1（哈希定位——「挂谁」一查便知）**：根值互异 ⟹ 建哈希表 `rootOf`（根值 → 树），遇到叶子值 $v$ 一查便知该挂哪棵树；查不到说明这片叶子只能保留原位。没有任何搜索与枚举。

**观察 2（最终根唯一——「谁是根」由排除法确定）**：一棵树被吸收，前提是它的根值出现在**当时**某片叶子上；而任何时刻的叶值都来自原始叶值集合（挂上去的树带来的也只是它自己的原叶值，见 §5 引理 1）。于是：

> **根值 ∉ 原始叶值集合的树永远不可能被吸收；若存在合法合并，最终根就是那棵唯一的候选树。** 候选有 0 棵或 ≥ 2 棵都直接判无解。

**观察 3（局部合法 ⇏ 全局合法——合并后必须整体验证）**：每棵输入树都是 BST，但拼接引入了**跨树祖先约束**——示例 2 中 6 在 `[3,2,6]` 内部合法，却因住进 5 的左子树而违规。合并完毕必须做一次**上下界递归**全局验证（承接 [98. 验证二叉搜索树](https://leetcode.cn/problems/validate-binary-search-tree/)）：左孩子继承 $(lo, val)$，右孩子继承 $(val, hi)$，全程严格不等号。

### 3.3 算法流程

![算法流程：定位候选根、贪心重构、检查使用数、全局验证](images/wc249_q4_algorithm_flow.svg)

1. **特判** $n = 1$：直接返回 `trees[0]`（输入保证合法；单节点树的根值在自身叶值集合中，通用流程会误判无候选）。
2. **建表与收集**：`rootOf`（根值 → 树）；`leafVals`（所有原始叶值，**单节点树的根本身就是叶**）。
3. **定位候选根**：扫描根值 $\notin$ `leafVals` 的树，恰一棵才继续（0 棵或 ≥ 2 棵返回 `null`），记为 $T^*$。
4. **DFS 贪心合并**：从 $T^*$ 出发，孩子是叶子且值命中**未用过**的树根 → 整棵挂上、标记已用、递归处理新子树的叶（合并链可以层层传递）。
5. **检查使用数**：`used` 大小 $= n$ 才说明 $n - 1$ 次操作全部发生，否则返回 `null`。
6. **上下界验证**：`ok(root, −∞, +∞)` 严格区间递归，通过才返回根。

### 3.4 示例演算

![示例演算：示例 1 逐步合并全部通过，示例 2 拼接后区间违规](images/wc249_q4_example_walkthrough.svg)

**示例 1**（上图上半）：候选根定位——叶值集合 $\{1, 2, 4, 5\}$，根值 $2, 5 \in$ 集合（会被吸收），唯根值 $3 \notin$ 集合，$T^* = [3,2,5]$。贪心重构：左叶 2 命中 Tree0 → 挂上；右叶 5 命中 Tree2 → 挂上；新叶 1、4 无命中保留。`used = {3,2,5}` 共 3 棵 ✓，逐点区间全部通过 → 返回根 3。

**示例 2**（上图下半）：只能做一次挂接，`used = n` 成立，但节点 6 的区间是 $(3, 5)$（祖先链 5 → 3 → 6），$6 \ge 5$ 违规 → 验证失败返回 `null`。单棵树各自合法、拼接后被跨树约束击毙——这正是观察 3 的体现。

## 4. 算法细节

1. **单节点树既是根也是叶**：收集叶值时 `!left && !right` 要把根自身计入（示例 3 中 `[3]` 贡献叶值 3）；候选根从起手就计入 `used`（计数口径：最终树包含全部 $n$ 棵树的根值）。
2. **叶子判定只需一层**：输入无孙节点，孩子是叶子 ⟺ 两个孙子指针皆空；挂接后新子树的叶子仍是同样形态，DFS 逐层处理「合并链」不遗漏（如 $[3,2,5] \to$ 挂 $[2,1] \to$ 继续检查 1 的孩子）。
3. **`used` 防重复挂接**：两片**同值叶**命中同一棵树时只能挂一次，另一片留叶，其重复值由验证阶段的严格区间捕获（见 §8 易错点 4）。
4. **上下界递归**：`ok(node, lo, hi)` 要求 $lo < val < hi$ **严格**成立，左子树传 $(lo, val)$、右子树传 $(val, hi)$。C++ 用 `long long` 配 `LLONG_MIN/MAX`（值域 $\le 5 \times 10^4$，无溢出）；Python 用 $\pm\infty$。
5. **迭代化防深递归**：合并链可以拉到 $O(n)$ 长（如 $[n, n-1]$、$[n-1, n-2]$、…… 首尾相挂，$n = 5 \times 10^4$ 时树高约 $n$），Python 默认递归上限会被击穿——参考代码的合并与验证都用**显式栈**替代递归；C++ 帧小，同样数据规模下递归一般无碍。
6. **挂接方向别搞反**：是把 `trees[j]` **整棵**挂到叶位置（叶节点被其根替换），不是把叶挂到树上。

## 5. 正确性证明

**引理 1（叶值封闭性）**：任意时刻，森林中所有叶值构成的多重集是原始叶值多重集的子集。

**证明**：对操作次数归纳。初始即原始集合。一步操作把叶 $v$ 替换为根值同为 $v$ 的树 $B$：移除叶值 $v$，加入 $B$ 自身的叶值——而 $B$ 是原始树，其叶值本就属于原始集合。故封闭性保持。∎

**推论（候选根判定）**：若存在合法合并，则恰有一棵树的根值 $\notin$ 原始叶值集合，且它就是最终根。

**证明**：$n - 1$ 次操作后幸存树的根从未被吸收，即其根值从未出现在当时任何叶子上，由引理 1 它不在原始叶值集合中——存在性得证。反之，根值 $\notin$ 原始叶值集合的树，由引理 1 在任何时刻都不可能被吸收（吸收要求根值出现在当时的叶子上）；若有**两棵**这样的树（$n \ge 2$），两棵都吸收不掉，无法归一，与存在合法合并矛盾——唯一性得证。∎

**引理 2（叶子命运唯一确定）**：设存在得到合法 BST $\mathcal{F}$ 的操作序列。对任何原始叶 $\ell$（值 $v$）：若存在根值为 $v$ 的原始树 $B$，则 $\ell$ 必被 $B$ 销毁；否则 $\ell$ 必存留为 $\mathcal{F}$ 的叶。

**证明**：$n - 1$ 次操作把除最终根外每棵树用掉恰好一次，故 $B$ 的根必落在某片值为 $v$ 的叶子上。反设 $\ell$ 未被 $B$ 销毁：能销毁 $\ell$ 的树必须根值 $= v$，根值互异故只能是 $B$，于是 $\ell$ 存留于 $\mathcal{F}$；而 $B$ 的根（值 $v$）也在 $\mathcal{F}$ 中，值 $v$ 出现两次，违反严格 BST 无重复值，矛盾。反之 $v$ 不是任何树的根值时，销毁 $\ell$ 的树不存在，$\ell$ 必存留。∎

**引理 3（贪心重构出唯一候选树）**：从候选根 $T^*$ 出发的贪心 DFS 重构出的树与 $\mathcal{F}$ 逐节点相同。

**证明**：$\mathcal{F}$ 中每棵原始树 $B \ne T^*$ 整体挂在某片被销毁的原始叶 $\ell$ 上，$\ell$ 属于某棵原始树 $U$（每个节点恰属一棵原始树）。对「$U$ 沿挂接链到 $T^*$ 的深度」作归纳：$T^*$ 是贪心起点（深度 0）。设深度为 $d$ 的 $U$ 已被贪心挂接：贪心会逐一检查 $U$ 的每片原始叶，遇到 $\ell$ 时其值为 $\mathrm{root}(B)$；由引理 2，**值为 $\mathrm{root}(B)$ 的原始叶全森林唯一**（若有两片，两片都须被 $B$ 销毁，而 $B$ 只挂一次），故此前 $B$ 不可能被贪心在别处用掉，贪心把 $B$ 整棵挂到 $\ell$ 并递归。按 $\mathcal{F}$ 的结构逐层归纳，每棵树都被贪心以同样方式、同样位置挂接，重构结果与 $\mathcal{F}$ 相同。∎

**引理 4（贪心挂接序列合法）**：贪心的挂接按执行序对应一列合法操作。

**证明**：把 $B$ 挂到 $U$ 的叶 $\ell$ 时：$U$ 已在 $T^*$ 的合并树中（贪心自顶向下逐层展开），$\ell$ 此刻仍是叶（每片叶只在被处理的那一刻决定命运，且只处理一次），$B$ 尚在数组中且与 $U$ 所在树下标不同（$B$ 未用过；且 $\ell$ 的值异于 $U$ 所在树的根值——BST 内孩子值严格小于或大于根值）。每次挂接后 $B$ 移出数组，挂接步数 $= |\text{used}| - 1 \le n - 1$。∎

**定理**：算法返回非空，当且仅当存在合法操作序列得到一棵合法 BST；且返回的树由输入唯一确定。

**证明**：

（⇐）设合法操作序列得到 $\mathcal{F}$。由推论，恰有一棵候选树且算法定位成功。由引理 3，贪心重构与 $\mathcal{F}$ 逐节点相同，故 `used` 覆盖全部 $n$ 个根值、上下界验证通过，算法返回 $\mathcal{F}$ 的根。

（⇒）算法返回非空时 `used` 恰含 $n$ 个根值，即贪心执行了 $n - 1$ 次挂接；由引理 4 它们构成合法操作序列，且验证通过说明结果是合法 BST。

唯一性：由引理 2 与引理 3，$\mathcal{F}$ 的结构被数据唯一锁定（每片叶子的命运都无选择），故答案树唯一——题面看似允许 $n!$ 种顺序，实际至多一棵结果树。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。建表 $O(n)$、收集叶值 $O(n)$（每棵树至多 3 节点）、定位根 $O(n)$；合并阶段每棵树至多被挂一次、每次只检查它至多 2 个孩子，$O(n)$；最终树节点数 $\le 3n - (n - 1) = 2n + 1$（每棵树 ≤ 3 节点、每次挂接销毁 1 个叶节点），验证 $O(n)$。
- **空间复杂度**：$O(n)$。`rootOf` 哈希表与 `leafVals` / `used` 集合共 $O(n)$；合并与验证的显式栈（或递归栈）最坏 $O(n)$（合并链深可达 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    TreeNode* canMerge(vector<TreeNode*>& trees) {
        int n = trees.size();
        if (n == 1) return trees[0];                 // 特判：单棵树直接返回

        unordered_map<int, TreeNode*> rootOf;        // 根值 -> 树
        for (TreeNode* t : trees) rootOf[t->val] = t;

        unordered_set<int> leafVals;                 // 所有原始叶值
        for (TreeNode* t : trees) {
            if (!t->left && !t->right) leafVals.insert(t->val); // 单节点树：根本身是叶
            if (t->left)  leafVals.insert(t->left->val);
            if (t->right) leafVals.insert(t->right->val);
        }

        TreeNode* root = nullptr;
        for (TreeNode* t : trees)
            if (!leafVals.count(t->val)) {
                if (root) return nullptr;            // 候选 >= 2：无解
                root = t;
            }
        if (!root) return nullptr;                   // 候选为 0：无解

        unordered_set<int> used{root->val};

        function<void(TreeNode*)> merge = [&](TreeNode* node) {
            if (!node) return;
            if (node->left && !node->left->left && !node->left->right) {
                int v = node->left->val;
                auto it = rootOf.find(v);
                if (it != rootOf.end() && !used.count(v)) {
                    used.insert(v);
                    node->left = it->second;         // 整棵挂上
                    merge(node->left);               // 继续处理新子树的叶
                }
            }
            if (node->right && !node->right->left && !node->right->right) {
                int v = node->right->val;
                auto it = rootOf.find(v);
                if (it != rootOf.end() && !used.count(v)) {
                    used.insert(v);
                    node->right = it->second;
                    merge(node->right);
                }
            }
        };
        merge(root);

        if ((int)used.size() != n) return nullptr;   // 有树始终没被吸收

        function<bool(TreeNode*, long long, long long)> ok =
            [&](TreeNode* node, long long lo, long long hi) -> bool {
            if (!node) return true;
            if (node->val <= lo || node->val >= hi) return false; // 严格区间
            return ok(node->left, lo, node->val) &&
                   ok(node->right, node->val, hi);
        };
        return ok(root, LLONG_MIN, LLONG_MAX) ? root : nullptr;
    }
};
```

### Python

```python
class Solution:
    def canMerge(self, trees: List[TreeNode]) -> Optional[TreeNode]:
        n = len(trees)
        if n == 1:
            return trees[0]                      # 特判：单棵树直接返回

        root_of = {t.val: t for t in trees}      # 根值 -> 树

        leaf_vals = set()                        # 所有原始叶值
        for t in trees:
            if not t.left and not t.right:       # 单节点树：根本身是叶
                leaf_vals.add(t.val)
            if t.left:
                leaf_vals.add(t.left.val)
            if t.right:
                leaf_vals.add(t.right.val)

        root = None
        for t in trees:
            if t.val not in leaf_vals:
                if root:
                    return None                  # 候选 >= 2：无解
                root = t
        if not root:
            return None                          # 候选为 0：无解

        used = {root.val}

        stack = [root]                           # 显式栈：合并链可达 O(n) 深
        while stack:
            node = stack.pop()
            for side in ("left", "right"):
                child = getattr(node, side)
                if child is None or child.left or child.right:
                    continue                     # 只在叶子位置挂接
                v = child.val
                if v in root_of and v not in used:
                    used.add(v)
                    new = root_of[v]
                    setattr(node, side, new)     # 整棵挂上
                    stack.append(new)            # 继续处理新子树的叶

        if len(used) != n:
            return None                          # 有树始终没被吸收

        check = [(root, float("-inf"), float("inf"))]   # 显式栈防深递归
        while check:
            node, lo, hi = check.pop()
            if not node:
                continue
            if not lo < node.val < hi:
                return None
            check.append((node.left, lo, node.val))
            check.append((node.right, node.val, hi))
        return root
```

> 💡 两版逻辑对应：特判 → 建表收叶 → 定位候选根 → 贪心合并（C++ 递归 / Python 显式栈）→ 使用数检查 → 上下界验证（C++ 递归 / Python 显式栈）。Python 版全程迭代，$n = 5 \times 10^4$ 的长合并链下不碰递归上限。

## 8. 边界情况与易错点

1. **$n = 1$ 必须特判**：单节点树时根值在自身叶值集合中，通用流程会误判「无候选」返回 `null`，而正确答案是 `trees[0]` 本身。
2. **单节点树既是根又是叶**：收集叶值时漏掉 `!left && !right` 的根自身，候选判定整体出错（示例 3 的 `[3]` 贡献叶值 3）；但它**不能命中自己**——操作要求两个不同下标。
3. **候选 0 棵或 ≥ 2 棵都要返回 `null`**：0 棵说明每棵树都「可能被吸收」，没有树能当根；≥ 2 棵说明有两棵谁都吸收不掉的树，无法归一（如 `[[2,1],[4,3]]`）。
4. **同值双叶陷阱（本题最阴的坑）**：两片叶子的值相同且都命中某棵树的根时，该树只能挂一次，另一片留叶 → 最终树出现重复值，由**严格区间验证**捕获（如 `[[4,2,6],[2,1,3],[6,2,7]]`：`[2,1,3]` 挂在 4 的左叶，`[6,2,7]` 挂在右叶后，其左叶 2 落在 $(4,6)$ 之外）。不要试图在合并阶段「聪明地」处理——留给验证阶段即可。
5. **合并方向别搞反**：`node->left = rootOf[v]` 是把整棵树替换到叶位置；写反成 `rootOf[v]->left = node->left` 结构全错。
6. **递归深度**：构造 `[[2,1],[3,2],[4,3],…]` 型首尾相挂可让树高接近 $n$；Python 递归版本会撞默认递归上限（`RecursionError`），用显式栈或提高上限，参考代码已迭代化；C++ 帧小通常无碍，但深链下也值得留意。
7. **严格不等号与值域**：验证必须 `lo < val < hi` 严格成立（BST 定义无重复值）；C++ 边界用 `LLONG_MIN/MAX` 且比较用 `long long`，值 $\le 5 \times 10^4$ 无溢出风险。
8. **`used` 检查别忘**：合并完不检查使用数，会把「部分树没挂上」的残树当答案返回；这正是「$n - 1$ 次操作全部执行」的题面要求所在。

**延伸思考**：

- **去掉「每棵树 ≤ 3 节点」的约束怎么办？** 收集叶值需 DFS 到真正叶子；挂接位置可能是任意深度，需要维护父指针或改用「叶值 → 父节点」哈希定位后逐层替换。整体仍是 $O(N)$（$N$ 为总节点数），但实现复杂度显著上升。
- **为什么答案唯一？** §5 定理末段：根值互异把「挂谁」锁死，重复值禁忌把「挂不挂」锁死——操作顺序是纯粹的表象。这也是本题作为 Hard 却能 $O(n)$ 拿下的根本原因：**看似搜索问题，实为确定性问题**。
- **如果允许操作少于 $n - 1$ 次（不必合并成一棵）？** 问题变成「森林中每棵树是否合法」的平凡判定，失去拼图结构；若允许丢弃某些树，则贪心 + 验证需改为「枚举保留集合」，回到组合问题——题面「执行 $n - 1$ 次」的强制约束正是确定性的来源。
