# LeetCode 图片平滑器 题解

## 1. 题目概述

- **标题 / 题号**：图片平滑器（#661，easy）
- **链接**：https://leetcode.cn/problems/image-smoother/
- **来源**：LeetCode 第 46 场周赛 Q1
- **难度**：简单
- **标签**：数组，矩阵

**题意**：给定 $m \times n$ 的整数灰度矩阵 `img`，对每个格子 $(i,j)$ 取「它自己 + 四周至多 8 个邻居」这 $3 \times 3$ 窗口内**实际存在**的格子，求算术平均并**向下取整**，写回一个同尺寸的新矩阵。落在图像外的位置既不参与求和，也不计入分母——这正是本题唯一的坑。

**约束**：

- $1 \le m, n \le 200$
- $0 \le \text{img}[i][j] \le 255$
- 返回矩阵与输入同尺寸

$200 \times 200$ 只有 $4 \times 10^4$ 个格子，签到题的难点从来不是复杂度，而是**边界的分类**：四个角、四条边、内部的格子各有不同的分母，再叠加 $m = 1$ 或 $n = 1$ 的退化形状。若把分母写死成 $9$，示例 2 的角格就会算成 $550/9 = 61$ 而不是 $137$。

## 2. 示例

**示例 1**

```text
输入：img = [[1,1,1],[1,0,1],[1,1,1]]
输出：[[0,0,0],[0,0,0],[0,0,0]]
解释：角上 4 格之和为 3，平均 0.75 → 0；
      边上 6 格之和为 5，平均 0.833… → 0；
      中心 9 格之和为 8，平均 0.888… → 0。
```

**示例 2**

```text
输入：img = [[100,200,100],[200,50,200],[100,200,100]]
输出：[[137,141,137],[141,138,141],[137,141,137]]
解释：角格 (100+200+200+50)/4 = 137.5 → 137；
      边格 850/6 = 141.67 → 141；
      中心 1250/9 = 138.89 → 138。
```

**补充示例（非官方，窄图退化情形）**

```text
输入：img = [[1,2,3]]
输出：[[1,2,2]]
解释：只有一行时，窗口只有 1 行 × 2 列或 1 行 × 3 列；
      (0,0) 是 (1+2)/2 = 1，(0,1) 是 (1+2+3)/3 = 2，(0,2) 是 (2+3)/2 = 2（2.5 向下取整）。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是：对每个格子 $(i,j)$，把整幅图的 $m \times n$ 个格子全扫一遍，用切比雪夫距离 $\max(\lvert r-i \rvert, \lvert c-j \rvert) \le 1$ 判断它是否属于窗口，是则累加。

复杂度 $O(m^2 n^2)$，代入 $m = n = 200$ 是 $1.6 \times 10^9$ 次判断，必然超时。但这个暴力版给出了正确的**语义定义**：窗口内的格子就是「行列偏移都不超过 1 的格子」。既然如此，就没必要去扫描整幅图——**满足条件的相对偏移只有 $9$ 组**，直接枚举它们即可：

$$(\Delta i, \Delta j) \in \{-1,0,1\} \times \{-1,0,1\}$$

这一步把 $O(m^2 n^2)$ 砍到 $O(9mn)$，是本题的第一层优化。

### 3.2 核心观察：分母等于行区间长度乘以列区间长度

![有效格子数只有 4/6/9 三种](images/wc46_q1_window_concept.svg)

枚举 9 个偏移量时还要为每个位置写越界判断，代码里有 $9$ 个 `if`，又长又容易写错。换一个角度：**行偏移与列偏移各自的合法范围就是一个独立区间**。

对格子 $(i,j)$，合法的行下标满足 $0 \le r \le m-1$ 且 $i-1 \le r \le i+1$，两者取交集：

$$r \in [\max(0, i-1),\ \min(m-1, i+1)] = [r_{\text{lo}},\ r_{\text{hi}}]$$

列同理得到 $[c_{\text{lo}}, c_{\text{hi}}]$。窗口内的格子恰是这两个区间的**笛卡尔积**，于是

$$\text{分母} = (r_{\text{hi}} - r_{\text{lo}} + 1) \times (c_{\text{hi}} - c_{\text{lo}} + 1)$$

由此立刻读出三种情况（$m, n \ge 2$ 时）：

| 格子的位置 | 行区间长度 | 列区间长度 | 分母 |
|---|---|---|---|
| 四个角 | 2 | 2 | 4 |
| 四条边（非角） | 2 | 3 | 6 |
| 内部 | 3 | 3 | 9 |

注意 $m = 1$ 时行区间恒为 $[0,0]$，长度为 1，公式自动给出 $1 \times 2 = 2$ 或 $1 \times 3 = 3$——**不需要为窄图写任何特判**。这正是「先算区间、再乘长度」比「数 9 个 `if` 命中几次」更稳的原因。

> 💡 一句话模板：**窗口类问题先求「裁剪后的区间」，分母、边界、循环上下界由区间自然导出**。

### 3.3 算法流程

![算法流程：两重循环 + 区间钳位](images/wc46_q1_scan_flow.svg)

1. 取 $m = \lvert \text{img} \rvert$、$n = \lvert \text{img}[0] \rvert$，新建 $m \times n$ 的全 0 结果矩阵 `res`（**不能原地修改**，理由见 §4）。
2. 外层枚举行 $i$，先算出 $r_{\text{lo}} = \max(0, i-1)$、$r_{\text{hi}} = \min(m-1, i+1)$。
3. 内层枚举列 $j$，同样算出 $c_{\text{lo}} = \max(0, j-1)$、$c_{\text{hi}} = \min(n-1, j+1)$。
4. 在 $[r_{\text{lo}}, r_{\text{hi}}] \times [c_{\text{lo}}, c_{\text{hi}}]$ 上双重循环累加 `sum`，最多访问 9 个格子。
5. `res[i][j] = sum / ((r_hi - r_lo + 1) * (c_hi - c_lo + 1))`，整数除法即向下取整。
6. 两重循环结束后返回 `res`。

因为 $r_{\text{lo}}, r_{\text{hi}}$ 只依赖 $i$，实现上把它们提到内层循环之外，于是每行只算一次，循环体内只剩列的钳位（每个格子两次 `max`/`min`）。

### 3.4 示例演算

![示例 2 的三角色走查](images/wc46_q1_walkthrough.svg)

以示例 2 的矩阵为例，三类格子各取一个：

| 格子 | 类别 | 窗口内格子 | 和 | 分母 | 平均值 | 取整 |
|---|---|---|---|---|---|---|
| $(0,0)$ | 角 | 4 | 550 | 4 | 137.5 | 137 |
| $(0,1)$ | 边 | 6 | 850 | 6 | 141.67 | 141 |
| $(1,1)$ | 内部 | 9 | 1250 | 9 | 138.89 | 138 |

按对称性，四个角的结果相同（137），四条边的结果相同（141），中心单独一个（138），最终输出正是 `[[137,141,137],[141,138,141],[137,141,137]]`，与官方答案一致。

再验证窄图 `[[1,2,3]]`：$(0,0)$ 的行区间 $[0,0]$、列区间 $[0,1]$，分母 $1 \times 2 = 2$，和 $1+2 = 3$，$3 // 2 = 1$；中心格列区间 $[0,2]$，分母 3，和 6，得 2；末格 $5 // 2 = 2$。输出 `[[1,2,2]]`——全程没有出现任何针对「只有一行」的特判。

## 4. 算法细节

1. **钳位而不是逐点判越界**：`max(0, i-1)`、`min(m-1, i+1)` 一次得到合法区间，循环体内不再需要任何 `if`，也就没有「忘记判断某个方向」的可能。
2. **分母必须由区间长度算出**：写死 $9$ 在边界上必错，写死 $4/6/9$ 的查表法在 $m = 1$ 或 $n = 1$ 时同样错。只有区间长度相乘 $(r_{\text{hi}}-r_{\text{lo}}+1)(c_{\text{hi}}-c_{\text{lo}}+1)$ 才能对所有输入统一正确。
3. **整数范围**：单个和最大 $9 \times 255 = 2295$，分母最大 9，`int` 绰绰有余，不需要 `long long`；这一点和「二维前缀和」版本不同（前缀和最大 $200 \times 200 \times 255 \approx 1.02 \times 10^7$，仍在 `int` 内，但接近千万级）。
4. **向下取整的实现**：所有元素非负，C++ 的整数除法向零截断与 `floor` 等价，Python 的 `//` 本身就是 `floor`。若题目允许负数，C++ 侧必须改用 `floor((double)sum / cnt)`，否则 $(-3)/4$ 会得到 $0$ 而不是 $-1$。
5. **不能原地修改**：第 $(i,j)$ 格的结果依赖 $(i+1, \cdot)$ 等尚未处理的原值；若写回 `img` 本身，后面的格子会用到已被平滑的值。必须新开矩阵（$O(mn)$ 额外空间），或者在需要原地时把结果编码进高位（如 `sum << 8 | count`）后再统一还原。
6. **Python 的常数优化**：外层用 `row = img[r]` 取行引用、把 `m - 1`、`n - 1` 提到循环外，能省掉大量属性与下标重复计算；用生成器写 `sum(img[r][c] for ...)` 亦可，但四层生成器在 $4\times10^4$ 个格子上会明显慢于显式循环。
7. **接口签名**：C++ 为 `vector<vector<int>> imageSmoother(vector<vector<int>>& img)`，Python 为 `def imageSmoother(self, img: list[list[int]]) -> list[list[int]]`，参数名都是 `img`，返回同尺寸新矩阵。

## 5. 正确性证明

**引理 1（窗口刻画）**：固定 $(i,j)$ 后，算法枚举的下标集合

$$S = \{(r,c) \mid r_{\text{lo}} \le r \le r_{\text{hi}},\ c_{\text{lo}} \le c \le c_{\text{hi}}\}$$

恰等于 $\{(r,c) \mid 0 \le r < m,\ 0 \le c < n,\ \lvert r-i \rvert \le 1,\ \lvert c-j \rvert \le 1\}$。

**证明**：$r$ 的取值是两条约束 $0 \le r \le m-1$ 与 $i-1 \le r \le i+1$ 的交集，而整数区间的交集仍是区间，端点取各自端点的 $\max$ 与 $\min$，即 $[\max(0,i-1), \min(m-1,i+1)]$。列同理。由于 $S$ 中行、列条件互相独立，$S$ 就是两个合法下标集合的笛卡尔积，正是原式的定义集合。∎

**引理 2（分母即格数）**：$\lvert S \rvert = (r_{\text{hi}}-r_{\text{lo}}+1)(c_{\text{hi}}-c_{\text{lo}}+1)$。

**证明**：$S$ 是矩形区域，行数 $r_{\text{hi}}-r_{\text{lo}}+1 \ge 1$（因 $r_{\text{lo}} \le i \le r_{\text{hi}}$），列数同理，矩形格数等于两方向长度之积。例如 $i = 0$ 时 $r_{\text{lo}} = 0$、$r_{\text{hi}} = \min(m-1,1)$，$m \ge 2$ 时行数 2，$m = 1$ 时行数 1，公式两种情形都成立。∎

**引理 3（取整正确）**：对所有非负整数 `sum` 与正整数 `cnt`，代码中的 `sum / cnt`（C++）与 `sum // cnt`（Python）都等于 $\lfloor \text{sum} / \text{cnt} \rfloor$。

**证明**：$\text{sum} \ge 0$、$\text{cnt} > 0$ 时带余除法给出 $\text{sum} = q \cdot \text{cnt} + r$，其中 $0 \le r < \text{cnt}$，故 $q = \lfloor \text{sum}/\text{cnt} \rfloor$。C 系语言在此情形下返回 $q$（向零截断等于向下取整），Python 的 `//` 直接定义为向下取整。∎

**定理**：算法返回的矩阵第 $(i,j)$ 项等于题面定义的平均灰度。

**证明**：由引理 1，累加恰好覆盖窗口内全部且仅这些格子，且每个格子只累加一次（双重循环下标互不相同），故 `sum` 等于这些格子的灰度之和；由引理 2，分母等于格子数；由引理 3，商即该平均值的下取整。各格独立计算、互不干扰（结果写入新矩阵），故整个矩阵与定义逐项相等。∎

## 6. 复杂度分析

- **时间**：$O(9mn) = O(mn)$。每个格子访问至多 $9$ 个邻居、做 $9$ 次加法与 $1$ 次除法，均为常数；两次区间钳位也是 $O(1)$。$m = n = 200$ 时约 $3.6 \times 10^5$ 次加法，实测 Python 约 $0.04$ 秒、C++ 可忽略。
- **空间**：$O(mn)$，用于输出矩阵（题面要求返回同尺寸新矩阵，这部分不可避免）；除输出外只用了常数个下标变量，额外空间 $O(1)$。若改用二维前缀和，额外空间升为 $O(mn)$（但时间常数与核大小解耦，见「延伸思考」）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> imageSmoother(vector<vector<int>>& img) {
        int m = img.size(), n = img[0].size();
        vector<vector<int>> res(m, vector<int>(n, 0));
        for (int i = 0; i < m; i++) {
            int rLo = max(0, i - 1), rHi = min(m - 1, i + 1);
            for (int j = 0; j < n; j++) {
                int cLo = max(0, j - 1), cHi = min(n - 1, j + 1);
                int sum = 0;
                for (int r = rLo; r <= rHi; r++)
                    for (int c = cLo; c <= cHi; c++)
                        sum += img[r][c];
                int cnt = (rHi - rLo + 1) * (cHi - cLo + 1);   // 4 / 6 / 9（窄图更小）
                res[i][j] = sum / cnt;                          // 非负整数除法即向下取整
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def imageSmoother(self, img: list[list[int]]) -> list[list[int]]:
        m, n = len(img), len(img[0])
        res = [[0] * n for _ in range(m)]
        for i in range(m):
            r_lo, r_hi = max(0, i - 1), min(m - 1, i + 1)
            for j in range(n):
                c_lo, c_hi = max(0, j - 1), min(n - 1, j + 1)
                total = 0
                for r in range(r_lo, r_hi + 1):
                    row = img[r]                      # 取行引用，减少下标开销
                    for c in range(c_lo, c_hi + 1):
                        total += row[c]
                res[i][j] = total // ((r_hi - r_lo + 1) * (c_hi - c_lo + 1))
        return res
```

## 8. 边界情况与易错点

1. **把分母写成 9**：示例 1 里角格的和是 3，$3/9 = 0$ 恰与答案相同，看起来「过了」，但示例 2 立刻暴露：$550/9 = 61 \ne 137$。分母一定要用有效格数。
2. **$m = 1$ 或 $n = 1$**：此时「边格」只有 3 格，「角格」只有 2 格，$1 \times 1$ 的图更是退回 1 格。查表法（角 4 / 边 6 / 内部 9）在这里全错，只有区间乘积写法天然正确。
3. **原地修改**：把结果写回 `img` 会让后面的格子吃到已平滑的值，整幅图变成「逐格传播」的错误结果。必须新开矩阵。
4. **四舍五入 vs 向下取整**：$137.5$ 的正确答案是 $137$，用 `round` 会得到 $138$；示例 1 的 $0.75 \to 0$ 同样排除了四舍五入和向上取整。
5. **用 padding 补零却忘了分母**：在四周补一圈 $0$ 可以让循环不用钳位，但补出来的 $0$ 会被算进平均数（$550/9$ 式的错误）。要补就必须再补一张 mask 统计有效格数，反而更复杂。
6. **下标越界**：直接在循环里写 `img[i-1][j-1]` 而不钳位，$i = 0$ 时就会越界（C++ 是未定义行为，Python 会取到末行，产生「看似正确实则错误」的环状结果）。
7. **返回输入对象本身**：Python 里若直接 `return img` 并在其上修改，返回值虽然「碰巧」对，但语义上是原地篡改，评测外的复用场景会出错。

**延伸思考**：

- **核变大到 $k \times k$**：枚举法退化为 $O(k^2 mn)$，$k$ 接近 $m$ 时不可接受。此时用二维前缀和，单格 $O(1)$：

  ![二维前缀和：容斥求子矩阵和](images/wc46_q1_prefix_sum.svg)

  记 $P[i][j]$ 为左上角 $i \times j$ 子矩阵的和，则

  $$\text{sum}(r_1,c_1,r_2,c_2) = P[r_2+1][c_2+1] - P[r_1][c_2+1] - P[r_2+1][c_1] + P[r_1][c_1]$$

  分母仍是 $(\text{行数}) \times (\text{列数})$，随边界收缩的写法一模一样，总复杂度 $O(mn)$。
- **均值核是可分离的**：$k \times k$ 窗口的和可以先按行求长度 $k$ 的滑动和、再按列求一次，做到 $O(k\,mn)$ 甚至 $O(mn)$（配合前后缀差分）。取整不会因此出错——正整数恒等式 $\lfloor \lfloor S/a \rfloor / b \rfloor = \lfloor S/(ab) \rfloor$ 保证两阶段相除与一次相除结果相同；**但要存「和」而不是「平均值」**：边缘行的有效格数可能互不相同，此时各行的平均值不能再直接平均。
- **边界策略**：除了「忽略缺失格子」，工程上还有 zero padding（补 0，会拉暗边缘）与 replicate padding（复制边缘像素，分母恒为 $k^2$，得到的是另一个滤波器）。两者在图像处理里语义完全不同，本题属于前者。
- **若要求四舍五入或保留浮点**：把结果类型改成 `double`，用 `floor(sum / cnt + 0.5)` 或 `round`，此时不能再依赖整数除法的截断；同时要留意累加顺序不同带来的浮点误差。
