# LeetCode 一最多的行 题解

## 1. 题目概述

- **标题 / 题号**：一最多的行（#2643，easy）
- **链接**：https://leetcode.cn/problems/row-with-maximum-ones/
- **来源**：LeetCode 第 341 场周赛 Q1
- **难度**：简单
- **标签**：数组、矩阵

**题意**：给定 $m \times n$ 的二进制矩阵 `mat`，找出 **1 的个数最多**的行，返回 `[行下标, 该行 1 的个数]`。若多行的 1 个数并列最多，返回**行下标最小**的那一行。

**约束**：

- `m == mat.length`，`n == mat[i].length`
- `1 <= m, n <= 100`
- `mat[i][j]` 为 `0` 或 `1`

## 2. 示例

**示例 1**

```text
输入：mat = [[0,1],[1,0]]
输出：[0,1]
解释：两行 1 的个数相同（各 1 个），返回下标最小的行 0。
```

**示例 2**

```text
输入：mat = [[0,0,0],[0,1,1]]
输出：[1,2]
解释：下标 1 的行有 2 个 1，最多。
```

**示例 3**

```text
输入：mat = [[0,0],[1,1],[0,0]]
输出：[1,2]
解释：下标 1 的行有 2 个 1，最多。
```

## 3. 解题思路

### 3.1 暴力思路：先计数再排序

最直接的做法：先逐行统计 1 的个数得到数组 $\mathrm{cnt}$，再按「1 的个数降序、下标升序」排序，取第一名，复杂度 $O(mn + m \log m)$。

这能过（$mn \le 10^4$），但排序是多余的——我们只需要**最大值及其首次出现的位置**，一次线性扫描即可。而且任何正确算法都必须读完全部 $mn$ 个元素（1 可能出现在任意位置），所以 $O(mn)$ 本身就是复杂度下界，一趟扫描已是理论最优。

### 3.2 核心观察：打擂台（严格大于才换擂主）

关键观察只有两点：

1. **行与行独立**：第 $i$ 行的答案只取决于该行 1 的个数 $\mathrm{cnt}_i$，问题退化为「在数组 $\mathrm{cnt}$ 中找最大值及首次出现的下标」。
2. **并列取小下标 $\iff$ 严格大于才更新**：按行下标从小到大扫描，仅当 $\mathrm{cnt}_i > \mathrm{best}$ 时才更新擂主。等于时不更新，第一个达到最大值的行天然被保留。

于是「1 最多」和「下标最小」两个需求被一个「严格大于」的更新条件同时满足，无需任何额外比较。

![打擂台扫描示意](images/row_max_ones_scan.svg)

> 💡 **一句话总结**：`max` + 首次出现的 `argmax` = 顺序扫描 + 严格大于才更新，一趟完成。

### 3.3 算法流程

```text
1. 初始化 ans = 0，best = -1   // 擂主：当前最多 1 的个数及其行下标
2. 从上到下逐行扫描：
     cnt = 当前行 1 的个数（内层顺带累加，无需计数数组）
     若 cnt > best：best = cnt，ans = i
3. 返回 [ans, best]
```

### 3.4 示例演算

用一个比官方示例更有信息量的矩阵（同时包含「并列」与「刷新擂主」两种情形）走查：

$$\mathtt{mat} = \begin{bmatrix} 0 & 1 & 0 & 1 \\ 1 & 1 & 0 & 0 \\ 0 & 1 & 1 & 1 \end{bmatrix}$$

- 初始：`best = -1`，`ans = 0`
- $i = 0$：`cnt = 2`，$2 > -1$ ✓ → 更新 `best = 2`，`ans = 0`
- $i = 1$：`cnt = 2`，$2 > 2$ ✗ → **不更新**（并列，保留下标更小的行 0）
- $i = 2$：`cnt = 3`，$3 > 2$ ✓ → 更新 `best = 3`，`ans = 2`

返回 `[2, 3]`。

![示例演算走查表](images/row_max_ones_walkthrough.svg)

## 4. 算法细节

1. **计数内联**：不必先建计数数组，内层循环直接累加 `mat[i][j]`（元素只有 0/1，加的就是布尔值），空间降到 $O(1)$。
2. **更新条件必须是严格大于**：`cnt > best`。若误写成 `cnt >= best`，并列时会保留**最大**下标，与题意相反。
3. **初始化**：`best = -1` 保证第一行必然触发一次更新（$\mathrm{cnt} \ge 0 > -1$）；由于 $m \ge 1$，结束时 `ans` 必然有效。
4. **返回值顺序**：题目要求 `[行下标, 1 的个数]`，先下标后计数。

## 5. 正确性证明

**引理 1**：扫描结束后，`best` 等于 $\max_i \mathrm{cnt}_i$。

**证明**：对已处理行数 $k$ 归纳，不变式为 $P(k)$：处理完前 $k$ 行后 $\mathrm{best} = \max(-1, \mathrm{cnt}_0, \ldots, \mathrm{cnt}_{k-1})$。$k = 0$ 时 `best = -1` 成立。设 $P(k)$ 成立，处理第 $k$ 行：若 $\mathrm{cnt}_k > \mathrm{best}$，则 `best` 更新为 $\mathrm{cnt}_k$，恰为前 $k+1$ 行的最大值；否则 $\mathrm{cnt}_k \le \mathrm{best}$，最大值不变，两种情况均使 $P(k+1)$ 成立。又 $\mathrm{cnt}_i \ge 0 > -1$，故扫描全部 $m$ 行后 $\mathrm{best} = \max_i \mathrm{cnt}_i$。∎

**定理**：算法返回的 `ans` 是 1 的个数最多的行中下标最小者，`best` 即该行的 1 的个数。

**证明**：设 $\mathrm{cnt}$ 的最大值首次出现在下标 $p$。处理到 $i = p$ 时，擂主为前 $p$ 行的最大值，因 $p$ 是首次出现，前 $p$ 行的 $\mathrm{cnt}$ 均**严格小于** $\mathrm{cnt}_p$，故 $\mathrm{cnt}_p > \mathrm{best}$ 成立，触发更新，`ans = p`。对任意 $i > p$，有 $\mathrm{cnt}_i \le \mathrm{cnt}_p = \mathrm{best}$，不满足严格大于，不再更新。结合引理 1，返回 `[p, cnt_p]`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \cdot n)$。每个矩阵元素在内层循环中恰好被访问一次；$m, n \le 100$ 时至多 $10^4$ 次基本运算。
- **空间复杂度**：$O(1)$。仅维护 `ans`、`best`、`cnt` 三个标量（不计输入矩阵）。

由于任何算法都必须读取全部 $mn$ 个元素才能确定答案，$O(mn)$ 已是渐近最优，不存在更快的做法。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> rowAndMaximumOnes(vector<vector<int>>& mat) {
        int m = mat.size(), n = mat[0].size();
        int ans = 0, best = -1;
        for (int i = 0; i < m; i++) {
            int cnt = 0;
            for (int j = 0; j < n; j++) cnt += mat[i][j];
            if (cnt > best) {
                best = cnt;
                ans = i;
            }
        }
        return {ans, best};
    }
};
```

### Python

```python
class Solution:
    def rowAndMaximumOnes(self, mat: List[List[int]]) -> List[int]:
        ans, best = 0, -1
        for i, row in enumerate(mat):
            cnt = sum(row)
            if cnt > best:
                best, ans = cnt, i
        return [ans, best]
```

## 8. 边界情况与易错点

1. **并列时取下标最小**：更新条件必须写**严格大于** `cnt > best`。写成 `>=` 会在并列时留下**最大**下标，官方示例 1（两行各 1 个 1）会错误地返回 `[1,1]`。
2. **全 0 矩阵**：所有行 `cnt = 0`，返回 `[0, 0]`。`best = -1` 的初始化使首行必然上擂台，天然覆盖此情形，无需特判。
3. **返回顺序**：`[行下标, 1 的个数]`，先下标后个数，别写反。
4. **单行矩阵**（$m = 1$）：返回 `[0, 该行 1 的个数]`，算法无需特判。
5. **行列别搞反**：外层枚举行、内层在一行内累计；行列交换会把「每行 1 的个数」数成「每列 1 的个数」。
6. **无溢出风险**：`cnt <= n <= 100`，`int` 足够，无需 `long long`。

**延伸思考**：

- 若每行**非降有序**（形如 `0...0 1...1`），每行 1 的个数可二分查找在 $O(\log n)$ 内求出，总复杂度降为 $O(m \log n)$——正是 1351 题的做法。
