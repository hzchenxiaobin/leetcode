# LeetCode 使数组互补的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组互补的最少操作次数（#1674，medium）
- **链接**：https://leetcode.cn/problems/minimum-moves-to-make-array-complementary/
- **来源**：LeetCode 第 217 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、前缀和（差分）

**题意**：给定长度为**偶数** $n$ 的整数数组 `nums` 和整数 `limit`。每次操作可将 `nums` 中任意一个数替换为 $[1, \text{limit}]$ 内的另一个整数。若对所有下标 $i$ 都有 $\text{nums}[i] + \text{nums}[n-1-i]$ 等于同一个值，则数组**互补**。求使数组互补的最少操作次数。

**约束**：

- $2 \le n \le 10^5$，且 $n$ 为偶数
- $1 \le \text{nums}[i] \le \text{limit} \le 10^5$（元素值天然落在合法替换域内）

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4,3], limit = 4
输出：1
解释：把 4 改成 2，数组变为 [1,2,2,3]：
      nums[0] + nums[3] = 1 + 3 = 4，nums[1] + nums[2] = 2 + 2 = 4，互补。
```

**示例 2**

```text
输入：nums = [1,2,2,1], limit = 2
输出：2
解释：两对 (1,1) 与 (2,2) 的和分别为 2 与 4。公共和取 2/3/4 都要 2 次：
      例如取 4 时需把两个 1 都改成 2，得到 [2,2,2,2]。不能改成 3（3 > limit）。
```

**示例 3**

```text
输入：nums = [1,2,1,2], limit = 2
输出：0
解释：两对 (1,2) 与 (1,2) 的和都已是 3，无需操作。
```

## 3. 解题思路

### 3.1 暴力思路

最优解一定对应某个**公共和** $T$（互补的定义要求所有对称对的和相等）。互补数组每个元素都在 $[1, \text{limit}]$ 内，故 $T \in [2, 2\,\text{limit}]$，候选约 $2 \times 10^5$ 个。

暴力：枚举每个 $T$，遍历全部 $n/2$ 个数对逐对求代价再求和，取最小。单对代价 $O(1)$ 可算（见 3.2），但总复杂度 $O(n \cdot \text{limit}) \approx 10^{10}$，必然超时。**瓶颈**：$T$ 的候选太多，而每个 $T$ 都要重新计算所有数对的代价。

### 3.2 核心观察：数对代价函数只有 0 / 1 / 2 三档

**第一层观察：固定 $T$ 后各数对互相独立。** 数对 $(\text{nums}[i], \text{nums}[n-1-i])$ 只关心自己的和是否等于 $T$，各对占用的下标互不重叠、修改互不干扰，因此**总代价 = 各对代价之和**。

**第二层观察：单对代价是关于 $T$ 的分段常函数，只有三档。** 记一对数为 $(a, b)$，不妨 $a \le b$，记 $L = \text{limit}$：

- $T = a + b$：**0 次**，保持不动；
- **只改一个数**：保留 $a$ 改 $b$，需 $T - a \in [1, L]$，即 $T \in [a+1, a+L]$；保留 $b$ 改 $a$，需 $T \in [b+1, b+L]$。由 $a \le b \le L$ 知 $b+1 \le a+L+1$，两区间相邻或重叠，并集恰为连续区间 $[a+1, b+L]$（扣除 $T = a+b$ 这一点），代价 **1 次**；
- 其余 $T$（$T \le a$ 或 $T \ge b+L+1$）：两个数都得改，代价 **2 次**。且 2 次必够：取 $x = \max(1,\, T - L)$、$y = T - x$，可验证 $x, y \in [1, L]$ 且 $x + y = T$。

![核心观察：单对代价随目标 T 分段为 2→1→0→1→2](images/1674_pair_cost_concept.svg)

> 💡 **一句话总结**：每对数贡献一条只有至多 5 个分界点（$2$、$a+1$、$a+b$、$a+b+1$、$b+L+1$）的阶梯函数；所有阶梯函数叠加仍是阶梯函数，跳变点总共只有 $O(n)$ 个——这正是**差分**的用武之地。

### 3.3 算法流程：差分数组聚合 + 一遍扫描

对每对 $(a, b)$（$a \le b$）往差分数组 `diff` 写入 5 个端点，其中 `diff[x]` 表示 $T$ 从 $x-1$ 走到 $x$ 时代价的变化量：

```text
diff[2]         += 2    # 基准：先按最坏情况"改两个数"计
diff[a+1]       -= 1    # T ≥ a+1 起进入"改一个数"区间
diff[a+b]       -= 1    # 在 T = a+b 处再降为 0
diff[a+b+1]     += 1    # 离开 a+b，回到"改一个数"
diff[b+limit+1] += 1    # T ≥ b+limit+1 回到"改两个数"
```

然后令 `cur` 从 $T = 2$ 起累加 `diff`，`cur` 即"公共和取 $T$ 时的总操作数"，扫描到 $2L$ 取最小即可。

![算法流程：每对写 5 个差分端点，前缀和扫描取最小](images/1674_diff_array_flow.svg)

> ⚠️ 注意第 5 个端点是 $b + L + 1$ 而不是 $b + L$：$T = b+L$ 恰是把 $a$ 改成 $L$ 的最大可达和，代价应为 1；差分端点写偏一位会让此处代价错记为 2（详见 §8）。

### 3.4 示例演算

以示例 1 为例：`nums = [1,2,4,3]`，`limit = 4`，两对为 $(1,3)$ 与 $(2,4)$。数对① 的单改区间是 $[2, 7]$、零点 $4$；数对② 的单改区间是 $[3, 8]$、零点 $6$。逐一计算每个 $T$ 的代价：

| $T$ | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|------|---|---|---|---|---|---|---|
| 数对① $(1,3)$，单改区 $[2,7]$，零点 $4$ | 1 | 1 | **0** | 1 | 1 | 1 | 2 |
| 数对② $(2,4)$，单改区 $[3,8]$，零点 $6$ | 2 | 2 | 1 | 1 | **0** | 1 | 1 |
| **总代价** | 3 | 2 | **1** | 2 | **1** | 2 | 3 |

![示例演算：两对数在每个 T 处的代价与总代价](images/1674_walkthrough.svg)

最小值 $1$ 在 $T = 4$（把 $4$ 改成 $2$，得 `[1,2,2,3]`）或 $T = 6$（把 $1$ 改成 $3$，得 `[3,2,4,3]`）处取得，与示例输出一致。

## 4. 算法细节

1. **$T$ 的取值范围**：互补数组每对值都 $\in [1, L]$，公共和必 $\in [2, 2L]$；反之 $[2, 2L]$ 内每个 $T$ 都能被每对以 $\le 2$ 次代价达到（3.2 已构造），故扫描区间完备、不漏最优。
2. **差分端点的方向语义**：`diff[x]` 的增量对所有 $T \ge x$ 的前缀和生效（从 $x-1$ 迈到 $x$ 时叠加）。五个端点叠加后在各段的累计值依次为 $2 \to 1 \to 0 \to 1 \to 2$，与 3.2 的分段代价逐段吻合。
3. **端点重合无需特判**：如 $a = b = 1$ 时 `diff[2]` 同时收到 $+2, -1, -1$，净效果为 $0$，恰好表达"$T=2$ 处代价 0"；差分天然支持同下标叠加。
4. **数组大小**：最大写入下标是 $b + L + 1 \le 2L + 1$，故开 $2L + 2$ 长度。
5. **答案初值**：$n$ 本身就是上界（每对都改两次、$T$ 任取时总代价 $\le 2 \times n/2 = n$），初始化为 $n$ 或 $+\infty$ 均可。

## 5. 正确性证明

**引理 1**（单对代价公式）：设 $1 \le a \le b \le L$，$T \in [2, 2L]$。使某对 $(a, b)$ 经修改后两数之和等于 $T$（修改后两数均在 $[1, L]$）的最少操作次数 $c(T)$ 满足：$c(T) = 0 \iff T = a+b$；$c(T) = 1 \iff T \in [a+1,\, b+L] \setminus \{a+b\}$；其余 $T$ 处 $c(T) = 2$。

**证明**：分三档。
（1）0 次 $\iff$ 不修改就满足 $a + b = T$。
（2）恰 1 次 $\iff$ 恰改一个数即可：保留 $a$ 时新值 $T - a$ 合法 $\iff T \in [a+1, a+L]$；保留 $b$ 时同理 $T \in [b+1, b+L]$。两闭区间的并：由 $a \le b$ 得左端点较小者为 $a+1$；由 $b \le L < a + L$ 得 $b + 1 \le a + L + 1$，两区间相邻或重叠，故并为连续区间 $[a+1, b+L]$；再扣除（1）中 $T = a+b$（若 1 次可行则 0 次更行，取最小，此处 $a + b$ 本身落在该区间内）。
（3）其余 $T$ 必须两个数都改，且 2 次必够：取 $x = \max(1, T-L)$、$y = T - x$。若 $T \le L+1$，则 $x = 1$，$y = T - 1 \in [1, L]$；若 $T > L+1$，则 $x = T - L \in [2, L]$，$y = L$。故 $(x, y)$ 总是合法方案。∎

**引理 2**（数对独立）：固定 $T$ 后，最小总操作数 $= \sum_{i=0}^{n/2-1} c_i(T)$，其中 $c_i$ 为第 $i$ 对按引理 1 的代价。

**证明**："互补"条件按对称下标分解为 $n/2$ 个独立约束 $\text{nums}[i] + \text{nums}[n-1-i] = T$，各约束涉及互不相交的下标集合。因此任一修改方案的总代价可按对分解，且各对可独立地取到自身最小代价——把每对的最优修改拼起来即为全局可行方案，反之任何全局方案的分解给出逐对下界。故总和即最小总代价。∎

**定理**：算法返回使数组互补的最少操作次数。

**证明**：任何互补数组的公共和 $T \in [2, 2L]$（每元素 $\in [1, L]$），结合引理 2，答案 $= \min_{T \in [2,\, 2L]} \sum_i c_i(T)$。对单个数对，五个差分端点在 $T$ 处的累计贡献为：$T \in [2, a]$：$+2$；$T \in [a+1, a+b-1]$：$2 - 1 = 1$；$T = a+b$：$2 - 1 - 1 = 0$；$T \in [a+b+1, b+L]$：$2 - 1 - 1 + 1 = 1$；$T \ge b+L+1$：$2 - 1 - 1 + 1 + 1 = 2$（端点重合时按叠加结果计，同得正确值），与引理 1 的 $c(T)$ 逐段一致。差分逐项相加后，扫描时的 `cur`$(T) = \sum_i c_i(T)$，故扫描取到的最小值即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + \text{limit})$。配对并写入端点共 $\tfrac{n}{2} \times 5 = O(n)$ 次数组更新；随后扫描 $2 \cdot \text{limit} - 1$ 个 $T$ 值各 $O(1)$ 累加比较。
- **空间复杂度**：$O(\text{limit})$。差分数组长度 $2\,\text{limit} + 2$，其余仅常数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minMoves(vector<int>& nums, int limit) {
        int n = nums.size();
        vector<int> diff(2 * limit + 2);
        for (int i = 0; i < n / 2; i++) {
            int a = nums[i], b = nums[n - 1 - i];
            if (a > b) swap(a, b);
            diff[2] += 2;
            diff[a + 1] -= 1;
            diff[a + b] -= 1;
            diff[a + b + 1] += 1;
            diff[b + limit + 1] += 1;
        }
        int ans = n;          // 上界：每对都改两次
        int cur = 0;
        for (int T = 2; T <= 2 * limit; T++) {
            cur += diff[T];   // cur = 公共和取 T 时的总操作数
            ans = min(ans, cur);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minMoves(self, nums: List[int], limit: int) -> int:
        n = len(nums)
        diff = [0] * (2 * limit + 2)
        for i in range(n // 2):
            a, b = nums[i], nums[n - 1 - i]
            if a > b:
                a, b = b, a
            diff[2] += 2
            diff[a + 1] -= 1
            diff[a + b] -= 1
            diff[a + b + 1] += 1
            diff[b + limit + 1] += 1
        ans, cur = n, 0       # 上界：每对都改两次
        for T in range(2, 2 * limit + 1):
            cur += diff[T]    # cur = 公共和取 T 时的总操作数
            ans = min(ans, cur)
        return ans
```

## 8. 边界情况与易错点

1. **`b + limit + 1` 的 `+1`**：本题最常见的 bug。`diff[x]` 语义是"跨过 $x$ 才生效"，若把最后一个端点写成 `b + limit`，则 $T = b + \text{limit}$（改一个数的最大可达和）会被错误记为 2。
2. **数组开小越界**：最大下标 $b + \text{limit} + 1$ 可达 $2\,\text{limit} + 1$，必须开 $2\,\text{limit} + 2$；开成 $2\,\text{limit}$ 在 $b = \text{limit}$ 时越界。
3. **先保证 $a \le b$**：整个推导按 $a \le b$ 进行，配对后不 swap 会算错单改区间。
4. **端点重合不是错**：$a = b = 1$ 等情形多个端点落同一下标，叠加后自动正确，**不要**特判。
5. **扫描区间含两端**：$T$ 从 $2$ 扫到 $2\,\text{limit}$，两端都是合法候选（$a=b=1$ 时 $T=2$ 零代价；$a=b=L$ 时 $T=2L$ 零代价）。
6. **不要退化成逐 $T$ 重算**：对每个 $T$ 遍历所有数对（或用哈希表逐对模拟）是 $O(n \cdot \text{limit})$，必超时；差分的意义正在于把"逐 $T$ 重算"换成"逐端点更新 + 一次前缀和"。
7. **溢出**：`cur` 最大为 $n \le 10^5$，`int` 足够，无溢出风险。
