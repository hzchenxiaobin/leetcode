# LeetCode 树节点的第 K 个祖先 题解

## 1. 题目概述

- **标题 / 题号**：树节点的第 K 个祖先（#1483，hard）
- **链接**：https://leetcode.cn/problems/kth-ancestor-of-a-tree-node/
- **来源**：LeetCode 第 193 场周赛 Q4
- **难度**：困难
- **标签**：位运算、树、深度优先搜索、广度优先搜索、设计、二分查找、动态规划、倍增

**题意**：给定一棵 $n$ 个节点的有根树（根为节点 $0$），以父数组 `parent` 给出，`parent[i]` 是节点 $i$ 的父节点、`parent[0] = -1`。要求实现 `TreeAncestor` 类：构造时接收 $n$ 与 `parent`；`getKthAncestor(node, k)` 返回「从 `node` 沿父指针向上走 $k$ 步」到达的节点编号，走不到就返回 `-1`。查询最多 $5\times10^4$ 次，所以每次查询必须做到 $O(\log n)$ 量级。

**约束**：

- $1 \le k \le n \le 5\times10^4$
- `parent.length == n`，`parent[0] == -1`
- 对 $0 < i < n$ 有 $0 \le parent[i] < n$，但**不保证 `parent[i] < i`**：节点编号与深度无关，不能按编号顺序假设「父节点一定更小」
- $0 \le node < n$，查询**至多** $5\times10^4$ 次

## 2. 示例

**示例 1**

```text
输入：
["TreeAncestor","getKthAncestor","getKthAncestor","getKthAncestor"]
[[7,[-1,0,0,1,1,2,2]],[3,1],[5,2],[6,3]]
输出：[null,1,0,-1]
解释：getKthAncestor(3,1) = 1  （1 是 3 的父节点）
      getKthAncestor(5,2) = 0  （0 是 5 的祖父节点）
      getKthAncestor(6,3) = -1 （6 只有两层祖先，不存在第 3 个）
```

**补充示例 2（退化成一条链，深度敏感）**

```text
输入：n = 10, parent = [-1,0,1,2,3,4,5,6,7,8]
查询：getKthAncestor(9,6)、getKthAncestor(9,9)、getKthAncestor(4,6)
输出：3、0、-1
解释：9 向上 6 步是 3；向上 9 步正好到根 0；节点 4 到根只有 4 步，走 6 步必然越界 → -1

解释：7→4→3；5→3→1→0；6→4→3→1→0；2→1→0→（再往上）-1
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是「查询时沿父指针一步步走」：`getKthAncestor` 循环 $k$ 次 `node = parent[node]`。单次 $O(k)$，最坏 $O(n)$；$5\times10^4$ 次查询、$k$ 又可达 $5\times10^4$，总量 $2.5\times10^9$，必然超时。

另一个极端是**预处理每个节点的完整祖先链**（`anc[v]` 存 $v$ 到根的所有节点）：查询 $O(1)$，但空间 $O(n^2)=2.5\times10^9$ 个整数，约 10 GB，直接爆内存。

两头都堵死，说明需要一种「用 $O(\log n)$ 的空间换 $O(\log n)$ 的查询」的折中结构。

### 3.2 核心观察：用二进制拆分把「走 k 步」变成「跳 log k 次」

![倍增：把 k 拆成二进制，每次向上跳 2^j 步](images/wc193_q4_binary_lifting_model.svg)

关键观察有两点：

1. **任何整数都有唯一的二进制拆分**：$k = \sum_j b_j 2^j$，$b_j \in \{0,1\}$。于是「向上走 $k$ 步」可以拆成「依次向上跳 $2^j$ 步」，**跳的顺序无关紧要**——每一步都只是把当前位置换成它的第 $2^j$ 个祖先，而祖先关系满足加法可交换（见 §5 引理 2）。
2. **只需存储「2 的幂次」级祖先**：只要知道每个节点的第 $1,2,4,8,\dots$ 个祖先，任意 $k$ 的组合都能拼出来。这样的表只有 $\lfloor \log_2 n\rfloor + 1$ 行，$n \le 5\times10^4 < 2^{16}$ 时最多 16 行，共 $8\times10^5$ 个整数（约 3.2 MB），完全放得下。

这就是**倍增（binary lifting）**：一次跳跃 $2^j$ 步 = 一次数组访问，查询代价从 $O(k)$ 降到 $O(\log k)$。

### 3.3 状态转移与查询流程

![up 表的递推：两段 2^(j−1) 步拼成 2^j 步](images/wc193_q4_lifting_dp_transition.svg)

记 $\mathrm{up}[j][v]$ 为节点 $v$ 的第 $2^j$ 个祖先（不存在时记 $-1$）。边界与转移为

$$\mathrm{up}[0][v] = \mathrm{parent}[v], \qquad \mathrm{up}[j][v] = \mathrm{up}[j-1]\bigl[\mathrm{up}[j-1][v]\bigr]$$

直观含义：从 $v$ 先跳 $2^{j-1}$ 步到中间点 $u$，再从 $u$ 跳 $2^{j-1}$ 步，合计 $2^j$ 步。若 $\mathrm{up}[j-1][v] = -1$（已越过根），则 $\mathrm{up}[j][v] = -1$。

建表：$O(n\log n)$ 双重循环，先填第 0 行，再逐行向上递推。

查询 `getKthAncestor(node, k)`：

1. `cur = node`，令 $j = 0,1,2,\dots$ 依次扫描 $k$ 的二进制位；
2. 若第 $j$ 位 $b_j = 1$，则 `cur = up[j][cur]`（一次跳 $2^j$ 步）；若此时 `cur == -1`，说明已越过根，**立即返回 -1**；
3. $j$ 递增直到扫描完 $k$ 的所有有效位，返回 `cur`。

### 3.4 示例演算

![示例 1 演算：树 + 三次查询的跳跃过程](images/wc193_q4_walkthrough.svg)

先算出示例 1 的倍增表（`parent = [-1,0,0,1,1,2,2]`）：

| $j$ | $\mathrm{up}[j][0..6]$ | 说明 |
|-----|------------------------|------|
| 0 | $[-1,0,0,1,1,2,2]$ | 就是 `parent` 本身 |
| 1 | $[-1,-1,-1,0,0,0,0]$ | 2 级祖先：$\mathrm{up}[1][3]=\mathrm{up}[0][1]=0$ |
| 2 | $[-1,-1,-1,-1,-1,-1,-1]$ | 4 级祖先：深度最多只有 2，全部越界 |

三次查询的走查：

| 查询 | $k$ 的二进制 | 跳跃过程 | 返回 |
|------|--------------|----------|------|
| `getKthAncestor(3,1)` | $1 = 2^0$ | 3 $\xrightarrow{2^0}$ 1 | 1 |
| `getKthAncestor(5,2)` | $2 = 2^1$ | 5 $\xrightarrow{2^1}$ 0 | 0 |
| `getKthAncestor(6,3)` | $3 = 2^0+2^1$ | 6 $\xrightarrow{2^0}$ 2 $\xrightarrow{2^1}$ $-1$ | -1 |

第三行值得注意：先跳 $2^0$ 步到 2，再想跳 $2^1$ 步时 $\mathrm{up}[1][2] = -1$，说明 2 的深度不足以再往上 2 步，此时剩余步数更多，必然不存在，直接返回 $-1$。

## 4. 算法细节

1. **哨兵与边界**：根的父节点记为 $-1$，表示「不存在祖先」。建表时 $\mathrm{up}[0][0]$ 必须是 $-1$；若输入 `parent[0]` 已为 $-1$ 则无需改动。
2. **表长 $LOG$**：$k \le n$，取最小的 $LOG$ 使 $2^{LOG} > n$，即 $LOG = \lceil \log_2(n+1)\rceil$（C++ 用 `while ((1<<LOG) <= n) ++LOG;`，Python 用 `n.bit_length()`）。$n=5\times10^4$ 时 $LOG=16$，最高能覆盖 $k$ 的第 15 位。
3. **递推顺序**：外层枚举行 $j$、内层枚举节点 $v$。同一行的各列互不依赖，既可按任意顺序填，也可整行用列表推导生成（Python 写法最简洁）。
4. **查询的位序**：$k$ 的第 $j$ 位对应 $\mathrm{up}[j]$，两者必须严格对齐。用 `while k:` 配 `k & 1`、`k >>= 1` 最不容易写错；用 `for j in range(LOG): if (k >> j) & 1` 等价。
5. **提前返回**：`cur == -1` 时立即返回，既省时间，又避免后续 `up[j][-1]` 这类越界/负索引访问（Python 里会静默取到最后一行）。
6. **内存布局**：C++ 可用一维 `vector<int> up(LOG * n)` 配合 `up[j*n + v]` 访问，比 `vector<vector<int>>` 少一层指针；本题 $16\times5\times10^4$ 个 `int` 约 3.2 MB，两种写法都安全。
7. **离线替代方案**：若查询可以离线，也可用 DFS 记录当前栈 + 「深度 = d 的栈顶」直接 $O(1)$ 回答，空间 $O(n)$；但本题接口要求**在线**查询，倍增更通用。

## 5. 正确性证明

**引理 1（表的语义）**：对任意 $j \ge 0$ 与节点 $v$，$\mathrm{up}[j][v]$ 等于 $v$ 的第 $2^j$ 个祖先；若 $v$ 的深度小于 $2^j$（祖先不存在），则 $\mathrm{up}[j][v] = -1$。

**证明**：对 $j$ 归纳。$j=0$ 时 $\mathrm{up}[0][v] = \mathrm{parent}[v]$，正是第 $2^0=1$ 个祖先（根处为 $-1$），成立。设结论对 $j-1$ 成立，令 $u = \mathrm{up}[j-1][v]$。若 $u = -1$，说明 $v$ 的深度小于 $2^{j-1} \le 2^j$，第 $2^j$ 个祖先不存在，我们令 $\mathrm{up}[j][v] = -1$，结论成立；若 $u \ne -1$，则按归纳假设 $u$ 是 $v$ 的第 $2^{j-1}$ 个祖先，且深度满足 $\mathrm{depth}(u) = \mathrm{depth}(v) - 2^{j-1}$。再由归纳假设，$\mathrm{up}[j-1][u]$ 是 $u$ 的第 $2^{j-1}$ 个祖先，当 $\mathrm{depth}(u) < 2^{j-1}$ 即 $\mathrm{depth}(v) < 2^j$ 时它是 $-1$，否则它就是 $v$ 的第 $2^{j-1}+2^{j-1}=2^j$ 个祖先。∎

**引理 2（祖先关系可复合）**：设 $A$ 是 $v$ 的第 $a$ 个祖先，$B$ 是 $A$ 的第 $b$ 个祖先，则 $B$ 是 $v$ 的第 $a+b$ 个祖先；并且「先跳 $a$ 步再跳 $b$ 步」与「先跳 $b$ 步再跳 $a$ 步」得到同一节点（只要都存在）。

**证明**：沿父指针从 $v$ 走 $a$ 步到达 $A$、再走 $b$ 步到达 $B$，总共走了 $a+b$ 步，而树中每个节点的父节点唯一，所以「走 $m$ 步的落点」由 $m$ 唯一确定，即 $B$ 是 $v$ 的第 $a+b$ 个祖先。交换顺序同理：两步路径的**总步数相同**，而落点只取决于总步数与起点，故结果一致。∎

**引理 3（查询循环的不变量）**：查询循环在第 $j$ 轮开始前，若 `cur != -1`，则 `cur` 是 `node` 的第 $(k \bmod 2^j)$ 个祖先。

**证明**：对 $j$ 归纳。$j=0$ 时 $k \bmod 1 = 0$，`cur = node` 是自身的第 0 个祖先，成立。设第 $j$ 轮开始时成立（第 $j$ 轮处理 $k$ 的第 $j$ 位）：

- 若 $b_j = 0$，`cur` 不变，而 $k \bmod 2^{j+1} = k \bmod 2^j$，不变量保持；
- 若 $b_j = 1$，由引理 1，`up[j][cur]` 是 `cur` 的第 $2^j$ 个祖先，再由引理 2 它是 `node` 的第 $(k \bmod 2^j) + 2^j$ 个祖先；因为第 $j$ 位为 1，这正是 $k \bmod 2^{j+1}$，不变量保持。∎

**定理**：`getKthAncestor(node, k)` 返回 `node` 的第 $k$ 个祖先；不存在时返回 $-1$。

**证明**：分两种情形。

1. **全程未遇 $-1$**：循环扫描完 $k$ 的所有位后 $j = LOG$，由引理 3 此时 `cur` 是 `node` 的第 $(k \bmod 2^{LOG})$ 个祖先；因 $k \le n < 2^{LOG}$，有 $k \bmod 2^{LOG} = k$，故返回的正是第 $k$ 个祖先。
2. **中途遇到 $-1$**：设第 $j$ 轮更新后 `cur = -1`。按引理 3 的推演，此时「从 `node` 走 $s = k \bmod 2^{j+1}$ 步」的落点不存在（越过根），即 $\mathrm{depth}(node) < s$。因为 $s \le k$，所以 $\mathrm{depth}(node) < k$，第 $k$ 个祖先同样不存在，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **预处理时间**：$O(n \log n)$。第 0 行 $O(n)$，其余 $LOG-1$ 行每行 $O(n)$ 次常数操作；$n=5\times10^4$、$LOG=16$ 时约 $8\times10^5$ 次。
- **单次查询时间**：$O(\log k) \le O(\log n)$，最多 16 次数组访问；中途遇到 $-1$ 还会提前结束。
- **总时间**：$O\bigl((n+q)\log n\bigr)$，$n = q = 5\times10^4$ 时约 $1.6\times10^6$ 次操作，远低于暴力解法的 $2.5\times10^9$。
- **空间**：$O(n\log n)$ 个 `int`，约 $16 \times 5\times10^4 \times 4\text{B} \approx 3.2\text{ MB}$；不需要存树的孩子关系，也不必递归，无栈溢出风险。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class TreeAncestor {
    vector<vector<int>> up;   // up[j][v] = v 的第 2^j 个祖先，不存在为 -1
    int LOG;

public:
    TreeAncestor(int n, vector<int>& parent) {
        LOG = 1;
        while ((1 << LOG) <= n) ++LOG;     // 覆盖 k 的全部二进制位
        up.assign(LOG, vector<int>(n, -1));
        for (int v = 0; v < n; ++v) up[0][v] = parent[v];   // 第 0 行就是父数组

        for (int j = 1; j < LOG; ++j) {
            for (int v = 0; v < n; ++v) {
                int mid = up[j - 1][v];                        // 先跳 2^(j-1) 步
                up[j][v] = (mid == -1) ? -1 : up[j - 1][mid];  // 再跳 2^(j-1) 步
            }
        }
    }

    int getKthAncestor(int node, int k) {
        for (int j = 0; j < LOG && node != -1; ++j) {
            if ((k >> j) & 1) node = up[j][node];   // 该位为 1 才跳 2^j 步
        }
        return node;
    }
};
```

### Python

```python
class TreeAncestor:

    def __init__(self, n: int, parent: list[int]):
        LOG = max(1, n.bit_length())          # 覆盖 k 的全部二进制位
        up = [list(parent)]
        up[0][0] = -1                         # 根没有祖先
        for _ in range(1, LOG):
            prev = up[-1]
            # prev[prev[v]] 中 prev[v] 可能为 -1，必须特判，否则会变成负索引
            up.append([prev[prev[v]] if prev[v] != -1 else -1 for v in range(n)])
        self.up = up
        self.LOG = LOG

    def getKthAncestor(self, node: int, k: int) -> int:
        j = 0
        while k:
            if k & 1:                         # k 的第 j 位为 1
                node = self.up[j][node]
                if node == -1:                # 已越过根，后面更不可能存在
                    return -1
            k >>= 1
            j += 1
        return node
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有一个根，$LOG = 1$，表只有一行 $[-1]$。任何 $k \ge 1$ 的查询都要靠 `up[0][0] = -1` 才能返回 $-1$，不能因为「$k$ 超过了表的行数」就跳过查表逻辑。
2. **Python 的负索引陷阱**：`prev[prev[v]]` 在 `prev[v] == -1` 时会取到**最后一行/最后一个元素**，静默返回错误答案而不是报错。必须写成 `prev[prev[v]] if prev[v] != -1 else -1`。
3. **$LOG$ 开小了**：若只开到 $\log_2 n$ 的下取整（$n=5\times10^4$ 时为 15 行），当 $k \ge 2^{15}=32768$ 时最高位无处可跳，会静默返回错误祖先。$LOG$ 必须满足 $2^{LOG} > n$。
4. **误以为 `parent[i] < i`**：题面不保证这一点，节点编号与深度无任何关系。所有逻辑必须按「父指针」处理，不能按编号顺序推断深度或祖先。
5. **$k$ 恰好等于深度**：走到根，返回 $0$；$k$ 比深度大 1 才是 $-1$。判定完全交给「查表得到 $-1$」即可，不需要额外算深度。
6. **`cur == -1` 之后继续查表**：越界或取到错误行。查询循环必须带 `node != -1` 条件（C++）或立即 `return -1`（Python）。
7. **建表时漏掉根的特判**：`up[0][0]` 必须为 $-1$；若输入可能给出其他值（题面保证为 $-1$），也应在构造里显式写入以保证哨兵语义。
8. **查询次数为 0**：只构造不查询时，构造过程不能依赖任何查询信息，也不能因懒加载导致越界（本解法为纯预处理，天然安全）。

**延伸思考**：

1. **空间换时间的两端**：若把 $\mathrm{up}$ 的每一行都保留成完整数组，空间 $O(n\log n)$、查询 $O(\log n)$；若只保留「每 $\sqrt{n}$ 层一个跳板」，空间 $O(n)$、查询 $O(\sqrt{n})$（先跳整块，再逐步走）。本题 $n = 5\times10^4$ 时倍增的常数更优，但「分块跳跃」在空间受限的嵌入式场景仍有价值。
2. **求第 $k$ 个后代**（沿子树方向而非祖先方向）：可对树做 DFS 序，按深度分桶后利用子树区间 $[\mathrm{tin}, \mathrm{tout})$ 与桶内二分，做到 $O(\log n)$；这与「向上倍增」恰好是对偶问题。
3. **在线加边 / 断边**：倍增表建立在静态拓扑上，动态树需要改用 Link-Cut Tree，或采用「重建倍增表」的分块重构（每 $\sqrt{n}$ 次修改重建一次，均摊 $O(\sqrt{n}\log n)$）。
4. **从倍增到稀疏表**：$\mathrm{up}[j][v]$ 本质是一张「跳跃长度固定为 $2^j$」的稀疏表，与 RMQ 的 ST 表同构；把「步数」换成「区间长度」，就能把同样的递推迁移到区间最值问题上。
