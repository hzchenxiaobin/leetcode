# LeetCode 不同整数的最少数目 题解

## 1. 题目概述

- **标题 / 题号**：不同整数的最少数目（#1481，medium）
- **链接**：https://leetcode.cn/problems/least-number-of-unique-integers-after-k-removals/
- **来源**：LeetCode 第 193 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、哈希表、计数、排序

**题意**：给定整数数组 `arr` 与整数 `k`，要求**恰好**删除 `k` 个元素（删哪几个、删完后数组什么顺序都不关心），使得剩下的数组里**不同整数的个数**尽可能少，返回这个最小值。

**约束**：

- $1 \le \text{arr.length} \le 10^5$
- $1 \le \text{arr}[i] \le 10^9$（值域很大，不能开桶，只能哈希表/排序）
- $0 \le k \le \text{arr.length}$（`k` 可以是 0，也可以等于整个数组长度）

## 2. 示例

**示例 1**

```text
输入：arr = [5,5,4], k = 1
输出：1
解释：唯一值得删的是那个单独的 4 —— 删掉它后数组只剩 5，种类数 1；
      若删掉一个 5，剩下 [5,4]，种类数仍是 2，不如前者。
```

**示例 2**

```text
输入：arr = [4,3,1,1,3,3,2], k = 3
输出：2
解释：频次为 值1→2、值2→1、值3→3、值4→1。
      先花 1 个名额灭掉 4，再花 1 个名额灭掉 2（至此用了 2 个名额，种类 4→2）；
      最后一个名额无论删 1 还是删 3，都只能让某个族从 2 变 1 或从 3 变 2，种类数不变。
      最后剩下 1 与 3 两种整数。
```

**补充示例（`k = 0` 的边界，非官方）**

```text
输入：arr = [1,1,2], k = 0
输出：2
解释：一个都不许删，种类数就是原数组的 2。
```

## 3. 解题思路

### 3.1 暴力思路

把「删除方案」当成组合来枚举：从 $n$ 个下标里选 $k$ 个删掉，方案数 $\binom{n}{k}$，每个方案再扫一遍统计种类，复杂度 $O\binom{n}{k} \cdot n$。$n = 10^5$ 时连 $k=2$ 的 $\binom{n}{2}$ 都过不去。

退一步，按「值」做 0/1 背包也不便宜：设共有 $m$ 种整数、第 $i$ 种的频次为 $c_i$，枚举前 $i$ 种、用掉 $j$ 个删除名额能灭掉多少种，状态数是 $O(mk) = O(n^2)$，同样不可行。

可见必须找到一个**不需要枚举**的结构性结论。

### 3.2 核心观察：灭掉一个整数要付它的频次，先付最便宜的

![灭族代价与升序贪心](images/wc193_q2_greedy_cost.svg)

把相同整数看成一个**族**，族的大小就是它的出现频次。要点只有两个：

1. **只有整族消失才会让答案变小**。删掉某一族里的部分元素，这一族还剩至少一个元素，不同整数个数一个都不少。所以「让 $k$ 个名额产生收益」的唯一方式是：**攒够 $c_i$ 个名额，把第 $i$ 族整族删光**，收益是种类数 $-1$。
2. **同样的名额，当然先灭便宜的族**。灭掉频次为 $c_i$ 的族需要 $c_i$ 个名额、换 1 点收益；先做单价（$c_i$）最小的，$k$ 个名额就能买下最多的族。

于是解法非常短：统计频次 → 把频次升序排序 → 从左往右依次「买」：若当前族的代价 $c$ 不超过剩余名额 $k$，就付掉 $c$、答案减一；一旦某个族买不起（$c > k$），后面更大的族只会更买不起，**直接 break**。

### 3.3 算法流程

![算法流程：计数、排序、逐族消费 k](images/wc193_q2_algorithm_flow.svg)

1. 用哈希表 `freq` 统计每个值出现的次数，复杂度 $O(n)$。
2. 取出 `freq` 的所有 value 组成 `counts` 数组，长度 $m$ 就是初始的不同整数个数，记为 `ans`。
3. 对 `counts` 升序排序。
4. 依次访问 `c`：`c <= k` 时执行 `k -= c; ans -= 1`；否则 `break`。
5. 返回 `ans`。

> 💡 循环不变量：进入每一次判定时，`k` 是「付清前面若干薄族之后」剩余的名额，`ans` 是尚未被灭掉的整数个数，故答案始终是 `ans`。

### 3.4 示例演算

![示例 2 的逐步走查表](images/wc193_q2_walkthrough.svg)

以 `arr = [4,3,1,1,3,3,2]`、`k = 3` 为例，频次排序后为 $[1,1,2,3]$：

| 步骤 | 代价 $c$（对应值） | 进入时 $k$ | $c \le k$ ? | 操作后 $k$ | `ans` |
|------|------------------|-----------|-------------|-----------|-------|
| 1 | 1（值 2） | 3 | 是 | 2 | 3 |
| 2 | 1（值 4） | 2 | 是 | 1 | 2 |
| 3 | 2（值 1） | 1 | 否，break | 1 | 2 |
| 4 | 3（值 3） | — | 未处理 | 1 | 2 |

最终返回 2，与示例一致。注意第 3 步之后的 1 个名额**必须用掉**（题目要求恰好删 $k$ 个），但它只能在剩下的族内部消耗，不改变种类数——这正是「恰好」二字不构成额外约束的原因：只要 $k \le n$，名额总有地方可花。

再看示例 1：`arr = [5,5,4]`，频次 $[1,2]$，`k = 1`。第 1 步买下代价 1 的族（值 4），`k` 归零、`ans` 从 2 变 1；下一步 $2 > 0$ 直接 break，返回 1。

## 4. 算法细节

1. **计数用哈希表**：值域 $10^9$ 不能开桶；C++ 用 `unordered_map<int,int>` 并 `reserve(2n)` 减少 rehash，Python 直接用 `Counter`。
2. **只排序频次数组，不排序原数组**：对 $m$ 个频次排序是 $O(m \log m)$，比对 $n$ 个元素排序更省；`ans` 初值取 `counts.size()`，不要取 `n`。
3. **升序 + 提前 break**：一旦 $c > k$ 就停，因为后面的 $c$ 更大、更不可能付得起。这个剪枝也顺带保证了不会出现 `k` 变负数。
4. **排序的替代方案**：频次总和为 $n$，所以每个频次都在 $[1, n]$ 内，可以用**计数排序**（桶大小为 $n+1$）把这一部分从 $O(m\log m)$ 降到 $O(n)$；不过 $n = 10^5$ 时排序版本已经足够快，代码更短。
5. **整数溢出**：频次累加最大 $10^5$，`k` 最大 $10^5$，均在 `int` 范围内，无需 `long long`。
6. **不要用「平均分配」的直觉**：把名额摊到多个族上看起来「更均匀」，但种类数一分不降；必须凑满一整族才兑换 1 点收益。

## 5. 正确性证明

设数组共有 $m$ 种不同的整数，第 $i$ 种出现 $c_i$ 次，`k` 为删除名额（$k \le n = \sum_i c_i$）。

**引理 1（问题等价于选一个代价填得下的族集合）**：任一删除方案恰好对应一个集合 $S \subseteq \{1,\dots,m\}$，其中 $S$ 是被整族删光的那些整数；该方案删满 $k$ 个元素可行当且仅当 $\sum_{i \in S} c_i \le k$，且此时剩下的不同整数个数恰为 $m - |S|$。

**证明**：若某族被整族删光，则它贡献 $c_i$ 个删除名额并从答案中消失；若某族被部分删除，则它仍至少有 1 个元素残留，仍算一种，且它的删除量不来自 $S$。因此总删除量 $= \sum_{i \in S} c_i + (\text{部分删除量})$，它等于 $k$ 当且仅当 $\sum_{i \in S} c_i \le k$（剩余名额可以在任意未灭光的族内消耗，未灭光的族总元素数 $\ge \sum_{i \notin S} c_i \ge k - \sum_{i \in S} c_i$，所以名额一定花得完）。剩余种类数显然是「未被灭光的族的个数」$= m - |S|$。∎

**引理 2（贪心前缀最优）**：设频次升序排列为 $c_1 \le c_2 \le \dots \le c_m$，令 $t = \max\{j : \sum_{i=1}^{j} c_i \le k\}$（空集时 $t = 0$）。则满足 $\sum_{i \in S} c_i \le k$ 的集合 $S$ 中，$|S|$ 的最大值恰为 $t$。

**证明**：一方面，前缀 $S = \{1,\dots,t\}$ 代价为 $\sum_{i \le t} c_i \le k$，故最大值 $\ge t$。另一方面，任取可行集合 $S$ 且 $|S| = s$，把 $S$ 中的元素按频次升序写成 $d_1 \le \dots \le d_s$，由排序后的第 $i$ 小不超过任取 $s$ 个元中的第 $i$ 小可知 $c_i \le d_i$，于是 $\sum_{i=1}^{s} c_i \le \sum_{i=1}^{s} d_i = \sum_{x \in S} c_x \le k$，这说明前缀 $s$ 可行，由 $t$ 的最大性得 $s \le t$。∎

**定理**：算法返回的 `ans` 等于最少可能的不同整数个数。

**证明**：由引理 1，答案 $= m - |S|$ 的最小值 $= m - \max |S|$；由引理 2，$\max |S| = t$，故最优值为 $m - t$。算法按升序依次消费：前 $t$ 个族都被买下（因为 $\sum_{i \le t} c_i \le k$），第 $t+1$ 个族买不起（因为 $\sum_{i \le t+1} c_i > k$，而此前已付出 $\sum_{i\le t} c_i$，剩余名额 $< c_{t+1}$；若 $t = m$ 则所有族都被买下，返回 0，同样等于 $m - t$），于是恰好灭掉 $t$ 个族，返回 $m - t$，与最优值相同。∎

## 6. 复杂度分析

- **时间**：$O(n + m \log m)$。哈希表计数 $O(n)$；对 $m$ 个频次排序 $O(m \log m)$，其中 $m \le n$；贪心扫描 $O(m)$。最坏情况 $O(n \log n)$，$n = 10^5$ 时非常轻松。若改用计数排序则为 $O(n)$。
- **空间**：$O(m)$。哈希表存 $m$ 个键值对、频次数组长 $m$，均不超过 $O(n)$；排序的递归栈 $O(\log m)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findLeastNumOfUniqueInts(vector<int>& arr, int k) {
        unordered_map<int, int> freq;
        freq.reserve(arr.size() * 2);
        for (int x : arr) ++freq[x];              // 统计每个值的频次

        vector<int> counts;
        counts.reserve(freq.size());
        for (auto& kv : freq) counts.push_back(kv.second);

        sort(counts.begin(), counts.end());        // 代价升序
        int ans = (int)counts.size();              // 初始种类数 = 族数
        for (int c : counts) {
            if (c <= k) {                          // 买得起就整族灭掉
                k -= c;
                --ans;
            } else {
                break;                             // 买不起，后面的更贵
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List
from collections import Counter


class Solution:
    def findLeastNumOfUniqueInts(self, arr: List[int], k: int) -> int:
        counts = sorted(Counter(arr).values())     # 每个整数的出现频次，升序
        ans = len(counts)
        for c in counts:
            if c <= k:                             # 名额够，整族灭掉
                k -= c
                ans -= 1
            else:                                  # 名额不够，后面只会更贵
                break
        return ans
```

## 8. 边界情况与易错点

1. **`k = 0`**：一次都不该删。循环第一次判定就 `c > 0` 成立并 break，返回原种类数；注意别写成「至少删一次」。
2. **`k = n`**：全部元素都被删光，答案应为 0。算法会把所有族依次买下，`ans` 减到 0，符合预期；不要给 `ans` 加 `max(ans, 1)` 之类的保护。
3. **只有一个整数**：`counts = [n]`，`k < n` 时买不起，返回 1；`k = n` 时返回 0。
4. **剩余名额必须花完**：题目要求「恰好」，但 $k \le n$ 保证花得完，且花在未灭光的族内部不会改变种类数，所以贪心过程中**不需要**为「浪费」做任何处理。
5. **不要用「删掉最多的族」的直觉**：灭大族要花更多名额，同样 $k$ 买下的族更少，收益反而差；正确方向是升序而不是降序（对比第 1338 题才是降序）。
6. **`ans` 的初值**：应是「不同整数个数」 `counts.size()`，不是数组长度 `n`；写成 `n` 会得到错误的偏大结果。
7. **提前 break 与 `k` 变负**：如果不 break 而继续循环，`k` 可能变负，后续判据仍正确但多做无用功；显式 break 更清晰也更安全。
