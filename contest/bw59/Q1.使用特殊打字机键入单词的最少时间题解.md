# LeetCode 使用特殊打字机键入单词的最少时间 题解

## 1. 题目概述

- **标题 / 题号**：使用特殊打字机键入单词的最少时间（#1974，easy）
- **链接**：https://leetcode.cn/problems/minimum-time-to-type-word-using-special-typewriter/
- **来源**：LeetCode 第 59 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、字符串

**题意**：特殊打字机由一个圆盘和一个指针组成，圆盘上顺时针依次标着 'a' 到 'z' 共 26 个小写字母，指针初始指向 'a'。每一秒可以执行两种操作之一：把指针顺时针或逆时针移动一格；键入指针当前指向的字符。给定单词 `word`，返回键入整个单词所需的最少秒数。

**约束**：

- $1 \le word.length \le 100$
- `word` 只包含小写英文字母。

## 2. 示例

**示例 1**

```text
输入：word = "abc"
输出：5
解释：键入 'a'（指针已在 a，1 秒）→ 移到 b（1 秒）→ 键入 b（1 秒）→ 移到 c（1 秒）→ 键入 c（1 秒），共 5 秒。
```

**示例 2**

```text
输入：word = "bza"
输出：7
解释：a→b 顺时针 1 步、键入 b；b→z 逆时针 2 步（b→a→z）、键入 z；z→a 顺时针 1 步、键入 a。
移动 1+2+1 = 4 秒，键入 3 秒，合计 7 秒。
```

**示例 3**

```text
输入：word = "zjpc"
输出：34
解释：a→z 逆时针 1 步；z→j 逆时针 10 步；j→p 顺时针 6 步；p→c 逆时针 13 步。
移动 1+10+6+13 = 30 秒，键入 4 秒，合计 34 秒。
```

## 3. 解题思路

### 3.1 暴力思路

把「指针位置 + 已键入到第几个字符」当作状态做 BFS：每个状态向「顺移一格、逆移一格、（指针恰好指向目标字符时）键入」三个后继扩展，边权均为 1，搜到「全部键入完」的状态即为最少秒数。状态数 $O(26 \times |word|)$，转移 $O(3)$，对 $|word| \le 100$ 而言毫无压力。但这是**杀鸡用牛刀**：每个字符的代价只依赖前后两个字符，根本不需要全局搜索。

### 3.2 核心观察：圆环上两点的最短转动 = 两条弧中的较短者

![核心观察：圆环上顺时针与逆时针两条弧取短者](images/bw59_q1_ring_distance.svg)

26 个字母首尾相接构成一个**圆环**。从字符 $a$ 转到字符 $b$，顺时针要走 $d$ 步（$d = |a - b|$，按字母下标计），逆时针恰好要走 $26 - d$ 步——因为两条弧合起来正好绕环一整圈。两个方向只能二选一（每秒顺或逆移一格，中途换向只会更慢），所以单次转动的最少耗时是：

$$cost(a, b) = \min(d, 26 - d), \quad d = |a - b|$$

贪心成立的原因是**无后效性**：转完当前字符后指针就停在当前字符上，与之前怎么转来的无关；每次移动独立取最小，全局自然最小。总时间再叠加每个字符各 1 秒的键入耗时即可。

### 3.3 算法流程

```text
1. ans = len(word)                  # 键入耗时是固定下界
2. prev = 0                         # 指针初始指向 'a'（下标 0）
3. 依次扫描 word 的每个字符 ch：
       cur = ch - 'a'
       d = |cur - prev|
       ans += min(d, 26 - d)        # 顺 / 逆时针取短
       prev = cur
4. 返回 ans
```

### 3.4 示例演算

![示例演算：word = "zjpc" 的逐步走查](images/bw59_q1_walkthrough.svg)

对 `word = "zjpc"`（示例 3）：初始指针在 'a'，先花 1 秒逆移到 'z'（顺移要 25 秒，明显劣）；'z' 到 'j' 下标差 16，逆走 $26 - 16 = 10$ 步更省；'j' 到 'p' 下标差 6，顺走 6 步；'p' 到 'c' 下标差 13，恰好 $26 - 13 = 13$，两方向等长。移动合计 $1 + 10 + 6 + 13 = 30$ 秒，加上键入 4 秒共 **34 秒**，与官方答案一致。可以看到当 $d = 13$（正环的一半）时两个方向等价，这也解释了为什么公式里取 $\min$ 就够了。

## 4. 算法细节

1. **键入耗时先加上**：每个字符必然键入一次、各花 1 秒，直接初始化 `ans = len(word)`，避免循环里漏加首字符或末字符。
2. **首字符从 'a' 出发**：指针初始指向 'a'（下标 0），因此 `prev` 初始化为 0，第一个字符的移动代价按 `a → word[0]` 计算，别错把 `prev` 初始化成 `word[0]`。
3. **下标差取绝对值**：$d = |cur - prev|$，顺逆两方向已由 $\min(d, 26-d)$ 完整覆盖，无需再讨论方向正负。
4. **数据类型**：$|word| \le 100$，每步移动至多 13，总和远小于 `int` 上界，无溢出风险。
5. **复杂度即扫描本身**：一次遍历、每个字符 $O(1)$ 计算，没有额外数据结构。

## 5. 正确性证明

**引理 1（单段转动的下界）**：指针从字符 $a$ 转到字符 $b$（$a \ne b$）至少需要 $\min(d, 26 - d)$ 秒，其中 $d = |a - b|$。

**证明**：指针位置是环 $\mathbb{Z}_{26}$ 上的点，每秒移动一格等价于位置 $\pm 1 \pmod{26}$。设顺时针走了 $x$ 格、逆时针走了 $y$ 格后从 $a$ 到达 $b$，则 $x - y \equiv b - a \pmod{26}$，总耗时 $x + y \ge |x - y| \ge \min\big((b-a) \bmod 26,\ (a-b) \bmod 26\big) = \min(d, 26 - d)$。另一方面，纯顺时针走 $d$ 格或纯逆时针走 $26 - d$ 格均可到达，故下界可以取到。∎

**引理 2（混合方向不优）**：到达目标字符的最优移动中不会中途换向。

**证明**：若先顺 $x_1$ 后逆 $y_1$（$x_1, y_1 > 0$），其净位移 $x_1 - y_1$ 与纯顺 $x_1 - y_1$（若为正）相同，而耗时 $x_1 + y_1 > |x_1 - y_1|$，故任何换向方案都能被一个不换向且更快的方案替代。∎

**定理**：逐字符取 $\min(d, 26-d)$ 并叠加键入耗时的贪心结果即最少总时间。

**证明**：键入操作不改变指针位置，且每个字符各需键入一次（固定 $|word|$ 秒）。各字符间的移动互相独立：第 $i$ 段移动的起点恰为第 $i-1$ 段的终点（首段起点为初始 'a'），段的划分由 `word` 唯一确定，前一段怎么走不影响后一段的起终点。由引理 1，每段移动至少 $\min(d_i, 26 - d_i)$ 秒且可达；由引理 2，段内取纯方向即为该段最优。各段下界相加即总下界，贪心逐段取到下界，故为最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$，$n = |word|$。单次遍历，每个字符 $O(1)$ 计算（减法、绝对值、取 min）。
- **空间**：$O(1)$。只维护 `prev` 与累加器，不随输入规模增长（忽略输入字符串本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minTimeToType(string word) {
        int total = (int)word.size();          // 每个字符键入各花 1 秒
        int prev = 0;                          // 指针初始指向 'a'
        for (char ch : word) {
            int cur = ch - 'a';
            int d = cur - prev;
            if (d < 0) d = -d;
            total += min(d, 26 - d);           // 顺时针 / 逆时针取短者
            prev = cur;
        }
        return total;
    }
};
```

### Python

```python
class Solution:
    def minTimeToType(self, word: str) -> int:
        total = len(word)              # 每个字符键入各花 1 秒
        prev = 0                       # 指针初始指向 'a'
        for ch in word:
            cur = ord(ch) - 97
            d = abs(cur - prev)
            total += min(d, 26 - d)    # 顺时针 / 逆时针取短者
            prev = cur
        return total
```

> 💡 两份代码均通过官方示例（`5`、`7`、`34`），并与 **BFS 暴力**（状态 = 指针位置 × 已键入下标，转移含顺移/逆移/条件键入）对拍 400 组随机串，全部一致。

## 8. 边界情况与易错点

1. **单字符单词**：`word = "a"` 时无移动、仅键入 1 秒；`word = "z"` 时逆移 1 步 + 键入 1 秒 = 2 秒，别错算成顺移 25 步。
2. **对半距离**：$d = 13$ 时顺逆等长（如 'p' 到 'c'），$\min$ 取哪个都一样，不影响正确性。
3. **忘算首字符的移动**：指针初始在 'a' 而非 `word[0]`，首字符也要从 'a' 转过去（除非 `word[0] == 'a'`）。
4. **忘算键入耗时**：只累加移动步数会全部偏小；键入次数 = `len(word)` 是固定项，初始化时加上最稳。
5. **方向枚举想复杂**：不需要「顺时针走到、逆时针走到」分别模拟，$|a-b|$ 与 $26-|a-b|$ 两个数取小即可。
