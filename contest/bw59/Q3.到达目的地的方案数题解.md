# LeetCode 到达目的地的方案数 题解

## 1. 题目概述

- **标题 / 题号**：到达目的地的方案数（#1976，medium）
- **链接**：https://leetcode.cn/problems/number-of-ways-to-arrive-at-destination/
- **来源**：LeetCode 第 59 场双周赛 Q3
- **难度**：中等
- **标签**：图、最短路、Dijkstra 算法、动态规划、拓扑排序

**题意**：城市由 $n$ 个路口（编号 $0 \sim n-1$）组成，`roads[i] = [u, v, time]` 表示路口 $u, v$ 之间一条耗时 `time` 的双向道路，任意两路口间至多一条路且全图连通。求从路口 $0$ 走到路口 $n-1$ 的**最短耗时路径**的条数，答案对 $10^9 + 7$ 取模。

**约束**：

- $1 \le n \le 200$
- $n - 1 \le roads.length \le \frac{n(n-1)}{2}$
- $0 \le u_i, v_i \le n-1$，$u_i \ne v_i$
- $1 \le time_i \le 10^9$
- 图连通，无重边（无自环）

## 2. 示例

**示例 1**

```text
输入：n = 7, roads = [[0,6,7],[0,1,2],[1,2,3],[1,3,3],[6,3,3],[3,5,1],[6,5,1],[2,5,1],[0,4,5],[4,6,2]]
输出：4
解释：最短耗时 7 分钟，共 4 条：0→6；0→4→6；0→1→2→5→6；0→1→3→5→6。
```

**示例 2**

```text
输入：n = 2, roads = [[1,0,10]]
输出：1
解释：只有一条路，耗时 10 分钟。
```

**示例 3（边界补充）**

```text
输入：n = 1, roads = []
输出：1
解释：起点即终点（0 = n−1），空路径算 1 条方案；Dijkstra 初始化 ways[0]=1 自然覆盖。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $0 \to n-1$ 的所有**简单路径**（路径不可能经过同一节点两次仍更短，因为边权为正），DFS 回溯统计最小耗时及达到该耗时的路径数。路径数是阶乘级的，$n = 200$ 时完全不可行；即便 $n \le 8$ 的随机图也要靠剪枝才跑得动。该做法仅适合当对拍参照。

### 3.2 核心观察：在 Dijkstra 松弛时顺带数路径——「更短则重置，等长则累加」

![核心观察：Dijkstra 松弛的三种情况](images/bw59_q3_relax_cases.svg)

边权全正，Dijkstra 出堆的节点 $u$ 其最短路 $dist[u]$ 已经**定型**。于是节点 $v$ 的最短路条数有干净的递推：所有把 $v$ 的 $dist$「最后一次定型」的前驱 $u$（满足 $dist[u] + w = dist[v]$）恰好划分出全部最短路。在松弛边 $(u, v, w)$ 时分三种情况：

1. $dist[u] + w < dist[v]$：发现**更短**的路，$dist[v]$ 更新为 $dist[u] + w$，之前的计数全部作废，$ways[v] = ways[u]$；
2. $dist[u] + w = dist[v]$：找到一条**等长**最短路，$ways[v] \mathrel{+}= ways[u]$；
3. $dist[u] + w > dist[v]$：对 $dist[v]$ 无贡献，忽略。

**等价视角**：只保留满足 $dist[u] + w = dist[v]$ 的边，得到一张以 $dist$ 为层次的 DAG；$ways[v] = \sum_{(u,v,w) \in DAG} ways[u]$，按 $dist$ 升序计算即为拓扑序 DP——而 Dijkstra 的出堆顺序恰好就是这个拓扑序，两件事一次循环同时完成。

### 3.3 算法流程

```text
1. 建邻接表 g[u] = [(v, w), ...]（无向边两向各存一次）
2. dist[0] = 0, ways[0] = 1, 其余 dist = ∞；小根堆压入 (0, 0)
3. 重复直到堆空：
       弹出 (d, u)；若 d > dist[u] 说明是过期元素，跳过
       对每条邻边 (v, w)：
           nd = d + w
           若 nd < dist[v]：dist[v] = nd；ways[v] = ways[u]；压入 (nd, v)
           否则若 nd == dist[v]：ways[v] = (ways[v] + ways[u]) mod 1e9+7
4. 返回 ways[n−1]
```

### 3.4 示例演算

![示例演算：n = 7 的最短路 DAG 与计数表](images/bw59_q3_example_dag.svg)

以示例 1 为例，Dijkstra 出堆顺序为 $dist$ 非降序：$0(0) \to 1(2) \to 4(5) \to 2(5) \to 3(5) \to 5(6) \to 6(7)$。计数逐点累积：节点 1、4、2、3 各只有一条最短路；节点 5 由 $2 \to 5$ 与 $3 \to 5$ 两条等长（耗时 1）最短路汇入，$ways[5] = 2$；节点 6 的最短路（7 分钟）来自三个方向——直接边 $0 \to 6$（1 条）、经 $4 \to 6$（1 条）、经 $5 \to 6$（$ways[5] = 2$ 条），合计 $1 + 1 + 2 = 4$ 条，与官方答案一致。图中绿实线即构成最短路 DAG 的边。

## 4. 算法细节

1. **`long long` 存距离**：$time_i \le 10^9$、一条路径至多 $n - 1 = 199$ 条边，$dist$ 可达 $2 \times 10^{11}$，32 位 `int` 必爆；比较「等长」时也必须用同宽类型，避免隐式截断造成假相等。
2. **过期堆元素的处理**：懒删除 Dijkstra 允许同一节点多次入堆，弹出时 `d > dist[u]` 直接 `continue`。**注意过期元素不能用于计数**——它携带的旧 `dist` 不满足等长条件，跳过即安全。
3. **计数的取模时机**：每次累加后立刻 `% MOD`；`ways[u]` 在入堆前后可能被继续更新吗？不会——$u$ 出堆后 $dist[u]$ 定型、其入边不再可能等长（后文证明），但同一轮内多次弹出不同节点会重复累加吗？会且应当：不同 $u$ 是不同的前驱，累加正是 DP 求和。真正要防的是**同一 $u$ 被弹出多次都参与累加**，懒删除已排除。
4. **无向边双向建边**：本题求 $0 \to n-1$，图是无向的，邻接表两个方向都要加；计数不会因此重复（DAG 按层次只保留「由近到远」的边）。
5. **初始化 `ways[0] = 1`**：空路径的计数基底；`n = 1` 时直接返回 1，无需特判。
6. **为什么不能用 SPFA/queue BFS**：边权不等长，普通 BFS 层次失效；SPFA 节点可重复入队，计数要额外小心「同一节点多次定型」，不如堆版 Dijkstra 的「出堆即定型」干净。
7. **备选实现：DAG 拓扑 DP**：先跑纯 Dijkstra 求 $dist$，再把满足 $dist[u] + w = dist[v]$ 的边留下，按 $dist$ 排序后做一维 DP。与堆版等价，代码稍长但思路更显式（本题对拍即用此实现做第二参照）。

## 5. 正确性证明

**引理 1（出堆定型）**：非负权图上，节点 $u$ 以 $dist[u]$ 出堆（且非过期）后，$dist[u]$ 即为源点到 $u$ 的最短路长度，此后不再改变。

**证明**：归纳于出堆次序。归纳假设：此前每次弹出均定型。反设 $u$ 出堆时 $dist[u]$ 非最优，存在更短的路径 $P$ 到 $u$；$P$ 上必有一条边 $(x, y)$ 满足 $x$ 已定型且 $dist[x] + w(x,y) < dist[u] \le dist[u]$，从而 $y$ 在 $u$ 之前已以 $dist[y] \le dist[x] + w(x,y) < dist[u]$ 的键入堆，小根堆保证 $y$ 先于 $u$ 出堆，且 $y$ 定型时松弛 $(x,y)$（或更早）已把 $dist[u]$ 压到 $\le dist[x] + w(x,y) < dist[u]$，矛盾。∎

**引理 2（前驱分解）**：设 $v \ne 0$，$dist[v]$ 为最短路长。则 $v$ 的每条最短路最后一条边 $(u, v)$ 必满足 $dist[u] + w(u,v) = dist[v]$，其中 $dist[u]$ 为 $u$ 的最短路长；反之每条这样的边 $(u, v)$ 加上 $u$ 的任一条最短路都拼成 $v$ 的一条最短路，且该分解按最后一条边两两不交、完全覆盖。

**证明**：最短路 $P = P' + (u, v)$，前缀 $P'$ 是到 $u$ 的最短路（否则换更短前缀得 到 $v$ 更短路，矛盾），故 $dist[u] + w = dist[v]$。反之 $u$ 的最短路（长 $dist[u]$）接边 $(u,v)$ 总长 $dist[u] + w = dist[v]$，是最短路。不同末边给出不同路径；末边固定时前缀遍历 $u$ 的全部最短路，恰与 $ways[u]$ 逐条对应。∎

**引理 3（计数时序安全）**：节点 $v$ 首次以 $dist[v]$ 出堆之前，其计数的所有加法来源 $u$ 均已出堆定型且计数完成。

**证明**：由引理 2，来源 $u$ 满足 $dist[u] = dist[v] - w(u,v) \le dist[v] - 1 < dist[v]$（边权 $\ge 1$，故严格小），即 $u$ 的堆键严格小于 $v$ 的最终键；小根堆保证键更小的元素（含因更新而插入的更小键版本）先出，故 $u$ 在 $v$ 首次出堆前已以定型距离出堆。$u$ 出堆时其计数已完成——若仍有 $dist$ 更小的前驱未处理，与 $u$ 已定型矛盾（该前驱会给出更短 $dist[u]$）。∎

**定理**：算法终止时 $ways[n-1]$ 等于 $0$ 到 $n-1$ 最短路条数模 $10^9+7$。

**证明**：对出堆次序归纳证明「$v$ 首次出堆后 $ways[v]$ 为其最短路条数」。$v = 0$ 时空路径 1 条，初始化成立。设此前节点均成立。$v$ 首次出堆前，其计数经历若干「重置」（发现更短 $dist[v]$，计数替换为某 $ways[u]$）与若干「累加」（等长累加 $ways[u]$）。由引理 3，参与重置/累加的每个 $u$ 都已定型且 $ways[u]$ 正确；且**当 $dist[v]$ 达到最终值后**，全部满足 $dist[u] + w = dist[v]$ 的边（且仅这些边）按引理 2 完整覆盖 $v$ 的最短路分解。关键在于重置语义：每次 $dist[v]$ 变小时，旧计数对应末边 $(u', v)$ 的 $dist[u'] + w > dist[v]$ 已不是最短路末边，丢弃正确；$dist[v]$ 定型后所有等长松弛恰好各发生一次（每条入边在 $u$ 出堆时松弛恰一次，且 $u$ 只有效出堆一次），累加和 $= \sum_{(u,v): dist[u]+w=dist[v]} ways[u]$，由归纳假设即 $v$ 的最短路条数。∎

## 6. 复杂度分析

- **时间**：$O((n + m)\log n)$。堆中至多 $O(m)$ 个元素（每条有效松弛入堆一次），每次弹出/压入 $O(\log m) = O(\log n)$；$n \le 200$、$m \le \binom{200}{2} \approx 2 \times 10^4$，瞬间完成。
- **空间**：$O(n + m)$。邻接表 $O(m)$，`dist`/`ways` 数组 $O(n)$，堆 $O(m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countPaths(int n, vector<vector<int>>& roads) {
        const long long MOD = 1000000007LL;
        const long long INF = 1e18;
        vector<vector<pair<int, int>>> g(n);          // 邻接表：(邻点, 边权)
        for (const auto& r : roads) {
            g[r[0]].push_back({r[1], r[2]});
            g[r[1]].push_back({r[0], r[2]});
        }
        vector<long long> dist(n, INF);              // 最短路长度
        vector<long long> ways(n, 0);                // 最短路条数
        dist[0] = 0;
        ways[0] = 1;
        priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                       greater<pair<long long, int>>> pq;
        pq.push({0LL, 0});
        while (!pq.empty()) {
            auto [d, u] = pq.top();
            pq.pop();
            if (d > dist[u]) continue;               // 过期堆元素，跳过
            for (auto [v, w] : g[u]) {
                long long nd = d + w;
                if (nd < dist[v]) {                  // 发现更短路：计数重置
                    dist[v] = nd;
                    ways[v] = ways[u];
                    pq.push({nd, v});
                } else if (nd == dist[v]) {          // 等长最短路：计数累加
                    ways[v] = (ways[v] + ways[u]) % MOD;
                }
            }
        }
        return (int)(ways[n - 1] % MOD);
    }
};
```

### Python

```python
class Solution:
    def countPaths(self, n: int, roads: list[list[int]]) -> int:
        g = [[] for _ in range(n)]                   # 邻接表：(邻点, 边权)
        for u, v, w in roads:
            g[u].append((v, w))
            g[v].append((u, w))
        INF = float("inf")
        dist = [INF] * n                             # 最短路长度
        ways = [0] * n                               # 最短路条数
        dist[0] = 0
        ways[0] = 1
        pq = [(0, 0)]
        while pq:
            d, u = heappop(pq)
            if d > dist[u]:                          # 过期堆元素，跳过
                continue
            for v, w in g[u]:
                nd = d + w
                if nd < dist[v]:                     # 发现更短路：计数重置
                    dist[v] = nd
                    ways[v] = ways[u]
                    heappush(pq, (nd, v))
                elif nd == dist[v]:                  # 等长最短路：计数累加
                    ways[v] = (ways[v] + ways[u]) % MOD
        return ways[n - 1] % MOD
```

> ⚠️ Python 参考代码需在文件头部 `from heapq import heappush, heappop`（LeetCode 平台已内置，可直接提交）。

> 💡 两份代码均通过官方示例（`4`、`1`）与 $n = 1$ 边界，并与两个独立参照——**简单路径枚举暴力**与 **Floyd + 按 dist 排序 DAG 计数**——对拍 300 组随机连通图（$n \le 8$、树 + 随机额外边），三方全部一致。

## 8. 边界情况与易错点

1. **`long long` / 等长比较**：$dist$ 上界约 $2 \times 10^{11}$，C++ 用 `long long`；`nd == dist[v]` 若一边 `int` 一边 `long long` 会隐式转换后侥幸正确，但混合 `int` 累加 `d + w` 会先按 32 位溢出，务必全程 64 位。
2. **过期元素参与计数**：弹出 `(d, u)` 若 `d > dist[u]` 必须 `continue`；漏掉会把已被更短路淘汰的贡献重复累加进 `ways`。
3. **重置与累加的先后**：先判 `<` 再判 `==`，两者互斥；`<` 分支里 `ways[v] = ways[u]` 是**赋值**（旧的更长的计数作废），不是 `+=`。
4. **`ways` 忘取模**：路径数可达天文数字，每次累加后 `% (10^9+7)`；C++ 中两个 `long long` 相加不会溢出（各 $< 10^9$），安全。
5. **$n = 1$**：起点即终点，`ways[0] = 1` 直接返回，循环体自然跳过；别在入口特判返回 0。
6. **无向边只建单向**：忘记给 `g[v]` 也加 `(u, w)` 会导致部分最短路丢失，答案偏小。
7. **模意义下相等的陷阱**：`dist` 是真实数值比较（不取模），只有 `ways` 取模。若把 `dist` 也取模，等长判断彻底崩坏——两类量的取模纪律必须分清。
