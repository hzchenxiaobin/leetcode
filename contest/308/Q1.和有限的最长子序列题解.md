# LeetCode 和有限的最长子序列 题解

## 1. 题目概述

- **标题 / 题号**：和有限的最长子序列（#2389，easy）
- **链接**：https://leetcode.cn/problems/longest-subsequence-with-limited-sum/
- **来源**：LeetCode 第 308 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、排序、前缀和、二分查找

**题意**：给定长度为 $n$ 的正整数数组 `nums` 和长度为 $m$ 的数组 `queries`，对每个 `queries[i]` 求出：`nums` 中元素之和 **小于等于** `queries[i]` 的 **子序列** 的 **最大长度**，返回长为 $m$ 的答案数组。

**约束**：

- $1 \le n, m \le 1000$
- $1 \le \text{nums}[i], \text{queries}[i] \le 10^6$（**全为正数**，这是贪心合法的关键）

> 💡 **签到题切入**：题面里「子序列」三个字是烟雾弹——判定条件只有「元素和」与「长度」，二者都不依赖顺序，本题等价于「从 `nums` 中选子集」。再抓住 $\text{nums}[i] \ge 1$ **全正数**：固定长度 $k$ 时取**最小的 $k$ 个数**最省额度。于是「排序 + 前缀和 + 二分」三步收工，全场最短路径之一。

## 2. 示例

**示例 1**

```text
输入：nums = [4,5,2,1], queries = [3,10,21]
输出：[2,3,4]
解释：
  q = 3  → 取 [2,1]，和 3 ≤ 3，最大长度 2
  q = 10 → 取 [4,5,1]（即排序后前 3 小 [1,2,4]），和 7 ≤ 10，最大长度 3
  q = 21 → 全选 [4,5,2,1]，和 12 ≤ 21，最大长度 4
```

**示例 2**

```text
输入：nums = [2,3,4,5], queries = [1]
输出：[0]
解释：最小的数是 2，也超过 1，只有空子序列（和为 0）合法。
```

**示例 3**（自构造：覆盖「重复元素 + 恰好取等」的情形）

```text
输入：nums = [3,3,3], queries = [7,9]
输出：[2,3]
解释：排序不改变重复值，pre = [0,3,6,9]。
  q = 7  → pre[2] = 6 ≤ 7 < pre[3] = 9 → 答案 2
  q = 9  → pre[3] = 9 ≤ 9（取等合法）→ 答案 3
```

## 3. 解题思路

### 3.1 暴力思路：每个 query 现场挑最小的数

最朴素的想法是对每个 `q` 把 `nums` 从小到大逐个累加，一旦超过 `q` 就停，当前个数即答案。排序一次 + 每次 $O(n)$ 线性扫，总时间 $O(n \log n + nm)$；$n, m \le 1000$ 时约 $10^6$，**能过**。至于枚举全部子集（$2^n$）则完全不可行。

问题在于：排序结果和累加过程被 $m$ 个 query **重复劳动** 了 $m$ 遍。把「前 $k$ 小之和」预处理成前缀和数组，每个 query 就只需一次 $O(\log n)$ 的二分。

### 3.2 核心观察：排序贪心 + 前缀和

![核心观察：和与顺序无关 + 全正数 → 排序取最小 k 个](images/limited_sum_greedy_concept.svg)

三个层层递进的观察：

- **观察一（顺序无关）**：子序列由「删除若干元素、不改变剩余顺序」得到，但题目只关心所选元素的**和**与**个数**，二者在任意重排下不变 → 问题等价于「从 `nums` 的多重集中选一个子集」。
- **观察二（全正数贪心）**：固定长度 $k$，最小可能和恰为排序后**前 $k$ 个数之和**（交换论证：方案若含大数 $x$ 而漏掉小数 $y < x$，用 $y$ 换 $x$ 后长度不变、和不增）。因此「长度 $k$ 是否可行」只需检查一个数——前 $k$ 小之和 $\text{pre}[k]$。
- **观察三（单调可二分）**：$\text{nums}[i] \ge 1$ 使 $\text{pre}$ **严格递增**，于是满足 $\text{pre}[k] \le q$ 的 $k$ 连成一段前缀区间 $\{0, 1, \ldots, K\}$，答案即右端点 $K$，二分可得。

$$\text{answer}[i] = \max\{\, k : \text{pre}[k] \le \text{queries}[i] \,\}$$

### 3.3 算法流程

![模型：排序 → 前缀和阶梯 → 二分找最后一个不超过 q 的柱子](images/limited_sum_prefix_staircase.svg)

1. 将 `nums` 升序排序；
2. 计算前缀和 `pre[0..n]`，其中 `pre[0] = 0`（对应空子序列）；
3. 对每个 `q = queries[i]`：在 `pre` 上二分，找**最后一个 ≤ q** 的位置 $k$；
4. `answer[i] = k`，返回 `answer`。

### 3.4 示例演算

![示例演算：三个 query 各自二分定位](images/limited_sum_example_walkthrough.svg)

以 `nums = [4,5,2,1]`、`queries = [3,10,21]` 为例，排序得 `[1,2,4,5]`，`pre = [0,1,3,7,12]`：

| query | 最后一个 ≤ q 的前缀和 | 临界比较 | answer | 对应子序列（前 k 小） |
|-------|----------------------|----------|--------|----------------------|
| 3 | pre[2] = 3 | pre[3] = 7 > 3 | 2 | [2,1]，和 3 |
| 10 | pre[3] = 7 | pre[4] = 12 > 10 | 3 | [1,2,4]，和 7 |
| 21 | pre[4] = 12 | 已到末尾 | 4 | [1,2,4,5]，和 12 |

## 4. 算法细节

1. **二分语义**：用「第一个 **大于** $q$ 的位置」再减 1，即得「最后一个 **小于等于** $q$ 的位置」。C++ 是 `upper_bound(pre.begin(), pre.end(), q) - pre.begin() - 1`，Python 是 `bisect_right(pre, q) - 1`。
2. **`pre[0] = 0` 必须保留**：它对应空子序列。由于 $q \ge 1 > 0$，`upper_bound` 至少落在下标 1，减 1 后结果 $\ge 0$——**答案为 0 的情形（示例 2）被天然处理**，无需特判。
3. **为什么可以二分**：$\text{pre}[k+1] - \text{pre}[k] = \text{nums}_{(k+1)} \ge 1 > 0$，`pre` 严格递增，检查条件单调。若允许 `nums[i] = 0`，前缀和变为非严格递增，但 `upper_bound` 的语义（越过所有等号）依然正确。
4. **原地排序**：LeetCode 传引用可直接 `sort(nums)`；工程上若不可破坏输入，复制一份即可，复杂度不变。
5. **等价的离线写法**：把 `queries` 连下标排序后与 `pre` 双指针推进，可做到 $O(n \log n + m \log m)$ 后线性合并；本题 $n, m \le 1000$ 无此必要，二分版代码最短。

## 5. 正确性证明

**引理 1**（顺序无关）：存在和 $\le q$ 的长度为 $k$ 的子序列，当且仅当存在和 $\le q$ 的 $k$ 元子集。

**证明**：子序列由保序删除得到，其元素恰构成一个 $k$ 元子集，二者和与长度相同；反之，任取 $k$ 元子集，按各元素在原数组中出现的相对顺序排列，即得一个合法子序列。∎

**引理 2**（最小 $k$ 元子和）：设排序后 $a_1 \le a_2 \le \cdots \le a_n$，则任意 $k$ 元子集 $S$ 的和 $\ge \text{pre}[k] = a_1 + \cdots + a_k$。

**证明**（交换论证）：令 $T = \{a_1, \ldots, a_k\}$。若 $S \ne T$，由 $|S| = |T| = k$ 知存在 $x \in S \setminus T$ 与 $y \in T \setminus S$。设 $x = a_j$（$j > k$）、$y = a_i$（$i \le k$），则 $y = a_i \le a_j = x$。令 $S' = S - \{x\} + \{y\}$，则 $|S'| = k$ 且 $\text{sum}(S') = \text{sum}(S) - x + y \le \text{sum}(S)$，同时 $|S' \cap T| \ge |S \cap T| + 1$。每轮交换使 $|S \cap T|$ 严格增大且和不增，至多 $k$ 轮后 $S = T$，故 $\text{sum}(S) \ge \text{sum}(T) = \text{pre}[k]$。∎

**引理 3**（前缀和严格递增）：$\text{pre}[k+1] - \text{pre}[k] = a_{k+1} \ge 1$，故 `pre` 关于 $k$ 严格递增，从而 $\{\, k : \text{pre}[k] \le q \,\}$ 形如 $\{0, 1, \ldots, K\}$（至少含 0，因为 $\text{pre}[0] = 0 \le q$）。

**证明**：由 $\text{nums}[i] \ge 1$ 直接得单调性；集合是前缀段因为若 $\text{pre}[k] \le q$ 且 $k' < k$，则 $\text{pre}[k'] < \text{pre}[k] \le q$。∎

**定理**：$\text{answer}[i] = \max\{\, k : \text{pre}[k] \le \text{queries}[i] \,\}$，且二分（`upper_bound` 前移一位）返回该值。

**证明**：（存在性）若 $\text{pre}[K] \le q$：前 $K$ 小的元素本身构成和为 $\text{pre}[K]$ 的 $K$ 元子集，由引理 1 对应长 $K$ 的合法子序列，故最大长度 $\ge K$。（最优性）若存在长 $k$ 的合法子序列，由引理 1 其对应 $k$ 元子集和 $\le q$，由引理 2 $\text{pre}[k] \le q$，故合法长度不超过 $\max\{\, k : \text{pre}[k] \le q \,\}$。两个方向合起来即等式；由引理 3 该集合是连续前缀段，`upper_bound` 找到第一个 $> q$ 的位置，其前一位下标即右端点 $K$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n + m \log n)$。排序 $O(n \log n)$，前缀和 $O(n)$，每个 query 二分 $O(\log n)$ 共 $O(m \log n)$；$n, m \le 1000$ 时总量约 $10^4$，远低于暴力版的 $10^6$。
- **空间复杂度**：$O(n)$。排序原地，`pre` 数组 $n+1$ 个元素；不计返回的答案数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> answerQueries(vector<int>& nums, vector<int>& queries) {
        sort(nums.begin(), nums.end());                 // 升序：小的先选
        int n = nums.size();
        vector<long long> pre(n + 1);                   // pre[0]=0 对应空子序列
        for (int i = 0; i < n; ++i) pre[i + 1] = pre[i] + nums[i];
        vector<int> answer;
        answer.reserve(queries.size());
        for (int q : queries)
            // 第一个 > q 的位置减 1 = 最后一个 <= q 的位置
            answer.push_back(upper_bound(pre.begin(), pre.end(), (long long)q)
                             - pre.begin() - 1);
        return answer;
    }
};
```

### Python

```python
from bisect import bisect_right

class Solution:
    def answerQueries(self, nums: List[int], queries: List[int]) -> List[int]:
        nums.sort()                                     # 升序：小的先选
        pre = [0]                                       # pre[0]=0 对应空子序列
        for x in nums:
            pre.append(pre[-1] + x)
        # bisect_right 找第一个 > q 的位置，减 1 即最后一个 <= q 的位置
        return [bisect_right(pre, q) - 1 for q in queries]
```

## 8. 边界情况与易错点

1. **「小于等于」不是「小于」**：恰好取等合法（示例 1 中 $q = 3 = \text{pre}[2]$），所以必须用 `upper_bound` / `bisect_right` 而不是 `lower_bound` / `bisect_left`，否则取等情形答案少 1。
2. **off-by-one**：`upper_bound` 返回的是「第一个 $> q$」的**迭代器**，记得整体减 1 才是答案；漏掉 `-1` 会把 $q = 21$ 算成 5。
3. **保留 `pre[0] = 0`**：它代表空子序列，是「一个数都装不下」时答案为 0 的来源（示例 2）。若前缀和数组从 1 开始编号且单独特判 0，代码更长还容易漏。
4. **全选情形**：$q \ge \text{pre}[n]$ 时二分返回 `end()` 位置 $n+1$，减 1 恰为 $n$，无需特判。
5. **数值范围**：$n \le 1000$、$\text{nums}[i] \le 10^6$，前缀和最大 $10^9 < 2^{31} - 1 \approx 2.1 \times 10^9$，`int` 不会溢出，但已贴近上限，C++ 习惯性用 `long long` 更稳；Python 无此顾虑。
6. **别被「子序列」带偏**：不需要 DP 求所有子序列，更不要枚举 $2^n$ 个子集——顺序信息在判定条件中根本不出现。
7. **原地排序副作用**：直接 `sort(nums)` 修改了输入数组，LeetCode 判题无碍；若接口语义要求只读，先复制。
