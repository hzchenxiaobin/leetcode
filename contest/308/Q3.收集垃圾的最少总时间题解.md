# LeetCode 收集垃圾的最少总时间 题解

## 1. 题目概述

- **标题 / 题号**：收集垃圾的最少总时间（#2391，medium）
- **链接**：https://leetcode.cn/problems/minimum-amount-of-time-to-collect-garbage/
- **来源**：LeetCode 第 308 场周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、前缀和、贪心

**题意**：街道上有 $n$ 栋房子，`garbage[i]` 是第 $i$ 栋的垃圾清单——串里每个字符（`M` / `P` / `G`）代表一单位金属 / 纸 / 玻璃垃圾，收拾一单位**任意**垃圾固定花 1 分钟。`travel[i]` 是从房子 $i$ 开到房子 $i+1$ 的分钟数。三辆垃圾车各管一类垃圾，都从房子 0 出发、**按房子顺序前进**、不必走完全程；**任一时刻只有一辆车在使用**（其余两辆不能动）。求收完全部垃圾的最少总时间。

**约束**：

- $2 \le \text{garbage.length} \le 10^5$
- `garbage[i]` 仅含 `M`、`P`、`G`，$1 \le \text{garbage[i].length} \le 10$
- `travel.length == garbage.length - 1`，$1 \le \text{travel[i]} \le 100$

> 💡 **一句话切入**：看似三车调度的外壳，拆开只有两笔账——**收集账**（每件垃圾 1 分钟，总额固定）与**行驶账**（每辆车只需开到「自己那类垃圾最后出现的房子」）。独占约束恰恰是礼物：没有并行，总时间就是三辆车各自时间的**简单相加**，谁先谁后都一样。

## 2. 示例

**示例 1**

```text
输入：garbage = ["G","P","GP","GG"], travel = [2,4,3]
输出：21
解释：收集 6 件 = 6 分钟（固定）。
P 车最后停在房 2：行驶 2+4 = 6；G 车最后停在房 3：行驶 2+4+3 = 9；M 车无金属垃圾，0 分钟。
总时间 = 6 + 6 + 9 = 21。
```

**示例 2**

```text
输入：garbage = ["MMM","PGM","GP"], travel = [3,10]
输出：37
解释：共 8 件垃圾 → 收集 8 分钟。
M 最后出现在房 1（行驶 3），P、G 最后都在房 2（行驶 3+10 = 13）。
总时间 = 8 + 3 + 13 + 13 = 37。
```

**示例 3**（自构造：覆盖「某类垃圾只出现在房子 0，行驶为 0」的情形）

```text
输入：garbage = ["GM","P","PP"], travel = [5,2]
输出：17
解释：共 5 件 → 收集 5 分钟。G 只在房 0 → 行驶 0；M 最后在房 1 → 5；P 最后在房 2 → 5+2 = 7。
总时间 = 5 + 0 + 5 + 7 = 17。
```

## 3. 解题思路

### 3.1 暴力思路与「想复杂」的陷阱

这题的坑不在复杂度，而在**问题定性**。比赛时最容易掉进两个歧途：

- **歧途一：当成调度 / DP 题**。注意到「任一时刻只有一辆车在使用」，以为要规划三辆车的执行顺序与交错方式，于是设计状态 $(\text{pos}_M, \text{pos}_P, \text{pos}_G, \text{哪辆车在动})$——位置组合就有 $O(n^3)$ 种，$n = 10^5$ 时状态数 $10^{15}$，直接爆炸。而且这个方向本身就是错的：**顺序根本不影响总时间**（见观察二）。
- **歧途二：分钟级模拟**。把时间轴切成一分钟一分钟，每分钟决定哪辆车移动或收拾。答案上限约 $3 \times 10^7$ 分钟，模拟本身勉强跑得动，但「每分钟怎么决策」又把你拖回歧途一。

而老实的模拟——对每辆车，从房 0 逐栋走到该类垃圾最后出现的房子，逐边累加 `travel`、逐件累加 1 分钟——其实已经是 $O(n + \sum|\text{garbage[i]}|)$ 的正确算法。所以真正的问题是：**为什么这样做是最优的？** 把这个想穿，代码就能压缩成一遍扫描。

### 3.2 核心观察：两笔账拆分 + 直达最远垃圾房

![核心观察：每辆车只开到「自己垃圾」最后出现的房子](images/garbage_last_house_concept.svg)

三个层层递进的观察：

- **观察一（收集账固定）**：每单位垃圾固定 1 分钟，且 $X$ 类垃圾只能由 $X$ 车收拾（车与垃圾类型一一对应）。所以无论怎么安排，收集总时长 $=$ 垃圾总件数，一分不多一分不少——这部分**没有优化空间，也不需要优化空间**。
- **观察二（独占 ⟹ 时间可加）**：任一时刻只有一辆车在工作，三辆车的工作时段两两不重叠，总时间 $=$ 三辆车各自时长之**和**。要最小化总和，只需每辆车各自取最小——三辆车完全**解耦**，没有任何「穿插配合」的收益。
- **观察三（目的地 $=$ 最后出现位置）**：$X$ 车必须收完所有 $X$ 垃圾，就必须至少到达 $X$ 垃圾**最后出现**的房子 $L_X$；而车只能向前开，多走一栋纯浪费。所以 $X$ 车的最优策略就是**从房 0 直达 $L_X$**，沿途顺路收光，行驶时长恰为 `travel` 的前缀和 $\text{pre}(L_X)$。

> 💡 「开到最远出现位置」与 763. 划分字母区间里「按字符最后出现位置合并区间」是同一个观察——都在问「这类资源最远延伸到哪里」。前缀和只是把逐边累加提前算好。

### 3.3 算法流程

![算法流程：单遍扫街，顺手记账](images/garbage_algorithm_flow.svg)

1. 初始化 `ans = 0`、`dist = 0`、`last[M] = last[P] = last[G] = 0`。`dist` 是「房 0 → 当前房子」的行驶前缀和；`last[c]` 是 $c$ 类垃圾最后出现时对应的 `dist`；
2. 从左到右遍历房子 $i = 0, 1, \dots, n-1$：
   - 遍历 `garbage[i]` 的每个字符 `c`：`ans += 1`（收集 1 分钟）；`last[c] = dist`（后写覆盖，天然记成「最后出现」）；
   - 若 $i < n-1$：`dist += travel[i]`（驶向下一栋）；
3. 答案 $=$ `ans + last[M] + last[P] + last[G]`。

### 3.4 示例演算

![示例演算：逐房推进的 ans 与 last 账本](images/garbage_example_walkthrough.svg)

以示例 1 为例，`dist` 滚动累计 `travel`，`last[c]` 每遇该类字符就被覆盖为当前 `dist`：

| 房子 $i$ | garbage[i] | dist(0→i) | 逐件收集 | last_M | last_P | last_G |
|------|------|------|------|------|------|------|
| 0 | `G` | 0 | G：ans → 1 | 0 | 0 | **0** |
| 1 | `P` | 2 | P：ans → 2 | 0 | **2** | 0 |
| 2 | `GP` | 6 | G、P：ans → 4 | 0 | **6** | **6** |
| 3 | `GG` | 9 | G、G：ans → 6 | 0 | 6 | **9** |

扫完：收集账 $= 6$，行驶账 $= 0 + 6 + 9 = 15$，总时间 $= 21$ ✓。注意 M 全程未出现，`last[M]` 保持初始值 0，恰好表示「M 车不出发」。

## 4. 算法细节

1. **不建显式前缀和数组**：`dist` 滚动累加即可；且记录 `last[c] = dist`（值）而不是记下标再回头查前缀和，一步到位，额外空间 $O(1)$。
2. **后写覆盖 $=$ 最后出现**：`last[c]` 在扫描中被同类型的后续字符反复覆盖，扫完天然是「最后出现」对应的值，无需 `max`、无需排序。
3. **初始化为 0 的巧妙**：某类垃圾若从未出现，`last[c]` 保持 0，恰好表示「这辆车不出发、行驶 0 分钟」——连特判都省了。若改记下标（$-1$ 表示不出现），最后要记得判掉。
4. **C++ 遍历 `string`**：range-for 即可；`garbage[i]` 至多 10 个字符，内层常数极小。分支用 `if/else if` 连判三次足矣，无需哈希表。
5. **范围分析**：垃圾件数 $\le 10^5 \times 10 = 10^6$；行驶总和 $\le 3 \times (10^5 \times 100) = 3 \times 10^7$；总答案 $< 3.1 \times 10^7$，`int`（上限约 $2.1 \times 10^9$）安全。用 `long long` 只是防御性习惯，不是必需。

## 5. 正确性证明

设 $X \in \{M, P, G\}$，其最后出现的房子为 $L_X$（不出现则该车时长为 0），件数为 $\text{cnt}_X$。记 $\text{pre}(i) = \sum_{j < i} \text{travel}[j]$ 为房 0 到房 $i$ 的直达行驶时长。

**引理 1**（收集账不变量）：任意可行方案中，三辆车收拾垃圾的总时长恰为垃圾总件数 $N = \sum_i |\text{garbage}[i]|$。

**证明**：$X$ 类垃圾只能由 $X$ 车收拾，每单位恰花 1 分钟，故收集总时长 $= \sum_X \text{cnt}_X = N$，与路线、顺序均无关。∎

**引理 2**（单车时长下界）：$X$ 车的工作时长 $T_X \ge \text{cnt}_X + \text{pre}(L_X)$。

**证明**：房 $L_X$ 处有 $X$ 垃圾，$X$ 车必须抵达 $L_X$；车从房 0 出发且按房子顺序前进，必经边 $0\text{-}1, 1\text{-}2, \dots, (L_X\text{-}1)\text{-}L_X$ 各至少一次，行驶时长 $\ge \text{pre}(L_X)$（每条边时长为正）。又它必须收拾全部 $\text{cnt}_X$ 件，收拾时长 $= \text{cnt}_X$。相加即得下界。∎

**引理 3**（时间可加）：任意可行方案的总时长 $\ge T_M + T_P + T_G$；且存在总时长 $= T_M + T_P + T_G$ 的方案。

**证明**：任一时刻至多一辆车在使用，各车工作时段两两不重叠，故总时长（含可能空闲）$\ge \sum_X T_X$。把三辆车的工作依次串行排开、无空档，即取等。∎

**定理**：最少总时间 $= N + \sum_{X} \text{pre}(L_X)$，由「每辆车直达自己垃圾最后出现的房子、沿途收光」达到。

**证明**：下界：由引理 3 与引理 1，总时长 $\ge T_M + T_P + T_G \ge \sum_X (\text{cnt}_X + \text{pre}(L_X)) = N + \sum_X \text{pre}(L_X)$。构造：令 $X$ 车从房 0 直达 $L_X$，沿途把每栋经过的房子里的 $X$ 垃圾全部收拾（不出现则不出发，时长 0）；由于车按序前进且停在最远出现处，恰好收光全部 $X$ 垃圾，时长 $= \text{cnt}_X + \text{pre}(L_X)$。三辆串行（引理 3）得总时长恰为 $N + \sum_X \text{pre}(L_X)$ 的可行方案。下界与构造相等，故为最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O\!\left(\sum_i |\text{garbage}[i]| + n\right)$。外层遍历 $n$ 栋房子，内层每个字符 $O(1)$；`dist` 每条边累加一次 $O(1)$。总量不超过 $10^5 \times 10 + 10^5 \approx 1.1 \times 10^6$。
- **空间复杂度**：$O(1)$ 额外空间。不建前缀和数组（滚动维护），只有 `dist` 与三个 `last` 变量；也不需要哈希表计数。

## 7. 参考代码

### C++

一遍扫描版（主推）：`dist` 滚动前缀和，`last` 记「最后出现时的行驶值」。

```cpp
class Solution {
public:
    int garbageCollection(vector<string>& garbage, vector<int>& travel) {
        int ans = 0;                                // 收集账：每件垃圾 +1
        int dist = 0;                               // 行驶账：房 0 → 当前房子的前缀和
        int lastM = 0, lastP = 0, lastG = 0;
        int n = garbage.size();
        for (int i = 0; i < n; ++i) {
            for (char c : garbage[i]) {
                ++ans;                              // 收拾这件垃圾：1 分钟
                if (c == 'M')      lastM = dist;    // 后写覆盖 → 最后出现
                else if (c == 'P') lastP = dist;
                else               lastG = dist;
            }
            if (i + 1 < n) dist += travel[i];       // 驶向下一栋（防越界）
        }
        return ans + lastM + lastP + lastG;
    }
};
```

两遍版（先记下标，再扫一遍前缀和，思路更直白）：

```cpp
class Solution {
public:
    int garbageCollection(vector<string>& garbage, vector<int>& travel) {
        int n = garbage.size();
        int lastM = -1, lastP = -1, lastG = -1;     // -1 = 全街没有这类垃圾
        int ans = 0;
        for (int i = 0; i < n; ++i)
            for (char c : garbage[i]) {
                ++ans;
                if (c == 'M')      lastM = i;
                else if (c == 'P') lastP = i;
                else               lastG = i;
            }
        int dist = 0;
        for (int i = 0; i + 1 < n; ++i) {
            dist += travel[i];
            if (i + 1 == lastM) ans += dist;        // 到达某车的最远房子
            if (i + 1 == lastP) ans += dist;
            if (i + 1 == lastG) ans += dist;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def garbageCollection(self, garbage: List[str], travel: List[int]) -> int:
        ans = 0
        dist = 0
        last = {'M': 0, 'P': 0, 'G': 0}
        n = len(garbage)
        for i, g in enumerate(garbage):
            for c in g:
                ans += 1
                last[c] = dist          # 后写覆盖 → 最后出现
            if i + 1 < n:
                dist += travel[i]       # 驶向下一栋
        return ans + last['M'] + last['P'] + last['G']
```

## 8. 边界情况与易错点

1. **`travel` 越界**：`travel` 长度是 $n-1$，最后一栋房子后面没有边——`dist += travel[i]` 必须用 `i + 1 < n` 守卫（或干脆只遍历到 $n-2$），否则越界。
2. **某类垃圾完全不存在**：`last` 初始 0 天然表示「不出发」；若用下标版初始化 `-1`，注意 $-1$ 永远不会匹配 `i + 1`，别把它当数组下标用。
3. **重复字符就是多件**：`garbage[i] = "GG"` 是**两件**玻璃、各 1 分钟；千万别按「字符种类数」计数。
4. **别把独占约束当调度题**：三辆车串行执行，先后顺序、是否穿插都不影响总和；任何 DP / 交错规划都是白费功夫——这是本题最大的思维陷阱。
5. **收集时间别漏算**：常见 WA 是只加了行驶时间；收集账虽固定，也是答案的一部分（件数最多 $10^6$，比行驶账还大）。
6. **溢出核对**：本题上限约 $3.1 \times 10^7$，`int` 安全；若数据范围放大（如 `travel[i] ≤ 10^9`）必须换 `long long`。
7. **房子 0 的特殊性**：所有车都从房 0 出发，房 0 的垃圾行驶成本为 0（示例 3 的 G 车）；没有「倒车」或「跳过再回来」的说法——车只能按序前进。
