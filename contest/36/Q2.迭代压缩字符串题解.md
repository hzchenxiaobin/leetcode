# LeetCode 迭代压缩字符串 题解

## 1. 题目概述

- **标题 / 题号**：迭代压缩字符串（#604，easy）
- **链接**：https://leetcode.cn/problems/design-compressed-string-iterator/
- **来源**：LeetCode 第 36 场周赛 Q2
- **难度**：简单
- **标签**：设计、数组、字符串、迭代器

**题意**：压缩串 `s` 由若干「字母 + 正整数」块首尾相接组成，字母 `c` 后跟 $k$ 表示解压串中连续出现 $k$ 个 `c`。实现迭代器 `StringIterator`：

- `next()`：返回解压串的下一个字符；若已全部输出，返回空格 `' '`。
- `hasNext()`：返回解压串中是否还有字符未输出。

注意**不允许真的把字符串解压出来**——单个块的重复次数可以到 $10^9$。

**约束**：

- $1 \le |s| \le 1000$
- `s` 由大小写英文字母与数字组成，每个字母后必跟一个正整数
- 单个字母的重复次数 $k \in [1, 10^9]$
- `next` / `hasNext` 的调用总次数不超过 $10^3$ 量级
- 类变量 / 静态变量跨测试用例保留，必须在构造函数中重置

## 2. 示例

**示例 1**（官方）

```text
输入：StringIterator("L1e2t1C1o1d1e1")
      next() × 7 → hasNext() → next() → hasNext() → next()
输出：'L','e','e','t','C','o','d',  true, 'e',  false, ' '
解释：解压串为 "LeetCode"；前 7 次 next 输出 L,e,e,t,C,o,d，
      此时还剩最后一个 'e'（e1 块），hasNext() 为 true；
      第 8 次 next 返回 'e'，随后 hasNext() 为 false，再 next() 返回空格。
```

**示例 2**（块内 hasNext：`i` 已到串尾但 `cnt` 仍大于 0）

```text
输入：StringIterator("a5")
      next(), next(), next(), hasNext(), next(), hasNext(), next()
输出：'a', 'a', 'a', true, 'a', true, 'a'
解释：前 3 次 next 之后 i = 2 = n，但本块还剩 2 个字符，
      hasNext() 必须仍为 true —— 只判断 i < n 就会错。
```

**示例 3**（多位数字 + 耗尽后返回空格）

```text
输入：StringIterator("a12b3")
      next() × 12 → hasNext() → next() → hasNext() → next() → hasNext() → next()
                   → hasNext() → next()
输出：'a' × 12, true, 'b', true, 'b', true, 'b', false, ' '
解释：数字 "12" 是多位的，必须整段解析；3 个 'b' 输出完 hasNext() 才为 false，
      此后 next() 返回空格。
```

## 3. 解题思路

### 3.1 暴力思路

两种朴素做法都写得出，但都有硬伤：

1. **构造时完整解压**：把 `s` 展开成真字符串再按下标游走。正确，但 $\sum k$ 最坏约 $500 \times 10^9 = 5\times10^{11}$ 个字符，内存直接需要数百 GB，必然 MLE。
2. **每次 `next` 从头扫描定位**：维护「已输出个数 $p$」，每次重新遍历压缩串找到第 $p$ 个字符所在块。单次 $O(|s|)$，总计 $O(|s| \cdot m)$。在 $|s|, m \le 10^3$ 时勉强能过，但它把「游标 + 剩余计数」这件显然的事做成了平方级，而且每次调用都重复解析同一段数字。

矛盾点很清楚：**解压串极长（$10^{11}$ 量级），调用次数却极少（$10^3$）** —— 所以只能「按需解压」。

### 3.2 核心观察：一个游标 + 一份剩余计数

![惰性解码：只维护 (i, cur, cnt)](images/wc36_q2_lazy_decode_concept.svg)

把「解压串的剩余部分」拆成两段：

$$\text{剩余输出} = \underbrace{cur \cdots cur}_{cnt\ \text{个}} + \mathrm{decode}(s[i..])$$

- `i`：压缩串中**第一个尚未解析**的下标；
- `cur`：当前块的字母；`cnt`：当前块还没输出的个数。

于是 `next()` 只需两步：若 `cnt > 0` 就吐出 `cur` 并 `cnt--`；否则先解析下一个块（读字母、再整段读数字），再吐。`hasNext()` 只看 `cnt > 0 || i < n`。

整个迭代器只保存 3 个标量，与解压长度完全无关。

### 3.3 算法流程

![next() / hasNext() 执行流程](images/wc36_q2_iterator_flow.svg)

1. **构造**：保存 `s`、`n = |s|`，令 `i = 0, cnt = 0, cur = ' '`。$O(1)$，不做任何解析。
2. **`hasNext()`**：返回 `cnt > 0 || i < n`。
3. **`next()`**：
   - 若 `!hasNext()`：返回 `' '`，**不改变状态**；
   - 若 `cnt == 0`：`cur = s[i++]`，循环 `num = num * 10 + (s[i] - '0')` 整段读数字，然后 `cnt = num`；
   - `cnt--`，返回 `cur`。

**为什么必须「`cnt` 归零才解析」**：一次 `next` 只消费一个字符，同一块的其余 $k-1$ 次调用与解析无关。若每次调用都重新定位数字段，一个块的 $k$ 次调用会各自花 $O(\text{块长})$，总代价退化成平方级。

### 3.4 示例演算

![示例走查表](images/wc36_q2_example_walkthrough.svg)

对 `s = "L1e2t1C1o1d1e1"`（解压得 `"LeetCode"`，7 个块、共 14 个字符）：

| 调用 | 调用前 $(i, cur, cnt)$ | 本次是否解析 | 返回 |
|------|------------------------|--------------|------|
| `next` | $(0,\ -,0)$ | 是（读 `L`、`1`） | `L` |
| `next` | $(2,L,0)$ | 是（读 `e`、`2`） | `e` |
| `next` | $(4,e,1)$ | **否** | `e` |
| `next` | $(4,e,0)$ | 是（读 `t`、`1`） | `t` |
| `next` | $(6,t,0)$ | 是（读 `C`、`1`） | `C` |
| `next` | $(8,C,0)$ | 是（读 `o`、`1`） | `o` |
| `next` | $(10,o,0)$ | 是（读 `d`、`1`） | `d` |
| `hasNext` | $(12,d,0)$ | 否 | `true` |
| `next` | $(12,d,0)$ | 是（读 `e`、`1`） | `e` |
| `hasNext` | $(14,e,0)$ | 否 | `false` |
| `next` | $(14,e,0)$ | 否（空分支） | `' '` |

7 个块各解析一次，全部调用合计只扫描 14 个字符；第 3 行的块内调用完全不碰数字。

## 4. 算法细节

1. **`i` 的语义固定为「下一个块的字母」**：解析块时先取字母 `s[i++]`，再吞掉整段数字，于是解析结束后 `i` 自动落到下一个字母（或 `n`），`i < n` 恰好等价于「还有整块没解析」。
2. **`hasNext()` 必须是两个条件的并**：`cnt > 0 || i < n`。漏掉 `cnt > 0` 会在「串已读完、当前块还剩若干字符」时误报 `false`（示例 2 就是这个坑）。
3. **数字整段解析**：`while (i < n && isdigit(s[i])) num = num * 10 + (s[i] - '0'), i++;`。只读一位会在 `"a12b3"` 上把 12 当成 1，输出数量全错。
4. **计数类型选 `long long`**：$k \le 10^9$ 刚好卡在 `int` 上界（$2.147\times10^9$）之内，看似安全；但只要上界被放宽到 $10^{10}$，累加式 `num = num * 10 + d` 就会在最后一步中途溢出。用 `long long` 一次性消掉这个隐患，Python 无此问题。
5. **耗尽分支不改状态**：`if (!hasNext()) return ' ';` 之后不要顺手动 `i`、`cnt`，否则后续 `hasNext()` / `next()` 的行为会漂移（这也保证了「耗尽后反复调用结果恒为空格」）。
6. **构造函数里重置所有成员**：题面 Note 明确要求。C++ 把 `i = cnt = 0` 写在构造函数体内，Python 在 `__init__` 中赋初值——多组测试用例复用同一实例时，脏状态是隐蔽 WA 的常见来源。
7. **返回单个字符**：C++ `char`、Python 单字符 `str`、Java `char`；空格用 `' '`（ASCII 32），不是 `'\0'`。

## 5. 正确性证明

设 $s$ 解压得到的字符串为 $U$，$\mathrm{decode}(s[i..])$ 表示从下标 $i$ 起剩余压缩段的解压结果。

**引理 1（状态不变量）**：任意时刻，尚未输出的字符序列恰为

$$\mathrm{rem} = \underbrace{cur \cdots cur}_{cnt} + \mathrm{decode}(s[i..])$$

**证明**：对调用次数归纳。

- 初始时 `cnt = 0, i = 0`，$\mathrm{rem} = \varepsilon + \mathrm{decode}(s) = U$，成立。
- `hasNext()` 只读不写，不变量保持。
- `next()` 且 `cnt > 0`：输出 `cur` 并令 `cnt ← cnt - 1`，新剩余为 $cur^{cnt-1} + \mathrm{decode}(s[i..])$，恰是原 `rem` 去掉首字符。
- `next()` 且 `cnt = 0`：此时 $\mathrm{rem} = \mathrm{decode}(s[i..])$。由压缩串合法性，$s[i]$ 为字母、其后紧跟一段连续数字，解析得字母 $c$、次数 $k'$，且 $\mathrm{decode}(s[i..]) = c^{k'} + \mathrm{decode}(s[i_{\text{new}}..])$。令 `cur = c`、`cnt = k' - 1` 并输出一个 $c$，新剩余正是原 `rem` 去掉首字符。
- `next()` 且 `!hasNext()`：由引理 2 知 `rem` 为空，本次不输出任何字符，不变量保持。∎

**引理 2（`hasNext` 判定精确）**：`hasNext()` 返回 true $\iff$ `rem` 非空。

**证明**：由引理 1，$|\mathrm{rem}| = cnt + \lvert \mathrm{decode}(s[i..]) \rvert$，且 $\lvert \mathrm{decode}(s[i..]) \rvert = 0 \iff i = n$（压缩串非空后缀解压后长度至少为 1）。故 $|\mathrm{rem}| > 0 \iff cnt > 0 \lor i < n$，与判定式一致；特别地 `cnt > 0` 时即使 `i = n` 也非空。∎

**引理 3（解析不重不漏）**：数字解析循环结束后，`i` 指向下一块的字母或 `n`，`cnt` 等于该块的重复次数。

**证明**：压缩串合法 ⇒ 每个字母后紧跟一段非空连续数字，数字段之后要么是字母要么是串尾。循环条件 `i < n && isdigit(s[i])` 恰好消费整段数字，故 `i` 停在数字段之后；`num` 按十进制逐位累加，等于该数字的值。∎

**定理**：连续调用 `next()` 会依序输出 $U$ 的全部字符；输出完毕后每次 `next()` 返回空格，`hasNext()` 返回 false。

**证明**：由引理 1，每次成功 `next()` 输出 `rem` 的首字符并使 `rem` 缩短 1；由引理 2，`hasNext()` 精确判断 `rem` 是否为空；由引理 3，每次解析得到的字符与次数都是压缩串中真实的值，因此输出的每一字符都落在 $U$ 的正确位置。$|U|$ 有限，故经过 $|U|$ 次成功 `next()` 后 `rem = ε`，此后 `hasNext()` 恒为 false，`next()` 走空分支恒返回空格且状态不变。∎

## 6. 复杂度分析

- **时间**：设 $|s| = n$，调用总次数 $m$。构造 $O(1)$；`hasNext()` 每次 $O(1)$；`next()` **摊还 $O(1)$**——每个块只在其 `cnt` 归零后解析一次，解析时字母 $O(1)$、数字段每个字符只被扫描一次，全部调用累计扫描不超过 $n$ 个字符。严格说单次 `next()` 最坏 $O(n)$（一口气吞下整条数字），但总额为 $O(n + m)$。
- **空间**：$O(1)$ 额外空间（不计保存输入串的 $O(n)$），与解压后的长度无关。这正是本题的核心收益：暴力解需要 $O(\sum k)$，最坏 $5\times10^{11}$；本解恒为常数。

## 7. 参考代码

### C++

```cpp
#include <cctype>
#include <string>
using namespace std;

class StringIterator {
public:
    StringIterator(string compressedString) {
        s = compressedString;
        n = (int)s.size();
        i = 0; cnt = 0; cur = ' ';   // 题面要求：构造函数里重置全部状态
    }

    char next() {
        if (!hasNext()) return ' ';          // 已耗尽，状态不变
        if (cnt == 0) {                      // 当前块用完，才解析下一个块
            cur = s[i++];                    // 块首字母
            long long num = 0;
            while (i < n && isdigit((unsigned char)s[i]))
                num = num * 10 + (s[i++] - '0');   // 多位数字整段解析
            cnt = num;
        }
        cnt--;
        return cur;
    }

    bool hasNext() {
        return cnt > 0 || i < n;             // 块内还有，或还有整块未解析
    }

private:
    string s;
    int n, i;
    long long cnt;
    char cur;
};
```

### Python

```python
class StringIterator:
    def __init__(self, compressedString: str):
        self.s = compressedString
        self.n = len(compressedString)
        self.i = 0            # 下一个待解析的下标
        self.cnt = 0          # 当前块还剩多少个
        self.cur = ''         # 当前块的字母

    def next(self) -> str:
        if not self.hasNext():
            return ' '                       # 已耗尽，状态不变
        if self.cnt == 0:                    # 当前块用完，才解析下一个块
            self.cur = self.s[self.i]
            self.i += 1
            num = 0
            while self.i < self.n and self.s[self.i].isdigit():
                num = num * 10 + (ord(self.s[self.i]) - 48)
                self.i += 1
            self.cnt = num
        self.cnt -= 1
        return self.cur

    def hasNext(self) -> bool:
        return self.cnt > 0 or self.i < self.n
```

## 8. 边界情况与易错点

1. **串读完但块内还有字符**：`"a5"` 走完 4 次 `next` 后 `i = 2 = n`、`cnt = 1`，`hasNext()` 必须返回 true。这是本题最高频的 WA 点（示例 2）。
2. **耗尽后反复调用 `next()`**：应恒返回空格且不改变 `i`、`cnt`；若把「取字母」写在校验之前，会越界或输出脏字符。
3. **多位数字**：`"a12b3"`、`"z1000000000"` 必须整段解析；只读一位就会把 12 读成 1。
4. **计数上界与溢出**：$10^9$ 用 `int` 勉强够，但 `num = num * 10 + d` 没有留下任何余量，上界稍一放宽就会溢出，统一用 `long long`；Python 无此问题。
5. **类变量残留**：多个测试用例复用同一类，`i` / `cnt` / `cur` 必须在构造函数里重置，否则第二组用例从脏状态开始。
6. **不要在构造函数里解压**：$\sum k$ 可达 $5\times10^{11}$，哪怕只存一个 $10^9$ 的块也会 TLE / MLE。
7. **`isdigit` 的边界**：C++ 应传 `(unsigned char)`，否则对负值 `char` 是未定义行为；循环必须带 `i < n`，防止解析串尾数字时越界。
