# LeetCode 合并二叉树 题解

## 1. 题目概述

- **标题 / 题号**：合并二叉树（#617，easy）
- **链接**：https://leetcode.cn/problems/merge-two-binary-trees/
- **来源**：LeetCode 第 36 场周赛 Q1
- **难度**：简单
- **标签**：树、深度优先搜索、广度优先搜索、二叉树

**题意**：给定两棵二叉树 `root1`、`root2`，从两个根节点同时向下「叠放」。同一位置两侧都有节点时，把两个值**相加**作为合并后该位置的节点；只有一侧有节点时，该节点及其**整棵子树**原样保留；两侧都空则不建节点。返回合并后的树。

**约束**：

- 两棵树的节点数目都在 $[0, 2000]$ 内
- $-10^4 \le Node.val \le 10^4$
- 合并必须从两棵树的根节点开始（不能跳过某层只合下层）

> 💡 这是典型的「签到题 + 递归模板题」：判定条件只有三个，写完不到十行。真正值得记的是**返回值语义**（父节点要接住递归结果）与**剪枝条件**（一侧为空时整棵挂上），这两点决定了后面所有「树上双指针/双树递归」题（相同的树、对称二叉树、树的子结构）的写法。

## 2. 示例

**示例 1**

```text
输入：root1 = [1,3,2,5], root2 = [2,1,3,null,4,null,7]
输出：[3,4,5,5,4,null,7]
解释：根 1+2=3；左子 3+1=4；右子 2+3=5；
      左左 5 + 空 = 5；左右 空 + 4 = 4；右右 空 + 7 = 7，右左两侧都空故不建节点。
```

**示例 2**

```text
输入：root1 = [1], root2 = [1,2]
输出：[2,2]
解释：根节点 1+1=2；root1 没有左孩子，root2 的左孩子 2 原样挂上；
      两棵树都没有右孩子，结果也没有右孩子。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的「非递归」写法是：把两棵树各自拍平成「位置 → 值」的字典（DFS 收集，位置用从根出发的路径串表示），合并字典时同键相加，再按字典重建一棵树。时间 $O(m+n)$，但要遍历三遍、额外开一个 $O(m+n)$ 的哈希表，还得写两段与题意无关的序列化代码。

另一种暴力是「按层枚举位置」：先求高度 $h$，把所有路径（最多 $2^{h}$ 条）列出来逐个检查两棵树在该位置是否有节点。判存在性本身就要沿路径走 $O(h)$，总代价 $O(2^h \cdot h)$，在退化链上完全跑不动，代码也更长。

两种暴力都说明了一件事：**合并这个操作在结构上是天然分治的**——根的决定（相加还是搬运）与左右子树的合并互不影响，所以根本不需要显式枚举位置。

### 3.2 核心观察：只递归「重叠」的那部分

![叠加模型：同位置节点相加，单侧子树整棵挂上](images/wc36_q1_merge_model.svg)

把每个节点用「从根出发的路径」定位（根记作 $\varepsilon$，左走记 $L$，右走记 $R$）。设 $v_1(p)$、$v_2(p)$ 分别为两棵树在位置 $p$ 上的值（不存在记 $0$），则合并结果就是

$$v(p) = v_1(p) + v_2(p), \qquad p \in P_1 \cup P_2$$

其中 $P_1,P_2$ 是两棵树的位置集合（$p$ 两侧都不存在时结果里也不建节点）。

关键推论有两个：

1. **位置集合按左右孩子递归划分**：$P = \{\varepsilon\} \cup \{Lp : p \in P^{L}\} \cup \{Rp : p \in P^{R}\}$。所以「合并根的左子树」与「合并根的右子树」是两个完全独立的子问题，可以各自递归。
2. **一侧为空时整棵挂上**：若 $root_1$ 为空，则 $\forall p \in P_2$ 都有 $v_1(p)=0$，于是 $v(p)=v_2(p)$——结果就是 $root_2$ 本身。此时不需要往下走，直接返回引用即可。

第 2 点让递归**只走两棵树真正重叠的部分**：重叠节点数不超过 $\min(m,n)$，不重叠的大片子树以 $O(1)$ 的代价挂接。

### 3.3 算法流程

![递归流程：三条出口与一次自顶向下](images/wc36_q1_dfs_flow.svg)

以 `root1` 作为合并载体，函数语义是「返回合并后该位置的子树根」：

1. 若 `root1` 为空，返回 `root2`（整棵挂上，结束）；
2. 若 `root2` 为空，返回 `root1`（整棵挂上，结束）；
3. 两侧都不空：`root1.val += root2.val`；
4. `root1.left = merge(root1.left, root2.left)`；
5. `root1.right = merge(root1.right, root2.right)`；
6. 返回 `root1`。

第 1、2 步的先后顺序不影响正确性（两棵树同时为空时返回哪个都是空），但先写 `root1` 空判定可以让「两棵空树」在一行内结束。

### 3.4 示例演算

![示例 1 走查：按位置逐格相加](images/wc36_q1_walkthrough.svg)

对示例 1，按位置逐格对照：

| 位置 | root1 | root2 | 合并后 | 命中分支 |
|------|-------|-------|--------|----------|
| $\varepsilon$ | 1 | 2 | 3 | 两侧都有 → 相加 |
| $L$ | 3 | 1 | 4 | 两侧都有 → 相加 |
| $R$ | 2 | 3 | 5 | 两侧都有 → 相加 |
| $LL$ | 5 | — | 5 | 仅 root1 → 搬运 |
| $LR$ | — | 4 | 4 | 仅 root2 → 搬运 |
| $RR$ | — | 7 | 7 | 仅 root2 → 搬运 |
| $RL$ | — | — | — | 两侧都空 → 不建节点 |

递归实际只发生 3 次（三个「两侧都有」的位置），$LL$、$LR$、$RR$ 三处在下一层就以「返回另一侧」结束。按层序把上表读回：根 $3$ → 第二层 $4,5$ → 第三层 $5,4,\text{null},7$，即 `[3,4,5,5,4,null,7]`，与官方输出一致。

## 4. 算法细节

1. **先判空，后相加**。顺序反了会解引用空指针；C++ 用 `!root1` 判定，Python 用 `root1 is None`（不要写 `if not root1`，`TreeNode` 未定义 `__bool__` 时虽然也能用，但语义上更推荐显式判空）。
2. **返回值必须被接住**。`root1.left = merge(...)` 中的赋值不可省略：`merge` 返回的可能是 `root2` 的子树根，甚至可能是 `nullptr`；写成 `merge(root1->left, root2->left);` 而不接收返回值，等于什么也没做。
3. **不要写 `root1 = root2`**。那样只改了形参（局部指针），父节点的 `left/right` 仍指向原来的 `root1`，`root2` 那棵子树直接丢失。
4. **原地合并 vs 新建节点**。本题允许修改输入，直接复用 `root1` 的节点可以把额外空间压到只剩递归栈。若要求「不破坏输入」，把第 3 步换成 `TreeNode* cur = new TreeNode(root1->val + root2->val);`，再递归 `cur->left/cur->right`，空间变为 $O(\text{重叠节点数})$。
5. **Python 的递归深度**。节点数上限是 $2000$，若两棵树都是退化左链，递归深度可达 $2000$，超过默认的 $1000$ 上限（实测深度 $1200$ 的链就会 `RecursionError`）。提交时在函数外写 `sys.setrecursionlimit(10000)`，或改成显式栈的迭代写法。
6. **值域不会溢出**。$|val| \le 10^4$，相加最大 $2\times 10^4$，`int` 足够；但不能用 $0$ 当「节点不存在」的哨兵，因为权值本身可以为 $0$ 甚至负数。
7. **迭代版等价改写**。用栈成对压入 $(a,b)$：先把两棵树根成对入栈，每次弹出一对，`a->val += b->val`，再看四个孩子的组合分别处理（都非空 → 成对入栈；只 `a` 侧空 → `a->left = b->left`；只 `b` 侧空 → 保持 `a->left`）。空间 $O(\min(m,n))$ 但常数更小，且完全避开递归上限。

## 5. 正确性证明

**引理 1（剪枝正确）**：若 $root_1$ 为空，则 `merge(root1, root2)` 返回 $root_2$ 时，结果树恰好覆盖位置集合 $P_2$，且每个位置上的值等于 $v_2(p)$。

**证明**：$root_1$ 为空意味着 $P_1=\varnothing$，于是对任意 $p \in P_2$ 有 $v_1(p)=0$，由合并规则 $v(p)=v_1(p)+v_2(p)=v_2(p)$；同时 $P_1\cup P_2=P_2$，故结果的形状与 $root_2$ 完全一致，直接返回其引用即可满足要求。∎

**引理 2（对称剪枝）**：若 $root_2$ 为空，则返回 $root_1$ 时结果覆盖 $P_1$ 且值不变。

**证明**：与引理 1 对称，交换下标即可。∎

**引理 3（重叠节点处理正确）**：设 $root_1,root_2$ 均非空，令 $h=\min(h_1,h_2)$。若对一切 $\min$ 高度小于 $h$ 的树对，`merge` 都返回正确的合并树，则 `merge(root1, root2)` 也正确。

**证明**：根位置 $\varepsilon$ 两侧都有节点，赋值为 $v_1(\varepsilon)+v_2(\varepsilon)$，符合规则。左子树对 $(root_1.left, root_2.left)$ 的 $\min$ 高度 $< h$（因为两者高度都严格小于 $h_1,h_2$ 中对应的那个），由归纳假设它对 $L$ 前缀的位置集合给出正确合并；右子树同理给出 $R$ 前缀部分的正确合并。而 $L$ 前缀与 $R$ 前缀位置集合互不相交，与 $\{\varepsilon\}$ 也不相交，三部分之并正是 $P_1\cup P_2$。因此整体结构和每个位置的值都正确。∎

**定理**：`mergeTrees(root1, root2)` 返回的树，其位置集合为 $P_1\cup P_2$，且每个位置 $p$ 上的值恰为 $v_1(p)+v_2(p)$（缺失一侧视为 $0$）。

**证明**：对 $h=\min(h_1,h_2)$ 作结构归纳。

- 基础情形：若 $h=0$（至少一侧为空），由引理 1、引理 2 立得。若 $h=1$，两侧根都在、四个孩子全空，根赋值相加，两次递归都命中引理 1/2 返回空，结果位置集合为 $\{\varepsilon\}=P_1\cup P_2$，值正确。
- 归纳步：设 $h \ge 2$ 时对一切更小的 $h$ 成立，由引理 3 即得 `merge(root1,root2)` 正确。
- 终止性：每层递归的两个实参都至少下降一层，树的深度有界，递归必停；每次调用只在两侧非空时继续，故总调用次数有限。∎

## 6. 复杂度分析

- **时间**：$O\bigl(\min(m,n)\bigr)$，其中 $m,n$ 为两棵树的节点数。只有「两侧都非空」的调用才会继续向下递归，这类调用数不超过两树重叠节点数，也就不会超过 $\min(m,n)$；一侧为空的调用是叶子，只做一次指针返回（$O(1)$），却可能一次挂上整棵子树。注意这**不是** $O(m+n)$：不重叠的子树根本不会被遍历。
- **空间**：$O\bigl(\min(h_1,h_2)\bigr)$，即递归栈深度，等于两棵树同时向下能走的最深重叠路径；退化链上为 $O(\min(m,n))$。原地合并不分配新节点，除递归栈外无额外空间。若改为「不破坏输入」的新建节点版本，空间再加 $O(\text{重叠节点数})$，仍不超过 $O(\min(m,n))$。

## 7. 参考代码

### C++

```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:
    TreeNode* mergeTrees(TreeNode* root1, TreeNode* root2) {
        if (root1 == nullptr) return root2;   // 只有 root2 有节点：整棵子树原样挂上
        if (root2 == nullptr) return root1;   // 对称情形
        root1->val += root2->val;             // 重叠位置：两值相加
        root1->left  = mergeTrees(root1->left,  root2->left);
        root1->right = mergeTrees(root1->right, root2->right);
        return root1;                         // 返回值必须被父节点接住
    }
};
```

### Python

```python
import sys
from typing import Optional

sys.setrecursionlimit(10000)   # 节点数上限 2000，退化链的递归深度会超过默认的 1000


class Solution:
    def mergeTrees(self, root1: Optional[TreeNode], root2: Optional[TreeNode]) -> Optional[TreeNode]:
        if root1 is None:          # 只有 root2 有节点：整棵子树原样挂上
            return root2
        if root2 is None:          # 对称情形
            return root1
        root1.val += root2.val     # 重叠位置：两值相加
        root1.left = self.mergeTrees(root1.left, root2.left)
        root1.right = self.mergeTrees(root1.right, root2.right)
        return root1               # 返回值必须被父节点接住
```

## 8. 边界情况与易错点

1. **两棵树都为空**：`root1 == nullptr` 判定立即命中，返回 `root2`（即空），不需要额外特判 `if (!root1 && !root2) return nullptr;`。
2. **一棵空一棵非空**：直接返回非空那棵的**引用**，不复制、不遍历。若误写成一个循环去复制节点，时间从 $O(1)$ 变成 $O(n)$，在「一棵 1 个节点、另一棵 2000 个节点」的数据上明显变慢。
3. **返回值丢失**：`mergeTrees(root1->left, root2->left);` 不接收返回值是最常见的 WA 原因——递归算了但结果没接上，输出仍是 `root1` 原样。
4. **`root1 = root2` 的陷阱**：这只改变形参，父节点那一侧的指针没变，结果树会丢掉 `root2` 的整个子树。要写 `root1->left = ...` 而不是重新绑定 `root1`。
5. **Python 递归上限**：默认 $1000$ 层，节点数上限 $2000$ 的退化链直接 `RecursionError`；本地实测深度 $1200$ 的链即触发。加 `sys.setrecursionlimit(10000)`，或在函数内维护显式栈。
6. **只有右孩子的树**：合并时左孩子为空、右孩子非空的情形必须分别处理，不能因为「左空」就整棵返回，否则会把右子树一起丢掉——本质是第 4、5 步的赋值顺序不能写反。
7. **负值与零**：$-5$ 与 $-7$ 合并得 $-12$，$0$ 是合法权值，不能用 $0$ 表示「不存在」。

**延伸思考**：① 若合并规则改成「相乘」或「取最大值」，代码只需换一行——因为规则只作用在「位置上的两个值」这一层，而递归结构由位置集合决定，与具体运算无关。② 若要求「两侧都空时也建一个值为 0 的节点」，则剪枝条件失效，必须枚举到两棵树最大深度的并集，复杂度升到 $O(2^{\max(h_1,h_2)})$，此时应改用哈希表按路径合并。③ 若同一棵树要被反复合并 $k$ 次（例如依次叠 $k$ 棵树），直接循环调用即可，总代价 $O(k \cdot \min)$；但如果 $k$ 棵树结构相同，可以先算出「同一位置的权值和」再一次性建树，把 $k$ 次合并摊到一次 $O(\sum n_i)$。
