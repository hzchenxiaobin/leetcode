# LeetCode 有效三角形的个数 题解

## 1. 题目概述

- **标题 / 题号**：有效三角形的个数（#611，medium）
- **链接**：https://leetcode.cn/problems/valid-triangle-number/
- **来源**：LeetCode 第 36 场周赛 Q3
- **难度**：中等
- **标签**：数组、贪心、排序、双指针、二分查找

**题意**：给定长度为 $n$ 的非负整数数组 `nums`，统计有多少个下标三元组 $(i,j,k)$，$i<j<k$，使得 `nums[i]`、`nums[j]`、`nums[k]` 能作为一个三角形的三条边长（退化三角形不算，即必须严格满足两边之和大于第三边）。注意数组元素可以重复，**相同数值但下标不同视为不同方案**；$0$ 是合法元素，但含 $0$ 的三元组永远组不成三角形。

**约束**：

- $1 \le n \le 1000$
- $0 \le \text{nums}[i] \le 1000$
- 答案上界为 $\binom{1000}{3} = 166167000 < 2^{31}-1$，32 位整数足够

## 2. 示例

**示例 1**

```text
输入：nums = [2,2,3,4]
输出：3
解释：排序后仍为 [2,2,3,4]，合法的三个下标组合是
      2,3,4（用第 1 个 2）
      2,3,4（用第 2 个 2）
      2,2,3
```

**示例 2**

```text
输入：nums = [4,2,3,4]
输出：4
解释：排序后为 [2,3,4,4]，合法组合是
      {2,3,4a}、{2,3,4b}、{2,4a,4b}、{3,4a,4b}，共 4 个。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是三重大小枚举：固定下标 $i<j<k$，检查三条不等式 $a+b>c$、$a+c>b$、$b+c>a$ 是否同时成立。枚举量是 $\binom{n}{3}$，$n=1000$ 时约 $1.66\times10^{8}$ 组、每组三次加法与比较，在 Python 里要跑几分钟，C++ 也接近时限；更重要的是它没有利用任何结构——三个不等式彼此独立地检查，等于把「三角形」这个几何对象当成黑盒。

稍微好一点的暴力是**排序后再枚举**：排序不改变「哪些三元组合法」（合法性只与数值有关，与下标顺序无关），而排序后只需检查一条不等式。但枚举量仍是 $\binom{n}{3}$，这一步只省下三分之二的比较，复杂度没有量级改善，所以还要继续压。

### 3.2 核心观察：固定最长边，双指针批量计数

![排序后只需判定 a + b > c](images/wc36_q3_fix_longest_side.svg)

把数组排序得到 $x_0 \le x_1 \le \dots \le x_{n-1}$。任取三条边，设它们升序为 $a \le b \le c$，则：

**只要 $a+b>c$ 成立，另两条不等式自动成立**。理由：由 $a+b>c\ge b$ 得 $a>0$，故 $a\ge1$，于是 $a+c\ge 1+c>b$；再看 $b+c>a$，若 $b+c=a$，则由 $c\ge b$ 得 $a\ge 2b$，与 $a\le b$ 合起来迫使 $b=0$、$a=c$，此时 $a+b=a=c$ 与 $a+b>c$ 矛盾，故 $b+c>a$。于是「三式」被压缩成「一式」，这是排序带来的第一个收益。

第二个收益是**枚举结构**。枚举最大边：固定 $k$（$x_k$ 为最大边），问题变成在区间 $[0,k)$ 中数出有多少对 $(i,j)$，$i<j$，满足 $x_i+x_j>x_k$。这就是经典的「两数之和大于目标」的计数问题，而它天然适合双指针：

- $i$ 指向区间左端、$j$ 指向区间右端；
- 若 $x_i+x_j>x_k$，由于数组递增，$x_i,x_{i+1},\dots,x_{j-1}$ 与 $x_j$ 配对**全部**合法，一次性加 $j-i$ 个，然后 $j$ 左移；
- 若 $x_i+x_j\le x_k$，说明最小的 $x_i$ 与当前最大的 $x_j$ 都凑不出大于 $x_k$ 的和，那么 $x_i$ 与区间内任何元素都凑不出，直接 $i$ 右移。

这就是本题的全部内容：外层 $O(n)$ 轮、内层双指针合计 $O(n)$，总计 $O(n^2)$；对 $n=1000$ 只有约 $5\times10^{5}$ 次指针移动，比 $\binom{n}{3}\approx1.66\times10^{8}$ 快了约 300 倍。

> 💡 与「三数之和」的区别：那题要求输出具体的值组合且需要去重，本题只要求**计数**，所以「一次加一批」的批量计数才是主菜；只要统计口径对，重复元素天然按下标区分，不需要任何去重逻辑。

### 3.3 算法流程

![两层循环与双指针的移动规则](images/wc36_q3_two_pointer_flow.svg)

1. 排序 `nums`，`ans = 0`；
2. 外层 $k$ 从 $n-1$ 递减到 $2$（$k<2$ 时它左边不足两个数，无法成组）；
3. 每轮令 $i=0$、$j=k-1$；
4. 当 $i<j$ 时循环：
   - 若 $nums[i] + nums[j] > nums[k]$：`ans += j - i`，然后 `j--`；
   - 否则：`i++`；
5. 返回 `ans`。

内层循环的两个分支都把「已确定的区间」向外收缩一格：命中时右侧端点 $j$ 用完了（与它配对的所有合法 $i$ 都数完了），未命中时左侧端点 $i$ 被证明无用。因此 $i$ 只增、$j$ 只减，内层总移动次数不超过 $k$，一轮 $O(k)$。

### 3.4 示例演算

![nums = [2,2,3,4] 的走查](images/wc36_q3_example_walkthrough.svg)

以 `nums = [2,2,3,4]`（排序后不变，下标 0..3）为例：

| 步骤 | 固定 $k$（最大边） | $i$ | $j$ | 比较 | 动作 | `ans` |
|------|--------------------|-----|-----|------|------|-------|
| ① | $k=3$，$c=4$ | 0 | 2 | $2+3=5>4$ ✓ | `ans += 2`，$j\to1$ | 2 |
| ② | $k=3$，$c=4$ | 0 | 1 | $2+2=4\le 4$ ✗ | $i\to1$，$i=j$ 结束 | 2 |
| ③ | $k=2$，$c=3$ | 0 | 1 | $2+2=4>3$ ✓ | `ans += 1`，$j\to0$ | 3 |
| ④ | $k=1<2$ | — | — | 外层条件失效 | 返回 `ans` | 3 |

步骤①是批量计数的关键：$j-i=2-0=2$，对应「$a$ 取下标 0 或 1 两个不同的 $2$，$b$ 固定为下标 2 的 $3$」，两对都满足 $2+3>4$，于是 `{2,3,4}`（第 1 个 2）与 `{2,3,4}`（第 2 个 2）同时入账。步骤②中 $2+2=4$ 不严格大于 $4$，是退化三角形（三条边 $2,2,4$ 压成一条线段），被正确排除。

示例 2 的 `[4,2,3,4]` 排序为 `[2,3,4,4]`：$k=3$ 时 $i=0,j=2$ 命中加 2（两个 `{2,3,4}`），$j=1$ 仍命中加 1（`{2,4,4}`，$2+4>4$）；$k=2$ 时命中加 1（`{3,4,4}`，$3+4>4$），合计 4。

## 4. 算法细节

1. **排序是前提而非优化**。排序让「最大边」有下标可指，也让「$x_i+x_j>x_k$ 的解集是后缀」这一单调性成立。合法性只与数值有关，与原始下标顺序无关，因此排序不会改变答案。
2. **外层下界是 $2$，不是 $1$**。$k=1$ 时左边只有一个元素，凑不出两条边；写成 `k >= 1` 虽不会错（内层 `i < j` 立刻失败），但会白跑 $n$ 轮，也容易让 `j = k-1 = 0` 与 `i = 0` 的边界更难读。
3. **命中时加 $j-i$，不是加 1**。这是本题最大的坑：$b$ 固定为 `nums[j]` 时，$a$ 可取下标 $i,i+1,\dots,j-1$，共 $j-i$ 个，且由于数组递增它们全都合法。
4. **未命中时 $i$ 右移的正确性依据**。此时 $nums[i]+nums[j]\le nums[k]$，而对任意 $j'\le j$ 有 $nums[j']\le nums[j]$，故 $nums[i]+nums[j']\le nums[k]$：`nums[i]` 与区间内**所有**候选 $b$ 都无法组成合法对，可以永久丢弃。
5. **$j$ 左移的正确性依据**。命中时「$b$ = `nums[j]`」这一批已经全部统计完（$a$ 的取值被 $j-i$ 覆盖完），所以 $j$ 可以安全左移；此时 $b$ 变小，需要重新判断哪些 $a$ 还合法，而 $i$ 保持不动即可——因为新的 $b$ 更小，原先合法的 $a$ 集合只会缩小，从当前的 $i$ 继续往右扫正好。
6. **$0$ 不需要特判**。若 `nums[i] = 0`，则 $0+nums[j]\le nums[j]\le nums[k]$ 恒成立，算法自然走 $i$ 右移分支，含 $0$ 的三元组一个都不会被计入。
7. **重复元素不需要去重**。本题按**下标**计数，排序后相同的值占据了不同位置，双指针按位置推进，天然把它们当作不同方案；这也是它比「三数之和」简单的地方。
8. **答案用 32 位即可**。$\binom{1000}{3}=166167000$ 远小于 $2^{31}-1$，C++ 用 `int` 不会溢出；但若把约束放大到 $n=10^5$，$\binom{n}{3}\approx1.7\times10^{14}$，必须换 `long long`。

## 5. 正确性证明

**引理 1（三式化一式）**：设 $0\le a\le b\le c$，则 $(a,b,c)$ 能组成（非退化）三角形当且仅当 $a+b>c$。

**证明**：
必要性显然。充分性：设 $a+b>c$。首先 $a\ne 0$，否则 $b\ge a+b>c\ge b$，矛盾，故 $a\ge1$。于是 $a+c\ge 1+c>b$，第二条不等式成立。再看 $b+c>a$：若 $b+c=a$，则由 $c\ge b$ 得 $a=b+c\ge 2b$，又 $a\le b$，故 $b=0$ 且 $a=c$，此时 $a+b=a=c$，与 $a+b>c$ 矛盾。故 $b+c>a$ 亦成立。∎

**引理 2（右端点固定时的合法集是后缀）**：固定 $k$ 与 $j<k$，令 $T=\{p:0\le p<j,\ x_p+x_j>x_k\}$。则存在 $t$ 使 $T=\{t,t+1,\dots,j-1\}$，且当 $T\ne\varnothing$ 时 $t$ 就是最小的合法左端点。

**证明**：若 $p\in T$ 且 $p<p'<j$，由 $x_{p'}\ge x_p$ 得 $x_{p'}+x_j\ge x_p+x_j>x_k$，故 $p'\in T$。集合对「向右」封闭，而 $T\subseteq\{0,\dots,j-1\}$ 有限，故 $T$ 必为后缀。∎

**引理 3（循环不变量）**：在某一轮（固定 $k$）内，每次进入内层循环体的瞬间，下面两条同时成立：

- (a) 所有满足 $q>j$ 且 $p<q$ 的合法对 $(p,q)$ 均已计入 `ans`；
- (b) 对所有 $p<i$，有 $x_p+x_j\le x_k$。

**证明**：对指针移动次数归纳。

- 初始 $i=0$、$j=k-1$：(a) 中 $q>k-1$ 的对不存在，空成立；(b) 中 $p<0$ 不存在，空成立。
- 命中分支（$x_i+x_j>x_k$）：由引理 2，满足 $q=j$ 的合法对恰为 $\{(p,j):t\le p<j\}$，其中 $t$ 是最小合法左端点；由 (b) 知 $p<i$ 时 $(p,j)$ 不合法，故 $t\ge i$，又 $(i,j)$ 合法故 $t\le i$，于是 $t=i$，本次加入的 $j-i$ 恰好数完全部满足 $q=j$ 的合法对。随后 $j\to j-1$，(a) 中 $q>j-1$ 的部分由「原有 $q>j$ 的对」加上「刚数完的 $q=j$ 的对」组成，成立；(b) 中 $x_{j-1}\le x_j$，故 $x_p+x_{j-1}\le x_p+x_j\le x_k$，成立。
- 未命中分支（$x_i+x_j\le x_k$）：$(i,j)$ 不合法；由有序性，对所有 $p\le i$ 有 $x_p+x_j\le x_i+x_j\le x_k$，故令 $i\to i+1$ 后 (b) 成立；(a) 未受影响，仍成立。∎

**定理**：算法返回的 `ans` 等于合法下标三元组的个数。

**证明**：先说明每一轮 $k$ 的退出条件保证该轮统计完整。内层以 $i<j$ 为条件，退出时 $i\ge j$，此时：

- 满足 $q>j$ 的合法对由引理 3(a) 已全部计入；
- 满足 $q=j$ 的对中，$p<j\le i$ 故 $p<i$，由 (b) 知 $x_p+x_j\le x_k$，即全部不合法；
- 满足 $q<j$ 的对有 $p<q<j\le i$，故 $p<i$，且由有序性 $x_q\le x_j$，于是 $x_p+x_q\le x_p+x_j\le x_k$，同样不合法。

故该轮把区间 $[0,k)$ 内所有合法对恰好统计一次，既不重也不漏。另一方面，排序后任意三元组对应唯一的位置组 $p<q<r$，它只在 $k=r$ 那一轮被统计（该轮枚举的正是「以 $x_r$ 为最大边、另两条取自 $[0,r)$」的全部点对），因此各轮统计互不重叠，对 $k=2,\dots,n-1$ 求和即得全部合法三元组数。∎

## 6. 复杂度分析

- **时间**：$O(n\log n+n^2)=O(n^2)$。排序 $O(n\log n)$；外层 $k$ 共 $n-2$ 轮，每轮内层 $i$ 只增、$j$ 只减，总移动次数不超过 $k\le n$，故内层合计 $O(n^2)$。$n=1000$ 时约 $5\times10^5$ 次比较，远快于 $\binom{n}{3}\approx1.66\times10^8$。
- **空间**：$O(1)$ 额外空间（不计排序）。双指针只有两个下标变量和一个计数器。C++ 的 `sort` 用内省排序，栈开销 $O(\log n)$；Python 的 `sorted` 返回新列表，额外 $O(n)$，若允许原地修改可写 `nums.sort()` 保持 $O(1)$（同样忽略排序自身开销）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int triangleNumber(vector<int>& nums) {
        sort(nums.begin(), nums.end());          // 排序：让「最大边」有下标可指
        int n = nums.size(), ans = 0;
        for (int k = n - 1; k >= 2; --k) {       // 固定最长边 nums[k]
            int i = 0, j = k - 1;                // 双指针在 [0, k-1] 内相向移动
            while (i < j) {
                if (nums[i] + nums[j] > nums[k]) {
                    ans += j - i;                // a 取 i..j-1 全部合法，批量计数
                    --j;                         // b 这一批已统计完，右端左移
                } else {
                    ++i;                         // nums[i] 太小，与谁都凑不成
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def triangleNumber(self, nums: List[int]) -> int:
        nums = sorted(nums)                      # 排序：让「最大边」有下标可指
        n = len(nums)
        ans = 0
        for k in range(n - 1, 1, -1):            # 固定最长边 nums[k]
            i, j = 0, k - 1                      # 双指针在 [0, k-1] 内相向移动
            while i < j:
                if nums[i] + nums[j] > nums[k]:
                    ans += j - i                 # a 取 i..j-1 全部合法，批量计数
                    j -= 1                       # b 这一批已统计完，右端左移
                else:
                    i += 1                       # nums[i] 太小，与谁都凑不成
        return ans
```

## 8. 边界情况与易错点

1. **$n<3$**：外层 `k = n-1` 到 `2`，当 $n\le2$ 时循环一次都不进，直接返回 0，无需特判。
2. **命中时写 `ans += 1`**：最常见的错误。漏掉了「$a$ 有多种取法」这一层，`[2,2,3,4]` 会输出 2 而不是 3。
3. **$j$ 的初值写成 $k$**：这会让最长边 `nums[k]` 与它自己配对——只要 `nums[i] > 0`，$x_k+x_i>x_k$ 恒成立，一个元素被用两次，答案会暴涨。$j$ 必须从 $k-1$ 起。（内层条件写成 `i <= j` 不会多算，因为 $i=j$ 时 $j-i=0$；但会白绕一圈，照直写 `i < j` 更清楚。）
4. **含 $0$**：`[0,0,0]`、`[0,1,1]` 都应返回 0。不要用「过滤掉 0 再算」的写法去优化——过滤后下标关系被打乱，一旦题目改成要求输出方案就会错；直接依赖 $0+x\le x$ 的自然排除更稳。
5. **排序后误以为下标信息还在**：本题只求个数，排序安全；若改成「返回所有合法三元组」，必须额外保存原下标或直接输出数值组合并去重。
6. **$j-i$ 算错方向**：合法 $a$ 的下标范围是 $[i,j-1]$，个数是 $j-i$（不是 $j-i+1$），因为 $j$ 位置本身是 $b$ 而不是 $a$。
7. **溢出**：$n=1000$ 时答案 $\le1.66\times10^8$，`int` 安全；但把代码复用到 $n$ 更大的场景（如 $10^5$）时，`int` 会溢出，需换 `long long`。
8. **重复值的计数口径**：两个数值相同的 $2$ 是不同下标，必须各算一次。排序后双指针按位置推进自动满足，千万不要在数到相等值时做「去重跳过」，那会把答案算少。

**延伸思考**：① 若把要求的「严格大于」改成「大于等于」（允许退化三角形），只需把判定从 `>` 改成 `>=`，但引理 1 的退化情形要重新讨论——此时 `[2,2,4]` 这类会被计入。② 若数据范围很小（$n\le100$），可以用 $O(n^3)$ 暴力对拍；若 $n$ 大到 $10^4$，$O(n^2)$ 也偏慢，可考虑按值域 $[0,1000]$ 做桶 + 前缀和，把「固定 $k$ 后统计和大于 $x_k$ 的点对数」压到 $O(V)$，整体 $O(V^2)$。③ 若要求的是四条边组成四边形（最长边小于其余三边之和），排序后固定最长边 + 三数之和计数，复杂度会升到 $O(n^3)$ 或 $O(n^2\log n)$，是本题的自然推广。
