# LeetCode 构造限制重复的字符串 题解

## 1. 题目概述

- **标题 / 题号**：构造限制重复的字符串（#2182，medium）
- **链接**：https://leetcode.cn/problems/construct-string-with-repeat-limit/
- **来源**：LeetCode 第 281 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、计数、堆（优先队列）

**题意**：给定字符串 `s`（小写字母）与整数 `repeatLimit`，用 `s` 中的字符（**允许弃用一部分**）构造新字符串，要求任何字母**连续**出现的次数不超过 `repeatLimit`，返回**字典序最大**的合法串。字典序比较规则：首个不同位置字母更大者更大；若一方是另一方前缀，则更长者更大。

**约束**：

- $1 \le \text{repeatLimit} \le |s| \le 10^5$
- `s` 仅由小写英文字母组成

> 💡 **读题定位**：重排 + 字典序最大 → 标准贪心信号。核心只有两条规则——「能放就放当前最大字母」和「封顶就垫一个次大字母」。难点不在写法而在**正确性**：「允许弃用字符」这个自由度会催生一堆错误直觉（例如「要不要省着大字母当分隔符」「分隔符选大还是选小」），必须靠干净的交换论证把它们全部排除。实现上 26 个桶 + 双指针即可线性完成，堆只是等价替代。

## 2. 示例

**示例 1**（官方）

```text
输入：s = "cczazcc", repeatLimit = 3
输出："zzcccac"
解释：z 连放 2 个；c 连放 3 个后被封顶，垫一个 a 解封，再放最后 1 个 c。
      虽然 "zzcccca" 字典序更大，但 c 连续出现 4 次 > 3，非法。
```

**示例 2**（官方）

```text
输入：s = "aababab", repeatLimit = 2
输出："bbabaa"
解释：b 连放 2 个 → 垫 a → 放最后 1 个 b → a 连放 2 个 → 剩 1 个 a
      无字母可垫，丢弃。注意答案没有用完全部字符（弃用了 1 个 a）。
```

**示例 3**（自造：垫片解封）

```text
输入：s = "zzza", repeatLimit = 2
输出："zzaz"
解释：z 连放 2 个封顶；垫 1 个 a 后 run 清零，还能再放 1 个 z。
      "zzaz" 严格大于只放到 "zza"（后者是前者的前缀）。
```

**示例 4**（自造：无垫片则丢弃）

```text
输入：s = "aaa", repeatLimit = 2
输出："aa"
解释：a 连放 2 个封顶后，没有任何别的字母能打断 run，
      剩下的 1 个 a 永远无法合法出现，只能丢弃。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的想法是枚举：`s` 的每个子多重集的每个排列都检查合法性，取字典序最大者。排列数是阶乘级，$|s| = 10^5$ 下天文数字，完全不可行；即使是验证某个候选串是否最优，也退化为同样的枚举。

换一个角度的「朴素模拟」反而有前途：从空串开始，每一步扫描 26 个计数桶，挑出**当前能合法接上的最大字母**，放 1 个，重复直到无字母可放。这个逐字符模拟就是正确贪心的原型，复杂度 $O(26n)$ 已经可过；剩下的问题是——(a) 它为什么对（证明见 §5）；(b) 怎么写得更快更干净（批量化，见 §3.3 与 §4）。真正要警惕的是下面这些「看似合理」的错误直觉。

### 3.2 核心观察：连放最大 + 垫次大解封

![核心观察：连放最大 + 垫次大分隔](images/wc281_q3_greedy_concept.svg)

字典序的比较是**逐位进行**的：首位占绝对优势，后面再怎么补救都翻不盘。由此推出两条规则：

**规则一（能放就放最大）**：设当前仍有余量的最大字母是 $m$。只要 $m$ 没被连续上限封住（末尾不是 $m$ 的 $L$ 长 run），就继续放 $m$——因为放 1 个 $m$ 之后，$m$ 依然是「最大且未封顶」的可用字母，没有任何理由切换到更小的字母。于是一路连放到 $\min(\mathrm{cnt}[m],\ L)$ 个为止。

**规则二（封顶就垫次大）**：当 $m$ 的 run 达到 $L$ 且还有余量时，$m$ 被封死。能解封的最便宜动作是垫 **1 个次大可用字母** $m'$（$\ne m$ 的最大有余量字母）：

- 垫完 1 个 $m'$ 后 run 立即清零，$m$ 重新可放且仍是最大——所以**只垫 1 个就回头**，第 2 个 $m'$ 的位置本来可以放更大的 $m$；
- 若不存在 $m'$（只剩 $m$ 自己有余量），run 永远无法被打断，剩余的 $m$ 全部报废，算法终止（示例 4）。

**三个直觉陷阱**（都能被交换论证否决，见 §5）：

1. **「省着用大字母」**：不舍得把大字母当普通字符连放？任何位置放更大字母都严格更优，后置补救无法逆转首差位。如 `s = "abzz"`，$L=1$：正确答案 `"zbza"`（b 毫不吝啬地当了垫片），把 b 留着换 a 垫只能得到 `"zazb"`，更小。
2. **「垫片选小字母，省着大的」**：同上，垫片位置的字母直接参与字典序比较，选次大 $m'$ 严格优于任何更小字母。
3. **「多垫几个更安全」**：多垫只会把本可以放 $m$ 的位置让给更小的字母，字典序严格变小。如 `s = "ccccaa"`，$L=2$：正确 `"ccacca"`，连垫 2 个 a 得 `"ccaacc"`，更小。

### 3.3 算法流程

![算法流程：26 桶计数 + 双指针批量贪心](images/wc281_q3_algorithm_flow.svg)

用 `cnt[26]` 计数代替排序/堆，指针 $i$ 从 `'z'` 向下滑动，指向当前最大的非空桶：

1. **连放**：一次性追加 $k = \min(\mathrm{cnt}[i],\ L)$ 个字母 $i$，扣减计数；
2. **下移**：若 $\mathrm{cnt}[i] = 0$（用尽），$i$ 下移到下一个非空桶——由于计数只减不增，$i$ 上方的桶永远为空，指针只需单向下滑，无需回扫；
3. **垫片**：若 $\mathrm{cnt}[i] > 0$（说明 $k = L$ 被封顶），找次大非空桶 $j$（$j < i$ 且 $\mathrm{cnt}[j] > 0$）：没有则终止（剩余报废）；有则放 1 个 $j$，回到第 1 步继续连放 $i$。

### 3.4 示例演算

![示例演算：cczazcc, L=3 的四步构造](images/wc281_q3_example_walkthrough.svg)

以官方示例 1 `s = "cczazcc"`，$L = 3$ 为例，计数桶为 $z{:}2,\ c{:}4,\ a{:}1$：

| 步 | 动作 | 串 | 桶状态 |
|----|------|----|--------|
| 1 | 最大 $m = z$，连放 $\min(2,3) = 2$ 个 | `zz` | z 用尽 |
| 2 | $m = c$，连放 $\min(4,3) = 3$ 个，封顶 | `zzccc` | c 剩 1 |
| 3 | 垫 1 个次大 $a$，run 清零 | `zzccca` | a 用尽 |
| 4 | $c$ 解封，再连放 $\min(1,3) = 1$ 个 | `zzcccac` | 全空 ✓ |

官方示例 2 `s = "aababab"`，$L = 2$ 同理：`bb`（封顶）→ 垫 `a` → `b`（用尽）→ `aa`（封顶，无字母可垫）→ 停止，答案 `"bbabaa"`，弃用 1 个 `a`——正是「不必用完全部字符」的体现。

## 4. 算法细节

1. **桶计数代替排序/堆**：字母表是常数 26，`int cnt[26]` 数组配合双指针即可 $O(1)$ 摊还地取「最大/次大非空桶」，比排序（$O(n \log n)$）和堆（$O(n \log 26)$，需要 push/pop）都更轻。用最大堆模拟同一贪心是等价写法，比赛时按手感选即可。
2. **指针 $i$ 的单调性**：初始指向最大的非空桶；计数只减不增，所以 $i$ 上方的桶一旦空就永远空，$i$ 只需下移。若实现成「每轮从 `'z'` 重扫」，正确性不变、常数略大；若把 $j$ 的搜索范围写错（必须是 $j < i$ 的最大非空桶，且每轮**重新**搜索——垫过的桶可能变空），才会出真正的 bug。
3. **批量连放**：一次 `append` $\min(\mathrm{cnt}[i], L)$ 个字母，而不是逐字符试探，把循环次数从 $O(n)$ 压到 $O(\text{批次数})$；每批必然追加至少 1 个字符（因 $L \ge 1$），循环天然终止。C++ 用 `ans.append(k, 'a' + i)` 并 `reserve`；Python 用列表收集 + `''.join`，避免字符串 `+=` 的潜在平方行为。
4. **终止条件即丢弃条件**：当且仅当「只剩被封顶的 $m$ 自己有余量」时停止。此时不存在任何字母能打断 run，剩余 $m$ 在**任何**合法串中都无法再出现（引理 1），丢弃是被迫且无损最优性的。
5. **无溢出风险**：计数 $\le 10^5$、答案长度 $\le n$，32 位整数全程够用。

## 5. 正确性证明

记状态 $\sigma = (\mathrm{cnt},\ \text{last},\ \text{run})$：剩余计数、当前末字符及其连续长度。$\sigma$ 的**合法延拓**指从 $\sigma$ 出发还能接出的合法后缀（允许是空串——对应「弃用剩余字符」）。称字母 $c$ **可放**，若 $\mathrm{cnt}[c] > 0$ 且（$c \ne \text{last}$ 或 $\text{run} < L$）。

**引理 1（可放性刻画）**：状态 $\sigma$ 存在可放字母 $\iff$ $\sigma$ 存在非空合法延拓。

**证明**：（⇒）直接放 1 个 $c$，新 run 为 1 或 $\text{run}+1$，均 $\le L$，合法。（⇐）若无可放字母，则一切有余量的字母都等于 $\text{last}$ 且 $\text{run} = L$；任何非空延拓的首字符必为某个有余量字母，即 $\text{last}$，接上后 run 变为 $L+1 > L$，非法。故唯一合法延拓是空串。∎

**定理（逐字符贪心最优）**：每一步放「当前可放的最大字母」，直到无可放字母，得到的串是字典序最大的合法串。

**证明**（对剩余字符总数 $R$ 归纳）：

- **基例** $R = 0$：唯一延拓为空串，贪心输出空后缀，显然最大。
- **归纳步**：设结论对一切余量为 $R - 1$ 的状态成立，当前状态 $\sigma$ 余量 $R \ge 1$。若无可放字母，由引理 1 唯一合法延拓为空串，贪心正确停止。否则设 $c^*$ 为最大可放字母，贪心输出 $G = c^* G'$，其中 $G'$ 是放掉一个 $c^*$ 后（余量 $R-1$）状态的贪心延拓。任取 $\sigma$ 的合法延拓 $X$：
  - **$X$ 为空**：空串是任何非空串的前缀，故 $X < G$；
  - **$X$ 首字符 $c < c^*$**：$c$ 可放而 $c^*$ 是最大可放字母，故 $c \le c^*$，即 $c < c^*$；$G$ 与 $X$ 在首位分出胜负，$G > X$；
  - **$X$ 首字符为 $c^*$**：写 $X = c^* X'$，则 $X'$ 是后继状态的合法延拓（$X$ 整体合法 $\iff$ $X'$ 相对新末尾 $c^*$ 合法）。由归纳假设 $G' \ge X'$，于是 $G = c^* G' \ge c^* X' = X$。

  三种情形均有 $G \ge X$，故贪心输出是字典序最大的合法延拓；对初始状态（空前缀）即本题答案。∎

**推论（批量实现的等价性）**：§3.3 / §7 的批量算法与逐字符贪心输出同一串。

**证明**：只需验证批量动作与逐字符贪心在每一步的选字一致：

- **末尾不是 $m$ 时**（$m$ 为最大有余量字母）：放 1 个 $m$ 后不存在更大的可放字母（更大的字母余量皆 0），且 $m$ 自身未封顶（run 从 0 或异字母处重新计数，$< L$），故下一字符仍是 $m$。如此延续到 run $= L$ 或 $\mathrm{cnt}[m] = 0$，恰为一次连放 $\min(\mathrm{cnt}[m], L)$ 个。
- **$m$ 的 run $= L$ 且有余量时**：任何 $\ne \text{last}$ 的字母都可放（run 重置为 1），可放字母中的最大者即次大 $m'$，逐字符贪心垫 1 个 $m'$；随后末尾变为 $m' \ne m$，$m$ 重新可放且仍是最大，回到上一情形。
- **终止**：逐字符贪心止于无可放字母；批量算法止于 $i$ 滑出字母表（全部用尽）或找不到次大 $j$（由引理 1，两者都等价于「唯一延拓是空串」）。∎

> 💡 **证明结构复盘**：引理 1 刻画终止条件，定理用「归纳 + 首位优势」的三情形讨论覆盖所有对手方案——这正是所有**字典序贪心**的证明模板：**任何与贪心不同的选择，都可以在其首个分歧位被直接比下去**。推论则负责把「逐字符的正确贪心」与「工程上的批量实现」焊接起来，这一步在写题解时最容易被省略，也最容易藏实现 bug。

## 6. 复杂度分析

- **时间复杂度**：$O(26 \cdot n)$，视为线性。计数 $O(n)$；主循环每轮至少追加 1 个字符（$k \ge 1$）或立即终止，故轮数 $\le n$，每轮指针至多下滑 26 步。
- **空间复杂度**：$O(26)$ 计数数组 + $O(n)$ 输出串（输出不计则 $O(26)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string repeatLimitedString(string s, int repeatLimit) {
        int cnt[26] = {};
        for (char c : s) ++cnt[c - 'a'];

        string ans;
        ans.reserve(s.size());
        int i = 25;                              // i：当前最大的非空桶
        while (i >= 0 && cnt[i] == 0) --i;

        while (i >= 0) {
            int k = min(cnt[i], repeatLimit);    // 规则一：连放 k 个 i
            ans.append(k, 'a' + i);
            cnt[i] -= k;
            if (cnt[i] == 0) {                   // i 用尽 → 最大字母下移
                while (i >= 0 && cnt[i] == 0) --i;
                continue;
            }
            int j = i - 1;                       // 规则二：找次大非空桶
            while (j >= 0 && cnt[j] == 0) --j;
            if (j < 0) break;                    // 无字母可垫 → 剩余丢弃
            ans.push_back('a' + j);
            --cnt[j];                            // 只垫 1 个，回头继续放 i
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def repeatLimitedString(self, s: str, repeatLimit: int) -> str:
        cnt = [0] * 26
        for c in s:
            cnt[ord(c) - 97] += 1

        ans = []
        i = 25                              # i：当前最大的非空桶
        while i >= 0 and cnt[i] == 0:
            i -= 1

        while i >= 0:
            k = min(cnt[i], repeatLimit)    # 规则一：连放 k 个 i
            ans.append(chr(97 + i) * k)
            cnt[i] -= k
            if cnt[i] == 0:                 # i 用尽 → 最大字母下移
                while i >= 0 and cnt[i] == 0:
                    i -= 1
                continue
            j = i - 1                       # 规则二：找次大非空桶
            while j >= 0 and cnt[j] == 0:
                j -= 1
            if j < 0:                       # 无字母可垫 → 剩余丢弃
                break
            ans.append(chr(97 + j))
            cnt[j] -= 1                     # 只垫 1 个，回头继续放 i
        return ''.join(ans)
```

> ⚠️ 两份代码都已对官方示例与随机小规模暴力对拍验证（645 组全一致）。实现的核心不变式：**`i` 永远指向当前最大非空桶，且 `i` 上方的桶恒为空**——这依赖「计数只减不增」，若代码另有修改计数的地方，必须重新审视该不变式。

## 8. 边界情况与易错点

1. **无垫片必须终止**：`s = "aaa"`，$L=2$ → `"aa"`。找不到次大 $j$ 却不 `break`，会死循环或继续非法地放 `i`。剩余字母丢弃是被迫的（引理 1：它们在任何合法串中都无法出现）。
2. **垫片只放 1 个**：把「垫 1 个次大」写成「连放次大 $\min(\mathrm{cnt}, L)$ 个」会错——第 2 个垫片的位置本应放更大的 $m$。反例：`s = "ccccaa"`，$L=2$，正确 `"ccacca"`，错写得 `"ccaacc"`。
3. **垫片必须取次大而非最小/任意**：`s = "abzz"`，$L=1$，正确 `"zbza"`（b 当垫片）；若用 a 垫得 `"zazb"`，更小。垫片位置的字母直接参与字典序比较。
4. **连放数量取 $\min(\mathrm{cnt}, L)$**：忘记 `min` 会在余量不足时凭空造字符；反向错误（封顶后不敢再放）会漏掉解封后的 $m$（示例 3 的 `"zzaz"`）。
5. **$j$ 的搜索范围**：必须是 $j < i$ 的最大非空桶，且**每轮重新搜索**（垫过的桶可能变空）；写成从 `'z'` 全量重扫不影响正确性，只影响常数。
6. **$L \ge 1$ 由约束保证**：故 $k \ge 1$、循环必然推进；若脑洞扩展到 $L = 0$ 需特判返回空串。
7. **性能细节**：Python 逐字符 `ans += ch` 在最坏情形有 $O(n^2)$ 风险，用列表 + `join`；C++ 记得 `reserve`。$n = 10^5$ 规模下均非必需，但值得养成习惯。
