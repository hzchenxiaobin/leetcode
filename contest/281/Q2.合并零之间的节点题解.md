# LeetCode 合并零之间的节点 题解

## 1. 题目概述

- **标题 / 题号**：合并零之间的节点（#2181，medium）
- **链接**：https://leetcode.cn/problems/merge-nodes-in-between-zeros/
- **来源**：LeetCode 第 281 场周赛 Q2
- **难度**：中等
- **标签**：链表、模拟、双指针、单趟扫描

**题意**：给定链表头节点 `head`，链表由若干整数节点构成，**首尾节点值均为 0**，中间的 0 节点充当分隔符。对**每两个相邻的 0**，把它们之间的所有节点合并成一个值为**总和**的节点，并移除所有 0。返回修改后的链表头节点，要求结果中不含任何 0。

**约束**：

- 节点数目在 $[3,\ 2 \times 10^5]$ 内
- $0 \le \text{Node.val} \le 1000$
- **不存在**连续两个 `Node.val == 0` 的节点
- 链表**开端**与**末尾**节点都满足 `Node.val == 0`

> 💡 **读题定位**：链表模拟基本功题，赛时最短路径是「累加 + 撞零结算 + 新建链表」的朴素版，$O(n)$ 直接可过。本题真正的复盘价值在两个结构性质上：① 题面说「**修改后的**链表」——允许就地改造，而每一段的**左侧必贴一个零节点**，它天生就是承载段和的容器，把分隔符升级为结果节点即可做到 $O(1)$ 空间、零次 `new`；② 首节点必为 0，天然充当结果链表头——**连哑节点都省了**。识别「冗余节点可复用」与「天然哨兵消灭哑节点」，是所有链表就地题的通用思维。

> 📚 本题在本仓库另有[每日题解 2181](../../solution/2101-2200/2181_合并零之间的节点.md)：侧重链表就地改造**两种范式**的对照（「改 `val` 复用节点」vs「改 `next` 重连节点」）与面试问答；本篇作为周赛复盘，补全**循环不变式化的引理-定理证明链**、指针三段划分的算法细节与赛时易错点清单，两篇刻意互补。

## 3. 解题思路

### 3.1 暴力思路：新建链表逐段累加

照题意直译：`cur` 从 `head.next` 起扫描，`sum` 累加非零值；撞到 0 就把 `sum` 封装成新节点接到结果链表尾部，然后 `sum` 清零。

```text
dummy = ListNode(0); tail = dummy
cur = head.next; sum = 0
while cur != null:
    if cur.val == 0:  tail.next = ListNode(sum); tail = tail.next; sum = 0
    else:             sum += cur.val
    cur = cur.next
return dummy.next
```

时间 $O(n)$，在 $n \le 2\times10^5$ 下**没有任何超时风险**——这份「暴力」本身就是正解的骨架。可挑剔的只有两点：

- **多分配了 $k$ 个节点**（$k$ 为段数，最多约 $10^5$ 个），空间 $O(k)$；
- 原链表的 $k+1$ 个零节点是**注定被丢弃的冗余节点**，同时又 `new` 了 $k$ 个新节点来装段和——一弃一造，两头浪费。

> ⚠️ 优化方向由此浮现：题目措辞是「**修改后的**链表」，即允许就地改造。能否让「被丢弃的零节点」自己变成「承载段和的结果节点」？

### 3.2 核心观察：每段左侧必贴一个零节点——分隔符复用为段和容器

![核心观察：零节点从分隔符升级为段和容器](images/wc281_q2_zero_reuse_concept.svg)

把链表按零节点切开：$\text{head} = z_0 \to \underbrace{a_1 \cdots a_x}_{\text{段}_0} \to z_1 \to \underbrace{b_1 \cdots b_y}_{\text{段}_1} \to z_2 \to \cdots \to z_k$。两条结构性观察：

1. **零节点就是现成的容器**：第 $i$ 段的左侧零节点 $z_i$ 在结果链表中的位置、时机都恰到好处——扫描完第 $i$ 段、撞上 $z_{i+1}$ 时，把段和直接写进 $z_i.\text{val}$，$z_i$ 便从「待删除的分隔符」变身「第 $i$ 个结果节点」。结果链表的节点**全部来自原零节点**（末尾零除外），一个都不用新建。
2. **首零天然是结果链表头**：$z_0 = \text{head}$，把它改写为 $\text{sum}(\text{段}_0)$ 之后仍是链表头——**无需哑节点**，最后直接返回 `head`。这与需要删头、不得不补哑节点的链表题（如 2095）形成鲜明对照。

由此得到就地版双指针骨架：`tail` 指向「当前正在填充的零节点」（即当前段左侧零），`cur` 从 `head.next` 起向后扫描；`cur` 撞零时结算，`tail` **跳到 `cur` 上**——因为 `cur` 此刻正停在**下一段的左侧零**上，恰好继续当容器，一段一节点走完整条链。

### 3.3 算法流程

![算法流程：tail/cur 双指针单趟扫描，撞零结算、末尾切断](images/wc281_q2_algorithm_flow.svg)

**完整步骤**：

1. **初始化**：`tail = head`（首零 = 第 0 段的容器），`cur = head.next`（跳过首零，从第一个值节点扫起），`sum = 0`。
2. **循环 `while cur != null`**：
   - **非零**：`sum += cur.val`；
   - **撞零**（`cur.val == 0`，`cur` 是当前段的右侧零）：
     1. `tail.val = sum`（段和写进左侧零）；
     2. 若 `cur.next == null`——`cur` 是**末尾零**，全部段已结算：`tail.next = null` 切断，跳出循环；
     3. 否则：`tail.next = cur`（把该零串进结果链表），`tail = cur`（升级为下一段容器），`sum = 0`；
   - `cur = cur.next`。
3. **返回** `head`。

> ⚠️ 两处最易翻车的动作：① **末尾切断**——最后一段结算后 `cur` 停在末尾零上，必须显式 `tail.next = null`，否则结果链表会拖着值为 0 的尾巴；② **`sum` 清零时机**——必须先 `tail.val = sum` 再 `sum = 0`，先清零会把当前段已累加的和抹掉。

### 3.4 示例演算

![示例演算：[0,3,1,0,4,5,2,0] 与 [0,1,0,3,0,2,2,0] 的逐步走查](images/wc281_q2_example_walkthrough.svg)

**示例 1：`head = [0,3,1,0,4,5,2,0]`**

| 步骤 | `cur.val`（本步扫描值） | `sum`（步末） | 动作 |
|------|---------|-------|------|
| 初始 | — | 0 | `tail = head`（首零 z₀），`cur = head.next` |
| 扫 3 | 3 | 3 | 累加 `sum = 3` |
| 扫 1 | 1 | 4 | 累加 `sum = 4` |
| 撞零① | 0 | 0 | `tail.val = 4`；串入 z₁，`tail = z₁`，`sum = 0` |
| 扫 4 | 4 | 4 | 累加 `sum = 4` |
| 扫 5 | 5 | 9 | 累加 `sum = 9` |
| 扫 2 | 2 | 11 | 累加 `sum = 11` |
| 撞零② | 0 | 11 | `tail.val = 11`；`cur` 是尾零 → `tail.next = null`，结束 |

结果：首零已改写为 $4$，第二个零改写为 $11$，即 `[4, 11]` ✓。中间的 `3,1,4,5,2` 全部被「跳过」，两个零节点零成本复用为结果链表的仅有的两个节点。

**示例 2：`head = [0,1,0,3,0,2,2,0]`**（三段）：三个零依次改写为 $1, 3, 4$；`cur` 到末尾零时切断，末尾零丢弃，结果 `[1,3,4]` ✓——注意本例有**四个零**，结果链表只保留前三个，末尾切断分支正是为此存在。

## 4. 算法细节

1. **指针不变式**：整个循环过程中维持三段划分——**已固定前缀**（`head` 到 `tail`，均为改写完的零节点）、**当前段工作区**（`tail` 之后到 `cur` 之前，正在累加）、**未处理后缀**（`cur` 起）。`sum` 恒等于工作区内已扫过的节点值之和。撞零的动作就是「工作区收编进前缀、后继零升格为新的工作区容器」。
2. **结算三步的顺序**：`tail.val = sum` → 串联（或切断）→ `sum = 0`。先写值再清零，顺序不可调换（见 §8 易错点 3）。
3. **`tail` 跳到 `cur` 而不是 `new`**：撞零时 `cur` 恰好停在**下一段的左侧零**上——串入结果链表并让它当下一个填充目标，正好实现「一段一节点」。末尾零 `cur.next == null` 时它**不再升格**（后面没有段了），而是被切断丢弃。
4. **为什么不需要哑节点**：`head.val == 0` 由约束保证，首节点天然就是第 0 段的容器与结果链表头。若仍套哑节点模板，反而多出一个需要跳过的虚拟节点——「哑节点是补边界用的，天然边界已存在时就是累赘」。
5. **结果节点数 = 段数 = 零节点数 − 1**：$k+1$ 个零节点中前 $k$ 个复用为结果节点，末尾零丢弃；非零节点全部被跳过。就地版全程零次节点分配。
6. **溢出核算**：最大段和 $\le (n-2) \times 1000 \approx 2 \times 10^8 < 2^{31}-1$，`int` 安全，无需 `long long`。

## 5. 正确性证明

把链表中所有 `val == 0` 的节点按出现顺序记为 $z_0, z_1, \ldots, z_k$（$z_0 = \text{head}$ 为首零，$z_k$ 为末尾零，$k \ge 1$）；$\text{seg}_i$ 表示 $z_i$ 与 $z_{i+1}$ 之间的节点序列（$0 \le i \le k-1$），$s_i$ 为其节点值之和。

**引理 1（零节点即分隔符，段内皆非零）**：每个 $\text{seg}_i$ 非空，且其中节点的值均不为 0。

**证明**：若 $\text{seg}_i$ 为空，则 $z_i$ 与 $z_{i+1}$ 是相邻节点且值均为 0，违反「不存在连续两个 0」；若 $\text{seg}_i$ 中有值 为 0 的节点 $u$，则 $u$ 也是一个零节点且严格介于 $z_i$、$z_{i+1}$ 之间，与「$z_i$、$z_{i+1}$ 是相继出现的两个零节点」矛盾。∎

**引理 2（段和非零）**：$s_i \ge 1$ 对所有 $i$ 成立。

**证明**：由引理 1，$\text{seg}_i$ 至少含一个节点且值非零，又 $0 \le \text{val} \le 1000$，故每个节点值 $\ge 1$，从而 $s_i \ge 1$。∎

**定理（就地算法正确）**：算法返回的链表依次为 $(s_0, s_1, \ldots, s_{k-1})$，特别地不含任何值为 0 的节点。

**证明**：用循环不变式。设 $j$ 为已完成结算的段数（初始 $j = 0$），断言每轮循环开始时：

- **(I1)** 从 `head` 沿 `next` 走到 `tail` 的链恰为 $(s_0, \ldots, s_{j-1})$，且 `tail` $= z_j$（第 $j$ 段的左侧零，已串入结果链）；
- **(I2)** `sum` $=$ $\text{seg}_j$ 中已被 `cur` 扫过的节点值之和；
- **(I3)** `cur` 指向 $\text{seg}_j$ 中首个未计入 `sum` 的节点，或恰为 $z_{j+1}$。

**初始化**：`tail = head =` $z_0$，结果链尚未有任何已结算段（$j=0$，(I1) 平凡成立）；`cur = head.next`，由引理 1 它属于 $\text{seg}_0$ 或等于 $z_1$，`sum = 0`，(I2)(I3) 成立。

**保持**：若 `cur.val` $\ne 0$，则 `cur` 是 $\text{seg}_j$ 中的节点，`sum` 累加后 (I2) 保持，`cur` 前移后 (I3) 保持，(I1) 不动。若 `cur.val` $= 0$，则由 (I3) 与引理 1，`cur` $= z_{j+1}$，且 $\text{seg}_j$ 的所有节点均已扫过——于是 (I2) 中 `sum` $= s_j$，执行 `tail.val = sum` 后 $z_j$ 的值恰为 $s_j$：

- 若 `cur.next` $\ne$ `null`，则 $z_{j+1}$ 非末尾零，`tail.next = cur` 把 $z_{j+1}$ 接到结果链尾，`tail = cur` 使 (I1) 对 $j+1$ 成立；`sum = 0` 与 `cur = cur.next`（由引理 1 落在 $\text{seg}_{j+1}$ 或 $z_{j+2}$ 上）重建 (I2)(I3)；
- 若 `cur.next` $=$ `null`，则 `cur` $= z_k$ 为末尾零，此时 $j + 1 = k$，即全部 $k$ 段均已结算，(I1) 给出结果链 $(s_0, \ldots, s_{k-1})$；`tail.next = null` 切断后循环结束。

**终止**：`cur` 每轮严格后移，至多 $n$ 轮后 `cur == null` 退出；由上述第二种撞零情形，退出时结果链即 $(s_0, \ldots, s_{k-1})$。结合引理 2，链中每个值 $\ge 1$，无 0。∎

**推论**：§3.1 的新建链表版与就地版输出完全相同（两者都输出段和序列），仅空间与是否修改原链表不同。∎

> 💡 **证明结构复盘**：这是标准的「循环不变式三件套」——初始化、保持、终止。链表就地改造题的证明抓手，就是刻画清楚「**已固定前缀 + 工作区 + 未处理后缀**」的三段划分，再逐一验证每个动作不破坏划分。引理 2 看似废话（段和当然非零），实则是把「结果不含 0」这条**输出要求**正式收进证明体系的一环——没有它，定理只说明输出是段和序列，还不能断言满足题目约束。另外注意引理 1 完全依赖「不存在连续两个 0」这条约束；若约束松动，见 §8 易错点 5 的讨论。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`cur` 单趟扫描，每个节点恰好被处理一次（非零累加、或撞零结算的 $O(1)$ 动作）；结算共发生 $k$ 次，合计仍是常数乘 $n$。
- **空间复杂度**：就地复用版 $O(1)$——仅 `tail`、`cur`、`sum` 三个局部量，结果链表节点全部复用原零节点，零次分配（输出链表本身不计入额外空间）。新建链表版为 $O(k)$ 额外节点分配，$k \le (n-1)/2$。

## 7. 参考代码

### C++（就地复用版，推荐）

```cpp
class Solution {
  public:
    ListNode* mergeNodes(ListNode* head) {
        ListNode* tail = head;        // 当前段的左侧零节点（填充目标）
        ListNode* cur = head->next;   // 从第一个值节点扫起
        int sum = 0;
        while (cur != nullptr) {
            if (cur->val == 0) {
                tail->val = sum;      // 段和写进左侧零
                if (cur->next == nullptr) {
                    tail->next = nullptr; // 末尾零：切断，丢弃
                    break;
                }
                tail->next = cur;     // 该零串入结果链
                tail = cur;           // 升格为下一段容器
                sum = 0;
            } else {
                sum += cur->val;
            }
            cur = cur->next;
        }
        return head;                  // 首零已改写为 s0，仍是链表头
    }
};
```

### Python（新建链表版，赛时保底对照）

```python
class Solution:
    def mergeNodes(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = tail = ListNode()
        cur, s = head.next, 0
        while cur:
            if cur.val == 0:
                tail.next = ListNode(s)
                tail = tail.next
                s = 0
            else:
                s += cur.val
            cur = cur.next
        return dummy.next
```

> ⚠️ 三份代码均已对官方示例、自造边界用例（`[0,5,0]`、`[0,2,7,0,9,0]`）及随机生成的合法链表（含单节点段、超长段、值 1 与 1000 混合）与新建链表版对拍验证，全部一致。就地版的核心不变式：**`tail` 永远指向当前段的左侧零节点，`cur` 永远在 `tail` 之后**——任何改动若破坏这条性质（例如让 `tail` 越过 `cur`），必须重新过一遍 §5 的证明。

## 8. 边界情况与易错点

1. **最短输入 `[0,5,0]`**：一次撞零即「结算 + 切断」同时发生，`cur.next == null` 分支必经。用它做最小用例心算，能同时覆盖两个分支。

2. **末尾切断不可漏**：最后一段结算时 `tail` 的 `next` 原本指向末尾零，不置 `null` 则输出形如 `[4, 11, 0]`——恰好违反「不应含有任何 0」，且多数测试都能暴露。判定条件写 `cur->next == nullptr`（`cur` 是末尾零）而非 `cur == nullptr`，后者永远等不到：循环体里 `cur` 停在零上时就要决策。

3. **`sum` 清零时机**：顺序必须是「先 `tail.val = sum`，后 `sum = 0`」。先清零再结算会把当前段整个抹为零——输出一串 0，立即违反约束，好在极易发现；更隐蔽的是把 `sum = 0` 写进「非零累加」分支，那会在每个节点处清零，段和永远只剩最后一个节点。

4. **不要画蛇添足加哑节点**：`head` 本身就是首零。若强行套 `dummy` 模板，返回 `dummy.next` 也没错，但白白多一次分支判断与指针赋值；更重要的是会掩盖「天然哨兵」这一结构观察。判别口诀：**只有「需要删除/替换头节点」的链表题才必须哑节点**。

5. **「不存在连续两个 0」是引理 1 的命门**：它保证每段非空、段内皆非零、每个 0 都是无歧义的分隔符。若约束松动（允许空段），撞零时 `sum == 0` 的段应跳过不产出节点，就地版需要额外分支；本题范围内无需考虑，但面试中主动点出这条依赖是加分项。同理，`0 <= Node.val` 中"值恰为 0 的节点即分隔符"这一读法，正是由引理 1 背书的。

6. **溢出核算**：最大段和 $\le (2\times10^5 - 2) \times 1000 < 2^{31} - 1$，32 位 `int` 全程安全；Python 无此问题。

7. **Python 别用递归**：$n = 2 \times 10^5$ 超出默认递归深度（1000）两个数量级，递归版会在深链上 `RecursionError`——链表题一律迭代。

8. **修改原链表是题目允许的**：题面明说「修改后的链表」，就地改写零节点的 `val` 与 `next` 合法；若面试官追加「不许修改原链表」，切换到新建链表版即可（§7 第三份代码），时间复杂度不变、空间退化为 $O(k)$。

**延伸思考**：

- **若允许连续两个 0（空段）**：撞零时 `sum == 0` 说明是空段，应跳过——就地版不能把空段也产出一个值为 0 的节点（违反「不含 0」），需在串联前判 `sum > 0` 或定义空段合并规则。可拿本题代码改造练手，体会约束变化对引理 1 的冲击。
- **若不允许修改原链表**：退回新建链表版，$O(k)$ 空间不可避免，但证明与复杂度框架完全复用——「就地 vs 新建」的取舍只看「原链表是否有可复用的冗余节点 + 是否允许修改」两个条件。
- **分隔符泛化**：把 0 换成任意哨兵值（如 $-1$）或「满足某谓词的节点」，算法与证明逐字成立——引理与定理中从未用到 0 的数值特性，只用到「分隔节点序列把链表切成段」这一结构。
- **游程编码视角**：本题本质是对链表按分隔符做**游程压缩**（run-length 式的段和折叠）。把「段和」换成「段 max / 段计数 / 段首值」，就得到一族同构的链表分段聚合题，模板可整体迁移。
