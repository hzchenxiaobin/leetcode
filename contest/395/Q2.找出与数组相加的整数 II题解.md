# LeetCode 找出与数组相加的整数 II 题解

## 1. 题目概述

- **标题 / 题号**：找出与数组相加的整数 II（#3132，medium）
- **链接**：https://leetcode.cn/problems/find-the-integer-added-to-array-ii/
- **来源**：LeetCode 第 395 场周赛 Q2
- **难度**：中等
- **标签**：数组、排序、双指针、枚举

**题意**：给定两个整数数组 `nums1` 和 `nums2`，`nums1` 恰好比 `nums2` 多 **2** 个元素。先从 `nums1` 中**移除两个元素**，再给其余所有元素统一加上整数 `x`（`x` 为负则表现为减少），要求结果与 `nums2` **相等**——当两个数组包含相同的整数且出现频次相同时视为相等（与顺序无关）。返回能实现相等的**最小**整数 `x`。题目保证至少存在一个合法的 `x`。

**约束**：

- `3 <= nums1.length <= 200`
- `nums2.length == nums1.length - 2`
- `0 <= nums1[i], nums2[i] <= 1000`
- 测试用例保证存在合法的 `x`（无需处理无解）

## 2. 示例

**示例 1**

```text
输入：nums1 = [4,20,16,12,8], nums2 = [14,18,10]
输出：-2
解释：移除 nums1 中下标 [0,4] 的两个元素（值 4 与 8），其余元素加 -2 得 [18,14,10]，与 nums2 相等。
```

**示例 2**

```text
输入：nums1 = [3,5,5,3], nums2 = [7,7]
输出：2
解释：移除两个 3，剩下 [5,5] 加 2 得 [7,7]。
```

**示例 3（构造）**

```text
输入：nums1 = [1,5,6,7,100], nums2 = [2,3,4]
输出：-3
解释：删 1 与 100、加 -3 得 [2,3,4]。从 j=2 生成的第一个候选 x=-4 会验证失败，必须回退到 j=1。
```

## 3. 解题思路

### 3.1 暴力思路

「删两个元素」看起来是一个不小的组合自由度，朴素做法都围绕它展开：

1. **枚举删法**：$\binom{n}{2} \approx 2 \times 10^4$ 种「删两个下标」的组合，每种删完后排序逐位比对（或哈希计数验证），单次 $O(n)$，总量约 $4 \times 10^6$。`n ≤ 200` 完全能过，但下标组合、去重、`x` 的计算细节多，赛场上代码风险偏高。
2. **枚举值域**：由 $0 \le \text{nums}_1[i], \text{nums}_2[i] \le 1000$ 知 $x \in [-1000, 1000]$ 共 2001 个候选，每个候选用计数数组验证——但「验证」仍要内嵌「允许删两个」的判定，又绕回枚举删法。

两条路的共同盲区：把「删两个」当成必须**显式枚举**的自由度。而排序配对的结构会告诉我们：这 2 个删除带来的自由度其实小得可怜——合法的候选 $x$ **至多 3 个**。

### 3.2 核心观察：合法 x 至多 3 个候选

![核心观察：删 2 个元素后，保留最小值只可能落在排序后前 3 格](images/added_int_ii_candidates.svg)

沿用 Q1（3131）的配对链：**多重集相等 ⇔ 排序后逐位相等**，而全体 $+x$ 是整体平移，不改变元素间的大小次序。把两个数组都排序，任取一个合法方案：

1. $\text{nums}_2[0]$ 是 `nums2` 的最小值，它配对的一定是 `nums1` **保留下来的元素中的最小值**——更小的元素在 `nums2` 里没有任何对象可配；
2. 设这个「保留最小」在排序后 `nums1` 中的下标为 $j$，则下标 $< j$ 的元素全都比它小，**必须全部被删除**；
3. 只允许删 2 个 $\Rightarrow j \le 2$。

于是所有合法的 $x$ 被**夹**进一个至多 3 个元素的候选集：

$$x_j = \text{nums}_2[0] - \text{nums}_1[j], \quad j \in \{0, 1, 2\}$$

再注意到 $\text{nums}_2[0]$ 固定、$\text{nums}_1[j]$ 随 $j$ 增大而增大，所以 $x_j$ 随 $j$ 增大而减小——**从 $j=2$ 开始试，第一个通过验证的候选就是最小 $x$**，连 `min()` 都省了。

> ⚠️ $j=2$ 并不保证成功：干扰元素可能出现在「保留最小」的**两侧**（见 §3.4 构造样例 `[1,5,6,7,100]` 删 `1` 和 `100`），此时保留最小落在 $j=1$ 甚至 $j=0$。枚举方向必须是 $2 \to 1 \to 0$ 的**回退链**，不能只验一个候选了事。

### 3.3 算法流程：候选枚举 + 双指针验证

![算法流程：排序、回退链 j=2→0、双指针验证、首过即返](images/added_int_ii_verify_flow.svg)

每个候选 $x$ 的合法性用**双指针**在有序数组上 $O(n)$ 判定：指针 $k$ 扫 `nums1`、指针 $p$ 扫 `nums2`——

- $\text{nums}_1[k] + x = \text{nums}_2[p]$：配对成功，$k{+}{+},\ p{+}{+}$；
- 否则 $\text{nums}_1[k]$ 配不上当前及之后的任何目标，**视为删除**，$k{+}{+}$。

判定条件只有一条：**$p$ 是否走完 `nums2`**。两数组长度恰差 2，$p$ 走完时被跳过的元素恰好就是被删的 2 个——长度守恒替我们免去了显式的删除计数。

整体流程：排序两个数组 → 按 $j = 2, 1, 0$ 生成候选并验证 → 首个通过者即答案。

### 3.4 示例演算

![示例演算：官方样例一步命中 vs 构造样例回退命中](images/added_int_ii_example_walkthrough.svg)

| 样例 | 排序后 | $j=2$ 候选 | 验证结果 | 答案 |
|------|--------|:---:|------|:---:|
| 例 1 `[4,20,16,12,8]` / `[14,18,10]` | `[4,8,12,16,20]` / `[10,14,18]` | $10-12=-2$ | 删 4、8，配齐 3 对 ✓ | **−2** |
| 例 2 `[3,5,5,3]` / `[7,7]` | `[3,3,5,5]` / `[7,7]` | $7-5=2$ | 删两个 3，配齐 2 对 ✓ | **2** |
| 构造 `[1,5,6,7,100]` / `[2,3,4]` | 同序 | $2-6=-4$ | $100-4=96 \ne 4$，`4` 无人可配 ✗ | **−3**（回退 $j=1$：$2-5=-3$，删 1、100 ✓） |

两个官方样例都在 $j=2$ 一步命中——这正是「看似只需试一个候选」的错觉来源；构造样例的干扰元素 `1`、`100` 一左一右夹住真解，逼出完整的 $2 \to 1 \to 0$ 回退链。另外例 1 中 $x \in \{-2, 2, 6\}$ 其实**全部合法**（对应三种不同删法），题目要的是其中的最小者。

## 4. 算法细节

1. **验证器的三分支语义**（两数组均已排序）：
   - $\text{nums}_1[k] + x < \text{nums}_2[p]$：当前元素偏小，后面目标只增不减，它只能被删（跳过）；
   - $\text{nums}_1[k] + x > \text{nums}_2[p]$：后面元素只会更大，$\text{nums}_2[p]$ **永远配不上**，$p$ 卡死，最终走不完 → 该 $x$ 非法（循环自然结束即可，$n \le 200$ 无需提前 break）；
   - 相等即配：配对由值唯一决定（$a$ 只能配 $a+x$），等值元素可互换（交换论证），「能配就配」永不劣。
2. **免计数的原理**：若 $p$ 最终走完，配对数 $= m$，跳过数 $= n - m = 2$ **自动成立**；反之若某个值配不上，$p$ 必然卡死在中途。所以判定只需 `return p == m`，既不会漏判「删多了」也不会漏判「删少了」。
3. **枚举顺序即答案序**：$x_j$ 随 $j$ 递减，按 $2 \to 1 \to 0$ 验证，首个合法候选就是最小 $x$。若写成 $0 \to 1 \to 2$，必须三个全验完再取 `min`——正确但白做验证，且例 1 会先撞上合法的 $x=6$，忘记取 `min` 直接 WA。
4. **候选重复无妨**：重复元素会让不同的 $j$ 生成同一个 $x$（例 2 的 $j=1$、$j=2$ 都是 $x=2$），重复验证一次 $O(n)$，无碍。
5. **等价实现**：用 `Counter`/值域桶做「逐值对消」同样 $O(n)$：`a+x` 在计数器里就扣减，否则计入删除，最终删除数恰为 2 即合法。双指针版胜在零额外空间。

## 5. 正确性证明

**引理 1（平移保序，排序逐位对齐）**：对多重集 $A$ 与整数 $x$，$A + x = B$（多重集相等）当且仅当排序后 $\text{sorted}(A)[i] + x = \text{sorted}(B)[i]$ 对所有 $i$ 成立。

**证明**：多重集相等即元素值与频次一致；全体加 $x$ 是值到值的一一映射，保持频次与大小次序，故 $A + x$ 的升序排列恰为 $A$ 的升序排列逐项加 $x$，反之亦然。∎

**引理 2（候选集刻画）**：设 $x$ 为任一合法整数（两数组均指排序后），则 $x \in \{\text{nums}_2[0] - \text{nums}_1[j] \mid j \in \{0,1,2\}\}$。

**证明**：设删除集 $D$（$|D| = 2$），$A$ 为 `nums1` 删除 $D$ 后所得多重集，则 $A + x = \text{nums}_2$。由引理 1，$\text{sorted}(A)[0] + x = \text{nums}_2[0]$。而 $\text{sorted}(A)$ 是 $\text{sorted}(\text{nums}_1)$ 删除 2 项后的子列，其首元素在原序列中的下标 $j$ 满足 $j \le 2$——若 $j \ge 3$，则下标 $0,1,2$ 三项全被删除，与 $|D| = 2$ 矛盾。于是 $\text{nums}_1[j] = \text{sorted}(A)[0] = \text{nums}_2[0] - x$。∎

**引理 3（验证器充要）**：对候选 $x$，双指针扫描结束时 $p = m$ 当且仅当 $x$ 合法。

**证明**：记 $c_1(v) = \#\{a \in \text{nums}_1 : a + x = v\}$，$c_2(v) = \#\{b \in \text{nums}_2 : b = v\}$。$x$ 合法等价于对每个 $v$ 都有 $c_1(v) \ge c_2(v)$（`nums2` 的每个值都能被配走）；此时由长度守恒 $\sum_v (c_1(v) - c_2(v)) = n - m = 2$ 自动成立，盈余恰为要删的 2 个元素。双指针在有序数组上恰好实现**逐值对消**：扫到值 $v - x$ 时与 `nums2` 中连续排布的 $v$ 逐一配对，$c_1$ 的盈余被跳过；若某值 $c_1(v) < c_2(v)$，则扫完所有 $v - x$ 后 $p$ 停在该值上，后续 `nums1` 元素更大、加 $x$ 后仍大于 $v$，$p$ 永远无法推进。故 $p = m \iff \forall v:\ c_1(v) \ge c_2(v) \iff x$ 合法；且 $p = m$ 时跳过数 $= n - m = 2$，删除数恰好合规。∎

**定理（最小性）**：按 $j = 2, 1, 0$ 的顺序验证候选、返回首个通过者，得到的是所有合法 $x$ 的最小值。

**证明**：由引理 2，合法 $x$ 全体是候选集的子集；由引理 3，验证器对每个候选的判定精确无偏。`nums1` 有序使 $x_j = \text{nums}_2[0] - \text{nums}_1[j]$ 关于 $j$ 递减，故验证顺序恰为候选升序。升序扫描中首个通过者即合法集的最小元；题面保证合法集非空，扫描必在 $j \ge 0$ 内命中返回。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导。随后至多 3 次验证、每次双指针线性扫描 $O(n)$，合计 $O(3n) = O(n)$。$n \le 200$，实际开销微秒级。
- **空间复杂度**：$O(1)$ 额外空间——原地排序加两个整型指针（不计语言排序栈）。计数器变体需要 $O(2001)$ 值域桶或 $O(n)$ 哈希表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumAddedInteger(vector<int>& nums1, vector<int>& nums2) {
        sort(nums1.begin(), nums1.end());
        sort(nums2.begin(), nums2.end());
        // x = nums2[0] - nums1[j] 随 j 增大而减小：从 j=2 开始试最小候选
        for (int j = 2; j >= 0; j--) {
            int x = nums2[0] - nums1[j];
            if (check(nums1, nums2, x)) return x;
        }
        return 0;  // 题面保证有解，不会到达
    }

private:
    // 双指针验证：被跳过的 nums1 元素即视为删除，p 走完 nums2 即合法
    bool check(const vector<int>& a, const vector<int>& b, int x) {
        int p = 0;
        for (int v : a) {
            if (p < (int)b.size() && v + x == b[p]) p++;
        }
        return p == (int)b.size();
    }
};
```

### Python

```python
class Solution:
    def minimumAddedInteger(self, nums1: List[int], nums2: List[int]) -> int:
        nums1.sort()
        nums2.sort()

        def check(x: int) -> bool:
            p = 0
            for v in nums1:
                if p < len(nums2) and v + x == nums2[p]:
                    p += 1
            return p == len(nums2)

        for j in (2, 1, 0):  # 候选升序：首个合法即最小 x
            x = nums2[0] - nums1[j]
            if check(x):
                return x
        return 0  # 题面保证有解，不会到达
```

> 💡 **写法盘点**：
> - **免计数**：`check` 里不维护「删除数 ≤ 2」——长度差恰为 2，`p` 走完时跳过数自动等于 2。若泛化为「删 k 个」则需补显式计数（见延伸思考）。
> - **枚举顺序即答案序**：从 $j=2$ 回退，首个合法候选就是最小 $x$；若按 $j=0 \to 2$ 枚举，必须三个全验完再取 `min`。
> - **一步命中错觉**：两个官方样例都在 $j=2$ 命中，容易误以为「试一个就够」；构造样例 `[1,5,6,7,100]` 专治这个侥幸。

## 8. 边界情况与易错点

1. **只验 $j=2$ 就返回**：干扰元素可夹在两端（构造样例 `[1,5,6,7,100]` / `[2,3,4]` 的 `1` 与 `100`），保留最小可能落在 $j=1$ 或 $j=0$，必须走完 $2 \to 1 \to 0$ 回退链。
2. **枚举方向写反**：按 $j=0 \to 2$ 且不取 `min`，例 1 会先命中合法的 $x=6$（$4+6=10$、$8+6=14$、$12+6=18$，删 16、20）而错误输出 6——合法 $x$ 不止一个（例 1 中 $-2, 2, 6$ 全合法），题目要**最小**。
3. **「恰删 2 个」不是「至多 2 个」**：双指针版由 `p == m` 隐式保证；若用计数版验证，条件必须是 `removed == 2`（`removed < 2` 由长度守恒不可能出现，`removed > 2` 必须判非法）。
4. **「能配就配」不能犹豫**：配对由值唯一决定（$a$ 只能配 $a+x$），等值元素可互换；跳过一个能配的元素只会让后面的目标更难配上。
5. **重复元素**：不同 $j$ 可能生成同一候选（例 2 的 $j=1$、$j=2$ 同为 $x=2$），重复验证无害；**不要**用 `set` 去重数组——频次信息是「相等」定义的一部分。
6. **x 为负数**：例 1 答案是 $-2$；做差方向固定为 $\text{nums}_2[0] - \text{nums}_1[j]$，写反恰好得到 $-x$。
7. **兜底返回**：题面保证有解，循环内必然 `return`；末尾的 `return 0` 只是防御性占位，正常数据不会到达。
8. **最小规模 $n=3$**（$m=1$）：排序后取前 3 个候选的做法依然正确，无需特判。
