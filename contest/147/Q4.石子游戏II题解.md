# LeetCode 石子游戏 II 题解

## 1. 题目概述

- **标题 / 题号**：石子游戏 II（#1140，medium）
- **链接**：https://leetcode.cn/problems/stone-game-ii/
- **来源**：LeetCode 第 147 场周赛 Q4
- **难度**：中等
- **标签**：Minimax、数组、数学、动态规划、博弈论、前缀和、零和博弈

**题意**：$n$ 堆石子排成一行，第 $i$ 堆有 `piles[i]` 颗（全为正）。Alice 先手，初始 $M = 1$；每回合当前玩家拿走**剩余前缀**里的前 $X$ 堆，要求 $1 \le X \le 2M$，随后 $M \leftarrow \max(M, X)$ 并换手；直到所有堆被拿完。双方都发挥最优，返回 **Alice 能拿到的最大石子数**。

**约束**：

- $1 \le n = \text{piles.length} \le 100$
- $1 \le \text{piles}[i] \le 10^4$
- 所有堆最终都会被拿完，不存在跳过或丢弃

> 💡 **与 #877 的区别**：877 每回合只能从**两端取 1 堆**，状态是区间 $[l, r]$；本题每回合只能从**左端取一整段前缀**，且上限 $2M$ 会随取法增长。左端固定后「区间」退化成一个下标 $i$，状态变成「起点 + 参数 $M$」——但 $M$ 必须进状态，否则无法判断对手能拿多少。

## 2. 示例

**示例 1**

```text
输入：piles = [2,7,9,4,4]
输出：10
解释：Alice 先取 1 堆（2），Bob 取 2 堆（7+9=16），M 变为 2；
      Alice 再取剩下 2 堆（4+4=8），总计 2+8 = 10。
      若 Alice 开局取 2 堆（2+7=9），Bob 可直接取走剩下 3 堆（9+4+4=17），
      Alice 只有 9 颗，故答案为 10。
```

**示例 2**

```text
输入：piles = [1,2,3,4,5,100]
输出：104
解释（补充的一条最优链路）：Alice 取 1 堆（1）→ Bob 取 1 堆（2）
      → Alice 取 1 堆（3）→ Bob 取 2 堆（4+5=9，M 变为 2）
      → Alice 一次取走 100，总计 1+3+100 = 104。
```

**示例 3**（自造边界，非官方）

```text
输入：piles = [5]
输出：5
解释：只剩 1 堆，2M = 2 ≥ 1，Alice 一次拿完。
```

## 3. 解题思路

### 3.1 暴力思路

从 $(i, M) = (0, 1)$ 出发，递归枚举每个合法 $X$，再让对手在新区间上枚举。第 $k$ 层分支数至多 $2M_k$，而 $M_k$ 单调不减，由于 $M$ 单调不减，路径数不超过「把 $n$ 拆成若干段」的 composition 总数 $2^{n-1}$，$n = 100$ 时约 $6.3 \times 10^{29}$，即便剪掉非法分支也远超 $10^{12}$。问题在于同一个 $(i, M)$ 会被不同路径反复抵达，因此必然要做记忆化；而记忆化的前提是先回答：$(i, M)$ 是否刻画了后续博弈的全部信息？

### 3.2 核心观察：后缀状态 + 零和化简

![状态设计：后缀状态与后缀和](images/wc147_q4_state_model.svg)

**观察一：状态只需 $(i, M)$。** 走到某一步时，已经被拿走的堆恰好是前缀 $[0, i)$（因为每回合都从剩余部分的最左端整段取走），所以「还剩哪些堆」完全由 $i$ 决定；「下一步能取几堆」完全由 $M$ 决定。历史只在 $M$ 里留下痕迹，得分不改变任何合法走法，因此 $(i, M)$ 是充分状态。

**观察二：这是一个零和博弈。** 剩余后缀 $[i, n)$ 的石子总量 $S_i$ 最终会被两人**全部拿完**，总分固定。于是「当前玩家拿多少」与「对手少拿多少」是同一件事，收益满足

$$a_{\text{me}} = S_i - a_{\text{opp}}$$

所以递归只需记录**当前玩家**一个人的收益，不必记录双方比分，也不必区分「轮到谁」——换手后同一个函数照样适用。

综合得到转移方程（$S_i$ 为后缀和，$dp(n, \cdot) = 0$）：

$$dp(i, M) = \max_{1 \le x \le \min(2M,\ n-i)} \Bigl( S_i - dp\bigl(i + x,\ \max(M, x)\bigr) \Bigr)$$

答案为 $dp(0, 1)$。

**为什么不能贪心**：对 `[2,7,9,4,4]`，开局 $2M = 2$，取 2 堆立刻拿到 9 颗，看起来比取 1 堆的 2 颗划算；但取 2 堆会令 $M$ 变成 2，Bob 面对后缀 `[9,4,4]` 时可以直接全拿 17 颗，Alice 只剩 9。取 1 堆时 $M$ 仍是 1，Bob 只能取 1 或 2 堆，Alice 最终拿到 10。**本回合收益最大 ≠ 全局收益最大**，因为 $X$ 越大，送给对手的 $M$ 也越大。

### 3.3 算法流程与状态转移

![自底向上填表顺序与转移分支](images/wc147_q4_dp_order.svg)

1. 预处理后缀和 $S_i = \sum_{k=i}^{n-1} \text{piles}[k]$，令 $S_n = 0$，边界 $dp(n, \cdot) = 0$ 自动成立。
2. 因为 $dp(i, M)$ 只引用 $i' = i + x > i$ 的状态，**按 $i$ 从 $n-1$ 递减到 0** 递推即可；同一行内 $m$ 的枚举顺序无关（行内状态互不引用）。
3. **剪枝**：若 $2M \ge n - i$，当前玩家可以一回合拿完全部剩余堆，此时 $dp(i, M) = S_i$（$S_i$ 已是理论上界，无需枚举）。这既是正确性结论，也是主要加速手段。
4. 否则枚举 $x = 1 \dots 2M$，此时必有 $i + x \le i + 2M < n$，下标天然安全。
5. 输出 $dp(0, 1)$——注意初始参数是 $M = 1$，不是 $M = 0$。

### 3.4 示例演算

![示例填表演算过程](images/wc147_q4_walkthrough.svg)

对 `piles = [2,7,9,4,4]`，后缀和依次为 $S = [26,24,17,8,4,0]$：

| $i$ | $S_i$ | $dp(i,1)$ | $dp(i,2)$ | $m=1$ 时最优 $x$ |
|-----|-------|-----------|-----------|------------------|
| 4 | 4 | 4 | 4 | 1（只剩一堆） |
| 3 | 8 | 8 | 8 | 2（$2M \ge 2$，全拿） |
| 2 | 17 | 13 | 17 | 2 |
| 1 | 24 | 16 | 24 | 2 |
| 0 | 26 | **10** | 22 | 1 |

逐格看关键几步：

- $i = 4$：只剩 1 堆，$2M \ge 1$ 直接全拿，$dp(4, \cdot) = 4$。
- $i = 3$：剩 2 堆，$M = 1$ 时 $2M = 2 \ge 2$，一次拿完，$dp(3, 1) = 8$。
- $i = 2$：$M = 1$ 只能取 $x = 1$ 或 $2$：$17 - dp(3,1) = 9$、$17 - dp(4,2) = 13$，取 $13$；$M = 2$ 时 $2M = 4 \ge 3$，全拿得 $17$。
- $i = 1$：$24 - dp(2,1) = 11$、$24 - dp(3,2) = 16$，取 $16$（Bob 在这里正好取走 7+9）。
- $i = 0$：$26 - dp(1,1) = 10$、$26 - dp(2,2) = 9$，取 **10**。

最优链路与官方解释一致：Alice 取 1 堆（2）→ Bob 取 2 堆（7+9，$M$ 变 2）→ Alice 一次取走 4+4。验证 $2 + 16 + 8 = 26$，总分守恒。

## 4. 算法细节

1. **后缀和是零和转化的载体**：$S_i$ 只算后缀，不用前缀或全局和，否则会把「已经拿走的石头」重复计入。$S_n = 0$ 让转移在 $i + x = n$ 时自然终止，不需要特判。
2. **$M$ 的上界取 $n$ 就够**：$X \le n - i \le n$，而 $M \leftarrow \max(M, X)$ 只会取到某个 $X$，因此 $M \le n$。数组第二维开 $n + 1$，`dp[i + x][max(m, x)]` 永不越界。
3. **枚举顺序**：外层 $i$ 递减是硬性要求；内层 $m$ 递增、递减都行。写成记忆化递归（`@cache` / `memo` 数组）也正确，$n \le 100$ 时递归深度不超过 100，但迭代版常数更小、不用改递归上限。
4. **剪枝的正确性**：$2M \ge n - i$ 时一次全拿得 $S_i$。由于该玩家最多只能拿走剩余的全部石子，$S_i$ 是任意策略的上界，取到上界自然最优。
5. **本回合的收益是 $S_i - dp(\cdot)$，不是 $dp(\cdot)$**：写反是最常见的错误。$dp(i+x, M')$ 是**对手**从新后缀里能拿到的最大值，我要用「剩下的总量减去对手拿走的」。
6. **实际可达状态比 $n^2$ 更少**：除初始的 $(0,1)$ 外，到达 $(i, M)$ 时必有 $M \le i$（$M$ 只由已取走的堆数增长），再叠加 $2M < n - i$ 的剪枝，转移量约 $8.3 \times 10^4$ 次比较（$n = 100$），远低于 $O(n^3)$ 的粗估上限。

## 5. 正确性证明

**引理 1（状态充分性）**：在任意时刻，后续博弈的合法走法集合与双方在剩余石子上的可能收益只由 $(i, M)$ 决定。

**证明**：每回合取走的是剩余部分的最左端连续若干堆，故已取走的堆恒为前缀 $[0, i)$，剩余堆恰为后缀 $[i, n)$；合法取数区间为 $[1, \min(2M, n-i)]$，只依赖 $(i, M)$。历史得分是可加的常数，不改变任何合法走法，也不改变后缀内部的收益分配，故对后续博弈无影响。∎

**引理 2（零和转化的正确性）**：设当前玩家在局面 $(i, M)$ 下采取最优策略可得 $dp(i, M)$，则对手从同一后缀中至多得到 $S_i - dp(i, M)$。

**证明**：后缀 $[i, n)$ 的石子会被两人全部取走，故两人在该后缀的收益之和恒为 $S_i$。对手的收益为 $S_i - a$，其中 $a$ 是当前玩家的收益；对手最大化自身收益等价于最小化 $a$，而当前玩家最大化 $a$ 的保证值正是 $dp(i, M)$，故对手无法让 $a$ 低于 $dp(i, M)$，其收益至多 $S_i - dp(i, M)$。∎

**引理 3（剪枝合法）**：若 $2M \ge n - i$，则 $dp(i, M) = S_i$。

**证明**：此时 $X = n - i$ 是合法选择，当前玩家可一回合取走全部剩余石子，收益 $S_i$；而任何策略的收益都不超过剩余石子总量 $S_i$，故最优值就是 $S_i$。∎

**引理 4（转移覆盖全部策略）**：局面 $(i, M)$ 下任一策略的第一步必为某个 $x \in [1, \min(2M, n-i)]$，且此后进入局面 $(i + x, \max(M, x))$。

**证明**：由题意，第一步只能从该集合中选 $x$；取走后前缀推进到 $i + x$，参数按规则变为 $\max(M, x)$，与引理 1 的状态定义一致。反之每个 $x$ 都是合法的第一步，因此枚举 $x$ 并取最大值覆盖了全部策略。∎

**定理**：自底向上填表得到的 $dp(0, 1)$ 等于 Alice 在双方最优策略下能获得的最大石子数。

**证明**：对剩余长度 $L = n - i$ 做归纳。$L = 0$ 时 $dp(n, \cdot) = 0$，无石子可取，成立。设对所有 $L' < L$ 成立，考虑长度 $L$ 的局面 $(i, M)$：若 $2M \ge L$，由引理 3 直接取 $S_i$，成立；否则对每个 $x$，子局面 $(i + x, \max(M, x))$ 的剩余长度 $L - x < L$，由归纳假设 $dp(i+x, \max(M,x))$ 是对手的最优收益，由引理 2 该分支下当前玩家的保证收益为 $S_i - dp(i+x, \max(M,x))$，再由引理 4 取所有 $x$ 的最大值即为该局面的最优值。零和博弈的 minimax 值唯一，故递推正确。取 $(i, M) = (0, 1)$ 即得 Alice 的最优收益。∎

## 6. 复杂度分析

- **时间**：状态数 $O(n^2)$（$i \in [0, n)$，$M \in [1, n]$），每个状态枚举至多 $2M \le 2n$ 个 $x$，故 $O(n^3)$；加剪枝后 $n = 100$ 时实际转移约 $8.3 \times 10^4$ 次，毫秒级。后缀和预处理 $O(n)$。
- **空间**：$O(n^2)$ 的 `dp` 表（$101 \times 101$ 个 `int`，约 $4 \times 10^4$ 字节），后缀和 $O(n)$。因为 $dp(i, \cdot)$ 依赖所有 $i' > i$ 的行，无法只保留一行，空间下界就是 $O(n^2)$；数值上界 $100 \times 10^4 = 10^6$，`int` 足够。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int stoneGameII(vector<int>& piles) {
        int n = piles.size();
        // 后缀和：suf[i] = piles[i] + ... + piles[n-1]，suf[n] = 0
        vector<int> suf(n + 1, 0);
        for (int i = n - 1; i >= 0; --i) suf[i] = suf[i + 1] + piles[i];

        // dp[i][m]：从后缀 i 出发、参数为 m 的当前玩家最多能拿多少石子
        vector<vector<int>> dp(n + 1, vector<int>(n + 1, 0));
        for (int i = n - 1; i >= 0; --i) {
            for (int m = 1; m <= n; ++m) {
                if (2 * m >= n - i) {        // 一回合可以全拿完
                    dp[i][m] = suf[i];
                    continue;
                }
                int best = 0;
                for (int x = 1; x <= 2 * m; ++x) {
                    // 取走 x 堆后，对手在 (i+x, max(m,x)) 上最优，我拿剩下的
                    best = max(best, suf[i] - dp[i + x][max(m, x)]);
                }
                dp[i][m] = best;
            }
        }
        return dp[0][1];                     // Alice 先手，初始 M = 1
    }
};
```

### Python

```python
class Solution:
    def stoneGameII(self, piles: list[int]) -> int:
        n = len(piles)
        suf = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1] + piles[i]

        # dp[i][m]：从后缀 i 出发、参数为 m 的当前玩家最多能拿多少石子
        dp = [[0] * (n + 1) for _ in range(n + 1)]
        for i in range(n - 1, -1, -1):
            for m in range(1, n + 1):
                if 2 * m >= n - i:           # 一回合可以全拿完
                    dp[i][m] = suf[i]
                    continue
                best = 0
                for x in range(1, 2 * m + 1):
                    cand = suf[i] - dp[i + x][max(m, x)]
                    if cand > best:
                        best = cand
                dp[i][m] = best
        return dp[0][1]                      # Alice 先手，初始 M = 1
```

## 8. 边界情况与易错点

1. **初始参数是 $M = 1$**：答案取 `dp[0][1]`。写成 `dp[0][0]` 会得到 0 或错值（$2M = 0$ 没有合法走法）。
2. **$2M$ 可能超过剩余堆数**：一定要取 $\min(2M, n-i)$。剪枝分支覆盖了 $2M \ge n-i$ 的情况，剩余分支里 $2M < n-i$ 保证 $i + x < n$；若把剪枝删掉又忘了 clamp，就会数组越界。
3. **不要贪心**：`[2,7,9,4,4]` 取 2 堆立即得 9，但全局只有 9；取 1 堆反而得 10。`[1,2,3,4,5,100]` 更极端：贪心取 2 堆（得 3）会让 $M = 2$，Bob 直接把余下 4 堆全吃光，Alice 总共只有 3；取 1 堆则能拿到 104。
4. **$M$ 会大于剩余堆数**：$M$ 单调不减，可能已经远大于剩余堆数，此时取数上限被 clamp 到 $n-i$。不要因为「$M$ 看起来没意义」就把它截断成 $n-i$ 再记忆化：虽然满足 $2M \ge n-i$ 的那些行全都等于 $S_i$、截断不改变数值，但保留原值更不容易出错，数组第二维开到 $n+1$ 即可。
5. **$n = 1$**：$2M = 2 \ge 1$，走剪枝分支返回 `piles[0]`，不应出现「无法取」的情况。
6. **零和前提**：结论依赖「所有堆最终被拿完」且 $piles[i] > 0$。若题目允许提前结束或堆权可为负，「$a_{\text{me}} = S_i - a_{\text{opp}}$」不再成立（见 #1406 石子游戏 III 的写法），必须回到双方分数的二维状态。
7. **总和不溢出**：$100 \times 10^4 = 10^6$，`int` 足够；Python 无溢出问题。
8. **别在状态里塞「轮到谁」**：换手后函数形式完全对称，加一个 turn 维度只是把状态数翻倍。

**延伸思考**：若把规则改成「每回合可取前 $X$ 堆，$1 \le X \le 3M$」，转移形式完全不变，只是区间上界变成 $3M$，复杂度仍为 $O(n^3)$。若要求同时输出 Alice 与 Bob 的最终得分，利用 $S_0$ 守恒直接算 $S_0 - dp(0,1)$ 即可，不必新增状态。真正的难点在数据范围放大到 $n = 10^5$ 时：状态数已是 $O(n^2)$，而 $dp(i, M)$ 关于 $M$ **并不单调**——$M$ 变大让自己多出选择，但同时抬高了对手的参数，两者相互抵消（随机数据里能轻易找到 $dp(i,1) > dp(i,2)$ 的反例），所以不能照搬区间 DP 那套「先证决策单调性再上 Knuth 优化」的套路；要继续优化就得换刻画方式，比如把「本轮取多少」与「下轮上限」合并成对 $\lceil (n-i)/2 \rceil$ 的分段讨论。这也提醒我们：博弈型 DP 里「参数更大一定更好」这种直觉，必须验证而不能假设。
