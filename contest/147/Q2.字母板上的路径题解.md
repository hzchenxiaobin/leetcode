# LeetCode 字母板上的路径 题解

## 1. 题目概述

- **标题 / 题号**：字母板上的路径（#1138，medium）
- **链接**：https://leetcode.cn/problems/alphabet-board-path/
- **来源**：LeetCode 第 147 场周赛 Q2
- **难度**：中等
- **标签**：哈希表，字符串

**题意**：字母板共有 26 个格子——前 5 行每行 5 个字母，第 6 行只有 1 个字母：

```text
第 0 行：a b c d e
第 1 行：f g h i j
第 2 行：k l m n o
第 3 行：p q r s t
第 4 行：u v w x y
第 5 行：z
```

从 `(0, 0)` 出发，可以发出五类指令：`U` / `D` / `L` / `R` 各移动一格（**目标格必须存在**），`!` 把当前位置的字符追加到答案。要求返回一条指令序列，使追加出的字符串恰好等于 `target`，并让**行动次数最少**；达成目标的最短序列不唯一，返回任意一条即可。

**约束**：

- $1 \le \lvert target \rvert \le 100$
- `target` 仅由小写英文字母组成
- 板上只有 26 个字母格：第 5 行的 $(5,1)$ 到 $(5,4)$ **不存在**

## 2. 示例

**示例 1**

```text
输入：target = "leet"
输出："DDR!UURRR!!DDD!"
解释：a(0,0) 下 2 右 1 到 l(2,1)，追加 l；再上 2 右 3 到 e(0,4)，追加 e；
      e 与上一步同格，直接再追加一次 e；再下 3 到 t(3,4)，追加 t。
```

**示例 2**

```text
输入：target = "code"
输出："RR!DDRR!UUL!R!"
解释：共 14 条指令，其中 10 条移动、4 条追加；
      第 3 段 (2,4) → (0,3) 官方先 U 后 L，本解法的 L → U → D → R 顺序先 L 后 U，
      两条路径都合法，题目允许返回任意最短路径。
```

**补充示例**（题面未给，用于核对 `z` 的处理）

```text
输入：target = "z"
输出："DDDDD!"       解释：只能沿第 0 列一路向下，第 5 行其它列不存在。

输入：target = "za"
输出："DDDDD!UUUUU!"  解释：先下到 z 追加，再从 z 升回 (0,0) 追加 a。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是把「输出指令序列」当成搜索问题：状态是 `(当前位置, 已拼出的前缀)`，每步枚举 `U/D/L/R/!` 五种动作，BFS 找最短解。状态里的前缀有 $26^n$ 种可能，而 BFS 的深度已经是最优答案的长度（最坏 $10n$），分支因子 5——这是指数级爆炸，$n = 100$ 时完全不可行。

第二个想法是「对每个字符跑一次 BFS」：在 26 个字母格上求最短距离。**距离确实是对的**，但要多存前驱才能还原指令，还要为每一段重新搜索，纯属杀鸡用牛刀——板上根本没有真正的障碍，只有「第 5 行不完整」这一处**伪障碍**。

### 3.2 核心观察：每段独立 + 曼哈顿下界

![字母板坐标公式、每段下界与唯一陷阱](images/wc147_q2_board_model.svg)

`!` 把整条指令序列切成 $n$ 个**互相独立**的段：第 $i$ 段只负责「从当前格走到 `target[i]` 的格子，然后追加一个字符」，段与段之间唯一的耦合是当前位置。所以总代价等于各段代价之和，可以把问题拆开看。

**下界**：设第 $i$ 段从 $(r, c)$ 走到 $(nr, nc)$。每条移动指令只让行或列改变 1，要把行差补齐至少要 $\lvert r - nr \rvert$ 条竖直指令，把列差补齐至少要 $\lvert c - nc \rvert$ 条水平指令；再加上恰好 1 条 `!`。于是

$$\text{第 } i \text{ 段代价} \ge d_i + 1, \qquad d_i = \lvert r - nr \rvert + \lvert c - nc \rvert$$

**达到下界的条件**：段内每一步都朝目标方向走（单调路径，不回头），此时移动次数恰为 $d_i$。也就是说——**只要找得到一条合法的单调路径，该段就是最优的**，而所有合法的单调路径长度相等。

**陷阱只有一个**：唯一可能让单调路径非法的地方，就是第 5 行。格子 $(5,1)$ 到 $(5,4)$ 不存在，因此

- 去 `z` 时若先 `D` 后 `L`，会在 $c > 0$ 的第 5 行踩空；
- 在 `z` 上若先 `R` 后 `U`，会从 $(5,0)$ 迈到不存在的 $(5,1)$。

换句话说，最优解的长度是**确定的**，唯一的自由度是「四个方向谁先谁后」。

### 3.3 算法流程：固定顺序 L → U → D → R

![固定顺序的安全性：四阶段逐步论证](images/wc147_q2_safe_order.svg)

**结论先行**：段内一律按 `L → U → D → R` 的固定顺序输出，就不需要任何 `if` 特判 `z`。每一步的数量都取「该方向上的差值」：

```text
r = 0, c = 0, ans = ""
for ch in target:
    nr = (ch - 'a') // 5        # 目标行
    nc = (ch - 'a') %  5        # 目标列
    ans += 'L' * max(0, c - nc) # ① 先把列收到 min(c, nc)
    ans += 'U' * max(0, r - nr) # ② 再把行抬到 min(r, nr)
    ans += 'D' * max(0, nr - r) # ③ 再把行压到 nr
    ans += 'R' * max(0, nc - c) # ④ 最后把列推到 nc（此时必在前 5 行）
    ans += '!'
    r, c = nr, nc
```

为什么这个顺序通吃全部情况？关键是看每个阶段结束时的落脚点：

1. `L` 段结束后列变成 $\min(c, nc)$，行还是 $r$。若 $r = 5$，由于唯一合法格是 $(5,0)$，必有 $c = 0$，于是 $\min(c, nc) = 0$，落点仍是 $(5,0)$；否则 $r \le 4$，整行 5 格都合法。
2. `U` 段结束后行变成 $\min(r, nr)$、列仍是 $\min(c, nc)$。若行等于 5，只能是 $r = 5$ 且 $nr = 5$（目标是 `z`），此时列已为 0，落点合法；否则行 $\le 4$，整行合法。
3. `D` 段结束后行变成 $nr$。若 $nr = 5$，目标必是 `z`，于是 $nc = 0$，而 ① 已把列收到 0，整段都沿第 0 列下行，落点合法。
4. `R` 段只在 $nc > c$ 时非空；若 $nr = 5$ 则目标为 `z`、即 $nc = 0$，与 $nc > c \ge 0$ 矛盾，故 $nr \le 4$，横移发生在完整行内。

> 💡 换个说法：`L` 排在 `D` 之前，保证「进入第 5 行时列已经对齐 0」；`U` 排在 `R` 之前，保证「离开第 5 行时先抬起来再横移」。这两条正是全部约束，`L` 与 `U` 之间、`D` 与 `R` 之间的先后其实可以互换。

### 3.4 示例演算

以 `target = "leet"` 为例：

![target = leet 的四段指令走查](images/wc147_q2_walkthrough.svg)

| 步 | 字符 | 起点 → 终点 | $\Delta r / \Delta c$ | 本段指令 | 累计输出 |
|----|------|-------------|----------------------|----------|----------|
| 1 | `l` | $(0,0) \to (2,1)$ | $+2\ /\ +1$ | `DDR!` | `DDR!` |
| 2 | `e` | $(2,1) \to (0,4)$ | $-2\ /\ +3$ | `UURRR!` | `DDR!UURRR!` |
| 3 | `e` | $(0,4) \to (0,4)$ | $0\ /\ 0$ | `!` | `DDR!UURRR!!` |
| 4 | `t` | $(0,4) \to (3,4)$ | $+3\ /\ 0$ | `DDD!` | `DDR!UURRR!!DDD!` |

总指令数 $=(2+1+1)+(2+3+1)+(0+0+1)+(3+0+1)=15$，与下界 $\sum_i d_i + n = (3+5+0+3) + 4 = 15$ 相等，故最优；结果与官方示例 1 逐字符一致。

对 `target = "code"` 本解法输出 `RR!DDRR!LUU!R!`，官方示例是 `RR!DDRR!UUL!R!`：第 3 段官方先 `U` 后 `L`、本解法先 `L` 后 `U`，两者都落在板上且同为 14 条指令——题目允许任意最短路径，不必照抄示例。

## 4. 算法细节

1. **坐标公式**：$k = ch - \text{'a'}$，$r = \lfloor k / 5 \rfloor$，$c = k \bmod 5$。不需要建哈希表/数组，$O(1)$ 即可（题面提示用 hashmap，本质就是这张「字符 → 坐标」表，公式等价且更省）。
2. **条数取非负**：四段的条数分别是 $c - nc$、$r - nr$、$nr - r$、$nc - c$，必然有正有负；必须用 $\max(0, \cdot)$ 截断，否则会生成「负长度」。
3. **`!` 的位置**：每段必须**先走完移动、再追加**，且整条序列里恰好有 $n$ 个 `!`。
4. **顺序的硬约束**：只有 `L` 必须早于 `D`（去 `z` 时列要先归零）、`U` 必须早于 `R`（离 `z` 时先离开第 5 行）。本文的 `L → U → D → R` 同时满足两条。
5. **不对 `z` 特判字符**：`z` 的坐标由公式自动得到 $(5,0)$，把 `z` 当普通字符处理即可，安全性由顺序保证。
6. **输出规模**：两格间曼哈顿距离最大为 $9$（$(0,4)$ 的 `e` 到 $(5,0)$ 的 `z`），加上 `!` 每字符至多 10 个字符，答案长度 $\le 10n \le 1000$；C++ 可 `reserve(10 * n)` 减少扩容。
7. **C++ 的负数长度**：`string(n, ch)` 的 $n$ 是 `size_t`，传 $-2$ 会变成天文数字并抛 `bad_alloc`；Python 里 `'L' * (-3)` 恰好是空串，两者行为不同，统一 `max(0, n)` 才能一致。

## 5. 正确性证明

记第 $i$ 段从 $(r_i, c_i)$ 到 $(nr_i, nc_i)$，$d_i = \lvert r_i - nr_i \rvert + \lvert c_i - nc_i \rvert$。

**引理 1（段代价下界）**：任何合法指令序列在第 $i$ 段（从上一次 `!` 之后到本次 `!`）内至少包含 $d_i$ 条移动指令和 1 条 `!`。

**证明**：`U`/`D` 只改变行号 1、`L`/`R` 只改变列号 1，要使行号净变化 $nr_i - r_i$、列号净变化 $nc_i - c_i$，所需竖直指令数不少于 $\lvert nr_i - r_i \rvert$、水平指令数不少于 $\lvert c_i - c_i \rvert$；再算上把字符追加进答案的那 1 条 `!`，结论成立。∎

**引理 2（合法性）**：若进入某段时位置 $(r, c)$ 是字母格（$r \le 4$ 且 $0 \le c \le 4$，或 $(r,c) = (5,0)$），则按 `L → U → D → R` 生成的段内路径每一步都落在字母格上。

**证明**：分四段考察中间落点，全程保持「行 = 5 时列 = 0」这一不变量。

- **`L` 段**：落点为 $(r, t)$，$t$ 从 $c$ 递减到 $\min(c, nc)$。若 $r = 5$，由前提 $c = 0$，故 $t$ 恒为 $0$，落点只能是 $(5,0)$；若 $r \le 4$，列始终在 $[0,4]$ 内，整行合法。
- **`U` 段**：落点为 $(t, \min(c, nc))$，$t$ 从 $r$ 递减到 $\min(r, nr)$。若某个 $t = 5$，则 $r = 5$，从而 $c = 0$、$\min(c, nc) = 0$，落点即 $(5,0)$；否则 $t \le 4$，列在 $[0,4]$ 内，合法。
- **`D` 段**：落点为 $(t, \min(c, nc))$，$t$ 从 $r$ 递增到 $nr$（仅当 $nr > r$ 时非空）。若某个 $t = 5$，则 $nr = 5$，即目标是 `z`、$nc = 0$，于是 $\min(c, nc) = 0$，落点为 $(5,0)$，合法。
- **`R` 段**：落点为 $(nr, t)$，$t$ 从 $\min(c, nc)$ 递增到 $nc$（仅当 $nc > c$ 时非空）。此时若 $nr = 5$，则目标为 `z`、$nc = 0$，与 $nc > c \ge 0$ 矛盾，故 $nr \le 4$，整行合法。

初始位置 $(0,0)$ 是字母格，故对每段用一次上述论证即得全程合法。∎

**引理 3（段长度恰好为下界）**：算法在第 $i$ 段输出的移动指令数恰为 $d_i$，加上 1 个 `!` 共 $d_i + 1$ 个字符。

**证明**：四段条数之和为

$$\max(0, c_i - nc_i) + \max(0, r_i - nr_i) + \max(0, nr_i - r_i) + \max(0, nc_i - c_i) = \lvert c_i - nc_i \rvert + \lvert r_i - nr_i \rvert = d_i$$

再追加 1 个 `!`，得 $d_i + 1$。∎

**定理（最优性与正确性）**：算法返回的指令序列合法，追加结果为 `target`，且总长度 $\sum_i (d_i + 1)$ 达到所有合法序列的下界，因此行动次数最少。

**证明**：合法性由引理 2 给出（结合初始位置合法）。段末位置为 $(nr_i, nc_i)$，而字母格到字符的映射是双射（索引 $k = 5r + c$ 与 $(r, c)$ 一一对应），故该格上的字符恰是 `target[i]`，每个 `!` 都追加正确字符，$n$ 段拼起来就是完整的 `target`。长度方面，引理 3 给出总长 $\sum_i (d_i + 1)$，而引理 1 说明任何合法序列的总长不少于同一个值，故算法输出长度最小。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符做一次常数次取模/整除、生成至多 9 条移动指令和 1 个 `!`，与 $n$ 线性相关；总输出字符数 $\le 10n$。
- **空间**：除输出字符串外 $O(1)$（只维护 `r`、`c` 与坐标公式）；输出字符串本身 $O(n)$，C++ 中可 `reserve(10n)` 把扩容开销摊平。
- **数值范围**：全程只有 $0 \sim 25$ 的索引与 $0 \sim 5$ 的坐标，不存在溢出问题。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string alphabetBoardPath(string target) {
        int r = 0, c = 0;
        string res;
        res.reserve(10 * target.size());
        auto rep = [&res](int k, char ch) {      // 负数必须跳过：string(n, ch) 的 n 是 size_t
            if (k > 0) res.append((size_t)k, ch);
        };
        for (char t : target) {
            int nr = (t - 'a') / 5;              // 目标行
            int nc = (t - 'a') % 5;              // 目标列
            rep(c - nc, 'L');                    // ① 先把列收到 min(c, nc)
            rep(r - nr, 'U');                    // ② 再把行抬到 min(r, nr)
            rep(nr - r, 'D');                    // ③ 再把行压到 nr（只会沿第 0 列进第 5 行）
            rep(nc - c, 'R');                    // ④ 最后把列推到 nc（此时必在前 5 行）
            res += '!';
            r = nr;
            c = nc;
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def alphabetBoardPath(self, target: str) -> str:
        r = c = 0
        res = []
        for ch in target:
            nr, nc = divmod(ord(ch) - ord('a'), 5)   # 目标行、目标列
            res.append('L' * max(0, c - nc))         # ① 先把列收到 min(c, nc)
            res.append('U' * max(0, r - nr))         # ② 再把行抬到 min(r, nr)
            res.append('D' * max(0, nr - r))         # ③ 再把行压到 nr
            res.append('R' * max(0, nc - c))         # ④ 最后把列推到 nc
            res.append('!')
            r, c = nr, nc
        return ''.join(res)
```

## 8. 边界情况与易错点

1. **目标是 `z`**：`target = "z"` 只能沿第 0 列下 5 格，答案是 `DDDDD!`；若实现先 `D` 后 `L`（例如统一「先竖直后水平」），从 $(0,4)$ 去 `z` 时会从 $(4,4)$ 直接下到不存在的 $(5,4)$ 而失败。
2. **起点是 `z`**：`"za"` 要先 `U` 再横移，输出 `DDDDD!UUUUU!`；若先 `R`，第一步就迈到不存在的 $(5,1)$。
3. **重复字符**：`"aa"` 段内 $d = 0$，只输出 `!`，答案是 `!!`；`"zz"` 是 `DDDDD!!`。别把「没有移动」误判成「不用追加」，也不要「优化」掉连续的 `!`。
4. **C++ 负长度**：`string(c - nc, 'L')` 当 $c < nc$ 时把负数转成 `size_t`，会直接 `bad_alloc`；Python 的 `'L' * (-3)` 是空串，两种语言行为不同，统一 `max(0, n)` 最稳。
5. **`!` 的数量与位置**：每段恰好 1 个 `!` 且必须在移动之后；多一个或少一个都会让结果与 `target` 不匹配。
6. **与示例输出不一致**：本解法对 `"code"` 给出 `RR!DDRR!LUU!R!`，与示例的 `RR!DDRR!UUL!R!` 顺序不同但等价。自测时应校验「合法性 + 长度 = 下界」，而不是与示例逐字符比对。
7. **下界公式别漏 `!`**：最优长度是 $\sum d_i + n$，只算 $\sum d_i$ 会低估，导致误以为还能更短。
