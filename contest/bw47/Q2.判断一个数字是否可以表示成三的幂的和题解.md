# LeetCode 判断一个数字是否可以表示成三的幂的和 题解

## 1. 题目概述

- **标题 / 题号**：判断一个数字是否可以表示成三的幂的和（#1780，medium）
- **链接**：https://leetcode.cn/problems/check-if-number-is-a-sum-of-powers-of-three/
- **来源**：LeetCode 第 47 场双周赛 Q2
- **难度**：中等
- **标签**：数学

**题意**：给定整数 $n$，判断能否把 $n$ 写成**若干个互不相同**的三的幂（$3^x$，$x \ge 0$ 为整数）之和。可以返回 `true`，否则返回 `false`。每个幂至多使用一次。

**约束**：

- $1 \le n \le 10^7$

## 2. 示例

**示例 1**

```text
输入：n = 12
输出：true
解释：12 = 3^1 + 3^2。
```

**示例 2**

```text
输入：n = 91
输出：true
解释：91 = 3^0 + 3^2 + 3^4 = 1 + 9 + 81。
```

**示例 3**

```text
输入：n = 21
输出：false
解释：21 的三进制表示是 210，出现数字 2。
```

## 3. 解题思路

### 3.1 暴力思路

幂的范围先定界：$3^{14} = 4782969 \le 10^7 < 3^{15} = 14348907$，所以可能用到的幂只有 $3^0, 3^1, \dots, 3^{14}$ 共 15 个。最粗暴的做法是把每个幂"选 / 不选"枚举一遍，共 $2^{15} = 32768$ 个子集，检查是否存在子集和恰为 $n$；或者预处理出全部可达和存入布尔表（背包），单次查询 $O(1)$。作为一次性判定这已经能过（$n \le 10^7$），但完全是"用组合暴力掩盖了结构"——本题真正想考察的是**进制表示**的洞察。

### 3.2 核心观察：三进制表示的每一位就是「这个幂取几次」

![核心观察：三进制每位即该幂的选取次数，出现 2 即非法](images/bw47_q2_ternary_digits.svg)

把 $n$ 写成三进制 $n = \overline{d_k d_{k-1} \dots d_1 d_0}$，按定义 $n = \sum_{i=0}^{k} d_i \cdot 3^i$，其中 $d_i \in \{0, 1, 2\}$。**第 $i$ 位数字 $d_i$ 恰好等于"幂 $3^i$ 在和式中被使用的次数"**：

- $d_i = 0$：$3^i$ 不用；
- $d_i = 1$：$3^i$ 用一次；
- $d_i = 2$：$3^i$ 要用**两次**——与"每个幂至多一次"直接冲突。

于是判定条件收敛为一句话：**$n$ 能表示成不同三的幂之和 ⇔ $n$ 的三进制表示中不出现数字 2**。由于三进制表示的唯一性（§5 引理 1），这个判定不依赖于任何构造顺序，是充要条件。

### 3.3 算法流程：反复除 3 逐位检查

![算法流程：反复除 3，余数只能是 0 或 1](images/bw47_q2_division_flow.svg)

不需要真的展开三进制数位，模拟"短除法"即可：

```text
1. 当 n > 0：
2.   r = n % 3
3.   若 r == 2：return false   # 某位是 2
4.   n = n / 3               # 弃掉刚检查过的最低位
5. 循环自然结束 → return true
```

`n % 3` 取出当前最低位，`n / 3` 把数位整体右移一位，整数除法天然完成进位处理。

### 3.4 示例演算

![示例演算：12 通过（110₃）、21 被拒（210₃）](images/bw47_q2_walkthrough.svg)

- $n = 12$：$12 \% 3 = 0$，$n \to 4$；$4 \% 3 = 1$，$n \to 1$；$1 \% 3 = 1$，$n \to 0$；各位为 $110_3$，全在 $\{0,1\}$ 内，返回 `true`（$12 = 3 + 9$）。
- $n = 21$：$21 \% 3 = 0$，$n \to 7$；$7 \% 3 = 1$，$n \to 2$；$2 \% 3 = 2$，立即返回 `false`（$21 = 210_3$）。

## 4. 算法细节

1. **幂的上界**：$3^{14} \approx 4.78 \times 10^6 < 10^7 < 3^{15}$，故 $n \le 10^7$ 的三进制位数不超过 15 位（$10^7$ 本身是 $102002002_3$，共 15 位），循环至多 16 轮，常数级。
2. **逐位判定 vs. 预处理**：`while` 短除法每次丢掉最低位，等价于右移——也可以先把三进制串完整求出再检查，两法等价，短除法代码更短。
3. **不要用浮点**：有人试图用 $\log_3 n$ 定界再贪心（从大幂往小幂"能减就减"）。该贪心其实是对的（每次减去不超过 $n$ 的最大幂），但要小心 $\log$ 的浮点误差导致幂次算错；短除法全程整数运算，无此风险。
4. **进位不会发生**：由于直接检查的是 $n$ 的规范三进制表示（唯一），不存在"先把某些位加到 2 再进位"的歧义——见 §5 引理 2。

## 5. 正确性证明

**引理 1（三进制表示的存在唯一性）**：任何非负整数 $n$ 存在唯一的表示 $n = \sum_{i=0}^{k} d_i 3^i$，其中 $d_i \in \{0,1,2\}$、$d_k \ne 0$（$n = 0$ 时约定各位全 0）。

**证明**：存在性即短除法过程：每次 $d_i = n \bmod 3$、$n \gets \lfloor n/3 \rfloor$，由于 $n$ 严格递减且非负，过程终止，回代即得表示。唯一性：设 $n$ 有两个表示 $\sum a_i 3^i = \sum b_i 3^i$（高位补零对齐）。设 $j$ 为 $a_j \ne b_j$ 的最大下标，则 $3^j \mid \sum_{i<j}(a_i - b_i) 3^i$，而 $0 \le \sum_{i<j} \lvert a_i - b_i \rvert 3^i \le 2 \cdot \frac{3^j - 1}{2} = 3^j - 1 < 3^j$，故 $\sum_{i<j}(a_i - b_i)3^i = 0$；于是 $(a_j - b_j)3^j = 0$，与 $a_j \ne b_j$ 矛盾。∎

**引理 2（无进位表示）**：若 $S \subseteq \{0,1,\dots,14\}$，则 $n = \sum_{i \in S} 3^i$ 的规范三进制表示第 $i$ 位恰为 $[i \in S]$（属于 $S$ 为 1，否则 0），不发生任何进位。

**证明**：把 $n$ 按位写成竖式：每个被加数 $3^i$ 的三进制是"第 $i$ 位为 1、其余为 0"的数，所有被加数按位相加，每一位的和为 $[i \in S] \in \{0,1\}$，任何一位都不超过 1，无需进位。该竖式结果是一个合法的三进制表示，由引理 1 的唯一性，它就是 $n$ 的规范三进制表示。∎

**定理**：$n$ 可以表示成若干个互不相同的三的幂之和，当且仅当 $n$ 的三进制表示中每一位都属于 $\{0, 1\}$。

**证明**：（⇐）设 $n$ 的三进制表示 $n = \sum d_i 3^i$ 且 $d_i \in \{0,1\}$。取 $S = \{i : d_i = 1\}$，则 $n = \sum_{i \in S} 3^i$ 是互不相同的幂之和，合法。（⇒）设 $n = \sum_{i \in S} 3^i$，$S$ 中下标互不相同。由引理 2，$n$ 的规范三进制表示第 $i$ 位为 $[i \in S] \in \{0,1\}$，无数字 2。两个方向合并即得充要条件；而短除法逐位取余检查的正是规范三进制表示的每一位（引理 1 的存在性构造），故算法判定正确。∎

## 6. 复杂度分析

- **时间**：$O(\log_3 n)$。每轮把 $n$ 缩小到原来的 $\frac{1}{3}$，$n \le 10^7$ 至多 16 轮。
- **空间**：$O(1)$。只用常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkPowersOfThree(int n) {
        while (n > 0) {
            if (n % 3 == 2) return false;   // 某位是 2：这个幂要用两次
            n /= 3;                         // 弃掉刚检查过的最低位
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def checkPowersOfThree(self, n: int) -> bool:
        while n > 0:
            if n % 3 == 2:      # 某位是 2：这个幂要用两次
                return False
            n //= 3             # 弃掉刚检查过的最低位
        return True
```

> 💡 两份代码均通过官方 3 组示例；另与「$3^0 \dots$ 枚举子集和」的可达集合暴力做了 1500 组随机数据（含三的幂组合、纯幂、随机数）对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **最小值**：$n = 1 = 3^0$，返回 `true`；$n = 2 = 3^0 + 3^0$ 不合法（同一幂用了两次），返回 `false`——这是"位出现 2"的最小例子。
2. **恰好是幂**：$n = 3^k$ 的三进制是 `1` 后跟 $k$ 个 `0`，全部通过，返回 `true`。
3. **`n % 3 == 2` 提前退出**：检查到第 2 位即可下结论，不必把所有位除完——但千万别把条件写成 `!= 0`（余 1 是合法的）。
4. **循环条件**：是 `while (n > 0)` 而非 `n >= 3`——$n$ 落到 1 或 2 时仍需检查最后一位。
5. **浮点定界的陷阱**：用 `pow(3, log(n)/log(3))` 之类浮点算幂上界可能差一（例如 $\log$ 误差把 $3^{14}$ 算成略小于它），本题全程整数除法即可规避。
6. **进位错觉**：$12 = 110_3$ 没有进位问题；但若有人先贪心选幂（$91 \to$ 减 81 余 10，减 9 余 1，减 1 归零）也正确——这本质是引理 2 的另一种表述：贪心每步减最大可用幂，余数的三进制位依然是 0/1。
