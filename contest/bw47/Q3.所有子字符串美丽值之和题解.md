# LeetCode 所有子字符串美丽值之和 题解

## 1. 题目概述

- **标题 / 题号**：所有子字符串美丽值之和（#1781，medium）
- **链接**：https://leetcode.cn/problems/sum-of-beauty-of-all-substrings/
- **来源**：LeetCode 第 47 场双周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、计数

**题意**：一个字符串的**美丽值**定义为：其中**出现频率最高**的字符与**出现频率最低**的字符的出现次数之差（最低频指实际出现的字符中频次最小者，不把没出现的字符算作 0 次）。给定字符串 $s$，求它**所有子字符串**的美丽值之和。

**约束**：

- $1 \le s.length \le 500$
- $s$ 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "aabcb"
输出：5
解释：美丽值非零的子串有 ["aab","aabc","aabcb","abcb","bcb"]，各贡献 1。
```

**示例 2**

```text
输入：s = "aabcbaa"
输出：17
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $O(n^2)$ 个子串，对每个子串用哈希表从零数一遍频次再求最大最小——每个子串 $O(\text{len})$，总计 $O(n^3)$。$n = 500$ 时约 $1.25 \times 10^8$ 量级，C++ 勉强能跑、Python 必超时。问题出在**重复劳动**：固定左端点时，子串 $[i, j]$ 与 $[i, j-1]$ 只差一个字符，频次表却从头数了一遍。

### 3.2 核心观察：固定左端点，右端点右移是增量更新

![核心观察：右端点右移一步，计数数组只加一](images/bw47_q3_sliding_count_concept.svg)

以左端点 $i$ 为锚点，让右端点 $j$ 从 $i$ 走到 $n-1$：子串从 $s[i..i]$ 逐字符生长到 $s[i..n-1]$，每步只需 `cnt[s[j]] += 1`——$O(1)$ 完成频次表更新。得到新频次表后，美丽值要取「出现过的字符的最大频次 − 出现过的字符的最小频次」，由于字母只有 26 个，扫一遍 `cnt` 数组求 `mx` 与 `mn`（跳过 0）是 $O(26)$ 的常数工作。总复杂度 $O(n^2 \cdot 26) \approx 6.5 \times 10^6$，轻松通过。

> ⚠️ **最小频次的定义**：`mn` 是**出现过的字符**中的最小频次，不是 0。若把没出现的字母当成 0，`mn` 恒为 0，美丽值会变成"最大频次"，整个题就做错了。扫描时用 `if (cnt[c] == 0) continue;` 跳过。

### 3.3 算法流程

![算法流程：外层 i 内层 j，增量计数 + 扫 26 求美丽值](images/bw47_q3_algorithm_flow.svg)

```text
1. ans = 0
2. 对每个左端点 i = 0..n-1：
3.   cnt[0..25] 清零
4.   对每个右端点 j = i..n-1：
5.     cnt[s[j] - 'a'] += 1
6.     mx = max(cnt[c])，mn = min(非零 cnt[c])      # 扫 26 个字母
7.     ans += mx - mn
8. 返回 ans
```

### 3.4 示例演算

![示例演算：aabcb 的三角形填表](images/bw47_q3_walkthrough.svg)

以 $s = $ `"aabcb"` 为例，$(i, j)$ 的美丽值排成一张三角形表：只有 $(0,2), (0,3), (0,4), (1,4), (2,4)$ 五格为 1（对应子串 `aab`、`aabc`、`aabcb`、`abcb`、`bcb`），其余格子 `mx == mn` 美丽值为 0，总和为 5。

## 4. 算法细节

1. **计数数组复用**：外层每换一个左端点就把 `cnt` 清零（`int cnt[26] = {0}` 作用域内重建即可），不要为每个子串新建数组。
2. **mx / mn 的求法**：`mx` 初值 0、`mn` 初值取 $n+1$（或 `INT_MAX`）；循环 `c = 0..25`，跳过 `cnt[c] == 0`。子串长度 $\ge 1$，至少有一个非零计数，`mn` 一定会被更新。
3. **单字符子串**：`mx == mn == 1`，美丽值为 0，自然贡献 0，无需特判。
4. **答案类型**：最大可能的总和约为 $\frac{n(n+1)}{2} \times (n-1) \le 125250 \times 499 \approx 6.25 \times 10^7$，`int`（上限约 $2.1 \times 10^9$）安全，无需 `long long`。
5. **能否省掉每次扫 26？** 可以维护增量 `mx`（只增不减，右移时 `cnt[s[j]]++` 后更新），但 `mn` 在字符频次增长时既可能增大也可能不变，不满足单调性，安全做法还是每步扫 26。也可以只对「出现过的字母集合」维护，常数优化空间不大，$O(26)$ 已经够快。
6. **进阶方向（贡献法）**：$\text{beauty} = \max - \min$，把总和拆成 $\sum_{\text{子串}} \max - \sum_{\text{子串}} \min$，两部分都能用"枚举字符 $c$，把 $c$ 之外的字符合并为 0/1 序列 + 前缀和/单调结构"做到 $O(26n)$，详见延伸思考；比赛时限内 $O(n^2 \cdot 26)$ 足矣。

## 5. 正确性证明

**引理 1（子串与端点对一一对应）**：非空子串 $s[i..j]$（$0 \le i \le j \le n-1$）与整数对 $(i, j)$ 一一对应，故算法的二重循环恰好不重不漏地枚举每个子串恰一次。

**证明**：子串由其起止下标唯一决定；反之每个满足 $i \le j$ 的对 $(i,j)$ 唯一确定一个非空子串。∎

**引理 2（增量计数不变量）**：处理 $(i, j)$ 时，`cnt[c]` 恰等于字符 $c$ 在子串 $s[i..j]$ 中的出现次数。

**证明**：对固定的 $i$ 归纳。$j = i$ 时刚执行 `cnt[s[i]] += 1`，`cnt[s[i]] = 1`、其余为 0，与单字符子串一致。设 $(i, j-1)$ 时成立，则 $(i, j)$ 时在原有基础上增加了 `s[j]` 一次计数，而子串 $s[i..j] = s[i..j-1] \cup \{s[j]\}$，频次恰为旧值加上 $s[j]$ 的一次，不变量保持。左端点更换时 `cnt` 清零，归纳基础重新成立。∎

**定理**：算法返回 $s$ 所有子字符串的美丽值之和。

**证明**：由引理 1，每个子串被处理恰一次；由引理 2，处理 $(i,j)$ 时 `cnt` 是该子串的精确频次表，于是 `mx` 是出现字符的最大频次、跳过零后求得的 `mn` 是出现字符的最小频次（与题目美丽值定义一致——"最低频"统计的是实际出现的字符），`ans += mx - mn` 恰好累加该子串的美丽值。全部子串贡献求和即为答案。∎

## 6. 复杂度分析

- **时间**：$O(n^2 \cdot 26)$。二重循环 $\frac{n(n+1)}{2} \approx 1.25 \times 10^5$ 个子串，每个做 1 次计数更新 + 26 次比较；$n = 500$ 时约 $6.5 \times 10^6$ 次基本操作。
- **空间**：$O(26) = O(1)$。频次计数数组复用一份，无其他随 $n$ 增长的结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int beautySum(string s) {
        int n = (int)s.size(), ans = 0;
        for (int i = 0; i < n; ++i) {          // 枚举子串左端点
            int cnt[26] = {0};
            for (int j = i; j < n; ++j) {      // 右端点逐步右移，增量维护计数
                ++cnt[s[j] - 'a'];
                int mx = 0, mn = n;
                for (int c = 0; c < 26; ++c) { // 出现字符的最大/最小频次
                    if (cnt[c] == 0) continue;
                    if (cnt[c] > mx) mx = cnt[c];
                    if (cnt[c] < mn) mn = cnt[c];
                }
                ans += mx - mn;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def beautySum(self, s: str) -> int:
        n, ans = len(s), 0
        for i in range(n):                    # 枚举子串左端点
            cnt = [0] * 26
            for j in range(i, n):             # 右端点逐步右移
                cnt[ord(s[j]) - ord('a')] += 1
                mx, mn = 0, n
                for c in cnt:
                    if c:
                        if c > mx: mx = c
                        if c < mn: mn = c
                ans += mx - mn
        return ans
```

> 💡 两份代码均通过官方 2 组示例；另与「每个子串用 `Counter` 重数频次」的三重循环暴力对拍 1500 组随机数据（字母表大小 1/2/3/5/26，长度 $\le 60$），`mismatch = 0`；$n = 500$ 满规模实测 C++ 约 5ms、Python 约 77ms。

## 8. 边界情况与易错点

1. **最小频次不是 0**：必须跳过 `cnt[c] == 0` 的桶。这是本题最高频的 WA 点——把 `mn` 算成 0 后所有子串的美丽值都偏大。
2. **`mn` 的初值**：设为 `n + 1` 或 `INT_MAX` 均可，但不能是 0（否则取不到真实最小值）；由于 $j \ge i$ 时至少有一个非零桶，最终 `mn` 必被更新为正数。
3. **单字符 / 全同字符**：$s = $ `"aaaa"` 的所有子串 `mx == mn`，答案为 0；$n = 1$ 同样返回 0。别对"空答案"做特殊输出。
4. **清零时机**：`cnt` 必须在每个左端点开始时清零，漏掉会把上一个左端点的计数带进来。
5. **子串 vs 子序列**：是**连续**子串，枚举 $(i, j)$ 即可；别按子序列（$2^n$ 个）理解。
6. **复杂度误判**：$O(n^3)$ 的"每个子串重数频次"在 Python 下大概率超时；也不要幻想 $O(n^2)$ 都要卡常——$6.5 \times 10^6$ 的常数操作非常宽裕。
7. **溢出**：最大总和约 $6.3 \times 10^7$，`int` 足够；Python 无此问题。
