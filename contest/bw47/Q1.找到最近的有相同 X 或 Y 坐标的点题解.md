# LeetCode 找到最近的有相同 X 或 Y 坐标的点 题解

## 1. 题目概述

- **标题 / 题号**：找到最近的有相同 X 或 Y 坐标的点（#1779，easy）
- **链接**：https://leetcode.cn/problems/find-nearest-point-that-has-the-same-x-or-y-coordinate/
- **来源**：LeetCode 第 47 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：你站在笛卡尔坐标系的 $(x, y)$ 处，给定数组 `points`，其中 `points[i] = [a_i, b_i]`。若某个点与你的位置**横坐标相同或纵坐标相同**，称其为**有效点**。在所有有效点中，找到与你的位置**曼哈顿距离**最近的那一个，返回其下标；若有多个最近的有效点，返回**下标最小**的；若不存在有效点，返回 $-1$。

**约束**：

- $1 \le points.length \le 10^4$
- `points[i].length == 2`
- $1 \le x, y, a_i, b_i \le 10^4$

## 2. 示例

**示例 1**

```text
输入：x = 3, y = 4, points = [[1,2],[3,1],[2,4],[2,3],[4,4]]
输出：2
解释：[3,1]、[2,4]、[4,4] 是有效点；[2,4] 与 [4,4] 的曼哈顿距离都为 1，
      取下标最小的 [2,4]，返回 2。
```

**示例 2**

```text
输入：x = 3, y = 4, points = [[3,4]]
输出：0
解释：有效点与当前位置重合，距离为 0。
```

**示例 3**

```text
输入：x = 3, y = 4, points = [[2,3]]
输出：-1
解释：没有任何点与当前位置同行或同列。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法分两步：先遍历一遍把所有有效点连同「(距离, 下标)」收集起来，排序后取字典序最小的元组，时间 $O(n \log n)$、空间 $O(n)$。结果正确，但既排序又开辅助数组，对一道签到题来说属于"绕路"。更进一步说，任何做法都至少要**扫一遍每个点**，所以 $O(n)$ 是天然下界——一遍扫描维护最优值即可，无需排序、无需额外数组。

> ⚠️ 一个容易忽略的坑：题面给的是**曼哈顿距离** $\lvert x_1 - x_2 \rvert + \lvert y_1 - y_2 \rvert$，不是欧氏距离。如果按欧氏距离开平方比较，不仅慢，而且在"平方后溢出/精度"上徒增风险，语义也和题目不符。

### 3.2 核心观察：有效点的距离退化为单轴差

![核心观察：同行或同列的点才有效，距离退化为单轴差](images/bw47_q1_valid_points.svg)

关键观察有两点：

1. **有效性判定** $a_i = x$ **或** $b_i = y$ 是 $O(1)$ 的两整数比较。若两者都不相等，这个点无论离你多近（哪怕欧氏距离再小）都不参与答案。
2. **有效点的曼哈顿距离退化**：若 $a_i = x$，则 $d = \lvert x - a_i \rvert + \lvert y - b_i \rvert = \lvert y - b_i \rvert$，只剩纵轴之差；若 $b_i = y$，同理只剩横轴之差。两个条件都满足时 $d = 0$。所以对有效点统一套公式 $d = \lvert x - a_i \rvert + \lvert y - b_i \rvert$ 计算即可，不需要分类讨论。

**平局规则**：距离相同时取下标最小。一遍扫描里只需用「**严格小于**」作为更新条件——后面的点只有真正更近时才能顶掉前面记录的答案，相同距离的后来者天然被拒之门外。

### 3.3 算法流程

![算法流程：一遍扫描，严格更优才更新](images/bw47_q1_scan_flow.svg)

```text
1. best = +∞, ans = -1
2. 依次考察每个点 i (0 ≤ i < n)，记 (a, b) = points[i]
3.   若 a != x 且 b != y：跳过（无效点）
4.   d = |x - a| + |y - b|
5.   若 d < best：best = d, ans = i（严格小于才更新）
6. 返回 ans
```

### 3.4 示例演算

![示例演算：x=3, y=4 五个点的扫描过程](images/bw47_q1_walkthrough.svg)

以示例 1（$x=3, y=4$）走一遍：下标 1 的 $(3,1)$ 是首个有效点，$best=3, ans=1$；下标 2 的 $(2,4)$ 距离 1 更近，更新为 $ans=2$；下标 4 的 $(4,4)$ 距离同为 1，**不满足严格小于**，保持 $ans=2$；最终返回 2。下标 0 与 3 的点既不同列也不同行，直接跳过。

## 4. 算法细节

1. **初始化**：`best` 初始化为 `INT_MAX`（或足够大的数），`ans = -1`。若全程无有效点，`ans` 保持 $-1$，自动覆盖"无解"分支。
2. **更新条件必须是 `d < best`**：写成 `<=` 会把相同距离中下标更大的点换上来，违反平局规则。
3. **重合点**：$a = x$ 且 $b = y$ 时 $d = 0$，正常参与比较；$d$ 不可能为负，`best` 单调不增。
4. **坐标范围**：$1 \le$ 坐标 $\le 10^4$，距离不超过 $2 \times 10^4$，`int` 绰绰有余，无溢出问题。
5. **不排序、不开哈希**：本题既不需要按坐标分桶，也不需要 `map`；任何 $O(n \log n)$ 的做法都是浪费。

## 5. 正确性证明

**引理 1（有效点的距离退化）**：点 $(a, b)$ 是有效点（$a = x$ 或 $b = y$）当且仅当它到 $(x, y)$ 的曼哈顿距离 $d = \lvert x - a \rvert + \lvert y - b \rvert$ 可以由一次 $O(1)$ 比较与一次绝对值计算得到；且 $d = 0$ 当且仅当 $(a,b) = (x,y)$。

**证明**：曼哈顿距离的定义即两项非负绝对值之和。当 $a = x$ 时第一项为 0，$d = \lvert y - b \rvert$；当 $b = y$ 时第二项为 0，$d = \lvert x - a \rvert$；两者均成立时 $d = 0$。公式本身对任意点都成立，有效与否只决定该点是否有资格参与比较，故统一套用公式正确。∎

**引理 2（严格更新保留最小下标）**：按 $i = 0, 1, \dots, n-1$ 顺序扫描，仅当 $d_i < best$ 时更新，则任意时刻 $(best, ans)$ 满足：$ans$ 是「已扫描的有效点中距离等于 $best$ 的最小下标」。

**证明**：对扫描步数归纳。初始无记录，命题空真。设某时刻命题成立，考察下一个有效点 $i$：若 $d_i < best$，则 $i$ 严格更近，更新后 $(d_i, i)$ 是新最近者且 $i$ 是该距离下已扫点中唯一者（之前的都更远），命题成立；若 $d_i = best$，不更新，而 $i > ans$，"距离为 $best$ 的最小下标"仍是 $ans$；若 $d_i > best$，$i$ 不影响最近距离，命题不变。∎

**定理**：上述一遍扫描算法返回所有有效点中曼哈顿距离最小、平局时下标最小的点；无有效点时返回 $-1$。

**证明**：由引理 2，扫描结束后 $ans$ 是最近有效点中的最小下标（若存在有效点）；若不存在有效点，任何点都不触发更新，$ans$ 保持初始值 $-1$。距离计算由引理 1 保证正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个点一次有效性判定、一次距离计算、一次比较，共 $n$ 轮。
- **空间**：$O(1)$。只用 `best` 与 `ans` 两个变量，不随输入规模增长。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int nearestValidPoint(int x, int y, vector<vector<int>>& points) {
        int best = INT_MAX, ans = -1;
        for (int i = 0; i < (int)points.size(); ++i) {
            int a = points[i][0], b = points[i][1];
            if (a != x && b != y) continue;       // 无效点：x、y 坐标都不相同
            int d = abs(x - a) + abs(y - b);      // 曼哈顿距离
            if (d < best) { best = d; ans = i; }  // 严格小于 → 平局保留下标最小
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def nearestValidPoint(self, x: int, y: int, points: list[list[int]]) -> int:
        best, ans = float('inf'), -1
        for i, (a, b) in enumerate(points):
            if a != x and b != y:          # 无效点
                continue
            d = abs(x - a) + abs(y - b)    # 曼哈顿距离
            if d < best:                   # 严格小于 → 平局保留下标最小
                best, ans = d, i
        return ans
```

> 💡 两份代码均通过官方 3 组示例，另与「按 (距离, 下标) 排序取最小」的独立实现做了 3000 组随机数据对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **无有效点**：返回 $-1$。别把 `ans` 初始化成 0——下标 0 未必是答案。
2. **平局规则**：更新条件务必用严格小于 `<`。用 `<=` 会在相同距离时返回更大下标，示例 1 中就会错答 4。
3. **重合点**：有效点可以与当前位置重合（$d = 0$），示例 2 即此情形，正常返回其下标。
4. **距离种类别搞错**：曼哈顿距离是"走格子"的距离，与欧氏距离的最近点可能不同，直接代入 $\lvert x-a \rvert + \lvert y-b \rvert$ 即可，无需 `sqrt`。
5. **负坐标不存在**：约束保证坐标全为正，无需额外处理；即便出现负数，`abs` 公式依然成立。
6. **数据规模**：$n \le 10^4$，$O(n)$ 或 $O(n \log n)$ 都能过，但 $O(n^2)$ 的两两比较（$10^8$）在 C++ 里勉强、在 Python 里必超时，没必要。
