# LeetCode 合并整数后的最小值 题解

## 1. 题目概述

- **标题 / 题号**：合并整数后的最小值（#4097，easy）
- **链接**：https://leetcode.cn/problems/minimum-value-of-merged-integers/
- **来源**：LeetCode 第 526 场周赛 Q1
- **难度**：简单
- **标签**：数学、模拟、字符串

**题意**：给定长度为偶数 $n$ 的整数数组 `nums`。按下标**固定配对**：`nums[0]` 与 `nums[1]` 合并、`nums[2]` 与 `nums[3]` 合并，依此类推。「合并」两个整数是指把第二个整数的所有十进制数位拼接在第一个整数的所有十进制数位之后。返回所有合并结果中的最小值。

**约束**：

- $2 \le n = \mathrm{nums.length} \le 100$，$n$ 为偶数
- $1 \le \mathrm{nums}[i] \le 1000$

> 💡 本题是纯模拟签到题：配对方式、拼接顺序都被题目定死，没有任何决策自由度，唯一要做的就是**把「拼接」翻译成算术**并正确取最小值。

## 2. 示例

**示例 1**

```text
输入：nums = [23,55,42,21]
输出：2355
解释：23 与 55 合并得 2355；42 与 21 合并得 4221。
      min(2355, 4221) = 2355。
```

**示例 2**

```text
输入：nums = [34,7,11,11]
输出：347
解释：34 与 7 合并得 347；11 与 11 合并得 1111。
      min(347, 1111) = 347。
```

**示例 3**

```text
输入：nums = [9,20]
输出：920
解释：只有一对，9 与 20 合并得 920，即为答案。
```

## 3. 解题思路

### 3.1 暴力思路

签到题，按定义直接模拟：从下标 0 开始每次跳 2，把 `nums[i]` 与 `nums[i+1]` 合并成一个整数，对全部合并结果取 $\min$。没有更朴素的做法，也不存在需要优化的瓶颈——数据规模 $n \le 100$、每个数最多 4 位，任何合理写法都在常数级开销内完成。

### 3.2 核心观察：拼接即移位，$\mathrm{merge}(a, b) = a \times 10^{d(b)} + b$

![核心观察：拼接即移位](images/merged_min_concat_formula.svg)

两个关键点：

1. **十进制拼接的算术表达**：把 $b$ 接在 $a$ 之后，等价于把 $a$ 整体「左移」$d(b)$ 个十进制位，再把 $b$ 补在空出的低位上，即
   $$\mathrm{merge}(a, b) = a \times 10^{d(b)} + b$$
   其中 $d(b)$ 表示 $b$ 的十进制位数。例如 $\mathrm{merge}(34, 7) = 34 \times 10^1 + 7 = 347$，$\mathrm{merge}(23, 55) = 23 \times 10^2 + 55 = 2355$。
2. **配对与顺序都由题目固定**：合并运算**不可交换**——$\mathrm{merge}(34, 7) = 347$ 而 $\mathrm{merge}(7, 34) = 734$——但题目只要求按下标 $(0,1), (2,3), \dots$ 合并，既不需要考虑谁前谁后的选择，也不存在排序、交换之类的优化空间。**纯模拟即可**。

### 3.3 算法流程

```text
1. ans = +∞
2. 对每个偶数下标 i（0, 2, 4, …, n-2）：
     a = nums[i]，b = nums[i+1]
     d = b 的十进制位数（除 10 计数）
     ans = min(ans, a × 10^d + b)
3. 返回 ans
```

求 $d(b)$ 的最稳写法是「除 10 计数」：`d = 0; while (b > 0) { d++; b /= 10; }`。Python 里直接 `len(str(b))`。

### 3.4 示例演算

![示例演算：逐对合并取最小](images/merged_min_walkthrough.svg)

| 配对 | 计算 | 合并值 | 所属示例 |
|------|------|--------|----------|
| $(23, 55)$ | $23 \times 10^2 + 55$ | $2355$ | 示例 1 |
| $(42, 21)$ | $42 \times 10^2 + 21$ | $4221$ | 示例 1 |
| $(34, 7)$ | $34 \times 10^1 + 7$ | $347$ | 示例 2 |
| $(11, 11)$ | $11 \times 10^2 + 11$ | $1111$ | 示例 2 |
| $(9, 20)$ | $9 \times 10^2 + 20$ | $920$ | 示例 3 |

三个示例的答案分别为 $\min(2355, 4221) = 2355$、$\min(347, 1111) = 347$、$920$（只有一对）。注意示例 2 中 $347$ 与 $1111$ **位数不同**——这正是不允许按字符串比较的原因。

## 4. 算法细节

1. **求位数 $d(b)$**：推荐「除 10 计数」循环，或 Python 的 `len(str(b))`。**不要**用 $\lfloor \log_{10} b \rfloor + 1$ 的浮点写法——`log10(1000)` 这类整边界值叠加浮点误差容易在取整时出错，收益又为零。
2. **字符串写法同样可行**：合并值也可写成 `int(str(a) + str(b))`（Python）或 `stoi(to_string(a) + to_string(b))`（C++），与移位公式结果完全一致。但**取 $\min$ 前必须转回整数**，直接对拼接字符串取 $\min$ 是错的（见 §8）。
3. **无需快速幂**：$d(b) \le 4$，直接连乘 10 即可（循环里 `shift *= 10` 顺便完成）。
4. **溢出**：$a, b \le 1000$，合并值最大为 $1000 \times 10^4 + 1000 = 10001000 < 2^{31} - 1$，C++ 用 `int` 即可，无需 `long long`。

## 5. 正确性证明

**引理 1**：对任意正整数 $a$、$b$，$a \times 10^{d(b)} + b$ 的十进制表示，恰为 $a$ 的十进制表示后接 $b$ 的十进制表示（即题目定义的合并结果）。

**证明**：设 $a$ 的十进制表示为 $\alpha_{k-1} \alpha_{k-2} \cdots \alpha_0$（$\alpha_{k-1} \ne 0$），$b$ 的十进制表示为 $\beta_{d-1} \beta_{d-2} \cdots \beta_0$（$\beta_{d-1} \ne 0$，$d = d(b)$）。则

$$a \times 10^{d} + b = \sum_{j=0}^{k-1} \alpha_j \, 10^{j+d} + \sum_{j=0}^{d-1} \beta_j \, 10^{j}$$

其中 $a$ 的各位落在 $10^{d}$ 至 $10^{k+d-1}$ 权位上，$b$ 的各位落在 $10^{0}$ 至 $10^{d-1}$ 权位上，两组权位互不重叠；每组内部最高位系数非零，低一组因 $\beta_{d-1} \ne 0$ 不会产生进位越界。由十进制表示的唯一性，该值的表示即拼接 $\alpha_{k-1} \cdots \alpha_0 \beta_{d-1} \cdots \beta_0$。∎

**定理**：算法返回值等于题目要求的「所有合并后整数中的最小值」。

**证明**：题目要求的合并集合恰为 $\{\mathrm{merge}(\mathrm{nums}[2k], \mathrm{nums}[2k+1]) : 0 \le k < n/2\}$，共 $n/2 \ge 1$ 个元素。算法以步长 2 遍历全部偶数下标，每对恰好计算一次且不重不漏；由引理 1，每个合并值的计算与定义一致。$\min$ 作用在有限非空集合上返回其最小元，故返回值即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L)$，其中 $L$ 为单个元素的最大十进制位数（本题 $L \le 4$），即求位数与移位的开销；总体为 $O(n)$，$n \le 100$ 下等同于常数级。
- **空间复杂度**：$O(1)$，仅使用 `ans`、`a`、`b`、`shift` 等常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minMergedInteger(vector<int>& nums) {
        int n = nums.size();
        int ans = INT_MAX;
        for (int i = 0; i + 1 < n; i += 2) {
            int a = nums[i], b = nums[i + 1];
            int shift = 1;
            for (int x = b; x > 0; x /= 10) {
                shift *= 10;
            }
            ans = min(ans, a * shift + b);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minMergedInteger(self, nums: list[int]) -> int:
        ans = inf
        for i in range(0, len(nums), 2):
            a, b = nums[i], nums[i + 1]
            ans = min(ans, a * 10 ** len(str(b)) + b)
        return ans
```

## 8. 边界情况与易错点

1. **字符串比较陷阱（最大坑）**：合并值位数不同时，字典序与数值序不一致——数值上 $347 < 1111$，但字符串 `"347" > "1111"`（首位 `'3' > '1'`）。拼接后**必须转回整数**再取 $\min$。
2. **$b = 1000$ 是范围内唯一的四位数**：$d(b) = 4$，移位达 $10^4$。想当然按「最多三位」处理会 WA。
3. **不要排序、不要交换**：合并不可交换（$34 \oplus 7 = 347$ 但 $7 \oplus 34 = 734$），且配对由下标定死。排序数组会破坏配对关系，属于方向性错误。
4. **$n = 2$ 只有一对**：循环只执行一次，直接返回该合并值（示例 3）；`ans` 初始化为 `INT_MAX` / `inf` 也能正确返回，但若初始化为 `0` 就错了。
5. **位数统计的边界**：约束 $b \ge 1$ 保证「除 10 计数」循环至少执行一次。若约束放宽允许 $b = 0$，则 $d(0)$ 应为 1（数位 `"0"` 占一位），循环写法会错误地得到 0，需特判——本题无需处理。
6. **溢出**：最大合并值 $10001000 < 2^{31} - 1$，`int` 足够，盲目开 `long long` 无害但无必要。
