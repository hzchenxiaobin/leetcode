# LeetCode 可以输入的最大单词数 题解

## 1. 题目概述

- **标题 / 题号**：可以输入的最大单词数（#1935，easy）
- **链接**：https://leetcode.cn/problems/maximum-number-of-words-you-can-type/
- **来源**：LeetCode 第 250 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、模拟

**题意**：键盘上部分字母键失灵，其余键正常。给定由**单个空格**分隔的字符串 `text`（不含前导/尾随空格，单词仅含小写字母），以及由**互不相同**小写字母组成的 `brokenLetters`，返回 `text` 中能**完全输入**（不含任何破损字母）的单词数目。

**约束**：

- $1 \le \text{text.length} \le 10^4$
- $0 \le \text{brokenLetters.length} \le 26$
- `text` 由若干用单个空格分隔的单词组成，不含前导/尾随空格
- 每个单词仅由小写英文字母组成
- `brokenLetters` 由互不相同的小写英文字母组成

> 💡 本题在本仓库另有[每日题解 1935](../../solution/1901-2000/1935_可以输入的最大单词数.md)，两篇为姊妹篇：那边侧重「不变小集合 + 高频查询」的哈希表招牌场景、哈希/布尔/位掩码三写法对照与面试问答。本篇按周赛复盘视角，聚焦**签到题从题面到代码的最短路径**——「空格即单词边界」的一趟扫描状态机、**末尾补结算**这一最易漏的边界复盘，以及切分等价性的引理-定理证明链。两篇互为印证。



```text
输出：0
解释：两个单词都含 'e'，均无法输入。
```

**自造边界样例**

```text
输入：text = "abc def", brokenLetters = ""
输出：2
解释：无破损键，全部单词可输入。这也是「漏掉末尾补结算」的照妖镜——漏补只得 1。

输入：text = "a", brokenLetters = "a"
输出：0
解释：单单词、无空格：循环内一次结算都没有，答案完全由末尾补结算给出。
```

## 3. 解题思路

### 3.1 赛场直觉：切分 + 逐字符查破损表（暴力）

最直觉的写法：把 `text` 按空格切成单词，对每个单词的每个字符，**线性扫描** `brokenLetters` 判断是否破损。

```text
for word in text.split(" "):
    ok = True
    for c in word:
        for b in brokenLetters:
            if c == b: ok = False
    if ok: ans += 1
```

- **正确性**：穷举每个字符是否破损，无误。
- **效率**：设 $n = \text{text.length}$、$B = \text{brokenLetters.length}$，共 $O(n \cdot B)$ 次比较，最坏约 $10^4 \times 26 = 2.6 \times 10^5$——本题数据规模下完全能过。

> ⚠️ 浪费在于「重复线性查找同一张破损表」。`brokenLetters` 在整次判定中**固定不变**，同一个字符是否破损本应 $O(1)$ 查表得出。签到题比拼的是**写对 + 写快**，两步提速各有抓手：建表消除重复查找，不切分消除中间容器。

### 3.2 核心观察：破损表建一次，空格即单词边界

![核心观察：破损表只建一次，字符流一趟判定](images/wc250_q1_onescan_concept.svg)

两个观察叠加，得到签到题的最短代码路径：

**观察一（建表）**：`brokenLetters` 是「不变的小集合 + 高频成员查询」——一次性装入长度 26 的布尔数组（或哈希集合），此后「字符 $c$ 是否破损」退化为下标寻址，$O(1)$ 完成，总复杂度从 $O(n \cdot B)$ 降到 $O(n + B)$。

**观察二（空格即边界）**：题目保证单词间**恰好一个空格**且无首尾空格——空格本身就是天然的「单词结束」事件，**根本不需要 `split`**。直接把 `text` 当字符流一趟扫描，维护两个变量：

$$\text{ans（已结算的可输入单词数）},\quad \text{ok（当前单词是否仍然可输入）}$$

- 遇到**字母** $c$：查表，若 `broken[c]` 则 `ok = false`（该单词报废，后续字符不必再查）；
- 遇到**空格**：结算刚结束的单词 `ans += ok`，并复位 `ok = true`；
- **扫描结束后**：`ans += ok`——**最后一个单词后面没有空格**，必须补一次结算。

$$\boxed{\text{返回值} = \sum_{j=1}^{W} \big[\,w_j \text{ 中不含破损字母}\,\big] \quad (W \text{ 为单词数})}$$

> ⚠️ **末尾补结算是本题唯一的陷阱**，与 251 场 Q1 的「循环 $k-1$ 轮不是 $k$ 轮」同属签到题的经典边界考点：逻辑全对、三个官方样例可能照样全过，唯独漏数最后一个单词。自造样例 `text = "abc def", brokenLetters = ""`（正确答案 2，漏补得 1）是专门照出它的测试。

### 3.3 算法流程

![算法流程：建表 → 一趟扫描（空格结算 + 末尾补结算）](images/wc250_q1_onescan_flow.svg)

1. **建表**：`broken[26]` 布尔数组，对 `brokenLetters` 每个字符置 `broken[c-'a'] = true`；初始化 `ans = 0, ok = true`。
2. **扫描**：遍历 `text` 每个字符 $c$：空格则 `ans += ok; ok = true`；字母则查表，命中即 `ok = false`。
3. **补结算**：扫描结束后 `ans += ok`（可直接写成 `return ans + ok`）。

> 💡 C++ 赛场形态就是这 5 行核心逻辑：无 `split`、无 `istringstream`、无字符串拷贝，除 26 字节的表外只花两个变量的空间。Python 赛场则反过来——`split` + `all()` 的一行流更快（语言生态差异），两种形态都在 §7 给出。

### 3.4 示例演算

![示例演算：一趟扫描的两个关键事件](images/wc250_q1_walkthrough.svg)

以示例 1（`text = "hello world"`，`broken = {a, d}`）走查状态机：

| 事件 | 字符 | 动作 | ans | ok |
|------|------|------|-----|-----|
| 扫词中 | h e l l o | 逐字符查表，全部 ✓ | 0 | true |
| **单词边界** | ␣ | 结算：`ans += true`，复位 `ok = true` | **1** | true |
| 扫词中 | w o r l | 逐字符查表，全部 ✓ | 1 | true |
| **命中破损** | d | `broken['d']` 为真 → `ok = false` | 1 | false |
| **扫描结束** | （无字符） | 补结算：`ans += false` | **1** | — |

返回 $1$ ✓。示例 3（`broken = {e}`）同一状态机：`"leet"` 在第二个字符 `e` 处 `ok = false`，空格结算 $+0$；`"code"` 又在末字符 `e` 处报废，补结算 $+0$，返回 $0$ ✓。

> 💡 注意 `ok` 是**布尔不是计数**：一个单词含多个破损字母（如 `leet` 的两个 `e`）仍只算一次「不可输入」，第一次命中后它已为 `false`，后续命中幂等。

## 4. 算法细节

1. **建表的三种形态**：① 布尔数组 `broken[26]`——字母固定 26 个，下标 $c - \texttt{'a'}$ 直接寻址，无哈希开销，常数最小；② 哈希集合 `unordered_set<char>` / `set`——通用、可读，字符集扩大时仍可行；③ **26 位位掩码**——`broken |= 1 << (c-'a')` 建表，单词一侧也累积掩码 `word`，结算条件 `word & broken == 0` 一次按位与判「全不在」。
2. **结算时机恰有两处**：空格处（单词边界）与扫描结束后（最后一个单词无空格收尾）。两处可以统一：`return ans + ok` 把补结算合并进返回表达式；或者扫描前给 `text` 末尾补一个空格（Python 可 `text + ' '`）让循环内结算覆盖全部单词——后者要多一次字符串拷贝，C++ 里前者更省。
3. **查表顺序先判空格再查表**：`if (c == ' ') … else if (broken[…]) …`——空格不是字母，不能拿去查 26 长度的表（越界）。
4. **提前终止是常数优化而非必需**：`ok = false` 后该单词剩余字符查不查表都不影响结果；一行流 `all(c not in broken for c in w)` 的短路等价于循环版发现命中即 `break`。
5. **位掩码版无短路**：必须扫完整词累积 `word` 掩码才能判定，对「破损字符靠前」的单词反而多做功——位掩码换来的是判定本身一次完成，两种思路的取舍在[每日题解 1935](../../solution/1901-2000/1935_可以输入的最大单词数.md)的扩展一节有对照。

## 5. 正确性证明

**引理 1（可输入的集合刻画）**：单词 $w$ 可以完全输入 $\iff$ $\text{chars}(w) \cap \text{brokenLetters} = \varnothing$。

**证明**：「完全输入」即 $w$ 的每个字符都能按下对应字母键。键 $c$ 可按 $\iff$ $c \notin \text{brokenLetters}$（其余键全部正常）。故 $w$ 可输入 $\iff$ $\forall c \in w:\ c \notin \text{brokenLetters}$ $\iff$ 字符集合与破损集合不交。∎

**引理 2（一趟扫描的结算语义）**：设 $\text{text} = w_1 \frown \texttt{'\ '} \frown w_2 \frown \texttt{'\ '} \frown \cdots \frown w_W$（$W$ 个单词）。算法执行中：遇到第 $j$ 个空格时，`ok` 的当前值 $= [\,w_j$ 不含破损字母$\,]$；扫描结束后，`ok` $= [\,w_W$ 不含破损字母$\,]$。

**证明**：对扫描位置归纳。`ok` 在每个空格处复位为 `true`，且仅在扫描到破损字母时置 `false`。于是从第 $j-1$ 个空格之后（或串首）到第 $j$ 个空格之前，`ok` 接收的全部修改恰来自 $w_j$ 的字符：$w_j$ 含破损字母则 `ok` 在命中处变 `false` 并保持（幂等），否则保持 `true`。故到达第 $j$ 个空格时 `ok` 的值正是 $[\,w_j$ 无破损字母$\,]$；串尾同理，$w_W$ 后不再有空格，扫描结束时 `ok` 保持其判定值。∎

**定理（算法正确性）**：算法返回可输入单词的数目。

**证明**：`ans` 的每次增加都发生在结算处：第 $j$ 个空格处 `ans += ok` 贡献 $[\,w_j$ 可输入$\,]$（引理 1 把「无破损字母」换为「可输入」，引理 2 给出 `ok` 值），扫描结束后的补结算贡献 $[\,w_W$ 可输入$\,]$。$W$ 个单词各恰被结算一次（$w_1, \dots, w_{W-1}$ 在空格处，$w_W$ 在补结算处），且除此之外 `ans` 不变，故 $\text{ans} = \sum_{j=1}^{W} [w_j \text{ 可输入}]$，即可输入单词数。∎

**推论（空表情形）**：$\text{brokenLetters} = \varnothing$ 时每个单词都可输入，返回值为单词数 $W$（空格数 $+ 1$），无需特判。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + B)$，其中 $n = \text{text.length}$、$B = \text{brokenLetters.length}$。建表遍历 `brokenLetters` 一次 $O(B)$；主循环遍历 `text` 每字符 $O(1)$（布尔寻址或哈希查询），合计 $O(n)$。对照暴力法的 $O(n \cdot B)$：本题 $B \le 26$ 两者常数差异不大，但「建表 + $O(1)$ 查询」是不变小集合的通用范式。
- **空间复杂度**：$O(26) = O(1)$（布尔数组 / 位掩码）或 $O(B)$（哈希集合）。一趟扫描版除表外只用 `ans`、`ok` 两个变量，不产生单词切分的中间容器——对照 `split` 版需 $O(n)$ 存单词列表。

## 7. 参考代码

### C++（一趟扫描：布尔数组 + 补结算并入返回值）

```cpp
class Solution {
public:
    int canBeTypedWords(string text, string brokenLetters) {
        bool broken[26] = {false};
        for (char c : brokenLetters) broken[c - 'a'] = true;
        int ans = 0;
        bool ok = true;
        for (char c : text) {
            if (c == ' ') { ans += ok; ok = true; }
            else if (broken[c - 'a']) ok = false;
        }
        return ans + ok;
    }
};
```

### C++（位掩码一趟：按位与整体判定）

```cpp
class Solution {
public:
    int canBeTypedWords(string text, string brokenLetters) {
        int broken = 0;
        for (char c : brokenLetters) broken |= 1 << (c - 'a');
        int ans = 0, word = 0;
        for (char c : text) {
            if (c == ' ') { ans += (word & broken) == 0; word = 0; }
            else word |= 1 << (c - 'a');
        }
        return ans + ((word & broken) == 0);
    }
};
```

### Python（一趟扫描）

```python
class Solution:
    def canBeTypedWords(self, text: str, brokenLetters: str) -> int:
        broken = set(brokenLetters)
        ans, ok = 0, True
        for c in text:
            if c == ' ':
                ans += ok
                ok = True
            elif c in broken:
                ok = False
        return ans + ok
```

### Python（赛场一行流：split + all 短路）

```python
class Solution:
    def canBeTypedWords(self, text: str, brokenLetters: str) -> int:
        broken = set(brokenLetters)
        return sum(all(c not in broken for c in w) for w in text.split())
```

> 💡 **写法对照**：① C++ 一趟扫描版是周赛签到题的标准形态——无切分、无拷贝、两个变量，`return ans + ok` 把补结算合并进出口；② 位掩码版把「逐字符查询」改为「单词掩码与破损掩码按位与」，判定一次完成，代价是无短路、须扫完整词；③ Python 赛场上 `split + all` 一行流编码最快，`all` 的短路天然实现提前终止；④ 四个版本对 $n \le 10^4$ 都是瞬时，差距要到字符集扩大或输入流式化时才显现（见延伸思考）。以上实现均已通过官方样例 1/2/3 及 `broken` 为空、单单词、全报废等自造边界，并与 `split` 参考实现互拍两万组随机数据。

## 8. 边界情况与易错点

1. **末尾补结算（本题最经典 WA）**：最后一个单词后没有空格，循环内不会为它结算。反例：`text = "abc def", brokenLetters = ""`，正确答案 2，漏写 `return ans + ok`（只 `return ans`）得 1。三个官方样例恰好都「最后单词报废」或「前面已结算」，**未必能照出这个 bug**——签到题交之前务必用一个「最后单词可输入」的样例自测。
2. **空格先判再查表**：`broken[c - 'a']` 只对字母合法；若先查表后判空格，空格（ASCII 32）会使 `c - 'a'` 为负、数组越界。
3. **`brokenLetters` 为空**：返回单词总数，通用逻辑自然覆盖（空表查不到任何命中），无需特判。
4. **单单词（无空格）**：循环内一次结算都没有，答案完全由补结算给出——`text = "a", broken = "a"` 应返回 0。
5. **`split(" ")` 与 `split()` 的差别**：题目保证单词间单个空格，两者等价；若约束放宽为任意空格，`split(" ")` 会切出空串（空串的 `all` 恒真、会被误计入答案），而无参 `split()` 自动合并连续空白——工程习惯上用后者更稳。
6. **`ok` 是布尔不是计数**：一个单词含多个破损字母仍只算一次「不可输入」，第一次命中后 `ok` 已为 `false`，重复命中幂等；别把「命中次数」当统计量。
7. **数的是「能输入」的词**：题目问可输入单词数，别数反成含破损字母的单词数（示例 1 会得 1 恰好相同，示例 3 会得 2 露馅）。
8. **位掩码的符号与宽度**：`1 << (c - 'a')` 最大 `1 << 25`，`int` 装得下；若字符集放宽到 32 位以上需换 `long long` / `uint64_t`，并同步检查 `word & broken` 的类型提升。

- **修饰键破损**：若破损的是「按键」而非「字符」（如 Shift 坏了导致大写打不出），字符到按键的映射不再单射，需按物理按键建表——判定对象从字符集换成按键集。
- **容错版本**：若每个单词至多容忍 $k$ 个破损字母仍算可输入，`ok` 升级为命中计数，结算条件变为 `cnt <= k`；$k = 0$ 即本题。
- **位掩码并行判定**：把「逐字符查表」整体化为「单词掩码 & 破损掩码」，详见[每日题解 1935](../../solution/1901-2000/1935_可以输入的最大单词数.md)的扩展一节。
