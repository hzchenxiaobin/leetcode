# LeetCode 查询最大基因差 题解

## 1. 题目概述

- **标题 / 题号**：查询最大基因差（#1938，hard）
- **链接**：https://leetcode.cn/problems/maximum-genetic-difference-query/
- **来源**：LeetCode 第 250 场周赛 Q4
- **难度**：困难
- **标签**：字典树、位运算、树、深度优先搜索、离线查询

**题意**：给定一棵 $n$ 个节点的有根树，节点编号 $0$ 到 $n-1$，每个节点的**基因值**就是它的编号（节点 $x$ 的基因值为 $x$）。两个基因值的**基因差**定义为两者的**异或和** $\oplus$。对每条查询 $[node_i, val_i]$，在「$node_i$ 到根的路径上全部节点（含两端）」的基因值中，找与 $val_i$ 异或**最大**的那个，返回答案数组 `ans`。

**约束**：

- $2 \le \text{parents.length} \le 10^5$，`parents[root] == -1`，其余 $0 \le \text{parents}[i] \le n-1$
- $1 \le \text{queries.length} \le 3 \times 10^4$
- $0 \le node_i \le n - 1$
- $0 \le val_i \le 2 \times 10^5$

> 💡 本题在本仓库另有[每日题解 1938](../../solution/1901-2000/1938_查询最大基因差.md)，两篇为姊妹篇：每日篇侧重**指针版 Trie**的实现细节、421/1707/1803/1766 的家族对照与面试问答。本篇按周赛复盘视角，聚焦**赛场最短识别路径**（两个模板的拼接点）、**数组版无指针 Trie**（与每日篇的指针版互为对照实现）、**路径不变式与逐位贪心**的完整证明链（§5），并补齐 250 场 Q1–Q4 的收官复盘。

## 3. 解题思路

### 3.1 暴力思路：逐查询上溯路径

对每条查询 $[node, val]$，从 $node$ 沿 `parents` 逐层上溯到根，对路径上每个基因值 $p$ 计算 $val \oplus p$ 取最大。单条查询最坏 $O(n)$（树退化为链时路径长 $n-1$），总计 $O(qn) = 3 \times 10^4 \times 10^5 = 3 \times 10^9$——**必超时**。

> ⚠️ 瓶颈有两个且相互独立：**① 路径物化**——每条查询独立上溯，公共祖先被反复扫；**② 集合内取最大异或**——线性枚举是 $O(\text{路径长})$。消掉两个瓶颈的手段也相互独立：① 用一次 DFS 让所有查询「顺路」得到路径；② 用 01-Trie 把单点查询降为 $O(\log V)$。正解 = ①×② 的拼接。

### 3.2 核心观察：离线挂载 + DFS 回溯，Trie 恒等于当前路径

![核心观察：离线挂载 + DFS 回溯，Trie 恒等于根到当前节点的路径](images/wc250_q4_concept.svg)

三步转换：

1. **查询离线**：每条查询的答案只依赖「根到 $node_i$ 的路径」与 $val_i$，不依赖其他查询——满足离线条件。把查询挂到节点上：`qAt[node].append((val, idx))`。
2. **DFS 复用路径**：DFS 自根向下，任意时刻「已进入未退出」的节点**恰好**构成根到当前节点的路径。于是访问到 $u$ 时，根到 $u$ 路径上的值天然就在手边——把 $qAt[u]$ 的查询在此刻统一回答。
3. **Trie 维护路径集合**：用一个**带 `cnt` 的二进制 Trie** 维护「当前路径上的全部基因值」：进入 $u$ 时 `insert(u)`，退出 $u$ 时 `remove(u)`。恒等式：

$$\boxed{\;\text{Trie} \equiv \{\, \text{root} \to u \text{ 的全部基因值} \,\}\;}$$

> 💡 **赛场识别**：困难题常常是「模板 A 的容器 × 模板 B 的场景」的拼接。这里 A = [421. 数组中两个数的最大异或值](../../solution/0401-0500/421_数组中两个数的最大异或值.md) 的 01-Trie 逐位贪心，B = [1766. 互质树](../../solution/1701-1800/1766_互质树.md) 的「树上离线查询 + DFS 回溯维护路径集合」。另外 $q \le 3 \times 10^4 \ll n = 10^5$，题目把查询摆到明面上等你离线——这是出题人递的梯子。

### 3.3 Trie 逐位贪心与懒删除

![Trie 逐位贪心：高位优先，每步想要与 val 相反的那一位](images/wc250_q4_greedy_bits.svg)

**查询贪心**：从最高位到最低位逐位决策。设 $val$ 当前位为 $d$：优先走「相反位 $d \oplus 1$」的子树——该位异或得 1，答案累加 $2^b$；走不到（子树空）才走相同位，该位贡献 0。高位一个 1 抵得过低位全部（$2^b > 2^b - 1$），贪心正确性见 §5 引理 2。

**懒删除**：`remove(x)` 沿 $x$ 的位串路径把 `cnt` 逐节点 $-1$，**不释放节点**。于是 Trie 里可能残留 `cnt == 0` 的「幻影分支」——贪心想走相反位时必须检查 `cnt > 0`，否则会走进已被删空的子树返回错误答案。

> ⚠️ 删除而不释放，是带计 Trie 的标准手法：后续再插入同值时直接复用节点、`cnt` 加回即可，避免反复分配。代价就是查询必须「看计数不看存在」。

### 3.4 算法流程

![算法流程：事件栈迭代 DFS，enter/exit 两个相位](images/wc250_q4_algorithm_flow.svg)

1. **建树**：由 `parents` 构建孩子邻接表 `children[]`，找到根（`parents[i] == -1` 的节点）。
2. **挂载查询**：`qAt[node].append((val, idx))`，`idx` 为原始下标。
3. **初始化**：空 Trie（`ch` / `cnt` 数组，0 号节点当根），事件栈 `[(root, enter)]`。
4. **迭代 DFS**（`(u, state)`，`enter`/`exit` 两相位，链状树深 $10^5$ 不爆栈）：
   - `enter` 相位：`insert(u)` → 依次回答 `qAt[u]`（此刻 Trie 恰为根到 $u$ 的路径）→ 压入 `(u, exit)` → 子节点逆序入栈；
   - `exit` 相位：`remove(u)`。
5. **返回** `ans`（按原始下标写回，与回答顺序无关）。

### 3.5 示例演算

![示例演算：示例 2 全过程，ans = [6, 14, 7]](images/wc250_q4_example_walkthrough.svg)

以示例 2 演算（`+x` 表示 `insert(x)`，`−x` 表示 `remove(x)`）：

| 事件 | 操作 | Trie 内容 | 回答查询 |
|------|------|-----------|----------|
| enter 2 → 3 → 0 | +2 +3 +0 | $\{2,3,0\}$ | q2=[0,5] → $\max(7,6,5)=\mathbf{7}$ |
| enter 4 | +4 | $\{2,3,0,4\}$ | q0=[4,6] → $\mathbf{6}$ |
| exit 4 / enter 6 / exit 6 | −4 +6 −6 | 回落到 $\{2,3,0\}$ | — |
| exit 0 / exit 3 | −0 −3 | $\{2\}$ | — |
| enter 7 → 1 | +7 +1 | $\{2,7,1\}$ | q1=[1,15] → $\mathbf{14}$ |
| 其余 exit | … | $\varnothing$ | — |

两个细节值得盯：**q2 在 enter 0 时就回答了**（早于进入 4）——路径查询与 DFS 到达的相对次序无关；**q1 的答案取在 node 自身**（$15 \oplus 1 = 14$）——路径**含 $node_i$ 与根两端**，实现里必须先 `insert(u)` 再回答。最终 `ans = [6, 14, 7]` ✓（按原始下标对号入座）。

## 4. 算法细节

1. **数组版 Trie（本篇主推，与每日篇的指针版对照）**：`ch`（每个节点两个孩子的下标，`0` 表示空）与 `cnt` 两个 `vector`，`push_back` 动态开点，0 号节点当根。无指针、无手动内存管理、访存连续对缓存友好。孩子下标用 `0` 而非 `-1` 表示「空」，天然兼容 `ch[cur][d] == 0` 判断。
2. **位深 $B = 18$**：$val_i \le 2 \times 10^5 < 2^{18} = 262144$，基因值 $\le 10^5 - 1 < 2^{17}$，两者异或结果 $< 2^{18}$，故 `bit17 → bit0` 共 18 层覆盖全部。取 $B = 17$（即从 `bit16` 起算）会丢掉 `bit17`——$2^{17} = 131072 \le 2 \times 10^5$，对大 `val` 直接判错（§8.1）。
3. **懒删除与幻影分支**：`remove` 只减 `cnt` 不释放节点，`query` 走相反位前必须 `cnt > 0` 双重检查。`ch[cur][want] != 0` 只说明「历史上建过这个分支」，不代表现在有活跃元素。
4. **Trie 节点数精算**：朴素上界 $n \cdot B \approx 1.8 \times 10^6$，但基因值是 $[0, n)$ 内**互异**的整数——同一前缀只占一个节点，第 $k$ 层节点数 $\le \min(2^k, n)$，总节点数 $\le \sum_{k=0}^{17} \min(2^k, n) \approx 1.3 \times 10^5 + 10^5 \approx 2.4 \times 10^5$（$n = 10^5$ 时）。高位前缀共享把空间压掉约一个数量级，这也是指针版也能稳过的原因；数组版 `reserve(2n)` 起步足够。
5. **迭代事件栈**：栈元素 $(u, state)$。`enter` 时压入 `(u, exit)` **先于**子节点入栈，保证 `exit` 最后弹出——即 $u$ 的子树整体处理完才回溯。子节点**逆序入栈**使访问按邻接表顺序进行（LIFO），同时保证兄弟分支互不污染：处理弟分支前，哥分支已整体退出。
6. **离线挂载 + 按位下标写回**：DFS 回答顺序 ≠ 查询顺序，`ans[idx]` 必须按原始下标落位。同一节点可挂多条查询，`qAt` 用列表天然支持。

## 5. 正确性证明

**引理 1（路径不变式）**：事件栈算法运行的任意时刻，设「已 `enter` 未 `exit`」的节点依进入次序为 $u_1, u_2, \ldots, u_k$，则 $u_1 = root$ 且 $u_1, \ldots, u_k$ 是根到 $u_k$ 的路径；且 Trie 的活跃多重集 $M = \{u_1, \ldots, u_k\}$。

**证明**：对已处理的事件数归纳。初始未处理任何事件，活跃集为空，成立。归纳地考察事件栈的两个结构事实：

（栈序事实）`enter(u)` 处理时按 `(u, exit)`、逆序子节点入栈。于是 `(u, exit)` 在栈中位于 $u$ 全部子孙事件**之下**，弹出必晚于它们——`exit(u)` 触发时 $u$ 的子树已整体处理完毕；而 `(v, enter)` 弹出时，先于它入栈的兄弟事件块已整体完成，`parent(v)` 必然活跃且位于活跃路径末端。

- **`enter(v)` 事件**：由栈序事实，此刻活跃序列是根到 $\text{parent}(v)$ 的路径；算法执行 `insert(v)`，活跃序列延长为根到 $v$ 的路径，$M' = M \cup \{v\}$，仍为该路径的集合（基因值互异，多重集即集合）。
- **`exit(u)` 事件**：由栈序事实，$u$ 的子孙已全部进出，活跃序列是根到 $u$ 的路径；算法执行 `remove(u)`，活跃序列缩短为根到 $\text{parent}(u)$ 的路径，$M' = M \setminus \{u\}$。

查询恰在 `enter(u)` 相位内、`insert(u)` 之后、子事件入栈之前回答，此时刻 $M = \{root \to u \text{ 的全部基因值}\}$，含 $u$ 与根两端。∎

**引理 2（Trie 贪心正确性）**：设非空集合 $S \subseteq [0, 2^B)$ 存于深度 $B$ 的 01-Trie，每个节点的 `cnt` 为其子树活跃元素个数（`insert`/`remove` 沿同一位串路径增减，与集合同步）。则对任意 $v$，逐位贪心返回 $\max\limits_{p \in S} v \oplus p$。

**证明**：对 $B$ 归纳。$B = 0$ 时 $S = \{0\}$，$v$ 也是单元素，返回 $0 = v \oplus 0$，显然。设 $b = B - 1$ 为最高位，按 $b$ 位把 $S$ 划分为 $S_0, S_1$（相应前缀的子树），记 $d$ 为 $v$ 的 $b$ 位：

- **若 $S_{1-d} \ne \varnothing$**：对任意 $p \in S_{1-d}$，$v \oplus p$ 的 $b$ 位为 $1$，故 $v \oplus p \ge 2^b$；对任意 $p \in S_d$，$b$ 位为 $0$，故 $v \oplus p < 2^b$。于是 $\max_{p \in S} v \oplus p$ 只能在 $S_{1-d}$ 中取得。贪心检查该子树 `cnt > 0`（即 $S_{1-d}$ 非空的准确判定）后走入之，res 的 $b$ 位记 1；而 $\max_{p \in S_{1-d}} v \oplus p = 2^b + \max_{p \in S_{1-d}} (\text{低 } b \text{ 位的异或})$——高位恒 1，两目标分离。剩下是子树内、深度 $b$ 的同型问题，由归纳假设，低 $b$ 位贪心取到其最大值，整体即全局最大。
- **若 $S_{1-d} = \varnothing$**：则 $S = S_d$ 非空，$\max$ 必在 $d$ 分支取得；贪心因 `cnt == 0`（或分支不存在）被迫走 $d$ 分支，res 的 $b$ 位记 0，$v \oplus p$ 的 $b$ 位恒 0，同样是深度 $b$ 的同型问题，归纳得证。∎

**定理（算法正确性）**：算法对每条查询 $[node, val]$ 返回 $\max\{\, val \oplus p : p \in \text{path}(root \to node) \,\}$。

**证明**：引理 1 保证回答时刻 Trie 的活跃集合恰为 $\text{path}(root \to node)$ 的基因值集合（非空，至少含 $node$ 自身）；引理 2 保证 `query(val)` 返回该集合上的最大异或。两引理串联即得。∎

**推论（工程安全性）**：（i）贪心每步到达的节点 `cnt > 0`——归纳：活跃元素至少 1 个，进入某节点说明其 `cnt > 0`，其活跃元素按下一层位分流，被选中走的分支（优先相反位且非空，否则相同位容纳全部）`cnt` 必 $> 0$，故查询永不空指针、必命中一个真实元素；（ii）$val < 2^{18}$ 且基因值 $< 2^{17}$，18 层不丢任何有效位。∎

> 💡 **证明的关键一步**是引理 2 的「$2^b > 2^b - 1$」断层：高位一个相反位贡献的 $2^b$，严格大于低位全部之和的上界 $2^b - 1$，因此最优解必然「先保证高位能相反就相反」——这也是逐位贪心在异或题族（421/1707/1803/1938）中通用的根本原因。引理 1 则是把「树上路径」翻译成「进出栈事件序列」的不变式，正是 1766（路径栈）到本题（路径 Trie）唯一需要替换的组件。

## 6. 复杂度分析

- **时间复杂度**：$O((n + q) \cdot B)$，其中 $B = 18$。建树与挂载 $O(n + q)$；每个节点 `enter`/`exit` 各一次 Trie 操作，每次沿 18 层路径 $O(B)$，共 $2nB$；每条查询贪心走 18 层 $O(B)$，共 $qB$。代入数据范围约 $(2 \times 10^5 + 3 \times 10^4) \times 18 \approx 4 \times 10^6$ 次 $O(1)$ 操作，远低于时限。对照暴力 $O(qn) \approx 3 \times 10^9$，快约三个数量级：Trie 把「集合内找最大异或」从 $O(\text{路径长})$ 降为 $O(\log V)$，DFS 回溯让路径集合随扫描增量维护、零重复物化。
- **空间复杂度**：$O(n \log V + q)$。Trie 节点 $\le \sum_{k=0}^{17} \min(2^k, n) + 1 \approx 2.4 \times 10^5$（§4.4 的精算上界，互异整数高位前缀共享），每节点 3 个 `int`；`children` $O(n)$；`qAt` $O(q)$；事件栈 $O(n)$。

## 7. 参考代码

### C++（数组版 Trie + 迭代事件栈）

```cpp
class Solution {
    static constexpr int B = 18;              // 2^18 > 2e5，覆盖 val 与基因值的全部位
    vector<array<int, 2>> ch;                  // 孩子下标，0 表示空
    vector<int> cnt;                           // 子树活跃元素个数（懒删除的计数）
public:
    vector<int> maxGeneticDifference(vector<int>& parents, vector<vector<int>>& queries) {
        int n = parents.size(), m = queries.size();
        vector<vector<int>> children(n);
        int root = -1;
        for (int i = 0; i < n; ++i) {
            if (parents[i] == -1) root = i;
            else children[parents[i]].push_back(i);
        }
        vector<vector<pair<int, int>>> qAt(n); // 挂载 (val, 原始下标)
        for (int i = 0; i < m; ++i)
            qAt[queries[i][0]].emplace_back(queries[i][1], i);

        ch.reserve(2 * n + 4); cnt.reserve(2 * n + 4);   // 互异整数高位共享，节点数 << n*B
        ch.push_back({0, 0}); cnt.push_back(0);          // 0 号节点当根
        auto insert = [&](int x) {
            int cur = 0;
            for (int b = B - 1; b >= 0; --b) {
                int d = (x >> b) & 1;
                if (ch[cur][d] == 0) {
                    ch.push_back({0, 0}); cnt.push_back(0);
                    ch[cur][d] = (int)ch.size() - 1;
                }
                cur = ch[cur][d];
                ++cnt[cur];
            }
        };
        auto remove = [&](int x) {
            int cur = 0;
            for (int b = B - 1; b >= 0; --b) {
                cur = ch[cur][(x >> b) & 1];
                --cnt[cur];                    // 懒删除：只减计数，不释放节点
            }
        };
        auto query = [&](int v) {
            int cur = 0, res = 0;
            for (int b = B - 1; b >= 0; --b) {
                int d = (v >> b) & 1;
                int want = d ^ 1;              // 想走与 val 相反的那一位
                if (ch[cur][want] != 0 && cnt[ch[cur][want]] > 0) {
                    res |= 1 << b;             // 该位异或得 1
                    cur = ch[cur][want];
                } else {
                    cur = ch[cur][d];          // 走不到才取相同位
                }
            }
            return res;
        };

        vector<int> ans(m);
        vector<pair<int, int>> stk;            // (节点, 相位)：0 = enter，1 = exit
        stk.reserve(n + 1);
        stk.emplace_back(root, 0);
        while (!stk.empty()) {
            auto [u, st] = stk.back();
            stk.pop_back();
            if (st == 0) {                     // enter：插 u、答查询、排子树
                insert(u);
                for (auto& [v, i] : qAt[u]) ans[i] = query(v);
                stk.emplace_back(u, 1);        // exit 先入栈 → 最后弹出（栈底）
                for (int i = (int)children[u].size() - 1; i >= 0; --i)
                    stk.emplace_back(children[u][i], 0);
            } else {                           // exit：删 u（子树已整体处理完）
                remove(u);
            }
        }
        return ans;
    }
};
```

### Python（数组版同构直译）

```python
class Solution:
    def maxGeneticDifference(self, parents: List[int], queries: List[List[int]]) -> List[int]:
        B = 18
        n = len(parents)
        children = [[] for _ in range(n)]
        root = -1
        for i, p in enumerate(parents):
            if p == -1:
                root = i
            else:
                children[p].append(i)
        q_at = [[] for _ in range(n)]
        for i, (node, val) in enumerate(queries):
            q_at[node].append((val, i))

        ch, cnt = [[0, 0]], [0]                # 数组版 Trie，0 号节点当根

        def insert(x):
            cur = 0
            for b in range(B - 1, -1, -1):
                d = (x >> b) & 1
                if ch[cur][d] == 0:
                    ch.append([0, 0])
                    cnt.append(0)
                    ch[cur][d] = len(ch) - 1
                cur = ch[cur][d]
                cnt[cur] += 1

        def remove(x):
            cur = 0
            for b in range(B - 1, -1, -1):
                cur = ch[cur][(x >> b) & 1]
                cnt[cur] -= 1                  # 懒删除

        def query(v):
            cur, res = 0, 0
            for b in range(B - 1, -1, -1):
                d = (v >> b) & 1
                w = ch[cur][d ^ 1]
                if w and cnt[w] > 0:
                    res |= 1 << b
                    cur = w
                else:
                    cur = ch[cur][d]
            return res

        ans = [0] * len(queries)
        stack = [(root, 0)]                    # (节点, 相位)
        while stack:
            u, st = stack.pop()
            if st == 0:
                insert(u)
                for val, i in q_at[u]:
                    ans[i] = query(val)
                stack.append((u, 1))
                for c in reversed(children[u]):
                    stack.append((c, 0))
            else:
                remove(u)
        return ans
```

> 💡 **写法对照**：① 与每日篇的指针版（`Node*` + `new`）相比，数组版把孩子下标与计数摊平进两个 `vector`，实现更短、无内存管理负担，两者共享同一套引理 1/2 的正确性骨架；② 两版均已通过官方样例 1–2、自造边界样例（链、单点根、val = 200000、同节点多查询、val = 262143 极限）以及 200+ 组随机小树对拍暴力、$10^5$ 链状树压测；③ `enter` 相位内「先 `insert` 后回答」的顺序是正确性的硬依赖（引理 1），别为省一行调换次序。

## 8. 边界情况与易错点

1. **位深取 17（本题第一大 WA）**：$val_i$ 可达 $2 \times 10^5 > 2^{17} = 131072$，`bit17` 必须参与贪心，18 层是底线。取 17 层对 $val \ge 131072$ 的查询高位判定全错；取 19 层也对，只是顶层多一圈恒 0 的空转。
2. **幻影分支（本题第二大 WA）**：懒删除后节点存在但 `cnt == 0`。查询只判 `ch[cur][want] != 0` 不判 `cnt > 0`，会把回溯后已删空的分支当真，答案虚高或直接错。判定口诀：**存在 ≠ 有货**。
3. **递归爆栈**：树可退化为 $10^5$ 深的链，Python 默认递归上限 1000 必 `RecursionError`，C++ 默认栈也有溢出风险。迭代事件栈（`(u, state)` 两相位）是稳妥解，也是每日篇与本篇共同的写法。
4. **路径含两端**：路径包含 $node_i$ 与根。`enter` 相位必须**先 `insert(u)` 再回答**，漏掉自身则示例 2 的 q1（$15 \oplus 1 = 14$ 取在 node 自身）直接错成 $15 \oplus 7 = 8$。
5. **离线乱序写回**：DFS 回答次序与查询次序无关，`ans` 必须按原始下标 `idx` 落位；直接 `append` 会打乱输出顺序。同一节点多条查询、重复查询都要兼容——`qAt` 挂列表天然成立。
6. **`remove` 的配对性**：`exit` 只会删「曾经 `insert` 过的值」，位串路径必然存在，无需防御判空；若加了判空反而会掩盖「进出不配对」的逻辑错误。
7. **C++ 位运算安全**：`1 << b` 的 $b \le 17$，`res < 2^{18}`，`int` 无溢出；数组版 `reserve(2n)` 起步即可（节点数精算见 §4.4），不必按 $n \cdot B$ 过度预留。
8. **查询数为 1 也要走全树**：单条查询暴力上溯 $O(n) = 10^5$ 本可水过，但本题按离线框架统一处理即可，勿因「查询少」改回暴力——$n$ 与 $q$ 的最坏乘积才是出题人的照妖镜。

**延伸思考**：

- **在线版：可持久化 Trie**。离线回溯增删要求「同一时刻只有一条活跃路径」；若查询强制在线（DFS 完才知道 queries），可沿根到每个节点持久化一版本 Trie（新版只加一条路径，父版本共享），任意 $(node, val)$ 随时查询，空间 $O(n \log V)$。
- **树上任意两点路径**。把「根到 $u$」推广为「$u$ 到 $v$」：$\text{path}(u,v) = \text{path}(root,u) \cup \text{path}(root,v) \setminus \text{path}(root,\text{lca}) \times 2$，可持久化 Trie 上三版本计数相减，即可复用贪心（Trie 节点带 $O(1)$ 版本计数差），与「树上路径第 $k$ 小」的主席树做法同构。
- **max-XOR 不可加，增删是唯一出路**。树状数组/线段树能维护路径**和**（DFS 序 + 前缀分解），但异或最值不满足可加可减，无法前缀分解——「可持久化」与「回溯增删」是 Trie 题族唯二的路径查询形态，判断依据就是这一条。
- **DSU on tree（启发式合并）为何不适配**：小代价合并子树集合是它的强项，但 Trie 无法低成本合并（需逐元素重插）；树上路径查询中，回溯增删天然 $O(1)$ 均摊进出，比启发式合并更简单也更省。
