# LeetCode 设计食物评分系统 题解

## 1. 题目概述

- **标题 / 题号**：设计食物评分系统（#2353，medium）
- **链接**：https://leetcode.cn/problems/design-a-food-rating-system/
- **来源**：LeetCode 第 303 场周赛 Q3
- **难度**：中等
- **标签**：设计、哈希表、有序集合、堆（优先队列）

**题意**：维护一个食物评分系统，支持两种操作：`changeRating(food, newRating)` 把名为 `food` 的食物评分改为 `newRating`；`highestRated(cuisine)` 返回烹饪方式 `cuisine` 下评分最高的食物名，平局时返回**字典序最小**的名字。构造时给定 $n$ 个食物的名字、所属菜系与初始评分。

**约束**：

- $1 \le n \le 2 \times 10^4$，`foods` 中食物名**互不相同**
- $1 \le |\text{foods}[i]|, |\text{cuisines}[i]| \le 10$，均由小写英文字母组成
- $1 \le \text{ratings}[i] \le 10^8$
- `changeRating` 与 `highestRated` 总调用次数不超过 $q = 2 \times 10^4$
- 调用保证合法：`food` 一定在系统中，`cuisine` 至少含一种食物

## 2. 示例

**示例 1**（题面示例，覆盖「调分后换最高」与「平局按字典序」两个关键行为）

```text

[[["kimchi","miso","sushi","moussaka","ramen","bulgogi"],
  ["korean","japanese","japanese","greek","japanese","korean"],
  [9,12,8,15,14,7]],

解释：
  highestRated("korean")   → "kimchi"   kimchi 9 分 > bulgogi 7 分
  highestRated("japanese") → "ramen"    ramen 14 分，为 japanese 中最高
  changeRating("sushi",16)             sushi 8 → 16，反超
  highestRated("japanese") → "sushi"   sushi 16 分最高
  changeRating("ramen",16)             ramen 14 → 16，与 sushi 平局
  highestRated("japanese") → "ramen"   16 分平局，"ramen" 字典序 < "sushi"
```

## 3. 解题思路

### 3.1 暴力思路：每次查询全表扫描

把全部食物存进数组：`changeRating` 直接更新哈希 $O(1)$；`highestRated` 遍历所有 $n$ 个食物，筛出菜系匹配者，在「评分更大、平局名字更小」的维度上取最优，单次 $O(n)$ 次字符串比较。

总量 $O(nq)$：$n = q = 2 \times 10^4$ 时约 $4 \times 10^8$ 次量级的字符串比较，Python 必然超时，C++ 也毫无余量。它对「查询永远只发生在单个菜系内」这一结构毫无利用——全表扫描中绝大部分比较都花在无关菜系的食物上。

> ⚠️ 暴力的真正问题是**没有按查询维度（菜系）建立索引**。设计题的标准动作：查询走哪条维度，就为哪条维度建分组容器。

### 3.2 核心观察：复合排序键一统两种比较

![核心数据结构：两张真值哈希表 + 按菜系分组的有序容器](images/2353_data_structure_overview.svg)

两个观察把复杂度打下来：

**观察一（按菜系分组）**：`highestRated(cuisine)` 只关心菜系 `cuisine` 内的食物。为每个菜系单独维护一个容器，查询范围从「全表 $n$」缩到「该菜系的食物数」，不同菜系互不干扰。

**观察二（复合排序键）**：把食物 $f$ 在容器中的键取为二元组 $(-r_f, f)$：

- $-r_x < -r_y \iff r_x > r_y$——**取负把「评分越大越优」翻转成「越小越靠前」**；
- 平局时 $-r_x = -r_y$，比较落到第二维 $x$ 与 $y$ 的字典序——**恰好是题目的平局规则**。

于是「评分最高、平局名字最小」这个复合最优，就是容器中**字典序最小的二元组**：有序集合的 `*begin()`、小顶堆的堆顶，都是 $O(1)$ 直取——无须自定义比较器，也无须平局时二次扫描。

再配两张哈希表 `foodCuisine`（食物 → 菜系）与 `foodRating`（食物 → 当前评分），`changeRating` 就能在 $O(\log n)$ 内完成「删旧键、插新键」。

### 3.3 算法流程：有序集合 or 懒删除堆

![changeRating 的两条实现路线](images/2353_change_rating_flow.svg)

**路线 A（有序集合，C++ `std::set` / Python `SortedList`）**：

1. 初始化：三张表逐食物填充，向 `cuisineSet[c]` 插入 $(-r_i, f_i)$，共 $O(n \log n)$；
2. `changeRating(f, r)`：取出菜系 $c = \text{foodCuisine}[f]$，在 `cuisineSet[c]` 中 `erase((-old, f))`，更新 `foodRating[f] = r`，再 `insert((-r, f))`；
3. `highestRated(c)`：返回 `cuisineSet[c]` 首元素的 `second`。

**路线 B（懒删除堆，Python `heapq`）**：

Python 没有内置平衡树，但堆可以「只进不删」：

1. `changeRating(f, r)`：更新真值 `foodRating[f]`，向菜系堆 `push((-r, f))`——**旧条目不删，留在堆里当幽灵**；
2. `highestRated(c)`：循环检查堆顶 $(r', f')$（存的是 $-r'$），若 $r' \ne \text{foodRating}[f']$（记录的评分已过期）就 `pop` 丢弃；栈顶有效时其 `second` 即答案。

幽灵条目不污染正确性：过期判定只依赖 `foodRating` 这张「当前真值表」，与堆里堆了多少幽灵无关。

### 3.4 示例演算

![示例演算：japanese 菜系随两次调分的三次查询](images/2353_japanese_example_walkthrough.svg)

以示例 1 的 `japanese` 菜系走全程（懒删除堆视角，条目按 $(-r, f)$ 升序）：

| 操作 | japanese 堆（按序） | 备注 | 答案 |
|------|---------------------|------|------|
| 初始 | (−14,ramen), (−12,miso), (−8,sushi) | 全部有效 | `highestRated` → **ramen**(14) |
| changeRating(sushi,16) | (−16,sushi), (−14,ramen), (−12,miso), (−8,sushi) | 末位是幽灵 | → **sushi**(16) |
| changeRating(ramen,16) | (−16,ramen), (−16,sushi), (−12,miso), (−14,ramen), (−8,sushi) | 后两位是幽灵 | 平局 16 分，"ramen" < "sushi" → **ramen** |

最后一行是键设计的点睛之笔：$(-16,\text{"ramen"}) < (-16,\text{"sushi"})$ 由第二维决出，堆顶自动落在字典序更小的 ramen 上，平局规则零成本生效。

## 4. 算法细节

1. **三张表，一张真相**：`foodCuisine` / `foodRating` 两张哈希表 + 按菜系的容器（set 或堆）。`foodRating` 是唯一的「当前真值」来源，懒删除的过期判定完全依赖它。
2. **set 版 erase 必须用旧评分**：`erase({-foodRating[food], food})` 要在更新 `foodRating` **之前**执行；顺序写反（先更新再删）会删错键，集合里留下幽灵，后续查询返回过期答案。
3. **堆版先判等再入堆**：`newRating == foodRating[food]` 时直接返回，既避免堆膨胀，也让「每个食物恰有一个有效条目」这一不变式严格成立。
4. **C++ 堆版必须是小顶堆**：`priority_queue` 默认大顶堆，直接存 $(-r, f)$ 会取出评分**最低**的食物。必须声明 `priority_queue<pair<int,string>, vector<...>, greater<>>`；C++ 里更省心的选择是直接用 `set`。
5. **外层映射**：菜系 → 容器的外层用 `unordered_map`（Python 用 `defaultdict`，访问缺失菜系自动建空容器）；菜系名至多 10 字符，哈希开销可忽略。
6. **pair 比较的短路**：整数不同时一步出结果，只有平局才走字符串比较，实际开销远小于以字符串为主键的方案。

## 5. 正确性证明

以下对懒删除堆版给出完整证明（set 版是它的特例：删除即时发生、无幽灵条目，引理 2 平凡成立）。

**引理 1（键序即答案）**：容器中键 $(-r_f, f)$ 最小的食物 $f^\ast$，恰为「评分最高、平局字典序最小」的食物。

**证明**：$(-r_x, x) < (-r_y, y)$ 当且仅当 $-r_x < -r_y$（即 $r_x > r_y$，$x$ 评分严格更高），或 $-r_x = -r_y \wedge x < y$（评分平局，$x$ 名字字典序更小）——这正是题目的比较规则逐字对应到 pair 字典序；全序下最小元唯一，故引理成立。∎

**引理 2（有效条目不变式）**：任一时刻，对每个食物 $f$，堆中恰有一个以 $f$ 为名的**有效条目**（键中评分等于 $\text{foodRating}[f]$），其余以 $f$ 为名的条目均为**过期条目**。

**证明**：对操作序列归纳。初始时每个食物恰入堆一次且评分即当前评分，命题成立。设某操作前命题成立：

- `changeRating(f, r)`：先判等保证 $r \ne \text{foodRating}[f]$（相等时直接返回，堆不变）。更新 $\text{foodRating}[f] \leftarrow r$ 后 push $(-r, f)$：$f$ 的原有效条目（评分 $\ne r$）降级为过期，新条目成为唯一有效条目；其他食物的条目与其真值均未受影响。
- `highestRated` 只弹出满足「键中评分 $\ne \text{foodRating}$」的条目——按定义它们全是过期条目，有效条目永不会被弹出。

故不变式始终成立。∎

**定理（正确性）**：`highestRated(c)` 返回菜系 $c$ 中评分最高、平局字典序最小的食物。

**证明**：查询循环从堆顶开始，弹出所有过期条目直到栈顶 $t$ 有效（由引理 2，堆中至少含每食物一个有效条目，堆非空，循环必然终止）。分两点：

- **返回者是最小键**：堆顶恒为堆中全局最小键。反设存在有效条目 $s < t$：因 $s$ 已在堆中，$s$ 必在 $t$ 之前到达堆顶；而弹出条件只淘汰过期条目（引理 2），$s$ 有效、不可能被弹出，于是循环应在 $s$ 处停止并返回 $s$，与返回 $t$ 矛盾。故 $t$ 是全体条目（特别地，全体有效条目）的最小键。
- **最小键即答案**：菜系容器按 `foodCuisine` 分堆，堆中条目恰为该菜系的食物；由引理 2，有效条目的键中评分即当前评分；再由引理 1，最小键 $t$ 的 `second` 恰为题目所求。∎

**推论（set 版）**：set 中任意时刻恰好保存每食物一个当前键，`*begin()` 即最小键，由引理 1 立得正确性。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n + q)\log n)$。初始化 $n$ 次插入 $O(n \log n)$；set 版每次 `changeRating` 为一次 erase + 一次 insert 共 $O(\log n)$，`highestRated` 为 $O(1)$；堆版每次 `changeRating` 为一次 push $O(\log n)$，`highestRated` 的弹出总数被总插入数 $n + q$ 平摊，摊还 $O(\log n)$。$n, q \le 2 \times 10^4$ 时总操作量在 $10^6$ 量级，轻松通过。
- **空间复杂度**：set 版 $O(n)$；堆版 $O(n + q)$——每个幽灵条目对应一次有效的 `changeRating`，至多堆积 $q$ 个，总量仍在 $4 \times 10^4$ 量级。

## 7. 参考代码

### C++（有序集合版，首选）

```cpp
class FoodRatings {
    unordered_map<string, string> foodCuisine_;                // 食物 → 菜系
    unordered_map<string, int> foodRating_;                   // 食物 → 当前评分（真值表）
    unordered_map<string, set<pair<int, string>>> cuisineSet_; // 菜系 → (-评分, 名字)

public:
    FoodRatings(vector<string>& foods, vector<string>& cuisines, vector<int>& ratings) {
        int n = foods.size();
        for (int i = 0; i < n; ++i) {
            foodCuisine_[foods[i]] = cuisines[i];
            foodRating_[foods[i]] = ratings[i];
            cuisineSet_[cuisines[i]].insert({-ratings[i], foods[i]});
        }
    }

    void changeRating(string food, int newRating) {
        auto& s = cuisineSet_[foodCuisine_[food]];
        s.erase({-foodRating_[food], food});    // 用旧评分构造键，删旧条目
        foodRating_[food] = newRating;
        s.insert({-newRating, food});
    }

    string highestRated(string cuisine) {
        return cuisineSet_[cuisine].begin()->second;  // 首元素即答案
    }
};
```

### C++（懒删除堆版）

```cpp
class FoodRatings {
    using Entry = pair<int, string>;
    unordered_map<string, string> foodCuisine_;
    unordered_map<string, int> foodRating_;
    unordered_map<string, priority_queue<Entry, vector<Entry>, greater<Entry>>> cuisineHeap_; // 小顶堆

public:
    FoodRatings(vector<string>& foods, vector<string>& cuisines, vector<int>& ratings) {
        int n = foods.size();
        for (int i = 0; i < n; ++i) {
            foodCuisine_[foods[i]] = cuisines[i];
            foodRating_[foods[i]] = ratings[i];
            cuisineHeap_[cuisines[i]].push({-ratings[i], foods[i]});
        }
    }

    void changeRating(string food, int newRating) {
        if (foodRating_[food] == newRating) return;      // 无变化，不产生冗余条目
        foodRating_[food] = newRating;
        cuisineHeap_[foodCuisine_[food]].push({-newRating, food});  // 旧条目留作幽灵
    }

    string highestRated(string cuisine) {
        auto& h = cuisineHeap_[cuisine];
        while (h.top().first != -foodRating_[h.top().second])
            h.pop();                                      // 过期条目：记录评分 ≠ 当前评分
        return h.top().second;
    }
};
```

### Python（懒删除堆版）

```python
class FoodRatings:
    def __init__(self, foods: List[str], cuisines: List[str], ratings: List[int]):
        self.food_cuisine = {}                   # 食物 → 菜系
        self.food_rating = {}                    # 食物 → 当前评分（唯一的真值表）
        self.cuisine_heap = defaultdict(list)    # 菜系 → 小顶堆 [(-评分, 名字)]
        for f, c, r in zip(foods, cuisines, ratings):
            self.food_cuisine[f] = c
            self.food_rating[f] = r
            heapq.heappush(self.cuisine_heap[c], (-r, f))

    def changeRating(self, food: str, newRating: int) -> None:
        if self.food_rating[food] == newRating:  # 无变化，直接返回
            return
        self.food_rating[food] = newRating
        heapq.heappush(self.cuisine_heap[self.food_cuisine[food]], (-newRating, food))

    def highestRated(self, cuisine: str) -> str:
        h = self.cuisine_heap[cuisine]
        while -h[0][0] != self.food_rating[h[0][1]]:
            heapq.heappop(h)                     # 过期条目：记录评分已不是当前值
        return h[0][1]
```

### Python（SortedList 版，可选）

```python
from sortedcontainers import SortedList

class FoodRatings:
    def __init__(self, foods: List[str], cuisines: List[str], ratings: List[int]):
        self.fc, self.fr = {}, {}
        self.cs = defaultdict(SortedList)        # 菜系 → (-评分, 名字) 升序列表
        for f, c, r in zip(foods, cuisines, ratings):
            self.fc[f], self.fr[f] = c, r
            self.cs[c].add((-r, f))

    def changeRating(self, food: str, newRating: int) -> None:
        s = self.cs[self.fc[food]]
        s.remove((-self.fr[food], food))        # 先用旧评分删旧键
        self.fr[food] = newRating
        s.add((-newRating, food))

    def highestRated(self, cuisine: str) -> str:
        return self.cs[cuisine][0][1]
```

## 8. 边界情况与易错点

1. **erase 必须用旧评分**：set 版最典型的 bug 是先更新 `foodRating` 再 `erase`，删错键后集合残留幽灵，后续查询返回过期答案。删旧键必须发生在更新真值表之前。
2. **C++ 堆版的小顶堆声明**：`priority_queue` 默认大顶堆，存 $(-r, f)$ 不加 `greater<>` 会取出评分**最低**的食物；单元素菜系或恰好平局的样例可能碰巧不报错，极难排查。
3. **懒删除弹出条件的负号**：堆中存的是 $-r$，判定应写 `h.top().first != -foodRating_[...]`；符号写反会把所有有效条目当过期弹光，下次查询访问空堆直接 RE。
4. **`newRating` 可等可降**：相等时堆版先判等返回（不变式更干净、也省内存）；调低时 $-r$ 变大、条目在容器中后移，逻辑无须任何特判。
5. **平局规则藏在第二维**：若键只放评分、平局时再在菜系内线性找最小名字，单次查询退化为 $O(n)$，最坏回到 $O(nq)$。$(-r, f)$ 复合键让平局由容器的字典序比较自动裁决。
6. **食物名互不相同**：这是 `foodRating` / `foodCuisine` 单值哈希的前提；若变体题允许重名，须改为「名字 + 菜系」复合键或按食物编号索引。
7. **评分上界 $10^8$**：`int` 足够，取负后的 $-10^8$ 也在 `int` 范围内，无须 `long long`。

**延伸思考**：

- **操作频率失衡的优化**：若 `changeRating` 极多而 `highestRated` 极少，可为每个菜系打脏标记，查询时才一次性重建该菜系容器（$O(k \log k)$，$k$ 为菜系大小），把维护成本从每次 $O(\log n)$ 摊成每次 $O(1)$。
- **评分改为浮点**：pair 键照用，但 $-r$ 须处理精度与 NaN；更稳妥的做法是先把评分离散化再入容器。
- **支持撤销/回滚**：set 不支持高效回滚，可改离线按时间分治（CDQ 分治）或可持久化结构；懒删除堆依赖「真值单向前进」，同样需要额外的版本号机制。
- **多关键字扩展**：若平局规则改为「名字字典序最大」或引入第三关键字，只需把键扩成 $(-r, \text{翻转的名字序}, \dots)$ 的多元组，容器选型与正确性证明原样照搬。
