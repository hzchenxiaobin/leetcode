# LeetCode 第一个出现两次的字母 题解

## 1. 题目概述

- **标题 / 题号**：第一个出现两次的字母（#2351，easy）
- **链接**：https://leetcode.cn/problems/first-letter-to-appear-twice/
- **来源**：LeetCode 第 303 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、位运算、计数

**题意**：给定一个仅由小写英文字母组成的字符串 `s`，返回**第一个出现两次**的字母。「第一个」的判据是**第二次出现的下标**：若字母 `a` 的第二次出现比 `b` 的第二次出现更靠前，则认为 `a` 在 `b` 之前出现两次。题目保证 `s` 中至少存在一个出现两次的字母。

**约束**：

- $2 \le \text{s.length} \le 100$
- `s` 仅由小写英文字母组成
- `s` 包含至少一个出现两次的字母

## 2. 示例

**示例 1**

```text
输入：s = "abccbaacz"
输出："c"
解释：
  'a' 的出现下标：0、5、6；'b'：1、4；'c'：2、3、7；'z'：8。
  'c' 的第二次出现在下标 3，是所有字母中最早的，故返回 'c'。
```

**示例 2**

```text
输入：s = "abcdd"
输出："d"
解释：只有 'd' 出现两次，其第二次出现在下标 4。
```

**补充示例 3**（覆盖「首字符不一定是答案」的关键情况）

```text
输入：s = "abba"
输出："b"
解释：'b' 的第二次出现在下标 2，早于 'a' 的第二次出现（下标 3），故答案是 'b' 而不是首字符 'a'。
```

## 3. 解题思路

### 3.1 暴力思路：逐位回查 + 一个经典错误思路

最朴素的模拟：对每个下标 `i`，向前回查 `s[0..i-1]` 中是否出现过 `s[i]`：

```text
for i in 0..n-1:
    for j in 0..i-1:
        if s[j] == s[i]: return s[i]
```

正确性没有问题，但每个 `i` 都回扫 $O(i)$，总计 $O(n^2)$。本题 $n \le 100$ 完全能过，可它的低效根源在于「**每次回查都丢弃历史**」——判断「`s[i]` 见过没有」本可 $O(1)$ 回答。

> ⚠️ **一个更危险的错误思路**：先统计全串频次，再从左到右找**第一个频次 ≥ 2 的字符**。它在示例 1 上就会翻车：`'a'` 的频次是 3，首字符 `'a'` 频次就 ≥ 2，错答 `'a'`；而正确答案是 `'c'`——`'c'` 的**第二次出现**（下标 3）早于 `'a'` 的第二次出现（下标 5）。**「第一个出现两次」比较的是第二次出现的位置，不是第一次**。

### 3.2 核心观察：首个「已见」字符即答案

![核心判据：比较的是第二次出现的下标，而非第一次](images/2351_second_occurrence_concept.svg)

维护一个**已见字符集合** `seen`，从左到右遍历 `s`：

- 若 `s[i]` 已在 `seen` 中，说明此刻恰是 `s[i]` 的**第二次出现**；又因为扫描是逐位进行的，此前没有任何字符第二次出现（否则早就停了），所以 `s[i]` 的第二次出现下标是**所有字母中最小的** → 立即返回 `s[i]`；
- 否则把 `s[i]` 登记进 `seen`，继续右扫。

> 💡 **扫描顺序与「第二次出现下标」的单调性天然对齐**：第一个撞见的重复，必然就是最早完成的「二次出现」。严格论证见 §5。

### 3.3 算法流程

![算法流程：单遍扫描，命中即返回](images/2351_scan_flow.svg)

单重循环，每个字符至多访问一次，命中即提前返回；最坏情况（答案靠后）才遍历全串。由**鸽巢原理**，26 个字母 + 保证有重复 ⟹ 前 27 个字符内必现重复，循环实际至多跑 $\min(n, 27)$ 次。

### 3.4 示例演算

![示例演算：abccbaacz 逐步执行](images/2351_example_walkthrough.svg)

以 `s = "abccbaacz"` 为例，`seen` 随扫描增长：

| i | s[i] | seen（处理前） | 命中？ | 动作 |
|---|------|----------------|--------|------|
| 0 | a    | ∅              | 否     | seen = {a} |
| 1 | b    | {a}            | 否     | seen = {a, b} |
| 2 | c    | {a, b}         | 否     | seen = {a, b, c} |
| 3 | c    | {a, b, c}      | **是** | 返回 `'c'` |

下标 3 处 `'c'` 第二次出现，正是所有字母中第二次出现下标最小者（'b' 在 4、'a' 在 5），故 `'c'` 为答案，`i = 4..8` 无需再看。

## 4. 算法细节

1. **先查后插**：每步必须先判断 `c ∈ seen` 再执行 `seen.add(c)`。若顺序颠倒，字符总能在集合里查到自己，恒在首字符处命中。
2. **`seen` 的三种实现**（字符集仅 26 个小写字母）：
   - `unordered_set<char>` / `set`：通用写法，不依赖字符集假设，单次操作均摊 $O(1)$；
   - 定长数组 `int seen[26]`：下标 `c - 'a'`，无哈希/再散列开销，小写字母集下常数最小；
   - **26 位整数位掩码**：`mask` 的第 $k$ 位表示字母 `'a'+k` 是否已见，查重 `mask & b`、登记 `mask |= b`（$b = 1 \ll (c - a)$），空间压成一个整数。
3. **提前返回**：命中即 `return`，不扫冗余后缀；由鸽巢原理，实际迭代次数有常数上界 27，与 $n$ 无关。
4. **兜底返回值**：题目保证至少一个重复字母，循环内必然 `return`；但函数签名要求闭合控制流，末尾给哨兵值（C++ 返回 `' '`、Python 返回 `""`），该分支不可达。

## 5. 正确性证明

记 $\text{occ}(x)$ 为字母 $x$ 在 `s` 中的出现下标集合；对满足 $|\text{occ}(x)| \ge 2$ 的字母，记 $\text{second}(x)$ 为其第二次出现的下标。由约束，这样的字母存在；按题意，所求即 $\text{second}(\cdot)$ 最小的那个字母。

**引理 1（首个命中位置 = 第二次出现下标的全局最小）**：从左到右扫描，在首个满足「`s[i]` 已在 `s[0..i-1]` 中出现」的下标 $k$ 处停止，则

$$k = \min_{|\text{occ}(x)| \ge 2} \text{second}(x)$$

**证明**：

- （$\ge$）在 $k$ 处命中意味着 `s[k]` 在前缀中已出现一次，故 $k$ 是字母 `s[k]` 的第二次出现下标，即 $k$ 属于 $\{\text{second}(x)\}$ 这一集合，从而 $k \ge \min_x \text{second}(x)$。
- （$\le$）设 $k^* = \min \text{second}(x)$，取达到者 $x^*$，则 $s[k^*] = x^*$。对任意 $i < k^*$：若 `s[i]` 已在 `s[0..i-1]` 中出现，则 $i$ 是某字母的第二次出现下标且 $i < k^*$，与 $k^*$ 的最小性矛盾，故扫描在前 $k^* - 1$ 个位置均不命中。而在 $k^*$ 处，$x^*$ 的第一次出现必在其第二次出现之前，即已落在 `s[0..k*-1]` 中，故命中。于是首个命中位置恰为 $k^*$。∎

**定理**：算法返回的字符恰为题目所求的「第一个出现两次的字母」。

**证明**：按题目定义，「`a` 在 `b` 之前出现两次」当且仅当 $\text{second}(a) < \text{second}(b)$，故所求字母即 $\text{second}(\cdot)$ 最小者。由引理 1，算法恰在 $k^*$ 处停止并返回 $s[k^*]$，而 $s[k^*]$ 正是 $\text{second}$ 取到最小值的字母。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单遍扫描，`seen` 的查询与插入均 $O(1)$（集合为均摊、数组与位掩码为严格常数）。由鸽巢原理，实际迭代至多 $\min(n, 27)$ 次。
- **空间复杂度**：$O(\min(|\Sigma|, n)) = O(26) = O(1)$。`seen` 至多登记 26 个小写字母；位掩码实现则压缩为单个整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    char repeatedCharacter(string s) {
        unordered_set<char> seen;
        for (char c : s) {
            if (seen.count(c)) return c; // 首命中即答案
            seen.insert(c);
        }
        return ' '; // 题目保证有重复，此行仅为闭合控制流
    }
};
```

字符集固定为 26 个小写字母，可用位掩码省去哈希开销：

```cpp
class Solution {
public:
    char repeatedCharacter(string s) {
        int mask = 0;
        for (char c : s) {
            int b = 1 << (c - 'a');
            if (mask & b) return c; // 该位已亮：第二次出现
            mask |= b;
        }
        return ' ';
    }
};
```

### Python

```python
class Solution:
    def repeatedCharacter(self, s: str) -> str:
        seen = set()
        for c in s:
            if c in seen:
                return c  # 首命中即答案
            seen.add(c)
        return ""  # 不可达，兜底闭合控制流
```

位掩码写法：

```python
class Solution:
    def repeatedCharacter(self, s: str) -> str:
        mask = 0
        for c in s:
            b = 1 << (ord(c) - 97)  # ord('a') == 97
            if mask & b:
                return c
            mask |= b
        return ""
```

## 8. 边界情况与易错点

1. **频次两遍法陷阱（本题最大的坑）**：「频次 ≥ 2 的最左字符」≠ 答案。示例 1 中该方法错答 `'a'`，而正确答案是 `'c'`。必须按「第二次出现下标最小」判定。
2. **先插后查的顺序错误**：若先 `seen.add(c)` 再判断 `c in seen`，每个字符都能查到自己，恒在首字符处返回。
3. **最小输入**：$n = 2$，如 `"aa"`，第二次循环即命中返回 `'a'`；`seen` 初始为空不需特判。
4. **接口类型差异**：C++ 签名是 `char repeatedCharacter(string s)` 返回**单个字符**；Python 返回 `str`。注意循环后的兜底返回值（`' '` / `""`）虽然不可达，但必须写以通过编译/类型检查。
5. **鸽巢上界**：答案必在前 27 个字符内产生；即便约束放宽到 $n = 10^6$，循环仍是常数次迭代，提前返回不是可有可无的优化，而是复杂度的本质保障。

**延伸思考**：

- 若字符集是任意 Unicode（不止 26 个小写字母），哪些实现仍可用？——哈希集合仍 $O(n)$；定长数组与 26 位掩码失效，体现「按字符集规模选数据结构」。
- 若要求「第一个出现 $k$ 次的字母」怎么改？——把 `seen` 换成计数数组 `cnt`，命中条件改为 `cnt[c] == k - 1` 后自增；「第 $r$ 次出现」同样满足一旦成立永成立的单调性，仍可一遍在线判定。
