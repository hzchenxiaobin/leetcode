# LeetCode 优质数对的数目 题解

## 1. 题目概述

- **标题 / 题号**：优质数对的数目（#2354，hard）
- **链接**：https://leetcode.cn/problems/number-of-excellent-pairs/
- **来源**：LeetCode 第 303 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、哈希表、二分查找

**题意**：给定正整数数组 `nums` 和正整数 $k$。数对 $(num_1, num_2)$ 是**优质数对**，当且仅当 $num_1$、$num_2$ 都在数组中出现，且 $num_1~\text{OR}~num_2$ 与 $num_1~\text{AND}~num_2$ 的二进制表示中 1 的位数之**和**大于等于 $k$。返回**不同**优质数对的数目——数对按**值**区分：$(a,b)$ 与 $(c,d)$ 不同当且仅当 $a \ne c$ 或 $b \ne d$。

**约束**：

- $1 \le n \le 10^5$
- $1 \le nums[i] \le 10^9$（故 $nums[i] < 2^{30}$，popcount 至多 30）
- $1 \le k \le 60$

> 💡 **读题关键**：三条信息决定了解法形态——①「按值区分数对」意味着**重复元素只算一次**，先去重；②判定条件涉及 OR 与 AND 两个位运算结果的 popcount 之和，暗示存在按位拆解的恒等式；③ $k \le 60 = 30 + 30$ 恰好是两个 30 位数 popcount 之和的上界，暗示把问题压缩到「popcount 值」这一维度（至多 31 种）。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,1], k = 3
输出：5

解释：去重后候选值 {1, 2, 3}，5 个优质数对为
  (3, 3)：pc(3 OR 3) + pc(3 AND 3) = 2 + 2 = 4 ≥ 3
  (2, 3) 与 (3, 2)：pc(2|3) + pc(2&3) = 2 + 1 = 3 ≥ 3
  (1, 3) 与 (3, 1)：pc(1|3) + pc(1&3) = 2 + 1 = 3 ≥ 3
注意 (1, 2)、(2, 1)、(1, 1)、(2, 2) 均不满足；第二个 1 不产生新数对。
```

**示例 2**

```text
输入：nums = [5,1,1], k = 10
输出：0

解释：候选值 {5, 1}，pc(5) = 2、pc(1) = 1，任意数对的位数和至多 2 + 2 = 4 < 10，
      不存在优质数对。
```

**补充示例 3（自造，覆盖「全部相同 + 重复元素」的极端情况）**

```text
输入：nums = [7,7,7,7], k = 3
输出：1

解释：4 个 7 去重后只剩一个值 7 = (111)₂，唯一候选数对是 (7, 7)：
      pc(7|7) + pc(7&7) = 3 + 3 = 6 ≥ 3，是优质数对。
      但所有元素值相同，不同的数对只有 (7,7) 这一个 → 答案 1，而非 4 × 4 = 16。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有值对

去重得到候选值集合 $S$（大小 $D \le n$），枚举全部有序值对 $(x, y) \in S \times S$，逐一计算 $pc(x~|~y) + pc(x~\&~y)$ 并与 $k$ 比较。

时间复杂度 $O(D^2)$。$n$ 可达 $10^5$，$D^2$ 最坏 $10^{10}$ 次位运算与 popcount，远超时限。它的浪费在于：判定一个数对是否优质，根本**不需要知道 $x$、$y$ 的具体二进制表示**，而暴力却为每个数对重新扫描 30 个二进制位。

> ⚠️ 暴力的真正问题是**没有提取判定条件的本质**。位运算题的通用套路：条件是按位表达的，就先做**按位拆解**，看每位贡献是否相互独立。

### 3.2 核心观察：OR 与 AND 的 popcount 之和可拆

![核心恒等式：按位拆解 OR 与 AND](images/2354_bit_identity_concept.svg)

对任意两个非负整数 $a, b$，有恒等式：

$$
\operatorname{pc}(a \mid b) + \operatorname{pc}(a \,\&\, b) = \operatorname{pc}(a) + \operatorname{pc}(b)
$$

其中 $\operatorname{pc}(x)$ 表示 $x$ 二进制表示中 1 的个数。**逐位验证**：任取一个二进制位 $i$，设 $a_i, b_i \in \{0, 1\}$：

| $(a_i, b_i)$ | OR 位 | AND 位 | OR+AND | $a_i + b_i$ |
|:---:|:---:|:---:|:---:|:---:|
| $(1, 1)$ | 1 | 1 | 2 | 2 |
| $(1, 0)$ | 1 | 0 | 1 | 1 |
| $(0, 1)$ | 1 | 0 | 1 | 1 |
| $(0, 0)$ | 0 | 0 | 0 | 0 |

四种情况下「OR 位 + AND 位」都恰好等于 $a_i + b_i$（直观理解：**OR 数并集、AND 数交集，重叠的位被数两次，正好等价于各自都数一次**）。对所有位求和即得恒等式。

于是题目条件被改写为：

$$
\operatorname{pc}(num_1 \mid num_2) + \operatorname{pc}(num_1 \,\&\, num_2) \ge k
\iff
\operatorname{pc}(num_1) + \operatorname{pc}(num_2) \ge k
$$

**数对是否优质，只取决于两个数各自 1 的个数**，与它们具体是哪些位为 1 完全无关。

### 3.3 算法流程：按 popcount 分桶计数

![算法流程：去重、分桶、枚举桶对](images/2354_bucket_counting_flow.svg)

1. **去重**：数对按值计数，`nums` 转入哈希集合 $S$。
2. **分桶**：统计 $cnt[c]$ = 候选值中 $\operatorname{pc}(x) = c$ 的个数。由 $nums[i] < 2^{30}$ 知 $c \in [1, 30]$，桶只有 31 个。
3. **枚举桶对**：答案为
   $$
   ans = \sum_{c_1 + c_2 \ge k} cnt[c_1] \cdot cnt[c_2]
   $$
   双重循环 $O(31^2) = O(961)$，可忽略不计。

> 💡 **两种等价写法**：
>
> - **后缀和**：预处理 $suf[c] = \sum_{c' \ge c} cnt[c']$，则 $ans = \sum_c cnt[c] \cdot suf[\max(k - c, 0)]$，$O(31)$。
> - **排序 + 二分**（官方标签中 Binary Search 的由来）：把所有候选值的 popcount 排成数组，对每个 $c_1 = \operatorname{pc}(x)$ 二分查找有多少个 $c_2 \ge k - c_1$，$O(D \log D)$。
>
> 三种写法的瓶颈都在第 1、2 步的 $O(n)$ 或 $O(n \log n)$，任选其一即可。

### 3.4 示例演算

![示例 1 的分桶与计数过程](images/2354_example_walkthrough.svg)

以示例 1 走一遍完整流程（$nums = [1,2,3,1]$，$k = 3$）：

1. 去重：$\{1, 2, 3\}$；
2. 分桶：$\operatorname{pc}(1) = \operatorname{pc}(2) = 1$，$\operatorname{pc}(3) = 2$，故 $cnt[1] = 2$、$cnt[2] = 1$；
3. 枚举桶对（有序）：$(1,2)$ 与 $(2,1)$ 贡献 $2 \times (cnt[1] \cdot cnt[2]) = 4$，$(2,2)$ 贡献 $cnt[2]^2 = 1$，$(1,1)$ 因 $1 + 1 = 2 < 3$ 排除；
4. 合计 $4 + 1 = 5$，与预期一致。这 5 个数对正是 $(1,3), (3,1), (2,3), (3,2), (3,3)$。

## 4. 算法细节

1. **去重容器**：C++ 用 `unordered_set`（$O(n)$ 均摊）；也可先排序再 `unique`（$O(n \log n)$，常数更小）。Python 直接 `set(nums)`。
2. **popcount 计算**：C++ 用 `__builtin_popcount(x)`（或 C++20 的 `std::popcount`）；Python 用 `bin(x).count('1')` 或 3.10+ 的 `x.bit_count()`。$nums[i] \le 10^9 < 2^{30}$，结果落在 $[1, 30]$。
3. **桶数组大小**：开 32（下标 $0 \sim 31$）留出余量，避免边界讨论。
4. **枚举的下界 clamp**：对每个 $c_1$，$c_2$ 的起点为 $\max(k - c_1, 0)$——$k - c_1$ 可能为负（如 $k = 1$ 时任何数对都优质），不 clamp 会数组越界；$k - c_1 > 31$ 时该轮为空区间，自然跳过。
5. **乘积用 64 位**：$cnt[c_1] \cdot cnt[c_2]$ 可达 $10^5 \times 10^5 = 10^{10}$，C++ 中桶数组直接声明为 `long long`，避免 int 相乘溢出。
6. **答案上界**：$D \le 10^5$，有序值对总数 $D^2 \le 10^{10}$，超过 `int` 范围，返回类型必须是 64 位（本题函数签名即 `long long`）。

## 5. 正确性证明

**引理 1**（按位恒等式）：对任意非负整数 $a, b$ 与任意二进制位 $i$，有 $(a \mid b)_i + (a \,\&\, b)_i = a_i + b_i$。

**证明**：按 $(a_i, b_i)$ 的取值分四类验证。

- $(1,1)$：OR 位为 1，AND 位为 1，左边 $= 2$，右边 $= 1 + 1 = 2$；
- $(1,0)$ 或 $(0,1)$：OR 位为 1，AND 位为 0，左边 $= 1$，右边 $= 1$；
- $(0,0)$：OR 位、AND 位均为 0，左边 $= 0$，右边 $= 0$。

四类均相等。∎

**推论 1**：$\operatorname{pc}(a \mid b) + \operatorname{pc}(a \,\&\, b) = \operatorname{pc}(a) + \operatorname{pc}(b)$。

**证明**：$\operatorname{pc}$ 是对所有二进制位求和，把引理 1 对 $i = 0, 1, 2, \dots$ 逐位相加即得。∎

**引理 2**（去重等价）：设 $S$ 为 `nums` 的去重值集合，则题目所求答案等于
$$
\left| \{ (x, y) \in S \times S : \operatorname{pc}(x) + \operatorname{pc}(y) \ge k \} \right|.
$$

**证明**：一方面，优质数对要求 $num_1, num_2$ 都在数组中出现，即 $num_1, num_2 \in S$。另一方面，题目以「$(a,b)$ 与 $(c,d)$ 不同当且仅当 $a \ne c$ 或 $b \ne d$」定义数对，即数对由**值**唯一决定，与下标、出现次数无关；由推论 1，判定条件 $\operatorname{pc}(num_1 \mid num_2) + \operatorname{pc}(num_1 \,\&\, num_2) \ge k$ 等价于 $\operatorname{pc}(num_1) + \operatorname{pc}(num_2) \ge k$。故答案恰为上述集合的大小。∎

**引理 3**（分桶计数）：设 $cnt[c] = |\{ x \in S : \operatorname{pc}(x) = c \}|$，则引理 2 中的答案等于 $\sum_{c_1 + c_2 \ge k} cnt[c_1] \cdot cnt[c_2]$。

**证明**：把 $S \times S$ 中的有序对按 $(\operatorname{pc}(x), \operatorname{pc}(y))$ 分类。popcount 为 $c_1$ 的值有 $cnt[c_1]$ 个、为 $c_2$ 的值有 $cnt[c_2]$ 个，故满足 $\operatorname{pc}(x) = c_1, \operatorname{pc}(y) = c_2$ 的有序对恰有 $cnt[c_1] \cdot cnt[c_2]$ 个；其中满足条件的那些恰好对应 $c_1 + c_2 \ge k$。对不同 $(c_1, c_2)$ 分类互斥且完备，求和即得。∎

**定理**：上述算法返回不同优质数对的数目。

**证明**：算法第一步构造 $S$，第二步构造 $cnt[\cdot]$，第三步计算 $\sum_{c_1 + c_2 \ge k} cnt[c_1] \cdot cnt[c_2]$。由引理 3 该值等于引理 2 中集合的大小，再由引理 2 与推论 1，它就是题目定义的不同优质数对数目。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$（哈希去重 + 每个数一次 popcount + $O(31^2)$ 桶对枚举；若用排序去重或排序+二分写法，则为 $O(n \log n)$）。
  - 去重：哈希集合 $O(n)$ 均摊；
  - 分桶：每个值一次 popcount，$O(30n)$ 的位运算总量可视为 $O(n)$；
  - 计数：双重循环 $31 \times 31 = 961$ 次，常数级。
- **空间复杂度**：$O(n)$（哈希集合存储去重值）+ $O(31)$ 桶数组。若排序去重可原地做到 $O(1)$ 额外空间（不计排序栈）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long countExcellentPairs(vector<int>& nums, int k) {
        // ① 去重：数对按值计数，重复元素只算一次
        unordered_set<int> s(nums.begin(), nums.end());

        // ② 按 popcount 分桶（nums[i] < 2^30，pc ∈ [1,30]，开 32 留余量）
        long long cnt[32] = {0};
        for (int x : s) {
            cnt[__builtin_popcount(x)]++;
        }

        // ③ 枚举满足 c1 + c2 >= k 的有序桶对
        long long ans = 0;
        for (int c1 = 0; c1 <= 31; ++c1) {
            for (int c2 = max(k - c1, 0); c2 <= 31; ++c2) {
                ans += cnt[c1] * cnt[c2];
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countExcellentPairs(self, nums: List[int], k: int) -> int:
        # ① 去重 + ② 按 popcount 分桶
        cnt = [0] * 32
        for x in set(nums):
            cnt[bin(x).count('1')] += 1   # 3.10+ 可写 x.bit_count()

        # ③ 枚举满足 c1 + c2 >= k 的有序桶对
        return sum(
            cnt[c1] * cnt[c2]
            for c1 in range(32)
            for c2 in range(max(k - c1, 0), 32)
        )
```

## 8. 边界情况与易错点

1. **忘记去重（本题最大陷阱）**
   - 数对按值区分，$[7,7,7,7]$ 的答案是 1 而不是 16。若不去重，同值数对会被重复计入，且去重与否还直接影响桶计数的正确性。
2. **数对是有序的**
   - $(a, b)$ 与 $(b, a)$ 是两个数对（$a \ne b$ 时）。$cnt[c_1] \cdot cnt[c_2]$ 的双重循环天然覆盖两个方向，**不要**误除以 2，也无需额外枚举对称情况。
3. **整数溢出**
   - 答案上界 $D^2 \le 10^{10}$，超过 32 位 int；C++ 中桶数组与答案都要用 `long long`。`cnt[c1] * cnt[c2]` 若用 int 相乘同样溢出，桶声明为 `long long` 一并解决。
4. **二分起点为负**
   - 枚举 $c_2$ 的起点 $\max(k - c_1, 0)$ 必须 clamp：$k = 1$ 时 $k - c_1$ 为负，直接作下标会越界。后缀和写法同理。
5. **popcount 的位宽上界**
   - $nums[i] \le 10^9 < 2^{30}$，桶开 32 即可。若把本题改到 $10^{18}$，桶需开 64——桶数 = 值域位宽，不是固定常数。
6. **答案可能为 0**
   - 示例 2：$k$ 超过任何可能的位数和（上界 $30 + 30 = 60$）时答案为 0，算法自然返回 0，无须特判。
7. **Python 版本兼容**
   - `int.bit_count()` 是 Python 3.10 引入的；低版本环境用 `bin(x).count('1')`。

**延伸思考**：

- 若数对改为**按下标**计数（即重复元素各自参与配对），算法如何变？——只须跳过去重，每个元素直接入桶 $cnt[\operatorname{pc}(nums[i])]++$，其余不变。
- 若条件改为 $\operatorname{pc}(num_1 \oplus num_2) + \operatorname{pc}(num_1 \,\&\, num_2) \ge k$ 呢？逐位验证：$(1,1)$ 时贡献 $0 + 1 = 1$（而非 $2$），其余情况与原恒等式相同——此时总和等于 $\operatorname{pc}(num_1 \mid num_2)$，**不再只依赖各自的 popcount**（还依赖两者 1 位的重叠方式），分桶技巧失效，需按值域做子集 DP（SOS）之类的手段。
- 若求的是**无序**数对（$(a,b)$ 与 $(b,a)$ 视为同一个）？——用 $cnt[c_1] \cdot cnt[c_2]$（$c_1 < c_2$）加上 $\binom{cnt[c]}{2}$（同桶，$c_1 = c_2$，且需排除 $a = b$ 的情形按题意细究）。
- 更一般的经验：**位运算条件的化简优先按位拆解验证**——OR/AND/XOR 三者与「各自 popcount」的关系（$pc(a|b) = pc(a) + pc(b) - pc(a\&b)$、$pc(a \oplus b) = pc(a) + pc(b) - 2pc(a\&b)$）是常驻工具箱的恒等式。
