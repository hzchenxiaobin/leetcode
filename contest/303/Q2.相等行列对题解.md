# LeetCode 相等行列对 题解

## 1. 题目概述

- **标题 / 题号**：相等行列对（#2352，medium）
- **链接**：https://leetcode.cn/problems/equal-row-and-column-pairs/
- **来源**：LeetCode 第 303 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、矩阵、模拟

**题意**：给定一个下标从 0 开始、大小为 $n \times n$ 的整数矩阵 `grid`，返回满足「第 $R_i$ 行与第 $C_j$ 列相等」的行列对 $(R_i, C_j)$ 的数目。「相等」指行和列以相同的顺序包含相同的元素，即作为**序列逐下标对应相等**。

**约束**：

- $n = \text{grid.length} = \text{grid}[i].\text{length}$，$1 \le n \le 200$
- $1 \le \text{grid}[i][j] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：grid = [[3,2,1],[1,7,6],[2,7,7]]
输出：1
解释：存在一对相等行列对：
  - (第 2 行，第 1 列)：[2,7,7]
```

**示例 2**（覆盖「重复行导致一对多」的关键情况）

```text
输入：grid = [[3,1,2,2],[1,4,4,5],[2,4,2,2],[2,4,2,2]]
输出：3
解释：存在三对相等行列对：
  - (第 0 行，第 0 列)：[3,1,2,2]
  - (第 2 行，第 2 列)：[2,4,2,2]
  - (第 3 行，第 2 列)：[2,4,2,2]
```

**补充示例 3**（最小规模 $n = 1$）

```text
输入：grid = [[7]]
输出：1
解释：唯一的行 [7] 与唯一的列 [7] 相等，恰有 1 对。
```

## 3. 解题思路

### 3.1 暴力思路：枚举全部行列对，逐位比较

最朴素的模拟：枚举所有行列对 $(i, j)$ 共 $n^2$ 对，每对花 $O(n)$ 逐位比较 $R_i$ 与 $C_j$，总复杂度 $O(n^3)$。$n \le 200$ 时约 $8 \times 10^6$ 次比较，比赛时也能 AC。

但它对「相同行重复出现」的结构毫无利用：两行完全相同时，它们与每一列的比较结果**完全一样**，暴力却把同一批列重复比较了一遍；$n$ 放大到 $10^3$（$10^9$ 次比较）立刻失效。

> ⚠️ 暴力真正的问题不是本题超不超时，而是思路不可扩展。周赛 Q2 的标准动作是把「逐对比较」升级为「分组计数」。

### 3.2 核心观察：行与列同构，序列化作键

![核心观察：行与列都是长度为 n 的序列，相等即逐位相等](images/2352_row_col_pair_concept.svg)

行 $R_i = (\text{grid}[i][0], \dots, \text{grid}[i][n-1])$，列 $C_j = (\text{grid}[0][j], \dots, \text{grid}[n-1][j])$——**都是长度为 $n$ 的整数序列**，且「行列相等」就是「两个序列完全一致」。

于是问题从「矩阵上的配对」退化为「序列匹配计数」：

- 把每个序列**序列化**成可哈希的键：C++ 用分隔符连接的字符串（`[2,4,2,2] → "2#4#2#2#"`），Python 直接用 `tuple`；
- **行建索引**：哈希表 `rowCnt` 统计每种键出现的行数；
- **列查索引**：每列序列化后在表中查询，`ans += rowCnt[key]`。

相同行被压缩成「同键计数」，重复比较被彻底消去——这正是「两数之和」把「枚举配对」换成「哈希查找」在序列维度的推广。

### 3.3 算法流程

![算法流程：阶段一建行索引，阶段二列查索引](images/2352_hash_counting_flow.svg)

1. 初始化空哈希表 `rowCnt` 与 `ans = 0`；
2. **阶段一（建索引）**：对每行 $R_i$，序列化为 `key`，执行 `rowCnt[key] += 1`；
3. **阶段二（查索引）**：对每列 $C_j$（按行下标 $i$ 自上而下读取），序列化为 `key`，执行 `ans += rowCnt[key]`；
4. 返回 `ans`。

行列角色完全对称——把列建索引、行查询同样正确；习惯上用行建索引，因为矩阵按行存储，序列化时访存连续。

### 3.4 示例演算

![示例演算：示例 2 建索引与逐列查询全过程](images/2352_example2_walkthrough.svg)

以示例 2 为例。**阶段一**建行索引得到 `rowCnt = {"3#1#2#2#": 1, "1#4#4#5#": 1, "2#4#2#2#": 2}`（注意 $R_2$、$R_3$ 同键合并计数）。**阶段二**逐列查询：

| 列 $C_j$ | 序列化键 | rowCnt[key] | 贡献 | ans |
|----------|----------|-------------|------|-----|
| $C_0$ = [3,1,2,2] | `"3#1#2#2#"` | 1 | +1 | 1 |
| $C_1$ = [1,4,4,4] | `"1#4#4#4#"` | 0 | +0 | 1 |
| $C_2$ = [2,4,2,2] | `"2#4#2#2#"` | **2** | +2 | 3 |
| $C_3$ = [2,5,2,2] | `"2#5#2#2#"` | 0 | +0 | 3 |

最终返回 `3`。注意 $C_2$ 的贡献是 **2**：$R_2$、$R_3$ 是完全相同的行，同键计数为 2，各自与 $C_2$ 配成一对。

## 4. 算法细节

1. **序列化的三种实现**：
   - C++ 首选 `unordered_map<string, int>`：每行/列的元素 `to_string` 后用 `#` 连接。`#` 不出现在十进制表示中，保证不同序列不撞键；
   - C++ 备选 `map<vector<int>, int>`：键即原序列，无须序列化，但单次比较 $O(n)$、总 $O(n^2 \log n)$，$n \le 200$ 同样能过；
   - Python 用 `tuple(grid[i])` 直接作 `Counter` 的键，元组原生可哈希且天然无撞键问题。
2. **列的读取顺序**：列 $C_j$ 必须按行下标 $i$ 从 $0$ 到 $n-1$ 自上而下读取，与行自左向右的顺序对应，才是题目定义的「同序相等」。
3. **计数而非去重**：`rowCnt[key] += 1` 保留重复行的多重性，答案才能计入每一个配对（3.4 中 $C_2$ 贡献 2）；若误用 `set` 去重会错答 2。
4. **查询缺失键**：列键不在表中时贡献 0。C++ `unordered_map` 的 `operator[]` 对缺失键插入默认值 0，`ans += rowCnt[key]` 恰好安全；Python `Counter` 对缺失键返回 0 且不插入。
5. **键的规模**：每个元素至多 6 位十进制 + 1 个分隔符，键长 $\le 7n = 1400$ 字符；共 $2n$ 个键，序列化总开销 $O(n^2)$。

## 5. 正确性证明

设 $\sigma$ 为序列化函数（每个元素的十进制表示后接一个 `#`），$R_i$、$C_j$ 均为长度 $n$ 的正整数序列。

**引理 1（$\sigma$ 是单射）**：若 $\sigma(x) = \sigma(y)$，则 $x = y$。

**证明**：对任意键按 `#` 切分，得到唯一确定的段序列；`to_string` 不产生前导零，每段唯一对应一个非负整数。于是由 $\sigma(x)$ 可还原 $x$，即 $\sigma$ 存在左逆，是单射。∎

**推论**：$R_i = C_j$（逐位相等）$\iff \sigma(R_i) = \sigma(C_j)$。（「$\Rightarrow$」显然；「$\Leftarrow$」即 $\sigma(R_i) = \sigma(C_j) \Rightarrow R_i = C_j$，由引理 1 直接得到。）

**引理 2（单列配对数）**：对任意列 $C_j$，与它相等的行的数目恰为 $\text{rowCnt}[\sigma(C_j)]$。

**证明**：由推论，$\{i : R_i = C_j\} = \{i : \sigma(R_i) = \sigma(C_j)\}$；建索引阶段把每个键 $k$ 计数到 $\text{rowCnt}[k]$ 的次数恰是 $\{i : \sigma(R_i) = k\}$ 的大小，取 $k = \sigma(C_j)$ 即得。∎

**定理**：算法返回值 $\sum_{j=0}^{n-1} \text{rowCnt}[\sigma(C_j)]$ 等于相等行列对总数 $\left|\{(i,j) : R_i = C_j\}\right|$。

**证明**：

- **不漏**：任取合法对 $(i, j)$。由引理 2，处理列 $C_j$ 时计入的 $\text{rowCnt}[\sigma(C_j)]$ 包含每一个满足 $R_i = C_j$ 的行 $i$，故 $(i,j)$ 被统计。
- **不重**：每个对 $(i, j)$ 只在处理列 $j$ 时可能被计入，且引理 2 保证该次计入的量恰为 $\{i : R_i = C_j\}$ 的大小——第 $j$ 列的每个相等的行恰好计一次，不同 $j$ 之间互不重叠。

故总和恰为目标集合的大小。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。共 $2n$ 次序列化，每次遍历 $n$ 个元素、拼接 $O(n)$ 字符，共 $O(n^2)$；哈希插入/查询各 $n$ 次，单次摊还 $O(1)$（$O(n)$ 长键的哈希与比较开销与序列化同量级，已含在内）。
- **空间复杂度**：$O(n^2)$。哈希表至多存 $n$ 个键，每键长 $O(n)$，合计 $O(n^2)$；答案只占 $O(1)$。

$n \le 200$ 时 $n^2 = 4 \times 10^4$，任何实现都能通过；本题考点不在性能上限，而在「序列化作键 + 建索引/查索引」这一把 $O(n^3)$ 逐对比较归约为两次线性扫描的转化。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int equalPairs(vector<vector<int>>& grid) {
        int n = grid.size();
        unordered_map<string, int> rowCnt;
        for (int i = 0; i < n; ++i) {
            string key;
            for (int j = 0; j < n; ++j) {
                key += to_string(grid[i][j]);
                key += '#'; // 分隔符：防 [2,4] 与 [24] 撞键
            }
            ++rowCnt[key];
        }
        int ans = 0;
        for (int j = 0; j < n; ++j) {
            string key;
            for (int i = 0; i < n; ++i) { // 列自上而下读取
                key += to_string(grid[i][j]);
                key += '#';
            }
            ans += rowCnt[key]; // 缺失键经 operator[] 得 0，安全
        }
        return ans;
    }
};
```

若不想手写序列化，`map` 直接以序列为键（$O(n^2 \log n)$，本题规模可过）：

```cpp
class Solution {
public:
    int equalPairs(vector<vector<int>>& grid) {
        int n = grid.size();
        map<vector<int>, int> rowCnt;
        for (auto& row : grid) ++rowCnt[row];
        int ans = 0;
        for (int j = 0; j < n; ++j) {
            vector<int> col;
            for (int i = 0; i < n; ++i) col.push_back(grid[i][j]);
            ans += rowCnt[col];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def equalPairs(self, grid: List[List[int]]) -> int:
        n = len(grid)
        row_cnt = Counter(tuple(row) for row in grid)  # 阶段一：行建索引
        ans = 0
        for j in range(n):                             # 阶段二：列查索引
            col = tuple(grid[i][j] for i in range(n))  # 自上而下读取
            ans += row_cnt[col]                        # 缺失键计 0
        return ans
```

## 8. 边界情况与易错点

1. **分隔符不可省（C++ 字符串键）**：直接拼接数字会把 `[2,4,2,2]` 与 `[24,22]` 映到同一键 `"2422"`，导致多算。本题元素可达 $10^5$（最多 6 位），两位数撞键是现实威胁而非人为构造。Python 的 `tuple` 与 C++ 的 `vector` 键天然无此问题。
2. **不能用数值摘要作键**：行和、行积、异或等摘要会撞键——`[1,3]` 与 `[3,1]` 的和都是 4、异或都是 2。键必须是完整序列的双射表示（带分隔符字符串 / 元组 / 原序列）。
3. **重复行的多重计数**：答案按「对」计，重复行的每个副本都要算。若误用 `set` 去重，示例 2 会错答 2（正确为 3）。
4. **列的读取方向**：列必须按 $i$ 升序自上而下读，与行自左向右同序；若把行列下标写反（如误读 `grid[j][i]`），统计的是「行 vs 行」，结果错乱。
5. **`operator[]` 的副作用**：C++ 中 `ans += rowCnt[key]` 对缺失键会插入 0 值项，本题无害，只是表可能膨胀到 $2n$ 项；在意空间可改用 `find`。
6. **最小规模 $n = 1$**：单元素矩阵的行与列必然相等，答案恒为 1，算法自然覆盖，无须特判。
7. **答案上界与溢出**：全部元素相同时答案为 $n^2 = 4 \times 10^4$，32 位 `int` 绰绰有余，无溢出风险。

**延伸思考**：

- **Trie 替代哈希**：把 $n$ 行逐一插入以元素值为边权的字典树，深度 $n$ 的节点记计数；每列沿树下行 $n$ 步，落到深度 $n$ 节点即取计数。时间仍 $O(n^2)$，免去字符串拼接，子节点用 `unordered_map` 存储——与 [LeetCode 421. 数组中两个数的最大异或值](https://leetcode.cn/problems/maximum-xor-of-two-numbers-in-an-array/) 的 01-Trie 同源。
- **更大规模**：若 $n = 10^4$，$O(n^2)$ 序列化约 $10^8$ 字符级操作，且按列读取跳跃访存、缓存不友好；可先转置矩阵让「列」变成连续的「行」再序列化。
- **配对条件变弱**：若「相等」改为「互为排列」（元素多重集相同），把每行/列**排序后**再序列化作键即可，复杂度升至 $O(n^2 \log n)$。
