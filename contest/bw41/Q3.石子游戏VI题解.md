# LeetCode 石子游戏 VI 题解

## 1. 题目概述

- **标题 / 题号**：石子游戏 VI（#1686，medium）
- **链接**：https://leetcode.cn/problems/stone-game-vi/
- **来源**：LeetCode 第 41 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、极小化极大、数组、数学、博弈、排序、堆（优先队列）

**题意**：Alice 与 Bob 轮流从 $n$ 颗石子中取走一颗（Alice 先手），取走即得分且石子消失。两人对同一颗石子的估值不同：Alice 取第 $i$ 颗得 $aliceValues[i]$ 分，Bob 得 $bobValues[i]$ 分，双方都完全知晓两个估值数组。全部取完后比较总分：Alice 高返回 $1$，Bob 高返回 $-1$，平局返回 $0$。双方都采用**最优策略**，推断结果。

**约束**：

- $n = aliceValues.length = bobValues.length \le 10^5$
- $1 \le aliceValues[i], bobValues[i] \le 10^4$

## 2. 示例

**示例 1**

```text
输入：aliceValues = [1,3], bobValues = [2,1]
输出：1
解释：Alice 取石子 1（得 3 分），Bob 只剩石子 0（得 2 分）。3 > 2，Alice 胜。
```

**示例 2**

```text
输入：aliceValues = [1,2], bobValues = [3,1]
输出：0
解释：Alice 取石子 0（得 1 分），Bob 取石子 1（得 1 分）。平局。
```

**示例 3**

```text
输入：aliceValues = [2,4,3], bobValues = [1,6,7]
输出：-1
解释：无论 Alice 怎么取，Bob 都能拿到更高的分。例如 Alice 取石子 1（4 分），
      Bob 取石子 2（7 分），Alice 取石子 0（2 分）：6 < 7，Bob 胜。
```

## 3. 解题思路

### 3.1 暴力思路

博弈搜索：状态为「已取石子的 bitmask + 轮到谁」，记忆化递归求双方最优。状态数 $O(2^n)$，$n = 10^5$ 下天文数字，仅当 $n \le 20$ 才勉强可用。必须找到能直接判定双方取石顺序的贪心结构。

### 3.2 核心观察：取一颗石子 = 自己得分 + 剥夺对方得分

![核心观察：取走石子 i 等价于落袋 a[i]+b[i] 并在分差天平上放置砝码](images/bw41_q3_score_transform.svg)

直觉上的困境是：Alice 该取"自己估值高"的还是"对方估值高"的？破局点是把博弈改写成**分差**形式。记 $s[i] = aliceValues[i] + bobValues[i]$，考察最终分差 $D = (\text{Alice 总分}) - (\text{Bob 总分})$：

设 Alice 最终取走的石子集合为 $A$，则

$$D = \sum_{i \in A} aliceValues[i] \;-\; \sum_{i \notin A} bobValues[i] = \sum_{i \in A} \underbrace{(aliceValues[i] + bobValues[i])}_{s[i]} \;-\; \sum_{i=1}^{n} bobValues[i]$$

第二项是**与策略无关的常数**！于是整个零和博弈等价于：双方轮流从多重集 $\{s[1], \dots, s[n]\}$ 中取数，**Alice 最大化她取到的 $s$ 总和，Bob 最小化之**。取走第 $i$ 颗石子的真实收益不再是 $aliceValues[i]$，而是 $s[i]$——"我拿到的 + 我不让对方拿到的"，估值差异被吸收进同一个量纲。

### 3.3 算法流程：按 s 降序，双方轮流取

![算法流程：按 a[i]+b[i] 降序排列，奇数位归 Alice、偶数位归 Bob](images/bw41_q3_pairing_strategy.svg)

对"轮流取数、一人最大化总和一人最小化总和"的博弈，双方的最优策略都是**取当前剩余的最大值**（§5 给出完整证明：配对策略给上界，归纳给下界）。于是：

```text
1. 计算 s[i] = aliceValues[i] + bobValues[i]
2. 按 s 降序排序得序列 t[0] >= t[1] >= ... >= t[n-1]
3. Alice 拿 t 的偶数下标（0,2,4,...），Bob 拿奇数下标
4. D = Σ(t[偶数位]) − Σ(bobValues)
5. 返回 D>0 ? 1 : (D<0 ? −1 : 0)
```

### 3.4 示例演算

![示例演算：示例 3 的排序与分配](images/bw41_q3_walkthrough.svg)

以示例 3 为例：$a = [2,4,3]$，$b = [1,6,7]$，$s = [3, 10, 10]$，$\sum b = 14$。

降序排列后 $t = [10, 10, 3]$（石子 1、石子 2、石子 0）：

| 轮次 | 玩家 | 取走的石子 | $s$ 值 | 分数 |
|------|------|-----------|--------|------|
| 1 | Alice | 石子 1 | 10 | $a[1] = 4$ |
| 2 | Bob | 石子 2 | 10 | $b[2] = 7$ |
| 3 | Alice | 石子 0 | 3 | $a[0] = 2$ |

$D = (10 + 3) - 14 = -1 < 0$，即 Alice 得 6 分、Bob 得 7 分，返回 $-1$ ✓。注意两颗 $s=10$ 的石子一颗归 Alice 一颗归 Bob——**排序相同取谁不影响分差**（$s$ 值相同的石子在分差公式中可互换）。

## 4. 算法细节

1. **排序键是和而非单边估值**：只按 $aliceValues$ 排序或只按 $bobValues$ 排序都是错的。反例：$a = [1, 100]$，$b = [100, 1]$。按 $a$ 排序 Alice 先取 $a=100$ 的石子？两颗石子 $s$ 都是 101，先取哪颗都行——此例无区分力。换 $a=[5,6]$，$b=[5,1]$：$s=[10,7]$，Alice 应取石子 0（$s=10$），尽管它的 $a$ 值更小。取石子 0 后 $D = 10 - 6 = 4 > 0$ Alice 胜；若取石子 1，$D = 7 - 6 = 1$，仍胜但优势缩小；极端参数下选错即败。
2. **分差的实现**：无需真的模拟双方取石再累加 $aliceValues/bobValues$，直接用 $D = \sum_{\text{偶位}} s[t] - \sum_i bobValues[i]$，一遍排序一遍累加即可。等价地也可以累加 $(-1)^{t} s$ 符号交替和。
3. **溢出**：$n \le 10^5$，$s[i] \le 2 \times 10^4$，总和 $\le 2 \times 10^9$，超出 `int` 上界，C++ 必须用 `long long` 累加（Python 天然大整数无虞）。
4. **实现方式**：排序下标数组（C++ `sort` + lambda）或直接排 $(s, i)$ 对；Python 用 `sorted(range(n), key=...)`。用堆（优先队列）模拟"每轮取最大"亦可行但多此一举——既然双方都取当前最大，最终的取石序列就是全局降序排列。
5. **相同 $s$ 值的处理**：任意顺序都正确。分差只依赖"哪些 $s$ 落在偶数位"，等值元素互换不改变偶数位的**多重集**。

## 5. 正确性证明

**引理 1（分差改写）**：对任意一局对弈（任意策略），设 Alice 取走的石子集合为 $A$，则分差 $D = \sum_{i \in A} s[i] - \sum_{i=1}^{n} bobValues[i]$，其中 $s[i] = aliceValues[i] + bobValues[i]$。

**证明**：$D = \sum_{i \in A} aliceValues[i] - \sum_{i \notin A} bobValues[i]$。对 $i \in A$ 写 $aliceValues[i] = s[i] - bobValues[i]$，则
$$D = \sum_{i \in A} s[i] - \sum_{i \in A} bobValues[i] - \sum_{i \notin A} bobValues[i] = \sum_{i \in A} s[i] - \sum_{i=1}^{n} bobValues[i]. \;\blacksquare$$

于是博弈等价于"轮流取数"博弈：Alice 最大化她取走的 $s$ 总和 $X$，Bob 最小化 $X$（两人目标严格对立，标准的零和形式）。

**引理 2（选数博弈引理）**：给定非负实数多重集降序排列 $s_1 \ge s_2 \ge \dots \ge s_m$，两人轮流取数（先手为"最大化者"，后手为"最小化者"）。则博弈值（最大化者所得 $X$）恰为 $s_1 + s_3 + s_5 + \dots$（降序奇数位之和），且**双方都取当前剩余的最大值**是一个均衡策略组。

**证明**：对 $m$ 归纳，分两个方向证博弈值为奇位和。

*上界（最小化者的配对策略）*：把降序序列两两配对 $(s_1, s_2), (s_3, s_4), \dots$。最小化者策略：每当最大化者从某个完整对中取走一个数，立即取走**同对的另一个**（首次取数前所有对完整；归纳可知任何时刻每个对要么完整要么已被双方各取一个，故该策略总能执行）。于是最大化者从每对中至多取一个数，且第 $t$ 对 $(s_{2t-1}, s_{2t})$ 中他至多取到较大者 $s_{2t-1}$。故 $X \le \sum_t s_{2t-1}$，与最大化者策略无关。

*下界（最大化者取当前最大 + 归纳）*：$m = 1$ 时最大化者取 $s_1$，恰为奇位和。设结论对 $m-1$ 成立（博弈值 = 奇位和，双方取最大为均衡）。最大化者先取 $s_1$，剩下多重集 $T_1 = \{s_2, \dots, s_m\}$，轮到最小化者先手。由归纳假设，$T_1$ 上的博弈值为 $T_1$ 的奇位和 $s_2 + s_4 + \dots$，而最大化者在 $T_1$ 上作为后手将得到 $\mathrm{sum}(T_1) - (s_2 + s_4 + \dots) = s_3 + s_5 + \dots$。故他的总所得为 $s_1 + s_3 + s_5 + \dots$。

还需证明取 $s_1$ 不劣于取任何其它 $s_j$（$j \ge 2$）：最大化者取 $s_j$ 后剩 $T_j = S \setminus \{s_j\}$，其总所得为 $s_j + \mathrm{sum}(T_j) - W(T_j) = \mathrm{sum}(S) - W(T_j)$，其中 $W(\cdot)$ 为对应多重集的博弈值；由归纳 $W(T_j)$ 等于 $T_j$ 的降序奇位和。直接展开（$T_j$ 的降序即 $S$ 的降序挖去第 $j$ 位，其奇数位由 $S$ 的奇数位与第 $j+1$ 位拼接而成）可得
$$W(T_j) - W(T_1) = \sum_{t=1}^{\lfloor j/2 \rfloor} \left( s_{2t-1} - s_{2t} \right) \ge 0,$$
即取走 $s_1$ 使对手面对的子博弈值最小、自己的所得最大。同理由归纳假设，子博弈中双方继续取最大构成均衡。归纳完成。∎

**定理**：按 $s[i] = aliceValues[i] + bobValues[i]$ 降序排序，Alice 取偶数位、Bob 取奇数位，得到的分差 $D$ 即双方最优对弈下的真实分差；算法的返回值正确。

**证明**：由引理 1，博弈等价于以 $s$ 值为筹码的选数博弈；由引理 2，均衡策略下最大化者取走降序奇数位的 $s$ 值，博弈值为 $s_1 + s_3 + \dots$。于是最优分差 $D^* = \left(\sum_{\text{奇位}} s\right) - \sum_i bobValues[i]$。降序排序后奇数位即代码中的偶数下标，故算法算出的 $D = D^*$，按其符号返回 $1 / -1 / 0$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$，排序主导；随后的奇偶位求和为 $O(n)$。
- **空间**：$O(n)$。排序下标数组（或 $(s,i)$ 对）与 $O(\log n)$ 的排序栈；若原地排值（C++ 排 pair 或下标均可），除输入外仍需 $O(n)$ 辅助。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int stoneGameVI(vector<int>& aliceValues, vector<int>& bobValues) {
        int n = aliceValues.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return aliceValues[a] + bobValues[a] > aliceValues[b] + bobValues[b];
        });
        long long diff = 0;                        // Alice 分 − Bob 分
        for (int t = 0; t < n; ++t) {
            int i = idx[t];
            if (t % 2 == 0) diff += aliceValues[i];   // Alice 先手取偶数位
            else            diff -= bobValues[i];
        }
        return diff > 0 ? 1 : (diff < 0 ? -1 : 0);
    }
};
```

### Python

```python
class Solution:
    def stoneGameVI(self, aliceValues: list[int], bobValues: list[int]) -> int:
        n = len(aliceValues)
        order = sorted(range(n),
                       key=lambda i: aliceValues[i] + bobValues[i],
                       reverse=True)
        diff = 0                        # Alice 分 − Bob 分
        for t, i in enumerate(order):
            if t % 2 == 0:
                diff += aliceValues[i]  # Alice 先手取偶数位
            else:
                diff -= bobValues[i]
        return (diff > 0) - (diff < 0)
```

> 💡 两份代码均通过全部官方示例（`1`、`0`、`-1`），并与 $O(2^n)$ 记忆化 minimax 博弈搜索做了 3000 组随机对拍（$n \le 9$，含大量相同 $s$ 值与一边倒估值），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：Alice 独取，直接比较 $aliceValues[0]$ 与 0（Bob 得 0 分），$a[0] \ge 1 > 0$ 恒返回 $1$。公式路径：$D = s_1 - b_1 = a_1 > 0$ ✓。
2. **排序键写错**是最常见的 WA：按 $a[i]$ 单独排序、按 $\max(a[i], b[i])$ 排序、按 $|a[i]-b[i]|$ 排序全都不对，正确键**只有和** $a[i]+b[i]$。直觉：取走石子同时实现"得分"与"抢夺"，两效叠加。
3. **溢出**：$\sum s$ 可达 $2 \times 10^9 > 2^{31}-1$。C++ 若用 `int` 累加偶位和会溢出为负，恰好翻转胜负判断——务必 `long long`。
4. **相同 $s$ 值**：不影响结果，但若写**不稳定比较器**（如比较器里对相等元素返回 true）会触发 UB（C++ `sort` 比较器必须严格弱序）。
5. **别模拟"逐轮决策"**：双方都取当前最大，等价于全局降序轮流分配，无需真的用堆维护"剩余最大"，直接排序即可。
6. **平局判定**：分差恰为 0 时返回 0；注意 $D$ 用整数运算，不存在浮点误差问题。
