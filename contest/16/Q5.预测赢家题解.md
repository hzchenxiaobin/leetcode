# LeetCode 预测赢家 题解

## 1. 题目概述

- **标题 / 题号**：预测赢家（#486，medium）
- **链接**：https://leetcode.cn/problems/predict-the-winner/
- **来源**：LeetCode 第 16 场周赛 B 卷 Q5
- **难度**：中等
- **标签**：递归，极小化极大（Minimax），数组，数学，动态规划，博弈论，零和博弈

**题意**：给定整数数组 $nums$，两名玩家轮流从**当前数组的任意一端**取走一个数并累加到自己得分上，玩家 1 先手，数组取空时游戏结束。双方都采取**最优策略**（各自最大化自己的最终得分），问玩家 1 的得分是否**不低于**玩家 2 的得分——相等也判玩家 1 获胜。

**约束**：

- $1 \le nums.length \le 20$
- $0 \le nums[i] \le 10^7$

**关键点**：这是一场**零和博弈**。所有数字的总和固定，一方多得一分，另一方必然少得一分，因此两人的目标其实是同一个量——分差的符号。

## 2. 示例

**示例 1**

```text
输入：nums = [1,5,2]
输出：false
解释：玩家 1 只能先取 1 或 2。
      取 1 后剩 [5,2]，玩家 2 拿 5，玩家 1 再拿 2；
      取 2 后剩 [1,5]，玩家 2 拿 5，玩家 1 再拿 1。
      无论如何玩家 1 得 3，玩家 2 得 5，玩家 1 无法获胜。
```

**示例 2**

```text
输入：nums = [1,5,233,7]
输出：true
解释：玩家 1 先取 1，剩 [5,233,7]；玩家 2 只能在 5 和 7 之间选，
      无论选哪个，玩家 1 下一步都能取走 233。
      最终玩家 1 得 234，玩家 2 得 12，返回 true。
```

**示例 3（补充：平局也算赢）**

```text
输入：nums = [1,1]
输出：true
解释：玩家 1 取 1，玩家 2 取剩下的 1，双方 1:1 战平；
      按题意平局同样判玩家 1 获胜，故返回 true。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**遍历整棵博弈树**：玩家 1 的每一步有「取左端 / 取右端」两种选择，玩家 2 同样如此，展开到叶子就是一条完整的取数序列，在叶子处比较两人总分。树叶数量为 $2^{n-1}$，时间复杂度 $O(2^n)$——$n = 20$ 时约 $5\times10^5$ 条路径，本题勉强能过，但数据范围一大就彻底崩掉。

更糟的是，这棵树里**大量节点是重复的子问题**：`[1,5,233,7]` 里先取左再取右、与先取右再取左，都会落到区间 $[1,2]$（对应 $5,233$）。这类区间一共只有 $n(n+1)/2 = 210$ 个，记忆化后即可去掉指数。

另外，**贪心（每步都取两端中较大的数）是错的**：对 `[1,5,233,7]`，贪心先取 7，玩家 2 立刻取走 233，玩家 1 只拿到 $7+5=12$，输给 $233+1=234$；而正确答案是玩家 1 获胜。原因是取走大端会把更大的数暴露给对手，局部最优破坏了后续结构。

### 3.2 核心观察：两个人的分数可以压成一个「分差」

![只跟踪分差的极小化极大模型](images/wc16_q5_minimax_diff_concept.svg)

设最终得分为 $p_1, p_2$，总和 $S = \sum nums$ 固定，于是 $p_2 = S - p_1$。所以：

- 玩家 1 最大化 $p_1$ $\iff$ 最大化分差 $d = p_1 - p_2$；
- 玩家 2 最大化 $p_2$ $\iff$ 最小化 $p_1$ $\iff$ 最小化同一个 $d$。

两人的对抗被压缩成**一个数** $d$ 的拉锯，状态不再需要记录「各自得了多少分」。定义

$$dp[i][j] = \text{在区间 } nums[i..j] \text{ 上、轮到当前玩家时，他能取得的最大分差}$$

当前玩家取左端时，先得 $nums[i]$，剩下的区间 $[i+1,j]$ 换对手先手；由定义，对手在那个子区间上能拿到净胜 $dp[i+1][j]$，所以当前玩家的净胜是 $nums[i] - dp[i+1][j]$。取右端完全对称。于是他要在两者中取较大值：

$$dp[i][j] = \max\bigl(nums[i] - dp[i+1][j],\ nums[j] - dp[i][j-1]\bigr)$$

基线是只剩一个数：$dp[i][i] = nums[i]$。最后的答案就是 $dp[0][n-1] \ge 0$（平局为 0，也算玩家 1 赢）。

> 💡 注意转移里的**减号**：子问题是「对手先手」的视角，对手的净胜正是我的净负，所以是减去而不是加上。这是所有零和博弈 DP 的统一写法。

### 3.3 算法流程

![按区间长度递增填表与一维滚动](images/wc16_q5_dp_order_flow.svg)

1. 初始化长度为 1 的所有区间：$dp[i][i] = nums[i]$。
2. 按**区间长度** $L = 2, 3, \dots, n$ 递增枚举（长度 $L$ 只依赖长度 $L-1$，天然无后效性）。
3. 对每个长度枚举左端点 $i = 0, 1, \dots, n-L$，令 $j = i + L - 1$，套用转移式。
4. 返回 $dp[0][n-1] \ge 0$。

**空间优化**：转移只用到「下一行」$dp[i+1][\cdot]$ 和「本行左边一格」$dp[i][j-1]$，因此可以**压成一维**。让 $i$ 从 $n-1$ 递减、$j$ 从 $i+1$ 递增，此时数组 $f$ 中：

- 更新前的 $f[j]$ 恰好是上一轮算出的 $dp[i+1][j]$；
- $f[j-1]$ 在本轮刚被更新，正是 $dp[i][j-1]$。

于是可以就地覆盖：$f[j] = \max(nums[i] - f[j],\ nums[j] - f[j-1])$，空间降到 $O(n)$。

### 3.4 示例演算

![nums = [1,5,233,7] 的 DP 表](images/wc16_q5_walkthrough.svg)

以 `nums = [1,5,233,7]`（$n = 4$）为例，按长度从小到大填表：

| 区间长度 | 状态与计算 | 值 |
|----------|------------|-----|
| 1 | $dp[0][0]=1$，$dp[1][1]=5$，$dp[2][2]=233$，$dp[3][3]=7$ | 基线 |
| 2 | $dp[0][1]=\max(1-5,\ 5-1)$ | 4 |
| 2 | $dp[1][2]=\max(5-233,\ 233-5)$ | 228 |
| 2 | $dp[2][3]=\max(233-7,\ 7-233)$ | 226 |
| 3 | $dp[0][2]=\max(1-228,\ 233-4)$ | 229 |
| 3 | $dp[1][3]=\max(5-226,\ 7-228)$ | −221 |
| 4 | $dp[0][3]=\max(1-(-221),\ 7-229)=\max(222,-222)$ | 222 |

$dp[0][3] = 222 \ge 0$，返回 `true`。再还原成具体分数：$p_1 = (246+222)/2 = 234$，$p_2 = (246-222)/2 = 12$，与题面示例解释完全一致。

作为对照，`nums = [1,5,2]`：$dp[0][1]=4$，$dp[1][2]=3$，$dp[0][2]=\max(1-3,\ 2-4)=-2 < 0$，返回 `false`，此时 $p_1=3,\ p_2=5$。

## 4. 算法细节

1. **状态是区间，不需要记录轮次**：区间长度决定了已经取走多少个数字，从而决定了轮到谁，因此 $(i,j)$ 两个下标就够。这是区间博弈题的通用状态设计。
2. **遍历顺序有两个等价选择**：二维写法「按长度 $L$ 递增」最直观；一维写法「$i$ 倒序 + $j$ 正序」只是同一个顺序的压维表达。两者都保证用到的子状态已经算好。
3. **一维覆盖的读写时机**：内层必须先读旧 $f[j]$（即 $dp[i+1][j]$）再写 $f[j]$，且 $j$ 必须从 $i+1$ 正序递增，才能让 $f[j-1]$ 是刚更新的 $dp[i][j-1]$。若把 $j$ 也倒序，读到的 $f[j-1]$ 还是上一行的值，答案会错。
4. **判胜用 $\ge 0$ 而不是 $> 0$**：题面明确规定平局算玩家 1 获胜，写成 `> 0` 会在 `[1,1]`、`[0,0]`、`[2,3,2]` 这类平局数据上返回错误答案。
5. **分数还原是可选的**：「两人分别得多少分」不是题目要求，但如果需要，用 $p_1=(S+d)/2$、$p_2=(S-d)/2$ 即可，其中 $d=dp[0][n-1]$、$S=\sum nums$。
6. **数据范围不会溢出**：$n \le 20$、$nums[i] \le 10^7$，总和至多 $2\times10^8$，所有中间值都落在 32 位 `int` 内；即便如此，C++ 中养成用 `int` 计算、必要时用 `long long` 的习惯也无妨。
7. **记忆化递归与递推等价**：自顶向下写 `solve(i, j)`，状态数 $n(n+1)/2$、每次转移 $O(1)$，与递推复杂度相同；递归深度不超过 $n=20$，不用担心栈。递推写法没有函数调用开销，更适合本题。
8. **可以加一条 $O(1)$ 快判**：$n$ 为偶数时玩家 1 必胜（见 §5 引理 3），可直接 `return true`；但 $n \le 20$ 时这条优化毫无必要，写进去反而容易掩盖 DP 本身的 bug，建议只在心里校验。

## 5. 正确性证明

**引理 1（零和等价）**：记 $S=\sum nums$，最终得分为 $p_1,p_2$，则 $p_1+p_2=S$。玩家 1 最大化自己的得分等价于最大化分差 $d=p_1-p_2$，玩家 2 最大化自己的得分等价于最小化同一个 $d$。

**证明**：由 $p_2=S-p_1$ 得 $d=2p_1-S$，它是 $p_1$ 的严格增函数；同理 $d=S-2p_2$ 是 $p_2$ 的严格减函数。故玩家 1 让 $p_1$ 最大即让 $d$ 最大，玩家 2 让 $p_2$ 最大即让 $d$ 最小。∎

**引理 2（状态定义良定）**：设 $F(i,j)$ 表示在区间 $nums[i..j]$ 上、轮到当前玩家且双方均采用最优策略时，当前玩家相对对手的净胜分，则

$$F(i,i)=nums[i],\qquad F(i,j)=\max\bigl(nums[i]-F(i+1,j),\ nums[j]-F(i,j-1)\bigr)$$

**证明**：对区间长度 $L=j-i+1$ 归纳。$L=1$ 时当前玩家取走唯一的数，对手得 0，净胜 $nums[i]$，成立。

设 $L\ge2$ 且所有长度小于 $L$ 的区间都满足上式。当前玩家只有两种选择：

- 取左端 $nums[i]$：他立刻得到 $nums[i]$；此后剩余区间 $[i+1,j]$ 由对手先手，长度 $L-1$，由归纳假设对手在该区间上能取得净胜 $F(i+1,j)$（对手视角），换成当前玩家视角就是 $-F(i+1,j)$，合计 $nums[i]-F(i+1,j)$。
- 取右端 $nums[j]$：对称地得到 $nums[j]-F(i,j-1)$。

由引理 1，当前玩家以最大化自己的净胜分为目标，故在两个选项里取较大者，递推式成立。∎

**引理 3（偶数长度必不败）**：若 $n$ 为偶数，则 $F(0,n-1)\ge 0$，即玩家 1 有不败策略。

**证明**：按原下标奇偶把元素分成两类 $E$、$O$，$n$ 为偶数时两类各含 $n/2$ 个元素，故 $\max\bigl(\sum_{E},\sum_{O}\bigr)\ge S/2$。玩家 1 预先选定和较大的一类作为「目标类」，策略是：每次轮到自己时，取走当前区间中属于目标类的那一端。

这是因为轮到他时剩余区间长度必为偶数（$n, n-2, \dots, 2$），而长度为偶数的区间两端下标奇偶不同，恰好有一端属于目标类，因此该端总是可取。玩家 2 取走任意一端后，区间长度重新变回偶数，两端仍一奇一偶，目标类元素依然暴露在一端。于是在他的 $n/2$ 个回合里，他取走的恰好是目标类全部元素，得分 $\ge S/2$，而对手最多得 $S/2$，故玩家 1 不败。∎

**定理**：算法返回 `true` 当且仅当玩家 1 存在不败策略。

**证明**：由引理 2，$d=F(0,n-1)=dp[0][n-1]$ 恰是双方最优时的分差，且 $p_1=(S+d)/2$。

- 若 $d\ge0$：玩家 1 按引理 2 的递推所对应的选择行动，可以保证最终分差恰为 $d\ge0$，即 $p_1\ge p_2$，不败。
- 若 $d<0$：引理 2 的递推对当前玩家的所有选择取最大值，因此任何选择给出的净胜都不超过 $d<0$，而玩家 2 总能按最优应对把分差保持为负，玩家 1 必败。

算法输出的正是 $d\ge0$，与「玩家 1 不败」完全等价。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。状态数为 $n(n+1)/2$（$n=20$ 时为 210 个），每个状态只做两次减法、一次比较，$O(1)$。即便用未记忆化的博弈树，树中不同子问题也只有这些。
- **空间**：$O(n)$。一维滚动数组 $f$ 占 $n$ 个整数。若写成二维表则为 $O(n^2)$；自顶向下记忆化递归另需 $O(n^2)$ 的缓存与 $O(n)$ 的递归栈。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    bool predictTheWinner(vector<int>& nums) {
        int n = (int)nums.size();
        vector<int> f(nums);              // f[j] 初值 = dp[j][j] = nums[j]
        // i 倒序：处理 i 时，f[j]（j > i）还停留在上一轮 i+1 的值 dp[i+1][j]
        for (int i = n - 2; i >= 0; --i) {
            for (int j = i + 1; j < n; ++j) {
                // f[j-1] 已在本轮更新为 dp[i][j-1]，f[j] 仍是 dp[i+1][j]
                f[j] = max(nums[i] - f[j], nums[j] - f[j - 1]);
            }
        }
        return f[n - 1] >= 0;             // 平局（0）也算玩家 1 赢
    }
};
```

### Python

```python
from typing import List


class Solution:
    def predictTheWinner(self, nums: List[int]) -> bool:
        n = len(nums)
        f = nums[:]                       # f[j] 初值 = dp[j][j] = nums[j]
        for i in range(n - 2, -1, -1):    # i 倒序：f[j] 还是上一行的 dp[i+1][j]
            for j in range(i + 1, n):
                # f[j-1] 已被本轮更新为 dp[i][j-1]
                f[j] = max(nums[i] - f[j], nums[j] - f[j - 1])
        return f[n - 1] >= 0              # 平局（0）也算玩家 1 赢
```

## 8. 边界情况与易错点

1. **只有一个数**：`nums = [7]`，循环不进入，直接返回 $nums[0] \ge 0$ 即 `true`，玩家 1 独得 7。
2. **平局必须算赢**：`[1,1]`、`[0,0]` 的分差为 0，判据要写 $d \ge 0$；写成 $d > 0$ 会在这类数据上错。
3. **全 0 数组**：`[0,0,0,0]` 分差为 0，返回 `true`；注意不要因为「没人得分」就误判成 `false`。
4. **贪心陷阱**：每步取两端较大者看似合理，`[1,5,233,7]` 会给出错误答案（见 §3.1）。必须保留「让对手先手」这一层，也就是转移式中的减号。
5. **一维滚动的方向**：`i` 必须倒序、`j` 必须正序。两者写反任一个，读到的都是被覆盖过的脏值，样例可能仍然过，随机数据必错。
6. **递归忘加记忆化**：直接 `return max(nums[i] - dfs(i+1,j), nums[j] - dfs(i,j-1))` 是 $O(2^n)$，数据稍大就超时；务必加 `lru_cache` 或改递推。
7. **偶数长度不需要特判**：$n$ 为偶数时答案必为 `true`（引理 3），但别把它写成唯一逻辑——奇数长度仍然要靠 DP，混着写容易漏掉 $n=1$ 的情形。
8. **返回值类型**：函数返回 `bool`，不要顺手返回分差或两人分数；$p_1$、$p_2$ 的还原只是分析手段。
