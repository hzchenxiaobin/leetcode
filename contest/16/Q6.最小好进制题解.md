# LeetCode 最小好进制 题解

## 1. 题目概述

- **标题 / 题号**：最小好进制（#483，hard）
- **链接**：https://leetcode.cn/problems/smallest-good-base/
- **来源**：LeetCode 第 16 场周赛 B 卷 Q6
- **难度**：困难
- **标签**：数学，二分查找

**题意**：给定一个十进制正整数 $n$（以字符串给出）。若 $n$ 在 $k$ 进制（$k \ge 2$）下的**每一位都是 $1$**，就称 $k$ 是 $n$ 的一个**好进制**。求 $n$ 的**最小**好进制，并以字符串形式返回。

**约束**：

- $3 \le n \le 10^{18}$，以字符串给出（超出 32 位整数范围，需按 64 位处理）
- $n$ 没有前导 0
- 保证答案存在：$k = n-1$ 时 $n$ 写成 `11`，永远是好进制（$n \ge 3 \Rightarrow n-1 \ge 2$）

## 2. 示例

**示例 1**

```text
输入：n = "13"
输出："3"
解释：13 的 3 进制是 111（1 + 3 + 9 = 13）。
      2 进制 1101 不是全 1，故最小好进制是 3。
```

**示例 2**

```text
输入：n = "4681"
输出："8"
解释：4681 的 8 进制是 11111（1 + 8 + 64 + 512 + 4096 = 4681）。
      2 到 7 进制下都不是全 1，故答案是 8。
```

**示例 3**

```text
输入：n = "1000000000000000000"
输出："999999999999999999"
解释：1e18 在 999999999999999999 进制下是 11，
      而 2 到 1e18−2 进制都不是全 1 —— 答案可以大到接近 n 本身。
```

## 3. 解题思路

### 3.1 暴力思路

从小到大枚举进制 $k = 2, 3, \dots$，把 $n$ 反复对 $k$ 取模、整除，检查每一位是否都是 $1$。单次检验是 $O(\log_k n)$，看起来很快——但**最小好进制最坏就是 $n-1$**（示例 3），枚举规模达到 $10^{18}$，直接超时。所以不能沿 $k$ 的方向暴力。

### 3.2 核心观察：固定位数 $m$，$k$ 就被唯一确定

![m 位全 1 就是等比数列求和](images/wc16_q6_power_sum_identity.svg)

把「$n$ 在 $k$ 进制下全为 $1$」按位展开。若共有 $m$ 位（高位到低位都是 $1$），则

$$n = 1 + k + k^2 + \cdots + k^{m-1} = \frac{k^m - 1}{k - 1}$$

这就是**等比数列求和**的封闭形式。于是题目从「枚举 $k$」变成了「枚举 $m$，再反解 $k$」：

1. **$m$ 的范围很小**。$f(k,m) = 1+k+\cdots+k^{m-1}$ 关于 $k$ 递增，$k \ge 2$ 时最小是 $2^m - 1$，所以 $2^m - 1 \le n$，即 $m \le \lfloor \log_2(n+1) \rfloor$。$n \le 10^{18}$ 时 $m \le 59$，只有 58 种可能（$m \ge 2$）。
2. **固定 $m$ 后 $k$ 至多一解**。$f(k,m)$ 关于 $k$ 严格递增，所以方程 $f(k,m)=n$ 要么无解，要么唯一解——**可以二分**。
3. **$m$ 与 $k$ 反向**。$m$ 越大，同样大的 $n$ 需要的 $k$ 就越小。所以**最小的 $k$ 藏在最大的可行 $m$ 里**：$m$ 从 $m_{\max}$ 递减枚举，第一次命中就是答案，不必比较所有解。

> 💡 一句话：把「进制」换成「位数」枚举，未知量就从 $10^{18}$ 个压到 59 个，每个再用二分 $O(\log n)$ 判定。

### 3.3 算法流程

![固定 m 后二分 k 的流程](images/wc16_q6_binary_search_k.svg)

```text
N ← int(n)，m_max ← ⌊log2(N+1)⌋
for m = m_max, m_max−1, …, 2:            # 位数从大到小
    lo ← 2, hi ← N−1                     # 进制区间
    while lo ≤ hi:
        mid ← (lo+hi)/2
        s ← 1 + mid + mid² + … + mid^(m−1)   # Horner 计算，超过 N 立即截断
        if s = N:  return mid            # 命中：m 最大 ⇒ k 最小，直接返回
        elif s < N: lo ← mid+1
        else:       hi ← mid−1
return N−1                               # m = 2 保底：N = 1 + (N−1)
```

**为什么 $m=2$ 一定能命中**：$f(k,2) = 1+k$，取 $k=N-1$（$N \ge 3$ 时 $\ge 2$）恰好等于 $N$，而且 $k=N-1$ 落在二分区间 $[2, N-1]$ 的右端点。所以最后一层必然返回，`return N−1` 只是把这条保底路径写清楚。

### 3.4 示例演算

![n = 4681 的走查：m 从 12 递减到 5](images/wc16_q6_walkthrough_4681.svg)

以 $n = 4681$ 为例，$m_{\max} = \lfloor \log_2 4682 \rfloor = 12$：

| 位数 $m$ | 最大的可行 $k$（$f \le n$） | 下一个 $k$ 的 $f$（已超过 $n$） | 结论 |
|----------|------------------------------|----------------------------------|------|
| 12 | $k=2$，$f=4095$ | $k=3$，$f=265720$ | 无整数解 |
| 11 | $k=2$，$f=2047$ | $k=3$，$f=88573$ | 无整数解 |
| 8 | $k=3$，$f=3280$ | $k=4$，$f=21845$ | 无整数解 |
| 6 | $k=5$，$f=3906$ | $k=6$，$f=9331$ | 无整数解 |
| **5** | $k=8$，$f=4681$ | $k=9$，$f=7381$ | **命中，返回 8** |

表中省略了同样无解的 $m = 10, 9, 7$ 三层；关键现象是：$m$ 越大，$f(k,m)$ 随 $k$ 涨得越快，$k$ 就被夹得越窄，往往只有一两个候选值。小例子 $n = 13$ 更直观：$m_{\max}=3$，$m=3$ 时 $f(2,3)=7 < 13$、$f(4,3)=21 > 13$，二分到 $k=3$ 时 $f(3,3)=1+3+9=13$，直接返回 `"3"`，$m=2$ 那一层根本不用跑。

## 4. 算法细节

1. **位数上界**：$m_{\max} = \lfloor \log_2(n+1) \rfloor$。C++ 可用循环 $m=3,4,\dots$ 试 $(1 \ll m)-1 \le N$；Python 直接 `(N+1).bit_length()-1`。注意 $m \le 59$，$m=60$ 时 $2^{60}-1 > 10^{18}$，不必再试。
2. **枚举顺序不能反**：必须从 $m_{\max}$ 往下。若从小到大枚举，第一个命中只是「位数最少」的解，对应**最大**的 $k$，恰好和答案相反。
3. **二分的两个端点**：$lo=2$（进制至少 2），$hi=N-1$（$m=2$ 的解就在右端点）。写 `mid = lo + (hi - lo) / 2` 避免 `lo + hi` 溢出；不要用 $N$ 当右端点，否则会多算一轮且 $k=N$ 无意义。
4. **Horner 累加 + 溢出保护**：$f$ 用 `s = s*k + 1` 递推 $m$ 次，只需 $m$ 次乘加。C++ 中 $k$ 可到 $10^{18}$，$k^{58}$ 必然溢出 64 位，所以每步先判 $s > (N-1)/k$（等价于 $s \cdot k + 1 > N$），成立就视为「已超过 $n$」提前退出。
5. **不要用浮点开根**：常见写法是 $k \approx n^{1/(m-1)}$ 再邻域微调。但 `double` 只有 53 位尾数，$n$ 接近 $10^{18}$ 时误差可达数个整数单位，边界上会取错值；整数二分是精确的，且代价只有约 60 步。
6. **类型选择**：输入是字符串，C++ 用 `unsigned long long`（`stoull`），乘积与和都留在无符号域内，不会溢出；Python 整数天然任意精度，只需在累加时用 `if s > N` 提前截断来控制乘法规模。
7. **提前返回**：命中即 `return`，不要保存 `best` 再继续枚举——$m$ 递减时后续解只会更大。

## 5. 正确性证明

**引理 1（全 1 与和式等价）**：设 $k \ge 2$、$m \ge 2$。$n$ 在 $k$ 进制下恰好有 $m$ 位且每一位都是 $1$，当且仅当 $n = f(k,m) = \sum_{i=0}^{m-1} k^{i}$。

**证明**：$k$ 进制按位展开即 $n = \sum_{i=0}^{m-1} d_i k^{i}$，最高位 $d_{m-1} \ne 0$。若每位 $d_i = 1$，则 $n = f(k,m)$；反之若 $n = f(k,m)$，由于 $f(k,m) < k^m$（$k \ge 2$ 时 $\sum_{i<m} k^i < k^m$）且 $f(k,m) \ge k^{m-1}$，$n$ 的 $k$ 进制表示恰有 $m$ 位，逐位比较唯一性给出 $d_i = 1$。∎

**引理 2（固定 $m$ 时解唯一）**：对固定 $m \ge 2$，$f(k,m)$ 关于 $k \ge 2$ 严格递增，故方程 $f(k,m) = n$ 至多有一个整数解；且二分查找能返回它（若存在）。

**证明**：设 $k' > k \ge 2$，则

$$f(k',m) - f(k,m) = \sum_{i=0}^{m-1}\left(k'^{i} - k^{i}\right) \ge k' - k \ge 1 > 0$$

其中 $i=1$ 的项 $k'-k \ge 1$、其余项非负，故严格递增；至多一解。二分维持不变量「$f(lo-1,m) < n$ 且 $f(hi+1,m) > n$」，每轮把区间缩半，终止时若命中则返回唯一解，否则该 $m$ 确实无解。∎

**引理 3（$m$ 越大，$k$ 越小）**：若 $m_1 > m_2 \ge 2$ 且两式均有解 $f(k_1,m_1) = f(k_2,m_2) = n$，则 $k_1 < k_2$。

**证明**：反设 $k_1 \ge k_2$。由引理 2 的单调性，$f(k_1,m_1) \ge f(k_2,m_1) = f(k_2,m_2) + \sum_{i=m_2}^{m_1-1} k_2^{i} > f(k_2,m_2) = n$（因为 $m_1 > m_2$ 且 $k_2 \ge 2$，新增项之和至少 $k_2^{m_2} \ge 2$），与 $f(k_1,m_1)=n$ 矛盾。∎

**引理 4（枚举范围不漏解）**：若 $k \ge 2$ 是 $n$ 的好进制、对应位数为 $m$，则 $m \le m_{\max} = \lfloor \log_2(n+1) \rfloor$。

**证明**：由引理 1，$n = f(k,m) \ge f(2,m) = 2^m - 1$，故 $2^m \le n+1$，即 $m \le \log_2(n+1)$，取整得 $m \le m_{\max}$。∎

**定理**：算法返回的字符串是 $n$ 的最小好进制。

**证明**：设最小好进制为 $k^{*}$，对应位数 $m^{*}$。由引理 4，$m^{*} \le m_{\max}$，枚举必然覆盖它；由引理 2，在该层二分能唯一确定 $k^{*}$，故算法不会漏掉它。另一方面，设算法在第一个命中的层 $m$ 返回 $k$。由于枚举是**从大到小**进行的，所有 $m' > m$ 的层都已被判定无解，即不存在位数大于 $m$ 的好进制；而由引理 3，任何位数小于 $m$ 的可行解对应的进制 $k' > k$。合起来：任何好进制或在 $k$ 处、或进制更大，故 $k$ 就是最小好进制。最后由 $m=2$ 层的保底解 $k=N-1$（引理 2 保证该层必命中）说明算法不会空手而归。∎

## 6. 复杂度分析

- **时间**：枚举 $m$ 共 $O(\log n)$ 层；每层在 $[2, n-1]$ 上二分 $O(\log n)$ 轮；每轮用 Horner 递推计算 $f(k,m)$，需要 $m = O(\log n)$ 次乘加。合计 $O(\log^3 n)$。$n \le 10^{18}$ 时约 $60 \times 60 \times 60 \approx 2.2 \times 10^5$ 次基本运算，实测 Python 单次求解在毫秒级。
- **空间**：$O(1)$。只用了常数个 64 位整数与循环变量，没有任何数组或哈希表。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string smallestGoodBase(string n) {
        unsigned long long N = stoull(n);

        // 位数上界：1 + 2 + ... + 2^(m-1) = 2^m - 1 <= N
        int mMax = 2;
        for (int m = 3; m <= 63 && (1ULL << m) - 1 <= N; ++m) mMax = m;

        for (int m = mMax; m >= 2; --m) {
            // 计算 min(1 + k + ... + k^(m-1), N+1)；一旦超过 N 就提前退出
            auto sumOfPowers = [&](unsigned long long k) -> unsigned long long {
                unsigned long long s = 0;
                for (int i = 0; i < m; ++i) {
                    if (s > (N - 1) / k) return N + 1;   // s*k + 1 > N，防溢出
                    s = s * k + 1;
                }
                return s;
            };

            unsigned long long lo = 2, hi = N - 1, ans = 0;
            while (lo <= hi) {
                unsigned long long mid = lo + (hi - lo) / 2;
                unsigned long long s = sumOfPowers(mid);
                if (s == N) { ans = mid; break; }
                if (s < N) lo = mid + 1;
                else hi = mid - 1;
            }
            if (ans) return to_string(ans);   // m 已最大 ⇒ k 已最小
        }
        return to_string(N - 1);              // 保底：N 在 N-1 进制下是 11
    }
};
```

### Python

```python
class Solution:
    def smallestGoodBase(self, n: str) -> str:
        N = int(n)
        m_max = (N + 1).bit_length() - 1      # 等价于 floor(log2(N + 1))

        def f(k: int, m: int) -> int:
            """1 + k + ... + k^(m-1)，超过 N 即截断为 N+1"""
            s = 0
            for _ in range(m):
                s = s * k + 1
                if s > N:
                    return N + 1
            return s

        for m in range(m_max, 1, -1):         # 位数从大到小，k 从小到大
            lo, hi = 2, N - 1
            while lo <= hi:
                mid = (lo + hi) // 2
                s = f(mid, m)
                if s == N:
                    return str(mid)           # 命中即最小
                if s < N:
                    lo = mid + 1
                else:
                    hi = mid - 1
        return str(N - 1)                     # 保底：m = 2 时 k = N-1
```

## 8. 边界情况与易错点

1. **最小输入 `"3"`**：$m_{\max} = \lfloor \log_2 4 \rfloor = 2$，只剩 $m=2$ 一层，$k=2$ 命中，返回 `"2"`。若把 $m$ 的下界写成 3，这里会直接漏解。
2. **答案是 $n-1$ 的大数**：`"1000000000000000000"` 的答案是 `"999999999999999999"`，说明答案本身超出 32 位，全程必须用 64 位无符号或 Python 大整数，任何一次 `int` 截断都会错。
3. **溢出**：C++ 里 $k$ 最大 $10^{18}$，$k^{58}$ 远超 64 位，因此累加前必须先判 `s > (N - 1) / k` 再乘；直接 `s = s * k + 1` 会回绕成小值，导致二分判断完全失真、死循环或错解。
4. **浮点开根不可靠**：用 `pow(n, 1.0/(m-1))` 估 $k$ 时，`double` 在 $10^{18}$ 附近的分辨率只有几十个单位，容易落在正确解旁边一两个数上；即便加邻域修正也很难覆盖所有 $m$，不如整数二分稳。
5. **$m$ 的上界不要用十进制位数**：$n \le 10^{18}$ 是「最多 19 位十进制」，对应 $m_{\max}$ 是 59（二进制），两者差了 3 倍多。写成 `len(n)` 会直接漏掉高位数的解。
6. **二分区间右端点**：取 $hi = N-1$ 而不是 $N$。$k = N$ 时 $n$ 在 $k$ 进制下是单个 `1`，不符合「至少两位、共 $m \ge 2$ 位」的模型；把 $N$ 放进区间会让 $m=2$ 层永远差一步。
7. **枚举方向**：从 $m_{\max}$ 递减是本题的「答案即最早命中」关键；若从小到大枚举，返回的是位数最少（即 $k$ 最大）的解，与题目要求的「最小好进制」正好相反。
