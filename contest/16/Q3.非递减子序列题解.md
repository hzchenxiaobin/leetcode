# LeetCode 非递减子序列 题解

## 1. 题目概述

- **标题 / 题号**：非递减子序列（#491，medium）
- **链接**：https://leetcode.cn/problems/non-decreasing-subsequences/
- **来源**：LeetCode 第 16 场周赛 A 卷 Q3
- **难度**：中等
- **标签**：位运算，数组，哈希表，回溯

**题意**：给定整数数组 `nums`，返回其中**所有不同**的**非递减子序列**，每个子序列**至少含 2 个元素**，答案顺序任意。题目里说的「不同」指**值序列**不同，而不是下标序列不同；相邻元素相等也属于非递减。

**约束**：

- $1 \le \lvert nums \rvert \le 15$
- $-100 \le nums[i] \le 100$
- 返回值是「值序列」的去重集合，同一个值序列只出现一次

## 2. 示例

**示例 1**

```text
输入：nums = [4,6,7,7]
输出：[[4,6],[4,6,7],[4,6,7,7],[4,7],[4,7,7],[6,7],[6,7,7],[7,7]]
解释：共 8 条。注意 [4,7] 既可由下标 (0,2) 得到，也可由 (0,3) 得到，
      但答案里只保留一条 —— 这正是本题的去重难点。
```

**示例 2**

```text
输入：nums = [4,4,3,2,1]
输出：[[4,4]]
解释：只有开头的两个 4 构成非递减对；之后的 3、2、1 都在下降，无法再接任何元素。
```

**示例 3（补充，全相同元素）**

```text
输入：nums = [1,1,1]
输出：[[1,1],[1,1,1]]
解释：值序列只有 (1,1) 和 (1,1,1) 两种；(1,1) 有 (0,1)、(0,2)、(1,2) 三种下标来源，
      去重后只剩一条，故答案恰为 2 条。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $2^n$ 个下标子集，过滤掉「长度 $< 2$」和「存在下降」的，把剩下的值序列塞进集合去重。$n \le 15$ 时 $2^{15} = 32768$，总量约 $O(n \cdot 2^n) \approx 5 \times 10^5$，本题**能过**。

但它有三个毛病：一是重复候选的规模可能远大于答案本身——15 个相同数字时 $2^{15}$ 个子集只对应 14 条答案，绝大多数时间花在丢弃重复上；二是每条候选都要临时构造序列并哈希，常数偏大；三是换成 $n = 20$ 就直接超时，模板不可迁移。而**回溯 + 同层去重**是边搜索边去重，只在搜索树上走合法解对应的路径，是本题的标准解法。

### 3.2 核心观察：重复只源于「同一层选了相同的值」

![同层去重：同一个值在每层只用一次](images/wc16_q3_level_dedup_concept.svg)

一个值序列之所以会被重复生成，是因为它可能对应**多条不同的下标序列**。例如 `[4,6,7,7]` 里的 `[4,7]`，既可以走下标 $(0,2)$，也可以走 $(0,3)$。观察这棵深度优先搜索树：重复只可能出现在**同一层**（即同一个 `start`、同一个已经选好的前缀）挑到**相同的值**时。

设第 $d$ 层先选了下标 $i'$、之后又选了下标 $i$，且 $i' < i$ 而 $nums[i'] = nums[i]$。那么任何以 $i$ 开头的后续选择都可以整体换成 $i'$：值序列一模一样，而 $i'$ 之后的可选区间 $[i'+1, n)$ **包含** $i$ 之后的 $[i+1, n)$，所以换过去只会更宽松，不会漏解。于是：

> **同一个值在每一层只用一次**——用 `used` 集合记录本层已经尝试过的值，同值只取第一次出现（最左下标）。

> ⚠️ 注意：数组本身**无序**，不能照搬「子集 II / 全排列 II」里 `排序 + nums[i] == nums[i-1] 就跳过` 的写法。排序会打乱子序列的先后关系，直接算错；必须靠「每层的 `used` 集合」而不是「和相邻元素比较」。

### 3.3 算法流程

![DFS 回溯流程：两道剪枝](images/wc16_q3_dfs_flow.svg)

```text
dfs(start):
    若 len(path) ≥ 2：把 path 的副本加入答案        # 不 return，继续往后接
    used = 空集合                                   # 每层独立新建
    for i = start … n-1:
        若 path 非空 且 nums[i] < path.back()：continue   # 剪枝①：破坏非递减
        若 nums[i] ∈ used：continue                      # 剪枝②：同层同值去重
        used.add(nums[i])
        path.push(nums[i]);  dfs(i + 1);  path.pop()
```

主函数调用 `dfs(0)` 即可。两个要点：**记录答案在扩展之前**（保证长度为 2 的前缀不会漏），**`used` 每层新建且层内不回退**（只在本层生效，跨层可以重复用同一个值）。

### 3.4 示例演算

![示例演算：nums = [4,6,7,7] 的 8 条答案](images/wc16_q3_walkthrough.svg)

对 `nums = [4,6,7,7]` 手工走一遍搜索树：

- 第 1 层：候选 $i=0(4)$、$i=1(6)$、$i=2(7)$、$i=3(7)$，最后一个是同层同值 → 剪掉，于是得到三条一元素路径 `[4]`、`[6]`、`[7]`。
- `[4]` 往下（`start=1`）：取 6 得 `[4,6]`；取 7 得 `[4,7]`（第三个 7 被剪）。`[4,6]` 再往下取 7 得 `[4,6,7]`，其后再取 7 得 `[4,6,7,7]`。`[4,7]` 往下取 7 得 `[4,7,7]`。
- `[6]` 往下（`start=2`）：取 7 得 `[6,7]`，再接 7 得 `[6,7,7]`。
- `[7]`（来自 $i=2$）往下（`start=3`）：取 7 得 `[7,7]`。

答案恰好 8 条，与官方输出一致；而 `(0,3)` 这条路径始终没有出现，重复在生成阶段就被消灭了。

## 4. 算法细节

1. **记录时机**：先判断 `len(path) >= 2` 就记录，再继续递归。若只在「无法再扩展」的叶子处记录，就会漏掉所有非极大的非递减序列（例如 `[4,6]` 能扩展成 `[4,6,7,7]`，但 `[4,6]` 本身也是答案）。
2. **存副本**：C++ 用 `res.push_back(path)`（值拷贝）、Python 用 `path[:]`、Java 用 `new ArrayList<>(path)`。若直接存入 `path` 的引用，后续 `pop` 会把已存答案改坏。
3. **`used` 的作用域**：必须定义在 `dfs` 函数体内（每层一个），不能做成全局或成员变量。否则会跨层误杀——`[4,6,7,7]` 中值 6、7 在不同层都要反复使用。
4. **`used` 不回退**：回溯时只 `path.pop()`，**不**从 `used` 里删元素。因为这一层已经试过的值，之后再遇到同值都应该跳过。
5. **值域优化**：$nums[i] \in [-100, 100]$ 只有 201 种取值，可用 `int seen[201]` 配合一个自增的时间戳 `stamp`：进层时 `++stamp`，判断 `seen[v] == stamp` 即为「本层已用过」。这样每层清空是 $O(1)$，且完全避开哈希开销。注意下标要偏移 `nums[i] + 100`，别用负数直接访问数组。
6. **下标严格递增**：`dfs(i + 1)` 传的是 $i+1$ 而不是 `start + 1`，这既保证了下标递增、避免重复选同一位置，也保证了子序列的定义。
7. **输出规模上限**：$n = 15$ 且元素全部互异递增时答案条数为 $2^{15} - 15 - 1 = 32752$，这是本题的理论最大值，回溯的时间与之同阶，必须能承受。

## 5. 正确性证明

**引理 1（输出合法）**：`dfs` 生成的每一条 `path`，都是一个长度 $\ge 2$、下标严格递增、元素非递减的子序列。

**证明**：只有 `len(path) >= 2` 时才记录，故长度条件满足。每次入栈前都检查了 `path` 为空或 $nums[i] \ge path.\text{back}()$，故相邻元素非递减。又因为每次递归传入 `i + 1`，新下标严格大于原下标，故下标严格递增。∎

**引理 2（不重复）**：同一条值序列最多被生成一次。

**证明**：反设值序列 $V = (v_1, \dots, v_k)$ 由两条不同的下标序列 $I = (i_1, \dots, i_k)$ 与 $J = (j_1, \dots, j_k)$ 生成。取第一个不同的位置 $d$，不妨设 $i_d < j_d$。这两个下标都出现在搜索树的第 $d$ 层（它们前面选中的下标完全相同），且 $nums[i_d] = nums[j_d] = v_d$。算法在同一层内按 $i$ 递增顺序遍历，先处理 $i_d$，把 $v_d$ 放进该层的 `used`；于是处理到 $j_d$ 时 $nums[j_d] \in used$，直接被剪枝跳过。与「$J$ 也被生成」矛盾。∎

**引理 3（不遗漏）**：任意合法的非递减序列（值序列）都会被生成。

**证明**：设 $V$ 是某个能由 $nums$ 生成的合法值序列，在所有能生成 $V$ 的下标序列中取字典序最小者 $I^{*}$（候选有限，必存在）。断言：算法会沿着 $I^{*}$ 生成 $V$。对层数 $d$ 归纳。

$d = 1$ 时，$I^{*}_1$ 必是值 $v_1$ 在整个数组中**第一次**出现的下标：否则存在更小的同值下标 $i' < I^{*}_1$，用它替换后下标序列依然递增且生成同一个 $V$，与最小性矛盾。既然它是最左出现，第 1 层遍历到它时不可能在 `used` 中，必被选中。

设算法已按 $I^{*}_1, \dots, I^{*}_d$ 进入第 $d+1$ 层（此时 `start` $= I^{*}_d + 1$）。同理，$I^{*}_{d+1}$ 必是值 $v_{d+1}$ 在区间 $[I^{*}_d + 1, n)$ 中**第一次**出现的下标：否则可换成该区间内更小的同值下标，得到更小的下标序列而值序列不变。于是该层扫到它时它不在 `used` 中，被选中。归纳完成。∎

**定理**：算法输出的集合恰好是「全部长度 $\ge 2$ 的不同非递减子序列」。

**证明**：由引理 1，每条输出都合法；由引理 2，输出中没有重复；由引理 3，任何合法值序列都被输出覆盖。三者合起来即「恰好」。∎

## 6. 复杂度分析

- **时间**：记答案条数为 $R$、答案元素总数（长度之和）为 $S$。搜索树只沿「被选中」的边向下，每个被访问的结点做一次 $O(1)$ 记录与一次最多 $n$ 个候选的层内扫描，故总时间为 $O(n \cdot (R + 1))$；由于 $R \le 2^n - n - 1$，最坏为 $O(n \cdot 2^n)$，$n = 15$ 时约 $5 \times 10^5$ 量级，非常宽裕。`used` 用定长数组 + 时间戳时，每层清空为 $O(1)$，不额外增加复杂度。
- **空间**：答案存储 $O(S)$（输出本身的大小，不计入辅助空间）；递归栈深度不超过 $n = 15$，每层 `used` 集合最多 $O(n)$（哈希最坏情况）或 $O(201)$（定长数组），辅助空间 $O(n^2)$ 即约 225 个槽位，可视为 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
#include <functional>
using namespace std;

class Solution {
public:
    vector<vector<int>> findSubsequences(vector<int>& nums) {
        vector<vector<int>> res;
        vector<int> path;
        int n = nums.size();

        function<void(int)> dfs = [&](int start) {
            if (path.size() >= 2) res.push_back(path);   // 先记录，再继续扩展
            unordered_set<int> used;                     // 本层已尝试过的值
            for (int i = start; i < n; ++i) {
                if (!path.empty() && nums[i] < path.back()) continue;  // 剪枝①
                if (used.count(nums[i])) continue;                     // 剪枝②
                used.insert(nums[i]);
                path.push_back(nums[i]);
                dfs(i + 1);
                path.pop_back();                         // used 不回退
            }
        };

        dfs(0);
        return res;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def findSubsequences(self, nums: List[int]) -> List[List[int]]:
        n = len(nums)
        res: List[List[int]] = []
        path: List[int] = []

        def dfs(start: int) -> None:
            if len(path) >= 2:
                res.append(path[:])          # 先记录副本，再继续扩展
            used = set()                     # 本层独立，跨层互不影响
            for i in range(start, n):
                if path and nums[i] < path[-1]:
                    continue                 # 剪枝①：破坏非递减
                if nums[i] in used:
                    continue                 # 剪枝②：同层同值只取最左
                used.add(nums[i])
                path.append(nums[i])
                dfs(i + 1)
                path.pop()                   # used 保留，不回退

        dfs(0)
        return res
```

## 8. 边界情况与易错点

1. **没有答案**：`n = 1`（如 `[5]`）或数组严格递减（如 `[15,14,...,1]`）时返回**空数组** `[]`，不要返回 `[[]]` 之类的占位结构。
2. **长度恰好为 2 的答案要保留**：记录点在扩展之前且记录后**不 return**，否则 `[4,6]` 这类能继续扩展的短答案会全部丢失。
3. **相等算非递减**：剪枝条件必须是 `nums[i] < path.back()`，写成 `<=` 会把 `[7,7]`、`[4,4]` 这类答案全剪光（`[4,4,3,2,1]` 的正确答案恰是 `[[4,4]]`）。
4. **数组无序 → 不能排序**：`排序 + nums[i]==nums[i-1] 跳过` 是子集类题目的套路，这里排序会改变子序列的相对顺序，结果直接错。
5. **`used` 必须是「每层」而非「全局」**：放成全局会让值 6、7 在后续层无法再次使用，`[4,6,7,7]` 只能得到个别答案。
6. **负数下标**：用定长数组做去重时记得偏移 `nums[i] + 100`，直接把 `nums[i]` 当下标会越界。
7. **大量重复元素**：15 个 7 时答案只有 14 条（各长度一条）。如果跑出 32752 条，说明剪枝②失效；反之若全递增的 `[1..15]` 跑不出 32752 条，说明剪枝①误伤了。
8. **C++ 引用捕获**：`dfs` 里用 `[&]` 捕获 `path` / `res`，别误用值捕获导致结果丢失；`res.push_back(path)` 本身是值拷贝，没问题。
