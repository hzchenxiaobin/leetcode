# LeetCode 字符串分组 题解

## 1. 题目概述

- **标题 / 题号**：字符串分组（#2157，hard）
- **链接**：https://leetcode.cn/problems/groups-of-strings/
- **来源**：LeetCode 第 278 场周赛 Q4
- **难度**：困难
- **标签**：位运算、并查集、数组、哈希表、字符串

**题意**：给定字符串数组 `words`，每个字符串只含小写字母且**每个字母至多出现一次**。称 $s_1$ 与 $s_2$ **关联**，若能通过以下三种操作之一从 $s_1$ 的**字母集合**得到 $s_2$ 的字母集合：往集合中**添加**一个字母；从集合中**删去**一个字母；把集合中一个字母**替换**成任意字母（也可以替换成它本身）。要求把 `words` 分成若干无交集的组，使得组内任意两字符串关联、组间任意两字符串不关联（方案唯一）。返回 $[\text{组数}, \text{最大组的字符串个数}]$。

**约束**：

- $1 \le \text{words.length} \le 2 \times 10^{4}$
- $1 \le |\text{words}[i]| \le 26$
- `words[i]` 只含小写字母，每个字母至多出现一次

> 💡 三个题设要点决定了整道题的形态：①「至多出现一次」意味着字符串**就是**一个字母集合，与顺序无关（`"ab"` 与 `"ba"` 无区别）；② 字母表只有 26 个，集合可以压成一个 26 位**整数掩码**；③ 操作只作用于集合，于是「关联」成为掩码之间的位运算关系。剩下的全部工作，是把「$O(n^2)$ 的两两配对」优化成「每个掩码主动枚举 $O(26^2)$ 个候选邻居再查表」。

## 2. 示例

**示例 1**

```text
输入：words = ["a","b","ab","cde"]
输出：[2,3]
解释："a" 与 "b"（替换 a→b）、"ab"（添加 b）关联，三者一组；
      "cde" 与谁都不关联，单独一组。共 2 组，最大组大小 3。
```

**示例 2**

```text
输入：words = ["a","ab","abc"]
输出：[1,3]
解释："a" 添加得 "ab"，"ab" 添加得 "abc"，全部关联，同组。
```

**示例 3（自构造：相同掩码）**

```text
输入：words = ["ab","ba","abc"]
输出：[1,3]
解释："ab" 与 "ba" 字母集合相同——相等集合靠「替换为自身」条款关联；
      "ab" 添加 c 得 "abc"。三者同组。
      若无该条款，相等集合将无法互达（加/删必然改变集合大小）。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是两两判断：对 $i < j$，计算 $m_i \oplus m_j$ 并按 popcount 分类判断是否关联，是则 `union(i, j)`。共 $\binom{n}{2} \approx 2 \times 10^{8}$ 对，每对 $O(1)$ 位运算——C++ 勉强危险，Python 必然超时。更糟的变体是对每个字符串枚举全部 $2^{26} \approx 6.7 \times 10^{7}$ 个掩码，完全不可行。

> ⚠️ $O(n^2)$ 的浪费在于：每个字符串的关联邻居其实**极少**——至多 $195$ 个（下证），却要和全部 $n = 2 \times 10^{4}$ 个字符串一一试探。突破口是反过来：不问「$b$ 与 $a$ 是否关联」，而是**主动生成 $a$ 的全部候选邻居，去哈希表里查在不在**。

### 3.2 核心观察：字母集合 ⟹ 26 位掩码 ⟹ 邻居枚举

![核心观察：字符串、字母集合与 26 位掩码，三种操作即三种位运算](images/2157_groups_mask_concept.svg)

记字符串 $w$ 的掩码为 $m(w) = \sum_{c \in S(w)} 2^{\,c}$（第 $c$ 位为 1 当且仅当字母 $c$ 出现），$\operatorname{pc}(m)$ 为 popcount。于是三种操作变成三种位运算：

| 操作 | 掩码形式 | 大小变化 |
|------|----------|----------|
| 添加 $c$ | $m \to m \,\mid\, 2^{c}$（$c \notin m$） | $\operatorname{pc}$ 加 1，子集关系 |
| 删除 $c$ | $m \to m \oplus 2^{c}$（$c \in m$） | $\operatorname{pc}$ 减 1，超集关系 |
| 替换 $c \to d$ | $m \to m \oplus 2^{c} \oplus 2^{d}$（$c \in m,\ d \notin m$） | $\operatorname{pc}$ 不变，对称差恰 2 位 |

**邻居数上界**：从掩码 $m$ 出发，添加候选至多 $26$ 个（$c$ 取不在 $m$ 中的字母），替换候选至多 $|m| \cdot (26 - |m|)$ 个（$c$ 取在 $m$ 中的、$d$ 取不在的，二者独立），而 $|m|(26-|m|)$ 在 $|m| = 13$ 时取最大值 $169$。合计每个掩码**至多 $26 + 169 = 195$ 个候选**，生成后去哈希表 $O(1)$ 查询——总代价 $195n \approx 3.9 \times 10^{6}$，比 $n^2 = 4 \times 10^{8}$ 直接降两个数量级。

分组本身是关联关系的**连通分量**（传递闭包），用**并查集**维护：每查到一个在表中的候选就 `union` 一次，最后数根、数组大小即可。

> 💡 这是「隐式图」建边的经典套路：图中节点是出现过的掩码（$\le 2 \times 10^{4}$ 个，存哈希表而非 $2^{26}$ 大数组），边不显式存，而是枚举候选现查现连。同类技巧见 1627（枚举倍数建边）、947（行列转点建边）。

### 3.3 算法流程

![算法流程：邻居枚举与删除—添加对称性，主动生成候选查表建边](images/2157_groups_neighbor_enum.svg)

1. **建掩码**：`mask[i]` = 第 $i$ 个字符串的 26 位掩码，$O(\sum |w_i|)$。
2. **第一趟（建全哈希表 + 合并重复）**：遍历 `mask`，`first[m]` 记录 $m$ 首次出现的下标；若 $m$ 已在表中，直接 `union(i, first[m])`——相同掩码靠「替换为自身」条款关联，必须同组。
3. **第二趟（枚举邻居建边）**：对每个 **unique** 掩码（即 `first[m] == i` 的代表下标 $i$）：
   - **添加**：对每个 $c \notin m$，候选 $m \mid 2^{c}$，查表命中则 `union`；
   - **替换**：对每个 $c \in m$、$d \notin m$，候选 $m \oplus 2^{c} \oplus 2^{d}$，查表命中则 `union`。
4. **统计**：对每个下标 `find` 取根；组数 = 不同根的个数，最大组大小 = 每个根下字符串个数（**含重复掩码的全部出现**）的最大值。

> 💡 **为什么删除不用枚举**：删除与添加是同一条边的两个方向——$a$ 删去 $c$ 得 $b$，等价于 $b$ 添加 $c$ 得 $a$。只要**每个掩码都枚举添加**，所有删除边必然会从对侧被发现一次。省掉这 26 个候选不是重点，重点是它揭示了「建边看双向」的一般原则。

> ⚠️ **两趟结构是省略删除的前提**：哈希表必须先建**全**再枚举。若边建边枚举（单趟），先处理的掩码会漏掉尚未入表的邻居，而我们又恰好不枚举删除——两边同时漏，得到错答。这是本题最隐蔽的实现陷阱（见 §8 第 1 条）。

### 3.4 示例演算

![示例演算：a、b、ab、cde 四个掩码的查表合并全过程](images/2157_groups_walkthrough.svg)

以 `words = ["a","b","ab","cde"]` 为例，四个掩码为 $1, 2, 3, 28$：

| 步骤 | 当前掩码 | 枚举与查表 | 结果 |
|------|----------|-----------|------------|
| ① 建表 | — | `first = {1:0, 2:1, 3:2, 28:3}`，无重复 | — |
| ② | $m=1$（"a"） | 添加：$1\mid2=3$ ✓；替换 a→b：$0\mid2=2$ ✓；其余候选 4, 5, 8, … ✗ | union(a, ab)、union(a, b) |
| ③ | $m=2$（"b"） | 添加：$2\mid1=3$ ✓；替换 b→a：$0\mid1=1$ ✓（已同组） | 无新组 |
| ④ | $m=3$（"ab"） | 添加候选 7, 11, 19, …、替换候选 5, 6, 9, 10, … 全部 ✗ | 无边 |
| ⑤ | $m=28$（"cde"） | 添加候选 29, 30, …、替换候选 25, 26, … 全部 ✗ | 独自成组 |

最终两个连通分量 $\{\text{"a","b","ab"}\}$（大小 3）与 $\{\text{"cde"}\}$（大小 1），返回 $[2, 3]$。

> 💡 注意 ② 中 "a" 与 "b" 互为**替换**邻居（大小相等、对称差 $\{a, b\}$ 恰 2 位），"a" 与 "ab" 互为**添加**邻居（子集、大小差 1）——三种关系在最小的例子里就占了两种。

## 4. 算法细节

1. **两趟不能合一（关键）**：`first` 表必须先整体建好，第二趟再枚举邻居。反例：单趟处理 `["a","ab"]`——处理 "a" 时 "ab" 尚未入表，添加候选 $3$ 查不到；轮到 "ab" 时，它到 "a" 的边是**删除**边，而我们不枚举删除——两边同时漏，`a` 与 `ab` 被错误拆开。若一定要单趟，就必须把删除也枚举上（对称地补齐），两种修复任选其一，但「两趟 + 省删除」是查表次数最少的组合。
2. **重复掩码的处理**：相同掩码（完全重复或 `"ab"`/`"ba"` 这类重排）在第一趟直接与代表合并，且第二趟只从代表下标枚举一次（相同掩码的候选集合完全相同）。统计组大小时按**出现次数**加权，而不是按 unique 掩码数。
3. **替换双重循环的约束是正确性问题，不只是优化**：必须限定 $c \in m$、$d \notin m$。若无约束地枚举全部 $26 \times 26$ 组合，$(c \notin m, d \notin m)$ 生成的是「两次添加」后的掩码、$(c \in m, d \in m)$ 生成的是「两次删除」后的掩码——它们与 $m$ **并不关联**，却会被查表命中并 union，造成**过度合并**，组数偏小、直接错答。
4. **哈希表而非大数组**：掩码空间 $2^{26} = 6.7 \times 10^{7}$，开 `int` 数组要 268MB；实际出现过的掩码至多 $2 \times 10^{4}$ 个，哈希表足够。
5. **并查集实现**：路径压缩（路径减半）+ 按大小合并，单次操作均摊近似 $O(\alpha(n))$。C++ 里按大小合并的 `sz[root]` 顺带就是组大小，可直接用于答案；Python 里统计阶段用 `Counter` 收集每个根的下标数即可。
6. **掩码用 `int` 足够**：26 位无符号需求，`1 << c`（$c \le 25$）在 `int` 范围内，无溢出风险；判断位用 `(m >> c) & 1`。

## 5. 正确性证明

记 $\Sigma$ 为 26 个小写字母，$S(w) \subseteq \Sigma$ 为字符串 $w$ 的字母集合，$m(w)$ 为其掩码。由题设每个字母至多出现一次，$w \leftrightarrow S(w)$ 双射（顺序无关）。

**引理 1（关联的掩码刻画）**：字符串 $u, v$ 关联，当且仅当下列之一成立：

- (i) $m(u) = m(v)$；
- (ii) $m(u) \subset m(v)$ 且 $\operatorname{pc}(m(v)) = \operatorname{pc}(m(u)) + 1$；
- (iii) $m(v) \subset m(u)$ 且 $\operatorname{pc}(m(u)) = \operatorname{pc}(m(v)) + 1$；
- (iv) $\operatorname{pc}(m(u)) = \operatorname{pc}(m(v))$ 且 $\operatorname{pc}(m(u) \oplus m(v)) = 2$。

**证明**：先证「关联 ⟹ (i)–(iv)」。设 $T$ 为从 $S = S(u)$ 经一次操作可得的集合，逐类讨论：

- **添加 $c$**：若 $c \in S$，则 $T = S$，得 (i)；否则 $T = S \cup \{c\}$，即 $m(u) \subset m(v)$ 且 popcount 差 1，得 (ii)。
- **删除 $c$（$c \in S$）**：$T = S \setminus \{c\}$，得 (iii)（以 $u$ 为大者方向）。
- **替换 $c \to d$（$c \in S$）**：若 $d = c$，$T = S$，得 (i)；若 $d \in S$ 且 $d \ne c$，则 $T = (S \setminus \{c\}) \cup \{d\} = S \setminus \{c\}$（$d$ 已在集合中），得 (iii)；若 $d \notin S$，则 $T = (S \setminus \{c\}) \cup \{d\}$，$|T| = |S|$ 且对称差恰为 $\{c, d\}$，得 (iv)。

再证「(i)–(iv) ⟹ 关联」：(i) 取任意 $c \in S(u)$（非空，因 $|\text{words}[i]| \ge 1$）替换为自身；(ii) 添加字母 $m(v) \setminus m(u)$ 对应位（由 (ii) 该差集恰一个元素且不在 $m(u)$ 中）；(iii) 对称地删除；(iv) 取 $c \in S(u) \setminus S(v)$、$d \in S(v) \setminus S(u)$（对称差恰这两个元素，故 $c \in S(u)$、$d \notin S(u)$），替换 $c \to d$ 得 $T = (S(u) \setminus \{c\}) \cup \{d\} = S(v)$。∎

**引理 2（删除—添加对称性）**：对掩码 $a, b$：$b = a \setminus \{c\}$（$c \in a$）当且仅当 $a = b \cup \{c\}$（$c \notin b$）。

**证明**：集合等式的直接改写。∎

**引理 3（无伪边）**：算法枚举的每个候选掩码若在 `first` 中命中，则命中者与当前掩码关联。

**证明**：候选仅有两种生成式。其一 $m' = m \mid 2^{c}$，$c \notin m$：由引理 1 反向部分，添加 $c$ 即从 $m$ 得 $m'$。其二 $m' = m \oplus 2^{c} \oplus 2^{d}$，$c \in m,\ d \notin m$：按位展开，$c$ 位由 1 变 0、$d$ 位由 0 变 1、其余不变，故 $m' = (m \setminus \{c\}) \cup \{d\}$，替换 $c \to d$ 即得。∎

**引理 4（全覆盖）**：设 $a \ne b$ 是数组中出现的两个掩码且其字符串关联，则第二趟枚举中至少有一次以 $a$ 或 $b$ 为起点的候选恰好命中对方。

**证明**：`first` 在第二趟开始前已包含**全部** unique 掩码，且每个 unique 掩码恰好从其代表下标枚举一次，故只需证明边 $(a, b)$ 在某一侧的候选集合中出现。由引理 1 分情况（$a \ne b$ 排除 (i)）：

- (ii) $a \subset b$，$b \setminus a = \{c\}$：$c \notin a$，处理 $a$ 时枚举添加 $c$ 得候选 $a \mid 2^{c} = b$，命中。
- (iii) $b \subset a$：由引理 2，$a = b \cup \{c\}$（$c = a \setminus b$ 的唯一元素），处理 $b$ 时枚举添加 $c$ 得候选 $a$，命中。
- (iv) $S(a) \setminus S(b) = \{c\}$，$S(b) \setminus S(a) = \{d\}$：$c \in a$；又 $d \notin a$（若 $d \in a$ 则 $d \in a \cap b$，与 $d \in S(b) \setminus S(a)$ 矛盾）。处理 $a$ 时枚举替换 $c \to d$，得候选 $(a \setminus \{c\}) \cup \{d\} = b$，命中。∎

**定理（正确性）**：算法返回的恰为 $[\text{组数}, \text{最大组大小}]$。

**证明**：题意所求分组是「组内关联、组间不关联」的唯一划分，即**关联图的连通分量**：任何满足「无跨组关联边」的划分中，同属一个连通分量的两个字符串必同组（否则沿路径必有一条跨组边），故连通分量给出唯一可行的最细划分。算法的并查集合并三类信息：① 相同掩码的重复下标（第一趟，合法性由引理 1 (i)）；② 枚举命中的边（第二趟，合法性由引理 3）。故并查集的每个连通分量都包含于某个关联图连通分量（**不会过度合并**）。反之，由引理 4，关联图中的每条边（含相同掩码的等价类）都被并查集直接或间接合并（**不会漏合并**），故二者连通分量完全一致。组数即不同根的个数；同一根下统计的是全部字符串下标（相同掩码的每次出现都计入），恰为该组字符串个数，取最大即 $\text{ans}[1]$。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(26^2 \cdot n\big)$。建掩码 $O(\sum |w_i|) \le O(26n)$；第二趟每个 unique 掩码枚举 $26 + |m|(26 - |m|) \le 195$ 个候选，总计至多 $195n \approx 3.9 \times 10^{6}$ 次哈希查询；并查集单次操作均摊 $O(\alpha(n))$。实测远低于上界——$|m| = 13$ 才取到替换候选的峰值 169，多数掩码远小。
- **空间复杂度**：$O(n)$。哈希表 `first` 至多 $2 \times 10^{4}$ 项，并查集 `parent` / `sz` 数组线性，掩码数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> groupStrings(vector<string>& words) {
        int n = words.size();
        vector<int> mask(n, 0);
        for (int i = 0; i < n; ++i)
            for (char c : words[i]) mask[i] |= 1 << (c - 'a');

        vector<int> parent(n), sz(n, 1);
        iota(parent.begin(), parent.end(), 0);
        auto find = [&](int x) {
            while (parent[x] != x) x = parent[x] = parent[parent[x]];
            return x;
        };
        auto unite = [&](int a, int b) {
            a = find(a), b = find(b);
            if (a == b) return;
            if (sz[a] < sz[b]) swap(a, b);
            parent[b] = a;
            sz[a] += sz[b];
        };

        // 第一趟：建全哈希表；相同掩码（替换为自身即关联）先合并
        unordered_map<int, int> first;
        for (int i = 0; i < n; ++i) {
            auto it = first.find(mask[i]);
            if (it == first.end()) first[mask[i]] = i;
            else unite(i, it->second);
        }

        // 第二趟：每个 unique 掩码只从代表下标枚举一次
        for (int i = 0; i < n; ++i) {
            if (first[mask[i]] != i) continue;
            int m = mask[i];
            for (int c = 0; c < 26; ++c) {          // 添加 c（删除由对侧的添加覆盖）
                if (m >> c & 1) continue;
                auto it = first.find(m | (1 << c));
                if (it != first.end()) unite(i, it->second);
            }
            for (int c = 0; c < 26; ++c) {          // 替换 c -> d（c ∈ m，d ∉ m）
                if (!(m >> c & 1)) continue;
                int mc = m ^ (1 << c);
                for (int d = 0; d < 26; ++d) {
                    if (m >> d & 1) continue;
                    auto it = first.find(mc | (1 << d));
                    if (it != first.end()) unite(i, it->second);
                }
            }
        }

        // sz[root] 在按大小合并下恰为组内字符串个数
        int groups = 0, best = 0;
        for (int i = 0; i < n; ++i)
            if (find(i) == i) ++groups, best = max(best, sz[i]);
        return {groups, best};
    }
};
```

### Python

```python
class Solution:
    def groupStrings(self, words: List[str]) -> List[int]:
        n = len(words)
        mask = [0] * n
        for i, w in enumerate(words):
            for c in w:
                mask[i] |= 1 << (ord(c) - 97)

        parent = list(range(n))
        size = [1] * n

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]   # 路径减半
                x = parent[x]
            return x

        def union(a, b):
            ra, rb = find(a), find(b)
            if ra == rb:
                return
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            size[ra] += size[rb]

        # 第一趟：建全哈希表；相同掩码（替换为自身即关联）先合并
        first = {}
        for i, m in enumerate(mask):
            if m in first:
                union(i, first[m])
            else:
                first[m] = i

        # 第二趟：每个 unique 掩码只从代表下标枚举一次
        for i, m in enumerate(mask):
            if first[m] != i:
                continue
            for c in range(26):
                if not m >> c & 1:              # 添加 c（删除由对侧的添加覆盖）
                    cand = m | (1 << c)
                    if cand in first:
                        union(i, first[cand])
            for c in range(26):
                if m >> c & 1:                  # 替换 c -> d（c ∈ m，d ∉ m）
                    mc = m ^ (1 << c)
                    for d in range(26):
                        if not m >> d & 1:
                            cand = mc | (1 << d)
                            if cand in first:
                                union(i, first[cand])

        cnt = Counter(find(i) for i in range(n))
        return [len(cnt), max(cnt.values())]
```

> 💡 两份代码结构完全对齐：两趟循环 + 双重枚举。C++ 利用按大小合并的 `sz[root]` 直接读出组大小；Python 用 `Counter` 统计每个根的下标数，语义相同。

## 8. 边界情况与易错点

1. **单趟 + 不枚举删除 = 漏边（最隐蔽）**：若把建表和枚举合并成一趟，先处理的掩码查不到后入表的邻居，而它到后者的边又可能是删除边（我们不枚举）——例如 `["a","ab"]` 会得到错误答案 `[2,1]`。修复：先建全表再枚举（本文做法），或单趟时把删除也枚举上。
2. **替换枚举缺约束 = 伪边（错答而非超时）**：双重循环必须限定 $c \in m$、$d \notin m$。无约束时会生成「两次添加/两次删除」的掩码——与 $m$ 不关联却被 union，组数偏小。这不是常数优化，是正确性的一部分。
3. **相同掩码必须同组**：`"ab"` 与 `"ba"`（重排）、重复字符串的掩码相同，靠「替换为自身」条款关联；第一趟合并 + 出现次数加权缺一不可。漏掉会把 `["ab","ba"]` 错拆成两组。
4. **$\text{ans}[1]$ 按字符串个数计**：含重复掩码的每一次出现，不是 unique 掩码数。
5. **不要开 $2^{26}$ 的数组**：268MB 直接超内存；出现过的掩码至多 $2 \times 10^{4}$ 个，用哈希表。
6. **全字母单词（26 个字母）**：添加候选与替换候选都为空集（没有 $d \notin m$），它只能靠**别人的添加边**入组——对称性设计恰好覆盖，无需特判。
7. **$n = 1$**：返回 `[1, 1]`，两趟结构天然覆盖。
8. **位运算书写**：`m >> c & 1`（移位先于按位与）合法但建议加括号 `(m >> c) & 1` 提升可读性；`1 << c` 的 $c \le 25$，`int` 无溢出。
