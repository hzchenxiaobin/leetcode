# LeetCode 将找到的值乘以 2 题解

## 1. 题目概述

- **标题 / 题号**：将找到的值乘以 2（#2154，easy）
- **链接**：https://leetcode.cn/problems/keep-multiplying-found-values-by-two/
- **来源**：LeetCode 第 278 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、模拟

**题意**：给定整数数组 `nums` 与整数 `original`。只要 `original` 在 `nums` 中出现，就把它**翻倍**（`original = 2 × original`），并对新值重复这一过程；一旦 `original` 不在 `nums` 中，立即停止。返回 `original` 的最终值。

**约束**：

- `1 <= nums.length <= 1000`
- `1 <= nums[i], original <= 1000`

## 2. 示例

**示例 1**

```text
输入：nums = [5,3,6,1,12], original = 3
输出：24
解释：3 → 6 → 12 → 24 都能在 nums 中依次找到，24 不在 nums 中，返回 24。
```

**示例 2**

```text
输入：nums = [2,7,9], original = 4
输出：4
解释：4 一开始就不在 nums 中，过程未发生任何翻倍，返回 4。
```

**示例 3（链走到值域尽头）**

```text
输入：nums = [1,2,4,8,16,32,64,128,256,512,1024], original = 1
输出：2048
解释：链上每个 2 的幂都命中，1024 翻倍得 2048，超出值域 1000 必然失配，返回 2048。
```

## 3. 解题思路

### 3.1 暴力思路

直接按题面模拟：每轮用一次 $O(n)$ 的线性扫描判断 `original` 是否在 `nums` 中，命中就翻倍。由约束 `nums[i] ≤ 1000` 可知 `original` 翻倍极少几轮就会超出 1000 而必然失配（起点 `original ≥ 1`，至多 11 次翻倍），总开销约 $O(n \log(\max V)) \approx 1.2 \times 10^4$，完全能过。

但这道题的"本质"是一连串**存在性查询**——每次都全量扫数组是浪费，把查询降到 $O(1)$ 是举手之劳，也是签到题里值得沉淀的套路。

### 3.2 核心观察：哈希集合 + 翻倍链

![翻倍链概念：装入集合后沿链走到链尾](images/2154_double_chain_concept.svg)

两个关键观察：

- **查询可加速**：把 `nums` 一次性装进哈希集合 $S$，每轮"在不在 `nums` 中"从 $O(n)$ 降为 $O(1)$；
- **翻倍链有上界**：`original` 每轮严格翻倍，从 1 出发也只需 11 次就达到 $2^{11} = 2048 > 1000 \ge \max(nums)$，此后必然失配。链长 $L \le 11$，循环天然终止，**无需任何哨兵或特判**。

### 3.3 算法流程

![算法流程：查询翻倍循环直到失配](images/2154_double_loop_flow.svg)

1. 建集合：$S \leftarrow \text{set}(nums)$；
2. 循环：只要 `original` $\in S$，就执行 `original ← original × 2`；
3. 失配时返回当前 `original`。

集合**建好后再不修改**：命中后下一轮查询的是新值，把旧值从集合里"删掉"是常见的过度设计（删了也不错，但毫无必要，见 §8）。

### 3.4 示例演算

![示例走查：3 → 6 → 12 → 24](images/2154_double_walkthrough.svg)

以示例 1 为例：查询 `3` 命中（下标 1）→ 翻倍为 `6`；查询 `6` 命中（下标 2）→ 翻倍为 `12`；查询 `12` 命中（下标 4）→ 翻倍为 `24`；查询 `24` 失配，返回 **24**。全程 4 次查询、3 次翻倍。

## 4. 算法细节

1. **建集合的姿势**：C++ 用 `unordered_set<int> s(nums.begin(), nums.end())`，Python 用 `s = set(nums)`，都是一次 $O(n)$ 构建。
2. **链长上界推导**：设起点为 $v_0 \ge 1$，第 $k$ 次翻倍后 $v_k = 2^k v_0 \ge 2^k$。当 $k = 11$ 时 $v_k \ge 2048 > 1000 \ge nums[i]$，故第 12 次查询必失败，翻倍至多发生 11 次。这个上界同时保证了**终止性**与"答案最大 2048，`int` 无溢出风险"。
3. **值域桶替代**：值域仅 $[1, 1000]$，也可用长度 1001 的布尔数组（或 `bitset<1001>`）标记出现，查询同为 $O(1)$ 且无哈希开销；但查询前必须加 `original <= 1000` 的下标保护（见 §8）。
4. **重复元素**：`nums` 中同一值出现多次毫无影响，集合自动去重；每轮查询的是"值是否存在"，与出现次数、位置无关。

## 5. 正确性证明

**引理 1**（终止性）：算法的循环至多进行 12 次查询、11 次翻倍。

**证明**：查询的值依次为 $v_0, v_1 = 2v_0, \dots, v_k = 2^k v_0$。由 $v_0 \ge 1$ 得 $v_{11} \ge 2048 > 1000 \ge nums[i]$，故 $v_{11} \notin S$，第 12 次查询必为假，循环终止。∎

**引理 2**（查询等价）：算法循环中判断 `original ∈ S` 与题意"original 在 nums 中"逐轮等价。

**证明**：$S$ 的成员关系由建集合那一刻的 `nums` 唯一决定，此后算法只修改 `original`、从不修改 $S$，故对任意待查值 $x$，`x ∈ nums ⟺ x ∈ S` 在全程保持。∎

**定理**：算法返回值等于按题意规则执行（找到即翻倍、找不到即停止）后的最终 `original`。

**证明**：对成功翻倍的轮数 $k$ 归纳。$k=0$：首轮查询即失败，题意与算法都原样返回 $v_0$。设第 $k$ 轮双方查询同一值 $v_k$，由引理 2 判断结果一致：为真则双方都翻倍进入第 $k+1$ 轮且规则自同构，为假则双方都停止并返回 $v_k$。由引理 1 过程必然停止，归纳完成。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + L)$，其中 $L \le 11$ 是翻倍链长。建集合 $O(n)$ 主导；循环内每次 $O(1)$ 哈希查询 + $O(1)$ 翻倍，合计不超过 12 次查询、11 次翻倍。
- **空间复杂度**：$O(n)$，哈希集合存储全部元素。暴力扫描做法空间 $O(1)$、时间 $O(nL) \approx 1.2 \times 10^4$，在本题数据下同样通过；值域桶做法时间 $O(n + V + L)$、空间 $O(V)$，$V = 1001$。

## 7. 参考代码

### C++（哈希集合）

```cpp
class Solution {
public:
    int findFinalValue(vector<int>& nums, int original) {
        unordered_set<int> s(nums.begin(), nums.end());
        while (s.count(original)) {
            original *= 2;
        }
        return original;
    }
};
```

### C++（值域桶）

```cpp
class Solution {
public:
    int findFinalValue(vector<int>& nums, int original) {
        bitset<1001> seen;
        for (int x : nums) seen.set(x);
        while (original <= 1000 && seen[original]) {
            original *= 2;
        }
        return original;
    }
};
```

### Python（哈希集合）

```python
class Solution:
    def findFinalValue(self, nums: List[int], original: int) -> int:
        s = set(nums)
        while original in s:
            original *= 2
        return original
```

### Python（暴力，最短写法）

```python
class Solution:
    def findFinalValue(self, nums: List[int], original: int) -> int:
        while original in nums:
            original *= 2
        return original
```

## 8. 边界情况与易错点

1. **起点即失配**：`original` 一开始就不在 `nums` 中（示例 2），`while` 循环零次执行、原样返回，无需特判。
2. **桶做法越界**：`original` 翻倍可达 2048，超过桶长 1001——`seen[original]` 前必须先判 `original <= 1000`，否则越界；哈希做法无此顾虑。
3. **不要"删除"命中元素**：误以为命中后要从集合中删掉旧值防止"重复使用"，是本题最常见的想多了——下一轮查询的是新值 `original × 2`，旧值是否留在集合里毫无影响。
4. **不会死循环**：值域上界保证链长 $\le 11$，无需设轮数上限或哨兵；答案上界 2048，`int` 不溢出。
5. **重复元素无影响**：`nums` 含重复值时集合自动去重，不影响任何一轮判断。
