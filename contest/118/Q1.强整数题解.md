# LeetCode 强整数 题解

## 1. 题目概述

- **标题 / 题号**：强整数（#970，medium）
- **链接**：https://leetcode.cn/problems/powerful-integers/
- **来源**：LeetCode 第 118 场周赛 Q1
- **难度**：中等
- **标签**：哈希表、数学、枚举

**题意**：给定三个整数 $x$、$y$ 和 $bound$。若整数可以写成

$$x^i + y^j \quad (i \ge 0,\ j \ge 0)$$

则称它是**强整数**。返回所有**小于或等于** $bound$ 的强整数组成的列表，列表内每个值**最多出现一次**，顺序任意。

**约束**：

- $1 \le x, y \le 100$
- $0 \le bound \le 10^6$

> 💡 这题的关键不是「怎么表示」，而是「要枚举多少个指数」——把指数范围从 $bound$ 压到 $\log bound$，问题就从不可做变成两重小循环。

## 2. 示例

**示例 1**

```text
输入：x = 2, y = 3, bound = 10
输出：[2,3,4,5,7,9,10]
解释：
2  = 2^0 + 3^0          3  = 2^1 + 3^0          4  = 2^0 + 3^1
5  = 2^1 + 3^1          7  = 2^2 + 3^1          9  = 2^3 + 3^0
10 = 2^0 + 3^2
（2^2 + 3^2 = 13 > 10，更大的指数只会更大）
```

**示例 2**

```text
输入：x = 3, y = 5, bound = 15
输出：[2,4,6,8,10,14]
解释：3 的幂为 1,3,9；5 的幂为 1,5,25(>15 已越界)。
      两两求和落在 [0,15] 内的恰为 2,4,6,8,10,14。
```

**示例 3（边界）**

```text
输入：x = 1, y = 1, bound = 1
输出：[]
解释：1^0 + 1^0 = 2 > 1，没有任何强整数；注意 x = 1 时幂恒为 1，不能无限枚举。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是双重循环枚举 $i$ 与 $j$，把满足 $x^i + y^j \le bound$ 的和塞进集合。问题是**指数的上界**：若照抄 $i, j \le bound$，那么 $x = y = 1$ 时循环次数是 $(10^6)^2$，即使 $x = y = 2$ 也会白算十几个已经溢出的指数。暴力本身不慢，**枚举范围没想清楚**才是坑。

### 3.2 核心观察：幂只有 $O(\log bound)$ 项

![幂序列长度只有对数级：指数枚举范围被 bound 卡死](images/wc118_q1_powers_table.svg)

只要 $x \ge 2$，幂序列 $1, x, x^2, x^3, \dots$ **严格递增**，于是「$x^i \le bound$」等价于「$i \le \lfloor \log_x bound \rfloor$」。由 $bound \le 10^6$：

- $x \ge 2$ 时，指数个数不超过 $\lfloor \log_2 10^6 \rfloor + 1 = 20$；
- $x = 1$ 时，$1^i \equiv 1$，幂序列**退化为一个元素**——枚举到 $1$ 就该停，否则会原地打转。

两边都只有 $O(\log bound)$ 项，两两求和的总量不超过 $20 \times 20 = 400$，用集合去重即可。

### 3.3 算法流程

![算法流程：外层枚举 x 的幂，内层枚举 y 的幂并去重](images/wc118_q1_algorithm_flow.svg)

```text
1. res = 空集合
2. a = 1
3. while a <= bound:
       b = 1
       while a + b <= bound:
           把 a + b 放入 res
           if y == 1: break        # 1 的幂恒为 1，枚举一次就停
           b = b * y
       if x == 1: break            # 同上，防止死循环
       a = a * x
4. 返回 res 的升序列表
```

两个 `break` 是本题的**正确性开关**：没有它们，$x = 1$ 或 $y = 1$ 就会写出死循环（或写出无意义的重复枚举）。

### 3.4 示例演算

对示例 1（$x = 2, y = 3, bound = 10$）做一次完整走查。行是 $2^i$，列是 $3^j$，格子里是两两之和，超过 $10$ 的划掉：

| $2^i \backslash 3^j$ | $1$ | $3$ | $9$ |
|---|---|---|---|
| $1$ | 2 ✓ | 4 ✓ | 10 ✓ |
| $2$ | 3 ✓ | 5 ✓ | 11 ✗ |
| $4$ | 5 ✓ | 7 ✓ | 13 ✗ |
| $8$ | 9 ✓ | 11 ✗ | 17 ✗ |

有效的和是 $\{2,3,4,5,7,9,10\}$（其中 $5$ 被算了两遍，集合去重后只留一个），恰好等于示例输出。

## 4. 算法细节

1. **用 `while` 而非 `for`**：循环变量 `a`、`b` 每次自乘 $x$、$y$，条件里已经是「$a \le bound$」「$a + b \le bound$」，不需要预先算出对数的上界，也就不必处理浮点误差。
2. **两个 `== 1` 的短路**：$x = 1$ 时若继续 `a *= x`，`a` 永远是 $1$，外层死循环；$y = 1$ 同理影响内层。写成「本轮枚举完就 `break`」最直观。
3. **内层条件用 `a + b <= bound`**：一旦越界，后续的 $b$ 只会更大（$y \ge 1$ 时 $b$ 不减），可以直接退出内层；这也顺带保证不会把越界的和放进集合。
4. **去重**：C++ 用 `set`（有序 + 去重一步到位），Python 用 `set` 后 `sorted` 输出。若题目不要求顺序，直接返回集合转列表即可。
5. **整数类型**：`bound` 只有 $10^6$，`a * x` 最大约 $10^8$，`int` 也不会溢出；但用 `long long` 更稳妥，避免把 $x$ 换成更大值域时踩坑。

## 5. 正确性证明

**引理 1（幂序列完备）**：对任意 $x \ge 1$，算法中 `a` 取遍的值恰为 $\{x^0, x^1, \dots, x^k\}$，其中 $k$ 是满足 $x^k \le bound$ 的最大指数（$x = 1$ 时只有 $x^0 = 1$）。

**证明**：`a` 从 $1 = x^0$ 出发，每次循环体结束后执行 `a = a * x`，故 `a` 依次取值 $x^0, x^1, x^2, \dots$；循环条件 `a <= bound` 保证只在 $x^i \le bound$ 时进入循环体。因 $x \ge 1$ 时 $x^i$ 单调不减，一旦 $x^k > bound$ 就不再进入，故取到的正是 $x^0, \dots, x^k$。$x = 1$ 时 `x == 1` 的 `break` 让循环只执行一次，恰为 $x^0$。∎

**引理 2（不重不漏）**：集合 `res` 恰好包含所有形如 $x^i + y^j \le bound$ 的整数，且各元素只存一份。

**证明**：由引理 1，外层遍历了所有满足 $x^i \le bound$ 的指数 $i$，内层遍历了所有满足 $x^i + y^j \le bound$ 的指数 $j$（同理，`b` 取遍 $y^0, y^1, \dots$，且在 `a + b > bound` 时立即停止——因 $y \ge 1$ 时 $b$ 单调不减，更大的 $j$ 必然更越界）。故每个合法和都被枚举至少一次；若 $x^i + y^j > bound$，则它既不在内层被加入（条件不满足），也不可能由别的指数组合进入，故不会多算。集合的语义保证重复加入自动合并。∎

**定理**：算法返回的列表恰为所有不超过 $bound$ 的强整数，每个值出现一次。

**证明**：设 $S$ 为题目定义的强整数集合，$R$ 为算法返回集合。由引理 2，$R$ 的元素都是形如 $x^i + y^j$ 且 $\le bound$ 的整数，故 $R \subseteq S$。反之任取 $v \in S$，存在 $i, j \ge 0$ 使 $v = x^i + y^j \le bound$，于是 $x^i \le v \le bound$ 且 $y^j \le v \le bound$，由引理 1 该对 $(i, j)$ 会被枚举，故 $v \in R$。结合去重与排序，返回值与 $S$ 作为集合相等，每个值恰出现一次。∎

## 6. 复杂度分析

- **时间**：$O(\log_x bound \cdot \log_y bound)$ 次求和，即最坏 $O(\log^2 bound)$；本题 $bound \le 10^6$ 时不超过 $20 \times 20 = 400$ 次循环，可视为常数。排序去重为 $O(m \log m)$，$m \le 400$。
- **空间**：$O(m)$，$m$ 为不同强整数个数，最坏不超过 $400$；`set` 与结果列表各占一份。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> powerfulIntegers(int x, int y, int bound) {
        set<int> res;
        for (long long a = 1; a <= bound; a *= x) {
            for (long long b = 1; a + b <= bound; b *= y) {
                res.insert((int)(a + b));
                if (y == 1) break;   // 1 的幂恒为 1，只枚举一次
            }
            if (x == 1) break;       // 同上，否则死循环
        }
        return vector<int>(res.begin(), res.end());
    }
};
```

### Python

```python
class Solution:
    def powerfulIntegers(self, x: int, y: int, bound: int) -> list[int]:
        res = set()
        a = 1
        while a <= bound:
            b = 1
            while a + b <= bound:
                res.add(a + b)
                if y == 1:
                    break
                b *= y
            if x == 1:
                break
            a *= x
        return sorted(res)
```

## 8. 边界情况与易错点

1. **$x = 1$ 或 $y = 1$ 导致死循环**：这是本题最大的坑。$1$ 的任何次幂都是 $1$，若不特判，`while a <= bound` 永不退出。示例 3 就是专门用来打这个点的。
2. **$bound = 0$**：$x^0 + y^0 = 2 > 0$，答案必须是空列表，直接返回 `[]`，不能因为「循环一次都没进」就误判为异常。
3. **$x = y$**：两个幂序列相同，会出现大量重复，必须去重。注意和不一定形如 $2x^i$——指数不同也可以配（如 $x = y = 2, bound = 10$，$3 = 2^1 + 2^0$ 也合法），正确答案是 $[2,3,4,5,6,8,9,10]$。
4. **重复求和的来源不止重复幂**：不同指数对也可能给出同一个和（如 $2 + 3 = 3 + 2$ 型），所以去重必须落在「和」上，而不是在指数层去重。
5. **不要用浮点算指数上界**：`(int)(log(bound) / log(x))` 在边界值上会因精度少算或多算一项，用 `while` 边乘边判更稳。
6. **输出顺序**：题目允许任意顺序，但本仓库统一返回升序，方便对拍与阅读。
