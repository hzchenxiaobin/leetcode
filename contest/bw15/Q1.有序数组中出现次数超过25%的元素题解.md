# LeetCode 有序数组中出现次数超过25%的元素 题解

## 1. 题目概述

- **标题 / 题号**：有序数组中出现次数超过25%的元素（#1287，easy）
- **链接**：https://leetcode.cn/problems/element-appearing-more-than-25-in-sorted-array/
- **来源**：LeetCode 第 15 场双周赛 Q1
- **难度**：简单
- **标签**：数组、二分查找

**题意**：给定一个**非递减**的有序整数数组 `arr`，已知其中**恰好有一个**整数出现次数超过数组元素总数的 25%。找到并返回这个整数。

**约束**：

- $1 \le arr.length \le 10^4$
- $0 \le arr[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,2,6,6,6,6,7,10]
输出：6
解释：6 出现 4 次，4 > 9 × 25% = 2.25。
```

**示例 2**

```text
输入：arr = [1,1]
输出：1
解释：1 出现 2 次，2 > 2 × 25% = 0.5。
```

**补充示例**

```text
输入：arr = [1,1,2,3]
输出：1
解释：n = 4，阈值 1；只有 1 出现 2 次，2 > 1。

输入：arr = [42]
输出：42
解释：单元素数组，42 出现 1 次，1 > 0.25。
```

## 3. 解题思路

### 3.1 暴力思路

一遍扫描用哈希表（或 `Counter`）计数，返回出现次数 $> n/4$ 的那个数——$O(n)$ 时间、$O(n)$ 空间。$n \le 10^4$ 完全能过，比赛先交这版保底毫无问题。但既然数组**有序**，这个信息被哈希版完全浪费了；而且"超过 25%"意味着该元素占据了数组的**连续一大段**，有序性理应换来更好的复杂度——$O(\log n)$ 才是本题的"满分解"。

### 3.2 核心观察：超长连续段必跨四分点

![出现超过 n/4 次的元素必占据四分点之一](images/bw15_q1_quarter_points.svg)

设 $n = arr.length$。因为数组有序，目标元素 $x$ 的所有出现构成**连续段** $[l, r]$，长度 $m = r - l + 1 > n/4$。取三个**四分点下标**：

$$q_1 = \left\lfloor \tfrac{n}{4} \right\rfloor,\qquad q_2 = \left\lfloor \tfrac{n}{2} \right\rfloor,\qquad q_3 = \left\lfloor \tfrac{3n}{4} \right\rfloor$$

直觉：这三个点把下标轴切成四段，每段长度都不足 $m$（都不超过 $\lfloor n/4 \rfloor$），一个比每段都长的连续段**必然跨过其中某个四分点**，即 $x \in \{arr[q_1], arr[q_2], arr[q_3]\}$——只需检查 **3 个候选值**。

### 3.3 算法流程：3 候选 + 二分验证

![候选验证流程：二分求出现次数再核对阈值](images/bw15_q1_verify_flow.svg)

1. 取候选 $arr[q_1], arr[q_2], arr[q_3]$（可能有重复，无妨）；
2. 对每个候选 $x$：二分找到其**第一次**出现（`lower_bound`，第一个 $\ge x$）与**最后一次**出现的下一个位置（`upper_bound`，第一个 $> x$），出现次数 $= \text{hi} - \text{lo}$；
3. 返回满足 $4 \times count > n$ 的候选（题目保证恰有一个存在）。

比较用整数运算 $4m > n$ 精确等价于 $m > n/4$，避免任何浮点误差。

### 3.4 示例演算

![示例演算：n=9 时三个候选与 6 的验证](images/bw15_q1_example_walkthrough.svg)

以示例 1 为例：$n = 9$，四分点 $q_1 = 2$、$q_2 = 4$、$q_3 = 6$，候选为 $arr[2] = 2$、$arr[4] = 6$、$arr[6] = 6$。验证：

- 候选 2：出现区间 $[1,2]$，次数 $2$，$4 \times 2 = 8 \le 9$，否；
- 候选 6：出现区间 $[3,6]$，次数 $4$，$4 \times 4 = 16 > 9$ ✓，返回 6。

补充示例 $[1,1]$：$n = 2$，$q_1 = q_2 = q_3$ 均 $\in \{0, 1\}$，候选就是 $1$，次数 $2$，$8 > 2$ ✓。注意 $n < 4$ 的情形三个四分点可能重合甚至都指向同一元素，候选集合缩小到 $1$ 个，依然正确（$n \le 3$ 时唯一答案必然占满大半数组）。

## 4. 算法细节

1. **四分点用下取整**：$q_1 = \lfloor n/4 \rfloor$ 等保证 $0 \le q_i \le n-1$ 恒成立（$n \ge 1$ 时 $\lfloor 3n/4 \rfloor \le n - 1$），无需特判越界。
2. **二分取边界**：C++ 直接 `lower_bound` / `upper_bound`；Python 手写两轮二分（`bisect` 亦可）：第一轮找第一个 $\ge x$ 的位置 `lo`，第二轮在其后找第一个 $> x$ 的位置 `hi`，次数 $= hi - lo$。有序数组中相等元素连续，两个边界夹出的就是全部出现。
3. **整数化比较**："$> n/4$" 写成 $4 \cdot m > n$。$m$ 最大 $10^4$，乘 4 不会溢出。
4. **候选重复无妨**：同一候选可能被验证两遍，多花 $O(\log n)$ 而已；也可以去重后再验，实现差别不大。
5. **"恰好一个"的保证**：三个候选中至少一个是答案（3.2 的观察），且答案只有一个，所以"第一个通过验证的候选"即答案；`return -1` 分支按题意不可达，纯属防御性写法。

## 5. 正确性证明

**引理 1（连续段）**：非递减数组中，值 $x$ 的全部出现构成连续下标区间 $[l_x, r_x]$。

**证明**：若 $arr[i] = arr[j] = x$ 且 $i < j$，则对任意 $i < k < j$，$arr[i] \le arr[k] \le arr[j]$，即 $arr[k] = x$。∎

**引理 2（四分点覆盖）**：任何满足 $m > n/4$ 的连续下标区间 $[l, r]$（$r - l + 1 = m$）必包含 $q_1$、$q_2$、$q_3$ 中至少一个。

**证明**：反设 $[l,r]$ 与三个四分点都不相交，则它整个落在四分点切出的四个间隙之一：

- $G_0 = [0, q_1 - 1]$，长度 $q_1 = \lfloor n/4 \rfloor$；
- $G_1 = [q_1 + 1, q_2 - 1]$，长度 $\lfloor n/2 \rfloor - \lfloor n/4 \rfloor - 1$；
- $G_2 = [q_2 + 1, q_3 - 1]$，长度 $\lfloor 3n/4 \rfloor - \lfloor n/2 \rfloor - 1$；
- $G_3 = [q_3 + 1, n - 1]$，长度 $n - 1 - \lfloor 3n/4 \rfloor$。

设 $n = 4t + r$（$r \in \{0,1,2,3\}$），逐一验证四个间隙的长度都不超过 $t$：

- $|G_0| = \lfloor n/4 \rfloor = t$；
- $|G_1| = \lfloor n/2 \rfloor - \lfloor n/4 \rfloor - 1 \le (2t+1) - t - 1 = t$；
- $|G_2| = \lfloor 3n/4 \rfloor - \lfloor n/2 \rfloor - 1 \le (3t+2) - (2t+1) - 1 = t$；
- $|G_3| = n - 1 - \lfloor 3n/4 \rfloor$，按余数展开：$r=0$ 时 $(4t-1)-3t = t-1$；$r=1$ 时 $4t-3t = t$；$r=2$ 时 $(4t+1)-(3t+1) = t$；$r=3$ 时 $(4t+2)-(3t+2) = t$，均 $\le t$。

而 $m > n/4$ 且 $m$ 为整数 $\Rightarrow m \ge \lfloor n/4 \rfloor + 1 = t + 1 > t$，四个间隙都塞不下长度为 $m$ 的区间 $[l, r]$，与反设矛盾。∎

**定理**：候选集 $\{arr[q_1], arr[q_2], arr[q_3]\}$ 包含答案 $x$，且验证步骤正确返回 $x$。

**证明**：$x$ 的出现区间长度 $m > n/4$（题设），由引理 2 它包含某个四分点 $q$，于是 $arr[q] = x$（区间内所有元素值都是 $x$，引理 1），候选集含 $x$。验证时对候选 $x$ 二分求出 $[l_x, r_x]$ 的边界，次数 $m$ 满足 $4m > n$，通过验证；由"恰好一个元素超 25%"的题设，其他候选值 $y \ne x$ 的出现次数 $\le n/4$，验证不通过。故算法返回 $x$。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。至多 3 个候选，每个候选两次二分；比哈希计数的 $O(n)$ 快一个数量级（虽然 $n \le 10^4$ 时两者体感相同）。
- **空间**：$O(1)$。只存三个候选与常数个指针；哈希表版是 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findSpecialInteger(vector<int>& arr) {
        int n = arr.size();
        int cand[3] = {arr[n / 4], arr[n / 2], arr[3 * n / 4]};   // 三个四分点候选
        for (int x : cand) {
            int lo = lower_bound(arr.begin(), arr.end(), x) - arr.begin();  // 第一个 >= x
            int hi = upper_bound(arr.begin(), arr.end(), x) - arr.begin();  // 第一个 >  x
            if (4 * (hi - lo) > n) return x;   // 出现次数 > n/4
        }
        return -1;                              // 题目保证存在，不会到达
    }
};
```

### Python

```python
class Solution:
    def findSpecialInteger(self, arr: List[int]) -> int:
        n = len(arr)

        def count(x: int) -> int:          # 二分求 x 的出现次数
            lo, hi = 0, n                  # 第一个 >= x
            while lo < hi:
                mid = (lo + hi) // 2
                if arr[mid] < x:
                    lo = mid + 1
                else:
                    hi = mid
            left = lo
            hi = n                         # 第一个 > x
            while lo < hi:
                mid = (lo + hi) // 2
                if arr[mid] <= x:
                    lo = mid + 1
                else:
                    hi = mid
            return lo - left

        for x in (arr[n // 4], arr[n // 2], arr[3 * n // 4]):   # 三个四分点候选
            if 4 * count(x) > n:                                # 出现次数 > n/4
                return x
        return -1                        # 题目保证存在，不会到达
```

> 💡 两份代码均通过官方 2 组示例（输出 `6`、`1`）以及 310 组随机测试：数据按"恰好一个超 25% 元素"构造，与独立的 `Counter` 计数参考对拍 `mismatch = 0`；覆盖 $n = 1, 2, 3$（三个四分点重合）、$n = 10^4$（性能边界）等关键情形。

## 8. 边界情况与易错点

1. **$n \le 3$ 的退化情形**：三个四分点 $\lfloor n/4 \rfloor, \lfloor n/2 \rfloor, \lfloor 3n/4 \rfloor$ 可能指向同一个元素（$n=1$ 时都是 0）甚至不足 3 个不同值；候选去不去重都行，但**别写成**假设三候选互异。
2. **"超过"是严格大于**：出现次数恰为 $n/4$（$n$ 是 4 的倍数）的元素**不**是答案，比较用 $4m > n$ 而非 $\ge$；浮点 `count > n / 4` 在 Python 中其实安全（`/` 是真除法），但在 C++ 里 `n / 4` 是整除，会错误地把 $m = n/4$ 也判真——必须乘 4 或用浮点。
3. **答案"恰好一个"**：如果去掉该保证（比如允许 0 个），验证失败时需要明确返回值；本题 `return -1` 不可达，但写出来是防御性的好习惯。
4. **别把阈值想成"最多 25%"**：$m > n/4$ 的连续段至少长 $\lfloor n/4 \rfloor + 1$，引理 2 的证明正是吃满这个"+1"。
5. **二分边界含义**：`lower_bound` 返回第一个 $\ge x$、`upper_bound` 返回第一个 $> x$，两者相减即出现次数——不要用 `upper - lower + 1`（会多数 1）。
6. **有序性是前提**：3 候选法依赖引理 1 的连续段；输入若乱序，此法完全失效（那就退回哈希）。
