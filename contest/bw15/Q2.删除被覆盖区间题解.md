# LeetCode 删除被覆盖区间 题解

## 1. 题目概述

- **标题 / 题号**：删除被覆盖区间（#1288，medium）
- **链接**：https://leetcode.cn/problems/remove-covered-intervals/
- **来源**：LeetCode 第 15 场双周赛 Q2
- **难度**：中等
- **标签**：数组、排序

**题意**：给定区间列表 `intervals`，其中 `intervals[i] = [a, b]`。当且仅当存在区间 $[c, d]$ 满足 $c \le a$ 且 $b \le d$ 时，称 $[a,b)$ **被** $[c,d)$ **覆盖**。删除所有被其他区间覆盖的区间，返回剩余区间的数目。

**约束**：

- $1 \le intervals.length \le 1000$
- $0 \le intervals[i][0] < intervals[i][1] \le 10^5$
- 所有的 $i \ne j$：`intervals[i] != intervals[j]`（区间互不相同）

## 2. 示例

**示例 1**

```text
输入：intervals = [[1,4],[3,6],[2,8]]
输出：2
解释：[3,6] 被 [2,8] 覆盖（2 ≤ 3 且 6 ≤ 8），删除；剩 [1,4] 与 [2,8]。
```

**官方数据示例**

```text
输入：intervals = [[52141,92589],[52991,93486],[46321,59199],[51955,78788],[18533,23127]]
输出：5
解释：两两之间互不包含，无区间被覆盖，5 个全保留。

输入：intervals = [[14041,32641],[24914,51477],[4983,81235],[62018,77987],[31523,32192],
                   [74196,96194],[16126,52652],[59901,67707],[36502,51366],[56437,86744]]
输出：3
解释：[4983,81235] 罩住前 6 个中的 5 个，[56437,86744] 再罩住 2 个，[74196,96194] 幸存。
```

**补充示例**

```text
输入：intervals = [[1,2],[1,4]]
输出：1
解释：左端点相同的两个区间，小的被大的覆盖——排序的关键分支。
```

## 3. 解题思路

### 3.1 暴力思路

对每对 $(i, j)$ 直接按定义检查 "$intervals[j]$ 是否覆盖 $intervals[i]$"——$O(n^2)$，$n \le 1000$ 时 $10^6$ 次比较，能过。但这个暴力在面试或更大数据量下没有前途，而且它没有用到问题的结构：**覆盖关系在合适的排序下是"有向"的**。

### 3.2 核心观察：排序后"覆盖者"必在前

![排序后一趟扫描：维护最远右端点](images/bw15_q2_sort_sweep_model.svg)

把区间按 **左端点升序；左端点相同时右端点降序** 排序。排序后有个关键性质：

> 若区间 $i$ 被某个区间覆盖，那么**覆盖它的一定排在它前面**。

因为排在后面的区间左端点 $\ge$ 当前左端点：若某区间 $j$ 排在 $i$ 后且覆盖 $i$，需要 $start_j \le start_i$，结合排序只能 $start_j = start_i$，而同起点时我们按右端点**降序**，$j$ 在后意味着 $end_j < end_i$，又与覆盖要求的 $end_i \le end_j$ 矛盾。

于是扫描时只需维护**已扫过区间中最远的右端点** $maxEnd$：当前区间 $i$ 被覆盖 $\iff maxEnd \ge end_i$（前面的某个区间左端点必 $\le start_i$，右端点又够远，就能罩住它）。一个变量就把 $O(n^2)$ 的成对比较压缩成 $O(1)$。

### 3.3 算法流程

```text
按 (start 升序, end 降序) 排序
remain = 0, maxEnd = -1
对每个区间 [s, e]：
    若 e > maxEnd：remain += 1；maxEnd = e     # 前面没有任何区间罩得住它
返回 remain
```

注意：判断用 $e > maxEnd$ 而非 $e > $ 前一个区间的右端点——罩住 $i$ 的可能是**更早**的某个大区间，不一定是前一个（见 3.4）。

### 3.4 示例演算

![示例演算：三个区间排序后逐个过闸](images/bw15_q2_example_walkthrough.svg)

示例 1：`[[1,4],[3,6],[2,8]]` 排序后为 `[[1,4],[2,8],[3,6]]`：

- $[1,4]$：$maxEnd = -1 < 4$ → 保留，$remain=1$，$maxEnd=4$；
- $[2,8]$：$8 > 4$ → 保留，$remain=2$，$maxEnd=8$；
- $[3,6]$：$6 \le 8$ → **被罩住**（罩它的是倒数第二个区间 $[2,8]$，不是上一个判断的变量，而是历史最大值），删除。

答案 2 ✓。再看"必须维护历史最大值"的小例子 `[[1,10],[2,3],[5,6]]`（排序后不变）：$[2,3]$ 与 $[5,6]$ 都不被**前一个**区间互相覆盖，但都被**最初的** $[1,10]$ 罩住——若只比较相邻区间就会漏判，答案应是 1。

补充示例 `[[1,2],[1,4]]`：同起点按右端点降序得 `[[1,4],[1,2]]`，$[1,2]$ 的右端点 $2 \le 4$ 被罩住，答案 1 ✓。这正是 tie-break 必须降序的原因：若升序排成 `[[1,2],[1,4]]`，扫到 $[1,4]$ 时 $maxEnd = 2 < 4$ 会误判其"幸存"，答案错成 2。

![同起点 tie-break 陷阱：降序正确、升序误判](images/bw15_q2_tiebreak_pitfall.svg)

## 4. 算法细节

1. **排序键**：`(start asc, end desc)`。两个方向缺一不可：左端点升序保证"可能的覆盖者"都在前面；同起点右端点降序保证同起点时"大的"在前，能罩住后面同起点的。
2. **历史最大右端点**：维护 $maxEnd$ 是对所有已处理区间的**最大值**，不是最近一个。因为罩住 $i$ 的区间只要左端点 $\le start_i$（排序保证任何一个前面的都满足）且右端点 $\ge end_i$，取历史最大即可。
3. **不必真的删除**：题目只要**数目**，扫描计数即可，无需重建列表。
4. **区间互不相同**：题目保证没有完全相同的两个区间；若允许重复，本题定义下两个相同区间互为覆盖，答案也应只留一个——扫描法天然会把第二个判为被覆盖（$e > maxEnd$ 不成立，$e = maxEnd$），依然正确，鲁棒性不错。
5. **数据范围**：坐标 $\le 10^5$，`int` 无压力；`maxEnd` 初值取 $-1$（或任何小于最小可能右端点的值，右端点 $\ge 1$）。

## 5. 正确性证明

**引理 1（覆盖者在前）**：按（左端点升序、同起点右端点降序）排序后，若区间 $i$ 被区间 $j$ 覆盖且 $i \ne j$，则 $j$ 排在 $i$ 之前。

**证明**：反设 $j$ 排在 $i$ 之后。排序给出 $start_j \ge start_i$；覆盖要求 $start_j \le start_i$，故 $start_j = start_i$。同起点时排序按右端点降序，$j$ 在后意味着 $end_j < end_i$（区间互不相同，严格不等）；而覆盖要求 $end_i \le end_j$，矛盾。∎

**引理 2（判定等价）**：排序后，区间 $i$ 被某区间覆盖 $\iff \max_{j < i} end_j \ge end_i$（没有更早的区间时视为 $-\infty$）。

**证明**：（⇐）设 $j^* = \arg\max_{j<i} end_j$。排序保证 $start_{j^*} \le start_i$（左端点升序，注意同起点时也成立），且 $end_i \le end_{j^*}$，故 $[start_i, end_i)$ 被 $[start_{j^*}, end_{j^*})$ 覆盖。（⇒）设 $i$ 被某个 $j$ 覆盖，由引理 1 $j < i$，且 $end_j \ge end_i$，于是 $\max_{j<i} end_j \ge end_i$。∎

**定理**：算法返回值等于未被覆盖区间的数目。

**证明**：对 $i$ 从小到大归纳，`maxEnd` 在处理第 $i$ 个区间前恰为 $\max_{j<i} end_j$。由引理 2，`e > maxEnd` 不成立当且仅当区间 $i$ 被覆盖；被覆盖者不计入 `remain`，未被覆盖者计入并令 `maxEnd` 更新为包含 $end_i$ 的最大值。归纳保持不变量，终止时 `remain` 恰为未被覆盖区间数。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序占主导；扫描一趟 $O(n)$。相比暴力 $O(n^2)$，在 $n = 10^3$ 时差异不大，但结构上更优且可扩展到 $n \sim 10^6$。
- **空间**：$O(1)$ 额外空间（原地排序，不计排序的栈/临时开销）；Python 的 `sort` 亦为原地。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int removeCoveredIntervals(vector<vector<int>>& intervals) {
        // 左端点升序；左端点相同时右端点降序（大的排前面，才能罩住后面同起点的）
        sort(intervals.begin(), intervals.end(), [](const vector<int>& a, const vector<int>& b) {
            return a[0] != b[0] ? a[0] < b[0] : a[1] > b[1];
        });
        int remain = 0;
        int maxEnd = -1;                 // 已处理区间中最远的右端点
        for (auto& iv : intervals) {
            if (iv[1] > maxEnd) {        // 没有更早的区间罩得住它
                ++remain;
                maxEnd = iv[1];
            }
        }
        return remain;
    }
};
```

### Python

```python
class Solution:
    def removeCoveredIntervals(self, intervals: List[List[int]]) -> int:
        # 左端点升序；左端点相同时右端点降序（大的排前面，才能罩住后面同起点的）
        intervals.sort(key=lambda p: (p[0], -p[1]))
        remain = 0
        max_end = -1                     # 已处理区间中最远的右端点
        for _, e in intervals:
            if e > max_end:              # 没有更早的区间罩得住它
                remain += 1
                max_end = e
        return remain
```

> 💡 两份代码均通过官方 2 组数据（输出 `5`、`3`）、题面示例（`2`）以及 304 组测试：其中 300 组随机小坐标用例（嵌套多、覆盖密集）与**独立的定义级暴力**（$O(n^2)$ 逐对判定覆盖）对拍 `mismatch = 0`，另含 $n = 1000$ 性能用例与官方大坐标数据。

## 8. 边界情况与易错点

1. **tie-break 方向是本题最大陷阱**：左端点相同时必须按右端点**降序**。排成升序后，`[[1,2],[1,4]]` 会把 $[1,4]$ 误判幸存（见 3.4），两组数据的答案就错了。
2. **维护的是"历史最大右端点"**：不是前一个区间的右端点！`[[1,10],[2,3],[5,6]]` 里 $[5,6]$ 的覆盖者是开头的大区间；只比较相邻区间（或只比较"上一个未被覆盖的区间"）都会漏。
3. **被删的区间仍然参与 maxEnd 吗**：参与与否不影响正确性——被覆盖区间的右端点必然 $\le$ 罩住它的区间右端点，更新 `maxEnd` 时取 max 不会改变值。扫描时统一更新即可，不必纠结"跳过被删的"。
4. **"覆盖"是 $\le$ 而非严格**：$c \le a$ 且 $b \le d$，端点相等也算覆盖（如 $[1,4]$ 覆盖 $[1,4]$——但题目保证区间互不相同，不会出现自我覆盖的歧义）。
5. **返回的是数目**：别费劲构造删除后的列表，题目只要 `remain`。
6. **maxEnd 初值**：右端点最小为 1（$0 \le a < b$），初值取 $-1$ 或 $0$ 均可；取 $0$ 时单靠 `>` 比较也正确（首个区间必保留）。
