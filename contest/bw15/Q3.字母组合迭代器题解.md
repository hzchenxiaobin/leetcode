# LeetCode 字母组合迭代器 题解

## 1. 题目概述

- **标题 / 题号**：字母组合迭代器（#1286，medium）
- **链接**：https://leetcode.cn/problems/iterator-for-combination/
- **来源**：LeetCode 第 15 场双周赛 Q3
- **难度**：中等
- **标签**：设计、回溯、迭代器

**题意**：设计迭代器类 `CombinationIterator`：

- `CombinationIterator(characters, combinationLength)`：`characters` 是一个**有序且字符互异**的字符串（仅小写字母），`combinationLength` 是组合长度 $k$；
- `next()`：按**字典序**返回下一个长度为 $k$ 的字母组合；
- `hasNext()`：还存在下一个组合时返回 `true`。

**约束**：

- $1 \le combinationLength \le characters.length \le 15$
- `characters` 中每个字符都不同
- `next` 与 `hasNext` 的调用总数最多 $10^4$ 次；题目保证每次调用 `next()` 时都存在下一个组合

## 2. 示例

**示例 1**

输入：

[["abc", 2], [], [], [], [], [], []]
输出：[null, "ab", true, "ac", true, "bc", false]
解释：长度为 2 的组合按字典序依次为 "ab"、"ac"、"bc"，之后耗尽。
```

输入：characters = "abc", combinationLength = 3
输出序列：next→"abc"，hasNext→false     # C(3,3)=1，只有一个组合

输入：characters = "abcdefghij", combinationLength = 4
输出序列首尾：next→"abcd" … next→"ghij"，共 C(10,4) = 210 个组合
```

## 3. 解题思路

### 3.1 暴力思路：预处理全部组合

构造时把 $\binom{n}{k}$ 个组合**全部生成**存进数组，`next` 按下标取、`hasNext` 比较下标与长度。$n \le 15$，$\binom{15}{7} = 6435$ 是峰值，字符串总长不过 $10^5$ 量级，空间时间都完全可行，比赛里这是最稳的保底写法。缺点是**构造即付出全部代价**：哪怕只调用一次 `next`，也要生成所有组合。更优雅的写法是**惰性**推进——`next()` 只从"当前组合"走到"下一个组合"，空间 $O(k)$。

### 3.2 核心观察：组合 ↔ 递增下标序列，"下一个"有闭式规则

![组合与下标序列的双射及可增位规则](images/bw15_q3_index_sequence_model.svg)

因为 `characters` 有序且字符互异，每个长度为 $k$ 的组合唯一对应一个**严格递增的下标序列** $idx[0..k-1]$（$idx[i]$ 是第 $i$ 个字符在 `characters` 中的位置），而且**组合的字典序恰好等于下标序列的字典序**。于是问题变成经典的"求字典序下一个递增序列"，与 `next_permutation` 同一套路：

> 从右往左找**最右一个还能增大的位置** $p$——满足 $idx[p] < n - k + p$（该位置的最大允许值是 $n-k+p$，否则后面的位置放不下 $k-p$ 个互异下标）。把 $idx[p]$ 加一，其后的位置依次取最小连续值 $idx[p]+1, idx[p]+2, \dots$

一个位置 $p$ "顶满了"（$idx[p] = n-k+p$）意味着从 $p$ 开始的后缀已经是 $\{n-k+p,\dots,n-1\}$——局部最大、无法再增。所有位置都顶满（$idx = \{n-k, \dots, n-1\}$，即 `characters` 的**后 $k$ 个字符**）时组合耗尽。

### 3.3 算法流程

![next 的推进流程：找可增位、增大、回填连续值](images/bw15_q3_next_flow.svg)

- **构造**：$idx = \{0, 1, \dots, k-1\}$（取前 $k$ 个字符，字典序最小），`has_next = true`；
- **next()**：先把当前 `idx` 翻译成字符串保存；再按 3.2 规则推进——找到 $p$ 则增大回填，找不到则 `has_next = false`；返回保存的字符串。**先输出再推进**，"当前组合"始终未消费；
- **hasNext()**：直接返回 `has_next`，$O(1)$。

推进耗尽的判定不需要额外标记——找 $p$ 失败（$p = -1$）本身就是"当前是最后一个组合"的信号，`has_next` 只是把这一事实缓存给 `hasNext()` 用。

### 3.4 示例演算

![示例演算："abc",k=2 的完整遍历](images/bw15_q3_example_walkthrough.svg)

`characters = "abc"`，$k = 2$，$n = 3$。下标最大值表：位置 0 上限 $n-k+0 = 1$，位置 1 上限 $n-k+1 = 2$。

| 步骤 | idx | 输出 | 推进过程 |
|------|-----|------|----------|
| 构造 | $\{0,1\}$ | — | 初始取前 $k$ 个 |
| next 1 | $\{0,1\}$ | `"ab"` | $p=1$：$idx[1]=1 < 2$ 可增 → $\{0,2\}$ |
| next 2 | $\{0,2\}$ | `"ac"` | $p=1$：$idx[1]=2$ 顶满；$p=0$：$0 < 1$ 可增 → $\{1,2\}$（回填连续） |
| next 3 | $\{1,2\}$ | `"bc"` | $p=1$ 顶满、$p=0$ 顶满（$1 = n-k+0$）→ `has_next = false` |
| hasNext | — | `false` | 已是最后组合 $\{1,2\}$ = 后 $k$ 个字符 `"bc"` ✓ |

## 4. 算法细节

1. **状态只要一个数组**：`idx`（$k$ 个整数）加一个 `has_next` 布尔。不需要把所有组合物化出来，构造 $O(k)$。
2. **上限公式 $n-k+p$ 的含义**：位置 $p$ 之后还有 $k-1-p$ 个位置要放互异递增下标，最后位置最大是 $n-1$，倒数回来位置 $p$ 最大就是 $n-1-(k-1-p) = n-k+p$。这个"留白"约束与组合的合法性一一对应。
3. **推进的正确姿势**：增大 $idx[p]$ 后，其后每个位置取**前一个加一**（最小连续值），保证字典序意义下的"下一个"；若回填成别的高位值，得到的是"某个更大的组合"而非"紧邻的下一个"。
4. **先复制后推进**：`next()` 必须**先**根据当前 `idx` 构造返回串**再**推进；顺序颠倒会让第一次 `next` 返回第二个组合。
5. **耗尽即后缀**：最后一个组合是 `characters` 的后 $k$ 个字符，推进失败（$p=-1$）时 `idx` 恰保持这个形态，无需恢复。
6. **调用限额**：$10^4$ 次调用、`next` 每次 $O(k)$（$k \le 15$），总量 $1.5 \times 10^5$ 字符操作，任何写法都不会超时，空间 $O(k)$ 是唯一值得追求的点。

## 5. 正确性证明

**引理 1（字典序同构）**：`characters` 有序且字符互异时，长度为 $k$ 的组合按字典序排序，与对应的严格递增下标序列按字典序排序，两者顺序完全一致。

**证明**：设两个组合 $A, B$ 对应下标序列 $\alpha, \beta$。比较组合的首个不同位置 $i$：$A_i \ne B_i$ 且 $A_0 = B_0, \dots, A_{i-1} = B_{i-1}$。由字符互异，相同字符 ⇔ 相同下标，故 $\alpha_j = \beta_j$（$j < i$）且 $\alpha_i \ne \beta_i$；由字符有序，$A_i < B_i \iff \alpha_i < \beta_i$。于是 $A <_{dict} B \iff \alpha <_{dict} \beta$。∎

**引理 2（推进规则）**：设当前合法序列 $idx$ 不是最后一个，$p$ 为最右满足 $idx[p] < n-k+p$ 的位置。则字典序中紧跟 $idx$ 的下一个合法序列 $idx'$ 恰为：前缀保持、$idx'[p] = idx[p]+1$、其后逐位取 $idx'[i] = idx'[i-1]+1$。

**证明**：先记录两条基本事实。

- **事实一（顶满的含义）**：合法序列每个位置 $i$ 满足 $idx[i] \le n-k+i$（其后 $k-1-i$ 个位置至少要留出这么大的下标空间）。称 $idx[i] = n-k+i$ 为位置 $i$ **顶满**。由 $p$ 的最右性，对一切 $i > p$，$idx[i] = n-k+i$（顶满）。
- **事实二（后缀下界）**：合法序列严格递增，故 $idx'[i] \ge idx'[p] + (i - p)$ 对任意 $i > p$。

(1) **$idx'$ 合法且大于 $idx$**：$idx'[p] = idx[p]+1 \le n-k+p$（$p$ 未顶满）；其后缀由事实二恰取最小值 $idx'[p] + (i-p)$，逐一代入验证 $\le n-k+i$，严格递增成立。字典序：前缀相同、位置 $p$ 变大，故 $idx' > idx$。

(2) **$idx'$ 与 $idx$ 之间无其它合法序列**：反设存在合法 $\gamma$ 使 $idx <_{dict} \gamma$，考察 $\gamma$ 与 $idx$ 的**首个不同位置** $q$（由 $\gamma > idx$ 知 $\gamma[q] > idx[q]$，且 $q \le k-1$）。

- 若 $q > p$：则 $idx[q] = n-k+q$（事实一），而 $\gamma[q] > idx[q] = n-k+q$ 超出合法上界，与 $\gamma$ 合法矛盾。故 $q \le p$。
- 若 $q = p$：$\gamma[p] \ge idx[p]+1 = idx'[p]$；再由事实二，对 $i > p$ 有 $\gamma[i] \ge \gamma[p] + (i-p) \ge idx'[p] + (i-p) = idx'[i]$。于是 $\gamma \ge idx'$。
- 若 $q < p$：$idx'[q] = idx[q] < \gamma[q]$ 且前缀相同，故 $\gamma >_{dict} idx'$。

三种情形合起来：任何大于 $idx$ 的合法序列都 $\ge idx'$，即 $idx'$ 是紧邻的下一个。∎

**定理**：设 `has_next` 初值为真。则每次 `next()` 返回字典序中未被返回过的最小组合；`hasNext()` 返回值等于"是否还有未返回的组合"。

**证明**：构造时 `idx` 为字典序最小组合（引理 1 下，下标 $\{0,\dots,k-1\}$ 最小，对应前 $k$ 个字符）。对调用次数归纳：第 $t$ 次 `next` 返回当前 `idx` 对应组合后推进。由引理 2，推进后的 `idx` 是字典序下一个组合；若当前已是最后一个，推进失败置 `has_next = false`，此后 `hasNext()` 返回 false 且不再有合法 `next`（题目保证不会调用）。归纳得所有返回值按字典序不重复且逐次递增，覆盖全部 $\binom{n}{k}$ 个组合。∎

## 6. 复杂度分析

- **时间**：构造 $O(k)$；`next()` 每次最坏 $O(k)$（找 $p$ 顺扫 + 回填 + 拼串），`hasNext()` $O(1)$。全程取尽为 $O(\binom{n}{k} \cdot k)$，与生成所有组合的总输出体量同阶，是熵意义上的最优。
- **空间**：$O(k)$。仅存 `idx` 与常数标记（不含 `characters` 本身 $O(n)$ 的引用）；对比预处理法 $O(\binom{n}{k} \cdot k)$ 的空间，$k=7, n=15$ 时相差约 $4.5 \times 10^4$ 倍。

## 7. 参考代码

### C++

```cpp
class CombinationIterator {
    string chars;        // 有序且字符唯一
    int n, k;
    vector<int> idx;     // 当前组合的下标序列（严格递增，与组合一一对应）
    bool has_next;       // idx 当前是否还代表一个未取出的组合

public:
    CombinationIterator(string characters, int combinationLength)
        : chars(characters), n(characters.size()), k(combinationLength) {
        idx.resize(k);
        for (int i = 0; i < k; ++i) idx[i] = i;   // 字典序最小：取前 k 个字符
        has_next = true;
    }

    string next() {
        string res;
        for (int i : idx) res.push_back(chars[i]);   // 输出当前组合
        // 推进到下一个组合：找最右一个还能增大的位置 p
        int p = k - 1;
        while (p >= 0 && idx[p] == n - k + p) --p;   // idx[p] 已顶到最大值 n-k+p
        if (p < 0) {
            has_next = false;                        // 已是最后一个组合
        } else {
            ++idx[p];                                // 增大 idx[p]
            for (int i = p + 1; i < k; ++i) idx[i] = idx[i - 1] + 1;  // 其后取最小连续值
        }
        return res;
    }

    bool hasNext() { return has_next; }
};
```

### Python

```python
class CombinationIterator:
    def __init__(self, characters: str, combinationLength: int):
        self.chars = characters                       # 有序且字符唯一
        self.n = len(characters)
        self.k = combinationLength
        self.idx = list(range(self.k))                # 字典序最小：取前 k 个
        self.has_next = True

    def next(self) -> str:
        res = ''.join(self.chars[i] for i in self.idx)   # 输出当前组合
        # 推进到下一个组合：找最右一个还能增大的位置 p
        p = self.k - 1
        while p >= 0 and self.idx[p] == self.n - self.k + p:   # 已顶到最大值 n-k+p
            p -= 1
        if p < 0:
            self.has_next = False                     # 已是最后一个组合
        else:
            self.idx[p] += 1                          # 增大 idx[p]
            for i in range(p + 1, self.k):            # 其后取最小连续值
                self.idx[i] = self.idx[i - 1] + 1
        return res

    def hasNext(self) -> bool:
        return self.has_next
```

> 💡 两份代码均通过官方示例（`[null,"ab",true,"ac",true,"bc",false]`）以及 159 组测试：随机字符集与 $k$ 下全程调用 `next`/`hasNext` 的序列，与 `itertools.combinations` 独立生成的期望序列逐条对拍 `mismatch = 0`；包含 $k = n$（唯一组合）、$k = 1$、$n = 15, k = 7$（$\binom{15}{7} = 6435$ 个组合全取尽）等边界。

## 8. 边界情况与易错点

1. **先输出再推进**：`next()` 的第一动作是把当前 `idx` 翻成字符串，推进放最后；顺序写反会漏掉第一个组合、多出（不存在的）最后一个之后的一次推进。
2. **上限公式别写错**：位置 $p$ 的上限是 $n - k + p$。写成 $n - p$、$n - k$、$n - 1$ 都是常见笔误——用 $n = k$ 的单组合用例一测就露馅（唯一组合必须立即判定"顶满"）。
3. **`has_next` 的时机**：它应该在 `next()` 返回**最后一个**组合的那次调用中被置 false（推进失败），而不是提前预测。`hasNext()` 本身 $O(1)$，不推进状态。
4. **回填"连续 +1"**：增大 $idx[p]$ 后，其后位置是 $idx[p]+1, idx[p]+2, \dots$（前一个加一），不是 $idx[p]$ 的简单复制，也不是从某固定值重新开始。
5. **题目保证 `next` 只在存在时被调用**：不必处理"next 到空"的防御分支；但 `hasNext()` 可在耗尽后被任意多次调用，`has_next` 缓存保证幂等。
6. **`characters` 已有序**：无需再排序（题目明说有序且互异）；若输入无序，先排序即可套用同一套逻辑。
7. **调用总数 $10^4$ vs 组合总数**：$\binom{15}{7} = 6435 < 10^4$，预处理版空间也不会爆，但惰性版在只调用一两次的场景下优势明显。
