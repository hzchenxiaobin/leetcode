# LeetCode 限制条件下元素之间的最小绝对差 题解

## 1. 题目概述

- **标题 / 题号**：限制条件下元素之间的最小绝对差（#2817，medium）
- **链接**：https://leetcode.cn/problems/minimum-absolute-difference-between-elements-with-constraint/
- **来源**：LeetCode 第 358 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找、有序集合

**题意**：给定下标从 0 开始的整数数组 `nums` 和整数 `x`。找两个下标 $i$ 和 $j$，满足 $|i - j| \ge x$，使 $|\text{nums}[i] - \text{nums}[j]|$ **最小**，返回这个最小差值。

**约束**：

- $1 \le n = \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- $0 \le x < n$（保证至少存在一对合法下标，答案一定存在）

> 💡 题面没有要求 $i \ne j$：当 $x = 0$ 时取 $i = j$ 差值为 0，**答案必然是 0**。这个免费特判值得第一时间注意到。

## 2. 示例

**示例 1**

```text
输入：nums = [4,3,2,4], x = 2
输出：0
解释：选 nums[0] = 4 和 nums[3] = 4，下标距离 3 ≥ 2，差值绝对值为 0。
```

**示例 2**

```text
输入：nums = [5,3,2,10,15], x = 1
输出：1
解释：选 nums[1] = 3 和 nums[2] = 2，下标距离 1 ≥ 1，差值绝对值为 1。
```

**示例 3**

```text
输入：nums = [1,2,3,4], x = 3
输出：3
解释：唯一合法对是 (0, 3)，差值 |1 - 4| = 3。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有数对

双重循环枚举 $(i, j)$，检查 $|i-j| \ge x$ 后取最小差，时间 $O(n^2)$。$n = 10^5$ 时约 $10^{10}$ 次运算，必然超时。

另一个诱人但**错误**的捷径是「把元素按值排序，最小差一定出现在排序后的相邻对之间」——这是无约束版本的经典结论。但加上**下标距离**约束后该性质失效：

```text
nums = [5, 3, 6, 2], x = 3
按值排序后相邻对（值, 下标）：(2,i₃)-(3,i₁)、(3,i₁)-(5,i₀)、(5,i₀)-(6,i₂)
三对的下标距离分别是 2、1、2，全都 < 3，一个合法对都凑不出来；
而真正的答案来自排序后并不相邻的 (2, i₃) 与 (5, i₀)：|5 - 2| = 3。
```

> ⚠️ 「排序后查相邻」要求最优对的两侧没有更近的值挡路，而下标约束恰恰可能把这些「挡路的值」全部判非法。所以必须**带着下标信息在线查询**。

### 3.2 核心观察：固定右端点 j，有序集合维护「距离 ≥ x 的左前缀」

不妨只考虑 $i < j$ 的对（$i > j$ 的对会在扫描到较大下标时被对称覆盖）。对固定右端点 $j$，合法的左端点恰好是**前缀** $\{0, 1, \ldots, j - x\}$：

- **单调增长**：$j$ 每右移一格，恰好有一个新元素 $\text{nums}[j - x]$ 获得资格——只进不出，天然适合在线维护；
- **快速查询**：在这个前缀里找与 $\text{nums}[j]$ 最接近的值，把前缀元素放进**有序集合**（C++ `multiset` / Python `SortedList`），一次 `lower_bound` 就能定位。

![核心观察：固定右端点，有序集合维护左前缀，查询前驱后继](images/minabs_sliding_set_concept.svg)

这与 [220. 存在重复元素 III](https://leetcode.cn/problems/contains-duplicate-iii/) 互为镜像：220 要求下标差**至多** $k$，维护大小为 $k$ 的滑动窗口（超出就删除）；本题要求下标差**至少** $x$，维护不断扩张的左前缀（**延迟 $x$ 步插入**）。一删一插，同一套有序集合骨架。

### 3.3 算法流程：每轮一次插入 + 一次前驱后继查询

对每个 $j = x, \ldots, n-1$：

1. 把 $\text{nums}[j - x]$ 插入有序集合 $S$（此刻 $S$ 恰为 $\text{nums}[0..j-x]$）；
2. 用 `lower_bound(nums[j])` 找到 $S$ 中第一个 $\ge \text{nums}[j]$ 的位置 `it`；
3. **后继** `*it`（若存在）：更新 $ans \gets \min(ans,\ \texttt{*it} - \text{nums}[j])$；
4. **前驱** `*prev(it)`（若存在）：更新 $ans \gets \min(ans,\ \text{nums}[j] - \texttt{*prev(it)})$。

![数轴视角：与查询值最近的集合元素只能是前驱或后继](images/minabs_pred_succ_query.svg)

> 💡 为什么只需查这两个候选？数轴上 $\text{nums}[j]$ 把 $S$ 劈成两半：比前驱更远的元素只会更左（差更大），比后继更远的只会更右。**最近的邻居必然紧贴两侧**——这是所有「有序集合 + 前驱后继」题目的共同引擎。

### 3.4 示例演算

以示例 2 `nums = [5, 3, 2, 10, 15]`，`x = 1` 走一遍（每轮先插入 $\text{nums}[j-1]$ 再查询）：

![示例演算：逐步插入与前驱后继查询](images/minabs_example_walkthrough.svg)

| $j$ | $\text{nums}[j]$ | 新插入 $\text{nums}[j-x]$ | 有序集合 $S$（值序） | 前驱 / 后继 | 本轮最优 | $ans$ |
|-----|------|------|-------------|-----------|---------|-------|
| 1 | 3 | 5 | $\{5\}$ | $\varnothing$ / 5 | $\|3-5\| = 2$ | 2 |
| 2 | 2 | 3 | $\{3, 5\}$ | $\varnothing$ / 3 | $\|2-3\| = 1$ | **1** |
| 3 | 10 | 2 | $\{2, 3, 5\}$ | 5 / $\varnothing$ | $\|10-5\| = 5$ | 1 |
| 4 | 15 | 10 | $\{2, 3, 5, 10\}$ | 10 / $\varnothing$ | $\|15-10\| = 5$ | 1 |

最终 $ans = 1$，由 $j = 2$ 时的 3 与 2 产生（下标 1 与 2，距离 $1 \ge x$）✓。

## 4. 算法细节

1. **循环范围**：$j$ 从 $x$ 开始。前 $x$ 轮（$j < x$）集合为空、无候选，直接跳过；由于 $x < n$，循环至少执行一轮，$ans$ 一定会被更新。
2. **先插入、后查询**：处理 $j$ 时必须先插入 $\text{nums}[j-x]$ 再查询 $\text{nums}[j]$，保证查询时刻 $S$ 恰为 $\text{nums}[0..j-x]$。顺序颠倒会漏掉 $i = j - x$ 这一边界对（见 §8 第 2 条）。
3. **`lower_bound` 的语义**：返回第一个 $\ge \text{nums}[j]$ 的迭代器/下标 `k`，则 `S[k]` 是后继、`S[k-1]` 是前驱。用 `upper_bound` / `bisect_right` 也行：此时等于 $\text{nums}[j]$ 的元素归入前驱一侧，两个候选同样覆盖最近邻。本题关键是**必须两側都查**。
4. **数据结构选型**：C++ 用 `multiset<int>`（值可重复，插入与 `lower_bound` 均 $O(\log n)$）；Python 用 `SortedList`（`add` 与 `bisect_left` 均均摊 $O(\log n)$）。
5. **剪枝**：差值的下界是 0，一旦 $ans$ 归 0 可立即返回，最坏情况（全部相同元素）从 $O(n \log n)$ 降为 $O(x + \log n)$ 级别。
6. **没有平衡树库时的替代**：将值离散化后用树状数组维护「值域上每个值是否出现」，前驱/后继查询变成值域上的倍增/二分定位，仍是 $O(n \log n)$。Python 若图省事用 `bisect.insort` 维护普通 `list`，单次插入是 $O(n)$ 的整体搬移，最坏 $O(n^2)$，$n = 10^5$ 时有超时风险，不推荐。

## 5. 正确性证明

**引理 1（前驱后继覆盖最近邻）**：设 $S$ 为有限非空整数集，$v \notin S$ 或 $v \in S$ 皆可。记 $p = \max\{s \in S : s \le v\}$（若存在，称为前驱），$q = \min\{s \in S : s \ge v\}$（若存在，称为后继）。则 $\min_{s \in S} |v - s|$ 在 $p$ 或 $q$ 处取得。

**证明**：任取 $s \in S$。若 $s \le v$，由 $p$ 的定义有 $s \le p \le v$，故 $|v - s| = v - s \ge v - p = |v - p|$；若 $s \ge v$，同理 $v \le q \le s$，故 $|v - s| = s - v \ge q - v = |v - q|$。即每个元素到 $v$ 的距离都不小于 $p$、$q$ 之一到 $v$ 的距离，最小值必在 $p$、$q$ 中取得（$S$ 非空保证两者至少其一存在）。∎

**引理 2（循环不变量）**：算法处理第 $j$ 轮的查询语句时（$x \le j \le n-1$），有序集合 $S$ 恰包含 $\{\text{nums}[0], \ldots, \text{nums}[j - x]\}$。

**证明**：对 $j$ 归纳。$j = x$ 时，本轮刚插入 $\text{nums}[x - x] = \text{nums}[0]$，$S = \{\text{nums}[0]\}$，成立。设 $j$ 轮查询时成立，则第 $j+1$ 轮查询前恰执行了一次插入 $\text{nums}[j + 1 - x]$，故查询时 $S = \{\text{nums}[0..j-x]\} \cup \{\text{nums}[j+1-x]\} = \{\text{nums}[0..j+1-x]\}$，且中间无删除操作。∎

**定理**：算法返回的 $ans = \min\{| \text{nums}[i] - \text{nums}[j] | : |i - j| \ge x\}$。

**证明**：记最优值为 $OPT$，取到最优的一对为 $(i^*, j^*)$；由扫描方向不妨设 $i^* < j^*$（$i^* = j^*$ 仅在 $x = 0$ 时合法，此时差为 0，而算法在 $j = 0$ 轮插入 $\text{nums}[0]$ 后查询 $\text{nums}[0]$ 得后继即自身值、差 0，同样被覆盖）。

**下界**：算法每次用候选 $s \in S$ 更新 $ans$ 时，由引理 2，$s$ 来自某个 $\text{nums}[i]$，$i \le j - x$，即 $|i - j| \ge x$——每次更新都对应一个合法对，故 $ans \ge OPT$。

**达界**：由 $|i^* - j^*| \ge x$ 得 $i^* \le j^* - x$。处理第 $j^*$ 轮查询时，由引理 2，$\text{nums}[i^*] \in S$；由引理 1，该轮取到的前驱/后继候选 $c$ 满足 $|\text{nums}[j^*] - c| \le |\text{nums}[j^*] - \text{nums}[i^*]| = OPT$。于是 $ans \le OPT$。

两者结合，$ans = OPT$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。共 $n - x \le n$ 轮，每轮一次有序集合插入 + 一次 `lower_bound` 查询，各 $O(\log n)$；`prev` 与比较为 $O(1)$。附带 $ans = 0$ 剪枝时更快，但不改变最坏界。
- **空间复杂度**：$O(n)$。有序集合最多存 $n - x$ 个元素；相比之下暴力法只用了 $O(1)$ 额外空间——用空间换「可查询的有序性」正是本题的付费点。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minAbsoluteDifference(vector<int>& nums, int x) {
        int n = nums.size();
        multiset<int> s;
        int ans = INT_MAX;
        for (int j = x; j < n; ++j) {
            s.insert(nums[j - x]);                // ① 先插入：S = nums[0..j-x]
            auto it = s.lower_bound(nums[j]);     // ② 第一个 >= nums[j] 的位置
            if (it != s.end()) {                  // ③ 后继候选
                ans = min(ans, *it - nums[j]);
            }
            if (it != s.begin()) {                // ④ 前驱候选
                ans = min(ans, nums[j] - *prev(it));
            }
            if (ans == 0) break;                  // ⑤ 差值下界剪枝
        }
        return ans;
    }
};
```

### Python

```python
from sortedcontainers import SortedList

class Solution:
    def minAbsoluteDifference(self, nums: List[int], x: int) -> int:
        sl = SortedList()
        ans = inf
        for j in range(x, len(nums)):
            sl.add(nums[j - x])                      # ① 先插入：S = nums[0..j-x]
            k = sl.bisect_left(nums[j])              # ② 第一个 >= nums[j] 的下标
            if k < len(sl):                          # ③ 后继候选
                ans = min(ans, sl[k] - nums[j])
            if k:                                    # ④ 前驱候选
                ans = min(ans, nums[j] - sl[k - 1])
            if ans == 0:                             # ⑤ 差值下界剪枝
                break
        return ans
```

> 💡 `multiset::lower_bound` 返回的迭代器判空有讲究：`it != s.end()` 说明后继存在，`it != s.begin()` 说明前驱存在，两个判据相互独立，漏判任何一个都会错过候选。

## 8. 边界情况与易错点

1. **`x = 0` 答案必为 0**：题目允许 $i = j$，直接 `return 0` 可秒过；不特判也没关系——算法在 $j = 0$ 轮「先插入自身再查询」，后继恰为等值元素，同样得 0。
2. **先插入、后查询的顺序不能反**：反例 `nums = [1, 100], x = 1`，唯一合法对是 $(0, 1)$。若写成「先查询、再插入为下一轮准备」，$j = 1$ 轮查询时 $S$ 为空，循环结束返回无穷大。先插入 $\text{nums}[j-x]$ 恰好把 $i = j - x$ 这个边界下标及时放行。
3. **判空两连**：`it == s.end()`（无后继）与 `it == s.begin()`（无前驱）必须分别处理；只查一侧会漏掉 `nums = [1,2,3,4], x = 3`（只有前驱）或全小于查询值的情形（只有后继）。
4. **值可重复，用 `multiset` 最稳**：本题只查询前驱后继的**值**，重复值互相替代不影响结果（`set` 侥幸也能过）；但一旦推广到需要计数的场景，`set` 去重就是 bug，习惯上统一用 `multiset`。
5. **`prev(it)` 只对有效迭代器安全**：对 `begin()` 取 `prev` 是未定义行为，务必先判 `it != s.begin()`。
6. **`ans` 一定存在**：约束 $0 \le x < n$ 保证循环至少一轮且首轮集合非空，无需特判「返回 `INT_MAX`」的分支；但初始化仍要设为 `INT_MAX` / `inf`，不能用 0。
7. **溢出核算**：$\text{nums}[i] \le 10^9$，差值 $< 10^9 < 2^{31} - 1$，C++ `int` 足够；`*it - nums[j]` 的操作数同为 `int`，不会溢出。
8. **Python 别用普通 `list` + `bisect.insort`**：单次插入需整体搬移，最坏 $O(n^2)$；`SortedList` 才是正解。比赛环境若没有 `sortedcontainers`，退路是离散化 + 树状数组（见延伸思考）。

**延伸思考**：

- **无平衡树库的实现**（Go / 早期 JS 选手的现实问题）：把所有值离散化到 $[1, n]$，用树状数组维护出现次数，前驱后继 = 在值域上二分定位最近的出现位置，总复杂度 $O(n \log n)$。这也是本题不用任何高级库的通用退路。
- **约束改成「下标差恰好 $x$」**：退化为 $\min_i |\text{nums}[i] - \text{nums}[i+x]|$，一趟线性扫描即可——约束从「至少」变「恰好」，维护结构从有序集合退化成单个变量。
- **约束改成「下标差至多 $x$」**：就是 220 题的最小差版本，窗口滑动时既要插入（右侧进）又要删除（左侧出），`SortedList` 的 `remove` 同为 $O(\log n)$，骨架不变、多一行删除。
- **在线查询版**：若依次到达的每个元素要即时回答「与之前所有距离 ≥ $x$ 元素的最小差」，本题算法原封不动就是在线算法——这正是它比离线排序做法更本质的地方。
