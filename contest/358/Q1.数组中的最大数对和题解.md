# LeetCode 数组中的最大数对和 题解

## 1. 题目概述

- **标题 / 题号**：数组中的最大数对和（#2815，easy）
- **链接**：https://leetcode.cn/problems/max-pair-sum-in-an-array/
- **来源**：LeetCode 第 358 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定下标从 **0** 开始的整数数组 `nums`，从中选出一对数 $(i, j)$（$i \ne j$），要求这两个数**数位上最大的数字相等**，目标是使 $\text{nums}[i] + \text{nums}[j]$ **最大**。返回该最大和；不存在满足题意的数对时返回 $-1$。

**约束**：

- $2 \le \text{nums.length} \le 100$
- $1 \le \text{nums[i]} \le 10^4$

> 💡 $\text{nums[i]} \ge 1$ 是个隐蔽但关键的条件：每个数至少含一个非零数位，故**最大数位 $\in [1, 9]$，只有 9 种取值**——这正是分桶的口子。签到题的第一直觉应该是「配对条件里的**不变量**是什么」，而不是急着写双重循环。

## 2. 示例

**示例 1**

```text
输入：nums = [51,71,17,24,42]
输出：88
解释：
i = 1 和 j = 2，nums[i] 和 nums[j] 数位上最大的数字相等，且这一对的总和 71 + 17 = 88。
i = 3 和 j = 4，nums[i] 和 nums[j] 数位上最大的数字相等，且这一对的总和 24 + 42 = 66。
可以证明不存在其他数对满足数位上最大的数字相等，所以答案是 88。
```

**示例 2**

```text
输入：nums = [2536,1613,3366,162]
输出：5902
解释：四个数的最大数位依次为 [6,6,6,6]，全部落在桶 6。
取桶内最大的两个 2536 + 3366 = 5902（而非 2536 + 1613 = 4149 或 1613 + 3366 = 4979）。
```

**示例 3**

```text
输入：nums = [1,2,3,4]
输出：-1
解释：每个数的最大数位各不相同（1/2/3/4），任何桶都凑不成一对。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $\binom{n}{2}$ 个数对 $(i, j)$，对每对分别求两个数的最大数位，相等则用两数之和更新答案。时间 $O(n^2 \cdot d)$（$d$ 为数位长度，$\le 5$），$n \le 100$ 时约 $5 \times 10^4$ 次数位运算，能过。

> ⚠️ 暴力法的硬伤：① 同一元素的最大数位被重复计算多次；② 完全没有利用「**只有最大数位相等的两个数才可能配对**」这一结构，大量比较注定无效。签到题的正确打开方式是把「配对条件」翻译成「**分组键**」。

### 3.2 核心观察：按最大数位分桶，桶内取最大的两个

配对条件「数位上最大的数字相等」等价于「**分到同一个桶**」，而最大数位只有 $1 \sim 9$ 共 9 种取值，因此：

1. 对每个数 $x$ 求 $d = \max\text{Digit}(x)$；
2. 按 $d$ 把元素归入 9 个桶（值域有限 → 用长度 10 的定长数组代替哈希表）；
3. **同一桶内任意两个元素都构成合法对**（条件仅约束最大数位，不约束下标与顺序），故桶能贡献的最大配对和 = **桶内最大与次大之和**；
4. 答案 = 各桶 Top-2 和的最大值；所有桶都凑不成一对才返回 $-1$。

![按最大数位分桶取 Top-2](images/max_pair_sum_bucket_concept.svg)

> 💡 **为什么取 Top-2 就够？** 因为合法性与数值大小完全解耦——同桶即合法。想让「和」最大，自然选桶里最大的两个数。示例 2 就是反例教材：四个数同桶时，2536 的最优搭档是 3366 而不是 1613。

### 3.3 算法流程：单趟扫描，流式维护桶最大值

分桶后不必显式存储整桶再排序：每个桶只需记住**目前见过的最大值** `best[d]`。一趟遍历，遇到 $x$ 时：

1. 求 $d = \max\text{Digit}(x)$；
2. 若 `best[d] > 0`（桶里已有数），得到候选和 $x + \text{best}[d]$，用它更新 `ans`；
3. 再用 $x$ 刷新 `best[d] = max(best[d], x)`。

顺序**必须先配对、再更新**——若先把 $x$ 写进 `best[d]` 再配对，$x$ 会和自己相加得到 $2x$ 的假配对。

![算法流程：单趟扫描流式维护 best](images/max_pair_sum_one_pass_flow.svg)

### 3.4 示例演算

以 `nums = [51,71,17,24,42]` 为例，逐元素追踪 `best` 与 `ans` 的变化：

![示例演算：单趟扫描过程](images/max_pair_sum_example_walkthrough.svg)

| x | 最大数位 d | 旧 best[d] | 候选和 | 新 best[d] | ans |
|---|-----------|------------|--------|-----------|-----|
| 51 | 5 | 0（空） | — | 51 | -1 |
| 71 | 7 | 0（空） | — | 71 | -1 |
| 17 | 7 | 71 | **17+71=88** | 71 | **88** |
| 24 | 4 | 0（空） | — | 24 | 88 |
| 42 | 4 | 24 | 42+24=66 | 42 | 88 |

最终返回 `88`，与示例 1 一致。注意 17 到达时用**旧** `best[7]=71` 配对得到 88，随后 `best[7]` 因 $17 < 71$ 保持不变——「先配对、再更新」在这一行体现得最清楚。

## 4. 算法细节

1. **最大数位的求法**：C++ 用算术取模 `d = max(d, x % 10); x /= 10`，从低位扫到高位，$O(d)$ 常数次除法；Python 借 `str(x)` 逐字符比较更短。循环条件 `x > 0` 在本题 $\text{nums[i]} \ge 1$ 下恒安全（即便 $x=0$，该写法也返回初值 0，恰好正确）。
2. **哨兵设计**：`best[d] = 0` 表示桶空——这依赖 $\text{nums[i]} \ge 1$（正数不会把桶「假填满」）。若值域含 0，需改用 $-1$ 哨兵或额外计数。
3. **更新顺序**：先 `ans = max(ans, x + best[d])` 再 `best[d] = max(best[d], x)`，防止 $x$ 与自己配对（详见 §8 第 2 条）。
4. **答案初值**：`ans = -1` 与「无解」返回值语义统一，无需额外的 `hasPair` 标志位。
5. **数据结构**：9 个桶 → 定长数组 `best[10]`，比 `unordered_map` 更快更省，是「值域有限 → 数组代替哈希」的标准落点。

## 5. 正确性证明

**引理 1（配对刻画）**：数对 $(i, j)$（$i \ne j$）满足题意当且仅当 $\max\text{Digit}(\text{nums}[i]) = \max\text{Digit}(\text{nums}[j])$。

**证明**：即题设条件的直接改写。∎

**引理 2（桶内最优 = Top-2 之和）**：设桶 $d$ 的全部元素构成多重集合 $S_d$（$|S_d| \ge 2$），$a_1 \ge a_2 \ge \cdots$ 为其降序排列，则 $S_d$ 内数对和的最大值为 $a_1 + a_2$。

**证明**：任取 $x \le y \in S_d$ 为一对。若 $y$ 取到 $a_1$：$x$ 是去掉一个 $a_1$ 之后的元素，其值不超过次大值 $a_2$，故 $x + y \le a_2 + a_1$；若 $y < a_1$：则 $y \le a_2$ 且 $x \le y \le a_2$，故 $x + y \le a_2 + a_2 \le a_1 + a_2$。另一方面 $a_1, a_2$ 对应原数组中两个不同下标（即使值相等也是两个元素），是一对合法解，其和恰为 $a_1 + a_2$。故最大值等于 $a_1 + a_2$。∎

**引理 3（流式不变式）**：处理完前 $k$ 个元素后：**(a)** $\text{best}[d] = \max\{\text{nums}[i] : i < k,\ \max\text{Digit}(\text{nums}[i]) = d\}$（空集时为 $0$）；**(b)** `ans` 等于前 $k$ 个元素中所有合法数对和的最大值（无合法对时为 $-1$）。

**证明**：对 $k$ 归纳。$k = 0$ 时 `best` 全 $0$、`ans` 为 $-1$，成立。设 $k$ 时成立，处理第 $k$ 个元素 $x$，记 $d = \max\text{Digit}(x)$：

- (a) 更新后 $\text{best}[d] \gets \max(\text{best}[d], x)$ 恰为前 $k+1$ 个元素中桶 $d$ 的最大值，其余桶不变。
- (b) 前 $k+1$ 个元素的合法对 = 前 $k$ 个元素的合法对 $\cup$ 形如 $(i, k)$ 的新对。若 $\text{best}[d] = 0$：由 (a) 前 $k$ 个元素没有落在桶 $d$ 的，新对不存在，答案不变。若 $\text{best}[d] > 0$：由 (a)，$\text{best}[d]$ 是某个 $i_0 < k$ 且与 $x$ 同桶的元素，故 $(i_0, k)$ 合法；且所有新对的和为 $\text{nums}[i] + x$（$\max\text{Digit}(\text{nums}[i]) = d$），其最大值恰为 $x + \text{best}[d]$——即候选和取遍并恰好取到新对的最优。故更新 `ans = max(ans, x + best[d])` 后 (b) 仍成立。∎

**定理**：算法返回 $-1$ 当且仅当不存在合法数对；否则返回全局最优配对和。

**证明**：引理 3 取 $k = n$：`ans` 即全部合法数对和的最大值，由引理 1、2 该值正是所求；无合法对时 `ans` 保持初值 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot d)$，其中 $d \le 5$（因 $\text{nums[i]} \le 10^4$），近似 $O(n)$。每个元素只做一次数位扫描（常数次取模除法）+ $O(1)$ 的桶操作，无排序、无重复计算。
- **空间复杂度**：$O(1)$。仅 `best[10]` 与常数个变量，与 $n$ 无关——值域 $1 \sim 9$ 固定，是「值域分桶」带来的红利。

## 7. 参考代码

### C++

```cpp
class Solution {
    int maxDigit(int x) {
        int d = 0;
        for (; x; x /= 10) d = max(d, x % 10);
        return d;
    }
public:
    int maxSum(vector<int>& nums) {
        int best[10]{};              // best[d]：桶 d 目前见过的最大值，0 表示桶空
        int ans = -1;
        for (int x : nums) {
            int d = maxDigit(x);
            if (best[d] > 0) ans = max(ans, x + best[d]);  // 先配对（用旧 best）
            best[d] = max(best[d], x);                     // 再更新
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, nums: List[int]) -> int:
        best = [0] * 10
        ans = -1
        for x in nums:
            d = max(map(int, str(x)))      # 最大数位
            if best[d]:
                ans = max(ans, x + best[d])
            best[d] = max(best[d], x)
        return ans
```

> 💡 周赛实战角度：这题从读完到 AC 的最短路径就是「9 个桶 + 每桶记最大值」。比起先分桶存列表再排序的写法，流式维护版代码量更少、边界更少（天然处理重复元素与相等值），Q1 省下的 3 分钟都是后面难题的时间。

## 8. 边界情况与易错点

1. **无合法对返回 -1**：示例 3 的核心考点。所有桶都只有 0 或 1 个元素时 `ans` 从未被更新，初值 $-1$ 直接返回，无需特判。
2. **更新顺序颠倒（最高频 WA 点）**：若先 `best[d] = max(best[d], x)` 再配对，当 $x$ 本身刷新最大值时会算出 $x + x$ 的假配对。例如桶 7 已有 71，又来一个 71：正确答案是 $142$（两个 71 各自参与）；而错误顺序下若来的是 75，会得到 $75 + 75 = 150$ 这种不存在的对。**先配对、再更新**。
3. **重复元素可配对**：$[71, 71]$ 应返回 $142$（两个值相等的数也是一对）。流式写法天然正确：第二个 71 到达时旧 `best[7] = 71`，候选 $142$。
4. **哨兵 0 依赖 $\text{nums[i]} \ge 1$**：若题目放宽到允许 $0$（最大数位为 0），`best[d] > 0` 的判空会误判「桶里已有 0」为空，需换 $-1$ 哨兵或维护每桶计数。
5. **溢出**：和最大 $2 \times 10^4$，`int` 毫无压力，无需 `long long`。
6. **最小规模 $n = 2$**：两个数要么同桶（返回其和）要么返回 $-1$，单趟逻辑自然覆盖。
7. **别画蛇添足**：不需要排序、不需要哈希表、不需要枚举数对——任何一步都是 Q1 时间黑洞。
