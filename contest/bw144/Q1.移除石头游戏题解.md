# LeetCode 移除石头游戏 题解

## 1. 题目概述

- **标题 / 题号**：移除石头游戏（#3360，easy）
- **链接**：https://leetcode.cn/problems/stone-removal-game/
- **来源**：LeetCode 第 144 场双周赛 Q1
- **难度**：简单
- **标签**：数学、模拟

**题意**：Alice 和 Bob 轮流从一堆石头中移除石头，Alice 先手。

- Alice 在**第一次**操作中移除**恰好** $10$ 个石头；
- 之后每次操作，当前玩家移除的石头数**恰好**等于**对方上一次**移除的石头数减 $1$；
- **第一位无法进行操作的玩家输掉游戏**。

给定初始石头数 $n$，若 Alice 能赢返回 `true`，否则返回 `false`。

**约束**：

- $1 \le n \le 50$

这道题的关键不在"博弈"，而在于看清一个事实：**整局游戏没有任何选择**——每一步要移除多少石头是被规则唯一确定的，玩家唯一能"决定"的事情根本没有。于是"博弈"退化成"按固定序列消耗石头，看谁先卡住"。

## 2. 示例

**示例 1**

```text
输入：n = 12
输出：true
解释：Alice 先移除 10 个，剩 2 个；Bob 按规则需要移除 9 个，但只剩 2 个，无法操作，Bob 输。
```

**示例 2**

```text
输入：n = 1
输出：false
解释：Alice 连第一次的 10 个都拿不出来，直接输。
```

**示例 3（补充）**

```text
输入：n = 19
输出：false
解释：Alice 移 10 个（剩 9），Bob 恰好能移 9 个（剩 0）；此时轮到 Alice 需要移 8 个，无石可移，Alice 输。
      n = 19 正好被 10 + 9 取尽，是"后手恰好收尾"的典型情形。
```

## 3. 解题思路

### 3.1 暴力思路

直接按规则模拟：维护当前剩余石头数 `stones`、本次应移除的数量 `take`（初始为 $10$）、当前轮到的玩家；只要 `stones >= take` 就消耗并换手（`take` 减 $1$），循环结束时"卡住"的那位玩家就是输家。

这一步已经足够通过本题（$n \le 50$，循环次数不超过 $11$ 次）。真正值得写下来的是**为什么模拟是对的**，以及一个更快的等价判定。

### 3.2 核心观察：局面的唯一性与奇偶性

![移除数量被规则锁定为 10, 9, 8, 7, ... 的递减序列](images/bw144_q1_take_sequence.svg)

**观察一（数量序列固定）**：第 $1$ 次移除 $10$ 个，第 $2$ 次移除 $10 - 1 = 9$ 个，第 $3$ 次移除 $9 - 1 = 8$ 个……归纳可得第 $j$ 次操作移除

$$a_j = 11 - j \quad (j = 1, 2, 3, \dots)$$

**观察二（玩家交替固定）**：奇数次操作由 Alice 执行，偶数次由 Bob 执行。因为没有任何选择，**整局游戏完全由 $n$ 决定**，不存在"策略"。

**观察三（胜负判据）**：设 $k$ 为满足

$$\sum_{j=1}^{k} (11 - j) \le n$$

的最大整数，即"能完整走完 $k$ 次操作"。则第 $k+1$ 次操作无法进行（它需要的石头数超过剩余量），游戏在此结束。第 $k+1$ 次操作轮到 Alice 当且仅当 $k$ 为偶数，因此

$$\text{Alice 获胜} \iff k \text{ 是奇数}.$$

前 $k$ 次移除的石头总数也可以用等差数列求和：

$$S(k) = 10 + 9 + \cdots + (11-k) = \frac{k(21-k)}{2}.$$

于是问题变成"求最大的 $k$ 使 $\dfrac{k(21-k)}{2} \le n$"。由于 $S(8) = 52 > 50$，$n \le 50$ 时必有 $k \le 7$，枚举/模拟的轮数是个常数。

### 3.3 算法流程

![算法流程：模拟消耗 10, 9, 8, ... 并翻转先手](images/bw144_q1_algorithm_flow.svg)

```text
1. stones = n, take = 10, alice = true
2. while stones >= take:          # 还能按规则移除
3.     stones -= take
4.     take   -= 1
5.     alice   = not alice        # 换手
6. return not alice               # 卡住的是 Bob 则 Alice 胜
```

### 3.4 示例演算

![示例 1 与示例 3 的逐步演算](images/bw144_q1_example_walkthrough.svg)

对 $n = 12$（示例 1）与 $n = 19$（示例 3）逐步走一遍：

| 步数 $j$ | 应移除 $a_j = 11-j$ | 玩家 | $n = 12$ 动手前剩余 | $n = 12$ 结果 | $n = 19$ 动手前剩余 | $n = 19$ 结果 |
|----------|--------------------|------|---------------------|---------------|---------------------|---------------|
| 1 | 10 | Alice | 12 | 剩余 2 | 19 | 剩余 9 |
| 2 | 9 | Bob | 2 | **不够，Bob 输** | 9 | 剩余 0 |
| 3 | 8 | Alice | — | — | 0 | **不够，Alice 输** |

两个例子的分界正是"完成的步数"的奇偶性：$n=12$ 时 $k=1$（奇数，Alice 胜），$n=19$ 时 $k=2$（偶数，Alice 输）。

## 4. 算法细节

1. **循环条件用 `stones >= take`**：相等时也能移除（剩 0 个），这是合法的。若写成 `stones > take` 会把 `n = 19` 这类"恰好取尽"的情形判错。
2. **`take` 递减到 0 的问题**：$n \le 50$ 时最多走 $7$ 步（$S(8) = 52 > 50$），`take` 从 $10$ 递减到 $4$ 就退出循环，不会出现"移除 0 个"或负数。
3. **玩家标识的初值**：`alice = true` 表示"当前轮到 Alice"；每完成一次操作就翻转。循环结束后**尚未翻转**的标识才代表"卡住的人"——注意代码里翻转发生在 `stones -= take` 之后，所以只要写对顺序就不会错。
4. **返回值取反**：循环退出时 `alice` 表示"轮到谁而谁不能动"，所以返回 `not alice`。这是最容易写反的一行，建议用"卡住的是 Bob ⇒ Alice 赢"这句话自检。
5. **等价写法**：也可以先算出 $k$ 再判奇偶，但模拟更短、更难错；$n \le 50$ 时两种写法都 $O(1)$。
6. **不用考虑"策略"**：本题没有分支让玩家选择，所以不存在"Alice 有更优走法"这种讨论。

## 5. 正确性证明

**引理 1（数量序列）**：第 $j$ 次操作移除的石头数恰为 $a_j = 11 - j$。

**证明**：对 $j$ 归纳。$j = 1$ 时规则规定 Alice 移除 $10 = 11 - 1$。设第 $j$ 次移除 $11 - j$，则第 $j+1$ 次由对手执行、数量为"对方上一次减 $1$"，即 $(11-j) - 1 = 11 - (j+1)$。∎

**引理 2（过程唯一）**：给定 $n$，整局游戏中被执行的操作序列（以及每一位玩家能否操作）由 $n$ 唯一确定，与玩家行为无关。

**证明**：由引理 1，每次操作的移除量只取决于步数 $j$；玩家的身份只取决于 $j$ 的奇偶。而"能否执行第 $j$ 次操作"只取决于前 $j-1$ 次是否都成功以及剩余量是否 $\ge a_j$。因此整局过程是 $n$ 的函数。∎

**引理 3（胜负判据）**：设 $k$ 为满足 $S(k) \le n$ 的最大整数，其中 $S(k) = \sum_{j=1}^{k}(11-j)$。则游戏恰好在第 $k+1$ 次操作时结束，且 Alice 获胜当且仅当 $k$ 为奇数。

**证明**：由 $k$ 的最大性，$S(k) \le n$ 而 $S(k+1) = S(k) + (10 - k) > n$（注意 $10-k \ge 1$，因为 $k \le 9$）。前 $k$ 次操作依次消耗 $a_1,\dots,a_k$，剩余 $n - S(k) \ge 0$；第 $k+1$ 次需要 $10-k$ 个石头，而剩余量 $n - S(k) < 10 - k$，故无法执行，游戏结束。此时轮到第 $k+1$ 位玩家：$k$ 为偶数时是 Alice，$k$ 为奇数时是 Bob。第一位无法操作者输，所以"Alice 输"当且仅当 $k$ 为偶数，即 Alice 胜 $\iff k$ 为奇数。∎

**定理**：模拟算法的返回值等于 Alice 是否获胜。

**证明**：模拟严格按引理 1 的序列逐个消耗，并在剩余量不足时停止；由引理 2、3，停止时的步数恰为 $k$，此时轮到的玩家与胜负关系由引理 3 给出。算法最后返回 `not alice`，其中 `alice` 在退出时表示"轮到 Alice 却不能操作"，故返回值 $\iff$ 卡住的是 Bob $\iff$ Alice 获胜。∎

## 6. 复杂度分析

- **时间**：循环执行 $k \le 7$ 次（因为 $S(8) = 52 > 50$），每次 $O(1)$，总时间 $O(1)$。
- **空间**：$O(1)$，只有三个整型/布尔变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canAliceWin(int n) {
        int stones = n, take = 10;
        bool alice = true;                       // 当前该谁操作
        while (stones >= take) {                 // 还能操作，就消耗并换手
            stones -= take;
            take--;
            alice = !alice;
        }
        return !alice;                           // 卡住的若是 Bob，则 Alice 获胜
    }
};
```

### Python

```python
class Solution:
    def canAliceWin(self, n: int) -> bool:
        stones, take, alice = n, 10, True
        while stones >= take:
            stones -= take
            take -= 1
            alice = not alice
        return not alice
```

## 8. 边界情况与易错点

1. **`stones == take` 必须算作"能移除"**：剩余量刚好等于本次需求量时是合法的（如 $n = 19$ 的第二步，Bob 恰好移除 9 个）。用 `>` 会判错。
2. **$n < 10$**：一次都走不了，返回 `false`（示例 2）。$n = 10$ 时 Alice 移完 10 个，Bob 需要 9 个但只剩 0 个，返回 `true`。
3. **返回值写反**：`return !alice` 与 `return alice` 只差一个字符，含义却完全相反。记忆口诀：退出时 `alice` 为真表示"Alice 该动却动不了"。
4. **误加"策略"分析**：本题没有选择，不要试图讨论"Alice 是否可以少拿一点"——规则规定"恰好"。
5. **`take` 会不会变成 0**：$n \le 50$ 时最多 7 次操作，`take` 从 10 减到 4 就停；如果题目把 $n$ 放大到 $\ge 55$，需要额外处理"移除数降到 0"的语义（本题不会发生）。
6. **奇偶判据的等价实现**：累积和 $S(k) = k(21-k)/2$，若用二分/循环求 $k$，注意 $k$ 的上限是 $7$（$S(8) = 52 > 50$）。
