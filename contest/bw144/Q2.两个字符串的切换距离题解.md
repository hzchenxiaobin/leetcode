# LeetCode 两个字符串的切换距离 题解

## 1. 题目概述

- **标题 / 题号**：两个字符串的切换距离（#3361，medium）
- **链接**：https://leetcode.cn/problems/shift-distance-between-two-strings/
- **来源**：LeetCode 第 144 场双周赛 Q2
- **难度**：中等
- **标签**：数组、字符串、前缀和

**题意**：给定两个等长字符串 $s$、$t$ 和两个长度 26 的数组 `nextCost`、`previousCost`。一次操作可以选择 $s$ 的一个下标 $i$，执行下面两者**之一**：

- **向后**切换一位（`'z'` 之后回到 `'a'`），代价为 `nextCost[j]`，其中 $j$ 是 $s[i]$ 当前在字母表中的下标（$0$ 表示 `'a'`）；
- **向前**切换一位（`'a'` 之前回到 `'z'`），代价为 `previousCost[j]`，$j$ 同上。

**切换距离**是把 $s$ 变成 $t$ 的**最少**总代价，要求返回它。

**约束**：

- $1 \le s.length = t.length \le 10^5$
- 两个串都只含小写英文字母
- $nextCost.length = previousCost.length = 26$
- $0 \le nextCost[i],\ previousCost[i] \le 10^9$

三个要点：字母表是**环**（可以绕圈），每一步的代价**取决于出发位置**（而不是方向固定），字符之间**互相独立**。

## 2. 示例

**示例 1**

```text
输入：s = "abab", t = "baba"
     nextCost     = [100,0,0,...,0]
     previousCost = [1,100,0,...,0]
输出：2
解释：'a' 向前绕 25 步到 'b'（代价 previousCost[0] = 1，其余经过的位置代价都是 0）；
      'b' 向后绕 25 步到 'a'（代价 nextCost[1..25] 全为 0，共 0）。
      四个字符逐位代价为 1、0、1、0，合计 2。
```

**示例 2**

```text
输入：s = "leet", t = "code"
     nextCost = previousCost = [1,1,...,1]
输出：31
解释：逐位取较小方向：9 + 10 + 1 + 11 = 31。
```

**示例 3（补充）**

```text
输入：s = "z", t = "a"
     nextCost = previousCost = [1,1,...,1]
输出：1
解释：'z' 的下标是 25，向后一位就绕回 'a'，代价 nextCost[25] = 1；
      向前则需要 25 步，代价 25。故答案为 1——注意下标是按"出发位置"算的。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法：对每一对 $(a, b)$ 跑一次最短路。字母表只有 26 个点，每个点有两条出边（$j \to j+1$ 代价 `nextCost[j]`，$j \to j-1$ 代价 `previousCost[j]`），用 Dijkstra 或反复松弛都行，单次 $O(26^2)$ 左右，26 个起点共 $O(26^3)$，再对每个下标查表 $O(n)$。

这个做法是对的（也确实能过），但它掩盖了本题最重要的一句话：**最优路径永远不会掉头**。把这一点说清楚，代码就从"跑最短路"退化为"两段区间和取小"，而且能立刻推广到"前缀和优化"。

### 3.2 核心观察：最优路径是单调的

![字母表是一个环，两个方向各有一条顺时针/逆时针路径](images/bw144_q2_shift_model.svg)

把字母表看作环 $\mathbb{Z}_{26}$，位置 $j$ 处有两条有向边：$j \to j+1$（代价 `nextCost[j]`）与 $j \to j-1$（代价 `previousCost[j]`）。

**观察一（折返是浪费）**：设从 $a$ 到 $b$ 的某条路径中，先向后走了若干步又向前走回来。这段"来回"里每条边都被正反各经过一次，把这段删掉后，起点终点不变、总代价只会减少（边权非负）。反复消除折返，可以得到一条**方向单调**的路径。

**观察二（单调路径只有两条）**：单调路径要么一路向后，要么一路向前。记

$$D_{\text{next}}(a,b) = \sum_{\text{沿 } a \to a+1 \to \dots \to b \text{ 的每条边}} \text{nextCost}, \qquad D_{\text{prev}}(a,b) = \sum_{\text{沿 } a \to a-1 \to \dots \to b} \text{previousCost},$$

（两者都允许绕圈，步数取 $0 \sim 25$）则

$$\text{cost}(a,b) = \min\big(D_{\text{next}}(a,b),\ D_{\text{prev}}(a,b)\big).$$

**观察三（各下标独立）**：一次操作只改一个字符，所以把 $s$ 变成 $t$ 的总代价是可加的：

$$\text{ans} = \sum_{i} \text{cost}(s_i, t_i).$$

于是只需预计算 $26 \times 26$ 的 `cost` 表（$26 \times 26 \times 25$ 次加法，约 $1.7 \times 10^4$ 次运算），再对 $n$ 个下标查表。

**观察四（代价按出发位置计）**：向后的第 $k$ 步代价是 `nextCost[(a + k) mod 26]`，也就是说"同样的两步，从不同位置出发代价不同"。这也是为什么不能简单地"按距离乘系数"。

### 3.3 算法流程

![算法流程：预计算 26×26 代价表，再逐位累加](images/bw144_q2_algorithm_flow.svg)

```text
1. for a = 0 .. 25:
2.     for b = 0 .. 25:
3.         if a == b: cost[a][b] = 0; continue
4.         up = 0;  i = a
5.         while i != b:  up += nextCost[i];  i = (i+1) % 26
6.         down = 0;  j = a
7.         while j != b:  down += previousCost[j];  j = (j-1+26) % 26
8.         cost[a][b] = min(up, down)
9. ans = 0
10. for i = 0 .. n-1:  ans += cost[s[i]-'a'][t[i]-'a']
11. return ans
```

### 3.4 示例演算

![示例 1 的逐位代价：a→b 靠向前绕圈，b→a 靠向后绕圈](images/bw144_q2_example_walkthrough.svg)

示例 1 中 `nextCost = [100,0,0,...]`、`previousCost = [1,100,0,...]`，逐位看两个方向：

| 位置 | 转换 | 向后（`nextCost`） | 向前（`previousCost`） | 取小 |
|------|------|--------------------|------------------------|------|
| 0 | `a` → `b` | `nextCost[0] = 100` | 25 步：`previousCost[0] + previousCost[25..2] = 1 + 0 = 1` | **1** |
| 1 | `b` → `a` | 25 步：`nextCost[1..25] = 0` | `previousCost[1] = 100` | **0** |
| 2 | `a` → `b` | 同位置 0 | 同位置 0 | **1** |
| 3 | `b` → `a` | 同位置 1 | 同位置 1 | **0** |

合计 $1 + 0 + 1 + 0 = 2$，与示例输出一致。这个例子很好地说明了"绕远路反而更便宜"：`a → b` 明明只差 1，却要向前绕 25 步，因为 `previousCost[0]` 只有 1，而 `nextCost[0]` 是 100。

再看示例 2（全 1 代价）的逐位计算：

| 位置 | 转换 | 向后步数 | 向前步数 | 取小 |
|------|------|----------|----------|------|
| 0 | `l`(11) → `c`(2) | 17 | 9 | **9** |
| 1 | `e`(4) → `o`(14) | 10 | 16 | **10** |
| 2 | `e`(4) → `d`(3) | 25 | 1 | **1** |
| 3 | `t`(19) → `e`(4) | 11 | 15 | **11** |

合计 31，与示例输出一致。

## 4. 算法细节

1. **两个方向的循环**：向后用 `i = (i + 1) % 26`，向前用 `j = (j - 1 + 26) % 26`（C++ 中负数取模仍为负，必须加 26；Python 的 `%` 天然非负，但统一加 26 更保险）。
2. **步数 0 的处理**：`a == b` 时循环体一次都不执行，`up = down = 0`，`min` 为 0，无需特判。
3. **累加必须用 64 位**：单步代价可达 $10^9$，$25$ 步就是 $2.5 \times 10^{10}$，再乘 $n = 10^5$ 后最坏约 $2.5 \times 10^{15}$，`int` 必然溢出，C++ 用 `long long`，Python 无此问题。
4. **为什么可以直接枚举两个方向而不是 Dijkstra**：由 §3.2 观察一，最优路径单调，故只需比较两条单调路径。这也让预处理从 $O(26^3 \log 26)$ 降到 $O(26^3)$ 的纯加法。
5. **可以进一步用前缀和**：把 `nextCost` 复制成两倍长度求前缀和，$D_{\text{next}}(a,b)$ 就是一段区间和，预处理降到 $O(26^2)$。本题 $26^3$ 已经足够，但写法值得记住。
6. **`cost` 表是静态的**：与 $s$、$t$ 无关，只和两个代价数组有关；多个测试用例重复调用时也是同样的表。
7. **下标映射**：`'a'` 对应 $0$、`'z'` 对应 $25$，用 `c - 'a'`（C++）或 `ord(c) - 97`（Python）。

## 5. 正确性证明

**引理 1（折返可消除）**：设从 $a$ 到 $b$ 的路径中最优者代价为 $C^\*(a,b)$，则存在一条**方向单调**（只向后、或只向前）的路径，其代价等于 $C^\*(a,b)$。

**证明**：把路径看成边序列 $e_1, e_2, \dots, e_m$。若它不单调，则存在下标 $r$ 使得第 $r$ 步与第 $r+1$ 步方向相反：设第 $r$ 步是 $j \to j+1$，第 $r+1$ 步是 $j+1 \to j$（反过来的情形对称）。这两步合起来把路径从 $j$ 带回 $j$，删去它们后，路径的起点终点不变，而代价减少了 $\text{nextCost}[j] + \text{previousCost}[j+1] \ge 0$。反复删除相邻的相反步对，最终得到不含逆序对的路径，即方向单调的路径，且代价不增。∎

**引理 2（单调路径的两种形态）**：方向单调的路径要么全是 $j \to j+1$，要么全是 $j \to j-1$；相应地它从 $a$ 出发走 $k$ 步到达 $(a+k) \bmod 26$（或 $(a-k) \bmod 26$）。因此从 $a$ 到 $b$ 只有两条单调路径：向后 $d_{\uparrow} = (b-a) \bmod 26$ 步，或向前 $d_{\downarrow} = (a-b) \bmod 26$ 步（规定 $a = b$ 时 $d = 0$）。

**证明**：单调路径每步的位移都同号且模 26 非零，故 $k$ 步后位置唯一确定；要到达 $b$，$k$ 必须满足 $k \equiv \pm(b-a) \pmod{26}$。最小的非负解分别是 $(b-a) \bmod 26$ 与 $(a-b) \bmod 26$；而多绕 $26$ 的整数倍只会让路径变长、代价增加（边权非负），故选最小步数即可。∎

**引理 3（逐位可加）**：$\text{ans} = \sum_i \text{cost}(s_i, t_i)$，其中 $\text{cost}(a,b) = \min(D_{\text{next}}(a,b), D_{\text{prev}}(a,b))$。

**证明**：一次操作只作用于一个下标，故任何把 $s$ 变成 $t$ 的操作序列都可以按"下标分组"：第 $i$ 组是作用在 $i$ 上的一串操作，总代价等于各组代价之和，且每组必须把 $s_i$ 变成 $t_i$，其代价 $\ge \text{cost}(s_i, t_i)$。因此总代价 $\ge \sum_i \text{cost}(s_i,t_i)$。反之，对每个 $i$ 独立执行其最优单调路径，就得到一个总代价恰为 $\sum_i \text{cost}(s_i,t_i)$ 的合法操作序列。两者相等。∎

**定理**：算法返回的值等于从 $s$ 到 $t$ 的切换距离。

**证明**：由引理 1 与引理 2，`cost` 表第 8 行求得的正是第 $a$ 个字母到第 $b$ 个字母的最少代价；由引理 3，累加逐位代价即得全局最优。算法输出的就是这个和。∎

## 6. 复杂度分析

- **预处理**：$26 \times 26$ 对字母，每对至多走 $25 + 25$ 步加法，共约 $3.4 \times 10^4$ 次 `long long` 加法，$O(26^3)$，且常数极小（$26^3 = 17576$）。
- **主循环**：$O(n)$ 次查表与加法。
- **总时间**：$O(26^3 + n) = O(n)$。
- **空间**：`cost` 表 $26 \times 26$ 个 `long long`，即 $O(26^2)$，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long shiftDistance(string s, string t, vector<int>& nextCost, vector<int>& previousCost) {
        long long cost[26][26] = {{0}};
        for (int a = 0; a < 26; a++) {
            for (int b = 0; b < 26; b++) {
                if (a == b) continue;
                long long up = 0, down = 0;
                for (int i = a; i != b; i = (i + 1) % 26) up += nextCost[i];
                for (int j = a; j != b; j = (j + 25) % 26) down += previousCost[j];
                cost[a][b] = min(up, down);
            }
        }
        long long ans = 0;
        for (size_t i = 0; i < s.size(); i++) ans += cost[s[i] - 'a'][t[i] - 'a'];
        return ans;
    }
};
```

### Python

```python
class Solution:
    def shiftDistance(self, s: str, t: str, nextCost: list, previousCost: list) -> int:
        cost = [[0] * 26 for _ in range(26)]
        for a in range(26):
            for b in range(26):
                if a == b:
                    continue
                up, i = 0, a
                while i != b:                 # 一路向后（'z' 之后回到 'a'）
                    up += nextCost[i]
                    i = (i + 1) % 26
                down, j = 0, a
                while j != b:                 # 一路向前（'a' 之前回到 'z'）
                    down += previousCost[j]
                    j = (j - 1) % 26
                cost[a][b] = min(up, down)
        return sum(cost[ord(x) - 97][ord(y) - 97] for x, y in zip(s, t))
```

## 8. 边界情况与易错点

1. **`a == b` 时不能进循环**：`while i != b` 天然跳过，结果为 0；若写成 `do-while` 或先加一步就会错。
2. **负数取模**：C++ 里 `(j - 1) % 26` 在 `j = 0` 时得到 `-1`，访问 `previousCost[-1]` 直接越界 UB。必须写 `(j + 25) % 26` 或 `(j - 1 + 26) % 26`。
3. **`int` 溢出**：最大总代价约 $25 \times 10^9 \times 10^5 = 2.5 \times 10^{15}$，超过 `int` 上限（约 $2.1 \times 10^9$）。C++ 的表与答案都要用 `long long`。
4. **"绕远路更便宜"**：不要用"两者字母距离取小"来估算代价，代价取决于**经过哪些出发位置**，必须老老实实累加（示例 1 的 `a → b` 就是绕 25 步更便宜）。
5. **代价可以为 0**：`nextCost[i] = 0` 时多绕几圈代价不变，因此"最小步数"是最优的，但"步数少"不必然"代价小"——两者独立，最终仍以 `min(两条单调路径)` 为准。
6. **下标语义**：操作代价用的是**出发位置**的下标。向后走 $a \to a+1$ 花的是 `nextCost[a]`，不是 `nextCost[a+1]`；这是最容易搞反的地方。
7. **长度相同**：题面保证 `s.length == t.length`，无需处理不等长，也不必担心对齐。
8. **多次调用**：`cost` 表与输入字符串无关，若写成类成员可跨用例复用；但每次重建也只有 $1.7 \times 10^4$ 次运算，不必优化。
