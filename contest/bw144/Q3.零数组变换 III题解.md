# LeetCode 零数组变换 III 题解

## 1. 题目概述

- **标题 / 题号**：零数组变换 III（#3362，medium）
- **链接**：https://leetcode.cn/problems/zero-array-transformation-iii/
- **来源**：LeetCode 第 144 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、双指针、前缀和、排序、堆（优先队列）

**题意**：给定长度为 $n$ 的数组 `nums` 和二维数组 `queries`，其中 `queries[i] = [l_i, r_i]` 表示一次操作：把 `nums` 中下标落在 $[l_i, r_i]$ 内的每个元素**最多**减少 $1$（区间内各元素**独立**决定是否减）。

**零数组**指所有元素都为 $0$ 的数组。要求返回**最多**可以从 `queries` 中删除多少个元素，使得剩下的查询仍然能把 `nums` 变成零数组；若无法做到，返回 `-1`。

**约束**：

- $1 \le nums.length \le 10^5$
- $0 \le nums[i] \le 10^5$
- $1 \le queries.length \le 10^5$
- $0 \le l_i \le r_i < nums.length$

"最多删除"等价于"**最少保留**"：设最少需要保留 $k$ 个查询，答案就是 $m - k$（$m$ 为查询总数）。所以核心是求**最小覆盖子集**。

## 2. 示例

**示例 1**

```text
输入：nums = [2,0,2], queries = [[0,2],[0,2],[1,1]]
输出：1
解释：保留前两个查询即可。它们各覆盖下标 0 与 2，两次叠加把 nums[0]、nums[2] 各减 2 变成 0；
      下标 1 本来就要求 0，无需覆盖。第 3 个查询 [1,1] 是多余的，删掉即可。
```

**示例 2**

```text
输入：nums = [1,1,1,1], queries = [[1,3],[0,2],[1,3],[1,2]]
输出：2
解释：最少保留 2 个，例如 [0,2] 与 [1,3]（或 [0,2] 与 [1,2]），四个下标都被覆盖至少 1 次。
      单个查询无法覆盖全部四个下标，所以最少就是 2，答案是 4 - 2 = 2。
```

**示例 3**

```text
输入：nums = [1,2,3,4], queries = [[0,3]]
输出：-1
解释：唯一的查询只能给每个下标最多减 1，而 nums 需要 1、2、3、4 次覆盖，做不到。
```

## 3. 解题思路

### 3.1 暴力思路

$m$ 个查询有 $2^m$ 个子集，枚举子集判定可行性是指数级；即使用"二分/枚举保留个数 $k$ + 组合搜索"也不现实（$m = 10^5$）。

需要先找到**可行性的等价判据**，把它变成"每个位置至少要覆盖多少次"的约束，再对"最少区间覆盖点需求"这一问题做贪心。

### 3.2 核心观察：可行性 = 逐点覆盖次数够

![每次查询对每个位置最多减 1，于是逐点覆盖次数必须不小于 nums[i]](images/bw144_q3_coverage_model.svg)

**观察一（必要性）**：查询 $[l,r]$ 对位置 $i$ 最多贡献 $1$ 次减一，所以保留下来的查询集 $Q$ 要能把 `nums[i]` 减到 $0$，必须

$$\text{cnt}_Q(i) := \#\{q \in Q : l_q \le i \le r_q\} \ge nums[i] .$$

**观察二（充分性）**：这个条件也是充分的！因为题面允许"区间内每个元素**独立**决定是否减 1"——只要覆盖次数够，就可以对每个位置 $i$ 从覆盖它的查询中挑 $nums[i]$ 个执行减法，其余查询在该位置"放空"。所以

$$Q \text{ 可行} \iff \forall i,\ \text{cnt}_Q(i) \ge nums[i] .$$

**观察三（贪心方向）**：问题变成"用最少的区间覆盖逐点需求量"。经典的贪心：**从左到右扫描位置，需要补覆盖时，优先选右端点最远的区间**——因为它在左边已经"没有用处"（所有被选区间都满足 $l \le i$），那么右端点越远，它对未来位置的潜在贡献越大，绝不会有坏处。

**观察四（怎么维护"候选"与"已选"）**：

- **候选池**：把所有 $l = i$ 的查询在扫描到 $i$ 时加入一个**大根堆**（按 $r$ 排序），这样堆顶就是右端点最远的可用查询；堆里可能残留 $r < i$ 的"废区间"，弹掉即可。
- **已选集合**：被选中的查询，其右端点进一个**小根堆**，用来判断"它还在覆盖当前位置吗"。当小根堆顶 $r < i$ 时，说明这个查询已经过期，覆盖计数 `cur` 减一。

于是每个位置 $i$ 的"还缺多少次覆盖"就是 `need = nums[i] - cur`，从大根堆里取 `need` 个右端点最远的查询即可。

### 3.3 算法流程

![算法流程：按左端点入大根堆，按需取最远右端点，用小根堆回收过期查询](images/bw144_q3_heap_flow.svg)

```text
1. 按左端点分组：byL[l] = 所有以 l 为左端点的查询的右端点
2. avail = 大根堆（存 -r）；active = 小根堆（存已选查询的 r）；cur = 0；used = 0
3. for i = 0 .. n-1:
4.     while active 非空 and active.top() < i:  pop；cur -= 1     # 过期查询退出
5.     把 byL[i] 全部压入 avail
6.     need = nums[i] - cur
7.     while need > 0:
8.         while avail 非空 and -avail.top() < i:  pop          # 右端点已在左侧，永远无用
9.         if avail 为空: return -1
10.        r = -pop(avail)；push(active, r)；cur += 1；used += 1；need -= 1
11. return m - used
```

### 3.4 示例演算

![示例 2 的逐步演算](images/bw144_q3_example_walkthrough.svg)

以示例 2（`nums = [1,1,1,1]`，`queries = [[1,3],[0,2],[1,3],[1,2]]`）为例：

| $i$ | 新入 avail | 过期弹栈 | `cur` | `nums[i]` | 选取 | `used` | 说明 |
|-----|-----------|----------|-------|-----------|------|--------|------|
| 0 | {2} | — | 0 | 1 | 取 $r=2$（来自 `[0,2]`） | 1 | 位置 0 只有 `[0,2]` 能覆盖 |
| 1 | {3,3,2} | — | 1 | 1 | 不需要 | 1 | `[0,2]` 仍覆盖 1 |
| 2 | — | — | 1 | 1 | 不需要 | 1 | `[0,2]` 仍覆盖 2 |
| 3 | — | 弹出 $r=2$，`cur=0` | 0 | 1 | 取 $r=3$（来自 `[1,3]`） | 2 | 位置 3 只剩 $r=3$ 的查询可用 |

最终 `used = 2`，答案 $4 - 2 = 2$，与示例一致。注意 $i = 3$ 时 `avail` 里只剩两个 $r = 3$ 的查询（$r = 2$ 的那个已经被当作过期废区间弹掉），此时从大根堆取出的自然是能覆盖位置 3 的最远右端点。

## 4. 算法细节

1. **按左端点分组**：`byL` 是长度 $n$ 的 `vector<vector<int>>`，总空间 $O(m)$，比排序 $O(m \log m)$ 更快；也可以用一次排序 + 指针。
2. **两个堆的分工**：`avail` 用大根堆（C++ 默认 `priority_queue<int>` 存 $r$，Python 存 $-r$）取"最远右端点"；`active` 用小根堆（`priority_queue<int, vector<int>, greater<int>>` / Python 直接 `heappush`）取"最早过期的已选查询"。
3. **`cur` 与 `active` 必须同步**：`cur` 等于 `active` 中尚未过期的元素个数。每次 `pop` 出过期查询就 `cur--`；每次选中新查询就 `cur++` 并压入 `active`。
4. **懒删除 `avail` 里的废区间**：右端点 $< i$ 的候选查询再也不可能覆盖任何位置 $i' \ge i$，但不必在入堆时清理，等到要取用时再弹（每个查询最多被弹一次，均摊 $O(\log m)$）。
5. **可行性判据的另一面**：$\sum_i nums[i]$ 可以大于总覆盖量时也会在扫描中暴露出来（某个位置 `avail` 耗尽），返回 `-1`。
6. **答案与 `used`**：`used` 是贪心选出的最少保留数，答案 = $m$ - `used`。注意不是"删除的查询数 = 未被覆盖的位置数"之类的错误直觉。
7. **复杂度**：每个查询入堆、出堆各 $O(\log m)$；每个位置一次 `while` 循环，整体 $O((n+m)\log m)$。
8. **为什么从大根堆里取的一定"合法"**：能进入 `avail` 的查询都满足 $l \le i$（扫描到 $l$ 时才入堆），再排除 $r < i$ 的，剩下的必然满足 $l \le i \le r$。

## 5. 正确性证明

**引理 1（可行性判据）**：查询子集 $Q$ 能把 `nums` 变成零数组，当且仅当对每个 $i$ 有 $\text{cnt}_Q(i) \ge nums[i]$。

**证明**：

- **必要性**：每次查询对位置 $i$ 至多减少 $1$，要把它从 $nums[i]$ 减到 $0$，至少需要 $nums[i]$ 次覆盖。
- **充分性**：若 $\text{cnt}_Q(i) \ge nums[i]$ 对所有 $i$ 成立，则对每个 $i$，从覆盖 $i$ 的查询里任选 $nums[i]$ 个，令这些查询"在位置 $i$ 上执行减 1"，其余查询在位置 $i$ 上"不执行"。题面明确允许区间内各元素独立决定，所以这样逐点拼出的方案是合法的，且使每个位置恰好减到 $0$。∎

**引理 2（贪心选择性）**：在扫描到位置 $i$、需要补充覆盖时，记

$$Q_i = \{q : l_q \le i \le r_q,\ q \notin G\}$$

为"尚未被贪心选中且覆盖 $i$ 的查询集合"。若 $Q_i \ne \varnothing$，取其中右端点最大者 $q^\*$，则存在一个**最小**可行集包含 $G \cup \{q^\*\}$。

**证明**：设 $O$ 是包含 $G$ 的最小可行集（归纳假设其存在）。若 $q^\* \in O$ 则已证。否则由于 $O$ 覆盖 $i$ 的次数 $\ge nums[i] > \text{cnt}_G(i)$（$G$ 在 $i$ 处还缺覆盖），必存在 $q' \in O \setminus G$ 覆盖 $i$，即 $q' \in Q_i$，于是 $r_{q'} \le r_{q^\*}$。

令 $O' = (O \setminus \{q'\}) \cup \{q^\*\}$，则 $\lvert O' \rvert = \lvert O \rvert$，且 $G \cup \{q^\*\} \subseteq O'$。验证 $O'$ 可行：

- 对 $j < i$：由贪心的过程，$G$ 在位置 $j$ 已经满足 $\text{cnt}_G(j) \ge nums[j]$（贪心在扫描到 $j$ 时已补齐），且 $G \subseteq O'$，故 $\text{cnt}_{O'}(j) \ge nums[j]$。
- 对 $j \ge i$：$q'$ 只可能在 $j \in [i, r_{q'}]$ 上贡献，而 $l_{q^\*} \le i \le j$ 且 $r_{q^\*} \ge r_{q'} \ge j$，故 $q^\*$ 覆盖 $j$，替换后覆盖次数不减。

于是 $O'$ 仍是可行集且大小不变，仍为最小可行集。∎

**引理 3（贪心不漏解）**：若贪心在某位置 $i$ 需要补覆盖时 $Q_i = \varnothing$，则不存在任何可行查询子集，答案应为 $-1$。

**证明**：由引理 2 反复应用，任何时刻都存在一个最小可行集 $O \supseteq G$。若 $Q_i = \varnothing$，则所有覆盖 $i$ 的查询要么已在 $G$ 中（共 $\text{cnt}_G(i) = cur < nums[i]$ 个），要么不满足 $l_q \le i \le r_q$（即根本不覆盖 $i$），于是任何 $O \supseteq G$ 都有 $\text{cnt}_O(i) = \text{cnt}_G(i) < nums[i]$，由引理 1 不可行，与"$O$ 可行"矛盾。故可行集不存在。∎

**定理**：若存在可行子集，算法返回 $m - k_{\min}$，其中 $k_{\min}$ 是最小可行子集大小；否则返回 $-1$。

**证明**：算法不返回 $-1$ 时，最终 $G$ 在每个位置 $i$ 都满足 $\text{cnt}_G(i) \ge nums[i]$（第 7–10 行的循环保证），由引理 1，$G$ 可行，故 $\lvert G \rvert \ge k_{\min}$。另一方面，由引理 2 逐步交换可得存在最小可行集 $O \supseteq G$，故 $\lvert G \rvert \le \lvert O \rvert = k_{\min}$。两者夹逼得 $\lvert G \rvert = k_{\min}$，答案 $m - \lvert G \rvert = m - k_{\min}$ 正确。若算法返回 $-1$，由引理 3 可行集不存在，返回 $-1$ 也正确。∎

## 6. 复杂度分析

- **建 `byL` 分组**：$O(n + m)$。
- **扫描**：$i$ 从 $0$ 到 $n-1$，每个查询最多入 `avail` 一次、出 `avail` 一次、入 `active` 一次、出 `active` 一次，每次堆操作 $O(\log m)$，故堆操作总计 $O(m \log m)$。
- **总时间**：$O(n + m \log m)$，每个查询最多 4 次堆操作（进出两个堆），总计约 $4 \times 10^5$ 次，每次 $O(\log m)$，$m = 10^5$ 时实测几十毫秒。
- **空间**：`byL` 存 $m$ 个整数 $O(m)$；两个堆各 $O(m)$；合计 $O(n + m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxRemoval(vector<int>& nums, vector<vector<int>>& queries) {
        int n = nums.size();
        vector<vector<int>> byL(n);
        for (auto& q : queries) byL[q[0]].push_back(q[1]);

        priority_queue<int> avail;                                   // 候选查询的右端点（大根堆）
        priority_queue<int, vector<int>, greater<int>> active;        // 已用查询的右端点（小根堆）
        int cur = 0, used = 0;                                        // cur：当前被覆盖次数

        for (int i = 0; i < n; i++) {
            while (!active.empty() && active.top() < i) {             // 已失效的查询退出
                active.pop();
                cur--;
            }
            for (int r : byL[i]) avail.push(r);
            int need = nums[i] - cur;                                 // 还需要几次覆盖
            while (need > 0) {
                while (!avail.empty() && avail.top() < i) avail.pop(); // 右端点已在左侧，永远没用
                if (avail.empty()) return -1;
                int r = avail.top();
                avail.pop();
                active.push(r);
                cur++;
                used++;
                need--;
            }
        }
        return (int)queries.size() - used;
    }
};
```

### Python

```python
import heapq
from collections import defaultdict


class Solution:
    def maxRemoval(self, nums: list, queries: list) -> int:
        n = len(nums)
        by_l = defaultdict(list)
        for l, r in queries:
            by_l[l].append(r)

        avail = []      # 大根堆（存 -r）：尚未使用、仍可能覆盖当前位置的查询
        active = []     # 小根堆：已使用的查询的右端点，用于判断何时失效
        cur = used = 0

        for i in range(n):
            while active and active[0] < i:
                heapq.heappop(active)
                cur -= 1
            for r in by_l[i]:
                heapq.heappush(avail, -r)
            need = nums[i] - cur
            while need > 0:
                while avail and -avail[0] < i:
                    heapq.heappop(avail)          # 右端点已在左侧，永远用不上
                if not avail:
                    return -1
                r = -heapq.heappop(avail)
                heapq.heappush(active, r)
                cur += 1
                used += 1
                need -= 1

        return len(queries) - used
```

## 8. 边界情况与易错点

1. **`nums[i] = 0`**：不需要覆盖，`need = 0`，直接跳过。若漏掉这个判断，会误选查询，答案偏小。
2. **返回 `-1` 的时机**：是在"某一个位置怎么凑都不够"时返回，而不是最后才判断；并且要确认此时 `avail` 里确实没有可用查询（包括"有查询但右端点 $< i$"的情况）。
3. **过期查询必须从句柄堆弹出**：`active` 里残留的旧查询若不弹出，`cur` 会虚高，导致该位置误判为"已够覆盖"，最终数组减不到零。
4. **`avail` 的清理位置**：只在"要取用"时清理（懒删除），不要在入堆时清理——入堆时还不知道当前位置，逻辑会乱。
5. **`cur` 与 `active` 的一致性**：每次 `cur++` 必须伴随一次 `active.push`，每次 `active.pop` 必须伴随 `cur--`，这对不变式是整份代码最容易出错的地方。
6. **答案公式**：返回 `m - used`（删除数），不是 `used`；也不是 `n - used`。
7. **区间要求 $l \le r$**：题面保证，无需处理空区间；但若 $l = r$，该查询只覆盖一个点，贪心同样正确。
8. **重复查询**：允许重复（示例 1 里有两个 `[0,2]`），堆天然处理，不要去重。
9. **`nums` 总和很大**：`cur` 与 `used` 最大为 $m \le 10^5$，`int` 足够；但若把覆盖计数写成 `long long` 也没坏处。
