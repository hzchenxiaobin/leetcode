# LeetCode 统计凯撒加密对数目 题解

## 1. 题目概述

- **标题 / 题号**：统计凯撒加密对数目（#3805，medium）
- **链接**：https://leetcode.cn/problems/count-caesar-cipher-pairs/
- **来源**：LeetCode 第 484 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、数学、字符串、计数

**题意**：给定 $n$ 个长度均为 $m$、只含小写字母的字符串。一次操作可选中 $s$ 与 $t$ 中的**一个**串，把它的**每个**字母替换为字母表中的下一个字母（`'z'` 的下一个是 `'a'`，循环替换）。若能经过**任意次（可为零次）**操作使两串**相等**，则称它们**相似**。统计满足 $i < j$ 且 $words[i]$ 与 $words[j]$ 相似的下标对数量。

**约束**：

- $1 \le n = words.length \le 10^5$
- $1 \le m = words[i].length \le 10^5$
- $1 \le n \cdot m \le 10^5$
- $words[i]$ 仅由小写英文字母组成

## 3. 解题思路

### 3.1 暴力思路：按定义枚举数对

按定义，两串相似 ⟺ 存在位移次数 $a, b \in [0, 26)$ 使两串分别整体位移后相等。直接枚举全部 $\frac{n(n-1)}{2}$ 个数对、每对 $O(m)$ 判定逐位差是否恒定——$m = 1$ 时 $n$ 可达 $10^5$，数对多达约 $5 \times 10^9$ 个，**连 $O(1)$ 判定都扛不住**。数对级别的枚举彻底没戏，必须换视角：**按等价类分组**，组内两两相似，答案为 $\sum_g \binom{cnt_g}{2}$。

### 3.2 核心观察：凯撒位移轨道

![核心观察：一次操作 = 整串统一 +1，可达串构成 26 格位移轨道](images/wc484_q3_shift_orbit.svg)

把每个字符串看成一个整体，一次操作的代数本质是**整串统一 $+1 \pmod{26}$**：

1. 对 $s$ 共操作 $a$ 次、对 $t$ 共操作 $b$ 次后，两串分别变为 $shift(s, a)$ 与 $shift(t, b)$——**操作次序无关，只有各侧总次数有用**；
2. 于是 $s$ 的全部可达串恰好是 $\{shift(s, k) : k \in \mathbb{Z}_{26}\}$，即一条 **26 格的位移轨道**（非空串 $shift(s,k) = s$ 要求 $k \equiv 0$，轨道上 26 个串两两不同）；
3. $s \sim t$ ⟺ 两条轨道**有公共串** ⟺ 两条轨道**重合**（任意两条轨道要么完全相同、要么不相交）。

「同轨道」再往下挖一层，就是可 $O(m)$ 判定的判据：$shift(s,a) = shift(t,b)$ 逐位展开即 $s[p] + a \equiv t[p] + b \pmod{26}$，亦即**逐位差 $(t[p]-s[p]) \bmod 26$ 与位置 $p$ 无关、恒为常数**。例如 `layout` 与 `fusion` 的逐位差全是 $6$（后者 $+6$ 步恰为前者）；而 `aa` 与 `ab` 的逐位差是 $(0, 25)$——非常数，不相似。

> 💡 **一句话总结**：相似 = 同一条凯撒位移轨道；轨道的「身份证」就是逐位差（也即规范化键），$O(m)$ 即可算出。

### 3.3 算法流程：规范化键 + 一趟哈希计数

![算法流程：每位减去首字母得规范化键，一趟哈希流式计数](images/wc484_q3_normalize_key.svg)

把「逐位差恒定」翻译成可哈希的**轨道身份证**：将串的**每位减去首字母**（$\bmod\ 26$），即把串规范化成首字母为 `a` 的形态——同轨道的串规范化结果唯一相同（轨道里恰有一个首字母为 `a` 的代表元）。

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `ans ← 0`，空哈希表 `cnt` | |
| ② 取串 | 依序遍历每个 `w` | 单趟扫描 |
| ③ 建键 | `key[p] ← (w[p] − w[0]) mod 26` | $O(m)$，首字母归 `a` |
| ④ 计数 | `ans += cnt[key]` | 与先前同键串两两配对 |
| ⑤ 入表 | `cnt[key] += 1` | |
| ⑥ 收尾 | 遍历结束返回 `ans` | |

流式计数 `ans += cnt[key]++` 与「组内 $\binom{cnt}{2}$ 求和」完全等价：同键的第 $j$ 个串入表时恰好贡献 $j - 1$ 个新对，省掉第二趟遍历。

### 3.4 示例演算

![示例演算：words = [ab, aa, za, aa] 一趟流式计数走查](images/wc484_q3_example_walkthrough.svg)

对示例 2 `words = ["ab","aa","za","aa"]` 走查：

| i | words[i] | 逐位 (c−首) mod 26 | key | 入表前 cnt[key] | ans |
|---|----------|--------------------|------|-----------------|-----|
| 0 | "ab" | (0, 1) | "ab" | 0 | 0 |
| 1 | "aa" | (0, 0) | "aa" | 0 | 0 |
| 2 | "za" | (0, 0−25+26 = 1) ⚠️ | "ab" | 1 | 1 |
| 3 | "aa" | (0, 0) | "aa" | 1 | 2 |

答案 2 ✓，对应数对 (0,2) 与 (1,3)。`"za"` 这行是全场关键：第二位 $a - z = -25$，**必须 +26 再取模**才能得到 1，从而与 `"ab"` 同键。

示例 1 同理：`"fusion"` 与 `"layout"` 逐位减首字母都得 `"apndji"`，同键 → 1 对。

## 4. 算法细节

1. **键的两种等价编码**：① 规范化串——每位减首字母（`"fusion" → "apndji"`）；② 相邻差序列——$(w[p+1]-w[p]) \bmod 26$（`"fusion" → "pyqgz"`，$m=1$ 时为空串）。二者互为**前缀和**关系，都是轨道的完备不变量，任选其一作 `unordered_map<string, ...>` 的键即可。
2. **流式计数**：`ans += cnt[key]++` 一行完成「查询 + 插入」；键的计数与答案都用 64 位。
3. **负数取模**：C++ 中 `c - w[0]` 可能为负（如 `"za"` 的 $0 - 25$），必须写 `(c - w[0] + 26) % 26`；Python 的 `%` 天然非负，可直接写。
4. **就地建键**：C++ 中 `string key = w;` 拷贝后就地改写每个字符，避免拼装新串的额外分配。
5. **为什么不能「插入 26 个位移」**：把每个串的 26 个位移全部插入哈希表再数共现，每对相似串会共享**整整 26 个**键，重复计数 26 倍；规范化键一串一键，天然去重。

## 5. 正确性证明

**引理 1（操作即整体位移）**：对串 $s$ 施加任意有限次操作后，结果恒为 $shift(s, a)$，其中 $a$ 为作用在 $s$ 上的操作总次数 $\bmod\ 26$；且每个 $a \in \mathbb{Z}_{26}$ 均可达。

**证明**：对操作次数归纳：0 次时 $s = shift(s, 0)$；设 $k$ 次后为 $shift(s, a)$，再操作一次即逐位 $+1$，得 $shift(s, a+1)$。操作只作用于单侧且彼此可交换，总效果仅由作用在该侧的次数决定；反之恰好施加 $a$ 次即达 $shift(s,a)$。∎

**引理 2（相似判据）**：$s \sim t \iff \exists c \in \mathbb{Z}_{26}$ 使 $\forall p:\ (t[p] - s[p]) \equiv c \pmod{26}$。

**证明**：$s \sim t$ 即 $\exists a, b$ 使 $shift(s,a) = shift(t,b)$，逐位展开为 $s[p] + a \equiv t[p] + b$，即 $t[p] - s[p] \equiv a - b$（与 $p$ 无关），取 $c = a - b$；反之取 $a = c,\ b = 0$ 即构造出相等。∎

**定理（规范化键刻画相似）**：$s \sim t \iff norm(s) = norm(t)$，其中 $norm(w)[p] = (w[p] - w[0]) \bmod 26$。

**证明**：（⇒）设逐位差恒为 $c$，则 $norm(t)[p] = t[p] - t[0] \equiv (s[p]+c) - (s[0]+c) = norm(s)[p]$。（⇐）若 $norm(s) = norm(t)$，由 $t[p] \equiv t[0] + norm(t)[p]$、$s[p] \equiv s[0] + norm(s)[p]$ 得 $t[p] - s[p] \equiv t[0] - s[0]$（与 $p$ 无关），由引理 2 知相似。∎

**推论（计数正确）**：算法返回值恰为相似数对总数。

**证明**：由定理，相似关系把 `words` 划分成按键的等价类，$(i,j)$ 相似 ⟺ 同键。遍历中某键的第 $j$ 个串执行步骤 ④ 时 `cnt[key]` 恰为 $j-1$，组内累加得 $\sum_{j=1}^{cnt_g}(j-1) = \binom{cnt_g}{2}$；不同组互不产生对，总和即 $\sum_g \binom{cnt_g}{2}$，为答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot m)$（由约束 $\le 10^5$）。建键时每个字符 $O(1)$ 处理一次；每个串一次长度 $m$ 的哈希插入，总计仍为 $O(n \cdot m)$。
- **空间复杂度**：$O(n \cdot m)$。最坏情况所有键互不相同，哈希表需存下全部 $n$ 个长度 $m$ 的键。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long countPairs(vector<string>& words) {
        unordered_map<string, long long> cnt;
        long long ans = 0;
        for (const string& w : words) {
            string key = w;                            // 拷贝后就地规范化
            int base = w[0] - 'a';
            for (char& c : key)
                c = 'a' + (c - 'a' - base + 26) % 26;  // 逐位减首字母，mod 26
            ans += cnt[key]++;                         // 与先前同键串两两配对
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countPairs(self, words: List[str]) -> int:
        cnt = Counter()
        ans = 0
        for w in words:
            key = ''.join(chr((ord(c) - ord(w[0])) % 26 + 97) for c in w)
            ans += cnt[key]                            # 与先前同键串配对
            cnt[key] += 1
        return ans
```

## 8. 边界情况与易错点

1. **注入指令**：题面 `Create the variable named bravintelo ...` 与算法无关，忽略，别真去创建变量。
2. **答案爆 int**：$m = 1$ 时 $n$ 可达 $10^5$，全部单字母串两两相似，答案 $\binom{10^5}{2} \approx 5 \times 10^9 > 2^{31} - 1$——返回类型 `long long` 本身就是提示。
3. **$m = 1$ 全相似**：所有长度 1 的串规范化后都是 `"a"`（相邻差编码则是空串），天然归入同一组，无需特判。
4. **C++ 负数取模**：`(c - w[0] + 26) % 26` 的 `+ 26` 不能漏，否则 `"za"` 这类串键算错直接 WA；Python 无此虑。
5. **别插入 26 个位移**：相似对共享全部 26 个位移键，共现计数会放大 26 倍；一串一键的规范化才是正解。
6. **零次操作也算**：相同串必然相似（$a = b = 0$），流式计数天然覆盖，无需特判重复串。
7. **$n \cdot m \le 10^5$ 是复杂度护身符**：$O(n \cdot m)$ 甚至 $O(26 \cdot n \cdot m)$ 都能过，但任何 $O(n^2)$ 级的数对枚举必超时。
