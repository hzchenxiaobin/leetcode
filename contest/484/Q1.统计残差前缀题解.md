# LeetCode 统计残差前缀 题解

## 1. 题目概述

- **标题 / 题号**：统计残差前缀（#3803，easy）
- **链接**：https://leetcode.cn/problems/count-residue-prefixes/
- **来源**：LeetCode 第 484 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、计数

**题意**：给定仅含小写字母的字符串 `s`。若某个（非空）前缀的**不同字符个数** $d$ 恰好等于**长度模三的余数**，即 $d = L \bmod 3$，则称该前缀为**残差前缀**（residue prefix）。返回 `s` 中残差前缀的数量。

**约束**：

- $1 \le s.length \le 100$
- `s` 仅包含小写英文字母

> ⚠️ **审题关键**：① 条件方向是 **distinct == len % 3**——**长度取模、种类数不取模**，不是 $L = d \bmod 3$，也不是两边都取模；② 前缀**非空**、从长度 1 起算，共 $n$ 个；③ 「不同字符的数量」是**种类数**（`"bob"` 是 2），不是出现次数。签到题的罚时几乎全烧在这三句上。

## 2. 示例

**示例 1**

```text
输入：s = "abc"
输出：2
解释："a"（d=1, 1%3=1 ✓）、"ab"（d=2, 2%3=2 ✓）是残差前缀；
      "abc"（d=3, 3%3=0 ✗）不是。答案是 2。
```

**示例 2**

```text
输入：s = "dd"
输出：1
解释："d"（d=1, 1%3=1 ✓）是；"dd"（d=1, 2%3=2 ✗）不是——
      长度在涨、种类数停着，两条轨迹就此错开。
```

**示例 3**

```text
输入：s = "bob"
输出：2
解释："b"（✓）、"bo"（✓）；"bob"（d=2, 3%3=0 ✗）不是。
```

**示例 4（自制，观察「冻结」）**

```text
输入：s = "abaca"
输出：2
解释："a"（✓）、"ab"（✓）；"aba"（d=2, 0 ✗）、"abac"（d=3, 1 ✗）、
      "abaca"（d=3, 2 ✗）。第 3 种字母一登场 d 升到 3，而 L%3 ≤ 2，
      之后永远追不上——答案从此冻结在 2。
```

## 3. 解题思路

签到题的目标是**从题面到代码的最短路径 + 零调试一次过**。算法零难度，风险集中在**读题方向**与**前缀边界**。

### 3.1 暴力思路：每个前缀重数一遍

枚举每个前缀长度 $L$，内层重建哈希集合数一遍不同字符，再与 $L \bmod 3$ 比较。复杂度 $O(n^2)$，$n \le 100$ 时约 $10^4$ 次操作，**也能过**——本题数据规模不设防。

但这个写法浪费了一个明显事实：**前缀是逐字符延长的**，从 $L-1$ 到 $L$ 只多了一个字符，不同字符数要么不变、要么恰加一，没必要从头重数。把「每个前缀重算」改成「随扫随更」，代码量相同、复杂度降为 $O(n)$。

### 3.2 核心观察：两条轨迹的相遇问题

![核心观察：distinct 只增不减，L%3 循环 0·1·2，只在交点命中](images/wc484_q1_residue_condition.svg)

把比较双方画成随 $L$ 变化的两条轨迹，三个要点立刻浮现：

1. **余数轨迹有上界**：$L \bmod 3 \in \{0, 1, 2\}$，而**非空**前缀至少含 1 个字符，$d \ge 1$——所以 $L \equiv 0 \pmod 3$ 的前缀要求 $d = 0$，**恒不可能**。条件实际坍缩为两种命中形态：
   - $L \equiv 1 \pmod 3$ 且前缀**只有 1 种字母**（如 `"a"`、`"aaaa"`）；
   - $L \equiv 2 \pmod 3$ 且前缀**恰好 2 种字母**（如 `"bo"`、`"abab"`）。
2. **种类轨迹单调不减**：$d$ 沿前缀只增不减（上界 26）。一旦 $d$ 达到 3，就永远超过 $L \bmod 3$ 的上界 2——**答案从此冻结**，之后全是 ✗。这是一个免费的可选剪枝（提前退出），$n \le 100$ 时无关性能，但「单调量追不上界即截断」的意识可迁移。
3. **增量维护**：`seen[26]` 布尔表 + 一个 `distinct` 计数器，每读一个字符 $O(1)$ 更新，一趟 $O(n)$ 完成。

> 💡 由要点 1 还有两个免费结论：**答案至少为 1**（$L=1$ 时 $d=1=1 \bmod 3$ 恒命中，返回 0 必有 bug）；**全同字母串**（如 `"aaaa"`）$d$ 恒为 1，只有 $L \equiv 1 \pmod 3$ 命中，答案为 $\lceil n/3 \rceil$。

### 3.3 算法流程

![算法流程：一趟扫描，增量维护 distinct，一行比较计数](images/wc484_q1_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `distinct ← 0`，`seen[26] ← 全 false`，`ans ← 0` | 计数器 + 出现表 |
| ② 取字符 | 从左到右取 `ch`，当前前缀长度 `L = i + 1` | 一趟扫描 |
| ③ 增量更新 | `ch` 首次出现则标记并 `distinct++` | 老字符什么都不做 |
| ④ 比较计数 | `distinct == L % 3` 成立则 `ans++` | **一行覆盖三种余数** |
| ⑤ 收尾 | 扫完返回 `ans` | 可选剪枝：`distinct > 2` 即可 break |

> 💡 第 ④ 步无需对 $L \bmod 3 = 0$ 特判：$d \ge 1$ 恒成立，等式自动失败——**把「不可能分支」交给不等式本身**，是砍掉特判代码的常用思路。

### 3.4 示例演算

![示例演算：官方样例 bob / dd 走查](images/wc484_q1_example_walkthrough.svg)

对示例 3 `s = "bob"` 逐前缀走查：

| 前缀 | b | bo | bob |
|------|---|----|-----|
| $L$ | 1 | 2 | 3 |
| $L \bmod 3$ | 1 | 2 | 0 |
| $d$（distinct） | 1 | 2 | 2 |
| 命中？ | ✓ | ✓ | ✗（需 $d = 0$） |

答案 2 ✓

示例 2 `"dd"`：`"d"` 命中（$1 = 1 \bmod 3$）；`"dd"` 时 $L$ 涨到 2 而 $d$ 停在 1，两条轨迹错开 → 答案 1 ✓

## 4. 算法细节

1. **出现表任选**：`bool seen[26]`（下标 `ch - 'a'`）或 `set` 均可，每次查询 $O(1)$；字符集固定 26，「值域受限用桶替哈希」是省常数的小习惯。
2. **比较式即定义**：`ans += (distinct == L % 3)`——布尔转整数直接累加，三种余数统一处理；$L \bmod 3 = 0$ 的不可能分支被 $d \ge 1$ 自然过滤，无需 `if` 分支。
3. **前缀长度从 1 起算**：循环下标 `i` 从 0 开始，取模必须用 `i + 1`（当前前缀长度）——off-by-one 是签到题最常见的罚时来源。
4. **可选冻结剪枝**：`if (distinct > 2) break;`——由单调性其后所有前缀必不命中，放比较前或比较后都不影响结果（$d \ge 3$ 时等式必失败）。$n \le 100$ 无性能意义，写不写都对。
5. **提交前心算三例**：`"a"` → 1、`"ab"` → 2、`"abc"` → 2，三秒锁死方向与边界。

## 5. 正确性证明

**引理 1（增量不变量）**：处理完前 $k$ 个字符后，`distinct` 恰等于前缀 $s[0..k)$ 中不同字符的个数。

**证明**：对 $k$ 归纳。$k = 0$ 时 `distinct` 为 0，空前缀不同字符数为 0，成立。设 $k$ 时成立，考察第 $k+1$ 个字符 $ch$：若 $ch$ 在前 $k$ 个字符中出现过，则 `seen` 已标记，计数器不变，且前缀字符集合未扩大，结论保持；若未曾出现，`seen` 标记且 `distinct` 加一，前缀字符集合恰扩大一个新种类，结论亦保持。∎

**引理 2（整除长度必不命中）**：$L \equiv 0 \pmod 3$ 的前缀不是残差前缀。

**证明**：前缀非空，至少包含一个字符，故 $d \ge 1 > 0 = L \bmod 3$，等式 $d = L \bmod 3$ 不成立。∎

**引理 3（冻结）**：若长度 $L_0$ 的前缀满足 $d(L_0) \ge 3$，则一切 $L \ge L_0$ 的前缀均不命中。

**证明**：前缀逐字符延长，字符集合只扩不缩，故 $d$ 关于 $L$ 单调不减，$d(L) \ge d(L_0) \ge 3$；而 $L \bmod 3 \le 2 < 3 \le d(L)$，等式恒不成立。∎

**定理**：算法返回值等于 `s` 中残差前缀的数量。

**证明**：循环第 $i$ 轮（$L = i + 1$）时，由引理 1，`distinct` 精确等于长度为 $L$ 的前缀的不同字符数；算法执行的比较 `distinct == L % 3` 与残差前缀的定义完全一致，成立则计数一次。每个长度 $L \in [1, n]$ 恰对应一轮比较，不重不漏，故计数总和即残差前缀总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n = s.length$。每个字符一次出现表查询 + 至多一次计数器自增 + 一次比较，均为 $O(1)$。这已是下界——每个字符都可能引入新种类改变 $d$，必须全部读过。
- **空间复杂度**：$O(|\Sigma|) = O(26) = O(1)$。一张出现表 + 三个整型计数器，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int residuePrefixes(string s) {
        bool seen[26] = {false};
        int distinct = 0, ans = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            int c = s[i] - 'a';
            if (!seen[c]) {
                seen[c] = true;
                ++distinct;
            }
            ans += (distinct == (i + 1) % 3);  // L%3==0 时 d≥1 自动不等
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def residuePrefixes(self, s: str) -> int:
        seen = set()
        ans = 0
        for i, ch in enumerate(s):
            seen.add(ch)
            ans += len(seen) == (i + 1) % 3
        return ans
```

> 💡 **Python 一行流**：`return sum(len({*s[:i]}) == i % 3 for i in range(1, len(s) + 1))`——每个前缀重数一遍的 $O(n^2)$ 版，$n \le 100$ 随便过；比赛求稳推荐上面的增量版。

## 8. 边界情况与易错点

1. **条件方向（头号陷阱）**：是 $d = L \bmod 3$，不是 $L = d \bmod 3$，也不是 $d \bmod 3 = L \bmod 3$（后者在 $d=3, L=3$ 时会误判命中）。读题 30 秒先锁定「谁取模」。
2. **别把空前缀算进去**：题面定义前缀**非空**。若从 $L = 0$ 起算，$d = 0 = 0 \bmod 3$ 会凭空多计 1。
3. **off-by-one**：循环下标 `i` 从 0 开始，取模要用 `i + 1`（当前前缀长度），不是 `i`。
4. **$L \bmod 3 = 0$ 无需特判**：$d \ge 1$ 恒成立，等式自动失败；手写 `if (L % 3 == 0) continue;` 多余但不致命。
5. **distinct 是种类数**：`"bob"` 的 $d = 2$ 不是 3——别数出现次数。
6. **答案下界 1**：$L = 1$ 恒命中；若返回 0 必然有 bug。
7. **全同字母串**：$d$ 恒 1，仅 $L \equiv 1 \pmod 3$ 命中，答案 $\lceil n/3 \rceil$（`"aaaa"` → 2）——可当对拍样例。
8. **规模极小**：$n \le 100$，无溢出、无性能压力；签到题的胜负全在读题与一次过率，不在算法。
