# LeetCode 需要教语言的最少人数 题解

## 1. 题目概述

- **标题 / 题号**：需要教语言的最少人数（#1733，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-people-to-teach/
- **来源**：LeetCode 第 44 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、哈希表

**题意**：社交网络有 $m$ 个用户、$n$ 种语言。`languages[i]` 是用户 $i$ 掌握的语言集合；`friendships[i] = [u, v]` 表示好友关系（**没有传递性**）。两个好友能沟通 ⟺ 掌握同一门语言。你可以**选一门语言**教给若干用户，使**所有好友对**都能沟通。求最少需要教多少名用户。

**约束**：

- $2 \le n \le 500$
- `languages.length == m`，$1 \le m \le 500$
- $1 \le languages[i].length \le n$，`languages[i]` 内值互不相同
- $1 \le friendships.length \le 500$，$1 \le u_i < v_i \le m$，好友对互不相同

## 2. 示例

**示例 1**

```text
输入：n = 2, languages = [[1],[2],[1,2]], friendships = [[1,2],[1,3],[2,3]]
输出：1
解释：教用户 1 学语言 2（或教用户 2 学语言 1）即可。
```

**示例 2**

```text
输入：n = 3, languages = [[2],[1,3],[1,2],[3]], friendships = [[1,4],[1,2],[3,4],[2,3]]
输出：2
解释：教用户 1、3 学语言 3，共 2 人。
```

## 3. 解题思路

### 3.1 暴力思路

枚举选哪门语言 $l$，再枚举要教用户的子集 $S$，检查所有好友对在「原语言 ∪ 新学 $l$」下能否沟通。子集枚举 $O(2^m)$，配合 $n$ 种语言是 $O(n \cdot 2^m \cdot |F|)$，只能做对拍。真正的突破口是：**选定了语言，要教谁是被完全逼出来的**。

### 3.2 核心观察：坏好友对与 involved 集合

![筛选坏好友对：无共同语言的好友对端点才需要被教](images/bw44_q2_bad_edges.svg)

先把好友对分成两类：**好对**（已有共同语言）与**坏对**（没有共同语言）。好对无论怎么教都能沟通，可以直接忽略。对坏对 $(u, v)$ 而言，选定语言 $l$ 后，必须让 $u, v$ **都会** $l$——不会的那个**非教不可**。于是：

- 把所有坏对的端点并成集合 `involved`；
- 对语言 $l$，**必须教的人**恰好是 `involved` 中原本不会 $l$ 的人，人数为

$$\text{cost}(l) = \bigl|\{\, i \in \text{involved} : l \notin \text{lang}[i] \,\}\bigr|.$$

**没有任何选择余地**——多教浪费、少教不合法。

### 3.3 算法流程：枚举语言取最小

![枚举语言并统计代价的流程](images/bw44_q2_teach_language.svg)

```text
1. 用集合/布尔表存每个用户的语言，判断好友对是否有交集 → 标记 involved
2. for l in 1..n：
       cost(l) = involved 中不会 l 的人数
3. 答案 = min_l cost(l)
```

### 3.4 示例演算

![示例 2 的完整演算：三门语言的代价都是 2](images/bw44_q2_walkthrough.svg)

以示例 2 为例：四个好友对中 $(1,4), (1,2), (3,4)$ 无共同语言（坏对），$(2,3)$ 共享语言 1（好对）。`involved = {1,2,3,4}`。$\text{cost}(1) = 2$（用户 1、4 缺）、$\text{cost}(2) = 2$（用户 2、4 缺）、$\text{cost}(3) = 2$（用户 1、3 缺），答案 $2$ ✓。

## 4. 算法细节

1. **判断「有无共同语言」**：$n \le 500$、每用户语言 $\le n$，用 $m \times (n+1)$ 布尔表 `know[i][l]` 最简单；Python 直接用 `set` 交 `lang[u] & lang[v]` 是否非空。逐语言扫 $O(n)$ 即可，也可对两用户的语言列表做双指针。
2. **involved 用布尔数组/集合**，去重后统计，避免同一用户在多个坏对里被重复计数。
3. **复杂度**：判坏对 $O(|F| \cdot n)$，统计代价 $O(n \cdot m)$，合计 $O((m + |F|) \cdot n) \le 500 \times 1000$，非常宽裕。
4. **答案上界**：把 `involved` 全部教会任何一门语言都可行，所以 `best` 初值取 $m$（或第一个语言代价）即可，无需 $\infty$。
5. **好友关系无传递性**：只要求每一对好友能沟通，不要求整个连通块同语言——这正是坏对可以「各自为政」的原因。

## 5. 正确性证明

**引理 1（必要条件）**：选定语言 $l$ 的任一可行方案 $S$（教 $S$ 中的人），必包含 $B_l = \{i \in \text{involved} : l \notin \text{lang}[i]\}$。

**证明**：坏对 $(u,v)$ 的两端原本无共同语言，教 $l$ 后要能沟通，唯一可能是双方都会 $l$：会 $l$ 的条件是「原本会」或「被教」。$u$ 原本不会 $l$（$B_l$ 的定义涵盖坏对端点），若 $u \notin S$ 则教完后仍只会原语言集合，与 $v$ 无共同语言的局面没有任何改变（$v$ 至多多会 $l$，但 $u$ 不会 $l$），矛盾。故 $B_l \subseteq S$。∎

**引理 2（充分条件）**：$S = B_l$ 本身可行。

**证明**：任取好友对 $(u,v)$：若原本有共同语言，仍然有 ✓。若原本没有（坏对），则 $u, v \in \text{involved}$；若两端原本都会 $l$，则沟通 ✓；否则缺 $l$ 的端点在 $B_l$ 中、教后也会 $l$，两端都会 $l$ ✓。∎

**定理**：最少教学人数 $= \min_{1 \le l \le n} |B_l|$。

**证明**：任何可行方案是某语言 $l$ 上的集合 $S \supseteq B_l$（引理 1），故 $|S| \ge |B_l| \ge \min_l |B_l|$；而 $\min_l |B_l|$ 恰好被某个 $B_{l^*}$ 达成且可行（引理 2）。∎

> 💡 贪心体现在「无关变量直接消去」：好对被剔除、非 involved 用户被剔除，剩下的唯一自由度是「选哪门语言」，枚举即可。

## 6. 复杂度分析

- **时间**：$O((m + |F|) \cdot n)$——判坏对 $|F| \cdot n$ 次布尔与、统计 $n \cdot m$ 次计数。最坏约 $5 \times 10^5$。
- **空间**：$O(m \cdot n)$——布尔语言表（Python 用集合为 $O(\sum |languages[i]|)$）；`involved` 为 $O(m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumTeachings(int n, vector<vector<int>>& languages, vector<vector<int>>& friendships) {
        int m = (int)languages.size();
        vector<vector<char>> know(m, vector<char>(n + 1, 0));  // know[i][l]：用户 i 是否会语言 l
        for (int i = 0; i < m; ++i)
            for (int l : languages[i]) know[i][l] = 1;
        vector<char> involved(m, 0);                          // 出现在“无共同语言好友对”中的用户
        for (auto& f : friendships) {
            int u = f[0] - 1, v = f[1] - 1;
            bool share = false;
            for (int l = 1; l <= n; ++l)
                if (know[u][l] && know[v][l]) { share = true; break; }
            if (!share) involved[u] = involved[v] = 1;
        }
        int best = m;                       // 上界：把相关用户全教一遍
        for (int l = 1; l <= n; ++l) {      // 枚举选择教的语言 l
            int cost = 0;
            for (int i = 0; i < m; ++i)
                if (involved[i] && !know[i][l]) ++cost;
            best = min(best, cost);
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def minimumTeachings(self, n: int, languages: list[list[int]],
                         friendships: list[list[int]]) -> int:
        lang = [set(l) for l in languages]
        involved = set()              # 出现在“无共同语言好友对”中的用户（0 起下标）
        for u, v in friendships:
            if not (lang[u - 1] & lang[v - 1]):
                involved.add(u - 1)
                involved.add(v - 1)
        best = len(languages)
        for l in range(1, n + 1):     # 枚举要教的语言
            cost = sum(1 for i in involved if l not in lang[i])
            best = min(best, cost)
        return best
```

> 💡 两份代码均通过官方示例（`1`、`2`），并与「枚举语言 × 枚举教学子集」的暴力在 2000 组随机数据上比对一致；另通过 $n = m = 500$ 的规模测试。

## 8. 边界情况与易错点

1. **好友对全部能沟通**：`involved` 为空，代价恒 0，返回 0——循环照常工作，无需特判。
2. **下标偏移**：用户编号从 1 开始、`languages` 下标从 0 开始，涉及 `-1` 的地方别错位。
3. **同一用户多个坏对**：`involved` 必须去重，否则同一人会被重复计数。
4. **别把「好对」也纳入教学需求**：它们已有共同语言，教了纯属浪费。
5. **只能选一门语言**：不要误以为可以给不同坏对教不同语言。
6. **答案可能为 0**：`best` 初值取 $m$ 是安全的（任何代价 $\le m$），但别初始化为不可能的负值。
