# LeetCode 删除字符串中的所有相邻重复项 II 题解

## 1. 题目概述

- **标题 / 题号**：删除字符串中的所有相邻重复项 II（#1209，medium）
- **链接**：https://leetcode.cn/problems/remove-all-adjacent-duplicates-in-string-ii/
- **来源**：LeetCode 第 156 场周赛 Q3
- **难度**：中等
- **标签**：栈，字符串

**题意**：给定字符串 `s` 和整数 `k`，一次「k 倍重复项删除」可以选走 `s` 中 **k 个相邻且相同**的字母，并让被删段左右两侧拼接起来。对 `s` 反复执行这种删除，直到任何位置都不再有 k 个相邻相同字母为止，返回最终字符串（题目保证答案唯一）。

**约束**：

- $1 \le \lvert s \rvert \le 10^5$
- $2 \le k \le 10^4$
- `s` 只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "abcd", k = 2
输出："abcd"
解释：没有任何两个相邻字符相等，无从删除。
```

**示例 2**

```text
输入：s = "deeedbbcccbdaa", k = 3
输出："aa"
解释：先删除 "eee" 和 "ccc"，得到 "ddbbbdaa"；
      再删除 "bbb"，得到 "dddaa"；
      最后删除 "ddd"，得到 "aa"。
```

**示例 3**

```text
输入：s = "pbbcggttciiippooaais", k = 2
输出："ps"
解释：反复成对删除 "bb"、"gg"、"tt"、"cc"，串变为 "piiippooaais"；
      再删 "ii" 得 "pippooaais"，接着删 "pp"、"oo"、"aa"，得到 "piis"；
      最后删 "ii"，只剩 "ps"。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「模拟」：每一轮从左到右扫描，找到任意一段长度 $\ge k$ 的连续相同字符，删掉其中 k 个，把左右拼起来，然后**重新从头扫描**——因为拼接处可能诞生新的可删段。

- 每轮只删 k 个字符，最多 $n/k$ 轮；每轮扫描 $O(n)$、字符串拼接 $O(n)$，总复杂度 $O(n^2/k)$。
- $n = 10^5$、$k = 2$ 时约 $5 \times 10^9$ 次字符操作，必然超时。
- 更麻烦的是「重新扫描」这件事本身：删除发生后，能做判断的位置只有**拼接处**，其余位置的信息完全没变。整轮重扫等于把已知结论重新算一遍。

> 💡 关键问题是：**删除之后只需要回头看一个地方**。把这个「回头看」用数据结构固化下来，就是栈。

### 3.2 核心观察：把连续相同字符合并成「计数块」

![计数栈：把连续相同字符合并成 (字符, 计数) 块](images/wc156_q3_stack_count_model.svg)

如果栈里只存单个字符（像 [1047. 删除字符串中的所有相邻重复项](https://leetcode.cn/problems/remove-all-adjacent-duplicates-in-string/) 那样），删掉 k 个之后还得重新数「新栈顶上又连着几个相同字符」。既然要反复数长度，就**把长度直接存进栈**：

1. **栈元素是一个块** `(字符 c, 连续出现次数 cnt)`，栈中相邻两块的字符一定不同。
2. 读入字符 `c` 时，只有**栈顶**可能和它相同——因为栈顶就是「已处理前缀」的最后一个字符。
3. 相同就让栈顶计数 `+1`；一旦计数**恰好等于 k**，这 k 个字符就是一段合法的删除对象，整块 `pop`。
4. 不同（或栈空）就压入新块 `(c, 1)`。

**不变式**：处理完前缀 `s[0..i]` 后，栈对应的字符串可以由该前缀经若干次合法删除得到，且其中不存在 k 个连续相同字符；同时栈内相邻块的字符互不相同。

因为弹出后露出的下方块字符必定 $\ne$ 被弹出的字符，**栈内部不会再产生新的 k 连**，唯一可能的新配对只发生在「新栈顶」和「尚未读入的下一个字符」之间——而这正好由下一次循环自然处理。于是完全不需要回溯。

### 3.3 算法流程

![算法流程：一个字符一次 O(1) 的压、累加、弹](images/wc156_q3_algorithm_flow.svg)

```text
栈 st = []                       # 元素为 (c, cnt)
for c in s:
    if st 非空 and st.top.c == c:
        st.top.cnt += 1
        if st.top.cnt == k:      # 凑够 k 个，整块删除
            st.pop()
    else:
        st.push((c, 1))          # 开一个新的计数块
答案 = 把 st 从栈底到栈顶按「字符 × 计数」展开
```

三处容易写错的地方：

- **`cnt` 初值是 1**：压栈时这个字符已经算一个了，写 0 会永远差一个。
- **到 k 立刻弹**：如果等下一次读入再判断，栈里就可能留着 `cnt = k` 的块，不变式被破坏。
- **弹出后即结束本轮**：不要再去检查栈顶是否也需要删，理由见 3.2 的最后一段。

### 3.4 示例演算

![示例演算：s = "deeedbbcccbdaa"，k = 3](images/wc156_q3_walkthrough.svg)

以 `s = "deeedbbcccbdaa"`、`k = 3` 为例，栈的变化（每行是该步处理完之后的状态）：

| 步 | 读入 | 栈（底 → 顶） | 说明 |
|----|------|----------------|------|
| 1 | `d` | `[(d,1)]` | 新块入栈 |
| 2 | `e,e,e` | `[(d,1)]` | `e` 计数 1→2→3，凑够 k 整块弹出 |
| 3 | `d` | `[(d,2)]` | 与栈顶 `d` 合并 |
| 4 | `b,b` | `[(d,2),(b,2)]` | `b` 累加到 2，未到 k |
| 5 | `c,c,c` | `[(d,2),(b,2)]` | `c` 计数到 3，弹出 |
| 6 | `b` | `[(d,2)]` | `b` 计数 2→3，弹出 |
| 7 | `d` | `[]` | `d` 计数 2→3，弹出，栈空 |
| 8 | `a,a` | `[(a,2)]` | 结束，展开得 `"aa"` |

注意第 7 步：这里的 `ddd` 由「原串第 0 个 `d`」「原串第 4 个 `d`」，以及「删掉 `bbb` 之后才与它们相邻的原串第 11 个 `d`」拼成，官方解释里它被放到最后才删。**删除顺序不同，结果相同**（题目保证唯一），栈只是选了「最早能删就删」这一种顺序。

示例 3 里也有同一个提醒：`"piiipp"` 段删掉 `"ii"` 之后还**剩下一个 `i`**（不是把三个 `i` 全清空），这个 `i` 后来又与末尾的 `i` 合成一对被删掉。可见「连续段」的边界会随删除不断变化。

## 4. 算法细节

1. **存储结构**：C++ 用 `vector<pair<char,int>>`（或两个平行数组，省掉 pair 的间接寻址）；Python 用 `list` 存 `[字符, 计数]`。Python 里**必须用 list 而不是 tuple**，否则 `st[-1][1] += 1` 会抛 `TypeError`。
2. **只比较栈顶**：判定条件是 `if st and st.back().first == c`，不要写成「与答案串末尾比较」——答案串是不存在的，栈就是答案。
3. **判断用 `== k` 而不是 `>= k`**：由于到 k 立刻弹出，任何块的计数都不会超过 k，所以 `==` 成立；写成 `>=` 虽然结果相同，但会掩盖「忘了弹」这类 bug，`==` 相当于顺手做了一个不变式自检。
4. **弹出后先判空再访问栈顶**：C++ 的 `st.pop_back()` 之后 `st.back()` 是未定义行为；Python 的 `st[-1]` 在空栈上抛 `IndexError`。若后续代码要再看栈顶，务必加 `if not st.empty()`。
5. **拼接结果时预留容量**：结果长度不超过 $n$，C++ 用 `res.reserve(s.size())`，展开用 `res.append(cnt, ch)`；Python 用 `''.join(ch * cnt for ch, cnt in st)`。方向必须**从栈底到栈顶**，也就是列表正序，别用 `reversed`。
6. **不要构造中间串**：暴力法每次删除都产生一个新串；计数栈全程只维护 $O(n)$ 个块，中间不产生任何字符串。
7. **与 1047 的关系**：$k = 2$ 时本题退化为「异或式消除」，此时每个块的计数非 0 即 1，单字符栈就够用；计数栈是它的直接推广。
8. **计数用 `int` 足够**：$k \le 10^4$，$n \le 10^5$，不会溢出；但如果题目把 $n$ 放大到 $10^{18}$ 级别（计数型输入），则需要 64 位整数。

## 5. 正确性证明

**引理 1（不变式）**：处理完前缀 `s[0..i]` 后，栈按「字符 × 计数」展开得到的字符串 $R_i$ 满足：(a) $R_i$ 可由 `s[0..i]` 经若干次合法的 k 倍删除得到；(b) $R_i$ 中不存在 k 个连续相同字符；(c) 栈中相邻两块的字符不同。

**证明**：对 $i$ 归纳。

- 基线：$i = -1$ 时栈为空，$R_{-1} = \varepsilon$，(a)(b)(c) 显然成立。
- 归纳步：设读入 `c = s[i]` 前不变式成立。若栈空或栈顶字符 $\ne c$，则压入新块 `(c,1)`：$R_{i} = R_{i-1} + c$，它可由 `s[0..i]` 得到（把处理 `s[0..i-1]` 时的删除原样作用，末字符不动），故 (a) 成立；新块计数为 $1 < k$（因 $k \ge 2$），且相邻块字符不同，故 (b)(c) 成立。
- 若栈顶字符 $= c$，则栈顶计数 $+1$。若新计数 $< k$，则 $R_i = R_{i-1} + c$：把处理 `s[0..i-1]` 时用过的那些删除原样作用到 `s[0..i]`（末字符完全不动）即可得到 $R_i$，故 (a) 成立；新块计数 $< k$ 且其下方块的字符 $\ne c$，故 (b)(c) 成立。若新计数 $= k$，则栈顶块正好是 $R_{i-1}$ 末尾的 k 个相同字符，删掉它们是一次合法操作，故 (a) 对 $R_i = R_{i-1}$ 去掉末尾 k 个字符成立；由 (c)，露出块的字符 $\ne c$，故 $R_i$ 中不会出现新的 k 连，(b) 成立；其余相邻块未变，(c) 成立。∎

**引理 2（终止）**：循环处理完所有字符后，算法输出不含 k 个连续相同字符。

**证明**：由引理 1(b)，最终栈展开的字符串不存在 k 连，即已是不可再删的形态，不会陷入无限删除。∎

**引理 3（结果唯一）**：不同删除顺序得到的最终串相同（题面已保证答案唯一）。

**证明**：这是题目给出的前提，此处直接引用：无论按何种顺序删除，最终都会停在同一个不可再删的串上。∎

**定理**：算法返回的字符串就是题目要求的最终字符串。

**证明**：由引理 1(a)、1(b) 与 2，算法的输出是一个「由 `s` 经合法删除到达、且不再含 k 连」的字符串；由引理 3，这样的字符串唯一。故算法输出即所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符恰被读入一次，做一次比较和一次 $O(1)$ 的压栈 / 累加；每次弹出也随之销毁一个块，而块的总数不超过入栈次数，故所有 `pop` 的总代价是 $O(n)$。最后的展开是每个字符输出一次，也是 $O(n)$。总计 $\Theta(n)$。
- **空间**：$O(n)$。栈最多包含 $n$ 个块（每个块 2 个字段）；返回的字符串长度不超过 $n$。没有递归、没有二维表，常数很小。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string removeDuplicates(string s, int k) {
        vector<pair<char, int>> st;      // (字符, 连续出现次数)
        st.reserve(s.size());
        for (char c : s) {
            if (!st.empty() && st.back().first == c) {
                if (++st.back().second == k) {
                    st.pop_back();       // 凑够 k 个，整块删除
                }
            } else {
                st.push_back({c, 1});    // 新开一个计数块，计数从 1 开始
            }
        }
        string res;
        res.reserve(s.size());
        for (auto &p : st) res.append(p.second, p.first);  // 栈底 → 栈顶
        return res;
    }
};
```

### Python

```python
class Solution:
    def removeDuplicates(self, s: str, k: int) -> str:
        st = []                     # 每个元素是 [字符, 连续出现次数]，必须是可变类型
        for c in s:
            if st and st[-1][0] == c:
                st[-1][1] += 1
                if st[-1][1] == k:
                    st.pop()        # 凑够 k 个，整块删除
            else:
                st.append([c, 1])   # 新开一个计数块，计数从 1 开始
        return "".join(c * cnt for c, cnt in st)  # 栈底 → 栈顶
```

## 8. 边界情况与易错点

1. **`k` 大于 `n` 或字符串本身无可删段**（如 `"abcd"`, `k = 2`）：循环里永远不会触发 `cnt == k`，直接原样展开返回 `s`，无需特判。
2. **连续相同字符超过 k 个**（如 `"aaaaa"`, `k = 3`）：只能删掉 k 个，剩下的 `"aa"` 继续留在栈里，答案是 `"aa"`。绝不能理解成「整段相同字符全删」，也不能把计数直接清零。
3. **删除后跨段拼接**：`"deeedbbcccbdaa"` 里的 `ddd` 是由三个不同来源的 `d` 拼成的。必须让「新栈顶」与「下一个读入字符」重新比较，否则会漏删。
4. **计数初值**：压栈写 `(c, 1)` 而不是 `(c, 0)`；累加放在比较之后，二者顺序颠倒会导致首字符被重复计数。
5. **空栈访问**：`"aaab"`, `k = 3` 时读到第 3 个 `a` 栈就被弹空，紧接着还要读 `b`，所以判定条件里的 `st` 非空检查不可省（C++ 的 `st.back()` 在空 vector 上是 UB）。
6. **Python 的可变性问题**：`st.append((c, 1))` 之后 `st[-1][1] += 1` 会报 `TypeError: 'tuple' object does not support item assignment`，必须用 list 或分两个栈。
7. **输出顺序**：栈底是最早的字符，栈顶是最近的字符，所以正序展开；写成倒序会得到反转的答案（若输入本身是回文串，倒序展开还会碰巧通过，从而掩盖 bug）。
8. **`== k` 与 `>= k`**：本题逐步弹出保证了计数不会越过 k，但若为了「小优化」把累加和弹出放在不同分支里，就可能出现 `k+1` 的块，此时 `==` 会漏删——保持「加到 k 立刻弹」的单一路径最安全。

**延伸思考**：

1. 如果每个位置有各自的阈值 $k_i$（一次删除的长度要恰好等于该段**起点处**的阈值），计数栈还够用吗？提示：合并两个块时阈值由谁决定会变得模糊，需要考虑「块内再做分段」或用并查集维护段长。
2. 如果题目要求输出「任意一个合法的删除序列」而不是最终串，栈的每次 `pop` 就天然给出了一步删除（附带它的起止位置），总步数不超过 $n/k$。但如果要求**最少/最多**步数，答案就不再唯一，需要额外讨论删除顺序。
3. 如果要求「删除次数不超过 $m$ 次时的最短结果」，问题会从 $O(n)$ 变成需要决策的 DP 或贪心加证明——此时「顺序无关」这一性质不再自动成立。
4. 反过来看：本题最有价值的结论不是栈怎么写，而是**「局部可判定 + 唯一归约」把 $O(n^2)$ 的反复扫描压成了 $O(n)$ 的单向扫描**，这个套路在字符串消消乐、括号匹配、表达式化简里反复出现。
