# LeetCode 尽可能使字符串相等 题解

## 1. 题目概述

- **标题 / 题号**：尽可能使字符串相等（#1208，medium）
- **链接**：https://leetcode.cn/problems/get-equal-substrings-within-budget/
- **来源**：LeetCode 第 156 场周赛 Q2
- **难度**：中等
- **标签**：字符串、二分查找、前缀和、滑动窗口

**题意**：给定两个等长字符串 `s`、`t` 和一个预算 `maxCost`。把 `s[i]` 改成 `t[i]` 的代价是 $|s[i]-t[i]|$，即两个字符 ASCII 码之差的绝对值（代价可能为 0）。现在从 `s` 中挑一个**连续子串**，把它整体改成 `t` 中**同一段下标**上的子串，要求总代价不超过 `maxCost`，返回能这样改的**最长**子串长度；如果不存在这样的子串（连单个字符的代价都超预算），返回 0。

**约束**：

- $1 \le |s| \le 10^5$，且 $|t| = |s|$
- $0 \le \text{maxCost} \le 10^6$
- `s`、`t` 只含小写英文字母，因此单字符代价 $0 \le \text{cost}[i] \le 25$，整个字符串的总代价不超过 $2.5 \times 10^6$

> 💡 注意子串是「同一下标区间」上的 `s` 子串与 `t` 子串配对，不能错位匹配；题目中的「转化不完全」指允许只转化一段，而不是允许跳过中间某个字符。

## 2. 示例

**示例 1**

```text
输入：s = "abcd", t = "bcdf", maxCost = 3
输出：3
解释：s 的子串 "abc" 可以变成 t 中对应的 "bcd"，
      代价 |a-b| + |b-c| + |c-d| = 1 + 1 + 1 = 3，恰好用满预算。
```

**示例 2**

```text
输入：s = "abcd", t = "cdef", maxCost = 3
输出：1
解释：每一位的代价都是 2（a→c、b→d、c→e、d→f），
      任意长度为 2 的子串代价都是 4 > 3，所以最长只能取 1 个字符。
```

**示例 3**

```text
输入：s = "abcd", t = "acde", maxCost = 0
输出：1
解释：只有第 0 位 a→a 的代价为 0，可以「免费」保留，
      因此长度为 1；任何包含第 1 位（b→c，代价 1）的子串都超预算。
```

## 3. 解题思路

### 3.1 暴力思路

先把代价数组算出来：$\text{cost}[i] = |s[i]-t[i]|$。于是问题变成「在 `cost` 中找一段**和不超过 maxCost 的最长连续区间**」。

最直白的做法是枚举左右端点 $l \le r$，对每个区间求和。用前缀和把区间和降到 $O(1)$ 后仍需枚举 $O(n^2)$ 个区间，$n = 10^5$ 时约有 $5 \times 10^9$ 个区间，必然超时。瓶颈在于：我们重复计算了大量互相包含的区间。

### 3.2 核心观察：代价非负 ⇒ 最长可行窗口可以双指针滑窗

![把字符差异摊平成代价数组](images/wc156_q2_cost_array.svg)

把「能不能转」翻译成区间和条件：

$$\text{子串 } s[l..r] \text{ 可转} \iff \sum_{i=l}^{r} \text{cost}[i] \le \text{maxCost}$$

关键性质是**所有代价都非负**。由此得到两条单调性：

1. 固定左端 $l$，让右端 $r$ 右移，区间和**只增不减**；
2. 固定右端 $r$，让左端 $l$ 右移，区间和**只减不增**。

第二条正是双指针的依据：对某个右端 $r$，如果当前窗口 $[left, r]$ 超预算，那么所有 $l \le left$ 的窗口 $[l, r]$ 只会更大、同样超预算，唯一出路是把左端继续右移。反过来说，一旦窗口合法，就不必再回退左端——因为对更大的 $r'$ 来说，原先被淘汰的左端只会让窗口更贵。

于是「最长合法窗口」可以只用两个只向右走的指针维护，每个下标最多进窗一次、出窗一次。

> 💡 同一单调性也能推出「二分长度 + 前缀和」的做法：长度 $L$ 可行则 $L-1$ 必然可行，二分 $L$ 后用前缀和检查是否存在长度为 $L$ 的合法窗口，复杂度 $O(n\log n)$。本题标签里的「二分查找、前缀和」指的就是这条路；而滑窗可以再省掉一个 $\log$。

### 3.3 算法流程 / 状态转移

![双指针滑窗流程](images/wc156_q2_two_pointer_flow.svg)

维护窗口 $[left, right]$ 与窗口内代价和 `sum`：

1. 初始化 `left = 0`、`sum = 0`、`ans = 0`；
2. 让 `right` 从 0 遍历到 $n-1$，每步先把 $\text{cost}[right]$ 加进 `sum`（右端入窗）；
3. **while** `sum > maxCost`：把 $\text{cost}[left]$ 从 `sum` 中减去，并 `left++`（左端出窗），直到窗口重新合法；
4. 此时窗口 $[left, right]$ 合法，用 `right - left + 1` 更新 `ans`。

第 3 步必须是 `while` 而不是 `if`：一次入窗可能让窗口超出很多，需要连续弹出多个左端元素才能回到预算内。弹出结束后 `left` 恰好是「使窗口合法的最小左端」，这一点会在正确性证明中用到。

### 3.4 示例演算

![示例 1 的逐步走查](images/wc156_q2_walkthrough.svg)

以示例 1 为例，`cost = [1, 1, 1, 2]`、`maxCost = 3`：

| 步骤 | right | 窗口 | 新增代价 | sum | 动作 | ans |
|------|-------|------|----------|-----|------|-----|
| 1 | 0 | [a] | 1 | 1 | 1 ≤ 3，不收缩 | 1 |
| 2 | 1 | [a,b] | 1 | 2 | 2 ≤ 3，不收缩 | 2 |
| 3 | 2 | [a,b,c] | 1 | 3 | 3 ≤ 3，预算刚好用满 | 3 |
| 4 | 3 | [c,d] | 2 | 3 | 5 > 3，弹出 a、b 后回到 3 | 3 |

第 4 步中，加入 $\text{cost}[3]=2$ 后 `sum = 5`，连续弹出 `cost[0]=1`（`sum=4`）与 `cost[1]=1`（`sum=3`）才重新合法，窗口退化为 `[c,d]`，长度 2，不改变答案。

再看示例 2：`cost = [2,2,2,2]`、`maxCost = 3`。第一位单独入窗时 `sum = 2` 合法，长度 1；从第二位起，每次加入 2 都让 `sum` 变成 4 > 3，必须弹出一个 2，窗口长度始终是 1，所以 `ans` 恒为 1，与官方答案一致。

## 4. 算法细节

1. **代价只算一次**：先构造 `cost` 数组，避免在收缩时反复用 `abs(s[left]-t[left])` 重算；虽然重算也是 $O(1)$，但预计算让「窗口和」的加减完全对称，出错概率更低。
2. **先加后缩**：顺序固定为「加入 `cost[right]` → 收缩到合法 → 更新 `ans`」。若先更新 `ans` 再收缩，会把非法窗口的长度也统计进去。
3. **收缩用 `while`**：单次入窗可能超预算不止一点（例如 `cost = [0,5,6]`、`maxCost = 5`，到第三个元素时 `sum = 11`，弹掉 0 之后仍是 11），必须持续弹出。
4. **合法窗口的定义是 $\text{sum} \le \text{maxCost}$**：题目是「总开销应当小于等于预算」，等号成立也算成功，示例 1 的答案恰好卡在等号上。
5. **`ans` 每轮都要更新**：不能只在「发生收缩」时更新，否则当 `maxCost` 足够大、窗口一路扩张时答案会漏记。
6. **空窗口也要能正确表达**：若单个 $\text{cost}[right] > maxCost$，收缩会把 `left` 推到 `right + 1`，此时 `right - left + 1 = 0`，`ans` 取 `max` 后保持不变，不会出现负数长度。
7. **整数范围**：单字符代价最大 25，窗口和最大 $25 \times 10^5 = 2.5 \times 10^6$，`int` 足够；注意不要把差值存进 `char`（会截断符号），C++ 中 `s[i] - t[i]` 的表达式类型已经是 `int`。
8. **二分 + 前缀和的替代写法**：前缀和 $\text{pre}[i+1] = \text{pre}[i] + \text{cost}[i]$，判定长度 $L$ 时检查所有 $l \in [0, n-L]$ 是否满足 $\text{pre}[l+L] - \text{pre}[l] \le \text{maxCost}$，单次 $O(n)$、共 $O(n\log n)$；二分上界取 $n$（整个字符串都可能可转），不是 $n-1$。

## 5. 正确性证明

**引理 1（子窗口单调性）**：若区间 $[l,r]$ 的代价和不超过 `maxCost`，则它的任意子区间 $[l',r'] \subseteq [l,r]$ 的代价和也不超过 `maxCost`。

**证明**：由代价非负，$\sum_{i=l'}^{r'} \text{cost}[i] \le \sum_{i=l}^{r} \text{cost}[i] \le \text{maxCost}$。∎

**引理 2（收缩后的 `left` 是最小合法左端）**：对每个 `right`，第 3 步的 `while` 结束后，`left` 是满足「区间 $[l, right]$ 的代价和不超过 `maxCost`」的最小 $l$（若不存在这样的 $l$，则 `left = right + 1`）。

**证明**：代价非负，故区间和关于左端 $l$ 单调不增。分两种情况。

- 若 `left` 从未被移动（`left = 0`），则窗口和的初值就满足条件，$l=0$ 已是最小下标。
- 否则 `left` 停在 $L > 0$：它是因为 $\sum_{i=L-1}^{right} \text{cost}[i] > \text{maxCost}$ 而被右移的，说明 $L-1$ 不合法；由单调性，所有 $l \le L-1$ 都不合法，而 $L$ 在循环退出时合法，故 $L$ 是最小合法左端。

空窗口（`left = right + 1`）的情形对应 $\text{cost}[right] > \text{maxCost}$：此时唯一可能的 $l = right$ 也不合法，故不存在合法左端，符合描述。∎

**定理**：算法返回的 `ans` 等于「代价和不超过 `maxCost` 的最长连续子区间」的长度。

**证明**：对每个 `right`，记 $L_{right}$ 为引理 2 中的最小合法左端。算法在该轮把 `right - L_{right} + 1` 与 `ans` 取最大值，这正是一切以 `right` 结尾的合法区间的最大长度（由引理 2，任何更小的左端都非法，更大的左端只会更短）。因此 `ans` 是所有 `right` 上的最大合法长度，即为全局最优值。

另一方面，每轮记录的区间 `[left, right]` 在记录时都满足预算（收缩已结束），故记录值不会超过真实最优值。两边夹逼，`ans` 恰为答案。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`right` 从 0 走到 $n-1$，每个元素恰好入窗一次；内层 `while` 中 `left` 只增不减，累计最多执行 $n$ 次，故总操作数是 $O(n)$（均摊 $O(1)$）。
- **空间**：$O(n)$，用于存放长度为 $n$ 的 `cost` 数组；其余只有常数个整型变量。若把 `cost` 改成在循环内用 `abs(s[i]-t[i])` 现算（收缩时再算一次 `abs(s[left]-t[left])`），可把额外空间降到 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <cstdlib>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int equalSubstring(string s, string t, int maxCost) {
        int n = s.size();
        vector<int> cost(n);
        for (int i = 0; i < n; ++i) cost[i] = abs(s[i] - t[i]);

        int left = 0, window_sum = 0, ans = 0;
        for (int right = 0; right < n; ++right) {
            window_sum += cost[right];              // 右端入窗
            while (window_sum > maxCost) {          // 超预算就弹左端
                window_sum -= cost[left];
                ++left;
            }
            ans = max(ans, right - left + 1);       // 此时窗口合法
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def equalSubstring(self, s: str, t: str, maxCost: int) -> int:
        n = len(s)
        cost = [abs(ord(a) - ord(b)) for a, b in zip(s, t)]

        left = 0
        window_sum = 0
        ans = 0
        for right in range(n):
            window_sum += cost[right]               # 右端入窗
            while window_sum > maxCost:             # 超预算就弹左端
                window_sum -= cost[left]
                left += 1
            ans = max(ans, right - left + 1)        # 此时窗口合法
        return ans
```

## 8. 边界情况与易错点

1. **`maxCost = 0` 不等于答案 0**：代价为 0 的位置可以免费保留，例如示例 3 返回 1。只有当所有位置的代价都为正、且连一个字符都付不起时才返回 0（如 `s = "abcd"`、`t = "cdef"`、`maxCost = 1`）。
2. **预算判断是 `<=` 而不是 `<`**：示例 1 的 `sum = 3` 恰好等于 `maxCost`，写成 `<` 会得到 2；等号是合法的。
3. **收缩必须用 `while`**：单次入窗可能让窗口超预算不止一个元素（`cost = [0,5,6]`、`maxCost = 5` 时，弹掉代价 0 后 `sum` 仍是 11）。若为了少写循环而只弹一次，窗口会长期处于非法状态，继续用 `sum` 做判断就出错；确实存在「每步最多缩一次、窗口长度单调不减」的写法，但它只能用来求长度，不能再依赖窗口本身的性质，初学不建议。
4. **先加后缩的顺序不能反**：如果先收缩再入窗（`while window_sum + cost[right] > maxCost` 后才加），逻辑同样正确，但两种写法不能混用；更常见的错误是在加入之前就用 `right - left + 1` 更新 `ans`，会把非法长度算进去。
5. **空窗口的边界**：当 $\text{cost}[right] > maxCost$ 时 `left` 会被推到 `right + 1`，长度 0。此时不要再访问 `cost[left]` 或把长度写成 `right - left`（会得到 -1）。
6. **不要让 `ans` 只在收缩时更新**：当 `maxCost` 大于总代价时窗口一路扩张、从不收缩，答案应为 $n$；若只在 `while` 内更新就会漏掉。
7. **`n = 1`**：循环只会跑一轮，代价为 $|s[0]-t[0]|$，返回 1 或 0，无需特判，但要保证单元素窗口的处理路径与一般情况一致（入窗、收缩、更新 `ans`）。

**延伸思考**：

1. 若代价可以为**负**，双指针立刻失效——「左端右移和一定减小」不再成立，被淘汰的左端未来可能重新变好。此时需要前缀和 + 单调队列/树状数组求「最长区间和 ≤ K」，或固定左端后在**前缀和数组上**二分右端。
2. 若要求的是「恰好花掉 `maxCost`」，可行性关于长度不再单调，二分长度也不成立，需要「前缀和 + 哈希表查 `pre[r] - maxCost`」统计最长匹配。
3. 若把「一个子串」改成「至多 $k$ 段互不重叠的子串」，滑窗就不够了，需要 DP：$dp[i][j]$ 表示前 $i$ 个字符分成 $j$ 段的最大总长，转移时用滑窗预处理「以 $i$ 结尾的最长合法段」即可保持 $O(nk)$。
