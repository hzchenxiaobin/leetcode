# LeetCode 独一无二的出现次数 题解

## 1. 题目概述

- **标题 / 题号**：独一无二的出现次数（#1207，easy）
- **链接**：https://leetcode.cn/problems/unique-number-of-occurrences/
- **来源**：LeetCode 第 156 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定整数数组 `arr`，先按取值把元素分组，得到每个不同取值的**出现次数**；如果这些出现次数**两两不同**（没有任何两个取值出现一样多次），返回 `true`，否则返回 `false`。注意比较的对象是「频次」而不是「取值」：`[1,2]` 的两个取值不同，但频次都是 $1$，因此答案是 `false`。

**约束**：

- $1 \le \text{arr.length} \le 1000$
- $-1000 \le \text{arr}[i] \le 1000$
- 返回值为布尔值，$n$ 很小，值域也只有 $2001$ 个整数

> 💡 Q1 的定位是签到题。本题的朴素做法（对每个取值扫一遍数组数次数）在 $n \le 1000$ 时本来就能过，真正值得沉淀的是这一步**翻译**：把「每个数的出现次数独一无二」翻译成「频次集合的大小等于不同取值的个数」，于是一行代码就能判定。

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,2,1,1,3]
输出：true
解释：1 出现 3 次，2 出现 2 次，3 出现 1 次，
      频次为 {3, 2, 1}，两两不同。
```

**示例 2**

```text
输入：arr = [1,2]
输出：false
解释：1 出现 1 次，2 出现 1 次，两个频次都是 1，撞车。
```

**示例 3**

```text
输入：arr = [-3,0,1,-3,1,1,1,-3,10,0]
输出：true
解释：-3 出现 3 次，0 出现 2 次，1 出现 4 次，10 出现 1 次，
      频次为 {3, 2, 4, 1}，两两不同。
```

示例 2 是本题唯一容易漏判的方向：数组里的**取值**互不相同，但**频次**完全相同。只看「取值有没有重复」会得到相反的答案。

## 3. 解题思路

### 3.1 暴力思路

最直白的写法分两步，两步都是暴力的：

- **数频次**：对每个出现过的取值 $v$，再完整扫一遍数组统计 `arr[i] == v` 的个数，共 $O(n \cdot d)$，其中 $d$ 是不同取值的个数。
- **判重**：把 $d$ 个频次两两比较，$O(d^2)$。

总复杂度 $O(nd + d^2)$。在 $n \le 1000$ 下最多约 $2 \times 10^6$ 次基本操作，**其实能过**——这正是 Q1 的特点：瓶颈不在性能，而在「能不能一次写对」。暴力的两个问题值得记下来：

1. 两两比较判重是 $O(d^2)$，而它想回答的问题只是「有没有两个数相等」，一次去重（哈希集合）就够，$O(d)$。
2. 用 `arr.count(v)` 逐个取值去数，是把同一个数组反复扫了 $d$ 遍；一次遍历把所有取值的频次同时累计下来，才是 $O(n)$。

### 3.2 核心观察：频次「两两不同」等价于一次去重

![两列映射：先数频次，再看频次是否互不相同](images/wc156_q1_count_then_set.svg)

设 $d$ 为不同取值的个数，把它们按某种顺序排成 $v_1, \dots, v_d$，对应的频次记作

$$C = (c_1, c_2, \dots, c_d), \qquad c_i = \#\{j : \text{arr}[j] = v_i\}$$

$C$ 是一个**多重集**（允许重复），题目要求的正是 $c_1, \dots, c_d$ 两两不等。设 $S = \operatorname{set}(C)$ 是去掉重复后剩下的不同频次，则

$$c_i \ne c_j \ \ (i \ne j) \iff \lvert S \rvert = d$$

理由极其简单：去重只会删掉重复元素，长度变小 $\iff$ 原本存在两个相等的元素。于是「判重」这一步既不需要排序，也不需要两两比较，只需要把 $d$ 个频次丢进集合，看集合还剩几项。

这一步把问题拆成了两个完全独立、各自线性的子任务：**统计频次**（哈希表）与**频次去重**（哈希集合）。

### 3.3 算法流程

![流程图：边插入边判重，撞车即刻返回](images/wc156_q1_algorithm_flow.svg)

1. **统计频次**：新建哈希表 `cnt`，遍历 `arr`，执行 `cnt[x] += 1`。遍历结束后 `cnt` 的键恰好是全部不同取值，共 $d$ 项。
2. **建立频次集合**：新建空集合 `seen`。
3. **逐项插入并判重**：遍历 `cnt` 的每个值 `c`，尝试把 `c` 插入 `seen`；若插入失败（说明 `c` 已经在集合里），立即返回 `false`——已经找到两个频次相同的取值，结论已定。
4. **收尾**：$d$ 项全部插入成功，说明 $d$ 个频次落进了 $d$ 个不同的格子，两两不同，返回 `true`。

第 3、4 步也可以写成先收集再比较的形式：`len(set(cnt.values())) == len(cnt)`。两种写法等价，前者能提前退出，后者更短；Python 里推荐后者，C++ 里 `unordered_set::insert` 返回的 `pair.second` 天然适合前者。

另外一个可选的实现选择：因为值域只有 $[-1000, 1000]$，可以用长度 $2001$ 的数组代替哈希表，下标取 $x + 1000$。这能把常数压到最小，也避免了哈希表的动态分配。

### 3.4 示例演算

![三组官方示例走查](images/wc156_q1_walkthrough.svg)

以三组官方示例走一遍（$d$ 记作不同取值的个数）：

| 示例 | `arr` | 频次表 `cnt` | 频次去重 | $\lvert S \rvert$ 与 $d$ | 判定 |
|------|-------|--------------|----------|--------------------------|------|
| ① | `[1,2,2,1,1,3]` | $1\to3,\ 2\to2,\ 3\to1$ | $\{3,2,1\}$ | $3 = d = 3$ | **true** |
| ② | `[1,2]` | $1\to1,\ 2\to1$ | $\{1\}$ | $1 < d = 2$ | **false** |
| ③ | `[-3,0,1,-3,1,1,1,-3,10,0]` | $-3\to3,\ 0\to2,\ 1\to4,\ 10\to1$ | $\{3,2,4,1\}$ | $4 = d = 4$ | **true** |

第 ② 行就是判定条件「$\lvert S \rvert < d$ 即 false」的直接体现；第 ① ③ 行虽然数值正负、频次大小完全不同，判定的算式却是同一个 $\lvert S \rvert = d$。

## 4. 算法细节

1. **计数结构二选一**：哈希表 `unordered_map<int,int>` 或值域桶 `vector<int> cnt(2001)`。后者利用约束 $-1000 \le \text{arr}[i] \le 1000$，下标写成 `x + 1000`，落在 $[0, 2000]$ 内；越界一格就会写坏内存，偏移量要和值域上界严格对齐。
2. **判重结构同样二选一**：频次取值在 $[1, n]$，所以 `seen` 可以是一个 `vector<bool> seen(n + 1)`，比哈希集合更快、更省；但要注意单个频次最大就是 $n$（所有元素相同），下标写 `n + 1` 是为了容纳 `n`。
3. **比较的两个量不能弄混**：左边是 **频次去重后的大小**，右边是 **不同取值的个数** $d$。常见笔误是把右边写成 $n$（数组长度），那几乎恒为 false；写成 `len(set(arr))` 则恒等于 $d$，判定变成恒真。
4. **频次之和是 $n$**：$\sum_i c_i = n$ 恒成立。这个恒等式不参与判定，但可以在调试时断言一下，能立刻发现"少统计了某个取值"这类错误。
5. **提前退出**：一旦 `seen.insert(c)` 失败就可以直接返回 `false`，后面即使还有频次也不用再看——结论只可能更差，不可能翻盘。
6. **鸽巢式的结构性约束**：若答案是 `true`，则 $d$ 个频次是 $d$ 个互不相同的正整数，其和不超过 $n$，故 $\frac{d(d+1)}{2} \le n$，在 $n \le 1000$ 下得 $d \le 44$。也就是说，只有「不同取值个数不超过 $44$」的输入才可能返回 `true`。这解释了为什么本题任何 $O(d^2)$ 的做法都不会超时，也说明判重这一步不需要任何优化——只要正确。
7. **返回值是布尔值**：不要返回频次差、重复频次个数之类的中间量；`uniqueOccurrences` 只回答"是/否"。

## 5. 正确性证明

**引理 1（计数表精确）**：算法结束时，对每个取值 $v$，`cnt[v]` 等于 $\#\{i : \text{arr}[i] = v\}$；且 `cnt` 的键集恰好是 `arr` 中出现过的全部取值，共 $d$ 项。

**证明**：对数组下标 $j$ 归纳。初始 `cnt` 为空，所有计数为 $0$。处理第 $j$ 个元素时只执行 `cnt[arr[j]] += 1`，它把取值 `arr[j]` 的计数加一、其余取值不变；同时若 `arr[j]` 首次出现，它的键被创建。归纳到遍历结束，每个取值 $v$ 的计数恰为其出现次数，键集恰为出现过的取值集合。∎

**引理 2（去重判等）**：设 `cnt` 的频次序列为 $C = (c_1, \dots, c_d)$，$S = \operatorname{set}(C)$。则 $C$ 中元素两两不同 $\iff \lvert S \rvert = d$。

**证明**：

- ($\Rightarrow$) 若 $c_i$ 两两不同，去重过程中没有任何元素被删，故 $\lvert S \rvert = \lvert C \rvert = d$。
- ($\Leftarrow$) 考虑映射 $f : C \to S$，$f(c_i) = c_i$。$\lvert S \rvert = d = \lvert C \rvert$ 说明像的大小等于定义域的大小，故 $f$ 是单射，即对任意 $i \ne j$ 有 $c_i \ne c_j$。∎

**定理**：算法返回 `true` $\iff$ `arr` 中每个取值的出现次数独一无二。

**证明**：由引理 1，`cnt.values()` 恰是全部 $d$ 个不同取值的频次，不多不少。算法返回 `true` $\iff$ 这 $d$ 个频次全部成功插入 `seen` $\iff$ 没有两个频次相等 $\iff \lvert S \rvert = d$（引理 2）。而"没有两个频次相等"正是"每个取值的出现次数独一无二"的定义。∎

## 6. 复杂度分析

- **时间**：$O(n + d) = O(n)$。建频次表遍历 $n$ 个元素，每次哈希操作均摊 $O(1)$；判重遍历 $d$ 项，每项一次集合插入，均摊 $O(1)$。最坏情况下（提前退出不触发）总操作数为 $n + d \le 2n$。若用值域桶，则为 $O(n + V)$，$V = 2001$ 是常数。
- **空间**：$O(d) \le O(n)$，哈希表存 $d$ 个键值对、集合最多存 $d$ 个频次。若用桶数组，空间为 $O(V) = O(2001)$，与 $n$ 无关。
- **常数与实现**：本题 $n \le 1000$，任何一版实现都在毫秒级；上面的复杂度分析是为了说清"每一步为什么是线性的"，而不是为了压缩常数。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <unordered_set>
using namespace std;

class Solution {
public:
    bool uniqueOccurrences(vector<int>& arr) {
        unordered_map<int, int> cnt;               // ① 值 -> 出现次数
        cnt.reserve(arr.size() * 2 + 1);
        for (int x : arr) ++cnt[x];

        unordered_set<int> seen;                   // ② 频次集合，重复插入即失败
        seen.reserve(cnt.size() * 2 + 1);
        for (const auto& kv : cnt) {
            if (!seen.insert(kv.second).second) {
                return false;                      // 该频次已出现过，撞车
            }
        }
        return true;                               // d 个频次互不相同
    }
};
```

### Python

```python
from typing import List
from collections import Counter


class Solution:
    def uniqueOccurrences(self, arr: List[int]) -> bool:
        cnt = Counter(arr)                          # ① 值 -> 出现次数
        return len(set(cnt.values())) == len(cnt)   # ② 频次去重后仍是 d 项
```

> 💡 值域只有 $[-1000, 1000]$ 时，也可以把 `Counter` 换成 `cnt = [0] * 2001` 加 `cnt[x + 1000] += 1`，再用 `seen = [False] * (n + 1)` 做频次判重——原理完全相同，只是把哈希换成了数组下标。

## 8. 边界情况与易错点

1. **只有一个不同取值**：`arr = [5]`，频次集合为 $\{1\}$，大小为 $1 = d$，答案是 `true`。不要因为"看起来没什么可比的"就特判成 `false`。
2. **全部取值互不相同**：`arr = [1,2,3]`，$d = n = 3$，频次全是 $1$，集合大小为 $1 < 3$，答案是 `false`。这是**最常见的漏判方向**：取值不重复不等于频次不重复。
3. **负数不能直接当数组下标**：值域含 $-1000$，用桶数组必须 `x + 1000` 偏移；C++ 的 `vector` 用负数下标是未定义行为，不会报错、只会悄悄算错。用哈希表则完全没有这个问题。
4. **判定式的右边写错**：`len(set(cnt.values())) == n` 几乎恒为 `false`（只有 $n = 1$ 时才可能成立，而那时答案本来就该是 `true`），`len(set(arr)) == len(cnt)` 则恒为 `true`。正确写法只有"$\lvert S \rvert = d$"这一种。
5. **单个频次可能等于 $n$**：`arr` 全相同时频次为 $n = 1000$。若 `seen` 用 `vector<bool>(n)` 开数组，下标 $n$ 就越界了，必须开 `n + 1`。
6. **"看起来相等"的两种 false**：`[1,1,2,2]`（频次 $2,2$）与 `[1,2]`（频次 $1,1$）都返回 `false`，但前者频次大于 $1$、后者等于 $1$；判重逻辑对两者一视同仁，不要按频次大小分支。
7. **时间复杂度别写错**：用 `for v in set(arr): arr.count(v)` 的写法是 $O(n \cdot d)$，虽然 $n \le 1000$ 时能过，但题解里不能声称它是 $O(n)$。
8. **C++ 的两次查找**：先 `seen.count(c)` 再 `seen.insert(c)` 查了两次；用 `!seen.insert(c).second` 一次搞定，语义也更贴切——"插入失败即重复"。
