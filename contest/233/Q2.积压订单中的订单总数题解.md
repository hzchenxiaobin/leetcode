# LeetCode 积压订单中的订单总数 题解

## 1. 题目概述

- **标题 / 题号**：积压订单中的订单总数（#1801，medium）
- **链接**：https://leetcode.cn/problems/number-of-orders-in-the-backlog/
- **来源**：LeetCode 第 233 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟、堆（优先队列）

**题意**：按提交时间先后给出 `orders`，每个 `orders[i] = [price_i, amount_i, orderType_i]` 表示一批共 `amount_i` 笔价格相同、类型相同的独立订单（`0` 表买入 buy，`1` 表卖出 sell）。维护一个初始为空的**积压订单簿**：

- 新 buy 到达时，查看积压中**价格最低**的 sell：若其价格 $\le$ 该买价，则两笔成交并移除该 sell；否则该 buy 进入积压；
- 新 sell 对称：查看积压中**价格最高**的 buy，若其价格 $\ge$ 该卖价则成交并移除该 buy；否则该 sell 进入积压。

全部订单处理完后，返回积压中的订单总数，对 $10^9 + 7$ 取模。

**约束**：

- $1 \le \text{orders.length} \le 10^5$
- $\text{orders}[i].\text{length} = 3$
- $1 \le \text{price}_i, \text{amount}_i \le 10^9$
- $\text{orderType}_i \in \{0, 1\}$

> 💡 **核心矛盾**：订单以「批」为单位，$n$ 批、每批最多 $10^9$ 笔，**总笔数可达 $10^{14}$**——逐笔模拟必超时。而撮合规则永远只与「对手方的极端价格」比价（买单看最低卖价、卖单看最高买价），这正是**双堆（买侧大顶堆 + 卖侧小顶堆）+ 批量减法**的标准信号。

## 2. 示例

**示例 1**

```text
输入：orders = [[10,5,0],[15,2,1],[25,1,1],[30,4,0]]
输出：6
解释：前三批无对手方成交，直接入积压；第 4 批 buy 30×4 依次与
      最低价卖单 15×2、25×1 成交，剩 1 笔入买堆。
      最终积压 = 买 10×5 + 买 30×1 = 6 笔。
```

**示例 2**

```text
输入：orders = [[7,1000000000,1],[15,3,0],[5,999999995,0],[5,1,1]]
输出：999999984
解释：最终积压 = (10^9 − 3) 笔卖 7 + (999999995 − 1) 笔买 5
      = 1999999991，mod (10^9 + 7) = 999999984。
      本例说明 amount 巨大 → 必须批量撮合，且答案必须取模。
```

**示例 3（自造边界：等价成交）**

```text
输入：orders = [[5,2,0],[5,3,1]]
输出：1
解释：buy 5×2 先入积压；sell 5×3 到达时最高买价 5 ≥ 卖价 5
      （等号也算成交），配掉 2 笔买单，剩 1 笔卖单入积压。答案 = 1。
```

## 3. 解题思路

### 3.1 暴力思路：逐笔模拟

把每批订单拆成 `amount` 笔单笔订单，严格按题面规则逐笔处理：每笔 buy 查当前最低价卖单，能配就配 1 笔。

瓶颈只有一个但足以致命：$\sum \text{amount}_i$ 可达 $10^5 \times 10^9 = 10^{14}$，哪怕每步 $O(1$ 或 $\log n)$ 都远超时限。但注意**同一批内的订单价格、类型完全相同**——它们连续撮合时面对的对手方堆顶不变（直到该堆顶被耗尽弹出、换下一个堆顶）。这意味着「逐笔」中大量重复的比较与扣减可以**合并成一次 `min(amount, 顶数量)` 的批量减法**。

### 3.2 核心观察：双堆 + 批量撮合

![核心观察：买侧大顶堆与卖侧小顶堆](images/wc233_q2_backlog_heap_concept.svg)

两个观察合起来解决本题：

**观察一（撮合只看极端价 → 双堆）。** 新 buy 只与「最低价卖单」比价，新 sell 只与「最高价买单」比价——所需的撮合信息永远是对面的**一个极端值**。于是：

- 卖侧用**小顶堆**：堆顶即时给出最低卖价；
- 买侧用**大顶堆**：堆顶即时给出最高买价。

更妙的是积压内部维持一个**不变量**：任意时刻最大买价 $<$ 最小卖价（买卖双方在积压内部互不成交，否则早就配掉了）。所以「堆顶不满足比价条件 $\Rightarrow$ 对面全堆都不满足」，一次比较即可判断本批能否开始/继续撮合。

**观察二（同批同价 → 批量减法）。** 一批 `amount` 笔订单在撮合中面对的堆顶 $(p_0, a_0)$ 价格不变、仍是极端价，直到它被耗尽弹出。因此循环的每一轮直接成交 $k = \min(\text{amount}, a_0)$ 笔（双方各减 $k$），而不是 1 笔。$10^{14}$ 步的逐笔模拟被压缩为每批至多「弹出的堆顶数 + 1」轮，总量 $O(n)$ 轮。

> 💡 **套路沉淀**：看到「总量巨大但同质」（同价、同类型）的批量事件，条件反射做**批量合并**；看到「反复询问另一侧的最值」，条件反射**对偶双堆**。两者叠加，就是交易所订单簿撮合的标准简化模型。

### 3.3 算法流程

![算法流程：双堆批量撮合每一批订单](images/wc233_q2_match_flow.svg)

对每条 `orders[i] = [price, amount, type]`：

1. **type = 0（买入）**：循环——若 `amount > 0`、卖堆非空且**顶卖价 $\le$ price**：取堆顶 $(p_0, a_0)$，成交 $k = \min(\text{amount}, a_0)$ 笔，`amount −= k`、堆顶剩 $a_0 - k$（耗尽则弹出，未耗尽则写回）。循环结束后若 `amount > 0`，把 `(price, amount)` 压入买堆。
2. **type = 1（卖出）**：完全对称——条件改为**顶买价 $\ge$ price**，对手是买堆，剩余压入卖堆。
3. 所有订单处理完后，答案 $= \bigl(\sum_{\text{买堆}} a + \sum_{\text{卖堆}} a\bigr) \bmod (10^9 + 7)$。

### 3.4 示例演算

![示例演算：双堆视角逐步走查](images/wc233_q2_example_walkthrough.svg)

以示例 1 为例走查（记号「价格×数量」，见上图）：

- **① buy 10×5**：卖堆空，直接入买堆 → 买堆 $\{10{\times}5\}$，积压 5。
- **② sell 15×2**：顶买 $10 < 15$，不成交，入卖堆 → 卖堆 $\{15{\times}2\}$，积压 7。
- **③ sell 25×1**：顶买 $10 < 25$，不成交，入卖堆 → 卖堆 $\{15{\times}2, 25{\times}1\}$，积压 8。
- **④ buy 30×4**：顶卖 $15 \le 30$ → 一次配 $\min(4,2)=2$ 笔，弹出；下一个顶卖 $25 \le 30$ → 配 $\min(2,1)=1$ 笔，弹出；卖堆空，剩 1 笔入买堆 → 买堆 $\{10{\times}5, 30{\times}1\}$。

最终积压 $5 + 1 = 6$ ✓。注意第 ④ 步 4 笔订单只花 **2 轮**循环，而非 4 轮——批量减法把每轮的成交笔数从 1 提升到 $\min(\text{amount}, a_0)$。

## 4. 算法细节

1. **数据结构选择**：C++ 买堆直接用默认 `priority_queue<pair<int, long long>>`（`pair` 先比价格，默认大顶）；卖堆模板参加 `greater<>` 变小顶。Python 统一用 `heapq`，买堆存 `(-price, amount)` 模拟大顶。
2. **批量撮合循环**：`while (amount > 0 && 对面堆非空 && 顶价满足条件)` 内部取 $k = \min(\text{amount}, a_0)$，双方各减 $k$；堆顶耗尽则弹出，未耗尽则**写回**剩余量。
3. **写回方式**：C++ 的 `priority_queue` 不支持修改堆顶后自动重排，标准写法是「pop 后若剩余 $>0$ 再 push」；Python 既可同样 pop/push，也可直接改 `heap[0]` 再 `heapify`（本题两者复杂度同阶，pop/push 更不易错）。
4. **取模时机**：堆内的 `amount` 是撮合依据，**绝不能提前取模**（会破坏撮合逻辑）；模运算只属于最后一步求和。总和最大 $10^5 \times 10^9 = 10^{14}$，`long long` / Python 大整数均安全。
5. **循环轮数上界**：每轮要么永久弹出一个堆条目，要么是本批最后一轮（`amount` 归零）。每批至多压入 1 个新条目，故总轮数 $\le 2n$，总复杂度 $O(n \log n)$。

## 5. 正确性证明

**引理 1（价格分离不变量）**：任意时刻（批与批之间），若积压两侧均非空，则每笔买单的价格 $<$ 每笔卖单的价格。

**证明**：对批数归纳。初始积压为空，平凡成立。设处理某批前不变量成立。

- 到达 **sell 批**（价格 $q$）：撮合只删买堆顶部（最高价买单），不动旧卖单。循环终止时买堆为空或顶价 $< q$。对留下的买 $b$ 与旧卖 $s$：$b$ 是处理前就存在的旧买单，由归纳假设 $\text{price}(b) < \text{price}(s)$。若剩余 sell（价格 $q$）入堆：循环因「空或顶 $< q$」而终止，故所有留存买价 $< q$。
- 到达 **buy 批**（价格 $p$）：撮合只删卖堆顶部（最低价卖单），不动旧买单。循环终止时卖堆为空或顶价 $> p$，即所有留存卖价 $> p$。旧买 $b$ 与留存卖 $s$（旧卖的子集）由归纳假设仍满足 $\text{price}(b) < \text{price}(s)$；新入堆的买（价格 $p$）$<$ 所有留存卖价。∎

**引理 2（堆顶充分性）**：价格 $p$ 的新 buy 批能成交 $\iff$ 卖堆非空且顶价 $\le p$；且按规则必须从堆顶（最低价卖单）开始撮合。

**证明**：小顶堆的堆顶即最低卖价。若顶价 $> p$，则所有卖价 $\ge$ 顶价 $> p$，条件（卖价 $\le$ 买价）无一满足；若顶价 $\le p$，规则指定与「价格最低的卖单」成交，即堆顶。sell 批对称。∎

**引理 3（批量撮合等价性）**：对一批 $m$ 笔价格 $p$ 的 buy 订单，算法的批量循环与逐笔套用题面规则 $m$ 次产生的状态完全相同。

**证明**：设当前卖堆顶为 $s = (p_0, a_0)$。逐笔模拟时，只要 $s$ 未被耗尽，它价格不变且始终是最低价卖单（其余卖价 $\ge p_0$），故**连续** $\min(m, a_0)$ 笔成交全部落在 $s$ 上——与批量循环的一轮（减 $k = \min(m, a_0)$）完全等价。此后要么 $m$ 归零（本批结束），要么 $s$ 被耗尽弹出，对新的堆顶重复上述论证。对弹出的堆顶个数归纳即得两状态一致。sell 批对称。∎

**定理**：双堆批量模拟返回的结果与题面规则的逐笔模拟一致（模 $10^9+7$ 后相等）。

**证明**：由引理 2，每笔撮合选择的对手方符合「最低价卖 / 最高价买」的规则；由引理 3，每批的批量处理与逐笔执行等价；两个堆始终正确维护各自侧的价格多重集（堆序只依赖价格，`amount` 伴随存储）。对批数归纳：算法在每批结束时的两侧 $(\text{price}, \text{amount})$ 多重集与逐笔模拟的积压完全相同，故最终总量相等；再统一取模即为答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，$n = \text{orders.length}$。每批至多 1 次入堆；每个堆条目至多被弹出 1 次；撮合循环总轮数 $\le 2n$（每轮要么永久弹出一个条目，要么是当批最后一轮）。每次堆操作 $O(\log n)$，总量约 $2 \times 10^5 \times 17 \approx 3 \times 10^6$ 级别，瞬间出解。
- **空间复杂度**：$O(n)$。两堆至多各存 $n$ 个 $(\text{price}, \text{amount})$ 条目。

> 💡 对比暴力逐笔的 $O(10^{14})$，批量减法一次性把「同质事件」折叠——这是本题唯一的算法难点，剩下的是工程细节。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int getNumberOfBacklogOrders(vector<vector<int>>& orders) {
        const long long MOD = 1'000'000'007;
        // 买堆：大顶（pair 先比价格）；卖堆：小顶
        priority_queue<pair<int, long long>> buyHeap;
        priority_queue<pair<int, long long>, vector<pair<int, long long>>,
                       greater<>> sellHeap;

        for (auto& o : orders) {
            int price = o[0], type = o[2];
            long long amount = o[1];
            if (type == 0) {                       // 买入：与最低价卖单撮合
                while (amount > 0 && !sellHeap.empty()
                       && sellHeap.top().first <= price) {
                    auto [p, a] = sellHeap.top();
                    sellHeap.pop();
                    long long k = min(amount, a);  // 批量成交 k 笔
                    amount -= k;
                    a -= k;
                    if (a > 0) sellHeap.push({p, a});
                }
                if (amount > 0) buyHeap.push({price, amount});
            } else {                               // 卖出：与最高价买单撮合
                while (amount > 0 && !buyHeap.empty()
                       && buyHeap.top().first >= price) {
                    auto [p, a] = buyHeap.top();
                    buyHeap.pop();
                    long long k = min(amount, a);
                    amount -= k;
                    a -= k;
                    if (a > 0) buyHeap.push({p, a});
                }
                if (amount > 0) sellHeap.push({price, amount});
            }
        }

        long long ans = 0;
        while (!buyHeap.empty())  { ans += buyHeap.top().second;  buyHeap.pop(); }
        while (!sellHeap.empty()) { ans += sellHeap.top().second; sellHeap.pop(); }
        return ans % MOD;
    }
};
```

### Python

```python
import heapq
from typing import List

class Solution:
    def getNumberOfBacklogOrders(self, orders: List[List[int]]) -> int:
        MOD = 10 ** 9 + 7
        buy_heap = []   # (-price, amount)：大顶堆
        sell_heap = []  # (price, amount)：小顶堆

        for price, amount, otype in orders:
            if otype == 0:  # 买入：与最低价卖单撮合
                while amount > 0 and sell_heap and sell_heap[0][0] <= price:
                    p, a = heapq.heappop(sell_heap)
                    k = min(amount, a)          # 批量成交 k 笔
                    amount -= k
                    if a - k > 0:
                        heapq.heappush(sell_heap, (p, a - k))
                if amount > 0:
                    heapq.heappush(buy_heap, (-price, amount))
            else:        # 卖出：与最高价买单撮合
                while amount > 0 and buy_heap and -buy_heap[0][0] >= price:
                    negp, a = heapq.heappop(buy_heap)
                    k = min(amount, a)
                    amount -= k
                    if a - k > 0:
                        heapq.heappush(buy_heap, (negp, a - k))
                if amount > 0:
                    heapq.heappush(sell_heap, (price, amount))

        return (sum(a for _, a in buy_heap) + sum(a for _, a in sell_heap)) % MOD
```

## 8. 边界情况与易错点

1. **不做批量减法 → TLE**：总笔数可达 $10^{14}$，每轮循环必须配 $k = \min(\text{amount}, a_0)$ 笔而非 1 笔，这是本题的生死线。
2. **比较符含等号**：成交条件是卖价 $\le$ 买价（或买价 $\ge$ 卖价），**等号也成交**；误写成严格不等号会把等价单留在积压里（自造示例 3 专门覆盖此边界）。
3. **C++ 堆方向**：买堆用默认大顶即可；卖堆必须显式加 `greater<>` 变小顶。`pair` 按第一维（价格）比较，价格相同时第二维参与比较但不影响正确性。
4. **溢出**：`amount` 与最终求和用 `long long`（$\sum \text{amount}$ 可达 $10^{14}$）；`min(amount, a)` 两侧类型需一致，避免 `int` 截断。
5. **取模时机**：只在最终求和取模；撮合过程中堆内的量是精确计数，提前取模会破坏撮合逻辑。
6. **部分消耗写回**：堆顶被消耗后若仍有剩余，必须 pop 后重新 push（或 Python 改 `heap[0]` 后重排），漏写会丢失剩余量。
7. **空堆判断顺序**：`while` 条件先判 `amount > 0` 与堆非空，再访问 `top()` / `heap[0]`，避免空堆解引用。
8. **顺序不可重排**：订单必须按输入顺序处理——撮合结果依赖提交顺序，不能按价格排序后再处理。
