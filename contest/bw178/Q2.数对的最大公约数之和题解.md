# LeetCode 数对的最大公约数之和 题解

## 1. 题目概述

- **标题 / 题号**：数对的最大公约数之和（#3867，medium）
- **链接**：https://leetcode.cn/problems/sum-of-gcd-of-formed-pairs/
- **来源**：LeetCode 第 178 场双周赛 Q2
- **难度**：中等
- **标签**：数组、数学、双指针、数论、排序、模拟

**题意**：给定长度为 $n$ 的数组 `nums`，先构造 `prefixGcd`：

- 令 $mx_i = \max(nums[0], \dots, nums[i])$（前缀最大值）；
- 令 $prefixGcd[i] = \gcd(nums[i], mx_i)$。

然后把 `prefixGcd` **按非递减排序**，反复取「最小的未配对元素」和「最大的未配对元素」组成一对，对每一对求 $\gcd$ 并累加；若 $n$ 为奇数，正中间的元素落单，**忽略不计**。返回所有数对的 $\gcd$ 之和。

**约束**：

- $1 \le n \le 10^5$
- $1 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,6,4]
输出：2
解释：mx       = [2,6,6]
      prefixGcd = [gcd(2,2), gcd(6,6), gcd(4,6)] = [2,6,2]
      排序后 [2,2,6]，取最小 2 与最大 6 → gcd(2,6)=2，中间剩下的 2 忽略。总和 2。
```

**示例 2**

```text
输入：nums = [3,6,2,8]
输出：5
解释：mx       = [3,6,6,8]
      prefixGcd = [3,6,2,8]，排序后 [2,3,6,8]
      配对 (2,8) → gcd=2；配对 (3,6) → gcd=3。总和 2+3=5。
```

## 3. 解题思路

### 3.1 暴力思路

按定义模拟：对每个 $i$ 重新扫 $0..i$ 求前缀最大值，再算 $\gcd$；排序后用双指针首尾配对求 $\gcd$ 之和。

重算前缀最大值是 $O(n^2)$，$n = 10^5$ 时会超时。但这个 $O(n^2)$ 是**完全没必要**的：$mx_i = \max(mx_{i-1}, nums[i])$，一次滚动即可，所以「按定义模拟」只要把前缀最大值改成滚动维护，就已经是正解了。

真正需要想清楚的是两件事：**为什么配对是首尾**（题目规定，照做即可）与**答案会不会溢出**（$n/2$ 个 $\gcd$ 相加，每个可达 $10^9$，必须 64 位）。

### 3.2 核心观察：前缀最大值只增不减，$\gcd(v, mx)$ 一定是 $mx$ 的因数

![第一步：边扫边维护前缀最大值，算出 prefixGcd](images/bw178_q2_prefix_gcd.svg)

- $mx$ 随下标**单调不减**，所以 $mx_i \ge nums[i]$ 恒成立，$\gcd(nums[i], mx_i)$ 必然整除 $mx_i$，并且不超过 $nums[i]$。
- 于是 `prefixGcd` 的每个元素都不超过对应位置的前缀最大值，量级与原数组一致（$\le 10^9$）。
- 计算本身只依赖**前一项**的 $mx$，因此可以边读边算，$O(1)$ 额外空间（若不需要保留原数组）。

![第二步：排序后首尾配对（最小配最大）](images/bw178_q2_pairing.svg)

排序之后，配对规则是「最小 + 最大」「次小 + 次大」……直到中间。用双指针 `i` 从左、`j` 从右，每次 `gcd(a[i], a[j])` 后 `i++`、`j--`，当 `i >= j` 时停止——这自然就把「$n$ 为奇数时中间元素落单」处理掉了（此时最后一步 `i == j`，循环条件不成立，不会配对）。

> 💡 **注意**：这里**不需要**证明「首尾配对最优」之类的结论——题目就是规定按这个顺序配对，我们只是忠实实现。真正要小心的是**别自作聪明**改成「相邻配对」或「贪心找最大 gcd 的配对」，那都会算错。

### 3.3 算法流程

```text
1. mx = 0, prefix = []
2. for v in nums:
3.     mx = max(mx, v)
4.     prefix.append(gcd(v, mx))
5. prefix.sort()
6. total = 0, i = 0, j = len(prefix) - 1
7. while i < j:
8.     total += gcd(prefix[i], prefix[j])
9.     i += 1; j -= 1
10. 返回 total
```

### 3.4 示例演算

对示例 2 的 `nums = [3,6,2,8]`：

| $i$ | $nums[i]$ | $mx_i$ | $prefixGcd[i] = \gcd(nums[i], mx_i)$ |
|-----|-----------|--------|--------------------------------------|
| 0 | 3 | 3 | $\gcd(3,3)=3$ |
| 1 | 6 | 6 | $\gcd(6,6)=6$ |
| 2 | 2 | 6 | $\gcd(2,6)=2$ |
| 3 | 8 | 8 | $\gcd(8,8)=8$ |

排序后 $[2,3,6,8]$，双指针配对：

| 轮次 | 左 | 右 | $\gcd$ | 累计 |
|------|----|----|--------|------|
| 1 | 2 | 8 | 2 | 2 |
| 2 | 3 | 6 | 3 | 5 |

此时 `i = 2`、`j = 1`，循环结束，返回 5 ✓。示例 1 得到 `prefixGcd = [2,6,2]`，排序后 $[2,2,6]$；第一轮取 $2$ 与 $6$ 得 2，之后 `i = 1`、`j = 1` 停止，中间那个 2 被忽略，返回 2 ✓。

## 4. 算法细节

1. **滚动前缀最大值**：`mx = max(mx, v)` 一步完成，不要写内层循环重扫——那是本题唯一的复杂度陷阱。
2. **`gcd` 的实现**：C++17 直接用 `std::gcd`（`<numeric>`）；Python 用 `math.gcd`。手写欧几里得也可以，注意用取模而非减法。
3. **排序**：`prefixGcd` 必须**非递减**排序，用 `sort` 即可；不要用 `set`（会去重，破坏元素个数与配对关系）。
4. **双指针终止条件**：`while (i < j)`，而不是 `i <= j`。后者在 $n$ 为奇数时会把中间元素与自己做一次 $\gcd$（结果等于它本身），导致答案偏大。
5. **数据范围**：$n \le 10^5$、值 $\le 10^9$，$\gcd$ 之和最坏约 $5 \times 10^4 \times 10^9 = 5\times10^{13}$，必须用 `long long`（Python 无此问题）。
6. **返回值类型**：题目返回 `long`，C++ 用 `long long`。

## 5. 正确性证明

**引理 1（前缀最大值滚动正确）**：设 $mx_i$ 为算法第 $i$ 步结束后的 `mx`，则 $mx_i = \max(nums[0..i])$。

**证明**：对 $i$ 归纳。$i = 0$ 时 $mx_0 = \max(0, nums[0]) = nums[0]$（$nums[i] \ge 1$）。设 $mx_{i-1} = \max(nums[0..i-1])$，则 $mx_i = \max(mx_{i-1}, nums[i]) = \max(nums[0..i])$。∎

**引理 2（prefixGcd 正确）**：算法构造的 `prefix` 数组满足 $\text{prefix}[i] = \gcd(nums[i], \max(nums[0..i]))$。

**证明**：第 $i$ 步把 $\gcd(nums[i], mx_i)$ 追加到 `prefix` 末尾，由引理 1，$mx_i = \max(nums[0..i])$，正是定义式；且追加顺序与下标顺序一致。∎

**引理 3（排序保持多重集）**：`sort` 之后数组是 `prefixGcd` 的一个排列。

**证明**：排序只改变元素顺序，不增删元素。∎

**引理 4（双指针恰好覆盖规定配对）**：设排序后的数组为 $b_0 \le b_1 \le \cdots \le b_{n-1}$，则双指针依次产生的配对恰好是 $(b_0, b_{n-1}), (b_1, b_{n-2}), \dots$，共 $\lfloor n/2 \rfloor$ 对，且 $n$ 为奇数时 $b_{\lfloor n/2 \rfloor}$ 不被使用。

**证明**：初始 $i = 0, j = n-1$，产生第 1 对；每轮 `i` 加 1、`j` 减 1，第 $t$ 轮（从 0 计）配对为 $(b_t, b_{n-1-t})$，循环在 $i \ge j$ 时停止，即 $t \ge n-1-t$，也就是 $2t \ge n-1$，即 $t = \lceil (n-1)/2 \rceil = \lfloor n/2 \rfloor$ 时停止。故共 $\lfloor n/2 \rfloor$ 对；$n$ 为奇数时中间的 $b_{(n-1)/2}$ 从未作为任一端点参与。∎

**定理**：算法返回值等于题目定义的「所有数对的 $\gcd$ 之和」。

**证明**：由引理 2、3，算法手中的有序数组正是 `prefixGcd` 排序后的结果；由引理 4，双指针产生的配对恰为题目规定的「最小与最大、次小与次大……」，未配对元素恰为 $n$ 为奇数时的中间元素，题目要求忽略。逐对累加 $\gcd$ 即得所求之和。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。构造 `prefixGcd` 一遍 $O(n)$（每次 $\gcd$ 为 $O(\log \max nums)$，可视作小常数）；排序 $O(n \log n)$；双指针配对 $O(n)$ 次 $\gcd$。总计由排序主导。
- **空间**：$O(n)$ 存放 `prefixGcd`；`nums` 本身不计入。若允许原地覆盖 `nums`，可做到 $O(1)$ 额外空间（排序本身仍需 $O(\log n)$ 栈）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long gcdSum(vector<int>& nums) {
        vector<int> prefix;
        int mx = 0;
        for (int v : nums) {
            mx = max(mx, v);
            prefix.push_back(std::gcd(v, mx));
        }
        sort(prefix.begin(), prefix.end());
        long long total = 0;
        int i = 0, j = (int)prefix.size() - 1;
        while (i < j) {
            total += std::gcd(prefix[i], prefix[j]);
            i++;
            j--;
        }
        return total;
    }
};
```

### Python

```python
from math import gcd

class Solution:
    def gcdSum(self, nums: list[int]) -> int:
        prefix = []
        mx = 0
        for v in nums:
            mx = max(mx, v)
            prefix.append(gcd(v, mx))
        prefix.sort()
        total = 0
        i, j = 0, len(prefix) - 1
        while i < j:
            total += gcd(prefix[i], prefix[j])
            i += 1
            j -= 1
        return total
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有一个元素，`i = 0`、`j = 0`，`i < j` 不成立，总和为 0。题目没有规定要返回该元素本身，**落单元素一律忽略**。
2. **$n$ 为奇数的中间元素**：`prefixGcd` 排序后正中间那个元素不参与任何配对。若把循环写成 `while (i <= j)`，它会被自己配一次，答案偏大。
3. **`mx` 的初值**：从 0 开始即可（$nums[i] \ge 1$）；若值域可能为负，应初始化为 $-\infty$，否则 $\gcd$ 会算错。
4. **排序 vs 去重**：题目要的是「排序」，不是「去重后排序」。用 `set` 会让元素个数变少，配对关系全乱。
5. **溢出**：$\gcd$ 之和可达 $5\times10^{13}$，`int` 会溢出。返回类型 `long` 对应 C++ 的 `long long`。
6. **`gcd(0, x)`**：本题不会出现 0，因为 $nums[i] \ge 1$ 且 $mx \ge 1$；但如果扩展题允许 0，注意 $\gcd(0,x)=x$。
7. **不要贪心换配对**：有人会尝试「让每对 $\gcd$ 最大」的配对方式，那与原题无关。题目规定了配对顺序，必须是首尾配对。
