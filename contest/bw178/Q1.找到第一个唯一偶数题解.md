# LeetCode 找到第一个唯一偶数 题解

## 1. 题目概述

- **标题 / 题号**：找到第一个唯一偶数（#3866，easy）
- **链接**：https://leetcode.cn/problems/first-unique-even-element/
- **来源**：LeetCode 第 178 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums`，返回其中**最早出现的、恰好出现一次**的**偶数**；若不存在这样的数，返回 $-1$。

两个关键词缺一不可：**偶数**（能被 2 整除）和**恰好一次**（频率为 1）。返回的是那个**数值**本身，不是它的下标。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [3,4,2,5,4,6]
输出：2
解释：偶数有 4、2、6。其中 2 和 6 各只出现一次，4 出现两次。
      2 的下标 2 早于 6 的下标 5，所以答案是 2。
```

**示例 2**

```text
输入：nums = [4,4]
输出：-1
解释：唯一的偶数是 4，但出现两次，没有「唯一偶数」。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$，判断 `nums[i]` 是不是偶数，再数一遍 `nums` 里 `nums[i]` 出现了几次，第一个满足「偶数且出现 1 次」的就返回。

每次判断都要扫一遍数组，总复杂度 $O(n^2)$。$n \le 100$ 时这完全可行，但它做了大量重复工作：同一个值的频率被反反复复地重算。

### 3.2 核心观察：先统计频率，再按原顺序挑第一个

![找到第一个唯一偶数：频次表 + 从左到右第一命中](images/bw178_q1_freq_scan.svg)

两个需求分别对应两件事：

1. **「恰好出现一次」**：这是**值的属性**，与位置无关 → 用一张频次表一次统计完，之后 $O(1)$ 查询。
2. **「第一个（最早）」**：这是**位置的属性** → 必须按**原始下标顺序**扫描，不能先排序（排序会打乱「谁更早」）。

所以最优做法是明确的**两遍扫描**：

- 第一遍：统计每个值的出现次数；
- 第二遍：按下标 $0,1,\dots,n-1$ 顺序检查，返回第一个「偶数且频率为 1」的值；都不满足则返回 $-1$。

> 💡 **为什么不能只扫一遍**：扫描到某个偶数时，我们还不知道它后面会不会再出现一次。只有当「后面不会再出现」时才能确认它唯一，这就必须先把频次统计完整。

### 3.3 算法流程

![算法流程：两遍扫描，O(n)](images/bw178_q1_flow.svg)

```text
1. freq = 空哈希表
2. for v in nums:   freq[v] += 1                  # 第一遍：统计频率
3. for v in nums:                                  # 第二遍：按原顺序
4.     若 v % 2 == 0 且 freq[v] == 1:  返回 v
5. 返回 -1
```

### 3.4 示例演算

对示例 1 的 `nums = [3,4,2,5,4,6]`，频次表为 $\{3\!:\!1,\ 4\!:\!2,\ 2\!:\!1,\ 5\!:\!1,\ 6\!:\!1\}$：

| 下标 | 值 | 偶数？ | 频率 | 结论 |
|------|----|--------|------|------|
| 0 | 3 | ✗ | 1 | 跳过（不是偶数） |
| 1 | 4 | ✓ | 2 | 跳过（不唯一） |
| 2 | 2 | ✓ | 1 | **命中，返回 2** |

示例 2 中 `nums = [4,4]`，频次表 $\{4\!:\!2\}$，两个下标都因频率为 2 被跳过，循环结束返回 $-1$。

## 4. 算法细节

1. **频次容器**：值域 $[1,100]$ 可以开长度 101 的桶数组；用 `unordered_map` / `dict` 更通用（若后续题目把值域放大到 $10^9$ 也不用改代码）。本文代码用哈希表。
2. **两遍顺序扫描**：第一遍只统计，第二遍只判定。不要在第一遍里边统计边判定——此时频率还没数完。
3. **判定顺序**：先判偶数再查频率，或者反过来都行；但要把两个条件写成 `&&` 同时满足，别写成一个 `if` 套另一个导致逻辑走偏。
4. **返回值是值不是下标**：题目要求返回整数本身。若题目改成「返回下标」，只需把第二遍的 `v` 换成 `i`。
5. **$1 \le nums[i]$**：数组中没有 0，因此不必担心「0 是偶数」带来的额外分支（0 也是偶数，若值域含 0，条件照样成立）。

## 5. 正确性证明

**引理 1（频次表精确）**：第一遍扫描结束后，对每个出现过的值 $v$，$\text{freq}[v]$ 等于 $v$ 在 `nums` 中的出现次数。

**证明**：第一遍对 `nums` 的每个元素恰好访问一次并且只做 $\text{freq}[v] \mathrel{+}= 1$，所以 $\text{freq}[v]$ 等于 $v$ 被访问的次数，即出现次数。∎

**引理 2（第二遍不改变频次表）**：第二遍扫描只读取 `freq`，不修改它，因此判定期间频率信息保持不变。

**证明**：第二遍只执行比较与提前返回，没有写操作。∎

**定理**：若存在「偶数且出现一次」的值，算法返回其中下标最小的那个值；否则返回 $-1$。

**证明**：第二遍按下标递增顺序访问。设 $i$ 是第一个满足「`nums[i]` 为偶数且频率为 1」的下标。算法在第 $i$ 步返回 `nums[i]`。任取下标 $j < i$，第 $j$ 步未返回，说明 $j$ 处的值不满足两个条件之一，故不存在更早的唯一偶数，返回值的「最早」性成立。又由引理 1，频率判定与真实出现次数一致，故返回的值确实唯一且为偶数。若不存在任何满足条件的下标，第二遍走完不返回，算法返回 $-1$，与无解要求一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。第一遍统计 $n$ 次哈希更新，第二遍 $n$ 次哈希查询，每次均摊 $O(1)$。
- **空间**：$O(V)$，$V$ 为不同值的个数（本题 $V \le \min(n,100)$），用于存放频次表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int firstUniqueEven(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int x : nums) freq[x]++;
        for (int x : nums) {
            if (x % 2 == 0 && freq[x] == 1) return x;
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def firstUniqueEven(self, nums: list[int]) -> int:
        freq = {}
        for x in nums:
            freq[x] = freq.get(x, 0) + 1
        for x in nums:
            if x % 2 == 0 and freq[x] == 1:
                return x
        return -1
```

## 8. 边界情况与易错点

1. **没有偶数 / 没有唯一值**：例如 `[1,3,5]`、`[4,4]`，都要返回 $-1$，不能返回 0 或空。
2. **「第一个」指下标最早，不是最小值**：`[6,2]` 的答案是 6 而不是 2。因此不能排序后再取。
3. **重复的偶数要整体淘汰**：`[2,2,4]` 的答案是 4，因为 2 出现两次；不要因为「2 第一次出现」就返回 2。
4. **奇数的唯一性无关**：`[3,4]` 中 3 只出现一次但它是奇数，答案仍是 4。别把「唯一」和「偶数」两个条件拆成两次独立查找。
5. **数组长度 1**：`[2]` 返回 2（偶数且唯一），`[3]` 返回 $-1$。
6. **值域桶的大小**：若用桶数组要保证下标能覆盖 $nums[i]$（本题 100），越界即 RE。
