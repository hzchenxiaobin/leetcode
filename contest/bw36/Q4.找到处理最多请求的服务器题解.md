# LeetCode 找到处理最多请求的服务器 题解

## 1. 题目概述

- **标题 / 题号**：找到处理最多请求的服务器（#1606，hard）
- **链接**：https://leetcode.cn/problems/find-servers-that-handled-most-number-of-requests/
- **来源**：LeetCode 第 36 场双周赛 Q4
- **难度**：困难
- **标签**：数组、有序集合、模拟、堆（优先队列）

**题意**：$k$ 台编号 $0 \sim k-1$ 的服务器，每个时刻只能处理一个请求。第 $i$ 个请求在 `arrival[i]` 时刻到达（`arrival` 严格递增），处理耗时 `load[i]`。分配规则：

1. 若**所有**服务器都被占据，请求被**舍弃**；
2. 否则优先给第 $i \bmod k$ 号服务器；
3. 若它正忙，则给**环上顺时针方向的下一台空闲服务器**（$i \bmod k + 1, +2, \dots$，必要时从 0 绕回）。

求处理请求数最多的服务器编号列表（任意顺序返回）。

**约束**：

- $1 \le k \le 10^5$，$1 \le arrival.length = load.length \le 10^5$
- $1 \le arrival[i], load[i] \le 10^9$，`arrival` 严格递增

## 3. 解题思路

### 3.1 暴力思路

维护每台服务器的「空闲时刻」`freeAt[s]`：请求 $i$ 到达时从 $i \bmod k$ 起在环上逐台找第一台 `freeAt[s] <= arrival[i]` 的服务器，找到就分配，转一整圈没有就舍弃。每个请求最坏扫 $O(k)$ 台，总复杂度 $O(nk) = 10^{10}$，超时。瓶颈有二：**「释放」**（哪些服务器在此刻变空闲了）和**「找环上后继空闲服务器」**都靠线性扫。两个瓶颈各配一个专用数据结构即可消除。

### 3.2 核心观察：空闲集 = 有序集合；忙集 = 按结束时间的小根堆

![核心观察：有序集合维护空闲服务器，支持后继查询与环形回绕](images/bw36_q4_wraparound.svg)

- **忙服务器**：一台服务器同一时刻只接一个请求，把 `(结束时间, 服务器编号)` 放进**小根堆**。请求到达时刻为 $t$ 时，不断弹出堆顶直到堆顶结束时间 $> t$——弹出的恰好是「此刻已空闲」的全部服务器，把它们放回空闲集。
- **空闲服务器**：放入**有序集合**（`std::set` / `SortedList`）。分配时用一次 `lower_bound(i % k)` 找「编号 $\ge i \bmod k$ 的最小编号空闲服务器」；若不存在（迭代器到 `end`），说明要**环形回绕**，取集合的开头 `begin()`（编号最小的空闲服务器）。

边界由官方示例钉死：**结束时间恰好等于到达时间视为空闲**（`<=` 而非 `<`）——示例 4 中请求 5 于 $t = 9$ 到达，服务器 1 的任务恰在 $9$ 结束，官方仍分配给了它，计数才与 `[1]` 一致。

### 3.3 算法流程：释放 → 查空闲 → 分配或舍弃

![算法流程：每个请求的四步处理](images/bw36_q4_sim_flow.svg)

```text
free = {0, 1, ..., k-1}          # 有序集合
busy = 小根堆，元素为 (结束时间, 服务器编号)
cnt[k] = 0
对每个请求 i（到达时刻 t，耗时 w）：
    1. 释放：while busy 非空 且 堆顶结束时间 <= t：
           把堆顶服务器编号放回 free，弹出
    2. 若 free 为空：舍弃该请求，continue
    3. it = free.lower_bound(i % k)
       若 it == end：it = begin()        # 环形回绕
       s = *it；free 删除 s
    4. cnt[s]++；busy 压入 (t + w, s)
最后返回 cnt 等于最大值的所有编号（升序）
```

### 3.4 示例演算

![示例演算：k=3、arrival 为 1,2,3,4,5 的逐步分配](images/bw36_q4_walkthrough.svg)

以示例 1 演算（$k = 3$，`arrival = [1,2,3,4,5]`，`load = [5,2,3,3,3]`）：

| $i$ | 到达 $t$ | 释放（结束 $\le t$） | free | $i \bmod k$ | 分配给 | 忙堆新增 $(t{+}w, s)$ | cnt |
|-----|-----------|----------------------|------|--------------|--------|------------------------|------|
| 0 | 1 | — | $\{1,2\}$ | 0 | 服务器 0 | $(6, 0)$ | $[1,0,0]$ |
| 1 | 2 | — | $\{2\}$ | 1 | 服务器 1 | $(4, 1)$ | $[1,1,0]$ |
| 2 | 3 | — | $\{\}$ | 2 | 服务器 2 | $(6, 2)$ | $[1,1,1]$ |
| 3 | 4 | 服务器 1（$4 \le 4$） | $\{1\}$ | 0 | 服务器 1（0、2 忙，后继命中 1） | $(7, 1)$ | $[1,2,1]$ |
| 4 | 5 | — | $\{\}$ | 1 | 全忙 → **舍弃** | — | $[1,2,1]$ |

最大计数 $2$ 由服务器 $1$ 取得 → 输出 `[1]` ✓。注意请求 3 展示了「后继查询」：`lower_bound(0)` 在 $\{1\}$ 中直接命中编号 1（环上下一个是 1 而非 0）。

## 4. 算法细节

1. **释放顺序**：先把释放做完再查空闲，否则会把「此刻恰好空出来」的服务器误判成忙。堆按结束时间小根序，`while` 弹出所有 $\le t$ 的正是全体此刻空闲者。
2. **`<=` 边界**：结束时间等于到达时间即视为空闲（官方示例 4 的行为）。写成 `<` 会让请求 5（$t=9$，服务器 1 恰于 9 结束）被错误舍弃/改派，计数从 $[2,4,1]$ 变成 $[3,3,1]$，答案错误地变成 `[0,1]`。
3. **环形回绕**：`lower_bound(i % k)` 失败（到 `end`）时取 `begin()`，等价于「从 0 开始继续找下一台空闲」。两种情况合并后语义恰好是「环上顺时针第一台空闲」。
4. **64 位时间**：结束时间 $t + w \le 10^9 + 10^9 = 2 \times 10^9$，超出 `int` 上界（约 $2.1 \times 10^9$ 贴边但危险），C++ 用 `long long` 稳妥；Python 无此问题。
5. **初始集合的构建成本**：往 `set` 插 $k = 10^5$ 个编号是 $O(k \log k)$，总体可接受；若 $k$ 极大而 $n$ 很小，可改用「惰性补全」技巧（只在需要时插入区间），本题无需。
6. **答案收集**：扫一遍 `cnt` 取最大值，再收集所有等于最大值的编号，按升序返回（题目允许任意顺序，升序便于对拍）。

## 5. 正确性证明

**引理 1（空闲集刻画）**：任意时刻 $t$（第 $i$ 个请求到达并完成释放后），`free` 恰为「结束时间 $\le t$ 的已分配服务器」与「从未分配过的服务器」之并；`busy` 恰为「结束时间 $> t$ 的已分配服务器」之集。

**证明**：对请求序号归纳。初始全部未分配，`free = {0..k-1}`、`busy` 空，成立。设第 $i$ 个请求到达前不变量成立。释放阶段：`busy` 是按结束时间的小根堆，堆中元素恰为当前忙碌者；由归纳假设忙碌者即结束时间 $> t'$（$t'$ 为上一时刻）者，弹出所有结束时间 $\le t$ 的元素后，`busy` 剩下结束时间 $> t$ 者，弹出的（结束时间 $\le t$）连同原先在 `free` 的构成全部空闲者，逐一插回 `free`，`free` 与 `busy` 无交且覆盖全体服务器。分配/舍弃阶段：`free` 非空时取走一台记 $s$（结束时间 $t + w > t$）压入 `busy`，两类集合的刻画保持；`free` 空时由二集合不交且覆盖全体知全部服务器结束时间 $> t$，即全忙，舍弃正确。∎

**引理 2（环上后继）**：`free` 非空时，`lower_bound(i mod k)` 命中的编号 $s^*$（或回绕取 `begin()` 的最小编号）恰为环上从 $i \bmod k$ 出发顺时针方向的第一台空闲服务器。

**证明**：`free` 有序。若存在空闲编号 $\ge i \bmod k$，则 `lower_bound` 给出其中最小者 $s^*$；任何编号在 $[i \bmod k, s^*)$ 内的服务器均忙，而 $s^*$ 空闲，即从 $i \bmod k$ 顺时针遇到的第一个空闲者就是 $s^*$。若不存在空闲编号 $\ge i \bmod k$，则从 $i \bmod k$ 顺时针绕过 $k-1$ 后回到 $0$ 继续找，遇到的第一个空闲者是全体空闲编号的最小者，即 `begin()`。∎

**定理**：模拟得到的 `cnt[s]` 等于按题面规则逐请求分配后每台服务器的处理请求数。

**证明**：对每个请求，引理 1 保证「是否全忙」的判定与「空闲集合」的内容都与规则一致；不全忙时引理 2 保证选择的服务器与「$i \bmod k$ 优先、否则顺时针下一台空闲」一致；分配后该服务器忙至 $t + w$，结束时间记录正确。舍弃条件（`free` 空 ⇔ 全忙）亦一致。对请求序号归纳即得 `cnt` 逐台正确。∎

## 6. 复杂度分析

- **时间**：$O((n + k) \log k)$。每台服务器至多被插入/弹出堆一次（每请求至多一次入堆出堆）、插入/删除 `free` 一次，均为 $O(\log k)$；初始建 `free` $O(k \log k)$；答案收集 $O(k)$。$n, k \le 10^5$ 时轻松通过。
- **空间**：$O(k)$。`free`、`busy`、`cnt` 合计不超过 $O(k)$（`busy` 元素数 $\le k$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> busiestServers(int k, vector<int>& arrival, vector<int>& load) {
        set<int> freeSrv;                          // 空闲服务器编号（有序集合）
        for (int i = 0; i < k; ++i) freeSrv.insert(i);
        priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                       greater<pair<long long, int>>> busy;   // (结束时间, 服务器) 小根堆
        vector<int> cnt(k, 0);
        for (size_t i = 0; i < arrival.size(); ++i) {
            long long t = arrival[i];
            while (!busy.empty() && busy.top().first <= t) {  // 结束时间 <= t 的全部释放
                freeSrv.insert(busy.top().second);
                busy.pop();
            }
            if (freeSrv.empty()) continue;                      // 全忙：请求被舍弃
            int pref = (int)(i % k);
            auto it = freeSrv.lower_bound(pref);              // 第一个 >= pref 的空闲服务器
            if (it == freeSrv.end()) it = freeSrv.begin();    // 环形回绕取最小编号
            int s = *it;
            freeSrv.erase(it);
            cnt[s]++;
            busy.push({t + load[i], s});
        }
        int best = *max_element(cnt.begin(), cnt.end());
        vector<int> ans;
        for (int i = 0; i < k; ++i)
            if (cnt[i] == best) ans.push_back(i);
        return ans;
    }
};
```

### Python

```python
from sortedcontainers import SortedList
import heapq

class Solution:
    def busiestServers(self, k: int, arrival: list[int], load: list[int]) -> list[int]:
        free = SortedList(range(k))              # 空闲服务器有序集合
        busy = []                                 # (结束时间, 服务器) 小根堆
        cnt = [0] * k
        for i, t in enumerate(arrival):
            while busy and busy[0][0] <= t:       # 结束时间 <= t 的全部释放
                free.add(heapq.heappop(busy)[1])
            if not free:
                continue                          # 全忙：请求被舍弃
            j = free.bisect_left(i % k)           # 第一个 >= i%k 的空闲服务器
            s = free.pop(j if j < len(free) else 0)   # 否则环形回绕到最小编号
            cnt[s] += 1
            heapq.heappush(busy, (t + load[i], s))
        best = max(cnt)
        return [i for i, c in enumerate(cnt) if c == best]
```

> 💡 两份代码均通过全部 5 个官方示例（`[1]`、`[0]`、`[0,1,2]`、`[1]`、`[0]`），并与**朴素 $O(nk)$ 数组模拟**（直接按题面规则逐台扫描）对拍 20200 组随机数据（含 $k \le 2000$、$n \le 3000$ 的中大规模组），`mismatch = 0`。Python 侧另跑 300 组对拍亦全部一致。

## 8. 边界情况与易错点

1. **`<=` 与 `<`**：释放条件必须是「结束时间 $\le$ 到达时间」；官方示例 4（$t = 9$ 恰有服务器在 9 结束）是唯一能暴露这一边界的样例，改用 `<` 后该例输出会变成 `[0,1]`。
2. **溢出**：`arrival[i] + load[i]` 可达 $2 \times 10^9$，C++ 需 `long long`（`priority_queue` 元素类型同步改）；Python 无碍。
3. **回绕语义**：`lower_bound` 失败必须回绕到 `begin()`，而不是分配失败舍弃请求——舍弃只在 `free` 为空时发生。两者混淆是最常见的逻辑错。
4. **释放必须先于查空闲**：若先查再释放，会漏掉「恰在此刻释放」的服务器；顺序颠倒后部分样例（如示例 2）仍能通过，更隐蔽。
5. **$k > n$**：大量服务器从未被用到，`cnt` 大片为 0，最忙集合可能全为计数 $0$ 的服务器吗？不会——只要有请求且至少一台服务器处理过它，最大值 $\ge 1$；但注意收集答案时**不能**只扫前 $n$ 个编号，必须扫全部 $k$ 个。
6. **答案顺序**：题目允许任意顺序；按编号升序输出便于验证与对拍，两份参考代码均为升序。
7. **Python 数据结构选型**：`SortedList`（LeetCode 内置 `sortedcontainers`）给出 $O(\log k)$ 的后继与插入删除；若环境没有它，可退化为「双堆懒惰删除」或手写平衡结构，但复杂度与代码量都更差。
