# LeetCode 设计停车系统 题解

## 1. 题目概述

- **标题 / 题号**：设计停车系统（#1603，easy）
- **链接**：https://leetcode.cn/problems/design-parking-system/
- **来源**：LeetCode 第 36 场双周赛 Q1
- **难度**：简单
- **标签**：设计、计数、模拟

**题意**：停车场有三种尺寸的车位——大、中、小，每种数目固定。实现 `ParkingSystem` 类：

- `ParkingSystem(int big, int medium, int small)`：初始化三种车位的数目；
- `bool addCar(int carType)`：一辆 `carType` 型车（$1$=大、$2$=中、$3$=小）到达，**只能停入对应尺寸的车位**。有空位则停入并返回 `true`，否则返回 `false`。

**约束**：

- $0 \le big, medium, small \le 1000$
- `carType` 取值为 $1$、$2$ 或 $3$
- `addCar` 最多被调用 $1000$ 次

## 2. 示例

**示例 1**

```text
输入：
["ParkingSystem", "addCar", "addCar", "addCar", "addCar"]
[[1, 1, 0], [1], [2], [3], [1]]
输出：[null, true, true, false, false]
解释：1 个大车位、1 个中车位、0 个小车位。
addCar(1) -> true  （剩 1 个大车位，停入）
addCar(2) -> true  （剩 1 个中车位，停入）
addCar(3) -> false （小车位为 0）
addCar(1) -> false （唯一大车位已被占用）
```

## 3. 解题思路

### 3.1 暴力思路

签到题没有复杂度压力，最朴素的实现是维护三个独立变量 + `switch(carType)` 三分支，或维护一个「已停车辆类型计数」数组、每次与初始容量比较。这些写法都正确，但分支逻辑容易抄错（$1/2/3$ 与 big/medium/small 的对应关系）。更简洁的做法是把「类型」直接当作**数组下标**。

### 3.2 核心观察：三个计数器，`carType` 即下标

![核心设计：按 carType 直接索引三类车位余量](images/bw36_q1_slots_design.svg)

把状态压缩成长度 $4$ 的数组 `slot`，`slot[t]` 表示 $t$ 类车位的**剩余数量**（下标 $0$ 弃置，让 `carType` 直接作下标）：

- 初始化：`slot = [_, big, medium, small]`；
- `addCar(t)`：若 `slot[t] > 0`，则 `slot[t] -= 1` 并返回 `true`；否则返回 `false`。

没有 `switch`、没有 `if-else` 链，判空与占用是同一行代码。车型互不通用（大车不能停中位），所以三类计数器完全独立、互不干扰。

### 3.3 算法流程

```text
构造：slot[1]=big, slot[2]=medium, slot[3]=small
addCar(carType)：
    若 slot[carType] > 0：
        slot[carType] -= 1
        返回 true
    否则返回 false
```

### 3.4 示例演算

![示例演算：官方示例四次 addCar 的状态变化](images/bw36_q1_walkthrough.svg)

对官方示例 `ParkingSystem(1, 1, 0)` 演算，初始 `slot = [_, 1, 1, 0]`：

| 调用 | 判定 | 状态变化 | 返回 |
|------|------|----------|------|
| `addCar(1)` | `slot[1] = 1 > 0` | `slot[1]: 1 → 0` | `true` |
| `addCar(2)` | `slot[2] = 1 > 0` | `slot[2]: 1 → 0` | `true` |
| `addCar(3)` | `slot[3] = 0` | 不变 | `false` |
| `addCar(1)` | `slot[1] = 0`（已被占） | 不变 | `false` |

与官方输出 `[null, true, true, false, false]` 一致。

## 4. 算法细节

1. **`carType` 直接作下标**：长度 $4$ 的数组（下标 $1..3$ 有效），避免 `switch` 分支中的手误；这是「枚举值连续」类模拟题的通用简化。
2. **返回前先减**：判空与占用必须原子完成——先判 `> 0` 再减一，顺序颠倒会在余量为 $0$ 时减成 $-1$。
3. **C++ 成员初始化**：构造函数初始化列表 `slot(4, 0)` 后再赋值三个位；或直接 `slot = {0, big, medium, small}`。
4. **为何不需要记录「哪辆车停在哪」**：题目只询问能否停入，车辆离开、车位复用等均不出现；若加上 `leave(carType)` 也只需 `slot[t] += 1`。
5. **并发与持久化**：本题单线程、无持久化；真实系统需要考虑并发计数（原子操作/锁）与宕机恢复（落盘），这是「设计题」标签想引导的思考方向。

## 5. 正确性证明

**引理（不变量）**：任意时刻，`slot[t]` 等于「初始 $t$ 类车位数 − 已成功停入的 $t$ 类车数」，且非负。

**证明**：对操作序列归纳。初始时无车停入，`slot[t]` 即初始数目，成立。每次 `addCar(t)`：若返回 `true`，成功停入数加 $1$ 且 `slot[t]` 减 $1$，等式保持；若返回 `false`，判定条件 `slot[t] = 0` 保证不执行减法，成功停入数与 `slot[t]` 均不变，等式保持。非负性由判定条件直接保证。∎

**定理**：`addCar(t)` 返回 `true` 当且仅当此刻存在一个空闲的 $t$ 类车位。

**证明**：$t$ 类车位互不串用（大车只停大位），故「存在空闲 $t$ 位」$\iff$「已停入 $t$ 类车数 $<$ 初始 $t$ 类车数」$\iff$（由引理）`slot[t] > 0`，这正是 `addCar` 的判定条件；返回 `true` 时同时完成减一（占位），返回 `false` 时状态不变。∎

## 6. 复杂度分析

- **时间**：`addCar` 为 $O(1)$（一次数组比较、一次减法）；构造 $O(1)$。
- **空间**：$O(1)$。固定长度 $4$ 的数组，与调用次数和车位数无关。

## 7. 参考代码

### C++

```cpp
class ParkingSystem {
    vector<int> slot;                        // slot[t]：t 类车（1大/2中/3小）剩余车位数
public:
    ParkingSystem(int big, int medium, int small) : slot(4, 0) {
        slot[1] = big;
        slot[2] = medium;
        slot[3] = small;
    }

    bool addCar(int carType) {
        if (slot[carType] > 0) {
            slot[carType]--;
            return true;
        }
        return false;
    }
};
```

### Python

```python
class ParkingSystem:
    def __init__(self, big: int, medium: int, small: int):
        self.slot = [0, big, medium, small]  # slot[t]：t 类车剩余车位数

    def addCar(self, carType: int) -> bool:
        if self.slot[carType] > 0:
            self.slot[carType] -= 1
            return True
        return False
```

> 💡 两份代码均通过官方示例（`[null, true, true, false, false]`）以及 400 组随机操作序列（随机初始容量 $0 \sim 4$ + 每组 12 次随机 `addCar`）与独立计数器模拟的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **某类车位初始为 $0$**：`addCar` 对应类型直接返回 `false`，判定条件天然覆盖，无需特判。
2. **减一顺序**：务必先判 `> 0` 再 `--`；写成先 `--` 再判断会把余量打成负数，后续调用全部错乱。
3. **下标越界**：若把 `slot` 开成长度 $3$ 而直接用 `carType` 索引会在 `carType = 3` 时越界（C++ 未定义行为、Python `IndexError`）。长度开 $4$、下标 $1..3$ 最稳。
4. **`carType` 与尺寸的对应**：$1$=大、$2$=中、$3$=小，初始化时 `slot[1]=big` 而非 `slot[0]=big`；用官方示例（含 `addCar(3)` 返回 `false`）即可自检对应关系。
5. **不要做「大车可停小位」之类脑补**：题面明确一辆车只能停在对应尺寸的车位中，三类计数器必须独立。
