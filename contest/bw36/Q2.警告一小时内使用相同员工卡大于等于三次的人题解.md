# LeetCode 警告一小时内使用相同员工卡大于等于三次的人 题解

## 1. 题目概述

- **标题 / 题号**：警告一小时内使用相同员工卡大于等于三次的人（#1604，medium）
- **链接**：https://leetcode.cn/problems/alert-using-same-key-card-three-or-more-times-in-a-one-hour-period/
- **来源**：LeetCode 第 36 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序

**题意**：安保系统记录员工每次刷卡的名字与时间。若一个员工在**一小时时间范围内**刷卡**至少三次**，系统对其发布警告。给定 `keyName[i]` 与 `keyTime[i]`（同一天内的 `"HH:MM"` 24 小时制时间），返回**去重后**收到警告的员工名字列表，按**字典序升序**排列。

特别注意边界：`"10:00" - "11:00"` 视为一小时范围内（差恰好 60 分钟算），而 `"22:51" - "23:52"` 不算（差 61 分钟）。

**约束**：

- $1 \le keyName.length = keyTime.length \le 10^5$
- `keyTime` 形如 `"HH:MM"`；保证 $(keyName[i], keyTime[i])$ 二元对**互不相同**
- $1 \le keyName[i].length \le 10$，只含小写字母

## 2. 示例

**示例 1**

```text
输入：keyName = ["daniel","daniel","daniel","luis","luis","luis","luis"]
     keyTime = ["10:00","10:40","11:00","09:00","11:00","13:00","15:00"]
输出：["daniel"]
解释：daniel 在一小时内刷了 3 次（10:00、10:40、11:00，首尾差 60 分钟，算）。
```

**示例 2**

```text
输入：keyName = ["alice","alice","alice","bob","bob","bob","bob"]
     keyTime = ["12:01","12:00","18:00","21:00","21:20","21:30","23:00"]
输出：["bob"]
解释：bob 在 21:00、21:20、21:30 一小时内刷了 3 次。
alice 的 12:00 与 12:01 与 18:00 首尾差 360 分钟，不算。
```

## 3. 解题思路

### 3.1 暴力思路

对每个人枚举其所有刷卡时间的**三元组**，检查首尾差是否 $\le 60$ 分钟。若一个员工有 $k$ 条记录，要检查 $\binom{k}{3} = O(k^3)$ 个三元组；最坏情况全部记录属于一个人，$k = 10^5$，约 $1.7 \times 10^{14}$ 次检查——不可行。瓶颈在于三元组枚举有大量重复：其实**只有排序后相邻的三元组才值得看**。

### 3.2 核心观察：排序后只查「连续三元组」；跨小时的判断交给数值化

![核心观察：按人分组、组内排序，用长度 3 的窗口检查](images/bw36_q2_group_window.svg)

两个关键化简：

1. **时间数值化**：`"HH:MM"` 化为分钟数 $60H + M$，「一小时范围」变成一个纯数值判断——三元组中最晚减最早 $\le 60$（含等号，对应 `"10:00"-"11:00"` 算）。
2. **分组 + 排序 + 连续窗口**：把记录按姓名分组（哈希表），组内时间排序后，若存在任何跨度 $\le 60$ 的三元组，则**必然存在一个「连续三个」**满足 $t[i+2] - t[i] \le 60$——因为取首尾更近的连续点只会让跨度更小（严格论证见 §5）。于是每人只需一遍线性扫描，复杂度从 $O(k^3)$ 降到 $O(k \log k)$。

> ⚠️ 边界的语义要吃透：题面给的两个对照例说明判定是「$t_{max} - t_{min} \le 60$」，即 `[含]` 两端。若写成 `< 60`，会把示例 1 的 daniel（差恰为 60）判成不警告。

### 3.3 算法流程

![算法流程：解析时间 → 分组 → 排序 → 窗口判定 → 汇总排序](images/bw36_q2_boundary_check.svg)

```text
1. 用哈希表 by 把每条记录按姓名归组：
       t = 60 * HH + MM；by[name].append(t)
2. 对每个 name、其时间列表 ts：
       ts 排序
       若存在 i 使 ts[i+2] - ts[i] <= 60：name 进入警告名单
3. 名单按字典序升序排序后返回（分组天然去重）
```

### 3.4 示例演算

![示例演算：三人时间轴上的 60 分钟窗口](images/bw36_q2_walkthrough.svg)

以示例 2 演算（化为分钟数）：

- `alice`：$\{721, 720, 1080\}$ → 排序 $[720, 721, 1080]$ → 窗口检查：$t_2 - t_0 = 360 > 60$ → 无警告；
- `bob`：$\{1260, 1280, 1290, 1380\}$ → 排序 $[1260, 1280, 1290, 1380\]$ → $i=0$：$t_2 - t_0 = 1290 - 1260 = 30 \le 60$ → 警告（$21:00, 21:20, 21:30$）；
- 若看 $i = 1$：$1380 - 1280 = 100 > 60$——不需要，第一个命中即可 `break`。

输出按字典序 `["bob"]` ✓。示例 1 同理：`daniel` 排序后 $[600, 640, 660]$，$660 - 600 = 60 \le 60$ → 警告；`luis` 的 $[540, 660, 780, 900]$ 任一窗口差均 $120 > 60$ → 无警告。

## 4. 算法细节

1. **时间解析**：`"HH:MM"` 定长，直接字符运算 `t = (s[0]-'0')*600 + (s[1]-'0')*60 + (s[3]-'0')*10 + (s[4]-'0')` 最快（C++）；Python 用 `int(h) * 60 + int(m)` 的 `split(":")` 即可。不要用字符串字典序直接比较时间——`"9:59"` 类缺零格式会出错（本题保证补零，但解析成整数更稳）。
2. **「同一天内」是隐含条件**：时间都在 $[0, 1439]$，不存在跨天回绕（如 23:50 与 00:10），无需环处理。
3. **连续三元组判定**：$i$ 从 $0$ 到 $len - 3$，判 $ts[i+2] - ts[i] \le 60$。组内记录数 $< 3$ 直接跳过。
4. **去重与排序**：按姓名分组后每人只检查一次，天然去重；最后对名单整体按字典序升序。C++ `sort` 字符串数组、Python `sorted` 均按字典序。
5. **二元对互不相同**是「免费」的条件**：同一人同一时刻不会刷两次卡，排序后无需处理并列；即便存在并列，窗口判定也依然正确（差为 0）。

## 5. 正确性证明

**引理 1（跨度刻画）**：员工在「一小时范围」内刷卡至少三次 $\iff$ 存在三次刷卡 $a \le b \le c$ 使 $c - a \le 60$。

**证明**：「一小时范围」定义为某个长度 60 分钟（含端点）的区间同时包含这三次时刻。三次时刻被同一区间 $[x, x+60]$ 包含 $\iff$ $c - a \le 60$（取 $x = a$ 即可）。∎

**引理 2（连续三元组归约）**：排序后的时间序列 $t_0 \le t_1 \le \dots \le t_{k-1}$ 中存在某三元组（任意位置）首尾差 $\le 60$ $\iff$ 存在下标 $i$ 使 $t_{i+2} - t_i \le 60$。

**证明**：($\Leftarrow$) 连续三元组本身就是三元组，显然。($\Rightarrow$) 设 $t_p \le t_q \le t_r$（$p < q < r$）是首尾差最小（$\le 60$）的三元组中任一组。因 $p < q < r$，有 $p + 2 \le r$，而序列单调不减，故 $t_{p+2} \le t_r$，于是 $t_{p+2} - t_p \le t_r - t_p \le 60$。取 $i = p$ 即是连续三元组。∎

**定理**：算法输出的名单恰为所有「一小时内刷卡 $\ge 3$ 次」的员工，按字典序升序且无重复。

**证明**：由引理 1，判定条件等价于「存在首尾差 $\le 60$ 的三次刷卡」；由引理 2，该条件等价于排序后存在连续三元组满足 $t_{i+2} - t_i \le 60$，算法逐一检查全部 $i$，判定完备且无遗漏。每人恰检查一次（哈希分组保证），故名单无重复；输出前整体排序保证字典序升序。∎

## 6. 复杂度分析

- **时间**：$O(N \log N)$。分组 $O(N)$；组内排序合计不超过 $O(N \log N)$（各组排序之和 $\le$ 全体排序量级）；每组的窗口扫描合计 $O(N)$；最终名单排序 $O(U \log U)$，$U \le N$。
- **空间**：$O(N)$。哈希表存全部记录（分钟数），答案列表 $O(U)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> alertNames(vector<string>& keyName, vector<string>& keyTime) {
        unordered_map<string, vector<int>> by;      // 姓名 -> 该人所有刷卡分钟数
        for (size_t i = 0; i < keyName.size(); ++i) {
            const string& ts = keyTime[i];
            int t = (ts[0] - '0') * 600 + (ts[1] - '0') * 60
                  + (ts[3] - '0') * 10 + (ts[4] - '0');
            by[keyName[i]].push_back(t);
        }
        vector<string> ans;
        for (auto& kv : by) {
            vector<int>& ts = kv.second;
            sort(ts.begin(), ts.end());
            for (size_t i = 0; i + 2 < ts.size(); ++i) {
                if (ts[i + 2] - ts[i] <= 60) {       // 连续三次刷卡落在 60 分钟内（含端点）
                    ans.push_back(kv.first);
                    break;
                }
            }
        }
        sort(ans.begin(), ans.end());               // 字典序升序
        return ans;
    }
};
```

### Python

```python
class Solution:
    def alertNames(self, keyName: list[str], keyTime: list[str]) -> list[str]:
        by = {}                                      # 姓名 -> 该人所有刷卡分钟数
        for name, ts in zip(keyName, keyTime):
            h, m = ts.split(":")
            by.setdefault(name, []).append(int(h) * 60 + int(m))
        ans = []
        for name, ts in by.items():
            ts.sort()
            if any(ts[i + 2] - ts[i] <= 60 for i in range(len(ts) - 2)):
                ans.append(name)                     # 连续三次刷卡落在 60 分钟内（含端点）
        ans.sort()                                   # 字典序升序
        return ans
```

> 💡 两份代码均通过全部 2 个官方示例（`["daniel"]`、`["bob"]`）以及与**「枚举全部三元组」暴力**的 800 组随机对拍（5 名员工、每轮最多 18 条记录、随机时间），`mismatch = 0`。

## 8. 边界情况与易错点

1. **60 分钟含端点**：`"10:00"-"11:00"` 算，判据是 $\le 60$ 而非 $< 60$。题面把这条写在了正文，读题不细是最常见失分点。
2. **刷卡不足三次的员工**：循环条件 `i + 2 < ts.size()` 天然跳过（含 `size() < 3` 时根本不进循环）。
3. **时间解析**：`"HH:MM"` 逐字符转数字；若直接对字符串 `sort`，同一天内补零的 `HH` 字典序恰好与时间序一致——能过但不推荐，跨天/缺零即翻车，数值化是更稳的通用习惯。
4. **同一个员工多次出现在名单**：分组检查、命中即 `break`，每人至多进名单一次；若按原始记录收集名单再排序会出重复。
5. **输出顺序**：必须是字典序升序；C++ `sort` 与 Python `sort` 对字符串均按字典序，无需自定义比较器。
6. **不需要跨天处理**：题面限定「某一天内」；若放宽为多天，需要先把时间戳化为全局时刻（加日期偏移），窗口逻辑不变。
