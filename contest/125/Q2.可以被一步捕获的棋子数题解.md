# LeetCode 可以被一步捕获的棋子数 题解

## 1. 题目概述

- **标题 / 题号**：可以被一步捕获的棋子数（#999，easy）
- **链接**：https://leetcode.cn/problems/available-captures-for-rook/
- **来源**：LeetCode 第 125 场周赛 Q2
- **难度**：简单
- **标签**：数组、矩阵、模拟

**题意**：给定 $8 \times 8$ 棋盘，只有一个白车 `'R'`，还可能有白象 `'B'` 与黑卒 `'p'`，空格用 `'.'` 表示。车可以向上下左右移动任意格，直到遇到棋子或棋盘边界；若能在一次移动中移动到某个棋子的格子，就能**吃掉**它。但车**不能穿过**其它棋子。返回车能一步吃掉的卒的数量。

**约束**：

- `board.length == 8`，`board[i].length == 8`
- 格子上只可能是 `'R'`、`'.'`、`'B'`、`'p'`
- 有且仅有一个 `'R'`

> 💡 车一次移动只能沿一条直线走到底，所以每个方向上**只有第一个棋子**可能被吃：它是卒就能吃，是象就被挡住。

## 2. 示例

**示例 1**

```text
输入：车在 (2,3)，四个方向上的第一个棋子都是卒
输出：3
解释：本例中车能吃掉全部三个卒（有一个方向没有卒）。
```

**示例 2**

```text
输入：车被白象包围成一圈
输出：0
解释：四个方向的第一个棋子都是象，车一个卒也吃不到。
```

**示例 3**

```text
输入：p 分布在 (1,3)、(2,3)、(3,0)、(3,1)、(3,5)、(6,3)，B 在 (3,6)、(5,3)，R 在 (3,3)
输出：3
解释：向上吃到 (2,3) 的卒、向左吃到 (3,1) 的卒、向右吃到 (3,5) 的卒；
     向下先遇到 (5,3) 的象，被挡住。
```

## 3. 解题思路

### 3.1 暴力思路

对车所在的行与列上的每一个卒，判断「车与它之间是否没有其它棋子」。这种写法需要为每个卒重新扫一遍区间，逻辑上等价但更容易出错（示例 3 里 (6,3) 的卒与车之间隔着象，必须排除）。更糟的是要处理「卒在车左边/右边」两方向的坐标大小关系。

### 3.2 核心观察：四个方向各扫一次，遇到第一个棋子就停

![四个方向各扫一次](images/wc125_q2_four_directions.svg)

车的一次移动是「沿直线走到撞上东西为止」，所以每个方向上**只有最近的棋子**与本次移动有关：

- 最近的棋子是 `'p'` → 可以吃掉，计数加一；
- 最近的棋子是 `'B'` → 被挡住，这个方向贡献 0；
- 一直走到边界都没有棋子 → 这个方向贡献 0。

于是只需从车的位置出发，沿四个方向逐格前进，遇到非空格就判定并终止。

### 3.3 算法流程

```text
1. 扫描棋盘找到 'R' 的坐标 (R, C)
2. ans = 0
3. for (dr, dc) in ((1,0), (-1,0), (0,1), (0,-1)):
       r, c = R + dr, C + dc
       while 0 <= r < 8 且 0 <= c < 8:
           若 board[r][c] == 'p': ans += 1; break
           若 board[r][c] != '.':  break
           r += dr; c += dc
4. 返回 ans
```

注意两个 `break` 的位置：吃到卒后必须立刻停（不能继续往后数），遇到象也必须立刻停（不能穿过去）。

### 3.4 示例演算

![示例 3 的四个方向](images/wc125_q2_walkthrough.svg)

对示例 3（车在 $(3,3)$）：

| 方向 | 沿途 | 第一个棋子 | 结果 |
|------|------|------------|------|
| 上 | $(2,3)$ | `'p'` | 吃，计 1 |
| 下 | $(4,3)$ 空，$(5,3)$ | `'B'` | 被挡，计 0 |
| 左 | $(3,2)$ 空，$(3,1)$ | `'p'` | 吃，计 1 |
| 右 | $(3,4)$ 空，$(3,5)$ | `'p'` | 吃，计 1 |

合计 3，与题面一致。注意 $(1,3)$ 与 $(6,3)$ 的卒分别在「上」「下」方向上被更近的棋子挡住，都吃不到。

## 4. 算法细节

1. **方向数组**：`((1,0),(-1,0),(0,1),(0,-1))` 分别对应下、上、右、左，配合 `while` 循环统一处理四个方向，避免复制四段代码。
2. **越界条件**：`0 <= r < 8` 且 `0 <= c < 8`，循环条件里同时判断，比在循环体内 `break` 更简洁。
3. **终止条件**：`'p'` 与 `'B'` 都要 `break`，只是前者顺手加一。写成「`'p'` 加一但不 break」是本题最常见的错误。
4. **不需要 visited**：每个方向最多走 7 格，不会重复访问。
5. **找车**：全盘扫描一次，$O(64)$；也可以边扫边记，但没必要优化。
6. **只读棋盘**：不修改输入。

## 5. 正确性证明

**引理 1（每个方向至多一个可吃目标）**：固定方向 $d$，车沿 $d$ 移动时遇到的第一个非空格是唯一可能被吃的棋子；若它是 `'B'` 或不存在，则该方向无法吃任何卒。

**证明**：车在 $d$ 方向上的移动必须连续经过空格，一旦遇到棋子就只能停在该棋子所在格（吃掉它）或无法前进。若第一个非空格是 `'B'`，车不能穿过它，它后面的所有棋子都在「被挡住」之外，均不可达；若一路无棋子，则车只到达边界，未遇到任何棋子。故只有第一个非空格可能被吃。∎

**引理 2（扫描正确终止）**：算法对每个方向的 `while` 循环，要么在遇到第一个非空格时终止，要么走到边界终止；终止前访问的格子都符合「从车出发沿 $d$ 连续、未跨越任何棋子」。

**证明**：循环每轮检查 `board[r][c]`：若为 `'p'` 则计数并 `break`；若不为 `'.'` 则 `break`；否则前进一格。因此循环只在「非空格」或「越界」时停止，而此前所有格子均为 `'.'`，正是连续空格。∎

**定理**：算法返回的 `ans` 等于车一步能吃的卒的数量。

**证明**：车的一步移动对应选择四个方向之一并走到第一个非空格（或不走）。由引理 1，每个方向至多贡献 1 个可吃卒，且仅当第一个非空格是 `'p'` 时贡献 1。由引理 2，算法的扫描恰好定位到该第一个非空格（若存在），并在其为 `'p'` 时计数、否则不计。四个方向互相独立、互不重叠（车一次只能走一条直线），故总计数等于可吃卒数。∎

## 6. 复杂度分析

- **时间**：$O(1)$。找车需扫 $8 \times 8 = 64$ 格；四个方向各至多走 7 格，共 28 格。棋盘尺寸固定，可视为常数。
- **空间**：$O(1)$。只用几个坐标变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numRookCaptures(vector<vector<char>>& board) {
        int R = 0, C = 0;
        for (int i = 0; i < 8; i++) {
            for (int j = 0; j < 8; j++) {
                if (board[i][j] == 'R') {
                    R = i;
                    C = j;
                }
            }
        }
        int ans = 0;
        const int dr[4] = {1, -1, 0, 0};
        const int dc[4] = {0, 0, 1, -1};
        for (int d = 0; d < 4; d++) {
            int r = R + dr[d], c = C + dc[d];
            while (r >= 0 && r < 8 && c >= 0 && c < 8) {
                if (board[r][c] == 'p') {
                    ans++;
                    break;
                }
                if (board[r][c] != '.') break;
                r += dr[d];
                c += dc[d];
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numRookCaptures(self, board: list[list[str]]) -> int:
        R = C = 0
        for i in range(8):
            for j in range(8):
                if board[i][j] == 'R':
                    R, C = i, j
        ans = 0
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            r, c = R + dr, C + dc
            while 0 <= r < 8 and 0 <= c < 8:
                if board[r][c] == 'p':
                    ans += 1
                    break
                if board[r][c] != '.':
                    break
                r += dr
                c += dc
        return ans
```

## 8. 边界情况与易错点

1. **吃完不 break**：会越过卒继续扫，把被它挡住的第二个卒也算进去，答案偏大。
2. **遇象不 break**：会「穿过」象数到后面的卒（示例 3 的下方向）。
3. **方向数组顺序**：四个方向不能重复也不能遗漏；`(1,0)` 是「行号加一」，即向**下**，别写反。
4. **边界判定**：`while` 条件同时判行与列，漏一个会越界访问。
5. **车在角落/边缘**：如 $(0,0)$，向上与向左一出发就越界，循环立即结束，贡献 0。
6. **没有卒**：返回 0（示例 2）。
7. **象紧邻车**：四个方向都被象围住时返回 0，注意此时「最近的棋子是象」而不是「没有棋子」。
8. **棋盘固定 8×8**：不要写成通用 $m \times n$ 之后又用 8 的硬编码，二者混用容易越界。
