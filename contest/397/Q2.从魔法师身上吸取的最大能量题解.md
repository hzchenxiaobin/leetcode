# LeetCode 从魔法师身上吸取的最大能量 题解

## 1. 题目概述

- **标题 / 题号**：从魔法师身上吸取的最大能量（#3147，medium）
- **链接**：https://leetcode.cn/problems/taking-maximum-energy-from-the-mystic-dungeon/
- **来源**：LeetCode 第 397 场周赛 Q2
- **难度**：中等
- **标签**：数组、动态规划、后缀和

**题意**：$n$ 个魔法师站成一排，$\mathrm{energy}[i]$ 是第 $i$ 位身上的能量，**可正可负**（负数表示他会反过来吸走你的能量）。你被施了诅咒：选定起点 $i$ 后，每吸取一位的能量就被**立即传送**到 $i+k$ 处，如此反复，直到 $i+k$ 越过序列末端。**途中经过的所有能量都必须吸收**——不能拒吸、不能中途退出。求能获得的最大总能量。

**约束**：

- $1 \le n = \mathrm{energy.length} \le 10^5$
- $-1000 \le \mathrm{energy}[i] \le 1000$
- $1 \le k \le n - 1$

> 💡 赛时读题抓三个信号，思路 30 秒内就能定型：① **起点是唯一自由度**——起点定了，路径 $i \to i+k \to i+2k \to \cdots$ 就完全确定，没有任何中途决策；② **必须吸到底**——没有「提前收手」选项，这是它与最大子数组和（Kadane）的本质分野；③ **答案可以是负数**——全负时只能「亏得最少」（示例 2），打擂台初值不能取 $0$。

## 2. 示例

**示例 1**

```text
输入：energy = [5, 2, -10, -5, 1], k = 3
输出：3
解释：从魔法师 1 出发，途经 1 → 4，吸取 2 + 1 = 3。
```

**示例 2**

```text
输入：energy = [-2, -3, -1], k = 2
输出：-1
解释：从魔法师 2 出发，只吸取 -1。全负数组，只能亏得最少。
```

**示例 3**

```text
输入：energy = [-1, 4, 2, 3, -2, 1], k = 2
输出：8
解释：从魔法师 1 出发，途经 1 → 3 → 5，吸取 4 + 3 + 1 = 8。
      若从 0 出发则被迫吸 -1：(-1) + 2 + (-2) = -1，起点选择直接决定盈亏。
```

## 3. 解题思路

### 3.1 暴力思路

对每个起点 $i \in [0, n-1]$，沿链 $i \to i+k \to i+2k \to \cdots$ 一路跳到底累加，取所有起点的最大值。总跳数为

$$\sum_{i=0}^{n-1} \left\lceil \frac{n-i}{k} \right\rceil \approx \frac{n^2}{2k}$$

$k = 1$ 时约 $\frac{n^2}{2} = 5 \times 10^9$（$n = 10^5$），必然超时。浪费点一眼可见：**从 $i$ 出发的收益与从 $i+k$ 出发的收益只差一步**，前者却把后者的整条链重算了一遍——典型的重叠子问题，一次递推就能摊平。

### 3.2 核心观察：模 $k$ 分链 + 后缀和

![核心概念：下标按 mod k 分成 k 条独立链，收益是链上后缀和](images/mystic_energy_chains.svg)

把「诅咒」翻译成结构语言：

1. **分链**：跳跃规则 $i \to i+k$ 把下标按**模 $k$ 同余**划分为 $k$ 条互不相交的链 $r,\ r+k,\ r+2k,\ \cdots$（$0 \le r < k$）。起点 $i$ 的整条路径都落在第 $i \bmod k$ 条链上，链与链之间毫无交集。
2. **无选择**：路径唯一且必须走完，所以「从 $i$ 出发的收益」是一个**确定的数**——就是链上从 $i$ 开始的后缀和，连「要不要继续」都不用讨论。
3. **递推**：定义 $dp[i]$ 为从 $i$ 出发的收益，则

$$dp[i] = \mathrm{energy}[i] + dp[i+k], \qquad i + k \ge n \text{ 时 } dp[i+k] = 0$$

依赖**全部在右侧**，从右往左一趟即可算完，答案是 $\max_i dp[i]$。

> ⚠️ **别顺手套 Kadane**：$dp[i]$ 里没有 $\max(0,\ \cdot)$ 那一项。最大子数组和允许中途丢弃劣质前缀，这里的诅咒强制吸到底——例如 $[5, -10, 1]$、$k=1$：本题从 $0$ 出发只能拿 $5-10+1=-4$（最优是从 $2$ 出发拿 $1$），而「允许中途收手」的版本会拿到 $5$。识别问题**不是**最大子段和，比会写 Kadane 更重要。

### 3.3 算法流程：倒序一趟原地 DP

![算法流程：从右往左一趟，原地 DP 加打擂台](images/mystic_energy_dp_flow.svg)

主循环从 $i = n-1$ 倒序走到 $0$，每个下标做两件事：

1. 若 $i + k < n$：`energy[i] += energy[i+k]`（原地后缀和）；否则保持原值（$i$ 是链尾，$dp[i+k]$ 视为 $0$）。
2. `ans = max(ans, energy[i])` 打擂台。

**原地更新的正确性锚点就一句：依赖在右，遍历向左**——处理 $i$ 时读到的 `energy[i+k]` 必定已被改写为 $dp[i+k]$；若正序遍历，读到的则是未加工的原值，整条递推作废。

### 3.4 示例演算

![示例演算：倒序逐步填出后缀和并打擂台](images/mystic_energy_walkthrough.svg)

以示例 1 $\mathrm{energy} = [5, 2, -10, -5, 1]$、$k = 3$ 为例倒序演算：

| $i$ | 原值 | $i+k$ 情形 | $dp[i]$ | `ans` |
|-----|------|-----------|---------|-------|
| 4 | 1 | $7 \ge 5$，链尾 | 1 | 1 |
| 3 | −5 | $6 \ge 5$，链尾 | −5 | 1 |
| 2 | −10 | $5 \ge 5$，链尾 | −10 | 1 |
| 1 | 2 | $4 < 5$，取 $dp[4]$ | $2 + 1 = 3$ | **3** |
| 0 | 5 | $3 < 5$，取 $dp[3]$ | $5 + (-5) = 0$ | 3 |

最终 $dp = [0, 3, -10, -5, 1]$，答案 $3$，与示例一致。✓ 示例 2 全负时，三个链尾 $-2, -3, -1$ 中取最优的 $-1$——印证了答案可为负。

## 4. 算法细节

1. **边界即链尾**：$dp[i+k] = 0$ 的条件写成 `i + k < n`，恰好覆盖 $i \in [n-k, n-1]$ 的 $k$ 个位置——每条链恰有一个链尾落在其中。
2. **原地 vs 开数组**：倒序遍历下，被读的 `energy[i+k]` 永远是已算好的 $dp$ 值，输入数组自己就是 dp 数组，空间 $O(1)$。若不希望破坏输入，可开 $O(n)$ 的 dp 数组照抄递推；更进一步可用 $O(k)$ 滚动数组：倒序执行 `suf[i % k] += energy[i]`，`suf[r]` 始终持有链 $r$ 当前起点的后缀和。
3. **按链实现的等价写法**：赛场上也有人对每条链单独处理——$r$ 从 $0$ 到 $k-1$，沿 $r, r+k, r+2k, \cdots$ 从链尾向前累加后缀和。与倒序一趟的多循环写法完全等价，但倒序单循环最短、最快写完，适合 Q2 的抢速度定位。
4. **打擂台两趟化**：循环里只做累加、最后 `max(energy)` / `*max_element` 整体取最大，可省掉 `ans` 初值的心智负担——因为 `max` 作用在非空数组上，天然规避「初值取 $0$」的陷阱。

## 5. 正确性证明

**引理 1（路径确定性）**：从起点 $i$ 出发，经过的位置恰为 $i,\ i+k,\ \cdots,\ i+mk$，其中 $m = \max \{\, j \ge 0 : i + jk \le n-1 \,\}$，且总收益为 $\sum_{j=0}^{m} \mathrm{energy}[i+jk]$。

**证明**：对步数归纳。第 $0$ 步位于 $i$；设第 $j$ 步位于 $i + jk \le n-1$，则传送规则给出第 $j+1$ 步位置 $i + (j+1)k$，当且仅当 $i + (j+1)k \ge n$ 时过程终止于第 $j$ 步。故经过的位置集合唯一确定，收益即沿途各项之和。∎

**引理 2（递推正确性）**：倒序遍历结束后，`energy[i]` 的值恰为 $dp[i] = \sum_{j \ge 0,\ i+jk \le n-1} \mathrm{energy}[i+jk]$（右端对原值求和）。

**证明**：对 $i$ 从 $n-1$ 到 $0$ 下行归纳。基例 $i \in [n-k, n-1]$：$i + k \ge n$，算法不修改该位置，$dp[i] = \mathrm{energy}[i]$，即链上仅含自身的后缀和。归纳步：设对所有 $i' > i$ 结论成立。处理 $i$ 时若 $i + k \ge n$ 同基例；若 $i + k < n$，因 $i + k > i$，此时 `energy[i+k]` 已等于 $dp[i+k]$（归纳假设），算法执行 `energy[i] += energy[i+k]` 后该位置的值为 $\mathrm{energy}[i] + dp[i+k]$，展开恰为链上从 $i$ 起的原值之和。∎

**定理**：算法返回题意所求的最大总能量。

**证明**：可行策略集恰为 $n$ 个起点（引理 1，每个起点对应唯一确定的收益）。由引理 2，倒序一趟后 `energy[i]` 即从 $i$ 出发的收益，循环中 `ans` 对每个 $i$ 恰执行一次 `max(ans, energy[i])` 且初值为 $-\infty$，故返回值为 $\max_{0 \le i \le n-1} dp[i]$，即所有可行策略收益的最大值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。倒序一趟，每个下标一次加法、一次比较，均为 $O(1)$。
- **空间复杂度**：$O(1)$ 额外空间（原地改写输入数组为 dp 数组）；不修改输入则为 $O(n)$（dp 数组）或 $O(k)$（按余数分桶滚动）。
- **值域安全**：链长至多 $\lceil n/k \rceil \le 10^5$，每项绝对值 $\le 1000$，故 $|dp| \le 10^8 < 2^{31} - 1 \approx 2.1 \times 10^9$，`int` 不溢出。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumEnergy(vector<int>& energy, int k) {
        int n = energy.size(), ans = INT_MIN;
        for (int i = n - 1; i >= 0; --i) {
            if (i + k < n) {
                energy[i] += energy[i + k];
            }
            ans = max(ans, energy[i]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumEnergy(self, energy: List[int], k: int) -> int:
        n = len(energy)
        for i in range(n - 1, -1, -1):
            if i + k < n:
                energy[i] += energy[i + k]
        return max(energy)
```

## 8. 边界情况与易错点

1. **`ans` 初始化为 0**：全负数组（示例 2）答案为负，初值取 $0$ 会错输出 $0$。用 $-\infty$（`INT_MIN` / `float("-inf")`），或干脆两趟化：只累加、最后对非空数组整体取 `max`。
2. **正序遍历**：$dp[i]$ 依赖 $dp[i+k]$（更靠右），正序会读到未加工的原值；必须倒序，这是原地更新的正确性前提（正确性证明引理 2）。
3. **边界条件写错**：应是 `i + k < n`；若误写成 `i + k <= n`，则 $i + k = n$ 时会越界访问 `energy[n]`。
4. **误套 Kadane**：加上 $\max(0, dp[i+k])$ 意味着允许「提前收手」，但诅咒强制吸到底。反例 $[5, -10, 1]$、$k=1$：正确答案 $1$，Kadane 版本错得 $5$。
5. **溢出评估**：$|dp| \le 10^8$，`int` 安全；无需 `long long`，但主动报出这个估算过程是加分习惯。
6. **依赖 $k \le n-1$ 的保证**：$n \ge 2$ 恒成立，且链长至少为 $1$；若题目变体允许 $k \ge n$，则每个位置都是链尾，答案退化为 $\max(\mathrm{energy})$，本算法无需任何修改即可覆盖。
7. **链尾无需特判清零**：$dp[i+k] = 0$ 通过「不执行加法」隐式实现，不要真去读一个虚拟的 $0$ 号位置。
