# LeetCode 两个字符串的排列差 题解

## 1. 题目概述

- **标题 / 题号**：两个字符串的排列差（#3146，easy）
- **链接**：https://leetcode.cn/problems/permutation-difference-between-two-strings/
- **来源**：LeetCode 第 397 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串

**题意**：给定两个字符串 $s$ 和 $t$，二者中的字符**互不重复**，且 $t$ 是 $s$ 的一个**排列**。定义**排列差**为 $s$ 和 $t$ 中每个字符在两个字符串中**位置的绝对差值之和**，即 $\sum_{c} \lvert \mathrm{pos}_s(c) - \mathrm{pos}_t(c) \rvert$。返回 $s$ 与 $t$ 之间的排列差。

**约束**：

- $1 \le s.\mathrm{length} \le 26$
- 每个字符在 $s$ 中最多出现一次
- $t$ 是 $s$ 的一个排列
- $s$ 仅由小写英文字母组成

> 💡 签到题的关键信号：**字符互不重复** + **排列**。这意味着每个字符在两个串中的位置都**唯一确定**，一张"字符 → 位置"的表就能把问题变成两次线性扫描。

## 2. 示例

**示例 1**

```text
输入：s = "abc", t = "bac"
输出：2
解释：排列差 = |0-1| + |1-0| + |2-2| = 1 + 1 + 0 = 2。
      'a' 在 s 的 0 位、t 的 1 位；'b' 在 s 的 1 位、t 的 0 位；'c' 两边都在 2 位。
```

**示例 2**

```text
输入：s = "abcde", t = "edbac"
输出：12
解释：排列差 = |0-3| + |1-2| + |2-4| + |3-1| + |4-0| = 3 + 1 + 2 + 2 + 4 = 12。
```

**示例 3**

```text
输入：s = "a", t = "a"
输出：0
解释：单个字符两边位置相同，差值为 0。
```

## 3. 解题思路

### 3.1 暴力思路

对 $s$ 中的每个字符 $s_i$，从头到尾扫描 $t$ 找到它的位置 $j$，累加 $|i - j|$。时间复杂度 $O(n^2)$。

由于 $n \le 26$，$O(n^2)$ 至多 $26^2 = 676$ 次操作，比赛时直接这样写也能过。但每次线性查找是重复劳动——同一个字符的位置被反复搜索，这正是**哈希表**要解决的场景。

### 3.2 核心观察：字符 → 位置的映射唯一

![字符到位置的映射：两趟扫描求排列差](images/perm_diff_position_map.svg)

**关键性质**：$s$ 中字符互不重复，且 $t$ 是 $s$ 的排列，因此：

1. 每个字符在 $t$ 中的位置**唯一**——遍历 $t$ 一遍，用数组/哈希表记录 $\mathrm{pos}[c] = i$，之后任意字符 $O(1)$ 查到位置；
2. 遍历 $s$ 时，下标 $i$ 天然就是 $\mathrm{pos}_s(s_i)$，无需再存一张表。

于是答案就是：

$$\mathrm{ans} = \sum_{i=0}^{n-1} \bigl\lvert\, i - \mathrm{pos}[s_i] \,\bigr\rvert$$

### 3.3 算法流程

1. **建表**：遍历 $t$，对每个下标 $j$ 记录 $\mathrm{pos}[t_j] = j$（长度 26 的数组即可）。
2. **累加**：遍历 $s$，对每个下标 $i$ 执行 $\mathrm{ans} \mathrel{+}= \lvert i - \mathrm{pos}[s_i] \rvert$。
3. 返回 $\mathrm{ans}$。

由于 $t$ 是 $s$ 的排列，步骤 2 中查表**必然命中**，无需判空。

### 3.4 示例演算

![示例 abcde 与 edbac 的逐步演算表](images/perm_diff_walkthrough.svg)

以 $s = $ `"abcde"`、$t = $ `"edbac"` 为例，先扫 $t$ 建表：$e \to 0,\ d \to 1,\ b \to 2,\ a \to 3,\ c \to 4$；再扫 $s$ 逐位累加：

| $s_i$ | $\mathrm{pos}_s$（下标 $i$） | $\mathrm{pos}_t$（查表） | $|i - \mathrm{pos}_t|$ | 累计 |
|-------|------|------|------|------|
| a | 0 | 3 | 3 | 3 |
| b | 1 | 2 | 1 | 4 |
| c | 2 | 4 | 2 | 6 |
| d | 3 | 1 | 2 | 8 |
| e | 4 | 0 | 4 | 12 |

最终答案 $12$，与示例一致。✓

## 4. 算法细节

1. **用长度 26 的数组代替哈希表**：字符集仅小写字母，`pos[c - 'a']` 比 `unordered_map` 更快且无哈希开销；Python 中用长度 26 的 `list` 或直接 `dict` 均可（$n \le 26$ 量级下无差别）。
2. **只需为 $t$ 建表**：$s$ 的下标本身就是位置，两边建表是多余的一半工作。
3. **对称性**：反过来先扫 $s$ 建表、再扫 $t$ 累加，结果相同（绝对差对称）。
4. **下标从 0 开始**：题面中的位置即 0 下标，直接用 `enumerate` / 循环变量即可，不要 +1。

## 5. 正确性证明

**引理 1**：对每个字符 $c \in s$，$\mathrm{pos}_t(c)$ 被第一趟遍历正确记录。

**证明**：$t$ 中字符互不重复，故 $c$ 在 $t$ 中恰出现一次，设其唯一出现位置为 $j$。遍历 $t$ 到下标 $j$ 时执行 $\mathrm{pos}[t_j] = j$，且其余下标的写入对象均非 $c$，故最终 $\mathrm{pos}[c] = j$。∎

**引理 2**：第二趟遍历中每次查表必然命中，且累加项恰为该字符的绝对位置差。

**证明**：$t$ 是 $s$ 的排列，故 $s$ 中每个字符都在 $t$ 中出现，由引理 1 其表项已被写入，查表命中。遍历 $s$ 至下标 $i$ 时，$i = \mathrm{pos}_s(s_i)$（字符在 $s$ 中唯一），累加项 $|i - \mathrm{pos}[s_i]| = |\mathrm{pos}_s(s_i) - \mathrm{pos}_t(s_i)|$。∎

**定理**：算法返回 $s$ 与 $t$ 的排列差。

**证明**：$s$ 中字符互不重复，第二趟遍历对每个字符恰好累加一次；由引理 2，各累加项与定义中 $\sum_c |\mathrm{pos}_s(c) - \mathrm{pos}_t(c)|$ 的各项一一对应相等，故总和即排列差。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n = |s| = |t|$。两趟遍历，每趟每字符 $O(1)$（数组直接寻址）。由 $n \le 26$，亦可视为 $O(|\Sigma|) = O(26)$ 的常数级。
- **空间复杂度**：$O(|\Sigma|) = O(26)$，即位置数组，与 $n$ 无关，视为 $O(1)$。

> 💡 相比暴力 $O(n^2)$，哈希表把"查找位置"从 $O(n)$ 降到 $O(1)$——这是所有"计数/定位"类签到题的通用套路。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findPermutationDifference(string s, string t) {
        int pos[26];
        for (int j = 0; j < (int)t.size(); ++j) {
            pos[t[j] - 'a'] = j;
        }
        int ans = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            ans += abs(i - pos[s[i] - 'a']);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findPermutationDifference(self, s: str, t: str) -> int:
        pos = {c: j for j, c in enumerate(t)}
        return sum(abs(i - pos[c]) for i, c in enumerate(s))
```

## 8. 边界情况与易错点

1. **$n = 1$**：$s = t$（单字符），答案为 $0$，两趟扫描自然覆盖，无需特判。
2. **$s = t$**：所有字符位置相同，答案为 $0$，同样无需特判。
3. **误用一维计数**：若误把"排列"当成只需比较字符集合（如计数数组比对），会丢掉位置信息——本题求的是**位置差的绝对值之和**，不是判断是否为排列。
4. **重复建表 / 建错方向**：只需为 $t$ 建表；若为两边都建再求和，结果虽对但浪费一半工作。反过来为 $s$ 建表、扫 $t$ 累加也对（对称性）。
5. **溢出**：最大答案出现在 $t$ 为 $s$ 反转且 $n = 26$ 时，为 $2 \times (1 + 2 + \dots + 13) = 182$，`int` 绰绰有余。
6. **依赖题设保证**：查表不判空依赖"$t$ 是 $s$ 的排列"这一保证；若去掉该保证（变体题），需处理缺键情况。
