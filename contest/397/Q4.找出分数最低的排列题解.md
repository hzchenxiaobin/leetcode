# LeetCode 找出分数最低的排列 题解

## 1. 题目概述

- **标题 / 题号**：找出分数最低的排列（#3149，hard）
- **链接**：https://leetcode.cn/problems/find-the-minimum-cost-array-permutation/
- **来源**：LeetCode 第 397 场周赛 Q4
- **难度**：困难
- **标签**：状态压缩 DP、位运算、贪心、哈密顿环（TSP 型）

**题意**：给定 $[0, 1, 2, \ldots, n-1]$ 的一个排列 `nums`。对于任意排列 `perm`，其分数定义为

$$\mathrm{score}(\mathrm{perm}) = \sum_{i=0}^{n-1} \bigl|\mathrm{perm}[i] - \mathrm{nums}[\mathrm{perm}[(i+1) \bmod n]]\bigr|$$

即「环形相邻对」代价之和。返回分数**最低**的排列；若有多个分数相同的排列，返回其中**字典序最小**的一个。

**约束**：

- `2 <= n == nums.length <= 14`
- `nums` 是 $[0, 1, 2, \ldots, n-1]$ 的一个排列

## 2. 示例

**示例 1**

```text
输入：nums = [1,0,2]
输出：[0,1,2]
解释：分数为 |0 − nums[1]| + |1 − nums[2]| + |2 − nums[0]| = |0−0| + |1−2| + |2−1| = 2。
```

**示例 2**

```text
输入：nums = [0,2,1]
输出：[0,2,1]
解释：分数为 |0 − nums[2]| + |2 − nums[1]| + |1 − nums[0]| = |0−1| + |2−2| + |1−0| = 2。
注意 [0,1,2] 的分数是 |0−2| + |1−1| + |2−0| = 4，并非最低分，故答案不是 [0,1,2]。
```

## 3. 解题思路

### 3.1 暴力思路：枚举全排列

最直接的做法是枚举 $[0, n-1]$ 的所有 $n!$ 个排列，逐个算分数取最小、再在并列者中取字典序最小。$n = 14$ 时 $14! \approx 8.7 \times 10^{10}$，即使每个排列只花 $O(n)$ 计算也远超时限，必须压缩状态空间。

### 3.2 核心观察一：分数是环形的，旋转不变 → 固定 perm[0] = 0

分数只与**环形相邻对** $(\mathrm{perm}[i], \mathrm{perm}[(i+1) \bmod n])$ 的集合有关。把排列整体旋转（循环移位），每个环形相邻对保持不变，只是求和顺序被重排，因此**分数不变**。

于是：任何最低分排列都可以旋转成以 $0$ 开头的排列，且分数不增不减；而所有 $[0, \ldots]$ 形排列的字典序**严格小于**任何 $[k, \ldots]$（$k > 0$）形排列（首位即分出大小）。两条结合可知：**字典序最小的最低分排列一定以 $0$ 开头**。

> 💡 这一步把「在 $n!$ 个排列中选」直接砍成「固定首位为 0，在后 $n-1$ 个位置上安排剩余数字」，也为下面的状压 DP 提供了固定起点。

![环形分数旋转不变，固定首位为 0](images/min_cost_perm_rotation.svg)

### 3.3 核心观察二：固定起点后是哈密顿环最小权 → 状压 DP

固定 $\mathrm{perm}[0] = 0$ 后，排列变成「**从 0 出发，每个数恰好经过一次的路径**，最后再加一条闭环边回到 0」——这正是带权**哈密顿环**（TSP 型）问题。TSP 型问题在 $n \le 14$ 时恰好落在状压 DP 的可行边界上：

- **状态**：$(\mathrm{mask}, \mathrm{last})$ —— 已放置的数字集合 $\mathrm{mask}$（必含 $0$）、当前排列末端为 $\mathrm{last}$。
- **转移**：从末端 $\mathrm{last}$ 接一个尚未放置的数 $x \notin \mathrm{mask}$，产生边权 $|\mathrm{last} - \mathrm{nums}[x]|$。
- **闭环**：全部放完后，末端 $\mathrm{last}$ 再付一条 $|\mathrm{last} - \mathrm{nums}[0]|$ 的闭环代价。

为了方便后面「字典序最小」的贪心重构，本文采用**后缀式**定义：

$$g(\mathrm{mask}, \mathrm{last}) = \min_{x \notin \mathrm{mask}} \Bigl( \bigl|\mathrm{last} - \mathrm{nums}[x]\bigr| + g(\mathrm{mask} \cup \{x\},\ x) \Bigr)$$

终态为 $g(\text{全集}, \mathrm{last}) = |\mathrm{last} - \mathrm{nums}[0]|$，最低分为 $g(\{0\}, 0)$。

> 💡 「后缀式」的含义：$g$ 回答的是「从当前局面出发，**还能**产生的最小代价」，它天然就是重构方案时的可行性判据。

![状压 DP 状态模型与转移方程](images/min_cost_perm_dp_model.svg)

### 3.4 字典序最小：先求最低分，再逐位贪心重构

求出最低分 $\mathrm{minScore} = g(\{0\}, 0)$ 后，从初始局面 $(\mathrm{mask}=\{0\}, \mathrm{last}=0)$、剩余目标 $\mathrm{rem} = \mathrm{minScore}$ 出发，**逐位**构造排列：

1. 每个位置把候选数 $x$ 从小到大依次尝试；
2. 若 $|\mathrm{last} - \mathrm{nums}[x]| + g(\mathrm{mask} \cup \{x\},\ x) = \mathrm{rem}$，说明选 $x$ 后仍能恰好凑出最低分——立即选定 $x$，令 $\mathrm{rem} \mathrel{-}= |\mathrm{last} - \mathrm{nums}[x]|$，进入下一位置；
3. 被跳过的 $x$ 都满足边权加后缀代价**严格大于** $\mathrm{rem}$，即任何以其延伸的排列分数都超过最低分，绝无冤枉。

由于每一步都选中了「能保持最优性的最小数字」，构造出的正是字典序最小的最低分排列。

## 4. 算法细节

1. **记忆化方向**：用「后缀式」$g(\mathrm{mask}, \mathrm{last})$ 而非「前缀式」DP。前缀式 $f(\mathrm{mask}, \mathrm{last})$（起点 0 到末端 last 的最小边权和）也能求最低分（答案为 $\min_{\mathrm{last}} f(\text{全集}, \mathrm{last}) + |\mathrm{last} - \mathrm{nums}[0]|$），但重构字典序最小方案时需要反复询问「从当前前缀出发能否达到目标」，后缀式的 $g$ 值恰好就是这个判据。
2. **终态预填**：先把所有 $g(\text{全集}, x) = |x - \mathrm{nums}[0]|$ 预填进表，再从 $(\{0\}, 0)$ 开始记忆化搜索。若在递归里对 `mask == full` 直接 `return` 而不落表，重构最后一位时会读到未计算的哨兵值，导致选不出最后一个数（这是本题最容易踩的坑，详见 §8）。
3. **重构时的可达性**：记忆化搜索从 $(\{0\}, 0)$ 出发，会访问**所有**满足 $0 \in \mathrm{mask}$、$\mathrm{last} \in \mathrm{mask}$ 的状态；重构过程中查询的每个 $(\mathrm{mask} \cup \{x\},\ x)$ 都是这种状态，因此其 $g$ 值必然已算好，无需再判「是否已计算」。
4. **重构不变量**：重构全程恒有 $\mathrm{rem} = g(\mathrm{mask}, \mathrm{last})$（初始显然；每次选中 $x$ 后 $\mathrm{rem}' = \mathrm{rem} - c = g(\mathrm{mask} \cup \{x\}, x)$）。由 $g$ 的定义 $g(\mathrm{mask}, \mathrm{last}) = \min_x (c_x + g_{\text{new}})$，对任何候选 $x$ 都有 $c_x + g_{\text{new}} \ge \mathrm{rem}$，故等式判定 `== rem` 精确区分「最优延续」与「必然超分」。
5. **位运算实现**：$\mathrm{mask} \cup \{x\}$ 写作 `mask | 1 << x`，判断 $x \notin \mathrm{mask}$ 写作 `mask >> x & 1 == 0`；全集为 `(1 << n) - 1`。

## 5. 正确性证明

**引理 1（旋转不变性）**：设排列 $P$ 循环左移一位得 $P'$，则 $\mathrm{score}(P) = \mathrm{score}(P')$。

**证明**：$\mathrm{score}(P) = \sum_i \bigl|P_i - \mathrm{nums}[P_{(i+1) \bmod n}]\bigr|$ 是对下标 $i$ 在 $\mathbb{Z}_n$ 上的求和。左移对应下标重命名 $j = i - 1 \pmod n$，每条环形相邻对 $(P_i, P_{(i+1) \bmod n})$ 与 $(P'_{j}, P'_{(j+1) \bmod n})$ 一一对应，逐项相等，故和相等。对旋转任意多位同理。∎

**引理 2（首位为 0）**：字典序最小的最低分排列 $Q$ 必满足 $Q_0 = 0$。

**证明**：取任意一个最低分排列 $P$，由引理 1 可将其旋转为 $0$ 在首位的 $P'$，$P'$ 仍是最低分。若 $Q_0 = k > 0$，则 $P'_0 = 0 < k = Q_0$，首项已分出 $P' < Q$（字典序），与 $Q$「字典序最小的最低分排列」矛盾。∎

**定理 1（DP 最优性）**：$g(\{0\}, 0)$ 等于全体排列的最低分。

**证明**：对未放置数个数 $m = n - |\mathrm{mask}|$ 归纳。$m = 0$ 时状态 $(\text{全集}, \mathrm{last})$ 只剩闭环边，$g = |\mathrm{last} - \mathrm{nums}[0]|$，正确。$m > 0$ 时，任何从 $(\mathrm{mask}, \mathrm{last})$ 出发的完整方案都由「选某个 $x \notin \mathrm{mask}$、付出边权 $c_x = |\mathrm{last} - \mathrm{nums}[x]|$、再从 $(\mathrm{mask} \cup \{x\}, x)$ 继续并最终闭环」构成，其总代价为 $c_x + (\text{后续 + 闭环代价}) \ge c_x + g(\mathrm{mask} \cup \{x\}, x) \ge \min_x \bigl(c_x + g(\mathrm{mask} \cup \{x\}, x)\bigr)$，且该下界在 $x$ 取到最小值、后续按最优方案进行时可以达到，故 $g$ 的递推式成立。$g(\{0\}, 0)$ 的决策树恰好与「以 $0$ 开头的全部排列」一一对应，由引理 2，字典序最小的最低分排列以 $0$ 开头，故 $g(\{0\}, 0)$ 即为所求最低分。∎

**定理 2（贪心重构正确性）**：逐位贪心构造的排列是字典序最小的最低分排列。

**证明**：记 $S_i$ 为贪心进行到第 $i$ 位时的前缀（含局面 $(\mathrm{mask}_i, \mathrm{last}_i)$ 与剩余目标 $\mathrm{rem}_i$），由 §4.4 的不变量 $\mathrm{rem}_i = g(\mathrm{mask}_i, \mathrm{last}_i)$。称前缀**可行**指存在补全使总分为最低分。对 $i$ 归纳证明：**(a)** $S_i$ 可行；**(b)** $S_i$ 是所有可行长度 $i$ 前缀中字典序最小者。

- $i = 1$：$S_1 = (0)$，由定理 1 可行；且由引理 2，可行前缀必以 $0$ 开头，故 (b) 成立。
- 归纳步：对候选 $x$，补全后总分 $\ge \text{已积累} + c_x + g(\mathrm{mask}_i \cup \{x\}, x)$，且存在补全恰取到 $g$（$g$ 的最小值可达，见定理 1）。故 $S_i + x$ 可行 $\iff c_x + g(\mathrm{mask}_i \cup \{x\}, x) = \mathrm{rem}_i$。贪心选中的 $x^*$ 是满足该等式的最小 $x$：所有更小的 $\tilde{x}$ 均不可行，故任何可行排列都无法以 $S_i$ 加更小的数字开头，(b) 保持；$x^*$ 自身可行，(a) 保持。∎

综上，算法返回的排列分数为最低分，且在所有最低分排列中字典序最小。

## 6. 复杂度分析

- **时间复杂度**：$O(2^n \cdot n^2)$。状态 $(\mathrm{mask}, \mathrm{last})$ 共 $2^n \cdot n$ 个，每个状态的转移枚举 $n$ 个候选 $x$；记忆化保证每个状态只算一次。$n = 14$ 时约 $16384 \times 14 \times 14 \approx 3.2 \times 10^6$，重构阶段每位枚举候选也是 $O(2^n \cdot n^2)$ 量级内，整体轻松通过。
- **空间复杂度**：$O(2^n \cdot n)$。记忆化表 $g$ 占 $2^14 \times 14 \approx 2.3 \times 10^5$ 个整数（约 1 MB），另需 $O(n)$ 的答案数组与递归栈（深度 $\le n$）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> findPermutation(vector<int>& nums) {
        int n = nums.size();
        int full = (1 << n) - 1;
        // g[mask][last]：已放集合 mask（含 0 与 last）、末端 last，
        // 放完剩余数并闭环的最小代价；-1 表示未计算
        vector<vector<int>> g(1 << n, vector<int>(n, -1));
        for (int x = 0; x < n; x++) g[full][x] = abs(x - nums[0]);  // 终态预填
        function<int(int, int)> go = [&](int mask, int last) -> int {
            int& res = g[mask][last];
            if (res != -1) return res;
            res = INT_MAX;
            for (int x = 0; x < n; x++)
                if (!(mask >> x & 1))
                    res = min(res, abs(last - nums[x]) + go(mask | 1 << x, x));
            return res;
        };
        int rem = go(1, 0);                 // 最低分 = g({0}, 0)
        vector<int> ans = {0};              // perm[0] 固定为 0
        int mask = 1, last = 0;
        for (int i = 1; i < n; i++) {       // 逐位贪心重构
            for (int x = 0; x < n; x++) {
                if (!(mask >> x & 1)) {
                    int c = abs(last - nums[x]);
                    if (g[mask | 1 << x][x] != -1 && c + g[mask | 1 << x][x] == rem) {
                        ans.push_back(x);
                        mask |= 1 << x;
                        rem -= c;
                        last = x;
                        break;
                    }
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findPermutation(self, nums: List[int]) -> List[int]:
        n = len(nums)
        full = (1 << n) - 1
        # g[mask][last]：已放集合 mask（含 0 与 last）、末端 last，
        # 放完剩余数并闭环的最小代价；-1 表示未计算
        g = [[-1] * n for _ in range(1 << n)]
        for x in range(n):
            g[full][x] = abs(x - nums[0])   # 终态预填

        def go(mask: int, last: int) -> int:
            if g[mask][last] != -1:
                return g[mask][last]
            best = inf
            for x in range(n):
                if not mask >> x & 1:
                    best = min(best, abs(last - nums[x]) + go(mask | 1 << x, x))
            g[mask][last] = best
            return best

        ans = [0]                           # perm[0] 固定为 0
        mask, last, rem = 1, 0, go(1, 0)     # rem = 最低分 = g({0}, 0)
        for _ in range(n - 1):              # 逐位贪心重构
            for x in range(n):
                if not mask >> x & 1:
                    c = abs(last - nums[x])
                    if c + g[mask | 1 << x][x] == rem:
                        ans.append(x)
                        mask |= 1 << x
                        rem -= c
                        last = x
                        break
        return ans
```

## 8. 边界情况与易错点

1. **闭环边必须计入**：分数定义的最后一项是 $|\mathrm{perm}[n-1] - \mathrm{nums}[\mathrm{perm}[0]]| = |\mathrm{perm}[n-1] - \mathrm{nums}[0]|$。若终态漏掉这条闭环边，最低分会系统性偏低。预填 `g[full][x] = abs(x - nums[0])` 一行绝不能少。
2. **终态不落表的陷阱**：若在递归里对 `mask == full` 直接 `return abs(...)` 而不写入 `g`，则重构最后一位时 `g[full][x] == -1`，等式永远不成立，最后一个元素选不出来，返回残缺排列。正确做法是先预填终态再搜索（本文实现），或重构时把 `-1` 特判为闭环代价。
3. **哨兵值参与比较**：用 `-1` 作「未计算」哨兵时，`c + (-1) == rem` 这种伪等式可能碰巧成立（如 $c = 3$、$\mathrm{rem} = 2$ 时），防御性写法是先判 `!= -1` 再比等式；按 §4.3 的可达性论证，两份参考代码中比较的 `g` 值都已算好，此判据是保险而非必需。
4. **不能忘掉 perm[0] = 0**：若不固定首位而在全部排列上做 DP，既浪费状态（起点不定的哈密顿环没有固定锚点，字典序重构也无从谈起），又会返回字典序非最小的答案（如示例 2 若允许任意起点，可能输出 $[2,1,0]$ 这类分数相同但字典序更大的排列——注意它旋转到 0 开头即为 $[0,2,1]$，分数相同，印证引理 1）。
5. **重构结束后 rem 不归零**：循环结束时 $\mathrm{rem}$ 恰好等于闭环边代价 $|\mathrm{last} - \mathrm{nums}[0]|$（由不变量 $\mathrm{rem} = g(\mathrm{mask}, \mathrm{last})$，终态 $g$ 即闭环边），不要误以为程序有 bug 而额外「修正」。
6. **n = 2 的最小规模**：只有两个排列 $[0,1]$、$[1,0]$，恰好用来验证「固定首位 + 重构」逻辑在只剩一个空位时是否正确（本文代码在 $n = 2$ 时重构循环只跑一轮）。
7. **C++ 的 INT_MAX 与加法**：`res` 初始化为 `INT_MAX` 后只作 `min` 的比较基准，不参与加法；`go` 返回值总是有限值，`abs(...) + go(...)` 不会溢出。若改写成「先加后比」的顺序需注意这一点。

**延伸思考**：

- **为什么 $n \le 14$？** $2^{14} \cdot 14^2 \approx 3.2 \times 10^6$ 尚可，$n = 20$ 时 $2^{20} \cdot 20^2 \approx 4 \times 10^8$ 已很勉强，$n = 25$ 起状压彻底不可行——TSP 型问题是 NP-hard，$n \le 14$~$16$ 正是「暴力排列 $n!$ 不可行、状压 $2^n$ 可行」的窗口。

- **变体**：若只要求返回最低分而不要求方案，前缀式 DP 加滚动数组可把空间压到 $O(2^n)$；若要求统计最低分排列的**个数**，需把 $g$ 的 `min` 改为「取最小值的方案数」双值 DP。
