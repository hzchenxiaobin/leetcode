# LeetCode 偶数的按位或运算 题解

## 1. 题目概述

- **标题 / 题号**：偶数的按位或运算（#3688，easy）
- **链接**：https://leetcode.cn/problems/bitwise-or-of-even-numbers-in-an-array/
- **来源**：LeetCode 第 468 场周赛 Q1
- **难度**：简单
- **标签**：位运算、数组、模拟

**题意**：给定整数数组 `nums`，返回其中**所有偶数**的按位**或**运算结果；若数组中没有偶数，返回 $0$。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,5,6]
输出：6

解释：偶数是 2、4、6，2 | 4 | 6 = 6。
```

**示例 2**

```text
输入：nums = [7,9,11]
输出：0

解释：数组中没有偶数，返回 0。
```

**示例 3**

```text
输入：nums = [1,8,16]
输出：24

解释：偶数是 8 和 16，8 | 16 = 24。
```

## 3. 解题思路

### 3.1 快速切入：题面 = 筛选 + 聚合

签到题的正确打开方式是把题面拆成两个动作：

1. **筛选**：挑出所有偶数；
2. **聚合**：把挑出的数用 `|` 连起来。

一遍扫描、逐个判断、累积即可，时间 $O(n)$——每个元素至少要看一眼，**模拟已经是最优**，不需要任何更聪明的做法。比赛时真正能失分的点只有三处：**偶数怎么判、初值给多少、运算符优先级**（分别见 §4 与 §8）。

### 3.2 核心观察：0 是按位或的单位元

按位或有一条极其好用的性质：

$$0 \mid x = x$$

即 **0 是 `|` 运算的单位元**。把累积变量初始化为 `ans = 0`：

- 扫到一个偶数 $x$：`ans = ans | x` 正确累积；
- 一个偶数都没有：`ans` 从头到尾保持 $0$，**「无偶数返回 0」的特判被初值天然覆盖**，不需要任何 `if`。

再送两个顺手的观察：偶数的二进制**最低位必为 0**，而 `|` 只置 1 不清 0，最低位永远是 0 在参与或——所以**结果必然是偶数**；又因为结果的二进制位包含每个参与者的所有为 1 的位，**结果 $\ge$ 参与运算的最大偶数**。

![核心观察：筛选偶数 + OR 累积](images/wc468_q1_even_or_insight.svg)

> 💡 一句话：`ans = 0` 起手，扫到偶数就 `ans |= x`，返回 `ans`。特判？不存在的。

### 3.3 算法流程

![算法流程：一遍扫描](images/wc468_q1_algorithm_flow.svg)

1. 初始化 `ans = 0`（OR 的单位元）
2. 从左到右扫描 $i = 0 \dots n-1$：
   - 若 $nums[i]$ 为偶数（最低二进制位为 0）：`ans |= nums[i]`
   - 否则跳过
3. 返回 `ans`

### 3.4 示例演算

![示例演算](images/wc468_q1_example_walkthrough.svg)

- $[1,2,3,4,5,6]$：三个偶数 $2,4,6$，累积过程 $0 \to 2 \to 6 \to 6$，答案 6
- $[7,9,11]$：没有偶数，`ans` 保持单位元 0，答案 0
- $[1,8,16]$：$8=01000_2$、$16=10000_2$，两组不相交的位直接拼成 $11000_2 = 24$，答案 24
- $[1,3,5,64]$：唯一的偶数 64，$0 \mid 64 = 64$，答案就是它本身

## 4. 算法细节

1. **偶数判定的等价写法**：$x$ 为偶数 $\iff$ 二进制最低位为 0 $\iff$ `(x & 1) == 0` $\iff$ `x % 2 == 0`。前者是位视角，后者是模运算视角，正数域完全等价；本题值域 $[1,100]$，两者都安全。
2. **初值只能是 0**：`|` 的单位元唯一。若手滑初始化成 $-1$（补码全 1 位）或 1，多余的位永远洗不掉，任何输入都得到错误答案。
3. **C++ 优先级陷阱**：`if (nums[i] & 1 == 0)` **不是**判偶数！C++ 中 `==` 优先级高于 `&`，该式解析为 `nums[i] & (1 == 0)` 即 `nums[i] & 0`，恒为 0（假），所有元素都被当成奇数跳过，**全偶数组也返回 0**。必须写 `(nums[i] & 1) == 0`。有趣的是 Python 中 `&` 优先级**高于**比较运算，`x & 1 == 0` 恰好就是 `(x & 1) == 0`——同一行代码在两种语言里语义不同。
4. **运算律保证顺序无关**：`|` 满足交换律与结合律，偶数以任何顺序累积结果都相同，因此无需排序，可以乱序甚至并行归约。
5. **值域与位宽**：$nums[i] \le 100 < 128 = 2^7$，结果至多 7 个二进制位（$\le 127$），`int` 毫无溢出风险。

## 5. 正确性证明

**引理 1（偶数的位刻画）**：正整数 $x$ 为偶数 $\iff$ $x$ 的二进制最低位为 0。

**证明**：设 $x = \sum_{k \ge 0} b_k 2^k$，$b_k \in \{0,1\}$。当 $k \ge 1$ 时 $2^k$ 均为偶数，故 $x \equiv b_0 \pmod 2$。因此 $2 \mid x \iff b_0 = 0$。∎

**引理 2（单位元）**：对任意非负整数 $x$，$0 \mid x = x$。

**证明**：按位或结果的第 $k$ 位为 $b_k(0) \lor b_k(x)$。由 $b_k(0) = 0$ 且析取满足 $0 \lor 0 = 0$、$0 \lor 1 = 1$，结果每一位都与 $x$ 的对应位相同。∎

**引理 3（循环不变式）**：扫描完前 $i$ 个元素后，`ans` 等于前 $i$ 个元素中所有偶数 $e_1, e_2, \dots, e_m$（按出现顺序）的按位或 $e_1 \mid e_2 \mid \cdots \mid e_m$；若 $m = 0$ 则 `ans` $= 0$。

**证明**：对 $i$ 归纳。$i = 0$ 时 `ans` 初始化为 0 且 $m = 0$，命题成立（空 OR 规定为单位元 0）。设 $i$ 时命题成立，考察第 $i+1$ 个元素 $x$：若 $x$ 为奇数，由引理 1 判定条件不触发，`ans` 与偶数列表均不变；若 $x$ 为偶数，`ans` 更新为 $(e_1 \mid \cdots \mid e_m) \mid x$，由 `|` 的结合律即 $e_1 \mid \cdots \mid e_m \mid x$。两种情况命题对 $i+1$ 均成立。∎

**定理**：算法返回 `nums` 中所有偶数的按位或；当且仅当不存在偶数时返回 $0$。

**证明**：在引理 3 中取 $i = n$：`ans` 即全部偶数的按位或。若存在偶数（$m \ge 1$），取其中最大者 $E$，`ans` 的二进制位包含 $E$ 的所有为 1 的位，故 `ans` $\ge E \ge 2 > 0$；若 $m = 0$，由引理 3 得 `ans` $= 0$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个元素一次 $O(1)$ 的位判断与至多一次 OR。
- **空间复杂度**：$O(1)$。仅维护 `ans` 一个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int evenNumberBitwiseORs(vector<int>& nums) {
        int ans = 0; // 0 是按位或的单位元，无偶数时天然返回 0
        for (int x : nums) {
            if ((x & 1) == 0) { // 注意括号：C++ 中 == 优先级高于 &
                ans |= x;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def evenNumberBitwiseORs(self, nums: List[int]) -> int:
        ans = 0
        for x in nums:
            if x % 2 == 0:
                ans |= x
        return ans
```

## 8. 边界情况与易错点

1. **无偶数返回 0**：`ans = 0` 的初值已自动覆盖（OR 的单位元），**不需要**额外特判；写了特判不算错，但说明没看穿这一层。
2. **C++ 运算符优先级**：`x & 1 == 0` 会被解析成 `x & (1 == 0)` 恒为假，症状是**全偶数组也返回 0**。判偶必须 `(x & 1) == 0`，或干脆用 `x % 2 == 0`。Python 无此坑（`&` 优先级更高）。
3. **别把 `|` 写成 `||`**：`a || b` 是逻辑或，结果只有 0/1；累积必须用按位或 `|`。同理别把 `&` 写成 `&&`。
4. **初值别乱给**：`-1`（补码全 1）或任何非 0 初值都会永久污染结果，0 是唯一免特判的初值。
5. **负数偶数（超出本题，但值得提前排雷）**：C++ 中 `-3 % 2 == -1`，用 `x % 2 == 1` 判奇会漏掉负奇数；而 `x % 2 == 0` 判偶与补码下的 `(x & 1) == 0` 对负数依然正确。本题值域 $[1,100]$，纯属顺手排雷。
6. **单元素数组**：$n = 1$ 时若该元素为偶数，答案就是它本身（$0 \mid x = x$）；为奇数则返回 0，代码无需改动。
7. **无溢出风险**：$n \le 100$、值 $\le 100$，OR 结果 $\le 127$，`int` 足够，不需要 `long long`。

**延伸思考**：

- **支持删除的数据流版本**：若元素不断到来又可能被撤销，直接维护 OR 不行——`|` 不可逆。改为**按位计数**：对每个二进制位维护「当前有多少个偶数在该位为 1」，插入加一、删除减一，计数归零才清位，查询时重组出 OR 值。
- **提前剪枝**：值域 $[1,100]$ 意味着结果 $< 128$（7 位）。一旦 `ans == 127`（低 7 位全 1），后续偶数不可能再改变结果，可提前退出。本题规模下毫无必要，但「OR 只置 1 不清 0、结果单调不减」是位运算题的常用观察。
- **为什么结果必为偶数**：所有偶数最低位为 0，OR 之后最低位仍是 0（引理 1 的直接推论）——可以用来肉眼快速校验答案的奇偶。
