# LeetCode 替换字符可以得到的最晚时间 题解

## 1. 题目概述

- **标题 / 题号**：替换字符可以得到的最晚时间（#3114，easy）
- **链接**：https://leetcode.cn/problems/latest-time-you-can-obtain-after-replacing-characters/
- **来源**：LeetCode 第 393 场周赛 Q1
- **难度**：简单
- **标签**：字符串、枚举、贪心

**题意**：给定长度为 5 的字符串 `s`，表示一个 12 小时制时间 `"HH:MM"`，其中一些数字被 `'?'` 替换（`s[2]` 恒为 `':'`）。小时 `HH` 的取值范围是 00 ~ 11，分钟 `MM` 的取值范围是 00 ~ 59。需要把**所有** `'?'` 替换成数字，使结果是一个**有效**的 12 小时制时间，且是所有有效替换中**最晚**的那个。返回结果字符串。

**约束**：

- `s.length == 5`，`s[2]` 是 `':'`，其余字符都是数字或 `'?'`
- 输入保证至少存在一种有效替换（无需处理无解）

> 💡 读题关键：「最晚」= 先比小时、再比分钟的**字典序最大化**。真正有自由度的只有 4 个位置 `s[0] / s[1] / s[3] / s[4]`，而它们的合法条件结构完全不同：小时两位**互相牵制**（$HH \le 11$），分钟两位**完全独立**（$MM \le 59$）。签到题的最短路径：把每个 `'?'` 能填的最大合法数字写清楚，小心小时那一对即可。

## 2. 示例

**示例 1**

```text
输入：s = "1?:?4"
输出："11:54"
解释：通过替换 "?" 字符，可以得到的最晚 12 小时制时间是 "11:54"。
```

**示例 2**

```text
输入：s = "0?:5?"
输出："09:59"
解释：通过替换 "?" 字符，可以得到的最晚 12 小时制时间是 "09:59"。
```

**示例 3（补充：覆盖十位兜底分支）**

```text
输入：s = "?4:??"
输出："04:59"
解释：小时个位是 '4'，十位填 '1' 会得到 "14"（非法），只能兜底填 '0' 得到 04；
      分钟两位无牵制，'?' 分别拉满为 '5' 和 '9'。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法：把 12 小时制的全部 $12 \times 60 = 720$ 个时间**从晚到早**枚举一遍，第一个与 `s` 模式匹配的就是答案（`'?'` 可匹配任意数字）：

```python
for t in range(11 * 60 + 59, -1, -1):          # 从 11:59 倒序枚举
    cand = f"{t // 60:02d}:{t % 60:02d}"
    if all(a == '?' or a == b for a, b in zip(s, cand)):
        return cand                            # 最晚的匹配者
```

每个候选只比对 5 个字符，总开销 $O(720 \times 5)$，作为常数必然能过。但 `'?'` 至多 4 个、时间结构完全固定，完全可以**逐位直接构造**出最晚时间，把枚举也省掉。

### 3.2 核心观察：先拉满小时，分钟独立拉满

![核心概念：小时两位互相牵制，分钟两位各自独立拉满](images/latest_time_hour_cases.svg)

把「最晚」翻译成逐位填数规则，只需三个观察：

- **观察 1：小时优先级高于分钟**。小时每 +1 相当于 +60 分钟，而分钟最多贡献 59——任何「小时更大」的方案都晚于任何「小时更小」的方案（§5 引理 1）。所以**先把小时拉到最大，再拉分钟**，两步互不干扰。
- **观察 2：分钟两位互相独立**。$MM \le 59$ 等价于「十位 $\le 5$ 且个位任意」：`s[3]` 是 `'?'` 就填 `'5'`（50 ~ 59 全部合法），`s[4]` 是 `'?'` 就填 `'9'`（00 ~ 59 中个位都可到 9）。两位的合法条件互不引用，各自拉满即可。
- **观察 3：小时两位互相牵制**。$HH \le 11$ 等价于「十位 $\in \{0,1\}$，且十位为 1 时个位 $\le 1$」。这正是本题唯一的陷阱：
  - `s[0]` 是 `'?'`：想冲 `'1'`（得到 10 或 11），但必须先看个位——`s[1]` 是 `'?'` 或 $\le \texttt{'1'}$ 才允许；若 `s[1]` 已是 `'2'` ~ `'9'`，十位只能兜底 `'0'`（得到 02 ~ 09）。
  - `s[1]` 是 `'?'`：填法取决于**填好之后的**十位——十位是 `'0'` 就填 `'9'`（09），十位是 `'1'` 就填 `'1'`（11）。

> ⚠️ 本题最常见的错误就是「十位是 `'?'` 无脑填 `'1'`」：`"?4"` 会变 `"14"`，非法。小时必须当作一个**两位数**整体决策，不能两位各自贪心。

### 3.3 算法流程

![算法流程：先填 s[0] 再填 s[1]，随后分钟两位各自拉满](images/latest_time_greedy_flow.svg)

流程四步，注意小时**必须先填 `s[0]` 再填 `s[1]`**（后者要引用前者的最终值）：

1. 若 `s[0] == '?'`：`s[1]` 是 `'?'` 或 $\le \texttt{'1'}$ → 填 `'1'`；否则填 `'0'`（兜底）；
2. 若 `s[1] == '?'`：`s[0] == '0'` → 填 `'9'`；否则（`s[0]` 为 `'1'`）→ 填 `'1'`；
3. 若 `s[3] == '?'`：填 `'5'`；
4. 若 `s[4] == '?'`：填 `'9'`。

### 3.4 示例演算

![示例演算：三条分支逐位填数得到最晚时间](images/latest_time_walkthrough.svg)

| 输入 | s[0]（十位） | s[1]（个位） | s[3] / s[4]（分钟） | 结果 |
|------|------------|------------|-------------------|------|
| `"1?:?4"` | 已是 `'1'` | `s[0]='1'` → `'1'` | `'5'` / 已是 `'4'` | `"11:54"` |
| `"0?:5?"` | 已是 `'0'` | `s[0]='0'` → `'9'` | 已是 `'5'` / `'9'` | `"09:59"` |
| `"?4:??"` | `s[1]='4'>'1'` → 兜底 `'0'` | 已是 `'4'` | `'5'` / `'9'` | `"04:59"` |
| `"??:??"` | `s[1]='?'` 不拦路 → `'1'` | `s[0]='1'` → `'1'` | `'5'` / `'9'` | `"11:59"` |

四个输入恰好覆盖小时的全部四条分支：十位已定 1、十位已定 0、十位兜底 0、十位冲 1 成功。

## 4. 算法细节

1. **决策顺序**：小时部分必须先 `s[0]` 后 `s[1]`——`s[1]` 的填法要引用 `s[0]` **填完之后**的值（`s[0]` 可能本来就是 `'0'` / `'1'`，也可能是刚从 `'?'` 填出来的）。若反过来先填 `s[1]`，条件必须另行修补，极易翻车；分钟两位无依赖，顺序随意。
2. **条件合并**：`s[1] == '?' || s[1] <= '1'` 一个布尔式覆盖「个位可以配合冲 10/11」的两种情况（个位是 `'?'`、个位是 `'0'` / `'1'`），是 `s[0]` 分支的唯一判断。
3. **分支为什么是完备的**：输入保证有解，故 `s[0]` 只可能是 `'0'`、`'1'`、`'?'`（否则任何替换都无解，与保证矛盾）；同理 `s[0]='1'` 时 `s[1]` 只可能是 `'0'`、`'1'`、`'?'`，`s[3]` 只可能是 `'0'` ~ `'5'` 或 `'?'`。因此 §3.3 的分支覆盖一切合法输入，不需要防御性代码。
4. **填值依据**（每个 `'?'` 位置的可行数字集合及其最大元）：

| 位置 | 可行数字 | 最大元 | 备注 |
|------|---------|--------|------|
| `s[0]` | 受 `s[1]` 牵制：`{0,1}` 或 `{0}` | `'1'`（若可行） | 冲 1 失败则兜底 `'0'` |
| `s[1]` | 受 `s[0]` 牵制：`{0..9}` 或 `{0,1}` | `'9'` / `'1'` | 十位 `'0'` → `'9'`；十位 `'1'` → `'1'` |
| `s[3]` | `{0..5}` | `'5'` | 与 `s[4]` 无关 |
| `s[4]` | `{0..9}` | `'9'` | 与 `s[3]` 无关 |

5. **字符串可变性**：C++ 的 `string` 可原地修改；Python 的 `str` 不可变，先 `list(s)` 改完再 `''.join`。
6. **对拍工具**：3.1 的枚举版不到 10 行，赛时可用来给贪心版做全模式对拍（见 §8 第 1 条）。

## 5. 正确性证明

**引理 1**（先小时后分钟）：设有效时间 $T_1 = H_1{:}M_1$、$T_2 = H_2{:}M_2$。则 $T_1$ 早于 $T_2$，当且仅当 $H_1 < H_2$，或 $H_1 = H_2$ 且 $M_1 < M_2$。

**证明**：把时间映射为分钟数 $v(T) = 60H + M$，先后关系即 $v$ 的大小关系。若 $H_1 < H_2$，则 $v(T_1) \le 60H_1 + 59 < 60(H_1 + 1) \le 60H_2 \le v(T_2)$，即 $T_1$ 更早；若 $H_1 = H_2$，则大小关系由 $M$ 直接给出。反之，由 $v$ 的表达式逐项对应可得。∎

**引理 2**（分钟独立拉满）：固定小时部分后，把 `s[3]`、`s[4]` 中的 `'?'` 分别填为 `'5'`、`'9'`，得到的是所有匹配分钟模式的有效分钟中最大的。

**证明**：分钟 $MM = 10a + b$（$a$ 为十位、$b$ 为个位）有效等价于 $a \le 5$ 且 $b \le 9$，两位的约束互不引用。故 `s[3]='?'` 时可行数字集为 $\{0,\dots,5\}$，`s[4]='?'` 时为 $\{0,\dots,9\}$，均不论另一位取值。而 $10a + b$ 对 $(a, b)$ 各分量严格单调递增，故各分量取可行集最大元（`'5'` 与 `'9'`）时整体最大。∎

**引理 3**（小时可行集）：对小时模式 $P = s[0]s[1]$（`'?'` 为自由位），全部有效替换得到的可行小时集合为：

| 模式 $P$ | 可行小时集合 | 最大元 |
|----------|------------|--------|
| `0d` / `1d`（`d` 为固定数字，`1d` 需 `d ≤ 1`，由有解保证） | 单点 $\{0d\}$ / $\{1d\}$ | 自身 |
| `?d`，`d ≥ 2` | $\{0d\}$ | $0d$ |
| `?d`，`d ≤ 1` | $\{0d,\ 1d\}$ | $1d$ |
| `0?` | $\{00,\dots,09\}$ | $09$ |
| `1?` | $\{10, 11\}$ | $11$ |
| `??` | $\{00,\dots,11\}$ | $11$ |

**证明**：逐模式枚举全部替换并保留 $\le 11$ 者即可，每个模式至多 $10 \times 10$ 种组合，直接验证。∎

**定理**：算法返回的字符串是 `s` 的最晚有效替换。

**证明**：小时模式与分钟模式位于 `s` 的不相交位置，替换互不影响，故可行替换集合是「可行小时集合 × 可行分钟集合」的直积。第一步、第二步恰好把小时填成引理 3 中可行小时集合的最大元 $H^\ast$（核对：`s[0]='?'` 且 `s[1]∈{?,0,1}` 填 `'1'` 对应表中 `?d (d≤1)`、`??` 两行的最大元；兜底 `'0'` 对应 `?d (d≥2)` 行；`s[1]='?'` 时按十位填 `'9'` / `'1'` 对应 `0?`、`1?` 两行的最大元；十位本来就是数字时不改动，对应单点行）。第三、四步由引理 2 把分钟填成可行分钟集合的最大元 $M^\ast$。最后由引理 1，时间的先后由 $(H, M)$ 的字典序决定，故 $(H^\ast, M^\ast)$ 即全局最晚，且它是 `s` 的一个有效替换。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。固定 4 个位置各做一次判断与赋值，字符串长度恒为 5；枚举版为 $O(720 \times 5)$，同样是常数，只是常数更大。
- **空间复杂度**：$O(1)$。C++ 原地修改 `s`；Python 用长度 5 的列表过渡，亦为常数。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string findLatestTime(string s) {
        if (s[0] == '?')                              // 小时十位：先填
            s[0] = (s[1] == '?' || s[1] <= '1') ? '1' : '0';
        if (s[1] == '?')                              // 小时个位：看填完的十位
            s[1] = (s[0] == '0') ? '9' : '1';
        if (s[3] == '?') s[3] = '5';                  // 分钟十位：独立拉满
        if (s[4] == '?') s[4] = '9';                  // 分钟个位：独立拉满
        return s;
    }
};
```

### Python

```python
class Solution:
    def findLatestTime(self, s: str) -> str:
        t = list(s)
        if t[0] == '?':                               # 小时十位：先填
            t[0] = '1' if t[1] == '?' or t[1] <= '1' else '0'
        if t[1] == '?':                               # 小时个位：看填完的十位
            t[1] = '9' if t[0] == '0' else '1'
        if t[3] == '?':                               # 分钟十位：独立拉满
            t[3] = '5'
        if t[4] == '?':                               # 分钟个位：独立拉满
            t[4] = '9'
        return ''.join(t)
```

## 8. 边界情况与易错点

1. **全 `'?'`**：`"??:??"` → `"11:59"`。先 `s[0]='1'`（`s[1]='?'` 不拦路），再 `s[1]='1'`；用枚举版可快速验证此分支。
2. **最深陷阱——十位冲 1 不看个位**：`"?4:5?"` 若填 `'1'` 得 `"14"` 非法，必须兜底 `'0'` → `"04:59"`。
3. **个位也不能无脑 `'9'`**：`"1?:??"` 若填 `'9'` 得 `"19"` 非法；十位为 `'1'` 时个位最多 `'1'` → `"11:59"`。
4. **决策顺序**：先 `s[0]` 后 `s[1]`。若把两步写反，`s[1]` 分支引用的 `s[0]` 还是 `'?'`，条件必须另行修补（见 §4 第 1 条），容易错。
5. **12 小时制没有 `"12:xx"`**：小时上界是 `11`，别把 24 小时制的 `12` / `23` 习惯带进来（对照相关题目 1736）。
6. **分钟十位最大是 `'5'` 不是 `'9'`**：`"0?:??"` 的分钟若按 `"9x"` 填就非法了。
7. **别改动已有的数字和 `':'`**：只把 `'?'` 替换成数字，其余字符原样保留，返回完整 5 字符串。
8. **无解不会出现**：题目保证至少一种有效替换，因此不需要失败分支；也正因如此，`s[0]` 不会是 `'2'` ~ `'9'` 等数字（那样必然无解）。
