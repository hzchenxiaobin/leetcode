# LeetCode 交通信号灯的颜色 题解

## 1. 题目概述

- **标题 / 题号**：交通信号灯的颜色（#3894，easy）
- **链接**：https://leetcode.cn/problems/traffic-signal-color/
- **来源**：LeetCode 第 180 场双周赛 Q1
- **难度**：简单
- **标签**：数学、字符串、模拟

**题意**：给定整数 `timer` 表示信号灯的剩余时间（秒），按下面的规则返回当前颜色字符串：

- `timer == 0` → `"Green"`
- `timer == 30` → `"Orange"`
- `30 < timer <= 90` → `"Red"`
- 都不满足 → `"Invalid"`

**约束**：

- $0 \le timer \le 1000$

## 2. 示例

**示例 1**

```text
输入：timer = 60
输出："Red"
解释：30 < 60 ≤ 90，落在 Red 区间。
```

**示例 2**

```text
输入：timer = 5
输出："Invalid"
解释：5 既不等于 0、也不等于 30，还不满足 30 < 5，返回 Invalid。
```

**示例 3（自测）**

```text
输入：timer = 30    输出："Orange"
输入：timer = 0     输出："Green"
输入：timer = 90    输出："Red"        （右端点闭区间）
输入：timer = 91    输出："Invalid"    （超出 90）
输入：timer = 1000  输出："Invalid"
```

## 3. 解题思路

### 3.1 暴力思路

本题没有「暴力 vs 优化」的余地：题目给的是一张**静态分类表**，输入只有一个整数，输出由它唯一决定。任何做法都是 $O(1)$，区别只在判断顺序是否清晰、边界是否写对。

### 3.2 核心观察：三个条件互斥，按顺序判断即可

![交通信号灯：三个离散条件 + 一个兜底](images/bw180_q1_timer_axis.svg)

把数轴上的取值分成四段：

| 取值 | 颜色 |
|------|------|
| $= 0$ | Green |
| $= 30$ | Orange |
| $30 < timer \le 90$ | Red |
| 其它 | Invalid |

三个「有颜色」的条件**两两互斥**（$0$、$30$、$(30,90]$ 没有交集），所以判断顺序不影响结果；写成 `if / else if / else` 的链式结构最清晰。

> ⚠️ **两个高频错点**：一是把 Red 的条件写成 $30 \le timer \le 90$（把 30 也算成 Red，与 Orange 冲突）；二是把 $90$ 排除在外（题目是**闭区间**右端点，`timer = 90` 应为 Red）。

### 3.3 算法流程

![算法流程：三次判断，兜底 Invalid](images/bw180_q1_flow.svg)

```text
1. 若 timer == 0:            返回 "Green"
2. 若 timer == 30:           返回 "Orange"
3. 若 30 < timer <= 90:      返回 "Red"
4. 返回 "Invalid"
```

### 3.4 示例演算

| `timer` | 命中条件 | 返回 |
|---------|---------|------|
| 0 | 条件 1 | `"Green"` |
| 30 | 条件 2 | `"Orange"` |
| 60 | 条件 3（$30 < 60 \le 90$） | `"Red"` |
| 90 | 条件 3（右端闭） | `"Red"` |
| 5 | 都不命中 | `"Invalid"` |
| 91 | 都不命中（$> 90$） | `"Invalid"` |

## 4. 算法细节

1. **判断顺序**：先判两个精确值（0、30），再判开区间，最后兜底。这样即使有人把区间写成 `timer >= 30`，也会因为 30 已被前面的分支拦下而不出错——但为了可读性，仍建议直接写 `timer > 30`。
2. **闭区间**：`timer <= 90` 必须有等号。
3. **返回值是字符串**：注意大小写与拼写（`"Green"`、`"Orange"`、`"Red"`、`"Invalid"`），拼错会被判 WA。
4. **整数范围**：$timer \le 1000$，`int` 足够，无需考虑溢出。
5. **不要用取模**：「剩余时间」不是周期，$timer = 1000$ 不能映射回 $1000 \bmod 90$ 之类的值。

## 5. 正确性证明

**引理 1（分类完备且互斥）**：集合 $\{0\}$、$\{30\}$、$(30, 90]$、其余部分四者两两不交，并集为全体整数。

**证明**：$\{0\}$ 与 $\{30\}$ 是不同单点集，显然不交；$0 < 30$ 不在 $(30,90]$ 内，$30 \notin (30,90]$（开区间左端），故单点集与开区间不交；「其余部分」按定义是所有不被前三者覆盖的整数，与前三者互补，自然不交。并集显然为全集。∎

**定理**：算法对每个整数输入都返回题目规定的颜色。

**证明**：算法的分支链依次检查引理 1 中的四个类。若输入属于某一类，则它在该类对应的分支被返回，且由于类之间互斥、前面的分支都不会误命中；若输入不属于前三类，则落到最后的 `"Invalid"` 分支，与题目「均不满足则返回 Invalid」一致。故返回值恒等于题目规定值。∎

## 6. 复杂度分析

- **时间**：$O(1)$，至多 3 次比较。
- **空间**：$O(1)$，只返回一个常量字符串（返回的字符串本身不计入辅助空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string trafficSignal(int timer) {
        if (timer == 0) return "Green";
        if (timer == 30) return "Orange";
        if (timer > 30 && timer <= 90) return "Red";
        return "Invalid";
    }
};
```

### Python

```python
class Solution:
    def trafficSignal(self, timer: int) -> str:
        if timer == 0:
            return "Green"
        if timer == 30:
            return "Orange"
        if 30 < timer <= 90:
            return "Red"
        return "Invalid"
```

## 8. 边界情况与易错点

1. **`timer = 0`**：只能是 `"Green"`，不要被「$0 \le 30$」误导成 Orange 或 Invalid。
2. **`timer = 30`**：必须是 `"Orange"`。若 Red 写成 `timer >= 30 && timer <= 90`，30 就会先命中 Red（若 Red 判在前面）。
3. **`timer = 90`**：属于 Red（右端闭区间）。
4. **`timer = 91`**：必须 Invalid，别把区间写成 `<= 100`。
5. **`timer` 在 $1 \sim 29$**：题目没有定义颜色，一律 `"Invalid"`。这看起来反直觉（现实中红灯/绿灯应连续），但必须严格照题面。
6. **字符串大小写**：`"Red"` 不是 `"RED"`，`"Invalid"` 不是 `"invalid"`。
