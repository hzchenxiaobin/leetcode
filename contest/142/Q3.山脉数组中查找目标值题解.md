# LeetCode 山脉数组中查找目标值 题解

## 1. 题目概述

- **标题 / 题号**：山脉数组中查找目标值（#1095，hard）
- **链接**：https://leetcode.cn/problems/find-in-mountain-array/
- **来源**：LeetCode 第 142 场周赛 Q3
- **难度**：困难
- **标签**：数组、二分查找、交互、三分查找

**题意**：这是一道**交互题**。`mountainArr` 是一个**山脉数组**：存在唯一的峰顶下标 $i$（$0<i<n-1$），使得
$$\text{arr}[0]<\text{arr}[1]<\cdots<\text{arr}[i]>\text{arr}[i+1]>\cdots>\text{arr}[n-1]$$
你不能直接访问数组，只能调用两个接口：`MountainArray.get(k)` 返回下标 $k$ 的元素，`MountainArray.length()` 返回长度。求**最小**的下标 `index` 使 `get(index) == target`，不存在则返回 $-1$。**整个过程中 `get` 的调用次数不得超过 100 次**。

**约束**：

- $3 \le \text{mountainArr.length()} \le 10^4$
- $0 \le \text{target} \le 10^9$
- $0 \le \text{mountainArr.get}(index) \le 10^9$
- `get` 调用超过 100 次的提交判为错误答案

> 💡 接口签名提醒：LeetCode 的 C++ / Python 接口把 `target` 放在**第一个参数**（`findInMountainArray(target, mountainArr)`），题面元信息里列参数的顺序是 `mountainArr, target`，以官方签名为准。

## 2. 示例

**示例 1**

```text
输入：mountainArr = [1,2,3,4,5,3,1], target = 3
输出：2
解释：3 出现在下标 2 和 5，返回较小的 2。
```

**示例 2**

```text
输入：mountainArr = [0,1,2,4,2,1], target = 3
输出：-1
解释：3 不在数组中。
```

**示例 3（自造，考查峰顶即答案）**

```text
输入：mountainArr = [1,5,2], target = 5
输出：1
解释：峰顶就是目标值；峰顶必须包含在升序段的二分区间内，否则会漏掉。
```

## 3. 解题思路

### 3.1 暴力思路

从下标 0 到 $n-1$ 逐个 `get` 比较，第一次命中即为最小下标。正确但**需要最多 $n\le10^4$ 次 `get`**，远超 100 次上限；而且没有任何剪枝空间——数组既不是整体有序，也不能直接访问。要满足调用限制，必须把「看哪些位置」压到对数级。

### 3.2 核心观察：山脉 = 升序段 + 降序段，先找峰再两段二分

![山脉数组 = 严格升序 + 严格递减两段](images/wc142_q3_three_segments.svg)

山脉数组虽然整体无序，但被峰顶切成两段**各自单调**的区间：

- 左段 $[0, peak]$ 严格递增；
- 右段 $[peak, n-1]$ 严格递减（峰顶同时属于两段）。

在单调段上就可以二分。于是算法分三步，全部是对数级：

1. **找峰顶**：比较 `get(mid)` 与 `get(mid+1)`，一次比较就能判断 `mid` 在峰的哪一侧；
2. **在左段 $[0, peak]$ 二分**（标准升序二分）——由于左段严格递增，至多命中一次，且命中的是**全局最小下标**；
3. 若左段没命中，**在右段 $(peak, n-1]$ 反向二分**（递减数组，比较方向反过来）。

![峰顶二分：只看 mid 与 mid+1 的大小关系](images/wc142_q3_peak_search.svg)

> 💡 为什么一定要先查左段？因为右段所有下标都大于 `peak`，只要左段有解，它一定是最小下标。顺序反了就会返回较大的下标。

### 3.3 算法流程

```text
1. n = length()
2. lo = 0, hi = n-1
   while lo < hi:                      # 找峰顶
       mid = lo + (hi-lo)/2
       若 get(mid) < get(mid+1): lo = mid+1     # mid 在上升段，峰在右边
       否则:                     hi = mid       # mid 在下降段（或就是峰）
   peak = lo
3. lo = 0, hi = peak
   while lo <= hi:                     # 左段升序二分
       mid = lo + (hi-lo)/2
       若 get(mid) == target: return mid
       若 get(mid) <  target: lo = mid+1
       否则:                  hi = mid-1
4. lo = peak+1, hi = n-1
   while lo <= hi:                     # 右段递减，反向二分
       mid = lo + (hi-lo)/2
       若 get(mid) == target: return mid
       若 get(mid) >  target: lo = mid+1   # 递减：值大说明还在左边
       否则:                  hi = mid-1
5. return -1
```

### 3.4 示例演算

![示例 1 的 get 调用序列](images/wc142_q3_walkthrough.svg)

对示例 1（`arr = [1,2,3,4,5,3,1]`，`target = 3`）：

| 阶段 | 区间 $[lo,hi]$ | mid | 比较结果 → 动作 |
|---|---|---|---|
| 找峰 1 | $[0,6]$ | 3 | `get(3)=4 < get(4)=5` → `lo = 4` |
| 找峰 2 | $[4,6]$ | 5 | `get(5)=3 > get(6)=1` → `hi = 5` |
| 找峰 3 | $[4,5]$ | 4 | `get(4)=5 > get(5)=3` → `hi = 4` |
| 峰顶 | $peak = 4$ | — | 峰顶值 5，不在端点 |
| 左段二分 | $[0,4]$ | 2 | `get(2)=3 == target` → 返回 2 |

全程只调用 5 次 `get`。注意下标 5 处的 3 虽然也等于 `target`，但因为左段先命中，直接返回 2，正是最小下标。

## 4. 算法细节

1. **峰顶二分的不变量**：始终维护 $peak\in[lo,hi]$。`mid` 取 `lo + (hi-lo)/2`，在 `lo<hi` 时必有 `mid < hi`，所以 `mid+1 ≤ hi ≤ n-1`，不会越界读。
2. **严格性保证**：山脉数组相邻元素严格不等，故 `get(mid)` 与 `get(mid+1)` 必有大小之分，不需要处理相等分支。
3. **左段包含峰顶**：左段取 $[0, peak]$（闭区间），否则峰顶上的 `target` 会被漏掉（示例 3）。
4. **右段从 `peak+1` 起**：峰顶已经在左段查过，右段从 `peak+1` 开始既避免重复也保证不越界；`peak == n-1` 不可能发生（题面保证峰不在端点），但仍可自然处理空区间。
5. **调用次数预算**：峰顶二分每轮 2 次 `get`，共 $\lceil\log_2 n\rceil$ 轮；左右两段各至多 $\lceil\log_2 n\rceil$ 次。总计约 $4\lceil\log_2 n\rceil$，$n\le10^4$ 时为 56 次，实测最坏 51 次，安全低于 100。
6. **可选的缓存优化**：把最近一次 `get(mid)` 的结果缓存下来，下一轮的 `get(mid)` 有可能命中缓存，可把峰顶二分从每轮 2 次降到约 1.5 次。
7. **比较方向**：递减段的二分最容易写反——`get(mid) > target` 时应向右走（`lo = mid+1`），因为左边更大。
8. **返回最小下标**：不要用「左右两段都查、取 min」的写法，那会多做一整轮二分；先左后右且左段命中即返回，天然最小。

## 5. 正确性证明

**引理 1（峰顶二分的分支正确）**：设当前区间 $[lo,hi]$ 满足 $peak\in[lo,hi]$，取 $mid=lo+\lfloor (hi-lo)/2\rfloor$（此时 $mid<hi$）。若 $\text{get}(mid)<\text{get}(mid+1)$，则 $peak\ge mid+1$；若 $\text{get}(mid)>\text{get}(mid+1)$，则 $peak\le mid$。

**证明**：数组在 $[0,peak]$ 上严格递增、在 $[peak,n-1]$ 上严格递减。
- 情形一：若 $mid\ge peak$，则 $mid$ 与 $mid+1$ 都在递减段上，必有 $\text{get}(mid)>\text{get}(mid+1)$，与假设矛盾。故 $mid<peak$，即 $peak\ge mid+1$。
- 情形二：若 $mid<peak$，则 $mid+1\le peak$，两点都在递增段上，必有 $\text{get}(mid)<\text{get}(mid+1)$，与假设矛盾。故 $mid\ge peak$。∎

**引理 2（峰顶二分收敛到峰）**：峰顶二分的循环结束时 $lo=hi=peak$。

**证明**：初始 $[0,n-1]$ 显然包含 $peak$。由引理 1，每轮之后新区间仍包含 $peak$，且长度严格变小（$lo\gets mid+1>lo$ 或 $hi\gets mid<hi$）。循环在 $lo=hi$ 时停止，此时唯一候选点就是 $peak$。∎

**引理 3（左段二分返回最小命中下标）**：左段 $[0,peak]$ 严格递增，标准二分若命中则返回其中唯一的匹配下标，否则返回「未找到」。

**证明**：严格递增序列中同一个值至多出现一次，故匹配唯一；标准二分在有序序列上的正确性由循环不变量（`target` 若存在则始终位于 $[lo,hi]$ 内）保证。又因右段下标都 $>peak$，左段若命中，该下标必为全局最小。∎

**引理 4（右段二分正确）**：右段 $(peak,n-1]$ 严格递减，把比较方向反转后的二分与升序二分同构，命中则返回其中唯一下标。

**证明**：令 $b[j]=\text{get}(n-1-j)$，则 $b$ 在对应区间上严格递增，反转比较方向后的二分等价于在 $b$ 上做标准二分，故正确。∎

**引理 5（调用次数上界）**：整个过程 `get` 的调用次数不超过 $4\lceil\log_2 n\rceil$。

**证明**：峰顶二分每轮恰好 2 次 `get`，区间长度每轮至少减半，至多 $\lceil\log_2 n\rceil$ 轮，故 $\le2\lceil\log_2 n\rceil$ 次；左段二分区间长度 $\le n$，每轮 1 次，至多 $\lceil\log_2 n\rceil$ 次；右段同理。合计 $\le4\lceil\log_2 n\rceil$。$n\le10^4$ 时该值不超过 56，小于 100。∎

**定理**：算法返回 `target` 在数组中出现的**最小下标**；若不存在则返回 $-1$。

**证明**：由引理 2 得到正确峰顶。若 `target` 出现在左段，由引理 3 返回其唯一且最小的下标；否则左段无解，若出现在右段，由引理 4 返回其唯一下标（右段严格递减，同样至多一个），且此时左段无解故它也是全数组最小下标；两段都无解则返回 $-1$，正确。调用次数由引理 5 满足限制。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$ 次 `get` 调用（每次 $O(1)$），合计 $O(\log n)$；不依赖数组总长度做线性扫描。
- **空间**：$O(1)$。只用 `lo`、`hi`、`mid`、`peak` 等常数个变量；若加缓存也只是 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findInMountainArray(int target, MountainArray &mountainArr) {
        int n = mountainArr.length();
        int lo = 0, hi = n - 1;
        while (lo < hi) {                        // 第一次二分：找峰顶下标 peak
            int mid = lo + (hi - lo) / 2;
            if (mountainArr.get(mid) < mountainArr.get(mid + 1)) lo = mid + 1;
            else hi = mid;
        }
        int peak = lo;
        lo = 0; hi = peak;
        while (lo <= hi) {                       // 第二次二分：峰左侧升序段
            int mid = lo + (hi - lo) / 2;
            int v = mountainArr.get(mid);
            if (v == target) return mid;
            if (v < target) lo = mid + 1;
            else hi = mid - 1;
        }
        lo = peak + 1; hi = n - 1;
        while (lo <= hi) {                       // 第三次二分：峰右侧降序段
            int mid = lo + (hi - lo) / 2;
            int v = mountainArr.get(mid);
            if (v == target) return mid;
            if (v > target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def findInMountainArray(self, target: int, mountainArr: "MountainArray") -> int:
        n = mountainArr.length()
        lo, hi = 0, n - 1
        while lo < hi:                           # 第一次二分：找峰顶下标 peak
            mid = (lo + hi) // 2
            if mountainArr.get(mid) < mountainArr.get(mid + 1):
                lo = mid + 1
            else:
                hi = mid
        peak = lo
        lo, hi = 0, peak
        while lo <= hi:                          # 第二次二分：峰左侧升序段
            mid = (lo + hi) // 2
            v = mountainArr.get(mid)
            if v == target:
                return mid
            if v < target:
                lo = mid + 1
            else:
                hi = mid - 1
        lo, hi = peak + 1, n - 1
        while lo <= hi:                          # 第三次二分：峰右侧降序段
            mid = (lo + hi) // 2
            v = mountainArr.get(mid)
            if v == target:
                return mid
            if v > target:
                lo = mid + 1
            else:
                hi = mid - 1
        return -1
```

## 8. 边界情况与易错点

1. **`get` 次数超限**：线性扫描 $10^4$ 次必然超限；三段二分约 56 次，留有余量。
2. **峰顶下标越界**：峰顶二分里访问 `mid+1`，必须保证 `mid<hi`；用 `lo+(hi-lo)/2` 恰好满足。
3. **左段区间写成 $[0,peak)$**：会漏掉峰顶上的 `target`（示例 3）。
4. **先查右段**：会返回较大的下标，违反「返回最小下标」。
5. **递减段比较方向写反**：`get(mid) > target` 时应往右走，写反会得到 $-1$ 或死循环。
6. **`target` 比所有元素都大 / 都小**：两段二分都会失败，返回 $-1$。
7. **$n=3$**：峰顶必为下标 1，峰顶二分 1 轮收敛，左段 $[0,1]$ 与右段 $[2,2]$ 各至多 2 次 `get`。
8. **参数顺序**：C++/Python 官方签名是 `(target, mountainArr)`，写反会编译失败或逻辑错乱。
9. **重复值**：山脉数组严格单调，同一值最多出现两次（分居峰两侧），不会出现「平台」，因此无需处理相等分支。
