# LeetCode 拼车 题解

## 1. 题目概述

- **标题 / 题号**：拼车（#1094，medium）
- **链接**：https://leetcode.cn/problems/car-pooling/
- **来源**：LeetCode 第 142 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和、差分、排序、模拟

**题意**：车一开始有 `capacity` 个空位，只能沿一个方向行驶。`trips[i] = [numPassengers, from, to]` 表示第 $i$ 批 `numPassengers` 位乘客在位置 `from` 上车、在位置 `to` 下车（位置是向东的公里数）。**乘客先下车后上车**，要求路线上任何一点车内人数都不超过 `capacity`。能接送完所有行程返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{trips.length} \le 1000$
- $1 \le \text{numPassengers}_i \le 100$
- $0 \le \text{from}_i < \text{to}_i \le 1000$
- $1 \le \text{capacity} \le 10^5$

> 💡 两个细节决定了正确性：行程占的是**半开区间** $[\text{from}, \text{to})$（到 `to` 就下车了），以及**先下后上**——同一位置上车的人数不与该位置下车的人数叠加。

## 2. 示例

**示例 1**

```text
输入：trips = [[2,1,5],[3,3,7]], capacity = 4
输出：false
解释：位置 3..4 车内 2+3 = 5 人，超过 4。
```

**示例 2**

```text
输入：trips = [[2,1,5],[3,3,7]], capacity = 5
输出：true
解释：峰值 5 人，恰好等于容量。
```

**示例 3（自造，专测「先下后上」）**

```text
输入：trips = [[3,0,2],[2,2,4]], capacity = 3
输出：true
解释：位置 2 处第一批 3 人先下车、第二批 2 人再上车，峰值只有 3；
     若把区间当成闭区间 [0,2] 与 [2,4]，会误判为 3+2=5 > 3 → false。
```

## 3. 解题思路

### 3.1 暴力思路

对每个位置 $p\in[0,1000]$，累加所有满足 $\text{from}_i \le p < \text{to}_i$ 的 `numPassengers`，与 `capacity` 比较。复杂度 $O(n\cdot P)$，其中 $P=1001$，$n\le1000$，总量约 $10^6$，能过；但每个位置都要重扫一遍全部行程，属于典型的「区间加、单点查」重复劳动。若位置范围放大到 $10^9$，这个做法直接失效。

### 3.2 核心观察：区间加 → 差分数组 → 前缀和

![区间加 → 差分数组 → 前缀和即车上人数](images/wc142_q2_diff_array.svg)

每个行程对载客数的贡献，是给区间 $[\text{from}, \text{to})$ 上的每个位置**加上** `numPassengers`。这是标准的「区间加、最后整体求值」，用**差分数组**一步搞定：

$$\text{diff}[\text{from}] \mathrel{+}= \text{num},\qquad \text{diff}[\text{to}] \mathrel{-}= \text{num}$$

前缀和 $cur(p)=\sum_{i\le p}\text{diff}[i]$ 就是位置 $p$ 的车内人数。为什么右端点是 `to` 而不是 `to - 1`？因为乘客到 `to` 就下车，位置 `to` 上不应该再算他们——这正是**半开区间**的含义，也天然实现了「先下后上」。

> 💡 差分把 $n$ 次区间加从 $O(nP)$ 压到 $O(n)$，再花 $O(P)$ 做一次前缀和，总复杂度 $O(n+P)$。

### 3.3 算法流程

![拼车判定流程](images/wc142_q2_flow.svg)

```text
1. diff[0..1001] 全部置 0
2. for [num, from, to] in trips:
       diff[from] += num
       diff[to]   -= num
3. cur = 0
   for p = 0 .. 1001:
       cur += diff[p]
       若 cur > capacity: 返回 false
4. 返回 true
```

### 3.4 示例演算

![示例 1 逐位置演算](images/wc142_q2_walkthrough.svg)

对示例 1（`trips = [[2,1,5],[3,3,7]]`，`capacity = 4`）：差分只有四处非零——`diff[1] = +2`、`diff[5] = -2`、`diff[3] = +3`、`diff[7] = -3`。前缀和按位置展开：

| 位置 $p$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 本点上客 | 0 | 2 | 0 | 3 | 0 | 0 | 0 | 0 |
| 本点下客 | 0 | 0 | 0 | 0 | 0 | 2 | 0 | 3 |
| $cur(p)$ | 0 | 2 | 2 | 5 | 5 | 3 | 3 | 0 |
| $\le 4$? | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ |

位置 3、4 处 $cur=5>4$，返回 `false`；把容量改成 5 则全程不超过 5，返回 `true`。

## 4. 算法细节

1. **差分数组长度**：`to` 最大可取 1000，`diff[1000] -= num` 必须落在数组内，所以长度取 `1001 + 1`（代码里的 `MAXP = 1001`，数组大小 `MAXP + 1`）。
2. **半开区间**：写 `diff[to] -= num`，不要写 `diff[to - 1] -= num` 或 `diff[to + 1] -= num`，前者会漏掉「到站即下车」，后者会越界。
3. **先下后上**：前缀和在位置 $p$ 处把 `-num` 与 `+num` 都算进去后再判超载，等价于「先下后上」；若先上后下，就得拆成两次判定，反而更麻烦。
4. **扫描范围**：只需扫 $0..1000$，代码多扫一格到 1001 是为了让所有 `diff[1001]` 的写入（其实没有）也被消费，属于保险写法。
5. **溢出**：载客总和最多 $1000\times100 = 10^5$，`int` 足够；`capacity` 也 $\le 10^5$，比较时不会溢出。
6. **提前返回**：一旦某位置超载就可以立即 `false`，不必扫完。
7. **不需要排序**：差分与原顺序无关，「按位置有序」这件事由下标本身承担。

## 5. 正确性证明

记 $D$ 为算法构造的差分数组，$cur(p)=\sum_{i\le p}D[i]$。

**引理 1（前缀和还原区间加）**：对任意 $p\ge0$，

$$cur(p)=\sum_{i:\ \text{from}_i \le p < \text{to}_i} \text{num}_i$$

**证明**：每个行程 $i$ 对 $D$ 的贡献是 $+\text{num}_i$ 于 `from`、$-\text{num}_i$ 于 `to`，故它对 $cur(p)$ 的贡献为

$$\text{num}_i\cdot\bigl([\text{from}_i \le p]-[\text{to}_i \le p]\bigr)=\text{num}_i\cdot[\text{from}_i\le p<\text{to}_i]$$

对 $i$ 求和即得结论。∎

**引理 2（位置内人数恒定）**：相邻两个整数位置之间（即开区间 $(p,p+1)$ 内）没有任何上、下车事件，故车内人数恒等于 $cur(p)$。

**证明**：所有 `from`、`to` 都是整数，事件只发生在整数位置；$p$ 到 $p+1$ 之间无事件，人数不变。∎

**引理 3（判定等价）**：方案可行 $\iff$ 对一切整数 $p\in[0,1000]$ 有 $cur(p)\le \text{capacity}$。

**证明**：由引理 2，路线上任意时刻的人数都等于某个 $cur(p)$（$p$ 取该时刻所在区间的左端点）。故若所有 $cur(p)\le$ 容量，则任意时刻都不超载；反之若有 $p$ 使 $cur(p)>\text{capacity}$，则区间 $(p,p+1)$ 内超载，方案不可行。∎

**定理**：算法返回 `true` 当且仅当可以接送完所有行程。

**证明**：算法在任一 $p$ 满足 $cur(p)>\text{capacity}$ 时返回 `false`，否则扫完返回 `true`；由引理 3，这恰好等价于方案可行。∎

## 6. 复杂度分析

- **时间**：$O(n+P)$。构造差分遍历 `trips` 一次 $O(n)$，前缀和扫描 $O(P)$，$P=1001$ 是常数级。
- **空间**：$O(P)$，仅一个差分数组；不计输入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool carPooling(vector<vector<int>>& trips, int capacity) {
        const int MAXP = 1001;                   // 位置上限 1000，多留一格
        vector<int> diff(MAXP + 1, 0);
        for (const auto& t : trips) {
            int num = t[0], from = t[1], to = t[2];
            diff[from] += num;                   // 在 from 上车
            diff[to] -= num;                     // 到 to 即下车（先下后上）
        }
        int cur = 0;
        for (int p = 0; p <= MAXP; p++) {
            cur += diff[p];                      // 位置 p 处车上人数
            if (cur > capacity) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def carPooling(self, trips: list[list[int]], capacity: int) -> bool:
        MAXP = 1001                              # 位置上限 1000，多留一格
        diff = [0] * (MAXP + 1)
        for num, start, end in trips:
            diff[start] += num                   # 在 start 上车
            diff[end] -= num                     # 到 end 即下车（先下后上）
        cur = 0
        for p in range(MAXP + 1):
            cur += diff[p]                       # 位置 p 处车上人数
            if cur > capacity:
                return False
        return True
```

## 8. 边界情况与易错点

1. **半开区间写成闭区间**：用 `diff[to + 1] -= num` 需要数组开到 1002，且语义上把「到站下车」变成「过站下车」，示例 3 会误判。
2. **`to = 1000` 越界**：数组只开 1001 时，`diff[1000]` 合法但 `diff[1000] -= num` 之外若还写 `diff[to+1]` 就越界。
3. **先下后上**：同一位置 $p$ 的 `-num` 与 `+num` 必须都计入后再判定，不能把上车人数与下车人数相加。
4. **单批人数超过容量**：`num > capacity` 时，该批次自己就超载，前缀和会在 `from` 处立刻暴露。
5. **`from = 0`**：扫描必须从 $p=0$ 开始，否则会漏掉起点上车的人。
6. **总人数不超过容量**：直接全 `true`，代码逻辑自然成立，无需特判。
7. **差分可能写出负值**：`diff[to]` 为负是正常的，不要误以为数组出错。
8. **中途断档**：`trips` 的位置不连续不影响正确性，前缀和在无事件处保持不变。
