# LeetCode 花括号展开 II 题解

## 1. 题目概述

- **标题 / 题号**：花括号展开 II（#1096，hard）
- **链接**：https://leetcode.cn/problems/brace-expansion-ii/
- **来源**：LeetCode 第 142 场周赛 Q4
- **难度**：困难
- **标签**：栈、广度优先搜索、哈希表、字符串、回溯、排序

**题意**：表达式只由花括号 `{}`、逗号 `,` 和小写字母组成，语义按三条规则递归定义：

1. 单一元素 $x$ 表示字符串集合 $\{x\}$；
2. **逗号并列**表示**并集**：$R(\{e_1,e_2,\dots\})=R(e_1)\cup R(e_2)\cup\cdots$；
3. **相邻相接**表示**连接**（笛卡尔积）：$R(e_1e_2)=\{a+b \mid a\in R(e_1), b\in R(e_2)\}$。

括号允许任意嵌套。要求返回表达式所表示的全部字符串，**去重**且按**字典序**排列。

**约束**：

- $1 \le \text{expression.length} \le 60$
- `expression[i]` 只含 `{`、`}`、`,` 与小写字母
- 输入一定是合法表达式

> 💡 与 I 版的区别：I 版（#1087）只有单层花括号、没有嵌套，可以直接按逗号切分；本题允许任意嵌套，必须先立文法再解析。

## 2. 示例

**示例 1**

```text
输入：expression = "{a,b}{c,{d,e}}"
输出：["ac","ad","ae","bc","bd","be"]
解释：{a,b} 与 {c,d,e} 做笛卡尔积，共 6 个串。
```

**示例 2**

```text
输入：expression = "{{a,z},a{b,c},{ab,z}}"
输出：["a","ab","ac","z"]
解释：{a,z} ∪ {ab,ac} ∪ {ab,z} = {a,z,ab,ac}，去重后按字典序排列。
      ab 由第二个与第三个并列项各贡献一次，只保留一份。
```

**示例 3（自造，考查优先级与去重）**

```text
输入：expression = "a{b,c}d"
输出：["abd","acd"]
解释：相邻是拼接（优先级高），所以是 a × {b,c} × d，而不是 a ∪ {b,c} ∪ d。
```

## 3. 解题思路

### 3.1 暴力思路

把表达式当成字符串反复展开：找到最内层（即内部不再含花括号）的一个 `{...}`，按顶层逗号切成若干备选，各自替换进原串，得到一批新表达式；重复直到没有花括号为止。正确性没问题（就是语义的直接转写），但每轮都要重新扫描整串，且中间会产生大量重复串，效率与代码整洁度都差。更糟的是很容易写错「最内层」的判定。

另一种常见错解是「先按逗号 split，再拼接」——它在 `{a,b}{c,d}` 这种相邻结构上会直接把逗号当成分隔符，得到错误结果，因为它忽视了**逗号优先级最低**。

### 3.2 核心观察：三层文法 + 集合运算

![表达式的三层文法与两种集合运算](images/wc142_q4_grammar.svg)

把语义整理成三层文法，优先级从低到高：

```text
expr   := term (',' term)*        逗号并列 → 并集 ∪
term   := factor+                 相邻相接 → 笛卡尔积 ×
factor := '{' expr '}' | 小写字母  括号只做分组
```

关键点：**逗号优先级最低**（并集），**相邻拼接次之**（笛卡尔积），括号最高（只改变分组）。这正好对应 `"{a,b}c" = {ac, bc}`、`"a{b,c}d" = {abd, acd}`。

由于求值结果始终是**字符串集合**，而并集与笛卡尔积都满足结合律，因此只要按文法递归下降，把每个非终结符翻译成一个集合运算即可，**天然去重**（用 `set`），最后排序输出。

> 💡 不用 DFS 枚举所有串再过滤重复：`set` 在构造过程中就把重复扼杀了，代码更短也更快。

### 3.3 算法流程

![递归下降：三个函数共享一个游标 pos](images/wc142_q4_parse_flow.svg)

```text
parseExpr():
    res = parseTerm()
    while 下一个字符 == ',':
        pos++                      # 跳过逗号
        res = res ∪ parseTerm()
    return res

parseTerm():
    res = parseFactor()
    while 下一个字符 ∈ { '{' } ∪ 小写字母:      # 还有相邻因子
        res = { a + b | a ∈ res, b ∈ parseFactor() }
    return res

parseFactor():
    if 当前字符 == '{':
        pos++                      # 跳过 '{'
        res = parseExpr()          # 括号内是完整的 expr（可含逗号）
        pos++                      # 跳过 '}'
        return res
    else:
        ch = 当前字符; pos++
        return { ch }

主函数: return sorted(parseExpr())
```

### 3.4 示例演算

![示例 2 的求值过程](images/wc142_q4_walkthrough.svg)

对示例 2 的 `"{{a,z},a{b,c},{ab,z}}"`：最外层花括号内部是三个并列的 term。

| 并列项 | 求值过程 | 结果集合 |
|---|---|---|
| `{a,z}` | 一个 factor：括号内 `a,z` 按逗号取并 | $\{a,z\}$ |
| `a{b,c}` | 两个 factor 相邻：`a` × `{b,c}` | $\{ab,ac\}$ |
| `{ab,z}` | 一个 factor：括号内 `ab,z` 取并 | $\{ab,z\}$ |

三者取并集：$\{a,z\}\cup\{ab,ac\}\cup\{ab,z\}=\{a,z,ab,ac\}$，排序后输出 `["a","ab","ac","z"]`。注意 `ab` 出现两次，被 `set` 去重；`{ab,z}` 中的 `ab` 是一个整体字母串，不会被拆成 `a` 和 `b`。

## 4. 算法细节

1. **共享游标 `pos`**：三个函数读写同一个下标，C++ 用成员变量，Python 用 `nonlocal`。这样每个字符只被消费一次，总代价线性于「消费次数 × 集合规模」。
2. **`parseTerm` 的循环条件**：下一个字符是 `{` 或小写字母 → 还有相邻因子；是 `,`、`}` 或已到末尾 → term 结束。这个判断是切分正确性的关键。
3. **`parseFactor` 的括号处理**：`'{'` 之后必须调用 `parseExpr`（而不是 `parseTerm`），因为括号内部可以是逗号并列；然后跳过 `}`。
4. **`set` 的字典序**：C++ 的 `std::set<std::string>` 按默认 `operator<` 排序，正好是字典序且唯一，直接 `vector(set.begin(), set.end())` 即为答案；Python 用 `sorted(set)`。
5. **不要用 `islower(char)`**：`<cctype>` 的函数接受 `int`，传入负值 `char` 是未定义行为；直接写 `ch >= 'a' && ch <= 'z'` 更安全（Python 的 `str.islower()` 无此问题）。
6. **去重发生在何处**：并集天然去重；笛卡尔积可能产生重复串（当两侧集合有交时），`set` 插入也会吸收。
7. **长度与规模的直觉**：每多一个「二选一」的组至少要 5 个字符（如 `{a,b}`），长度 60 时输出规模在 $10^4$ 量级以内，直接枚举完全安全。
8. **结果串长度**：不超过原表达式长度（去掉括号与逗号后最多 60），因此字符串比较代价很小。

## 5. 正确性证明

设 $R(\cdot)$ 为题面三条规则定义的语义函数，$S(f)$ 表示函数 `parse*` 的返回值。

**引理 1（factor 正确）**：对任意 `factor` 片段 $f$，`parseFactor` 返回 $R(f)$。

**证明**：分两种情形。若 $f$ 是单个小写字母 $c$，规则 1 给出 $R(f)=\{c\}$，代码返回 `{c}`。若 $f=\{\,e\,\}$，规则 2、3 下括号只表示分组，$R(\{\,e\,\})=R(e)$，代码递归调用 `parseExpr` 并跳过 `}`，由引理 3（对更短的 $e$ 归纳）返回 $R(e)$。∎

**引理 2（term 正确且切分唯一）**：对任意 `term` 片段 $t=f_1f_2\cdots f_k$（$k\ge1$），`parseTerm` 返回 $R(t)$，且恰好消费完 $t$ 的全部字符。

**证明**：对 $k$ 归纳。$k=1$ 时由引理 1 直接成立，且 `parseFactor` 消费掉 $f_1$ 的全部字符，此后下一个字符必为 `,`、`}` 或末尾（因为 $t$ 只有这一个因子），循环条件为假。
设 $k>1$，`parseFactor` 先消费 $f_1$ 得 $S_1=R(f_1)$（引理 1）。由于 $f_2$ 的首字符是 `{` 或字母，循环条件为真；归纳假设对 $f_2\cdots f_k$ 成立，最终 $res$ 逐步变成 $R(f_1f_2\cdots f_j)$（每次取笛卡尔积，符合规则 3）。循环在消费完 $f_k$ 后停止，因为 term 的定义中 `,` 与 `}` 都不是因子的首字符。∎

**引理 3（expr 正确）**：对任意 `expr` 片段 $e=t_1,t_2,\dots,t_m$（$m\ge1$），`parseExpr` 返回 $R(e)$。

**证明**：对 $m$ 归纳。$m=1$ 时由引理 2 成立。$m>1$ 时，第一个 term 消费完后下一个字符必为 `,`，代码跳过逗号并递归求下一个 term，再用 `set::insert` 取并集（规则 2）。归纳至 $m$ 个 term 全部并入。∎

**定理**：`braceExpansionII` 返回的数组是 $R(\text{expression})$ 的全部元素，无重复且按字典序升序。

**证明**：由引理 3，`parseExpr()` 的返回值作为集合恰为 $R(\text{expression})$；`std::set` 保证元素唯一且按 `operator<`（字符串字典序）升序；转成 `vector` 后顺序不变。故返回数组既不重不漏、又是字典序。∎

## 6. 复杂度分析

设 $n=\lvert\text{expression}\rvert\le60$，$R$ 为输出集合大小，$L\le n$ 为单个结果串的长度。

- **时间**：每个字符被消费常数次；主要开销是笛卡尔积与集合插入。拼接的总次数不超过「各中间集合大小之和」，与 $R\cdot L$ 同阶；每次插入 `set` 需 $O(L\log R)$ 次字符比较。故总体可写为 $O(R\cdot L\cdot n\log R)$ 的量级。由于 $n\le60$ 且结果规模在 $10^4$ 量级，实际运行很快。
- **空间**：$O(R\cdot L)$ 存全部结果；递归深度不超过括号嵌套层数，$O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> braceExpansionII(string expression) {
        s = expression;
        pos = 0;
        set<string> res = parseExpr();
        return vector<string>(res.begin(), res.end());   // set 已按字典序
    }

private:
    string s;
    int pos = 0;

    // expr := term (',' term)*   —— 逗号表示并集
    set<string> parseExpr() {
        set<string> res = parseTerm();
        while (pos < (int)s.size() && s[pos] == ',') {
            pos++;                                  // 跳过 ','
            set<string> t = parseTerm();
            res.insert(t.begin(), t.end());
        }
        return res;
    }

    // term := factor+           —— 相邻表示拼接（笛卡尔积）
    set<string> parseTerm() {
        set<string> res = parseFactor();
        while (pos < (int)s.size() && (s[pos] == '{' || (s[pos] >= 'a' && s[pos] <= 'z'))) {
            set<string> f = parseFactor();
            set<string> nxt;
            for (const string& a : res)
                for (const string& b : f)
                    nxt.insert(a + b);
            res.swap(nxt);
        }
        return res;
    }

    // factor := '{' expr '}' | 单个小写字母
    set<string> parseFactor() {
        if (s[pos] == '{') {
            pos++;                                  // 跳过 '{'
            set<string> res = parseExpr();
            pos++;                                  // 跳过 '}'
            return res;
        }
        return {string(1, s[pos++])};
    }
};
```

### Python

```python
class Solution:
    def braceExpansionII(self, expression: str) -> list[str]:
        s, pos = expression, 0

        # expr := term (',' term)*    逗号表示并集
        def parse_expr() -> set:
            nonlocal pos
            res = parse_term()
            while pos < len(s) and s[pos] == ',':
                pos += 1                                 # 跳过 ','
                res |= parse_term()
            return res

        # term := factor+             相邻表示拼接（笛卡尔积）
        def parse_term() -> set:
            nonlocal pos
            res = parse_factor()
            while pos < len(s) and (s[pos] == '{' or s[pos].islower()):
                f = parse_factor()
                res = {a + b for a in res for b in f}
            return res

        # factor := '{' expr '}' | 单个小写字母
        def parse_factor() -> set:
            nonlocal pos
            if s[pos] == '{':
                pos += 1                                 # 跳过 '{'
                res = parse_expr()
                pos += 1                                 # 跳过 '}'
                return res
            ch = s[pos]
            pos += 1
            return {ch}

        return sorted(parse_expr())
```

## 8. 边界情况与易错点

1. **纯字母**：`"a"` → `["a"]`；`"ab"` → `["ab"]`（相邻即拼接，不是并集）。
2. **单层花括号**：`"{a,b}"` → `["a","b"]`；嵌套同义 `"{{a,b},{b,c}}"` → `["a","b","c"]`（去重）。
3. **逗号优先级最低**：`"{a,b}c"` 必须是 `{ac,bc}`；若把逗号当最外层分隔符会得到 `{"a","bc"}`。
4. **`{a}` 这种单元素括号**：返回 `{a}`，不影响集合大小，代码天然正确。
5. **`islower` 的未定义行为**：`islower(char)` 在 `char` 为负时是 UB，用范围比较替代。
6. **游标越界**：`parseTerm` 的循环条件必须先判 `pos < n` 再取 `s[pos]`，否则末尾会越界读。
7. **括号左后直接是 `}`**：合法表达式不会出现空 term（`{}`），但 `parseExpr` 也从未被设计成支持空串，输入保证不需要。
8. **结果规模**：`"a{b,c}{d,e}f{g,h}"` 有 $2^4=16$ 个结果，全部保留、不要漏乘。
9. **顺序**：题目要求字典序，`set` 直接满足；若用 `unordered_set` 必须手动排序。
