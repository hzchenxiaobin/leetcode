# LeetCode 三角形类型 题解

## 1. 题目概述

- **标题 / 题号**：三角形类型（#3024，easy）
- **链接**：https://leetcode.cn/problems/type-of-triangle/
- **来源**：LeetCode 第 123 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学、排序

**题意**：给一个长度为 $3$ 的整数数组 nums，把它当作三条边的长度。若三条边围不成三角形，返回 `"none"`；否则按边的相等情况返回：三边全等为 `"equilateral"`，恰好两边相等为 `"isosceles"`，三边互不相等为 `"scalene"`。

**约束**：

- nums.length == 3
- 1 <= nums[i] <= 100

## 2. 示例

**示例 1**

```text
输入：nums = [3,3,3]
输出："equilateral"
解释：三条边长度相等，构成等边三角形。
```

**示例 2**

```text
输入：nums = [3,4,5]
输出："scalene"
解释：3+4=7 > 5，3+5=8 > 4，4+5=9 > 3，三组不等式都成立；
      三条边互不相等，所以是 scalene。
```

**示例 3（边界补充）**

```text
输入：nums = [1,1,2]
输出："none"
解释：1+1 = 2，没有严格大于第三边。三点共线，退化成一条线段，不算三角形。
```

## 3. 解题思路

### 3.1 暴力思路

题目只要求判定，谈不上搜索：最直接的做法是**逐条验证三组不等式** $nums[0]+nums[1] > nums[2]$、$nums[0]+nums[2] > nums[1]$、$nums[1]+nums[2] > nums[0]$，再数一数有几条边相等。这样写不算错，但三组不等式要写三遍、相等关系又要分支，代码冗长且容易漏掉某一条。

真正的优化点不在复杂度（$n$ 恒为 $3$，怎么算都是 $O(1)$），而在**把判断压缩成两个短句**。

### 3.2 核心观察：排序之后只剩一条不等式

![判定流程：先排序，再逐级判断](images/bw123_q1_decision_flow.svg)

先把三边排序成 $a \le b \le c$。此时：

1. **三角形不等式只需验一条**：$a + b > c$ 成立时，$a + c > b$ 与 $b + c > a$ 自动成立。因为 $c$ 最大，$a + c > b$ 等价于「最大的加一个正数大于中间的」，显然成立；$b + c > a$ 同理。
2. **类型只需看相等关系**：排序后首尾相等 $a = c$ 就说明三边全等；否则只要 $a = b$ 或 $b = c$ 就说明恰有两边相等；都不满足则三边互异。

于是判定变成一条链：先排除退化，再判断全等，再判断等腰，最后落到不等边。

![把 a、b 首尾接起来与 c 比长短](images/bw123_q1_side_relation.svg)

上图把「$a+b>c$」具象化为一次比长短：把 $a$、$b$ 两条线段首尾相接，与 $c$ 放在同一起点比较。接起来比 $c$ 长才能闭合出三角形；恰好等长则三点共线（退化）；比 $c$ 短则两头根本接不上。

### 3.3 算法流程

按上面的链条顺序判断，任何一步命中就直接返回：

```text
1. 排序 nums，记 a = nums[0], b = nums[1], c = nums[2]
2. 若 a + b <= c        → 返回 "none"
3. 若 a == c            → 返回 "equilateral"
4. 若 a == b 或 b == c   → 返回 "isosceles"
5. 否则                  → 返回 "scalene"
```

顺序不能调换：`a == c` 必须在等腰判断之前，否则等边三角形会被误判成等腰。

### 3.4 示例演算

![常见输入走一遍判定表](images/bw123_q1_example_table.svg)

以示例 2 的 `[3,4,5]` 为例：排序后仍是 `3,4,5`；$3+4=7>5$ 通过；$a=3 \ne c=5$；$a=3 \ne b=4$ 且 $b=4 \ne c=5$；落到最后一行返回 `"scalene"`。

再看 `[3,3,4]`：$3+3=6>4$ 通过；$a=3 \ne c=4$；但 $a=b=3$，返回 `"isosceles"`。而 `[1,1,2]` 在第一步就因 $1+1=2 \le 2$ 被拦下，返回 `"none"`。

## 4. 算法细节

1. **排序代替三组比较**：`sort` 三个数代价可忽略，却把「谁是斜边」这件事一次说清。
2. **退化判定用 `<=`**：$a+b=c$ 时三点共线，围不出面积，必须返回 `"none"`；写成 `<` 会把 `[1,1,2]` 误判为等腰。
3. **等边用 `a == c`**：在 $a \le b \le c$ 的前提下，首尾相等即三边全等，不必写成三个 `&&`。
4. **等腰用 `a == b || b == c`**：排序后中间那条边一定参与相等关系，所以只需检查相邻两对，无需检查 $a == c$（那是等边，已在上一行拦掉）。
5. **返回值是固定小写字符串**：`"none"`、`"equilateral"`、`"isosceles"`、`"scalene"`，拼错一个字母就错。
6. **纯整数运算**：边长都是整数，比较全用整数，不需要开根号或浮点。

## 5. 正确性证明

**引理 1**：设 $a \le b \le c$，则三条边能构成三角形当且仅当 $a + b > c$。

**证明**：必要性显然——三角形任意两边之和大于第三边，取 $a, b$ 即得。充分性：若 $a + b > c$，则 $a + c > a + b > c > b$（因为 $a > 0$），故 $a + c > b$；同理 $b + c > b + a > c > a$，故 $b + c > a$。三组不等式全部成立，由三角形不等式定理可知三边可构成三角形。∎

**引理 2**：设 $a \le b \le c$ 且已通过引理 1 的检验，则

- $a = c$ 当且仅当三边全等；
- 在 $a \ne c$ 时，$a = b$ 或 $b = c$ 当且仅当恰有两边相等。

**证明**：$a = c$ 配合 $a \le b \le c$ 得 $a = b = c$，三边全等；反之三边全等当然有 $a = c$。若 $a \ne c$，则 $a < c$，排序后至少有一条相邻对相等才会出现两边相等：$a = b$（此时 $b < c$，恰两边相等）或 $b = c$（此时 $a < b$，恰两边相等）；两者都不成立时 $a < b < c$，三边互异。∎

**定理**：上述算法对任意长度 $3$ 的正整数数组返回正确的三角形类型。

**证明**：排序不改变元素集合，故不影响「能否成三角形」与「边的相等情况」。若 $a + b \le c$，由引理 1 不能成三角形，算法返回 `"none"` 正确。否则能成三角形，依次检查：$a = c$ 时由引理 2 为等边，返回 `"equilateral"`；$a \ne c$ 且 $a = b$ 或 $b = c$ 时由引理 2 恰有两边相等，返回 `"isosceles"`；剩余情形 $a < b < c$ 三边互异，返回 `"scalene"`。三条分支互斥且覆盖全部情形，故返回值唯一且正确。∎

## 6. 复杂度分析

- **时间**：$O(1)$。排序固定 $3$ 个元素，后续判断都是常数次比较；若按一般写法记为 $O(n \log n)$，这里 $n = 3$。
- **空间**：$O(1)$。C++ 的 `sort` 原地排序，Python 的 `sorted` 会额外产生长度 $3$ 的列表，也是常数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string triangleType(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int a = nums[0], b = nums[1], c = nums[2];
        if (a + b <= c) return "none";       // 两边之和不大于第三边 → 退化，无法成三角形
        if (a == c) return "equilateral";    // 排序后首尾相等 ⇔ 三边相等
        if (a == b || b == c) return "isosceles";
        return "scalene";
    }
};
```

### Python

```python
class Solution:
    def triangleType(self, nums: list[int]) -> str:
        a, b, c = sorted(nums)
        if a + b <= c:
            return "none"
        if a == c:
            return "equilateral"
        if a == b or b == c:
            return "isosceles"
        return "scalene"
```

> 💡 两份代码均通过官方示例（`"equilateral"`、`"scalene"`）以及 `[1,1,2]`、`[2,3,2]`、`[1,2,2]`、`[100,100,100]` 等边界，C++ 与 Python 输出一致。

## 8. 边界情况与易错点

1. **退化三角形**：$a + b = c$ 必须判为 `"none"`，条件写成 `<=`。这是本题最容易错的地方。
2. **乱序输入**：`[2,3,2]` 必须先排序再判断，否则直接比较 `nums[0] + nums[1] > nums[2]` 会得出 `2+3 > 2` 而漏判类型。
3. **判断顺序**：等边要先于等腰判断。若先判 `a == b`，`[3,3,3]` 会返回 `"isosceles"`。
4. **等腰只需两对相邻边**：排序后 `a == b || b == c` 已覆盖全部「恰有两边相等」的情形，再写 `a == c` 是冗余（等价于等边）。
5. **字符串常量拼写**：`equilateral`、`isosceles`、`scalene` 都是长单词，建议直接从题面复制。
6. **不要用浮点**：本题只需大小比较与相等判断，引入 `double` 反而可能带来精度问题。
7. **边长下界是 1**：不存在 $0$ 或负数边，无需额外处理零边、负边这类退化输入。
