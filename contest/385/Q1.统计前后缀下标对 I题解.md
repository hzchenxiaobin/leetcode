# LeetCode 统计前后缀下标对 I 题解

## 1. 题目概述

- **标题 / 题号**：统计前后缀下标对 I（#3042，easy）
- **链接**：https://leetcode.cn/problems/count-prefix-and-suffix-pairs-i/
- **来源**：LeetCode 第 385 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、字符串匹配、枚举

**题意**：给定字符串数组 `words`，定义 `isPrefixAndSuffix(str1, str2)`：当 `str1` **同时**是 `str2` 的前缀**和**后缀时为 true。返回满足 `i < j` 且 `isPrefixAndSuffix(words[i], words[j])` 为 true 的下标对 `(i, j)` 的数量。

**约束**：

- `1 <= words.length <= 50`
- `1 <= words[i].length <= 10`
- `words[i]` 仅由小写英文字母组成

> 💡 数据范围极小（50 个长度至多 10 的字符串），这题是签到题，直接双重循环暴力即可，不需要任何高级数据结构。同场 Q4（#3045）是本题的数据加强版（`words.length <= 10^5`），才需要字典树 / 字符串哈希。

## 2. 示例

**示例 1**

```text
输入：words = ["a","aba","ababa","aa"]
输出：4
解释：(0,1)、(0,2)、(0,3) 中 "a" 是三个字符串的前后缀；
      (1,2) 中 "aba" 是 "ababa" 的前后缀。
```

**示例 2**

```text
输入：words = ["pa","papa","ma","mama"]
输出：2
解释：(0,1) "pa" 是 "papa" 的前后缀；(2,3) "ma" 是 "mama" 的前后缀。
```

**示例 3**

```text
输入：words = ["abab","ab"]
输出：0
解释：唯一候选 (0,1)，但 "abab" 比 "ab" 长，不能是它的前后缀。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 `(i, j)`（`i < j`），对每一对调用一次 `isPrefixAndSuffix(words[i], words[j])` 判定，统计为 true 的数量。

对数至多 `50 × 49 / 2 = 1225` 个，每次判定至多比较 `2 × 10` 个字符，总操作数约 `2.5 万`，远低于任何时限约束。

### 3.2 核心观察：前后缀判定可以一步完成

![isPrefixAndSuffix 判定：既是前缀又是后缀](images/wc385_q1_prefix_suffix_concept.svg)

判定 `str1` 是否同时是 `str2` 的前缀和后缀，只需三个条件：

1. **长度门槛**：`|str1| <= |str2|`（长串不可能是短串的前后缀）；
2. **前缀相等**：`str2` 的开头 `|str1|` 个字符等于 `str1`；
3. **后缀相等**：`str2` 的末尾 `|str1|` 个字符等于 `str1`。

三者同时成立即返回 true。注意长度相等时（`|str1| == |str2|`）条件 2、3 退化为 `str1 == str2`——**字符串本身也是自己的前缀和后缀**，所以两个内容相同、下标不同的字符串是一对合法答案。

### 3.3 算法流程：双重循环

![暴力双重循环流程](images/wc385_q1_double_loop_flow.svg)

外层枚举 `j`（被判断的 `str2`），内层枚举所有 `i < j`（候选的 `str1`），按「长度 → 前缀 → 后缀」的顺序短路判定，全部通过则计数加一。

### 3.4 示例演算

![示例 1 的上三角判定矩阵](images/wc385_q1_example_walkthrough.svg)

以 `words = ["a","aba","ababa","aa"]` 为例，列出 `i < j` 的上三角判定矩阵：绿色 ✓ 表示通过，红色 ✗ 表示长度不够，虚线 — 表示 `i >= j` 不枚举。共 4 个绿色格子，答案为 4。

## 4. 算法细节

1. **长度检查必须前置**：C++ 中若先算 `y.size() - x.size()`，当 `x` 比 `y` 长时无符号整数下溢得到极大值，`substr` 直接越界抛异常。先判 `x.size() <= y.size()` 再取后缀。
2. **前缀判定**：`y.compare(0, x.size(), x) == 0`，或 Python 直接 `y.startswith(x)`。
3. **后缀判定**：`y.compare(y.size() - x.size(), x.size(), x) == 0`，或 Python 直接 `y.endswith(x)`。
4. **枚举方向**：内层 `i` 严格小于 `j`，即 `for i in range(j)`，天然排除 `i == j`（自身与自身配对）。
5. **判定顺序**：长度 → 前缀 → 后缀，利用短路求值尽早失败，虽然本题规模下无关性能，但是好习惯。

## 5. 正确性证明

**引理 1**：`str1` 是 `str2` 的前缀，当且仅当 `|str1| <= |str2|` 且 `str2[0..|str1|-1] = str1`；`str1` 是 `str2` 的后缀，当且仅当 `|str1| <= |str2|` 且 `str2[|str2|-|str1| .. |str2|-1] = str1`。

**证明**：前缀/后缀的定义即 `str2` 的开头/末尾连续子段与 `str1` 完全相同，该子段存在的前提是其长度 `|str1|` 不超过 `|str2|`。∎

**定理**：双重循环统计的 `ans` 恰为满足条件的下标对数量。

**证明**：循环枚举且仅枚举所有满足 `0 <= i < j <= n-1` 的对（每个有序对恰访问一次，无重复无遗漏）。由引理 1，三条件判定与 `isPrefixAndSuffix(words[i], words[j])` 的定义逐字等价，故每对被计数当且仅当其为有效对。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n^2 * L)`，其中 `n = words.length <= 50`，`L = max |words[i]| <= 10`。共 `O(n^2)` 对，每对判定比较至多 `2L` 个字符。
- **空间复杂度**：`O(1)`。仅用常数变量计数（若用 `substr` 拷贝子串则为 `O(L)`，仍可忽略）。

## 7. 参考代码

### C++

```cpp
class Solution {
    bool isPrefixAndSuffix(const string& x, const string& y) {
        if (x.size() > y.size()) return false;
        return y.compare(0, x.size(), x) == 0 &&
               y.compare(y.size() - x.size(), x.size(), x) == 0;
    }
public:
    int countPrefixSuffixPairs(vector<string>& words) {
        int n = words.size(), ans = 0;
        for (int j = 1; j < n; j++)
            for (int i = 0; i < j; i++)
                if (isPrefixAndSuffix(words[i], words[j])) ans++;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countPrefixSuffixPairs(self, words: List[str]) -> int:
        def ok(x: str, y: str) -> bool:
            return len(x) <= len(y) and y.startswith(x) and y.endswith(x)
        return sum(ok(words[i], words[j])
                   for j in range(len(words)) for i in range(j))
```

## 8. 边界情况与易错点

1. **相同字符串的有效对**：`words = ["ab","ab"]` 答案是 1 不是 0——`i != j` 时内容相同的两个串互为前后缀，别把"字符串等于自身"误判为非法。
2. **不要写成 `i <= j`**：会把自己和自己配对也数进去（如示例 1 会多算 4 个）。
3. **无符号下溢**：C++ 中 `y.size() - x.size()` 在 `x` 更长时是巨大的无符号数而非负数，必须先判长度再取后缀，否则 `substr`/`compare` 越界。
4. **长度相等时的退化**：`|x| == |y|` 时前缀和后缀都是整个串，判定退化为 `x == y`，无需特判，通用逻辑自然覆盖。
5. **单元素数组**：`n == 1` 时无任何 `i < j` 对，答案为 0。
