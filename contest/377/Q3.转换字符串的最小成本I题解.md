# LeetCode 转换字符串的最小成本 I 题解

## 1. 题目概述

- **标题 / 题号**：转换字符串的最小成本 I（#2976，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-convert-string-i/
- **来源**：LeetCode 第 377 场周赛 Q3
- **难度**：中等
- **标签**：图、最短路、Floyd-Warshall、字符串、数组

**题意**：给定两个等长（$n$）的小写串 `source` 与 `target`，以及 $m$ 条**字符转换规则**：花 $\text{cost}[j]$ 的代价可以把**一个**字符 $\text{original}[j]$ 变成 $\text{changed}[j]$。规则可以对任意位置、任意多次使用，同一个字符也可以被连续转换（如 $a \to c \to b$）。求把 `source` 逐位变成 `target` 的最小总成本；无法完成返回 $-1$。

**约束**：

- $1 \le n = \text{source.length} = \text{target.length} \le 10^5$
- $1 \le m = \text{cost.length} = \text{original.length} = \text{changed.length} \le 2000$
- $\text{original}[i]$、$\text{changed}[i]$ 为小写字母，且 $\text{original}[i] \ne \text{changed}[i]$
- $1 \le \text{cost}[i] \le 10^6$

> 💡 读题先抓三个信号：**字符只有 26 种**（图的节点数极小）；**规则可以串联**（$a \to c \to b$，转换是链式的，提示最短路）；**每个位置互不影响**（对位置 $i$ 的操作不干扰其他位置）。三个信号叠加，几乎直接喊出「26 节点有向图上的全源最短路」。

## 2. 示例

**示例 1**

```text
输入：source = "abcd", target = "acbe",
     original = ["a","b","c","c","e","d"], changed = ["b","c","b","e","b","e"],
     cost = [2,5,5,1,2,20]
输出：28
解释：位置 1：b→c 花 5；位置 2：c→e 花 1 再 e→b 花 2（比直连 c→b 的 5 便宜）；
     位置 3：d→e 花 20。总计 5 + 1 + 2 + 20 = 28。
```

**示例 2**

```text
输入：source = "aaaa", target = "bbbb", original = ["a","c"], changed = ["c","b"], cost = [1,2]
输出：12
解释：a→b 没有直连规则，但 a→c→b 成本 1+2 = 3；四位共 3 × 4 = 12。
```

**示例 3**

```text
输入：source = "abcd", target = "abce", original = ["a"], changed = ["e"], cost = [10000]
输出：-1
解释：位置 3 需要 d→e，但唯一规则是 a→e，d 到 e 无任何路径。
```

## 3. 解题思路

### 3.1 暴力思路：直连贪心与逐位现算为何不行

最直观的想法有两种，各有一个致命伤：

- **只用直连规则**：对每位直接取「直连成本」求和。**逻辑错误**——示例 1 的位置 2 需要把 `c` 变 `b`，直连规则要 5，但绕道 $c \to e \to b$ 只要 $1 + 2 = 3$。规则可串联意味着必须考虑**多步转换**。
- **逐位现算最短路**：对每个位置跑一次 Dijkstra。$n$ 高达 $10^5$，每次 $O(m \log m)$，总量约 $10^9$ 量级，C++ 勉强、Python 必挂。

> ⚠️ 第二种做法的浪费在于：**所有查询只落在至多 $26 \times 26 = 676$ 个字符对 $(x, y)$ 上**，却重复算了 $10^5$ 次。把「按位置查询」翻转成「按字符对预计算」，$10^5$ 次最短路就坍缩成一次全源最短路。

### 3.2 核心观察：26 个字母建图 + 位置独立 + 全源最短路

![核心观察：26 个字母建图，转换规则是有向边，位置独立逐位查最短路](images/wc377_q3_char_graph_model.svg)

三步拆解：

1. **建有向带权图**：节点是 26 个小写字母；每条规则是一条有向边 $x \to y$，权为 $\text{cost}$；同一 $(x, y)$ 出现多条规则时**重边取 min**。边是**有向**的——$a \to b$ 不能反着用。
2. **位置独立**：操作只作用于单个位置，位置之间零耦合。于是

$$\text{answer} = \sum_{i=0}^{n-1} g[\text{source}[i]][\text{target}[i]]$$

   其中 $g[x][y]$ 是图上 $x$ 到 $y$ 的最短路（把一个字符 $x$ 变成 $y$ 的最小成本，见 §5 引理 2）。

3. **全源最短路一次算完**：查询对至多 676 种，节点只有 26 个——Floyd-Warshall 三重循环 $26^3 \approx 1.8 \times 10^4$ 次松弛，比最后扫一遍字符串还轻。

### 3.3 算法流程

![算法流程：建矩阵取 min、Floyd 松弛、逐位累加、不可达判 -1](images/wc377_q3_floyd_flow.svg)

1. **初始化**：$g$ 为 $26 \times 26$ 矩阵，$g[x][x] = 0$（同字符零成本），其余为 $\infty$；
2. **建边**：逐条规则更新 $g[x][y] = \min(g[x][y], \text{cost}[j])$，重边自动留下最便宜的；
3. **Floyd**：`for k, i, j: g[i][j] = min(g[i][j], g[i][k] + g[k][j])`——$k$ 是「中转字母」；
4. **求和**：逐位累加 $g[\text{source}[i]][\text{target}[i]]$，任何一位为 $\infty$ 即返回 $-1$。

### 3.4 示例演算

![示例演算：四位分别查表 0+5+3+20=28，距离矩阵与绕行细节](images/wc377_q3_example_walkthrough.svg)

以示例 1 为例。Floyd 后的距离表 $g$（仅列出出现的 5 个字母）：

| $g$ | a | b | c | d | e |
|-----|---|---|---|---|---|
| **a** | 0 | 2 | 7 | ∞ | 8 |
| **b** | ∞ | 0 | 5 | ∞ | 6 |
| **c** | ∞ | **3** | 0 | ∞ | 1 |
| **d** | ∞ | 22 | 27 | 0 | **20** |
| **e** | ∞ | 2 | 7 | ∞ | 0 |

逐位查表：

| 位置 | 0 | 1 | 2 | 3 |
|------|---|---|---|---|
| source | a | b | c | d |
| target | a | c | b | e |
| 最短路 | 不变 | b→c | **c→e→b** | d→e |
| 成本 | 0 | 5 | **3** | 20 |

总成本 $0 + 5 + 3 + 20 = 28$ ✓。位置 2 正是本题的「题眼」：直连 5、绕行 3，Floyd 枚举中转字母 $e$ 时松弛出更短的路。示例 2 中 $g[a][b] = 3$ 同理（经 $c$ 中转）；示例 3 中 $g[d][e] = \infty$，一位不可达即返回 $-1$。

## 4. 算法细节

- **矩阵初始化**：$g[x][x] = 0$ 不可省——`source[i] == target[i]` 的位置成本为 0；约束保证 $\text{original} \ne \text{changed}$，规则不会产生自环，0 只能来自初始化。
- **重边取 min**：题面明说可能存在 $i \ne j$ 使 $(\text{original}[i], \text{changed}[i]) = (\text{original}[j], \text{changed}[j])$，直接覆盖会丢便宜边。
- **有向图**：`a→b` 与 `b→a` 是两条不同的边，别顺手建成无向图。
- **Floyd 的循环层次**：中转点 $k$ **必须在最外层**——$g_k[i][j]$ 的含义是「仅允许前 $k$ 个字母中转」的最短路，交换循环次序会破坏这个归纳结构。
- **$\infty$ 的取值**：取 $10^{18}$。两个 $\infty$ 相加得 $2 \times 10^{18}$，仍在 `long long`（上限约 $9.2 \times 10^{18}$）范围内，松弛比较既不溢出也不会误更新；真实路径成本上限约 $25 \times 10^6$，远小于 $\infty$，判 $g \ge \infty$ 即不可达。
- **累加器类型**：最坏总成本约 $10^5 \times 2.5 \times 10^7 = 2.5 \times 10^{12}$，超出 32 位范围，C++ 必须用 `long long`。

## 5. 正确性证明

**引理 1（位置独立性）**：最优总成本 $= \sum_{i=0}^{n-1} c_i$，其中 $c_i$ 是把字符 $\text{source}[i]$ 变成 $\text{target}[i]$ 的最小成本。

**证明**：任一合法操作序列可按其作用的位置拆成 $n$ 个子序列；规则与成本只依赖字符本身、与位置无关，故每个子序列单独仍是合法的转换方案，总成本为各子序列成本之和，$\ge \sum_i c_i$。反过来，把每位各自的最优方案按任意顺序拼接，得到合法操作序列，成本恰为 $\sum_i c_i$。两方面夹逼得证。∎

**引理 2（单字符转换 = 图上最短路）**：$c_i = g[x][y]$，即有向图 $G$（节点为字母，边为规则）中 $x$ 到 $y$ 的最短路长，其中 $x = \text{source}[i]$，$y = \text{target}[i]$。

**证明**：把一个字符从 $x$ 变到 $y$ 的任一操作序列，逐次操作对应边 $x = v_0 \to v_1 \to \cdots \to v_k = y$，构成 $G$ 中一条**途径**（walk），总成本 $= \sum \text{边权} \ge \text{dist}(x, y)$。反之，任一 $x$ 到 $y$ 的途径按顺序执行即得合法操作序列，成本为边权和；又边权为正，最短途径可取简单路径，故 $c_i \le \text{dist}(x, y)$（不可达时 $c_i = +\infty$）。∎

**引理 3（Floyd 的正确性）**：三重循环结束后 $g[i][j] = \text{dist}(i, j)$。

**证明**：对 $k$ 归纳：第 $k$ 轮结束时的 $g_k[i][j]$ 是「仅允许下标 $\le k$ 的节点中转」的最短路。归纳步分两类：若最优路不经过 $k$，则 $g_k[i][j] = g_{k-1}[i][j]$，松弛式不更新也不破坏；若经过 $k$，正权下最短路是简单路径、$k$ 恰出现一次，拆成 $i \rightsquigarrow k$ 与 $k \rightsquigarrow j$ 两段（均不再以 $k$ 为中转），故 $g_k[i][j] = g_{k-1}[i][k] + g_{k-1}[k][j]$，恰被松弛式覆盖。$k = 25$ 轮后即无中转限制的最短路。∎

**定理**：算法返回 $\sum_i g[\text{source}[i]][\text{target}[i]]$；若某位 $g = \infty$ 则返回 $-1$，与真实最优一致。

**证明**：由引理 3，矩阵中即全源最短路；由引理 1、2，逐位取值求和即最优总成本；某位 $\infty$ 意味着该位置不存在任何转换途径（引理 2 的逆否），整体不可行，按题意返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m + 26^3 + n)$。建边 $O(m) = 2000$；Floyd $26^3 \approx 1.8 \times 10^4$；逐位求和 $O(n) = 10^5$。总计约 $1.2 \times 10^5$，远低于限时。
- **空间复杂度**：$O(26^2)$。距离矩阵 676 个 `long long`，其余 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long minimumCost(string source, string target, vector<char>& original,
                          vector<char>& changed, vector<int>& cost) {
        const long long INF = 1e18;
        long long g[26][26];
        for (int i = 0; i < 26; i++)
            for (int j = 0; j < 26; j++) g[i][j] = (i == j ? 0 : INF);
        for (int j = 0; j < (int)original.size(); j++) {
            int x = original[j] - 'a', y = changed[j] - 'a';
            g[x][y] = min(g[x][y], (long long)cost[j]);
        }
        for (int k = 0; k < 26; k++)
            for (int i = 0; i < 26; i++)
                for (int j = 0; j < 26; j++)
                    if (g[i][k] + g[k][j] < g[i][j])
                        g[i][j] = g[i][k] + g[k][j];

        long long ans = 0;
        for (int i = 0; i < (int)source.size(); i++) {
            long long c = g[source[i] - 'a'][target[i] - 'a'];
            if (c >= INF) return -1;
            ans += c;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, source: str, target: str, original: List[str],
                    changed: List[str], cost: List[int]) -> int:
        INF = float('inf')
        g = [[INF] * 26 for _ in range(26)]
        for x in range(26):
            g[x][x] = 0
        for x, y, c in zip(original, changed, cost):
            x, y = ord(x) - 97, ord(y) - 97
            if c < g[x][y]:
                g[x][y] = c
        for k in range(26):
            row = g[k]
            for gi in g:
                via = gi[k]
                if via == INF:
                    continue
                for j in range(26):
                    if via + row[j] < gi[j]:
                        gi[j] = via + row[j]
        ans = 0
        for s, t in zip(source, target):
            c = g[ord(s) - 97][ord(t) - 97]
            if c == INF:
                return -1
            ans += c
        return ans
```

> 💡 语言细节：C++ 用静态数组 `long long g[26][26]` 比嵌套 `vector` 更省事；Python 内层缓存 `g[i]`、`g[k]` 的行引用并跳过 `via == INF`，把 $26^3$ 的常数压低（其实不优化也能过）。

## 8. 边界情况与易错点

1. **重边直接覆盖**：$(\text{original}, \text{changed})$ 可能重复，必须 `min` 而不是赋值，否则贵的规则可能把便宜的顶掉。
2. **建成无向图**：规则是单向的 $x \to y$，`a→b` 不代表 `b→a` 可行。
3. **忘记 $g[x][x] = 0$**：`source[i] == target[i]` 的位置会被误判成绕路成本（自环不存在，0 只能靠初始化）。
4. **累加器用 `int`**：最坏约 $2.5 \times 10^{12}$，32 位直接溢出变负数；C++ 全程 `long long`。
5. **$\infty$ 参与加法溢出**：若 $\infty$ 取 `LLONG_MAX`，`g[i][k] + g[k][j]` 直接越界；取 $10^{18}$ 这类「大而能加」的哨兵值。
6. **不可达判定口径**：**任意一位**不可达就返回 $-1$，不是全部不可达才返回。
7. **Floyd 循环层次写反**：$k$ 必须在最外层，内层 $i, j$ 互换无妨，把 $k$ 放到里面结果就错了。
8. **接口类型差异**：C++ 的 `original`/`changed` 是 `vector<char>`，Python 是单字符 `List[str]`，按语言分别处理。

**延伸思考**：

- 若 $\text{cost}$ 可为负数：正权性是「最短路可取简单路径」的保障，负权需换 Bellman-Ford，且负环意味着成本无下界（无限转圈刷成本）。
- 若字符集扩大到 $10^5$ 种：$V^3$ 的 Floyd 失效，应按出现的查询对跑 Dijkstra（$O(q \cdot E \log V)$）或 Johnson 算法。
- 本题「676 种查询」的本质是**值域去重**：当查询数远大于值域平方时，预计算全源最短路总是赚的——这一权衡在 Q4 中再次出现（子串级别的值域去重靠哈希实现）。
