# LeetCode 移除前缀使数组严格递增 题解

## 1. 题目概述

- **标题 / 题号**：移除前缀使数组严格递增（#3818，medium）
- **链接**：https://leetcode.cn/problems/minimum-prefix-removal-to-make-array-strictly-increasing/
- **来源**：LeetCode 第 486 场周赛 Q1
- **难度**：中等
- **标签**：数组、一次遍历

**题意**：给定整数数组 `nums`，需要从中**恰好移除一个前缀**（可以为空），使剩余数组**严格递增**。返回被移除前缀的**最小**长度。前缀指从数组起始位置延伸到任意位置的子数组；单个元素（乃至空数组）视为严格递增。

**约束**：

- $1 \le nums.length \le 10^5$
- $-10^9 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [1,-1,2,3,3,4,5]
输出：4
解释：移除前缀 [1, -1, 2, 3] 后，剩余数组为 [3, 4, 5]，严格递增。
```

**示例 2**

```text
输入：nums = [4,3,-2,-5]
输出：3
解释：移除前缀 [4, 3, -2] 后，剩余数组为 [-5]，严格递增。
```

**示例 3**

```text
输入：nums = [1,2,3,4]
输出：0
解释：数组本身已经严格递增，移除空前缀即可。
```

## 3. 解题思路

### 3.1 暴力思路：枚举切点逐个验证

枚举移除长度 $k = 0, 1, \ldots, n-1$，对每个 $k$ 检查后缀 `nums[k:]` 是否严格递增，返回首个可行的 $k$：

```python
for k in range(n):
    if all(nums[i] < nums[i + 1] for i in range(k, n - 1)):
        return k
```

单次检查 $O(n)$，总体 $O(n^2)$；$n = 10^5$ 时最坏约 $10^{10}$ 次比较，必然超时。浪费是明显的：相邻的 $k$ 重复检查了几乎相同的相邻对，而「每个起点的后缀干不干净」这件事，一趟扫描就能全部刻画出来。

### 3.2 核心观察：最右「违规对」一锤定音

![核心观察：最右违规对决定切点](images/wc486_q1_violation_concept.svg)

称下标 $i$（$0 \le i \le n-2$）为**违规对**，若 $nums[i] \ge nums[i+1]$（注意**相等也违规**——严格递增要求严格小于）。设 $i^*$ 为最右违规对（若存在），则：

$$nums[k:] \text{ 严格递增} \iff k > i^*$$

- **必要性**：$k \le i^*$ 时，坏对 $(i^*,\, i^*+1)$ 完整落在保留部分里，递增被破坏；
- **充分性**：$k = i^*+1$ 时，切点右侧再无任何违规对，后缀干净。

于是可行切点恰为 $\{i^*+1, \ldots, n-1\}$——**向上封闭**（切得越晚越容易合法），最小元即答案：

$$ans = \begin{cases} i^* + 1, & \text{存在违规对} \\ 0, & \text{整个数组已严格递增} \end{cases}$$

> 💡 比 $i^*$ 更靠左的违规对（如示例 1 的 $1 \ge -1$）无需关心：它们落在被移除的前缀里，随切割一并消失，真正卡住切点的只有**最右**那一个。

### 3.3 算法流程：一趟从左向右扫描

![算法流程：从左向右扫描，违规即覆盖更新 ans](images/wc486_q1_scan_flow.svg)

从左向右扫所有相邻对，每遇到违规对就覆盖更新 `ans = i + 1`；扫完时 `ans` 恰好对应**最后一个**（最右）违规对：

```text
ans = 0
for i = 0 .. n-2:
    if nums[i] >= nums[i+1]:  ans = i + 1    # 后写覆盖先写
return ans
```

**等价写法（从右向左早停）**：从 $i = n-2$ 向左扫，**首次命中**的违规对就是最右违规对，直接 `return i + 1`；扫完无命中返回 0。两种写法都是一趟 $O(n)$：正向版「ans 只增不减」更贴直觉，反向版代码更短、平均情况提前退出。

### 3.4 示例演算

![示例演算：三个示例的一趟扫描](images/wc486_q1_example_walkthrough.svg)

**示例 1** `nums = [1,-1,2,3,3,4,5]`，逐对检查：

| i | 相邻对 | 比较 | 违规？ | ans |
|---|--------|------|--------|-----|
| 0 | (1, −1) | $1 \ge -1$ | ✗ | 1 |
| 1 | (−1, 2) | $-1 < 2$ | ✓ | 1 |
| 2 | (2, 3) | $2 < 3$ | ✓ | 1 |
| 3 | (3, 3) | $3 \ge 3$ | ✗ | **4** |
| 4 | (3, 4) | $3 < 4$ | ✓ | 4 |
| 5 | (4, 5) | $4 < 5$ | ✓ | 4 |

扫完 `ans = 4`，保留 `[3, 4, 5]` ✓。注意 $i = 0$ 的违规对先写过 `ans = 1`，随后被 $i = 3$ 覆盖——这正是「后写覆盖先写」的语义。**示例 2** 三个相邻对全部违规，`ans` 一路被覆盖到 $2 + 1 = 3$；**示例 3** 无任何违规，`ans` 保持 0。

## 4. 算法细节

1. **违规判定用 $\ge$ 而非 $>$**：严格递增要求相邻不等，$nums[i] = nums[i+1]$（示例 1 的两个 3）同样必须切断。
2. **覆盖更新的不变式**：任意时刻 `ans` = 「**已扫描前缀内**最右违规位置 + 1」；每遇新违规对，`ans = i + 1` 严格增大，循环结束即为全局最右违规对 + 1。
3. **循环边界**：$i$ 只需遍历 $[0, n-2]$（相邻对的左端下标）；$n = 1$ 时循环体不执行，天然返回 0，免特判。
4. **无需二分**：可行切点关于 $k$ 单调（向上封闭），理论上可「二分 + 检查」做到 $O(n \log n)$，但一趟线性扫描 $O(n)$ 更简单直接。
5. **两个方向等价**：正向「记最后一个」与反向「首次命中即返回」产出相同答案；反向写法 `for i in range(n - 2, -1, -1)` 在 $n = 1$ 时 range 为空，同样免特判。

## 5. 正确性证明

**引理 1（后缀封闭性）**：若 `nums[k..n-1]` 严格递增，则对任意 $k' \in [k, n-1]$，`nums[k'..n-1]` 也严格递增。

**证明**：`nums[k'..n-1]` 是 `nums[k..n-1]` 的连续子段。对其内部任意相邻对 $(i, i+1)$（$k' \le i \le n-2$），有 $k \le i$，由整体严格递增得 $nums[i] < nums[i+1]$。故子段也严格递增。∎

**引理 2（成对判定）**：`nums[k..n-1]` 严格递增 $\iff$ 对所有 $i \in [k, n-2]$ 都有 $nums[i] < nums[i+1]$。

**证明**：「每个元素严格大于它的前一个元素（若存在）」展开后即对所有相邻对成立严格不等，二者逐对等价。∎

**定理**：设 $i^*$ 为最大的 $i \in [0, n-2]$ 使 $nums[i] \ge nums[i+1]$（若不存在则答案为 0），则最小移除前缀长度为 $i^* + 1$。

**证明**：

（可行性）取 $k = i^* + 1$。对任意 $i \in [k, n-2]$，由 $i > i^*$ 及 $i^*$ 的最大性知 $nums[i] < nums[i+1]$，由引理 2 得 `nums[k..n-1]` 严格递增，即移除长度 $i^*+1$ 可行。

（最优性）对任意 $k \le i^*$，相邻对 $(i^*, i^*+1)$ 落在 `nums[k..n-1]` 内且 $nums[i^*] \ge nums[i^*+1]$，由引理 2 其不严格递增，即移除长度 $k$ 不可行。故 $i^* + 1$ 是最小可行长度。∎

**推论**：可行切点集合恰为 $\{i^*+1, \ldots, n-1\}$（由引理 1，$i^*+1$ 可行蕴涵更大的切点都可行），且答案上界为 $n - 1$——只保留最后一个元素必然合法。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描 $n - 1$ 个相邻对，每次 $O(1)$ 比较；$n = 10^5$ 时仅 $10^5$ 次比较，远优于暴力的 $O(n^2) \approx 10^{10}$。
- **空间复杂度**：$O(1)$。只使用 `ans` 与循环变量 `i`，原地判断，无额外数据结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumPrefixLength(vector<int>& nums) {
        int ans = 0;                       // 无违规时移除空前缀
        for (int i = 0; i + 1 < (int)nums.size(); ++i) {
            if (nums[i] >= nums[i + 1]) {  // 相等也违规
                ans = i + 1;               // 后写覆盖先写：留下最右违规
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumPrefixLength(self, nums: List[int]) -> int:
        ans = 0
        for i in range(len(nums) - 1):
            if nums[i] >= nums[i + 1]:  # 相等也违规
                ans = i + 1             # 覆盖更新：最终对应最右违规对
        return ans
```

## 8. 边界情况与易错点

1. **相邻相等是违规对**：判定必须写 $\ge$；示例 1 正是 $(3, 3)$ 卡住切点，误写成 $>$ 会返回 1。
2. **$n = 1$**：无相邻对，单元素天然严格递增，返回 0（循环体不执行，免特判）。
3. **整个数组递减**（示例 2）：最右违规对为 $i^* = n-2$，答案 $n - 1$，只保留最后一个元素。**答案永远不等于 $n$**。
4. **已严格递增**（示例 3）：答案是 0（空前缀），`ans` 必须初始化为 0。
5. **两种写法的相反陷阱**：正向版中途的 `ans` 不是最终答案（示例 1 先得 1 后被 4 覆盖），循环内提前返回会错；反向版则相反——**必须**首次命中就返回，扫完才返回会拿到最左违规对。
6. **数值范围**：$|nums[i]| \le 10^9$ 且只做比较不做加减，`int` 无溢出风险。
