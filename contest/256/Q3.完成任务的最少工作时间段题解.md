# LeetCode 完成任务的最少工作时间段 题解

## 1. 题目概述

- **标题 / 题号**：完成任务的最少工作时间段（#1986，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-work-sessions-to-finish-the-tasks/
- **来源**：LeetCode 第 256 场周赛 Q3
- **难度**：中等
- **标签**：位运算、状态压缩、动态规划、子集枚举

**题意**：给定 $n$ 个任务，第 $i$ 个任务需耗时 $\text{tasks}[i]$ 小时。一个**工作时间段**内至多连续工作 $\text{sessionTime}$ 小时。要求：

- 任务**不可拆分**：在某时间段开始的任务必须在**同一个**时间段内完成；
- 完成一个任务后可以立马开始下一个；
- 完成顺序**任意**。

返回完成全部任务所需的**最少**工作时间段数。

**约束**：

- $n = \text{tasks.length}$，$1 \le n \le 14$
- $1 \le \text{tasks}[i] \le 10$
- $\max(\text{tasks}[i]) \le \text{sessionTime} \le 15$

> 💡 **审题关键**：① 「不可拆分 + 任意顺序」意味着我们只关心每个时段**装了哪些任务**，与先后无关——这是装箱视角的入口；② $n \le 14$，$2^{14} = 16384$，是**状压 DP 的甜区**；③ 本题本质是 NP-hard 的装箱问题求**精确最优**，靠 $n$ 极小才可指数级求解；④ $\max(\text{tasks}) \le \text{sessionTime}$ 保证任何任务至少能单独占一段，答案必然存在。

## 2. 示例

**示例 1**

```text
输入：tasks = [1,2,3], sessionTime = 3
输出：2
解释：第 1 段完成任务 0 和 1（1 + 2 = 3 小时，恰好装满），第 2 段完成任务 2（3 小时）。
```

**示例 2**

```text
输入：tasks = [3,1,3,1,1], sessionTime = 8
输出：2
解释：第 1 段完成前四个任务（3 + 1 + 3 + 1 = 8 小时），第 2 段完成最后一个任务（1 小时）。
```

**示例 3**

```text
输入：tasks = [1,2,3,4,5], sessionTime = 15
输出：1
解释：总时长 1+2+3+4+5 = 15 ≤ 15，一个时间段全部做完。
```

## 3. 解题思路

### 3.1 暴力思路

**排列视角**：枚举任务的全排列，按顺序「贪心装箱」——能塞进当前段就塞、塞不下就新开一段。这个做法其实是**正确**的（§5 引理 5 的交换论证恰好说明：存在一个最优分组，能被某个排列的顺序贪心复原），但 $14! \approx 8.7 \times 10^{10}$，数量级不可行。

**划分视角**：让每个任务选一个时段编号，方案数是组合爆炸的划分数，同样不可行。

**DFS + 剪枝**（二分答案 + 装箱判定回溯）：最坏仍是指数级，靠剪枝和数据弱过关，不稳定（姊妹篇题解有完整实现）。

三种暴力的共同浪费：**同一个「任务子集」的装箱可能性被反复搜索**。比如「$\{3,1,3,1\}$ 能否装进一段」这个问题，在无数条搜索分支里被重复回答——而它明明只取决于子集自身。把「子集」升格为一等公民，就是状压 DP 的起点。

### 3.2 核心观察：一个时段 = 一个「时长和 ≤ sessionTime」的子集

![核心观察：任务装箱进时段，n 小于等于 14 时子集可全部枚举](images/wc256_q3_partition_concept.svg)

由「不可拆分 + 任意顺序」，一个合法方案完全等价于：把全集 $\text{FULL}$ 划分成 $k$ 个**两两不交**的子集 $S_1, \dots, S_k$，每个子集的时长和 $\le \text{sessionTime}$（时段内不并行，时长直接相加）。目标是最小化 $k$。

两个关键性质让状压成为可能：

1. **子集可全枚举**：$n \le 14$，用 $n$ 位二进制数 `mask` 表示任务集合，全集只有 $2^{14} = 16384$ 个；
2. **「子集能否单独占一段」是子集的固有属性**：只取决于 $\text{sum}(s) \le \text{sessionTime}$，与方案的其他部分无关——可以预处理成一张表，一次计算、全局复用。

### 3.3 状态转移：枚举「一个时段」所装的子集

![算法流程：锚定 lowbit 枚举候选子集 s，逐状态递推](images/wc256_q3_subset_dp_flow.svg)

**状态定义**：$dp[\text{mask}]$ = 把 `mask` 内的任务划分成合法时段的**最少段数**，$dp[0] = 0$。

**转移**：从 `mask` 中切出一个能装进一个时段的非空子集 $s$，剩下的交给子问题：

$$dp[\text{mask}] = \min_{\substack{\varnothing \ne s \subseteq \text{mask} \\ \text{sum}(s) \le \text{sessionTime}}} dp[\text{mask} \setminus s] + 1$$

因为 $\text{mask} \setminus s$ 数值上严格小于 `mask`，**按 mask 从 $1$ 到 $2^n - 1$ 递增一趟即可完成递推**。

**lowbit 锚定（常数减半）**：上式要求 $s$ 取遍所有非空子集。但注意到——任何划分里，`mask` 最低位 1 所在的那个时段是**唯一确定**的。因此只需枚举**含 `lowbit(mask)` 的子集**，其余子集全是重复劳动。设 $\text{low} = \text{mask} \,\&\, (-\text{mask})$，$\text{rest} = \text{mask} \oplus \text{low}$，则 $s = \text{sub} \mid \text{low}$，`sub` 取遍 `rest` 的所有子集。转移总量从 $3^n \approx 4.8 \times 10^6$ 降到 $3^n/2 \approx 2.4 \times 10^6$。

### 3.4 示例演算

![示例演算：tasks 为 1,2,3、sessionTime 为 3 时 8 个子集的 dp 值](images/wc256_q3_walkthrough.svg)

取示例 1：`tasks = [1,2,3]`，`sessionTime = 3`，只有 $2^3 = 8$ 个状态（任务 0/1/2 时长分别为 1/2/3）：

| mask | 完成任务 | sum | dp | 最优划分 |
|------|---------|-----|----|---------|
| 000 | $\varnothing$ | 0 | 0 | — |
| 001 | {0} | 1 ✓ | 1 | [1] |
| 010 | {1} | 2 ✓ | 1 | [2] |
| 011 | {0,1} | 3 ✓ | 1 | [1+2] 装满一段 |
| 100 | {2} | 3 ✓ | 1 | [3] |
| 101 | {0,2} | 4 ✗ | 2 | [1][3] |
| 110 | {1,2} | 5 ✗ | 2 | [2][3] |
| 111 | 全部 | 6 ✗ | **2** | [1+2][3] ← 答案 |

聚焦 `mask = 111` 的转移（lowbit = 任务 0，$s$ 必含它）：

- $s = \{0,1\}$：sum $= 3 \le 3$ ✓ → $dp[100] + 1 = 2$，**最优**；
- $s = \{0\}$：✓ → $dp[110] + 1 = 3$；
- $s = \{0,2\}$：sum $= 4$ ✗ 跳过；$s = \{0,1,2\}$：sum $= 6$ ✗ 跳过。

故 $dp[111] = 2$，与示例一致。示例 3 对照：`[1,2,3,4,5] @ 15` 时 $\text{sum}(\text{FULL}) = 15 \le 15$，整组恰好一段，$dp[\text{FULL}] = dp[0] + 1 = 1$——**「s 取到 mask 本身」这一候选必须被枚举到**（见易错点 3）。

## 4. 算法细节

1. **子集和预处理**（$O(2^n)$ 一趟递推，避免对每个子集 $O(n)$ 求和）：

   $$\text{total}[\text{mask}] = \text{total}[\text{mask} \,\&\, (\text{mask}-1)] + \text{tasks}[\text{ctz}(\text{mask})]$$

   `mask & (mask-1)` 去掉最低位 1，`__builtin_ctz`（C++）/ `(low).bit_length() - 1`（Python）求最低位下标。

2. **子集枚举模板**：`for (s = mask; s; s = (s-1) & mask)` 按数值从大到小访问 `mask` 的所有非空子集，总量 $3^n$。锚定版改为对 `rest` 枚举后并上 `low`，注意**含空集**（`sub = 0` 时 $s = \{low\}$，即「lowbit 单独一段」这一候选），处理完 `sub = 0` 要 `break`，否则死循环。

3. **语言选择**：C++ 下 $3^n$ 版毫秒级；Python 下锚定版约 $2.4 \times 10^6$ 步（实测 $n=14$ 约 0.3 秒，也能过），但下面的二元组版只要 $n \cdot 2^n \approx 2.3 \times 10^5$ 步（实测约 36 毫秒），是 Python 的更优选择。

4. **优化替代：二元组 DP**（$O(n \cdot 2^n)$，比赛实战首选）。换一套状态——不枚举「一个时段装谁」，而是**逐个任务**决策，状态只记当前时段的余量：

   ![二元组优化：状态转移与支配关系](images/wc256_q3_pair_dp_dominance.svg)

   $$dp[\text{mask}] = (k, t)：\ \begin{cases} k = \text{最少段数（含当前打开段）} \\ t = \text{当前段已用时长（} k \text{最小时再最小化）} \end{cases}$$

   初始 $dp[0] = (1, 0)$——**预先打开一个空时段**。转移枚举最后加入的任务 $j$（前驱为 $\text{mask} \oplus 2^j$，其值为 $(k, t)$）：

   - 塞得下（$t + \text{tasks}[j] \le \text{sessionTime}$）→ $(k,\ t + \text{tasks}[j])$，留在当前段；
   - 塞不下 → $(k+1,\ \text{tasks}[j])$，关闭当前段、新开一段。

   候选取 $(k, t)$ **字典序最小**。安全性由支配关系保证（右图）：同 mask 下，$k$ 更小 ⟹ 支配（哪怕 $t$ 更大，图中的 $(1,14)$ 完胜 $(2,2)$）；$k$ 相等且 $t$ 更小 ⟹ 支配（余量更大）。严格证明见 §5 引理 3–5。

5. **与二分答案 + 回溯的关系**：答案 $k$ 单调（段越多越容易装下），可二分后用「降序 + 同余量去重」的装箱回溯判定。那是搜索派的解法，复杂度依赖剪枝；DP 派对 $2^n$ 是多项式级的，更稳。

## 5. 正确性证明

以下记 $C = \text{sessionTime}$，$\text{OPT}(\text{mask})$ 为 `mask` 的最优划分段数。

**引理 1（算法值对应合法方案）**：对任意 `mask`，$dp[\text{mask}]$ 是某个合法划分的段数，故 $dp[\text{mask}] \ge \text{OPT}(\text{mask})$。

**证明**：对 $\text{popcount}(\text{mask})$ 归纳。`mask` $= 0$：$dp = 0$ 对应空划分。归纳步：设 $dp[\text{mask}]$ 取到 $dp[\text{mask} \setminus s] + 1$，其中 $\text{sum}(s) \le C$。由归纳假设，$\text{mask} \setminus s$ 存在 $dp[\text{mask} \setminus s]$ 组的合法划分；添上「一组装 $s$」（和 $\le C$，合法）即为 `mask` 的 $dp[\text{mask}]$ 组合法划分。∎

**引理 2（最优解被枚举覆盖）**：$dp[\text{mask}] \le \text{OPT}(\text{mask})$。

**证明**：对 $\text{popcount}$ 归纳。取 `mask` 的一个最优划分 $P$，设 $s^*$ 为 $P$ 中**包含 $\text{lowbit(mask)}$ 的组**：非空、$s^* \subseteq \text{mask}$、$\text{sum}(s^*) \le C$，恰在锚定枚举范围内。$P$ 去掉 $s^*$ 后是 $\text{mask} \setminus s^*$ 的 $\text{OPT}(\text{mask}) - 1$ 组划分，由归纳假设 $dp[\text{mask} \setminus s^*] \le \text{OPT}(\text{mask}) - 1$，故

$$dp[\text{mask}] \le dp[\text{mask} \setminus s^*] + 1 \le \text{OPT}(\text{mask}). \qquad \square$$

**定理 1**：子集枚举版返回 $dp[\text{FULL}] = \text{OPT}(\text{FULL})$，即最少工作时间段数。

**证明**：引理 1 给 $dp[\text{FULL}] \ge \text{OPT}(\text{FULL})$，引理 2 给反方向。∎

下面证明二元组版的正确性。记转移函数 $\text{step}((k,t), x) = (k, t+x)$ 若 $t + x \le C$，否则 $(k+1, x)$。

**引理 3（转移保序）**：$(k_1, t_1) \le_{\text{lex}} (k_2, t_2)$ 蕴含 $\text{step}((k_1,t_1), x) \le_{\text{lex}} \text{step}((k_2,t_2), x)$。

**证明**：分三类。① $k_1 < k_2$：$\text{step}$ 的第一分量只可能不变或加一，故左边第一分量 $\le k_1 + 1 \le k_2 \le$ 右边第一分量；若恰相等（$k_1 + 1 = k_2$ 且右边塞下），则左边为 $(k_1+1, x)$、右边为 $(k_2, t_2 + x)$，$x \le t_2 + x$ ✓。② $k_1 = k_2,\ t_1 \le t_2$ 且右边**新开**（$t_2 + x > C$）：左边塞下则第一分量 $k_1 < k_2 + 1$ ✓；新开则两边同为 $(k_1+1, x)$ ✓。③ $k_1 = k_2,\ t_1 \le t_2$ 且右边**塞下**：$t_1 + x \le t_2 + x \le C$，左边必也塞下，$(k_1, t_1 + x) \le_{\text{lex}} (k_2, t_2 + x)$ ✓。∎

**引理 4（支配性）**：同一 `mask` 下，$(k, t) \le_{\text{lex}} (k', t')$ 蕴含：从 $(k, t)$ 出发，可以逐步模拟从 $(k', t')$ 出发的**任意**合法续序列，且最终段数不增。

**证明**：设对方的续序列逐个加入任务 $x_1, x_2, \dots$（每步按「塞得下就塞、塞不下新开」走），我方按**相同顺序**加入相同任务。归纳维持不变量：

$$k_{\text{cur}} < k_{\sigma} \quad\text{或}\quad (k_{\text{cur}} = k_{\sigma} \text{ 且 } t_{\text{cur}} \le t_{\sigma})$$

初始由 $\le_{\text{lex}}$ 直接成立。每步核查四类情形：对方塞下 / 对方新开 × 我方塞下 / 我方新开——

- 对方塞下、$k_{\text{cur}} < k_{\sigma}$：我方塞下则 $k$ 仍小 ✓；新开则 $k_{\text{cur}} + 1 \le k_{\sigma}$（取等时 $t = x \le t_{\sigma} + x$）✓；
- 对方新开、$k_{\text{cur}} < k_{\sigma}$：对方变为 $(k_{\sigma}+1, x)$，我方无论塞下（$k_{\text{cur}} < k_\sigma + 1$）还是新开（$k_{\text{cur}} + 1 \le k_\sigma < k_\sigma + 1$）✓；
- 对方塞下、$k$ 相等：由 $t_{\text{cur}} \le t_{\sigma}$ 得 $t_{\text{cur}} + x \le t_{\sigma} + x \le C$，我方**必也塞下**，保持 $k$ 相等且 $t$ 不增 ✓；
- 对方新开、$k$ 相等：我方塞下则变为「$k$ 小一截」✓；新开则两边同为 $(k_{\sigma}+1, x)$ ✓。

不变量始终成立，序列结束时 $k_{\text{final}} \le k'_{\text{final}}$。∎

**引理 5（贪心序可达最优）**：存在一条合法的逐任务加入序列，其二元组路径终点 $k = \text{OPT}(\text{FULL})$。

**证明**：取最优划分 $B_1, \dots, B_m$（$m = \text{OPT}$）。若某任务 $x \in B_i$ 能塞进更早的组 $B_j$（$j < i$）的剩余空间，就把 $x$ 前移到 $B_j$：各组之和仍 $\le C$；若 $B_i$ 因此清空则得到 $m - 1$ 组划分，与最优性矛盾，故组数保持 $m$。定义势函数 $\Phi = \sum_{\text{任务 } x} x \text{ 所在组下标}$，每次前移严格减小 $\Phi$，过程必然终止。终止时得到最优划分 $B'_1, \dots, B'_m$：**任何任务都塞不进更早组的剩余空间**。

按「$B'_1$ 的任务、$B'_2$ 的任务、……」的顺序逐个加入：组内前缀和 $\le$ 组和 $\le C$，每步走「塞下」分支；$B'_{i+1}$ 的首任务塞不进 $B'_i$ 的剩余空间，恰走「新开」分支。整条路径合法且终点 $k = m = \text{OPT}$。∎

**定理 2**：二元组版返回 $dp[\text{FULL}].k = \text{OPT}(\text{FULL})$。

**证明**：（$\ge$）每个 $dp$ 值都对应合法方案：与引理 1 同理归纳——「塞下」扩充当前段保持 $\le C$，「新开」的单任务段合法依赖 $\text{tasks}[j] \le \max(\text{tasks}) \le C$。（$\le$）取引理 5 的最优路径，设其在前缀 `mask` 处的状态为 $(k_{\text{mask}}, t_{\text{mask}})$。对前缀长度归纳证明 $dp[\text{mask}] \le_{\text{lex}} (k_{\text{mask}}, t_{\text{mask}})$：起点两同为 $(1, 0)$；归纳步中路径状态 $\text{step}((k_{\text{mask}}, t_{\text{mask}}), x_j)$，而 $\text{step}(dp[\text{mask}], x_j)$ 是 $dp[\text{mask} \cup \{j\}]$ 的候选之一，由引理 3 与候选取 min 得

$$dp[\text{mask} \cup \{j\}] \le_{\text{lex}} \text{step}(dp[\text{mask}], x_j) \le_{\text{lex}} \text{step}((k_{\text{mask}}, t_{\text{mask}}), x_j) = (k_{\text{mask} \cup \{j\}}, t_{\text{mask} \cup \{j\}}).$$

在 $\text{mask} = \text{FULL}$ 处得 $dp[\text{FULL}] \le_{\text{lex}} (\text{OPT}, \cdot)$，即 $dp[\text{FULL}].k \le \text{OPT}$。∎

> 💡 引理 4 说明「每个 mask 只留一个字典序最小的代表」是安全的（其余状态被支配）；定理 2 的前缀归纳则是它的形式化落地——两者合起来，正是「二元组 + 字典序」这套设计的完整合法性来源。

## 6. 复杂度分析

- **时间复杂度**：
  - 子集枚举版：$O(2^n + 3^n)$——预处理 $2^n$，主循环遍历全部（mask, 子集）对共 $3^n \approx 4.8 \times 10^6$ 步，lowbit 锚定后 $\approx 2.4 \times 10^6$ 步；
  - 二元组版：$O(n \cdot 2^n)$——$2^{14}$ 个状态各枚举 $n = 14$ 个「最后加入的任务」，约 $2.3 \times 10^5$ 步，比子集枚举版快约 20 倍。
- **空间复杂度**：$O(2^n)$，即 `total[]` 与 `dp[]` 两个长度 $2^{14}$ 的数组（二元组版只需 `dp[]`，每项存一对小整数）。

## 7. 参考代码

### C++（子集枚举 + lowbit 锚定）

```cpp
class Solution {
public:
    int minSessions(vector<int>& tasks, int sessionTime) {
        int n = tasks.size();
        int full = (1 << n) - 1;

        // total[mask]：mask 内任务时长之和（去掉最低位递推，O(2^n)）
        vector<int> total(1 << n, 0);
        for (int mask = 1; mask <= full; ++mask)
            total[mask] = total[mask & (mask - 1)] + tasks[__builtin_ctz(mask)];

        const int INF = 100;
        vector<int> dp(1 << n, INF);
        dp[0] = 0;
        for (int mask = 1; mask <= full; ++mask) {
            int low = mask & -mask;              // 锚定：枚举「lowbit 所在时段」
            int rest = mask ^ low;
            for (int sub = rest; ; sub = (sub - 1) & rest) {
                int s = sub | low;               // s 必含 lowbit，首迭代 s = mask
                if (total[s] <= sessionTime)
                    dp[mask] = min(dp[mask], dp[mask ^ s] + 1);
                if (sub == 0) break;             // 空集处理完必须跳出
            }
        }
        return dp[full];
    }
};
```

### Python（二元组 DP，$O(n \cdot 2^n)$）

```python
class Solution:
    def minSessions(self, tasks: List[int], sessionTime: int) -> int:
        n = len(tasks)
        INF = (float('inf'), float('inf'))
        dp = [INF] * (1 << n)
        dp[0] = (1, 0)                    # 预先打开一个空时段：1 段、已用 0
        for mask in range(1, 1 << n):
            best = INF
            for j in range(n):
                if mask >> j & 1:
                    k, t = dp[mask ^ (1 << j)]
                    if t + tasks[j] <= sessionTime:      # 塞进当前段
                        cand = (k, t + tasks[j])
                    else:                                # 关闭当前段，新开一段
                        cand = (k + 1, tasks[j])
                    if cand < best:                      # (k, t) 字典序最小
                        best = cand
            dp[mask] = best
        return dp[-1][0]
```

> 💡 Python 元组的 `<` 恰是字典序，`cand < best` 一行完成「先比段数、再比已用时长」的双目标比较。若想跑子集枚举版，把锚定枚举直接翻译即可（约 0.3 秒，同样能过）。

## 8. 边界情况与易错点

1. **二元组版的初始化是最大陷阱**：$dp[0]$ 必须是 $(1, 0)$「预先打开一个空时段」。若误写成 $(0, 0)$，第一个任务会落进一个**从不计数的幽灵时段**（得到 $(0, x)$ 而非 $(1, x)$），全程恰好少计一段——`[1,2,3] @ 3` 会错误地返回 1 而不是 2。姊妹篇用 $(1, \text{sessionTime})$ 记「剩余容量」是同一件事的另一种写法。
2. **比较必须取 $(k, t)$ 字典序最小——尤其 $k$ 相同时 $t$ 要取最小**：`[9,1,9,5] @ 14` 中 mask $\{9,9,1\}$ 同时可达 $(2,9)$ 与 $(2,10)$，若保留 $(2,10)$，「任务 5 恰好装满当前段」的路线就断了——$9 + 5 = 14$ 本可塞下，$10 + 5 = 15$ 却超时，被迫新开一段，答案从 2 错成 3（正确 2：$\{9,5\},\{9,1\}$）。至于把 $t$ 排在 $k$ 前面的「余量优先」变体：它会丢弃 $k$ 更小的支配状态（§4 支配关系图中的 $(1,14)$ vs $(2,2)$，被丢弃的恰是前者），引理 3 的保序性对它也不成立——本文的证明只覆盖字典序这一种比较，实战别在此处自作聪明。
3. **子集枚举必须覆盖 $s = \text{mask}$ 本身**：`for (s = mask; s; s = (s-1) & mask)` 从 `mask` 起步是对的；若从 `(mask-1) & mask` 起步会漏掉「整组恰好一段」——示例 3（sum 恰为 15）会算错。锚定版首迭代 `sub = rest` 时 $s = \text{mask}$ 自然出现；循环**处理完 `sub = 0` 后必须 `break`**，否则死循环。
4. **用 $\le$ 不要用 $<$**：$t + \text{tasks}[j] = \text{sessionTime}$ 与 $\text{sum}(s) = \text{sessionTime}$ 都是合法的「恰好装满」，`[1,2,3] @ 3` 用 `<` 会把 $\{1,2\}$ 误判超时、答案从 2 错成 3。
5. **无需处理 $\text{tasks}[i] > \text{sessionTime}$**：题目显式保证 $\max(\text{tasks}) \le \text{sessionTime}$，单任务时段恒合法（二元组版「新开一段装 $x$」的合法性正依赖于此）。
6. **递推顺序**：按 mask 数值递增即可——子集枚举版的转移目标 $\text{mask} \setminus s$ 数值更小，二元组版去掉一个 1 位后数值更小，无环；改成记忆化搜索同样正确。
7. **$n = 1$、全部任务一段等平凡情形无需特判**，DP 自然覆盖；答案下界 $\lceil \text{sum}/\text{sessionTime} \rceil$ 可用作对拍时的快速 sanity check。
