# LeetCode 不同的好子序列数目 题解

## 1. 题目概述

- **标题 / 题号**：不同的好子序列数目（#1987，hard）
- **链接**：https://leetcode.cn/problems/number-of-unique-good-subsequences/
- **来源**：LeetCode 第 256 场周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划、去重计数、计数 DP

**题意**：给定一个二进制字符串 `binary`。它的一个子序列如果**非空**且**没有前导 0**（除非整个子序列就是 `"0"` 本身），则称为**好子序列**。求 `binary` 的**不同**好子序列数目——相同的字符串只算一次，答案对 $10^9+7$ 取模。

**约束**：

- $1 \le n = \text{binary.length} \le 10^5$
- `binary` 只含有 `'0'` 和 `'1'`

> 💡 **审题关键**：① 「不同」按**字符串值**判等——同一个串可由多组下标产生，必须去重（示例 3 里 `"1"` 由下标 $\{0\}$、$\{2\}$ 产生两次，只算一个）；② 「好」$\iff$ 以 `'1'` 开头，或恰好是 `"0"`——这条二分是全部状态设计的地基；③ 「按值去重的子序列计数」是 [940. 不同的子序列 II](https://leetcode.cn/problems/distinct-subsequences-ii/) 的套路，本题在其之上叠加前导零限制。

## 2. 示例

**示例 1**

```text
输入：binary = "001"
输出：2
解释：好的挑选有 "0"（下标 {0}）、"0"（下标 {1}）、"1"（下标 {2}），
      而 "00"、"01"、"001" 都有前导 0，不算好。
      按值去重后只剩 "0" 和 "1"，共 2 个。
```

**示例 2**

```text
输入：binary = "11"
输出：2
解释：好的挑选有 "1"、"1"、"11"；不同好子序列为 "1" 和 "11"。
```

**示例 3**

```text
输入：binary = "101"
输出：5
解释：好的挑选有 "1"、"0"、"1"、"10"、"11"、"101"（"01" 被前导 0 过滤）；
      不同好子序列为 "0"、"1"、"10"、"11"、"101"，共 5 个。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $2^n$ 个下标集合，拼出字符串、过滤「好」、丢进哈希集合去重：时间 $O(2^n \cdot n)$，空间最坏同样指数级。$n = 10^5$ 时 $2^n$ 连表示都是问题。

更本质的障碍：**答案本身（取模前）就是指数级的**。交替串 `"1010…"` 的不同好子序列数目按斐波那契级（$\varphi^n$ 量级）增长——枚举与存储必然爆炸，只能**计数**。

按「长度」做普通计数 DP 也不行：$\text{cnt}[i][j]$（前 $i$ 位、长度 $j$）把同一个串在下标维度重复计入（`"101"` 中 `"1"` 被两处位置各贡献一次），而位置信息无法区分同值串——去重失败。暴力的浪费在于「按位置枚举、把去重推迟到生成之后」；解法必须把去重**做进递推**。

### 3.2 核心观察：按「末尾字符」分桶 + 末字符重挂

![核心观察：不同位置会撞车，按末尾字符分桶去重](images/wc256_q4_dedup_concept.svg)

两条观察撑起整个解法：

**观察 A（值 vs 位置）**：题目按**值**计数，而「以哪个字符结尾」是关于值的属性，与产生它的位置无关。好子序列的末位只有 `'0'` / `'1'` 两种 → **两个计数器** $\text{ends0}$、$\text{ends1}$ 足以编码全部去重信息，无需存储任何字符串。

**观察 B（末字符重挂 / interchange）**：设 $t$ 是以 $c$ 结尾的好子序列。当扫描到某个等于 $c$ 的位置时，$t$ 的末位可以「挪」到当前位置——同字符互换，**串值不变**。于是「以**当前位** $c$ 结尾」的好子序列集合恰为 $\{\, s + c \mid s \text{ 是合法前缀} \,\}$：由前缀经**单射** $s \mapsto s + c$ 生成，**天然不重不漏**。

**「好」的落地**（用审题关键 ② 的二分）：

- 好且 $\ne$ `"0"` $\iff$ 以 `'1'` 开头。末位拼 `'1'` 或 `'0'` 都不动首字符，好子序列拼任何字符仍然好；空串拼 `'1'` 得 `"1"`，合法；
- 空串拼 `'0'` 得 `"0"`：合法但**特例**——它不能当前缀（`"0"+"0"="00"`、`"0"+"1"="01"` 都有前导 0）。把 `"0"` 摘出 DP，用标记 `has0` 在最后单独 $+1$。

### 3.3 状态转移：单趟扫描，覆盖式更新

![状态转移：两个计数器按当前字符覆盖式更新](images/wc256_q4_dp_transition.svg)

**状态**：$\text{ends0}$ / $\text{ends1}$ = 当前前缀中以 `'0'` / `'1'` 结尾的好子序列**个数**（均不含特例 `"0"`，`"0"` 走 `has0` 通道）。初始均为 $0$，`has0 = false`。

**转移**（读 $binary[i] = c$，$s$ 遍历旧前缀的好子序列全体）：

- $c = \text{'1'}$：$\text{ends1} \leftarrow \text{ends0} + \text{ends1} + 1$（两桶全体 $+\ \text{"1"}$ 本身）；
- $c = \text{'0'}$：$\text{ends0} \leftarrow \text{ends0} + \text{ends1}$（两桶全体，**无 +1**）；`has0 ← true`。

**答案**：

$$\text{ans} = \big(\text{ends0} + \text{ends1} + (has0\,?\,1:0)\big) \bmod (10^9+7)$$

**覆盖（`=`）而非累加（`+=`）**是去重的关键一步：新桶由单射生成，旧桶整体 $\subseteq$ 新桶（每个旧元素都能重挂到当前位），丢弃旧值不漏计。若误写成累加，`"11"` 会数出 $3$——`"1"` 被算了两遍。

### 3.4 示例演算

![示例演算：binary 为 101 时两个计数器的完整轨迹](images/wc256_q4_walkthrough.svg)

以 `binary = "101"` 演算（绿色格为本步被覆盖的计数器）：

| 步骤 | ch | ends0 | ends1 | has0 | 以 '0' 结尾 | 以 '1' 结尾 |
|------|----|----|----|------|------------|------------|
| 初始 | — | 0 | 0 | 否 | { } | { } |
| i=0 | '1' | 0 | **1** | 否 | { } | { "1" } |
| i=1 | '0' | **1** | 1 | **是** | { "10" } | { "1" } |
| i=2 | '1' | 1 | **3** | 是 | { "10" } | { "1", "11", "101" } |

答案 $= 1 + 3 + 1 = 5$，与手算 $\{\text{"0"},\text{"1"},\text{"10"},\text{"11"},\text{"101"}\}$ 一致。

末步读 `'1'` 时值得盯住：新桶 $= \{\text{"10"}+\text{'1'}=\text{"101"},\ \text{"1"}+\text{'1'}=\text{"11"},\ \varepsilon+\text{'1'}=\text{"1"}\}$——i=0 的旧 `"1"` 重挂到 i=2 后与新建 `"1"` **合并**，覆盖式更新在此刻完成去重。

快速对照：`"001"` 的 `ends0` 恒为 $0$（没有 `'1'` 可作首字符）、`ends1 = 1`，答案 $0+1+1=2$；`"11"` 的 `ends1` 走 $1 \to 2$，答案 $0+2+0=2$。

## 4. 算法细节

1. **状态的排他性**：`ends0` 显式排除特例 `"0"`，`ends1` 天然不含它（`"0"` 不以 `'1'` 结尾）。于是「`ends0` 桶 / `ends1` 桶 / `"0"`」恰好三分全部好子序列（按末字符分类 + 特例），计数不重不漏（§5 定理 2）。
2. **读 `'1'` 的 `+1`**：唯一来源是空串拼 `'1'` = `"1"`，这是整个 DP 的「白手起家」入口；读 `'0'` **不能**加 `+1`：`"0"` 会被每个 `'0'` 重复计入 `ends0`，且下一步会拼出非法的 `"00"`。
3. **覆盖式赋值**：每个分支只读旧值、写一个新值（读的 `ends0`/`ends1` 都是转移前的值，`'0'`/`'1'` 分支互不干扰），不需要临时变量。
4. **取模**：每步 `% (10^9+7)`。C++ 中 $\text{ends0}+\text{ends1}+1 < 3\times(10^9+1) < 2^{33}$，`int` 必溢出，用 `long long` 承载中间和。
5. **`has0` 与位置、次数无关**：`"0"` 作为子序列只需串里**存在**一个 `'0'`，任何位置见到就置位。
6. **与 940 的关系**：940 的通用公式 $dp \gets 2\,dp - last[c]$ 对整个字符表统一转移；本题字符集为 $\{0,1\}$ 且 `'0'` 开头的支路被「好」砍掉，$-last[c]$ 被「覆盖式重生成」吸收，化简为两计数器版本。

## 5. 正确性证明

以下记 $P_i = binary[0..i)$ 为前 $i$ 个字符的前缀；$G(P)$ 为 $P$ 的好子序列全体；$T(P) = G(P) \setminus \{\text{"0"}\}$（由引理 1，即 $P$ 中以 `'1'` 开头的子序列全体）；$E_c(P) = \{\, t \in T(P) : t \text{ 以 } c \text{ 结尾} \,\}$。

**引理 1（「好」的刻画与前缀封闭）**：
(a) 字符串 $t$ 是好子序列 $\iff$ $t = \text{"0"}$ 或 $t$ 以 `'1'` 开头。
(b) 若 $t \in T(P)$ 且 $|t| \ge 2$，则 $t$ 去掉末位后的串 $t^-$ 满足 $t^- \in T(P)$。

**证明**：(a) 是「无前导 0，除非整个串就是 "0"」的直接转述。(b) $t$ 好且 $t \ne \text{"0"}$，由 (a) $t$ 以 `'1'` 开头；$t^-$ 非空且仍以 `'1'` 开头，下标取 $t$ 的前 $|t|-1$ 个仍递增，故 $t^-$ 是 $P$ 的、无前导 0 且 $\ne \text{"0"}$ 的子序列，即 $t^- \in T(P)$。∎

**引理 2（重挂表示）**：设位置 $i$ 满足 $binary[i] = c$，则

$$E_c(P_{i+1}) \;=\; \{\, s + c \mid s \in T(P_i) \,\} \;\cup\; \begin{cases} \{\text{"1"}\}, & c = \text{'1'} \\ \varnothing, & c = \text{'0'} \end{cases}$$

且右端两个部分互不重复，故 $|E_c(P_{i+1})| = |T(P_i)| + [c = \text{'1'}]$。

**证明**：
（⊆）任取 $s \in T(P_i)$：$s$ 以 `'1'` 开头，故 $s + c$ 非空、以 `'1'` 开头、以 $c$ 结尾，且由「$s$ 的下标（均 $< i$）$+\ i$」构成 $P_{i+1}$ 的子序列 → 属于 $E_c(P_{i+1})$。`"1"` 显然属于 $E_1(P_{i+1})$。
（⊇）任取 $t \in E_c(P_{i+1})$，取其一组下标 $j_1 < \cdots < j_k$，则 $j_k \le i$ 且 $binary[j_k] = c = binary[i]$，把末位替换为下标 $i$，串值不变，故可设 $t$ 的末位取自位置 $i$。令 $s$ 为 $t$ 去掉末位：
- 若 $s = \varepsilon$：$t$ 是单字符。$t \in T$ 排除 $t = \text{"0"}$，故 $t = \text{"1"}$，且只能发生在 $c = \text{'1'}$ 时，对应右端第二部分；
- 若 $s \ne \varepsilon$：由引理 1(b)，$s \in T(P_i)$（$s$ 的下标均 $< i$），故 $t = s + c$ 属于右端第一部分。
（不重复）$s \mapsto s + c$ 为单射（去掉末位即逆映射），且 $s + c$ 长度 $\ge 2$、以 `'1'` 开头，与单字符 `"1"` 不同。∎

**定理 1（转移正确性）**：算法在处理完每个前缀 $P_i$ 后维持不变式

$$\text{ends0} = |E_0(P_i)|, \qquad \text{ends1} = |E_1(P_i)|.$$

**证明**：对 $i$ 归纳。$i = 0$：空前缀无好子序列，两计数器为 $0$ ✓。
归纳步 $i \to i + 1$，记 $c = binary[i]$：
- **另一桶不变**：若 $c = \text{'1'}$，以 `'0'` 结尾的子序列不可能使用位置 $i$，故 $E_0(P_{i+1}) = E_0(P_i)$，`ends0` 不动 ✓（$c = \text{'0'}$ 时对 `ends1` 同理）。
- **本桶覆盖**：由引理 2，$|E_c(P_{i+1})| = |T(P_i)| + [c = \text{'1'}]$。而 $T(P_i) = E_0(P_i) \sqcup E_1(P_i)$（$T$ 中每个串按末位二分，不重不漏），由归纳假设 $|T(P_i)| = \text{ends0} + \text{ends1}$。于是读 `'1'` 时 $\text{ends1} \leftarrow \text{ends0}+\text{ends1}+1$、读 `'0'` 时 $\text{ends0} \leftarrow \text{ends0}+\text{ends1}$，与代码一致 ✓。
- **覆盖不漏**：被丢弃的旧桶 $E_c(P_i) \subseteq E_c(P_{i+1})$——其中每个元素都是 $P_{i+1}$ 的以 $c$ 结尾的 $T$-子序列，而引理 2 的 (⊇) 方向给出了它们在新桶中的表示。∎

**定理 2（答案正确性）**：算法返回 $|G(binary)| \bmod (10^9+7)$。

**证明**：每个好子序列要么是 `"0"`，要么属于 $T$（引理 1(a)）；$T = E_0 \sqcup E_1$。而 `"0"` 是 `binary` 的子序列 $\iff$ `binary` 含 `'0'` $\iff$ `has0` 为真。故

$$|G(binary)| = |E_0| + |E_1| + (has0\,?\,1:0) = \text{ends0} + \text{ends1} + (has0\,?\,1:0),$$

最后由定理 1 与全程取模的同余性即得。∎

> 💡 引理 2 的 (⊇) 方向就是「重挂」的形式化：它同时回答了两个问题——为什么**覆盖**不漏计（旧桶整体包含于新桶）、为什么**单射**保证不重计（桶内元素由互异前缀一一生成）。这两个方向合起来，正是 `O(1)` 状态去重的完整合法性来源。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$——单趟扫描，每个字符一次 $O(1)$ 转移（两次加法、一次取模）；$n = 10^5$ 时约 $10^5$ 步，远在时限内。
- **空间复杂度**：$O(1)$——仅 `ends0` / `ends1` / `has0` 三个标量，与 $n$ 无关（这正是观察 A 的价值：不存任何字符串）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfUniqueGoodSubsequences(string binary) {
        const long long MOD = 1e9 + 7;
        long long ends0 = 0, ends1 = 0;   // 以 '0'/'1' 结尾的好子序列数（不含 "0"）
        bool has0 = false;               // 特例 "0" 的旁路标记
        for (char c : binary) {
            if (c == '0') {
                ends0 = (ends0 + ends1) % MOD;   // 覆盖：全体拼上这个 '0'
                has0 = true;
            } else {
                ends1 = (ends0 + ends1 + 1) % MOD;  // 覆盖：全体 + 新建 "1"
            }
        }
        return (int)((ends0 + ends1 + (has0 ? 1 : 0)) % MOD);
    }
};
```

### Python

```python
class Solution:
    def numberOfUniqueGoodSubsequences(self, binary: str) -> int:
        MOD = 10**9 + 7
        ends0 = ends1 = 0          # 以 '0'/'1' 结尾的好子序列数（不含 "0"）
        has0 = False               # 特例 "0" 的旁路标记
        for c in binary:
            if c == '0':
                ends0 = (ends0 + ends1) % MOD      # 覆盖式更新
                has0 = True
            else:
                ends1 = (ends1 + ends0 + 1) % MOD  # 覆盖式更新
        return (ends0 + ends1 + (1 if has0 else 0)) % MOD
```

> 💡 两个分支只读旧值、各写各的桶，转移顺序无关；`has0` 可以在任何时刻置位。C++ 用 `long long` 承载 $\text{ends0}+\text{ends1}+1$（可近 $3\times 10^9$，超出 `int` 上界）。

## 8. 边界情况与易错点

1. **读 `'0'` 误加 `+1`**：`"00"` 会算出 $2$（真实答案 $1$：只有 `"0"`）。两个错误叠加——每个 `'0'` 都把 `"0"` 计入 `ends0` 一次；且下一步 $s = \text{"0"}$ 作前缀拼出非法的 `"00"` 也被计入。
2. **用累加 `+=` 而非覆盖 `=`**：`"11"` 会算出 $3$ 而非 $2$（`"1"` 被新旧两轮重复计入）。引理 2 的 (⊇) 方向保证旧桶整体在新桶内，覆盖才安全——这是比赛时最容易凭直觉写错的一处。
3. **忘记 `has0` 通道**：`"001"` 会算出 $1$ 而非 $2$——特例 `"0"` 既进不了 `ends0`（显式排除）也进不了 `ends1`，必须最后单独 $+1$。
4. **C++ 中间和溢出**：$\text{ends0}+\text{ends1}+1$ 接近 $3 \times 10^9$，超过 `int` 上界 $\approx 2.1 \times 10^9$，须 `long long`（或逐项取模后再加）。
5. **答案取模后可能为 $0$**：真值是 $10^9+7$ 的倍数时返回 $0$，属正常，按题意返回取模值即可，不要特判。
6. **全 `'0'` 串 / 全 `'1'` 串是天然对拍样例**：全 `'0'` → `ends0`、`ends1` 恒 $0$，答案 $= has0 = 1$；全 `'1'` → `ends1` 每步恰 $+1$，答案 $= n$（好子序列为 `"1"`、`"11"`、…、$n$ 个 `'1'`）。
7. **不要按 (位置, 长度) 维度做普通计数 DP**：同值不同位置的子序列在该框架内无法区分（`"101"` 的 `"1"` 被两个位置各计一次），去重失败——见 §3.1。
8. **`has0` 与 `'0'` 的位置无关**：`"0"` 作为子序列只需串中存在 `'0'`，哪怕它出现在所有 `'1'` 之前（`"001"`）或之后（`"10"`）。
