# LeetCode 找出数组中的第 K 大整数 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的第 K 大整数（#1985，medium）
- **链接**：https://leetcode.cn/problems/find-the-kth-largest-integer-in-the-array/
- **来源**：LeetCode 第 256 场周赛 Q2
- **难度**：中等
- **标签**：字符串、排序、堆、快速选择

**题意**：给定字符串数组 `nums` 与整数 $k$，每个 `nums[i]` 表示一个**不含前导零**的非负整数（$1 \sim 100$ 位）。返回其中**第 $k$ 大**整数对应的字符串。重复数字按不同元素计——`["1","2","2"]` 中两个 `"2"` 分别算第 1 大与第 2 大。

**约束**：

- $1 \le k \le \text{nums.length} \le 10^4$
- $1 \le \text{nums}[i].\text{length} \le 100$
- `nums[i]` 仅由数字组成，且不含任何前导零

> 💡 本题在本仓库另有[每日题解 1985](../../solution/1901-2000/1985_找出数组中的第K大整数.md)：那边侧重「比较器设计细节、堆与快速选择的完整实现」与面试问答。本篇按周赛复盘视角，聚焦**赛场的最短切入路径**（读约束 → 识破大数陷阱 → 两行比较器）、**严格弱序等实现暗礁**，并补全「元组序 ≡ 数值序」的完整正确性证明。

## 2. 示例

**示例 1**

```text
输入：nums = ["3","6","7","10"], k = 4
输出："3"
解释：四个数全部等长，按字典序非递减排列为 ["3","6","7","10"]，
第 4 大即最小的 "3"。
```

**示例 2**

```text
输入：nums = ["2","21","12","1"], k = 3
输出："2"
解释：按数值非递减排列为 ["1","2","12","21"]，第 3 大是 "2"。
注意 "2" 与 "12" 长度不同——字典序的 "12" < "2" 在这里不适用。
```

**示例 3**

```text
输入：nums = ["0","0"], k = 2
输出："0"
解释：两个 "0" 重复但视为不同元素，第 1、第 2 大均为 "0"。
```

**示例 4（自拟：跨长度）**

```text
输入：nums = ["9","21"], k = 1
输出："21"
解释：数值上 21 > 9；但字典序 "9" > "21"（'9' > '2'）。
若比较器忘了先比长度，本题会错答 "9"。
```

## 3. 解题思路

### 3.1 暴力思路：转成整数再排序

最直觉的做法是把字符串转成整数，套用 [215. 数组中的第K个最大元素](../../solution/0201-0300/215_数组中的第K个最大元素.md) 的排序 / 快速选择模板。

**致命问题**：`nums[i]` 最长 $100$ 位，数值可达 $10^{100}$；而 64 位整数上限约 $9.2 \times 10^{18}$（19 位），差了约 81 个数量级。C++/Java 没有内置大整数，`stoll` 直接抛 `std::out_of_range`。Python 虽有任意精度整数，`nums.sort(key=int)` 确实能 AC，但要完成 $10^4 \times 100$ 位的转换与逐位数值比较，思路也不可移植——赛场上可以这么兜底，复盘时不应停在这里。

核心矛盾一句话：**题目要的是「比较」大数，从没要「算出」大数**。比较两个数不需要知道它们各是多少，而无前导零的数字字符串，恰好自带一套与数值序完全等价的比较规则。

### 3.2 核心观察：无前导零 ⇒「(长度, 字典序)」即数值序

![核心观察：长度优先 + 等长字典序等价于数值比较](images/wc256_q2_comparator_concept.svg)

无前导零意味着**字符串长度 = 数值位数**，比较分两段：

- **长度不同**：位数多者必大。最小的 $\ell+1$ 位数为 $10^{\ell}$，严格大于最大的 $\ell$ 位数 $10^{\ell}-1$（如 $100 > 99$），推到「100 位 vs 99 位」同样成立；
- **长度相同**：从左到右的字典序比较就是逐位数值比较，两者完全一致（如 `"12" < "21"` $\iff 12 < 21$）。

于是比较器两行写完：先比 `size()`，等长再比字典序。等价地，以元组 $(\text{len}(s),\ s)$ 为排序键——Python 里就是 `key=lambda s: (len(s), s)`。

> 💡 **赛况**：这是一道「读约束定算法」的题——看到「长度 ≤ 100」就应立即放弃转整数的念头，考点只剩比较器。本题唯一的坑（忘比长度、直接字典序）恰好被示例 2 拦住：`["2","21","12","1"]` 直接字典序排序会得到 `["1","12","2","21"]`，第 3 大错成 `"12"`。

### 3.3 算法流程

![算法流程：自定义比较器排序，返回 nums[n−k]](images/wc256_q2_algorithm_flow.svg)

1. **定义比较器** `cmp(a, b)`：`a.size() != b.size()` 时按长度定序；等长按字典序 `a < b`；
2. **排序**：用 `cmp` 对 `nums` 升序排序，重复元素保留；
3. **取位**：升序序列的第 $k$ 大就是下标 $n-k$ 处的元素，返回 `nums[n-k]`。

排序、快速选择（`std::nth_element`）、大小为 $k$ 的小顶堆三条路都通，区别只在比较次数：本题 $n \le 10^4$，全排序约 $1.4 \times 10^7$ 次字符比较，毫秒级完成——**排序法代码最短、无最坏情况，赛场上首选**。

### 3.4 示例演算

以**示例 2** `nums = ["2","21","12","1"]`、`k = 3` 演算：

![示例演算：按长度分桶、组内字典序、拼接后取 nums[n−k]](images/wc256_q2_example_walkthrough.svg)

| 步骤 | 操作 | 结果 |
|------|------|------|
| 分桶 | 按长度分组：长度 1 → `"1"`,`"2"`；长度 2 → `"12"`,`"21"` | — |
| 组内排序 | 各组按字典序：`"1" < "2"`、`"12" < "21"` | — |
| 拼接 | 短组在前、长组在后 | `["1", "2", "12", "21"]` |
| 取位 | $n = 4$、$k = 3$ → `nums[n−k] = nums[1]` | **`"2"`** |

从右往左验证：第 1 大 `"21"`、第 2 大 `"12"`、第 3 大 `"2"` ✓。长度 2 的两个数整体排在长度 1 之后，正是「长度即量级」的直观体现。

## 4. 算法细节

1. **比较器先判长度**：`a.size() != b.size()` 是 $O(1)$，等长才进入 $O(L)$ 的字典序比较。长度离散分布时绝大多数比较在第一段早退，实际常数远小于最坏 $O(L)$。
2. **等价的元组键**：两段式比较即元组 $(\text{len}(s),\ s)$ 的字典序。Python 直接 `key=lambda s: (len(s), s)`；C++ 用 `cmp` 仿函数，语义相同。
3. **严格弱序（C++ 暗礁）**：`std::sort` 要求比较器满足严格弱序（`cmp(x, x)` 必须为 `false`）。把 `a < b` 误写成 `a <= b` 会让内省排序的假设崩塌，可能直接越界崩溃。按「元组字典序」的语义写比较器，严格性自动成立。
4. **返回下标**：升序第 $k$ 大 = `nums[n-k]`，Python 可写 `nums[-k]`；$k=1$ 取最大、$k=n$ 取最小，同一公式自适应。
5. **备选路线**：`std::nth_element(nums.begin(), nums.begin()+n-k, nums.end(), cmp)` 平均 $O(n \cdot L)$，只定位不排全序；大小为 $k$ 的小顶堆 $O(n \log k \cdot L)$，适合 $k \ll n$ 或数据流场景——堆顶始终是「当前前 $k$ 大中的最小者」。
6. **`size()` 的无符号性**：`a.size() < b.size()` 两侧同为 `size_t`，不存在符号混用问题（与 Q1 中 `i < nums.size()` 的隐患不同）。

## 5. 正确性证明

**引理 1（长度即量级）**：设 $s$ 为不含前导零的十进制数字串，长度 $\ell(s)$，数值 $v(s)$。若 $\ell(a) > \ell(b)$，则 $v(a) > v(b)$。

**证明**：先建立两个界。上界：任意长度 $\ell$ 的数字串 $v \le \underbrace{99\cdots9}_{\ell} = 10^{\ell}-1$。下界：若 $s \ne$ `"0"`，则首位 $d \ge 1$，$v(s) \ge d \cdot 10^{\ell-1} \ge 10^{\ell-1}$。现设 $\ell(a) \ge \ell(b)+1$：由 $\ell(a) \ge 2$ 知 $a \ne$ `"0"`，故 $v(a) \ge 10^{\ell(a)-1} \ge 10^{\ell(b)} > 10^{\ell(b)}-1 \ge v(b)$。∎

**引理 2（等长时字典序 = 数值序）**：等长的十进制数字串 $s, t$（此条不依赖无前导零），$s <_{\text{lex}} t \iff v(s) < v(t)$。

**证明**：若 $s = t$ 显然。否则设从左起第一个不同的位为第 $i$ 位（$s_i \ne t_i$），其后各位之差满足 $\left|\sum_{j>i}(t_j - s_j)10^{\ell-j}\right| \le 9\sum_{r=0}^{\ell-i-1}10^{r} = 10^{\ell-i}-1 < 10^{\ell-i}$。于是

$$v(t) - v(s) = (t_i - s_i)\,10^{\ell-i} + \sum_{j>i}(t_j - s_j)\,10^{\ell-j}$$

中高位项绝对值 $\ge 10^{\ell-i}$、低位项绝对值 $< 10^{\ell-i}$，差的符号由最高不同位 $t_i - s_i$ 决定（低位之差不足以翻盘），而 $t_i - s_i$ 的符号恰是字典序比较的结果。∎

**引理 3（排序定位）**：$n$ 个元素非降排序后，第 $k$ 大（重复按不同元素计）位于下标 $n-k$。

**证明**：第 $k$ 大即非升次序下的第 $k$ 个元素；非降序列反读即非升，其第 $k$ 个即原序列下标 $n-k$ 处的元素。∎

**定理**：按 `cmp` 升序排序后返回 `nums[n-k]`，得到第 $k$ 大整数的字符串。

**证明**：`cmp` 与数值大小关系一致——长度不同时由引理 1，长度相同时由引理 2——故排序结果按数值非降。再由引理 3，`nums[n-k]` 恰为第 $k$ 大；排序不去重，与「重复视为不同元素」的定义相符。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n \cdot L)$，其中 $L \le 100$ 为最长位数。排序产生 $O(n \log n)$ 次比较，每次先 $O(1)$ 判长度、等长时最坏 $O(L)$ 字典序。$n = 10^4$ 时约 $10^4 \times 14 \times 100 \approx 1.4 \times 10^7$ 次字符比较，毫秒级。
- **空间复杂度**：$O(\log n)$，C++ 内省排序的递归栈（Python Timsort 需 $O(n)$ 临时空间）。若改用小顶堆则为 $O(k)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string kthLargestNumber(vector<string>& nums, int k) {
        auto cmp = [](const string& a, const string& b) {
            if (a.size() != b.size()) return a.size() < b.size();
            return a < b;
        };
        sort(nums.begin(), nums.end(), cmp);
        return nums[nums.size() - k];
    }
};
```

### Python

```python
class Solution:
    def kthLargestNumber(self, nums: List[str], k: int) -> str:
        nums.sort(key=lambda s: (len(s), s))
        return nums[-k]
```

> ⚠️ **赛场兜底**：Python 的 `nums.sort(key=int)` 依赖任意精度整数，能 AC 但不可移植到 C++/Java，且 $O(nL)$ 的转换开销更大。C++ 想省掉全排序，可用 `nth_element` 只定位第 $n-k$ 位（平均 $O(n \cdot L)$）：

```cpp
nth_element(nums.begin(), nums.begin() + nums.size() - k, nums.end(), cmp);
return nums[nums.size() - k];
```

## 8. 边界情况与易错点

1. **转整数必炸**：100 位数字超出 `long long`（19 位）约 81 个数量级，`stoll` 抛 `out_of_range`、Java `Long.parseLong` 直接报错。看到「长度 ≤ 100」就应转入字符串比较思路。
2. **忘比长度是最常见错误**：直接 `sort(nums)` 按字典序，则 `"9" > "21"`、`"12" < "2"`，示例 2 会错答 `"12"`。**必须先比长度**。
3. **`"0"` 无需特判**：无前导零保证 `"0"` 是零的唯一表示，长度 1、字典序最小，天然排最前（示例 3 两个 `"0"` 依重复计数输出 `"0"`）。
4. **重复元素不去重**：`["1","2","2"]` 的第 2 大是 `"2"` 而非 `"1"`；排序天然保留重复，切勿用 `set` 去重。
5. **k = 1 与 k = n**：分别取最大（`nums[n-1]`）与最小（`nums[0]`），公式 `nums[n-k]` 自适应，无需特判。
6. **C++ 比较器严格性**：写成 `<=` 违反严格弱序，`std::sort` 可能越界崩溃；按「元组 $(\text{len}, s)$ 字典序」的语义写即安全。
7. **返回原字符串**：答案要求返回 `nums` 中的字符串本身，不要做「转数值再转回字符串」的往返。
8. **Python 负索引**：`nums[-k]` 等价于 `nums[n-k]`；$k = n$ 时 `nums[-n] = nums[0]`，自然覆盖取最小的情形。
