# LeetCode 学生分数的最小差值 题解

## 1. 题目概述

- **标题 / 题号**：学生分数的最小差值（#1984，easy）
- **链接**：https://leetcode.cn/problems/minimum-difference-between-highest-and-lowest-of-k-scores/
- **来源**：LeetCode 第 256 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序、滑动窗口

**题意**：给定一个 **0 下标** 整数数组 `nums`，`nums[i]` 表示第 `i` 名学生的分数；另给整数 `k`。从数组中**任选** $k$ 名学生的分数，最小化这 $k$ 个分数中**最高分与最低分的差值**，返回可能的最小差值。

**约束**：

- $1 \le k \le \text{nums.length} \le 1000$
- $0 \le \text{nums}[i] \le 10^5$

> 💡 本题在本仓库另有[每日题解 1984](../../solution/1901-2000/1984_学生分数的最小差值.md)：那边侧重「极差类问题的通用范式」与面试问答。本篇按周赛复盘视角，聚焦**赛场的最短切入路径**（题面三个关键词 → 模板识别）与**交换论证的完整正确性证明**，并补充重复分数、$k = n$ 等边界处理。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [90], k = 1
输出：0
解释：只选 90 这一个分数，最高分 = 最低分 = 90，差值为 0。
```

**示例 2**

```text
输入：nums = [9,4,1,7], k = 2
输出：2
解释：6 种选法中，选 {9, 7} 时差值 9 − 7 = 2 最小。
```

**示例 3（自拟：k = n）**

```text
输入：nums = [9,4,1,7], k = 4
输出：8
解释：必须全选，唯一选法的差值 = max − min = 9 − 1 = 8。
```

**示例 4（自拟：重复分数）**

```text
输入：nums = [5,5,9], k = 2
输出：0
解释：两名 5 分的学生都选上，最高分 = 最低分 = 5，差值为 0。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素：枚举全部 $\binom{n}{k}$ 个 $k$ 元子集，逐个求 $\max - \min$。$n = 1000$、$k \approx n/2$ 时组合数高达约 $10^{299}$，完全不可行。

次一级：**排序后**枚举「最小值下标 $i$、最大值下标 $j$（$j \ge i + k - 1$）」的所有对，取 $a[j] - a[i]$ 的最小值——$O(n^2) \approx 10^6$ 对，在 $n \le 1000$ 的数据下**赛场上能过**。但它仍在重复劳动：固定左端 $i$ 后，右端取得越小差值越小，最右只需看到 $i + k - 1$，根本没有必要扫到 $j$ 更远的位置。

### 3.2 核心观察：排序后，最优的 k 个必然连续

![核心观察：排序后跳跃选择可被连续窗口替换且差值不增](images/wc256_q1_sort_window_concept.svg)

题面三个关键词直接给出模板：

- **「任选 $k$ 名」**——是任意子集，不要求相邻，学生顺序无意义 → 可以**排序**；
- **「最高分 − 最低分」**——差值只由所选子集的最小/最大值决定，中间 $k - 2$ 个数不影响答案；
- **「最小化」**——「选 $k$ 个使极差最小」正是经典的**排序 + 定长滑窗**模板。

于是关键洞察分两步：

- **观察 1（极差只看端点）**：「选哪 $k$ 个」可以简化为「最小值落在哪、最大值落在哪」，中间的数只要**塞得下**即可；
- **观察 2（连续窗口不劣）**：排序后，若某选择的最小值落在下标 $i_1$，则窗口 $[i_1,\ i_1 + k - 1]$ 与它**同左端点**，而右端从「实际最大值的位置」收紧到「第 $k$ 个位置」，差值只会更小（见上图：跳跃选 $\{1,9\}$ 差值 8，被同起点的窗口 $\{1,4\}$ 差值 3 支配）。

因此**全体子集的最小差值 = 全体长度为 $k$ 的连续窗口的最小差值**，只需枚举排序数组中的 $n - k + 1$ 个窗口。

> 💡 **赛况**：签到题的「模板识别」打法——读到「选 $k$ 个、极差最小」应条件反射地写「排序 + 定长滑窗」，从题面到代码一分钟以内。

### 3.3 算法流程

![算法流程：排序 → 一趟滑窗 → 维护最小差值](images/wc256_q1_algorithm_flow.svg)

1. **排序**：`nums` 升序排序；
2. **初始化**：`ans = +∞`；
3. **滑窗扫描**：$i$ 从 $0$ 到 $n - k$，对每个窗口 $[i,\ i + k - 1]$ 计算 $\text{nums}[i + k - 1] - \text{nums}[i]$，更新 `ans`；
4. **返回** `ans`。

有序数组中窗口的 $\max$ 就是右端、$\min$ 就是左端，**每个窗口 $O(1)$ 端点相减**，无需任何窗口内数据结构——这是定长滑窗的最简形态。

### 3.4 示例演算

以**示例 2** `nums = [9,4,1,7]`、`k = 2` 演算：

![示例演算：排序后 [1,4,7,9] 三个窗口差值 3、3、2，最小为 2](images/wc256_q1_example_walkthrough.svg)

| 步骤 | 排序后数组 | 窗口 | 差值 | ans |
|------|-----------|------|------|-----|
| 排序 | `[1, 4, 7, 9]` | — | — | `+∞` |
| $i=0$ | `[1, 4, 7, 9]` | `[1, 4]` | $4 - 1 = 3$ | `3` |
| $i=1$ | `[1, 4, 7, 9]` | `[4, 7]` | $7 - 4 = 3$ | `3` |
| $i=2$ | `[1, 4, 7, 9]` | `[7, 9]` | $9 - 7 = 2$ | `2` |

- 只考察 $n - k + 1 = 3$ 个窗口，而非 $\binom{4}{2} = 6$ 个子集；
- 最小差值为 `2`，对应选出 $\{7, 9\}$，与题面枚举 6 种选法的结果一致。

## 4. 算法细节

1. **排序的全部回报**：升序数组中任意区间 $[l, r]$ 的最大值 = $a[r]$、最小值 = $a[l]$——把窗口内 $O(k)$ 的极值查询降为 $O(1)$ 端点相减。
2. **窗口数 = $n - k + 1$**：左端点 $i \in [0, n - k]$，右端 $i + k - 1 \le n - 1$ 恰好压到最后一个元素。
3. **循环边界**：`i + k - 1 < n`、`i + k <= n`、`i <= n - k` 三种写法等价；C++ 中把 `nums.size()` 显式转成 `int` 再比较，避免有符号/无符号混用警告。
4. **数据类型**：值 $\le 10^5$，差值 $\le 10^5$，`int` 足够，无需 `long long`。
5. **$k = 1$ 与 $k = n$ 自适应**：$k = 1$ 时每个窗口差值为 0（见正确性：窗口 $[i, i]$）；$k = n$ 时只有唯一窗口 $[0, n-1]$。两者均无需特判。

## 5. 正确性证明

**引理 1（极差只依赖端点）**：任一 $k$ 元选择 $S$ 的差值 $D(S) = \max S - \min S$，与 $S$ 中其余 $k - 2$ 个数无关。

**证明**：差值按定义即 $\max S - \min S$，中间元素不进入表达式。∎

**引理 2（下标跨度）**：设 $a$ 为升序排序后的数组，任一合法选择对应 $k$ 个互异下标 $j_1 < j_2 < \cdots < j_k$，则 $j_k - j_1 \ge k - 1$，即 $j_1 + k - 1 \le j_k \le n - 1$。

**证明**：$k$ 个严格递增整数的相邻间隔至少为 1，首尾跨度至少为 $k - 1$ 个间隔之和 $\ge k - 1$。∎

**引理 3（连续窗口替换不增）**：对上述任意选择 $S$，连续窗口 $W = \{a[j_1], a[j_1 + 1], \ldots, a[j_1 + k - 1]\}$ 是合法的 $k$ 元选择，且 $D(W) \le D(S)$。

**证明**：合法性由引理 2（窗口右端不越界）保证。差值方面，$D(W) = a[j_1 + k - 1] - a[j_1] \le a[j_k] - a[j_1] = D(S)$，其中不等号由 $j_1 + k - 1 \le j_k$ 及 $a$ 升序（下标大者值不小）得到。∎

**定理**：算法返回的 $\min_{0 \le i \le n - k}\big(a[i + k - 1] - a[i]\big)$ 等于所有 $k$ 元选择的最小差值。

**证明**：

- **算法值 $\ge$ 最优值**：每个连续窗口本身就是合法的 $k$ 元选择，其差值不低于全体选择的最小差值，取 min 后仍如此；
- **算法值 $\le$ 最优值**：任一选择 $S$ 由引理 3 被某个枚举范围内的窗口 $W$ 支配（$D(W) \le D(S)$），故算法的最小值 $\le D(W) \le D(S)$；对全体 $S$ 成立，即 $\le$ 最优值。

两个方向合起来，算法返回值恰为最小差值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序 $O(n \log n)$ 是瓶颈；一趟滑窗 $O(n)$，每个窗口 $O(1)$（端点相减）。$n \le 1000$ 时约 $10^4$ 次操作，远在时限内；即使 $n$ 放大到 $10^5$ 也从容。
- **空间复杂度**：$O(\log n)$。仅排序的递归栈 / 临时空间（C++ `std::sort` 内省排序、Python Timsort），不计输入数组的原地排序外无额外开销。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumDifference(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        int ans = INT_MAX;
        for (int i = 0; i + k - 1 < n; ++i) {
            ans = min(ans, nums[i + k - 1] - nums[i]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumDifference(self, nums: List[int], k: int) -> int:
        nums.sort()
        n = len(nums)
        ans = float('inf')
        for i in range(n - k + 1):
            ans = min(ans, nums[i + k - 1] - nums[i])
        return ans
```

（Python 亦可一行收工：`return min(nums[i + k - 1] - nums[i] for i in range(len(nums) - k + 1))`。）

> ⚠️ **赛场兜底**：$n \le 1000$ 放得很松，即便一时没想到引理 3，「排序 + 双重循环枚举 $(i, j \ge i + k - 1)$ 取 $a[j] - a[i]$ 最小」的 $O(n^2)$ 写法也能过。但正解与它的代码量完全相同——没有理由停在 $O(n^2)$。

## 8. 边界情况与易错点

1. **忘排序是最常见错误**：在**原数组**上滑窗，窗口两端不是 $\max / \min$，直接得到错误答案。窗口是定义在**排序后**的数组上的。
2. **读题坑：「任选 k 名」≠「相邻 k 名」**：题目选的是任意子集。若误读成「选连续 $k$ 名学生」（子数组），会得到完全不同的问题（见延伸思考）。
3. **k = 1**：任一窗口差值为 0，直接返回 0；循环条件 `i <= n - 1` 自然成立，无需特判（示例 1）。
4. **k = n**：唯一窗口 $[0, n-1]$，答案即全局极差（自拟示例 3）。
5. **重复分数**：两个相同分数可同时入选，差值可为 0（自拟示例 4）。排序后相同值相邻，窗口天然覆盖——**千万不要去重**：去重后「两个 5」只剩一个，$[5,5,9]$、$k=2$ 会从 0 错成 4。
6. **循环边界差一**：`i` 的上界是 `n - k`；写成 `n - k + 1` 会越界访问 `nums[i + k - 1]`（C++ 中为未定义行为，Python 抛 IndexError）。
7. **有符号/无符号比较**：C++ 中 `i + k - 1 < (int)nums.size()` 建议显式转 `int`，否则 `int` 与 `size_t` 比较触发警告（本题不影响正确性，但值得养成习惯）。
