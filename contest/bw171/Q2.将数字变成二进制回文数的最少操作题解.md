# LeetCode 将数字变成二进制回文数的最少操作 题解

## 1. 题目概述

- **标题 / 题号**：将数字变成二进制回文数的最少操作（#3766，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-binary-palindrome/
- **来源**：LeetCode 第 171 场双周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、双指针、二分查找

**题意**：对数组 `nums` 的每个元素 $nums[i]$，可以反复执行「$+1$」或「$-1$」（任意次、任意方向）。若一个数的**二进制表示**（无前导零）正读反读相同，则称它是**二进制回文数**。求把每个 $nums[i]$ 变成二进制回文数所需的**最少操作次数**，返回结果数组。

**约束**：

- $1 \le nums.length \le 5000$
- $1 \le nums[i] \le 5000$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4]
输出：[0,1,1]
解释：1 = "1" 已是回文（0 次）；2 = "10" → 3 = "11"（+1）；
     4 = "100" → 3 = "11"（−1）。
```

**示例 2**

```text
输入：nums = [6,7,12]
输出：[1,0,3]
解释：6 = "110" → 5 = "101"（−1）；7 = "111" 已是回文（0 次）；
     12 = "1100" → 15 = "1111"（+3）。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $x$，从 $d = 0, 1, 2, \ldots$ 开始，检查 $x - d$ 与 $x + d$ 是否为二进制回文，第一个命中的 $d$ 就是答案。正确但最坏要扫很远（本题实测最大距离 48，尚可），且每个数都要重复做「构造二进制串 + 判回文」，$5000$ 个数 × 上百次检查 = 有点浪费。

更聪明的做法：**预处理**所有二进制回文数，查询时二分找最近的一个。

### 3.2 核心观察：最近回文数必是有序表中的相邻元素

![先筛出全部二进制回文数，再在有序表里二分找左右邻居](images/bw171_q2_precompute_and_search.svg)

关键事实：把 $[1, M]$ 内所有二进制回文数**升序**排成数组 $P$，则对任意 $x$，最近的回文数是

$$\arg\min_{p \in P} \lvert x - p \rvert \in \{\,P[\text{lower\_bound}(x)],\ P[\text{lower\_bound}(x)-1]\,\}$$

即「第一个 $\ge x$ 的」与「最后一个 $< x$ 的」之一。于是每个查询只需 $O(\log |P|)$。

两个配套结论：

- **上界取多大**：$nums[i] \le 5000$，只需保证最近的回文数不超过 $M = 16384 = 2^{14}$。实测 $[1, 5000]$ 内最近距离最大仅 48（出现在 2097），远在范围内，所以 $M = 2^{14}$ 绰绰有余。
- **回文数个数很少**：$M = 2^{14}$ 内只有 $254$ 个二进制回文数（长度 $L$ 的回文数由前 $\lceil L/2 \rceil$ 位唯一确定，共 $2^{\lceil L/2\rceil - 1}$ 个），二分极快。

### 3.3 算法流程

![算法流程：预处理 + 逐元素二分](images/bw171_q2_algorithm_flow.svg)

```text
1. pals = [v for v in 1..16383 if 二进制(v) 是回文]   # 升序
2. 对每个 x in nums:
       i = lower_bound(pals, x)          # 第一个 >= x 的下标
       best = +∞
       若 i < len(pals):        best = min(best, pals[i] - x)
       若 i > 0:                best = min(best, x - pals[i-1])
       ans.append(best)
3. 返回 ans
```

### 3.4 示例演算

对示例 1 的 `nums = [1, 2, 4]`，先看 $[1, 15]$ 内的二进制回文数：

| v | 二进制 | 回文？ |
|---|--------|--------|
| 1 | 1 | ✓ |
| 2 | 10 | ✗ |
| 3 | 11 | ✓ |
| 4 | 100 | ✗ |
| 5 | 101 | ✓ |
| 6 | 110 | ✗ |
| 7 | 111 | ✓ |
| 9 | 1001 | ✓ |
| 15 | 1111 | ✓ |

查询过程：

| x | lower_bound 位置 | 右侧候选 | 左侧候选 | 答案 |
|---|------------------|----------|----------|------|
| 1 | 指向 1 | 1（距离 0） | — | 0 |
| 2 | 指向 3 | 3（距离 1） | 1（距离 1） | 1 |

与示例输出 `[0, 1, 1]` 一致。示例 2 中 $12 = \texttt{1100}$ 的左右邻居是 $9 = \texttt{1001}$（距离 3）与 $15 = \texttt{1111}$（距离 3），实际输出 3——两个方向都是 3，说明本题**不需要**区分加减方向，只数步数。

## 4. 算法细节

1. **判二进制回文**：取最低位依次入栈（数组），再双指针从两端夹；或用 `bitset` / `std::string`。注意**不含前导零**，所以从最低位开始收集到的位数就是真实长度。
2. **预处理一次即可**：$nums$ 有 $5000$ 个元素，若每次调用都重建 $2^{14}$ 规模的表，最坏 $5000 \times 5000 \times 14$ 次位运算——在单次 LeetCode 调用里没问题，但在多次调用的测试环境下会明显变慢。用 `static` 局部变量（C++）或模块级缓存（Python）只建一次。
3. **`lower_bound` 语义**：C++ `lower_bound` 返回第一个 $\ge x$ 的位置；`std::set` 也可，但数组二分更快。
4. **两个候选都要看**：只看向右或只看向左都会错。例如 $x = 2$ 时左右各 1 步；$x = 2097$ 时最近的是左侧的 2047（距离 50）而右侧更远，必须双向取 min。
5. **答案非负**：$x$ 本身是回文时距离为 0，直接命中，无需特判。
6. **值域与上界**：$nums[i] \le 5000$，最近的回文数可能大于 $5000$（例如 $5001$ 的最近是 $5049$，需要向右看）。所以上界必须留余量，取 $2^{14}$ 而非 $\max(nums)$，否则会漏掉右侧候选。

## 5. 正确性证明

**引理 1（最近邻必在左右两侧）**：设 $P$ 升序、非空，$x$ 为任意整数，$i = \text{lower\_bound}(P, x)$。则 $\min_{p \in P}\lvert x-p\rvert = \min\big(\lvert P[i]-x\rvert\ (\text{若 } i<|P|),\ \lvert x-P[i-1]\rvert\ (\text{若 } i>0)\big)$。

**证明**：$P$ 升序，故 $P[0..i-1] < x \le P[i..|P|-1]$（若 $i = |P|$ 则所有元素都 $< x$）。对任意 $j < i-1$，有 $P[j] < P[i-1] < x$，故 $\lvert x-P[j]\rvert = x - P[j] > x - P[i-1] = \lvert x - P[i-1]\rvert$，即左侧更远的元素不可能更优。对任意 $j > i$，有 $P[j] > P[i] \ge x$，故 $\lvert P[j]-x\rvert = P[j] - x > P[i] - x$，右侧更远的也不可能更优。故最优值只可能出现在 $P[i]$ 与 $P[i-1]$ 两者中。∎

**引理 2（枚举完整）**：预处理得到的 `pals` 恰好是 $[1, 2^{14}-1]$ 内全部二进制回文数，且升序。

**证明**：循环从 1 到 $2^{14}-1$ 逐一检查、满足条件才加入，故集合相等；按下标递增遍历，故升序。∎

**引理 3（取值范围足够）**：对任意 $x \in [1, 5000]$，$[1, 2^{14}-1]$ 内存在回文数 $p$ 使 $\lvert x - p\rvert$ 等于全体正整数中最近的距离。

**证明**：只需说明「最近的回文数」不会出现在 $[1, 2^{14}-1]$ 之外。$4095 = \texttt{111111111111}$（12 个 1）是回文数，对任意 $x \le 5000$ 有 $\lvert x - 4095\rvert \le 905$ 或 $x < 4095$ 时更小。若最近回文数 $p > 2^{14}-1 = 16383$，则 $\lvert x - p\rvert \ge 16384 - 5000 = 11384 > 905$，与 $4095$ 的候选矛盾。故最近者必在范围内（实际上实测最大距离仅 48）。∎

**定理**：算法输出的第 $i$ 项等于把 $nums[i]$ 变成二进制回文数的最少操作次数。

**证明**：每次操作使数值改变 $\pm 1$，故把 $x$ 变成 $p$ 所需操作数恰为 $\lvert x - p\rvert$（下界：每步最多改变距离 1；可达：朝 $p$ 方向走 $\lvert x-p\rvert$ 步）。因此最少操作次数 $= \min_{p \in \text{回文数}} \lvert x-p\rvert$。由引理 2、3，该最小值等于在 `pals` 上取到的最小值；由引理 1，二分左右邻居即可取到。∎

## 6. 复杂度分析

- **时间**：预处理 $O(M \log M)$（$M = 2^{14}$，每个数 $O(\log M)$ 判回文），只做一次；每个查询一次二分 $O(\log |P|) \approx O(10)$，共 $O(n \log |P|)$。总时间 $O(M \log M + n \log |P|)$，实际约 $2 \times 10^5 + 5 \times 10^4$ 次操作。
- **空间**：$O(|P|)$ 存回文数表（$254$ 项）与 $O(n)$ 输出数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minOperations(vector<int>& nums) {
        static const vector<int> pals = buildPalindromes();
        vector<int> ans;
        ans.reserve(nums.size());
        for (int x : nums) {
            auto it = lower_bound(pals.begin(), pals.end(), x);
            int best = INT_MAX;
            if (it != pals.end()) best = min(best, *it - x);
            if (it != pals.begin()) best = min(best, x - *(it - 1));
            ans.push_back(best);
        }
        return ans;
    }

private:
    static bool isBinaryPalindrome(int v) {
        int bits[32], len = 0;
        while (v > 0) {
            bits[len++] = v & 1;
            v >>= 1;
        }
        for (int i = 0, j = len - 1; i < j; i++, j--) {
            if (bits[i] != bits[j]) return false;
        }
        return true;
    }

    static vector<int> buildPalindromes() {
        vector<int> pals;
        for (int v = 1; v < (1 << 14); v++) {
            if (isBinaryPalindrome(v)) pals.push_back(v);
        }
        return pals;
    }
};
```

### Python

```python
from bisect import bisect_left

_PALINDROMES = None


def _binary_palindromes():
    global _PALINDROMES
    if _PALINDROMES is None:
        _PALINDROMES = [
            v for v in range(1, 1 << 14) if bin(v)[2:] == bin(v)[2:][::-1]
        ]
    return _PALINDROMES


class Solution:
    def minOperations(self, nums: list[int]) -> list[int]:
        pals = _binary_palindromes()
        ans = []
        for x in nums:
            i = bisect_left(pals, x)
            best = None
            if i < len(pals):
                best = pals[i] - x
            if i > 0:
                d = x - pals[i - 1]
                best = d if best is None else min(best, d)
            ans.append(best)
        return ans
```

## 8. 边界情况与易错点

1. **前导零**：判回文时必须用「无前导零」的二进制表示。若用定长（如 14 位）补零后判回文，$1 = \texttt{00000000000001}$ 会被判成非回文。代码从最低位收集、长度为真实位数，天然正确。
2. **只看向一侧**：$x = 2$ 的左右邻居距离都是 1，$x = 2097$ 的最近在左侧，只看向右会得到错误答案。必须两侧取 min。
3. **上界卡太死**：若把预处理上界设成 $\max(nums)$，那么「比最大值略大的最近回文数」就不会被枚举到。必须留余量（本题用 $2^{14}$）。
4. **$x$ 本身是回文**：`lower_bound` 会精确命中，距离 0，无需特判；但要确保比较用的是 `>=` 语义（`lower_bound` 而非 `upper_bound`，两者在命中时结果相同，但对距离计算要注意取 `*it - x`）。
5. **`INT_MAX` 溢出**：C++ 里若把 `best` 初值设成 `INT_MAX` 再参与 `min` 是安全的（`min` 不会做加法），但若写成 `best + something` 就会溢出；注意别在初值上做运算。
6. **重复元素**：`nums` 可能含重复值，逐个查询即可，无需去重（去重反而要维护映射）。
7. **多次调用**：`static` / 全局缓存很关键，否则每次调用都重建 $2^{14}$ 的表。
