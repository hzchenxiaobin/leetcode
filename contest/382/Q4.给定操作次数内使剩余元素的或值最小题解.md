# LeetCode 给定操作次数内使剩余元素的或值最小 题解

## 1. 题目概述

- **标题 / 题号**：给定操作次数内使剩余元素的或值最小（#3022，hard）
- **链接**：https://leetcode.cn/problems/minimize-or-of-remaining-elements-using-operations/
- **来源**：LeetCode 第 382 场周赛 Q4
- **难度**：困难
- **标签**：贪心、位运算、数组

**题意**：给定下标从 0 开始的整数数组 `nums` 和整数 $k$。一次操作可选择满足 $0 \le i < \text{len} - 1$ 的下标 $i$，把相邻的两个元素 $\text{nums}[i]$、$\text{nums}[i+1]$ **替换成一个数** $\text{nums}[i] \mathbin{\&} \text{nums}[i+1]$（数组长度减 1）。在**至多 $k$ 次操作**内，最小化剩余所有元素的按位 **OR**。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $0 \le \text{nums}[i] < 2^{30}$
- $0 \le k < \text{nums.length}$

> ⚠️ 题面里两个细节决定解法走向：操作对象是**相邻**元素、合并后**两变一**。这暗示终态不是任意集合，而是一个「连续段划分」——全题的突破口。

## 2. 示例

**示例 1**

```text
输入：nums = [3,5,3,2,7], k = 2
输出：3
解释：合并 3,5 → 1，再合并 3,2 → 2，数组变为 [1,3,2]，
      OR = 1 | 3 | 2 = 3。
```

**示例 2**

```text
输入：nums = [7,3,15,14,2,8], k = 4
输出：2
解释：4 次操作可把数组缩成 [2, 0]，OR = 2。
```

**示例 3**

```text
输入：nums = [10,7,10,3,9,14,9,4], k = 1
输出：15
解释：一次操作得不偿失，不动最优，OR = 15。
```

## 3. 解题思路

### 3.1 暴力思路

每一步操作有 $O(n)$ 种选法，至多 $k \le n - 1$ 步，搜索树约 $n^{n}$ 规模；即使发现「终态只与划分有关」，用记忆化枚举所有划分，也是 $2^{n-1}$ 级别（每条相邻缝隙切或不切），$n = 10^5$ 完全不可行。

> 💡 **转换视角**：不要逐步模拟「怎么操作」，先刻画「终态长什么样」——把操作序列翻译成一个**组合结构**（连续段划分），再把「最小化 OR」拆成**逐位的 0/1 决策**。

### 3.2 核心观察：操作 ⟺ 连续段划分

![核心概念：操作等价于连续段划分](images/wc382_q4_partition_concept.svg)

**观察 1（终态刻画）**：每次操作把相邻两数并成它们的 AND。由 AND 结合律，归纳可证：**任何操作序列的终态，都等于把原数组切成若干连续段、每段缩成段内所有数的 AND**；反之任何切法都能实现（每段内自左向右逐对合并）。切成 $m$ 段恰用 $n - m$ 次操作，于是

$$\text{「至多 } k \text{ 次操作」} \iff \text{「段数} \ge n - k\text{」}$$

问题改写为：**在段数 $\ge n - k$ 的所有连续段划分中，最小化各段 AND 的按位 OR**。

**观察 2（OR 按位独立，从高位往低位清零）**：答案一定是 $\text{full} = \text{nums}[0] \,|\, \text{nums}[1] \,|\, \cdots$ 的子掩码。OR 的每一位独立贡献 $2^b$，我们逐位决策：维护 $\text{cleared}$ = **已确认能全部清零的位集合**，从 $b = 29$ 到 $0$ 逐位试探 $\text{mask} = \text{cleared} \,|\, (1 \ll b)$——

- 问：是否存在 $\le k$ 次操作的方案，使**每个剩余元素**与 $\text{mask}$ 按位与为 0？
- 可行则 $\text{cleared} \leftarrow \text{mask}$（位 $b$ 确认清零）；不可行则位 $b$ 留在答案里。

注意检查时**未决策的低位不受约束**——它们「允许留下」，所以位与位之间的检查互不干扰、可以叠加。

**观察 3（可行性检查 = 一趟贪心扫描）**：给定 mask，求「让每段 AND 都与 mask 不相交」的**最少操作数**（等价于最多段数）。从左到右扫描，`cur` 累积当前段的 AND：

- 若 $\text{cur} \mathbin{\&} \text{mask} = 0$：本段已合法，**立刻切段**（免费），`cur` 复位全 1；
- 否则 `cnt++`：当前段必须继续吞并下一个元素（花 1 次操作）。

扫描结束时 `cnt` 恰为最少操作数。两个关键细节：

- **尾段没收尾**：把尾段并入上一段——并段 AND 是上一段 AND 的子掩码（AND 的元素越多位越少），上一段合法则并段自动合法，其代价恰好就是尾段最后一个元素在扫描中计的那一次 `cnt`；
- **全体 AND 都压不干净**：任何连续段的 AND 都是全体 AND 的超集，一次段也切不出来，$\text{cnt} = n > k$（因 $k \le n - 1$）自动否决，**无需特判**。

### 3.3 算法流程

![逐位贪心与可行性扫描流程](images/wc382_q4_bit_greedy_flow.svg)

整体三步：求 `full` → 从高位到低位逐位试探（每位一趟 $O(n)$ 扫描计 `cnt`）→ 返回 `full & ~cleared`。

其中「切段要趁早」的直觉：**区间越长，AND 保留的位越少**。某个前缀一旦合法，延长只会更合法；早切段给后面的元素留出更多划分空间，是对「最多段数」的贪心。

### 3.4 示例演算

![示例 2 的逐位演算](images/wc382_q4_example_walkthrough.svg)

以示例 2 `nums = [7,3,15,14,2,8], k = 4` 走一遍（$\text{full} = 15 = 1111_2$，各元素二进制：$7{=}0111$、$3{=}0011$、$15{=}1111$、$14{=}1110$、$2{=}0010$、$8{=}1000$）：

| 试探位 | mask | 动作序列（切 = 段收尾 / 吞 = 必须并入下一位） | cnt | 结论 |
|--------|---------|-----------------------------------------------|-----|------|
| bit 3 | $1000_2$ | 切 · 切 · 吞 · 吞 · 切 · 吞 | 3 | ✓ 清零 |
| bit 2 | $1100_2$ | 吞 · 切 · 吞 · 吞 · 切 · 吞 | 4 | ✓ 清零 |
| bit 1 | $1110_2$ | 吞 · 吞 · 吞 · 吞 · 吞 · 切 | 5 | ✗ 保留 |
| bit 0 | $1101_2$ | 吞 · 吞 · 吞 · 切 · 切 · 吞 | 4 | ✓ 清零 |

- **bit 3**：$7$、$3$ 天然不含 bit 3，各自成段；$15,14$ 都含 bit 3 只能互吞，吞进 $2$ 后 AND 变 $0010$ 合法切段；末尾 $8$ 与 mask 相撞，尾段并入上一段。$\text{cnt} = 3 \le 4$ ✓。
- **bit 1**：$7$ 开始一直吞到 $14$，AND 才降到 $0010$，但仍含 bit 1；直到 $8$ 才把 AND 清成 $0000$——可惜 $\text{cnt} = 5 > 4$，切得太晚，bit 1 只能保留。
- **bit 0**：$7,3,15$ 连吞三次后 AND $= 0011$ 仍含 bit 0，吞进 $14$ 后 AND $= 0010$ 合法切段；$2$ 自成一段；末尾 $8$ 尾段并入。对应划分 $[7,3,15,14],\ [2,8]$，各段 AND 为 $2, 0$，OR $= 2$，操作 $3 + 1 = 4 = k$ ✓——与官方解释 $[2, 0]$ 完全一致。

最终 $\text{cleared} = 1101_2$（bit 3、bit 2、bit 0 清零），答案 $= 1111_2 \mathbin{\&} 0010_2 = 0010_2 = \mathbf{2}$ ✓。

## 4. 算法细节

1. **预处理 full**：答案只会是 `full` 的子掩码（每个剩余元素都是若干原数的 AND，是 `full` 的子掩码）。不在 `full` 中的位任何元素都为 0，天然「已清零」，外层循环直接跳过。
2. **cur 初始化为全 1**：C++ / Python 都写 `cur = -1`（补码全 1），首次 `cur &= x` 后即等于 $x$。
3. **cnt 的语义**：每个「不能作为段尾」的元素各计一次 cnt，恰好对应一次必须执行的合并。设扫描中共切段 $t$ 次，则 $\text{cnt} = n - t$ 且隐含划分恰用 $\text{cnt}$ 次操作（尾段并入上一段的代价 = 尾段最后一个元素的那次 cnt）。
4. **提前退出**：`cnt > k` 时后继扫描已无意义，直接 break；退出后 `cnt <= k` 必为假，判定不受影响。
5. **失败的位不回退**：位 $b$ 试探失败时什么都不用做——它不会进入 `cleared`，自动经 `full & ~cleared` 留在答案里。
6. **试探集合必须叠加**：检查用 `cleared | (1 << b)` 而不是单独的 `(1 << b)`——已确认的高位必须同时满足，位与位不冲突但**共同生效**。

## 5. 正确性证明

**引理 1（终态 = 连续段划分）**：任何操作序列执行 $t$ 次后的数组，等于把原数组切成 $n - t$ 个连续段、每段缩成段内 AND 的结果；反之任何 $m$ 段的划分都可用恰好 $n - m$ 次操作实现。

**证明**：对操作次数归纳。初始每个元素对应长度 1 的段，值即自身。设某时刻各元素对应连续段 $S_1, \dots, S_m$ 且值为各自段 AND；对相邻两段操作后，新元素对应段 $S_j \cup S_{j+1}$，值为 $\text{AND}(S_j) \mathbin{\&} \text{AND}(S_{j+1}) = \text{AND}(S_j \cup S_{j+1})$（AND 结合律），段数减 1。反之，每段内自左向右逐对合并，长度 $\ell$ 的段用 $\ell - 1$ 次，合计 $\sum (\ell_i - 1) = n - m$。∎

**引理 2（切段趁早）**：固定 mask，贪心扫描得到的 $\text{cnt}$ 等于「使每个剩余元素与 mask 不相交」的最少操作数。

**证明**：设扫描共切段 $t$ 次，则 $\text{cnt} = n - t$。这 $t$ 个切段位置本身给出一个合法划分：末尾若有残留元素未切段（其 AND 与 mask 相交），把它并入最后一个切段——并段 AND 仍是原段 AND 的子掩码，合法性保持；该划分恰用 $n - t = \text{cnt}$ 次操作。故最少操作数 $\le \text{cnt}$。

再证任何合法划分 $Q$ 至多 $t$ 段。记 $f(i)$ = 使「从下标 $i$ 开始的段」AND 与 mask 不相交的最早右端点；因区间越大 AND 保留的位越少，$i \le i' \Rightarrow f(i) \le f(i')$。贪心第 $j$ 个切段位置满足 $p_j = f(p_{j-1} + 1)$（$p_0 = -1$）。对 $Q$ 的第 $j$ 个段尾 $c_j$ 归纳：$c_1$ 处前缀段合法，故 $c_1 \ge f(0) = p_1$；设 $c_{j-1} \ge p_{j-1}$，则 $c_j \ge f(c_{j-1} + 1) \ge f(p_{j-1} + 1) = p_j$。若 $Q$ 有 $t + 1$ 段，则 $p_{t+1} \le c_{t+1} \le n - 1$ 应存在——但贪心自 $p_t + 1$ 起扫到末尾都未触发切段，即 $f(p_t + 1) > n - 1$，矛盾。故 $Q$ 的操作数 $\ge n - t = \text{cnt}$。∎

**引理 3（可行位集合对并封闭）**：称 mask **可行**，若存在 $\le k$ 次操作的方案使每个剩余元素与 mask 不相交。若 mask₁、mask₂ 都可行，则 $\text{mask}_1 \cup \text{mask}_2$ 也可行。

**证明**：两个可行方案分别对应划分 $P_1, P_2$，其**刀位集合**（相邻元素间被切开的缝隙）为 $C_1, C_2$，代价 $= |C_i| \le k$。取刀位为 $C_1 \cap C_2$ 的划分 $Q$：代价 $|C_1 \cap C_2| \le k$；$Q$ 的每段内部不含 $C_1$ 的刀，故它由 $P_1$ 的若干**完整段**拼接而成（对 $P_2$ 同理）。于是 $Q$ 的段 AND 既是其中每个 $P_1$ 段 AND 的子掩码（与 mask₁ 不交），也是每个 $P_2$ 段 AND 的子掩码（与 mask₂ 不交），从而与 $\text{mask}_1 \cup \text{mask}_2$ 不交。∎

**推论**：全体可行 mask 的并 $M^*$ 仍可行（有限族上反复用引理 3），是唯一的最大可行位集合；且可行集合族向下封闭（$M^*$ 的任何子集可行——同一方案即可）。

**定理**：最优 OR 值 $= \text{full} \mathbin{\&} \sim M^*$，且从高位到低位的逐位贪心求出的正是它。

**证明**：

1. 任一 $\le k$ 次操作的方案，其 OR 值 $v \subseteq \text{full}$，且每个剩余元素与 $\sim v$ 不交，故 $\sim v$ 可行，$\sim v \subseteq M^*$，即 $v \supseteq \text{full} \setminus M^*$；
2. $M^*$ 可行：其方案的 OR 值 $v \subseteq \text{full}$ 且与 $M^*$ 不交，即 $v \subseteq \text{full} \setminus M^*$。结合 1，该 $v$ 恰为 $\text{full} \setminus M^*$，是可达 OR 的最小值；
3. 贪心终态 $= M^*$：每次确认前都检查了可行性，而可行 $\Rightarrow \subseteq M^*$，故不变量「已确认集合 $\subseteq M^*$」始终成立。结束时若有 $b \in M^*$ 未被确认：检查位 $b$ 时的试探集合 = 当时已确认集合 $\cup \{b\} \subseteq M^*$，由向下封闭知其可行，贪心会确认 $b$，矛盾。∎

> 💡 值得玩味：证明只用了「可行集合族对并封闭 + 向下封闭」，**与位的枚举顺序无关**——任意固定顺序（哪怕从低位到高位）都能得到 $M^*$。「高位优先」只是符合「先消大位」的直觉；这也解释了为什么贪心无需回溯。

## 6. 复杂度分析

- **时间复杂度**：$O(30 \cdot n)$。外层枚举 30 个二进制位（$\text{nums}[i] < 2^{30}$），每位一趟 $O(n)$ 扫描（`cnt > k` 可提前 break）；$n = 10^5$ 时约 $3 \times 10^6$ 次位运算。
- **空间复杂度**：$O(1)$。只用 `full`、`cleared`、`mask`、`cur`、`cnt` 等常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minOrAfterOperations(vector<int>& nums, int k) {
        int full = 0;
        for (int x : nums) full |= x;

        int cleared = 0;                       // 已确认能清零的位集合
        for (int b = 29; b >= 0; --b) {
            if (!((full >> b) & 1)) continue;  // 该位不在 OR 里，天然已清零
            int mask = cleared | (1 << b);      // 在已确认位之上叠加试探位 b
            int cnt = 0, cur = -1;             // -1 补码全 1，& 后即 nums[i]
            for (int x : nums) {
                cur &= x;
                if ((cur & mask) == 0) cur = -1;    // 本段合法，立刻切段
                else if (++cnt > k) break;          // 必须吞并下一位：+1 次操作
            }
            if (cnt <= k) cleared = mask;      // 位 b 确认清零
        }
        return full & ~cleared;                // 必须与 full：~cleared 高位含 1
    }
};
```

### Python

```python
class Solution:
    def minOrAfterOperations(self, nums: List[int], k: int) -> int:
        full = 0
        for x in nums:
            full |= x

        cleared = 0                       # 已确认能清零的位集合
        for b in range(29, -1, -1):
            if not (full >> b) & 1:        # 该位不在 OR 里，天然已清零
                continue
            mask = cleared | (1 << b)     # 在已确认位之上叠加试探位 b
            cnt, cur = 0, -1              # -1 即全 1，& 后变 nums[i]
            for x in nums:
                cur &= x
                if cur & mask == 0:
                    cur = -1              # 本段合法，立刻切段
                else:
                    cnt += 1              # 必须吞并下一位：+1 次操作
                    if cnt > k:
                        break
            if cnt <= k:
                cleared = mask           # 位 b 确认清零
        return full & ~cleared
```

## 8. 边界情况与易错点

1. **返回值必须 `full & ~cleared`**：`~cleared` 的高位全为 1（C++ 里它是负数），单独返回会出错；与 `full` 按位与才把答案限制在出现过的位内。
2. **尾段处理**：扫描结束 `cur & mask != 0` 时，尾段并入上一段**自动合法**（AND 位只减不增），代价已被尾段最后一个元素的 `cnt` 覆盖——既不要误判为不可行，也不要单独写特判。
3. **「切段要趁早」不能改**：不能改成「能吞多长吞多长」或「尽量少切段」的其它贪心——只有最早切段才能最大化段数（引理 2 依赖 $f$ 的单调性）。
4. **试探集合必须叠加已确认高位**：检查位 $b$ 时用 `cleared | (1 << b)`，漏掉 `cleared` 会把「单独可清但合起来清不掉」的位错误清零。
5. **$k = 0$**：退化为「每个元素单独与 mask 不相交」的逐元素判定，算法自然覆盖，无需特判。
6. **$n = 1$**：此时必有 $k = 0$，无法合并，答案 = `nums[0]`；扫描中每个含 mask 位的元素都会让 `cnt` 超过 0，自动正确。
7. **位上限**：$\text{nums}[i] < 2^{30}$，从 bit 29 开始枚举即可；若值域更大只需改起点。
8. **`cnt = n` 的不可行情形**：一次段都切不出来时 `cnt = n > k` 恒假（$k \le n-1$），无需对「全体 AND 与 mask 相交」写专门分支。
9. **溢出**：全程值 $< 2^{30}$，C++ `int` 足够；Python 无需关心。

**延伸思考**：

- **改成「恰好 $k$ 次」答案会变吗？** 不会。把一个划分中的两段并成一段，总 OR 只减不增（新段 AND 是原两段 AND 的按位与）；所以至多 $k$ 次的最优解总可以通过继续合并「补齐」到恰好 $k$ 次。这也说明答案关于 $k$ 单调不增。
- **$k = n - 1$ 的极端情形**：全部并成一段即可，答案 = 全体 AND，逐位贪心在每一位都会成功。
- **若合并运算换成 OR、目标改成最小化 AND？** 镜像问题：每段缩成段内 OR，从高位到低位置 1 地试探「这一位能否在所有段 AND 中为 1」，可行性检查同样是切早贪心，值得动手推一遍。
