# LeetCode 按键变更的次数 题解

## 1. 题目概述

- **标题 / 题号**：按键变更的次数（#3019，easy）
- **链接**：https://leetcode.cn/problems/number-of-changing-keys/
- **来源**：LeetCode 第 382 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定字符串 `s`，模拟用户的按键输入过程。**按键变更**指本次按键与上一次按键使用了不同的键。`shift` / `caps lock` 等修饰键不计入按键变更，即 `'a'` 与 `'A'` 视为同一个键。返回整个输入过程中按键变更的次数。

**约束**：

- `1 <= s.length <= 100`
- `s` 仅由英文大写字母和小写字母组成

> 💡 **关键转化**：修饰键不计入 ⟹ 大小写视为同一个键 ⟹ 比较 `s[i]` 与 `s[i-1]` 时忽略大小写。

## 2. 示例

**示例 1**

```text
输入：s = "aAbBcC"
输出：2
解释：
s[0]='a' → s[1]='A'：同一个键（忽略大小写），不计变更。
s[1]='A' → s[2]='b'：不同键，变更 1 次。
s[2]='b' → s[3]='B'：同一个键，不计变更。
s[3]='B' → s[4]='c'：不同键，变更 2 次。
s[4]='c' → s[5]='C'：同一个键，不计变更。
```

**示例 2**

```text
输入：s = "AaAaAaaA"
输出：0
解释：全程只按了字母 'a'/'A' 对应的同一个键，不存在按键变更。
```

## 3. 解题思路

### 3.1 暴力思路

签到题，暴力即正解：从左到右扫描，对每个相邻位置 `(i-1, i)` 判断两个字符忽略大小写后是否不同，不同则计数 +1。

唯一需要想清楚的是**"忽略大小写"这一步怎么做**——这是本题唯一的陷阱。

### 3.2 核心观察：归一化后比较相邻字符

![忽略大小写比较相邻字符](images/key_changes_concept.svg)

**关键 insight**：`shift` / `caps lock` 不计入按键变更，等价于"键"只由字母本身决定，与大小写无关。因此：

1. 把每个字符**归一化**到小写（`tolower`）；
2. 比较 `lower(s[i])` 与 `lower(s[i-1])`，不同则答案 +1。

### 3.3 算法流程

![算法流程：线性扫描计数](images/key_changes_flow.svg)

```text
ans = 0
for i = 1 to n-1:
    if lower(s[i]) != lower(s[i-1]):
        ans += 1
return ans
```

### 3.4 示例演算

以 `s = "aAbBcC"` 为例，逐对比较：

| 相邻对 | 归一化后 | 是否变更 | 累计 |
|--------|----------|----------|------|
| (a, A) | (a, a) | 否 | 0 |
| (A, b) | (a, b) | **是** | 1 |
| (b, B) | (b, b) | 否 | 1 |
| (B, c) | (b, c) | **是** | 2 |
| (c, C) | (c, c) | 否 | 2 |

答案为 2 ✓

## 4. 算法细节

1. **归一化方式**：逐字符 `tolower` 比较；也可以先把整个串 `s.lower()` 再扫一遍，语义相同。C++ 中 `tolower` 参数需转为 `unsigned char` 防止负值（本题仅英文字母，无碍，但好习惯要养成）。
2. **计数条件**：从下标 `1` 开始扫（`i-1` 与 `i`），长度为 1 的串循环不执行，自然返回 0。
3. **一次遍历即可**：不需要额外的数据结构，也不需要预处理。

## 5. 正确性证明

**引理 1**：字符 `c1`、`c2` 对应同一个键，当且仅当 `lower(c1) == lower(c2)`。

**证明**：键盘上字母键与大小写无关，大小写差异只能由 `shift` / `caps lock` 产生，而题目规定修饰键不计入按键变更。英文字母中 `lower` 是"同键等价类"的代表元映射：`'a'` 与 `'A'` 映射相同，不同字母映射不同。∎

**定理**：算法返回值等于输入过程中按键变更的次数。

**证明**：按键变更发生在第 `i`（`i >= 1`）次按键且与第 `i-1` 次按键不同键时。由引理 1，"不同键"等价于 `lower(s[i]) != lower(s[i-1])`。算法对每个 `i ∈ [1, n-1]` 恰判断一次该条件并计数一次，与按键变更的定义一一对应。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，单次线性扫描，每个字符做一次 `tolower` 常数操作。
- **空间复杂度**：$O(1)$，只维护一个计数器（若先整体 `lower()` 则为 $O(n)$，逐字符比较更优）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countKeyChanges(string s) {
        int ans = 0;
        for (int i = 1; i < (int)s.size(); i++) {
            if (tolower((unsigned char)s[i]) != tolower((unsigned char)s[i - 1])) {
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countKeyChanges(self, s: str) -> int:
        return sum(a.lower() != b.lower() for a, b in zip(s, s[1:]))
```

## 8. 边界情况与易错点

1. **忘忽略大小写**：直接比较 `s[i] != s[i-1]`，示例 1 会错误地算成 5。这是本题唯一考点。
2. **长度为 1**：没有相邻对，答案为 0，循环天然不执行，无需特判。
3. **全部相同字符**：如 `"AaAaAaaA"`，答案为 0。
4. **C++ `tolower` 陷阱**：传入 `char` 可能为负（非 ASCII 扩展字符），规范写法是 `(unsigned char)` 强转；本题仅英文字母，无实际风险。
5. **不要去重统计**：比较的只是**相邻**两次按键，不是不同键的总数，"去重后数种类"是错误思路。
