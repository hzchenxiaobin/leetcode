# LeetCode 任务调度器 题解

## 1. 题目概述

- **标题 / 题号**：任务调度器（#621，medium）
- **链接**：https://leetcode.cn/problems/task-scheduler/
- **来源**：LeetCode 第 37 场周赛 Q4
- **难度**：中等
- **标签**：贪心、数组、哈希表、计数、排序、堆（优先队列）

**题意**：CPU 要执行 $T$ 个任务，任务用大写字母 `A`–`Z` 表示，同一字母代表同一种任务。每个单位时间最多执行一个任务；**同一种任务的两执行之间必须至少隔 $n$ 个时间单位**，间隔里可以放别的任务，也可以让 CPU 空转。求执行完所有任务的最短时间。

**约束**：

- $1 \le \lvert tasks \rvert \le 10^4$
- `tasks[i]` 仅含大写英文字母，即任务至多 26 种
- $0 \le n \le 100$

## 2. 示例

**示例 1**

```text
输入：tasks = ["A","A","A","B","B","B"], n = 2
输出：8
解释：A 之后要空两格，B 同理。
      A -> B -> idle -> A -> B -> idle -> A -> B，共 8 个时间单位。
```

**示例 2**

```text
输入：tasks = ["A","C","A","B","D","B"], n = 1
输出：6
解释：A -> B -> C -> D -> A -> B。冷却为 1 时，中间夹一个别的任务就够，
      任务种类够多，一次都不用空转。
```

**示例 3**

```text
输入：tasks = ["A","A","A","B","B","B"], n = 3
输出：10
解释：A -> B -> idle -> idle -> A -> B -> idle -> idle -> A -> B。
      只有两种任务，冷却又长，中间的 4 个时刻只能空转。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的状态搜索：状态为「每种任务还剩几次 + 每种任务还要冷却几拍」，从初始状态做 BFS 求最短步数。状态数随任务种类指数增长（最多 26 种），$10^4$ 的数据完全不可行，只能用来对拍小数据。

另一条路是**模拟**：每个时刻从「未完成且已冷却」的任务里挑剩余次数最多的执行，全都不可用就空转。正确性没问题（它恰好实现了 §5 引理 3 的构造，见 (b) 中「频次降序、最靠左可用列」的贪心），复杂度 $O(T \log 26)$，$10^4$ 也过得去。但本题有一个只看频次的**闭式解**，$O(T + 26)$，赛场上想清楚它能省下大量调试时间。

### 3.2 核心观察：最频繁的任务决定框架

![框架法：最频繁的任务决定骨架](images/wc37_q4_frame_bound.svg)

只看频次统计，与任务的原始顺序无关——因为冷却约束只关心「同类任务相隔多远」，任务可以随意重排。

设出现次数最多的任务出现 $f$ 次，且**有 $cnt$ 种任务都出现了 $f$ 次**（$cnt \ge 1$），任务总数 $T$。

把出现 $f$ 次的任务叫**主任务**。取其中任意一个，它的第 $j$ 次和第 $j+1$ 次执行之间必须塞进 $n$ 个时间单位，加上它自己那一格，两相邻执行至少占掉 $n+1$ 格。于是它像一把梳子，把时间轴切成 $f-1$ 个**间隔段**：

- 每段的宽度是 $n+1$；
- 每段里主任务自己占 1 格，剩下 $n$ 格必须由**别的任务**填，填不满就只能空转；
- 主任务的最后一次执行之后不需要再冷却，它只占 1 格。

最后一点很关键：$cnt$ 个主任务各有一次「收尾」，它们的收尾时刻互不相同（同一时刻只能做一个任务），所以时间轴末尾还要再加 $cnt$ 格。这就得到**框架下界**

$$L = (f-1)\,(n+1) + cnt$$

任何合法调度都不可能比 $L$ 更短（§5 引理 1）。

但答案未必是 $L$：任务数 $T$ 本身也是下界——每个任务至少要占一个时刻。当任务种类多、每种次数少时，框架里的空位被塞满还有溢出，实际长度由 $T$ 决定。所以

$$\text{ans} = \max\Bigl(T,\ (f-1)(n+1)+cnt\Bigr)$$

### 3.3 算法流程

![算法流程：四步得到闭式答案](images/wc37_q4_greedy_flow.svg)

1. 统计 26 个字母各自的出现次数 $c_i$；
2. 求最大频次 $f=\max c_i$，以及频次等于 $f$ 的类型个数 $cnt$；
3. 算框架下界 $L=(f-1)(n+1)+cnt$；
4. 返回 $\max(T, L)$。

整个过程不需要模拟时间轴，也不必真的排出调度方案。

### 3.4 示例演算

![示例演算：先算 L 再与 T 取 max](images/wc37_q4_walkthrough.svg)

| 输入 | $f$ | $cnt$ | $T$ | $L=(f-1)(n+1)+cnt$ | 答案 $\max(T,L)$ |
|------|-----|-------|-----|--------------------|------------------|
| `A A A B B B`, $n=2$ | 3 | 2 | 6 | $2\times3+2=8$ | 8 |
| `A C A B D B`, $n=1$ | 2 | 2 | 6 | $1\times2+2=4$ | 6 |
| `A A A B B B`, $n=3$ | 3 | 2 | 6 | $2\times4+2=10$ | 10 |
| `A A B B C`, $n=1$ | 2 | 2 | 5 | $1\times2+2=4$ | 5 |

两种情形正好各占两行：

- **$T < L$（第 1、3 行）**：任务太少，框架里必然剩空位。例如第 3 行要排 `A B idle idle | A B idle idle | A B`，$A$ 每次间隔 4 格，中间的 2 格谁都填不上。
- **$T > L$（第 2、4 行）**：任务种类够多，框架被填满还溢出，长度被 $T$ 顶住。第 4 行排 `A B C A B`，一次空转都没有。

注意第 1 行恰好 $T=6<L=8$，而把 $n$ 改小到 1 后 $L$ 降到 $2\times2+2=6=T$，空位消失、长度正好 6——公式对 $n$ 是连续变化的。

## 4. 算法细节

1. **顺序无关，只统计频次**：冷却约束只看同类任务的距离，重排任务不影响可行性与最优长度，所以第一步一定是频次数组 `cnt[26]`。
2. **$f$ 与 $cnt$ 一趟求出**：遍历频次时 `if (v > f) { f = v; cnt = 1; } else if (v == f && v > 0) cnt++;`；注意 `cnt` 只统计「等于最大值」的类型，不是统计所有类型。
3. **公式三项的含义**：$f-1$ 是主任务之间的间隔段数；$n+1$ 是每段宽度（主任务 1 格 + 冷却 $n$ 格）；$cnt$ 是尾段长度（每个主任务收尾一格）。
4. **为什么要和 $T$ 取 max**：$L$ 只描述「主任务骨架」撑出的最小跨度，$T$ 描述「任务必须全部塞进去」的最小跨度，两个下界互相独立，答案取二者的较大者；$T>L$ 时骨架被填满后还能往后接，$T<L$ 时多出来的空位消不掉。
5. **$n=0$ 的退化**：此时 $L=f-1+cnt\le T$ 恒成立，答案就是 $T$，符合「没有冷却、顺序随便排」的直觉；实现里不必特判。
6. **枚举字母表而不是排序**：只需在 26 个字母上求最大值与计数，$O(26)$；用哈希表 + 排序是 $O(k\log k)$，同样正确但没必要。
7. **整数范围**：$T\le 10^4$、$f\le 10^4$、$n+1\le 101$，$L$ 的上界约 $10^6$，`int` 足够，不会溢出。
8. **C++ 类型细节**：`tasks.size()` 是 `size_t`（无符号），与 `int` 一起进 `std::max` 会被推导成无符号，务必写成 `max((int)tasks.size(), ...)`。

## 5. 正确性证明

设 $T=\lvert tasks\rvert$，$f$ 为最大频次，$cnt$ 为频次等于 $f$ 的任务种数，$L=(f-1)(n+1)+cnt$。

**引理 1（框架下界）**：任何合法调度的总长度 $\ge L$。

**证明**：任取一个主任务 $X$（出现 $f$ 次），设它的执行时刻为 $t_1<t_2<\dots<t_f$。相邻两次之间至少隔 $n$ 个时间单位，故 $t_{j+1}-t_j\ge n+1$，累加得 $t_f\ge (f-1)(n+1)+1$。

这样的主任务共有 $cnt$ 个，它们的**最后一次执行时刻互不相同**（一个时刻只能执行一个任务），且都在 $[(f-1)(n+1)+1,\ M]$ 内，其中 $M$ 是调度总长度。区间内共有 $M-(f-1)(n+1)$ 个整数时刻，故 $M-(f-1)(n+1)\ge cnt$，即 $M\ge L$。∎

**引理 2（任务数下界）**：任何合法调度的总长度 $\ge T$。

**证明**：每个任务至少占用一个时刻，且每个时刻至多执行一个任务，故 $M\ge T$。∎

**引理 3（上界可达）**：存在长度恰为 $M=\max(T,L)$ 的合法调度。

**证明**：记段宽 $d=n+1$，主任务为 $X_1,\dots,X_{cnt}$。

*(a) $T\le L$*：搭 $f-1$ 个宽度为 $d$ 的段，再加一个宽度为 $cnt$ 的尾段，共 $L$ 个槽位。把 $X_j$ 放在每个段的第 $j$ 列（尾段同理），则 $X_j$ 相邻两次执行恰好相隔 $d$，冷却满足。扣除主任务占用的 $cnt$ 列后，前 $f-1$ 段各剩 $d-cnt$ 个空格，空位总数
$$(f-1)(d-cnt)\ \ge\ T-f\cdot cnt,$$
最后一个不等号由 $T\le L=(f-1)d+cnt$ 直接变形得到。其余任务的总出现次数为 $T-f\cdot cnt$，把它们按「一次执行占一个段、同一任务占**不同的**段、同一段内占不同的列」填进空位：把任务与段看成二分图的两侧，任务 $i$ 需要 $c_i\le f-1$ 个段、每段可容 $d-cnt$ 个任务，由于每个 $c_i\le f-1$（段数）且总需求不超过总容量，Hall 条件成立，逐段贪心填充不会卡住。让同一任务在所有段里用**同一列**，则它相邻两次执行相隔段宽的整数倍 $\ge d$，冷却依然满足。填不满的空位留作空闲，总长恰为 $L=M$。

*(b) $T>L$*：此时一格空闲都不允许，长度只能是 $T$。取 $B=\lceil T/d\rceil$，把时间轴切成 $B$ 段（前 $B-1$ 段各 $d$ 格，末段 $T-(B-1)d$ 格）。由 $T\ge (f-1)d+cnt+1$ 得 $B\ge f$，于是每种任务的次数 $c_i\le B$，可以把它安排进 $c_i$ 个**互不相同**的段（同类型不会在同一段里出现两次）。再让每个类型在相邻两段中的**列号不降**：若它在相邻两段都出现，间隔 $=(d-p)+q\ge d$（$q\ge p$）；若跨段出现，间隔更大。冷却于是得到满足。列号按「频次降序，逐个类型放进当前最靠左的可用列」贪心确定：类型 $i$ 的需求是 $c_i\le B$ 个段、段的容量是 $d$ 格，总需求 $\sum_i c_i=T\le B\cdot d$ 不超过总容量，各类型需求与段容量满足 Hall 条件，逐类型放置不会卡住（万一某列被同段的别的类型占了，往右挪一列即可，右移只会让间隔变大）。填满 $T$ 格后即得长度恰为 $T=M$ 的合法调度。∎

（构造只用于证明存在性；编程时直接算公式即可。若确实需要输出调度方案，用 §3.1 的堆模拟。）

**定理**：最少时间 $= \max\bigl(T,\ (f-1)(n+1)+cnt\bigr)$。

**证明**：由引理 1、2，任何调度的长度都 $\ge \max(T,L)$；由引理 3，存在长度恰为 $\max(T,L)$ 的调度。故最优值等于 $\max(T,L)$。∎

## 6. 复杂度分析

- **时间**：$O(T + 26)=O(T)$。统计频次需遍历 $T$ 个任务，之后在 26 个字母上求最大值与计数是常数时间。
- **空间**：$O(1)$（准确说是 $O(26)$）。只需要一个长度 26 的计数数组，与 $T$ 无关。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int leastInterval(vector<char>& tasks, int n) {
        int freq[26] = {0};
        for (char t : tasks) freq[t - 'A']++;

        int f = 0;                        // 最大频次
        for (int i = 0; i < 26; i++) f = max(f, freq[i]);

        int cnt = 0;                      // 频次等于最大值的类型数
        for (int i = 0; i < 26; i++)
            if (freq[i] == f) cnt++;

        int frame = (f - 1) * (n + 1) + cnt;   // 框架下界 L
        return max((int)tasks.size(), frame);  // 注意 size() 是 size_t
    }
};
```

### Python

```python
from typing import List
from collections import Counter


class Solution:
    def leastInterval(self, tasks: List[str], n: int) -> int:
        freq = Counter(tasks)                 # 每种任务出现几次
        f = max(freq.values())                # 最大频次
        cnt = sum(1 for v in freq.values() if v == f)   # 并列最多的任务种数
        frame = (f - 1) * (n + 1) + cnt       # 框架下界 L
        return max(len(tasks), frame)
```

## 8. 边界情况与易错点

1. **只有一种任务**：`["A","A","A"], n=2` → $L=2\times3+1=7$，序列 `A idle idle A idle idle A`；别把最后一段的收尾也加上冷却。
2. **$n=0$**：答案就是 $T$，公式自动覆盖（$L=f-1+cnt\le T$）；实现里不必特判 $n=0$，也不要把段宽写成 $n$ 而不是 $n+1$。
3. **$cnt$ 的统计口径**：只数「频次 $=f$」的类型。`["A","A","B"], n=1` 中 $f=2$、$cnt=1$，$L=(2-1)\times2+1=3$；若把频次 $1$ 的 `B` 也算进 $cnt$，会错答成 4。
4. **少算一段**：框架是 $(f-1)(n+1)$ 而不是 $f(n+1)$——最后一次执行后面没有需要填的冷却段；`["A","A","A"], n=100` 的正确答案是 $2\times101+1=203$，写成 $f(n+1)+cnt$ 会多出一整个冷却段。
5. **$T$ 更大时的方向**：$T>L$ 说明任务种类多、每种次数少，此时**一次空转都不需要**，长度被 $T$ 顶住。若代码只返回 $L$，`["A","A","B","B","C"], n=1` 会错答成 4 而不是 5。
6. **C++ 无符号比较**：`max(tasks.size(), frame)` 中 `frame` 为 `int`、`tasks.size()` 为 `size_t`，混用会导致编译失败或隐式转换告警，先 `(int)` 强转。
7. **不要真的去重排字符串**：本题只要长度；构造具体序列既慢又容易在「同类型恰好 $n$ 格之外」这种边界写错下标。
