# LeetCode 网格图中递增路径的数目 题解

## 1. 题目概述

- **标题 / 题号**：网格图中递增路径的数目（#2328，hard）
- **链接**：https://leetcode.cn/problems/number-of-increasing-paths-in-a-grid/
- **来源**：LeetCode 第 300 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、记忆化搜索、动态规划、图、拓扑排序

**题意**：给定 $m \times n$ 的整数网格 `grid`，每步可从一个格子移动到 **4 方向相邻**的格子。统计所有**值严格递增**的路径数目——路径可从**任意**格子出发、止于**任意**格子（长度至少为 $1$，即单格自身也算一条路径）。两条路径只要访问过的格子不完全相同即视为不同。答案对 $10^9 + 7$ 取余后返回。

**约束**：

- $m = \text{grid.length}$，$n = \text{grid}[i].\text{length}$
- $1 \le m, n \le 1000$
- $1 \le m \times n \le 10^5$
- $1 \le \text{grid}[i][j] \le 10^5$

> 💡 **赛场定位**：这是 [329. 矩阵中的最长递增路径](https://leetcode.cn/problems/longest-increasing-path-in-a-matrix/) 的**计数孪生题**——329 在同样的"小 → 大"移动关系上求最长长度（聚合算子 $\max$），本题求路径总数（聚合算子 $\sum$）。做过 329 的选手应该能条件反射地想到 **记忆化搜索**。本场 Q1 模拟、Q2 矩阵遍历、Q3 线性 DP，Q4 收在网格 DAG 计数上，整体难度友好，是典型的"套路困难题"。

## 2. 示例

**示例 1**

```text
输入：grid = [[1,1],[3,4]]
输出：8
解释：严格递增路径：
- 长度 1：[1], [1], [3], [4]                  → 4 条
- 长度 2：[1→3], [1→4], [3→4]                → 3 条
- 长度 3：[1→3→4]                            → 1 条
合计 4 + 3 + 1 = 8 条
```

**示例 2**

```text
输入：grid = [[1],[2]]
输出：3
解释：长度 1：[1], [2]；长度 2：[1→2]。合计 2 + 1 = 3 条
```

**示例 3**（自造，覆盖"同值格子互不连边"的情形）

```text
输入：grid = [[2,2,2]]
输出：3
解释：三个 2 互不相同却彼此值相等——严格递增要求值变大，
相等不构成边，故只有 3 条单格路径，没有任何长度 ≥ 2 的路径。
```

## 3. 解题思路

### 3.1 暴力思路：从每格裸 DFS

最朴素的做法：从每个格子出发做一次不带记忆化的 DFS，只要邻居值严格更大就走下去，每深入一层就多出一条新路径，走不动为止；最后把所有起点的结果相加。

问题在于**子问题被重复展开**：同一条递增链上的中间格子，会被所有能到达它的上层路径反复探索。构造一条蛇形递增链（$1, 2, 3, \dots, m n$ 蛇形排布）时，从链首出发的裸 DFS 分支近似按 $4^{mn}$ 爆炸，$m \times n = 10^5$ 下毫无希望。

> 💡 **转折点**：「以 $(i,j)$ 为起点的递增路径数」**只取决于这格本身和它四周的值**，与"从哪里走到这格"完全无关——这就是**无后效性**。既然子问题答案与调用历史无关，就能**缓存一次、处处复用**：记忆化搜索。

### 3.2 核心观察：严格递增 ⇒ 网格是 DAG，路径计数 = DP-on-DAG

![核心观察：网格按小到大定向后是有向无环图](images/wc300_q4_dag_concept.svg)

把每个格子看作节点，只在"**值严格更小的相邻格 → 值严格更大的相邻格**"之间连有向边。三个直接推论：

1. **无环**：沿边每走一步值严格变大，不可能回到任何访问过的格子（回到原格意味着值先变大再复原，矛盾）。**相等值之间不连边**，同值格子互不打转。
2. **天然分层**：按值排序就是一个合法拓扑序（同值格之间无边，先后无所谓），所以"按值升序做 DP"与"拓扑排序 DP"是同一件事——这正是官方标签里 Topological Sort 的由来。
3. **单格路径是基底**：每个节点自身就是一条长度为 $1$ 的路径，任何长路径都是"先迈出一步，再接上后继的路径"。

于是定义状态（**以 $(i,j)$ 为起点**）：

$$\text{dp}(i,j) = \text{以 } (i,j) \text{ 为起点的严格递增路径数}$$

$$\text{dp}(i,j) = 1 + \sum_{\substack{(ni,nj) \text{ 为四邻居} \\ \text{grid}[ni][nj] > \text{grid}[i][j]}} \text{dp}(ni,nj)$$

- $1$ 是"只含 $(i,j)$ 自身"的单格路径，每格必有；
- 求和项把"先走到某个更大邻居，再从那里延伸"的所有路径接上 $(i,j)$ 作前缀——第二格不同则路径必然不同，**不重不漏**。

答案为所有格子的 dp 之和：

$$\text{ans} = \sum_{i,j} \text{dp}(i,j) \bmod (10^9+7)$$

### 3.3 算法流程：记忆化 DFS

![算法流程：记忆化 DFS 的决策流程](images/wc300_q4_memo_flow.svg)

1. `memo[i][j]` 初始化为 `-1` 表示未计算；
2. `dfs(i, j)`：命中记忆直接返回；否则 `res = 1`，枚举四方向邻居，**界内且值严格更大**才递归累加；最后写回 `memo[i][j]` 并返回；
3. 主流程对所有格子调用 `dfs` 求和，全程 `% (10^9+7)`。

递归只会走向值更大的格子，递归链长度不超过不同值的个数，**天然有底**；`dfs` 首次返回后 memo 生效，每格真正计算恰好一次。

### 3.4 示例演算

![示例演算：grid=[[1,1],[3,4]] 的 dp 逐步填充](images/wc300_q4_example_walkthrough.svg)

以示例 1 为例，按值从大到小逐格计算：

| 步骤 | 格子 (值) | 严格更大的邻居 | 计算 | dp |
|------|-----------|---------------|------|----|
| ① | (1,1) 值 4 | 无 | $1$ | $1$ |
| ② | (1,0) 值 3 | (1,1)=4 | $1 + \text{dp}(1,1) = 2$ | $2$ |
| ③ | (0,1) 值 1 | (1,1)=4 | $1 + \text{dp}(1,1) = 2$ | $2$ |
| ④ | (0,0) 值 1 | (1,0)=3 | $1 + \text{dp}(1,0) = 3$ | $3$ |

两个细节值得盯着看：

- $(0,0)$ 与 $(0,1)$ 值同为 $1$，**不严格更大，不计入彼此的求和**——这就是"相等不构成边"，写错成 `>=` 会立刻在此翻车；
- $(0,0)$ 的对角格 $(1,1)=4$ 虽然值更大，但**不相邻**，也不能走。

答案 $= 1 + 2 + 2 + 3 = 8$ ✓。按长度分解（$4+3+1=8$）与按起点求和（$1+2+2+3=8$）口径不同、总数相同——前者数路径，后者把每条路径记在它的**起点**头上。

## 4. 算法细节

1. **哨兵值必须用 $-1$，不能用 $0$**：直觉上"路径数至少为 $1$"，似乎 $0$ 可当"未算"标记；但转移是取模加法，$1 + \sum(\text{已取模的 dp})$ 在模 $10^9+7$ 下**可能恰好 $\equiv 0$**（例如 $1 + (10^9+6) \equiv 0$）。用 $0$ 当哨兵会把这类格子永久当成"未算"重复展开。Python 的 `lru_cache` 天然规避此问题。
2. **递归方向**：`dfs(i,j)` 只朝**值严格更大**的邻居递归，进入前先比较 `grid[ni][nj] > grid[i][j]`；相等与更小一律跳过，不要在递归内部再判断。
3. **求和口径**：主函数对**所有**格子调用 `dfs` 求和——每条路径恰好被它的起点统计一次，不需要按终点再统计一遍。
4. **取模节奏**：C++ 中每一步累加后立即 `% MOD`，用 `long long` 承载；全是加法，不存在负数问题。Python 大整数不溢出，递归内取模或最后取模皆可（中途取模更省）。
5. **无递归的等价写法（拓扑 DP）**：把全部格子按值**升序**排序后依次处理，状态改为"以 $(i,j)$ 为**终点**"的路径数 $\text{dp}[i][j] = 1 + \sum_{\text{更小的邻居}} \text{dp}[ni][nj]$——处理到 $(i,j)$ 时更小邻居必已就绪。同值格之间无边，`sort` 的任意先后都合法，**普通排序 = 拓扑排序**。复杂度多一个 $O(mn \log mn)$ 的排序，换来零递归栈风险；若按值域 $10^5$ 做桶排，可回到 $O(mn + V)$。
6. **`std::function` 的性能提示**：C++ 递归版用 `std::function` 逐层调用有可测开销，$mn = 10^5$ 量级通常无碍；追求极限可改成传引用的静态函数或手写显式栈（即按值排序的迭代版）。

## 5. 正确性证明

**引理 1**（DAG 性）：按"值严格更小的相邻格指向值严格更大的相邻格"对网格建图 $G$，则 $G$ 是有向无环图。

**证明**：反设存在有向环 $v_1 \to v_2 \to \cdots \to v_k \to v_1$。每条有向边 $(u \to v)$ 都满足 $\text{grid}[v] > \text{grid}[u]$，于是沿环一周得 $\text{grid}[v_1] > \text{grid}[v_1]$，矛盾。∎

**引理 2**（路径分解）：以 $(i,j)$ 为起点的严格递增路径集合 $P(i,j)$ 可分解为两个不交部分：

$$P(i,j) = \{\langle (i,j) \rangle\} \;\sqcup\; \bigsqcup_{\substack{(ni,nj) \text{ 相邻} \\ \text{grid}[ni][nj] > \text{grid}[i][j]}} \{\langle (i,j), (ni,nj) \rangle \ concat \ p : p \in P(ni,nj)\}$$

即"单格路径"与"首步走到某个更大邻居 $(ni,nj)$、后缀为 $P(ni,nj)$ 中任意路径"的全体，且各部分两两不交、并起来不漏。

**证明**：按路径长度分情况。长度为 $1$ 的路径恰是 $\langle (i,j) \rangle$，属于第一部分。长度 $\ge 2$ 的路径 $p = \langle (i,j), (ni,nj), \dots \rangle$，其第二格 $(ni,nj)$ 与 $(i,j)$ 相邻且由递增性 $\text{grid}[ni][nj] > \text{grid}[i][j]$；去掉首格后的后缀是**以 $(ni,nj)$ 为起点的严格递增路径**，即属于 $P(ni,nj)$。反之，任取满足条件的 $(ni,nj)$ 与 $p' \in P(ni,nj)$，前接 $(i,j)$ 后值仍严格递增，是一条合法路径。第二格不同的路径显然不同（后缀族之间不交）；首步相同则由后缀唯一决定。两个部分按长度 $1$ 与 $\ge 2$ 区分，不交。∎

**定理**：设 $\text{dp}(i,j)$ 按递归式 $\text{dp}(i,j) = 1 + \sum_{\text{更大邻居}} \text{dp}(ni,nj)$ 定义（由引理 1，递归在严格递减的值链上展开，必然终止），则 $\text{dp}(i,j) = |P(i,j)|$，且 $\text{ans} = \sum_{i,j} \text{dp}(i,j) \bmod (10^9+7)$ 为所求答案。

**证明**：对 $(i,j)$ 的值沿"严格大于"的良序做强归纳：值最大的格子无更大邻居，$\text{dp} = 1 = |P|$（只有单格路径）。设所有值更大的格子处结论成立，则由引理 2 的不交分解与归纳假设，

$$|P(i,j)| = 1 + \sum_{\text{更大邻居}} |P(ni,nj)| = 1 + \sum_{\text{更大邻居}} \text{dp}(ni,nj) = \text{dp}(i,j)$$

（引理 2 中各部分基数可加正是"不交"的用途）。最后，每条合法路径有唯一的起点格子，故全体路径数 $= \sum_{i,j} |P(i,j)| = \sum_{i,j} \text{dp}(i,j)$；取模不改变计数的正确性。∎

**复杂度正确性**：记忆化保证每格的 `dfs` 体只执行一次（首次返回即写 memo，此后 $O(1)$ 命中），每次执行只扫 $4$ 个邻居，故总时间为 $O(4mn) = O(mn)$。

## 6. 复杂度分析

- **时间复杂度**：$O(m \times n)$。每格恰好计算一次，每次计算看 $4$ 个邻居；主流程的求和同样是 $O(mn)$。$m \times n \le 10^5$，远在时限内。
- **空间复杂度**：$O(m \times n)$。`memo` 表占 $O(mn)$；递归栈最坏 $O(mn)$（蛇形递增链把所有格子串成一条链，深度达 $10^5$，Python 必须 `setrecursionlimit`，见 §8）。迭代版无栈开销，但多一个 $O(mn)$ 的格子列表用于排序。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countPaths(vector<vector<int>>& grid) {
        const int MOD = 1e9 + 7;
        int m = grid.size(), n = grid[0].size();
        vector<vector<int>> memo(m, vector<int>(n, -1));        // -1 = 未算（不能用 0！）
        int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};

        function<int(int, int)> dfs = [&](int i, int j) -> int {
            if (memo[i][j] != -1) return memo[i][j];            // 记忆化命中
            int res = 1;                                        // 自身单格路径
            for (int k = 0; k < 4; ++k) {
                int ni = i + dr[k], nj = j + dc[k];
                if (ni >= 0 && ni < m && nj >= 0 && nj < n &&
                    grid[ni][nj] > grid[i][j])                  // 严格更大才递归
                    res = (res + dfs(ni, nj)) % MOD;
            }
            return memo[i][j] = res;
        };

        int ans = 0;
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                ans = (ans + dfs(i, j)) % MOD;                  // 按起点求和
        return ans;
    }
};
```

### Python

```python
import sys
from functools import lru_cache

class Solution:
    def countPaths(self, grid: List[List[int]]) -> int:
        MOD = 10 ** 9 + 7
        m, n = len(grid), len(grid[0])
        # 蛇形递增链下递归深度可达 m*n，必须抬高上限
        sys.setrecursionlimit(max(sys.getrecursionlimit(), m * n + 10))
        DIRS = ((-1, 0), (1, 0), (0, -1), (0, 1))

        @lru_cache(None)
        def dfs(i: int, j: int) -> int:
            res = 1                                  # 自身单格路径
            for dr, dc in DIRS:
                ni, nj = i + dr, j + dc
                if 0 <= ni < m and 0 <= nj < n and grid[ni][nj] > grid[i][j]:
                    res += dfs(ni, nj)
            return res % MOD

        return sum(dfs(i, j) for i in range(m) for j in range(n)) % MOD
```

### 迭代版（按值排序的拓扑 DP，无递归栈）

```python
class Solution:
    def countPaths(self, grid: List[List[int]]) -> int:
        MOD = 10 ** 9 + 7
        m, n = len(grid), len(grid[0])
        cells = [(i, j) for i in range(m) for j in range(n)]
        cells.sort(key=lambda p: grid[p[0]][p[1]])   # 值升序 = 拓扑序
        dp = [[1] * n for _ in range(m)]             # 每格自身算 1 条
        ans = 0
        for i, j in cells:
            for di, dj in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < m and 0 <= nj < n and grid[ni][nj] < grid[i][j]:
                    dp[i][j] += dp[ni][nj]           # 更小的邻居必已就绪
            dp[i][j] %= MOD
            ans = (ans + dp[i][j]) % MOD
        return ans
```

## 8. 边界情况与易错点

1. **`>` 误写成 `>=`**：相等值不是边。示例 1 中两个 $1$ 相邻、示例 3 中三个 $2$ 相邻，用 `>=` 会把等值格连边、引入"环"并重复计数，答案立刻错误。
2. **漏掉基底 $1$**：`res` 初值必须是 $1$（单格路径），漏写会丢掉全部 $m \times n$ 条长度为 $1$ 的路径——示例 1 会算出 $4$ 而非 $8$。
3. **哨兵不能用 $0$**：取模后的 dp 可能恰好为 $0$（$1 + (10^9+6) \equiv 0 \pmod{10^9+7}$），C++ 手写 memo 必须用 `-1` 或独立 visited 标记；这是本题最隐蔽的坑。
4. **Python 递归深度**：蛇形链深度 $10^5 \gg$ 默认上限 $1000$，不 `setrecursionlimit` 直接 `RecursionError`；若评测环境限制栈，改用迭代版。
5. **对角不算相邻**：只有 4 方向，$(0,0)$ 与 $(1,1)$ 值再大也不能直接跳；枚举方向数组就 4 组，别多写。
6. **C++ 溢出**：`int` 累加会溢出，用 `long long` 或每步 `% MOD`（参考代码为每步取模的 `int` 版）。
7. **单行 / 单列网格**：$m=1$ 或 $n=1$ 时邻居只剩 $2$ 个，方向数组自然处理，无需特判。
8. **答案别忘了取模**：路径数是组合级大数，题目要求对 $10^9+7$ 取余；主流程累加处取模即可。
