# LeetCode 解密消息 题解

## 1. 题目概述

- **标题 / 题号**：解密消息（#2325，easy）
- **链接**：https://leetcode.cn/problems/decode-the-message/
- **来源**：LeetCode 第 300 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、模拟

**题意**：给定密钥字符串 `key` 和密文 `message`，二者只含小写字母和空格。取 `key` 中 **26 个小写字母各自首次出现的顺序**作为替换表的字母顺序，与普通字母表 `a`–`z` 逐位对齐形成对照表；把 `message` 中每个字母按对照表替换，空格保持不变，返回解密后的消息。

**约束**：

- $26 \le \text{key.length} \le 2000$，`key` 由小写字母及空格组成，且包含 `'a'` 到 `'z'` 每个字母**至少一次**
- $1 \le \text{message.length} \le 2000$，`message` 由小写字母和空格组成

> 💡 Q1 签到题，赛场上的目标是把「题面描述」尽快翻译成「一张 26 项的字符对照表」：扫一遍 `key` 建表，再扫一遍 `message` 查表。两个细节别踩坑——**空格不进表**、**每个字母只在首次出现时登记**。

## 2. 示例

**示例 1**

```text
输入：key = "the quick brown fox jumps over the lazy dog", message = "vkbs bs t suepuv"
输出："this is a secret"
解释：key 去重后的字母顺序为 t,h,e,q,u,i,c,k,b,r,o,w,n,f,x,j,m,p,s,v,l,a,z,y,d,g，
      与 a,b,c,…,z 逐位对齐。v 对应 'a'+19='t'，k 对应 'a'+7='h'，…… 全文解出 "this is a secret"。
```

**示例 2**

输出："the five boxing wizards jump quickly"
解释：key 本身就是 26 个互异字母，去重序列就是它自身，直接按位对齐解码。
```

解释：去重序列恰为字母表本身，每个字母映射到它自己，解密后原样输出。
```

## 3. 解题思路

### 3.1 暴力思路

对 `message` 的每个字母，从头扫描 `key` 找它的首次出现位置，并统计该位置之前出现过的**不同字母数**作为下标 $i$，输出 `'a'+i`。单次查询 $O(|\text{key}|)$，整体 $O(|\text{message}|\cdot|\text{key}|)$，最坏约 $2000\times 2000=4\times 10^6$，本土能过但纯属重复劳动——同一个字母的映射在整条消息里被反复计算，且「统计前缀不同字母数」的实现远比看起来容易写错。签到题也不该交暴力：建一次表、查 $O(1)$ 才是从题面到代码的最短路径。

### 3.2 核心观察：去重序列与字母表逐位对齐

![核心观察：key 去重后的第 i 个字母对应字母表第 i 个字母](images/wc300_q1_mapping_concept.svg)

`key` 去掉空格、每个字母只保留首次出现后，得到一条长度**恰为 26** 的去重序列 $D$（题目保证 `key` 含全部 26 个字母，所以表必然填满）。把 $D$ 与字母表逐位对齐：

$$D[i] \;\leftrightarrow\; \texttt{'a'} + i \qquad (i = 0, 1, \dots, 25)$$

于是解密就是**建表 + 查表**：扫描 `key` 时维护计数器 $\textit{idx}$，遇到「未登记过的字母」$c$ 就令 $\textit{map}[c] = \texttt{'a'}+\textit{idx}$ 并 $\textit{idx}\mathrel{+}=1$；扫描 `message` 时每个字母 $O(1)$ 查表，空格原样输出。

### 3.3 算法流程

![算法流程：先建表再解码](images/wc300_q1_algorithm_flow.svg)

两阶段串联，各自只扫一遍字符串：

1. **建表**：遍历 `key`，遇空格或已登记字母则跳过；否则登记 $\textit{map}[c]=\texttt{'a'}+\textit{idx}$，$\textit{idx}$ 自增；
2. **解码**：遍历 `message`，空格输出空格，字母输出 $\textit{map}[c]$，依次拼接即为答案。

### 3.4 示例演算

![示例演算：逐字查表解码](images/wc300_q1_example_walkthrough.svg)

以示例 1 为例，去重序列 $D=\text{t,h,e,q,u,i,c,k,b,r,o,w,n,f,x,j,m,p,s,v,l,a,z,y,d,g}$，按位置编号 $0\dots25$。对 `message = "vkbs bs t suepuv"` 逐字解码：

| message 字母 | 在 D 中下标 | 输出 |
|-------------|------------|------|
| `v` | $19$ | `t` |
| `k` | $7$ | `h` |
| `b` | $8$ | `i` |
| `s` | $18$ | `s` |
| `␣` | — | `␣` |
| `b` `s` | $8$ $18$ | `i` `s` |
| `␣` | — | `␣` |
| `t` | $0$ | `a` |
| `␣` | — | `␣` |
| `s` `u` `e` `p` `u` `v` | $18,4,2,17,4,19$ | `s` `e` `c` `r` `e` `t` |

拼接得 `"this is a secret"`。注意 `t` 的下标是 $0$，输出 `'a'+0='a'`——**下标即字母表偏移**，无需任何额外运算。

## 4. 算法细节

1. **建表方向**：$\textit{map}[\text{key 字母}] = \text{字母表字母}$，即「key 中的字母 → 它对应的明文字母」。这是解密方向；建反了会得到编码结果。
2. **「首次出现」的判定**：用哈希表的「已存在」检查（或 `seen[26]` 布尔数组）实现；已登记的字母再次出现时**必须跳过**，否则会覆盖旧映射或让 `idx` 多走一步，破坏逐位对齐。
3. **空格的处理**：`key` 中的空格不是字母、不占下标；`message` 中的空格原样输出。两个阶段各处理一次，逻辑对称。
4. **表必满、查询必中**：约束保证 `key` 含全部 26 个字母，故建表结束时恰好登记 26 项、$\textit{idx}$ 恰为 $26$，解码阶段查表无需兜底。
5. **数据结构选择**：`unordered_map<char,char>` 与 `char mp[26] + bool seen[26]` 均可；数组版无哈希常数、空间严格 $O(1)$，赛场写哪个都行，选最顺手、最不易错的。

## 5. 正确性证明

**引理 1**（去重序列的结构）：`key` 去除空格、每个字母只保留首次出现后得到序列 $D$，则 $D$ 长度恰为 26 且字母互异。

**证明**：约束保证 26 个字母各至少出现一次，故每个字母都有首次出现位置，$D$ 含全部 26 个字母；「只保留首次出现」使每个字母至多出现一次，故 $|D|=26$ 且互异。∎

**引理 2**（登记下标 = 首次出现顺序）：一次扫描 `key`、跳过空格与已登记字母、给未登记字母依次赋予递增下标 $0,1,2,\dots$，则字母 $c$ 获得的下标等于 $c$ 在 $D$ 中的位置。

**证明**：对扫描位置归纳。任意时刻，已登记集合恰为「当前前缀中出现过的互异字母」，且登记顺序即各字母首次出现的先后。当 $c$ 首次出现被登记时，此前已登记的字母恰是所有按首次出现顺序排在 $c$ 之前的字母，个数为 $i$ 当且仅当 $c$ 是 $D$ 的第 $i$ 个（下标 $i$）字母。∎

**定理**：按 $\textit{map}[D[i]] = \texttt{'a'}+i$ 建表后，对 `message` 中每个字母 $c$ 输出 $\textit{map}[c]$、空格输出空格，结果即题意所求的解密消息。

**证明**：题意规定 `key` 中第 $i$ 个首次出现的字母对应字母表的第 $i$ 个字母，即密文字母 $D[i]$ 应解为 $\texttt{'a'}+i$；由引理 2，建表恰好给出 $\textit{map}[D[i]]=\texttt{'a'}+i$，故查表输出与题意一致。由引理 1，表覆盖全部 26 个字母，`message` 中的字母（约束保证只含小写字母）查询必中；空格按题意原样保留。∎

## 6. 复杂度分析

- **时间复杂度**：$O(|\text{key}| + |\text{message}|)$。建表扫一遍 `key`，每字符 $O(1)$ 判断与登记；解码扫一遍 `message`，每字符 $O(1)$ 查表。
- **空间复杂度**：$O(|\Sigma|) = O(1)$。映射表至多 26 项，被字母表大小封顶，与两个字符串的长度无关；返回的字符串是题目要求的结果，不计入辅助空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string decodeMessage(string key, string message) {
        char cur = 'a';
        unordered_map<char, char> mp;
        for (char c : key)
            if (c != ' ' && !mp.count(c))
                mp[c] = cur++;
        string res;
        for (char c : message)
            res.push_back(c == ' ' ? ' ' : mp[c]);
        return res;
    }
};
```

### Python

```python
class Solution:
    def decodeMessage(self, key: str, message: str) -> str:
        mp = {}
        idx = 0
        for c in key:
            if c != ' ' and c not in mp:
                mp[c] = chr(ord('a') + idx)
                idx += 1
        return ''.join(' ' if c == ' ' else mp[c] for c in message)
```

## 8. 边界情况与易错点

1. **方向搞反**：表是「key 字母 → 明文字母」（`map[c] = 'a'+idx`）。若建成「字母表 → key 字母」，解密就变成了加密，输出无意义。判据：登记时写进去的键是 **key 里扫到的字母**。
2. **空格混进表**：`key` 中的空格必须跳过。若给空格也分配下标，后面所有字母整体错位一位，全盘皆错。
3. **重复字母重复登记**：示例 1 的 `key` 里 `t` 出现 3 次、`o` 出现 2 次，只有首次出现才登记；已登记再覆盖会让 `idx` 走过头，第 27 个「登记」越界破坏对齐。
4. **「表必满」是前提不是巧合**：解码不写兜底的安全性完全来自「key 含全 26 字母」的约束；若题目去掉该保证，`message` 中可能出现表外字母，必须约定兜底行为。
5. **C++ 的 `char` 自增**：`cur++` 从 `'a'` 起可直接自增到 `'z'`，初值别写成 `0`；Python 必须显式 `chr(ord('a') + idx)`，对字符做算术后忘转 `chr` 是常见笔误。
6. **最短 key 自测**：`key = "abcdefghijklmnopqrstuvwxyz"` 时映射为恒等（输出 = 输入），可当赛场上最快的肉眼验证用例。
