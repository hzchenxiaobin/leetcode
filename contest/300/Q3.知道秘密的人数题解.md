# LeetCode 知道秘密的人数 题解

## 1. 题目概述

- **标题 / 题号**：知道秘密的人数（#2327，medium）
- **链接**：https://leetcode.cn/problems/number-of-people-aware-of-a-secret/
- **来源**：LeetCode 第 300 场周赛 Q3
- **难度**：中等
- **标签**：动态规划、前缀和、模拟、队列

**题意**：第 1 天有一个人发现了一个秘密。记 $D = \text{delay}$，$F = \text{forget}$：一个在第 $j$ 天首次知道秘密的人，从第 $j + D$ 天起**每天**把秘密告诉一个新的人，直到第 $j + F - 1$ 天；到第 $j + F$ 天他会**忘记**秘密——当天即不再知道、也不再传播。求第 $n$ 天结束时知道秘密的人数，答案对 $10^9 + 7$ 取模。

**约束**：

- $2 \le n \le 1000$
- $1 \le D < F \le n$

> 💡 传播规则是纯"时间表"式的：每个人的行为完全由他**首次知道秘密的那一天 $j$** 决定，与其他人是谁、有多少人无关。抓住这一点，问题就从"模拟一群人"退化为"一个一维递推"。

## 3. 解题思路

### 3.1 暴力思路：按人模拟，人数指数爆炸

最朴素的模拟：把每个知道秘密的人建模成一个对象，记录他的发现日，然后一天天推进——每天让所有"存活且已过沉默期"的人各产生一个新人。

问题在于**人数增长是指数级的**：从第 $j$ 天起每个活跃者每天再造一人，总人数近似按斐波那契方式爆炸，$n = 1000$ 时是天文数字，逐人模拟不可行。

> 💡 转折点：我们其实不关心"具体是谁"知道秘密，只关心**人数**。而每个人的行为完全由发现日 $j$ 决定——**同一天发现秘密的人彼此不可区分**。于是把"人"压缩成"计数"：令 $a_i$ = 第 $i$ 天**首次知道**秘密的人数。

按天分组后，即使不做任何优化，每天对"贡献窗口"直接求和，也能以 $O(n \cdot F) \le O(n^2) = 10^6$ 通过 $n \le 1000$；下面再把它优化到 $O(n)$。

### 3.2 核心观察：行为时刻表 + 活跃窗口

![核心观察：一个第 j 天知道秘密的人的完整生命周期](images/wc300_q3_lifecycle_concept.svg)

一个第 $j$ 天知道秘密的人，其完整时间表分三段：

1. **沉默期** $[j+1,\; j+D-1]$：知道，但不传播；
2. **分享期** $[j+D,\; j+F-1]$：每天把秘密告诉**一个**新的人；
3. **第 $j+F$ 天起**：忘记，既不知道也不再传播。

于是"第 $i$ 天有哪些人在分享"有精确刻画：

$$\text{第 } j \text{ 天知道的人在 } i \text{ 天活跃} \iff j + D \le i \le j + F - 1 \iff i - F + 1 \le j \le i - D$$

而第 $i$ 天的新人人数 = 当天活跃人数（每个活跃者恰带来一个互不相同的新人）：

$$a_i = \sum_{j=\max(1,\; i-F+1)}^{i-D} a_j \qquad (i \ge 2)$$

加上初始条件 $a_1 = 1$，这就是一个**窗口长度固定为 $F - D$ 的滑动窗口求和型递推**。

### 3.3 算法流程：前缀和差分，O(1) 转移

![算法流程：前缀和差分递推与最终尾段求和](images/wc300_q3_prefix_flow.svg)

窗口 $[i-F+1,\; i-D]$ 随 $i$ 右移，是连续区间和——用前缀和 $S_i = a_1 + \cdots + a_i$ 即可 $O(1)$ 转移：

$$a_i = S_{i-D} - S_{i-F} \qquad (\text{下标} < 0 \text{ 时取 } 0,\; i \ge 2)$$

$$S_i = S_{i-1} + a_i$$

最后统计第 $n$ 天结束时**仍记得**秘密的人：第 $i$ 天知道的人在第 $i+F$ 天忘记，所以当且仅当 $i + F > n$ 即 $i \ge n - F + 1$ 时仍然存活：

$$\text{ans} = \sum_{i=n-F+1}^{n} a_i = S_n - S_{n-F}$$

（约束 $F \le n$ 保证 $n - F \ge 0$，$S_0 = 0$。）

流程总结：

1. 初始化 $a_1 = S_1 = 1$；
2. $i$ 从 $2$ 到 $n$：先由前缀和差分算 $a_i$，再更新 $S_i$；
3. 输出 $(S_n - S_{n-F}) \bmod (10^9+7)$。

### 3.4 示例演算

![示例演算：n=6, delay=2, forget=4 的逐日走查](images/wc300_q3_example_walkthrough.svg)

对示例 1（$n=6,\; D=2,\; F=4$），贡献窗口为 $[i-3,\; i-2]$：

| $i$ | 窗口 $[i-3,\, i-2]$ | $a_i$ | 当天知道人数 | 事件 |
|----|---------------------|-------|-------------|------|
| 1 | ——（天降初始） | 1 | 1 | A 发现秘密 |
| 2 | $[-1,\, 0]$ → 空 | 0 | 1 | A 沉默 |
| 3 | $[0,\, 1]$ → $a_1$ | 1 | 2 | A 分享给 B |
| 4 | $[1,\, 2]$ → $a_1{+}a_2$ | 1 | 3 | A 分享给 C |
| 5 | $[2,\, 3]$ → $a_2{+}a_3$ | 1 | 3 | A 忘记；B 分享给 D |
| 6 | $[3,\, 4]$ → $a_3{+}a_4$ | 2 | 5 | B 分享给 E，C 分享给 F |

存活条件 $i \ge n - F + 1 = 3$，$\text{ans} = a_3 + a_4 + a_5 + a_6 = S_6 - S_2 = 6 - 1 = 5$ ✓。

注意第 5 行：A 恰在第 $1 + F = 5$ 天忘记，因此**当天既不在"知道人数"里、也不贡献新分享**——这一天的人数从 3（A、B、C）变为 3（B、C、D），一增一减。

## 4. 算法细节

1. **状态定义**：$a_i$ 是"第 $i$ 天**首次**知道"的人数，不是"第 $i$ 天知道"的累计人数。后者 $= \sum_{j=i-F+1}^{i} a_j$，两者不要混用；只有按"首次知道日"分组，组内行为才同构，才能递推。
2. **下标防御**：递推用到 $S_{i-D}$、$S_{i-F}$，在最初几天二者都可能为负（如 $i=2$、$F=n$ 时 $i-F<0$），统一约定**负下标取 0**。
3. **取模减法**：$S_{i-D} - S_{i-F}$ 在模 $10^9+7$ 下可能为负，先加 MOD 再取模（Python 的 `%` 自带非负语义可省）。
4. **初始值必须特判**：$a_1 = 1$ 是天降的初始条件，不满足递推——$i=1$ 时窗口 $[2-F,\, 1-D]$ 上界 $\le 0$ 恒为空。递推从 $i = 2$ 开始。
5. **等价的滑动窗口差分递推**：窗口 $[i-F+1,\, i-D]$ 与前一天窗口 $[i-F,\, i-D-1]$ 恰好只差两端各一项，逐项相减得

$$a_i = a_{i-1} + a_{i-D} - a_{i-F} \qquad (i \ge 3)$$

   它省去了前缀和数组（$a_2$ 仍需按窗口直接算，减法同样防负）。两种写法等价，任选其一。
6. **队列视角**：把 $a_j$ 依天数入队，窗口 $[i-F+1,\, i-D]$ 是队列中连续一段：$j = i-D$ 一侧是刚满 $D$ 天开始分享的人，$j = i-F$ 一侧是满 $F$ 天被遗忘出队的人。这正是官方标签 Queue 的由来；滑动窗口与队列在实现上同构。

## 5. 正确性证明

**引理 1**（行为时刻表）：一个在第 $j$ 天首次知道秘密的人，恰在第 $j+D,\; \dots,\; j+F-1$ 天中的每一天把秘密告诉一个新的人；在第 $j+F$ 天及之后既不知道秘密也不分享。

**证明**：题面规定"发现后 $D$ 天之后每天分享一人"，即从第 $j+D$ 天起每天分享；"发现 $F$ 天之后忘记"，即第 $j+F$ 天忘记，且"不能在忘记那一天及之后的日子里分享"。端点可由示例 1 核验：$j=1$ 的 A 首次分享于第 $1+D=3$ 天，忘记于第 $1+F=5$ 天且当天不分享。∎

**引理 2**（计数递推）：对 $i \ge 2$，第 $i$ 天首次知道秘密的人数满足

$$a_i = \sum_{j=\max(1,\; i-F+1)}^{i-D} a_j$$

（当 $i - D < 1$ 时右端为空和，值为 0。）

**证明**：除第 1 天的天降初始外，知道秘密的唯一途径是被分享，故第 $i$ 天的新人人数 = 当天的活跃分享者人数（"新人"指当天首次知道的人，每个新人恰被一个分享者首次告知，分享者与新人一一对应）。第 $j$ 天知道的 $a_j$ 个人在第 $i$ 天活跃，当且仅当 $j + D \le i \le j + F - 1$（引理 1），即 $i - F + 1 \le j \le i - D$；对满足条件的 $j \ge 1$ 求和即得。∎

**引理 3**（存活条件）：第 $i$ 天首次知道秘密的人在第 $n$ 天结束时仍知道秘密，当且仅当 $i + F > n$。

**证明**：由引理 1，其在第 $i+F$ 天起忘记。又 $i \le n$，故第 $n$ 天结束时仍知道 $\iff n < i + F$。∎

**定理**：记 $S$ 为 $a$ 的前缀和（$S_0 = 0$，负下标取 0），按 $a_1 = 1$、$a_i = S_{i-D} - S_{i-F}$（$i \ge 2$）计算，则第 $n$ 天结束时知道秘密的人数为 $(S_n - S_{n-F}) \bmod (10^9+7)$。

**证明**：先归纳证 $a$ 数组与真实人数过程一致：$a_1 = 1$ 为初始；设 $a_1, \dots, a_{i-1}$ 均正确，则由引理 2 与 $S_{i-D} - S_{i-F} = \sum_{j=i-F+1}^{i-D} a_j$ 知 $a_i$ 正确。再由引理 3，答案为 $\sum_{i=n-F+1}^{n} a_i$（$F \le n$ 保证下界 $\ge 1$），该区间和恰为 $S_n - S_{n-F}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。$i$ 从 2 到 $n$，每步做两次前缀和查询与一次加法更新，全部 $O(1)$；最后做一次差分得答案。分组后不带优化的逐项求和版本为 $O(n \cdot F)$，在本题 $n \le 1000$ 下也能通过。
- **空间复杂度**：$O(n)$。存 $a$ 与 $S$ 两个长度 $n+1$ 的数组。若改用滑动窗口差分递推（§4 第 5 点），可降到 $O(F)$（只保留最近 $F$ 天的值）；$n \le 1000$ 时无此必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int peopleAwareOfSecret(int n, int delay, int forget) {
        const int MOD = 1'000'000'007;
        // a[i]: 第 i 天首次知道秘密的人数; S[i]: a[1..i] 的前缀和
        vector<int> a(n + 1), S(n + 1);
        auto pre = [&](int x) { return x < 0 ? 0 : S[x]; };   // 负下标取 0
        a[1] = S[1] = 1;                                       // 初始: 天降 1 人
        for (int i = 2; i <= n; ++i) {
            a[i] = (pre(i - delay) - pre(i - forget) + MOD) % MOD;
            S[i] = (S[i - 1] + a[i]) % MOD;
        }
        // 存活条件 i + forget > n, 即 i ∈ [n-forget+1, n]
        return (S[n] - S[n - forget] + MOD) % MOD;
    }
};
```

### Python

```python
class Solution:
    def peopleAwareOfSecret(self, n: int, delay: int, forget: int) -> int:
        MOD = 10 ** 9 + 7
        # a[i]: 第 i 天首次知道秘密的人数; S[i]: a[1..i] 的前缀和
        a = [0] * (n + 1)
        S = [0] * (n + 1)
        a[1] = S[1] = 1
        for i in range(2, n + 1):
            hi = S[i - delay] if i - delay >= 0 else 0   # 负下标必须显式判 0
            lo = S[i - forget] if i - forget >= 0 else 0  # 否则 Python 负索引回绕
            a[i] = (hi - lo) % MOD
            S[i] = (S[i - 1] + a[i]) % MOD
        return (S[n] - S[n - forget]) % MOD
```

## 8. 边界情况与易错点

1. **端点 ±1 是头号陷阱**：贡献窗口是 $[i-F+1,\; i-D]$——忘记当天 $j+F$ **不分享**。若误写成 $[i-F,\; i-D]$（下界少减 1）或 $[i-F+1,\; i-D+1]$（上界多加 1），示例 1 会在第 5 天多算上已忘记的 A（A 恰在第 $1+F=5$ 天忘记）。写完务必用"第 5 天 A 忘记但人数仍为 3"核对。
2. **答案不是 $S_n$**：必须减去已忘记的 $S_{n-F}$。"曾经知道过的总人数"与"第 $n$ 天还知道的人数"是两回事。
3. **Python 负下标回绕**：`S[i - forget]` 在 $i < \text{forget}$ 时会静默取到列表尾部元素（**不报错**），产出难以调试的错值，必须显式判 `>= 0`；C++ 越界是未定义行为，同理用防御式取值。
4. **取模减法出负**：C++ 中 `(x - y) % MOD` 可能为负，先 `+ MOD` 再 `%`；Python 的 `%` 结果非负，可省。
5. **$a_1$ 不能靠递推**：第 1 天的窗口恒为空（$D \ge 1$），$a_1 = 1$ 必须作为初始条件；漏写初值会把整个数组推成全 0。
6. **别用"直觉公式"**：诸如"第 $i$ 天新增 = 第 $i-D$ 天的知道人数"是错的——那批人里含已忘记者，且会重复计入；正确的对象只有"首次知道日"分组的窗口和。
7. **$n = F$ 的退化**：$S_{n-F} = S_0 = 0$，存活区间为 $[1, n]$ 全部；数组开 $n+1$ 长保证下标 0 可用。
8. **中途取模不可省**：真实人数可达斐波那契级天文数字，C++ 不取模会溢出；每步 `% MOD`。
