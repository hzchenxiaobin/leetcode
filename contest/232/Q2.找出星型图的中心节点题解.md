# LeetCode 找出星型图的中心节点 题解

## 1. 题目概述

- **标题 / 题号**：找出星型图的中心节点（#1791，easy）
- **链接**：https://leetcode.cn/problems/find-center-of-star-graph/
- **来源**：LeetCode 第 232 场周赛 Q2
- **难度**：简单
- **标签**：图、度数

**题意**：给定一个 $n$ 个节点（编号 $1$ 到 $n$）的无向**星型图**（star graph）：存在一个**中心节点**，恰有 $n-1$ 条边把中心与其余每个节点各连一条。输入边列表 `edges`（`edges[i] = [u_i, v_i]` 表示 $u_i$ 与 $v_i$ 之间有边），返回中心节点的编号。

**约束**：

- $3 \le n \le 10^5$
- `edges.length == n - 1`
- `edges[i].length == 2`，$1 \le u_i, v_i \le n$，$u_i \ne v_i$
- 题目保证 `edges` 表示一个**有效的星型图**

## 2. 示例

**示例 1**

```text
输入：edges = [[1,2],[2,3],[4,2]]
输出：2
解释：节点 2 与 1、3、4 各连一条边，是中心节点。
```

**示例 2**

```text
输入：edges = [[1,2],[5,1],[1,3],[1,4]]
输出：1
解释：节点 1 与 2、5、3、4 各连一条边，是中心节点。
```

**示例 3（补充：中心位于每条边第一个端点的情形）**

```text
输入：edges = [[3,4],[3,1],[3,2]]
输出：3
解释：节点 3 与 4、1、2 各连一条边，是中心节点。
```

## 3. 解题思路

### 3.1 暴力思路：统计度数再筛选

遍历所有边，用哈希表（或长度 $n+1$ 的数组）累计每个节点出现的次数——即**度数**；度为 $n-1$ 的节点即中心：

```text
deg = [0] * (n + 1)
for u, v in edges:
    deg[u] += 1
    deg[v] += 1
for x in 1..n:
    if deg[x] == n - 1:
        return x
```

时间 $O(n)$、空间 $O(n)$，在 $n \le 10^5$ 下毫无压力、必然 AC。但这套「全局统计 + 筛选」完全没有用到星型图的结构——**中心出现在每一条边里**，意味着定位中心根本不需要把边看完，后面的 $n-3$ 条边不提供任何新信息。

### 3.2 核心观察：中心是任意两条边的公共端点

![核心观察：星型图中心出现在每一条边里，任两条边的公共端点即中心](images/wc232_q2_star_concept.svg)

星型图的边集形态极其受限：每条边都形如 $\{c, x\}$，其中 $c$ 是中心、$x$ 是非中心节点。于是度数分布是极端的二分：

$$\deg(c) = n-1, \qquad \deg(x) = 1 \ (x \ne c)$$

但对本题更实用的不是度数本身，而是**公共端点**视角：

- 中心 $c$ 在**每条**边里 ⟹ 对任意两条边 $e_0, e_1$ 都有 $c \in e_0 \cap e_1$；
- 非中心节点只出现在**唯一**一条边里 ⟹ 两条不同边的非中心端点互不相同；
- 因此 $e_0 \cap e_1$ **恰为 $\{c\}$**——任意两条边的公共端点唯一且就是中心。

> 💡 **一句话**：度数视角需要数完所有边才能确认「谁的度是 $n-1$」；公共端点视角只取两条边就能锁定中心。前者是全局统计，后者是局部判定。

### 3.3 算法流程

![算法流程：解包前两条边并一次判定](images/wc232_q2_algorithm_flow.svg)

1. **解包前两条边**：$e_0 = [u_0, v_0]$，$e_1 = [u_1, v_1]$（$n \ge 3$ 保证至少有两条边）。
2. **一次判定**：若 $u_0 = u_1$ 或 $u_0 = v_1$（即 $u_0$ 出现在 $e_1$ 中），返回 $u_0$。
3. **否则返回 $v_0$**。

由 $c \in e_0$ 知中心只能是 $u_0$ 或 $v_0$ 二者之一，所以**检查一个端点即可分流**，连 $v_0$ 是否在 $e_1$ 中都不用查。

### 3.4 示例演算

![示例演算：两个示例分别走否、是分支](images/wc232_q2_example_walkthrough.svg)

| 示例 | $e_0$ | $e_1$ | $u_0$ | $u_0 \in e_1$？ | 分支 | 返回 |
|------|-------|-------|-------|-----------------|------|------|
| 1 | $[1,2]$ | $[2,3]$ | $1$ | $1 \notin \{2,3\}$ → 否 | 返回 $v_0$ | $\mathbf{2}$ |
| 2 | $[1,2]$ | $[5,1]$ | $1$ | $1 \in \{5,1\}$ → 是 | 返回 $u_0$ | $\mathbf{1}$ |
| 3 | $[3,4]$ | $[3,1]$ | $3$ | $3 \in \{3,1\}$ → 是 | 返回 $u_0$ | $\mathbf{3}$ |

示例 1 走「否」分支：$u_0 = 1$ 只出现在 $e_0$ 一条边里，不是中心，故中心是 $e_0$ 的另一端 $v_0 = 2$。示例 2 走「是」分支：$u_0 = 1$ 同时出现在两条边里（命中 $u_0 = v_1$ 子条件），它就是中心。示例 3 覆盖另一半子条件：中心同在两条边的首位（$u_0 = u_1 = 3$）。三例都只读了前两条边。

## 4. 算法细节

1. **判定式一行写完**：`(u0 == u1 || u0 == v1) ? u0 : v0`，共 4 次数组访问、至多 2 次比较。
2. **候选集收缩**：由 $c \in e_0$ 得候选集 $\{u_0, v_0\}$；用「$u_0$ 是否出现在 $e_1$ 中」把二选一变成一判一推——$u_0$ 被排除后剩下的必然是 $v_0$。
3. **两种命中方式都要写**：$u_0 = u_1$（中心同在首位，示例 3）与 $u_0 = v_1$（中心跨位，示例 2），条件里的 `||` 少写一半就会在半数输入上出错。
4. **不依赖 $n$**：接口本就不传 $n$；度数阈值 $n-1$ 在 $O(1)$ 解法中根本不出现，也无需建图或开哈希表。
5. **恰好的信息量**：只读一条边无法区分中心与叶（两者都在该边中），读两条边恰可确定——本解法达到了该问题的读取下界。

## 5. 正确性证明

**引理 1**（边的形态）：设中心为 $c$，则边集与 $V \setminus \{c\}$ 一一对应，每条边恰形如 $\{c, x\}$（$x \ne c$）；特别地 $c$ 出现在每条边中。

**证明**：题意「恰有 $n-1$ 条边将中心节点与其他每个节点连接」，即对每个 $x \in V \setminus \{c\}$ 恰有一条边连接 $c$ 与 $x$，且不存在其他边。∎

**引理 2**（非中心只出现一次）：任意非中心节点 $x$ 恰出现在一条边（即 $\{c, x\}$）中。

**证明**：由引理 1，所有边均为 $\{c, y\}$ 形态。$x \in \{c, y\}$ 当且仅当 $y = x$（因 $x \ne c$），而每个 $y$ 恰对应一条边，故恰有一条边包含 $x$。∎

**定理**：任意两条不同边的公共端点恰为 $c$，且上述算法返回 $c$。

**证明**：设 $e_0, e_1$ 为两条不同边。由引理 1 可写 $e_0 = \{c, x\}$、$e_1 = \{c, y\}$；若 $x = y$ 则 $e_0 = e_1$，与引理 1 的双射矛盾，故 $x \ne y$。于是

$$e_0 \cap e_1 = \{c, x\} \cap \{c, y\} = \{c\},$$

即公共端点唯一且为 $c$。

再证算法正确。$n \ge 3$ 保证 $e_0, e_1$ 存在。由引理 1，$c \in e_0$，故 $c \in \{u_0, v_0\}$：

- 若 $c = u_0$：由引理 1，$c \in e_1$，即 $u_0 = u_1$ 或 $u_0 = v_1$，判定为真，算法返回 $u_0 = c$；
- 若 $c = v_0$：则 $u_0 \ne c$，$u_0$ 是非中心节点，由引理 2，$u_0 \notin e_1$，判定为假，算法返回 $v_0 = c$。

两种情况均返回 $c$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。只访问 `edges[0]` 与 `edges[1]` 共 4 个整数，做至多 2 次比较，与 $n$ 无关（度数统计为 $O(n)$）。
- **空间复杂度**：$O(1)$。仅 4 个整型变量，不建图、不开哈希表（度数统计为 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findCenter(vector<vector<int>>& edges) {
        int u0 = edges[0][0], v0 = edges[0][1];
        int u1 = edges[1][0], v1 = edges[1][1];
        return (u0 == u1 || u0 == v1) ? u0 : v0;
    }
};
```

### Python

```python
class Solution:
    def findCenter(self, edges: List[List[int]]) -> int:
        (u0, v0), (u1, v1) = edges[0], edges[1]
        return u0 if u0 in (u1, v1) else v0
```

## 8. 边界情况与易错点

1. **`edges[1]` 必然存在**：$n \ge 3$ 且 `edges.length == n - 1` ⟹ 至少 2 条边，无需判空。
2. **中心可在端点任意一侧**：同一条 `e0 = [1,2]` 里，中心既可能是 1（示例 2）也可能是 2（示例 1）；判定条件必须同时覆盖 $u_0 = u_1$ 与 $u_0 = v_1$。
3. **别顺手统计度数**：哈希表数度数再找 $n-1$ 的做法 $O(n)$ 时间 / $O(n)$ 空间，能 AC 但浪费了「中心在每条边」的结构约束。
4. **无需检查 $v_0$**：$u_0$ 分流后 $v_0$ 自动确定，再查一次是冗余（查了结果也不会变，但白白多读数据）。
5. **合法性保证是命门**：O(1) 判定完全依赖「edges 表示有效星型图」。若输入可能是普通图（如 `[[1,2],[3,4]]` 两条边无公共端点），前两条边的公共端点可能不存在或不唯一，必须退回度数统计并处理无解情形。
6. **最小规模 $n = 3$**：恰两条边，算法照样只看这两条，行为与大规模完全一致。
