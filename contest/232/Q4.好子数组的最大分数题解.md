# LeetCode 好子数组的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：好子数组的最大分数（#1793，hard）
- **链接**：https://leetcode.cn/problems/maximum-score-of-a-good-subarray/
- **来源**：LeetCode 第 232 场周赛 Q4
- **难度**：困难
- **标签**：数组、双指针、贪心、单调栈

**题意**：给定整数数组 `nums`（下标从 0 开始）和整数 `k`。子数组 $(i, j)$ 的**分数**定义为

$$\text{score}(i, j) = \min(\text{nums}[i], \ldots, \text{nums}[j]) \times (j - i + 1)$$

**好子数组**要求端点满足 $i \le k \le j$，即子数组必须**覆盖下标 `k`**。返回好子数组分数的最大值。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 2 \times 10^4$
- $0 \le k < \text{nums.length}$

> 💡 **关键约束解读**："必须包含 `k`" 是本题的灵魂。它把 [84. 柱状图中最大的矩形](https://leetcode.cn/problems/largest-rectangle-in-histogram/)（全局最大矩形）特化为"**必须覆盖第 `k` 根柱子的最大矩形**"，从而催生出从 `k` 出发、$O(1)$ 空间的贪心双指针解法。值域 $\le 2 \times 10^4$ 则暗示可以从"最小值的取值"角度思考问题。

## 2. 示例

**示例 1**

```text
输入：nums = [1,4,3,7,4,5], k = 3
输出：15
解释：最优子数组端点 (1, 5)，min(4,3,7,4,5) × (5-1+1) = 3 × 5 = 15。
```

**示例 2**

```text
输入：nums = [5,5,4,5,4,1,1,1], k = 0
输出：20
解释：最优子数组端点 (0, 4)，min(5,5,4,5,4) × (4-0+1) = 4 × 5 = 20。
```

**示例 3（自构造，体会"覆盖 k"的约束力）**

```text
输入：nums = [9,1,9], k = 1
输出：3
解释：任何包含下标 1 的子数组 min 都是 1，最宽的 (0, 2) 得 1×3 = 3。
若忽略"覆盖 k"的约束会误答 9（单柱 9 不含 k，非法）。
```

## 3. 解题思路

### 3.1 暴力思路

所有好子数组共享锚点 `k`：左端点 $i \in [0, k]$，右端点 $j \in [k, n-1]$。固定 `i` 向右扩展 `j` 时可以增量维护 min，每个窗口 $O(1)$ 结算，但窗口总数达 $(k+1)(n-k)$——`k` 居中时约 $n^2/4 \approx 2.5 \times 10^9$（$n = 10^5$），即使每窗口 $O(1)$ 也超时；若对每窗口现算 min 则是 $O(n^3)$。

> ⚠️ **暴力的浪费所在**：分数 = $\min \times$ 宽度，两者**此消彼长**。最小值相同的窗口里，宽的永远不会更差——每个"最小值水位"其实只需要考察一个把宽度拉满的极限窗口。

### 3.2 核心观察：枚举最小值水位 v，而不是枚举子数组

![枚举最小值水位v的候选表](images/good_subarray_max_score_threshold.svg)

把视角从"枚举窗口"切换到"枚举最小值"。对整数 $v$，定义

$$W(v) = \text{包含 } k \text{ 且元素全 } \ge v \text{ 的最长连续区间}$$

那么答案可以被改写成一张"水位表"（上图）：

$$\text{ans} = \max_{v \ge 1} \; v \times |W(v)|$$

三个要点：

1. **固定水位 v，宽度直接拉满**：任何最小值 $\ge v$ 的好子数组都装在 $W(v)$ 里，宽度最多 $|W(v)|$，所以水位 $v$ 的候选分数就是 $v \times |W(v)|$。
2. **只需考察"自洽值"**：若 $W(v)$ 的真实最小值比 $v$ 高（如示例 1 中 $v=5$ 时 $W(5)=[3,3]$ 但真实 min 是 7），候选 $5 \times 1$ 会被更高水位 $7 \times 1$ **支配**。值得考察的只有满足 $v = \min(W(v))$ 的自洽值——它一定是某个元素值，至多 $n$ 个。
3. **如何不重不漏地扫出自洽候选**：从 `k` 出发贪心扩展，见下一节。

### 3.3 算法流程：从 k 出发，每步并入较大的邻居

![从k出发贪心双向扩展流程](images/good_subarray_max_score_flow.svg)

窗口从 $[k, k]$ 出发，每一步在两个候选邻居 $\text{nums}[l-1]$ 与 $\text{nums}[r+1]$ 中**并入较大的一侧**：

1. **初始化**：$l = r = k$，$\text{mn} = \text{nums}[k]$，$\text{ans} = \text{nums}[k]$（窗口 $[k,k]$ 本身就是好子数组）。
2. **循环**（当 $l > 0$ 或 $r < n-1$）：
   - 取 $lv = \text{nums}[l-1]$（$l = 0$ 时记 $-\infty$），$rv = \text{nums}[r+1]$（$r = n-1$ 时记 $-\infty$）；
   - 若 $lv > rv$：向左扩展，$l \leftarrow l-1$；否则向右扩展，$r \leftarrow r+1$；
   - 更新 $\text{mn} \leftarrow \min(\text{mn}, \text{nums}[\text{新端点}])$；
   - 记录候选 $\text{ans} \leftarrow \max(\text{ans},\; \text{mn} \times (r - l + 1))$。
3. 共 $n - 1$ 轮，窗口从长度 1 扩满整个数组，返回 `ans`。

**为什么"选较大的一侧"是对的**（直观版，严格证明见 §5）：

- 它让 $\text{mn}$ **下降得最慢**——并入的元素尽量不拉低水位；
- 更本质地：只要窗口还没铺满 $W(v)$，落在 $W(v)$ **内侧**的邻居值 $\ge v$、**外侧**的邻居值 $< v$，较大的一侧必然是内侧。于是**窗口必然先铺满 $W(v)$，才会跌破水位 $v$**；铺满的那一刻 $\text{mn} = \min(W(v))$，恰好把自洽候选 $v \times |W(v)|$ 记进答案。

### 3.4 示例演算

![示例1逐步扩展演算](images/good_subarray_max_score_walkthrough.svg)

以示例 1 `nums = [1,4,3,7,4,5]`，`k = 3` 为例（上图）：

- 第 ①② 步：右侧邻居 4、5 都大于左侧的 3，贪心连续右扩，`mn` 稳在 4，分数 7 → 8 → 12；
- 第 ③④ 步：右侧到头后被迫左扩，`mn` 跌到 3，但宽度继续涨，$3 \times 5 = 15$ 在窗口**首次铺满 $W(3) = [1,5]$** 时被记录，成为最优；
- 第 ⑤ 步：并入 `nums[0] = 1` 后 `mn` 暴跌，分数回落，但 `ans` 已锁定峰值。

> 💡 **对比示例 2**（`k = 0`）：`k` 贴左端点，全程只能向右扩展——贪心退化为单向扫描，`mn` 从 5 降到 4 后宽度涨到 5，$4 \times 5 = 20$ 即最优。单向情形是双向贪心的特例，无需单独处理。

## 4. 算法细节

1. **状态量**：`l`、`r`（窗口端点）、`mn`（窗口真实最小值）、`ans`（历史最优）。`mn` 始终等于 $\min(\text{nums}[l..r])$——初始为 `nums[k]`，每并入一个端点做一次 `min`，$O(1)$ 维护。
2. **越界哨兵**：把"不可扩展的一侧"记为 $-\infty$（实现中取比一切元素小的值即可，如 `INT_MIN`），一个比较表达式就统一了"贴边"与"两侧可选"的全部情形，避免手写四路分支时的越界错误。
3. **每一轮都结算**：包括 `mn` 没有下降的轮——宽度在涨，分数可能继续上涨（演算第 ④ 步 `mn` 已跌到 3，分数仍从 12 涨到 15）。
4. **并列时任选**：$\text{nums}[l-1] = \text{nums}[r+1]$ 时选哪边都正确。§5 的证明只用到"贪心取到较大的一侧（并列时任意）"，与方向无关。
5. **单调栈替代解法**（同样 $O(n)$）：本题等价于"柱状图中必须覆盖第 `k` 根柱子的最大矩形"。两次单调栈求出每个元素左、右第一个**严格更小**元素，得到其作为最小值的管辖区间 $[L_i, R_i]$；若 $L_i \le k \le R_i$，则以 $\text{nums}[i] \times (R_i - L_i + 1)$ 为候选。它通用性更强（去掉 `k` 约束就是 84 题），代价是 $O(n)$ 额外空间，代码见 §7 解法二。

## 5. 正确性证明

**记号**：$W(v)$ 表示包含 $k$ 且元素全 $\ge v$ 的最长连续区间；$v > \text{nums}[k]$ 时 $W(v)$ 不存在，约定对应候选为 $0$。窗口指当前区间 $[l, r]$，$\text{mn} = \min(\text{nums}[l..r])$。$\mathrm{OPT}$ 为最优答案。注意 $\text{nums}[i] \ge 1$。

**引理 1（阈值表示）**：$\mathrm{OPT} = \max_{v \ge 1} \; v \times |W(v)|$。

**证明**：
("$\ge$") 对每个 $v$：若 $W(v)$ 存在，它本身是好子数组（包含 $k$），真实分数为 $\min(W(v)) \times |W(v)| \ge v \times |W(v)|$，故 $\mathrm{OPT} \ge v \times |W(v)|$；若不存在则候选为 $0 \le \mathrm{OPT}$。
("$\le$") 设 $(i^*, j^*)$ 取到 $\mathrm{OPT}$，$m^* = \min(\text{nums}[i^*..j^*])$。其全部元素 $\ge m^*$ 且区间包含 $k$，故 $m^* \le \text{nums}[k]$（$W(m^*)$ 非空）且 $(i^*, j^*) \subseteq W(m^*)$。于是 $|W(m^*)| \ge j^* - i^* + 1$，又 $m^* \ge 1 > 0$，得
$$m^* \times |W(m^*)| \;\ge\; m^* \times (j^* - i^* + 1) \;=\; \mathrm{OPT}.$$
两个方向合并即得。∎

**引理 2（自洽值支配）**：设 $W(v)$ 非空，$m = \min(W(v))$，则 $W(m) = W(v)$，且 $m \times |W(m)| \ge v \times |W(v)|$。

**证明**：$W(v)$ 内元素全 $\ge m$ 且包含 $k$，由最大性 $W(v) \subseteq W(m)$；反之 $m \ge v$，"元素全 $\ge m$"蕴含"元素全 $\ge v$"，故 $W(m) \subseteq W(v)$。两者相等，且 $m \ge v > 0$ 给出候选不等式。∎

**推论**：引理 1 的最大值总可在某个**自洽值** $v$（满足 $v = \min(W(v))$）处取得；自洽值必为某元素值，互不相同者至多 $n$ 个。

**引理 3（扩展不变式）**：若某轮开始时窗口满足 $[l, r] \subseteq W(v)$ 且 $[l, r] \subsetneq W(v)$，则本轮贪心并入的元素落在 $W(v)$ 内（新窗口仍 $\subseteq W(v)$，长度加一）。

**证明**：记 $W(v) = [L, R]$。由 $[l,r] \subsetneq W(v)$ 知 $l > L$ 或 $r < R$ 至少一侧成立。不妨 $l > L$：则 $\text{nums}[l-1]$ 位于 $[L, l-1] \subseteq W(v)$ 内，故 $\text{nums}[l-1] \ge v$；$r < R$ 同理。另一方面，越出 $W(v)$ 的候选邻居（若存在，如 $r+1 > R$）必满足 $\text{nums}[r+1] < v$——否则 $[L, R+1]$ 是更长的全 $\ge v$ 且含 $k$ 区间，与 $W(v)$ 最大性矛盾。于是两侧候选中**内侧的 $\ge v$、外侧的 $< v$**，贪心取较大者必然选中内侧；特别地，一侧已贴住 $W(v)$ 边界时，另一侧的余量同样只会被优先吸收。∎

**定理**：贪心算法返回 $\mathrm{OPT}$。

**证明**：
("$\le$") 每轮记录的候选 $\text{mn} \times (r-l+1)$ 恰是当前窗口（一个好子数组）的真实分数，故返回值 $\le \mathrm{OPT}$。
("$\ge$") 由引理 2 推论，取自洽值 $v^*$ 使 $v^* \times |W(v^*)| = \mathrm{OPT}$。初始窗口 $[k,k] \subseteq W(v^*)$（因 $k \in W(v^*)$）。对引理 3 归纳：窗口未铺满 $W(v^*)$ 时，每轮都保持在 $W(v^*)$ 内且长度加一。窗口长度从 1 严格递增至 $n$，而 $1 \le |W(v^*)| \le n$，故存在某轮窗口**恰好等于** $W(v^*)$。该轮 $\text{mn} = \min(W(v^*)) = v^*$（自洽性），记录候选 $v^* \times |W(v^*)| = \mathrm{OPT}$。
两个方向合并，返回值 $= \mathrm{OPT}$。∎

> 💡 **证明的精髓**：贪心路径不是在"随机枚举窗口"，而是**按水位从高到低依次铺满每个 $W(v)$**——每个自洽候选恰好在其"铺满时刻"被结算一次，不多不少。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。主循环恰好 $n-1$ 轮（窗口从长度 1 扩到 $n$，每轮并入 1 个元素），每轮比较、取 min、结算均为 $O(1)$。相比暴力的 $O(n^2)$，本质是把"枚举 $O(n^2)$ 个窗口"压缩成"枚举 $O(n)$ 个临界水位"。
- **空间复杂度**：$O(1)$。只维护 `l`、`r`、`mn`、`ans` 四个变量（单调栈解法则需要 $O(n)$ 额外空间存储左右边界）。

## 7. 参考代码

### C++（解法一：贪心双指针，$O(n)$ / $O(1)$）

```cpp
class Solution {
  public:
    int maximumScore(vector<int>& nums, int k) {
        int n = nums.size();
        int l = k, r = k;
        int mn = nums[k];
        long long ans = nums[k];

        while (l > 0 || r < n - 1) {
            // 越界一侧记 -inf，谁大选谁
            int lv = (l > 0) ? nums[l - 1] : INT_MIN;
            int rv = (r < n - 1) ? nums[r + 1] : INT_MIN;
            if (lv > rv) {
                l--;
                mn = min(mn, nums[l]);
            } else {
                r++;
                mn = min(mn, nums[r]);
            }
            ans = max(ans, 1LL * mn * (r - l + 1));
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maximumScore(self, nums: List[int], k: int) -> int:
        n = len(nums)
        l = r = k
        mn = nums[k]
        ans = nums[k]

        while l > 0 or r < n - 1:
            lv = nums[l - 1] if l > 0 else float("-inf")
            rv = nums[r + 1] if r < n - 1 else float("-inf")
            if lv > rv:
                l -= 1
                mn = min(mn, nums[l])
            else:
                r += 1
                mn = min(mn, nums[r])
            ans = max(ans, mn * (r - l + 1))
        return ans
```

### C++（解法二：单调栈，$O(n)$ / $O(n)$）

```cpp
class Solution {
  public:
    int maximumScore(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> left(n), right(n);
        stack<int> st;

        // left[i]: i 左侧第一个严格更小元素的下标
        for (int i = 0; i < n; ++i) {
            while (!st.empty() && nums[st.top()] >= nums[i]) st.pop();
            left[i] = st.empty() ? -1 : st.top();
            st.push(i);
        }
        st = stack<int>();

        // right[i]: i 右侧第一个严格更小元素的下标
        for (int i = n - 1; i >= 0; --i) {
            while (!st.empty() && nums[st.top()] >= nums[i]) st.pop();
            right[i] = st.empty() ? n : st.top();
            st.push(i);
        }

        long long ans = 0;
        for (int i = 0; i < n; ++i) {
            // i 的管辖区间 [left[i]+1, right[i]-1] 覆盖 k 才合法
            if (left[i] < k && k < right[i]) {
                ans = max(ans, 1LL * nums[i] * (right[i] - left[i] - 1));
            }
        }
        return (int)ans;
    }
};
```

> ⚠️ 等高元素两侧都取**严格更小**作边界，等高邻居会互相穿透、重复声明同一区间——对取 `max` 无影响；若一侧改成"更小或相等"，等高邻居会把彼此的管辖区间截断，导致漏解。

## 8. 边界情况与易错点

1. **初始候选别漏**：`ans` 必须从 `nums[k]` 起算，窗口 $[k,k]$ 本身就是好子数组（`n = 1` 时它是唯一答案，循环不执行）。
2. **k 贴端点**（示例 2 `k = 0`）：全程单向扩展。哨兵写法自动处理；若手写四路分支，必须**先判 `l == 0` / `r == n-1` 再比较两侧**，否则下标越界。
3. **乘法溢出**：候选上限 $2 \times 10^4 \times 10^5 = 2 \times 10^9$，贴着 32 位 `int` 上限（约 $2.147 \times 10^9$）。虽然恰好不溢，但毫无余量，C++ 中应像上面代码那样用 `long long` 承接乘积。
4. **不能提前 break**：`mn` 暴跌后分数仍可能创新高（演算第 ④ 步 12 → 15）。"水位跌了就停"是 WA 的经典姿势；贪心不回头，但也不需要回头。
5. **别把 84 题的全局解直接搬来**：必须过滤"管辖区间覆盖 `k`"。反例 `nums = [9,1,9], k = 1`：全局最大矩形是 9（不含 `k` 的单柱），正确答案是 3。
6. **相等元素的扩展方向**：`nums[l-1] == nums[r+1]` 时选哪边都不影响正确性（§5 证明只用到"取到较大（并列即任意）的一侧"）。
7. **mn 必须是"窗口真实最小值"**：每并入一个端点都要 `min` 进来，漏掉任何一次都会高估或低估后续所有候选。

**延伸思考**：

- **多次询问不同的 k**：贪心只适用单次询问。离线做法：单调栈预处理每个元素的管辖区间 $[L_i, R_i]$ 与候选值 $c_i$，把候选视为"对 $k \in [L_i, R_i]$ 的区间赋值"，按 $k = 0..n-1$ 扫描，用支持"区间取 max / 单点查询"的线段树（或按 $L_i$ 入堆、$R_i$ 出堆的堆）维护当前覆盖 `k` 的最大候选，总计 $O(n \log n)$。
- **值域视角的离线实现**：$\text{nums}[i] \le 2 \times 10^4$ 提示按值从大到小"激活"元素——每激活一个值 $v$ 的元素，就用并查集与相邻激活段合并，读出包含 `k` 的连续段长度 $\ell$，以 $v \times \ell$ 更新答案。这恰是"枚举阈值"的离线版本，排序后 $O(n \log n)$。
- **允许 0 / 负数**："宽度涨分数涨"的直觉失效，但贪心依然正确：若 $\text{nums}[k] \le 0$，任何含 `k` 窗口的 $\min \le \text{nums}[k] \le 0$，乘上长度只会更小，$[k,k]$ 直接最优（恰是贪心起点）；若 $\text{nums}[k] > 0$，则最优分数为正、最优窗口的 $\min > 0$，§5 的阈值论证逐字适用。可见"必须包含 `k`"这一约束比"元素为正"更本质——只是正值让直觉更顺，证明则必须走阈值路线。
