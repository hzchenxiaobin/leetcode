# LeetCode 在 LR 字符串中交换相邻字符 题解

## 1. 题目概述

- **标题 / 题号**：在 LR 字符串中交换相邻字符（#777，medium）
- **链接**：https://leetcode.cn/problems/swap-adjacent-in-lr-string/
- **来源**：LeetCode 第 70 场周赛 Q3
- **难度**：中等
- **标签**：双指针、字符串

**题意**：字符串只由 `L`、`R`、`X` 三种字符组成。一次**移动**只能是下面两种替换之一：

- 把子串 `XL` 换成 `LX`，效果是**一个 `L` 向左挪一格**（与它左边的空位 `X` 交换）；
- 把子串 `RX` 换成 `XR`，效果是**一个 `R` 向右挪一格**（与它右边的空位 `X` 交换）。

注意操作是**单向**的：`L` 永远不会往右跑，`R` 永远不会往左跑。给定起始串 `start` 与目标串 `result`（长度相同），判断能否通过若干次移动把 `start` 变成 `result`。

**约束**：

- $1 \le \lvert \text{start} \rvert \le 10^4$，且 $\lvert \text{start} \rvert = \lvert \text{result} \rvert$
- `start` 与 `result` 都只含 `L` / `R` / `X`
- 数据规模决定了：直接搜索状态空间必死，$O(n^2)$ 的逐字符模拟也不该写，正解必须是 $O(n)$ 的一趟扫描

## 2. 示例

**示例 1**

```text
输入：start = "RXXLRXRXL", result = "XRLXXRRLX"
输出：true
解释：四步可达（每一步都只动一个字母一格，且不改变非 X 字符的顺序）：
      RXXLRXRXL
   -> XRXLRXRXL
   -> XRLXRXRXL
   -> XRLXXRRXL
   -> XRLXXRRLX
```

**示例 2**

```text
输入：start = "X", result = "L"
输出：false
解释：X 里没有 L，移动既不能凭空造出字符，也不能改变字符个数。
```

**示例 3（补充，两个极小反例）**

```text
输入：start = "XL", result = "LX"    输出：true（正好套用一次 XL -> LX）
输入：start = "LXX", result = "XXL"  输出：false（L 只能左移，目标却要它右移）
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是把「字符串」当作状态做 BFS：从 `start` 出发，枚举所有满足 `s[p..p+2] == "XL"` 或 `"RX"` 的位置 $p$，替换后入队，直到遇到 `result`。

两个致命问题：

1. **状态数爆炸**。移动不改变非 X 字符的相对顺序，所以从 $s$ 能到达的状态恰好是「把 $m$ 个非 X 字符按原顺序塞进 $n$ 个位置」的方案数，即 $\binom{n}{m}$。$n = 10^4$、$m = 5000$ 时这是天文数字；即使 $n = 20$ 也有近 $10^5\sim10^6$ 个状态。
2. **每步还要 $O(n)$ 复制字符串**，且会大量重复入队。总开销 $O\!\left(n\binom{n}{m}\right)$，完全不可行。

顺带一提，本题状态图其实是个 **DAG**：令势函数 $\Phi = \sum_k \text{pos}(R_k) - \sum_k \text{pos}(L_k)$，每次移动都让它 $+1$。可惜「无环」并不能把状态数降下来——真正能降维的是下面两个不变量。

### 3.2 核心观察：顺序守恒 + 单侧漂移

![L 只左漂、R 只右漂，且互不穿越](images/wc70_q3_direction_invariant.svg)

把三种字符的角色分清楚，题目的结构就出来了：

| 字符 | 运动方向 | 说明 |
|------|----------|------|
| `L` | 只能**向左**（`XL -> LX`） | 只与 `X` 交换，穿不过任何非 X 字符 |
| `R` | 只能**向右**（`RX -> XR`） | 只与 `X` 交换，穿不过任何非 X 字符 |
| `X` | 被动让位 | 空位本身不「移动」，数量恒定 |

由此得到两条**必要条件**。记非 X 字符序列为 $c_1, c_2, \dots, c_m$，它们在 `start` 中的下标为 $a_1 < a_2 < \cdots < a_m$，在 `result` 中的下标为 $b_1 < b_2 < \cdots < b_m$。

> 💡 **条件 1（顺序守恒）**：两串去掉所有 `X` 后得到的序列必须完全相同，即 $c_k$ 逐一相等。因为 `L` 与 `R` 之间从不直接交换，字母的先后次序是硬约束。

> 💡 **条件 2（单侧漂移）**：对每个配对的 $c_k$——
> - 若 $c_k = L$，则 $a_k \ge b_k$（L 只可能左移或不动）；
> - 若 $c_k = R$，则 $a_k \le b_k$（R 只可能右移或不动）。

关键在于这两条**不只是必要，而且充分**：只要方向都对，`X` 就是可以自由让位的空位，字母总能一格一格走到目标位置（§5 用「距离单调下降」的归纳给出了构造性证明）。于是问题从「搜索一个巨大的状态图」变成「检查两条静态条件」——这就是本题的全部。

> 💡 条件 2 还有一种**等价写法**：对任意前缀长度 $p$，`result` 前缀里的 `L` 个数不少于 `start` 前缀里的 `L` 个数，`R` 个数不多于 `start` 前缀里的。这正是「每个 L 只左移、每个 R 只右移」的计数形式，好处是完全不需要下标配对，坏处是要额外维护计数器。本题选下标配对更直接。

### 3.3 算法流程：双指针逐对校验

![双指针判定流程](images/wc70_q3_two_pointer_flow.svg)

维护两个指针 $i$（扫 `start`）、$j$（扫 `result`），**保留原始下标**，只对齐非 X 字符：

1. 内层循环跳过 `X`：`start[i] == 'X'` 则 `i++`；`result[j] == 'X'` 则 `j++`。重复直到两个指针都落在 `L`/`R` 上，或到达末尾。
2. 若有一方先到末尾：返回「两者是否都到末尾」——只有一方到头说明非 X 字符个数不同，直接失败。
3. 若 `start[i] != result[j]`：非 X 序列不同（顺序被破坏），返回 `false`。
4. 若 `start[i] == 'L'` 且 $i < j$：L 需要右移，违法，返回 `false`。
5. 若 `start[i] == 'R'` 且 $i > j$：R 需要左移，违法，返回 `false`。
6. 这一对通过，`i++`、`j++`，回到第 1 步。
7. 两串同时扫完即返回 `true`。

整个过程**不修改任何字符串**，也不需要建「去 X」的新串。

### 3.4 示例演算

![示例演算：RXXLRXRXL -> XRLXXRRLX](images/wc70_q3_walkthrough.svg)

以 `start = "RXXLRXRXL"`、`result = "XRLXXRRLX"` 为例，跳过 `X` 后依次配对：

| 配对 | start 位置 $i$ / 字符 | result 位置 $j$ / 字符 | 方向校验 | 结论 |
|------|----------------------|-----------------------|----------|------|
| ① | $i=0$，`R` | $j=1$，`R` | R 右移 $0 \to 1$ ✓ | 通过 |
| ② | $i=3$，`L` | $j=2$，`L` | L 左移 $3 \to 2$ ✓ | 通过 |
| ③ | $i=4$，`R` | $j=5$，`R` | R 右移 $4 \to 5$ ✓ | 通过 |
| ④ | $i=6$，`R` | $j=6$，`R` | 原地不动 ✓ | 通过 |
| ⑤ | $i=8$，`L` | $j=7$，`L` | L 左移 $8 \to 7$ ✓ | 通过 |

5 对全部通过且两串同时扫完（$i=j=9$），返回 `true`。注意配对 ① 是「`start` 的 `R` 跑到了右边空位」、配对 ④ 是「一个字母都没动也在合法区间内」，两种情况都必须放行。

**两个反例**：

- `start = "LR"`、`result = "RL"`：去 X 后是 `LR` 与 `RL`，第 1 对就 `L != R` → 顺序被破坏，`false`。
- `start = "LXX"`、`result = "XXL"`：字符配对成功，但 $i=0 < j=2$，L 要往右跑 → 方向违法，`false`。

## 4. 算法细节

1. **必须保留原始下标**。$i$、$j$ 表示「第 $k$ 个非 X 字符在原串里的位置」，而不是它在压缩序列里的序号。方向校验比较的是**绝对位置**，一旦压成序号，$a_k \ge b_k$ 这类信息就被抹掉了。
2. **跳过 `X` 的 `while` 放在循环开头**。上一轮 `i++`、`j++` 之后很可能又踩到 `X`（示例中配对 ③ 之后 `i=5` 正好落在 `X` 上），漏掉这一步会错位比较。
3. **先判顺序、再判方向**。顺序不同时方向讨论没有意义，先返回能避免大量无谓分支。
4. **方向判定要写足等号的情形**。$i = j$ 时两个条件都成立（字母不动），如果顺手写成 `L 且 i > j` 就会把合法的「不动」误判成非法。
5. **不需要单独校验 X 的个数**。两串等长，非 X 子序列又完全一致，故非 X 个数 $m$ 相同，$X$ 的个数 $n - m$ 自然相同。
6. **不要真的构造「去 X」的字符串**。`s.replace('X','')` 或 `[ch for ch in s if ch != 'X']` 是 $O(n)$ 额外空间 + 两趟遍历，而且丢掉了下标信息，还得再做一次配对；双指针一趟原地解决。
7. **循环结构**：外层用 `while True`，唯一的出口是第 2 步的「一方到末尾」，那里已经覆盖了「两侧都到头」的成功分支，因此不会死循环，也不需要额外的 `while i < n || j < n` 条件。
8. **越界保护只在内层**。内层 `while` 已有 `i < n`（`j < n`）守卫，所以第 3 步直接取 `start[i]` 是安全的——因为此时已确认 `i < n` 且 `j < n`。

## 5. 正确性证明

沿用 §3.2 的记号：非 X 字符序列 $c_1, \dots, c_m$，在 `start` 中下标 $a_1 < \cdots < a_m$，在 `result` 中下标 $b_1 < \cdots < b_m$。

**引理 1（顺序守恒）**：任意一次移动都不改变字符串的非 X 字符序列。

**证明**：移动只有两种：`XL -> LX` 与 `RX -> XR`。前者把相邻的 `X`、`L` 换成 `L`、`X`，删掉 `X` 后两种写法都只剩一个 `L`；后者把 `R`、`X` 换成 `X`、`R`，删掉 `X` 后都只剩一个 `R`。其余位置不受影响，故整个非 X 序列不变。∎

**引理 2（单侧漂移）**：在任意移动序列中，某个具体 `L` 的下标单调不增，某个具体 `R` 的下标单调不减。

**证明**：一次移动只改变参与交换的那个字母与那个 `X` 的位置，其他字符位置不变；被移动的 `L` 恰好左移 1，被移动的 `R` 恰好右移 1。由归纳，每个 `L` 的下标只减不增、每个 `R` 只增不减。∎

**推论 1（必要条件）**：若 `start` 能变成 `result`，则两串非 X 序列相同，且对每个 $k$：$c_k = L \Rightarrow a_k \ge b_k$，$c_k = R \Rightarrow a_k \le b_k$。

**证明**：由引理 1，两串的非 X 序列都是 $c_1,\dots,c_m$（同一批字母），第 $k$ 个字母对应同一个字符；由引理 2，它的下标从 $a_k$ 单调漂移到 $b_k$，故 L 时有 $b_k \le a_k$、R 时有 $b_k \ge a_k$。∎

**定义（距离）**：在条件成立的前提下，令
$$D = \sum_{k:\,c_k = L} (a_k - b_k) \;+\; \sum_{k:\,c_k = R} (b_k - a_k) \ \ge 0 .$$
每一项都是「第 $k$ 个字母还差几步才到位」，$D$ 是总步数的一个下界。

**引理 3（下降步存在）**：若条件成立且 $D > 0$，则存在一次合法移动使 $D$ 恰好减 1。

**证明**：取最小的 $k$ 使第 $k$ 项 $d_k > 0$（即该字母尚未到位）。

- 若 $c_k = L$：此时 $a_k > b_k$，L 需要左移，我们证明 $a_k - 1$ 处必为 `X`。反设不是，则 $a_k - 1$ 处是一个非 X 字符，也就是 $a_{k-1} = a_k - 1$（$k \ge 2$，因为 $a_k > b_k \ge 0$）。由 $k$ 的最小性 $d_{k-1} = 0$，即 $a_{k-1} = b_{k-1}$。于是 $b_k > b_{k-1} = a_{k-1} = a_k - 1$，得 $b_k \ge a_k$，与 $a_k > b_k$ 矛盾。故 $a_k - 1$ 处为 `X`，`XL -> LX` 合法。移动后 $a_k$ 减 1、其余 $a$ 不变，于是 $d_k$ 减 1、$D$ 减 1。
- 若 $c_k = R$：此时 $b_k > a_k$，R 需要右移，同理证明 $a_k + 1$ 处必为 `X`。反设不是，则 $a_{k+1} = a_k + 1$（$k \le m-1$，因为 $a_k < b_k \le n-1$）。由 $k$ 的最小性 $d_{k+1} = 0$，即 $a_{k+1} = b_{k+1}$。于是 $b_k < b_{k+1} = a_{k+1} = a_k + 1$，得 $b_k \le a_k$，与 $b_k > a_k$ 矛盾。故 $a_k + 1$ 处为 `X`，`RX -> XR` 合法，$d_k$ 与 $D$ 各减 1。∎

**引理 4（不变量保持）**：引理 3 中的移动执行后，两条条件仍成立（对同一个 `result`）。

**证明**：移动只改动 $a_k$ 一项：$L$ 时 $a_k$ 减 1，因原来 $a_k > b_k$ 故仍有 $a_k - 1 \ge b_k$；$R$ 时 $a_k$ 加 1，因原来 $a_k < b_k$ 故仍有 $a_k + 1 \le b_k$。非 X 序列不变（引理 1），其余项不动。∎

**定理 1（充分性）**：若两串非 X 序列相同且满足条件 2，则 `start` 可变换为 `result`。

**证明**：对 $D$ 归纳。$D = 0$ 时每个 $a_k = b_k$，非 X 字符在两串中占据完全相同的下标集合，其余位置在两边都是 `X`，故 `start = result`。$D > 0$ 时由引理 3 存在合法移动使 $D$ 减 1，由引理 4 条件仍成立，归纳假设给出后续变换序列，拼接即得。∎

**定理 2（算法正确）**：双指针算法返回 `true` 当且仅当 `start` 可变换为 `result`。

**证明**：
- 返回 `true` 时：每次配对都验证了「字符相同」与「方向合法」，且两个指针同时扫完意味着非 X 字符个数相同，于是条件 1、2 全部成立，由定理 1 可变换。
- 可变换时：由推论 1 两条条件成立，算法在三处判断上都不会误报（字符必相同、方向必合法、非 X 个数必相同），故一路走到同时扫完并返回 `true`。∎

## 6. 复杂度分析

- **时间**：$O(n)$。指针 $i$、$j$ 都只增不减，各自最多走 $n$ 步；每次内层跳过与每次配对都是 $O(1)$ 判断；配对次数不超过 $n$。三者相加仍是 $O(n)$。
- **空间**：$O(1)$。只有两个指针与常数个临时变量；不构造「去 X」字符串，不建队列、哈希表或状态集合。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    bool canTransform(string start, string result) {
        int n = (int)start.size();
        int i = 0, j = 0;                 // 两个指针都保留原始下标
        while (true) {
            while (i < n && start[i] == 'X') ++i;    // 跳过 start 的 X
            while (j < n && result[j] == 'X') ++j;   // 跳过 result 的 X
            if (i == n || j == n)                    // 一方先扫完：必须双方同时到底
                return i == n && j == n;
            if (start[i] != result[j]) return false; // 非 X 序列不同，顺序被破坏
            if (start[i] == 'L' && i < j) return false;  // L 只能左移或不动
            if (start[i] == 'R' && i > j) return false;  // R 只能右移或不动
            ++i;
            ++j;
        }
    }
};
```

### Python

```python
class Solution:
    def canTransform(self, start: str, result: str) -> bool:
        n = len(start)
        i = j = 0                       # 两个指针都保留原始下标
        while True:
            while i < n and start[i] == 'X':
                i += 1
            while j < n and result[j] == 'X':
                j += 1
            if i == n or j == n:        # 一方先扫完：必须双方同时到底
                return i == n and j == n
            if start[i] != result[j]:   # 非 X 序列不同，顺序被破坏
                return False
            if start[i] == 'L' and i < j:   # L 只能左移或不动
                return False
            if start[i] == 'R' and i > j:   # R 只能右移或不动
                return False
            i += 1
            j += 1
```

## 8. 边界情况与易错点

1. **全 `X`**：两个指针立刻同时到达 $n$，返回 `true`。若 `start` 全 `X` 而 `result` 含字母，则 `j` 会停在字母上、`i == n`，返回 `false`，不会误判。
2. **没有任何 `X`**：唯一合法的「移动」是原地不动，所以只有 `start == result` 才为真。此时双指针逐位比对，天然正确。
3. **长度为 1**：单字符时最多配对一次，结果等价于 `start == result`，代码无需特判。
4. **方向反了的经典反例**：`"LXX" -> "XXL"`、`"XXR" -> "RXX"`。字符与个数全对，只有方向不对，必须返回 `false`——这是最容易漏判的一类。
5. **顺序打乱的反例**：`"LR" -> "RL"`、`"RL" -> "LR"`。只数 `L`、`R` 的个数是查不出来的，必须逐对比较字符。
6. **等长是前提**：题面保证 $\lvert \text{start} \rvert = \lvert \text{result} \rvert$。工程代码里建议先判长度（不等直接 `false`）；本文写法虽然不会越界（内层有 `i < n` 守卫），但语义上不该省略这一步。
7. **别把「不动」判成非法**：$i = j$ 是合法状态（示例配对 ④）。方向条件是两个不等式，不是严格不等式。
8. **别真的模拟移动**：若在循环里做字符串替换，最坏要走 $\Theta(n^2)$ 步、每步 $O(n)$ 复制，退化成 $O(n^3)$（极端情形：$n/2$ 个 `R` 全在最左侧、其余全是 `X`，每个 `R` 都要右移 $n/2$ 格），直接超时；本题只需要「校验」，不需要「构造」。

**延伸思考**：

1. **最少移动次数**：由 §5 的证明，答案恰好是 $D = \sum_k \lvert a_k - b_k \rvert$。下界来自「一次移动只让 $D$ 变化 1」，上界来自引理 3 的下降步——因此不必模拟就能 $O(n)$ 算出步数。
2. **如果操作可逆**（`XL <-> LX`、`RX <-> XR` 双向）：方向约束消失，条件退化为「非 X 子序列相同」，此时 `"LXX"` 与 `"XXL"` 也可互达。
3. **如果允许 `L`、`R` 直接交换**：相邻交换可以生成任意排列，于是条件只剩「`L`、`R` 的个数分别相同」，问题塌缩成计数。
4. **如果要求输出操作序列**：按引理 3「总找最小的未就位 $k$」贪心执行，每步 $O(n)$ 定位、共 $D$ 步，总 $O(nD)$。
