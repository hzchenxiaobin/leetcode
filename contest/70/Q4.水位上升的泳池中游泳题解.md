# LeetCode 水位上升的泳池中游泳 题解

## 1. 题目概述

- **标题 / 题号**：水位上升的泳池中游泳（#778，hard）
- **链接**：https://leetcode.cn/problems/swim-in-rising-water/
- **来源**：LeetCode 第 70 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、广度优先搜索、并查集、最小化最大值、数组、二分查找、矩阵、Dijkstra 算法、堆（优先队列）

**题意**：给定 $n\times n$ 的矩阵 `grid`，`grid[i][j]` 是格子 $(i,j)$ 的平台高度。时刻 $t$ 水池水位为 $t$，可以从一个平台游到**四邻**平台，当且仅当**两个平台的高度都不超过 $t$**。游泳本身不耗时（可以瞬移任意距离），所以时间只受水位限制。从 $(0,0)$ 出发，求到达 $(n-1,n-1)$ 的**最少时间**。

**约束**：

- $1 \le n \le 50$
- $0 \le \text{grid}[i][j] < n^2$，且所有值**互不相同**——于是 `grid` 恰好是 $0 \sim n^2-1$ 的一个排列
- 只能上下左右移动，不能移出矩阵

## 2. 示例

**示例 1**

```text
输入：grid = [[0,2],[1,3]]
输出：3
解释：t = 0 时你站在 (0,0)，四个方向的平台都高于水位 0，哪也去不了；
      等水位涨到 3，全图都被淹没，才可以游到 (1,1)。所以首次到达的时刻是 3。
```

**示例 2**

```text
输入：grid = [[0,1,2,3,4],[24,23,22,21,5],[12,13,14,15,16],[11,17,18,19,20],[10,9,8,7,6]]
输出：16
解释：必须等到 t = 16，(0,0) 与 (4,4) 才处在同一个连通块里；
      t = 15 时它们仍分属两块（见 3.4 节的走查）。
```

## 3. 解题思路

### 3.1 暴力思路

顺着题意直接做，有三条路，都不合适：

1. **枚举所有路径**，对每条路径算「路径上最大高度」再取最小。$n=50$ 时简单路径数量是指数级的，完全不可行。
2. **让水位从 0 开始一格一格涨**，每个 $t$ 都做一次 BFS 判断连通。单次 BFS 是 $O(n^2)$，最多 $n^2$ 个时刻，总计 $O(n^4)=6.25\times10^6$ 次格子访问——在 $n\le 50$ 的数据上勉强能过，但完全没有利用「答案可以一次算出」的结构。
3. **把高度当成边权求最短路（求和）**——这是最容易踩的坑。求和与「取最大」的最优路线可以不同：取

$$\text{grid} = \begin{bmatrix} 0 & 1 & 2 \\ 3 & 4 & 7 \\ 8 & 6 & 5 \end{bmatrix}$$

高度和最小的路线是 $0 \to 1 \to 2 \to 7 \to 5$，和为 15，但它的**瓶颈**是 7；而路线 $0 \to 3 \to 4 \to 6 \to 5$ 高度和为 18，瓶颈只有 6。正确答案是 **6**，求和版会给出 7。

### 3.2 核心观察：答案是「瓶颈路」上的最大高度

![把高度看作格子代价的瓶颈路](images/wc70_q4_bottleneck_path.svg)

固定水位 $t$，记可踩格子的集合为

$$S_t = \{(i,j) : \text{grid}[i][j] \le t\}$$

那么「$t$ 时刻能否到达终点」就等价于「起点与终点在诱导子图 $S_t$ 中是否连通」。$S_t$ 随 $t$ 只增不减，所以存在一个**临界水位** $t^\star$：$t \ge t^\star$ 可达、$t < t^\star$ 不可达，它就是要返回的答案。

把「连通」翻译成「存在一条路径」：$t$ 时刻可达 $\iff$ 存在路径 $P$ 使 $\max_{v\in P} h(v) \le t$。于是最小的可行时刻为

$$t^\star = \min_{P} \max_{v \in P} h(v)$$

其中 $P$ 取遍所有从左上到右下的四邻路径。这就是经典的**瓶颈最短路（minimax path / 最小化最大值）**：代价不再是求和，而是取路径上的最大值。

### 3.3 算法流程：把 Dijkstra 的加法换成取最大值

![Dijkstra 流程：加法换成 max](images/wc70_q4_dijkstra_flow.svg)

令 $b[v]$ 表示从起点到 $v$ 的所有路径中「最大高度」的最小值，则 $b$ 满足

$$b[v] = \min_{u \sim v} \max\bigl(b[u],\ h(v)\bigr), \qquad b[(0,0)] = h(0,0)$$

这个式子与普通最短路只差一个运算符，但 $\min$ 与 $\max$ 的性质足够好，堆优化的贪心框架可以原样保留：

1. **初始化**：$b[(0,0)] = h(0,0)$，其余为 $+\infty$；小根堆放 $(h(0,0), 0, 0)$。
2. **弹出堆顶** $(d,i,j)$：若 $d > b[i][j]$，说明是过期堆项，直接丢弃。
3. **终点判定**：若 $(i,j)$ 是终点，立刻返回 $d$——首次出堆即终值。
4. **松弛**：对四个邻居 $v$，令 $nd = \max(d, h(v))$；若 $nd < b[v]$，更新并入堆。
5. **结束**：若堆空仍未到终点（网格四连通，实际不会发生），返回 $b[(n-1,n-1)]$。

**两条等价路线**（同样的正确性，任选其一实现）：

- **二分答案**：在 $[\,\max(h(0,0), h(n-1,n-1)),\ n^2-1\,]$ 上二分水位 $T$，判定函数就是「只走 $h \le T$ 的格子能否从起点泛洪到终点」。
- **并查集按高度激活**：把格子按高度升序逐个「激活」，每次与已激活的四邻合并；起点与终点第一次属于同一集合时的高度就是答案。

![二分阈值、泛洪判定与三种实现](images/wc70_q4_binary_search_flood.svg)

三种写法的时间复杂度都在 $O(n^2\log n)$ 量级（并查集版是 $O(n^2\alpha)$），$n\le 50$ 时全部轻松通过，选自己写起来最稳的一种即可。

### 3.4 示例演算

![示例 2 的连通块演化与瓶颈路线](images/wc70_q4_walkthrough.svg)

先看示例 1：$t=0$ 时 $S_0=\{0\}$，只有起点；$t=1$ 时 $S_1=\{0,1\}$；$t=2$ 时 $S_2=\{0,1,2\}$，终点高度 3 还没被淹没；$t=3$ 时全图连通，答案 3。两条候选路线的瓶颈都是 3。

再看示例 2（$n=5$），水位上涨时连通块的变化：

| 水位 $t$ | 新淹没的关键格子 | $S_t$ 的连通块 | 能到 $(4,4)$？ |
|:---:|:---|:---|:---:|
| 4 | 顶行 $0,1,2,3,4$ 连成一条 | $A=\{0,1,2,3,4\}$ | 否 |
| 5 | $(1,4)=5$ 接在 4 下方 | $A=\{0,\dots,5\}$ | 否 |
| 11 | $(3,0)=11$ 接上底行的 $6\sim10$ | $A$；$B=\{6,\dots,11\}$ | 否 |
| 15 | $(2,0)\sim(2,3)=12\sim15$ 沿第三行接上 11 | $A$；$B=\{6,\dots,15\}$ | 否 |
| 16 | $(2,4)=16$ 同时挨着 5 和 15 | $A$ 与 $B$ 合并 | **是** |

关键就是 16 号格：在所有高度 $\le 16$ 的格子里，只有它同时邻接 $A$（上方的 5）与 $B$（左方的 15），因此它一到就能把两块桥接起来，$t^\star=16$。取瓶颈为 16 的那条路线

$$0\to1\to2\to3\to4\to5\to16\to15\to14\to13\to12\to11\to10\to9\to8\to7\to6$$

路径上最大值恰好是 16，与下界（$t=15$ 不可达）吻合。

## 4. 算法细节

1. **顶点权重挂到边上**：代价在格子上，把边 $u\to v$ 的权定义为 $h(v)$，并把起点初值设为 $h(0,0)$。这样路径代价 $\max\bigl(h(0,0), w_1,\dots,w_k\bigr)=\max_{v\in P}h(v)$，不会漏掉起点。
2. **松弛式不能写成加法**：必须用 $b[v] \leftarrow \min\bigl(b[v], \max(d, h(v))\bigr)$。若按普通最短路写成 $b[u]+h(v)$，就会挑中 3.1 中那条瓶颈为 7 的路线，答案错成 7。
3. **小根堆的写法**：C++ 用 `priority_queue<tuple<int,int,int>, vector<...>, greater<...>>`；不要用默认大根堆再存负值，容易把 max 与「取反」的符号搞错。Python 直接用 `heapq`。
4. **惰性删除**：同一格子可能被多次松弛，旧项弹出时 $d > b[u]$，`continue` 丢弃即可；这保证每个格子只在其终值那一次真正扩展邻居。
5. **提前返回**：终点第一次出堆就可以返回 $d$。由引理 3 它已是终值，继续跑完整个堆只是浪费。
6. **二分版的下界与判定**：答案必 $\ge \max(h(0,0), h(n-1,n-1))$，把 $lo$ 直接设成它；判定用显式队列/栈 + `visited` 数组，避免 $n=50$ 时 2500 层递归把 Python 栈打爆。
7. **并查集版的顺序**：格子按高度升序排序后逐个激活，激活时与「已激活」的四邻合并，合并完成后再检查起点终点是否同根；$n=1$ 时起点即终点，答案就是 $h(0,0)$。
8. **不能用 `visited` 代替 $b$**：普通 BFS 里「第一次访问即最短」，但这里第一次到达某格的瓶颈不一定最优（可能先被一条高瓶颈的路碰到），必须比较 $nd < b[v]$ 才能更新。

## 5. 正确性证明

**引理 1（可达性单调）**：若在时刻 $t$ 能从起点到达终点，则对任意 $t' \ge t$ 也能到达。

**证明**：设 $P$ 是 $t$ 时刻的一条可行路径，则 $P$ 上每个格子 $v$ 都满足 $h(v) \le t \le t'$，所以 $P$ 在 $t'$ 时刻依然全程可踩，其中每步都是四邻移动，故 $t'$ 时刻同样可达。∎

**引理 2（阈值刻画）**：$t$ 时刻可达 $\iff$ 存在路径 $P$ 使 $\max_{v\in P} h(v) \le t$。

**证明**：

- ($\Rightarrow$) 取 $t$ 时刻实际可行的一条路径 $P$，逐格都在 $S_t$ 中，即 $h(v)\le t$，故 $\max_{v\in P}h(v)\le t$。
- ($\Leftarrow$) 若某条路径 $P$ 满足 $\max_{v\in P}h(v)\le t$，则 $P$ 的每个格子都属于 $S_t$，沿 $P$ 逐格游动合法，故可达。∎

**推论**：记 $t^\star=\min_P \max_{v\in P} h(v)$，则 $t^\star$ 是最小可行水位。

**证明**：对 $t=t^\star$，取达到最小值的路径 $P^\star$，由引理 2 可达。若 $t<t^\star$，任取路径 $P$ 都有 $\max_{v\in P}h(v)\ge t^\star>t$，由引理 2 的逆否命题不可达。故 $t^\star$ 是最小可行水位。∎

**引理 3（出堆即终值）**：算法中每次弹出的 $(d,u)$ 都满足 $d=b[u]$，即 $b[u]$ 已经是 $u$ 的最终最优值。

**证明**：对出堆顺序归纳。堆中的每个键都来自一条**真实存在**的路径，故键 $\ge b[\cdot]$（键是真实值的上界），于是 $d \ge b[u]$ 恒成立——键是一条真实路径的瓶颈，不可能小于最优值。

再证 $d \le b[u]$。反设 $b[u] < d$，取达到 $b[u]$ 的最优路径 $P$，沿 $P$ 从起点走，设 $w$ 是 $P$ 上第一个尚未出堆的顶点，$p$ 是它在 $P$ 上的前驱。起点的键 $h(0,0)\le b[u]<d$，必在 $u$ 之前出堆，故 $p$ 已出堆；由归纳假设 $p$ 出堆时其键正是 $b[p]$，而此后 $b[w]$ 只会更小，所以堆中必存在 $w$ 的键

$$K(w) \le \max\bigl(b[p], h(w)\bigr) \le \max_{v\in P} h(v) = b[u] < d$$

（若 $p$ 的松弛没有改进 $b[w]$，则堆里早已有更小的键；$w$ 尚未出堆，它的键一定还在堆里。）这与「$d$ 是堆中最小键」矛盾。故 $d \le b[u]$，结合上一条得 $d=b[u]$。∎

**定理**：`swimInWater` 返回的值等于 $\min_P \max_{v\in P}h(v)$，即题目要求的最少时间。

**证明**：由引理 3，终点第一次出堆时 $d=b[(n-1,n-1)]$；而 $b[(n-1,n-1)]$ 按定义为「从起点到终点的所有路径中最大高度的最小值」，正是 $\min_P\max_{v\in P}h(v)$。再由推论，该值等于最小可行水位，即所需的最少时间。∎

## 6. 复杂度分析

- **时间**：$O(n^2\log n)$。每个格子最多被松弛若干次但 $b$ 严格递减，堆中元素 $O(n^2)$ 个，每次堆操作 $O(\log n^2)=O(\log n)$；松弛总数 $4n^2$。二分版是 $O(\log n)$ 轮 × 每轮 $O(n^2)$ 泛洪，同为 $O(n^2\log n)$；并查集版排序 $O(n^2\log n)$、合并近似线性。实测 $n=50$ 时松弛约 $10^4$ 次，两种语言都在毫秒级。
- **空间**：$O(n^2)$。`best` 矩阵 $n^2$ 个整数，堆最坏 $O(n^2)$ 项，访问数组同样 $n^2$；$n=50$ 时约 2500 个格子，常数极小。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <tuple>
#include <algorithm>
using namespace std;

class Solution {
public:
    int swimInWater(vector<vector<int>>& grid) {
        int n = grid.size();
        const int INF = 1 << 30;
        vector<vector<int>> best(n, vector<int>(n, INF));
        // 小根堆：(瓶颈值, 行, 列)
        priority_queue<tuple<int, int, int>,
                       vector<tuple<int, int, int>>,
                       greater<tuple<int, int, int>>> pq;
        best[0][0] = grid[0][0];
        pq.push({grid[0][0], 0, 0});
        int dirs[4][2] = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};
        while (!pq.empty()) {
            auto [d, i, j] = pq.top();
            pq.pop();
            if (d > best[i][j]) continue;          // 过期堆项
            if (i == n - 1 && j == n - 1) return d; // 首次出堆即最优
            for (auto& dir : dirs) {
                int ni = i + dir[0], nj = j + dir[1];
                if (ni < 0 || ni >= n || nj < 0 || nj >= n) continue;
                int nd = max(d, grid[ni][nj]);      // 加法换成取最大值
                if (nd < best[ni][nj]) {
                    best[ni][nj] = nd;
                    pq.push({nd, ni, nj});
                }
            }
        }
        return best[n - 1][n - 1];
    }
};
```

### Python

```python
import heapq


class Solution:
    def swimInWater(self, grid: list[list[int]]) -> int:
        n = len(grid)
        INF = float('inf')
        best = [[INF] * n for _ in range(n)]
        best[0][0] = grid[0][0]
        pq = [(grid[0][0], 0, 0)]          # (瓶颈值, 行, 列)
        while pq:
            d, i, j = heapq.heappop(pq)
            if d > best[i][j]:            # 过期堆项
                continue
            if i == n - 1 and j == n - 1: # 首次出堆即最优
                return d
            for di, dj in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                ni, nj = i + di, j + dj
                if 0 <= ni < n and 0 <= nj < n:
                    nd = max(d, grid[ni][nj])   # min-max 松弛
                    if nd < best[ni][nj]:
                        best[ni][nj] = nd
                        heapq.heappush(pq, (nd, ni, nj))
        return best[n - 1][n - 1]
```

## 8. 边界情况与易错点

1. **$n=1$**：起点就是终点，答案 $h(0,0)$（约束下必为 0）。代码里初值已覆盖，弹出时直接返回，不要额外特判成 $-1$。
2. **起点高度不是 0**：若把 $b[(0,0)]$ 初始化成 0 而不是 $h(0,0)$，会低估答案；答案是「路径最大值」，起点本身也算在内。
3. **终点高度很高**：答案必然 $\ge h(n-1,n-1)$，这一点由「取 max 覆盖终点」自动保证，不需要单独判断。
4. **求和与取最大混淆**：见 3.1 的反例，$[[0,1,2],[3,4,7],[8,6,5]]$ 的正确答案是 6，求和最短路给 7。写完代码务必用这类小数据对拍。
5. **首次访问当最短**：本题不能像无权 BFS 那样「访问过就跳过」，必须用 $b$ 值比较；漏掉这一点会在环路上丢掉更优瓶颈。
6. **堆里没有更新标记**：直接改 $b$ 而不把新值入堆，会让堆里永远是旧值；正确做法是「改 $b$ + 入堆」，靠出堆时的 $d>b[u]$ 过滤。
7. **二分边界**：循环条件写 $lo < hi$、更新 $hi=mid$，返回 $lo$；若用 $lo\le hi$ 且 $hi=mid$ 会死循环，写成 $mid+1$ 又可能漏掉正确答案。
8. **并查集检查时机**：必须先合并再判连通；若激活 $v$ 后先判连通再合并，$n=1$ 或相邻两个格子直接连通时会漏判。
