# LeetCode 拆分二叉搜索树 题解

## 1. 题目概述

- **标题 / 题号**：拆分二叉搜索树（#776，medium）
- **链接**：https://leetcode.cn/problems/split-bst/
- **来源**：LeetCode 第 70 场周赛 Q2
- **难度**：中等
- **标签**：树、二叉搜索树、递归、二叉树

**题意**：给定一棵**二叉搜索树** `root` 与目标值 `V`，把它拆成两棵子树：一棵只含**小于等于** `V` 的节点，另一棵只含**大于** `V` 的节点，返回两棵子树的根（**顺序任意**）。`V` 不必是树中已有的值。

题面还附加了一条**结构约束**：对原树中任意一对父子 `(P, C)`，如果二者被分到同一棵子树，那么 `C` 在结果中**必须仍以 `P` 为父节点**——即「尽量少改动结构」，不允许随便重建。

**约束**：

- BST 大小不超过 $50$（$1 \le n \le 50$）
- 输入始终是**合法 BST**，且所有节点的值**互不相同**
- 可以假设 `target` 为整数；`target` 可能小于最小值、大于最大值，或等于某个节点值

**接口**：`vector<TreeNode*> splitBST(TreeNode* root, int target)`，返回长度为 2 的数组（Python 返回长度为 2 的 list）。

## 2. 示例

**示例 1**

```text
输入：root = [4,2,6,1,3,5,7]，V = 2
输出：[[2,1],[4,3,6,null,null,5,7]]
解释：小树 = 2 带着左孩子 1（2→1 保留，2→3 被剪断）；
      大树 = 4 带着左孩子 3、右孩子 6，而 6 仍带着 5 与 7，
      即 4 的左指针改指 3，4→2、2→3 两条边断开。
```

**示例 2**

```text
输入：root = [1]，V = 1
输出：[[1],[]]
解释：唯一节点 1 ≤ 1，落在小树；大树为空。
```

**示例 3**（补充：`V` 不在树中）

```text
输入：root = [5,3,8,1,4,7,9]，V = 6
输出：[[5,3,null,1,4],[8,7,9]]
解释：6 不是树中的值。小树仍是原树的左侧部分（5 带着 3），
      大树是 8 带着 7、9；5→8 这条边被剪断，没有产生新边。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：遍历整棵树收集所有节点，按值分成两组，然后**在每组内部重新插入建 BST**。单次插入 $O(h)$，总 $O(n \log n)$ 甚至 $O(n^2)$（退化成链时）。

问题不在于复杂度，而在于它**不满足题目的结构约束**：重新插入会把父子关系全部重排，比如示例 1 中 `6` 与 `5`、`7` 的关系、`4` 与 `6` 的关系虽可能巧合保持，但只要键的插入顺序一变就会漂移。要「重建后再验证结构约束」，就得枚举形状，$n = 50$ 时不可能。

真正的瓶颈是：**拆分需要同时给出两棵树的根，而普通递归只能返回一个值**。破解这一点，就得到一条 $O(n)$ 的极简递归。

### 3.2 核心观察：把「剪边」变成递归的二元组

![按 target 剪开 BST](images/wc70_q2_split_concept.svg)

把「拆分」看成**剪边**：值域被 `V` 切成两段，原树的每条父子边要么连接同侧节点（保留），要么跨越分界线（剪断）。剪断后，两侧各留下若干个连通块，而**每个连通块内部的结构已经确定**——同侧父子边一根都不许动。

于是问题只剩「如何把各连通块按 BST 顺序串起来」。观察根节点 $u$：

- 若 $u.\text{val} \le V$：$u$ 属于小树，$u$ 的**整棵左子树**值都 $< u.\text{val} \le V$，全部属于小树且原样不动；只有**右子树**可能跨侧，需要继续切。
- 若 $u.\text{val} > V$：$u$ 属于大树，其**右子树**全部 $> u.\text{val} > V$，原样不动；只有**左子树**需要继续切。

所以每层只需递归**一个孩子**，并让递归返回**一对根**：

$$\text{split}(u)=\begin{cases}(\text{null},\ \text{null}), & u=\text{null}\\[2pt] (u,\ b)\ \text{其中}\ (a,b)=\text{split}(u.\text{right}),\ u.\text{right}\leftarrow a, & u.\text{val}\le V\\[2pt] (a,\ u)\ \text{其中}\ (a,b)=\text{split}(u.\text{left}),\ u.\text{left}\leftarrow b, & u.\text{val}> V\end{cases}$$

![返回二元组 (小树根, 大树根) 的语义](images/wc70_q2_return_pair.svg)

二元组的语义是**全局统一**的：`(小树根, 大树根)`，左边永远 $\le V$、右边永远 $> V$。因此父层拿到返回值后可以无脑使用：

- $u.\text{val} \le V$ 时，把递归回来的**小半边** `a` 接成 `u.right`，自己连同 `a` 作为本层的小树根，把 `b` 原封不动上交；
- $u.\text{val} > V$ 时，把递归回来的**大半边** `b` 接成 `u.left`，自己作为大树根上交 `a`。

> 💡 直觉：跨侧断边处，父层把「对面那一侧最靠上的节点」接回自己的空指针——这正是「最近同侧祖先」接管，结构改动降到最低。

### 3.3 算法流程

![递归流程](images/wc70_q2_recursion_flow.svg)

1. **递归基**：`root == null` 时返回 `(null, null)`。
2. **比较**：`root.val <= V` 走左分支，否则走右分支。
3. **左分支**（根归小树）：`(a, b) = split(root.right)`；`root.right = a`；返回 `(root, b)`。
4. **右分支**（根归大树）：`(a, b) = split(root.left)`；`root.left = b`；返回 `(a, root)`。
5. **回溯**：调用栈回到根，直接返回这一对根（顺序为 `[小树, 大树]`，题面允许任意顺序）。
6. **原地拆分**：全程不 `new` 新节点，只改指针，原树结构被「复用来」当作结果。

一句话版本：**沿比较方向一路下钻到空树，回溯时把「同侧的那一半」接回自己的空指针。**

### 3.4 示例演算

![示例走查](images/wc70_q2_walkthrough.svg)

对 `root = [4,2,6,1,3,5,7]`、`V = 2`，递归只走一条链（$4 \to 2 \to 3 \to \text{null}$）：

| 递归调用 | 比较 | 递归方向 | 本层返回 (小, 大) | 回溯挂接 |
|----------|------|----------|-------------------|----------|
| `split(4)` | $4 > 2$ | 左子 `2` | `(2, 4)` | `4.left ← 3` |
| `split(2)` | $2 \le 2$ | 右子 `3` | `(2, 3)` | `2.right ← null` |
| `split(3)` | $3 > 2$ | 左子 `null` | `(null, 3)` | `3.left ← null` |
| `split(null)` | — | — | `(null, null)` | 无改写 |

自底向上装配：

1. `split(3)`：3 归大树，左子树为空，返回 `(null, 3)`。
2. `split(2)`：2 归小树，把小半边 `null` 接成 `2.right`（原来的 3 被摘走），返回 `(2, 3)`。
3. `split(4)`：4 归大树，把大半边 `3` 接成 `4.left`，返回 `(2, 4)`。
4. 最终结果：小树 `[2,1]`，大树 `[4,3,6,null,null,5,7]`，与官方输出一致。

注意 `6`、`5`、`7` 三个节点整条支路**一次都没被访问**——它们全都 $> V$，在 `split(4)` 处被原样保留，这正是 $O(n)$ 的来源。

## 4. 算法细节

1. **比较符号必须是 `<=`**：题意是「一棵子树里所有节点**小于等于** `V`」，等于 `V` 的节点归**小树**。写成 `<` 会让等于 `V` 的节点跑到大树，示例 2（`[1], V=1`）立刻出错。
2. **每层只递归一个孩子**：左分支只碰 `right`，右分支只碰 `left`；另一侧整棵子树直接跟随根节点归属，既省时间也保证了「结构不动」。
3. **先取返回值、再改写指针**：必须写成 `(a, b) = split(root.right); root.right = a`。若先写 `root.right = ...` 再递归，递归入口拿到的是已被改写的指针，会丢子树。
4. **返回值的顺序要自洽**：本层返回 `(root, b)` 还是 `(a, root)`，取决于谁当小树根。两种情形都必须保持「第一个是小树、第二个是大树」，否则父层接错边。
5. **递归基返回 `(null, null)`**：空树的「小半边」「大半边」都为空，这样上层可以直接用返回值，不需要额外判空分支。
6. **原地拆分、零拷贝**：所有节点都从原树复用，指针只是重新指向；不 `new`、不复制、不删除，因此额外堆空间是 $O(1)$。
7. **顺序任意但建议固定**：题面说「in any order」，实际评测按数组顺序比较，统一用 `[小树, 大树]` 最稳。
8. **不需要显式断链**：把 `u.right` 改成递归回来的 `a`（可能是 `null`）时，跨侧的旧边就自然被覆盖掉了，不必先写 `u.right = null`。

## 5. 正确性证明

记 $\text{sub}(u)$ 为原树中以 $u$ 为根的子树，$\text{keys}(u)$ 为其键集合。对「子树高度」做归纳。

**引理 1（节点集正确划分）**：`split(u)` 返回的二元组 $(S, R)$ 满足 $S$ 恰含 $\text{keys}(u)$ 中所有 $\le V$ 的键，$R$ 恰含所有 $> V$ 的键，且每个键恰好出现一次。

**证明**：$u = \text{null}$ 时两边皆空，成立。设 $u.\text{val} \le V$。由 BST 性质，$\text{keys}(u) = \text{keys}(u.\text{left}) \cup \{u.\text{val}\} \cup \text{keys}(u.\text{right})$，其中左子树键 $< u.\text{val} \le V$ 全在小树、右子树键 $> u.\text{val}$ 可能跨侧。由归纳假设，`split(u.right)` 返回的 $(a,b)$ 精确划分 $\text{keys}(u.\text{right})$，于是小树 $= \text{keys}(u.\text{left}) \cup \{u.\text{val}\} \cup \text{keys}(a)$ 恰为全部 $\le V$ 的键，大树 $= \text{keys}(b)$ 恰为全部 $> V$ 的键，且三者不重不漏。$u.\text{val} > V$ 情形对称。∎

**引理 2（结果仍是合法 BST）**：`split(u)` 返回的两棵树各自满足 BST 性质。

**证明**：仍设 $u.\text{val} \le V$。小树的根是 $u$，左孩子是原 `u.left`（键 $< u.\text{val}$，且由归纳假设其内部有序），右孩子是 $a$；而 $\text{keys}(a) \subseteq \text{keys}(u.\text{right})$ 且 $\text{keys}(a) \subseteq (V, +\infty)$，故 $a$ 中每个键都 $> u.\text{val}$，两侧区间与 $u.\text{val}$ 严格分离，BST 性质在根处成立；由归纳假设 $a$ 内部也是 BST，其它部分（`u.left`）未被改动，故整个小树是 BST。大树 $b$ 由归纳假设已是 BST。另一情形完全对称。∎

**观察（根的身份）**：`split(T)` 返回的**小树根恰是** $T$ 中最浅的 $\le V$ 节点，**大树根恰是** $T$ 中最浅的 $> V$ 节点。

**证明**：设 $T$ 的根为 $r$。若 $r$ 属于该侧，递归直接返回 $r$，它当然是最浅的；若 $r$ 属于另一侧，则 $r$ 的另一棵子树整体落在 $r$ 的同一侧（$r \le V$ 时右子树键全 $> r$ 可能跨侧、左子树键全 $< r \le V$ 必属小树；$r > V$ 时对称），不可能含本侧节点，只能继续往唯一可能的那棵子树里找。对高度归纳即得。∎

**引理 3（结构保持）**：`split(u)` 保留原树中所有**同侧**父子边；跨侧边被剪断，剪断处由「离该节点最近的同侧祖先」接管，每层最多新增一条桥边。

**证明**：对高度归纳。设 $u.\text{val} \le V$，考察 $u$ 的两个孩子。

- 同侧孩子 $c$：因 $c$ 是 $\text{sub}(c)$ 中最浅的节点且属于本侧，由观察，`split(c)` 返回的本侧根**就是 $c$**，故边 $(u,c)$ 保留。特别地 $c = u.\text{left}$ 时其键 $< u.\text{val} \le V$ 必属小树，一定保留。
- 跨侧孩子 $c = u.\text{right}$（$c.\text{val} > V$）：`split(c)` 返回 $(a,b)$，其中 $a$ 是小树根。由观察，$a$ 恰是 $\text{sub}(c)$ 中最浅的 $\le V$ 节点。把 $a$ 接成 `u.right`，就是让 $u$ 成为 $a$ 的父节点；而 $u$ 是 $a$ 在原树中的祖先，且 $u.\text{val} \le V$、$u$ 与 $a$ 之间无其它 $\le V$ 节点，故 $u$ 正是 $a$ 最近的同侧祖先。

因此除跨侧边外没有改动任何父子关系，新增边的父端也被唯一确定。∎

**定理**：`split(root)` 返回的两棵子树满足题面全部要求：节点按 `V` 正确二分、两棵都是合法 BST、原树中所有同侧父子关系保持不变。

**证明**：由引理 1，节点集划分为 $\le V$ 与 $> V$ 两组，不重不漏；由引理 2，两棵结果都是合法 BST；由引理 3，原树所有同侧父子边都被保留，即「同处一棵子树的父子，其父子关系不变」。三条合起来正是题面要求的全部条件。∎

**推论（改动最小）**：任何合法方案都**必须**断开全部跨侧边（跨侧的两个节点分属两棵树，不可能保持父子关系），也**必须**保留全部同侧边；自由度只在于断点如何重新挂接。本方案新增的桥边数恰等于跨侧断点数，且每条桥边的父端取最近的同侧祖先，不引入任何额外的深度增长，因而已是该自由度下的最小改动。

**证明**：桥边只在 $u$ 与 $a$（或 $b$）之间新增，一个跨侧断点对应一条桥边，不多不少；父端 $u$ 是 $a$ 最近的同侧祖先，由引理 3 唯一确定。若把 $a$ 改挂到别的节点，要么违反 BST 序，要么割断本应保留的同侧边，改动只会更大。∎

> 📌 题面只约束「同侧父子关系不动」，并未禁止其它挂法（例如某侧只剩两个键时，根的选择在 BST 意义上仍有自由度）。本题递归给出的是「每个节点挂到最近的同侧祖先」这一**规范答案**，也正是官方期望输出。

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点只被访问一次：进入时做一次比较与一次递归，回溯时做一次指针赋值，全是 $O(1)$ 操作。注意递归只沿**单条比较方向**下钻，另一侧子树被整块保留、根本不进入递归。
- **空间**：$O(h)$，$h$ 为树高，来自递归调用栈；最好（平衡）$O(\log n)$，最坏（退化成链）$O(n)$，本题 $n \le 50$ 完全安全。
- **额外堆空间**：$O(1)$。全程复用原有节点、只改指针，没有新建或拷贝节点；返回的两个根就是原树节点本身。
- **下界**：必须先读到每个节点的值才能判断归属，因此 $\Omega(n)$ 是最优；本算法达到该下界（剪枝使得实际常数更小，等于「跨侧路径上的节点数 $+1$」）。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    vector<TreeNode*> splitBST(TreeNode* root, int target) {
        if (!root) return {nullptr, nullptr};          // 空树：两边都空

        if (root->val <= target) {                     // 根留在小树
            vector<TreeNode*> sub = splitBST(root->right, target);
            root->right = sub[0];                      // 小半边接回右指针
            return {root, sub[1]};                     // 大半边交给父层
        } else {                                       // 根留在大树
            vector<TreeNode*> sub = splitBST(root->left, target);
            root->left = sub[1];                       // 大半边接回左指针
            return {sub[0], root};                     // 小半边交给父层
        }
    }
};
```

### Python

```python
class Solution:
    def splitBST(self, root: 'TreeNode', target: int) -> list:
        if root is None:                       # 空树：两边都空
            return [None, None]

        if root.val <= target:                 # 根留在小树
            small, big = self.splitBST(root.right, target)
            root.right = small                 # 小半边接回右指针
            return [root, big]                 # 大半边交给父层
        else:                                  # 根留在大树
            small, big = self.splitBST(root.left, target)
            root.left = big                    # 大半边接回左指针
            return [small, root]               # 小半边交给父层
```

## 8. 边界情况与易错点

1. **`target` 小于所有值**：整棵树都属于大树，小树为 `null`。例如 `[1,null,2]`、`target = 0` → `[[], [1,null,2]]`。
2. **`target` 不小于最大值**：整棵树都属于小树，大树为 `null`。例如 `[10]`、`target = 99` → `[[10], []]`。
3. **`target` 恰为根的值**：根归小树，`root.right` 整体进入大树。例如 `[4,2,6,1,3,5,7]`、`target = 4` 时小树是 `4` 带着左子树，大树是 `6(5,7)`。
4. **`target` 不在树中**：比较结果依然明确（要么 `≤` 要么 `>`），算法无需任何特判；但断边处不会产生新边（见示例 3）。
5. **指针改写顺序**：`(a, b) = split(root.right)` 必须在 `root.right = a` **之前**完成；反过来写会先丢失右子树，导致结果缺节点。
6. **误用 `<` 而非 `<=`**：等于 `target` 的节点会被分到大树，示例 2 直接 WA。
7. **返回顺序写反**：某层返回 `(big, root)`、另一层返回 `(root, big)`，会导致父层把小树接进大树，最终两棵树都非法。
8. **试图深拷贝**：题目接受原地拆分，节点复用即可；若为了「不破坏原树」而拷贝，会变成 $O(n)$ 额外空间，且没必要（原树在拆分后本来就应被消耗）。
9. **递归深度**：$n \le 50$ 时最坏 50 层，安全；若把题目数据扩展到 $10^5$ 的链，则需改写成显式栈的迭代版本。

- [LeetCode 450. 删除二叉搜索树中的节点](https://leetcode.cn/problems/delete-node-in-a-bst/)：删除同样要「改结构但不重排」，递归返回新子树根的套路与本篇同源。
- [LeetCode 701. 二叉搜索树中的插入操作](https://leetcode.cn/problems/insert-into-a-binary-search-tree/)：反过来「接上一条边」，与本题的「断开一条边」互为镜像。
- [LeetCode 1382. 将二叉搜索树变平衡](https://leetcode.cn/problems/balance-a-binary-search-tree/)：先中序展开、再重建，对比本题「不重建」的取舍。
- [LeetCode 1038. 从二叉搜索树到更大和树](https://leetcode.cn/problems/binary-search-tree-to-greater-sum-tree/)：另一场周赛（第 135 场）的 Q2 树题，示范了「后序回溯中改指针」的写法。

**延伸思考**：

1. **切成 $k$ 份**：给定 $k-1$ 个分界值，让递归返回长度为 $k$ 的指针数组，每层按自己落在哪一段决定把哪个孩子往下切——这正是 Treap 中 `split` 的多元版本。
2. **与 Treap 的 split 对比**：Treap 按 key 拆分时也返回两个根，但因为堆序（随机优先级）额外约束了形状，结果**唯一**；本题没有堆序，只有「同侧边不动」的弱约束，所以递归给出的答案是一种规范选择。
3. **改成按节点数拆分**：把比较换成「左子树大小与 `k` 的关系」，就得到按排名（rank）拆分，可用于「求第 k 小」「区间翻转」等平衡树操作。
4. **若允许重排**：去掉结构约束后，只需按键集重建任意合法 BST（例如取中位数为根建平衡树），复杂度仍是 $O(n)$，但父子关系会大变——这也说明结构约束才是本题真正的难点。
