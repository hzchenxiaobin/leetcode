# LeetCode 最长公共后缀查询 题解

## 1. 题目概述

- **标题 / 题号**：最长公共后缀查询（#3093，hard）
- **链接**：https://leetcode.cn/problems/longest-common-suffix-queries/
- **来源**：LeetCode 第 390 场周赛 Q4
- **难度**：困难
- **标签**：字典树（Trie）、字符串、数组

**题意**：给定字符串数组 `wordsContainer` 与 `wordsQuery`。对每个查询 `wordsQuery[i]`，在 `wordsContainer` 中找与其**最长公共后缀**最长的字符串；若并列，取**长度最短**者；仍并列，取**下标最小**者。返回所有查询对应的下标数组 `ans`。

**约束**：

- $1 \le \text{wordsContainer.length}, \text{wordsQuery.length} \le 10^4$
- $1 \le \text{wordsContainer}[i].\text{length}, \text{wordsQuery}[i].\text{length} \le 5 \times 10^3$
- 两数组各自的总字符数不超过 $5 \times 10^5$
- 所有字符串只含小写英文字母

> 💡 两条「总长」限制是复杂度的风向标：允许**线性**遍历全部字符，但任何「查询 × 容器词」两两配对的平方级做法都会超时。

## 2. 示例

**示例 1**

```text
输入：wordsContainer = ["abcd","bcd","xbcd"], wordsQuery = ["cd","bcd","xyz"]
输出：[1,1,1]

解释：
"cd"  与三个词的公共后缀均为 "cd"（长 2），并列取最短的 "bcd"（下标 1）；
"bcd" 与三个词的公共后缀均为 "bcd"（长 3），仍取 "bcd"（下标 1）；
"xyz" 与任何词都无公共后缀（长 0），全体并列，取全局最短 "bcd"（下标 1）。
```

**示例 2**

```text
输入：wordsContainer = ["abcdefgh","poiuygh","ghghgh"], wordsQuery = ["gh","acbfgh","acbfegh"]
输出：[2,0,2]

解释：
"gh"      三个词都以 "gh" 结尾（长 2 并列），取最短的 "ghghgh"（下标 2）；
"acbfgh"  只有 "abcdefgh" 与它有长 3 的公共后缀 "fgh"（其余仅 "gh"），取下标 0；
"acbfegh" 三个词的公共后缀均为 "gh"（长 2，因倒数第三位 e 与 f / y / h 均不同），取下标 2。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询 $q$ 与每个容器词 $u$，从尾部双指针求 $|\mathrm{lcsuf}(q, u)|$，单对代价 $O(|q| + |u|)$。总时间为

$$O\Big(\sum_{q} \sum_{u} (|q| + |u|)\Big) = O\big(n_q \cdot S_C + n_c \cdot S_Q\big)$$

其中 $S_C, S_Q$ 是两数组的总字符数。最坏 $10^4 \times 5\times 10^5 = 5\times 10^9$，必然超时。瓶颈在于：**同一批容器词的后缀信息被每个查询重复扫描**——需要把「后缀」预先组织成可共享查询的结构。

### 3.2 核心观察：后缀匹配 = 倒序前缀匹配

把两个串都反转，公共后缀就变成公共前缀：

$$|\mathrm{lcsuf}(a, b)| = \big|\mathrm{lcp}(\overleftarrow{a}, \overleftarrow{b})\big|$$

（$\overleftarrow{x}$ 表示反串——逐位相等关系在反转下不变，只是下标镜像。）

而「一批串的公共前缀」正是 **Trie** 的看家本领。把每个 `wordsContainer[i]` **倒序**插入 Trie，则：

- 从根走到节点 $v$ 的路径读出串 $p$ ⟺ 某个容器词以 $\overleftarrow{p}$ 为后缀；
- 查询 $q$ 沿 $\overleftarrow{q}$ 在 Trie 上能走多深，$q$ 与容器词的最长公共后缀就多长。

![后缀 Trie：倒序插入，节点维护最优 (len, idx)](images/lcsq_suffix_trie_concept.svg)

### 3.3 算法流程：节点只存一个 (len, idx)

查询在 Trie 上走到的节点，天然给出候选集合：**所有以该后缀结尾的容器词**（即「插入时经过该节点的词」）。于是每个节点只需维护一个聚合值：

$$\text{best}[v] = \min_{u \text{ 经过 } v} \big(\lvert u \rvert,\ \mathrm{idx}(u)\big)$$

「经过 $v$ 的所有词」中 (长度, 下标) 字典序最小者——恰好就是题目后两级平局规则。插入时沿途用 `cur < best[v]` 更新即可，**不需要任何删除操作**。

- **插入** `wordsContainer[i] = s`：令 `cur = (|s|, i)`；先尝试更新**根**，再倒序逐字符下行，每经过一个节点就尝试更新其 `best`；
- **查询** `q`：从根倒序下行，走到没有出边为止，答案 = **停留节点**的 `best`。特别地，若第一步就走不动（公共后缀为空），停留节点就是根——所以**根也必须维护 best**（全局最短、最早）。

![插入与查询流程](images/lcsq_insert_query_flow.svg)

> ⚠️ 最大的坑：公共后缀为空时（示例 1 的 `"xyz"`），答案不是任意词，而是**全体容器词中 (len, idx) 最小者**。它对应的「节点」是根，因此根必须参与 best 的维护——只在孩子节点上更新的写法会让这类查询返回垃圾值。

### 3.4 示例演算

以示例 1 走全程。倒序插入串为 `dcba`、`dcb`、`dcbx`：

| 插入 | cur | 沿途节点 | best 变化 |
|------|-----|---------|-----------|
| `"abcd"` | (4, 0) | root→d→c→b→a | 全部置为 (4, 0) |
| `"bcd"` | (3, 1) | root→d→c→b | (3, 1) < (4, 0)，四处全部更新 |
| `"xbcd"` | (4, 2) | root→d→c→b→x | (4, 2) 不小于 (3, 1)，沿途不更新；仅新节点 x 为 (4, 2) |

查询：

| 查询 | 倒序 | 匹配路径 | 停留节点 | best | ans |
|------|------|---------|---------|------|-----|
| `"cd"` | `dc` | d→c | 深度 2 节点 c | (3, 1) | 1 |
| `"bcd"` | `dcb` | d→c→b | 深度 3 节点 b | (3, 1) | 1 |
| `"xyz"` | `zyx` | z 无出边 | 根 | (3, 1) | 1 |

再用示例 2 检验「长后缀优先于短长度」：查询 `"acbfgh"`（倒序 `hgf...`）沿 h→g→f 走 3 步后 `b` 无出边，停在 f 节点，其 best = (8, 0)——后缀 `fgh` 长 3 只有 `"abcdefgh"` 满足，尽管 `"ghghgh"` 更短也轮不到它，ans = 0。

## 4. 算法细节

1. **26 叉数组 Trie**：孩子用 `ch[v][26]` 数组直接寻址，单字符转移 $O(1)$。字符集固定为小写字母，数组寻址优于哈希表。
2. **节点编号约定**：根编号 0，孩子指针初始化为 0 兼作「空指针」，新节点从 1 开始编号（新编号 = 当前 `ch.size()`）；也可统一用 $-1$ 表示空，两种等价，但不要混用。
3. **best 用元组存**：C++ 的 `pair<int,int>` / Python 的 tuple 比较就是双关键字字典序，`(len, idx)` 一次比较同时覆盖「更短」与「更早」两级平局规则，无需手写比较函数。
4. **根的 best**：插入每个词时先执行一次 `cur < best[0]`；查询走不进任何出边时返回 `best[0]` 的下标。
5. **倒序遍历**：C++ 写 `for (int j = (int)s.size() - 1; j >= 0; j--)`，`j` 必须是**有符号**整型（`size_t` 会下溢死循环）；Python 直接 `reversed(s)`。
6. **内存预算**：节点数上界 = 容器词总长 $5 \times 10^5$，26 叉 `int` 数组约 $26 \times 5 \times 10^5 \times 4\text{B} \approx 52\text{MB}$，应 `reserve` 预分配避免反复扩容；若内存吃紧可改为 `map` / 哈希表孩子，代价是转移多一个 $\log$ 或哈希常数。
7. **重复词无需特判**：Trie 路径已存在，best 按元组序自然保持或更新。

## 5. 正确性证明

记 $\overleftarrow{x}$ 为反串，$\mathrm{lcp}$ 为最长公共前缀，$\mathrm{lcsuf}$ 为最长公共后缀，$C$ 为容器词集合，$\mathrm{idx}(u)$ 为 $u$ 的下标。

**引理 1（反转对应）**：对任意词 $w, u$，有 $|\mathrm{lcsuf}(w, u)| = |\mathrm{lcp}(\overleftarrow{w}, \overleftarrow{u})|$。

**证明**：$w$ 与 $u$ 的长为 $d$ 后缀逐位相等，即 $w[m_w - k] = u[m_u - k]$ 对 $k = 1, \ldots, d$ 成立；这恰好等价于 $\overleftarrow{w}$ 与 $\overleftarrow{u}$ 的长为 $d$ 前缀逐位相等（反转把「从尾数第 $k$ 位」映到「从头数第 $k - 1$ 位」）。对最大可行的 $d$ 取等即证。∎

**引理 2（节点语义与 best 维护）**：设从根到节点 $v$ 的路径边标依次为 $c_1 c_2 \cdots c_d$（即 $v$ 代表反串前缀 $c_1 \cdots c_d$）。定义 $S_v = \{u \in C : u \text{ 以 } c_d c_{d-1} \cdots c_1 \text{ 为后缀}\}$。则：
（a）词 $u$ 的插入路径经过 $v$ 当且仅当 $u \in S_v$；
（b）全部词插入完成后，$\text{best}[v] = \arg\min_{u \in S_v} (\lvert u \rvert, \mathrm{idx}(u))$。

**证明**：（a）倒序插入 $u$ 即沿 $\overleftarrow{u}$ 逐字符下行，经过深度 $d$ 的节点 $v$ 当且仅当 $\overleftarrow{u}$ 以 $c_1 \cdots c_d$ 为前缀，当且仅当 $u$ 以 $c_d \cdots c_1$ 为后缀，即 $u \in S_v$。（b）对插入次数归纳：节点创建时 best 为 $+\infty$；每次插入 $u$ 经过 $v$ 时执行 `best[v] ← min(best[v], (|u|, idx(u)))`，由（a）参与取 min 的恰是 $S_v$ 中的元素。故任意时刻 best[v] 为「已插入的 $S_v$ 元素」之最小者，全部插完即为 $S_v$ 之最小者。对 $v = \text{root}$（$d = 0$）同样成立：每个词都经过根，$S_{\text{root}} = C$（空后缀人人皆有）。∎

**引理 3（查询路径与候选集）**：查询 $w$ 从根沿 $\overleftarrow{w}$ 的最大可行深度为 $D$，则 $D = \max_{u \in C} |\mathrm{lcsuf}(w, u)|$；且（$D \ge 1$ 时）停留节点 $v$ 满足 $S_v = \{u : |\mathrm{lcsuf}(w, u)| = D\}$；$D = 0$ 时该集合为全体 $C$。

**证明**：深度 $d$ 的节点在 $\overleftarrow{w}$ 的前缀路径上存在，当且仅当某 $u \in C$ 的插入路径经过它，即 $\overleftarrow{u}$ 以 $\overleftarrow{w}$ 的长 $d$ 前缀为前缀；由引理 1 等价于存在 $u$ 以 $w$ 的长 $d$ 后缀为后缀，即 $\max_u |\mathrm{lcsuf}(w, u)| \ge d$。对 $d = D$ 与 $d = D + 1$ 分别应用，即得第一断言。其次，$u \in S_v$ 当且仅当 $u$ 以 $w$ 的长 $D$ 后缀为后缀，此时 $|\mathrm{lcsuf}(w, u)| \ge D$，而 $D$ 已是最大值，故 $= D$；反之显然。$D = 0$ 时所有 $|\mathrm{lcsuf}(w, u)| = 0$，候选为全体。∎

**定理**：对每个查询 $w$，算法返回的下标满足题目的三级规则（最长公共后缀 → 最短长度 → 最小下标）。

**证明**：候选集为 $\{u : |\mathrm{lcsuf}(w, u)| = D\}$（引理 3），已穷尽第一级规则。算法恰好停在该集合对应的节点（$D = 0$ 时为根），由引理 2，返回的是候选集中 $(\lvert u \rvert, \mathrm{idx}(u))$ 最小者的下标，即后两级规则。∎

## 6. 复杂度分析

- **时间复杂度**：$O(S_C + S_Q)$，其中 $S_C, S_Q \le 5 \times 10^5$ 为两数组总字符数。插入每个字符一次数组寻址加一次元组比较 $O(1)$；查询每个字符同样 $O(1)$。建 Trie 与全部查询均为线性。
- **空间复杂度**：$O(26 \cdot S_C)$ 存转移数组（上界；实际节点数按不同后缀路径共享，通常更少），$O(S_C)$ 存 best。26 叉 `int` 数组约 52 MB，是本题主要的内存开销。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> stringIndices(vector<string>& wordsContainer, vector<string>& wordsQuery) {
        int total = 0;
        for (auto& s : wordsContainer) total += (int)s.size();
        vector<array<int, 26>> ch(1);                        // ch[0] = 根；孩子指针 0 表示空
        ch.reserve(total + 1);
        vector<pair<int, int>> best(1, {INT_MAX, INT_MAX});  // best[v] = (长度, 下标)
        best.reserve(total + 1);

        for (int i = 0; i < (int)wordsContainer.size(); i++) {
            const string& s = wordsContainer[i];
            pair<int, int> cur = {(int)s.size(), i};
            if (cur < best[0]) best[0] = cur;  // 根也要维护：空后缀的候选是全体
            int u = 0;
            for (int j = (int)s.size() - 1; j >= 0; j--) {
                int c = s[j] - 'a';
                if (ch[u][c] == 0) {
                    ch[u][c] = (int)ch.size();
                    ch.emplace_back();
                    best.emplace_back(INT_MAX, INT_MAX);
                }
                u = ch[u][c];
                if (cur < best[u]) best[u] = cur;
            }
        }

        vector<int> ans;
        ans.reserve(wordsQuery.size());
        for (const string& q : wordsQuery) {
            int u = 0;
            for (int j = (int)q.size() - 1; j >= 0; j--) {
                int v = ch[u][q[j] - 'a'];
                if (v == 0) break;  // 走不动：停在当前节点
                u = v;
            }
            ans.push_back(best[u].second);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def stringIndices(self, wordsContainer: List[str], wordsQuery: List[str]) -> List[int]:
        INF = (float('inf'), float('inf'))
        ch = [[-1] * 26]        # ch[0] 为根，-1 表示无孩子
        best = [INF]            # best[v] = (长度, 下标)，越小越优
        for i, s in enumerate(wordsContainer):
            cur = (len(s), i)
            if cur < best[0]:   # 根也要维护（空后缀的候选 = 全体词）
                best[0] = cur
            u = 0
            for c in reversed(s):
                c = ord(c) - 97
                if ch[u][c] < 0:
                    ch[u][c] = len(ch)
                    ch.append([-1] * 26)
                    best.append(INF)
                u = ch[u][c]
                if cur < best[u]:
                    best[u] = cur
        ans = []
        for q in wordsQuery:
            u = 0
            for c in reversed(q):
                v = ch[u][ord(c) - 97]
                if v < 0:
                    break       # 后缀链断裂：停在当前节点
                u = v
            ans.append(best[u][1])
        return ans
```

## 8. 边界情况与易错点

1. **空后缀兜底（最大坑）**：查询与所有词都无公共后缀时，答案 = 全局 (最短, 最早) 的词（示例 1 的 `"xyz"`）。必须维护**根节点**的 best；只在孩子节点更新的写法会让这类查询返回未定义值。
2. **根节点更新时机**：插入每个词都要先做一次 `cur < best[root]`，漏掉的话根的 best 停留在初始 $+\infty$。
3. **双关键字比较**：只比长度会漏「同长取更早下标」；用 `(len, idx)` 元组序一次到位。
4. **无符号下溢**：C++ 倒序循环的 `j` 若声明为 `size_t`，`j >= 0` 恒真导致死循环或越界，必须用 `int`。
5. **「走不动」≠ 没答案**：查询中途断掉时，答案取**停留节点**（后缀长度 = 已走深度），既不回退也不返回 $-1$。
6. **内存与扩容**：26 叉数组最坏约 52 MB，务必按总长 `reserve`；vector 反复扩容既拖慢速度又可能出现双倍峰值内存。
7. **节点编号从 1 开始**：用 0 兼作空指针时，新节点编号 = 当前 `ch.size()`（恒 $\ge 1$），不会与根冲突；若混用 $-1$ 约定要保持一致。
8. **查询词很长**：可能比 Trie 中任何路径都长，走完自身字符即停，同样取停留节点的 best。

**延伸思考**：

- 若每次查询问的是**最长公共前缀**，直接正序建 Trie，做法完全同构。
