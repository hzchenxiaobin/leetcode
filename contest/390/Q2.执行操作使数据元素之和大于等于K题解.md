# LeetCode 执行操作使数据元素之和大于等于K 题解

## 1. 题目概述

- **标题 / 题号**：执行操作使数据元素之和大于等于 K（#3091，medium）
- **链接**：https://leetcode.cn/problems/apply-operations-to-make-sum-of-array-greater-than-or-equal-to-k/
- **来源**：LeetCode 第 390 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数学、枚举

**题意**：给定正整数 $k$，初始数组 $\text{nums} = [1]$。每次可执行两种操作之一：把**任意一个元素的值增加 1**；或**复制任意一个元素**并追加到数组末尾。求使数组**元素之和大于等于 $k$** 的最少操作次数。

**约束**：

- $1 \le k \le 10^5$

## 2. 示例

**示例 1**

```text
输入：k = 11
输出：5

解释：先给唯一的元素 +1 三次得 nums = [4]（3 次操作），
再复制两次得 nums = [4,4,4]（2 次操作），和 = 12 ≥ 11。
总操作次数 = 3 + 2 = 5。
```

**示例 2**

```text
输入：k = 1
输出：0

解释：初始数组的和已经是 1，无需任何操作。
```

**示例 3（补充）**

```text
输入：k = 5
输出：3

解释：方案一：+1 一次得 [2]，再复制两次得 [2,2,2]，和 6，共 3 次；
方案二：+1 两次得 [3]，再复制一次得 [3,3]，和 6，共 3 次。两者并列最优。
```

## 3. 解题思路

### 3.1 暴力思路

数组状态是任意多重集、两种操作可无限执行，**状态空间无界**，BFS / 记忆化搜索无从下手——$k$ 只约束「和」，不约束单元素值与数组长度，必须先**刻画终局形态**再计数操作。

朴素的改进：直觉上最优策略是「把 1 加到某个值 $v$，再复制出 $m$ 份」，于是枚举 $v \in [1, k]$，每轮取最小份数 $m = \lceil k/v \rceil$，代价 $(v-1)+(m-1)$，$O(k)$ 也能通过（$k \le 10^5$）。但这留下两个问题：**终局为什么一定长这样**（加法与复制的顺序、加法分给谁）？**枚举能否更快**？——分别用交换论证与镜像枚举解决。

### 3.2 核心观察：加法要趁早，复制挑最大

![核心观察：加法要趁早，复制挑最大](images/ops_sum_k_amplify_concept.svg)

**观察一（$+1$ 必须赶在复制之前）**：对值为 $v$ 的元素，比较同样花 2 步的两种顺序：

- ✗ 先复制再给副本 $+1$：得 $\{v,\ v+1\}$，和为 $2v+1$；
- ✓ 先 $+1$ 再复制：得 $\{v+1,\ v+1\}$，和为 $2v+2$。

先加后复制**多赚 1**——本质是「加法在被复制放大之前生效」。任何「复制之后才加」的操作序列，都能把这个 $+1$ 沿复制树**上移**到复制之前：操作数不变、和不减。因此 **WLOG 所有加法先做**。

**观察二（加法集中、复制挑最大）**：所有加法前置后，把 $x$ 次 $+1$ 全部集中在唯一的元素上养出 $v = 1+x$，再复制它 $y$ 次（复制小值被复制最大值**支配**——同样 1 步拷出的数不更大）。此时 $x$ 次加法 + $y$ 次复制的**最大可达和**为 $(1+x)(1+y)$（严格证明见 §5 引理 1）。

**转化为整数优化**：令 $v = 1+x$、$m = 1+y$，问题变为

$$\min\ (v - 1) + (m - 1) \quad \text{s.t.} \quad v \cdot m \ge k,\quad v, m \in \mathbb{Z}^+$$

固定 $v$ 时代价随 $m$ 递增，取最小可行份数 $m = \lceil k/v \rceil$，得单变量函数

$$f(v) = (v - 1) + \left(\lceil k/v \rceil - 1\right)$$

### 3.3 算法流程：枚举 v 到 √k 即可

![算法流程：枚举 v 到 ⌊√k⌋+1](images/ops_sum_k_enumerate_flow.svg)

直觉来自**均值不等式** $v + k/v \ge 2\sqrt{k}$：加法成本与复制成本此消彼长，最优解落在 $v \approx m \approx \sqrt{k}$ 附近。严格地说，只需枚举 $v \in [1, \lfloor\sqrt{k}\rfloor + 1]$——超出该范围的 $v$ 可**镜像**为范围内的 $m$ 且代价不增（§5 引理 3），$k = 10^5$ 时约 **317** 轮。

初始化 `ans = k - 1`（$v = 1$ 纯复制的兜底方案），随后逐个 $v$ 计算 $f(v)$ 取最小。

### 3.4 示例演算

![示例演算：k=11 枚举过程](images/ops_sum_k_walkthrough.svg)

以 $k = 11$ 走一遍，$\lfloor\sqrt{11}\rfloor + 1 = 4$：

| $v$ | $m = \lceil 11/v \rceil$ | 操作数 $(v-1)+(m-1)$ | 终局 |
|-----|--------------------------|----------------------|------|
| 1 | 11 | 10 | 纯复制 $[1,\dots,1]$，和 11 |
| 2 | 6 | 6 | $[2,2,2,2,2,2]$，和 12 |
| **3** | **4** | **5** | $[3,3,3,3]$，和 12 |
| **4** | **3** | **5** | $[4,4,4]$，和 12（示例 1） |

最小值 $\text{ans} = 5$，$v = 3$ 与 $v = 4$ 并列取到。$v$ 再增大时加法成本压过复制收益，$f(v)$ 回升，无需再看。

## 4. 算法细节

1. **终局定形**：由交换论证，最优解可化为「$v-1$ 次 $+1$ 全加在 1 上 → $m-1$ 次复制」的**正规形**，代价 $v + m - 2$。
2. **$m$ 直接取上取整**：固定 $v$ 时代价关于 $m$ 严格递增，而约束只需 $v \cdot m \ge k$，取 $m = \lceil k/v \rceil$ 即最小可行份数，无需再枚举 $m$。
3. **整数上取整**：`m = (k + v - 1) / v`，全程整数运算，避免浮点误差。
4. **枚举上界**：$v$ 只需到 $\lfloor\sqrt{k}\rfloor + 1$；用 `isqrt` / `sqrtl` 取整数平方根，避免浮点抖动导致边界差一。
5. **初始化**：`ans = k - 1` 对应 $v = 1$ 纯复制的兜底方案；由于循环从 $v = 1$ 开始，初始化为任意大数同样正确。

## 5. 正确性证明

**引理 1（和的上界）**：任意时刻，若已执行 $i$ 次加法、$c$ 次复制，则 $\text{sum} \le (1+i)(1+c)$。

**证明**：对操作数归纳。基础：初始 $\text{sum} = 1 = (1+0)(1+0)$。
加法步（$i \to i+1$）：$\text{sum}' \le (1+i)(1+c) + 1 \le (2+i)(1+c)$（因 $1 \le 1+c$）。
复制步（$c \to c+1$）：由归纳可再维护不变式「任何元素的值 $\le 1 + i$」（元素值 = 初始 1 + 其血统链上分到的加法次数 $\le i$，对每一步操作均成立），故 $\text{sum}' \le (1+i)(1+c) + (1+i) = (1+i)(2+c)$。∎

**引理 2（正规形达到上界）**：「$i$ 次加法全加在唯一元素上、再复制 $c$ 次」恰好取到 $\text{sum} = (1+i)(1+c)$。

**证明**：加法前置后该元素值为 $1+i$，复制 $c$ 次得 $1+c$ 个该值，和为 $(1+i)(1+c)$。∎

**定理 1**：最少操作数 $= \min\{\, v + m - 2 : v, m \in \mathbb{Z}^+,\ v \cdot m \ge k \,\}$。

**证明**：一方面，对任一达到 $\text{sum} \ge k$ 的方案（$i$ 次加法 + $c$ 次复制），由引理 1 有 $(1+i)(1+c) \ge \text{sum} \ge k$，即 $(1+i,\ 1+c)$ 是右侧优化问题的可行解，故优化最优值 $\le i + c$；对所有方案取下确界得：优化最优值 $\le$ 最少操作数。另一方面，取优化问题最优解 $(v^*, m^*)$，由引理 2 的正规形以 $v^* + m^* - 2$ 次操作达到和 $v^* m^* \ge k$，故最少操作数 $\le$ 优化最优值。两个方向夹逼即得。∎

**引理 3（镜像枚举足够）**：对任意 $v > \lfloor\sqrt{k}\rfloor + 1$，令 $m = \lceil k/v \rceil$，则 $m \le \lfloor\sqrt{k}\rfloor + 1$ 且 $f(m) \le f(v)$。

**证明**：由 $m \cdot v \ge k$ 且 $v$ 为整数得 $v \ge \lceil k/m \rceil$，于是 $f(m) = (m-1) + (\lceil k/m \rceil - 1) \le (m-1) + (v-1) = f(v)$。又 $v \ge \lfloor\sqrt{k}\rfloor + 2$ 时 $m \le \lceil k / (\lfloor\sqrt{k}\rfloor + 2) \rceil \le \lfloor\sqrt{k}\rfloor + 1$（因 $k < (\lfloor\sqrt{k}\rfloor + 1)^2$），即镜像点落在枚举范围内。∎

**定理 2**：只枚举 $v \in [1, \lfloor\sqrt{k}\rfloor + 1]$ 即可取到全局最优。

**证明**：取优化问题最优解 $(v^*, m^*)$。由定理 1 后半的构造可设 $m^* = \lceil k/v^* \rceil$（固定 $v^*$ 时代价随 $m$ 递增，最优解必取最小可行份数）。若 $v^* \le \lfloor\sqrt{k}\rfloor + 1$，则 $f(v^*)$ 已被枚举覆盖；否则由引理 3，$m^* \le \lfloor\sqrt{k}\rfloor + 1$ 且 $f(m^*) \le f(v^*)$，枚举范围内仍存在代价不增的候选。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\sqrt{k})$。枚举 $v \in [1, \lfloor\sqrt{k}\rfloor + 1]$，每轮 $O(1)$ 整数运算；$k = 10^5$ 时约 317 轮。
- **空间复杂度**：$O(1)$，仅常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minOperations(int k) {
        int ans = k - 1;                              // v = 1：纯复制兜底
        int lim = (int)sqrtl((long double)k) + 1;     // 枚举上界 ⌊√k⌋+1
        for (int v = 1; v <= lim; ++v) {
            int m = (k + v - 1) / v;                  // ⌈k/v⌉ 份
            ans = min(ans, (v - 1) + (m - 1));
        }
        return ans;
    }
};
```

### Python

```python
from math import isqrt

class Solution:
    def minOperations(self, k: int) -> int:
        ans = k - 1                             # v = 1：纯复制兜底
        for v in range(1, isqrt(k) + 2):        # 枚举到 ⌊√k⌋+1
            m = (k + v - 1) // v                # ⌈k/v⌉ 份
            ans = min(ans, (v - 1) + (m - 1))
        return ans
```

> 💡 `(k + v - 1) / v` 是整数写法的 $\lceil k/v \rceil$。循环第一轮 $v = 1$ 就覆盖了初始化的兜底值，`ans` 也可初始化为任意大数。

## 8. 边界情况与易错点

1. **k = 1**：$v = m = 1$，$f(1) = 0$，公式**自然覆盖**「不操作」的边界，无需特判。
2. **上取整别用浮点**：`(k + v - 1) / v` 是安全的整数写法；`ceil(k / v)` 依赖浮点除法，极端值可能差一。
3. **枚举上界差一**：只枚举到 $\lfloor\sqrt{k}\rfloor$ 可能漏解，统一取 $\lfloor\sqrt{k}\rfloor + 1$ 保险；求平方根优先用 `isqrt` / `sqrtl`。
4. **两个极端都是兜底**：$v = 1$（纯复制）与 $m = 1$（纯加法）的代价都是 $k - 1$，均在枚举范围内被自然覆盖，不必单独处理。
5. **溢出**：$k \le 10^5$，$v + m \le 2\sqrt{k} + 1 \approx 640$，`int` 绰绰有余。
6. **别漏「复制挑最大」**：若复制较小元素，其结果被「复制最大值」支配（同样 1 步拷出的数更大）；正规形里只需复制养大的那个值。
