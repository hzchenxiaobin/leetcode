# LeetCode 最高频率的 ID 题解

## 1. 题目概述

- **标题 / 题号**：最高频率的 ID（#3092，medium）
- **链接**：https://leetcode.cn/problems/most-frequent-ids/
- **来源**：LeetCode 第 390 场周赛 Q3
- **难度**：中等
- **标签**：哈希表、堆（优先队列）、懒删除、有序集合

**题意**：用一个哈希表动态维护每个 ID 的出现次数 $\text{cnt}[x]$。第 $i$ 步把 $\text{cnt}[\text{nums}[i]]$ 加上 $\text{freq}[i]$（正为插入、负为删除），随后立即询问**当前所有 ID 中最大的频次**；若集合为空则答案为 $0$。返回每步答案构成的数组。

**约束**：

- $1 \le n = \text{nums.length} = \text{freq.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^5$，$-10^5 \le \text{freq}[i] \le 10^5$ 且 $\text{freq}[i] \ne 0$
- 任何操作后计数不为负——频次上界可达 $n \cdot \max|\text{freq}| = 10^{10}$，**超出 `int` 范围**

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,2,1], freq = [3,2,-3,1]
输出：[3,3,2,2]

解释：
第 0 步：cnt = {2:3}，最大频次 3；
第 1 步：cnt = {2:3, 3:2}，最大频次 3；
第 2 步：ID 2 删光，cnt = {3:2}，最大频次 2；
第 3 步：cnt = {3:2, 1:1}，最大频次 2。
```

**示例 2**

```text
输入：nums = [5,5,3], freq = [2,-2,1]
输出：[2,0,1]

解释：第 1 步把 ID 5 删光，集合为空，ans[1] = 0。
```

**示例 3（补充：频次回升与过期条目）**

```text
输入：nums = [1,2,1,2,1], freq = [4,3,-2,1,1]
输出：[4,4,3,4,4]

解释：
第 0 步：cnt = {1:4}，ans = 4；
第 1 步：cnt = {1:4, 2:3}，ans = 4；
第 2 步：cnt[1] 降到 2，ans = 3；
第 3 步：cnt[2] 升到 4，ans = 4；
第 4 步：cnt[1] 升到 3，ans 仍为 4。
同一 ID 的多个历史频次条目会同时留在堆里，靠"对账"识别过期。
```

## 3. 解题思路

### 3.1 暴力思路

维护哈希表 $\text{cnt}$，每步更新后**线性扫描所有键**取最大值：单步 $O(n)$，总 $O(n^2) = 10^{10}$，必然超时。

另一种直觉是"维护当前最大值 $\text{maxFreq}$"：增加时上跳容易，但**减少时若恰是最大频次被削，最大值该降到哪并不知道**，只能重新扫描。困难的本质是：**普通变量只记得"谁是最大"，记不住"第二名是谁"**——需要一种能按频次排序、又支持高频次增删的结构。

### 3.2 核心观察：懒删除堆——真值表 + 历史快照

![懒删除堆：真值表与历史快照对账](images/mfid_lazy_heap_concept.svg)

把两份信息分开存：

- **真值表**：哈希表 $\text{cnt}[x]$ 记录每个 ID **当前**的真实频次，每步 $O(1)$ 更新；
- **历史快照库**：大根堆存放二元组 $(\text{cnt}[x],\ x)$——每次更新后，把**新频次连同 ID** 推入堆，旧的条目**不急着删**。

堆里的条目未必真实（频次后来可能又变了），但有一条不变的关系：**只要 ID $x$ 的当前频次是 $c$，堆中就一定留有 $(c, x)$ 这张"最新快照"**（它是最后一批推入的，见 §5 引理 2）。

于是查询时做一次**对账**：若堆顶 $(c, x)$ 满足 $c \ne \text{cnt}[x]$，说明它是**过期快照**，直接弹出；重复直到堆顶对得上真值表。此时堆顶频次就是全场最大频次。

> 💡 每个条目至多被推入一次、弹出一次，$n$ 步总代价 $O(n \log n)$——"懒删除"的本质是把删除成本**摊到未来真正挡路的时刻**再付。

### 3.3 算法流程

![算法流程：更新、入堆、对账、取顶](images/mfid_flow.svg)

1. 建哈希表 `cnt`（真值表）与空大根堆 `pq`（快照库）；
2. 第 $i$ 步：`cnt[nums[i]] += freq[i]`，随后 `push(cnt[nums[i]], nums[i])`（**计数变 0 也照样推**，统一处理）；
3. **对账**：`while` 堆顶频次 ≠ 真值表中该 ID 的当前频次，弹出堆顶；
4. `ans[i] =` 堆顶频次（每步都 push 过，堆必非空；若采用"计数为 0 不入堆"的写法，才需要堆空时返回 0）。

### 3.4 示例演算

![示例演算：示例 1 的堆快照与对账过程](images/mfid_example_walkthrough.svg)

以示例 1 `nums = [2,3,2,1]`，`freq = [3,2,-3,1]` 走一遍（堆中条目按从顶到底排列，✗ 表示对账时被弹出的过期快照）：

| 步 | 操作 | 堆内快照（顶→底） | 对账 | ans |
|----|------|-------------------|------|-----|
| 0 | cnt[2]=3，push (3,2) | **(3,2)** | 3 = cnt[2] ✓ | 3 |
| 1 | cnt[3]=2，push (2,3) | **(3,2)**, (2,3) | 3 = cnt[2] ✓ | 3 |
| 2 | cnt[2]=0，push (0,2) | ~~(3,2)~~ ✗ → **(2,3)**, (0,2) | 3 ≠ cnt[2]=0 弹出；2 = cnt[3] ✓ | 2 |
| 3 | cnt[1]=1，push (1,1) | **(2,3)**, (1,1), (0,2) | 2 = cnt[3] ✓ | 2 |

第 2 步是关键：ID 2 的旧快照 $(3,2)$ 虽在堆顶却已过期，对账弹掉后，露出真实的最大频次 2。第 3 步里 $(0,2)$ 留在堆底不出来，无害——**懒删除只清挡路的**。

## 4. 算法细节

1. **频次必须用 64 位**：单个 ID 的频次上界 $10^5 \times 10^5 = 10^{10}$，C++ 用 `long long`（函数返回类型就是 `vector<long long>`）；Python 无需处理。
2. **计数减到 0 仍入堆**：统一 `push(cnt[x], x)`，代码最短；0 快照值与真值一致，永远不会被对账误弹，也永远压不过正频次条目。若改用"为 0 不入堆"，查询处需补堆空判断。
3. **对账条件用"值不等"而非"时间戳"**：只需 `堆顶频次 != cnt[堆顶ID]`。旧快照若**恰好**等于当前真值（频次降了又升回来），它给出的 (值, ID) 与真值完全一致，留作堆顶无害——正确性不依赖弹出所有过期条目，只依赖堆顶**值**正确（§5 引理 3）。
4. **堆会积累条目，但总量可控**：push 恰好 $n$ 次，内存 $O(n)$，无须清理。
5. **替代解法（有序集合/频次桶）**：维护有序映射 `频次 → 该频次的 ID 个数`，每次修改把 ID 从旧频次桶挪进新频次桶（桶空则删 key），最大频次即最大 key（C++ `map.rbegin()`，Python `SortedDict.peekitem(-1)`）。为什么不用"数组桶 + 最大值指针"？频次值域 $10^{10}$，数组开不下；且最大值指针在频次大幅震荡时下降不均摊。平衡树把"找次大频次"变成 $O(\log n)$，见 §7 代码二。

## 5. 正确性证明

**引理 1（堆顶有效性）**：对账循环结束时，堆顶 $(c, x)$ 满足 $c = \text{cnt}[x]$。

**证明**：循环终止条件即堆顶频次与真值相等；每步至少 push 一个条目、堆非空，循环必然在堆空前遇到值匹配的堆顶——因为当前最大频次的最新快照总在堆中（引理 2），它上方的条目全部会被弹出。∎

**引理 2（最新快照长存）**：设第 $i$ 步后 $\text{cnt}[x] = c > 0$，且 $x$ 最后一次被修改是第 $j$ 步（$j \le i$），则第 $i$ 步查询时堆中存在条目 $(c, x)$。

**证明**：第 $j$ 步 push 了 $(c, x)$。在其后第 $k$ 步（$j < k \le i$）的对账中，$x$ 未再被修改，真值恒为 $c$，故条目 $(c,x)$ 即便到达堆顶也因 $c = \text{cnt}[x]$ 不满足弹出条件；不在堆顶时更不会被弹。因此它一直留存到第 $i$ 步。∎

**引理 3（有效堆顶即真值）**：堆中任何满足 $c = \text{cnt}[x]$ 的条目 $(c, x)$，其频次 $c \le M$，其中 $M$ 为第 $i$ 步后的真实最大频次（$M = 0$ 表示集合为空）。

**证明**：$c$ 就是某个 ID 的真实频次，当然不超过全体最大值 $M$。∎

**定理**：第 $i$ 步对账后，堆顶频次恰为 $M = \max_x \text{cnt}[x]$（集合为空时为 $0$）。

**证明**：若 $M = 0$：所有真值为 0，本步 push 的 0 快照使堆非空且堆顶频次为 0（任何正频次条目都是过期的，会被对账弹出；0 快照值匹配永不被弹），返回 0 ✓。若 $M > 0$：取达到 $M$ 的 ID $x^*$，其最后一次修改步为 $j$，由引理 2，条目 $(M, x^*)$ 在堆中。由引理 1，堆顶 $(c, x)$ 满足 $c = \text{cnt}[x]$；由引理 3，$c \le M$；又 $(M, x^*)$ 在堆中，堆顶频次 $\ge M$。故堆顶频次 $= M$。∎

**复杂度的均摊论证**：全程 push 恰好 $n$ 次；pop 只发生在对账循环中，每次 pop 消灭一个曾 push 的条目，故 pop 总次数 $\le n$。单次堆操作 $O(\log n)$，总计 $O(n \log n)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。每步一次哈希更新 $O(1)$、一次 push $O(\log n)$；对账 pop 的总次数被 push 总次数 $n$ 均摊封顶。
- **空间复杂度**：$O(n)$。哈希表至多 $10^5$ 个键；堆中恰好 $n$ 个条目（每步一个，从不重复清理）。

## 7. 参考代码

### C++（解法一：懒删除堆）

```cpp
class Solution {
  public:
    vector<long long> mostFrequentIDs(vector<int>& nums, vector<int>& freq) {
        int n = nums.size();
        vector<long long> ans(n);
        unordered_map<int, long long> cnt;         // 真值表：id → 当前频次
        priority_queue<pair<long long, int>> pq;   // 快照库：(频次, id)
        for (int i = 0; i < n; ++i) {
            int x = nums[i];
            cnt[x] += freq[i];
            pq.push({cnt[x], x});                  // 新快照入堆（0 也入）
            while (pq.top().first != cnt[pq.top().second])   // 对账弹过期
                pq.pop();
            ans[i] = pq.top().first;               // 每步都 push，堆必非空
        }
        return ans;
    }
};
```

### Python（解法一：懒删除堆）

```python
class Solution:
    def mostFrequentIDs(self, nums: List[int], freq: List[int]) -> List[int]:
        cnt = defaultdict(int)                    # 真值表
        heap = []                                # 快照库（取负模拟大根堆）
        ans = []
        for x, f in zip(nums, freq):
            cnt[x] += f
            heapq.heappush(heap, (-cnt[x], x))
            while -heap[0][0] != cnt[heap[0][1]]:  # 对账弹过期
                heapq.heappop(heap)
            ans.append(-heap[0][0])               # 每步都 push，堆必非空
        return ans
```

### C++（解法二：频次桶 + 有序集合）

```cpp
class Solution {
  public:
    vector<long long> mostFrequentIDs(vector<int>& nums, vector<int>& freq) {
        int n = nums.size();
        vector<long long> ans(n);
        unordered_map<int, long long> cnt;        // 真值表
        map<long long, int> bucket;               // 频次 → 该频次的 ID 数
        for (int i = 0; i < n; ++i) {
            int x = nums[i];
            if (cnt[x] > 0 && --bucket[cnt[x]] == 0)   // 移出旧频次桶
                bucket.erase(cnt[x]);
            cnt[x] += freq[i];
            if (cnt[x] > 0)                             // 移入新频次桶
                ++bucket[cnt[x]];
            ans[i] = bucket.empty() ? 0 : bucket.rbegin()->first;
        }
        return ans;
    }
};
```

### Python（解法二：频次桶 + SortedDict）

```python
from sortedcontainers import SortedDict

class Solution:
    def mostFrequentIDs(self, nums: List[int], freq: List[int]) -> List[int]:
        cnt = defaultdict(int)
        bucket = SortedDict()                    # 频次 → 该频次的 ID 数
        ans = []
        for x, f in zip(nums, freq):
            if cnt[x] > 0:
                bucket[cnt[x]] -= 1
                if bucket[cnt[x]] == 0:
                    del bucket[cnt[x]]           # 移出旧频次桶
            cnt[x] += f
            if cnt[x] > 0:
                bucket[cnt[x]] = bucket.get(cnt[x], 0) + 1
            ans.append(bucket.peekitem(-1)[0] if bucket else 0)
        return ans
```

> 💡 两解法复杂度同为 $O(n \log n)$。懒删除堆短小精悍；频次桶对"每步都查最大"的题更稳（无对账循环），且天然支持"最大频次的 ID 有几个"这类扩展询问。

## 8. 边界情况与易错点

1. **频次溢出**：$10^{10}$ 超 `int`，C++ 全程 `long long`（含堆的 `pair`、哈希表值、返回数组）；Python 无此虞。
2. **减到 0 后又回升**：堆中同 ID 的多个快照共存（示例 3），靠对账识别；若手写"弹出后 break"或用时间戳判过期，注意旧快照值恰好等于回升后的真值时（引理 3 讨论）结论仍正确，勿画蛇添足。
3. **对账循环别写成 `if`**：过期快照可能连续多个堆叠在顶上，必须 `while`。
4. **集合为空**：本写法每步 push（含 0 快照），堆必非空且堆顶频次为 0，自然返回 0；若改用"0 不入堆"，查询前必须判堆空。
5. **别用"数组桶 + 最大值指针"**：频次值域 $10^{10}$ 开不了数组；即便离散化，最大值指针在大幅升降数据下不均摊。有序集合（`map` / `SortedDict`）或懒删除堆才是正解。
6. **`priority_queue` 存 `pair` 默认按第一关键字大根**：`(频次, id)` 直接可用；Python 需频次取负模拟大根堆。
