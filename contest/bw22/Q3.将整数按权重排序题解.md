# LeetCode 将整数按权重排序 题解

## 1. 题目概述

- **标题 / 题号**：将整数按权重排序（#1387，medium）
- **链接**：https://leetcode.cn/problems/sort-integers-by-the-power-value/
- **来源**：LeetCode 第 22 场双周赛 Q3
- **难度**：中等
- **标签**：记忆化、动态规划、排序

**题意**：整数 $x$ 的**权重**定义为按如下规则把 $x$ 变成 1 所需的步数：$x$ 偶数则 $x \leftarrow x/2$，奇数则 $x \leftarrow 3x+1$（Collatz 猜想的迭代过程）。例如 $3 \to 10 \to 5 \to 16 \to 8 \to 4 \to 2 \to 1$，权重为 7。给定 $lo, hi, k$，把区间 $[lo, hi]$ 内的整数按权重升序排序，权重相同按数值升序，返回第 $k$ 个数。

**约束**：

- $1 \le lo \le hi \le 1000$
- $1 \le k \le hi - lo + 1$
- 题目保证任意 $x \in [lo, hi]$ 变到 1 的步数是 32 位有符号整数

## 2. 示例

**示例 1**

```text
输入：lo = 12, hi = 15, k = 2
输出：13
解释：权重 12→9、13→9、14→17、15→17。排序后 [12, 13, 14, 15]
      （12 与 13 同权重按数值升序，14 与 15 同理），第 2 个是 13。
```

**示例 2**

```text
输入：lo = 7, hi = 11, k = 4
输出：7
解释：区间 [7, 8, 9, 10, 11] 的权重为 [16, 3, 19, 6, 14]，
      排序后 [8, 10, 11, 7, 9]，第 4 个是 7。
```

## 3. 解题思路

### 3.1 暴力思路

对 $[lo, hi]$ 每个数**从零开始**迭代 Collatz 过程数步数，再排序取第 $k$ 个。区间至多 1000 个数，每个的链长平均几十步，总共 $10^5$ 次量级的迭代——本题规模下暴力也能过。但「同一个数被反复算权重」的浪费明显：$power(8)$ 在算 8、16、32……时都要重走一遍。把每一步的结果存下来，就是教科书级的**记忆化**。

### 3.2 核心观察：大问题化小问题，记忆化只算一次

![Collatz 权重：大问题化小问题，记忆化只算一次](images/bw22_q3_memo_chain.svg)

权重天然满足递归结构：

$$power(x) = \begin{cases} 0 & x = 1\\ 1 + power(x/2) & x \text{ 偶}\\ 1 + power(3x+1) & x \text{ 奇（} x > 1\text{）} \end{cases}$$

子问题 $power(x/2)$ 或 $power(3x+1)$ 的参数与 $x$ 无关，可以直接递归。注意到链上的数**会越过 1000**（如 $3 \to 10 \to 5 \to 16$ 尚未越界，但 $27 \to 82 \to 41 \to 124 \dots$ 一路飙升到 9232；$x \le 1000$ 的全体链中中间值最高冲到 250504，出自 $x = 703$），所以记忆化数组不能只开 1001 就想全覆盖——要么开到二十五万，要么**只在 $x \le 1000$ 时落缓存**、越界值不存。后者明显更省。后者更省心：$> 1000$ 的中间值每个至多被路过一次，不缓存也不影响正确性，只轻微影响速度。

### 3.3 算法流程：记忆化求权重 + 双关键字排序

![排序流程：算权重 → 双关键字排序 → 第 k 个](images/bw22_q3_sort_flow.svg)

```text
1. memo[1] = 0（memo 长度 1001，其余未算）
2. power(x)：
     若 x == 1：返回 0
     若 x ≤ 1000 且 memo[x] 已算：返回 memo[x]
     p = 1 + power(x 偶 ? x/2 : 3x+1)
     若 x ≤ 1000：memo[x] = p
     返回 p
3. 把 [lo, hi] 的数按 (power(x), x) 双关键字升序排序
4. 返回排序后第 k 个
```

排序部分也可以偷懒不排全序：`nth_element`（C++ 快速选择）只保证第 $k$ 个就位，均摊 $O(m)$；$m \le 1000$ 时排序 $O(m \log m)$ 与之相差无几，写哪个都行。

### 3.4 示例演算

以示例 2 为例，先算区间内各数权重：

| $x$ | Collatz 链（步数） | 权重 |
|-----|---------------------|------|
| 7 | 7→22→11→34→17→52→26→13→40→20→10→5→16→8→4→2→1 | 16 |
| 8 | 8→4→2→1 | 3 |
| 9 | 9→28→14→7→（接上 7 的链，16 步）| 19 |
| 10 | 10→5→16→8→4→2→1 | 6 |
| 11 | 11→34→17→…（接 17 起的 13 步）| 14 |

按 $(权重, 数值)$ 排序：$(3,8), (6,10), (14,11), (16,7), (19,9)$，第 $k=4$ 个是 **7**。注意 9 的链走到 7 后**复用**了 7 的权重 16（$power(9) = 2 + 16 = 18$？——不：$9 \to 28 \to 14 \to 7$ 是 3 步，$power(9) = 3 + power(7) = 3 + 16 = 19$ ✓），这正是记忆化的意义：算 7 时的成果直接给 9、14、28 等所有「路过 7」的数共享。

## 4. 算法细节

1. **递归 vs 递推**：从小到大递推 $power[x] = 1 + power[x/2]$ 要求 $x/2 < x$ 已算好（偶数 OK），但奇数依赖 $3x+1 > x$ 尚未算——递推需要把数组开到中间值上界并按「链」而非「值序」处理，别扭；**递归 + 备忘录**天然处理「先大后小」的依赖，是首选。Python 记得调 `sys.setrecursionlimit`（链最长约 178 步，默认上限其实够，但保险起见）。
2. **缓存上界的取舍**：数组开 1001 只存「将来还会被问到/路过」的值。$x \le 1000$ 的 Collatz 链中间值最大 9232，若开 9233 的数组全存，查询全 $O(1)$ 但初始化与内存翻九倍；只存 $\le 1000$ 的则越界值走「裸递归」。本题 $m \le 1000$，两种都瞬间完成。
3. **排序关键字**：`(power(x), x)` 元组比较，Python 直接 `key=lambda x: (power(x), x)`；C++ 可 `pair<int,int>`（权重，数值）排序取第 k 个。
4. **`nth_element` 的比较器陷阱**：快速选择的比较器里**不要**惰性递归计算权重——比较器可能对同一元素反复调用，且要求严格弱序；正确做法是先把 $(power, x)$ 算好存进数组再 `nth_element`。
5. **链长上界**：$x \le 1000$ 时最大权重 178（$x = 871$ 或 $916$），32 位整数绰绰有余；题目也显式保证了这一点。
6. **别忘 memo[1] = 0**：递归基。若 memo 全零初始化，1 的权重自动为 0，但「未算」与「权重 0」的混淆要小心——本文用「单独赋值 + 判已算」避免歧义。

## 5. 正确性证明

**引理 1（递归公式的正确性）**：对任意正整数 $x$，Collatz 过程在有限步内到达 1（题面已保证），且 $power(x) = 1 + power(\text{next}(x))$，其中 $\text{next}(x) = x/2$（$x$ 偶）或 $3x+1$（$x$ 奇），$power(1) = 0$。

**证明**：权重按定义是「变成 1 的步数」。从 $x$ 走一步到 $\text{next}(x)$，此后从 $\text{next}(x)$ 到 1 的步数按定义即 $power(\text{next}(x))$（过程无记忆，从哪个数开始数步数都一样），故总步数 $= 1 + power(\text{next}(x))$。$x = 1$ 时已到达，0 步。∎

**引理 2（记忆化不改变结果）**：备忘录版本的 `power(x)` 与朴素递归对任意 $x$ 返回相同值。

**证明**：记忆化仅在「计算完成后的返回点」插入缓存读写，缓存值即朴素递归在该点的返回值（首次计算时写入）。后续命中缓存返回的正是同一递归式的解，与重新展开计算逐位一致。∎

**定理**：算法返回的数是 $[lo, hi]$ 按规则排序后的第 $k$ 个。

**证明**：由引理 1、2，每个 $x \in [lo, hi]$ 的权重计算正确。排序键为二元组 $(power(x), x)$，比较器为字典序：先按权重升序、同权重按数值升序——与题目排序规则逐字对应。对至多 1000 个元素做全序排序后取第 $k$ 个（$k \le$ 元素个数），即规则意义下的第 $k$ 名。∎

## 6. 复杂度分析

- **时间**：$O(m \cdot L + m \log m)$，$m = hi - lo + 1 \le 1000$，$L$ 为平均链长（$\le 178$）。记忆化把「同一数值的重复计算」全部消除，每个 $\le 1000$ 的数值至多完整计算一次，其后全部 $O(1)$ 命中；越过 1000 的中间值不缓存，至多被路过常数次。排序 $O(m \log m) \approx 10^4$；`nth_element` 可省至均摊 $O(m)$。
- **空间**：$O(1000 + D)$：memo 数组 1001 项；递归栈深至多链长 $L \le 178$ 帧外加越界段（不缓存时栈深 = 完整链长，仍 $O(L)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<int> memo;
    int power(int x) {                                    // 记忆化递归求权重
        if (x == 1) return 0;
        if (x <= 1000 && memo[x] != -1) return memo[x];
        int p = 1 + power(x % 2 == 0 ? x / 2 : 3 * x + 1);
        if (x <= 1000) memo[x] = p;
        return p;
    }
public:
    int getKth(int lo, int hi, int k) {
        memo.assign(1001, -1);
        vector<pair<int, int>> v;                         // (权重, 数值)
        for (int x = lo; x <= hi; ++x) v.emplace_back(power(x), x);
        nth_element(v.begin(), v.begin() + k - 1, v.end());
        return v[k - 1].second;
    }
};
```

### Python

```python
import sys
sys.setrecursionlimit(100000)

class Solution:
    def __init__(self):
        self.memo = {1: 0}

    def power(self, x: int) -> int:
        if x in self.memo:
            return self.memo[x]
        self.memo[x] = 1 + self.power(x // 2 if x % 2 == 0 else 3 * x + 1)
        return self.memo[x]

    def getKth(self, lo: int, hi: int, k: int) -> int:
        nums = sorted(range(lo, hi + 1), key=lambda x: (self.power(x), x))
        return nums[k - 1]
```

> 💡 两份代码均通过官方 2 组示例（13、7），并与「朴素迭代数步数 + 全排序」的暴力对拍 500 组随机区间加全域抽查（$[1,1000]$ 的 $k=1/500/1000$ 等）全部一致。注：C++ 版把权重先算进 `pair` 数组再 `nth_element`，避免了在比较器里惰性递归的隐患。

## 8. 边界情况与易错点

1. **链会越过 1000**：$power(27)$ 的链最高冲到 9232。若 memo 只开 1001 且无脑按下标访问越界值，直接数组越界 RE。本文写法是「$x \le 1000$ 才读写缓存，越界值裸递归」。
2. **`power(1) = 0` 别写成 1**：1 已经是 1，无需任何步。递归基错了全体权重 +1，排序可能错位。
3. **奇数判断用位运算或取模均可，但 0/1 边界**：$x = 1$ 是奇数，若忘记递归基会无限递归 $1 \to 4 \to 2 \to 1 \to \dots$。
4. **同权重的次序**：必须按数值升序。只按权重排序（稳定排序下保持原相对次序）在 $lo..hi$ 天然递增输入时碰巧等价，但写明双关键字才是保险做法。
5. **`nth_element` 的第 k 下标**：`k - 1`（0 基），且保证 $k \le m$ 有效；题目已保证 $1 \le k \le hi - lo + 1$。
6. **Python 的 memo 放实例字典**：LeetCode 对同一 Solution 实例可能多次调用，字典跨调用**复用**反而省时；若担心污染（不会，键值确定），可在 `getKth` 内重建。
7. **Collatz 猜想尚未被证明**：一般情形「任意正整数必到 1」是未解决问题；本题靠题面保证（步数是 32 位整数）才可递归不设防。工程上可给递归深度设哨兵。
