# LeetCode 安排电影院座位 题解

## 1. 题目概述

- **标题 / 题号**：安排电影院座位（#1386，medium）
- **链接**：https://leetcode.cn/problems/cinema-seat-allocation/
- **来源**：LeetCode 第 22 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、位运算、数组、哈希表

**题意**：影院有 $n$ 行座位（$n$ 可达 $10^9$），每行 10 个座位（编号 1–10）。给定预约表 `reservedSeats[i] = [row, seat]`。四人小组必须坐在同一行**连续**的一组可用座位上，且只允许以下三个座位块之一：$\{2,3,4,5\}$（记 A）、$\{4,5,6,7\}$（记 B）、$\{6,7,8,9\}$（记 C）。每个座位至多分配给一个小组。返回最多能安排的四人小组数。

**约束**：

- $1 \le n \le 10^9$
- $1 \le reservedSeats.length \le \min(10 n, 10^4)$
- $1 \le row_i \le n$，$1 \le seat_i \le 10$，预约互不相同

## 2. 示例

**示例 1**

```text
输入：n = 3, reservedSeats = [[1,2],[1,3],[1,8],[2,6],[3,1],[3,10]]
输出：4
解释：第 1 行座位 2、3 预约 → A 被破坏、B 可用 → 1 组；第 2 行座位 6 预约 →
      B、C 被破坏，A 可用 → 1 组；第 3 行座位 1、10 不属于任何块，三块全可用
      → A、C 同时安排 → 2 组。合计 1+1+2 = 4。
```

**示例 2**

```text
输入：n = 2, reservedSeats = [[2,1],[1,8],[2,6]]
输出：2
解释：第 1 行座位 8 → C 破坏，A、B 至多选一 → 1 组；第 2 行座位 6 → B、C
      破坏（A 由座位 1 无碍）→ 1 组。合计 2。
```

**示例 3**

```text
输入：n = 4, reservedSeats = [[4,3],[1,4],[4,6],[1,7]]
输出：4
解释：第 1 行预约 4、7：A 含 4 破坏、B 含 4、7 破坏、C 含 7 破坏 → 三块全灭，0 组；
      第 4 行预约 3、6：A 含 3 破坏、B 含 6 破坏、C 含 6 破坏 → 三块全灭，0 组；
      第 2、3 行无预约，各 2 组。合计 0+0+2+2 = 4。
```

注意第 1 行：预约只占了 4、7 两个座位，直觉上「剩 6 个空座总该塞下一组」——但四人组必须**恰好**落在 A/B/C 之一，座位 2、3 与 8、9 都凑不出合法块。这正是本题最常见的误判点，详见 §3.4 与 §8。

## 3. 解题思路

### 3.1 暴力思路

开 $n \times 10$ 的占用数组逐行枚举块组合。$n \le 10^9$ 直接内存爆炸；即使只开 `reservedSeats` 涉及的行（至多 $10^4$ 行），对每行枚举 A/B/C 的 $2^3$ 种使用组合也绰绰有余——真正的问题只剩「未涉及的 $n - 10^4$ 行怎么算」：它们每行必能坐满 2 组（A、C 同时可用）。于是规模塌缩到「只处理有预约的行」。

### 3.2 核心观察：一行 10 座只有 3 个候选块，位压缩成 8 位掩码

![10 个座位只有 3 个可行块：A / B / C](images/bw22_q2_seat_blocks.svg)

每行独立的子问题：三个块 A、B、C，其中 **A 与 C 不相交**（座位 2–5 与 6–9），可同时安排 2 组；**B 与 A、C 都相交**（共享 4、5 或 6、7），不能与任何块并存。结论一目了然：

- 三块全空 → 2 组（A + C）；
- 恰有一块空 → 1 组；
- 三块全被预约污染 → 0 组。

判定「块是否空」只需知道该行 8 个座位（2–9）的占用情况——座位 1 与 10 **不属于任何块，预约了也无影响**，可直接丢弃。把座位 $s \in [2, 9]$ 映射到位 $s - 2$，一行压成 8 位掩码，A、B、C 对应常量 `0x0F`、`0x3C`、`0xF0`，按位与为 0 即「该块可用」。

### 3.3 算法流程：哈希行号 + 位掩码聚合

![一行 10 座压成 8 位掩码，查表得该行组数](images/bw22_q2_bitmask_rows.svg)

```text
1. rows = {}                        # 行号 → 8 位占用掩码
   对每条预约 (r, s)：若 2 ≤ s ≤ 9，rows[r] |= 1 << (s−2)
2. total = 2 × (n − |rows|)         # 无预约行每行 2 组
3. 对 rows 中每个掩码 mask：
     a = (mask & 0x0F) == 0         # A 可用
     b = (mask & 0x3C) == 0         # B 可用
     c = (mask & 0xF0) == 0         # C 可用
     若 a 且 c：total += 2
     否则若 a 或 b 或 c：total += 1
4. 返回 total
```

$n$ 高达 $10^9$ 但只出现在第 2 步的乘法里，时间空间都与 $n$ 无关、只与预约数 $m$ 相关。

### 3.4 示例演算

**示例 1**（$n = 3$）：

| 行 | 预约座位 | 掩码（位 0..7 对应座 2..9） | A / B / C | 组数 |
|----|----------|------------------------------|-----------|------|
| 1 | 2, 3, 8 | `0b10000011` | A 含 2、3 破坏；B ✓；C 含 8 破坏 | 1 |
| 2 | 6 | `0b00010000` | A ✓；B、C 含 6 破坏 | 1 |
| 3 | 1, 10 | （丢弃，掩码 0） | 全空 | 2 |

无预约行数 $3 - 3 = 0$，合计 $1 + 1 + 2 = 4$ ✓。

**示例 3 的陷阱行**（预约 4、7）：掩码含位 2 与位 5，A（位 0–3）被位 2 污染、B（位 2–5）被两边污染、C（位 4–7）被位 5 污染——**三块全灭**，0 组。直觉上「预约只占了两个座，应该还能塞下一组」是错的：四个座位必须**连续且恰好落在三个合法块之一**，碎座位救不了场。

## 4. 算法细节

1. **座位 1、10 直接丢弃**：它们不属于任何合法块，预约了也白约。不丢弃则会把位映射做满 10 位，白白多两个恒 0/1 的位，还容易在移位下标上出错。
2. **同一行多次预约用「按位或」聚合**：`rows[r] |= bit`，天然去重（预约本身也保证互不相同，但「或」让逻辑不依赖这个保证）。
3. **常量掩码**：A = `0b00001111`（座 2–5 → 位 0–3）、B = `0b00111100`（座 4–7 → 位 2–5）、C = `0b11110000`（座 6–9 → 位 4–7）。三个常量写对，判定只有三次按位与。
4. **2 组条件是 a && c 而非「可用块数 ≥ 2」**：A 与 B 相交、B 与 C 相交，唯一的不相交对是 {A, C}。若写成 `count(可用块) >= 2 ? 2 : ...`，在「A、B 可用」时会错给 2 组（B 的座位 4、5 与 A 重叠）。
5. **哈希表键用行号**：`unordered_map<int,int>` / `dict`。$n$ 到 $10^9$，任何开数组的行为都不可行；$m \le 10^4$ 行哈希毫无压力。
6. **乘法溢出**（C++）：`2 * (n - |rows|)` 在 $n = 10^9$ 时约 $2 \times 10^9$，超出 `int` 上界，须用 `long long` 累加，返回前转 `int`（结果本身 ≤ $2 \times 10^9$……实际 $n \le 10^9$ 时结果上界 $2n = 2 \times 10^9$ 已超 `int`，LeetCode 本题返回 `int`——按题面 $n \le 10^9$ 且行数至多 $10^4$ 有预约，结果最大 $2 \times 10^9$ 恰好超界，稳妥起见中间全程 `long long`）。

## 5. 正确性证明

**引理 1（单行组数公式）**：设某行座位 2–9 的占用集合为 $S$。该行能安排的最多小组数为 $f(S) = 2$ 若 $S \cap A = S \cap B = S \cap C = \emptyset$（全空）；$f(S) = 1$ 若恰有一块与 $S$ 不交；$f(S) = 0$ 若三块都与 $S$ 相交。其中 $A = \{2,3,4,5\}$、$B = \{4,5,6,7\}$、$C = \{6,7,8,9\}$。

**证明**：小组必须整块使用三个块之一（题面限定），且块内座位全部空闲。一行内最多 2 组：10 个座位至多容纳 $\lfloor 8/4 \rfloor = 2$ 个互不相交的块（座位 1、10 永不可用，可用座位共 8 个）。达到 2 组需要两个互不相交的块都空闲：三块中唯一不相交的块对是 $(A, C)$（B 与 A 共享 $\{4,5\}$、与 C 共享 $\{6,7\}$），故 2 组 ⇔ A、C 均与 $S$ 不交 ⇔（此时 B 若也空闲不影响，仍只能选不相交对）三块全空。恰有一块空闲时该块可用而任何两块必相交（含 B 的组合相交、A-C 组合缺一个），至多 1 组，取 1。三块均被污染时无块可用，0 组。∎

**引理 2（行间独立）**：总组数等于各行组数之和。

**证明**：小组必须同一行内连续四座（题面），不存在跨行小组；行与行之间座位不相交，一行的占用不影响另一行可选的块。故各行可独立取最大，总和即全局最大。∎

**定理**：算法返回的 total 等于可安排小组数的最大值。

**证明**：无预约行的 $S = \emptyset$，由引理 1 得 2 组，共 $2(n - |\text{rows}|)$ 组；有预约行 $r$ 的占用集合编码为掩码 $\text{mask}(r)$（座位 $s \in [2,9]$ ↔ 位 $s-2$，或聚合保证与 $S$ 一致），算法按引理 1 的三分支给出 $f(S_r)$。由引理 2，总和即最大值。座位 1、10 被丢弃正确，因为它们不属于 $A \cup B \cup C$，对任何块的可否使用无影响。∎

## 6. 复杂度分析

- **时间**：$O(m)$。一次遍历预约建哈希表，一次遍历哈希表（至多 $\min(m, 10^4)$ 行）做三次按位与判定；与 $n$ 无关。
- **空间**：$O(m)$。哈希表至多存 $\min(m, 10^4)$ 个「行号 → 掩码」条目；掩码与计数均为常数空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxNumberOfFamilies(int n, vector<vector<int>>& reservedSeats) {
        unordered_map<int, int> rowMask;                  // 行号 → 8 位座位掩码
        for (const auto& rs : reservedSeats) {
            int s = rs[1];
            if (s >= 2 && s <= 9)                        // 座位 1、10 不属于任何块
                rowMask[rs[0]] |= 1 << (s - 2);
        }
        long long total = 2LL * (n - (long long)rowMask.size());  // 空行每行 2 组
        for (auto& [row, mask] : rowMask) {
            const int A = 0x0F, B = 0x3C, C = 0xF0;       // 座位 2-5 / 4-7 / 6-9
            bool a = !(mask & A), b = !(mask & B), c = !(mask & C);
            if (a && c) total += 2;
            else if (a || b || c) total += 1;
        }
        return (int)total;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxNumberOfFamilies(self, n: int, reservedSeats: List[List[int]]) -> int:
        A, B, C = 0b1111, 0b111100, 0b11110000   # 座位 2-5 / 4-7 / 6-9
        rows = {}
        for r, s in reservedSeats:
            if 2 <= s <= 9:                      # 座位 1、10 不属于任何块
                rows[r] = rows.get(r, 0) | (1 << (s - 2))
        total = 2 * (n - len(rows))              # 无预约行每行 2 组
        for mask in rows.values():
            a, b, c = not mask & A, not mask & B, not mask & C
            if a and c:
                total += 2
            elif a or b or c:
                total += 1
        return total
```

> 💡 两份代码均通过官方 3 组示例（4、2、4），并与「逐行枚举 A/B/C 全部 $2^3$ 使用组合 + 相交检查 + 预约检查」的暴力对拍 3000 组随机数据（$n \le 8$ 全行枚举核对）全部一致；另验证 $n = 10^9$、预约集中少数行时与「逐行暴力 + 空行补偿」结果一致（$1999999998$）。

## 8. 边界情况与易错点

1. **座位 1、10 是烟雾弹**：预约它们对答案零影响。若把 10 个座位全编进掩码，需要 10 位且判定常量全变，纯增错误面。
2. **「可用块数 ≥ 2」的错误判定**：唯一能并排 2 组的组合是 {A, C}。A、B 同时「可用」时只能选其一（B 的 4、5 与 A 重叠）。判定必须写 `a && c` 给 2 组。
3. **B 的角色**：B 只在「A、C 都不可用而 B 可用」时救场贡献 1 组；不要因为「B 居中」就先判 B。
4. **$n$ 到 $10^9$ 的两处坑**：不能开 $n$ 大小的数组（内存）；`2 * (n - |rows|)` 在 C++ 中要用 `long long`（$2 \times 10^9$ 溢出 `int`）。
5. **预约数组的行号可以稀疏**：`min(10n, 10^4)` 条预约分布在 $10^9$ 行里，哈希表大小只由预约数决定；空行用乘法一次性补齐，别逐行循环。
6. **示例 3 型陷阱**：两个预约（如 4 与 7）可同时杀死全部三块。人工演算时逐块检查「块内是否含任一预约座位」，别数空座个数。
7. **同一行多条预约**：或聚合天然处理；若误用「覆盖赋值」只留最后一条会漏判。
