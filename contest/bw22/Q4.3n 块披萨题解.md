# LeetCode 3n 块披萨 题解

## 1. 题目概述

- **标题 / 题号**：3n 块披萨（#1388，hard）
- **链接**：https://leetcode.cn/problems/pizza-with-3n-slices/
- **来源**：LeetCode 第 22 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、动态规划、堆（优先队列）

**题意**：披萨由 $3n$ 块大小不同的部分组成，顺时针排列成环形数组 `slices`。分配规则：你先任选一块；随后 Alice 拿走**逆时针方向**紧邻的一块，Bob 拿走**顺时针方向**紧邻的一块；重复（每轮你先选，两位朋友各拿走你所选块两侧的相邻块），直到披萨取完。你一共会选 $n$ 次，返回你能获得披萨大小总和的最大值。

**约束**：

- $1 \le slices.length \le 500$，且 $slices.length \equiv 0 \pmod 3$
- $1 \le slices[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：slices = [1,2,3,4,5,6]
输出：10
解释：先选 4，Alice/Bob 拿走 3 和 5；再选 6，Alice/Bob 拿走 2 和 1。总和 4+6 = 10。
```

**示例 2**

```text
输入：slices = [8,9,8,6,1,1]
输出：16
解释：两轮都选大小 8 的披萨。若先选 9，两个 8 都会被朋友拿走，总和反而小。
```

**示例 3（边界补充）**

```text
输入：slices = [1,2,3]
输出：3
解释：n = 1，你只能选一轮。选任一块后两侧都被拿走，选最大的 3。
```

## 3. 解题思路

### 3.1 暴力思路

直接模拟博弈：每轮你在剩余环上任选一块，朋友拿走两侧，共 $\binom{3n}{n}$ 量级的选法组合，用带记忆化的搜索（状态 = 剩余块的位掩码）在 $n \le 2$（6 块）时可行，$n = 3$（9 块、$2^9$ 状态）勉强，$n \ge 8$（24 块）时状态数指数爆炸。关键洞察藏在规则本身：**朋友的行为完全机械**（拿两侧相邻块），没有策略对抗——问题不是博弈，而是「你能构造出的选择序列」的结构刻画。

### 3.2 核心观察：环上互不相邻地选 n 个

![关键转化：环上取走一块，相邻两块必被朋友拿走](images/bw22_q4_ring_model.svg)

每轮 3 块披萨中你拿 1 块、朋友拿 2 块，共 $n$ 轮、$3n$ 块恰好分完——**你恰好拿到 $n$ 块**。你的每一块的两例邻居都被朋友即时拿走，于是：

- 你拿的任意两块**在原环上不相邻**（相邻则后选的那块早被朋友拿走）；
- 反过来，**环上任意 $n$ 个互不相邻的位置都能被你拿到**：按顺时针顺序依次选这些位置即可（每次你选的位置两侧都是「留给朋友」的块，归纳可证不会冲突，见引理 2）。

于是问题等价转化为：

> **在长度 $3n$ 的环上，选出恰好 $n$ 个互不相邻的位置，最大化选中的元素和。**

这是「打家劫舍 II」（#213，环上打家劫舍）的「恰好选 k 个」加强版。

### 3.3 算法流程：断环成链 + 双段链上 DP

![断环成链：首尾不能同取 → 拆成两条链分别 DP 取最大](images/bw22_q4_break_ring.svg)

环的处理是经典套路：**首尾两块在环上相邻，不能同时选**，故任一合法方案必落进两种情形之一——不选首块（剩下链 $slices[1..3n-1]$）或不选尾块（剩下链 $slices[0..3n-2]$）。两种情形各自是**链上**「选恰好 $j$ 个互不相邻元素的最大和」问题，取两者最大即覆盖全部方案（不选首也不选尾的方案在两段里都出现，不重复计最大值）。

链上 DP 的状态设计：$f[i][j][0/1]$ = 前 $i$ 个元素中选了 $j$ 个、第 $i$ 个**不选/选**的最大和。转移：

$$f[i][j][0] = \max(f[i-1][j][0],\ f[i-1][j][1]), \qquad f[i][j][1] = f[i-1][j-1][0] + a[i]$$

选第 $i$ 个时第 $i-1$ 个必须没选（互不相邻），且已选数减一。实现时按 $j$ 分层滚动（$j$ 从 1 到 $n$，层内递推 $i$），空间降到 $O(m)$。两条链各跑一遍，答案为

$$\max\big(\text{best}(slices[1..],\ n),\ \text{best}(slices[..3n-2],\ n)\big)$$

### 3.4 示例演算

![示例 1 演算：slices = [1,2,3,4,5,6]，n = 2，答案 10](images/bw22_q4_example_walkthrough.svg)

以示例 1（`[1,2,3,4,5,6]`，$n = 2$）为例：

- **情形一（弃首块 1）**：链 $[2,3,4,5,6]$，选 2 个互不相邻：候选 $\{2,4\}=6$、$\{2,5\}=7$、$\{2,6\}=8$、$\{3,5\}=8$、$\{3,6\}=9$、$\{4,6\}=10$ → 最优 **10**（选 4 和 6，中间隔 5）。
- **情形二（弃尾块 6）**：链 $[1,2,3,4,5]$，最优 $\{3,5\}=8$。

两情形取最大得 **10** ✓，与示例一致。对应到原博弈：先选 4（朋友拿 3、5），再选 6（朋友拿 2、1）——选中的 4、6 在原环上恰好不相邻。

## 4. 算法细节

1. **「恰好选 $n$ 个」不能省**：普通打家劫舍的 DP 是「至多选若干」，本题必须带 $j$ 维计数——环长 $3n$、选 $n$ 个是硬约束（多了意味着某两块相邻，少了意味着放弃应得的份额）。DP 中 $j$ 不满是非法状态，用 $-\infty$ 哨兵隔离。
2. **分层滚动的实现**：$f[\cdot][0/1]$ 表示「已选 $s$ 个」的层；从 $s=0$ 层（全不选、和 0）出发，逐层 $s = 1 \dots n$ 用上一层转移出新层。关键坑：$s=0$ 层的 $f[i][0]$ 对**所有** $i$ 都是 0（前 $i$ 个一个不选恒可行），不是只有 $i=0$。
3. **哨兵 $-\infty$ 的取值**：C++ 用 `INT_MIN / 2` 防止相加溢出；Python 用 `float('-inf')`。
4. **两段链的构造**：`slices[1:]` 与 `slices[:-1]`，长度都是 $3n - 1$；不必担心 $n = 1$（3 块）时链长 2、选 1 个——两段分别给 $\max(s[1], s[2])$ 与 $\max(s[0], s[1])$，合起来覆盖三块中任选一块的最大值 $s$ 的最大元素，正确。
5. **答案的界**：$n \le 166$（$3n \le 500$）、每块 $\le 1000$，总和 $\le 1.66 \times 10^5$，`int` 充裕。
6. **复杂度核对**：两条链各 $O(n \cdot 3n) = O(n^2)$（准确说 $O(n \cdot m)$，$m = 3n - 1$），$n \le 166$ 时约 $8 \times 10^4$ 状态转移，毫秒级。

## 5. 正确性证明

**引理 1（可行性刻画）**：你拿到的大小多重集 $S$ 合法（存在按规则行棋的选择序列），当且仅当 $S$ 由环上 $n$ 个**互不相邻**位置上的元素组成。

**证明**：（⇒）设你在第 $t$ 轮选了位置 $p_t$。归纳证明任意两轮位置在原环上不相邻：第 $t$ 轮你选 $p_t$ 后，$p_t$ 的两个**当前邻居** $q, q'$ 立即被 Alice/Bob 拿走，故 $p_t$ 与其后任意一轮所选位置都不相邻（后续轮次只能选当时仍在场的位置）。特别地所有 $p_t$ 两两不相邻。又每轮恰好消耗 3 块（你 1 + 朋友 2），$n$ 轮后 $3n$ 块取完，你恰好 $n$ 块。
（⇐）设位置集 $P = \{p_1 < p_2 < \dots < p_n\}$（顺时针序）两两不相邻。按顺时针从任意 $p_1$ 起依次选：选 $p_t$ 时，它的两侧邻居若在场则被朋友拿走——需证 $p_{t+1}$ 不会在 $p_t$ 的两侧已被拿走之列。$P$ 两两不相邻保证 $p_{t+1}$ 不是 $p_t$ 的直接邻居。更进一步归纳假设「选完 $p_t$ 后，被拿走的位置恰为 $\{p_1..p_t\}$ 及每个 $p_s$（$s \le t$）选时两侧的邻居，且 $P$ 中其余位置仍在场」：选 $p_s$ 时其两侧邻居 $q, q'$ 不属于 $P$（$P$ 内不相邻），也不属于已拿走集合（在场才可被拿），故被拿走的恰是场外位置，$P$ 内其余位置不受影响。归纳成立，$n$ 轮后你拿到全部 $P$。∎

**引理 2（环到两链的覆盖）**：环上任取 $n$ 个互不相邻位置的方案，其位置集必不含首块、或不含尾块（或两者皆不含）；反之，链 $slices[1..]$（不含首）与链 $slices[..3n-2]$（不含尾）上各自的「$n$ 个互不相邻」方案都是环上的合法方案。

**证明**：首尾两块在环上相邻，由不相邻性任何方案不能同时含两者，故必落「不含首」或「不含尾」两侧（可能都不含）。反之，链上 $n$ 个互不相邻的位置放回环中：链内相邻关系与环一致（只是少了首尾相邻这条边），链上不相邻 ⇒ 环上亦然（环的相邻对更多只会更严，方案满足更严的约束）。特别地，不含首块的链方案不会用到「首尾相邻」这条环边，故在环上合法；不含尾同理。∎

**引理 3（链 DP 正确性）**：$f[i][j][0/1]$ 经所述转移计算后，等于「前 $i$ 个元素中选恰好 $j$ 个互不相邻元素、第 $i$ 个不选/选」的最大和（不可行时 $-\infty$）。

**证明**：对 $i$ 归纳。$i = 0$：选 0 个且「无第 0 个」状态 $f[0][0][0] = 0$，其余 $-\infty$，与边界一致。设 $i - 1$ 层正确。$f[i][j][0]$：不选第 $i$ 个，方案仅由前 $i - 1$ 个构成，且第 $i - 1$ 个选不选皆可，最大值即 $\max(f[i-1][j][0], f[i-1][j][1])$。$f[i][j][1]$：选第 $i$ 个，第 $i - 1$ 个必须不选（相邻约束），剩余 $j - 1$ 个名额在前 $i - 1$ 个中且第 $i - 1$ 个不选，最大值 $f[i-1][j-1][0] + a[i]$。转移穷尽了两种情形且无遗漏，归纳成立。∎

**定理**：算法返回值等于博弈中你能获得的最大总和。

**证明**：由引理 1，博弈的最优值 = 环上选 $n$ 个互不相邻位置的最大元素和。由引理 2，该最大值 = $\max(\text{链}_1 \text{最优}, \text{链}_2 \text{最优})$，其中链最优由引理 3 的 DP 以 $f[m][n][0/1]$ 之最大正确给出（分层滚动不改变值，只是按 $j$ 维重排计算顺序）。三层串联，算法输出即博弈最优值。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot m) = O(n^2)$，$m = 3n - 1$。两条链各跑一遍 $j \times i$ 的双层递推；$n \le 166$ 时约 $1.6 \times 10^5$ 次转移，毫秒级。
- **空间**：$O(m)$。分层滚动只保留相邻两层（当前 $s$ 层与 $s-1$ 层），每层 $m + 1$ 个二元组；输入本身 $O(3n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
    // 链 a[0..m-1] 上选恰好 j 个互不相邻元素的最大和（分层滚动，层 = 已选个数）
    int best(const vector<int>& a, int j) {
        int m = (int)a.size();
        if (j <= 0) return 0;
        const int NEG = INT_MIN / 2;
        vector<vector<int>> f(m + 1, vector<int>(2, NEG));
        for (int i = 0; i <= m; ++i) f[i][0] = 0;        // s = 0 层：全不选恒为 0
        for (int s = 1; s <= j; ++s) {
            vector<vector<int>> g(m + 1, vector<int>(2, NEG));
            for (int i = 1; i <= m; ++i) {
                g[i][0] = max(g[i - 1][0], g[i - 1][1]); // 不选第 i 个
                g[i][1] = f[i - 1][0] + a[i - 1];        // 选第 i 个
            }
            f.swap(g);
        }
        return max(f[m][0], f[m][1]);
    }
public:
    int maxSizeSlices(vector<int>& slices) {
        int n = (int)slices.size() / 3;
        vector<int> skipFirst(slices.begin() + 1, slices.end());  // 弃首块
        vector<int> skipLast(slices.begin(), slices.end() - 1);   // 弃尾块
        return max(best(skipFirst, n), best(skipLast, n));
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxSizeSlices(self, slices: List[int]) -> int:
        def best(a, j):
            """链 a 上选恰好 j 个互不相邻元素的最大和。"""
            m, NEG = len(a), float('-inf')
            # f[i][0/1]：前 i 个里选了 s 个、第 i 个不选/选 的最大和
            f = [[0, NEG] for _ in range(m + 1)]  # s = 0 层：全不选，恒为 0
            for s in range(1, j + 1):             # 按已选个数分层滚动
                g = [[NEG, NEG] for _ in range(m + 1)]
                for i in range(1, m + 1):
                    g[i][0] = max(g[i - 1][0], g[i - 1][1])   # 不选第 i 个
                    g[i][1] = f[i - 1][0] + a[i - 1]           # 选第 i 个
                f = g
            return max(f[m][0], f[m][1])
        n = len(slices) // 3
        return max(best(slices[1:], n), best(slices[:-1], n))
```

> 💡 两份代码均通过官方 2 组示例（10、16）与边界 $[1,2,3] \to 3$，并与**真实博弈的带记忆化全搜索**（状态 = 剩余块位掩码，枚举你每轮的全部选择，朋友按规则拿两侧）对拍 2000 组随机博弈（$n \le 3$）全部一致，另核对 12 块用例 `[9,8,1,7,7,7,7,6,3,3,4,5]`（双方一致为 29）。

## 8. 边界情况与易错点

1. **转化是全题的命门**：没看出「互不相邻选 $n$ 个」的等价性就只能对着博弈模拟硬啃。记住朋友是**机械**的（无策略），所以这不是 min-max 博弈，是结构刻画 + DP。
2. **断环的两段都要跑**：只跑「弃首」会漏掉「选了尾块」的方案族（如示例 1 若答案需要 6 就只能从弃首段拿到，但对称场景需要弃尾段）；正确姿势恒为两段取 max。
3. **「恰好 $n$ 个」的 $j$ 维**：漏掉 $j$ 维变成普通打家劫舍会多选（$3n$ 个里选出远超 $n$ 个互不相邻的位置），答案虚高。$j$ 维不可省。
4. **$s = 0$ 层的正确初始化**：前 $i$ 个全不选对任意 $i$ 可行、值为 0；若只把 $f[0][0]$ 置 0 其余 $f[i][0]$ 留 $-\infty$，第 1 个之后的位置无法作为「第一个被选元素」的出发点（选 $i$ 要查 $f[i-1][0]$），DP 全线崩溃——这是实现时最常见的一处错。
5. **`NEG` 哨兵防溢出**：`INT_MIN` 直接加 `a[i]` 会回绕成正数；除以 2 或用 `long long`。Python 的 `-inf` 无此虑。
6. **$n = 1$（3 块）**：两段链长均为 2，各自「选 1 个」的最大值合并后恰为三块之最大，无需特判。
7. **别用贪心（堆 + 反悔）**：直觉的「每轮拿当前最大」是错的（示例 2 里先拿 9 会送走两个 8）；存在反悔贪心（双向链表 + 懒删除堆）能做本题，但复杂度与正确性论证都远难于断环 DP，比赛场景下 DP 是正解。
