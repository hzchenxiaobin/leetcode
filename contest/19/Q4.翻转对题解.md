# LeetCode 翻转对 题解

## 1. 题目概述

- **标题 / 题号**：翻转对（#493，hard）
- **链接**：https://leetcode.cn/problems/reverse-pairs/
- **来源**：LeetCode 第 19 场周赛 Q4
- **难度**：困难
- **标签**：归并排序，分治，树状数组，线段树，二分查找，有序集合

**题意**：给定数组 `nums`，统计满足 $i < j$ 且 $\texttt{nums}[i] > 2 \cdot \texttt{nums}[j]$ 的下标对 $(i,j)$ 的数量。与普通「逆序对」的两点差别决定全部难点：比较对象是**两倍值**，且关系是**严格大于**（`nums[i] == 2 * nums[j]` 不算一对）。

**约束**：

- $1 \le n \le 5 \times 10^4$（题面表述为「长度不会超过 50000」）
- $-2^{31} \le \texttt{nums[i]} \le 2^{31} - 1$，即 32 位整数范围；因此 $2\cdot\texttt{nums}[j]$ 可达 $-2^{32}$ 或 $2^{32}-2$，**在 32 位 `int` 中溢出**，必须用 64 位中间量。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,2,3,1]
输出：2
解释：合法对为 (1,4)：nums[1]=3 > 2*nums[4]=2；(3,4)：nums[3]=3 > 2*nums[4]=2；
      而 (0,4) 不合法：1 > 2*1 不成立。
```

**示例 2**

```text
输入：nums = [2,4,3,5,1]
输出：3
解释：合法对为 (1,4)：4 > 2*1、(2,4)：3 > 2*1、(3,4)：5 > 2*1。
      而 (0,4)：2 > 2*1 不成立（严格大于）。
```

两个示例的合法对全部落在「前面大、后面小」的方向上，这正是「翻转」的含义；但判定尺度翻倍，且不能容忍相等。

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举 $i < j$，逐个判断 `nums[i] > 2 * nums[j]`，时间 $O(n^2)$，空间 $O(1)$。

$n = 5\times10^4$ 时最坏要比较 $n(n-1)/2 \approx 1.25 \times 10^9$ 次，远超时限。

能否先排序？**不行**。题目要求 $i < j$，排序会把下标关系彻底打乱；即使记录原始下标，排序后仍需二维统计，并没有变简单。

突破口在于：排序虽然破坏了下标顺序，但**分治可以把「下标顺序」切成两半来保持**——左半的下标一定小于右半的下标。

### 3.2 核心观察：分治 + 跨区间单调双指针

![分治：跨区间计数](images/wc19_q4_divide_conquer_concept.svg)

把区间 $[l,r]$ 以 $m$ 为界切成左右两半，重要对分成三类，**互不重叠、完全覆盖**：

$$\text{ans}(l,r) = \text{ans}(l,m) + \text{ans}(m+1,r) + \text{cross}(l,m,r)$$

- 前两类递归求解；
- 第三类 `cross` 里，$i$ 在左半、$j$ 在右半，**下标条件 $i<j$ 自动成立**，只需处理值条件。

于是问题变成：给定两个数组 $L$、$R$，数出多少对 $(x \in L, y \in R)$ 满足 $x > 2y$。

**关键性质**：递归返回后，$L$ 与 $R$ 各自**已经升序**（归并排序的副产物）。在两侧有序的前提下：

- 固定 $x$，满足 $2y < x$ 的 $y$ 在 $R$ 中构成一个**前缀**（$R$ 升序）；
- 让 $x$ 从小到大遍历 $L$，阈值 $x/2$ 单调上升，这个前缀**只增不减**。

所以用一个指针 $j$ 指向「$R$ 中第一个不满足 $2R[j] < L[i]$ 的位置」，$j$ 只向右走，全程 $O(\lvert L \rvert + \lvert R \rvert)$。这就是本题的核心。

> 💡 计数必须发生在**归并之前**。一旦把两段合并成一个有序数组，左右边界就消失了，再也没法区分「跨区间」的对。

### 3.3 算法流程

![mergeSort 流程](images/wc19_q4_merge_count_flow.svg)

```text
solve(l, r):
    if l >= r: return                    # 长度 0/1，无对可数
    m = l + (r - l) / 2
    solve(l, m)                          # 左半内部
    solve(m + 1, r)                      # 右半内部
    j = m + 1                            # 跨区间双指针
    for i = l .. m:
        while j <= r and 2 * a[j] < a[i]: j++    # 严格大于，用 64 位乘
        ans += j - (m + 1)               # R[0 .. j-(m+1)-1] 全部合法
    merge(a[l..m], a[m+1..r])            # 普通归并，保证上一层有序
```

两点注意：

1. `j` 在**每个递归节点内**从 `m + 1` 出发，节点之间互不影响；
2. 循环退出时 `j` 停在第一个不合法位置，贡献数就是 `j - (m + 1)`。

### 3.4 示例演算

![示例 [1,3,2,3,1] 走查](images/wc19_q4_example_walkthrough.svg)

对 `nums = [1,3,2,3,1]`，分治树自底向上共 4 次合并，每次都先计数再归并：

| 合并区间 | 左半 $L$ | 右半 $R$ | 双指针过程 | 本次 | 累计 |
|---|---|---|---|---|---|
| $(0,1)$ | `[1]` | `[3]` | $1 > 6$ ✗，$j$ 不动 | 0 | 0 |
| $(0,2)$ | `[1,3]` | `[2]` | $1>4$ ✗，$3>4$ ✗ | 0 | 0 |
| $(3,4)$ | `[3]` | `[1]` | $3>2$ ✓，$j$ 越过 $r$ | 1 | 1 |
| $(0,4)$ | `[1,2,3]` | `[1,3]` | $1>2$ ✗，$2>2$ ✗，$3>2$ ✓，$3>6$ ✗ | 1 | **2** |

第 3 行：$j=4$ 时 $2 \times 1 = 2 < 3$，$j$ 移到 5（越界），贡献 $5-4=1$。
第 4 行：$j$ 从 3 开始，$i=2$（值为 3）时 $3 > 2 \times 1$ 成立，$j$ 移到 4，又被 $2 \times 3 = 6$ 拦住，贡献 $4-3=1$。
最终答案 2，与示例 1 一致。

## 4. 算法细节

1. **先数后并，顺序不可交换**。计数依赖「左右两半各自有序但尚未合并」的状态；若先合并再计数，跨区间下标关系被销毁。
2. **双指针的单调性来源**。$L$ 升序 ⇒ 阈值 $L[i]$ 单调不减 ⇒ 合法前缀不缩短 ⇒ $j$ 只进不退。因此 `while` 内层总共执行 $O(len)$ 次，而不是每个 $i$ 都从 $m+1$ 重扫（那会退化成 $O(len^2)$）。
3. **严格大于的写法**。判定写成 `2LL*a[j] < a[i]` 时 `j++`，等价于「不满足 `a[i] > 2a[j]` 就停」。若写成 `<=`，`[2,1]` 会被误算 1 对。
4. **溢出**。`a[i]` 可达 $2^{31}-1$、`a[j]` 可达 $-2^{31}$，`2*a[j]` 为 $-2^{32}$，32 位 `int` 溢出行为未定义（实际常回绕成正数，比较全错）。C++ 用 `2LL * a[j]`；不要改成 `a[i] / 2 > a[j]`，因为 C++ 整数除法向零取整：`a[i]=3, a[j]=1` 时 `3 > 2` 为真，而 `3/2=1 > 1` 为假，会漏数。
5. **答案范围**。最多 $n(n-1)/2 = 1\,249\,975\,000 < 2^{31}-1$，返回值 `int` 放得下；但累加器用 `long long` / Python `int` 更稳妥，也便于对照暴力。
6. **辅助数组复用**。`tmp` 只分配一次，归并时写到 `tmp[l..r]` 再整体回写；避免每层新建 `vector` 带来的常数开销。
7. **递归深度与稳定性**。$O(\log n) \approx 16$ 层，栈安全；归并时相等元素谁先谁后不影响计数（计数在合并前完成），`<=` / `<` 只影响排序稳定性。

## 5. 正确性证明

**引理 1（不重不漏）**：任意一对下标 $i < j$，恰好在分治树中唯一的节点被计入 `cross`。

**证明**：取分治树上最小的、使 $i$ 与 $j$ 分居左右两半的节点 $v$（即二者的 LCA 对应的合并节点）。在 $v$ 的所有祖先节点上，$i$ 与 $j$ 同处一侧，只可能被当作「内部对」继续下传，不会进入 `cross`；在 $v$ 的所有后代节点上，$i$ 与 $j$ 至少有一个不在该节点区间内，根本不会被枚举。而在 $v$ 处 $i$ 必在左半、$j$ 必在右半（因为 $i < j$ 且分界点为 $m$），故被 `cross` 计数一次。∎

**引理 2（双指针计数精确）**：设某节点左右两半已分别升序，令 `j` 为该节点内单调右移的指针，则对每个 $i \in [l,m]$，`j - (m+1)` 等于右半中满足 $2a[k] < a[i]$ 的元素个数，且 $j$ 全程总移动量不超过 $r-l+1$。

**证明**：右半升序 ⇒ 若 $2a[k] < a[i]$ 且 $k' < k$，则 $2a[k'] \le 2a[k] < a[i]$，合法下标构成前缀 $[m+1, j^{*}-1]$。`while` 循环不变量「$j$ 及其左边全部合法、$j$ 是第一个不合法位置」在每次 `j++` 前后均成立，循环结束时 $j = j^{*}$，贡献数 $j - (m+1) = j^{*} - (m+1)$ 正确。又 $a[i]$ 随 $i$ 递增，合法前缀不会缩短，故新 $j^{*}$ 不小于旧值，$j$ 单调右移，总移动量 $O(r-l+1)$。∎

**引理 3（有序性不变式）**：`solve(l,r)` 返回后，$a[l..r]$ 升序；且 `ans` 恰增加区间内全部合法对数。

**证明**：对区间长度归纳。$l \ge r$ 时显然。否则递归调用由归纳假设返回两个升序段，引理 2 保证 `cross` 计数精确，引理 1 保证本层新增的对不与其他层重复；随后的归并把两个升序段合并为升序段，不变式成立。∎

**定理**：`solve(0, n-1)` 结束后，`ans` 等于数组 $a$ 中重要翻转对的总数。

**证明**：由引理 3 取 $[l,r] = [0,n-1]$，$a[0..n-1]$ 覆盖全部下标，`ans` 恰为区间内所有合法对数，而按定义这正是所求。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。递归式 $T(n) = 2T(n/2) + O(n)$：每层计数 $O(len)$（双指针总移动量有界）、归并 $O(len)$，共 $\log n$ 层。$n = 5\times10^4$ 时约 $8\times10^5$ 次基本操作，相比暴力的 $1.25\times10^9$ 次少了约三个数量级。
- **空间**：$O(n)$。辅助数组 `tmp` 占 $n$ 个元素；递归栈 $O(\log n)$。除此之外只用了常数个指针与计数器。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
    long long ans = 0;
    vector<int> tmp;

    void mergeSort(vector<int>& a, int l, int r) {
        if (l >= r) return;
        int m = l + (r - l) / 2;
        mergeSort(a, l, m);
        mergeSort(a, m + 1, r);

        // 先计数：此刻 a[l..m] 与 a[m+1..r] 各自升序
        int j = m + 1;
        for (int i = l; i <= m; ++i) {
            while (j <= r && (long long)a[i] > 2LL * a[j]) ++j;  // 严格大于
            ans += j - (m + 1);
        }

        // 再归并，保证上一层拿到有序数组
        int p = l, q = m + 1, k = l;
        while (p <= m && q <= r) {
            if (a[p] <= a[q]) tmp[k++] = a[p++];
            else tmp[k++] = a[q++];
        }
        while (p <= m) tmp[k++] = a[p++];
        while (q <= r) tmp[k++] = a[q++];
        for (int t = l; t <= r; ++t) a[t] = tmp[t];
    }

public:
    int reversePairs(vector<int>& nums) {
        int n = nums.size();
        if (n < 2) return 0;
        tmp.assign(n, 0);
        ans = 0;
        mergeSort(nums, 0, n - 1);
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def reversePairs(self, nums: list[int]) -> int:
        n = len(nums)
        if n < 2:
            return 0
        tmp = [0] * n
        self.ans = 0

        def sort(l: int, r: int) -> None:
            if l >= r:
                return
            m = (l + r) // 2
            sort(l, m)
            sort(m + 1, r)

            # 先计数：两侧已各自升序，j 单调右移
            j = m + 1
            for i in range(l, m + 1):
                while j <= r and nums[i] > 2 * nums[j]:
                    j += 1
                self.ans += j - (m + 1)

            # 再归并
            p, q, k = l, m + 1, l
            while p <= m and q <= r:
                if nums[p] <= nums[q]:
                    tmp[k] = nums[p]
                    p += 1
                else:
                    tmp[k] = nums[q]
                    q += 1
                k += 1
            while p <= m:
                tmp[k] = nums[p]
                p += 1
                k += 1
            while q <= r:
                tmp[k] = nums[q]
                q += 1
                k += 1
            nums[l:r + 1] = tmp[l:r + 1]

        sort(0, n - 1)
        return self.ans
```

## 8. 边界情况与易错点

1. **长度为 0 或 1**：直接返回 0。LeetCode 约束下 $n \ge 1$，但本地对拍常传空数组，代码里保留 `n < 2` 判断最安全。
2. **严格大于**：`[2,1]` 的答案是 0（$2 > 2 \times 1$ 不成立），`[3,1]` 才是 1。写成 `>=` 会把所有「恰好两倍」的对误算进来。
3. **32 位溢出**：`2 * nums[j]` 在 `int` 下溢出。反例 `[-2147483648, -2147483648]` 的正确答案是 1（$-2^{31} > -2^{32}$），而 `2 * nums[j]` 回绕成 `0` 会把答案判成 0。用 `2LL` 提升；也不要用除法替代乘法（负数向零取整会漏判，如 `a[i]=3, a[j]=1`）。
4. **先数后并**：把计数挪到 `merge` 之后，左右边界已消失，`cross` 无法再算；这是最常见的手写顺序错误。
5. **`j` 不重置**：`j` 必须在上层 `for i` 之前初始化一次，循环内只增不减；每个 `i` 都重置会让复杂度退化为 $O(n^2)$，虽然答案仍正确但必然超时。
6. **负数与 0**：因为乘 2 保序（$x \le y \iff 2x \le 2y$），升序性质对负数同样成立，无需分类讨论；`0` 也只是普通值，`0 > 0` 不成立。
7. **答案上界与多实例调用**：$n=5\times10^4$ 时最多 $1\,249\,975\,000$ 对，`int` 够用；但若上界放宽到 $n > 65536$，$\binom{n}{2}$ 会超过 $2^{31}-1$，故累加器用 `long long` 更稳。另外 `ans` 是成员变量，`reversePairs` 开头必须重置为 0（不能依赖「每个用例新建实例」）。
