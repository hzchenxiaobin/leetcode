# LeetCode 一个图中连通三元组的最小度数 题解

## 1. 题目概述

- **标题 / 题号**：一个图中连通三元组的最小度数（#1761，hard）
- **链接**：https://leetcode.cn/problems/minimum-degree-of-a-connected-trio-in-a-graph/
- **来源**：LeetCode 第 228 场周赛 Q4
- **难度**：困难
- **标签**：图、枚举、暴力

**题意**：给定一个 $n$ 个节点的无向图，`edges[i] = [ui, vi]` 表示 $u_i$ 与 $v_i$ 之间有一条无向边。

- **连通三元组**：三个节点组成的集合，且这三个点**两两有边**（即图中的一个三角形 $K_3$）。
- **三元组的度数**：所有「一个顶点在三元组内、另一个顶点不在此三元组内」的边的数目（即从三角形「跨出去」的边数）。

返回所有连通三元组度数的**最小值**；若图中不存在连通三元组，返回 $-1$。

**约束**：

- $2 \le n \le 400$
- $1 \le \text{edges.length} \le \dfrac{n(n-1)}{2}$
- $1 \le u_i, v_i \le n$，$u_i \ne v_i$
- 图中没有重复的边

> 💡 **数据范围是最大的提示**：$n \le 400$ 意味着 $O(n^3) \sim 6.4 \times 10^7$（实际枚举三元组只有 $\binom{400}{3} \approx 1.06 \times 10^7$ 个）是可以接受的——「无脑枚举所有三元组」正是本题预期的解法，难点只剩**如何 $O(1)$ 算出每个三元组的度数**。

## 2. 示例

**示例 1**

```text
输入：n = 6, edges = [[1,2],[1,3],[3,2],[4,1],[5,2],[3,6]]
输出：3

解释：图中唯一的连通三元组是 {1,2,3}。
- 内部边：1-2、1-3、2-3
- 跨出边：1-4、2-5、3-6，共 3 条 → 度数为 3
```

**示例 2**

```text
输入：n = 7, edges = [[1,3],[4,1],[4,3],[2,5],[5,6],[6,7],[7,5],[2,6]]
输出：0

解释：共 3 个连通三元组：
1) {1,3,4}：度数为 0
2) {2,5,6}：度数为 2
3) {5,6,7}：度数为 2
最小值为 0。
```

## 3. 解题思路

### 3.1 暴力思路

按定义模拟：枚举所有 $\binom{n}{3}$ 个三点组合，对每个组合做两件事：

1. **判定是否为连通三元组**：检查三条边是否存在。用邻接矩阵可以 $O(1)$ 完成。
2. **统计度数**：朴素做法是遍历全部 $m$ 条边，数出「恰有一个端点在组内」的边数，$O(m)$。

总复杂度 $O\!\left(\binom{n}{3} \cdot m\right)$，取 $n = 400$、$m \approx 8 \times 10^4$ 时约 $8 \times 10^{11}$，不可行。

> ⚠️ 瓶颈不在「枚举三元组」，而在「每个三元组花 $O(m)$ 统计度数」。只要把度数统计降到 $O(1)$，整题就通了。

### 3.2 核心观察：度数公式

![三元组度数公式推导](images/trio_degree_formula.svg)

预处理每个节点的度数 $deg(\cdot)$ 之后，任意连通三元组 $\{u, v, w\}$ 的度数可以 $O(1)$ 算出：

$$\text{degree}(\{u,v,w\}) = deg(u) + deg(v) + deg(w) - 6$$

直观理解——把三个点的度数**加起来**时，图中的边按端点落点分三类记账：

| 边的类型 | 在度和 $deg(u)+deg(v)+deg(w)$ 中被计的次数 | 说明 |
|---|---|---|
| 两端都在三元组内（$uv$、$uw$、$vw$） | 每条计 **2 次** | 两个端点各贡献 1，多算了 $3 \times 2 = 6$ |
| 恰有一端在三元组内 | 每条计 **1 次** | 这正是**度数的定义** |
| 两端都在三元组外 | 计 0 次 | 不涉及这三个点的度数 |

于是「度和 = 内部边贡献 6 + 跨出边数目」，移项即得公式。用示例 1 验证：$deg(1)+deg(2)+deg(3) = 3+3+3 = 9$，$9 - 6 = 3$，与直接数跨出边（1-4、2-5、3-6）的结果一致。

### 3.3 算法流程：枚举所有三元组

![算法流程图](images/trio_enumeration_flow.svg)

**C++ 版（邻接矩阵 + 三重循环）**：

1. 预处理：邻接矩阵 `adj[u][v]`（bool）与度数数组 `deg[u]`。
2. 按 $u < v < w$ 的固定顺序三重循环，保证每个三点集合**恰好被枚举一次**。
3. 若 `adj[u][v] && adj[u][w] && adj[v][w]` 成立，即为连通三元组，用度数公式 $O(1)$ 更新答案。
4. 若答案从未被更新，说明图中无三角形，返回 $-1$。

**Python 版（枚举边 + 邻接集求交）**：纯 Python 三重循环跑 $10^7$ 次会超时，改用等价的枚举方式：

1. 邻接表用 `set` 存储。
2. 对每条边 $(u, v)$（规范化为 $u < v$），取公共邻居集合 $adj[u] \cap adj[v]$（C 层完成的集合交）。
3. 其中满足 $w > v$ 的点 $w$ 与 $u, v$ 构成三元组 $\{u < v < w\}$，用公式更新答案。

两种枚举方式都保证每个三元组**不重不漏**地被考虑一次（见 §5 引理 2）。

### 3.4 示例演算

![示例 2 的三个三元组演算](images/trio_example_walkthrough.svg)

以示例 2 为例走一遍完整流程。各点度数为 $deg = [2, 2, 2, 2, 3, 3, 2]$（下标 $1 \sim 7$）：

- 三元组 $\{1,3,4\}$：度数 $= 2+2+2-6 = 0$
- 三元组 $\{2,5,6\}$：度数 $= 2+3+3-6 = 2$
- 三元组 $\{5,6,7\}$：度数 $= 3+3+2-6 = 2$

三个结果都能与「直接数跨出边」对上，答案为 $0$。注意 $\{2,5,6\}$ 和 $\{5,6,7\}$ 共享边 5-6——同一条边对不同三元组既可能是内部边也可能是跨出边，这正是公式按「端点记账」的优势：不需要知道每条边扮演什么角色。

## 4. 算法细节

1. **邻接矩阵用 `vector<vector<char>>`**：$401 \times 401$ 的 `char` 矩阵约 160KB，查询 $O(1)$。不要用 `map`/`set` 存 C++ 邻接（每次查询带 $\log$ 因子且常数大）。
2. **度数数组在读边时顺手累加**：`deg[u]++`、`deg[v]++`，无需单独一轮统计。
3. **枚举顺序固定为 $u < v < w$**：任意三点集合排序结果唯一，因此不重不漏；若不排序，同一三元组会被枚举 $3! = 6$ 次，白白慢 6 倍。
4. **v 层先剪枝**：进入 $w$ 层循环前先判 `adj[u][v]`，非边点对直接跳过，稀疏图上显著加速。
5. **Python 求交写法**：`adj[u] & adj[v]` 的复杂度是 $O(\min(deg(u), deg(v)))$（遍历小集合、在大集合中哈希查找），最坏（近完全图）约 $3.2 \times 10^7$ 次底层操作，Python 可以承受。
6. **答案上界**：最大度数为 $n - 1 = 399$，度数最大 $3 \times 399 - 6 = 1191$，`int` 完全够用，无溢出风险。

## 5. 正确性证明

**引理 1（度数公式）**：对连通三元组 $T = \{u, v, w\}$，有 $\text{degree}(T) = deg(u) + deg(v) + deg(w) - 6$。

**证明**：设 $S = deg(u) + deg(v) + deg(w)$。$S$ 中的每一项都来自某条边的一个端点，故可按边对 $S$ 的总贡献分类：

- 两端都在 $T$ 内的边：由于 $T$ 是连通三元组，恰为 $uv$、$uw$、$vw$ 三条（无重复边保证不重计），每条的两个端点都在 $T$ 中，各贡献 1，共贡献 $2$，合计 $6$；
- 恰有一端在 $T$ 内的边：只有一个端点在 $T$ 中，贡献 $1$，此类边的数目按定义即为 $\text{degree}(T)$；
- 两端都不在 $T$ 内的边：不进入 $T$ 中任何点的度数，贡献 $0$。

三类贡献相加得 $S = 6 + \text{degree}(T)$，移项即证。∎

**引理 2（枚举的不重不漏与判定）**：按 $u < v < w$ 的三重循环枚举，每个三点集合恰好被枚举一次，且 `adj[u][v] && adj[u][w] && adj[v][w]` 为真当且仅当 $\{u, v, w\}$ 是连通三元组；「枚举边 $(u,v)$（$u<v$）并取 $w \in adj[u] \cap adj[v]$ 且 $w > v$」的枚举方式同样不重不漏。

**证明**：任一 3 元集合的元素按大小排序结果唯一，故三重循环中每个集合恰好出现一次；三个布尔条件与「两两有边」一一对应。

对边枚举方式：设 $a < b < c$ 构成一个连通三元组，则边 $(a,b)$、$(a,c)$、$(b,c)$ 各被处理一次（读入后规范化为小端在前）。处理 $(a,b)$ 时，$c \in adj[a] \cap adj[b]$ 且 $c > b$，该三元组被发现；处理 $(a,c)$ 时公共邻居 $b$ 不满足 $b > c$，处理 $(b,c)$ 时公共邻居 $a$ 不满足 $a > c$，故不重复。反之，任何被发现的 $(u, v, w)$ 都满足三边齐全，必为连通三元组。∎

**定理**：算法返回图中所有连通三元组度数的最小值；若不存在连通三元组则返回 $-1$。

**证明**：由引理 2，两种枚举方式都恰好遍历每个连通三元组一次；由引理 1，每个三元组的度数由公式正确算出；对所有候选取 `min` 即得全局最小值。若图中无三角形，答案变量从未被更新，算法据此返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：
  - 预处理：$O(n^2 + m)$（C++ 邻接矩阵初始化 $O(n^2)$；Python 建 `set` 为 $O(n + m)$）。
  - C++ 枚举：$O(n^3)$。$n = 400$ 时最内层判定执行 $\binom{400}{3} \approx 1.06 \times 10^7$ 次，加上 v 层剪枝，轻松通过。
  - Python 枚举：$O\!\left(\sum_{(u,v) \in E} \min(deg(u), deg(v))\right)$，上界 $O(mn) \approx 3.2 \times 10^7$ 次集合交底层操作。
- **空间复杂度**：
  - C++：$O(n^2)$（邻接矩阵，$401^2 \approx 1.6 \times 10^5$ 字节）。
  - Python：$O(n + m)$（邻接集与度数数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minTrioDegree(int n, vector<vector<int>>& edges) {
        vector<vector<char>> adj(n + 1, vector<char>(n + 1, 0));
        vector<int> deg(n + 1, 0);
        for (auto& e : edges) {
            int u = e[0], v = e[1];
            adj[u][v] = adj[v][u] = 1;
            deg[u]++, deg[v]++;
        }

        int ans = INT_MAX;
        for (int u = 1; u <= n; ++u)
            for (int v = u + 1; v <= n; ++v) {
                if (!adj[u][v]) continue;          // 剪枝：跳过非边点对
                for (int w = v + 1; w <= n; ++w)
                    if (adj[u][w] && adj[v][w])    // 三角形判定，O(1)
                        ans = min(ans, deg[u] + deg[v] + deg[w] - 6);
            }
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minTrioDegree(self, n: int, edges: List[List[int]]) -> int:
        adj = [set() for _ in range(n + 1)]
        deg = [0] * (n + 1)
        for u, v in edges:
            adj[u].add(v)
            adj[v].add(u)
            deg[u] += 1
            deg[v] += 1

        best = None
        for u, v in edges:
            if u > v:
                u, v = v, u                     # 保证 u < v，每条边只处理一次
            for w in adj[u] & adj[v]:           # 公共邻居（C 层集合交）
                if w > v:                       # 保证 u < v < w，不重不漏
                    d = deg[u] + deg[v] + deg[w] - 6
                    if best is None or d < best:
                        best = d
        return -1 if best is None else best
```

## 8. 边界情况与易错点

1. **不存在三元组**：树、二分图等无三角形的图要返回 $-1$；$n = 2$ 时必然无三元组。用「答案变量是否被更新」判断，而不是任何特定数值。
2. **度数 0 是合法答案**：示例 2 的答案就是 $0$。哨兵初值必须取 $+\infty$（`INT_MAX` / `None`），**不能用 0**，否则会把「无解」和「度数为 0」混淆。
3. **枚举去重**：必须保证 $u < v < w$（或等价的 `w > v` 过滤）。重复枚举虽不影响 `min` 的正确性，但会慢 6 倍，Python 版很可能因此超时。
4. **常数 −6 别写错**：内部边是 3 条、每条在度和中被计 2 次，故减 $3 \times 2 = 6$；写成 −3 或 −2 都会错。
5. **自环与重边**：本题保证没有，无需处理。若变体允许重边，公式需改为减去「内部边总重数的 2 倍」，不能直接减 6。
6. **Python 性能**：纯三重循环（$10^7$ 次以上 Python 字节码）大概率超时；用「枚举边 + 集合交」，或把邻接矩阵做成整型位掩码（`mask[u] & mask[v]` 后枚举 $> v$ 的位）也能加速。

**延伸思考**：

- **bitset 优化**：C++ 中把邻接矩阵的每一行换成 `bitset<401>`，则 `adj[u] & adj[v]` 一条指令同时处理 64 个 $w$，枚举复杂度降为 $O(n^3 / 64)$，$n$ 再大一个量级也能做。
- **更大规模（$n \sim 10^5$）怎么办**：把每条边从度数较小（编号较小破平手）的一端**定向**到较大的一端，则每个点出度不超过 $O(\sqrt{m})$，沿「$u \to v \to w$ 再查 $uw$ 边」枚举三角形总代价 $O(m\sqrt{m})$——这是数三角形的标准提速手段；对本题还需在定向图上按 $deg$ 和最小来维护答案。
- **变体**：求三元组的**最大**度数（把 `min` 换 `max` 即可）；统计图中三角形**个数**；统计每个点参与了多少个三角形（对每个三角形给三个点各 +1）。
