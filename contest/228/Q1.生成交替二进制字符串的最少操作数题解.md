# LeetCode 生成交替二进制字符串的最少操作数 题解

## 1. 题目概述

- **标题 / 题号**：生成交替二进制字符串的最少操作数（#1758，easy）
- **链接**：https://leetcode.cn/problems/minimum-changes-to-make-alternating-binary-string/
- **来源**：LeetCode 第 228 场周赛 Q1
- **难度**：简单
- **标签**：字符串、计数

**题意**：给定仅由 `'0'` 和 `'1'` 组成的字符串 `s`。一步操作可将任意一个字符取反（`'0'` ↔ `'1'`）。**交替字符串**定义为任意相邻两个字符都不相等的字符串（形如 `"0101…"` 或 `"1010…"`）。返回使 `s` 变成交替字符串的最少操作数。

**约束**：

- $1 \le \text{s.length} \le 10^4$
- `s[i]` 为 `'0'` 或 `'1'`

> 💡 **快速切入（签到题 30 秒路线）**：① 操作是「逐位独立翻转」→ 变成某个目标的最少操作数就是与目标的**差异位数**；② 交替串由首位唯一决定 → **目标只有 2 个**；③ 两个目标逐位互补 → **数出一个、减出另一个**。三步直达代码。

## 2. 示例

**示例 1**

```text
输入：s = "0100"
输出：1
解释：将最后一位 '0' 变成 '1'，s 变为 "0101"，符合交替字符串定义。
```

**示例 2**

```text
输入：s = "10"
输出：0
解释："10" 已是交替字符串，无需操作。
```

**示例 3**

```text
输入：s = "1111"
输出：2
解释：改成 "1010" 或 "0101" 都需要 2 步操作。
```

## 3. 解题思路

### 3.1 暴力思路与贪心陷阱

**枚举子集（真暴力）**：每个位置翻或不翻共 $2^n$ 种方案，逐一检查结果是否交替并取最小翻转数。$n \le 10^4$ 下指数级，不可行。

**贪心修复（常见错误思路）**：从左到右扫描，一旦 `s[i] == s[i-1]` 就翻转 `s[i]`。这等价于**固定 `s[0]` 不动**、把串修成「以 `s[0]` 开头的那个交替目标」——只优化了两个候选目标之一，可能次优：

```text
s = "001010"
贪心修复：锁死 s[0]='0'，一路修成 "010101"，耗 5 步
最优解：  只翻 s[0] 一位，得 "101010"，耗 1 步
```

> ⚠️ **症结**：贪心修复隐式放弃了「翻转 `s[0]`」这一选择自由度。正确的枚举必须把**两个目标都算一遍**再取最小。

### 3.2 核心观察：目标只有两种，且逐位互补

![核心观察：约束传递使交替目标只有两种，A 与 B 逐位互补，diffA + diffB = n](images/wc228_q1_two_targets_concept.svg)

**观察 1（目标只有 2 个）**：交替约束 $s[i] \ne s[i+1]$ 意味着 $s[i+1] = 1 - s[i]$——**定下 `s[0]`，整串即被唯一锁定**。`s[0]` 只有两种取值，故候选目标恒为两个：

- 目标 A = `"0101…"`（偶数位 `'0'`、奇数位 `'1'`）
- 目标 B = `"1010…"`（偶数位 `'1'`、奇数位 `'0'`）

**观察 2（逐位互补）**：A 与 B 在**每个位置**上都取相反字符，而 `s[i] ∈ {0, 1}` 恰等于二者之一，故每个位置**恰与一个目标匹配、与另一个不匹配**。设

$$
\text{diffA} = \#\{i : s[i] \ne A[i]\}, \qquad \text{diffB} = \#\{i : s[i] \ne B[i]\}
$$

则

$$
\text{diffA} + \text{diffB} = n \qquad \Longrightarrow \qquad \text{answer} = \min(\text{diffA},\; n - \text{diffA})
$$

只须**一趟扫描**数出 `diffA`，`diffB` 用一次减法即可得到，连第二遍循环都省了。

> 💡 **可迁移套路**：「候选目标极少的修改问题」= 逐目标数差异位再取最小。当候选之间**逐位互补**时，还能用总和关系省掉多余遍历。同套路的 [926. 将字符串翻转到单调递增](https://leetcode.cn/problems/flip-string-to-monotone-increasing/)用前缀计数一步取最小。

### 3.3 算法流程

![算法流程：一趟扫描统计与目标 A 的差异数 diff，返回 min(diff, n − diff)](images/wc228_q1_scan_flow.svg)

1. **初始化**：`diff = 0`。
2. **一趟扫描**：遍历 $i = 0 \ldots n-1$，期望字符为 `'0'`（$i$ 偶）或 `'1'`（$i$ 奇），即目标 A 的对应位；若 `s[i]` 不等于期望字符则 `diff++`。
3. **互补换算**：`diffB = n - diff`。
4. **返回**：`min(diff, n - diff)`。

### 3.4 示例演算

![示例演算：s=0100 逐位比对两个目标，diffA=1、diffB=3，答案 1](images/wc228_q1_walkthrough.svg)

以示例 1 `s = "0100"`（$n = 4$）为例，A = `"0101"`，B = `"1010"`：

| $i$ | `s[i]` | `A[i]` | 匹配? | `B[i]` | 匹配? |
|-----|--------|--------|-------|--------|-------|
| $0$ | `0` | `0` | ✓ | `1` | ✗ |
| $1$ | `1` | `1` | ✓ | `0` | ✗ |
| $2$ | `0` | `0` | ✓ | `1` | ✗ |
| $3$ | `0` | `1` | ✗ | `0` | ✓ |

- $\text{diffA} = 1$，$\text{diffB} = 3 = n - \text{diffA}$ ✓（每行恰一个 ✓、一个 ✗，正是互补关系的微观体现）
- 答案 $= \min(1, 3) = 1$：翻转 $s[3]$ 得 `"0101"` ✓

## 4. 算法细节

1. **期望字符的 $O(1)$ 计算**：目标 A 在下标 $i$ 处的字符就是 `'0' + (i \& 1)`，无需显式构造目标串。
2. **只数一个方向**：利用 $\text{diffB} = n - \text{diffA}$，避免第二趟循环，常数直接减半。
3. **判断的位运算写法**：`(s[i] - '0') ^ (i & 1)` 为 1 当且仅当 `s[i]` 与期望不符，可直接累加；`i & 1` 与 `i % 2` 等价。
4. **数据规模**：$n \le 10^4$，`diff` 最大 $10^4$，`int` 足够，无溢出风险。

## 5. 正确性证明

**引理 1（目标刻画）**：长度为 $n$ 的交替 01 串只有 A、B 两个。

**证明**：交替串满足 $s[i+1] = 1 - s[i]$（对所有 $0 \le i < n-1$），由数学归纳得 $s[i] = s[0] \oplus (i \bmod 2)$，整串由 $s[0]$ 唯一决定。$s[0] \in \{0, 1\}$ 分别对应 A、B，且两者确为交替串。∎

**引理 2（单目标代价）**：把 `s` 变成特定目标 `T` 的最少操作数恰为差异位数 $d(s, T) = \#\{i : s[i] \ne T[i]\}$。

**证明**：每次操作只改变一个位置，故 $d$ 个差异位置各需**至少一次**操作，代价 $\ge d$；反之，每个差异位置恰翻转一次（翻转后不再动它）即可变成 `T`，代价 $\le d$。两向夹逼得代价恰为 $d$。∎

**引理 3（互补性）**：$\text{diffA} + \text{diffB} = n$。

**证明**：由引理 1，$A[i] \ne B[i]$ 对每个 $i$ 成立，而 $s[i]$ 取值恰为二者之一，故每个 $i$ 对 $\text{diffA} + \text{diffB}$ 恰贡献 1，对全部下标求和即得 $n$。∎

**定理**：最少操作数 $= \min(\text{diffA}, \text{diffB}) = \min(\text{diffA},\, n - \text{diffA})$。

**证明**：操作结果必须是交替串，由引理 1 目标只能是 A 或 B；由引理 2，两种终态的最少代价分别为 $\text{diffA}$、$\text{diffB}$，全局最优即二者取小；再由引理 3 用 $n - \text{diffA}$ 替换 $\text{diffB}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个位置一次 $O(1)$ 比较；比「分别统计两个目标」的朴素两趟少一半常数。
- **空间复杂度**：$O(1)$。仅 `diff` 与循环变量，不显式构造目标串。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(string s) {
        int n = s.size(), diff = 0;
        for (int i = 0; i < n; ++i)
            if (s[i] != '0' + (i & 1)) ++diff;
        return min(diff, n - diff);
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, s: str) -> int:
        diff = sum(int(c) ^ (i & 1) for i, c in enumerate(s))
        return min(diff, len(s) - diff)
```

> ⚠️ **别写两趟**：分别统计与 A、与 B 的差异虽然也是 $O(n)$，但由互补关系 $\text{diffB} = n - \text{diffA}$，一次减法就够，第二趟纯属性能浪费。更不要用 3.1 的「遇相邻相等翻后者」贪心——它会锁死 `s[0]` 而错过最优目标。

## 8. 边界情况与易错点

1. **n = 1**：单字符必交替，答案 0。验证：$\text{diffA} \in \{0, 1\}$，$\min(\text{diffA}, 1 - \text{diffA}) = 0$ ✓。
2. **全同串**（`"1111"`、`"0000"`）：两种目标代价分别为 $\lceil n/2 \rceil$ 与 $\lfloor n/2 \rfloor$，答案为 $\lfloor n/2 \rfloor$，无需特判。
3. **已是交替串**：`diffA = 0` 或 `diffB = 0`，`min` 自动返回 0，无需提前 return。
4. **贪心陷阱**：见 3.1，「遇相邻相等翻后者」等价于锁定 `s[0]`，反例 `"001010"`（贪心 5 步 vs 最优 1 步）。
5. **奇偶判断**：`i & 1` 与 `i % 2` 等价；C++ 中期望字符是 `'0' + i % 2`（char 算术），别直接拿 `i % 2`（int）与 `s[i]` 比较——类型隐式转换可能「能编译但逻辑错」。
6. **n 的奇偶不影响算法**：交替只约束相邻位，两种目标对任何 $n$ 都合法，无需分类讨论。
7. **返回值别写成 `diff`**：`diff` 只是与目标 A 的差异，忘了与 `n - diff` 取小是典型 WA 点。反例 `s = "10"`：`diffA = 2` 而 `diffB = 0`（本来就是交替串），直接返回 `diff` 会得 2，正确答案是 0。

**延伸思考**：

1. **环形变体**（首尾也要求不等）：等价于对环做二染色——$n$ 为奇数时**无解**（奇环不可二染色，绕一圈 0/1 无法交替配对）；$n$ 为偶数时 A、B 的首尾天然不等，答案与链式相同。
2. **k 元字母表**（相邻不等、字符集大小 $k$）：首位 $k$ 种选择、其后每位 $k-1$ 种，候选目标爆炸，互补关系失效，需改用 DP：$\text{dp}[i][c] = \min_{c' \ne c} \text{dp}[i-1][c'] + [s[i] \ne c]$，时间 $O(nk)$、滚动后空间 $O(k)$；$k = 2$ 时恰退化为本题的「双目标枚举」。
3. **操作改成「交换任意两个字符」**：交换不改变 0/1 频次，须先判 $|\text{cnt}_0 - \text{cnt}_1| \le 1$ 的可行性，再最小化错位归位的交换次数——与本题「逐位独立翻转」本质不同，不可套用差异位数公式。
