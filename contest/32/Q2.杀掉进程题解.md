# LeetCode 杀掉进程 题解

## 1. 题目概述

- **标题 / 题号**：杀掉进程（#582，medium）
- **链接**：https://leetcode.cn/problems/kill-process/
- **来源**：LeetCode 第 32 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、数组、哈希表

**题意**：给出 $n$ 个进程的 PID 列表 `pid` 与一一对应的父进程列表 `ppid`，它们构成一棵进程树（只有一个进程的 PPID 为 $0$，即树根）。现在要杀掉进程 `kill`，规则是**杀父必杀子**：它的全部后代都会被连带杀掉。返回最终被杀掉的所有 PID，顺序任意。

**约束**：

- `pid.length == ppid.length`，$n \ge 1$
- 所有 PID 是**互不相同的正整数**，值域没有上界——不能拿 PID 当数组下标
- 恰有一个进程的 PPID 为 $0$，它是整棵树的根；其余 PPID 都出现在 `pid` 中
- `kill` 保证出现在 `pid` 中
- 答案不要求顺序（Special Judge）

## 2. 示例

**示例 1**

```text
输入：pid = [1,3,10,5]，ppid = [3,0,5,3]，kill = 5
输出：[5,10]
解释：3 是根（ppid = 0），它的两个孩子是 1 与 5；5 的孩子是 10。
      杀掉 5 会连带杀掉 10；父进程 3 与兄弟 1 不受影响。
```

**示例 2**

```text
输入：pid = [1]，ppid = [0]，kill = 1
输出：[1]
解释：只有一个根进程，杀掉它只有它自己。
```

**示例 3（补充，非官方）**

```text
输入：pid = [2,4,7,9]，ppid = [0,2,4,4]，kill = 2
输出：[2,4,7,9]
解释：2 是根，4 是 2 的孩子，7、9 是 4 的孩子；杀根等于全杀。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的做法是**对每个进程单独判断它会不会死**：先把 `ppid` 整理成父指针表，然后对每个进程 $v$ 沿父指针一路向上跳，看能否撞到 `kill`。单次判定是 $O(h)$（$h$ 为深度），$n$ 个进程合计 $O(nh)$；当进程树退化成一条链时 $h = n$，总复杂度 $O(n^2)$。

另一条「模拟删除」的暴力是反复扫描：凡是父进程已经不在 `pid` 里的进程都记作死亡，重复若干轮直到没有变化，同样是 $O(n^2)$。

$n$ 上到 $10^5$ 时这两条都会超时。但它们都指向同一个结构事实：**死亡是沿父子边向下传播的**，所以不需要对每个点单独回溯，只要从 `kill` 出发向下走一遍。

### 3.2 核心观察：杀掉一个进程就是删掉一棵子树

![杀掉 kill 等于删除以它为根的子树](images/wc32_q2_kill_subtree.svg)

进程关系天然是「父 $\to$ 子」的单向结构：每个进程只有一个父进程，但可以有多个孩子。于是

- $u$ 被杀 $\Rightarrow$ $u$ 的所有孩子被杀 $\Rightarrow$ 孩子的孩子被杀……**死亡沿父子边严格向下传播**；
- 反向不成立：$u$ 被杀**不会**牵连它的父进程，也不会牵连它的兄弟（兄弟与 $u$ 只共享祖先，不共享后代）。

因此答案恰好是**以 `kill` 为根的子树节点集合**，也就是 `children` 图上从 `kill` 出发的可达点集。

把 $(pid_i, ppid_i)$ 这对表格「转置」成邻接表 `children[ppid] → [pid, ...]`，问题就退化成**树上的一次遍历**，每个进程只处理一次。

### 3.3 算法流程

![建 children 表 → 遍历子树 → 收集答案](images/wc32_q2_pipeline_flow.svg)

1. **建表**：遍历下标 $i \in [0, n)$，执行 `children[ppid[i]].push_back(pid[i])`。方向必须是「父 $\to$ 子」，这个方向正好与感染方向一致。
2. **初始化**：`ans = []`，队列 `q = [kill]`。
3. **遍历**：不断弹出队首 $u$，把 $u$ 追加进 `ans`，再把 `children[u]` 里的全部孩子入队。
4. **终止**：队列为空时返回 `ans`。若改用 DFS，把队列换成显式栈即可，输出顺序不同但集合相同。

```text
BFS(kill):
    ans ← 空列表; q ← [kill]
    while q 非空:
        u ← q.pop_front()
        ans.append(u)
        for v in children[u]:  q.push_back(v)
    return ans
```

> 💡 这个「建邻接表 → 从一个点遍历」的两段式模板是树形题的通解骨架：员工重要性、通知所有员工所需时间、二叉树中距离为 $K$ 的结点，都是同一套写法换一个统计量。

### 3.4 示例演算

![BFS 队列逐步演算](images/wc32_q2_bfs_walkthrough.svg)

对示例 1：`children` 表为 $0 \to [3]$、$3 \to [1,5]$、$5 \to [10]$，`kill = 5`。

| 步 | 出队 $u$ | `ans` | 队列 |
|----|----------|-------|------|
| 1 | 5 | `[5]` | `[10]`（`children[5]` 入队） |
| 2 | 10 | `[5, 10]` | `[]`，结束 |

注意 $3$ 是 $5$ 的父进程、$1$ 是 $5$ 的兄弟，二者都没有出现在 `ans` 里——它们走的是「向上/旁支」方向，感染传不过去。再看图下方的链式小例子 $2 \to 4 \to 7$：先入队 $2$，弹出后入队 $4$，再入队 $7$，每层只多压一个孩子，队列长度始终很小，这也是 BFS 在深链上比递归 DFS 安全的原因。

## 4. 算法细节

1. **邻接表只需要单向边**：只建 `父 → 子`，绝不建 `子 → 父`。若建了反向边又不加限制，遍历就会跑到祖先和兄弟上去，答案直接错。
2. **PID 不能当下标**：PID 是值域无上界的正整数（可能到 $2^{31}$ 量级），必须用哈希表。C++ 用 `unordered_map<int, vector<int>>` 并 `reserve(n*2)`；Python 用 `defaultdict(list)`。
3. **必须迭代实现**：进程树可以是一条长度 $n$ 的链，递归 DFS 的栈深度与 $n$ 同阶，$n = 10^5$ 时容易爆栈（LeetCode 上表现为 Runtime Error）。BFS 队列或显式栈都安全。
4. **出队即记录**：在弹出时写入 `ans`（而不是入队时），可以保证每个进程恰好输出一次，并且广度优先的第一层就是 `kill` 本身。
5. **不写 `visited` 也正确，但加上更稳**：树结构下每个非根进程只有唯一父进程、只有一条入边，天然不会重复入队；但若数据存在脏环（不合法的输入），加一个 `unordered_set` 或 `visited` 就能自保，代价是 $O(n)$ 额外空间。
6. **顺序不必处理**：本题是 Special Judge，输出顺序任意。若想本地对拍方便，把结果 `sort` 一下再比较，或按集合比较。
7. **建表时按下标并行扫描**：`pid` 和 `ppid` 等长且一一对应，一次 `for i in range(n)` 即可，不要在里面再做 `index()` 之类的线性查找。
8. **返回值类型**：`vector<int>` / `List[int]`，不要多返回一个 `kill` 的副本，也不要把根进程额外塞进去。

## 5. 正确性证明

**引理 1（树结构）**：由 $(pid, ppid)$ 定义的父子关系构成一棵以 PPID 为 $0$ 的进程为根的树；每个非根进程沿父指针上溯都能唯一到达根，且不存在环。

**证明**：每个进程恰有一个父进程，且父进程一定出现在 `pid` 中（PPID 为 $0$ 的那个除外），所以父指针是一条「单出边」链。若上溯过程中出现环，环上每个节点的祖先链都在环内循环，永远到不了 PPID 为 $0$ 的根；这与题面「只有一个进程没有父进程、其余进程同属这棵树」相矛盾。又因 PID 互不相同，父指针唯一，故每个进程到根的路径唯一，整体是一棵树。∎

**引理 2（被杀 $\iff$ 可达）**：进程 $v$ 最终会被杀掉，当且仅当 $v$ 在 `children` 图上从 `kill` 出发可达。

**证明**：分两个方向。

- （$\Leftarrow$）设 $v$ 到 `kill` 的 `children` 路径长度为 $d$，对 $d$ 归纳：$d = 0$ 时 $v = $ `kill`，直接被杀死；$d > 0$ 时 $v$ 的父进程 $u$ 路径长度为 $d-1$，由归纳假设 $u$ 被杀，而「杀父必杀子」使 $v$ 也被杀。
- （$\Rightarrow$）对被杀的成因做结构归纳：$v$ 被杀只有两种来源——$v = $ `kill`（距离 $0$，可达），或者 $v$ 的父进程 $u$ 被杀。由归纳假设 $u$ 可达，而 $v$ 是 $u$ 的孩子，补上边 $u \to v$ 后 $v$ 也可达。∎

**引理 3（每个进程至多入队一次）**：遍历过程中，任一进程只会被加入队列一次。

**证明**：对从 `kill` 出发的 `children` 路径长度 $d$ 归纳。$d = 0$ 时只有 `kill` 初始入队一次。对 $d > 0$ 的节点 $v$，它唯一的父进程 $u$（引理 1 保证唯一）距离为 $d-1$，由归纳假设 $u$ 至多出队一次，而 $v$ 只在 $u$ 出队时被压入一次，故 $v$ 至多入队一次。∎

**定理（算法正确）**：算法返回的列表恰好是最终被杀掉的 PID 集合，每个 PID 恰好出现一次。

**证明**：由引理 3，遍历终止且每个节点至多入队一次、至多写入 `ans` 一次，因此无重复；由引理 2，遍历访问的节点集合恰好等于被杀集合，`kill` 可达的节点全被访问、不可达的节点一个也不会被访问。故 `ans` 与被杀集合相等且无重复元素，与顺序无关。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建表扫描一遍 $n$ 组 $(pid, ppid)$，每条「父 $\to$ 子」边恰好被插入一次；遍历阶段每个被访问的节点出入队各一次，所有孩子边合计不超过 $n-1$ 条（森林时更少）。哈希表的均摊插入/查询是 $O(1)$。
- **空间**：$O(n)$。`children` 表至多 $n$ 个键、合计 $n-1$ 条边（每个 `vector` 自身有常数开销）；队列最长不超过「某一层的兄弟总数」，最坏 $O(n)$；`ans` 长度等于被杀进程数，最坏 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <queue>
using namespace std;

class Solution {
public:
    vector<int> killProcess(vector<int>& pid, vector<int>& ppid, int kill) {
        // 1. 建「父 -> 孩子」邻接表
        unordered_map<int, vector<int>> children;
        children.reserve(pid.size() * 2);
        for (size_t i = 0; i < pid.size(); ++i)
            children[ppid[i]].push_back(pid[i]);

        // 2. 从 kill 出发 BFS（迭代，链状数据也不爆栈）
        vector<int> ans;
        queue<int> q;
        q.push(kill);
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            ans.push_back(u);                       // 出队即记录，保证不重不漏
            auto it = children.find(u);
            if (it == children.end()) continue;     // 叶子进程
            for (int v : it->second) q.push(v);
        }
        return ans;
    }
};
```

### Python

```python
from typing import List
from collections import defaultdict, deque


class Solution:
    def killProcess(self, pid: List[int], ppid: List[int], kill: int) -> List[int]:
        children = defaultdict(list)
        for p, parent in zip(pid, ppid):
            children[parent].append(p)          # 只建父 -> 子，方向不能反

        ans, q = [], deque([kill])
        while q:
            u = q.popleft()
            ans.append(u)                       # 出队即记录
            q.extend(children.get(u, ()))       # 用 get 避免给叶子凭空建空桶
        return ans
```

## 8. 边界情况与易错点

1. **`kill` 是叶子**：`children[kill]` 不存在，直接返回 `[kill]`。C++ 里若用 `children[u]` 访问会凭空插入一个空桶，虽不影响答案但白建节点，建议先 `find`。
2. **`kill` 是根**：答案就是全部 PID，此时遍历会访问所有节点，等价于「整棵树被删」。
3. **$n = 1$**：`pid = [1]`、`ppid = [0]`、`kill = 1`，返回 `[1]`；不要因为「根没有父进程」而漏掉它。
4. **深链爆栈**：$n$ 个进程组成一条链时深度为 $n$，递归 DFS 会栈溢出，必须用迭代或增大栈。
5. **方向写反**：把邻接表建成「子 $\to$ 父」会得到祖先链，把 `3` 也当被杀进程输出，是本题最常见的错解。
6. **把兄弟也算进去**：只有「后代」才被杀。示例 1 里 `1` 与 `5` 共享父进程 `3`，但杀 `5` 不会伤到 `1`。
7. **用 PID 当数组下标**：`vector<int> children(pid[i])` 这类写法在 PID 很大时直接内存爆炸或越界，必须用哈希表。
8. **输出重复**：若改成「入队时就写 `ans`」又缺少 `visited`，在非树数据上可能重复输出；本题树结构安全，但注意别重复 `push` 同一孩子。
