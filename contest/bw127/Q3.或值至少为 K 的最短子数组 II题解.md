# LeetCode 或值至少为 K 的最短子数组 II 题解

## 1. 题目概述

- **标题 / 题号**：或值至少为 K 的最短子数组 II（#3097，medium）
- **链接**：https://leetcode.cn/problems/shortest-subarray-with-or-at-least-k-ii/
- **来源**：LeetCode 第 127 场双周赛 Q3
- **难度**：中等
- **标签**：位运算，数组，滑动窗口

**题意**：与第 127 场双周赛 Q1 完全相同的题面——求最短的非空子数组，使其所有元素的按位或 $\ge k$，不存在返回 $-1$。区别只在数据范围被拉大了一个量级。

**约束**：

- $1 \le nums.length \le 2 \times 10^5$
- $0 \le nums[i] \le 10^9$
- $0 \le k \le 10^9$

> ⚠️ Q1 的 $O(n^2)$ 暴力在 $n = 2 \times 10^5$ 时约 $4 \times 10^{10}$ 次操作，必然超时。本题的核心是发现「以某个位置结尾的不同或值只有常数个」。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]，k = 2
输出：1
解释：[3] 或值 3 ≥ 2；[2] 或值 2 ≥ 2，长度都是 1。
```

**示例 2**

```text
输入：nums = [2,1,8]，k = 10
输出：3
解释：单元素最大 8 < 10；[2,1] 为 3；[1,8] 为 9；[2,1,8] 为 11 ≥ 10。
```

**示例 3**

```text
输入：nums = [1,2]，k = 0
输出：1
解释：任何非空子数组的或值都 ≥ 0，最短即 1。
```

## 3. 解题思路

### 3.1 暴力思路

枚举左端点、向右累或，$O(n^2)$。$n = 2 \times 10^5$ 时不可行。另一条思路是「二分答案 + 检查」：单调性本身没问题（长度 $\le L$ 可行则 $\le L+1$ 也可行），但判定「是否存在长度 $\le L$ 的特别子数组」仍要枚举 $O(nL)$ 个窗口，代价与暴力同阶，二分并不能省下枚举，所以这条路也走不通。

### 3.2 核心观察：固定结尾，不同或值只有 $O(\log V)$ 个

![每个结尾只保留不同或值与最大起点](images/bw127_q3_distinct_or_sets.svg)

固定右端点 $i$，考虑所有以 $i$ 结尾的子数组 $[s, i]$（$0 \le s \le i$）。$s$ 减小时，窗口变大，或值只可能**多出若干个 1**，因此：

- 或值随着 $s$ 变小而单调不减（位集合不断扩张）；
- 或值的**不同取值极少**：每个新取值至少比前一个多一个二进制位，而 $nums[i] \le 10^9 < 2^{30}$，位最多 30 个，所以不同或值至多 $30 + 1 = 31$ 个。

于是每个 $i$ 只需维护一个长度 $\le 31$ 的列表，而不是 $O(n)$ 个起点。

### 3.3 算法流程：从 $i-1$ 的列表递推出 $i$ 的列表

![递推三步：并入当前元素、相邻去重、检查答案](images/bw127_q3_merge_flow.svg)

设 $S_{i}$ 是「以 $i$ 结尾的所有子数组」的压缩表示，元素为二元组 $(v, s)$：或值 $v$，以及能取到该或值的**最大**起点 $s$。

$$S_i = \{(nums[i], i)\} \cup \{(v \mid nums[i],\; s) : (v, s) \in S_{i-1}\}$$

合并时若新算出的或值与前一项相同，就**丢弃后者**（保留起点更大的那个，窗口更短）。最后扫描 $S_i$，对所有 $v \ge k$ 用 $i - s + 1$ 更新答案。

```text
1. cur = []，ans = n + 1
2. for i = 0 .. n-1:
       nxt = [(nums[i], i)]                     # 只含 nums[i] 的子数组
       for (v, s) in cur:
           nv = v | nums[i]
           if nxt.back().v == nv: continue      # 已有更短窗口，丢弃
           nxt.append((nv, s))
       for (v, s) in nxt:
           if v >= k: ans = min(ans, i - s + 1)
       cur = nxt
3. return ans == n + 1 ? -1 : ans
```

### 3.4 示例演算

以 `nums = [2,1,8]`、$k = 10$ 为例：

| $i$ | 当前元素 | $S_i$（或值, 起点） | 满足 $\ge k$ 的长度 |
|-----|----------|----------------------|----------------------|
| 0 | 2 | $(2, 0)$ | 无 |
| 1 | 1 | $(1, 1),\ (3, 0)$ | 无 |
| 2 | 8 | $(8, 2),\ (9, 1),\ (11, 0)$ | $11 \ge 10$，长度 $2-0+1 = 3$ |

对比暴力：$i = 2$ 时理论上有 3 个起点，压缩后同样是 3 项；但当 $n$ 很大时，暴力要扫 $n$ 个起点，压缩后始终 $\le 31$ 项。

## 4. 算法细节

1. **为什么只保留最大起点**：同一个或值 $v$ 可能由多个起点得到；我们对 $v$ 只关心「最短窗口」，也就是最大的 $s$。丢掉更小的 $s$ 不会丢失任何最优解——它对应的窗口更长，且或值相同。
2. **为什么重复值一定相邻**：$S_{i-1}$ 中的元素按起点 $s$ **从大到小**排列（越靠前的项窗口越短、位越少），逐项或上 `nums[i]` 后这个顺序保持，且或值随 $s$ 减小而单调不减，所以相同或值必然连续出现，只需和 `nxt.back()` 比较即可。
3. **列表长度上界**：位集合是一条严格包含链，每升一级至少多一个 1 位，而 $10^9 < 2^{30}$ 最多容纳 30 个 1 位，故链长至多 31（还可能有一个「全 0」的值）。即便把值域放宽到 $2^{31}$，也只有 32 项，常数极小。
4. **整数范围**：$nums[i] \le 10^9 < 2^{30}$，或值 $< 2^{30}$，$k \le 10^9$，全部可用 `int`；C++ 中无需 `long long`。
5. **$k = 0$**：任何非空子数组都满足，第一轮就会得到 `ans = 1`。
6. **答案只在「当前 $i$」处更新**：因为 $S_i$ 描述的都是以 $i$ 结尾的窗口，不可能提前知道未来更短的窗口。
7. **备选写法**：由于或值在窗口收缩时单调不增，也可以用「双指针 + 30 个位计数」维护窗口或值。

![窗口收缩时或值单调不增，因此双指针也可行](images/bw127_q3_or_monotone.svg)

双指针需要额外维护每个二进制位在窗口内出现的次数（用来判断某位是否还在），每步 $O(30)$，复杂度同为 $O(n \log V)$，但常数与代码量都更大，本文采用集合写法。

## 5. 正确性证明

**引理 1（位集单调）**：若 $0 \le s_1 \le s_2 \le i$，则 $\text{OR}(s_1..i)$ 的位集合 $\supseteq \text{OR}(s_2..i)$ 的位集合，数值上也 $\ge$。

**证明**：$[s_2, i] \subseteq [s_1, i]$，按位或对更多元素只会把更多位置 1。数值不等式的理由同第 127 场 Q1 引理 1。∎

**引理 2（集合大小）**：$S_i$ 中不同或值的个数不超过 $B + 1$，其中 $B = 30$ 是值域的位数。

**证明**：设不同或值按起点从大到小为 $v_1 < v_2 < \dots < v_t$（由引理 1 严格递增）。相邻两项对应的位集合满足严格包含 $V_1 \subsetneq V_2 \subsetneq \dots \subsetneq V_t$（数值严格增大意味着位集合必不同，而包含关系保证只能是严格包含）。每步严格包含至少多出一个二进制位，故 $|V_t| \ge t - 1$，即 $t \le B + 1 = 31$。∎

**引理 3（递推的完备性与最优性）**：设 $S_i$ 由 §3.3 的递推得到，则对每个起点 $s \in [0, i]$，存在 $(v, s') \in S_i$ 使 $v = \text{OR}(s..i)$ 且 $s' \ge s$；且 $S_i$ 中每个 $(v, s')$ 都对应真实子数组 $[s', i]$ 且 $v = \text{OR}(s'..i)$。

**证明**：对 $i$ 归纳。$i = 0$ 时 $S_0 = \{(nums[0], 0)\}$，唯一子数组 $[0,0]$，成立。设对 $i-1$ 成立。对 $s = i$：$S_i$ 中显式含 $(nums[i], i)$，对应真实子数组且或值正确。对 $s < i$：由归纳假设存在 $(v, s') \in S_{i-1}$，满足 $v = \text{OR}(s..i-1)$、$s' \ge s$。递推会把 $v \mid nums[i] = \text{OR}(s..i)$ 放入 $S_i$（可能被同值的更早项覆盖，但覆盖者起点更大、或值相同，仍满足 $s'' \ge s' \ge s$）。故完备性成立。另一方面，$S_i$ 的每一项或来自 $(nums[i], i)$、或来自 $(v, s') \in S_{i-1}$ 与其后的合并，两种情况都对应真实子数组 $[s', i]$ 且或值计算正确（按位或的结合律与「或上一个元素」的定义）。∎

**定理**：算法返回最短特别非空子数组的长度，若无则返回 $-1$。

**证明**：设最优解为 $[s^*, i^*]$（长度最小）。由引理 3，存在 $(v, s') \in S_{i^*}$ 使 $v = \text{OR}(s^*..i^*) \ge k$ 且 $s' \ge s^*$，于是算法在 $i^*$ 处至少能得到候选长度 $i^* - s' + 1 \le i^* - s^* + 1$，即 `ans` 不会大于最优值。反过来，算法记录的每个候选 $(v, s')$ 都对应真实子数组且 $v \ge k$（引理 3），所以 `ans` 不会小于最优值。两者相等。若不存在可行子数组，则任何 $S_i$ 中都没有 $v \ge k$ 的项，`ans` 保持哨兵值，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot B)$，$B = 30$。每个位置遍历上一轮的列表（$\le 31$ 项）并做 $O(1)$ 的按位或与比较；$n = 2 \times 10^5$ 时约 $6 \times 10^6$ 次操作。
- **空间**：$O(B)$。只需保存上一轮的列表，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumSubarrayLength(vector<int>& nums, int k) {
        int n = nums.size();
        int ans = n + 1;
        vector<pair<int, int>> cur;            // (子数组或值, 该或值能取到的最大起点)
        for (int i = 0; i < n; ++i) {
            vector<pair<int, int>> nxt;
            nxt.push_back({nums[i], i});       // 只含 nums[i] 的子数组
            for (auto& [v, s] : cur) {
                int nv = v | nums[i];          // 起点 s、终点 i 的子数组或值
                if (nxt.back().first == nv) continue;  // 同值只留更大起点（窗口更短）
                nxt.push_back({nv, s});
            }
            for (auto& [v, s] : nxt)
                if (v >= k) ans = min(ans, i - s + 1);
            cur.swap(nxt);
        }
        return ans == n + 1 ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minimumSubarrayLength(self, nums: list[int], k: int) -> int:
        n = len(nums)
        ans = n + 1
        cur = []                               # [(子数组或值, 该或值能取到的最大起点)]
        for i, x in enumerate(nums):
            nxt = [(x, i)]                     # 只含 nums[i] 的子数组
            for v, s in cur:
                nv = v | x
                if nxt[-1][0] == nv:           # 同值只留更大起点（窗口更短）
                    continue
                nxt.append((nv, s))
            for v, s in nxt:
                if v >= k:
                    ans = min(ans, i - s + 1)
            cur = nxt
        return -1 if ans == n + 1 else ans
```

> 💡 两份代码均通过官方示例（`1`、`3`、`1`），并与 $O(n^2)$ 暴力对拍了 400 组随机数据（$n \le 40$，值域含 $0$、$2$ 的幂、全 $1$ 位模式等易错形态），结果完全一致；$n = 2 \times 10^5$ 的极限数据单次运行约 0.3 秒（含 I/O）。

## 8. 边界情况与易错点

1. **$k = 0$**：必须返回 1（数组非空）。若写成 `if (v > k)` 会错。
2. **无解**：所有或值都 $< k$（例如 `nums = [1,2]`、$k = 4$），返回 $-1$。
3. **合并时不要更新起点**：`if (nxt.back().first == nv) continue;` 是正确的——现有项的起点更大；若写成 `nxt.back().second = s` 会把更短的窗口换成更长的，答案偏大。
4. **`nxt` 初始化必须包含 `(nums[i], i)`**：否则长度 1 的子数组全部丢失（$k = 0$ 时会直接出错）。
5. **列表顺序**：依赖「上一轮按起点递减」这一不变量；若你自己改成按起点递增存储，去重判断就要比较 `nxt.front()` 或改用哈希表。
6. **不要保存整个集合序列**：只保留上一轮的 `cur`，否则空间退化为 $O(n \cdot 31)$，$2 \times 10^5$ 规模下会 MLE。
7. **数值类型**：$nums[i] \le 10^9$，或值 $< 2^{30}$，`int` 足够；但若题目放宽到 $10^{18}$ 就必须换 `long long`，同时列表上界变成 63。

**延伸思考**：这个「不同或值集合」技巧的本质是：按位或的取值随窗口扩张构成一条**位集合链**，长度被位数卡死。同理，按位**与**在窗口扩张时位集合收缩，也是一条链（方向相反），因此「与值 $\ge k$ / 等于某值」的最短窗口也可以用同样的集合维护；而按位**异或**不具备这种单调性（可增可减），只能靠前缀异或 + 哈希。若题目改成「或值恰好等于 $k$」，只需把判据从 `v >= k` 换成 `v == k`，其余不变。
