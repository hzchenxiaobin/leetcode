# LeetCode 得到更多分数的最少关卡数目 题解

## 1. 题目概述

- **标题 / 题号**：得到更多分数的最少关卡数目（#3096，medium）
- **链接**：https://leetcode.cn/problems/minimum-levels-to-gain-more-points/
- **来源**：LeetCode 第 127 场双周赛 Q2
- **难度**：中等
- **标签**：数组，前缀和

**题意**：长度为 $n$ 的二进制数组 `possible` 描述 $n$ 个关卡：`possible[i] == 0` 表示困难关（两人都过不去，遇到扣 1 分），`possible[i] == 1` 表示简单关（通过得 1 分）。Alice 从第 0 关开始**顺序**完成前 $m$ 关，Bob 完成剩下的 $n-m$ 关，**两人都至少完成 1 关**。求使 Alice 得分**严格大于** Bob 得分的最小 $m$；不存在则返回 $-1$。

**约束**：

- $2 \le n \le 10^5$
- $possible[i] \in \{0, 1\}$

> 💡 把 0/1 映射成 $-1/+1$ 后，问题就是「找一个最短前缀，使前缀和严格大于后缀和」。

## 2. 示例

**示例 1**

```text
输入：possible = [1,0,1,0]
输出：1
解释：Alice 只拿第 0 关得 1 分，Bob 拿后三关得 −1 + 1 − 1 = −1 分，1 > −1。
```

**示例 2**

```text
输入：possible = [1,1,1,1,1]
输出：3
解释：m = 1 时 1 比 4；m = 2 时 2 比 3；m = 3 时 3 比 2，首次反超。
```

**示例 3**

```text
输入：possible = [0,0]
输出：-1
解释：两人各拿 1 关，都得 −1 分，打平不算「更多」，返回 −1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个分界 $m = 1, \dots, n-1$，分别求前缀和与后缀和。每次求和是 $O(n)$，总复杂度 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次运算，必然超时。

### 3.2 核心观察：一次算总分，之后只维护前缀

![一个分界点把数组切成 Alice 前缀与 Bob 后缀](images/bw127_q2_split_model.svg)

设把 `possible[i] == 1` 记作 $+1$、`== 0` 记作 $-1$，令

$$\text{pre}(m) = \sum_{i=0}^{m-1} a_i, \qquad \text{total} = \sum_{i=0}^{n-1} a_i$$

则 Bob 的得分是 $\text{total} - \text{pre}(m)$，Alice 赢的条件是

$$\text{pre}(m) > \text{total} - \text{pre}(m) \iff 2 \cdot \text{pre}(m) > \text{total}$$

总分只算一次，之后 $m$ 每增加 1，`pre` 只需加上 $a_{m-1}$，判据 $O(1)$ 更新。**第一个**满足不等式的 $m$ 就是答案（题目问最少关卡数，而我们是按 $m$ 从小到大扫描的）。

### 3.3 算法流程

```text
1. total = Σ (possible[i] == 1 ? +1 : -1)
2. pre = 0
3. for m = 1 .. n-1:                 # 保留最后 1 关给 Bob
       pre += (possible[m-1] == 1 ? +1 : -1)
       if 2 * pre > total:  return m
4. return -1
```

注意循环上界是 `n - 1` 而不是 `n`：`m = n` 意味着 Bob 一关都没有，违反「每人至少 1 关」。

### 3.4 示例演算

![两个示例的并排演算](images/bw127_q2_walkthrough.svg)

**示例 2**（`[1,1,1,1,1]`，$\text{total} = 5$）：

| $m$ | $\text{pre}(m)$ | Bob | $\text{pre} > \text{Bob}$？ | 动作 |
|-----|-----------------|-----|------------------------------|------|
| 1 | 1 | 4 | $1 > 4$ ✗ | 继续 |
| 2 | 2 | 3 | $2 > 3$ ✗ | 继续 |
| 3 | 3 | 2 | $3 > 2$ ✓ | 返回 3 |

**示例 1**（`[1,0,1,0]`，$\text{total} = 0$）：$m = 1$ 时 $\text{pre} = 1$，Bob $= -1$，$1 > -1$ 成立，直接返回 1。

## 4. 算法细节

1. **映射方式**：用一个三元表达式 `(x == 1 ? 1 : -1)`，或先整体求和再处理。不要写成 `x ? 0 : -1` 之类的错误映射。
2. **严格大于**：题目要求「比 Bob 更多的分数」，判据必须是 `pre > total - pre`（或 `2 * pre > total`），写成 `>=` 会在示例 3 这类打平的情形下出错。
3. **循环上界 `n - 1`**：这是最容易漏的一处边界，Bob 必须至少完成 1 关。
4. **不需要二分**：$\text{pre}(m)$ 由于存在 $-1$，**并不单调**，因此不能用二分找第一个满足条件的 $m$。好在题目要的就是「最小 $m$」，从左到右扫描并返回第一个命中即可。
5. **一次遍历**：先 $O(n)$ 求 total，再 $O(n)$ 扫描，总计 $O(n)$；不要为每个 $m$ 重新求和。
6. **整数范围**：$\text{total} \in [-10^5, 10^5]$，`2 * pre` 也在 `int` 范围内，无溢出风险。

## 5. 正确性证明

**引理 1（得分公式）**：若 Alice 完成前 $m$ 关（$1 \le m \le n-1$），则 Alice 得分为 $\text{pre}(m)$，Bob 得分为 $\text{total} - \text{pre}(m)$。

**证明**：Alice 完成的是下标 $0..m-1$，按定义累加即 $\text{pre}(m)$；Bob 完成下标 $m..n-1$，其和 $= \text{total} - \sum_{i<m} a_i = \text{total} - \text{pre}(m)$。∎

**引理 2（判据等价）**：$\text{pre}(m) > \text{total} - \text{pre}(m) \iff 2\,\text{pre}(m) > \text{total}$。

**证明**：两边同加 $\text{pre}(m)$ 得 $2\text{pre}(m) > \text{total}$，整式变形等价。∎

**定理**：算法返回的 $m$ 是满足「Alice 得分严格大于 Bob」的最小关卡数；若不存在则返回 $-1$。

**证明**：算法按 $m = 1, 2, \dots, n-1$ 递增顺序检查，由引理 1、2，检查的正是该 $m$ 是否可行，因此首次返回的 $m$ 必是最小的可行值。若循环结束都未返回，说明 $m \in [1, n-1]$ 全部不可行，而 $m = 0$（Alice 没玩）与 $m = n$（Bob 没玩）被题目排除，故无解，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次求和 + 一次扫描，每次 $O(1)$。
- **空间**：$O(1)$。只维护 `total` 与 `pre` 两个变量，没有额外数组（Python 版本的生成器求和也是 $O(1)$ 额外空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumLevels(vector<int>& possible) {
        int n = possible.size();
        int total = 0;
        for (int x : possible) total += (x == 1 ? 1 : -1);  // 全部关卡的总分
        int pre = 0;
        for (int i = 0; i + 1 < n; ++i) {                   // 至少留 1 关给 Bob
            pre += (possible[i] == 1 ? 1 : -1);              // Alice 的前缀得分
            if (pre > total - pre) return i + 1;             // 严格大于才算赢
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def minimumLevels(self, possible: list[int]) -> int:
        n = len(possible)
        total = sum(1 if x == 1 else -1 for x in possible)
        pre = 0
        for i in range(n - 1):                 # 至少留 1 关给 Bob
            pre += 1 if possible[i] == 1 else -1
            if pre > total - pre:              # 严格大于才算赢
                return i + 1
        return -1
```

> 💡 两份代码均通过官方三个示例（`1`、`3`、`-1`），并与「对每个 $m$ 重新求两段和」的暴力实现对拍了 600 组随机数据（$n \le 12$），结果完全一致。

## 8. 边界情况与易错点

1. **打平不算赢**：示例 3 中两人都是 $-1$，必须返回 $-1$；判据用严格大于。
2. **循环上界**：`m` 最大取 `n - 1`，否则 Bob 没有关卡可玩。写成 `for m in range(1, n)` 而不是 `range(1, n + 1)`。
3. **全 0 数组**：`[0,0]` 打平，返回 $-1$；但 `[0,0,0]` 时 $m=1$ 得 $-1$ 而 Bob 得 $-2$，$-1 > -2$ 成立，答案反而是 1。可见「全是困难关」并不等于无解，必须老老实实按判据算（$n \ge 3$ 且全 0 时答案恒为 1）。
4. **全 1 数组**：答案约为 $\lfloor n/2 \rfloor + 1$，例如 $n = 5$ 时是 3。
5. **`2 * pre` 与 `total` 的比较**：用乘法形式可以避免「Bob 的分数」这个中间量写错符号，推荐。
6. **返回值语义**：返回的是**关卡数目**（$m$），不是下标（$m-1$）。示例 1 返回 1 而非 0。
