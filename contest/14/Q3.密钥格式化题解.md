# LeetCode 密钥格式化 题解

## 1. 题目概述

- **标题 / 题号**：密钥格式化（#482，easy）
- **链接**：https://leetcode.cn/problems/license-key-formatting/
- **来源**：LeetCode 第 14 场周赛 Q3
- **难度**：简单
- **标签**：字符串

**题意**：给定只含字母、数字和 `-` 的字符串 $s$ 与整数 $k$。先做两步清洗——**删掉所有** `-`、把**小写字母全部转大写**，得到一个纯字符序列；再把它**从右端锚定**、每 $k$ 个字符切成一组，组与组之间用**单个** `-` 连接。唯一放宽的地方是最左边那一组：它可以不足 $k$ 个字符，但至少要有 1 个字符。返回重排后的密钥串。

**约束**：

- $1 \le \lvert s \rvert \le 10^5$，$s$ 只含英文字母、数字与 `-`
- $1 \le k \le 10^4$
- 由规模推出的硬要求：答案长度 $n + \lceil n/k \rceil - 1$ 最大可到 $2\lvert s \rvert - 1$（$k = 1$ 时），因此必须做到 $O(\lvert s \rvert)$，任何"反复在头部插入"的写法都会退化

## 2. 示例

**示例 1**

```text
输入：s = "5F3Z-2e-9-w", k = 4
输出："5F3Z-2E9W"
解释：清洗掉 3 个破折号并大写，得到 "5F3Z2E9W"（8 个字符），
      按 4 个一组切分为 "5F3Z" 与 "2E9W"，两组之间只需要 1 个破折号；
      原来的 3 个破折号里有 2 个是多余的，全部删除后重新安放。
```

**示例 2**

```text
输入：s = "2-5g-3-J", k = 2
输出："2-5G-3J"
解释：清洗后为 "25G3J"（5 个字符），组数 ⌈5/2⌉ = 3，
      首组长度 5 mod 2 = 1，于是得到 "2" + "-5G" + "-3J"。
```

**示例 3（补充，覆盖退化情况）**

```text
输入：s = "---", k = 2
输出：""
解释：清洗后没有任何字符，不存在合法的非空组，返回空串。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是**从左往右**切：把 `-` 删掉、大写，再从头部每 $k$ 个字符放一个 `-`。

问题在于余数的落点：从左切时，攒不满 $k$ 个的那一组必然出现在**最右边**，而题目只允许**最左边**那组变短。想修正就得整体右移、或者反复调用 `insert(0, ...)`，而单次头部插入是 $O(n)$，最坏退化成 $O(n^2/k)$；$n = 10^5$、$k = 1$ 时约 $10^{10}$ 次搬移，直接 TLE。

另一种"能过"的写法是先从左边数一遍有效字符数 $n$，算出首组长 $first = n \bmod k$，再从左切分。它是对的，但白白多出一趟扫描（或一个暂存串），而且 $n \bmod k = 0$ 时要特判成 $k$，是最容易写错的一处。两者差的其实只是"分组的锚点选在哪一端"这一个观察。

### 3.2 核心观察：分组由右端锚定

![从右端锚定分组：余数自然落在最左一组](images/wc14_q3_tail_group_concept.svg)

设清洗后长度为 $n$，组数 $g = \lceil n/k \rceil$。从右数第 $j$ 组的长度被完全确定：

$$
L_j = \begin{cases} k, & 1 \le j \le g-1 \\[2pt] n - k\,(g-1) = n \bmod k \ (\text{为 } 0 \text{ 时取 } k), & j = g \end{cases}
$$

也就是说：**最右那一组一定紧贴串尾、恰好 $k$ 个字符**（当 $n \ge k$ 时）。于是不需要预先知道 $n$ —— 只要从右往左走，每数满 $k$ 个字符就落一个 `-`，走完时剩下的那段前缀长度自然等于 $n \bmod k$，正好就是题目允许变短的首组。

> 💡 这是「固定宽度分组、只允许首组偏短」类问题的通用模板：**锚点永远在右端**。银行卡号、电话号码、UUID 的展示格式都是同一套逻辑。

### 3.3 算法流程

![反向扫描 + 计数器 + 整体反转](images/wc14_q3_reverse_scan_flow.svg)

维护一个**反向暂存串** `res`（它反转后才是答案）与计数器 $cnt$ = 当前这一组已收进的字符数（$0 \le cnt \le k$）：

1. $i$ 从 $n-1$ 递减到 $0$；遇到 `-` 直接跳过（清洗即"不写"）。
2. 若 $cnt = k$：说明右邻那组已经攒满，先在 `res` 末尾补一个 `-`，再令 $cnt = 0$。
3. 把 $\text{upper}(s[i])$ 追加到 `res` 末尾，$cnt \mathrel{+}= 1$。
4. 遍历结束后把 `res` **整体反转**，即为答案。

因为新字符总是被追加到 `res` 尾部（反转后即成为答案的**最左**位置），破折号只在"下方那组已满"时才插入，所以最终串里既不会有前导 `-`，也不会有连续两个 `-`。

### 3.4 示例演算

![示例 2 的逐步走查表](images/wc14_q3_walkthrough.svg)

以 `s = "2-5g-3-J"`、$k = 2$ 为例，从右往左读到的字符依次是 `J`、`-`、`3`、`-`、`g`、`5`、`-`、`2`：

| 读入 | 动作 | 反向串 `res` | $cnt$ |
|------|------|--------------|-------|
| `J` | 写入 `J` | `"J"` | 1 |
| `-` | 跳过 | `"J"` | 1 |
| `3` | 写入 `3` | `"J3"` | 2 |
| `-` | 跳过 | `"J3"` | 2 |
| `g` | $cnt=k$，先补 `-` 再写 `G` | `"J3-G"` | 1 |
| `5` | 写入 `5` | `"J3-G5"` | 2 |
| `-` | 跳过 | `"J3-G5"` | 2 |
| `2` | $cnt=k$，先补 `-` 再写 `2` | `"J3-G5-2"` | 1 |

反转 `"J3-G5-2"` 得到 `"2-5G-3J"`，与示例 2 一致。对示例 1：清洗得 `5F3Z2E9W`（$n=8$），反向先读出 `W9E2` 攒满 4 个，接着读 `Z` 时先补一个 `-`，再收 `3`、`F`，最后读 `5`，得 `"W9E2-Z3F5"`，反转即 `"5F3Z-2E9W"` ✓。

## 4. 算法细节

1. **$cnt$ 的含义要钉死**：它是"当前组已写入的字符数"，取值 $0..k$。可以证明处理完长度为 $m$ 的后缀时 $cnt = m \bmod k$（$m \bmod k = 0$ 且 $m>0$ 时 $cnt = k$），所以 $cnt = k$ 与"该开新组"完全等价，不需要额外比较下标。
2. **破折号插在写字符之前**：这样 `-` 只会出现在两个满组之间；若改成写完之后再判断，串尾会多出一个 `-`，还要额外裁掉。
3. **大小写转换**：C++ 必须写 `toupper((unsigned char)c)` —— 若 `char` 为有符号且字符高位为 1，直接传负值是 UB；Python 直接 `c.upper()`（本题只含 ASCII 字母数字，不会出现 `ß → SS` 这类长度变化）。
4. **预留空间**：答案长度 $n + g - 1 \le \lvert s \rvert + \lceil n/k \rceil$，C++ 用 `res.reserve(s.size() + s.size() / k)` 避免多次 realloc；Python 用 `list` 追加再 `''.join`，同样避免 $O(n^2)$ 的字符串拼接。
5. **反转而不是头部插入**：`string(res.rbegin(), res.rend())` 与 `res.reverse()` 都是 $O(n)$；`res.insert(res.begin(), c)` 单次 $O(n)$，整体 $O(n^2)$，是最常见的性能坑。
6. **等价的从左两趟写法**：先统计有效字符数 $n$，令 $first = n \bmod k$（为 0 时取 $k$），再取 `clean[:first]` 与后续每 $k$ 个切分。正确但要多存一份清洗串，且必须处理 $n = 0$。
7. **能不能原地覆盖**：答案长 $n + \lceil n/k \rceil - 1$，只有当原串破折号数 $d \ge \lceil n/k \rceil - 1$ 时它才不长于原串。即便满足，原地重写也不省心：从左往右写时每插一个破折号，写指针就会追上一次读指针，必须额外缓存一个前瞻字符才不会踩到未读数据。收益远小于风险，参考代码直接新开缓冲区——况且存放答案本身就需要 $O(\lvert s \rvert)$ 空间。

## 5. 正确性证明

**引理 1（清洗结果唯一）**：删除全部 `-` 并把字母统一为大写后，得到的字符序列 $t$ 唯一，长度 $n$ 等于 $s$ 中非 `-` 字符的个数。

**证明**：删除操作只依赖字符是否为 `-`，大小写转换是逐字符的确定性函数，且题目字符集只含 ASCII 字母与数字，转换不改变长度与顺序，故 $t$ 唯一，长度即为被保留字符数。∎

**引理 2（合法格式唯一）**：若 $n \ge 1$，满足"组间恰好一个 `-`、除最左组外每组恰 $k$ 个字符、最左组非空且不超过 $k$"的串唯一，其最左组长度必为 $n \bmod k$（为 $0$ 取 $k$），其余各组恰 $k$ 个字符。

**证明**：设共有 $g$ 组、第 $i$ 组长度 $l_i$。则 $\sum l_i = n$，$1 \le l_1 \le k$，$l_2 = \dots = l_g = k$，于是 $n = l_1 + k(g-1)$，即 $l_1 = n - k(g-1) \equiv n \pmod k$，且由 $1 \le l_1 \le k$ 可知 $g$ 与 $l_1$ 都被 $n, k$ 唯一确定（$l_1$ 取 $n \bmod k$ 的正代表，余 0 时取 $k$）。长度序列唯一，字符顺序又由 $t$ 固定，故整串唯一。∎

**引理 3（反向扫描不变量）**：设已处理 $s[i..n-1]$，其中非 `-` 字符数为 $m$，$u = t[n-m..n)$。则 `res` 反转后恰为"把 $u$ 从右端按每 $k$ 个一组、组间一个 `-`"形成的串，且 $cnt = m \bmod k$（$m \bmod k = 0$ 且 $m>0$ 时 $cnt = k$）。

**证明**：对 $m$ 归纳。$m = 0$ 时 `res` 为空、$cnt = 0$，成立。设 $m$ 时成立，处理下一个非 `-` 字符 $c$（$m \to m+1$）：

- 若 $cnt = k$，则 $m$ 是 $k$ 的正倍数，$u$ 的最左组已满 $k$ 个，新字符必须开启新组 —— 算法先补 `-` 再写 $c$，正合；
- 若 $cnt < k$，则 $u$ 的最左组未满（或 $m = 0$），新字符并入该组即可 —— 算法直接追加 $c$，不补 `-`，正合。

两种情况都只是把 $c$ 放到 `res` 尾部，即答案最左端，且 $cnt$ 相应更新为 $(m+1) \bmod k$ 的正代表，不变量保持。∎

**定理**：算法返回的字符串即为题目要求的格式化密钥。

**证明**：遍历结束时 $m = n$，由引理 3 可知输出恰为"把 $t$ 从右端按每 $k$ 个字符分组、组间一个 `-`"的结果；由引理 2 该串正是满足题意的唯一格式。若 $n = 0$，算法不写入任何字符并返回空串，此时不存在合法的非空组，输出也正确。∎

## 6. 复杂度分析

- **时间**：$O(\lvert s \rvert)$。反向扫描每个字符恰好访问一次（$O(\lvert s \rvert)$），`res` 追加均摊 $O(1)$，最后一次反转 $O(n + g)$，拼接输出 $O(n+g)$；总计 $O(\lvert s \rvert)$。
- **空间**：$O(\lvert s \rvert)$，用于存放答案（或 `res` 暂存 + 结果串）；除输出外只用了 $i, cnt$ 等常数个辅助变量，即额外空间 $O(1)$（Python 的 `list` 与 `string` 各占 $O(\lvert s \rvert)$）。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string licenseKeyFormatting(string s, int k) {
        string res;
        res.reserve(s.size() + s.size() / k);
        int cnt = 0;                       // 当前组已收进的字符数，0..k
        for (int i = (int)s.size() - 1; i >= 0; --i) {
            char c = s[i];
            if (c == '-') continue;        // 清洗：破折号一律丢弃
            if (cnt == k) {                // 下方那组已满，先落一个破折号
                res.push_back('-');
                cnt = 0;
            }
            res.push_back((char)toupper((unsigned char)c));
            ++cnt;
        }
        return string(res.rbegin(), res.rend());   // 反转得到正序答案
    }
};
```

### Python

```python
class Solution:
    def licenseKeyFormatting(self, s: str, k: int) -> str:
        res = []
        cnt = 0                            # 当前组已收进的字符数，0..k
        for i in range(len(s) - 1, -1, -1):
            c = s[i]
            if c == '-':                   # 清洗：破折号一律丢弃
                continue
            if cnt == k:                   # 下方那组已满，先落一个破折号
                res.append('-')
                cnt = 0
            res.append(c.upper())
            cnt += 1
        res.reverse()                      # 反向暂存串整体翻转为答案
        return ''.join(res)
```

## 8. 边界情况与易错点

1. **`s` 全是破折号**：清洗后 $n = 0$，应返回 `""`。反向写法天然给出空串（一个字符都没写）；两趟写法则要显式 `if n == 0: return ""` 提前返回，不要指望切分逻辑兜底。
2. **余数为 0 时首组也是满的**：$n \bmod k = 0$ 时最左组应取 $k$ 个字符而不是 0 个，否则答案会以 `-` 开头。这是本题最常见的 WA 点。
3. **$k$ 大于有效字符数**：只有一组、且不能插任何破折号，例如 `"a-1"`、$k = 5$ → `"A1"`。
4. **连续破折号与首尾破折号**：`"--a--b--"` 之类全部丢弃，绝不能在输出里留下连续 `-`；`cnt` 只在写入真实字符时自增，破折号不参与计数。
5. **`toupper` 的参数**：必须转成 `unsigned char` 再用（`tolower` 同理），直接传可能为负的 `char` 属于未定义行为，在不同平台上结果不一致。
6. **$k = 1$ 的极端输出**：答案长为 $2n - 1$，几乎每个字符后都有 `-`；容量按 $\lvert s \rvert + \lceil n/k \rceil$ 预留，别只按 $\lvert s \rvert$ 预留。
7. **别用头部插入**：`res.insert(res.begin(), ...)` 或 `res = c + res` 会把整体复杂度推到 $O(n^2)$，$10^5$ 规模下必然超时。
