# LeetCode 数字的补数 题解

## 1. 题目概述

- **标题 / 题号**：数字的补数（#476，easy）
- **链接**：https://leetcode.cn/problems/number-complement/
- **来源**：LeetCode 第 14 场周赛 Q1
- **难度**：简单
- **标签**：位运算

**题意**：把 $num$ 的二进制表示（**不含前导零**，长度记为 $k$）逐位取反，再把得到的 01 串按二进制读回十进制。例如 $5 = (101)_2$ 取反得 $(010)_2 = 2$。注意「取反」只发生在 $num$ 的**有效位**上：第 $k$ 位及以上不在二进制表示里，也就不参与取反。

**约束**：

- $1 \le num < 2^{31}$：单个数、单次询问，$k \in [1, 31]$，答案必然仍在 32 位有符号整数范围内。
- 最坏情况 $num = 2^{31}-1$ 时 $k = 31$：掩码必须恰好覆盖 31 位，既不能少（漏翻高位）也不能多（把前导零翻成 1），这是本题唯一的「规模」约束。

## 2. 示例

**示例 1**

```text
输入：num = 5
输出：2
解释：5 的二进制表示为 101（没有前导零位），其补数为 010，即 2。
```

**示例 2**

```text
输入：num = 1
输出：0
解释：1 的二进制表示为 1，取反后是 0，所以输出 0。
```

**示例 3（补充，便于对照边界）**

```text
输入：num = 2147483647 = 2^31 - 1
输出：0
解释：31 位全为 1，逐位取反后 31 位全为 0，结果 0；这也说明答案可以是 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是把 $num$ 转成二进制字符串（C++ 用 `bitset` 或手写循环，Python 用 `bin()`），逐字符把 `0`/`1` 互换，再按二进制解析回去：$O(k)$ 次字符串操作。

另一条朴素路线是「从高位到低位逐位重建」：

$$\text{ans} = \sum_{i=0}^{k-1} \left(1 - b_i\right) \cdot 2^i,\qquad b_i = \left\lfloor num / 2^i \right\rfloor \bmod 2$$

两种写法都能过（$k \le 31$），但都要先求位数 $k$、都带字符串或循环常数，而且容易在前导零和位宽上翻车。真正值得沉淀的是下面这一步：**取反不是一种新运算，它只是异或的一个特例**。

### 3.2 核心观察：补数 = num ^ (同宽全 1 掩码)

![异或同宽全 1 掩码即逐位取反](images/wc14_q1_xor_mask.svg)

关键事实只有一条：对单个二进制位，

$$b \oplus 1 = 1 - b,\qquad b \oplus 0 = b$$

也就是说**异或 1 就是取反，异或 0 就是保持**。于是只要构造一个「与 $num$ 同宽、$k$ 位全 1、更高位全 0」的掩码

$$\mathrm{mask} = 2^k - 1 = \underbrace{11\cdots1}_{k\ \mathrm{bits}}$$

就有

$$\mathrm{ans} = num \oplus \mathrm{mask}$$

掩码在 $k$ 位以上都是 $0$，所以不会把本该「不存在」的高位翻成 $1$——这正是题目「没有前导零位」的含义。把上式改写一下还能得到另一个恒等式：$num$ 与它的补数每一位互补，两数相加恰好是 $k$ 位全 1，

$$num + \mathrm{ans} = 2^k - 1 \;\Longrightarrow\; \mathrm{ans} = \left(2^k - 1\right) - num$$

它与异或写法完全等价，但异或只需一次运算，且不涉及减法借位，更适合作为模板。

### 3.3 算法流程：先传播出掩码，再异或

![OR-移位传播构造掩码](images/wc14_q1_mask_propagation.svg)

问题归结为「如何求 $2^k - 1$」。最省事的是 **OR-移位传播**：从 `mask = num` 出发，反复把掩码右移后按位或回去。

```text
mask = num
mask |= mask >> 1
mask |= mask >> 2
mask |= mask >> 4
mask |= mask >> 8
mask |= mask >> 16
```

移位量按 $1, 2, 4, 8, 16$ 倍增，$1 + 2 + 4 + 8 + 16 = 31$，而 $k \le 31$，所以 5 步之后最高位的那个 `1` 就会被「抹平」成低 $k$ 位全 1，高位仍是 0。另外两种写法作对照：

1. **内建位数**：$k = \mathrm{bitLength}(num)$，则 $\mathrm{mask} = (1 \ll k) - 1$。Python 用 `num.bit_length()`；C++ 用 `32 - __builtin_clz(num)`（$num \ge 1$ 时安全）。注意 $k = 31$ 时不能写有符号的 `1 << 31`（溢出属未定义行为），要用 `1u << k` 或 `1LL << k`。
2. **逐位循环**：`for i in range(k): ans |= (1 - ((num >> i) & 1)) << i`，直观但循环常数最大，仅作对照。

得到 `mask` 后返回 `num ^ mask`（等价于 `~num & mask`，但后者多一步、且依赖 `~` 的补码语义，不推荐）。

### 3.4 示例演算

![三种位长的演算对照](images/wc14_q1_walkthrough.svg)

以 $num = 5$ 走一遍传播过程（5 位宽书写，高位补 0 仅用于展示）：

| 步骤 | 表达式 | 掩码位串 | 十进制 |
|------|--------|----------|--------|
| 初始 | `mask = num` | 0 0 1 0 1 | 5 |
| 第 1 步 | `mask >>= 1` 后或回 | 0 0 1 1 1 | 7 |
| 第 2 步 | `mask >>= 2` 后或回 | 0 0 1 1 1 | 7 |
| 后续 | 移位量 4/8/16 | 0 0 1 1 1 | 7 |

第 1 步已经把唯一的 `1` 向右铺满低 3 位，后续步骤只做幂等确认。最后 $5 \oplus 7 = (101)_2 \oplus (111)_2 = (010)_2 = 2$，与官方输出一致。

再看一个位数不同的例子：$num = 10 = (1010)_2$，$k = 4$，`mask` 收敛到 $(1111)_2 = 15$，于是 $10 \oplus 15 = (0101)_2 = 5$。可见**位数不同只会改变 mask 的长度，公式本身不变**。

## 4. 算法细节

1. **掩码初值必须是 `num` 而不是 `0`**：若从 `mask = 0` 出发，右移与或都是 0，永远得不到全 1；`num` 的最高位 `1` 正是传播的种子。
2. **移位量取 $1,2,4,8,16$，共 5 次**：它覆盖 $2^5 = 32$ 位宽，而 $k \le 31$。少写一步（例如漏掉 `>> 16`）时，$k \ge 17$ 的数就会算错：$num = 65536 = 2^{16}$ 会得到 $131070$ 而不是 $131071$，答案从 $65535$ 错成 $65534$。
3. **返回 `num ^ mask`，不要返回 `~num`**：在 C++/Java 里 `~num` 是补码意义上的负数，Python 里是负整数（如 `~5 == -6`），都不是补数。若坚持用 `~`，必须再与掩码相与：`~num & mask`。
4. **不要用 32 位全 1（`0xFFFFFFFF` / `-1`）当掩码**：那会把 $k$ 位以上的 0 也翻成 1。例如 $num = 5$ 会得到 $4294967290$，Python 里还是正数，错误更隐蔽。
5. **$k = 31$ 的溢出边界**：`(1 << k) - 1` 在 `int` 上是未定义行为，务必写成 `(1u << k) - 1` 或 `(1LL << k) - 1`；OR-移位写法天然没有这个问题，因为它只做右移与或，不产生第 31 位以上的 1。
6. **位数来源要统一**：`__builtin_clz(0)` 未定义，而本题 $num \ge 1$，可以安全使用；若把函数改成通用工具函数，必须先特判 $num = 0$（此时补数定义为 0）。
7. **答案允许为 0**：$num = 2^k - 1$ 时补数为 0，不要用 `0` 作「还没算出来」的哨兵，也不要给 `ans` 加额外的 `+1` 修正。

## 5. 正确性证明

**引理 1（异或掩码即逐位取反）**：设 $k$ 为 $num$ 的二进制长度，$\text{mask} = 2^k - 1$，则 $num \oplus \text{mask}$ 的二进制恰为 $num$ 的 $k$ 位表示逐位取反，且没有额外的高位。

**证明**：对第 $i$ 位分两种情况。若 $0 \le i < k$，掩码第 $i$ 位为 1，故 $(num \oplus \text{mask})_i = b_i \oplus 1 = 1 - b_i$，即该位被取反；若 $i \ge k$，则 $num$ 的第 $i$ 位为 0（$k$ 是最高有效位的位置上界）、掩码第 $i$ 位也为 0，异或结果为 0。逐位合并即得结论。∎

**引理 2（OR-移位传播的语义）**：记 $t_0 = num$，$t_{j+1} = t_j \mid (t_j \gg 2^j)$，则 $t_j$ 的第 $i$ 位为 1 当且仅当 $num$ 在区间 $\left[i,\ i + 2^j - 1\right]$ 内存在某一位为 1。

**证明**：对 $j$ 归纳。$j = 0$ 时区间退化为 $[i, i]$，$t_0$ 的第 $i$ 位就是 $num$ 的第 $i$ 位，成立。设命题对 $j$ 成立，则

$$\left(t_{j+1}\right)_i = \left(t_j\right)_i \lor \left(t_j\right)_{i + 2^j}$$

由归纳假设，右式等价于「$num$ 在 $\left[i, i + 2^j - 1\right]$ 有 1」或「$num$ 在 $\left[i + 2^j, i + 2^{j+1} - 1\right]$ 有 1」，两者合并正好是「$num$ 在 $\left[i, i + 2^{j+1} - 1\right]$ 有 1」。∎

**引理 3（5 步后掩码正确）**：$t_5 = 2^k - 1$。

**证明**：此时区间长度为 $2^5 = 32 \ge k$。对任意 $0 \le i \le k-1$，有 $i \le k-1 \le i + 31$（左边显然，右边由 $k \le 31$ 得），故最高有效位 $k-1$ 落在区间 $\left[i, i + 31\right]$ 内，该位为 1，由引理 2 得 $t_5$ 第 $i$ 位为 1。对 $i \ge k$，区间内所有位置在 $num$ 中都是 0，故 $t_5$ 第 $i$ 位为 0。于是 $t_5$ 低 $k$ 位全 1、其余为 0，即 $2^k - 1$。∎

**定理**：算法返回 $num$ 的补数。

**证明**：由引理 3，循环结束后 $\mathrm{mask} = 2^k - 1$；由引理 1，$num \oplus \mathrm{mask}$ 的二进制正是 $num$ 的 $k$ 位表示逐位取反、无额外高位，按定义即为 $num$ 的补数。∎

## 6. 复杂度分析

- **时间**：$O(1)$。固定 5 次右移与按位或，每次作用于一个机器字（至多 31 个有效位）；若按输入位数计则为 $O(\log num)$。没有任何循环依赖 $num$ 的数值大小。
- **空间**：$O(1)$。只使用 `mask` 一个临时整型变量，无数组、无字符串。
- 对比：字符串往返写法同为 $O(\log num)$，但常数包含进制转换与内存分配，实际更慢且更易错。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findComplement(int num) {
        int mask = num;          // 以最高位 1 为种子
        mask |= mask >> 1;       // 传播 1 位
        mask |= mask >> 2;       // 传播 2 位
        mask |= mask >> 4;       // 传播 4 位
        mask |= mask >> 8;       // 传播 8 位
        mask |= mask >> 16;      // 传播 16 位：累计覆盖 31 位，k <= 31 足够
        return num ^ mask;       // 与同宽全 1 掩码异或 = 逐位取反
    }
};
```

### Python

```python
class Solution:
    def findComplement(self, num: int) -> int:
        mask = num
        mask |= mask >> 1
        mask |= mask >> 2
        mask |= mask >> 4
        mask |= mask >> 8
        mask |= mask >> 16
        return num ^ mask
```

Python 也可写成等价的一行（利用大整数无溢出）：

```python
class Solution:
    def findComplement(self, num: int) -> int:
        return num ^ ((1 << num.bit_length()) - 1)
```

## 8. 边界情况与易错点

1. **$num = 1$**：`mask` 传播后仍为 1，答案为 0；不要误以为「答案至少是 1」而做无谓修正。
2. **$num = 2^k - 1$（全 1）**：$num = 2147483647$ 时答案为 0，是最容易触发「0 被当成空值」的用例。
3. **漏掉 `>> 16`**：$k \ge 17$ 就会错，例如 $num = 65536$ 得到 65534（正确 65535）；用倍增移位时要数清 5 步。
4. **有符号左移溢出**：`1 << 31` 在 32 位 `int` 上属未定义行为，C++ 中应写 `1u << k`；本解法不做左移，天然规避。
5. **误用 `~num`**：C++/Java 返回负数，Python 返回负整数；补数必须限制在 $k$ 位内，只能用异或掩码或 `~num & mask`。
6. **掩码取成 32 位全 1**：$num = 5$ 会返回 4294967290 而非 2；题目明确「没有前导零位」，位宽必须跟着 $num$ 走。
7. **把位数算成 32**：若用固定的 32 位宽构造掩码，等价于把 $num$ 视为定长 32 位无符号数，语义与题意不符。
