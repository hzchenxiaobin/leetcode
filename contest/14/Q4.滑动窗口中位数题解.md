# LeetCode 滑动窗口中位数 题解

## 1. 题目概述

- **标题 / 题号**：滑动窗口中位数（#480，hard）
- **链接**：https://leetcode.cn/problems/sliding-window-median/
- **来源**：LeetCode 第 14 场周赛 Q4
- **难度**：困难
- **标签**：数组、哈希表、树堆、滑动窗口、堆（优先队列）

**题意**：给定数组 `nums` 与窗口长度 `k`，长度为 `k` 的窗口从最左端逐格右移。每到一个位置，求出窗口内 $k$ 个数的中位数——`k` 为奇数时取正中间那个数，`k` 为偶数时取中间两个数的平均值。按窗口出现顺序返回这 $n-k+1$ 个中位数。

**约束**：

- $1 \le k \le \text{nums.length} \le 10^5$
- $-2^{31} \le \text{nums}[i] \le 2^{31}-1$
- 与真实值误差在 $10^{-5}$ 以内视为正确；题面保证 `k` 始终有效

## 2. 示例

```text
示例 1
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[1.00000,-1.00000,-1.00000,3.00000,5.00000,6.00000]
解释：6 个窗口依次是 [1,3,-1] → 1，[3,-1,-3] → -1，[-1,-3,5] → -1，
      [-3,5,3] → 3，[5,3,6] → 5，[3,6,7] → 6。

示例 2
输入：nums = [1,2,3,4,2,3,1,4,2], k = 3
输出：[2.00000,3.00000,3.00000,3.00000,2.00000,3.00000,2.00000]
解释：7 个窗口的中位数依次为 2,3,3,3,2,3,2。

补充示例（偶数 k）
输入：nums = [1,4,2,3], k = 4
输出：[2.50000]；唯一的窗口排序后为 [1,2,3,4]，中位数 = (2 + 3) / 2 = 2.5。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每个窗口取出 $k$ 个数排序，取中间下标。

- 排序：每窗 $O(k \log k)$，共 $n-k+1$ 个窗口 → $O(nk \log k)$；
- 用 `nth_element` 只求第 $\lceil k/2 \rceil$ 小：每窗 $O(k)$ → $O(nk)$。

$n = k = 10^5$ 时 $nk = 10^{10}$，必然超时。瓶颈很清楚：**相邻两个窗口只差一个数，却把全部数重新排了一遍**。真正需要的只是「删一个、加一个、再问一次中位数」。

### 3.2 核心观察：对顶堆（两个半区）

![对顶堆：把窗口切成较小一半与较大一半](images/wc14_q4_dual_heap.svg)

中位数只依赖两个位置：第 $\lceil k/2 \rceil$ 小与第 $\lceil k/2 \rceil+1$ 小。于是把窗口拆成两半：

- **low**：较小的 $\lceil k/2 \rceil$ 个数，用**大顶堆**维护，堆顶是 $\max(\text{low})$；
- **high**：较大的 $\lfloor k/2 \rfloor$ 个数，用**小顶堆**维护，堆顶是 $\min(\text{high})$。

只要两半的划分正确（low 中每个数都不大于 high 中每个数），就有

$$\text{median} = \begin{cases} \max(\text{low}), & k \text{ 为奇数}\\[2pt] \bigl(\max(\text{low}) + \min(\text{high})\bigr) / 2, & k \text{ 为偶数}\end{cases}$$

插入 $O(\log k)$，读中位数 $O(1)$。剩下的唯一难点是：**窗口滑出时如何从堆里删掉任意一个元素**——堆天生只能删堆顶。

### 3.3 算法流程：延迟删除 + 规模平衡

![单步流程：插入、延迟删除、平衡、取中位数](images/wc14_q4_lazy_delete_flow.svg)

既然不值得为一道题手写平衡树，就用**延迟删除（lazy deletion）**：元素滑出窗口时先不真删，只打一个失效标记；等它自己冒到堆顶时再弹掉。

标记必须按**元素身份（下标）**，不能按值。窗口里可能有多个相同的数，若用「值 → 待删个数」计数，这份删除额度会被**另一个堆里的同值副本**冒领，真正失效的那份却赖在堆里，之后被当成有效元素参与取中位数，答案就错了。所以堆里存 `(值, 下标)`，另开 `alive[]` 标记下标是否还在窗口内。

第 $i$ 步的流程：

1. 把 `(nums[i], i)` 插入：不大于 $\max(\text{low})$ 就进 low，否则进 high；
2. 若 $i \ge k$，令 `alive[i-k] = false`（左端滑出）；
3. `clean`：反复查看两个堆顶，谁是失效下标就弹谁；
4. `balance`：比较 low 的**有效**元素个数 $n_l$ 与目标 $\lceil k/2 \rceil$——多了把 low 堆顶搬给 high，少了把 high 堆顶搬回 low；
5. 若 $i \ge k-1$，按 $k$ 的奇偶读取堆顶得到中位数。

### 3.4 示例演算

![示例演算：窗口、两半与中位数](images/wc14_q4_example_walkthrough.svg)

以 `nums = [1,3,-1,-3,5,3,6,7]`、`k = 3` 为例（low 目标 2 个、high 目标 1 个，中位数 = max(low)）：

| $i$ | 新元素 | low（有效） | high（有效） | 中位数 |
|-----|--------|-------------|--------------|--------|
| 2 | -1 | {-1, 1} | {3} | 1 |
| 3 | -3 | {-3, -1} | {3} | -1 |
| 4 | 5 | {-3, -1} | {5} | -1 |
| 5 | 3 | {-3, 3} | {5} | 3 |
| 6 | 6 | {3, 5} | {6} | 5 |
| 7 | 7 | {3, 6} | {7} | 6 |

第 5 步最能说明问题：5 进 high，−1 滑出窗口；`clean` 把 −1 从 low 堆顶弹掉后 low 只剩 {−3}，此时 $n_l = 1 < 2$，于是把 high 的最小值 3 搬进 low，low 恢复为 {−3, 3}，堆顶 3 正是本窗答案。

## 4. 算法细节

1. **堆里存什么**：一律存 `(值, 下标)`。C++ 中 low 用 `priority_queue<pair<long long,int>>`（默认大顶堆），high 用同类型配 `greater<>`（小顶堆）；Python 的 `heapq` 是小顶堆，low 存 `(-值, 下标)` 取反模拟大顶堆。
2. **有效计数单独维护**：物理大小包含尚未清理的失效元素，不能拿来判断规模。用 $n_l, n_h$ 两个计数器：插入时 ++，滑出时按 `side[]` 记录的所在堆 --，搬移时两边同步增减。
3. **平衡只需常数次搬移**：每步净增 1 个、净减 1 个，$n_l$ 与目标最多差 1，故两个 `while` 各自至多执行一次，均摊 $O(\log k)$。
4. **取堆顶前必须 `clean`**：插入时比较 $\max(\text{low})$、搬移时取堆顶、输出中位数时取堆顶，三处都要保证堆顶有效；搬移会掀开新的堆顶，所以搬移后要再 `clean` 一次。
5. **窗口未满时不平衡**：$i < k-1$ 时窗口里还没有 $k$ 个数，若硬把 $n_l$ 补到 $\lceil k/2 \rceil$ 就会去空堆取元素（`k = 1` 第一步即崩）。平衡与输出都限制在 $i \ge k-1$。
6. **若改用 `multiset`**：删除要写 `erase(find(value))`，因为 C++ 的 `erase(key)` 会删掉**所有**等值元素。

## 5. 正确性证明

**引理 1（分区不变式）**：在每个 $i \ge k-1$ 的步骤末尾（取中位数之前），low 中的有效元素恰为窗口中较小的 $\lceil k/2 \rceil$ 个数，high 中的有效元素恰为较大的 $\lfloor k/2 \rfloor$ 个数。

**证明**：只需证三条不变量在每个 $i \ge k-1$ 的步骤末尾成立：(a) 有效元素总数 $n_l + n_h = k$；(b) $n_l = \lceil k/2 \rceil$、$n_h = \lfloor k/2 \rfloor$；(c) low 中任一有效元素不大于 high 中任一有效元素。

**初始**（$i = k-1$）：插入规则保证 (c)——新元素不大于 $\max(\text{low})$ 就进 low，否则进 high，故不会出现 low 元素大于 high 元素；`balance` 每次搬移都保持 (c)，并把 $n_l$ 调到 $\lceil k/2 \rceil$，于是 (a)(b) 成立。

**归纳**：设第 $i$ 步开始时不变量成立。插入一个元素后总数变为 $k+1$，(c) 仍成立（理由同上）；把下标 $i-k$ 标记失效只做减法，不会引入跨区逆序，总数回到 $k$；`balance` 在保持 (c) 的前提下调整 $n_l$，结束后 $n_l = \lceil k/2 \rceil$，由 (a) 得 $n_h = \lfloor k/2 \rfloor$。注意 (c) 单独不够、必须与 (b) 合用：满足 (c) 且两半数目正确时 low 必是全体中最小的 $\lceil k/2 \rceil$ 个，否则 high 中的 $x$ 小于 low 中的 $y$ 就违反 (c)。∎

**引理 2（延迟删除安全）**：`clean` 之后两个堆的堆顶都是有效元素；失效元素的存在不改变有效元素之间的偏序。

**证明**：`clean` 反复弹掉堆顶的失效下标，直到堆顶有效或堆空，故堆顶有效。失效元素只是仍占据堆中某个位置，堆的父子偏序由键值决定、与有效性无关，所以有效元素之间的相对次序不变；堆顶一旦有效，它就是所有有效元素中的最值。∎

**引理 3（平衡可终止且规模正确）**：`balance` 结束时 $n_l = \lceil k/2 \rceil$ 且 $n_l + n_h = k$。

**证明**：每步插入一个、失效一个，$n_l$ 与目标的偏差不超过 1，两个循环各自至多执行一次；每次搬移把 $n_l$ 朝目标推近 1，故必然终止于 $n_l = \lceil k/2 \rceil$；总数由插入/删除维护为 $k$，搬移不改变总数。∎

**定理**：算法对每个窗口输出的值就是该窗口的中位数。

**证明**：由引理 1，low 恰为较小的 $\lceil k/2 \rceil$ 个数、high 恰为较大的 $\lfloor k/2 \rfloor$ 个数；由引理 2，`clean` 后堆顶是两半的最值。当 $k = 2t+1$ 为奇数，low 有 $t+1$ 个元素，其最大值即升序第 $t+1$ 个，正是中位数；当 $k = 2t$ 为偶数，low 的最大值是第 $t$ 小、high 的最小值是第 $t+1$ 小，二者平均即中位数。∎

## 6. 复杂度分析

- **时间**：$O(n \log k)$。每个下标至多入堆一次，出堆（被 `clean` 弹出或被搬移）一次，每次堆操作 $O(\log k)$，每步只做常数次；读中位数 $O(1)$。$n = 10^5$ 时约 $10^5 \times 17$ 次基本操作。
- **空间**：$O(n + k)$。两个堆合计为 $k$ 个有效元素加上少量未清理的失效元素；`alive`、`side` 各 $O(n)$；答案数组 $O(n-k+1)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <utility>
using namespace std;

class Solution {
public:
    vector<double> medianSlidingWindow(vector<int>& nums, int k) {
        int n = (int)nums.size();
        priority_queue<pair<long long, int>> low;                   // 大顶堆：较小的一半
        priority_queue<pair<long long, int>, vector<pair<long long, int>>,
                       greater<pair<long long, int>>> high;         // 小顶堆：较大的一半
        vector<char> alive(n, 0), side(n, 0);   // 下标是否有效 / 下标所在堆(0=low,1=high)
        int nl = 0, nh = 0;                     // 两堆中有效元素个数
        const int target = (k + 1) / 2;
        vector<double> res;

        auto clean = [&]() {                    // 反复弹掉堆顶的失效元素
            while (!low.empty() && !alive[low.top().second]) low.pop();
            while (!high.empty() && !alive[high.top().second]) high.pop();
        };

        for (int i = 0; i < n; i++) {
            long long x = nums[i];
            alive[i] = 1;
            if (!low.empty() && x <= low.top().first) { low.push({x, i});  side[i] = 0; nl++; }
            else                                      { high.push({x, i}); side[i] = 1; nh++; }

            if (i >= k) {                       // 左端滑出：只打失效标记
                int j = i - k;
                alive[j] = 0;
                if (side[j] == 0) nl--; else nh--;
            }
            if (i < k - 1) continue;            // 窗口未满，既不平衡也不取中位数

            clean();
            while (nl > target) {               // low 偏多：最大值交给 high
                auto p = low.top(); low.pop();
                high.push(p); side[p.second] = 1; nl--; nh++;
                clean();
            }
            while (nl < target) {               // low 偏少：换入 high 的最小值
                auto p = high.top(); high.pop();
                low.push(p); side[p.second] = 0; nl++; nh--;
                clean();
            }
            if (k & 1) res.push_back((double)low.top().first);
            else res.push_back(((double)low.top().first + (double)high.top().first) / 2.0);
        }
        return res;
    }
};
```

### Python

```python
import heapq
from typing import List


class Solution:
    def medianSlidingWindow(self, nums: List[int], k: int) -> List[float]:
        n = len(nums)
        low, high = [], []      # 大顶堆（存 -值）：较小半；小顶堆：较大半
        alive = [False] * n     # 下标是否仍在窗口内
        side = [0] * n          # 下标所在堆：0 -> low, 1 -> high
        nl = nh = 0             # 两堆中「有效」元素个数
        target, res = (k + 1) // 2, []

        def clean() -> None:    # 反复弹掉堆顶的失效元素
            while low and not alive[low[0][1]]:
                heapq.heappop(low)
            while high and not alive[high[0][1]]:
                heapq.heappop(high)

        for i, x in enumerate(nums):
            alive[i] = True
            if low and x <= -low[0][0]:
                heapq.heappush(low, (-x, i)); side[i] = 0; nl += 1
            else:
                heapq.heappush(high, (x, i)); side[i] = 1; nh += 1
            if i >= k:                      # 左端滑出：只打失效标记
                j = i - k
                alive[j] = False
                if side[j] == 0: nl -= 1
                else: nh -= 1
            if i < k - 1:                   # 窗口未满，既不平衡也不取中位数
                continue
            clean()
            while nl > target:              # low 偏多：最大值交给 high
                v, idx = heapq.heappop(low)
                heapq.heappush(high, (-v, idx)); side[idx] = 1; nl -= 1; nh += 1
                clean()
            while nl < target:              # low 偏少：换入 high 的最小值
                v, idx = heapq.heappop(high)
                heapq.heappush(low, (-v, idx)); side[idx] = 0; nl += 1; nh -= 1
                clean()
            res.append(float(-low[0][0]) if k & 1
                       else (-low[0][0] + high[0][0]) / 2.0)
        return res
```

## 8. 边界情况与易错点

1. **`k = 1`**：窗口只有一个数，答案就是原数组的浮点形式。此时 low 目标是 1，第一步插入后若立刻去平衡，就会从空堆取元素而崩溃；平衡与输出都要限制在 $i \ge k-1$。
2. **偶数 `k` 的溢出**：`nums[i]` 可达 $2^{31}-1$，两个中位数相加会溢出 `int`，必须转 `long long`/`double` 再除 2；Python 整数不会溢出。
3. **按值延迟删除是错的**：`nums = [1,1,2,3]`、`k = 2` 这类重复值会同时出现在两个堆里，按值的删除计数会被错误的堆消耗，失效元素随后被当成有效元素。
4. **忘记 `clean` 就读堆顶**：失效元素恰好是最大值/最小值时堆顶一定是脏的，读出来直接错；三处读堆顶前都要 `clean`。
5. **用物理大小判断规模**：失效元素让物理大小虚高，$n_l$ 随之漂移，两半元素个数不再等于 $\lceil k/2 \rceil$ 与 $\lfloor k/2 \rfloor$。
6. **奇数 `k` 不能做成「两堆等大」**：low 必须多放一个，否则 $\max(\text{low})$ 不是中位数而是第 $\lfloor k/2 \rfloor$ 小。
7. **全相同元素**：值全相等也正确——失效标记按下标区分，low/high 里放的是同值的不同副本。
