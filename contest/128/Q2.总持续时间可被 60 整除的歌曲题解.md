# LeetCode 总持续时间可被 60 整除的歌曲 题解

## 1. 题目概述

- **标题 / 题号**：总持续时间可被 60 整除的歌曲（#1010，medium）
- **链接**：https://leetcode.cn/problems/pairs-of-songs-with-total-durations-divisible-by-60/
- **来源**：LeetCode 第 128 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：给定歌曲时长数组 `time`，统计满足 $i < j$ 且 $(time[i] + time[j]) \bmod 60 = 0$ 的下标对数量。

**约束**：

- $1 \le time.length \le 6 \times 10^4$
- $1 \le time[i] \le 500$

## 2. 示例

**示例 1**

```text
输入：time = [30,20,150,100,40]
输出：3
解释：
(30, 150) → 180
(20, 100) → 120
(20, 40)  → 60
共 3 对。
```

**示例 2**

```text
输入：time = [60,60,60]
输出：3
解释：任意两对之和都是 120，C(3,2) = 3。
```

**示例 3**

```text
输入：time = [1,2,3]
输出：0
解释：任意两首之和都小于 60 且不为 60 的倍数。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $i < j$，判断两数之和能否被 60 整除。时间复杂度 $O(n^2)$，$n = 6\times 10^4$ 时约 $1.8 \times 10^9$ 次判断，必然超时。

但暴力揭示了关键：**判断只依赖两数之和模 60 的余数**，与具体数值无关。$30 + 150$ 和 $30 + 90$ 都贡献同一对余数 $(30, 30)$。

### 3.2 核心观察：按余数配对，边扫边统计

![按余数配对：r 与 (60−r) mod 60 互补](images/wc128_q2_remainder_concept.svg)

把每首歌的时长替换成余数 $r = time[i] \bmod 60 \in [0, 59]$。两首歌能配对的条件是

$$(r_i + r_j) \bmod 60 = 0 \iff r_j = (60 - r_i) \bmod 60$$

所以，**一个余数为 $r$ 的歌曲，只能与余数为 $(60-r) \bmod 60$ 的歌曲配对**。这样问题就变成「按余数计数，再两两组合」：

- 用一个长度 60 的计数数组 `cnt`，`cnt[r]` 表示「已扫描过的歌曲中余数为 $r$ 的数量」。
- 从左到右扫描。扫描到第 $i$ 首（余数 $r$）时，**它只能和左边的歌配对**，左边能配的数目恰好是 `cnt[(60 - r) % 60]`，累加到答案；然后 `cnt[r]++`。

这样每对 $(i, j)$（$i < j$）恰好在下标 $j$ 处被统计一次，不重不漏。

注意两种「自配对」情形：

- $r = 0$：需要另一个余数 0，$(60-0)\bmod 60 = 0$，自动成立；
- $r = 30$：需要另一个余数 30，$(60-30)\bmod 60 = 30$，自动成立。

这两种情形用统一的 `(60 - r) % 60` 公式就自然处理了，不需要特判。

### 3.3 算法流程

![算法流程：先查互补余数的计数，再登记自己的余数](images/wc128_q2_flow.svg)

```text
1. cnt[60] = {0}，ans = 0
2. for t in time:
       r = t % 60
       ans += cnt[(60 - r) % 60]
       cnt[r] += 1
3. 返回 ans
```

顺序很重要：**先累加、后自增**。若反过来，会把自己和自己配成一对。

### 3.4 示例演算

![示例演算：time = [30,20,150,100,40] 的计数过程](images/wc128_q2_walkthrough.svg)

对示例 1 的 `time = [30,20,150,100,40]`：

| $i$ | $time[i]$ | 余数 $r$ | 需要的余数 | 此前 `cnt` | 新增对数 | `ans` |
|---|---|---|---|---|---|---|
| 0 | 30 | 30 | 30 | `cnt[30]=0` | 0 | 0 |
| 1 | 20 | 20 | 40 | `cnt[40]=0` | 0 | 0 |
| 2 | 150 | 30 | 30 | `cnt[30]=1` | 1 | 1 |
| 3 | 100 | 40 | 20 | `cnt[20]=1` | 1 | 2 |
| 4 | 40 | 40 | 20 | `cnt[20]=1` | 1 | 3 |

总计 3 对 ✓，与示例输出一致。三个新增对分别是 $(30,150)$、$(20,100)$、$(20,40)$，全部在下标较大处被计入。

再看示例 2 的 `[60,60,60]`：三个余数都是 0，第 1 首新增 0、第 2 首新增 1（与第 1 首配）、第 3 首新增 2，合计 3 ✓。

## 4. 算法细节

1. **余数数组代替哈希表**：余数只有 $0 \sim 59$，用 `int cnt[60]` 即可，比 `unordered_map` 快一个数量级，且没有哈希冲突。
2. **先查后加**：这一顺序保证只统计 $i < j$ 的对，避免重复计数与自配对。
3. **`(60 - r) % 60` 不能简化成 `60 - r`**：当 $r = 0$ 时后者得 60，会数组越界；取模后得 0 才正确。
4. **答案规模**：最多 $\binom{60000}{2} \approx 1.8 \times 10^9$，恰好小于 `INT_MAX`（$2.147 \times 10^9$），用 `int` 不会溢出；但用 `long long` 累加更稳妥，避免题目数据范围微调后翻车。
5. **`time[i] % 60` 的语义**：本题 `time[i] \ge 1`，不会出现负数取模的问题；若允许负数，C++ 的 `%` 会返回负余数，需要 `(r % 60 + 60) % 60`。
6. **无需排序**：配对与顺序无关，但「按较大下标计入」要求按下标顺序扫描，排序会破坏下标关系。
7. **重复元素**：相同余数的多首歌之间两两配对，公式自动累加（第 $k$ 首与前面 $k-1$ 首各配一次）。

## 5. 正确性证明

**引理 1（配对判据）**：对任意 $a, b \in [0, 59]$，$(a + b) \bmod 60 = 0 \iff b = (60 - a) \bmod 60$。

**证明**：$a + b \equiv 0 \pmod{60} \iff b \equiv -a \equiv 60 - a \pmod{60}$。由于 $b \in [0,59]$，同余类中唯一的代表元就是 $(60-a) \bmod 60$。∎

**引理 2（统计不重不漏）**：对每一对 $i < j$，算法恰在下标 $j$ 处把这一对计入一次。

**证明**：扫描到 $j$ 时，`cnt[(60 - r_j) % 60]` 统计的是「下标 $< j$ 且余数为 $(60-r_j)\bmod 60$ 的歌曲数」。由引理 1，余数为 $r_i$ 的 $i$ 与 $j$ 可配对 $\iff r_i = (60-r_j)\bmod 60$。故 `i` 被计入当且仅当 $(i,j)$ 可配对。每一对 $(i,j)$ 只在 $j$ 处被检查一次（因为 $i < j$ 固定），故不重不漏。∎

**定理**：算法返回值等于满足条件的下标对数量。

**证明**：由引理 2，`ans` 是「可配对且 $i<j$」的有序对 $(i,j)$ 的个数；而每个合法的无序对恰有唯一一种 $i<j$ 的写法，故 `ans` 恰为所求对数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每首歌做一次取模、一次数组查询、一次自增，都是 $O(1)$；总计 $n \le 6\times10^4$ 次。
- **空间**：$O(60) = O(1)$。定长计数数组，与 $n$ 无关。
- 对比：暴力 $O(n^2)$；排序 + 双指针需要 $O(n\log n)$ 且要额外处理「等于 30 和 0 的自配对」边界，反而不如计数简洁。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numPairsDivisibleBy60(vector<int>& time) {
        int cnt[60] = {0};
        long long ans = 0;
        for (int t : time) {
            int r = t % 60;
            ans += cnt[(60 - r) % 60];
            cnt[r]++;
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def numPairsDivisibleBy60(self, time: list[int]) -> int:
        cnt = [0] * 60
        ans = 0
        for t in time:
            r = t % 60
            ans += cnt[(60 - r) % 60]
            cnt[r] += 1
        return ans
```

## 8. 边界情况与易错点

1. **先自增后查询**：会把自己算进去（$r + r$ 恰好被 60 整除的 $r$ 只有 0 和 30），导致答案偏大。
2. **`60 - r` 忘记取模**：$r = 0$ 时下标为 60，数组越界（C++ 是 UB，Python 会 `IndexError`）。
3. **`n = 1`**：返回 0，代码天然正确。
4. **全部是 60 的倍数**：所有余数为 0，答案 $\binom{n}{2}$，注意用 `long long` 累加避免溢出。
5. **余数 30 自配对**：如 `[30,30]`，答案是 1；`[30,30,30]` 是 3。统一公式自动处理，不需要特判。
6. **用值域而非余数建表**：$time[i] \le 500$ 看着很小，但真正相关的是模 60 的余数；按值建表会漏掉 $150$ 与 $30$ 的等价性。
7. **重复计数**：若对每个 $i$ 都统计「右边的可配对数」再加起来，会重复计数；只能按较大下标计入一次。
8. **负数取模**（扩展到允许负数时）：C++ 的 `-1 % 60 == -1`，需要归一化到 $[0,59]$。
