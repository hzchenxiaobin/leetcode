# LeetCode 替换数组中的元素 题解

## 1. 题目概述

- **标题 / 题号**：替换数组中的元素（#2295，medium）
- **链接**：https://leetcode.cn/problems/replace-elements-in-an-array/
- **来源**：LeetCode 第 296 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：给定下标从 $0$ 开始、含 $n$ 个**互不相同**正整数的数组 `nums`，对其执行 $m$ 个操作：第 $i$ 个操作把数组中的数值 $\textit{operations}[i][0]$（记作 $\textit{from}$）替换为 $\textit{operations}[i][1]$（记作 $\textit{to}$）。题目保证执行第 $i$ 个操作时 $\textit{from}$ 一定在数组中、$\textit{to}$ 一定不在。返回执行完全部操作后的数组。

**约束**：

- $n = \textit{nums.length}$，$m = \textit{operations.length}$，$1 \le n, m \le 10^5$
- `nums` 中所有数字互不相同
- $\textit{operations}[i].\text{length} = 2$
- $1 \le \textit{nums}[i],\ \textit{operations}[i][0],\ \textit{operations}[i][1] \le 10^6$
- 执行第 $i$ 个操作时，$\textit{operations}[i][0]$ 在 `nums` 中存在，$\textit{operations}[i][1]$ 不存在

> 💡 本题在本仓库另有[每日题解 2295](../../solution/2201-2300/2295_替换数组中的元素.md)：以「值→下标反向索引」为主线，附「取消 to 不存在保证」的扩展与面试问答。本篇按**周赛复盘视角**展开：30 秒从题面到 $O(n+m)$ 的最短路径、互异性不变量与「值的一生」链式观察、引理-定理证明与边界清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4,6], operations = [[1,3],[4,7],[6,1]]
输出：[3,2,7,1]
解释：
- 将 1 替换为 3 → [3,2,4,6]
- 将 4 替换为 7 → [3,2,7,6]
- 将 6 替换为 1 → [3,2,7,1]
```

**示例 2**

```text
输入：nums = [1,2], operations = [[1,3],[2,1],[3,2]]
输出：[2,1]
解释：
- 将 1 替换为 3 → [3,2]（1 消失，3 新生）
- 将 2 替换为 1 → [3,1]（1 复活，挂到下标 1）
- 将 3 替换为 2 → [2,1]（新生值 3 早逝）
```

**补充示例：单槽位乒乓**

```text
输入：nums = [1], operations = [[1,2],[2,1]]
输出：[1]
解释：同一个格子被反复改写——替换是「原地换值」，
值可以死而复生，数组长度始终为 n。
```

> ⚠️ 示例 2 与补充示例揭示了本题的全部坑点：**值的一生是链式的**——旧值被删掉后可能被后续操作「复活」到另一个下标；刚写入的新值也可能立刻被下一操作替换。索引必须**实时同步**，任何「一次预处理、事后套用」的静态想法都会翻车（见 §3.4）。

## 3. 解题思路

### 3.1 暴力思路：每个操作线性扫数组找 from

对每个操作 $[\textit{from},\ \textit{to}]$，从头到尾扫描 `nums` 找到值等于 $\textit{from}$ 的下标，原地写入 $\textit{to}$。单个操作 $O(n)$，总计 $O(n \times m) \approx 10^{10}$，必然超时。

瓶颈不在「改」而在「找」：数组天然只支持**按下标取值** $O(1)$，不支持**按值找下标**。$m$ 次「找值」每次都要付 $O(n)$ 的线性代价——缺的是一张**反向索引**。

### 3.2 核心观察：互不相同 ⇒ 值可作键，「值→下标」倒排索引

![核心观察：互不相同让「值→下标」成为双射，O(1) 定位替换](images/wc296_q3_value_index_concept.svg)

**观察 1（值是身份证）**：`nums` 互不相同，且由题目保证可归纳出——**任一时刻**数组元素都互不相同（每步恰好删一个值、写一个新鲜值）。于是「值 → 下标」是一张**双射**：知道值就唯一确定位置，$O(1)$ 可查。

**观察 2（两个保证 = 增删永不冲突）**：

- $\textit{from}$ 一定存在 ⇒ 查询 $\textit{pos}[\textit{from}]$ 必命中；
- $\textit{to}$ 一定不存在 ⇒ 写入 $\textit{pos}[\textit{to}]$ 不会覆盖任何已有键。

两者合起来：只要每步**一删一增**同步维护，$\textit{pos}$ 永远是当前数组的实时镜像。

于是每个操作三步、每步 $O(1)$：

1. **查**：$\textit{idx} = \textit{pos}[\textit{from}]$；
2. **改**：$\textit{nums}[\textit{idx}] = \textit{to}$（原地换值，其他元素纹丝不动）；
3. **同步**：删 $\textit{pos}[\textit{from}]$，置 $\textit{pos}[\textit{to}] = \textit{idx}$。

### 3.3 算法流程

![算法流程：建索引 → 逐操作「查、改、同步」→ 返回](images/wc296_q3_algorithm_flow.svg)

```text
1. pos ← 空哈希表
2. for i = 0 .. n-1:  pos[nums[i]] = i        # O(n) 建倒排索引
3. for (from, to) in operations:               # 重复 m 次
   a. idx ← pos[from]                          # 查，O(1)
   b. nums[idx] ← to                           # 改，O(1)
   c. 删除 pos[from]，置 pos[to] = idx          # 同步，O(1)
4. 返回 nums
```

### 3.4 示例演算：「值的一生」

![示例演算：示例 1 逐步走查与示例 2 的链式替换](images/wc296_q3_example_walkthrough.svg)

**示例 1 走查**（`nums = [1,2,4,6]`）：

| 步骤 | 操作 | 替换后 `nums` | `pos` 同步 |
|------|------|---------------|------------|
| 初始 | — | `[1, 2, 4, 6]` | `{1:0, 2:1, 4:2, 6:3}` |
| ① | `[1,3]` | `[3, 2, 4, 6]` | 删 `1→0`，加 `3→0` → `{3:0, 2:1, 4:2, 6:3}` |
| ② | `[4,7]` | `[3, 2, 7, 6]` | 删 `4→2`，加 `7→2` → `{3:0, 2:1, 7:2, 6:3}` |
| ③ | `[6,1]` | `[3, 2, 7, 1]` | 删 `6→3`，加 `1→3` → `{3:0, 2:1, 7:2, 1:3}` |

返回 `[3,2,7,1]` ✓。

**示例 2 的链式结构**（`nums = [1,2]`，见上图下半部分）：两个槽位的演化史各成一条链：

```text
槽位 0：1 —op①[1,3]→ 3 —op③[3,2]→ 2
槽位 1：2 —op②[2,1]→ 1
```

- 值 $1$ 被 op① 删除后，又被 op② **复活**（挂到新的下标 1 上）；
- 值 $3$ 由 op① **新生**，又被 op③ 替换——**早逝**。

这说明「值 ↔ 下标」的对应关系随时间流转，唯一可靠的做法是**每步同步增删**，让 `pos` 始终描述「当前」的数组。它也解释了为什么朴素离线捷径不可行——比如「只记录每个 from 最后一次出现的操作、最后一次性套用」：替换沿链传播，直接套用会跳过链中间的环节（示例 2 中从初始值 $1$ 直接套其最后操作得 $3$，而真实终点是 $2$）。链的正确读法是倒序从尾部定型（见延伸思考的倒序压缩法）。

## 4. 算法细节

- **建索引**：一遍 $O(n)$ 扫描构造 $\textit{pos}[\textit{nums}[i]] = i$。因元素互异，不存在键冲突。
- **三步顺序不可乱**：必须先 `idx = pos[from]` 取出下标，再 `erase(from)`、`pos[to] = idx`。若先删后读，C++ 的 `unordered_map::operator[]` 会为缺失键**默认插入**一个垃圾值，Python 则抛 `KeyError`——都是访问已删除键的越权行为。
- **一删一增，规模恒定**：每步删一个键加一个键，`pos` 恒有 $n$ 个键值对，空间与值域大小（$10^6$）无关。
- **值域数组的替代**：因 $1 \le v \le 10^6$，可用 `vector<int> pos(1000001, -1)` 代替哈希表，查询/更新无哈希开销、常数更小；代价是 $O(V)$ 空间（约 4 MB）。哈希表版本更通用（值域大、稀疏都无碍），赛场按值域稠密度二选一。
- **原地换值**：替换只动一个格子，不移动、不交换、不追加——数组长度始终为 $n$，答案就是原数组。

## 5. 正确性证明

**引理 1（互异性不变量）**：对任意时刻 $t \in \{0, 1, \dots, m\}$（执行完前 $t$ 个操作后），`nums` 中元素互不相同。

**证明**：对 $t$ 归纳。$t = 0$ 时由题设互异。设 $t$ 时刻互异，考察第 $t+1$ 个操作 $[\textit{from}, \textit{to}]$：由保证，$\textit{from}$ 在数组中、$\textit{to}$ 不在数组中。操作后 $\textit{from}$ 消失、$\textit{to}$ 出现在原 $\textit{from}$ 的位置、其余元素未动。若操作后出现重复，只可能是 $\textit{to}$ 与某个未动元素相同——与「$\textit{to}$ 不在数组中」矛盾。∎

**引理 2（索引镜像不变量）**：若在每步操作前 $\textit{pos} = \{(v, i) \mid \textit{nums}[i] = v\}$ 恰是当前数组的值→下标双射（由引理 1，双射存在），则执行「查、改、同步」三步后不变量仍成立。

**证明**：三步后，数组中 $\textit{from}$ 被移除、$\textit{to}$ 出现在下标 $\textit{idx}$。同步步骤恰好删除键 $\textit{from}$（对应被移除的元素）、添加键 $\textit{to} \to \textit{idx}$（对应新出现的元素）。由引理 1，$\textit{to}$ 在新数组中唯一，新键不与任何保留键冲突；其余键的对应关系未变。故 $\textit{pos}$ 仍是新数组的值→下标双射。∎

**定理**：算法返回的数组等于按题意逐操作字面替换后的最终数组。

**证明**：对操作步数 $t$ 归纳，证「执行完前 $t$ 步后，算法的 `nums` 等于字面模拟的结果，且 $\textit{pos}$ 满足镜像不变量」。$t = 0$：数组未动，建索引后由引理 1 不变量成立。设 $t$ 时命题成立，则第 $t+1$ 步中 $\textit{idx} = \textit{pos}[\textit{from}]$ 由镜像不变量恰为 $\textit{from}$ 的真实下标，写入位置与字面替换一致；由引理 2，执行后命题对 $t+1$ 成立。取 $t = m$ 即得定理。∎

> 💡 证明骨架是**双不变量归纳**：引理 1 保证「值可作键」永远成立（互异性），引理 2 保证「键永远镜像数组」（同步性）。两个不变量一环扣一环，是所有「哈希实时索引」类题目的通用证明模板。

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。建索引扫描 `nums` 一遍 $O(n)$；$m$ 个操作每个做常数次哈希查询/插入/删除，均摊 $O(1)$，合计 $O(m)$。$n, m \le 10^5$ 时约 $2 \times 10^5$ 次哈希操作，远在时限内。
- **空间复杂度**：$O(n)$。`pos` 一删一增，键数恒为 $n$；原地修改 `nums` 不额外占用。若用值域数组替代则 $O(V)$，$V = 10^6$ 约 4 MB。

## 7. 参考代码

### C++（哈希表）

```cpp
class Solution {
  public:
    vector<int> arrayChange(vector<int>& nums, vector<vector<int>>& operations) {
        unordered_map<int, int> pos;
        for (int i = 0; i < (int)nums.size(); ++i)
            pos[nums[i]] = i;
        for (auto& op : operations) {
            int idx = pos[op[0]];
            nums[idx] = op[1];
            pos.erase(op[0]);
            pos[op[1]] = idx;
        }
        return nums;
    }
};
```

### C++（值域数组版，$v \le 10^6$ 时更快）

```cpp
class Solution {
  public:
    vector<int> arrayChange(vector<int>& nums, vector<vector<int>>& operations) {
        vector<int> pos(1000001, -1);
        for (int i = 0; i < (int)nums.size(); ++i)
            pos[nums[i]] = i;
        for (auto& op : operations) {
            int idx = pos[op[0]];
            nums[idx] = op[1];
            pos[op[0]] = -1;
            pos[op[1]] = idx;
        }
        return nums;
    }
};
```

### Python

```python
class Solution:
    def arrayChange(self, nums: List[int], operations: List[List[int]]) -> List[int]:
        pos = {v: i for i, v in enumerate(nums)}
        for old, new in operations:
            idx = pos.pop(old)
            nums[idx] = new
            pos[new] = idx
        return nums
```

## 8. 边界情况与易错点

1. **别线性扫**：每个操作 $O(n)$ 地找 $\textit{from}$，总量 $O(nm) \approx 10^{10}$ 必超时——本题唯一的「难度」就在这一刀：补反向索引。
2. **三步顺序**：先取 `idx`、再删键、再加键。先删后读会访问已删除键（C++ `operator[]` 还会默认插入垃圾项）；Python 推荐 `dict.pop(old)` 一步完成取值与删除。
3. **链式替换**：值会被删掉再复活（示例 2 的 $1$）、新生值会早逝（示例 2 的 $3$）。索引必须逐步同步，不能「先离线统计每个值被替换成什么、最后一次性套用」——替换沿链传播，直接套用会跳过链的中间环节。
4. **「只加不删」是踩线行为**：若忘记删旧键，靠「值重新入数组时会重写该键」这一保证，查询恰好都新鲜、结果碰巧正确，但 `pos` 会积累脏键、规模涨到 $O(n+m)$，且依赖了题目的隐式保证——务必删。
5. **原地换值，不是交换**：`from` 的位置写入 `to`，`from` 从此消失；数组长度恒为 $n$。
6. **值域数组版**：大小开 $10^6 + 1$（上界 $10^6$ 是**闭**边界），初值 $-1$ 作「不存在」哨兵。
7. **单槽位大量操作**：$n = 1$、$m = 10^5$，同一格子被反复改写（补充示例的乒乓），算法天然支持。
8. **哈希键是值不是下标**：方向别建反——按下标找值，数组本身就是 $O(1)$，要补的是反方向。

**延伸思考**：

- **倒序链压缩（离线替代法）**：把每个槽位的演化看成一条链，则值的命运在**倒序**处理时从链尾先定型：从后往前扫操作，维护映射 $\textit{nxt}$，对操作 $[\textit{from}, \textit{to}]$ 置 $\textit{nxt}[\textit{from}] = \textit{nxt}.\text{get}(\textit{to}, \textit{to})$（$\textit{to}$ 若日后再被替换，其最终归宿已在更早的倒序步骤中算好）；最后 $\textit{ans}[i] = \textit{nxt}.\text{get}(\textit{nums}[i], \textit{nums}[i])$。全程不维护数组本体，同样 $O(n+m)$。但要小心同一值多次「转世」时 `nxt` 的覆盖次序——正向模拟天然规避这些坑，赛场上首选正向。
- **取消「to 不存在」保证**：互异性被破坏，「值→下标」退化为「值→下标集合」（如 `map<int, set<int>>`），替换时从集合任取一个下标迁移；详见每日题解 §5 的展开。
- **值域稀疏或巨大**（如 $10^9$、负数）：值域数组失效，哈希表是首选；若还要求最坏 $O(1)$ 查询，可换平衡树（`std::map`，单次 $O(\log n)$）。
