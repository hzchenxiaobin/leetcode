# LeetCode 设计一个文本编辑器 题解

## 1. 题目概述

- **标题 / 题号**：设计一个文本编辑器（#2296，hard）
- **链接**：https://leetcode.cn/problems/design-a-text-editor/
- **来源**：LeetCode 第 296 场周赛 Q4
- **难度**：困难
- **标签**：栈、设计、字符串、模拟、链表

**题意**：设计一个带光标的文本编辑器 `TextEditor`，支持四种操作：

- `addText(text)`：在光标处插入 `text`，插入后光标位于 `text` 的右侧；
- `deleteText(k)`：删除光标左侧 $k$ 个字符（退格键语义），返回**实际删除**的字符数；
- `cursorLeft(k)` / `cursorRight(k)`：光标左移 / 右移 $k$ 次（**不能移出文本**），返回移动后光标左边 $\min(10, \textit{len})$ 个字符，其中 $\textit{len}$ 是移动后光标左侧的字符数。

任意时刻光标都在文本内部，即 $0 \le \textit{pos} \le \textit{len}$。

**约束**：

- $1 \le \textit{text.length},\ k \le 40$
- `text` 只含小写英文字母
- 四个接口的**总调用次数** $\le 2 \times 10^4$
- 进阶：每个操作 $O(k)$

> 💡 本题在本仓库另有[每日题解 2296](../../solution/2201-2300/2296_设计一个文本编辑器.md)：以「对顶栈即拆成两段的 gap buffer」为主线，附面试要点。本篇按**周赛复盘视角**展开：暴力瓶颈分析、搬运顺序的不变量证明、边界清单与同场四题的收官串联，两篇互为印证。

## 2. 示例

**示例 1**

[[], ["leetcode"], [4], ["practice"], [3], [8], [10], [2], [6]]
输出：
[null, null, 4, null, "etpractice", "leet", 4, "", "practi"]

解释：
addText("leetcode")   → "leetcode|"            （| 表示光标）
deleteText(4)          → "leet|"，返回 4
addText("practice")    → "leetpractice|"
cursorRight(3)         → 光标已在末尾，无法右移，返回 "etpractice"
cursorLeft(8)          → "leet|practice"，返回 "leet"
deleteText(10)         → 左侧只有 4 个，返回 4，文本 "|practice"
cursorLeft(2)          → 左侧为空，无法左移，返回 ""
cursorRight(6)         → "practi|ce"，返回 "practi"
```

**补充示例：截断与窗口**

addText("abcdef")  → "abcdef|"，返回 null
cursorLeft(3)      → "abc|def"，返回 "abc"

```

## 3. 解题思路

### 3.1 暴力思路：整串维护 + 光标下标

最直接的模拟：用 `string s` 存全部文本、`int pos` 存光标位置。

- `addText`：`s.insert(pos, text)`，并把 `pos` 增加 $|\textit{text}|$；
- `deleteText`：`s.erase(pos - cnt, cnt)`；
- `cursorLeft / cursorRight`：修改 `pos` 本身 $O(1)$，再取 `s.substr(pos - m, m)` 构造返回值，$O(10)$。

问题出在 `insert` / `erase`：它们要把光标**右侧的整段文本**逐字符后移 / 前移，单次 $O(n)$。最坏情况下每次调用文本净增 $40$，$q = 2\times 10^4$ 次调用后文本长 $L \le 40q = 8 \times 10^5$，总代价

$$
\sum_{\text{调用}} O(L) \;=\; O(q \cdot L) \;\approx\; 1.6 \times 10^{10}
$$

次字符移动，必然超时。**瓶颈：插入 / 删除在「挪动光标右边那段无辜的文本」**——而那段文本的内容与相对顺序从头到尾都没变过。

### 3.2 核心观察：光标劈开文本 ⇒ 对顶双栈

![核心观察：光标劈开文本成左右两个栈，栈顶贴光标](images/wc296_q4_two_stacks_concept.svg)

**观察 1（一切修改都发生在门口）**：插入加在光标左侧、删除删的是光标左侧、返回值看的是光标左侧 $10$ 个字符——距光标第 $1$ 格的字符被反复触碰，而距光标 $d$ 格的字符只在光标走满 $d$ 步后才会被碰到。

**观察 2（右半段是「刚体」）**：光标右侧那段文本永远不被改写、不被重排，它只是整体地「离光标更近或更远」。同理左半段除栈顶附近的插入删除外也是稳定的。

于是把文本在光标处切成两段，**各自装进一个栈，栈顶都朝向光标**：

- `left`：存光标左侧字符，**栈底 → 栈顶 = 文本正序**（栈顶恰是光标左邻）；
- `right`：存光标右侧字符，**栈顶 → 栈底 = 文本正序**（栈顶恰是光标右邻）。

「距光标第 1 格」就是栈顶，「门口」就是两个栈顶。所有 $O(n)$ 的整体挪动被消灭：插入 = 逐字符压 `left`；删除 = 从 `left` 弹出；移动光标 $k$ 格 = 在两栈之间搬运 $\min(k, \text{栈长})$ 个字符。**对顶栈（facing stacks）**由此得名。

### 3.3 算法流程：四种操作 = 字符在两栈间流动

![四种操作的字符流动：压入、弹出、跨光标搬运](images/wc296_q4_ops_flow.svg)

```text
addText(text)：
    for c in text: left.push(c)                    # 光标自然落在 text 右侧

deleteText(k)：
    cnt ← min(k, |left|)
    重复 cnt 次：left.pop()
    return cnt                                     # 实际删除数

cursorLeft(k)：
    cnt ← min(k, |left|)
    重复 cnt 次：right.push(left.pop())             # 弹 t 再弹 e……压过去恰成正序
    return left 顶部 min(10, |left|) 个字符（正序读出）

cursorRight(k)：
    cnt ← min(k, |right|)
    重复 cnt 次：left.push(right.pop())
    return left 顶部 min(10, |left|) 个字符（正序读出）
```

> 💡 注意搬运方向的巧妙之处：`cursorLeft` 从 `left` 弹出的顺序是「光标左邻、左邻的左边、……」，即**从右往左**；逐个压入 `right` 后，`right` 的栈顶到栈底恰好恢复**从左往右**的文本正序。反方向对称。这就是「栈顶贴光标」布局的回报——**往返搬运零额外整理**。

### 3.4 示例演算：leet|practice 的完整生命周期

![示例 1 逐步走查：压入、弹出、两次截断与两次搬运](images/wc296_q4_example_walkthrough.svg)

**关键三步**：

- **⑤ `cursorRight(3)`**：`right` 栈为空（光标本就在文本末尾），$\textit{cnt} = \min(3, 0) = 0$，光标原地不动，但返回值仍要照常计算——`left` 有 $13$ 个字符，返回顶部 $10$ 个 `"etpractice"`。**「移动失败」不等于「没有返回值」**。
- **⑥ `cursorLeft(8)`**：搬 $\min(8, 13) = 8$ 个字符（弹出顺序 `e,c,i,t,c,a,r,p`）到 `right`，两栈各剩 `leet` / `practice`。右侧整段 `practice` **从未被逐字符重排**，只是换了个栈。
- **⑧ `cursorRight(6)`**：再搬 $\min(6, 8) = 6$ 个回来（弹出顺序 `p,r,a,c,t,i` 恰为正序压回 `left`），文本变为 `practi|ce`，返回 `"practi"`。

## 4. 算法细节

- **数据结构选择**：不需要手写栈——C++ 的 `std::string` 自带 `push_back` / `pop_back`，本身就是字符栈，且取「末尾 $m$ 个字符」可直接 `substr`；Python 用 `list` + `append` / `pop`，返回时 `''.join(left[len(left)-m:])`。
- **截断统一公式**：所有「越界」都被 $\min(k, \text{栈长})$ 一行解决——左移不越过 $0$，右移不越过文本末尾，删除不超过左侧存量。**不存在任何特判分支**。
- **返回值窗口**：$m = \min(10, |\textit{left}|)$，返回 `left` 的**最后** $m$ 个字符、按文本正序。栈顶是光标左邻，所以「最后 $m$ 个」就是「紧贴光标的 $m$ 个」。
- **C++ 下标安全**：取窗口写成 `left.substr(left.size() - m)`——因为 $m$ 已经与 `left.size()` 取过 `min`，`left.size() - m` 不会无符号下溢；**切忌**直接写 `left.size() - 10`（见 §8）。
- **Python 切片安全**：`left[-m:]` 在 $m = 0$ 时即 `left[0:]` 是**整个列表**，必须写成 `left[len(left) - m:]` 或前置判空（见 §8）。
- **光标位置的显隐**：实现里根本没有 `pos` 变量——光标位置隐式地等于 $|\textit{left}|$，两栈长度之和恒等于当前文本长度。

## 5. 正确性证明

**不变量 I**：任意时刻，设当前文本为 $s$（$|s| = n$）、光标位置为 $p$（$0 \le p \le n$），则 `left` 从栈底到栈顶依次为 $s[0], s[1], \dots, s[p-1]$；`right` 从栈顶到栈底依次为 $s[p], s[p+1], \dots, s[n-1]$。

**引理 1（操作保不变量）**：若调用某接口前不变量 I 成立，则调用后 I 仍成立。

**证明**：逐操作验证。

- `addText(text)`：设 `text` 为 $t_1 t_2 \cdots t_j$。逐字符压入后，`left` 从栈底到栈顶为 $s[0..p-1] t_1 \cdots t_j$，新文本在原光标处拼接了 `text`、新光标位置 $p' = p + j$，恰好 $s'[0..p'-1]$ 即新文本前缀；`right` 未动，且 $s'[p'..] = s[p..]$。I 保持。∎
- `deleteText(k)`：设 $\textit{cnt} = \min(k, p)$，弹出 `left` 顶部 $\textit{cnt}$ 个后，`left` 为 $s[0..p-\textit{cnt}-1]$，即新文本（删去 $s[p-\textit{cnt}..p-1]$ 后）的前缀，新光标 $p' = p - \textit{cnt}$；`right` 与 $s'[p'..]$ 一致。I 保持。∎
- `cursorLeft(k)`：设 $\textit{cnt} = \min(k, p)$。第 $i$ 次搬运弹出的是 $s[p-i]$、压入 `right`。搬运完成后 `left` 为 $s[0..p-\textit{cnt}-1]$（新光标 $p' = p - \textit{cnt} = \max(0, p-k)$）；`right` 的栈顶到栈底为 $s[p-\textit{cnt}], \dots, s[p-1]$ 接上原来的 $s[p..n-1]$，即完整的 $s[p'..n-1]$。I 保持。∎
- `cursorRight(k)`：与 `cursorLeft` 关于光标完全对称，新光标 $p' = \min(n, p+k)$。∎

**引理 2（截断即边界语义）**：光标左移 / 右移 $k$ 次且不越出文本，等价于 $p \to \max(0, p-k)$ / $p \to \min(n, p+k)$；删除 $k$ 个等价于删去 $\min(k, p)$ 个。

**证明**：光标每次左移一格要求当前 $p \ge 1$，故从 $p$ 出发至多移 $p$ 格，总移动量 $\min(k, p)$；右移同理至多 $n - p$ 格。删除键只作用于光标左侧，存量 $p$ 即上限。∎

**定理**：算法对每个接口的行为与返回值均符合题意。

**证明**：对调用次数归纳。初始时文本为空、两栈皆空，I 成立。由引理 1，I 在每次调用后保持，故任意时刻 `left` 精确表示光标左侧文本。于是：

- `deleteText` 返回 $\min(k, p)$，由引理 2 即实际删除数；
- `cursorLeft` / `cursorRight` 后，光标左侧共 $p' = |\textit{left}|$ 个字符，返回的是 `left` 末尾 $m = \min(10, p')$ 个字符且按正序读出，恰为题意要求的「光标左边 $\min(10, \textit{len})$ 个字符」。∎

> 💡 证明骨架是**单不变量归纳**：不变量 I 把「两个栈」和「一段文本 + 光标」绑成一个同构，四个操作全部化归为栈顶的局部动作。这是所有「用简单结构模拟复杂对象」题目的通用证明模板——先立同构，再证每步保同构。

## 6. 复杂度分析

- **时间复杂度**：单次调用 $O(k)$（或 $O(|\textit{text}|)$，上界均为 $40$）——压、弹、搬运都是单字符 $O(1)$，每个接口至多执行 $\min(k, \cdot) \le 40$ 次；构造返回值再花 $O(\min(10, |\textit{left}|)) \le O(10)$。全部 $q \le 2\times 10^4$ 次调用合计至多 $40 \times 2 \times 10^4 = 8 \times 10^5$ 次栈操作，**达成进阶要求**。
- **空间复杂度**：$O(L)$，$L$ 为当前文本长度（两栈长度之和恒等于 $L$，最大 $8 \times 10^5$ 个字符）。无其余开销。

## 7. 参考代码

### C++

```cpp
class TextEditor {
  public:
    TextEditor() {}

    void addText(string text) {
        for (char c : text) left.push_back(c);
    }

    int deleteText(int k) {
        int cnt = min(k, (int)left.size());
        for (int i = 0; i < cnt; ++i) left.pop_back();
        return cnt;
    }

    string cursorLeft(int k) {
        shift(min(k, (int)left.size()));
        return lastTen();
    }

    string cursorRight(int k) {
        int cnt = min(k, (int)right.size());
        for (int i = 0; i < cnt; ++i) {
            left.push_back(right.back());
            right.pop_back();
        }
        return lastTen();
    }

  private:
    string left, right;   // left：光标左侧，栈顶 = 光标左邻
                           // right：栈顶 = 光标右邻（栈顶到栈底为文本正序）

    void shift(int cnt) { // 光标左移：left → right 搬运 cnt 个
        for (int i = 0; i < cnt; ++i) {
            right.push_back(left.back());
            left.pop_back();
        }
    }

    string lastTen() {
        int m = min(10, (int)left.size());
        return left.substr(left.size() - m, m);
    }
};
```

### Python

```python
class TextEditor:
    def __init__(self):
        self.left: list[str] = []    # 光标左侧，末尾 = 光标左邻
        self.right: list[str] = []   # 末尾 = 光标右邻

    def addText(self, text: str) -> None:
        self.left.extend(text)

    def deleteText(self, k: int) -> int:
        cnt = min(k, len(self.left))
        del self.left[len(self.left) - cnt:]
        return cnt

    def cursorLeft(self, k: int) -> str:
        for _ in range(min(k, len(self.left))):
            self.right.append(self.left.pop())
        return self._last_ten()

    def cursorRight(self, k: int) -> str:
        for _ in range(min(k, len(self.right))):
            self.left.append(self.right.pop())
        return self._last_ten()

    def _last_ten(self) -> str:
        m = min(10, len(self.left))
        return ''.join(self.left[len(self.left) - m:])
```

## 8. 边界情况与易错点

1. **`deleteText` 返回实际删除数** $\min(k, |\textit{left}|)$，不是 $k$。示例 1 第 ⑦ 步 `deleteText(10)` 只删 4 个、返回 4。
2. **返回值以「移动后」为准**：`cursorRight(3)` 即使一步没动（第 ⑤ 步），也要返回当前光标左侧 $\min(10, \textit{len})$ 个字符——「移动失败」≠「无返回值」。
3. **光标不能移出文本**：统一用 $\min(k, \text{栈长})$ 截断，不需要 `if` 特判；漏掉截断会让字符凭空消失或凭空出现。
4. **C++ 无符号下溢**（本题最经典的 RE 点）：`left.size() - 10` 在 `left.size() < 10` 时是巨大的无符号数，`substr` 将抛 `std::out_of_range`。必须先 `m = min(10, (int)left.size())` 再 `left.size() - m`。
5. **Python 切片陷阱**：`left[-m:]` 在 $m = 0$ 时是 `left[0:]` 即**整个列表**（空光标左侧却返回全部文本）；`del self.left[-cnt:]` 同理在 `cnt = 0` 时会把整栈删光。统一写成 `left[len(left) - m:]` 的正向切片。
6. **`right` 栈方向别搞反**：`right` 的**栈顶**是光标右邻（栈顶到栈底为文本正序）。若误存成「栈底到栈顶为正序」，`cursorRight` 搬回的字符顺序全倒。
7. **`deleteText` 与移动互不干扰**：删除只弹 `left` 不碰 `right`；移动只搬运不删除。混用逻辑（如移动时误弹丢弃字符）是常见笔误。
8. **`addText` 后光标在 text 右侧**：压入 `left` 后天然满足，无需额外调整——若实现中额外维护 `pos` 变量，记得同步 $|\textit{text}|$ 的增量。
9. **两栈长度和恒等于文本长度**：这是调试时的速查不变量，任何一步破坏它都说明弹 / 压不对称。

- **把 $k$ 和 $|\textit{text}|$ 放大到 $10^5$**：单次 $O(k)$ 也会累计到 $O(qk) = 10^9$ 量级。出路是换「对顶平衡树」：光标 = 两棵隐式 Treap（FHQ-Treap）的拼接点，插入 / 删除 / 移动全部变成 $O(\log n)$ 的 `split` / `merge`，取左侧 $10$ 个字符再单次 `split`——这也是各类「文本编辑器」OJ 母题的标准解。
- **对顶栈与 gap buffer 的等价性**：把两个栈换成两块可增长数组、摊还拷贝，正是编辑器实现中经典的 **gap buffer**（Emacs 长期使用的方案）；每篇题解侧重的复杂度口径不同——对顶栈按「本次操作搬运量」计 $O(k)$，gap buffer 按摊还计 $O(1)$ 均摊到每字符。
- **撤销 / 重做**：若再要求 `undo` / `redo`，对顶栈天然可扩展——额外记录每次操作的逆动作（或操作日志栈），`redo` 清空撤销栈，与 1472 的 `visit` 清空 forward 栈同构。
