# LeetCode 极大极小游戏 题解

## 1. 题目概述

- **标题 / 题号**：极大极小游戏（#2293，easy）
- **链接**：https://leetcode.cn/problems/min-max-game/
- **来源**：LeetCode 第 296 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定下标从 $0$ 开始、长度为 $2$ 的幂的整数数组 `nums`，反复执行下述「折叠」过程直到只剩一个数：每轮创建长度折半的新数组 `newNums`，对每个下标 $i \in [0, n/2)$，**偶数** $i$ 取 `min(nums[2i], nums[2i+1])`、**奇数** $i$ 取 `max(nums[2i], nums[2i+1])` 写入 `newNums[i]`。返回最终剩下的数字。

**约束**：

- $1 \le \text{nums.length} \le 1024$，且是 $2$ 的幂
- $1 \le \text{nums}[i] \le 10^9$

> 💡 本题在本仓库另有[每日题解 2293](../../solution/2201-2300/2293_极大极小游戏.md)：主线是「**原地折叠** + 满二叉树分治递归」，附面试问答与分治展开。本篇按**周赛复盘视角**展开，侧重签到题的**最短切入路径**（读题 → 算工作量 → 直译提交）、两类高频错误（**奇偶看错位置 / 原地自读自写**）、轮不变量证明与边界清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,5,2,4,8,2,2]
输出：1
解释：第一轮 → [1,5,4,2]；第二轮 → [1,4]；第三轮 → [1]，返回 1。
```

**示例 2**

```text
输入：nums = [3]
输出：3
解释：长度已是 1，算法直接终止，返回 3。
```

**补充示例：答案不是全局最小值**

```text
输入：nums = [3,5,1,2]
输出：2
解释：第一轮：i=0 偶 → min(3,5)=3；i=1 奇 → max(1,2)=2，得 [3,2]；
      第二轮：i=0 偶 → min(3,2)=2，得 [2]。答案 2 ≠ 全局最小值 1。
```

## 3. 解题思路

### 3.1 直译思路：每轮新建数组

签到题的标准动作：**逐句翻译题面**，不引入任何额外想法——

- 外层 `while (n > 1)` 控制轮数；每轮申请长度 $n/2$ 的新数组；
- 内层 `for i in [0, n/2)`，按 $i$ 奇偶填 `min` 或 `max`；结束后用新数组替换旧数组。

这个写法**就是正解**：时间 $O(n)$、空间 $O(n)$，$n \le 1024$ 下毫无压力。签到题的正确策略是「确认复杂度无忧后直译提交、不恋战」，把时间留给后面的题。

### 3.2 核心观察：配对折叠结构 + 奇偶规则作用于写位置

![核心观察：配对折叠与奇偶规则](images/wc296_q1_pair_fold_concept.svg)

三层观察让直译「抄得又快又对」：

1. **总工作量极小**：每轮 $n \to n/2$，共 $\log_2 n \le 10$ 轮；每轮 $n/2$ 次比较，总计 $n + n/2 + \cdots + 1 = 2n - 1 \le 2047$ 次运算。**任何不绕弯的实现都必然不超时**——这就是「直译即可提交」的底气。
2. **配对方式固定**：第 $i$ 个结果永远来自第 $2i$、$2i+1$ 个原值（相邻一对），与值的大小、原下标的奇偶**都无关**——不存在「聪明的配对」，也不会有人能少折叠一轮。
3. **奇偶看的是写入位置**（本题头号易错点）：`min`/`max` 由**新数组下标 $i$**（写位置）的奇偶决定，**不是**读取位置 $2i$、$2i+1$ 的奇偶。例：`max(5,2)=5` 落在 $i=1$（奇），即便 `5` 来自偶数位、`2` 来自奇数位也不影响。

> ⚠️ 观察 3 之外还有一个隐含的坑：最终答案**不一定是全局最小值**（见补充示例，$1$ 在奇位对里被 `max` 吞掉）。有「答案肯定是 $\min$」直觉的同学会在样例之外翻车——签到题也要老老实实模拟。

在此之上还有一个可选的**空间优化**：`newNums[i]` 其实可以直接写回 `nums[i]`——写位置 $i \le$ 读位置 $2i, 2i+1$，按 $i$ 递增处理不会踩踏，于是新数组是多余的（详见 §5 引理 1）。比赛时可以不追求，但它是把本题从「模拟」升华成「原地技巧」的关键一步，也是每日题解的主线。

### 3.3 算法流程

![算法流程：原地折叠](images/wc296_q1_algorithm_flow.svg)

1. `n ← nums.length`；
2. 若 $n = 1$，返回 `nums[0]`；
3. 对 $i = 0, 1, \dots, n/2 - 1$ 递增处理：偶 $i$ 执行 `nums[i] = min(nums[2i], nums[2i+1])`，奇 $i$ 执行 `nums[i] = max(nums[2i], nums[2i+1])`（原地写回，右值先算）；
4. $n \leftarrow n/2$，回到步骤 2。

### 3.4 示例演算

![示例演算：三轮折叠](images/wc296_q1_example_walkthrough.svg)

以示例 1 `nums = [1,3,5,2,4,8,2,2]` 走查：

| 轮 | 进入时数组 | 配对结果 | 结束时有效段 |
|----|-----------|---------|------------|
| 1 | `[1,3,5,2,4,8,2,2]`（n=8） | min(1,3)=1，max(5,2)=5，min(4,8)=4，max(2,2)=2 | `[1,5,4,2]` |
| 2 | `[1,5,4,2]`（n=4） | min(1,5)=1，max(4,2)=4 | `[1,4]` |
| 3 | `[1,4]`（n=2） | min(1,4)=1 | `[1]` |

返回 $1$ ✓。注意每轮 `min`/`max` 的选取只看**结果落位** $i$ 的奇偶：第 1 轮的 `5` 落在 $i=1$（奇）所以取 `max`，与它来自原数组偶数位无关。

## 4. 算法细节

1. **奇偶判定**：`(i & 1) == 0` 为偶取 `min`，否则取 `max`；等价于按 $i$ 交替切换运算符。
2. **原地折叠的处理顺序**：必须按 $i$ **从左到右**递增处理。每轮只写 `nums[0..n/2-1]`，后半段 `nums[n/2..n-1]` 不再被读取，直接废弃。
3. **$i=0$ 的自读自写**：`nums[0] = op(nums[0], nums[1])` 中读与写都涉及 `nums[0]`，依赖赋值语句「**右值先算**」保证安全——C++/Python 均如此，但若把一轮拆成「先写后读」的手动展开就会踩坑。
4. **逻辑长度与物理长度分离**：原地版只收缩逻辑长度 `n`，不动容器本身；`n >>= 1` 与 `n /= 2` 等价（$n$ 是 $2$ 的幂，整除精确）。
5. **无需任何预处理**：不排序、不找规律、不记录全局最值——纯模拟。

## 5. 正确性证明

**引理 1（读取保真）**：某一轮内按 $i$ 从 $0$ 到 $n/2-1$ 递增执行原地赋值，则处理下标 $i$ 时，`nums[2i]` 与 `nums[2i+1]` 仍持有**本轮开始时**的值。

**证明**：处理 $i$ 之前，本轮只写过下标 $0, 1, \dots, i-1$。若 $i \ge 1$，则 $2i \ge i+1 > i-1$ 且 $2i+1 > 2i > i-1$，两个读取位置都未被写过，值未变。若 $i = 0$，读取位置之一恰是写位置 $0$，但赋值语句的语义是**先求右值** `op(nums[0], nums[1])` 再回写，读取发生在写入之前。∎

**引理 2（轮不变量）**：一轮结束后，`nums[0..n/2-1]` 逐下标等于题面定义的 `newNums`。

**证明**：对每个 $i$，由引理 1，右值 `op(nums[2i], nums[2i+1])` 中两个操作数均为本轮原始值，与题面生成 `newNums[i]` 所用的操作数完全一致；运算符又由同一规则（$i$ 偶取 `min`、奇取 `max`）选取，故 `nums[i]` 被赋成的值与 `newNums[i]` 逐字相同。∎

**定理**：算法返回题面过程执行后剩下的那个数字。

**证明**：对轮数归纳。初始时 `nums[0..n-1]` 即题面初值。设某轮开始时有效段与题面一致：由引理 2，轮后 `nums[0..n/2-1]` 等于 `newNums`，与题面「用 `newNums` 替换 `nums`」后的长度 $n/2$ 数组一致，归纳传递。由于 $n$ 是 $2$ 的幂，每轮精确减半，有限轮后 $n = 1$，循环终止，此时 `nums[0]` 即题面剩下的数字。∎

> 💡 直译版（每轮新建数组）的正确性是平凡的；上面的引理-定理链专门为**原地版**补上了「写回不破坏后续读取」这关键一环——这也是原地技巧类题目通用的证明模板（对照 [27. 移除元素](../../solution/0001-0100/27_移除元素.md) 的快慢指针覆盖写）。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每轮做 $n/2$ 次 `min`/`max`，各轮长度构成等比数列，总运算 $n + n/2 + \cdots + 2 + 1 = 2n - 1$；$n \le 1024$ 时至多 $2047$ 次比较。
- **空间复杂度**：原地版 $O(1)$，仅 `n`、`i` 常数个变量；直译新建数组版 $O(n)$（单轮峰值 $n/2$，亦不叠加）。

## 7. 参考代码

### C++（主解：原地折叠，O(1) 额外空间）

```cpp
class Solution {
  public:
    int minMaxGame(vector<int>& nums) {
        int n = nums.size();
        while (n > 1) {
            for (int i = 0; i < n / 2; i++) {
                int a = nums[2 * i], b = nums[2 * i + 1];  // 右值先读，防 i=0 自读自写
                nums[i] = (i % 2 == 0) ? min(a, b) : max(a, b);
            }
            n >>= 1;
        }
        return nums[0];
    }
};
```

### C++（变体：直译题面，每轮新建数组）

```cpp
class Solution {
  public:
    int minMaxGame(vector<int>& nums) {
        while (nums.size() > 1) {
            vector<int> cur(nums.size() / 2);
            for (int i = 0; i < (int)cur.size(); i++) {
                int a = nums[2 * i], b = nums[2 * i + 1];
                cur[i] = (i % 2 == 0) ? min(a, b) : max(a, b);
            }
            nums = move(cur);
        }
        return nums[0];
    }
};
```

> 💡 两版逐轮等价（引理 2）：变体把「写回原数组」显式化，是赛场上下意识的最稳写法；主解省去每轮的申请/释放，把空间压到 $O(1)$。

### Python（与主解同构）

```python
class Solution:
    def minMaxGame(self, nums: List[int]) -> int:
        n = len(nums)
        while n > 1:
            for i in range(n // 2):
                a, b = nums[2 * i], nums[2 * i + 1]
                nums[i] = min(a, b) if i % 2 == 0 else max(a, b)
            n >>= 1
        return nums[0]
```

## 8. 边界情况与易错点

1. **头号易错：奇偶看错位置**。`min`/`max` 由**新数组下标 $i$（写位置）** 的奇偶决定，不是读取位置 $2i$、$2i+1$ 的奇偶。看错后示例 1 恰好不暴露（第 1 轮两组结果差别被后续轮掩盖与否不定），赛后对拍才会发现。
2. **原地 $i=0$ 自读自写**：`nums[0] = op(nums[0], nums[1])` 必须保证右值先算。C++/Python 单条赋值天然安全；若拆成先写后读的两步（或 lambda 捕获引用时机不当）就会踩坑。
3. **$n = 1$ 不进循环**：直接返回 `nums[0]`（示例 2）。循环条件写 `n > 1`，写 `n >= 1` 会死循环。
4. **$n/2$ 整除精确**：$n$ 是 $2$ 的幂，`n >>= 1` 与 `n /= 2` 均无余数损失；但若输入去掉「$2$ 的幂」保证（变体题），单元素落单需要重新定义规则。
5. **无溢出风险**：`min`/`max` 只**选择**不**运算**，$10^9$ 在 `int` 范围内。
6. **别找规律**：答案与全局 $\min/\max$ 没有简单关系（补充示例：`[3,5,1,2] → 2`），任何试图绕过模拟的「洞察」都是坑。
7. **值相同的对**：`min = max`，结果不受奇偶影响（示例 1 末对 `(2,2)`），无需特判。
