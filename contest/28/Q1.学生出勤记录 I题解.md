# LeetCode 学生出勤记录 I 题解

## 1. 题目概述

- **标题 / 题号**：学生出勤记录 I（#551，easy）
- **链接**：https://leetcode.cn/problems/student-attendance-record-i/
- **来源**：LeetCode 第 28 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定一个只含 `'A'`、`'L'`、`'P'` 的字符串 $s$，它按天记录学生状态：缺勤、迟到、到场。学生能拿到出勤奖励，当且仅当**同时**满足：

1. `'A'` 的总数**严格小于 2**（即至多缺勤 1 天）；
2. 不存在**连续 3 天或更多**的 `'L'`（即子串 `"LLL"` 不出现）。

返回 `true` 表示能获奖，否则返回 `false`。

**约束**：

- $1 \le \lvert s \rvert \le 1000$
- $s[i] \in \{\text{'A'}, \text{'L'}, \text{'P'}\}$

> 💡 本题是签名式签到题：接口名 `checkRecord(string s) -> bool`，没有任何隐藏操作，考的是「两个独立条件能否一次扫描同时维护」。

## 2. 示例

**示例 1**

```text
输入：s = "PPALLP"
输出：true
解释：缺勤 1 次（少于 2 次），最长连续迟到为 2 天（未达 3 天），两个条件都满足。
```

**示例 2**

```text
输入：s = "PPALLL"
输出：false
解释：缺勤虽然只有 1 次，但最后三天连续迟到，破坏了「连续 3 天」这条规则。
```

**示例 3（补充）**

```text
输入：s = "AA"
输出：false
解释：连续两次缺勤，`'A'` 的数量为 2，不满足「严格少于 2 天」。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**把两条规则分别暴力检查**：

- 用一层循环统计 `'A'` 的个数，$O(n)$；
- 用两层循环枚举所有三元组 $(i, i+1, i+2)$，判断是否三个位置都是 `'L'`，$O(n^2)$ 次比较（更好的是滑动窗口，$O(n)$）。

$n \le 1000$ 时 $O(n^2)$ 只有 $10^6$ 次操作，完全能过。但这类「多个独立条件同时判定」的题，正确的沉淀是**单次扫描 + 多个计数器**：它把两条规则的检查合并到同一个循环里，$O(n)$ 时间、$O(1)$ 空间，而且天然支持「违规即早退」。下面给出这个写法。

### 3.2 核心观察：两个条件都是「逐字符递推」的局部性质

![两条规则：缺勤计数与连续迟到计数](images/wc28_q1_two_rules.svg)

两条规则看似不同，其实都只需要**极少的记忆**：

- **规则 ①** 只关心 `'A'` 出现了几次，用一个整数 `cntA` 累加即可，与顺序无关；
- **规则 ②** 只关心「以当前位置结尾的连续 `'L'` 有多长」，用一个整数 `curL` 递推即可，与更早的历史无关。

因此整个扫描过程需要的状态只有 $(cntA, curL)$ 这一个二元组，且 $cntA \in \{0, 1, \ge 2\}$、$curL \in \{0, 1, 2, \ge 3\}$，只有常数种取值——**这是一个有限状态机**，所以既不需要额外数组，也不需要回溯。

> 💡 关键点：条件之间**互相独立**，所以两个计数器可以并行维护；但结论是 **AND**（任一违规即 `false`），不是 OR。

### 3.3 算法流程

![单次扫描：每个字符只做两种更新](images/wc28_q1_scan_flow.svg)

伪代码如下：

```text
cntA ← 0, curL ← 0
for ch in s:
    if ch == 'A':
        cntA ← cntA + 1
        curL ← 0                 # 缺勤也打断连续迟到
        if cntA >= 2: return false
    elif ch == 'L':
        curL ← curL + 1          # 自增，不是重置为 1
        if curL >= 3: return false
    else:                        # 'P'
        curL ← 0
return true                      # 扫完且从未触发违规
```

三个分支互斥且覆盖全部字符，因此循环体是 $O(1)$，总时间 $O(n)$。

### 3.4 示例演算

![示例演算：PPALLL 的逐步计数](images/wc28_q1_walkthrough.svg)

对 $s = \text{"PPALLL"}$ 逐步走查：

| 索引 $i$ | $s[i]$ | `cntA` | `curL` | 判定 |
|---|---|---|---|---|
| 0 | P | 0 | 0 | 继续 |
| 1 | P | 0 | 0 | 继续 |
| 2 | A | 1 | 0 | 继续（`cntA` 已清零 `curL`） |
| 3 | L | 1 | 1 | 继续 |
| 4 | L | 1 | 2 | 继续 |
| 5 | L | 1 | **3** | **违规，返回 `false`** |

对照组 $s = \text{"PPALLP"}$：`curL` 的峰值为 2，`cntA` 终值为 1，两个条件都没有被破坏，返回 `true`。

## 4. 算法细节

1. **两个计数器初值都为 0**，分别表示「已见缺勤次数」与「以当前位置结尾的连续迟到长度」。
2. **遇到 `'A'` 要同时做两件事**：`cntA += 1` 且 `curL = 0`。缺勤日既不是迟到，也会打断迟到连续段——漏掉后半句是最常见的错误。
3. **遇到 `'L'` 用 `curL += 1` 而不是 `curL = 1`**；写成赋 1 会让 `"LLL"` 永远检测不出来。
4. **`'P'` 只清零 `curL`**，不影响 `cntA`。
5. **判断用 `>=` 而不是 `==`**：`curL >= 3` 在提前返回的写法下等价，但若某次忘记早退，`>=` 仍然正确，鲁棒性更好。
6. **早退是安全的**：两个条件都只依赖「是否已经发生过违规」，一旦发生就无法被后续字符撤销，所以 `return false` 立刻返回不会漏判。
7. **不必构造子串**：Python 里可以一行 `s.count('A') < 2 and 'LLL' not in s` 通过，但那是**两次**扫描（且 `'LLL' not in s` 走的是 C 层，常数极小）；面试与周赛都建议写出单次扫描的通用版本，才能推广到「连续 $k$ 天」的变体。

## 5. 正确性证明

**引理 1（`cntA` 的语义）**：扫描结束后 `cntA` 等于 $s$ 中字符 `'A'` 的出现次数。

**证明**：对字符串长度归纳。初始 `cntA = 0`，空串中 `'A'` 个数为 0。设扫描完前 $i$ 个字符后 `cntA` 等于其中 `'A'` 的个数；扫描第 $i+1$ 个字符时，若它是 `'A'` 则 `cntA` 加 1，否则不变，恰好对应「前 $i+1$ 个字符中 `'A'` 的个数」。∎

**引理 2（`curL` 的语义）**：扫描到下标 $i$ 时，若尚未返回，则 `curL` 等于「以 $i$ 结尾的连续 `'L'` 的长度」。

**证明**：对 $i$ 归纳。$i = 0$ 时：若 $s[0] = \text{'L'}$，`curL` 变为 1，正确；否则 `curL` 为 0，正确。设结论对 $i-1$ 成立，考察 $s[i]$：若 $s[i] = \text{'L'}$，则以 $i$ 结尾的连续 `'L'` 长度为「以 $i-1$ 结尾的长度 $+ 1$」，而代码执行 `curL += 1`，一致；若 $s[i] \ne \text{'L'}$，则以 $i$ 结尾的连续 `'L'` 长度为 0，代码把它置 0，一致。∎

**引理 3（`"LLL"` 的等价判定）**：$s$ 中存在子串 `"LLL"` 当且仅当扫描过程中某个时刻 `curL >= 3`。

**证明**：

- ($\Leftarrow$) 若某时刻 `curL >= 3`，由引理 2，存在以该位置结尾、长度至少 3 的连续 `'L'` 段，取它最后三个字符即为 `"LLL"`。
- ($\Rightarrow$) 若 $s[j..j+2]$ 三个字符均为 `'L'`，则扫描到下标 $j+2$ 时，以 $j+2$ 结尾的连续 `'L'` 段长度至少为 3，由引理 2 得 `curL >= 3`。∎

**定理**：算法返回 `true` 当且仅当学生满足获奖的两个条件。

**证明**：

- 若算法返回 `false`，则只有两种可能：结束时 `cntA >= 2`，由引理 1 缺勤不少于 2 天，违反条件 ①；或中途 `curL >= 3`，由引理 3 存在 `"LLL"`，违反条件 ②。故返回 `false` 时确实不该获奖。
- 若算法返回 `true`，说明整个扫描从未触发上述两处判定，即终态 `cntA <= 1` 且全程 `curL <= 2`。由引理 1 缺勤少于 2 天；由引理 3 的逆否命题不存在 `"LLL"`，即没有连续 3 天及以上迟到。两个条件都成立，应当获奖。∎

## 6. 复杂度分析

- **时间**：$O(n)$。只遍历字符串一次，每个字符做常数次整数运算与比较；早退只会让实际耗时更短，上界不变。
- **空间**：$O(1)$。只使用 `cntA`、`curL` 两个整型计数器与一个循环下标，与 $n$ 无关；输入字符串本身不计入额外空间。
- **对比**：若用 `s.count('A')` + `'LLL' not in s`，时间同样是 $O(n)$，但需要两趟扫描，常数约为单次扫描的 2 倍。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    bool checkRecord(string s) {
        int cntA = 0, curL = 0;
        for (char ch : s) {
            if (ch == 'A') {
                ++cntA;
                curL = 0;                // 缺勤打断连续迟到
                if (cntA >= 2) return false;
            } else if (ch == 'L') {
                ++curL;                  // 自增，而不是重置为 1
                if (curL >= 3) return false;
            } else {                     // 'P'
                curL = 0;
            }
        }
        return true;                     // 扫完全程无违规
    }
};
```

### Python

```python
class Solution:
    def checkRecord(self, s: str) -> bool:
        cnt_a = 0
        cur_l = 0
        for ch in s:
            if ch == 'A':
                cnt_a += 1
                cur_l = 0                # 缺勤同样打断连续迟到
                if cnt_a >= 2:
                    return False
            elif ch == 'L':
                cur_l += 1               # 连续段长度自增
                if cur_l >= 3:
                    return False
            else:                        # 'P'
                cur_l = 0
        return True
```

## 8. 边界情况与易错点

1. **恰好 1 个 `'A'`**：`"A"`、`"PPALP"` 都应返回 `true`；规则是「严格少于 2」，写成 `cntA > 1` 判负就等价，写成 `cntA >= 1` 会误判。
2. **恰好 2 个 `'A'`**：`"AA"`、`"ALLA"` 返回 `false`，且第 2 个 `'A'` 出现时即可返回，不必等扫描结束。
3. **`"LLL"` 出现在任意位置**：前缀 `"LLLP"`、中段 `"PLLLP"`、后缀 `"PLLL"` 都要判负；只检查结尾会漏掉前两种情况。
4. **连续 `'L'` 不足 3**：`"LL"`、`"LLPLL"` 返回 `true`，`curL` 峰值 2 不触发判负，判负条件写成 `curL >= 3` 最稳；若写成 `curL == 3`，一旦漏掉早退、继续扫描就可能出现 `curL = 4` 而不再命中。
5. **`'A'` 与 `"LLL"` 同时出现**：`"ALLL"` 两个条件都被破坏，返回 `false`；任一违规就足够判负，不要写成「两者都违规」。
6. **长度为 1**：`"A"`、`"L"`、`"P"` 全部返回 `true`；循环不越界，也不需要额外特判。
7. **`'P'` 的清零作用**：`"LLPLLL"` 中连续的 L 段被 `'P'` 切成 2 和 3，答案 `false`；若忘了 `'P'` 分支清零，会得到错误的 5 连 L，仍判 false（碰巧对），但 `"LLPLL"` 就会被误判为 `false`。**测试用例要挑这类能区分「清零」与「不清零」的数据。**
8. **C++ 的 `size()` 是 `size_t`**：本题用 range-for 遍历，无需比较下标与 `s.size()`，天然避开有符号/无符号混用告警。

**延伸思考**：

1. 把阈值改成参数：缺勤上限 $a$、连续迟到上限 $k$，本题代码只需把 `2` 与 `3` 换成 `a`、`k`，复杂度仍是 $O(n)$。
