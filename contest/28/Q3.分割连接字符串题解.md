# LeetCode 分割连接字符串 题解

## 1. 题目概述

- **标题 / 题号**：分割连接字符串（#555，medium）
- **链接**：https://leetcode.cn/problems/split-concatenated-strings/
- **来源**：LeetCode 第 28 场周赛 Q3
- **难度**：中等
- **标签**：贪心, 数组, 字符串

**题意**：给定 $n$ 个字符串 `strs`，要经过两个阶段构造一个普通字符串：

1. **成环**：所有串按**给定顺序**首尾相接成一个环，其中每个串可以原样保留，也可以整串翻转（$s_i$ 或 $\text{rev}(s_i)$）；
2. **剪一刀**：在环上任意位置剪断，从断点字符开始沿环读一圈，把环拉直成普通字符串。

求所有（朝向组合, 断点）方案中，能得到的**字典序最大**的字符串。

**约束**：

- `strs[i]` 只含小写英文字母；
- 所有串的**总长度不超过 1000**；
- 每个串都必须完整出现在环上，只允许选择朝向、不允许调换串之间的顺序；
- 答案长度恒等于总长度 $L=\sum_i |s_i|$（翻转与剪断都不改变字符数）。

> 💡 接口：`splitLoopedString(vector<string>& strs) -> string`，参数只有一个字符串数组，返回读出的最大串。本题是会员题，题面本身没有任何额外操作或隐藏指令。

## 2. 示例

**示例 1**

```text
输入：strs = ["abc", "xyz"]
输出："zyxcba"
解释：四个可选的环是 "abcxyz"、"abczyx"、"cbaxyz"、"cbazyx"。
      取环 "cbazyx"，在 'a' 之后（也就是 "zyx" 的首字符前）剪断，
      沿环读出 "zyx" + "cba" = "zyxcba"，它是所有方案里字典序最大的。
```

**示例 2**

```text
输入：strs = ["abc"]
输出："cba"
解释：环只有 "abc" 与 "cba" 两种。
      "abc" 的旋转为 abc / bca / cab，"cba" 的旋转为 cba / bac / acb，
      最大者是 "cba"。
```

**示例 3（补充，最能区分写法对错）**

```text
输入：strs = ["ab", "ba"]
输出："bbaa"
解释：环 "abba"（"ab" 保持 + "ba" 保持）在第 2 个字符前剪断，读出 "bbaa"。
      若先把两个串都归一成较大朝向 "ba"，环只剩 "baba"，最好也只有 "baba"，
      可见「被剪开的串必须两种朝向都试」。
```

## 3. 解题思路

### 3.1 暴力思路

![环形模型：先定朝向，再剪一刀](images/wc28_q3_loop_model.svg)

题意本身就是一个两层枚举：

- 朝向组合有 $2^n$ 种（每个串翻转或不翻转）；
- 断点有 $L$ 个（每个字符前都可以剪）；
- 每个候选串构造一次要 $O(L)$。

总复杂度 $O(2^n \cdot L^2)$。$L \le 1000$ 不算大，但 $n$ 可以很大（全部是单字符串时 $n = 1000$），$2^{1000}$ 完全不可行。所以暴力只配用来对拍小数据；正解必须把「朝向」这一维从指数级压成贪心，只留「断点」的线性枚举。

### 3.2 核心观察：只有被剪开的串，朝向不能提前定死

![只有被剪开的串需要枚举两种朝向](images/wc28_q3_greedy_concept.svg)

**观察 1（未被剪开的串，取最大朝向最优）**：固定「断点所在的串 $i$、它的朝向 $c$、断点位置 $j$」之后，其余 $n-1$ 个串都是**整段**出现在结果串里，且翻转不改变长度，因此每一段占据的区间 $[a,b)$ 与朝向选择无关。把某个串 $k$（$k \ne i$）换成 $\max(s_k, \text{rev}(s_k))$，只有 $[a,b)$ 这段内容变化，前缀完全相同，于是整串的比较退化成这两段（等长）的比较——取最大朝向一定不比原来差。

**观察 2（被剪开的串，两种朝向都得枚举）**：它被剪开了，**尾部跑到结果串开头、头部落到结果串结尾**，不再是一个完整的块，观察 1 的逐块论证失效。

> ⚠️ 典型错误：把所有串都归一成 $\max(s, \text{rev}(s))$，然后只在这个串上枚举断点。反例 `["ab","ba"]` 归一化后环只有 `"baba"`，最好得到 `"baba"`；正确答案 `"bbaa"` 必须把 `"ab"`（较小朝向！）在 $j=1$ 处切开：`"b" + "ba" + "a"`。

于是得到算法骨架：**贪心定朝向（其余串） + 枚举（被剪开的串, 朝向, 断点）**，指数因子被彻底消掉。

### 3.3 算法流程

![贪心定朝向 + 枚举断点](images/wc28_q3_algorithm_flow.svg)

1. 令 $c_i = \max(s_i, \text{rev}(s_i))$，总长 $L = \sum_i |c_i|$；
2. 对每个 $i$（枚举「谁被剪开」），拼出 $\text{other} = c_{i+1} c_{i+2} \cdots c_{n-1} c_0 c_1 \cdots c_{i-1}$，它就是环上 $i$ 之后的全部内容；
3. 对 $c \in \{c_i, \text{rev}(c_i)\}$（两种朝向）与断点 $j \in [0, |c_i|)$（$c[j]$ 成为新串首字符），构造候选并更新答案；
4. 返回 `ans`。

第 3 步的含义是：**被剪开的串从 $j$ 处断开，后半段接在最前面、前半段接在最后面**，于是

$$\text{cand} = c[j:] + \text{other} + c[:j]$$

每个 $i$ 产生 $2|c_i|$ 个候选，全部 $i$ 合计 $2L$ 个。

> 💡 断点只需枚举 $[0, |c_i|)$：$j = |c_i|$ 与「下一个串的 $j=0$」是同一个物理位置，重复枚举没有意义。

### 3.4 示例演算

![示例演算：12 个候选里取最大](images/wc28_q3_example_walkthrough.svg)

`strs = ["abc","xyz"]`，归一化后 $c = [\text{"cba"}, \text{"zyx"}]$，候选共 $2 \times (3+3) = 12$ 个，摘录 6 个：

| $i$ | 朝向 $c$ | 断点 $j$ | 候选 $\text{cand}$ |
|---|---|---|---|
| 0 | cba | 0 | cbazyx |
| 0 | abc | 1 | bczyxa |
| 0 | cba | 2 | azyxcb |
| 1 | zyx | 0 | **zyxcba** |
| 1 | zyx | 1 | yxcbaz |
| 1 | xyz | 2 | zcbaxy |

以 `z` 开头的候选只有 `zyxcba` 与 `zcbaxy`，比较第二位 $y > c$，故答案 `zyxcba`，与官方输出一致。注意最优解的断点 $j = 0$ 正好落在串 1 的首字符前——**剪在串边界上也是合法断点**，不要漏掉。

## 4. 算法细节

1. **归一化写法**：`best[i] = max(s, rev(s))`。Python 直接 `max(s, s[::-1])`；C++ 先 `reverse` 出一份副本再 `max`，不要在原串上原地翻转（后面还要用它）。
2. **`other` 只拼一次**：把 $c_{i+1..n-1}$ 与 $c_{0..i-1}$ 依次追加到 `other`，是 $O(L)$；若写进内层循环，复杂度会涨到 $O(L^3)$。
3. **切片顺序不能反**：候选必须是 `c[j:] + other + c[:j]`（**尾部在前、头部在后**）。写成 `c[:j] + other + c[j:]` 是最隐蔽的笔误，长度仍然正确，但语义完全错了。
4. **两种朝向都试**：`for c in (best[i], best[i][::-1])`。$s_i$ 是回文时两者相同，只是多跑常数倍，不必特判。
5. **比较规则**：所有候选长度都等于 $L$，所以 C++ 的 `string` 的 `<`、Python 的 `<` 就是字典序，不需要「长度优先」的额外规则；`ans` 初始化为空串即可。
6. **下标类型**：C++ 里 `c.size()` 是 `size_t`，与 `int j` 比较时显式转成 `(int)`，避免无符号回绕；`substr` / `substr(0, j)` 的边界都在 $[0,|c|]$ 内。
7. **不用去重**：两种朝向相同、$j$ 与相邻串 $j=0$ 重合都会产生重复候选，但重复只增加 $O(L^2)$ 内的常数，用 `set` 去重反而引入额外哈希与内存开销。

## 5. 正确性证明

**引理 1（逐块贪心）**：固定断点信息（所在串 $i$、朝向 $c$、位置 $j$）。对任意 $k \ne i$，把 $s_k$ 的朝向从 $x$ 换成 $\max(s_k, \text{rev}(s_k))$，结果串不会变小。

**证明**：翻转保持长度，所以结果串中每个块的起止下标与朝向选择无关。设块 $k$ 占据 $[a,b)$。两种方案在 $[0,a)$ 上内容完全相同（同样的 $c[j:]$ 与同样的前序块），于是比较结果串从下标 $a$ 开始，等价于比较这两段等长子串，即比较 $x$ 与 $\max(s_k, \text{rev}(s_k))$。后者按定义不小于前者，故结果串不会变小。∎

**引理 2（候选集足够）**：设 $(\text{朝向组合}^*, \text{断点}^*)$ 是任一合法方案，结果为 $R^*$。则算法枚举出的候选中有某个 $C$ 满足 $C \ge R^*$。

**证明**：设断点落在串 $i$ 的第 $j$ 个字符前，串 $i$ 在方案 $^*$ 中的朝向为 $c^* \in \{s_i, \text{rev}(s_i)\}$。算法枚举 $(i, c^*, j)$（$c \in \{c_i, \text{rev}(c_i)\}$ 正是这两个朝向），其余串用 $c_k = \max(s_k,\text{rev}(s_k))$。由引理 1 反复应用 $n-1$ 次，得到候选 $C \ge R^*$。∎

**引理 3（候选都可达）**：算法产生的每个 `cand` 都是某个合法（朝向组合, 断点）下的读出串。

**证明**：取朝向组合「$i$ 用 $c$，其余用 $c_k$」，断点取串 $i$ 的第 $j$ 个字符前。沿环从 $c[j]$ 开始读一圈，依次是 $c[j:]$、$c_{i+1}\cdots c_{n-1}$、$c_0\cdots c_{i-1}$、$c[:j]$，恰为 `cand`。∎

**定理**：算法返回的字符串等于所有合法方案中字典序最大的读出串。

**证明**：设最优值为 $R^\star$。一方面由引理 3，`ans` 是若干合法方案结果的最大值，故 `ans` $\le R^\star$；另一方面由引理 2 存在候选 $C \ge R^\star$，而 `ans` 取所有候选的最大值，故 `ans` $\ge C \ge R^\star$。两向夹逼得 `ans` $= R^\star$。∎

## 6. 复杂度分析

- **时间**：$O(L^2)$。归一化 $O(L)$；外层枚举 $i$ 时拼 `other` 总计 $O(nL) \subseteq O(L^2)$；候选总数是 $\sum_i 2|c_i| = 2L$，每个候选的拼接与比较各 $O(L)$，合计 $O(L^2)$。$L \le 1000$ 时约 $2 \times 10^6$ 次字符搬运，Python 亦可毫秒级跑完。
- **空间**：$O(L)$。`best` 数组容纳全部字符共 $L$ 个，`other`、`cand`、`ans` 各 $O(L)$；无递归、无哈希表、无二维 DP。
- **对比**：暴力枚举 $2^n$ 种朝向为 $O(2^n L^2)$，$n$ 稍大即不可行；本做法用引理 1 把 $2^{n-1}$ 这个因子整体消掉，只保留线性的断点枚举。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    string splitLoopedString(vector<string>& strs) {
        int n = (int)strs.size();
        vector<string> best(n);
        for (int i = 0; i < n; ++i) {
            string r = strs[i];
            reverse(r.begin(), r.end());
            best[i] = max(strs[i], r);              // 贪心：未被剪开的串取最大朝向
        }

        string ans;
        for (int i = 0; i < n; ++i) {
            string other;                            // 环上 i 之后的全部内容
            for (int k = 1; k < n; ++k) other += best[(i + k) % n];
            string rev = best[i];
            reverse(rev.begin(), rev.end());
            for (const string& c : {best[i], rev}) {  // 被剪开的串：两种朝向都试
                for (int j = 0; j < (int)c.size(); ++j) {
                    string cand = c.substr(j) + other + c.substr(0, j);
                    if (cand > ans) ans = cand;      // 等长，直接字典序比较
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def splitLoopedString(self, strs: List[str]) -> str:
        n = len(strs)
        best = [max(s, s[::-1]) for s in strs]       # 每个串的最大朝向
        ans = ""
        for i in range(n):
            other = "".join(best[i + 1:] + best[:i])  # 环上 i 之后的其余部分
            for c in (best[i], best[i][::-1]):        # 被剪开的串：两种朝向
                for j in range(len(c)):               # 断点：c[j] 成为新串首字符
                    cand = c[j:] + other + c[:j]
                    if cand > ans:
                        ans = cand
        return ans
```

## 8. 边界情况与易错点

1. **只有一个串**：`["abc"]` → `"cba"`。此时 `other` 为空串，候选就是该串的全部旋转（含反向），不能因为「没有其他串」就直接返回原串。
2. **只试最大朝向**：`["ab","ba"]` 会得到 `"baba"` 而不是 `"bbaa"`，这是本题最经典的错误；被剪开的串必须两种朝向都枚举。
3. **断点范围**：`j ∈ [0, |c|)`，漏掉 `j = 0` 会丢掉「整串从首字符开始读」的候选——示例 1 的最优解恰好是 $j=0$。
4. **空串（若数据允许）**：$|c| = 0$ 时内层不产生候选，等价于「在相邻串的边界剪断」，结果不受影响；若所有串都为空，`ans` 保持 `""`，仍是正确答案。
5. **回文 / 重复串**：两种朝向相同会重复枚举，只是常数开销；不要为此加 `set` 去重。
6. **全部字符相同**：如 `["aaaa"]`，任意方案都是 `"aaaa"`；比较写 `>` 或 `>=` 不影响结果，`ans` 初值取 `""` 最省事。
7. **切片顺序写反**：`c[:j] + other + c[j:]` 长度也等于 $L$，能通过「长度检查」，但语义完全错，务必用示例 1 的 `zyxcba` 自测。
8. **C++ 的 `size_t`**：`for (int j = 0; j < (int)c.size(); ++j)` 要显式转换；`c.size()` 为 0 时循环不执行，`substr(0,0)` 也安全。

**延伸思考**：

1. 若要求**字典序最小**，全部推导对称成立（`max` 换成 `min`），代码只改两处比较方向。
2. 若允许**任意调换串的顺序**，问题退化为「拼接后字典序最大」，按 $c_i + c_j$ 与 $c_j + c_i$ 的比较器排序即可，$O(L \log n)$。
3. 若允许剪**两刀**（取出一个连续段重排），候选从 $O(L)$ 个涨到 $O(L^2)$ 个，比较必须用哈希或后缀数组加速，否则 $O(L^3)$ 在 $L = 1000$ 时已经很紧。
4. 若每个字符带权、目标是权值和最大，逐块贪心失效（后缀和会影响朝向选择），需要改用 DP。
