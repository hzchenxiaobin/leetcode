# LeetCode 从二叉搜索树到更大和树 题解

## 1. 题目概述

- **标题 / 题号**：从二叉搜索树到更大和树（#1038，medium）
- **链接**：https://leetcode.cn/problems/binary-search-tree-to-greater-sum-tree/
- **来源**：LeetCode 第 135 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、二叉搜索树、二叉树

**题意**：给定一棵二叉搜索树 `root`，把**每个节点的值**替换成原树中**大于或等于该节点值**的所有节点值之和，返回修改后的树（结构与原树相同）。

**约束**：

- 节点数在 $[1, 100]$ 范围内
- $0 \le \text{Node.val} \le 100$
- 树中所有值**互不重复**

**关键概念**：BST 的**中序遍历**是递增序列；把中序反过来走（右 → 根 → 左）就是**递减序列**，于是「所有 $\ge$ 当前值的和」天然等于一个**后缀和**。本题与 538 题完全相同。

## 2. 示例

**示例 1**

```text
输入：[4,1,6,0,2,5,7,null,null,null,3,null,null,null,8]
输出：[30,36,21,36,35,26,15,null,null,null,33,null,null,null,8]
解释：如节点 4 的新值为 4+5+6+7+8 = 30；节点 6 的新值为 6+7+8 = 21。
```

**示例 2**

```text
输入：[0,null,1]
输出：[1,null,1]
解释：值 1 是最大值，新值仍为 1；值 0 的新值为 0+1 = 1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个节点，重新遍历整棵树求「$\ge$ 它」的和：$O(n^2)$。$n \le 100$ 时当然能过（约 $10^4$ 次操作），但完全没有利用 BST 的有序性，而且写法啰嗦。

### 3.2 核心观察：逆向中序 = 递减序 = 后缀和

![逆向中序的过程](images/wc135_q2_reverse_inorder.svg)

BST 的性质：左子树键值全部小于根，右子树键值全部大于根。因此

- **中序**（左 → 根 → 右）得到**严格递增**序列；
- **逆向中序**（右 → 根 → 左）得到**严格递减**序列。

维护一个累加器 `total`，按逆向中序访问节点：由于此时所有**比当前节点更大**的键都已经访问过，`total` 里装的正是「原值 $>$ 当前值」之和。于是

$$\text{total} \mathrel{+}= \text{node.val}, \qquad \text{node.val} = \text{total}$$

得到的就恰好是「$\ge$ 当前节点值」之和。整个过程**一次 DFS**，不需要额外数组。

### 3.3 算法流程

```text
dfs(node):
    若 node 为空: 返回
    dfs(node.right)         # 1. 先处理所有更大的键
    total += node.val       # 2. 累加当前值
    node.val = total        # 3. 写回“后缀和”
    dfs(node.left)          # 4. 再处理更小的键

主函数: total = 0; dfs(root); 返回 root
```

### 3.4 示例演算

![示例 1 的逐节点答案](images/wc135_q2_example_tree.svg)

示例 1 的树（层序）：根 4，左子树 {1,0,2,3}，右子树 {6,5,7,8}。逆向中序访问顺序与累加过程：

| 访问节点 | 累加前 total | 累加后 total = 新值 |
|----------|-------------|---------------------|
| 8 | 0 | 8 |
| 7 | 8 | 15 |
| 6 | 15 | 21 |
| 5 | 21 | 26 |
| 4 | 26 | 30 |
| 3 | 30 | 33 |
| 2 | 33 | 35 |
| 1 | 35 | 36 |
| 0 | 36 | 36 |

对照原树：节点 2 的「$\ge 2$」之和为 $2+3+4+5+6+7+8 = 35$ ✓；节点 3 为 $3+4+5+6+7+8 = 33$ ✓。层序输出与示例完全一致。

## 4. 算法细节

1. **递归顺序必须是「右-根-左」**：写成「左-根-右」会得到递增序的前缀和（那是另一道题：把 BST 变成累加树的方向搞反）。
2. **累加器的作用域**：C++ 用成员变量 `total`，Python 用 `self.total`；注意 `self.total = 0` 要写在主函数里，否则同一实例多次调用会累加上一次的值（LeetCode 每次用例都是新实例，但养成习惯更好）。
3. **原地修改**：值写回节点本身，无需新建树；因为访问顺序保证「先读后写」——父节点被写时，它的右子树已经全部处理完，左子树还没读，所以不会读到被污染的值（见引理 2）。
4. **递归深度**：节点数 $\le 100$，最坏是一条链（深度 100），递归安全；若节点数到 $10^5$ 且链状，需改成显式栈的迭代写法。
5. **返回值**：返回根节点 `root`（题目要求返回修改后的树），不要返回 `nullptr` 或某个子节点。

## 5. 正确性证明

**引理 1（逆向中序为递减序）**：对任意 BST 做「右 → 根 → 左」遍历，得到的节点值序列严格递减。

**证明**：对树高归纳。设根为 $r$，左子树 $L$、右子树 $R$。逆向中序的输出为「$R$ 的逆向中序」接 $r$ 再接「$L$ 的逆向中序」。由 BST 性质，$R$ 中所有值 $> r >$ $L$ 中所有值；由归纳假设，$R$ 的输出严格递减、$L$ 的输出严格递减，故整体严格递减。∎

**引理 2（访问时的 total 恰为更大的键之和）**：设节点 $v$ 是逆向中序中第 $t$ 个被访问的节点，则访问它时 `total` 等于原树中所有**大于** $v$ 的节点值之和。

**证明**：由引理 1，前 $t-1$ 个被访问的节点恰为原树中所有大于 $v$ 的节点（因为遍历顺序就是全局降序），而 `total` 正是这 $t-1$ 个节点的原值之和。注意第 3 步「写回」只改 `node.val`，而 `total` 累加用的是**写回前的值**（语句顺序：先 `total += node.val` 再赋值），且更小的键尚未被访问，故它们的原值未被污染。∎

**定理**：算法结束后，每个节点的值等于原树中所有 $\ge$ 该节点原值的节点值之和。

**证明**：设节点 $v$ 原值为 $x$。访问 $v$ 时，由引理 2，`total` 为所有 $> x$ 的值之和；执行 `total += node.val` 后为所有 $\ge x$ 的值之和（$v$ 自身恰被计入一次）；随后 `node.val = total` 把它写回。由于值互不重复，不存在「相等但不该计入」的歧义。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点恰好被访问一次，每次做常数次加法与赋值。
- **空间**：$O(h)$，$h$ 为树高（递归栈）。最坏（链状）$O(n)$，最好（平衡）$O(\log n)$；不使用额外数组。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

struct TreeNode {
    int val;
    TreeNode* left;
    TreeNode* right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

class Solution {
public:
    int total = 0;
    TreeNode* bstToGst(TreeNode* root) {
        dfs(root);
        return root;
    }
    void dfs(TreeNode* node) {
        if (!node) return;
        dfs(node->right);          // 先访问所有更大的键
        total += node->val;
        node->val = total;         // 逆向中序：把后缀和写回节点
        dfs(node->left);
    }
};
```

### Python

```python
class Solution:
    def bstToGst(self, root: 'TreeNode') -> 'TreeNode':
        self.total = 0

        def dfs(node):
            if node is None:
                return
            dfs(node.right)          # 先处理所有更大的键
            self.total += node.val
            node.val = self.total    # 逆向中序：累加后缀和
            dfs(node.left)

        dfs(root)
        return root
```

## 8. 边界情况与易错点

1. **遍历方向写反**：写成「左-根-右」得到的是前缀和（把每个节点变成「$\le$ 它」之和），示例 1 会输出 `[10,10,28,...]` 之类的错误结果。
2. **语句顺序**：必须 `total += node.val` 在 `node.val = total` 之前；反过来会把节点值覆盖成旧 `total`，漏掉自身。
3. **单节点树**：`[1]` → 返回 `[1]`（最大值即自身），循环/递归都自然处理。
4. **只有右链**：`[0,null,1]` 这种「退化链」，递归先走右再走根，顺序正确；注意很多人在迭代写法里忘记先压右孩子。
5. **实例复用**：把 `total` 写成类成员时，如果评测在同一实例上连续调用，需要在使用前重置（本解法在主函数入口即可重置）。
6. **返回的是根**：题目要求返回 `TreeNode*`，若只做原地修改而忘了 `return root`，评测会拿到空指针。
