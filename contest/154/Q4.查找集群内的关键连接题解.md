# LeetCode 查找集群内的关键连接 题解

## 1. 题目概述

- **标题 / 题号**：查找集群内的关键连接（#1192，hard）
- **链接**：https://leetcode.cn/problems/critical-connections-in-a-network/
- **来源**：LeetCode 第 154 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、图、桥、双连通分量

**题意**：有 $n$ 台服务器（编号 $0 \sim n-1$），用无向边 $connections[i] = [a_i, b_i]$ 相连，整张图连通。若删去某条边后，有服务器无法再到达另一台服务器，该边就是**关键连接**（critical connection），即图论中的**桥**。返回所有桥，顺序任意、每条边的两个端点方向也任意。

**约束**：

- $2 \le n \le 10^5$
- $n-1 \le \lvert connections \rvert \le 10^5$
- $0 \le a_i, b_i \le n-1$，$a_i \ne b_i$
- 不存在重复的连接（无重边）
- 图是连通的

## 2. 示例

**示例 1**

```text
输入：n = 4, connections = [[0,1],[1,2],[2,0],[1,3]]
输出：[[1,3]]（[[3,1]] 同样正确）
解释：0-1-2 构成一个环，删去环上任意一条边，四个点仍连通；
      删去 (1,3) 后节点 3 与其余节点断开，故它是唯一的桥。
```

**示例 2**

```text
输入：n = 2, connections = [[0,1]]
输出：[[0,1]]
解释：只有一条边，删掉它图就分成两个孤立点，因此它是桥。
```

**补充示例**

```text
输入：n = 6, connections = [[0,1],[1,2],[2,0],[1,3],[3,4],[4,5],[5,3]]
输出：[[1,3]]
解释：0-1-2 是一个环，3-4-5 也是一个环，两个环只靠 (1,3) 相连，
      故 (1,3) 是唯一的桥。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每条边，把它从图中删除，再对剩下的图做一次 BFS/DFS 统计连通分量数：若分量数从 1 变为 2，该边就是桥。每条边判一次，耗时 $O(E(V+E))$，在 $V, E \approx 10^5$ 时约 $10^{15}$ 次操作，完全不可行。暴力的浪费在于：它每次都在回答一个**全局**问题，而一条边是否为桥其实只取决于它所在 DFS 子树的一个**局部**性质。

### 3.2 核心观察：桥 = 回边够不着的树边

![桥与环的直观区别](images/wc154_q4_bridge_model.svg)

对图做一次 DFS 得到**DFS 生成树**（无向图的 DFS 树只有**树边**与**回边**，没有横叉边）：

- **树边**：访问未访问节点时走过的边，构成生成树；
- **回边**：指向某个仍在递归栈中（灰色）的祖先的边，它是"绕行通道"。

$(u,v)$ 是桥 $\iff$ 删掉它后 $v$ 的子树无法再回到 $u$ 或 $u$ 的祖先。于是给每个节点记两个量：

- $dfn[u]$：$u$ 被首次访问的时间戳（$1,2,3,\dots$）；
- $low[u]$：从 $u$ 的子树出发，只走树边、最多再走**一条回边**，能到达的**最小** $dfn$。

$low[v] > dfn[u]$ 就意味着"$v$ 的子树连 $u$ 都够不到"，此时 $(u,v)$ 必为桥；反之子树能绕回 $u$ 或更高，删边不断开。

> 💡 直觉：**环上的边都不是桥，只有挂在环外的"独木桥"才是桥**。$low$ 值就是自动检测"这条树边是否属于某个环"的工具。

### 3.3 算法流程 / 状态转移

![Tarjan 找桥流程](images/wc154_q4_tarjan_flow.svg)

1. **进入** $u$：`dfn[u] = low[u] = ++timer`。
2. **枚举邻边** $(u,v)$，跳过"来时的父边"（用边的编号识别）。
3. 若 $v$ 未访问（树边）：深入 $v$（迭代实现里就是压栈）；回溯后先做 `low[u] = min(low[u], low[v])`，再判 `low[v] > dfn[u]`，成立则记录 $(u,v)$ 为桥。
4. 若 $v$ 已访问且不是父边（回边）：`low[u] = min(low[u], dfn[v])`，**用 $dfn[v]$ 而不是 $low[v]$**。
5. 外层对所有未访问节点启动 DFS，兼容非连通图。

### 3.4 示例演算

对补充示例 `n = 6`，从 0 出发 DFS，访问顺序 $0 \to 1 \to 2$（回边 $2 \to 0$），再 $1 \to 3 \to 4 \to 5$（回边 $5 \to 3$）：

![示例的 DFS 树与 dfn/low](images/wc154_q4_walkthrough.svg)

| 步骤 | 动作 | $dfn$ / $low$ 变化 | 桥判定 |
|------|------|--------------------|--------|
| 1 | 访问 0 | $dfn_0=low_0=1$ | — |
| 2 | 树边 $0\to1\to2$ | $dfn_1=low_1=2$，$dfn_2=low_2=3$ | — |
| 3 | 回边 $2\to0$，回溯到 1 | $low_2=\min(3,1)=1$，$low_1=\min(2,1)=1$ | $low_2=1>dfn_1=2$？否 |
| 4 | 树边 $1\to3$ | $dfn_3=low_3=4$ | — |
| 5 | 树边 $3\to4\to5$ | $dfn_4=low_4=5$，$dfn_5=low_5=6$ | — |
| 6 | 回边 $5\to3$ | $low_5=\min(6,4)=4$ | — |
| 7 | 回溯到 4、3 | $low_4=\min(5,4)=4$，$low_3=\min(4,4)=4$ | $4>dfn_4=5$？否；$4>dfn_3=4$？否 |
| 8 | 回溯到 1 | $low_1=\min(1,4)=1$ | $low_3=4>dfn_1=2$？**是 → $(1,3)$ 是桥** |
| 9 | 回溯到 0 | $low_0=\min(1,1)=1$ | $1>dfn_0=1$？否 |

最终 `[[1,3]]`。关键在 $low_3 = 4$：节点 3 的子树只能靠回边 $5\to3$ 回到 3 自己，够不到 1，因此 $(1,3)$ 是独木桥。

## 4. 算法细节

1. **时间戳从 0 或 1 开始都行**，但要与"未访问"标记区分开；用 `dfn = -1` 表示未访问，$low$ 初值无意义。
2. **判桥必须放在回溯更新之后**：先 `low[u] = min(low[u], low[v])`，再判 `low[v] > dfn[u]`。顺序写反时 $low[v]$ 可能被其他子树污染，判定失真。
3. **回边用 $dfn[v]$ 而不是 $low[v]$**：$low$ 的定义只允许"至多一条回边"，跨多级的传递靠树边回溯逐层完成；写成 $low[v]$ 在部分图上会错误地把桥判成非桥。
4. **父边必须用边编号识别**：邻接表里每条无向边存两次，用 `eid` 区分正反。本题保证无重边，用"$v \ne parent$"也能过；但若存在平行边（两节点间两条边），平行边构成 2-环，两条都不是桥，按顶点跳过会把其中一条误判为桥。
5. **图不连通也要兜底**：题面保证连通，但外层 `for s in range(n)` 加一个 `dfn[s] == -1` 判断几乎零成本，能直接复用到非连通图。
6. **两种语言都用显式栈迭代**：$n=10^5$ 时 DFS 可退化成一条长链，递归深度 $10^5$ 在 Python 会超递归上限、在 C++ 也可能击穿线程栈（本机 $10^5$ 长链实测会段错误）。栈帧取「节点、父边编号、邻接表下标」三元组即可无损模拟递归。
7. **输出格式**：边按 $(u,v)$ 或 $(v,u)$ 输出均可，顺序任意，但每条桥只能出现一次——只在树边回溯时收集，天然不重复。

## 5. 正确性证明

**引理 1（无向图 DFS 只有树边与回边）**：DFS 过程中任取一条边 $(x,y)$，若 $y$ 在 $x$ 被访问时尚未访问，则它是树边；否则 $y$ 已被访问，此时 $y$ 要么是 $x$ 的祖先（回边），要么是 $x$ 的后代。不会出现"已完成分支"之间的横叉边。

**证明**：反设有边 $(x,y)$ 连接两个不同子树，且 $x$ 先被发现。当 $x$ 处理这条边时 $y$ 必然尚未被发现——否则 $y$ 早已在某个更早的分支里被访问完，与"二者分属不同子树"矛盾。于是 DFS 会从 $x$ 走到 $y$，把 $y$ 收为 $x$ 的后代，与不同子树矛盾。故不存在横叉边。∎

**引理 2（$low$ 的含义）**：算法结束时
$$low[u] = \min\Bigl(\{dfn[u]\} \cup \{\,dfn[w] : \text{子树}(u)\text{ 中存在回边连向 } w\,\}\Bigr).$$

**证明**：对子树大小归纳。叶子没有子树，只可能更新到自身与指向祖先的回边，成立。设 $u$ 的子节点为 $v_1,\dots,v_k$。进入时 $low[u]=dfn[u]$；枚举到回边 $(u,w)$ 时并入 $dfn[w]$；对每个子节点回溯时并入 $low[v_i]$。由归纳假设，$low[v_i]$ 恰为子树 $(v_i)$ 能触到的最小 $dfn$，而子树 $(u)$ 的回边集合正是 $u$ 自身的回边并上各子树回边之并，取 $\min$ 后即为上式右端。∎

**引理 3（桥判定）**：树边 $(u,v)$（$v$ 为 $u$ 的子节点）是桥 $\iff low[v] > dfn[u]$。

**证明**：

- ($\Leftarrow$) 若 $low[v] > dfn[u]$，取子树 $(v)$ 内任一条回边 $(x,w)$：$w$ 是 $x$ 的祖先且 $dfn[w] \ge low[v] > dfn[u]$；而 $v$ 的祖先中只有 $v$ 自己的 $dfn$ 大于 $dfn[u]$，所以 $w$ 只能落在子树 $(v)$ 内部。可见子树 $(v)$ 与外界的唯一通道就是树边 $(u,v)$，删去它后子树 $(v)$ 与 $u$ 断开，故 $(u,v)$ 是桥。
- ($\Rightarrow$) 若 $low[v] \le dfn[u]$，则存在一条回边从子树 $(v)$ 内某点 $x$ 连到 $dfn[w] \le dfn[u]$ 的节点 $w$。由引理 1，$w$ 是 $x$ 的祖先，因而 $w$ 是 $u$ 本身或 $u$ 的祖先。删去 $(u,v)$ 后仍可走 $v \leadsto x \to w \leadsto u$（全程不经过 $(u,v)$，因为 $(u,v)$ 在 $u$ 下方），子树 $(v)$ 未与 $u$ 断开，$(u,v)$ 不是桥。∎

**定理**：算法输出的边集恰为图中所有桥。

**证明**：图连通时，每条非树边都在某个环上（它与其两端在树上的路径构成环），删去不改变连通性，故桥必为树边。对每条树边，算法回溯时按引理 3 精确判定并收集；引理 2 保证 $low$ 值计算正确。因此收集到的正是全部桥，且每条桥只在其子节点回溯时被收集一次，不重不漏。∎

## 6. 复杂度分析

- **时间**：$O(V+E)$。DFS 每个节点入栈、出栈各一次；每条无向边在邻接表中出现两次，各被考察一次；$low$ 更新与桥判定均为 $O(1)$。
- **空间**：$O(V+E)$。邻接表占 $O(V+E)$（存边编号），$dfn$、$low$ 两个数组各 $O(V)$，显式栈最坏 $O(V)$，答案数组最坏 $O(E)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <array>
#include <utility>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> criticalConnections(int n, vector<vector<int>>& connections) {
        // 邻接表存 (邻居, 边编号)，用边编号识别父边，兼容重边
        vector<vector<pair<int, int>>> adj(n);
        for (int i = 0; i < (int)connections.size(); ++i) {
            int a = connections[i][0], b = connections[i][1];
            adj[a].push_back({b, i});
            adj[b].push_back({a, i});
        }

        vector<int> dfn(n, -1), low(n, 0);
        vector<vector<int>> ans;
        int timer = 0;
        vector<array<int, 3>> st;        // 栈帧：{节点, 父边编号, 下一个邻边下标}

        for (int s = 0; s < n; ++s) {
            if (dfn[s] != -1) continue;
            dfn[s] = low[s] = timer++;
            st.push_back({s, -1, 0});
            while (!st.empty()) {
                int u = st.back()[0], pe = st.back()[1];
                if (st.back()[2] < (int)adj[u].size()) {
                    auto [v, eid] = adj[u][st.back()[2]++];
                    if (eid == pe) continue;              // 跳过父边
                    if (dfn[v] == -1) {                   // 树边
                        dfn[v] = low[v] = timer++;
                        st.push_back({v, eid, 0});
                    } else {                              // 回边：用 dfn[v]
                        low[u] = min(low[u], dfn[v]);
                    }
                } else {                                  // u 处理完毕，回溯
                    st.pop_back();
                    if (!st.empty()) {
                        int p = st.back()[0];
                        low[p] = min(low[p], low[u]);
                        if (low[u] > dfn[p]) ans.push_back({p, u});
                    }
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def criticalConnections(self, n: int, connections: List[List[int]]) -> List[List[int]]:
        adj = [[] for _ in range(n)]
        for eid, (u, v) in enumerate(connections):
            adj[u].append((v, eid))
            adj[v].append((u, eid))

        dfn = [-1] * n
        low = [0] * n
        timer = 0
        ans = []

        for s in range(n):
            if dfn[s] != -1:
                continue
            dfn[s] = low[s] = timer
            timer += 1
            # 栈元素：(节点, 父边编号, 下一个待处理的邻接表下标)
            stack = [(s, -1, 0)]
            while stack:
                u, parent_edge, i = stack[-1]
                if i < len(adj[u]):
                    stack[-1] = (u, parent_edge, i + 1)
                    v, eid = adj[u][i]
                    if eid == parent_edge:
                        continue                       # 跳过父边
                    if dfn[v] == -1:                   # 树边
                        dfn[v] = low[v] = timer
                        timer += 1
                        stack.append((v, eid, 0))
                    else:                              # 回边：用 dfn[v]
                        low[u] = min(low[u], dfn[v])
                else:                                  # u 处理完毕，回溯
                    stack.pop()
                    if stack:
                        p = stack[-1][0]
                        low[p] = min(low[p], low[u])
                        if low[u] > dfn[p]:
                            ans.append([p, u])
        return ans
```

## 8. 边界情况与易错点

1. **$n = 2$ 只有一条边**：这条边必是桥，返回 `[[0,1]]`，不要因为"删掉后只剩一个点"而漏判。
2. **答案是树**：连通且无环（$E = n-1$）时所有边都是桥，答案长度为 $n-1$；此时 DFS 深度为 $n$，递归写法（Python 超上限、C++ 击穿栈）都会崩，必须用显式栈。
3. **纯环**：每点度数 2 时没有桥，应返回空列表，而不是把任意一条边当成桥。
4. **重边（本题约束外，但实现要稳）**：两点间两条平行边构成 2-环，两条都不是桥；若只用"$v \ne parent$"判父边，第二条平行边会被当作父边跳过，$low[v]$ 拉不下来，$(u,v)$ 会被**误报**为桥。
5. **回边更新不能写成 $low[v]$**：只在树边回溯时合并 $low$，回边处必须用 $dfn[v]$，否则多级绕行的信息会被错误传播。
6. **判桥顺序**：先合并 $low$ 再判 `low[v] > dfn[u]`；如果先判后合并，用的是尚未吸收子树信息的旧值，会漏桥。

**延伸思考**：桥的判定可以自然推广到**割点**：树边上 $u$ 是割点当且仅当 $low[v] \ge dfn[u]$（根节点需至少两个子节点）。把所有桥删掉后，图分裂成若干**边双连通分量**；把每个分量缩成一个点，得到的恰好是一棵**树**——于是"任意两点间必须经过的桥"就变成树上的路径查询，可以用 LCA 或树上差分在 $O(\log n)$ 内回答。若题目改成"删除一条边后最多能分裂出多少块"，答案就与边双连通分量缩点后的度数相关。
