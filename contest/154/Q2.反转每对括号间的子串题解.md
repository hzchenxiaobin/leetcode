# LeetCode 反转每对括号间的子串 题解

## 1. 题目概述

- **标题 / 题号**：反转每对括号间的子串（#1190，medium）
- **链接**：https://leetcode.cn/problems/reverse-substrings-between-each-pair-of-parentheses/
- **来源**：LeetCode 第 154 场周赛 Q2
- **难度**：中等
- **标签**：栈、字符串、括号序列

**题意**：给定只含小写字母与括号的合法括号串 $s$，按「由内向外」的顺序把每一对匹配括号内部的子串反转一次，最后删掉全部括号并返回。设 $R(s)$ 表示答案，把 $s$ 按顶层括号切分为 $x_0\,(u_1)\,x_1\,(u_2)\,x_2\cdots$（$x_i$ 为纯字母片段），则

$$R(s)=x_0\cdot\mathrm{rev}\bigl(R(u_1)\bigr)\cdot x_1\cdot\mathrm{rev}\bigl(R(u_2)\bigr)\cdot x_2\cdots$$

**约束**：

- $1 \le \lvert s\rvert \le 2000$
- $s$ 仅含小写英文字母与 `(`、`)`
- 所有括号保证成对匹配，结果串不含任何括号

## 2. 示例

**示例 1**

```text
输入：s = "(abcd)"
输出："dcba"
```

**示例 2**

```text
输入：s = "(u(love)i)"
输出："iloveu"
解释：先反转最内层的 "love" 得到 "evol"，串变成 "uevoli"；
      再反转外层，得到 "iloveu"。
```

**示例 3**

```text
输入：s = "(ed(et(oc))el)"
输出："leetcode"
解释：先反转 "oc" → "co"；再反转 "etco" → "octe"；
      此时外层内容为 "edocteel"，反转后得到 "leetcode"。
```

## 3. 解题思路

### 3.1 暴力思路

按定义硬做：反复定位「最内层」括号对（先找到第一个 `)`，再向左数出与它配对的那个 `(`），把夹在中间的片段反转后替换掉整对括号，直到串中再无括号。

- 每轮都要一次定位加一次字符串重建，代价 $O(n)$；最多 $n/2$ 轮，总时间 $O(n^2)$。
- 写成递归（`solve(l, r)` 返回区间的展开结果）也是每次拼接新串，最坏 $O(n^2)$，且深嵌套时递归深度可达 $O(n)$。
- 根本浪费在于：同一批字符被反复搬动、反复反转，嵌套越深越吃亏。

$n \le 2000$ 时 $O(n^2)$ 其实也能过，但周赛更值得掌握的是把它压到 $O(n)$ 的视角。

### 3.2 核心观察：反转 = 换一个方向读

![括号即方向翻转](images/wc154_q2_direction_model.svg)

先把「反转」这个动作换个说法：

- 一段文字反转，等于**从右往左**读这段文字。
- 每进入一层括号，读取方向取反；离开这一层时再取反一次。
- 于是**嵌套层数决定字符被翻转的次数**：位于第 $d$ 层的字符被反转 $d$ 次，$d$ 为奇数则逆序、为偶数则保持正序。

关键推论：不必真的逐层反转字符串，只要**按正确的方向把每个字符读一遍**。指针走到括号时不需要「处理」括号内容，只需**跳到配对位置并翻转方向**——括号里的字符自然就被反向读到了。

### 3.3 算法流程：两遍扫描

![两遍扫描流程](images/wc154_q2_two_pass_flow.svg)

1. **第一遍 · 栈配对**：扫描 $s$，遇到 `(` 把下标压栈，遇到 `)` 弹出 $j$，记 `match[i] = j`、`match[j] = i`。双向记录是必需的，因为第二遍可能向左行进，此时要由 `)` 反查 `(`。
2. **第二遍 · 带方向游走**：置 `i = 0`、`dir = 1`，答案串为空。循环：
   - 若 $s[i]$ 是括号：`i = match[i]`，`dir = -dir`；
   - 否则把 $s[i]$ 追加到答案；
   - 统一执行 `i += dir`，$i$ 越界即结束。

每个字母只被输出一次、每对括号只被跳常数次，所以第二遍是严格线性的。

**另一种常见写法**：栈里不放下标，而放「字符缓冲区」。

![栈式缓冲区写法](images/wc154_q2_stack_buffer.svg)

遇到 `(` 压入一个空缓冲区，遇到字母写进栈顶，遇到 `)` 就弹出栈顶、把内容反转后接回新的栈顶，扫完剩下的即答案。这个写法最贴近题面直觉，代价是**每次弹出都要整体反转一次**，深嵌套下同一批字符被搬动多次，最坏 $O(n\cdot d)$（$d$ 为嵌套深度）。本题 $n\le 2000$ 足够快，但「跳跃换向」才是严格 $O(n)$ 的做法。

### 3.4 示例演算

以 `s = "(u(love)i)"` 为例，配对关系为 $0\leftrightarrow 9$、$2\leftrightarrow 7$：

![示例走查](images/wc154_q2_walkthrough.svg)

| 步 | $i$ | dir | 读到 | 动作 | 累计答案 |
|----|-----|-----|------|------|----------|
| 1 | 0 | $+1$ | ( | 跳到 9，方向取反 | （空） |
| 2 | 8 | $-1$ | i | 输出 i | i |
| 3 | 7 | $-1$ | ) | 跳到 2，方向取反 | i |
| 4 | 3 | $+1$ | l | 输出 l | il |
| 5 | 4 | $+1$ | o | 输出 o | ilo |
| 6 | 5 | $+1$ | v | 输出 v | ilov |
| 7 | 6 | $+1$ | e | 输出 e | ilove |
| 8 | 7 | $+1$ | ) | 跳到 2，方向取反 | ilove |
| 9 | 1 | $-1$ | u | 输出 u | iloveu |
| 10 | 0 | $-1$ | ( | 跳到 9，方向取反 | iloveu |

第 10 步后 `i = 10` 越界，返回 `"iloveu"`。对照 3.2 的结论：`love` 在第 2 层（偶数层），保持正序；`u`、`i` 在第 1 层，于是首尾互换。

## 4. 算法细节

1. **配对表必须双向写**：`match[i] = j` 与 `match[j] = i` 都要存，否则向左行进时遇到 `)` 无法一次跳到配对的 `(`，会退化成逐格回退。
2. **第二遍用 while 而不是 for**：`i` 会被改写、还会反向递减，`for i in range(n)` 的步进语义完全不适用。
3. **方向用 $\pm 1$ 表示**：`dir = 1` 向右、`dir = -1` 向左；跳跃时 `dir = -dir`，推进统一写成 `i += dir`，分支内不必各写一次。
4. **终止条件写成 `0 <= i < n`**：向左走时 `i` 会变成 $-1$，只判 `i < n` 在 Python 里会静默地按负下标取到串尾，造成死循环或错误输出。
5. **答案用可增长的容器**：Python 用 `list` 加 `"".join`，C++ 用 `string` 并 `reserve(n)`；避免 `ans += c` 这类可能退化成 $O(n^2)$ 的拼接惯例。
6. **不要真的反转**：本解法 $O(n)$ 的全部价值就在「只读不搬」，任何 `reverse` 或切片操作都会把复杂度打回 $O(n\cdot d)$。
7. **栈里存下标而非字符**：配对是位置关系，字符本身没有信息量；存下标才能写出 `match` 表。

## 5. 正确性证明

记 $R(s)$ 为题目要求的答案（递归定义见 §1），$\mathrm{rev}(x)$ 表示字符串反转。

**引理 1（双向走查）**：对任意合法括号串 $u$：

(i) 从 $u$ 的最左端以 `dir = +1` 出发，按「遇括号跳到配对处并取反方向」的规则走查，输出恰为 $R(u)$；

(ii) 从 $u$ 的最右端以 `dir = -1` 出发，用同一规则走查，输出恰为 $\mathrm{rev}\bigl(R(u)\bigr)$。

**证明**：对 $u$ 的括号对数做结构归纳。按顶层括号把 $u$ 切分为

$$u=x_0\,(u_1)\,x_1\,(u_2)\,x_2\cdots(u_k)\,x_k$$

其中 $x_i$ 不含括号，于是 $R(u)=x_0\,\mathrm{rev}(R(u_1))\,x_1\cdots\mathrm{rev}(R(u_k))\,x_k$。

证 (i)：走查先原序输出 $x_0$；到达 `(` 时跳到配对的 `)`，方向取反为 $-1$，于是从 $u_1$ 的右端开始向左——由归纳假设 (ii)（$u_1$ 的括号对数更少）这段输出为 $\mathrm{rev}(R(u_1))$；随后走到同一对的 `(` 上，再跳回 `)` 并把方向取反为 $+1$，继续处理 $x_1$ 与 $(u_2)$……逐段拼接即得 $R(u)$。

证 (ii)：走查先逆序输出 $x_k$；到达 `)` 时跳到配对的 `(`，方向取反为 $+1$，于是从 $u_k$ 的左端开始向右——由归纳假设 (i) 这段输出 $R(u_k)$；而 $\mathrm{rev}(R(u))$ 中对应段的贡献恰为 $\mathrm{rev}\bigl(\mathrm{rev}(R(u_k))\bigr)=R(u_k)$，因此吻合。走到该对的 `)` 时再跳回 `(` 并把方向取反为 $-1$，继续向左处理 $x_{k-1}$ 与 $(u_{k-1})$……逐段拼起来恰为 $\mathrm{rev}(R(u))$。∎

**引理 2（不重不漏）**：走查过程中每个字母位置被输出且仅被输出一次；每个括号位置被访问不超过两次。

**证明**：由引理 1 的构造，一对括号只在「从外侧进入」和「从内侧退出」时各被跳过一次；每次跳转后都要把该对括号内部的片段完整走一遍才离开，因此内部字母不会被重复访问；不含括号的片段 $x_i$ 只被顺序扫过一次。∎

**定理**：算法返回的字符串等于 $R(s)$。

**证明**：第一遍扫描正确——合法括号串上，`)` 弹出的一定是最近的未匹配 `(`，这是标准括号匹配的归纳结论，故 `match` 表正确。第二遍从最左端以 `dir = +1` 出发，行为与引理 1 (i) 完全一致，输出即 $R(s)$；由引理 2 不重不漏，长度等于字母总数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。第一遍每个下标入栈、出栈至多一次；第二遍每个字母输出一次，每对括号被跳至多两次，总步数为 $O(n)$。
- **空间**：$O(n)$。`match` 表 $n$ 个整数，配对栈最坏 $O(n)$，答案串 $O(n)$；迭代实现无递归栈开销。
- **对比**：暴力与递归展开 $O(n^2)$；栈式缓冲区 $O(n\cdot d)$；本做法最优。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string reverseParentheses(string s) {
        int n = (int)s.size();
        vector<int> match(n, -1), st;
        st.reserve(n);
        for (int i = 0; i < n; i++) {
            if (s[i] == '(') {
                st.push_back(i);
            } else if (s[i] == ')') {
                int j = st.back();
                st.pop_back();
                match[i] = j;
                match[j] = i;      // 双向记录：向左走时要由 ) 反查 (
            }
        }

        string ans;
        ans.reserve(n);
        int i = 0, dir = 1;
        while (i >= 0 && i < n) {
            if (s[i] == '(' || s[i] == ')') {
                i = match[i];      // 跳到配对位置
                dir = -dir;        // 方向取反
            } else {
                ans.push_back(s[i]);
            }
            i += dir;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def reverseParentheses(self, s: str) -> str:
        n = len(s)
        match = [-1] * n
        st = []
        for i, ch in enumerate(s):
            if ch == '(':
                st.append(i)
            elif ch == ')':
                j = st.pop()
                match[i] = j
                match[j] = i        # 双向记录

        ans = []
        i, d = 0, 1
        while 0 <= i < n:
            if s[i] == '(' or s[i] == ')':
                i = match[i]        # 跳到配对位置
                d = -d              # 方向取反
            else:
                ans.append(s[i])
            i += d
        return ''.join(ans)
```

## 8. 边界情况与易错点

1. **没有括号**：`"abc"` 原样返回；走查会把字母按序输出，不会出错。
2. **空结果**：`"()"` 的答案是空串，此时答案容器为空；不要因为结果为空就误判为没有处理。
3. **深嵌套**：`"(((...(a)...)))"` 这类形状在 $|s|=2000$ 时嵌套接近 1000 层，递归写法有爆栈风险，迭代加显式栈安全。
4. **向左越界**：`i` 会变成 $-1$；Python 中 `s[-1]` 合法但语义错误，循环条件必须写成 `0 <= i < n`。
5. **忘记双向配对**：只写 `match[i] = j`，向左遇到 `)` 时取到的下标无意义，会陷入死循环。
6. **用 for 推进指针**：在 `for` 里手动 `i += d` 无效，循环自身的步进会覆盖修改值，必须换成 `while`。
7. **相邻括号组**：`"(ab)(cd)"` 的答案是 `"badc"`，两组互不影响且顺序保持不变，适合作为自测用例。
