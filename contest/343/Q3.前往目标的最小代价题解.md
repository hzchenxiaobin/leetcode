# LeetCode 前往目标的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：前往目标的最小代价（#2662，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-of-a-path-with-special-roads/
- **来源**：LeetCode 第 343 场周赛 Q3
- **难度**：中等
- **标签**：图、最短路、堆（优先队列）、数组

**题意**：给定起点 `start = [startX, startY]` 与终点 `target = [targetX, targetY]`。从 $(x_1, y_1)$ **步行**到平面上任一点 $(x_2, y_2)$ 的代价是曼哈顿距离 $|x_2 - x_1| + |y_2 - y_1|$。另有 `specialRoads[i] = [x1_i, y1_i, x2_i, y2_i, cost_i]` 表示一条**单向**特殊道路：从 $(x_{1i}, y_{1i})$ 走到 $(x_{2i}, y_{2i})$ 恰好花费 $cost_i$（可能比步行贵也可能便宜），每条道路**可以使用任意多次**。返回起点到终点的最小总代价。

**约束**：

- `start.length == target.length == 2`
- $1 \le \text{startX} \le \text{targetX} \le 10^5$，$1 \le \text{startY} \le \text{targetY} \le 10^5$
- $1 \le \text{specialRoads.length} \le 200$，`specialRoads[i].length == 5`
- $\text{startX} \le x_{1i}, x_{2i} \le \text{targetX}$，$\text{startY} \le y_{1i}, y_{2i} \le \text{targetY}$
- $1 \le cost_i \le 10^5$

> 📚 本题在本仓库另有[每日题解 2662](../../solution/2601-2700/2662_前往目标的最小代价.md)：侧重堆优化 Dijkstra 模板的通用变体与面试问答；本篇作为周赛复盘，补全「稀疏建图为什么对」的**引理-定理证明**、赛时决策链与易错清单。

> 💡 两条关键信号：**坐标范围 $10^5 \times 10^5$，道路却只有 $\le 200$ 条** ⇒ 网格大到无法逐格搜索，但「值得停下来做决策」的位置极少——提示**只取关键点建小图**；**步行代价 = 曼哈顿距离** ⇒ 满足三角不等式，任意两个决策点之间都能 $O(1)$ 算出直达代价 ⇒ 边不必显式建，松弛时现算即可。

## 2. 示例

**示例 1**

```text
输入：start = [1,1], target = [4,5], specialRoads = [[1,2,3,3,2],[3,4,4,5,1]]
输出：5
解释：(1,1) 步行到 (1,2) 花费 1 → 取道路 0 到 (3,3) 花费 2
     → 步行到 (3,4) 花费 1 → 取道路 1 到 (4,5) 花费 1，总计 1+2+1+1 = 5。
     纯步行要 |4-1|+|5-1| = 7，两条道路把 7 压到 5。
```

**示例 2**

```text
输入：start = [3,2], target = [5,7], specialRoads = [[5,7,3,2,1],[3,2,3,4,4],[3,3,5,5,5],[3,4,5,6,6]]
输出：7
解释：所有组合都不如直接步行 |5-3|+|7-2| = 7。注意道路 0 的方向是
     (5,7)→(3,2)，与我们要走的方向相反，用不上。
```

**示例 3**

```text
输入：start = [1,1], target = [10,4], specialRoads = [[4,2,1,1,3],[1,2,7,4,4],[10,3,6,1,2],[6,1,1,2,3]]
输出：8
解释：(1,1) 步行 1 到 (1,2) → 取道路 1（代价 4）到 (7,4) → 步行 3 到 (10,4)，总计 8。
```

## 3. 解题思路

### 3.1 暴力思路

**把网格当图逐格搜索**：坐标上界 $10^5$，全图多达 $10^{10}$ 个格子，BFS / Dijkstra 无论时间还是空间都直接爆炸。

**枚举道路使用方案**：每条道路用或不用、以什么顺序用，本质是指数级的组合搜索，且"用了 A 再用 B"与"只用 B"之间没有简单的局部比较规则（贪心有后效性：先绕远路用一条贵路，可能换来后面便宜路的起点更近）。

> ⚠️ 两个暴力都死在同一个地方：**状态空间被坐标范围撑爆**。突破口是反过来问——最优路径到底会在哪些位置「停下来做决策」？

### 3.2 核心观察：决策位置只有 $O(n)$ 个，其余全部直达

![核心概念：网格巨大但决策位置稀疏，抽象成 n+2 个节点的小图](images/special_roads_sparse_nodes.svg)

最优路径一定呈「**步行 → 道路 → 步行 → 道路 → … → 步行**」的交替结构（引理 1 保证）。在两个「用道路」的动作之间，步行段是**曼哈顿直达**的——中途停留没有任何收益。于是真正需要维护最短距离的位置只有：

- **起点 $S$、终点 $T$**；
- **每条道路的终点** $(x_{2i}, y_{2i})$——从这里出发还能继续取别的道路或步行收尾。

共 $n + 2 \le 202$ 个节点。**道路起点 $(x_{1i}, y_{1i})$ 不必作为节点**：转移「先步行到道路起点、再走道路」是复合动作，步行距离在松弛时隐式算入，道路起点只是被「途经」，不需要独立的最短距离。

由此把问题转成一张**有向带权图上的单源最短路**：

- **步行边**：任意节点 $u \to T$，权值 $d(u, T) = |x_T - x_u| + |y_T - y_u|$；
- **道路边**：任意节点 $u \xrightarrow{i} re_i$，权值 $d(u, rs_i) + cost_i$。

所有边权非负（曼哈顿距离 $\ge 0$、$cost_i \ge 1$），**堆优化 Dijkstra** 直接适用，弹出 $u = T$ 时可提前返回。

### 3.3 算法流程

![算法流程：堆优化 Dijkstra 主循环与两类松弛](images/special_roads_dijkstra_flow.svg)

1. `dist[S] = 0`，其余节点视为 $\infty$（惰性加入哈希表）；堆中压入 `(0, S)`；
2. 弹出堆顶 `(d, u)`：若 `d > dist[u]` 是过期记录，跳过（懒删除）；若 `u == T`，`d` 即答案，提前返回；
3. 对 `u` 松弛两类出边：
   - **① 步行直达终点**：候选 `d + d(u, T)` 更新 `dist[T]`；
   - **② 每条道路 $i$**：候选 `d + d(u, rs_i) + cost_i` 更新 `dist[re_i]`；
4. 每次更新成功则写入 `dist` 并入堆，回到第 2 步；堆空时返回 `dist[T]`。

边全部在弹出时**现算**（每条 $O(1)$），不需要邻接表——这是曼哈顿距离带来的福利。

### 3.4 示例演算

![示例 1 演算：平面走查与 Dijkstra 三步](images/special_roads_example_walkthrough.svg)

以示例 1 走查（$S=(1,1)$，$T=(4,5)$，道路 0：$(1,2)\to(3,3)$ 代价 2，道路 1：$(3,4)\to(4,5)$ 代价 1）。注意 $T$ 恰好是道路 1 的终点，节点集仅 $\{S,\ B=(3,3),\ T\}$：

| 步骤 | 弹出 (d, u) | 关键松弛 | dist 状态 |
|------|------------|----------|-----------|
| ① | (0, S) | 道路 0：$0+1+2=3 \to B$；道路 1：$0+5+1=6 \to T$；步行：$0+7=7$ 不更新 | $B=3$，$T=6$ |
| ② | (3, B) | 道路 1：$3+1+1=5 \to T$；步行：$3+3=6$ 不更新 | $T: 6 \to 5$ |
| ③ | (5, T) | $u = T$ → 提前返回 **5** ✓ | — |

> 💡 第 ② 步是全场看点：从 $B=(3,3)$ 出发步行 1 格到道路 1 的起点 $(3,4)$，再花 1 取道路，把 `dist[T]` 从 6 改善到 5。$(3,4)$ 从头到尾没有入过堆——「道路起点不入堆」在这条样例里省掉了一个节点，而在 $n=200$ 的最坏情形下省掉一半节点与一半转移。

## 4. 算法细节

1. **节点表示**：坐标直接做 `pair<int,int>` / 元组作哈希键，`dist` 用哈希表（Python `dict`）或 `map`（C++）。节点**惰性加入**：初始只放 `S`，`T` 与各 $re_i$ 在首次被松弛时才写入，省去显式收集去重。
2. **两类出边动态生成**：不建邻接表。弹出 `u` 时对每条道路 $i$ 现算 $d(u, rs_i) + cost_i$（$O(1)$），再加一条步行边 $d(u, T)$。总转移数 $O(n)$ 每节点。
3. **提前返回的正确性**：边权非负 ⇒ Dijkstra 弹出一个节点时其 `dist` 已是最终值；弹出 `T` 即可停，后续松弛不可能再改善它。
4. **可选过滤**：$cost_i \ge d(rs_i, re_i)$（道路比自己步行还贵）的道路永远不会出现在最优解里——由三角不等式，$d(u, rs_i) + cost_i \ge d(u, rs_i) + d(rs_i, re_i) \ge d(u, re_i)$，即「先到 $rs_i$ 再取道路」不比直接步行到 $re_i$ 好。删掉它们不改变答案。本题 $n \le 200$ 完全不需要这层优化，但它是把 $n$ 撑到 $10^5$ 时的第一刀。
5. **溢出**：答案上界即纯步行 $2 \times 10^5$，中间松弛值也不超过 $10^8$ 量级，`int` 侥幸够用；按习惯用 `long long`（C++）最稳，Python 无需关心。
6. **「使用任意多次」天然被覆盖**：Dijkstra 允许重复经过同一节点，图上不存在「每条边只能走一次」的限制，无需任何特判（引理 3 还说明最优解其实每条道路至多用一次）。

## 5. 正确性证明

**引理 1（规范形式）**：任意一条从 $S$ 到 $T$ 的合法移动序列，都存在总代价不大于它的**规范序列**：形如 $S \to_{\text{walk}} rs_{i_1} \to_{\text{road}} re_{i_1} \to_{\text{walk}} rs_{i_2} \to_{\text{road}} re_{i_2} \to \cdots \to_{\text{walk}} T$，其中不存在连续两个步行段。

**证明**：步行代价 $d(a, b) = |x_a - x_b| + |y_a - y_b|$ 满足三角不等式 $d(a, c) \le d(a, b) + d(b, c)$。把序列中相邻的步行段 $a \to b \to c$ 合并为直达段 $a \to c$，其余步骤不动，总代价不增；重复至没有相邻步行段，即得规范序列。∎

**引理 2（稀疏图等价）**：原问题的最小总代价等于有向图 $G$ 中 $S \to T$ 的最短距离，其中 $G$ 的节点集 $V = \{S, T\} \cup \{re_i\}$，边集为 ① $(u \to T,\ d(u, T))$ 与 ② $(u \to re_i,\ d(u, rs_i) + cost_i)$。

**证明**：（$\ge$ 方向）任取一条规范序列，其代价为
$$d(S, rs_{i_1}) + c_{i_1} + d(re_{i_1}, rs_{i_2}) + c_{i_2} + \cdots + d(re_{i_k}, T),$$
它逐项对应 $G$ 中路径 $S \to re_{i_1} \to re_{i_2} \to \cdots \to T$（首尾分别是 ② 型与 ① 型边，中间均为 ② 型边），代价相等，故最小代价 $\ge$ 图上最短路。（$\le$ 方向）$G$ 中任何一条 $S \to T$ 路径，把每条 ② 型边展开为「步行到 $rs_i$、使用道路 $i$」、① 型边展开为「步行」，即得一条等代价的合法移动序列，故图上最短路 $\ge$ 最小代价。两向合并即相等。∎

**引理 3（重复使用无增益）**：存在一条最优规范序列，其中每条道路至多使用一次。

**证明**：若道路 $i$ 被使用两次，考察第一次使用后到达 $re_i$ 与第二次使用后再次到达 $re_i$ 之间的片段：其代价非负。删除「该片段 + 步行到 $rs_i$ + 第二次使用道路 $i$」，从第一次的 $re_i$ 直接衔接后续步骤，代价不增且仍合法。重复至无重复使用。∎（这说明题目「每条道路可用任意多次」的宽松条件在图模型下自动满足。）

**定理**：算法返回的 `dist[T]` 是从 $S$ 到 $T$ 的最小总代价。

**证明**：图中所有边权非负（曼哈顿距离 $\ge 0$，$cost_i \ge 1$），堆优化 Dijkstra 在非负权图上正确计算单源最短路（每条出边都被松弛、懒删除仅丢弃过期记录、提前返回只发生在 `dist` 已终定的节点上）。由引理 1、2，该最短路恰等于原问题最优值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 \log n)$。节点数 $m = n + 2 \le 202$，每个节点至多一次有效弹出，每次弹出松弛 $n + 1$ 条出边（$n$ 条道路边 + 1 条步行边），每条边至多入堆一次，堆操作 $O(\log)$。$n = 200$ 时约 $200 \times 201 \times 8 \approx 3 \times 10^5$ 次基本操作，瞬时通过。
- **空间复杂度**：$O(n^2)$。`dist` 表 $O(n)$；堆中记录数上界为「节点数 × 每节点有效松弛数」$= O(n^2)$（实际远小于该上界）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumCost(vector<int>& start, vector<int>& target, vector<vector<int>>& specialRoads) {
        using ll = long long;
        using P = pair<int, int>;
        P S = {start[0], start[1]};
        P T = {target[0], target[1]};

        // 可选优化：过滤 cost >= 自身步行曼哈顿距离的道路（不改变答案）
        vector<vector<int>> roads;
        for (auto& r : specialRoads)
            if (r[4] < abs(r[2] - r[0]) + abs(r[3] - r[1]))
                roads.push_back(r);

        map<P, ll> dist;
        dist[S] = 0;
        priority_queue<pair<ll, P>, vector<pair<ll, P>>, greater<>> pq;
        pq.push({0, S});

        while (!pq.empty()) {
            auto [d, u] = pq.top();
            pq.pop();
            if (d > dist[u]) continue;          // 懒删除：过期记录
            if (u == T) return (int) d;         // 提前返回：dist[T] 已终定

            // ① 步行直达终点
            ll nd = d + abs(T.first - u.first) + abs(T.second - u.second);
            auto it = dist.find(T);
            if (it == dist.end() || nd < it->second) {
                dist[T] = nd;
                pq.push({nd, T});
            }

            // ② 每条道路：步行到道路起点 + 道路代价（复合转移）
            for (auto& r : roads) {
                P v = {r[2], r[3]};
                nd = d + abs(r[0] - u.first) + abs(r[1] - u.second) + r[4];
                auto it2 = dist.find(v);
                if (it2 == dist.end() || nd < it2->second) {
                    dist[v] = nd;
                    pq.push({nd, v});
                }
            }
        }
        return (int) dist[T];
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, start: List[int], target: List[int], specialRoads: List[List[int]]) -> int:
        from heapq import heappop, heappush

        S = (start[0], start[1])
        T = (target[0], target[1])
        INF = float('inf')

        # 可选优化：过滤 cost >= 自身步行曼哈顿距离的道路（不改变答案）
        roads = [r for r in specialRoads
                 if r[4] < abs(r[2] - r[0]) + abs(r[3] - r[1])]

        dist = {S: 0}
        pq = [(0, S)]
        while pq:
            d, u = heappop(pq)
            if d > dist.get(u, INF):        # 懒删除：过期记录
                continue
            if u == T:                      # 提前返回：dist[T] 已终定
                return d

            # ① 步行直达终点
            nd = d + abs(T[0] - u[0]) + abs(T[1] - u[1])
            if nd < dist.get(T, INF):
                dist[T] = nd
                heappush(pq, (nd, T))

            # ② 每条道路：步行到道路起点 + 道路代价（复合转移）
            for x1, y1, x2, y2, c in roads:
                nd = d + abs(x1 - u[0]) + abs(y1 - u[1]) + c
                v = (x2, y2)
                if nd < dist.get(v, INF):
                    dist[v] = nd
                    heappush(pq, (nd, v))

        return dist[T]
```

## 8. 边界情况与易错点

1. **漏掉「步行直达 $T$」的边**：最常见的 WA。若只松弛道路边，示例 2（最优是纯步行 7）会直接算错。步行边就是「什么都不用」的兜底候选，与道路边地位平等。
2. **道路是单向的**：`[x1, y1, x2, y2, cost]` 只能 $rs \to re$，不能倒着走（示例 2 的道路 0 方向相反就是专门埋的坑）。想反向必须存在另一条方向合适的道路。
3. **道路不一定划算**：$cost_i$ 可能远大于步行距离（示例 2 里两条 4、5、6 的路），不能假设「见到道路就要用」；也不要在建图时把「到 $rs_i$ 的步行」误当免费。
4. **道路起点不要入堆**：既不需要也不该有 `dist[rs_i]`。它是复合转移的中间踏脚石；若给它独立状态反而在 $S = rs_i$ 或多处重合时引入冗余（倒不会错，但白白翻倍节点数）。
5. **$S = T$**：`dist[S] = 0` 加上「弹出即判 `u == T`」天然返回 0，无需特判；若把初始化写歪（如先松弛再入堆）就可能漏掉这个 0。
6. **重复使用道路**：无需特判——Dijkstra 本身允许再次到达并再次松弛同一条边（引理 3 保证最优解也不会真用到重复）。
7. **懒删除判断**：`if d > dist[u]: continue` 不能省。不写也能对（旧记录松弛不出更小值），但堆会无谓膨胀；$n$ 小看不出来，这是模板习惯问题。
8. **节点重合**：多条道路终点相同、或 $re_i = T$（示例 1）、甚至 $re_i = S$ 都可能发生，哈希表按坐标键自动合并，无需人工去重。
9. **溢出**：答案 $\le 2 \times 10^5$，`int` 够，但按习惯 C++ 用 `long long` 存距离更保险。
10. **别用 BFS / DP**：边权各不相同且非负，没有层结构也没有无后效性；正确工具就是 Dijkstra。同理别想成 0-1 BFS 或分层 BFS。

- **道路双向可用怎么办？** 给每条道路补一条对称边 $(re_i \to rs_i,\ cost_i)$ 即可，模型其余不动。
- **道路数涨到 $10^5$ 怎么办？** $O(n^2 \log n)$ 的全对松弛失效，需要把「最近的道路起点」查询交给空间索引（如 KD-Tree 按曼哈顿距离最近邻），或按坐标分块批量松弛。
- **要求恰好用 $k$ 条道路的最小代价？** 状态加一维「已用道路数」做分层图 Dijkstra：节点 $(位置,\ j)$，转移时道路边 $j \to j{+}1$，答案取 $dist[(T,\ k)]$——把「计数约束」写进状态是分层图的通用手法。
