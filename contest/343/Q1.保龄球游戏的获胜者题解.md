# LeetCode 保龄球游戏的获胜者 题解

## 1. 题目概述

- **标题 / 题号**：保龄球游戏的获胜者（#2660，easy）
- **链接**：https://leetcode.cn/problems/determine-the-winner-of-a-bowling-game/
- **来源**：LeetCode 第 343 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：两名玩家各打 $n$ 轮保龄球（每轮满瓶 10 个），`player1[i]`、`player2[i]` 为第 $i$ 轮击中的瓶数 $x_i$。第 $i$ 轮的**价值**：若**前两轮**（第 $i-1$、$i-2$ 轮中实际存在者）里**任意一轮恰好击中 10 个瓶子**，则为 $2x_i$，否则为 $x_i$；**得分**为 $n$ 轮价值之和。返回赢家编号：玩家 1 胜返回 1，玩家 2 胜返回 2，平局返回 0。

**约束**：

- $n = \text{player1.length} = \text{player2.length}$，$1 \le n \le 1000$
- $0 \le \text{player1}[i], \text{player2}[i] \le 10$

> 📚 本题在本仓库另有[每日题解 2660](../../solution/2601-2700/2660_保龄球游戏的获胜者.md)：含「回看窗口 / 前瞻倒计时」双视角对照与面试问答；本篇侧重赛时最短路径——如何把题面规则一次性翻译成不会翻车的布尔判定。

> 💡 三条关键信号：**触发条件是定长回看窗口**（恰好看 $i-1$、$i-2$ 两轮的原始瓶数）⇒ 直接下标访问，无需任何数据结构；**判定是布尔「或」**（窗口内存在 10 即翻倍，不叠加）；$n \le 1000$ ⇒ 一趟 $O(n)$ 模拟就是正解，比拼的是把题面翻译成代码时**不漏不重**。

## 3. 解题思路

### 3.1 赛时最短路：一趟模拟即正解

签到题的最优策略是**用最短时间写出一定对的代码**。本题没有渐近上的优化空间：把题面规则逐字翻译成循环就是 $O(n)$ 正解。赛时应先把核心判定抽成 `score(a)`：

```python
def score(a):
    s = 0
    for i, x in enumerate(a):
        if (i >= 1 and a[i - 1] == 10) or (i >= 2 and a[i - 2] == 10):
            s += 2 * x          # 前两轮（存在者）里有 10 ⇒ 本轮翻倍
        else:
            s += x
    return s
```

风险不在算法而在**翻译**：窗口长度、触发值、下标守卫、平局返回值，任何一处笔误都是一次 WA。Q1 的复盘价值就是把题面拆成可核对的关键词清单（见 §8）。

> ⚠️ Python 里漏写 `i >= 1` 守卫不会报错：$i = 0$ 时 `a[i-1]` 即 `a[-1]`，**静默取到最后一个元素**——若末尾恰好是 10，第 0 轮会被凭空翻倍。比 C++ 的越界未定义行为更难发现。

### 3.2 核心观察：定长窗口 + 原始值触发

![核心概念：第 i 轮是否翻倍由前两轮的原始瓶数窗口决定](images/bowling_double_window.svg)

把题面三个关键词抽出来，判定式一次写对：

- **「前两轮」**：恰是 $i-1$、$i-2$ 两个下标——**定长回看窗口**。更早轮次的 10 已经「花完」了自己的奖励（只覆盖其后两轮），对第 $i$ 轮失效；
- **「任意一轮击中 10」**：窗口内的**存在性**判定（布尔「或」），不是计数——前两轮都是 10 也只翻倍**一次**（$2x_i$ 而非 $4x_i$）；
- **「击中 10 个瓶子」**：触发看**原始击瓶数** $x_j = 10$，与翻倍后的轮次价值无关——价值 $2 \times 5 = 10$ 的轮次**不**触发，原始 10 翻倍成价值 20 的轮次**仍**触发。

一句话：$\text{val}(i) = 2x_i \iff (i \ge 1 \wedge x_{i-1} = 10) \vee (i \ge 2 \wedge x_{i-2} = 10)$，否则 $\text{val}(i) = x_i$。

### 3.3 算法流程

![算法流程：score() 逐轮判定翻倍并累加，最后比较总分三分支返回](images/bowling_score_flow.svg)

1. 抽取 `score(a)`：`s = 0`，从 $i = 0$ 扫到 $n-1$；
2. 每轮做一次判定 $(i \ge 1 \wedge a_{i-1} = 10) \vee (i \ge 2 \wedge a_{i-2} = 10)$：真则 `s += 2·a[i]`，假则 `s += a[i]`；
3. 两玩家各调用一次：$s_1 = \text{score(player1)}$，$s_2 = \text{score(player2)}$；
4. 三分支返回：$s_1 > s_2$ 返回 1，$s_2 > s_1$ 返回 2，相等返回 0。

### 3.4 示例演算

![示例演算：示例 4 两位玩家 73 vs 75 的逐轮对比](images/bowling_example_walkthrough.svg)

以最刁钻的**示例 4** 走查（两玩家都只击出 10 和 1 两种瓶数，胜负全在「翻倍链的余热」上）：

| 轮次 $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 玩家 1 瓶数 | 1 | 1 | 1 | 10 | 10 | 10 | 10 |
| 玩家 1 价值 | 1 | 1 | 1 | 10 | **20** | **20** | **20** |
| 玩家 2 瓶数 | 10 | 10 | 10 | 10 | 1 | 1 | 1 |
| 玩家 2 价值 | 10 | **20** | **20** | **20** | **2** | **2** | 1 |

玩家 1 的 10 到第 3 轮才出现，翻倍链只覆盖后三轮，得 $73$；玩家 2 开局连出 4 个 10，第 5 轮（窗口 $[10, 1]$，第 3 轮的 10 仍在）继续翻倍，得 $75$。$73 < 75$，返回 `2` ✓

> 💡 看点：玩家 2 的第 5 轮是本题题眼——上一轮只击中 1，但**上上轮的 10 还在窗口里**，「任意一轮」≠「上一轮」。第 6 轮窗口滑成 $[1, 1]$，余热耗尽恢复原值。

## 4. 算法细节

1. **helper 复用**：两玩家规则完全一致且互不耦合，抽 `score(a)` 各调一次，杜绝复制粘贴两份循环后改漏一处。
2. **守卫写死在判定里**：`(i >= 1 && a[i-1] == 10) || (i >= 2 && a[i-2] == 10)`，把「前轮不足」内化成短路条件。不要用 `a[max(i-2, 0)]` 之类的钳位下标——$i = 0$ 时会把**当前轮**错塞进自己的判定窗口。
3. **等价的「倒计时」写法**：维护翻倍剩余轮数 $\text{bonus}$——本轮先按 $\text{bonus} > 0$ 决定是否翻倍，再更新：$x_i = 10$ 则 $\text{bonus} = 2$（**覆盖**而非累加），否则 $\max(\text{bonus} - 1, 0)$。前瞻视角天然不需要下标守卫，推广到「前 $k$ 轮」也只改一个常数（详见[每日题解 2660](../../solution/2601-2700/2660_保龄球游戏的获胜者.md)的方法二）。
4. **得分上界**：每轮价值 $\le 2 \times 10 = 20$，总分 $\le 20000$，`int` 无溢出风险。
5. **返回值三分支**：$1$ / $2$ / $0$（平局），不要顺手写成布尔。

## 5. 正确性证明

**引理 1（单轮价值）**：`score(a)` 中第 $i$ 轮累加进 `s` 的值恰等于题面定义的第 $i$ 轮价值。

**证明**：题面定义第 $i$ 轮价值为 $2x_i$ 当且仅当**存在**前驱轮次 $j \in \{i-1, i-2\}$ 且 $j \ge 0$，使 $x_j = 10$。代码条件 $(i \ge 1 \wedge a_{i-1} = 10) \vee (i \ge 2 \wedge a_{i-2} = 10)$ 中两个合取项分别对应 $j = i-1$ 与 $j = i-2$，而 $i \ge 1$、$i \ge 2$ 恰是二者合法（$j \ge 0$）的存在性守卫；$i = 0$ 时两项均假，与「无前驱轮」一致。故条件为真当且仅当存在这样的 $j$，此时累加 $2x_i$，否则累加 $x_i$，与定义逐字对应。∎

**定理**：算法返回值与两名玩家的胜负关系一致。

**证明**：由引理 1，循环把每轮价值恰好累加一次，故 $s_1$、$s_2$ 分别为玩家 1、玩家 2 按题面定义的总得分。返回逻辑三分支完全枚举：$s_1 > s_2 \Rightarrow 1$，$s_2 > s_1 \Rightarrow 2$，$s_1 = s_2 \Rightarrow 0$，与题面要求的返回值一一对应且无遗漏。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`score` 对每个数组单趟扫描，每轮一次 $O(1)$ 的布尔判定（两次下标访问）与一次累加；两个玩家共 $2n$ 轮，$n \le 1000$ 瞬时通过。
- **空间复杂度**：$O(1)$。仅累计变量、循环下标与临时布尔值，不随 $n$ 增长。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int isWinner(vector<int>& player1, vector<int>& player2) {
        auto score = [](const vector<int>& a) {
            int s = 0;
            for (int i = 0; i < (int)a.size(); ++i) {
                bool dbl = (i >= 1 && a[i - 1] == 10) ||
                           (i >= 2 && a[i - 2] == 10);
                s += dbl ? 2 * a[i] : a[i];
            }
            return s;
        };
        int s1 = score(player1), s2 = score(player2);
        return s1 > s2 ? 1 : (s2 > s1 ? 2 : 0);
    }
};
```

### Python

```python
class Solution:
    def isWinner(self, player1: List[int], player2: List[int]) -> int:
        def score(a: List[int]) -> int:
            s = 0
            for i, x in enumerate(a):
                if (i >= 1 and a[i - 1] == 10) or (i >= 2 and a[i - 2] == 10):
                    s += 2 * x      # 前两轮（存在者）里有 10 ⇒ 翻倍一次
                else:
                    s += x
            return s

        s1, s2 = score(player1), score(player2)
        return 1 if s1 > s2 else (2 if s2 > s1 else 0)
```

## 8. 边界情况与易错点

1. **前轮不足两轮**：$i = 0$ 无前驱、$i = 1$ 只有 $i-1$。守卫 $i \ge 1$ / $i \ge 2$ 必须写进判定；Python 漏守卫时 `a[i-1]` 取负索引**静默出错**（$i = 0$ 时可能拿数组末尾的 10 给第 0 轮翻倍）。
2. **钳位下标陷阱**：`a[max(i-2, 0)]` 在 $i = 0$ 时把当前轮塞进自己的窗口——若 `a[0] = 10`，第 0 轮被凭空翻倍。守卫只能用存在性条件，不能用下标钳位。
3. **「任意一轮」≠「上一轮」**：$a = [10, 1, 1]$ 的第 2 轮靠第 0 轮的 10 照样翻倍；反之 $a = [10, 1, 1, 1]$ 的第 3 轮**不**翻倍——窗口长度恰为 2，第 0 轮的 10 已出窗。
4. **翻倍不叠加**：前两轮都是 10 也只翻倍一次（$2x_i$ 而非 $4x_i$），判定是布尔「或」不是计数。
5. **触发看原始瓶数**：反例 $a = [10, 5, 5]$——若误用「轮次价值 $= 10$」当触发条件，第 2 轮会因第 1 轮价值 $2 \times 5 = 10$ 而翻倍得 20；正确是第 2 轮价值 $2 \times 5 = 10$（窗口内是第 0 轮的**原始** 10），总分 30 而非 40。
6. **平局返回 0**：不是 $-1$ 也不是布尔；用示例 3 自测三分支。
7. **无溢出**：总分上界 $2 \times 10 \times 1000 = 20000$，`int` 足够。
8. **赛时自测三件套**：$n = 1$（无任何翻倍）、全 10（首轮原值、其余全翻倍）、`[10,1,1,1]`（10 的奖励恰好两轮耗尽）——三个用例把窗口边界全部踩一遍。
