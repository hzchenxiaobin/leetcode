# LeetCode 输入单词需要的最少按键次数 II 题解

## 1. 题目概述

- **标题 / 题号**：输入单词需要的最少按键次数 II（#3016，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-pushes-to-type-word-ii/
- **来源**：LeetCode 第 381 场周赛 Q3
- **难度**：中等
- **标签**：贪心、哈希表、字符串、计数、排序

**题意**：给定仅含小写字母的字符串 `word`，允许把编号 $2 \sim 9$ 的 **8 个按键**重新映射到不同的字母集合：每个键可挂**任意多个**字母（也可空着），每个字母必须**恰好**挂到一个键上。挂在某键第 $p$ 位的字母，每输入一次要连按 $p$ 次键。请自行设计映射，使输入整个 `word` 的总按键次数最少，返回该最小值。

**约束**：

- $1 \le \text{word.length} \le 10^5$；
- `word` 仅由小写英文字母组成。

> 💡 **赛时背景**：本题是本场 Q1（[3014. 输入单词需要的最少按键次数 I](https://leetcode.cn/problems/minimum-number-of-pushes-to-type-word-i/)）的放开版——Q1 保证字母**互不相同**且 $|\text{word}| \le 26$，Q3 允许重复。两题共用同一套「分层」洞察：Q1 是「每层放 8 个**字母**」，Q3 升级为「每层放 8 个**频率**」，只多一步统计与排序。赛时若已把 Q1 的层计数公式立住，本题应当是顺手题；卡住多半是没意识到**同一字母反复计费**要以频率为权重。

## 2. 示例

**示例 1**

```text
输入：word = "abcde"
输出：5
解释：5 种字母各占一个键的第 1 位，每个字母按 1 次：1×5 = 5。
```

**示例 2**

```text
输入：word = "xyzxyzxyzxyz"
输出：12
解释：x / y / z 各出现 4 次，各占一个键的第 1 位：4×1 + 4×1 + 4×1 = 12。
      键 9 可以空着——不必让每个键都挂字母。
```

**示例 3**

```text
输入：word = "aabbccddeeffgghhiiiiii"
输出：24
解释：i 出现 6 次排最前，占某键第 1 位；a~g 各 2 次占另外 7 个键的第 1 位；
      h 排第 9，只能落到某键第 2 位（按 2 次）。
      总代价 = 6×1 + 2×7×1 + 2×2 = 24。
```

## 3. 解题思路

### 3.1 暴力思路

「设计键盘」最直接的想法是枚举：把 26 个字母分到 8 个键、再排定每个键内部的先后次序，方案数是 $26!$ 量级的组合爆炸；即使只考虑 `word` 中出现过的 $m \le 26$ 种字母，把 $m$ 个元素塞进 8 个有序列表也仍是指数级。搜索彻底没戏。

退一步看，这本质是个**指派问题**：字母连向「槽位」，边权是 $\text{freq} \times \text{位次}$，求最小权匹配——匈牙利算法 / 费用流 $O(m^3)$ 在 $m \le 26$ 下完全可跑。但一旦看清槽位的**供给结构**，匹配也是杀鸡用牛刀：一次排序就能出答案。

### 3.2 核心观察：位次计费，每层 8 个浅槽，降序填入

![核心观察：八键分层槽位模型](images/wc381_q3_keypad_slots.svg)

**观察一：键的身份不重要，位次才重要。** 字母 $c$ 挂在某键第 $p$ 位，每次出现贡献 $p$ 次按键，于是

$$\text{ans} = \sum_{c} \text{freq}(c) \times \text{pos}(c)$$

挂键 2 还是键 9、同位次内部谁先谁后，代价完全一样。「设计键盘」由此坍缩为「给每个字母定一个**位次**」。

**观察二：浅槽有硬供给上限，贪心分层恰好取满。** 8 个键各自都能提供第 $1$ 位、第 $2$ 位、……，所以**任何**合法映射中，位次 $\le p$ 的槽至多 $8p$ 个。贪心「频率从高到低，每 8 个占一层」把每层供给吃满：$26 = 8 + 8 + 8 + 2$，位次代价多重集取到 $\{1{\times}8,\ 2{\times}8,\ 3{\times}8,\ 4{\times}2\}$。

> ⚠️ 「槽位多重集是固定的」并不严谨——把 5 个字母挂同一个键照样能造出代价 5 的槽，只是毫无好处。严谨表述是**供给约束**（位次 $\le p$ 的槽 $\le 8p$ 个）加**逐分量下界**（§5 引理 1）：贪心的分层恰好逐格顶到下界。

**观察三：交换论证——高频字母必须占浅槽。**

![交换论证：高频字母陷在深槽，换出来代价只降不升](images/wc381_q3_exchange_argument.svg)

设字母 $a$、$b$ 频率 $f_a \ge f_b$，但 $a$ 占了深槽（$c_a > c_b$）、$b$ 占浅槽。交换两者的位次，总代价变化

$$\Delta = f_a c_b + f_b c_a - f_a c_a - f_b c_b = (f_a - f_b)(c_b - c_a) \le 0$$

交换永不增代价，且每换一次至少消掉一个「高深低浅」的逆序对；有限步后逆序对清零，终局正是**频率降序 × 位次升序**——贪心的填法。

### 3.3 算法流程

![算法流程：计数、降序排序、分层求和](images/wc381_q3_algorithm_flow.svg)

1. **统计频率**：`freq[26]` 一遍扫描 `word` 计数，$O(n)$；
2. **降序排序**：对 26 个频率降序排（0 频率自然沉底），$O(26 \log 26)$；
3. **分层求和**：第 $i$ 个（0 下标）字母落在第 $\lfloor i/8 \rfloor + 1$ 层，$\text{ans} \mathrel{+}= \text{freq}[i] \times (\lfloor i/8 \rfloor + 1)$，$O(26)$。

全程不构造任何键盘方案——答案只由「频率多重集 + 层号」决定。

### 3.4 示例演算

![示例演算：aabbccddeeffgghhiiiiii 分层求和得 24](images/wc381_q3_example_walkthrough.svg)

以示例 3 `word = "aabbccddeeffgghhiiiiii"` 走一遍：共 9 种字母，频率降序为 $[6, 2, 2, 2, 2, 2, 2, 2, 2]$（$i$ 最高，$a \sim h$ 同为 2）。排队后第 1 层装 $i, a, b, c, d, e, f, g$ 共 8 个（各按 1 次），第 2 层只剩 $h$（按 2 次）。总代价 $= (6 + 2 \times 7) \times 1 + 2 \times 2 = 20 + 4 = \mathbf{24}$ ✓，与官方解释一致。同频的 $a \sim h$ 中谁被挤到第 2 层无所谓——层内位次代价相同，答案唯一。

## 4. 算法细节

1. **计数用数组还是哈希**：字母表只有 26 个，`freq[26]` 数组最快；`Counter` 只含出现过的字母，两者等价——0 频率乘任何位次都是 0，排序时自然沉底，**无需特判**。
2. **层号的两种写法**：0 下标第 $i$ 个字母的代价是 $\lfloor i/8 \rfloor + 1$；等价地，1 下标第 $i$ 个是 $\lceil i/8 \rceil$。代码里即 `i / 8 + 1`（C++ 整除）或 `i // 8 + 1`（Python）。
3. **排序对象是 26 个频率，不是整个串**：即使 $n = 10^5$，待排的也只有至多 26 个数。
4. **同频与同层的等价性**：同频字母互换位次答案不变，同一层内挂到哪个键也不影响。因此答案**唯一确定**、与任何具体键位方案无关——这也是为什么代码里连字母本身都不必保留，只排频率数组。
5. **为什么不必每个键都用**：供给上限是「至多」而非「恰要」；字母种数不足 8 时浅槽够用，多余的键自然空置（示例 2 的键 9）。
6. **溢出估算**：位次至多 4（$26 \le 8 \times 4$），总代价 $\le 4n \le 4 \times 10^5$，`int` 绰绰有余；不过「乘积累加用 `long long`」是值得保留的肌肉记忆。

## 5. 正确性证明

**引理 1（供给约束）**：任何合法映射中，位次 $\le p$ 的字母至多 $8p$ 个；从而把该映射下 $m$ 个出现字母的位次升序排列为 $c_1 \le c_2 \le \cdots \le c_m$，则对每个 $i$ 有 $c_i \ge \lceil i/8 \rceil$。

**证明**：某键挂 $t_j$ 个字母，其位次为 $1 \sim t_j$，其中位次 $\le p$ 的恰有 $\min(t_j, p) \le p$ 个；8 个键合计 $\sum_j \min(t_j, p) \le 8p$。若 $c_i < \lceil i/8 \rceil$，取 $p = \lceil i/8 \rceil - 1$，则 $8p < i$ 且 $c_i \le p$；由升序性，前 $i$ 个位次全 $\le p$，即位次 $\le p$ 的字母至少 $i > 8p$ 个，与供给约束矛盾。∎

**引理 2（逆序配对最优，重排不等式）**：固定代价序列 $c_1 \le \cdots \le c_m$ 与频率 $f_1, \ldots, f_m \ge 0$，则 $\sum_i f_i c_{\sigma(i)}$ 在「频率降序配代价升序」时取得最小值。

**证明**：若某配对中存在频率 $f_a \ge f_b$ 的两个字母，却满足 $c_{\sigma(a)} > c_{\sigma(b)}$（高频者配了更贵的代价），交换二者的配对，总和变化

$$\Delta = f_a c_{\sigma(b)} + f_b c_{\sigma(a)} - f_a c_{\sigma(a)} - f_b c_{\sigma(b)} = (f_a - f_b)\bigl(c_{\sigma(b)} - c_{\sigma(a)}\bigr) \le 0$$

每次交换总和不增，且至少消掉一个逆序对；有限步后逆序对清零，终局配对即「频率降序 × 代价升序」，其总和不大于任何初始配对。∎

**定理（分层贪心最优）**：把频率降序排列为 $f_1^{\downarrow} \ge \cdots \ge f_m^{\downarrow}$，则最小总代价恰为

$$\text{OPT} = \sum_{i=1}^{m} f_i^{\downarrow} \cdot \Bigl\lceil \tfrac{i}{8} \Bigr\rceil$$

**证明**：记 $L_i = \lceil i/8 \rceil$。

**（可达）**把第 $1 \sim 8$ 个字母分到 8 个不同键的第 1 位，第 $9 \sim 16$ 个分到各键第 2 位，依此类推——每个键每层至多挂一个字母，是合法映射，总代价即 $\sum_i f_i^{\downarrow} L_i$（未出现的字母堆到任意键更深的位置即可，频率为 0，不影响总代价）。

**（下界）**任取一个合法映射，设其 $m$ 个出现字母的位次多重集升序为 $c_1 \le \cdots \le c_m$。该映射的总代价是频率与位次的某种配对之和，由引理 2 不小于 $\sum_i f_i^{\downarrow} c_i$；又由引理 1 有 $c_i \ge L_i$ 且 $f_i^{\downarrow} \ge 0$，故 $\sum_i f_i^{\downarrow} c_i \ge \sum_i f_i^{\downarrow} L_i$。

综合两方面，$\text{OPT} = \sum_{i=1}^{m} f_i^{\downarrow} L_i$。∎

**推论（答案唯一）**：最优值只依赖频率的多重集；同频字母互换、层内键位调换均不改变总代价，故输出与具体键盘方案无关。

> 💡 **直觉的缺口是怎么堵上的**：看起来的「每层 8 个」像是唯一选择，但合法映射其实五花八门（一键挂 10 个字母也行）。引理 1 说明无论方案多离谱，其**升序位次序列逐格不低于** $L$；引理 2 保证配对方式不会让总和低于降序配对——两道关卡一起把任意方案的总代价压在贪心值之上。

## 6. 复杂度分析

- **时间复杂度**：$O(n + 26 \log 26)$。计数一遍 $O(n)$ 是主要开销；对至多 26 个频率排序与分层求和均为常数级，整体即 $O(n)$，$n = 10^5$ 轻松通过。
- **空间复杂度**：$O(26)$。计数数组大小恒为 26（`Counter` 版为出现过的字母数，$\le 26$），与 $n$ 无关。

## 7. 参考代码

### C++（值域计数 + 降序分层）

```cpp
class Solution {
  public:
    int minimumPushes(string word) {
        int freq[26] = {0};
        for (char c : word) ++freq[c - 'a'];            // 计数

        sort(begin(freq), end(freq), greater<int>());   // 频率降序

        int ans = 0;
        for (int i = 0; i < 26; ++i)                    // 前 8 个 ×1，接着 8 个 ×2 ……
            ans += freq[i] * (i / 8 + 1);               // 0 频率乘任何位次仍是 0
        return ans;                                     // 至多 4n ≤ 4e5，int 足够
    }
};
```

### Python（Counter 一行流）

```python
class Solution:
    def minimumPushes(self, word: str) -> int:
        freq = sorted(Counter(word).values(), reverse=True)
        return sum(f * (i // 8 + 1) for i, f in enumerate(freq))
```

> 💡 两版语义完全一致：C++ 排含 0 的 26 格数组，Python 只排出现过的字母——0 频率不产生贡献，两边等价。

## 8. 边界情况与易错点

1. **忘乘频率（最大陷阱）**：直接套 Q1 的「层计数」只数字母种数——示例 3 会算成 $8 \times 1 + 1 \times 2 = 10 \ne 24$。Q3 相对 Q1 的唯一增量就是「频率作权重」，必须是 `freq[i] * (i / 8 + 1)`。
2. **层号 off-by-one**：0 下标代价是 $\lfloor i/8 \rfloor + 1$。自检：$i = 7$ 代价 1，$i = 8$ 代价 2；0 下标误写 $\lceil i/8 \rceil$ 会把第 8 个字母多压一层。
3. **字母互异时退化成 Q1**：频率全 1，公式塌缩为 $\sum_{i=1}^{n} \lceil i/8 \rceil$——$n \le 8$ 时答案就是 $n$；$n = 26$ 时 $8 + 16 + 24 + 8 = 56$。
4. **单一字母刷满全串**：$m = 1$，答案就是 $n$（第 1 层）——别把没出现的字母也算进层里。
5. **自带不存在的约束**：老式 T9 键盘「每键 3 个字母」「8 个键必须用满」都不是本题条件——每键可挂任意多字母（示例 3 的 `i`、`h` 同挂键 9），键也可以空着（示例 2 的键 9）。
6. **26 个字母必须都有归属**：不在 `word` 里出现的字母也要挂在某个键上——好在 0 频率怎么挂都不产生代价，代码无需关心。
7. **溢出**：总代价上界 $4n \le 4 \times 10^5$，`int` 安全；字母表或串长放大时改用 `long long` 累加。
8. **别对整个串排序**：对 $10^5$ 长的串做 $O(n \log n)$ 排序虽也能过，但排序 26 个频率才是本题的复杂度形态。
