# LeetCode 统计星号 题解

## 1. 题目概述

- **标题 / 题号**：统计星号（#2315，easy）
- **链接**：https://leetcode.cn/problems/count-asterisks/
- **来源**：LeetCode 第 81 场双周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定字符串 $s$，其中竖线 `|` **两两配对**（第 1、2 条为一对，第 3、4 条为一对，以此类推），每条竖线恰好属于一个对。统计**不在任何竖线对之间**的字符 `*` 的数目。

**约束**：

- $1 \le s.length \le 1000$
- $s$ 只包含小写英文字母、竖线 `|` 和星号 `*`
- $s$ 中竖线的总数为**偶数**（保证配对完整，不会出现「半扇门」）

## 2. 示例

**示例 1**

```text
输入：s = "l|*e*et|c**o|*de|"
输出：2
解释：竖线对之外的部分为 "l"、"c**o"、"*de"，
其中星号出现在 "c**o" 内共 2 个，返回 2。
```

**示例 2**

```text
输入：s = "iamprogrammer"
输出：0
解释：没有星号，无论怎么配对都是 0。
```

**示例 3**

```text
输入：s = "yo|uar|e**|b|e***au|tifu|l"
输出：5
解释：竖线对之外的部分为 "yo"、"e**"、"e***au"、"l"，
星号数 0 + 2 + 3 + 0 = 5。
```

## 3. 解题思路

### 3.1 暴力思路

先把字符串按 `|` 切分成 $2k+1$ 段（$k$ 为竖线对数）：切出来的段交替处于「门外 / 门内」——下标 $0, 2, 4, \dots$ 的段在门外，下标 $1, 3, 5, \dots$ 的段在门内。对门外各段统计 `*` 个数求和即可。这个做法本身已经是 $O(n)$，谈不上不可行，只是需要 $O(n)$ 额外空间存切分结果（Python `s.split('|')` 尤其方便）。

> ⚠️ 一个想当然的坑：不能简单地「遇到 `|` 就跳到下一个 `|`」再继续数星号吗？可以，但实现时容易在「连续两条竖线 `||`」「竖线在串首/串尾」这些位置把段下标错位。用显式的布尔状态变量最不易错。

### 3.2 核心观察：一个布尔开关就够

![核心观察：竖线成对开关模型](images/bw81_q1_toggle_model.svg)

维护布尔量 $inPair$（当前是否处于某对竖线内部）：

- 初始 $inPair = false$（门外）；
- 每遇到一条 `|`，$inPair$ 取反——第 1 条竖线开门（进入对内）、第 2 条关门（回到门外）、第 3 条再开门……
- 只有当 $inPair = false$ 时遇到的 `*` 才计入答案。

由于竖线总数为偶数，扫描结束时 $inPair$ 必然回到 $false$，无需收尾特判。「奇数条竖线开门、偶数条关门」与「第 $2t-1$、$2t$ 条配成一对」完全等价。

### 3.3 算法流程

![单趟扫描流程图](images/bw81_q1_scan_flow.svg)

```text
1. ans = 0, inPair = false
2. 从左到右扫描每个字符 c：
       若 c == '|'：inPair = !inPair        （开关翻转）
       若 c == '*' 且 !inPair：++ans        （门外星号计数）
       其他字符：跳过
3. 返回 ans
```

一次遍历、常数额外空间，字符数 $n \le 1000$ 绰绰有余。

### 3.4 示例演算

![示例演算：切段视角与开关视角](images/bw81_q1_example_walkthrough.svg)

以示例 3（`"yo|uar|e**|b|e***au|tifu|l"`）为例，按竖线切分得 9 段：

| 段下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|--------|-----|-----|-----|---|--------|------|-----|---|
| 内容 | yo | uar | e** | b | e***au | tifu | l | | |
| 门内？ | 门外 | 门内 | 门外 | 门内 | 门外 | 门内 | 门外 | | |
| 星号 | 0 | — | 2 | — | 3 | — | 0 | | |

门外星号合计 $0 + 2 + 3 + 0 = 5$，与答案一致。开关视角与切段视角**恒等**：段下标的奇偶性恰好对应 $inPair$ 的翻转次数。

## 4. 算法细节

1. **状态定义放循环外**：`inPair` 是贯穿整个扫描的「全局」状态，不要在循环内重置。
2. **先判 `|` 再判 `*`**：`|` 与 `*` 是不同字符，两个 `if` 顺序其实无所谓，但写成 `if-else if` 结构可以少一次无谓比较。
3. **C++ 遍历方式**：`for (char c : s)` 按值拷贝每个字符，$n \le 1000$ 无性能顾虑；也可用下标。
4. **Python 的另一种一行写法**：`sum(s.split('|')[::2].count('*'))`——切分后取偶数下标段（门外），统计星号。正确性来自「段下标奇偶 = 门内外」的对应，可作为验算工具。
5. **不需要任何数据结构**：没有嵌套、没有回溯，一个计数器加一个布尔就是全部状态。

## 5. 正确性证明

**引理 1（开关状态的对应）**：设前缀 $s[0..i]$ 中竖线的条数为 $t$。则处理完 $s[0..i]$ 后 $inPair = true$ 当且仅当 $t$ 为奇数。

**证明**：对扫描位置归纳。初始（空前缀）$t = 0$ 为偶数且 $inPair = false$，成立。设处理完 $s[0..i-1]$ 时命题成立。若 $s[i] \ne$ `|`，$t$ 与 $inPair$ 均不变，命题保持；若 $s[i] =$ `|`，$t$ 增加 1，同时 $inPair$ 取反——奇偶性互换，「$t$ 为奇数 ⇔ $inPair = true$」的等价关系依然保持。∎

**引理 2（门内判定的正确性）**：字符 $s[j]$ 处于某竖线对之内，当且仅当处理完 $s[0..j-1]$ 后 $inPair = true$。

**证明**：设 $s[0..j-1]$ 中竖线条数为 $t$，即 $s[j]$ 之前恰有 $t$ 条竖线。按配对规则，第 $2q-1$ 条与第 $2q$ 条竖线之间的字符在对内（$q = 1, 2, \dots$）。若 $t = 2q$ 为偶数，则 $s[j]$ 位于第 $q$ 对的关门之后、第 $q+1$ 对的开门之前，在对外，且由引理 1 $inPair = false$；若 $t = 2q-1$ 为奇数，则 $s[j]$ 位于第 $q$ 对的开门之后、关门之前，在对内，且 $inPair = true$。两方向均得证。∎

**定理**：算法返回的 $ans$ 恰等于「不在任何竖线对之间的 `*` 数目」。

**证明**：算法只在 `c == '*'` 且当前 $inPair = false$ 时累加。由引理 2，此条件恰等价于「该 `*` 位于所有竖线对之外」；反之每个满足条件的 `*` 恰被累加一次（每字符访问一次、判定互斥）。故 $ans$ 与目标计数一一对应。∎

## 6. 复杂度分析

- **时间**：$O(n)$，单趟扫描，每个字符常数次比较；$n \le 1000$，实际耗时微秒级。
- **空间**：$O(1)$ 额外空间（一个布尔量与一个计数器）；若采用 `split` 视角则为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countAsterisks(string s) {
        int ans = 0;
        bool inPair = false;                    // 当前是否位于某对竖线内部
        for (char c : s) {
            if (c == '|') inPair = !inPair;     // 每遇到一条竖线，进出状态翻转
            else if (c == '*' && !inPair) ++ans; // 只数竖线对之外的星号
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countAsterisks(self, s: str) -> int:
        ans = 0
        in_pair = False                     # 当前是否位于某对竖线内部
        for c in s:
            if c == '|':
                in_pair = not in_pair       # 每遇到一条竖线，进出状态翻转
            elif c == '*' and not in_pair:
                ans += 1                    # 只数竖线对之外的星号
        return ans
```

> 💡 两份代码均通过官方 3 个示例，并与「`split('|')` 取偶数下标段计数」的独立实现做了 400 组随机对拍（含连续竖线、竖线在首尾等边界），`mismatch = 0`。

## 8. 边界情况与易错点

1. **竖线总数为偶数**是题目保证，代码不必防御「落单竖线」；若去掉该保证（变体题），扫描结束时 $inPair$ 可能为 $true$，但星号判定逻辑依然自洽（末尾奇数段视为门内）。
2. **连续竖线 `||`**：两次翻转连在一起，中间形成「空的对」，不会计数任何字符——状态机天然正确。
3. **竖线在首尾**：`"|abc|"` 的门恰好包住整个 `abc`；`"abc|"`（配合总偶数条件实际是 `"abc||"` 之类）同样由状态机处理，无需特判。
4. **`split` 视角的下标陷阱**：切分段的奇偶下标对应门内外，若误写成 `[1::2]`（门内段）统计，答案会变成「门内星号数」，与目标恰好互补——用小样例（如 `"a|*|*"`）即可发现。
5. **不要用正则贪心配对**：`re` 匹配 `\|[^|]*\|` 逐对剔除虽然可行，但写法繁琐且性能更差，纯状态机更稳。
