# LeetCode 对字母串可执行的最大删除数 题解

## 1. 题目概述

- **标题 / 题号**：对字母串可执行的最大删除数（#2430，hard）
- **链接**：https://leetcode.cn/problems/maximum-deletions-on-a-string/
- **来源**：LeetCode 第 313 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、字符串哈希、最长公共前缀（LCP）、字符串匹配

**题意**：给定仅由小写字母组成的字符串 `s`。每一步操作二选一：

1. **删除整个字符串** `s`（之后为空，过程结束）；或
2. 选一个 $i$（$1 \le i \le |s|/2$），若 `s` 的**前 $i$ 个字母**与**紧随其后的 $i$ 个字母**完全相等，则**删除前 $i$ 个字母**。

注意相等比较的对象是**紧跟着的那一段**，不是任意后续出现（官方示例 1 特意强调了这一点：`"abcdabc"` 中不能再删 `"abc"`，因为第二次出现并不紧随其后）。返回把 `s` 完全删空所需的**最大**操作数。

**约束**：

- $1 \le n = |s| \le 4000$
- `s` 仅由小写英文字母组成

$n \le 4000$ 说明 $O(n^2) \approx 1.6 \times 10^7$ 的做法在预期内，可以放心预处理 $O(n^2)$ 级别的判定结构。

## 2. 示例

**示例 1**

```text
输入：s = "abcabcdabc"
输出：2
解释：删前 3 个 "abc"（s[0:3] == s[3:6]）→ 剩 "abcdabc"；再删整串。共 2 步。
      第二步不能再删 "abc"：它的下一次出现不紧随其后。
```

**示例 2**

```text
输入：s = "aaabaab"
输出：4
解释：删 "a" → "aabaab"；删 "aab" → "aab"；删 "a" → "ab"；删整串。共 4 步。
```

**示例 3**

```text
输入：s = "aaaaa"
输出：5
解释：每一步都只删第一个字母（'a' == 'a'），共 5 步。
```

**补充示例（贪心反例，见 3.2）**

```text
输入：s = "aaaa"
输出：4
解释：每步删 1 个：aaaa → aaa → aa → a → ∅，共 4 步。
      若每步贪心删最长的 j = 2：aaaa → aa → a → ∅，只有 3 步，不是最优。
```

## 3. 解题思路

### 3.1 暴力思路：后缀记忆化 + 逐字符比较

两种操作有一个共同点：**都只删前缀**（删整串是它的极端情形）。因此从 `s` 出发，任何时刻的剩余串都是原串的某个后缀 $s[l:]$，只需定义

$$dp[l] = \text{删空后缀 } s[l:] \text{ 所需的最大操作数}$$

转移为：要么一步删整串（贡献 $1$ 步），要么删一个合法的前 $j$ 个（要求 $s[l:l+j] = s[l+j:l+2j]$，$l + 2j \le n$），再转交给后缀 $s[l+j:]$：

$$dp[l] = \max\Bigl(1,\ \max_{\substack{1 \le j \le \lfloor (n-l)/2 \rfloor \\ s[l:l+j] = s[l+j:l+2j]}} \bigl(dp[l+j] + 1\bigr)\Bigr), \qquad dp[n] = 0$$

答案为 $dp[0]$。若判定 $s[l:l+j] = s[l+j:l+2j]$ 用逐字符比较，单次 $O(j)$：状态 $O(n)$ 个、每个枚举 $O(n)$ 个 $j$、每次比较 $O(n)$，总计 $O(n^3) \approx 6.4 \times 10^{10}$（$n = 4000$），必然超时。瓶颈在于**重复比较大量重叠子串**。

### 3.2 核心观察：状态一维 + 不能贪心

![核心观察：每步只删前缀，剩余串永远是原串的后缀，状态只剩左端点 l](images/wc313_q4_suffix_state_model.svg)

**观察一（状态设计）**：操作只删前缀，右端点恒为 $n$，左端点 $l$ 单调右移。剩余串由 $l$ 唯一决定，与「怎么走到 $l$」无关（无后效性），状态数 $O(n)$。一次合法的「删前 $j$ 个」等价于：当前开头恰是一个**平方串** $ww$（$w = s[l:l+j]$），删掉前一半 $w$。

**观察二（必须对所有 $j$ 取 max）**：步数与删掉的字符数无关，贪心两个方向都有反例：

![贪心反例：aaaa 上贪删最长只有 3 步；aaabaab 的 l=1 处贪删最短只有 2 步](images/wc313_q4_greedy_counter.svg)

- **贪「删最长」**：`"aaaa"` 上每步删 $j=2$ 只走 3 步，逐步删 1 个反而 4 步；
- **贪「删最短」**：`"aaabaab"` 在 $l=1$（后缀 `aabaab`）处，删 $j=1$ 得 $1 + dp[2] = 2$，删 $j=3$ 得 $1 + dp[4] = 3$——删得远可能恰好跳到一个「更耐删」的后缀。

所以只能老老实实枚举所有合法 $j$ 取 max，这就是 DP。

### 3.3 算法流程：倒序 DP + $O(1)$ 子串相等判定

![后缀图是 DAG：每条边 1 步，dp 即 DAG 最长路；判定用 LCP 表或滚动哈希压到 O(1)](images/wc313_q4_dp_transition_model.svg)

把每个后缀 $s[l:]$ 看成节点，$l \to l+j$（合法 $j$）与 $l \to n$（删整串）连边，每条边代价 1 步。边全部指向更大的 $l$，图是 **DAG**，$dp$ 就是 DAG 最长路，按 $l$ 从 $n-1$ 倒序到 $0$ 递推即可。

剩下的唯一瓶颈：把判定 $s[l:l+j] = s[l+j:l+2j]$ 从 $O(j)$ 压到 $O(1)$，两条路线：

- **LCP 二维表**（C++ 采用）：$\text{lcp}(a, b)$ 表示后缀 $s[a:]$ 与 $s[b:]$ 的最长公共前缀长度，满足递推
  $$\text{lcp}(a, b) = \begin{cases} 1 + \text{lcp}(a+1,\, b+1), & s[a] = s[b] \\ 0, & s[a] \ne s[b] \end{cases}$$
  倒序双循环 $O(n^2)$ 预处理整表（与 [718. 最长重复子数组](https://leetcode.cn/problems/maximum-length-of-repeated-subarray/) 的二维 DP 同源）。判定条件等价于 $\text{lcp}(l,\, l+j) \ge j$——公共前缀一旦达到 $j$，两段就逐位相等。
- **滚动哈希**（Python 采用）：预处理前缀哈希 $H[k]$（$s[:k]$ 的多项式哈希），任意子串哈希 $O(1)$：
  $$h\bigl(s[a:b]\bigr) = \bigl(H[b] - H[a] \cdot p^{\,b-a}\bigr) \bmod M$$
  判定即 $h(s[l:l+j]) = h(s[l+j:l+2j])$。用**双模数**把冲突概率压到可忽略（见 §8）。

**流程**：

1. 预处理：LCP 整表，或前缀哈希 + 幂表；
2. $l$ 从 $n-1$ 倒序到 $0$：$dp[l] \leftarrow 1$（删整串）；枚举 $j = 1 \dots \lfloor (n-l)/2 \rfloor$，判定通过则 $dp[l] \leftarrow \max(dp[l],\ dp[l+j] + 1)$；
3. 返回 $dp[0]$。

### 3.4 示例演算

![示例演算：s=aaabaab 从最短后缀倒推 dp，最优路径 0→1→4→5→∅ 共 4 步](images/wc313_q4_example_walkthrough.svg)

以示例 2 `s = "aaabaab"`（$n = 7$）为例，从最短的后缀开始倒推：

| $l$ | 后缀 $s[l:]$ | 合法 $j$（$\text{lcp}(l, l+j) \ge j$） | 转移 | $dp[l]$ |
|-----|--------------|----------------------------------------|------|---------|
| 6 | `b` | — | 删整串 | 1 |
| 5 | `ab` | — | 删整串 | 1 |
| 4 | `aab` | $j=1$（`a`=`a`） | $\max(1,\ 1+dp[5])$ | **2** |
| 3 | `baab` | — | 删整串 | 1 |
| 2 | `abaab` | — | 删整串 | 1 |
| 1 | `aabaab` | $j=1$，$j=3$（`aab`=`aab`） | $\max(1,\ 1+dp[2],\ 1+dp[4])$ | **3** |
| 0 | `aaabaab` | $j=1$（`a`=`a`） | $\max(1,\ 1+dp[1])$ | **4** |

最优路径 $0 \xrightarrow{j=1} 1 \xrightarrow{j=3} 4 \xrightarrow{j=1} 5 \xrightarrow{\text{删整串}} \varnothing$，共 4 步，与官方解释一致（`a` → `aab` → `a` → 删整串）。注意 $l=1$ 处弃 $j=1$ 取 $j=3$，正呼应 3.2 的反例。

## 4. 算法细节

1. **状态与转移**：$dp[l] = \max\bigl(1,\ \max_{\text{合法 } j}(dp[l+j]+1)\bigr)$，$dp[n] = 0$。「删整串」就是转移到空状态 $n$，贡献 $1 + dp[n] = 1$，可与匹配转移统一处理。
2. **枚举顺序**：$dp[l]$ 只依赖更大的下标 $dp[l+j]$，故 $l$ 从 $n-1$ 到 $0$ 倒序递推，一圈完成。
3. **LCP 表**：大小 $(n+1) \times (n+1)$，第 $n$ 行/列恒为 0（空后缀的公共前缀为 0），从 $i = j = n-1$ 倒序填表。判定 $s[l:l+j] = s[l+j:l+2j]$ 即查 $\text{lcp}[l][l+j] \ge j$，精确无冲突。空间 $(4001)^2$ 个 `int` 约 64 MB，可换 `unsigned short`（$\text{lcp} \le 4000 < 32768$）减半，或滚动成一行 $O(n)$（本站 [每日题解版](../../solution/2401-2500/2430_对字母串可执行的最大删除数.md) 即此写法）。
4. **滚动哈希**：基数 $B = 131$（大于字符集即可），双模数 $M_1 = 10^9{+}7$、$M_2 = 998244353$。子串哈希取 $H[b] - H[a] \cdot p^{b-a}$ 后对 $M$ 取模；**两个模数下都相等**才判定子串相等。Python 的 `%` 对负数天然返回非负值，可直接比较。
5. **$j$ 的上界**：$\lfloor (n-l)/2 \rfloor$，来自两个条件：题面 $i \le |s|/2$，以及「接下来的 $j$ 个字母」必须完整存在（$l + 2j \le n$）。

## 5. 正确性证明

**引理 1（后缀不变性）**：从 `s` 出发执行任意操作序列，任意时刻的剩余串都是原串的后缀 $s[l:]$（或空串）。

**证明**：对操作步数归纳。初始剩余为 $s[0:]$。设当前剩余为 $s[l:]$：执行「删整串」后为空；执行「删前 $j$ 个」后为 $s[l+j:]$（该操作要求 $s[l:l+j] = s[l+j:l+2j]$ 且 $l + 2j \le n$）。两种情形结论均成立。∎

**引理 2（操作序列与路径一一对应）**：把 `s` 完全删空的操作方案，与满足下述条件的结点序列 $0 = l_0 < l_1 < \cdots < l_k = n$ 一一对应：对每个 $t$，要么 $l_{t+1} = l_t + j_t$ 且 $s[l_t : l_{t+1}] = s[l_{t+1} : l_t + 2j_t]$、$l_t + 2j_t \le n$，要么 $l_{t+1} = n$（删整串）。且操作数 $= k$。

**证明**：操作只删除当前串的前缀。由引理 1，第 $t$ 步操作作用在后缀 $s[l_t:]$ 上：若是「删前 $j$ 个」，则合法条件恰为 $s[l_t : l_t + j] = s[l_t + j : l_t + 2j]$ 且 $l_t + 2j \le n$，执行后 $l_{t+1} = l_t + j$；若是「删整串」，执行后为空，即 $l_{t+1} = n$，且此后不再有操作（$l_k = n$ 为最后一项）。每步对应一条边，操作数即边数 $k$。反过来，任何满足条件的序列按边逐步执行都是合法方案。∎

**定理（转移方程）**：设 $D(l)$ 为删空 $s[l:]$ 的真实最大操作数，则 $D(n) = 0$，且对 $0 \le l < n$：

$$D(l) = 1 + \max\Bigl(0,\ \max_{\substack{1 \le j \le \lfloor (n-l)/2 \rfloor \\ s[l:l+j] = s[l+j:l+2j]}} D(l+j)\Bigr)$$

按该方程倒序递推得到的 $dp$ 数组满足 $dp[l] = D(l)$；特别地，算法输出 $dp[0]$ 为所求最大操作数。

**证明**：对 $l$ 从 $n$ 向 $0$ 归纳（等价于对后缀长度归纳），设对所有 $l' > l$ 已有 $dp[l'] = D(l')$。

**（下界，$\ge$）**：右式每个候选都对应一个真实方案——取 $j$ 使匹配条件成立时，先删前 $j$ 个（合法），再接「删空 $s[l+j:]$ 的最优方案」，由归纳假设共 $1 + D(l+j) = 1 + dp[l+j]$ 步；取 $0$（即删整串）则 1 步。故 $D(l) \ge$ 右式。

**（上界，$\le$）**：设删空 $s[l:]$ 的最优方案共 $D(l)$ 步。由引理 2，其第一步对应一条出边：删整串（则 $D(l) = 1 \le$ 右式，因右式 $\ge 1 + 0$）；或删前 $j$ 个（$j$ 满足匹配条件），其后半段是删空 $s[l+j:]$ 的某个方案，步数不超过 $D(l+j)$（最优性），故 $D(l) \le 1 + D(l+j) \le$ 右式。∎

**推论**：3.2 中两个方向的反例说明方程右端的 max 不可省略——任何只看单一 $j$ 的贪心都不满足定理。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。LCP 版：填表 $n^2 \approx 1.6 \times 10^7$ 次常数递推 + 主循环 $\sum_l \lfloor (n-l)/2 \rfloor \approx n^2/4 = 4 \times 10^6$ 次常数判定，实测 $n = 4000$ 约 0.05 s。哈希版：预处理 $O(n)$，主循环同样 $n^2/4$ 次判定，每次约 10 个整数运算，实测约 2 s。
- **空间复杂度**：LCP 表版 $O(n^2)$（`int` 约 64 MB，`unsigned short` 减半；滚动可到 $O(n)$）；哈希版 $O(n)$（四个长度 $n+1$ 的数组 + $dp$）。

## 7. 参考代码

### C++（LCP 二维表）

```cpp
class Solution {
public:
    int deleteString(string s) {
        int n = s.size();
        // lcp[i][j] = 后缀 s[i:] 与 s[j:] 的最长公共前缀长度，第 n 行/列恒为 0
        vector<vector<int>> lcp(n + 1, vector<int>(n + 1, 0));
        for (int i = n - 1; i >= 0; --i)
            for (int j = n - 1; j >= 0; --j)
                if (s[i] == s[j]) lcp[i][j] = lcp[i + 1][j + 1] + 1;
        // dp[i] = 删空后缀 s[i:] 的最大操作数，dp[n] = 0
        vector<int> dp(n + 1, 0);
        for (int i = n - 1; i >= 0; --i) {
            dp[i] = 1;                          // 删整串：1 步
            for (int j = 1; i + 2 * j <= n; ++j)
                if (lcp[i][i + j] >= j)         // s[i:i+j] == s[i+j:i+2j]
                    dp[i] = max(dp[i], dp[i + j] + 1);
        }
        return dp[0];
    }
};
```

### Python（双模数滚动哈希）

```python
class Solution:
    def deleteString(self, s: str) -> int:
        n = len(s)
        MOD1, MOD2, B = 1_000_000_007, 998_244_353, 131
        # 前缀哈希 h[k] = s[:k] 的哈希值，p[k] = B^k
        h1 = [0] * (n + 1)
        h2 = [0] * (n + 1)
        p1 = [1] * (n + 1)
        p2 = [1] * (n + 1)
        for k, c in enumerate(s):
            o = ord(c)
            h1[k + 1] = (h1[k] * B + o) % MOD1
            h2[k + 1] = (h2[k] * B + o) % MOD2
            p1[k + 1] = p1[k] * B % MOD1
            p2[k + 1] = p2[k] * B % MOD2
        dp = [0] * (n + 1)                      # dp[n] = 0（空串）
        for i in range(n - 1, -1, -1):
            best = 1                            # 删整串：1 步
            for j in range(1, (n - i) // 2 + 1):
                m = i + j
                # 子串哈希 h(s[a:a+j]) = h[a+j] - h[a]*p[j]，双模数都相等才判定相等
                if (h1[m] - h1[i] * p1[j]) % MOD1 == (h1[m + j] - h1[m] * p1[j]) % MOD1 \
                        and (h2[m] - h2[i] * p2[j]) % MOD2 == (h2[m + j] - h2[m] * p2[j]) % MOD2:
                    if dp[m] + 1 > best:
                        best = dp[m] + 1
            dp[i] = best
        return dp[0]
```

## 8. 边界情况与易错点

1. **$j$ 的上界差一**：必须 $l + 2j \le n$（「接下来的 $j$ 个」要完整存在）。写成 $l + j \le n$ 不会立刻WA（被截断的第二段长度不足 $j$，比较仍会失败），但会导致哈希数组 / LCP 表**下标越界**——Python 抛 `IndexError`，C++ 是未定义行为。例如 `"aaa"` 在 $l=0$ 处 $j$ 只能取 1。
2. **答案下界是 1**：任何非空串都能一步删整串，$dp[l]$ 初始化为 1；全无匹配（如 `"ab"`）或 $n = 1$ 时返回 1，无需特判。
3. **$dp[n] = 0$ 而不是 1**：空串不需要操作；误设为 1 会让「删整串」变成 2 步。
4. **贪心两个方向都错**：贪长（`"aaaa"` → 3 步）、贪短（`"aaabaab"` 的 $l=1$ → 2 步）均有反例（见 3.2），必须枚举全部合法 $j$ 取 max。
5. **比较对象是紧随其后的那段**：不是任意后续出现。官方示例 1 的注释即针对此易错点。
6. **LCP 表边界与内存**：表开 $(n+1) \times (n+1)$，第 $n$ 行/列恒 0，倒序填表；`int` 约 64 MB，紧张时换 `unsigned short` 或滚动数组。
7. **哈希防冲突**：单 $10^9$ 级模数在本题约 $4 \times 10^6$ 次判定下整体冲突风险约千分之几，且不排除针对性构造；双模数可降到 $10^{-12}$ 量级。C++ 还需注意负数取模要 `((x % M) + M) % M`（Python 的 `%` 天然非负）。
8. **Python 性能**：内层共约 $n^2/4 = 4 \times 10^6$ 次判定，写成纯列表索引 + 局部变量即可通过；避免在循环内做切片（每次切片是 $O(j)$ 的拷贝，会退化成 $O(n^3)$ 字节操作）。

**延伸思考**：

- **空间优化**：LCP 表按行滚动（依赖上一行 $\text{lcp}(l+1, \cdot)$）可降到 $O(n)$，代价是判定与滚动交错、代码细节变多（见每日题解版）。
- **$n$ 更大时**（如 $10^5$）：判定可用后缀数组 + ST 表做到 $O(1)$ 查任意 $\text{lcp}$，但枚举 $j$ 本身就是 $O(n)$，总量仍 $O(n^2)$。想真正低于平方，需要利用合法 $j$ 集合的周期结构——例如由 Fine–Wilf 定理可证同一位置的两个平方 $ww$、$ww'$（$|w| + |w'| - \gcd \le$ 重叠长度）会推出更短的平方，从而候选 $j$ 有稀疏结构，属于竞赛级进阶。
- **变体**：若求**最小**操作数，答案恒为 1（一步删整串），问题退化；若**禁止删整串**，则有些串永远删不空（如 `"ab"`），可问「判断能否删空 / 删空的最少与最多步数」，可达性与最值都需要重新设计 DP 初值（不可达记 $-\infty$）。
