# LeetCode 最小异或 题解

## 1. 题目概述

- **标题 / 题号**：最小异或（#2429，medium）
- **链接**：https://leetcode.cn/problems/minimize-xor/
- **来源**：LeetCode 第 313 场周赛 Q3
- **难度**：中等
- **标签**：贪心、位运算

**题意**：给定两个正整数 `num1` 和 `num2`，找出满足下述条件的正整数 `x`：

1. `x` 的**置位数**（二进制表示中 1 的个数）与 `num2` 相同；
2. `x XOR num1` 的值**最小**。

返回 `x`。题目保证 `x` 唯一确定。

**约束**：

- $1 \le \text{num1}, \text{num2} \le 10^9$

由 $10^9 < 2^{30}$ 可知两数都只占位 $0 \sim 29$，且 `num2` 的置位数 $c \le 29$（30 个 1 的最小值 $2^{30}-1 > 10^9$）——这保证了 30 个低位槽位一定够用。

## 2. 示例

**示例 1**

```text
输入：num1 = 3, num2 = 5
输出：3
解释：num1 = 0011，num2 = 0101（置位数 c = 2）。
      x = 3 = 0011 的置位数同为 2，且 3 XOR 3 = 0 是异或的最小可能值。
```

**示例 2**

```text
输入：num1 = 1, num2 = 12
输出：3
解释：num1 = 0001（k = 1），num2 = 1100（c = 2）。
      x = 3 = 0011 的置位数为 2，3 XOR 1 = 0010 = 2 最小。
```

**补充示例（c < k，需要删 1）**

```text
输入：num1 = 7, num2 = 4
输出：4
解释：num1 = 0111（k = 3），num2 = 0100（c = 1）。
      x 只能保留 1 个 1：保留最高的 bit2 得 x = 0100，7 XOR 4 = 3 最小。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有置位数等于 c 的 x

记 $c = \text{popcount}(\text{num2})$。合法的 `x` 是「恰好 $c$ 个 1」的正整数，候选是无穷集合（`x` 可以远大于 `num1`），即便限制在 30 位内，组合数 $\binom{30}{15} \approx 1.55 \times 10^8$ 也无法逐个求 XOR 取最小。必须利用 **XOR 的按位结构**。

### 3.2 核心观察：XOR 按位独立，问题变成「带权选位」

![按位代价模型：XOR 最小化转化为选位问题，num1 的 1 是负权、0 是正权](images/wc313_q3_bit_cost_model.svg)

异或的值可以**按位分解**：

$$x \oplus \text{num1} = \sum_{i:\, x_i \neq \text{num1}_i} 2^i$$

即每一位「失配」独立贡献 $2^i$，**位与位之间互不影响**。设 $S$ 为 `x` 的置位集合（$|S| = c$），总代价为：

$$\text{cost}(S) = \underbrace{\sum_{i \notin S,\ \text{num1}_i = 1} 2^i}_{\text{删掉 num1 的 1，每位付 } 2^i} + \underbrace{\sum_{i \in S,\ \text{num1}_i = 0} 2^i}_{\text{新添的 1，每位付 } 2^i}$$

把「与 num1 无关」的部分提出来，可改写成**常数 + 逐位权重**：

$$\text{cost}(S) = \text{num1} + \sum_{i \in S} w_i, \qquad w_i = \begin{cases} -2^i, & \text{num1}_i = 1 \\[2pt] +2^i, & \text{num1}_i = 0 \end{cases}$$

于是「最小化 XOR」变成：**从所有位中选恰好 $c$ 个，最小化权重和**——

- `num1` 的 1 位是**负权**（选中反而降低代价）→ 尽量多选；
- `num1` 的 0 位是**正权** → 必须选时从**低位**选起（$2^i$ 最小）。

对照 $k = \text{popcount}(\text{num1})$ 分三种情况：

| 情况 | 贪心策略 | 结果 |
|------|----------|------|
| $c = k$ | 负权位全选 | $x = \text{num1}$，XOR $= 0$（下界） |
| $c < k$ | 只能选 $c$ 个负权位 → **保留最高的 $c$ 个 1**，排除最低的 $k - c$ 个 | XOR $= $ 被排除的低位 1 之和 |
| $c > k$ | 负权位全选，再从 **0 位中由低到高**补 $c - k$ 个 1 | XOR $= $ 新添低位 1 之和 |

> 💡 一句话：**删 1 删低位（保留高位），补 1 补低位**。两种操作都往「便宜的位」上凑——失配的代价就是 $2^i$，永远优先牺牲小位。

### 3.3 算法流程

![贪心流程：第一遍从高位到低位保留 num1 的 1，第二遍从低位到高位补 0](images/wc313_q3_greedy_flow.svg)

1. 计算 $c = \text{popcount}(\text{num2})$，初始化 $x = 0$。
2. **第一遍（高位 → 低位）**：$i$ 从 29 扫到 0，若 num1 第 $i$ 位为 1 且 $c > 0$，则 $x$ 置位 $i$，$c \gets c - 1$。
3. 若 $c = 0$，直接返回 $x$。
4. **第二遍（低位 → 高位）**：$i$ 从 0 向上扫，若 $x$ 第 $i$ 位为 0，则置位并 $c \gets c - 1$，直到 $c = 0$。
5. 返回 $x$。

> ⚠️ 第二遍判空的对象是 **x 的当前位**而非 num1 的位：第一遍在 $c < k$ 时会排除部分 1 位，这些位在第二遍**不允许**再置位；判 $x$ 天然跳过所有已占用位，写法更安全。

### 3.4 示例演算

![示例演算：c > k 时补低位 0，c < k 时保留高位 1](images/wc313_q3_example_walkthrough.svg)

**示例 2**：num1 $= 0001$，num2 $= 1100$，$c = 2 > k = 1$：

| 步骤 | 操作 | $x$（bit3..0） | 剩余 $c$ |
|------|------|----------------|----------|
| 第一遍 $i = 3 \to 0$ | num1 的 1 在 bit0，置位 | $0001$ | $1$ |
| 第二遍 $i = 0$ | bit0 已占用，跳过 | $0001$ | $1$ |
| 第二遍 $i = 1$ | bit1 为 0，置位 | $0011$ | $0$ ✓ |

$x = 3$，XOR $= 0011 \oplus 0001 = 0010 = 2$ ✓

**补充示例**：num1 $= 0111$，num2 $= 0100$，$c = 1 < k = 3$：

| 步骤 | 操作 | $x$（bit3..0） |
|------|------|----------------|
| 第一遍 $i = 3 \to 0$ | 从高到低遇到的第一个 1 是 bit2，置位后 $c = 0$ | $0100$ |

$x = 4$，XOR $= 0111 \oplus 0100 = 0011 = 3$ ✓（任何只含 1 个 1 的 $x$ 中，bit2 的失配代价最小）

## 4. 算法细节

1. **popcount**：C++ 用 `__builtin_popcount`；Python 用 `bin(num2).count('1')`。
2. **扫描位数**：num1, num2 $\le 10^9 < 2^{30}$，第一遍扫 $i = 29 \cdots 0$ 即覆盖 num1 全部有效位。第二遍不设固定上界（`while c > 0`）：虽然由 $c \le 29$、位 $0 \sim 29$ 内恰有 $30 - k \ge c - k$ 个 0 位、理论上不会越界，但无上界写法对更大输入天然鲁棒。
3. **两遍方向相反的原因**：$c < k$ 时被排除的位付出 $2^i$，排除**低位**代价小，因此第一遍**从高位保留**；$c > k$ 时新增的位付出 $2^i$，选**低位**代价小，因此第二遍**从低位补**。
4. **两遍互不冲突**：第一遍只动 num1 的 1 位，第二遍只动 $x$ 的 0 位（即 num1 的 0 位及更高空位），职责天然分离，无需回退。
5. **x 可能大于 num1**：$c > k$ 时补位可能超出 num1 的最高位（如 num1 $= 1$，$c = 2$ 时 $x = 3$），题目对 $x$ 的大小无约束，只要置位数匹配即可。

## 5. 正确性证明

**引理 1（按位分解）**：对任意非负整数 $a, b$，有 $a \oplus b = \sum_{i:\, a_i \neq b_i} 2^i$。

**证明**：异或按位独立运算：第 $i$ 位相同则结果该位为 0，不同则为 1，即该位对数值的贡献恰为 $2^i$。∎

**引理 2（代价改写）**：设 $S$ 为 $x$ 的置位集合且 $|S| = c$，则 $\text{cost}(S) = \text{num1} + \sum_{i \in S} w_i$，其中 $w_i = -2^i$（num1 第 $i$ 位为 1）或 $+2^i$（为 0）。

**证明**：由引理 1，

$$\text{cost}(S) = \sum_{i \notin S,\, \text{num1}_i = 1} 2^i + \sum_{i \in S,\, \text{num1}_i = 0} 2^i = \underbrace{\sum_{i:\,\text{num1}_i = 1} 2^i}_{=\ \text{num1}} - \sum_{i \in S,\, \text{num1}_i = 1} 2^i + \sum_{i \in S,\, \text{num1}_i = 0} 2^i = \text{num1} + \sum_{i \in S} w_i. \;\blacksquare$$

**定理**：贪心解——保留 num1 最高的 $\min(c, k)$ 个 1；若 $c > k$，再在 0 位中由低到高补 $c - k$ 个 1——是唯一最优解。

**证明**：由引理 2，只需在所有 $|S| = c$ 的集合中最小化 $\sum_{i \in S} w_i$。记负权位集合 $N = \{i : \text{num1}_i = 1\}$（$|N| = k$），正权位集合 $P = \{i : \text{num1}_i = 0\}$。

**情形一 $c \le k$**：设某解 $S$ 含正权位 $j \in P$ 但不含负权位 $i \in N$。用 $i$ 替换 $j$ 后权和变化 $w_i - w_j = -2^i - 2^j < 0$，严格更优。故最优解不含任何正权位，即 $S \subseteq N$。此时被排除的 $N \setminus S$ 共 $k - c$ 个位，每个被排除的位 $i$ 使代价相对下界多出 $2^i$（少减了 $2^i$），排除**最低**的 $k - c$ 个 1 位代价最小，即保留最高的 $c$ 个 1——恰为贪心解。

**情形二 $c > k$**：若 $S$ 不含某负权位 $i \in N$ 却含某正权位 $j \in P$，同样的替换使权和严格下降，矛盾。故最优解 $S \supseteq N$；剩余 $c - k$ 个位取自 $P$，每个付出 $+2^i$，取**最低**的 $c - k$ 个 0 位代价最小——恰为贪心解。

**唯一性**：不同位置的权重绝对值 $2^i$ 两两不同，且任何负权严格优于任何正权，故上述选择集唯一，最优 $x$ 唯一（与题目「$x$ 唯一确定」呼应）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(B)$，$B$ 为扫描位宽（本题取 30，常数级）。两遍扫描各至多 $B$ 次，每次 $O(1)$ 位判断与置位。若视为通用 $\log$ 级算法，则为 $O(\log \text{num1} + \log \text{num2})$。
- **空间复杂度**：$O(1)$，只使用常数个整数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimizeXor(int num1, int num2) {
        int c = __builtin_popcount((unsigned)num2);
        int x = 0;
        // 第一遍：高位 → 低位，贪心保留 num1 的高位 1
        for (int i = 29; i >= 0 && c > 0; --i) {
            if ((num1 >> i) & 1) {
                x |= 1 << i;
                --c;
            }
        }
        // 第二遍：低位 → 高位，把多余的 1 放到最低的 0 位
        for (int i = 0; c > 0; ++i) {
            if (!((x >> i) & 1)) {
                x |= 1 << i;
                --c;
            }
        }
        return x;
    }
};
```

### Python

```python
class Solution:
    def minimizeXor(self, num1: int, num2: int) -> int:
        c = bin(num2).count('1')
        x = 0
        # 第一遍：高位 → 低位，贪心保留 num1 的高位 1
        for i in range(29, -1, -1):
            if c == 0:
                break
            if (num1 >> i) & 1:
                x |= 1 << i
                c -= 1
        # 第二遍：低位 → 高位，把多余的 1 放到最低的 0 位
        i = 0
        while c > 0:
            if not (x >> i) & 1:
                x |= 1 << i
                c -= 1
            i += 1
        return x
```

## 8. 边界情况与易错点

1. **目标是 XOR 最小，不是 x 最小**：示例 2 中 $x = 3 > \text{num1} = 1$。若误把「最小 x」当目标，会偏向把 1 堆在低位而破坏与 num1 高位的匹配。
2. **c 与 k 别数错对象**：约束条件落在 `x` 上的置位数 $c$ 来自 **num2**；$k = \text{popcount}(\text{num1})$ 只用于分析。混淆两者是 WA 高发点。
3. **第二遍判空对象是 x**：$c < k$ 时第一遍会排除 num1 的部分 1 位（低位），这些位第二遍不能再置位；判 `x` 的当前位可天然避开，判 num1 的位则会错。
4. **c == k 是「免费的完美匹配」**：此时 $x = \text{num1}$、XOR $= 0$，代码无需特判，两遍扫描自动退化为此结果。
5. **位宽与越界**：第一遍上界取 29（num1 $< 2^{30}$）；第二遍用无上界循环更鲁棒。由 $c \le 29$ 可证 30 个低位槽位必够，但通用写法不依赖该证明。
6. **溢出**：$x < 2^{30}$，C++ `int` 安全；`1 << i` 在 $i \le 29$ 时无符号溢出问题。
