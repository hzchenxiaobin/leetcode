# LeetCode 成本最小路径 题解

## 1. 题目概述

- **标题 / 题号**：成本最小路径（#656，hard）
- **链接**：https://leetcode.cn/problems/coin-path/
- **来源**：LeetCode 第 44 场周赛 Q4
- **难度**：困难
- **标签**：数组, 动态规划

**题意**：给定长度为 $n$ 的数组 `coins`（下标从 1 开始）与最大步长 $maxJump$。你是站在下标 1 上的棋子，每次可以从下标 $i$ 跳到 $i+1, i+2, \ldots, i+maxJump$ 中任一位置；**落到下标 $i$ 就要支付 $coins[i]$ 枚硬币**（起点与终点都要付）。若 $coins[i] = -1$，该位置不可落脚（但可以一步跨过它）。求从 1 走到 $n$ 的**花费最小**的下标序列；若有多条花费相同的路径，返回**字典序最小**的那条；无法到达则返回空数组。

> 💡 **字典序的定义**：路径 $P_{a_1},\ldots,P_{a_p}$ 小于 $P_{b_1},\ldots,P_{b_q}$，当且仅当在第一个满足 $P_{a_i} \ne P_{b_i}$ 的位置 $i$ 上有 $P_{a_i} < P_{b_i}$。注意它**不是**「步数最少」，而是逐位比下标大小——这是本题最容易写错的地方。

**约束**：

- $1 \le n \le 1000$
- $1 \le maxJump \le 100$
- $coins[1] \ge 0$；对 $i \ge 2$ 有 $coins[i] \in [-1, 100]$，其中 $-1$ 表示该位置**不可落脚**（本解额外兼容 $coins[1] = -1$，此时无解返回空数组）

## 2. 示例

**示例 1**

```text
输入：coins = [1,2,4,-1,2], maxJump = 2
输出：[1,3,5]
解释：路径 1→3→5 花费 1 + 4 + 2 = 7；
      1→2→3→5 花费 1 + 2 + 4 + 2 = 9，更贵；
      1→2→5 跨度为 3，超过 maxJump 不合法；
      下标 4 是 -1 不可落脚，但可以从 3 一步跨过去。
```

**示例 2**

```text
输入：coins = [1,2,4,-1,2], maxJump = 1
输出：[]
解释：每次只能前进 1 步，必须经过下标 4，而它是 -1，无法到达下标 5。
```

**示例 3（补充）**

```text
输入：coins = [0,0,0], maxJump = 2
输出：[1,2,3]
解释：[1,2,3] 与 [1,3] 花费都是 0；第一个不同位置是第 2 个元素，2 < 3，
      故 [1,2,3] 字典序更小——同花费时必须选「更小步」的那条。
```

## 3. 解题思路

### 3.1 暴力思路

直接 DFS 枚举所有合法路径：每一步最多 $maxJump$ 个分支，路径最多 $n$ 个点，最坏枚举量 $O(maxJump^{\,n})$。$n = 1000$ 时是天文数字，完全不可行。

即使只求最小花费，枚举也浪费：**同一条后缀会被无数条前缀重复访问**。注意到「下标严格递增」使整张状态图是一个 DAG，而花费又是**可加且非负**的，于是「从 $i$ 走到 $n$ 的最小花费」与「如何走到 $i$」无关——这正是 DP 的标准前提。

### 3.2 核心观察：反向 DP，把「还要付多少」作为状态

![反向 DP 模型：dp[i] 表示从 i 走到 N 的最小花费](images/wc44_q4_dp_model.svg)

**关键定义**：令 $dp[i]$ 表示「从下标 $i$ 出发走到 $n$ 的最小总花费」，其中**包含落脚 $i$ 时支付的 $coins[i]$**，也包含终点的 $coins[n]$。于是终点是唯一答案已知的位置：

$$dp[n] = coins[n], \qquad dp[i] = coins[i] + \min_{i < j \le \min(n,\, i+maxJump)} dp[j]$$

其中若 $coins[i] = -1$，或窗口内所有 $dp[j]$ 都不可达，则令 $dp[i] = +\infty$。

**为什么从右往左**：转移只依赖**右侧**的 $dp$ 值。若从左往右定义「到达 $i$ 的最小花费」，虽然也能算，但字典序信息全丢了——你必须额外记录路径才能比较；而反向定义配合下面的贪心重建，$O(n)$ 空间就够了。

> 💡 **字典序的关键性质**：所有最优路径的花费相同，因此**第一个分岔口**就决定了字典序大小。只要每一步都选「最小可行下标」，整条路径就字典序最小。这个贪心之所以成立，是因为下标越小越靠前，与后续选择无关。

### 3.3 算法流程 / 状态转移

![算法流程：倒序 DP + 贪心重建](images/wc44_q4_transition_flow.svg)

1. **初始化**：$dp[n] = coins[n]$（若 $coins[n] = -1$，则 $dp[n] = +\infty$，全题无解）。
2. **倒序转移**：$i$ 从 $n-1$ 递减到 $1$。若 $coins[i] = -1$ 则跳过（保持 $+\infty$）；否则在窗口 $j \in (i,\ \min(n, i+maxJump)]$ 内取最小的 $dp[j]$，令 $dp[i] = coins[i] + \min$。
3. **无解判定**：若 $dp[1] = +\infty$，直接返回空数组。
4. **贪心重建**：$cur = 1$，路径为 $[1]$；当 $cur \ne n$ 时，在窗口内**从小到大**扫，找到第一个满足
   $$dp[j] + coins[cur] = dp[cur]$$
   的 $j$（这样的 $j$ 必然存在），令 $cur = j$ 并把 $cur$ 加入路径。
5. **返回**路径（全程 1-based 输出）。

### 3.4 示例演算

![示例演算：coins = [1,2,4,-1,2]、maxJump = 2 的 DP 表与重建](images/wc44_q4_walkthrough.svg)

对 `coins = [1,2,4,-1,2]`、$maxJump = 2$：

| $i$ | $coins[i]$ | 窗口内候选 $dp$ | $dp[i]$ | 说明 |
|-----|-----------|-----------------|---------|------|
| 5 | 2 | 无（终点） | 2 | 基准 |
| 4 | $-1$ | — | $+\infty$ | 不可落脚 |
| 3 | 4 | $dp[4]=\infty,\ dp[5]=2$ | 6 | 只能走 $3 \to 5$ |
| 2 | 2 | $dp[3]=6,\ dp[4]=\infty$ | 8 | 必须经过 3 |
| 1 | 1 | $dp[2]=8,\ dp[3]=6$ | 7 | 走 3 更便宜 |

重建：从 1 出发，窗口 $\{2,3\}$ 中 $dp[2] + 1 = 9 \ne 7$，$dp[3] + 1 = 7 = dp[1]$，取 $j = 3$；从 3 出发，窗口 $\{4,5\}$ 中 $dp[4] = \infty$，$dp[5] + 4 = 6 = dp[3]$，取 $j = 5$。得到 $[1,3,5]$，花费 7。

对照被淘汰的 $[1,2,3,5]$：下标 2 的硬币只有 2，看起来比 4 便宜，但它**离终点更远且被迫经过两个点**，总花费反而是 9。这说明局部贪心（每步选最便宜的落点）是错的，必须靠 DP 看「剩余花费」。

## 4. 算法细节

1. **维度与下标**：题面 1-based、代码 0-based。$dp$ 与 `coins` 统一用 0-based，重建时输出 `i + 1`，避免两套下标混用。
2. **无穷大的选取**：C++ 用 `const long long INF = (long long)1e18`，Python 用 `float('inf')`；必须**先判 `best < INF` 再相加**，否则会算出 `INF + coins` 这类污染值（`int` 下甚至会溢出成负数）。
3. **窗口右端要夹住**：$j$ 的范围是 $i+1 \sim \min(n-1,\ i+maxJump)$。当 $maxJump \ge n$ 时整段可达，忘记夹 $\min$ 会数组越界。
4. **窗内取「最小值」而非「第一个可达值」**：重建时扫到的第一个 $dp[j] < \infty$ 的 $j$ 未必是最便宜的，必须让 $dp[j] + coins[cur] = dp[cur]$ 成立；反之，凡满足该等式的 $j$ 都在某条最优路径上。
5. **并列时取最小下标**：窗口内可能有两个 $j$ 都满足等式（硬币为 0 时尤其常见），此时取**下标较小**的那个，这就是字典序贪心。
6. **滑动窗口可再优化**：转移本质是「窗口最小值」，用单调队列可做到 $O(n)$ 总时间。但本题 $n \le 1000$、$maxJump \le 100$，$O(n \cdot maxJump) = 10^5$ 的双重循环更短、更不容易写错，是规模下的正确取舍。
7. **`-1` 的双重含义**：既不能作为落点（$dp = \infty$），也不能作为起点（第 1 位为 $-1$ 时 $dp[1] = \infty$）；同时它**不阻断跨越**——只要跳跃跨度够，可以一步跳过。
8. **终点特判先于一切**：若 $coins[n-1] = -1$，$dp[n-1]$ 恒为 $\infty$，所有转移自然失败，无需额外分支，但要知道这是「无解」而非「越界」。

## 5. 正确性证明

**引理 1（最优子结构）**：对任意可落脚的下标 $i$，$dp[i]$ 等于所有「从 $i$ 出发、落到 $n$ 且中途不踩 $-1$」的路径花费的最小值。

**证明**：对 $n - i$ 作强归纳。$i = n$ 时路径只能是 $[n]$，花费 $coins[n]$，成立。设对 $i+1, \ldots, n$ 均成立，则任意从 $i$ 出发的合法路径第一步必落到某个 $j \in (i,\ \min(n, i+maxJump)]$，其后是从 $j$ 到 $n$ 的合法路径，总花费为 $coins[i] + \text{cost}(j \to n)$；反过来，任一 $j$ 的最优后缀拼上 $i$ 也构成合法路径。故
$$dp[i] = coins[i] + \min_{j} dp[j],$$
由归纳假设该式恰为全局最小花费。∎

**引理 2（候选集非空且都在最优解上）**：若 $dp[i] < \infty$，则 $S_i = \{\, j : i < j \le \min(n, i+maxJump),\ dp[j] + coins[i] = dp[i] \,\}$ 非空，且对任意 $j \in S_i$ 都存在一条经过边 $i \to j$ 的从 $i$ 出发的最优路径。

**证明**：由引理 1，$dp[i]$ 是窗口内某个 $dp[j]$ 加上 $coins[i]$ 取到的，故 $S_i$ 非空。取 $j \in S_i$：由引理 1，从 $j$ 存在花费为 $dp[j]$ 的最优后缀 $j \to \cdots \to n$；把它接在 $i \to j$ 之后，总花费 $coins[i] + dp[j] = dp[i]$，即为最佳。∎

**引理 3（每步取最小下标 ⇒ 字典序最小）**：设 $j^{\ast} = \min S_i$，路径 $P^{\ast}$ 从 $i$ 出发按「每步取当前最小可行下标」构造。则对任意从 $i$ 出发的最优路径 $P$，都有 $P^{\ast} \le_{\text{lex}} P$。

**证明**：对 $P$ 的长度作强归纳。设 $P$ 首步为 $j \in S_i$，由 $j^{\ast} = \min S_i$ 得 $j^{\ast} \le j$。若 $j^{\ast} < j$，两条路径除起点外第一个元素就不同，且 $j^{\ast} < j$，故 $P^{\ast} \le_{\text{lex}} P$；若 $j^{\ast} = j$，首步相同，去掉起点后 $P$ 的剩余部分是从 $j$ 出发的最优路径，由归纳假设 $P^{\ast}$ 的剩余部分字典序不劣于它，故 $P^{\ast} \le_{\text{lex}} P$。∎

**定理**：算法返回的路径合法、花费等于 $dp[1]$（即最小花费），且在最小花费的路径中字典序最小；若 $dp[1] = \infty$，返回空数组正确。

**证明**：$dp[1] = \infty$ 时由引理 1 不存在合法路径，返回空数组正确。否则每次重建都从 $S_i$ 中取点，由引理 2 候选非空且落在最优路径上，下标严格递增，至多 $n$ 步必达 $n$，故路径合法；又每步都有 $dp[cur] - dp[j] = coins[cur]$，沿路径逐项相消得总花费
$$\sum_k coins[i_k] = dp[1] - dp[n] + coins[n] = dp[1],$$
即恰为最小花费。字典序最小性由引理 3。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot maxJump)$。倒序 DP 每个位置扫一次长度 $maxJump$ 的窗口，共 $O(n \cdot maxJump)$；重建最多 $n$ 步、每步 $O(maxJump)$。$n = 1000$、$maxJump = 100$ 时约 $10^5$ 次操作。
- **空间**：$O(n)$。仅一个 `dp` 数组；答案路径长度不超过 $n$。若改用单调队列，时间可降到 $O(n)$，但空间仍为 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> cheapestJump(vector<int>& coins, int maxJump) {
        int n = coins.size();
        const long long INF = (long long)1e18;
        vector<long long> dp(n, INF);
        if (coins[n - 1] != -1) dp[n - 1] = coins[n - 1];

        // 反向 DP：dp[i] = coins[i] + 窗口内最小的 dp[j]
        for (int i = n - 2; i >= 0; --i) {
            if (coins[i] == -1) continue;
            long long best = INF;
            int hi = min(n - 1, i + maxJump);
            for (int j = i + 1; j <= hi; ++j)
                if (dp[j] < best) best = dp[j];
            if (best < INF) dp[i] = coins[i] + best;
        }

        if (dp[0] >= INF) return {};

        // 贪心重建：每步取最小的、仍能保持最优代价的下标
        vector<int> path{1};
        int i = 0;
        while (i != n - 1) {
            int hi = min(n - 1, i + maxJump);
            int nxt = -1;
            for (int j = i + 1; j <= hi; ++j) {
                if (dp[j] < INF && dp[j] + coins[i] == dp[i]) { nxt = j; break; }
            }
            i = nxt;
            path.push_back(i + 1);
        }
        return path;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def cheapestJump(self, coins: List[int], maxJump: int) -> List[int]:
        n = len(coins)
        INF = float('inf')
        dp = [INF] * n
        if coins[-1] != -1:
            dp[-1] = coins[-1]

        # 反向 DP：窗口内取最小 dp 值
        for i in range(n - 2, -1, -1):
            if coins[i] == -1:
                continue
            best = INF
            for j in range(i + 1, min(n, i + maxJump + 1)):
                if dp[j] < best:
                    best = dp[j]
            if best < INF:
                dp[i] = coins[i] + best

        if dp[0] == INF:
            return []

        # 贪心重建：从小到大找第一个「代价匹配」的下标
        path, i = [1], 0
        while i != n - 1:
            nxt = -1
            for j in range(i + 1, min(n, i + maxJump + 1)):
                if dp[j] < INF and dp[j] + coins[i] == dp[i]:
                    nxt = j
                    break
            i = nxt
            path.append(i + 1)
        return path
```

## 8. 边界情况与易错点

1. **$n = 1$**：起点即终点，应返回 `[1]`（只支付 $coins[1]$）。重建循环写成 `while (cur != n)` 才自然正确；若先无条件「跳一步」再判断，单点输入会越界或误返 `[]`。
2. **终点不可落脚**：`coins[n-1] = -1` 时无解，返回 `[]`。此时 DP 里 $dp[n-1] = \infty$，所有转移自动失败，不要误以为越界。
3. **步长为 1 且途中有 $-1$**：如示例 2，整条链被截断，返回 `[]`。
4. **全 $0$ 硬币（大量并列最优）**：字典序要求「尽量小步走」。`coins = [0,0,0]`、$maxJump = 2$ 的答案是 `[1,2,3]` 而非更短的 `[1,3]`——按步数选会错。
5. **重建取了「第一个可达」而非「代价匹配」**：只有 $dp[j] + coins[cur] = dp[cur]$ 的 $j$ 才能拼接出最优解，随便取一个可达下标会得到更贵路径。
6. **并列候选未取最小下标**：窗口内多个 $j$ 满足等式时（硬币为 0 时常见），必须取最小的那个，否则字典序变大。
7. **无穷大参与加法**：C++ 若用 `int` 且 `INF = INT_MAX`，`INF + coins` 会溢出成负数，导致「不可达」被误判为「很便宜」。
8. **输出下标偏移**：题面 1-based，若重建时直接 `push_back(i)`，答案整体错一位。
