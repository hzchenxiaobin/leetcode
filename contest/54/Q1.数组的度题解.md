# LeetCode 数组的度 题解

## 1. 题目概述

- **标题 / 题号**：数组的度（#697，easy）
- **链接**：https://leetcode.cn/problems/degree-of-an-array/
- **来源**：LeetCode 第 54 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定非空数组 `nums`，其**度**定义为任一元素出现频次的最大值 $D$。要求找出一个**连续子数组**，使它的度也等于 $D$，并返回满足条件的**最短**子数组长度。

**约束**：

- $1 \le \textit{nums}.\text{length} \le 5 \times 10^4$
- $0 \le \textit{nums}[i] \le 49999$
- 数组只含非负整数，且保证非空（答案必然存在）

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,3,1]
输出：2
解释：度为 2，因为 1 和 2 各出现 2 次。
      度同为 2 的子数组有：[1,2,2,3,1]、[1,2,2,3]、[2,2,3,1]、
      [1,2,2]、[2,2,3]、[2,2]，最短的是 [2,2]，长度 2。
```

**示例 2**

```text
输入：nums = [1,2,2,3,1,4,2]
输出：6
解释：度为 3（元素 2 出现 3 次）；包含这 3 次出现的最短区间是
      [2,2,3,1,4,2]（下标 1..6），长度 6。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有连续子数组（共 $\frac{n(n+1)}{2}$ 个），对每个子数组重新统计频次求度，与 $D$ 比较后取最短长度：时间 $O(n^3)$。即使把统计做成「右端点每扩一格就增量更新」，仍有 $O(n^2)$ 次频次更新，$n = 5\times 10^4$ 时约 $1.25\times 10^9$ 次操作，必然超时。

前缀和、滑动窗口等线性技巧在这里都用不上：**「度」不是可减的度量**，窗口收缩时最高频次可能保持不变、也可能骤降，无法像「和」「不同数个数」那样靠单调性判定窗口该不该动。

### 3.2 核心观察：同度子数组 = 某个度元素的 first..last 区间

![同度子数组由度元素的首末出现位置定界](images/wc54_q1_span_concept.svg)

设元素 $x$ 在原数组中出现了 $\text{cnt}(x)$ 次，首次、末次出现的下标为 $\text{first}(x)$、$\text{last}(x)$，记它的**跨度**为

$$\text{span}(x) = \text{last}(x) - \text{first}(x) + 1$$

关键观察有三点：

1. 一个子数组的任一元素出现次数都**不超过**它在原数组中的出现次数，所以子数组的度 $\le D$。想让度恰好等于 $D$，必须让**某个频次为 $D$ 的元素 $x$ 全部出现**都落在子数组内。
2. 包含 $x$ 全部出现位置的最短区间，就是首末出现之间那一段 $[\text{first}(x), \text{last}(x)]$，长度恰为 $\text{span}(x)$——再短必漏掉一次出现，度就掉到 $D-1$。
3. $x$ 也可以出现在比 $\text{span}(x)$ 更宽的区间里，但那只会更长，不会更优。

于是问题从「枚举子数组」塌缩成「**枚举候选元素**」：

$$\text{答案} = \min_{\text{cnt}(x) = D} \text{span}(x)$$

> 💡 一句话：**度是频次的上界，跨度是位置的下界**。求出度、再对号入座取最小跨度即可，全程只需要一次扫描。

### 3.3 算法流程与状态转移

![一次遍历：建表 + 同步维护 degree 与 ans](images/wc54_q1_algorithm_flow.svg)

三张哈希表 `cnt`、`first`、`last` 一次扫描即可同时填好；更进一步，**不必等扫描结束再找最小值**，可以在扫描中同步维护：

```text
输入：nums（长度 n）
1. degree ← 0，ans ← n
2. for i ← 0 to n−1:
3.     x ← nums[i]
4.     if x 首次出现: first[x] ← i
5.     last[x] ← i，cnt[x] ← cnt[x] + 1，c ← cnt[x]
6.     span ← last[x] − first[x] + 1
7.     if c > degree:  degree ← c，ans ← span        # 新度只可能由 x 达成
8.     elif c = degree: ans ← min(ans, span)          # 同度候选，取更短
9. 返回 ans
```

第 7、8 行的分支就是整个算法的状态转移：

$$\text{ans} \leftarrow \begin{cases} \text{span}, & c > \text{degree} \\ \min(\text{ans}, \text{span}), & c = \text{degree} \\ \text{ans}, & c < \text{degree} \end{cases}$$

注意 $c > \text{degree}$ 时是**覆盖**而不是取 $\min$：旧 `ans` 对应的元素频次已经低于新度，全部作废。

### 3.4 示例演算

![示例逐位置走查：degree 与 ans 如何变化](images/wc54_q1_walkthrough.svg)

对 `nums = [1,2,2,3,1]`：

- $i=0$：读入 1，`cnt[1]=1`，跨度 1，$1 > 0$ 使 `degree=1`、`ans=1`。
- $i=1$：读入 2，`cnt[2]=1`，跨度 1，$1 = 1$ 时 $\min(1,1)=1$，不改变答案。
- $i=2$：再读入 2，`cnt[2]=2`，跨度 2，$2 > 1$ 使 `degree=2`、`ans=2`。
- $i=3$：读入 3，`cnt[3]=1`，跨度 1，$1 < 2$ 直接跳过。
- $i=4$：再读入 1，`cnt[1]=2`，跨度 5，$2 = 2$ 时 $\min(2,5)=2$，**答案保持 2**。

最终 `ans = 2`，对应子数组 `[2,2]`。第 8 行的 $\min$ 在本例中没有改变结果，但用来排除「后出现的同度元素更紧凑」时会漏掉的解：对 `[5,4,3,2,1,5,7,6,8,8]`，元素 5 在 $i=5$ 时先让度升到 2（跨度 6），元素 8 在 $i=9$ 时同度但跨度只有 2，答案应为 2——只保留首个候选就会错答 6。

## 4. 算法细节

1. **三张表各司其职**：`cnt` 回答「频次够不够 $D$」，`first`/`last` 回答「跨度多大」。三者缺一不可——只有 `cnt` 求不出长度，只有首末求不出度。
2. **首次出现的判定要在 `last` 更新之前**：用「`first` 中不存在 $x$」判断，而不是用 `cnt[x] == 0` 顺手写反顺序；两者等价但前者更不容易写错（先写 `if x not in first: first[x] = i`）。
3. **`degree` 从 0 起步、`ans` 从 $n$ 起步**：$i=0$ 时必然触发 $1 > 0$ 分支，`ans` 被立刻修正为 1，所以初值只要是个不小于真实答案的数即可；用 $n$ 最自然，也天然覆盖「所有元素互不相同」的情形。
4. **可以用桶代替哈希表**：值域是 $[0, 49999]$，直接开 `cnt[50000]`、`first[50000]`（初值 $-1$）、`last[50000]`，把 $O(1)$ 的哈希开销换成数组下标，常数小 3～5 倍；但**数组大小要写 50000**（下标 $49999$ 合法），写成 `49999` 会越界。
5. **两个等价写法**：先完整扫一遍三张表，再遍历所有键取 $\min$（两遍，思路最直白）；或如上单遍维护 `degree/ans`（少一次遍历）。两者复杂度同阶，单遍版对「流式输入」也能直接用。
6. **不要排序**：排序会打乱下标，`first`/`last` 随之失效；本题只需要位置信息，$O(n\log n)$ 的排序纯属自找麻烦。
7. **溢出与类型**：频次与下标都在 $5\times10^4$ 以内，`int` 足够；`last - first + 1` 不会为负（因为 `last >= first`），无需特殊处理。

## 5. 正确性证明

**引理 1（跨度是包含全部出现的最短长度）**：对任意元素 $x$，任何包含 $x$ 全部 $\text{cnt}(x)$ 次出现的子数组长度不小于 $\text{span}(x)$；而 $[\text{first}(x), \text{last}(x)]$ 恰好包含全部出现，长度等于 $\text{span}(x)$。

**证明**：设子数组 $[l, r]$ 包含 $x$ 的全部出现，则 $l \le \text{first}(x)$ 且 $r \ge \text{last}(x)$，故 $r-l+1 \ge \text{last}(x)-\text{first}(x)+1 = \text{span}(x)$。另一方面，$x$ 的每次出现都在 $[\text{first}(x), \text{last}(x)]$ 内，故该区间包含全部出现，长度正是 $\text{span}(x)$。∎

**引理 2（同度子数组的刻画）**：子数组 $A$ 的度等于 $D$ 当且仅当存在某元素 $x$ 使 $\text{cnt}(x) = D$ 且 $A$ 包含 $x$ 的全部出现。

**证明**：

- ($\Leftarrow$) 若 $A$ 包含 $x$ 的全部 $D$ 次出现，则 $A$ 的度 $\ge D$；又 $A$ 中任一元素的出现次数不超过它在原数组中的次数，即不超过 $D$，故 $A$ 的度恰为 $D$。
- ($\Rightarrow$) 若 $A$ 的度为 $D$，取 $A$ 中达到该度的元素 $x$，则 $A$ 中 $x$ 出现 $D$ 次。而原数组中 $x$ 至多出现 $D$ 次（$D$ 是全局最大值），故 $x$ 的全部出现都在 $A$ 内，且 $\text{cnt}(x) = D$。∎

**引理 3（单遍不变式）**：处理完前 $i+1$ 个位置后，记 $\text{degree}_i$ 为前缀中的最大频次，则 `ans` 恒等于 $\min\{\text{span}_i(x) : \text{cnt}_i(x) = \text{degree}_i\}$，其中 $\text{span}_i(x) = \text{last}_i(x) - \text{first}_i(x) + 1$。

**证明**：对 $i$ 归纳。$i=0$ 时 `degree=1`、`ans=1`，仅有的元素满足条件。设处理到第 $i$ 个位置、读入 $x$ 后频次为 $c$：

- 若 $c > \text{degree}_{i-1}$：前缀最大频次只可能由 $x$ 取得，$x$ 是唯一达成新度的元素，故 `ans` 应恰为 $\text{span}_i(x)$，代码正是覆盖为 `span`。
- 若 $c = \text{degree}_{i-1}$：达成度的集合是旧集合加 $\{x\}$（若 $x$ 已在其中则不变，其跨度已更新），取 $\min$ 即正确。
- 若 $c < \text{degree}_{i-1}$：达成度的集合不变，`ans` 不动，且 $x$ 的跨度变化不影响正确答案。

三种情形都与代码一致，故不变式成立。∎

**定理**：算法返回的 `ans` 等于最短同度子数组的长度。

**证明**：由引理 2，最短同度子数组的长度为 $\min\{\text{span}(x) : \text{cnt}(x) = D\}$；由引理 1，该最小值由对应区间 $[\text{first}(x), \text{last}(x)]$ 取到。扫描结束时 $\text{degree}_n = D$，由引理 3，`ans` 恰为该最小值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个位置只做常数次哈希表读写（`first` 判存在、`last` 赋值、`cnt` 自增）与两次整数比较，无嵌套循环、无排序。
- **空间**：$O(u)$，$u$ 为不同元素个数（$u \le \min(n, 50000)$）。每个不同值在 `cnt`、`first`、`last` 中各占一项；若改用定长桶数组，则为 $O(V)$ 的 $3 \times 50000$ 个 `int`，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int findShortestSubArray(vector<int>& nums) {
        unordered_map<int, int> cnt, first, last;
        int n = (int)nums.size();
        cnt.reserve(n * 2);
        first.reserve(n * 2);
        last.reserve(n * 2);

        int degree = 0, ans = n;          // ans 初值取 n，首轮即被修正
        for (int i = 0; i < n; ++i) {
            int x = nums[i];
            if (!first.count(x)) first[x] = i;   // 只在首次出现时记录
            last[x] = i;
            int c = ++cnt[x];
            int span = last[x] - first[x] + 1;
            if (c > degree) {                    // 度被刷新：旧候选全部作废
                degree = c;
                ans = span;
            } else if (c == degree && span < ans) {
                ans = span;                      // 同度候选：取更短
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findShortestSubArray(self, nums: List[int]) -> int:
        cnt = {}
        first = {}
        last = {}
        degree = 0
        ans = len(nums)                      # 初值取 n，首轮即被修正
        for i, x in enumerate(nums):
            if x not in first:               # 只在首次出现时记录左端点
                first[x] = i
            last[x] = i
            cnt[x] = cnt.get(x, 0) + 1
            c = cnt[x]
            span = last[x] - first[x] + 1
            if c > degree:                   # 度被刷新：旧候选全部作废
                degree = c
                ans = span
            elif c == degree and span < ans:
                ans = span                   # 同度候选：取更短
        return ans
```

## 8. 边界情况与易错点

1. **所有元素互不相同**（如 `[1,2,3]`）：度为 1，任何单元素子数组都满足，答案是 1。代码中 `i=0` 时 `degree=1`、`ans=1`，后续全走 $c < \text{degree}$ 分支，正确。
2. **全部元素相同**（如 `[7,7,7]`）：度为 $n$，唯一同度子数组是整体，答案是 $n$。跨度随扫描增长，每步都触发 $c > \text{degree}$ 覆盖 `ans`，最终恰为 $n$。
3. **多个元素同度**（如 `[2,1,1,2]`）：度为 2，元素 1 跨度 2、元素 2 跨度 4，答案 2。漏掉 $c = \text{degree}$ 的 $\min$ 分支就会错答 4。
4. **度元素的跨度可以很大**（如 `[1,2,2,3,1,4,2]` 中元素 2 的跨度 6）：说明「同度」不等于「连续」，必须回到首末下标，不能只看相邻重复。
5. **把 `>` 写成 `>=`**：若用 `c >= degree` 且直接 `ans = span`，同度时会被更长的跨度覆盖，答案偏大；正确写法是「`>` 覆盖、`==` 取 $\min$」。
6. **桶数组越界**：值域上界是 $49999$，桶长必须 $\ge 50000$；`first` 桶用 $-1$ 表示未出现，避免把下标 0 误判成「没出现过」。
7. **`span` 别写成 `last - first`**：闭区间长度要 $+1$，否则所有答案都少 1。

**延伸思考**：

- 若要求返回**所有**最短同度子数组的起点（按升序），只需在求出 `ans` 后再扫一遍 `cnt`/`first`/`last`，收集 `cnt[x] == degree && span == ans` 的 `first[x]`；每个这样的 $x$ 对应唯一区间 $[\text{first}(x), \text{last}(x)]$，长度都是 `ans`。
- 若把「度」换成「出现次数第二大的频次」或「频次的中位数」，首末下标这套定界就不再充分——因为目标量不再对应单个元素的完整出现集合，需要维护频次的分布（如按频次分桶），复杂度会升到 $O(n\sqrt{n})$ 或依赖值域。
- 若输入是**只能顺序读一次的流**，单遍版本可直接使用；反之若要求 $O(1)$ 额外空间，则必须反复扫描，时间退化到 $O(n^2)$——这是「时间换空间」的典型取舍。
