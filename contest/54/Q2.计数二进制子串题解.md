# LeetCode 计数二进制子串 题解

## 1. 题目概述

- **标题 / 题号**：计数二进制子串（#696，easy）
- **链接**：https://leetcode.cn/problems/count-binary-substrings/
- **来源**：LeetCode 第 54 场周赛 Q2
- **难度**：简单
- **标签**：双指针，字符串

**题意**：给定只含 `'0'` 和 `'1'` 的字符串 `s`，统计**非空连续子串**的个数，要求该子串中 `0` 与 `1` 的数量相等，并且子串里所有 `0` 成组连续、所有 `1` 成组连续。满足这两条的子串只能形如 $0^t1^t$ 或 $1^t0^t$（$t \ge 1$）。子串按下标位置区分，内容相同但起点不同的要分别计数。

**约束**：

- $1 \le \lvert s \rvert \le 10^5$
- `s[i]` 为 `'0'` 或 `'1'`

## 2. 示例

**示例 1**

```text
输入：s = "00110011"
输出：6
解释：合法子串为 "0011"、"01"、"1100"、"10"、"0011"、"01"，共 6 个。
      注意内容重复的子串（不同位置）要各算一次。
      而 "00110011" 本身不合法：0 与 1 各自没有全部成组连续。
```

**示例 2**

```text
输入：s = "10101"
输出：4
解释：只有 4 个长度为 2 的子串合法："10"、"01"、"10"、"01"。
      长度 ≥ 4 的子串里 0 或 1 必然分成两段，不满足"成组连续"。
```

**补充示例（便于理解公式）**

```text
输入：s = "0011"
输出：2
解释：分界点在 0/1 之间，左段 "00"（长 2）、右段 "11"（长 2），
      贡献 min(2,2) = 2，对应子串 "01" 与 "0011"。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子串 $s[l..r)$，再判它是否由前后两个等长的同字符块组成，共 $O(n^3)$；即便用「双指针从每个分界点向两侧扩展」优化，最坏也是 $O(n^2)$（例如 `"000…0111…1"` 只有一个分界点，却要扩展 $n/2$ 轮）。$n = 10^5$ 时 $O(n^2) = 10^{10}$，必然超时。

### 3.2 核心观察：按连续段分解，每对相邻段贡献 min

![连续段分解与答案公式](images/wc54_q2_run_length.svg)

把 `s` 压缩成**段长数组** $g_0, g_1, \dots, g_{m-1}$：$g_i$ 是第 $i$ 段连续相同字符的长度，相邻段字符必不相同。于是原串的每个位置 $p$ 只可能是两类：段内位置，或**段分界点**。

关键观察只有一句：**合法子串恰好被它内部的那一个分界点决定**。

- 因为 `0` 与 `1` 都要成组连续，子串里字符只能变化一次，所以子串内部恰有一个分界点 $p$，且 $s[p-1] \ne s[p]$——它也一定是原串的段分界点。
- 子串必须是「分界点左侧取 $t$ 个、右侧取 $t$ 个」，即 $s[p-t..p+t)$，长度 $2t$。
- 这样取要落在真实段内：左侧需 $t \le$ 左段长 $a$，右侧需 $t \le$ 右段长 $b$。因此 $t = 1, 2, \dots, \min(a,b)$，恰好 $\min(a,b)$ 个。

所以答案就是所有相邻段对的较小段长之和：

$$\text{ans} = \sum_{i=0}^{m-2} \min(g_i, g_{i+1})$$

以 `"00110011"` 为例，$g = [2,2,2,2]$，答案为 $2+2+2=6$；以 `"10101"` 为例，$g = [1,1,1,1,1]$，答案为 $1 \times 4 = 4$，与示例完全吻合。

### 3.3 算法流程：滚动维护相邻两个段长

![一次扫描的流程图](images/wc54_q2_scan_flow.svg)

不必真的存下整个 $g$ 数组，只需在扫描时维护两个变量：

- `cur`：**当前段**（包含当前位置 $i$）的长度；
- `prev`：紧邻当前段之前的**上一段**长度，若当前段是第一段则为 $0$。

扫到 $i$ 时，若 `s[i] == s[i-1]`，说明当前段还在延长，`cur += 1`，不结算——因为右段还没结束，贡献数此时无法确定。若字符发生变化，说明**上一段已经完整**，此时它与更前一段构成的分界点可以结算了：`ans += min(prev, cur)`，然后 `prev = cur, cur = 1` 开始新段。

这里有一个易错点：结算的是**上一个**分界点（`prev` 与刚结束的 `cur` 之间那个），而不是刚刚遇到的这个——刚遇到的分界点右段长度还是未知的。循环结束后还剩最后一个分界点没结算，必须补一句 `ans += min(prev, cur)`。

### 3.4 示例演算

![s = "00110011" 的逐步演算](images/wc54_q2_walkthrough.svg)

对 `s = "00110011"`：

| 动作 | prev | cur | ans |
|------|------|-----|-----|
| 初始化 | 0 | 1 | 0 |
| $i=1$：`0==0`，`cur+=1` | 0 | 2 | 0 |
| $i=2$：`1!=0`，`ans+=min(0,2)` | 2 | 1 | 0 |
| $i=3$：`1==1`，`cur+=1` | 2 | 2 | 0 |
| $i=4$：`0!=1`，`ans+=min(2,2)` | 2 | 1 | 2 |
| $i=5$：`0==0`，`cur+=1` | 2 | 2 | 2 |
| $i=6$：`1!=0`，`ans+=min(2,2)` | 2 | 1 | 4 |
| $i=7$：`1==1`，`cur+=1` | 2 | 2 | 4 |
| 循环结束，补 `ans+=min(2,2)` | 2 | 2 | **6** |

三个分界点（下标 1|2、3|4、5|6 之间）各贡献 $2$，合计 $6$。

## 4. 算法细节

1. **`prev` 初值取 0**：第一段没有左邻段，`min(0, cur) = 0`，恰好让「第一段左侧那个不存在的分界点」贡献 0，无需特判。
2. **`cur` 初值取 1**：`s[0]` 本身已经是当前段的第一个字符，从 $i=1$ 开始循环。
3. **只在字符变化时结算**：`ans += min(prev, cur)` 必须写在 `else` 分支里；若每次迭代都加，同一个分界点会被重复计入多次。
4. **循环后必须补结算**：最后一个分界点没有"下一段变化"来触发它，遗漏这一行是最常见的 WA。
5. **结算顺序不能反**：必须先用旧的 `prev`、`cur` 结算，再执行 `prev = cur; cur = 1`；写成 `cur = 1; prev = cur` 会把 `prev` 置 1。
6. **$O(1)$ 空间**：全过程只用两个计数器，不需要 `vector`/`list` 保存段长。若想更直观，也可以先建段长数组再求和，代码更短但多 $O(n)$ 空间。
7. **另一条等价路线**：对每个满足 `s[i] != s[i+1]` 的分界点，用左右指针同时向外走，每走一步（两侧字符仍各异）就 `ans += 1`。它总步数等于答案、也为 $O(n)$，是很适合写来对拍的暴力版。
8. **答案范围**：$n \le 10^5$ 时答案不超过 $n/2 = 5\times 10^4$，`int` 足够；但如果把公式改成带乘法的形式（如统计同构子串的 $g(g+1)/2$），就必须开 `long long`。

## 5. 正确性证明

**引理 1（合法子串唯一对应一个分界点）**：若子串 $s[l..r)$ 合法，则存在唯一的 $p$（$l < p < r$）使得 $s[p-1] \ne s[p]$，且 $s[l..p)$、$s[p..r)$ 分别为同一种字符的连续块。

**证明**：合法性要求所有 `0` 成组、所有 `1` 成组，且两类字符数量相等均为正，故子串中 `0` 与 `1` 都出现，且各自只占一个连续块。子串内字符变化次数因此恰为 1，设发生在 $p$ 处，则 $s[p-1]$ 与 $s[p]$ 相异。又 $s[p-1] \ne s[p]$ 是原串的局部性质，与子串边界无关，故 $p$ 也是原串的段分界点。唯一性由"变化次数恰为 1"直接得到。∎

**引理 2（固定分界点的贡献恰为 $\min(a,b)$）**：设 $p$ 是原串分界点，左段长 $a$（即 $s[p-a..p)$ 全为 $s[p-1]$），右段长 $b$（$s[p..p+b)$ 全为 $s[p]$）。则对 $t \ge 1$，子串 $s[p-t..p+t)$ 合法当且仅当 $t \le \min(a,b)$；且不同 $t$ 给出不同子串。

**证明**：该子串前半 $t$ 个字符全为 $s[p-1]$、后半 $t$ 个全为 $s[p]$，两类字符数量相等且各成一组，故合法性与"是否越出段边界"等价。左侧需 $p-t \ge p-a$，即 $t \le a$；右侧需 $p+t \le p+b$，即 $t \le b$，合并即 $t \le \min(a,b)$，共有 $\min(a,b)$ 个取值。不同 $t$ 的子串长度 $2t$ 不同，故互不相同。∎

**引理 3（扫描不变量）**：任一时刻设当前位置为 $i$，记 `cur` 为包含 $i$ 的那一段的长度、`prev` 为其前一段长度（无前段时为 0），则 `ans` 恰好等于「右段已在 $i$ 之前完整结束的所有分界点」的贡献之和；`prev` 与 `cur` 之间的那个分界点是唯一未结算的分界点。

**证明**：对 $i$ 归纳。$i = 0$ 时只有一段，`prev = 0`、`cur = 1`、`ans = 0`，无已结算分界点，成立。设 $i-1$ 时成立并考察 $i$：若 `s[i] == s[i-1]`，当前段延长，`cur` 加一，分界点集合不变，`ans` 不变，不变量保持；若 `s[i] != s[i-1]`，则原 `cur` 那一段在 $i-1$ 处完整结束，未结算的那个分界点（左右段长分别为 `prev`、`cur`）此时右段已完整，按 `ans += min(prev, cur)` 结算，随后令 `prev = cur`、`cur = 1`，新的未结算分界点恰为 $i$ 处分界点、其左段长正是旧 `cur`，不变量保持。∎

**定理**：算法返回的 `ans` 等于 `s` 中合法子串的个数。

**证明**：扫描结束时，由引理 3，唯一未结算的仍是 `prev` 与 `cur` 之间的分界点，补执行 `ans += min(prev, cur)` 后所有分界点均已结算。由引理 1，每个合法子串唯一确定一个分界点 $p$ 与参数 $t$；由引理 2，分界点 $p$ 的合法子串恰有 $\min(a_p, b_p)$ 个，且正是算法在该处累加的值。不同分界点给出的子串起点 $p-t$ 落在互不相交的段对区间内，故互不重复。于是求和一次性覆盖且仅覆盖所有合法子串，`ans` 即为答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。只扫描一遍字符串，每个字符做一次比较，字符变化时做 $O(1)$ 的加法与赋值；无嵌套循环、无字符串切片。
- **空间复杂度**：$O(1)$。仅 `ans`、`prev`、`cur` 三个整型变量，与 $n$ 无关（若改用段长数组则为 $O(n)$，属可选的直观写法）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    int countBinarySubstrings(string s) {
        int n = s.size();
        int ans = 0;
        int prev = 0;   // 上一段长度（第一段时无前段，取 0）
        int cur = 1;    // 当前段长度，s[0] 已计入
        for (int i = 1; i < n; i++) {
            if (s[i] == s[i - 1]) {
                cur++;                       // 当前段继续延长，不结算
            } else {
                ans += min(prev, cur);       // 结算「上一段与当前段」之间的分界点
                prev = cur;                  // 当前段变成新的「上一段」
                cur = 1;                     // 新段以 s[i] 开头
            }
        }
        ans += min(prev, cur);               // 补结算最后一个分界点
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countBinarySubstrings(self, s: str) -> int:
        ans = 0
        prev = 0          # 上一段长度（第一段时为 0）
        cur = 1           # 当前段长度，s[0] 已计入
        for i in range(1, len(s)):
            if s[i] == s[i - 1]:
                cur += 1                  # 同字符，当前段变长
            else:
                ans += min(prev, cur)     # 结算上一个分界点
                prev, cur = cur, 1        # 切换段；注意先结算再赋值
        ans += min(prev, cur)             # 收尾：最后一个分界点
        return ans
```

## 8. 边界情况与易错点

1. **单字符串**：`s = "0"`，循环不执行，`min(prev, cur) = min(0, 1) = 0`，返回 0。若把 `prev` 初值写成 1，就会错误返回 1。
2. **全同字符**：`s = "000000"` 全在一段内，没有分界点，答案 0；此时 `prev` 一直是 0，收尾那句也贡献 0。
3. **只有一段对**：`s = "01"` 在 $i=1$ 处结算 `min(0,1)=0`，循环后补 `min(1,1)=1`，返回 1。漏写收尾语句就会返回 0。
4. **收尾漏加**是最常见的 WA：共 $\text{段数}-1$ 个分界点，而 `else` 分支只在「新段开始」时触发，第一次触发时 `prev = 0` 是无效结算（贡献 0），因此最后一个分界点永远等不到触发，必须靠循环外那一句补上。
5. **赋值顺序**：`prev, cur = cur, 1` 必须在结算之后；Python 用元组同时赋值才不丢旧 `cur`，写成两行 `prev = cur; cur = 1` 也对，但 `cur = 1; prev = cur` 是错的。
6. **重复结算**：把 `ans += min(prev, cur)` 挪到 `if` 之外每次迭代都加，会让同一分界点被反复计入，`"00110011"` 会得到 11 而不是 6。
7. **答案上界**：$n = 10^5$ 时最大答案 $5\times 10^4$（`"0101…"`），`int` 足够；但若题目改成「求所有合法子串长度之和」，`"0"*50000 + "1"*50000` 单个分界点就贡献 $\sum_{t=1}^{50000} 2t = 2{,}500{,}050{,}000 > 2^{31}-1$，必须开 `long long`。
8. **不要用切分法**：`re.split` 或手写 `"0"*k` 拼接去构造子串会引入 $O(n)$ 额外空间甚至 $O(n^2)$ 时间，直接计数即可。
