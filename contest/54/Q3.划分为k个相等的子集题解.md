# LeetCode 划分为k个相等的子集 题解

## 1. 题目概述

- **标题 / 题号**：划分为k个相等的子集（#698，medium）
- **链接**：https://leetcode.cn/problems/partition-to-k-equal-sum-subsets/
- **来源**：LeetCode 第 54 场周赛 Q3
- **难度**：中等
- **标签**：位运算，状态压缩，动态规划，回溯，记忆化

**题意**：给定整数数组 `nums` 与正整数 $k$，判断能否把数组**恰好**划分成 $k$ 个**非空**子集，使得每个子集的元素和都相等。每个元素必须用且只用一次，子集不要求连续、不要求保序。

**约束**：

- $1 \le k \le n \le 16$：子集状态最多 $2^{16} = 65536$，**位掩码 DP 正好卡在可做范围**
- $0 < nums[i] < 10000$：全正数（保证「装满的桶不能再改动」这一单调性），总和上界 $16 \times 9999 < 1.6\times10^5$
- 每个元素的频率在 $[1,4]$：重复元素最多 4 份，这是数据弱化保证，DFS 剪枝收益大、但不影响 DP 的正确性
- $k \le n$ 意味着每个桶至少能分到一个元素，无需为空桶操心

## 2. 示例

**示例 1**

```text
输入：nums = [4,3,2,3,5,2,1], k = 4
输出：true
解释：总和 20，每个子集必须和为 5，一种划分是
      (5)、(1,4)、(2,3)、(2,3)。
```

**示例 2**

```text
输入：nums = [1,2,3,4], k = 3
输出：false
解释：总和 10 不能被 3 整除，连「每个子集和相等」这个必要条件都不满足。
```

**补充（边界自测）**

```text
输入：nums = [2,2,2,2,3,4,5], k = 4
输出：false
解释：target = 5，5 单独成桶后剩 4, 3, 2, 2, 2, 2 要凑 3 个 5，
      4 既不能和 2 凑（6 > 5）也无法独自成桶，无解。
```

## 3. 解题思路

### 3.1 暴力思路

按题面提示的搜索方式：对每个元素，决定它进入 $k$ 个桶中的哪一个，递归到底检查是否所有桶都恰好装满。分支因子是 $k$，深度是 $n$，总搜索量 $k^n$；$k = n = 16$ 时约 $1.8\times10^{19}$，完全不可行。

可行的暴力必须靠剪枝活下来：把元素降序排序（大元素先放，失败早）、桶按剩余容量去重（残量相同的桶只试一次）、某个元素在任何桶都放不下就回溯、空桶尝试失败后直接跳出循环。$k=4$ 的火柴拼正方形（#473）正是这样过的。但剪枝的复杂度**没有可证明的上界**，最坏数据仍会超时；我们需要一个状态数有硬上界的做法。

### 3.2 核心观察：桶无序 ⇒ 状态塌缩成一个 mask

![桶无序时状态如何压缩成 mask](images/wc54_q3_bitmask_state_model.svg)

第一个观察是**必要条件**：设 $\text{total} = \sum nums[i]$，则每个桶的目标和必须是

$$\text{target} = \frac{\text{total}}{k}$$

于是 `total % k != 0` 直接判否；任何 $nums[i] > \text{target}$ 也直接判否（这个元素放不进任何桶）。

第二个观察才是关键：**$k$ 个桶彼此没有任何区别**。既然桶不可区分，我们就可以规定一条规范顺序——「永远只往当前这个未满的桶里放元素，把它装满了才开下一个桶」。任何合法划分都能按桶逐个重放出来，所以这条规则**不丢解**，只是把同一个划分的 $k!$ 种桶编号重复计数删掉了。

这样一来，过程中需要记住的信息只有两件：**哪些元素已经用掉**（一个 $n$ 位二进制数 $\text{mask}$），以及**当前桶已经装了多少**（记为 $r$）。而第二件其实不用存：所有已经装满的桶和都恰好是 target，对后续毫无影响，于是

$$r = S(\text{mask}) \bmod \text{target}, \qquad S(\text{mask}) = \sum_{i \in \text{mask}} nums[i]$$

也就是说，$r$ 被 $\text{mask}$ 唯一确定。状态从「(mask, r)」塌缩成一维的 $\text{mask}$，状态数从 $k^n$ 降到 $2^n \le 65536$。

> 💡 一句话：**桶无序 + 全正数**，使得「装满的桶」成为不可逆的既成事实，只剩「当前桶还差多少」需要追踪，而它由已用集合完全决定。

### 3.3 算法流程与状态转移

![按 mask 升序填桶的 DP 流程](images/wc54_q3_dp_flow.svg)

定义 $dp[\text{mask}]$：$\text{mask}$ 中的元素已被装入「若干满桶 + 一个当前桶」时，**当前桶里已装的和**；值为 $-1$ 表示该状态不可达。转移就是「把一个还没用的元素放进当前桶」：

$$dp[\text{mask} \mid 2^i] = \bigl(dp[\text{mask}] + nums[i]\bigr) \bmod \text{target}, \quad \text{当 } dp[\text{mask}] \ge 0 \text{ 且 } dp[\text{mask}] + nums[i] \le \text{target}$$

其中 $2^i$ 就是代码里的 `1 << i`。

其中取模的语义正是「装满了就归零、开一个空桶」。流程：

1. 求 `total`，若 `total % k != 0` 返回 `false`；令 `target = total / k`，若 `max(nums) > target` 返回 `false`。
2. `dp[0] = 0`（还没放任何元素，当前桶是空的），其余全部置 `-1`。
3. `mask` 从 $0$ 扫到 $2^n - 1$。因为 $\text{mask} \mid 2^i > \text{mask}$，**数值升序天然就是拓扑序**，一遍扫完即可，不需要队列或递归。
4. 对每个可达状态，枚举所有未使用的 $i$；若 $r + nums[i] \le \text{target}$，就更新后继状态。
5. 返回 `dp[2^n - 1] == 0`：全部元素装完，且残量为 $0$，说明恰好收尾了 $k$ 个满桶。

注意 $dp$ 的写入不需要取 `max` 或 `min`：同一个 mask 无论从哪条路径到达，$dp$ 值都等于 $S(\text{mask}) \bmod \text{target}$，是**唯一确定**的，直接覆盖写即可。

### 3.4 示例演算

![示例 1 的一条填桶状态链](images/wc54_q3_walkthrough.svg)

把示例 1 的 `[4,3,2,3,5,2,1]` 按值降序排成 $[5,4,3,3,2,2,1]$（排序只影响遍历顺序，不影响可达性），位序 $b_0 \dots b_6$ 依次对应这 7 个数，$\text{target} = 20/4 = 5$。一条可行的状态链：

| 步 | 加入 | mask（二进制 = 十进制） | 残量 $r$ | 含义 |
|----|------|------|----------|------|
| 0 | — | 0000000 = 0 | 0 | 起点，空桶 |
| 1 | 5 | 0000001 = 1 | 0 | 桶 1 装满 |
| 2 | 4 | 0000011 = 3 | 4 | 桶 2 未满 |
| 3 | 1 | 1000011 = 67 | 0 | 桶 2 装满 |
| 4 | 3 | 1000111 = 71 | 3 | 桶 3 未满 |
| 5 | 2 | 1010111 = 87 | 0 | 桶 3 装满 |
| 6 | 3 | 1011111 = 95 | 3 | 桶 4 未满 |
| 7 | 2 | 1111111 = 127 | 0 | 桶 4 装满，返回 true |

每一步都满足 $r + nums[i] \le 5$，装到正好等于 5 时取模归零，正是「关桶开新桶」。最终 $\text{mask} = 2^7 - 1$、$r = 0$，答案是 `true`。本例 128 个 mask 中有 102 个可达，其余 26 个的 $dp$ 值停在 $-1$，枚举时被直接跳过——这就是状态压缩节省下来的工作量。

## 4. 算法细节

1. **哨兵值 $-1$**：$dp$ 的取值范围是 $[0, \text{target})$，用 $-1$ 表示「不可达」不会与任何合法值冲突。Python 中若用 `0` 当初值就会把「空桶」和「不可达」混为一谈，后续会从错误状态扩散。
2. **溢出判据必须是 $\le$**：$r + nums[i] \le \text{target}$ 才允许放；写成 $<$ 会漏掉「刚好装满」的那一步，永远走不到 $r = 0$，答案恒为 `false`。
3. **升序扫描即拓扑序**：转移只会把 mask 的某个 $0$ 位变 $1$，所以后继的数值严格更大。按 $0 \to 2^n-1$ 顺序处理，处理到某个 mask 时它的所有前驱都已算完，无需记忆化搜索的递归栈。
4. **值唯一，直接覆盖**：$dp[\text{mask}']$ 的取值只与 $S(\text{mask}')$ 有关，与到达路径无关，所以多个前驱写同一个后继时结果一致，不用比较。
5. **不排序也能过，排序更好**：DP 的正确性不依赖顺序；但把 `nums` 降序排列会让「大元素先失败」更早发生，在 DFS 版本里是决定性的剪枝，在 DP 版本里也能小幅改善缓存局部性。
6. **提前返回的两处**：`total % k != 0` 与 `max(nums) > target` 是最廉价的两个否决，放在 DP 之前可以把绝大多数无解数据挡在 $O(n)$ 内。
7. **不要试图用「只枚举最低位未用元素」来加速**：那是 DFS 里固定「第一个元素必进第一个桶」的对称性剪枝，在「边填边换桶」的 DP 中会漏掉合法分配；DP 的加速手段是位运算，例如用 `full ^ mask` 取出未用集合，用 `lowbit` 逐个取位。
8. **整数范围**：`total` 最大 $16 \times 9999 < 2^{31}$，`int` 足够；`mask` 最大 $2^{16}$，`int` 也够。若把 $n$ 放宽到 $20$ 以上，$2^n$ 的内存会先撑爆，应改回带剪枝的 DFS。

## 5. 正确性证明

**引理 1（单步不变式）**：若 $dp[\text{mask}] = r \ge 0$，则 $\text{mask}$ 中的元素可以被划分为若干个和恰为 $\text{target}$ 的桶，外加一个和恰为 $r$ 的当前桶（$r = 0$ 时当前桶为空），并且 $r = S(\text{mask}) \bmod \text{target}$。

**证明**：对 $|\text{mask}|$ 归纳。$\text{mask} = 0$ 时 $S = 0$、$r = 0$，满桶集合为空，成立。设 $\text{mask}$ 满足结论，转移新增元素 $nums[i]$，记 $s = r + nums[i] \le \text{target}$。

- 若 $s < \text{target}$：新元素并入当前桶，满桶个数不变，新残量 $s = (S(\text{mask}) + nums[i]) \bmod \text{target}$，因为 $S(\text{mask}) \bmod \text{target} = r$ 且 $s < \text{target}$。
- 若 $s = \text{target}$：当前桶被填满，它加入满桶之列，新的当前桶为空、残量 $0 = (S(\text{mask}) + nums[i]) \bmod \text{target}$。

两情形下结论都继承，归纳完成。∎

**引理 2（完备性）**：若存在合法划分，则算法结束时 $dp[2^n - 1] = 0$。

**证明**：取任一合法划分 $B_1, \dots, B_k$（每个和恰为 $\text{target}$、非空）。按桶的顺序把元素依次加入：第 $j$ 个桶内的元素逐个放入时，桶内和从 $0$ 单调增到 $\text{target}$，每一步都不超过 $\text{target}$，因此每一步都满足转移条件，$dp$ 沿这条状态链从 $0$ 一路传播到 $2^n-1$。由于链上 mask 严格递增，按数值升序扫描时前驱先被处理，传播不会被漏掉；最后一步把最后一个桶填满，残量归 $0$。故 $dp[2^n-1] = 0$。∎

**引理 3（可靠性）**：若 $dp[2^n - 1] \ge 0$，则全部元素可划分为恰好 $k$ 个和恰为 $\text{target}$ 的非空子集。

**证明**：由引理 1，$2^n-1$ 的元素被分成若干个满桶加一个和 $r$ 的当前桶，且 $r = S(2^n-1) \bmod \text{target} = \text{total} \bmod \text{target} = 0$。元素全为正数，所以和为 $0$ 的当前桶必为空，不构成子集；于是全部元素被这些满桶恰好覆盖。设满桶个数为 $c$，则 $c \cdot \text{target} = \text{total} = k \cdot \text{target}$，得 $c = k$；又每个满桶都是因为至少放入了一个元素才存在，故非空。∎

**定理**：算法返回 `true` 当且仅当 `nums` 能划分成 $k$ 个和相等的非空子集。

**证明**：两个前置判否分别对应必要条件不成立（`total % k != 0` 时 $\text{target}$ 非整数；$nums[i] > \text{target}$ 时该元素无处安放），此时确实无解。在必要条件成立的前提下，引理 2 给出「可划分 ⇒ 返回 true」，引理 3 给出「返回 true ⇒ 可划分」。∎

## 6. 复杂度分析

- **时间**：$O(2^n \cdot n)$。共 $2^n$ 个 mask，每个可达状态枚举 $n$ 个候选元素；$n = 16$ 时上界约 $1.05\times10^6$ 次转移，实测 Python 约 $0.09$ 秒、C++ 在毫秒级。不可达状态会被跳过，实际更少。
- **空间**：$O(2^n)$。一个长度 $2^n$ 的 `int` 数组，$n = 16$ 时是 65536 个元素 $\approx 256$ KB，无需压位。
- **对比暴力**：DFS 回溯是 $k^n$（$16^{16} \approx 1.8\times10^{19}$），剪枝后实际很快但没有可证上界；位掩码 DP 用 $2^n$ 个状态覆盖了「同一已用集合 + 同一当前桶残量」的所有等价搜索分支，把指数底数从 $k$ 降到 $2$。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool canPartitionKSubsets(vector<int>& nums, int k) {
        int n = nums.size();
        int total = 0;
        for (int x : nums) total += x;
        if (total % k != 0) return false;          // 总和都分不平
        int target = total / k;
        for (int x : nums) if (x > target) return false;  // 大元素无处可放

        int full = 1 << n;
        // dp[mask]：已用 mask 时当前桶里已装的和；-1 表示该 mask 不可达
        vector<int> dp(full, -1);
        dp[0] = 0;
        for (int mask = 0; mask < full; ++mask) {
            if (dp[mask] < 0) continue;            // 不可达状态不扩散
            for (int i = 0; i < n; ++i) {
                if ((mask >> i) & 1) continue;     // 已用过
                int s = dp[mask] + nums[i];
                if (s > target) continue;          // 当前桶装不下
                dp[mask | (1 << i)] = s % target;  // 装满就归零，开新桶
            }
        }
        return dp[full - 1] == 0;
    }
};
```

### Python

```python
class Solution:
    def canPartitionKSubsets(self, nums: list[int], k: int) -> bool:
        total = sum(nums)
        if total % k:
            return False                      # 总和都分不平
        target = total // k
        if max(nums) > target:
            return False                      # 大元素无处可放

        n = len(nums)
        full = 1 << n
        dp = [-1] * full                      # 当前桶已装的和，-1 表示不可达
        dp[0] = 0
        for mask in range(full):
            r = dp[mask]
            if r < 0:
                continue                      # 不可达状态不扩散
            for i in range(n):
                if mask >> i & 1:
                    continue                  # 已用过
                s = r + nums[i]
                if s > target:
                    continue                  # 当前桶装不下
                dp[mask | (1 << i)] = s % target   # 装满就归零，开新桶
        return dp[full - 1] == 0
```

## 8. 边界情况与易错点

1. **$k = 1$**：整个数组就是一个子集，答案必为 `true`。代码无需特判也能得到正确结果（`total % 1 == 0`，`max ≤ total`，DP 会一路推进到满状态并返回 $0$），但可以显式 `if (k == 1) return true;` 省掉整趟 DP。
2. **`total % k != 0`**：示例 2 的唯一原因（$10 \bmod 3 = 1$）。这条必须先判，否则 `target` 向下取整会让算法在一个根本不存在的问题上瞎搜。
3. **`max(nums) > target`**：例如 `[2,2,2,2,3,4,5], k=4`，$\text{target}=5$ 而元素 $4$ 谁也凑不上。只判总和不判单元素是本题最常漏的一条。
4. **溢出判据写成 `<`**：`if (s > target) continue;` 的补集是 $s \le \text{target}$。若写成 $s < \text{target}$，恰好装满的那一刻被跳过，残量永远回不到 $0$，答案恒 `false`。
5. **漏掉 `if (dp[mask] < 0) continue`**：从 $-1$ 继续扩展会得到 $-1 + nums[i] \le \text{target}$ 这种「负残量合法」的假状态，可能把真正的无解数据误判为 `true`。
6. **答案判据写错**：满状态可达时 $dp$ 值**必然**是 $0$（$\text{total} \bmod \text{target} = 0$），所以判 `dp[full-1] == 0` 等价于判可达；不要写成 `== target`，也不用再统计桶数。
7. **误以为需要 `long long`**：$16 \times 9999 < 2^{31}$，`int` 足够；但若把 $n$ 或 $nums[i]$ 上限放大，`total` 与 `target` 都要跟着升级类型。
8. **$k > n$ 的空桶陷阱**：本题约束保证 $k \le n$。若自己造数据越界，空桶的「和为 0」不能充当合法子集，应直接返回 `false`，而不是让 DP 用「凑满 $k$ 个桶」的表述去兼容。
