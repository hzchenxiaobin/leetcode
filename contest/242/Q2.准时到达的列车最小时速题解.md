# LeetCode 准时到达的列车最小时速 题解

## 1. 题目概述

- **标题 / 题号**：准时到达的列车最小时速（#1870，medium）
- **链接**：https://leetcode.cn/problems/minimum-speed-to-arrive-on-time/
- **来源**：LeetCode 第 242 场周赛 Q2
- **难度**：中等
- **标签**：数组、二分查找、数学（取整）

**题意**：给定浮点数 `hour`（总通勤时限）与长度为 $n$ 的整数数组 `dist`。必须**按给定次序**乘坐 $n$ 趟列车，`dist[i]` 是第 $i$ 趟的行驶距离；列车**只能在整点发车**，故两趟之间可能需要等待。返回能在时限内到达办公室的**最小正整数**时速（km/h）；无法准时到达返回 $-1$。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{dist}[i] \le 10^5$
- $1 \le \text{hour} \le 10^9$，且 `hour` **小数点后最多两位**
- 题目保证答案不超过 $10^7$

> 💡 **审题两个关键点**：① 「整点发车」意味着前 $n-1$ 趟的耗时是 $\lceil \text{dist}[i]/v \rceil$（到达非整点要等到下一个整点），而**末趟到达即结束**，耗时是精确的 $\text{dist}[n-1]/v$；② `hour` 至多两位小数——这是后面「×100 整数化」规避浮点误差的天然前提。

## 2. 示例

**示例 1**

```text
输入：dist = [1,3,2], hour = 6
输出：1
解释：v=1 时三趟各耗时 1+3+2 = 6 小时，每次都在整点到达、立即换乘，恰在第 6 小时到达。
```

**示例 2**

```text
输入：dist = [1,3,2], hour = 2.7
输出：3
解释：v=3 时耗时 ⌈1/3⌉ + ⌈3/3⌉ + 2/3 = 1 + 1 + 0.667 = 2.667 ≤ 2.7。
```

**示例 3**

```text
输入：dist = [1,3,2], hour = 1.9
输出：-1
解释：前两趟至少各 1 小时，且末趟耗时恒 > 0，总耗时 > 2 > 1.9，不可能准时到达。
```

**示例 4（补充：上界 10⁷ 是紧确界）**

```text
输入：dist = [1,1,100000], hour = 2.01
输出：10000000
解释：T(v) = 1 + 1 + 100000/v ≤ 2.01 ⟺ 100000/v ≤ 0.01 ⟺ v ≥ 10⁷，答案恰为上界。
```

## 3. 解题思路

### 3.1 暴力思路：顺序枚举时速

时速 $v$ 的合法取值是 $[1, 10^7]$（题面保证答案上界）。从 $v=1$ 起逐个验证：对每个 $v$ 花 $O(n)$ 累加总耗时 $T(v)$，第一个满足 $T(v) \le \text{hour}$ 的即为答案。总复杂度 $O(n \cdot 10^7)$，$n$ 可达 $10^5$，约 $10^{12}$ 次运算，必然超时。

但这个「逐个验证」的**判定函数**是一切后续做法的地基——优化方向不是换判定，而是**减少判定次数**。

### 3.2 核心观察一：整点发车 ⇒ 耗时公式

![整点发车模型：发车时刻递推与前n-1趟取整、末趟精确除法](images/wc242_q2_ceil_model.svg)

设时速为 $v$，第 $i$ 趟列车**最早发车时刻**为整数 $D_i$。第 0 趟 0 时刻发车；第 $i$ 趟运行 $\text{dist}[i]/v$ 后于 $D_i + \text{dist}[i]/v$ 到达，而下一趟最早可乘的发车时刻是不小于它的最小整数：

$$D_{i+1} = \left\lceil D_i + \frac{\text{dist}[i]}{v} \right\rceil = D_i + \left\lceil \frac{\text{dist}[i]}{v} \right\rceil$$

（$D_i$ 是整数，可提出取整号外）。归纳展开即得**总耗时公式**：

$$T(v) = \sum_{i=0}^{n-2} \left\lceil \frac{\text{dist}[i]}{v} \right\rceil + \frac{\text{dist}[n-1]}{v}$$

> ⚠️ **末趟不取整**是本题最大的陷阱：末趟到达即结束、无需等下一班整点，耗时是**精确除法**。若对全部 $n$ 趟都取整，则示例 2 中 $T'(v) = \lceil 1/v \rceil + \lceil 3/v \rceil + \lceil 2/v \rceil \ge 3 > 2.7$ 对一切 $v$ 成立，会把正确答案 $3$ 误判成 $-1$。

### 3.3 核心观察二：单调 ⇒ 二分答案；无解判据与上界

![二分答案：T(v) 单调不增，可行域是右闭区间，二分找左端点](images/wc242_q2_binary_search_threshold.svg)

$T(v)$ 的每一项都随 $v$ 增大而**不增**（$\lceil d/v \rceil$ 与 $d/v$ 均单调不增），故 $T(v)$ 关于 $v$ **单调不增**。于是可行集 $\{v : T(v) \le \text{hour}\}$ 是一个**右闭区间** $[v^*, \infty)$——这正是二分答案所需的**二段性**：在 $[1, 10^7]$ 上二分，判定可行则向左找更小，不可行则提速向右。

两个配套结论（证明见 §5）：

- **无解判据**：$\text{hour} \le n-1$（**含等号**）时返回 $-1$。因为前 $n-1$ 趟每趟至少 $1$ 小时、末趟耗时恒正，$T(v) > n-1$ 严格成立。
- **上界 $10^7$ 的由来**：$\text{hour} > n-1$ 且两位小数 $\Rightarrow \text{hour} \ge n-1+0.01$；而 $v = 10^7$ 时 $\lceil \text{dist}[i]/10^7 \rceil = 1$（因 $1 \le \text{dist}[i] \le 10^5 < 10^7$）、末项 $\le 10^5/10^7 = 0.01$，故 $T(10^7) \le n-1+0.01 \le \text{hour}$，**必有解**。示例 4 表明该上界取得到。

### 3.4 算法流程：×100 放大，全程整数

![算法流程：×100整数化的二分答案完整流程](images/wc242_q2_integer_check_flow.svg)

判定 $T(v) \le \text{hour}$ 若用浮点累加，在**恰好相等**的边界上会被舍入误差坑（实测反例见 §8.3）。而 `hour` 至多两位小数，令

$$H = \mathrm{round}(\text{hour} \times 100)$$

则 $H$ 是精确整数。记 $S = \sum_{i=0}^{n-2} \lceil \text{dist}[i]/v \rceil$（整数）、$d = \text{dist}[n-1]$（整数），交叉相乘把判定**彻底整数化**（$v > 0$）：

$$T(v) \le \text{hour} \;\Longleftrightarrow\; S + \frac{d}{v} \le \frac{H}{100} \;\Longleftrightarrow\; \boxed{100\,(S \cdot v + d) \le H \cdot v}$$

流程：先做无解预判 $H \le 100(n-1)$，再在 $[1, 10^7]$ 上闭区间二分，每次用上述整数不等式判定 `mid`。

### 3.5 示例演算

![示例演算：dist=[1,3,2], hour=2.7 的整数判定对照表与二分收敛](images/wc242_q2_example_walkthrough.svg)

以示例 2（$H = 270$）逐档验证：

| $v$ | $S=\lceil 1/v\rceil+\lceil 3/v\rceil$ | 末项 $2/v$ | $T(v)$ | 整数判定 $100(Sv+2)$ vs $270v$ | 结论 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| $1$ | $1+3=4$ | $2.00$ | $6.00$ | $600 > 270$ | ✗ 太慢 |
| $2$ | $1+2=3$ | $1.00$ | $4.00$ | $800 > 540$ | ✗ 太慢 |
| $3$ | $1+1=2$ | $0.67$ | $2.67$ | $\mathbf{800 \le 810}$ | ✓ **答案** |
| $4$ | $1+1=2$ | $0.50$ | $2.50$ | $1000 \le 1080$ | ✓ 非最小 |

注意 $v=3$ 时 $T(v) = 2.67$ 与 `hour=2.7` 并不相等，但末项 $\tfrac{2}{3}$ 这种「除不尽」的情形恰被整数式 $800 \le 810$ 干净地捕捉，全程无浮点。

## 4. 算法细节

1. **向上取整的整数写法**：$\lceil d/v \rceil$ 用 $(d + v - 1) / v$（整数除法）。免去浮点开销，也免去对 `ceil((double)d/v)` 的精度分析。
2. **×100 放大的合法性**：`hour` 至多两位小数 $\Rightarrow$ `hour × 100` 在数学上是整数；`hour ≤ 10⁹` 故放大后 $\le 10^{11} < 2^{53}$，`double` 乘法误差远小于 $0.5$，`llround` / `round` 必然恢复出正确整数。
3. **无解判据同步整数化**：$\text{hour} \le n-1 \Longleftrightarrow H \le 100(n-1)$，预判与主判定统一在整数域，不残留任何浮点比较。
4. **二分框架**：闭区间 $[1, 10^7]$ + `ans` 记录版。可行（`ans = mid`）则 `hi = mid - 1`，不可行则 `lo = mid + 1`；循环不变量保证 `ans` 终为最小可行值（证明见 §5）。迭代次数 $\lceil \log_2 10^7 \rceil = 24$。
5. **溢出分析（C++）**：判定式中 $S \le \sum_i (\text{dist}[i] + v - 1) \le 10^{10} + 10^5 \cdot 10^7$，故 $100(S \cdot v + d) \lesssim 10^{14}$；$H \cdot v \le 10^{11} \cdot 10^7 = 10^{18} < 2^{63} \approx 9.2 \times 10^{18}$。中间量统一用 `long long` 即安全（Python 无此虑）。

## 5. 正确性证明

**引理 1（耗时公式）**：固定时速 $v \ge 1$，按题意最早到达时刻为 $T(v) = \sum_{i=0}^{n-2} \lceil \text{dist}[i]/v \rceil + \text{dist}[n-1]/v$。

**证明**：对 $i$ 归纳证明第 $i$ 趟最早发车时刻 $D_i = \sum_{j<i} \lceil \text{dist}[j]/v \rceil$ 且为整数。$i=0$ 时 $D_0 = 0$ 成立。设第 $i$ 趟于整数时刻 $D_i$ 发车，运行 $\text{dist}[i]/v$ 后于 $D_i + \text{dist}[i]/v$ 到达；下一趟的发车时刻须为整数且不早于到达时刻，故最早取 $\lceil D_i + \text{dist}[i]/v \rceil = D_i + \lceil \text{dist}[i]/v \rceil$（整数可提出取整号），归纳成立。末趟无后续列车，到达时刻 $D_{n-1} + \text{dist}[n-1]/v$ 即所求。∎

**引理 2（单调性）**：$v_1 \le v_2 \Rightarrow T(v_1) \ge T(v_2)$。

**证明**：对每个 $d \ge 0$，$\lceil d/v \rceil$ 与 $d/v$ 均关于 $v$ 单调不增（分母变大商变小，取整保序），$T$ 是诸项之和，故单调不增。∎

**引理 3（无解判据）**：返回 $-1$ 当且仅当 $\text{hour} \le n-1$。

**证明**：（⇒）若 $\text{hour} \le n-1$：对任意 $v \ge 1$ 与 $i \le n-2$，$\text{dist}[i] \ge 1$ 使 $\text{dist}[i]/v > 0$，故 $\lceil \text{dist}[i]/v \rceil \ge 1$；末项 $\text{dist}[n-1]/v > 0$。于是 $T(v) \ge (n-1) + \text{dist}[n-1]/v > n-1 \ge \text{hour}$，无解。（⇐）若 $\text{hour} > n-1$：两位小数条件给出 $\text{hour} \ge n-1+0.01$；由 §3.3 的计算 $T(10^7) \le n-1+0.01 \le \text{hour}$，$v = 10^7$ 可行。∎

**定理（算法正确性）**：预判后，二分返回的是最小可行时速（且不超过 $10^7$）；预判命中时返回 $-1$，与最优解一致。

**证明**：由引理 2，可行集 $F = \{v \in [1, 10^7] : T(v) \le \text{hour}\}$ 是区间（若非空则形如 $[v^*, 10^7]$）；由引理 3，预判通过时 $10^7 \in F$，$F$ 非空。闭区间二分维持不变量：`lo` 左侧（$< $ 原 `lo`）全部不可行，`hi` 右侧全部可行，且 `ans` 恒为已发现的最小可行值。初始区间为全集，不变量平凡成立；每次迭代以 `mid` 的判定结果收缩一侧，不变量保持。循环每轮区间严格减半，至多 $\lceil \log_2 10^7 \rceil$ 轮后终止，此时 `ans` $= \min F = v^*$。整数化判定的等价性由 §4.2 的交叉相乘保证（$v > 0$ 时不等式两边同乘 $100v$ 不改变方向），故浮点误差不影响判定结果。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log M)$，其中 $M = 10^7$。二分共 $\lceil \log_2 10^7 \rceil = 24$ 轮，每轮一次 $O(n)$ 的整数判定（一次累加 + 一次整数比较）；预判 $O(1)$。$n = 10^5$ 时约 $2.4 \times 10^6$ 次基本操作，轻松通过。
- **空间复杂度**：$O(1)$。仅 `lo/hi/mid/ans/S/H` 等常数个变量，不随 $n$ 增长（Python 的 `dist[:-1]` 切片若写出会引入 $O(n)$，参考代码用下标遍历避免）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minSpeedOnTime(vector<int>& dist, double hour) {
        long long n = dist.size();
        long long H = llround(hour * 100);          // 两位小数 → 精确整数
        if (H <= 100 * (n - 1)) return -1;          // T(v) > n-1 ≥ hour 恒成立

        int lo = 1, hi = 10000000, ans = -1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            long long S = 0;                        // 前 n-1 趟取整耗时之和
            for (long long i = 0; i + 1 < n; ++i)
                S += (dist[i] + mid - 1) / mid;     // 整数向上取整
            if (100 * (S * mid + dist[n - 1]) <= H * mid) {  // T(mid) ≤ hour，整数形式
                ans = mid;
                hi = mid - 1;                       // 可行：向左找更小
            } else {
                lo = mid + 1;                       // 太慢：提速
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minSpeedOnTime(self, dist: List[int], hour: float) -> int:
        n = len(dist)
        H = round(hour * 100)                       # 两位小数 → 精确整数
        if H <= 100 * (n - 1):
            return -1                               # T(v) > n-1 ≥ hour 恒成立

        def ok(v: int) -> bool:                     # T(v) ≤ hour 的整数判定
            s = 0
            for i in range(n - 1):
                s += (dist[i] + v - 1) // v         # 整数向上取整
            return 100 * (s * v + dist[-1]) <= H * v

        lo, hi, ans = 1, 10 ** 7, -1
        while lo <= hi:
            mid = (lo + hi) // 2
            if ok(mid):
                ans, hi = mid, mid - 1              # 可行：向左找更小
            else:
                lo = mid + 1                        # 太慢：提速
        return ans
```

## 8. 边界情况与易错点

1. **末趟误取整**（最高频 WA）：对全部 $n$ 趟做 $\lceil \cdot \rceil$ 会使末趟虚增等待时间。示例 2 中全取整的 $T'(v) \ge 3 > 2.7$ 恒成立，正确答案 $3$ 被误判为 $-1$。只有**前 $n-1$ 趟**取整。
2. **无解判据漏掉等号**：$\text{hour} = n-1$ 时也是 $-1$——$T(v) > n-1$ 是**严格**不等式（末项恒正），`hour <= n-1` 与整数式 `H <= 100(n-1)` 都必须含 `=`。例：`dist=[1,1], hour=1.0` → $-1$。
3. **浮点恰好相等的边界（实测可复现）**：`dist=[1,1,7], hour=2.28`，正确答案 $25$（$T(25) = 2 + 7/25 = 2.28$ 恰相等）。但 `2.0 + 7.0/25.0` 算得 `2.2800000000000002`，而字面量 `2.28` 是 `2.2799999999999998`，朴素浮点比较 `total <= hour` 判 $25$ 不可行，输出错误的 $26$。修复：本篇的 ×100 整数化（根治），或 `total <= hour + 1e-9` 容差（每日一题版写法，能过但需解释容差来源）。
4. **上界照抄 875 的 `max(dist)`**：875「爱吃香蕉的珂珂」的速度上界取 `max(piles)` 即可，但本题末趟是**精确除法**，$\text{dist}[n-1]/v$ 可任意小，答案可达 $10^7$（示例 4），必须以题面保证的 $10^7$ 为上界。
5. **C++ 中间量溢出**：`H * mid` 最大 $10^{11} \times 10^7 = 10^{18}$，逼近但不超过 `long long` 上限；`H`、`S`、判定式必须用 `long long`，用 `int` 会溢出未定义行为。`hi` 写成 `10000000`（$10^7 < 2^{31}$，`int` 可容纳）。
6. **`n = 1`（无取整项）**：$T(v) = \text{dist}[0]/v$，此时 $n-1 = 0 < 1 \le \text{hour}$，预判恒不触发，二分正常求解纯精确除法不等式，无需特判。
7. **Python 切片的隐性开销**：`sum(... for d in dist[:-1])` 每次判定复制 $O(n)$ 列表，24 轮二分放大成 $24n$ 的额外分配；用下标 `range(n-1)` 遍历即可保持 $O(1)$ 额外空间。
