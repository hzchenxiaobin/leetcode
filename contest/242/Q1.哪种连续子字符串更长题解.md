# LeetCode 哪种连续子字符串更长 题解

## 1. 题目概述

- **标题 / 题号**：哪种连续子字符串更长（#1869，easy）
- **链接**：https://leetcode.cn/problems/longer-contiguous-segments-of-ones-than-zeros/
- **来源**：LeetCode 第 242 场周赛 Q1
- **难度**：简单
- **标签**：字符串、游程（连续段）计数

**题意**：给定二进制字符串 `s`（仅含 `'0'`、`'1'`）。若由 `'1'` 组成的**最长连续子字符串**的长度**严格大于**由 `'0'` 组成的最长连续子字符串的长度，返回 `true`；否则返回 `false`。某种字符在串中不存在时，其最长连续段长度记为 $0$。

**约束**：

- $1 \le \text{s.length} \le 100$
- `s[i]` 为 `'0'` 或 `'1'`

> 💡 **审题三个关键点**：① 比较的是**各自最长的一段**，不是字符总数、也不是段数；② 是**严格大于**（`>` 而非 `≥`），两边相等即 `false`；③ 字符缺席按 $0$ 处理——把两个最大值初始化为 $0$ 即天然覆盖，**无需特判**。

## 2. 示例

**示例 1**

```text
输入：s = "1101"
输出：true
解释：最长 1 段为 "11"（长度 2），最长 0 段为 "0"（长度 1），2 > 1 → true。
```

**示例 2**

```text
输入：s = "111000"
输出：false
解释：最长 1 段为 "111"（长度 3），最长 0 段为 "000"（长度 3），3 > 3 不成立 → false。
```

**示例 3**

```text
输入：s = "110100010"
输出：false
解释：最长 1 段为 "11"（长度 2），最长 0 段为 "000"（长度 3），2 > 3 不成立 → false。
```

**示例 4（补充：总数相同不代表答案相同）**

```text
输入：s = "11100100"
输出：true
解释：'1' 与 '0' 的总个数都是 4，但最长 1 段 "111" 长度 3 > 最长 0 段 "00" 长度 2 → true。
      若误把题意理解成"比较字符个数"会得到 4 > 4 不成立的错误答案。
```

## 3. 解题思路

### 3.1 暴力思路：枚举子串

枚举所有 $O(n^2)$ 个子串，每个花 $O(n)$ 检查是否全 `'1'` / 全 `'0'` 并更新两个最大值，总复杂度 $O(n^3)$。$n \le 100$ 时约 $10^6$ 量级，稳过。

但签到题的正确打开方式是**从结构切入**：所求只是两个数（最长 1 段长、最长 0 段长），一趟扫描即可同时拿到，代码比三重循环更短、更不易错——比赛时直接写结构解，抢时间也抢心态。

### 3.2 核心观察：游程分解，答案只由 (max₁, max₀) 决定

![核心观察：游程分解后答案只由 max1 与 max0 两个数决定](images/wc242_q1_runs_concept.svg)

把 `s` 按连续相同字符切成**游程**（run）：如 `"110100010"` = `11 | 0 | 1 | 000 | 1 | 0`。两个观察：

1. **全 1 子串必落在某个 1 游程内**：任何由连续 `'1'` 组成的子串都完整包含于唯一一个极大 1 段，故**最长 1 子串 = 最长 1 游程**；`'0'` 对称同理。
2. **答案只依赖两个数**：$max_1$（最长 1 段）与 $max_0$（最长 0 段），返回 $max_1 > max_0$ 即可。段的位置、段数、字符总数统统无关（见示例 4）。

**比赛速写（Python 一行流）**：`s.split('0')` 把所有 `'0'` 当分隔符，切出的片段恰是全部极大 `1` 段（外加空串）：

```python
max(map(len, s.split('0'))) > max(map(len, s.split('1')))
```

空串长度为 $0$，天然处理"某字符缺席"的情形。

### 3.3 算法流程：双车道计数，即时结算

![算法流程：双车道计数即时结算，遇异字符清零对侧](images/wc242_q1_counter_lanes_flow.svg)

不显式存游程，只维护四个变量：`cnt1` / `cnt0` 是**当前段**的实时长度，`max1` / `max0` 记录历史最长。每读一个字符 `c`：

- `c == '1'`：`cnt1 += 1`，同时 `cnt0 = 0`（`0` 段刚被切断），并**立刻** `max1 = max(max1, cnt1)`；
- `c == '0'`：对称地 `cnt0 += 1`、`cnt1 = 0`、`max0 = max(max0, cnt0)`。

> 💡 **为什么"即时结算"没有末段陷阱？** `max` 在**每个位置**都被更新，最后一段在它的每个字符处都已计入 `max`，循环结束后无需补一次"结算末段"。这与"字符切换时才结算"的写法形成对照——后者必须记得在循环后补结算，是本题最高频的 WA 点（见 §8.3）。

### 3.4 示例演算

![示例演算：s=110100010 逐字符状态追踪](images/wc242_q1_example_walkthrough.svg)

以 `s = "110100010"` 为例逐字符追踪：

| $i$ | $s_i$ | cnt₁ | cnt₀ | max₁ | max₀ | 说明 |
|:---:|:-----:|:----:|:----:|:----:|:----:|------|
| 0 | 1 | $1$ | $0$ | $\mathbf{1}$ | $0$ | 1 段起步 |
| 1 | 1 | $2$ | $0$ | $\mathbf{2}$ | $0$ | "11"，max₁ 升到 2 |
| 2 | 0 | $0$ | $1$ | $2$ | $\mathbf{1}$ | 切换：cnt₁ 清零，0 段起步 |
| 3 | 1 | $1$ | $0$ | $2$ | $1$ | 切换：cnt₀ 清零 |
| 4 | 0 | $0$ | $1$ | $2$ | $1$ | 切换 |
| 5 | 0 | $0$ | $2$ | $2$ | $\mathbf{2}$ | "00" |
| 6 | 0 | $0$ | $3$ | $2$ | $\mathbf{3}$ | "000"，max₀ 升到 3 |
| 7 | 1 | $1$ | $0$ | $2$ | $3$ | 切换：cnt₀ 清零 |
| 8 | 0 | $0$ | $1$ | $2$ | $3$ | 末段 "0" 已即时计入 |

最终 $max_1 = 2$、$max_0 = 3$，$2 > 3$ 不成立 → 返回 `false` ✓。

## 4. 算法细节

1. **状态语义**：`cnt1` 恒等于"以当前字符结尾的连续 `'1'` 个数"（当前字符是 `'0'` 时为 $0$），`cnt0` 对称。这保证它就是当前段的实时长度，无需额外记忆段起点。
2. **对侧清零**：读到 `'1'` 时必须 `cnt0 = 0`——`0` 段刚被 `'1'` 切断；只自增不清零会把不相邻的两段错误累加（反例见 §8.4）。
3. **即时更新 max**：每步都执行一次 `max`，代价 $O(1)$，换来"无末段结算"的结构正确性——用微小常数换掉一整类 bug，签到题里极其划算。
4. **返回值**：直接 `return max1 > max0`，比较表达式本身就是 `bool`。
5. **等价写法**：① 双指针分段（内层 `while` 一次吃完整段再结算，天然无末段问题）；② 字符切换时结算 + 循环后补结算末段（需警惕遗漏）；③ Python `split` 一行流。三种写法的对照见文末链接的每日题解。

## 5. 正确性证明

**引理 1（游程刻画）**：全 `'1'` 子串长度的最大值等于最长 `1` 游程的长度；`'0'` 对称。

**证明**：任一全 `'1'` 子串是连续同字符片段，必完整包含于某个极大 `1` 游程，故其长度不超过该游程长度，从而不超过最长 `1` 游程。反之，任一 `1` 游程本身就是一个全 `'1'` 子串，其长度（特别是最长游程的长度）可以被取到。两个方向夹逼即得。∎

**引理 2（循环不变量）**：处理完前缀 $s[0..i]$ 后：`cnt1` 等于以 $s_i$ 结尾的连续 `1` 段长度（$s_i = 0$ 时为 $0$），`cnt0` 对称；`max1` / `max0` 等于该前缀内最长 `1` / `0` 游程的长度。

**证明**：对 $i$ 归纳。空前缀（$i = -1$）时四个变量均为 $0$，成立。设处理完 $s[0..i-1]$ 后不变量成立，考察 $s_i$：

- 若 $s_i = 1$：以 $i$ 结尾的 `1` 段长度 = 以 $i-1$ 结尾的 `1` 段长度 $+ 1$（$s_{i-1} = 1$ 时由归纳假设即旧 `cnt1`，新 `cnt1` = 旧值 $+ 1$；$s_{i-1} = 0$ 时旧 `cnt1` $= 0$，新 `cnt1` $= 1$，同样正确）；同时 $s_i = 1$ 使以 $i$ 结尾的 `0` 段不存在，`cnt0 ← 0` 正确。前缀内**以 $i$ 结尾**的 `1` 游程长度恰为新 `cnt1`，`max1 ← max(旧 max1, 新 cnt1)` 把它计入；不以 $i$ 结尾的 `1` 游程已含于旧 `max1`。故新 `max1` 是新前缀的最长 `1` 游程长；`0` 侧没有新游程在 $i$ 结束，`max0` 沿用旧值仍正确。
- $s_i = 0$ 的情形对称。

∎

**定理**：算法返回 `true`，当且仅当 `s` 中最长 `1` 连续子串严格长于最长 `0` 连续子串。

**证明**：由引理 2，扫描结束时 `max1` / `max0` 为全串最长 `1` / `0` 游程长度；由引理 1，它们即题意所求的两个最长连续子串长度。某字符缺席时对应 `max` 保持初值 $0$，与题面"不存在记 $0$"的约定一致。算法返回 `max1 > max0`，恰为所求布尔值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个字符 $O(1)$（一次比较、一次自增、一次清零、一次 `max`）。$n \le 100$ 远未触及瓶颈，即使 $n = 10^6$ 也一遍而过。
- **空间复杂度**：$O(1)$。仅 `cnt1` / `cnt0` / `max1` / `max0` 四个整型变量。Python `split` 一行流时间同为 $O(n)$，但产生中间数组，空间 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool checkZeroOnes(string s) {
        int max1 = 0, max0 = 0, cnt1 = 0, cnt0 = 0;
        for (char c : s) {
            if (c == '1') {
                ++cnt1;
                cnt0 = 0;                      // 0 段被切断
                max1 = max(max1, cnt1);        // 即时结算，无末段陷阱
            } else {
                ++cnt0;
                cnt1 = 0;                      // 1 段被切断
                max0 = max(max0, cnt0);
            }
        }
        return max1 > max0;
    }
};
```

### Python

```python
class Solution:
    def checkZeroOnes(self, s: str) -> bool:
        max1 = max0 = cnt1 = cnt0 = 0
        for c in s:
            if c == '1':
                cnt1 += 1
                cnt0 = 0
                max1 = max(max1, cnt1)
            else:
                cnt0 += 1
                cnt1 = 0
                max0 = max(max0, cnt0)
        return max1 > max0
```

比赛抢时间可直接交一行流（原理见 §3.2）：

```python
class Solution:
    def checkZeroOnes(self, s: str) -> bool:
        return max(map(len, s.split('0'))) > max(map(len, s.split('1')))
```

## 8. 边界情况与易错点

1. **严格大于**：`"111000"` 两边最长段都是 3，`3 > 3` 不成立 → `false`（示例 2）。误写成 `>=` 全 WA。
2. **全 `1` / 全 `0` / 单字符**：缺席一侧的 `max` 保持初值 $0$，`"1"` → `true`、`"0"` → `false`，初始化天然兜底，无需特判。
3. **切换结算版忘结算末段**（若采用 §4.5 写法②）：如 `"10"`，末段 `"0"` 不补结算则 `max0 = 0`，误判 `1 > 0` → `true`，正确答案 `false`。本篇的"即时结算"写法从结构上根除此陷阱。
4. **忘清零对侧计数器**：`"101"` 中两个 `1` 被中间的 `0` 隔开，若读 `'1'` 时不清 `cnt1` 的历史值，末尾 `cnt1` 会累成 2，误得 `max1 = 2 > max0 = 1` → `true`（正确 `false`）；`"0110"` 是 `0` 侧的对称反例。
5. **误比字符总数**：`"11100100"` 的 `1`、`0` 总数相等（各 4），但答案是 `true`（最长段 3 > 2）。题面比较的是**最长段**，不是个数（示例 4）。
6. **Python 一行流的坑**：必须带参 `split('0')`，无参 `split()` 按任意空白切分，行为完全不同；`s` 非空保证 `split` 结果列表非空，`max(map(len, ...))` 不会抛异常，空串片段取 0 恰是"缺席记 0"的语义。
7. **返回类型**：接口是 `bool`，直接 `return max1 > max0`，不要返回 `int`。
