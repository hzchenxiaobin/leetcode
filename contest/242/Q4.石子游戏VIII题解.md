# LeetCode 石子游戏 VIII 题解

## 1. 题目概述

- **标题 / 题号**：石子游戏 VIII（#1872，hard）
- **链接**：https://leetcode.cn/problems/stone-game-viii/
- **来源**：LeetCode 第 242 场周赛 Q4
- **难度**：困难
- **标签**：极小化极大、动态规划、前缀和、博弈

**题意**：Alice 和 Bob 轮流操作，**Alice 先手**。共有 $n$ 块石头排成一行。轮到某个玩家时，若当前石头数**大于 1**，他必须：

1. 选择一个整数 $x > 1$，移除**最左边**的 $x$ 块石头；
2. 把移除石头价值之**和**累加到自己的分数中；
3. 把一块**新石头**放在最左边，其价值等于被移除石头之和。

当只剩**一块**石头时游戏结束。定义分数差为（Alice 的分数 − Bob 的分数），Alice 想最大化它，Bob 想最小化它。返回双方都采用最优策略时的分数差。

**约束**：

- $2 \le n \le 10^5$
- $-10^4 \le \text{stones}[i] \le 10^4$

> 💡 **读题三个信号**：① 每次操作只动**最左边**、且新石头值恰为被移除者之和——这是「**前缀合并**」结构，强烈暗示前缀和；② 双方目标相反（最大 / 最小化同一差值）——**零和博弈**，标准 minimax DP；③ $n$ 高达 $10^5$——排除 $O(n^2)$ 区间 DP（石子游戏 VII 那套），必须把状态压成线性。

## 2. 示例

**示例 1**

```text
输入：stones = [-1,2,-3,4,-5]
输出：5

解释：
- Alice 移除最左边 4 块，得分 (-1)+2+(-3)+4 = 2，放回值为 2 的新石头。stones = [2,-5]。
- Bob 移除最左边 2 块，得分 2+(-5) = -3，放回值为 -3 的新石头。stones = [-3]。
分数差 = 2 - (-3) = 5。
```

**示例 2**

```text
输入：stones = [7,-6,5,10,5,-2,-6]
输出：13

解释：
- Alice 一步移除全部 7 块，得分 13，stones = [13]，游戏立即结束。
分数差 = 13 - 0 = 13。
```

**示例 3**

```text
输入：stones = [-10,-12]
输出：-22

解释：
- Alice 只有一种操作：全部移除，得分 -22。
分数差 = -22 - 0 = -22。（即使得分为负也必须操作，不能弃权！）
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是沿博弈树搜索：状态是「当前石头序列 + 轮到谁」，每个分支枚举 $x \in [2, \text{剩余块数}]$。即使加上记忆化（状态其实只由「已合并到第几块」这个指针决定），转移也是

$$
dp[i] = \max_{j=i+1}^{n}\big(\text{pre}[j] - dp[j]\big), \qquad dp[n] := 0,
$$

直接实现是**双层循环** $O(n^2)$。本题 $n = 10^5$，$10^{10}$ 次运算必然超时——瓶颈在于「每个状态要枚举所有后继」。

> ⚠️ 注意不能照搬石子游戏 VII 的区间 DP：那题 $n \le 500$，本题 $n \le 10^5$，区间 DP 的 $O(n^2)$ 状态数本身就不可行。

### 3.2 核心观察：前缀和不变性

盯着「移除最左边 $x$ 块 + 放回它们的和」这条规则看：**无论怎么操作，最左边的石头永远是某个原始前缀和**。

设 $\text{pre}[j]$ 为前 $j$ 块原始石头之和（下文统一 1-indexed）。若当前最左石头已经「吞并」了前 $k$ 块，那么剩余序列是

$$
[\,\text{pre}[k],\ \text{stones}[k{+}1],\ \ldots,\ \text{stones}[n]\,].
$$

此时玩家选 $x$ 块移除，得分与新石头值都是

$$
\text{pre}[k] + \text{stones}[k{+}1] + \cdots + \text{stones}[k{+}x{-}1] = \text{pre}[k{+}x{-}1],
$$

即操作**等价于把指针从 $k$ 推到 $j = k + x - 1$，得分恒为原始前缀和 $\text{pre}[j]$**。

![一次操作等于吞并一个前缀](images/wc242_q4_merge_concept.svg)

初始时指针 $k = 1$（最左石头就是第 1 块本身）。于是整场博弈被压缩成：

> **等价博弈**：双方轮流在数组 $\text{pre}[2..n]$ 上挑**严格递增**的位置，选中 $j$ 得 $\text{pre}[j]$ 分；谁选中 $j = n$（全部吞并），游戏立即结束，对方不再得分。

![等价博弈：前缀和数组上挑递增位置](images/wc242_q4_equiv_game.svg)

### 3.3 状态设计与 $O(n)$ 递推

等价博弈只依赖「指针位置」和「轮到谁」，天然无后效性。定义：

$$
dp[i] = \text{指针在 } i \text{ 且轮到当前玩家时，}\text{(当前玩家 − 对手)}\text{ 的最大分差}, \qquad dp[n] := 0.
$$

当前玩家选 $j \in (i, n]$：立刻得 $\text{pre}[j]$，随后对手在状态 $j$ 拿到 $dp[j]$ 的（对手 − 当前）差，故当前玩家视角总差为 $\text{pre}[j] - dp[j]$，取最大：

$$
dp[i] = \max_{j=i+1}^{n}\big(\text{pre}[j] - dp[j]\big).
$$

**关键一步（后缀最大折叠）**：把 $j = i+1$ 这一项单独拆出，剩余部分 $\max_{j \ge i+2}(\text{pre}[j] - dp[j])$ **恰好就是 $dp[i+1]$ 自身**（这正是 $dp[i+1]$ 的定义式）。于是

$$
\boxed{\;dp[i] = \max\big(\underbrace{\text{pre}[i{+}1] - dp[i{+}1]}_{\text{把指针推到 } i+1},\ \underbrace{dp[i{+}1]}_{\text{跳过 } i+1}\big)\;}
$$

边界 $dp[n-1] = \text{pre}[n]$（只剩 2 块，**被迫**一步全拿），答案为 $dp[1]$（Alice 先手、指针初始在 1）。

![状态设计与后缀最大折叠](images/wc242_q4_dp_recurrence.svg)

### 3.4 示例演算

以示例 1（`stones = [-1,2,-3,4,-5]`）倒序填表：$\text{pre} = [-1, 1, -2, 2, -3]$。

| $i$ | 计算 | $dp[i]$ |
|---|---|---|
| $n=5$ | 哨兵 | $0$ |
| $4$ | $= \text{pre}[5]$ | $-3$ |
| $3$ | $\max(-3,\ 2-(-3)) = \max(-3, 5)$ | $5$ |
| $2$ | $\max(5,\ -2-5)$ | $5$ |
| $1$ | $\max(5,\ 1-5)$ | $5$ ✓ |

回溯最优策略：Alice 跳过 2、3 直接选 $j=4$（得 $\text{pre}[4]=2$），Bob 被迫选 $j=5$（得 $-3$），差为 $5$，与示例一致。

![示例 1 倒序填表演算](images/wc242_q4_walkthrough.svg)

## 4. 算法细节

1. **预处理前缀和**：$\text{pre}[i] = \text{pre}[i-1] + \text{stones}[i]$（1-indexed），$O(n)$。
2. **倒序递推**：滚动变量 `cur` 初始为 $\text{pre}[n]$（即 $dp[n-1]$），从状态「吞并前 $n-1$ 块」一路倒推到「吞并前 1 块」：
   - 状态 $i$（已吞并前 $i$ 块，$i = n{-}1, \ldots, 1$）：
     - 若 $i = n-1$：`cur = pre[n]`（强制）；
     - 否则：`cur = max(cur, pre[i+1] - cur)`。
   - 循环结束后 `cur` 即 $dp[1]$，返回。
3. **实现下标对照**（代码用 0-indexed 数组 `pre[i]` 表示前 $i+1$ 块之和）：循环变量 `i` 从 `n-2` 递减到 `1`，对应状态「已吞并前 `i+1` 块」，转移为 `cur = max(cur, pre[i] - cur)`。
4. **为什么不用记忆化搜索**：递归深度 $10^5$ 在部分环境有爆栈风险；且倒序递推天然按依赖序（$dp[i]$ 只依赖 $dp[i+1]$）计算，更简洁。
5. **数据类型**：分数差的理论值域为 $\pm\sum|\text{stones}[i]| \le 10^9$，`int` 勉强够但已贴近上限，C++ 建议用 `long long` 防御。

## 5. 正确性证明

**引理 1（前缀和不变性）**：设 $\text{pre}[j] = \sum_{t=1}^{j}\text{stones}[t]$。任何时刻，若最左石头已吞并前 $k$ 块（$1 \le k \le n-1$），则剩余序列为 $[\text{pre}[k], \text{stones}[k+1], \ldots, \text{stones}[n]]$；从该状态选择 $x \in [2,\ n-k+1]$ 的操作，等价于把指针移到 $j = k+x-1 \in (k,\ n]$，得分恰为 $\text{pre}[j]$。

**证明**：对操作次数归纳。初始 $k=1$，最左石头即 $\text{stones}[1] = \text{pre}[1]$，命题成立。归纳步：设当前为状态 $k$，移除前 $x$ 块的得分与新石头值为

$$
\text{pre}[k] + \text{stones}[k{+}1] + \cdots + \text{stones}[k{+}x{-}1] = \text{pre}[k{+}x{-}1],
$$

故新状态为 $j = k+x-1$。由 $x \ge 2$ 得 $j \ge k+1$，由 $x \le n-k+1$ 得 $j \le n$；反之任意 $j \in (k, n]$ 可由 $x = j-k+1 \ge 2$ 达到，故状态转移与得分严格对应。∎

**引理 2（minimax 转移）**：定义 $dp[i]$（$1 \le i \le n-1$）为指针在 $i$ 且轮到当前玩家 $P$ 时、双方此后均最优的（$P$ − 对手）分差，$dp[n] := 0$，则

$$
dp[i] = \max_{j=i+1}^{n}\big(\text{pre}[j] - dp[j]\big).
$$

**证明**：$P$ 选 $j$ 后立即得 $\text{pre}[j]$（引理 1），随后轮到对手 $Q$、指针在 $j$。若 $j = n$ 游戏结束，$Q$ 不再得分，总差为 $\text{pre}[j] - 0$；若 $j < n$，$Q$ 以最优策略取得（$Q$ − $P$）差 $dp[j]$，故 $P$ 视角总差为 $\text{pre}[j] - dp[j]$。零和博弈下 $P$ 的最优即对所有可行 $j$ 取最大。∎

**引理 3（折叠恒等式）**：对 $1 \le i \le n-2$，有 $\max_{j=i+2}^{n}\big(\text{pre}[j] - dp[j]\big) = dp[i+1]$。

**证明**：因 $i+1 \le n-1$，$dp[i+1]$ 有定义，且其转移式（引理 2）为 $dp[i+1] = \max_{j=(i+1)+1}^{n}(\text{pre}[j] - dp[j])$，恰为所需。∎

**定理**：$dp[n-1] = \text{pre}[n]$；对 $1 \le i \le n-2$，$dp[i] = \max\big(dp[i+1],\ \text{pre}[i+1] - dp[i+1]\big)$；双方最优策略下的分数差为 $dp[1]$。倒序一趟计算即得正确答案。

**证明**：状态 $n-1$ 时仅剩 2 块，规则强制 $x = 2$，即 $j = n$ 唯一可选，$dp[n-1] = \text{pre}[n] - dp[n] = \text{pre}[n]$。对 $i \le n-2$，由引理 2 拆出 $j = i+1$ 项、引理 3 折叠其余项得递推式。由引理 1，初始状态为指针 $1$ 且 Alice 先手，故分数差为 $dp[1]$。递推按 $i$ 严格递减的依赖序计算，无循环依赖，一趟完成。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$
  - 前缀和一趟 $O(n)$；
  - 倒序递推一趟 $O(n)$，每个状态 $O(1)$ 转移（后缀最大被折叠进 $dp[i+1]$）。
- **空间复杂度**：$O(n)$ 存前缀和数组；若允许原地改写 `stones` 为前缀和，额外空间 $O(1)$（仅一个滚动变量 `cur`）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int stoneGameVIII(vector<int>& stones) {
        int n = stones.size();
        vector<long long> pre(n);            // pre[i] = 前 i+1 块之和（0-indexed）
        pre[0] = stones[0];
        for (int i = 1; i < n; ++i) pre[i] = pre[i - 1] + stones[i];

        long long cur = pre[n - 1];          // dp[n-1]：只剩 2 块，被迫全拿
        for (int i = n - 2; i >= 1; --i)     // 状态：已吞并前 i+1 块
            cur = max(cur, pre[i] - cur);    // max(跳过 i+1, 把指针推到 i+1)
        return (int)cur;                     // cur = dp[1]
    }
};
```

### Python

```python
class Solution:
    def stoneGameVIII(self, stones: List[int]) -> int:
        pre = list(accumulate(stones))       # pre[i] = 前 i+1 块之和
        cur = pre[-1]                        # dp[n-1]：被迫全拿
        for i in range(len(stones) - 2, 0, -1):
            cur = max(cur, pre[i] - cur)     # max(跳过, 推进)
        return cur                           # dp[1]
```

## 8. 边界情况与易错点

1. **不能弃权**：$dp[n-1]$ 必须初始化为 $\text{pre}[n]$，而不是 $\max(0, \text{pre}[n])$。玩家在只剩 2 块时**必须**操作，$\text{pre}[n] < 0$ 也得吞——示例 3（`[-10,-12]`，答案 $-22$）专门考察这一点。
2. **首步限制 $x > 1$**：等价博弈中 Alice 首个位置必须 $\ge 2$，对应初始指针 $k=1$ 而非 $0$；若误从 $0$ 起步会允许「只拿第一块」的非法操作。
3. **循环变量与状态错位**：0-indexed 代码中 `pre[i]` 是前 $i+1$ 块之和，循环区间是 `[n-2, 1]` 而非 `[n-1, 1]`——下标平移差一是本题最常见的手误，建议写代码前先在示例 3（$n=2$，循环体不执行）上验证：返回值应恰为 `pre[-1]`。
4. **整数溢出**：分数差理论值域 $\pm 10^9$，`int` 上限 $2^{31}-1 \approx 2.1 \times 10^9$，勉强安全但贴边；C++ 用 `long long` 存 `pre` 与 `cur` 更稳（$\text{pre}$ 本身可达 $\pm 10^9$）。
5. **别套区间 DP**：石子游戏 VII（#1690）的 $O(n^2)$ 区间 DP 在 $n = 10^5$ 下状态数就爆炸；本题能线性化的根源是「只动最左边」带来的前缀和不变性。
