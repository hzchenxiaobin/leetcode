# LeetCode 取整购买后的账户余额 题解

## 1. 题目概述

- **标题 / 题号**：取整购买后的账户余额（#2806，easy）
- **链接**：https://leetcode.cn/problems/account-balance-after-rounded-purchase/
- **来源**：LeetCode 第 110 场双周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：账户初始有 100 元。给定购买意愿金额 `purchaseAmount`，实际支付金额会**四舍五入到最近的 10 的倍数**（记为 `roundedAmount`，要求它是非负的 10 的倍数且 $|\mathrm{roundedAmount} - \mathrm{purchaseAmount}|$ 最小）；若有两个等近的倍数，**取较大者**。返回购买后的账户余额（$100 - \mathrm{roundedAmount}$）。

**约束**：

- $0 \le \mathrm{purchaseAmount} \le 100$

## 2. 示例

**示例 1**

```text
输入：purchaseAmount = 9
输出：90
解释：最接近 9 的 10 的倍数是 10，余额 100 − 10 = 90。
```

**示例 2**

```text
输入：purchaseAmount = 15
输出：80
解释：10 与 20 距离 15 相同，取较大的 20，余额 100 − 20 = 80。
```

**示例 3（官方隐藏用例）**

```text
输入：purchaseAmount = 10
输出：90
解释：10 本身就是 10 的倍数，原样支付 10，余额 90。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有候选倍数 $m \in \{0, 10, 20, \dots, 100\}$（注意 0 也是 10 的倍数），取 $|m - a|$ 最小者；平局时取更大的 $m$。至多 11 个候选，$O(1)$ 但要写比较逻辑（严格小于才更新，相等时取大）。正确且直观，但既然候选分布如此规则，一行公式更利落。

### 3.2 核心观察：加 5 再整除即是"四舍五入、平局取大"

![数轴上的取整：最近倍数与平局规则](images/bw110_q1_number_line.svg)

把数轴按 $10$ 的倍数分桶，$a$ 落在桶 $[10q, 10q+10)$ 内：

$$\mathrm{rounded} = \left\lfloor \frac{a + 5}{10} \right\rfloor \times 10$$

- 个位 $\le 4$ 时 $a + 5 < 10(q+1)$，得 $10q$（向下取整到本桶左端）；
- 个位 $= 5$ 时 $a + 5 = 10(q+1)$，恰好整除进到 $10(q+1)$——**平局自动取大**；
- 个位 $\ge 6$ 时同样进位到 $10(q+1)$。

这正是"四舍五入"在整数运算下的标准等价式，边界 $a = 0$（得 0）与 $a = 100$（得 100）都自然覆盖，无需特判。

### 3.3 算法流程

```text
1. rounded = (a + 5) / 10 * 10      # 整数除法
2. 返回 100 - rounded
```

### 3.4 示例演算

![三个用例的取整与余额演算](images/bw110_q1_walkthrough.svg)

| $a$ | $(a+5)/10$ | rounded | 余额 |
|-----|-----------|---------|------|
| 9 | 1 | 10 | 90 |
| 15 | 2 | 20 | 80 |
| 10 | 1 | 10 | 90 |
| 4 | 0 | 0 | 100 |
| 5 | 1 | 10 | 90 |

## 4. 算法细节

1. **整数除法即可**：C++ `/`、Python `//` 对非负数都是下取整；本题 $a \ge 0$，无负数除法的方向歧义。
2. **不要用 `round(a / 10.0) * 10`**：浮点路径有精度隐患（如 `round(2.5)` 的银行家舍入行为、二进制表示误差），整数式绝对安全。
3. **0 与 100 两个端点**：$a=0$ 时支付 0（余额 100），$a=100$ 时支付 100（余额 0），公式都正确——题面特别强调"0 也是 10 的倍数"。
4. **无溢出**：$a + 5 \le 105$，任何整数类型都够。

## 5. 正确性证明

**引理 1（分桶刻画）**：设 $a = 10q + r$（$0 \le r \le 9$）。最近的 10 的倍数在 $r \le 4$ 时为 $10q$，在 $r \ge 6$ 时为 $10q+10$，在 $r = 5$ 时 $10q$ 与 $10q+10$ 等距（按题意取 $10q+10$）。

**证明**：$|10q - a| = r$，$|10q + 10 - a| = 10 - r$。比较 $r$ 与 $10 - r$：$r < 5$ 即 $r \le 4$ 时前者小；$r > 5$ 即 $r \ge 6$ 时后者小；$r = 5$ 时相等。∎

**引理 2（公式与刻画一致）**：$\lfloor (a+5)/10 \rfloor \times 10$ 等于引理 1 中确定的倍数。

**证明**：$a + 5 = 10q + (r + 5)$。$r \le 4$ 时 $r + 5 \le 9 < 10$，商为 $q$，结果 $10q$ ✓；$r \ge 5$ 时 $10 \le r + 5 \le 14 < 20$，商为 $q + 1$，结果 $10q + 10$ ✓（含 $r=5$ 的平局取大）。∎

**定理**：算法返回值 $100 - \mathrm{rounded}$ 即购买后的账户余额。

**证明**：由引理 1、2，`rounded` 恰为题面定义的实际支付金额（非负、10 的倍数、距离最小、平局取大）；余额 = 初始 100 − 支付额。∎

## 6. 复杂度分析

- **时间**：$O(1)$，一次加法、一次除法、一次乘法、一次减法。
- **空间**：$O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int accountBalanceAfterPurchase(int purchaseAmount) {
        int rounded = (purchaseAmount + 5) / 10 * 10;   // 四舍五入到 10 的倍数，平局取大
        return 100 - rounded;
    }
};
```

### Python

```python
class Solution:
    def accountBalanceAfterPurchase(self, purchaseAmount: int) -> int:
        rounded = (purchaseAmount + 5) // 10 * 10   # 四舍五入，平局取大
        return 100 - rounded
```

> 💡 两份代码均通过全部官方用例（`90`、`80`、`90`）；并对 $a = 0 \sim 100$ 全量 101 个值与"枚举全部 10 的倍数取最近（平局取大）"的独立暴力逐一对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **平局规则是"取大"**：15 → 20 而非 10；个位恰为 5 时必须进位。若误用"取小"，示例 2 就会输出 90。
2. **0 是合法倍数**：$a \le 4$ 时支付 0、余额 100；不要假设支付金额至少为 10。
3. **浮点陷阱**：`round()` 在 Python 3 中是**银行家舍入**（`round(15/10)*10 = 20` 恰好对，但 `round(25/10)*10 = 20` 而非 30）；C++ 的 `round` 虽是"四舍五入、平局远离零"，但中间经过浮点除法仍可能踩精度坑。整数式一并规避。
4. **负数不会出现**：约束 $a \ge 0$；若有负数需求，整数除法的向零截断会改变平局方向，需另行处理（本题无此情况）。
5. **余额可以为 0**：$a \ge 95$ 时支付 100，返回 0，不是错误。
