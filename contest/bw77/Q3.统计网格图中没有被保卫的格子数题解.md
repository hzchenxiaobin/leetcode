# LeetCode 统计网格图中没有被保卫的格子数 题解

## 1. 题目概述

- **标题 / 题号**：统计网格图中没有被保卫的格子数（#2257，medium）
- **链接**：https://leetcode.cn/problems/count-unguarded-cells-in-the-grid/
- **来源**：LeetCode 第 77 场双周赛 Q3
- **难度**：中等
- **标签**：数组、矩阵、模拟

**题意**：给定 $m \times n$ 网格、警卫数组 `guards` 与墙数组 `walls`。每个警卫能看到东、南、西、北四个坐标轴方向的所有格子，视线被**墙或另一个警卫**阻挡。一个格子若能被至少一个警卫看到则称**被保卫**。返回**空格子**中未被保卫的数目。

**约束**：

- $1 \le m, n \le 10^5$ 且 $2 \le m \cdot n \le 10^5$
- $1 \le guards.length,\ walls.length \le 5 \times 10^4$
- $2 \le guards.length + walls.length \le m \cdot n$
- `guards` 与 `walls` 内位置互不相同

## 2. 示例

**示例 1**

```text
输入：m = 4, n = 6, guards = [[0,0],[1,1],[2,3]], walls = [[0,1],[2,2],[1,4]]
输出：7
解释：三个警卫各自向四向投射视线，被墙与彼此阻挡；未被保卫的空格子共 7 个。
```

**示例 2**

```text
输入：m = 3, n = 3, guards = [[1,1]], walls = [[0,1],[1,0],[2,1],[1,2]]
输出：4
解释：警卫四邻全是墙，什么也看不到；4 个角落格子未被保卫。
```

**示例 3（边界补充）**

```text
输入：m = 2, n = 2, guards = [[0,0]], walls = [[1,1]]
输出：0
解释：警卫 (0,0) 看到整行 (0,1) 与整列 (1,0)；仅墙 (1,1) 非空格。答案 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个空格 $(i,j)$，沿四个方向逐格搜索直到越界、撞墙或撞到警卫，判断是否能看到某个警卫。单次判定最坏 $O(m+n)$，总计 $O(mn(m+n))$；$m \cdot n = 10^5$、$m + n$ 可达 $10^5$ 量级（细长网格）时约 $10^{10}$，超时。更致命的是写法上容易把「警卫挡视线」漏掉——警卫本身能被看到（它自己是遮挡物），但穿过它继续看后面的格子是错的。

### 3.2 核心观察：视线是逐格传递的，反向投射一遍即达 O(4mn)

![四向射线模型：警卫向四方向投射，遇墙/警卫停止](images/bw77_q3_ray_model.svg)

把「格子 $x$ 能否看到警卫」反过来问：「**警卫 $g$ 能看到哪些格子**」。警卫的视线是四条射线：沿某方向逐格前进，每格标记「被保卫」，一旦遇到**墙或另一个警卫**（两者同为遮挡物）立即停止。把墙与警卫统一编码为**遮挡格**后，投射规则只剩一条：越过遮挡格即断。

关键效率事实：每个格子每条射线至多被经过常数次（若对每个警卫独立投射，同一直线上的多个警卫会重复扫同一段），但由于每格只有「遮挡 / 已标记 / 空」三种状态且标记是**幂等**的，重复标记不改变结果、也不改变复杂度阶——总工作量 $O(4 \cdot m \cdot n)$。$m \cdot n \le 10^5$，稳过。

### 3.3 算法流程

![算法流程：标记遮挡 → 四向投射 → 统计](images/bw77_q3_algorithm_flow.svg)

```text
1. 建网格 g[m][n]，初始全 0（空）
2. 对每面墙 (r,c)：g[r][c] = 1            ┐ 遮挡物
   对每个警卫 (r,c)：g[r][c] = 1          ┘ 统一编码
3. 对每个警卫 (r,c)：
       对 4 个方向 (dr,dc)：
           (nr,nc) = (r+dr, c+dc)
           当 0 ≤ nr < m 且 0 ≤ nc < n 且 g[nr][nc] ≠ 1：
               g[nr][nc] = 2               # 标记被保卫
               (nr,nc) ← (nr+dr, nc+dc)    # 继续前进
           （g[nr][nc] == 1 或越界 → 该方向停止）
4. 答案 = g 中值为 0 的格子数
```

### 3.4 示例演算

![示例演算：示例 2 的 3×3 网格走查](images/bw77_q3_walkthrough.svg)

以示例 2（$3\times 3$，警卫 $(1,1)$，墙 $(0,1),(1,0),(2,1),(1,2)$）为例。墙与警卫统一标记为遮挡 `■` 后，网格为：

| | c0 | c1 | c2 |
|---|----|----|----|
| **r0** | 空 | ■ | 空 |
| **r1** | ■ | 警■ | ■ |
| **r2** | 空 | ■ | 空 |

从警卫 $(1,1)$ 向四向投射：北首格 $(0,1)$ 是墙——停；南首格 $(2,1)$ 是墙——停；西首格 $(1,0)$ 是墙——停；东首格 $(1,2)$ 是墙——停。**一个格子都没标到**。最终值为 0（未被保卫）的空格子是 $(0,0),(0,2),(2,0),(2,2)$ 四个角落，返回 $4$ ✓。

## 4. 算法细节

1. **遮挡物统一编码**：墙与警卫在「阻断视线」上等价，都写成状态 1。这把「遇墙停 **或** 遇警卫停」合并成一次判 `g[nr][nc] == 1`，既省分支又防漏判（漏判警卫挡视线是本题最常见 WA）。
2. **警卫自身也算被占据**：警卫所在格是遮挡格（值 1），不参与「未保卫空格」计数——计数只统计值 0 的格子，墙、警卫、被保卫格（值 2）统统排除。
3. **幂等标记换简洁**：值 2（已保卫）的格子再次被扫到时直接覆盖为 2，无害。若想更省，可在内层遇 2 时也继续、遇 1 停——本写法遇「非 1」都继续并置 2，语义一致。
4. **顺序无关性**：先标记全部遮挡物、再投射，保证投射时看到的遮挡格局是最终的；边投射边放警卫会漏掉「后来的警卫挡住先投射者视线」的情形。
5. **数据结构选择**：$m \cdot n \le 10^5$，二维 `vector<vector<int>>` / 嵌套 list 足够；无需 bitset（标记需要三态）。
6. **替代实现「四遍全扫」**：另写法是对每个方向做整表扫描（例如向上：逐列从下往上扫，记 `seen` 自上一遮挡物以来的可见状态）。那是 $O(4mn)$ 无重复的版本，本解法依赖幂等性达到同样的阶，代码更短。

## 5. 正确性证明

**引理 1（可见性刻画）**：空格 $x$ 被警卫 $g$ 保卫 $\iff$ $x$ 与 $g$ 同行或同列，且二者之间（不含端点）没有墙也没有警卫。

**证明**：警卫视线沿坐标轴方向直达。若 $x$、$g$ 不同行不同列，任何轴向射线都无法同时经过两者，$x$ 不可见。若同行（列同理），设 $x$ 在 $g$ 的某侧；警卫沿该方向的射线依次覆盖相邻格，被覆盖当且仅当射线未提前终止，即 $x$ 与 $g$ 之间无遮挡物；若中间有墙或警卫 $y$，视线在 $y$ 处截断，$x$ 在截断点之外不可见。∎

**定理（算法正确性）**：算法终止后 $g[i][j] = 0$ 当且仅当 $(i,j)$ 是未被任何警卫保卫的空格，故计数正确。

**证明**：先证**可信**（标记的都是真被保卫的）：若算法把某格标记为 2，它必是某警卫沿某方向逐格前进时经过的格；逐格前进仅在遇到值 1（墙或警卫）或越界时停止，故从该警卫到此格之间没有遮挡物，由引理 1 该格确被此警卫保卫。再证**完备**（被保卫的都被标记）：设空格 $x$ 被警卫 $q$ 保卫，由引理 1 二者之间无遮挡物；算法处理警卫 $q$ 沿该方向投射时，从 $q$ 出发逐格前进，每步检查「越界或值 1 才停」——$q$ 到 $x$ 的路径上全是值 0 或 2（无遮挡），前进不会中断，必经过 $x$ 并将其置 2（若已是 2 仍为 2）。两方向合流：标记集合 = 被保卫集合；而值 1 的格恰是墙与警卫占据格。于是 $g[i][j] = 0 \iff (i,j)$ 为空格且不被任何警卫保卫。∎

## 6. 复杂度分析

- **时间**：$O(mn + G)$，其中 $G = guards.length + walls.length$。建表 $O(mn)$；每个警卫向四方向投射，单格最多被 4 个方向的射线重复经过常数次（同一格在同一方向上可能被多个同线警卫重复标记），总量 $O(4mn)$；计数 $O(mn)$。
- **空间**：$O(mn)$。网格表本身；本题 $mn \le 10^5$，几十万字节可接受。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countUnguarded(int m, int n, vector<vector<int>>& guards,
                       vector<vector<int>>& walls) {
        // 0 空  1 墙/警卫（遮挡物）  2 已被保卫
        vector<vector<int>> g(m, vector<int>(n, 0));
        for (auto& w : walls)  g[w[0]][w[1]] = 1;
        for (auto& q : guards) g[q[0]][q[1]] = 1;
        constexpr int DR[4] = {-1, 1, 0, 0};
        constexpr int DC[4] = {0, 0, -1, 1};
        for (auto& q : guards) {                    // 每个警卫向四向投射
            int r = q[0], c = q[1];
            for (int d = 0; d < 4; ++d) {
                int nr = r + DR[d], nc = c + DC[d];
                while (0 <= nr && nr < m && 0 <= nc && nc < n && g[nr][nc] != 1) {
                    g[nr][nc] = 2;                  // 标记被保卫，继续前进
                    nr += DR[d];
                    nc += DC[d];
                }
            }
        }
        int ans = 0;
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                if (g[i][j] == 0) ++ans;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countUnguarded(self, m: int, n: int,
                       guards: list[list[int]], walls: list[list[int]]) -> int:
        g = [[0] * n for _ in range(m)]   # 0 空  1 墙/警卫（遮挡）  2 被保卫
        for r, c in walls:
            g[r][c] = 1
        for r, c in guards:
            g[r][c] = 1
        for r, c in guards:               # 每个警卫向四向投射
            for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):
                nr, nc = r + dr, c + dc
                while 0 <= nr < m and 0 <= nc < n and g[nr][nc] != 1:
                    g[nr][nc] = 2
                    nr += dr
                    nc += dc
        return sum(row.count(0) for row in g)
```

> 💡 两份代码均通过官方示例（`7`、`4`），并与「每个空格四向搜索警卫」的独立暴力对拍：C++ 600 组 + Python 3000 组随机网格（$m, n \le 7$，含警卫互挡、警卫贴墙、全遮挡等形态），另有 $250 \times 400$、5 万遮挡物的大规模性能验证（0.05 s），`mismatch = 0`。

## 8. 边界情况与易错点

1. **警卫挡视线**：警卫与墙一样会截断视线。只把墙当遮挡物会让视线穿透警卫，是本题最高频的错误。
2. **警卫所在格不计数**：答案统计的是**空格**中未保卫者；警卫格、墙格无论是否被别的警卫看到都不算。三态编码（空 / 遮挡 / 被保卫）天然区分。
3. **先放遮挡再投射**：必须先把所有墙与警卫标记完毕再开始投射，否则后放的遮挡物挡不住先前警卫已投射的视线（顺序依赖 bug）。本实现两阶段分离，无此隐患。
4. **重复标记无害但要心里有数**：同一直线上两个警卫会各自扫过中间格子两遍；靠幂等性结果不变，复杂度仍是 $O(4mn)$。若改成「遇 2 也停」需小心同方向两个警卫相邻的退化情形。
5. **细长网格**：$m = 10^5$、$n = 1$ 时单条竖直射线长 $10^5$，总工作量仍 $\le 4mn = 4 \times 10^5$，无栈无递归（while 循环），不会爆栈。
6. **遮挡物数量上界**：$guards + walls \le 5 \times 10^4$ 级别，但即便 $= mn$（全遮挡），投射一步即停，反而更快；最坏情形是遮挡物稀疏的长射线。
