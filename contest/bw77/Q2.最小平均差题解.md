# LeetCode 最小平均差 题解

## 1. 题目概述

- **标题 / 题号**：最小平均差（#2256，medium）
- **链接**：https://leetcode.cn/problems/minimum-average-difference/
- **来源**：LeetCode 第 77 场双周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和

**题意**：给定下标从 0 开始、长度为 $n$ 的整数数组 `nums`。下标 $i$ 处的**平均差**定义为：前 $i+1$ 个元素的平均值与后 $n-i-1$ 个元素的平均值之差的绝对值，两个平均值都**向下取整**。返回平均差最小的下标；有多个并列时返回**最小**的下标。$0$ 个元素的平均值视为 $0$。

**约束**：

- $1 \le nums.length \le 10^5$
- $0 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [2,5,3,9,5,3]
输出：3
解释：下标 3 处：|(2+5+3+9)/4 − (5+3)/2| = |4 − 4| = 0，为最小平均差。
```

**示例 2**

```text
输入：nums = [0]
输出：0
解释：唯一下标。|0/1 − 0| = 0（右侧 0 个元素的平均值视为 0）。
```

**示例 3（边界补充）**

```text
输入：nums = [100000, 100000]
输出：0
解释：下标 0：|100000 − 0| = 100000；下标 1：|100000 − 0| = 100000。并列时返回更小下标 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$ 现场累加两侧的和再取平均：$O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时。瓶颈在于「前缀和、后缀和」被重复计算——每个 $i$ 都把左右两段各自重算一遍，而这些和之间只差一个元素的增量。

### 3.2 核心观察：前缀和增量递推，两侧和都不必重算

![前缀和递推模型：pre 与 total−pre](images/bw77_q2_prefix_model.svg)

记 $pre_i = \sum_{k=0}^{i} nums[k]$。从左往右扫一遍，$pre_i$ 由 $pre_{i-1} + nums[i]$ 增量得到；右侧和恰为 $total - pre_i$。于是每个下标的平均差可 $O(1)$ 算出：

$$\text{diff}_i = \left| \left\lfloor \frac{pre_i}{i+1} \right\rfloor - \left\lfloor \frac{total - pre_i}{n-i-1} \right\rfloor \right|,\qquad \text{diff}_{n-1} = \left\lfloor \frac{total}{n} \right\rfloor$$

（右侧分母 $n-i-1 = 0$ 时规定平均值为 $0$。）整体一趟 $O(n)$。

### 3.3 算法流程

```text
1. total = nums 全体元素之和（long long）
2. pre = 0，best = +∞，bestIdx = −1
3. 对 i = 0 .. n−1：
       pre += nums[i]
       left  = pre / (i+1)                  # 整数除法即向下取整
       right = (i == n−1) ? 0 : (total − pre) / (n−i−1)
       cur = |left − right|
       若 cur < best：best = cur，bestIdx = i
4. 返回 bestIdx
```

### 3.4 示例演算

![示例演算：六个下标的平均差表](images/bw77_q2_walkthrough.svg)

以示例 1（`nums = [2,5,3,9,5,3]`，$total = 27$）为例：

| $i$ | $pre_i$ | 左均值 | 右和 | 右均值 | 平均差 |
|-----|---------|--------|------|--------|--------|
| 0 | 2 | $2/1 = 2$ | 25 | $25/5 = 5$ | $\lvert 2-5 \rvert = 3$ |
| 1 | 7 | $7/2 = 3$ | 20 | $20/4 = 5$ | $\lvert 3-5 \rvert = 2$ |
| 2 | 10 | $10/3 = 3$ | 17 | $17/3 = 5$ | $\lvert 3-5 \rvert = 2$ |
| 3 | 19 | $19/4 = 4$ | 8 | $8/2 = 4$ | $\lvert 4-4 \rvert = \mathbf{0}$ |
| 4 | 24 | $24/5 = 4$ | 3 | $3/1 = 3$ | $\lvert 4-3 \rvert = 1$ |
| 5 | 27 | $27/6 = 4$ | 0 | $0$（规定） | $\lvert 4-0 \rvert = 4$ |

最小平均差 $0$ 首次出现在 $i = 3$，返回 $3$ ✓。

## 4. 算法细节

1. **求和必须用 64 位**：$n \le 10^5$、$nums[i] \le 10^5$，总和上界 $10^{10}$，远超 `int` 的约 $2.1 \times 10^9$。C++ 用 `long long` 累加；Python 原生大整数无此顾虑。
2. **向下取整 = 整数除法**：元素非负（$nums[i] \ge 0$），C++/Python 的整除都等于向下取整，直接用 `/` 与 `//`。若元素可负，C++ 整除向零取整需另行处理（本题不涉及）。
3. **除零防护**：$i = n-1$ 时右半长度为 0，平均差规定为 $\lfloor pre/n \rfloor$ 的绝对值（元素非负时非负），代码里用三目运算符把右均值置 0，等价。
4. **并列取最小下标**：更新条件用**严格小于** `cur < best`——后面的并列值不会覆盖先记录的下标，天然满足「最小下标」要求。
5. **一次遍历同时维护三个量**：`pre` 增量、`cur` 计算、`best/bestIdx` 更新，空间只需常数个变量，连前缀和数组都不必显式存。

## 5. 正确性证明

**引理 1（增量正确性）**：遍历到下标 $i$ 时，变量 $pre$ 的值等于 $\sum_{k=0}^{i} nums[k]$。

**证明**：对 $i$ 归纳。$i = 0$ 时进入循环体前 $pre = 0$，执行 `pre += nums[0]` 后 $pre = nums[0]$，成立。设下标 $i-1$ 结束时 $pre = \sum_{k=0}^{i-1} nums[k]$；下标 $i$ 轮执行 `pre += nums[i]` 后 $pre = \sum_{k=0}^{i-1} nums[k] + nums[i] = \sum_{k=0}^{i} nums[k]$。∎

**定理（算法正确性）**：一遍遍历后返回的 `bestIdx` 是使平均差最小的下标中最小的那个。

**证明**：由引理 1，每个下标 $i$ 处计算出的 $cur_i = \left\lvert \lfloor pre_i/(i+1) \rfloor - \bar{r}_i \right\rvert$（$\bar{r}_i$ 为右均值，$i = n-1$ 时按题意取 0）恰为题面定义的平均差。更新规则「$cur_i < best$ 时才覆盖」保证任意时刻 $(best, bestIdx)$ 满足：$best = \min_{j \le i} cur_j$ 且 $bestIdx$ 是取得该最小值的**首个**下标（相等时不覆盖）。遍历覆盖全部下标，故终止时 $bestIdx$ 是全局最小平均差的最小下标。∎

## 6. 复杂度分析

- **时间**：$O(n)$。先 $O(n)$ 求 `total`，再 $O(n)$ 一遍扫描，每个下标 $O(1)$ 计算；总计约 $3n$ 次加减与两次除法。
- **空间**：$O(1)$ 额外空间。只维护 `total / pre / best / bestIdx` 四个变量，未建前缀和数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumAverageDifference(vector<int>& nums) {
        int n = nums.size();
        long long total = 0;
        for (int x : nums) total += x;
        long long pre = 0;
        long long best = LLONG_MAX;                 // 最小平均差
        int bestIdx = -1;                           // 首个取到它的下标
        for (int i = 0; i < n; ++i) {
            pre += nums[i];
            long long left = pre / (i + 1);         // 整数除法 = 向下取整
            long long right = (i == n - 1) ? 0 : (total - pre) / (n - i - 1);
            long long cur = llabs(left - right);
            if (cur < best) {                       // 严格小于：并列保留下标更小者
                best = cur;
                bestIdx = i;
            }
        }
        return bestIdx;
    }
};
```

### Python

```python
class Solution:
    def minimumAverageDifference(self, nums: list[int]) -> int:
        n = len(nums)
        total = sum(nums)
        pre = 0
        best, best_idx = float('inf'), -1
        for i, x in enumerate(nums):
            pre += x
            left = pre // (i + 1)
            right = (total - pre) // (n - i - 1) if i < n - 1 else 0
            cur = abs(left - right)
            if cur < best:                          # 严格小于：并列保留下标更小者
                best, best_idx = cur, i
        return best_idx
```

> 💡 两份代码均通过官方示例（`3`、`0`），并与「每个下标重新求和 + `sum` 切片」的直接暴力对拍 2000 组随机数据（含 $n = 1$、全 $10^5$、全 0、并列平均差），`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出是头号陷阱**：$total$ 上界 $10^{10}$、$pre$ 同阶，`int` 必炸。C++ 必须全程 `long long`；常见 WA 就是累加用 `int` 在大样例上悄悄溢出成负数。
2. **末下标的右均值**：$i = n-1$ 时右半为空，规定均值为 $0$ 而不是除零崩溃。漏掉特分会 `SIGFPE`（整除 0）。
3. **并列取最小下标**：更新必须用严格 `<`。用 `<=` 会让并列时的较大下标覆盖，示例 3（两下标平均差并列）即错。
4. **向下取整 vs 四舍五入**：题面明确「向下取整到最近的整数」，整数除法直接满足；切勿先算浮点均值再 `round`——浮点误差加上舍入语义不同会引入偏差。
5. **负数不存在但别侥幸**：$nums[i] \ge 0$ 使整除与向下取整一致；若有负数（本题没有），C++ `/` 向零取整、Python `//` 向下取整，两者语义分叉，移植时要注意。
6. **$n = 1$**：唯一下标 0 的平均差是 $\lvert nums[0] - 0 \rvert$，循环正常覆盖，无需特判。
