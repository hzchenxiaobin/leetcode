# LeetCode 子数组按位或操作 题解

## 1. 题目概述

- **标题 / 题号**：子数组按位或操作（#898，medium）
- **链接**：https://leetcode.cn/problems/bitwise-ors-of-subarrays/
- **来源**：LeetCode 第 100 场周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、动态规划

**题意**：给定整数数组 `arr`，对每个**非空连续子数组**求所有元素的按位或，返回这些 OR 值中**不同**的个数。

**约束**：

- $1 \le \text{arr.length} \le 5 \times 10^4$
- $0 \le \text{arr}[i] \le 10^9$

> 💡 子数组有 $O(n^2)$ 个，但不同 OR 值远少于子数组个数——关键就在于「以某位置结尾的不同 OR 值很少」。

## 2. 示例

**示例 1**

```text
输入：arr = [0]
输出：1
解释：唯一子数组 [0] 的 OR 为 0。
```

**示例 2**

```text
输入：arr = [1,1,2]
输出：3
解释：子数组 OR 依次为 1,1,2,1,3,3，不同值只有 1、2、3。
```

**示例 3**

```text
输入：arr = [1,2,4]
输出：6
解释：可能的结果是 1、2、3、4、6、7，共 6 个。
```

## 3. 解题思路

### 3.1 暴力思路

枚举左右端点 $(l, r)$，边扩展边维护 OR，用哈希集合去重。时间 $O(n^2)$，$n = 5\times10^4$ 时约 $1.25 \times 10^9$ 次操作，超时。

### 3.2 核心观察：以 i 结尾的不同 OR 值至多 31 个

![OR 只会让 1 的位数增加](images/wc100_q3_distinct_or_concept.svg)

固定右端点 $i$，令 $S_i = \{\text{arr}[j] \mid \text{arr}[j+1] \mid \cdots \mid \text{arr}[i] : 0 \le j \le i\}$。当 $j$ 从 $i$ 递减到 $0$ 时，OR 值只会**单调增加**（按位包含意义下），每变化一次至少多出一个 1 位。数值 $\le 10^9 < 2^{30}$，最多 30 个二进制位，因此

$$|S_i| \le 31$$

更关键的是递推关系：

$$S_i = \{\text{arr}[i]\} \cup \{\, v \mid \text{arr}[i] : v \in S_{i-1} \,\}$$

于是只需**滚动维护** $S_{i-1}$ 这一个集合（大小 ≤ 31），用哈希集合去重，同时把每个 $S_i$ 并入全局答案集合 `all`。

总复杂度 $O(n \times 31)$，约 $1.5\times10^6$ 次位运算，非常快。

### 3.3 算法流程

![滚动维护 OR 集合](images/wc100_q3_rolling_flow.svg)

```text
all = ∅, cur = ∅
for x in arr:
    nxt = {x}                        # 子数组 [i, i]
    for v in cur:
        nxt.add(v | x)               # 之前以 i-1 结尾的，再或上 x
    all |= nxt
    cur = nxt
return |all|
```

### 3.4 示例演算

![示例演算：数组 1,2,4 的 OR 集合](images/wc100_q3_walkthrough.svg)

| 步骤 | `cur`（以 $i$ 结尾） | `all`（累计） | 累计个数 |
|------|----------------------|---------------|---------|
| $i=0,\ x=1$ | $\{1\}$ | $\{1\}$ | 1 |
| $i=1,\ x=2$ | $\{2,\ 1\mid 2=3\}$ | $\{1,2,3\}$ | 3 |
| $i=2,\ x=4$ | $\{4,\ 2\mid 4=6,\ 3\mid 4=7\}$ | $\{1,2,3,4,6,7\}$ | 6 |

六个不同的 OR 值 $1,2,3,4,6,7$，与题面一致。

## 4. 算法细节

1. **前一位的集合要整体保留**：`cur` 表示「以 $i-1$ 结尾」的全部 OR 值，必须整批并上 $x$ 后才能变成「以 $i$ 结尾」；漏掉任何一个旧值就会漏子数组。
2. **单独加入 `x`**：子数组 $[i,i]$ 的 OR 就是 `x` 本身，不能只靠「旧值 | x」得到（当 `cur` 为空时尤其明显）。
3. **集合去重**：C++ 用 `unordered_set<int>`，Python 用 `set`；`nxt` 每轮重建，避免污染旧集合。
4. **位宽**：$\text{arr}[i] \le 10^9 < 2^{30}$，所以 30 位；若数值范围扩大（如 $10^{18}$），上界变成 63。
5. **为什么不是 $2^{30}$**：单调性（只增不减的位集合）把「可能的 OR 值」压缩成一条链，链长 ≤ 位数 + 1，而不是所有子集。
6. **空间**：`cur` 与 `nxt` 各 ≤ 31 个元素，`all` 最多 $n \times 31$ 但实际远小（本例约数万），总体 $O(n \cdot B)$。
7. **是否可以用前缀和/差分**：OR 没有逆运算，不能用前缀 OR 直接相减，必须靠「按右端点滚动」的技巧。

## 5. 正确性证明

记 $B$ 为数值的二进制位数（本题 $B = 30$）。

**引理 1（滚动递推）**：对每个 $i \ge 0$，$S_i = \{\text{arr}[i]\} \cup \{\, v \mid \text{arr}[i] : v \in S_{i-1} \,\}$（约定 $S_{-1} = \emptyset$）。

**证明**：

- （$\subseteq$）任取 $j \le i$。若 $j = i$，OR 为 $\text{arr}[i]$；若 $j < i$，则
  $$\text{OR}(j..i) = \text{OR}(j..i-1) \mid \text{arr}[i],$$
  且 $\text{OR}(j..i-1) \in S_{i-1}$，故落在右侧集合。
- （$\supseteq$）$\text{arr}[i]$ 对应子数组 $[i,i]$；对任意 $v \in S_{i-1}$，存在 $j \le i-1$ 使 $v = \text{OR}(j..i-1)$，于是 $v \mid \text{arr}[i] = \text{OR}(j..i) \in S_i$。∎

**引理 2（集合大小上界）**：$|S_i| \le B + 1$。

**证明**：把 $S_i$ 的元素按对应左端点 $j$ 从大到小排列：$j = i, i-1, \dots, 0$，得到序列 $o_0, o_1, \dots, o_i$。由 OR 的定义，$o_{k+1} = o_k \mid \text{arr}[i-k-1]$，故 $o_k$ 的 1 位集合是 $o_{k+1}$ 的子集（单调不减）。若 $o_{k+1} \ne o_k$，则 $o_{k+1}$ 至少比 $o_k$ 多一个为 1 的位。位集合只有 $B$ 位，从空到满最多发生 $B$ 次变化，因此序列中不同值的个数 ≤ $B + 1$。$S_i$ 是这些值的集合，故 $|S_i| \le B+1$。∎

**引理 3（全局集合语义）**：循环进行到第 $i$ 步后，`all` $= \bigcup_{k \le i} S_k$。

**证明**：对 $i$ 归纳。初始 `all` 为空，成立。第 $i$ 步把 `nxt` 并入 `all`，而由引理 1，`nxt` 恰为 $S_i$；由归纳假设与并集结合律，`all` 变为 $\bigcup_{k \le i} S_k$。∎

**定理**：算法返回的值等于所有非空子数组 OR 值的不同个数。

**证明**：任意非空子数组 $[j,i]$ 的 OR 属于 $S_i$，故全体 OR 值的集合为 $\bigcup_{i} S_i$；由引理 3，循环结束时 `all` 正是该集合。集合大小即不同 OR 值的个数。∎

## 6. 复杂度分析

- **时间**：外层 $n$ 次，内层遍历 `cur`（由引理 2，大小 ≤ $B+1 = 31$），每次 $O(1)$ 位运算与哈希插入，总 $O(nB)$，约 $1.5\times10^6$ 次操作。
- **空间**：`cur`、`nxt` 各 $O(B)$；`all` 最多 $O(nB)$ 个不同值（实际远小），总体 $O(nB)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int subarrayBitwiseORs(vector<int>& arr) {
        unordered_set<int> all;                  // 所有出现过的 OR 值
        unordered_set<int> cur;                  // 以当前元素结尾的所有子数组 OR 值
        for (int x : arr) {
            unordered_set<int> nxt;
            nxt.insert(x);                       // 只含 x 的子数组 [i, i]
            for (int v : cur) nxt.insert(v | x);  // 之前以 i-1 结尾的再或上 x
            all.insert(nxt.begin(), nxt.end());
            cur.swap(nxt);
        }
        return (int)all.size();
    }
};
```

### Python

```python
class Solution:
    def subarrayBitwiseORs(self, arr: List[int]) -> int:
        all_or = set()                      # 所有出现过的 OR 值
        cur = set()                         # 以当前元素结尾的所有子数组 OR 值
        for x in arr:
            cur = {x} | {v | x for v in cur}  # 只含 x 的 + 之前结尾的再或上 x
            all_or |= cur
        return len(all_or)
```

## 8. 边界情况与易错点

1. **忘了单独加入 `x`**：当 `cur` 为空（第一个元素）时，`{v | x}` 为空，答案会少 1。
2. **`cur` 被原地修改**：若直接 `for v in cur: cur.add(v | x)`，遍历时修改集合在 Python 会抛 `RuntimeError`，C++ 中也可能无限增长；必须新建 `nxt`。
3. **`all` 与 `cur` 混淆**：`cur` 只保留「以当前元素结尾」的集合，`all` 才是累计答案；把 `cur` 当答案会漏掉之前的所有子数组。
4. **`0` 元素**：`arr = [0]` 时 `nxt = {0}`，答案 1；连续 `0` 不会引入新值，正常。
5. **位宽估计**：$10^9 < 2^{30}$，但 `2^30 = 1073741824 > 10^9`，所以最高位是第 29 位；写 31 或 32 作为上界都安全。
6. **`int` 溢出**：OR 不会超过 $2^{30}-1$，`int` 安全；若数值到 $10^{18}$ 需 `long long`（C++）——Python 无此问题。
7. **哈希性能**：`unordered_set` 在小集合（≤ 31 个元素）上开销可接受；若追求极致可用 `vector` 去重 + 排序，但没必要。
8. **不能用「前缀 OR」相减**：OR 无逆运算，$\text{OR}(l..r) \ne \text{pre}[r] - \text{pre}[l-1]$。

**延伸思考**：若把 OR 换成 **AND** 或 **GCD**，单调性同样成立（位只会减少 / 因子只会减少），同一套滚动集合解法仍然有效；若换成 **XOR**，则没有单调性，只能借助前缀异或 + 01-Trie 在 $O(n \log V)$ 内处理「不同异或值个数」类问题。若要求「每个不同 OR 值对应的子数组个数」，可以在 `cur` 中同时保存「该 OR 值对应的左端点区间长度」，滚动时累加区间长度即可。
