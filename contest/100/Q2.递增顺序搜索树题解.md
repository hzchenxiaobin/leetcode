# LeetCode 递增顺序搜索树 题解

## 1. 题目概述

- **标题 / 题号**：递增顺序搜索树（#897，easy）
- **链接**：https://leetcode.cn/problems/increasing-order-search-tree/
- **来源**：LeetCode 第 100 场周赛 Q2
- **难度**：简单
- **标签**：栈、树、深度优先搜索、二叉搜索树、二叉树

**题意**：给定一棵二叉搜索树的根 `root`，按**中序遍历**的顺序把它重新排列成一棵「递增顺序搜索树」：最左边的节点成为新的根，每个节点**没有左孩子**，只有**一个右孩子**，整棵树退化为一条向右的链，链上的值从左到右递增。

**约束**：

- 节点数在 $[1, 100]$ 之间
- $0 \le \text{Node.val} \le 1000$

> 💡 只允许**改接指针**，不能新建节点、也不应改变节点值的集合；中序遍历的顺序本来就天然升序。

## 2. 示例

**示例 1**

```text
输入：root = [5,3,6,2,4,null,8,1,null,null,null,7,9]
输出：[1,null,2,null,3,null,4,null,5,null,6,null,7,null,8,null,9]
解释：原树中序为 1,2,3,4,5,6,7,8,9，重接成一条纯右链。
```

**示例 2**

```text
输入：root = [5,1,7]
输出：[1,null,5,null,7]
解释：中序 1,5,7。
```

**示例 3**

```text
输入：root = [1]
输出：[1]
解释：单节点，原样返回。
```

## 3. 解题思路

### 3.1 暴力思路

先中序遍历把节点值收进一个数组，再按数组顺序新建一条右链。正确性显然，但**新建了节点**（改变了树的结构语义），且额外 $O(n)$ 空间；题目期望的是原地改接指针。

### 3.2 核心观察：中序顺序不变，只把「指针」改向

![中序顺序不变，指针改接成右链](images/wc100_q2_inorder_relink_concept.svg)

BST 的中序遍历结果本身就是升序序列，所以**节点的先后顺序完全不用变**。需要变的只是指针：

- 每个节点访问完它的左子树后，**左指针清空**（`left = null`）；
- 把它接到当前链表的**尾部**（`tail->right = node`），然后 `tail = node`；
- 再递归处理它的右子树。

用一个**哨兵节点** `dummy` 作为链表的「虚拟头」，可以省掉「第一个节点怎么接」的特判；最后返回 `dummy.right`。

### 3.3 算法流程

![示例演算：中序接力](images/wc100_q2_walkthrough.svg)

```text
dummy = new TreeNode(0); tail = dummy
inorder(node):
    若 node 为空: return
    inorder(node.left)        # 先处理更小的数
    node.left = null          # 不许再有左孩子
    tail.right = node         # 挂到链表尾部
    tail = node
    inorder(node.right)       # 再处理更大的数

inorder(root)
return dummy.right
```

### 3.4 示例演算

以示例 1 为例，中序访问序列为 $1,2,3,4,5,6,7,8,9$，链条逐步生长：

| 访问节点 | `tail.right` 接上 | 链（从左到右） |
|----------|-------------------|----------------|
| 1 | dummy → 1 | 1 |
| 2 | 1 → 2 | 1 → 2 |
| 3 | 2 → 3 | 1 → 2 → 3 |
| … | … | … |
| 9 | 8 → 9 | 1 → … → 9 |

层序输出恰为 `[1,null,2,null,3,null,4,null,5,null,6,null,7,null,8,null,9]`。

## 4. 算法细节

1. **哨兵节点**：`dummy.right` 最终指向新根（中序第一个节点）；哨兵本身不参与答案。
2. **先清左再挂右**：`node.left = null` 必须在 `tail.right = node` 之前或之后都可以，但必须在递归 `node.right` 之前完成，避免链条里残留左孩子。
3. **`tail.right = node` 会覆盖 `tail` 原来的右指针**：这是有意为之——原来的右指针指向的节点会在后面被访问并重新接上，不会丢失。
4. **最后一个节点的 `right`**：中序最后一个是整棵树最右的节点，它本来就没有右孩子，因此链尾天然终止，无需额外置空。
5. **递归深度**：$n \le 100$，递归安全；若 $n$ 很大（如 $10^5$ 的斜树）应改成显式栈的迭代中序。
6. **原地修改**：返回的树复用了原节点，没有新建（除哨兵），符合「重排」语义。
7. **值域与重复值**：题面未强调节点值互异；若存在重复值，中序结果非降，链仍然有序，方法不变。

## 5. 正确性证明

设树的中序访问序列为 $v_0, v_1, \dots, v_{n-1}$（按访问先后编号）。

**引理 1（中序升序）**：对 BST，$v_0 \le v_1 \le \cdots \le v_{n-1}$。

**证明**：中序遍历按「左子树 → 根 → 右子树」访问。对任意相邻访问的两个节点，要么前者是后者左子树中的最大节点（故前者 $\le$ 后者），要么后者是前者右子树中的最小节点（故前者 $\le$ 后者）。由传递性得整个序列非降。若 BST 中值互异，则严格递增。∎

**引理 2（链条不变式）**：在 `inorder` 处理完 $v_i$ 后（即刚执行完 `tail = v_i`），有：

1. `dummy.right = v_0`；
2. 对每个 $0 \le k < i$，`v_k.left = null` 且 `v_k.right = v_{k+1}`；
3. `v_i.left = null`，且 `tail = v_i`。

**证明**：对 $i$ 归纳。$i = 0$：访问 $v_0$ 时 `tail = dummy`，执行 `v_0.left = null`、`dummy.right = v_0`、`tail = v_0`，三条均成立。

设 $i-1$ 时成立，现在访问 $v_i$：算法先 `v_i.left = null`（条件 3 的 `left` 部分），再 `tail.right = v_i`、`tail = v_i`。此时 `tail` 原为 $v_{i-1}$，故新增 $v_{i-1}.right = v_i$（条件 2 的新增项），而旧的 $v_{i-1}.right$ 被覆盖——它指向的节点正是接下来要访问的 $v_i$ 或其后继，覆盖不会丢失未访问节点（访问顺序由递归调用的实参决定，指针覆盖发生在读取之后）。其余 $k < i-1$ 的指针未被修改。∎

**引理 3（中序访问序列由递归确定，与指针改接无关）**：算法对右子树的递归调用使用了调用时刻的 `node.right`，而 `node.right` 只有在 `node` 被访问之后才可能被覆盖，因此访问序列与原始树的中序完全一致。

**证明**：对节点 `node`，算法顺序为 `inorder(node.left)`、挂接、`inorder(node.right)`。挂接只修改 `tail.right`（`tail` 为刚访问的节点，可能是 `node` 的祖先），不会修改尚未访问节点内部用于导航的指针；且 `inorder(node.right)` 的实参在调用前读取，之后即使被覆盖也不影响已进入的递归。由结构归纳，访问序列等于原树中序。∎

**定理**：算法返回的树是一棵以 $v_0$ 为根、只含右指针、链上值非降的「递增顺序搜索树」，且节点集合与原树相同。

**证明**：由引理 3，访问序列恰为原树中序 $v_0..v_{n-1}$，故节点集合不变。由引理 2，处理完 $v_{n-1}$ 后 `dummy.right = v_0`，且对每个 $k$，$v_k.left = null$、$v_k.right = v_{k+1}$（$k < n-1$）；链尾 $v_{n-1}$ 无右孩子。于是整棵树是一条以 $v_0$ 为根的纯右链，链上值由引理 1 非降。∎

## 6. 复杂度分析

- **时间**：每个节点恰好被访问一次（挂接 $O(1)$），总 $O(n)$。
- **空间**：递归栈深度等于树高 $O(h)$，最坏 $O(n)$（斜树）；除哨兵外没有新建节点，若改成迭代中序可把额外空间压到 $O(h)$ 的显式栈或 Morris 遍历的 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
    TreeNode* tail = nullptr;                    // 已接好链表的尾节点

    void inorder(TreeNode* node) {
        if (!node) return;
        inorder(node->left);                     // 左：先处理更小的数
        node->left = nullptr;                    // 每个人都不许再有左孩子
        tail->right = node;                      // 接到链表尾部
        tail = node;
        inorder(node->right);                    // 右：再处理更大的数
    }

public:
    TreeNode* increasingBST(TreeNode* root) {
        TreeNode dummy(0);                       // 哨兵，省掉"第一个节点"的特判
        tail = &dummy;
        inorder(root);
        return dummy.right;
    }
};
```

### Python

```python
class Solution:
    def increasingBST(self, root: Optional[TreeNode]) -> Optional[TreeNode]:
        dummy = TreeNode(0)                     # 哨兵，省掉"第一个节点"的特判
        cur = dummy

        def inorder(node: Optional[TreeNode]) -> None:
            nonlocal cur
            if not node:
                return
            inorder(node.left)                  # 左：先处理更小的数
            node.left = None                    # 每个人都不许再有左孩子
            cur.right = node                    # 接到链表尾部
            cur = node
            inorder(node.right)                 # 右：再处理更大的数

        inorder(root)
        return dummy.right
```

## 8. 边界情况与易错点

1. **忘记清空 `left`**：只改 `right` 会留下原左孩子，判题序列化时会出现多余节点（结构错误）。
2. **哨兵的生命周期**：C++ 里 `dummy` 是栈对象，返回 `dummy.right` 没问题（返回的是原树节点指针，不是哨兵）；但不要把 `dummy` 用 `new` 后忘记释放而误以为返回它。
3. **`tail` 的初始化**：每次调用都要重置 `tail = &dummy`，否则同一 `Solution` 对象被多次调用（如本地测试）会串联出错误结果。
4. **空树**：题目保证至少 1 个节点，但空树时应返回 `nullptr`，代码天然成立。
5. **单节点**：`left/right` 都为空，直接返回自身。
6. **斜树**：全左链或全右链时递归深度 $O(n)$，$n = 100$ 安全；若数据量放大需要迭代版。
7. **覆盖右指针的时机**：先挂接再递归右子树，且递归实参在调用时求值；如果先递归右子树再挂接，会把已改接的 pointer 结构弄乱。
8. **Morris 遍历**：可以做到 $O(1)$ 额外空间，但改接指针与线索化容易互相干扰，本题数据量下不值得。
