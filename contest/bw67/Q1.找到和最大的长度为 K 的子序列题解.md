# LeetCode 找到和最大的长度为 K 的子序列 题解

## 1. 题目概述

- **标题 / 题号**：找到和最大的长度为 K 的子序列（#2099，easy）
- **链接**：https://leetcode.cn/problems/find-subsequence-of-length-k-with-the-largest-sum/
- **来源**：LeetCode 第 67 场双周赛 Q1
- **难度**：简单
- **标签**：数组、排序、堆（优先队列）

**题意**：给定整数数组 `nums` 和整数 $k$，要从 `nums` 中选出一个长度为 $k$ 的**子序列**（保留元素在原数组中的相对顺序），使其元素**和最大**。题目保证答案存在，返回**任意**一个满足条件的子序列即可。

**约束**：

- $1 \le nums.length \le 1000$
- $-10^5 \le nums[i] \le 10^5$
- $1 \le k \le nums.length$

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,3,3], k = 2
输出：[3,3]
解释：子序列有最大和 3 + 3 = 6。
```

**示例 2**

```text
输入：nums = [-1,-2,3,4], k = 3
输出：[-1,3,4]
解释：子序列有最大和 -1 + 3 + 4 = 6。
```

**示例 3**

```text
输入：nums = [3,4,3,3], k = 2
输出：[3,4]
解释：子序列有最大和 3 + 4 = 7，另一个可行的子序列为 [4,3]。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $n$ 个位置中选 $k$ 个的方案数 $\binom{n}{k}$，逐一求和取最大——$n = 1000$、$k = 500$ 时是天文数字，显然不可行。稍加观察会发现，「子序列」这个限制其实非常松：它只要求**保留的元素相对顺序不变**，并不要求元素连续。也就是说，**任意一个大小为 $k$ 的下标子集都唯一对应一个合法子序列**（把下标从小到大取出即可）。于是问题退化为纯粹的「选哪 $k$ 个」，与顺序无关。

### 3.2 核心观察：和最大的 $k$ 个值 + 下标升序还原

![核心观察：按值选出最大的k个，再按原下标顺序输出](images/bw67_q1_topk_model.svg)

既然和只与「选出的元素集合」有关，那么和最大的充要条件就是：**选出值最大的 $k$ 个元素**（多重集意义上的前 $k$ 大）。相等的值无论选哪一个，和都相同，因此并列时任取。确定集合后，把这些元素按**原下标升序**输出，就自动得到了保序的子序列。

> 💡 **一句话总结**：先「按值挑」、再「按序排」。两步分别解决「和最大」与「是子序列」两个要求，互不干扰。

### 3.3 算法流程

![算法流程：下标按值排序、取前k、按下标升序输出](images/bw67_q1_algorithm_flow.svg)

```text
1. 生成下标数组 idx = [0, 1, ..., n-1]
2. 按 nums[idx] 的值从大到小排序 idx
3. 取 idx 的前 k 个，得到「值最大的 k 个元素」的下标集合
4. 将这 k 个下标升序排序（恢复原数组相对顺序）
5. 依次输出 nums[i]，即为答案
```

### 3.4 示例演算

![示例演算：nums=[-1,-2,3,4], k=3 的三步走查](images/bw67_q1_example_walkthrough.svg)

以示例 2（`nums = [-1,-2,3,4], k = 3`）为例：

| 步骤 | 状态 | 说明 |
|------|------|------|
| 按值降序排下标 | $[3, 2, 0, 1]$ | 值依次为 $4, 3, -1, -2$ |
| 取前 $k = 3$ 个 | $\{3, 2, 0\}$ | 值 $4, 3, -1$，和为 $6$，最大 |
| 下标升序 | $[0, 2, 3]$ | 恢复原数组顺序 |
| 输出 | $[-1, 3, 4]$ | 与官方示例一致 |

## 4. 算法细节

1. **对下标排序而非对值排序**：直接 `sort(nums)` 会丢失原位置信息。持有下标数组，一次比较器 `nums[a] > nums[b]` 就能按值排序，最后再 `sort` 一遍选中的下标即可保序。
2. **相等元素不必特殊处理**：值并列时任取 $k$ 个，和不变。`std::sort` 不稳定也无妨——题目只要求和最大，并列时任何选法都合法。
3. **快速选择优化（可选）**：只需要前 $k$ 大而非全部有序，C++ 可用 `nth_element` 把第 1 步降到 $O(n)$，随后对 $k$ 个下标排序 $O(k \log k)$；本题 $n \le 1000$，普通排序绰绰有余。
4. **数据规模**：$k \cdot \max|nums[i]| \le 10^8$，`int` 即可存下求和过程（本题甚至不需要显式求和）。
5. **另一种等价实现**：用大小为 $k$ 的最小堆扫一遍数组（堆里维护「当前最大的 $k$ 个值的下标」），弹出时同样按下标排序输出——即标签里的堆解法，复杂度 $O(n \log k)$，适合 $n$ 更大、$k$ 更小的流式场景。

## 5. 正确性证明

**引理 1（子序列与下标集合一一对应）**：任取下标集合 $S \subseteq \{0, 1, \dots, n-1\}$，$|S| = k$，将 $S$ 中下标按升序排列为 $i_1 < i_2 < \dots < i_k$，则 $(nums[i_1], \dots, nums[i_k])$ 是 `nums` 的子序列；反之，`nums` 的任何长度为 $k$ 的子序列都唯一确定一个大小为 $k$ 的下标集合。

**证明**：子序列的定义是「删除若干元素后不改变剩余元素顺序」。给定 $S$，删除下标不在 $S$ 中的元素，剩余元素恰好按 $i_1 < \dots < i_k$ 的原顺序排列，故是子序列。反之，一个子序列由其保留元素的位置集合唯一刻画。∎

**引理 2（和最大的集合是前 $k$ 大值）**：设 $T$ 为值最大的 $k$ 个元素构成的多重集（值降序排列的第 $1 \sim k$ 名），则对任意大小为 $k$ 的下标集合 $S$，$\sum_{i \in S} nums[i] \le \sum_{v \in T} v$。

**证明**：反设存在 $S$ 使 $\sum_{i \in S} nums[i] > \sum_{v \in T} v$。把 $S$ 的值按降序排为 $a_1 \ge a_2 \ge \dots \ge a_k$，$T$ 的值降序排为 $t_1 \ge t_2 \ge \dots \ge t_k$（$t_j$ 即全体值的第 $j$ 大）。若存在某个 $j$ 使 $a_j > t_j$，说明值 $\ge a_j \ge t_j + 1$ 的元素超过 $j$ 个，与 $t_j$ 是第 $j$ 大矛盾；故对所有 $j$ 都有 $a_j \le t_j$，从而 $\sum a_j \le \sum t_j$，与反设矛盾。∎

**定理**：算法的输出是 `nums` 的一个长度为 $k$ 的子序列，且其和等于所有长度为 $k$ 的子序列之和的最大值。

**证明**：算法第 3 步选出的正是值最大的 $k$ 个元素的下标集合（对下标按值降序排序后取前 $k$ 个，等价于值排名前 $k$），由引理 2 其和最大；第 4~5 步按下标升序输出，由引理 1 得到合法子序列。两者结合即证。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。下标按值排序 $O(n \log n)$ 为主导；取前 $k$ 为 $O(1)$（`resize` 截断），$k$ 个下标升序排序 $O(k \log k)$，输出 $O(k)$。若改用 `nth_element`，整体降为 $O(n + k \log k)$。
- **空间**：$O(n)$。下标数组 $O(n)$（快速选择可做到原地 $O(1)$ 额外空间），输出不计入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> maxSubsequence(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) { return nums[a] > nums[b]; });
        idx.resize(k);
        sort(idx.begin(), idx.end());                 // 恢复原下标顺序
        vector<int> ans;
        ans.reserve(k);
        for (int i : idx) ans.push_back(nums[i]);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxSubsequence(self, nums: list[int], k: int) -> list[int]:
        order = sorted(range(len(nums)), key=lambda i: nums[i], reverse=True)
        picked = sorted(order[:k])                 # 选中的下标升序，保持原顺序
        return [nums[i] for i in picked]
```

> 💡 两份代码均通过全部官方示例（`[3,3]`、`[-1,3,4]`、`[3,4]`），并通过 C++ 5000 组 / Python 4000 组随机数组的性质校验：输出长度恰为 $k$、确实为原数组的子序列（下标严格递增匹配）、且其和等于排序后前 $k$ 大值之和，全部一致。

## 8. 边界情况与易错点

1. **不能对值排序后直接输出**：必须保留「值来自哪个下标」的信息。示例 3 中输出 `[3,4]` 依赖下标 $(0, 1)$ 的相对顺序，若把值排序后直接截断，遇到并列值时可能输出一个顺序错误（但仍合法）或位置错误的组合——只要按下标还原就永远安全。
2. **$k = n$**：整个数组都是答案，算法自然成立（`resize` 不截断任何元素）。
3. **全负数组**：如 `nums = [-5,-2,-9], k = 2`，答案是较大的两个负数 `[-5,-2]`（按下标序），不要因为「负数不选最好」出错——长度必须恰为 $k$。
4. **并列值**：`[3,4,3,3], k = 2` 中值为 3 的元素有三个并列，任取即可；`sort` 的不稳定性不影响正确性。
5. **差一错误**：是「前 $k$ 大」不是「前 $k+1$ 大」，`resize(k)` / 切片 `[:k]` 都要注意边界。
6. **返回的是子序列不是子数组**：元素不必连续。若误用滑窗/连续子数组思路则方向错了。

**延伸思考**：本题是「前 $k$ 大」最裸的形态。当数据以流的形式到达、内存放不下整个数组时，标准做法是维护一个大小为 $k$ 的**最小堆**（堆顶是当前第 $k$ 大），每个元素与堆顶比较后决定入堆与否，单元素 $O(\log k)$——这正是本题「堆」标签的用武之地。再进一步，若要在海量数据里求「前 $k$ 大的精确和 + 并列打散」，还需要稳定的排序键或随机化 tie-break，避免并列元素被系统性地偏袒。
