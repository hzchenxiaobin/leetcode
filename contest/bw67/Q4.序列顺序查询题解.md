# LeetCode 序列顺序查询 题解

## 1. 题目概述

- **标题 / 题号**：序列顺序查询（#2102，hard）
- **链接**：https://leetcode.cn/problems/sequentially-ordinal-rank-tracker/
- **来源**：LeetCode 第 67 场双周赛 Q4
- **难度**：困难
- **标签**：设计、数据流、有序集合、堆（优先队列）

**题意**：维护一个景点排名系统，初始为空。景点由唯一的名字 `name` 与评分 `score` 组成，**评分越高越好；评分相同时名字字典序越小越好**。系统支持两种操作：

- `add(name, score)`：加入一个景点；
- `get()`：返回当前已添加景点中第 $i$ 好的景点，其中 $i$ 是**包括本次在内**的 `get` 调用次数（第 1 次返回第 1 好，第 2 次返回第 2 好……）。

题目保证任意时刻 `get` 的累计次数不超过景点总数。

**约束**：

- `name` 只含小写字母，且各景点名字互不相同，$1 \le name.length \le 10$
- $1 \le score \le 10^5$
- 任意时刻 `get` 次数 $\le$ `add` 次数
- `add` 与 `get` 的总调用次数 $\le 4 \times 10^4$

## 2. 示例

**示例（官方调用序列回放）**

```text
输入：
["SORTracker", "add", "add", "get", "add", "get", "add", "get", "add", "get", "add", "get", "get"]
[[], ["bradford", 2], ["branford", 3], [], ["alps", 2], [], ["orland", 2], [],
 ["orlando", 3], [], ["alpine", 2], [], []]

输出：
[null, null, null, "branford", null, "alps", null, "bradford", null, "bradford",
 null, "bradford", "orland"]

解释（最后一次 get 时全体景点从好到坏）：
branford(3) > orlando(3) > alpine(2) > alps(2) > bradford(2) > orland(2)
```

## 3. 解题思路

### 3.1 暴力思路

`add` 时把 $(score, name)$ 追加进数组；每次 `get` 前**全量排序**，取出第 $i$ 名。设总操作 $q = 4 \times 10^4$、景点数 $m$，最坏一半是 `get`：每次 $O(m \log m)$，总计 $O(q \cdot m \log m) \approx 2 \times 10^4 \times 2 \times 10^4 \times 15$ 次比较——数量级 $10^9$，比赛里大概率超时；而且每次 `get` 的排序结果与上次几乎相同，全部重排是纯粹的浪费。优化的方向自然是：**让有序性在 `add` 时就被增量维护，`get` 只做 $O(1)$ 或 $O(\log m)$ 的动作**。

### 3.2 核心观察：双参数全序 + 有序集合上的「游标」

![核心观察：按(-score, name)字典序排列的有序序列与游标](images/bw67_q4_cursor_model.svg)

把每个景点编码成二元组 $(-score, name)$，按**字典序**比较：

$$(-score_1, name_1) < (-score_2, name_2) \iff score_1 > score_2 \text{ 或 } (score_1 = score_2 \text{ 且 } name_1 < name_2)$$

由于名字互不相同，这是全体景点上的**严格全序**，且恰好就是「好 → 坏」的顺序（分数取负把「大者优」翻成「小者优」，与第二关键字「名字小者优」天然对齐，可直接复用默认比较器）。

用 `multiset`（有序多重集）把所有景点按此序维护。关键是在集合里放一个**游标** `cur`：

> **不变量**：设已调用 `get` 共 $k$ 次，则 `cur` 恒指向集合按好到坏排序的**第 $k+1$ 个**元素。

于是 `get()` = 读出 `cur` 指向的名字，然后 `cur` 右移一格（下次要第 $k+2$ 名）；`add()` = 插入新元素，若它插在 `cur` **之前**（比游标所指的更好），说明原第 $k+1$ 名被挤到第 $k+2$ 名，游标左移一格补位，否则游标不动。两个操作都只碰 $O(1)$ 个迭代器位置。

### 3.3 算法流程

![算法流程：add 三分支与 get 的游标移动](images/bw67_q4_add_cases.svg)

```text
初始化：ms = 空有序集；cur = ms.end()

add(name, score)：
    p = (-score, name)
    若 cur == ms.end()（目前 get 次数 == 元素个数）：
        插入 p；cur = prev(ms.end())        # 新的最差元素即下一个第 k+1 名
    否则若 p < *cur（新景点严格好于游标元素）：
        插入 p；--cur                        # 原第 k+1 名后移，游标左移
    否则：
        插入 p（插在游标之后，不影响前 k+1 名）

get()：
    ans = cur->name；++cur；返回 ans
```

### 3.4 示例演算

![示例演算：官方示例中游标的六次移动](images/bw67_q4_example_walkthrough.svg)

回放官方示例，跟踪「集合（好→坏）」与游标位置（**加粗**者为操作开始时 `cur` 所指，恰为第 $k+1$ 名）：

| 操作 | 集合（好→坏） | 游标动作 | get 返回 |
|------|--------------|----------|----------|
| add(bradford,2) | **bradford** | 空集分支：cur = 唯一元素 | — |
| add(branford,3) | **branford**, bradford | 新元素更好 → --cur | — |
| get #1 | **branford**, bradford | 读 branford；++cur | branford |
| add(alps,2) | branford, **alps**, bradford | alps 好于游标所指 → --cur | — |
| get #2 | branford, **alps**, bradford | 读 alps；++cur | alps |
| add(orland,2) | branford, alps, **bradford**, orland | orland 差于 bradford → 游标不动 | — |
| get #3 | branford, alps, **bradford**, orland | 读 bradford；++cur | bradford |
| add(orlando,3) | branford, orlando, alps, **bradford**, orland | orlando 更好 → --cur | — |
| get #4 | branford, orlando, alps, **bradford**, orland | 读 bradford；++cur | bradford |
| add(alpine,2) | branford, orlando, alpine, alps, **bradford**, orland | alpine 更好 → --cur | — |
| get #5 | branford, orlando, alpine, alps, **bradford**, orland | 读 bradford；++cur | bradford |
| get #6 | branford, orlando, alpine, alps, bradford, **orland** | 读 orland；++cur → end() | orland |

六次返回依次为 `branford, alps, bradford, bradford, bradford, orland`，与官方输出完全一致。注意两个细节：`add(orland,2)` 比游标所指的 bradford 差，插在游标之后，前 $k+1$ 名不受扰动；而 `get #6` 之后游标到达 `end()`（$k = m = 6$），此时若再来一次 `add` 就会触发 §3.3 的第一个分支——官方序列没有走到，但题面允许这种序列，随机对拍中专门覆盖了它。

## 4. 算法细节

1. **为什么存 $(-score, name)$**：C++ `multiset<pair<int,string>>` 的默认比较是字典序，取负分数后「分数大者在前、平分名字小者在前」自动成立，无需手写比较器；Python 里直接比较元组同理。
2. **multiset 迭代器的稳定性**：C++ 标准保证 `multiset::insert` **不失效**任何已有迭代器，被插入元素的新迭代器有效——这是游标方案合法性的基石（`vector` 就不行，插入可能触发扩容搬家）。
3. **`cur == end()` 分支是隐藏陷阱**：`get` 次数等于元素个数时（$k = m$，题面允许），游标已越到 `end()`，此时 `add` 若直接解引用 `*cur` 比较是未定义行为。正确处理：插入后把 `cur` 设为新的最差元素 `prev(ms.end())`（见 §5 引理 3）。
4. **`get` 的顺序**：先读后移。若先移后读会整体错位一名。
5. **Python 的双堆替代**：Python 标准库没有 `multiset`，可用两个堆镜像同一思想——左堆维护「最好的 $k+1$ 个」（按差为键的小顶堆，堆顶即第 $k+1$ 名），右堆维护其余（按好为键的小顶堆）。`add` 后左堆超编就把最差者弹出给右堆；`get` 读左堆顶后从右堆补一个最好的进左堆。平分时名字要「大者先出」，用反转字典序的字符串包装（`_Rev`）作堆键。
6. **复杂度对比**：multiset 方案 `add` $O(\log m)$、`get` $O(1)$；双堆方案两者都 $O(\log m)$。总调用 $\le 4 \times 10^4$，两种都轻松通过。

## 5. 正确性证明

**引理 1（全序性）**：在 $(-score, name)$ 的字典序下，任意两个不同景点可比较，且该序与题面「好 → 坏」一致。

**证明**：设 $p_1 = (-s_1, n_1), p_2 = (-s_2, n_2)$。若 $s_1 \ne s_2$，则 $-s_1 < -s_2 \iff s_1 > s_2$，分数高者序小（排前）；若 $s_1 = s_2$，字典序归结为 $n_1 < n_2$，名字小者排前。名字互不相同保证无相等元素，故为严格全序。∎

**引理 2（插入对名次的影响）**：向按全序排好的序列插入元素 $p$ 后，位于 $p$ 之后的原元素名次各加一，其余元素名次不变；特别地，若 $p$ 严格小于原第 $j$ 名，则新的第 $j$ 名是原第 $j-1$ 名。

**证明**：按序插入即把 $p$ 放进序列使整体仍有序。$p$ 之前的元素相对次序与自身位置不变，名次不变；$p$ 之后（严格大于 $p$ 的）元素统一后移一位，名次加一。若 $p <$ 原第 $j$ 名 $e_j$，则 $e_j$ 名次变为 $j+1$，而名次 $\le j-1$ 的元素都不动，故新的第 $j$ 名为原第 $j-1$ 名（$j \ge 2$ 时必存在）。∎

**引理 3（end 分支）**：设当前 `get` 次数为 $k$、元素个数 $m = k$（游标在 `end()`）。插入 $p$ 后，新的第 $k+1$ 名是集合的最差元素。

**证明**：插入后元素个数 $m + 1 = k + 1$，即全部 $k+1$ 个元素名次为 $1 \dots k+1$，第 $k+1$ 名就是最后一个（最差）元素，即 `prev(ms.end())`。∎

**定理（游标不变量）**：在任意操作序列后，设 `get` 累计次数为 $k$、集合非空，则 `cur` 指向集合按好到坏的第 $\min(k+1, m)$ 个元素；若 $k \ge m$ 则 `cur == end()`。

**证明**：对操作次数归纳。初始 $k = 0, m = 0$，`cur == end()`，命题成立（$\min(1, 0) = 0$，约定指向第 0 个即 end）。

归纳步一（`add(p)`）：设原状态 $m, k$ 满足不变量。
- 若 $k \ge m$（`cur == end()`）：由引理 3，插入后 `cur = prev(end())` 指向新的第 $\min(k+1, m+1) = m + 1$ 个（$m \le k \Rightarrow \min(k+1, m+1) = m+1$）即最差元素 ✓。
- 若 $k < m$（`cur` 指向第 $k+1$ 名 $e_{k+1}$，有效迭代器）：
  - $p < e_{k+1}$：由引理 2，插入后 $e_{k+1}$ 是第 $k+2$ 名，新的第 $k+1$ 名是原第 $k$ 名，即 `cur` 左移一位（`--cur`）所指 ✓（$k \ge 1$ 时原第 $k$ 名存在；$k = 0$ 时 $p$ 恰是新的第 1 名且插在 `cur` 之前，`--cur` 从原第 1 名移到 $p$ ✓）。
  - $p > e_{k+1}$：插入位置在游标之后，前 $k+1$ 名不变，`cur` 不动 ✓。
- $k$ 不变，归纳完成。

归纳步二（`get()`）：调用前置 $k \le m - 1$（题面保证 $k+1 \le m$），`cur` 指向第 $k+1$ 名，读出正确；`++cur` 后若 $k + 2 \le m$ 则指向第 $k+2$ 名，否则到 `end()`，与新的 $k+1$（$k$ 已加一）匹配 ✓。∎

**推论**：每次 `get` 返回的正是题面要求的第 $i$ 好景点。∎

## 6. 复杂度分析

- **时间**：multiset 方案单次 `add` $O(\log m)$（红黑树插入 + 至多一次迭代器移动）、单次 `get` $O(1)$；总计 $O(q \log q)$，$q \le 4 \times 10^4$。双堆方案单次 `add`、`get` 均摊 $O(\log m)$，总计同阶。
- **空间**：$O(m)$。有序集或两个堆存放全部景点，$m \le 4 \times 10^4$ 个 `(int, string)`。

## 7. 参考代码

### C++（multiset + 游标）

```cpp
class SORTracker {
public:
    SORTracker() : cur(ms.end()) {}

    void add(string name, int score) {
        pair<int, string> p{-score, name};        // 存 (-score, name)，默认序即「好 → 坏」
        if (cur == ms.end()) {                    // get 次数 == 元素个数
            ms.insert(p);
            cur = prev(ms.end());                 // 新的最差元素就是下一个要返回的
        } else if (p < *cur) {                    // 新景点严格好于游标元素
            ms.insert(p);
            --cur;                                // 游标元素名次后移一位，游标左移补位
        } else {
            ms.insert(p);                         // 插在游标之后，不影响前 k+1 名
        }
    }

    string get() {
        string ans = cur->second;                 // 游标所指即第 i 好景点
        ++cur;                                    // 下一次 get 取第 i+1 好
        return ans;
    }

private:
    multiset<pair<int, string>> ms;               // 按好到坏排序的有序多重集
    multiset<pair<int, string>>::iterator cur;   // 游标：指向「下一次 get 要返回」的元素
};
```

### Python（双堆）

```python
from heapq import heappush, heappop

class _Rev(str):
    """反转字典序比较的字符串包装：heapq 只用 <，把它变成「字典序大者更小」。"""
    def __lt__(self, other):
        return str.__gt__(self, other)

class SORTracker:
    def __init__(self):
        self._left = []      # 最好的 gets+1 个：按「差」为键的小顶堆，堆顶 = 其中最差
        self._right = []     # 其余景点：按「好」为键的小顶堆，堆顶 = 其中最好
        self._gets = 0

    def add(self, name: str, score: int) -> None:
        heappush(self._left, (score, _Rev(name)))
        if len(self._left) > self._gets + 1:       # 左堆超编：把最差的挪到右堆
            s, rn = heappop(self._left)
            heappush(self._right, (-s, str(rn)))

    def get(self) -> str:
        ans = str(self._left[0][1])                # 左堆堆顶 = 第 gets+1 好景点
        if self._right:                            # 扩编：右堆最好的补进左堆
            s, nm = heappop(self._right)
            heappush(self._left, (-s, _Rev(str(nm))))
        self._gets += 1
        return ans
```

> 💡 两份代码均回放官方调用序列，输出 `branford, alps, bradford, bradford, bradford, orland` 与官方一致；并与「每次 get 前全量重排取第 $i$ 名」的暴力 oracle 对拍 300 组随机操作序列（每组约 300 次操作、小分数域制造大量平分、随机穿插 `get` 追平 `add` 的场景），全部一致；另通过 $2 \times 10^4$ 次 `add` + $2 \times 10^4$ 次 `get` 的性能冒烟。

## 8. 边界情况与易错点

1. **游标在 `end()` 时 `add`**：$k = m$ 时（如 `add, get, add` 的序列）游标已越界，解引用 `*cur` 是未定义行为，必须走专门分支（§5 引理 3）。许多公开解法漏掉该分支——题面允许该序列，漏写属于潜在 UB。
2. **平分时的字典序方向**：评分相同**名字字典序小者更好**。存 $(-score, name)$ 后默认字典序恰好吃掉这一点；若手写比较器，注意两处方向不能只翻一处。
3. **`get` 先读后移**：`return cur->second; ++cur;` 的写法（读后立刻移动）与「先保存再移动再返回」等价，但「先 `++cur` 再返回」必错一位。
4. **堆键的平分处理**：Python 左堆要弹「最差」，键 $(score, name)$ 在平分时弹的是字典序**小**的名字——恰好不是最差的，必须反转名字比较（`_Rev` 包装或字符互补映射）。
5. **多测实例**：LeetCode 会新建多个 `SORTracker` 实例，成员变量在构造函数里初始化，别依赖静态/全局状态。
6. **名字唯一性**：题面保证名字互不相同，故全序严格、`multiset` 中无重复；若去掉该保证，`multiset` 版本依然正确（重复元素相邻不影响名次语义），双堆版本需在键里补充稳定性。
7. **`add` 在空集合上**：首个元素插入走 `cur == end()` 分支，`cur = prev(end()) = begin()`，正确指向第 1 名。
