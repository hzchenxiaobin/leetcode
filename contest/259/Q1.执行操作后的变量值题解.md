# LeetCode 执行操作后的变量值 题解

## 1. 题目概述

- **标题 / 题号**：执行操作后的变量值（#2011，easy）
- **链接**：https://leetcode.cn/problems/final-value-of-variable-after-performing-operations/
- **来源**：LeetCode 第 259 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、模拟

**题意**：存在一种只支持 4 种操作、只有 1 个变量 X 的编程语言：`"++X"` 与 `"X++"` 使 X 加 1，`"--X"` 与 `"X--"` 使 X 减 1。X 初值为 0。给定字符串数组 `operations`，返回依次执行全部操作后 X 的**最终值**。

**约束**：

- $1 \le n = \text{operations.length} \le 100$
- $\text{operations}[i]$ 只可能是 `"++X"`、`"X++"`、`"--X"`、`"X--"` 之一

> 💡 签到题抓两点：① 每个操作串长度固定为 3，且**下标 1 的字符就是符号位**——`"++X"`/`"X++"` 的 $\text{op}[1]$ 都是 `'+'`，`"--X"`/`"X--"` 的 $\text{op}[1]$ 都是 `'-'`，识别一个操作只需一次字符比较；② 加 1 减 1 满足**交换律**，最终值只取决于正负操作的个数、与顺序无关。从题面到代码的最短路径就是"一次扫描 + 一个计数器"。

## 2. 示例

**示例 1**

```text
输入：operations = ["--X","X++","X++"]
输出：1
解释：最初 X = 0；
      --X：X = 0 - 1 = -1
      X++：X = -1 + 1 = 0
      X++：X = 0 + 1 = 1
```

**示例 2**

```text
输入：operations = ["++X","++X","X++"]
输出：3
解释：三个操作全部是加 1，X = 0 + 1 + 1 + 1 = 3。
```

**示例 3**

```text
输入：operations = ["X++","++X","--X","X--"]
输出：0
解释：两加两减相互抵消，X = 1 + 1 - 1 - 1 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

按题面直译：对每个操作串做**四路完整字符串比较**——

```python
if op == "++X" or op == "X++":
    x += 1
elif op == "--X" or op == "X--":
    x -= 1
```

$n \le 100$、串长恒为 3，复杂度上毫无压力，**能过**。问题不在性能而在**代码冗长易错**：四路比较写漏一路、条件抄错一个字符都会 WA。签到题的追求是"从题面到代码的最短路径"——把四路分支压缩成一路判断，把逐条模拟升华成计数。

### 3.2 核心观察：中间字符定符号，计数即答案

![核心观察：下标 1 的字符就是符号位](images/wc259_q1_middle_char_concept.svg)

- **观察 1（中间字符定符号）**：四种操作串都是"**两个相同符号 + 一个 X**"，X 只在头或尾——`"++X"`/`"X++"` 是"符号符号X"/"X符号符号"，`"--X"`/`"X--"` 同理。无论 X 在头还是尾，**中间位置（下标 1）必然被符号占据**：

  ```text
  ++X : op[0]='+'  op[1]='+' ⭐  op[2]='X'
  X++ : op[0]='X'   op[1]='+' ⭐  op[2]='+'
  --X : op[0]='-'   op[1]='-' ⭐  op[2]='X'
  X-- : op[0]='X'   op[1]='-' ⭐  op[2]='-'
  ```

  于是 $\text{op}[1] = $ `'+'` 当且仅当效果为 $+1$，一次字符比较即可识别一个操作。注意**首、尾字符都不行**：$\text{op}[0]$ 为 `'X'` 时无法区分 `"X++"` 与 `"X--"`，$\text{op}[2]$ 为 `'X'` 时无法区分 `"++X"` 与 `"--X"`，唯独中间字符无歧义。

- **观察 2（计数即答案）**：$+1$ 与 $-1$ 的叠加满足交换律与结合律，最终值 $X = p - m$（$p$ 为加操作个数、$m$ 为减操作个数），**与执行顺序无关**。所以无需真正"模拟"，统计符号个数即可。

> 💡 这是"**识别冗余，降维到计数**"的典型签到套路：当操作效果可交换、操作种类有限且可 $O(1)$ 判别时，逐条模拟与计数等价，而后者的代码只有一个循环一行判断。

### 3.3 算法流程

![算法流程：一次扫描，中间字符定加减](images/wc259_q1_scan_flow.svg)

1. **初始化**：$x = 0$（变量 X 的初值）。
2. **遍历**每个操作串 $\text{op}$：
   - 若 $\text{op}[1] = $ `'+'`：$x \leftarrow x + 1$；
   - 否则（$\text{op}[1] = $ `'-'`）：$x \leftarrow x - 1$。
3. 遍历结束，返回 $x$。

> ⚠️ 判据必须落在 $\text{op}[1]$ 上，不要顺手写成 $\text{op}[0]$——`"X++"` 与 `"X--"` 的首字符都是 `'X'`，按首字符分支会把这两类全部误判。

### 3.4 示例演算

![示例演算：operations 为 --X, X++, X++ 的逐步执行](images/wc259_q1_walkthrough.svg)

以 `operations = ["--X","X++","X++"]` 为例逐步走查：

| 步 | 操作 | $\text{op}[1]$ | 效果 | 执行后 $x$ |
|---|---|---|---|---|
| 0 | （初值） | — | — | $0$ |
| 1 | `--X` | `'-'` | $-1$ | $-1$ |
| 2 | `X++` | `'+'` | $+1$ | $0$ |
| 3 | `X++` | `'+'` | $+1$ | $1$ ⭐ |

最终返回 $1$。三步的判断全部落在中间字符上，`"--X"` 与 `"X++"` 形态不同但判据统一。

## 4. 算法细节

1. **判据统一用下标 1**：`op[1] == '+'` 是唯一无歧义的单字符判据（见 §3.2 观察 1）。C++ 中 `string` 支持 `op[1]` 直接取字符，与 `'+'` 比较即可。
2. **每串一次比较**：无需 `substr`、无需整体相等比较、无需哈希表建立"串 → 效果"映射，识别成本 $O(1)$。
3. **计数式写法**：由观察 2，也可写成求和形式——Python 一行 `sum(1 if op[1] == '+' else -1 for op in operations)`，C++ 用 `accumulate` 加三元表达式同理，与循环累加完全等价。
4. **无需防御非法输入**：题目保证只有四种合法串，不必校验长度或字符集。
5. **规模极小**：$n \le 100$，$|x| \le 100$，任何整型都安全。

## 5. 正确性证明

**引理 1（符号位判定）**：对任意合法操作串 $s$：$s$ 为 `"++X"` 或 `"X++"` 当且仅当 $s[1] = $ `'+'`；$s$ 为 `"--X"` 或 `"X--"` 当且仅当 $s[1] = $ `'-'`。

**证明**：合法串只有四种，穷举其下标 1 的字符：`"++X"` 与 `"X++"` 均为 `'+'`，`"--X"` 与 `"X--"` 均为 `'-'`，故"$s[1] = $ `'+'`"与"$s \in \{$`"++X"`, `"X++"`$\}$"互为充要，负号情形对称成立。∎

**引理 2（顺序无关）**：设 $p$ 为效果 $+1$ 的操作个数、$m$ 为效果 $-1$ 的操作个数，则无论按何种顺序执行这 $n = p + m$ 个操作，最终 $X = p - m$。

**证明**：记每个操作的效果为 $e(\sigma) \in \{+1, -1\}$，执行过程为 $X = 0 + e(\sigma_1) + e(\sigma_2) + \cdots + e(\sigma_n)$。整数加法满足交换律与结合律，故该和与项的排列顺序无关，恒等于 $\sum_{i=1}^{n} e(\sigma_i) = p \cdot 1 + m \cdot (-1) = p - m$。∎

**定理**：算法返回按题目给定顺序执行全部操作后 X 的最终值。

**证明**：由引理 1，算法对每个操作以 $s[1]$ 正确判定其效果 $e(\sigma)$ 并累加，循环结束时 $x = \sum_i e(\sigma_i)$。由引理 2，此值与执行顺序无关，当然等于按给定顺序执行的结果，即 X 的最终值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个操作一次字符比较、一次加减；串长恒为 3，是常数开销。
- **空间复杂度**：$O(1)$。仅一个累加变量 $x$，无辅助数据结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int finalValueAfterOperations(vector<string>& operations) {
        int x = 0;
        for (const string& op : operations) {
            x += (op[1] == '+') ? 1 : -1;   // 中间字符就是符号位
        }
        return x;
    }
};
```

### Python

```python
class Solution:
    def finalValueAfterOperations(self, operations: List[str]) -> int:
        x = 0
        for op in operations:
            x += 1 if op[1] == '+' else -1  # 中间字符就是符号位
        return x
```

## 8. 边界情况与易错点

1. **别用 `op[0]` 或 `op[2]` 判符号**：`"X++"` 与 `"X--"` 首字符均为 `'X'`（歧义），`"++X"` 与 `"--X"` 尾字符均为 `'X'`（歧义），只有 `op[1]` 唯一确定符号。这是本题最高频的 WA 点。
2. **答案可为负**：全部是 `"--X"` 时返回 $-n$，属正常输出，不要画蛇添足地取非负。
3. **四路分支要写全**：若坚持 if-else 链，`"++X"`/`"X++"`/`"--X"`/`"X--"` 四种形态一个不能漏——前缀自增/自减与后缀自增/自减各有两种写法；用 `op[1]` 判据天然全覆盖。
4. **无需输入校验**：题目保证串的合法性，防御性检查（长度、字符集）纯属浪费。
5. **无溢出风险**：$n \le 100$，$|x| \le 100$，`int`（乃至 `int8`）都绰绰有余。
6. **本题题面无注入指令**：周赛题面若混入 "Create the variable..." 之类句子，按惯例忽略并标注即可，本题未出现。
