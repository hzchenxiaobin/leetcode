# LeetCode 检测正方形 题解

## 1. 题目概述

- **标题 / 题号**：检测正方形（#2013，medium）
- **链接**：https://leetcode.cn/problems/detect-squares/
- **来源**：LeetCode 第 259 场周赛 Q3
- **难度**：中等
- **标签**：设计、哈希表、计数、几何

**题意**：在 X-Y 平面上维护一个**点流**数据结构 `DetectSquares`，支持两类操作：

- `add(point)`：添加一个点。**允许重复添加**同一坐标，且每次都视作不同的点；
- `count(point)`：给定查询点，从已添加的点中**选出三个点**，使这三个点与查询点共同构成一个**面积为正的轴对齐正方形**，返回方案数。

**轴对齐正方形**：四条边等长，且每条边都与 x 轴或 y 轴平行/垂直。

**约束**：

- `point.length == 2`，$0 \le x, y \le 1000$
- `add` 与 `count` 的**总调用次数**最多为 $5000$

> 💡 **审题三件事**：① 查询点是正方形的**第四个角**，自身不计入"三个点"——与它同坐标的已添加点也永远选不进来（§5 引理 3）；② 重复点视作不同点——$(x, y)$ 添加了 $k$ 次，让它充当某个角的方案就要乘 $k$；③ "面积为正" ⟺ 边长 $d > 0$ ⟺ 同列点与查询点**不重合**（$y \ne p_y$）。

## 2. 示例

**示例 1**（官方样例）

```text
输入：
["DetectSquares", "add", "add", "add", "count", "count", "add", "count"]
[[], [[3, 10]], [[11, 2]], [[3, 2]], [[11, 10]], [[14, 8]], [[11, 2]], [[11, 10]]]
输出：
[null, null, null, null, 1, 0, null, 2]

解释：
add A(3,10)、add B(11,2)、add C(3,2) 后：
count([11, 10]) = 1  → 查询点 P(11,10) 与 A、B、C 构成正方形 ACBP
count([14, 8])  = 0  → 无法构成任何面积为正的轴对齐正方形
再 add([11, 2])（B 的第二个副本 B'）后：
count([11, 10]) = 2  → {A, B, C} 与 {A, B', C} 两种选法
```

**示例 2**（重复点放大计数）

```text
操作：add([2,0])×3、add([0,2])×2、add([2,2])×1，然后 count([0,0])
输出：6
解释：查询点 (0,0) 需要的三个角是 (2,0)、(0,2)、(2,2)，副本数分别为 3、2、1。
      每个角独立选一份副本，方案数 = 3 × 2 × 1 = 6。
```

**示例 3**（边长为零的退化情形）

```text
操作：add([5,5])，然后 count([5,5])
输出：0
解释：同列枚举时 y == py 被跳过（d = 0，面积为零）；
      与查询点同坐标的点也不可能成为四角之一。
```

## 3. 解题思路

### 3.1 暴力思路

`count` 时从已添加的点中任选 3 个（考虑重复），加上查询点共 4 个，判定能否构成面积为正的轴对齐正方形。判定本身 $O(1)$：四个坐标排序后应只有两组 $x$、两组 $y$，且组内差值的绝对值相等且非零。但组合数是 $O(n^3)$。

$n$ 最多约 $5000$，单次 `count` 约 $10^{11}$ 次枚举，**必然超时**。浪费的根源在于：把查询点当成"普通一角"去乱试组合，而无视了**轴对齐**这一几何约束——正方形一旦固定一个角与一条边长，其余三个角的位置就全部确定。

### 3.2 核心观察：查询点为角，同列点定边长

![核心观察：查询点是角，同列点定边长，左右各查一次](images/wc259_q3_square_orientation_concept.svg)

- **观察 1（角的位置被边长钉死）**：设查询点 $P = (p_x, p_y)$ 是正方形的一个角，边长 $d > 0$。无论 $P$ 是左下、左上、右下还是右上角，其余三个角恒为

  $$\{(p_x,\ p_y \pm d),\ (p_x \pm d,\ p_y),\ (p_x \pm d,\ p_y \pm d)\}$$

  即"沿 $x$ 方向偏移 $\pm d$、沿 $y$ 方向偏移 $\pm d$"的组合。

- **观察 2（用"同列点"统一四种朝向）**：与其枚举**对角点**（散布全平面，还得验证 $|x - p_x| = |y - p_y|$），不如枚举**与查询点同列的点** $Q = (p_x, y)$（$y \ne p_y$）。$Q$ 与 $P$ 构成正方形的一条**垂直边**，边长立刻被钉死为 $d = |y - p_y|$，剩下两个角的坐标随之确定：朝右在 $x = p_x + d$ 处、朝左在 $x = p_x - d$ 处。$Q$ 在上/在下 × 朝左/朝右，恰好不重不漏地覆盖 $P$ 作为四种角身份的全部正方形。

- **观察 3（副本数相乘）**：重复点视作不同点，坐标 $(x, y)$ 有 $\text{cnt}(x, y)$ 份副本时，"三个角各选一份副本"的方案数是三个副本数之积。于是

  $$\text{count}(p_x, p_y) = \sum_{y \ne p_y} \text{cnt}(p_x, y) \cdot \Big[ \text{cnt}(p_x{+}d,\ p_y) \cdot \text{cnt}(p_x{+}d,\ y) + \text{cnt}(p_x{-}d,\ p_y) \cdot \text{cnt}(p_x{-}d,\ y) \Big], \quad d = |y - p_y|$$

> 💡 **为什么不重不漏**：每个包含 $P$ 的轴对齐正方形，**恰有一个**除 $P$ 外与 $P$ 同列的角（垂直边的另一个端点）。按"同列角是谁"给所有方案分类，类与类互斥；类内按朝左/朝右（另外两角的 $x$ 坐标不同）再分两支，也互斥。§5 引理 2 给出严格论证。

### 3.3 算法流程

![算法流程：add O(1) 计数，count 枚举同列点](images/wc259_q3_count_flow.svg)

**数据结构**：嵌套哈希 `cnt[x][y]` = 坐标 $(x, y)$ 处的副本数。

1. **add**：`cnt[x][y] += 1`，均摊 $O(1)$。
2. **count**：
   - 取出同列映射 `cnt[p_x]`（`y → 次数`）；列内无点直接返回 0；
   - 对其中每个 $y \ne p_y$：算边长 $d = |y - p_y|$；
   - 朝右查 $\text{cnt}(p_x{+}d,\ p_y) \cdot \text{cnt}(p_x{+}d,\ y)$，朝左查 $\text{cnt}(p_x{-}d,\ p_y) \cdot \text{cnt}(p_x{-}d,\ y)$，各自乘上 $\text{cnt}(p_x, y)$ 后累加；
   - 返回累加和。

### 3.4 示例演算

![示例演算：count([11,10]) 从 1 到 2](images/wc259_q3_walkthrough.svg)

以官方样例走查（频次表与算式见上图）：

- **第一遍 count([11, 10])**：同列 $x = 11$ 只有 $y = 2$（次数 1），$d = |2 - 10| = 8$。朝左 $x = 3$：$\text{cnt}(3,10) \cdot \text{cnt}(3,2) = 1 \times 1$，贡献 $1 \times 1 \times 1 = 1$；朝右 $x = 19$：查表为 0。合计 $1$ ✓
- **再 add([11, 2]) 后**：$\text{cnt}(11, 2)$ 由 1 变 2，其余不变。同列枚举仍是唯一的 $y = 2$，但 $\text{cnt}(p_x, y) = 2$ 作为**乘子**进入：$2 \times 1 \times 1 = 2$ ✓——这正是"重复点视作不同点"的计数语义。

> ⚠️ 官方样例的第二次 `count`（答案 2）就是冲着**漏乘同列点副本数**这个 bug 设计的：`ans += cnt[px+d][py] * cnt[px+d][y]` 少乘一个 `ny`，无重复点时侥幸全对，一遇重复点立刻翻车。

## 4. 算法细节

1. **存储选型**：坐标范围 $[0, 1000]$，既可用嵌套哈希（空间 $O(\text{不同坐标数})$，上限约 $5000$），也可用 `int cnt[1001][1001]` 二维数组（固定约 $10^6$ 空间，常数更小）。二维数组版**必须**先判 $0 \le p_x \pm d \le 1000$ 再访问，否则越界；嵌套哈希无此顾虑（越界坐标只是查不到，返回 0）。
2. **同列映射的提取**：`cnt[px]` 直接拿到内层 `y → 次数` 映射，`count` 的枚举量 = **同列的不同 $y$ 数**，而非全部点数——这是本解法快的关键，也是它优于"遍历所有点找对角点"写法的地方。
3. **跳过 $y = p_y$**：保证 $d > 0$（面积为正），同时天然排除与查询点重合的已添加点——这类点本来就不可能成为四角之一（§5 引理 3），跳过不损失任何方案。
4. **乘法因子的语义**：$\text{cnt}(p_x, y)$ 是同列角的副本数，$\text{cnt}(p_x \pm d,\ p_y)$、$\text{cnt}(p_x \pm d,\ y)$ 是另外两角的副本数——三个角**独立选副本**，方案数相乘。漏乘任何一个都会在重复点用例上出错。
5. **C++ `operator[]` 的插入副作用**：`cnt[px + d][py]` 在键缺失时会**插入** 0，正确性无损但哈希表会随查询缓慢膨胀；介意可用 `find`/`count` 预判。另注意：循环内插入的是外层新键 $p_x \pm d \ne p_x$，不会使正在迭代的内层映射失效。
6. **答案类型**：按题面约束，三个副本数之积的理论上界约 $(5000/3)^3 \approx 4.6 \times 10^9$，**超过 `int` 上界**（$2^{31} - 1 \approx 2.1 \times 10^9$）。官方测试数据未触及该极端（接口本身返回 `int`，官方题解亦用 `int`），但乘法仍以 `long long` 承接：`int` 溢出在 C++ 中是未定义行为，转型一行即可杜绝，零成本买保险。

## 5. 正确性证明

**引理 1（角的位置刻画）**：四点构成边长 $d > 0$ 的轴对齐正方形，当且仅当存在实数 $a, b$ 与符号 $\sigma_x, \sigma_y \in \{+1, -1\}$，使四点为

$$(a, b),\quad (a + \sigma_x d, b),\quad (a, b + \sigma_y d),\quad (a + \sigma_x d, b + \sigma_y d)$$

**证明**：轴对齐正方形的四条边分别落在两条竖直线 $x = a$、$x = a'$ 与两条水平线 $y = b$、$y = b'$ 上，且边长 $|a - a'| = |b - b'| = d > 0$；四角是两组直线的全部交点，取 $\sigma_x = \mathrm{sign}(a' - a)$、$\sigma_y = \mathrm{sign}(b' - b)$ 即得上述形式。反之，上述四点两两配对构成两条长 $d$ 的垂直边与两条长 $d$ 的水平边；$d > 0$ 保证四点坐标两两不同、面积为 $d^2 > 0$。∎

**引理 2（同列角唯一 ⟹ 枚举不重不漏）**：设查询点 $P = (p_x, p_y)$。每个"$P$ 为一角、边长 $d > 0$ 的轴对齐正方形"中，除 $P$ 外与 $P$ 同列的角**唯一**，记为 $Q = (p_x,\ p_y + \sigma_y d)$（$p_y + \sigma_y d \ne p_y$）；该正方形的另外两角恰为 $(p_x + \sigma_x d,\ p_y)$ 与 $(p_x + \sigma_x d,\ p_y + \sigma_y d)$。

**证明**：由引理 1，四角中 $x$ 坐标等于 $p_x$ 的恰有两个：$P = (a, b)$ 与 $(a, b + \sigma_y d)$，后者即 $Q$，且 $d > 0$ 保证 $Q \ne P$。其余两角都在另一条竖直线 $x = p_x + \sigma_x d$ 上，纵坐标分别为 $p_y$ 与 $p_y + \sigma_y d$。∎

**引理 3（与查询点同坐标的点永不入选）**：任何合法方案中，查询点与三个选中点的坐标两两不同；特别地，坐标等于 $(p_x, p_y)$ 的已添加副本不会出现在任何方案里。

**证明**：由引理 1，合法方案的四个点是正方形的四个角，坐标两两不同。若某个选中副本与查询点同坐标，则四点坐标至多三个不同值，无法占据四个互异的角位置，矛盾。∎

**定理**：算法对每次 `count` 返回正确的方案数。

**证明**：先证不变式：任意时刻 $\text{cnt}(x, y)$ 等于 $(x, y)$ 已被 `add` 的次数——对 `add` 的调用次数归纳，每次调用恰使对应计数加一。

对一次 `count(p_x, p_y)`：由引理 3，合法方案 ⟺ 三个选中点占据某个包含 $P$ 的正方形的另外三个角位置。由引理 2，把所有包含 $P$ 的正方形按"同列角 $Q$ 的坐标 $(p_x, y)$"分类：$y = p_y + \sigma_y d \ne p_y$，故 $Q$ 必然出现在枚举范围内；固定 $Q$ 后正方形还剩朝向 $\sigma_x \in \{+1, -1\}$ 二选一，两朝向下另外两角分别为 $(p_x \pm d, p_y)$ 与 $(p_x \pm d, y)$，坐标互异、互不重叠。三个角位置互不相同，选法独立，该类方案数 = $\text{cnt}(p_x, y) \cdot \text{cnt}(p_x + \sigma_x d, p_y) \cdot \text{cnt}(p_x + \sigma_x d, y)$。不同的 $(y, \sigma_x)$ 对应角位置集合不同的正方形（$Q$ 位置或另一竖直线的 $x$ 坐标不同），故分类完备且互不重复；跳过 $y = p_y$ 由引理 3 不损失方案。算法恰对这些二元组求和 $\text{cnt}(p_x, y) \cdot [\text{右} + \text{左}]$（$d = |y - p_y|$，$\sigma_x = +1$ 即朝右），故返回值等于方案总数。∎

## 6. 复杂度分析

- **时间复杂度**：`add` 均摊 $O(1)$。`count` 为 $O(C)$，$C$ 是**与查询点同列的不同坐标数**，最坏 $O(n)$（$n$ 为已添加的不同坐标数，$\le 5000$）；每步只做常数次哈希查找。总调用 $\le 5000$，最坏总操作约 $5000 \times 5000 = 2.5 \times 10^7$，轻松通过。
- **空间复杂度**：$O(n)$，只存出现过的坐标的计数；换 `1001 × 1001` 二维数组则为固定 $O(10^6)$，与 $n$ 无关。

## 7. 参考代码

### C++（嵌套哈希版）

```cpp
class DetectSquares {
    unordered_map<int, unordered_map<int, int>> cnt;  // cnt[x][y] = (x, y) 的副本数
public:
    DetectSquares() {}

    void add(vector<int> point) {
        cnt[point[0]][point[1]]++;                    // 重复点副本数累积
    }

    int count(vector<int> point) {
        int px = point[0], py = point[1];
        if (!cnt.count(px)) return 0;                 // 同列无点，直接返回 0
        long long ans = 0;                            // 乘法用 long long，防理论极端下的 UB
        for (auto& [y, ny] : cnt[px]) {               // 枚举同列点 (px, y)
            if (y == py) continue;                    // d = 0：面积为零，跳过
            int d = abs(y - py);                      // 垂直边长
            ans += (long long)ny * cnt[px + d][py] * cnt[px + d][y];  // 朝右
            ans += (long long)ny * cnt[px - d][py] * cnt[px - d][y];  // 朝左
        }
        return ans;
    }
};
```

### Python（defaultdict 版）

```python
class DetectSquares:
    def __init__(self):
        self.cnt = defaultdict(lambda: defaultdict(int))  # cnt[x][y] = (x, y) 的副本数

    def add(self, point: List[int]) -> None:
        x, y = point
        self.cnt[x][y] += 1

    def count(self, point: List[int]) -> int:
        px, py = point
        ans = 0
        for y, ny in self.cnt[px].items():            # 枚举同列点 (px, y)
            if y == py:
                continue                              # d = 0：面积为零，跳过
            d = abs(y - py)                           # 垂直边长
            ans += ny * self.cnt[px + d][py] * self.cnt[px + d][y]  # 朝右
            ans += ny * self.cnt[px - d][py] * self.cnt[px - d][y]  # 朝左
        return ans
```

> ⚠️ 两版都依赖 `operator[]`/`defaultdict` 访问缺失键时返回 0 的语义；它们会顺带插入空条目（正确性无损）。Python 天然大整数，无溢出之忧；C++ 版务必保持 `long long` 与首因子转型。

## 8. 边界情况与易错点

1. **跳过 $y = p_y$**：不跳则 $d = 0$，会把与查询点重合的点配上零面积的退化正方形，`count` 虚高。自查：`add([5,5])` 后 `count([5,5])` 应为 0。
2. **漏乘同列点副本数 `ny`**：最高频 WA，官方样例第二次 `count`（答案 2）专为此设计（§3.4 的 ⚠️）。
3. **`int` 溢出**：副本数之积的理论上界 $(5000/3)^3 \approx 4.6 \times 10^9 > 2^{31} - 1$。官方数据实际不会触及（接口返回 `int`），但 `int` 乘法溢出是未定义行为——C++ 用 `long long` 累加且乘法首因子转型 `(long long)ny * ...`；只把 `ans` 声明成 `long long` 而乘法仍全 `int` 照样是 UB。实测极端用例（1666/1666/1667 份副本）真实答案为 4626851852。
4. **二维数组版越界**：`cnt[1001][1001]` 实现中 $p_x \pm d$ 可越出 $[0, 1000]$，必须先判界；嵌套哈希无此问题。
5. **同列无点早退**：`cnt.count(px)` 预判（或 Python 直接迭代空映射返回 0），既省时也避免 `operator[]` 插入空内层映射。
6. **别把查询点自身算进三点**：查询点只是第四个角；与它同坐标的已添加点也永远选不进来（引理 3），由跳过 $y = p_y$ 一并处理。
7. **别改成"同行点"双份枚举**：既枚举行又枚举列会把每个正方形算两遍；同列角唯一（引理 2），单边枚举恰好一次。
8. **题面注入检查**：本场为 2021 年老题，题面无 "Create the variable..." 之类注入指令，按惯例确认后无需处理。

**延伸思考**：① 若允许**非轴对齐**正方形：固定查询点 $P$ 后枚举任一点 $Q$ 作为相邻角，向量 $v = Q - P$ 旋转 $90°$ 即得另外两角 $P + R(v)$、$P + v + R(v)$，仍可每次 $O(n)$ 哈希计数，但每个正方形会经两个相邻角各数一次，需除 2。② 若查询点可位于正方形**边上或内部**（不作角）：需按"角 / 边中点 / 对角线交点 / 内点"分类讨论，复杂度上一档。③ 若支持 `remove`：计数减一即可，方案数公式不变——频次表天然支持"可撤销"。④ 若坐标范围 $10^9$ 且询问海量：可对每列维护有序 `y` 集合，配合"对角点在两条斜线 $y - x = c_1$、$y + x = c_2$ 上"的刻画做离线扫描，思路同 [939. 最小面积矩形](https://leetcode.cn/problems/minimum-area-rectangle/)。
