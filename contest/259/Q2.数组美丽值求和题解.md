# LeetCode 数组美丽值求和 题解

## 1. 题目概述

- **标题 / 题号**：数组美丽值求和（#2012，medium）
- **链接**：https://leetcode.cn/problems/sum-of-beauty-in-the-array/
- **来源**：LeetCode 第 259 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀最值、预处理

**题意**：给定下标从 0 开始的整数数组 `nums`。对每个**内部下标** $i$（$1 \le i \le n-2$），`nums[i]` 的**美丽值**分三档：

- **2 分**：`nums[i]` 严格大于**左侧所有**元素，且严格小于**右侧所有**元素；
- **1 分**：未满足 2 档条件，但相邻三元素严格递增 $\text{nums}[i-1] < \text{nums}[i] < \text{nums}[i+1]$；
- **0 分**：以上都不满足。

返回所有内部下标美丽值的**总和**。

**约束**：

- $3 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^5$

> 💡 比赛切入只需一眼：2 档条件里藏着**两个全称量词**——"对所有 $j < i$"与"对所有 $k > i$"，直接判定是每个 $i$ 两侧各扫一遍的 $O(n^2)$。把两个量词分别压缩成**前缀最大值**与**后缀最小值**，降维就完成了——这是与 [238. 除自身以外数组的乘积](https://leetcode.cn/problems/product-of-array-except-self/) 完全同构的前缀/后缀预处理套路，只是把"乘积"换成了"最值"。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]
输出：2
解释：唯一内部下标 i=1：nums[1]=2 严格大于左侧全部 [1]、
      严格小于右侧全部 [3] → 美丽值 2。
```

**示例 2**

```text
输入：nums = [2,4,6,4]
输出：1
解释：
- i=1（4）：左侧最大 2 < 4 ✓，但右侧最小 4，4 < 4 ✗ → 非 2 档；
            相邻 2 < 4 < 6 ✓ → 美丽值 1。
- i=2（6）：左侧最大 4 < 6 ✓，但右侧最小 4，6 < 4 ✗ → 非 2 档；
            相邻 4 < 6 < 4 ✗ → 美丽值 0。
总和 = 1。
```

**示例 3**

```text
输入：nums = [3,2,1]
输出：0
解释：i=1（2）：左侧最大 3 < 2 ✗ → 非 2 档；相邻 3 < 2 ✗ → 美丽值 0。
      严格递减数组全员 0 分。
```

## 3. 解题思路

### 3.1 暴力思路

按题面直译：对每个内部下标 $i$，向左扫全部元素取最大值、向右扫全部取最小值，判 2 档；不中再判相邻三元素。

```text
for i in 1..n-2:
    left_max  = max(nums[0..i-1])     # O(i) 次比较
    right_min = min(nums[i+1..n-1])   # O(n-i-1) 次比较
    if left_max < nums[i] < right_min: ans += 2
    elif nums[i-1] < nums[i] < nums[i+1]: ans += 1
```

时间复杂度 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，**必然超时**。瓶颈在于：相邻两个 $i$ 的"左侧最大"只差一个元素、"右侧最小"也只差一个元素——信息高度重叠却被整体重算。这正是**预处理**的信号：把重复扫描的侧信息一次性缓存成数组，之后每个 $i$ 查表 $O(1)$。

### 3.2 核心观察：量词压成最值，档位从高到低

![三档美丽值：全称量词压缩成前缀最大与后缀最小](images/wc259_q2_beauty_tiers_concept.svg)

- **观察 1（最值压缩全称量词）**：

  $$\big(\forall\, j < i:\ \text{nums}[j] < \text{nums}[i]\big) \iff \max_{j<i} \text{nums}[j] < \text{nums}[i]$$

  有限非空集合的最大值必然是集合的一员——**比所有元素大都等价于只比最大值大**。于是 $O(i)$ 次的全称检查被压缩成与"代表值"的一次比较。右侧对称：严格小于右侧所有元素 ⟺ 小于右侧最小值。预处理两个数组：

  - $\text{left\_max}[i] = \max(\text{nums}[0..i-1])$，从左向右递推，每步 $O(1)$；
  - $\text{right\_min}[i] = \min(\text{nums}[i+1..n-1])$，从右向左递推，每步 $O(1)$。

  预处理完成后，2 档判定就是两次比较：$\text{left\_max}[i] < \text{nums}[i] < \text{right\_min}[i]$。

- **观察 2（档位蕴含 → 判定顺序）**：若 2 档成立，则 $\text{nums}[i-1]$ 就在"左侧"里（$i \ge 1$）、$\text{nums}[i+1]$ 就在"右侧"里（$i \le n-2$），所以 $\text{nums}[i-1] < \text{nums}[i] < \text{nums}[i+1]$ **自动成立**——2 档是 1 档的全局加强。三档不是三个独立条件的并集，而是同一性质**强度递减的分层**：全局夹住 ⟹ 局部递增 ⟹ 其余。判定因此必须**从高档到低档**：先判 2 档，命中 $+2$ 跳过；未中再判相邻 $+1$。顺序反过来，每个 2 分位都会被相邻递增条件"截流"成 1 分（§5 引理 2 给出严格论证）。

> 💡 **record 视角**：$\text{left\_max}[i] < \text{nums}[i]$ ⟺ `nums[i]` 刷新前缀最大值（从左看的"新高"）；$\text{nums}[i] < \text{right\_min}[i]$ ⟺ 从右看的"新低"。得 2 分 ⟺ 既是前缀新高、又是后缀新低——一个位置要同时通过两端的"记录值"检验。

### 3.3 算法流程

![算法流程：两遍预处理加一遍从高到低的判定](images/wc259_q2_prefix_suffix_flow.svg)

1. **预处理 left_max**：哨兵 $\text{left\_max}[0] = -\infty$；$i$ 从 $1$ 到 $n-1$ 递推 $\text{left\_max}[i] = \max(\text{left\_max}[i-1],\ \text{nums}[i-1])$。
2. **预处理 right_min**：哨兵 $\text{right\_min}[n-1] = +\infty$；$i$ 从 $n-2$ 到 $0$ 递推 $\text{right\_min}[i] = \min(\text{right\_min}[i+1],\ \text{nums}[i+1])$。
3. **判定**：$i$ 从 $1$ 到 $n-2$，先判 $\text{left\_max}[i] < \text{nums}[i] < \text{right\_min}[i]$ 得 2 分；否则判 $\text{nums}[i-1] < \text{nums}[i] < \text{nums}[i+1]$ 得 1 分。
4. 返回累加和 `ans`。

三遍线性扫描，每步 $O(1)$，总计 $O(n)$。

### 3.4 示例演算

![示例演算：三个官方样例的查表走查](images/wc259_q2_walkthrough.svg)

以三个官方样例走查（完整表格见上图）：

- **示例 1** `[1,2,3]`：$i=1$ 时 $\text{left\_max}=1$、$\text{right\_min}=3$，$1 < 2 < 3$ 成立 → 2 分，总和 $2$。
- **示例 2** `[2,4,6,4]`：$i=1$ 时左侧最大 $2 < 4$ 通过、右侧最小 $4$ 使 $4 < 4$ **为假** → 降级判相邻 $2 < 4 < 6$ 成立 → 1 分；$i=2$ 时 $6 < 4$ 为假、相邻 $4 < 6 < 4$ 也假 → 0 分。总和 $1$。
- **示例 3** `[3,2,1]`：$i=1$ 时 $3 < 2$ 直接失败 → 0 分，总和 $0$。

> ⚠️ 示例 2 的 $i=1$ 是官方埋的**严格性陷阱**：`nums[1]=4` 与右侧最小值 $4$ 相等，$4 < 4$ 为假，不满足 2 档。若把比较写成 $\le$，此处会误判 2 档、输出 3。

## 4. 算法细节

1. **哨兵设计**：$\text{left\_max}[0] = \text{INT\_MIN}$、$\text{right\_min}[n-1] = \text{INT\_MAX}$（Python 用 $\pm\infty$），让 $i=1$ 与 $i=n-2$ 的首次递推无需特判。值域 $[1, 10^5]$ 与哨兵无碰撞风险。
2. **递推方向与信息方向一致**：前缀信息从左往右滚、后缀信息从右往左滚，每个元素在每条递推链上只被消费一次——这是前缀/后缀预处理的标准姿态。
3. **判定顺序固定 2 → 1**（观察 2）：高档未中才查低档；1 档判定只涉及下标 $i-1, i, i+1$，天然 $O(1)$，无任何预处理需求。
4. **空间的方向性**：`left_max` 可降为**滚动变量** `lm`——判定阶段本就从左向右走，与 `lm` 的维护方向一致，判完 $i$ 再并入 $\text{nums}[i]$ 即可。但 `right_min` 必须整存：判定走到 $i$ 时右侧元素"尚未到达"，后缀信息无法边走边算。**单向扫描至少要预存一端的信息**，这是方向的固有代价。
5. **答案范围**：$0 \le \text{ans} \le 2(n-2) < 2 \times 10^5$，`int` 充裕，无溢出风险。

## 5. 正确性证明

**引理 1（最值压缩）**：对 $i \ge 1$ 与任意值 $x$：所有 $j \in [0, i)$ 满足 $\text{nums}[j] < x$，当且仅当 $\text{left\_max}[i] < x$。

**证明**：（⇒）左侧集合 $\{\text{nums}[j] : 0 \le j < i\}$ 非空有限，其最大值可被某个 $j^\*$ 取得，即 $\text{left\_max}[i] = \text{nums}[j^\*] < x$。（⇐）任取 $j < i$，$\text{nums}[j] \le \text{left\_max}[i] < x$。∎

**引理 2（档位蕴含）**：若 $i \in [1, n-2]$ 满足 2 档条件（左侧全部 $< \text{nums}[i]$ 且 $\text{nums}[i] <$ 右侧全部），则 $\text{nums}[i-1] < \text{nums}[i] < \text{nums}[i+1]$。

**证明**：由 $i \ge 1$ 知 $i-1 \in \{j : 0 \le j < i\}$，故 $\text{nums}[i-1] < \text{nums}[i]$；由 $i \le n-2$ 知 $i+1 \in \{k : i < k \le n-1\}$，故 $\text{nums}[i] < \text{nums}[i+1]$。∎

**推论**：按"先 2 档后 1 档"的分支，每个内部下标被赋予且仅被赋予题面定义的档位分值——满足 2 档者得 2（其 1 档条件虽也成立，但分支已截断）；不满足 2 档而相邻递增者得 1；其余得 0。三档互斥完备。

**引理 3（递推正确性）**：递推式 $\text{left\_max}[i] = \max(\text{left\_max}[i-1], \text{nums}[i-1])$（配合哨兵 $\text{left\_max}[0] = -\infty$）对所有 $i \in [1, n)$ 产生 $\max(\text{nums}[0..i-1])$；`right_min` 对称成立。

**证明**：对 $i$ 归纳。$i = 1$：$\max(-\infty, \text{nums}[0]) = \text{nums}[0] = \max(\text{nums}[0..0])$。设 $i$ 成立，则 $\text{left\_max}[i+1] = \max(\text{left\_max}[i], \text{nums}[i]) = \max(\max(\text{nums}[0..i-1]), \text{nums}[i]) = \max(\text{nums}[0..i])$，其中末步用了 $\max$ 的结合律。∎

**定理**：算法返回 $\sum_{i=1}^{n-2} \text{beauty}(i)$。

**证明**：由引理 3，两个辅助数组各自实现其声称的含义；由引理 1，2 档分支的比较判定与题面的全称量词条件等价；1 档分支逐字对应题面。由引理 2 的推论，从高到低的分支结构给每个内部下标恰好分配其档位分值。各分值求和即为所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。三次单遍扫描——`left_max` 预处理一遍、`right_min` 预处理一遍、判定一遍，每步仅常数次比较与赋值。
- **空间复杂度**：$O(n)$。两个长度为 $n$ 的辅助数组；采用 §4 的滚动优化后只剩 `right_min` 一个（$n \le 10^5$ 下完全可接受，双数组版更对称易读）。

## 7. 参考代码

### C++（双辅助数组版）

```cpp
class Solution {
public:
    int sumOfBeauties(vector<int>& nums) {
        int n = nums.size();
        vector<int> left_max(n), right_min(n);

        left_max[0] = INT_MIN;                       // 哨兵：i=0 无左侧元素
        for (int i = 1; i < n; ++i)
            left_max[i] = max(left_max[i - 1], nums[i - 1]);

        right_min[n - 1] = INT_MAX;                  // 哨兵：i=n-1 无右侧元素
        for (int i = n - 2; i >= 0; --i)
            right_min[i] = min(right_min[i + 1], nums[i + 1]);

        int ans = 0;
        for (int i = 1; i <= n - 2; ++i) {
            if (left_max[i] < nums[i] && nums[i] < right_min[i])
                ans += 2;                            // 2 档：全局夹住
            else if (nums[i - 1] < nums[i] && nums[i] < nums[i + 1])
                ans += 1;                            // 1 档：相邻递增
        }
        return ans;
    }
};
```

### Python（滚动左最大版）

```python
class Solution:
    def sumOfBeauties(self, nums: List[int]) -> int:
        n = len(nums)
        right_min = [0] * n
        right_min[n - 1] = float("inf")          # 哨兵：i=n-1 无右侧元素
        for i in range(n - 2, -1, -1):
            right_min[i] = min(right_min[i + 1], nums[i + 1])

        ans = 0
        lm = nums[0]                             # 滚动左最大：与判定同向，可省一个数组
        for i in range(1, n - 1):
            if lm < nums[i] < right_min[i]:
                ans += 2                         # 2 档：全局夹住
            elif nums[i - 1] < nums[i] < nums[i + 1]:
                ans += 1                         # 1 档：相邻递增
            lm = max(lm, nums[i])                # 判定完 i 再并入，防止自己和自己比
        return ans
```

## 8. 边界情况与易错点

1. **严格比较**：`<` 误写成 `<=` 是本题最高频 WA——示例 2 的 $i=1$（$4 < 4$ 为假）就是官方埋的陷阱，误写后输出 3 而非 1。
2. **判定顺序**：先判 1 档会把 2 分位系统性截流成 1 分（引理 2）。自查用例：严格递增数组 `[1,2,3,4,5]` 的正确答案是 $2(n-2) = 6$，顺序写反只会得到 $n-2 = 3$。
3. **i 的范围**：$[1, n-2]$，两端不参与判定；$n = 3$ 时仅 $i = 1$ 一个位置。
4. **哨兵别装反**：`left_max[0] = INT_MIN`（无左侧）、`right_min[n-1] = INT_MAX`（无右侧）。
5. **滚动版的并入时机**：必须在判定完当前 $i$ **之后**再执行 `lm = max(lm, nums[i])`，否则当前元素混进"左侧"，$lm < \text{nums}[i]$ 恒假，2 档全军覆没。
6. **递推下标的差一错误**：`left_max[i]` 由 `nums[i-1]` 参与递推（不含 `nums[i]` 本身），`right_min` 对称——边界抄错会让判定系统性失真。
7. **溢出审计**：答案上界 $2(n-2) < 2 \times 10^5$、元素值 $\le 10^5$，`int` 充裕，无需 `long long`。
8. **题面注入检查**：本场题目为 2021 年老题，题面无 "Create the variable..." 之类注入指令，按惯例确认后无需处理。
