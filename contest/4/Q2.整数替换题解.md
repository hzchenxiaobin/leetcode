# LeetCode 整数替换 题解

## 1. 题目概述

- **标题 / 题号**：整数替换（#397，medium）
- **链接**：https://leetcode.cn/problems/integer-replacement/
- **来源**：LeetCode 第 4 场周赛 Q2
- **难度**：中等
- **标签**：贪心、位运算、记忆化搜索、动态规划

**题意**：给定正整数 $n$，反复执行以下替换直到 $n = 1$：

- $n$ 为偶数时**只能**替换为 $n/2$；
- $n$ 为奇数时**可以**替换为 $n+1$ 或 $n-1$。

返回把 $n$ 变成 $1$ 所需的**最少替换次数**。

**约束**：

- $1 \le n \le 2^{31}-1 = 2147483647$
- 偶数只有一种操作，奇数有两个选择，因此搜索树在每个奇数处二分裂
- 答案规模很小（$n = 2^{31}-1$ 时为 $32$），但 $n$ 本身很大，任何按数值枚举或正向填表的做法都不行，只能依赖 $n$ 的二进制位数

## 2. 示例

**示例 1**

```text
输入：n = 8
输出：3
解释：8 -> 4 -> 2 -> 1
      偶数只能除以 2，路径唯一。
```

**示例 2**

```text
输入：n = 7
输出：4
解释：7 -> 8 -> 4 -> 2 -> 1
      或 7 -> 6 -> 3 -> 2 -> 1
      两条路径都是 4 步；这一步 ±1 的选择在本例中打平。
```

**示例 3**

```text
输入：n = 4
输出：2
解释：4 -> 2 -> 1
```

## 3. 解题思路

### 3.1 暴力思路

把每个数看成状态、把每次替换看成一条边权为 $1$ 的边，答案就是从 $n$ 到 $1$ 的最短路。

- **朴素递归**：直接写出 $f(n) = 1 + \min\{f(n-1), f(n+1)\}$（$n$ 为奇数）、$f(2m) = 1 + f(m)$，不做记忆化。每个奇数分两支，递归量为 $T(n) \approx T((n-1)/2) + T((n+1)/2)$，即 $O(n)$ 个结点；$n$ 到 $2^{31}$ 时彻底不可行。
- **记忆化 / BFS**：加一个哈希表记录算过的状态就能过（实测 $n = 2^{31}-1$ 只访问约 90 个状态），但状态数没有紧的界，空间是 $O(S)$（$S$ 为实际访问的状态数），正确性论证也要绕回 DP 归纳。
- **贪心**：只看 $n$ 的二进制末尾两位，每轮 $O(1)$ 决策，时间 $O(\log n)$、空间 $O(1)$，是本题的标准解法。

关键问题是：**奇数时到底该 $+1$ 还是 $-1$？**

### 3.2 核心观察：末尾两位决定 ±1

![二进制末尾两位决定加减一](images/wc4_q2_greedy_bits.svg)

先把「$\pm 1$ 与紧随其后的 $/2$」打包成一步。对奇数 $n$，无论选哪边，下一步一定是偶数，于是

$$n \;\longrightarrow\; n\pm1 \;\longrightarrow\; \frac{n\pm1}{2}$$

两操作合成 2 步。设 $f(n)$ 为最少步数，则对奇数 $n \ge 3$（记 $k=(n-1)/2$）

$$f(n) = 2 + \min\bigl\{f(k),\; f(k+1)\bigr\}$$

于是问题变成：**$k$ 与 $k+1$ 谁的 $f$ 更小？** 答案由 $n$ 的末两位给出：

- $n \equiv 1 \pmod 4$，即二进制以 $01$ 结尾：$n-1$ 以 $00$ 结尾，除以 2 之后仍以 $0$ 结尾（偶数），可以继续白拿一次除法；而 $n+1$ 以 $10$ 结尾，除以 2 之后变成奇数，又要再决策一次。所以选 $n-1$。
- $n \equiv 3 \pmod 4$ 且 $n > 3$，即二进制以 $011$ 结尾（更一般地：末尾是一串 $1$）：$n+1$ 会把这串 $1$ 全部进位成 $100\cdots0$，随后连续多次除以 2 都不必决策；而 $n-1$ 只把末位清零，除以 2 后又回到奇数。所以选 $n+1$。
- **唯一例外 $n = 3$**：$3 \to 2 \to 1$ 只要 2 步，而 $3 \to 4 \to 2 \to 1$ 要 3 步。$3$ 虽然 $\equiv 3 \pmod 4$，但 $3+1 = 4$ 只换来一次除法，不划算，必须走 $-1$。

> 💡 **一句话记忆**：$n$ 是奇数时，「让 $n/2$ 之后还是偶数」就是好的选择。末尾 $01$ 减 1，末尾一串 $1$ 加 1（进位），只有 $3$ 这个退化情形例外。

### 3.3 算法流程

![贪心算法流程图](images/wc4_q2_algorithm_flow.svg)

```text
cnt = 0
while n > 1:
    if n 是偶数:            n = n / 2
    elif n == 3 或 n % 4 == 1: n = n - 1
    else:                   n = n + 1
    cnt += 1
return cnt
```

循环不变量：进入循环时 $cnt$ 是「已经把原始输入变成当前 $n$」所花的操作数，循环结束时 $n = 1$，故 $cnt$ 就是答案。判定顺序可以交换（$3 \bmod 4 = 3$，不会落进 $n \bmod 4 = 1$ 的分支），但先写 $n = 3$ 更能表达「这是例外」。

### 3.4 示例演算

![n = 13 的逐轮演算](images/wc4_q2_walkthrough.svg)

以 $n = 13 = 1101_2$ 为例，贪心路径 $13 \to 12 \to 6 \to 3 \to 2 \to 1$ 共 **5 步**：

| 步 | $n$ | 二进制 | 判定依据 | 操作 |
|----|-----|--------|----------|------|
| 0 | 13 | 1101 | 奇数，$13 \bmod 4 = 1$ | $n-1 = 12$ |
| 1 | 12 | 1100 | 偶数 | $n/2 = 6$ |
| 2 | 6 | 110 | 偶数 | $n/2 = 3$ |
| 3 | 3 | 11 | 奇数且 $n = 3$（特判） | $n-1 = 2$ |
| 4 | 2 | 10 | 偶数 | $n/2 = 1$ |
| 5 | 1 | 1 | 循环结束 | 返回 $cnt = 5$ |

若第 0 步改选 $+1$：$13 \to 14 \to 7 \to 8 \to 4 \to 2 \to 1$ 需要 6 步，比贪心多 1 步。反过来，$n = 15 = 1111_2$ 时 $+1$ 更优：$15 \to 16 \to 8 \to 4 \to 2 \to 1$ 只要 5 步，而 $15 \to 14 \to 7 \to 8 \to 4 \to 2 \to 1$ 要 6 步 —— 这正是「末尾一串 $1$ 加 1 进位」的收益。

## 4. 算法细节

1. **溢出**：$n$ 最大 $2^{31}-1$，此时 $n+1 = 2^{31}$ 已经超出 `int` 范围。C++ 里必须用 `long long` 承接 $n$（或先特判 $n = 2^{31}-1$）；Python 的整数无上限，无需处理。
2. **$n = 3$ 的特判**：写在 `n == 3 || n % 4 == 1` 里，与「末尾一串 $1$ 加 1」的规则区分开。漏判时 $3 \to 4 \to 2 \to 1$ 会返回 3。
3. **循环不变量**：`cnt` 与 `n` 必须同步更新（先改 `n` 再 `cnt++`，或反之，只要每轮恰好一次）。这类计数题常见的 bug 是某个分支忘了自增。
4. **位运算写法**：`n` 为正整数时 `n & 1` 判奇偶、`(n & 3) == 3` 代替 `n % 4 == 3`、`n >>= 1` 代替 `n /= 2` 都成立；但右移在有符号负数上是实现定义的，本题恒正，用 `long long` 即可安全。
5. **不需要记忆化**：贪心每轮只维护 $n$ 与 `cnt` 两个变量，空间 $O(1)$。记忆化 DFS 也能通过（每个奇数最多两个分支，访问的状态数远小于 $n$），但它要额外哈希表与递归栈，属于「能过但不是最优形态」。
6. **不要把两步合成一次循环**：虽然 $f(n) = 2 + \min\{f(k), f(k+1)\}$ 允许一次处理两步，但 $n = 3$、$n = 2$ 的边界会变得难写，可读性下降，收益仅是常数因子 2。
7. **不要对 $n$ 做正推 DP**：$f(n)$ 依赖 $f(n+1)$，下标会「往后跑」，正向填表不成立；要么记忆化递归，要么就用本题的贪心。

## 5. 正确性证明

设 $f(n)$ 为把 $n$ 变成 $1$ 的最少操作数，$f(1) = 0$。再设贪心算法对 $n$ 的输出为 $g(n)$。

**引理 1（偶数唯一）**：对任意 $m \ge 1$，$f(2m) = 1 + f(m)$。

**证明**：$2m$ 是偶数，合法操作只有 $2m \to m$ 一种，此后至少还要 $f(m)$ 步，故 $f(2m) = 1 + f(m)$。∎

**引理 2（奇数递推）**：设 $n \ge 3$ 为奇数，$k = (n-1)/2$，则 $f(n) = 2 + \min\{f(k), f(k+1)\}$。

**证明**：$n-1 = 2k$，$n+1 = 2k+2$，二者均为偶数。先 $n \to n-1$ 再 $n-1 \to k$ 用 2 步到达 $k$，先 $n \to n+1$ 再 $n+1 \to k+1$ 用 2 步到达 $k+1$，由 $f$ 的最优性取两者较小值。∎

**引理 3（相邻差至多 1）**：对任意 $m \ge 1$，$\lvert f(m+1) - f(m)\rvert \le 1$。

**证明**：对 $m$ 做强归纳。$m = 1$ 时 $f(1) = 0,\ f(2) = 1$，成立。设结论对一切小于 $m$ 的正整数成立。

- 若 $m$ 为偶数（$m \ge 2$）：$m+1$ 为奇数且 $\ge 3$，由引理 2 有 $f(m+1) = 2 + \min\{f(m/2), f(m/2+1)\}$；由引理 1 有 $f(m) = 1 + f(m/2)$。于是

  $$f(m+1) - f(m) = 1 + \min\{f(m/2), f(m/2+1)\} - f(m/2) \le 1,$$

  又由归纳假设 $f(m/2+1) \ge f(m/2) - 1$，得 $f(m) - f(m+1) \le f(m/2) - 1 - \bigl(f(m/2)-1\bigr) = 0$。故 $\lvert f(m+1)-f(m)\rvert \le 1$。

- 若 $m$ 为奇数（$m \ge 3$）：由引理 2，$f(m) = 2 + \min\{f((m-1)/2), f((m+1)/2)\}$；由引理 1，$f(m+1) = 1 + f((m+1)/2)$。归纳假设给出相邻的 $(m-1)/2$ 与 $(m+1)/2$ 的函数值相差不超过 $1$，即 $\min\{\cdot\} \ge f((m+1)/2) - 1$，于是 $f(m+1) - f(m) \le 0$，且 $f(m) - f(m+1) = 1 + \min\{\cdot\} - f((m+1)/2) \le 1$。

两种情形均得 $\lvert f(m+1) - f(m)\rvert \le 1$。∎

**引理 4（偶数不大于右邻奇数）**：对任意 $m \ge 1$，$f(2m) \le f(2m+1)$。

**证明**：由引理 1，$f(2m) = 1 + f(m)$；由引理 2，$f(2m+1) = 2 + \min\{f(m), f(m+1)\}$。再由引理 3 有 $\min\{f(m), f(m+1)\} \ge f(m) - 1$，故 $f(2m+1) \ge 1 + f(m) = f(2m)$。∎

**引理 5（奇数不小于右邻偶数）**：对任意 $m \ge 1$，$f(2m+1) \ge f(2m+2)$。

**证明**：$f(2m+2) = 1 + f(m+1)$；由引理 2 及引理 3，$f(2m+1) = 2 + \min\{f(m), f(m+1)\} \ge 2 + f(m+1) - 1 = 1 + f(m+1)$。∎

引理 4 与引理 5 合起来说明：**每个奇数都是「局部山峰」，与它相邻的两个偶数都不比它差**，所以奇数处的选择只要比出「哪个邻居更小」即可。

**定理**：对所有 $n \ge 1$，$g(n) = f(n)$。

**证明**：对 $n$ 做强归纳，设结论对一切小于 $n$ 的正整数成立。

- $n = 1$：$g(1) = f(1) = 0$。
- $n$ 为偶数：$g(n) = 1 + g(n/2) = 1 + f(n/2) = f(n)$，最后一步用了引理 1 与归纳假设。
- $n = 3$：$f(3) = 1 + f(2) = 2$，贪心输出 $g(3) = 2$，相等。
- $n = 4m+1$（$m \ge 1$）：两个候选是 $(n-1)/2 = 2m$ 与 $(n+1)/2 = 2m+1$。由引理 4，$f(2m) \le f(2m+1)$，故 $f(n) = 2 + f(2m) = 3 + f(m)$。贪心走 $n \to 4m \to 2m \to m$ 共 3 步，之后按归纳假设最优，即 $g(n) = 3 + g(m) = 3 + f(m) = f(n)$。
- $n = 4m+3$（$m \ge 1$，此时 $n \ge 7$）：两个候选是 $2m+1$ 与 $2m+2$。由引理 5，$f(2m+2) \le f(2m+1)$，故 $f(n) = 2 + f(2m+2) = 3 + f(m+1)$。贪心走 $n \to 4m+4 \to 2m+2 \to m+1$ 共 3 步，再由归纳假设 $g(m+1) = f(m+1)$，得 $g(n) = 3 + f(m+1) = f(n)$。

所有情形均有 $g(n) = f(n)$。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。若某轮 $n$ 为偶数，一轮就减半；若为奇数，则本轮变成 $n \pm 1$（偶数），下一轮除以 2，两轮后不超过 $(n+1)/2$。所以每两轮 $n$ 至少减半，循环轮数为 $2\log_2 n + O(1)$，每轮 $O(1)$ 次比较与算术运算。
- **空间**：$O(1)$。只维护当前值 $n$（C++ 中为 `long long`）与计数 `cnt`，与 $n$ 的规模无关，无递归栈、无哈希表。

对比：记忆化 DFS 的时间是 $O(S)$、空间 $O(S)$（$S$ 为可达状态数，实测远小于 $n$ 但无紧界）；朴素搜索最坏 $O(n)$ 条路径。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int integerReplacement(int n) {
        long long x = n, cnt = 0;   // n 最大 2^31-1，n+1 会溢出 int
        while (x > 1) {
            if (x % 2 == 0) {              // 偶数只有一种操作
                x /= 2;
            } else if (x == 3 || x % 4 == 1) {
                x -= 1;                    // 末尾 01：减 1，让 /2 后仍是偶数
            } else {
                x += 1;                    // 末尾一串 1：加 1 进位
            }
            ++cnt;
        }
        return (int)cnt;
    }
};
```

### Python

```python
class Solution:
    def integerReplacement(self, n: int) -> int:
        cnt = 0
        while n > 1:
            if n % 2 == 0:            # 偶数：唯一操作
                n //= 2
            elif n == 3 or n % 4 == 1:
                n -= 1                # 13 = 1101 -> 1100，除两次都还是偶数
            else:
                n += 1                # 15 = 1111 -> 10000，一次进位换四次除法
            cnt += 1
        return cnt
```

## 8. 边界情况与易错点

1. **$n = 1$**：一次操作都不需要，答案为 0。若把循环写成 `do-while` 或在循环外先 `cnt = 1`，会返回 1。
2. **$n = 3$**：唯一需要特判的奇数。漏掉它时全程走 $+1$ 会得到 3 而不是 2（$3 \to 4 \to 2 \to 1$）。
3. **溢出**：$n = 2147483647$ 时第一轮就执行 $n+1 = 2^{31}$。C++ 用 `int` 会溢出成负数，随后 `n % 2`、`n / 2` 全部失效甚至死循环；必须用 `long long`。
4. **$n = 2^{31}-1$ 的答案**：32 步。可以拿它做最大的边界用例，同时检验溢出与循环终止。
5. **$n$ 为 2 的幂**（如 $2^{30}$）：全程走偶数分支，答案恰为指数 30，是检验「偶数分支」是否写对的最简用例。
6. **判断顺序**：`n == 3` 与 `n % 4 == 1` 必须落在同一个「减 1」分支，否则 $3$、$7$ 会走错；若写成 `n % 4 == 1` 单独判、`n % 4 == 3` 走加 1，就漏掉了 $n = 3$。
7. **计数位置**：每个分支都要恰好 `cnt += 1` 一次；把自增写在 `if` 内部容易在某个分支漏掉，写在循环末尾最稳。
8. **不要用「先判断能否被 4 整除」代替取模**：`n & 3` 与 `n % 4` 对正整数等价，但混用时注意括号，`n & 3 == 3` 在 C++ 中会先算 `3 == 3`，必须写 `(n & 3) == 3`。

**延伸思考**：

- 把 $n$ 写成**带符号二进制** $n = \sum_i \varepsilon_i 2^i$（$\varepsilon_i \in \{-1,0,1\}$），一次 $\pm 1$ 就是给某一位定一个非零系数，一次除法就是右移一位。总步数约等于「最高位下标 $+$ 非零系数个数 $- 1$」，贪心正是在局部选择让非零系数更少的进位方式（类似非相邻形式 NAF）。用这个视角可以解释为什么「末尾一串 1 要进位」。
- 若操作改成「奇数只能 $-1$」，答案直接是「位数 $-1$ 加上 $1$ 的个数 $-1$」；允许 $+1$ 之后才有进位带来的优化空间。
- 若把「除以 2」换成「除以 $k$」，或每类操作代价不同，局部贪心立刻失效，应回到最短路 / 记忆化搜索，并在状态里带上余数信息。
- 若要求输出**具体路径**而不只是步数，贪心同样适用：每轮记录选择即可，空间仍是 $O(\log n)$（存路径）。
