# LeetCode 旋转函数 题解

## 1. 题目概述

- **标题 / 题号**：旋转函数（#396，medium）
- **链接**：https://leetcode.cn/problems/rotate-function/
- **来源**：LeetCode 第 4 场周赛 Q1
- **难度**：中等
- **标签**：数组、数学、动态规划

**题意**：把长度为 $n$ 的数组 `nums` 顺时针旋转 $k$ 位得到 $arr_k$，定义

$$F(k) = 0 \cdot arr_k[0] + 1 \cdot arr_k[1] + \cdots + (n-1) \cdot arr_k[n-1] = \sum_{i=0}^{n-1} i \cdot arr_k[i]$$

求 $F(0), F(1), \dots, F(n-1)$ 的最大值。直观理解：把数组看成一个环，每轮让末尾元素绕回开头，求「下标 × 元素」之和的最大值。

**约束**：

- $1 \le n \le 10^5$
- $-100 \le nums[i] \le 100$
- 生成的测试用例保证答案在 32 位整数范围内

## 2. 示例

**示例 1**

```text
输入：nums = [4,3,2,6]
输出：26
解释：
F(0) = 0*4 + 1*3 + 2*2 + 3*6 = 0 + 3 + 4 + 18 = 25
F(1) = 0*6 + 1*4 + 2*3 + 3*2 = 0 + 4 + 6 + 6  = 16
F(2) = 0*2 + 1*6 + 2*4 + 3*3 = 0 + 6 + 8 + 9  = 23
F(3) = 0*3 + 1*2 + 2*6 + 3*4 = 0 + 2 + 12 + 12 = 26
最大值是 F(3) = 26。
```

**示例 2**

```text
输入：nums = [100]
输出：0
解释：只有一个元素，F(0) = 0*100 = 0，n = 1 时也就只有这一个旋转。
```

## 3. 解题思路

### 3.1 暴力思路

按定义枚举 $k = 0,1,\dots,n-1$：每轮把数组真的旋转一位（切片复制是 $O(n)$），再花 $O(n)$ 求加权和，总计 $O(n^2)$。

$n = 10^5$ 时约 $10^{10}$ 次基本运算，必然超时。而且暴力明显浪费了一个事实：**$F(k)$ 与 $F(k-1)$ 之间只差「一个元素换了个位置」**，其余 $n-1$ 项的权重都是整齐地 $+1$。

### 3.2 核心观察：相邻两轮之差只有 $O(1)$ 项

![顺时针旋转一位后各元素权重的变化](images/wc4_q1_rotation_weight_shift.svg)

记 $S = \sum_{i=0}^{n-1} nums[i]$，$x = arr_k[n-1]$（第 $k$ 轮位于末尾的元素）。顺时针旋转一位后：

- 原来的 $arr_k[0..n-2]$ 整体右移一格，权重从 $i$ 变成 $i+1$；
- 末尾的 $x$ 绕回开头，权重从 $n-1$ 变成 $0$。

逐项比较 $F(k+1)$ 与 $F(k)$：

- 前 $n-1$ 个元素权重各 $+1$，贡献增加 $\sum_{i=0}^{n-2} arr_k[i] = S - x$；
- 尾元素 $x$ 权重从 $n-1$ 掉到 $0$，贡献减少 $(n-1)x$。

两者合并，得到**一阶递推**：

$$F(k+1) - F(k) = (S - x) - (n-1)x = S - n\,x, \qquad x = arr_k[n-1] = nums[n-1-k]$$

于是每个 $F(k)$ 都能由前一个 $O(1)$ 算出，$n$ 个值一次扫完——这正是标签里「数学 + 动态规划」的含义：**状态是 $F(k)$，转移只依赖 $S$ 和当前尾元素**。

### 3.3 算法流程

![一次遍历加滚动递推的算法流程](images/wc4_q1_recurrence_flow.svg)

1. 一次遍历求出 $S = \sum nums[i]$ 与 $F(0) = \sum i \cdot nums[i]$，令 $cur = F(0)$、$best = F(0)$。
2. 对 $k = 1, 2, \dots, n-1$：取 $x = nums[n-k]$，更新 $cur \leftarrow cur + S - n\,x$，再令 $best \leftarrow \max(best, cur)$。
3. 返回 $best$。

> 💡 为什么是 `nums[n-k]`：第 $k$ 轮要绕回开头的元素，正是第 $k-1$ 轮（即 $arr_{k-1}$）的末尾元素，由 $arr_{k-1}[n-1] = nums[(n-1)-(k-1)] = nums[n-k]$ 得到。$k$ 从 $1$ 取到 $n-1$，下标 $n-k$ 落在 $[1, n-1]$，不会越界。

### 3.4 示例演算

![示例 nums = [4,3,2,6] 的逐步演算表](images/wc4_q1_walkthrough_table.svg)

对 `nums = [4,3,2,6]`，$S = 15$，$F(0) = 0\cdot4 + 1\cdot3 + 2\cdot2 + 3\cdot6 = 25$：

| $k$ | $x = nums[4-k]$ | $\Delta = 15 - 4x$ | $F(k)$ | $best$ |
|-----|-----------------|--------------------|--------|--------|
| 0 | — | — | 25 | 25 |
| 1 | $nums[3] = 6$ | $15 - 24 = -9$ | 16 | 25 |
| 2 | $nums[2] = 2$ | $15 - 8 = 7$ | 23 | 25 |
| 3 | $nums[1] = 3$ | $15 - 12 = 3$ | 26 | 26 |

答案为 $26$，与官方输出一致。注意 $F$ **并不单调**（$25 \to 16 \to 23 \to 26$），不能提前退出，必须扫完所有 $n$ 个候选。

## 4. 算法细节

1. **求和只做一次**：$S$ 在整个递推过程中是不变量，先算好复用；不要每轮重新 `sum(nums)`，否则又退回 $O(n^2)$。
2. **64 位中间量**：$n = 10^5$、$|nums[i]| \le 100$ 时，$|F(k)|$ 的量级可达 $\frac{n(n-1)}{2} \cdot 100 \approx 5 \times 10^{11}$，远超 `int`。C++ 中 `S`、`cur`、`best` 都必须用 `long long`，乘法写成 `1LL * i * nums[i]`、`1LL * n * x`；返回值再收窄成 `int`（题目保证答案在 32 位内，中间值不保证）。
3. **下标映射**：第 $k$ 轮绕回的是 `nums[n-k]`（$k \ge 1$）。若写成 `nums[n-1-k]`，相当于把递推整体错开一轮，示例 1 会算出 35 而不是 26。
4. **`best` 初值取 $F(0)$，不要取 0**：元素可以为负，最大值本身可能 $\le 0$，例如 `nums = [-5,-3]` 时 $F(0) = -3$、$F(1) = -5$，答案是 $-3$。
5. **`n == 1` 的退化**：循环体执行 $0$ 次，直接返回 $F(0) = 0$，无需特判。
6. **不要真的旋转数组**：Python 的 `nums[-k:] + nums[:-k]`、C++ 的 `std::rotate` 每轮都是 $O(n)$，会把 $O(n)$ 打回 $O(n^2)$；本算法只需要「读一个元素」。
7. **同值数组自检**：若所有元素都是 $c$，则 $S = nc$、$x = c$，增量 $S - nx = 0$，所有 $F(k)$ 相同，答案恒为 $c \cdot \frac{n(n-1)}{2}$。这是最好用的对拍用例。

## 5. 正确性证明

**引理 1（旋转的坐标关系）**：对任意 $k \ge 0$，有 $arr_{k+1}[0] = arr_k[n-1]$，且 $arr_{k+1}[i] = arr_k[i-1]$（$1 \le i \le n-1$）。

**证明**：顺时针旋转一位即「整体右移一格、末位元素绕回首位」，这正是题面对 $arr_k$ 的定义，逐坐标展开即得。∎

**引理 2（差分公式）**：设 $S = \sum_{j=0}^{n-1} arr_k[j]$、$x = arr_k[n-1]$，则 $F(k+1) = F(k) + S - n x$。

**证明**：由引理 1，

$$F(k+1) = \sum_{i=0}^{n-1} i \cdot arr_{k+1}[i] = 0 \cdot x + \sum_{i=1}^{n-1} i \cdot arr_k[i-1]$$

令 $j = i-1$，则 $i = j+1$、$j$ 取遍 $0 \dots n-2$：

$$F(k+1) = \sum_{j=0}^{n-2} (j+1) arr_k[j] = \sum_{j=0}^{n-2} j\,arr_k[j] + \sum_{j=0}^{n-2} arr_k[j]$$

其中前者 $= F(k) - (n-1)x$（$F(k)$ 去掉末项），后者 $= S - x$（总和去掉末项），故

$$F(k+1) = F(k) - (n-1)x + (S - x) = F(k) + S - n x$$

∎

**引理 3（下标对应）**：对 $1 \le k \le n-1$，有 $arr_{k-1}[n-1] = nums[n-k]$。

**证明**：$arr_k$ 的通式为 $arr_k[i] = nums[(i-k) \bmod n]$。取 $k-1$ 与 $i = n-1$：$(n-1-(k-1)) \bmod n = (n-k) \bmod n$。因 $1 \le k \le n-1$ 时 $1 \le n-k \le n-1$，取模无变化，故等于 $nums[n-k]$。∎

**定理**：算法返回 $\max_{0 \le k \le n-1} F(k)$。

**证明**：对 $k$ 归纳证明「第 $k$ 轮结束时 `cur` $= F(k)$」。$k=0$ 时由初始化 $cur = \sum i \cdot nums[i] = F(0)$ 成立。设第 $k-1$ 轮后 $cur = F(k-1)$，则第 $k$ 轮中由引理 3 取到的 $x = arr_{k-1}[n-1]$，由引理 2 更新后 $cur = F(k-1) + S - nx = F(k)$，归纳成立。循环覆盖 $k = 1 \dots n-1$，故 `cur` 依次遍历了全部 $n$ 个值，而 `best` 在每一步都取了 $\max$（含初值 $F(0)$），因此最终 `best` $= \max_{0 \le k \le n-1} F(k)$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。第一遍遍历同时求 $S$ 与 $F(0)$，$O(n)$；随后 $n-1$ 轮递推，每轮一次加法、一次乘法、一次比较，$O(1)$。总计 $O(n)$，$n = 10^5$ 时约 $2 \times 10^5$ 次基本运算，常数极小。
- **空间**：$O(1)$ 额外空间（$S$、$cur$、$best$ 与循环变量），输入数组不计入；不构造任何旋转副本。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxRotateFunction(vector<int>& nums) {
        int n = (int)nums.size();
        long long S = 0, cur = 0;
        for (int i = 0; i < n; i++) {
            S += nums[i];
            cur += 1LL * i * nums[i];          // F(0)
        }
        long long best = cur;                   // 初值必须是 F(0)，不能是 0
        for (int k = 1; k < n; k++) {
            long long x = nums[n - k];          // arr[k-1] 的末尾元素
            cur += S - 1LL * n * x;             // F(k) = F(k-1) + S - n*x
            if (cur > best) best = cur;
        }
        return (int)best;
    }
};
```

### Python

```python
class Solution:
    def maxRotateFunction(self, nums: list[int]) -> int:
        n = len(nums)
        S = sum(nums)
        cur = sum(i * v for i, v in enumerate(nums))   # F(0)
        best = cur                                      # 初值取 F(0)
        for k in range(1, n):
            x = nums[n - k]                             # arr[k-1] 的末尾元素
            cur += S - n * x                            # F(k) = F(k-1) + S - n*x
            if cur > best:
                best = cur
        return best
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有 $F(0) = 0 \cdot nums[0] = 0$。`range(1, 1)` 为空、`for k = 1; k < 1` 不成立，直接返回 0，代码无需特判。
2. **全负数组**：`[-5,-3]` → $F(0) = -3$、$F(1) = -5$，答案 $-3$。若把 `best` 初始化成 0，会错误输出 0。
3. **32 位溢出**：$F$ 的中间值可达 $5 \times 10^{11}$，C++ 里 `i * nums[i]`、`n * x` 必须写成 `1LL *` 形式；`long long` 不会溢出（$5\times10^{11} \ll 9.2\times10^{18}$），最后再转 `int` 返回。
4. **下标偏移**：绕回元素是 `nums[n-k]`；误写成 `nums[n-1-k]` 会让整个递推序列错位，示例 1 得到 35 而非 26。
5. **答案非单调**：示例 1 中 $F$ 是 $25 \to 16 \to 23 \to 26$，不能因为「变小了」就提前 break，也不能只比较相邻两项。
6. **别真的旋转**：切片刻副本或调用 `std::rotate` 会让复杂度退化为 $O(n^2)$；本算法每轮只读一个元素。

**延伸思考**：

1. 若要输出**取到最大值的 $k$**（多个取最小），只需在更新 `best` 时同步记录 `k`，仍是 $O(n)$。
2. 若把「旋转一位」换成「旋转 $d$ 位」，则 $F(k+d) = F(k) + dS - n \cdot \sum_{j=1}^{d} arr_k[n-j]$，多出来的是一段滑动窗口和；配合前缀和仍是 $O(n)$。
3. 若定义改成 $G(k) = \sum (i+1) arr_k[i]$，则 $G(k) = F(k) + S$，全部答案整体平移 $S$，最大值与 $F$ 相同——这类「权重整体加常数」的变形可以直接归约。
4. 若数组会被**动态修改**（单点更新 + 反复查询 $\max_k F(k)$），单点改 $nums[p]$ 会影响所有 $F(k)$ 的一个线性项，需要线段树维护 $\max$，本题的递推就不再够用了。
