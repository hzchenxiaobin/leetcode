# LeetCode 随机数索引 题解

## 1. 题目概述

- **标题 / 题号**：随机数索引（#398，medium）
- **链接**：https://leetcode.cn/problems/random-pick-index/
- **来源**：LeetCode 第 4 场周赛 Q3
- **难度**：中等
- **标签**：蓄水池抽样、哈希表、随机化、数学、设计

**题意**：数组 `nums` 中可能有重复元素。实现 `Solution(nums)` 与 `pick(target)`：每次调用返回一个下标 $i$ 使 `nums[i] == target`，且**每个合法下标被返回的概率相等**；`target` 保证在数组中出现。同一个对象上 `pick` 会被调用多次，每次都要独立地给出一次均匀分布的结果。

**约束**：

- $1 \le \text{nums.length} \le 2 \times 10^4$
- $-2^{31} \le \text{nums}[i] \le 2^{31}-1$，即 C++ 的 `int` 全值域
- `target` 一定是 `nums` 中的元素
- `pick` 最多被调用 $10^4$ 次
- 答案不唯一，评测按返回值是否落在合法集合以及整体分布判断

## 3. 解题思路

### 3.1 暴力思路

最直接的三种写法，各有各的短板：

1. **两遍扫描**：第一遍数出 `target` 出现次数 $c$，取 $k = \text{randrange}(c)$，第二遍找出第 $k$ 个 `target` 返回。它是正确的 $O(n)$ / $O(1)$ 做法，但**要求数组能被扫两次**，碰到流式输入或只能前进的迭代器就失效。
2. **预处理索引表**：`__init__` 里建「值 → 下标列表」的哈希表，`pick` 直接 `random.choice` 列表。查询 $O(1)$，代价是最坏 $O(n)$ 的额外空间，且数据一变就得重建。
3. **拒绝采样**：随机取一个下标，命中 `target` 就返回，否则重抽。条件在命中上均匀，但期望尝试 $n/c$ 次；当 $c = 1$ 时退化成期望 $n$ 次，单次调用耗时不可控。

能不能**一趟扫描、$O(1)$ 额外空间、严格均匀**？可以，这就是蓄水池抽样。

### 3.2 核心观察：容量为 1 的蓄水池抽样

![蓄水池抽样：第 j 个命中以 1/j 的概率替换候选](images/wc4_q3_reservoir_concept.svg)

设 `target` 在 `nums` 中出现的下标依次为 $i_1 < i_2 < \dots < i_c$，其中 $c$ 事先未知。做法只有一句话：

> 扫描到第 $j$ 个命中时，以 $\frac{1}{j}$ 的概率把候选答案换成当前下标，否则保持原值。

为什么这样能均匀？固定第 $j$ 个命中 $i_j$：它先在 $j$ 时刻以 $1/j$ 的概率被选中，之后每一个更晚的命中 $i_k$（$k > j$）都必须**没有**替换它，概率为 $(k-1)/k$。这些事件独立，于是

$$P(ans = i_j) = \frac{1}{j}\prod_{k=j+1}^{c}\frac{k-1}{k} = \frac{1}{j}\cdot\frac{j}{c} = \frac{1}{c}$$

乘积像望远镜一样逐项约掉。**要害在于分母是「当前命中序号」而不是总数**：越靠后的命中越难替换，恰好抵消「先来者更容易被挤掉」的偏差。全程既不需要知道 $c$，也不需要第二遍扫描。

### 3.3 算法流程 / 状态转移

![pick 的流程图：计数、抽样、替换](images/wc4_q3_reservoir_flow.svg)

```text
pick(target):
    cnt ← 0, ans ← -1
    for i from 0 to n-1:
        if nums[i] == target:
            cnt ← cnt + 1
            if randrange(cnt) == 0:      # 概率 1/cnt
                ans ← i
    return ans
```

用 $p_j^{(m)}$ 表示「处理完前 $m$ 个命中后，`ans` 恰为 $i_j$」的概率，则处理第 $m+1$ 个命中时

$$p_{m+1}^{(m+1)} = \frac{1}{m+1}, \qquad p_j^{(m+1)} = p_j^{(m)}\cdot\frac{m}{m+1}\ (j \le m)$$

初值 $p_1^{(1)} = 1$，归纳即得 $p_j^{(m)} = 1/m$：处理完 $m$ 个命中后，这 $m$ 个下标等概率。取 $m = c$ 就是答案。

### 3.4 示例演算

![示例数组上 pick(3) 的概率走查表](images/wc4_q3_prob_walkthrough.svg)

以 `nums = [1, 2, 3, 3, 3]`、`target = 3` 为例，命中发生在下标 2、3、4：

| 扫描位置 | cnt | 抽样动作 | ans 的分布 |
|---|---|---|---|
| $i = 2$ | 1 | 用 $1/1$ 的概率替换 | $P(2) = 1$ |
| $i = 3$ | 2 | 用 $1/2$ 的概率替换 | $P(2) = P(3) = 1/2$ |
| $i = 4$ | 3 | 用 $1/3$ 的概率替换 | $P(2) = P(3) = P(4) = 1/3$ |

验算第一步到第三步：$P(ans = 2) = 1 \times \frac{1}{2} \times \frac{2}{3} = \frac{1}{3}$；$P(ans = 3) = \frac{1}{2} \times \frac{2}{3} = \frac{1}{3}$；$P(ans = 4) = \frac{1}{3}$。三者相加为 1，与预期一致。

## 4. 算法细节

1. **状态必须是局部变量**：`cnt` 与 `ans` 在每次 `pick` 开头重置为 `0` 与 `-1`。若把它们放进对象成员，第二次调用会接着上次的计数往下数，分母全错，分布立刻崩掉。
2. **随机数必须取自 $[0, \text{cnt})$ 且均匀**：Python 用 `random.randrange(cnt)`，C++ 用 `std::uniform_int_distribution<int>(0, cnt - 1)`。**不要**写 `rand() % cnt`——Windows 上 `RAND_MAX` 只有 32767，而 `cnt` 可达 $2\times10^4$，取模后前段数值的出现概率接近后段的两倍；也不要写 `rand() / RAND_MAX < 1.0 / cnt`，浮点边界会引入系统性偏差。
3. **判等只做相等比较**：写 `nums[i] == target`，不要写 `nums[i] - target == 0`。`nums[i]` 可取 $-2^{31}$，减法在 `int` 上溢出是未定义行为。
4. **替换判据与随机数区间必须配套**：`randrange(cnt)` 返回 $0, 1, \dots, cnt-1$，其中取到 0 的概率恰为 $1/\text{cnt}$，所以判据是 `== 0`；若改用 `randint(1, cnt)`（返回 $1..cnt$）则判据必须改成 `== 1`。两种区间混着写（例如 `randint(1, cnt) == 0`）会让替换永不发生，`ans` 始终停在 $-1$。
5. **不做任何「提前返回」**：第一次命中直接返回、或最后命中的下标直接返回，都会破坏均匀性。算法必须把数组扫完，`ans` 才有正确的分布。
6. **只读快照**：整个 `pick` 不修改 `nums`，因此多次调用（甚至并发调用）互不干扰。C++ 构造时拷贝一份 `vector` 占 $O(n)$ 内存；若允许共享，存 `const vector<int>&` 或指针可省掉这次拷贝。
7. **Python 的常数因子**：`pick` 是纯 Python 循环，极限数据（$n = 2\times10^4$、$10^4$ 次调用）约 $2\times10^8$ 次比较，可能逼近时限。若线上超时，把 `__init__` 改成用 `collections.defaultdict(list)` 建「值 → 下标列表」，`pick` 用 `random.choice` 直接取，$O(1)$ 查询；这是用 $O(n)$ 空间换常数，不改变正确性。

## 5. 正确性证明

**引理 1（不变量）**：处理完前 $m$ 个命中后，对每个 $1 \le j \le m$，`ans` 等于 $i_j$ 的概率恰为 $1/m$。

**证明**：对 $m$ 归纳。$m = 1$ 时 `cnt = 1`，`randrange(1)` 恒为 0，故 `ans = i_1`，概率 $1 = 1/1$。

设 $m$ 时成立。处理第 $m+1$ 个命中时，以 $1/(m+1)$ 的概率把 `ans` 置为 $i_{m+1}$，故 $P(ans = i_{m+1}) = 1/(m+1)$。对 $j \le m$，事件「$ans = i_j$」要求此前已是 $i_j$（概率 $1/m$）且本次没有替换（概率 $1 - 1/(m+1) = m/(m+1)$）。由于本次抽样与此前结果独立，

$$P(ans = i_j) = \frac{1}{m}\cdot\frac{m}{m+1} = \frac{1}{m+1}$$

故 $m+1$ 时结论成立。∎

**引理 2（返回值合法）**：`pick` 返回的下标 $i$ 一定满足 `nums[i] == target`。

**证明**：`ans` 只在 `nums[i] == target` 的分支里被赋值为 $i$，从不被赋其他值；又因 `target` 保证出现，`cnt` 至少为 1，第一次命中时 `randrange(1) = 0` 必然赋值，故返回时 `ans >= 0` 且指向一个命中下标。∎

**引理 3（多次调用独立同分布）**：同一对象上第 $q$ 次调用与之前的调用独立，且分布与第一次相同。

**证明**：`pick` 的所有可变状态（`cnt`、`ans`、循环变量）都是局部变量，调用结束即销毁；唯一被读取的 `nums` 只读不写；每次调用内部的随机数由独立的均匀源产生。因此各次调用的随机变量相互独立、分布相同。∎

**定理**：设 `target` 在 `nums` 中出现 $c$ 次，则 `pick(target)` 以概率 $1/c$ 返回其中每个下标。

**证明**：由引理 2，返回值必是 $c$ 个合法下标之一；由引理 1 取 $m = c$，每个 $i_j$ 的概率均为 $1/c$；概率之和为 1 说明没有别的取值。∎

## 6. 复杂度分析

- **时间**：构造函数 $O(1)$（若拷贝数组则 $O(n)$）。单次 `pick` 完整扫描一遍数组，$O(n)$；其中每个命中做一次 $O(1)$ 的随机抽样。$q$ 次调用总计 $O(qn)$，最坏 $10^4 \times 2\times10^4 = 2\times10^8$ 次整数比较。索引表方案把 `pick` 降到 $O(1)$，预处理 $O(n)$。
- **空间**：$O(1)$ 额外空间——只有 `cnt`、`ans` 和循环变量，与 $n$、$c$ 都无关；输入数组本身不计入。对比索引表方案需要 $O(n)$ 额外空间（最坏每个值一个列表节点）。

## 7. 参考代码

本题在中文站的接口是 `Solution(nums)` 构造函数加 `pick(target)` 方法，不是常见的 `RandomPickIndex` 类名。

### C++

```cpp
#include <vector>
#include <random>
using namespace std;

class Solution {
    vector<int> a;
    mt19937 rng;
public:
    Solution(vector<int>& nums) : a(nums), rng(random_device{}()) {}

    int pick(int target) {
        int cnt = 0, ans = -1;
        for (int i = 0; i < (int)a.size(); ++i) {
            if (a[i] != target) continue;
            ++cnt;
            // 以 1/cnt 的概率把候选换成 i
            if (uniform_int_distribution<int>(0, cnt - 1)(rng) == 0) ans = i;
        }
        return ans;
    }
};
```

### Python

```python
import random


class Solution:
    def __init__(self, nums: list[int]):
        self.nums = nums

    def pick(self, target: int) -> int:
        cnt = 0
        ans = -1
        for i, x in enumerate(self.nums):
            if x == target:
                cnt += 1
                if random.randrange(cnt) == 0:   # 以 1/cnt 的概率替换
                    ans = i
        return ans
```

## 8. 边界情况与易错点

1. **`target` 只出现一次**：`cnt` 恒为 1、`randrange(1)` 恒为 0，返回唯一下标即可；不要为了「优化」在 `cnt == 1` 时提前 `return`，那会漏掉后面可能出现的新命中。
2. **所有元素都等于 `target`**：每个下标被选中的概率都是 $1/n$，算法天然成立；此时 `cnt` 能涨到 $2\times10^4$，正好是 `rand() % cnt` 模偏差最严重的区间。
3. **`INT_MIN` / `INT_MAX` 元素**：只做 `==` 比较，避免 `nums[i] - target` 在 `int` 上溢出。
4. **忘记重置 `cnt` 与 `ans`**：把状态放成员变量是本题最常见的 Wa——第一次调用分布正确，第二次开始分母从旧值继续累加。
5. **替换条件写反**：`randrange(cnt) == cnt` 永远为假，`ans` 一直停在 $-1$，直接返回非法下标；`randrange(cnt) != 0` 则是以 $(cnt-1)/\text{cnt}$ 的概率替换，分布同样错误。
6. **用浮点比较代替整数抽样**：`random.random() < 1.0 / cnt` 在 $cnt$ 很大时有精度损失，虽然本题 $cnt \le 2\times10^4$ 影响极小，但换成整数 `randrange` 更稳妥。
7. **Python 极限数据超时**：纯循环 $2\times10^8$ 次比较偏慢；改用索引表 + `random.choice`，或直接换 PyPy/编译型语言。
