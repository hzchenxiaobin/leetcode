# LeetCode 除法求值 题解

## 1. 题目概述

- **标题 / 题号**：除法求值（#399，medium）
- **链接**：https://leetcode.cn/problems/evaluate-division/
- **来源**：LeetCode 第 4 场周赛 Q4
- **难度**：中等
- **标签**：图、并查集、深度优先搜索、广度优先搜索、最短路、Floyd 算法、字符串

**题意**：给定若干等式 $A_i / B_i = values[i]$，对每个询问 $C_j / D_j$ 求值。若两个变量之间没有任何等式链可以传递（不在同一连通块），或者变量从未在 `equations` 中出现（未定义），该询问答案为 $-1.0$。数据保证等式组无矛盾、不会出现除数为 $0$ 的询问。

**约束**：

- $1 \le equations.length \le 20$，$equations[i].length == 2$
- $0 < values[i] \le 20$
- $1 \le queries.length \le 20$
- 变量名长度 $1 \sim 5$，仅由小写字母与数字组成

## 2. 示例

**示例 1**

```text
输入：equations = [["a","b"],["b","c"]], values = [2.0,3.0]
     queries   = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]
输出：[6.00000,0.50000,-1.00000,1.00000,-1.00000]
解释：a/c = 2.0 × 3.0 = 6.0，b/a = 1/2.0 = 0.5；e 未出现、x 未定义 ⇒ 都是 -1.0；a/a 恒为 1.0。
```

**示例 2**

```text
输入：equations = [["a","b"],["b","c"],["bc","cd"]], values = [1.5,2.5,5.0]
     queries   = [["a","c"],["c","b"],["bc","cd"],["cd","bc"]]
输出：[3.75000,0.40000,5.00000,0.20000]
解释：a/c = 1.5 × 2.5 = 3.75；c/b = 1/2.5 = 0.4；bc/cd 直接查表 5.0，反向取倒数 0.2。
```

**示例 3**

```text
输入：equations = [["a","b"]], values = [0.5]
     queries   = [["a","b"],["b","a"],["a","c"],["x","y"]]
输出：[0.50000,2.00000,-1.00000,-1.00000]
解释：a/c 中 c 未出现，x/y 两个变量都未定义 ⇒ 均为 -1.0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是把等式当「可传递的比值」，对每个询问反复扫描等式表做松弛（类似 Bellman-Ford）：只要存在 $x/y$ 与 $y/z$，就补出 $x/z$。单次询问最多松弛 $E$ 轮、每轮扫 $E$ 条边，复杂度 $O(QE^2)$，配上 $E, Q \le 20$ 当然能过，但实现上要维护「已知比值表」并反复判重，遇到冗余边（如同时给出 $a/b$、$b/c$、$a/c$）容易重复计入或陷入循环。更朴素地枚举 $C$ 到 $D$ 的所有路径则是路径数级，指数爆炸。问题的本质是：**「比值能沿边连乘传播」这件事缺一个数据结构来承载**，而图模型能一次讲清楚。

### 3.2 核心观察：比值关系是一张带权有向图

![比值关系建成带权有向图](images/wc4_q4_ratio_graph.svg)

把一个变量看成一个点，把等式 $A / B = v$ 看成两条有向边：$A \to B$ 权为 $v$，$B \to A$ 权为 $1/v$。沿路径 $x = p_0 \to p_1 \to \cdots \to p_k = y$ 把边权连乘，恰好得到 $x/y$：

$$\frac{x}{y} = \prod_{i=0}^{k-1} w(p_i,\, p_{i+1})$$

于是每个询问只剩两件事：$C$ 与 $D$ 是否**连通**（不连通或变量没出现过 $\Rightarrow -1.0$）；连通时乘积是多少（由引理 1，**任意一条路径的乘积都相同**，取一条即可）。

> 💡 关键认知：题目给的不是「一堆等式」，而是「一张带权图 + 若干个两点间路径乘积查询」。难点从「解方程」变成了「维护连通块内的相对比值」。

### 3.3 算法流程：带权并查集

![带权并查集：ratio 定义、路径压缩与合并公式](images/wc4_q4_weighted_dsu.svg)

只需要「连通性 + 相对比值」，带权并查集是天然选择。为每个点维护

$$\text{ratio}[x] = \frac{\text{value}(x)}{\text{value}(\text{parent}[x])}, \qquad \text{ratio}[\text{root}] = 1$$

并查集只记录「每个点相对于自己父亲的比值」，从不关心变量的绝对大小：

- **查找** $\text{find}(x)$：递归到根，回溯时乘上父节点**压缩后**的比值（即 $\text{value}(p)/\text{value}(\text{root})$），再把 $x$ 直接挂到根上（路径压缩）。压缩完成后 $\text{ratio}[x] = \text{value}(x)/\text{value}(\text{root})$。
- **合并** $\text{union}(a,b,v)$（已知 $a/b=v$）：设两根为 $r_a, r_b$，由

$$\frac{a}{b} = \frac{\text{ratio}[a]\cdot \text{value}(r_a)}{\text{ratio}[b]\cdot \text{value}(r_b)} = v \;\Longrightarrow\; \frac{\text{value}(r_a)}{\text{value}(r_b)} = \frac{v\cdot \text{ratio}[b]}{\text{ratio}[a]}$$

  按大小合并决定挂接方向：$r_b$ 挂到 $r_a$ 下时 $\text{ratio}[r_b] = \text{ratio}[a]\,/\,(v\cdot\text{ratio}[b])$；反过来 $r_a$ 挂到 $r_b$ 下时 $\text{ratio}[r_a] = v\cdot\text{ratio}[b]\,/\,\text{ratio}[a]$。
- **查询** $c/d$：两个变量必须都在 `equations` 中出现过；分别 $\text{find}$ 后若同根，答案是 $\text{ratio}[c]/\text{ratio}[d]$，否则 $-1.0$。

整体流程与询问顺序无关：给 `equations` 中出现的变量编号并初始化（`parent[x]=x`、`ratio[x]=1`、`size[x]=1`）→ 逐条等式 $\text{union}$，两端同根说明是冗余边，直接跳过 → 逐个询问先判变量是否出现过，再判是否同根，最后取商。

### 3.4 示例演算

![示例 1 的并查集演算表](images/wc4_q4_walkthrough_table.svg)

以示例 1 的 $a/b=2.0$、$b/c=3.0$ 走一遍（表中最右列是「依据」）：

| 步骤 | 操作 | 并查集状态 | 依据 |
|------|------|------------|------|
| 1 | 建点 $a,b,c$ | 三个孤立根，`ratio` 全为 1 | 初始状态 |
| 2 | $\text{union}(a,b,2.0)$ | $b \to a$，$\text{ratio}[b]=0.5$ | $1/(2.0\times 1)$ |
| 3 | $\text{union}(b,c,3.0)$ | $c \to a$，$\text{ratio}[c]=1/6$ | $0.5/(3.0\times 1)$ |
| 4 | 查询 $a/c$ | 同根 $a$ | $1/(1/6)=6.0$ |
| 5 | 查询 $b/a$ | 同根 $a$ | $0.5/1=0.5$ |
| 6 | 查询 $a/a$ | 同根 $a$ | $1/1=1.0$ |
| 7 | 查询 $x/x$ | $x$ 没有编号 | 未定义 $\Rightarrow -1.0$ |

第 3 步值得单独核对：此时 $\text{ratio}[b]=0.5$ 表示 $b$ 是 $a$ 的 $0.5$ 倍，$c$ 是 $b$ 的 $1/3$，所以 $c$ 是 $a$ 的 $1/6$，写回的正是 $c \to a$ 的 $1/6$。第 4 步取 $\text{ratio}[a]/\text{ratio}[c]$，恰好把「$a$ 相对根」与「$c$ 相对根」两段约掉，得到 $a/c=6.0$。

## 4. 算法细节

1. **编号只给 `equations` 里的变量**。查询里出现但等式里没有的名字必须保持「未编号」，否则 $x/x$ 会被误判成已知变量而返回 $1.0$（示例 1 的坑）。
2. **`find` 里必须先保存旧父亲**：`p = parent[x]`，再递归 `find(p)`，最后 `ratio[x] *= ratio[p]`、`parent[x] = 根`。如果先改写 `parent[x]` 再取 `ratio[parent[x]]`，读到的是根节点的 `ratio`，路径压缩会把比值算错。
3. **合并公式与挂接方向绑定**。$r_b$ 挂 $r_a$ 时 $\text{ratio}[r_b]=\text{ratio}[a]/(v\cdot\text{ratio}[b])$；$r_a$ 挂 $r_b$ 时取倒数关系 $\text{ratio}[r_a]=v\cdot\text{ratio}[b]/\text{ratio}[a]$。按 `size` 合并时两个分支都要写对，最省事的自测是 $a/b=2$ 必须得到 $b/a=0.5$。
4. **查询前一定要 `find`**。`ratio` 只保证「相对于当前父亲」；只有 `find` 之后才变成「相对于根」。两次 `find` 都做完再取 `ratio[c] / ratio[d]`。
5. **已连通就跳过合并**。同根时两条边其实给的是同一个约束，题目保证无矛盾，直接 `return`；若想兼容矛盾输入，可断言 $\text{ratio}[a]/\text{ratio}[b] \approx v$ 并报错。
6. **用 `double`，别用 `float`**。最长的传递链有 20 条边，比值最大约 $20^{19}\approx 5.2\times 10^{24}$，仍在 `double` 范围内；`float` 的有效位数只有 7 位，链式相乘会明显失准。返回值比较用相对误差而不是 `==`，但特殊值 $-1.0$ 必须精确给出。
7. **等价替代方案**：对每个询问从 $C$ 做一次 BFS/DFS，边搜边乘，遇到 $D$ 即返回。单次 $O(V+E)$，总 $O(Q(V+E))$，本题 $V\le 40$ 完全够用；带权并查集的优势在「查询量极大」时（每次近 $O(1)$）。此外也可以用 Floyd 式闭包直接维护全源比值矩阵，$O(V^3)$ 预处理后 $O(1)$ 查询。

## 5. 正确性证明

**引理 1（路径无关性）**：若等式组无矛盾，则对同一连通块内任意两点 $x,y$，任意一条 $x \to y$ 路径的边权乘积都等于 $\text{value}(x)/\text{value}(y)$，因而彼此相等。

**证明**：无矛盾意味着存在一组正实数赋值 $\text{value}(\cdot)$ 满足全部等式，即对每条边 $(u,v)$ 有 $w(u,v)=\text{value}(u)/\text{value}(v)$（反向边权为 $1/v=\text{value}(v)/\text{value}(u)$，同样成立）。沿路径 $p_0=x,\dots,p_k=y$ 连乘：

$$\prod_{i=0}^{k-1}\frac{\text{value}(p_i)}{\text{value}(p_{i+1})}=\frac{\text{value}(p_0)}{\text{value}(p_k)}=\frac{\text{value}(x)}{\text{value}(y)}$$

乘积望远镜式相消，与路径选择无关。∎

**引理 2（并查集不变量）**：任意时刻对每个已编号的 $x$，都有 $\text{ratio}[x]=\text{value}(x)/\text{value}(\text{parent}[x])$；且 $\text{find}(x)$ 返回根 $r$ 后，$\text{parent}[x]=r$、$\text{ratio}[x]=\text{value}(x)/\text{value}(r)$。

**证明**：对操作次数归纳。初始 `parent[x] = x`、$\text{ratio}[x]=1$，成立。合并时设两端分别为 $a,b$，已知 $a/b=v$，并已由归纳假设得到 $\text{ratio}[a]=\text{value}(a)/\text{value}(r_a)$、$\text{ratio}[b]=\text{value}(b)/\text{value}(r_b)$。把 $r_b$ 挂到 $r_a$ 下时，代码写入

$$\text{ratio}[r_b]=\frac{\text{ratio}[a]}{v\cdot\text{ratio}[b]}=\frac{\text{value}(a)/\text{value}(r_a)}{v\cdot \text{value}(b)/\text{value}(r_b)}=\frac{\text{value}(r_b)}{\text{value}(r_a)}$$

这正是新父亲 $r_a$ 所需的比值（此处用到 $v=\text{value}(a)/\text{value}(b)$），不变量保持；反向挂接时同理。压缩时先递归得到 $\text{ratio}[p]=\text{value}(p)/\text{value}(r)$，再令 $\text{ratio}[x]\leftarrow \text{ratio}[x]\cdot\text{ratio}[p]=\bigl(\text{value}(x)/\text{value}(p)\bigr)\cdot\bigl(\text{value}(p)/\text{value}(r)\bigr)=\text{value}(x)/\text{value}(r)$，并把父亲改成 $r$，不变量保持。∎

**引理 3（连通性判定）**：$\text{find}(c)=\text{find}(d)$ 当且仅当 $c,d$ 之间存在由等式边组成的路径。

**证明**：并查集只在存在等式边时合并两个连通块，合并后不再拆分，故有路径必同根。反之，若同根，则二者在一次合并序列中被连到一起，每一步合并都对应一条等式边，把这些边串起来就是一条路径。∎

**定理**：算法对每个询问的输出都正确。

**证明**：分三种情况。

1. $c,d$ 都出现过且同根：由引理 2，两次 `find` 后 $\text{ratio}[c]=\text{value}(c)/\text{value}(r)$、$\text{ratio}[d]=\text{value}(d)/\text{value}(r)$，相除得 $\text{value}(c)/\text{value}(d)=c/d$；由引理 1 这是唯一可推出的值，输出正确。
2. 都出现过但不同根：由引理 3 不存在连接路径，任何推导都需要一条等式边链，故答案无法确定，输出 $-1.0$ 正确。
3. 至少一个未出现：该变量未定义，即便 $c=d$ 也无法确定，输出 $-1.0$ 正确。∎

## 6. 复杂度分析

- **时间**：编号与建表 $O(E)$；$E$ 次合并、$Q$ 次查询，每次至多两次带路径压缩的 `find`，均摊 $O(\alpha(V))$。总计 $O\bigl((E+Q)\,\alpha(V)\bigr)$，其中 $V \le 2E \le 40$，实际是常数级开销。若改用「每个询问一次 BFS」，则为 $O\bigl(Q(V+E)\bigr)$，同样远低于时限。
- **空间**：`parent`、`ratio`、`size` 三个数组各 $O(V)$，名字到编号的哈希表 $O(V)$，答案数组 $O(Q)$；总计 $O(V+Q)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <string>
#include <unordered_map>
using namespace std;

class Solution {
    unordered_map<string, int> id;
    vector<int> parent, sz;
    vector<double> ratio;          // ratio[x] = value(x) / value(parent[x])

    int getId(const string& s) {
        auto it = id.find(s);
        if (it != id.end()) return it->second;
        int i = (int)parent.size();
        id[s] = i; parent.push_back(i); sz.push_back(1); ratio.push_back(1.0);
        return i;
    }
    int find(int x) {              // 返回根；ratio[x] 变为 value(x)/value(root)
        if (parent[x] == x) return x;
        int p = parent[x];         // 必须先存旧父亲，递归后 parent[x] 会被改写
        int r = find(p);           // 压缩后 ratio[p] = value(p)/value(r)
        ratio[x] *= ratio[p];      // value(x)/value(r)
        parent[x] = r;
        return r;
    }
    void unite(int a, int b, double v) {   // 已知 a / b = v
        int ra = find(a), rb = find(b);
        if (ra == rb) return;             // 已连通，题目保证无矛盾
        if (sz[ra] < sz[rb]) {            // 小树 ra 挂到大树 rb 下
            parent[ra] = rb;
            ratio[ra] = v * ratio[b] / ratio[a];
            sz[rb] += sz[ra];
        } else {
            parent[rb] = ra;
            ratio[rb] = ratio[a] / (v * ratio[b]);
            sz[ra] += sz[rb];
        }
    }

public:
    vector<double> calcEquation(vector<vector<string>>& equations, vector<double>& values,
                                vector<vector<string>>& queries) {
        id.clear(); parent.clear(); sz.clear(); ratio.clear();
        for (size_t i = 0; i < equations.size(); ++i)
            unite(getId(equations[i][0]), getId(equations[i][1]), values[i]);
        vector<double> ans(queries.size(), -1.0);
        for (size_t i = 0; i < queries.size(); ++i) {
            auto ic = id.find(queries[i][0]), jd = id.find(queries[i][1]);
            if (ic == id.end() || jd == id.end()) continue;
            int c = ic->second, d = jd->second;
            if (find(c) != find(d)) continue;
            ans[i] = ratio[c] / ratio[d];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def calcEquation(self, equations, values, queries):
        idx = {}                          # 变量名 -> 编号
        parent, size, ratio = [], [], []  # ratio[x] = value(x) / value(parent[x])
        def get_id(name):
            if name not in idx:
                idx[name] = len(parent)
                parent.append(len(parent)); size.append(1); ratio.append(1.0)
            return idx[name]
        def find(x):
            if parent[x] != x:
                p = parent[x]             # 先记下旧父亲
                r = find(p)               # 递归压缩后 ratio[p] = value(p)/value(r)
                ratio[x] *= ratio[p]      # value(x)/value(r)
                parent[x] = r
            return parent[x]
        def unite(a, b, v):               # 已知 a / b = v
            ra, rb = find(a), find(b)
            if ra == rb:
                return                    # 已连通；题目保证无矛盾
            if size[ra] < size[rb]:       # 把小树 ra 挂到大树 rb 下
                parent[ra] = rb
                ratio[ra] = v * ratio[b] / ratio[a]
                size[rb] += size[ra]
            else:
                parent[rb] = ra
                ratio[rb] = ratio[a] / (v * ratio[b])
                size[ra] += size[rb]

        for (a, b), v in zip(equations, values):
            unite(get_id(a), get_id(b), v)
        ans = [-1.0] * len(queries)
        for i, (c, d) in enumerate(queries):
            if c not in idx or d not in idx:
                continue
            ic, idd = idx[c], idx[d]
            if find(ic) == find(idd):
                ans[i] = ratio[ic] / ratio[idd]
        return ans
```

## 8. 边界情况与易错点

1. **未定义变量自比**：`["x","x"]` 必须返回 $-1.0$，不能因为 $c=d$ 就提前返回 $1.0$。判存在性要放在最前面。
2. **已知变量自比**：`["a","a"]`（$a$ 在等式中出现过）返回 $1.0$，走的是 $\text{ratio}[a]/\text{ratio}[a]$ 这条路，无需特判。
3. **`find` 顺序写错**：必须先 `p = parent[x]`、再递归、最后 `ratio[x] *= ratio[p]`；若先改 `parent[x]`，压缩会把两段比值乘错，形成链时答案全错。
4. **查询漏掉 `find`**：直接读 `ratio` 只能拿到「相对父亲」的比值，父亲不是根时答案偏小或偏大；两次 `find` 都做完再取商。
5. **合并方向与公式必须配套**：按 `size` 合并时「小树挂大树」两个分支的公式互为倒数，写反后 $a/b=2$ 的 $b/a$ 会得到 $2.0$ 而不是 $0.5$。
6. **冗余边**：数据里可能同时给出 $a/b$、$b/c$、$a/c$（无矛盾），合并时遇到同根直接返回，不要重复改 `ratio`。
7. **浮点精度**：用 `double` 而非 `float`；输出 $-1.0$ 是特殊标记，不能拿容差比较去判它，也不要在无法确定时返回 `0.0`。
8. **只在查询里出现的名字**：不要给它分配编号，否则会被当作「已知变量」，$x/x$ 误判为 $1.0$、$a/x$ 误判为某个有限值。

**延伸思考**：如果输入可能矛盾（例如同时给出 $a/b=2$ 与 $a/b=3$），需要在合并同根时校验 $\text{ratio}[a]/\text{ratio}[b]$ 与 $v$ 的相对误差，把「无矛盾」从题设变成可检测的性质；如果变量需要精确值（避免浮点误差），可以把比值存成「分子/分母」的最简分数，并查集合并时做一次 $\gcd$ 约分，代价是常数变大；如果要求「多路径不一致时的最小二乘解」，问题就变成对数域上的差分约束 / 最小二乘，超出了并查集的能力范围。
