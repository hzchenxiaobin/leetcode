# LeetCode 非递减数列 题解

## 1. 题目概述

- **标题 / 题号**：非递减数列（#665，medium）
- **链接**：https://leetcode.cn/problems/non-decreasing-array/
- **来源**：LeetCode 第 47 场周赛 Q1
- **难度**：中等
- **标签**：数组

**题意**：给定长度为 $n$ 的整数数组 `nums`，**最多**把其中 1 个元素改成任意整数，问能否让整个数组变成非递减数列，即对所有 $0 \le i \le n-2$ 满足 $nums[i] \le nums[i+1]$。返回能否做到。

**约束**：

- $1 \le n \le 10^4$
- $-10^5 \le nums[i] \le 10^5$
- 「最多」包含 0 次修改：原数组本来就非递减时直接返回 `true`

> 💡 本场签到题，结论只有一句话：**下降点至多一处，而这一处只有两种改法**。真正容易翻车的是边界——下降发生在下标 $0$ 时没有左邻居。

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,3]
输出：true
解释：把第一个 4 改成 2（或更小），得到 [2,2,3]，非递减。
```

**示例 2**

```text
输入：nums = [4,2,1]
输出：false
解释：改一个元素无法同时消除 4>2 与 2>1 两处下降。
```

**补充示例 3（需要抬高右邻）**

```text
输入：nums = [2,4,1,5]
输出：true
解释：下降点 i=1，左邻 2 > 1，压低 4 会破坏左边；把 1 抬成 4 得 [2,4,4,5]。
```

**补充示例 4（抬高后引发新下降）**

```text
输入：nums = [3,5,2,4]
输出：false
解释：下降点 i=1，左邻 3 > 2，只能把 2 抬成 5，得到 [3,5,5,4]，又出现 5>4。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的暴力是「枚举改哪个下标 $k$ $\times$ 改成什么值 $v$」。值域连续无界，$v$ 根本枚举不完。

退一步：枚举 $k$，直接构造该位置的最优取值——为了不破坏邻居必须满足 $nums[k-1] \le nums[k] \le nums[k+1]$，这样的整数存在当且仅当 $k=0$、$k=n-1$ 或 $nums[k-1] \le nums[k+1]$；之后还要花 $O(n)$ 校验一遍。总复杂度 $O(n^2)$，$n=10^4$ 时约 $10^8$ 次操作，偏紧且完全没必要。

还要注意一个常见误区：**「删除」不是「修改」**。例如 $[3,4,2,3]$ 删掉 4 得到 $[3,2,3]$ 仍然不有序，而「删掉一个元素」本身也不是题目允许的操作。

### 3.2 核心观察：单下降点贪心——压低左邻或抬高右邻

称 $i$ 为**下降点**，若 $nums[i] > nums[i+1]$。

- **观察 A**：改一个元素 $nums[k]$ 只会影响相邻两对 $(k-1,k)$ 与 $(k,k+1)$，所以一次修改最多消除一处下降；事实上出现两处下降时必然无解（§5 引理 1）。
- **观察 B**：若整个数组只有一处下降点 $i$，则前缀 $nums[0..i]$ 与后缀 $nums[i+1..n-1]$ 各自非递减，修复只需在 $i$ 与 $i+1$ 之间做选择：
  - 若 $i=0$ 或 $nums[i-1] \le nums[i+1]$（$i=0$ 时把左邻视为 $-\infty$）：把 $nums[i]$ **压到** $nums[i+1]$，两个相邻对同时成立，后缀完全不动 → 必定成功；
  - 否则 $nums[i-1] > nums[i+1]$：压低 $nums[i]$ 会破坏左边那对，只能把 $nums[i+1]$ **抬到** $nums[i]$；此时右侧对 $(i+1,i+2)$ 可能被顶坏，把问题交给后续扫描。

![下降点的两种修正方向](images/wc47_q1_descent_insight.svg)

> 💡 判断条件只比两个数：**左邻 vs 右邻**。左邻不超过右邻就压低左边这个元素，否则抬高右边那个元素。

### 3.3 算法流程

维护「已用修改次数」`cnt`，一趟扫描：

1. 令 $i$ 从 $0$ 取到 $n-2$；
2. 若 $nums[i] \le nums[i+1]$，继续下一个；
3. 否则 `cnt += 1`，若 `cnt > 1` 立刻返回 `false`；
4. 若 $i > 0$ 且 $nums[i-1] > nums[i+1]$，就地令 $nums[i+1] \leftarrow nums[i]$；
5. 否则就地令 $nums[i] \leftarrow nums[i+1]$；
6. 扫描结束返回 `true`。

关键是第 4、5 步**就地写回**：后面的比较用的是修正后的值，于是「抬高右邻顶坏下一个元素」这类连锁情况不需要任何特判，会被第 3 步的计数自然捕获。

### 3.4 示例演算

| 输入 | 下降点 | 左邻比较 | 动作 | 结果数组 | 答案 |
|------|--------|----------|------|----------|------|
| `[4,2,3]` | $i=0$ | 无左邻 | 压低 $nums[0]$ | `[2,2,3]` | `true` |
| `[2,4,1,5]` | $i=1$ | $2 > 1$ | 抬高 $nums[2]$ | `[2,4,4,5]` | `true` |
| `[3,5,2,4]` | $i=1$ | $3 > 2$ | 抬高 $nums[2]$ | `[3,5,5,4]` → 再下降 | `false` |

![三组输入走查](images/wc47_q1_walkthrough.svg)

第三行说明为什么不能「只处理第一处下降就收工」：抬高会把手里的矛盾推到右边，必须让扫描继续走完。

## 4. 算法细节

1. **`cnt` 上限为 2**：一旦出现第二处下降立即返回 `false`，不必等扫描结束，省掉无谓判断。
2. **$i=0$ 的边界**：没有左邻居，直接走压低分支；C++ 里绝不能写 $nums[i-1]$，否则是未定义行为（负下标）。
3. **就地修改**：两个分支都要真正写回数组，且写回后继续参与后续比较——这是「一处修改」的计数逻辑成立的前提。
4. **末尾下降**：$[1,2,3,2]$ 的下降点在 $i=n-2$，此时 $3 > 2$，抬高最后一个元素即可；循环上界写成 `i + 1 < n` 更稳。
5. **不改输入数组的写法**：若要保留原数组，可先复制一份（$O(n)$ 空间）；也可改用等价的「枚举删除」刻画——存在某个 $k$ 使删除 $nums[k]$ 后数组非递减，因为删除后必有 $nums[k-1] \le nums[k+1]$，此时把 $nums[k]$ 改成 $nums[k-1]$ 就合法。
6. **比较直接用整数原值**：$|nums[i]| \le 10^5$，`int` 足够，不需要 `long long`；相等不构成下降，比较必须是严格大于。

## 5. 正确性证明

**引理 1（两处下降必无解）**：若数组中的下降点不少于 2 个，则任何单点修改都无法使其非递减。

**证明**：设在 $i < j$ 两处下降。修改下标 $k$ 只改变相邻两对 $(k-1,k)$ 与 $(k,k+1)$，要同时消除 $i$、$j$ 必须 $i, j \in \{k-1, k\}$，故 $j = i+1$ 且 $k = j$。但 $nums[i] > nums[i+1] = nums[j]$ 且 $nums[j] > nums[j+1]$；要让改后的 $nums[j]$ 同时满足 $nums[i] \le nums[j]$ 与 $nums[j] \le nums[j+1]$，需 $nums[i] \le nums[j+1]$，与 $nums[i] > nums[j] > nums[j+1]$ 矛盾。∎

**引理 2（唯一下降点时的分支判定）**：设数组只有一处下降点 $i$，其余相邻对均非递减。

1. 若 $i = 0$ 或 $nums[i-1] \le nums[i+1]$，则令 $nums[i] \leftarrow nums[i+1]$ 后数组非递减；
2. 若 $i > 0$ 且 $nums[i-1] > nums[i+1]$，则任何可行修改都必须把 $nums[i+1]$ 抬到不小于 $nums[i]$，且取 $nums[i]$ 是其中对右侧最友好的选择。

**证明**：(1) $i=0$ 时左侧无约束；$i>0$ 时 $nums[i-1] \le nums[i+1]$ 恰是新 $nums[i]$ 需要满足的全部左约束，而 $nums[i+1] \le nums[i+1]$ 自明，右侧元素未动。(2) 若改 $nums[i]$，需同时满足 $nums[i-1] \le nums[i] \le nums[i+1]$，与 $nums[i-1] > nums[i+1]$ 矛盾，故只能改 $nums[i+1]$（改更远的元素修不了这对下降）；要修好 $(i,i+1)$ 需新值 $v \ge nums[i]$。取 $v = nums[i]$：若某合法方案取 $v' \ge nums[i]$，则 $nums[i+2] \ge v' \ge nums[i]$，故 $v$ 同样合法，最小取值不会更差。∎

**定理**：算法返回 `true` 当且仅当数组能在至多一次修改后变为非递减。

**证明**：
（⇐）设存在合法修改。若 0 次修改即可，扫描全程不遇下降，`cnt=0`，返回 `true`。若恰改一处：由引理 1，原数组的下降点唯一，记作 $i$，修改位置只能是 $i$ 或 $i+1$。若 $i=0$ 或 $nums[i-1] \le nums[i+1]$，算法按引理 2(1) 压低 $nums[i]$，一次到位，此后不会再有下降；若 $nums[i-1] > nums[i+1]$，合法方案只能把 $nums[i+1]$ 抬成某个 $v' \ge nums[i]$（引理 2(2)），算法改取的 $nums[i]$ 更小，而 $nums[i+2] \ge v' \ge nums[i]$，后续相邻对仍非递减，于是扫描不会出现第二处下降，同样返回 `true`。
（⇒）设算法返回 `true`。维护不变量：处理完下标 $i$ 后，$nums[0..i+1]$ 非递减，且已修改次数为 `cnt`。初值（$i=-1$）显然成立；每步只在发现下降时按引理 2 修复当前相邻对：压低分支满足左约束，抬高分支把右元素变大、其左约束由抬高本身满足，两者都不破坏已有序前缀。扫描结束时前缀就是整个数组，非递减且修改次数不超过 1，方案合法。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个下标只做常数次比较与赋值；出现第二处下降可提前退出，本质上是一趟扫描加常数次修改。
- **空间复杂度**：$O(1)$ 额外空间（就地修改输入数组）。若不允许修改输入，复制一份则为 $O(n)$ 空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkPossibility(vector<int>& nums) {
        int cnt = 0, n = nums.size();
        for (int i = 0; i + 1 < n; ++i) {
            if (nums[i] > nums[i + 1]) {
                if (++cnt > 1) return false;              // 第二处下降 → 无解
                if (i > 0 && nums[i - 1] > nums[i + 1])
                    nums[i + 1] = nums[i];               // 左邻太大：抬高右邻
                else
                    nums[i] = nums[i + 1];               // 否则压低左邻
            }
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def checkPossibility(self, nums: List[int]) -> bool:
        cnt = 0
        for i in range(len(nums) - 1):
            if nums[i] > nums[i + 1]:
                cnt += 1
                if cnt > 1:
                    return False
                if i > 0 and nums[i - 1] > nums[i + 1]:
                    nums[i + 1] = nums[i]      # 左邻太大：抬高右邻
                else:
                    nums[i] = nums[i + 1]      # 否则压低左邻
        return True
```

```python
class Solution:
    def checkPossibility(self, nums: List[int]) -> bool:
        # 不改输入数组：只在副本上动手
        a = nums[:]
        cnt = 0
        for i in range(len(a) - 1):
            if a[i] > a[i + 1]:
                cnt += 1
                if cnt > 1:
                    return False
                if i > 0 and a[i - 1] > a[i + 1]:
                    a[i + 1] = a[i]
                else:
                    a[i] = a[i + 1]
        return True
```

## 8. 边界情况与易错点

1. **$n \le 2$**：循环不执行或只比一次，直接返回 `true`；单元素数组天然非递减。
2. **下降在下标 0**：$[4,2,3]$ 没有左邻，必须走压低分支，别去读 $nums[-1]$。
3. **下降在末尾**：$[1,2,3,2]$ 需要抬高最后一个元素，循环写 `i + 1 < n`，不要漏掉 $i=n-2$ 这一对。
4. **相邻双下降**：$[3,2,1]$ 有两处下降，直接 `false`，别指望「改中间元素能同时修好两对」。
5. **抬高引发新下降**：$[3,5,2,4]$ 抬成 $[3,5,5,4]$ 之后仍要失败，靠 `cnt` 而不是一次性判定。
6. **重复元素**：$[2,2,1]$ 只有一处下降，左邻 $2 > 1$，把 $nums[2]$ 抬到 2 得 $[2,2,2]$，答案 `true`；相等不构成下降。
7. **不等号方向**：用严格大于 $nums[i-1] > nums[i+1]$ 判断；相等时 $nums[i-1] \le nums[i+1]$ 成立，压低分支可行。

**延伸思考**：若把「最多 1 次」放宽成「最多 $k$ 次」，一趟扫描的贪心不再直接适用，但存在等价刻画——**最少修改次数 $= n - \mathrm{LNDS}(nums)$**，其中 $\mathrm{LNDS}$ 为最长非递减子序列长度。理由是：不动的元素必须构成非递减子序列；反过来，给定任意非递减子序列，两个保留位置之间的空位全部填左端点的值即可（因左端点不超过右端点），首段填第一个保留值、末段填最后一个保留值，整体仍非递减。于是原问题等价于 $\mathrm{LNDS} \ge n-1$，可用 $O(n \log n)$ 的耐心排序求解；对本题反而不如 $O(n)$ 的贪心，但它给出了可推广的判据。
