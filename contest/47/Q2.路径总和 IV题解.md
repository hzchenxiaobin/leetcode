# LeetCode 路径总和 IV 题解

## 1. 题目概述

- **标题 / 题号**：路径总和 IV（#666，medium）
- **链接**：https://leetcode.cn/problems/path-sum-iv/
- **来源**：LeetCode 第 47 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、数组、哈希表、二叉树

**题意**：深度小于 5 的二叉树可以用一串**三位整数**表示：百位是深度 $D$（$1 \le D \le 4$），十位是该节点在本层中的位置 $P$（$1 \le P \le 8$，编号方式与满二叉树一致），个位是节点值 $V$（$0 \le V \le 9$）。输入按升序给出这些三位数，要求返回**所有「根 → 叶子」路径上节点值之和的总和**。

> 💡 位置法则：$(D,P)$ 的左孩子是 $(D+1,\ 2P-1)$，右孩子是 $(D+1,\ 2P)$，父节点是 $(D-1,\ \lceil P/2 \rceil)$。某个位置在数组中不存在，就表示那里没有节点。

**约束**：

- $1 \le \text{nums.length} \le 15$（深度 $\le 4$ 的满二叉树最多 $1+2+4+8=15$ 个节点）
- 每个元素是三位整数：$D \in [1,4]$，$P \in [1,8]$，$V \in [0,9]$
- 数组按三位整数**升序**给出，等价于按 $(D,P)$ 的字典序给出
- 数组表示一棵**合法**二叉树：每个非根节点的父节点都存在
- 答案在 32 位有符号整数范围内（最坏 $8$ 个叶子、单条路径和 $\le 4 \times 9 = 36$，总和 $\le 288$）

## 2. 示例

**示例 1**

```text
输入：nums = [113, 215, 221]
输出：12
解释：113 是根（D=1,P=1,V=3），215 是左孩子（值 5），221 是右孩子（值 1）。
      两条路径：3+5 = 8，3+1 = 4，总和 8+4 = 12。
```

**示例 2**

```text
输入：nums = [113, 221]
输出：4
解释：221 的坐标是 (D=2, P=2)，即根的第 2 层第 2 个位置（右孩子）；
      位置 (2,1) 不存在，所以根只有一个孩子，路径和 3+1 = 4。
```

**示例 3（补充）**

```text
输入：nums = [111, 212, 223, 314, 325, 336, 347]
输出：36
解释：7 个节点，叶子是 (3,1)=4、(3,2)=5、(3,3)=6、(3,4)=7，
      四条路径和分别 1+2+4=7、1+2+5=8、1+3+6=10、1+3+7=11，总和 36。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**先把编码还原成真正的二叉树**：遍历数组，对每个节点算出父坐标 $(D-1,\lceil P/2\rceil)$，在哈希表里找到父节点对象，再按「左右孩子」把指针挂上去；然后套用 112 题的 DFS 模板求路径和。

这条路可行，但有三处多余开销：

1. 需要额外分配至多 15 个 `TreeNode` 对象，代码量大、常数大；
2. 挂指针时「左孩子还是右孩子」要靠 $P$ 的奇偶判断，容易写错；
3. 更糟的版本是不建哈希表、对每个节点在数组里**线性扫父节点**，退化到 $O(n^2)$ 次比较。

本题 $n \le 15$，任何写法都不会超时，但真正值得沉淀的结论是：**树结构已经完整编码在节点坐标里，根本不需要建树**。

### 3.2 核心观察：前两位是坐标，位置法则是唯一的边

![三位数编码与满二叉树位置法则](images/wc47_q2_encoding_parent.svg)

**观察一：键值就在同一次除法里。** 三位数 $\text{num} = 100D + 10P + V$，于是

$$
\text{key} = \text{num} \div 10 = 10D + P, \qquad V = \text{num} \bmod 10
$$

`key` 同时编码了层号与位置，天然唯一，可以直接当哈希表的键；它的值域只有 $[11, 48]$。

**观察二：父子关系是一组纯算术。** 满二叉树的位置编号满足

$$
\text{parent}(D,P) = \left(D-1,\ \left\lceil \frac{P}{2} \right\rceil\right),\qquad
\text{left}(D,P) = (D+1,\ 2P-1),\qquad
\text{right}(D,P) = (D+1,\ 2P)
$$

没有指针、没有数组下标、也不需要知道树有多大——给一个坐标就能立刻算出它的父与子。这正是把「建树」这一步彻底省掉的关键：**树是隐式的，边是按需算出来的**。

### 3.3 算法流程：升序 = 层序，一趟递推前缀和

![建表 → 递推前缀和 → 判叶子 → 累加](images/wc47_q2_bottom_up_flow.svg)

输入升序这一点非常关键：三位数升序就是按 $D$ 优先、$P$ 次之排序，恰好是**层序遍历**。而父节点的键 $10(D-1) + \lceil P/2\rceil$ 严格小于子节点的键，所以**扫描到任一节点时，它的父节点必定已经被处理过**。于是可以一趟递推：

$$
\text{pre}[\text{key}] = \text{pre}[\text{parent}(\text{key})] + V(\text{key}), \qquad \text{pre}[\text{root}] = V(\text{root})
$$

其中 $\text{pre}$ 表示「根到该节点的路径和」。递推结束后，再扫一遍找叶子：

$$
\text{ans} = \sum_{\text{key 是叶子}} \text{pre}[\text{key}]
$$

**叶子判定**：左右孩子的键 $10(D+1) + 2P - 1$ 与 $10(D+1) + 2P$ **都不在表中**。不能只看一个孩子，也不能用「$D = 4$」代替——叶子可以出现在任意深度。

### 3.4 示例演算

![示例演算：7 个节点的路径和递推](images/wc47_q2_walkthrough.svg)

以 `nums = [111, 212, 223, 314, 325, 336, 347]` 为例：

| num | key | $V$ | $(D,P)$ | 父 key | $\text{pre}$ | 是叶子？ |
|-----|-----|-----|---------|--------|--------------|----------|
| 111 | 11 | 1 | (1,1) | — | 1 | 否（有孩子 21、22） |
| 212 | 21 | 2 | (2,1) | 11 | 1+2 = 3 | 否（有孩子 31、32） |
| 223 | 22 | 3 | (2,2) | 11 | 1+3 = 4 | 否（有孩子 33、34） |
| 314 | 31 | 4 | (3,1) | 21 | 3+4 = 7 | **是** |
| 325 | 32 | 5 | (3,2) | 21 | 3+5 = 8 | **是** |
| 336 | 33 | 6 | (3,3) | 22 | 4+6 = 10 | **是** |
| 347 | 34 | 7 | (3,4) | 22 | 4+7 = 11 | **是** |

累加四个叶子的 $\text{pre}$：$7 + 8 + 10 + 11 = 36$。注意节点 `212`、`223` 虽然算出了 $\text{pre}$，但它们是**中间节点**，不进入答案。

## 4. 算法细节

1. **一次拆分拿到键和值**：`key = num / 10`、`V = num % 10`，不要用 `num / 100`、`(num / 10) % 10` 分别取 $D$、$P$——先得到复合键，需要时再用 `key / 10`、`key % 10` 拆层号与位置。
2. **父坐标必须用向上取整**：$p$ 的父位置是 $\lceil p/2 \rceil$，整数写法 `(p + 1) / 2`；写成 `p / 2` 会让 $p=3$ 的父错成 1（正确是 2），整棵右子树都会串位。
3. **根要显式判定**：根的 `key` 是 11，写 `if (d == 1)` 最稳。若用「父 key 是否在表里」来判断，必须用 `count` 而不是 `operator[]`——后者会静默插入值 0，把根误当成「父的 pre 为 0」。
4. **不要用 0 当哨兵**：节点值可以为 0，$\text{pre}$ 也可以为 0（例如 `[110]`），用 0 表示「未计算」会直接出错。用 `d == 1` 或「是否调用过」区分。
5. **叶子判定查两个键**：`(D+1)*10 + 2*P - 1` 与 `(D+1)*10 + 2*P`，两个都 `count == 0` 才是叶子；只查左孩子会把「只有右孩子」的节点误判为叶子。
6. **数据结构可以用数组**：$D \le 4$、$P \le 8$，键值域是 $[11,48]$，开两个长度 50 的数组（值表与 $\text{pre}$ 表）比 `unordered_map` 更快，也避开哈希开销；用 `unordered_map` 时同样建议 `reserve(32)`。
7. **答案上界**：叶子最多 8 个，单条路径最多 4 个节点、每值 $\le 9$，故答案 $\le 288$，`int` 足够，不需要 `long long`。

## 5. 正确性证明

**引理 1（坐标可逆）**：三位数 `num` 与三元组 $(D,P,V)$ 一一对应，且 `key = num / 10` 与 $(D,P)$ 一一对应。

**证明**：$\text{num} = 100D + 10P + V$ 且 $0 \le V \le 9$，这是标准的十进制分解，$D$、$P$、$V$ 由 `num` 唯一确定；反之给定 $(D,P,V)$ 也唯一确定 `num`。整除 10 只是去掉个位，故 `key = 10D + P` 同样可逆。∎

**引理 2（位置法则）**：在满二叉树编号下，$(D,P)$ 的左孩子是 $(D+1,2P-1)$、右孩子是 $(D+1,2P)$，父节点是 $(D-1,\lceil P/2 \rceil)$。

**证明**：满二叉树第 $D$ 层有 $2^{D-1}$ 个位置，按从左到右 $1..2^{D-1}$ 编号。第 $D$ 层第 $k$ 个节点（$1$ 起）的左子树占据第 $D+1$ 层的第 $2k-1$ 与 $2k$ 个位置，故左孩子位置 $2P-1$、右孩子位置 $2P$；反向求父即得 $\lceil P/2 \rceil$。这正是本题题面规定的编号方式。∎

**引理 3（递推正确）**：按输入升序处理时，处理到任一非根节点前其父节点的 $\text{pre}$ 已算好，且最终 $\text{pre}[\text{key}]$ 等于根到该节点的路径和。

**证明**：父键 $10(D-1) + \lceil P/2\rceil$ 与子键 $10D + P$ 比较：因 $\lceil P/2 \rceil \le P$ 且 $D-1 < D$，父键必严格更小；输入升序保证键小的先被处理，故父已处理。对深度归纳：$D=1$ 时 $\text{pre} = V$ 即路径和；设 $D-1$ 层结论成立，则 $D$ 层节点的根到自身路径 = 根到父的路径 + 自身值，即 $\text{pre}[\text{parent}] + V$，结论成立。∎

**引理 4（叶子判定）**：节点是叶子 $\iff$ 它的两个孩子的键都不在值表中。

**证明**：($\Leftarrow$) 两个孩子键都不在表中，说明这两个位置没有节点，即该节点无孩子，按定义为叶子。($\Rightarrow$) 若节点是叶子，则它没有孩子；题面保证输入是合法二叉树（不存在「孩子有而父缺失」的孤立节点），故这两个位置不可能存在节点，键不在表中。∎

**定理**：算法返回的值等于所有「根 → 叶子」路径上节点值之和的总和。

**证明**：由引理 3，表中每个叶子的 $\text{pre}$ 恰为对应根到叶路径的节点值之和；由引理 4，遍历时被选中的节点恰好是所有叶子，无遗漏、无重复。答案即这些值之和，命题成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$，其中 $n = \text{nums.length} \le 15$。建值表 $O(n)$、递推 $\text{pre}$ $O(n)$、判叶并累加 $O(n)$，每个节点只做常数次整除、取模与哈希查找（用数组时是 $O(1)$ 直接寻址）。
- **空间**：$O(n)$。值表与 $\text{pre}$ 表各存 $n$ 个键值对；若用长度 50 的数组则是 $O(1)$ 的常数空间（$D\le 4$、$P\le 8$ 使键值域固定在 $[11,48]$）。本题树深 $\le 4$，递归写法栈深也只有 4。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int pathSum(vector<int>& nums) {
        // key = 10*D + P（num 去掉个位），值为节点值 V
        unordered_map<int, int> val;
        val.reserve(32);
        for (int num : nums) val[num / 10] = num % 10;

        // 升序即层序：处理到某节点时，它的父节点一定已经算好
        unordered_map<int, int> pre;                 // 根到该节点的路径和
        pre.reserve(32);
        for (int num : nums) {
            int key = num / 10;
            int d = key / 10, p = key % 10;
            if (d == 1) {
                pre[key] = num % 10;                 // 根：路径和就是自身值
            } else {
                int parent = (d - 1) * 10 + (p + 1) / 2;   // 父位置 = ceil(P/2)
                pre[key] = pre[parent] + num % 10;
            }
        }

        int ans = 0;
        for (int num : nums) {
            int key = num / 10;
            int d = key / 10, p = key % 10;
            int lc = (d + 1) * 10 + (2 * p - 1);     // 左孩子 (D+1, 2P-1)
            int rc = (d + 1) * 10 + (2 * p);         // 右孩子 (D+1, 2P)
            if (!val.count(lc) && !val.count(rc)) {  // 两个孩子都没有 → 叶子
                ans += pre[key];
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def pathSum(self, nums: List[int]) -> int:
        # key = 10*D + P（num 去掉个位），值为节点值 V
        val = {num // 10: num % 10 for num in nums}

        # 升序即层序：处理到某节点时，它的父节点一定已经算好
        pre = {}
        for num in nums:
            key = num // 10
            d, p = key // 10, key % 10
            if d == 1:
                pre[key] = num % 10                  # 根：路径和就是自身值
            else:
                parent = (d - 1) * 10 + (p + 1) // 2  # 父位置 = ceil(P/2)
                pre[key] = pre[parent] + num % 10

        ans = 0
        for num in nums:
            key = num // 10
            d, p = key // 10, key % 10
            left_child = (d + 1) * 10 + (2 * p - 1)   # (D+1, 2P-1)
            right_child = (d + 1) * 10 + (2 * p)      # (D+1, 2P)
            if left_child not in val and right_child not in val:
                ans += pre[key]                       # 叶子才结算整条路径
        return ans
```

## 8. 边界情况与易错点

1. **只有一个节点**：`[110]` 的答案是 0（根即叶子，值为 0）。此时 $\text{pre}$ 与答案都是 0，若把 0 当作「未计算」的哨兵就会出错——必须靠 `d == 1` 判断根。
2. **只有右孩子**：`[113, 221]` 中 221 的坐标是 $(2,2)$，是根的**右**孩子。用 $P$ 的奇偶判左右：奇数左、偶数右；不要按数组下标猜。
3. **叶子可以不在第 4 层**：示例 3 的叶子都在第 3 层。用「两个孩子都不存在」判叶子，绝不能写 `d == 4`。
4. **`p / 2` 与 `(p + 1) / 2` 之差**：$p=3$ 的父是位置 2（$p=1$ 的右孩子），取整写错会让右子树全部挂错父节点。C++/Python 的整数除法都是向下取整，所以必须写成 `(p + 1) / 2`。
5. **`unordered_map::operator[]` 的副作用**：`pre[parent]` 在父键不存在时会插入 0，让错误静默通过；判存在一律用 `count` / `find` / `in`。
6. **值可以为 0**：`[113, 210, 314]` 中 (2,1) 的值为 0，唯一路径和 $3+0+4=7$。值为 0 的中间节点不改变路径和，但它**依然占着一个位置**，不能因为值为 0 就当它不存在，更不能把它当作「空位」删掉。
7. **键值域可利用**：`key ∈ [11,48]`，若改用长度 50 的数组，记得额外开一个 `bool` 存在标记，否则「值 0 的节点」与「不存在的节点」无法区分。

**延伸思考**：

- **如果列表不保证升序**？一句话修好：先把 `nums` 按 `num / 10` 排序（或直接对 `key` 排序），层序性质就恢复了，复杂度 $O(n\log n)$；也可以不用前缀和，改成从根 $(1,1)$ 出发的 DFS，靠「孩子键是否存在」决定走向，天然不依赖顺序。
- **如果要求输出每条路径本身（而非总和）**？递推时顺便记录父指针 $O(1)$ 回溯即可，或者直接写自顶向下的 DFS，把路径栈跟着递归传。
- **如果深度超过 4**？三位数编码不再够用（百位只能放 1 位），需要改成 `pair<int,int>` 或更大的进制；算法本身（位置法则 + 前缀和）完全不变，因为它的正确性只依赖编号体系，与编码位数无关。
