# LeetCode 乘法表中第k小的数 题解

## 1. 题目概述

- **标题 / 题号**：乘法表中第k小的数（#668，hard）
- **链接**：https://leetcode.cn/problems/kth-smallest-number-in-multiplication-table/
- **来源**：LeetCode 第 47 场周赛 Q4
- **难度**：困难
- **标签**：数学、二分查找

**题意**：大小为 $m \times n$ 的乘法表中，第 $i$ 行第 $j$ 列的元素为 $i \cdot j$（$1 \le i \le m$，$1 \le j \le n$）。把整张表按升序排成一列（**重复值分别占位**），返回第 $k$ 个元素。

**约束**：

- $1 \le m, n \le 3 \times 10^4$
- $1 \le k \le m \cdot n$

关键推论：$m \cdot n$ 最大 $9 \times 10^8$，**不可能显式生成整张表**——时间与空间都会超限，必须用「计数」代替「排序」。

## 2. 示例

输出：3
解释：乘法表为
      1  2  3
      2  4  6
      3  6  9
      升序为 [1, 2, 2, 3, 3, 4, 6, 6, 9]，第 5 个是 3。
```

输出：6
解释：乘法表为
      1  2  3
      2  4  6

```

      升序 [1,2,2,3,3,4,4,5,6,6,8,9,10,12,15]，第 12 个是 9。

## 3. 解题思路

### 3.1 暴力思路

把 $mn$ 个元素全部生成、排序后取第 $k$ 个：时间 $O(mn \log(mn))$，空间 $O(mn)$。当 $m = n = 3 \times 10^4$ 时需要 $9 \times 10^8$ 个整数（约 3.6 GB）和上亿次比较，必然 MLE/TLE。

退一步用堆做多路归并（$m$ 路，每路是升序的倍数序列），每次弹出最小值后再压入下一个，复杂度 $O(k \log m)$。看似避开了存整表，但 $k$ 最坏取到 $9\times10^8$，弹出这么多次同样超时。**结论：任何「逐个产出元素」的路线都走不通，必须一次跳过大段元素。**

### 3.2 核心观察：计数函数单调 → 值域二分

![乘法表的计数函数是阶梯函数，答案是最小的 x 使 f(x) ≥ k](images/wc47_q4_count_monotone.svg)

换个问法：不问「第 $k$ 个是谁」，而问「**有多少个元素 $\le x$**」。定义

$$f(x) = \#\{(i,j) : 1 \le i \le m,\ 1 \le j \le n,\ i \cdot j \le x\}$$

它有几条立即可用的性质：$f$ 关于 $x$ **单调不减**；$f(0) = 0$；$f(mn) = mn$。单调性直接把「第 $k$ 小」变成一个判定问题：

$$f(x) \ge k \iff \text{表中第 } k \text{ 小的数} \le x$$

于是答案就是那个**分界点**

$$x^* = \min\{\,x \ge 1 : f(x) \ge k\,\}$$

只要单次求 $f(x)$ 能做到 $O(\min(m,n))$，在值域 $[1, mn]$ 上二分 $O(\log(mn))$ 轮即可，总计约 $9 \times 10^5$ 次操作。

> 💡 **与「候选集合二分」的区别**：本题二分的是**值域**，`mid` 未必是表中真实出现的值（例如 $3\times3$ 表中并没有 5）。因此要采用 `lo < hi` + `hi = mid` 的写法，让区间自然收敛到第一个可行值，而不是 `hi = mid - 1`。

**为什么分界点一定在表里？** 直觉上：$f$ 只在「表中真实出现的值」处发生跳跃。$x^*$ 是 $f$ 第一次达到 $k$ 的位置，说明 $f(x^*-1) < k \le f(x^*)$，$f$ 在 $x^*$ 处严格增长，因此表中确实有元素恰好等于 $x^*$——否则 $f(x^*) = f(x^*-1)$，与最小性矛盾。形式化证明见 §5 引理 3。

### 3.3 算法流程：逐行整除计数

![值域二分流程与逐行整除计数](images/wc47_q4_algorithm_flow.svg)

求 $f(x)$ 的关键在**行内结构**：第 $i$ 行的元素是 $i, 2i, 3i, \dots, ni$，天然升序，且都是 $i$ 的倍数。要数其中 $\le x$ 的个数，只需求最大的合法下标：

$$i \cdot j \le x \iff j \le \left\lfloor \frac{x}{i} \right\rfloor$$

但每行只有 $n$ 列，故第 $i$ 行贡献 $\min\!\left(n, \lfloor x/i \rfloor\right)$，累加得

$$f(x) = \sum_{i=1}^{m} \min\!\left(n, \left\lfloor \frac{x}{i} \right\rfloor\right)$$

每个 $i$ 只需一次整除 + 一次 `min`，共 $O(m)$。整体流程：

1. 令 $m \gets \min(m,n)$、$n \gets \max(m,n)$（乘法表转置后元素集合不变）。
2. 二分区间取 $[1, mn]$。
3. 每轮取 `mid`，令 $i$ 从 $1$ 到 $m$ 累加 $\min(n, \lfloor mid/i \rfloor)$；若 $i > mid$ 或累计值已 $\ge k$，提前收手。
4. 若 `cnt >= k`：$x^* \le mid$，置 `hi = mid`；否则 $x^* > mid$，置 `lo = mid + 1`。
5. 循环结束时 `lo == hi`，即第 $k$ 小的数。

### 3.4 示例演算

![m=3, n=3, k=5 的三轮二分走查](images/wc47_q4_walkthrough.svg)

以 $m = 3$、$n = 3$、$k = 5$ 为例，在 $[1, 9]$ 上二分：

| 轮次 | $[lo, hi]$ | $mid$ | 逐行 $\min(n, \lfloor mid/i\rfloor)$ | $cnt$ | 判定 |
|------|-----------|-------|--------------------------------------|-------|------|
| 1 | $[1,9]$ | 5 | $3,\ 2,\ 1$ | 6 | $\ge 5 \Rightarrow hi = 5$ |
| 2 | $[1,5]$ | 3 | $3,\ 1,\ 1$ | 5 | $\ge 5 \Rightarrow hi = 3$ |
| 3 | $[1,3]$ | 2 | $2,\ 1,\ 0$ | 3 | $< 5 \Rightarrow lo = 3$ |
| 结束 | $lo = hi = 3$ | — | — | — | 返回 3 |

注意 $f$ 的阶梯形状：$f(1)=1$、$f(2)=3$、$f(3)=5$、$f(4)=6$、$f(5)=6$。$4$ 与 $5$ 之间是一段**平台**（没有新值出现），这正是「`mid` 可能不是表中元素」的直观体现；而 $f$ 在 $x = 3$ 处从 3 跳到 5，说明表中确实存在 3。

## 4. 算法细节

1. **转置让外层更小**：$a_{ij} = a_{ji}$，故 $(m,n)$ 表与 $(n,m)$ 表的元素集合完全相同、答案不变。把较小的维度放到外层，单次计数从 $O(m)$ 降为 $O(\min(m,n))$，在 $m,n$ 悬殊时是常数倍的实质差别。
2. **封顶 $n$ 不能省**：$i$ 很小时 $\lfloor mid/i \rfloor$ 可能远大于列数。例如 $3\times3$ 表取 $x=9$，第 1 行算出 $\lfloor 9/1 \rfloor = 9$，但该行只有 3 个元素；漏掉 `min` 会把不存在的「虚拟列」算入，导致 $f$ 偏大、二分向右错位。
3. **两个提前终止**：$i > mid$ 时 $\lfloor mid/i \rfloor = 0$，后续行贡献只会更小，直接 `break`；累计 `cnt >= k` 时也无需继续——判定只关心「够不够 $k$ 个」。
4. **二分模板**：`lo = 1`、`hi = m * n`，`while (lo < hi)`；可行走 `hi = mid`（保留 `mid`，它可能就是答案），不可行走 `lo = mid + 1`。循环内 `mid = lo + (hi - lo) / 2`，保证 `mid ∈ [lo, hi)`，不会死循环。
5. **溢出边界**：$mn \le 9\times10^8 < 2^{31}-1$，`cnt` 用 `int` 足够；若题面上界改为 $10^5$ 量级，`m * n` 与 `cnt` 都必须换 `long long`。
6. **判可行用 `>=` 而不是 `==`**：乘法表重复值极多（$6 = 2\cdot3 = 3\cdot2 = 1\cdot6$），$f$ 会跳跃，某些 $k$ 永远不会出现 `cnt == k` 的等号。
7. **不需要记录 `ans`**：值域二分的收敛点就是第一个可行值，`lo` 本身就承载答案，无需额外的候选变量。

## 5. 正确性证明

**引理 1（行计数公式）**：对任意 $1 \le i \le m$，第 $i$ 行中 $\le x$ 的元素个数恰为 $\min\!\left(n, \lfloor x/i \rfloor\right)$。

**证明**：第 $i$ 行第 $j$ 个元素是 $i \cdot j$，条件 $i \cdot j \le x$ 等价于 $j \le x/i$；因 $j$ 是整数，即 $j \le \lfloor x/i \rfloor$。另一方面 $j$ 只能取 $1, 2, \dots, n$ 共 $n$ 个值。两者取交集，个数为 $\min\!\left(n, \lfloor x/i \rfloor\right)$。∎

**引理 2（单调性）**：$f(x)$ 等于表中 $\le x$ 的元素总数，且关于 $x$ 单调不减。

**证明**：由引理 1 逐行相加即得第一句。若 $x_1 \le x_2$，任一满足 $i\cdot j \le x_1$ 的格子也满足 $i \cdot j \le x_2$，故 $f(x_1) \le f(x_2)$。∎

**引理 3（分界点必在表中）**：设 $x^* = \min\{x \ge 1 : f(x) \ge k\}$，则存在 $(i,j)$ 使 $i \cdot j = x^*$。

**证明**：由 $x^*$ 的最小性有 $f(x^*-1) < k$（当 $x^* = 1$ 时约定 $f(0) = 0 < k$，因 $k \ge 1$），而 $f(x^*) \ge k$。两式相减得

$$f(x^*) - f(x^*-1) \ge k - (k-1) = 1$$

差值恰是「取值等于 $x^*$」的格子数（$\le x^*$ 的格子减去 $\le x^*-1$ 的格子），故至少有一个格子满足 $i \cdot j = x^*$。∎

**引理 4（判定等价）**：$f(x) \ge k$ 当且仅当表中第 $k$ 小的数 $\le x$。

**证明**：若 $f(x) \ge k$，则表中至少有 $k$ 个元素 $\le x$，把它们升序排列后第 $k$ 个必然 $\le x$；反之若第 $k$ 小的数为 $y \le x$，则至少有 $k$ 个元素 $\le y \le x$，即 $f(x) \ge k$。∎

**定理**：算法返回的 $lo$ 等于表中第 $k$ 小的数。

**证明**：维护不变式 $lo \le x^* \le hi$。初始 $lo = 1 \le x^*$（因 $x^* \ge 1$），$hi = mn$ 且 $f(mn) = mn \ge k$，故 $x^* \le mn$。每轮取 $mid \in [lo, hi)$：若 $f(mid) \ge k$，由 $x^*$ 的最小性得 $x^* \le mid$，置 $hi = mid$ 后不变式保持；若 $f(mid) < k$，则 $x^* > mid$，置 $lo = mid + 1$ 后不变式保持。循环终止时 $lo = hi$，故 $lo = x^*$。最后由引理 3，$x^*$ 是表中真实存在的值；结合引理 4 与 $x^*$ 的最小性，$\le x^*-1$ 的元素不足 $k$ 个、$\le x^*$ 的元素至少 $k$ 个，因此第 $k$ 小恰为 $x^*$。∎

## 6. 复杂度分析

- **时间**：$O(\min(m,n) \cdot \log(mn))$。二分至多 $\lceil \log_2(mn) \rceil \le 30$ 轮，每轮遍历 $\min(m,n) \le 3\times10^4$ 行、每行 $O(1)$ 次整除，总计约 $9\times10^5$ 次基本运算，实测 C++ 单次约 1 ms。
- **空间**：$O(1)$。只使用 `lo`、`hi`、`mid`、`cnt` 四个整型变量，不构造任何表结构。
- **与暴力对比**：暴力需要 $O(mn \log(mn))$ 时间与 $O(mn)$ 空间；本解把「逐元素处理」换成「整段计数」，是本题唯一可行的方向。Python 版本在 $m=n=3\times10^4$ 的最大用例上约 120 ms。

## 7. 参考代码

### C++

```cpp
#include <algorithm>

class Solution {
public:
    int findKthNumber(int m, int n, int k) {
        if (m > n) std::swap(m, n);       // 转置：元素集合不变，外层只跑 min(m,n)
        int lo = 1, hi = m * n;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            int cnt = 0;
            for (int i = 1; i <= m && i <= mid; ++i) {
                cnt += std::min(mid / i, n);
                if (cnt >= k) break;      // 已够 k 个，无需继续统计
            }
            if (cnt >= k) hi = mid;       // 第 k 小 ≤ mid，答案在左闭区间
            else          lo = mid + 1;   // 第 k 小 > mid
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def findKthNumber(self, m: int, n: int, k: int) -> int:
        if m > n:
            m, n = n, m                  # 转置不改变元素集合
        lo, hi = 1, m * n
        while lo < hi:
            mid = (lo + hi) // 2
            cnt = 0
            for i in range(1, m + 1):
                if i > mid:
                    break                # 后续行贡献全为 0
                cnt += min(mid // i, n)
                if cnt >= k:
                    break                # 已够 k 个
            if cnt >= k:
                hi = mid                 # 第 k 小 ≤ mid
            else:
                lo = mid + 1             # 第 k 小 > mid
        return lo
```

## 8. 边界情况与易错点

1. **$k = 1$ 与 $k = mn$**：前者答案恒为 1（左上角），后者恒为 $mn$（乘积最大的一格，转置后仍是同一值）。二分区间必须取 $[1, mn]$，写成 $[2, mn]$ 或 $[1, mn-1]$ 都会漏掉端点。
2. **单行或单列表**：$m = 1$ 时表就是 $1, 2, \dots, n$，答案为 $k$；转置后外层只有 1 行，$f(x) = \min(n, x)$，二分依然正确，无需特判。
3. **漏掉 `min(·, n)` 封顶**：小 $i$ 行的高估会让 $f$ 偏大、二分收敛到偏小的错值，这是本题最常见的 WA。
4. **误用 `hi = mid - 1`**：`mid` 可能不等于任何表中元素（如 $4$ 与 $5$ 之间的平台），减 1 会跨过分界点，返回无效值。
5. **用 `cnt == k` 判终止**：$f$ 在重复值处跳跃（$3\times3$ 表中 $f(3)=5$、$f(4)=6$），部分 $k$ 永远不会「恰好命中」，必须用 `>=`。
6. **循环条件写成 `lo <= hi`**：配合 `hi = mid` 会在 `lo == hi` 且仍可行时原地打转；正确写法是 `while (lo < hi)`。
7. **大 $m,n$ 的乘积类型**：本题 $mn \le 9\times10^8$ 未溢出 `int`；若把上界提到 $10^5$，`m * n` 必须改用 `long long`，否则 `mid` 直接变负数。
