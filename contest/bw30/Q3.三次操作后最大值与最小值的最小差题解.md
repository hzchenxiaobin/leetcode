# LeetCode 三次操作后最大值与最小值的最小差 题解

## 1. 题目概述

- **标题 / 题号**：三次操作后最大值与最小值的最小差（#1509，medium）
- **链接**：https://leetcode.cn/problems/minimum-difference-between-largest-and-smallest-value-in-three-moves/
- **来源**：LeetCode 第 30 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：每次操作可把 `nums` 中**任意一个**元素改成**任意值**。最多执行 3 次操作后，返回数组中**最大值与最小值之差**能达到的最小值。

**约束**：

- $1 \le nums.length \le 10^5$
- $-10^9 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [5,3,2,4]
输出：0
解释：3 次操作分别把 2、4、5 都改成 3，数组变 [3,3,3,3]，差为 0。
```

**示例 2**

```text
输入：nums = [1,5,0,10,14]
输出：1
解释：排序得 [0,1,5,10,14]。最优是把 3 个「极端值」向中间收：
      改 0→1、10→5、14→5 后数组 [1,1,5,5,5]，差为 1。
```

**示例 3（n ≤ 4 直接归零）**

```text
输入：nums = [3,100,20]
输出：0
解释：3 个元素，3 次操作足以把其中 3 个都改成第 4 个的值（或全改成同一个值），差为 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「哪些元素被改、改成什么值」——改成什么值的最优选择本身可以证明（见引理 1）是「改成某个保留元素的值」，于是可枚举从 $n$ 个元素里**保留哪些**：$\binom{n}{n-3}$ 种组合再各自求极差，$O(n^4)$ 级别，$n = 10^5$ 完全不可行。更进一步的洞察是：被改的元素若不是「当前最大/最小的极端者」，改动它毫无收益——极端值才是极差的来源。这把候选组合数瞬间压到常数个。

### 3.2 核心观察：只动两端，四种分配

![核心观察：3 次操作只花在两端，四种「抬小压大」的分配](images/bw30_q3_four_cases.svg)

**把一个元素改成任意值，等价于把它从「极差计算」中删去**——因为改成什么最好？改成最终保留区间的任一值（如新的最小值）即可，它的存在不再拉大极差。于是「至多 3 次操作」=「至多删去 3 个元素」，且**只有删最大的或最小的元素才可能减小极差**（删中间元素不改变 min/max）。

排序后，删去的 3 个元素应该全部来自「最大的若干个」和「最小的若干个」。设删 $i$ 个最小的、$3 - i$ 个最大的（$i = 0, 1, 2, 3$），剩余极差即

$$\min_{0 \le i \le 3}\ \big(nums[n-4+i] - nums[i]\big)$$

（下标含义：删去前 $i$ 个与后 $3-i$ 个后，剩余元素的最小值是 $nums[i]$、最大值是 $nums[n-4+i]$。）只有 4 种组合，逐个取 min 即可。$n \le 4$ 时 3 次操作可删掉除一个元素外的全部，极差直接为 0。

### 3.3 算法流程

```text
1. n = len(nums)
2. 若 n ≤ 4：返回 0          # 3 次操作可改掉除 1 个外的全部元素
3. nums 排序
4. 返回 min(nums[n−4+i] − nums[i] for i in 0..3)
```

### 3.4 示例演算

![示例演算：1,5,0,10,14 的四种删除方案对比](images/bw30_q3_walkthrough.svg)

以示例 2（排序后 $[0, 1, 5, 10, 14]$，$n = 5$）为例：

| 方案 | 删除（i 个最小 + 3−i 个最大） | 剩余区间 | 极差 |
|------|-------------------------------|----------|------|
| $i=0$ | 后 3 个：10, 14 及 5 | $[0, 1]$ | 1 |
| $i=1$ | 0；14, 10 | $[1, 5]$ | 4 |
| $i=2$ | 0, 1；14 | $[5, 10]$ | 5 |
| $i=3$ | 0, 1, 5 | $[10, 14]$ | 4 |

四种方案最小值为 $1$，与期望一致（改 $0 \to 1$、$10 \to 5$、$14 \to 5$ 即方案 $i=0$ 的实现）。

## 4. 算法细节

1. **等价转化的精确表述**：「至多 3 次改值」严格强于「删 3 个」吗？不弱——删 3 个总能用 3 次改值模拟（把要删的元素改成保留区间的某个值）；改 3 个也总能用删 3 个模拟出**不更大**的极差（见引理 2）。两者等价，故按「删」分析不失一般性。
2. **排序后只需 4 次比较**：`ans = min(nums[n-4]-nums[0], nums[n-3]-nums[1], nums[n-2]-nums[2], nums[n-1]-nums[3])`；Python 里用生成器 + `min` 一行表达。
3. **$n \le 4$ 特判**：4 个元素删 3 个剩 1 个（极差 0）；1、2、3 个元素同理（3 次操作足以改掉 $n - 1$ 个）。判据 $n \le 4$ 对应「删除数 $\ge n - 1$」。
4. **溢出贴近上界**：$|nums[i]| \le 10^9$，极差最大 $2 \times 10^9$，虽未超过 `int` 上界 $2147483647$ 但极其贴近，C++ 计算差值时用 `long long` 是最稳的习惯。
5. **改值的「任意值」包括越界值**：改成的目标值不必在原数组值域内（如全改成 $0$），这不影响「删元素」等价性——删去后该元素对 min/max 无贡献，改到任何「保留区间内」的值都一样。

## 5. 正确性证明

**引理 1（改值 = 删除）**：设某方案执行至多 3 次改值后极差为 $D$，则存在「删去至多 3 个元素」的方案使剩余极差 $\le D$；反之任何「删去 $m \le 3$ 个元素」的方案可由 $m$ 次改值实现且极差相同。

**证明**：改值方案中被改的至多 3 个元素记为集合 $C$，未改元素 $R = nums \setminus C$ 的极差 $\le D$（整体极差 $\ge$ 任何子集极差）。删去 $C$ 后剩余恰为 $R$，极差 $\le D$。反向：删去集合 $C$（$|C| = m \le 3$）后剩余最小值 $a$、最大值 $b$，把 $C$ 中每个元素改成 $a$（$m$ 次操作），全数组极差仍为 $b - a$。∎

**引理 2（只删两端不劣）**：对任何删 $m \le 3$ 个元素的方案 $C$，存在只删「最小的若干个与最大的若干个」共 $m$ 个的方案 $C'$，使剩余极差不增。

**证明**：设 $C$ 删后剩余集合 $R$ 的最小值为 $nums[i]$、最大值为 $nums[j]$（排序后下标），则 $R \subseteq [nums[i], nums[j]]$ 且 $R$ 至多删去 $m$ 个元素，故 $j - i + 1 \ge n - m$，即区间 $[i, j]$ 外的元素个数 $\le m$。构造 $C'$ = 区间 $[i,j]$ **之外**的全部元素（$\le m$ 个），再从区间两端向内补足到恰 $m$ 个删除（删 $nums[i]$ 或 $nums[j]$ 侧的元素只会让剩余的 min 不减、max 不增）。$C'$ 删后剩余集合 $R' \subseteq R$（若补删了端点则 $R' \subsetneq R$ 的极差 $\le$ 原极差；未补删则 $R' = R$ 中极差相同，更准确地说 $R' = \{nums[i..j]\} \setminus \text{补删端点}$，其 min $\ge nums[i]$、max $\le nums[j]$）。两种情形剩余极差均 $\le nums[j] - nums[i] = D$。∎

**定理**：$n \ge 5$ 时，$\min_{0 \le i \le 3}\big(nums[n-4+i] - nums[i]\big)$（排序后）为答案；$n \le 4$ 时答案为 0。

**证明**：由引理 1，最优值等于「删至多 3 个元素后的最小极差」。由引理 2，最优删除集可设为「删 $i$ 个最小 + $3-i$ 个最大」（不足 3 个时补删端点不劣，或等价地视为 $i$ 与 $3-i$ 之和 $< 3$ 的情形被 $i' \ge i$ 覆盖：多删只会让极差不增，故只需求恰删 3 个的四种分配）。删 $i$ 小 $3-i$ 大后剩余元素为 $nums[i..n-4+i]$（共 $n - 3$ 个），极差 $nums[n-4+i] - nums[i]$。对 $i = 0, 1, 2, 3$ 取最小即得。$n \le 4$ 时删 $n - 1 \le 3$ 个只剩单元素，极差 0，且由引理 1 可用改值实现。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$，排序主导；排序后仅 4 次减法比较。若只需前 4 小/后 4 大可用 `nth_element` 思想做到 $O(n)$，但 $n = 10^5$ 下排序已绰绰有余。
- **空间**：$O(1)$ 额外（原地排序；Python 的 `sort` 也是原地）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minDifference(vector<int>& nums) {
        int n = (int)nums.size();
        if (n <= 4) return 0;                    // 4 个以内：改其余全部即可归零
        sort(nums.begin(), nums.end());
        long long ans = 4e9;
        for (int i = 0; i < 4; ++i)
            ans = min(ans, (long long)nums[n - 4 + i] - nums[i]);
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minDifference(self, nums: list[int]) -> int:
        n = len(nums)
        if n <= 4:
            return 0
        nums.sort()
        return min(nums[n - 4 + i] - nums[i] for i in range(4))
```

> 💡 两份代码均通过全部官方示例（$0$ / $1$ / $0$）及 $n = 1 \sim 4$ 边界；另与「枚举所有 $\le 3$ 个元素的删除组合、对每组求剩余极差」的独立暴力实现在 2000 组随机数组（$n \le 12$，值域 $[-50, 50]$）上对拍，并在 $n = 10^5$、元素 $\pm 10^9$ 的满规模极值数据上与 Python 版交叉对拍，失配数均为 0。

## 8. 边界情况与易错点

1. **$n \le 4$ 必须特判**：此时 3 次操作足以改掉 $n - 1 \le 3$ 个元素、让全数组相等，极差为 0。若不特判，$n \le 3$ 时公式里 `n - 4 + i` 为负下标直接越界；$n = 4$ 时公式碰巧全算出 $nums[i] - nums[i] = 0$，但那是「删 3 剩 1」的巧合，不能作为不特判的理由。
2. **溢出贴近上界**：$-10^9$ 与 $10^9$ 之差 $2 \times 10^9$，恰在 `int` 上界 $2147483647$ 之下但非常贴近，任何中间运算稍加放大（如先加后减）就可能越界；C++ 用 `long long` 计算差值最稳，返回前转 `int` 是安全的。
3. **「改中间元素」没有意义**：极差只由 min/max 决定，把中间元素改成任何值都不改变两端（除非改到端点之外反向拉大极差），故最优解不包含改中间元素——这个直觉由引理 2 严格化。
4. **「至多 3 次」不是「恰好 3 次」**：少用操作不劣（改值只会带来更多自由度），分析按恰 3 次取 min 不影响结果。
5. **数组未排序就套公式**：公式完全依赖有序性，务必先 `sort`。

**延伸思考**：本题的「改值 = 删除」等价是有损的——若把「改成任意值」换成「改成相邻元素的值」「改变固定代价」等带约束的操作，等价性立刻崩塌（如每次只能 $\pm 1$，就变成计算最小操作次数的另一类问题）。更一般的框架是：$m$ 次任意改值下最小化 max-min，等价于在排序数组的「两端各取若干」的 $m+1$ 种分配中取最优——这个「$m+1$ 种组合」结构在「移动石子」「配对差值」等一串题里反复出现，识别它比记住公式更重要。
