# LeetCode 三个无重叠子数组的最大和 题解

## 1. 题目概述

- **标题 / 题号**：三个无重叠子数组的最大和（#689，hard）
- **链接**：https://leetcode.cn/problems/maximum-sum-of-3-non-overlapping-subarrays/
- **来源**：LeetCode 第 52 场周赛 Q4
- **难度**：困难
- **标签**：数组，动态规划，前缀和，滑动窗口

**题意**：给定整数数组 `nums` 和整数 $k$，在「长度恰为 $k$、两两不重叠」的所有三元子数组中，选出元素**总和最大**的一组，返回这三个子数组的**起始下标**（从小到大排列）。若有多组同时达到最大和，返回**字典序最小**的那一组。

**约束**：

- $1 \le \text{nums.length} \le 2 \times 10^4$
- $1 \le \text{nums}[i] < 2^{16}$
- $1 \le k \le \lfloor \text{nums.length} / 3 \rfloor$，即**输入一定存在可行解**，不必考虑无解

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,1,2,6,7,5,1], k = 2
输出：[0,3,5]
解释：[1,2]、[2,6]、[7,5] 起始下标为 [0,3,5]，和为 3 + 8 + 12 = 23，是全局最大；
      也可以取 [1,3,5]（[2,1] + [2,6] + [7,5]）同样等于 23，
      但 [0,3,5] 的字典序更小，故输出前者。
```

**示例 2**

```text
输入：nums = [1,2,1,2,1,2,1,2,1], k = 2
输出：[0,2,4]
解释：任意长度为 2 的窗口和都是 3，所以最大和恒为 9，所有方案并列；
      [0,2,4] 是字典序最小的方案。
```

**补充示例（并列 + 非均匀数据）**

```text
输入：nums = [4,5,10,6,11,17,4,4,4,4], k = 2
输出：[0,2,4]
解释：[4,5] + [10,6] + [11,17] = 9 + 16 + 28 = 53；
      [1,3,5] 为 15 + 17 + 21 = 53，同样并列，但字典序 [0,2,4] 更小。
```

## 3. 解题思路

### 3.1 暴力思路

直接枚举三个起点 $i < j < l$，要求 $i + k \le j$、$j + k \le l$，再分别求和：$O(n^3)$ 枚举 × $O(k)$ 求和 = $O(n^3 k)$，$n = 2\times 10^4$ 时约 $10^{12}$ 量级，必然超时。

即使用前缀和把每段求和降到 $O(1)$，三层枚举仍是 $O(n^3) \approx 8\times 10^{12}$。所以必须想办法把「三层枚举」压掉两层。

关键的结构性观察有两条：

- 长度固定为 $k$，一个子数组由**起点**唯一确定，候选对象只有 $m = n - k + 1$ 个「窗口」；
- 互不重叠 $\iff$ 三个起点之间至少隔 $k$，即 $i + k \le j$ 且 $j + k \le l$。

### 3.2 核心观察：固定中间窗口，左右两侧彻底解耦

![把区间选择降维成窗口下标选择](images/wc52_q4_window_sums.svg)

记 $w[i] = \text{nums}[i] + \dots + \text{nums}[i+k-1]$，$i = 0,\dots,m-1$。问题变为：在 $w$ 上选 $i < j < l$，满足 $i + k \le j$、$j + k \le l$，最大化 $w[i] + w[j] + w[l]$。

**固定中间的 $j$**，左右两段的选择就完全独立了：

- 左窗口起点只能落在 $[0,\,j-k]$，最优值是 $L(j) = \max_{0 \le i \le j-k} w[i]$；
- 右窗口起点只能落在 $[j+k,\,m-1]$，最优值是 $R(j) = \max_{j+k \le l \le m-1} w[l]$；
- 三者之间没有任何耦合，于是「固定 $j$ 的最优和」就是 $L(j) + w[j] + R(j)$。

把 $L$ 与 $R$ 对**所有** $j$ 预处理出来（就是前缀最值 / 后缀最值），枚举 $j$ 时每个位置只需一次加法，总复杂度降到 $O(n)$。这实质上是最朴素的一维 DP：

$$\text{best}[i] = \max\bigl(\text{best}[i-1],\ w[i]\bigr)\ (\text{正向}),\qquad \text{best}[i] = \max\bigl(\text{best}[i+1],\ w[i]\bigr)\ (\text{反向})$$

只不过我们存的不是最大值本身，而是**取到最大值的最小下标**——这样可以一路携带「字典序最小」的信息。

### 3.3 算法流程

![前后缀最值数组的构造与查询](images/wc52_q4_prefix_suffix_best.svg)

1. **滑动窗口求窗口和**（$O(n)$）：
   $$w[0] = \sum_{t=0}^{k-1}\text{nums}[t],\qquad w[i] = w[i-1] - \text{nums}[i-1] + \text{nums}[i+k-1]$$
2. **正向扫描求 left**：`left[i]` = $[0,i]$ 中 $w$ 最大的**最小下标**。当 $w[i] > w[\text{left}[i-1]]$ 时才更新，并列时保留更早的下标。
3. **反向扫描求 right**：`right[i]` = $[i,m-1]$ 中 $w$ 最大的**最小下标**。注意比较符是 $w[i] \ge w[\text{right}[i+1]]$：因为从右往左扫，`>=` 会把最优下标不断「往小推」，正好在并列时留下最小下标。
4. **枚举中间窗口** $j \in [k,\ m-k-1]$，对应的候选三元组是
   $$\bigl(\text{left}[j-k],\ j,\ \text{right}[j+k]\bigr)$$
   按「和更大，或和相同但整组下标更小」更新答案。

### 3.4 示例演算

![示例 1 的三种中间窗口](images/wc52_q4_example_walkthrough.svg)

以示例 1 为例：`nums = [1,2,1,2,6,7,5,1]`，$k=2$，于是

$$w = [3,3,3,8,13,12,6],\quad m = 7$$
$$\text{left} = [0,0,0,3,4,4,4],\quad \text{right} = [4,4,4,4,4,5,6]$$

$j$ 只能取 $2,3,4$：

| $j$ | $i=\text{left}[j-k]$ | $l=\text{right}[j+k]$ | 和 | 三元组 |
|-----|----------------------|-----------------------|----|--------|
| 2 | 0 | 4 | $3+3+13=19$ | (0,2,4) |
| 3 | 0 | 5 | $3+8+12=23$ | (0,3,5) |
| 4 | 0 | 6 | $3+13+6=22$ | (0,4,6) |

最大和 23 只在 $j=3$ 取得，输出 `[0,3,5]`，与官方答案一致。

再看并列情形：`nums = [4,5,10,6,11,17,4,4,4,4]`、$k=2$ 时，$j=2$ 给出 $9+16+28=53$（`[0,2,4]`），$j=3$ 给出 $15+17+21=53$（`[1,3,5]`）——两组同和，必须比较整组下标，取字典序更小的 `[0,2,4]`。

## 4. 算法细节

1. **窗口和用滑动窗口，不要反复求和**。`sum(nums[i:i+k])` 每次 $O(k)$，总量 $O(nk)$；滑动窗口只做一加一减，$O(n)$，且不需要单独的前缀和数组。
2. **两个数组的并列处理方向相反**：`left` 正向扫描、用严格 `>`（并列留更早的下标）；`right` 反向扫描、用 `>=`（并列把下标推到更小）。写反会让 `right` 在并列时指向最右那个下标，示例 2 会得到 `[0,2,7]` 而不是 `[0,2,4]`。
3. **$j$ 的范围是 $[k,\ m-k-1]$（两端都含）**，等价于 $k \le j \le n - 2k$。当 $3k = n$ 时只剩 $j = k$ 一种，循环边界写成 `for j in range(k, m-k)` 才刚好覆盖。
4. **并列时按整组下标比较**：字典序先比 $i$、再比 $j$、最后比 $l$。代码里写成 `cur > bestSum or (cur == bestSum and cand < res)`。其实可以证明「$j$ 递增 + 只有严格更大才替换」也是对的（若并列时出现更小的 $i$，把它换到前一个 $j$ 上会得到严格更大的和，矛盾），但整组比较更直白，不需要额外论证。
5. **数值范围**：单个窗口和 $\le k \cdot (2^{16}-1)$，三个窗口之和最大约 $3 \times 6666 \times 65535 \approx 1.3\times 10^{9}$，勉强在 `int` 内；但余量很窄，C++ 实现统一用 `long long`，避免换参数或改成四段时溢出。
6. **答案下标是 0-based 起点**，既不是右端点也不是 1-based 下标；三个下标天然递增，不需要再排序。
7. **兜底**：`if (3 * k > n) return {};`。本题约束保证不触发，但作为可复用的模板保留这一行更安全。

## 5. 正确性证明

**引理 1（固定 $j$ 时的分解）**：对任意合法中间窗口 $j$，任何合法三元组 $(i,j,l)$ 都满足 $w[i] \le L(j)$、$w[l] \le R(j)$；且和取得最大值时必有 $w[i] = L(j)$ 与 $w[l] = R(j)$。

**证明**：由 $i + k \le j$ 得 $i \le j-k$，故 $i$ 落在 $[0,j-k]$ 内，$w[i] \le \max_{0\le t\le j-k} w[t] = L(j)$；同理由 $l \ge j+k$ 得 $w[l] \le R(j)$。若 $w[i] < L(j)$，取任一满足 $w[t^\ast] = L(j)$ 的下标 $t^\ast$，显然 $t^\ast \le j-k$，把 $i$ 换成 $t^\ast$ 后仍是合法三元组且和严格变大，与「取得最大值」矛盾；故 $w[i] = L(j)$。对 $l$ 同理。∎

**引理 2（left / right 数组计算正确）**：正向扫描结束时 $\text{left}[i]$ 是 $[0,i]$ 中使 $w$ 取最大值的最小下标；反向扫描结束时 $\text{right}[i]$ 是 $[i,m-1]$ 中使 $w$ 取最大值的最小下标。

**证明**：对 $i$ 归纳。$i=0$ 时 $\text{left}[0]=0$，显然正确。设 $\text{left}[i-1]$ 是 $[0,i-1]$ 的最优最小下标，则 $[0,i]$ 的最大值只可能来自 $[0,i-1]$ 或 $i$：若 $w[i] > w[\text{left}[i-1]]$，最大值唯一地是 $i$，取 $\text{left}[i]=i$；否则最大值仍是 $w[\text{left}[i-1]]$，而 $\text{left}[i-1]$ 已是并列中最小者，取 $\text{left}[i]=\text{left}[i-1]$。两种情况都得到最小下标。`right` 的证明把区间方向反转对称即可：反向扫描时若 $w[i] \ge w[\text{right}[i+1]]$ 就取 $i$，由于 $i < \text{right}[i+1]$，等号成立时取的正是并列中更小的下标。∎

**引理 3（固定 $j$ 时字典序最小）**：在固定 $j$ 的所有最优三元组中，$(\text{left}[j-k],\, j,\, \text{right}[j+k])$ 的字典序最小。

**证明**：由引理 1，固定 $j$ 的最优三元组集合恰为 $\{(i,j,l) \mid w[i]=L(j),\ w[l]=R(j)\}$——$i$ 与 $l$ 的选择互相独立。字典序比较先看 $i$，故应取并列中最小的 $i$，由引理 2 即 $\text{left}[j-k]$；$i$ 相同后再比 $l$，同理取 $\text{right}[j+k]$。∎

**定理**：算法输出的下标数组是所有合法方案中「和最大、且并列时字典序最小」的那一个。

**证明**：合法性：$\text{left}[j-k] \le j-k$、$\text{right}[j+k] \ge j+k$，故三段互不重叠；三个下标递增。最优性：任一合法三元组的中间下标 $j$ 必满足 $k \le j \le m-k-1$（因为 $i \ge 0 \Rightarrow j \ge k$，$l \le m-1 \Rightarrow j \le m-k-1$），被枚举覆盖；由引理 1 其和不超过 $L(j)+w[j]+R(j)$，而算法对该 $j$ 取到的正是这个上界，故算法取的最大值不劣于任何方案。字典序：全局最优方案必属于某个 $j$，对每个 $j$ 算法已取到该 $j$ 下字典序最小者（引理 3），外层再按整组下标取最小，于是全局字典序最小。∎

## 6. 复杂度分析

- **时间**：$O(n)$。滑动窗口求 $w$ 一趟 $O(n)$；`left`、`right` 各一趟 $O(m)$；枚举 $j$ 一趟 $O(m)$，每次 $O(1)$ 查询与比较。合计 $O(n)$，$n = 2\times 10^4$ 时不到 $10^5$ 次基本操作。
- **空间**：$O(n)$。窗口和数组 $w$、前缀最值 `left`、后缀最值 `right` 各长 $m \le n$，均为整数数组；除返回值外无其他辅助结构，可视为 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <numeric>
using namespace std;

class Solution {
public:
    vector<int> maxSumOfThreeSubarrays(vector<int>& nums, int k) {
        int n = nums.size();
        if (3 * k > n) return {};

        int m = n - k + 1;                       // 长度为 k 的窗口个数
        vector<long long> w(m);
        w[0] = accumulate(nums.begin(), nums.begin() + k, 0LL);
        for (int i = 1; i < m; i++)              // 滑动窗口：一加一减
            w[i] = w[i - 1] - nums[i - 1] + nums[i + k - 1];

        vector<int> L(m), R(m);
        int b = 0;
        for (int i = 0; i < m; i++) {            // left[i] = [0,i] 中最大的最小下标
            if (w[i] > w[b]) b = i;              // 严格大于：并列留更早的
            L[i] = b;
        }
        b = m - 1;
        for (int i = m - 1; i >= 0; i--) {       // right[i] = [i,m-1] 中最大的最小下标
            if (w[i] >= w[b]) b = i;             // 大于等于：并列把下标往小推
            R[i] = b;
        }

        long long bestSum = -1;
        vector<int> res;
        for (int j = k; j < m - k; j++) {        // 枚举中间窗口的起点
            int i = L[j - k], l = R[j + k];
            long long cur = w[i] + w[j] + w[l];
            vector<int> cand{i, j, l};
            if (cur > bestSum || (cur == bestSum && cand < res)) {
                bestSum = cur;
                res = cand;
            }
        }
        return res;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxSumOfThreeSubarrays(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        if 3 * k > n:
            return []

        m = n - k + 1                              # 长度为 k 的窗口个数
        w = [0] * m
        w[0] = sum(nums[:k])
        for i in range(1, m):                      # 滑动窗口求窗口和
            w[i] = w[i - 1] - nums[i - 1] + nums[i + k - 1]

        left = [0] * m                             # [0, i] 中窗口和最大的最小下标
        best = 0
        for i in range(m):
            if w[i] > w[best]:                     # 严格大于 → 并列保留更早的
                best = i
            left[i] = best

        right = [0] * m                            # [i, m-1] 中窗口和最大的最小下标
        best = m - 1
        for i in range(m - 1, -1, -1):
            if w[i] >= w[best]:                    # 大于等于 → 并列保留更小的下标
                best = i
            right[i] = best

        best_sum, res = -1, []
        for j in range(k, m - k):                  # 枚举中间窗口的起点
            i, l = left[j - k], right[j + k]
            cur = w[i] + w[j] + w[l]
            cand = [i, j, l]
            if cur > best_sum or (cur == best_sum and cand < res):
                best_sum, res = cur, cand
        return res
```

## 8. 边界情况与易错点

1. **$3k = n$（刚好塞满）**：此时唯一可行解是 $i=0,\ j=k,\ l=2k$，循环必须能在 $j = m-k-1$ 上跑一次。上界写成 `j < m-k-1` 会少枚举一个 $j$（直接漏解），写成 `j <= m-k` 则会越界访问 `right[m]`。
2. **$k = 1$**：窗口数 $m = n$，$j$ 从 $1$ 到 $n-2$；`left` / `right` 退化为前缀最大值 / 后缀最大值，逻辑不变，但要保证 $m - k \ge k$ 才会进循环（由 $k \le \lfloor n/3\rfloor$ 保证）。
3. **所有窗口和全相等**（示例 2）：正确答案是 `[0,k,2k]`。这里最容易踩坑的是 `right` 用了严格 `>`，会得到 `[0,2,7]` 这种字典序更大的解。
4. **并列但不在同一 $j$ 上**（补充示例）：$j=2$ 与 $j=3$ 都能取到 53，必须比较整组下标，不能只记住「最后更新」的那个。
5. **无解兜底**：虽然本题约束保证 $3k \le n$，但模板里保留 `3*k > n` 的提前返回，可以无改动复用到「不一定有解」的变体。
6. **返回值类型**：C++ 返回 `vector<int>`（值语义），不要写成引用或返回内部数组指针；Python 返回普通的 `list`，长度恒为 3。
7. **下标语义**：返回的是起点，不是终点；若误用「窗口终点 $i+k$」，所有答案都会整体偏移 $k$。
