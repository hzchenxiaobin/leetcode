# LeetCode 最大网络秩 题解

## 1. 题目概述

- **标题 / 题号**：最大网络秩（#1615，medium）
- **链接**：https://leetcode.cn/problems/maximal-network-rank/
- **来源**：LeetCode 第 210 场周赛 Q2
- **难度**：中等
- **标签**：图、度数、容斥原理、枚举

**题意**：$n$ 座城市与若干双向道路 `roads` 构成基础设施网络，每条 `roads[i] = [ai, bi]` 连接城市 $a_i$ 与 $b_i$（无重边、无自环）。两座**不同**城市 $(u, v)$ 构成的**城市对**的**网络秩**定义为：与这两座城市**直接相连**的道路总数；若 $u$、$v$ 之间本身有道路，这条道路只计**一次**。返回所有不同城市对中网络秩的**最大值**。

**约束**：

- $2 \le n \le 100$
- $0 \le \mathrm{roads.length} \le \dfrac{n(n-1)}{2}$
- $0 \le a_i, b_i \le n-1$，$a_i \ne b_i$
- 每对城市之间最多一条道路

> 💡 典型的**图统计手速题**：把"与 $u$ 或 $v$ 相连的道路数"翻译成度数的**容斥**，再用 $n \le 100$ 的平方枚举收尾。比赛时的全部风险都集中在"直连边被数两次"这一处修正上。

## 2. 示例

输入：n = 4, roads = [[0,1],[0,3],[1,2],[1,3]]
输出：4
解释：城市 0 和 1 的网络秩是 4——与 0 或 1 相连的道路共 4 条，
     0 与 1 之间的道路只计算一次。
```

**示例 2**

输出：5
解释：城市 1 和 2 的网络秩是 5。
```

**示例 3**

```text
输入：n = 8, roads = [[0,1],[1,2],[2,3],[2,4],[5,6],[5,7]]
输出：5
解释：城市 2 和 5 的网络秩是 5——注意图不必连通。
```

```text
输入：n = 2, roads = []

```

## 3. 解题思路

### 3.1 暴力思路：对每个城市对重扫边表

按定义，对每个城市对 $(u, v)$ 把 `roads` 整个扫一遍，统计"至少一端是 $u$ 或 $v$"的道路条数（遇到 $u \leftrightarrow v$ 那条还要留神别数两次）。时间 $O\!\left(m\binom{n}{2}\right)$，$n = 100$、$m = 4950$ 时约 $2.4 \times 10^7$，规模上勉强能过，但每对城市都在重复扫描同一份边表——"哪些边挨着城市 $u$"对每座城市是**固定**的，根本没必要一对一对地重算。

### 3.2 核心观察：网络秩 = 度数和 − 直连修正

![核心观察：容斥公式 rank(u,v) = deg(u)+deg(v)−[u↔v 直连]](images/netrank_inclusion_exclusion_concept.svg)

设 $E(x)$ 为与城市 $x$ 关联的边集，则"与 $u$ 或 $v$ 直接相连的道路"就是 $E(u) \cup E(v)$。由**容斥原理**：

$$\operatorname{rank}(u,v) = |E(u) \cup E(v)| = \deg(u) + \deg(v) - |E(u) \cap E(v)|$$

而一条边要同时关联 $u$ 与 $v$，当且仅当它就是 $u \leftrightarrow v$ 那条道路；又因**每对城市最多一条道路**，$E(u) \cap E(v)$ 要么为空、要么恰好是这一条边。于是：

$$\operatorname{rank}(u,v) = \deg(u) + \deg(v) - \mathbf{1}[u \leftrightarrow v]$$

一次 $O(n+m)$ 预处理出**度数数组** `deg[]` 与**直连判定** `conn`，之后任意城市对 $O(1)$ 出值。

> ⚠️ 直连的那条边在 $\deg(u)$ 与 $\deg(v)$ 里各被计一次、合计两次，而题目要求只算一次——这就是 $-1$ 修正的唯一来源。忘掉它是本题最流行的 WA（示例 1 会把 4 算成 5）。

### 3.3 算法流程

![算法流程：O(n+m) 预处理 + O(n²) 双循环枚举](images/netrank_pair_enumeration_flow.svg)

```text
1. 预处理（O(n+m)）：
   扫一遍 roads：deg[u]++、deg[v]++；conn[u][v] = conn[v][u] = true
2. 枚举（O(n²)）：
   for u = 0 .. n−1:
     for v = u+1 .. n−1:
       rank = deg[u] + deg[v] − (conn[u][v] ? 1 : 0)
       ans = max(ans, rank)
3. 返回 ans
```

### 3.4 示例演算

![示例演算：n=8 双分量图，跨分量对 (2,5) 以 5 夺魁](images/netrank_example_walkthrough.svg)

以示例 3（`n = 8, roads = [[0,1],[1,2],[2,3],[2,4],[5,6],[5,7]]`）为例。度数：`deg = [1,2,3,1,1,2,1,1]`。摘录几对演算：

| 城市对 | deg 和 | 直连? | rank |
|--------|--------|-------|------|
| (0,1) | 1+2 | ✔ | 2 |
| (0,2) | 1+3 | ✘ | 4 |
| (1,2) | 2+3 | ✔ | 4 |
| (1,5) | 2+2 | ✘ | 4 |
| **(2,5)** | **3+2** | **✘** | **5** ← ans |
| (5,6) | 2+1 | ✔ | 2 |

全部 $\binom{8}{2} = 28$ 对枚举后取最大，返回 $5$ ✓。两个观察值得记下：**不直连的对反而可能更大**（$(0,2)$ 达到 4，因为免去了 $-1$ 修正）；**图根本不需要连通**——$(2,5)$ 之间连路径都没有，照样是合法城市对。

## 4. 算法细节

1. **无向图的对称登记**：每条道路要给两个端点各自 `deg++`，`conn` 也要双向标记，漏掉一半是最常见的实现失误。
2. **直连判定的三种实现**：
   - `bool` 矩阵 `conn[n][n]`：空间 $O(n^2)$（$n = 100$ 时约 10 KB），查询 $O(1)$，**本题首选**；
   - 哈希集合存编码 `u * n + v`（或规范化后的 `(min, max)`）：空间 $O(n+m)$，$n$ 大边稀疏时用；
   - 邻接表排序后二分：不依赖哈希，常数居中。
3. **枚举 `u < v`**：既避免 $(u,v)$、$(v,u)$ 重复计算（结果不变、白跑一倍），也天然排除 $u = v$——题目只承认"两座**不同**城市"。
4. **`ans` 初值取 0 合法**：任何城市对的 rank 恒非负（§5 引理 2），而 $n \ge 2$ 保证至少存在一个城市对。
5. **一个不需要的优化**：只考察最大度（及唯一时再配次大度）城市的配对，可把枚举压到 $O(n + m + k^2)$；但 $n \le 100$ 时双循环 4950 次早已绰绰有余——周赛里**先交稳的**。

## 5. 正确性证明

**引理 1（容斥公式）**：对任意两座不同城市 $u \ne v$，

$$\operatorname{rank}(u,v) = \deg(u) + \deg(v) - \mathbf{1}[u \leftrightarrow v]$$

**证明**：与 $u$ 或 $v$ 直接相连的道路即 $E(u) \cup E(v)$。由容斥原理，$|E(u) \cup E(v)| = |E(u)| + |E(v)| - |E(u) \cap E(v)|$。一条边属于 $E(u) \cap E(v)$ 当且仅当它的两端恰为 $u$ 与 $v$，即它就是道路 $(u,v)$；又每对城市之间最多一条道路，故 $|E(u) \cap E(v)| = \mathbf{1}[u \leftrightarrow v]$。∎

**引理 2（非负性）**：对一切 $u \ne v$，$\operatorname{rank}(u,v) \ge 0$。

**证明**：若 $u \leftrightarrow v$，则这条道路分别为 $u$、$v$ 各贡献一个度数，$\deg(u), \deg(v) \ge 1$，故 $\operatorname{rank}(u,v) \ge 1 + 1 - 1 = 0$；若不直连，$\operatorname{rank}(u,v) = \deg(u) + \deg(v) \ge 0$。∎

**定理**：算法返回整个基础设施网络的最大网络秩。

**证明**：约束 $n \ge 2$ 保证城市对存在。双循环恰好遍历每个无序对 $\{u, v\}$（$u < v$）一次，不重不漏；由引理 1，每个城市对都被赋予正确的 rank 值，故循环结束后 `ans` 即所有 rank 的最大值。再由引理 2，各 rank 非负，`ans` 的初值 $0$ 不会污染结果：若真实最大值为 $0$（如 `roads` 为空），初值恰好等于它；否则必被某个正 rank 覆盖。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 + m)$。预处理扫一遍边表 $O(n+m)$；枚举 $\binom{n}{2} < n^2/2$ 对、每对 $O(1)$。由 $m \le n(n-1)/2$，总量即 $O(n^2)$；$n = 100$ 时约 5000 次内层判断，毫秒级完成。
- **空间复杂度**：$O(n^2)$（`bool` 直连矩阵）。改用哈希集合可降至 $O(n+m)$，但 $n \le 100$ 无此必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximalNetworkRank(int n, vector<vector<int>>& roads) {
        vector<int> deg(n, 0);
        vector<vector<bool>> conn(n, vector<bool>(n, false));
        for (auto& r : roads) {
            int u = r[0], v = r[1];
            deg[u]++, deg[v]++;
            conn[u][v] = conn[v][u] = true;
        }
        int ans = 0;
        for (int u = 0; u < n; u++)
            for (int v = u + 1; v < n; v++)
                ans = max(ans, deg[u] + deg[v] - (conn[u][v] ? 1 : 0));
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximalNetworkRank(self, n: int, roads: List[List[int]]) -> int:
        deg = [0] * n
        adj = [set() for _ in range(n)]
        for u, v in roads:
            deg[u] += 1
            deg[v] += 1
            adj[u].add(v)
            adj[v].add(u)
        return max(
            deg[u] + deg[v] - (v in adj[u])
            for u in range(n)
            for v in range(u + 1, n)
        )
```

> 💡 Python 版用邻接 `set` 做直连判定；$n \ge 2$ 保证生成器非空，`max` 不会抛异常。

## 8. 边界情况与易错点

1. **忘减直连修正（最高频 WA）**：把 rank 算成 `deg[u] + deg[v]`，示例 1 会输出 5 而非 4。
2. **不直连时误减**：修正只在 `conn[u][v]` 为真时进行，"一律减 1"会把不直连的对系统性算小。
3. **roads 为空**：所有度数为 0，答案为 0——`ans` 初值 0 直接正确，无需特判。
4. **图不连通**：网络秩与连通性毫无关系（示例 3 的 $(2,5)$ 跨分量夺魁），不要画蛇添足做连通性检查。
5. **无向登记要双向**：`deg` 与 `conn` 都要两端处理，只登记一半会漏算。
6. **别把 $u = v$ 混进枚举**：题目只承认两座不同城市，内层从 `v = u + 1` 起步即可。
7. **溢出无虞**：$\deg \le n - 1 \le 99$，rank 上界 $2(n-1) - 1 < 200$，`int` 十分安全。
