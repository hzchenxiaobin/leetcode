# LeetCode 包含所有三种字符的子字符串数目 题解

## 1. 题目概述

- **标题 / 题号**：包含所有三种字符的子字符串数目（#1358，medium）
- **链接**：https://leetcode.cn/problems/number-of-substrings-containing-all-three-characters/
- **来源**：LeetCode 第 20 场双周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、滑动窗口

**题意**：字符串 `s` 只含 `a`、`b`、`c` 三种字符。统计**同时至少出现一次 `a`、`b`、`c`** 的子字符串数目（子串按位置区分，相同内容算多次）。

**约束**：

- $3 \le s.length \le 5 \times 10^4$
- `s` 只包含字符 `a`、`b`、`c`

## 2. 示例

**示例 1**

```text
输入：s = "abcabc"
输出：10
解释："abc"、"abca"、"abcab"、"abcabc"、"bca"、"bcab"、"bcabc"、
      "cab"、"cabc" 与末尾的 "abc"，共 10 个。
```

**示例 2**

```text
输入：s = "aaacb"
输出：3
解释："aaacb"、"aacb"、"acb"。
```

**示例 3**

```text
输入：s = "abc"
输出：1
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部子串 $O(n^2)$ 个，每个再花 $O(n)$ 检查三种字符是否齐全：$O(n^3)$，$n = 5\times10^4$ 时完全不可行；即便用前缀计数把检查降到 $O(1)$，$O(n^2) \approx 2.5\times10^9$ 个子串也仍过多。突破口在于**单调性**：子串越长越容易包含全部字符，于是「以某端点为界」的合法子串构成连续区间。

### 3.2 核心观察：固定右端点，合法左端点是前缀——贡献 = 最小 last + 1

![固定右端点j：最靠左可行起点由三者最小决定](images/bw20_q3_window_model.svg)

固定右端点 $j$，设 `last[c]` = 字符 $c$ 在 $[0, j]$ 内**最后出现的下标**（未出现为 $-1$）。那么子串 $[i, j]$ 包含全部三种字符，当且仅当 $i \le \min(last[a], last[b], last[c])$——再往右的起点会把「最晚报到的那个字符」丢掉。

于是以 $j$ 结尾的合法子串数恰为

$$\big(\min(last[a], last[b], last[c]) + 1\big)$$

（起点取 $0 \sim \min$ 的每一个）。$j$ 右移时 `last` 只会被刷新得更大、$\min$ 单调不减，因此**左端点无需回退**——这是滑动窗口/双指针的本质，也可以像下面代码那样干脆只维护三个 `last` 标量，连双指针都省了。

### 3.3 算法流程

```text
1. last[a] = last[b] = last[c] = −1, ans = 0
2. j 从 0 到 n−1：
       last[s[j]] = j                       # 刷新该字符最后出现位置
       若三者均 ≥ 0：ans += min(last[a], last[b], last[c]) + 1
3. 返回 ans
```

等价的双指针写法：`cnt` 数组统计窗口内各字符个数，`i` 随 `j` 收缩到「窗口刚好仍合法」，答案累加 `i + 1`。两版可以互为对拍。

### 3.4 示例演算

![abcabc走查：last表逐位更新累计10](images/bw20_q3_walkthrough.svg)

对 `"abcabc"`：$j=0,1$ 时 `last` 未集齐，贡献 0；$j=2$ 时 `last=(0,1,2)`，$\min=0$，贡献 1（子串 `abc`）；$j=3$ 时 $\min=1$，贡献 2；$j=4$ 时 $\min=2$，贡献 3；$j=5$ 时 $\min=3$，贡献 4。累计 $1+2+3+4=10$ ✓。字符集没有凑齐前贡献恒为 0，起点不会「抢跑」。

## 4. 算法细节

1. **只需三个标量**：字符集固定为 `a/b/c`，`last` 用长度 3 的数组（`s[j]-'a'` 索引）即可；`min({...})` 三元一次比较。
2. **未出现用 $-1$**：三种字符未集齐时若不加判断直接算 `min+1`，$-1$ 恰好给出 0 贡献——两种写法等价，显式判断更可读。
3. **答案规模**：最坏 $\sum (\min + 1) \le \frac{n(n+1)}{2} \approx 1.25\times10^9$，贴着 `int` 上界（$2.1\times10^9$）；C++ 用 `long long` 累加最稳，Python 整数无虞。
4. **为什么不先判「合法再收缩」**：另一种常见写法是 `cnt` 计数 + 左指针收缩；两者复杂度相同，`last` 版少一个指针、少一段收缩逻辑，是「逐右端点计数」型问题的最短实现。
5. **推广到 $k$ 种字符**：把 `last` 换成哈希表、$\min$ 换成「最早需要的字符」，或用「窗口内不同字符数 == k」收缩，即可处理「包含 $k$ 种字符的子串」一般型（见延伸思考）。

## 5. 正确性证明

**引理 1（合法左端点的刻画）**：固定右端点 $j$，子串 $s[i..j]$ 包含 `a`、`b`、`c` 各至少一次，当且仅当 $i \le L_j$，其中 $L_j = \min(\,last_j[a], last_j[b], last_j[c]\,)$，$last_j[c]$ 为 $c$ 在 $[0, j]$ 内最后出现的下标（不存在为 $-1$）。

**证明**：（⇐）若 $i \le L_j$，则三个 `last` 下标都 $\ge L_j \ge i$ 且 $\le j$，即三种字符都在 $[i, j]$ 内出现过。（⇒）反之若 $i > L_j$，不妨设 $L_j = last_j[c_0]$（三个最后出现位置中最小者），则 $c_0$ 在 $[i, j]$ 内没有出现（$c_0$ 的最后出现位置 $L_j < i$），子串不合法。∎

**引理 2（单调性）**：$L_j$ 关于 $j$ 单调不减，且 $L_j = \min(L_{j-1}, \dots)$ 的更新只增加不减少。

**证明**：$j$ 增大时每个 `last_j[c]` 要么不变要么增大（最后出现位置只会被刷新得更靠右），三者取 $\min$ 也随之不减。∎

**定理**：算法返回值等于合法子串总数。

**证明**：按右端点 $j$ 分组计数：每个合法子串有唯一右端点 $j$，恰在处理 $j$ 时被统计一次。处理 $j$ 时，若三字符未集齐则该组为空集（由引理 1，$L_j = -1 < 0$，起点 $0..L_j$ 为空），贡献 0 正确；若集齐，由引理 1 该组合法子串个数 $= L_j + 1$，与累加值一致。故 $\sum_j (L_j + 1) + 0 = \sum_j |\{i : [i,j]\text{ 合法}\}| = |\{(i,j) : [i,j]\text{ 合法}\}| = $ 合法子串总数（位置二元组与子串一一对应）。∎

## 6. 复杂度分析

- **时间**：$O(n)$——单趟扫描，每步 $O(1)$ 更新与 $O(1)$ 三元取最小。
- **空间**：$O(1)$——三个 `last` 标量与一个累加器；双指针版也只需 $O(1)$（`cnt` 数组大小 3）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfSubstrings(string s) {
        int last[3] = {-1, -1, -1};      // 三种字符最后出现的下标
        int ans = 0;
        for (int j = 0; j < (int)s.size(); ++j) {
            last[s[j] - 'a'] = j;
            if (last[0] >= 0 && last[1] >= 0 && last[2] >= 0)
                ans += min({last[0], last[1], last[2]}) + 1;   // 起点 0..min(last) 都合法
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfSubstrings(self, s: str) -> int:
        last = {"a": -1, "b": -1, "c": -1}
        ans = 0
        for j, ch in enumerate(s):
            last[ch] = j
            if min(last.values()) >= 0:          # 三种字符都已出现
                ans += min(last.values()) + 1    # 起点 0..min(last) 都合法
        return ans
```

> 💡 两份代码均通过官方示例（`10`、`3`、`1`），并与「三重循环逐子串检查」的 $O(n^3)$ 暴力对拍 4003 组随机数据（C++，$n \le 15$）+ 3000 组（Python）全部一致；另与双指针收缩版互验等价。

## 8. 边界情况与易错点

1. **前缀字符不齐时贡献必须是 0**：判断「三者都 $\ge 0$」不可省（或依赖 $-1$ 的加法兜底，但要明白原理），否则前几个位置会数出负贡献。
2. **答案是子串总数而非字符数**：同一内容 `"abc"` 出现两次计两次，按 $(i, j)$ 位置对计数天然正确，别去做「去重」。
3. **累加器溢出**：$n = 5\times10^4$ 时答案可逼近 $1.25\times10^9$，`int` 勉强够但贴线，C++ 建议 `long long`（本题返回 `int`，累加用 `long long` 后转型）。
4. **字典序别用 `min(last)` 顺序写错**：`min({l0, l1, l2})` 是 C++ 初始化列表版，需 `#include <algorithm>`；写成 `min(min(l0, l1), l2)` 无需额外头文件，效果相同。
5. **字符集假设**：`s[j]-'a'` 依赖题面「只含 a/b/c」；若输入可能混入其他字符，先断言或改用哈希表。
6. **双指针版本的收缩条件**：`cnt` 全正才收缩 vs 收缩到刚好不合法，两种边界恰好差 1，是这类题最常见的 off-by-one 来源；`last` 版没有左指针，从根上回避。
