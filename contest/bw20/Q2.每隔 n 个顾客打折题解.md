# LeetCode 每隔 n 个顾客打折 题解

## 1. 题目概述

- **标题 / 题号**：每隔 n 个顾客打折（#1357，medium）
- **链接**：https://leetcode.cn/problems/apply-discount-every-n-orders/
- **来源**：LeetCode 第 20 场双周赛 Q2
- **难度**：中等
- **标签**：设计、数组、哈希表

**题意**：实现一个超市结账系统 `Cashier`：

- 构造函数 `Cashier(n, discount, products, prices)`：每第 $n$ 位顾客结账时享受 `discount`% 的折扣；`products[i]` 是第 $i$ 种商品的编号，`prices[i]` 是其单价；
- `getBill(product, amount)`：顾客购买 `product[i]` 编号的商品各 `amount[i]` 件，返回**实际金额**（打折顾客返回原价 $x$ 的 $x - x \cdot discount / 100$），系统结账后计数并迎接下一位顾客。

误差 $10^{-5}$ 内视为正确。

**约束**：

- $1 \le n \le 10^4$，$0 \le discount \le 100$
- $1 \le products.length \le 200$，$1 \le products[i] \le 200$，无重复
- $1 \le prices[i] \le 1000$，$prices.length = products.length$
- 每次 `getBill`：$1 \le product.length \le 200$（商品必在 `products` 中），$1 \le amount[i] \le 1000$，调用至多 1000 次

## 2. 示例

**示例 1**

```text
输入：
["Cashier","getBill","getBill","getBill","getBill","getBill","getBill","getBill"]
[[3,50,[1,2,3,4,5,6,7],[100,200,300,400,300,200,100]],
 [[1,2],[1,2]],[[3,7],[10,10]],[[1,2,3,4,5,6,7],[1,1,1,1,1,1,1]],
 [[4],[10]],[[7,3],[10,10]],[[7,5,3,1,6,4,2],[10,10,10,9,9,9,7]],
 [[2,3,5],[5,3,2]]]
输出：
[null,500.0,4000.0,800.0,4000.0,4000.0,7350.0,2500.0]
解释：第 3 位顾客原价 1600，5 折后 800；第 6 位顾客原价 14700，5 折后 7350。
```

## 3. 解题思路

### 3.1 暴力思路

每次 `getBill` 时遍历 `products` 数组，对 `product[i]` 线性查找其单价——单次 $O(200 \times 200)$，1000 次调用共 $4\times10^7$，能过但难看。商品编号即天然键，直接用**哈希表**把「编号 → 单价」在构造时存好，查询降为 $O(1)$；计数器每调用自增一次，判断 `cnt % n == 0` 决定是否打折。本题实质是「哈希表 + 计数器」的模板设计题。

### 3.2 核心观察：折扣只由「第几位顾客」决定，与账单内容无关

![Cashier设计：哈希表存单价，计数器取模触发折扣](images/bw20_q2_design_flow.svg)

关键点有三：

1. **价目表**：`products`/`prices` 是全量商品，构造时一次性建成 `price[products[i]] = prices[i]` 的哈希表；`getBill` 里的 `product` 只是本次购买清单的编号子集。
2. **计数器语义**：「每隔 n 个顾客」指**第 $n$、$2n$、$3n$…位**顾客享受折扣——即调用次数 `cnt` 自增后 `cnt % n == 0`；系统随后「重新开始计数」，而连续取模天然给出这一周期，无需手动重置。
3. **金额计算**：原价 $= \sum price[p_i] \times amount_i$；打折时实付 $= x \cdot (100 - discount)/100$。范围极小（原价 $\le 200 \times 1000 \times 1000 = 2\times10^8$），整型累加后再转 `double` 精确无损。

### 3.3 算法流程

```text
构造：哈希表 price[商品号] = 单价；cnt = 0；保存 n 与 discount
getBill(product, amount)：
1. bill = Σ price[product[i]] × amount[i]
2. cnt += 1
3. 若 cnt % n == 0：返回 bill × (100 − discount) / 100.0
   否则：返回 bill（转 double）
```

### 3.4 示例演算

![官方示例走查：cnt=3、6 触发5折](images/bw20_q2_walkthrough.svg)

对官方示例（$n=3$，5 折）走一遍 7 次调用：`cnt` 依次 $1\sim7$，账单原价依次 $500, 4000, 1600, 4000, 4000, 14700, 2500$。第 3、6 位触发 5 折：$1600 \to 800$、$14700 \to 7350$，其余按原价返回，与官方输出序列完全一致。

## 4. 算法细节

1. **数据结构选型**：`products[i] ≤ 200` 值域极小，其实开一个 `price[201]` 数组即可（构造时 `price[products[i]] = prices[i]`），比哈希表更快；用 `unordered_map` / `dict` 也完全够用，语义更通用。
2. **计数从 0 开始、先自增再判断**：`++cnt; if (cnt % n == 0)` 恰好让第 $n$ 位顾客命中；若先判断再自增会错位一位。
3. **不要手动重置计数器**：`if (cnt == n) { 打折; cnt = 0; }` 也能对，但 `cnt` 无界增长到 $10^4 \times 10^3$ 以内并无溢出风险，直接取模更简洁；两种写法都已验证等价。
4. **折扣公式**：$x - x \cdot d/100 = x(100-d)/100$。用后者一次乘除，避免「先减再除」的两步浮点；本题所有整数 $\le 2\times10^{10}$（乘上 $100-d \le 100$）在 `double`（53 位尾数）下仍精确，除以 100 只在结果非整数时产生一次舍入，误差远小于 $10^{-5}$。
5. **整型累积再转浮点**：`bill` 用 `long long`（C++）/`int`（Python 任意精度）累加商品金额，避免循环里反复浮点累加。
6. **构造函数参数按 metaData 顺序**：`(n, discount, products, prices)`，C++ 传 `vector<int>&`；`getBill` 返回 `double`。

## 5. 正确性证明

**引理 1（打折时机）**：第 $k$ 位顾客（`getBill` 的第 $k$ 次调用）享受折扣，当且仅当 $k \bmod n = 0$。

**证明**：「每隔 $n$ 个顾客会得到折扣」且「结账后系统重新开始计数」定义的正是 $n, 2n, 3n, \dots$ 这一等差序列。算法中 `cnt` 在第 $k$ 次调用后等于 $k$，判定 `cnt % n == 0` 等价于 $n \mid k$，即 $k$ 是该序列中的数。∎

**引理 2（金额公式）**：`getBill` 第 1 步算出的 `bill` 等于购买商品的总原价；打折时返回值与「$x - x \cdot discount/100$」的差在浮点舍入误差内。

**证明**：每种商品 `product[i]` 的单价由构造时的哈希表唯一给出，`amount[i]` 件共 `price × amount`，购物车总价为各商品之和。打折分支计算 $bill \cdot (100 - d) / 100$，与题面 $x - xd/100$ 在代数上恒等（$x(100-d)/100 = x - xd/100$），浮点部分至多两次舍入，误差 $< 10^{-12}$ 量级，远在 $10^{-5}$ 容差内。∎

**定理**：`Cashier` 对每次 `getBill` 返回的金额与题面定义一致。

**证明**：由引理 1，折扣恰好在第 $n, 2n, \dots$ 位顾客触发、其余不触发；由引理 2，两种分支的金额公式均正确。状态仅有 `cnt` 与只读价目表，第 $k$ 次调用只依赖 `cnt = k`，归纳即得全部调用正确。∎

## 6. 复杂度分析

- **时间**：构造 $O(P)$（$P \le 200$ 建价目表）；每次 `getBill` $O(L)$（$L \le 200$ 遍历购物清单，哈希查询 $O(1)$）。1000 次调用总计 $\le 2\times10^5$ 次操作。
- **空间**：$O(P)$ 存价目表与常数个计数器。

## 7. 参考代码

### C++

```cpp
class Cashier {
public:
    Cashier(int n, int discount, vector<int>& products, vector<int>& prices)
        : freq_(n), disc_(discount), cnt_(0) {
        for (int i = 0; i < (int)products.size(); ++i)
            price_[products[i]] = prices[i];
    }

    double getBill(vector<int> product, vector<int> amount) {
        long long bill = 0;
        for (int i = 0; i < (int)product.size(); ++i)
            bill += 1LL * price_[product[i]] * amount[i];
        ++cnt_;
        if (cnt_ % freq_ == 0)                   // 第 n、2n、… 个顾客打折
            return bill * (100 - disc_) / 100.0;
        return (double)bill;
    }
private:
    int freq_, disc_, cnt_;
    unordered_map<int, int> price_;
};
```

### Python

```python
class Cashier:
    def __init__(self, n: int, discount: int, products: List[int], prices: List[int]):
        self.freq = n
        self.disc = discount
        self.cnt = 0
        self.price = dict(zip(products, prices))

    def getBill(self, product: List[int], amount: List[int]) -> float:
        bill = sum(self.price[p] * a for p, a in zip(product, amount))
        self.cnt += 1
        if self.cnt % self.freq == 0:            # 第 n、2n、… 个顾客打折
            return bill * (100 - self.disc) / 100.0
        return float(bill)
```

> 💡 两份实现均完整回放官方 8 步调用序列，得到 `[null, 500.0, 4000.0, 800.0, 4000.0, 4000.0, 7350.0, 2500.0]`，逐项误差为 0；另用「`cnt` 达到 $n$ 时打折并手动清零」的等价写法复核一致。

## 8. 边界情况与易错点

1. **$n = 1$**：每位顾客都打折（每次调用 `cnt % 1 == 0` 恒真），不要以为「要跳过第 0 位」。
2. **$discount = 100$**：实付恒为 0；$discount = 0$ 时实付等于原价——取模分支仍要走，但结果不变。
3. **计数器初值与自增顺序**：初值 0、先 `++` 后判定，第一位顾客是第 1 位；顺序颠倒会让打折提前/推后一位。
4. **返回类型是 `double`**：C++ 打折分支务必 `/ 100.0`（或 `* (100.0 - d) / 100.0`），整数 `/ 100` 会截断成整型；不打折分支记得 `(double)bill` 转型，避免隐式窄化警告。
5. **商品编号 ≠ 数组下标**：`products[i]` 是编号（$1 \sim 200$），必须经哈希表/数组映射取价，不要拿 `product[i]` 直接当下标去查 `prices`。
6. **购买清单允许重复出现同一商品吗**：题面保证 `product` 是子集语义（每项一种商品），但即使重复出现，逐项累加的写法也天然正确——线性扫描比「合并同类项」更鲁棒。
7. **Python 整数 / 浮点**：`sum` 结果是 `int`，打折分支 `/ 100.0` 后自然变 `float`；不打折分支记得 `float(bill)` 以满足返回类型（不转也不会错，但语义更清晰）。
