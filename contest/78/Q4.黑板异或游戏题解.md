# LeetCode 黑板异或游戏 题解

## 1. 题目概述

- **标题 / 题号**：黑板异或游戏（#810，hard）
- **链接**：https://leetcode.cn/problems/chalkboard-xor-game/
- **来源**：LeetCode 第 78 场周赛 Q4
- **难度**：困难
- **标签**：位运算、脑筋急转弯、数组、数学、博弈论、零和博弈、无偏博弈

**题意**：黑板上写着 $n$ 个非负整数 `nums`，Alice 先手，两人轮流**恰好擦掉一个数**，规则共三条：

1. 若擦掉某个数后，**剩余的**所有数异或和为 $0$，则**擦除者立即失败**；
2. 若轮到某个玩家时，黑板上**当前的**异或和为 $0$，则该玩家**立即获胜**；
3. 只剩一个数时异或和就是它本身；**没有数时异或和约定为 $0$**。

双方都按最优策略行动，问 Alice 是否必胜。

**约束**：

- $1 \le \lvert \text{nums} \rvert \le 1000$
- $0 \le \text{nums}[i] < 2^{16}$

**关键点**：规则 1 与规则 2 看起来像同一件事，其实方向相反——规则 1 作用在「擦除**之后**」，规则 2 作用在「轮到你**之时**」。整道题的答案只取决于「长度奇偶」与「异或和是否为 $0$」这两个量。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2]
输出：false
解释：Alice 只有两种选择。
      擦掉 1 → 剩 [1,2]，异或 1^2 = 3 ≠ 0，轮到 Bob，Bob 随便擦一个都能把
                Alice 逼到「必须擦最后一个数」的境地，Alice 必输；
      擦掉 2 → 剩 [1,1]，异或 1^1 = 0，按规则 2，轮到 Bob 时 Bob 直接获胜。
      两条分支都输，故返回 false。
```

**示例 2**

```text
输入：nums = [0,1]
输出：true
解释：整体异或为 1 ≠ 0，但长度为 2（偶数），是标准的必胜态：
      Alice 擦掉 0，剩 [1]（异或 1 ≠ 0，奇数长度），Bob 只能擦掉 1，
      擦完黑板为空、异或为 0，Bob 输掉；Alice 获胜。
```

**示例 3**

```text
输入：nums = [1,2,3]
输出：true
解释：1 ^ 2 ^ 3 = 0，Alice 开局就满足规则 2，一个数都不用擦，直接获胜。
```

## 3. 解题思路

### 3.1 暴力思路

把黑板上的数看作一个**多重集合**，直接做博弈搜索：状态是当前剩下的子集，每个状态有 $\lvert S \rvert$ 个后继（擦掉任意一个数）。状态数 $O(2^n)$、转移 $O(n)$，总时间 $O(n \cdot 2^n)$，空间 $O(2^n)$。

$n$ 最大 $1000$，$2^n$ 天文数字，连 $n = 30$ 都跑不动。暴力只能用来在小数据上**对拍**（$n \le 8$ 时可用它检验猜想），真正提交必须找闭式判据。而这类「擦数博弈」的闭式判据通常来自**奇偶性 + 不变量**，所以我们先找不变量。

### 3.2 核心观察：局面只有三种类型

![局面分类：长度奇偶 × 异或和是否为 0](images/wc78_q4_position_types.svg)

**不变量一（奇偶翻转）**：每走一步，黑板上的元素个数减少 $1$，长度的奇偶性必然翻转。

**不变量二（终止条件）**：一旦某个局面异或和为 $0$，游戏立刻结束，且**赢家是「轮到的那个人」**。也就是「异或和 $= 0$」是终局，谁遇到谁赢。

把「轮到者的处境」按两个量分类，只有三种非平凡情况：

| 局面 | 轮到者的处境 | 理由 |
|------|--------------|------|
| $x = 0$ | **立即获胜** | 规则 2 直接判定，与长度无关 |
| $n$ 偶且 $x \ne 0$ | **必胜** | 总能找到一手，把「奇数长度 + 非零」交给对手 |
| $n$ 奇且 $x \ne 0$ | **必败** | 任何一手要么当场输，要么给对手送必胜态 |

于是结论极其简洁：

$$\text{Alice 必胜} \iff x = 0 \ \text{或}\ n \text{ 为偶数}$$

为什么「$n$ 偶且 $x \ne 0$」一定有安全的一手？**反证**：若所有下标 $i$ 都满足 $x \oplus \text{nums}[i] = 0$，则每个 $\text{nums}[i]$ 都等于 $x$，于是 $x$ 自身等于 $n$ 个 $x$ 的异或；$n$ 为偶数时这 $n$ 个 $x$ 两两抵消得 $0$，与 $x \ne 0$ 矛盾。所以**至少存在一个 $\text{nums}[i] \ne x$**，擦掉它就是安全的。

### 3.3 算法流程

![算法流程：一次遍历求异或 + 两条判定](images/wc78_q4_algorithm_flow.svg)

1. 一次遍历求出整体异或 $x = \text{nums}[0] \oplus \text{nums}[1] \oplus \cdots \oplus \text{nums}[n-1]$（累加器初值 $0$，恰好与「空数组异或为 $0$」的约定一致）。
2. 若 $x = 0$，Alice 开局即胜，返回 `true`。
3. 否则若 $n$ 为偶数，Alice 处于必胜态，返回 `true`。
4. 否则（$n$ 为奇数且 $x \ne 0$）Alice 处于必败态，返回 `false`。

整个算法**没有任何循环嵌套、没有数据结构**，就是一次异或累加加一个布尔表达式。

### 3.4 示例演算

![示例演算：nums = [1,1,2] 的完整博弈树](images/wc78_q4_walkthrough.svg)

对 `nums = [1,1,2]` 走一遍完整博弈树：根局面 $x = 1 \oplus 1 \oplus 2 = 2 \ne 0$、$n = 3$ 为奇数，属于必败态。

- Alice 擦 $1$：剩 $[1,2]$，$x = 3 \ne 0$、长度 $2$ 偶数 → Bob 必胜。Bob 无论擦哪个，剩下的都是「单个数 $\ne 0$」，轮到 Alice 只能擦掉它，黑板变空、异或为 $0$，Alice 输。
- Alice 擦 $2$：剩 $[1,1]$，$x = 0$，轮到 Bob 时按规则 2 **Bob 立即获胜**，Alice 同样输。

再看另外两个官方示例的判定：

| 输入 | $x$ | 长度 | 结论 |
|------|-----|------|------|
| $[1,1,2]$ | $2$ | $3$（奇） | `false`（奇数且 $x \ne 0$） |
| $[0,1]$ | $1$ | $2$（偶） | `true`（偶数即必胜） |
| $[1,2,3]$ | $0$ | $3$（奇） | `true`（$x = 0$ 立即胜） |

三个示例分别覆盖了「必败态」「偶数必胜」「$x = 0$ 立即胜」三条分支，与判据完全吻合。

## 4. 算法细节

1. **异或累加器初值取 $0$**：既让代码从第一个元素开始就正确，又天然吻合「空数组异或为 $0$」的题面约定；后面归纳证明里会反复用到这条约定。
2. **判定式可以写成一条**：`return x == 0 || n % 2 == 0`。`||` 的短路求值只是省一次比较，不影响正确性——两个条件互相独立，都只是「Alice 必胜」的充分条件。
3. **不会溢出**：$\text{nums}[i] < 2^{16}$，任意多个数的异或结果仍落在 $[0, 2^{16})$，`int` 完全够用；即使把值域放大到 $64$ 位，也只需把累加器换成 `long long`，结论一字不改。异或运算是逐位独立的，不存在进位。
4. **不要排序、去重或建表**：重复元素对异或和的贡献是「偶数次抵消」，长度也不需要去重，一遍 $O(n)$ 扫描即可，任何额外预处理都是浪费。
5. **顺手能给出必胜走法**：当 $n$ 为偶数且 $x \ne 0$ 时，任取一个满足 $\text{nums}[i] \ne x$ 的下标擦掉即可（因为 $x \oplus \text{nums}[i] = 0 \iff \text{nums}[i] = x$）。由 3.2 的反证知这样的 $i$ 必然存在，所以「存在必胜手」是可构造的，而不只是存在性命题。
6. **长度的作用只有奇偶**：$n = 1000$ 与 $n = 2$ 在判定上等价，$n = 999$ 与 $n = 1$ 等价。写证明时要对「奇数长度」整体归纳，而不是对具体数值讨论。
7. **注释里写清三条规则的分工**：擦除后为 $0$ 者输、轮到时为 $0$ 者赢、空数组异或为 $0$。三条规则缺一条，答案都会变——这正是本题容易想歪的地方。

## 5. 正确性证明

先约定记号：局面记为 $(S, x)$，其中 $S$ 是黑板上剩余数的多重集合、$x = \bigoplus_{v \in S} v$，$n = \lvert S \rvert$；「当前玩家」指轮到行动的人。

**引理 1（终局判定）**：若局面的 $x = 0$，则当前玩家立即获胜。

**证明**：这正是题面规则 2 的直接陈述：轮到某个玩家时若黑板异或和为 $0$，该玩家获胜。特别地，空集合的异或和为 $0$，所以「留给对手空黑板」等价于把胜利送给对手。∎

**引理 2（偶长度非零局面必有安全手）**：若 $n$ 为偶数且 $x \ne 0$，则存在下标 $i$ 使 $x \oplus \text{nums}[i] \ne 0$。

**证明**：反证法。假设对一切 $i$ 都有 $x \oplus \text{nums}[i] = 0$，则 $\text{nums}[i] = x$ 对一切 $i$ 成立，于是
$$x = \bigoplus_{i=1}^{n} \text{nums}[i] = \underbrace{x \oplus x \oplus \cdots \oplus x}_{n \text{ 个}} = 0,$$
最后一步用到了 $n$ 为偶数（成对抵消）。这与 $x \ne 0$ 矛盾，故存在这样的下标。∎

**引理 3（奇长度非零局面必败）**：若 $n$ 为奇数且 $x \ne 0$，则当前玩家必败。

**证明**：对奇数 $n$ 做归纳。

- **基础** $n = 1$：设唯一的数是 $a$，则 $x = a \ne 0$。当前玩家只有一手——擦掉 $a$，此后黑板为空，异或和为 $0$，按规则 1 擦除者输。故必败。
- **归纳**：设结论对所有奇数 $n' \le n - 2$ 成立，其中 $n \ge 3$ 为奇数。当前玩家任选一手擦掉 $\text{nums}[i]$，新局面的异或为 $x' = x \oplus \text{nums}[i]$，长度为 $n - 1$（偶数）。
  - 若 $x' = 0$：按规则 1，擦除者立即输。
  - 若 $x' \ne 0$：此时是「偶数长度 $n-1$ + 非零异或」，由引理 2，轮到行动的对手存在一手使局面变为「长度 $n - 2$（奇数）、异或仍非 $0$」；由归纳假设，该局面对于届时轮到的玩家（即当前玩家）必败，也就是说对手有必胜策略。

  两种情况下当前玩家都必败，归纳完成。∎

**引理 4（偶长度非零局面必胜）**：若 $n$ 为偶数且 $x \ne 0$，则当前玩家必胜。

**证明**：由引理 2 取下标 $i$ 使 $x' = x \oplus \text{nums}[i] \ne 0$，当前玩家擦掉 $\text{nums}[i]$，把「长度 $n - 1$（奇数）+ 异或非零」的局面交给对手；由引理 3，对手在该局面必败。∎

**定理**：Alice 必胜当且仅当 $x = 0$ 或 $n$ 为偶数。

**证明**：

- **充分性**：若 $x = 0$，由引理 1，Alice 开局即胜；若 $x \ne 0$ 且 $n$ 为偶数，由引理 4，Alice 处于必胜态。
- **必要性**：若 $x \ne 0$ 且 $n$ 为奇数，由引理 3，Alice 处于必败态，故不能保证获胜。两种情形互斥且穷尽了所有输入（$x = 0$ 与 $x \ne 0$；$n$ 奇与 $n$ 偶），所以判据是精确的。∎

## 6. 复杂度分析

- **时间**：$O(n)$。只需一次遍历对 $n$ 个元素做异或，每个元素 $O(1)$；判定与返回都是 $O(1)$。
- **空间**：$O(1)$。只用一个整型累加器保存异或和，不随 $n$ 增长（输入数组本身不计）。
- **对比**：暴力博弈搜索为 $O(n \cdot 2^n)$ 时间、$O(2^n)$ 空间，在 $n = 1000$ 时完全不可行；本题的复杂度已是最优——至少要读一遍输入，$O(n)$ 无法再降。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool xorGame(vector<int>& nums) {
        int x = 0;
        for (int v : nums) {
            x ^= v;              // 一次遍历求整体异或，初值 0 与「空数组异或为 0」一致
        }
        // 规则二：开局异或为 0，Alice 立即获胜；
        // 否则偶长度是必胜态，奇长度（且异或非 0）是必败态。
        return x == 0 || nums.size() % 2 == 0;
    }
};
```

### Python

```python
class Solution:
    def xorGame(self, nums: list[int]) -> bool:
        x = 0
        for v in nums:
            x ^= v          # 一次遍历求整体异或
        # 异或为 0 → 轮到 Alice 时直接获胜；否则长度偶数即必胜
        return x == 0 or len(nums) % 2 == 0
```

## 8. 边界情况与易错点

1. **单元素且为 $0$**：`nums = [0]` → 整体异或为 $0$ → 返回 `true`。不要不假思索地认为「只有一个数，擦掉就空了，所以必输」——规则 2 让 Alice 根本不需要动手。
2. **单元素且非 $0$**：`nums = [5]` → $x = 5 \ne 0$ 且长度为奇数 → 返回 `false`。这是「奇数 + 非零 = 必败」最直接的实例：擦掉 $5$ 后黑板为空、异或为 $0$，擦的人（Alice）输。
3. **全零数组**：`[0,0,0]` 这类输入整体异或为 $0$，返回 `true`，同样走规则 2 的快速通道，与长度奇偶无关。
4. **两个条件不能合并**：`[0,1]` 长度偶数但异或非零 → `true`；`[1,2,3]` 长度奇数但异或为零 → `true`；`[1,1,2]` 两者都不满足 → `false`。只写「偶数」或只写「异或为零」都会错。
5. **Python 别把布尔值当整数用错**：`len(nums) % 2` 在偶数时是 `0`（假），若要写 `or` 形式必须是 `len(nums) % 2 == 0`；写成 `return x == 0 or len(nums) % 2` 会让结果完全反转。
6. **不要误解规则 1**：是「擦除后剩余异或为 $0$ 则**擦的人输**」，不是「赢」。把这个方向搞反，整道题的结论会从 `x == 0 || n % 2 == 0` 变成它的反面。
7. **不要漏掉空数组约定**：题面明确「没有数时异或为 $0$」。证明中 $n = 1$ 的基础情形、以及「对手把空黑板留给你 = 你赢」都依赖这条约定，读题时容易跳过。
