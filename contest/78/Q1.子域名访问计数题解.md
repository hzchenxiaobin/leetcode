# LeetCode 子域名访问计数 题解

## 1. 题目概述

- **标题 / 题号**：子域名访问计数（#811，medium）
- **链接**：https://leetcode.cn/problems/subdomain-visit-count/
- **来源**：LeetCode 第 78 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、字符串、计数

**题意**：域名由点分片段构成，`"discuss.leetcode.com"` 的父域名依次是 `"leetcode.com"` 和 `"com"`。访问一个域名时，它的所有父域名也被**隐式访问**。给定若干**计数配对域名** `"rep d1.d2.d3"`（`rep` 是访问次数，后半是完整域名），把每条记录的次数**向下分发**给它的完整域名与全部父域名，最后按 `"总次数 域名"` 的格式输出每个子域名，顺序任意。

**约束**：

- $1 \le \text{cpdomains.length} \le 100$
- $1 \le \lvert\text{cpdomains}[i]\rvert \le 100$
- 每条记录形如 `"rep d1.d2.d3"` 或 `"rep d1.d2"`
- `rep` 在 $[1, 10^4]$ 内，片段只含小写字母

## 2. 示例

**示例 1**

```text
输入：cpdomains = ["9001 discuss.leetcode.com"]
输出：["9001 leetcode.com","9001 discuss.leetcode.com","9001 com"]
解释：只有一条记录。discuss.leetcode.com 被访问 9001 次，
      leetcode.com 与 com 也各被隐式访问 9001 次。
```

**示例 2**

```text
输入：cpdomains = ["900 google.mail.com","50 yahoo.com","1 intel.mail.com","5 wiki.org"]
输出：["901 mail.com","50 yahoo.com","900 google.mail.com","5 wiki.org","5 org","1 intel.mail.com","951 com"]
解释：google.mail.com=900、yahoo.com=50、intel.mail.com=1、wiki.org=5 为各记录自身；
      mail.com = 900+1 = 901，com = 900+50+1 = 951，org = 5。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的写法是：先把所有记录解析成 `(rep, domain)` 列表，再枚举每个域名与它的每个父域名，对每个候选子域名**回扫整个列表**累加它自身与它所有子域名的次数。

设记录数为 $n$、域名长度为 $L$，则候选子域名有 $\Theta(nL)$ 个，每个候选回扫整个列表做前缀/后缀判断要 $O(nL)$，总计 $O(n^2L^2)$ 量级。$n=100$ 时虽然也能过，但这完全是白做的重复劳动：同一条记录会被扫描很多遍，且还要额外去重。

关键问题是「一次遍历就同时完成**分发**和**累加**」——这只需要一张哈希表。

### 3.2 核心观察：后缀恰好是「每个点之后的那一段」

![点分域名在每处切片后得到全部父域名](images/wc78_q1_suffix_split.svg)

对域名 $d$ 定义 $k$ 为其中 `.` 的个数。层数等于片段数，而父域名就是「砍掉最左边一片」，所以：

- $d$ 自身是 $d[0:]$；
- 第 1 个父域名是第 1 个点之后的部分，即 $d[\,p_1+1:\,]$；
- 一级级往上，直到第 $k$ 个点之后的最后一片（顶级域）。

于是就得到**后缀下标集合**：

$$S(d) = \{\,0\,\} \cup \{\,p+1 \mid d[p] = \texttt{'.'}\,\}$$

其中 $\lvert S(d)\rvert = k+1$，恰好是「完整域名 + $k$ 级父域名」的个数。**每个起点只出现一次**，因此不需要任何去重结构：对 $\text{start} \in S(d)$ 各自累加一次 $\text{rep}$ 即可。

这一步把「层级关系」这种看起来像树的结构，压缩成了一个**线性扫描 + 哈希表**的问题：树上的每条祖先链，都对应一次「从某个点之后开始取后缀」。

### 3.3 算法流程

![解析计数、跳点取后缀、哈希表累加、格式化输出](images/wc78_q1_algorithm_flow.svg)

1. 建空哈希表 $\text{cnt}$，键是子域名字符串，值是累计次数。
2. 对每条记录 `item`：
   - 找到第一个空格，左侧 `rep = stoi(item[0:sp])`，右侧 `domain = item[sp+1:]`；
   - `start = 0`；
   - 循环：$\text{cnt}[\,\text{domain}[\text{start}:]\,] \mathrel{+}= \text{rep}$；在 `domain` 中从 `start` 起找下一个 `.`，位置记为 `dot`；若不存在则跳出，否则 `start = dot + 1`。
3. 遍历 `cnt`，把每个键值拼成 `"count domain"` 放进答案数组。

注意第 2 步的循环**天然是「先加自身，再逐级向上」**的顺序：`start = 0` 那一次加的是完整域名，之后每跳过一个点就上升一层，最后一次加的是顶级域。

### 3.4 示例演算

以示例 2 为例，四条记录的分发与合并过程：

![示例 2 的四条记录逐条分发与累加过程](images/wc78_q1_walkthrough.svg)

| 记录 | 产生的后缀（次数） | 说明 |
|------|--------------------|------|
| `900 google.mail.com` | google.mail.com +900，mail.com +900，com +900 | 两个点 ⇒ 3 个后缀 |
| `50 yahoo.com` | yahoo.com +50，com +50 | 一个点 ⇒ 2 个后缀 |
| `1 intel.mail.com` | intel.mail.com +1，mail.com +1，com +1 | 两个点 ⇒ 3 个后缀 |
| `5 wiki.org` | wiki.org +5，org +5 | 一个点 ⇒ 2 个后缀 |

合并后：`mail.com = 900+1 = 901`，`com = 900+50+1 = 951`，其余各自等于本记录的 `rep`。共 $3+2+3+2=10$ 次累加，产生 7 个不同的键，与输出长度一致。

## 4. 算法细节

1. **只按第一个空格切分**。C++ 用 `item.find(' ')` 取位置后分两段；Python 用 `item.split(' ', 1)`。若写成 `split()` 全切，域名里一旦混入多余空格就会被拆散（本题保证不会，但 `split(' ', 1)` 更贴合「计数 + 域名」的两段式定义）。
2. **后缀用「指针跳点」生成，而不是 `split('.')` 再逐级 `join`**。前者每次只做一次 `find`，代价是「后缀总长度」；后者要在每层重新拼一遍字符串，写起来啰嗦且同样有 $O(L^2)$ 的复制。本题 $L \le 100$，两者都能过，但跳点写法更短、更不容易错。
3. **`find` 的起点必须是 `start`**。写成 `domain.find('.')`（等价于从 0 找）会永远返回第 1 个点，导致 `start` 卡死或死循环。这是本题最容易写错的一行。
4. **累加用 `+=` 而不是 `=`**。同一个子域名可能来自多条记录（`mail.com` 来自 900 和 1 两条），覆盖写会丢掉前面的和。
5. **计数上限只有 $10^6$**。单条 `rep ≤ 10^4`、至多 100 条，总和 $\le 10^6$，C++ 用 `int` 足够，不需要 `long long`。
6. **C++ 的 `unordered_map<string,int>` 用 `operator[]`** 会在键不存在时插入 0，随后 `+= rep`；遍历时用 `const auto& kv` 避免拷贝键。`.reserve()` 不是必须的，但键数不超过 $\sum (k_i+1) \le 300$，加上可减少 rehash。
7. **输出顺序任意**。判题器按集合比较，不需要排序。若自己写对拍脚本，比较前务必先把两个列表排序，否则会因为顺序不同误报 WA。
8. **`stoi` 的边界**。`rep` 从下标 0 开始、到空格前结束，`stoi(item.substr(0, sp))` 或 `atoi` 都可以；不要用 `item[0] - '0'` 只取一位，`rep` 可能是四位数。

## 5. 正确性证明

**引理 1（后缀集合完整且无重复）**：设域名 $d$ 有 $k$ 个点，位置为 $p_1 < p_2 < \dots < p_k$，则 $d$ 的全部子域名（自身 + 各级父域名）恰为

$$d[0:],\ d[p_1+1:],\ d[p_2+1:],\ \dots,\ d[p_k+1:]$$

共 $k+1$ 个，且两两不同。

**证明**：层数等于点分片段数 $k+1$。第 0 层是 $d$ 自身；第 $j$ 层（$1 \le j \le k$）是「删去最左 $j$ 个片段」，正好从第 $j$ 个点之后开始，即 $d[p_j+1:]$。另一方面，$d[p_j+1:]$ 的长度为 $\lvert d\rvert - p_j - 1$，关于 $j$ 严格递减，故 $k+1$ 个后缀长度两两不同，必不相等。∎

**引理 2（每条记录对每个后缀恰好累加一次）**：第 $i$ 条记录执行时，内层循环对每个 $\text{start} \in S(d_i)$ 恰好访问一次，且只访问这些起点。

**证明**：起点序列由 `start = 0` 与 `start = dot + 1` 递推生成，其中 `dot` 是「从当前 `start` 起的第一个点」，即 $p_1, p_2, \dots, p_k$ 依次被枚举，每轮 `start` 严格递增，故不重不漏；当 `find` 返回 $\text{npos}$ 时循环结束，正好在最后一个点之后停止。∎

**引理 3（不变式）**：处理完前 $m$ 条记录后，对任意域名 $s$ 有

$$\text{cnt}[s] = \sum_{i \le m,\ s \in \text{Sub}(d_i)} \text{rep}_i$$

（$\text{Sub}(d)$ 表示 $d$ 的全部子域名；未出现过的 $s$ 视为 0。）

**证明**：对 $m$ 归纳。$m=0$ 时表为空、右端为空和，成立。设处理完前 $m$ 条成立，处理第 $m+1$ 条时由引理 2，它对自己每个子域名 $s \in \text{Sub}(d_{m+1})$ 恰好加一次 $\text{rep}_{m+1}$，对其余域名不加任何东西，故不变式推进为 $m+1$。∎

**定理（算法正确）**：处理完全部 $n$ 条记录后，输出的每个 `"cnt[s] s"` 中 `cnt[s]` 等于 $s$ 的真实总访问次数；且哈希表的键集合恰为所有出现过的子域名。

**证明**：取引理 3 中 $m=n$，$\text{cnt}[s]$ 就是所有把 $s$ 作为子域名的记录次数之和，正是 $s$ 的总访问次数（访问完整域名时隐式访问全部父域名，由引理 1 枚举完整）。键集合等于 $\bigcup_i \text{Sub}(d_i)$，因为只有内层循环会写键、且写入的键都来自某个 $\text{Sub}(d_i)$；每个键只输出一次（哈希表键唯一），恰好覆盖所有出现过的子域名。∎

## 6. 复杂度分析

- **时间**：设第 $i$ 条记录的域名长度为 $L_i$、点数为 $k_i$，其余部分（读入、找空格）为 $O(L_i)$。内层循环做 $k_i+1$ 次「切片 + 哈希 + 累加」，切片复制长度为 $L_i - \text{start}$，故单条记录代价为

  $$O\!\left(\sum_{j=0}^{k_i} (L_i - \text{start}_j)\right) = O(k_i L_i)$$

  由题面 $k_i \le 2$，即每条记录 $O(L_i)$；总计 $O\!\left(\sum_i L_i\right) = O(N)$，其中 $N \le 10^4$ 是输入总字符数（$100 \times 100$）。字符串哈希本身是 $O(L)$，已在切片长度里计入。最后遍历哈希表输出 $O(\sum \text{长度})$。
- **空间**：哈希表最多存 $\sum_i (k_i+1) \le 300$ 个键，键的总长度 $\le \sum_i O(k_i L_i) = O(N)$；答案数组同理。故额外空间 $O(N)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<string> subdomainVisits(vector<string>& cpdomains) {
        unordered_map<string, int> cnt;          // 子域名 -> 累计访问次数
        cnt.reserve(cpdomains.size() * 3);

        for (const string& item : cpdomains) {
            size_t sp = item.find(' ');          // 只按第一个空格切分
            int rep = stoi(item.substr(0, sp));
            string domain = item.substr(sp + 1);

            size_t start = 0;
            while (true) {
                cnt[domain.substr(start)] += rep;    // 完整域名 / 某一级父域名
                size_t dot = domain.find('.', start);  // 必须从 start 起找
                if (dot == string::npos) break;
                start = dot + 1;
            }
        }

        vector<string> ans;
        ans.reserve(cnt.size());
        for (const auto& kv : cnt) {
            ans.push_back(to_string(kv.second) + " " + kv.first);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def subdomainVisits(self, cpdomains: list[str]) -> list[str]:
        cnt = {}
        for item in cpdomains:
            num, domain = item.split(' ', 1)   # 计数与域名两段
            rep = int(num)

            start = 0
            while True:
                sub = domain[start:]           # 完整域名，或某一级父域名
                cnt[sub] = cnt.get(sub, 0) + rep
                dot = domain.find('.', start)  # 从 start 起找，别写成 find('.')
                if dot == -1:
                    break
                start = dot + 1

        return [f"{v} {k}" for k, v in cnt.items()]
```

## 8. 边界情况与易错点

1. **域名里没有点**。题面保证 `d1.d2.d3` 或 `d1.d2`，但循环必须能优雅退出：`find` 返回 `npos`/`-1` 就 `break`，不要假设「至少有一个点」而先 `start = dot + 1`，否则 `npos + 1` 回绕成 0，直接死循环。
2. **`find` 忘了带起点参数**。`domain.find('.')` 永远指向第 1 个点，`start` 会卡在第 1 个点之后反复累加同一后缀。这是本题最高频的 WA 来源，务必写 `find('.', start)`。
3. **覆盖写而非累加**。`cnt[sub] = rep` 会把 `mail.com` 的 900 和 1 变成 1，示例 2 立刻出错（正确是 901）。
4. **漏掉完整域名自身**。若循环从「第一个点之后」开始，答案里就没有 `discuss.leetcode.com` 这样的完整域名；起点必须是 `0`。
5. **比较输出顺序**。题目允许任意顺序，本地对拍要先 `sorted()` 再比；直接把官方输出和你的输出按位置比会误判。
6. **`rep` 只取一位**。`rep` 最大 $10^4$，是四位/五位数，必须整段 `stoi`/`int`，不能用 `item[0] - '0'`。
7. **同一记录重复出现**。例如 `["1 a.com","2 a.com"]` 应得 `3 a.com`、`3 com`；哈希表的 `+=` 天然处理，不要额外去重记录。
