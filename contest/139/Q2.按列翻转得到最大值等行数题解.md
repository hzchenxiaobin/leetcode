# LeetCode 按列翻转得到最大值等行数 题解

## 1. 题目概述

- **标题 / 题号**：按列翻转得到最大值等行数（#1072，medium）
- **链接**：https://leetcode.cn/problems/flip-columns-for-maximum-number-of-equal-rows/
- **来源**：LeetCode 第 139 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、矩阵

**题意**：给定 $m \times n$ 的 0/1 矩阵。可以任选若干列，把这一列上的所有格子**同时**取反（0 变 1、1 变 0）。求操作后「行内所有值都相等」的行数最大值。

**约束**：

- $m = \text{matrix.length}$，$n = \text{matrix}[i]\text{.length}$
- $1 \le m, n \le 300$
- $\text{matrix}[i][j] \in \{0, 1\}$

**一句话转化**：翻转列相当于给**每一行**异或同一个 0/1 掩码；要让尽量多的行变成「全 0」或「全 1」，等价于让它们**归一化**后完全相同。

## 2. 示例

**示例 1**

```text
输入：matrix = [[0,1],[1,1]]
输出：1
解释：不进行翻转，只有第 2 行（[1,1]）行内值相等。
```

**示例 2**

```text
输入：matrix = [[0,1],[1,0]]
输出：2
解释：翻转第 1 列后得到 [[1,1],[0,0]]，两行都行内相等。
```

**示例 3**

```text
输入：matrix = [[0,0,0],[0,0,1],[1,1,0]]
输出：2
解释：翻转前两列后得到 [[1,1,0],[1,1,0],[0,0,0]] 的等价形，后两行变成全相等。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有列的子集（$2^n$ 种翻转方案），每种方案逐行检查是否全相等，复杂度 $O(2^n \cdot mn)$。$n \le 300$ 时 $2^{300}$ 完全不可能。即使用「每行只关心自己是否全相等」来优化，方案数依旧是障碍——必须换视角。

### 3.2 核心观察：翻转 = 异或同一个掩码

![把每行归一化成首元素为 0](images/wc139_q2_canonical.svg)

设翻转的列集合对应的掩码为 $K \in \{0,1\}^n$。对第 $i$ 行 $r_i$，翻转后为 $r_i \oplus K$（按位异或）。

行 $r_i \oplus K$ 行内全相等，意味着它要么是 $0^n$、要么是 $1^n$，即

$$r_i = K \quad \text{或} \quad r_i = \overline{K}$$

于是：**在同一个掩码 $K$ 下能变成全相等的行，只能等于 $K$ 或 $\overline{K}$**。反过来说，两行 $X, Y$ 能被同一个掩码同时救成全相等，当且仅当 $X = Y$ 或 $X = \overline{Y}$。

给每行定义一个**归一化键**：把行与自己的首元素异或，得到首元素必为 0 的那一行：

$$\text{key}(r) = r \oplus (r_0, r_0, \ldots, r_0)$$

- 若 $X = Y$，显然 $\text{key}(X) = \text{key}(Y)$；
- 若 $X = \overline{Y}$，则两者的首元素相反，归一化后都变成「首元素为 0」的那一个形态，键也相同。

于是答案就是**同一归一化键出现次数的最大值**：把这个键本身取作 $K$，该键对应的所有行（原始形态只有两种）都会变成 $0^n$。

### 3.3 算法流程

```text
1. 哈希表 cnt = {}
2. 对每一行 r：
       key = (r[0] ? r ⊕ 1^n : r)      # 等价于 r[i] ^ r[0]
       cnt[key] += 1
3. 返回 max(cnt.values())
```

对每一行的第 $j$ 位，`key[j] = r[j] ^ r[0]`：若 $r_0 = 0$ 键就是原行，若 $r_0 = 1$ 键就是取反后的行。

### 3.4 示例演算

![示例 3 的归一化与频次统计](images/wc139_q2_walkthrough.svg)

`matrix = [[0,0,0],[0,0,1],[1,1,0]]`：

| 行 | 原行 | $r_0$ | 归一化键 | 键频次 |
|----|------|-------|----------|--------|
| 1 | `0 0 0` | 0 | `0 0 0` | A：1 |
| 2 | `0 0 1` | 0 | `0 0 1` | B：2 |
| 3 | `1 1 0` | 1 | `0 0 1` | B：2 |

键 B 出现 2 次，故答案 2：取 $K = (0,0,1)$，翻转第 1、2 列后第 2、3 行都变成 `1 1 1`。

再看示例 2：`[[0,1],[1,0]]` 的键都是 `0 1`，答案 2，对应翻转第 1 列。

示例 1：`[[0,1],[1,1]]` 的键分别是 `0 1` 与 `0 0`，最大频次为 1，答案 1。

## 4. 算法细节

1. **键的表示**：C++ 可用 `string`（每行 $n$ 个 `'0'`/`'1'` 字符）作哈希键，代码最简；也可用 `bitset` + 自定义哈希，或把每 60 位打包成 `long long`。Python 直接用 `tuple(row)` 作键。
2. **复杂度**：每行 $O(n)$ 构造键 + 哈希 $O(n)$，总计 $O(mn)$，$m = n = 300$ 时 $9 \times 10^4$ 次操作。
3. **最大值维护**：可以在插入时顺手更新 `best = max(best, ++cnt[key])`，省掉最后一次遍历。
4. **`r[0] ^ r[0] = 0`**：用 `x ^ r[0]` 同时处理「不改」和「整体取反」两种情况，写起来最简洁（0/1 异或等价于条件取反）。
5. **不需要真的翻转矩阵**：只做统计，最后答案与具体的翻转方案无关。
6. **哈希碰撞**：用 `string` / `tuple` 作键不会碰撞；若自定义整型键要注意位数上限。

## 5. 正确性证明

记第 $i$ 行为 $r_i \in \{0,1\}^n$，翻转掩码 $K \in \{0,1\}^n$。

**引理 1（翻转即异或）**：翻转列集合 $S \subseteq \{1..n\}$ 后，第 $i$ 行等于 $r_i \oplus K$，其中 $K_j = 1 \iff j \in S$。

**证明**：逐位看：若 $j \in S$，该列取反，$r_i[j] \to 1 - r_i[j] = r_i[j] \oplus 1 = r_i[j] \oplus K_j$；若 $j \notin S$，$r_i[j] = r_i[j] \oplus 0$。∎

**引理 2（行被救的条件）**：$r_i \oplus K$ 行内全相等 $\iff r_i = K$ 或 $r_i = \overline{K}$。

**证明**：$r_i \oplus K$ 行内全相等意味着它对所有 $j$ 都等于同一个比特 $b \in \{0,1\}$，即 $r_i \oplus K = b^n$，于是 $r_i = K \oplus b^n$：$b = 0$ 时 $r_i = K$，$b = 1$ 时 $r_i = \overline{K}$。反之亦然。∎

**引理 3（键相同的等价刻画）**：$\text{key}(X) = \text{key}(Y) \iff X = Y$ 或 $X = \overline{Y}$。

**证明**：($\Leftarrow$) 若 $X = Y$，显然键相同；若 $X = \overline{Y}$，则 $X_0 = 1 - Y_0$，$\text{key}(X)_j = X_j \oplus X_0 = \overline{Y_j} \oplus (1 - Y_0) = Y_j \oplus Y_0 = \text{key}(Y)_j$。
($\Rightarrow$) 若键相同，注意由 $X = \text{key}(X) \oplus X_0^n$ 与 $Y = \text{key}(Y) \oplus Y_0^n$，两行都等于同一个键加上「首比特广播」的两种可能之一，故 $X = Y$（当 $X_0 = Y_0$）或 $X = \overline{Y}$（当 $X_0 \ne Y_0$）。∎

**定理**：算法返回 $\max_K \#\{i : r_i = K \text{ 或 } r_i = \overline{K}\}$，即题目的答案。

**证明**：对固定掩码 $K$，由引理 2，被救成全相等的行恰为 $r_i = K$ 或 $r_i = \overline{K}$ 者。设 $\text{key}$ 值为 $v$ 的行集合为 $C_v$，由引理 3，$C_v = \{i : r_i = X \text{ 或 } r_i = \overline{X}\}$，其中 $X$ 是 $C_v$ 中任一行的原形态。于是「取 $K = v$ 时被救的行数」$= \lvert C_v \rvert$。算法取所有键频次的最大值，即 $\max_v \lvert C_v \rvert = \max_K \#\{i : r_i = K \text{ 或 } r_i = \overline{K}\}$，故与最优翻转方案的行数一致。又每个 $K$ 都可实际执行（翻转 $K$ 中为 1 的列），故答案可达。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每行构造键 $O(n)$，哈希插入均摊 $O(n)$（字符串哈希），共 $m$ 行。
- **空间**：$O(mn)$ 存放全部键（最坏每行不同）；若只需答案可边插边更新，额外空间仍为 $O(mn)$ 的键存储。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int maxEqualRowsAfterFlips(vector<vector<int>>& matrix) {
        unordered_map<string, int> cnt;
        int best = 0;
        for (auto& row : matrix) {
            string key;
            key.reserve(row.size());
            for (int x : row) key.push_back((char)('0' + (x ^ row[0])));
            best = max(best, ++cnt[key]);
        }
        return best;
    }
};
```

### Python

```python
from collections import Counter


class Solution:
    def maxEqualRowsAfterFlips(self, matrix: list[list[int]]) -> int:
        cnt = Counter()
        for row in matrix:
            head = row[0]
            cnt[tuple(x ^ head for x in row)] += 1
        return max(cnt.values())
```

## 8. 边界情况与易错点

1. **`n == 1`**：任何一行翻转后都只有 1 个元素，天然「行内全相等」，答案是 $m$。算法中每行键都是 `(0,)`，频次 $m$，正确。
2. **`m == 1`**：只有一行，答案 1（翻转列不会让它变得不相等）。
3. **行完全相同**：如 `[[1,0],[1,0]]`，键相同，答案 2。
4. **行互补**：如 `[[1,0],[0,1]]`，键相同，答案也是 2——这正是「取反后相同」的情形，容易漏。
5. **误以为要比较「原行相等」**：只比较原行会漏掉互补的行对（示例 2 就是互补）。
6. **键里必须含首元素的处理**：若直接把 `row` 当键，会把 `[0,1]` 与 `[1,0]` 判为不同，答案偏小。
7. **`std::string` 里存 `'0'+bit`**：注意 `char('0' + (x ^ row[0]))` 中 `x ^ row[0]` 是 0/1，别写成 `x ^ '0'` 之类。
8. **返回值是行数最大值**，不是翻转后全相等的**最长**行，也不是翻转次数。
