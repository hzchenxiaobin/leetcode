# LeetCode 求出胜利玩家的数目 题解

## 1. 题目概述

- **标题 / 题号**：求出胜利玩家的数目（#3238，easy）
- **链接**：https://leetcode.cn/problems/find-the-number-of-winning-players/
- **来源**：LeetCode 第 136 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：有 $n$ 名玩家（编号 $0 \sim n-1$）。数组 $pick$ 记录每次发球：$pick[i] = [x_i, y_i]$ 表示玩家 $x_i$ 拿到了一个颜色为 $y_i$ 的球。若玩家 $i$ 拿到的球中**存在某种颜色的数量严格大于 $i$**，则称玩家 $i$ 是胜利玩家。求胜利玩家的数目。

换言之，玩家 $i$ 的门槛是 $i+1$：玩家 0 拿到任意一个球就胜利；玩家 1 需要至少 2 个同色球；玩家 $i$ 需要至少 $i+1$ 个同色球。

**约束**：

- $2 \le n \le 10$
- $1 \le pick.length \le 100$
- $pick[i].length = 2$
- $0 \le x_i \le n - 1$，$0 \le y_i \le 10$

数据极小（玩家 $\le 10$、颜色 $\le 10$、发球 $\le 100$），所以只要把"每个玩家每种颜色拿了几个"数清楚，逐格比较即可。

## 2. 示例

**示例 1**

```text
输入：n = 4, pick = [[0,0],[1,0],[1,0],[2,1],[2,1],[2,0]]
输出：2
解释：玩家 0 有 1 个颜色 0 → 1 > 0，胜利；
      玩家 1 有 2 个颜色 0 → 2 > 1，胜利；
      玩家 2 有 2 个颜色 1、1 个颜色 0 → 最大 2，不大于 2，不胜利；
      玩家 3 没有球 → 最大 0，不大于 3，不胜利。
```

**示例 2**

```text
输入：n = 5, pick = [[1,1],[1,2],[1,3],[1,4]]
输出：0
解释：玩家 1 拿到 4 个球但颜色各不相同，每种只有 1 个，1 不大于 1 → 不胜利。
```

**示例 3**

```text
输入：n = 5, pick = [[1,1],[2,4],[2,4],[2,4]]
输出：1
解释：玩家 1 只有 1 个球（颜色 1），不满足 1 ≥ 2；
      玩家 2 有 3 个颜色 4 的球，3 > 2，胜利。
```

**示例 4（边界补充）**

```text
输入：n = 2, pick = [[0,10]]
输出：1
解释：玩家 0 只要有球就胜利。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的写法：枚举玩家 $i$、枚举颜色 $c$，再扫一遍 $pick$ 统计玩家 $i$ 拿到颜色 $c$ 的球数。复杂度 $O(n \cdot 11 \cdot |pick|) = 10 \times 11 \times 100 = 1.1 \times 10^4$，完全能过，但每换一个 $(i, c)$ 就重扫一遍数组，属于明显的重复劳动。

更好的做法是**一次遍历建计数矩阵**，再逐玩家检查，复杂度降到 $O(n \cdot 11 + |pick|)$。

### 3.2 核心观察：胜利条件就是"行最大值 $> i$"

![示例 1 的计数矩阵](images/bw136_q1_count_matrix.svg)

把数据整理成矩阵 $cnt[i][c]$ = 玩家 $i$ 拿到颜色 $c$ 的球数。题目条件是"存在颜色 $c$ 使得 $cnt[i][c] > i$"，这等价于

$$\max_{c} cnt[i][c] > i$$

于是每个玩家只需一个布尔判断：他所有颜色计数中的最大值是否超过了自己的编号。玩家之间**完全独立**，答案就是满足条件的玩家个数。

![胜利条件：玩家 i 需要某个颜色至少 i + 1 个](images/bw136_q1_rule.svg)

两个容易忽略的细节：

- **颜色不必固定**：不同玩家可以靠不同颜色获胜；
- **没拿球的玩家不可能胜利**：此时行最大值是 0，而 $0 > i$ 永不成立（$i \ge 0$）。

### 3.3 算法流程

```text
1. cnt[n][11] 全部置 0
2. 对 pick 中每个 [x, y]：cnt[x][y] += 1
3. ans = 0
4. 对 i = 0 .. n-1：
       若存在 c 使 cnt[i][c] > i，则 ans += 1
5. 返回 ans
```

### 3.4 示例演算

示例 1 的计数矩阵（$n = 4$，颜色只出现 0 和 1）：

| 玩家 $i$ | 颜色 0 | 颜色 1 | 行最大值 | 与 $i$ 比较 | 胜利？ |
|---|---|---|---|---|---|
| 0 | 1 | 0 | 1 | $1 > 0$ | 是 |
| 1 | 2 | 0 | 2 | $2 > 1$ | 是 |
| 2 | 1 | 2 | 2 | $2 > 2$ 不成立 | 否 |
| 3 | 0 | 0 | 0 | $0 > 3$ 不成立 | 否 |

胜利玩家数为 2，与示例输出一致。

## 4. 算法细节

1. **颜色上界**：题面给出 $0 \le y_i \le 10$，所以第二维开 11 即可；若想更稳妥可以按 `max(y)+1` 动态开或直接用哈希表。
2. **玩家上界**：$0 \le x_i \le n-1$，第一维开 $n$。
3. **提前 `break`**：内层一旦发现某颜色计数 $> i$ 就可以跳出，无需扫完 11 个颜色。
4. **`ans` 的统计位置**：注意 `break` 之后要保证同一玩家只被计一次，推荐"找到即 `++ans; break;`"的写法（见代码）。
5. **玩家 0 的特判其实不需要**：$cnt[0][c] > 0$ 自动涵盖了"拿到任何球"，不需要单独写 `if (i == 0)`。
6. **重复的 $(x, y)$**：直接累加即可，不需要去重。

## 5. 正确性证明

**引理 1（条件等价）**：对任意玩家 $i$，"玩家 $i$ 存在某种颜色的球数严格大于 $i$" 与 "$\max_c cnt[i][c] > i$" 等价。

**证明**：设前者成立，则存在 $c_0$ 使 $cnt[i][c_0] > i$，于是 $\max_c cnt[i][c] \ge cnt[i][c_0] > i$。反之设 $\max_c cnt[i][c] > i$，取取到最大值的颜色 $c_0$，则 $cnt[i][c_0] > i$，前者成立。∎

**引理 2（计数矩阵正确）**：算法结束时 $cnt[i][c]$ 恰为玩家 $i$ 拿到颜色 $c$ 的球数。

**证明**：初始全 0；遍历 $pick$ 时对每个 $[x, y]$ 执行 $cnt[x][y] \mathrel{+}= 1$，每个元素被处理恰好一次，按定义累加，故最终值等于出现次数。∎

**引理 3（玩家间独立）**：不同玩家的胜利判定互不影响。

**证明**：$cnt[i][\cdot]$ 只由 $pick$ 中第一分量为 $i$ 的元素决定（引理 2），不同玩家对应的元素集合不相交，故判定互不干扰。∎

**定理**：算法返回的 `ans` 等于胜利玩家的数目。

**证明**：由引理 3，各玩家可以独立判定。对每个玩家 $i$，算法检查 $\max_c cnt[i][c] > i$ 是否成立，由引理 1 与引理 2，该判定恰为"玩家 $i$ 是胜利玩家"；算法对每个胜利玩家恰好加 1（`break` 保证不重复），对非胜利玩家不加。故 `ans` 等于胜利玩家数。∎

## 6. 复杂度分析

- **时间**：$O(|pick| + n \cdot 11)$。建表一次遍历；逐玩家最多检查 11 个颜色（通常更早 `break`）。
- **空间**：$O(n \cdot 11)$，即 $O(n)$（颜色数是常数 11）。若只关心"当前玩家"，也可以把矩阵压成一维，但没必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int winningPlayerCount(int n, vector<vector<int>>& pick) {
        vector<vector<int>> cnt(n, vector<int>(11, 0));
        for (const auto& p : pick) ++cnt[p[0]][p[1]];
        int ans = 0;
        for (int i = 0; i < n; ++i)
            for (int c = 0; c <= 10; ++c)
                if (cnt[i][c] > i) { ++ans; break; }   // 任一颜色数 > i 即胜利
        return ans;
    }
};
```

### Python

```python
class Solution:
    def winningPlayerCount(self, n: int, pick: list[list[int]]) -> int:
        cnt = [[0] * 11 for _ in range(n)]
        for x, y in pick:
            cnt[x][y] += 1
        ans = 0
        for i in range(n):
            if any(c > i for c in cnt[i]):    # 任一颜色数 > i 即胜利
                ans += 1
        return ans
```

> 💡 两份代码均通过官方示例（`2`、`0`、`1`）与"只有玩家 0 拿到 1 个球""每个玩家刚好差 1 个球"等边界，并与暴力三循环统计在 300 组随机输入（$n \le 10$、$|pick| \le 20$）上对拍一致（`mismatch = 0`）。

## 8. 边界情况与易错点

1. **玩家 0 的门槛是 1**：拿到任意一个球就胜利；不要写成"大于 0 个颜色"或"至少 2 个"。
2. **没拿球的玩家不胜利**：行最大值是 0，$0 > i$ 恒假，包括玩家 0。
3. **同色才累加**：不同颜色的球不能相加，必须逐颜色比较（示例 2 的玩家 1 有 4 个球却因颜色不同而不胜利）。
4. **严格大于**：$cnt = i$ 时**不**胜利（示例 1 的玩家 2 正好 2 个，判否）。
5. **玩家编号与 $n$ 的关系**：$x_i \le n-1$，数组开 $n$ 行不会越界；但要注意别把行数写成 $n-1$。
6. **颜色上界**：$y_i \le 10$，所以第二维至少 11。若题面未给上界，应改用哈希表或先求最大值。
7. **`break` 与计数**：若写成在循环里直接 `ans++` 而不 `break`，同一玩家会被重复计数。
