# LeetCode 对数组执行操作使平方和最大 题解

## 1. 题目概述

- **标题 / 题号**：对数组执行操作使平方和最大（#2897，hard）
- **链接**：https://leetcode.cn/problems/apply-operations-on-array-to-maximize-sum-of-squares/
- **来源**：LeetCode 第 366 场周赛 Q4
- **难度**：困难
- **标签**：贪心、位运算、数组

**题意**：给定下标从 0 开始的整数数组 `nums` 与正整数 $k$。可以执行**任意次**操作：任选两个互不相同的下标 $i, j$，**同时**将 `nums[i]` 更新为 `nums[i] AND nums[j]`、`nums[j]` 更新为 `nums[i] OR nums[j]`（两个新值都按操作前的**旧值**计算）。操作全部结束后，从数组中选 $k$ 个元素，最大化它们的**平方和**；答案对 $10^9 + 7$ 取模后返回。

**约束**：

- $1 \le k \le n = \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,6,5,8], k = 2
输出：261
解释：op(0,3)：nums 变为 [0,6,5,10]（2 AND 8 = 0，2 OR 8 = 10）；
      op(2,3)：nums 变为 [0,6,0,15]（5 AND 10 = 0，5 OR 10 = 15）。
      选 15 和 6，15² + 6² = 225 + 36 = 261。
```

**示例 2**

```text
输入：nums = [4,5,4,7], k = 3
输出：90
解释：无需任何操作，选 7、5、4：49 + 25 + 16 = 90。
```

**示例 3**（自造，感受「聚集」的收益）

```text
输入：nums = [1,2,4], k = 1
输出：49
解释：op(2,0)：[5,2,0]（4 AND 1 = 0，4 OR 1 = 5）；op(0,1)：[0,7,0]（5 AND 2 = 0，5 OR 2 = 7）。
      选 7，得 49。若不操作只能选 4，仅 16 —— k = 1 时应把所有位聚成一个数。
```

## 3. 解题思路

### 3.1 暴力思路：无穷的状态空间

操作次数没有上界，数组的可达状态无限，BFS/DFS 或枚举操作序列无从下手；即便意识到「位可以在元素之间流动」，直接枚举每位分给谁也是组合爆炸（30 个位 × $10^5$ 个元素）。突破口必须是不变量——把「怎么操作」这个动态过程压缩成一个**静态量**。

### 3.2 核心观察一：位计数不变量

![操作即搬位，位计数守恒](images/wc366_q4_bit_transfer.svg)

固定某个二进制位 $b$，一次操作只涉及两个数。逐位枚举该位的四种输入组合（见上图表格）：$(1,1) \to (1,1)$、$(1,0) \to (0,1)$、$(0,1) \to (0,1)$、$(0,0) \to (0,0)$——**该位上 1 的个数永远不变**。

换言之，一次操作的语义是：**AND 侧交出「自己有、对方没有」的位，OR 侧照单全收**。位像货物一样在元素之间搬运，但库存清单 $\text{cnt}[b]$（第 $b$ 位上 1 的总数）全程守恒。于是：

> 💡 初始数组的具体数值、位落在谁身上都**无关紧要**，有意义的只有位库存 $\text{cnt}[0], \dots, \text{cnt}[29]$（$\text{nums}[i] \le 10^9 < 2^{30}$）。问题从「怎么操作」降维成「怎么把库存分给 $k$ 个数」。

### 3.3 核心观察二：凸性聚集 → 嵌套链

![凸性聚集与嵌套链](images/wc366_q4_nested_funnel.svg)

现在只剩一个分配问题：把每位 $b$ 的 $\text{cnt}[b]$ 个 1 发给被选中的 $k$ 个数，最大化平方和。

**发给谁？** 平方是凸函数，同样的总量**越集中平方和越大**。交换论证：设 $x \ge y \ge 2^b$，把 $y$ 的位 $b$ 挪给 $x$，平方和增量

$$\Delta = (x+2^b)^2 + (y-2^b)^2 - x^2 - y^2 = 2^{b+1}(x - y) + 2 \cdot 4^b > 0$$

所以每一位都应发给**当前值最大**的数。两个观察一结合，最优分配是嵌套链：

$$v_i = \{\, b : \text{cnt}[b] \ge i \,\}, \qquad i = 1, 2, \dots, k$$

即第 $i$ 大的数拿到**所有份数不少于 $i$** 的位——位集嵌套 $v_1 \supseteq v_2 \supseteq \cdots \supseteq v_k$（马太效应：劫贫济富）。$\text{cnt}[b] > k$ 的多余份数倾倒给未选中的元素即可，反正不计入平方和。

### 3.4 算法流程

1. **统计位库存**：$\text{cnt}[b] \leftarrow$ `nums` 中第 $b$ 位为 1 的元素个数，$b \in [0, 30)$；
2. **拼数**：对 $i = 1, \dots, k$：$v_i = \sum_{\text{cnt}[b] \ge i} 2^b$；
3. **累加取模**：$\text{ans} = \sum_{i=1}^{k} v_i^2 \bmod (10^9+7)$。

**等价实现**（免拼数）：维护长度为 $k$ 的降序数组 `vals`，从**高位到低位**把 $2^b$ 加到前 $c = \min(\text{cnt}[b], k)$ 个元素上——「降序数组前缀同值加法」不破坏降序（$\text{vals}[c-1] + 2^b > \text{vals}[c-1] \ge \text{vals}[c]$），全程免排序。

### 3.5 示例演算

![示例演算](images/wc366_q4_example_walkthrough.svg)

以示例 1（`nums = [2,6,5,8]`，$k=2$）为例。位库存：$\text{cnt}[3] = 1$（8）、$\text{cnt}[2] = 2$（6, 5）、$\text{cnt}[1] = 2$（2, 6）、$\text{cnt}[0] = 1$（5）。

| $i$ | 拿到的位（$\text{cnt}[b] \ge i$） | $v_i$ | $v_i^2$ |
|-----|----------------------------------|-------|---------|
| 1 | 8, 4, 2, 1 | 15 | 225 |
| 2 | 4, 2 | 6 | 36 |

$\text{ans} = 225 + 36 = 261$ ✓。上图左侧给出一条**真实操作序列**（依序吸收，见 §5 引理 4）：6 次操作后数组恰好变成 $[15, 6, 0, 0]$，与贪心直接拼出的嵌套链完全一致；官方示例的两步操作 $[0,6,0,15]$ 也是同一条链——**嵌套链是一切最优操作殊途同归的终点**。

再复核示例 2（`nums = [4,5,4,7]`，$k=3$）：$\text{cnt}[2] = 4$（全员）、$\text{cnt}[1] = 1$（7）、$\text{cnt}[0] = 2$（5, 7），拼出 $v = (7, 5, 4)$，$49 + 25 + 16 = 90$ ✓——原数组本身已含这条链，所以「不操作」就是最优。

## 4. 算法细节

1. **位宽取 30**：$\text{nums}[i] \le 10^9 < 2^{30} = 1073741824$，位下标 $0 \sim 29$。
2. **「同时更新」语义**：两个新值都用操作前的旧值计算。贪心只读守恒量 $\text{cnt}$，与该语义无关；但构造操作序列（引理 4）时要注意 **OR 侧是吸收方**，方向别写反。
3. **拼数与发位两种写法等价**：按 $i$ 拼 $v_i$ 是 $O(30k)$；按位发前缀也是 $O(30k)$ 外加保序技巧。两者都是嵌套链的直接翻译，任选其一。
4. **溢出与取模**：$v < 2^{30} \Rightarrow v^2 < 2^{60}$，单个平方在 `long long` 内；但 $k$ 个平方累加可达 $10^5 \cdot 2^{60}$，必须**边加边模**。C++ 移位统一写 `1LL << b`。Python 无溢出，最后取一次模即可。
5. **不要排序 `nums`**：数值大小与答案无关（反例见 §8 的 $[8,1]$），排序纯属浪费。

## 5. 正确性证明

记 $\text{cnt}[b]$ 为初始数组中第 $b$ 位为 1 的元素个数。

**引理 1（位守恒）**：任意有限次操作后，全数组第 $b$ 位上 1 的总数仍为 $\text{cnt}[b]$。

**证明**：一次操作把二元组 $(x, y)$ 替换为 $(x \,\&\, y,\ x \,|\, y)$。固定位 $b$ 枚举四种输入：$(1,1) \to (1,1)$（个数 $2 \to 2$）；$(1,0) \to (0,1)$（$1 \to 1$）；$(0,1) \to (0,1)$（$1 \to 1$）；$(0,0) \to (0,0)$（$0 \to 0$）。对操作次数归纳即得。∎

**引理 2（选中集合的位预算）**：任何终态、任何选中的 $k$ 个数中，位 $b$ 出现的次数 $m_b \le \min(\text{cnt}[b],\, k)$。

**证明**：由引理 1，位 $b$ 在全部 $n$ 个数中共出现 $\text{cnt}[b]$ 次，故任意 $k$ 个数中至多 $\text{cnt}[b]$ 次；又每个数的每个二进制位至多一个 1，故至多 $k$ 次。∎

**引理 3（上移严格增益）**：设非负整数 $x \ge y \ge 2^b$ 且 $y$ 的位集含 $b$。把这一个 $b$ 从 $y$ 挪给 $x$（$x' = x + 2^b$，$y' = y - 2^b \ge 0$），则

$$\Delta = (x')^2 + (y')^2 - x^2 - y^2 = 2^{b+1}(x - y) + 2 \cdot 4^b > 0$$

**证明**：展开 $(x+2^b)^2 + (y-2^b)^2 - x^2 - y^2$，交叉项相消后即得；$x \ge y$ 与 $2 \cdot 4^b > 0$ 保证严格为正。∎

**引理 4（嵌套链可达）**：存在有限次操作，使数组前 $k$ 个元素恰为嵌套链 $v_1, v_2, \dots, v_k$。

**证明**（依序吸收 + 归纳）：对 $j = 0, 1, \dots, k-1$ 执行第 $j$ 轮：以 `nums[j]` 为 **OR 侧（吸收方）**，依次对 $i = j+1, \dots, n-1$ 各做一次操作。归纳命题：第 $j$ 轮开始时，(a) `nums[0..j-1]` 已定格为 $v_1, \dots, v_j$；(b) 下标 $\ge j$ 的元素中，位 $b$ 还剩 $\max(\text{cnt}[b] - j,\, 0)$ 份。

$j = 0$ 时 (b) 即初始状态。轮内处理 $i$ 时，吸收器的当前值恰为「本轮开始时下标 $j..i-1$ 的 OR」，而 `nums[i]` 尚未被本轮触碰——因此位 $b$ 的副本在 $i$ 处保留当且仅当 $i$ **不是**位 $b$ 在下标 $j..n-1$ 中的首次出现。于是第 $j$ 轮结束后：吸收器

$$\text{nums}[j] = \{\, b : \max(\text{cnt}[b] - j, 0) \ge 1 \,\} = \{\, b : \text{cnt}[b] \ge j+1 \,\} = v_{j+1}$$

且下标 $\ge j+1$ 的元素中位 $b$ 恰剩 $\max(\text{cnt}[b] - j - 1, 0)$ 份，`nums[j]` 从此不再被触碰，归纳完成。共 $\sum_{j=0}^{k-1}(n-1-j) = O(nk)$ 次操作——这只是**存在性证明**，代码并不执行。∎

**定理**：嵌套链的平方和 $\sum_{i=1}^{k} v_i^2 \bmod (10^9+7)$ 即为所求最大值。

**证明**：考虑放松问题：所有满足引理 2 预算的位集组 $(S_1, \dots, S_k)$，最大化 $\sum_i \bigl(\sum_{b \in S_i} 2^b\bigr)^2$。该问题取值有限，最优组存在。

（上界）任何可达终态中选出的 $k$ 个数（按值降序 $w_1 \ge \cdots \ge w_k$，位集 $S_1, \dots, S_k$）由引理 1、2 构成放松问题的可行点。设 $(S_1, \dots, S_k)$ 是放松问题的最优组。若存在 $i < j$ 与位 $b \in S_j \setminus S_i$，则 $w_i \ge w_j \ge 2^b$，由引理 3 把 $b$ 上移到 $S_i$ 严格增大目标，与最优性矛盾——故**最优组嵌套**。嵌套时位 $b$ 恰占前 $m_b$ 层；若 $m_b < \min(\text{cnt}[b], k)$，把 $b$ 加进第 $m_b + 1$ 层（仍在预算内且保持嵌套）严格增大目标，矛盾——故 $m_b = \min(\text{cnt}[b], k)$。于是最优组唯一，就是嵌套链 $(v_i)$；任何可行点（从而任何可达解）的值 $\le \sum_{i=1}^{k} v_i^2$。

（取等）由引理 4，嵌套链可达。∎

> 💡 另一个紧凑视角（majorization）：嵌套链（按降序）的任意前 $m$ 项和都达到上界 $\sum_b 2^b \min(\text{cnt}[b], m)$，即嵌套链**弱优超**（weakly majorizes）一切可行解；$\varphi(t) = t^2$ 在非负轴上凸且单调增，故 $\sum \varphi$ 在弱优超序下单调不减。交换论证（引理 3）正是它的初等形式。

## 6. 复杂度分析

- **时间复杂度**：$O((n + k) \cdot 30)$。统计位库存 $O(30n)$，拼数 $O(30k)$；由 $k \le n \le 10^5$，总量约 $6 \times 10^6$ 次基本运算。
- **空间复杂度**：$O(30)$（位计数数组）；若采用「发位前缀」写法则另需 $O(k)$ 的 `vals` 数组。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxSum(vector<int>& nums, int k) {
        const int MOD = 1'000'000'007;
        const int B = 30;                          // nums[i] ≤ 1e9 < 2^30

        int cnt[B] = {0};
        for (int x : nums)
            for (int b = 0; b < B; b++)
                cnt[b] += (x >> b) & 1;            // 位库存（不变量）

        long long ans = 0;
        for (int i = 1; i <= k; i++) {             // 第 i 大的数
            long long v = 0;
            for (int b = 0; b < B; b++)
                if (cnt[b] >= i)
                    v |= 1LL << b;                 // 位 b 发给前 cnt[b] 个数
            ans = (ans + v * v) % MOD;             // v² < 2^60，边加边模
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, nums: List[int], k: int) -> int:
        MOD = 10**9 + 7
        B = 30                                   # nums[i] ≤ 1e9 < 2^30

        cnt = [0] * B
        for x in nums:
            for b in range(B):
                cnt[b] += x >> b & 1             # 位库存（不变量）

        ans = 0
        for i in range(1, k + 1):                # 第 i 大的数
            v = 0
            for b in range(B):
                if cnt[b] >= i:
                    v |= 1 << b                  # 位 b 发给前 cnt[b] 个数
            ans += v * v
        return ans % MOD
```

> 💡 等价的「发位前缀」写法：`vals = [0] * k` 保持降序，从 $b = 29$ 到 $0$ 把 `1 << b` 加到 `vals[:min(cnt[b], k)]` 的每个元素上（前缀同值加法保降序），最后 `sum(v * v for v in vals) % MOD`。两者都是嵌套链的直译。

## 8. 边界情况与易错点

1. **忘记取模 / 溢出**：$k \cdot v^2$ 可达 $10^5 \times 2^{60}$，C++ 必须边加边模（`ans = (ans + v * v % MOD) % MOD`）；Python 大整数不怕，但**返回前**要取模。
2. **「不操作」陷阱**：位能搬就搬，原数组的最大元素未必最优。反例 `nums = [8,1], k = 1`：直接选 8 得 64，而把 bit0 搬给 8 得 9，答案 **81**。同理**排序数组毫无意义**。
3. **位宽写错**：$10^9 < 2^{30}$，30 位足够；开 31/32 不影响正确性，但按十进制位数开 10 位会 WA。
4. **「同时更新」用旧值**：构造/模拟操作时若用新值连环覆盖会得出错误状态（贪心解法本身不受影响，因为它只读 $\text{cnt}$）。
5. **`1LL << b`**：C++ 中 `int` 移位在 $b \ge 31$ 时溢出，统一写 `1LL << b` 最稳。
6. **k = 1**：答案 $= (\text{OR of all nums})^2 \bmod p$，全部位聚成一个数，公式天然覆盖，无需特判。
7. **k = n**：此时 $\text{cnt}[b] \le n = k$，没有多余位浪费，每位都用满。
8. **函数名是 `maxSum`**：不是 `maxSumOfSquares`，抄错签名直接编译失败。
