# LeetCode 最小处理时间 题解

## 1. 题目概述

- **标题 / 题号**：最小处理时间（#2895，medium）
- **链接**：https://leetcode.cn/problems/minimum-processing-time/
- **来源**：LeetCode 第 366 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：$n$ 颗处理器各有 $4$ 个核心，共 $4n$ 个待执行任务，每个核心恰好执行一个任务。`processorTime[i]` 表示第 $i$ 颗处理器的**最早空闲时刻**，`tasks[j]` 表示任务 $j$ 的耗时；同一处理器的 $4$ 个核心并行、互不干扰。返回所有任务全部执行完毕的**最小时刻**。

**约束**：

- $1 \le n = \text{processorTime.length} \le 25000$
- $\text{tasks.length} = 4n \le 10^5$
- $0 \le \text{processorTime}[i] \le 10^9$
- $1 \le \text{tasks}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：processorTime = [8,10], tasks = [2,2,3,1,8,7,4,5]
输出：16
解释：最长的 4 个任务 [8,7,5,4] 分给 p = 8 的处理器 → 8 + 8 = 16；
     其余 [3,2,2,1] 分给 p = 10 的处理器 → 10 + 3 = 13。答案 = max(16, 13) = 16。
```

**示例 2**

```text
输入：processorTime = [10,20], tasks = [2,3,1,2,5,8,4,3]
输出：23
解释：最长的 4 个任务 [8,5,4,3] 分给 p = 10 → 18；
     其余 [3,2,2,1] 分给 p = 20 → 23。答案 = 23。
```

**示例 3**（自造对比样例）

```text
输入：processorTime = [0,100], tasks = [50,1,1,1,2,2,2,2]
输出：102
解释：逆序配对：max(0+50, 100+2) = 102；
     若同向配对（小任务给早空闲的处理器）：max(0+2, 100+50) = 150，明显更差。
```

## 3. 解题思路

### 3.1 暴力思路

枚举把 $4n$ 个任务切成 $n$ 组（每组 4 个）、再把各组分配给处理器的全部方案，取最小 max。方案数为 $\binom{4n}{4}\binom{4n-4}{4}\cdots\binom{4}{4}\cdot n!$，$n \le 25000$ 时是天文数字，完全不可行。

换一个角度看自由度：同组 $4$ 个任务共享 $p_i$ 且并行，完成时刻只由**组内最长任务**决定——每组只有一个「关键任务」。于是问题退化为：把 $4n$ 个任务切成 $n$ 组、每组 $4$ 个，最小化 $\max_i\bigl(p_i + \max(\text{组}_i)\bigr)$，是典型的 **min-max 配对**问题。

### 3.2 核心观察：逆序配对

![核心观察：逆序配对](images/min_proc_time_reverse_pairing.svg)

**观察一（组内归约）**：处理器 $i$ 的完成时刻 $= p_i + $ 组内最长任务，其余 $3$ 个任务不影响结果。

**观察二（交换不增）**：设 $p_a \le p_b$、$t_x \ge t_y$，则

$$\max(p_a + t_x,\ p_b + t_y)\ \le\ \max(p_a + t_y,\ p_b + t_x)$$

由 $p_a + t_x \le p_b + t_x$ 与 $p_b + t_y \le p_b + t_x$ 即得——把**长任务配早空闲的处理器**（左式）永远不会比反过来（右式）更差。直觉：最重的负担要交给最充裕的资源，才能压住最大值。

**结论**：`processorTime` **升序** + `tasks` **降序**，第 $i$ 小的处理器接降序数组的第 $i$ 块（4 个）：

$$\text{ans} = \max_{0 \le i < n} \bigl(\text{processorTime}[i] + \text{tasks}[4i]\bigr)$$

### 3.3 算法流程

1. `processorTime` 升序排序；
2. `tasks` 降序排序；
3. $i$ 从 $0$ 到 $n-1$：$\text{ans} = \max(\text{ans},\ p_i + \text{tasks}[4i])$；
4. 返回 `ans`。

降序数组的第 $i$ 块 $\{\text{tasks}[4i], \text{tasks}[4i+1], \text{tasks}[4i+2], \text{tasks}[4i+3]\}$ 恰好以组内最长任务 `tasks[4i]` 开头，因此每颗处理器只需读**一个**元素。

### 3.4 示例演算

![示例演算](images/min_proc_time_walkthrough.svg)

以示例 1 为例（$p$ 升序 $[8,10]$，任务降序 $[8,7,5,4,3,2,2,1]$）：

| 处理器 | $p_i$ | 分到的任务（第 $i$ 块） | 组内最长 | 完成时刻 |
|--------|-------|--------------------------|----------|----------|
| ① | 8 | $[8,7,5,4]$ | 8 | $8+8=\mathbf{16}$ |
| ② | 10 | $[3,2,2,1]$ | 3 | $10+3=13$ |

$\text{ans} = \max(16, 13) = 16$。

## 4. 算法细节

1. **方向是逆序**：$p$ **升序**配任务**降序**。「小配小、大配大」的同向配对是本题最常见 WA（反例见 §8）。
2. **只读 `tasks[4i]`**：组内其余 3 个任务被最长任务「淹没」，无需参与 max，也别对整块 4 个元素取最大。
3. **索引换算**：0 下标，第 $i$ 块首元素下标恰为 $4i$；Python 可直接用切片 `tasks[::4]` 一次取出全部块首。
4. **溢出贴边**：$p_i + t \le 10^9 + 10^9 = 2\times 10^9 < 2^{31}-1 \approx 2.147\times 10^9$，`int` 恰好安全，但余量不足 $8\%$——比赛中求稳可直接用 `long long`（Python 无此问题）。
5. **降序的两种写法**：C++ 用 `sort(tasks.begin(), tasks.end(), greater<int>())`；或将 `tasks` 升序、`processorTime` **降序**后同样取 `tasks[4i]`，两种写法等价。

## 5. 正确性证明

记 $p$ 升序为 $p_1 \le p_2 \le \cdots \le p_n$，任务降序为 $t_1 \ge t_2 \ge \cdots \ge t_{4n}$（$t_j$ 即降序数组第 $j$ 个元素）。

**引理 1（组内归约）**：任意方案下，分到任务组 $T_i$（$|T_i| = 4$）的处理器，完成时刻为 $p_i + \max T_i$。

**证明**：4 个核心独立并行，均从 $p_i$ 起跑各执行一个任务，最后结束的是耗时最长者。∎

**引理 2（鸽笼下界）**：对任意 $1 \le k \le n$ 与任意合法方案 $V$，有 $V \ge p_k + t_{4k-3}$。

**证明**：考虑最长的 $4k-3$ 个任务 $t_1, \ldots, t_{4k-3}$。每颗处理器只有 $4$ 个核心，故它们至少落在 $\lceil (4k-3)/4 \rceil = k$ 颗处理器上，设触及集合为 $S$，$|S| \ge k$。若 $S \subseteq \{1, \ldots, k-1\}$，则 $|S| \le k-1$，矛盾；故存在 $i \in S$ 且 $i \ge k$，即 $p_i \ge p_k$。处理器 $i$ 分到至少一个前 $4k-3$ 长的任务，故 $\max T_i \ge t_{4k-3}$。由引理 1，

$$V \ge p_i + \max T_i \ge p_k + t_{4k-3} \quad \square$$

**定理（贪心最优）**：`processorTime` 升序、`tasks` 降序后按块配对的贪心值 $G = \max_{1 \le i \le n}\,(p_i + t_{4i-3})$ 是最优解。

**证明**：贪心把降序任务按顺序切成大小为 4 的块，第 $i$ 块 $\{t_{4i-3}, t_{4i-2}, t_{4i-1}, t_{4i}\}$ 分给第 $i$ 小的处理器，组内最长恰为 $t_{4i-3}$，由引理 1 贪心值恰为 $G$。另一方面，由引理 2，任意方案 $V \ge \max_{1 \le k \le n}(p_k + t_{4k-3}) = G$。构造达到下界，故最优。∎

![鸽笼下界示意](images/min_proc_time_pigeonhole_proof.svg)

> 💡 交换不等式（§3.2）解释「为什么长任务该配早空闲的处理器」的直觉；鸽笼下界则一步给出与贪心值**完全匹配**的下界，两者互补，合起来即严格证明。

## 6. 复杂度分析

- **时间复杂度**：$O(m \log m)$，其中 $m = 4n \le 10^5$。两次排序占主导（$O(n\log n + m\log m)$），扫描仅 $O(n)$。
- **空间复杂度**：$O(1)$ 额外空间（原地排序，忽略排序递归栈 $O(\log m)$），仅常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minProcessingTime(vector<int>& processorTime, vector<int>& tasks) {
        sort(processorTime.begin(), processorTime.end());   // p 升序
        sort(tasks.begin(), tasks.end(), greater<int>());   // t 降序
        int ans = 0;
        for (int i = 0; i < (int)processorTime.size(); ++i) {
            ans = max(ans, processorTime[i] + tasks[4 * i]); // 组内最长即 tasks[4i]
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minProcessingTime(self, processorTime: List[int], tasks: List[int]) -> int:
        processorTime.sort()          # p 升序
        tasks.sort(reverse=True)      # t 降序
        # tasks[::4] 恰为每块首元素（组内最长任务）
        return max(p + t for p, t in zip(processorTime, tasks[::4]))
```

## 8. 边界情况与易错点

1. **配对方向搞反**（最常见 WA）：同向配对小配小，例如 $p = [0,100]$、任务降序 $[50,2,2,2,2,1,1,1]$ 时得 $150$ 而非 $102$。口诀：**要 max 最小，就逆序配对**。
2. **溢出贴边**：$p + t$ 最大 $2\times 10^9$，`int` 恰好不溢出（上限 $2147483647$），但余量不足 $8\%$；C++ 求稳可全程 `long long`。
3. **n = 1**：唯一处理器接全部 4 个任务，答案 $= p_1 + \max(\text{tasks})$，公式天然覆盖，无需特判。
4. **processorTime 可为 0**：不影响任何逻辑，无需特判。
5. **重复值**：大量相同的 $p$ 或任务耗时完全不影响，排序后任意交错等价，答案唯一。
6. **索引粗心**：块首下标是 $4i$ 不是 $i$；写成 `tasks[i]` 只会碰巧在 $n = 1$ 时通过。
