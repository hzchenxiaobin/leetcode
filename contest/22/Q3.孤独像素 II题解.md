# LeetCode 孤独像素 II 题解

## 1. 题目概述

- **标题 / 题号**：孤独像素 II（#533，medium）
- **链接**：https://leetcode.cn/problems/lonely-pixel-ii/
- **来源**：LeetCode 第 22 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、矩阵

**题意**：给定一个由 `'B'`（黑）与 `'W'`（白）组成的 $m \times n$ 图像 `picture`，以及正整数 $N$，统计满足下面两条规则的黑色像素 $(R, C)$ 的个数：

1. 第 $R$ 行与第 $C$ 列**都恰好**含有 $N$ 个黑色像素；
2. 第 $C$ 列上**所有**含有黑像素的行，都与第 $R$ 行逐格完全相同。

**约束**：

- $1 \le m, n \le 200$，图像最多 $4\times10^4$ 个格子
- `picture[i][j]` 只取 `'B'` 或 `'W'`
- $N$ 为正整数，即 $N \ge 1$
- 答案上界为 $m \times n = 4\times10^4$，不会溢出 32 位整数

## 2. 示例

**示例 1**

```text
输入：picture = [["W","B","W","B","B","W"],
                 ["W","B","W","B","B","W"],
                 ["W","B","W","B","B","W"],
                 ["W","W","B","W","B","W"]]
      target = 3
输出：6
解释：行 0/1/2 完全相同且各含 3 个黑像素，行 3 只含 2 个。
      列 1、列 3 各有 3 个黑像素且这些黑像素都在行 0/1/2 上，
      于是 (0,1)(1,1)(2,1) 与 (0,3)(1,3)(2,3) 共 6 个像素合规。
      列 4 虽然有 4 个黑像素（4 ≠ 3），整列作废。
```

**示例 2**

```text
输入：picture = [["W","W","B"],
                 ["W","W","B"],
                 ["W","W","B"]]
      target = 1
输出：0
解释：三行完全相同，但每行含 1 个黑像素、每列含 3 个黑像素。
      列 2 的黑像素数 3 ≠ target = 1，不满足规则一，故答案为 0。
```

## 3. 解题思路

### 3.1 暴力思路

逐个检查每个黑像素 $(R, C)$：先数第 $R$ 行、第 $C$ 列的黑像素个数，再扫描「第 $C$ 列上所有含黑像素的行」与第 $R$ 行逐格比较。单次检查 $O(mn)$，总计 $O(m^2 n^2)$；$m=n=200$ 时约 $1.6\times10^{9}$ 次字符比较，超时。

即便把行比较优化到 $O(1)$，仍要对 $m \times n$ 个像素各做一次判定。真正的问题是：**同一个像素的判定被重复计算了**——整列的黑像素结论完全一样。

### 3.2 核心观察：判定按列分解 + 行签名

![核心观察：合规列整列计数](images/wc22_q3_column_decomposition.svg)

**观察 1（整列同命）**：规则二只涉及「第 $C$ 列上含黑像素的行」，与具体是哪个像素无关。因此对固定的列 $C$，要么**该列每个黑像素都合规**，要么**该列一个都不合规**。于是答案可以按列累加：

$$ans = \sum_{C \text{ 合规}} colCnt[C]$$

其中 $colCnt[C]$ 是第 $C$ 列的黑像素个数。

**观察 2（合规列的三条判据）**：列 $C$ 合规 $\iff$ 下面三条同时成立：

1. $colCnt[C] = N$（规则一的列部分）；
2. 第 $C$ 列上所有含黑像素的行，其行字符串**两两相同**（规则二；它们当然与其中任意一行相同，包括 $R$）；
3. 这个公共行的黑像素个数 $= N$（规则一的行部分）。

**观察 3（行签名）**：判据 2 只需比较整行是否相等。把每一行映射成一个整数 **签名** $sig[i]$：相同的行给出相同的 id。之后两行相等 $\iff$ $sig$ 相等，比较从 $O(n)$ 降到 $O(1)$；由于公共行只有一个，判据 3 只需查一次。

> 💡 关键点：一列一旦通过判据，贡献的是 $colCnt[C]$（即 $N$）个像素，而不是 1 个。示例 1 的答案 6 正是「2 列 × 每列 3 个」。

### 3.3 算法流程

![算法流程：行签名 + 行列计数，逐列双重校验](images/wc22_q3_signature_flow.svg)

1. 一次遍历统计 $rowCnt[i]$ 与 $colCnt[j]$，并顺手把每行转成字符串。
2. 为每行求签名 id（相同字符串 → 同一 id）。
3. 枚举每一列 $c$：先用最便宜的 $colCnt[c] = N$ 剪枝（绝大多数列在此被淘汰）。
4. 扫描该列的 $m$ 行，记录第一个黑像素所在行的签名 `canon`；若后面出现不同签名，立刻放弃该列。
5. 若 `canon` 对应的行黑数 $= N$，则 $ans \leftarrow ans + colCnt[c]$。
6. 所有列处理完，返回 $ans$。

整体只需常数遍矩阵扫描，$O(mn)$。

### 3.4 示例演算

![示例 1 演算：逐列判定表](images/wc22_q3_walkthrough.svg)

对示例 1（$4 \times 6$，$N = 3$）逐列走一遍：

1. **列 0、列 5**：$colCnt = 0 \ne 3$，第 3 步直接淘汰，贡献 0。
2. **列 2**：只有行 3 含黑像素，$colCnt = 1 \ne 3$，第一关淘汰；而且行 3 只有 2 个黑像素，规则一的行部分同样不满足。
3. **列 1、列 3**：$colCnt = 3 = N$；含黑像素的行是 $\{0,1,2\}$，三者行字符串全等；公共行黑数 $3 = N$。两条规则成立，各贡献 3。
4. **列 4**：$colCnt = 4 \ne 3$，虽然含黑像素的行也是 $\{0,1,2,3\}$ 且前 3 行相同，但规则一先失败，整列作废。

最终 $ans = 0+3+0+3+0+0 = 6$，与官方输出一致。

## 4. 算法细节

1. **按列而不是按像素做外层循环**：外层枚举列，内层只扫该列的 $m$ 个格子，总工作量恰为 $m \times n$，不存在重复判定。
2. **剪枝顺序**：先查 $colCnt[c] = N$（$O(1)$），再查行签名（最多 $O(m)$），最后查行黑数（$O(1)$）。把最便宜的判断放最前面，绝大多数列在第一关就被淘汰。
3. **行签名实现**：C++ 用 `unordered_map<string,int>` 给不同行编号；Python 直接拿行字符串（`''.join(row)`）当键，用 `dict` 编号，或用 `set` + 首次出现下标。
4. **只需记录一个公共行**：判据 2 只要求「全部相同」，所以拿第一个黑像素所在行当基准，后续任一不同即失败；同时把它的 `rowCnt` 存下来，判据 3 复用。
5. **累加的是 `colCnt[c]` 而不是 1**：通过判据时该列每个黑像素都算一个答案，漏掉这一步会得到「合规列数」而不是「合规像素数」。
6. **空列防御**：若 $N$ 允许为 0，$colCnt[c] = 0$ 时该列没有黑像素，公共行不存在，必须跳过（代码里用 `canon == -1` / `sig is None` 判断），否则会访问无效下标。
7. **字符比较与字符串构造**：行字符串在预处理阶段构造一次即可，循环内不要再切片；C++ 传参是 `vector<vector<char>>`，比较时用 `'B'` 字面量。

## 5. 正确性证明

**引理 1（整列同命）**：对固定的列 $C$，若它满足「$colCnt[C] = N$、列上含黑像素的行全部相同、公共行黑数为 $N$」这三条，则该列的每个黑像素都合规；反之，只要该列有一个黑像素合规，则这三条都成立。

**证明**：

- ($\Rightarrow$) 任取该列黑像素 $(R', C)$。由条件 $colCnt[C] = N$；又 $R'$ 属于该列含黑像素的行集合，集合中每行都等于公共行、公共行黑数为 $N$，故 $rowCnt[R'] = N$。规则二方面，该列所有含黑像素的行都等于公共行，因而都与 $R'$ 所在行相同。所以 $(R', C)$ 合规。
- ($\Leftarrow$) 设 $(R, C)$ 合规。规则一给出 $colCnt[C] = N$ 且 $rowCnt[R] = N$；规则二给出该列所有含黑像素的行都等于行 $R$，故它们两两相同、公共行黑数为 $N$。∎

**引理 2（判定精确）**：对每一列，算法的三条判据同时成立 $\iff$ 该列合规（即引理 1 的三个条件）。

**证明**：判据 1 直接比较 $colCnt[c]$ 与 `target`；判据 2 用签名 id 比较行是否相等，而签名由完整行字符串确定，故 `canon` 全程不变 $\iff$ 该列所有含黑像素的行字符串相同；判据 3 取公共行的 `rowCnt` 与 `target` 比较。三条都是必要条件且合起来充分，故等价。∎

**定理**：算法返回的整数等于满足两条规则的黑色像素总数。

**证明**：设合规列的集合为 $\mathcal{S}$。由引理 1，答案 $=\sum_{C \in \mathcal{S}} colCnt[C]$，且各列像素集合互不相交。由引理 2，算法累加的列恰好是 $\mathcal{S}$，每列累加 $colCnt[C]$，故累计值等于答案。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。统计行列黑数 $O(mn)$；构造行字符串并求签名 $O(mn)$（字符串哈希均摊 $O(1)$ 每次比较）；枚举列时每列最多扫 $m$ 行，共 $O(mn)$。总计一次线性扫描量级。
- **空间**：$O(mn)$ 存行字符串（也可只存每行的哈希值，降到 $O(m)$）；$rowCnt$、$colCnt$ 各 $O(m)$、$O(n)$；签名表最多 $m$ 个不同行，故 $O(m)$。整体 $O(mn)$，$m,n \le 200$ 时不超过几十 KB。

## 7. 参考代码

### C++

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int findBlackPixel(vector<vector<char>>& picture, int target) {
        int m = picture.size();
        if (m == 0) return 0;
        int n = picture[0].size();

        vector<int> rowCnt(m, 0), colCnt(n, 0);
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (picture[i][j] == 'B') { rowCnt[i]++; colCnt[j]++; }

        // 行签名：相同字符串的行拿到同一个 id
        unordered_map<string, int> id;
        vector<int> rid(m);
        for (int i = 0; i < m; i++) {
            string s(picture[i].begin(), picture[i].end());
            auto it = id.find(s);
            if (it == id.end()) {
                int k = (int)id.size();
                id[s] = k;
                rid[i] = k;
            } else {
                rid[i] = it->second;
            }
        }

        int ans = 0;
        for (int c = 0; c < n; c++) {
            if (colCnt[c] != target) continue;      // 规则一（列）：最便宜的剪枝
            int canon = -1, firstRow = -1;
            bool ok = true;
            for (int i = 0; i < m && ok; i++) {
                if (picture[i][c] != 'B') continue;
                if (canon == -1) { canon = rid[i]; firstRow = i; }
                else if (rid[i] != canon) ok = false;   // 该列各行不全同
            }
            if (!ok || canon == -1) continue;       // 空列或签名不一致
            if (rowCnt[firstRow] != target) continue;   // 规则一（行）
            ans += colCnt[c];                       // 整列黑像素全部合规
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findBlackPixel(self, picture: List[List[str]], target: int) -> int:
        if not picture or not picture[0]:
            return 0
        m, n = len(picture), len(picture[0])

        rows = [''.join(r) for r in picture]        # 行签名：整行字符串
        row_cnt = [r.count('B') for r in rows]
        col_cnt = [0] * n
        for r in rows:
            for j, ch in enumerate(r):
                if ch == 'B':
                    col_cnt[j] += 1

        ans = 0
        for c in range(n):
            if col_cnt[c] != target:                # 规则一（列）：先做剪枝
                continue
            sig = None
            common_row_cnt = -1
            ok = True
            for i in range(m):
                if rows[i][c] != 'B':
                    continue
                if sig is None:
                    sig, common_row_cnt = rows[i], row_cnt[i]
                elif rows[i] != sig:                # 该列各行不全同
                    ok = False
                    break
            if not ok or sig is None:               # 空列或签名不一致
                continue
            if common_row_cnt != target:            # 规则一（行）
                continue
            ans += col_cnt[c]                       # 整列黑像素全部合规
        return ans
```

## 8. 边界情况与易错点

1. **答案按像素而非按列计数**：通过判据的列要加 $colCnt[c]$（$=N$）。若误写成 `ans += 1`，示例 1 会输出 2。
2. **两处黑像素数都要校验**：$3\times3$ 全 `"WWB"` 且 $N=1$ 时，三行完全相同但该列有 3 个黑像素，规则一（列）先失败，答案 0；反过来 $3\times2$ 全 `'B'` 且 $N=3$ 时，两列黑像素数都等于 3、三行也全同，可每行只有 2 个黑像素，必须靠判据 3（行黑数）拦下，答案同样是 0。缺任何一条判据都会算错。
3. **单行 / 单列**：$m=1$ 时「所有含黑像素的行」只有一行，判据 2 恒真，只要 $colCnt[c] = rowCnt[0] = N$ 就整行计入；$1\times1$ 的 `"B"` 且 $N=1$ 答案为 1。
4. **全白图像**：$colCnt$ 全为 0，$N \ge 1$ 时全部被首关淘汰，答案 0；若实现里允许 $N=0$，务必跳过没有黑像素的列，避免用 `-1` 索引 `rowCnt`。
5. **不规则输入**：题目保证矩形，但工程实现里 `picture` 为空时要直接返回 0，不要访问 `picture[0].size()`（C++ 代码里已有此防御）。
6. **字符类型与比较**：LeetCode 传的是 `vector<vector<char>>`，比较对象是字符 `'B'`，不要写成字符串 `"B"`，否则编译不过或语义出错。
