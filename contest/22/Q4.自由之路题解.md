# LeetCode 自由之路 题解

## 1. 题目概述

- **标题 / 题号**：自由之路（#514，hard）
- **链接**：https://leetcode.cn/problems/freedom-trail/
- **来源**：LeetCode 第 22 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、广度优先搜索、字符串、动态规划

**题意**：字符串 `ring` 刻在一个可以正反转动的圆环上，12:00 方向有一个固定指针，初始时 `ring[0]` 正对指针。要按顺序拼出 `key` 的每个字符：先把某个等于 `key[i]` 的位置转到 12:00（每转动一格记 1 步），再按下中心按钮（也记 1 步），随后才能拼下一个字符。求拼完整个 `key` 的**最少总步数**。

**约束**：

- $1 \le \lvert ring \rvert, \lvert key \rvert \le 100$
- `ring` 与 `key` 只含小写英文字母
- 保证 `key` 一定能由 `ring` 旋转拼出（即 `key` 中每个字符都在 `ring` 中出现过）

## 2. 示例

**示例 1**

```text
输入：ring = "godding", key = "gd"
输出：4
解释：'g' 已在 12:00，按键 1 步 ⇒ 1；
      再把 'd'（下标 2）逆时针转 2 步到位，按键 1 步 ⇒ 2 + 1；
      合计 1 + 3 = 4。
```

**示例 2**

```text
输入：ring = "godding", key = "godding"
输出：13
解释：g→o→d→d→i→n→g 逐字符累加，
      最优路径为 0 → 1 → 2 → 2 → 4 → 5 → 6（位置下标），
      总代价 1+2+2+1+3+2+2 = 13。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「枚举每个 `key[i]` 选哪个同名字符位置」：设 `ring` 中字符 $c$ 出现 $occ(c)$ 次，则路径总数为 $\prod_i occ(key[i])$，最坏 $100^{100}$，完全不可行。即便加上 DFS + 记忆化，也要先想清楚「状态该记什么」，否则会把「已经转过的角度」也记进状态，导致状态爆炸。

另一条同样正确的路是**状态图上的 BFS**：状态取 $(i, j)$（已拼好 `key[:i]`，12:00 对着 `ring[j]`），边有三条——顺时针转一格、逆时针转一格、以及在 `ring[j] = key[i]` 时按键进入 $(i+1, j)$，边权全为 1，于是 BFS 一遍就是 $O(\lvert key \rvert \cdot \lvert ring \rvert)$。它足够快（本文的对拍程序就用它），但需要为「逐格旋转」显式建边；而按「字符出现位置」跳跃的 DP 更贴合题意，也是官方思路，且能自然推广到「按键代价随字符变化」的变体。

### 3.2 核心观察：环上最短弧 + 位置层 DP

![环形状态：dp 状态只需记住 12:00 对着哪个位置](images/wc22_q4_ring_state_concept.svg)

三个观察把问题压成一个小 DP：

1. **无后效性**：拼完 `key` 的某个前缀后，未来的代价只取决于「现在 12:00 正对哪个位置 $j$」，与之前是怎么转到 $j$ 的无关。于是状态只需 $(i, j)$。
2. **环上最短弧**：从位置 $k$ 转到位置 $j$，正转要走 $\lvert j-k \rvert$ 格，反转要走 $n-\lvert j-k \rvert$ 格，最短为
   $$\operatorname{dist}(k,j)=\min\bigl(\lvert j-k\rvert,\; n-\lvert j-k\rvert\bigr)$$
3. **只保留匹配位置**：只有 `ring[j] = key[i]` 的位置才可能出现在第 $i$ 层，其余位置的 dp 值恒为 $+\infty$。这一条把每层 $\lvert ring \rvert$ 个状态压缩到 $occ(key[i])$ 个。

由此定义

$$dp[i][j] = \text{拼完 } key[0..i] \text{ 且 12:00 正对 } ring[j] \text{ 的最少总步数}$$

初值（起点固定在 `ring[0]`，`key[0]` 可以选任意同名位置）：

$$dp[0][j]=\operatorname{dist}(0,j)+1,\qquad ring[j]=key[0]$$

转移（先从某个 $k$ 转到 $j$，再按键付 1 步）：

$$dp[i][j]=\min_{k:\;ring[k]=key[i-1]}\Bigl\{dp[i-1][k]+\operatorname{dist}(k,j)+1\Bigr\},\qquad ring[j]=key[i]$$

答案为最后一层的最小值 $\min_j dp[m-1][j]$。

### 3.3 算法流程 / 状态转移

![分层转移：每层只保留匹配位置，层间用环形距离松弛](images/wc22_q4_dp_flow.svg)

1. **预处理位置表**：`pos[c]` 存字符 $c$ 在 `ring` 中所有下标，共 $O(n)$。
2. **第 0 层**：对每个 $j \in pos[key[0]]$ 置 $dp[j]=\operatorname{dist}(0,j)+1$，其余为 $+\infty$。
3. **逐层推进**：对 $i=1..m-1$，遍历 $j \in pos[key[i]]$，在上一层有限状态 $k \in pos[key[i-1]]$ 上取最小值，加 $\operatorname{dist}(k,j)+1$ 写入 $ndp[j]$。
4. **滚动数组**：只保留上一层的 $dp$ 与当前层的 $ndp$，空间从 $O(mn)$ 降到 $O(n)$。
5. **收尾**：返回 $\min_{j \in pos[key[m-1]]} dp[j]$。

整个算法就是在这张「层 × 位置」的分层图上做一次最短路松弛，每层的边只从 `key[i-1]` 的出现位置连向 `key[i]` 的出现位置；灰色虚线是被 $\min$ 淘汰的候选边。

### 3.4 示例演算

![逐层 dp 演算表：ring = "godding", key = "godding"](images/wc22_q4_walkthrough.svg)

以 `ring = "godding"`（$n=7$，下标 0..6 对应 `g o d d i n g`）为例：

| 层 $i$ | `key[i]` | 可达位置 $j$ 及其 dp 值 | 代价来源 |
|--------|----------|--------------------------|----------|
| 0 | `g` | $j=0:1$，$j=6:2$ | $\min(0,7)+1$；$\min(6,1)+1$ |
| 1 | `o` | $j=1:3$ | $1\to1$ 走 1 格，$1+1+1$ |
| 2 | `d` | $j=2:5$，$j=3:6$ | $1\to2$ 走 1 格 $\Rightarrow 5$；$1\to3$ 走 2 格 $\Rightarrow 6$ |
| 3 | `d` | $j=2:6$，$j=3:7$ | 同字符再按一次，原地各 $+1$ |
| 4 | `i` | $j=4:9$ | $2\to4$ 走 2 格：$6+2+1=9$ |
| 5 | `n` | $j=5:11$ | $4\to5$ 走 1 格：$9+1+1=11$ |
| 6 | `g` | $j=0:14$，$j=6:13$ | $5\to6$ 逆行 1 格：$11+1+1=13$ |

最后一层取最小值得到 $13$，与示例 2 一致。

若 `key = "gd"`，则只需前两层：$dp_0=\{0{:}1,\,6{:}2\}$，$dp_1=\{2{:}4,\,3{:}5\}$，答案为 $\min(4,5)=4$，与示例 1 一致。注意 $i=2$ 那一行的两个 dp 值恰好在不同的来源上「交叉」，这正是必须保留整层所有候选位置、而不能只贪心留一个最小值的原因。

## 4. 算法细节

1. **初值不要漏掉按键的那 1 步**：$dp[0][j]=\operatorname{dist}(0,j)+1$，末尾的 $+1$ 是首次按键；漏掉它会使答案整体少 $m$。
2. **环上距离的写法**：`d = abs(j - k)`，取 `min(d, n - d)`。$n=1$ 时 `n-d = 0`，结果仍是 0，无需特判。
3. **用位置表而不是全表扫描**：`pos[26]` 让内层循环只跑 $occ(key[i-1])$ 次；最坏 $n^2=10^4$ 每层，$m\le100$ 时总转移数不超过 $10^6$。
4. **滚动数组**：`ndp` 每层重新初始化为 $+\infty$，只写匹配位置；用 `swap` 交换后旧的 `ndp` 自动被覆盖，无需清零。
5. **无穷大的选择**：`dp` 上界约为 $100 \times 51 = 5100$，取 `INF = 1e9` 后用 `int` 完全安全；C++ 里判断 `dp[k] >= INF` 可跳过不可达的 $k$（虽然遍历 `pos[key[i-1]]` 时它们本就可达，防御性保留更稳）。
6. **不要真的旋转字符串**：把 `ring` 转成 `ddinggo` 之类的做法每次代价 $O(n)$ 且极易写错取模；直接用下标 + 环形距离即可。
7. **答案取最后一层的最小值**：拼完 `key[m-1]` 后指针停在哪个位置都算完成，不能固定取某个下标。

## 5. 正确性证明

**引理 1（环上最短距离）**：在一个 $n$ 个位置的圆环上，从 $k$ 到 $j$ 的最少旋转步数为 $\operatorname{dist}(k,j)=\min(\lvert j-k\rvert, n-\lvert j-k\rvert)$。

**证明**：任何旋转序列都可以把「正转格数」与「反转格数」相互抵消，故净效果等价于正转 $t$ 格或反转 $t$ 格，其中 $t$ 为正整数。正转到 $j$ 需要 $j-k \equiv t \pmod n$ 且 $t \ge 0$，最小非负解为 $t_1 = (j-k) \bmod n$；反转同理得到 $t_2 = (k-j) \bmod n = n - t_1$（当 $t_1>0$）。两者是全部可行解中最小的两个代表，因此最短步数为 $\min(t_1, t_2)=\min(\lvert j-k\rvert, n-\lvert j-k\rvert)$。$t_1=0$ 时 $t_2$ 退化为 $0$，公式仍成立。∎

**引理 2（最优子结构）**：设拼完 `key[0..i]` 且停在 $j$ 的最优方案为 $S$，它上一步停在 $k$，则 $S$ 在拼完 `key[0..i-1]` 后停在 $k$ 的那段前缀，本身是「拼完 `key[0..i-1]` 且停在 $k$」的最优方案。

**证明**：反证。若存在更短的方案 $S'$ 拼完 `key[0..i-1]` 并停在 $k$，则把 $S'$ 与 $S$ 中「从 $k$ 转到 $j$ 再按键」的后缀拼接，得到一个总步数更小的合法方案，与 $S$ 的最优性矛盾。∎

**引理 3（状态充分性）**：拼完 `key[:i]` 之后，剩余问题的最优代价只由「12:00 正对的 `ring` 下标 $j$」与「剩余字符 `key[i:]`」决定，与到达 $j$ 的历史无关。

**证明**：可执行的操作只依赖于当前对齐位置（能转到哪些位置、能否按键），环的形态固定且不发生任何变化，历史旋转不留下副作用。故两个到达同一 $j$ 的历史在后续拥有完全相同的可行操作集合与代价函数。∎

**定理**：对任意 $i \in [0, m)$ 与任意 $j$ 满足 `ring[j] = key[i]`，上述 dp 值 $dp[i][j]$ 等于拼完 `key[0..i]` 且停在 $j$ 的最少总步数。

**证明**：对 $i$ 归纳。

- $i=0$：唯一可能的操作是从起点 0 转到 $j$ 再按一次键，由引理 1 代价为 $\operatorname{dist}(0,j)+1$，与初值一致。
- 设 $i-1$ 成立。任一合法方案拼完 `key[0..i]` 停在 $j$，其最后一步必然是从某个 $k$（`ring[k] = key[i-1]`）转到 $j$ 并按键。该方案总代价 $=$「拼完 `key[0..i-1]` 停在 $k$ 的代价」$+\operatorname{dist}(k,j)+1$。由引理 2 前半段可换成最优前缀，由归纳假设它 $\ge dp[i-1][k]$，故总代价 $\ge dp[i-1][k] + \operatorname{dist}(k,j) + 1 \ge dp[i][j]$（转移取的是所有 $k$ 的最小值），即 $dp[i][j]$ 是下界。
- 另一方面，取使转移取到最小值的 $k^*$，把「$dp[i-1][k^*]$ 对应的最优方案」+「由引理 1 的最短弧转到 $j$」+「按键」拼起来，是一个合法方案，代价恰为 $dp[i][j]$，故下界可达。

两者合并，$dp[i][j]$ 就是最少总步数。∎

**推论**：答案为 $\min_{j:\;ring[j]=key[m-1]} dp[m-1][j]$，因为拼完最后一个字符后指针可停在任意匹配位置。

## 6. 复杂度分析

- **时间**：$O\bigl(\lvert key \rvert \cdot \lvert ring \rvert^2\bigr)$ 为上界；更紧的界是逐层转移数之和 $\sum_{i=1}^{m-1} occ(key[i-1]) \cdot occ(key[i])$。预处理位置表 $O(n)$。取 $n=m=100$ 时约 $10^6$ 次基本运算，远低于限制。
- **空间**：$O(n)$。两层滚动数组各 $n$ 个 `int`，位置表 $O(n)$；若不用滚动数组则为 $O(mn)$，仍在 $10^4$ 量级。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findRotateSteps(string ring, string key) {
        int n = ring.size();
        vector<vector<int>> pos(26);
        for (int j = 0; j < n; j++) pos[ring[j] - 'a'].push_back(j);

        const int INF = 1e9;
        vector<int> dp(n, INF);
        for (int j : pos[key[0] - 'a'])
            dp[j] = min(j, n - j) + 1;          // 起点 ring[0] 转到 j，再按一次键

        for (int i = 1; i < (int)key.size(); i++) {
            vector<int> ndp(n, INF);
            for (int j : pos[key[i] - 'a']) {
                int best = INF;
                for (int k : pos[key[i - 1] - 'a']) {
                    if (dp[k] >= INF) continue;
                    int d = abs(j - k);
                    best = min(best, dp[k] + min(d, n - d) + 1);   // 旋转 + 按键
                }
                ndp[j] = best;
            }
            dp.swap(ndp);
        }

        int ans = INF;
        for (int j : pos[key.back() - 'a']) ans = min(ans, dp[j]);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findRotateSteps(self, ring: str, key: str) -> int:
        n = len(ring)
        pos = {}
        for j, ch in enumerate(ring):
            pos.setdefault(ch, []).append(j)

        INF = float('inf')
        dp = {j: min(j, n - j) + 1 for j in pos[key[0]]}

        for ch in key[1:]:
            ndp = {}
            for j in pos[ch]:
                best = INF
                for k, val in dp.items():
                    d = abs(j - k)
                    cand = val + min(d, n - d) + 1
                    if cand < best:
                        best = cand
                ndp[j] = best
            dp = ndp

        return min(dp.values())
```

## 8. 边界情况与易错点

1. **`ring` 只有 1 个字符**（`ring = "a"`，`key = "aaa"`）：环形距离恒为 0，答案应为 $m=3$（每次按键 1 步）。公式中 `min(d, n-d)` 在 $n=1$ 时给出 0，无需特判。
2. **`key` 全为同一字符**：可能出现在同一位置连续按键多次的情况，此时每层转移代价为 $0+1$，答案 $= \operatorname{dist}(0,j)+(m-1)+1$；若代码误把「同一位置」判为无效会算大。
3. **起点就在 $j$ 上**：$dp[0][0]=1$（转 0 步 + 按键 1 步），不能写成 0。
4. **`n` 为偶数、目标在正对面**（$j-k=n/2$）：两个方向等长，`min(d, n-d)` 两条路都对；不要写成 `d` 而与 `n-d` 比较时漏掉等号一侧的取值。
5. **不可达状态**：若某层某个位置从未被写入，其值应为 $+\infty$；滚动时若不重置 `ndp`，上一层的旧值会「穿越」到下一层造成错误。
6. **别把「拼完」判断提前**：只有 `key` 全部拼完才结束，中途某层只剩一个候选位置也不能提前终止（后续字符仍可能需要绕远路）。
7. **答案取 `min` 而非固定下标**：`dp[n-1]` 或 `dp[0]` 都是错的，最终停在哪个匹配位置由最优路径决定。

**延伸思考**：

1. **更快的等价写法**：在 $(i, j)$ 状态图上做 BFS（旋转 $\pm1$ 与按键三条边，权值均为 1），复杂度 $O(mn)$，比本文的 $O(mn^2)$ 更优；因为所有边权相同，甚至连 Dijkstra 都不需要。本文保留 DP 写法，是因为它在「按键代价随字符变化」「旋转代价按角度非线性」等变体下仍然直接可用。
2. **带权变体**：若旋转一格代价为 $w_1$、按键代价为 $w_2$（甚至与字符有关），只需把 $\operatorname{dist}(k,j)$ 与按键的 $+1$ 换成对应权值，DP 不变；此时 BFS 失效，必须用 Dijkstra 或本 DP。
3. **规模放大**：若 $\lvert ring \rvert$ 达到 $10^5$、$\lvert key \rvert$ 达到 $10^5$，逐对枚举出现位置会退化。可以对「同一层的候选位置集合」做环形排序 + 单调队列/前缀最小值优化，把每层松弛降到 $O(occ \log occ + occ)$。
