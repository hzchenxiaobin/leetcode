# LeetCode 孤独像素 I 题解

## 1. 题目概述

- **标题 / 题号**：孤独像素 I（#531，medium）
- **链接**：https://leetcode.cn/problems/lonely-pixel-i/
- **来源**：LeetCode 第 22 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、矩阵

**题意**：给定 $m \times n$ 的字符矩阵 `picture`，元素只有 `'B'`（黑）与 `'W'`（白）。一个黑格 $(i,j)$ 称为**孤独像素**，当且仅当它所在的第 $i$ 行与第 $j$ 列中**没有其他黑格**（即该行黑格总数与列黑格总数都为 1）。返回孤独黑色像素的个数。

**约束**：

- 矩阵的宽与高均在 $[1, 500]$ 内，即 $1 \le m, n \le 500$
- 元素只含 `'B'` 与 `'W'`
- 格子总数不超过 $2.5 \times 10^{5}$：允许 $O(mn)$ 的扫描，但不允许对每个黑格再扫一遍它的行列

## 2. 示例

**示例 1**

```text
输入：picture = [["W","W","B"],
                 ["W","B","W"],
                 ["B","W","W"]]
输出：3
解释：三个 'B' 分别位于 (0,2)、(1,1)、(2,0)；
      每一行、每一列都只有一个黑格，因此三个都是孤独像素。
```

**示例 2**

```text
输入：picture = [["B","B","B"],
                 ["B","B","W"],
                 ["B","B","B"]]
输出：0
解释：每一行至少有两个 'B'，任取一个黑格都能在同行找到另一个黑格，故没有孤独像素。
```

**补充示例（便于核对边界）**

```text
输入：picture = [["B","W"]]
输出：1
解释：全图只有一个黑格，它的行与列都没有其他黑格。
```

## 3. 解题思路

### 3.1 暴力思路

对每个黑格 $(i,j)$ 分别扫描第 $i$ 行与第 $j$ 列，确认其中没有别的黑格：单次判定 $O(m+n)$，总计 $O\bigl(mn(m+n)\bigr)$。$m=n=500$ 时约 $2.5\times 10^{8}$ 次比较，C++ 勉强、Python 必然超时。更致命的是**同一行被重复扫描了 $O(n)$ 次**：一份可以复用的信息被反复重算，这是典型的「查询多、预处理少」。

### 3.2 核心观察：孤独性只由两个一维计数决定

![孤独像素的行列计数判定](images/wc22_q2_row_col_concept.svg)

记 `rowCnt[i]` 为第 $i$ 行的黑格数、`colCnt[j]` 为第 $j$ 列的黑格数。因为黑格自身已经被计入，所以对任意黑格 $(i,j)$ 有

$$(i,j) \text{ 是孤独像素} \iff \text{rowCnt}[i] = 1 \ \wedge\ \text{colCnt}[j] = 1$$

于是「同行 / 同列还有没有别的黑格」这类**海量重复查询**被压成**一次预处理**：$O(mn)$ 扫一遍求出两个计数数组，此后每个格子的判定都是 $O(1)$，总复杂度 $O(mn)$。

> 💡 题目标签里的「哈希表」指的是「按行号 / 列号分桶计数」这一思想。由于行号、列号分别是 $[0,m)$、$[0,n)$ 上的紧凑整数，直接用数组比哈希表更快、常数更小。

### 3.3 算法流程

![两遍扫描流程](images/wc22_q2_flow.svg)

**第 1 遍（统计）**：枚举所有格子，遇到 `'B'` 就执行 `rowCnt[i]++` 与 `colCnt[j]++`。

**第 2 遍（判定）**：枚举每一行 $i$。若 `rowCnt[i] != 1` 则整行跳过（这一行要么没有黑格，要么至少有两个，都不可能产生孤独像素）；否则找出该行唯一的黑格所在列 $j$，检查 `colCnt[j] == 1`，成立则答案加一。

行筛选是关键剪枝：`rowCnt[i] == 1` 的行里黑格唯一，找到即可 `break`，第 2 遍的实际工作量远小于 $mn$；但复杂度上界仍按 $mn$ 计。

### 3.4 示例演算

![两个示例的行列计数走查](images/wc22_q2_walkthrough.svg)

**示例 1**：$m = n = 3$。

| 行 $i$ | 该行黑格所在列 | `rowCnt[i]` | `colCnt` | 第 2 遍判定 |
|--------|----------------|-------------|----------|-------------|
| 0 | 2 | 1 | `[1,1,1]` | `colCnt[2]=1` → ans = 1 |
| 1 | 1 | 1 | `[1,1,1]` | `colCnt[1]=1` → ans = 2 |
| 2 | 0 | 1 | `[1,1,1]` | `colCnt[0]=1` → ans = 3 |

三个候选全部通过，答案 3。

**示例 2**：统计得 `rowCnt = [3,2,3]`、`colCnt = [3,3,2]`。没有任何一行的计数等于 1，第 2 遍在**行筛选阶段**就跳过了全部行，答案 0——列计数根本没机会参与判定。

## 4. 算法细节

1. **两遍扫描不可合并**：判定依赖完整的行列计数，必须等统计结束后再做第二遍；边统计边判定会用到「尚未计完」的 `colCnt`，结果偏大。
2. **先按行筛选，再按列定案**：`rowCnt[i] != 1` 的行整行跳过，这是把平均工作量压下去的主要剪枝；最坏情况（如对角线全黑）仍然是 $O(mn)$。
3. **`picture[i][j] == 'B'` 不能省**：只判 `colCnt[j] == 1` 会把白格也算进去。例如示例 1 的白格 $(0,0)$，其所在行、列都只有一个黑格，省掉字符判断就会多算。
4. **找到唯一黑格立即 `break`**：`rowCnt[i] == 1` 保证行内黑格唯一，取到即可停止扫描该行；平均能省掉近一半的无效比较。
5. **计数数组用原生数组或 `vector`**：行号、列号是连续整数，下标本身就是哈希函数；$m, n \le 500$，额外开销可忽略。
6. **Python 不要用 `zip(*picture)` 求列计数**：转置会复制 $O(mn)$ 个元素，既费内存又慢，直接双重循环累加更划算。
7. **不要在循环里调用 `sum(row == 'B')` 之类的切片统计**：那会把第一遍退化成 $O(mn^{2})$；一次遍历同时维护两个数组即可。
8. **空间不必再优化**：$O(m+n)$ 已经是这个框架下的自然量级，把计数编码进矩阵虽然有 $O(1)$ 额外空间的写法，但会破坏可读性，赛时不值得。

## 5. 正确性证明

**引理 1（计数刻画）**：设 $(i,j)$ 为黑格，则 $(i,j)$ 是孤独像素，当且仅当 $\text{rowCnt}[i] = 1$ 且 $\text{colCnt}[j] = 1$。

**证明**：

- （$\Rightarrow$）若 $(i,j)$ 是孤独像素，则第 $i$ 行除 $(i,j)$ 外没有黑格，而 $(i,j)$ 自身是黑格，故该行黑格数恰为 1，即 $\text{rowCnt}[i] = 1$；对列同理得 $\text{colCnt}[j] = 1$。
- （$\Leftarrow$）若 $\text{rowCnt}[i] = 1$ 且 $(i,j)$ 是黑格，则该行唯一的黑格就是 $(i,j)$，不存在「其他黑格」；列同理。故 $(i,j)$ 是孤独像素。∎

**引理 2（行筛选不漏解）**：第 2 遍只枚举满足 $\text{rowCnt}[i] = 1$ 的行，仍然检查到了所有孤独像素。

**证明**：设 $(i,j)$ 是孤独像素，由引理 1 得 $\text{rowCnt}[i] = 1$，故第 $i$ 行不会被跳过；该行内唯一的黑格（即 $(i,j)$）被取出并参与列判定。∎

**引理 3（不重不漏地计数）**：第 2 遍中每个格子至多使答案加一一次。

**证明**：外层按行遍历，每行最多取一个黑格（`rowCnt[i] == 1` 时行内黑格唯一，且取到即 `break`），不同行对应不同的格子，故同一格子不会被统计两次。∎

**定理**：算法返回的值等于矩阵中孤独像素的个数。

**证明**：设 $S$ 为第 2 遍中「被判定通过」的格子集合，答案变量的值恰为 $|S|$（由引理 3 不重复计数）。判定通过的条件是「该格为 `'B'` 且 $\text{rowCnt}[i] = 1$ 且 $\text{colCnt}[j] = 1$」，由引理 1 该条件等价于「该格是孤独像素」，故 $S$ 恰为全部孤独像素；又由引理 2，任何孤独像素所在的行都参与了枚举，不存在遗漏。故返回值等于孤独像素总数。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。第一遍枚举 $mn$ 个格子，每次常数次加法；第二遍外层 $m$ 次，每行最多扫描 $n$ 个格子且找到唯一黑格即退出，合计不超过 $mn$ 次；总计 $O(mn)$，最坏约 $2.5\times 10^{5}$ 次基本操作。
- **空间**：$O(m+n)$。两个计数数组分别长 $m$、$n$，其余变量为常数；与矩阵规模之外的结构无关，也不修改输入。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findLonelyPixel(vector<vector<char>>& picture) {
        int m = picture.size(), n = picture[0].size();
        vector<int> rowCnt(m, 0), colCnt(n, 0);

        // 第 1 遍：统计每行、每列的黑格数
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (picture[i][j] == 'B') { rowCnt[i]++; colCnt[j]++; }

        // 第 2 遍：只检查「本行黑格唯一」的行
        int ans = 0;
        for (int i = 0; i < m; i++) {
            if (rowCnt[i] != 1) continue;
            for (int j = 0; j < n; j++) {
                if (picture[i][j] != 'B') continue;
                if (colCnt[j] == 1) ans++;   // 该列也只有它一个黑格
                break;                       // 该行黑格唯一，找到即可停止
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def findLonelyPixel(self, picture: List[List[str]]) -> int:
        m, n = len(picture), len(picture[0])
        row_cnt = [0] * m
        col_cnt = [0] * n

        # 第 1 遍：统计每行、每列的黑格数
        for i in range(m):
            for j in range(n):
                if picture[i][j] == 'B':
                    row_cnt[i] += 1
                    col_cnt[j] += 1

        # 第 2 遍：只检查「本行黑格唯一」的行
        ans = 0
        for i in range(m):
            if row_cnt[i] != 1:
                continue
            for j in range(n):
                if picture[i][j] == 'B':
                    if col_cnt[j] == 1:
                        ans += 1
                    break                    # 该行黑格唯一，找到即可停止
        return ans
```

## 8. 边界情况与易错点

1. **整张图全白**：所有 `rowCnt` 为 0，第 2 遍全部跳过，返回 0，不要因为「没有黑格」而漏掉返回语句。
2. **单行有多个黑格**：`picture = [["B","B"]]` 返回 0 而不是 2——`rowCnt[0] = 2`，两个黑格都不孤独。
3. **全图唯一黑格**：`picture = [["B"]]` 返回 1。判定用 `rowCnt == 1` 而不是 `rowCnt == 0`，因为黑格自身已被计入行计数。
4. **白格误判**：省掉 `picture[i][j] == 'B'` 就会在「行、列各只有一个黑格」的行里把白格算进去；示例 1 的白格 $(0,0)$ 正是这种情况。
5. **$500\times500$ 对角线**：每个黑格的行、列都唯一，答案是 500，不是 1；不要把「`rowCnt == 1`」误解为「全图只有一个黑格」。
6. **单列矩阵**：`picture = [["B"],["W"],["B"]]` 中行筛选能通过（两行各一个黑格），但 `colCnt[0] = 2`，答案为 0——行筛选之后必须仍有列定案。
7. **`n == 1` 时内层循环的 `break`**：内层循环最多执行一次，`break` 不改变语义，不要为它加特判。
8. **返回值类型**：函数返回 `int`，最大计数为 500（对角线情形），不会溢出。

**延伸思考**：

- 若矩阵**动态更新**（每次翻转一个格子并查询答案），可以 $O(1)$ 增量维护 `rowCnt` / `colCnt`，但答案不能 $O(1)$ 更新：翻转 $(i,j)$ 会改变第 $i$ 行与第 $j$ 列的孤独性，需要重算这两条线上受影响的黑格，单次 $O(m+n)$。
- 若把「同行、同列」换成「两条对角线」，判定就从「两个计数」变成「四个计数（主对角、副对角、行、列）」，思路完全平移，只是预处理要按对角线编号建桶。
- 孤独像素 II 的真正难点不在计数而在**模式匹配**：要求两行的黑格列号集合完全相同，需要先按行计数筛出候选行，再用哈希或排序比较列模式，否则退化成 $O(m^{2}n)$。
