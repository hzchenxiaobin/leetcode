# LeetCode 数组中的 k-diff 数对 题解

## 1. 题目概述

- **标题 / 题号**：数组中的 k-diff 数对（#532，medium）
- **链接**：https://leetcode.cn/problems/k-diff-pairs-in-an-array/
- **来源**：LeetCode 第 22 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、双指针、二分查找、排序

**题意**：给定整数数组 `nums` 与整数 `k`，统计**不同的** k-diff 数对个数。数对是二元组 `(nums[i], nums[j])`，满足 `i != j` 且 $\lvert nums[i] - nums[j] \rvert = k$。关键在「不同」二字：数对只按**取值**区分，同一个值对有多个下标组合（如 `nums` 里两个 `1` 配上同一个 `3`）也只算**一个**。

**约束**：

- $1 \le nums.length \le 10^4$
- $-10^7 \le nums[i] \le 10^7$
- $0 \le k \le 10^7$（`k` 非负，无需处理负差值）

## 2. 示例

**示例 1**

```text
输入：nums = [3, 1, 4, 1, 5], k = 2
输出：2
解释：存在两个 2-diff 数对：(1, 3) 和 (3, 5)。
     数组里有两个 1，但它们与 3 组成的数对只按值算一次，故答案 2。
```

**示例 2**

```text
输入：nums = [1, 2, 3, 4, 5], k = 1
输出：4
解释：四个 1-diff 数对：(1,2)、(2,3)、(3,4)、(4,5)。
```

**示例 3**

```text
输入：nums = [1, 3, 1, 5, 4], k = 0
输出：1
解释：k = 0 时数对形如 (x, x)，但要求 i != j，
     所以只有值 1 出现两次，能凑出唯一的 0-diff 数对 (1, 1)。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i, j)$，$i \ne j$，若 $\lvert nums[i] - nums[j] \rvert = k$ 就把 $\bigl(\min(a,b), \max(a,b)\bigr)$ 塞进哈希集合去重，最后返回集合大小。

时间 $O(n^2)$，$n = 10^4$ 时约 $10^8$ 次比较，C++ 勉强、Python 必超时；空间 $O(n)$。更根本的问题是**信息冗余**：下标 $i, j$ 的取值组合对答案毫无意义，同一个值对被反复枚举，说明我们没有抓住题目的结构。

### 3.2 核心观察：数对由「较小值」唯一确定

![k-diff 数对由较小值唯一确定](images/wc22_q1_unique_pairs.svg)

把数对写成有序形式 $a \le b$。若 $b - a = k$ 且 $k > 0$，则 $a < b$，于是：

- 给定 $a$，候选的 $b$ 只能是 $a + k$，**没有第二种可能**；
- 给定 $b$，候选的 $a$ 只能是 $b - k$，同样唯一。

因此「所有不同的 k-diff 数对」与「所有满足 $x + k \in S$ 的值 $x$」之间存在一一对应（$S$ 为 `nums` 的去重值集合）：

$$\text{ans} = \bigl\lvert\{\, x \in S \;:\; x + k \in S \,\}\bigr\rvert \qquad (k > 0)$$

注意这里只用到「值是否出现」，同一数值在数组中重复多少次都不影响答案——这正好解释了示例 1 的两个 `1` 只算一次（该结论仅对 $k > 0$ 成立）。

$k = 0$ 是**另一种结构**：数对形如 $(x, x)$，需要两个**不同下标**却有相同取值，所以只与频次有关：

$$\text{ans} = \bigl\lvert\{\, x \;:\; \mathrm{cnt}(x) \ge 2 \,\}\bigr\rvert \qquad (k = 0)$$

> 💡 **一句话总结**：$k > 0$ 时答案只看「值的集合」，$k = 0$ 时答案只看「频次 ≥ 2 的值」。两条分支都不需要下标。

### 3.3 算法流程：排序去重 + 双指针

![排序去重后双指针滑窗](images/wc22_q1_sort_two_pointers.svg)

对 $k > 0$，把 `nums` 升序排序后原地去重，得到严格递增数组 $u$（长度 $m$），再用**同向双指针**：

1. `sort(nums)`；
2. `nums.erase(unique(...))` 得到严格递增的 $u$（Python 可直接 `sorted(set(nums))`）；
3. `j` 从 $1$ 开始；对每个 $i$，在 `u[j] - u[i] < k` 时右移 `j`；
4. 若 `u[j] - u[i] == k`，`ans++`；随后 $i$ 右移，`j` **不回退**（恒有 `j = max(j, i+1)`）。

因为 $u$ 严格递增，固定 $i$ 时差值随 $j$ 严格递增、固定 $j$ 时随 $i$ 严格递减，所以 $i$ 与 $j$ 都只需向右走，总移动量 $O(m)$。

对 $k = 0$，排序后扫描相邻相同的连续段，段长 $\ge 2$ 就 `ans++`（等价于统计频次）。

也可以完全用哈希表：`set(nums)` 后对每个 $x$ 查 $x + k$ 是否存在，期望 $O(n)$；或用 `Counter` 直接处理 $k = 0$。两种写法都要注意**只朝一个方向查**（统一查 $x+k$，不要同时查 $x-k$），否则同一个数对会被数两次。

### 3.4 示例演算

![示例 1 双指针走查](images/wc22_q1_walkthrough.svg)

对 `nums = [3, 1, 4, 1, 5]`、`k = 2`：排序得 `[1, 1, 3, 4, 5]`，去重得 $u = [1, 3, 4, 5]$。

| 步骤 | $i$ | $u[i]$ | $j$ | $u[j]$ | 差值 | 动作 |
|------|-----|--------|-----|--------|------|------|
| 1 | 0 | 1 | 1 | 3 | $2 = k$ | `ans = 1`，收下 $(1,3)$ |
| 2 | 1 | 3 | 2 | 4 | $1 < k$ | `j++` → $j = 3$ |
| 3 | 1 | 3 | 3 | 5 | $2 = k$ | `ans = 2`，收下 $(3,5)$ |
| 4 | 2 | 4 | 4 | — | 越界 | `j = m`，循环结束 |

答案 $2$。$k = 0$ 的示例 3 走频次分支：`[1, 3, 1, 5, 4]` 中只有值 `1` 出现 2 次，答案 $1$。

## 4. 算法细节

1. **两条分支必须分开**：$k > 0$ 用值集合，$k = 0$ 用频次。把 $k = 0$ 也丢进值集合会恒得 $0$；把 $k > 0$ 也用频次会重复计数。
2. **去重方式任选**：`sort + unique` 原地去重、额外空间 $O(1)$（不计排序栈）；`set` 额外 $O(n)$ 但免排序、期望 $O(n)$。二者答案一致。
3. **指针不回退的写法**：`j` 初值 $1$，每轮先做 `if (j <= i) j = i + 1;`，保证 $j > i$（$i$ 追赶时不出错），再 `while (j < m && u[j] - u[i] < k) ++j`。
4. **越界与结束条件**：`j == m` 说明 $u[i] + k$ 超出数组最大值，而对更大的 $i$，$u[i] + k$ 只会更大，可**直接结束**整个循环（写 `break` 或让 `for` 自然空转都正确）。
5. **差值范围**：$nums[i] \in [-10^7, 10^7]$，两数之差最大 $2 \times 10^7$，虽未溢出 32 位有符号整数（上限 $2.1 \times 10^9$），但不该依赖这种巧合：C++ 里用 `long long` 承接差值，比较时把 `k` 也提升为 64 位。
6. **哈希集合的查法**：`for x in set(nums): if x + k in s: ans += 1`。只查 $x + k$，保证每个数对恰好被较小值命中一次；同时查 $x - k$ 会让每个数对贡献 2。
7. **`k` 为负的防御**：本题约束 $k \ge 0$，但在通用实现里加一句 `if (k < 0) return 0;`（差绝对值不可能为负）更健壮。
8. **不要改调用方的数组语义**：`sort` 会破坏原始顺序，LeetCode 允许；若在工程代码里复用，先拷贝一份。

## 5. 正确性证明

**引理 1**：当 $k > 0$ 时，映射 $x \mapsto (x, x+k)$ 是从集合 $A = \{\,x \in S : x + k \in S\,\}$ 到全部不同 k-diff 数对的双射。

**证明**：任取 $x \in A$，$x$ 与 $x + k$ 都是数组中的值且二者不等（$k > 0$），取它们各自的一个下标即得到合法数对 $(x, x+k)$，故映射良定义、且不同 $x$ 给出不同数对（较小值不同），是单射。反之任取不同 k-diff 数对 $\{a, b\}$（$a < b$），由 $b - a = k$ 得 $b = a + k$，于是 $a \in S$、$a + k \in S$，即 $a \in A$ 且该数对被 $a$ 命中，是满射。∎

**引理 2**：当 $k = 0$ 时，存在 0-diff 数对 $(x, x)$ 当且仅当 $\mathrm{cnt}(x) \ge 2$。

**证明**：$(\Leftarrow)$ 若 $\mathrm{cnt}(x) \ge 2$，取两个不同下标 $i \ne j$ 且 $nums[i] = nums[j] = x$，则 $\lvert nums[i] - nums[j] \rvert = 0 = k$，数对 $(x,x)$ 合法。$(\Rightarrow)$ 若 $(x, x)$ 是合法数对，则存在 $i \ne j$ 且 $nums[i] = nums[j] = x$，这两个下标就贡献了两次出现，故 $\mathrm{cnt}(x) \ge 2$。∎

**引理 3**：设 $u$ 严格递增。对每个 $i$，`while` 循环结束后「存在 $j > i$ 使 $u[j] - u[i] = k$」的判定结果正确。

**证明**：固定 $i$，令 $g(j) = u[j] - u[i]$，由 $u$ 严格递增知 $g$ 在 $[i, m)$ 上严格递增。设 `while` 结束时指针为 $j_0 \ge i+1$，则必有 $j_0 = m$ 或 $g(j_0) \ge k$，且扫描过程中所有 $j \in [i+1, j_0)$ 都满足 $g(j) < k$。分三种情况：

- $j_0 < m$ 且 $g(j_0) = k$：存在这样的 $j$，判定为真，正确；
- $j_0 < m$ 且 $g(j_0) > k$：$j < j_0$ 时 $g(j) < k$，$j = j_0$ 时 $g(j) > k$，$j > j_0$ 时 $g(j) > g(j_0) > k$，故无解，判定为假，正确；
- $j_0 = m$：所有 $j$ 都已扫过且 $g(j) < k$，无解，判定为假，正确。

三种情况覆盖全部可能，判定精确。∎

**引理 4**：$j$ 不回退不遗漏任何解。

**证明**：设处理完 $i$ 后指针停在 $j_0$，取 $i' > i$。由于 $u[i'] > u[i]$，对任意 $j < j_0$ 有 $u[j] - u[i'] < u[j] - u[i] < k$（后一个不等式来自循环停止条件），即这些位置在 $i'$ 下仍然不可能是解；故 $i'$ 的解若存在必落在 $j \ge j_0$，从 $j_0$ 继续右移不会跳过它。∎

**定理**：算法返回的值等于不同 k-diff 数对的个数。

**证明**：$k > 0$ 时由引理 3、引理 4，算法对每个 $u[i]$ 都精确判定 $u[i] + k$ 是否存在、且不漏解，累计的正是集合 $A$ 的大小，由引理 1 即不同数对个数。$k = 0$ 时算法统计的是 $\mathrm{cnt}(x) \ge 2$ 的值个数（排序后同值连续成段，段长即频次），由引理 2 即不同数对个数。∎

## 6. 复杂度分析

- **时间**：排序 $O(n \log n)$；去重 $O(n)$；双指针中 $i$ 走 $m$ 步、$j$ 至多走 $m$ 步，共 $O(m) \subseteq O(n)$，故总 $O(n \log n)$，瓶颈在排序。$k = 0$ 时一次线性扫描，同样 $O(n \log n)$。若用哈希集合，期望 $O(n)$（`set` 构造与查询均摊 $O(1)$）；`Counter` 版本也是 $O(n)$。
- **空间**：排序原地，`std::sort` 递归栈 $O(\log n)$；`sort + unique` 去重不额外申请数组；哈希写法需要 $O(n)$ 的集合/计数字典。输出只有整数，$O(1)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findPairs(vector<int>& nums, int k) {
        if (k < 0) return 0;                 // 本题 k >= 0，防御性写法
        sort(nums.begin(), nums.end());
        int n = nums.size(), ans = 0;

        if (k == 0) {                        // 分支一：只看频次
            for (int i = 0; i < n; ) {
                int j = i;
                while (j < n && nums[j] == nums[i]) ++j;
                if (j - i >= 2) ++ans;       // 同一个值出现 >= 2 次
                i = j;
            }
            return ans;
        }

        // 分支二：去重成严格递增数组，双指针数 x + k 是否存在
        nums.erase(unique(nums.begin(), nums.end()), nums.end());
        int m = nums.size(), j = 1;
        for (int i = 0; i < m; ++i) {
            if (j <= i) j = i + 1;           // 保证 j > i
            while (j < m && (long long)nums[j] - nums[i] < k) ++j;
            if (j == m) break;               // 再往右只会更大，可提前结束
            if ((long long)nums[j] - nums[i] == k) ++ans;
        }
        return ans;
    }
};
```

### Python

```python
from typing import List
from collections import Counter


class Solution:
    def findPairs(self, nums: List[int], k: int) -> int:
        if k < 0:
            return 0
        if k == 0:
            # 只与频次有关：出现 >= 2 次的值各有唯一数对 (x, x)
            return sum(1 for v in Counter(nums).values() if v >= 2)
        # k > 0：数对由较小值唯一确定，只需查一次 x + k
        s = set(nums)
        return sum(1 for x in s if x + k in s)
```

## 8. 边界情况与易错点

1. **$k = 0$ 单独处理**：值集合会丢掉重复信息，若仍走 `x + k in s` 会得到 $n$ 个「自配对」之类的错误答案。$k = 0$ 只数频次 $\ge 2$ 的值，示例 3 答案为 1。
2. **重复值导致重复计数**：`[1, 1, 1, 3]`、$k = 2$ 的答案仍是 1（只有数对 $(1,3)$），不是 3。任何「按数组元素逐个累加」的写法都必须先去重或按频次归并。
3. **单元素数组**：$n = 1$ 时无论 $k$ 为何都返回 0（没有 $i \ne j$ 的下标对），双指针版 `j` 一开始就越界。
4. **全相同的数组**：`[4, 4, 4]`、$k = 0$ → 1；$k > 0$ → 0（去重后只剩一个值，无 $x + k$）。
5. **$k$ 大于整个取值范围**：如 `[1, 2]`、$k = 10^7$，去重后 `j` 立即越界，返回 0，不能漏掉 `break` 后误加答案。
6. **负数与符号**：`[-3, -1]`、$k = 2$ → 1。排序后统一用 $u[j] - u[i]$（大减小）比较，天然对应 $\lvert a - b \rvert$，不要写成绝对值后既查 $+k$ 又查 $-k$。
7. **双向查找的重复计数**：哈希写法若写成 `if x+k in s: ans+=1` 的同时又 `if x-k in s: ans+=1`，每个数对会被数两次；统一朝一个方向查。
8. **提前结束的时机**：去重后若指针走到 `j == m`，说明 $u[i] + k$ 已超过数组最大值，对更大的 $i$ 只会更超，可安全 `break`；但若 $j < m$ 只是「差值 $> k$」（即 $u[i]+k$ 落在两个相邻值之间、不存在），**不能** `break`，必须继续 $i{+}{+}$，否则会漏掉后续 $u[i'] + k$ 恰好存在的解。
