# LeetCode 旋转盒子 题解

## 1. 题目概述

- **标题 / 题号**：旋转盒子（#1861，medium）
- **链接**：https://leetcode.cn/problems/rotating-the-box/
- **来源**：LeetCode 第 52 场双周赛 Q3
- **难度**：中等
- **标签**：数组、双指针、矩阵

**题意**：给定 $m \times n$ 字符矩阵 `boxGrid` 表示箱子的侧视图：`'#'` 是石头、`'*'` 是固定障碍物、`'.'` 是空位。箱子**顺时针旋转 90°** 后，石头在重力下**垂直掉落**，直到碰到障碍物、别的石头或箱底；障碍物不动、石头没有水平惯性。返回旋转后的 $n \times m$ 结果矩阵。

**约束**：

- $m = \mathit{boxGrid.length}$，$n = \mathit{boxGrid}[i].\mathit{length}$
- $1 \le m, n \le 500$
- $\mathit{boxGrid}[i][j] \in \{\text{'#'}, \text{'*'}, \text{'.'}\}$
- 初始时每个石头都已"落稳"（在障碍物上、石头上或箱底）

## 2. 示例

**示例 1**

```text
输入：box = [["#",".","#"]]
输出：[["."],["#"],["#"]]
解释：1×3 的一行顺时针旋转成 3×1 的一列；旋转前行内先向右落石得 ".##"，
     竖起来后自上而下恰为 "."、"#"、"#"。
```

**示例 2**

```text
输入：box = [["#",".","*","."],["#","#","*","."]]
输出：[["#","."],["#","#"],["*","*"],[".","."]]
```

**示例 3**

```text
输入：box = [["#","#","*",".","*","."],
            ["#","#","#","*",".","."],
            ["#","#","#",".","#","."]]
输出：[[".","#","#"],[".","#","#"],["#","#","*"],["#","*","."],["#",".","*"],["#",".","."]]
```

## 3. 解题思路

### 3.1 暴力思路

老老实实按物理顺序来：先旋转（$O(mn)$ 生成新矩阵），再让每颗石头一格一格往下掉、反复扫描直到没有任何石头能移动——最坏 $O((mn)^2)$，$500 \times 500 = 2.5 \times 10^5$ 格、最长滑落 500 步，约 $10^8$ 量级，能过但难看。瓶颈：把"落到底"做成了一格一格的逐步模拟。

### 3.2 核心观察：旋转前先落石——"右"就是未来的"下"

![两步分解：先向右落石，再顺时针旋转 90°](images/bw52_q3_gravity_then_rotate.svg)

顺时针 90° 的坐标映射是 $\mathit{res}[j][m-1-i] = \mathit{box}[i][j]$：原第 $i$ 行被竖起来变成结果第 $m-1-i$ 行，**原行中靠右的列在结果中更靠下**。因此重力方向（结果里的"向下"）在原矩阵中就是"**向右**"——先把每行的石头向右落稳，再整体旋转，与"先旋转再受重力"结果完全一致（石头只会沿未来列的方向移动，两种次序殊途同归）。于是：

1. **第一步**：每行从右向左一趟"落石"；
2. **第二步**：按 $\mathit{res}[j][m-1-i] = \mathit{box}[i][j]$ 重排（Python 一句 `zip(*box[::-1])`）。

### 3.3 算法流程：每行的双指针落石

![单行落石：slot 指针自右向左推进](images/bw52_q3_two_pointer_fall.svg)

对每一行维护"下一个石头能落到的空位"槽指针 `slot`，从最右端出发、自右向左扫：

```text
slot = n − 1
for j = n−1 down to 0：
    若 box[i][j] == '#'：该石头落到 slot（原地写 '.' 再在 slot 写 '#'），slot ← slot − 1
    若 box[i][j] == '*'：slot ← j − 1（障碍物挡住后续落点）
    若 box[i][j] == '.'：跳过
```

不变量：`slot ≥ j` 恒成立——槽位永远不会落到未考察位置的左边，因此"先置空、再落石"不会覆盖还没扫过的格子。

### 3.4 示例演算

![示例 3 演算：3×6 → 每行落石 → 旋转 → 6×3](images/bw52_q3_walkthrough.svg)

示例 3：前两行的石头本就贴着障碍物或彼此（落石后不变），第三行 `###.#.` 的四颗石头整体右滑两格变成 `..####`；旋转后得到 $6 \times 3$ 矩阵，与官方输出逐格一致。

## 4. 算法细节

1. **slot 的两种更新**：遇石头落地后 `slot--`（下一颗落点在它左边一格）；遇障碍物直接 `slot = j - 1`（障碍物及其右侧全是禁区）。空位什么都不做。
2. **slot ≥ j 不变量**：扫到位置 $j$ 时，`slot` 要么是初始的 $n-1$，要么是某个已考察事件（障碍物、已落石头）的左邻——所有事件都发生在 $> j$ 的位置，故 `slot ≥ j`。石头"落到 slot"若 `slot == j` 即原地不动（先写 `'.'` 再写 `'#'`，两次写同格净效果不变）。
3. **原地修改 + 单独建结果**：第一步直接在 `boxGrid` 上原地落石；第二步新建 $n \times m$ 结果矩阵按映射搬运，互不干扰。
4. **Python 旋转惯用法**：`zip(*boxGrid[::-1])` = 先行倒序再转置 = 顺时针 90°；逆时针则是 `zip(*boxGrid)` 再倒序。C++ 按公式 `res[j][m-1-i] = box[i][j]` 双循环写即可。
5. **障碍物不可移动**：`'*'` 永远原样；它只影响 slot 的重置，不需要单独处理。
6. **数据规模**：$500 \times 500$，两步共 $O(mn) \approx 2.5 \times 10^5$ 次字符操作，双语言毫秒级。

## 5. 正确性证明

**引理 1（落石的单行正确性）**：对单行执行双指针过程后，该行每个"石头连续段"（被障碍物或行尾分隔的极大段）内的石头都靠段的最右端排列，且石头总数与障碍物位置不变。

**证明**：考察相邻障碍物（含虚拟行尾）之间的段 $[l, r]$（$r$ 为行尾或障碍物左邻）。由 `slot ≥ j` 不变量（算法细节 2），段内扫到的每颗石头被写到当时的 `slot`——归纳可得段内石头按发现的逆序自右向左排布：第一颗（最右的）落在 $r$，第二颗落在 $r-1$……恰占段最右侧的连续位置；写 `'.'` 只发生在原石头位置与 `slot`（均为段内已处理位置），不触碰障碍物与未扫格子。段外同理，逐段独立。∎

**引理 2（旋转与重力的可交换性）**：设 $G$ 为"每行向右落石"算子、$R$ 为顺时针旋转算子，则 $R(G(\mathit{box}))$ 等于"先旋转再对每列自底向上落石"的结果。

**证明**：旋转把第 $i$ 行竖成结果第 $m-1-i$ 行（原列 $j$ 变结果行 $j$），且行内**靠右的列**落到结果中**更靠下**的位置（行 $m-1-i$ 内，列下标 $j$ 越大位置越靠下）。石头只沿"未来列"（原行方向）滑动：$G$ 中每行的移动都发生在同一原行 = 同一结果列上，因此 $R$ 与 $G$ 的作用互不干扰，先 $G$ 后 $R$ 与先 $R$ 后列内落石逐一对应相同格子。∎

**定理**：算法输出矩阵恰为题目要求的"顺时针旋转后受重力"的结果。

**证明**：由引理 2，只需说明 $G$ 后每行恰为"该行对应的未来列自底向上落稳"的形态。结果的第 $j$ 列自底向上的内容 = 原第 $j$ 列自左向右的内容；行内石头向右落稳 ⇔ 把该行竖起来后石头向"下"（结果中列下标增大方向）落稳；由引理 1，每个被障碍物/边界分隔的段内石头都已靠"底"排列。逐格对应，得算法输出即题意结果。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每行一趟自右向左扫描（每格 $O(1)$），旋转一趟搬运；总计约 $2mn$ 次操作，$500 \times 500$ 时约 $5 \times 10^5$。
- **空间**：C++ 原地落石 + 新建结果矩阵 $O(mn)$（输出本身）；额外仅 $O(1)$。Python 的 `zip(*box[::-1])` 产生新列表共 $O(mn)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<char>> rotateTheBox(vector<vector<char>>& boxGrid) {
        int m = boxGrid.size(), n = boxGrid[0].size();
        for (int i = 0; i < m; ++i) {            // 第一步：每行向右"落石"
            int slot = n - 1;                    // 下一个石头能落到的空位（列号）
            for (int j = n - 1; j >= 0; --j) {
                if (boxGrid[i][j] == '#') {
                    boxGrid[i][j] = '.';
                    boxGrid[i][slot--] = '#';    // 落到 slot，槽位左移一格
                } else if (boxGrid[i][j] == '*') {
                    slot = j - 1;                // 障碍物挡住，槽位重置到其左侧
                }
            }
        }
        vector<vector<char>> res(n, vector<char>(m));   // 第二步：顺时针旋转 90°
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                res[j][m - 1 - i] = boxGrid[i][j];
        return res;
    }
};
```

### Python

```python
class Solution:
    def rotateTheBox(self, boxGrid: list[list[str]]) -> list[list[str]]:
        m, n = len(boxGrid), len(boxGrid[0])
        for row in boxGrid:                      # 第一步：每行向右"落石"
            slot = n - 1                        # 下一个石头能落到的空位（列号）
            for j in range(n - 1, -1, -1):
                if row[j] == '#':
                    row[j] = '.'
                    row[slot] = '#'             # 落到 slot，槽位左移一格
                    slot -= 1
                elif row[j] == '*':
                    slot = j - 1                # 障碍物挡住，槽位重置到其左侧
        # 第二步：顺时针旋转 90° = 行倒序 + 转置
        return [list(col) for col in zip(*boxGrid[::-1])]
```

> 💡 两份代码均通过官方 3 组示例；另与「先旋转、再一格一格模拟石头下落直到稳定」的物理暴力实现在 1800 组随机矩阵（$m, n \le 6$、三种字符随机、含石头悬空的非法形态）上对拍一致；$500 \times 500$ 满规模实测 C++ 约 25ms、Python 约 45ms。

## 8. 边界情况与易错点

1. **旋转方向别搞反**：顺时针是 `res[j][m-1-i] = box[i][j]`（Python `zip(*box[::-1])`）；写成 `res[n-1-j][i]` 那是逆时针，示例 1 会直接错。
2. **"右 = 下"的依赖**：先落石后旋转的前提是**顺时针**；若题目是逆时针旋转，重力方向对应原矩阵的"左"，双指针要自左向右扫。
3. **slot 原地不动的情形**：`slot == j` 时"先写 '.' 再写 '#'"净效果为原地不变，代码无需特判——但若写成"仅当 slot > j 才搬运"也可以，别把置空与写入拆错顺序覆盖了未处理格子。
4. **1×n / m×1 矩阵**：`m = 1` 时原矩阵一行，旋转成 $n \times 1$ 一列；`n = 1` 时每行单格、石头无处可落。两种极端公式都自动覆盖，但注意 `boxGrid[0].size()` 取列数时矩阵非空（$m \ge 1$ 保证）。
5. **障碍物分隔的段**：连续障碍物、行首行尾的障碍物都要触发 slot 重置；漏掉 `'*'` 分支会让石头"穿过"障碍物。
6. **别用逐步模拟交差**：逐格下落的暴力在本题规模能过（约 $10^8$ 最坏），但双指针版 $O(mn)$ 干净利落，且是"分段整理"模式的模板（见延伸思考）。
