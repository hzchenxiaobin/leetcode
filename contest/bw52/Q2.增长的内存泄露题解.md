# LeetCode 增长的内存泄露 题解

## 1. 题目概述

- **标题 / 题号**：增长的内存泄露（#1860，medium）
- **链接**：https://leetcode.cn/problems/incremental-memory-leak/
- **来源**：LeetCode 第 52 场双周赛 Q2
- **难度**：中等
- **标签**：数学、模拟

**题意**：两个内存条分别剩余 `memory1` 与 `memory2` 个比特。一个失控程序从第 $1$ 秒开始每秒分配内存：第 $i$ 秒分配 $i$ 个比特，分配给**剩余较多**的那条（相等时给第一条）。若两条剩余都**不足 $i$**，程序意外退出。返回 `[crashTime, memory1, memory2]`——崩溃时刻与两条内存的最后剩余。

**约束**：

- $0 \le \mathit{memory1}, \mathit{memory2} \le 2^{31} - 1$

## 2. 示例

**示例 1**

```text
输入：memory1 = 2, memory2 = 2
输出：[3,1,0]
解释：第 1 秒扣条 1（2→1）；第 2 秒扣条 2（2→0）；
     第 3 秒 max(1, 0) = 1 < 3，两条都付不起，崩溃。
```

**示例 2**

```text
输入：memory1 = 8, memory2 = 11
输出：[6,0,4]
解释：第 1 秒扣条 2（11→10），第 2 秒扣条 2（10→8），第 3 秒平局扣条 1（8→5），
     第 4 秒扣条 2（8→4），第 5 秒扣条 1（5→0），
     第 6 秒 max(0, 4) = 4 < 6，崩溃。
```

**示例 3（边界补充）**

```text
输入：memory1 = 0, memory2 = 0
输出：[1,0,0]
解释：第 1 秒 max(0, 0) = 0 < 1，程序立刻崩溃。
```

## 3. 解题思路

### 3.1 暴力思路

看似 $2^{31} - 1$ 的内存会让人担心循环次数爆炸——其实不会：每秒分配给谁、谁就被扣掉 $i$，**总量**每秒恰好减少 $i$；存活过前 $t-1$ 秒意味着累计已扣 $1 + 2 + \dots + (t-1) = t(t-1)/2 \le m_1 + m_2$，而总量 $M \le 2^{32} - 2$，故崩溃时刻 $t \le \sqrt{2M} \approx 92681$。**直接模拟只有约 $10^5$ 步**，完全可行。真正要小心的只有两件事：64 位运算（闭式里的 $t(t+1)/2 \approx 4.3 \times 10^9$ 超 `int`）和平局规则。

### 3.2 核心观察：崩溃条件可以写成「较大者付不起」

![每秒把 t 位内存扣给剩余较多的一条](images/bw52_q2_balance_model.svg)

第 $i$ 秒的分配规则是"给较大的一条"。设 $m_1 \ge m_2$：若 $m_1 \ge i$，条 1 付得起（条 2 自然也轮不到）；若 $m_1 < i$，则 $m_2 \le m_1 < i$，**两条都付不起**——崩溃。于是循环条件浓缩成一行：

$$\max(m_1, m_2) \ge t \iff \text{第 } t \text{ 秒能继续}$$

较大者付不起时较小者必然也付不起，不用分别判断两条。

### 3.3 算法流程

```text
1. m1 ← memory1，m2 ← memory2，t ← 1
2. 循环：
     若 max(m1, m2) < t：跳出（崩溃）
     若 m1 >= m2：m1 ← m1 − t（平局优先第一条）
     否则：m2 ← m2 − t
     t ← t + 1
3. 返回 [t, m1, m2]
```

### 3.4 示例演算

![示例 2 演算表：8 vs 11 的六秒](images/bw52_q2_walkthrough.svg)

示例 2 的逐秒表格（见上图）：前两秒条 2 较大连扣 11→10→8；第 3 秒 $8 = 8$ 平局按规则扣条 1（8→5）；第 4 秒条 2 又变大（8→4）；第 5 秒条 1（5→0）；第 6 秒 $\max(0, 4) = 4 < 6$ 崩溃，返回 $[6, 0, 4]$。

## 4. 算法细节

1. **64 位**：`memory` 单条可达 $2^{31}-1$，`int` 的加减虽未越界（$2^{31}-1 - t$ 仍是正数范围内），但比较 `max(m1, m2) < t` 里 `t` 与内存都接近 `int` 上界时减法与求和容易踩线；C++ 索性全用 `long long`，返回前转回 `int`。Python 无此问题。
2. **平局规则**：相等时扣**第一条**——写成 `if m1 >= m2`（含等号）恰好在平局时先扣条 1；用 `>` 会在相等时错误地扣条 2。
3. **崩溃时刻的语义**：返回的 `t` 是"第一次付不起的那一秒"（崩溃发生在该秒），不是最后成功的一秒——官方示例 `crashTime = 6`（第 5 秒成功、第 6 秒崩溃）确认了这一点。
4. **闭式解（可选）**：总量视角 $S_t = t(t+1)/2 \le m_1 + m_2$ 给出 $t$ 的界 $t \approx \lfloor(\sqrt{8(m_1+m_2)+1}-1)/2\rfloor$；但**分配对象的选择影响后续走势**（扣谁会让谁变小、切换分配方向），崩溃时刻并不能仅由总量唯一确定，闭式只能求界。直接模拟反而更不易错。
5. **模拟步数上界**：$M \le 2^{33}$ 量级 ⇒ $t \le 92681$；每步 $O(1)$，总量约 $10^5$ 次操作，双语言都在 50ms 内。

## 5. 正确性证明

**引理 1（分配规则刻画）**：第 $t$ 秒分配给条 1 当且仅当 $m_1 \ge m_2$ 且 $m_1 \ge t$；否则若 $m_2 > m_1$ 且 $m_2 \ge t$ 分配给条 2；否则两条都 $< t$，崩溃。

**证明**：按题意，分配给"剩余较多"者（相等给条 1），前提是被分配者付得起 $t$。设 $m_1 \ge m_2$：条 1 是（并列）较大者，若 $m_1 \ge t$ 则合法分配给条 1；若 $m_1 < t$ 则 $m_2 \le m_1 < t$，条 2 也付不起，崩溃。$m_2 > m_1$ 时对称。∎

**引理 2（终止性）**：程序必在第 $t^*$ 秒崩溃，且 $t^* \le \min\{t : t(t+1)/2 > m_1 + m_2\}$。

**证明**：每过一秒两条内存总量恰好减少 $t$（分配给谁都是扣 $t$），故到第 $t$ 秒开始时总量为 $m_1 + m_2 - (1 + 2 + \dots + (t-1)) = m_1 + m_2 - t(t-1)/2$。当 $t(t-1)/2 \ge m_1 + m_2$ 时总量 $\le 0$，于是 $\max(m_1, m_2) = 0 < t$（$t \ge 1$），程序崩溃。∎

**定理（模拟正确性）**：算法返回的 $[t, m_1, m_2]$ 中，$t$ 是首个使 $\max < t$ 的秒数，$m_1, m_2$ 是到此为止恰好执行了 $t-1$ 次合法分配后的剩余量。

**证明**：循环不变量：进入第 $t$ 轮时，`m1`、`m2` 等于前 $t-1$ 秒按题意分配后的剩余（归纳：每轮由引理 1 恰好复现"分配给较大者、平局给条 1"的一次合法分配，或判定崩溃跳出）。循环条件 `max(m1, m2) < t` 由引理 1 等价于"第 $t$ 秒两条都付不起"，首次满足时即崩溃时刻；此时内存状态未被第 $t$ 秒的分配修改，恰为崩溃时刻的剩余。∎

## 6. 复杂度分析

- **时间**：$O(\sqrt{m_1 + m_2})$。由引理 2，$t \le \sqrt{2(m_1+m_2)} \approx 9.3 \times 10^4$（上界 $2^{32}-2$ 时）；每步 $O(1)$。
- **空间**：$O(1)$。只维护两个计数器与秒数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> memLeak(int memory1, int memory2) {
        long long m1 = memory1, m2 = memory2, t = 1;
        for (;; ++t) {
            if (max(m1, m2) < t) break;         // 两条都不够第 t 秒 → 崩溃
            if (m1 >= m2) m1 -= t;               // 相等也优先第一条
            else m2 -= t;
        }
        return {(int)t, (int)m1, (int)m2};
    }
};
```

### Python

```python
class Solution:
    def memLeak(self, memory1: int, memory2: int) -> list[int]:
        m1, m2, t = memory1, memory2, 1
        while max(m1, m2) >= t:                  # 较大的一条能撑住第 t 秒
            if m1 >= m2:                         # 相等也优先第一条
                m1 -= t
            else:
                m2 -= t
            t += 1
        return [t, m1, m2]
```

> 💡 两份代码均通过官方 2 组示例；另与「显式 if-else 分支模拟」的独立参考实现在 6000 组随机输入（含 $0$、$2^{31}-1$、单边为 0 等极端）上三方一致（题解 C++ / 题解 Python / 参考实现）；双满内存 $2^{31}-1$ 实测 C++ 约 7ms、Python 约 40ms（崩溃时刻 $t = 92681$）。

## 8. 边界情况与易错点

1. **双零内存**：`[0, 0]` 时第 1 秒立刻崩溃，返回 `[1, 0, 0]`——循环条件用 `>=` 保证正确处理，别让 0 ≥ 1 判定出错。
2. **崩溃时刻差一**：返回的是"付不起的第一秒"而非"最后成功的一秒"；把循环写成"成功后再 +1"容易错位，建议循环体内先判崩溃再分配（或用 while 形式如参考代码）。
3. **平局方向**：相等必须扣条 1（`>=` 含等号），写成 `>` 会把示例 2 第 3 秒扣错。
4. **32 位溢出**：C++ 用 `int` 存 $t$ 本身不会溢（$t \le 92681$），但 `t * (t+1) / 2` 之类的闭式计算会；稳妥起见全程 `long long`。
5. **别预处理扣减顺序**：不需要先算"前一半扣谁、后一半扣谁"——分配对象每秒都可能切换（大吃小之后自己变小），逐秒判断才是正解。
6. **上界直觉**：$2^{31}-1$ 看似吓人，但等差求和告诉我们 $\sqrt{2 \times 2^{32}} \approx 92681$ 步就耗尽——**"数据范围大"不等于"循环会爆炸"**，先估算步数再选实现是本题给赛手的提醒。
