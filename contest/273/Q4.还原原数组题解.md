# LeetCode 还原原数组 题解

## 1. 题目概述

- **标题 / 题号**：还原原数组（#2122，hard）
- **链接**：https://leetcode.cn/problems/recover-the-original-array/
- **来源**：LeetCode 第 273 场周赛 Q4
- **难度**：困难
- **标签**：数组、排序、枚举、双指针、贪心、哈希表

**题意**：Alice 有一个由 $n$ 个正整数组成的数组 `arr`，她任选一个**正整数** $k$，构造出两个长度均为 $n$ 的数组：`lower[i] = arr[i] − k` 与 `higher[i] = arr[i] + k`。随后三个数组全部丢失，只剩下 `lower` 与 `higher` 合并打乱后的长度为 $2n$ 的数组 `nums`（不知道每个数来自哪个数组）。给定 `nums`，还原并返回**任一**合法的 `arr`。题目保证至少存在一组有效解。

**约束**：

- $2n = \text{nums.length}$，$1 \le n \le 1000$
- $1 \le \text{nums}[i] \le 10^9$
- 生成的测试用例保证存在至少一个有效数组 `arr`

> 💡 本站已有本题的每日版题解 `../solution/2101-2200/2122_还原原数组.md`，以「频率表批量消耗」为主线并附面试问答；本篇周赛复盘以**排序 + 枚举候选 + 双指针贪心**为主线，并补全引理–定理证明链，两篇可对照阅读。同场 Q1–Q3 的题解见本目录。

```text
      另一组合法解为 arr = [5,7,9]，k = 3（lower = [2,4,6]，higher = [8,10,12]）。
```

## 3. 解题思路

### 3.1 暴力思路：枚举 k + 搜索配对

与题意一一对应的朴素做法分两层：

1. **枚举 $k$**：合法的 $k$ 介于 $1$ 与 $(\max(\text{nums}) - \min(\text{nums})) / 2$ 之间，上限约 $5 \times 10^9$，根本枚举不完；
2. **固定 $k$ 后判定**：能否把 $2n$ 个数划分成 $n$ 对、每对差恰为 $2k$。若用回溯搜索逐个试配，最坏是指数级。

> ⚠️ 暴力的瓶颈有二：$k$ 的搜索空间巨大、盲目配对指数爆炸。突破口是两个结构观察——**最小值锁定 `lower`**（把 $2k$ 的候选压到 $O(n)$ 个），以及**最小未配对元素身份唯一**（把匹配降维成线性贪心）。切勿枚举所有 $\text{nums}[j] - \text{nums}[i]$ 作候选——那是 $O(n^2)$ 个候选，再各花 $O(n)$ 验证就是 $O(n^3)$，$n = 1000$ 时约 $10^9$ 次运算，超时。

### 3.2 核心观察：最小值锁定 lower，固定间距 2k 配对

![核心观察：每对 lower/higher 关于 arr[i] 对称，最小值必属 lower](images/wc273_q4_k_pairing_concept.svg)

**观察一（最小值必属 lower，压缩候选）**：把 `nums` 升序排序。设 $\text{arr}_{\min} = \min(\text{arr})$，则对一切 $i$ 有 $\text{arr}[i] - k \ge \text{arr}_{\min} - k$ 且 $\text{arr}[i] + k > \text{arr}_{\min} - k$，故 $\min(\text{nums}) = \text{arr}_{\min} - k$——**全局最小值在任何合法方案里都属于 `lower`**。它的 `higher` 配对 $\text{nums}[0] + 2k$ 必在 `nums` 中出现，于是合法的 $2k$ 只能取自 $\{\text{nums}[j] - \text{nums}[0] : j > 0\}$。

**观察二（$2k$ 为正偶数，候选可剪枝）**：$k$ 是正整数 ⇒ $2k \ge 2$ 且为偶数。候选中差非正、差为奇数的直接跳过；相同差值去重后，候选至多 $2n - 1$ 个。

**观察三（固定 $2k$ 后是「被迫选择」的贪心）**：固定候选 $d = 2k$ 后，问题变为把 $2n$ 个数**完美匹配**成 $n$ 对、每对差恰为 $d$。每次取**最小未配对元素** $x$：比它小的值都已配完，它不可能是任何已处理 `lower` 的 `higher`（那些配对值 $= \text{lower} + d$ 已被消耗），故 $x$ **只能是 `lower`**，其配对只能是 $x + d$——身份与配对双重唯一，无需交换论证。

$$\boxed{\text{排序后逐个贪心：} x \text{ 为最小未用元素} \Rightarrow x \text{ 当 lower，配对 } x + d,\ \text{arr} \leftarrow x + d/2}$$

> 💡 **为何不用担心「假阳性」？** 若某个错误的 $k$ 也配满了 $n$ 对，那这 $n$ 对每对差恰为 $2k$，取中点 $x + k$ 即得到合法 `arr`（`lower` = 中点 $-k$、`higher` = 中点 $+k$ 重组恰为 `nums` 的排列）。所以**任何配满的方案都对应一组真实解**——题目只要求返回任一解，正中下怀，配满即是终止条件。

### 3.3 算法流程：排序 → 枚举候选 → 双指针匹配

![算法流程：排序、枚举候选、双指针匹配、配满即返回](images/wc273_q4_two_pointer_flow.svg)

1. **排序** `nums`（$O(n \log n)$）。
2. **枚举候选** $d = \text{nums}[j] - \text{nums}[0]$（$j = 1 \dots 2n-1$）：跳过 $d \le 0$、$d$ 为奇数、与前一候选重复的 $j$。
3. **双指针匹配**（对每个候选 $d$，记 $k = d/2$）：
   - 指针 $i$ 依序扫描，遇到**未标记**的位置即作为本轮 `lower`（它就是当前最小未用元素）；
   - 指针 $p$ **单调向右推进**，跳过已标记或值小于 $\text{nums}[i] + d$ 的位置，停在首个可能的位置；
   - 若 $\text{nums}[p] = \text{nums}[i] + d$：配对成功，标记 `used[i] = used[p] = true`，记录 $\text{arr} \leftarrow \text{nums}[i] + k$；
   - 若 $p$ 推到头或值对不上：该候选失败，换下一个候选。
4. 某候选**配满 $n$ 对**即返回 `arr`；题目保证有解，必有一个候选成功。

> 💡 **$p$ 为什么不用回退？** $p$ 被跳过的位置只有两种：已标记（永远不能再配）或值 $< \text{nums}[i] + d$（后续 `lower` 只会更大，目标值只增不减，这些位置永远追不上）。因此 $p$ 在单个候选内总移动量是 $O(n)$，单次验证线性。注意**换候选时 $p$ 必须归零重置**。

### 3.4 示例演算

![示例演算：候选 d=2 的三步配对与候选 d=4 的失败](images/wc273_q4_matching_walkthrough.svg)

以示例 1 演示，排序后 `nums = [2,4,6,8,10,12]`。$j = 1$ 给出首个候选 $d = 2$（$k = 1$）：

| 步骤 | $i$（lower） | 目标 $\text{nums}[i] + d$ | $p$ 停在 | 动作 |
|------|-------------|---------------------------|----------|------|
| 1 | $0$（值 $2$） | $4$ | 下标 $1$（值 $4$） | 配对 $(2,4)$，`arr ← [3]` |
| 2 | $2$（值 $6$） | $8$ | 下标 $3$（值 $8$） | 配对 $(6,8)$，`arr ← [3,7]` |
| 3 | $4$（值 $10$） | $12$ | 下标 $5$（值 $12$） | 配对 $(10,12)$，`arr ← [3,7,11]` |

配满 $n = 3$ 对，返回 `[3,7,11]`。每步 $i$ 都落在「当前最小未用元素」上，$p$ 一路向右从未回退——$i$ 与 $p$ 的总移动量都是线性。

**失败候选的样子**（若首个候选不巧失败）：试 $d = 4$（$k = 2$），$2$ 配 $6$、$4$ 配 $8$ 皆成功，但 $10$ 需要 $14$，而 $14 \notin \text{nums}$ → 配不满 $n$ 对 → 该候选作废，回到枚举换下一个。**部分匹配不算成功**，这是实现里最容易埋 bug 的地方（§8 第 4 条）。

## 4. 算法细节

1. **候选剪枝三连**：$d = \text{nums}[j] - \text{nums}[0]$ 需同时满足 $d > 0$（排除 $k = 0$）、$d$ 为偶数（$k$ 是整数）、$\text{nums}[j] \ne \text{nums}[j-1]$（排序后相邻去重，同一差值只试一次）。三条都只是加速与合法性过滤，不影响正确性——错误候选至多「白跑一趟」然后失败。
2. **双指针不变式**：处理未标记的 $i$ 时，所有下标 $< i$ 的值 $\le \text{nums}[i] < \text{nums}[i] + d$，故配对下标必然 $> i$，$p$ 从当前位置向右推进即可；且 $p$ 跳过的未标记位置值都太小，**未来也不可能成为任何配对**（目标值单调不减）。两个指针各自走满至多一趟，单候选验证 $O(n)$。
3. **`used` 标记数组**：等价于「从多重集合里删除已配元素」，但免去哈希开销；换候选时整体清零（C++ 用 `fill`，Python 重建列表）。
4. **`arr` 元素 = 中点**：每对 $(a, b) = (\text{nums}[i], \text{nums}[i] + d)$，取 $a + d/2 = (a+b)/2$，即 `lower + k`，无需再算一次除法求中点。
5. **溢出审计（C++）**：$\text{nums}[i] \le 10^9$、$d \le 10^9$，故 $\text{nums}[i] + d$ 可达 $2 \times 10^9$——虽小于 `INT_MAX`（约 $2.147 \times 10^9$）但已临界，把 $d$ 声明为 `long long` 让加法与比较全程在 64 位下进行最稳妥。结果 $a + d/2 < 10^9$ 落回 `int` 安全。Python 整数任意精度，免疫此坑。
6. **两种实现对照**：本题固定 $d$ 后的贪心既可写成上述双指针，也可写成「频率表 + 升序键批量消耗」（每日版 `../solution/2101-2200/2122_还原原数组.md` 的主线，对应官方标签里的 Hash Table）。两者复杂度同阶：频率表版贴近 2007 一族「还原数组」题的通用模板、便于讲解；双指针版常数更小、额外空间只有一个 `used` 数组。

## 5. 正确性证明

以下均设 `nums` 已升序排序，长度 $m = 2n$，并把「合法方案」定义为：存在正整数 $k$ 与数组 `arr`，使 `nums` 的多重集合等于 $\{\text{arr}[i] - k\} \cup \{\text{arr}[i] + k\}$。

**引理 1（最小值属 lower）**：在任何合法方案中，$\text{nums}[0] = \min(\text{nums})$ 是某个 `lower[i]`。

**证明**：设 $\text{arr}_{\min} = \min(\text{arr})$。对一切 $i$，$\text{arr}[i] - k \ge \text{arr}_{\min} - k$ 且 $\text{arr}[i] + k > \text{arr}_{\min} - k$（$k \ge 1$），故 $\min(\text{nums}) = \text{arr}_{\min} - k$，它恰是 `lower` 中 $\text{arr}_{\min}$ 对应的元素。∎

**引理 2（候选覆盖）**：若 $(k, \text{arr})$ 是合法方案，则存在 $j \ge 1$ 使 $2k = \text{nums}[j] - \text{nums}[0]$，且该差值为正偶数。

**证明**：由引理 1，$\text{nums}[0]$ 是 `lower` 元素，设 $\text{nums}[0] = \text{arr}[t] - k$，则其同下标的 `higher` 元素 $\text{arr}[t] + k = \text{nums}[0] + 2k$ 出现在 `nums` 中，记其某个出现位置为 $j$，即得 $2k = \text{nums}[j] - \text{nums}[0]$。又 $k \ge 1$，故差为正偶数。∎

**引理 3（贪心匹配的完备性）**：固定 $d > 0$，若多重集合 $M$（$|M| = 2n$）能划分成 $n$ 对、每对差恰为 $d$，则「每次取最小剩余元素 $x$ 作 `lower`、配掉一个 $x + d$」的贪心必然成功。

**证明**：对剩余元素个数归纳。设 $M$ 存在完美划分，取 $M$ 的最小值 $x$。若某个 $x$ 作为 pair 中较大的一方，其配对为 $x - d < x \notin M$，矛盾；故划分中每个 $x$ 都与一个 $x + d$ 配对，从而 $M$ 中 $x + d$ 的重数不小于 $x$ 的重数，贪心此步可行。删去这些 $(x, x+d)$ 对后，原划分的限制仍是剩余多重集合的完美划分，归纳假设适用，贪心全程成功。∎

**定理（算法正确且完备）**：算法返回的 `arr` 是合法方案；且只要存在合法方案，算法必返回其中之一。

**证明**：**完备性**：设存在合法方案，由引理 2 其 $2k$ 对应的候选 $d$ 必被枚举到（剪枝只排除 $d \le 0$、奇数、重复，合法 $d$ 均存活）；由引理 3，对该候选贪心配满 $n$ 对，算法返回。**正确性**：算法只在配满 $n$ 对时返回，此时 `nums` 被划分成 $n$ 对 $(a, b)$，$b - a = d = 2k$ 且 $k = d/2 \ge 1$ 为正整数；取 $\text{arr}[i] = a + k$，则每对恰为 $(\text{arr}[i] - k, \text{arr}[i] + k)$，重组即 `nums` 的多重集合，是合法方案。∎

> 💡 证明骨架是「**锁定身份 → 压缩候选 → 被迫贪心 → 无假阳性**」四段式：引理 1、2 负责「不漏」（正确解必在搜索空间内），引理 3 负责「必中」（搜索空间内任取一个候选都能被线性验证），定理收口「配满即真解」。「被迫选择」型贪心（每步唯一合法动作）比交换论证更强，与 2007 一族还原数组题共享同一条论证链。

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。排序 $O(n \log n)$ 非主项；去重后候选至多 $m - 1 = 2n - 1$ 个，每个候选的双指针验证中 $i$、$p$ 各自至多推进 $m$ 步，单次 $O(n)$，合计 $O(n^2)$。$n = 1000$ 时约 $4 \times 10^6$ 次基本操作，宽裕。
- **空间复杂度**：$O(n)$。`used` 标记数组 $m$ 个布尔、返回数组 $n$ 个元素；不计输出则仅 `used` 一项。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> recoverArray(vector<int>& nums) {
        int m = nums.size();
        sort(nums.begin(), nums.end());
        vector<int> arr;
        vector<bool> used(m);
        for (int j = 1; j < m; ++j) {
            long long d = nums[j] - nums[0];              // d = 2k，64 位防临界溢出
            if (d == 0 || d % 2 || (j > 1 && nums[j] == nums[j - 1])) continue;
            long long k = d / 2;
            fill(used.begin(), used.end(), false);        // 换候选必须整体重置
            arr.clear();
            int p = 0;                                    // 配对指针：单候选内只进不退
            bool ok = true;
            for (int i = 0; i < m; ++i) {
                if (used[i]) continue;                    // i = 当前最小未用元素 → lower
                while (p < m && (used[p] || nums[p] < nums[i] + d)) ++p;
                if (p == m || nums[p] != nums[i] + d) { ok = false; break; }
                used[i] = used[p] = true;
                arr.push_back((int)(nums[i] + k));        // 中点 = lower + k
            }
            if (ok) return arr;                           // 必须配满 n 对才算成功
        }
        return {};                                        // 题目保证有解，不会到达
    }
};
```

### Python

```python
class Solution:
    def recoverArray(self, nums: List[int]) -> List[int]:
        nums.sort()
        m = len(nums)
        for j in range(1, m):
            d = nums[j] - nums[0]                         # d = 2k
            if d == 0 or d % 2 or (j > 1 and nums[j] == nums[j - 1]):
                continue
            k = d // 2
            used = [False] * m                            # 换候选整体重建
            arr = []
            p = 0                                         # 配对指针：单候选内只进不退
            for i in range(m):
                if used[i]:
                    continue                              # i = 当前最小未用元素 → lower
                while p < m and (used[p] or nums[p] < nums[i] + d):
                    p += 1
                if p == m or nums[p] != nums[i] + d:
                    break                                 # 此候选失败，换下一个
                used[i] = used[p] = True
                arr.append(nums[i] + k)                   # 中点 = lower + k
            else:
                return arr                                # for-else：正常跑完 = 配满 n 对
        return []                                         # 题目保证有解，不会执行
```

## 8. 边界情况与易错点

1. **$k = 0$ 反例（示例 2）**：`nums = [1,1,3,3]` 若取 `arr = [1,3]` 则 $k = 0$ 非法。候选 $d = 0$（含 $\text{nums}[1] = \text{nums}[0]$ 的重复值情形）必须跳过——`d == 0` 这半句判断不能省。
2. **部分匹配误当成功**：内层循环中途 `break`（失败）与正常结束（配满）必须区分。Python 用 `for-else`（`break` 会跳过 `else`）；C++ 用 `ok` 标志。若混用，失败候选残留的部分 `arr` 会被当答案返回——示例 1 的 $d = 4$ 就会错误输出 `[4,6]` 一类残缺结果。
3. **`p` 忘记按候选重置**：`p` 只在单个候选内单调；换候选后必须归零，否则带着上一候选的进度搜索，必然错判。
4. **候选去重漏写**：不给 $\text{nums}[j] = \text{nums}[j-1]$ 去重不影响正确性（同一差值多跑几遍），但最坏会白跑 $O(n)$ 次 $O(n)$ 验证；去重一行搞定，别省。
5. **加法溢出（C++）**：$\text{nums}[i] + d$ 峰值约 $2 \times 10^9$，贴着 `INT_MAX`；把 `d` 声明为 `long long` 让整个表达式提升到 64 位即可，勿写成两个 `int` 相加后再比较。
6. **答案不唯一**：示例 1 有 `[3,7,11]`（$k=1$）与 `[5,7,9]`（$k=3$）两组解，返回任一即可——不要试图枚举或去重所有解，也不要对拍时误判多解为错误。
7. **$n = 1$（$m = 2$）**：单对配对自动成立（示例 3），双指针天然处理，无需特判。
8. **别枚举全体两两之差**：候选只需 $\text{nums}[j] - \text{nums}[0]$（引理 1 保证最小值必属 `lower`），枚举所有 $i < j$ 的差是 $O(n^2)$ 个候选、总 $O(n^3)$，$n = 1000$ 直接超时。

**延伸思考**：若允许 $k = 0$，`lower` 与 `higher` 相同，问题退化为「能否把 `nums` 的多重集合对半复制」，判定条件与返回方式都要重写；若还知道 `lower` 与 `higher` 的元素**个数不等**（比如 $n_1 + n_2 = 2n$），「最小值必属元素多的一方」的引理失效，需要更细的计数论证；若要求返回**字典序最小**的 `arr`，则不能在首个配满候选处提前返回，须对所有候选求出 `arr` 排序取最小；若 $n$ 放大到 $10^5$，$O(n^2)$ 的候选枚举不再可行，可对「$\text{nums}[0]$ 的配对值」用随机化或按值域分桶的思路再降一阶。
