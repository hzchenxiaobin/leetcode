# LeetCode 执行所有后缀指令 题解

## 1. 题目概述

- **标题 / 题号**：执行所有后缀指令（#2120，medium）
- **链接**：https://leetcode.cn/problems/execution-of-all-suffix-instructions-staying-in-a-grid/
- **来源**：LeetCode 第 273 场周赛 Q2
- **难度**：中等
- **标签**：字符串、模拟

**题意**：给定 $n \times n$ 网格与起点 `startPos`（`startPos = [startrow, startcol]`），以及长度为 $m$ 的指令串 $s$，每条指令为 `L` / `R` / `U` / `D`（左右上下各走一格）。机器人**最开始站在 `startPos`**，可以从 $s$ 的**任意第 $i$ 条指令开始**逐条执行直到串尾；一旦「下一条指令会把机器人移出网格」，机器人立即停下——该指令**不执行**。返回长度为 $m$ 的数组 `answer`，其中 `answer[i]` 是从第 $i$ 条指令开始时**实际执行的指令条数**。

**约束**：

- $m = |s|$，$1 \le n, m \le 500$
- `startPos.length == 2`，$0 \le \text{startrow}, \text{startcol} < n$（起点保证在网格内）
- $s$ 仅由 `L`、`R`、`U`、`D` 组成

> 💡 本题是标准的「阅读理解 + 模拟」：$m \le 500$ 明示 $O(m^2)$ 可过，真正的考点是把两句话读准——**「从第 $i$ 条开始」意味着出发位置永远是 `startPos`**（而不是先走完前 $i$ 条再继续），以及**「导致出界的那条指令」既不执行也不计数**。把这两点读对，代码只剩一个双重循环。

## 2. 示例

**示例 1**

```text
输入：n = 3, startPos = [0,1], s = "RRDDLU"
输出：[1,5,4,3,1,0]
解释：机器人从 (0,1) 出发，从第 i 条指令开始执行：
- i=0: "RRDDLU"，执行 1 条 R 到 (0,2) 后，下一条 R 将出界，停止。
- i=1: "RDDLU"，5 条全部执行，终点 (1,1)。
- i=2: "DDLU"，4 条全部执行，终点 (1,0)。
- i=3: "DLU"，3 条全部执行，终点 (0,0)。
- i=4: "LU"，执行 1 条 L 到 (0,0) 后，U 将出界，停止。
- i=5: "U"，第 1 条指令即出界，执行 0 条。
```

**示例 2**

```text
输入：n = 2, startPos = [1,1], s = "LURD"
输出：[4,1,0,0]
解释：
- 0: "LURD" 4 条全部执行
- 1: "URD"  执行 1 条 U 后，R 将出界
- 2: "RD"   第 1 条 R 即出界
- 3: "D"    第 1 条 D 即出界
```

**示例 3**

```text
输入：n = 1, startPos = [0,0], s = "LRUD"
输出：[0,0,0,0]
解释：1×1 网格中任何一条指令都会出界，答案全为 0。
```

> ⚠️ **官方解释的一处笔误**：示例 1 的官方解释称 $i=1$、$i=2$「最终到达 $(0,0)$」。按题意逐步模拟，两者的终点分别是 $(1,1)$ 与 $(1,0)$；$(0,0)$ 实为 $i=3$ 的终点（疑似复制粘贴笔误）。**答案数组 $[1,5,4,3,1,0]$ 本身无误**，逐格核对时别被带偏。

## 3. 解题思路

### 3.1 朴素思路：逐后缀完整模拟（就是正解）

最直接的做法与题意一一对应：枚举起点下标 $i \in [0, m)$，让机器人从 `startPos` 出发，逐条执行 $s[i], s[i+1], \dots$，每执行一条就检查落点，出界即停。

一次后缀模拟至多走 $m - i$ 步，总步数为

$$\sum_{i=0}^{m-1}(m-i) = \frac{m(m+1)}{2} \le \frac{500 \times 501}{2} = 125\,250$$

每步只是常数次加减与比较。与大多数题目「先算暴力复杂度、再找优化」的节奏不同，这个朴素做法**就是本题的正解**——数据范围 $m \le 500$ 摆明了给 $O(m^2)$ 留足了空间。因此本题的功夫不在「怎么优化」，而在「怎么把语义读对、把循环写干净」。当然，仍要先把两件事想透：为什么各后缀**无法共享**计算（3.2 观察一），以及「数步数」的等价刻画（3.2 观察二）。

### 3.2 核心观察：重开一局 + 首个出界下标差

![核心观察：从第 i 条开始 = 重开一局，出发永远是 startPos](images/wc273_q2_restart_concept.svg)

**观察一（重开一局）**：题面说「机器人**最开始**在 `startPos`」「**可以从任一第 $i$ 条指令开始执行**」——两句合起来：无论选哪个 $i$，机器人都站在 `startPos` 原地不动，直接从 $s[i]$ 开始执行，$s[0..i-1]$ 被**整段跳过**、不留任何痕迹。这直接排除最常见的误读（先走前 $i$ 条再继续），也说明**各后缀的轨迹没有任何公共前缀**——后缀 $i$ 与 $i+1$ 的行走互不相干，不存在「算一次、处处用」的共享结构。

**观察二（首个出界下标差）**：把「数执行了几条」改写为「定位首个出界事件」。定义

$$j_i = \min\{\, k \in [i, m) : \text{执行 } s[k] \text{ 后落地在网格外} \,\} \quad (\text{集合为空则 } j_i = m)$$

则从第 $i$ 条开始的机器人恰好执行 $s[i..j_i-1]$，共 $j_i - i$ 条，即 $\text{answer}[i] = j_i - i$（证明见 §5）。这个改写的妙处在于**统一了两个出口**：中途出界时 $k$ 停在首个出界指令上，走完全程时 $k = m$，两种情况的答案都是 $k - i$——代码里一个特判都不用写（见 §4 第 3 条）。

顺带一提，$j_i$ 关于 $i$ **不单调**（示例 1 中 $j$ 序列为 $1,6,6,6,5,6$，在 $i=4$ 处回落），因此「用相邻后缀的结果推导当前后缀」的贪心复用也不成立，进一步印证观察一：老老实实逐个模拟。

最后留一个伏笔：从 $i$ 出发执行到第 $k$ 条后的位置可写成 $\text{start} + S(k+1) - S(i)$（$S$ 为指令位移的前缀和），出界判定只与**前缀和之差**是否落在盒 $[-r_0,\, n-1-r_0] \times [-c_0,\, n-1-c_0]$ 外有关——这是把 $O(m^2)$ 优化到 $O(m \log m)$ 的钥匙，见「相关题目与扩展」。

### 3.3 算法流程：试探移动 + 越界即停

![算法流程：外层枚举 i，内层试探移动 + 越界即停](images/wc273_q2_simulation_flow.svg)

结合观察二，算法就是一个「外层枚举 + 内层早停」的双重循环：

1. 外层：枚举起点下标 $i = 0, 1, \dots, m-1$；
2. 进入后缀 $i$ 前，**重置** $(r, c) \leftarrow \text{startPos}$（观察一的推论），并令 $k \leftarrow i$；
3. 内层：只要 $k < m$，就**试探性**地按 $s[k]$ 移动 $(r, c)$；若落点出界则 `break`（$s[k]$ 未执行）；否则 $k \leftarrow k + 1$ 继续；
4. 两个出口汇合于同一行赋值：$\text{answer}[i] \leftarrow k - i$。

「先动再判」是关键的小技巧：出界后 $(r, c)$ 已是脏值，但该后缀的模拟到此为止、坐标不再被读取，因此**无需回滚**；同时这个顺序天然把「未执行的那条指令」排除在计数之外。

### 3.4 示例演算

![示例演算：n=3 网格上的六条后缀轨迹与 j 序列](images/wc273_q2_example_walkthrough.svg)

以示例 1（$n=3$，$\text{startPos}=(0,1)$，$s=$ `RRDDLU`）走查全部六个后缀：

| $i$ | 后缀 $s[i..]$ | 轨迹（起点 $(0,1)$） | answer[$i$] | $j_i = i + \text{answer}[i]$ |
|-----|---------------|----------------------|-------------|------------------------------|
| 0 | `RRDDLU` | R→$(0,2)$，再 R 出界 ✗ | 1 | 1 |
| 1 | `RDDLU` | R→D→D→L→U，全执行 | 5 | 6 |
| 2 | `DDLU` | D→D→L→U，全执行 | 4 | 6 |
| 3 | `DLU` | D→L→U，全执行 | 3 | 6 |
| 4 | `LU` | L→$(0,0)$，U 出界 ✗ | 1 | 5 |
| 5 | `U` | 第 1 条即出界 ✗ | 0 | 6 |

两个看点：其一，$i=0$ 与 $i=4$ 的答案都是 1，但**停在不同的指令上**（一个被第二条 `R` 挡住、一个被 `U` 挡住），再次说明各后缀互相独立；其二，$j$ 序列 $1,6,6,6,5,6$ 在 $i=4$ 处回落——不单调，任何「复用相邻结果」的算盘都会在这里落空。

## 4. 算法细节

1. **方向映射**：坐标系的 row $0$ 在顶部，因此 `U` 是 $(\Delta r, \Delta c) = (-1, 0)$，`D` 是 $(+1, 0)$，`L` 是 $(0, -1)$，`R` 是 $(0, +1)$。
2. **试探移动，无需回滚**：先按 $s[k]$ 移动再判界，边界检查 $0 \le r < n \ \land\ 0 \le c < n$ 一次覆盖四个方向，不必写四个分支；出界后的脏坐标不会被再读（§3.3）。
3. **统一出口公式**：`answer[i] = k − i` 同时覆盖「break（k 停在首个出界指令，未执行）」与「走完（k = m）」两种结束方式，不需要任何 `if` 特判——这是观察二直接兑现的代码红利。
4. **每轮重置坐标**：`r, c = startPos` 必须写在外层循环体内（观察一的推论）。漏写的话只有 $i = 0$ 正确。
5. **前缀和改写（优化伏笔）**：令 $S(t) = \sum_{u<t} \vec{\delta}(s[u])$（$\vec\delta$ 为方向位移向量），则从 $i$ 出发执行到第 $k$ 条后的位置为 $\text{start} + S(k+1) - S(i)$，于是

   $$\text{出界} \iff S(k+1) - S(i) \notin [-r_0,\, n-1-r_0] \times [-c_0,\, n-1-c_0]$$

   「模拟」被翻译成「区间内首个落在某个盒外的前缀和」。
6. **常数层面**（可忽略）：Python 把方向字典提出循环外、C++ 用 `switch`；$m \le 500$ 时怎么做都在毫秒量级。

## 5. 正确性证明

记网格为 $G = [0, n) \times [0, n)$。对起点下标 $i$，定义**假想位置** $H_i(k)$（$i \le k \le m-1$）为无视停止规则、从 `startPos` 出发连续执行 $s[i..k]$ 后的位置，并约定 $H_i(i-1) = \text{startPos}$；令

$$j_i = \min\{\, k \in [i, m) : H_i(k) \notin G \,\}, \quad \text{集合为空时 } j_i = m$$

**引理 1（轨迹重合）**：机器人实际执行的指令恰好是 $s[i..j_i-1]$，且执行完 $s[i..k]$（$i \le k < j_i$）后位于 $H_i(k)$。

**证明**：对 $k$ 归纳。执行 $s[i]$ 之前，机器人位于 $\text{startPos} = H_i(i-1)$；若 $i < j_i$，由 $j_i$ 的最小性有 $H_i(i) \in G$，停止条件不触发，机器人执行 $s[i]$ 并到达 $H_i(i)$。归纳步：设机器人已执行 $s[i..k-1]$ 且位于 $H_i(k-1)$（$k < j_i$）。停止规则只取决于「执行 $s[k]$ 后是否出界」，即 $H_i(k) \notin G$ 与否；由 $k < j_i$ 知 $H_i(k) \in G$，故机器人执行 $s[k]$ 到达 $H_i(k)$。当 $k = j_i \le m-1$ 时 $H_i(j_i) \notin G$，机器人不执行 $s[j_i]$，停止。∎

**引理 2（计数刻画）**：$\text{answer}[i] = j_i - i$。

**证明**：由引理 1，实际执行的指令为 $s[i..j_i-1]$，共 $j_i - i$ 条；$j_i = m$ 时即 $s[i..m-1]$，共 $m - i$ 条，仍为 $j_i - i$。∎

**定理（模拟算法正确性）**：双重循环算法对每个 $i$ 输出 $j_i - i$。

**证明**：内层循环不变式：「判定第 $k$ 轮时 $(r, c) = H_i(k-1)$，且 $H_i(i), \dots, H_i(k-1) \in G$」。循环体先按 $s[k]$ 移动，使 $(r, c) = H_i(k)$，再检查：若出界则 `break`，由不变式此前所有假想位置均在界内，故此 $k$ 正是 $j_i$，输出 $k - i = j_i - i$；若在界内则 $k$ 自增，不变式保持。若循环推进到 $k = m$ 自然结束，说明 $H_i(i), \dots, H_i(m-1)$ 全在界内，即 $j_i = m$，输出 $m - i = j_i - i$。∎

> 💡 引理 1 的本质是「停止规则只截断、不扭曲轨迹」：实际轨迹是假想轨迹的**初始段**，因此「首个出界事件」是唯一需要定位的对象——这正是前缀和改写（§4 第 5 条）与线段树优化（延伸思考）的入口。

## 6. 复杂度分析

- **时间复杂度**：$O(m^2)$。后缀 $i$ 至多走 $m - i$ 步，总计 $\sum_{i=0}^{m-1}(m-i) = \frac{m(m+1)}{2}$；$m = 500$ 时约 $1.25 \times 10^5$ 次「一次移动 + 一次判界」，远低于任何时限阈值；提前出界只会让实际步数更少。复杂度与 $n$ 无关——$n$ 只出现在边界比较的常数里。
- **空间复杂度**：$O(1)$ 额外空间（不算返回的 `answer` 数组；返回数组本身占 $O(m)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> executeInstructions(int n, vector<int>& startPos, string s) {
        int m = s.size();
        vector<int> answer(m);
        for (int i = 0; i < m; i++) {
            int r = startPos[0], c = startPos[1];
            int k = i;
            while (k < m) {
                if (s[k] == 'L')      c--;
                else if (s[k] == 'R') c++;
                else if (s[k] == 'U') r--;
                else                  r++;
                if (r < 0 || r >= n || c < 0 || c >= n) break;
                k++;
            }
            answer[i] = k - i;   // 统一出口：break 时 k=j_i，走完时 k=m
        }
        return answer;
    }
};
```

### Python

```python
class Solution:
    def executeInstructions(self, n: int, startPos: List[int], s: str) -> List[int]:
        m = len(s)
        dirs = {'L': (0, -1), 'R': (0, 1), 'U': (-1, 0), 'D': (1, 0)}
        answer = []
        for i in range(m):
            r, c = startPos          # 每个后缀都从 startPos 重开一局
            k = i
            while k < m:
                dr, dc = dirs[s[k]]
                r, c = r + dr, c + dc
                if not (0 <= r < n and 0 <= c < n):
                    break
                k += 1
            answer.append(k - i)     # 统一出口：break 时 k=j_i，走完时 k=m
        return answer
```

## 8. 边界情况与易错点

1. **「从第 $i$ 条开始」≠ 先走前 $i$ 条**：机器人永远从 `startPos` 出发直接执行 $s[i]$。按误读实现会整题全错，这是本题头号陷阱（§3.2 观察一）。
2. **出界的指令不执行、不计数**：`answer[i]` 数的是「执行了的」条数。示例 1 的 `answer[0] = 1`（不是 2）与示例 3 的全 0 都是这条语义的哨兵。
3. **U / D 方向别写反**：row 0 在顶部，`U` 使 row 减一、`D` 使 row 加一。可用示例 2 的 $i=1$ 自测：正确答案为 1（`U` 后再 `R` 出界）；若 U/D 写反会得到 0。
4. **每个后缀开始时重置 $(r, c) = \text{startPos}$**：受「复用轨迹」的错误直觉影响最容易忘写；$j_i$ 不单调（§3.4）也说明复用本身不成立。
5. **$n = 1$ 或起点贴边**：可能第一条指令就出界，`answer[i] = 0`；循环在 $k = i$ 时 `break`，输出 $k - i = 0$，天然正确。
6. **别用二分找「首个出界」**：假想轨迹可以先出界再回到界内（如 `R` 走出后 `L` 走回），「在网格内」不随下标单调，二分不合法（正确加速姿势见延伸思考）。
7. **官方解释示例 1 的终点笔误**：$i=1$、$i=2$ 的实际终点是 $(1,1)$、$(1,0)$，不是官方所说的 $(0,0)$；对答案无影响，但逐格核对时别被带偏。

**延伸思考**：若 $m$ 放大到 $2 \times 10^5$ 甚至 $10^6$，$O(m^2)$ 不再可行。由 §4 第 5 条的前缀和改写，$\text{answer}[i] = (\text{首个 } k \ge i \text{ 使 } S(k+1) \text{ 落在以 } S(i) \text{ 为锚的 } n \times n \text{ 盒外}) - i$。注意**不能二分**（§8 第 6 条），正确姿势是对 $S(0..m)$ 建线段树，每个节点维护区间内行/列前缀和的最小值与最大值；查询时自顶向下优先深入左子树——子树四个极值均在盒内即可整体剪枝，否则进入子树定位首个越界点——单次查询 $O(\log m)$，总时间 $O(m \log m)$。「在线段树上二分定位首个违规位置」是值得单独沉淀的手法，与「乘法原理拆维度」「哨兵约束」一样，是网格模拟题的工具箱常客。
