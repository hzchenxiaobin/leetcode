# LeetCode 反转两次的数字 题解

## 1. 题目概述

- **标题 / 题号**：反转两次的数字（#2119，easy）
- **链接**：https://leetcode.cn/problems/a-number-after-a-double-reversal/
- **来源**：LeetCode 第 273 场周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：「反转」一个整数 = 把它的十进制数位倒序排列，且**不保留前导零**（例如 `12300` 反转得 `321`）。给定整数 `num`，先反转得 `reversed1`，再反转 `reversed1` 得 `reversed2`。若 `reversed2 == num` 返回 `true`，否则返回 `false`。

**约束**：

- $0 \le \text{num} \le 10^6$

> 💡 签到题的胜负手在「从题面到代码的最短路径」。本题的题眼藏在「**不保留前导零**」六个字里：反转并非可逆变换，唯一可能丢失的信息就是零——而是否丢失，只取决于 `num` 的**末位**。想通这一点，代码就只剩一行。

## 2. 示例

**示例 1**

```text
输入：num = 526
输出：true
解释：反转 num 得到 625，接着反转 625 得到 526，等于 num。
```

**示例 2**

```text
输入：num = 1800
输出：false
解释：反转 num 得到 81，接着反转 81 得到 18，不等于 num。
```

**示例 3**

```text
输入：num = 0
输出：true
解释：反转 num 得到 0，接着反转 0 得到 0，等于 num。
```

## 3. 解题思路

### 3.1 暴力思路：老实执行两次反转

按题意模拟——实现 `reverse(x)`，连调两次再与原数比较：

```python
class Solution:
    def isSameAfterReversals(self, num: int) -> bool:
        def reverse(x: int) -> int:
            return int(str(x)[::-1])   # int() 天然吞掉前导零
        return reverse(reverse(num)) == num
```

时间 $O(\log_{10}\text{num})$（数位个数），本题必然能过。但题目只问「**能否还原**」，并不需要 `reversed1`、`reversed2` 的具体数值——真正决定答案的信息只有**一个比特**：`num` 的末位是不是 0。暴力法把所有数位都翻了两遍，却只为提取这一个比特，是典型的「没消化题面」。

### 3.2 核心观察：反转是有损变换，丢失的恰是尾随零

![核心观察：反转丢弃前导零，即原数的尾随零永久丢失](images/wc273_q1_double_reverse_concept.svg)

「不保留前导零」意味着反转 $R$ 是一条**有损**信道，且损毁方式高度结构化：

- **末位非零**（如 526）：反转后的首位是原末位（非零），**没有任何数位被丢弃**，信息无损，再反转必然还原；
- **末位为零**（如 1800）：尾随零反转后变成前导零，被整段丢弃，位数不可逆地缩水，之后无论怎么反转都回不去；
- **num = 0**：唯一的特例——0 反转仍是 0，返回 `true`。

把这句话提炼成数学命题（证明见 §5）：$R(R(\text{num}))$ 恰等于 `num` **剥离尾随零后**的结果。于是「两次反转能否还原」被翻译成「`num` 是否没有尾随零」。

### 3.3 算法流程：O(1) 末位判定

![算法流程：不反转，只看末位](images/wc273_q1_decide_flow.svg)

由核心观察，判定流程退化为三个分支：

1. 若 $\text{num} = 0$，返回 `true`（特例）；
2. 否则若 $\text{num} \bmod 10 = 0$，返回 `false`（尾随零必然丢失）；
3. 否则返回 `true`（无损，必然还原）。

一次比较加一次取模，$O(1)$ 读完即判，连反转函数都不用写。

### 3.4 示例演算

![示例演算：526 / 1800 / 0 的两次反转全过程](images/wc273_q1_example_walkthrough.svg)

| num | 第一次反转 $R(\text{num})$ | 第二次反转 $R(R(\text{num}))$ | 判定 | 原因 |
|-----|--------------------------|------------------------------|------|------|
| 526 | 625 | 526 | `true` | 末位 $6 \ne 0$，两次反转零丢失 |
| 1800 | 81（0081 丢前导零） | 18 | `false` | 两个尾随零永久丢失 |
| 0 | 0 | 0 | `true` | 唯一特例：0 反转仍是 0 |

三个官方示例恰好覆盖全部三类情形，也暗示了正解的分类讨论结构。

## 4. 算法细节

1. **判定式**：$\text{num} = 0 \ \lor\ \text{num} \bmod 10 \ne 0$。两个条件缺一不可——$\text{num} = 0$ 是「末位为零但仍能还原」的唯一例外（§8 第 1 条）。
2. **为什么只看末位、不必看其他数位**：由剥离公式（引理 2），$R(R(\text{num}))$ 只依赖 `num` 剥离尾随零后的值 $a$，而 $a = a \cdot 10^t$ 当且仅当 $t = 0$。中间数位在两次反转中**对称抵消**，与判定无关。
3. **若坚持暴力**：字符串写法 `int(str(x)[::-1])` 依赖 `int()` 吞掉前导零才正确；数学写法（弹出/压入，同第 7 题）在 $x = 0$ 时循环体不执行、返回 0，同样正确——但需当心把循环条件写错（如 `while x > 1`）会在个位数上出错。
4. **数据范围的角色**：$\text{num} \le 10^6$ 保证任何做法都能过，本题的区分度不在复杂度，而在**能否想到 $O(1)$ 判定**；同时取模与比较绝无溢出问题。

## 5. 正确性证明

记 $R(x)$ 为反转操作（数位倒序 + 丢弃前导零），约定 $R(0) = 0$。对 $\text{num} > 0$，写 $\text{num} = a \cdot 10^t$，其中 $t \ge 0$ 为尾随零个数，$a \ge 1$ 且 $a \bmod 10 \ne 0$（即 $a$ 是 `num` 剥离尾随零后的结果）。

**引理 1**：对任何 $y > 0$，$R(y)$ 的末位非零。

**证明**：设 $y$ 的十进制表示为 $d_{k-1} d_{k-2} \cdots d_1 d_0$（$d_{k-1} \ne 0$）。反转串为 $d_0 d_1 \cdots d_{k-1}$，丢弃前导零只作用于串的**开头**；而串的**末位**是 $d_{k-1} \ne 0$，不受丢弃影响。故 $R(y)$ 的末位为 $d_{k-1} \ne 0$。∎

**引理 2（剥离公式）**：$\text{num} > 0$ 时，$R(R(\text{num})) = a$，即两次反转恰好剥掉全部尾随零。

**证明**：`num` 的数字串 =「$a$ 的各位」后接 $t$ 个 '0'。第一次反转得「$t$ 个 '0'」+「$a$ 的各位倒序」；丢弃 $t$ 个前导零后恰剩「$a$ 的各位倒序」。由 $a \bmod 10 \ne 0$，该串首位（即 $a$ 的末位）非零，无进一步丢弃，故 $R(\text{num})$ 的数字串**就是** $a$ 的倒序串。再反转一次：$R(\text{num})$ 的倒序串 = $a$ 的原序串，其首位 = $a$ 的首位 $\ne 0$，同样无丢弃。于是 $R(R(\text{num})) = a$。∎

**定理**：$R(R(\text{num})) = \text{num}$ 当且仅当 $\text{num} = 0$ 或 $\text{num} \bmod 10 \ne 0$。

**证明**：$\text{num} = 0$ 时 $R(R(0)) = 0$，成立。$\text{num} > 0$ 时由引理 2，$R(R(\text{num})) = a$，而 $\text{num} = a \cdot 10^t$：若 $t = 0$ 则 $a = \text{num}$，成立；若 $t \ge 1$，则由 $a \ge 1$ 得 $a \cdot 10^t \ge 10a > a$，不成立。又 $t = 0 \iff \text{num} \bmod 10 \ne 0$。∎

> 💡 引理 2 是本题的「压缩包」：它把「执行两次翻转」这个 $O(\log)$ 的过程压缩成「剥离尾随零」这个 $O(1)$ 可判定的性质。证明的关键结构是**对称抵消**——丢完前导零后，剩下的串再翻一次必然回到原序。

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。一次 `== 0` 比较加一次 `% 10` 取模，与输入规模无关；对照暴力模拟的 $O(\log_{10} \text{num})$（需遍历全部数位）。
- **空间复杂度**：$O(1)$。不引入任何字符串副本或辅助变量；暴力法需 $O(\log_{10} \text{num})$ 存反转串。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isSameAfterReversals(int num) {
        return num == 0 || num % 10 != 0;
    }
};
```

### Python

```python
class Solution:
    def isSameAfterReversals(self, num: int) -> bool:
        return num == 0 or num % 10 != 0
```

## 8. 边界情况与易错点

1. **`num = 0` 是头号陷阱**：它末位为 0，按「末位为零 → false」会错判，但正确答案是 `true`（0 反转仍是 0）。判定式必须写成 `num == 0 || num % 10 != 0`，落掉前半支在示例 3 上直接挂掉。
2. **别把本题当成回文数**：526 不是回文，但答案 `true`——本题判定的是 $R(R(x)) = x$（两次反转），不是 $R(x) = x$（回文）。把两者混淆是最常见的思路污染。
3. **上界 $10^6$ 本身是末位为零的输入**（1000000），答案是 `false`，可作快速自测。
4. **暴力法的隐性依赖**：手写逐位翻转时若忘了处理前导零（例如翻完拼成字符串直接比较），会对 1800 类输入判反；`int(str(x)[::-1])` 与弹出/压入写法则天然正确。
5. **负数不存在**：约束保证 $\text{num} \ge 0$，无需讨论符号；若放开到负数，还需先约定反转对符号的处理（对照第 7 题整数反转）。
