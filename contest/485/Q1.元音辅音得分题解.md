# LeetCode 元音辅音得分 题解

## 1. 题目概述

- **标题 / 题号**：元音辅音得分（#3813，easy）
- **链接**：https://leetcode.cn/problems/vowel-consonant-score/
- **来源**：LeetCode 第 485 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定字符串 `s`（由小写英文字母、空格和数字组成）。令 $v$ 表示 `s` 中**元音字母**（`a/e/i/o/u`）的数量，$c` 表示**辅音字母**（英文字母表中除元音外的其他字母）的数量。得分定义：$c > 0$ 时 $\text{score} = \lfloor v / c \rfloor$（向下取整）；$c = 0$ 时 $\text{score} = 0$。返回这个得分。

**约束**：

- $1 \le s.length \le 100$
- `s` 仅由小写英文字母、空格和数字组成

> ⚠️ **审题关键**：① **空格和数字既不是元音也不是辅音**——题面写明辅音是「英文字母表中除元音外的其他字母」，只有字母参与分类，这是全题唯一的陷阱；② $c = 0$ 时**直接得 0**，既是题意规定，也顺带躲开除零。

## 2. 示例

**示例 1**

```text
输入：s = "cooear"
输出：2
解释：v = 4（'o','o','e','a'），c = 2（'c','r'），⌊4 / 2⌋ = 2。
```

**示例 2**

```text
输入：s = "axeyizou"
输出：1
解释：v = 5（'a','e','i','o','u'），c = 3（'x','y','z'），⌊5 / 3⌋ = 1。
```

**示例 3**

```text
输入：s = "au 123"
输出：0
解释：'a','u' 是元音；空格和数字不是字母，两边都不算
      → v = 2，c = 0 → 得分为 0（除零保护分支）。
```

## 3. 解题思路

签到题的目标是**从题面到代码的最短路径 + 零调试一次过**。算法本身没有难度，全部风险集中在两处：**字符分类的顺序**与**除零**。

### 3.1 暴力思路：照定义直译

按题面分两步：第一趟数出 $v$（统计 `'a','e','i','o','u'` 的出现次数），第二趟数出 $c$（统计「是字母但不是元音」的次数），最后按定义算分。$n \le 100$，两趟、三趟都是线性，怎么写都能过——**效率不是本题考点**，错的人全错在分类上：

- 若写成「是元音则 $v{+}{+}$，**否则** $c{+}{+}$」——空格和数字会被误计入 $c$。官方示例 3 恰好测不出这个 bug（误算 $v=2$、$c=3$，$\lfloor 2/3 \rfloor = 0$ 碰巧等于正确答案 0），隐蔽性极强；但换个输入如 `"ab 1"`：正确分类 $v=1$、$c=1$ 得 1，误分类 $v=1$、$c=3$ 得 0，当场翻车；
- 若忘了 $c = 0$ 特判——整数除以零，C++ 是未定义行为，Python 直接抛 `ZeroDivisionError`。

所以朴素做法「能过」但「写错很常见」：先把「是不是字母」这道门守住，再谈元音 / 辅音。

### 3.2 核心观察：一趟扫描 + 三分类 + 除零保护

![核心观察：字符三分——空格与数字在「是字母」门口就被拦下](images/wc485_q1_three_bucket_concept.svg)

三个要点：

1. **三分类**：每个字符恰好落入三个桶之一——元音（计入 $v$）、辅音（计入 $c$）、空格/数字（两边都不算）。判定顺序必须是「**先 `isalpha`，再判元音**」：非字母在门口就被拦下，永远轮不到进辅音桶；
2. **一趟统计**：$v$、$c$ 两个计数器随扫随加，一趟 $O(n)$ 完成，无需两趟、无需容器；
3. **收尾判定**：扫完后若 $c = 0$ 返回 0（除零保护），否则返回整数除法 $v / c$。

> 💡 $v$、$c$ 均非负，C++ 的 `/`（向零截断）与 Python 的 `//`（向下取整）结果一致，都等于 $\lfloor v/c \rfloor$——不需要任何取整函数。

### 3.3 算法流程

![算法流程：先过「是字母」门，再分元音辅音，收尾防除零](images/wc485_q1_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `v ← 0`，`c ← 0` | 两个计数器 |
| ② 取字符 | 逐个取 `ch` | 至多 $n$ 轮 |
| ③ 门卫判定 | `ch` 是字母？否 → 跳过 | **空格/数字在这里被拦下** |
| ④ 二分 | 是元音？是 → `v++`；否 → `c++` | 只有字母才走到这一步 |
| ⑤ 收尾 | `c > 0` ？返回 `v / c` ：返回 `0` | 除零保护 |

![示例演算：官方样例走查与反例对照](images/wc485_q1_example_walkthrough.svg)

对示例 2 `s = "axeyizou"` 逐字符走查：

| 字符 | a | x | e | y | i | z | o | u |
|------|---|---|---|---|---|---|---|---|
| 分类 | 元音 | 辅音 | 元音 | 辅音 | 元音 | 辅音 | 元音 | 元音 |
| $v$ | 1 | · | 2 | · | 3 | · | 4 | 5 |
| $c$ | · | 1 | · | 2 | · | 3 | · | · |

扫完得 $v = 5$、$c = 3$，$\text{score} = \lfloor 5/3 \rfloor = 1$ ✓

示例 3 `"au 123"`：空格和数字全被门卫拦下，$v = 2$、$c = 0$，走保护分支返回 0 ✓

## 4. 算法细节

1. **门卫先行**：`if (!isalpha(ch)) continue;` 必须写在元音判定**之前**——这一行是全题正确性的支点，它保证走到「辅音」分支的字符一定是字母。
2. **元音判定任选**：五连比较 `ch=='a' || ch=='e' || ...`（编译器可优化为位运算）、`ch in "aeiou"`、`set('aeiou')`、`switch`，都是 $O(1)$ 且常数极小，选顺手的即可。
3. **收尾判定压进返回式**：`return c == 0 ? 0 : v / c;`——三元表达式把「除零保护」收进一行，无需独立 if 分支。
4. **整数除法语义**：$v$、$c$ 非负，C++ `/` 向零截断 = Python `//` 向下取整 = $\lfloor v/c \rfloor$，跨语言行为一致；只有可能出现负数时两者才分裂。
5. **C++ ctype 卫生习惯**：`isalpha` 系列要求入参为 `unsigned char` 或 `EOF`，直接传 `char` 在有符号 char 平台是 UB。本题字符集（小写字母/空格/数字）恒非负不出事，但 `static_cast<unsigned char>(ch)` 是习惯性防御。
6. **Python 一行流**：`v = sum(map('aeiou'.__contains__, s))`，`c = sum(map(str.isalpha, s)) - v`——「辅音数 = 字母数 − 元音数」把三分类压成两个布尔计数，仍为 $O(n)$。

## 5. 正确性证明

**引理 1（计数不变量）**：扫描完任意前缀 $s[0..k-1]$ 后，$v$、$c$ 分别等于该前缀中元音、辅音的个数。

**证明**：对 $k$ 归纳。$k = 0$ 时 $v = c = 0$，平凡成立。设 $k$ 时结论成立，考察第 $k+1$ 个字符 $ch$：若 $ch$ 非字母，两个计数器均不变，而按题意它既不是元音也不是辅音（辅音定义为英文字母表中除元音外的字母），结论保持；若 $ch \in \{\texttt{a},\texttt{e},\texttt{i},\texttt{o},\texttt{u}\}$，仅 $v$ 加一，且 $ch$ 恰是一个元音；否则 $ch$ 是非元音字母即辅音，仅 $c$ 加一。三种情形结论均保持。∎

**引理 2（非负整除即 floor）**：当 $v, c \ge 0$ 且 $c \ge 1$ 时，C++ 的 `v / c` 与 Python 的 `v // c` 均等于 $\lfloor v/c \rfloor$。

**证明**：Python 的 `//` 定义即向下取整。C++ 整数除法向零截断：设 $v = qc + r$（$0 \le r < c$），则商为 $q$；又 $q \le v/c < q + 1$ 且 $q$ 为整数，故 $q = \lfloor v/c \rfloor$。被除数非负、除数为正时截断与 floor 一致。∎

**定理**：算法返回值等于题目定义的得分。

**证明**：扫描终止时，由引理 1（取 $k = n$），$v$、$c$ 即整串中元音与辅音的个数。若 $c = 0$：算法走保护分支返回 0，与定义一致。若 $c > 0$：算法返回 `v / c`，由引理 2 其值为 $\lfloor v/c \rfloor$，亦与定义一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个字符一次门卫判定 + 至多一次元音判定，均为 $O(1)$。这已是信息论下界——任何字符都可能改变 $v$ 或 $c$，必须全部读过。
- **空间复杂度**：$O(1)$。两个计数器 + 恒定大小（5 个元素）的元音集合，无需容器。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int vowelConsonantScore(string s) {
        auto isVowel = [](char ch) {
            return ch == 'a' || ch == 'e' || ch == 'i' || ch == 'o' || ch == 'u';
        };
        int v = 0, c = 0;
        for (char ch : s) {
            if (!isalpha(static_cast<unsigned char>(ch))) continue;  // 门卫：空格/数字拦下
            if (isVowel(ch)) ++v;
            else ++c;
        }
        return c == 0 ? 0 : v / c;   // 非负整数除法 = ⌊v/c⌋
    }
};
```

### Python

```python
class Solution:
    def vowelConsonantScore(self, s: str) -> int:
        vowels = set('aeiou')
        v = c = 0
        for ch in s:
            if not ch.isalpha():
                continue              # 空格/数字：两边都不算
            if ch in vowels:
                v += 1
            else:
                c += 1
        return v // c if c else 0     # c = 0 防除零
```

> 💡 **Python 一行流**：`v = sum(map('aeiou'.__contains__, s))`，`c = sum(map(str.isalpha, s)) - v`，`return v // c if c else 0`。

## 8. 边界情况与易错点

1. **空格和数字既非元音也非辅音**（最大陷阱）：必须「先 `isalpha` 再判元音」。直接「不是元音就算辅音」会把非字母误计入 $c$，且官方示例 3 误算后碰巧仍得 0——**样例测不出**，写对了才算真懂题。
2. **$c = 0$ 除零**：示例 3 就是冲着这个边界设计的。不判的话 C++ 是 UB，Python 抛 `ZeroDivisionError`。
3. **$v = 0$**（如 `"xyz"`）：$\lfloor 0/c \rfloor = 0$，整数除法天然正确，无需特判。
4. **全非字母**（如 `"123"`、`" "`）：$v = c = 0$，走 $c = 0$ 分支返回 0——注意这是「题意规定的 0」，不是除零。
5. **C++ `isalpha` 入参转 `unsigned char`**：本题字符集非负不出事，但这是 `ctype` 家族的卫生习惯，比赛时顺手写上零成本。
6. **单字符**：`"a"` → $c = 0$ → 0；`"b"` → $\lfloor 0/1 \rfloor = 0$，同一套逻辑覆盖。
7. **不需要取整函数**：非负整数除法本身就是 floor；别手滑写成 `ceil` / `round`，也别用浮点 `/` 再 `int()`（$n \le 100$ 不会触发精度问题，但习惯要正）。
8. **规模极小**：$n \le 100$，无溢出、无性能压力——签到题的目标是**零调试一次过**，把审题时间花在「空格数字算什么」这一句上。
