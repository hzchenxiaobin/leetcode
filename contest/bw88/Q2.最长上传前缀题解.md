# LeetCode 最长上传前缀 题解

## 1. 题目概述

- **标题 / 题号**：最长上传前缀（#2424，medium）
- **链接**：https://leetcode.cn/problems/longest-uploaded-prefix/
- **来源**：LeetCode 第 88 场双周赛 Q2
- **难度**：中等
- **标签**：设计、树状数组、并查集、二分查找（官方标签另含线段树、有序集合、堆、哈希表——皆可实现）

**题意**：实现 `LUPrefix` 类，管理 $n$ 个视频（编号 $1 \sim n$，互不相同）的上传过程：

- `LUPrefix(int n)`：初始化。
- `void upload(int video)`：上传编号 `video` 的视频。
- `int longest()`：返回**最长上传前缀**——最大的 $i$，使得闭区间 $[1, i]$ 内的所有视频都已上传。

**约束**：

- $1 \le n \le 10^5$，$1 \le \text{video} \le 10^5$，视频编号互不相同
- `upload` 与 `longest` 的总调用次数不超过 $2 \times 10^5$，`longest` 至少调用一次

## 2. 示例

**示例 1（官方调用序列回放）**

```text
操作：
["LUPrefix", "upload", "longest", "upload", "longest", "upload", "longest"]
[[4], [3], [], [1], [], [2], []]

输出：
[null, null, 0, null, 1, null, 3]

解释：
server = new LUPrefix(4);   // 4 个视频的上传流
server.upload(3);           // 上传 3 号 → 前缀 1 缺失，longest = 0
server.upload(1);           // 上传 1 号 → [1] 完整，longest = 1
server.upload(2);           // 上传 2 号 → [1,2,3] 完整，longest = 3
```

**示例 2（边界回放）**

```text
new LUPrefix(1); upload(1); longest();   // → 1：单个视频，上传即满前缀
new LUPrefix(5); longest();              // → 0：一个都没传，前缀为空
```

## 3. 解题思路

### 3.1 暴力思路

用一个哈希集合存已上传编号，每次 `longest()` 从 $1$ 开始线性扫到第一个空位——单次最坏 $O(n)$，调用 $2 \times 10^5$ 次、$n = 10^5$ 时总数 $2 \times 10^{10}$，必然超时。瓶颈在于「每次都从起点重新找断点」，而**断点只会右移**——这就是优化空间。

### 3.2 核心观察：断点单调右移，指针只前进

![设计：布尔数组+只前进的指针](images/bw88_q2_pointer_design.svg)

「最长前缀」的定义蕴含单调性：已上传的集合只增不减，若 $[1, i]$ 已完整，它永远完整——因此答案 `cur` **只会增大、不会回退**。用两个部件即可：

- 布尔数组 `seen[v]`：`upload` 只做一次 `seen[video] = true`，$O(1)$；
- 游标 `cur`：`longest()` 时执行 `while (seen[cur + 1]) ++cur;`，扫到第一个空位即停并返回 `cur`。

`cur` 右侧的新上传只可能让 `cur` 继续前进，绝不会使它后退——所以把「找断点」的成本摊到整个操作序列上：每个位置至多被 `cur` 跨过一次。

### 3.3 算法流程与均摊分析

```text
LUPrefix(n)：seen = [false] * (n + 2)   # 多开两个哨兵位，cur+1 永不越界
             cur = 0
upload(video)：seen[video] = true       # O(1)
longest()：    while seen[cur + 1]: cur += 1
               return cur
```

![均摊分析：指针一生只前进n步](images/bw88_q2_amortized.svg)

单次 `longest()` 可能一口气跳很多步（比如缺的编号最后才补上），但「跳的总步数」上界是 $n$：`cur` 严格递增且不超过 $n$。把跳步总量摊给 $2 \times 10^5$ 次调用，每次均摊 $O(1)$。这与单调队列、933. 最近的请求次数是同一个摊还模板：**只进不退的游标 + 「重复劳动合并成一遍」**。

### 3.4 示例演算

![官方示例回放](images/bw88_q2_example_walkthrough.svg)

**示例 1**（$n = 4$）：

| 操作 | seen 状态（1..4） | cur 变化 | longest |
|------|-------------------|----------|---------|
| upload(3) | ✗ ✗ ✓ ✗ | 0 → 0 | — |
| longest() | | 0（seen[1] 为假，一步不走） | 0 |
| upload(1) | ✓ ✗ ✓ ✗ | 0 → 1 | 1 |
| longest() | | 1（seen[2] 为假） | 1 |
| upload(2) | ✓ ✓ ✓ ✗ | 1 → 3（连跨 2、3） | 3 |

三次 `longest()` 的推进步数 $0 + 1 + 2 = 3$，恰等于最终 `cur`——「被跨过的槽位数」就是全部成本。

### 3.5 其他实现选型

- **有序集合 + `n` 上界判断**：`upload` 插入 $O(\log n)$，`longest` 仍需从游标扫（集合支持 `contains(cur+1)`）——本质相同，多一层 $O(\log)$ 与常数。
- **树状数组/线段树**：`upload` 单点 +1，`longest` 在树上二分找「前缀和恰等于下标」的最大位置，单次 $O(\log n)$，支持本题扩展（若 `n` 达 $10^9$ 只需离散化或哈希映射）。
- **并查集**（官方标签之一）：`find(v)` 返回「从 $v$ 向右第一个未上传位置」，`upload(v)` 时 `fa[v] = find(v+1)`；`longest = find(1) - 1`。同样均摊近似 $O(1)$，代码略长。
- 数据规模 $10^5$、调用 $2 \times 10^5$ 下，布尔数组 + 游标是最简、最快、最不易错的选型。

## 4. 算法细节

1. **哨兵省边界判断**：`seen` 开到 $n + 2$，`cur = n` 时 `seen[cur + 1] = seen[n+1]` 恒为假——`while` 自然停住，无需在循环条件里写 `cur + 1 <= n`。
2. **`upload` 不需要维护任何前缀信息**：判重、判界都交给题面（编号合法且互不相同），一次赋值了事。设计题的纪律：**查询要什么，写入才维护什么**。
3. **`cur` 的初值是 0**：`longest()` 在任何上传之前调用返回 0（题面保证至少调用一次，但首次调用可能先于所有 upload）。
4. **`longest()` 里的推进也可以放进 `upload`**（上传后顺手推进），把 `longest` 做成纯读——两种写法摊还复杂度相同，放在 `longest` 里更直观且不需要在 `upload` 里带条件判断。
5. **复杂度记账**：总代价 = 调用数 $\times O(1)$ + 游标总步数 $\le n$，即 $O(q + n)$。

## 5. 正确性证明

**引理（游标不变量）**：`longest()` 返回时，`cur` 等于当前真正的最长上传前缀长度。

**证明**：循环保持不变量「$1 \dots \text{cur}$ 全部已上传」：初始 `cur = 0` 平凡成立；每次 `++cur` 的前置条件是 `seen[cur+1]` 为真，推进后新区间 $1 \dots \text{cur}$ 仍全上传。循环终止只有两种情形：`seen[cur+1]` 为假——则 $[1, \text{cur}]$ 完整而 $[1, \text{cur}+1]$ 不完整，`cur` 是最大的合法 $i$；或 `cur + 1 = n + 1` 触到哨兵（恒假），此时全部视频已上传，`cur = n` 即最大值。∎

**定理（单调性与均摊复杂度）**：任意操作序列下 `cur` 单调不减，`longest()` 的总推进步数不超过 $n$；整个结构处理 $q$ 次调用的总时间为 $O(q + n)$。

**证明**：单调性：`longest` 只增 `cur`，`upload` 不改 `cur`。故各次 `longest` 的推进步数之和 = `cur` 的总增量 $\le n - 0 = n$。`upload` 每次恰为一次数组写入 $O(1)$，`longest` 每次为「推进步数 + 一次比较 + 返回」，求和即 $O(q + n)$。结合引理，每次返回值均正确。∎

## 6. 复杂度分析

- **时间**：单次 `upload` $O(1)$；单次 `longest` 均摊 $O(1)$（最坏单次 $O(n)$，但总推进 $\le n$）。总量 $O(q + n)$，$q \le 2 \times 10^5$、$n \le 10^5$，毫无压力。
- **空间**：$O(n)$——布尔数组 $n + 2$ 个字节位（C++ `vector<char>` 约 100 KB，Python 列表约 400 KB，均可接受；若追求极致可用 `bitset`）。

## 7. 参考代码

### C++

```cpp
class LUPrefix {
    vector<char> seen;   // seen[v]: 视频 v 是否已上传
    int cur = 0;         // 当前最长上传前缀长度（只增不减）
public:
    LUPrefix(int n) : seen(n + 2, 0) {}

    void upload(int video) {
        seen[video] = 1;
    }

    int longest() {
        while (seen[cur + 1]) ++cur;   // 指针只前进
        return cur;
    }
};
```

### Python

```python
class LUPrefix:
    def __init__(self, n: int):
        self.seen = [False] * (n + 2)   # 哨兵位：cur+1 永不越界
        self.cur = 0

    def upload(self, video: int) -> None:
        self.seen[video] = True

    def longest(self) -> int:
        while self.seen[self.cur + 1]:  # 指针只前进
            self.cur += 1
        return self.cur
```

> 💡 两份代码均通过官方 7 步调用序列回放（`[null, null, 0, null, 1, null, 3]`）与边界（$n = 1$、先查后传返回 0），并与「哈希集合 + 每次从 1 线性扫」的暴力实现做了 3 万组（C++，约 300 万次 longest 查询）/ 400 组（Python，约 2 万次查询）随机操作序列对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **`longest()` 先于任何 `upload()` 调用**：返回 0；`cur` 初值必须是 0 而不是 $-1$（$-1$ 会让「无前缀」的表达混乱）。
2. **数组越界**：`cur = n` 时访问 `seen[n+1]`——不开哨兵就要在 `while` 里加 `cur + 1 <= n`；两个条件写漏一个都越界。开 $n + 2$ 大小最省心。
3. **不要每次从 1 重扫**：把「找断点」写进 `upload` 或 `longest` 都行，但**起点必须是游标**；写成 `for i in 1..n` 退回 $O(nq)$ 暴力，正好卡在超时线上。
4. **上传顺序任意**：`upload` 与编号大小无关（先传 3 再传 1），代码里没有顺序假设；若错误地把 `cur` 与「上传次数」绑定（如 `cur = min(cur + 1, ...)`）会漏掉乱序上传。
5. **编号互不相同是题面保证**：`upload` 无需判重；若题目改成可能重复上传，`seen[video] = true` 幂等，依然正确——这正是布尔标记比计数优越的地方。
6. **C++ 用 `vector<char>` 而非 `vector<bool>`**：`vector<bool>` 的位压缩在此处无性能收益且代理引用有坑；`vector<char>` 简单直接（`bool` 数组同样可行）。
