# LeetCode 满足不等式的数对数目 题解

> 💡 本题在本仓库另有[每日题解 2426](../../solution/2401-2500/2426_满足不等式的数对数目.md)，侧重归并排序与树状数组的选型对比。本篇按**周赛复盘视角**展开：从读题到「变形 → 值域平移 → 树状数组」的完整推导链、先查询后插入的顺序纪律，以及以引理–定理结构写全计数正确性证明。

## 1. 题目概述

- **标题 / 题号**：满足不等式的数对数目（#2426，hard）
- **链接**：https://leetcode.cn/problems/number-of-pairs-satisfying-inequality/
- **来源**：LeetCode 第 88 场双周赛 Q4
- **难度**：困难
- **标签**：树状数组、线段树、归并排序、二分查找

**题意**：给定长度均为 $n$ 的数组 `nums1`、`nums2` 与整数 `diff`，统计满足
$$0 \le i < j \le n-1 \quad\text{且}\quad \text{nums1}[i] - \text{nums1}[j] \le \text{nums2}[i] - \text{nums2}[j] + \text{diff}$$
的数对 $(i, j)$ 的数目。

**约束**：

- $2 \le n \le 10^5$
- $-10^4 \le \text{nums1}[i], \text{nums2}[i] \le 10^4$
- $-10^4 \le \text{diff} \le 10^4$

## 2. 示例

**示例 1**

```text
输入：nums1 = [3,2,5], nums2 = [2,2,1], diff = 1
输出：3
解释：(0,1)：1 ≤ 1 ✓；(0,2)：-2 ≤ 2 ✓；(1,2)：-3 ≤ 2 ✓。
```

**示例 2**

```text
输入：nums1 = [3,-1], nums2 = [-2,2], diff = -1
输出：0
解释：唯一数对 (0,1)：5 - (-3) = 8 ≤ -1 ✗。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环直接数：$O(n^2) = 10^{10}$，超时。但暴力已经把目标说清楚了——在 $i < j$ 的前提下统计一个**纯数值条件**。要害是把这个条件改写成「只看各自下标的一个函数值」的形式，让「下标顺序」与「数值比较」解耦。

### 3.2 核心观察：不等式变形，变成「值域顺序对计数」

![不等式变形：把下标对化成值对](images/bw88_q4_transform.svg)

把 $j$ 的项挪到左边、$i$ 的项挪到右边：
$$\text{nums1}[i] - \text{nums2}[i] \le \text{nums1}[j] - \text{nums2}[j] + \text{diff}\text{。}$$
令 $c_k = \text{nums1}[k] - \text{nums2}[k]$（每个下标一个值），条件即
$$c_i \le c_j + \text{diff} \quad (i < j)\text{。}$$
变形后「$i < j$」与「$c_i \le c_j + \text{diff}$」**完全解耦**：前者只管枚举方向，后者只管两个值。固定 $j$，数出左边出现过的、满足 $c_i \le c_j + \text{diff}$ 的 $c_i$ 个数即可——这是一个标准的「顺序对计数」骨架，树状数组（BIT）、归并排序、有序集合 + 二分都是现成工具。

> ⚠️ 由约束，$c_k \in [-2 \times 10^4, 2 \times 10^4]$，阈值 $c_j + \text{diff} \in [-3 \times 10^4, 3 \times 10^4]$——值域极小且集中，**平移后直接开数组**比离散化更省事（见 §4）。

### 3.3 算法流程：从左往右扫，先查询、后插入

![从左往右扫+树状数组：先查询再插入](images/bw88_q4_bit_scan.svg)

```text
OFF = 30000, MAXV = 60001        # 平移量与 BIT 大小
ans = 0
for j = 0 .. n-1:
    c = nums1[j] - nums2[j]
    ans += query(c + diff + OFF)   # BIT 里是 c_0..c_{j-1}，数 ≤ 阈值的个数
    add(c + OFF)                   # 再把 c_j 放进去供后面的 j' 查询
return ans
```

`query(x)` 返回已插入值中 $\le x$ 的个数，BIT 单次 $O(\log V)$。也可从右往左扫，改数「右边满足 $c_j \ge c_i - \text{diff}$ 的个数」（官方提示的路线），两者互为镜像。

替代实现：

- **归并排序计数**：对 $c$ 做归并，合并两个有序半段时对左段每个元素二分/双指针数右段中 $\le c_i - \text{diff}$ 的个数（注意方向），$O(n \log n)$；
- **有序集合 + 二分**：C++ `multiset` 不支持随机访问序数，需手写平衡树或用 `policy_tree`；Python 可用 `SortedList` 的 `bisect_left`，单次 $O(\log n)$；
- **离散化 + BIT**：把所有 $c_k$ 与 $c_k + \text{diff}$ 一起排序去重再建 BIT——通用性最好（值域无关），本题值域小可以省略。

### 3.4 示例演算

![示例演算表](images/bw88_q4_example_walkthrough.svg)

**示例 1**：$c = [1, 0, 4]$，$\text{diff} = 1$，条件 $c_i \le c_j + 1$：

| $j$ | 阈值 $c_j + \text{diff}$ | BIT 中已有 | 查询结果 |
|-----|--------------------------|------------|----------|
| 0 | 2 | 空 | 0 |
| 1 | 1 | {1} | 1（$c_0 = 1 \le 1$） |
| 2 | 5 | {1, 0} | 2（两个都 $\le 5$） |

合计 $0 + 1 + 2 = 3$ ✓，对应数对 $(0,1), (0,2), (1,2)$。

**示例 2**：$c = [5, -3]$，$\text{diff} = -1$。$j = 1$ 时阈值为 $-4$，BIT 中 $\{5\}$ 不满足 → 0 ✓。

## 4. 算法细节

1. **值域平移**：$c_k + \text{OFF} \in [1, 60001]$（$\text{OFF} = 3 \times 10^4$），阈值 $c_j + \text{diff} + \text{OFF} \in [0, 60000]$——落在 $[0, 60000]$ 内恰好能直接作为 BIT 下标；`query(0)` 返回 0（负阈值自然数不到任何值），上界 60000 $\le \text{MAXV}$。这套「左端取 0 防负、右端留余量」的平移法，在值域有界时永远比离散化短小。
2. **先查询、后插入**：处理 $j$ 时 BIT 中必须是 $c_0, \dots, c_{j-1}$。若先插入再查询，会把 $c_j$ 自己也算进去（$c_j \le c_j + \text{diff}$ 只有 $\text{diff} \ge 0$ 时成立，$\text{diff} < 0$ 时漏数、$\text{diff} \ge 0$ 时多数，两个方向都错）。
3. **BIT 实现要点**：`add(i)` 沿 `i += i & -i` 上跳；`query(i)` 沿 `i -= i & -i` 下跳；数组开 `MAXV + 1`，全部一次初始化为 0。每次调用用局部（或重新 `assign`）的 BIT，避免多次调用共享状态——本题单次调用即结束，但养成习惯防「同实例多调用」。
4. **答案类型**：全部相等时 $\binom{10^5}{2} \approx 5 \times 10^9$，超出 32 位——C++ 必须 `long long`（metaData 返回 `long`），Python 天然无碍。
5. **负数别慌**：变形后 $c$、阈值、diff 都可能为负，平移统一处理；真正要小心的只有平移量是否覆盖「值 + diff」的整个范围（是 $3 \times 10^4$ 量级而非 $2 \times 10^4$）。

## 5. 正确性证明

**引理（变形等价）**：原始条件
$$\text{nums1}[i] - \text{nums1}[j] \le \text{nums2}[i] - \text{nums2}[j] + \text{diff} \quad (i < j)$$
与 $c_i \le c_j + \text{diff}$（其中 $c_k = \text{nums1}[k] - \text{nums2}[k]$）等价。

**证明**：移项，把含 $i$ 的移到左端、含 $j$ 的移到右端：
$\text{nums1}[i] - \text{nums2}[i] \le \text{nums1}[j] - \text{nums2}[j] + \text{diff}$，两边各合并成 $c_i$、$c_j$ 即得；步骤全部为等式变形，可逆。∎

**定理（计数正确）**：从左往右扫描，处理 $j$ 时累加「BIT 中已插入的 $c_0, \dots, c_{j-1}$ 里 $\le c_j + \text{diff}$ 的个数」，最终累加值恰为满足条件的数对总数。

**证明**：任取数对 $(i, j)$，$i < j$。$c_i$ 恰在处理下标 $i$ 时被插入 BIT（在处理 $j$ 之前），故在第 $j$ 轮查询时它在 BIT 中当且仅当 $i < j$ 成立。查询 `query(c_j + diff + OFF)` 统计的是「已插入值中 $\le c_j + \text{diff}$ 的个数」；由平移的一一对应（$x \mapsto x + \text{OFF}$ 保序），这正是 $\{c_i : i < j, c_i \le c_j + \text{diff}\}$ 的大小。于是每个满足条件的数对在第 $j$ 轮恰被统计一次，不满足的（$c_i > c_j + \text{diff}$）不被统计；对 $j$ 求和即得总数。∎

**推论（复杂度）**：$n$ 次查询 + $n$ 次插入，单次 $O(\log V)$（$V = 60001$），总 $O(n \log V)$；空间 $O(V)$。

## 6. 复杂度分析

- **时间**：$O(n \log V)$，$V \approx 6 \times 10^4$、$\log V \approx 16$，$n = 10^5$ 时约 $3.2 \times 10^6$ 次 BIT 跳步，轻松通过。
- **空间**：$O(V)$——一个约 6 万长度的 `int` 数组（约 240 KB）；若改离散化则为 $O(n)$ 且不依赖值域。

## 7. 参考代码

### C++

```cpp
class Solution {
    static constexpr int OFF = 30000;    // c = nums1[i]-nums2[i] ∈ [-20000, 20000]
    static constexpr int MAXV = 60001;   // 查询上界 c + diff + OFF ∈ [0, 60000]
    vector<int> bit;                      // 每次调用独立建树
    void add(int i) {
        for (; i <= MAXV; i += i & (-i)) ++bit[i];
    }
    int query(int i) {                   // 已插入值中 <= i 的个数
        int s = 0;
        for (; i > 0; i -= i & (-i)) s += bit[i];
        return s;
    }
public:
    long long numberOfPairs(vector<int>& nums1, vector<int>& nums2, int diff) {
        bit.assign(MAXV + 1, 0);
        long long ans = 0;
        for (size_t k = 0; k < nums1.size(); ++k) {
            int c = nums1[k] - nums2[k];
            ans += query(c + diff + OFF);   // 之前的 c_i 里满足 c_i - c_k <= diff 的个数
            add(c + OFF);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfPairs(self, nums1: list[int], nums2: list[int], diff: int) -> int:
        OFF, MAXV = 30000, 60001            # c ∈ [-20000,20000]，阈值 +diff 后 ∈ [0,60000]
        bit = [0] * (MAXV + 1)

        def add(i: int) -> None:
            while i <= MAXV:
                bit[i] += 1
                i += i & (-i)

        def query(i: int) -> int:           # 已插入值中 <= i 的个数
            s = 0
            while i > 0:
                s += bit[i]
                i -= i & (-i)
            return s

        ans = 0
        for a, b in zip(nums1, nums2):
            c = a - b
            ans += query(c + diff + OFF)   # 之前的 c_i 里满足 c_i - c_k <= diff 的个数
            add(c + OFF)
        return ans
```

> 💡 两份代码均通过官方示例（`3`、`0`），并与「双重循环直接计数」的暴力实现做了 2 万组（C++）/ 2500 组（Python）随机对拍（$n \le 80$，值域 $[-60,60]$，覆盖负 diff），另加 20 组（C++）/ 5 组（Python）$n = 2000$、值域顶满 $[-10^4, 10^4]$ 的大规模抽查，`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出**：答案最大约 $5 \times 10^9$，C++ 必须用 `long long` 累加；中间值 `c + diff` 最大约 $3 \times 10^4$，`int` 即可。
2. **负 diff 与负阈值**：`diff = -1` 时阈值可为负，平移后 `query(0)` 应返回 0——BIT 的 `for (; i > 0; ...)` 循环天然处理，但若平移量算小了会出现负下标、未定义行为或 Python 负索引串位（Python 里 `bit[-5]` 会静默取到队尾的值，**不报错但结果全错**——这是 Python 版最阴的坑）。
3. **先查询后插入**：顺序颠倒会把 $j$ 自己计入（$\text{diff} \ge 0$ 时）或漏计其他对；见 §4 第 2 条，方向两个错法都有人踩。
4. **平移量覆盖「值 + diff」而非只覆盖「值」**：$c$ 的范围是 $\pm 2 \times 10^4$，但阈值要再加 $\text{diff} \in \pm 10^4$，BIT 容量与平移量都要按 $\pm 3 \times 10^4$ 设计。
5. **变形方向别绕晕**：是 $c_i \le c_j + \text{diff}$（$i$ 在左在前），不是 $c_j \le c_i + \text{diff}$；写反后条件变为「递减对」，示例 1 会数出 $(0,1)$ 一组而答案错成 1。
6. **BIT 多次调用复用**：若在同一个 `Solution` 实例上连续调用 `numberOfPairs`，成员 BIT 必须先清零（参考代码每次 `assign`）；LeetCode 单测试点通常无碍，但对拍与本地测试必炸。
7. **n = 2**：最小规模，唯一数对；用它做变形方向的「单元测试」最直观。
