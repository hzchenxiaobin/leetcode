# LeetCode 长度为 K 的无重复字符子串 题解

## 1. 题目概述

- **标题 / 题号**：长度为 K 的无重复字符子串（#1100，medium）
- **链接**：https://leetcode.cn/problems/find-k-length-substrings-with-no-repeated-characters/
- **来源**：LeetCode 第 3 场双周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、滑动窗口

**题意**：给定只含小写英文字母的字符串 `s` 和整数 `k`，统计 `s` 中长度**恰好为 $k$** 且**不含重复字符**的子串个数。子串必须连续；两个子串只要**起点不同**就算两个，即使内容相同（可重叠计数）。

**约束**：

- $1 \le s.length \le 10^4$
- `s` 只含小写英文字母
- $1 \le k \le 10^4$

## 2. 示例

**示例 1**

```text
输入：s = "havefunonleetcode", k = 5
输出：6
解释：6 个合法子串为 'havef'、'avefu'、'vefun'、'efuno'、'etcod'、'tcode'。
```

**示例 2**

```text
输入：s = "home", k = 5
输出：0
解释：k 可以大于字符串长度，此时不存在长度为 5 的子串。
```

**示例 3（边界补充）**

```text
输入：s = "aaaa", k = 1
输出：4
解释：k = 1 时任何单字符子串都无重复，4 个起点各计一次。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个起点 $i$（共 $n - k + 1$ 个），用长度为 $k$ 的切片检查字符是否互异，单次 $O(k)$，总计 $O(nk)$。代入上界 $n = k = 10^4$ 得 $10^8$ 次字符操作，在周赛时限内非常危险。瓶颈在于：**相邻两个窗口只差一进一出两个字符**，暴力却每次从零重建整个窗口的判重信息——这正是滑动窗口该登场的信号。

### 3.2 核心观察：定长窗口「一进一出」+ distinct 计数

![核心观察：定长窗口每滑一格只有一进一出两个计数变化](images/bw3_q2_sliding_window_model.svg)

维护一个长度恒为 $k$ 的窗口 $[i-k+1, i]$，以及窗口内每个字符的出现次数 `cnt[26]` 和**互异字符数** `distinct`：

- **进窗**（右端纳入 $s[i]$）：`cnt[c]++`；若旧计数为 $0$，说明来了一个新字符，`distinct++`；
- **出窗**（左端弹出 $s[i-k]$）：`cnt[c]--`；若减到 $0$，说明少了一种字符，`distinct--`。

窗口合法的判据惊人地简单：**窗口无重复字符 $\iff distinct = k$**。因为窗口恰好 $k$ 个位置——若全互异，自然有 $k$ 种字符；反之若 $k$ 个位置装了 $k$ 种字符，每种字符恰好出现一次（鸽巢），不可能重复。

> 💡 别小看「$k > 26$ 直接返回 $0$」这个小特判：小写字母只有 $26$ 种，长度超过 $26$ 的窗口必然重复，提前返回既省时间又挡掉一类手滑越界。

### 3.3 算法流程

![算法流程：定长滑动窗口加 26 计数数组](images/bw3_q2_algorithm_flow.svg)

```text
1. 若 k > 26：返回 0（鸽巢原理，不可能无重复）
2. cnt[26] = 0，distinct = 0，ans = 0
3. 对 i = 0 … n-1：
4.     c = s[i]，cnt[c]++；若旧计数为 0 → distinct++     # 右端进窗
5.     若 i ≥ k：d = s[i-k]，cnt[d]--；若减到 0 → distinct--  # 左端出窗
6.     若 i ≥ k-1 且 distinct == k：ans++                # 窗口恰好装满且全互异
7. 返回 ans
```

### 3.4 示例演算

![示例演算：havefunonleetcode 的 13 个窗口中 6 个合法](images/bw3_q2_example_walkthrough.svg)

以示例 1 `s = "havefunonleetcode"`、$k = 5$ 为例，13 个起点（$0 \sim 12$）的判定结果一目了然：

- **起点 0–3**（`havef`、`avefu`、`vefun`、`efuno`）：每个窗口恰好 $5$ 种互异字符，`distinct = k = 5`，连续命中 $4$ 个；
- **起点 4–6**（`funon`、`unonl`、`nonle`）：字母表里的 `n` 在下标 6、8 各出现一次，凡同时罩住这两个 `n` 的窗口必含重复，三连败；
- **起点 7–10**（`onlee`、`nleet`、`leetc`、`eetco`）：`le` 段连续两个 `e`（下标 10、11），又四连败；
- **起点 11–12**（`etcod`、`tcode`）：窗口滑出低谷后重新凑齐 $5$ 种互异字符，再中两个。

合计 $6$ 个合法窗口，与官方输出一致。中段「连败」很好地展示了增量计数的威力：无论窗口内容怎么折腾，每步只需 $O(1)$ 更新两个计数。

## 4. 算法细节

1. **计数数组用固定 `cnt[26]`** 而非哈希表：字符集只有 26 个小写字母，数组更快；若字符集更大，可换成 `unordered_map` 或「计数数组 + 变更列表」。
2. **`distinct` 的两条维护规则**必须成对：进窗时旧计数为 $0$ 才 `++`；出窗时**减到 $0$** 才 `--`（不是减之前判 $0$，注意两者语义差异——出窗判的是「减完之后这种字符是否绝迹」）。
3. **出窗时机**：$i \ge k$ 时移除 $s[i-k]$，保证窗口长度恰为 $k$；$i = k-1$ 那一轮是第一个完整窗口，**不出窗**。
4. **判定时机**：`i >= k-1` 才可能命中（窗口未满时 `distinct < k`，判不中都无妨，但显式写出更清晰）。
5. **早退 `k > 26`**：其实是 `distinct ≤ 26 < k` 永不命中的推论，不写也对，但把鸽巢原理显式化，既快一拍也防越界类手误。
6. **为什么必须「先出窗、再判定」**：判定时窗口必须是精确的 $[i-k+1, i]$。若先判后出，$i \ge k$ 的轮次判定的是一个 $k+1$ 长的中间态，`distinct == k` 会**误判**（多出的字符可能恰好是重复位上的）。

## 5. 正确性证明

**引理 1（判据等价）**：长度为 $k$ 的子串无重复字符 $\iff$ 其中互异字符数恰为 $k$。

**证明**：若 $k$ 个位置互不重复，则每种出现至多一次，共 $k$ 种字符，互异数 $= k$。反之若互异字符数为 $k$：$k$ 个位置共 $k$ 次出现、分布在 $k$ 种字符上，每种字符至少出现一次、总计却只有 $k$ 次，故每种恰出现一次，无重复。∎

**引理 2（窗口表示不变量）**：第 $i$ 轮（$0 \le i < n$）的进窗/出窗操作完成后，`cnt` 与 `distinct` 恰好表示子串 $s[\max(0, i-k+1) .. i]$ 中各字符的出现次数与互异字符数。

**证明**：对 $i$ 归纳。$i = 0$：纳入 $s[0]$，无出窗，表示 $s[0..0]$ ✓。设第 $i-1$ 轮后表示 $s[\max(0,i-k) .. i-1]$。第 $i$ 轮：先纳入 $s[i]$，表示 $s[\max(0,i-k) .. i]$；若 $i \ge k$ 再移除左端 $s[i-k]$（它是窗口内最左字符），表示 $s[i-k+1 .. i]$，长度恰为 $k$；若 $i < k$ 则 $\max(0, i-k+1) = 0$，表示 $s[0..i]$ ✓。`distinct` 的增减与 `cnt` 的从 $0$ 到 $1$、从 $1$ 到 $0$ 的跨越严格同步，归纳可逐轮验证。∎

**引理 3（不重不漏）**：每个长度为 $k$ 的子串 $s[j..j+k-1]$ 恰好对应第 $i = j+k-1$ 轮的判定，且不同子串对应不同轮次。

**证明**：映射 $j \mapsto j + k - 1$ 是 $[0, n-k]$ 到 $[k-1, n-1]$ 的一一对应；第 $i$ 轮判定时（引理 2）窗口正是 $s[i-k+1..i]$。∎

**定理**：算法返回 `s` 中长度为 $k$ 且无重复字符的子串个数。

**证明**：`ans` 的每次自增都发生在某轮 `i ≥ k-1` 且 `distinct == k` 时。由引理 2，`distinct` 就是当前窗口 $s[i-k+1..i]$ 的互异字符数；由引理 1，`distinct == k` $\iff$ 该子串无重复；由引理 3，每个候选子串恰被判定一次，且窗口之外不产生计数。故 `ans` 恰好等于合法子串个数。$k > n$ 时没有任何轮次满足 `i ≥ k-1`，返回 $0$；$k > 26$ 时被第 1 步拦截，而鸽巢原理保证此时确无合法子串。∎

## 6. 复杂度分析

- **时间**：$O(n + 26)$。每个字符一进一出各 $O(1)$，判定 $O(1)$；`k > 26` 时甚至 $O(1)$ 返回。
- **空间**：$O(26) = O(1)$。一个固定计数数组与几个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numKLenSubstrNoRepeats(string s, int k) {
        if (k > 26) return 0;              // 小写字母只有 26 个，不可能无重复
        int cnt[26] = {0}, distinct = 0, ans = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            if (cnt[s[i] - 'a']++ == 0) ++distinct;               // 右端进窗
            if (i >= k && --cnt[s[i - k] - 'a'] == 0) --distinct; // 左端出窗
            if (i >= k - 1 && distinct == k) ++ans;               // k 个互异字符
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numKLenSubstrNoRepeats(self, s: str, k: int) -> int:
        if k > 26:                        # 小写字母只有 26 个，不可能无重复
            return 0
        cnt = [0] * 26
        distinct = 0
        ans = 0
        for i, ch in enumerate(s):
            j = ord(ch) - ord('a')
            if cnt[j] == 0:               # 右端进窗
                distinct += 1
            cnt[j] += 1
            if i >= k:                    # 左端出窗
                p = ord(s[i - k]) - ord('a')
                cnt[p] -= 1
                if cnt[p] == 0:
                    distinct -= 1
            if i >= k - 1 and distinct == k:  # k 个互异字符
                ans += 1
        return ans
```

> 💡 两份代码均已通过官方全部示例（`6`、`0`）以及 600+ 组随机数据与 $O(nk)$ 暴力的对拍验证。

## 8. 边界情况与易错点

1. **$k > 26$**：鸽巢原理下必然有重复，直接返回 $0$；漏判也不会错，但多扫一遍。
2. **$k > n$**：窗口永远凑不满，`i ≥ k-1` 永不成立，自然返回 $0$（示例 2）。
3. **$k = 1$**：所有单字符子串都合法，答案为 $n$；模板自动覆盖，无需特判。
4. **出窗下标是 $s[i-k]$**，写成 $s[i-k+1]$ 会把窗口左端多留一个字符，`distinct` 永远偏大 $1$。
5. **先出窗、再判定**：顺序颠倒会在 $i \ge k$ 的轮次用 $k+1$ 长度的中间态做判定，可能把含重复的窗口误判为合法。
6. **`distinct--` 的条件是「减到 0」**（`--cnt[..] == 0`），判成「减之前为 0」会让 `distinct` 越减越少。
7. **按位置计数**：内容相同的窗口在不同起点要分别计数（例 3 的四个 `a`），不要去重。
