# LeetCode 小于 K 的两数之和 题解

## 1. 题目概述

- **标题 / 题号**：小于 K 的两数之和（#1099，easy）
- **链接**：https://leetcode.cn/problems/two-sum-less-than-k/
- **来源**：LeetCode 第 3 场双周赛 Q1
- **难度**：简单
- **标签**：数组、双指针、二分查找、排序

**题意**：给定一个**正整数**数组 `nums` 和整数 `k`，在所有满足 $i < j$ 且 $nums[i] + nums[j] < k$ 的数对中，求**最大**的数对和；若不存在任何满足条件的数对，返回 $-1$。本题是 Two Sum 家族的变体：从「找精确和」变成「在严格小于 $k$ 的约束下找最大和」。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 1000$
- $1 \le k \le 2000$

## 2. 示例

**示例 1**

```text
输入：nums = [34,23,1,24,75,33,54,8], k = 60
输出：58
解释：34 + 24 = 58 < 60，不存在比 58 更大的、严格小于 60 的数对和。
```

**示例 2**

```text
输入：nums = [10,20,30], k = 15
输出：-1
解释：最小的数对和为 10 + 20 = 30 ≥ 15，无解。
```

**示例 3（边界补充）**

```text
输入：nums = [8], k = 10
输出：-1
解释：数组只有 1 个元素，凑不出任何数对，直接返回 -1。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有 $i < j$ 的数对，凡是和 $< k$ 就用它更新最大值，$O(n^2)$ 时间、$O(1)$ 空间。本题 $n \le 100$，最多不到 $5000$ 个数对，暴力完全可以通过。但「排序 + 双指针」是 Two Sum 系列的标配模板（枚举一端、另一端单调收缩），正好借这道理由把它沉淀下来，为 Q2~Q4 的更复杂套路热身。

### 3.2 核心观察：排序后「和」随端点外扩单调 → 对向双指针

![核心观察：排序后每个 lo 的最优搭档是最大的 hi 使和小于 k](images/bw3_q1_two_pointers_model.svg)

排序之后，「和」出现关键的单调性：固定一端，另一端越靠外，和越大。于是对向双指针每一步都能**安全丢弃一个端点**：

- $s = nums[lo] + nums[hi] < k$：当前 $hi$ 已经是 $lo$ 能配到的**最大**搭档（$hi$ 再大就会超出 $k$），记录 $ans = \max(ans, s)$ 后 $lo$ 右移，去尝试更大的和；
- $s \ge k$：这个 $hi$ 太大了，而且对任何 $lo' \ge lo$ 都依然超限（排序后 $nums[lo'] \ge nums[lo]$），$hi$ 左移，安全丢弃。

> ⚠️ 注意方向别记反：**和太小就动左指针**（要变大），**和太大就动右指针**（要变小）。若无序直接双指针，「和」毫无单调性可言，每步的丢弃都不安全。

### 3.3 算法流程

![算法流程：排序后对向双指针，循环外返回 ans](images/bw3_q1_algorithm_flow.svg)

```text
1. 将 nums 升序排序
2. lo = 0, hi = n - 1, ans = -1
3. while lo < hi:
4.     s = nums[lo] + nums[hi]
5.     若 s < k:   # hi 已是 lo 的最优搭档
6.         ans = max(ans, s)
7.         lo = lo + 1
8.     否则:       # s ≥ k：hi 与任何 lo' ≥ lo 配对都超限
9.         hi = hi - 1
10. 返回 ans       # 从未记录过则仍为 -1
```

### 3.4 示例演算

![示例演算：排序后八步收敛到最优对 (24,34)](images/bw3_q1_example_walkthrough.svg)

以示例 1 为例，排序后数组为 $[1, 8, 23, 24, 33, 34, 54, 75]$，$k = 60$：

- 前两轮 $1+75=76 \ge 60$、$1+54=55 < 60$，记录 $ans=55$ 后左指针右移；
- 中段 $8+54 \ge 60$ 再丢一个 $hi$；随后 $8+34=42$、$23+34=57$、$24+34=58$ 连续三次命中，$ans$ 依次抬到 $55 \to 55 \to 57 \to 58$；
- 第 6 步的 $(24, 34)$ 就是**最优对**，$ans$ 封顶 $58$；
- 之后 $33+34=67 \ge 60$，两指针在 下标 4 相遇，循环结束，返回 $58$。

可以看到：两指针各只单向移动、绝不回头，总步数不超过 $n$。

## 4. 算法细节

1. **排序可直接在入参数组上进行**（LeetCode 不要求保持原序）；若要求保留原数组，先复制一份即可。
2. **`ans` 初始化为 $-1$**，且只在 $s < k$ 时更新——$-1$ 天然成为「无解」哨兵，不需要额外的标志位。
3. **判据是严格小于**：$s = k$ 时不能记录，指针走 $hi$ 分支即可（$s \ge k$）。
4. **双指针模板的本质**是给每个 $lo$ 找「最大的可行搭档」：由于 $hi$ 在 $s < k$ 时不必回退（详见证明中的不变量），整体是线性扫描而非 $O(n^2)$ 枚举。
5. **备选写法（官方 hint 路线）**：排序后对每个 $i$，二分查找最大的 $j$ 使 $nums[j] < k - nums[i]$，同为 $O(n \log n)$；双指针常数更小、代码更短。

## 5. 正确性证明

**引理 1（记录值合法）**：`ans` 的每次更新值都来自一对真实下标 $(lo, hi)$（$lo < hi$）且其和严格小于 $k$；因此 $ans \le \mathrm{OPT}$ 恒成立，其中 $\mathrm{OPT}$ 为最优数对和（不存在时约定 $ans$ 保持 $-1$）。

**证明**：更新只发生在循环体内 $s < k$ 的分支，而循环条件保证 $lo < hi$，故 $s$ 是合法数对和。∎

**引理 2（双指针不变量）**：设排序后 $(i^\ast, j^\ast)$（$i^\ast < j^\ast$）是某个最优数对，$\mathrm{OPT}$ 为其和。循环每轮开始时：若 $ans < \mathrm{OPT}$，则必有 $lo \le i^\ast$ 且 $hi \ge j^\ast$。

**证明**：对轮数归纳。初始 $lo = 0 \le i^\ast$、$hi = n-1 \ge j^\ast$，成立。设某轮满足 $lo \le i^\ast$、$hi \ge j^\ast$ 且 $ans < \mathrm{OPT}$，按指针位置分四种情形：

- $lo = i^\ast$ 且 $hi = j^\ast$：$s = \mathrm{OPT} < k$，走 $s < k$ 分支，$ans = \max(ans, \mathrm{OPT}) = \mathrm{OPT}$，此后 $ans < \mathrm{OPT}$ 不再成立，无需维护不变量；
- $lo = i^\ast$ 且 $hi > j^\ast$：$s = nums[i^\ast] + nums[hi] \ge nums[i^\ast] + nums[j^\ast] = \mathrm{OPT}$。若 $s < k$，则 $ans \ge s \ge \mathrm{OPT}$，结合引理 1 得 $ans = \mathrm{OPT}$；若 $s \ge k$，执行 $hi \gets hi - 1$，仍有 $hi \ge j^\ast$；
- $lo < i^\ast$ 且 $hi = j^\ast$：$s \le nums[i^\ast] + nums[j^\ast] = \mathrm{OPT} < k$，必走 $lo$ 右移分支，$lo + 1 \le i^\ast$；
- $lo < i^\ast$ 且 $hi > j^\ast$：无论走哪个分支，要么 $lo$ 右移（$lo + 1 \le i^\ast$），要么 $hi$ 左移（$hi - 1 \ge j^\ast$），不变量保持。∎

**定理**：算法返回最优数对和 $\mathrm{OPT}$；若不存在合法数对则返回 $-1$。

**证明**：先设最优对存在。由引理 1，$ans \le \mathrm{OPT}$ 恒成立。反设算法终止时 $ans < \mathrm{OPT}$：由引理 2，终止（$lo \ge hi$）那一刻仍有 $lo \le i^\ast < j^\ast \le hi$，即 $lo < hi$，与循环终止条件矛盾。又每轮 $hi - lo$ 严格减小、循环必然终止，故终止前必有某轮进入「$lo = i^\ast$ 且 $hi = j^\ast$」情形或更早把 $ans$ 抬到 $\mathrm{OPT}$，两种情况都返回 $\mathrm{OPT}$。再设不存在合法数对：由引理 1，`ans` 从未被更新，初始值 $-1$ 被原样返回。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序占主导；双指针扫描每轮至少移动一个指针，至多 $n$ 轮，每轮 $O(1)$。
- **空间**：$O(1)$ 额外空间（原地排序，不计排序本身的栈开销）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int twoSumLessThanK(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());            // 升序排序
        int lo = 0, hi = (int)nums.size() - 1;
        int ans = -1;
        while (lo < hi) {
            int s = nums[lo] + nums[hi];
            if (s < k) {                           // 和太小：记录并右移 lo
                ans = max(ans, s);
                ++lo;
            } else {                               // 和太大：左移 hi
                --hi;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def twoSumLessThanK(self, nums: list[int], k: int) -> int:
        nums.sort()                        # 升序排序
        lo, hi = 0, len(nums) - 1
        ans = -1
        while lo < hi:
            s = nums[lo] + nums[hi]
            if s < k:                      # 和太小：记录并右移 lo
                ans = max(ans, s)
                lo += 1
            else:                          # 和太大：左移 hi
                hi -= 1
        return ans
```

> 💡 两份代码均已通过官方全部示例（`58`、`-1`）以及 600+ 组随机数据与 $O(n^2)$ 暴力的对拍验证。

## 8. 边界情况与易错点

1. **单元素数组**：`nums = [8]` 无任何数对，循环不进入，返回 $-1$。
2. **$k \le 2$ 必无解**：元素全是正整数，最小数对和为 $1 + 1 = 2$，要求 $s < k \le 2$ 不可能；代码无需特判，模板天然处理。
3. **严格小于**：判据是 $s < k$，把 $s == k$ 的情形也记录进去是错的；同时 $s \ge k$ 分支里**不能**更新 `ans`。
4. **指针方向写反**：`s < k` 时若移动 `hi`，会丢掉所有可能的最优对（引理 2 的不变量被破坏）。
5. **`ans` 初值**：用 $-1$ 做哨兵而不是 $0$——存在合法数对时和至少为 $2$，二者恰好区分「无解」。
6. **修改入参**：`sort` 是原地操作，工程上下文若要求保留原序，先 `copy`。
7. **不要输出「任意一对满足条件的数对」**：题目要的是**最大和**，不是任意可行解。
