# LeetCode 二倍数对数组 题解

## 1. 题目概述

- **标题 / 题号**：二倍数对数组（#954，medium）
- **链接**：https://leetcode.cn/problems/array-of-doubled-pairs/
- **来源**：LeetCode 第 114 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、哈希表、排序

**题意**：给定长度为偶数的整数数组 `arr`，判断能否重新排列它，使得对每个 $0 \le i < len(arr)/2$ 都有

$$arr[2i+1] = 2 \cdot arr[2i].$$

换句话说：能否把 `arr` 划分成 $len(arr)/2$ 个**无序对** $\{x, 2x\}$。

**约束**：

- $0 \le arr.length \le 3\times10^4$，且 $arr.length$ 为偶数
- $-10^5 \le arr[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：arr = [3,1,3,6]
输出：false
解释：3 的搭档只能是 6 或 1.5（不存在），1 的搭档只能是 2（不存在）。
     两个 3 只有一个 6 可用，凑不出两对，故 false。
```

**示例 2**

```text
输入：arr = [2,1,2,6]
输出：false
解释：1 与 2 可以成一对，但剩下的 2 需要 4（不存在），6 需要 3（不存在）。
```

**示例 3**

```text
输入：arr = [4,-2,2,-4]
输出：true
解释：可分成 (-2,-4) 与 (2,4) 两对，排列成 [-2,-4,2,4] 或 [2,4,-2,-4]。
```

## 3. 解题思路

### 3.1 暴力思路

把问题看成"完美配对"：每个元素 $x$ 只有两个候选搭档 $2x$ 与 $x/2$（若存在），于是可以回溯搜索所有匹配方案，找到一条覆盖全部元素的路。

- 状态数最坏是 $(n-1)!!$ 量级（每个元素两种选择，且互相牵连），$n = 3\times10^4$ 时完全不可行；
- 换成一般图的最大匹配（$O(n^3)$）也超时，而且丢掉了"配对关系是 $x \leftrightarrow 2x$"这一强结构。

另有一些直觉上很自然但**错误**的贪心：

- 按**原数组顺序**两两配对：`[1,2,4,8]` 会被配成 (1,2)、(4,8) 恰好对，但 `[4,8,1,2]` 就会先配 (4,8) 再配 (1,2) 也对——问题在于 `[2,4,1,2]` 这种顺序会失败；
- 按**数值升序**配对：负数会出错。`[-4,-2]` 按数值升序先处理 $-4$，它需要 $-8$，但实际上 $-4 = 2 \cdot (-2)$ 才是正确搭档。

### 3.2 核心观察：按绝对值从小到大贪心

![按绝对值升序处理，最小的元素只能与它的二倍配对](images/wc114_q2_abs_greedy.svg)

**观察 1（搭档唯一性）**：若 $\{x, y\}$ 是合法对，则 $y = 2x$ 或 $x = 2y$。也就是说，$x$ 的搭档**只能**是 $2x$ 或 $x/2$（$x \ne 0$ 时）。

**观察 2（绝对值单调）**：当 $x \ne 0$ 时 $\lvert x/2 \rvert < \lvert x \rvert < \lvert 2x \rvert$。于是若我们按 $\lvert x \rvert$ **升序**处理每个不同的值，轮到 $x$ 时：

- $x$ 的"小搭档" $x/2$（若存在）早已被处理完，且它的可用个数已经被消耗为 $0$；
- 因此 $x$ 剩下的每个副本**别无选择**，只能与 $2x$ 配对。

**观察 3（0 是特例）**：$2 \cdot 0 = 0$，所以 0 只能与 0 配对，`arr` 中 0 的个数必须是偶数。

![0 只能与 0 配对；其余元素按 |x| 递增贪心](images/wc114_q2_zero_case.svg)

这一观察把"全局匹配"变成了"逐个判定"：按 $\lvert x \rvert$ 升序扫描不同的值，若当前值 $x$ 还剩 `c` 个，就把 `2x` 的计数减去 `c`；若 `2x` 的剩余量不足 `c`，说明必然无法配对，返回 `false`。

### 3.3 算法流程

```text
1. cnt = 每个值出现的次数
2. keys = cnt 的所有不同值，按 (|v|, v) 升序排序
3. for x in keys:
       c = cnt[x]
       若 c == 0:  continue
       若 x == 0:  若 c 为奇数: return false;  否则 cnt[0] = 0; continue
       若 cnt[2x] < c:  return false
       cnt[2x] -= c
       cnt[x] = 0
4. return true
```

### 3.4 示例演算

![示例 3 的演算：按 |x| 升序，-2 先吃掉 -4，再处理 2 吃掉 4](images/wc114_q2_walkthrough.svg)

对示例 3 的 `arr = [4,-2,2,-4]`，计数为 `{-4:1, -2:1, 2:1, 4:1}`，按键的 $\lvert v \rvert$ 升序排列得 `[-2, 2, -4, 4]`：

| 步骤 | 当前 x | cnt[x] | 需要的 2x | cnt[2x] | 动作 |
|------|--------|--------|-----------|---------|------|
| 1 | -2 | 1 | -4 | 1 | 足够，cnt[-4] ← 0，cnt[-2] ← 0 |
| 2 | 2 | 1 | 4 | 1 | 足够，cnt[4] ← 0，cnt[2] ← 0 |
| 3 | -4 | 0 | — | — | 已耗尽，跳过 |
| 4 | 4 | 0 | — | — | 已耗尽，跳过 |

全部处理完，返回 `true`。而示例 1 的 `arr = [3,1,3,6]`：先处理 `1`，它需要 `2`，但 `cnt[2] = 0 < 1`，立即返回 `false`。

## 4. 算法细节

1. **排序键的选取**：必须按 $\lvert x \rvert$ 升序（$\lvert x \rvert$ 相同时的次序无关紧要，例如 $-2$ 与 $2$ 互不为搭档）。C++ 里用 `sort(keys.begin(), keys.end(), [](int a, int b){ return abs(a) < abs(b) || (abs(a)==abs(b) && a < b); })`。
2. **只对"不同值"遍历**：哈希表去重后不同值个数 $U \le \min(n, 2\times10^5+1)$，避免对 $3\times10^4$ 个元素逐个判定的重复劳动。
3. **0 必须单独处理**：若不特判，`cnt[0] -= cnt[0]` 会把自己清零，奇数个 0 也能蒙混过关（如 `[0]`、`[0,0,0,2]` 会误判）。
4. **`2x` 越界**：$\lvert 2x \rvert \le 2\times10^5$，`int` 足够；但写成 `2LL * x` 更稳妥，也便于迁移到值域更大的版本。
5. **查询不存在的键**：C++ 的 `map::operator[]` 会插入默认值 0，Python 的 `Counter` 缺键返回 0——两者语义一致，正合需要（不足即失败）。
6. **消耗后清零**：`cnt[x] = 0` 保证每个值只被处理一次；否则后续再扫到 $x$ 会重复扣减 `2x`。
7. **总计数守恒**：可以顺带断言每次扣减后 `2x` 的计数非负——这正是第 3 步的检查项。

## 5. 正确性证明

**引理 1（搭档唯一性）**：设 $\{x, y\}$ 是合法对（$y = 2x$ 或 $x = 2y$）。若 $x \ne 0$，则 $y \in \{2x, x/2\}$，且这两个值互不相同。

**证明**：合法对的定义就是 $y = 2x$ 或 $x = 2y$，后者等价于 $y = x/2$。若 $2x = x/2$ 则 $3x/2 = 0$，即 $x = 0$，与 $x \ne 0$ 矛盾。∎

**引理 2（处理顺序保证"小搭档"已耗尽）**：按 $\lvert x \rvert$ 升序处理，轮到值 $x$（$x \ne 0$）时，`cnt[x/2] = 0`（若 $x/2$ 不是整数或不在表中，本就没有搭档）。

**证明**：$\lvert x/2 \rvert < \lvert x \rvert$，故 $x/2$ 在 $x$ 之前被处理（若它不是整数，则 $x$ 根本没有这个搭档）。$x/2$ 被处理时，算法要么因配对失败而返回 `false`（那结论已成立），要么把它的计数清零并扣掉相应数量的 $x$。因此轮到 $x$ 时 `cnt[x/2] = 0`。∎

**引理 3（贪心步骤的必要性）**：设处理到 $x$ 时 `cnt[x] = c > 0` 且此前未失败。则任何合法划分都必须把当前剩余的 $c$ 个 $x$ **全部**与 $2x$ 配对；因此若 `cnt[2x] < c` 则不存在合法划分。

**证明**：由引理 1，每个 $x$ 的搭档只能是 $2x$ 或 $x/2$；由引理 2，$x/2$ 的剩余计数为 0，故每个剩余的 $x$ 只能配 $2x$。$c$ 个不同的 $x$ 副本需要 $c$ 个不同的 $2x$ 副本（一个元素只能属于一对），所以必须 `cnt[2x] >= c`。∎

**引理 4（贪心不破坏可行性）**：若存在合法划分，则它在把 $c$ 个 $x$ 与 $c$ 个 $2x$ 配对后，剩余元素仍可合法划分。

**证明**：取任一合法划分 $\mathcal{P}$。由引理 3 的论证，$\mathcal{P}$ 中每个 $x$ 都与某个 $2x$ 配对（$x/2$ 的副本已全部用尽）。于是 $\mathcal{P}$ 中恰有 $c$ 对形如 $\{x, 2x\}$，把这些对整体删除后，剩下的对仍是 $\mathcal{P}$ 的子集，自然覆盖剩余元素且每对合法。∎

**定理**：算法返回 `true` 当且仅当存在把 `arr` 划分成若干 $\{x, 2x\}$ 的方案。

**证明**：

- **必要性（返回 true ⟹ 存在划分）**：算法每次成功扣减都显式构造了 `c` 对 $\{x, 2x\}$；处理结束时所有非零计数都被清零（0 的情形按偶数个两两配对），因此这些对恰好覆盖全部元素，构成合法划分。
- **充分性（存在划分 ⟹ 返回 false 不会发生）**：对处理过的不同值个数归纳。假设存在合法划分。处理第一个值 $x_1$ 时，若 $x_1 = 0$，其个数必须为偶数（0 只能与 0 配对），算法不返回 false；否则由引理 3，`cnt[2x_1] >= cnt[x_1]`，算法不返回 false，且由引理 4 剩余子问题仍可行。设前 $k$ 步都未失败且剩余子问题可行，第 $k+1$ 步同理不会失败（引理 3 保证计数足够），归纳下去算法必然把全部值处理完并返回 `true`。∎

> 💡 直观总结：每一步都是"当前绝对值最小的元素没有别的选择"，这是典型的**贪心选择唯一性**论证——因为不存在第二条边可选，贪心不需要比较，直接就是唯一解。

## 6. 复杂度分析

- **时间**：$O(n + U\log U)$。建计数表 $O(n)$；对 $U$ 个不同键排序 $O(U\log U)$；随后每个键 $O(1)$ 判定，其中哈希/平衡树查询 $O(1)$ / $O(\log U)$。最坏 $U = n = 3\times10^4$，总计约 $5\times10^5$ 次基本操作。
- **空间**：$O(U)$，即计数表；$U \le \min(n, 2\times10^5+1)$。排序的键数组也是 $O(U)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <map>
#include <algorithm>
#include <cstdlib>

using namespace std;

class Solution {
public:
    bool canReorderDoubled(vector<int>& arr) {
        map<int, int> cnt;
        for (int x : arr) cnt[x]++;

        vector<int> keys;
        for (auto& kv : cnt) keys.push_back(kv.first);
        sort(keys.begin(), keys.end(), [](int a, int b) {
            if (abs(a) != abs(b)) return abs(a) < abs(b);
            return a < b;
        });

        for (int x : keys) {
            int c = cnt[x];
            if (c == 0) continue;
            if (x == 0) {                    // 0 只能与 0 配对
                if (c % 2 != 0) return false;
                cnt[0] = 0;
                continue;
            }
            long long need = 2LL * x;
            if (cnt.find((int)need) == cnt.end() || cnt[(int)need] < c) return false;
            cnt[(int)need] -= c;
            cnt[x] = 0;
        }
        return true;
    }
};
```

### Python

```python
from collections import Counter

class Solution:
    def canReorderDoubled(self, arr: list[int]) -> bool:
        cnt = Counter(arr)
        for x in sorted(cnt, key=lambda v: (abs(v), v)):
            c = cnt[x]
            if c == 0:
                continue
            if x == 0:                       # 0 只能与 0 配对
                if c % 2:
                    return False
                cnt[0] = 0
                continue
            if cnt[2 * x] < c:
                return False
            cnt[2 * x] -= c
            cnt[x] = 0
        return True
```

## 8. 边界情况与易错点

1. **空数组**：`arr.length = 0` 是偶数，空划分合法，返回 `true`。
2. **奇数个 0**：`[0]`、`[0,0,0,2]` 都不合法。0 只能与 0 配，必须凑成偶数个；这也是最容易漏掉的特殊分支。
3. **负数方向**：`[-4,-2]` 合法（$-2$ 与 $-4$），`[4,2]` 合法；但只能按 $\lvert x \rvert$ 排序。按数值升序处理 $[-4,-2]$ 时，$-4$ 会去找 $-8$ 而失败。
4. **$\lvert x \rvert$ 相同时的顺序**：$x$ 与 $-x$ 互不为搭档（除非 $x = 0$），排序的 tie-break 不影响正确性，但写成稳定的全序便于复现。
5. **`2x` 越界**：值域 $10^5$ 时 `2x` 到 $2\times10^5$，仍在 `int` 内；若把约束放宽到 $10^9$ 就必须用 `long long` 建表。
6. **只判"存在"不判"数量"**：用 `set` 或 `bool` 记录是否出现过 $2x$ 是错的，必须比较**计数**（如 `[1,1,2]` 有 2 但不够两个 1）。
7. **配对后忘记清零**：会在后续遍历中重复消耗 $2x$，导致计数变负、误判为可行。
8. **朴素回溯会超时**：$n$ 高达 $3\times10^4$，只有"按 $\lvert x \rvert$ 升序的强制贪心"才是多项式且线性的。
