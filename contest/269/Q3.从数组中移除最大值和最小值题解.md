# LeetCode 从数组中移除最大值和最小值 题解

## 1. 题目概述

- **标题 / 题号**：从数组中移除最大值和最小值（#2091，medium）
- **链接**：https://leetcode.cn/problems/removing-minimum-and-maximum-from-array/
- **来源**：LeetCode 第 269 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定下标从 0 开始、由**互不相同**整数组成的数组 `nums`。一次**删除**操作定义为从数组的**前面**或**后面**移除一个元素。要求把数组中的**最小值**和**最大值**两个元素都移除，返回所需的最小删除次数。

**约束**：

- $1 \le n = \text{nums.length} \le 10^5$
- $-10^5 \le \text{nums[i]} \le 10^5$
- 元素**互不相同** $\Rightarrow$ $n \ge 2$ 时最小值、最大值的下标必不相同

> 💡 **审题三连**：① 只能从**两端**删、不能从中间挖——这决定了任何方案的结构都是「前缀 + 后缀」两段；② 要删的只是**两个特定元素**，其余元素删多删少无所谓，唯一目标是总次数最小；③ 元素互不相同 $\Rightarrow$ 两个目标各有唯一下标，本题彻底退化为**纯位置问题**：用最短的「前缀 + 后缀」覆盖两个指定下标。

## 2. 示例

**示例 1（极值分居两侧）**

```text
输入：nums = [2,10,7,5,4,1,8,6]
输出：5
解释：最小值 nums[5] = 1，最大值 nums[1] = 10。
      从前面删 2 个（2、10），从后面删 3 个（6、8、1），共 2 + 3 = 5。
```

**示例 2（极值挤在同一侧）**

```text
输入：nums = [0,-4,19,1,8,-2,-3,5]
输出：3
解释：最小值 nums[1] = -4，最大值 nums[2] = 19。
      两个极值相邻且靠左，从前面删 3 个（0、-4、19）一并解决，共 3。
```

**示例 3（单元素边界）**

```text
输入：nums = [101]
输出：1
解释：唯一元素既是最大值又是最小值，删 1 次即可。
```

## 3. 解题思路

### 3.1 暴力思路：二维枚举 (p, q)

任何删除方案都可以改写成「先从前面删 $p$ 个、再从后面删 $q$ 个」（§5 引理 1 严格证明这一点，顺序本身不影响删掉的集合）。于是朴素做法是枚举所有 $(p, q)$：要求 $p + q \le n$，检查两个目标下标是否都落在被删的前缀或后缀里，代价 $p + q$ 取最小。

- 时间：$(p, q)$ 组合约 $\frac{n(n+1)}{2} \approx 5 \times 10^9$ 个（$n = 10^5$），即使每个 $O(1)$ 检查也**必然超时**。
- 空间：$O(1)$。

浪费的根源：$n^2$ 个组合里绝大多数与「如何覆盖两个目标」毫无关系。真正的自由度只有**两个目标各自被哪一侧覆盖**。

### 3.2 核心观察：覆盖两个点的非劣形态只有 3 种

![核心观察：三种非劣形态](images/wc269_q3_three_cases.svg)

一趟扫描得到最小值下标 $a$、最大值下标 $b$，**归一化**为 $i = \min(a, b)$、$j = \max(a, b)$（$i \le j$，按**位置**而非按值）。按「$i$、$j$ 各由前缀还是后缀覆盖」分类，理论上有 4 种组合，其中一种不可行：

| 形态 | 覆盖方式 | 代价 | 说明 |
|------|----------|------|------|
| ① 双左 | 前缀删到 $j$（顺带覆盖 $i$） | $j + 1$ | 极值都靠左端时最优 |
| ② 双右 | 后缀删到 $i$（顺带覆盖 $j$） | $n - i$ | 极值都靠右端时最优 |
| ③ 分删 | 前缀删到 $i$ ＋ 后缀删到 $j$ | $(i+1) + (n-j)$ | 极值分居两端时最优 |
| ④ 交叉 | 前缀删到 $j$ ＋ 后缀删到 $i$ | $\ge (j+1)+(n-i) = n+1+(j-i)$ | **超出元素总数，不可行**：前缀删到 $j$ 时 $i$ 已被顺带删掉 |

$$\text{answer} = \min\big(\, j+1,\ \ n-i,\ \ (i+1)+(n-j)\,\big)$$

> ⚠️ **为什么没有「删中间段」？** $i$、$j$ 把数组切成左段 $[0, i]$、中段 $[i, j]$、右段 $[j, n-1]$。中段夹在两个目标**之间**，无论从哪头删都轮不到它先于目标被删；删它既覆盖不了 $i$ 也覆盖不了 $j$，纯属浪费次数。而左段、右段的价值只取决于「删到的最深位置」，最优方案里左段要么不删、要么删到 $i$ 或 $j$ 为止，右段对称——这正是三个候选的来历。

### 3.3 算法流程

![算法流程：一趟找极值，归一化后三候选取最小](images/wc269_q3_algorithm_flow.svg)

1. **一趟遍历**：同时维护最小值下标 `a` 与最大值下标 `b`（元素互不相同，无并列极值需要处理）；
2. **归一化**：`i = min(a, b)`，`j = max(a, b)`，保证 $i \le j$；
3. **三候选 $O(1)$ 计算**：`c1 = j + 1`（双左）、`c2 = n - i`（双右）、`c3 = (i + 1) + (n - j)`（分删）；
4. **返回** `min(c1, c2, c3)`。

### 3.4 示例演算

以示例 1 走查（`nums = [2,10,7,5,4,1,8,6]`，$n = 8$）：

![示例演算：三候选代价 6 / 7 / 5，取最小 5](images/wc269_q3_example_walkthrough.svg)

一趟遍历得 $a = 5$（min $= 1$）、$b = 1$（max $= 10$），归一化 $i = 1$、$j = 5$：

| 形态 | 删除范围 | 计算 | 代价 |
|------|----------|------|------|
| ① 全从左删 | 前缀 $[0, 5]$ | $j + 1 = 6$ | 6 |
| ② 全从右删 | 后缀 $[1, 7]$ | $n - i = 8 - 1 = 7$ | 7 |
| ③ 两侧分删 | 前缀 $[0, 1]$ ＋ 后缀 $[5, 7]$ | $(1+1) + (8-5) = 2 + 3$ | **5** |

$\text{answer} = \min(6, 7, 5) = 5$，与示例一致。

> 💡 **对照示例 2**：$a = 1$、$b = 2$，$i = 1$、$j = 2$，三候选 $\min(3,\ 7,\ 8) = 3$——极值挤在左端时「全从左删」最省。**极值越聚拢，单侧删越划算；极值越分散，两侧夹击越划算。**

## 4. 算法细节

1. **一趟遍历同时找两个极值**：`if (nums[k] < nums[a]) a = k; if (nums[k] > nums[b]) b = k;` 一个循环两个分支，比 `min_element` + `max_element` 各扫一遍少一半常数；Python 的 `nums.index(min(nums))` 写法要扫三趟，同为 $O(n)$，按简洁与效率自行取舍。
2. **归一化 $i \le j$ 是公式正确的前提**：三个候选都假设 $i$ 是**靠左**的极值下标、$j$ 是**靠右**的。若把 `minIdx`、`maxIdx` 原序代入，形态③会变成「左删 min 位置 + 右删 max 位置」——当 `minIdx > maxIdx`（示例 1 正是如此）时两个范围互相包含，含义错乱。注意 $i$ 处放的不一定是 min：示例 1 里 $i = 1$ 恰好是**最大值**的位置。
3. **枚举前缀长度的统一视角**：固定前缀删除数 $p$，剩余目标只能靠后缀，故总代价
   $$f(p) = p + \begin{cases} n - i, & 0 \le p \le i \\ n - j, & i+1 \le p \le j \\ 0, & j+1 \le p \le n \end{cases}$$
   $f$ 是三段线性函数，三段各自的最小值在 $p = 0$、$p = i+1$、$p = j+1$ 处取得，恰好对应候选②、③、①。「只有 3 种非劣形态」与「$f$ 只有 3 个有意义的临界点」是一枚硬币的两面。
4. **`min({c1, c2, c3})`**：C++ 的初始化列表语法，比嵌套 `min(min(c1, c2), c3)` 清爽。
5. **互不相同的作用**：保证 $n \ge 2$ 时 $i < j$ 严格成立、两个极值下标唯一。若元素可重复，三候选公式不再直接适用（见 §8 第 7 条与延伸思考）。

## 5. 正确性证明

**引理 1（结构引理）**：任何删除方案中，被「从前面」删掉的元素集合是原数组的一个前缀，被「从后面」删掉的元素集合是一个与其不相交的后缀。

**证明**：设原数组下标 $t$ 的元素被从前面删除，那一刻它是当前数组的首元素，故所有下标 $s < t$ 的元素都已被先删掉。反设其中某个 $s$ 是被从后面删掉的：删 $s$ 那一刻它是当前尾元素，故下标 $> s$ 的元素（含 $t$）都已先被删掉——与「$t$ 在删 $s$ 之后才被从前面删除」矛盾（每个元素只能被删一次）。故所有 $s < t$ 都是从前面删的，即「从前面删」的集合是前缀；对称地，「从后面删」的集合是后缀；每次删除删走一个当前元素，两集合不相交。∎

**引理 2（三形态代价）**：设 $0 \le i \le j \le n-1$ 为两个目标下标。一对 $(p, q)$（前缀长 $p$、后缀长 $q$，$p + q \le n$）能覆盖两目标，当且仅当满足下列某一形态，且各形态的最小代价为：

- **①** $p \ge j + 1$：最小代价 $j + 1$（$q = 0$，此时 $i \le j$ 被前缀顺带覆盖）；
- **②** $q \ge n - i$：最小代价 $n - i$（$p = 0$，$j \ge i$ 被后缀顺带覆盖）；
- **③** $p \ge i + 1$ 且 $q \ge n - j$：最小代价 $(i+1) + (n-j)$（要求 $i < j$ 使 $p + q \le n$；$i = j$ 时不可行）；
- **④** $p \ge j + 1$ 且 $q \ge n - i$：$p + q \ge (j+1) + (n-i) = n + 1 + (j - i) > n$，**不存在**这样的可行方案。

**证明**：覆盖条件的必要性：目标必须落在被删的前缀 $[0, p-1]$ 或后缀 $[n-q, n-1]$ 内。逐项验证：①中 $j \le p - 1 \iff p \ge j+1$；②中 $i \ge n - q$；③中 $i \le p-1$ 且 $j \ge n-q$。**可达性**：满足各形态条件的 $(p, q)$（且 $p + q \le n$）都能实现——先从前面删 $p$ 次，剩余数组是原数组的连续段 $[p, n-1]$，再从后面删 $q$ 次，恰好删掉原后缀 $[n-q, n-1]$。④中 $(j+1) + (n-i) = n + 1 + (j-i)$，当 $i < j$ 时严格大于 $n$，而任何方案至多删 $n$ 个元素，故该形态无可行解；即便放松为下界，它也不小于 $j + 1$（形态①）。∎

**定理**：$\text{answer} = \min\big(j+1,\ n-i,\ (i+1)+(n-j)\big)$，其中 $i \le j$ 为最小值、最大值下标中的较小者与较大者。

**证明**：由引理 1，任何可行方案对应一对 $(p, q)$；由引理 2，其覆盖方式必属形态①②③④之一，而④无解，故任何可行方案的代价 $\ge \min(j+1,\ n-i,\ (i+1)+(n-j))$。反之由引理 2 的可达性，三个候选值（$i<j$ 时）都能被合法方案实现，$n = 1$ 时见下方推论。最小值即答案。∎

**推论（$n = 1$ 无需特判）**：$n = 1$ 时 $i = j = 0$，三候选为 $\min(1,\ 1,\ 2) = 1$。其中形态③的值 $(i+1)+(n-j) = 2 > n$，对应「同一元素被前后缀各删一次」的**虚候选**——不可实现，但恒不小于①②，被支配，不影响最小值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟遍历找两个极值下标是主体开销，归一化与三候选计算仅 $O(1)$。这同时是下界：极值可能藏在任何位置，不读完整个数组就无法确定 $i$、$j$，故 $\Omega(n)$ 不可避免。
- **空间复杂度**：$O(1)$。仅 `a, b, i, j` 与三个候选值等常数个标量，不随输入规模增长。

## 7. 参考代码

### C++（一趟扫描版）

```cpp
class Solution {
public:
    int minimumDeletions(vector<int>& nums) {
        int n = nums.size();
        int a = 0, b = 0;                     // 最小值/最大值下标
        for (int k = 1; k < n; ++k) {
            if (nums[k] < nums[a]) a = k;
            if (nums[k] > nums[b]) b = k;
        }
        int i = min(a, b), j = max(a, b);     // 归一化 i <= j
        return min({j + 1, n - i, (i + 1) + (n - j)});
    }
};
```

### Python（一趟扫描版）

```python
class Solution:
    def minimumDeletions(self, nums: List[int]) -> int:
        n = len(nums)
        a = b = 0
        for k in range(1, n):
            if nums[k] < nums[a]:
                a = k
            if nums[k] > nums[b]:
                b = k
        i, j = min(a, b), max(a, b)
        return min(j + 1, n - i, i + 1 + n - j)
```

### Python（内置函数简洁版）

```python
class Solution:
    def minimumDeletions(self, nums: List[int]) -> int:
        i, j = sorted((nums.index(min(nums)), nums.index(max(nums))))
        return min(j + 1, len(nums) - i, i + 1 + len(nums) - j)
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一元素既是 min 又是 max，答案 1。公式自动成立（§5 推论），形态③的虚候选 $2$ 被支配，无需特判。
2. **$n = 2$**：$i = 0$、$j = 1$，三候选 $\min(2, 2, 2) = 2$——两个都得删，等于把数组删光，同样无需特判。
3. **忘归一化 $i \le j$**：直接把 `minIdx`、`maxIdx` 原序代入公式是本题**最高频错误**。示例 1 中 `minIdx = 5 > maxIdx = 1`，原序代入必错。
4. **差一错误**：「全左删」是 $j + 1$ 不是 $j$——下标从 0 起，删到 $j$（含 $j$ 本身）共 $j + 1$ 个；「全右删」是 $n - i$ 不是 $n - i - 1$——删下标 $i$ 到 $n - 1$ 共 $n - i$ 个。
5. **不要模拟删除过程**：用 deque 逐步「贪心删离目标近的一端」既繁琐又需额外论证正确性；静态分析三个候选即可 $O(1)$ 收尾，比赛时应直接走结构分析这条路。
6. **溢出**：$n \le 10^5$，候选值 $\le 2n \le 2 \times 10^5$，`int` 绰绰有余（Python 无此虑）。
7. **题目变体——允许重复元素**：若多个位置等于 min/max 且要求全部删掉，三候选公式失效，需覆盖**所有**目标下标（见延伸思考的一般化框架）。
8. **「删中间」的诱惑**：任何想从中间「挖」一个元素的冲动都违反操作定义——中间元素只能等两侧逐渐推进把它暴露到端头才能被删，引理 1 已说明删掉的永远是一头一尾两段。
