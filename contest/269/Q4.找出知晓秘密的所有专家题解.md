# LeetCode 找出知晓秘密的所有专家 题解

## 1. 题目概述

- **标题 / 题号**：找出知晓秘密的所有专家（#2092，hard）
- **链接**：https://leetcode.cn/problems/find-all-people-with-secret/
- **来源**：LeetCode 第 269 场周赛 Q4
- **难度**：困难
- **标签**：并查集、图、排序、广度优先搜索

**题意**：$n$ 个专家编号 $0$ 到 $n-1$。专家 $0$ 持有秘密，在时刻 $0$ 把秘密告诉专家 `firstPerson`。此后有 $M$ 场会议，$\text{meetings}[i] = [x_i, y_i, \text{time}_i]$：时刻 $\text{time}_i$ 专家 $x_i$、$y_i$ 见面，若**一方此刻知晓秘密**则立刻分享给另一方。秘密共享是**瞬时发生**的——同一时刻刚接到秘密的人，还能在**同时刻**的其他会议上继续外传。问所有会议结束后，哪些专家知晓秘密（答案顺序任意）。

**约束**：

- $2 \le n \le 10^5$
- $1 \le \text{meetings.length} \le 10^5$
- $0 \le x_i, y_i \le n-1$ 且 $x_i \ne y_i$
- $1 \le \text{time}_i \le 10^5$
- $1 \le \text{firstPerson} \le n-1$

> ⚠️ 本题题眼在「**瞬时**」二字：同一时刻的多场会议不是先后发生的孤立事件，而是一张**同时生效的图**——秘密可在其中跨会议连锁扩散**任意多跳**。逐场独立处理必然出错，必须按时间**成组**处理。

## 2. 示例

**示例 1（沿时间轴接力，无同刻连锁）**

```text
输入：n = 6, meetings = [[1,2,5],[2,3,8],[1,5,10]], firstPerson = 1
输出：[0,1,2,3,5]
解释：t=0 → 0 告诉 1；t=5 → 1 告诉 2；t=8 → 2 告诉 3；t=10 → 1 告诉 5。
```

**示例 2（不知晓者之间的会议不传播）**

```text
输入：n = 4, meetings = [[3,1,3],[1,2,2],[0,3,3]], firstPerson = 3
输出：[0,1,3]
解释：t=2 的会议 [1,2] 双方都不知晓，白开一场；t=3 的 [3,1] 与 [0,3] 把
      0、1、3 连成一个分量，3 已知晓 ⇒ 1 习得。2 始终不知。
```

**示例 3（同时间连锁传播——本题核心）**

```text
输入：n = 5, meetings = [[3,4,2],[1,2,1],[2,3,1]], firstPerson = 1
输出：[0,1,2,3,4]
解释：t=1 的两场会议 [1,2]、[2,3] 同时发生：1 知晓 → 2 习得，2 又在
      同一时刻把秘密传给 3；t=2 → 3 告诉 4。
```

## 3. 解题思路

### 3.1 暴力思路：排序后逐场处理

最直觉的写法：会议按时间排序，逐场扫描，一方知晓就点亮另一方：

```text
sort meetings by time
for [x, y, t] in meetings:
    if knows[x]: knows[y] = true
    if knows[y]: knows[x] = true
```

**这是错的**。反例就是示例 3：$t=1$ 的两场会议 $[1,2]$、$[2,3]$ 同刻发生，若扫描顺序恰好先 $[2,3]$ 后 $[1,2]$——$[2,3]$ 双方都不知晓，无事发生；$[1,2]$ 点亮 $2$，但 $3$ 永远错过了（同刻的会议已结算完）。输出 $[0,1,2,4]$，漏 $3$。

**根因**：同一时刻的会议应视为**同时结算**，知晓状态要在该时间组内传播到**不动点**（反复扩散直到无人新习得），而不是逐场单次判断。

两个修复方向：

- **修复 A**：对每个时间组反复扫描直到无变化。链式会议 $[1,2],[2,3],[3,4],\dots$ 一组内可有 $O(M)$ 条边，每轮只推进一跳，单组最坏 $O(M^2) = 10^{10}$，**超时**。
- **修复 B**：把「传播到不动点」识别为**图可达性**——这就是正解，见下。

### 3.2 核心观察：同时间会议 = 一张图，秘密按连通分量整块扩散

![核心观察：同时间会议构成一张图，秘密按连通分量扩散](images/fapws_concept.svg)

固定时刻 $t$，把该时刻**所有会议**看成无向图 $G_t$ 的边（端点是参会专家）。设进入时刻 $t$ 时的知晓集合为 $K$（此前所有时刻的传播结果）。由**瞬时性**：

- 若 $G_t$ 的某连通分量 $C$ 与 $K$ 相交（分量里有种子），则 $C$ 内人人可经「接收→同刻再分享」的连锁链从种子拿到秘密——传播链可以**任意长**，全部发生在时刻 $t$ 内 ⇒ $C$ **全员知晓**；
- 若分量 $C$ 与 $K$ 不相交，组内无人有秘密可传 ⇒ $C$ **无人知晓**。

于是时刻 $t$ 结束时的知晓集合恰为 $K$ 加上所有「含种子」的连通分量。算法骨架就此确定：

- **外层**：会议按 `time` 排序，切成互异时刻的时间组，按时间递增逐组处理；
- **内层**：用**并查集**维护组内连通分量，把含知晓者的分量整体点亮。

这里必须区分两个数组的**生命周期**，是本题第二个关键：

| 数组 | 语义 | 生命周期 |
|------|------|----------|
| `knows[]` | 是否知晓（终身事实，单调不减） | **持久**，跨组保留 |
| `parent[]` | 并查集连通（只在本组内有意义） | **临时**，组后必须重置 |

> ⚠️ 若 `parent` 跨组残留：上一组把 A、B 连通过（但双方都没习得秘密），下一组 B 单独与知晓者开会时，`find(B)` 沿残留路径可能挂到旧根上，造成**误点亮**。第 8 节第 2 条给出一个具体的 WA 反例。

### 3.3 算法流程：按时间分组 + 并查集四步循环

![算法流程：按时间分组，组内并查集四步循环](images/fapws_flow.svg)

每个时间组内依次执行：

1. **① 组内 union**：对组内每条会议 `union(x, y)`，把会议图的一个个连通分量收进并查集；
2. **② 收集种子根**：对组内每个参会者 $u$，若 `knows[u]` 为真，则把 `find(u)` 放入种子根集合——**存根不存人**，同一分量多个种子 `find` 后同根，天然去重；
3. **③ 点亮分量**：对组内每个参会者 $v$，若 `find(v)` 在种子根集合中，则 `knows[v] = true`；
4. **④ 重置**：对组内每条会议的两个端点执行 `parent[x] = x`——只清临时连通，`knows` 原样保留。

全部组处理完后，扫一遍 `knows` 收集答案。

### 3.4 示例演算

以示例 3 走查（排序后 $t=1$ 组 $\{[1,2],[2,3]\}$、$t=2$ 组 $\{[3,4]\}$）：

![示例演算：同时间连锁传播与组后重置](images/fapws_walkthrough.svg)

**t = 0**：`knows = {0, 1}`（初始传播，不入会议循环）。

**t = 1**（会议 $[1,2]$、$[2,3]$ 一组）：

| 步骤 | 操作 | 结果 |
|------|------|------|
| ① union | `union(1,2)`、`union(2,3)` | 分量 $\{1,2,3\}$ |
| ② 种子根 | `knows[1]=true` → 记根 `find(1)` | 种子根集合 = {该分量的根} |
| ③ 点亮 | `find(2)`、`find(3)` 同根 | `knows[2]=knows[3]=true` |
| ④ 重置 | `parent[1]=1`、`parent[2]=2`、`parent[3]=3` | 连通清空，`knows={0,1,2,3}` 保留 |

**t = 2**（会议 $[3,4]$ 一组）：`union(3,4)` → 分量 $\{3,4\}$；`knows[3]=true` → 种子根命中 → `knows[4]=true`；重置。最终 `knows={0,1,2,3,4}` ✅。

## 4. 算法细节

1. **排序与分组**：`sort` 按 `time` 升序，双指针切出同时间组 $[i, j)$。排序不稳定无妨——同 `time` 的会议必属同组，而组内处理顺序不影响结果（union 满足结合/交换律，②③④都按端点幂等）。
2. **种子根集合用「时间戳标记数组」实现**：`mark[find(u)] = 组起点下标 i`，判定时查 `mark[find(v)] == i`。组号随处理严格递增，历史标记绝不会误命中，还免去每组清空哈希集合的开销——这是「多轮询问、互不干扰」的经典**时间戳**技巧，比赛时比 `unordered_set` 更快也更短。
3. **重置只需逐端点 `parent[x] = x`，无需按树序自底向上**：本组内被改写过的 `parent` 只可能属于本组端点集合（第 5 节引理 2 严格证明），对每条会议的两个端点逐一归位即完备覆盖，顺序无关。
4. **并查集只配路径压缩、不配按秩合并**：`rank[]` 和 `parent[]` 一样是需要重置的状态——只重置 `parent` 忘了 `rank` 会埋雷。纯路径压缩的单次 `find` 摊还 $O(\log n)$，本题规模绰绰有余，实现也最短。
5. **时刻 0 不进循环**：`knows[0] = knows[firstPerson] = true` 直接初始化，等价于「第 0 组」，不必把它伪装成会议去排序。
6. **BFS 等价解法**：组内建邻接表 + 多源 BFS（种子全部入队，访问到即知晓）同样到达不动点，思路更直白、无重置烦恼；并查集版不建图、常数更小。复杂度同阶，见延伸思考。

## 5. 正确性证明

记互异的会议时刻升序为 $t_1 < t_2 < \dots < t_g$；$K_0 = \{0, \text{firstPerson}\}$ 为时刻 $0$ 传播后的知晓集；$G_k$ 为时刻 $t_k$ 的会议构成的无向图（顶点集恰为该组参会者）。

**引理 1（组内传播 = 连通分量闭包）**：设进入组 $k$（时刻 $t_k$ 之前）的知晓集为 $K$，则时刻 $t_k$ 结束时的知晓集为

$$K \;\cup\; \bigcup_{C \in \mathcal{C}(G_k),\; C \cap K \neq \varnothing} C,$$

其中 $\mathcal{C}(G_k)$ 是 $G_k$ 的连通分量族。

**证明**：分两个方向。

（⊇ 充分）对 $G_k$ 中的路径长度 $\ell$ 归纳：若 $u \in K$ 与 $v$ 之间有长为 $\ell$ 的路径 $u = v_0, v_1, \dots, v_\ell = v$，则 $v$ 在时刻 $t_k$ 结束时知晓。$\ell = 0$ 即 $v = u \in K$，成立。设对 $\ell - 1$ 成立：$v_{\ell-1}$ 在时刻 $t_k$ 内知晓，而 $(v_{\ell-1}, v_\ell)$ 是时刻 $t_k$ 的一场会议，故 $v_{\ell-1}$ 在此会议中把秘密传给 $v_\ell$。由**瞬时性**（同一时刻接收与再分享可叠加），整条链都落在时刻 $t_k$ 内。归纳完成。

（⊆ 必要）时刻 $t_k$ 内的每次习得都发生在某场**时刻 $t_k$ 的**会议 $(x, y)$ 中，且传播方在结算那一刻已知晓。对「习得所需的跳数」归纳：一跳习得者的传播方属于 $K$；$d$ 跳习得者的传播方是 $d-1$ 跳习得者。因而时刻 $t_k$ 结束时的每个知晓者，都存在一条从 $K$ 出发、每条边都是时刻 $t_k$ 会议的路径，即落在 $K$ 触及的连通分量中。∎

**引理 2（重置完备性）**：每组处理前 `parent` 处于「全员自环」状态；组内一切 `find`/`union` 只改写**本组端点集合** $S_k$ 中节点的 `parent`；步骤④对每条会议两端点归位后，`parent` 恢复全员自环。

**证明**：对组数归纳。第一组前构造 `parent[x] = x` 对全体成立。设组 $k$ 处理前全员自环，考察组内操作序列的不变式「被改写过的节点 $\subseteq S_k$」：入口端点本身属于 $S_k$；`find(x)` 的路径上，非根节点的 `parent` 必已被改写（否则自环即停），由归纳假设属于 $S_k$，路径终止的根亦然（根是路径上一员）。`union(a, b)` 改写的是 `find(a)` 的根，`find` 的路径压缩改写的是路径成员——都已证属于 $S_k$。故不变式保持。而 $S_k$ 恰是本组所有会议端点之并，步骤④对每条会议的两个端点执行 `parent[x] = x`，覆盖全部被改写者，恢复全员自环。∎

**定理（主定理）**：算法结束时 `knows` 集合等于真实传播过程的最终知晓集合。

**证明**：对组序 $k$ 归纳「处理完组 $1..k$ 后 `knows` = 真实过程中时刻 $t_k$ 末的知晓集」。基础：处理组 1 前 `knows` $= K_0$；因 $t_1 \ge 1 > 0$，$K_0$ 正是时刻 $t_1$ 之前的知晓集。归纳步：设处理组 $k$ 前 `knows` $= K$（时刻 $t_k$ 之前的知晓集）。由引理 2，组 $k$ 开始时并查集全员自环，于是步骤①沿边逐步 union 后，并查集的等价类恰为 $G_k$ 的连通分量（同一顶点集、同一边集下的传递闭包一致）。步骤②收集的种子根集合恰对应「与 $K$ 相交的分量」；步骤③把组内每个端点按 `find` 落点判定，等价于把这些分量的**全部成员**（分量成员都是本组某条边的端点）标记知晓、其余端点不动；步骤④只动 `parent`。故处理后 `knows` $= K \cup \bigcup_{C \cap K \neq \varnothing} C$，由引理 1 这正是时刻 $t_k$ 末的真实知晓集。归纳完成；输出即最终知晓集合。∎

**推论（时间戳正确性）**：`mark[r] = i` 仅在处理组 $i$ 时被写入；组号序列严格递增且互异，故判定 `mark[find(v)] == i` 当且仅当 $v$ 所在分量的根在本组被标记为种子根，历史标记不会误命中。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(M(\log M + \log n)\big)$。排序 $O(M \log M)$ 是主体；主循环中每条会议被 ①②③④ 四趟各扫一次，每次 `find` 为路径压缩下的摊还 $O(\log n)$。$M, n \le 10^5$ 时约为 $10^6$ 量级的指针操作，远低于时限。
- **空间复杂度**：$O(n + M)$。`parent`、`knows`、`mark` 各 $O(n)$；排序 C++ 原地、Python Timsort 额外 $O(M)$。
- 若把组内并查集换成组内 BFS：排序 $O(M \log M)$ + 每组建图并遍历 $O(\text{组大小})$，总计 $O(M \log M + M)$，略去 $\log n$ 因子，实践差别不大。

## 7. 参考代码

### C++（时间戳版并查集）

```cpp
class Solution {
  public:
    vector<int> parent;
    vector<int> mark;   // mark[根] = 组起点下标（时间戳），替代哈希集合

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // 路径压缩
            x = parent[x];
        }
        return x;
    }

    vector<int> findAllPeople(int n, vector<vector<int>>& meetings,
                              int firstPerson) {
        parent.resize(n);
        iota(parent.begin(), parent.end(), 0);
        mark.assign(n, -1);
        vector<bool> knows(n, false);
        knows[0] = knows[firstPerson] = true;          // 时刻 0 的初始传播

        sort(meetings.begin(), meetings.end(),
             [](const auto& a, const auto& b) { return a[2] < b[2]; });

        int m = meetings.size();
        for (int i = 0; i < m;) {
            int j = i;
            while (j < m && meetings[j][2] == meetings[i][2]) j++;

            for (int k = i; k < j; k++) {              // ① 组内 union
                int ra = find(meetings[k][0]), rb = find(meetings[k][1]);
                if (ra != rb) parent[ra] = rb;
            }
            for (int k = i; k < j; k++) {              // ② 标记种子根
                if (knows[meetings[k][0]]) mark[find(meetings[k][0])] = i;
                if (knows[meetings[k][1]]) mark[find(meetings[k][1])] = i;
            }
            for (int k = i; k < j; k++) {              // ③ 点亮分量成员
                if (mark[find(meetings[k][0])] == i) knows[meetings[k][0]] = true;
                if (mark[find(meetings[k][1])] == i) knows[meetings[k][1]] = true;
            }
            for (int k = i; k < j; k++) {              // ④ 重置（knows 保留）
                parent[meetings[k][0]] = meetings[k][0];
                parent[meetings[k][1]] = meetings[k][1];
            }
            i = j;
        }

        vector<int> ans;
        for (int p = 0; p < n; p++)
            if (knows[p]) ans.push_back(p);
        return ans;
    }
};
```

### Python（时间戳版并查集）

```python
class Solution:
    def findAllPeople(self, n: int, meetings: List[List[int]],
                      firstPerson: int) -> List[int]:
        parent = list(range(n))
        mark = [-1] * n
        knows = [False] * n
        knows[0] = knows[firstPerson] = True

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]   # 路径压缩
                x = parent[x]
            return x

        meetings.sort(key=lambda mtg: mtg[2])

        m = len(meetings)
        i = 0
        while i < m:
            j = i
            while j < m and meetings[j][2] == meetings[i][2]:
                j += 1
            for k in range(i, j):               # ① 组内 union
                ra, rb = find(meetings[k][0]), find(meetings[k][1])
                if ra != rb:
                    parent[ra] = rb
            for k in range(i, j):               # ② 标记种子根
                if knows[meetings[k][0]]:
                    mark[find(meetings[k][0])] = i
                if knows[meetings[k][1]]:
                    mark[find(meetings[k][1])] = i
            for k in range(i, j):               # ③ 点亮分量成员
                if mark[find(meetings[k][0])] == i:
                    knows[meetings[k][0]] = True
                if mark[find(meetings[k][1])] == i:
                    knows[meetings[k][1]] = True
            for k in range(i, j):               # ④ 重置（knows 保留）
                parent[meetings[k][0]] = meetings[k][0]
                parent[meetings[k][1]] = meetings[k][1]
            i = j

        return [p for p in range(n) if knows[p]]
```

## 8. 边界情况与易错点

1. **同时间会议逐场处理（最高频 WA）**：示例 3 本身就是反例——$[2,3]$ 排在 $[1,2]$ 前面就漏掉 3。必须成组结算到不动点。
2. **忘组后重置 `parent`（隐蔽 WA）**：具体反例：`n = 5, firstPerson = 4, meetings = [[1,2,1],[1,3,2],[2,0,2]]`，正确答案 $\{0, 2, 4\}$（$t=2$ 时 0 在会议 $[2,0]$ 中点亮 2；1、3 从未与知晓者同组连通）。若不重置：$t=1$ 组残留 `parent[1]=2`，$t=2$ 组 `union(1,3)` 时 `find(1)` 沿残留链走到 2，再 `union(2,0)` 后整棵树挂在 0 的根下——种子 0 的标记让 1、3 被**误点亮**，输出 $\{0,1,2,3,4\}$。机制：残留连通把本组端点的 `find` 链带到旧根，制造了本组并不存在的会议路径。
3. **混淆两个数组的生命周期**：`knows` 是持久事实，`parent` 是临时状态。口诀「**知晓终身有效，连通用完即弃**」。
4. **按秩合并不重置 `rank`**：与 `parent` 一样需要组后归零，漏掉会让后续组树结构失真；干脆只用路径压缩（见 §4 第 4 点）。
5. **`mark` 时间戳初值**：首个组号从 0 开始时，`mark` 初值必须取负数（如 $-1$），否则第一组会把「从未标记」误判为「已标记」。
6. **同刻重复会议对**：同一对专家在同一时刻出现多次，union 幂等、判定重复，无需去重。
7. **`firstPerson` 的处理**：直接初始化 `knows`，等价于「第 0 组」，别把它塞进会议列表参与排序。
8. **输出顺序**：题目允许任意顺序，按编号升序收集最省事；数据规模下无溢出风险。

**延伸思考**：若规定「每人拿到秘密后需消化 $d$ 个单位时间才能外传」，瞬时闭包即告失效——秘密沿时间轴变成**带延迟的扩散**，改用对每个专家维护最早知晓时刻 $\text{know}[v]$，按会议时间 Dijkstra 式松弛：$\text{know}[v] = \min(\text{know}[v],\ \max(t,\ \text{know}[u] + d))$（对会议 $(u, v, t)$，$t \ge \text{know}[u] + d$ 时可传播）。本题是 $d = 0$ 且同刻会议同时结算的退化特例；$d > 0$ 时同一时刻的会议不再「同时生效」，时间戳分组的闭包解法不再适用。
