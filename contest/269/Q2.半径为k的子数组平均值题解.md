# LeetCode 半径为k的子数组平均值 题解

## 1. 题目概述

- **标题 / 题号**：半径为k的子数组平均值（#2090，medium）
- **链接**：https://leetcode.cn/problems/k-radius-subarray-averages/
- **来源**：LeetCode 第 269 场周赛 Q2
- **难度**：中等
- **标签**：数组、滑动窗口、前缀和

**题意**：给定下标从 0 开始、长度为 $n$ 的数组 `nums` 与整数 $k$。对每个下标 $i$，若其左右两侧各有至少 $k$ 个元素，则 $\text{avgs}[i]$ 取以 $i$ 为中心、半径为 $k$ 的子数组（即窗口 $[i-k,\ i+k]$，共 $2k+1$ 个元素）的平均值——用**截断式整数除法**；否则 $\text{avgs}[i] = -1$。返回长度为 $n$ 的数组 `avgs`。

**约束**：

- $n = \text{nums.length}$，$1 \le n \le 10^5$
- $0 \le \text{nums[i]} \le 10^5$
- $0 \le k \le 10^5$

> ⚠️ **溢出预警**：窗口和最大可达 $10^5 \times 10^5 = 10^{10}$，远超 32 位 `int` 上界（约 $2.1 \times 10^9$），C++/Java 必须 用 64 位整数累加；Python 原生大整数无此问题。

> 💡 本题是**定长滑动窗口**的教科书式模板：所有窗口长度恒为 $2k+1$，中心右移一位窗口就整体右移一位——「出一进一」，每步 $O(1)$ 转移。比赛时识别出这一点，两分钟内即可写完。

## 2. 示例

**示例 1（一般情形）**

```text
输入：nums = [7,4,3,9,1,8,5,2,6], k = 3
输出：[-1,-1,-1,5,4,4,-1,-1,-1]
解释：窗口大小 2k+1 = 7。
- i=3：窗口 [0,6] = [7,4,3,9,1,8,5]，和 37，avg = 37/7 = 5。
- i=4：窗口 [1,7]，和 32，avg = 32/7 = 4。
- i=5：窗口 [2,8]，和 34，avg = 34/7 = 4。
- 其余下标左右元素不足 3 个，均为 -1。
```

**示例 2（k = 0）**

```text
输入：nums = [100000], k = 0
输出：[100000]
解释：窗口大小 1，每个下标的平均值就是 nums[i] 本身，所有下标都是合法中心。
```

**示例 3（窗口装不下）**

```text
输入：nums = [8], k = 100000
输出：[-1]
解释：窗口大小 200001 远大于 n = 1，无合法中心，全 -1。
```

## 3. 解题思路

### 3.1 暴力思路：逐中心求和

最直接的做法是对每个合法中心 $i \in [k,\ n-1-k]$，内层循环遍历 $\text{nums}[i-k..i+k]$ 求和再除以 $2k+1$；不合法的中心填 $-1$。

- 时间：每个合法中心 $O(k)$，整体最坏 $O(n \cdot k)$，当 $k \approx n/2$ 时退化为 $O(n^2) \approx 10^{10}$ 次操作，$n = 10^5$ 下**必然超时**。
- 空间：$O(1)$。

问题出在**重复计算**：相邻中心的窗口重叠 $2k$ 个元素，暴力却每次从头加起。

### 3.2 核心观察：定长窗口 → 出一进一

![核心观察：定长窗口平移，出一进一](images/wc269_q2_window_concept.svg)

把中心 $i$ 的窗口和记为 $S_i$。**所有窗口长度恒为 $2k+1$，且中心每右移一位，窗口恰好整体右移一位**：窗口 $[i-k,\ i+k]$ 与 $[i+1-k,\ i+1+k]$ 的交集是 $[i+1-k,\ i+k]$，重叠 $2k$ 个元素；变化的只有两端——左端 $\text{nums}[i-k]$ 离开、右端 $\text{nums}[i+k+1]$ 进入。于是：

$$
S_{i+1} = S_i - \text{nums}[i-k] + \text{nums}[i+k+1]
$$

每步 $O(1)$ 即可由旧和推出新和，总共 $n - 2k$ 步，彻底消掉重复求和。这就是**定长滑动窗口**——与 209 那类「变长窗口」不同，它连收缩逻辑都不需要，每步固定「出一进一」。

### 3.3 算法流程

![算法流程：先铺 -1，合法区间内滑窗平移](images/wc269_q2_algorithm_flow.svg)

维护变量：`window = 2k+1`（窗口大小）、`sum`（当前窗口和，64 位）、`ans`（初值全 `-1` 的答案数组）。

1. `ans` 初始化为 $n$ 个 $-1$；
2. 若 $2k+1 > n$：整个数组装不下一个完整窗口，直接返回全 $-1$；
3. 计算首窗 $[0,\ 2k]$ 的和 `sum`，填 `ans[k] = sum / window`；
4. 循环 $i$ 从 $k+1$ 起，只要 $i + k < n$：`sum += nums[i+k] - nums[i-k-1]`（进右出左），`ans[i] = sum / window`；
5. 返回 `ans`。

> 💡 **先铺 `-1` 再覆盖**：边界下标（$i < k$ 或 $i > n-1-k$）从未进入循环，天然保持初值 $-1$，省去逐下标判断边界的分支。

### 3.4 示例演算

以示例 1 走查（`nums = [7,4,3,9,1,8,5,2,6]`，`k = 3`，窗口大小 7）：

![示例演算：滑窗三步平移全过程](images/wc269_q2_example_walkthrough.svg)

| 中心 i | 窗口范围 | 进入(+) / 离开(−) | sum | avg = sum/7 | ans[i] |
|--------|---------|------------------|-----|-------------|--------|
| 3 | [0, 6] | 初始：7+4+3+9+1+8+5 | 37 | 5 | 5 |
| 4 | [1, 7] | +2（进）− 7（出） | 32 | 4 | 4 |
| 5 | [2, 8] | +6（进）− 4（出） | 34 | 4 | 4 |
| 6 | — | $i + k = 9 \ge n$，终止 | — | — | −1 |

其余下标 $i \in \{0,1,2,6,7,8\}$ 保持初值 $-1$，最终输出 `[-1,-1,-1,5,4,4,-1,-1,-1]`，与示例一致。

## 4. 算法细节

1. **转移公式的下标推导**：处理中心 $i$ 时，上一中心是 $i-1$（窗口 $[i-1-k,\ i-1+k]$）。新进入的右端是 $\text{nums}[i+k]$，刚离开的左端是上一窗口最左端 $\text{nums}[i-k-1]$。两个下标之差恰为窗口长度 $2k+1$，可作自检。
2. **循环边界的两种等价写法**：C++ 用 `for (int i = k + 1; i + k < n; ++i)`，Python 用 `range(k + 1, n - k)`——后者是「合法中心 $[k,\ n-1-k]$」的左闭右开形式，二者完全等价。**不要**写成 `i < n`，否则右端 `nums[i+k]` 越界。
3. **`window > n` 提前返回**：既处理了「全 `-1`」的退化情形，也保证后续 `nums[i-k-1]`、`nums[i+k]` 的下标安全（首窗 $[0,\ 2k]$ 装得下）。
4. **64 位累加**：`sum` 声明为 `long long`（Java 用 `long`）。转移式 `sum += nums[i+k] - nums[i-k-1]` 中两个 `int` 先做减法再累加——差值范围为 $\pm 10^5$，`int` 中转安全，无需先转再算。
5. **前缀和对照版**：定长窗口求和本质是区间和，也可用前缀和 $O(1)$ 查询：$\text{sum}_i = \text{prefix}[i+k+1] - \text{prefix}[i-k]$（`prefix[0] = 0`）。写法更对称，但多 $O(n)$ 空间；滑窗版 $O(1)$ 空间、常数更小，比赛优先。

## 5. 正确性证明

**引理 1（合法中心范围）**：$\text{avgs}[i] \ne -1$ 当且仅当 $k \le i \le n-1-k$；该范围非空当且仅当 $2k+1 \le n$。

**证明**：窗口 $[i-k,\ i+k]$ 完整落在数组内 $\iff i-k \ge 0$ 且 $i+k \le n-1 \iff k \le i \le n-1-k$。区间非空 $\iff k \le n-1-k \iff 2k+1 \le n$。∎

**引理 2（相邻窗口转移）**：对满足 $k \le i \le n-2-k$ 的每个 $i$（即 $i$ 与 $i+1$ 均为合法中心），有 $S_{i+1} = S_i - \text{nums}[i-k] + \text{nums}[i+k+1]$。

**证明**：$S_i$ 对应多重集合 $\{\text{nums}[j] : i-k \le j \le i+k\}$，$S_{i+1}$ 对应 $\{\text{nums}[j] : i+1-k \le j \le i+1+k\}$。两区间之交为 $[i+1-k,\ i+k]$，故对称差恰为 $\{i-k\} \cup \{i+k+1\}$：$i-k$ 只属于旧窗口（贡献被减去），$i+k+1$ 只属于新窗口（贡献被加入）。逐项求和即得等式。∎

**定理**：算法输出与题面定义完全一致：合法中心 $i$ 处输出 $\lfloor S_i / (2k+1) \rfloor$，其余处输出 $-1$。

**证明**：**边界**：由引理 1，$-1$ 恰好填在非法中心处，而算法只对 $[k,\ n-1-k]$ 覆盖（循环从 $k$ 起步、条件 $i+k<n$ 即 $i \le n-1-k$），初始铺的 $-1$ 在非法位置原样保留。**窗口和**：对 $i$ 归纳——归纳基础：首窗求和遍历 $[0,\ 2k]$，恰是中心 $k$ 的窗口，$S_k$ 正确；归纳步骤：设处理中心 $i$ 前 `sum` $= S_{i-1}$，由引理 2（取 $i-1$ 为转移起点），执行 `sum += nums[i+k] - nums[i-k-1]` 后 `sum` $= S_i$。**截断除法**：约束保证 $\text{nums}[j] \ge 0$，故 $S_i \ge 0$，C++/Java 整数除法向零截断与非负数的向下取整一致，即题面要求的截断式除法。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。首窗求和 $O(2k+1)$；滑窗共 $n-2k$ 步、每步 $O(1)$；初始化 $O(n)$。每个元素至多「进窗一次、出窗一次」，总体线性。这已是下界——至少要读一遍 `nums` 才能给出所有平均值。
- **空间复杂度**：$O(1)$。仅 `sum`、`window` 等常数个变量（答案数组不计入额外空间）；前缀和版为 $O(n)$。

## 7. 参考代码

### C++（定长滑动窗口）

```cpp
class Solution {
public:
    vector<int> getAverages(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> ans(n, -1);                     // 先铺 -1
        int window = 2 * k + 1;
        if (window > n) return ans;                 // 装不下完整窗口 → 全 -1
        long long sum = 0;
        for (int i = 0; i < window; ++i) sum += nums[i];   // 首窗 [0, 2k]
        ans[k] = sum / window;                      // 中心 i = k
        for (int i = k + 1; i + k < n; ++i) {
            sum += nums[i + k] - nums[i - k - 1];   // 进右出左，O(1) 转移
            ans[i] = sum / window;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getAverages(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        ans = [-1] * n
        window = 2 * k + 1
        if window > n:
            return ans
        s = sum(nums[:window])                      # 首窗 [0, 2k]
        ans[k] = s // window
        for i in range(k + 1, n - k):               # 等价于 i + k < n
            s += nums[i + k] - nums[i - k - 1]      # 进右出左
            ans[i] = s // window
        return ans
```

### C++（前缀和版，对照）

```cpp
class Solution {
public:
    vector<int> getAverages(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> ans(n, -1);
        vector<long long> p(n + 1, 0);
        for (int i = 0; i < n; ++i) p[i + 1] = p[i] + nums[i];
        int window = 2 * k + 1;
        for (int i = k; i + k < n; ++i)             // 每个中心独立查询
            ans[i] = (p[i + k + 1] - p[i - k]) / window;
        return ans;
    }
};
```

## 8. 边界情况与易错点

1. **窗口和溢出**：最大约 $10^{10} > 2^{31}-1$，C++ 忘写 `long long` 是本题**最高频 WA**；Python 无此问题。
2. **`2k+1 > n` 时全 `-1`**：包括 $n = 1$、$k = 10^5$ 这类极端组合（示例 3）。不提前返回的话，首窗循环会越界读 `nums`。
3. **`k = 0` 退化**：`window = 1`，`ans = nums` 原样拷贝（示例 2）。滑窗代码无需特判自然正确：每步「出 `nums[i-1]` 进 `nums[i]`」。
4. **转移下标写反/写错**：进入的是 `nums[i+k]`（当前中心右端），离开的是 `nums[i-k-1]`（上一窗口左端）。误写成 `nums[i-k]`（当前窗口左端）会把还在窗口内的元素误减，是最典型的下标笔误。
5. **循环上界**：条件是 $i + k < n$，不是 $i < n$。写成后者会访问 `nums[i+k]` 越界。
6. **截断式除法**：元素均非负，C++/Java `/` 与 Python `//` 行为一致。但若题目变体出现负数，C++/Java 整除**向零取整**而 Python `//` **向下取整**，两者在负数上不同，需手动 `floor` 对齐题意。
7. **先铺 `-1` 再覆盖**优于逐下标判断边界：分支更少、不会漏判左右两侧之一（只判 $i \ge k$ 忘判 $i \le n-1-k$ 是常见漏网）。
