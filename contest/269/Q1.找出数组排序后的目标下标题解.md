# LeetCode 找出数组排序后的目标下标 题解

## 1. 题目概述

- **标题 / 题号**：找出数组排序后的目标下标（#2089，easy）
- **链接**：https://leetcode.cn/problems/find-target-indices-after-sorting-array/
- **来源**：LeetCode 第 269 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序、计数、二分查找

**题意**：给定下标从 0 开始的整数数组 `nums` 与目标值 `target`。**目标下标**是满足 `nums[i] == target` 的下标 `i`。将 `nums` 按**非递减**顺序排序后，返回由所有目标下标组成的列表；答案需按**递增**顺序排列，若 `target` 不存在则返回**空**列表。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums[i]}, \text{target} \le 100$

> 💡 作为签到题，最短路径不是「老实排序再扫描」，而是意识到：**升序数组中 `target` 块的位置只由「比它小的元素个数」决定**。一趟遍历统计两个计数变量 `less` / `equal`，答案区间 $[\text{less},\ \text{less}+\text{equal}-1]$ 直接算出来——全程不动数组。

## 2. 示例

**示例 1（多个目标下标）**

```text
输入：nums = [1,2,5,2,3], target = 2
输出：[1,2]
解释：排序后，nums 变为 [1,2,2,3,5]。满足 nums[i] == 2 的下标是 1 和 2。
```

**示例 2（单个目标下标）**

```text
输入：nums = [1,2,5,2,3], target = 3
输出：[3]
解释：排序后，nums 变为 [1,2,2,3,5]。满足 nums[i] == 3 的下标是 3。
```

**示例 3（空答案合法）**

```text
输入：nums = [1,2,5,2,3], target = 4
输出：[]
解释：nums 中不含值为 4 的元素，返回空列表，无需特判。
```

## 3. 解题思路

### 3.1 暴力思路：直译题面

最老实的做法是**严格照题面模拟**：排序 → 从左到右扫描 → 收集 `nums[i] == target` 的下标：

```text
sort(nums)
return [i for i in 0..n-1 if nums[i] == target]
```

时间 $O(n \log n)$（排序主导），$n = 100$ 下轻松通过，比赛一分钟写完提交。但它做了一件**多余的功**：排序把全部元素的相对顺序都确定了下来，而题目只用到一条信息——**`target` 落在哪些位置**。比 `target` 小的元素谁先谁后、比 `target` 大的元素怎么排，对答案**零影响**。

> ⚠️ 签到题的时间预算也可以省：与其花 $O(n \log n)$ 换来一堆用不上的顺序信息，不如直接「算出」`target` 该在哪。

### 3.2 核心观察：排序 = 按值分块，计数定位

![核心观察：升序数组按值分块，target 块起点由 less 决定](images/wc269_q1_count_concept.svg)

升序排序的唯一结构效果是**按值分块、块内连续**。设：

- $\text{less}$ = 严格小于 `target` 的元素个数
- $\text{equal}$ = 等于 `target` 的元素个数

排序后数组必然呈三段式：`[< target 的 less 个] [== target 的 equal 个] [> target 的其余]`。前 $\text{less}$ 个位置被更小元素占满，紧随其后的 $\text{equal}$ 个位置恰属于 `target`，因此目标下标集合就是：

$$
\{\,\text{less},\ \text{less}+1,\ \dots,\ \text{less}+\text{equal}-1\,\}
$$

$\text{equal} = 0$ 时区间为空，返回 `[]`。**小于或大于 `target` 的元素内部如何排列不影响这个结论**，所以无需真的排序。

### 3.3 算法流程

![算法流程：一趟遍历三分类计数 → 区间生成](images/wc269_q1_algorithm_flow.svg)

一趟遍历 + 三分类判定：每个元素与 `target` 比较后落入 `less++`、`equal++`、跳过三条分支之一；遍历结束直接生成区间 $[\text{less},\ \text{less}+\text{equal}-1]$。没有排序、没有第二遍扫描、输出天然递增。

### 3.4 示例演算

以 `nums = [1,2,5,2,3]`、`target = 2` 为例走查一遍：

![示例演算：计数定位全过程](images/wc269_q1_example_walkthrough.svg)

| 步骤 | v = nums[i] | 与 target=2 比较 | less | equal |
|------|-------------|------------------|------|-------|
| 1 | 1 | $1 < 2$ → less++ | 1 | 0 |
| 2 | 2 | $2 == 2$ → equal++ | 1 | 1 |
| 3 | 5 | $5 > 2$ → 跳过 | 1 | 1 |
| 4 | 2 | $2 == 2$ → equal++ | 1 | 2 |
| 5 | 3 | $3 > 2$ → 跳过 | 1 | 2 |

遍历结束：$\text{less} = 1$、$\text{equal} = 2$，目标区间 $= [1,\ 1+2-1] = [1, 2]$，与排序后数组 `[1,2,2,3,5]` 中 2 的实际位置吻合。

## 4. 算法细节

1. **三分类一次遍历**：`if (v < target) ++less; else if (v == target) ++equal;`——大于 `target` 的分支不用写，天然被跳过。
2. **less 必须「严格小于」**：误写 `v <= target` 是典型笔误，会把起点左移到第一个 `target` 之前。
3. **区间生成零逻辑**：`for (i = less; i < less + equal; ++i)`，Python 直接 `list(range(less, less + equal))`。左闭右开写法让 `equal == 0` 时自然为空，无需特判。
4. **比赛备选：二分版**。官方标签含 Binary Search——先 `sort`，再用 `lower_bound` / `upper_bound` 定位 `target` 区间两端，同样正确，$O(n \log n)$。适合手边模板熟、不想现场推计数不变式的场景；计数版在三个维度上更优：线性时间、不修改入参、零额外结构。
5. **值域思路（完整计数排序）**：$1 \le \text{nums[i]} \le 100$，也可开 101 个桶做计数排序。但只需 `target` 一个值的位置，两个标量足够，桶都嫌重。

## 5. 正确性证明

**引理 1（分块连续性）**：数组按非递减排序后，所有值 $< \text{target}$ 的元素占据前 $\text{less}$ 个位置，所有值 $= \text{target}$ 的元素占据紧接着的 $\text{equal}$ 个位置。

**证明**：非递减序列中，任取值 $x < \text{target}$ 的元素与值 $y \ge \text{target}$ 的元素，必有 $x$ 排在 $y$ 之前，否则出现逆序与有序性矛盾。故值 $< \text{target}$ 的 $\text{less}$ 个元素整体位于其余元素之前，恰好占满下标 $[0, \text{less}-1]$。同理，值 $= \text{target}$ 的元素既不与前面更小的元素交错（前述论证），也不与后面 $> \text{target}$ 的元素交错（对称论证），故连续占据 $[\text{less},\ \text{less}+\text{equal}-1]$。∎

**定理**：排序后满足 `nums[i] == target` 的下标集合恰为 $\{\text{less}, \dots, \text{less}+\text{equal}-1\}$，且按此生成的答案严格递增。

**证明**：由引理 1，值等于 `target` 的元素排序后连续占据区间 $[\text{less},\ \text{less}+\text{equal}-1]$，故目标下标集合与该区间一一对应；算法按自然数序枚举区间，输出严格递增。$\text{equal} = 0$ 时区间为空，对应返回空列表。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟遍历统计两个计数；生成结果 $O(\text{equal}) \le O(n)$。对比直译版 $O(n \log n)$——$n = 100$ 时差异无感，但若约束放到 $10^5$ 级别，计数版依旧线性，排序版才开始吃力。
- **空间复杂度**：$O(1)$。仅两个计数变量（输出列表不计入额外空间），且不修改原数组。

## 7. 参考代码

### C++（计数定位，一趟遍历）

```cpp
class Solution {
public:
    vector<int> targetIndices(vector<int>& nums, int target) {
        int less = 0, equal = 0;
        for (int v : nums) {                      // 一趟遍历三分类
            if (v < target) ++less;
            else if (v == target) ++equal;
        }
        vector<int> ans;
        ans.reserve(equal);
        for (int i = less; i < less + equal; ++i) // 直接生成区间
            ans.push_back(i);
        return ans;                               // 天然递增
    }
};
```

### Python

```python
class Solution:
    def targetIndices(self, nums: List[int], target: int) -> List[int]:
        less = sum(1 for v in nums if v < target)
        equal = sum(1 for v in nums if v == target)
        return list(range(less, less + equal))    # equal=0 时自然为空
```

### Python（二分版，对照）

```python
class Solution:
    def targetIndices(self, nums: List[int], target: int) -> List[int]:
        nums.sort()
        lo = bisect_left(nums, target)
        hi = bisect_right(nums, target)
        return list(range(lo, hi))
```

> ⚠️ 二分版 `nums.sort()` 会修改入参数组；比赛无碍，工程中若调用方依赖原顺序需先拷贝。

## 8. 边界情况与易错点

1. **`target` 不存在**：`equal = 0`，`range(less, less)` 为空，自然返回 `[]`，无需 if 特判。
2. **全部等于 `target`**：`less = 0`，答案 `[0, 1, …, n−1]`。
3. **`less` 的比较方向**：必须**严格小于**。误写 `v <= target` 会让起点左移 1，是本题最典型的 WA。
4. **返回的是排序后的下标**：不是原数组里 `target` 的下标！直译版先排序再收集不会踩坑；不排序又收集原下标，方向就错了。
5. **升序输出**：区间生成天然递增；直译版排序后从左到右扫描也天然递增，均无需最后再 `sort`。
6. **无溢出风险**：$n \le 100$，计数与下标均在 `int` 范围内绰绰有余。
7. **空数组不会出现**：约束保证 $n \ge 1$，但计数版即便 $n = 0$ 也返回 `[]`，逻辑自洽。
