# LeetCode 删除树节点 题解

## 1. 题目概述

- **标题 / 题号**：删除树节点（#1273，medium）
- **链接**：https://leetcode.cn/problems/delete-tree-nodes/
- **来源**：LeetCode 第 14 场双周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、树形 DP

**题意**：给一棵以节点 0 为根的树：共 `nodes` 个节点，第 $i$ 个节点的值是 `value[i]`，父节点是 `parent[i]`（`parent[0] = -1`）。把**每一棵"节点值之和为 0"的子树**（连同其全部后代）整体删除，返回删除后剩余的节点数。

**约束**：

- $1 \le nodes \le 10^4$
- $-10^5 \le value[i] \le 10^5$
- `parent.length == nodes`，`parent[0] == -1`，输入构成合法的树

## 2. 示例

**示例 1**

```text
输入：nodes = 7, parent = [-1,0,0,1,2,2,2], value = [1,-2,4,0,-2,-1,-1]
输出：2
解释：节点 3 的子树和为 0，删除节点 3；
     节点 2 的子树和为 4+(-2)+(-1)+(-1) = 0，删除节点 2、4、5、6。
     剩下节点 0 和节点 1，共 2 个。
```

**示例 2**

```text
输入：nodes = 7, parent = [-1,0,0,1,2,2,2], value = [1,-2,4,0,-2,-1,-2]
输出：6
解释：只有节点 3 的子树和为 0，删除它；节点 2 的子树和为 -1，保留。剩 6 个。
```

## 3. 解题思路

### 3.1 暴力思路

对每个节点 $v$ 都 DFS 一遍求出以 $v$ 为根的子树和，再把所有子树和为 0 的节点标记删除——$O(n^2)$，$n = 10^4$ 时是 $10^8$ 级别，C++ 勉强、Python 必超时。稍微动一下脑子：**每个节点的子树和都可以由孩子的子树和累加得到**，一次自底向上的遍历（后序 DFS）就能求出全部子树和，$O(n)$。

### 3.2 核心观察：零和子树"删了白删"，一遍后序足够

![后序自底向上累加子树和与保留计数](images/bw14_q3_postorder_model.svg)

本题表面上有"先删哪棵子树、删完再重算"的顺序问题，其实是假象——**关键观察**：

1. **删除一个零和子树，不会改变其它任何子树的和**。被删子树对祖先的贡献恰好是 0（它的整棵子树和就是 0），祖先的子树和不变；与它不相交的子树更不受影响。所以"所有零和子树"构成一个**确定的、可同时删除**的集合，在原始树上算一次就够，不存在迭代到不动点的过程。
2. 由此，一次**后序遍历**即可同时完成两件事：累加子树和 $sum(v)$，累加保留计数 $cnt(v)$：

$$cnt(v) = \begin{cases} 0, & sum(v) = 0 \text{（整棵删除）} \\ 1 + \sum_{c \in children(v)} cnt(c), & sum(v) \ne 0 \end{cases}$$

答案就是 $cnt(root)$。孩子 $c$ 若自身零和，$cnt(c) = 0$，对父亲的贡献自动为"整棵不存在"。

### 3.3 算法流程：BFS 序的逆序做迭代后序

![BFS 序逆序即自底向上](images/bw14_q3_bottomup_flow.svg)

1. 由 `parent` 建孩子邻接表；
2. 从根 0 出发做一次 **BFS**，得到数组 `order`——BFS 序保证**孩子必排在双亲之后**；
3. **倒序**扫描 `order`（即全部叶子先处理、根最后处理，等价于后序"先孩子后双亲"的顺序）：
   - $sum(v) \mathrel{+}= value[v]$（此时孩子的 $sum$ 已全部累加进来）；
   - 若 $sum(v) = 0$ 则 $cnt(v) = 0$，否则 $cnt(v)$ 保持 $1$ 加上孩子们已累加的 $cnt$；
   - 把 $sum(v)$、$cnt(v)$ 上传给父亲。
4. 返回 $cnt(0)$。

用"BFS 序 + 倒序扫描"而非递归，是因为 $n$ 可达 $10^4$ 且树可能退化成**一条链**——递归深度 $10^4$ 在 Python 会直接 `RecursionError`（默认栈深 1000），C++ 也逼近栈上限。迭代写法彻底免疫深度问题。

### 3.4 示例演算

![示例演算：7 节点树的两轮删除](images/bw14_q3_example_walkthrough.svg)

示例 1 的树：0 的孩子是 1、2；1 的孩子是 3；2 的孩子是 4、5、6。倒序处理（叶子优先）：

- 节点 3：$sum = 0$ → 删，$cnt_3 = 0$；
- 节点 4、5、6：$sum$ 各为 $-2, -1, -1$，各 $cnt = 1$，上传给 2；
- 节点 2：$sum = 4 + 0 \cdot (\text{已删的 } 3 \text{ 不在} ) + (-2) + (-1) + (-1) = 0$ → 整棵删除，$cnt_2 = 0$；
- 节点 1：$sum = -2 + 0 = -2 \ne 0$，$cnt_1 = 1 + cnt_3 = 1$；
- 节点 0：$sum = 1 + (-2) + 0 = -1 \ne 0$，$cnt_0 = 1 + cnt_1 + cnt_2 = 1 + 1 + 0 = 2$ ✓。

示例 2 中节点 2 的子树和为 $4 - 2 - 1 - 2 = -1 \ne 0$，$cnt_2 = 4$，最终 $cnt_0 = 1 + 1 + 4 = 6$ ✓。

## 4. 算法细节

1. **建图**：`children[parent[i]].push_back(i)`，只对 $i \ge 1$（根的 `parent` 是 -1）。
2. **BFS 序的正确性**：BFS 中节点出队时才扩展孩子，因此 `order` 中任何孩子的下标一定大于父亲的下标；倒序扫描即保证处理 $v$ 时它的孩子全部处理完毕——这正是后序的语义，无需显式栈。
3. **上传即合并**：处理完 $v$ 立即把 `sum[v]`、`cnt[v]` 加到 `parent[v]` 上，省去"先遍历再求和"的第二趟。
4. **计数初始化为 1**：`cnt[v] = 1` 表示"自己保留"，孩子的贡献逐个加上来；置 0 只发生在 `sum[v] == 0` 时。
5. **求和范围**：$|sum| \le 10^4 \times 10^5 = 10^9$，`int` 上限 $2.1 \times 10^9$ 勉强够但已贴边，C++ 中用 `long long` 求和最稳妥；Python 无此问题。

## 5. 正确性证明

**引理 1（删除集合的确定性）**：设 $Z = \{v : sum(v) = 0\}$ 为**原始树**上子树和为 0 的节点集合，则"删除所有零和子树"的结果恰为"删除 $Z$ 中所有节点的子树"，且 $Z$ 在删除过程中不发生变化。

**证明**：删除子树 $T_u$（$u \in Z$）对任一其它节点 $w$ 的子树和 $sum(w)$ 的影响：若 $T_u \subseteq T_w$（$u$ 是 $w$ 的后代或 $w$ 本身…… $w \notin T_u$，因为子树被删后 $w$ 也不在了），则 $sum(w)$ 减去 $sum(u) = 0$，不变；若 $T_u \cap T_w = \emptyset$，无影响。故任何删除顺序下，各节点子树和（若仍存活）保持原值，$Z$ 不因删除而改变，所有 $u \in Z$ 的子树可**同时**删除。∎

**引理 2（存活判定）**：删除后节点 $v$ 存活 $\iff$ $v$ 及其所有祖先（含自身）的子树和均非 0。

**证明**：$v$ 被删除 $\iff$ $v$ 落在某棵被删子树内 $\iff$ 存在 $u \in Z$ 使 $v \in T_u$ $\iff$ $v$ 的某个祖先或 $v$ 本身属于 $Z$。取逆否即得。∎

**定理**：算法返回值 $cnt(0)$ 等于删除后剩余节点数。

**证明**：对树高归纳证明更强的命题：倒序处理完 $v$ 后，$cnt(v)$ 等于"以 $v$ 为根的子树在删除操作后的存活节点数"（且若 $sum(v) = 0$ 则 $cnt(v) = 0$）。若 $v$ 是叶子：$sum(v) = value[v]$，$sum(v) = 0$ 时整棵（单节点）删除、$cnt(v) = 0$ ✓；否则存活 1 个 ✓。若 $v$ 有孩子：由归纳假设，各孩子 $c$ 的 $cnt(c)$ 已是 $T_c$ 删除后的存活数；$sum(v) = value[v] + \sum_c sum(c)$ 按原始树算出（引理 1 保证删除不改变它）。若 $sum(v) = 0$，由引理 1、2 整棵 $T_v$ 删除，存活 0 = $cnt(v)$ ✓；若 $sum(v) \ne 0$，$v$ 自身存活（引理 2：其祖先的情况由外层归纳处理），存活数 = $1 + \sum_c cnt(c)$ ✓。根处理完毕时 $cnt(0)$ 即全树存活数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建邻接表、BFS、倒序扫描各一趟。
- **空间**：$O(n)$。邻接表、`order`、`sum`、`cnt` 均为 $O(n)$；迭代写法栈深 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int deleteTreeNodes(int nodes, vector<int>& parent, vector<int>& value) {
        vector<vector<int>> children(nodes);
        for (int i = 1; i < nodes; ++i) children[parent[i]].push_back(i);

        // BFS 序：孩子必排在双亲之后；其逆序即是合法的自底向上（后序）处理顺序
        vector<int> order;
        order.reserve(nodes);
        order.push_back(0);
        for (size_t k = 0; k < order.size(); ++k)
            for (int c : children[order[k]]) order.push_back(c);

        vector<long long> sum(nodes, 0);   // 子树和（含被删子树，删除不改变其余子树和）
        vector<int> cnt(nodes, 1);         // 子树中保留下来的节点数
        for (int k = nodes - 1; k >= 0; --k) {
            int v = order[k];
            sum[v] += value[v];            // 孩子的 sum 已在更早的轮次累加进来
            if (sum[v] == 0) cnt[v] = 0;   // 整棵子树删除
            int p = parent[v];
            if (p != -1) { sum[p] += sum[v]; cnt[p] += cnt[v]; }
        }
        return cnt[0];
    }
};
```

### Python

```python
class Solution:
    def deleteTreeNodes(self, nodes: int, parent: List[int], value: List[int]) -> int:
        children = [[] for _ in range(nodes)]
        for i in range(1, nodes):
            children[parent[i]].append(i)

        # BFS 序：孩子必排在双亲之后；其逆序即是合法的自底向上（后序）处理顺序
        order = [0]
        k = 0
        while k < len(order):
            v = order[k]
            k += 1
            order.extend(children[v])

        sub_sum = [0] * nodes    # 子树和（含被删子树，删除不改变其余子树和）
        cnt = [1] * nodes        # 子树中保留下来的节点数
        for v in reversed(order):
            sub_sum[v] += value[v]          # 孩子的和已在更早的轮次累加进来
            if sub_sum[v] == 0:
                cnt[v] = 0                  # 整棵子树删除
            p = parent[v]
            if p != -1:
                sub_sum[p] += sub_sum[v]
                cnt[p] += cnt[v]
        return cnt[0]
```

> 💡 两份代码均通过官方 2 组示例（输出 `2`、`6`）以及 308 组随机测试：与**独立的定义级模拟**（递归求每个节点子树和，再逐节点检查"自身与所有祖先的子树和均非 0"来计数）对拍 `mismatch = 0`；其中包含 $n = 10^4$ 的**链形树**，验证迭代实现的深度安全性。

## 8. 边界情况与易错点

1. **递归深度**：$10^4$ 节点可能是一条链，递归 DFS 在 Python 必炸栈（默认深度 1000）。用 BFS 序逆序的迭代法最稳；坚持递归就要 `sys.setrecursionlimit` 并祈祷平台栈够。
2. **"删除"不改变其他子树的和**：这是能一次遍历解决的全部依据（引理 1）。若写成了"先删一层、再对剩下的树重算"，会引入不必要的迭代，还容易在"删过的孩子还参不参与父亲求和"上纠结——答案：按**原树**算即可。
3. **零和子树嵌套**：节点 3 删除后节点 1 的子树和是 $-2 + 0 = -2$（按原树算，被删孩子贡献照加，反正加的是 0）；不要试图"把被删孩子的值清零再求和"，多余且易错。
4. **根也可能整棵被删**：$sum(0) = 0$ 时答案为 0（单节点 `value=[0]` 的用例）。
5. **计数与求和要一起上传**：上传 $sum$ 不上传 $cnt$（或反之），父亲就无法同时完成两个递推。
6. **求和溢出**：$10^4 \times 10^5 = 10^9$ 贴近 `int` 上限，C++ 用 `long long` 一步到位。
