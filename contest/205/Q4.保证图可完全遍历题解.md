# LeetCode 保证图可完全遍历 题解

## 1. 题目概述

- **标题 / 题号**：保证图可完全遍历（#1579，hard）
- **链接**：https://leetcode.cn/problems/remove-max-number-of-edges-to-keep-graph-fully-traversable/
- **来源**：LeetCode 第 205 场周赛 Q4
- **难度**：困难
- **标签**：并查集、贪心、图论

**题意**：Alice 和 Bob 共享一个含 $n$ 个节点的无向图，边分三类：**类型 1** 只能 Alice 走，**类型 2** 只能 Bob 走，**类型 3** 两人都能走。`edges[i] = [type_i, u_i, v_i]` 表示 $u_i$、$v_i$ 之间有一条类型为 `type_i` 的双向边。在**两人都能从任一节点到达所有其他节点**（图可被两人完全遍历）的前提下，求**最多能删除多少条边**；若无论如何都无法完全遍历，返回 $-1$。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{edges.length} \le \min(10^5,\ 3n(n-1)/2)$
- $\text{edges}[i] = [\text{type}_i, u_i, v_i]$，$1 \le \text{type}_i \le 3$，$1 \le u_i < v_i \le n$
- 所有 $(\text{type}_i, u_i, v_i)$ 互不相同——注意**同一对 $(u,v)$ 可以同时拥有多个类型的边**

> 💡 题眼：删最多 ⇔ 保留最少。两人各自需要一棵生成树，而**公共边能同时挂进两棵树**——先用类型 3 边搭好「公共生成森林」$F_3$，再各自补独占边，保留数恰好取到下界 $2(n-1) - |F_3|$。

## 2. 示例

**示例 1**

```text
输入：n = 4, edges = [[3,1,2],[3,2,3],[1,1,3],[1,2,4],[1,1,2],[2,3,4]]
输出：2
解释：删除 [1,1,2] 和 [1,1,3] 后，Alice 与 Bob 仍可完全遍历；
      再删任何一条都会有人断开，所以最多删 2 条。
```

**示例 2**

```text
输入：n = 4, edges = [[3,1,2],[3,2,3],[1,1,4],[2,1,4]]
输出：0
解释：每条边都不可少——删任何一条，都有一人无法完全遍历。
```

**示例 3**

```text
输入：n = 4, edges = [[3,2,3],[1,1,2],[2,3,4]]
输出：-1
解释：Alice 到不了节点 4，Bob 到不了节点 1，无解。
```

## 3. 解题思路

### 3.1 暴力思路

对 $m$ 条边枚举所有删除子集（$2^m$ 种），每种删法对 Alice、Bob 各跑一次连通性检查：$m \le 10^5$ 时完全不可行。退一步做「逐条试删」——每删一条就检查两人连通性、不行就放回——也要 $O(m \cdot (n + m)) \approx 10^{10}$，依然超时。

关键认知：**判断「删一条边是否破坏连通」根本不需要真的删**——并查集里 $\text{find}(u) = \text{find}(v)$ 就说明这条边两端早已连通、它只会闭合成环，对连通性毫无贡献。于是自然的想法是「凡成环的边全删」。但真正的难点在于：**保留哪些边才能既让两人连通、又让保留数最少**——类型 3 边同时服务两人，独占边只服务一人，如何取舍需要论证（见 §5）。

### 3.2 核心观察：公共边「一石二鸟」

![核心观察：公共边一石二鸟，保留总数 = 2(n−1) − |公共森林|](images/wc205_q4_shared_edges_first.svg)

记 $T_1, T_2, T_3$ 为三种类型的边集，保留集为 $S$。三个层层递进的观察：

**观察一（问题刻画）**：Alice 能完全遍历 $S$ ⇔ 子图 $(V,\ S \cap (T_1 \cup T_3))$ 连通；Bob 同理用 $T_2 \cup T_3$。两人互不干扰，各自只关心一个连通性——「可完全遍历」就是「各自有一棵生成树」。

**观察二（计数下界）**：连通 $n$ 个点至少 $n-1$ 条边。设 $S$ 中公共边 $k$ 条、Alice 独占 $a$ 条、Bob 独占 $b$ 条，则 $a + k \ge n-1$ 且 $b + k \ge n-1$，两式相加得

$$|S| = a + b + k \ge 2(n-1) - k$$

**公共边越多，保留数的下界越低**——这就是「一石二鸟」的定量刻画。

**观察三（公共边的极限）**：公共边不能无限用。保留的公共边若在 $T_3$ 中成环，环上任何一条对两人都冗余（见 §5 引理 3），最小保留集里它们构成森林。森林大小的极限是公共图 $G_3 = (V, T_3)$ 的**生成森林** $F_3$，$|F_3| = n - c(G_3)$（$c$ 为 $G_3$ 的连通分量数）。

三条观察合流：先用 $F_3$ 把两人「同步」连通到 $c(G_3)$ 个分量，再各自补 $c(G_3) - 1$ 条独占边，总保留 $|F_3| + 2(c(G_3) - 1) = 2(n-1) - |F_3|$，恰好钉死观察二的下界。

### 3.3 算法流程：两个并查集、三遍扫描

![算法流程图：两个并查集，三遍扫描](images/wc205_q4_algorithm_flow.svg)

1. 建立**两套并查集** `faA`、`faB`，各初始化为 $n$ 个独立分量。
2. **第一遍，只扫类型 3**：每条公共边在 `faA`、`faB` 里**各做一次** union（两次都要执行）；任一成功则 `keep++`，两个都失败说明两边都已连通、可删。此阶段两套并查集状态完全同步，效果等价于对 $G_3$ 贪心建生成森林。
3. **第二遍，扫类型 1**：只在 `faA` 里 union，成功则 `keep++`，失败即对 Alice 冗余、可删。
4. **第二遍，扫类型 2**：只在 `faB` 里 union，同理。
5. **判定**：数根，若 `faA`、`faB` 的分量数都为 1，答案 $= m - \text{keep}$；否则返回 $-1$。

### 3.4 示例演算

![示例演算：三遍扫描的完整走查](images/wc205_q4_example_walkthrough.svg)

以示例 1（$n = 4$，6 条边）走查：第一遍保留两条橙色公共边 $(1,2)$、$(2,3)$，两人分量同步变为 $\{1,2,3\}\{4\}$；第二遍类型 1 中 $(1,3)$ 两端已连通、$(1,2)$ 与公共边重复，双双删除，只用 $(2,4)$ 把 Alice 补全连通；类型 2 用 $(3,4)$ 把 Bob 补全。共保留 4 条，答案 $6 - 4 = 2$，删掉的正是 $(1,1,3)$ 与 $(1,1,2)$。

## 4. 算法细节

1. **两套并查集各司其职**：`faA` 只吃类型 1 + 类型 3，`faB` 只吃类型 2 + 类型 3。类型 3 边要**同时喂给两套**。
2. **短路求值陷阱（本题头号 WA 点）**：C++ 的 `unite(faA,..) || unite(faB,..)` 与 Python 的 `or` 都会短路——`faA` 成功合并后就跳过 `faB` 的合并，导致 Bob 侧状态残缺。必须写成两条独立语句，再判断「任一成功」。
3. **第一遍的同步性**：两套并查集在第一遍里吃进完全相同的边、状态始终相同，因此「任一成功 ⇔ 两个都成功」。第二遍起两套才真正分岔。
4. **成环即冗余**：某条边 union 失败 ⇔ $\text{find}(u) = \text{find}(v)$ ⇔ 两端已连通 ⇔ 该边对当前这套并查集是环上多余边，删除不破坏连通性。
5. **连通性判定两种等价写法**：数根（`find(i) == i` 的个数为 1），或分别统计 Alice / Bob 侧成功合并次数是否等于 $n-1$。两人都要检查，只查一人是经典错误。
6. **无需排序/分类**：两遍扫描只按 `e[0]` 过滤，边处理顺序不影响结果（分量计数论证，见 §5 定理 2）。路径压缩的写法足以通过，无需按秩合并。
7. **下标从 1 开始**：并查集数组开 $n+1$ 大小。

## 5. 正确性证明

以下记 $m = |E|$，$T_1, T_2, T_3$ 为三种类型的边集，$G_3 = (V, T_3)$，$c(\cdot)$ 为连通分量数，$F_3$ 为 $G_3$ 的生成森林。

**引理 1（遍历刻画）**：边集 $S$ 可行（两人都可完全遍历）⇔ $(V,\ S \cap (T_1 \cup T_3))$ 连通且 $(V,\ S \cap (T_2 \cup T_3))$ 连通。

**证明**：Alice 的可达关系恰是 $S \cap (T_1 \cup T_3)$ 诱导的连通关系，「从任一点可达所有点」即该子图连通；Bob 同理。∎

**引理 2（计数下界）**：任一可行集 $S$ 满足 $|S| + |S \cap T_3| \ge 2(n-1)$，即 $|S| \ge 2(n-1) - |S \cap T_3|$。

**证明**：可行 ⇒ 两个子图都连通 ⇒ 各自包含生成树 ⇒ $|S \cap (T_1 \cup T_3)| \ge n-1$ 且 $|S \cap (T_2 \cup T_3)| \ge n-1$。相加，注意 $S \cap T_3$ 被数了两次：
$|S| + |S \cap T_3| \ge 2(n-1)$。∎

**引理 3（公共边无环）**：最小可行集 $S^*$ 中，$S^* \cap T_3$ 是 $G_3$ 中的森林，从而 $|S^* \cap T_3| \le n - c(G_3) = |F_3|$。

**证明**：若 $S^* \cap T_3$ 含环 $C$，任取 $e \in C$：$C - e$ 仍用**纯公共边**连接 $e$ 的两端，而公共边两人都能走，故在 $S^* - e$ 中 Alice 与 Bob 的连通关系都不变，$S^* - e$ 仍可行，与 $S^*$ 最小矛盾。又 $G_3$ 中任一森林的每棵树都完整落在 $G_3$ 的某个分量内、至多（点数 $-1$）条边，按分量求和得边数 $\le n - c(G_3)$。∎

**定理 1（最优保留数）**：问题可行时，最少保留数恰为 $2(n-1) - |F_3|$。

**证明**：
*下界*：可行集有限，取最小的 $S^*$。由引理 2 与引理 3：
$|S^*| \ge 2(n-1) - |S^* \cap T_3| \ge 2(n-1) - |F_3|$。

*可达*：先取 $F_3$（两人同步并入各自并查集），此时两人分量划分相同，均为 $G_3$ 的分量划分。注意**任何类型 3 边的两端必在 $G_3$ 的同一分量内**，而 $F_3$ 已把每个分量内部连通，故 $T_1 \cup T_3$ 连通 ⇔ $F_3 \cup T_1$ 连通。于是若原问题可行（$T_1 \cup T_3$ 连通），第二遍对 `faA` 逐条尝试类型 1 边必能把分量合并到 1 个，恰成功 $c(G_3) - 1$ 次；Bob 同理。总保留
$$|F_3| + 2\big(c(G_3) - 1\big) = |F_3| + 2\big(n - |F_3| - 1\big) = 2(n-1) - |F_3|,$$
取到下界。∎

**定理 2（算法正确性）**：§3.3 的三遍扫描算法在可行时返回 $m - \big(2(n-1) - |F_3|\big)$，不可行时返回 $-1$。

**证明**：第一遍中两套并查集状态始终相同；某条类型 3 边合并失败 ⇔ 其两端已在已保留公共边构成的森林的同一棵树内 ⇔ 它对 $G_3$ 的生成森林冗余。按任意顺序贪心，每次成功合并使分量数恰减 1，从 $n$ 降到 $c(G_3)$，故成功次数恒为 $n - c(G_3) = |F_3|$，与顺序无关——第一遍保留的正是 $G_3$ 的一个生成森林。第二遍同理：Alice 侧成功合并次数为分量从 $c(G_3)$ 降到 1 所需的 $c(G_3) - 1$（可行时），保留边构成商图 $G_1 / P_3$ 的生成森林；Bob 侧对称。最后数根判定两人连通性并兜底 $-1$。结合定理 1，返回值 $= m - \text{最少保留数} = \text{最大删除数}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n + m) \cdot \alpha(n))$。两遍全量扫描各 $O(m)$ 次近乎常数的并查集操作，末尾数根 $O(n \log n)$ 以内（路径压缩后近乎 $O(n)$）。
- **空间复杂度**：$O(n)$。两套并查集各 $n+1$ 个位置，其余为 $O(1)$ 标量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxNumEdgesToRemove(int n, vector<vector<int>>& edges) {
        vector<int> faA(n + 1), faB(n + 1);
        iota(faA.begin(), faA.end(), 0);
        iota(faB.begin(), faB.end(), 0);
        auto find = [](vector<int>& fa, int x) {
            while (fa[x] != x) { fa[x] = fa[fa[x]]; x = fa[x]; }
            return x;
        };
        auto unite = [&](vector<int>& fa, int u, int v) {
            u = find(fa, u); v = find(fa, v);
            if (u == v) return false;
            fa[u] = v;
            return true;
        };

        int keep = 0;
        // 第一遍：公共边，两套并查集都要合并（写成两条语句，防短路）
        for (auto& e : edges) {
            if (e[0] == 3) {
                bool a = unite(faA, e[1], e[2]);
                bool b = unite(faB, e[1], e[2]);
                if (a || b) ++keep;
            }
        }
        // 第二遍：独占边各归各
        for (auto& e : edges) {
            if (e[0] == 1) {
                if (unite(faA, e[1], e[2])) ++keep;
            } else if (e[0] == 2) {
                if (unite(faB, e[1], e[2])) ++keep;
            }
        }

        // 两人都必须全连通
        int cA = 0, cB = 0;
        for (int i = 1; i <= n; ++i) {
            if (find(faA, i) == i) ++cA;
            if (find(faB, i) == i) ++cB;
        }
        if (cA != 1 || cB != 1) return -1;
        return (int)edges.size() - keep;
    }
};
```

### Python

```python
class Solution:
    def maxNumEdgesToRemove(self, n: int, edges: List[List[int]]) -> int:
        fa_a = list(range(n + 1))
        fa_b = list(range(n + 1))

        def find(fa, x):
            while fa[x] != x:
                fa[x] = fa[fa[x]]
                x = fa[x]
            return x

        def union(fa, u, v):
            ru, rv = find(fa, u), find(fa, v)
            if ru == rv:
                return False
            fa[ru] = rv
            return True

        keep = 0
        # 第一遍：公共边，两套并查集都合并（不能用 or 短路）
        for t, u, v in edges:
            if t == 3:
                ma = union(fa_a, u, v)
                mb = union(fa_b, u, v)
                if ma or mb:
                    keep += 1
        # 第二遍：独占边各归各
        for t, u, v in edges:
            if t == 1:
                keep += union(fa_a, u, v)
            elif t == 2:
                keep += union(fa_b, u, v)

        if sum(1 for i in range(1, n + 1) if find(fa_a, i) == i) != 1:
            return -1
        if sum(1 for i in range(1, n + 1) if find(fa_b, i) == i) != 1:
            return -1
        return len(edges) - keep
```

## 8. 边界情况与易错点

1. **短路求值（最常见 WA）**：C++ `unite(faA,..) || unite(faB,..)`、Python `union(..) or union(..)` 都会跳过第二个合并。类型 3 边必须两边都执行 union，见 §4 第 2 点。
2. **只检查一人连通**：$-1$ 的判定要求 Alice、Bob **都**只剩 1 个分量；示例 3 中两人各缺一个点，只查一人会误判可行。
3. **同一 $(u,v)$ 多种类型的边**：题目只保证三元组互异，$(u,v)$ 可同时有类型 3 与类型 1 的边。公共边连通后，同点对的独占边自动判冗余，无需特判——示例 1 的 $(1,2)$ 正是如此。
4. **$n = 1$**（若数据出现）：两人天然全连通，所有边都可删；数根个数为 1 自动成立，算法无需修改。
5. **顺序无关**：三遍扫描内部按任意顺序处理边都不影响答案（定理 2 的分量计数论证），不必排序或稳定分区。
6. **并查集数组开 $n + 1$**：节点下标从 1 开始，开成 $n$ 会越界。
7. **数值范围**：$m \le 10^5$、$\text{keep} \le 2n$，`int` 足够，无溢出风险。
