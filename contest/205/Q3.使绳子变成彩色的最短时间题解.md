# LeetCode 使绳子变成彩色的最短时间 题解

## 1. 题目概述

- **标题 / 题号**：使绳子变成彩色的最短时间（#1578，medium）
- **链接**：https://leetcode.cn/problems/minimum-time-to-make-rope-colorful/
- **来源**：LeetCode 第 205 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、字符串、动态规划

**题意**：`n` 个气球排在一根绳子上，`colors[i]` 是第 `i` 个气球的颜色，`neededTime[i]` 是移除第 `i` 个气球所需的时间（秒）。Bob 要移除若干气球，使绳子上**任意相邻两个气球颜色都不同**，返回移除总时间的最小值。

**约束**：

- $n = \text{colors.length} = \text{neededTime.length}$，$1 \le n \le 10^5$
- $1 \le \text{neededTime}[i] \le 10^4$
- `colors` 仅由小写英文字母组成

> 💡 题眼：把串切成**极大同色连续段**。段与段之间天然异色，删除只发生在段内；每段至多留 1 个气球，留 `neededTime` 最大的那个，段代价闭式为 $\text{sum} - \max$。

## 2. 示例

**示例 1**

```text
输入：colors = "abaac", neededTime = [1,2,3,4,5]
输出：3
解释：移除下标 2 的 'a'（耗时 3），剩下 "abac"，无相邻同色。
```

**示例 2**

```text
输入：colors = "abc", neededTime = [1,2,3]
输出：0
解释：已无相邻同色，什么都不用删。
```

**示例 3**

```text
输入：colors = "aabaa", neededTime = [1,2,3,4,1]
输出：2
解释：移除下标 0 和下标 4 的 'a'，各耗时 1，总时间 2。
```

## 3. 解题思路

### 3.1 暴力思路

每个气球都有「删 / 不删」两种选择，朴素枚举 $2^n$ 种组合再逐一检查合法性，$n \le 10^5$ 下完全不可行。

稍加分析可以立刻降维：合法性约束是**纯局部**的（只看相邻），把串按颜色切成极大同色段后，长度为 $k$ 的段**必须删掉 $k-1$ 个、至多保留 1 个**（证明见 §5 引理 1、2）。于是问题按段独立：对每段枚举「保留哪一个」，段长 $k$ 枚举 $k$ 种，全局合计 $O(n)$。这已经是正确复杂度——离正解只差最后一步观察：**保留谁根本不用枚举，是闭式决定的**。

### 3.2 核心观察：同色段保留「最贵」的气球

![核心观察：极大同色段至多保留 1 个气球，保留最贵的](images/wc205_q3_run_keep_max.svg)

三个层层递进的观察：

**观察一（结构）**：合法方案 ⇔ 每个极大同色段至多保留 1 个气球。段内任意两个保留气球，它们中间的位置全是同色，最终必然形成相邻同色对；而相邻两个极大段的颜色必不同（否则会并成同一段），段间永远安全。

**观察二（代价）**：段长为 $k$ 的段必删 $k-1$ 个，段内删除代价 $=\text{sum} - \text{保留项}$。要让代价最小 ⇔ 保留项取到段内最大值 $\max$。**保留 `neededTime` 最大的气球**，段代价即为 $\text{sum} - \max$。

**观察三（赛场写法）**：不必显式切段。从左到右扫描，维护 `kept` = 当前段「存活代表」的 `neededTime`（即段内已扫部分的最大值）。每遇到一对相邻同色气球，就让二者「打擂台」：**较小者（输家）计入答案被删，较大者（赢家）成为新的存活代表**。

### 3.3 算法流程：相邻同色打擂台

![算法流程图：单次扫描，输家付费、赢家留守](images/wc205_q3_pairwise_flow.svg)

维护 `ans = 0` 与 `kept = neededTime[0]`，从 $i = 1$ 扫到 $n-1$：

- `colors[i] == colors[i-1]`：同色对决——`ans += min(neededTime[i], kept)`，再 `kept = max(kept, neededTime[i])`；
- 否则：换色开新段，`kept = neededTime[i]`。

扫描结束，`ans` 即答案。单次遍历、$O(1)$ 附加空间。

### 3.4 示例演算

![示例演算：abaac 逐对走查](images/wc205_q3_walkthrough.svg)

对示例 1 `colors = "abaac", neededTime = [1,2,3,4,5]`：只有 $i=3$ 处 `'a' == 'a'` 触发一次对决，`ans += min(4, 3) = 3`，`kept` 升级为 $4$，最终 `ans = 3`。

对示例 3 `colors = "aabaa", neededTime = [1,2,3,4,1]`，分三段结算：

| 段 | 气球时间 | sum | max | sum − max |
|----|----------|-----|-----|-----------|
| `aa` | 1, 2 | 3 | 2 | 1 |
| `b` | 3 | 3 | 3 | 0 |
| `aa` | 4, 1 | 5 | 4 | 1 |

答案 $= 1 + 0 + 1 = 2$。逐对 / 分段两种视角算出的值恒等，证明见 §5 定理 2。

## 4. 算法细节

1. **两个标量走天下**：`ans`（答案累计）与 `kept`（当前段存活代表的代价）。不显式建段、不开额外数组。
2. **`kept` 的含义**：始终等于**当前同色段已扫部分的 `neededTime` 最大值**。换色时重置为新气球代价；同色时与新来者取 $\max$——这正是「段内保留 max」的流式实现。
3. **等价的原地写法**：不引入 `kept`，直接把擂台结果写回数组：`ans += min(neededTime[i], neededTime[i-1]); neededTime[i] = max(neededTime[i], neededTime[i-1]);`。二者完全等价（改写后的 `neededTime[i]` 正好扮演 `kept`），但**修改了入参**，更推荐 `kept` 变量版。
4. **为什么不能对每个相邻同色对直接累加 `min(neededTime[i-1], neededTime[i])` 就完事**？段长超过 2 时，左边的赢家还要继续和右边比。反例：`"aaa", neededTime = [2,1,5]`，不带 `kept` 传递会误得 $\min(2,1)+\min(1,5)=2$，正确答案是 $8-5=3$（保留 $5$，删 $2$ 和 $1$）。**存活代表的传递是正确性的命门**。
5. **数值范围**：$\text{ans} \le n \cdot \max(\text{neededTime}) = 10^9$，在 32 位 `int` 范围内但已接近半程，C++ 中放宽约束时须换 `long long`；Python 无此顾虑。

## 5. 正确性证明

**引理 1（结构引理）**：任一合法方案中，每个极大同色段至多保留 1 个气球。

**证明**：设某极大段（区间 $[l, r]$，`colors[l..r]` 同色且两端越界或异色）中保留了下标 $i < j$ 两个气球。最终绳子是原序列的**子序列**，保持原有顺序，故子序列中位于 $i$ 与 $j$ 之间的保留气球，其原下标必落在 $(i, j) \subseteq [l, r]$ 内，全是同色气球。取子序列中 $i$ 后面的第一个保留气球 $k$（若存在），则 $i$ 与 $k$ 相邻且同色；若不存在，则 $i$ 与 $j$ 直接相邻且同色。两种情况都与合法性矛盾。∎

**引理 2（可行性引理）**：每个极大同色段各保留恰好 1 个气球的方案必合法。

**证明**：考察子序列中相邻的两个保留气球，设来自段 $s_p$ 与 $s_q$（$p < q$）。若 $q > p+1$，则中间的段 $s_{p+1}$ 也保留了 1 个气球，会插在二者之间，与「相邻」矛盾；故 $q = p + 1$，两段相邻。由极大性，相邻两段颜色必不同（同色则并成一段）。∎

**定理 1（最优值）**：最小总代价 $=\sum_{r}\left(\text{sum}_r - \text{max}_r\right)$，其中 $\text{sum}_r$、$\text{max}_r$ 为段 $r$ 内 `neededTime` 之和与最大值。

**证明**：任一方案的总代价 $=\sum_{i}\text{neededTime}[i] - \sum_{\text{保留}}\text{neededTime}[i]$。由引理 1，合法方案的保留集在每段至多 1 个；由引理 2，「每段保留 1 个」总可实现。于是合法方案与「每段选一个保留代表」一一对应，$\sum_{\text{保留}} = \sum_r \text{kept}_r \le \sum_r \text{max}_r$，且取 $\text{kept}_r = \text{max}_r$ 时取等。故最小代价 $=\sum_i \text{neededTime}[i] - \sum_r \text{max}_r = \sum_r (\text{sum}_r - \text{max}_r)$。∎

**定理 2（算法正确性）**：§3.3 的扫描算法返回 $\sum_r(\text{sum}_r - \text{max}_r)$。

**证明**：记 $t = \text{neededTime}$，对每个段归纳证明：扫描完段内下标 $l..i$ 后，（i）`kept` $= \max(t_l, \dots, t_i)$；（ii）该段对 `ans` 的累计贡献 $=\sum_{k=l}^{i} t_k - \max(t_l, \dots, t_i)$。段首 $i = l$ 时 `kept` $= t_l$、贡献为 $0$，成立。归纳步：新气球 $t_{i+1}$ 同色时贡献增加 $\min(\text{kept}, t_{i+1})$，且

$$\sum_{k=l}^{i+1} t_k - \max(\text{kept}, t_{i+1}) = \Big(\sum_{k=l}^{i} t_k - \text{kept}\Big) + \big(\text{kept} + t_{i+1} - \max(\text{kept}, t_{i+1})\big) = \text{旧贡献} + \min(\text{kept}, t_{i+1})$$

归纳保持；换色时 `kept` 重置、该段贡献封存，恰为 $\text{sum} - \text{max}$。对所有段求和即得结论。结合定理 1，算法返回最优值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单次扫描，每步至多一次比较、一次 $\min$/$\max$ 与一次累加。
- **空间复杂度**：$O(1)$。仅 `ans`、`kept` 两个标量（原地写法亦为 $O(1)$，但改写了入参数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(string colors, vector<int>& neededTime) {
        int n = colors.size();
        int ans = 0, kept = neededTime[0];
        for (int i = 1; i < n; ++i) {
            if (colors[i] == colors[i - 1]) {
                ans += min(neededTime[i], kept);
                kept = max(kept, neededTime[i]);
            } else {
                kept = neededTime[i];
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minCost(self, colors: str, neededTime: List[int]) -> int:
        ans, kept = 0, neededTime[0]
        for i in range(1, len(colors)):
            if colors[i] == colors[i - 1]:
                ans += min(neededTime[i], kept)
                kept = max(kept, neededTime[i])
            else:
                kept = neededTime[i]
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：循环不执行，答案 0；`kept = neededTime[0]` 依赖 $n \ge 1$（题目保证）。
2. **全串同色**（如 `"aaaa"`）：整段结算，答案 $=\text{sum} - \max$，恰好删 $n-1$ 个。
3. **全串无相邻同色**（如 `"abc"`）：一次对决都不触发，答案 0。
4. **忘做 `kept` 升级**（最常见 WA）：对每个相邻同色对累加 `min(原值)` 而不传递赢家，`"aaa", [2,1,5]` 会误得 2（正确 3），见 §4 第 4 点的反例推演。
5. **分段 `sum − max` 写法的末段补结**：若改用「换色时结算 `ans += sum - mx`」的写法，循环结束后必须补结最后一段，漏掉是经典 off-by-one。
6. **溢出**：`ans` 上界 $10^9$，`int` 可容但已过半；数据范围放宽时换 `long long`。
