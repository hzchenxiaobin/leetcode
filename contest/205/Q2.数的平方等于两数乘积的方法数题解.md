# LeetCode 数的平方等于两数乘积的方法数 题解

## 1. 题目概述

- **标题 / 题号**：数的平方等于两数乘积的方法数（#1577，medium）
- **链接**：https://leetcode.cn/problems/number-of-ways-where-square-of-number-is-equal-to-product-of-two-numbers/
- **来源**：LeetCode 第 205 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、数学、计数

**题意**：给定两个整数数组 `nums1` 与 `nums2`，统计两类三元组（按有序下标 $(i, j, k)$ 计数）的总数目：

- **类型 1**：$\text{nums1}[i]^2 = \text{nums2}[j] \times \text{nums2}[k]$，其中 $0 \le i < |\text{nums1}|$ 且 $0 \le j < k < |\text{nums2}|$；
- **类型 2**：$\text{nums2}[i]^2 = \text{nums1}[j] \times \text{nums1}[k]$，其中 $0 \le i < |\text{nums2}|$ 且 $0 \le j < k < |\text{nums1}|$。

**约束**：

- $1 \le |\text{nums1}|, |\text{nums2}| \le 1000$
- $1 \le \text{nums1}[i], \text{nums2}[i] \le 10^5$

> 💡 两种类型完全对称：交换两数组的角色，类型 1 就变成类型 2。只需实现一个「平方侧 $A$ × 乘积侧 $B$」的核心函数 `countType(A, B)`，两种类型各调用一次再求和。

## 2. 示例

**示例 1**

```text
输入：nums1 = [7,4], nums2 = [5,2,8,9]
输出：1
解释：类型 1：(1,1,2)，nums1[1]^2 = nums2[1] × nums2[2]，即 4² = 2 × 8。
```

**示例 2**

```text
输入：nums1 = [1,1], nums2 = [1,1,1]
输出：9
解释：1² = 1 × 1，所有三元组均合法。
类型 1 共 6 个：(0,0,1), (0,0,2), (0,1,2), (1,0,1), (1,0,2), (1,1,2)
类型 2 共 3 个：(0,0,1), (1,0,1), (2,0,1)
```

**示例 3**

```text
输入：nums1 = [7,7,8,3], nums2 = [1,2,9,7]
输出：2
解释：类型 1：(3,0,2)，3² = 1 × 9；类型 2：(3,0,1)，7² = 7 × 7。
```

## 3. 解题思路

### 3.1 暴力思路

以类型 1 为例：枚举 $i$（$n$ 种）与下标对 $(j, k)$（$\binom{m}{2}$ 种），逐个验证 $\text{nums2}[j] \times \text{nums2}[k] = \text{nums1}[i]^2$。单类型 $O(n \cdot m^2)$，两类合计约 $10^9$ 次运算——C++ 赌常数也许能过，Python 必超时，赛中不值得赌。

> ⚠️ **浪费在哪**：对每个 $i$ 都把 $\binom{m}{2}$ 个下标对重新扫一遍，而「哪些对的乘积等于 $t$」只取决于目标值 $t = \text{A}[i]^2$，与 $i$ 本身无关。数组里**相同数值**的元素目标完全相同，却被当成独立任务重复整套枚举。乘积侧的枚举是**循环不变量**，应当外提——一次算好，反复使用。

### 3.2 核心观察：乘积哈希——一次建表，多次查询

![核心观察：一次建表多次查询，乘积哈希消除重复枚举](images/wc205_q2_pair_product_concept.svg)

三元组 $(i, j, k)$ 中，$i$ 与 $(j, k)$ 只通过一个等式耦合：$\text{B}[j] \times \text{B}[k] = \text{A}[i]^2$。于是计数可以拆成两件独立的事：

- **乘积侧（建表，一次）**：枚举 $B$ 的全部 $\binom{m}{2}$ 个下标对 $(j, k)$（$j < k$），把每个乘积的出现次数存入哈希表：`cnt[B[j]·B[k]] += 1`。这张表与 $A$ 完全无关。
- **平方侧（查询，$n$ 次）**：对 $A$ 中每个元素 $x$（重复元素各自查询），把 `cnt[x²]` 累加进答案。

$$\text{countType}(A, B) = \sum_{x \in A} \text{cnt}[x^2]$$

> 💡 **重复值零特判**：$A$ 中相同的 $x$ 各查一次——它们对应不同下标 $i$，本来就该分别计数；$B$ 中不同下标对产生相同乘积时自动累加（如两对 $(7,8)$ 都得 56，则 `cnt[56] = 2`）。哈希表天然同时完成「按下标对计数」与「按值聚合」两件事。

### 3.3 算法流程

![算法流程：同一函数 countType(A,B) 跑两遍，两类结果相加](images/wc205_q2_algorithm_flow.svg)

1. **建表**：双重循环 $j < k$ 枚举 $B$ 的下标对，`cnt[B[j]·B[k]]++`，$O(m^2)$；
2. **查询**：遍历 $A$ 的每个元素 $x$，`res += cnt[x²]`，$O(n)$；
3. **两类各跑一遍**：类型 1 取 $(A, B) = (\text{nums1}, \text{nums2})$，类型 2 交换参数即可；
4. **求和返回**。两张表按需构建、用完即弃，峰值只占一份。

### 3.4 示例演算

![示例演算：nums1=[7,7,8,3], nums2=[1,2,9,7]，答案 2](images/wc205_q2_walkthrough.svg)

以示例 3 演算：

**类型 1**（$A = \text{nums1}$，$B = \text{nums2}$）：建表得 $\text{cnt2} = \{2{:}1,\ 9{:}1,\ 7{:}1,\ 18{:}1,\ 14{:}1,\ 63{:}1\}$；查询 $[49, 49, 64, 9]$，只有 $3^2 = 9$ 命中一次 $\Rightarrow res_1 = 1$，即三元组 $(3, 0, 2)$。

**类型 2**（$A = \text{nums2}$，$B = \text{nums1}$）：建表得 $\text{cnt1} = \{49{:}1,\ 56{:}2,\ 21{:}2,\ 24{:}1\}$——两对 $(7,8)$ 乘积同为 56、两对 $(7,3)$ 乘积同为 21，自动累加；查询 $[1, 4, 81, 49]$，只有 $7^2 = 49$ 命中一次 $\Rightarrow res_2 = 1$，即三元组 $(3, 0, 1)$。

$$\text{答案} = 1 + 1 = 2 \quad \checkmark$$

## 4. 算法细节

1. **对称复用**：`countType(sq, pr)` 只认「平方侧 / 乘积侧」两种角色，类型 2 就是交换实参再调用，杜绝复制两份代码引入的不一致。
2. **$j < k$ 双重循环**：保证每个无序下标对恰入表一次，`cnt` 的语义是「乘积为 $t$ 的**下标对**个数」，而非元素个数。
3. **查询侧按元素遍历**（含重复），天然正确；若改按唯一值遍历，必须乘回出现次数，反而易错。
4. **溢出**：$x^2$ 与 $\text{B}[j] \cdot \text{B}[k]$ 均可达 $10^{10}$，超出 32 位范围，C++ 中乘法前先转 `long long`。
5. **答案规模**：全 1 极限数据下答案 $\le 2 \times 1000 \times \binom{1000}{2} \approx 9.99 \times 10^8$，勉强落在 `int` 内但已近上界一半，累加器直接用 `long long` 最稳。
6. **内存**：峰值仅一张乘积表，至多 $\binom{1000}{2} \approx 5 \times 10^5$ 项；第一张建完查完即弃，再建第二张。
7. **进阶优化**：用「值频率表 + 整除判定」可把建表从 $O(m^2)$ 降到 $O(U_A \cdot U_B)$（$U$ 为唯一值个数，本题 $U \le 1000$），详见文末每日题解——数组更长时会从「可选优化」变成「必经之路」。

## 5. 正确性证明

**引理 1（按首坐标分解）**：记类型 1 的合法三元组全集为 $T_1$，则 $T_1 = \biguplus_{i} T_1(i)$，其中 $T_1(i) = \{(i, j, k) : 0 \le j < k < m,\ \text{B}[j] \cdot \text{B}[k] = \text{A}[i]^2\}$。

**证明**：按首坐标 $i$ 划分 $T_1$：任一三元组的首坐标唯一，故各组两两不交；每个 $T_1(i)$ 中的元素都满足类型 1 的定义（首坐标在范围内、$j < k$、乘积等式成立），故都属于 $T_1$，反之亦然。∎

**引理 2（建表正确性）**：建表完成后，对任意正整数 $t$，$\text{cnt}[t] = \#\{(j,k) : 0 \le j < k < m,\ \text{B}[j] \cdot \text{B}[k] = t\}$。

**证明**：双重循环恰好无重复地遍历所有满足 $j < k$ 的下标对（$(j,k)$ 与 $(k,j)$ 只取其一）；每个下标对当且仅当 $\text{B}[j] \cdot \text{B}[k] = t$ 时为 $\text{cnt}[t]$ 贡献 $+1$，故对每个 $t$ 的计数不重不漏。∎

**定理（算法正确性）**：$\text{countType}(A, B) = |T_1|$。

**证明**：算法返回 $\sum_{x \in A} \text{cnt}[x^2] = \sum_{i=0}^{n-1} \text{cnt}[\text{A}[i]^2]$。由引理 2，$\text{cnt}[\text{A}[i]^2] = |T_1(i)|$；由引理 1，$\sum_{i} |T_1(i)| = |T_1|$。∎

**推论**：两次调用（原参数序 + 交换参数序）相加即最终答案，两类内部按首坐标不交、两类按「谁的平方」不交，全局不重不漏。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m^2 + n^2)$。类型 1 建表 $\binom{m}{2}$ 次乘法与哈希插入、类型 2 建表 $\binom{n}{2}$ 次；查询共 $n + m$ 次 $O(1)$ 哈希查找。$n = m = 1000$ 时约 $2 \times 10^6$ 次操作，远低于暴力 $O(n \cdot m^2) \approx 10^9$。
- **空间复杂度**：$O(\max(n, m)^2)$。峰值只有一张乘积表（至多 $\binom{1000}{2} \approx 5 \times 10^5$ 项），逐类型构建、用完即弃。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numTriplets(vector<int>& nums1, vector<int>& nums2) {
        long long ans = countType(nums1, nums2) + countType(nums2, nums1);
        return (int)ans;
    }

private:
    long long countType(vector<int>& sq, vector<int>& pr) {
        int m = pr.size();
        unordered_map<long long, long long> cnt;
        for (int j = 0; j < m; ++j)
            for (int k = j + 1; k < m; ++k)
                cnt[(long long)pr[j] * pr[k]]++;
        long long res = 0;
        for (int x : sq) {
            auto it = cnt.find((long long)x * x);
            if (it != cnt.end()) res += it->second;
        }
        return res;
    }
};
```

### Python

```python
from collections import Counter
from itertools import combinations


class Solution:
    def numTriplets(self, nums1: List[int], nums2: List[int]) -> int:
        def count_type(sq: List[int], pr: List[int]) -> int:
            cnt = Counter(p * q for p, q in combinations(pr, 2))
            return sum(cnt[x * x] for x in sq)

        return count_type(nums1, nums2) + count_type(nums2, nums1)
```

## 8. 边界情况与易错点

1. **乘法溢出（最常见 WA）**：$x^2$ 与 $\text{B}[j] \cdot \text{B}[k]$ 均可达 $10^{10}$，超出 32 位范围；C++ 中 `int * int` 先按 32 位运算再扩展，必须显式转 `long long`，否则未定义行为。
2. **只算一种类型**：示例 2 将误得 6 而非 9。
3. **$j < k$ 误写成 $j \ne k$**：每个下标对计两次，示例 2 的类型 1 会误得 12；正确语义是「无序对，按有序 $(j,k)$ 恰计一次」。
4. **查询侧误用唯一值**：若先对 $A$ 去重，必须乘回出现频率，否则示例 2 的类型 1（两个 1）会少算一半；按元素遍历可完全规避。
5. **C++ 用 `operator[]` 查询**：会为未命中的键插入默认值，悄悄撑大哈希表；用 `find` 更干净。
6. **单元素数组**：$\binom{1}{2} = 0$，无下标对、答案为 0，流程自然成立无需特判。
7. **答案累加用 `int`**：极限约 $9.99 \times 10^8$，虽未溢出但离上界不远，统一 `long long` 免去心算。
