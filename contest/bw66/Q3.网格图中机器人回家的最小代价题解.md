# LeetCode 网格图中机器人回家的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：网格图中机器人回家的最小代价（#2087，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-homecoming-of-a-robot-in-a-grid/
- **来源**：LeetCode 第 66 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、数学

**题意**：$m \times n$ 网格，机器人初始在 $(startRow, startCol)$，家在 $(homeRow, homeCol)$。每步可上下左右移动（不能出界），移动的代价按**进入的格子**计：上下移动进入第 $r$ 行付 $rowCosts[r]$，左右移动进入第 $c$ 列付 $colCosts[c]$。求回家的最小总代价。

**约束**：

- $1 \le m, n \le 10^5$
- $0 \le rowCosts[r], colCosts[c] \le 10^4$
- 起点与终点都在网格内

> ⚠️ 坑点：题面给的是"机器人**回家**"，加上示意图里机器人从右上往左下走，很容易让人以为方向受限（只能上/左）；实际机器人**四个方向都能走**。真正让问题变简单的是**代价非负**这一条件——绕路永远不划算，最优路径就是"直走"。

## 2. 示例

**示例 1**

```text
输入：startPos = [1,0], homePos = [2,3], rowCosts = [5,4,3], colCosts = [8,2,6,7]
输出：18
解释：下移到 (2,0) 付 rowCosts[2]=3；右移 (2,1)→(2,2)→(2,3) 付 2+6+7。
总代价 3 + 2 + 6 + 7 = 18。
```

**示例 2（起点即家）**

```text
输入：startPos = [0,0], homePos = [0,0], rowCosts = [5], colCosts = [26]
输出：0
解释：机器人已在家，一步都不用走。
```

**示例 3（家在左上方，补充）**

```text
输入：startPos = [2,3], homePos = [0,0], rowCosts = [1,1,1], colCosts = [1,2,3,4]
输出：8
解释：向上 2 步进入第 1、0 行，付 rowCosts[1]+rowCosts[0] = 1+1 = 2；
向左 3 步进入第 2、1、0 列，付 colCosts[2]+colCosts[1]+colCosts[0] = 3+2+1 = 6。
总代价 2 + 6 = 8。起点的行、列费用（rowCosts[2]、colCosts[3]）从不被支付。
```

## 3. 解题思路

### 3.1 暴力思路

把网格建成图（每个格子到四邻的边权 = 进入邻居的行列代价），跑 Dijkstra：$O(mn \log(mn))$。$m, n \le 10^5$ 时 $mn$ 达 $10^{10}$，连图都建不起来。普通 BFS/DP 也是 $O(mn)$，同样爆炸——必须利用**代价只与"进入哪一行/列"有关**的结构。

### 3.2 核心观察：绕路必不亏是假象——是"绕路必不赚"！

![直走路径与代价归属](images/bw66_q3_direct_path.svg)

代价全部**非负**。任何一条从起点到终点的路径，其竖直方向位移的**绝对值**至少是 $|r_1 - r_0|$、水平至少 $|c_1 - c_0|$。多走的每一步（上下往返、左右折返）对净位移无贡献、纯付非负代价，故可全部删去，剩下的路径恰为"竖直走 $|r_1-r_0|$ 步 + 水平走 $|c_1-c_0|$ 步"的**单调直走路径**（先竖后横或交错都行，顺序不影响总代价，见引理 2）。

于是答案就是两个**区间和**：

$$ans = \sum_{r=\min(r_0,r_1)}^{\max(r_0,r_1)} rowCosts[r] + \sum_{c=\min(c_0,c_1)}^{\max(c_0,c_1)} colCosts[c] - rowCosts[r_0] - colCosts[c_0]$$

减去的两项是**起点的行列代价**：机器人从起点出发的第一步，付的是"进入新行/列"的费用，从不付"待在起点"的钱。

### 3.3 为什么不用 DP

![为什么不用 DP：多余移动只增不减](images/bw66_q3_no_dp_needed.svg)

一眼看去这是网格 DP（最短路）题，但代价结构有两个决定性性质：

1. **行列可分离**：每步代价只属于行费用或列费用之一，与具体列/行无关——上下移动不付列费、左右移动不付行费；
2. **非负**：任何"多余"的往返只加钱不挪窝。

二者合起来：路径的总代价 = (经过的行多重集的费用和) + (经过的列多重集的费用和)。直走路径每个中间行/列恰好经过一次，任何别的路径经过的行/列集合是它的**超集**（还可能重复）。DP 能做的只是确认这一点，实际一行区间求和就够。

### 3.4 示例演算

示例 1：$r_0=1, r_1=2, c_0=0, c_1=3$。行区间 $[1,2]$ 和 $= 4+3 = 7$；列区间 $[0,3]$ 和 $= 8+2+6+7 = 23$；扣除起点 $rowCosts[1] + colCosts[0] = 4 + 8 = 12$。答案 $7 + 23 - 12 = 18$ ✓。

## 4. 算法细节

1. **闭区间求和再扣起点**：直接累加 $\min \sim \max$ 的闭区间，最后减 $rowCosts[r_0]$ 与 $colCosts[c_0]$，比在循环里跳过起点更不易错（起点本身在区间内，因为 $\min \le r_0 \le \max$）。
2. **方向无关**：$r_1 < r_0$ 时区间自动反转为 $[r_1, r_0]$，无需分支。
3. **溢出**：最坏 $10^5$ 行 × $10^4$ 代价 = $10^9$，再加列的 $10^9$，共 $2 \times 10^9$ **超出 `int` 上界**（$2147483647$）！C++ 必须用 `long long` 累加，返回前转 `int`（答案上界 $2 \times 10^9 - 2 \times 10^4 < 2^{31}$？不对——$1999980000 < 2147483647$ 恰好安全，但累加过程中的和已达 $2 \times 10^9$，中间量必须 64 位）。Python 无此虞。
4. **同点特判可省**：$r_0=r_1, c_0=c_1$ 时两个区间和减去自身恰为 0，公式天然给出 0，无需特判（但显式特判更直观）。
5. **前缀和可省**：一次区间求和直接线性扫即可 $O(m+n)$；若查询多次才需要前缀和。

## 5. 正确性证明

**引理 1（位移下界）**：任何从 $(r_0, c_0)$ 到 $(r_1, c_1)$ 的格点路径，竖直步数 $\ge |r_1 - r_0|$，水平步数 $\ge |c_1 - c_0|$。

**证明**：竖直净位移是各竖直步的带符号和，每步贡献 $\pm 1$，故步数不少于净位移绝对值；水平同理。∎

**引理 2（直走路径的代价公式）**：一条恰好含 $|r_1-r_0|$ 个竖直步与 $|c_1-c_0|$ 个水平步的单调路径（每步都朝终点方向）的总代价为 $\sum_{r \in R} rowCosts[r] + \sum_{c \in C} colCosts[c] - rowCosts[r_0] - colCosts[c_0]$，其中 $R$、$C$ 是起点终点间的行/列闭区间，且**与步序无关**。

**证明**：单调路径依次进入行 $r_0 \pm 1, r_0 \pm 2, \dots, r_1$ 各一次（竖直步）与列 $c_0 \pm 1, \dots, c_1$ 各一次（水平步）。第一步付的是离开起点后进入的新行列费用；起点行列从未被"进入"，其余每个 $R \setminus \{r_0\}$ 的行恰被进入一次、$C \setminus \{c_0\}$ 的列恰被进入一次。总代价即区间和扣除起点两项。竖直步与水平步的费用互不纠缠（各付各的），故与两类步的排列顺序无关。∎

**定理**：最小总代价由引理 2 的公式给出。

**证明**：任取一条路径 $P$，由引理 1 其竖直步、水平步数分别不小于单调需求。把 $P$ 的费用按步分解：每个竖直步付某行费用、每个水平步付某列费用，全部非负。$P$ 的竖直步所进入的行的多重集包含 $R \setminus \{r_0\}$ 中每行至少一次（净位移需要跨越区间内每一行），水平同理包含 $C \setminus \{c_0\}$。于是 $cost(P) \ge \sum_{R} rowCosts + \sum_{C} colCosts - rowCosts[r_0] - colCosts[c_0]$，且单调路径恰好取到该下界（引理 2）。故公式即最小值。∎

## 6. 复杂度分析

- **时间**：$O(m + n)$，两个区间各扫一遍。
- **空间**：$O(1)$ 额外空间（不建网格、不建图）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(vector<int>& startPos, vector<int>& homePos, vector<int>& rowCosts, vector<int>& colCosts) {
        int r0 = startPos[0], c0 = startPos[1];
        int r1 = homePos[0], c1 = homePos[1];
        long long ans = -rowCosts[r0] - colCosts[c0];      // 先累加闭区间和，再扣除起点
        for (int r = min(r0, r1); r <= max(r0, r1); ++r) ans += rowCosts[r];
        for (int c = min(c0, c1); c <= max(c0, c1); ++c) ans += colCosts[c];
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minCost(self, startPos: list[int], homePos: list[int], rowCosts: list[int], colCosts: list[int]) -> int:
        r0, c0 = startPos
        r1, c1 = homePos
        ans = -rowCosts[r0] - colCosts[c0]        # 闭区间和再扣起点
        ans += sum(rowCosts[min(r0, r1):max(r0, r1) + 1])
        ans += sum(colCosts[min(c0, c1):max(c0, c1) + 1])
        return ans
```

> 💡 两份代码均通过官方 2 组示例（`18` / `0`）、$10^5 \times 10^5$ 全满代价的极值冒烟（答案 $1999980000$），以及 C++ 3000 组、Python 1200 组随机小网格与 **Dijkstra**（按"进入格子付行列费"建图）的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出（最大坑）**：中间累加和可达 $2 \times 10^9$，超 `int`；C++ 用 `long long` 累加。返回值虽恰好 $< 2^{31}$，但过程中必须 64 位。
2. **别扣错起点**：扣除的是 $rowCosts[r_0]$ 与 $colCosts[c_0]$（各一次），不是"出发方向对应的那一个"——机器人可能先竖走也可能先横走，但无论先走哪步，起点行列都没被付费进入，两项都该扣。
3. **起点 = 终点**：公式给 0，天然正确；写显式特判 `if r0==r1 and c0==c1: return 0` 也行。
4. **方向反转**：家在左上时区间端点自动换序（`min/max`），无需 if-else。
5. **误当 DP 做**：$O(mn)$ 的 DP 在 $m=n=10^5$ 时爆内存爆时间；本题的"贪心/数学"标签正提示闭式解。
6. **费用为 0**：某行/列费用 0 时经过它白嫖，公式自动包含，无需处理。
