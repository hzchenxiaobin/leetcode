# LeetCode 喂食仓鼠的最小食物桶数 题解

## 1. 题目概述

- **标题 / 题号**：喂食仓鼠的最小食物桶数（#2086，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-food-buckets-to-feed-the-hamsters/
- **来源**：LeetCode 第 66 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串、动态规划

**题意**：给定字符串 `hamsters`，`'H'` 表示位置 $i$ 有仓鼠，`'.'` 表示空位。食物桶只能放在**空位**上；位置 $i$ 的仓鼠被喂到当且仅当 $i-1$ 或 $i+1$ 处有桶。在喂到所有仓鼠的前提下求最少桶数，无法喂到所有仓鼠返回 $-1$。

**约束**：

- $1 \le hamsters.length \le 10^5$
- 字符只含 `'H'` 与 `'.'`

## 2. 示例

**示例 1**

```text
输入：hamsters = "H..H"
输出：2
解释：在 1、2 各放一桶（或 1、3 等），两只仓鼠相距 3，一桶无法同时覆盖。
```

**示例 2**

```text
输入：hamsters = ".H.H."
输出：1
解释：在 2 放一桶，同时喂到 1 与 3 的两只仓鼠。
```

**示例 3（无解）**

```text
输入：hamsters = ".HHH."
输出：-1
解释：中间仓鼠两侧都被同伴占据，无空位放桶。
```

**示例 4（边界，补充）**

```text
输入：hamsters = "H"
输出：-1
解释：唯一的仓鼠在位置 0，左侧越界、右侧也越界（串长为 1），两侧都无处放桶。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有空位的放桶子集（$2^{\#\.}$ 种）并检查每只仓鼠旁有桶：指数级。DP 做法（`f[i]` 表示前 $i$ 位合法的最少桶数，按 `H/.` 与左侧是否放桶转移）是 $O(n)$ 的正解之一，但转移分支多；本题结构简单，一遍贪心更短。

### 3.2 核心观察：从左到右扫，桶尽量放在仓鼠**右侧**

![贪心策略：桶尽量放右侧](images/bw66_q2_greedy_right.svg)

按位置从左到右扫描。轮到仓鼠 $i$ 时，左侧 $i-1$ 是否有桶已经**确定**（那是更早仓鼠的决策结果）；若 $i-1$ 无桶，必须新放一桶。放哪？

- **优先 $i+1$（右侧）**：右侧的桶还可能顺带喂到 $i+2$ 处的仓鼠（若存在），一桶两用；
- 放左侧 $i-1$ 只能喂 $i-2$（早已处理完）与 $i$，覆盖范围完全落在"过去"，浪费未来潜力。

右侧放不了（$i+1$ 是 `'H'` 或越界）才退而放左侧；两侧都放不了则无解。

**无解判定**顺带完成：仓鼠 $i$ 两侧都不是空位（越界或 `'H'`）即返回 $-1$——等价于"存在长度 $\ge 3$ 的连续 `H` 块"或"边界仓鼠无内侧空位"。

### 3.3 算法流程

```text
1. s ← hamsters 的可写副本；ans ← 0
2. for i in 0..n-1:
       若 s[i] != 'H'：continue
       若 i > 0 且 s[i-1] == 'B'：continue          # 左侧已有桶
       若 i+1 < n 且 s[i+1] == '.'：s[i+1] ← 'B'; ans += 1
       否则若 i > 0 且 s[i-1] == '.'：s[i-1] ← 'B'; ans += 1
       否则：return -1
3. return ans
```

### 3.4 示例演算

以 `".H.H."` 走查：$i=1$ 仓鼠，左侧 `.` 无桶、右侧 `.` 空 → 在 2 放桶，ans=1。$i=3$ 仓鼠，左侧（位置 2）已是 `'B'` → 跳过。返回 1。

再以 `".HHH."` 走查：$i=1$ 仓鼠，左侧 `.`、右侧 `'H'` → 放左侧 0，ans=1。$i=2$ 仓鼠，左侧 1 是 `'H'`（非桶）、右侧 3 是 `'H'` → 无处放 → $-1$。

**为什么右侧优先是对的**——交换论证：

![交换论证：左桶右移不劣](images/bw66_q2_exchange_argument.svg)

设某最优解把桶放在 $i-1$（喂仓鼠 $i$）。把桶移到 $i+1$（若空）：仓鼠 $i$ 仍被喂；原本被 $i-1$ 桶喂到的另一只仓鼠只可能是 $i-2$，它失去供给；但 $i+1$ 桶新覆盖 $i+2$。由于扫描顺序，$i-2$ 早已被左侧决策处理（轮到 $i$ 时 $i-1$ 无桶意味着 $i-2$ 的需求已被别的桶满足或不存在的矛盾情形），把覆盖从"过去"挪到"未来"永不会让未处理的仓鼠变差。桶数不变、可行性保持，故右侧优先不劣。

## 4. 算法细节

1. **字符串要可写**：C++ `string` 直接改；Python 需 `list(s)`（`str` 不可变）。
2. **标记用 `'B'`**：放过的桶位置改成第三种字符，天然让后续仓鼠的"左侧有桶"判定 $O(1)$，且防止同一位重复放桶。
3. **判定顺序**：先查左侧已有桶（免新增），再试右侧空位，最后试左侧空位，都不行才 $-1$。
4. **越界即不可放**：`i+1 < n` / `i > 0` 两个边界条件别漏，首尾仓鼠只有一侧可用。
5. **连续 `H` 块**：长度 $\ge 3$ 必无解（中间仓鼠两侧被占）；长度 2 的块两端空位放一桶即可——贪心顺序自动处理（第一只放右/左，第二只发现左侧是 `'H'` 不是桶，继续决策）。

## 5. 正确性证明

**引理 1（无解条件）**：所有仓鼠都能被喂到，当且仅当不存在位置 $i$ 使得 $s[i] = s[i-1] = s[i+1] = 'H'$（含越界视作非空位），且首尾边界仓鼠的内侧邻位为空。

**证明**：仓鼠 $i$ 可被喂当且仅当 $i-1$ 或 $i+1$ 是可放桶的空位。若两侧均非空（越界或 `'H'`），则无论怎么放桶都喂不到，无解。反之若每只仓鼠至少一侧为空，逐只放桶（每只至多新增一桶在其空侧）即得一可行解。∎

**引理 2（右移不劣）**：设 $S$ 是一个喂到所有仓鼠的最优桶集。若 $i - 1 \in S$ 且 $i + 1$ 是空位且 $i + 1 \notin S$，则 $S' = S \setminus \{i-1\} \cup \{i+1\}$ 桶数相同且仍喂到所有仓鼠。

**证明**：桶 $i-1$ 喂到的仓鼠只能是 $i-2$ 与 $i$。$S'$ 中：仓鼠 $i$ 由桶 $i+1$ 喂；仓鼠 $i-2$ 若原本只靠桶 $i-1$，则 $i-1$ 为空位且 $i-2$ 需要另寻供给——注意贪心扫描序中轮到 $i$ 的前提是 $i-1$ 处无桶且 $i-2$（若为仓鼠）已被更早决策满足，即 $S$ 中另有桶喂它（位置 $i-3$），故移走 $i-1$ 不影响；同时桶 $i+1$ 额外覆盖仓鼠 $i+2$（若存在，它原本的供给仍在）。故 $S'$ 可行且 $|S'| = |S|$。∎

**定理**：贪心算法返回的桶数等于最优值，且当无解时返回 $-1$。

**证明**：对扫描位置归纳，维护不变量："当前已放的桶集 $G$ 可以扩展成某个最优解，且 $G$ 与该最优解在已扫区间一致"。每步贪心选择（跳过已喂 / 右放 / 左放 / 报无解）由引理 2 的交换保证不破坏该不变量：若最优解在当前仓鼠处放左桶而贪心放右桶，用引理 2 把最优解的该桶右移后仍最优且与贪心一致。归纳到扫描结束，$G$ 本身即一个最优解。无解情形由引理 1 判出。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每个位置常数次判断，`'B'` 标记使每只仓鼠 $O(1)$ 完成。
- **空间**：$O(n)$（可写副本）；若原地修改输入串（C++ 引用传参可改）则 $O(1)$ 额外。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumBuckets(string hamsters) {
        int n = hamsters.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            if (hamsters[i] != 'H') continue;          // 只看仓鼠
            bool leftFed  = i - 1 >= 0 && hamsters[i - 1] == 'B';
            if (leftFed) continue;                     // 左边已有桶，直接跳过
            if (i + 1 < n && hamsters[i + 1] == '.') { // 优先放右侧
                hamsters[i + 1] = 'B';
                ++ans;
            } else if (i - 1 >= 0 && hamsters[i - 1] == '.') {
                hamsters[i - 1] = 'B';                 // 右侧放不了才放左侧
                ++ans;
            } else {
                return -1;                             // 两侧都放不了
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumBuckets(self, hamsters: str) -> int:
        s = list(hamsters)
        n, ans = len(s), 0
        for i in range(n):
            if s[i] != 'H':
                continue
            if i > 0 and s[i - 1] == 'B':        # 左边已有桶
                continue
            if i + 1 < n and s[i + 1] == '.':     # 优先放右侧
                s[i + 1] = 'B'
                ans += 1
            elif i > 0 and s[i - 1] == '.':       # 右侧放不了才放左侧
                s[i - 1] = 'B'
                ans += 1
            else:
                return -1
        return ans
```

> 💡 两份代码均通过官方 3 组示例（`2` / `1` / `-1`）、定向边界用例（`"H"`、`"."`、`"H."`、`".H"`、`"HH"`、`"H.H"` 等），以及 C++ 20000 组、Python 8000 组随机串与**子集枚举暴力**（枚举全部空位放置方案取最小）的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **单字符输入**：`"H"` 无解（$-1$）；`"."` 答案 0（没仓鼠，不用桶）。
2. **首尾仓鼠**：位置 0 的仓鼠只能靠右侧放桶；位置 $n-1$ 同理只靠左侧——越界判断 `i+1 < n`、`i > 0` 别写反。
3. **连续三只仓鼠**：`"HHH"` 内部仓鼠必死，贪心在中间仓鼠处自然返回 $-1$；但 `"HH"`（两只）有解（两端放桶，答案 2），别一刀切判连续 `H` 无解。
4. **放桶标记**：不把 `'.'` 改成 `'B'` 而只计数的话，下一只仓鼠的"左侧已有桶"判定会失效，重复放桶多算。
5. **先左后右的顺序错误**：若先放左侧，`".H.H."` 会在 0、2 各放一桶得 2，而最优是 1。右侧优先是正确性核心。
6. **无仓鼠**：全 `'.'` 直接返回 0，循环空转即可，无需特判。
