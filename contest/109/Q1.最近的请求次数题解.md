# LeetCode 最近的请求次数 题解

## 1. 题目概述

- **标题 / 题号**：最近的请求次数（#933，easy）
- **链接**：https://leetcode.cn/problems/number-of-recent-calls/
- **来源**：LeetCode 第 109 场周赛 Q1
- **难度**：简单
- **标签**：设计、队列、数据流

**题意**：实现计数器类 `RecentCounter`：

- `RecentCounter()`：初始化，请求数为 0；
- `int ping(int t)`：在时刻 $t$（毫秒）新增一个请求，返回在闭区间 $[t - 3000, t]$ 内发生过的请求数（包含本次）。

保证每次 `ping` 的 $t$ **严格递增**。

**约束**：

- $1 \le t \le 10^9$
- 每次 `ping` 的 $t$ 严格递增
- 至多调用 `ping` $10^4$ 次

> 💡 单调递增的输入是本题的核心红利：**过期请求永远不会「复活」**，因此可以用一个不断从队头弹出的队列，而不需要任何查找结构。

## 2. 示例

**示例 1**

```text
输入：["RecentCounter","ping","ping","ping","ping"]
     [[],[1],[100],[3001],[3002]]
输出：[null,1,2,3,3]
解释：ping(1)    窗口 [-2999,1]     → 1
     ping(100)  窗口 [-2900,100]   → 2
     ping(3001) 窗口 [1,3001]      → 3
     ping(3002) 窗口 [2,3002]      → 3（时刻 1 掉出窗口）
```

**示例 2（补充）**

```text
输入：["RecentCounter","ping","ping"]，[[],[1],[3001]]
输出：[null,1,2]
解释：3001 − 3000 = 1，时刻 1 的请求恰好落在下界上，仍被计入（闭区间）。
```

## 3. 解题思路

### 3.1 暴力思路

每次 `ping` 时把**全部历史时刻**存下来，再线性扫描统计落在 $[t-3000, t]$ 内的个数：$O(k)$ 每次，总 $O(k^2)$，$k = 10^4$ 时 $10^8$ —— 勉强能过，但完全没有利用「$t$ 严格递增」这一条件。

二分查找（在有序历史里 `lower_bound(t-3000)`）可以做到 $O(\log k)$，也不错；但每次仍然要保留全部历史，且多了一个 $\log$ 因子。

### 3.2 核心观察：窗口只向右移动，过期请求一次性出队

![滑动窗口：只保留最近 3000 毫秒内的请求](images/wc109_q1_window_concept.svg)

维护一个队列 `q`，按时刻升序存放**仍在窗口内的请求**。每次 `ping(t)`：

1. 把 $t$ 入队（它是当前最新的时刻）；
2. 反复检查队头：若 `q.front() < t - 3000`，说明它已过期，弹出；
3. 此时队列里剩下的恰好全部落在 $[t-3000, t]$ 内，返回队列长度。

**为什么可以「一次弹出就永远不再管」**：因为 $t$ 严格递增，下一轮的 $t' > t$，窗口下界 $t' - 3000 > t - 3000$ 只会更靠右；被弹出的元素永远不可能再回到窗口内。这就是「单调输入 + 滑动窗口」的经典搭配。

> 💡 边界是**闭区间**：下界 $t - 3000$ 本身要算，所以判据是 `q.front() < t - 3000`（严格小于）而不是 `<=`。

### 3.3 算法流程

```text
RecentCounter():
    q = 空队列

ping(t):
    q.push_back(t)
    while q 非空 且 q.front() < t - 3000:
        q.pop_front()
    return q.size()
```

### 3.4 示例演算

![示例演算：四次 ping](images/wc109_q1_walkthrough.svg)

| 调用 | 窗口 | 窗口内请求 | 返回 |
|------|------|-----------|------|
| `ping(1)` | $[-2999, 1]$ | `[1]` | 1 |
| `ping(100)` | $[-2900, 100]$ | `[1, 100]` | 2 |
| `ping(3001)` | $[1, 3001]$ | `[1, 100, 3001]` | 3 |
| `ping(3002)` | $[2, 3002]$ | `[100, 3001, 3002]` | 3 |

第 4 次调用时队头 `1 < 3002 - 3000 = 2`，被弹出，队列剩 3 个元素，故返回 3。

## 4. 算法细节

1. **用 `deque` 而不是 `vector`**：C++ 的 `std::queue` 底层默认 `deque`，`push/pop` 都是 $O(1)$；Python 用 `collections.deque`，`popleft()` 是 $O(1)$（`list.pop(0)` 是 $O(n)$，不要用）。
2. **也可以用一个 `vector` + 头指针**：入队只 `push_back`、出队只移动 `head` 下标，避免真正的删除，代码更简单。注意这样「队列长度」要算 `size - head`，而不是 `size`。
3. **闭区间的边界**：`q.front() < t - 3000` 才弹出；若写成 `<=`，恰好等于下界的请求会被错误丢弃（示例 2 会返回 1 而不是 2）。
4. **`t` 最大 $10^9$**：`int` 足够（$10^9 < 2^{31}$），但 `t - 3000` 可能为负，用 `int` / `long` 都行，不会溢出。
5. **调用次数 $10^4$**：每个请求最多入队一次、出队一次，总操作数 $O(k)$，性能极佳。
6. **类成员初始化**：构造函数里把队列清空即可，不需要额外状态。

## 5. 正确性证明

固定某次调用 `ping(t)`，记调用前队列为 $Q$（按时刻升序）。

**引理 1（不变式）**：每次 `ping` 返回后，队列中恰好存放「此前所有满足 $\text{time} \ge t - 3000$ 的请求时刻」，且按升序排列。

**证明**：对调用次数归纳。

*基础*：初始队列为空，任何时刻都无请求，空集满足条件。

*归纳*：设第 $k$ 次调用前队列 $Q$ 恰为「此前满足 $\text{time} \ge t_{k-1} - 3000$ 的请求」，升序。执行 `ping(t_k)`：

1. 入队 $t_k$，此时队列是 $Q \cup \{t_k\}$，仍升序（因 $t_k > t_{k-1} \ge$ 队尾）。
2. 循环弹出所有 `< t_k - 3000` 的队头。由于队列升序，这些元素恰好是队首的一段连续前缀；弹出后剩下的正是「此前满足 $\text{time} \ge t_k - 3000$ 的请求」加上 $t_k$。
3. 归纳成立。∎

**引理 2（弹出不误伤）**：循环结束时，队列中任意元素都满足 $\text{time} \ge t - 3000$；且不存在「本应保留却被弹出」的元素。

**证明**：弹出条件严格为 `time < t - 3000`，被弹出的元素都**不在**闭区间 $[t-3000, t]$ 内。反之，任何 $\text{time} \ge t - 3000$ 的元素都不满足弹出条件，而队列升序意味着它位于所有被弹出元素之后，故不会被弹出。∎

**引理 3（不漏计）**：任何满足 $t - 3000 \le \text{time} \le t$ 的请求都在队列中。

**证明**：由引理 1 的不变式，上一次调用后队列包含所有 $\text{time} \ge t_{k-1} - 3000$ 的请求。本次需要统计的请求满足 $\text{time} \ge t_k - 3000 > t_{k-1} - 3000$，故它若存在于历史中，就一定在上次队列里；若它就是本次的 $t_k$，则刚刚入队。两种情况都在队列中。∎

**定理**：`ping(t)` 返回的值等于区间 $[t-3000, t]$ 内的请求个数。

**证明**：由引理 1，队列元素全部在窗口内（升序且下界已过滤），且上界 $t$ 自动满足（$t$ 严格递增，历史时刻都 $\le t$）。由引理 2、3，队列元素与窗口内的历史请求一一对应，故队列长度即所求个数。∎

## 6. 复杂度分析

- **时间**：单次 `ping` 为 $O(1)$ **均摊**（可能一次弹出多个，但每个元素一生只被弹出一次）；$k$ 次调用总计 $O(k)$。
- **空间**：$O(k)$，队列最多同时保留窗口内的请求；$k \le 10^4$。
- **对比**：线性扫描 $O(k^2)$、二分 $O(k \log k)$，均摊队列最优且常数最小。

## 7. 参考代码

### C++

```cpp
class RecentCounter {
    vector<int> q;    // 只保留窗口内的请求时刻，天然有序（t 严格递增）
    size_t head = 0;  // 队头下标，避免频繁 erase
public:
    RecentCounter() {}

    int ping(int t) {
        q.push_back(t);
        // 把早于 t-3000 的请求全部弹出窗口
        while (head < q.size() && q[head] < t - 3000) head++;
        return (int)(q.size() - head);
    }
};
```

### Python

```python
from collections import deque


class RecentCounter:
    def __init__(self):
        self.q = deque()

    def ping(self, t: int) -> int:
        self.q.append(t)
        while self.q[0] < t - 3000:
            self.q.popleft()
        return len(self.q)
```

## 8. 边界情况与易错点

1. **闭区间写成开区间**：判据用 `<` 而不是 `<=`；`ping(1)` 后 `ping(3001)` 应返回 2（时刻 1 正好在边界上）。
2. **`list.pop(0)` 的 $O(n)$ 陷阱**：Python 用 `list` 模拟队列时 `pop(0)` 是线性开销，必须用 `deque`；C++ 用 `vector::erase(begin())` 同理。
3. **队列长度算错（头指针写法）**：用 `head` 时返回 `size - head`，不要把已过期的也数进去。
4. **忘记把 $t$ 先入队**：本次请求一定在窗口内（区间右端就是 $t$），必须先入队再统计。
5. **`t` 单调性的依赖**：本题依赖「严格递增」。若输入乱序，滑动窗口失效，需要改用有序容器 + 二分。
6. **多次调用同一 $t$**：题目保证严格递增，不会出现；若出现，队列仍能正确处理（两个相同的 $t$ 都在窗口内）。
7. **$t \le 3000$**：窗口下界为负，所有历史请求都在窗口内，`while` 不会误弹。
