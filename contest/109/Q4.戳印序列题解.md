# LeetCode 戳印序列 题解

## 1. 题目概述

- **标题 / 题号**：戳印序列（#936，hard）
- **链接**：https://leetcode.cn/problems/stamping-the-sequence/
- **来源**：LeetCode 第 109 场周赛 Q4
- **难度**：困难
- **标签**：栈、贪心、队列、字符串

**题意**：初始序列是 `target.length` 个 `'?'`。你有一个长度 $m$ 的小写字母印章 `stamp`，每回合可以把印章盖在序列的某个位置上（必须完全落在边界内），把该区间内的字符**全部替换**为印章对应位置的字符。问能否最终得到 `target`；若能，返回每回合印章**最左端下标**组成的数组（顺序任意），且回合数不得超过 $10 \cdot \text{target.length}$。若不能，返回空数组。

**约束**：

- $1 \le m \le n \le 1000$（$m = |\text{stamp}|$，$n = |\text{target}|$）
- 只含小写字母

> 💡 正向模拟极难：先盖的印章会被后盖的覆盖，如何安排顺序几乎无从下手。把过程**倒过来看**，问题立刻变得清晰。

## 2. 示例

**示例 1**

```text
输入：stamp = "abc", target = "ababc"
输出：[0,2]（[1,0,2] 等其他合法序列也被接受）
解释：先在位置 0 盖 "abc" 得 "abc??"，再在位置 2 盖 "abc" 得 "ababc"。
```

**示例 2**

```text
输入：stamp = "abca", target = "aabcaca"
输出：[3,0,1]
解释：在 3 盖得 "???abca"，在 0 盖得 "abca???"，最后在 1 盖得 "aabcaca"。
```

**示例 3（补充）**

```text
输入：stamp = "a", target = "aaaa"
输出：[3,2,1,0]（也接受 [0,1,2,3] 等任意顺序）
解释：每个位置单独盖一次，共 4 次（不超过 10 × 4）。
```

## 3. 解题思路

### 3.1 暴力思路

正向 BFS：状态是当前字符串（含 `'?'`），每步枚举所有 $O(n)$ 个盖印位置。状态数是 $O(n^m)$ 级别，$n = 1000$ 时完全爆炸——即使 $n = 10$ 也只能处理很短的目标串。

所以只能另找结构：本题的关键不是搜索策略，而是**换一个方向看问题**。

### 3.2 核心观察：逆向「擦除」，从 target 擦回全 `'?'`

![逆序思考：从 target 倒着「擦」回全 ?](images/wc109_q4_reverse_concept.svg)

把盖章过程倒放：最终串是 `target`，每「倒放」一步就**擦掉**某次盖章的痕迹——把某个位置上仍与 `stamp` 对齐的一段字符变回 `'?'`。

一次逆向擦除合法的条件（位置 $i$）：

- 对每个 $k \in [0, m)$：`target[i+k]` 要么**等于** `stamp[k]`，要么**已经是** `'?'`（说明它被「更晚盖的印章」覆盖过，倒放时先被擦掉）；
- 且至少要有一个非 `'?'` 的字符被擦掉（否则空转，会无限循环）。

反复擦到全 `'?'`：把擦除顺序**反转**就是盖章顺序。如果最后还残留非 `'?'` 字符，说明不可能印出，返回空数组。

**为什么这个贪心是安全的**：擦除只会把字符变成 `'?'`，而 `'?'` 是「万能匹配」——它让更多位置变得可擦。因此**先擦除一个当前可擦的位置，绝不会让原本可解的实例变得不可解**（见引理 2）。这就是贪心可行、且顺序无关的根源。

### 3.3 算法流程

![算法流程：计数 + 队列](images/wc109_q4_algorithm_flow.svg)

对每个起点 $i \in [0, n-m]$ 维护 `cnt[i]`＝「该起点上已经与 stamp 对上的字符数」（`'?'` 视为对上）。当 `cnt[i]` 达到 $m$ 时，位置 $i$ 就可擦。

```text
1. 初始化：cnt[i] = #{k : target[i+k] == stamp[k]}；cnt[i] == m 的 i 入队
2. while 队列非空：
       i = 出队
       记录 i；把 [i, i+m) 内尚未擦掉的字符全部标记为 '?'（记 done）
       对这些新变成 '?' 的位置 p：
           枚举所有覆盖 p 的起点 j ∈ [max(0, p-m+1), min(p, n-m)]：
               若 target[p] != stamp[p-j]（即原本不匹配，现在被 '?' 救活）：
                   cnt[j] += 1；若 cnt[j] == m 则 j 入队
3. 若仍有位置未擦掉 → 返回 []；否则把记录的答案反转后返回
```

**为什么用队列而不是反复全量扫描**：全量扫描每轮 $O(nm)$、最坏 $O(n)$ 轮；而队列 + 计数把每个位置「被擦」的事件均摊到 $O(m)$ 个覆盖它的起点上，总复杂度 $O(nm)$（详见复杂度分析）。

**注意一个易错点**：只有 `target[p] != stamp[p-j]` 时才给 `cnt[j]` 加 1。因为 `cnt` 初始化时已经数过「本来就匹配」的位置，若无条件 +1 会重复计数，让不该擦的位置被误判为可擦。

### 3.4 示例演算

![示例演算：stamp = "abc"，target = "ababc"](images/wc109_q4_walkthrough.svg)

`stamp = "abc"`、`target = "ababc"`（$n = 5$、$m = 3$，起点 $i \in \{0,1,2\}$）：

初始化各起点的匹配数：

| 起点 | 覆盖的串 | 与 `"abc"` 逐位比较 | cnt |
|------|----------|---------------------|-----|
| 0 | `aba` | a=a ✓、b=b ✓、a≠c ✗ | 2 |
| 1 | `bab` | b≠a、a≠b、b≠c | 0 |
| 2 | `abc` | 全匹配 | 3 → 入队 |

擦除过程（队列开头是当前唯一候选 2）：

1. **弹出 2**，记录 2，把位置 2、3、4 擦成 `'?'`：
   - $p=2$：覆盖它的起点有 0、1。`target[2]='a'` 与 `stamp[2]='c'` 不同 → `cnt[0]: 2→3`（入队）；与 `stamp[1]='b'` 不同 → `cnt[1]: 0→1`。
   - $p=3$：起点 1。`target[3]='b'` 与 `stamp[2]='c'` 不同 → `cnt[1]: 1→2`。
   - $p=4$：只有起点 2（自己），跳过。
2. **弹出 0**，记录 0，擦掉位置 0、1（2、3、4 已擦）：
   - $p=1$：起点 1。`target[1]='b'` 与 `stamp[0]='a'` 不同 → `cnt[1]: 2→3`（入队）。
3. **弹出 1**，记录 1，其覆盖的位置已全部擦除。
4. 三个位置全部擦完，记录顺序 `[2, 0, 1]`，反转得 **[1, 0, 2]**。

正向验证：位置 1 盖 → `?abc?`；位置 0 盖 → `abcc?`？——准确地说覆盖位置 0、1、2 后得到 `abc c?` 形如 `[a,b,c,c,?]`；最后在位置 2 盖得 `[a,b,a,b,c]` = `"ababc"` ✓。

官方示例给出的是 `[0, 2]`，本题接受任何合法序列，`[1, 0, 2]` 同样正确。

## 4. 算法细节

1. **`done` 与 `cnt` 分离**：`done[p]` 表示该位置已变 `'?'`；`cnt[i]` 是「对上数」。两者独立维护，别混用。
2. **`cnt` 的初值只数「相等」**：`'?'` 只在后续通过 `done` 体现，初始化时 `target` 里没有 `'?'`。
3. **增量更新的条件**：`target[p] != stamp[p - j]` 才 `cnt[j]++`，否则重复计数（这是本题最容易写错的地方）。
4. **覆盖区间**：位置 $p$ 被起点 $j$ 覆盖 $\iff j \le p \le j + m - 1 \iff j \in [p - m + 1,\ p]$，再与 $[0, n-m]$ 取交集。
5. **跳过自身**：擦除起点 $i$ 时，$j = i$ 无需再更新（它已经擦过），否则会把 `cnt[i]` 推到 $m+1$ 并重复入队。
6. **答案反转**：记录的是逆序（后盖的先被擦），所以最后要 `reverse`。
7. **步数限制**：每个位置最多被擦一次，故答案长度 $\le n \le 10n$，自动满足题目的回合上限。
8. **失败判定**：若擦除结束后仍有 `done[p] == false`，说明这些字符无法被任何合法印章解释，返回空数组。

## 5. 正确性证明

把逆向过程形式化：定义「可擦状态」为字符串 $T$（含 `'?'`），位置 $i$ 可擦当且仅当 $\forall k:\ T[i+k] = \text{stamp}[k]$ 或 $T[i+k] = \text{'?'}$，且至少一个 $T[i+k] \ne \text{'?'}$。

**引理 1（逆向模拟的等价性）**：设正向盖章序列为 $i_1, i_2, \dots, i_r$（依次执行）能得到 `target`，则从 `target` 出发，按 $i_r, i_{r-1}, \dots, i_1$ 的顺序依次擦除是合法的，且擦完得到全 `'?'`。

**证明**：对 $t$ 从 $r$ 递减到 1 归纳。执行完正向的第 $t$ 步后，字符串为 $T_t$；最终 $T_r = \text{target}$。逆向第 $r$ 步要在 $T_r$ 上擦除 $i_r$：正向第 $r$ 步是把 $[i_r, i_r+m)$ 全部写成 `stamp`，故 $T_r[i_r + k]$ 要么等于 $\text{stamp}[k]$（如果之后没有被别的印章覆盖），要么被更晚的印章覆盖——但 $i_r$ 是最后一步，不存在更晚的覆盖，所以 $T_r[i_r+k] = \text{stamp}[k]$ 对所有 $k$ 成立，满足可擦条件（且至少一个非 `'?'`，因为 $m \ge 1$）。

一般地，设逆向已擦除 $i_r, \dots, i_{t+1}$，当前串 $T$ 中这些位置为 `'?'`，其余位置与 $T_t$ 相同。擦除 $i_t$：正向第 $t$ 步把 $[i_t, i_t+m)$ 写成 `stamp`；之后若被某个 $i_s$（$s > t$）覆盖，则该位置在当前 $T$ 中已是 `'?'`；否则当前 $T$ 中它仍是 `stamp[k]`。两种情况都满足「等于 `stamp[k]` 或为 `'?'`」，故可擦。擦完 $i_t$ 后，$[i_t, i_t+m)$ 全为 `'?'`，归纳成立。

最终 $T_0$ 是全 `'?'`（初始序列）。∎

**引理 2（贪心安全 / 交换论证）**：设当前状态 $T$ 有可擦位置 $i$ 与 $i'$。则在 $T$ 上先擦 $i$ 再擦 $i'$ 一定合法（若 $i'$ 在擦 $i$ 后仍可擦）。

**证明**：擦除 $i$ 只把 $[i, i+m)$ 的字符变成 `'?'`，其余不变。对 $i'$ 的可擦条件：其每个位置要么原本等于 `stamp`、要么是 `'?'`；擦除后这些字符要么不变、要么从某个字母变成 `'?'`，两种情况下条件仍成立。因此 $i'$ 在擦 $i$ 后依然可擦。∎

**推论**：从同一状态出发，任何「能擦就擦」的极大序列，只要最终能擦到全 `'?'`，都对应一个合法的正向盖章序列（由引理 1 的逆否方向 + 反转顺序）。

**引理 3（计数正确性）**：算法中 `cnt[i] == m` 当且仅当位置 $i$ 在当前状态下可擦；且 `cnt[i]` 的每次增加都对应「一个原本不匹配的位置变成了 `'?'`」。

**证明**：`cnt[i]` 的初值是 $\#\{k : \text{target}[i+k] = \text{stamp}[k]\}$，此后每当某个 $p \in [i, i+m)$ 变成 `'?'` 且 `target[p] != stamp[p-i]` 时 `cnt[i]` 加 1。每对 $(i, p)$（$p$ 在 $i$ 的覆盖区间内、原本不匹配）至多触发一次：$p$ 只会被 `done` 一次。故
$$\text{cnt}[i] = (\text{原本匹配的位置数}) + (\text{已擦除且原本不匹配的位置数}) = \#\{k : \text{target}[i+k] = \text{stamp}[k] \text{ 或 } \text{done}[i+k]\}$$
右侧正是「每个位置都等于 `stamp` 或已是 `'?'`」的计数，故 `cnt[i] == m` $\iff$ 字符条件全部满足。

再看「至少擦掉一个非 `'?'`」：若 $i$ 初始就 `cnt[i] == m`，说明 $m$ 个位置全部匹配，都不为 `'?'`，擦除有效；若 $i$ 是后来通过加 1 达到 $m$，则最后一次加 1 来自某个刚从非 `'?'` 变成 `'?'` 的位置 $p$——它能触发加 1 正说明 `target[p] != stamp[p-i]`、即它此前不是 `'?'`，擦除它确实消去了非 `'?'` 字符。∎

**定理**：算法返回的序列（反转后）是合法的盖章序列；当且仅当存在合法序列时算法不返回空数组。

**证明**：

*可行性*：由引理 3，算法每次入队/擦除的位置都满足可擦条件，故擦除序列本身合法；由引理 1 的逆否方向（把擦除序列反转即盖章序列，逐步可验证），反转后的序列能正好印出 `target`。答案长度 $\le n$（每个位置最多擦一次），满足 $10n$ 的回合限制。

*完备性*：若存在合法盖章序列，由引理 1，从 `target` 出发按逆序擦除可到达全 `'?'`。由引理 2，贪心擦除不会破坏可解性：算法每步选择的可擦位置与「最优序列」的下一步可以交换而不失合法性。因此算法不会卡死；若算法结束仍有未擦位置，说明任何极大擦除序列都到达不了全 `'?'`，由引理 2 的交换论证，合法序列不存在，返回空数组正确。∎

## 6. 复杂度分析

- **时间**：$O(nm)$。初始化统计每个起点的匹配数：$O(nm)$。擦除阶段：每个位置 $p$ 只被 `done` 一次，每次枚举至多 $m$ 个覆盖它的起点，故总更新次数 $O(nm)$；每个起点至多入队一次，出队 $O(1)$。整体 $O(nm) \le 10^6$。
- **空间**：$O(n + nm)$？不——`cnt` 长 $n-m+1$、`done` 长 $n$、队列至多 $n$ 项、答案至多 $n$ 项，故 $O(n)$。
- **对比**：正向 BFS 状态爆炸；「反复全量扫描」的写法是 $O(n^2 m)$，本题数据下也能过，但队列版把复杂度降了一个维度。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> movesToStamp(string stamp, string target) {
        int m = (int)stamp.size(), n = (int)target.size();
        vector<int> ans;
        vector<char> done(n, 0);        // 该位置是否已被擦成 '?'
        vector<int> cnt(n - m + 1, 0);  // 每个起点「已对上的字符数」（'?' 视为对上）
        queue<int> q;

        for (int i = 0; i <= n - m; ++i) {
            for (int k = 0; k < m; ++k) {
                if (target[i + k] == stamp[k]) cnt[i]++;
            }
            if (cnt[i] == m) q.push(i);
        }

        while (!q.empty()) {
            int i = q.front();
            q.pop();
            if (cnt[i] != m) continue;      // 过期候选（理论上不会出现）
            ans.push_back(i);
            for (int k = 0; k < m; ++k) {
                int p = i + k;
                if (done[p]) continue;
                done[p] = 1;
                // 位置 p 变成 '?'，所有覆盖 p 的起点都多“对上”一个字符
                int lo = max(0, p - m + 1), hi = min(p, n - m);
                for (int j = lo; j <= hi; ++j) {
                    if (j == i) continue;              // 当前起点已擦过
                    if (target[p] == stamp[p - j]) continue;  // 本来就对上，不重复计数
                    if (++cnt[j] == m) q.push(j);
                }
            }
        }
        for (int i = 0; i < n; ++i) {
            if (!done[i]) return {};        // 还有擦不掉的位置 → 不可能
        }
        reverse(ans.begin(), ans.end());
        return ans;
    }
};
```

### Python

```python
from collections import deque


class Solution:
    def movesToStamp(self, stamp: str, target: str) -> list[int]:
        m, n = len(stamp), len(target)
        ans = []
        done = [False] * n
        cnt = [0] * (n - m + 1)
        q = deque()

        for i in range(n - m + 1):
            for k in range(m):
                if target[i + k] == stamp[k]:
                    cnt[i] += 1
            if cnt[i] == m:
                q.append(i)

        while q:
            i = q.popleft()
            if cnt[i] != m:
                continue
            ans.append(i)
            for k in range(m):
                p = i + k
                if done[p]:
                    continue
                done[p] = True
                for j in range(max(0, p - m + 1), min(p, n - m) + 1):
                    if j == i:
                        continue
                    if target[p] == stamp[p - j]:
                        continue
                    cnt[j] += 1
                    if cnt[j] == m:
                        q.append(j)

        if not all(done):
            return []
        return ans[::-1]
```

## 8. 边界情况与易错点

1. **重复计数**：无条件 `cnt[j] += 1` 会让「原本就匹配」的位置被数两次，产生非法答案（例如 `stamp = "bba"`、`target = "babba"` 会输出错误序列）。必须判 `target[p] != stamp[p-j]`。
2. **`j == i` 要跳过**：擦除起点 $i$ 时它自己已被处理，再更新会让 `cnt[i]` 超过 $m$ 甚至重复入队。
3. **空擦除**：只擦「至少一个非 `'?'`」的位置，否则队列会无限循环。队列版通过 `done[p]` 判断天然避免。
4. **`m == n`**：起点只有 0，可擦则答案 `[0]`，否则 `[]`（如 `stamp = "ab"`、`target = "ba"`）。
5. **`m == 1`**：每个字符独立，答案长度可达 $n$（如 `stamp = "a"`、`target = "aaaa"` 输出 `[0,1,2,3]`），仍满足 $\le 10n$。
6. **不可解的长串**：如 `stamp = "ab"`、`target = "bb"`，位置 0 的 `b` 对不上 `stamp[0]='a'` 且无人覆盖，最终 `done[0] = false` → 返回 `[]`；这类判断不要靠特判，交给「是否全部擦完」统一处理。
7. **答案顺序**：题目接受任意合法顺序，但必须**每一步都合法**；我们的实现返回的是反转后的逆序记录。
8. **回合数上限**：答案长度 $\le n \le 10n$ 自动满足；不要为了「更短」而做额外优化（那是 NP 风格的追求，本题不需要）。
