# LeetCode 高度检查器 题解

## 1. 题目概述

- **标题 / 题号**：高度检查器（#1051，easy）
- **链接**：https://leetcode.cn/problems/height-checker/
- **来源**：LeetCode 第 138 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序、计数排序

**题意**：学生本应按**非递减**身高排成一行，排好后的高度序列记作 `expected`。给定当前站位 `heights`，返回满足 `heights[i] != expected[i]` 的**下标个数**。

**约束**：

- $1 \le \text{heights.length} \le 100$
- $1 \le \text{heights}[i] \le 100$

**一句话转化**：`expected` 就是把 `heights` 升序排列的结果，答案是两个数组**逐位不相同**的位置数。

## 2. 示例

**示例 1**

```text
输入：heights = [1,1,4,2,1,3]
输出：3
解释：heights  = [1,1, 4 ,2, 1 , 3 ]
      expected = [1,1, 1 ,2, 3 , 4 ]
      下标 2、4、5 处高度不匹配。
```

**示例 2**

```text
输入：heights = [5,1,2,3,4]
输出：5
解释：expected = [1,2,3,4,5]，每个下标都不匹配。
```

**示例 3**

```text
输入：heights = [1,2,3,4,5]
输出：0
解释：已经有序，两个数组完全相同。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**模拟调整**：对当前站位反复做相邻交换（冒泡），每交换一次就更新「哪些下标已经归位」。但题目问的是「与最终有序序列不同的下标数」，而不是交换次数，模拟过程中的中间状态对答案毫无贡献，反而把 $O(n \log n)$ 的排序拖成 $O(n^2)$，还要额外维护下标集合。

也可以对每个 $i$ 单独求它的「排名」：统计有多少个元素严格小于 `heights[i]`、有多少个相等元素排在它前面，从而算出 `expected[i]`，整体 $O(n^2)$。思路正确，但重复扫描数组，没有必要。

### 3.2 核心观察：`expected` 与排序算法无关

![排序后第 i 名的身高就是 expected 的第 i 项](images/wc138_q1_concept.svg)

把 `heights` 看成**多重集**。题目要求的 `expected` 是这个多重集按非递减顺序的唯一排列（即便有重复元素，值序列也唯一）。因此：

- 完全不需要知道学生"应该怎么换位"，只需要一份**升序副本**；
- 答案就是两份数组逐位比较的失配数，一次线性扫描即可。

由于 $1 \le \text{heights}[i] \le 100$，还可以用**计数排序**把排序开销从 $O(n \log n)$ 降到 $O(n + C)$（$C = 100$）。

### 3.3 算法流程

![两步：排序 + 逐位比对](images/wc138_q1_flow.svg)

```text
1. expected = heights 的升序副本
2. ans = 0
3. for i = 0 .. n-1:
       if heights[i] != expected[i]:  ans += 1
4. 返回 ans
```

### 3.4 示例演算

以 `heights = [1,1,4,2,1,3]` 为例：

| 下标 i | 0 | 1 | 2 | 3 | 4 | 5 |
|--------|---|---|---|---|---|---|
| `heights` | 1 | 1 | **4** | 2 | **1** | **3** |
| `expected` | 1 | 1 | **1** | 2 | **3** | **4** |
| 是否失配 | 否 | 否 | 是 | 否 | 是 | 是 |

失配下标为 2、4、5，答案 3。

## 4. 算法细节

1. **先复制再排序**：C++ 里 `vector<int> expected(heights);` 而不是直接 `sort(heights)`，避免破坏入参（有些调用方仍会用到原数组）。
2. **计数排序的实现**：开长度 101 的桶，统计频次后按下标从小到大展开，天然得到升序；也可原地把桶"写回"数组的前缀。
3. **比较时只比数值**：不需要记录每个学生是谁——题目统计的是**下标个数**，元素身份无关。
4. **提前退出无意义**：答案需要完整统计失配数，无法中途短路；但可以在同一个循环里完成比较与计数。
5. **Python 的 `zip` 写法**：`sum(1 for cur, want in zip(heights, expected) if cur != want)` 一行完成，语义与 C++ 循环一致。

## 5. 正确性证明

**引理 1（`expected` 的唯一性）**：把 `heights` 视为多重集 $M$，则满足「非递减」的排列在数值序列上唯一，即 `expected` 就是 $M$ 的升序展开。

**证明**：设 $a$ 与 $b$ 都是 $M$ 的非递减排列。若非递减序列中某一位置 $i$ 有 $a_i \ne b_i$，不妨 $a_i < b_i$；由于 $b$ 非递减，$b_i$ 之后的元素都 $\ge b_i > a_i$，而 $a$ 中 $a_i$ 之前的元素都 $\le a_i < b_i$。于是 $b$ 中值等于 $b_i$ 的元素只能落在下标 $i$ 及其后，$a$ 中这些元素只能落在下标 $i$ 及其前，二者数量都对，但位置冲突（下标 $i$ 处只能有一个值），与 $a, b$ 是同一多重集的排列矛盾。故 $a = b$。∎

**引理 2（排序副本即 `expected`）**：任何正确的排序算法作用在 `heights` 的副本上，输出都等于 `expected`。

**证明**：排序算法的输出是输入多重集的一个非递减排列，由引理 1 该排列唯一，故等于 `expected`。∎

**定理**：算法返回的 `ans` 等于题目要求的下标个数。

**证明**：由引理 2，算法中的 `expected` 就是题目定义的「排序后的高度情况」。算法对每个下标 $i$ 恰好判断一次条件 `heights[i] != expected[i]`，条件成立时 `ans` 加一，因此 `ans` 精确等于满足该条件的下标个数，不多不少。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$，其中排序 $O(n \log n)$、逐位比对 $O(n)$。若改用计数排序则为 $O(n + C)$，$C = 100$ 为值域大小。
- **空间**：$O(n)$ 存放 `expected`（计数排序版额外 $O(C)$ 的桶）。若不要求保留入参，可省略副本，空间降为 $O(\log n)$（排序栈）或 $O(C)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int heightChecker(vector<int>& heights) {
        vector<int> expected(heights);
        sort(expected.begin(), expected.end());
        int ans = 0;
        for (int i = 0; i < (int)heights.size(); i++) {
            if (heights[i] != expected[i]) {
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def heightChecker(self, heights: list[int]) -> int:
        expected = sorted(heights)
        return sum(1 for cur, want in zip(heights, expected) if cur != want)
```

## 8. 边界情况与易错点

1. **长度为 1**：任何人都"已经归位"，答案 0；算法天然给出 0，不需要特判。
2. **全部元素相同**：如 `[3,3,3]`，`expected` 与原数组相同，答案 0。
3. **大量重复时的全失配**：`[2,2,1,1]` 的 `expected` 是 `[1,1,2,2]`，四个下标全部失配，答案 4——不要误以为「有重复就不可能全失配」。
4. **直接对入参排序**：某些语言的判题会复用同一数组，改坏入参有风险，务必先复制。
5. **把题意读成「交换次数」**：题目统计的是**失配下标数**，两者没有关系。例如 `[5,1,2,3,4]` 只需一次循环移位就能有序，但答案是 5。
6. **计数排序的桶大小**：值域上界是 100，桶长 101 才能覆盖下标 100；写 100 会越界。
