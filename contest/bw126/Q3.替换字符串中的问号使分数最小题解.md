# LeetCode 替换字符串中的问号使分数最小 题解

## 1. 题目概述

- **标题 / 题号**：替换字符串中的问号使分数最小（#3081，medium）
- **链接**：https://leetcode.cn/problems/replace-question-marks-in-string-to-minimize-its-value/
- **来源**：LeetCode 第 126 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、哈希表、字符串、计数、排序、堆（优先队列）

**题意**：给定字符串 `s`，其中每个字符要么是小写字母，要么是 `'?'`。对只含小写字母的字符串 `t`，定义 `cost(i)` 为下标 $i$ **之前**（区间 $[0, i-1]$）与 `t[i]` 相同字符出现的次数，`t` 的**分数**为所有 `cost(i)` 之和。要求把所有 `'?'` 替换成小写字母，使分数**最小**；分数相同的方案中，返回**字典序最小**的字符串。

**约束**：

- $1 \le s.length \le 10^5$
- `s[i]` 是小写英文字母或 `'?'`

**关键前提**：分数只依赖**每种字母出现的总次数**，与它们在字符串中的位置无关。这一条把「排列问题」拆成了两个独立子问题：先决定「填哪些字母」，再决定「哪个位置填哪个字母」。

**示例 1**

```text
输入：s = "???"

解释：三个问号填 a、b、c，每种字母各出现 1 次，所有 cost 均为 0，分数 0。
      分数为 0 的还有 "cba"、"abz" 等，其中 "abc" 字典序最小。
```

**示例 2**

```text
解释：已有两个 a，两个问号填 b、c（频次最小的两个字母），得到 "abac"：
      cost = 0,0,1,0，分数 1（两个 a 贡献一对）。
      若填成 "acab"，分数同样是 1，但 "abac" 字典序更小。
```

**示例 3（边界补充：单个问号）**

```text

输出："a"
解释：所有字母频次都是 0，取字母序最小的 a。
```


## 3. 解题思路

### 3.1 暴力思路

先枚举「每个问号填哪个字母」——$26^{q}$ 种（$q$ 为问号个数），再对每个候选串计算分数、比较字典序。$q$ 稍大就爆炸；即使只考虑「填入的字母集合」，也可能有 $\binom{26+q-1}{q}$ 种组合。暴力的唯一价值是提示我们：**分数与排列无关**，所以第一步应先确定「每种字母要加几次」，而不是直接尝试填字符串。

### 3.2 核心观察：分数 = 各字母频次的「对数」之和

![核心观察：分数等于每种字母出现次数的组合数之和](images/bw126_q3_cost_freq.svg)

设字符 $c$ 在串中出现了 $f_c$ 次。每一对「相同字符」的位置 $(i, j)$（$i < j$）恰好在 $cost(j)$ 中被计一次，而 `cost(j)` 统计的正是「$j$ 之前与 `t[j]` 相同的字符个数」。于是

$$\text{score}(t) = \sum_{i} cost(i) = \sum_{c} \binom{f_c}{2} = \sum_c \frac{f_c (f_c - 1)}{2}.$$

这条恒等式有两个直接推论：

1. **顺序无关**：分数只由频次向量 $(f_a, \dots, f_z)$ 决定，把字符任意重排不改变分数。
2. **单次插入的边际代价**：若某字母当前频次为 $f$，再插入一个该字母，分数增加 $\binom{f+1}{2} - \binom{f}{2} = f$。也就是说，**往越少的字母上加，代价越小**。

于是「最小化分数」变成一个纯粹的**负载均衡**问题：给定已有频次，把 $q$ 个位置分配给 26 个字母，使 $\sum_c \binom{f_c}{2}$ 最小——每次都应选当前频次**最小**的字母（同频时选字母序更小的，以便字典序也最小）。这就是「水往低处流」的注水法（water filling）。

### 3.3 算法流程：先定字母，再定位置

![算法流程：注水法选字母，排序后从左到右填](images/bw126_q3_greedy_fill.svg)

```text
1. freq[0..25] ← s 中每个字母的出现次数（'?' 不计）
2. 建小根堆，元素为 (freq[c], c)，共 26 个
3. add ← 空列表
4. 按从左到右的顺序遍历 s 的每个字符：
       若是 '?'：
           弹出堆顶 (f, c)                     # 当前频次最小（同频字母序最小）
           add.append(c)
           压入 (f + 1, c)                     # 该字母频次 +1
5. 把 add 升序排序                        # 关键：贪心取出的顺序不保证非递减
6. 再从左到右扫描 s，把第 k 个 '?' 替换为 add[k]
7. 返回替换后的字符串
```

**为什么第 5 步必须排序**：第 4 步只保证「每次取的字母在当前最优」，取出的**序列**却未必升序。例如 26 个字母频次为 $a=3,\ b=2,\ c=\cdots=z=3$ 时，第一次取 $b$（频次 2 最小），第二次所有字母都变成 3，堆顶是按字母序最小的 $a$——序列变成 $b, a$。若按取出顺序原地填，前面的问号会拿到较大的字母，字典序偏大；排序后再从左到右填，才能把最小的字母放到最靠前的位置。

### 3.4 示例演算

![示例 2 的注水与填位过程](images/bw126_q3_example_walkthrough.svg)

**示例 2**（`s = "a?a?"`）：初始 $freq_a = 2$，其余为 0。

| 步骤 | 问号位置 | 堆顶 $(\text{频次}, \text{字母})$ | 取出 | 取后频次 |
|------|----------|-----------------------------------|------|----------|
| 1 | 1 | $(0, b)$ | b | $freq_b = 1$ |
| 2 | 3 | $(0, c)$ | c | $freq_c = 1$ |

`add = ['b', 'c']`，排序后仍是 `['b', 'c']`；按位置填入：位置 1 填 `b`，位置 3 填 `c`，得到 `"abac"`。分数为 $\binom{2}{2} + \binom{1}{2} + \binom{1}{2} = 1$，与示例一致。

**示例 1**（`s = "???"`）：三次取出的都是当前频次 0 的最小字母，依次为 a、b、c，排序后仍为 a、b、c，得到 `"abc"`，分数 0。

**示例 4**（`s = "zz?"`）：$freq_z = 2$，其余 0。堆顶是 $(0, a)$（字母 a 频次 0 且字母序最小），填 `a`，得到 `"zza"`；新增分数为 0，总分数仍为 $\binom{2}{2} = 1$。

## 4. 算法细节

1. **频次数组而非哈希表**：字符集固定为 26 个小写字母，`int freq[26]` 足够，常数最小；不必用 `unordered_map`。
2. **堆元素用 `(频次, 字母)` 的字典序**：这样「频次相同取字母小」由堆的比较规则自动完成。C++ 用 `priority_queue<pair<int,char>, vector<...>, greater<...>>`，Python 用 `heapq`（元组比较即字典序）。
3. **26 个元素的堆 vs 每次扫 26 个字母**：两者都是常数级（$26 \log 26$ vs $26$），本题 $q \le 10^5$，直接线性扫 26 个字母甚至更快；用堆只是表达更清晰。
4. **必须先收集再排序**：见 3.3 的说明。这一步是本题最容易漏的细节，漏了会在「已有字母频次分布不均」的数据上 WA。
5. **填位是一次顺序扫描**：把 `add` 排序后，用指针 `p` 从左到右把 `'?'` 依次替换即可；不需要按字母分组，也不需要额外构造列表。
6. **分数本身不必计算**：算法只维护频次；若需要验证答案可以顺手算 $\sum \binom{f_c}{2}$，此时注意 $n = 10^5$ 时上界约 $5 \times 10^9$，要用 64 位（Python 无此问题）。
7. **`'?'` 不计入频次**：初始化频次时必须跳过 `'?'`，否则会凭空多出一种「字母」。
8. **复杂度**：$O(n + q \log 26) = O(n)$，其中 $q$ 为问号个数；排序 `add` 是 $O(q \log q)$，但因为只有 26 种字母、且同一字母的多次出现可以合并计数，实际也可按 26 个桶计数后一次输出。

## 5. 正确性证明

设字符串长度为 $n$，问号个数为 $q$，字符 $c$ 的初始频次为 $f_c$，最终频次为 $F_c$。

**引理 1（分数公式）**：$\text{score}(t) = \sum_c \binom{F_c}{2}$。

**证明**：对每个 $c$，设其出现位置为 $p_1 < p_2 < \cdots < p_{F_c}$。则 $cost(p_k) = k - 1$（$p_k$ 之前恰有 $k-1$ 个 $c$），故该字母对分数的贡献为 $\sum_{k=1}^{F_c} (k-1) = \binom{F_c}{2}$。不同字母的贡献互不重叠，求和即得。∎

**引理 2（边际代价）**：在频次向量 $F$ 中把某个 $'?'$ 填成 $c$，分数增量为 $F_c$。

**证明**：由引理 1，变化量为 $\binom{F_c+1}{2} - \binom{F_c}{2} = F_c$。∎

**引理 3（注水法最优）**：给定初始频次 $f$ 与 $q$ 次插入，使 $\sum_c \binom{F_c}{2}$ 最小的方案中，可以取「每次插入当前频次最小的字母」。

**证明**：把「往字母 $c$ 上插入第 $j$ 次」看成一个**边际代价**，由引理 2 它等于插入前 $c$ 的频次。若最终往 $c$ 上插入了 $a_c$ 次，则这些边际代价恰好是
$$f_c,\ f_c + 1,\ f_c + 2,\ \dots,\ f_c + a_c - 1,$$
是一个**严格递增**的序列，且总代价为
$$\sum_c \binom{f_c}{2} + \sum_c \big(a_c f_c + \tfrac{a_c(a_c-1)}{2}\big) = \sum_c \binom{f_c}{2} + \big(\text{所选 } q \text{ 个边际代价之和}\big).$$
于是问题变成：从 26 条递增序列的**前缀**中挑 $q$ 个边际代价，使和最小（选了第 $j$ 个必须先选前 $j-1$ 个）。由于每条序列递增，**每次取当前所有可用边际代价中的最小者**显然最优：若某最优解在某一步取了较大的边际代价 $y$ 而当时存在更小的可用者 $x$，把 $y$ 换成 $x$ 仍满足前缀约束（$x$ 是可用者，即它的前驱都已被选），且总和不增——于是总存在一个最优解与贪心在每一步的选择相同，故贪心的总代价也最小。而「取当前位置频次最小的字母」正是「取当前最小可用边际代价」。∎

**引理 4（同分下的字典序：排序后填位最优）**：设待填字母的多重集合为 $M$（由引理 3 的注水法确定），把 $M$ 中的字母**升序**依次填入从左到右的问号位置，所得字符串在「使用 $M$ 的方案」中字典序最小。

**证明**：设问号位置为 $q_1 < q_2 < \cdots < q_m$（$m = |M|$）。任一使用 $M$ 的方案给出一个序列 $(x_1, \dots, x_m)$，$x_k$ 填在 $q_k$。若该序列不是升序，则存在 $i < j$ 使 $x_i > x_j$；交换 $x_i, x_j$ 后，两个位置上的字母互换，而 $q_i < q_j$ 之前的字符完全相同，在 $q_i$ 处新字母更小，故字符串严格变小。反复交换即可把任意方案变成升序方案且字典序不增，故升序填充最小。∎

**引理 5（同频取小字母的必要性）**：在注水法的任何一步，若多个字母频次并列最小，取字母序最小者不会使最终字典序变大。

**证明**：并列最小时，选哪个字母对后续「频次向量」的影响相同（只是把某个最小频次 $+1$），因此最终可用的字母多重集合在两种选择下只差一次「字母替换」。取更小的字母会使升序排列后的多重集合在字典序意义下不变大（逐位比较更小或相等），由引理 4 填充后字符串字典序不变大。∎

**定理**：算法返回的字符串在所有替换方案中分数最小，且分数相同时字典序最小。

**证明**：由引理 3，注水法给出的字母多重集合达到最小分数；算法第 4 步正是逐步执行注水法（堆保证每次取当前频次最小者），故其字母多重集合对应最小分数。由引理 4、5，排序后从左到右填位得到的字符串在所有最小分数方案中字典序最小。所以返回值同时满足两个目标。∎

## 6. 复杂度分析

- **时间**：$O(n + q \log 26 + q \log q) = O(n \log n)$ 最坏，$n = |s|$、$q$ 为问号数。统计频次 $O(n)$；每个问号一次堆操作 $O(\log 26)$；排序待填字母 $O(q \log q)$（字母只有 26 种，用桶计数可降到 $O(q + 26)$）；填位 $O(n)$。实测 $n = 10^5$ 全问号时 C++ 约 $0.01$ 秒、Python 约 $0.05$ 秒。
- **空间**：$O(n)$。待填字母列表 $O(q)$、结果字符串 $O(n)$；频次数组与堆均为 $O(26)$ 的常数空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string minimizeStringValue(string s) {
        vector<int> freq(26, 0);
        for (char c : s)
            if (c != '?') ++freq[c - 'a'];
        priority_queue<pair<int, char>, vector<pair<int, char>>,
                       greater<pair<int, char>>> pq;   // (频次, 字母) 小根堆
        for (int i = 0; i < 26; ++i) pq.push({freq[i], (char)('a' + i)});
        string add;
        for (char c : s) {                             // 按从左到右的顺序挑字母
            if (c != '?') continue;
            auto [f, ch] = pq.top(); pq.pop();
            add += ch;                                 // 收集待填字母
            pq.push({f + 1, ch});
        }
        sort(add.begin(), add.end());                  // 升序，字典序最小
        int p = 0;
        for (char& c : s)
            if (c == '?') c = add[p++];
        return s;
    }
};
```

### Python

```python
import heapq


class Solution:
    def minimizeStringValue(self, s: str) -> str:
        freq = [0] * 26
        for ch in s:
            if ch != '?':
                freq[ord(ch) - 97] += 1
        heap = [(freq[i], i) for i in range(26)]
        heapq.heapify(heap)                     # (当前频次, 字母)
        add = []
        for ch in s:
            if ch != '?':
                continue
            f, i = heapq.heappop(heap)
            add.append(chr(97 + i))             # 频次最小（同频取字母小）的字母
            heapq.heappush(heap, (f + 1, i))
        add.sort()                              # 待填字母升序 -> 字典序最小
        res = list(s)
        p = 0
        for i, ch in enumerate(res):
            if ch == '?':
                res[i] = add[p]
                p += 1
        return ''.join(res)
```

> 💡 两份代码通过官方示例（`"abc"`、`"abac"`）与 `"?"`（答案 `"a"`）、`"zz?"`（答案 `"zza"`）、26 个字母各出现一次再跟一个问号（答案以 `a` 结尾）等边界，并与「枚举 $26^q$ 种填法、取分数最小再取字典序最小」的暴力在 120 组随机串（长度 $\le 6$、问号 $\le 3$）上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **漏掉「排序待填字母」**：这是本题最主要的错误来源。贪心取出的字母序列不保证非递减（如 $a=3, b=2, c\sim z=3$ 时先取 b 再取 a），按取出顺序原地填会得到偏大的字典序。
2. **同频时必须取字母小的**：堆的键写成 `(freq, letter)` 即可天然满足；若只按 `freq` 建堆而忽略字母序，字典序可能不是最小。
3. **`'?'` 不计入频次**：初始化时忘了 `if (ch != '?')` 会把 `'?'` 当成第 27 种字母参与计数，后续逻辑全错。
4. **分数与顺序无关，但字典序有关**：两者必须分两步处理（先定多重集合、再定位置），混在一起贪心会出错。
5. **返回的必须是「分数最小」前提下的字典序最小**：只追求字典序（把问号全填 `a`）会让分数暴涨，方向反了。
6. **`q = 0`**：没有问号时 `add` 为空，填位循环不执行，直接返回原串，不要特判成返回空串。
7. **分数计算可能溢出**：若额外计算分数验证，上界是 $\binom{10^5}{2} \approx 5 \times 10^9$，`int` 会溢出，用 64 位。
8. **不要修改输入**：C++ 版直接原地替换 `s` 并返回（形参是值传递的副本，安全）；Python 版先 `list(s)` 再改，避免对不可变字符串做低效拼接。
