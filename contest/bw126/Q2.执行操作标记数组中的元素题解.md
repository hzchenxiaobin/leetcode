# LeetCode 执行操作标记数组中的元素 题解

## 1. 题目概述

- **标题 / 题号**：执行操作标记数组中的元素（#3080，medium）
- **链接**：https://leetcode.cn/problems/mark-elements-on-array-by-performing-queries/
- **来源**：LeetCode 第 126 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、排序、模拟、堆（优先队列）

**题意**：给定长度为 $n$ 的正整数数组 `nums`，初始所有元素都**未标记**。按顺序执行 $m$ 次操作，第 $i$ 次操作给出 `queries[i] = [index_i, k_i]`，需要：

1. 若下标 `index_i` 处的元素**尚未标记**，则标记它（已标记则忽略这一步）；
2. 再标记 $k_i$ 个**未标记元素中最小的**那些；若值相同，优先标记**下标较小**的；若不足 $k_i$ 个，就全部标记。

返回长度 $m$ 的数组 `answer`，`answer[i]` 是第 $i$ 次操作后**仍未标记元素之和**。

**约束**：

- $n = nums.length$，$m = queries.length$，$1 \le m \le n \le 10^5$
- $1 \le nums[i] \le 10^5$
- $0 \le index_i, k_i \le n - 1$

**关键前提**：**标记只增不减**。这个单调性意味着「未标记元素集合」只会收缩，于是「当前最小的未标记元素」可以沿着一个**预先排好的顺序**一路向右走，而不必每次重新扫描。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,1,2,3,1], queries = [[1,2],[3,3],[4,2]]
输出：[8,3,0]
解释：第 1 次：标记下标 1（值 2），再标记最小的 2 个未标记（下标 0、3，值均为 1），剩余和 2+2+3+1 = 8；
      第 2 次：下标 3 已标记，忽略；再标记最小的 3 个（下标 6 值 1、下标 2 值 2、下标 4 值 2），剩余 3；
      第 3 次：下标 4 已标记，忽略；再标记最小的 2 个（下标 5 值 3），剩余 0。
```

**示例 2**

```text
输入：nums = [1,4,2,3], queries = [[0,1]]
输出：[7]
解释：标记下标 0，再标记最小的 1 个未标记元素（下标 2，值 2）；剩余 4 + 3 = 7。
```

**示例 3（边界补充：$k_i = 0$）**

```text
输入：nums = [5,1], queries = [[0,0]]
输出：[1]
解释：只标记下标 0，k = 0 不额外标记，剩余 1。
```

**示例 4（边界补充：值重复时的下标优先）**

```text
输入：nums = [2,2,2], queries = [[1,1]]
输出：[2]
解释：先标记下标 1；再标记「最小且下标最小」的未标记元素，即下标 0；剩余 2。
      若忽略「下标较小优先」，可能错标下标 2，剩余值虽同为 2，但在其他数据上会导致后续结果不同。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：每次操作先把 `index_i` 标记，然后重复 $k_i$ 遍「线性扫描所有未标记元素、取 `(值, 下标)` 最小者并标记」。单次扫描 $O(n)$，单次操作 $O(k_i n)$，最坏总复杂度 $O(m n^2)$（$k_i$ 与 $n$ 同阶时约 $10^{15}$），完全不可行。

即便用堆优化到 $O(k_i \log n)$，总标记数也不超过 $n$，看似可行，但堆里会积累大量「已标记但仍留在堆中」的失效元素，需要惰性删除；再加上每次 `index_i` 的随机标记，代码容易写乱。更干净的思路是利用单调性做**一次排序 + 一个只前进的指针**。

### 3.2 核心观察：把「元素」按 (值, 下标) 预排序，指针只向右走

![核心观察：按 (值, 下标) 排序后，用只前进的指针取未标记的最小元](images/bw126_q2_sorted_pointer.svg)

把下标 $0 \sim n-1$ 按 `(nums[i], i)` 升序排序得到数组 `order`。对**任意**标记状态，「未标记元素中最小者（值相同取下标小）」恰好就是 `order` 中**第一个未标记的位置**。于是：

- 「标记 $k$ 个最小的未标记元素」＝ 从指针 `p` 开始向右扫，遇到未标记的就标记并 `k--`，遇到已标记的就跳过；
- 由于**标记只增不减**，`order` 中位置 $< p$ 的元素一旦被扫过就必然已被标记（要么当时被标记，要么本来就是被 `index_i` 标记的），因此指针**永远不需要回退**，总移动次数不超过 $n$。

再维护一个变量 `rest` = 当前未标记元素之和：初始为整个数组之和；**每标记一个元素就减去它的值**。这样每次操作结束时，`answer[i] = rest` 直接可得，不需要重新求和。

这两个观察合起来，把「每次操作找最小值」的 $O(n)$ 扫描降成了全局均摊 $O(1)$ 的指针推进，总复杂度由排序主导：$O(n \log n)$。

### 3.3 算法流程

```text
1. order ← 0..n-1 按 (nums[i], i) 升序        # 值小优先，值同下标小优先
2. marked[0..n-1] ← false；rest ← sum(nums)；p ← 0
3. 对每条查询 (idx, k)：
      若 not marked[idx]：                       # 第一步：标记指定下标
          marked[idx] ← true；rest ← rest − nums[idx]
      当 k > 0 且 p < n：                        # 第二步：标记最小的 k 个未标记
          j ← order[p]
          若 not marked[j]：
              marked[j] ← true；rest ← rest − nums[j]；k ← k − 1
          p ← p + 1                              # 指针只前进
      answer.push(rest)
4. 返回 answer
```

### 3.4 示例演算

![示例 1 的逐步标记过程与剩余和](images/bw126_q2_example_walkthrough.svg)

`nums = [1,2,2,1,2,3,1]`，`order`（按值与下标排序）为 $[0,3,6,1,2,4,5]$，即值是 $1,1,1,2,2,2,3$；初始 `rest = 12`。

| 操作 | `idx` | 标记 `idx` | `k` | 额外标记的下标 | `rest` |
|------|-------|------------|-----|----------------|--------|
| 1 | 1 | 值 2，`rest = 10` | 2 | 0（值 1）、3（值 1） | 8 |
| 2 | 3 | 已标记，跳过 | 3 | 6（值 1）、2（值 2）、4（值 2） | 3 |
| 3 | 4 | 已标记，跳过 | 2 | 5（值 3），之后无元素 | 0 |

第 1 次操作后未标记的是下标 $2,4,5,6$，值和 $2+2+3+1=8$；第 2 次后只剩下标 $5$（值 3）；第 3 次后全被标记，和为 $0$，与示例输出 `[8,3,0]` 一致。

## 4. 算法细节

1. **排序键必须是 `(值, 下标)`**：题面要求「值相同则下标小者优先」。只按值排序时，相同值的元素相对顺序取决于排序算法是否稳定，答案可能随之改变（示例 4 就是用来暴露这个问题的）。
2. **两步的顺序不能反**：先标记 `index_i`，再标记 $k_i$ 个最小未标记。若先把 $k_i$ 个最小标记完再处理 `index_i`，当 `index_i` 本身就在那 $k_i$ 个里时，结果会少标记一个元素。
3. **`index_i` 已标记时必须跳过**：不能再 `rest -= nums[idx]`，否则同一个值被减两次，剩余和偏小。用 `marked` 数组做守卫。
4. **`k` 用 `while (k > 0 && p < n)` 控制**：`k_i` 可能大于剩余未标记元素个数（题面允许，此时全部标记），必须有 `p < n` 兜底，否则越界。
5. **指针位置不需要重置**：`p` 在查询之间保持连续推进。这是因为 `order` 中位置 $< p$ 的元素都已标记（见 §5 引理 2），再次从 `p` 开始仍然正确，而且总推进次数不超过 $n$。
6. **`rest` 用 64 位**：$n \le 10^5$、$nums[i] \le 10^5$，总和最大 $10^{10}$，超出 `int`。C++ 用 `long long`，Python 无此问题（返回类型也是 `long[]`）。
7. **`marked` 用 `vector<char>` / `bool` 数组**：$O(n)$ 空间、$O(1)$ 查询，比哈希表快；Python 用 `bytearray` 或 `list[bool]` 均可。
8. **不需要真正的堆**：指针法已经能达到「取最小未标记」的效果且常数更小；若坚持用堆，必须处理「堆内已标记元素」的惰性弹出，代码反而更长。

## 5. 正确性证明

设 `order` 是将下标按 `(nums[i], i)` 升序排列后的序列。对任意标记状态，记 $U$ 为未标记下标集合。

**引理 1（排序序即优先序）**：若 $j$ 是 `order` 中第一个属于 $U$ 的下标，则 $j = \arg\min_{u \in U} (nums[u], u)$（按字典序取最小）。

**证明**：`order` 按 $(nums, index)$ 升序排列。设 `order` 中 $j$ 之前的位置为 $o_1, \dots, o_{t}$，它们都不在 $U$ 中（由 $j$ 是第一个未标记者），而 $j \in U$。对任意 $u \in U$，$u \ne o_k$，故 $u$ 在 `order` 中的位置 $\ge j$ 的位置，于是 $(nums[u], u) \ge (nums[j], j)$（字典序）。故 $j$ 就是 $U$ 中字典序最小者。∎

**引理 2（指针不变式）**：每次查询的第二步结束后（以及每次查询开始时），`order` 中位置 $< p$ 的所有下标都已标记。

**证明**：对查询次数归纳。初始 $p = 0$，平凡成立。设某次查询开始时成立。第二步的循环每轮把 $p$ 加 1：若 `order[p]` 已标记，不变式显然保持；若未标记，则在本轮被标记，$p$ 加 1 后该位置也已标记。循环退出时要么 $k = 0$（此时所有被访问过的位置都处理完毕，$p$ 已越过最后一个被标记的位置），要么 $p = n$（全部标记）。两种情况下不变式均保持。第一步（标记 `index_i`）只会增加标记，不会破坏「位置 $< p$ 已标记」。故归纳成立。∎

**引理 3（第二步标记的集合正确）**：某次查询的第二步结束时，新标记的恰好是「当前未标记元素中按 $(nums, index)$ 最小的 $\min(k_i, |U|)$ 个」。

**证明**：循环从 $p$ 开始向右扫描，由引理 2 位置 $< p$ 的元素都已标记，故从 $p$ 起的第一个未标记元素就是当前 $U$ 的最小者（引理 1）；标记它之后继续向右找下一个未标记者，即 $U$ 中次小者，依此类推。每标记一个 `k` 减 1，故恰好标记前 $\min(k_i, |U|)$ 个最小者。∎

**引理 4（`rest` 不变式）**：每次查询结束时 `rest` 等于当前未标记元素之和。

**证明**：初始 `rest = sum(nums)` 即全体之和。每次标记一个此前未标记的元素 $j$（由 `marked[j]` 守卫，保证每个元素至多被减一次），`rest` 减去 $nums[j]$，与「从未标记集合中移除 $j$」一致。故不变式在每次标记后保持，查询结束时成立。∎

**定理**：算法返回的 `answer[i]` 等于第 $i$ 次操作后未标记元素之和。

**证明**：第一步按题面规则标记 `index_i`（已标记则忽略，符合题意）；第二步由引理 3 标记了正确的 $k_i$ 个最小未标记元素。于是每次操作后的标记状态与题面要求的完全一致；由引理 4，此时 `rest` 正是未标记元素之和，算法把它压入 `answer`。对 $i = 0, \dots, m-1$ 均成立。∎

## 6. 复杂度分析

- **时间**：$O(n \log n + m)$。排序 $O(n \log n)$ 是瓶颈；每条查询第一步 $O(1)$；第二步中指针总推进次数不超过 $n$（引理 2），故所有查询的第二步合计 $O(n)$。$n = 10^5$ 时排序约 $1.7 \times 10^6$ 次比较，实测 C++ 约 $0.31$ 秒（含 I/O）、Python 约 $0.09$ 秒。
- **空间**：$O(n)$。`order`、`marked`、`answer` 各 $O(n)$；无堆、无哈希表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<long long> unmarkedSumArray(vector<int>& nums, vector<vector<int>>& queries) {
        int n = nums.size();
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) {
            if (nums[a] != nums[b]) return nums[a] < nums[b];
            return a < b;                                  // 值相同：下标小者优先
        });
        vector<char> marked(n, 0);
        long long rest = 0;
        for (int x : nums) rest += x;
        vector<long long> ans;
        ans.reserve(queries.size());
        int p = 0;                                         // 指针只前进
        for (auto& q : queries) {
            int idx = q[0], k = q[1];
            if (!marked[idx]) {                            // 第一步：标记指定下标
                marked[idx] = 1;
                rest -= nums[idx];
            }
            while (k > 0 && p < n) {                       // 第二步：标记最小的 k 个未标记
                int j = order[p];
                if (!marked[j]) {
                    marked[j] = 1;
                    rest -= nums[j];
                    --k;
                }
                ++p;
            }
            ans.push_back(rest);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def unmarkedSumArray(self, nums: list[int], queries: list[list[int]]) -> list[int]:
        n = len(nums)
        order = sorted(range(n), key=lambda i: (nums[i], i))   # 值小优先，其次下标小
        marked = [False] * n
        rest = sum(nums)
        ans = []
        p = 0                                                  # 指针只前进
        for idx, k in queries:
            if not marked[idx]:                                # 第一步：标记指定下标
                marked[idx] = True
                rest -= nums[idx]
            while k > 0 and p < n:                             # 第二步：标记最小的 k 个未标记
                j = order[p]
                if not marked[j]:
                    marked[j] = True
                    rest -= nums[j]
                    k -= 1
                p += 1
            ans.append(rest)
        return ans
```

> 💡 两份代码通过官方示例（`[8,3,0]`、`[7]`）与 `k = 0`、`k` 大于剩余未标记数、全部元素值相同等边界，并与「每次操作线性扫描找最小未标记元素」的 $O(mn)$ 暴力在 200 组随机数据（$n \le 9$，值域 $\le 6$）上对拍，`mismatch = 0`；$n = m = 10^5$ 的极限数据 C++ 耗时 $0.31$ 秒。

## 8. 边界情况与易错点

1. **两步顺序**：先标记 `index_i`，再标记 $k_i$ 个最小未标记。反序会在 `index_i` 属于「最小 $k_i$ 个」时少标记一个元素。
2. **已标记的 `index_i` 要跳过**：重复 `rest -= nums[idx]` 会让剩余和偏小（示例 1 的第 2、3 次操作都踩这条）。
3. **值相同的下标优先**：排序比较器必须带上 `i` 的升序，否则结果依赖排序稳定性，在「值相同但后续查询命中其中某个下标」的数据上会出错。
4. **`k_i = 0`**：约束允许 $0 \le k_i$。此时第二步不应标记任何元素，`while (k > 0 ...)` 天然跳过。
5. **`k_i` 大于剩余未标记数**：此时把剩余的全部标记，`rest` 归零；`p < n` 的判断必不可少。
6. **求和溢出**：$10^{10}$ 量级，C++ 必须用 `long long`；返回类型是 `long[]` 也不是偶然。
7. **指针不要重置**：每次查询都把 `p` 归零会退化成 $O(nm)$；正确做法是查询之间沿用同一个 `p`（由不变式保证正确）。
8. **不要真的用堆 + 惰性删除**：虽然可行，但 `index_i` 的任意标记会让堆顶频繁失效，代码复杂且常数更大；排序 + 指针是本题最省心的写法。
