# LeetCode 求出加密整数的和 题解

## 1. 题目概述

- **标题 / 题号**：求出加密整数的和（#3079，easy）
- **链接**：https://leetcode.cn/problems/find-the-sum-of-encrypted-integers/
- **来源**：LeetCode 第 126 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：数组 `nums` 中都是正整数。定义加密函数 `encrypt(x)`：把 $x$ 的**每一个数位**都替换成 $x$ 中的**最大数位**（位数不变）。例如 `encrypt(523) = 555`、`encrypt(213) = 333`。返回数组所有元素加密后的**和**。

**约束**：

- $1 \le nums.length \le 50$
- $1 \le nums[i] \le 1000$

**关键前提**：加密只做「数位替换」，**不改变位数**。因此 `encrypt(x)` 的形状完全由两个量决定：最大数位 $m$，以及位数 $L$。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]
输出：6
解释：三个数都是个位数，加密后仍是 [1,2,3]，和为 6。
```

**示例 2**

```text
输入：nums = [10,21,31]
输出：66
解释：encrypt(10) = 11（最大数位 1，两位全填 1）；
      encrypt(21) = 22；encrypt(31) = 33。11 + 22 + 33 = 66。
```

**示例 3（边界补充：含 0 的数位）**

```text
输入：nums = [1000]
输出：1111
解释：1000 的最大数位是 1，四位全部填 1，得到 1111。
      注意位数是 4 而不是把 1000 当作「1」。
```

**示例 4（边界补充：单元素与等位数混合）**

```text
输入：nums = [1000, 999]
输出：2110
解释：encrypt(1000) = 1111，encrypt(999) = 999，和为 2110。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $x$ 把数位取出来（转字符串或反复取模），找到最大值，再拼回一个与原数**同位数**、每位都是该最大值的新数。这本身就是正解——$n \le 50$、$x \le 1000$（最多 4 位），整体不到 $200$ 次数位操作。真正需要想清楚的不是「怎么算得更快」，而是「怎么拼回时才不丢位数」：如果用字符串处理，直接把 `max(digits) * len(digits)` 转成整数即可；如果纯算术，则需要先数出位数再用循环构造。

### 3.2 核心观察：加密结果 = 全 1 数 × 最大数位

![核心观察：每个数位替换成最大数位，结果形如 m·111…1](images/bw126_q1_encrypt_digits.svg)

设 $x$ 有 $L$ 位、最大数位为 $m$。加密后每一位都是 $m$，于是

$$encrypt(x) = \underbrace{mm\cdots m}_{L \text{ 位}} = m \times \underbrace{11\cdots 1}_{L \text{ 位}} = m \cdot \frac{10^{L} - 1}{9}.$$

这条恒等式解释了为什么「位数」必须保留：$encrypt(1000) = 1111$ 而不是 $1$，因为 $L = 4$。它同时给出了两种等价实现：

- **算术法**：一边取模一边统计最大数位与位数，最后用 `enc = enc * 10 + m` 循环 $L$ 次构造；
- **字符串法**：`m = max(str(x))`，`int(m * len(str(x)))`。

两种写法都对，算术法不依赖字符串转换，字符串法更短。

### 3.3 算法流程

![算法流程：逐个数位取最大，按位数拼回，累加求和](images/bw126_q1_sum_flow.svg)

```text
1. total ← 0
2. 对 nums 中每个 x：
       mx ← 0, digits ← 0
       t ← x
       当 t > 0：
           mx ← max(mx, t mod 10)
           digits ← digits + 1
           t ← t / 10                    # 整除
       enc ← 0
       重复 digits 次：enc ← enc * 10 + mx
       total ← total + enc
3. 返回 total
```

### 3.4 示例演算

以示例 2（`nums = [10,21,31]`）为例：

| $x$ | 数位 | 最大数位 $m$ | 位数 $L$ | $encrypt(x)$ |
|-----|------|--------------|----------|--------------|
| 10 | 1, 0 | 1 | 2 | 11 |
| 21 | 2, 1 | 2 | 2 | 22 |
| 31 | 3, 1 | 3 | 2 | 33 |

总和 $11 + 22 + 33 = 66$。

再看示例 3（`nums = [1000]`）：数位是 $1, 0, 0, 0$，$m = 1$、$L = 4$，$encrypt(1000) = 1 \times 1111 = 1111$。若误把「最大数位」当成加密结果直接返回，就会得到 $1$——这是本题最典型的错误。

## 4. 算法细节

1. **位数要单独统计**：只取最大数位是不够的，必须同时知道位数，否则无法区分 $1000 \to 1111$ 与 $1 \to 1$。
2. **算术构造的循环次数**：`for (int i = 0; i < digits; ++i) enc = enc * 10 + mx;` 共 $L$ 次，得到 $L$ 位全 $m$ 的数；循环写成 `digits - 1` 会少一位。
3. **字符串写法**：`int(max(str(x)) * len(str(x)))`——`max(str(x))` 取的是字符的最大值（如 `'9'`），乘字符串是重复，`int` 转换自动去掉前导零问题（本题 $x \ge 1$，不会出现全 0）。
4. **整数范围**：单个加密值最大 $1111$，$50$ 个数求和最大 $55550$，`int` 绰绰有余；不需要 `long long`。
5. **不要用排序或哈希**：每个数独立处理，元素之间唯一的交互是最后的求和，因此一遍扫描累加即可，无需保存中间结果。
6. **`x` 的临时变量**：取数位会破坏 $x$ 的值，务必用临时变量（`int t = x`）迭代，别把原数组改掉。
7. **与「数位和」「数位乘积」类题的区分**：本题是**替换**而非**聚合**，输出与输入同位数；这正是 $m \times R_L$ 这种「形状 × 数位」分解能成立的原因。
8. **$x = 0$ 的假设**：约束保证 $nums[i] \ge 1$，`while (t > 0)` 写法安全；若扩展到 $0$，该写法会得到 $digits = mx = 0$、$enc = 0$，仍然正确（0 加密后是 0）。

## 5. 正确性证明

**引理 1（加密结果的形状）**：设正整数 $x$ 有 $L$ 位、最大数位为 $m$，则 $encrypt(x) = m \cdot R_L$，其中 $R_L = \sum_{i=0}^{L-1} 10^i = \frac{10^L - 1}{9}$。

**证明**：加密把每一位都换成 $m$、位数保持 $L$，故加密结果是 $\sum_{i=0}^{L-1} m \cdot 10^i = m \sum_{i=0}^{L-1} 10^i = m R_L$。∎

**引理 2（位数与最大数位的提取正确）**：对 $x \ge 1$，算法中的 `while (t > 0) { mx = max(mx, t % 10); digits++; t /= 10; }` 结束后 `mx` 等于 $x$ 的最大数位、`digits` 等于 $x$ 的位数。

**证明**：对迭代次数归纳。第 $k$ 次迭代取出的 `t % 10` 恰为 $x$ 的第 $k$ 低位（因为 `t` 是 $x$ 整除 $10^{k-1}$ 的商），且循环在 `t` 变为 $0$ 时结束，共执行 $\lfloor \log_{10} x \rfloor + 1 = L$ 次。故 `digits` $= L$，`mx` 取遍全部 $L$ 个数位中的最大者。∎

**引理 3（构造正确）**：`enc = 0` 起、重复 $L$ 次 `enc = enc * 10 + m`，得到 $m R_L$。

**证明**：第 $k$ 次执行后 `enc` $= m R_k$（对 $k$ 归纳：$k = 1$ 时为 $m$；设 $k$ 时成立，则第 $k+1$ 次得 $m R_k \cdot 10 + m = m(10 R_k + 1) = m R_{k+1}$）。取 $k = L$ 即得 $m R_L$。∎

**定理**：算法返回的值等于 $\sum_{x \in nums} encrypt(x)$。

**证明**：由引理 2、3，对每个 $x$ 算出的 `enc` 等于 $m \cdot R_L$，即由引理 1 等于 $encrypt(x)$；算法把所有 `enc` 累加进 `total`，故返回值就是所有元素加密结果之和。∎

## 6. 复杂度分析

- **时间**：$O(n \log_{10} V)$，其中 $V = \max nums$。每个元素处理其全部数位（$V \le 1000$ 时至多 $4$ 位），构造又走一遍同长度的循环；总操作数约 $2n \log_{10} V \le 400$。
- **空间**：$O(1)$。只用几个整型变量；字符串写法额外用 $O(\log_{10} V) \le 4$ 个字符的临时空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int sumOfEncryptedInt(vector<int>& nums) {
        int total = 0;
        for (int x : nums) {
            int mx = 0, digits = 0;
            for (int t = x; t > 0; t /= 10) {   // 取出最大数位与位数
                mx = max(mx, t % 10);
                ++digits;
            }
            int enc = 0;
            for (int i = 0; i < digits; ++i)    // 构造 digits 位全为 mx 的数
                enc = enc * 10 + mx;
            total += enc;
        }
        return total;
    }
};
```

### Python

```python
class Solution:
    def sumOfEncryptedInt(self, nums: list[int]) -> int:
        total = 0
        for x in nums:
            digits = str(x)
            m = max(digits)                       # 最大数位（字符）
            total += int(m * len(digits))         # 每位都换成最大数位
        return total
```

> 💡 两份代码通过官方示例（`6`、`66`）与 `[1000]`（答案 `1111`）、`[1000, 999]`（答案 `2110`）、`[1000] * 50`（答案 `55550`）等边界，并与「按字符串逐位替换」的独立实现在 300 组随机数组（值域 $\le 1000$）上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **位数必须保留**：`1000 → 1111` 而不是 `1`。只取最大数位而忘了位数，是本题最核心的错点。
2. **数位中有 0**：如 `10`，最大数位是 $1$（0 不参与最大），结果是 `11`；不要因为「看起来像前导零」而丢掉位数。
3. **个位数**：$x \le 9$ 时 $L = 1$、$m = x$，加密后不变，算法自然成立，无需特判。
4. **返回类型**：最大总和 $50 \times 1111 = 55550$，`int` 足够；若把约束放大到 $nums[i] \le 10^9$ 且 $n = 10^5$，则需要 64 位。
5. **算术法的循环次数**：`i < digits` 不能写成 `i <= digits`（会多一位），也不能写成 `i < digits - 1`（会少一位）。
6. **修改了原数组**：取数位时若直接用 `x` 做 `x /= 10`，会把 `nums` 里的值改坏；必须用临时变量。
7. **字符串写法的类型**：`max(str(x))` 返回字符，`m * len(digits)` 是字符串重复，最后要 `int(...)`；直接相加会变成字符串拼接。
8. **$x = 0$ 的扩展**：约束保证 $nums[i] \ge 1$；若放宽到 $0$，算术法（`while t > 0`）与字符串法（`int('0' * 1)`）都返回 $0$，行为一致。
