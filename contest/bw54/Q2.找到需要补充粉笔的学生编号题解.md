# LeetCode 找到需要补充粉笔的学生编号 题解

## 1. 题目概述

- **标题 / 题号**：找到需要补充粉笔的学生编号（#1894，medium）
- **链接**：https://leetcode.cn/problems/find-the-student-that-will-replace-the-chalk/
- **来源**：LeetCode 第 54 场双周赛 Q2
- **难度**：中等
- **标签**：数组、二分查找、前缀和、模拟

**题意**：班级 $n$ 个学生编号 $0 \sim n-1$，循环轮流答题：编号 $0$ 先答，依次到 $n-1$，再回到 $0$。粉笔盒初始有 $k$ 支粉笔；编号 $i$ 的学生答题消耗 $chalk[i]$ 支。若**剩余粉笔严格小于** $chalk[i]$，学生 $i$ 需要补充粉笔。返回需要补充粉笔的学生编号。

**约束**：

- $chalk.length = n$，$1 \le n \le 10^5$
- $1 \le chalk[i] \le 10^5$
- $1 \le k \le 10^9$

## 2. 示例

**示例 1**

```text
输入：chalk = [5,1,5], k = 22
输出：0
解释：三轮循环共消耗 3×11 = 33 支；22 支走完 2 轮（22 = 11 + 11）后剩 0，
编号 0 的学生面对 5 支需求只有 0 支（0 < 5），需要补充。
```

**示例 2**

```text
输入：chalk = [3,4,1,2], k = 25
输出：1
解释：一轮共 10 支。25 = 2×10 + 5，剩 5 支从头走：学生 0 用 3 剩 2，
学生 1 需要 4 支但只剩 2（2 < 4），需要补充。
```

**示例 3（边界补充）**

```text
输入：chalk = [1], k = 10^9
输出：0
解释：唯一的学生循环消耗，k mod 1 = 0 < 1，学生 0 补充。
```

## 3. 解题思路

### 3.1 暴力思路

直接模拟：`while k >= chalk[i]: k -= chalk[i]; i = (i+1) % n`。一轮消耗 $total = \sum chalk$，最坏 $k = 10^9$、$chalk[i] = 1$、$n = 10^5$ 时要循环 $10^9$ 次才减完（$total = 10^5$，$10^9 / 10^5 = 10^4$ 轮 × 每轮 $10^5$ 人 = $10^9$ 步），超时。瓶颈在于**整轮循环的重复**。

### 3.2 核心观察：整轮消耗是「复读机」，k mod total 定终止点

![取模循环：整轮消耗固定](images/bw54_q2_mod_cycle.svg)

粉笔盒每走完一整轮恰好减少 $total = \sum chalk[i]$，学生顺序与剩余量都回到「同构」状态（只是 $k$ 变小）。因此：

$$k \;=\; q \times total + r, \quad 0 \le r < total$$

**跳过 $q$ 个整轮不改变答案**，等价于从 $k = r < total$ 开始单趟扫描。这一步把 $10^9$ 规模直接压到 $10^5$ 以内。严格证明（归纳）见 §5。

### 3.3 算法流程：前缀和视角

```text
1. total = Σ chalk[i]
2. k = k mod total                       # 去掉整轮
3. for i in 0..n-1:
4.     若 k < chalk[i]：返回 i           # 剩余严格小于需求
5.     k -= chalk[i]
```

等价的前缀和/二分视角：令 $pre[i] = chalk[0] + \dots + chalk[i]$，找**最小的 $i$** 使 $pre[i] > k \bmod total$（即走到学生 $i$ 时剩余粉笔不够）。前缀和数组单调不减，可二分查找（`upper_bound`），复杂度 $O(n)$ / $O(\log n)$ 两种写法都对。

### 3.4 示例演算

![示例演算：k=25 取模后的单趟扫描](images/bw54_q2_example_walkthrough.svg)

例 2（$chalk = [3,4,1,2]$、$k = 25$，见上图）：$total = 10$，$25 \bmod 10 = 5$；剩 5 支单趟走：学生 0 用 3 剩 2；学生 1 需 4 支但 $2 < 4$ → 答案 1。例 1 同理：$22 \bmod 11 = 11$，学生 0 用 5 剩 6、学生 1 用 1 剩 5、学生 2 用 5 剩 0，回到学生 0 时 $0 < 5$ → 答案 0。

## 4. 算法细节

1. **取模对象**：`k % total` 中的 `total` 是**一轮总消耗**（前缀和数组的末项），不是 `n`；`chalk[i] ≥ 1` 保证 `total ≥ n ≥ 1`，取模无零除风险。
2. **严格小于的语义**：判定是 `k < chalk[i]`（剩余**严格小于**需求才补充）；`k == chalk[i]` 时够用，正常扣除后继续。
3. **溢出**：$n \cdot chalk[i] \le 10^5 \times 10^5 = 10^{10}$，`int` 会溢出！`total` 与取模后的 `k` 必须用 `long long`（C++）——Python 天然大数无碍。
4. **取模后必然终止**：$r < total = \sum chalk$，单趟扫描内必有某个 $i$ 使累计消耗超过 $r$（否则 $r \ge total$，矛盾），循环不会走完一轮，写 `return -1` 兜底只是防御式编程。
5. **二分写法**：`pre` 数组严格递增（$chalk[i] \ge 1$），`upper_bound(pre.begin(), pre.end(), r)` 给出第一个 $pre[i] > r$ 的位置即答案；注意是 `>` 不是 `≥`（`pre[i] == r` 时恰好走完学生 $i$，下一个才补充）。

## 5. 正确性证明

**引理 1（整轮不变性）**：设一轮消耗 $total = \sum_{i} chalk[i]$。若 $k \ge total$，则从 $k$ 开始与从 $k - total$ 开始，需要补充粉笔的学生编号相同。

**证明**：从 $k$ 开始的过程可分段为「完整的一轮」（每个学生 $i$ 依次满足 $k_t \ge chalk[i]$，其中 $k_t$ 为走到该生时的剩余量），再接上从 $k - total$ 开始的过程。关键在于：$k \ge total$ 时，一轮内每个学生到达时的剩余量 $k_t \ge k - total + \sum_{j > i} chalk[j] \ge chalk[i]$（因为 $k - total \ge 0$ 且该生之前消耗的总量不超过 $total - \sum_{j \ge i} chalk[j]$，剩余恰为 $k - \text{已耗} \ge k - (total - \sum_{j \ge i} chalk[j]) \ge \sum_{j \ge i} chalk[j] \ge chalk[i]$），故整轮无人补充粉笔；轮末剩余恰为 $k - total$，后续过程与「直接从 $k - total$ 开始」逐步相同（同一决定论模拟）。∎

**引理 2（取模等价）**：令 $r = k \bmod total$，则从 $k$ 开始与从 $r$ 开始的答案相同。

**证明**：对 $q = \lfloor k / total \rfloor$ 归纳：$q = 0$ 时显然；$q \ge 1$ 时 $k \ge total$，由引理 1 归约到 $k - total$（其商为 $q - 1$），归纳得证。∎

**定理（单趟扫描的正确性）**：设 $r = k \bmod total < total$。单趟扫描中首个满足「到达时剩余 $< chalk[i]$」的学生编号，即全局答案。

**证明**：由引理 2，只需考虑从 $r$ 出发。$r < total$ 保证一轮之内必停：设前缀消耗 $pre[i] = \sum_{j \le i} chalk[j]$，学生 $i$ 到达时剩余 $r - pre[i-1]$；若所有学生都满足 $r - pre[i-1] \ge chalk[i]$，则 $r \ge pre[n-1] = total$，矛盾。故存在首个停止点 $i^*$，其到达时剩余 $r - pre[i^*-1] < chalk[i^*]$（前缀严格递增保证「首个」良定义）。扫描恰在 $i^*$ 返回。∎

## 6. 复杂度分析

- **时间**：$O(n)$。求和一趟、取模后扫描一趟（至多走 $n$ 步，且因 $r < total$ 实际必然中途停止）。二分写法为 $O(n)$ 预处理 + $O(\log n)$ 查询，总体仍是 $O(n)$。
- **空间**：$O(1)$（累加版，无需保存前缀和数组）或 $O(n)$（二分版需前缀和数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int chalkReplacer(vector<int>& chalk, long long k) {
        long long total = 0;
        for (int c : chalk) total += c;
        k %= total;                                   // 去掉完整的轮数
        for (int i = 0; i < (int)chalk.size(); ++i) {
            if (k < chalk[i]) return i;               // 剩余严格小于当前消耗 → 补充
            k -= chalk[i];
        }
        return -1;                                    // 按题意不可达
    }
};
```

### Python

```python
class Solution:
    def chalkReplacer(self, chalk: list[int], k: int) -> int:
        total = sum(chalk)
        k %= total                                    # 去掉完整的轮数
        for i, c in enumerate(chalk):
            if k < c:
                return i
            k -= c
        return -1                                     # 按题意不可达
```

> 💡 两份代码均通过官方示例（`0`、`1`），并与「逐学生模拟（不取模直接循环）」的暴力实现对拍 2 万组随机数据（$n \le 10$、$chalk[i] \le 20$、$k \le 10^5$），`mismatch = 0`。

## 8. 边界情况与易错点

1. **`total` 溢出**：$total \le 10^{10}$，C++ 中 `int` 累加必然溢出，必须 `long long`；参数 `k` 也建议直接收成 `long long`（LeetCode 的 C++ 签名实为 `int k`，题面约束 $k \le 10^9$ 在 `int` 内，但内部累加 `total` 一定要宽类型）。
2. **严格小于**：`k == chalk[i]` 时学生**能**答题（用完正好），继续往下走；判成 `k <= chalk[i]` 会提前一位返回。
3. **$n = 1$**：答案恒为 0（$k \bmod chalk[0] < chalk[0]$ 成立）。
4. **取模对象是 `total` 不是 `max(chalk)`**，也不是「走到某一格的周期」——整轮消耗固定不变，才是可约去的重复单元。
5. **兜底返回值**：数学上取模后必停，循环走完返回 `-1` 不可达；但若把取模写漏（直接扫原 `k`），单趟可能走完一轮回到起点死循环——务必先取模再扫描。
6. **二分版边界**：`upper_bound` 找第一个 `pre[i] > r`；若用 `lower_bound` 配 `pre[i] >= r` 会把「恰好用完」误判为补充。
