# LeetCode 检查是否区域内所有整数都被覆盖 题解

## 1. 题目概述

- **标题 / 题号**：检查是否区域内所有整数都被覆盖（#1893，easy）
- **链接**：https://leetcode.cn/problems/check-if-all-the-integers-in-a-range-are-covered/
- **来源**：LeetCode 第 54 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、前缀和

**题意**：给定二维整数数组 `ranges`（每个元素是闭区间 $[start_i, end_i]$）与整数 $[left, right]$。若 $[left, right]$ 内**每个整数**都被至少一个区间覆盖（$start_i \le x \le end_i$），返回 `true`，否则 `false`。

**约束**：

- $1 \le ranges.length \le 50$
- $1 \le start_i \le end_i \le 50$
- $1 \le left \le right \le 50$

## 2. 示例

**示例 1**

```text
输入：ranges = [[1,2],[3,4],[5,6]], left = 2, right = 5
输出：true
解释：2 被第一个区间覆盖；3、4 被第二个覆盖；5 被第三个覆盖。
```

**示例 2**

```text
输入：ranges = [[1,10],[10,20]], left = 21, right = 21
输出：false
解释：21 不被任何区间覆盖。
```

**示例 3（边界补充）**

```text
输入：ranges = [[1,3],[5,6]], left = 2, right = 5
输出：false
解释：4 落在两个区间的空隙中，未被覆盖。
```

## 3. 解题思路

### 3.1 暴力思路

对 $[left, right]$ 内每个整数 $x$，扫一遍 `ranges` 判断是否被覆盖。时间 $O((right - left + 1) \cdot |ranges|) \le 50 \times 50 = 2500$，对本题数据完全够用。这是最稳的签到写法，但「区间 → 覆盖计数」的结构用**差分数组**更优雅，也是本题想考察的模板。

### 3.2 核心观察：差分数组把「区间覆盖」变成两次单点修改

![差分数组：+1 打头、−1 收尾](images/bw54_q1_diff_array.svg)

值域只有 $1 \sim 50$，开一个差分数组 `diff`：对每个区间 $[s, e]$ 做 `diff[s] += 1; diff[e+1] -= 1`。随后从左到右累加，得到每个整数点的**覆盖次数** `cur`（前缀和）。判定：$[left, right]$ 内所有点的 `cur ≥ 1` 即 `true`。

> 💡 差分是「前缀和的逆运算」：单点值 = 差分数组的前缀和。区间多次重叠时计数自然累加，与区间是否排序、是否相交完全无关——这是它优于「排序 + 合并区间」的地方（后者要多写排序与边界合并逻辑）。

### 3.3 算法流程

```text
1. diff = [0] * 52                     # 值域 1..50，e+1 最大 51，开 52
2. 对每个 [s, e] ∈ ranges：diff[s]++, diff[e+1]−−
3. cur = 0
4. for x in 1..50:
5.     cur += diff[x]
6.     若 left ≤ x ≤ right 且 cur == 0：返回 false
7. 返回 true
```

### 3.4 示例演算

![示例演算：覆盖与缺口](images/bw54_q1_example_walkthrough.svg)

例 1：三个区间 $[1,2],[3,4],[5,6]$ 相邻铺满，$[2,5]$ 内每点覆盖次数均为 1，返回 `true`。
例 2：$[1,10]$ 与 $[10,20]$ 都够不到 21，点 21 的覆盖次数为 0，返回 `false`。
反例（见上图）：$[1,3]$ 与 $[5,6]$ 之间有缺口 4，询问 $[2,5]$ 时在 $x=4$ 处 `cur == 0`，返回 `false`——区间「相邻铺满」与「有缺口」的区分正是本题的核心判定。

## 4. 算法细节

1. **数组大小**：值域上限 50，`e + 1` 最大 51，差分数组开 52（下标 0..51）即可，`diff[51]` 只写不读（兜底防止越界）。
2. **先打全部差分标记再统一扫描**：不要边打标记边查询（那样与暴力无异）；两趟分离正是差分的意义。
3. **询问区间的判定位置**：在扫描循环里判断 `left <= x <= right`；也可扫完后单独复查，但合并进一趟更省事。
4. **重复区间 / 单点区间**：`[3,3]` 即 `diff[3]++, diff[4]--`，自动正确处理；重复区间叠加计数无影响（只判 `== 0` 与否）。
5. **为什么不用排序合并**：排序 + 合并区间再判覆盖也是 $O(L \log L)$ 的正解，但代码更长（要处理合并后的区间与 $[left,right]$ 的相交）；差分版完全无分支逻辑，是值域小时的优选。

## 5. 正确性证明

**引理 1（差分还原）**：设 `cur[x] = Σ_{y ≤ x} diff[y]`，则对区间集合施以上述差分标记后，`cur[x]` 等于包含 $x$ 的区间个数。

**证明**：对每个区间 $[s, e]$：其标记在 $y \le x$ 的累加中贡献 $+1$ 当且仅当 $s \le x$，贡献 $-1$ 当且仅当 $e + 1 \le x$。于是该区间对 `cur[x]` 的净贡献为 $\mathbb{1}[s \le x] - \mathbb{1}[e+1 \le x] = \mathbb{1}[s \le x \le e]$。由线性可加性，`cur[x]` 等于所有区间中包含 $x$ 的个数。∎

**引理 2（判定等价性）**：$[left, right]$ 内每个整数都被至少一个区间覆盖 $\iff$ 对所有 $x \in [left, right]$，`cur[x] ≥ 1`。

**证明**：由引理 1，`cur[x] ≥ 1` 即「包含 $x$ 的区间个数 ≥ 1」，即 $x$ 被覆盖。逐点等价即得区间级等价。∎

**定理**：算法返回 `true` 当且仅当 $[left, right]$ 被完全覆盖。

**证明**：算法在扫描中一旦遇到 $x \in [left, right]$ 且 `cur[x] == 0`（由引理 2 即 $x$ 未被覆盖）立即返回 `false`；若扫描完成未触发，则所有 $x \in [left, right]$ 均有 `cur[x] ≥ 1`，由引理 2 全部被覆盖，返回 `true`。两方向均成立。∎

## 6. 复杂度分析

- **时间**：$O(L + |ranges|)$，$L = 50$ 为值域上界。打标记 $O(|ranges|)$，扫描 $O(L)$，与询问区间长度无关。
- **空间**：$O(L)$。一个长度 52 的差分数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isCovered(vector<vector<int>>& ranges, int left, int right) {
        vector<int> diff(52, 0);                     // 值域 1..50，末端 51 兜底
        for (auto& r : ranges) {
            ++diff[r[0]];
            --diff[r[1] + 1];
        }
        int cur = 0;
        for (int x = 1; x <= 50; ++x) {
            cur += diff[x];
            if (left <= x && x <= right && cur == 0) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def isCovered(self, ranges: list[list[int]], left: int, right: int) -> bool:
        diff = [0] * 52                              # 值域 1..50，末端 51 兜底
        for s, e in ranges:
            diff[s] += 1
            diff[e + 1] -= 1
        cur = 0
        for x in range(1, 51):
            cur += diff[x]
            if left <= x <= right and cur == 0:
                return False
        return True
```

> 💡 两份代码均通过官方示例（`true`、`false`），并与「逐点暴力扫区间」的实现对拍 3 万组随机数据（区间数 ≤ 12、值域满范围），`mismatch = 0`。

## 8. 边界情况与易错点

1. **数组开到 52 而不是 51**：`e + 1` 在 `e = 50` 时为 51，差分数组必须能写下标 51。
2. **`right` 可能大于所有区间上界**（如示例 2 的 21 > 20）：靠 `cur == 0` 自然判 false，不要假设询问区间一定被 ranges「夹住」。
3. **缺口情形**：区间相邻 ≠ 覆盖连续（见 §3.4 反例），必须逐点确认，不能只看「区间排序后首尾相接」。
4. **差分端点方向**：`+1` 打在 $s$、`−1` 打在 $e+1$（闭区间）；写成 `e` 会把区间末端那一点的覆盖漏掉。
5. **闭区间语义**：题目是 $start_i \le x \le end_i$ 的闭覆盖，别按左闭右开处理。
6. **不要被 $left > 1$ 误导**：扫描从 1 开始没问题，也可以从 `left` 开始（`cur` 初值要先累加 $[1, left-1]$ 的差分），从 1 扫最不容易错。
