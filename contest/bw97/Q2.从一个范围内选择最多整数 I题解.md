# LeetCode 从一个范围内选择最多整数 I 题解

## 1. 题目概述

- **标题 / 题号**：从一个范围内选择最多整数 I（#2554，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-integers-to-choose-from-a-range-i/
- **来源**：LeetCode 第 97 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、哈希表、二分查找

**题意**：给定整数数组 `banned` 与整数 $n$、$maxSum$。需要选出一个整数集合，满足：所选整数都在 $[1, n]$ 内；每个整数至多选一次；所选整数不在 `banned` 中；所选整数之和不超过 $maxSum$。返回最多能选多少个整数。

**约束**：

- $1 \le banned.length \le 10^4$
- $1 \le banned[i], n \le 10^4$
- $1 \le maxSum \le 10^9$

## 2. 示例

**示例 1**

```text
输入：banned = [1,6,5], n = 5, maxSum = 6
输出：2
解释：可选 2 和 4，都在 [1,5] 内、不在 banned 中，和为 6 ≤ maxSum。
```

**示例 2**

```text
输入：banned = [1,2,3,4,5,6,7], n = 8, maxSum = 1
输出：0
解释：范围内未被禁用的整数只有 8，但 8 > maxSum = 1，一个都选不了。
```

**示例 3**

```text
输入：banned = [11], n = 7, maxSum = 50
输出：7
解释：banned 中的 11 超出 [1,7]，等于没禁用，1~7 全选，和为 28 ≤ 50。
```

**示例 4（边界补充）**

```text
输入：banned = [1], n = 1, maxSum = 1000000000
输出：0
解释：范围内唯一的整数 1 被禁用，答案为 0。
```

## 3. 解题思路

### 3.1 暴力思路

把「选哪些数」当成子集选择问题：$[1, n]$ 内未被禁用的数最多 $10^4$ 个，子集枚举 $O(2^n)$ 直接爆炸。退一步的正确暴力是**反悔贪心/背包**：按数值从小到大逐个决定选或不选，用 $dp$（容量 $maxSum \le 10^9$）不可行——容量维度太大。其实本题有极强的结构：**每个数的“代价”就是它本身**，且代价互不相同。这让「选 $c$ 个数」的最小化和变成一个与 `banned` 无关的经典问题。

### 3.2 核心观察：选 $c$ 个数的最小总和 = 从小到大取最小的 $c$ 个可用数

![核心观察：从小到大取可用数，总和增长最慢](images/bw97_q2_greedy_pick.svg)

**关键单调性**：设 $S(c)$ 为「从可用数集中选 $c$ 个数的最小可能总和」。若 $A$ 是任意 $c$ 个可用数的集合，把 $A$ 中某个数 $a$ 换成**未选中的更小可用数** $b < a$，总和严格变小。反复交换后总和最小的一定是**可用数从小到大排列的前 $c$ 个**。

于是贪心成立：**从 1 开始向上扫，遇到可用数就取、累计和、计数，一旦「再取下一个就超 $maxSum$」立即停止**。为什么停在这里是对的？因为后续任何更大的数只会让和更大（见 §5 交换论证）。

### 3.3 算法流程

![算法流程：哈希禁用集 + 从 1 向上贪心累积](images/bw97_q2_algorithm_flow.svg)

```text
1. ban ← banned 的哈希集合（只保留 ≤ n 的也行，直接全存更简单）
2. sum ← 0, cnt ← 0
3. for i = 1 .. n:
       若 i ∈ ban：跳过（不取也不终止）
       若 sum + i > maxSum：break（后面的数更大，必超）
       sum += i; cnt += 1
4. 返回 cnt
```

`banned` 的判定用 `unordered_set` $O(1)$ 完成；也可以排序 + 双指针，但没必要。

### 3.4 示例演算

**示例 1**（`banned = {1,6,5}`，$n=5$，$maxSum=6$）：

| i | 是否禁用 | sum + i | 动作 | sum | cnt |
|---|----------|---------|------|-----|-----|
| 1 | 是 | — | 跳过 | 0 | 0 |
| 2 | 否 | 2 ≤ 6 | 选入 | 2 | 1 |
| 3 | 否 | 5 ≤ 6 | 选入 | 5 | 2 |
| 4 | 否 | 9 > 6 | **break** | 5 | 2 |
| 5 | 是 | — | — | — | — |

返回 $cnt = 2$（选的是 2 与 3，示例给的是 2 与 4——两种方案都是 2 个数，题目只要数目）。

**示例 2**（`banned = {1..7}`，$n=8$，$maxSum=1$）：$i=1..7$ 全跳过；$i=8$ 时 $sum+8=8>1$，break，返回 $0$。

**示例 3**（$\text{banned} = \{11\}$，$n=7$）：$11$ 不在扫描范围内，1~7 依次选入，$sum = 28 \le 50$，返回 $7$。

## 4. 算法细节

1. **`banned` 直接全量入集合**：$banned[i]$ 可以超过 $n$（如示例 3 的 11），扫描只到 $n$，超界的禁用数自然不会被查到，无需预先过滤。
2. **`banned` 可能有重复**：`[2,2,3]` 与 `[2,3]` 禁用效果相同，哈希集合自动去重，不影响正确性。
3. **溢出**：$sum$ 单调递增，一旦 $sum + i > maxSum$ 就 break，因此 $sum \le maxSum + 10^4 < 2 \times 10^9$，**超过 32 位 `int`**（$\approx 2.1 \times 10^9$）吗？$sum$ 在加之前最大是 $maxSum \le 10^9$，加上 $i \le 10^4$ 后用于比较的中间值最多 $10^9 + 10^4$，`int` 放得下但很贴边；用 `long long` 累加最稳，Python 无此问题。
4. **break 的位置**：break 判断必须在「非禁用」判断**之后**——禁用数不参与和的比较（它根本不被选），顺序写反会把「跳过禁用数」误判成「超限终止」。
5. **复杂度与瓶颈**：扫描 $O(n)$ + 哈希构建 $O(|banned|)$，总量 $10^4$ 级别，毫秒级。若把 $n$ 放大到 $10^9$（本题 II 版 2557 的方向），就得改成「在 `banned` 排序去重后二分第 $c$ 个可用数、解 $S(c) \le maxSum$ 的最大 $c$」。
6. **另一种等价实现**：先取 $1..c$ 的前缀和 $T(c) = c(c+1)/2$，减去落在 $[1,c]$ 内的禁用数之和得到 $S(c)$，$S(c)$ 关于 $c$ 单调，可二分。本题规模下线性扫更直接。

## 5. 正确性证明

**引理 1（前 $c$ 个最优）**：设可用数集为 $A \subseteq [1, n]$。对任意 $c \ge 1$，从 $A$ 中选 $c$ 个数的最小总和等于「$A$ 从小到大排序后的前 $c$ 个数之和」$S(c)$。

**证明**：设某最优选择 $B$ 不是前 $c$ 个最小可用数。把 $A$ 排序为 $a_1 < a_2 < \dots$，则存在下标 $j \le c$ 使 $a_j \notin B$，同时存在 $a_i \in B$ 且 $i > c \ge j$（否则 $B$ 恰是前 $c$ 个）。因 $i > j$ 有 $a_i > a_j$，用 $a_j$ 替换 $a_i$ 得到仍合法（$c$ 个不同可用数）且总和严格更小的选择，与 $B$ 最优矛盾。∎

**引理 2（$S$ 的单调性）**：$S(c)$ 关于 $c$ 严格递增（$S(0) = 0$）。

**证明**：前 $c+1$ 个最小可用数 = 前 $c$ 个最小可用数 ∪ 第 $c+1$ 小的可用数 $a_{c+1} \ge 1 > 0$，故 $S(c+1) = S(c) + a_{c+1} > S(c)$。∎

**定理（贪心正确性）**：算法返回的 $cnt$ 是可选整数数目的最大值。

**证明**：记 $OPT$ 为最大可选数目。算法选出的是可用数从小到大的前 $cnt$ 个，其和 $S(cnt) \le maxSum$（算法只在 $sum + i \le maxSum$ 时选入，且每次选入的都是按序的下一个最小可用数，归纳知 $sum = S(\cdot)$），故 $cnt \le OPT$。反之取最优解 $B^*$，$|B^*| = OPT$，其和 $\ge S(OPT)$（引理 1 给出 $S$ 是 $OPT$ 个数的最小总和，$B^*$ 的和是某个 $OPT$ 个数的选择之和，必然 $\ge S(OPT)$）；若 $OPT > cnt$，由引理 2 得 $S(OPT) > S(cnt+1)$，而算法在 $cnt+1$ 步停止说明 $S(cnt+1) > maxSum$，于是 $B^*$ 的和 $> maxSum$，矛盾。故 $cnt = OPT$。∎

## 6. 复杂度分析

- **时间**：$O(|banned| + n)$。构建哈希集合 $O(|banned|)$（平均）；主循环至多扫 $n \le 10^4$ 个数，每个做一次 $O(1)$ 集合查询与累加。
- **空间**：$O(|banned|)$。哈希集合存至多 $10^4$ 个整数；其余变量 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxCount(vector<int>& banned, int n, int maxSum) {
        unordered_set<int> ban(banned.begin(), banned.end());
        long long sum = 0;
        int cnt = 0;
        for (int i = 1; i <= n; ++i) {
            if (ban.count(i)) continue;      // 禁用数：跳过但不终止
            if (sum + i > maxSum) break;     // 更大的数只会更超，直接停
            sum += i;
            ++cnt;
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def maxCount(self, banned: List[int], n: int, maxSum: int) -> int:
        ban = set(banned)
        total = cnt = 0
        for i in range(1, n + 1):
            if i in ban:
                continue
            if total + i > maxSum:
                break
            total += i
            cnt += 1
        return cnt
```

> 💡 两份代码均通过官方示例（`2`、`0`、`7`）及「唯一可用数被禁用」「`maxSum` 极大」等边界。

## 8. 边界情况与易错点

1. **`banned` 含超界值与重复值**：`banned[i] > n` 无副作用；重复禁用数在集合中自动去重。两种情况都不需要预处理。
2. **溢出贴边**：比较用的中间量 $sum + i$ 最多 $10^9 + 10^4$，32 位 `int` 理论上够，但 `long long` 累加更稳（尤其后续 II 版本 $n$ 到 $10^9$ 时必爆）。
3. **break 与 continue 的顺序**：先判禁用（continue），再判超限（break）。若先判 $sum + i > maxSum$ 就 break，遇到「禁用数恰好在临界处」会提前终止，少算合法选择。
4. **禁用数不占预算**：`banned` 中的数只是**不可选**，不消耗 `maxSum`，不要把它们从 `maxSum` 里扣。
5. **`maxSum` 大到全选**：$n = 10^4$ 全选时和为 $n(n+1)/2 \approx 5 \times 10^7$，远小于 $10^9$，常见于「看似要优化实则全取」的样例（如示例 3）。
6. **答案为 0**：`n` 内所有数被禁用，或最小可用数已超 `maxSum`；算法自然返回 0，无需特判。
