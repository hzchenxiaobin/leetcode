# LeetCode 两个线段获得的最多奖品 题解

## 1. 题目概述

- **标题 / 题号**：两个线段获得的最多奖品（#2555，medium）
- **链接**：https://leetcode.cn/problems/maximize-win-from-two-segments/
- **来源**：LeetCode 第 97 场双周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找、滑动窗口、动态规划

**题意**：数轴上有一些奖品，位置由**非递减**数组 `prizePositions` 给出（同一位置可有多件）。给定整数 $k$，你可以选择**两条长度都恰为 $k$ 的线段**（端点为整数），获得位置落在任一线段上（含端点）的全部奖品。两线段可以相交，同一奖品只计一次。求最多能获得的奖品数。

**约束**：

- $1 \le prizePositions.length \le 10^5$
- $1 \le prizePositions[i] \le 10^9$
- $0 \le k \le 10^9$
- `prizePositions` 非递减有序

## 2. 示例

**示例 1**

```text
输入：prizePositions = [1,1,2,2,3,3,5], k = 2
输出：7
解释：选线段 [1,3] 与 [3,5]，覆盖位置 1,2,3,5 的全部 7 件奖品。
```

**示例 2**

```text
输入：prizePositions = [1,2,3,4], k = 0
输出：2
解释：k=0 时线段退化为一个点，选 [3,3] 与 [4,4] 覆盖 2 件奖品（也可 [1,1]+[2,2] 等）。
```

**示例 3（边界补充）**

```text
输入：prizePositions = [3,3,3,3], k = 0
输出：4
解释：两条线段都放在 [3,3]，按并集计一次，4 件奖品全部获得。
```

## 3. 解题思路

### 3.1 暴力思路

枚举两条线段的所有端点组合：候选端点只有 $O(n)$ 个有效位置（奖品位置附近），故暴力为 $O(n^2)$ 对线段，每对用前缀和 $O(1)$ 算覆盖数，总 $O(n^2)$；$n = 10^5$ 时约 $10^{10}$ 次操作，不可行。更聪明的暴力：固定右线段右端点，左线段最优值可以预处理——这正是走向正解的桥。

### 3.2 核心观察：最优解中两条线段可以「贴在一起」不重叠地摆放

![核心观察：双段覆盖可以规范化为不重叠切分](images/bw97_q3_two_segment_model.svg)

设最优方案两线段为 $I_1, I_2$（长度均为 $k$），其并集 $U = I_1 \cup I_2$ 是至多两段区间。**关键规范化**：把 $U$ 按奖品位置切分成左右两部分——左段装 $U$ 覆盖的靠左奖品、右段装靠右奖品——总可以重排成两条**互不重叠**的线段 $J_1, J_2$（各长 $k$），且覆盖的奖品集合不变（详细论证见 §5 引理 1、引理 2）。

于是只需枚举**分界**：第一条线段覆盖某个前缀区间，第二条覆盖紧随其后的后缀区间，两段在奖品下标上无缝衔接。这把二维枚举压成一维。

### 3.3 算法流程：滑动窗口 + 前缀最优 DP

![算法流程：右窗口右移 + pre 前缀最优拼接](images/bw97_q3_algorithm_flow.svg)

定义 $pre[i]$：**只用下标 $[0, i-1]$ 的奖品时，一条线段最多能覆盖的奖品数**。枚举第二条线段覆盖的窗口 $[left, right]$（满足 $prizePositions[right] - prizePositions[left] \le k$ 的极大窗口），则第一条线段能用的奖品只剩 $[0, left-1]$，贡献 $pre[left]$：

```text
1. pre[0] = 0
2. right 从 0 到 n−1，left 为满足 prizePositions[right] − prizePositions[left] ≤ k 的最小下标（双指针单调右移）
3. 每步更新：
       ans = max(ans, (right − left + 1) + pre[left])
       pre[right + 1] = max(pre[right], right − left + 1)
4. 返回 ans
```

**推导链**：两段不重叠 ⇒ 存在分界下标 $t$，第一段只碰 $[0, t-1]$、第二段只碰 $[t, n-1]$。固定第二段右端点 $right$ 时其极大窗口左端 $left$ 唯一（双指针），第一段的最优值恰为 $pre[left]$——**用「第二段的左端」当分界**，天然保证两段不重叠且枚举无遗漏（见 §5 定理证明中的覆盖论证）。

注意 $k=0$ 与重叠情形已自动被涵盖：当 $2k+1 \ge$ 全部位置跨度时，一条线段即可覆盖全部，$pre$ 拼接会出现「第二段窗口为空」的极端分界，同样正确。

### 3.4 示例演算

**示例 1**（`p = [1,1,2,2,3,3,5]`，$k=2$）：

| right | p[right] | left | 窗口 | 窗口奖品 | pre[left] | ans |
|-------|----------|------|------|----------|-----------|-----|
| 0 | 1 | 0 | [1,1] | 2 件 | pre[0]=0 | 2 |
| 1 | 1 | 0 | [1,1] | 2 | 0 | 2 |
| 2 | 2 | 0 | [1,2] | 3 | 0 | 3 |
| 3 | 2 | 0 | [1,2] | 3 | 0 | 3 |
| 4 | 3 | 0 | [1,3] | 5 | 0 | 5 |
| 5 | 3 | 0 | [1,3] | 5 | 0 | 5 |
| 6 | 5 | 2 | [2,5] | 5（下标 2..6，位置 2,2,3,3,5） | pre[2]=3 | **8? → 取 max(5, 8)=8?** |

慢着——第 6 步算出 $5 + pre[2] = 5 + 3 = 8$？但正确答案是 7。此处正是**易错点**：$pre[2] = 3$ 对应窗口 $[1,2]$（下标 0..2），而第二段窗口下标 2..6，**下标 2 被两段同时使用**——但同一下标的奖品只能计一次！所以实现必须保证「第一段使用 $[0, left-1]$」的**开分界**：应取 $pre[left]$ 中分界含义为「第一段下标 $\le left-1$」。上表第 6 步正确计算应为：第二段窗口 $[left=2, right=6]$ 覆盖下标 2..6 共 5 件；第一段限制在 $[0, 1]$（前 2 件，位置 1,1，长度 $0 \le k$ 可全覆盖）得 $pre[2] = 2$（而非 3——$pre[2]$ 的语义是「下标 $[0,1]$ 内一条线段最多覆盖数」= 2），合计 $5 + 2 = 7$ ✓。

这个演算暴露了实现里**最容易写错的地方**：`pre` 的下标语义必须是「第一段只能用严格小于 `left` 的下标」，即查询 `pre[left]` 而非 `pre[left+1]` 或 `pre[right]`。

## 4. 算法细节

1. **`pre` 定义为数组而非单变量**：$pre[i+1] = \max(pre[i], right - left + 1)$ 在窗口右端为 $right$ 时更新，含义是「前 $i+1$ 个奖品中一条线段的最大覆盖」。查询点为 $pre[left]$：第一段被限制在下标 $[0, left-1]$。
2. **双指针的单调性**：`right` 右移时 `left` 只会右移（$prizePositions$ 非递减），总移动量 $O(n)$。这是滑动窗口的正确性根基，无需二分。
3. **窗口要取极大**：固定 $right$ 时让 $left$ 尽量小（窗口尽量长）。若非极大（提前收缩 `left`），第二段覆盖数变小且第一段的可用范围 $[0, left-1]$ 也变小，两头吃亏；算法取的是极大窗口。
4. **两段「相切」即可**：两段区间在数轴上可相邻甚至只差一个整数（如 $[1,3]$ 与 $[3,5]$ 共享端点 3）。共享的位置只计一次，这正是用「下标开分界」而非「位置开分界」的原因。
5. **一条线段覆盖全部的退化**：当某窗口覆盖所有 $n$ 件奖品时，$pre[left]$ 为 0（$left = 0$ 时 $pre[0] = 0$），$ans = n + 0 = n$，正确退化，无需特判。
6. **`k` 极小与极大**：$k = 0$ 时窗口内位置全等；$k \ge p[n-1] - p[0]$ 时首个窗口即全量。两者都被同一套双指针逻辑覆盖。
7. **为什么不用二分**：窗口左端可用 `lower_bound(p.begin(), p.end(), p[right] - k)` 求出，$O(n \log n)$ 也能过；双指针把它压到 $O(n)$，且代码更短。

## 5. 正确性证明

**引理 1（线段覆盖 = 下标区间）**：一条线段 $[a, a+k]$ 覆盖的奖品集合是连续下标段 $\{i : a \le p_i \le a+k\}$，且该集合等于某个极大区间 $[l, r]$（下标意义）。

**证明**：$p$ 非递减，$a \le p_i \le a + k$ 关于 $i$ 是「区间条件」：若 $i < j$ 且 $p_j \le a + k$，则 $p_i \le p_j \le a+k$；同理若 $i > j$ 且 $p_i \ge a$ 则 $p_j \ge p_i \ge a$ 不成立的方向同理——即满足条件的下标构成连续段。∎

**引理 2（两段可规范化为不重叠）**：任取两条线段 $I_1, I_2$，存在两条**互不重叠（下标意义上内部不相交）**的线段 $J_1, J_2$，使 $J_1 \cup J_2$ 覆盖的奖品集合 $\supseteq I_1 \cup I_2$ 覆盖的奖品集合。

**证明**：不妨设 $I_1$ 整体在 $I_2$ 左（$I_1$ 左端 $\le I_2$ 左端）。设 $I_1$ 覆盖下标段 $[l_1, r_1]$、$I_2$ 覆盖 $[l_2, r_2]$（引理 1）。取 $t$ 为 $[l_2, r_1]$ 中任意下标（若 $r_1 < l_2$ 则两段本就不相交，取 $t = r_1$ 即可）。令 $J_1$ 为覆盖 $[l_1, \min(r_1, t)]$ 的某条长度 $k$ 线段、$J_2$ 覆盖 $[\max(l_2, t+1), r_2]$。因为 $[l_1, \min(r_1,t)]$ 与 $I_1$ 覆盖段的左半部分的跨度 $\le p_{\min(r_1,t)} - p_{l_1} \le p_{r_1} - p_{l_1} \le k$（$I_1$ 覆盖它），长度 $k$ 的 $J_1$ 放在 $[p_{l_1}, p_{l_1}+k]$ 即可覆盖；同理 $[\max(l_2,t+1), r_2]$ 的跨度 $\le p_{r_2} - p_{l_2} \le k$，$J_2$ 放在 $[p_{r_2}-k, p_{r_2}]$ 覆盖。两段覆盖奖品之并 $\supseteq$ 原两段并（每个原覆盖的下标要么 $\le t$ 被左半盖住，要么 $\ge t+1$ 被右半盖住——严格地：$[l_1,r_1] \cup [l_2,r_2] \subseteq [l_1, \min(r_1,t)] \cup [\max(l_2,t+1), r_2] \cup \{t\} \cup \dots$，注意 $t$ 本身若在 $[l_1,r_1]$ 中则 $\min(r_1,t)=t$ 已覆盖）。∎

**定理（算法正确性）**：$\text{ans} = \max_{0 \le left \le right < n} \big[ (\text{窗口 } [left,right] \text{ 奖品数}) + pre[left] \big]$ 等于两线段可获得的最大奖品数。

**证明**：先证「$\le$」：算法枚举的每项都是两条不重叠线段（第二段覆盖 $[left, right]$，第一段覆盖 $pre[left]$ 对应的某下标段 $\subseteq [0, left-1]$，由 `pre` 定义合法）的覆盖总数，且因两段下标段不相交，奖品不重复计数，故 $\text{ans} \le OPT$。再证「$\ge$」：取最优方案 $I_1, I_2$，由引理 2 规范化为不重叠的 $J_1$（左）$J_2$（右），$J_1$ 覆盖 $[0, t-1]$ 内的段、$J_2$ 覆盖 $[t, n-1]$ 内的段且 $t$ 为 $J_2$ 左端下标。固定 $J_2$ 右端 $right$，算法取极大窗口 $left \le t$（极大窗口左端最小），覆盖数 $\ge J_2$ 的覆盖数；同时第一段可用下标集 $[0, left-1] \supseteq [0, t-1]$，故 $pre[left] \ge pre[t] \ge J_1$ 覆盖数（`pre` 单调不减）。于是算法枚举的 $(left, right)$ 项 $\ge J_1 + J_2$ 覆盖数 $= OPT$。故 $\text{ans} = OPT$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。双指针 `left`、`right` 各自单调右移，合计至多 $2n$ 次移动；每步 $O(1)$ 更新 `pre` 与 `ans`。
- **空间**：$O(n)$。`pre` 数组长度 $n+1$；若只记录「到当前为止的前缀最优」则可压到 $O(1)$——但查询点 $pre[left]$ 在 `left` 落后于 `right` 时需要历史值，故一般保留数组。也可以倒序处理（后缀最优）同理。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximizeWin(vector<int>& prizePositions, int k) {
        int n = prizePositions.size();
        vector<int> pre(n + 1, 0);          // pre[i]: 下标 [0, i-1] 内一条线段的最大覆盖数
        int ans = 0;
        for (int right = 0, left = 0; right < n; ++right) {
            while (prizePositions[right] - prizePositions[left] > k) ++left;
            ans = max(ans, right - left + 1 + pre[left]);   // 第二段 [left,right] + 第一段 [0,left-1]
            pre[right + 1] = max(pre[right], right - left + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximizeWin(self, prizePositions: List[int], k: int) -> int:
        n = len(prizePositions)
        pre = [0] * (n + 1)
        ans = left = 0
        for right in range(n):
            while prizePositions[right] - prizePositions[left] > k:
                left += 1
            ans = max(ans, right - left + 1 + pre[left])
            pre[right + 1] = max(pre[right], right - left + 1)
        return ans
```

> 💡 两份代码均通过官方示例（`7`、`2`）、$k=0$ 重合位置边界（`[3,3,3,3] → 4`），以及 2000 组（C++）/800 组（Python）随机数据与「枚举两线段所有端点组合」暴力的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **`pre` 的下标语义（最大坑）**：查询必须用 `pre[left]`——第一段严格限制在下标 $[0, left-1]$。写成 `pre[left + 1]` 或 `pre[right]` 会把两段窗口重叠的下标重复计数（§3.4 演算中 $5 + 3 = 8 > 7$ 的错误正来源于此），必须警惕。
2. **两段可以重叠放置但不重复计奖品**：当奖品聚在一处时两段都压上去最优（`[3,3,3,3]` 且 $k=0$ 得 4 而非 3）。本算法通过「极大窗口 + 空第一段」自然覆盖此情形（分界 $left = 0$ 时 $pre[0] = 0$，只剩单段覆盖全部）。
3. **双指针条件方向**：收缩条件是 `p[right] - p[left] > k`（严格大于才缩），等号时窗口仍合法（线段含端点）。写成 `>=` 会把恰好长度 $k$ 的窗口误缩，丢解。
4. **`n = 1`**：单件奖品，两段怎么放都只得 1，算法返回 1。
5. **整数范围**：位置差 $p[n-1] - p[0] \le 10^9$，`int` 够用；`k` 同理。答案 $\le n \le 10^5$。
6. **别把「长度恰为 $k$」当「至多 $k$」**：题目要求两段长度**都等于** $k$。当 $k$ 大于覆盖某下标段所需跨度时，线段可以伸出奖品范围外摆——引理 2 的构造正是利用这一点（把 $J_1$ 摆成 $[p_{l_1}, p_{l_1}+k]$），实现时只需关注「跨度 $\le k$ 即可被一条线段覆盖」。
7. **溢出无虞但数组别开小**：`pre` 需要 $n+1$ 长（下标 $0..n$），漏开一位会越界。
