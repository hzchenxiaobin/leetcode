# LeetCode 分数验证器 题解

## 1. 题目概述

- **标题 / 题号**：分数验证器（#3921，easy）
- **链接**：https://leetcode.cn/problems/score-validator/
- **来源**：LeetCode 第 182 场双周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、模拟

**题意**：初始 `score = 0`、`counter = 0`，从左到右处理字符串数组 `events`，每个元素的含义是：

- `"0"`、`"1"`、`"2"`、`"3"`、`"4"`、`"6"`：把该数值**加到 score**；
- `"W"`：**counter 加 1**，score 不变；
- `"WD"`、`"NB"`：**score 加 1**，counter 不变。

处理过程中，一旦**所有元素处理完**或 **counter 变成 10**，就立即停止。返回 `[score, counter]`。

**约束**：

- $1 \le events.length \le 1000$
- `events[i]` 是 `"0"`、`"1"`、`"2"`、`"3"`、`"4"`、`"6"`、`"W"`、`"WD"`、`"NB"` 之一

## 2. 示例

**示例 1**

```text
输入：events = ["1","4","W","6","WD"]
输出：[12,1]
解释：1 → score=1；4 → 5；W → counter=1；6 → 11；WD → 12。
```

**示例 2**

```text
输入：events = ["WD","NB","0","4","4"]
输出：[10,0]
解释：1 + 1 + 0 + 4 + 4 = 10，全程没有 W，counter 保持 0。
```

**示例 3**

```text
输入：events = ["W","W","W","W","W","W","W","W","W","W","W"]
输出：[0,10]
解释：第 10 个 "W" 让 counter 变成 10，立即停止；多余的第 11 个被忽略。
```

## 3. 解题思路

### 3.1 暴力思路

本题没有「更优算法」的余地：题面就是一段**逐条执行的规则**，任何解法都至少要看一遍事件（除非提前停）。所以「暴力」= 按题意模拟，时间复杂度 $O(n)$，$n \le 1000$ 时最多千次操作——这就是最优解。真正的考点是**规则细节**：哪些事件加什么、什么时候停。

### 3.2 核心观察：两个独立累加器 + 一个提前退出

![分数验证器：9 种事件，两个计数器](images/bw182_q1_event_rules.svg)

- **两个计数器互不干扰**：`score` 只受数字事件与 `WD`/`NB` 影响；`counter` 只受 `W` 影响。所以不存在「加错人」的复杂状态。
- **停止条件是「变成 10」而不是「超过 10」**：`counter` 只会在遇到 `"W"` 时 $+1$，因此它不会跳过 10，判断 `counter == 10` 即可；写成 `>= 10` 也更安全。
- **停止的时机**：第 10 个 `"W"` **本身**计入 counter（它使 counter 从 9 变 10），之后的事件全部忽略。示例 3 的答案是 `[0, 10]` 而不是 `[0, 9]`，正是这个细节。
- **数字事件的取值**：只有 6 种（0/1/2/3/4/6），可以用 `stoi`/`int(e)` 转换，也可以利用「单字符事件」用 `e[0] - '0'` 直接取数值——后者更快且天然覆盖 `"0"`。

### 3.3 算法流程

![示例演算：逐事件推进，以及 counter 到 10 的提前终止](images/bw182_q1_walkthrough.svg)

```text
1. score = 0，counter = 0
2. for e in events:
     if e == "W":      counter += 1；若 counter == 10 则 break
     elif e == "WD" 或 e == "NB":  score += 1
     else:             score += int(e)          // "0" "1" "2" "3" "4" "6"
3. 返回 [score, counter]
```

### 3.4 示例演算

示例 1 的逐步状态：

| 事件 | score | counter |
|------|-------|---------|
| `"1"` | 1 | 0 |
| `"4"` | 5 | 0 |
| `"W"` | 5 | 1 |
| `"6"` | 11 | 1 |
| `"WD"` | 12 | 1 |

结果 `[12, 1]`。示例 2 没有 `W`，counter 恒为 0，score 为 $1+1+0+4+4 = 10$；示例 3 在第 10 个 `W` 处提前退出，结果为 `[0, 10]`。

## 4. 算法细节

1. **`"W"` 与 `"WD"` 都要先判**：`"WD"` 的第一个字符也是 `W`，若用「首字符是 `W`」来分类会把 `WD` 误判成 `W`。必须按完整字符串比较。
2. **`"0"` 是合法事件**：加 0 分，别把它当成「空事件」跳过——虽然结果不变，但跳过会让人误以为有特殊处理。
3. **提前退出的位置**：`counter` 一到 10 就 `break`，不必等循环结束；否则示例 3 会把第 11 个 `W` 也处理，counter 变成 11。
4. **返回的是数组**：C++ 用 `return {score, counter};`，Python 用 `return [score, counter]`。
5. **不需要额外空间**：两个整型变量 + 结果数组，$O(1)$ 辅助空间。

## 5. 正确性证明

**引理 1（事件分类完备且互斥）**：算法的三个分支恰好覆盖题面允许的 9 种事件，且每个事件只落入一个分支。

**证明**：题面事件集合为 $\{"0","1","2","3","4","6","W","WD","NB"\}$。分支 1 精确匹配 `"W"`；分支 2 精确匹配 `"WD"` 与 `"NB"`；其余 6 种单字符数字事件落入分支 3。三个分支的匹配条件互不相同，故互斥且完备。∎

**引理 2（分数语义正确）**：每次循环结束时，`score` 等于「已处理的数字事件与 `WD`/`NB` 事件对得分的贡献之和」，`counter` 等于「已处理的 `W` 事件个数」。

**证明**：对处理的事件数归纳。分支 3 按题面把数值加入 score，分支 2 加 1，分支 1 只加 counter，均与题面逐条对应；归纳假设在加入当前事件后仍成立。∎

**定理**：算法返回 `[score, counter]`，且是题面规定的「停止时刻」的状态。

**证明**：由引理 1、2，循环中每一步的状态都与题面一致。停止条件有二：循环走完（对应「所有元素处理完」）；或在 `counter` 变成 10 时 `break`（对应「counter 变为 10」）。由引理 2，`break` 时 counter 恰为 10、score 恰为前序贡献之和，故返回的是停止时刻的正确状态。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每个事件 $O(1)$ 处理；提前退出只会更快。
- **空间**：$O(1)$ 额外空间（不计返回的 2 元素数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> scoreValidator(vector<string>& events) {
        int score = 0, counter = 0;
        for (auto& e : events) {
            if (e == "W") {
                if (++counter == 10) break;
            } else if (e == "WD" || e == "NB") {
                score += 1;
            } else {
                score += e[0] - '0';
            }
        }
        return {score, counter};
    }
};
```

### Python

```python
class Solution:
    def scoreValidator(self, events: list[str]) -> list[int]:
        score = 0
        counter = 0
        for e in events:
            if e == "W":
                counter += 1
                if counter == 10:
                    break
            elif e in ("WD", "NB"):
                score += 1
            else:
                score += int(e)
        return [score, counter]
```

## 8. 边界情况与易错点

1. **`"WD"` 被误判为 `"W"`**：这是最典型的 WA。必须先比较 `"W"` 全等，或用长度判断后再分派。
2. **第 10 个 `"W"` 要计入**：counter 应为 10（不是 9），且停止后不再处理后续事件（示例 3）。
3. **不足 10 个 `"W"`**：正常走完所有事件，counter 保留实际值（示例 1 返回 1）。
4. **全数字事件没有 `W`**：counter 恒 0，`[score, 0]` 合法（示例 2）。
5. **`"0"` 事件**：加 0 分，不影响结果，但确实会「消耗」一个事件位置。
6. **score 上界**：最多 1000 个 `"6"`，即 6000，`int` 足够。
7. **字符串比较开销**：$n \le 1000$ 可以忽略；若 $n$ 放大到 $10^6$，可先按首字符与长度做一次分派，把 `"W"`、`"WD"`、`"NB"`、数字区分开。
