# LeetCode 得到目标点的最少代数 题解

## 1. 题目概述

- **标题 / 题号**：得到目标点的最少代数（#3923，medium）
- **链接**：https://leetcode.cn/problems/minimum-generations-to-target-point/
- **来源**：LeetCode 第 182 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：给定三维点集 `points` 与目标点 `target`。第 0 代就是初始点集。对 $k \ge 1$，第 $k$ 代这样产生：

- 从**第 0 代到第 $k-1$ 代产生的所有点**中任取两个**坐标不同**的点 $a, b$；
- 计算 $c = \left(\left\lfloor \frac{a_x + b_x}{2} \right\rfloor, \left\lfloor \frac{a_y + b_y}{2} \right\rfloor, \left\lfloor \frac{a_z + b_z}{2} \right\rfloor\right)$；
- 把所有这样的 $c$ 收集起来，就是第 $k$ 代（同一代内的点**同时**由前代产生，不能互相配对）。

求 `target` 首次出现的**最小代数** $k$；已在初始点集中返回 0；永远无法产生返回 $-1$。

**约束**：

- $1 \le points.length \le 20$，初始点集无重复
- $0 \le x_i, y_i, z_i \le 6$，$target$ 的三个坐标也都在 $[0, 6]$

## 2. 示例

**示例 1**

```text
输入：points = [[0,0,0],[6,6,6]], target = [3,3,3]
输出：1
解释：第 1 代用这两个点配对，floor((0+6)/2) = 3，直接得到 [3,3,3]。
```

**示例 2**

```text
输入：points = [[0,0,0],[5,5,5]], target = [1,1,1]
输出：2
解释：第 1 代只得到 [2,2,2]（floor(5/2) = 2）；第 2 代用 [0,0,0] 与 [2,2,2]
     配对得 floor(2/2) = 1，即 [1,1,1]，故答案 2。
```

**示例 3**

```text
输入：points = [[0,0,0],[2,2,2],[3,3,3]], target = [2,2,2]
输出：0
解释：target 已在第 0 代中。
```

**示例 4**

```text
输入：points = [[1,2,3]], target = [5,5,5]
输出：-1
解释：只有一个点，无法配对，永远产生不出新点。
```

## 3. 解题思路

### 3.1 暴力思路

直接模拟每一代：维护「当前可用点集」$S$，每代枚举 $S$ 中的全部点对算出新点。由于坐标恒在 $[0, 6]$，「点」最多只有

$$7 \times 7 \times 7 = 343$$

个。每代最多 $\binom{343}{2} \approx 5.9 \times 10^4$ 次配对，单次 $O(1)$，一代不到 $10^5$ 次操作——**直接模拟就是正解**。真正的关键不是优化，而是把「何时停止」想清楚。

### 3.2 核心观察：状态集合单调增长，且被 343 个格点卡住

![逐代生成：示例 2 的演化过程](images/bw182_q3_generation.svg)

- **集合只会变大**：第 $k$ 代基于前 $k-1$ 代的**并集**生成，所有旧点仍然可用，因此 $S_0 \subseteq S_1 \subseteq S_2 \subseteq \cdots$。
- **坐标不会越界**：若所有点的每个坐标都在 $[0, 6]$，则 $\lfloor (a+b)/2 \rfloor$ 也在 $[0, 6]$（两个 $[0,6]$ 内整数的平均向下取整仍在该区间）。所以候选点总数不超过 343，**集合最多增长 343 次**。
- **终止判定**：如果某一代**没有产生任何新点**，则集合不再变化，下一代的点集与这一代完全相同（同样的输入产生同样的输出），于是**永远**不会出现新点。此时若 target 仍不在集合中，答案就是 $-1$。
- **同步性**：第 $k$ 代内部点不能互相配对。实现上就是「先用上一代的集合算出整代新点，再一次性并入」，不能边算边并入。

### 3.3 算法流程

![终止性：状态集合单调增长且被 343 个格点卡住](images/bw182_q3_closure.svg)

```text
1. 用编码 (x*7 + y)*7 + z 把点压成 0..342 的整数，存入 have[]，并把初始点放入 cur 列表
2. 若 target 已在 have 中：返回 0
3. for gen = 1, 2, 3, …:
     fresh = []
     for cur 中每一对不同的点 (a, b):
         c = floor 平均值（逐坐标）
         若 c 既不在 have 也不在本代 fresh 中：加入 fresh
     若 fresh 为空：返回 -1                 // 集合已封闭
     把 fresh 全部标记进 have 并加入 cur
     若 have[target]：返回 gen
```

### 3.4 示例演算

示例 2（`[[0,0,0],[5,5,5]]` → `[1,1,1]`）：

| 代 | 可用点集 | 本代新点 | target 是否出现 |
|----|----------|----------|------------------|
| 0 | {[0,0,0], [5,5,5]} | — | 否 |
| 1 | 加入 [2,2,2] | [2,2,2] | 否 |
| 2 | 加入 [1,1,1]、[3,3,3] | [1,1,1]、[3,3,3] | **是** → 返回 2 |

注意第 2 代中 `[5,5,5]` 与 `[0,0,0]` 再次配对仍得到 `[2,2,2]`，它已在集合中，因此不计入 `fresh`——这正是「是否还有新点」的判据。

## 4. 算法细节

1. **编码**：坐标 $\le 6$，用 `(x*7 + y)*7 + z` 编码，值域 $[0, 342]$，用 `vector<char> have(343)` 做 $O(1)$ 查重，比 `set<tuple>` 快一个量级。
2. **去重**：初始点集无重复（题面保证），但仍建议用 `have` 判重后再入列，避免重复点导致「同坐标不能配对」的语义出错。
3. **配对只遍历下标对**：`for i < j`，天然满足「两个不同的点」且不重复配对。
4. **逐坐标 floor**：C++ 中非负整数直接 `(ax + bx) / 2` 即向下取整；Python 用 `//`（非负时与 `floor` 一致，本题坐标非负，安全）。
5. **本代内去重**：`nxt[]` 标记本代已生成的点，避免 `fresh` 里出现大量重复。
6. **终止上界**：至多 $343 - |S_0|$ 代会产生新点，不会死循环；循环上界写 `343` 或 `400` 都可。

## 5. 正确性证明

**引理 1（坐标不越界）**：若所有可用点的每个坐标都在 $[0, 6]$，则任意配对产生的 $c$ 的每个坐标也在 $[0, 6]$。

**证明**：设 $a, b \in [0, 6]$，则 $0 \le \lfloor (a+b)/2 \rfloor \le 6$（非负数之和的一半向下取整仍在 $[0,6]$ 内，因为 $\lfloor (a+b)/2 \rfloor \le \lfloor 12/2 \rfloor = 6$）。逐坐标成立。∎

**引理 2（同步生成正确）**：算法第 `gen` 轮加入的 `fresh` 恰好等于题面定义的第 `gen` 代点集与旧集合的差集。

**证明**：本轮用 `cur`（即第 $0$ 至 `gen-1` 代的并集）中所有点对生成候选，符合「第 `gen` 代由前 `gen` 代的所有点配对产生」；因为 `fresh` 在整轮枚举结束后才并入 `cur`，本轮内新点不会互相配对，符合「同代点同时产生」的同步语义。剔除已在 `have` 中的点，正是与旧集合的差集。∎

**引理 3（封闭性）**：若某一代 `fresh` 为空，则此后所有代的点集都不变。

**证明**：`fresh` 为空意味着「对当前集合的所有点对取平均」得到的结果全部已在集合中，即 $f(S) \subseteq S$。由于集合单调不减，下一代的输入仍是 $S$，输出仍为 $f(S) \subseteq S$，故集合不再变化，对任意 $k$ 都成立。∎

**定理**：算法返回最小的 $k$ 使 target 出现在第 $0$ 至第 $k$ 代中；若始终不出现则返回 $-1$。

**证明**：

- 若 target 在初始集合，返回 0，显然最小。
- 否则每轮结束时检查 `have[target]`，返回的 `gen` 是 target 首次被加入的那一代（由引理 2，加入即出现在该代），而更早的代数都检查过且未命中，故为最小 $k$。
- 若某轮 `fresh` 为空（引理 3），此后集合不再变化，target 永远不会出现，返回 $-1$ 正确。

∎

## 6. 复杂度分析

- **时间**：至多 $343$ 轮；每轮枚举当前集合的点对，最多 $\binom{343}{2} \approx 5.9\times10^4$ 对，每对 $O(1)$，故最坏 $O(343 \times 343^2) \approx 4\times10^7$ 次基本操作——但实际因集合远小于 343、且往往几十轮内就封闭，运行只需毫秒级。
- **空间**：$O(343)$ 的 `have` 标记 + $O(343)$ 的点列表，常数极小（编码后是整型数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minGenerations(vector<vector<int>>& points, vector<int>& target) {
        auto enc = [](int x, int y, int z) { return (x * 7 + y) * 7 + z; };
        vector<char> have(343, 0);
        vector<int> cur;
        for (auto& p : points) {
            int code = enc(p[0], p[1], p[2]);
            if (!have[code]) { have[code] = 1; cur.push_back(code); }
        }
        int t = enc(target[0], target[1], target[2]);
        if (have[t]) return 0;
        for (int gen = 1; gen <= 400; gen++) {
            vector<char> nxt(343, 0);
            vector<int> fresh;
            for (size_t i = 0; i < cur.size(); i++) {
                int a = cur[i];
                int ax = a / 49, ay = a / 7 % 7, az = a % 7;
                for (size_t j = i + 1; j < cur.size(); j++) {
                    int b = cur[j];
                    int code = enc((ax + b / 49) / 2, (ay + b / 7 % 7) / 2, (az + b % 7) / 2);
                    if (!have[code] && !nxt[code]) { nxt[code] = 1; fresh.push_back(code); }
                }
            }
            if (fresh.empty()) return -1;
            for (int c : fresh) { have[c] = 1; cur.push_back(c); }
            if (have[t]) return gen;
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def minGenerations(self, points: list[list[int]], target: list[int]) -> int:
        cur = {tuple(p) for p in points}
        t = tuple(target)
        if t in cur:
            return 0
        k = 0
        while True:
            k += 1
            pts = list(cur)
            nxt = set()
            for i in range(len(pts)):
                a = pts[i]
                for j in range(i + 1, len(pts)):
                    b = pts[j]
                    nxt.add(((a[0] + b[0]) // 2, (a[1] + b[1]) // 2, (a[2] + b[2]) // 2))
            fresh = nxt - cur
            cur |= nxt
            if t in cur:
                return k
            if not fresh:
                return -1
```

## 8. 边界情况与易错点

1. **只有一个初始点**：无法配对，`fresh` 为空，返回 $-1$（示例 4）。若 target 就是这个点，则返回 0。
2. **同步性**：第 $k$ 代中两两配对**只能用前 $k$ 代的点**，不能用同代新点。实现上必须「算完一整代再并入」；边算边并入会得到比正确答案更小的 $k$。
3. **`floor` 而非四舍五入**：`(5+0)/2` 在整数除法下是 2，不是 3。用浮点 `round` 会直接算错（示例 2 的答案 2 就依赖 floor）。
4. **「不同的点」指坐标不同**：初始点集保证无重复，但不同代可能产生相同坐标；用 `have` 判重后，集合内不会有重复点，配对时用下标 `i < j` 即可。
5. **终止而非死循环**：必须有「`fresh` 为空 → $-1$」的分支，否则集合封闭时会无限循环。循环次数上界取 343（格点总数）即可，写 400 更保险。
6. **target 已在初始集合**：先判 0，避免多余的一代计算（示例 3）。
7. **编码的进制**：坐标 $\le 6$ 是 7 个取值，编码用 7 进制；若误用 6 会冲突。
