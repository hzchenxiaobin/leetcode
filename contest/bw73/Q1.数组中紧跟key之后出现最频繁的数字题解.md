# LeetCode 数组中紧跟 key 之后出现最频繁的数字 题解

## 1. 题目概述

- **标题 / 题号**：数组中紧跟 key 之后出现最频繁的数字（#2190，easy）
- **链接**：https://leetcode.cn/problems/most-frequent-number-following-key-in-an-array/
- **来源**：LeetCode 第 73 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定下标从 0 开始的整数数组 `nums` 和整数 `key`（`key` 保证在 `nums` 中出现过）。统计所有「紧跟在 `key` 后面」出现的整数：若存在下标 $i$ 满足 $0 \le i \le n-2$、`nums[i] == key` 且 `nums[i+1] == target`，则这一次出现计入 `target` 的次数。返回出现次数最多的 `target`（题目保证答案唯一）。

**约束**：

- $2 \le nums.length \le 1000$
- $1 \le nums[i] \le 1000$
- `key` 在 `nums` 中出现过；出现次数最多的 `target` 唯一

## 2. 示例

**示例 1**

```text
输入：nums = [1,100,200,1,100], key = 1
输出：100
解释：i = 0 时 nums[1] = 100，i = 3 时 nums[4] = 100，target = 100 共出现 2 次；
     没有其他整数紧跟在 key 后面出现，故返回 100。
```

**示例 2**

```text
输入：nums = [2,2,2,2,3], key = 2
输出：2
解释：i = 0, 1, 2 时紧跟的都是 2（共 3 次），i = 3 时紧跟的是 3（1 次），返回 2。
```

**示例 3（边界补充：key 连续出现形成链）**

```text
输入：nums = [7,7,7,7], key = 7
输出：7
解释：i = 0, 1, 2 各贡献一次 target = 7，共 3 次；注意 (nums[1], nums[2]) 这对
     相邻的 7 同时以「target」和「下一轮的 key」两种身份参与计数，互不干扰。
```

## 3. 解题思路

### 3.1 暴力思路

「出现次数最多」是一个**众数**问题，最直接的暴力是枚举候选值：对每个 $v \in [1, 1000]$，从头到尾扫一遍数组，统计满足 `nums[i] == key` 且 `nums[i+1] == v` 的下标个数，最后取计数最大的 $v$。时间是 $O(V \cdot n)$，其中 $V = 1000$ 为值域，约 $10^6$ 次操作，勉强可以通过——但它把「每个下标 $i$ 只对应一个 target」这一事实重复计算了 $V$ 遍，本质上是对同一段数组的 1000 次重复扫描。

### 3.2 核心观察：一遍扫描，「key 的后继」直接入桶计数

![核心观察：遇到 key 就给它的后继计数加一](images/bw73_q1_scan_count_concept.svg)

换个方向看：与其枚举 target 再扫数组验证，不如**只扫一遍数组，遇到 `nums[i] == key` 时，把 `nums[i+1]` 这个「现成的 target」直接丢进计数桶**。每个满足条件的下标 $i$ 恰好被访问一次、恰好贡献一次计数，时间降为 $O(n)$。

计数桶的选择：值域只有 $1 \sim 1000$，直接开长度 1001 的数组即可，比哈希表更快更省事。统计过程中同时维护「当前最大计数及其对应的 target」，扫完即得答案，无需二次遍历。

### 3.3 算法流程

```text
1. cnt[1..1000] 清零；best = 0（最大计数），ans = 0（对应 target）
2. for i in 0 .. n-2:
       若 nums[i] == key：
           t = nums[i+1]
           cnt[t] += 1
           若 cnt[t] > best：best = cnt[t]，ans = t
3. 返回 ans
```

### 3.4 示例演算

![示例演算：示例 2 的扫描与计数过程](images/bw73_q1_example_walkthrough.svg)

以示例 2（`nums = [2,2,2,2,3]`，`key = 2`）为例：

| $i$ | nums[i] | 是否等于 key | target = nums[i+1] | 计数桶变化 | best / ans |
|-----|---------|--------------|--------------------|------------|------------|
| 0 | 2 | 是 | 2 | cnt[2] = 1 | 1 / 2 |
| 1 | 2 | 是 | 2 | cnt[2] = 2 | 2 / 2 |
| 2 | 2 | 是 | 2 | cnt[2] = 3 | 3 / 2 |
| 3 | 2 | 是 | 3 | cnt[3] = 1 | 3 / 2 |

扫描结束，返回 `ans = 2`，与官方答案一致。注意 $i$ 只取到 $n-2$：最后一个元素没有后继，永远不可能成为某个 $i$ 的 `nums[i+1]`。

## 4. 算法细节

1. **计数下标只到 $n-2$**：条件 `nums[i+1]` 要求 $i + 1 \le n - 1$。循环写成 `for i in range(len(nums) - 1)` 或 `i + 1 < n`，越界即错。
2. **值域数组而非哈希表**：$1 \le nums[i] \le 1000$，`cnt` 开 1001 长度（下标 0 弃用），读写都是 $O(1)$ 且无哈希开销。若值域更大（如 $10^9$），则换成 `unordered_map` / `dict`，逻辑不变。
3. **边扫边维护最大值**：`cnt[t]++` 之后立刻与 `best` 比较，省去结束后的再遍历。由于答案唯一，用严格大于 `>` 更新即可；即便出现平局（题目保证不会），保留先达到该计数的那个也不影响合法性。
4. **链式出现的正确性**：`[2,2,2,2,3]` 中同一对相邻的 2 既被 $i$ 统计为 target、又作为 $i+1$ 处的 key 参与下一轮判断。这没有问题——题目定义的每一次「出现」对应一个下标 $i$，各个下标的计数互相独立，代码按 $i$ 逐个累加恰好与定义一一对应。
5. **防御性初始化**：`best` 与 `ans` 初始化为 0。若 `key` 只出现在最后一个位置（此时没有任何合法的 $i$，题目保证不会发生），函数返回 0 而不是未定义值。

## 5. 正确性证明

**引理 1（计数等价）**：对任意 $v$，算法结束后 `cnt[v]` 等于满足 `nums[i] == key` 且 `nums[i+1] == v` 的下标 $i \in [0, n-2]$ 的个数。

**证明**：对每个这样的下标 $i$，循环体恰好执行一次 `cnt[nums[i+1]] += 1`，即 `cnt[v]` 加一；反之，`cnt[v]` 的每次自增都来自某个满足两条件的 $i$，二者一一对应，故计数相等。∎

**定理**：算法返回的 `ans` 是出现次数最多的 `target`。

**证明**：由引理 1，每个候选 `target` 的出现次数被准确统计。`best` 在扫描过程中始终保持「已见过的 target 中的最大计数」，结束时 `best = max(cnt)`，`ans` 是达到该最大计数的某个 target。题目保证出现次数最多的 `target` 唯一，故 `ans` 即为所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，每个下标 $O(1)$ 处理；若用值域数组且把清零也算上，是 $O(n + V)$，$V = 1001$。
- **空间**：$O(V)$，即计数数组 `cnt` 的 1001 个整数；若值域数组换成哈希表，则为 $O(\min(n, V))$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int mostFrequent(vector<int>& nums, int key) {
        vector<int> cnt(1001, 0);
        int best = 0, ans = 0;
        for (int i = 0; i + 1 < (int)nums.size(); ++i) {
            if (nums[i] == key) {
                int t = nums[i + 1];
                if (++cnt[t] > best) { best = cnt[t]; ans = t; }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def mostFrequent(self, nums: list, key: int) -> int:
        cnt = [0] * 1001
        best, ans = 0, 0
        for i in range(len(nums) - 1):
            if nums[i] == key:
                t = nums[i + 1]
                cnt[t] += 1
                if cnt[t] > best:
                    best, ans = cnt[t], t
        return ans
```

> 💡 两份代码均通过官方示例（`100`、`2`）及自拟边界（`[7,7,7,7]`、key 只在末位等）；另以「收集所有后继、排序后扫描最长平台找众数」的独立暴力做 checker，随机 20 万组（C++）+ 3000 组（Python）零失配。

## 8. 边界情况与易错点

1. **循环上界**：必须扫到 $n-2$ 为止，写成 `i < n` 会访问 `nums[n]` 越界；写成 `i < n - 1` 是对的，最容易被 `n` 与下标上限搞混。
2. **key 只出现在末位**：理论上可能（题面只保证 key 出现过），此时不存在任何合法 $i$，算法返回 0。正式数据保证答案存在，不会触发，但初始化为 0 比未定义值安全。
3. **平局不要特判**：题目保证答案唯一，用严格 `>` 更新即可；如果想更稳，`>=` 会改为保留「后达到最大」的那个，对合法输入两者等价，切勿写复杂的平局规则。
4. **别把 key 计进自己**：统计的是 `nums[i+1]`，不是 `nums[i]`；`[1,100,200,1,100]` 中 key = 1 出现 2 次，但答案与「1 出现几次」无关。
5. **值域下标**：`cnt` 大小取 1001（容纳下标 1000），C++ 中开 1000 会越界写坏栈。
