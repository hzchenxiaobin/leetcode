# LeetCode K 站中转内最便宜的航班 题解

## 1. 题目概述

- **标题 / 题号**：K 站中转内最便宜的航班（#787，medium）
- **链接**：https://leetcode.cn/problems/cheapest-flights-within-k-stops/
- **来源**：LeetCode 第 72 场周赛 Q3
- **难度**：中等
- **标签**：图、动态规划、最短路、广度优先搜索、深度优先搜索、堆（优先队列）

**题意**：给定 $n$ 个城市与一批**有向**航班 `flights[i] = [fromᵢ, toᵢ, priceᵢ]`，再给定起点 `src`、终点 `dst` 和整数 $k$。求从 `src` 到 `dst`、**最多经过 $k$ 站中转**的路径中的最小总票价；若不存在这样的路径返回 `-1`。

**约束**：

- $2 \le n \le 100$
- $0 \le \lvert\text{flights}\rvert \le \dfrac{n(n-1)}{2} \le 4950$
- $0 \le \text{from}_i, \text{to}_i < n$，$\text{from}_i \ne \text{to}_i$，无重边、无自环
- $1 \le \text{price}_i \le 10^4$
- $0 \le \text{src}, \text{dst}, k < n$，$\text{src} \ne \text{dst}$

> 💡 **审题关键**：$k$ 限制的是**中转站数**，所以整条路径的**边数**上限是 $k+1$，循环轮数别写成 $k$。另外边是**有向**的、价格**恒正**（这两点决定了不能随便套无向图最短路模板，也保证了可以提前收敛）。

## 2. 示例

**示例 1**（便宜的路站数超限）

```text
输入：n = 4, flights = [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], src = 0, dst = 3, k = 1
输出：700
解释：0→1→3 花 100 + 600 = 700，1 站，合法；
      0→1→2→3 只要 400，但用了 2 站，超出 k = 1，无效。
```

**示例 2**（中转比直飞便宜）

```text
输入：n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 1
输出：200
解释：0→1→2 花 200，用 1 站；直飞 0→2 花 500，两者都合法，取小。
```

**示例 3**（$k = 0$ 只许直飞）

```text
输入：n = 3, flights = [[0,1,100],[1,2,100],[0,2,500]], src = 0, dst = 2, k = 0
输出：500
解释：不允许任何中转，只能 0→2 直飞，花 500；200 那条要 1 站，被排除。
```

## 3. 解题思路

### 3.1 暴力思路

从 `src` 出发做 DFS，枚举所有边数不超过 $k+1$ 的路径，取到达 `dst` 的最小票价。路径条数最坏是 $n^{k+1}$ 量级（$n = k+1 = 100$ 时为 $100^{100}$），指数爆炸。

暴力的浪费在于：它把「已经花了多少钱」和「还剩几站」都当成搜索状态重新展开，而实际上这两件事完全可以合并成一个**表格**来递推。

### 3.2 核心观察：把「已用边数」并入状态，得到分层图

![站数是状态维度：分层图上从 src 到各层的 dst](images/wc72_q3_layered_state.svg)

**单维最短路为什么会错**：若只保留 `dist[城市]`，我们就在「花得少」和「站数少」之间只看到了前者。反例：$k = 1$，航班 $0\to1(100)$、$0\to2(1)$、$2\to1(1)$、$1\to3(1)$。忽略站数的最短路会给出 $0\to2\to1\to3 = 3$，但它用了 3 条边 = 2 站，非法；真正答案是 $0\to1\to3 = 101$。可见「先以更低价格到达中转站」反而可能让后续被站数卡死，**便宜的解必须被丢弃，而那恰恰是 Dijkstra 的贪心会永久丢掉的信息**。

**正确的状态**：让 $f_t(v)$ 表示「从 `src` 到 $v$、且**边数不超过** $t$ 的最小花费」。$t$ 就是「已经飞了几条边」这一维，$t$ 与站数的关系是：

$$\text{中转站数} = \text{边数} - 1 \quad\Longrightarrow\quad \text{边数} \le k + 1$$

于是答案就是 $f_{k+1}(\text{dst})$。这个做法的好处是：$f_t$ 只依赖 $f_{t-1}$，**层与层之间没有横向依赖**，可以像 Bellman–Ford 一样逐轮松弛，只需滚动保存两行。

### 3.3 算法流程 / 状态转移

![逐轮松弛流程：快照 + 扫全部边](images/wc72_q3_relax_flow.svg)

初值（0 条边只能停在起点）：

$$f_0(v) = \begin{cases} 0, & v = \text{src} \\ +\infty, & v \ne \text{src} \end{cases}$$

转移（对 $t = 1, 2, \dots, k+1$）：

$$f_t(v) = \min\Bigl(\, f_{t-1}(v),\ \min_{(u,v,w) \in E}\bigl(f_{t-1}(u) + w\bigr) \Bigr)$$

其中第一项 $f_{t-1}(v)$ 表示「**用不满** $t$ 条边」，正是「至多」语义；若题目要求「恰好 $k$ 站」，去掉这一项即可。等价写法是 **Bellman–Ford 跑 $k+1$ 轮**：

1. `dist[src] = 0`，其余 `INF`。
2. 重复 $k+1$ 次：**先快照** `cur = dist`，再对每条边 $(u,v,w)$ 做 `dist[v] = min(dist[v], cur[u] + w)`。
3. 结束时 `dist[dst]` 是答案；仍是 `INF` 则返回 `-1`。

快照这一步是整个算法的**命门**：如果直接拿正在被修改的 `dist[u]` 去松弛，同一轮里就会连走多条边，把 3 条边的路径算进「2 条边」的层，答案偏小。

### 3.4 示例演算

![示例 1 的逐轮演算表](images/wc72_q3_walkthrough.svg)

以示例 1 为例，$k = 1$ 故最多 2 条边：

| 轮次 $t$（边数上限） | $f_t(0)$ | $f_t(1)$ | $f_t(2)$ | $f_t(3)$ |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 0 | $\infty$ | $\infty$ | $\infty$ |
| 1 | 0 | 100 | $\infty$ | $\infty$ |
| 2 | 0 | 100 | 200 | **700** |

- 第 1 轮：只有 $0\to1$ 可达，`dist[1] = 100`。
- 第 2 轮：从 $1$ 出发松弛，$1\to2$ 得 `200`，$1\to3$ 得 `700`，取最小值即答案。
- $0\to1\to2\to3$ 只要 400，但要走到第 3 轮（2 站），$k = 1$ 时被排除；这正是「便宜但超站」的典型陷阱。

## 4. 算法细节

1. **轮数是 $k+1$ 不是 $k$**：$k$ 计数的是中转站，路径边数 = 站数 + 1。只跑 $k$ 轮会漏掉「直飞终点」那一类解。
2. **必须用快照**：每轮开头复制一份 `cur`（或写 `nxt = dist` 后只改 `nxt`）。C++ 里 `vector<int> nxt = dist;` 后 `swap` 是零成本写法。
3. **「至多」靠复制实现**：若把 `nxt` 重置成全 `INF`，转移就变成「恰好 $t$ 条边」，此时答案要取 $\min_{t \le k+1} f_t(\text{dst})$。两种写法都对，但混用会错。
4. **直接遍历 `flights` 数组，不建邻接表**：每轮都要扫全部 $m$ 条边，数组连续访问的常数比 `vector<vector<pair>>` 小，代码也更短。
5. **`INF` 取 $10^9$**：单条路径最多 $100 \times 10^4 = 10^6$，用 `INT_MAX` 做加法会溢出，用 $10^9$ 加法不溢出且远大于任何真实答案。
6. **可提前收敛**：某一轮 `dist` 与上一轮完全相同就 `break`（价格恒正，继续跑不会更优），最坏情况仍被 $k+1$ 轮上界约束。
7. **等价的分层 Dijkstra**：把状态写成 `(city, steps)`，堆里存 `(cost, city, steps)`，`steps > k+1` 直接丢弃，第一次弹出 `dst` 即答案；复杂度 $O((k+1)m \log)$，比本 DP 多一个 $\log$，但能顺便还原路径。

## 5. 正确性证明

**引理 1（路径可拆分）**：设 $P$ 是从 `src` 到 $v$、恰有 $t \ge 1$ 条边的路径，则删去最后一条边 $(u,v,w)$ 后，剩下一段是从 `src` 到 $u$、恰有 $t-1$ 条边的路径，且花费减少 $w$。

**证明**：$P$ 的顶点序列为 $v_0 = \text{src}, v_1, \dots, v_t = v$，边 $e_i = (v_{i-1}, v_i)$，花费 $\sum_{i=1}^{t} w_i$。删去 $e_t$ 后序列 $v_0, \dots, v_{t-1}$ 中相邻对仍都是图中的边（子路径的边来自原路径），边数为 $t-1$，花费为 $\sum_{i=1}^{t-1} w_i = \text{cost}(P) - w$。∎

**引理 2（转移完备且紧）**：按 §3.3 的递推式算出的 $f_t(v)$，等于「从 `src` 到 $v$、边数不超过 $t$ 的所有路径」的最小花费。

**证明**：对 $t$ 归纳。$t = 0$ 时只有零长路径（停在 `src`），与初值一致。设 $f_{t-1}$ 正确，考察边数 $\le t$ 的任意路径 $P$：

- 若 $P$ 边数 $\le t-1$，由归纳假设 $\text{cost}(P) \ge f_{t-1}(v) \ge f_t(v)$；
- 若 $P$ 恰有 $t$ 条边，由引理 1，其前半段是到某 $u$、边数 $\le t-1$ 的路径，故 $\text{cost}(P) = \text{cost}(\text{前半段}) + w \ge f_{t-1}(u) + w \ge f_t(v)$。

所以 $f_t(v)$ 不超过任何合法路径的花费。另一方面，递推式的两项各自都对应一条真实路径（第一项是边数更少的同一路径，第二项是「到 $u$ 的最优前缀 + 边 $(u,v)$」，边数 $\le t$），故 $f_t(v)$ 也被某条合法路径达到。∎

**引理 3（单调性）**：对任意 $v$，$f_t(v) \le f_{t-1}(v)$。

**证明**：边数上限放宽后可行集只会变大，最小值不可能变大。∎

**定理**：算法返回 $\min\bigl(f_{k+1}(\text{dst}), +\infty\bigr)$，当其为 $+\infty$ 时输出 `-1`，即为题目所求。

**证明**：题目要求「至多 $k$ 站中转」，即边数 $\le k+1$。由引理 2，$f_{k+1}(\text{dst})$ 恰是该约束下的最小花费；若为 $+\infty$，说明不存在任何边数 $\le k+1$ 的路径，输出 `-1` 正确。算法只做 $k+1$ 轮、每轮用快照保证只加一条边，因此第 $t$ 轮结束时 `dist` 就是 $f_t$，与递推式一致。∎

## 6. 复杂度分析

- **时间**：$O\bigl((k+1)(n + m)\bigr)$。每轮复制 $O(n)$ 的数组、再扫 $O(m)$ 条边；最坏 $k+1 = 100$、$m = 4950$，约 $5 \times 10^5$ 次操作，远低于限制。若某轮 `dist` 完全没有更新，说明已经收敛，可以提前 `break`（示例 1 就不会提前收敛：第 3 轮还能把 $f(3)$ 从 700 降到 400，只是 $k=1$ 不允许）。
- **空间**：$O(n)$。只有 `dist` 与 `cur/nxt` 三份长度 $n$ 的数组；若不滚动而保存全部 $k+1$ 层，则是 $O(kn)$，本题无必要。
- **对比**：分层 Dijkstra 为 $O\bigl((k+1)m \log((k+1)n)\bigr)$，常数更大但可还原路径；Floyd 处理不了「站数上限」，不适合。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findCheapestPrice(int n, vector<vector<int>>& flights, int src, int dst, int k) {
        const int INF = 1000000000;          // 真实花费 ≤ 1e6，用 1e9 做加法不溢出
        vector<int> dist(n, INF);
        dist[src] = 0;
        for (int step = 0; step <= k; ++step) {   // k 站 ⇒ k+1 条边，循环 k+1 轮
            vector<int> nxt = dist;               // 快照：保留「至多 step 条边」的旧值
            for (size_t i = 0; i < flights.size(); ++i) {
                int u = flights[i][0], v = flights[i][1], w = flights[i][2];
                if (dist[u] != INF && dist[u] + w < nxt[v])
                    nxt[v] = dist[u] + w;         // 只写 nxt，绝不写回 dist
            }
            dist.swap(nxt);
        }
        return dist[dst] == INF ? -1 : dist[dst];
    }
};
```

### Python

```python
from typing import List

class Solution:
    def findCheapestPrice(self, n: int, flights: List[List[int]], src: int, dst: int, k: int) -> int:
        INF = float('inf')
        dist = [INF] * n
        dist[src] = 0
        for _ in range(k + 1):                 # k 站 ⇒ 最多 k + 1 条边
            nxt = dist[:]                      # 快照：本轮只读上一轮的 dist
            for u, v, w in flights:
                if dist[u] + w < nxt[v]:       # dist[u] 为 INF 时加法仍是 INF，无需特判
                    nxt[v] = dist[u] + w
            dist = nxt
        return -1 if dist[dst] == INF else dist[dst]
```

## 8. 边界情况与易错点

1. **$k = 0$**：只允许直飞（1 条边）。示例 3 中必须返回 500 而非 200；轮数写成 $k+1 = 1$ 恰好正确，若写成 `range(k)` 会一轮都不跑。
2. **不可达**：`dst` 在 $k+1$ 条边内无法到达，或 `flights` 为空，都返回 `-1`。判断写成 `dist[dst] == INF`（用 `float('inf')` 或 $10^9$ 都可以），千万别把 `INF` 本身当答案输出。
3. **就地更新的经典 WA**：写成 `dist[v] = min(dist[v], dist[u] + w)` 而不快照，就会在单轮内连走多条边，答案偏小。这是本题最常见的错误写法。
4. **少跑一轮**：$k$ 与边数差 1，「跑 $k$ 轮」会漏掉「1 站中转就到位」的解（如示例 2 的 200 恰好需要 2 条边，$k = 1$ 时必须跑满 2 轮）。
5. **`INT_MAX` 溢出**：`INT_MAX + w` 溢出成负数会被当成更优解；本实现用 $10^9$ 并加 `dist[u] != INF` 判断，双重保险。
6. **方向性**：航班是有向边，只按 $(u \to v)$ 松弛；若按无向图建双边，答案可能凭空变便宜。
7. **正权自带的剪枝**：因为 `price ≥ 1`，可以放心在「某轮无更新」时 `break`；若允许负权边则不能这样剪，但本递推的边数上限本身就限制了复杂度。
8. **`src == dst`**：题面保证不会出现，但代码里 `dist[src] = 0` 会让它自然返回 0（0 条边），不会踩空。

**延伸思考**：若要求**恰好** $k$ 站中转，只需把转移式里的继承项 $f_{t-1}(v)$ 删掉、最后取 $f_{k+1}(\text{dst})$；若还要求统计**方案条数**，则在 $f_t$ 之外再维护一个计数数组，转移时按「取到更小值就重置、取到相等值就累加」处理。若 $k$ 大到 $\ge n$，站数约束形同虚设，问题退化为普通正权最短路，直接用 Dijkstra 更快；反之若 $k$ 很小而 $m$ 很大，则本 DP 的 $O((k+1)m)$ 反而是最优选择——这正是「维度换时间」的典型取舍。
