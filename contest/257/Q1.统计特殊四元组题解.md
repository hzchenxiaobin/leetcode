# LeetCode 统计特殊四元组 题解

## 1. 题目概述

- **标题 / 题号**：统计特殊四元组（#1995，easy）
- **链接**：https://leetcode.cn/problems/count-special-quadruplets/
- **来源**：LeetCode 第 257 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、枚举

**题意**：给定一个 **0 下标** 整数数组 `nums`，统计同时满足下述条件的**不同**四元组 $(a, b, c, d)$ 的数目：

- $\text{nums}[a] + \text{nums}[b] + \text{nums}[c] = \text{nums}[d]$
- $a < b < c < d$

**约束**：

- $4 \le \text{nums.length} \le 50$
- $1 \le \text{nums}[i] \le 100$

> 💡 本题在本仓库另有[每日题解 1995](../../solution/1901-2000/1995_统计特殊四元组.md)：那边以 $b$ 为分割线**从右往左**扫、哈希存右半 $(c,d)$ 的差。本篇按周赛复盘视角，以 $c$ 为分割线**从左往右**扫、哈希存左半 $(a,b)$ 的和——两者镜像同构，本篇顺下标自然方向书写，赛场上更不易写错。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,6]
输出：1
解释：唯一的特殊四元组 (0, 1, 2, 3)：1 + 2 + 3 == 6。
```

**示例 2**

```text
输入：nums = [3,3,6,4,5]
输出：0
解释：不存在满足条件的四元组。
```

**示例 3**

```text
输入：nums = [1,1,1,3,5]
输出：4
解释：
  (0, 1, 2, 3) → 1 + 1 + 1 == 3
  (0, 1, 3, 4) → 1 + 1 + 3 == 5
  (0, 2, 3, 4) → 1 + 1 + 3 == 5
  (1, 2, 3, 4) → 1 + 1 + 3 == 5
```

## 3. 解题思路

### 3.1 暴力思路：四重循环

忠实枚举所有 $(a,b,c,d)$ 组合，逐个判定。候选组合数至多 $\binom{50}{4} = 230300$，四重循环直接交也能稳过——**签到题赛场上这样写完全没问题，30 秒从题面到代码**。

但它把「值的相等关系」拆成下标层面的四重逐对比较，完全没有利用等式的**可拆分结构**：四个下标其实被 $a < b < c < d$ 切成了「左半两个」和「右半两个」，中间只隔一条线。

### 3.2 核心观察：等式拆半，枚举分割线 c

![核心观察：等式拆半，左半存和，右半查差](images/1995_equation_split.svg)

把等式**移项**：

$$\text{nums}[a] + \text{nums}[b] + \text{nums}[c] = \text{nums}[d] \iff \text{nums}[a] + \text{nums}[b] = \text{nums}[d] - \text{nums}[c]$$

- **左侧**只涉及 $a, b$，是一个「**和**」；
- **右侧**只涉及 $c, d$，是一个「**差**」；
- $a < b < c < d$ 保证左半整体在右半左侧——**枚举 $c$ 就是移动这条分割线**。

于是思路变成：**用哈希表 `cnt` 维护分割线左侧所有 $(a,b)$ 对的和的出现次数**；固定每个 $c$、枚举每个 $d > c$，用右侧的差 $O(1)$ 查表命中次数。这就是 [454. 四数相加 II](https://leetcode.cn/problems/4sum-ii/) 的「Meet in the Middle」，只不过 454 是四个独立数组天然分组，本题靠「下标有序」在同一数组内切分。

### 3.3 算法流程

![算法流程：c 从左到右推进，每轮先查后建](images/1995_left_sweep_flow.svg)

1. 初始化 `cnt` 为空哈希表，`ans = 0`。
2. **外层** $c$ 从 $0$ 到 $n-1$，每一轮：
   - **① 先查**：枚举 $d \in (c, n)$，`ans += cnt[nums[d] - nums[c]]`；
   - **② 后建**：枚举 $a \in [0, c)$，`++cnt[nums[a] + nums[c]]`，把以 $c$ 结尾的对挂到表上，供后续更大的 $c$ 查询。
3. 返回 `ans`。

> ⚠️ **必须先查后建**：查询发生时，`cnt` 里只能有 $b < c$ 的对。若先建后查，刚加入的 $(a, c)$ 对会让「$b = c$」这种违反 $b < c$ 严格性的非法对混入，凭空多算。

### 3.4 示例演算

![示例演算：nums=[1,2,3,6]，c 从左到右扫一遍](images/1995_example_walkthrough.svg)

对示例 1 `nums = [1,2,3,6]` 逐步走查：

| 轮次 | ① 查：枚举 $d > c$ | ② 建：以 $c$ 结尾的对 | cnt 状态 | ans |
|------|--------------------|----------------------|----------|-----|
| $c=0$ | $d=1,2,3$：表为空 → +0 | $a < 0$：无对可加 | $\{\}$ | 0 |
| $c=1$ | $d=2,3$：→ +0 | $(0,1)$：和 $1+2=3$，cnt$[3]{+}{=}1$ | $\{3{:}1\}$ | 0 |
| $c=2$ | $d=3$：cnt$[6-3]={\rm cnt}[3]=1$ → **+1** | $(0,2)\!:\!$cnt$[4]$，$(1,2)\!:\!$cnt$[5]$ | $\{3{:}1,4{:}1,5{:}1\}$ | **1** |
| $c=3$ | 无 $d > 3$ → +0 | $(0,3),(1,3),(2,3)$ 入表 | $\{\dots\}$ | 1 |

最终 `ans = 1` ✓。唯一命中在 $c=2$：左半和 $1+2=3$ 恰等于右半差 $6-3$。

再看示例 3 `[1,1,1,3,5]`：扫到 $c=3$ 时，`cnt[2] = 3`（三个重复的 $1+1$），一次查询 `cnt[5-3]` 直接收下 $3$ 个四元组——**重复值靠「存次数」一次吃进**，这正是 `cnt` 必须是计数表而非集合的原因。

## 4. 算法细节

1. **分割线选 $c$ 而非 $b$**：$a < b < c < d$ 中 $b$、$c$ 都可以做左半与右半的分界（选 $b$ 即每日题解的从右往左写法）。选 $c$、从左往右扫，顺着下标自然方向书写，边界不易错。
2. **先查后建的顺序**：见 3.3 的警示。一句话记忆——「**查的时候，新建的不能算数**」。
3. **`cnt` 存次数**（多重集语义）：题目问四元组**个数**，同一和值可能对应多个 $(a,b)$ 对，命中时按次数累加。
4. **值域小可换定长数组**：$1 \le \text{nums}[i] \le 100$，故差 $\text{nums}[d]-\text{nums}[c] \in [-99, 99]$、和 $\text{nums}[a]+\text{nums}[c] \in [2, 200]$。加偏移 $100$ 后同落在一个大小 $301$ 的数组内，比哈希表常数更小。
5. **中间台阶 $O(n^3)$**：固定 $b, c, d$ 三重循环、用频率数组查 $a$ 的个数也能过，是想不到 $O(n^2)$ 时的自然折衷，完整代码见[每日题解 1995](../../solution/1901-2000/1995_统计特殊四元组.md)。

## 5. 正确性证明

**引理 1**（区间不变式）：进入第 $c$ 轮「查」之前，`cnt` 恰为多重集 $\{\, \text{nums}[a] + \text{nums}[b] : 0 \le a < b \le c-1 \,\}$ 的计数表。

**证明**：对 $c$ 归纳。$c = 0$ 时左侧无满足 $a < b \le -1$ 的对，`cnt` 为空，成立。设第 $c$ 轮成立，则该轮「建」阶段把所有 $(a, c)$（$0 \le a < c$）的和入表，得到恰为 $\{\text{nums}[a]+\text{nums}[b] : a < b \le c\}$ 的计数表，正是第 $c+1$ 轮所需的 $\{a < b \le (c+1)-1\}$。∎

**引理 2**（一一对应）：算法最终累计的 `ans` 等于集合 $T = \{\,(a,b,c,d) : a < b < c < d,\ \text{nums}[a]+\text{nums}[b] = \text{nums}[d]-\text{nums}[c]\,\}$ 的大小。

**证明**：第 $c$ 轮对每个 $d > c$ 累加 cnt$[\text{nums}[d]-\text{nums}[c]]$。由引理 1，该值恰为 $\#\{(a,b) : a < b < c,\ \text{nums}[a]+\text{nums}[b] = \text{nums}[d]-\text{nums}[c]\}$，其中每对 $(a,b)$ 都与当前的 $(c,d)$ 组成一个 $T$ 中元素。反过来，任取 $T$ 中元素 $(a,b,c,d)$，它恰在第 $c$ 轮、枚举到该 $d$ 时被计数一次——因为查询发生在建表之前，表中对满足 $b < c$，不会引入 $T$ 之外的计数。累加遍历所有 $(c,d)$，两个方向均为一一对应。∎

**定理**：算法返回特殊四元组的总数。

**证明**：移项是等价变形，$\text{nums}[a]+\text{nums}[b]+\text{nums}[c]=\text{nums}[d]$ 与 $\text{nums}[a]+\text{nums}[b]=\text{nums}[d]-\text{nums}[c]$ 在 $a<b<c<d$ 下定义了同一集合，故 $T$ 就是特殊四元组集合。由引理 2，返回值即其大小。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。第 $c$ 轮「查」$O(n-c-1)$ 次、「建」$O(c)$ 次，合计 $\sum_{c=0}^{n-1} O(n) = O(n^2)$；哈希操作均摊 $O(1)$。$n = 50$ 时约 $2500$ 步，瞬间完成。
- **空间复杂度**：$O(\min(\binom{n}{2}, V))$，其中值域宽度 $V = 199$（和 $\in [2,200]$）。哈希表键数不超过 $199$，可视作常数；若用 $301$ 大小偏移数组则为严格 $O(1)$ 额外空间。

## 7. 参考代码

### C++（O(n²)，先查后建）

```cpp
class Solution {
public:
    int countQuadruplets(vector<int>& nums) {
        int n = nums.size(), ans = 0;
        unordered_map<int, int> cnt; // cnt[s]：分割线左侧 a<b 的对中 nums[a]+nums[b]==s 的个数
        for (int c = 0; c < n; ++c) {
            for (int d = c + 1; d < n; ++d)      // ① 先查：右半 (c,d)
                ans += cnt[nums[d] - nums[c]];
            for (int a = 0; a < c; ++a)          // ② 后建：以 c 结尾的左半对 (a,c)
                ++cnt[nums[a] + nums[c]];
        }
        return ans;
    }
};
```

值域数组版（偏移 100，常数更小）：

```cpp
class Solution {
public:
    int countQuadruplets(vector<int>& nums) {
        int n = nums.size(), ans = 0;
        int cnt[301] = {0}; // 差 ∈ [-99,99]、和 ∈ [2,200]，加 100 后落在 [1,200]
        for (int c = 0; c < n; ++c) {
            for (int d = c + 1; d < n; ++d)
                ans += cnt[nums[d] - nums[c] + 100];
            for (int a = 0; a < c; ++a)
                ++cnt[nums[a] + nums[c] + 100];
        }
        return ans;
    }
};
```

### C++（赛场保底：四重循环 O(n⁴)）

```cpp
class Solution {
public:
    int countQuadruplets(vector<int>& nums) {
        int n = nums.size(), ans = 0;
        for (int a = 0; a < n; ++a)
            for (int b = a + 1; b < n; ++b)
                for (int c = b + 1; c < n; ++c)
                    for (int d = c + 1; d < n; ++d)
                        if (nums[a] + nums[b] + nums[c] == nums[d]) ++ans;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countQuadruplets(self, nums: List[int]) -> int:
        n = len(nums)
        cnt = defaultdict(int)  # cnt[s]：分割线左侧 a<b 的对中 nums[a]+nums[b]==s 的个数
        ans = 0
        for c in range(n):
            for d in range(c + 1, n):      # ① 先查：右半 (c,d)
                ans += cnt[nums[d] - nums[c]]
            for a in range(c):             # ② 后建：以 c 结尾的左半对 (a,c)
                cnt[nums[a] + nums[c]] += 1
        return ans
```

## 8. 边界情况与易错点

1. **先查后建，顺序不能反**：若先建后查，$(a, c)$ 对混入查询，相当于允许 $b = c$，违反 $b < c$ 的严格性，会多算不存在的四元组。这是本解法唯一的「暗礁」。
2. **不能排序**：$a < b < c < d$ 是**下标**约束，排序会破坏下标顺序，直接改变答案。数组保持原样，一切逻辑围绕下标展开。
3. **差可能为负或零**：$\text{nums}[d] - \text{nums}[c] \in [-99, 99]$。哈希表天然支持负键；值域数组必须加偏移（如 +100），否则负数下标越界。
4. **无溢出风险**：$n \le 50$ 时四元组总数至多 $\binom{50}{4} = 230300$，`int` 绰绰有余；值的和最大 $300$ 也无压力。
5. **最小规模 $n = 4$**：唯一候选 $(0,1,2,3)$，如 `[1,1,1,3]` 输出 1、`[1,2,3,6]` 输出 1、`[3,3,6,4]` 输出 0。
6. **重复元素必须「存次数」**：`cnt` 用计数表（`map`/`defaultdict(int)`），不能用集合——示例 3 中一次查询要一次吃进 3 个四元组。
7. **循环边界**：`c` 从 $0$ 起扫即可，$c = 0, 1$ 两轮查询自动落空、无需特判；`d` 从 $c+1$ 起、`a` 到 $c-1$ 止，两端都取开区间语义。

**延伸思考**：

- 若 $n$ 放大到 $10^4$，$O(n^2)$ 的 2500 万步哈希操作会很勉强——值域仍小（键 $\le 199$ 个）时可用「前缀桶」把每轮查询也压到 $O(V)$ 之外吗？实际上瓶颈在建表 $O(n^2)$ 对，需要改用值域上的计数卷积（和的分布 = 两个值域计数数组的卷积），思路与 [454](https://leetcode.cn/problems/4sum-ii/) 的进一步优化同源。
