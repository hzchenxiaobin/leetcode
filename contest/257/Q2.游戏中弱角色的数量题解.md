# LeetCode 游戏中弱角色的数量 题解

## 1. 题目概述

- **标题 / 题号**：游戏中弱角色的数量（#1996，medium）
- **链接**：https://leetcode.cn/problems/the-number-of-weak-characters-in-the-game/
- **来源**：LeetCode 第 257 场周赛 Q2
- **难度**：中等
- **标签**：栈、贪心、数组、排序、单调栈

**题意**：每个角色有两个属性——**攻击**与**防御**，给定 `properties[i] = [attack_i, defense_i]`。若存在**另一个**角色 $j$ 满足 $\text{attack}_j > \text{attack}_i$ **且** $\text{defense}_j > \text{defense}_i$（双属性**都严格更大**），则角色 $i$ 为**弱角色**。返回弱角色的数量。

**约束**：

- $2 \le \text{properties.length} \le 10^5$
- $\text{properties}[i].\text{length} == 2$
- $1 \le \text{attack}_i, \text{defense}_i \le 10^5$

> 💡 本题在本仓库另有[每日题解 1996](../../solution/1901-2000/1996_游戏中弱角色的数量.md)：那边走「攻击**降序** + 同攻击防御**升序** + 单变量 `max_def` 一趟判定」。本篇按周赛复盘视角，沿题目标签里的**单调栈**主线（攻击**升序** + 同攻击防御**降序**，即防御维的「下一个更大元素」），并完整给出「弹栈计数 ⇔ 弱角色」的一一对应证明——两篇互为镜像印证。

## 2. 示例

**示例 1**

```text
输入：properties = [[5,5],[6,3],[3,6]]
输出：0
解释：不存在攻击和防御都严格高于其他角色的角色。
      [6,3] 攻击更大但防御更小，[3,6] 反之——谁也压不住谁。
```

**示例 2**

```text
输入：properties = [[2,2],[3,3]]
输出：1
解释：[3,3] 双属性严格大于 [2,2]，故 [2,2] 是弱角色。
```

**示例 3**

```text
输入：properties = [[1,5],[10,4],[4,3]]
输出：1
解释：[10,4] 双属性严格大于 [4,3]，故 [4,3] 是弱角色；
      [1,5] 攻击最小但防御最大，无人能双压。
```

## 3. 解题思路

### 3.1 暴力思路：两两比较

对每个角色 $i$ 扫描所有 $j \ne i$，判定是否存在支配者——$O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。瓶颈在于把每个角色**孤立地**找支配者，完全没有利用**攻击维度的全局顺序**。

### 3.2 核心观察：排序降维——支配者必在右侧

![核心观察：攻击升序排序后支配者必在右侧，同攻击防御降序消除组内歧义](images/1996_weak_sort_concept.svg)

「弱角色」判定是一个**二维严格偏序**上的存在性查询：

$$i \text{ 弱} \iff \exists\, j:\ \text{attack}_j > \text{attack}_i \ \wedge\ \text{defense}_j > \text{defense}_i$$

两条观察把维度压下来：

1. **按攻击升序排序**：支配者 $j$ 要求 $\text{attack}_j > \text{attack}_i$，排序后 $j$ **一定排在 $i$ 右侧**。「找支配者」从全量两两比较变成**单向向后看**。
2. **同攻击按防御降序**：同攻击的角色**永不互相支配**（攻击相等不满足严格大于）。让同组内防御从大到小处理，则「右侧角色的防御 > 左侧角色」在同组内**永不成立**——凡是被右侧弹出，支配者必来自攻击**严格更大**的组。**「严格」的语义完全交给排序的次关键字**，扫描逻辑里再也不必比较攻击。

降维后问题只剩一维：**防御维上问「右侧是否存在严格更大的值」**——这正是 [739. 每日温度](https://leetcode.cn/problems/daily-temperatures/) 的「下一个更大元素」，单调栈的标准用武之地。

### 3.3 算法流程：单调栈

![算法流程：栈存未找到支配者的角色防御，栈顶小于当前防御则弹出计数](images/1996_weak_stack_flow.svg)

栈中存放**尚未找到支配者**的角色的防御值（自底向顶非递增）：

1. 排序：主键攻击**升序**，次键（同攻击时）防御**降序**。
2. 从左到右扫描，设当前角色防御为 $d$：
   - **while 栈非空 且 栈顶 < $d$**：弹出栈顶，`ans++`——栈顶角色被当前角色双属性严格压制，确认为弱；
   - 将 $d$ 入栈。
3. 扫描结束，返回 `ans`。

> ⚠️ 弹栈条件是**严格小于**：防御相等不构成支配（要求严格大于）；攻击维的严格性已由次关键字降序保证。两个「严格」各有着落，这是本题全部细节所在。

### 3.4 示例演算

![示例演算：[[1,5],[10,4],[4,3]] 排序后单趟扫描，弹出 3 计数一次](images/1996_weak_walkthrough.svg)

对示例 3 `[[1,5],[10,4],[4,3]]`，排序后为 `[(1,5), (4,3), (10,4)]`：

| 角色 (攻, 防) | 栈操作 | 栈（底 → 顶） | ans |
|---------------|--------|---------------|-----|
| (1,5) | 栈空，5 入栈 | [5] | 0 |
| (4,3) | 栈顶 5 ≥ 3，3 入栈 | [5, 3] | 0 |
| (10,4) | 栈顶 3 < 4 → **弹出计数**；再 5 ≥ 4，4 入栈 | [5, 4] | **1** |

被弹出的 3 正是角色 (4,3)——被 (10,4) 以 $10 > 4$、$4 > 3$ 双属性压制 ✓。栈中残留的 5、4 对应 (1,5)、(10,4)，均非弱。

再看示例 1 `[[5,5],[6,3],[3,6]]`，排序后 `[(3,6), (5,5), (6,3)]`：防御 6、5、3 依次入栈、全程无弹出，`ans = 0` ✓。示例 2 `[[2,2],[3,3]]` 是最小规模的一次弹出：(3,3) 弹出 (2,2)，`ans = 1` ✓。

## 4. 算法细节

1. **排序键（attack 升序，defense 降序）**：次键方向是本题最常见 WA 点。若同攻击按防御**升序**，反例 `[[5,3],[5,4]]`：(5,4) 会把同攻击的 (5,3) 弹出计数，但攻击相等不构成支配——正确答案 0，升序写法错算 1。
2. **栈只存防御值**：攻击无需入栈。引理 2（见 §5）保证凡被弹出者的攻击必严格小于弹出者，栈里根本不用记攻击。
3. **计数不重不漏的来源**：每个角色**恰好入栈一次、至多出栈一次**，弹出即计数——不会重复；弱角色必被某个支配者弹出——不会漏。
4. **只需存在性，可退化为单变量**：若只问「是否存在支配者」，栈还能再省——按攻击**降序**、同攻击防御**升序**排，维护「攻击严格更大的前缀」的最大防御 `max_def`，一趟比较即可（即[每日题解 1996](../../solution/1901-2000/1996_游戏中弱角色的数量.md) 的镜像写法，额外空间 $O(1)$）。单调栈的优势在**变体更通用**：防御带权、需要配对信息（谁支配谁）、或改为「到下一个更大防御的距离」时，栈结构直接迁移。
5. **排序实现**：C++ 自定义比较 `a[0] != b[0] ? a[0] < b[0] : a[1] > b[1]`；Python 一行 `key=lambda p: (p[0], -p[1])`。值域 $10^5$ 允许按攻击分桶做到 $O(n + V)$，但 `std::sort` 的 $O(n \log n)$ 已绰绰有余。

## 5. 正确性证明

**引理 1（栈不变式）**：任意时刻，栈自底向顶防御值**非递增**。

**证明**：对操作次数归纳。初始栈空，成立。设某次入栈前不变式成立，入栈值为 $d$：弹栈阶段已移除所有防御 $< d$ 的栈顶，故剩余栈顶（若有）防御 $\ge d$；压入 $d$ 后新的相邻对满足「下 $\ge$ 上」，其余相邻对不变。弹栈只移除元素，不破坏顺序。∎

**引理 2（弹出即被支配）**：若角色 $i$ 被当前角色 $j$ 弹出，则 $\text{attack}_i < \text{attack}_j$ 且 $\text{defense}_i < \text{defense}_j$，即 $j$ 严格支配 $i$。

**证明**：弹栈条件直接给出 $\text{defense}_i < \text{defense}_j$。$i$ 先于 $j$ 入栈，排序按攻击升序，故 $\text{attack}_i \le \text{attack}_j$；若二者相等，则同组按防御**降序**处理，先处理者防御 $\ge$ 后处理者，即 $\text{defense}_i \ge \text{defense}_j$，与弹栈条件矛盾。故 $\text{attack}_i < \text{attack}_j$。∎

**引理 3（弱者必被弹出）**：若 $i$ 是弱角色，则扫描过程中 $i$ 恰好被弹出一次并计数一次。

**证明**：$i$ 弱 ⇒ 存在支配者 $j$（$\text{attack}_j > \text{attack}_i$ 且 $\text{defense}_j > \text{defense}_i$）。由攻击升序，$j$ 在 $i$ **之后**被处理。处理 $j$ 时：若 $i$ 已出栈，则已被计数；若 $i$ 仍在栈中，由引理 1，$i$ 上方所有元素防御 $\le \text{defense}_i < \text{defense}_j$，它们在弹栈阶段被连续弹出直至 $i$ 成为栈顶，随后 $\text{defense}_i < \text{defense}_j$ 使 $i$ 也被弹出计数。又因每角色至多出栈一次，「恰好一次」成立。∎

**定理**：算法返回值等于弱角色的数量。

**证明**：由引理 2，每次计数都对应一个确被支配的弱角色（不重）；由引理 3，每个弱角色都恰被计数一次（不漏）。二者合并即返回值 = 弱角色数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序主导；扫描阶段每个角色恰好入栈一次、至多出栈一次，栈操作总数 $O(n)$，摊还每次 $O(1)$。$n = 10^5$ 时约 $1.7 \times 10^6$ 次排序比较加 $2 \times 10^5$ 次栈操作，轻松通过。
- **空间复杂度**：$O(n)$。栈最坏存放全部角色——例如攻击严格递增且防御严格递减的数据 `[[1,9],[2,8],[3,7],...]`，无人被弹出、全员滞留栈中；排序另需 $O(\log n)$ 递归栈。若改用单变量 `max_def` 镜像写法，额外空间可省到 $O(1)$。

## 7. 参考代码

### C++（单调栈主解）

```cpp
class Solution {
public:
    int numberOfWeakCharacters(vector<vector<int>>& properties) {
        // 攻击升序；同攻击防御降序——次键反向，严格性交给排序
        sort(properties.begin(), properties.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[0] != b[0] ? a[0] < b[0] : a[1] > b[1];
             });
        vector<int> st;                    // 栈：尚未找到支配者的角色的防御值
        int ans = 0;
        for (const auto& p : properties) {
            while (!st.empty() && st.back() < p[1]) {  // 栈顶被当前防御严格压制
                st.pop_back();
                ++ans;                                  // 弹出即弱，计数一次
            }
            st.push_back(p[1]);
        }
        return ans;
    }
};
```

### C++（镜像简化：单变量 max_def）

```cpp
class Solution {
public:
    int numberOfWeakCharacters(vector<vector<int>>& properties) {
        // 镜像方向：攻击降序；同攻击防御升序
        sort(properties.begin(), properties.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[0] != b[0] ? a[0] > b[0] : a[1] < b[1];
             });
        int maxDef = 0, ans = 0;           // 攻击严格更大的前缀中的最大防御
        for (const auto& p : properties) {
            if (p[1] < maxDef) ++ans;      // 左侧存在攻击严格更大且防御更大者
            else maxDef = p[1];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfWeakCharacters(self, properties: List[List[int]]) -> int:
        properties.sort(key=lambda p: (p[0], -p[1]))  # 攻击升序，同攻击防御降序
        st, ans = [], 0
        for _, d in properties:
            while st and st[-1] < d:      # 栈顶防御被严格压制 → 弹出计数
                st.pop()
                ans += 1
            st.append(d)
        return ans
```

## 8. 边界情况与易错点

1. **次键必须降序（最大暗礁）**：同攻击若按防御升序，`[[5,3],[5,4]]` 会把同组的 (5,3) 误弹计数（正确答案 0）。方向口诀：**主键升序定扫描方向，次键反向消同值歧义**。
2. **弹栈条件是严格小于**：`[[3,5],[4,5]]` 答案为 0——防御相等不构成支配，写成 `<=` 会错算 1。
3. **两维都要严格**：攻击相等或防御相等，任一不严格即非支配。示例 1 中 [6,3] 与 [3,6] 互相卡死就是这个边界。
4. **最小规模 $n = 2$**：`[[2,2],[3,3]]` 输出 1、`[[5,5],[5,5]]` 输出 0（相同角色互不支配）。
5. **栈空间是 $O(n)$ 不是 $O(1)$**：攻击升序 + 防御降序的极端数据会让全员滞留栈中；卡空间时可换单变量镜像写法。
6. **计数语义靠「一进一出」保证**：每个角色恰好入栈一次、至多出栈一次，`ans` 不会重复累计同一角色（证明见 §5）。
7. **无溢出风险**：`ans` ≤ $n \le 10^5$，属性值 ≤ $10^5$，`int` 足够。
