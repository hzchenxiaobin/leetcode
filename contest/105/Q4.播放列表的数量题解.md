# LeetCode 播放列表的数量 题解

## 1. 题目概述

- **标题 / 题号**：播放列表的数量（#920，hard）
- **链接**：https://leetcode.cn/problems/number-of-music-playlists/
- **来源**：LeetCode 第 105 场周赛 Q4
- **难度**：困难
- **标签**：数学、动态规划、组合数学

**题意**：音乐播放器里有 $n$ 首**不同**的歌，旅途中要听 `goal` 首歌（允许重复）。播放列表需满足：

1. **每首歌至少播放一次**；
2. 同一首歌再次播放之前，必须已经播放过**至少 $k$ 首其他歌**（即同一首歌的两次出现之间至少隔着 $k$ 个位置）。

求满足条件的播放列表数量，模 $10^9+7$。

**约束**：

- $0 \le k < n \le goal \le 100$

## 2. 示例

**示例 1**

```text
输入：n = 3, goal = 3, k = 1
输出：6
解释：goal = n，三首歌各放一次，即 3! = 6 种排列。
```

**示例 2**

```text
输入：n = 2, goal = 3, k = 0
输出：6
解释：k = 0 表示可以立即重复。长度 3、两首都出现的序列共 2³ − 2 = 6 种
      （减去的 2 种是 [1,1,1] 与 [2,2,2]，它们只用了一首歌）。
```

**示例 3**

```text
输入：n = 2, goal = 3, k = 1
输出：2
解释：只能交替播放 [1,2,1] 与 [2,1,2]；[1,1,2] 这类「连续两首相同」不合法。
```

**示例 4（自造，边界）**

```text
输入：n = 1, goal = 1, k = 0
输出：1
解释：只有 [1]。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有长度为 `goal` 的序列：每步有 $n$ 种选择，共 $n^{goal} = 100^{100}$ 种，天文数字；即便用「必须覆盖所有歌」做剪枝，也无济于事。

DFS 加记忆化看起来可行，但状态是「已经播放的序列」——信息量指数级。必须找到**只依赖少量统计量**的状态描述。

### 3.2 核心观察：只需知道「用了多少首不同的歌」

![状态：长度 i、已用 j 首不同的歌](images/wc105_q4_dp_state_concept.svg)

考虑从左往右构造播放列表。放在第 $i$ 个位置时，真正影响「能不能放某首歌」的信息只有：

- 已经用了多少首**不同**的歌（记为 $j$）——决定了还有几首新歌可放；
- 最近 $k$ 个位置放了哪些歌——决定了哪些旧歌暂时不能放。

但由规则可以推出：**最近 $k$ 个位置的歌必然两两不同**（否则那两首相同的歌距离 $\le k-1 < k+1$，已经违规）。因此「最近 $k$ 首」恰好是 $k$ 首互不相同的歌，它们都在已用的 $j$ 首之中。于是：

- 放**新歌**：可选 $n - j$ 首（第 $i$ 首是新歌时，前 $i-1$ 首用了 $j-1$ 首，故有 $n-(j-1)$ 种选法）；
- 放**旧歌**：可选的旧歌数是 $j - k$（总数 $j$ 减去最近 $k$ 首禁用的 $k$ 首），当 $j \le k$ 时为 0。

这样状态就压缩成二维：$dp[i][j]$ = 「长度为 $i$、恰好用了 $j$ 首不同歌的合法播放列表数」。

### 3.3 状态转移

![两层循环：i 从 1 到 goal，j 从 1 到 min(i, n)](images/wc105_q4_transition_flow.svg)

按「第 $i$ 首是新歌还是旧歌」分类：

$$
dp[i][j] =
\underbrace{dp[i-1][j-1] \cdot (n - j + 1)}_{\text{第 } i \text{ 首是新歌}}
\;+\;
\underbrace{dp[i-1][j] \cdot \max(j - k,\ 0)}_{\text{第 } i \text{ 首是旧歌}}
$$

边界与答案：

- $dp[0][0] = 1$（空列表，$0$ 首不同歌）；
- $dp[i][j] = 0$ 当 $j > i$ 或 $j > n$（不可能用比长度更多的歌）；
- 答案 $dp[goal][n]$：长度恰为 `goal`，且 $n$ 首歌**全部**用过（这正是「每首歌至少一次」）。

```text
1. dp[0][0] = 1
2. for i = 1 .. goal:
3.     for j = 1 .. min(i, n):
4.         dp[i][j] = dp[i-1][j-1] * (n - j + 1)
5.         if j > k:  dp[i][j] += dp[i-1][j] * (j - k)
6.         对 MOD 取模
7. 返回 dp[goal][n]
```

### 3.4 示例演算

![示例：n = 2, goal = 3, k = 1 → 答案 2](images/wc105_q4_walkthrough.svg)

以 $n = 2$、$goal = 3$、$k = 1$ 为例（$j$ 只取 1、2）：

| $i$ | $dp[i][1]$ | $dp[i][2]$ | 说明 |
|-----|------------|------------|------|
| 0 | 0 | 0 | $dp[0][0] = 1$ |
| 1 | $1 \times (2-0) = 2$ | 0 | 只放一首歌，两种选择 |
| 2 | $dp[1][0]\cdot 2 + dp[1][1]\cdot 0 = 0$ | $dp[1][1] \cdot (2-1) = 2$ | $j=1 \le k$，旧歌不可放 |
| 3 | $0 + dp[2][1]\cdot 0 = 0$ | $dp[2][1]\cdot 1 + dp[2][2]\cdot(2-1) = 2$ | 得到 2 |

答案 $dp[3][2] = 2$，正是 `[1,2,1]` 与 `[2,1,2]`。

对比示例 2（$k = 0$）：第 3 行 $j=1$ 时 `j > k` 成立，旧歌可取 $1-0 = 1$ 首，最终 $dp[3][2] = 6$。

## 4. 算法细节

1. **状态定义的两个参数**：$i$ 是长度（位置数），$j$ 是**不同**歌的数目（不是总播放次数）。
2. **新歌的系数**：前 $i-1$ 首用了 $j-1$ 首，剩余未用歌数为 $n-(j-1) = n-j+1$。
3. **旧歌的系数**：$\max(j-k, 0)$。当 $j \le k$ 时所有已用歌都在最近 $k$ 个位置中，不能再放，系数为 0；这也是「$k$ 较大时前若干位置只能放新歌」的体现。
4. **循环范围**：$j$ 上界是 $\min(i, n)$；$j > i$ 的状态无意义，保持 0。
5. **`dp[0][0] = 1`**：这是整个递推的种子，表示空序列有 1 种。
6. **取模**：每次乘法后取模，避免溢出；C++ 用 `long long` 承接中间结果（最大约 $10^9 \times 100$，仍在 64 位内）。
7. **`goal < n` 时自动为 0**：此时 $dp[goal][n]$ 访问不到（$j$ 上界是 $\min(i,n) = goal < n$），结果自然是 0，无需特判。
8. **空间优化**：转移只依赖 $i-1$ 层，可用两个一维数组滚动，空间降到 $O(n)$；但 $n, goal \le 100$ 时二维数组只有 $10^4$ 个元素，直接写更清晰。

## 5. 正确性证明

**定义**：称长度为 $i$ 的序列为**合法**的，若它满足题目两条规则（每首至少一次；同一首歌两次出现之间的位置差 $> k$）。令 $dp[i][j]$ 表示长度 $i$、恰好使用 $j$ 首不同歌的合法序列数。

**引理 1（最近 $k$ 首互不相同）**：若 $i \ge k+1$ 且序列合法，则位置 $i-k, i-k+1, \dots, i-1$ 上的歌两两不同。

**证明**：任取其中两个位置 $p < q$，则 $q - p \le (i-1) - (i-k) = k-1 \le k$。若两处歌相同，则位置差 $\le k$，违反「两次出现之间至少隔着 $k$ 个位置」（等价于位置差 $\ge k+1$）。故不同。∎

**引理 2（新歌分支）**：长度 $i$、$j$ 首不同、第 $i$ 首为**首次出现**的合法序列数为 $dp[i-1][j-1] \cdot (n-j+1)$。

**证明**：删去第 $i$ 首，前 $i-1$ 首是使用 $j-1$ 首不同歌的合法序列，数量为 $dp[i-1][j-1]$。第 $i$ 首必须是尚未出现的歌，共 $n-(j-1)$ 首可选。由于它是新歌，与之前任何位置都不相同，不会违反间隔规则；反之任一「合法前段 + 任一未用歌」都构成合法序列且第 $i$ 首恰为首次出现。故一一对应。∎

**引理 3（旧歌分支）**：长度 $i$、$j$ 首不同、第 $i$ 首为**重复出现**的合法序列数为 $dp[i-1][j] \cdot \max(j-k, 0)$。

**证明**：删去第 $i$ 首，前 $i-1$ 首是使用 $j$ 首不同歌的合法序列，数量 $dp[i-1][j]$。第 $i$ 首必须从已用的 $j$ 首中选，且不能是最近 $k$ 个位置（$i-k \sim i-1$）上的歌。分两种情形：

- $i-1 \ge k$：由引理 1，最近 $k$ 个位置上是 $k$ 首互不相同的歌，且都在已用的 $j$ 首中（注意此时必有 $j \ge k$，因为它们的歌都属于已用集合）。故禁选恰好 $k$ 首，可选 $j-k$ 首。若 $j = k$ 则 $j-k = 0$，与 $\max(j-k,0)$ 一致。
- $i-1 < k$：此时已用的 $j$ 首歌全部出现在前 $i-1 < k$ 个位置中，全都在禁选范围内，可选数为 $0$；另一方面 $j \le i-1 < k$，故 $j - k < 0$，$\max(j-k,0) = 0$，一致。

反过来，任取一个合法前段（用了 $j$ 首）与任一可选旧歌接在其后，得到的序列必然合法：该歌上一次出现的位置不在最近 $k$ 个位置中（否则它会落入禁选集），故两次出现的位置差 $\ge k+1$；前段内部的合法性由归纳假设保证。故两类之间一一对应。∎

**引理 4（分类完备且互斥）**：每个长度 $i$、$j$ 首不同的合法序列，其第 $i$ 首要么是首次出现、要么是重复出现，二者互斥且穷尽。

**证明**：按第 $i$ 首是否在前 $i-1$ 个位置出现过划分，两种情形不可能同时成立，也不会遗漏。∎

**定理**：$dp[i][j]$ 恰好等于长度 $i$、使用 $j$ 首不同歌的合法序列数；特别地，答案是 $dp[goal][n]$。

**证明**：对 $i$ 归纳。$i = 0$ 时唯一序列为空，$dp[0][0] = 1$，其余 $j$ 为 0，成立。设 $i-1$ 层正确，则由引理 2、3 得到两类序列的精确计数，由引理 4 两类互斥完备，相加即得 $dp[i][j]$，故 $i$ 层也正确。

最后，「每首歌至少播放一次」$\iff$ 使用的不同歌数 $j = n$（因为总共只有 $n$ 首），故答案为 $dp[goal][n]$。∎

## 6. 复杂度分析

- **时间**：$O(goal \cdot n)$。两层循环，每个状态 $O(1)$ 转移；$n, goal \le 100$ 时最多 $10^4$ 次转移。
- **空间**：$O(goal \cdot n)$。二维 DP 表最多 $101 \times 101$ 个 64 位整数；若用滚动数组可降到 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numMusicPlaylists(int n, int goal, int k) {
        const long long MOD = 1000000007;
        vector<vector<long long>> dp(goal + 1, vector<long long>(n + 1, 0));
        dp[0][0] = 1;
        for (int i = 1; i <= goal; i++) {
            for (int j = 1; j <= min(i, n); j++) {
                dp[i][j] = dp[i - 1][j - 1] * (n - j + 1) % MOD;
                if (j > k) {
                    dp[i][j] = (dp[i][j] + dp[i - 1][j] * (j - k)) % MOD;
                }
            }
        }
        return (int)dp[goal][n];
    }
};
```

### Python

```python
class Solution:
    def numMusicPlaylists(self, n: int, goal: int, k: int) -> int:
        MOD = 10 ** 9 + 7
        dp = [[0] * (n + 1) for _ in range(goal + 1)]
        dp[0][0] = 1
        for i in range(1, goal + 1):
            for j in range(1, min(i, n) + 1):
                dp[i][j] = dp[i - 1][j - 1] * (n - j + 1) % MOD
                if j > k:
                    dp[i][j] = (dp[i][j] + dp[i - 1][j] * (j - k)) % MOD
        return dp[goal][n]
```

## 8. 边界情况与易错点

1. **$j - k$ 写成负数**：当 $j \le k$ 时可选旧歌数为 0，必须用 $\max(j-k,0)$ 或加 `if (j > k)` 判断，否则会得到负数方案数（取模后变成巨大正数）。
2. **$k = 0$**：旧歌系数是 $j$，即所有已用歌都能立刻重放；示例 2 的答案 6 就靠这一项。
3. **`goal = n`**：答案应为 $n!$（每首恰好一次），可用来快速自测（示例 1：$3! = 6$）。
4. **`goal < n`**：答案 0（不可能每首至少一次）。二维数组访问不到 $j=n$ 的位置，结果自动为 0。
5. **忘记取模**：$dp$ 值会指数爆炸；每次乘法后都要 `% MOD`。
6. **`dp[0][0]` 没初始化**：整个表会全零。
7. **循环上界写 `n`**：当 $i < n$ 时 $j$ 不可能超过 $i$，虽然写了也不影响正确性（那些位置保持 0），但上界取 $\min(i,n)$ 更清晰且少做无用功。
8. **`int` 溢出**：C++ 中 $dp$ 值最大约 $10^9$，乘上系数（$\le 100$）后约 $10^{11}$，超出 `int`，必须用 `long long`。

**延伸思考**：若把约束改成「同一首歌两次播放之间至少隔 **恰好** $k$ 首」或「至多 $k$ 首」，转移中的系数会变成分段函数，需要对「最近 $k$ 首的集合大小」做更细的状态（例如记录最近 $k$ 首中不同歌的数量），状态维度上升。本题之所以能用 $j-k$ 这样简洁的系数，正是因为「合法序列的最近 $k$ 首必然两两不同」这一结构性质——识别出这类不变量，往往是把指数级问题压缩成多项式 DP 的关键。
