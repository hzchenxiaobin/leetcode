# LeetCode 将字符串中的元音字母排序 题解

## 1. 题目概述

- **标题 / 题号**：将字符串中的元音字母排序（#2785，medium）
- **链接**：https://leetcode.cn/problems/sort-vowels-in-a-string/
- **来源**：LeetCode 第 109 场双周赛 Q2
- **难度**：中等
- **标签**：字符串、排序

**题意**：给定下标从 0 开始的字符串 $s$，将其重排得到字符串 $t$，要求：(1) 所有**辅音字母**留在原位置（若 $s[i]$ 是辅音则 $t[i] = s[i]$）；(2) 所有**元音字母**按 **ASCII 值非递减**排列（对任意两个元音位置 $i < j$，$t[i]$ 的 ASCII 不大于 $t[j]$）。返回 $t$。元音为 `a e i o u` 的大小写共 10 种字符。

**约束**：

- $1 \le s.length \le 10^5$
- $s$ 只含英文大小写字母

## 2. 示例

**示例 1**

```text
输入：s = "lEetcOde"
输出："lEOtcede"
解释：元音 E、O、e 按 ASCII 排序为 E、O、e，回填到原元音位置；
辅音 l、t、c、d 原位不动。
```

**示例 2**

```text
输入：s = "lYmpH"
输出："lYmpH"
解释：s 中没有元音（Y 不是元音），原样返回。
```

## 3. 解题思路

### 3.1 暴力思路

枚举元音字符的所有重排方式再验证辅音位置不变——显然荒谬。朴素可行做法其实已经接近正解：把元音抽出来排个序再塞回去。真正的"暴力感"在于**排序方式**的选择：若对整个字符串按某种自定义序重排，或试图用 `tolower` 统一大小写再排，都会破坏题意（见 §8）。本题考点是把"位置集合"与"字符多重集"**分开处理**的正确姿势，以及 ASCII 序中大写在小写之前这一细节。

### 3.2 核心观察：元音位置集合与元音多重集彼此独立

![核心观察：收集、排序、回填三步](images/bw109_q2_collect_sort_fill.svg)

重排的自由度只落在元音位置上：辅音位置被 $t[i]=s[i]$ 钉死，元音位置上放什么字符不受限（只要还是元音）。于是答案由两个独立量决定：

- **哪些位置是元音**（集合 $P$，由 $s$ 唯一确定）；
- **元音字符的多重集** $V$（由 $s$ 唯一确定）。

要使元音按 ASCII 非递减，就是把 $V$ 排序后**从左到右**依次填入 $P$ 中的位置——这是唯一解。因此算法 = 一次扫描收集 $V$ → 对 $V$ 排序 → 一次扫描回填。

### 3.3 算法流程：ASCII 序里大写元音全部在小写元音之前

![ASCII 顺序：大写区在小写区左侧](images/bw109_q2_ascii_order.svg)

```text
1. isVowel(c)：c ∈ {a,e,i,o,u,A,E,I,O,U}
2. v = [c for c in s if isVowel(c)]      # 收集元音
3. sort(v)                                # 按 ASCII 升序（普通字符比较即可）
4. k = 0；从左到右扫 s：
       若 s[i] 是元音 → t[i] = v[k++]
       否则        → t[i] = s[i]
5. 返回 t
```

由于 `'A'..'U'` 的 ASCII 为 $65\sim85$、`'a'..'u'` 为 $97\sim117$，普通 `sort` 会把**所有大写元音排在小写元音之前**，且同大小写内部按字母序——这正是题目要求的"ASCII 值非递减"，无需任何自定义比较器。

### 3.4 示例演算

![示例演算：lEetcOde 的三步变换](images/bw109_q2_walkthrough.svg)

$s = $ `lEetcOde`：元音位置 $\{1, 2, 5, 7\}$，收集 $V = [E, e, O, e]$；排序得 $[E, O, e, e]$（ASCII $69 < 79 < 101 = 101$）；回填后 $t = $ `lEOtcede`。

## 4. 算法细节

1. **判断元音别漏大小写**：10 个字符 `aeiouAEIOU` 写全；用 `tolower(c)` 后再判也可以，但注意只在**判断**时用小写化，排序时必须保留原字符（否则 `E` 与 `e` 混淆）。
2. **排序直接用默认字符比较**：C++ `sort(v.begin(), v.end())`、Python `sorted(v)` 即 ASCII 序，不需要自定义 `key`。
3. **计数排序可省掉 $\log$ 因子**：元音只有 10 种，可以统计每种字符频次，然后按 `A E I O U a e i o u` 的固定顺序生成有序序列，回填时用一个队列弹出——$O(n + 10)$。本题 $n \le 10^5$，普通排序毫无压力，计数版可作为模板积累。
4. **回填的指针**：`k` 只在元音处自增；Python 里用 `iter` + `next` 一行完成，也可先转 `list(s)` 再原地改。
5. **不可原地改 const 输入**：C++ 的参数按值传入（`string s`），可直接修改；Python 字符串不可变，必须构造新串。
6. **复杂度不是瓶颈时的代码取舍**：两遍扫描（收集 + 回填）比合并成一遍更清晰；均摊 $O(n)$ 次字符判断。

## 5. 正确性证明

**引理 1（解的唯一性）**：满足题意的 $t$ 若存在，则唯一，且 $t$ 恰为"将 $V$ 升序填入 $P$"。

**证明**：题意要求 $t$ 在位置集 $P$ 上的字符是 $V$ 的一个排列（辅音位置固定后，元音位置只能是元音：否则 $t[i]$ 是辅音且 $t[i] \ne s[i]$ 违反条件 (1)；同时 $V$ 中字符必须全部用上，因为 $t$ 与 $s$ 等长且逐位字符来源被 (1) 约束后，元音位置个数 $= |V|$）。设 $P = \{p_1 < p_2 < \dots < p_k\}$，条件 (2) 要求 $t[p_1] \le t[p_2] \le \dots \le t[p_k]$（ASCII 序）。一个多重集的升序排列唯一，故 $t[p_j] = V_{(j)}$（$V$ 升序后的第 $j$ 个）。∎

**引理 2（算法产出该解）**："排序后按位置从左到右回填"得到的 $t$，其元音位置的字符序列恰为 $V$ 的升序排列，辅音位置等于 $s$。

**证明**：回填按 $p_1 < \dots < p_k$ 依次放置 $V_{(1)} \le \dots \le V_{(k)}$，故 $t[p_1] \le \dots \le t[p_k]$，且多重集为 $V$；非 $P$ 位置直接复制 $s$。∎

**定理**：上述算法返回的 $t$ 是满足题意的字符串，且是唯一的。

**证明**：由引理 2，$t$ 满足条件 (1)(2)；由引理 1，满足条件的字符串唯一，故算法正确且完备。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$，其中 $n = |s|$。收集与回填各 $O(n)$，排序元音 $O(k \log k)$（$k \le n$ 为元音个数）；用计数排序可降到 $O(n + 10)$。
- **空间**：$O(n)$。存放元音序列与结果串；辅助空间除排序外 $O(k)$（C++ 原地排序）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string sortVowels(string s) {
        auto isVowel = [](char c) {
            switch (c) {
                case 'a': case 'e': case 'i': case 'o': case 'u':
                case 'A': case 'E': case 'I': case 'O': case 'U':
                    return true;
                default:
                    return false;
            }
        };
        string v;                                 // 收集所有元音
        for (char c : s) if (isVowel(c)) v.push_back(c);
        sort(v.begin(), v.end());                 // 按 ASCII 升序
        size_t k = 0;
        for (char& c : s)                         // 回填到元音位置
            if (isVowel(c)) c = v[k++];
        return s;
    }
};
```

### Python

```python
class Solution:
    def sortVowels(self, s: str) -> str:
        vowels = set("aeiouAEIOU")
        vs = sorted(c for c in s if c in vowels)   # 收集元音并按 ASCII 排序
        it = iter(vs)
        return "".join(next(it) if c in vowels else c for c in s)
```

> 💡 两份代码均通过全部官方示例（`lEOtcede`、`lYmpH`），并做了 3000 组随机字符串（长度 $1\sim30$，含全元音、全辅音、单字符、`Y/y` 干扰位）的性质校验：辅音原位不变、元音 ASCII 非降、元音多重集与原串一致，`mismatch = 0`。

## 8. 边界情况与易错点

1. **大写在小写之前**：`'E'(69) < 'a'(97)`，混排时所有大写元音必须排在小写元音之前。若误按"不区分大小写的字母序"（例如以 `c.lower()` 为比较键）排序，`E` 与 `e` 会被视为相等而保持原相对顺序，得到如 `e E` 这样的错误输出；正确 ASCII 序应为 `E e`。
2. **`Y` 不是元音**：示例 2 的 `lYmpH` 专门埋了这个坑（`y` 无论大小写都不属于 `aeiou`）。
3. **判定与排序要分开**：`tolower` 只能用于判定是否元音；若把原字符小写化后放入排序序列，会改动输出字符本身。
4. **全元音 / 全辅音**：全元音时答案就是整个串的 ASCII 排序；全辅音时原样返回（回填指针始终为 0，天然正确）。
5. **空串不会出现**（$n \ge 1$），但代码对空串也安全（`join` 空迭代器得空串）。
6. **性能误判**：$n = 10^5$ 时任何 $O(n \log n)$ 都绰绰有余；真正的坑是把回填写成 $O(n^2)$ 的字符串拼接（Python 中用 `+=` 在最坏实现下可能退化，用 `"".join(...)` 或列表拼接最稳）。
