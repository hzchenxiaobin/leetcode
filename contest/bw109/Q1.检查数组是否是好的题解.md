# LeetCode 检查数组是否是好的 题解

## 1. 题目概述

- **标题 / 题号**：检查数组是否是好的（#2784，easy）
- **链接**：https://leetcode.cn/problems/check-if-array-is-good/
- **来源**：LeetCode 第 109 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序

**题意**：给定整数数组 `nums`，判断它是否是数组 $\mathrm{base}[n] = [1, 2, \dots, n-1, n, n]$ 的一个**排列**。$\mathrm{base}[n]$ 长度为 $n+1$，其中 $1 \sim n-1$ 各出现一次、$n$ 出现两次（例如 $\mathrm{base}[1] = [1,1]$，$\mathrm{base}[3] = [1,2,3,3]$）。是好数组返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \mathrm{nums.length} \le 100$
- $1 \le \mathrm{nums}[i] \le 200$

## 2. 示例

**示例 1**

```text
输入：nums = [2, 1, 3]
输出：false
解释：最大元素是 3，候选 n = 3，但 base[3] 长度为 4，nums 只有 3 个元素。
```

**示例 2**

```text
输入：nums = [1, 3, 3, 2]
输出：true
解释：最大元素是 3，nums 恰是 base[3] = [1,2,3,3] 的一个排列。
```

**示例 3**

```text
输入：nums = [1, 1]
输出：true
解释：最大元素是 1，nums 是 base[1] = [1,1] 的排列。
```

**示例 4**

```text
输入：nums = [3, 4, 4, 1, 2, 1]
输出：false
解释：最大元素是 4，候选 base[4] 长度为 5，而 nums 有 6 个元素；多出的第二个 1 不属于 base。
```

## 3. 解题思路

### 3.1 暴力思路

把 $n$ 从 1 枚举到某个上界，对每个 $n$ 构造 $\mathrm{base}[n]$，再检查 `nums` 是否是它的排列（比如两边都排序后比较，或用哈希表比对多重集）。$n$ 其实不用猜：若 `nums` 是好数组，最大元素必然等于 $n$ 且恰好出现两次——但即便锁定 $n = \max(\mathrm{nums})$，仍要逐个核对 $1 \sim n-1$ 各出现一次。这样做完全正确，只是**没必要枚举**：数组长度 $m$ 与 $n$ 满足 $m = n + 1$，也就是说 $n$ 被长度唯一确定，无需看最大值。

### 3.2 核心观察：排序后与"模板"逐位比对

![核心观察：base[n] 的结构模板](images/bw109_q1_base_structure.svg)

**排列 ⇔ 多重集相等 ⇔ 排序后逐位相等**。设 $m$ 为 `nums` 的长度，则好数组排序后必然恰好是 $[1, 2, \dots, m-1, m-1]$：前 $m-1$ 位是 $1 \sim m-1$ 各一个，最后一位是重复的 $n = m-1$。于是判定只需三步：排序 → 检查前 $m-1$ 位满足 $\mathrm{nums}[i] = i + 1$ → 检查末位 $\mathrm{nums}[m-1] = m - 1$。

这个"模板"是**由长度直接写死的**，不需要 `max` 参与——示例 4 中长度 6 对应模板末位 5，而排序后末位是 4，一步就能判负。

### 3.3 算法流程

```text
1. 将 nums 升序排序，记 m = nums.length
2. for i in [0, m-2]:
       若 nums[i] != i + 1 → 返回 false
3. 返回 nums[m-1] == m - 1
```

### 3.4 示例演算

![示例演算：好数组与坏数组的逐位比对](images/bw109_q1_sort_check_flow.svg)

**好例子** $[1,3,3,2]$：排序得 $[1,2,3,3]$，$m = 4$；前 3 位 $1,2,3$ 恰为 $1,2,3$，末位 $3 = m-1$ → `true`。

**坏例子** $[3,4,4,1,2,1]$：排序得 $[1,1,2,3,4,4]$，$m = 6$；模板是 $[1,2,3,4,5,5]$，第 2 位 $1 \ne 2$ → `false`（末位 $4 \ne 5$ 也对不上）。

## 4. 算法细节

1. **$n$ 由长度唯一确定**：好数组长度 $m = n + 1$，故 $n = m - 1$。题面示例的"看最大值"只是解释思路；代码里直接用长度构造模板最不易错。
2. **排序判等的两层含义**：前 $m-1$ 位 $\mathrm{nums}[i] = i+1$ 保证了 $1 \sim m-1$ 各出现一次（若某值缺失或重复，升序序列必有一位对不上）；末位单独判 $\mathrm{nums}[m-1] = m-1$，保证重复的是 $n$ 而不是别的值。
3. **等价计数法**：也可以开一个长度 $m$ 的计数数组（值域 $\le 200$），统计每个值的出现次数，要求 $\mathrm{cnt}[v] = 1$（$1 \le v \le m-1$）、$\mathrm{cnt}[m-1] = 2$、$\mathrm{cnt}[m] = 0$，其余为 0。$O(m + V)$，略快但代码更长；本题规模下排序法完全够。
4. **原地修改**：`sort` 直接在传入的 `nums` 上排，$O(1)$ 额外空间（不计递归栈）。
5. **特判不需要**：$m = 1$ 时循环不执行，返回 $\mathrm{nums}[0] == 0$，而 $\mathrm{nums}[0] \ge 1$，自动得 `false`——最短的 $\mathrm{base}[1]$ 也有 2 个元素，单元素数组不可能是好数组，逻辑天然正确。

## 5. 正确性证明

**引理 1（模板刻画）**：`nums` 是 $\mathrm{base}[n]$ 的排列，当且仅当 `nums` 排序（升序）后等于 $[1, 2, \dots, n-1, n, n]$。

**证明**：排列是同一多重集的重新排列，因此"是排列" ⇔ 两数组作为多重集相等。两个多重集相等 ⇔ 各自升序排序后逐位相等（升序排列是多重集的规范形式，由值的多重集唯一决定）。而 $[1,2,\dots,n-1,n,n]$ 正是 $\mathrm{base}[n]$ 的升序排列，因为它已升序且无重排余地。∎

**引理 2（长度锁定 $n$）**：若 `nums` 是好数组且长度为 $m$，则 $n = m - 1$。

**证明**：$\mathrm{base}[n]$ 长度为 $n + 1$，排列不改变长度，故 $m = n + 1$。∎

**定理**：设 `nums` 长度为 $m$，升序排序后记为 $a$。`nums` 是好数组，当且仅当 $a[i] = i + 1$ 对所有 $0 \le i \le m-2$ 成立，且 $a[m-1] = m-1$。

**证明**：由引理 2，只需判定"`nums` 是 $\mathrm{base}[m-1]$ 的排列"。由引理 1，这等价于 $a$ 逐位等于 $[1, 2, \dots, m-2, m-1, m-1]$。该模板前 $m-1$ 项为 $i + 1$（$i = 0, \dots, m-2$），末项为 $m - 1$，与判定条件逐项对应。∎

## 6. 复杂度分析

- **时间**：$O(m \log m)$，排序主导；随后的逐位检查 $O(m)$。$m \le 100$，可忽略不计。
- **空间**：$O(1)$ 额外空间（原地排序；若用计数法则为 $O(V)$，$V \le 201$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isGood(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int m = (int)nums.size();
        for (int i = 0; i + 1 < m; ++i)          // 前 m-1 位必须是 1..m-1
            if (nums[i] != i + 1) return false;
        return nums[m - 1] == m - 1;             // 最后一位是重复的 n = m-1
    }
};
```

### Python

```python
class Solution:
    def isGood(self, nums: list[int]) -> bool:
        nums.sort()
        m = len(nums)
        return all(v == i + 1 for i, v in enumerate(nums[:m - 1])) and nums[-1] == m - 1
```

> 💡 两份代码均通过全部 4 组官方示例；另用「构造 $\mathrm{base}[\max]$ 再比对多重集」的独立暴力做了 5000 组随机对拍（长度 $1\sim10$、值 $1\sim9$），`mismatch = 0`。

## 8. 边界情况与易错点

1. **别用 `max` 当唯一依据**：只检查"最大值出现两次"不够——$[1,1,4,4]$ 中 4 出现两次但它不是好数组（缺 2、3，多 1）。排序逐位比对同时校验了所有值。
2. **长度与 $n$ 的关系**：$m = n+1$，模板末位是 $m-1$ 不是 $m$；写成 $\mathrm{nums}[m-1] == m$ 会把 $[1,2,2]$（$m=3$，应为 $[1,2,2]$ ✓）误判——注意 $[1,2,2]$ 恰是 $\mathrm{base}[2]$，末位 $2 = m-1$，若与 $m$ 比较就错了。
3. **重复值位置**：重复的 $n$ 排序后必然落在**最后两位**，所以只需单独判末位，倒数第二位已被 $\mathrm{nums}[m-2] = m-1$ 覆盖，无需再查"出现次数恰为 2"。
4. **单元素数组**：$m=1$ 时直接返回 `false`（$\mathrm{base}[n]$ 最短长度为 2），上述代码天然满足。
5. **值域溢出**：$\mathrm{nums}[i] \le 200$，模板比较用 `int` 即可，无溢出风险。

**延伸思考**：本题的判定本质是**多重集相等**，排序判等与计数判等是它的两种标准实现（$O(m\log m)$ vs $O(m+V)$）。当值域很小且要判多个数组时，计数法可以做成"计数签名"（如把每个值的出现次数编码成字符串/大整数），一次预处理、多次 $O(m)$ 比对；若把"互不相同"改成"可重复"，则模板末位不再固定，需要整套计数校验——这也是不少面试变体的出发点。
