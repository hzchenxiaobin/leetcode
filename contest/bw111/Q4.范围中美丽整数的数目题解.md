# LeetCode 范围中美丽整数的数目 题解

## 1. 题目概述

- **标题 / 题号**：范围中美丽整数的数目（#2827，hard）
- **链接**：https://leetcode.cn/problems/number-of-beautiful-integers-in-the-range/
- **来源**：LeetCode 第 111 场双周赛 Q4
- **难度**：困难
- **标签**：数学、动态规划、数位 DP

**题意**：正整数 $x$ 是**美丽的**，当且仅当：(1) $x$ 的十进制表示中**偶数数位个数与奇数数位个数相同**；(2) $x$ 能被 $k$ 整除。给定 $low, high, k$，返回 $[low, high]$ 中美丽整数的数目。

**约束**：

- $0 < low \le high \le 10^9$
- $0 < k \le 20$

## 2. 示例

**示例 1**

```text
输入：low = 10, high = 20, k = 3
输出：2
解释：范围 [10,20] 中只有 12 与 18 是美丽的：
     12 与 18 各含 1 个奇数位、1 个偶数位（平衡），且都能被 3 整除。
     15 虽被 3 整除，但两个数位 1、5 都是奇数位，奇偶不平衡。
     16 奇偶平衡但 16 mod 3 = 1，不满足整除。
```

**示例 2**

```text
输入：low = 1, high = 10, k = 1
输出：1
解释：只有 10 满足（1 奇 1 偶，被 1 整除）。
```

**示例 3**

```text
输入：low = 5, high = 5, k = 2
输出：0
解释：5 只有一个奇数位，奇偶数位不等。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $[low, high]$ 中每个数，逐位统计奇偶并判整除——$O((high - low + 1) \times 10)$，$high = 10^9$ 时约 $10^{10}$ 次操作，必然超时。区间计数问题的标准出路是**前缀和转化**：设 $f(n)$ 为 $[1, n]$ 中美丽整数的个数，则答案为 $f(high) - f(low - 1)$；而 $f(n)$ 用**数位 DP** 在与 $n$ 的位数成正比的状态空间内精确算出。

### 3.2 核心观察：三个约束 → 三个状态分量

![核心观察：数位 DP 状态设计（pos, diff, mod, tight, started）](images/bw111_q4_digitdp_states.svg)

从高位到低位逐位填数，填数过程中需要记住三件事才能在填完时判定「美丽」：

- **奇偶平衡** `diff`：已填数位中「偶数位个数 − 奇数位个数」。填偶数位 $d$（$d \in \{0,2,4,6,8\}$）时 $diff{+}{+}$，填奇数位时 $diff{-}{-}$；最终要求 $diff = 0$。用**差值**而不是两个计数器，把二维状态压成一维（两者可以互相推出：位数 $=$ 偶数 + 奇数，差值确定则个数确定）。
- **模 $k$ 余数** `mod`：填入新数位 $d$ 后余数变为 $(mod \times 10 + d) \bmod k$（竖式进位的同余表达）；最终要求 $mod = 0$。
- **贴上界标志** `tight`：当前已填前缀是否与 $n$ 的前缀完全相同。贴着时下一位至多填 $n$ 的对应数位，否则可以填 $0..9$。
- 另需 `started` 标志处理**前导零**：$0$ 不算数位（否则 `10` 会被误统计成两位而实际有效位是两位 1、0 —— 恰好这里 10 的确两位，但 `007` 这类填法会把 7 误判为三位数，导致奇偶位计数错误）。`started = 0` 时填 $d = 0$ 仍是未开始，`diff`/`mod` 不变。

**关键规模核算**：位数 $\le 10$，$diff \in [-10, 10]$（存成 $diff + 10 \in [0, 20]$），$mod \in [0, k) \subseteq [0, 20)$，状态总数 $\le 10 \times 21 \times 20 = 4200$，每个状态转移 10 个数位——记忆化后 $f(n)$ 的计算量约 $4 \times 10^4$，两个前缀共 $10^5$ 以内，瞬间完成。

### 3.3 算法流程

```text
计算 f(n)（[1,n] 中美丽整数个数）：
1. 把 n 的十进制各位取出为 digits[0..L-1]（高位在前）
2. 记忆化搜索 dfs(pos, diff, mod, tight, started)：
   pos == L：返回 (started 且 diff == 0 且 mod == 0) ? 1 : 0
   若 started 且非 tight：查 memo[pos][diff+10][mod]，命中直接返回
   枚举数位 d ∈ [0, hi]，hi = tight ? digits[pos] : 9：
       nstarted = started 或 d > 0
       若 nstarted：ndiff = diff ± 1（d 偶 +1，d 奇 −1）
                    nmod  = (mod*10 + d) mod k
       否则（仍是前导零）：ndiff = diff，nmod = mod
       累加 dfs(pos+1, ndiff, nmod, tight 且 d==hi, nstarted)
3. 返回 dfs(0, 0, 0, true, false)
答案 = f(high) − f(low − 1)
```

### 3.4 示例演算

![示例演算：f(20) 与 f(9) 的差给出 [10,20] 的答案](images/bw111_q4_prefix_diff.svg)

以示例 1（$low = 10$, $high = 20$, $k = 3$）为例。$f(20)$ 逐位枚举到的两位数（无前导零）中：$10 \to (1\text{奇}1\text{偶}, 10 \bmod 3 = 1)$ 不美丽；$12 \to$ 奇偶平衡且 $12 \bmod 3 = 0$ ✓；$18$ ✓；$11, 13, \dots$ 奇偶不平衡；$20 \to (2\text{偶}0\text{奇}, 20 \bmod 3 = 2)$ 不美丽。故 $f(20) = 2$（$[1,20]$ 中美丽的只有 12、18——一位数 1~9 奇偶位必不平衡）。$f(9) = 0$。答案 $= f(20) - f(9) = 2 - 0 = 2$ ✓。

| 数 | 数位 | 奇位 | 偶位 | 平衡？ | mod 3 | 美丽？ |
|----|------|------|------|--------|-------|--------|
| 10 | 1,0 | 1 | 1 | ✓ | 1 | ✗ |
| 12 | 1,2 | 1 | 1 | ✓ | 0 | ✓ |
| 15 | 1,5 | 2 | 0 | ✗ | 0 | ✗ |
| 18 | 1,8 | 1 | 1 | ✓ | 0 | ✓ |
| 20 | 2,0 | 0 | 2 | ✗ | 2 | ✗ |

## 4. 算法细节

1. **前缀差**：答案 $= f(high) - f(low - 1)$。$f$ 定义在 $[1, n]$ 上；$low = 1$ 时 $f(0) = 0$（`n <= 0` 直接返回 0，别让空数位串误产生计数）。
2. **记忆化的作用域**：只有 `started = true` 且 `tight = false` 的状态才可缓存——`tight` 状态依赖具体的 $n$（同一个 `pos/diff/mod` 在不同 $n$ 的上界下枚举范围不同），`started = false` 只出现在从最高位开始的极少数路径上（每层至多 1 条），不缓存也不会超时。
3. **diff 的偏移存储**：差值取值 $[-L, L] \subseteq [-10, 10]$，数组下标加 10 变非负；$k \le 20$ 使 $mod < 20$，`memo[11][21][21]` 即可容纳（$k = 20$ 时 mod 最大 19，开 21 列留裕量）。
4. **余数转移**：新余数 $(mod \times 10 + d) \bmod k$ 来自「已填前缀构成的数 $P$ 满足 $P \equiv mod$，填 $d$ 后数为 $10P + d$，$(10P + d) \bmod k = (10 \cdot mod + d) \bmod k$」。这是竖式进位的同余不变量，$k \le 20$ 无溢出。
5. **终局判定**：`pos == L` 时要求 `started`（排除全前导零即数 0 本身——题目从 1 起且 0 无效）、`diff == 0`（奇偶位相等，隐含总位数为偶数）、`mod == 0`（被 $k$ 整除），三者缺一不可。
6. **位数不齐的处理**：数位 DP 天然覆盖「位数小于 $L$」的情形——它们就是 `started` 在中途转真、随后 `tight` 恒为假的路径（前缀小于 $n$ 的最高位后自由填），无需单独枚举位数。
7. **复杂度核算**：$f(n)$ 的状态空间 $L \times (2L+1) \times k \le 10 \times 21 \times 20 = 4200$，转移 $10$ 次，约 $4.2 \times 10^4$ 次基本操作；调两次 $f$ 共 $10^5$ 以内。$10^9$ 上界（10 位数）毫无压力。

## 5. 正确性证明

**引理 1（前缀差）**：$[low, high]$ 中美丽整数的个数 $= f(high) - f(low - 1)$，其中 $f(n) = \#\{x \in [1, n] : x \text{ 美丽}\}$。

**证明**：$[1, high] = [1, low-1] \uplus [low, high]$（$low \ge 1$ 保证不交且并完备），计数在不相交并上可加。∎

**引理 2（数位路径对应）**：设 $n$ 有 $L$ 位（十进制、无前导零）。$[1, n]$ 中每个数 $x$ 与「长度 $L$、从高位起填数、全程 `started` 最终为真、且数值不超过 $n$」的填数路径一一对应；路径终点收集的 $(diff, mod)$ 恰为 $x$ 的（偶数位 − 奇数位）与 $x \bmod k$。

**证明**：$x$ 的十进制表示无前导零，设其长 $\ell \le L$。对应路径：前 $L - \ell$ 步填 $d = 0$ 且 `started` 保持假（前导零，不改变 `diff/mod`），第 $L - \ell + 1$ 步填 $x$ 的最高位（非零，`started` 转真），其余步依次填 $x$ 的各位。反之任何终局 `started` 为真的路径去掉前导零后读出的数位串即某个正整数 $x$，路径与 $x$ 相互唯一确定。数值约束：路径全程不越界（每一步 `tight` 时 $d \le digits[pos]$）当且仅当 $x \le n$——这是「逐位比较不超上界」的标准等价。`diff` 与 `mod` 的终值：`started` 转真后每步的 $\pm 1$ 与 $(mod \times 10 + d) \bmod k$ 正是逐位累计奇偶差与竖式同余，终值即 $x$ 的奇偶位差与 $x \bmod k$。∎

**引理 3（记忆化不改变结果）**：对同一 $(pos, diff, mod)$ 且 `started = true, tight = false` 的两次搜索调用，其子树返回值相同。

**证明**：该状态下后续能填的数位集合只由 $(pos, tight)$ 决定，而 `tight = false` 已保证后续每步可选 $0..9$、永远不再受 $n$ 约束；终局判定只看 $(diff, mod, started)$。因此子树的返回值仅由 $(pos, diff, mod)$ 决定，与到达该状态的历史路径无关，缓存命中安全。∎

**定理**：算法返回 $[low, high]$ 中美丽整数的个数。

**证明**：由引理 1 只需证 $f(n)$ 正确。`dfs(0,0,0,true,false)` 枚举的正是引理 2 中全部合法路径（初始 `tight`、每步界内），终局判定 `diff == 0 且 mod == 0 且 started` 恰好筛选出奇偶位相等且被 $k$ 整除的正整数 $x \le n$；由引理 2 的双射，路径计数与整数计数相等。记忆化由引理 3 保证不改变任何返回值。故 $f(n)$ 正确，定理成立。∎

## 6. 复杂度分析

- **时间**：$O(L \cdot D \cdot k \cdot 10)$，$L = 10$、$D = 2L + 1 = 21$、$k \le 20$，单个 $f(n)$ 约 $4 \times 10^4$ 次操作；全程两次 $f$，总计 $O(L^2 k)$ 量级、实际不到 $10^5$ 次基本操作。
- **空间**：$O(L \cdot D \cdot k) \approx 4200$ 个整数的记忆化数组（C++ 固定 `int memo[11][21][21]`），加递归栈深 $O(L)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfBeautifulIntegers(int low, int high, int k) {
        return countUpTo(high, k) - countUpTo(low - 1, k);
    }
private:
    int K;
    vector<int> digits;
    int memo[11][21][21];        // pos, diff+10, mod —— 仅 started=1 且 tight=0 的状态
    int countUpTo(int n, int k) {
        if (n <= 0) return 0;
        K = k;
        digits.clear();
        for (int x = n; x > 0; x /= 10) digits.push_back(x % 10);
        reverse(digits.begin(), digits.end());
        memset(memo, -1, sizeof(memo));
        return dfs(0, 0, 0, true, false);
    }
    // diff = 已放数位中(偶数位个数 − 奇数位个数)
    int dfs(int pos, int diff, int mod, bool tight, bool started) {
        if (pos == (int)digits.size())
            return (started && diff == 0 && mod == 0) ? 1 : 0;
        if (started && !tight) {
            int& res = memo[pos][diff + 10][mod];
            if (res != -1) return res;
            int r = 0;
            for (int d = 0; d <= 9; ++d) {
                int nd = diff + (d % 2 == 0 ? 1 : -1);
                int nm = (mod * 10 + d) % K;
                r += dfs(pos + 1, nd, nm, false, true);
            }
            return res = r;
        }
        int r = 0;
        int hi = tight ? digits[pos] : 9;
        for (int d = 0; d <= hi; ++d) {
            bool nstarted = started || d > 0;
            int nd = diff, nm = mod;
            if (nstarted) {                       // 前导 0 不计入数位
                nd = diff + (d % 2 == 0 ? 1 : -1);
                nm = (mod * 10 + d) % K;
            }
            r += dfs(pos + 1, nd, nm, tight && d == hi, nstarted);
        }
        return r;
    }
};
```

### Python

```python
from functools import lru_cache

class Solution:
    def numberOfBeautifulIntegers(self, low: int, high: int, k: int) -> int:
        def count_up_to(n: int) -> int:            # [1, n] 中美丽整数个数
            if n <= 0:
                return 0
            s = str(n)
            L = len(s)

            @lru_cache(maxsize=None)
            def dfs(pos, diff, mod, tight, started):
                if pos == L:
                    return 1 if (started and diff == 0 and mod == 0) else 0
                hi = int(s[pos]) if tight else 9
                total = 0
                for d in range(hi + 1):
                    ntight = tight and d == hi
                    nstarted = started or d > 0
                    if nstarted:                   # 前导 0 不算数位
                        ndiff = diff + (1 if d % 2 == 0 else -1)
                        nmod = (mod * 10 + d) % k
                        total += dfs(pos + 1, ndiff, nmod, ntight, True)
                    else:
                        total += dfs(pos + 1, diff, mod, ntight, False)
                return total

            return dfs(0, 0, 0, True, False)       # dfs 随每次调用新建，缓存天然隔离

        return count_up_to(high) - count_up_to(low - 1)
```

> 💡 两份代码均通过官方示例（`2`、`1`、`0`），并与逐数判定的暴力做了 4.3 万组（C++）/ 6 千组（Python）随机对拍（$high \le 20000$，覆盖 9→10、99→100、999→1000、9999→10000 等进位边界），另对 $n \le 3000$ 的每个 $n$ 做了前缀逐点核对，失配数为 0。大规模抽查：$f(10^9, k{=}20) = 1105750$，$f(10^9, k{=}1) = 24894045$，C++ 与 Python 输出完全一致。

## 8. 边界情况与易错点

1. **$low = 1$ 时 $f(0)$**：`n <= 0` 必须直接返回 0，否则空数位串会走 `pos == 0 == L` 分支——幸好 `started` 为假不会误判美丽，但依赖这一点是脆弱的，显式判 0 更稳。
2. **记忆化的条件别放宽**：`tight = true` 的状态**不可缓存**（依赖具体 $n$ 的上界）；`started = false` 同样不缓存（每层至多一条，不缓存不影响复杂度）。把缓存条件写成「非 tight 即缓存」会在 `started = false` 时因 `diff` 未区分语义而算错。
3. **前导零必须跳过统计**：`started` 为假时填 $d = 0$ 不改 `diff/mod`；若误把 0 当偶数位，`7` 会被算成「1 奇 + 前导若干偶」的错位计数。
4. **diff 的取值范围与偏移**：$|diff| \le L \le 10$，数组下标 `diff + 10`；开小了（如 `[21]` 只够 $[-10,10]$）在 $L = 10$ 恰好贴边，谨慎起见按 $L$ 上界开。
5. **一位数永远不美丽**：奇偶位相等要求总位数为偶数，最短也是两位（如 10、12）——这不是特判，而是 `diff` 语义的自然推论，写测试时可以用它自检。
6. **Python 的 `lru_cache` 复用陷阱**：`dfs` 闭包捕获了当前 $n$ 的字符串与位数，两次 `count_up_to` 必须各用独立的缓存——本实现把 `dfs` 定义在 `count_up_to` 内部（每次调用新建），天然隔离；若把缓存提升到类级别或外部，务必在两次调用之间 `cache_clear()`，否则第一次的上界会污染第二次的枚举范围。
7. **模 $k$ 的转移**：是 $(mod \times 10 + d) \bmod k$ 而非 $(mod + d) \bmod k$——漏掉 $\times 10$ 是数位 DP 最常见笔误，对拍会立刻暴露（几乎所有 $k > 1$ 的用例都错）。
8. **$k = 1$ 退化**：任何数都被 1 整除，`mod` 恒 0，状态维度自动坍缩，无需特判（对拍里专门含 $k = 1$）。
