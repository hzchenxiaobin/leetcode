# LeetCode 统计和小于目标的下标对数目 题解

## 1. 题目概述

- **标题 / 题号**：统计和小于目标的下标对数目（#2824，easy）
- **链接**：https://leetcode.cn/problems/count-pairs-whose-sum-is-less-than-target/
- **来源**：LeetCode 第 111 场双周赛 Q1
- **难度**：简单
- **标签**：数组、双指针、二分查找、排序

**题意**：给定长度为 $n$ 的整数数组 `nums` 与整数 `target`，返回满足 $0 \le i < j < n$ 且 $nums[i] + nums[j] < target$ 的下标对 $(i, j)$ 的数目。

**约束**：

- $1 \le n \le 50$
- $-50 \le nums[i] \le 50$，$-50 \le target \le 50$

## 2. 示例

**示例 1**

```text
输入：nums = [-1,1,2,3,1], target = 2
输出：3
解释：满足条件的下标对是 (0,1)、(0,2)、(0,4)；
     (0,3) 不计入，因为 -1 + 3 = 2 并不严格小于 target = 2。
```

**示例 2**

```text
输入：nums = [-6,2,5,-2,-7,-1,3], target = -2
输出：10
```

**示例 3（边界补充）**

```text
输入：nums = [7], target = 100
输出：0
解释：只有一个元素，构不成任何数对。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有下标对 $(i, j)$（$i < j$），逐一判断 $nums[i] + nums[j] < target$，时间 $O(n^2)$。$n \le 50$ 时至多 $\binom{50}{2} = 1225$ 对，暴力完全可以接受——这也是官方提示的意图。但作为签到题，本题真正值得沉淀的是**排序 + 双指针**这一计数模板：一旦 $n$ 放大到 $10^5$ 甚至 $10^6$（比如 LC 1099「小于 K 的两数之和」的加强版），$O(n^2)$ 就不可行了。

### 3.2 核心观察：条件只看「数值对」，排序不改变答案

![核心观察：排序后数对条件不变，双指针批量计数](images/bw111_q1_sort_two_pointers.svg)

判断条件 $nums[i] + nums[j] < target$ 只依赖**两个位置的数值**，与它们的下标顺序无关；而「下标对 $(i,j)$，$i<j$」与「无序数值对 $\{nums[i], nums[j]\}$（保序取一次）」一一对应。因此把数组排序后统计，答案不变——排序只是把同一组数值换了一种摆放顺序。

排序带来关键的单调性：固定右端 $right$，若 $nums[left] + nums[right] < target$，那么对任意 $left < x < right$，都有 $nums[x] \le nums[right]$，于是 $nums[left] + nums[x] \le nums[left] + nums[right] < target$——**一整批 $right - left$ 个数对同时达标**，无需逐个检查。

### 3.3 算法流程

```text
1. 将 nums 升序排序
2. left = 0, right = n − 1, ans = 0
3. 当 left < right 时循环：
       若 nums[left] + nums[right] < target：
           ans += right − left        # (left, left+1..right) 全部满足
           left += 1                  # left 配对完毕，右移
       否则：
           right −= 1                 # 与 right 配对的最小和都超了，right 报废
4. 返回 ans
```

### 3.4 示例演算

![示例演算：示例 2 排序后的双指针走查](images/bw111_q1_walkthrough.svg)

以示例 2 为例：排序后 $nums = [-7, -6, -2, -1, 2, 3, 5]$，$target = -2$。

| 步骤 | left | right | 和 | 判断 | 动作 | ans |
|------|------|-------|-----|------|------|-----|
| 1 | 0（−7） | 6（5） | −2 | $-2 < -2$ 不成立 | right−− | 0 |
| 2 | 0（−7） | 5（3） | −4 | 成立 | ans += 5，left++ | 5 |
| 3 | 1（−6） | 5（3） | −3 | 成立 | ans += 4，left++ | 9 |
| 4 | 2（−2） | 5（3） | 1 | 不成立 | right−− | 9 |
| 5 | 2（−2） | 4（2） | 0 | 不成立 | right−− | 9 |
| 6 | 2（−2） | 3（−1） | −3 | 成立 | ans += 1，left++ | 10 |

循环结束（left 与 right 相遇），返回 $10$，与官方答案一致。

## 4. 算法细节

1. **排序是原地的**：直接 `sort(nums.begin(), nums.end())` / `nums.sort()`，题目不要求保留下标，统计结果不受影响。
2. **批量计数的方向**：满足条件时累加 $right - left$（left 与 $(left, right]$ 内每个位置配对都达标），然后**移动 left**；不满足时只有 right 需要放弃（$nums[right]$ 与最小的 $nums[left]$ 配对都不达标，与更大的左值更不行），故移动 right。两个方向别写反。
3. **相等的元素各自计数**：数对按「下标对」计数而非「数值对」，例如 $[1,1]$、$target=3$ 中 $(0,1)$ 是一个合法数对。排序不会丢失重复元素，计数自动正确。
4. **严格小于**：条件是 $< target$ 而非 $\le$，双指针判断处不要顺手写成 `<=`（示例 1 的 (0,3) 正是和等于 target 被排除的例子）。
5. **另一种等价写法**：固定每个 $i$，在排序数组中二分找最后一个 $j$ 使 $nums[i] + nums[j] < target$（`lower_bound(target - nums[i])` 前移一位），累加计数——这也是本题标签里「二分查找」的来历，复杂度同为 $O(n \log n)$。
6. **无溢出风险**：$|nums[i] + nums[j]| \le 100$，`int` 足够；$ans \le \binom{50}{2} < 10^4$。

## 5. 正确性证明

**引理 1（排序不变性）**：对任意数组 $A$ 与其升序排列 $B$，$\#\{(i,j) : i < j,\ A[i] + A[j] < t\} = \#\{(i,j) : i < j,\ B[i] + B[j] < t\}$。

**证明**：设 $\sigma$ 为把 $A$ 排成 $B$ 的置换（$B[\sigma(i)] = A[i]$）。$\sigma$ 是 $\{0,1,\dots,n-1\}$ 到自身的双射，故 $(i,j) \mapsto (\min(\sigma(i),\sigma(j)),\ \max(\sigma(i),\sigma(j)))$ 把「$A$ 的有序下标对」双射到「$B$ 的有序下标对」，且 $A[i] + A[j] = B[\sigma(i)] + B[\sigma(j)]$，条件真值在双射下保持。两个有限集合经双射保持基数相等。∎

**引理 2（计数不变量）**：算法任意时刻，`ans` 等于满足 $B[x]+B[y]<target$ 且**至少一端已移出未决区间** $[left, right]$ 的数对个数（$B$ 为排序后的数组，未决区间初始为 $[0, n-1]$）。

**证明**：对循环步数归纳。初始未决区间为全集，没有任何数对的端点在外，`ans = 0` 成立。设某步命题成立，考察下一步。若 $B[left]+B[right] \ge target$：对任意 $left \le x < right$，由升序有 $B[x]+B[right] \ge B[left]+B[right] \ge target$，即**含 right 的所有未决数对都不满足条件**；把 right 移出后，「至少一端在外」的数对新增的恰是这批（全不满足），`ans` 不加即保持正确。若 $B[left]+B[right] < target$：对任意 $left < x \le right$，$B[left]+B[x] \le B[left]+B[right] < target$，即**含 left 的所有未决数对（共 $right-left$ 个）全部满足条件**；把 left 移出后它们恰好构成「一端在外且满足」的新增数对，累加 $right-left$ 后命题保持。∎

**定理**：算法返回满足条件的下标对总数。

**证明**：由引理 1，只需对排序后的数组 $B$ 证明。循环每步未决区间严格缩小（left 右移或 right 左移），必然终止；终止时 $left \ge right$，未决区间内不再包含任何数对，故全部 $\binom{n}{2}$ 个数对都「至少一端在外」。由引理 2 的不变量，此时 `ans` 恰等于其中满足 $B[x]+B[y]<target$ 的数对个数，即所求总数。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序主导；双指针主循环中 $left$ 与 $right$ 合计至多移动 $n$ 次，每次 $O(1)$（含一次批量累加）。$n = 50$ 时与 $O(n^2)$ 暴力无异，但规模增大后优势立即显现。
- **空间**：$O(1)$ 额外空间（C++ 原地 `sort`；Python `list.sort` 亦为原地）。若语言内置排序需要辅助空间则记 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countPairs(vector<int>& nums, int target) {
        sort(nums.begin(), nums.end());
        int n = nums.size(), ans = 0;
        int left = 0, right = n - 1;
        while (left < right) {
            if (nums[left] + nums[right] < target) {
                ans += right - left;   // (left, left+1..right) 全部满足
                ++left;
            } else {
                --right;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countPairs(self, nums: list[int], target: int) -> int:
        nums.sort()
        left, right = 0, len(nums) - 1
        ans = 0
        while left < right:
            if nums[left] + nums[right] < target:
                ans += right - left     # (left, left+1..right) 全部满足
                left += 1
            else:
                right -= 1
        return ans
```

> 💡 两份代码均通过官方示例（`3`、`10`）与 $n = 1$ 边界，并与 $O(n^2)$ 暴力做了 20 万组（C++）/ 3 万组（Python）随机对拍（$n \le 50$，值域 $[-50, 50]$ 全覆盖），失配数为 0。

## 8. 边界情况与易错点

1. **$n = 1$**：无任何数对，循环体不执行，返回 0；不要特判遗漏导致访问越界（双指针写法天然安全）。
2. **严格小于**：`< target` 别写成 `<=`；和恰好等于 target 的数对不计入（示例 1 的 (0,3) 即反例）。
3. **负数与负 target**：全负数组、负 target 都合法（示例 2 的 target 就是 $-2$），双指针判断对负数完全一致，无需任何特判。
4. **批量累加的计数**：是 `right - left` 而不是 `right - left + 1`（数对 $(left, left)$ 不存在），也不是 `n - left`（right 右侧的下标已弃用）。
5. **重复元素**：相同数值的不同下标对都要计数；排序不去重，切勿先 `unique`。
6. **移动方向别反**：满足条件时动 left（left 已「配额用尽」），不满足时动 right；写反会漏计或死循环（例如两个指针同时不动）。
