# LeetCode 循环增长使字符串子序列等于另一个字符串 题解

## 1. 题目概述

- **标题 / 题号**：循环增长使字符串子序列等于另一个字符串（#2825，medium）
- **链接**：https://leetcode.cn/problems/make-string-a-subsequence-using-cyclic-increments/
- **来源**：LeetCode 第 111 场双周赛 Q2
- **难度**：中等
- **标签**：双指针、字符串、贪心

**题意**：一次操作中你可以选择 `str1` 中**任意若干个**下标（可零个），把每个选中下标 $i$ 上的字符**循环递增**一步（`a→b`、`b→c`、…、`z→a`）。若执行**至多一次**这样的操作后，`str2` 能成为 `str1` 的子序列，返回 `true`；否则返回 `false`。

**约束**：

- $1 \le |str1|, |str2| \le 10^5$
- 两串均只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：str1 = "abc", str2 = "ad"
输出：true
解释：选中 str1 的下标 2，将 'c' 递增为 'd'，str1 变为 "abd"，
     此时 "ad" 是其子序列。
```

**示例 2**

```text
输入：str1 = "zc", str2 = "ad"
输出：true
解释：选中下标 0、1：'z' 循环递增变 'a'，'c' 递增变 'd'，
     str1 变为 "ad"。
```

**示例 3**

```text
输入：str1 = "ab", str2 = "d"
输出：false
解释：'a'、'b' 递增后至多变成 'b'、'c'，无法得到 'd'。
```

## 3. 解题思路

### 3.1 暴力思路

`str1` 每个下标都有「不变 / +1」两种选择，共 $2^{n}$ 种操作方案，逐一模拟再判子序列——指数级，$n = 10^5$ 完全不可行。退一步的「正确暴力」是意识到操作的本质：**每个字符独立地可以在 $\{c,\ c^{+}\}$ 两个候选值里任选其一**（$c^{+}$ 为 $c$ 循环加一）。于是问题变成：能否从左到右为 `str2` 的每个字符在 `str1` 中找到**互不重叠且递增**的匹配位置，使每个位置上的字符等于该候选值之一。

### 3.2 核心观察：匹配是子序列匹配，逐字符贪心「尽早匹配」

![核心观察：每个位置两个候选值，从左到右贪心匹配](images/bw111_q2_match_concept.svg)

把 `str1` 位置 $i$ 的字符记为 $c$，它的候选集合是 $\{c,\ (c+1) \bmod 26\}$。**关键结论：`str2` 是「操作后 str1」的子序列，当且仅当存在一组匹配位置 $p_1 < p_2 < \dots < p_m$，使得对每个 $j$ 都有 $str2[j] \in \{str1[p_j],\ str1[p_j]^{+}\}$。**

理由是双向的：若这样的匹配存在，只需选中所有 $p_j$ 中满足 $str1[p_j] \ne str2[j]$ 的那些下标执行一次操作（操作可选任意多个下标，且**未被匹配的下标保持不变也不影响子序列**——子序列只要求匹配位置对得上），`str2` 即成为子序列；反之若一次操作后 `str2` 是子序列，其匹配位置与匹配后的字符恰好给出上述匹配组。

于是这就退化为一个标准的**双指针子序列匹配**：指针 $i$ 扫 `str1`，指针 $j$ 扫 `str2`；`str1[i]` 能吞掉 `str2[j]` 当且仅当 $str1[i] = str2[j]$ 或 $str1[i]^{+} = str2[j]$。**尽早匹配**（能吞就吞）是正确的贪心：让 $j$ 尽快前进只会给后续字符留出更长（不更短）的剩余后缀。

### 3.3 算法流程

![算法流程：双指针一躺扫描的判定逻辑](images/bw111_q2_two_pointer_flow.svg)

```text
1. i = 0, j = 0（分别指向 str1 与 str2）
2. 当 i < n 且 j < m 时循环：
       若 str1[i] == str2[j] 或 next(str1[i]) == str2[j]：
           j += 1                  # 该字符被吞掉
       i += 1                      # 无论是否吞，i 前进
3. 返回 j == m
```

其中 $next(c) = $ `char((c - 'a' + 1) % 26 + 'a')`，注意 `z` 的 next 是 `a`（循环）。

### 3.4 示例演算

以示例 2 `str1 = "zc"`、`str2 = "ad"` 为例：位置 0 的 `z` 候选 $\{z, a\}$，匹配 $str2[0] = a$（用到了 z→a 的循环递增）；位置 1 的 `c` 候选 $\{c, d\}$，匹配 $str2[1] = d$。$j$ 到达末尾，返回 `true`。

再看示例 3 `str1 = "ab"`、`str2 = "d"`：`a` 候选 $\{a,b\}$、`b` 候选 $\{b,c\}$，都不含 `d`，$j$ 停在 0，返回 `false`。

| 步骤 | i | j | str1[i] | 候选 | str2[j] | 动作 |
|------|---|---|---------|------|---------|------|
| 1 | 0 | 0 | z | {z,a} | a | 匹配，j=1 |
| 2 | 1 | 1 | c | {c,d} | d | 匹配，j=2 |
| — | 2 | 2 | — | — | — | j == m，成功 |

## 4. 算法细节

1. **循环加一的写法**：`(str1[i] - 'a' + 1) % 26 + 'a'`。`z` 变 `a` 必须取模；只写 `+1` 会在 `z` 处越界或算错，这是本题最典型的手滑点（示例 2 正是专为此设计）。
2. **「至多一次」的语义**：一次操作可选**任意多个**下标、每个至多 +1，因此每个位置的候选集合恰为 $\{c, c^{+}\}$，不存在「先 +1 再 +1」的叠加——递增只走一步。
3. **未被匹配的位置不必管**：子序列允许跳过字符，操作不必作用于它们（选中它们反而可能破坏？不会——操作自由选择下标，不选即可）。判定只看匹配位置。
4. **贪心的方向**：匹配条件成立时必须让 $j$ 前进而不是等更好的（例如 `str1 = "ac"`、`str2 = "ac"`，位置 0 用 `a` 匹配后位置 1 的 `c` 仍用 `c` 匹配；若跳过反而浪费）。详见 §5 引理 2。
5. **复杂度**：单躺 $O(n)$，无需任何数据结构；$n, m \le 10^5$ 轻松通过。

## 5. 正确性证明

**引理 1（操作的等价刻画）**：执行至多一次操作后 `str2` 是 `str1` 的子序列 $\iff$ 存在下标序列 $p_1 < \dots < p_m$ 使 $str2[j] \in \{str1[p_j],\ str1[p_j]^{+}\}$ 对所有 $j$ 成立（$str1[p]^{+}$ 表示该字符循环加一）。

**证明**：（⇐）取操作集合 $S = \{p_j : str1[p_j] \ne str2[j]\}$，即只对需要递增的匹配位置执行 +1。操作一次后 `str1` 在 $p_1 < \dots < p_m$ 处依次恰好是 $str2[1..m]$，故 `str2` 是子序列。（⇒）设操作集合 $S$ 执行后 `str2` 在位置 $p_1 < \dots < p_m$ 匹配。若 $p_j \notin S$，则匹配字符就是 $str1[p_j]$；若 $p_j \in S$，匹配字符是 $str1[p_j]^{+}$。两种情形都落在候选集合内。∎

**引理 2（贪心交换）**：设贪心在扫描到 `str1` 的某个前缀时，$j$ 的值达到 $g$；任何可行匹配（按引理 1 的意义）在同一前缀上至多让 $j$ 达到 $g$。换言之，贪心匹配的 `str2` 前缀长度在每一步都不劣于任何其他策略。

**证明**：对已扫描的 `str1` 前缀长度归纳。前缀长 0 时两者都为 0。设前缀长 $L$ 时结论成立，考察第 $L+1$ 个字符 $c = str1[L]$（候选 $\{c, c^{+}\}$）：贪心若匹配则 $g$ 增 1。任取可行匹配方案 $M$ 在前缀 $L+1$ 内匹配了 $t$ 个字符：若 $t \le g$ 则 $t \le g + 1$ 无需讨论；若 $t = g + 1$，则 $M$ 必在位置 $L$ 上匹配了 $str2[g]$（归纳假设保证前 $L$ 个位置至多匹配 $g$ 个），即 $str2[g] \in \{c, c^{+}\}$——与贪心的匹配条件相同，故贪心也匹配，$g$ 增至 $g+1 = t$。归纳成立。∎

**定理**：算法返回 `true` 当且仅当存在一次操作使 `str2` 成为 `str1` 的子序列。

**证明**：算法即贪心地应用引理 2 的策略，终止时 $j = g$ 为贪心在全长上匹配的 `str2` 前缀长度。若 $g = m$：贪心自己给出一组满足引理 1 的匹配（每个匹配位置的字符在候选集合内），由引理 1 必要性方向的构造，一次操作后 `str2` 是子序列，返回 `true` 正确。若 $g < m$：由引理 2，任何可行匹配在全长上也至多匹配 $g < m$ 个字符，即不存在满足引理 1 的匹配组，由引理 1 不存在可行的操作方案，返回 `false` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。指针 $i$ 每步前进且从不回退，$j$ 单调不降，总步数以 $n$ 为上界；每步仅做两次字符比较与一次模加。实际实现是 $O(n)$（$m \le$ 匹配数 $+ n$）。
- **空间**：$O(1)$ 额外空间，不复制字符串、不建表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canMakeSubsequence(string str1, string str2) {
        int n = str1.size(), m = str2.size();
        int j = 0;
        for (int i = 0; i < n && j < m; ++i) {
            char inc = char((str1[i] - 'a' + 1) % 26 + 'a');   // 循环 +1
            if (str1[i] == str2[j] || inc == str2[j]) ++j;
        }
        return j == m;
    }
};
```

### Python

```python
class Solution:
    def canMakeSubsequence(self, str1: str, str2: str) -> bool:
        j = 0
        for c in str1:
            if j == len(str2):
                break
            if c == str2[j] or chr((ord(c) - ord('a') + 1) % 26 + ord('a')) == str2[j]:
                j += 1
        return j == len(str2)
```

> 💡 两份代码均通过官方示例（`true`、`true`、`false`）与 `z→a` 循环、$|str2| > |str1|$、两串全等等定向用例，并与「枚举 $2^n$ 种增量子集 + 子序列判定」的暴力做了 6 万组（C++）/ 8 千组（Python）随机对拍（$n, m \le 10$，字母表全覆盖），失配数为 0。

## 8. 边界情况与易错点

1. **`z` 的循环递增**：`z` 变 `a` 而不是 `{` 或报错，必须 `% 26`；示例 2（`"zc"` → `"ad"`）专门考这一点。
2. **$|str2| > |str1|$**：子序列长度受限，直接返回 `false`，双指针自然处理（$j$ 到不了 $m$），无需特判。
3. **两串相等**：不需要任何操作（选 0 个下标也是「至多一次」），返回 `true`；别把「必须执行操作」错误地当成约束。
4. **一个位置只能 +1 一步**：`'a'` 想变 `'c'` 不行；匹配条件里不要允许「差 2」。
5. **贪心别跳过**：见到可匹配就匹配（$j$ 前进），不要为「保留更好字符」而跳过——候选集合与位置绑定，跳过只会让剩余后缀变短（见 §5 引理 2）。
6. **提前终止**：$j$ 到达 $m$ 后可立刻 `break`（Python 版已写，C++ 版的循环条件 `j < m` 同效），大数据下省一点扫描。

**延伸思考**：若把「+1」换成「+d（$d$ 为给定步数）」，候选集合变为 $\{c, (c+d) \bmod 26\}$，算法不变；若允许「每个位置 0~k 次递增」，候选集合扩大为 $\{c, c^{+}, \dots, c^{+k}\}$（仍是连续区间模 26），双指针照旧成立——只要「候选集合只与位置相关、与匹配历史无关」，尽早匹配的贪心就不失效。而一旦操作涉及相邻位置（如交换、区间整体 +1），位置间的独立性被破坏，就需要转向 DP 或差分。
