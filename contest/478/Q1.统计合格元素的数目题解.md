# LeetCode 统计合格元素的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计合格元素的数目（#3759，medium）
- **链接**：https://leetcode.cn/problems/count-elements-with-at-least-k-greater-values/
- **来源**：LeetCode 第 478 场周赛 Q1
- **难度**：中等
- **标签**：数组、排序、二分查找、快速选择

**题意**：给定长度为 $n$ 的整数数组 `nums` 和整数 $k$。若数组中**存在至少 $k$ 个元素严格大于**某个元素，则称其为「合格元素」。返回合格元素的总数。

**约束**：

- $1 \le n = nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$
- $0 \le k < n$

## 2. 示例

**示例 1**

```text
输入：nums = [3,1,2], k = 1
输出：2
解释：1 有 {2,3} 两个更大的、2 有 {3} 一个更大的，均合格；
      3 没有任何元素比它大，不合格。
```

**示例 2**

```text
输入：nums = [5,5,5], k = 2
输出：0
解释：所有元素相等，没有任何元素「严格大于」另一个，全员不合格。
```

**示例 3**（k = 0 边界）

```text
输入：nums = [7], k = 0
输出：1
解释：「至少 0 个更大」是空条件，任何元素都合格，答案恒为 n。
```

**示例 4**（重复值跨过阈值）

```text
输入：nums = [2,2,1,3], k = 2
输出：1
解释：只有 1 有 {2,2,3} 三个更大的元素；
      两个 2 各只有 {3} 一个更大的，3 一个都没有。
```

## 3. 解题思路

### 3.1 暴力思路

对每个元素 $nums[i]$ 扫一遍数组，数出严格大于它的元素个数 $g_i$，统计满足 $g_i \ge k$ 的下标数。时间 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。

标准改进：**排序 + 逐个二分**。升序排序后 $g_i = n - \mathrm{upper\_bound}(a,\ a[i])$，对每个位置做一次二分即可判定，整体 $O(n \log n)$，已经能过。但这藏着一步多余的功夫——合格性**只取决于元素的值**：等值元素命运必然相同，且值越小越容易合格。既然合格性关于值**单调**，就不需要对每个元素分别二分，一次**阈值判断**就能把整个数组一刀切开。

### 3.2 核心观察：合格 ⟺ 严格小于第 k 大（计重数）

![核心观察：合格等价于严格小于第 k 大](images/wc478_q1_threshold_insight.svg)

将数组升序排序为 $a[0..n-1]$，盯住**最后 $k$ 个元素** $a[n-k..n-1]$（即最大的 $k$ 个，按出现次数计）。令阈值

$$t = a[n-k] \quad (\text{即「计重数的第 } k \text{ 大」})$$

> **元素 $v$ 合格 $\iff v < t$**（$k \ge 1$ 时）

- **若 $v < t$**：$a[n-k..n-1]$ 这 $k$ 个元素都 $\ge t > v$，$v$ 白捡 $k$ 个更大的元素，合格；
- **若 $v \ge t$**：严格大于 $v$ 的元素必然也严格大于 $t$，而它们只能排在 $t$ 最后一次出现（下标 $\ge n-k$）之后，至多 $n-1-(n-k) = k-1$ 个，不足 $k$，不合格。

于是答案就是**值严格小于 $t$ 的元素个数**——排序数组里这恰好是 $t$ 首次出现的下标，一次 `lower_bound` 即得：

$$\text{ans} = \mathrm{lower\_bound}(a,\ t)$$

> 💡 一句话：**阈值 $t$ 是道分水岭，严格小于它的全合格、不小于它的全不合格**。与 $t$ 相等的元素恰好被「最大的 $k$ 个」挤出局——重复值会并列挤占前 $k$ 大的名额，所以比较必须卡在**值**上用严格小于，而不是卡在排名上。

$k = 0$ 时「至少 0 个更大」恒真，全员合格，答案为 $n$（此时 $a[n-k]$ 越界，需特判）。

### 3.3 算法流程

![算法流程：特判排序取阈值一次二分](images/wc478_q1_algorithm_flow.svg)

1. 若 $k = 0$，直接返回 $n$
2. 将 `nums` 升序排序（原地）
3. 取阈值 $t = nums[n-k]$（第 $k$ 大，计重数）
4. 返回 `lower_bound(nums, t)`，即首个等于 $t$ 的下标——其左侧元素全部严格小于 $t$

### 3.4 示例演算

![四个示例的演算走查](images/wc478_q1_example_walkthrough.svg)

| nums | k | 排序后 | $t=a[n-k]$ | 严格小于 $t$ 的元素 | 答案 |
|------|---|--------|------------|--------------------|------|
| [3,1,2] | 1 | [1,2,3] | 3 | 1、2 | 2 |
| [5,5,5] | 2 | [5,5,5] | 5 | 无 | 0 |
| [2,2,1,3] | 1 | [1,2,2,3] | 3 | 1、2、2 | 3 |
| [2,2,1,3] | 2 | [1,2,2,3] | 2 | 1 | 1 |

注意第 4 行：$t = 2$ 时两个 $2$ **都不合格**（大于 2 的只有 3 这一个），哪怕其中一个就站在「最大的 $k=2$ 个」区域里——与阈值相等就是不合格。

## 4. 算法细节

1. **k = 0 特判**：「至少 0 个更大」是空约束恒成立，答案 $n$；若不特判，$a[n-k] = a[n]$ 直接越界。这是本题最大的坑。
2. **阈值必须计重数**：$t$ 是排序后下标 $n-k$ 上的值（「计重数的第 $k$ 大」），**不是**去重后的第 $k$ 个不同值。反例 $[5,5,5],\ k=2$：相等元素互不贡献「严格更大」，按去重口径会误判。
3. **为什么一次 `lower_bound` 就够**：合格性只依赖值与阈值的大小关系（单调），与下标无关；等值元素合格性相同，按值一刀切计数即可，无需对每个下标分别二分。
4. **`lower_bound` 返回值的含义**：升序数组中首个 $\ge t$ 的位置；由于 $t$ 一定在数组中，它就是首个 $= t$ 的位置，其左边恰是全体 $< t$ 的元素，故返回下标即答案。
5. **进阶 $O(n)$ 做法**：整个算法只用到「第 $n-k$ 小的值」和「小于它的元素个数」——用**快速选择**（C++ `nth_element`，平均 $O(n)$）把 $t$ 摆到下标 $n-k$，再线性扫一遍数出 $< t$ 的个数即可，无需完整排序。这正是本题标签里 Divide and Conquer / Quickselect 的来历。

## 5. 正确性证明

**引理 1（单调性）**：设 $v_1 \le v_2$ 为数组中两个元素的值。若 $v_2$ 合格，则 $v_1$ 合格。

**证明**：凡严格大于 $v_2$ 的元素 $x$ 满足 $x > v_2 \ge v_1$，故 $\{x : x > v_2\} \subseteq \{x : x > v_1\}$，后者个数不少于前者，也 $\ge k$。∎

**引理 2（分水岭）**：设 $1 \le k \le n-1$，$a$ 为升序排序后的数组，$t = a[n-k]$。对任意值 $v$：$v$ 合格 $\iff v < t$。

**证明**：
(⟸) 若 $v < t$：下标 $n-k, \dots, n-1$ 处的 $k$ 个元素均 $\ge t > v$，故至少有 $k$ 个元素严格大于 $v$，$v$ 合格。
(⟹) 若 $v \ge t$：凡满足 $x > v$ 的元素有 $x > v \ge t$，故 $\{x : x > v\} \subseteq \{x : x > t\}$。升序数组中大于 $t$ 的元素构成一段后缀，起始于 $t$ 最后一次出现之后；而 $t$ 出现在下标 $n-k$，其最后一次出现的下标 $\ge n-k$，故该后缀长度 $\le n-1-(n-k) = k-1 < k$，$v$ 不合格。∎

**定理**：$k = 0$ 时答案为 $n$；$k \ge 1$ 时答案为排序后严格小于 $a[n-k]$ 的元素个数，即 $\mathrm{lower\_bound}(a,\ a[n-k])$ 返回的下标。

**证明**：$k = 0$ 时「至少 0 个更大」对每个元素都成立，故答案为 $n$。$k \ge 1$ 时由引理 2，合格元素恰为取值 $< a[n-k]$ 的元素全体；升序数组中它们是连续的一段前缀 $a[0..p-1]$，其中 $p$ 为 $a[n-k]$ 首次出现的下标，即 $\mathrm{lower\_bound}(a,\ a[n-k])$ 的返回值，共 $p$ 个。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导；一次 `lower_bound` 仅 $O(\log n)$，可忽略。改用快速选择找阈值则平均 $O(n)$。
- **空间复杂度**：除排序外仅 $O(1)$ 辅助变量；排序本身 C++ introsort 需 $O(\log n)$ 栈空间，Python Timsort 需 $O(n)$ 辅助数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countElements(vector<int>& nums, int k) {
        int n = nums.size();
        if (k == 0) {
            return n;
        }
        sort(nums.begin(), nums.end());
        return lower_bound(nums.begin(), nums.end(), nums[n - k]) - nums.begin();
    }
};
```

### Python

```python
from bisect import bisect_left

class Solution:
    def countElements(self, nums: List[int], k: int) -> int:
        if k == 0:
            return len(nums)
        nums.sort()
        return bisect_left(nums, nums[-k])
```

## 8. 边界情况与易错点

1. **k = 0 必须特判**：不判则 `nums[n-k]` 越界；且语义上答案为 $n$ 而非 0（「至少 0 个」恒真）。约束 $k < n$ 保证 $k \ge 1$ 时 $n-k \ge 1$，唯独 $k=0$ 需要单独兜底。
2. **比较必须是严格小于**：与阈值 $t$ 相等的元素不合格——它们恰好被「最大的 $k$ 个」挤出局。示例 2 的 $[5,5,5]$ 是最直接的照妖镜，把「严格小于」放宽成「不超过」会答 3 而不是 0。
3. **第 k 大计重数**：阈值取 $a[n-k]$（含重复），不是去重后第 $k$ 个不同值。
4. **别对每个元素各做一次二分**：$O(n \log n)$ 能过但浪费——合格性关于值单调，一刀切只需一次二分（甚至排序后线性扫描计数也行）。
5. **单元素数组**：$n = 1$ 时约束迫使 $k = 0$，落入特判返回 1，不会触碰 $a[n-k]$。
6. **无溢出风险**：$n \le 10^5$、$nums[i] \le 10^9$，计数与比较均在 `int` 范围内。
7. **排序会打乱原下标**：本题只问个数故无妨；若接口改为返回合格元素的下标列表，需先记录 (值, 原下标) 再排。

**延伸思考**：

- **平均 $O(n)$**：`nth_element` / quickselect 把 $t$ 摆到下标 $n-k$，再线性数出小于 $t$ 的个数；$k$ 很小时也可用大小为 $k$ 的最小堆维护前 $k$ 大，堆顶即阈值（最坏 $O(n \log k)$）。
- **「严格大于」改成「大于等于」**：条件变为「至少 $k$ 个元素 $\ge v$」，同款分水岭论证可得 $v$ 合格 $\iff v \le a[n-k]$，答案改为 $\mathrm{upper\_bound}(a,\ a[n-k])$——只是切分点从「严格小于」挪到「不超过」，镜像对称。
- **多组询问**：若对同一数组有多个不同的 $k$ 依次询问，可离线按 $k$ 排序，在有序数组上双指针移动阈值并累计计数，每组询问均摊 $O(1)$；或预处理值域前缀计数（值域 $10^9$ 需离散化），单次询问 $O(\log n)$。
