# LeetCode 检查数组对是否可以被 k 整除 题解

## 1. 题目概述

- **标题 / 题号**：检查数组对是否可以被 k 整除（#1497，medium）
- **链接**：https://leetcode.cn/problems/check-if-array-pairs-are-divisible-by-k/
- **来源**：LeetCode 第 195 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：给定长度为偶数 $n$ 的整数数组 `arr` 和整数 $k$，要求把数组**恰好**分成 $n/2$ 对，使**每一对**的两个数之和都能被 $k$ 整除。存在这样的分法返回 `true`，否则返回 `false`。每个元素必须恰好属于一对，不允许落单。

**约束**：

- $1 \le n \le 10^5$，且 $n$ 为偶数
- $-10^9 \le \text{arr}[i] \le 10^9$（**元素可为负**）
- $1 \le k \le 10^5$

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,3,4,5,10,6,7,8,9], k = 5
输出：true
解释：划分为 (1,9),(2,8),(3,7),(4,6),(5,10)，每对之和都是 5 的倍数。
```

**示例 2**

```text
输入：arr = [1,2,3,4,5,6], k = 7
输出：true
解释：划分为 (1,6),(2,5),(3,4)，每对之和都是 7。
```

**示例 3**

```text
输入：arr = [1,2,3,4,5,6], k = 10
输出：false
解释：k 为偶数时余 5（= k/2）的数只能与余 5 的数配对，而余 5 的数只有
      1 个（5 本身），凑不成一对。
```

**示例 4（补充：负数输入）**

```text
输入：arr = [-1,-1,-2,-2,-3,-3], k = 3
输出：true
解释：(-1)+(-2)=-3，(-1)+(-2)=-3，(-3)+(-3)=-6，均能被 3 整除。
      负数取模需归一化：-1 mod 3 = 2，-2 mod 3 = 1，-3 mod 3 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举配对方案：搜索「每个未配对元素依次挑选搭档」，复杂度约 $O(n!!)$（双阶乘）；或状压 DP $O(2^n \cdot n^2)$。$n$ 达 $10^5$，两条路都完全不可行。

瓶颈在于：我们试图在**具体数字**层面做匹配，但「和能否被 $k$ 整除」这件事根本不关心数字本身，只关心**余数**——巨大的信息冗余才是真正的敌人。

### 3.2 核心观察：整除性只看余数，余数必须互补

![核心观察：a+b 被 k 整除当且仅当两数余数互补，k=5 时余 0 自配、余 1 配余 4、余 2 配余 3](images/wc195_q2_remainder_pairing_concept.svg)

**关键转化**：$k \mid (a+b)$ 当且仅当 $(a \bmod k) + (b \bmod k) \equiv 0 \pmod k$。也就是说，**余数为 $r$ 的数只能与余数为 $(k-r) \bmod k$ 的数配对**，与商（数值大小）无关。

于是问题从「$10^5$ 个具体数字的匹配」坍缩为「$k$ 个余数类的**计数守恒检查**」：

1. **余 0 类**只能与余 0 类配对（$0+0=0$）→ 数量必须是**偶数**；
2. $k$ 为**偶数**时，**余 $k/2$ 类**也只能自配（$k/2 + k/2 = k$）→ 数量必须是**偶数**；
3. 其余余数 $r$（$1 \le r < k/2$）只能与余 $k-r$ 配对 → 两类数量必须**相等**。

### 3.3 算法流程

![算法流程：统计余数计数后依次检查三类条件，任一失败返回 false](images/wc195_q2_checking_flow.svg)

1. 建立 `cnt[0..k-1]` 计数数组，遍历 `arr`，将每个元素**归一化余数** `r = ((x % k) + k) % k` 的计数加一（负数归一化是 C++/Java 的必经步骤）；
2. 检查 `cnt[0]` 是否为偶数，不是直接返回 `false`；
3. 若 $k$ 为偶数，检查 `cnt[k/2]` 是否为偶数，不是直接返回 `false`；
4. 对每个 $1 \le r \le \lfloor k/2 \rfloor$（$r = k/2$ 的情况已在第 3 步处理）：检查 `cnt[r] == cnt[k-r]`，不等返回 `false`；
5. 全部通过，返回 `true`。

### 3.4 示例演算

![示例演算：同一数组 k=5 时三类条件全过返回 true，k=10 时 cnt[k/2] 为奇数返回 false](images/wc195_q2_example_walkthrough.svg)

**示例 1（k = 5，true）**：余数序列为 $1,2,3,4,0,0,1,2,3,4$，计数表 `cnt = [2,2,2,2,2]`。检查：`cnt[0]=2` 偶 ✓；`cnt[1]=cnt[4]=2` ✓；`cnt[2]=cnt[3]=2` ✓ → `true`。

**示例 3（k = 10，false）**：余数序列为 $1,2,3,4,5,6$。$k$ 为偶数，余 $5 = k/2$ 的数只有 1 个（奇数），无法自配 → `false`。这正是「$k/2$ 自配特判」最容易漏掉的地方。

## 4. 算法细节

- **余数归一化**：C++/Java 的 `%` 遵循「截断除法」，负数取模结果为负（如 `(-1) % 5 == -1`），直接作下标会越界或计数错位。统一写 $r = ((x \bmod k) + k) \bmod k$ 把余数压到 $[0, k)$。Python 的 `%` 结果恒非负，天然免疫，但跨语言提交要养成归一化习惯。
- **计数数组而非哈希表**：$k \le 10^5$，直接开长度为 $k$ 的 `cnt` 数组，比 `unordered_map` 更快更省。
- **循环上界的写法**：`for (r = 1; r <= k / 2; ++r)`，配合「`r == k - r` 时查奇偶，否则查 `cnt[r] == cnt[k-r]`」的分支，可同时覆盖 $k$ 奇（上界 $(k-1)/2$）与 $k$ 偶（含 $k/2$ 自配检查）两种情形，无需额外特判。
- **单侧遍历**：只遍历 $r \le k/2$ 一侧，天然避免 `cnt[r]` 与 `cnt[k-r]` 被重复比较。
- **不需求和**：整个算法只做取模和计数，$|a+b| \le 2 \times 10^9$ 的溢出风险根本不会出现；若写暴力验证单对之和，C++ 需改用 `long`。

## 5. 正确性证明

**引理 1（整除性只看余数）**：对整数 $a, b$，设 $r_a = a \bmod k \in [0,k)$，$r_b = b \bmod k \in [0,k)$，则 $k \mid (a+b) \iff r_a + r_b = 0$ 或 $r_a + r_b = k$。

**证明**：写 $a = q_a k + r_a$，$b = q_b k + r_b$，则 $a + b = (q_a + q_b)k + (r_a + r_b)$，故 $k \mid (a+b) \iff k \mid (r_a + r_b)$。又 $0 \le r_a + r_b \le 2k - 2$，所以 $k \mid (r_a + r_b) \iff r_a + r_b \in \{0, k\}$。∎

**推论**：合法配对的余数组合只有三种形态：$(0, 0)$；$k$ 为偶数时的 $(k/2, k/2)$；以及 $1 \le r < k/2$ 时的 $(r, k-r)$（对称地 $(k-r, r)$）。

**引理 2（配对结构的唯一性）**：余数为 $r$（$1 \le r \le k-1$，$2r \not\equiv 0 \pmod k$）的元素，在任何合法方案中只能与余数为 $k - r$ 的元素配对；余 0 的元素只能与余 0 的元素配对。

**证明**：由引理 1，配偶的余数 $s$ 必须满足 $r + s \in \{0, k\}$，即 $s = (k - r) \bmod k$，唯一确定。$r = 0$ 时 $s = 0$；$1 \le r \le k-1$ 且 $2r \not\equiv 0$ 时 $s = k - r \ne r$。∎

**定理**：`arr` 可以分成 $n/2$ 对且每对之和被 $k$ 整除 $\iff$ 以下三条同时成立：

1. $\text{cnt}[0]$ 为偶数；
2. $k$ 为偶数时 $\text{cnt}[k/2]$ 为偶数；
3. 对所有 $1 \le r < k/2$，$\text{cnt}[r] = \text{cnt}[k-r]$。

**证明**：

- **必要性**：设存在合法方案。由引理 2，余 0 类只能类内两两配对，故 $\text{cnt}[0]$ 为偶数；$k$ 偶时余 $k/2$ 类同理。对 $1 \le r < k/2$（此时 $r \neq k - r$），余 $r$ 类每个元素都与余 $k-r$ 类配对，每对在两类中各消耗一个元素，两类最终同时耗尽，故 $\text{cnt}[r] = \text{cnt}[k-r]$。
- **充分性**：构造方案——余 0 类内任意两两配对；$k$ 偶时余 $k/2$ 类内两两配对；对每个 $1 \le r < k/2$，把余 $r$ 类与余 $k-r$ 类的元素按任意顺序一一配对。由三个计数条件，所有元素恰好用完（总数 $n$ 为偶数保证无剩余），且由引理 1 每对之和都被 $k$ 整除，恰好得到 $n/2$ 对。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k)$。一次遍历 `arr` 统计计数为 $O(n)$；检查阶段遍历余数 $r$ 至 $k/2$，为 $O(k)$。$k \le 10^5$、$n \le 10^5$，总量级不超过 $2 \times 10^5$。
- **空间复杂度**：$O(k)$。计数数组 `cnt` 长 $k$，不计输入数组本身。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canArrange(vector<int>& arr, int k) {
        vector<int> cnt(k, 0);
        for (int x : arr) {
            int r = ((x % k) + k) % k;   // 负数归一化到 [0, k)
            ++cnt[r];
        }
        if (cnt[0] % 2 != 0) return false;
        for (int r = 1; r <= k / 2; ++r) {
            if (r == k - r) {            // k 为偶数且 r = k/2：自配类
                if (cnt[r] % 2 != 0) return false;
            } else if (cnt[r] != cnt[k - r]) {
                return false;
            }
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canArrange(self, arr: List[int], k: int) -> bool:
        cnt = [0] * k
        for x in arr:
            cnt[x % k] += 1              # Python 的 % 恒非负，无需归一化
        if cnt[0] % 2:
            return False
        for r in range(1, k // 2 + 1):
            if r == k - r:               # k 为偶数且 r = k/2：自配类
                if cnt[r] % 2:
                    return False
            elif cnt[r] != cnt[k - r]:
                return False
        return True
```

## 8. 边界情况与易错点

1. **负数取模（本题最高频 WA 点）**：C++/Java 中 `(-1) % 5 == -1` 而非 `4`，负余数会导致数组越界或计数错位，必须 $r = ((x \bmod k) + k) \bmod k$ 归一化。示例 4 的全负数组专门踩这一点。
2. **$k$ 为偶数时 $k/2$ 自配类的奇偶特判**：示例 3 死在这里（`cnt[5] = 1` 奇数）。若检查只写 `cnt[r] == cnt[k-r]` 且 $r$ 只遍历到 $k/2 - 1$，或对 $r = k/2$ 也只写相等判断（变成 `cnt[k/2] == cnt[k/2]` 恒真），都会漏判。
3. **循环边界**：推荐 `r <= k/2` 配合 `r == k - r` 分支，一套逻辑同时覆盖奇偶 $k$；$k = 1$ 时 `k/2 = 0`，循环体不执行，只剩 `cnt[0] = n` 恒偶的检查，自动返回 `true`（任何整数都能被 1 整除），无需特判。
4. **「恰好 $n/2$ 对」**：每个元素必须用掉、不允许落单——这正是数量守恒条件（相等 / 偶数）的来源，不是可放宽的软约束。
5. **溢出**：本算法不做加法，`int` 足够；若手滑写了验证 `a + b` 的暴力，$|a+b| \le 2 \times 10^9$ 会溢出 `int32`，C++ 需 `long long`。
6. **$k > n$**：大量余数类计数为 0，`0 == 0` 恒成立不影响判断；某个非零类找不到互补（$\text{cnt}[k-r] = 0 \ne \text{cnt}[r]$）会被正确判 `false`。
7. **只遍历单侧**：$r$ 从 1 到 $k/2$ 即可，双侧遍历虽然结果不变但做了两倍工作，还容易把 $r = k/2$ 的分支写错。
