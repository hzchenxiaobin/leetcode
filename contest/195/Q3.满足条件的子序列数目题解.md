# LeetCode 满足条件的子序列数目 题解

## 1. 题目概述

- **标题 / 题号**：满足条件的子序列数目（#1498，medium）
- **链接**：https://leetcode.cn/problems/number-of-subsequences-that-satisfy-the-given-sum-condition/
- **来源**：LeetCode 第 195 场周赛 Q3
- **难度**：中等
- **标签**：数组、双指针、二分查找、排序、计数

**题意**：给定整数数组 `nums` 和整数 `target`，统计并返回 `nums` 中满足**最小元素与最大元素之和小于或等于 `target`** 的**非空子序列**数目。子序列是从数组中删除若干（可不删）元素后、**不改变剩余元素相对顺序**得到的结果（即「按下标集合选取」）。答案很大，对 $10^9 + 7$ 取模后返回。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^6$
- $1 \le \text{target} \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums = [3,5,6,7], target = 9
输出：4
解释：有 4 个子序列满足该条件。
[3]      -> 3 + 3 = 6 ≤ 9
[3,5]    -> 3 + 5 = 8 ≤ 9
[3,5,6]  -> 3 + 6 = 9 ≤ 9
[3,6]    -> 3 + 6 = 9 ≤ 9
```

**示例 2**

```text
输入：nums = [3,3,6,8], target = 10
输出：6
解释：[3], [3], [3,3], [3,6], [3,6], [3,3,6]
      两个 3 是不同下标，算作不同的子序列。
```

**示例 3**

```text
输入：nums = [2,3,3,4,6,7], target = 12
输出：61
解释：共 2⁶ − 1 = 63 个非空子序列，其中 2 个不满足条件（[6,7] 与 [7]），
      63 − 2 = 61。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $2^n - 1$ 个非空子序列，对每个逐一求 min 与 max 再判断，复杂度 $O(2^n \cdot n)$；即使中途「边选边维护 min/max」也要 $O(2^n)$。$n$ 达 $10^5$，完全不可行。

另一个自然的优化方向是对每个 $i$ 枚举子序列并维护，仍是指数级。瓶颈在于：**我们在「具体子序列」层面做判断，但条件 $\min + \max \le \text{target}$ 根本不关心元素顺序，也不关心中间元素是哪些**——真正的信息只有「选了哪些数（多重集合）」。信息冗余才是该被攻击的对象。

### 3.2 核心观察：min+max 只依赖「选了哪些数」→ 排序 + 固定最小值

![核心观察：子序列只看选了哪些数，排序不改答案；固定最小值后中间元素自由选、右边界由 j 界定，贡献 2 的幂](images/wc195_q3_minmax_concept.svg)

**观察 1（排序合法）**：子序列由**下标集合**决定，但 $\min + \max$ 只依赖所选元素的**多重集合**。把数组排序只是对下标做了一次重排双射，排序前后的子序列集合一一对应且每对的条件取值相同，因此**排序不改变答案**。排序后问题变为：在有序数组中数「多重集合」的个数。

**观察 2（固定一端，另一端只是上界）**：排序后，把子序列按「所选最小下标 $i$」分类。固定 $i$ 必选（充当 min），设 $j(i)$ 为满足 $\text{nums}[i] + \text{nums}[j] \le \text{target}$ 的**最大**下标，则：

- 下标 $i+1, \dots, j(i)$ 中的每个元素**选 / 不选**都合法——max 不超过 $\text{nums}[j(i)]$，min 恰为 $\text{nums}[i]$，和必然不超 `target`；
- 任何下标 $> j(i)$ 的元素一旦选中，max 至少是 $\text{nums}[j(i)+1]$，min 仍是 $\text{nums}[i]$，和必然超 `target`。

于是以 $i$ 为最小值的合法子序列恰有 $2^{\,j(i) - i}$ 个（$i$ 必选，中间 $j(i)-i$ 个位置独立二选一）。若 $2 \cdot \text{nums}[i] > \text{target}$，则 $j(i) < i$，贡献为 $0$。

> ⚠️ **最容易犯的错**：把 $j$ 误当成「必须选中的 max」，从而写成 $2^{j-i-1}$。$j$ 只是**允许的上界**，max 可以是 $i+1, \dots, j$ 中任何一个被选中的位置，也可以就是 $i$ 自己。示例 1 里 $[3]$、$[3,5]$（max $< 6$）都在 $i=0, j=2$ 的贡献里，一旦「双端必选」就漏了。从几何级数视角看两种数法等价：$1 + 2^0 + 2^1 + \dots + 2^{j-i-1} = 2^{j-i}$，但逐对枚举是 $O(n^2)$，级数求和一步到位。

### 3.3 算法流程：双指针

![算法流程：排序、预处理 2 的幂，i 从左 j 从右双指针，满足则计数并右移 i，否则左移 j](images/wc195_q3_two_pointer_flow.svg)

1. 将 `nums` 升序排序；
2. 预处理 $\text{pow2}[0..n-1]$，$\text{pow2}[k] = 2^k \bmod (10^9+7)$；
3. 双指针 $i = 0$，$j = n-1$，$\text{ans} = 0$；
4. 当 $i \le j$ 时：
   - 若 $\text{nums}[i] + \text{nums}[j] \le \text{target}$：此时 $j$ 恰为 $j(i)$，累加 $\text{ans} \mathrel{+}= \text{pow2}[j-i]$，然后 $i \mathrel{+}= 1$；
   - 否则 $j$ 太大：$j \mathrel{-}= 1$；
5. 循环结束（$i > j$），返回 $\text{ans}$。

$j$ 随 $i$ 单调不增（$i$ 变大 → min 变大 → 容许的 max 变小），每轮指针二选一移动，总移动次数不超过 $2n$。也可以不用双指针，对每个 $i$ 二分查找 $j(i)$，复杂度同为 $O(n \log n)$ 级别（双指针把扫描部分压到 $O(n)$，瓶颈在排序）。

### 3.4 示例演算

![示例演算：nums=2,3,3,4,6,7 target=12 的双指针逐步走查，累计 32+16+8+4+1=61](images/wc195_q3_example_walkthrough.svg)

以示例 3（`nums = [2,3,3,4,6,7]`，`target = 12`，已有序）为例：

| $(i, j)$ | $\text{nums}[i] + \text{nums}[j]$ | 动作 | 贡献 | ans |
|---|---|---|---|---|
| $(0, 5)$ | $2 + 7 = 9 \le 12$ | ✓ 计数，$i \to 1$ | $2^5 = 32$ | 32 |
| $(1, 5)$ | $3 + 7 = 10 \le 12$ | ✓ 计数，$i \to 2$ | $2^4 = 16$ | 48 |
| $(2, 5)$ | $3 + 7 = 10 \le 12$ | ✓ 计数，$i \to 3$ | $2^3 = 8$ | 56 |
| $(3, 5)$ | $4 + 7 = 11 \le 12$ | ✓ 计数，$i \to 4$ | $2^2 = 4$ | 60 |
| $(4, 5)$ | $6 + 7 = 13 > 12$ | ✗ $j \to 4$ | — | 60 |
| $(4, 4)$ | $6 + 6 = 12 \le 12$ | ✓ 计数，$i \to 5$（单选 $[6]$） | $2^0 = 1$ | 61 |
| $(5, 4)$ | — | $i > j$，结束 | — | **61** |

与题面核对：63 个非空子序列里恰好 $[7]$ 与 $[6,7]$ 非法，$63 - 2 = 61$ ✓。

## 4. 算法细节

- **幂表预处理优于逐次快速幂**：贡献最多被累加 $n$ 次，每次需要 $2^{j-i}$。预处理一张 $\text{pow2}$ 表每次 $O(1)$ 查询；若每个 $i$ 现场跑快速幂 $O(\log n)$，总量 $O(n \log n)$ 也能过，但多余且易错（尤其 Python 不取模会让整数膨胀到天文数字）。
- **为什么双指针停在的 $j$ 恰是 $j(i)$**：$j$ 只在 $\text{nums}[i'] + \text{nums}[j] > \text{target}$（其中 $i' \le$ 当前 $i$）时递减，而 $\text{nums}[i'] \le \text{nums}[i]$，故每次递减发生时必有 $\text{nums}[i] + \text{nums}[j] > \text{target}$，即 $j$ 从不越过 $j(i)$；反过来当 $j > j(i)$ 时当前判定必不满足、触发 $j$ 递减，最终恰停在 $j(i)$。详见 §5 引理 3。
- **`while (i <= j)` 自带终止条件**：当 $j < i$ 时说明当前及更靠右的元素自配（$2 \cdot \text{nums}[i]$）都超 `target`，其后更大的 $i$ 更不可能，循环正确终止，无需对 $j(i) < i$ 单独特判。二分写法则需要显式判断「二分出的 $j \ge i$」才能计数。
- **重复元素**：相同数值、不同下标视为不同子序列（示例 2 的两个 `[3]`）。算法按下标分类计数，天然正确处理重复值。
- **取模与类型**：C++ 中 `pow2[k-1] < 10^9+7 < 2^30`，`pow2[k-1] * 2 < 2^31` 尚在 `int` 内，但 `ans + pow2[...]` 同理紧贴上界，习惯上用 `long long` 免去心智负担；Python 任意精度无溢出，但仍应逐步取模控制数字大小。
- **接口名**：本题函数签名为 `numSubseq(vector<int>& nums, int target)`，注意是 `numSubseq` 不是 `numSubsequence`。

## 5. 正确性证明

**引理 1（排序不改变答案）**：设 $\sigma$ 为把 `nums` 排序的下标重排（$\text{nums}[\sigma(0)] \le \dots \le \text{nums}[\sigma(n-1)]$），映射 $S \mapsto \sigma(S)$ 是原数组子序列集合到排序后数组子序列集合的双射，且 $\min S + \max S$ 在映射下不变。

**证明**：子序列由下标集合唯一决定，$\sigma$ 是下标集合到下标集合的双射。而 $\min$ 与 $\max$ 只依赖所选元素的多重集合 $\{\text{nums}[k] : k \in S\}$，该多重集合在重排下逐元素相等，故条件 $\min + \max \le \text{target}$ 的真假在映射前后一致。双射保持计数不变。∎

**引理 2（固定最小值的贡献公式）**：排序后，对每个下标 $i$，设 $j(i) = \max\{\, j : \text{nums}[i] + \text{nums}[j] \le \text{target} \,\}$（集合为空时记 $j(i) < i$）。则以 $i$ 为所选**最小下标**的合法子序列恰有 $2^{\,j(i)-i}$ 个（$j(i) \ge i$ 时），且它们全部形如 $\{i\} \cup T$，$T \subseteq \{i+1, \dots, j(i)\}$。

**证明**：$i$ 为所选最小下标意味着 $i \in$ 选中集且选中集中不含比 $i$ 小的下标，即选中集 $= \{i\} \cup T$，$T \subseteq \{i+1, \dots, n-1\}$。
（合法性 ⇒ $T \subseteq \{i+1,\dots,j(i)\}$）若 $T$ 中含某 $k > j(i)$，则 $\max = \text{nums}[k] \ge \text{nums}[j(i)+1]$，而 $\min = \text{nums}[i]$，故 $\min + \max \ge \text{nums}[i] + \text{nums}[j(i)+1] > \text{target}$，非法。
（$T \subseteq \{i+1,\dots,j(i)\}$ ⇒ 合法）此时 $\min = \text{nums}[i]$（其余下标更大），$\max \le \text{nums}[j(i)]$，故 $\min + \max \le \text{nums}[i] + \text{nums}[j(i)] \le \text{target}$，合法。
因此合法的 $T$ 恰为 $\{i+1, \dots, j(i)\}$ 的全部子集，共 $2^{\,j(i)-i}$ 个。∎

**引理 3（$j(i)$ 单调不增 + 双指针不变式）**：若 $i_1 < i_2$，则 $j(i_2) \le j(i_1)$；且双指针算法在每次针对当前 $i$ 做出「计数」决策时，当前 $j$ 恰等于 $j(i)$。

**证明**：$\text{nums}[i_1] \le \text{nums}[i_2]$，故凡满足 $\text{nums}[i_2] + \text{nums}[j] \le \text{target}$ 的 $j$ 必满足 $\text{nums}[i_1] + \text{nums}[j] \le \text{target}$，即 $j(i_2)$ 的候选集合含于 $j(i_1)$ 的候选集合，最大值不增。
对双指针维护不变式「每当对当前 $i$ 判定 $\text{nums}[i]+\text{nums}[j] \le \text{target}$ 时，$j$ 不小于程序语义上的真值」：$j$ 的每次递减发生在 $\text{nums}[i'] + \text{nums}[j] > \text{target}$ 且 $i' \le$ 当前 $i$ 时，此时 $\text{nums}[i] + \text{nums}[j] \ge \text{nums}[i'] + \text{nums}[j] > \text{target}$，说明被减掉的每个 $j$ 都大于 $j(i)$，故递减永不冲过头。反之当 $j > j(i)$ 时判定必失败并继续递减，直到 $j = j(i)$ 判定成功、计数并 $i$ 递增。由归纳，每一步计数的 $2^{j-i}$ 恰为引理 2 的 $2^{\,j(i)-i}$。∎

**定理**：算法返回的 $\text{ans} = \sum_{i:\, j(i) \ge i} 2^{\,j(i)-i} \bmod (10^9+7)$ 等于满足条件的子序列数目。

**证明**：把全部子序列按「所选最小下标 $i$」分类，各类两两不交且并为全集（非空子序列必有最小下标）。由引理 2，第 $i$ 类中的合法子序列恰 $2^{\,j(i)-i}$ 个（$j(i) < i$ 时为 0 个）；由引理 3，双指针逐一给出这些 $j(i)$ 并正确累加；由引理 1，排序前后计数相同。全部取模运算只做加法与乘法，与模运算的良定义性兼容。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，瓶颈在排序 $O(n \log n)$；幂表预处理 $O(n)$，双指针每轮 $i{+}{+}$ 或 $j{-}{-}$ 至少其一，总步数 $\le 2n$，为 $O(n)$。若用「对每个 $i$ 二分找 $j(i)$」的写法，扫描部分为 $O(n \log n)$，总量不变。
- **空间复杂度**：$O(n)$，幂表 $\text{pow2}$ 长 $n$（排序若用原地快排不占额外大空间；不计输入数组本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numSubseq(vector<int>& nums, int target) {
        const int MOD = 1'000'000'007;
        int n = nums.size();
        sort(nums.begin(), nums.end());

        vector<int> pow2(n);
        pow2[0] = 1;
        for (int k = 1; k < n; ++k)
            pow2[k] = pow2[k - 1] * 2 % MOD;

        long long ans = 0;
        int i = 0, j = n - 1;
        while (i <= j) {
            if (nums[i] + nums[j] <= target) {
                ans = (ans + pow2[j - i]) % MOD;  // j 只是上界，max 不必选
                ++i;
            } else {
                --j;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numSubseq(self, nums: List[int], target: int) -> int:
        MOD = 10**9 + 7
        nums.sort()
        n = len(nums)

        pow2 = [1] * n
        for k in range(1, n):
            pow2[k] = pow2[k - 1] * 2 % MOD

        ans = 0
        i, j = 0, n - 1
        while i <= j:
            if nums[i] + nums[j] <= target:
                ans = (ans + pow2[j - i]) % MOD
                i += 1
            else:
                j -= 1
        return ans
```

## 8. 边界情况与易错点

1. **贡献写成 $2^{j-i-1}$（本题最高频 WA）**：误以为「max 必选」。$j$ 是允许的上界，$i+1..j$ 每个位置独立「选 / 不选」，正确贡献是 $2^{j-i}$；漏掉的单元素子序列 $[i]$（$i=j$ 时）与「max $< \text{nums}[j]$」的子序列都在其中。自查方法：示例 1 的 $[3]$、$[3,5]$ 必须被 $i=0$ 的贡献覆盖。
2. **不排序直接双指针**：`min+max` 与顺序无关是排序合法性的全部来源；原数组上 `i`、`j` 的移动没有任何单调性保证，双指针彻底失效。
3. **$i = j$ 的含义**：此时判定的是「单选 $\text{nums}[i]$ 是否合法」（$2 \cdot \text{nums}[i] \le \text{target}$），贡献 $2^0 = 1$，示例 3 演算的最后一行（$[6]$）正是这一情形；`while (i <= j)` 的等号不可写成 `<`。
4. **2 的幂不取模**：$n \le 10^5$，$2^{99999}$ 远超任何整型；C++ 中必须逐步 `% MOD`（`pow2[k-1] * 2` 因 $\text{MOD} < 2^{30}$ 恰好不溢 `int`，但为稳妥建议 `long long`）；Python 不溢出但大整数运算慢，同样要逐步取模。
5. **二分写法的边界**：若不用双指针而 `upper_bound`/`bisect` 找 $j(i)$，注意二分结果可能是 $i-1$（即所有 $j$ 都不满足，$2\,\text{nums}[i] > \text{target}$），必须 `if j >= i` 才累加 $2^{j-i}$，否则会累加负指数或漏判断。
6. **答案的取模时机**：每步累加后立刻取模，避免中间值膨胀；返回前无需再取（已控制在 $[0, \text{MOD})$）。
7. **与滑动窗口计数混淆**：LC 713 那类「以右端点收尾的窗口贡献 $r-l+1$」是**连续子数组**专属公式；本题是子序列，选与不选的乘法原理（$2$ 的幂）才是正确结构，窗口长度公式在这里完全不适用。
8. **别把「子序列」当「子数组」枚举**：题目允许跳跃选取，总子序列数是 $2^n - 1$ 而非 $n(n+1)/2$；示例 3 用 $63 = 2^6 - 1$ 交叉验证答案 61。
