# LeetCode 每个查询的最大异或值 题解

## 1. 题目概述

- **标题 / 题号**：每个查询的最大异或值（#1829，medium）
- **链接**：https://leetcode.cn/problems/maximum-xor-for-each-query/
- **来源**：LeetCode 第 50 场双周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、前缀和

**题意**：给定升序数组 `nums`（$n$ 个非负整数，每个都 $< 2^{\textit{maximumBit}}$）与整数 `maximumBit`。执行 $n$ 次查询，第 $i$ 次查询时：先找一个非负整数 $k < 2^{\textit{maximumBit}}$ 使当前数组全部元素的异或 $P$ 与 $k$ 异或后**最大**，记为答案 `answer[i]`；然后**删除数组最后一个元素**。返回 `answer`。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \textit{maximumBit} \le 30$
- $0 \le nums[i] < 2^{\textit{maximumBit}}$

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,1,3], maximumBit = 2
输出：[0,3,2,3]
解释：4 次查询的数组分别为 [0,1,1,3]、[0,1,1]、[0,1]、[0]，
     对应前缀异或 P = 3、0、1、0，k = P XOR 3 = 0、3、2、3，结果都达到上界 3。
```

**示例 2**

```text
输入：nums = [2,3,4,7], maximumBit = 3
输出：[5,2,6,5]
解释：各次前缀异或为 2、1、5、2... 逐次取 k = P XOR 7，结果恒为 7。
```

**示例 3**

```text
输入：nums = [0,1,2,2,5,7], maximumBit = 3
输出：[4,3,6,4,6,7]
```

## 3. 解题思路

### 3.1 暴力思路

每次查询把当前数组异或一遍得到 $P$，再枚举 $k \in [0, 2^{\textit{maximumBit}})$ 逐个试 $P \oplus k$ 取最大：总复杂度 $O(n^2 + n \cdot 2^{\textit{maximumBit}})$，$n = 10^5$、$\textit{maximumBit} = 30$ 时完全不可行。两处都可优化：异或总和可以用"前缀异或 + 撤销"维护；而"枚举 $k$ 求最大"根本不用枚举——上界可以直接达到。

### 3.2 核心观察：最大值就是全 1，$k$ 取前缀异或的"取反"

![位视角：k 的每一位都设成与 P 相反，把结果每一位都补成 1](images/bw50_q3_bit_complement.svg)

设当前前缀异或为 $P$。由于每个 $nums[i] < 2^{\textit{maximumBit}}$，有 $P < 2^{\textit{maximumBit}}$，即 $P$ 的二进制只有 $\textit{maximumBit}$ 位。于是：

- $P \oplus k$ 的每一位都只能在第 $0 \sim \textit{maximumBit}-1$ 位上活动，故 $P \oplus k \le 2^{\textit{maximumBit}} - 1$（**全 1** 是理论上界）；
- 从最高位往低位**贪心**：想让结果的第 $j$ 位为 1，就把 $k$ 的第 $j$ 位设成与 $P$ 的第 $j$ 位**相反**。每一位都能做到——这正是

$$k = P \oplus (2^{\textit{maximumBit}} - 1),$$

即 $k$ 是 $P$ 在 $\textit{maximumBit}$ 位宽度内的**按位取反**。如此 $P \oplus k = 2^{\textit{maximumBit}} - 1$ 恰好撞上理论最大值；又 $k$ 的每一位也都在 $\textit{maximumBit}$ 位内，合法（$0 \le k < 2^{\textit{maximumBit}}$）。**每一步查询的答案结果恒为全 1**，变的只是 $k$。

### 3.3 算法流程：前缀异或 + 撤销最后一个元素

![前缀异或与撤销：每次删掉末尾元素即异或回去](images/bw50_q3_prefix_rollback.svg)

```text
1. mask = 2^maximumBit − 1（全 1）
2. prefix = nums 全体异或        # 第一次查询针对整个数组
3. answer = []
4. 对 i = n−1 downto 0：
       answer 追加 prefix XOR mask     # k = P 的按位取反
       prefix ^= nums[i]               # 撤销末尾元素 → 下一查询的前缀异或
5. 返回 answer
```

关键在于：删除末尾元素后的数组异或 = 原前缀异或 $\oplus$ 该元素（异或的自逆性：$x \oplus x = 0$），无需重算整个前缀。题面强调"**有序数组**"是个烟雾弹——异或与顺序无关。

### 3.4 示例演算

**示例 1**（$mask = 3$）：

| 查询 | 当前数组 | $P$ | $k = P \oplus 3$ | $P \oplus k$ |
|------|------------|-----|------------------|---------------|
| 1 | [0,1,1,3] | $0{\oplus}1{\oplus}1{\oplus}3 = 3$ | $3{\oplus}3 = 0$ | 3 |
| 2 | [0,1,1] | 0 | 3 | 3 |
| 3 | [0,1] | 1 | 2 | 3 |
| 4 | [0] | 0 | 3 | 3 |

`answer = [0,3,2,3]` ✓——注意 `answer[i]` 存的是 $k$ 而不是异或结果，每行的 $k$ 恰是题目要的答案。

## 4. 算法细节

1. **先算整个数组的前缀异或**：第一次查询作用在完整数组上，从 $P_{\text{全}}$ 起步；循环从 $i = n-1$ 开始，"追加答案 → 撤销末位"的次序别颠倒。
2. **mask 的构造**：`mask = (1 << maximumBit) - 1`。$\textit{maximumBit} = 30$ 时 $2^{30}$ 恰在 `int` 边缘（$2^{30} < 2^{31}-1$，安全；但 `1 << 30` 仍建议配 `int` 无符号习惯），Python 天然大整数无碍。
3. **撤销用自逆**：`prefix ^= nums[i]` 一行完成"删除"，因为异或满足 $a \oplus b \oplus b = a$。
4. **升序是干扰信息**：不需要排序、二分或任何有序性结构。
5. **复杂度敏感点**：全程 $O(n)$、无额外数组，比"每次重新异或一遍"的 $O(n^2)$ 写法快两个数量级。

## 5. 正确性证明

**引理 1（值域上界）**：若 $0 \le P, k < 2^m$，则 $P \oplus k < 2^m$，故 $P \oplus k \le 2^m - 1$。

**证明**：$P, k$ 的二进制展开中第 $m$ 位及以上均为 0，逐位异或后这些位仍为 0，故结果 $< 2^m$。∎

**引理 2（上界可达）**：取 $k = P \oplus (2^m - 1)$，则 $0 \le k < 2^m$ 且 $P \oplus k = 2^m - 1$。

**证明**：由 $0 \le P < 2^m$ 知 $P$ 的第 $0 \sim m-1$ 位与全 1 异或后恰好逐位取反，结果各位均为 1 或 0 且不超过 $m$ 位，故 $0 \le k < 2^m$，合法。代入：$P \oplus k = P \oplus P \oplus (2^m-1) = 0 \oplus (2^m - 1) = 2^m - 1$（异或结合律与自逆性）。∎

**定理**：设第 $i$ 次查询时数组为 $nums[0..n-i)$，其异或为 $P_i$，则最优的 $k$ 为 $P_i \oplus (2^{\textit{maximumBit}}-1)$，算法输出正确。

**证明**：由约束 $nums[j] < 2^{\textit{maximumBit}}$，归纳得 $P_i < 2^{\textit{maximumBit}}$。由引理 1，任何合法 $k$ 给出的结果 $\le 2^{\textit{maximumBit}} - 1$；由引理 2，算法取的 $k$ 恰达到该上界，故为最优。前缀异或的滚动维护由 $P_{i+1} = P_i \oplus nums[n-i]$ 直接给出（删除末位元素），与定义一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一遍求总异或 $O(n)$，循环每步常数次位运算，共 $n$ 步。
- **空间**：$O(1)$ 额外空间（输出数组不计）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> getMaximumXor(vector<int>& nums, int maximumBit) {
        int mask = (1 << maximumBit) - 1;             // k 的取值范围 [0, 2^maximumBit)
        int prefix = 0;
        for (int x : nums) prefix ^= x;              // 整个数组的前缀异或
        vector<int> ans;
        for (int i = (int)nums.size() - 1; i >= 0; --i) {
            ans.push_back(prefix ^ mask);             // k = 全 1 异或当前前缀异或
            prefix ^= nums[i];                       // 撤销最后一个元素
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getMaximumXor(self, nums: list[int], maximumBit: int) -> list[int]:
        mask = (1 << maximumBit) - 1        # k 的取值范围 [0, 2^maximumBit)
        prefix = 0
        for x in nums:
            prefix ^= x
        ans = []
        for i in range(len(nums) - 1, -1, -1):
            ans.append(prefix ^ mask)       # k = 全 1 异或当前前缀异或
            prefix ^= nums[i]               # 撤销最后一个元素
        return ans
```

> 💡 两份代码通过官方 3 个示例（`[0,3,2,3]`、`[5,2,6,5]`、`[4,3,6,4,6,7]`），与"每次穷举全部 $k \in [0, 2^{\textit{maximumBit}})$ 取最大"的暴力在 2000 组随机数据（$n \le 8$、$\textit{maximumBit} \le 4$）上对拍（`mismatch = 0`），$n = 10^5$、$\textit{maximumBit} = 30$ 大数组瞬时完成且两语言一致。

## 8. 边界情况与易错点

1. **答案存 $k$ 而不是最大值**：每步的最大值恒为 $2^{\textit{maximumBit}} - 1$（全 1），要返回的是达成它的 $k$；把 `ans.append(mask)` 当答案就全错了。
2. **查询顺序**：第 1 个查询对应**完整数组**，最后一个查询对应只剩 `nums[0]`；先算总异或、再倒序撤销，顺序颠倒会把第一次查询作用在单元素上。
3. **`mask` 别写成 `2^maximumBit`**：$k$ 的合法范围是 $[0, 2^m)$，全 1 是 $2^m - 1$，多 1 就越界非法。
4. **$\textit{maximumBit} = 1$**：$mask = 1$，$k \in \{0,1\}$，逻辑自动退化正确，无需特判。
5. **异或自逆性撤销**：`prefix ^= nums[i]` 依赖"被撤销的元素恰好是累加过的那一个"，若数组顺序被改动（例如先排序）会撤销错位——本题根本不需要排序。
6. **溢出错觉**：$\textit{maximumBit} \le 30$，$2^{30} - 1 < 2^{31} - 1$，`int` 安全；若题面放宽到 31 位以上才需要 `long long`/Python。
