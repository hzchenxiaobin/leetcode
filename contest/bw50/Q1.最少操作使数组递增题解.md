# LeetCode 最少操作使数组递增 题解

## 1. 题目概述

- **标题 / 题号**：最少操作使数组递增（#1827，easy）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-the-array-increasing/
- **来源**：LeetCode 第 50 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、数组

**题意**：每次操作可任选数组中一个元素并将其**加 1**。求使 `nums` 变成**严格递增**（对所有 $0 \le i < n-1$ 有 $nums[i] < nums[i+1]$）的最少操作次数。

**约束**：

- $1 \le n \le 5000$
- $1 \le nums[i] \le 10^4$

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,1]
输出：3
解释：[1,1,1] → [1,2,1] → [1,2,2] → [1,2,3]，共 3 次操作。
```

**示例 2**

```text
输入：nums = [1,5,2,4,1]
输出：14
解释：最终变成 [1,5,6,7,8]，各位置分别抬升 0+0+4+3+7 = 14 次。
```

**示例 3**

```text
输入：nums = [8]
输出：0
解释：长度为 1 的数组是严格递增的特例。
```

## 3. 解题思路

### 3.1 暴力思路

把每个位置的最终值作为变量，最小化 $\sum (\text{最终值} - nums[i])$，且最终值严格递增、每个最终值 $\ge$ 原值——这是一个整数规划 / DP 问题：$dp[i][v]$ 表示前 $i$ 个元素、第 $i$ 个抬到 $v$ 的最小代价，转移取 $\min_{v' < v} dp[i-1][v']$，复杂度 $O(n \cdot V^2)$。能做，但这里有个决定性的事实：**只能加不能减**，因此每个元素"抬得越低，给后面留的余地越大"，最优解必然是逐个取下界的——贪心一行搞定。

### 3.2 核心观察：只加不减 → 每个位置都取理论下界

![贪心抬柱：每个元素抬到恰好 prev+1](images/bw50_q1_lift_bars.svg)

从左往右扫，维护"上一个位置的最终值" $\text{prev}$。当前位置的最终值必须**严格大于 prev** 且**不小于原值**，而抬高当前元素只会让后面的元素被迫更高（操作单调地向上传导），所以最优选择就是两者中较大的那一个：

$$\text{prev} \leftarrow \max(\text{prev} + 1,\; x)， \qquad \text{代价} \mathrel{+}= \text{prev} - x.$$

直觉上这是"把柱状图逐列垫高到比前一列恰好高 1"；任何"多垫一格"的行为都会原样传导成后面至少多一格的代价，不会更优。

### 3.3 算法流程

```text
1. prev = nums[0]，ans = 0
2. 对 i = 1 .. n-1：
       prev = max(prev + 1, nums[i])   # 本位置最终值：取下界
       ans += prev - nums[i]           # 抬升代价
3. 返回 ans
```

### 3.4 示例演算

![示例 2 的逐元素演算表](images/bw50_q1_walkthrough_table.svg)

**示例 2**（$[1,5,2,4,1]$）：

| $i$ | 原值 $x$ | 下界 $\max(\text{prev}{+}1, x)$ | 最终值 | 抬升次数 |
|-----|----------|-------------------------------|--------|----------|
| 0 | 1 | —（起点） | 1 | 0 |
| 1 | 5 | $\max(2,5)$ | 5 | 0 |
| 2 | 2 | $\max(6,2)$ | 6 | 4 |
| 3 | 4 | $\max(7,4)$ | 7 | 3 |
| 4 | 1 | $\max(8,1)$ | 8 | 7 |

合计 $0+0+4+3+7 = 14$ ✓。

**示例 1**（$[1,1,1]$）：三个位置依次抬到 $1,2,3$，代价 $0+1+2=3$ ✓；**示例 3** 单元素无相邻对，代价 0 ✓。

## 4. 算法细节

1. **prev 初始化为 nums[0]**：首元素不需要任何操作（它左边没有约束）。
2. **更新次序**：先算新 `prev` 再累加代价，`ans += prev - nums[i]` 中的 `prev` 已是最终值。
3. **数值范围**：最坏情况 $n=5000$ 个全 1，总代价 $\sum_{k=1}^{n-1} k \approx 1.25 \times 10^7$；再加上原值上限 $10^4$，总代价 $< 5 \times 10^7$，`int` 放得下，但 C++ 中用 `long long` 累加更稳妥。
4. **原地修改与否**：不需要真的修改数组，只维护 `prev`，空间 $O(1)$。

## 5. 正确性证明

**引理 1（下界）**：任何合法方案中，从左到右定义最终值序列 $b_0 < b_1 < \dots < b_{n-1}$ 且 $b_i \ge nums[i]$。则 $b_i \ge b^{opt}_i$，其中 $b^{opt}_i$ 由贪心递推 $b^{opt}_0 = nums[0]$、$b^{opt}_i = \max(b^{opt}_{i-1} + 1,\; nums[i])$ 给出。

**证明**：对 $i$ 归纳。$i=0$：$b_0 \ge nums[0] = b^{opt}_0$。设 $b_{i-1} \ge b^{opt}_{i-1}$。则 $b_i > b_{i-1} \ge b^{opt}_{i-1}$，即 $b_i \ge b_{i-1} + 1 \ge b^{opt}_{i-1} + 1$；又 $b_i \ge nums[i]$，两者合并得 $b_i \ge \max(b^{opt}_{i-1}+1,\; nums[i]) = b^{opt}_i$。∎

**定理（贪心最优）**：贪心序列 $b^{opt}$ 本身合法，且总代价 $\sum_i (b^{opt}_i - nums[i])$ 是所有合法方案的最小值。

**证明**：合法性：$b^{opt}_i \ge b^{opt}_{i-1} + 1$ 即严格递增，且 $b^{opt}_i \ge nums[i]$ 只增不减，每步代价非负。对任意合法方案 $b$，由引理 1 逐项 $b_i \ge b^{opt}_i \ge nums[i]$，故 $\sum (b_i - nums[i]) \ge \sum (b^{opt}_i - nums[i])$，贪心达到下界，最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，每个元素常数次比较与加法。
- **空间**：$O(1)$。仅 `prev` 与累加器两个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums) {
        long long ans = 0;
        int prev = nums[0];
        for (size_t i = 1; i < nums.size(); ++i) {
            prev = max(prev + 1, nums[i]);   // 本位置最终值：取下界 prev+1 与原值的较大者
            ans += prev - nums[i];           // 抬升代价
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int]) -> int:
        ans = 0
        prev = nums[0]
        for x in nums[1:]:
            prev = max(prev + 1, x)      # x 至少要抬到 prev + 1
            ans += prev - x              # 抬升代价
        return ans
```

> 💡 两份代码通过官方 3 个示例（`3 / 14 / 0`），并与"逐位置 DP 求最小总抬升"的独立暴力在 2000 组随机数组（$n \le 12$、值 $\le 15$）上对拍（`mismatch = 0`）；C++ 与 Python 在 300 组随机输入上交叉一致。

## 8. 边界情况与易错点

1. **单元素数组**：循环不执行，返回 0；不要给 `nums[0]` 预先加操作。
2. **只能加不能减**：若忽视这一约束写成"调整到任意严格递增"，会错误地给出类似最长递增子序列的更小代价；本题下界受 $b_i \ge nums[i]$ 钳制。
3. **溢出评估**：全 1 数组总代价约 $n^2/2 = 1.25 \times 10^7$，`int` 安全，但若题面放大 $n$ 或值域，`long long` 是习惯性保险。
4. **`prev` 未更新**：忘记 `prev = max(prev+1, x)`、一直用旧值比较，是这题最常见的笔误。
5. **严格递增 vs 非递减**：是 `prev + 1` 不是 `prev`；"非递减"版本（允许相等）见延伸思考。
