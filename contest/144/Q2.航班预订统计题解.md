# LeetCode 航班预订统计 题解

## 1. 题目概述

- **标题 / 题号**：航班预订统计（#1109，medium）
- **链接**：https://leetcode.cn/problems/corporate-flight-bookings/
- **来源**：LeetCode 第 144 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和

**题意**：有 $n$ 个航班，编号 $1 \sim n$。预订表 `bookings` 的每条记录 `[first, last, seats]` 表示**从 first 到 last（含两端）的每一个航班**都新增 `seats` 个已订座位。返回长度为 $n$ 的数组 `answer`，其中 `answer[i]` 是第 $i+1$ 个航班的座位总数。

题目的本质是：给定 $m$ 次**区间加**操作，求所有操作结束后的**最终点值**。

**约束**：

- $1 \le n \le 2 \times 10^4$
- $1 \le \text{bookings.length} \le 2 \times 10^4$
- $\text{bookings}[i].\text{length} = 3$
- $1 \le \text{first}_i \le \text{last}_i \le n$
- $1 \le \text{seats}_i \le 10^4$

## 2. 示例

**示例 1**

```text
输入：bookings = [[1,2,10],[2,3,20],[2,5,25]], n = 5
输出：[10,55,45,25,25]
解释：航班 1 只被第 1 条预订覆盖      → 10
      航班 2 被三条预订同时覆盖        → 10+20+25 = 55
      航班 3 被第 2、3 条覆盖          → 20+25 = 45
      航班 4、5 只被第 3 条覆盖        → 25
```

**示例 2**

```text
输入：bookings = [[1,2,10],[2,2,15]], n = 2
输出：[10,25]
解释：第 2 条预订只覆盖航班 2 自己（first = last = 2），
      故航班 2 得到 10 + 15 = 25。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每条预订 `[first, last, seats]`，用一个内层循环把 `answer[first-1 .. last-1]` 逐个加上 `seats`。

- 单条预订的代价是区间长度 $\text{last} - \text{first} + 1$，最坏为 $n$；
- 总代价 $\sum (\text{last}_i - \text{first}_i + 1) \le n \cdot m = 4 \times 10^8$。

在 $n, m$ 均取上界、且每条预订都覆盖整段航班时，这是 $4 \times 10^8$ 次加法，明显超时。瓶颈在于：**同一段连续位置被加上了同一个值，我们却对每个位置都单独写了一次**。

### 3.2 核心观察：区间加 = 两个「事件」

![差分数组把区间加变成两个端点事件](images/wc144_q2_difference_model.svg)

把答案数组反过来看——不直接维护「每个航班现在多少座位」，而是维护**增量从哪个位置开始、到哪个位置结束**：

对第 $j$ 条预订 $[\text{first}_j, \text{last}_j]$ 加 $v_j$ 来说，它在差分数组上只留下两个单点操作：

- 在 $\text{first}_j$ 处加 $v_j$（增量从第 $\text{first}_j$ 个航班起生效）；
- 在 $\text{last}_j + 1$ 处减 $v_j$（从第 $\text{last}_j + 1$ 个航班起撤销）。

之后对 `diff` 求一次**前缀和**，就还原出每个航班的座位数：

$$\text{answer}[i] = \sum_{k=1}^{i} \text{diff}[k]$$

直觉：`diff[l] += v` 是「从第 $l$ 个航班起，这段增量开始生效」；`diff[r+1] -= v` 是「从第 $r+1$ 个航班起，它被撤销」。两条事件的**时间点不同**，于是区间 $[l, r]$ 内的每个点在前缀和里都恰好累加一次 $v$，区间外则先加后减、完全抵消。

这样一次区间加从 $O(\text{len})$ 降到 $O(1)$，总复杂度变成 $O(n + m)$。

### 3.3 算法流程

![先记账再结算的算法流程](images/wc144_q2_algorithm_flow.svg)

```text
1. diff[1..n+1] = 0                       // 多开一格，容纳 last = n 时的 last+1
2. for each [first, last, seats] in bookings:
       diff[first]     += seats
       diff[last + 1]  -= seats
3. cur = 0
   for i = 1 .. n:
       cur += diff[i]                     // 前缀和
       answer[i-1] = cur
4. 返回 answer
```

两个循环互不嵌套：第一个循环只看 `bookings`，第二个循环只看 `diff`，所以总代价是 $O(m + n)$。

### 3.4 示例演算

![示例 1 的差分数组与前缀和走查](images/wc144_q2_walkthrough.svg)

以示例 1 为例（$n = 5$），三条预订被拆成 6 个事件，叠加后 `diff[1..6] = [10, 45, -10, -20, 0, -25]`，再做前缀和：

| $i$ | $\text{diff}[i]$ | 来源 | $cur$（累加） | $answer[i-1]$ |
|-----|------------------|------|----------------|----------------|
| 1 | +10 | 预订 1 的起点 | 10 | 10 |
| 2 | +45 | 预订 2 的起点 +20、预订 3 的起点 +25 | 55 | 55 |
| 3 | −10 | 预订 1 的终点后撤销 | 45 | 45 |
| 4 | −20 | 预订 2 的终点后撤销 | 25 | 25 |
| 5 | 0 | 无事件 | 25 | 25 |
| 6 | −25 | 预订 3 的终点后撤销（不进答案） | 0 | — |

得到 `[10,55,45,25,25]`，与官方输出一致。注意 `i = 6` 这一格只是「收尾」，它保证前缀和在 $n$ 之后归零，但不会写入答案。

## 4. 算法细节

1. **`diff` 长度取 $n+2$**：下标 $1 \sim n$ 对应航班 $1 \sim n$，而 $\text{last} = n$ 时要写 $\text{diff}[n+1]$，所以数组至少要有 $n+2$ 个元素（0 号位空置）。这是本题最高频的越界点。
2. **下标从 1 开始最省心**：`first`、`last` 都是 1-based，直接把 `diff` 开成 1-based，避免在循环里反复 `first - 1`；只在最后写 `answer[i-1]` 时转换一次。
3. **不需要真的存前缀和数组**：`cur` 一个变量滚动累加即可，`answer` 就是最终结果数组，空间只多出 `diff`。
4. **数值范围**：单点最大值是 $2 \times 10^4 \times 10^4 = 2 \times 10^8$，在 32 位有符号整数范围内，C++ 用 `int` 足够；若 `seats` 上界改为 $10^9$，则 `diff` 与 `cur` 都必须换成 `long long`。
5. **事件可以叠加**：多条预订出现相同的 `first` 或相同的 `last+1` 时，直接在 `diff` 上累加即可，不需要去重或排序。
6. **与「前缀和数组」区分**：`diff` 是**事件表**（记录变化量），`answer` 是**前缀和**（记录绝对量）。二者含义不同，混用会把符号写反。
7. **反向操作不要写**：先求答案再扣减（离线删除）在这题里没有意义；差分只做一次正向结算。

## 5. 正确性证明

设第 $j$ 条预订为 $[l_j, r_j]$、增量为 $v_j$（$1 \le j \le m$）。

**引理 1（差分数组刻画了事件）**：算法结束后，对每个 $k \in [1, n+1]$，

$$\text{diff}[k] = \sum_{j:\, l_j = k} v_j \; - \sum_{j:\, r_j + 1 = k} v_j.$$

**证明**：`diff` 初值全为 0，每条预订恰好执行两次单点加：在 $l_j$ 处加 $v_j$，在 $r_j + 1$ 处减 $v_j$。由于所有操作都是加法且互不影响（加法可交换），最终每个位置的值就是落在该位置上的所有操作之和，即上式。∎

**引理 2（前缀和等于座位数）**：对每个 $i \in [1, n]$，算法第 3 步结束时

$$\text{cur}_i = \sum_{k=1}^{i} \text{diff}[k] = \sum_{j:\, l_j \le i \le r_j} v_j.$$

**证明**：第一式由前缀和的定义直接得到。对第二式，把引理 1 代入并按「起点事件 / 终点事件」分组：

$$\sum_{k=1}^{i} \text{diff}[k] = \sum_{j:\, l_j \le i} v_j \; - \sum_{j:\, r_j + 1 \le i} v_j = \sum_{j:\, l_j \le i} v_j \; - \sum_{j:\, r_j < i} v_j.$$

对每条预订 $j$ 分类讨论它在差值中的系数：

- 若 $l_j \le i$ 且 $r_j \ge i$（即 $i$ 被预订 $j$ 覆盖），它只出现在第一项，系数为 $+1$；
- 若 $r_j < i$，则必有 $l_j \le r_j < i$，它同时出现在两项中，系数 $+1 - 1 = 0$；
- 若 $l_j > i$，由 $l_j \le r_j$ 得 $r_j \ge l_j > i$，两项都不出现，系数为 $0$。

故求和只剩被覆盖的预订，每条的贡献恰为 $v_j$。∎

**定理（算法正确）**：算法返回的 `answer` 满足 $\text{answer}[i-1]$ 等于第 $i$ 个航班的座位总数。

**证明**：算法令 $\text{answer}[i-1] = \text{cur}_i$，而由引理 2，$\text{cur}_i = \sum_{j: l_j \le i \le r_j} v_j$，正是所有覆盖第 $i$ 个航班的预订座位数之和。由 $i$ 的任意性，数组每个位置都正确。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。第一个循环遍历 $m$ 条预订，每条做两次单点加，$O(m)$；第二个循环对 $i = 1 \sim n$ 做一次加法与一次赋值，$O(n)$。两次循环顺序执行、互不嵌套。
- **空间**：$O(n)$。`diff` 长 $n+2$，答案数组长 $n$，除此之外只有常数个标量。若不把返回值计入，则额外空间为 $O(n)$；输入本身不被修改。

对比暴力解 $O(nm)$（最坏 $4 \times 10^8$），差分把「区间长度」这一维彻底消掉了。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> corpFlightBookings(vector<vector<int>>& bookings, int n) {
        // 1-based：diff[1..n+1]，多开一位容纳 last + 1
        vector<int> diff(n + 2, 0);
        for (const auto& b : bookings) {
            int first = b[0], last = b[1], seats = b[2];
            diff[first] += seats;
            diff[last + 1] -= seats;
        }
        vector<int> answer(n);
        int cur = 0;
        for (int i = 1; i <= n; ++i) {
            cur += diff[i];
            answer[i - 1] = cur;
        }
        return answer;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def corpFlightBookings(self, bookings: List[List[int]], n: int) -> List[int]:
        diff = [0] * (n + 2)          # diff[1..n+1]，0 号位空置
        for first, last, seats in bookings:
            diff[first] += seats
            diff[last + 1] -= seats

        answer = [0] * n
        cur = 0
        for i in range(1, n + 1):
            cur += diff[i]
            answer[i - 1] = cur
        return answer
```

## 8. 边界情况与易错点

1. **`diff` 开小了直接越界**：当某条预订的 `last = n` 时，代码要写 `diff[n + 1]`。只开 `n` 或 `n + 1` 个元素（且用 0-based 时更易错）会数组越界，务必开到 `n + 2`。
2. **`first == last` 的退化区间**：只影响一个航班，差分写法无需特判；若强行特判反而容易漏掉 `diff[r+1]` 的撤销。
3. **`n = 1`**：`diff` 长度为 3，写入 `diff[1] += v` 与 `diff[2] -= v` 都合法，前缀和只扫 `i = 1`，返回单元素数组。
4. **下标基准混用**：`bookings` 是 1-based，结果数组是 0-based。写完 `diff` 后忘记 `answer[i-1]`，会让结果整体右移一位。
5. **符号写反**：差分是「起点加、终点后减」。若写成 `diff[last] -= seats`，等于把区间的最后一个航班漏掉。
6. **溢出**：本题 $2 \times 10^8$ 不溢出 `int`；但若把 `seats` 或 `n` 放宽到 $10^9$ 量级，`diff`、`cur` 与返回值都要换成 64 位整数。
7. **重复预订**：题目允许同一区间被预订多次，答案要**累加**而不是覆盖，差分天然支持。
8. **不要在循环里反复创建列表**：Python 里用 `[0] * (n + 2)` 一次性分配，比逐步 `append` 更快也更少出错。

**延伸思考**：

1. 若操作变成「区间加、单点查询」，差分数组即可，甚至不需要最后的前缀和；若变成「单点加、区间求和」，则要换成树状数组或前缀和数组。本题是「区间加、全局最后查询」这一最简情形。
2. 若把一维航班换成 $n \times n$ 的矩阵、预订换成子矩阵加，就要用**二维差分**：四个角各记一次事件，再在行、列两个方向分别做前缀和。
3. 若预订是**在线**的（每次加完立刻要查询某个航班），差分失效，需要线段树或树状数组维护区间加与单点查询，代价升到 $O((n + m)\log n)$。
