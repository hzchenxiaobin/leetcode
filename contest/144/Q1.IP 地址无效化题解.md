# LeetCode IP 地址无效化 题解

## 1. 题目概述

- **标题 / 题号**：IP 地址无效化（#1108，easy）
- **链接**：https://leetcode.cn/problems/defanging-an-ip-address/
- **来源**：LeetCode 第 144 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定一个合法的 IPv4 地址字符串 `address`，把其中每个点号 `.` 替换成三字符的 `[.]`，返回替换后的字符串。例如 `1.1.1.1` 变成 `1[.]1[.]1[.]1`。

**关键概念**：「无效化」不是数值解析，也不是地址校验，只是**纯文本的字符级替换**。替换后的串不再能被解析成 IPv4 地址，从而不会被邮件客户端、聊天工具误识别成可点击的链接——这正是题目名字的由来。

**约束**：

- `address` 是一个合法的 IPv4 地址：4 段十进制数用 `.` 连接，每段取值 $0 \sim 255$；
- 因此串中**恰好有 3 个点号**，字符只可能是数字与 `.`，长度在 $7 \sim 15$ 之间；
- 不需要（也不应该）做任何合法性校验或数值转换。

## 2. 示例

**示例 1**

```text
输入：address = "1.1.1.1"
输出："1[.]1[.]1[.]1"
解释：3 个点号各自替换为 "[.]"，数字原样保留，字符顺序不变。
```

**示例 2**

```text
输入：address = "255.100.50.0"
输出："255[.]100[.]50[.]0"
解释：每段的位数可以不同（1~3 位），但替换规则与段长无关。
```

**补充示例（非官方，边界）**

```text
输入：address = "0.0.0.0"
输出："0[.]0[.]0[.]0"
解释：最短的合法 IPv4 地址，n = 7，输出长度 7 + 2 × 3 = 13。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是反复用 `find('.')` 找点号，再在该位置 `insert("[.]")` 并删掉原来的点号。每次插入/删除都要搬移后面的全部字符，最坏 $O(n^2)$。另一种常见写法是按 `.` 切分成若干段，再用 `"[.]"` 连接，时间 $O(n)$，但需要额外的切分数组，且把「一换三」这件事藏进了库函数里。

两种写法都能过（$n \le 15$），但都绕开了问题的真正结构。要先回答一个问题：**这些替换会互相影响吗？**

### 3.2 核心观察：字符之间完全独立

![只有点号需要一分为三](images/wc144_q1_expand_concept.svg)

答案是否定的。对每个字符单独定义一个映射：

$$
f(c)=
\begin{cases}
\texttt{"[.]"}, & c = \texttt{'.'},\\
c, & c \ne \texttt{'.'}.
\end{cases}
$$

因为替换只依赖当前字符本身、不依赖它前面或后面是什么，所以整串答案就是把每个字符的像按原顺序拼起来：

$$
\text{ans} = f(address[0]) \,\|\, f(address[1]) \,\|\, \cdots \,\|\, f(address[n-1]).
$$

由此还能**预先算出答案长度**。设 $k$ 为点号个数，每个点号让长度增加 $2$，于是

$$
|\text{ans}| = n + 2k.
$$

本题是合法 IPv4，$k$ 恒为 $3$，所以 $|\text{ans}| = n + 6$。有了长度就可以一次性预留缓冲区，扫描一遍直接填完；而任何正确算法都必须至少读入每个字符，因此 $O(n)$ 已是下界。

> 💡 一句话模板：**「逐字符独立映射 + 预计算输出长度」**。凡是「某些字符替换成长度不同的串，且替换规则互不影响」的题，都可以套这个框架。

### 3.3 算法流程

![一次扫描的流程图](images/wc144_q1_scan_flow.svg)

```text
ans ← 空串
for i ← 0 to n-1:
    c ← address[i]
    if c = '.':
        ans ← ans + "[.]"
    else:
        ans ← ans + c
return ans
```

伪代码里的 `ans +` 在 C++ 中对应 `ans +=`（均摊 $O(1)$），在 Python 中应改为往列表 `append` 后 `join`。C++ 还有一个更省内存的写法：把 `address` 直接 `resize` 到 $n+6$，然后用两个指针**从右往左**填充（见 §4 第 4 条），这样连输出缓冲都不额外分配。

### 3.4 示例演算

以 `address = "1.0.0.1"` 为例（$n = 7$、$k = 3$，输出长度 $13$）：

![逐字符走查](images/wc144_q1_walkthrough.svg)

| 步骤 | 读入 | 追加 | 当前答案 |
|------|------|------|----------|
| 0 | `1` | `1` | `1` |
| 1 | `.` | `[.]` | `1[.]` |
| 2 | `0` | `0` | `1[.]0` |
| 3 | `.` | `[.]` | `1[.]0[.]` |
| 4 | `0` | `0` | `1[.]0[.]0` |
| 5 | `.` | `[.]` | `1[.]0[.]0[.]` |
| 6 | `1` | `1` | `1[.]0[.]0[.]1` |

每一步只做一次判断，且处理完前 $i$ 个字符后，`ans` 永远是「前 $i$ 个字符的无效化结果」——这条不变式就是下一节证明的核心。

## 4. 算法细节

1. **预留容量**：C++ 先 `ans.reserve(address.size() + 6)`。合法 IPv4 恰有 3 个点，每个点多出 2 个字符，因此最终长度恰好为 $n + 6$，一次分配即可，避免中途扩容搬移。
2. **追加而不是拼接**：`ans += c` / `ans += "[.]"` 是均摊 $O(1)$ 的；不要写 `ans = ans + c`，那会每轮复制整个串。
3. **判断条件只认点号**：`if (c == '.')` 就够了。不要用 `isdigit` 反向排除——题面保证输入合法，多写校验反而增加出错面。
4. **原地扩张（可选优化）**：C++ 中先 `address.resize(n + 6)`，令 `i = n - 1`、`j = n + 5`；若 `address[i] == '.'` 则把 `"[.]"` 逆序写到 `j-2..j` 并令 `j -= 3`，否则写单字符并令 `j -= 1`，最后 `i -= 1`。由于扩张发生在右侧、且每次写入的区间都不越过当前读指针，不会覆盖尚未读取的字符。
5. **Python 的字符串不可变**：在循环里用 `ans += c` 会反复复制，最坏 $O(n^2)$。用 `list` 收集再 `''.join(...)`，或者直接用 `address.replace('.', '[.]')`（库函数一次扫描，语义与手写循环完全相同）。
6. **点号本身必须保留**：答案是 `[.]`（左方括号、点、右方括号），不是 `[]`，也不是 `[..]`；点号只是被「包」起来，并没有消失。
7. **按字符而非按字节思考**：`.` 是 ASCII 字符，按字节扫描在 UTF-8 下也不会切错，但通用写法应遍历「字符」。本题输入只有数字和点，两种写法结果一致。

## 5. 正确性证明

设 $n = |address|$，$f$ 为 §3.2 定义的字符映射，记 $S = f(address[0]) \| \cdots \| f(address[n-1])$。

**引理 1（前缀不变式）**：扫描循环处理完前 $i$ 个字符（下标 $0 \sim i-1$）后，`ans` 恰好等于 $f(address[0]) \| \cdots \| f(address[i-1])$。

**证明**：对 $i$ 归纳。$i = 0$ 时 `ans` 为空串，拼接也为空，成立。假设 $i$ 时成立，处理第 $i$ 个字符 $c = address[i]$：若 $c = \texttt{'.'}$，算法追加 `"[.]"`，即 $f(c)$；否则追加 $c$ 本身，也等于 $f(c)$。于是 `ans` 变为前 $i$ 个像的拼接再并上 $f(c)$，恰为前 $i+1$ 个像的拼接，不变式传递到 $i+1$。∎

**引理 2（原地扩张不破坏未读字符）**：设 $d_i$ 为前 $i$ 个字符中点的个数，则 $f(address[i])$ 在最终答案中的起始下标为 $i + 2d_i$。从右往左填充时，写指针处理的区间为 $[\,i + 2d_i,\ i + 2d_i + |f(address[i])| - 1\,]$，其左端点 $\ge i$。

**证明**：前 $i$ 个字符的像总长度是 $i + 2d_i$，所以第 $i$ 个字符的像紧接着排在它后面，起始下标正是 $i + 2d_i$。从右往左填充时，$j$ 等于最终长度 $n + 2k$ 减去后缀（第 $i$ 个字符之后的像）的长度再减一，即 $j = i + 2d_i + |f(address[i])| - 1$，正好是该区间的右端点。又 $d_i \ge 0$，故左端点 $i + 2d_i \ge i$。写入前字符 $address[i]$ 已被读入变量，位置 $i$ 可以安全覆盖；位置 $> i$ 的字符在更早的迭代中已经处理完毕。因此任何一次写入都不会破坏尚未读取的字符。∎

**定理**：上述算法返回的字符串等于 $S$，即「把 `address` 中每个 `.` 替换为 `"[.]"`」的结果。

**证明**：在引理 1 中取 $i = n$，得 $\text{ans} = f(address[0]) \| \cdots \| f(address[n-1]) = S$；而逐项展开 $f$ 的定义，数字保持原位、每个点号变成 `"[.]"`，正是题目要求的无效化结果。原地版本由引理 2 保证写入位置合法，且每个字符被写到它在最终答案中的唯一位置，故与顺序版本输出相同。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符只做一次比较和一次追加（追加的字符数不超过 3），共 $n$ 轮；任何算法都要读入全部字符，故这是最优量级。
- **空间**：$O(n)$，用于存放答案本身（长度 $n + 6$），这部分是输出必需的开销。
- **额外空间**：顺序版本除答案外为 $O(1)$；C++ 原地版本连答案缓冲区都复用入参，额外空间 $O(1)$。Python 因字符串不可变，至少需要 $O(n)$ 的新串。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string defangIPaddr(string address) {
        string ans;
        // 合法 IPv4 恰有 3 个点号，每个点号让结果多 2 个字符
        ans.reserve(address.size() + 6);
        for (char c : address) {
            if (c == '.') {
                ans += "[.]";
            } else {
                ans += c;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def defangIPaddr(self, address: str) -> str:
        parts = []
        for c in address:
            # 点号扩张成三个字符，其余字符原样保留
            parts.append("[.]" if c == "." else c)
        # 等价的一行写法：return address.replace(".", "[.]")
        return "".join(parts)
```

## 8. 边界情况与易错点

1. **点号被写丢**：正确答案是 `[.]`，三个字符都要有；写成 `[]` 会丢掉点号本身，写成 `[..]` 会多一个点。
2. **多写反斜杠**：不要把结果写成 `[\.]`。题面要求的是字面上的三个字符 `[`、`.`、`]`，没有转义。
3. **`reserve(n + 6)` 的前提**：它只在「恰有 3 个点」时刚好够用。若把函数推广到任意字符串，应先统计点数或用 $n + 2k$，否则容量不足时只会触发自动扩容，不影响正确性，但失去了这次优化的意义。
4. **最短与最长输入**：`"0.0.0.0"` → `"0[.]0[.]0[.]0"`（长度 13）；`"255.255.255.255"` → 长度 $15 + 6 = 21$。两者都不涉及溢出，但可用来核对长度公式。
5. **Python 循环内字符串拼接**：`ans += c` 每次都会新建字符串，$n$ 大时退化为 $O(n^2)$；本题 $n \le 15$ 看不出差异，但应养成 `list + join` 的习惯。
6. **返回类型**：接口是 `string defangIPaddr(string address)`，返回新字符串即可；不要返回 `vector<string>`、不要试图原地改写后返回引用，也不要输出带引号的字面量。
7. **不要做数值解析**：把每段转成整数再转回字符串会丢掉位数信息（如 `010` 变成 `10`），本题只应做文本替换。
