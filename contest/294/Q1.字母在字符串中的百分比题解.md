# LeetCode 字母在字符串中的百分比 题解

## 1. 题目概述

- **标题 / 题号**：字母在字符串中的百分比（#2278，easy）
- **链接**：https://leetcode.cn/problems/percentage-of-letter-in-string/
- **来源**：LeetCode 第 294 场周赛 Q1
- **难度**：简单
- **标签**：字符串、计数、数学

**题意**：给定字符串 `s` 和字符 `letter`，统计 `s` 中等于 `letter` 的字符占比，返回**百分比数值**，**向下取整**到最接近的百分比。

**约束**：

- $1 \le n = \text{len}(s) \le 100$
- `s` 由小写英文字母组成
- `letter` 是一个小写英文字母（**可能不在 `s` 中出现**）

> 💡 本题在本仓库另有[每日题解 2278](../../solution/2201-2300/2278_字母在字符串中的百分比.md)：以「先乘后除保精度」主线展开，含浮点规避的原理分析与面试问答。本篇按**周赛复盘视角**展开，侧重签到题从题面到代码的**最短提交路径**、两类高频 WA（**先除后乘 / 浮点截断**）在约束内的**实锤反例**、跨语言除法语义对照、引理-定理证明与边界清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：s = "foobar", letter = "o"
输出：33
解释：等于 'o' 的字符占比 2 / 6 × 100% = 33.33…%，向下取整得 33。
```

**示例 2**

```text
输入：s = "jjjj", letter = "k"
输出：0
解释：'k' 不在 s 中出现，占比 0%。
```

**补充反例：浮点写法在约束内必错（WA 实锤）**

```text
输入：s 为 29 个 'a' 加 71 个 'b'（n = 100），letter = 'a'
输出：29
解释：正确答案 29 × 100 // 100 = 29。
      浮点写法 int(29 / 100 * 100) 在 Python 与 C++ 中都得 28：
      0.29 的双精度近似是 0.289999…98，乘 100 得 28.999…96，
      向零截断后比真值少 1。
```

> ⚠️ 这个补充反例揭示浮点写法不是「理论上有隐患」而是**约束内可构造的必然错误**：$n \le 100$、$\text{cnt} \le n$ 的全部组合里，$(n,\text{cnt}) \in \{(50,29),\ (100,29),\ (100,57),\ (100,58)\}$ 四组的浮点结果都恰差 $1$——只要官方数据踩中任何一组，浮点提交即刻 WA。

## 3. 解题思路

### 3.1 直译题面的写法：两种「顺手」与两种坑

签到题的目标是**最短路径**：识别出这是「计数 + 整数百分比」模板后，一行即可是最优解。但两种「顺手的写法」都埋着雷：

**写法 A（浮点版）**：`int(cnt / n * 100)`。看似直译题面「占比乘 100 取整」，实则依赖二进制浮点近似——$\text{cnt}/n$ 多为无限循环小数，当真值恰为整数 $K$ 时浮点可能算成 $K - \epsilon$，截断后**少算 1**（补充反例的 28 vs 29）。官方数据未覆盖反例时侥幸 AC，覆盖即 WA。

**写法 B（先除后乘版）**：`cnt // n * 100`。看似「更纯的整数算术」，实则**过早取整**：$\text{cnt} < n$ 时 $\lfloor \text{cnt}/n \rfloor = 0$，乘 $100$ 还是 $0$——把示例 1 的 $33\%$ 直接抹成 $0\%$，**任何数据下必错**，是本题头号 WA。

两种坑同根同源：在「结果本是精确整数」的目标下，要么引入了近似（浮点），要么把取整提前到了会丢信息的位置（先除后乘）。

### 3.2 核心观察：先乘 100 放大，再整除取整

![核心观察：先乘 100 放大再整除取整，顺序即正确性](images/wc294_q1_multiply_first_concept.svg)

设 $n = \text{len}(s)$，$\text{cnt}$ 为 `letter` 出现次数，题目要的是

$$\text{ans} = \left\lfloor \frac{\text{cnt}}{n} \times 100 \right\rfloor$$

三层观察：

1. **乘除可交换次序（实数层面）**：$\dfrac{\text{cnt}}{n} \times 100 = \dfrac{\text{cnt} \times 100}{n}$，故整数写法 `cnt * 100 // n`（**先乘后除**）只在最后做一次取整，结果精确等于真值（引理 1）；而 `cnt // n * 100`（先除后乘）取整了**两次**，多丢一次小数部分（引理 2）。
2. **非负整数除法天然向下取整**：C++ 的 `/` 向零截断、Python 的 `//` 向下取整，但本题 $\text{cnt} \ge 0$、$n \ge 1$、$\text{cnt} \times 100 \ge 0$ 全非负，两种语义**结果一致**（引理 3）——「向下取整」由整数算术免费获得，无需 `floor`/`math.floor`。
3. **无溢出、无除零**：$n \ge 1$ 排除除零；$\text{cnt} \le n \le 100$，故 $\text{cnt} \times 100 \le 10^4$，远在 32 位 `int` 范围内，先乘绝对安全。

> 💡 一句话：**计数之后，先乘后除，绝不引入浮点。**`s.count(letter) * 100 // len(s)` 就是本题的最优提交——30 秒内可以落笔的签到答案。

### 3.3 算法流程

![算法流程：一趟遍历计数，先乘 100 再整除取整](images/wc294_q1_algorithm_flow.svg)

1. **计数**：遍历 `s`，每遇字符等于 `letter` 则 $\text{cnt} \mathrel{+}= 1$（C++ 用 `std::count`，Python 用 `str.count`，内建 $O(n)$）；
2. **放大**：$\text{cnt} \times 100$（精确整数乘法，无溢出）；
3. **取整**：$\text{ans} = (\text{cnt} \times 100) \, // \, n$（非负整除 = 向下取整，只此一次）；
4. **返回** `ans`。

无分支、无特判：零命中、单字符、全命中都走同一条路。

### 3.4 示例演算

![示例演算：foobar 得 33，jjjj 得 0，浮点反例差 1](images/wc294_q1_example_walkthrough.svg)

**示例 1** `s = "foobar", letter = 'o'`（$n = 6$）：

| 步骤 | 值 | 说明 |
|------|----|------|
| 计数 $\text{cnt}$ | 2 | 两个 `'o'`（下标 1、2） |
| $\text{cnt} \times 100$ | 200 | 先放大，不取整 |
| $200 \,//\, 6$ | **33** | $200/6 = 33.33\ldots$，整除即向下取整 |

对照写法 B：$2 \,//\, 6 = 0$，$0 \times 100 = 0$——同一条数据，仅次序不同即从 $33$ 变 $0$。

**示例 2** `s = "jjjj", letter = 'k'`（$n = 4$，零命中）：$\text{cnt} = 0 \Rightarrow 0 \times 100 = 0 \Rightarrow 0 \,//\, 4 = \mathbf{0}$。零命中与除零都不出现：$n \ge 1$ 保证除法合法，$0$ 乘任何数仍 $0$，**无需特判**。

**补充反例**（$n = 100$、$\text{cnt} = 29$）：整数路径 $29 \times 100 \,//\, 100 = 29$ 精确；浮点路径 $29 / 100 = 0.28999\ldots$，$\times 100 = 28.999\ldots$，截断得 $28$——真值恰为整数的边界上，浮点近似恰好跌到下一格。

## 4. 算法细节

1. **计数的语言设施**：C++ `count(s.begin(), s.end(), letter)` 与 Python `s.count(letter)` 都是内建 $O(n)$，签到时直接调用，省去手写循环；注意 Python 的 `letter` 是长度 $1$ 的 `str`，`str.count` 统计的是子串出现次数，长度 $1$ 时即字符计数。
2. **顺序铁律**：表达式必须是 `cnt * 100 / n`，乘法在除法**之前**。写成 `cnt / n * 100`（C++ 整型）即头号 WA；写成 `cnt / n * 100`（Python 真除法 + `int`）即浮点隐患版。
3. **除法语义**：C++ `/` 整型向零截断、Python `//` 向下取整，本题操作数全非负故二者相等（引理 3）；若推广到可能为负的场合（如误差、差值），两者才会分歧，本题无此虑。
4. **C++ 无符号混算**：`s.size()` 返回 `size_t`，`cnt * 100 / s.size()` 中 `int` 被提升为无符号——本题值域非负且 $\le 10^4$，结果正确；若介意可写 `cnt * 100 / (int)s.size()`，纯属代码洁癖。
5. **数值边界**：$\text{cnt} \times 100 \le 10^4$，`int` 绰绰有余；$n \ge 1$ 无除零；$\text{cnt} = 0$ 时公式自然给出 $0$。三个边界全部被通用表达式覆盖，**零特判**。

## 5. 正确性证明

**引理 1（先乘后除的真值刻画）**：设 $a \ge 0$、$b \ge 1$、$c \ge 0$ 均为整数，则整数表达式「先精确计算 $a \cdot c$、再整除 $b$」的值等于 $\left\lfloor \dfrac{a}{b} \cdot c \right\rfloor$（其中 $a/b$ 指实数除法）。

**证明**：由带余除法，$a \cdot c = qb + r$，$0 \le r < b$，则 $q = \left\lfloor ac/b \right\rfloor$。作为实数，$\dfrac{a}{b} \cdot c = \dfrac{ac}{b} = q + \dfrac{r}{b} \in [q,\, q+1)$，故 $\left\lfloor \frac{a}{b} \cdot c \right\rfloor = q$。而整数算术先算 $a \cdot c$（两整数之积精确，无溢出前提下无误差），再整除得 $q$，与目标一致。∎

**引理 2（过早取整必然不多算、通常少算）**：$\left\lfloor \dfrac{a}{b} \right\rfloor \cdot c \le \left\lfloor \dfrac{a}{b} \cdot c \right\rfloor$；且当 $a < b$、$b \nmid a$、$c \ge 1$ 时严格小于。特别地，本题取 $a = \text{cnt}$、$b = n$、$c = 100$：当 $\text{cnt} < n$ 且 $n \nmid \text{cnt}$ 时，$\lfloor \text{cnt}/n \rfloor \times 100 = 0 < \left\lfloor \text{cnt}/n \times 100 \right\rfloor$。

**证明**：写 $a = qb + r$，$0 \le r < b$。左边 $= qc$；右边对应的实数 $\dfrac{a}{b} c = qc + \dfrac{rc}{b} \ge qc$，取整后仍 $\ge qc$，得不等式。当 $a < b$：$q = 0$；若再 $b \nmid a$ 则 $r \ge 1$，$\dfrac{rc}{b} > 0$（$c \ge 1$），故右边 $\ge \lfloor qc + \text{正数} \rfloor \ge qc + 1 = 1 > 0$，而左边 $= 0$，严格不等成立。∎

**引理 3（非负操作数上两种除法语义一致）**：C++ 整型除法向零截断，Python `//` 向下取整；当被除数 $\ge 0$、除数 $\ge 1$ 时两者相等，且都等于向下取整。

**证明**：设 $a \ge 0$、$b \ge 1$，$a = qb + r$，$0 \le r < b$，则 $q \ge 0$ 且 $a/b = q + r/b \in [q, q+1)$。向下取整直接得 $q$；向零截断对非负数即截掉小数部分，同样得 $q$。∎

**定理**：算法返回题面所求的 $\left\lfloor \dfrac{\text{cnt}}{n} \times 100 \right\rfloor$。

**证明**：遍历计数后 `cnt` 恰为 `letter` 在 `s` 中的出现次数（逐字符比对，计数正确性显然），$n = \text{len}(s) \ge 1$ 保证除法合法，$\text{cnt} \le n \le 100$ 保证 $\text{cnt} \times 100 \le 10^4$ 精确无溢出。由引理 3，C++ 与 Python 的整除在此均等于向下取整；由引理 1，`cnt * 100 / n` 的值即 $\left\lfloor \text{cnt}/n \times 100 \right\rfloor$，为题面定义的答案。∎

> 💡 引理 2 同时解释了两类 WA 的公共根源：「先除后乘」是主动触发的引理 2 严格情形；「浮点版」则是把本应精确的 $ac/b$ 换成了近似值再截断——都偏离了引理 1 的唯一正确路径。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n = \text{len}(s) \le 100$。一趟遍历计数（内建 `count` 同为线性），乘除各 $O(1)$；对 $n \le 100$ 至多百次比较，签到无任何时限压力。
- **空间复杂度**：$O(1)$。仅 `cnt` 与 `n` 两个变量，不随输入规模增长。

## 7. 参考代码

### C++（主解：`std::count` + 先乘后除）

```cpp
class Solution {
public:
    int percentageLetter(string s, char letter) {
        int cnt = count(s.begin(), s.end(), letter);
        return cnt * 100 / s.size();   // 先乘后除：只在最后取整一次
    }
};
```

### Python（主解：一行即最优）

```python
class Solution:
    def percentageLetter(self, s: str, letter: str) -> int:
        return s.count(letter) * 100 // len(s)
```

### Python（变体：手写循环，与 C++ 主解同构）

```python
class Solution:
    def percentageLetter(self, s: str, letter: str) -> int:
        cnt = 0
        for c in s:
            if c == letter:
                cnt += 1
        return cnt * 100 // len(s)
```

> ⚠️ 三个版本的核心表达式一字不差：`cnt * 100 / n`（Python `//`）。对照错误写法：C++ `cnt / n * 100` 对 `"foobar"` 返回 $0$；`int(cnt / n * 100)` 对 $n = 100$、$\text{cnt} = 29$ 返回 $28$——两类反例均已实测复现。

## 8. 边界情况与易错点

1. **先除后乘（头号 WA）**：`cnt / n * 100`（C++ 整型）或 `cnt // n * 100`（Python）在 $\text{cnt} < n$ 时恒为 $0$——示例 1 的 $33$ 被抹成 $0$。乘法必须在除法之前。
2. **浮点截断少 1**：`int(cnt / n * 100)` 在约束内有四组实锤反例 $(n,\text{cnt}) = (50,29),\ (100,29),\ (100,57),\ (100,58)$，真值恰为整数时浮点近似跌到 $K - \epsilon$、截断后少 $1$。「能用整数就别用浮点」。
3. **不要用 `round` / `ceil`**：题面是**向下取整**；四舍五入到最近百分比是另一个语义（变体公式 $\lfloor (\text{cnt} \times 100 + n/2) / n \rfloor$，见延伸思考）。
4. **零命中无需特判**：$\text{cnt} = 0 \Rightarrow 0 \times 100 // n = 0$（示例 2）；`letter` 是小写字母但**不保证出现在 `s` 中**。
5. **无除零**：$n \ge 1$ 由约束保证；单字符串 $n = 1$ 时答案只能是 $0$ 或 $100$，公式自然覆盖。
6. **溢出无忧（本题）**：$\text{cnt} \times 100 \le 10^4$，`int` 安全；若数据放大（如 $n \le 10^9$ 且另乘大系数），先乘可能溢出，需升 `long long` 或分段（见延伸思考）。
7. **C++ 无符号混算**：`s.size()` 是 `size_t`，`cnt * 100 / s.size()` 里 `int` 被提升为无符号；本题值域非负且极小，无实际风险。
8. **接口差异**：C++ 的 `letter` 是 `char`，Python 的是长度 $1$ 的 `str`——`s.count(letter)` 在 Python 侧合法（子串计数），C++ 侧对应的是 `std::count` 而非某个 `string::count`。
