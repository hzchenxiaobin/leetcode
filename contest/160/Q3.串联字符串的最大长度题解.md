# LeetCode 串联字符串的最大长度 题解

## 1. 题目概述

- **标题 / 题号**：串联字符串的最大长度（#1239，medium）
- **链接**：https://leetcode.cn/problems/maximum-length-of-a-concatenated-string-with-unique-characters/
- **来源**：LeetCode 第 160 场周赛 Q3
- **难度**：中等
- **标签**：位运算，数组，字符串，回溯

**题意**：给定字符串数组 `arr`。从 `arr` 中按原顺序挑出一个**子序列**（允许一个都不挑），把它们首尾相接成字符串 $s$，要求 $s$ 中**每个字母最多出现一次**。返回所有合法 $s$ 中最长的那个的长度（空串长度 0 合法）。

**约束**：

- $1 \le \text{arr.length} \le 16$，即最多只有 $2^{16} = 65536$ 种子序列
- $1 \le \text{arr[i].length} \le 26$
- `arr[i]` 只含小写英文字母
- 字母表只有 26 个字符，因此答案天然满足 $0 \le \text{ans} \le 26$

## 2. 示例

**示例 1**

```text
输入：arr = ["un","iq","ue"]
输出：4
解释：全部合法串联结果是 ""、"un"、"iq"、"ue"、"uniq"("un"+"iq")、"ique"("iq"+"ue")，
      最长长度为 4。注意 "un"+"ue" 不合法，因为字母 u 出现了两次。
```

**示例 2**

```text
输入：arr = ["cha","r","act","ers"]
输出：6
解释：最长解是 "chaers"("cha"+"ers") 与 "acters"("act"+"ers")，长度都是 6；
      "cha" 与 "act" 共享字母 a、c，"r" 与 "ers" 共享字母 r，因此两两组合最多只能拼到 6。
```

**示例 3**

```text
输入：arr = ["abcdefghijklmnopqrstuvwxyz"]
输出：26
解释：唯一的串本身就包含全部 26 个字母且互不重复，直接返回它的长度 26。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举 `arr` 的全部子序列（共 $2^{n}$ 种），把挑出的串连接起来，再用集合检查字符是否重复：

$$O\left(2^{n}\cdot \sum_i \lvert \text{arr}[i]\rvert\right)\;\le\;2^{16}\times 416\approx 2.7\times 10^{7}$$

C++ 里勉强能过，但常数很难看；换到 Python 上「每个叶子重新扫一遍所有字符」就会踩到时间线。更本质的浪费在于**状态重复**：不同子集可能拼出同一个字符集合，例如 `["ab","ba"]`（或任何顺序不同的同字母串）的两种选法都得到 $\{a,b\}$，长度也一样。既然答案只取决于字符集合，这些重复状态完全可以合并——这就是掩码表示与状态去重的动机。

### 3.2 核心观察：字符集就是一个 26 位掩码

![每个字符串压成 26 位掩码，或运算合并、与运算判冲突](images/wc160_q3_string_masks.svg)

三条性质把「拼接字符串」彻底变成了「整数集合运算」：

1. **合法性只看字符集合**：$s$ 中没有重复字母 $\iff$ 所选各串的字符集合**两两不相交**，并且每串自身不含重复字母。
2. **长度只看字符集合**：$s$ 的长度 $=$ 所选各串字符集合并集的大小。至于「子序列」的顺序，只影响拼出来的具体字符串长什么样，**不影响合法性与长度**。
3. **集合运算就是位运算**：让字符 $c$ 对应第 $(c-\text{'a'})$ 位，一个串的字符集就是一个掩码 $m$。于是两串可共存 $\iff m_1 \,\&\, m_2 = 0$；合并两串 $\iff m_1 \mid m_2$。

预处理时把每个串压成掩码，并顺手丢掉**自冲突串**（如 `"aa"`、`"aba"`）：从左往右扫描，一旦发现某一位已经置位，说明该串内部就有重复字母，它永远不可能被选中。

于是原问题变成：

> 从 $n$ 个掩码中挑一组**两两按位与为 0** 的掩码，使它们按位或结果的 popcount 最大。

### 3.3 算法流程 / 状态转移：可达掩码集合的 DP

![可达掩码集合 S 的迭代流程](images/wc160_q3_dp_mask_set.svg)

设 $S$ 为「目前能拼出的全部合法字符集」的掩码集合，从 $S=\{0\}$（一个串都不选）出发，逐个处理有效掩码 $m$：

$$\text{add} = \{\, x \mid m \;:\; x \in S,\; x \,\&\, m = 0 \,\}, \qquad S \leftarrow S \cup \text{add}$$

遍历结束后

$$\text{ans} = \max_{x \in S} \operatorname{popcount}(x)$$

一句话概括：**在旧状态里挑出所有与 $m$ 不冲突的掩码，或上 $m$ 得到新状态，再并回集合**。这本质上是 0/1 背包——每个串「选或不选」，只不过状态换成了掩码；而用**集合**存 $S$ 天然完成了「同一个掩码只保留一份」的去重。

与回溯 `dfs(i, mask)` 相比：回溯会把同一个 mask 在多个分支里反复展开，而集合 DP 里每个掩码只被处理一次。由于 $|S| \le 2^{n}$，总代价是 $O(n \lvert S\rvert)$，最坏 $16 \times 65536$ 次集合操作，非常轻。

### 3.4 示例演算

![arr = ["un","iq","ue"] 的集合扩张过程](images/wc160_q3_walkthrough.svg)

| 步骤 | 处理串 → 掩码 | 新增的可达掩码 | $S$（用字母集合书写） | 最优 |
|------|----------------|----------------|------------------------|------|
| 初始 | — | — | ∅ | 0 |
| ① | `"un"` → {u,n} | un | ∅, un | 2 |
| ② | `"iq"` → {i,q} | iq、uniq | ∅, un, iq, uniq | 4 |
| ③ | `"ue"` → {u,e} | ue、ique | ∅, un, iq, uniq, ue, ique | 4 |

第 ③ 步的两处细节值得注意：

- `"ue"` 与 `"un"` 都含 `u`，掩码按位与不为 0 $\Rightarrow$ `"ue"`+`"un"` 被拒绝，不会进入 $S$；
- `"ue"` 与 `"iq"` 不冲突 $\Rightarrow$ 生成新掩码 `ique`（长度 4），但 $S$ 里 `uniq` 已经达到 4，最优值保持不变。

遍历结束 $\max \operatorname{popcount} = 4$，对应串是 `"uniq"` 或 `"ique"`，与官方输出一致。

## 4. 算法细节

1. **位编号**：`bit = 1 << (c - 'a')`，掩码用 32 位整型足够（$26 < 32$），不要用 `char`/`short` 存。
2. **自冲突串的判定**：扫描时若 `m & bit` 非 0，说明该字母在此串里已出现过，标记后 `break` 并**不要**加入 `masks`；实现上用布尔标记（C++ 的 `ok`）或把 `m` 置 0（Python）当「废串」标记，push 前判 `ok` / `m != 0`。
3. **快照语义（Python）**：`reach |= {x | m for x in reach if not (x & m)}` 是安全的——集合推导式会**先把右值完整算出来**，再执行 `|=`。若改写成 `for x in reach: reach.add(x | m)`，一边遍历一边修改集合会直接抛 `RuntimeError: Set changed size during iteration`，而且逻辑上会让本轮新增的掩码被反复复用。
4. **快照语义（C++）**：`unordered_set` 在遍历过程中插入会触发 rehash、使迭代器失效（UB），必须先把 `add` 收进 `vector`，出了循环再统一下标插入。
5. **popcount 的取法**：C++ 用 `__builtin_popcount((unsigned)x)`，Python 用 `bin(x).count("1")`（Python 3.8+ 也可 `x.bit_count()`）。
6. **同掩码去重**：若两个串掩码相同，它们互为字母重排、长度必然相同，去重后不影响答案；用 `sort + unique` 或 `set` 收一遍即可（本题 $n \le 16$，属于可选优化）。
7. **提前退出**：答案上界是 26，若某个时刻已经取到 26 可直接返回；也可以先把掩码按 popcount 降序处理，让最优值尽早变大（只影响剪枝效果，不影响正确性）。
8. **不拼接字符串**：本题只需要长度，全程用掩码，既避免 $O(\sum|arr[i]|)$ 的字符串构造，也让「是否重复」的判断变成 $O(1)$ 的按位与。

## 5. 正确性证明

**引理 1（掩码刻画合法性）**：对 `arr` 的任一子序列 $T$，其拼接串 $s$ 的字母两两不同 $\iff$（a）$T$ 中每个串自身字母不重复；（b）对 $T$ 中任意两个不同的串 $u, v$，其掩码满足 $m_u \,\&\, m_v = 0$。

**证明**：

- （$\Leftarrow$）由（a）每个串内部无重复字母；由（b）任意两串字符集不相交，故跨串也不可能出现同一字母。于是 $s$ 中每个字母至多出现一次。
- （$\Rightarrow$）若某串自身含重复字母，则 $s$ 中该字母至少出现两次，矛盾；若两串共享字母 $c$，则 $c$ 在 $s$ 中至少出现两次，也矛盾。

∎

**引理 2（长度公式）**：若 $T$ 合法，则 $\lvert s\rvert = \operatorname{popcount}\left(\bigvee_{v \in T} m_v\right)$。

**证明**：由引理 1，$T$ 中各串的字符集两两不交，并集大小等于各自大小之和；而一个串的字符数恰好等于其掩码的置位数，故 $\lvert s\rvert = \sum_v \operatorname{popcount}(m_v) = \operatorname{popcount}\left(\bigvee_{v\in T} m_v\right)$（不交集合的置位数可直接相加，或运算不丢失任何位）。∎

**引理 3（DP 不变量）**：处理完前 $k$ 个有效掩码后，$S$ 恰好等于「用前 $k$ 个串的某个子集拼出的全部合法字符集」所对应的掩码集合。

**证明**：对 $k$ 归纳。$k = 0$ 时 $S = \{0\}$，对应空子集，成立。设处理完前 $k-1$ 个后不变量成立，现在加入第 $k$ 个掩码 $m$。任取一个用前 $k$ 个串的合法选择：若它不含第 $k$ 个串，其掩码已在旧 $S$ 中，并集后仍在；若它含第 $k$ 个串，则去掉第 $k$ 个串后剩下的选择 $x$ 合法（合法性的子集仍合法），且由引理 1 有 $x \,\&\, m = 0$，其掩码为 $x \mid m$，正是 `add` 的元素。反向，`add` 中每个 $x \mid m$ 都由一个合法选择拼出（$x$ 合法且与 $m$ 不冲突，加入第 $k$ 个串后仍合法）。故 $S \cup \text{add}$ 恰好覆盖了用前 $k$ 个串的全部合法选择，不变量保持。∎

**定理**：算法返回值等于所有合法拼接串长度的最大值。

**证明**：由引理 3，遍历结束后 $S$ 等于全部合法选择的字符集掩码集合；由引理 2，掩码 $x$ 的 $\operatorname{popcount}$ 恰为对应拼接串的长度。因此 $\max_{x\in S}\operatorname{popcount}(x)$ 就是最优长度。又因空子集始终贡献掩码 $0$（长度 0），$S$ 非空、最大值至少为 0，与「允许空串」的题意一致。∎

## 6. 复杂度分析

- **时间**：预处理 $O\left(\sum_i \lvert \text{arr}[i]\rvert\right) \le O(26n)$；DP 对每个有效掩码线性扫描一遍 $S$，共 $O(n\lvert S\rvert)$，其中 $\lvert S\rvert \le \min(2^{n}, 2^{26})$，故最坏 $O(n \cdot 2^{n}) \le 16 \times 65536 \approx 10^{6}$ 次集合操作；最后一次求最大值 $O(\lvert S\rvert)$。整体可视为 $O(n\cdot 2^{n})$。
- **空间**：$O(\lvert S\rvert)$ 个整数存可达掩码（最多 65536 个 `int`，约 256 KB），外加 $O(n)$ 的掩码数组；不随字符串内容增长。

实测：16 个串、可达掩码接近 $2^{16}$ 的最坏数据，纯 Python 大约 6 ms。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_set>
#include <algorithm>

using namespace std;

class Solution {
public:
    int maxLength(vector<string>& arr) {
        // 1) 每个串压成 26 位掩码；自冲突串直接丢弃
        vector<int> masks;
        for (const string& s : arr) {
            int m = 0;
            bool ok = true;
            for (char c : s) {
                int bit = 1 << (c - 'a');
                if (m & bit) { ok = false; break; }   // 串内字符重复，永远不能选
                m |= bit;
            }
            if (ok) masks.push_back(m);
        }

        // 2) 可达掩码集合 S，初始只有空串对应的 0
        unordered_set<int> reach;
        reach.insert(0);
        for (int m : masks) {
            vector<int> add;
            add.reserve(reach.size());
            for (int x : reach)                       // 只在旧快照上扫描
                if ((x & m) == 0) add.push_back(x | m);
            reach.insert(add.begin(), add.end());     // 出循环后再统一插入
        }

        // 3) 取置位数最大的掩码，就是最长长度
        int ans = 0;
        for (int x : reach) ans = max(ans, __builtin_popcount((unsigned)x));
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxLength(self, arr: List[str]) -> int:
        # 1) 每个串压成 26 位掩码；自冲突串直接丢弃（m 置 0）
        masks = []
        for s in arr:
            m = 0
            for ch in s:
                bit = 1 << (ord(ch) - 97)
                if m & bit:
                    m = 0
                    break
                m |= bit
            if m:
                masks.append(m)

        # 2) 可达掩码集合：集合推导式先算完右值，再并回 reach，天然快照
        reach = {0}
        for m in masks:
            reach |= {x | m for x in reach if not (x & m)}

        # 3) 置位数最大即最长长度
        return max(bin(x).count("1") for x in reach)
```

## 8. 边界情况与易错点

1. **全部串都自冲突**：如 `["aa","bb"]`，唯一合法选择是空子集，必须返回 `0`，而不是认为「至少要选一个串」返回 `-1` 或报错。
2. **遍历时修改集合**：Python 里 `for x in reach: reach.add(...)` 会抛 `RuntimeError`；用集合推导式或先收集 `add` 再合并。
3. **C++ 迭代器失效**：`unordered_set` 在遍历中插入可能 rehash，属于未定义行为；必须先攒到 `vector` 里。
4. **答案上界与掩码位宽**：答案不超过 26，掩码必须用 32 位整型（`char`/`short` 会溢出）；用 `1 << (c - 'a')` 时 `c - 'a'` 最大 25，不能写反成 `1 << c`。
5. **漏判串内重复**：`"aab"` 这类串必须在预处理阶段就 break 掉；若只检查「两串之间」的关系而忽略串内重复，会得到偏大的答案。
6. **子序列 ≠ 子集，但不影响本题**：题目限定按下标顺序挑选，但由于只统计字符集合与长度，按子集处理不会漏解；反之，若题目要求输出具体字符串，就必须额外记录选择顺序。
7. **不要真的拼接字符串**：每次 `+` 都是 $O(\lvert s\rvert)$ 拷贝，$2^{16}$ 个叶子会把常数放大到不可接受；掩码方案全程无字符串拷贝。
8. **同一掩码多条串**：`["ab","ba"]` 掩码相同、长度相同，重复入 `reach` 只是多算一次，结果不变；若追求常数可先对 `masks` 去重。

**延伸思考**：

1. 若把限制从「每个字母最多一次」放宽为「每个字母最多 $k$ 次」，掩码不再够用，状态要变成 26 维计数向量，只能用回溯 + 剪枝（或按剩余容量做可行性剪枝），复杂度重新变成指数级。
2. 若 `arr` 的长度上限放大到 30（子集数 $>10^{9}$），集合 DP 会爆；此时可以先按掩码去重，再做 **meet-in-the-middle**：拆成两半各枚举 $2^{15}$ 个掩码，用「互补掩码」查询另一半，复杂度降到 $O(2^{n/2})$ 量级。
3. 若要求输出具体的拼接串而非长度，只需在 $S$ 里为每个掩码额外记录「由哪个前驱掩码 + 哪个串得到」，最后沿前驱链回溯即可，时间复杂度不变。
