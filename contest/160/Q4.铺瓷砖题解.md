# LeetCode 铺瓷砖 题解

## 1. 题目概述

- **标题 / 题号**：铺瓷砖（#1240，hard）
- **链接**：https://leetcode.cn/problems/tiling-a-rectangle-with-the-fewest-squares/
- **来源**：LeetCode 第 160 场周赛 Q4
- **难度**：困难
- **标签**：回溯、剪枝、状态压缩

**题意**：给定一个 $n \times m$ 的矩形，用若干个**边长为整数**的正方形把它**无重叠、无缝隙**地完全铺满，返回所需正方形数量的**最小值**。

两个容易读歪的点：

- 「整数边长」约束的是每一块正方形的尺寸（不允许 $2.5 \times 2.5$），不是对块数的限制；
- 求的是**最少块数**，不要求输出方案，因此不存在多解判定问题。

**约束**：

- $1 \le n, m \le 13$
- 规模极小，但本题本质是**指数级搜索**：必须靠状态压缩 + 剪枝通过，没有已知的多项式算法

## 2. 示例

**示例 1**

```text
输入：n = 2, m = 3
输出：3
解释：2×2 + 两块 1×1 恰好铺满 2×3。2 块不可能：盖住左下角的方块只能取 2×2 或 1×1，
      前者剩下 2×1 细条、后者剩下 5 格，都无法用一块正方形补齐。
```

**示例 2**

```text
输入：n = 5, m = 8
输出：5
解释：5×5 + 3×3 + 2×2 + 1×1 + 1×1，面积 25 + 9 + 4 + 1 + 1 = 40 = 5 × 8。
      注意这个方案不是「一刀切到底」的直线切割形状，T 形接缝才是常态。
```

**示例 3**

```text
输入：n = 11, m = 13
输出：6
解释：最优解需要 6 块，但离面积下界 ⌈143 / 121⌉ = 2 非常远——
      面积估计对本题几乎没有约束力，只能老老实实搜索。
      贪心（每步放最大的）在这里给出 8 块，比最优多 2 块。
```

## 3. 解题思路

### 3.1 暴力思路

三条路都不通：

1. **枚举切分（guillotine）**：每次沿一条直线把矩形切成两半再递归。它只能生成「一刀到底」的方案，而本题最优解常含 T 形接缝（11×13 正是如此），会系统性算出偏大的答案。
2. **贪心**：每步放能放下的最大正方形。5×8 上它恰好给出 5，但 11×13 上给出 8，最优是 6——**贪心是错的**，且没有简单的修补办法。
3. **朴素搜索**：矩形里每个格子「铺没铺」有 $2^{169}$ 种状态；更糟的是同一种铺法会被「先放左下角」「先放右上角」等多种放置顺序重复枚举，状态数与时序冗余同时爆炸。

要做成可搜索的问题，需要两件事：**状态压缩**（用 $O(m)$ 的高度数组代替 $n \times m$ 的布尔矩阵）与**去序**（让每种铺法只有唯一一条枚举路径）。

### 3.2 核心观察：锚点定死落点（DFS + 回溯 + 剪枝）

![锚点：最矮最左的空格](images/wc160_q4_anchor_skyline.svg)

**状态压缩**：如果所有方块都从「当前地面」往上长，那么已铺区域在**每一列**都恰好是底部的一段前缀。于是整张图只需一个长度为 $m$ 的**高度数组** $h$：第 $j$ 列已铺 $0,1,\dots,h[j]-1$ 行（从下往上数），其上方全空。状态由 $h$ 唯一确定，理论上至多 $(n+1)^m$ 种阶梯形——真正把搜索压小的是后面的锚点论证与剪枝。

**锚点**：设 $\text{minh} = \min_j h[j]$，$c$ 是**最左**的满足 $h[c] = \text{minh}$ 的列，则格子 $(\text{minh}, c)$ 就是「最靠下、再靠左」的空格。任何补全方案中覆盖它的正方形，其**左下角一定是** $(\text{minh}, c)$：

- 它不能往左挪：$c$ 左侧的列高度都 $> \text{minh}$，那一格早已被铺；
- 它不能往下挪：第 $c$ 列高度恰为 $\text{minh}$，它下方全是已铺格。

边长同样被卡死。设 $w$ 是从 $c$ 起**向右连续**高度为 $\text{minh}$ 的列数，则

$$1 \le s \le \text{maxs} = \min\bigl(w,\; n - \text{minh}\bigr)$$

$s \le w$ 保证方块下面整段地面等高（否则方块会悬空、压到已铺格），$s \le n - \text{minh}$ 保证不越出矩形的上边界。

**去序**：由于下一步的落点被唯一确定，同一种铺法不会被不同顺序重复枚举——搜索树里每种铺法恰好对应一条从根到叶的路径。这两点合起来，就把一个几何覆盖问题变成了「一维高度数组上的整型递归」。

### 3.3 算法流程 / 状态转移

![DFS + 回溯 + 全局最优剪枝](images/wc160_q4_dfs_flow.svg)

状态就是高度数组 $h$ 与已用块数 $cnt$，转移是「在锚点上放一个 $s \times s$ 的方块」，即把 $h[c..c+s-1]$ 从 $\text{minh}$ 抬到 $\text{minh}+s$。用 DFS 枚举，并用全局最优值 $\text{best}$ 剪枝：

1. 求 $\text{minh}$ 与最左列 $c$、以及连续同高列数 $w$；
2. 若 $\text{minh} = n$，所有列都铺满，用 $cnt$ 更新 $\text{best}$ 并返回；
3. 剪枝：若 $cnt + 1 \ge \text{best}$，说明即使只再放一块也不会更优（或只能打平），直接返回；
4. 令 $\text{maxs} = \min(w,\, n - \text{minh})$；
5. 从 $s = \text{maxs}$ **递减**到 1：把 $h[c..c+s-1]$ 置为 $\text{minh}+s$，递归 $cnt+1$，再把这一段恢复成 $\text{minh}$；
6. 回溯结束后返回，$\text{best}$ 即答案。

枚举 $s$ 时**从大到小**是刻意的：先放大的方块能更快碰到接近最优的完整方案，让 $\text{best}$ 迅速变小，剪枝立刻变强。顺序本身不影响正确性。

### 3.4 示例演算

![5×8 的铺设与高度数组演化](images/wc160_q4_walkthrough.svg)

以 $n = 5, m = 8$ 为例，取 $h$ 为长度 8 的数组，$\text{best}$ 初值 $5 \times 8 = 40$：

| 步 | minh | c | w | maxs | 动作 | 动作后的 $h$ | cnt |
|----|------|---|---|------|------|--------------|-----|
| 0 | 0 | 0 | 8 | 5 | 放 5×5 | 5 5 5 5 5 0 0 0 | 1 |
| 1 | 0 | 5 | 3 | 3 | 放 3×3 | 5 5 5 5 5 3 3 3 | 2 |
| 2 | 3 | 5 | 3 | 2 | 放 2×2 | 5 5 5 5 5 5 5 3 | 3 |
| 3 | 3 | 7 | 1 | 1 | 放 1×1 | 5 5 5 5 5 5 5 4 | 4 |
| 4 | 4 | 7 | 1 | 1 | 放 1×1 | 5 5 5 5 5 5 5 5 | 5 |

最后一行（步 4）执行后 $\text{minh} = 5 = n$，全满，$\text{best}$ 被更新成 5。随后回溯：在较早的节点改放更小的方块（例如根节点改放 4×4 或 3×3、第二块改放更小的方块），这些分支要么铺不满、要么在 $cnt+1 \ge 5$ 处被剪掉，都不会再改进 $\text{best}$，最终返回 5。

顺带把贪心的失败点说透：11×13 上「每步放最大的」先切 11×11，剩下的 2×11 只能拆成 2×2 五块 + 1×1 两块，共 8 块；而最优的 6 块是 **7×7 + 6×6 + 5×5 + 4×4 + 4×4 + 1×1**（面积 $49+36+25+16+16+1 = 143$），摆放位置左上 7×7、右上 6×6、其下 1×1 与 5×5、左下并排两块 4×4。这个方案里全是 T 形接缝，正是「枚举直线切割」失效的原因。

## 4. 算法细节

1. **转置对称**：先 `if (n > m) swap(n, m)` 固定行数 $n \le m$（转置不改变答案），这样高度数组长度恒为 $m$，代码里哪一维是「行」、哪一维是「列」不会随输入翻转。
2. **单次扫描找锚点**：一遍循环同时得到 $\text{minh}$ 和它的最小下标 $c$（最左），$O(m)$。不要用排序或 `set`——它们会丢掉「最左」这一关键信息。
3. **$w$ 必须连续**：从 $c$ 向右扫，遇到第一个 $h[\cdot] \ne \text{minh}$ 立刻停；把「整张图里高度等于 minh 的列数」当成 $w$ 是常见错误。
4. **边长上限是双约束**：$s \le \min(w, n-\text{minh})$。只写 $s \le w$ 时，$n < m$ 且地面全平的情形会选出 $s > n$，方块越出矩形上边界。
5. **枚举顺序**：从 $\text{maxs}$ 递减。它让 $\text{best}$ 尽早收敛，是本题在 13×11 上跑到毫秒级的关键；如果从小到大枚举，正确性不变但明显变慢。
6. **剪枝放在铺满判断之后**：先判 $\text{minh} = n$ 再判 $cnt+1 \ge \text{best}$。顺序反了会把 $cnt$ 已经等于答案的完成态误剪，只能靠 $\text{best}$ 的初值兜底。
7. **回溯用 minh 而不是 0**：本层被抬高的列原来都等于 $\text{minh}$，恢复成 0 会把阶梯地面抹平，产生非法状态。
8. **特判**：$n = m$ 直接返回 1；$n = 1$ 直接返回 $m$（只能全用 1×1）。二者都能省掉无意义的深递归。

## 5. 正确性证明

**引理 1（前缀不变量）**：搜索过程中任意时刻，第 $j$ 列被占据的格子恰好是从底部起的 $0,1,\dots,h[j]-1$ 行。

**证明**：初始 $h \equiv 0$，结论成立。归纳一步：新方块覆盖列 $c..c+s-1$、行 $\text{minh}..\text{minh}+s-1$，由 $s \le w$ 知这些列的当前高度都等于 $\text{minh}$，故被覆盖的格子此前全空；放好后这些列高度变为 $\text{minh}+s$，下方仍是原来的前缀，仍满足结论。∎

**引理 2（锚点唯一）**：设当前 $h \ne n$，$\text{minh} = \min_j h[j]$，$c$ 为最左达到 $\text{minh}$ 的列，$w$ 为 $c$ 起连续同高列数。若该状态可补全为完整铺法，则任何补全方案中覆盖格子 $(\text{minh}, c)$ 的正方形左下角必为 $(\text{minh}, c)$，且边长 $s \le \min(w, n-\text{minh})$。

**证明**：设该正方形占列 $c'..c'+s-1$、行 $r..r+s-1$，且包含 $(\text{minh}, c)$。
若 $c' < c$，则它包含 $(\text{minh}, c')$，但 $c'$ 列高度 $> \text{minh}$，该格已铺，与不重叠矛盾；若 $c' > c$ 则不包含 $(\text{minh}, c)$。故 $c' = c$。
若 $r < \text{minh}$，则它包含 $(r, c)$，而 $c$ 列高度为 $\text{minh}$，该格已铺，同样矛盾；$r > \text{minh}$ 则不包含 $(\text{minh}, c)$。故 $r = \text{minh}$。
再看边长：方块在行 $\text{minh}$ 上覆盖列 $c..c+s-1$，这些格必须为空，由引理 1 得 $h[j] \le \text{minh}$，而 $\text{minh}$ 是最小值，故 $h[j] = \text{minh}$，即这 $s$ 列必须都落在 $c$ 起的连续同高段内，$s \le w$；同时 $s \le n - \text{minh}$ 才能不越过上边界。∎

**引理 3（枚举合法且完备）**：DFS 的每个分支产生的状态都对应一个合法的部分铺法；且对任意完整铺法，DFS 都存在一条路径按锚点顺序逐块重现它。

**证明**：合法性由引理 1 的归纳证明给出（新方块落点全空、不越界，且块数正确累加）。完备性：设完整铺法 $T$，由引理 2 它的第一块必以锚点为左下角、边长 $1 \le s_1 \le \text{maxs}$，正在枚举范围内；除去这一块后，$T$ 的剩余部分仍是该新状态的合法补全，于是可以归纳地逐块重放。∎

**定理（最优性）**：搜索结束时 $\text{best}$ 等于最少正方形数 $\text{OPT}$。

**证明**：

- $\text{best}$ 不会被低估：每次更新都发生在 $\text{minh} = n$ 的节点，此时所有列高度为 $n$，即全部格子被 $cnt$ 个互不重叠的整数边正方形覆盖，是一个合法铺法，故 $\text{best} \ge \text{OPT}$。
- $\text{best}$ 不会高于 $\text{OPT}$：若过程中 $\text{best}$ 曾取到 $\text{OPT}$，结论已经成立。否则 $\text{best} > \text{OPT}$ 始终成立，由引理 3 存在一条重现最优铺法的路径；该路径上非终点节点满足 $cnt + 1 \le \text{OPT} < \text{best}$，剪枝条件不成立，路径不会被切断，于是必然抵达 $\text{minh} = n$ 且 $cnt = \text{OPT}$ 的终点，并在「先判铺满」的次序下把 $\text{best}$ 更新为 $\text{OPT}$，与 $\text{best} > \text{OPT}$ 矛盾。
- 两者合并得 $\text{best} = \text{OPT}$。∎

## 6. 复杂度分析

- **时间**：最坏是指数级。每层分支数 $\le \text{maxs} \le 13$，深度 $\le \text{OPT} \le 13$（$1 \times m$ 的答案 13 已被特判，$n, m \ge 2$ 时答案不超过 8），理论上界 $13^{13}$；但「锚点唯一」把每种铺法压成一条路径，加上 $cnt+1 \ge \text{best}$ 剪枝与从大到小的枚举，实际搜索树极小——实测（Python 实现）$1 \le n, m \le 13$ 的全部 169 组输入合计约 0.12 s，单组最慢约 8 ms（$12 \times 13$）。
- **空间**：高度数组 $O(m)$；递归深度 $O(\text{OPT}) \le 13$。合计 $O(\max(n, m))$，与 $n \cdot m$ 的网格存储相比几乎不占空间。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>
using namespace std;

class Solution {
public:
    int tilingRectangle(int n, int m) {
        if (n > m) swap(n, m);           // 转置对称：固定 n <= m
        if (n == m) return 1;
        if (n == 1) return m;
        vector<int> h(m, 0);             // h[j] = 第 j 列已铺的行数（底部前缀）
        int best = n * m;                // 用 n*m 个 1x1 一定可行
        dfs(0, n, m, h, best);
        return best;
    }

private:
    void dfs(int cnt, int n, int m, vector<int>& h, int& best) {
        int minh = INT_MAX;
        for (int v : h) minh = min(minh, v);
        if (minh == n) {                 // 所有列都铺满 → 得到一个完整方案
            best = min(best, cnt);
            return;
        }
        if (cnt + 1 >= best) return;     // 至少还要再放一块，不可能严格更优

        int c = 0;
        while (h[c] != minh) c++;        // 最左的最矮列（锚点所在列）
        int w = 1;
        while (c + w < m && h[c + w] == minh) w++;
        for (int s = min(w, n - minh); s >= 1; s--) {
            for (int j = c; j < c + s; j++) h[j] = minh + s;
            dfs(cnt + 1, n, m, h, best);
            for (int j = c; j < c + s; j++) h[j] = minh;   // 回溯恢复
        }
    }
};
```

### Python

```python
class Solution:
    def tilingRectangle(self, n: int, m: int) -> int:
        if n > m:
            n, m = m, n                  # 转置对称：固定 n <= m
        if n == m:
            return 1
        if n == 1:
            return m

        h = [0] * m                      # h[j] = 第 j 列已铺的行数（底部前缀）
        best = [n * m]                   # 用 n*m 个 1x1 一定可行

        def dfs(cnt: int) -> None:
            minh = min(h)
            if minh == n:                # 所有列都铺满 → 得到一个完整方案
                if cnt < best[0]:
                    best[0] = cnt
                return
            if cnt + 1 >= best[0]:       # 至少还要再放一块，不可能严格更优
                return

            c = h.index(minh)            # 最左的最矮列（锚点所在列）
            w = 1
            while c + w < m and h[c + w] == minh:
                w += 1                   # c 起向右连续同高的列数
            for s in range(min(w, n - minh), 0, -1):
                for j in range(c, c + s):
                    h[j] = minh + s
                dfs(cnt + 1)
                for j in range(c, c + s):
                    h[j] = minh          # 回溯恢复

        dfs(0)
        return best[0]
```

## 8. 边界情况与易错点

1. **$n = m$**：必须返回 1。交给搜索也能算对，但会先枚举一堆无用分支，浪费时间。
2. **$n = 1$ 或 $m = 1$**：答案就是较长边（只能全用 1×1）。不特判时搜索仍正确，但要白跑 $m$ 层递归。
3. **剪枝与铺满判断的顺序**：先判 $\text{minh} = n$，再判 $cnt + 1 \ge \text{best}$。若反过来写在前面，$cnt$ 恰好等于答案的完成态会被提前砍掉，只能靠 $\text{best}$ 初值巧合兜住，换成 `INT_MAX` 初值就错。
4. **回溯恢复写法**：必须把 $h[c..c+s-1]$ 写回 $\text{minh}$。写回 0 会抹平阶梯地面，让后续分支在非法状态上搜索，答案偏小。
5. **$w$ 的连续性**：向右扫到第一个不同的高度立即停。把「全图中高度为 minh 的列数」当 $w$，会让方块盖在更矮的列上（悬空）或跨过更矮列。
6. **$s$ 的上界漏掉 $n - \text{minh}$**：$n < m$ 且地面全平时 $w$ 可能等于 $m$，只写 $s \le w$ 会选出 $s > n$，直接越出矩形上边界；$n = m$ 时因为 $w \le m = n$ 才侥幸没事。
7. **枚举顺序**：从大到小只影响效率。若不小心写成从小到大，答案仍对，但 $13 \times 11$ 这类输入会慢一个量级。
8. **不要对 $h$ 排序或去重**：状态是「有列序」的向量，排序会破坏「最左」语义，得到错误答案。

**延伸思考**：把 $n, m$ 放大到 20 以上时本题是 NP-hard（最小平方剖分没有已知多项式算法），此时只能靠更强的下界（整数规划、已知小规模答案表）或双向搜索。一个自然的变体是「只允许边长在集合 $S$ 中的正方形」——它同样是 NP-hard，但剪枝要改成「枚举 $S$ 中不超过 maxs 的元素」，`cnt + 1 >= best` 这一层仍可直接复用。另一个变体是「用最少正方形覆盖一个 0/1 矩阵」（允许留空），锚点论证依然成立，只是铺满判断换成「所有 1 都被覆盖」，说明这套「锚点 + 高度数组」的建模比具体题目更通用。
