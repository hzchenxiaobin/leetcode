# LeetCode 玩筹码 题解

## 1. 题目概述

- **标题 / 题号**：玩筹码（#1217，easy）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-move-chips-to-the-same-position/
- **来源**：LeetCode 第 157 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、数学

**题意**：有 $n$ 个筹码，第 $i$ 个筹码位于 `position[i]`。一次操作可以把某个筹码的位置从 $p$ 改成：

- $p + 2$ 或 $p - 2$，**代价 0**；
- $p + 1$ 或 $p - 1$，**代价 1**。

要求把所有筹码挪到**同一个位置**，返回最小总代价。注意目标位置没有任何额外限制：它不必是输入中出现过的坐标，只要取一个「奇偶性合适」的整数即可。

**约束**：

- $1 \le n \le 100$
- $1 \le \text{position}[i] \le 10^9$

> 💡 Q1 的定位是签到题：它看起来像「选址 + 距离」问题，实际上**坐标的数值大小完全不参与计算**。真正的题眼只有一句话——**移动偶数距离免费，所以只有奇偶性重要**。把这句话说清楚，代码就是三行。

## 2. 示例

**示例 1**

```text
输入：position = [1,2,3]
输出：1
解释：位置 3 的筹码移到位置 1，差 2，代价 0；
      位置 2 的筹码移到位置 1，差 1，代价 1。
      总代价 1。
```

**示例 2**

```text
输入：position = [2,2,2,3,3]
输出：2
解释：位置 2 上有 3 个筹码（偶数位），位置 3 上有 2 个（奇数位）。
      把两个位置 3 的筹码各花 1 元搬到位置 2，总代价 2；
      若反过来以位置 3 为目标，则 3 个偶数位筹码各花 1 元，代价 3。
```

**示例 3**

```text
输入：position = [1,1000000000]
输出：1
解释：两个筹码奇偶性不同（1 是奇数，1000000000 是偶数），
      距离 999999999 是奇数，但只需最后一步花 1 元：
      999999998 的距离用 ±2 免费走完。
```

三个示例共同说明：答案与筹码的**距离远近无关**。示例 3 中两枚筹码相距近 $10^9$，答案依然是 1；决定答案的只有「两种奇偶性各有多少枚」。

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是枚举目标位置 $T$，对每个筹码算「从 $p$ 到 $T$ 的最小代价」，再求和取最小。

- 值域是 $[1, 10^9]$，枚举 $T$ 不可行。
- 若只在输入的 $n$ 个坐标里枚举 $T$，复杂度 $O(n^2)$。本题 $n \le 100$，$10^4$ 次运算其实**也能通过**，但它完全没用到题目的结构，换到 $n = 10^5$ 就立刻失效。

更糟的是，这种写法需要每个筹码、每个目标都重新算一遍「怎么挪最便宜」，而「怎么挪最便宜」本身又有 $O(1)$ 与 $O(n)$ 的分歧——周赛现场没有理由承担这种复杂度风险。本题存在 $O(n)$ 的**计数级**做法。

### 3.2 核心观察：±2 免费 → 只剩奇偶性

![两条互不相通的奇偶轨道](images/wc157_q1_parity_tracks.svg)

把数轴按奇偶性切成两条「轨道」：$1, 3, 5, 7, \dots$ 与 $2, 4, 6, 8, \dots$。

1. **同一条轨道内自由滑动**：同一轨道上两点之差必为偶数，即 $|p - q| = 2k$。连续做 $k$ 次 $\pm 2$（每次代价 0）就能从 $p$ 走到 $q$，**代价为 0**。所以一条轨道就是一个免费的连通块。
2. **换轨道必须花钱，且只花 1 元**：$\pm 2$ 不改变奇偶性，只有 $\pm 1$ 才改变。任何一个「换轨道」的方案里 $\pm 1$ 至少出现 1 次，故代价 $\ge 1$；而先做一次 $\pm 1$、剩下的偶数距离全部用 $\pm 2$ 走完，代价恰好 1。

两条结论合起来：

$$\text{cost}(p \to T) = \begin{cases} 0, & p \equiv T \pmod 2 \\ 1, & p \not\equiv T \pmod 2 \end{cases}$$

于是**总代价只由目标位置的奇偶性决定**：

$$C(T) = \#\{i : \text{position}[i] \not\equiv T \pmod 2\}$$

- 目标取**奇数位**：所有偶数位筹码各付 1 元，$C = \text{even}$；
- 目标取**偶数位**：所有奇数位筹码各付 1 元，$C = \text{odd}$。

只有两种选择，取较小者即可：答案 $= \min(\text{even},\ \text{odd})$。**挑选目标位置这件事被压缩成了一个二选一。**

### 3.3 算法流程

![一次遍历统计再取较小一侧](images/wc157_q1_algorithm_flow.svg)

1. **一次遍历**：统计 `position[i] % 2 == 0` 的筹码数 `even`。
2. **一次减法**：`odd = n - even`，不需要第二遍循环。
3. **返回**：`min(even, odd)`。

整个过程没有排序、没有哈希、没有距离计算，甚至连目标位置都不需要真的选出来——我们只需要知道它取哪一种奇偶性更划算。

### 3.4 示例演算

![三个官方示例的分组与比较](images/wc157_q1_walkthrough.svg)

**示例 1**：`position = [1,2,3]`，奇数位筹码 $\{1, 3\}$ 共 2 枚，偶数位筹码 $\{2\}$ 共 1 枚。

| 目标奇偶性 | 具体目标可取 | 需要花钱的筹码 | 代价 |
|------------|--------------|----------------|------|
| 奇数位 | 1 或 3 | $\{2\}$ | 1 |
| 偶数位 | 2 或 4 | $\{1, 3\}$ | 2 |

取较小值 1。实际路径：$3 \to 1$（差 2，免费），$2 \to 1$（差 1，1 元）。与官方解释一致。

**示例 2**：`position = [2,2,2,3,3]`，偶数位 3 枚、奇数位 2 枚，故 $\min(3,2) = 2$：以位置 2 为目标，两个位置 3 的筹码各花 1 元。

**示例 3**：`position = [1, 1000000000]`，奇数位 1 枚、偶数位 1 枚，$\min(1,1) = 1$。虽然两者相距 $999999999$（奇数），但只把最后一步的「奇偶性差异」计入代价：$999999998$ 的距离全部免费走完。

## 4. 算法细节

1. **只统计余数，不统计坐标**：`even` 由 `p % 2 == 0` 判定，`odd` 由总和减出；不需要记录任何位置，也不需要排序——排序对本题毫无帮助。
2. **`odd = n - even` 优于两次计数**：一次遍历、一个计数器，天然不会漏项；同时避免「两个计数器都忘记初始化」这类低级错误。
3. **取模的符号问题**：本题 $p \ge 1$，`p % 2` 在 C++ 中非负，安全；但若把函数改造成接受负数（或 $0$ 的变体），C++ 的 `-3 % 2 == -1`，必须写成 `(p % 2 + 2) % 2` 或直接用位运算 `p & 1`（补码下对负数同样给出正确的奇偶性）。
4. **答案上界极小**：答案不超过 $\lfloor n/2 \rfloor \le 50$，`int` 绰绰有余；即使坐标是 $10^9$，代码里也不出现任何「距离」变量，不存在溢出风险。
5. **目标位置是自由的**：不要误以为目标必须是输入中出现过的坐标。选一个「奇偶性正确的虚拟点」（如 $T = 1$ 或 $T = 2$）即可；这也解释了为什么 `even == 0` 或 `odd == 0` 时答案是 0——所有筹码本来就在同一条轨道上。
6. **代价可以逐个筹码独立相加**：筹码之间互不阻挡、不占位，允许多个筹码落在同一位置，所以「每枚筹码各自付各自的钱」是合法且最优的，直接求和不会重复或冲突。
7. **不要试图构造具体移动序列**：本题只问最小代价，不要求输出方案；一旦开始模拟移动，「越界」「绕路」等细节会凭空多出一堆讨论，而答案其实与这些细节无关。

## 5. 正确性证明

**引理 1（同奇偶两点零代价可达）**：若 $p \equiv q \pmod 2$，则从 $p$ 到 $q$ 存在代价为 0 的移动序列。

**证明**：$|p - q|$ 为偶数，设 $|p - q| = 2k$，$k \ge 0$。若 $q > p$，连续执行 $k$ 次 $p \to p + 2$；若 $q < p$，连续执行 $k$ 次 $p \to p - 2$。第 $j$ 次后位置为 $p \pm 2j$，$j = k$ 时恰为 $q$。每次代价 0，总代价 0。∎

**引理 2（异奇偶两点最小代价为 1）**：若 $p \not\equiv q \pmod 2$，则从 $p$ 到 $q$ 的任意移动序列代价 $\ge 1$，且存在代价恰为 1 的序列。

**证明**：

- **下界**：设序列中 $\pm 2$ 操作共 $a$ 次、$\pm 1$ 操作共 $b$ 次。$\pm 2$ 保持奇偶性，$\pm 1$ 翻转奇偶性，而起点与终点奇偶性不同，故 $b$ 必须为**奇数**，特别地 $b \ge 1$。总代价为 $0 \cdot a + 1 \cdot b = b \ge 1$。
- **上界**：先做一次 $\pm 1$ 使位置变为 $p'$，此时 $p' \equiv q \pmod 2$，由引理 1 再用 0 代价走到 $q$，总代价 1。

∎

**引理 3（固定目标奇偶性时的最小总代价）**：设目标位置 $T$ 满足 $T \bmod 2 = \sigma$，则把所有筹码移到 $T$ 的最小总代价为

$$C_\sigma = \#\{i : \text{position}[i] \bmod 2 \ne \sigma\}$$

**证明**：各筹码的移动相互独立，总代价是单个筹码代价之和。对每个筹码，由引理 1、2，其最小代价恰为 $[\text{position}[i] \bmod 2 \ne \sigma]$（异或指示，取 1 当且仅当奇偶性不同）。求和即得 $C_\sigma$。由于每个筹码都能独立达到自己的最小值（引理 2 的构造对每个筹码分别执行，互不影响），该下界是可同时达到的。∎

**定理**：算法返回的 $\min(\text{even}, \text{odd})$ 等于题目要求的最小总代价。

**证明**：任取一个把全部筹码移到位置 $T$ 的合法方案，$T$ 的奇偶性只能是 $0$ 或 $1$。若 $T$ 为偶数，由引理 3 该方案代价 $\ge C_0 = \text{odd}$；若 $T$ 为奇数，代价 $\ge C_1 = \text{even}$。因此任意方案的代价都 $\ge \min(\text{even}, \text{odd})$。

另一方面，取 $\sigma$ 为筹码较少的一侧对应的奇偶性，并令 $T$ 为 $1$ 或 $2$ 中与 $\sigma$ 同奇偶的那一个，由引理 3 得到代价恰为 $\min(\text{even}, \text{odd})$，说明该下界可达。

上下界重合，故算法输出即最优值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。对每个筹码做一次取模判断与自增，$n \le 100$ 时不足百次操作；没有排序的 $O(n \log n)$，也没有任何嵌套循环。
- **空间**：$O(1)$。只维护 `even` 与 `odd` 两个整数；输入数组本身不计入额外空间，Python 版本额外创建了一个生成器，仍是 $O(1)$。
- **对比**：若按 3.1 的暴力做法枚举 $T \in \text{position}$ 并对每个 $T$ 重新计算代价，时间为 $O(n^2)$、空间 $O(1)$；本题规模下两者都能过，但计数法在 $n$ 增大时优势明显，且没有「目标位置枚举不全」的正确性隐患。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int minCostToMoveChips(vector<int>& position) {
        int n = static_cast<int>(position.size());
        int even = 0;
        for (int p : position) {          // ① 只数偶数位筹码
            if (p % 2 == 0) ++even;
        }
        int odd = n - even;               // ② 其余都是奇数位筹码
        return min(even, odd);            // ③ 目标选筹码多的一侧，异侧各付 1 元
    }
};
```

### Python

```python
from typing import List


class Solution:
    def minCostToMoveChips(self, position: List[int]) -> int:
        even = sum(1 for p in position if p % 2 == 0)   # ① 偶数位筹码数
        odd = len(position) - even                      # ② 奇数位筹码数
        return min(even, odd)                           # ③ 取较小的一侧
```

> 💡 如果面试官追问「能再快吗」：答案是否定的——必须读完整个数组才知道两类的数量，$\Omega(n)$ 是下界。若追问「如果允许修改数组」，可以原地把奇偶信息写回数组前几位，把空间压到严格 $O(1)$，但对本题没有实际收益。

## 8. 边界情况与易错点

1. **$n = 1$**：`even` 与 `odd` 中恰有一个为 1、另一个为 0，返回 0。这是正确答案（唯一筹码已经在目标位置上），不要因为「没有移动」而误判成需要特判。
2. **所有筹码同奇偶**：如 `[2,4,6]`，返回 0。任何「以坐标均值 / 中位数做目标」的想法在这里都会算出非零代价，因为那些做法默认「每移动 1 个单位花 1 元」。
3. **两类数量相等**：如示例 3（各 1 枚），`min` 取任何一个，结果都正确；不存在「必须选坐标更靠中间的轨道」这回事。
4. **坐标巨大不构成难度**：$10^9$ 只是让「枚举目标位置」的暴力彻底不可行，对计数法毫无影响。千万不要写 `abs(p - T) / 2` 之类的式子——距离除以 2 既不是代价，还引入了不必要的整除细节。
5. **别把答案写成距离或距离的一半**：示例 3 的距离是 $999999999$，答案是 1，差距九个数量级，足以暴露任何「按距离算钱」的错误建模。
6. **C++ 负数取模**：本题 $p \ge 1$ 不会触发，但若扩展成允许 $0$ 或负数，`p % 2` 会得到 $-1$，此时 `p % 2 == 0` 的判断仍然正确（负数奇数不会等于 0），但任何把余数当 $0/1$ 用的写法都会出错。
7. **直接套「中位数选址」模板**：如果把代价当成距离和 $\sum_i \lvert \text{position}[i] - T \rvert$ 再去取中位数，示例 1 会算出 $\lvert 1-2 \rvert + 0 + \lvert 3-2 \rvert = 2$，而正确答案是 1。本题的代价函数是「奇偶性异或」而不是距离，套错模板是最常见的失分方式。
8. **返回值类型**：函数签名是 `int`，不要返回 `long long` 或浮点数；Python 返回 `int` 即可，`min` 作用在整数上不会产生 `float`。

- [LeetCode 1551. 使数组中所有元素相等的最小操作数](https://leetcode.cn/problems/minimum-operations-to-make-array-equal/)：允许 $\pm 2$、要求元素相等且**统计操作次数**。本题则是 $\pm 2$ 免费、只统计 $\pm 1$ 的次数，两题的「免费/收费」互换，正好互为镜像。
- [LeetCode 2448. 使数组相等的最小开销](https://leetcode.cn/problems/minimum-cost-to-make-array-equal/)：每个位置有「单位距离单价」，带权中位数选址；可视为本题「所有单价相同且只关心奇偶」的一般化。

**延伸思考**：

1. **把「$\pm 2$ 免费」改成「$\pm k$ 免费」**：同一同余类内零代价可达，换类需付 1 元。答案变成 $\displaystyle n - \max_{r} \#\{i : \text{position}[i] \equiv r \pmod k\}$，因为目标同余类应选筹码最多的那一类。本题是 $k = 2$ 的特例。
2. **加权版本**：若第 $i$ 枚筹码的「搬运费」为 $w_i$（每换一次轨道付 $w_i$），则答案变为 $\min\bigl(\sum_{\text{odd}} w_i,\ \sum_{\text{even}} w_i\bigr)$，仍是 $O(n)$，但证明里引理 3 的求和要带上权重。
3. **若 $\pm 1$ 的价格为 $c$、$\pm 2$ 的价格为 $d$**：当 $d \ge 2c$ 时 $\pm 2$ 永不划算，问题退化成「中位数选址」；当 $d < 2c$ 时需要用 $\pm 2$ 尽量跳，此时每个筹码的最小代价是与距离奇偶性相关的分段函数，模板会复杂不少。
4. **目标位置限定在区间 $[L, R]$ 内**：同奇偶性之间的免费滑动在区间内依然可行（步长 2 不会跨越端点），但若区间只含一种奇偶性，则答案直接由另一类筹码的数量决定——也就是说，限制目标区间只会把「二选一」变成「一选一」。
