# LeetCode 会议室 III 题解

## 1. 题目概述

- **标题 / 题号**：会议室 III（#2402，hard）
- **链接**：https://leetcode.cn/problems/meeting-rooms-iii/
- **来源**：LeetCode 第 309 场周赛 Q4
- **难度**：困难
- **标签**：数组、排序、模拟、堆（优先队列）

**题意**：共有 `n` 个会议室（编号 `0` 到 `n-1`）和一组会议 `meetings`，`meetings[i] = [start_i, end_i]` 表示会议在**半闭区间** `[start_i, end_i)` 召开，所有 `start_i` 互不相同。会议按如下规则分配房间：每场会议进**未占用且编号最小**的房间；若无空房则**顺延**（时长不变），直到有房间腾出；房间腾出时优先提供给**原开始时间更早**的会议。返回举办会议次数最多的房间编号，并列时返回编号最小者。

**约束**：

- $1 \le n \le 100$
- $1 \le \text{meetings.length} \le 10^5$
- $0 \le \text{start}_i < \text{end}_i \le 5 \times 10^5$
- 所有 $\text{start}_i$ **互不相同**

> 💡 **切入信号**：这是「会议室」系列的模拟进阶版——[253. 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/) 只问「峰值并发」（统计型），本题要把**每场会议落到哪个房间**精确还原（模拟型）。三条规则天然拆成三个数据结构动作：排序管优先级、一个堆管编号、另一个堆管腾出时刻。赛点的全部难度藏在三个坑里：`≤` 与 `<` 的一字之差、并列腾出的编号裁决、以及顺延链式累加导致的 64 位溢出。

## 2. 示例

**示例 1**

```text
输入：n = 2, meetings = [[0,10],[1,5],[2,7],[3,4]]
输出：0
解释：
  [0,10) → 房 0；[1,5) → 房 1
  [2,7) 两房被占，顺延到房 1 腾出：[5,10) 于房 1
  [3,4) 两房被占，顺延：t=10 两房同刻腾出，取编号小的房 0：[10,11) 于房 0
  房 0、房 1 各 2 场 → 并列返回 0
```

**示例 2**

```text
输入：n = 3, meetings = [[1,20],[2,10],[3,5],[4,9],[6,8]]
输出：1
解释：
  [1,20)→房0；[2,10)→房1；[3,5)→房2
  [4,9) 无空房，顺延到 (5, 房2)：[5,10) 于房 2
  [6,8) 无空房，顺延到 (10, 房1)：[10,12) 于房 1
  房 1、房 2 各 2 场 → 并列返回 1
```

**示例 3**（自构造：`n = 1` 的链式顺延，覆盖「全部顺延」的极端情形）

```text
输入：n = 1, meetings = [[0,5],[1,3],[2,4]]
输出：0
解释：唯一房间被连续占用，三场会议首尾相接：
  [0,5) → [5,7) → [7,9)，房 0 共 3 场，返回 0。
  若把时长与规模拉满（10⁵ 场 × 5×10⁵ 时长），结束时刻累加至约 5×10¹⁰ —— 这是必须用 64 位整数的信号。
```

## 3. 解题思路

### 3.1 暴力思路：逐刻模拟 → 事件驱动 O(m·n)

最原始的直觉是把时间轴当成主循环逐刻推进：每个时刻先释放到期房间、再把等待队列里 `start` 最早的会议塞进编号最小的空房。问题在于**顺延会把时间轴拉长**——如示例 3 所示，`n = 1` 时结束时刻可以累加到约 $5 \times 10^{10}$，逐刻模拟连循环边界都开不下；何况绝大多数时刻什么也不发生。

真正推动状态变化的只有两类**事件**：**会议到场**与**房间腾出**。于是退一步得到事件驱动的暴力：按 `start` 排序后逐场处理，维护每间房的占用结束时刻 `end[r]`，每场会议**线性扫一遍全部 `n` 间房**——取 `end[r] ≤ s` 中编号最小者正常分配；若不存在，取 `(end[r], r)` 最小的房间顺延。每场 $O(n)$，总计 $O(m \cdot n) \approx 10^7$，赛时完全够用，是稳妥的**保底解**。

但这个扫描里藏着两处「取最小」：$n \le 100$ 时无感，若 $n$ 与 $m$ 同阶（比如 $10^5$ 间房），$O(m \cdot n)$ 就崩了。把两处取最小各换成一个堆，就是正解。

### 3.2 核心观察：三条规则 → 三个数据结构动作

| 题面规则 | 数据结构动作 |
|----------|--------------|
| 规则③：房间腾出时优先给原 `start` 更早的会议 | **按 `start` 升序排序**后逐场处理（`start` 互不相同，处理序 = 优先序） |
| 规则①：进未占用且**编号最小**的房间 | **`idle` 小顶堆**存空闲房间编号，堆顶即所求 |
| 规则②：无空房则**顺延到最早腾出**、时长不变 | **`busy` 小顶堆**存 `(结束时刻, 房间编号)`，堆顶即所求 |

![核心观察：双堆分工——idle 管编号，busy 管时刻](images/meeting_rooms_iii_dual_heap_model.svg)

`busy` 堆元组的**第二维放房间编号**是点睛之笔：多间房**同刻腾出**时，`(end, room)` 字典序自动先弹出小编号——这恰好是规则①在「腾出瞬间」的应用。

> 💡 **为什么这个模拟是忠实的？** 一个常见的困惑：会议 A 顺延到 `t` 才开始，那在它顺延目标时刻之前，它锁定的房间算不算「物理空闲」、能不能给后到的会议插队？答案是**不存在这种空档**——顺延会议的新区间 $[t, t + d)$ 与该房间上一占用区间 $[\cdot, t)$ **无缝相接**（见 §5 引理 1）：房间腾出的那一瞬间，顺延会议恰好入场。因此 `busy` 堆里每个 `(end, room)` 都是房间**真实的下一次腾出时刻**，「无空房才顺延」与「顺延到最早腾出」自洽，后到者永远找不到可插的缝。

### 3.3 算法流程

![算法流程：排序 → 逐会议「释放 → 分配 / 顺延」](images/meeting_rooms_iii_event_flow.svg)

1. 将 `meetings` 按 `start` 升序排序（`start` 互不相同，无需处理并列）。
2. 初始化 `idle = {0, 1, …, n-1}`（小顶堆），`busy` 为空，计数数组 `cnt[0..n-1] = 0`。
3. 对每场会议 `(s, e)`：
   - **释放**：`while busy 非空且堆顶 end ≤ s`：弹出 `(end, r)`，把 `r` 压回 `idle`。
   - **分配**：若 `idle` 非空，弹出堆顶 `r`，压入 `(e, r)`，`cnt[r]++`。
   - **顺延**：否则弹出 `busy` 堆顶 `(t, r)`，压入 `(t + (e − s), r)`，`cnt[r]++`。
4. 遍历 `cnt`，返回最大计数中**编号最小**的房间。

### 3.4 示例演算

以示例 1 `n=2, meetings=[[0,10],[1,5],[2,7],[3,4]]` 为例（已按 `start` 排序）：

| 会议 | 释放 end≤s | idle | 动作 | busy | cnt |
|------|-----------|------|------|------|-----|
| [0,10] | 无 | {0,1} | 取房 0 | {(10,0)} | [1,0] |
| [1,5] | 无 | {1} | 取房 1 | {(5,1),(10,0)} | [1,1] |
| [2,7] | 无 | {} | 顺延到 (5,1)，新区间 [5,10) | {(10,0),(10,1)} | [1,2] |
| [3,4] | 无 | {} | 顺延到 (10,0)（同刻取小号），新区间 [10,11) | {(10,1),(11,0)} | [2,2] |

最终 `cnt = [2, 2]`，并列取编号小的 **0**。

![示例1走查：顺延会议无缝衔接，同刻腾出取小号](images/meeting_rooms_iii_gantt_walkthrough.svg)

> ⚠️ **第 4 场是本题的题眼**：`busy` 堆顶两个元素 `(10,0)` 与 `(10,1)` 结束时刻相同。若堆里只存 `end` 不存 `room`（或堆序不对），这一步可能把会议④给房 1，`cnt` 变成 `[1,3]`，答案错成 1。元组第二维正是为了裁决这种并列。

## 4. 算法细节

1. **排序**：处理前必须排序，输入未必按 `start` 有序。`start` 两两不同，排序后无并列歧义；Python 直接 `meetings.sort()`，C++ 用 `sort`（默认按第一维、再按第二维，均无害）。

2. **释放循环用 `≤` 而非 `<`**：半闭区间 $[s, e)$ 的语义是「`e` 时刻房间即可复用」。反例：`n=2, meetings=[[0,6],[1,5],[6,7]]`——正确过程释放两房后会议③进编号最小的房 0，`cnt=[2,1]`，答案 0；若写成 `<`，`end=6` 的房 0 不会被释放（`6 < 6` 为假），会议③被错误顺延给房 1，`cnt=[1,2]`，答案错成 1。

3. **两个分支的公式**：
   - 正常分配：新区间就是 $[s, e)$，压入 $(e, r)$；
   - 顺延：设堆顶为 $(t, r)$，新区间为 $[t,\ t + (e - s))$，压入 $(t + (e - s), r)$。**时长 $e - s$ 平移不变**，新结束时刻是 $t + (e-s)$ 而不是 $e$（常见笔误）。

4. **溢出推导（C++ 必须用 `long long`）**：$n = 1$ 时所有会议在同一间房链式顺延，结束时刻逐场累加时长，最坏 $10^5 \times 5 \times 10^5 = 5 \times 10^{10}$，远超 32 位 `int`（约 $2.1 \times 10^9$）。`busy` 堆的元素类型应为 `pair<long long, int>`。

5. **答案的并列裁决**：遍历时用**严格大于**才更新（`cnt[i] > cnt[ans]`），保证并列保留小编号；Python 可直接 `cnt.index(max(cnt))`。

6. **语言细节**：Python 的 `heapq` 是小顶堆，元组按字典序比较，`(end, room)` 自动先比 `end` 再比 `room`；C++ 用 `priority_queue<pair<long long,int>, vector<...>, greater<>>` 达到同样堆序。

## 5. 正确性证明

**引理 1（无缝衔接）**：任一房间的最终日程是一列互不相交、按时间排列的占用区间，且每个**顺延**区间的起点恰等于同房间前一区间的右端点。

**证明**：对处理场次归纳。归纳基础（尚未安排任何会议）显然。设前 $k$ 场成立。处理第 $k+1$ 场 $(s, e)$ 时：正常分配所选房间在 `idle` 中，其当前占用区间（若存在）右端点 $\le s$，新区间 $[s, e)$ 与之不交；顺延分配弹出 `busy` 堆顶 $(t, r)$，而 `busy` 中存的就是 $r$ 当前占用区间的右端点 $t$，新区间 $[t, t + (e-s))$ 与 $[\cdot, t)$ **首尾相接**。两种情况下房间日程仍为不相交区间的列表，且顺延区间起点 = 前一区间右端点。∎

**引理 2（空闲判定一致性）**：处理会议 $i$（区间 $[s_i, e_i)$）时，`idle` 堆中的房间恰为最终日程中时刻 $s_i$ 真实空闲的房间。

**证明**：
（$\supseteq$）`idle` 中房间的当前占用区间右端点 $\le s_i$（或从未占用）。在 $i$ 之后处理的会议 $j$ 满足 $s_j > s_i$，其占用区间无论正常 $[s_j, e_j)$ 还是顺延 $[t_j, t_j + d_j)$（注意 $t_j > s_j$），起点都严格大于 $s_i$，不会覆盖时刻 $s_i$。
（$\subseteq$）先注意每间房「当前占用区间的右端点」在处理过程中**单调不减**：正常分配的新右端点 $e_k > s_k \ge$ 旧右端点（旧区间在 $s_k$ 前已结束）；顺延的新右端点 $t + d > t$ = 旧右端点。设房间 $r$ 在最终日程中被区间 $I$ 覆盖于 $s_i$，$I$ 由某会议 $k$ 排定。若 $k$ 在 $i$ 之后处理，则 $I$ 的起点 $> s_i$，矛盾；故 $k$ 在 $i$ 之前处理，且 $I$ 的右端点 $> s_i$。由单调性，处理 $i$ 时 $r$ 的当前区间右端点 $\ge I$ 的右端点 $> s_i$，不会被释放，$r \notin \text{idle}$。∎

**引理 3（堆序对应规则）**：`idle` 小顶堆的堆顶是编号最小的空闲房间（规则①）；`busy` 按 $(end, room)$ 字典序小顶，堆顶是**最早腾出**的房间，腾出时刻并列时**编号最小**（规则②与规则①在腾出瞬间的联合应用）。

**证明**：小顶堆性质直接给出前者；元组字典序先比 `end` 再比 `room`，给出后者。∎

**定理**：双堆模拟得到的分配满足题面三条规则；且三条规则在每个事件点唯一确定选择，故满足规则的调度唯一，模拟结果的计数即为所求。

**证明**：对处理场次归纳，维护不变量：「`busy` = 各房间当前占用区间的 $(右端点, 编号)$ 全体；`idle` = 当前无排定占用的房间全体」。处理会议 $i$ 时：

1. 由引理 2，释放循环恰好腾出「时刻 $s_i$ 真实空闲」的房间，不多不少——规则②的前提「没有可用的会议室」被精确判定。
2. 若 `idle` 非空，由引理 3 会议进入编号最小的空房，占用 $[s_i, e_i)$——规则①落实。
3. 若 `idle` 为空，此刻真实无空房（引理 2 的逆否）。由引理 1，堆顶 $(t, r)$ 中的 $t$ 就是下一间房的真实腾出时刻，会议以原时长从 $t$ 无缝开始——规则②落实。同刻 $t$ 腾出的房间中编号最小者先被弹出（引理 3），而此刻尚未处理的会议 `start` 都更大，正在处理的这场正是规则③意义下的最高优先者——规则③落实。

每个事件点的选择都被规则唯一确定（最小编号 / 最早腾出加最小编号），归纳成立，模拟结果即唯一合法调度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \log m + (m + n) \log n)$。排序 $O(m \log m)$；每场会议自身压弹堆 $O(\log n)$，释放循环整体均摊——每个房间每被压入一次至多被弹出一次，全场总压入次数 $\le m + n$，故堆操作总计 $O((m + n) \log n)$。
- **空间复杂度**：$O(n)$。两个堆共存至多 $n$ 个房间编号，计数数组 $O(n)$（排序若不计输入原地）。
- **对照保底解**：$O(m \cdot n) \approx 10^7$ 在 $n \le 100$ 时同样通过；双堆版的优势是当 $n$ 与 $m$ 同阶时依然成立，是可迁移的模板（同构题见 1882）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int mostBooked(int n, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end());   // 按 start 升序（规则③）

        priority_queue<int, vector<int>, greater<int>> idle;
        for (int i = 0; i < n; i++) idle.push(i);

        using pli = pair<long long, int>;          // (结束时刻, 房间编号)
        priority_queue<pli, vector<pli>, greater<pli>> busy;
        vector<int> cnt(n, 0);

        for (auto& m : meetings) {
            long long s = m[0], e = m[1];
            // 释放：半开区间语义，end == s 也算腾出
            while (!busy.empty() && busy.top().first <= s) {
                idle.push(busy.top().second);
                busy.pop();
            }
            if (!idle.empty()) {                   // 有空房：编号最小
                int r = idle.top(); idle.pop();
                busy.push({e, r});
                cnt[r]++;
            } else {                               // 无空房：顺延，时长不变
                auto [t, r] = busy.top(); busy.pop();
                busy.push({t + (e - s), r});
                cnt[r]++;
            }
        }

        int ans = 0;
        for (int i = 1; i < n; i++)
            if (cnt[i] > cnt[ans]) ans = i;        // 严格大于：并列保留小编号
        return ans;
    }
};
```

### Python

```python
class Solution:
    def mostBooked(self, n: int, meetings: List[List[int]]) -> int:
        meetings.sort()                      # 按 start 升序（规则③）
        idle = list(range(n))                # 空闲堆：房间编号
        heapq.heapify(idle)
        busy = []                            # 占用堆：(end, room)
        cnt = [0] * n

        for s, e in meetings:
            while busy and busy[0][0] <= s:  # 释放：end == s 也算腾出
                heapq.heappush(idle, heapq.heappop(busy)[1])
            if idle:                         # 有空房：编号最小
                r = heapq.heappop(idle)
                heapq.heappush(busy, (e, r))
            else:                            # 无空房：顺延，时长不变
                t, r = heapq.heappop(busy)
                heapq.heappush(busy, (t + e - s, r))
            cnt[r] += 1

        return cnt.index(max(cnt))           # 并列自动取最小编号
```

## 8. 边界情况与易错点

1. **溢出（C++ 最大坑）**：$n=1$ 链式顺延最坏 $5 \times 10^{10}$，`busy` 堆必须存 `long long`。Python 无此问题，但要有意识。
2. **释放条件是 `end ≤ s`**：半开区间下恰在 `s` 腾出的房间可立即复用。反例见 §4 第 2 条（`[[0,6],[1,5],[6,7]]`，`<` 把答案从 0 错成 1）。
3. **`busy` 堆必须带第二维 `room`**：同刻腾出时裁决编号。反例即示例 1 第 4 场：堆序不对则 `cnt` 错成 `[1,3]`、答案错成 1。
4. **顺延的新结束时刻**是 $t + (e - s)$，不是 $e$；时长平移不变。
5. **处理前必须排序**：输入不保证按 `start` 有序。
6. **答案并列取小号**：用严格 `>` 更新，或 Python 的 `cnt.index(max(cnt))`。
7. **会议数少于房间数**：`idle` 永远非空，顺延分支不触发，前 $\min(m, n)$ 场各进一间房——代码无需特判，自然成立。
8. **`n = 1`**：所有会议链式串行，是溢出与顺延正确性的双重点，建议作为对拍用例。

**延伸思考**：

- 若 $n$ 放大到 $10^5$：$O(m \cdot n)$ 扫描解失效，双堆解 $O((m+n) \log n)$ 照常工作——这正是堆版作为模板的价值。
- **二分 + 本模拟 = 会议室 II**：以「给定 $n$ 是否不发生任何顺延」为判定器，二分最小的 $n$ 就得到 253 的答案（最少房间数 = 最大并发）；253 的差分 / 单堆解法是这一判定的加速版。
- **在线版**：会议按时间实时到来（不允许预排序）——由于处理顺序本来就是到场顺序，同样的双堆结构直接支持在线调度。
- 若要求输出每个房间的完整日程：在两个分支各记录 `(房间, [start, end])` 即可，复杂度不变。
