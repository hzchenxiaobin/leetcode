# LeetCode 最长优雅子数组 题解

## 1. 题目概述

- **标题 / 题号**：最长优雅子数组（#2401，medium）
- **链接**：https://leetcode.cn/problems/longest-nice-subarray/
- **来源**：LeetCode 第 309 场周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、滑动窗口

**题意**：给定一个由**正整数**组成的数组 `nums`。若子数组中位于**不同位置**的每对元素按位 **AND** 的结果都等于 0，则称该子数组为**优雅子数组**。求最长优雅子数组的长度（长度为 1 的子数组恒为优雅）。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

> 💡 **切入信号**：「任意两数 AND = 0」是**成对条件**，朴素检验需枚举 $O(L^2)$ 个数对。但比特与比特之间互不干扰——把每个比特位看作一份**独占资源**，成对条件就坍缩为「每份资源至多被一个元素占用」的**整体条件**，于是可用一个 **OR 累积器**在 $O(1)$ 内判定新元素能否入窗；再配合「窗口越长条件越难满足」的单调性，滑动窗口水到渠成。本质上这是 [LC 3. 无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/) 的位运算版。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,8,48,10]
输出：3
解释：最长优雅子数组是 [3,8,48]：3 AND 8 = 0，3 AND 48 = 0，8 AND 48 = 0，
      不存在更长的优雅子数组。
```

**示例 2**

```text
输入：nums = [3,1,5,11,13]
输出：1
解释：任何两数的按位 AND 都非零（如 3 AND 1 = 1、5 AND 13 = 5、11 AND 13 = 9），
      故最长优雅子数组长度为 1。
```

**示例 3**（自构造：数组整体优雅，收缩一次都不触发）

```text
输入：nums = [1,2,4,8,16]
输出：5
解释：互不相同的 2 的幂两两 AND = 0，整个数组本身就是优雅子数组。
```

## 3. 解题思路

### 3.1 暴力思路：枚举子数组，逐对（或逐元素）检验

朴素做法有两档写法：

1. **枚举全部子数组 + 逐对检验**：$O(n^2)$ 个子数组，每个最多 $O(L^2)$ 次两两 AND，总量 $O(n^4)$；
2. **枚举左端点，向右扩展**：固定 `left` 后逐个纳入 `nums[right]`，只需检验它与**已纳入元素**是否冲突——维护已纳入元素的 OR，检查 `nums[right] & or`，冲突立即停止扩展。单次扩展 $O(L)$，总计 $O(n \cdot L)$（$L$ 为最长优雅子数组长度）。

写法 2 其实已经用上了 §3.2 的核心观察，但复杂度仍可能退化到 $O(n^2)$（$L$ 可达 $n$）：取 `nums = [1,2,4,8,16,...]` 这类互不相同的 2 的幂，每个左端点都要一路扩展到数组末尾才停。**症结在于：同一个右端点的可行左端点被反复重算**——没有利用左端点的单调性。

### 3.2 核心观察：比特位是「独占资源」，OR 就是占用表

![核心观察：两两 AND 为 0 等价于每个比特列至多一个 1](images/wc309_q3_bit_window_concept.svg)

把每个比特位看作一间「房间」，元素置 1 的位就是它占用的房间：

- **两两 AND = 0 ⟺ 每个比特位至多被一个元素占用**（证明见 §5 引理 1）。前者是 $O(L^2)$ 的成对条件，后者是 $O(1)$ 可判定的整体条件；
- 于是**窗口内所有元素的 OR** 恰好充当「当前占用表」：新元素 `x` 能否入窗，只需检验一次 `x & or == 0`（§5 引理 2）；
- 优雅性在删去元素后**自动保持**（数对只减不增），因此固定右端点时可行左端点单调不减——滑动窗口的全部前提都齐了。

### 3.3 算法流程：OR 累积器 + XOR 撤销

![算法流程：滑动窗口，冲突时用 XOR 撤销最左元素](images/wc309_q3_sliding_window_flow.svg)

维护窗口 $[\text{left}, \text{right}]$ 与累积器 $\text{mask}$（窗口内所有元素的按位或）：

1. 右端 `right` 逐个右移，令 $x = \text{nums}[\text{right}]$；
2. **冲突则收缩**：当 $\text{mask} \,\&\, x \ne 0$，说明 $x$ 想占的比特已被窗口占用，执行 $\text{mask} \oplus{=} \text{nums}[\text{left}]$、`left++`，循环直至无冲突；
3. **纳入**：$\text{mask} \,|{=}\, x$，更新 $\text{ans} = \max(\text{ans},\ \text{right} - \text{left} + 1)$。

> 💡 **XOR 撤销的精妙之处**：按位 OR 本身**不可逆**——两个元素共享某位时，撤掉一个也清不掉共享位。但优雅窗口内**每个比特至多被一个元素占有**，各元素的占位集合**两两不交**；不交集合上「并 = 异或」，所以 $\text{mask} \oplus \text{nums}[\text{left}]$ 恰好清掉它独占的位、不伤及任何其他元素（§5 引理 4）。这是本题最值得沉淀的技巧：**用 XOR 撤销 OR，前提是由「位独占」不变量保证**。

### 3.4 示例演算

![示例演算：nums=1,3,8,48,10 的窗口滑动全过程](images/wc309_q3_example_walkthrough.svg)

以示例 1 为例，$\text{mask}$ 用 6 位二进制展示（实际 $10^9 < 2^{30}$，为 30 位）：

| right | x | 检查 mask & x | 动作 | 窗口 | mask（纳入后） | ans |
|-------|-----|---------------|------|------|----------------|-----|
| 0 | 1 | $000000 \& 000001 = 0$ | 直接纳入 | $[1]$ | $000001$ | 1 |
| 1 | 3 | $000001 \& 000011 \ne 0$ | 撤销下标 0（元素 1） | $[3]$ | $000011$ | 1 |
| 2 | 8 | $000011 \& 001000 = 0$ | 纳入 | $[3,8]$ | $001011$ | 2 |
| 3 | 48 | $001011 \& 110000 = 0$ | 纳入 | $[3,8,48]$ | $111011$ | **3** |
| 4 | 10 | $111011 \& 001010 \ne 0$ | 连撤下标 1（3）、2（8） | $[48,10]$ | $111010$ | 3 |

最关键的是第 4 步：$10 = 001010$ 想占比特 3 和比特 1，但占用表 $111011$ 显示比特 1 被 3 占、比特 3 被 8 占——先撤销 3（腾出比特 0、1），检查 $111000 \& 001010 \ne 0$ 发现比特 3 仍被 8 占，再撤销 8，检验 $110000 \& 001010 = 0$ 通过，纳入 10。最终窗口 $[48,10]$ 长度 2，答案保持 3。

## 4. 算法细节

1. **顺序不能颠倒**：必须**先**执行收缩循环 `while (mask & x)`、**后**执行 `mask |= x`。若先把 $x$ 或进 mask 再检查，则 $x$ 自己的位已在 mask 中，`mask & x` 永远非零，收缩逻辑被彻底破坏（见 §8 陷阱 1）。
2. **XOR 撤销为何安全**：循环不变量是「窗口时刻保持优雅」。由引理 4，只要不变量成立，`mask ^= nums[left]` 就精确等价于「从窗口 OR 中移除最左元素」；而该不变量由算法流程归纳维持（§5 定理）。
3. **双指针均单调不减**：`left` 只在收缩中增加，`right` 每轮加一，总移动步数 $\le 2n$。收缩循环虽嵌套在遍历里，均摊后每步 $O(1)$——经典的均摊分析。
4. **位宽预算**：$1 \le \text{nums}[i] \le 10^9 < 2^{30}$，`mask` 用 32 位 `int` 即可；所有 AND/OR/XOR 均为单机器字运算，不存在加法前缀和那样的溢出风险。
5. **替代实现（按位记录最后下标）**：对 30 个比特各维护 $\text{last}[b]$ = 该位最近一次出现的下标（初值 $-1$）。处理下标 $r$ 时，对 $x = \text{nums}[r]$ 的每个置位 $b$ 执行 $\text{left} = \max(\text{left},\ \text{last}[b] + 1)$，随后更新 $\text{last}[b] = r$。复杂度 $O(30n)$，不依赖 XOR 撤销技巧，与 LC 3「记录字符上次出现位置」的写法同构，可作交叉验证。
6. **调试利器（popcount 判别式）**：窗口优雅 $\iff \sum_{x \in W} \operatorname{popcount}(x) = \operatorname{popcount}(\text{mask})$，对拍或断言时可用。

## 5. 正确性证明

**引理 1**（成对条件 ⟺ 位独占）：子数组 $S$ 中任意两个不同位置的元素按位 AND 为 0 $\iff$ $S$ 中每个比特位至多被一个元素置 1。

**证明**：（⟹）反设比特 $b$ 被两个不同元素 $x, y$ 同时置 1，则 $x \& y$ 的第 $b$ 位为 1，故 $x \& y \ne 0$，与优雅性矛盾。（⟐）若存在数对 $x \ne y$ 使 $x \& y \ne 0$，取 $x \& y$ 中任一置位 $b$，则 $x, y$ 都在比特 $b$ 置 1，即 $b$ 被至少两个元素占用。∎

**引理 2**（OR 一票判定）：设 $W$ 为优雅子数组，$\text{mask} = \bigvee_{x \in W} x$，则元素 $x$ 使 $W \cup \{x\}$ 仍优雅 $\iff$ $x \,\&\, \text{mask} = 0$。

**证明**：由引理 1，$W$ 优雅 $\iff$ $W$ 内部无共享位，且 $W$ 的占用位集合恰为 $\text{mask}$ 的置位集合。而 $W \cup \{x\}$ 优雅 $\iff$ $W$ 内部无共享位（已知成立）且 $x$ 与 $W$ 中每个元素无共享位 $\iff$ $x$ 的任一置位都不属于 $W$ 的占用集合 $\iff$ $x \& \text{mask} = 0$。∎

**引理 3**（遗传性与单调性）：优雅子数组的子子数组优雅；对每个下标 $r$，记 $f(r)$ 为使 $[\ell, r]$ 优雅的最小 $\ell$，则 $f$ 关于 $r$ 单调不减。

**证明**：成对 AND 条件只涉及窗口内的数对，删去元素后数对集合缩小，条件自动保持，得遗传性。若 $[\ell, r+1]$ 优雅，则删去末元素得 $[\ell, r]$ 优雅，由 $f$ 的最小性 $f(r) \le \ell$；对 $\ell = f(r+1)$ 取等即 $f(r) \le f(r+1)$。∎

**引理 4**（XOR 撤销）：若 $W = [\ell, r]$ 优雅、$u = \text{nums}[\ell]$ 为其最左元素，则 $\bigvee_{x \in W \setminus \{u\}} x = \text{mask} \oplus u$。

**证明**：由引理 1，$W$ 中各元素的置位集合两两不交。对任意比特 $b$：若 $b$ 恰被某个 $y \in W$ 置 1，则 $\text{mask}$ 在该位为 1，且 $\text{mask} \oplus u$ 在该位为 1 当且仅当 $y \ne u$，与 $W \setminus \{u\}$ 的 OR 在该位一致；若 $b$ 无元素置 1，则两侧均为 0。逐位一致，等式成立。∎

**定理**：算法返回最长优雅子数组的长度。

**证明**：先证循环不变量「每轮纳入 $x$ 后，$[\text{left}, \text{right}]$ 优雅且 $\text{mask}$ 等于其 OR」。空窗口平凡成立；对 `right` 归纳，设处理前对上一轮成立。收缩循环中每步由引理 4 保持「mask = 窗口 OR」，且剩余窗口由引理 3 保持优雅；循环终止时 $\text{mask} \& x = 0$，由引理 2，纳入 $x$ 后窗口仍优雅且 `mask |= x` 正确维护其 OR。

再证最优性，断言：处理完 `right` $= r$ 后 $\text{left} = f(r)$。收缩起点为上一轮的 $\text{left} = f(r-1) \le f(r)$（引理 3 及归纳假设；$r=0$ 时起点 $0 = f(0)$）。收缩循环从该起点逐个右移，由引理 2，$\text{mask} \& x = 0$ 当且仅当当前 $\ell$ 使 $[\ell, r]$ 优雅；而 $[\text{start}, f(r))$ 内每个 $\ell < f(r)$ 都不可行，故循环恰停在 $f(r)$。于是 $\text{ans} = \max_r \big( r - f(r) + 1 \big)$，即所有右端点能张成的最长优雅子数组长度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`right` 移动 $n$ 次；`left` 单调不减，全程至多再移动 $n$ 次；每次移动为常数次机器字位运算。替代实现（按位 last 数组）为 $O(30n)$，同为线性级别。
- **空间复杂度**：$O(1)$。仅累积器 `mask` 与两个下标；替代实现为 $O(30)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int longestNiceSubarray(vector<int>& nums) {
        int n = nums.size(), ans = 1, mask = 0;   // 长度 1 恒优雅
        for (int left = 0, right = 0; right < n; ++right) {
            while (mask & nums[right])    // 冲突：x 要占的位已被窗口占用
                mask ^= nums[left++];     // 位集合两两不交 → XOR 恰好撤销最左元素
            mask |= nums[right];          // 先收缩、后纳入，顺序不可颠倒
            ans = max(ans, right - left + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def longestNiceSubarray(self, nums: List[int]) -> int:
        ans, mask, left = 1, 0, 0
        for right, x in enumerate(nums):
            while mask & x:            # 冲突：撤销最左元素腾出比特位
                mask ^= nums[left]
                left += 1
            mask |= x                  # 先收缩、后纳入
            ans = max(ans, right - left + 1)
        return ans
```

## 8. 边界情况与易错点

1. **「先纳入后检查」的顺序错误**：若把 `mask |= x` 放在收缩循环之前，则 $x$ 自身的位已在 mask 中，`mask & x` 恒非零，收缩会一路清空窗口、答案全错。正确顺序：**检查 → 收缩 → 纳入**。
2. **误以为 OR 可以用减法/其他方式撤销**：`mask -= nums[left]` 完全错误（OR 无逆元）。`mask ^= nums[left]` 的正确性依赖「窗口内位独占」这一不变量，而该不变量恰好由算法自身维护——这也是它只能配优雅窗口使用、不能盲目套用的原因。
3. **忘记长度 1 恒优雅**：`ans` 初值应取 1 而非 0；$n = 1$ 时循环只走一轮，天然返回 1。
4. **全数组优雅**（如互不相同的 2 的幂，示例 3）：收缩一次不触发，答案为 $n$；此时枚举式暴力恰好退化到 $O(n^2)$，正是滑窗收益最大的场景。
5. **所有元素相同且非零**（如全 1）：每轮都恰好收缩一次，答案 1；同时可验证收缩总步数仍是 $O(n)$ 而非 $O(n^2)$。
6. **值域与类型**：$10^9 < 2^{30} < 2^{31}$，C++ 用 `int` 即可；若值域放宽到 $10^{18}$ 则换 `long long`，算法结构不变。
7. **别与「最长美好子字符串」撞名混淆**：LC 1763 的"美好字符串"是大小写配对问题，与本题的位运算毫无关系，仅名字相似。
