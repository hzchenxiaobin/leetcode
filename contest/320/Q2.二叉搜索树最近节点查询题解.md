# LeetCode 二叉搜索树最近节点查询 题解

## 1. 题目概述

- **标题 / 题号**：二叉搜索树最近节点查询（#2476，medium）
- **链接**：https://leetcode.cn/problems/closest-nodes-queries-in-a-binary-search-tree/
- **来源**：LeetCode 第 320 场周赛 Q2
- **难度**：中等
- **标签**：树、二叉搜索树、中序遍历、二分查找

**题意**：给定一棵 **二叉搜索树（BST）** 的根 `root` 和长度为 $m$ 的正整数数组 `queries`。对每个 $q = \text{queries}[i]$ 求二元组 $\text{answer}[i] = [\text{mini}, \text{maxi}]$：`mini` 是树中**小于等于** $q$ 的**最大值**，不存在则为 $-1$；`maxi` 是树中**大于等于** $q$ 的**最小值**，不存在则为 $-1$。

**约束**：

- 树中节点数目 $2 \le n \le 10^5$
- $1 \le \text{Node.val} \le 10^6$，BST 定义（左子树全体 < 根 < 右子树全体）保证值互不相同
- $1 \le \text{queries.length} \le 10^5$，$1 \le \text{queries}[i] \le 10^6$

> 💡 读题先抓两个信号：① `mini`/`maxi` 就是 $q$ 在「全体节点值」上的 **floor（≤ $q$ 的最大值）** 与 **ceiling（≥ $q$ 的最小值）**；② $n$、$m$ 都是 $10^5$ 量级，只允许 $O((n+m)\log n)$ 以内的做法。再想一步：**查询答案只依赖值集合，与树形完全无关**——这是本题最值钱的观察，直接把树问题降维成有序数组问题。

## 2. 示例

**示例 1**

```text
输入：root = [6,2,13,1,4,9,15,null,null,null,null,null,null,14], queries = [2,5,16]
输出：[[2,2],[4,6],[15,-1]]
解释：树含 8 个节点值 {1,2,4,6,9,13,14,15}。
  q=2 ：命中 2，≤2 的最大值与 ≥2 的最小值都是 2 → [2,2]
  q=5 ：落在 4 与 6 之间 → mini=4，maxi=6 → [4,6]
  q=16：大于全体 → mini=15（末元素），maxi=-1 → [15,-1]
```

**示例 2**

```text
输入：root = [4,null,9], queries = [3]
输出：[[-1,4]]
解释：树中无 ≤3 的值 → mini=-1；≥3 的最小值是 4 → maxi=4。
```

## 3. 解题思路

### 3.1 暴力思路

两种朴素做法都倒在最坏情况：

1. **逐查询全树扫描**：对每个 $q$ 遍历全部节点值，途中维护 floor / ceiling 候选。单次 $O(n)$，总计 $O(nm) = 10^{10}$，必然 TLE。
2. **逐查询顺树搜索（更大的陷阱）**：从根出发沿 BST 下行——当前值 $< q$ 就刷新 `mini` 并向右走（找更大的），当前值 $> q$ 就刷新 `maxi` 并向左走（找更小的），命中即止。单次只有 $O(h)$，直觉上很美；但题目**只保证 BST、不保证平衡**，链状树 $h = n$ 时总计仍是 $O(nm) = 10^{10}$。随手写这版，随机数据（近乎平衡）能过，构造的链状数据直接超时——周赛里这是典型的「树形敏感」暗坑。

> ⚠️ 瓶颈都在「每个查询重新面对整棵树」。突破口：**一次 $O(n)$ 把 BST 摊平成有序数组**，让全部查询共用同一个有序结构，树形的未知被彻底消除。

### 3.2 核心观察：中序摊平 + 二分找邻居

![核心观察：BST 中序摊平成有序数组，对每个 q 二分找 floor/ceiling 邻居](images/wc320_q2_flatten_concept.svg)

BST 的两条性质在这里被压榨到极致：

1. **中序遍历 = 严格递增序列**（§5 引理 1）：一次 DFS「左 → 根 → 右」，$O(n)$ 收集出有序数组 $a$，**无需再排序**；
2. **有序数组上的 floor / ceiling = 二分找边界**：
   - $\text{lo} = \text{lower\_bound}(q)$（首个 $\ge q$ 的下标，无则 $n$）$\Rightarrow \text{maxi} = (lo < n)\ ?\ a[lo] : -1$；
   - $\text{hi} = \text{upper\_bound}(q)$（首个 $> q$ 的下标，无则 $n$）$\Rightarrow \text{mini} = (hi > 0)\ ?\ a[hi-1] : -1$。

整体 $O(n + m\log n)$，约 $2\times10^6$ 次比较。核心收益一句话：**用 $O(n)$ 空间买最坏情况的确定性**——摊平之后单查询 $O(\log n)$ 与树是否平衡无关，顺树搜索的「链状退化」风险被一次性免疫。

### 3.3 算法流程

![算法流程：中序摊平 + 每查询两次二分](images/wc320_q2_binary_search_flow.svg)

1. **迭代中序遍历**（栈模拟，防链状树递归爆栈）收集 $a$；
2. **逐查询循环**：对每个 $q$ 做两次二分；
3. **算 maxi**：$lo = \text{lower\_bound}(q)$，$lo < n$ 则 $a[lo]$，否则 $-1$；
4. **算 mini**：$hi = \text{upper\_bound}(q)$，$hi > 0$ 则 $a[hi-1]$，否则 $-1$；
5. **拼装**：$\text{answer}[i] = [\text{mini}, \text{maxi}]$（**先 mini 后 maxi**）。

### 3.4 示例演算

![示例演算：q=2/5/16 在 a=[1,2,4,6,9,13,14,15] 上二分](images/wc320_q2_walkthrough.svg)

中序得到 $a = [1,2,4,6,9,13,14,15]$（$n=8$），三个查询逐一演算：

| $q$ | $\text{lower\_bound}(\ge q)$ | $\text{upper\_bound}(> q)$ | $\text{mini}=a[hi-1]$ | $\text{maxi}=a[lo]$ | answer |
|-----|------------------------------|----------------------------|------------------------|----------------------|--------|
| 2 | idx 1（值 2） | idx 2（值 4） | $a[1]=2$ | $a[1]=2$ | `[2,2]` |
| 5 | idx 3（值 6） | idx 3（值 6） | $a[2]=4$ | $a[3]=6$ | `[4,6]` |
| 16 | idx 8 $= n$（越界） | idx 8 $= n$（越界） | $a[7]=15$ | $-1$ | `[15,-1]` |

- $q=2$ **命中**元素：`lower/upper` 落在相邻位置，floor 与 ceiling 都是命中值本身；
- $q=5$ **落空隙**：`lower = upper = idx 3`，前驱 $a[2]=4$ 是 floor，本身 $a[3]=6$ 是 ceiling；
- $q=16$ **大于全体**：两支同越右界，`maxi` 无解返 $-1$，`mini` 仍取末元素 $15$。

示例 2 则展示另一侧：$a=[4,9]$，$q=3$ 小于全体，$hi=0$ → `mini=-1`，$lo=0$ → `maxi=4`，得 `[-1,4]`。

## 4. 算法细节

1. **`lower_bound` / `upper_bound` 语义**：前者找**首个 ≥ $q$**（下标集 $\{j: a_j \ge q\}$ 是升序数组的后缀，二分找后缀起点）；后者找**首个 > $q$**（同理，严格大于的后缀起点）。两者相差的正是「等于 $q$ 的那段」，本题值互异时长度至多 1。
2. **mini 为什么用 `upper_bound − 1` 而非 `lower_bound − 1`**：若 $q$ 恰命中 $a[k]=q$，`lower_bound` 落在 $k$，减一漏掉命中元素；`upper_bound` 落在 $k+1$，其前驱恰是**最后一个 ≤ $q$ 的元素**——命中与未命中**逻辑统一，无特判**。
3. **迭代中序防爆栈**：链状树深度 $10^5$，Python 默认递归上限 1000 直接 `RecursionError`，C++ 深递归也有爆栈风险。用显式栈「一路向左压栈 → 弹栈取值 → 转右子树」，与 [173. 二叉搜索树迭代器](https://leetcode.cn/problems/binary-search-tree-iterator/) 同款模板。
4. **不必再 `sort`**：BST 中序已严格递增，再排序是白付 $O(n\log n)$，还抹掉了「BST 有序性」这题眼。
5. **`reserve` 预分配**：$a$、`answer` 各至多 $10^5$ 元素，预分配省掉多次扩容拷贝，常数更稳。
6. **离线替代**（等价解法）：把 `queries` 排序后与 $a$ 归并双指针，$O(n + m\log m)$；对本题无增益，但**查询远多于元素**或**值域极小**时（见延伸思考）是更优形态。

## 5. 正确性证明

**引理 1（中序单调性）**：任意 BST 的中序遍历序列严格递增。

**证明**：对树的结构归纳。空树的序列为空，平凡成立。设根为 $r$，左、右子树为 $L$、$R$，中序序列为 $\text{in}(L) \cdot r \cdot \text{in}(R)$。由归纳假设 $\text{in}(L)$、$\text{in}(R)$ 各自严格递增；由 BST 性质 $L$ 中全体值 $< r < R$ 中全体值。故三段拼接后任意相邻位置满足严格递增，整条序列严格递增。∎

**引理 2（floor 刻画）**：设 $a[0..n-1]$ 严格递增，$hi = \min\{j : a[j] > q\}$（不存在则 $hi = n$，即 `upper_bound`）。若 $hi = 0$，则不存在 $\le q$ 的元素；若 $hi > 0$，则 $a[hi-1]$ 是 $\le q$ 的元素中的最大值。

**证明**：$hi = 0$ 时 $a[0] > q$，而 $a[0]$ 是最小值，故全体 $> q$，mini 无解，返 $-1$ 正确。$hi > 0$ 时：下标 $hi-1 < hi$ 说明 $a[hi-1] \le q$（否则 $hi-1$ 也满足 $a[j] > q$，与 $hi$ 最小性矛盾）；对 $j \ge hi$ 有 $a[j] \ge a[hi] > q$，对 $j < hi-1$ 有 $a[j] < a[hi-1]$。故 $\le q$ 的元素恰为前缀 $a[0..hi-1]$，最大者是 $a[hi-1]$。∎

**引理 3（ceiling 刻画）**：设 $lo = \min\{j : a[j] \ge q\}$（不存在则 $lo = n$，即 `lower_bound`）。若 $lo = n$，则不存在 $\ge q$ 的元素；若 $lo < n$，则 $a[lo]$ 是 $\ge q$ 的元素中的最小值。

**证明**：由严格递增，若 $a[j] \ge q$ 且 $j < k$，则 $a[k] > a[j] \ge q$，故 $\{j : a[j] \ge q\}$ 是一段后缀，$lo$ 是其起点。$lo = n$ 即后缀为空，全体 $< q$，maxi 无解，返 $-1$ 正确。$lo < n$ 时：$a[lo] \ge q$；对 $j < lo$ 由最小性 $a[j] < q$；对 $j > lo$ 有 $a[j] > a[lo] \ge q$。故 $\ge q$ 的元素恰为后缀 $a[lo..n-1]$，最小者是 $a[lo]$。∎

**定理（算法正确性）**：算法对每个查询 $q$ 输出的 $[\text{mini}, \text{maxi}]$ 恰为题目要求的二元组。

**证明**：由引理 1，中序收集的 $a$ 是全体节点值的严格递增排列，查询被化为有序数组上的 floor/ceiling 问题。对每个 $q$：算法的 `maxi` 分支即引理 3 的刻画（$lo = \text{lower\_bound}(q)$，判 $lo < n$），`mini` 分支即引理 2 的刻画（$hi = \text{upper\_bound}(q)$，判 $hi > 0$），两分支的「无解返 $-1$」与题目约定逐一对应。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m\log n)$。中序摊平单趟 $O(n)$；每个查询两次二分各 $O(\log n)$，共 $m$ 个查询。
- **空间复杂度**：$O(n)$。有序数组 $a$ 占 $O(n)$；迭代中序的显式栈最坏 $O(h)$（链状树即 $O(n)$）。不计输出的 `answer` 数组 $O(m)$。
- **对照**：暴力全扫 $O(nm)$；顺树搜索 $O(mh)$ 树形敏感（链状退化为 $O(nm)$）；值域预处理 $O(V + n)$ + 单查询 $O(1)$（$V = 10^6$ 可行但对本题 $\log n \approx 17$ 是杀鸡用牛刀）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> closestNodes(TreeNode* root, vector<int>& queries) {
        vector<int> a;
        a.reserve(100000);
        stack<TreeNode*> st;                 // 迭代中序：防链状树递归爆栈
        TreeNode* cur = root;
        while (cur || !st.empty()) {
            while (cur) { st.push(cur); cur = cur->left; }
            cur = st.top(); st.pop();
            a.push_back(cur->val);           // 左 → 根 → 右
            cur = cur->right;
        }
        int n = (int)a.size();
        vector<vector<int>> answer;
        answer.reserve(queries.size());
        for (int q : queries) {
            int lo = lower_bound(a.begin(), a.end(), q) - a.begin();  // 首个 >= q
            int hi = upper_bound(a.begin(), a.end(), q) - a.begin();  // 首个 >  q
            int mini = hi > 0 ? a[hi - 1] : -1;                       // floor
            int maxi = lo < n ? a[lo] : -1;                           // ceiling
            answer.push_back({mini, maxi});
        }
        return answer;
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right

class Solution:
    def closestNodes(self, root: Optional[TreeNode], queries: List[int]) -> List[List[int]]:
        a = []
        stack, cur = [], root
        while cur or stack:                  # 迭代中序：防链状树爆递归栈
            while cur:
                stack.append(cur)
                cur = cur.left
            cur = stack.pop()
            a.append(cur.val)                # 左 → 根 → 右
            cur = cur.right

        n = len(a)
        answer = []
        for q in queries:
            lo = bisect_left(a, q)           # 首个 >= q
            hi = bisect_right(a, q)          # 首个 >  q
            mini = a[hi - 1] if hi > 0 else -1   # floor
            maxi = a[lo] if lo < n else -1       # ceiling
            answer.append([mini, maxi])
        return answer
```

## 8. 边界情况与易错点

1. **`[mini, maxi]` 的顺序**：题目要求**先 mini 后 maxi**。顺手按思维顺序写 `[maxi, mini]` 是读题不细的高频 WA。
2. **mini 用 `upper_bound − 1`，不是 `lower_bound − 1`**：$q$ 命中元素时后者会漏掉命中值（见 §4 第 2 点），命中与落空隙两分支必须逻辑统一。
3. **两个越界独立**：`hi == 0`（$q$ 小于全体）只影响 `mini`；`lo == n`（$q$ 大于全体）只影响 `maxi`。示例 1 的 `q=16` 与示例 2 的 `q=3` 各只触发一侧，别把两个边界混成一个特判。
4. **递归深度陷阱**：链状树 $n = 10^5$，Python 默认上限 1000 必炸 `RecursionError`，C++ 深递归同样有爆栈风险——**直接写迭代中序**，一劳永逸。
5. **`-1` 哨兵合法**：因为题目值域 $1 \le \text{Node.val} \le 10^6$，`-1` 不会与真值混淆。
6. **不要再 `sort`**：中序序列已严格递增；排序既浪费 $O(n\log n)$，也暴露「没想透 BST 性质」。
7. **顺树搜索的隐性 TLE**：本地随机数据全过、提交被链状树卡死，是本题最阴的坑（见 §3.1）；摊平写法对树形完全免疫。
8. **自构造验证建议**：提交前脑内跑一遍「$q$ 小于全体 / 大于全体 / 恰命中 / 落空隙」四类，配合 $n=2$ 的最小树。
