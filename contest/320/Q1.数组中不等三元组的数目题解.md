# LeetCode 数组中不等三元组的数目 题解

## 1. 题目概述

- **标题 / 题号**：数组中不等三元组的数目（#2475，easy）
- **链接**：https://leetcode.cn/problems/number-of-unequal-triplets-in-array/
- **来源**：LeetCode 第 320 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序

**题意**：给定下标从 0 开始的正整数数组 `nums`，统计满足 `0 <= i < j < k < n` 且 `nums[i]`、`nums[j]`、`nums[k]` **两两不同**的三元组 `(i, j, k)` 的数目。

**约束**：

- `3 <= nums.length <= 100`
- `1 <= nums[i] <= 1000`

## 2. 示例

**示例 1**

```text
输入：nums = [4,4,2,4,3]
输出：3
解释：满足条件的三元组：
  (0, 2, 4) → (4, 2, 3)
  (1, 2, 4) → (4, 2, 3)
  (2, 3, 4) → (2, 4, 3)
注意 (2, 0, 4) 不是合法三元组，因为要求 i < j < k。
```

**示例 2**

```text
输入：nums = [1,1,1,1,1]
输出：0
解释：所有元素相同，不存在两两不同的三元组。
```

**示例 3**（自构造）

```text
输入：nums = [1,2,3]
输出：1
解释：n=3 且三值互异，唯一三元组 (0,1,2) 合法。
```

## 3. 解题思路

### 3.1 暴力思路

三重循环枚举 `(i, j, k)`，检查三个值两两不同。`n <= 100` 时最多 `C(100,3) ≈ 1.6×10^5` 次判断，比赛时直接交即可过。但数据范围明显留了优化空间，值得想清楚 `O(n)` 的数法。

### 3.2 核心观察：条件只与「值」有关，按值分组计数

![按值分组：left × c × right](images/unequal_triplets_group_model.svg)

关键 **insight**：「两两不同」只约束**值**，不约束下标顺序。而每个下标集合 `{i, j, k}` 恰好对应一个有序的 `i < j < k`，所以：

> 答案 = 从三个**不同值组**中各选一个元素的方案数。

把数组按值分成 `m` 组（组大小 `c_1, …, c_m`），固定一个组的处理顺序，逐组扫描时维护：

- `left`：已处理组的元素总数
- `right = n - left - c`：未处理组的元素总数

当前组（大小 `c`）对答案的贡献为 `left × c × right` —— 它枚举的正是「当前组的值排在中间」的所有合法三元组。

### 3.3 算法流程

1. 用哈希表统计每个值的出现次数；
2. `left = 0, ans = 0`，逐组处理每个值组 `c`：
   - `ans += left * c * (n - left - c)`
   - `left += c`
3. 返回 `ans`。

分组顺序（哈希表迭代序、排序后的值序均可）不影响正确性，只要在单次扫描中**固定不变**。

### 3.4 示例演算

![示例演算：10 个三元组逐一判定](images/unequal_triplets_walkthrough.svg)

`nums = [4,4,2,4,3]`，分组为 `值4×3、值2×1、值3×1`：

| 处理组 | left | c | right | 贡献 |
|--------|------|---|-------|------|
| 值 4 | 0 | 3 | 2 | 0×3×2 = 0 |
| 值 2 | 3 | 1 | 1 | 3×1×1 = 3 |
| 值 3 | 4 | 1 | 0 | 4×1×0 = 0 |

`ans = 0 + 3 + 0 = 3` ✓（三个合法三元组 `(0,2,4)`、`(1,2,4)`、`(2,3,4)` 全部在「值 2 作中间值」时被计入）

## 4. 算法细节

1. **分组顺序任意**：哈希表迭代顺序、排序后顺序都能用，证明只要求顺序固定（见 §5 引理 2）。
2. **`left × c × right` 的含义**：从「左侧组」「当前组」「右侧组」各选一个元素的三元组数，三个区域互斥保证不重不漏。
3. **补集公式（等价解法）**：
   $$ans = \binom{n}{3} - \sum_{v}\left[\binom{c_v}{2}(n - c_v) + \binom{c_v}{3}\right]$$
   其中「坏三元组」（至少有两个值相同）按出现值 `v` 分类是互斥的——3 个位置装不下两组"至少两个同值"。
4. **值域小**：`1 <= nums[i] <= 1000`，可用长度 1001 的数组代替哈希表。

## 5. 正确性证明

**引理 1**：合法三元组与「元素来自三个不同值组的 3 元素下标集合」一一对应。

**证明**：`i < j < k` 的排序唯一，故有序三元组与无序下标集合是双射；三值两两不同当且仅当三个下标分属三个不同值组。∎

**引理 2**：固定组顺序后，任一合法三元组恰在一个「当前组」处被计数。

**证明**：设合法三元组的三个值组按固定顺序为 `p < q < r`。仅在处理 `q` 时，它的三个元素分别落在 left 区（组 `p`）、当前组 `q`、right 区（组 `r`），从而被乘积 `left × c_q × right` 包含。处理其它任何组 `g` 时：若 `g < p` 或 `g > r`，三元组三个元素都落在同一侧，无法同时横跨三区；若 `g = p`（或 `r`），只有组 `p` 在当前区、组 `q`、`r` 都在 right 区，同样无法横跨。故恰被计数一次。∎

**定理**：算法返回值等于合法三元组总数。

**证明**：由引理 1，答案即「三元素分属三个不同组」的下标集合总数。`left × c × right` 精确计数「一个元素来自已处理组、一个来自当前组、一个来自未处理组」的下标集合（三区互斥，每个集合至多一种划分）；任何此类集合的三元素必分属三个不同组，为合法三元组。反之由引理 2，每个合法三元组恰被某个当前组计入一次。求和后两者相等。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n)`。一次哈希计数遍历数组，再遍历全部值组（组数 `m <= n`）；若改用值域数组，则为 `O(n + V)`，`V = 1000`。
- **空间复杂度**：`O(n)`。哈希表最多存 `n` 个不同值；改用 `cnt[1001]` 则为 `O(V)`。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int unequalTriplets(vector<int>& nums) {
        int n = nums.size();
        unordered_map<int, int> cnt;
        for (int x : nums) cnt[x]++;
        int ans = 0, left = 0;
        for (auto& [v, c] : cnt) {
            ans += left * c * (n - left - c);
            left += c;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def unequalTriplets(self, nums: list[int]) -> int:
        n = len(nums)
        cnt = Counter(nums)
        ans = left = 0
        for c in cnt.values():
            ans += left * c * (n - left - c)
            left += c
        return ans
```

## 8. 边界情况与易错点

1. **全部相同**：如 `[1,1,1,1,1]`，每个当前组的 `left` 或 `right` 至少一边无贡献，返回 0。
2. **全部不同**：答案为 $\binom{n}{3}$；最小规模 `n = 3` 时答案为 1。
3. **不要乘 6**：`i < j < k` 已固定下标顺序，统计的是无序下标集合；按「有序值排列」多乘 `3!` 是常见手误。
4. **无溢出风险**：`n <= 100`，`ans <= C(100,3) = 161700`，`int` 足够。
5. **暴力也过**：`O(n^3)` 在本题范围可行，但 `O(n)` 写法在 `n` 放大到 `10^5` 时依然稳，是更值得沉淀的模板。
