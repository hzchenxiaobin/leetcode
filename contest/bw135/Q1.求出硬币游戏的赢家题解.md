# LeetCode 求出硬币游戏的赢家 题解

## 1. 题目概述

- **标题 / 题号**：求出硬币游戏的赢家（#3222，easy）
- **链接**：https://leetcode.cn/problems/find-the-winning-player-in-coin-game/
- **来源**：LeetCode 第 135 场双周赛 Q1
- **难度**：简单
- **标签**：数学、博弈、模拟

**题意**：桌上有 $x$ 枚面值 $75$ 的硬币和 $y$ 枚面值 $10$ 的硬币。Alice 与 Bob 轮流操作，Alice 先手；每一轮当前玩家必须取走**若干枚硬币，面值总和恰好为 $115$**。取不出来的人输。两人都采取最优策略，求赢家。

这道"博弈"题的关键不是策略，而是**唯一分解**：$115 = 75 \times 1 + 10 \times 4$，所以每轮能取的东西是固定的，双方**都没有任何选择余地**，游戏进程被完全确定，胜负只由可执行的轮数奇偶决定。

**约束**：

- $1 \le x \le 100$
- $1 \le y \le 100$

规模极小，$\min(x, \lfloor y/4 \rfloor)$ 直接算即可，不存在溢出或性能问题。

## 2. 示例

**示例 1**

```text
输入：x = 2, y = 7
输出："Alice"
解释：Alice 取走 1 枚 75 与 4 枚 10，总和 115；还剩 x = 1, y = 3。
      Bob 凑不出 115（缺 10 元硬币）→ Bob 输，Alice 胜。
```

**示例 2**

```text
输入：x = 4, y = 11
输出："Bob"
解释：Alice 取 (1, 4)，Bob 取 (1, 4)；此后 x = 2, y = 3，Alice 凑不出 115 → Alice 输。
```

**示例 3（边界补充）**

```text
输入：x = 1, y = 4
输出："Alice"
解释：只有 1 轮可走，Alice 走完 Bob 无币可取。

输入：x = 1, y = 3
输出："Bob"
解释：0 轮可走，先手 Alice 直接输。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是模拟：每轮枚举"取 $a$ 枚 75、取 $b$ 枚 10"的所有组合，用 DFS 判断当前玩家能否必胜。但把枚举写出来就会发现——满足 $75a + 10b = 115$ 的 $(a, b)$ **只有一个**，DFS 的每个节点都只有一条分支，所谓"最优策略"根本无从发挥。于是暴力退化为"数轮数"，$O(1)$ 即可。

### 3.2 核心观察：$115$ 的唯一分解

![115 的唯一分解：1 枚 75 加 4 枚 10](images/bw135_q1_unique_decomp.svg)

把方程 $75a + 10b = 115$ 两边除以 $5$，得

$$15a + 2b = 23, \qquad a, b \ge 0 \text{ 为整数}$$

逐一检验 $a$：$a = 1 \Rightarrow b = 4$；$a \ge 2 \Rightarrow 15a \ge 30 > 23$；$a = 0 \Rightarrow 2b = 23$ 无整数解。**解唯一**。

这意味着：

- 每轮**必然**消耗 1 枚 75 和 4 枚 10，双方无法"多取"或"少取"；
- 只要 $x \ge 1$ 且 $y \ge 4$，当前玩家就一定能操作；
- 于是整局游戏能进行的轮数是常量 $T = \min(x, \lfloor y/4 \rfloor)$，与策略无关。

> ⚠️ 常见错误直觉：用总价值 $75x + 10y \ge 115$ 判断能否继续。面值固定、必须凑出 1 枚 75，所以总价值够并不代表能操作——例如 $x = 0,\ y = 12$ 总价值 $120 > 115$，却一步也走不了。

### 3.3 算法流程

![轮数奇偶决定胜负](images/bw135_q1_turns_parity.svg)

```text
1. T = min(x, y / 4)              # 整数除法，向下取整
2. 若 T 为奇数 → 返回 "Alice"
3. 否则        → 返回 "Bob"
```

胜负判定的语义要捋清楚：输的人是**"轮到他却无法操作"**的那个人。

- $T$ 为奇数：第 $1, 3, \dots, T$ 轮都由 Alice 执行，走完第 $T$ 轮后轮到 Bob，他无币可取 → **Bob 输，Alice 胜**。
- $T$ 为偶数：最后一轮由 Bob 执行，之后 Alice 无币可取 → **Alice 输，Bob 胜**。$T = 0$（先手立即无法操作）也落在这一类。

### 3.4 示例演算

![示例演算：四组输入的计算过程](images/bw135_q1_example_walkthrough.svg)

| $x$ | $y$ | $\lfloor y/4 \rfloor$ | $T = \min$ | $T$ 奇偶 | 赢家 |
|-----|-----|----------------------|-----------|---------|------|
| 2 | 7 | 1 | 1 | 奇 | Alice |
| 4 | 11 | 2 | 2 | 偶 | Bob |
| 1 | 4 | 1 | 1 | 奇 | Alice |
| 1 | 3 | 0 | 0 | 偶 | Bob |

以 $x = 4, y = 11$ 为例：$T = \min(4, 2) = 2$，两轮后剩下 $x = 2, y = 3$；第三轮轮到 Alice，$y = 3 < 4$，无法操作，Bob 胜。

## 4. 算法细节

1. **整数除法**：`y / 4` 在 C++ 与 Python 中对非负整数都是向下取整，直接用；不要写 `ceil` 或浮点除法。
2. **不要真的模拟**：虽然 $T \le 25$（$y \le 100$），循环也对，但公式一步到位更符合"看清结构"的意图，也避免把胜负判定写反。
3. **奇偶判断**：`T % 2 == 1` 与 `T & 1` 等价；注意 $T = 0$ 必须归入"Bob 胜"。
4. **返回值是字符串**：`"Alice"` / `"Bob"`，大小写与题面一致（LeetCode 对字符串返回值区分大小写）。
5. **无需考虑"取 2 枚 75 后找回零钱"**：题目只允许"取走"，不能把硬币放回或拆分，故不存在其它组合。

## 5. 正确性证明

**引理 1（操作唯一性）**：任何一次合法操作恰好取走 1 枚面值 75 的硬币和 4 枚面值 10 的硬币。

**证明**：设一次操作取 $a$ 枚 75、$b$ 枚 10，其中 $a, b$ 为非负整数，则 $75a + 10b = 115$。两边除以 5 得 $15a + 2b = 23$。若 $a = 0$，则 $2b = 23$，左边为偶数、右边为奇数，无解；若 $a = 1$，则 $b = 4$，是解；若 $a \ge 2$，则 $15a \ge 30 > 23$，无解。故 $(a, b) = (1, 4)$ 是唯一解。∎

**引理 2（轮数恒定）**：游戏能进行的轮数恒为 $T = \min(x, \lfloor y/4 \rfloor)$，且与双方的策略无关。

**证明**：由引理 1，每轮必然把状态 $(x, y)$ 变为 $(x - 1, y - 4)$，故任何一方都无法改变消耗速率，也无法"提前"或"延后"耗尽资源。当前玩家能操作当且仅当 $x \ge 1$ 且 $y \ge 4$，即 $x \ge 1$ 且 $y/4 \ge 1$。因此游戏在第 $T$ 轮之后恰好无法继续，其中 $T$ 是满足"经过 $T$ 轮后 $x - T \ge 0$ 且 $y - 4T \ge 0$"的最大整数，即 $T = \min(x, \lfloor y/4 \rfloor)$。∎

**定理**：$T$ 为奇数时 Alice 必胜，$T$ 为偶数时 Bob 必胜。

**证明**：由引理 2，游戏恰进行 $T$ 轮，且第 $k$ 轮由 Alice 执行（$k$ 奇）或 Bob 执行（$k$ 偶）。第 $T$ 轮结束后资源不满足操作条件，轮到下一名玩家时他无法操作，按规则判负，故赢家是**执行了第 $T$ 轮的人**。$T$ 为奇数时此人是 Alice，$T$ 为偶数时此人是 Bob。特别地 $T = 0$ 时无人执行任何轮，先手 Alice 立即无法操作，判 Bob 胜，与"偶数 → Bob"一致。∎

## 6. 复杂度分析

- **时间**：$O(1)$。一次整数除法、一次取最小值、一次奇偶判断。
- **空间**：$O(1)$。只用了几个整型临时变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string winningPlayer(int x, int y) {
        int turns = min(x, y / 4);          // 每轮消耗 1 枚 75 与 4 枚 10
        return turns % 2 == 1 ? "Alice" : "Bob";
    }
};
```

### Python

```python
class Solution:
    def winningPlayer(self, x: int, y: int) -> str:
        turns = min(x, y // 4)          # 每轮消耗 1 枚 75 与 4 枚 10
        return "Alice" if turns % 2 == 1 else "Bob"
```

> 💡 两份代码均通过官方示例（`"Alice"`、`"Bob"`）与边界用例 $(x, y) = (1, 4)$、$(1, 3)$，并与逐轮模拟在 $1 \le x, y \le 100$ 上的 300 组随机输入对拍一致（`mismatch = 0`）。

## 8. 边界情况与易错点

1. **$y < 4$**：$T = 0$，先手直接输，答案必须是 `"Bob"`。若把胜负写反成"$T$ 偶 → Alice"，这一条会立刻暴露。
2. **$x = 0$ 虽然不在数据范围**（$x \ge 1$），但思路要能自洽：$x = 0$ 时 $T = 0$，同样是 Bob 胜。
3. **不要用总价值判定**：$75x + 10y \ge 115$ 只是必要条件，不是充分条件；必须凑出整枚 75。
4. **整数除法的方向**：`y / 4` 是向下取整，正好是"能凑出几组 4 枚 10"。若误用 `ceil(y / 4.0)` 会把不足 4 枚的情况算成一轮。
5. **不要漏掉"取走"的语义**：硬币取出后不归还，所以轮数上限是 $\min$ 而不是"每轮重新判断总额"。
6. **字符串拼写**：返回 `"Alice"`、`"Bob"`，不是 `"alice"`，也不要返回 `"Alice "`（带空格）——LeetCode 对返回值做精确比较。
