# LeetCode 分糖果 II 题解

## 1. 题目概述

- **标题 / 题号**：分糖果 II（#1103，easy）
- **链接**：https://leetcode.cn/problems/distribute-candies-to-people/
- **来源**：LeetCode 第 143 场周赛 Q1
- **难度**：简单
- **标签**：数学、模拟

**题意**：`num_people` 个小朋友排成一队，从队首开始发糖：第 $k$ 次发 $k$ 颗（$k=1,2,3,\dots$），发给第 $(k-1)\bmod n$ 个小朋友；发完一个轮回就回到队首，而礼物数**继续递增**（第 $n+1$ 次发 $n+1$ 颗）。糖果发完即止；最后一份若剩余 $r$ 不足应发的 $k$ 颗，就把 $r$ 颗全部给当前小朋友。返回长度为 $n$、元素和为 `candies` 的数组。

**约束**：

- $1 \le \text{candies} \le 10^9$
- $1 \le \text{num\_people} \le 1000$
- 输出数组长度为 $n$，且 $\sum_i \text{ans}[i] = \text{candies}$

> 💡 题面没有注入类噪声指令，可直接按原意实现。真正的考点是：$10^9$ 颗糖不能逐颗发，但**按「次」结算**只需要约 $4.5\times10^4$ 次迭代。

解释：

  第 2 次：ans[1] += 2 → [1,2,0,0]
  第 3 次：ans[2] += 3 → [1,2,3,0]

```

  第 4 次：ans[0] += 4（恰好发完，回到队首）→ [5,2,3]
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是「逐颗发」：维护当前应发数量 $k$，每发一颗就把 $k$ 减 1，减到 0 再让 $k$ 加 1 并换人。这个模拟完全正确，但步数等于糖果总数——$\text{candies}$ 最大 $10^9$，循环 $10^9$ 次在 Python 里要十几秒、C++ 也接近超时边缘，且毫无必要。

另一种「假优化」是把外层循环写成「发 $k$ 颗」但内层仍用 `for j in range(k)` 一颗颗加，总步数依旧是 $O(\text{candies})$，同样过不了。突破口只能是：**一次操作处理一整个份额**。

### 3.2 核心观察：按「次」结算的计数器模型

![第 k 次发 k 颗，收糖人是 (k−1) mod n](images/wc143_q1_turn_index.svg)

题目看似有「第几轮」和「第几个人」两个维度，其实二者被同一个计数器 $k$ 完全决定：

- **发几颗**：第 $k$ 次就是 $k$ 颗，与轮次无关；
- **发给谁**：第 $k$ 次给第 $(k-1)\bmod n$ 个人，也与轮次无关。

于是「轮」这个概念可以直接删掉，状态只剩「剩余糖果 $c$」与「计数器 $k$」两个量，每步做常数工作：

$$d=\min(k,\ c),\qquad \text{ans}[(k-1)\bmod n]\mathrel{+}=d,\qquad c\mathrel{-}=d,\qquad k\mathrel{+}=1$$

**为什么这样就够快**：第 $k$ 次发完后累计发出 $T(k)=k(k+1)/2$ 颗，当 $T(k)\ge \text{candies}$ 时分配必然已经结束，所以总次数满足

$$t \le \left\lceil \frac{\sqrt{8\,\text{candies}+1}-1}{2}\right\rceil$$

代入 $10^9$ 得 $t\le 44721$，与 $n$ 无关。$4.5\times10^4$ 次 $O(1)$ 操作，任何语言都是毫秒级。这个「总和是二次函数 ⇒ 次数是根号级」的观察，是本题唯一的分水岭。

### 3.3 算法流程

![按「次」结算的模拟流程](images/wc143_q1_sim_flow.svg)

```text
1. ans = [0] * num_people，k = 1，i = 0
2. 当 candies > 0 时循环：
       d = min(k, candies)          # 不够一整份就全给，截断只可能发生在最后一趟
       ans[i] += d
       candies -= d
       i = (i + 1) % num_people     # 换到下一个人；等价于人号 (k−1) mod n
       k += 1
3. 返回 ans
```

其中 `i` 与 `k` 同步递增：进入第 $k$ 次时 `i` 恰等于 $(k-1)\bmod n$，这是循环不变量；用增量取模比每次重算少一次取模，也避免了下标与 $k$ 的差一错误。

### 3.4 示例演算

![两个官方示例的逐次走查](images/wc143_q1_walkthrough.svg)

先看示例 1（`candies = 7`，$n=4$）：$T(3)=6<7\le T(4)=10$，所以一共发 4 次，且第 4 次只剩 $7-6=1$ 颗 —— 应发 4 颗、实发 $\min(4,1)=1$ 颗。

| 第 k 次 | 应发 | 实发 | 剩余 candies | ans |
|---|---|---|---|---|
| 1 | 1 | 1 → 小朋友 0 | 6 | [1,0,0,0] |
| 2 | 2 | 2 → 小朋友 1 | 4 | [1,2,0,0] |
| 3 | 3 | 3 → 小朋友 2 | 1 | [1,2,3,0] |
| 4 | 4 | min(4,1)=1 → 小朋友 3 | 0 | [1,2,3,1] |

再看示例 2（`candies = 10`，$n=3$）：$T(4)=10$ 恰好等于 `candies`，所以第 4 次发**满** 4 颗就结束，不需要截断；第 4 次的人号是 $(4-1)\bmod 3=0$，正好绕回队首，于是 $\text{ans}[0]$ 变成 $1+4=5$。

极值感受一下：`candies = 10^9` 时 $T(44720)=999961560$，第 $44721$ 次只剩 $38440$ 颗，应发 $44721$ 颗却只发得出 $38440$ 颗，落在 $(44720)\bmod 1000=720$ 号小朋友身上。

## 4. 算法细节

1. **用 `min` 吸收收尾**：`d = min(k, candies)` 一行同时表达「够就发一份」「不够就全给」，比赛时不必为最后一趟写任何 if 分支，也就没机会写错。
2. **人号别错位**：第 $k$ 次（$k$ 从 1 开始）给 $(k-1)\bmod n$。若改用 0-based 计数器 `i` 从 0 开始并每次 `i = (i+1) % n`，两种写法等价；但把 1-based 的 $k$ 直接拿去取模 `k % n` 会整体后移一人。
3. **循环条件是 `candies > 0`**：不要写 `candies >= k`（最后不足时会漏发），也不要写 `candies >= 0`——那样在 `candies == 0` 时会算出 `d = 0`，`candies` 不再变化，直接死循环。
4. **不变量**：每一趟结束后 $\sum_i \text{ans}[i] = \text{candies}_0 - \text{candies}$。它既是正确性证明的骨架，也是调试时最好用的断言。
5. **溢出分析**：单个 $\text{ans}[i]$ 的上界是 $\text{candies}$（$\le 10^9$），$\sum_i \text{ans}[i] = \text{candies}$ 也 $\le 10^9$，二者都在 32 位 `int` 范围内，所以 C++ 用 `int` 是安全的；$k$ 最大只到 $44721$。但若把题目上限改成 $10^{18}$，累加就必须换 `long long`。
6. **次数上界可以提前算**：$t=\left\lceil(\sqrt{8\,\text{candies}+1}-1)/2\right\rceil$ 可用于预分配或剪枝，但本题不需要，写进循环条件反而容易在浮点开方上翻车。
7. **数学 $O(n)$ 变体的思路**：完整轮可以闭式求和（见文末延伸），余下不足一轮再模拟；当 `candies` 达到 $10^{18}$ 时，$t\approx1.4\times10^9$ 的模拟已经不可接受，必须换闭式。

## 5. 正确性证明

**引理 1（不变量）**：循环的每一趟开始前，$\sum_i \text{ans}[i] = \text{candies}_0 - \text{candies}$，且 `k` 等于「这是第几次发放」。

**证明**：初始时 `ans` 全 0、$\text{candies} = \text{candies}_0$，等式成立且 $k=1$。设某趟开始前成立，该趟只把 $d$ 从 `candies` 移入 `ans[i]`，所以总和变为 $\text{candies}_0 - (\text{candies}-d)$，与新的剩余一致；随后 `k` 自增 1，仍等于下一次的序号。∎

**引理 2（单趟语义正确）**：设某趟开始时剩余 $c>0$、序号为 $k$，则该趟实发的 $d=\min(k,c)$ 颗与题目要求完全一致。

**证明**：若 $c\ge k$，题目要求发满 $k$ 颗，$d=k$ 符合；若 $c<k$，题目要求「剩下的糖果全部发给当前的小朋友」，$d=c$ 符合，且此时 $c-d=0$，循环随即终止，与「发完即止」一致。∎

**引理 3（人号正确）**：第 $k$ 次发放的收糖人是 $(k-1)\bmod n$。

**证明**：第 1 次给第 0 人；每次发完换到下一位，下标 $(i+1)\bmod n$ 循环，故第 $k$ 次的下标为 $(k-1)\bmod n$（对 $k$ 归纳即得）。∎

**定理**：算法在有限步内终止，且返回的 `ans` 恰好是题目要求的分发结果。

**证明**：终止性——每趟 `candies` 减去 $d=\min(k,c)\ge 1$（因 $c>0$ 且 $k\ge1$），严格单调递减且下界为 0，故至多 $\text{candies}$ 趟后停止，实际趟数由引理 2 的 $T(k)$ 界更紧地约束为 $O(\sqrt{\text{candies}})$。正确性——由引理 1，全部糖果都被且只被发出一次，最终 $\sum_i\text{ans}[i]=\text{candies}_0$；由引理 2，每一趟发出的颗数与该趟应发/实发一致；由引理 3，每一趟都记在正确的小朋友名下。三者合起来说明 `ans` 与题目定义的最终分发情况逐项相等。∎

## 6. 复杂度分析

- **时间**：$O(t)$，其中 $t$ 是发放总次数，满足 $t(t+1)/2\ge \text{candies}$，即 $t=O(\sqrt{\text{candies}})$，最坏约 $44721$ 次；每次迭代只做一次 `min` 比较、一次加法、一次减法、一次取模，故总时间 $O(\sqrt{\text{candies}})$，与 $n$ 无关。
- **空间**：$O(n)$ 用于返回的答案数组（$n\le1000$）；除此之外只有 `k`、`i`、`d` 三个标量，额外空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> distributeCandies(int candies, int num_people) {
        vector<int> ans(num_people, 0);
        int k = 1;   // 第 k 次发放，应发 k 颗
        int i = 0;   // 本次收糖的小朋友下标 = (k-1) % num_people
        while (candies > 0) {
            int d = min(k, candies);       // 不够一整份就把剩下的全给
            ans[i] += d;
            candies -= d;
            i = (i + 1) % num_people;      // 换到下一位，到队尾自动归队
            ++k;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def distributeCandies(self, candies: int, num_people: int) -> list[int]:
        ans = [0] * num_people
        k = 1          # 第 k 次发放，应发 k 颗
        i = 0          # 本次收糖的小朋友下标 = (k-1) % num_people
        while candies > 0:
            d = min(k, candies)        # 不够一整份就把剩下的全给
            ans[i] += d
            candies -= d
            i = (i + 1) % num_people   # 换到下一位，到队尾自动归队
            k += 1
        return ans
```

## 8. 边界情况与易错点

1. **`num_people == 1`**：所有人都是同一个人，答案恒为 `[candies]`。代码不特判也正确，因为 `i` 永远取模回 0；但若手写「换人」的 if 分支就容易漏掉这种情况。
2. **最后一趟不足一整份**：`d = min(k, candies)` 之后 `candies` 归零，循环必须立刻退出；如果写成 `for k in range(...)` 固定次数或忘了判断，就会把后面的份额也发出去（甚至发成负数）。
3. **循环条件写成 `candies >= 0`**：`candies == 0` 时 `d = 0`，`candies` 不变、`k` 疯长，直接死循环——这是本题最常见的 WA/TLE 原因。
4. **人号差一**：1-based 的 $k$ 必须映射到 $(k-1)\bmod n$；写成 $k\bmod n$ 会让所有糖果整体错后一位，示例 1 会得到 [1,1,2,3]（第 4 次被错误地发给 0 号位）。
5. **`candies` 很小、$n$ 很大**：例如 `candies = 2, n = 1000`，答案是 `[1,1,0,...]`，数组长度仍必须是 $n$，不能按「实际被发到的人」截断。
6. **别真的逐颗发**：`for _ in range(candies)` 在 `candies = 10^9` 时必超时；同理 `ans[i] += 1` 循环 $k$ 次也是 $O(\text{candies})$。
7. **C++ 的 `min` 类型**：若一个操作数是 `long long` 另一个是 `int`，`std::min` 会编译失败（模板参数推导冲突），统一用 `int` 或补 `min<long long>`。

**延伸思考**：本题可以做到 $O(n)$ 与「糖果数无关」。设 $t$ 为满足 $t(t+1)/2\le \text{candies}$ 的最大整数，$m=\lfloor t/n\rfloor$ 是完整轮数，则第 $p$ 位小朋友（0-based）在前 $m$ 轮共得

$$\sum_{j=0}^{m-1}\bigl(p+1+jn\bigr)=m(p+1)+\frac{n\,m(m-1)}{2}$$

余下 $\text{candies}-\frac{nm(nm+1)}{2}$ 颗从第 $nm+1$ 次开始，不足一轮、直接模拟即可。这样当 `candies` 放大到 $10^{18}$（此时模拟需要 $1.4\times10^9$ 趟）仍然瞬间出解。再进一步，若礼物数改成等差数列 $a, a+c, a+2c,\dots$，累计和变成二次函数 $ak+ck(k-1)/2$，同一套「先解二次不等式定轮数、再处理残局」的框架照样适用——这正是本题最值得带走的模板。
