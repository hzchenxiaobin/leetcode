# LeetCode 解析布尔表达式 题解

## 1. 题目概述

- **标题 / 题号**：解析布尔表达式（#1106，hard）
- **链接**：https://leetcode.cn/problems/parsing-a-boolean-expression/
- **来源**：LeetCode 第 143 场周赛 Q4
- **难度**：困难
- **标签**：栈、递归、字符串

**题意**：给定一个合法布尔表达式字符串，求它的真值。表达式只有这几种形态：

1. `'t'` → true，`'f'` → false；
2. `!(subExpr)` → 对子式取**逻辑非**；
3. `&(subExpr1, subExpr2, ..., subExprk)` → 对 $k \ge 1$ 个子式取**逻辑与**；
4. `|(subExpr1, subExpr2, ..., subExprk)` → 对 $k \ge 1$ 个子式取**逻辑或**。

即**运算符写在括号前面**（前缀形式），逗号在同一层内分隔子式，括号可以任意嵌套。

**约束**：

- $1 \le \lvert \text{expression} \rvert \le 2 \times 10^4$
- `expression[i]` 只会是 `(`、`)`、`&`、`|`、`!`、`t`、`f`、`,` 之一
- 输入保证是合法表达式：`!` 后恰好一个 `(`，`&`、`|` 后至少一个子式

## 2. 示例

**示例 1**

```text
输入：expression = "&(|(f))"
输出：false
解释：先算 |(f) --> f 得 "&(f)"，再算 &(f) --> f 得 "f"，最终返回 false。
```

**示例 2**

```text
输入：expression = "|(f,f,f,t)"
输出：true
解释：false OR false OR false OR true = true。
```

**示例 3**

```text
输入：expression = "!(&(f,t))"
输出：true
解释：先算 &(f,t) --> false，式子变为 "!(f)"；
      再算 !(f) --> NOT false = true。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**反复求值最内层括号**：扫描找到最内层的一对 `(`、`)`，把里面的内容按逗号切开，算出 `t` 或 `f`，再用这一个字符替换掉 `运算符 + (...)` 整段；重复直到整个串只剩下一个字符。

正确性是显然的（就是题面「先算内层」的直接转写），但每一轮都要重新扫描并**重建字符串**，嵌套层数最多 $O(n)$ 层，总代价 $O(n^2)$：$n = 2\times10^4$ 时约 $3\times10^8$ 次字符搬运，Python 必然超时。递归下降若每层都**切片**传子串，复制量同样是 $O(n^2)$，而且嵌套深度可达 $n/3 \approx 6666$ 层，超过 Python 默认递归上限 1000。

### 3.2 核心观察：括号嵌套 = 一棵隐式语法树

![括号嵌套就是一棵语法树](images/wc143_q4_syntax_tree.svg)

把文法写出来就很清楚：

```text
E := 't' | 'f'
   | '!' '(' E ')'
   | '&' '(' E (',' E)* ')'
   | '|' '(' E (',' E)* ')'
```

表达式本质上是一棵**语法树**：

- 每个运算符节点是树上的一个非叶节点，它的子式就是它的儿子；
- **逗号只是同一层儿子之间的分隔符**，不产生任何运算；
- **`(` 不携带信息**——它只是紧跟在运算符后面、给这个节点的子树「定界」的记号。

> **关键观察**：运算符字符后面**紧跟**一个 `(`，因此「括号的嵌套层数」与「运算符的压栈顺序」一一对应；读到某个 `)` 时，最近一个还没关闭的 `(` 前面那个运算符，恰好就是当前要结算的节点，而它的**全部子式此时都已经读完了**。

既然读到 `)` 时子式一定齐了，就**根本不用把子式收集成列表**再遍历一遍：给每个运算符节点配一个**单位元**作为初始累计值（`&` 配 true、`|` 配 false），每读到一个叶子 `t`/`f` 就**立刻归并**进栈顶节点；读到 `)` 时栈顶的累计值就是这棵子树的真值，弹栈并把它交给父节点。整个算法一遍扫描、每个字符只处理一次。

### 3.3 算法流程：单栈 + 单位元就地归并

![单栈 + 单位元就地归并的流程](images/wc143_q4_stack_flow.svg)

栈中元素是二元组 `(op, acc)`：`op` 是运算符，`acc` 是该节点**已读入的子式**按 `op` 归并后的结果。归并函数统一写成

```text
merge(op, acc, v):
    '&' -> acc AND v      # 压栈时 acc 初值 true （AND 的单位元）
    '|' -> acc OR  v      # 压栈时 acc 初值 false（OR  的单位元）
    '!' -> NOT v          # 只有一个子式，直接覆盖
```

主循环按字符分四类处理：

```text
for c in expression:
    ',' 或 '('  ->  忽略
    '!' '&' '|' ->  push (c, c == '&')      # 新节点，开始收集子式
    't' 或 'f'   ->  v = (c == 't')；若栈空直接返回 v；否则 merge(栈顶, v)
    ')'          ->  弹出 (op, acc)；若栈空则返回 acc；否则 merge(新栈顶, acc)
```

三个要点：`(` 和 `,` 都是「纯标点」，跳过；`!` 的归并是**覆盖**而不是 AND/OR；`)` 弹出的同时完成一次「结算 + 向上汇报」。

### 3.4 示例演算

![示例 3 的栈变化](images/wc143_q4_walkthrough.svg)

以 `expression = "!(&(f,t))"` 为例，符号 `(!,F)` 表示「运算符 `!`，累计值 false」：

| 步 | 字符 | 动作 | 栈（底 → 顶） |
|----|------|------|----------------|
| 1 | `!` | 压入 `(!, false)` | `(!,F)` |
| 2 | `(` | 忽略 | `(!,F)` |
| 3 | `&` | 压入 `(&, true)` | `(!,F) (&,T)` |
| 4 | `(` | 忽略 | `(!,F) (&,T)` |
| 5 | `f` | 归并 `&`：true $\wedge$ false | `(!,F) (&,F)` |
| 6 | `,` | 忽略 | `(!,F) (&,F)` |
| 7 | `t` | 归并 `&`：false $\wedge$ true | `(!,F) (&,F)` |
| 8 | `)` | 弹出 `(&,F)`，交给 `!` 取反得 true | `(!,T)` |
| 9 | `)` | 弹出 `(!,T)`，栈空 ⇒ 返回 true | 空 |

第 9 步的「栈空」是一个信号：根节点被弹出，说明整式已经结算完毕，可以直接 `return`。对示例 1 的 `"&(|(f))"`，遇到第一个 `)` 时会先把 `(|,F)` 结算成 false 交给 `&`，`&` 的累计值变成 false，最终返回 false——与「先算内层」的语义完全一致。

## 4. 算法细节

1. **为什么能忽略 `(`**：文法规定每个运算符字符后面必然紧跟 `(`，这个 `(` 不提供任何新信息（新节点已经由运算符字符压栈了）；而它的 `)` 会在第 3.3 节的规则里负责「结算」。如果输入允许 `!  (t)` 这种中间夹空格的写法，就必须显式校验，本题不需要。
2. **为什么能忽略 `,`**：逗号只是同一层子式之间的分隔，而子式的值在读到叶子的那一刻就已经归并进栈顶了，逗号出现时无事可做。
3. **单位元的选择**：`&` 的归并初值必须是 true（$x \wedge \top = x$），`|` 的初值必须是 false（$x \vee \bot = x$），否则第一个子式会被「污染」。`!` 没有单位元（只有一个子式），初值随便占位，反正会被覆盖。
4. **`!` 必须覆盖而不是归并**：若把 `!` 也写成 `acc = acc && v`，那么 `!(f)` 会算成 `true && false = false`，而正确答案是 `true`。这是本题最容易写错的一处。
5. **`t`/`f` 要防止空栈**：输入可能只有 `"t"` 或 `"f"`，此时没有任何运算符被压栈，直接返回该字面量的真假。
6. **用迭代而不是递归**：嵌套深度可达 $n/3 \approx 6666$，超过 Python 默认递归上限 1000；迭代版栈深只会等于嵌套深度，且不受语言递归限制。
7. **单栈就够，不必用「值栈 + 符号栈」**：每个节点的结果只是一个 `bool`，`&`/`|` 的归并满足结合律、`!` 只有一个子式，所以运算符和它自己的累计值放在同一个栈元素里即可；分成两个栈反而要额外维护括号配对与两侧长度。

## 5. 正确性证明

先给出不变量。设扫描到位置 $i$（字符 $i$ 尚未处理），把栈中元素自底向上记为 $(op_1, acc_1), \dots, (op_d, acc_d)$。

**引理 1（不变量）**：任意时刻，栈中第 $j$ 个元素恰好对应语法树上「当前正在填写的节点」的第 $j$ 层祖先，且 $acc_j$ 等于该节点**已读入的全部子式**按 $op_j$ 归并的结果（`&` 以 true 为初值、`|` 以 false 为初值、`!` 的 $acc$ 是其唯一子式的取反）。

**证明**：对已扫描的字符数归纳。

- 初始栈为空，命题空真。
- 读到运算符：相当于在树上向下走一层，新节点还没有子式，$acc$ 取单位元（`!` 取占位值），不变量保持。
- 读到 `t`/`f`：它是当前节点（栈顶）的下一个子式，`merge` 按定义把 $acc_d$ 更新为「原有的全部子式 + 这一个新的」的归并值；读到 `,` 只是分隔符，不改状态，两种情况都保持不变量。
- 读到 `)`：由引理 2，栈顶节点的全部子式已经齐了，其 $acc_d$ 就是该子树的真值；弹出后若栈非空，则它作为父节点的「下一个子式」被归并，父节点满足归并定义，保持；若栈空，说明整棵树已经结算。∎

**引理 2（右括号对应栈顶）**：读到的每个 `)`，其匹配的 `(` 之前紧邻的运算符，恰好就是当前栈顶元素；且在读到这个 `)` 时，该节点的所有子式都已读入。

**证明**：由文法，每个运算符字符后面紧跟它的 `(`，因此「左括号的开启顺序」与「运算符的压栈顺序」完全一致；`(` 被忽略后，栈中元素与「尚未关闭的左括号」一一对应，最内层未关闭的 `(` 对应栈顶，而 `)` 关闭的正是最内层未关闭者。又因为任何在该节点内部开启的嵌套节点，都会在更早的位置遇到属于它自己的 `)` 并被弹出（那些 `)` 都在当前 `)` 之前），所以当前 `)` 出现时，栈顶以下兄弟们的子式都已归并完毕，内部子节点也都已结算并向上汇报。∎

**引理 3（归并语义正确）**：对任一运算符节点，`merge` 的三种分支分别实现了逻辑与、逻辑或、逻辑非的定义。

**证明**：`&` 分支做 `acc AND v` 且初值为 true，由 AND 的结合律与单位元性质，累计结果是所有子式之积（全为真才是真）；`|` 分支对称，初值 false，累计结果是所有子式之和（有一个为真就是真）；`!` 分支只有一个子式，直接取反，正是逻辑非。∎

**定理**：`parseBoolExpr` 返回表达式 `expression` 的真值。

**证明**：由引理 2，扫描过程中每个 `)` 都能让栈顶节点在其子式齐全后结算；由引理 1 与引理 3，结算出的值等于该子树的真值，并作为子式正确归并进父节点。整个输入扫描到尾时，根节点必然已被某个 `)` 弹出（或在输入为单个字面量时直接返回），此时栈空且返回值就是根节点真值，即整个表达式的真值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符恰好被处理一次：运算符入栈 $O(1)$，叶子做一次归并 $O(1)$，`)` 出栈 + 一次归并 $O(1)$，`,`、`(` 直接跳过。没有子串复制、没有二次遍历。
- **空间**：$O(n)$，更精确地说是 $O(d)$，其中 $d$ 是最大嵌套深度。每个运算符恰好入栈一次，最坏情况（如 `!(!(...(t)...))`）$d \approx n/3$；栈元素只是一个 `char` 加一个 `bool`，常数极小。
- **常数**：整个过程只做栈的 `push/pop` 与布尔运算，C++ 与 Python 在 $n = 2\times10^4$ 时都是毫秒级。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <utility>
using namespace std;

class Solution {
public:
    bool parseBoolExpr(string expression) {
        // 栈元素: (运算符, 已归并的子式结果)
        vector<pair<char, bool>> st;
        for (char c : expression) {
            if (c == ',' || c == '(') continue;          // 纯标点，跳过
            if (c == '&' || c == '|' || c == '!') {
                st.emplace_back(c, c == '&');            // '&' 的单位元是 true，其余占位
            } else if (c == 't' || c == 'f') {
                bool v = (c == 't');
                if (st.empty()) return v;                // 整个表达式就是一个字面量
                mergeInto(st.back(), v);
            } else {                                     // c == ')'
                auto node = st.back();                   // 拷贝一份后出栈
                st.pop_back();
                if (st.empty()) return node.second;      // 根节点结算完毕
                mergeInto(st.back(), node.second);       // 作为子式交给父节点
            }
        }
        return false;                                    // 合法输入不会走到这里
    }

private:
    void mergeInto(pair<char, bool>& node, bool v) {
        if (node.first == '&')      node.second = node.second && v;
        else if (node.first == '|') node.second = node.second || v;
        else                        node.second = !v;    // '!' 只有一个子式
    }
};
```

### Python

```python
class Solution:
    def parseBoolExpr(self, expression: str) -> bool:
        stack = []                                   # 元素为 [运算符, 已归并的子式结果]

        def merge(node, v):
            op = node[0]
            if op == '&':
                node[1] = node[1] and v
            elif op == '|':
                node[1] = node[1] or v
            else:                                    # '!' 只有一个子式，直接覆盖
                node[1] = not v

        for c in expression:
            if c in ',(':
                continue                             # 纯标点，跳过
            if c in '&|!':
                stack.append([c, c == '&'])          # '&' 的单位元是 true，其余占位
            elif c in 'tf':
                if not stack:
                    return c == 't'                  # 整个表达式就是一个字面量
                merge(stack[-1], c == 't')
            else:                                    # ')'
                node = stack.pop()
                if not stack:
                    return node[1]                   # 根节点结算完毕
                merge(stack[-1], node[1])
        return False                                 # 合法输入不会走到这里
```

## 8. 边界情况与易错点

1. **单字面量输入**：`"t"`、`"f"` 必须先判空栈再取栈顶，否则越界；返回的是这个字面量本身的真假。
2. **`!` 的归并方向**：把 `!` 写成 `acc = acc && v`（初值 true）在 `!(f)` 上会得到 false，正确结果是 true。`!` 必须覆盖。
3. **不要漏掉 `(`**：因为 `(` 直接跳过，栈里只剩运算符和累计值，`t`/`f` 才能无条件归并到栈顶；若把 `(` 也压栈，就得额外判断「跳过括号再找运算符」。
4. **递归深度**：嵌套最深处约 $n/3$ 层，Python 默认递归上限 1000 会 `RecursionError`；要么改成迭代（本解），要么 `sys.setrecursionlimit(30000)`。
5. **宽度陷阱**：`&(t,t,...,t)` 形式的表达式子式极多（$k$ 可达约 $10^4/2$），实现时**不要先把子式收进 `vector` 再求值**——虽然仍是 $O(n)$，但多了一轮遍历与额外内存；边读边归并是一趟完成。
6. **`auto [op, acc] = st.back()` 是拷贝**：想原地修改必须用 `auto&`。本解取拷贝后立即 `pop_back`，所以没问题。
7. **返回类型**：题目要求 `bool`，不要在 C++ 里返回 `'t'`/`'f'` 字符或 `int`。栈内直接存 `bool`，避免字符比较。
