# LeetCode 满足目标工作时长的员工数目 题解

## 1. 题目概述

- **标题 / 题号**：满足目标工作时长的员工数目（#2798，easy）
- **链接**：https://leetcode.cn/problems/number-of-employees-who-met-the-target/
- **来源**：LeetCode 第 356 场周赛 Q1
- **难度**：简单
- **标签**：数组、计数

**题意**：公司有 $n$ 名员工（编号 $0 \sim n-1$），员工 $i$ 已工作 $\text{hours}[i]$ 小时。公司要求每人工作**至少** $\text{target}$ 小时。给定非负整数数组 $\text{hours}$ 与非负整数 $\text{target}$，返回达标（工作时长达于 $\text{target}$ 及以上）的员工数。

**约束**：

- $1 \le n = \text{hours.length} \le 50$
- $0 \le \text{hours}[i],\ \text{target} \le 10^5$

> 💡 签到题的第一个动作是**圈出量词**：「至少」=「不少于」$= \ge$（**含等号**）。整道题就是把这句话翻译成一个比较符加一次计数，任何多余动作（排序、建表）都是负优化。

## 2. 示例

**示例 1**

```text
输入：hours = [0,1,2,3,4], target = 2
输出：3
解释：公司要求每位员工工作至少 2 小时。
- 员工 0 工作 0 小时，不满足要求。
- 员工 1 工作 1 小时，不满足要求。
- 员工 2 工作 2 小时，满足要求。
- 员工 3 工作 3 小时，满足要求。
- 员工 4 工作 4 小时，满足要求。
共有 3 位满足要求的员工。
```

**示例 2**

```text
输入：hours = [5,1,4,2,2], target = 6
输出：0
解释：数组最大值 5 < target = 6，无人达标。
```

**补充示例（自构造，覆盖 target = 0 边界）**

```text
输入：hours = [5,1,4,2,2], target = 0
输出：5
解释：hours[i] ≥ 0 恒成立，人人达标——target = 0 时答案必为 n。
```

## 3. 解题思路

### 3.1 暴力思路

本题的"朴素解"就是终点：从左到右扫一遍，`h >= target` 就给计数器加一。不存在更笨也更有必要写的做法，反倒是两个常见的**负优化**要警惕：

- **先排序**：$O(n \log n)$ 比直接扫描的 $O(n)$ 还慢——排序换来的有序性对"数一遍"毫无用处；
- **建布尔数组再求和**：多占一块 $O(n)$ 辅助空间，只比边扫边数难看。

> ⚠️ 周赛视角：$n \le 50$ 时怎么写都能过，签到题拼的是**读题到代码的最短路径**与**零 WA**，省下的时间都是 Q3/Q4 的。

### 3.2 核心观察：题面翻译 + 无序计数的 $\Omega(n)$ 下界

![核心观察：「至少」翻译成 ≥，单趟计数即最优](images/target_hours_threshold_concept.svg)

两句话构成完整解法：

1. **翻译**：「至少 $\text{target}$ 小时」$\iff \text{hours}[i] \ge \text{target}$（含等号）。员工之间相互独立、与顺序无关，答案就是满足该条件的下标个数——单趟扫描计数即得。
2. **最优性**：数组无序，$\text{target} \ge 1$ 时任何正确算法最坏情况下**必须读取每个元素**——否则对手可把未读位置在 $\text{target}-1$ 与 $\text{target}$ 之间切换，两种输入的正确答案差 1，而算法所见完全相同（§5 引理 3）。故 $O(n)$ 单趟扫描不是"够用"，而是"不可能更快"。

> 💡 唯一例外是 $\text{target} = 0$：由 $\text{hours}[i] \ge 0$ 恒成立，答案必为 $n$，理论上 $O(1)$ 可直接输出——这是"读数据范围找捷径"的小例子；但扫描写法无需特判也正确，比赛里不值得为此加分支。

### 3.3 算法流程

![算法流程：单趟扫描，一次比较至多一次自增](images/target_hours_one_pass_flow.svg)

1. 计数器 $\text{cnt} \gets 0$；
2. 从左到右遍历每个 $\text{hours}[i] = h$：
   - 若 $h \ge \text{target}$：$\text{cnt} \gets \text{cnt} + 1$；
   - 否则跳过；
3. 遍历结束，返回 $\text{cnt}$。

每个元素恰被访问一次、比较一次、至多自增一次，无回溯、无排序、无辅助结构。

### 3.4 示例演算

![示例演算：hours = [0,1,2,3,4]，target = 2](images/target_hours_example_walkthrough.svg)

以 `hours = [0,1,2,3,4], target = 2` 走查（$\text{cnt}$ 从 0 起累加）：

| $i$ | $\text{hours}[i]$ | $\ge 2$ ? | $\text{cnt}$ | 说明 |
|----|------------------|-----------|--------------|------|
| 0 | 0 | ✗ | 0 | $0 < 2$ |
| 1 | 1 | ✗ | 0 | $1 < 2$ |
| 2 | 2 | ✓ | 1 | **恰好 $=$ target 也算（含等号）** |
| 3 | 3 | ✓ | 2 | |
| 4 | 4 | ✓ | 3 | |

最终 $\text{cnt} = 3$ ✓。示例 2 中 $\max = 5 < 6$，五个比较全否，$\text{cnt}$ 保持初值 0。

## 4. 算法细节

1. **判定条件方向**：`h >= target`——"至少 / 不少于"都含等号，这是本题唯一的知识点（也是唯一高频 WA 点，见 §8 第 1 条）。
2. **语言惯用法（赛场加速）**：C++ 用 range-for 显式循环，或一行 `count_if(hours.begin(), hours.end(), [&](int h){ return h >= target; })`；Python 用 `sum(h >= target for h in hours)`——生成器逐元素求值，`True/False` 即 `1/0`，$O(n)$ 时间 $O(1)$ 空间。
3. **target = 0 特例**：答案恒为 $n$。要不要写 `if (target == 0) return n;`？比赛里**不写**——特判是新的出错面，扫描版天然正确；面试里可作为"能否 $O(1)$"的加分讨论点（引理 3 的下界正是在 $\text{target} \ge 1$ 时才成立）。
4. **计数器**：`int` 足够——只计个数（$n \le 50$），不求和，无溢出可言。
5. **不排序、不哈希、不建辅助数组**：单次查询下排序是负优化，任何额外结构都是 Q1 时间黑洞。

## 5. 正确性证明

**引理 1（计数刻画）**：所求答案 $= \left|\{\, i : \text{hours}[i] \ge \text{target} \,\}\right|$。

**证明**：题设"工作至少 $\text{target}$ 小时"即 $\text{hours}[i] \ge \text{target}$，所求为其个数，即上式。∎

**引理 2（循环不变式）**：遍历完前 $k$（$0 \le k \le n$）个元素后，$\text{cnt} = \left|\{\, i < k : \text{hours}[i] \ge \text{target} \,\}\right|$。

**证明**：对 $k$ 归纳。$k = 0$ 时 $\text{cnt} = 0$，右边为空集基数 $0$，成立。设 $k$ 时成立，处理第 $k$ 个元素 $h = \text{hours}[k]$：若 $h \ge \text{target}$，算法执行 $\text{cnt} \gets \text{cnt} + 1$，而右边集合恰好新增元素 $k$，两边同增 $1$；否则算法不动作，右边集合亦不变。两种情况不变式均保持。∎

**定理 1（正确性）**：算法返回 $\left|\{\, i : \text{hours}[i] \ge \text{target} \,\}\right|$，即所求答案。

**证明**：在引理 2 中取 $k = n$，遍历结束时 $\text{cnt}$ 即满足条件的全部下标个数，由引理 1 即所求。∎

**引理 3（下界）**：当 $\text{target} \ge 1$ 时，任何确定性正确算法在最坏情况下必须读取 $\text{hours}$ 的全部 $n$ 个元素，故时间复杂度为 $\Omega(n)$。

**证明**（对手论证）：反设某算法在某次运行中未读取下标 $j$ 的值即给出输出。构造两组输入 $A$ 与 $B$：除 $\text{hours}[j]$ 分别取 $\text{target} - 1$（$A$）与 $\text{target}$（$B$）外完全相同，其余位置任意（如全取 $0$）。由 $\text{target} \ge 1$ 知 $\text{target} - 1 \ge 0$，两组均为合法输入；两组仅在未读的下标 $j$ 处不同，故算法在 $A$、$B$ 上的执行轨迹（读取内容与输出）完全相同。但由引理 1，$A$ 与 $B$ 的正确答案恰差 $1$，算法至少在其中一组上输出错误，矛盾。∎

**推论**：单趟 $O(n)$ 扫描是渐近最优算法（$\text{target} = 0$ 是唯一例外：此时答案恒为 $n$，$O(1)$ 可得）。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素一次比较、至多一次自增，$n \le 50$ 时瞬时完成；且由引理 3，$O(n)$ 已是下界——不是"够用"，而是"不可能更快"。
- **空间复杂度**：$O(1)$。仅一个计数器与循环变量，原地处理，无任何辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfEmployeesWhoMetTarget(vector<int>& hours, int target) {
        int cnt = 0;
        for (int h : hours)
            if (h >= target) ++cnt;   // 「至少」→ >=，含等号
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def numberOfEmployeesWhoMetTarget(self, hours: List[int], target: int) -> int:
        return sum(h >= target for h in hours)
```

> 💡 两版都是"读完题即写完"。Python 的 `sum` 直接消费布尔生成器；C++ 的等价一行是 `count_if`。签到题保持最顺手的写法，把调试时间压到零。

## 8. 边界情况与易错点

1. **`≥` 写成 `>`（最高频 WA）**：「至少」含等号。示例 1 中员工 2 恰好工作 2 小时必须计入，误用 `>` 会错答 2 而非 3。
2. **target = 0**：由 $\text{hours}[i] \ge 0$ 恒成立，答案恒为 $n$；扫描写法无需特判（这也是引理 3 下界不成立的情形）。
3. **target > max(hours)**：如示例 2（$\max = 5 < 6$），返回 0——计数器从未被更新，初值 0 直接返回，无需特判。
4. **全员达标**：返回 $n$；`target = 0` 只是它的极端情形。
5. **溢出**：只计个数、不求和，$n \le 50$，`int` 无任何风险。
6. **Python 陷阱**：`sum(h >= target for h in hours)` 正确；但 `sum(hours >= target)` 是拿 list 与 int 比较，直接 `TypeError`（list 没有 numpy 那样的广播）。
7. **别排序 / 别建表**：单次查询下排序 $O(n \log n)$、值域计数数组 $O(V)$ 都是负优化；Q1 的目标是两分钟内零 WA 提交。
