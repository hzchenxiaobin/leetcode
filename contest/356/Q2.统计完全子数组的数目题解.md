# LeetCode 统计完全子数组的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计完全子数组的数目（#2799，medium）
- **链接**：https://leetcode.cn/problems/count-complete-subarrays-in-an-array/
- **来源**：LeetCode 第 356 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：给定一个由**正**整数组成的数组 $\text{nums}$。若某个子数组中**不同**元素的数目等于**整个数组**不同元素的数目，则称该子数组为**完全子数组**。返回完全子数组的数目。子数组是数组中连续的非空序列。

**约束**：

- $1 \le n = \text{nums.length} \le 1000$
- $1 \le \text{nums}[i] \le 2000$

> 💡 **周赛定位**：$n \le 1000$ 意味着 $O(n^2)$ 双重循环即可通过（约 $10^6$），这是 Q2 留给选手的"保底通道"；冲击前排则要一眼认出这是**凑齐即计数**的单调滑窗模板。本题在站内已有 daily 版题解（[2799. 统计完全子数组的数目](../../solution/2701-2800/2799_统计完全子数组的数目.md)），采用"以左端为锚、数合法右端"的视角；本篇周赛复盘采用与之**互为镜像**的"以右端为锚、数合法左端"视角，两相对照可以完整看到滑窗计数的两个方向。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,1,2,2]
输出：4
解释：完全子数组有：[1,3,1,2]、[1,3,1,2,2]、[3,1,2] 和 [3,1,2,2]。
```

**示例 2**

```text
输入：nums = [5,5,5,5]
输出：10
解释：数组仅由整数 5 组成，任意子数组都满足条件，子数组总数 4×5/2 = 10。
```

**补充示例（自构造，全互异极端）**

```text
输入：nums = [1,2,3]
输出：1
解释：k = 3，唯一凑齐三种元素的子数组是整串 [1,2,3]。
```

## 3. 解题思路

### 3.1 暴力思路：枚举左端 + 凑齐即停

记 $k$ 为整个数组不同元素的个数（先一趟 `set` 求出）。最朴素的做法是枚举全部 $O(n^2)$ 个子数组、每个再花 $O(n)$ 统计，总 $O(n^3)$ 不可取；真正的**赛场保底**是枚举左端 $i$、向右扫并**增量**维护出现过的元素集合，第一次凑齐 $k$ 种时打住——设此刻右端为 $j$，由"向右加元素种类只增不减"，$j, j+1, \dots, n-1$ 作右端全部合法，一次性累加 $n - j$：

```python
# 赛场保底：O(n²)，n ≤ 1000 稳过
class Solution:
    def countCompleteSubarrays(self, nums: List[int]) -> int:
        k, n, ans = len(set(nums)), len(nums), 0
        for i in range(n):
            seen = set()
            for j in range(i, n):
                seen.add(nums[j])
                if len(seen) == k:
                    ans += n - j      # 凑齐后右端 j..n-1 全合法
                    break
        return ans
```

> ⚠️ 暴力的真正价值在于逼出观察一：**"凑齐即停 + 一次性累加"** 已经吃掉了滑窗一半的洞察。剩下的问题只有一个——`i` 右移一格后，`j` 是否必须从头再扫？若能证明不回头，$O(n^2)$ 就塌缩成 $O(n)$。

### 3.2 核心观察：可行左端连成前缀，且分界点只右移

![核心观察：固定右端，可行左端连成前缀 [0, L(r)]](images/complete_subarray_prefix_anchors.svg)

三个观察叠加，把 $O(n^2)$ 压成 $O(n)$：

1. **观察一（右端单调）**：子数组变长，不同元素数**只增不减**，而 $k$ 是任何子数组都不可逾越的**全局上限**。于是 $[l, r]$ 完全 $\Rightarrow$ 任意 $j \ge r$，$[l, j]$ 仍完全。
2. **观察二（左端前缀性）**：固定右端 $r$，若 $[l, r]$ 完全，则任意 $l' < l$ 有 $[l', r] \supseteq [l, r]$，种类更多、仍被封顶在 $k$，故也完全。因此以 $r$ 为右端的完全子数组恰好是**左端取 $0, 1, \dots, L(r)$ 的连续前缀**，共 $L(r) + 1$ 个——数子数组变成数左端。
3. **观察三（分界单调）**：$L(r) \le L(r+1)$。由观察一，$[L(r), r]$ 完全 $\Rightarrow [L(r), r+1]$ 完全 $\Rightarrow L(r+1) \ge L(r)$。分界点只右移，双指针合法，整体 $O(n)$。

> 💡 与 daily 版对照：daily 版固定**左端**数右端（凑齐后累加 $n - \text{right} + 1$），本篇固定**右端**数左端（累加 $L(r) + 1$）。同一单调结构，计数方向翻转；两个方向都要能写，滑窗计数才算真正吃透。

### 3.3 算法流程：以右端为锚，收缩到"恰好完全"

![算法流程：入窗 → 若凑齐则收缩冗余左端 → 按前缀长度计数](images/complete_subarray_sliding_flow.svg)

$\text{right}$ 从左到右前进，窗口 $[\text{left}, \text{right}]$ 全程维护一个不变式——**窗口的元素集合与前缀 $[0, \text{right}]$ 的元素集合相同**（证明见 §5 引理 2）：

1. **入窗**：$\text{cnt}[\text{nums}[\text{right}]]{+}{+}$，频次从 $0 \to 1$ 时 $\text{distinct}{+}{+}$；
2. **收缩**：若 $\text{distinct} = k$，只要 $\text{cnt}[\text{nums}[\text{left}]] > 1$（左端元素在窗口内还有冗余，去掉后依然完全），移出并 $\text{left}{+}{+}$；循环自然停在"再去一个就不完全"的临界处，此时 $\text{left} = L(\text{right})$；
3. **计数**：若 $\text{distinct} = k$，累加 $\text{left} + 1$——即以 $\text{right}$ 为右端的全部完全子数组个数。

### 3.4 示例演算

![示例演算：nums=[1,3,1,2,2]，k=3](images/complete_subarray_example_walkthrough.svg)

以示例 1 `nums = [1,3,1,2,2]`（$k = 3$）走查：

| $\text{right}$ | 入窗 | $\text{distinct}$ | 收缩动作 | 收缩后 $\text{left}$ | 累加 | $\text{ans}$ |
|---|---|---|---|---|---|---|
| 0 | 1 | 1 | — | 0 | 0 | 0 |
| 1 | 3 | 2 | — | 0 | 0 | 0 |
| 2 | 1 | 2 | — | 0 | 0 | 0 |
| 3 | 2 | $3 = k$ ✓ | 移出下标 0 的 1（$\text{cnt}=2 \to 1$） | 1 | $1 + 1 = 2$ | 2 |
| 4 | 2 | $3 = k$ ✓ | $\text{cnt}[3] = 1$，不缩 | 1 | $1 + 1 = 2$ | 4 |

- **$\text{right} = 3$（首度凑齐）**：窗口 $[0,3]$ 含 $1,3,2$ 三种；左端元素 $1$ 在窗口出现两次，属冗余——移出下标 0 后仍完全，$\text{left}$ 到 1 停（$3$ 只剩一次，再移即破坏）。$L(3) = 1$，累加 2，对应 $[1,3,1,2]$、$[3,1,2]$。
- **$\text{right} = 4$（恰好完全）**：入窗一个 2 后窗口 $[1,4]$ 仍恰好完全，左端 $3$ 无冗余，不缩不扩，直接累加 2，对应 $[1,3,1,2,2]$、$[3,1,2,2]$。最终 $4$ ✓。

> 💡 **示例 2 验证**：`nums=[5,5,5,5]`，$k=1$。每轮入窗即完全，收缩把多余的 5 逐个挤掉后 $L(r) = r$，累加依次为 $1,2,3,4$，合计 $10$ ✓。**自构造示例验证**：`[1,2,3]` 全互异，$k=3$，仅最后一轮 $\text{distinct} = k$，累加 $0 + 1 = 1$ ✓。

## 4. 算法细节

1. **先求 $k$**：$k$ 是全局性质，必须先单独求出（一趟 `set` / 值域扫描）；窗口逻辑只维护 $\text{distinct}$ 是否"追平"$k$，不负责发现 $k$。
2. **值域数组替代哈希**：$1 \le \text{nums}[i] \le 2000$，开 `int cnt[2001]` 直接下标计数，比 `unordered_map` 快且零哈希开销；若求 $k$ 时复用同一数组，**务必重新清零**。
3. **收缩条件的等价刻画**：$\text{cnt}[\text{nums}[\text{left}]] > 1 \iff$ 移出后 $\text{distinct}$ 不变 $\iff$ 窗口左端存在冗余 $\iff$ 窗口还不是"恰好完全"的最短形态。三种说法一个意思，写代码时认准第一种（频次比较），推导时用第二种（集合不变）。
4. **为何 $\text{left}$ 指针合法**：由观察三 $L(r)$ 单调不减，$\text{left}$ 永不回退；$\text{left}$、$\text{right}$ 各自累计至多前进 $n$ 步，每个元素至多入窗、出窗各一次，均摊 $O(n)$。
5. **计数方向**：累加 $\text{left} + 1$（合法左端个数 $0..\text{left}$）。若与 daily 镜像版混淆写成 $n - \text{right} + 1$（数右端），两者在"以右端为锚"的循环里**不等价**——见 §8 第 2 条。

## 5. 正确性证明

**引理 1（左端前缀性）**：固定右端 $r$，若 $[l, r]$ 完全，则对任意 $l' < l$，$[l', r]$ 也完全；从而以 $r$ 为右端的完全子数组恰为左端 $0..L(r)$ 的前缀，共 $L(r)+1$ 个，其中 $L(r)$ 为最大可行左端（约定不存在时 $L(r) = -1$）。

**证明**：$[l', r] \supseteq [l, r]$，不同元素数关于包含单调不减，故 $\text{distinct}([l',r]) \ge \text{distinct}([l,r]) = k$；又任何子数组的不同元素数 $\le k$（$k$ 为全局种类数），故 $= k$，即完全。可行左端对更小左端封闭，且若 $[0, r]$ 不完全则无任何可行左端，故可行左端集是 $[0, L(r)]$ 或空。∎

**引理 2（集合不变式）**：每轮处理完 $\text{nums}[\text{right}]$ 且收缩循环结束时，窗口元素集合等于前缀元素集合：$\mathrm{set}[\text{left}, \text{right}] = \mathrm{set}[0, \text{right}]$。

**证明**（对 $\text{right}$ 归纳）：$\text{right} = 0$ 时窗口即前缀，成立。设上一轮成立。

- **入窗**：$\text{nums}[\text{right}]$ 加入窗口与前缀两边同步；由归纳假设两集合此前相等，故该元素"是否带来新种类"在两边一致，加入后仍相等。
- **收缩**（仅当 $\text{distinct} = k$ 时发生）：此时 $\mathrm{set}[\text{left}, \text{right}]$ 已达 $k$ 种，即全局元素集，而 $\mathrm{set}[0, \text{right}]$ 是其子集，二者相等。收缩每步移出的元素频次 $\ge 2$，移出后仍在窗口中，**集合不变**，等号保持。∎

**引理 3（计数刻画）**：第 $\text{right}$ 轮结束时：若 $\text{distinct} = k$，则 $\text{left} = L(\text{right})$，算法累加 $\text{left}+1$ 恰等于以 $\text{right}$ 为右端的完全子数组个数；若 $\text{distinct} < k$，算法累加 $0$，且以 $\text{right}$ 为右端的完全子数组不存在。

**证明**：若 $\text{distinct} = k$：由引理 2，$\mathrm{set}[\text{left}, \text{right}]$ 含全部 $k$ 种，窗口完全，故 $\text{left}$ 可行；收缩循环终止于 $\text{cnt}[\text{nums}[\text{left}]] \le 1$，若 $\text{left}$ 可行则必有 $\text{cnt}[\text{nums}[\text{left}]] = 1$，移出即失去一种元素，$[\text{left}+1, \text{right}]$ 不完全，故 $\text{left}$ 是最大可行左端 $L(\text{right})$；由引理 1 累加值正确。若 $\text{distinct} < k$：由引理 2，$\mathrm{set}[0, \text{right}]$ 不足 $k$ 种，$[0, \text{right}]$ 不完全，由引理 1 无可行左端，两不相漏。∎

**定理（正确性）**：算法返回数组中完全子数组的总数。

**证明**：每个子数组按右端唯一归类，第 $\text{right}$ 轮的累加值恰为以 $\text{right}$ 为右端的完全子数组个数（引理 3），各轮互不相交且覆盖全部右端，求和即总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$（哈希版，均摊）或 $O(n + V)$（值域数组版，$V = 2001$，含建表清零）。核心均摊论证：$\text{right}$ 从 $0$ 单调推进到 $n-1$ 共 $n$ 步；$\text{left}$ 由观察三单调不减，全程至多推进 $n$ 步。每个元素至多入窗、出窗各一次，总基本操作 $O(n)$。
- **空间复杂度**：$O(V)$（值域数组）或 $O(k)$（哈希表，$k \le \min(n, V)$ 为全局种类数）。

> ⚠️ 本场 $n \le 1000$，$O(n^2)$ 保底版约 $10^6$ 步也能过；但同样的模板在 $n \sim 10^5$ 的场（如 2962 一族）只有 $O(n)$ 能活——周赛里顺手写正解，等于提前练掉一场 WA。

## 7. 参考代码

### C++（值域数组 + 单趟滑窗）

```cpp
class Solution {
public:
    int countCompleteSubarrays(vector<int>& nums) {
        int cnt[2001] = {};
        int k = 0;
        for (int x : nums)
            if (cnt[x]++ == 0) ++k;          // 先求全局不同元素数 k
        memset(cnt, 0, sizeof(cnt));         // 复用前务必清零

        int n = nums.size(), left = 0, distinct = 0, ans = 0;
        for (int right = 0; right < n; ++right) {
            if (cnt[nums[right]]++ == 0) ++distinct;
            // 左端有冗余：去掉后仍完全，收缩到「恰好完全」
            while (distinct == k && cnt[nums[left]] > 1)
                --cnt[nums[left++]];
            if (distinct == k)
                ans += left + 1;             // 合法左端 0..left 共 left+1 个
        }
        return ans;
    }
};
```

### Python（字典滑窗）

```python
class Solution:
    def countCompleteSubarrays(self, nums: List[int]) -> int:
        k = len(set(nums))
        n = len(nums)
        cnt = defaultdict(int)
        left = distinct = ans = 0
        for right in range(n):
            x = nums[right]
            cnt[x] += 1
            if cnt[x] == 1:
                distinct += 1
            while distinct == k and cnt[nums[left]] > 1:   # 左端冗余才收缩
                cnt[nums[left]] -= 1
                left += 1
            if distinct == k:
                ans += left + 1
        return ans
```

> 💡 两版主循环完全同构：入窗 → 凑齐后挤掉冗余左端 → 按前缀长度累加。C++ 版利用 $V \le 2000$ 用裸数组换掉哈希，是 $n$ 卡常时的第一选择；Python 版的 `defaultdict(int)` 避免裸下标访问的 `KeyError`。

## 8. 边界情况与易错点

1. **过度收缩（最高频 WA）**：把收缩写成"凑齐就一直移出、直到不完全"——`while (distinct == k) { 移出; 若频次归零则 distinct--; left++; }`。窗口被缩到不完全后**无法恢复**，后续轮次的计数全部偏小（如示例 1 中 $\text{right}=4$ 一轮会漏算）。正确收缩只在 $\text{cnt}[\text{nums}[\text{left}]] > 1$ 时发生——**先判冗余、再移出**，而非"先移出、再补救"。
2. **计数公式张冠李戴**：本篇"以右端为锚"累加 $\text{left} + 1$；daily 版"以左端为锚"累加 $n - \text{right} + 1$。两套公式配两套循环骨架，混搭（右端锚 + 数右端公式）必错。
3. **$k = 1$（全同元素）**：每轮都完全，收缩把窗口挤到长度 1，累加 $1, 2, \dots, n$，答案 $\frac{n(n+1)}{2}$（示例 2 的 10）。若手算验证时忘了收缩逻辑，容易误以为每轮累加 1。
4. **全互异（$k = n$）**：只有整串完全，答案恒为 1；全程不收缩，最后一轮才计数。可作 $O(1)$ 自检用例。
5. **值域数组边界**：$\text{nums}[i] \le 2000$ 含端点，数组开 `2001`；求 $k$ 与滑窗复用同一数组时，**两次循环之间必须清零**（C++ 版的 `memset` 一旦遗漏，$\text{distinct}$ 直接失真）。
6. **溢出**：答案上限 $\frac{n(n+1)}{2} \le \frac{1000 \times 1001}{2} = 500500$，`int` 无虞；但把累加写成 `long long` 也无妨，防御式写法不扣分。
7. **Python 计数容器的选择**：裸 `dict` 下标读（`cnt[x]`）在键不存在时抛 `KeyError`，用 `defaultdict(int)` 或 `cnt.get(x, 0) + 1`；`Counter` 亦可但初始化略慢，赛场上 `defaultdict` 最顺手。
8. **别把"恰好"当"至多"**：完全子数组要求**等于** $k$ 种，不是至少含某特定元素。窗口多余元素（冗余）不影响合法性——它们是计数时左端前缀的来源，不是要排除的对象。
