# LeetCode 与敌人战斗后的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：与敌人战斗后的最大分数（#3207，medium）
- **链接**：https://leetcode.cn/problems/maximum-points-after-enemy-battles/
- **来源**：LeetCode 第 134 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组

**题意**：有 $n$ 个未标记的敌人，第 $i$ 个的能量为 $enemyEnergies[i]$，初始能量 $currentEnergy$，初始分数 0。每步可以二选一：

1. **攻击**：选一个**未标记**且 $currentEnergy \ge enemyEnergies[i]$ 的敌人，得 1 分，能量减去 $enemyEnergies[i]$（敌人**不被标记**，可以反复攻击）。
2. **标记**：若当前**至少有 1 分**，选一个未标记敌人 $i$，能量**增加** $enemyEnergies[i]$，该敌人被标记（此后不能再攻击它）。

求能获得的最大分数。

**约束**：

- $1 \le enemyEnergies.length \le 10^5$
- $1 \le enemyEnergies[i] \le 10^9$
- $0 \le currentEnergy \le 10^9$
- 返回值类型是 `long`（Python 无影响，C++ 用 `long long`）

**关键点**：标记是「一次性把敌人换成能量」，被标记的敌人不能再打；因此**留下最弱的那个当长期饭票**，其余全部标记换能量，是最优结构。

## 2. 示例

**示例 1**

```text
输入：enemyEnergies = [3,2,2], currentEnergy = 2
输出：3
解释：
  攻击敌人 1（能量 2）：得分 1，能量 0
  标记敌人 0（能量 3）：能量 3，敌人 0 被标记
  攻击敌人 2（能量 2）：得分 2，能量 1
  标记敌人 2（能量 2）：能量 3，敌人 2 被标记
  攻击敌人 1（能量 2）：得分 3，能量 1
共 3 分。
```

**示例 2**

```text
输入：enemyEnergies = [2], currentEnergy = 10
输出：5
解释：只有一个敌人，永远不标记它，反复攻击 5 次（10 ÷ 2 = 5），得 5 分。
```

**示例 3（边界补充，连最弱的都打不过）**

```text
输入：enemyEnergies = [5,5], currentEnergy = 4
输出：0
解释：初始能量 4 < 5，无法攻击任何敌人；没有分数也就无法执行标记操作。得 0 分。
```

## 3. 解题思路

### 3.1 暴力思路

状态是（已标记集合, 当前能量），转移是「攻击某个未标记敌人」或「标记某个未标记敌人」。状态数与能量取值都可能很大，$n = 10^5$ 时完全不可行；即使 $n \le 5$，也要靠记忆化搜索才勉强能跑。暴力的价值在于**验证贪心**：$n \le 5$、能量 $\le 12$ 时可以直接搜。

### 3.2 核心观察：最弱的敌人当「能量兑换机」

![排序后：最弱的敌人当能量兑换机](images/bw134_q2_greedy_model.svg)

把敌人按能量升序排列，记最小值 $a_0 = \min$、总和 $S = \sum a_i$。两条关键观察：

1. **攻击的目标永远选最弱的**。每次攻击得 1 分，代价是敌人的能量；既然只关心「同样能量能换几分」，当然挑最便宜的。最弱的敌人**绝不应该被标记**——它是唯一值得反复攻击的对象。
2. **标记操作的顺序无关紧要，且应该「一次把其余全部标记」**。标记只增加能量、不消耗分数，被标记的敌人只是失去被攻击的资格。既然其余敌人本来就不值得攻击（都比 $a_0$ 贵），那就在拿到第 1 分之后把它们**全部**标记，一次性把能量池加满。

于是最优流程被钉死为三步：

$$\text{打 } a_0 \text{ 一次} \rightarrow \text{标记其余全部} \rightarrow \text{反复打 } a_0$$

总能量 = $currentEnergy - a_0 + (S - a_0)$，每次攻击花 $a_0$，所以

$$\text{ans} = \left\lfloor \frac{currentEnergy + S - a_0}{a_0} \right\rfloor$$

### 3.3 算法流程

![判定流程：先看能否开局，再一次性兑换](images/bw134_q2_flow.svg)

```text
a0 = min(enemyEnergies), S = sum(enemyEnergies)
if currentEnergy < a0:      # 连一次都打不了，也就拿不到第 1 分
    return 0
return (currentEnergy + S − a0) / a0        # 整数除法
```

整个算法只需一次遍历求最小值与总和，$O(n)$。（先排序再取 `a[0]` 与 `sum` 也完全等价，只是多花 $O(n \log n)$。）

### 3.4 示例演算

![示例走查：三步走拿到 3 分](images/bw134_q2_example_walk.svg)

$enemyEnergies = [3,2,2]$，$currentEnergy = 2$：$a_0 = 2$，$S = 7$。

| 步骤 | 操作 | 分数 | 能量 | 已标记 |
|------|------|------|------|--------|
| 初始 | — | 0 | 2 | — |
| 1 | 攻击敌人 1（花 2） | 1 | 0 | — |
| 2 | 标记敌人 0（+3） | 1 | 3 | {0} |
| 3 | 攻击敌人 2（花 2） | 2 | 1 | {0} |
| 4 | 标记敌人 2（+2） | 2 | 3 | {0,2} |
| 5 | 攻击敌人 1（花 2） | 3 | 1 | {0,2} |

代入公式：$(2 + 7 - 2) / 2 = 7 / 2 = 3$，与模拟结果一致。

## 4. 算法细节

1. **先判门槛**：$currentEnergy < a_0$ 时，攻击操作一次也做不了；而标记操作要求「至少有 1 分」，分数只能靠攻击获得——于是什么都做不了，直接返回 0。这是最容易漏的一个分支。
2. **只能标记「其余」敌人**：$a_0$ 若被标记，就再也没有便宜的攻击目标，收益必然变差（见 §5 引理 1 的界）。当 $n = 1$ 时「其余」为空，公式退化为 $currentEnergy / a_0$，与示例 2 相符。
3. **先攻击一次再标记**：标记需要至少 1 分，所以必须先用一次攻击「启动」。这一步不能省，也不能把它算成「白送」——它同样消耗 $a_0$ 能量、贡献 1 分，公式里已经包含。
4. **整除与向下取整**：剩余能量不足以再打一次时就停，所以是向下取整。公式 $($currentEnergy$ + S - a_0) / a_0$ 在整数除法下自动完成。
5. **溢出**：$S \le 10^5 \times 10^9 = 10^{14}$，超出 `int`，C++ 必须用 `long long`；Python 的整数无上限，天然安全。
6. **不需要真的排序**：只要最小值与总和。排序版本（`sort` 后取 `a[0]`、`accumulate` 求和）也正确，可作为对照实现。
7. **不要贪心地「边打边标记」**：由于标记不消耗分数，把标记推迟只会让中间过程能量更紧，不会带来任何好处；一次性标记完是最优的。

## 5. 正确性证明

先把敌人的能量升序排列为 $a_0 \le a_1 \le \dots \le a_{n-1}$，记 $S = \sum_i a_i$。约定一次「攻击」消耗 $a_i$、得 1 分；一次「标记」获得 $a_i$、失去该敌人。

**引理 1（得分上界）**：任何合法操作序列得到的分数 $P$ 满足 $P \cdot a_0 \le currentEnergy + S - a_0$。

**证明**：设序列结束时被标记的敌人集合为 $M$，标记获得的能量为 $G = \sum_{i \in M} a_i$，攻击消耗的总能量为 $D$。由能量非负，$D \le currentEnergy + G$，且每次攻击至少花 $a_0$，故 $P \cdot a_0 \le D \le currentEnergy + G$。分两种情况：

- 若 $M \ne$ 全体（存在未被标记的敌人），设 $j \notin M$，则 $G = S - \sum_{i \notin M} a_i \le S - a_j \le S - a_0$。
- 若 $M =$ 全体，考虑**最后一次标记**发生的时刻，它标记了某个敌人 $j$。此后所有敌人都已被标记，无法再攻击，故全部 $P$ 次攻击都发生在此刻之前；而此刻之前被标记的敌人集合是 $M \setminus \{j\}$，获得能量 $S - a_j \le S - a_0$，消耗 $D' \ge P \cdot a_0$，于是 $P \cdot a_0 \le D' \le currentEnergy + S - a_j \le currentEnergy + S - a_0$。

两种情况都得到 $P \cdot a_0 \le currentEnergy + S - a_0$，即 $P \le \left\lfloor (currentEnergy + S - a_0)/a_0 \right\rfloor$。∎

**引理 2（构造达到上界）**：当 $currentEnergy \ge a_0$ 时，存在合法序列恰好得到 $\left\lfloor (currentEnergy + S - a_0)/a_0 \right\rfloor$ 分。

**证明**：按如下顺序操作：（1）攻击敌人 $0$ 一次（合法，因 $currentEnergy \ge a_0$），得 1 分，能量变为 $currentEnergy - a_0$；（2）把敌人 $1, \dots, n-1$ 依次标记（此时已有 1 分，合法），能量变为 $currentEnergy - a_0 + (S - a_0)$；（3）反复攻击敌人 $0$，每次花 $a_0$ 得 1 分，直到能量不足 $a_0$。第（3）步可执行 $\left\lfloor \frac{currentEnergy - a_0 + S - a_0}{a_0} \right\rfloor$ 次。总分数为
$$1 + \left\lfloor \frac{currentEnergy + S - 2a_0}{a_0} \right\rfloor = \left\lfloor \frac{a_0 + currentEnergy + S - 2a_0}{a_0} \right\rfloor = \left\lfloor \frac{currentEnergy + S - a_0}{a_0} \right\rfloor,$$
其中第一个等号用到 $\lfloor (k + R)/k \rfloor = 1 + \lfloor R/k \rfloor$（$R \ge 0$）。∎

**引理 3（无法开局则 0 分）**：若 $currentEnergy < a_0$，则任何操作都不可执行，最大分数为 0。

**证明**：攻击操作要求 $currentEnergy \ge a_i \ge a_0 > currentEnergy$，不可行；标记操作要求当前分数 $\ge 1$，而分数只能通过攻击获得，攻击从不可行出发故永远不可行（归纳）。因此初始状态就是唯一的可达状态，分数恒为 0。∎

**定理**：算法返回值即为最大可得分数。

**证明**：$currentEnergy < a_0$ 时由引理 3 返回 0，正确。否则由引理 2 存在达到 $\lfloor (currentEnergy + S - a_0)/a_0 \rfloor$ 分的方案，又由引理 1 任何方案都不超过该值，故它即为最大值，算法返回它，正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次遍历同时求最小值与总和；若选择先排序则 $O(n \log n)$。
- **空间**：$O(1)$。仅几个标量（排序版本为 $O(\log n)$ 的栈空间或 $O(n)$ 的副本）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maximumPoints(vector<int>& enemyEnergies, int currentEnergy) {
        long long mn = *min_element(enemyEnergies.begin(), enemyEnergies.end());
        if ((long long)currentEnergy < mn) return 0;         // 连最弱的都打不过
        long long total = accumulate(enemyEnergies.begin(), enemyEnergies.end(), 0LL);
        // 打最弱一次 + 标记其余全部 + 反复打最弱
        return (currentEnergy + total - mn) / mn;
    }
};
```

### Python

```python
class Solution:
    def maximumPoints(self, enemyEnergies: list[int], currentEnergy: int) -> int:
        mn = min(enemyEnergies)
        if currentEnergy < mn:          # 连最弱的都打不过
            return 0
        total = sum(enemyEnergies)
        # 打最弱一次 + 标记其余全部 + 反复打最弱
        return (currentEnergy + total - mn) // mn
```

> 💡 两段代码通过官方示例（`3`、`5`）与 $n = 1$、$currentEnergy < \min$ 等边界；并与「状态搜索（已标记集合 × 能量）」的暴力实现在 $n \le 5$、能量 $\le 12$ 的范围做了 300 组随机对拍，`mismatch = 0`。最坏答案可达约 $10^{14}$（$a_0 = 1$、$S \approx 10^{14}$），必须用 64 位整型；$n = 10^5$ 的输入耗时在毫秒级。

## 8. 边界情况与易错点

1. **$n = 1$**：没有「其余敌人」可标记，答案就是 $currentEnergy / a_0$（示例 2）。公式 $(c + a_0 - a_0)/a_0$ 恰好给出 $c/a_0$，无需特判。
2. **$currentEnergy < a_0$**：必须返回 0，不能返回 `(c + S - a_0)/a_0`——后者在 $c=0$ 时可能给出正数（例如 $S = 100$、$a_0 = 50$ 时算出 1），完全错误。
3. **`int` 溢出**：$S$ 可达 $10^{14}$，`int` 必然溢出；C++ 中 `accumulate` 的初值必须写 `0LL`，否则会以 `int` 累加。
4. **不要标记最弱的敌人**：它被标记后就失去了便宜的攻击目标，收益严格变差（引理 1 的界正是靠「留一个未标记」取得的）。
5. **标记需要先有 1 分**：如果写成「一开始就标记全部敌人再攻击」，在 $currentEnergy < a_0$ 但 $\ge$ 0 时会误判为可行，逻辑上也不符合题面。
6. **整除方向**：能量不足时不能再打，因此是向下取整（`/` 对非负整数即下取整；Python 用 `//` 一致）。
7. **返回值类型**：题目要求 `long`，答案上界约 $10^{14}/1 = 10^{14}$，必须用 64 位整型。
