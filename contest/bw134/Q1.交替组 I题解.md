# LeetCode 交替组 I 题解

## 1. 题目概述

- **标题 / 题号**：交替组 I（#3206，easy）
- **链接**：https://leetcode.cn/problems/alternating-groups-i/
- **来源**：LeetCode 第 134 场双周赛 Q1
- **难度**：简单
- **标签**：数组、滑动窗口

**题意**：$colors$ 表示一个**环**，第 $i$ 块瓷砖的颜色为 $colors[i]$（0 红、1 蓝）。若环中连续 3 块瓷砖满足「中间那块的颜色与左右两块都不同」，就称这 3 块构成一个**交替组**。求交替组的数目。由于是环，第一块与最后一块相邻。

**约束**：

- $3 \le colors.length \le 100$
- $0 \le colors[i] \le 1$
- 每个交替组由「中间那块」唯一确定，块数固定为 3

**关键点**：连续 3 块的头尾不参与判断，只有**中间那块**需要和两个邻居比较；环的接缝用取模处理即可。这是标准的签到题。

## 2. 示例

**示例 1**

```text
输入：colors = [1,1,1]
输出：0
解释：三块同色，任何三连都无法交替。
```

**示例 2**

```text
输入：colors = [0,1,0,0,1]
输出：3
解释：以各块为「中间」检查：
  i=0：邻居是 colors[4]=1 与 colors[1]=1，0 ≠ 1 ⇒ 计数
  i=1：邻居是 colors[0]=0 与 colors[2]=0，1 ≠ 0 ⇒ 计数
  i=2：邻居是 colors[1]=1 与 colors[3]=0，中间是 0 = colors[3] ⇒ 不计数
  i=3：邻居是 colors[2]=0 与 colors[4]=1，中间是 0 = colors[2] ⇒ 不计数
  i=4：邻居是 colors[3]=0 与 colors[0]=0，1 ≠ 0 ⇒ 计数
共 3 个。
```

**示例 3（边界补充，最短环）**

```text
输入：colors = [0,1,0]
输出：1
解释：n = 3 时 3 块彼此相邻，只有 i=1 满足「与两侧都不同」，故答案为 1。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有长度为 3 的连续段（环上共 $n$ 个起点），对每段检查「中间与左右都不同」：$O(n)$。本题 $n \le 100$，即使把每段的比较写得很笨重也不会有性能问题。真正需要注意的是**环的边界**，以及**不要漏判一侧**。

### 3.2 核心观察：每个交替组由中间那块唯一确定

![环上的交替组：中间瓷砖与左右邻居都不同](images/bw134_q1_ring.svg)

一个交替组是「连续 3 块」，它的位置由**中间那块的起点**决定：设中间块下标为 $i$，则三块依次是 $i-1, i, i+1$。因此

> 交替组的个数 = 满足 $colors[i] \ne colors[i-1]$ 且 $colors[i] \ne colors[i+1]$ 的下标 $i$ 的个数。

这个「中心化」的视角把「枚举 $n$ 个长度为 3 的窗口」简化成「枚举 $n$ 个中心」。下标环绕用取模完成：左邻居 $(i-1+n) \bmod n$、右邻居 $(i+1) \bmod n$。环的接缝（$i=0$ 与 $i=n-1$）自动被处理，不需要任何特判。

### 3.3 算法流程

```text
ans = 0
n = len(colors)
for i = 0 .. n−1:
    left  = colors[(i − 1 + n) mod n]
    right = colors[(i + 1) mod n]
    if colors[i] != left and colors[i] != right:
        ans += 1
return ans
```

### 3.4 示例演算

![示例走查：环上五个中心只有三组命中](images/bw134_q1_example_walk.svg)

$colors = [0,1,0,0,1]$（环形，下标 4 与 0 相邻）：

| 中心 $i$ | 左邻居 | 中间 | 右邻居 | 判定 |
|----------|--------|------|--------|------|
| 0 | $colors[4]=1$ | 0 | $colors[1]=1$ | ✓ |
| 1 | $colors[0]=0$ | 1 | $colors[2]=0$ | ✓ |
| 2 | $colors[1]=1$ | 0 | $colors[3]=0$ | ✗ 右侧同色 |
| 3 | $colors[2]=0$ | 0 | $colors[4]=1$ | ✗ 左侧同色 |
| 4 | $colors[3]=0$ | 1 | $colors[0]=0$ | ✓ |

三组命中，答案 3。

## 4. 算法细节

1. **左右都要查**：只写 `colors[i] != colors[i+1]` 会把 $i=2$（右侧同色）和 $i=3$（左侧同色）都算进去，得到 4 而不是 3。这是本题最常见的错。
2. **负下标处理**：C++ 中 `(i - 1) % n` 在 $i = 0$ 时得到 $-1$，是负下标；必须写 `(i - 1 + n) % n`。Python 的负数取模天然回到正数范围，但为了可读性建议统一写法。
3. **环的接缝**：$i=0$ 的左邻居是 $n-1$，$i=n-1$ 的右邻居是 0，取模自动完成，无需单独处理首尾。
4. **不需要复制成两倍长度**：本题每块都要查两侧，直接取模比「拼接数组 + 偏移」更清晰。若窗口长度 $k > 3$（如 #3208），拼接成链会更方便。
5. **复杂度与数据范围**：$n \le 100$，$O(n)$ 一遍扫完即可；无任何溢出或精度问题。
6. **不要用「相邻对计数」的等价变形**：有人想统计「相邻两两不同的对数」再折算，这在环上会重复计数且边界条件繁琐，不如直接按中心判定。

## 5. 正确性证明

**引理 1（中心唯一性）**：环上任意连续 3 块瓷砖 $\{i-1, i, i+1\}$ 中，下标 $i$ 是唯一被其余两块同时相邻的那块（即「中间块」），且不同的 $i$ 对应不同的三连块。

**证明**：连续 3 块的下标集合是 $\{i-1, i, i+1\}$（模 $n$）。其中 $i-1$ 与 $i+1$ 在环上的距离为 2（当 $n > 3$ 时，二者不相邻），只有 $i$ 同时与两者相邻，故「中间块」的位置被唯一确定。若 $i \ne j$，则三连块 $\{i-1,i,i+1\}$ 与 $\{j-1,j,j+1\}$ 的中间元素不同，集合也不同（$n \ge 3$ 时长度为 3 的窗口互不相同），故对应关系是双射。∎

**引理 2（判定条件的等价性）**：三连块 $\{i-1,i,i+1\}$ 是交替组，当且仅当 $colors[i] \ne colors[i-1]$ 且 $colors[i] \ne colors[i+1]$。

**证明**：题面定义「连续 3 块颜色交替」为：除首尾外，中间那块的颜色与左边、右边都不同。由于三连块只有 3 个元素，首尾之外恰是 $i$ 这一块，「与左右都不同」正是上述两个不等式。又 $colors$ 取值只有 0/1 两种，故「都与中间不同」自动意味着左右两块同色，符合交替的直观。∎

**定理**：算法输出的计数等于交替组的数目。

**证明**：由引理 1，交替组与「中间下标 $i \in [0, n-1]$」一一对应；由引理 2，某个 $i$ 对应的三连块是交替组，当且仅当算法在第 $i$ 次迭代时把 $ans$ 加 1。算法遍历全部 $n$ 个下标且每个只处理一次，故累加值恰为交替组总数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标常数次取模与比较，$n \le 100$ 时瞬间完成。
- **空间**：$O(1)$。只用一个计数器，未开辟额外数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfAlternatingGroups(vector<int>& colors) {
        int n = colors.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            int left  = colors[(i - 1 + n) % n];   // 环的左侧，注意 +n 防负下标
            int right = colors[(i + 1) % n];
            if (colors[i] != left && colors[i] != right) ++ans;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfAlternatingGroups(self, colors: list[int]) -> int:
        n = len(colors)
        ans = 0
        for i in range(n):
            left = colors[(i - 1) % n]      # Python 负数取模即为环上左邻居
            right = colors[(i + 1) % n]
            if colors[i] != left and colors[i] != right:
                ans += 1
        return ans
```

> 💡 两段代码通过官方示例（`0`、`3`）与 $n = 3$ 的边界，并与「枚举所有长度 3 窗口 + 直接判定」的暴力实现做了 300 组随机对拍（$n \in [3,10]$），`mismatch = 0`。

## 8. 边界情况与易错点

1. **只检查一侧**：必须同时比较左右邻居，否则会把「左侧同色」或「右侧同色」的情形误判为交替组。
2. **$i = 0$ 的负下标**：C++/Java 中 `(i-1) % n` 会得到 $-1$ 并越界访问，务必写成 `(i-1+n) % n`。
3. **$n = 3$ 的特殊性**：此时三块两两相邻，中心块的两个邻居是另外两块不同的瓷砖（下标 $i-1$ 与 $i+1$ 互不相同），公式与取模写法依然成立；不要额外写「邻居是同一块」之类的特判。
4. **全同色**：所有位置都命中 `colors[i] == colors[i±1]`，返回 0（示例 1）。
5. **全交替的环**（如 $[0,1,0,1,0]$，$n$ 为奇数）：$n$ 为奇数时环不可能完全交替，必然存在一个「同色接缝」，因此答案不会是 $n$；只有 $n$ 为偶数时才可能每块都是交替中心（此时答案为 $n$）。用 $[0,1,0,1]$ 验证：每块左右都与自己不同，答案 4。
6. **不要写成「三块两两不同」**：3 块只有 0/1 两种颜色，「两两不同」永远不成立；正确条件是「中间与两侧不同」。

**延伸思考**：本题的判定可以用**差分**重写：令 $d_i = colors[i] \oplus colors[i+1]$（环上共 $n$ 条边），则 $i$ 是交替中心当且仅当 $d_{i-1} = d_i = 1$。于是问题变成「环上有多少个连续两个 1」，这直接推广到 $k$ 长度：找 $d$ 上连续 $k-1$ 个 1 的位置数，也就是 #3208 的做法。可以说 #3208 的骨架就是把「三连」换成「$k$ 连」后的差分视角。
