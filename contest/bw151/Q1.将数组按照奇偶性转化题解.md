# LeetCode 将数组按照奇偶性转化 题解

## 1. 题目概述

- **标题 / 题号**：将数组按照奇偶性转化（#3467，easy）
- **链接**：https://leetcode.cn/problems/transform-array-by-parity/
- **来源**：LeetCode 第 151 场双周赛 Q1
- **难度**：简单
- **标签**：数组、计数、排序

**题意**：给定整数数组 `nums`，按顺序执行三步操作：

1. 把每个**偶数**替换为 $0$；
2. 把每个**奇数**替换为 $1$；
3. 把修改后的数组按**非递减**顺序排序。

返回执行完这些操作后的数组。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：nums = [4,3,2,1]
输出：[0,0,1,1]
解释：偶数 4、2 变成 0，奇数 3、1 变成 1，得到 [0,1,0,1]，排序后是 [0,0,1,1]。
```

**示例 2**

```text
输入：nums = [1,5,1,4,2]
输出：[0,0,1,1,1]
解释：偶数只有 4 和 2 两个，奇数有 1、5、1 三个，排序后前 2 个是 0，后 3 个是 1。
```

**示例 3（易错）**

```text
输入：nums = [2,4]
输出：[0,0]
解释：全是偶数，结果里没有任何 1；这种全偶/全奇的情况最容易在数组下标上写错。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是把题目抄一遍：先遍历一遍替换成 $0$ 或 $1$，再调用一次 `sort`。这份代码一定正确，复杂度 $O(n \log n)$，而 $n \le 100$ 也远远跑不进超时区。

所以本题的"暴力"并不是错，而是**浪费**：我们为了把一堆只有两种取值的数排好序，付了 $O(n \log n)$ 的代价，却没有利用"只有 $0$ 和 $1$ 两种值"这个极强的前提。

### 3.2 核心观察：结果只由偶数个数决定

![奇偶替换 + 排序的本质：前 cnt 个 0，后面全是 1](images/bw151_q1_parity_partition.svg)

替换之后数组里只剩 $0$ 和 $1$。对这样一个数组做**非递减排序**，结果必然形如

$$\underbrace{0,0,\dots,0}_{cnt\ \text{个}},\ \underbrace{1,1,\dots,1}_{n-cnt\ \text{个}}$$

其中 $cnt$ 就是原数组中**偶数的个数**——因为一个元素变成 $0$ 当且仅当它是偶数。换句话说，排序这个动作在这里只起到"把所有的 $0$ 挤到前面"的作用，而这件事完全可以用计数加填充一步到位：

- 数一遍有多少个偶数，得到 $cnt$；
- 新开一个长度 $n$ 的数组，前 $cnt$ 位填 $0$，其余填 $1$。

> 💡 **一句话总结**：排序的语义被"两种取值"彻底压扁了，答案的形状只由一个计数量 $cnt$ 决定。

### 3.3 算法流程

![算法流程：一次计数，一次拼接](images/bw151_q1_algorithm_flow.svg)

```text
1. cnt = 0
2. for x in nums:
       if x 是偶数: cnt += 1
3. ans = 长度 n 的数组，前 cnt 个元素为 0，其余为 1
4. 返回 ans
```

### 3.4 示例演算

对示例 2 的 `nums = [1,5,1,4,2]`：

| 下标 | 0 | 1 | 2 | 3 | 4 |
|------|---|---|---|---|---|
| 原值 | 1 | 5 | 1 | 4 | 2 |
| 奇偶 | 奇 | 奇 | 奇 | **偶** | **偶** |
| 替换 | 1 | 1 | 1 | 0 | 0 |
| 排序后 | 0 | 0 | 1 | 1 | 1 |

偶数个数 $cnt = 2$，于是答案就是"2 个 0 + 3 个 1"，与示例输出 $[0,0,1,1,1]$ 一致。示例 1 的 $cnt = 2$、$n = 4$，得到 $[0,0,1,1]$；示例 3 的 $cnt = 2 = n$，得到 $[0,0]$。

## 4. 算法细节

1. **判定方式**：用 `x % 2 == 0` 判偶数。约束保证 $nums[i] \ge 1$，所以不必担心负数取模在 C++ 里得到 $-1$ 的老问题；如果题目放宽到负数，应该改写成 `x % 2 == 0`（对负数也成立：$-4 \% 2 = 0$，$-3 \% 2 = -1$），而不是 `x % 2 == 1` 判奇。
2. **一次分配 + 填充**：C++ 里先 `vector<int> ans(n, 1)` 再覆盖前 $cnt$ 个位置为 $0$，避免在循环里 `push_back` 扩容；Python 里直接用 `[0] * cnt + [1] * (n - cnt)` 拼接。
3. **不要真的排序**：即使数据小，`sort` 也把问题从"计数"误导成"比较"，丢掉本题最想考的那层观察。
4. **答案是新数组**：返回值与入参不是同一块内存，别在原地把 `nums` 改坏后直接返回（LeetCode 判题按返回值比较，改坏入参不影响对错，但语义上不干净）。

## 5. 正确性证明

**引理 1（替换结果唯一）**：替换步骤之后，第 $i$ 个位置的值必为 $0$（若 $nums[i]$ 为偶数）或 $1$（若 $nums[i]$ 为奇数），与其它位置无关。

**证明**：替换规则逐元素独立地规定"偶数 → $0$、奇数 → $1$"，每个整数的奇偶性是确定的，因此每个位置的结果也是确定的。∎

**引理 2（排序后的形状）**：对只含 $0$ 和 $1$ 的长度 $n$ 数组做非递减排序，排序结果必为前 $cnt$ 个 $0$、后 $n-cnt$ 个 $1$，其中 $cnt$ 是 $0$ 的个数（即偶数的个数）。

**证明**：排序后数组非递减，故所有 $0$ 必须排在所有 $1$ 之前（若某个 $0$ 出现在某个 $1$ 之后，则相邻逆序，与非递减矛盾）。又排序是重排，$0$ 的总数仍为 $cnt$，于是恰好是"前 $cnt$ 个位置为 $0$、其余为 $1$"。而由引理 1，$0$ 的个数正是原数组偶数的个数。∎

**定理**：算法返回的数组等于题目要求的数组。

**证明**：算法先统计偶数个数 $cnt$，再构造"前 $cnt$ 个 $0$、后 $n-cnt$ 个 $1$"的数组。由引理 1、引理 2，题目要求的数组正是这一形状，两者逐位相同。∎

## 6. 复杂度分析

- **时间**：$O(n)$。统计偶数个数一遍扫描，构造答案是 $O(n)$ 的填充；没有排序，也没有嵌套循环。
- **空间**：$O(n)$，即返回值本身占用的空间（不计输出则额外空间为 $O(1)$）。

补充：若直接用 `sort`，时间是 $O(n \log n)$、额外空间 $O(\log n)$（快排递归栈），在 $n \le 100$ 时都能过，但这属于"能过但不是本题的要义"。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> transformArray(vector<int>& nums) {
        int evenCnt = 0;
        for (int x : nums) {
            if (x % 2 == 0) evenCnt++;
        }
        vector<int> ans(nums.size(), 1);   // 先全部填 1
        for (int i = 0; i < evenCnt; i++) {
            ans[i] = 0;                    // 剩下的偶数位填 0
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def transformArray(self, nums: list[int]) -> list[int]:
        even_cnt = sum(1 for x in nums if x % 2 == 0)
        return [0] * even_cnt + [1] * (len(nums) - even_cnt)
```

## 8. 边界情况与易错点

1. **全是奇数**：$cnt = 0$，答案是 $n$ 个 $1$。若把"前 $cnt$ 个填 0"写成"`for i in range(cnt): ans[i] = 0`"就没问题；但若写成 `ans[cnt - 1] = 0` 就会越界（$cnt = 0$ 时下标 $-1$）。
2. **全是偶数**：$cnt = n$，答案是 $n$ 个 $0$，此时不能有任何 $1$ 残留——先整体填 $1$ 再覆盖前 $cnt$ 位的写法天然正确。
3. **$n = 1$**：单个元素，偶数输出 $[0]$、奇数输出 $[1]$，循环边界不要写成 `for i in range(1, cnt)`。
4. **负数取模**：C++ 中 `-3 % 2 == -1`，若用 `x % 2 == 1` 判奇数会漏掉负奇数。本题约束为正，但养成"判偶用 `% 2 == 0`"的习惯更安全。
5. **误以为要先排序**：本题最容易犯的思路性错误就是"老老实实 sort"，虽然能过，但把计数题做成了排序题。
6. **原地修改**：若要原地完成（把 $0$ 前移），必须用双指针或计数后重写，直接"遇到偶数就交换"容易写乱。
