# LeetCode 移除所有数组元素的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：移除所有数组元素的最小代价（#3469，medium）
- **链接**：https://leetcode.cn/problems/find-minimum-cost-to-remove-array-elements/
- **来源**：LeetCode 第 151 场双周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划

**题意**：给定整数数组 `nums`，每一步执行下列操作之一，直到数组为空：

1. 从 `nums` 的**前三个元素**中任选两个移除，代价为这两个元素中的**最大值**；
2. 如果剩下的元素**少于三个**，一次性移除全部剩余元素，代价为剩余元素中的最大值。

返回移除所有元素所需的**最小总代价**。

**约束**：

- $1 \le nums.length \le 1000$
- $1 \le nums[i] \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums = [6,2,8,4]
输出：12
解释：先删 nums[0]=6 与 nums[2]=8，代价 max(6,8)=8，剩 [2,4]；
      再把剩余的一并删掉，代价 max(2,4)=4。总代价 8+4=12。
```

**示例 2**

```text
输入：nums = [2,1,3,3]
输出：5
解释：先删 nums[0]=2 与 nums[1]=1，代价 max(2,1)=2，剩 [3,3]；
      再一次性删完，代价 3。总代价 2+3=5。
```

**示例 3（边界）**

```text
输入：nums = [7]
输出：7
解释：只剩一个元素，按"不足三个"的规则一次性删掉，代价 7。
```

## 3. 解题思路

### 3.1 暴力思路

每一步在"前三个元素"里做 $\binom{3}{2} = 3$ 种选择，最坏情况下要走约 $n/2$ 步，搜索树大小约 $3^{n/2}$——$n = 1000$ 时是天文数字。

但注意暴力的**状态**其实很稀疏：每一步只从前面删两个元素，剩余数组的形状被高度约束。把"剩余数组长什么样"搞清楚，就能把指数搜索压成多项式 DP。

### 3.2 核心观察：剩余数组 = 一个"欠着的"元素 + 一个后缀

![状态设计：欠着一个 nums 里的旧元素，前缀从 p 开始](images/bw151_q3_state_model.svg)

关键观察：**每次操作只碰前三个元素，而前三个元素永远由"一个更早被剩下的元素"和"后缀最前面的两个元素"组成**。于是任意时刻的剩余数组都能写成

$$[\ nums[i]\ ]\ +\ nums[p],\ nums[p+1],\ \dots,\ nums[n-1] \qquad (i < p)$$

其中 $nums[i]$ 是之前某一步"被留下"的那个元素（下面称它为**欠着的元素**），$nums[p..n-1]$ 是一段尚未处理的后缀。初始时取 $i = 0,\ p = 1$，正好表示整个数组。

在状态 $(i,p)$ 下，前三个元素是 $nums[i],\ nums[p],\ nums[p+1]$，三种选择分别把状态推向：

| 删除 | 代价 | 新状态 | 含义 |
|------|------|--------|------|
| $nums[i]$ 与 $nums[p]$ | $\max(nums[i], nums[p])$ | $(p+1,\ p+2)$ | 留下 $nums[p+1]$ |
| $nums[i]$ 与 $nums[p+1]$ | $\max(nums[i], nums[p+1])$ | $(p,\ p+2)$ | 留下 $nums[p]$ |
| $nums[p]$ 与 $nums[p+1]$ | $\max(nums[p], nums[p+1])$ | $(i,\ p+2)$ | 欠着的还是 $nums[i]$ |

三种转移都把 $p$ 推进 2，因此状态只可能出现在"同奇偶"的 $p$ 上，总状态数是 $O(n^2)$，DP 完全可行。

**边界**：

- $p \ge n$：只剩 $nums[i]$ 一个元素，代价 $nums[i]$；
- $p = n-1$：剩 $nums[i]$ 与 $nums[n-1]$ 两个元素，按规则一次性删完，代价 $\max(nums[i], nums[n-1])$。

> 💡 **一句话总结**：操作限制在前三个元素 ⟹ 剩余数组的形状是"1 + 后缀"，于是状态只需记"欠着谁"和"后缀起点"。

### 3.3 算法流程 / 状态转移

![所有转移都跳到 p+2，按列从右往左算，只需保留两列](images/bw151_q3_dp_layers.svg)

设 $dp(i,p)$ 为从状态 $(i,p)$ 出发删完所有元素的最小代价，则

$$
dp(i,p) = \min\begin{cases}
\max(nums[i], nums[p]) + dp(p+1,\ p+2)\\
\max(nums[i], nums[p+1]) + dp(p,\ p+2)\\
\max(nums[p], nums[p+1]) + dp(i,\ p+2)
\end{cases}
$$

边界为 $dp(i,n) = nums[i]$、$dp(i,n-1) = \max(nums[i], nums[n-1])$，答案是 $dp(0,1)$。

```text
1. 若 n == 1: 返回 nums[0]
2. 若 n == 2: 返回 max(nums[0], nums[1])
3. col[n][i]   = nums[i]                          # p = n
   col[n-1][i] = max(nums[i], nums[n-1])          # p = n-1
4. for p = n-2 down to 1:
       对每个 i < p:
           dp = min(上面三行)
5. 返回 dp(0, 1)
```

注意所有转移的右端都落在第 $p+2$ 列（以及其中的 $p$、$p+1$ 两个特殊位置），所以按 $p$ **从大到小**计算，并只保留 $p+2$ 与 $p+1$ 两列即可，空间从 $O(n^2)$ 降到 $O(n)$。

### 3.4 示例演算

![示例 1 演算：三种首步走法，最优为 12](images/bw151_q3_example_walkthrough.svg)

对 `nums = [6,2,8,4]`，初始状态 $(0,1)$，前三个是 $6,2,8$：

| 首步 | 代价 | 新状态 | 剩余 | 后续代价 | 合计 |
|------|------|--------|------|----------|------|
| 删 6、2 | 6 | $(2,3)$ | $[8,4]$ | $\max(8,4)=8$ | **14** |
| 删 6、8 | 8 | $(1,3)$ | $[2,4]$ | $\max(2,4)=4$ | **12** ✓ |
| 删 2、8 | 8 | $(0,3)$ | $[6,4]$ | $\max(6,4)=6$ | **14** |

取最小得 12，与示例输出一致。示例 2 的 `[2,1,3,3]` 三种走法分别得 $5, 6, 6$，最优 5。

## 4. 算法细节

1. **状态下标的含义**：$i$ 是"欠着的元素"的下标，$p$ 是后缀起点，永远有 $i < p$。初始化 $(0,1)$ 而不是 $(0,2)$，因为前三元组是 $nums[0], nums[1], nums[2]$。
2. **两个特殊边界**：$p = n$ 与 $p = n-1$ 必须单独写，$p \ge n+1$ 的状态不会出现（每次 $p$ 加 2，取值与初始 $p=1$ 同奇偶）。
3. **滚动列实现**：用 `cp` 表示第 $p+2$ 列、`cp1` 表示第 $p+1$ 列，计算完第 $p$ 列后整体左移一格。C++ 里再加上列长随 $p$ 递减，注意 `cur` 只需分配 $p$ 个元素。
4. **数组下标的可用性**：第 $p+2$ 列的下标范围是 $0..p+1$，所以 $dp(p+1,p+2)$ 与 $dp(p,p+2)$ 都能直接取到；实现时把第 $n$ 列开成 $n+1$ 个元素（多一个空位）最省心。
5. **用 `long long`**：单步代价最大 $10^6$，最坏约 $n/2 = 500$ 步，总和最大 $5\times 10^8$，其实 `int` 也能装下，但用 `long long` 累加更稳。
6. **不用递归**：递归深度约 $n/2 = 500$，C++ 尚可，Python 需要 `sys.setrecursionlimit`；改成按列倒推的迭代写法既无栈风险又更快。

## 5. 正确性证明

**引理 1（结构不变式）**：在任意时刻，剩余数组必可写成 $[nums[i]] + nums[p..n-1]$ 的形式（$[nums[i]]$ 可缺省），其中 $i < p$；初始时刻为 $i = 0, p = 1$。

**证明**：初始时剩余数组就是 $[nums[0]] + nums[1..n-1]$，成立。设某时刻剩余为 $[nums[i]] + nums[p..n-1]$，则前三元组是 $nums[i], nums[p], nums[p+1]$：

- 删 $nums[i]$ 与 $nums[p]$：剩余 $nums[p+1], nums[p+2], \dots$，即 $[nums[p+1]] + nums[p+2..n-1]$，对应 $(p+1, p+2)$；
- 删 $nums[i]$ 与 $nums[p+1]$：剩余 $nums[p], nums[p+2], \dots$，即 $[nums[p]] + nums[p+2..n-1]$，对应 $(p, p+2)$；
- 删 $nums[p]$ 与 $nums[p+1]$：剩余 $nums[i], nums[p+2], \dots$，即 $[nums[i]] + nums[p+2..n-1]$，对应 $(i, p+2)$。

三种情形都保持 $i < p$ 且形如"1 + 后缀"，归纳成立。∎

**引理 2（转移完备）**：状态 $(i,p)$ 下所有合法的第一步恰好是表中三种，"一次删完"只发生在剩余元素不足三个时。

**证明**：题目规定每次从前三个元素中选两个，而三元组 $\{nums[i], nums[p], nums[p+1]\}$ 的二元子集恰好 $\binom{3}{2} = 3$ 个，故三种转移穷尽所有选择。剩余元素个数为 $1 + (n - p)$，当且仅当 $p \ge n-1$ 时不超过 2，此时按规则 2 一次删完。∎

**引理 3（边界正确）**：$dp(i,n) = nums[i]$，$dp(i,n-1) = \max(nums[i], nums[n-1])$。

**证明**：$p = n$ 时剩余仅 $nums[i]$；$p = n-1$ 时剩余 $nums[i], nums[n-1]$ 两个元素，元素数少于三个，按规则 2 一次删完，代价为剩余元素最大值。∎

**定理**：$dp(i,p)$ 的递推定义给出从状态 $(i,p)$ 出发删完所有元素的最小总代价，特别地 $dp(0,1)$ 就是答案。

**证明**：对剩余元素个数 $m = 1 + (n - p)$ 做归纳。

- $m \le 2$：由引理 3，值正确。
- $m \ge 3$：由引理 2，任何最优方案的第一步必是表中三种之一。第一步的代价只取决于被删的两个元素，与后续无关，总代价 = 第一步代价 + 子状态的最小代价，而子状态的 $m' = m - 2 < m$，由归纳假设其 DP 值就是子问题最优值。于是最优方案的总代价恰为三者之一的最小值，取 $\min$ 即得最优。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。第 $p$ 列有 $p$ 个状态，每个状态常数次比较与加法，总状态数 $\sum_{p=1}^{n} p = O(n^2)$，$n = 1000$ 时约 $5\times 10^5$ 次运算。
- **空间**：$O(n)$。只保留第 $p+2$、$p+1$、$p$ 三列，每列长度不超过 $n$；朴素写法是 $O(n^2)$ 的表格。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(vector<int>& nums) {
        int n = (int)nums.size();
        if (n == 1) return nums[0];
        if (n == 2) return max(nums[0], nums[1]);

        const long long INF = (long long)4e18;   // 足够大的哨兵
        // col[i] 表示状态 (carried = i, p = 当前列号) 的最小代价
        vector<long long> colN(n + 1, 0), colN1(n, 0);
        for (int i = 0; i < n; i++) colN[i] = nums[i];          // p = n：只剩 carried
        for (int i = 0; i < n - 1; i++) colN1[i] = max(nums[i], nums[n - 1]);  // p = n-1

        vector<long long> cp = colN, cp1 = colN1;  // cp = 列 p+2，cp1 = 列 p+1
        vector<long long> cur;
        for (int p = n - 2; p >= 1; p--) {
            cur.assign(p, INF);
            for (int i = 0; i < p; i++) {
                long long a = (long long)max(nums[i], nums[p]) + cp[p + 1];
                long long b = (long long)max(nums[i], nums[p + 1]) + cp[p];
                long long c = (long long)max(nums[p], nums[p + 1]) + cp[i];
                cur[i] = min(a, min(b, c));
            }
            cp = cp1;
            cp1 = cur;
        }
        return (int)cp1[0];
    }
};
```

### Python

```python
class Solution:
    def minCost(self, nums: list[int]) -> int:
        n = len(nums)
        if n == 1:
            return nums[0]
        if n == 2:
            return max(nums[0], nums[1])

        # col[p][i] = 状态 (carried = i, 待处理起点 p) 的最小代价
        col_n = list(nums)                       # p = n：只剩 carried 一个元素
        col_n1 = [max(nums[i], nums[n - 1]) for i in range(n - 1)]  # p = n-1

        cp, cp1 = col_n, col_n1                  # cp = 列 p+2，cp1 = 列 p+1
        for p in range(n - 2, 0, -1):
            cur = [0] * p
            for i in range(p):
                a = max(nums[i], nums[p]) + cp[p + 1]
                b = max(nums[i], nums[p + 1]) + cp[p]
                c = max(nums[p], nums[p + 1]) + cp[i]
                cur[i] = min(a, b, c)
            cp, cp1 = cp1, cur
        return cp1[0]
```

## 8. 边界情况与易错点

1. **$n = 1$**：没有"前三个"，直接返回 $nums[0]$。若只写了 $n=2$ 的特判，$n=1$ 时访问 $nums[1]$ 会越界。
2. **$n = 2$**：一次删完，答案 $\max(nums[0], nums[1])$。
3. **初始状态写成 $(0,2)$**：那表示"欠着 $nums[0]$，后缀从 2 开始"，漏掉了 $nums[1]$，答案必然错。正确是 $(0,1)$。
4. **下标错位**：$dp(p+1,p+2)$ 对应"留下 $nums[p+1]$"，$dp(p,p+2)$ 对应"留下 $nums[p]$"，两者容易写反；写反后仍能过部分样例，但会在多点数据上偏大。
5. **列数组长度**：第 $p$ 列只有 $p$ 个有效下标（$i < p$），若复用同一个数组而不重置，残留的旧值会被读到。代码里用 `cur` 重新分配而不是复用。
6. **忘记 $p+2$ 边界**：$p = n-2$ 时要读第 $n$ 列，该列长度是 $n+1$（含一个空位），别忘了初始化。
7. **只是"最大值的和"**：每一步的代价是 $\max$，不是两个元素之和，也不是前缀最大值；这是本题与"合并石子"类问题的区别。
