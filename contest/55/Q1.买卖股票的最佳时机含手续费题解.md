# LeetCode 买卖股票的最佳时机含手续费 题解

## 1. 题目概述

- **标题 / 题号**：买卖股票的最佳时机含手续费（#714，medium）
- **链接**：https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-with-transaction-fee/
- **来源**：LeetCode 第 55 场周赛 Q1
- **难度**：中等
- **标签**：贪心、数组、动态规划

**题意**：给定每天的股价 `prices` 与固定手续费 `fee`，可以完成**任意多笔**交易，但任意时刻最多持有一股（必须先卖后买），且**每笔交易只收一次手续费**（一次买入 + 一次卖出算一笔，只付一次 `fee`）。求能获得的最大总利润。

**约束**：

- $1 \le n = \lvert prices \rvert \le 5 \times 10^4$
- $1 \le prices[i] < 5 \times 10^4$
- $0 \le fee < 5 \times 10^4$

> 💡 手续费是本场的唯一变量：它把 122 题「见到上涨就吃」的贪心打破——同一段上涨若被拆成两笔交易，就要多付一次 `fee`，所以「什么时候必须并成一笔、什么时候值得下车再上车」成了核心问题。

## 2. 示例

**示例 1**

```text
输入：prices = [1,3,2,8,4,9], fee = 2
输出：8
解释：最大值由两笔交易达成：
     第 1 天买入 prices[0] = 1，第 4 天卖出 prices[3] = 8，收益 (8-1)-2 = 5；
     第 5 天买入 prices[4] = 4，第 6 天卖出 prices[5] = 9，收益 (9-4)-2 = 3；
     合计 5 + 3 = 8。注意中间 1→8 的上涨段必须并成一笔，拆开会多付手续费。
```

**示例 2**

```text
输入：prices = [1,3,7,5,10,3], fee = 3
输出：6
解释：只做一笔最划算：第 1 天 1 买入、第 5 天 10 卖出，收益 10-1-3 = 6。
     若拆成两笔：(7-1-3) + (10-5-3) = 3+2 = 5，反而更差，多付了一次 fee。
```

## 3. 解题思路

### 3.1 暴力思路

所有方案都是「若干互不重叠的 (买入日, 卖出日) 对」的集合，直接枚举子集是 $O(2^n)$；写成「枚举上一笔交易的结束日」的区间 DP 也要 $O(n^2)$，$n = 5\times10^4$ 时 $10^9$ 级别，必然超时。暴力唯一的价值是：把问题**形式化**成「带权区间挑选」，从而看清它只和「当前是否持股」有关。

> ⚠️ 常见的错误贪心：把每一天的涨跌当作独立收益（`sum(max(0, p[i]-p[i-1]))`，即 122 题的答案）。加入手续费后，每次微小波动都要付一次 `fee`：示例 2 的价差之和为 $2+4+5 = 11$，而真正的最优值只有 6——多出来的部分全是重复支付的手续费。

### 3.2 核心观察：只需要「持股 / 不持股」两种状态

![两种持仓状态与四条转移](images/wc55_q1_state_machine.svg)

关键有两点：

1. **状态极少**：某一天结束时，你只有两种可能——手上有一张股票（记 `hold`），或者空仓（记 `cash`）。因为「最多持有一股」+「必须先卖后买」，历史对未来的影响被完全压缩进这一个比特。
2. **手续费只付一次**：约定 `fee` **在买入时**从现金里扣掉，卖出时不再扣。于是一笔交易的净收益自动是 $p_{\text{sell}} - p_{\text{buy}} - fee$，且「买了不卖」不会重复收费。

于是第 $i$ 天（价格为 $p$）的两条转移是：

$$hold_i = \max\bigl(hold_{i-1},\; cash_{i-1} - p - fee\bigr)$$

$$cash_i = \max\bigl(cash_{i-1},\; hold_{i-1} + p\bigr)$$

前者表示「继续持有」或「今天买入」，后者表示「继续空仓」或「今天卖出」。初始 $cash_0 = 0$、$hold_0 = -\infty$（还没买入，不可能持股）；答案就是 $cash_n$。

### 3.3 算法流程

![每天一次松弛的流程图](images/wc55_q1_dp_flow.svg)

1. 令 `cash = 0`、`hold = -∞`。
2. 依次遍历 `prices` 中的每个价格 $p$：
   - 用**旧**的 `cash` 更新 `hold`：`hold = max(hold, cash - p - fee)`；
   - 用**旧**的 `hold` 更新 `cash`：`cash = max(cash, hold + p)`。
3. 遍历结束后返回 `cash`。

两个状态互相依赖，所以要「读旧值、写新值」：把两个 `max` 在同一份旧状态上算完再一起赋值。这样两个变量始终表示「第 $i$ 天结束时」的准确值，也彻底排除了「同一天既买入又卖出」这种题面禁止的动作。

> 💡 顺带一提：本题即使写成「先更新 `hold`、再用新 `hold` 更新 `cash`」也不会算错——同日买入再卖出的净收益是 $-fee \le 0$，会被 `max` 淘汰（实测与原写法完全一致）。但状态不变量会被搅乱，遇到含冷冻期、多笔数限制的题目就会直接错，所以不要依赖这种巧合。

### 3.4 示例演算

![示例 1 的逐日状态表](images/wc55_q1_walkthrough.svg)

以 `prices = [1,3,2,8,4,9]`、`fee = 2` 为例：

| 天 $i$ | 1 | 2 | 3 | 4 | 5 | 6 |
|--------|---|---|---|---|---|---|
| $p_i$ | 1 | 3 | 2 | 8 | 4 | 9 |
| `hold` | -3 | -3 | -3 | -3 | **-1** | -1 |
| `cash` | 0 | 0 | 0 | **5** | 5 | **8** |

- 第 4 天：$8 + (-3) = 5 > 0$，卖出落袋，`cash` 由 0 变 5；
- 第 5 天：$5 - 4 - 2 = -1 > -3$，重新上车，`hold` 由 -3 变 -1；
- 第 6 天：$9 + (-1) = 8$，`cash` 由 5 变 8；此时持股仅 -1，故最终取 `cash = 8`。

## 4. 算法细节

1. **`fee` 记在买入侧**：`hold = max(hold, cash - p - fee)`、`cash = max(cash, hold + p)`。反过来把 `fee` 记在卖出侧也等价：`hold = max(hold, cash - p)`、`cash = max(cash, hold + p - fee)`，初始同样取 `hold = -∞`。两种写法只差收费时点，结果完全相同，选一种并保持一致即可。
2. **必须同时更新**：C++ 里用 `newHold` / `newCash` 两个临时量；Python 里直接写 `cash, hold = f(cash, hold), g(cash, hold)`，因为右侧整体先求值。写成「先更新 `hold` 再用新 `hold` 更新 `cash`」在本题不会改变答案（同日买卖的净收益是 $-fee \le 0$，被 `max` 淘汰），但会让「两个状态都基于第 $i-1$ 天」这个不变量失效。
3. **$-\infty$ 的取值**：`hold` 初值必须是「不可能」，C++ 用 `LLONG_MIN / 4` 而不是 `LLONG_MIN`，避免 `cash - p - fee` 下溢；Python 用 `-10**18` 即可。
4. **状态空间只有 2**：滚动变量即可，空间 $O(1)$。写 `dp[n][2]` 数组也对，但对本题是浪费。
5. **等价贪心**（同源的另一视角）：把 `fee` 前置成「有效买入价」，维护 `buy` 表示当前这笔交易的成本——若 $p + fee < buy$ 就更新 $buy \leftarrow p + fee$；若 $p > buy$ 就结算 $\text{profit} \mathrel{+}= p - buy$，并令 $buy \leftarrow p$。卖出后把 `buy` 置为 $p$（而不是 $p + fee$）是精髓：它表示「这两笔交易可以合并成一笔，`fee` 只在第一次买入时付」，恰好对应 DP 中 $cash - p - fee$ 的合并效果。
6. **答案为什么是 `cash` 而不是 $\max(cash, hold)$**：最后一天持股等价于「还没卖出」，而卖出不额外收费、价格 $p_n \ge 1 > 0$，所以卖掉一定更赚，期末必然空仓。

## 5. 正确性证明

记 $H_i, C_i$ 为「只考虑前 $i$ 天、第 $i$ 天结束时分别持股 / 空仓」的最大利润（$i = 0$ 表示还没开始交易）。

**引理 1（转移完备）**：第 $i$ 天结束时持股的方案，只有两类：第 $i-1$ 天结束时已持股且第 $i$ 天不动；或第 $i-1$ 天结束时空仓且第 $i$ 天买入。

**证明**：第 $i$ 天只有买、卖、不动三种动作。若当天卖出，结束时必然空仓，与「结束时持股」矛盾；若当天买入，则前一天结束时不能持股（最多一股），必为空仓；若当天不动，则状态与前一天相同。∎

**引理 2（递推正确）**：对任意 $i \ge 1$，有
$$H_i = \max\bigl(H_{i-1},\, C_{i-1} - p_i - fee\bigr),\qquad C_i = \max\bigl(C_{i-1},\, H_{i-1} + p_i\bigr)$$

**证明**：由引理 1，持股方案的利润上界为两类候选的最大值：不动则不超过 $H_{i-1}$；当天买入则在第 $i-1$ 天空仓最优解上再花 $p_i + fee$，即 $C_{i-1} - p_i - fee$。两个候选都可达（在已有方案后追加「不动」或「买入」即可），只是买入后利润可能为负——题目只要求最大化利润，不限制本金，所以 $C_{i-1} - p_i - fee$ 允许是负数，取 `max` 时自然会被 $H_{i-1}$ 淘汰。空仓方案同理：不动不超过 $C_{i-1}$，当天卖出为 $H_{i-1} + p_i$。∎

**引理 3（费用恰好一次）**：任意合法方案的利润等于 $\sum_{\text{每笔}} (p_{\text{sell}} - p_{\text{buy}} - fee)$，且在递推中每笔交易只在买入时扣一次 `fee`。

**证明**：每笔交易由一次买入和其后的一次卖出构成，买入时从 `cash` 中扣去 $p_{\text{buy}} + fee$，卖出时只加回 $p_{\text{sell}}$，故该笔贡献恰为 $p_{\text{sell}} - p_{\text{buy}} - fee$；不同交易在时间上不重叠、各自独立结算，`fee` 不会被重复扣除，也不会遗漏。∎

**定理**：算法返回的 `cash` 等于最大总利润。

**证明**：对 $i$ 归纳。$i = 0$ 时 $C_0 = 0$、$H_0 = -\infty$ 与实际相符。设 $i-1$ 时两状态均为最优，则由引理 2 得 $i$ 时也为最优。最终由引理 1，最优方案只可能以持股或空仓结束；若以持股结束，因 $p_n \ge 1 > 0$ 且卖出不再扣费，补上「第 $n$ 天卖出」得到利润严格更大的合法方案，矛盾。故最优方案以空仓结束，答案即 $C_n$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个价格做两次加法、两次比较、两次赋值，常数极小；无排序、无额外循环。
- **空间**：$O(1)$。只保留 `cash`、`hold` 两个变量（若写成 `dp[n][2]` 则为 $O(n)$，无必要）。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>
using namespace std;

class Solution {
public:
    int maxProfit(vector<int>& prices, int fee) {
        // cash：第 i 天结束后不持股的最大利润；hold：持股的最大利润
        long long cash = 0, hold = LLONG_MIN / 4;
        for (int p : prices) {
            long long newHold = max(hold, cash - p - fee);  // 今天买入，fee 计入成本
            long long newCash = max(cash, hold + p);        // 今天卖出，fee 已在买入时付过
            hold = newHold;
            cash = newCash;
        }
        return (int)cash;
    }
};
```

### Python

```python
class Solution:
    def maxProfit(self, prices: list[int], fee: int) -> int:
        cash, hold = 0, -10 ** 18          # 空仓 / 持股，第 0 天不持股、也不可能持股
        for p in prices:
            # 右侧全部用旧值计算，再一起赋值，避免同一天既买又卖
            cash, hold = max(cash, hold + p), max(hold, cash - p - fee)
        return cash
```

## 8. 边界情况与易错点

1. **只有一天**（$n = 1$）：买不了也卖不了，返回 0。`hold` 的初值 $-\infty$ 保证不会把「未买入」当成 0 成本持股而算出正收益。
2. **`hold` 初值写成 0**：这等于「什么都没做就有 0 成本的股票」，会把答案虚高。正确写法是 $-\infty$ / `LLONG_MIN / 4` / `-10**18`。
3. **`fee = 0`**：退化成 122 题，答案等于 $\sum_i \max(0, p_i - p_{i-1})$，DP 自动兼容，无需特判。
4. **单调下跌**（如 `[5,4,3]`）：任何交易都亏（还要付 `fee`），`hold` 始终为负、`cash` 始终为 0，返回 0。
5. **手续费吞掉全部价差**：`prices = [1,2]`、`fee = 5` 时收益 $2-1-5 < 0$，答案 0——DP 靠 `max(cash, hold + p)` 自动跳过亏损交易，不要额外写 `if`。
6. **溢出**：中间量建议用 64 位。本题实际上界为每笔最多 $5\times10^4 - 1$、至多 $n/2$ 笔，约 $1.25\times10^9 < 2^{31}-1$，`int` 放得下，但用 `long long` 计算更保险，Python 无此问题。
7. **同时更新**：`hold` 与 `cash` 应基于同一份旧状态更新。本题写成「先 `hold` 后 `cash`」恰好不至于算错（同日买卖净收益非正，被 `max` 淘汰），但这不是规律——换成 309 题的冷冻期、188 题的笔数维度就会出错，所以要养成先用旧值算完再统一赋值的习惯。

**延伸思考**：

1. 若手续费是**按成交额百分比** $r$ 收取，则买入扣 $p(1+r)$、卖出得 $p(1-r)$，转移变成 $hold = \max(hold, cash - p(1+r))$、$cash = \max(cash, hold + p(1-r))$，结构完全不变——这正是股票系列「换费用模型不改骨架」的体现。
2. 若允许**同时持有不超过 $m$ 股**，状态从 2 个变成 $m+1$ 个，复杂度 $O(nm)$；再加「最多 $k$ 笔」就是 $O(nkm)$。
3. 若要求输出**具体买卖方案**而不只是利润，只需在转移时额外记录「这次更新来自哪个候选」，回溯即可得到每天的买 / 卖 / 不动动作序列。
