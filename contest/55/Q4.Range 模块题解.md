# LeetCode Range 模块 题解

## 1. 题目概述

- **标题 / 题号**：Range 模块（#715，hard）
- **链接**：https://leetcode.cn/problems/range-module/
- **来源**：LeetCode 第 55 场周赛 Q4
- **难度**：困难
- **标签**：设计、线段树、有序集合

**题意**：实现 `RangeModule` 类，内部维护「实数轴上被跟踪的点集」，支持三种操作：

- `addRange(left, right)`：把半开区间 `[left, right)` 内的每个实数都标记为已跟踪；
- `removeRange(left, right)`：把 `[left, right)` 内已跟踪的实数取消跟踪；
- `queryRange(left, right)`：仅当 `[left, right)` **整段**都被跟踪时返回 `true`。

**约束**：

- $1 \le left < right \le 10^9$：坐标跨度到 $10^9$，**不能**开布尔数组
- 单个测试用例内 `addRange`、`removeRange`、`queryRange` 的调用总数不超过 $10^4$
- 区间是**半开**的：$[l,r)$ 含 $l$ 不含 $r$，所以 `[1, 2)` 与 `[2, 3)` 是相邻而非重叠

## 2. 示例

**示例 1（官方）**

```text
输入：
["RangeModule", "addRange", "removeRange", "queryRange", "queryRange", "queryRange"]
[[], [10, 20], [14, 16], [10, 14], [13, 15], [16, 17]]
输出：
[null, null, null, true, false, true]
解释：
addRange(10, 20)     集合 = [10, 20)
removeRange(14, 16)  集合 = [10, 14) ∪ [16, 20)，出现缺口 [14, 16)
queryRange(10, 14)   true   —— [10, 14) 全部被跟踪
queryRange(13, 15)   false  —— [14, 15) 已被移除，如 14.03 未被跟踪
queryRange(16, 17)   true   —— 16 属于 [16, 20)，删除不影响到右段
```

**示例 2（补充，相邻区间必须合并）**

```text
addRange(1, 2)      集合 = [1, 2)
addRange(2, 3)      集合 = [1, 3)     ← 相接的两段要合并成一段
queryRange(1, 3)    true
removeRange(1, 2)   集合 = [2, 3)
queryRange(1, 3)    false
```

## 3. 解题思路

### 3.1 暴力思路

| 方案 | 单次操作 | 问题 |
|------|----------|------|
| 布尔数组 `tracked[x]` | $O(len)$ | 坐标到 $10^9$，内存直接爆掉 |
| 存「全部被跟踪的单位区间」，每次操作线性扫表并重建 | $O(n)$ | $10^4$ 次操作 × $10^4$ 段，约 $10^8$ 且有大量重建，写得也不舒服 |

动态开点线段树也能做到 $O(\log C)$，但要写下推与覆盖标记，赛时容易写挂。三个操作真正的共同困难是「**定位**」：给定 $[left, right)$，要快速知道它压到了哪些已有的段 —— 而这正是**有序表上的二分**擅长的事。

### 3.2 核心观察：用「有序 + 互不相接」的区间表表示集合

![区间模型：有序不相交的半开区间表](images/wc55_q4_interval_model.svg)

被跟踪的集合永远是一个**有限个半开区间的并**。关键在于把表示法约束成：

$$\text{表中区间按左端点递增排列，且相邻两段之间必有空隙：} r_i < l_{i+1}$$

这条「互不相接」的约束带来两个直接好处：

1. **定位只需一次二分**：所有与 $[left, right)$ 有交或相接的段，在表中必然是**连续的一段**，从「第一个右端点 $\ge left$ 的段」开始，到「最后一个左端点 $\le right$ 的段」结束。
2. **查询只需看前驱**：覆盖 $left$ 的段如果有，只能是「左端点 $\le left$ 的最后一段」。若它不是一直盖到 $right$，那么它右端点之后到下一段左端点之间存在**真空**（因为 $r_i < l_{i+1}$），这段真空必落在 $[left, right)$ 里，答案就是 `false`。

> 💡 第 2 点是「必须合并相接区间」的真正原因：若允许 `[1,2)` 与 `[2,3)` 并存，`queryRange(1,3)` 取前驱得到 `[1,2)`，右端点 $2 < 3$，就会误判成 `false`。

### 3.3 算法流程

![三个操作的算法流程](images/wc55_q4_algorithm_flow.svg)

设表为 `seg`，键是左端点，值是右端点（C++ 用 `map`，Python 用两个平行数组 + `bisect`）。

**`addRange(left, right)`**
```text
pos = 第一个 start > left 的位置
若 pos 的前驱存在且 pre.end >= left，则 pos = 前驱
while pos 存在 且 pos.start <= right:
    left  = min(left,  pos.start)
    right = max(right, pos.end)
    删除 pos，pos 后移
在 pos 处插入 [left, right)
```

**`queryRange(left, right)`**
```text
pos = 最后一个 start <= left 的段
若不存在: return false
return pos.end >= right
```

**`removeRange(left, right)`**
```text
pos = 第一个 start >= left 的位置
若 pos 的前驱存在且 pre.end > left，则 pos = 前驱
while pos 存在 且 pos.start < right:
    记 (l, r) = pos，删除 pos，pos 后移
    若 l < left:  插入 [l, left)
    若 r > right: 插入 [right, r)
```

### 3.4 示例演算

![官方示例逐步演算](images/wc55_q4_walkthrough.svg)

第 2 步的关键是**切口**：删除 `[14,16)` 时 `[10,20)` 被切成 `[10,14)` 与 `[16,20)`，两段之间的空隙正是答案的来源。注意第 4 步：查询区间 $[13,15)$ 明明「大部分」被跟踪，但只要有一个点（比如 $14.5$）不在集合里，就必须返回 `false` —— 这是**整段**覆盖判定，不是相交判定。

## 4. 算法细节

1. **数据结构选型**：C++ 用 `map<int,int>`（红黑树，`upper_bound`/`lower_bound` 均 $O(\log n)$）；Python 标准库没有有序容器，用 `starts` / `ends` 两个平行有序数组配合 `bisect`，改写时用**切片赋值** `starts[i:j] = [...]` 一次完成删除与插入。
2. **定位语义要精确**：`addRange` 用「第一个 `start > left`」，再回退一格检查前驱；`removeRange` 用「第一个 `start >= left`」，同样回退一格但要判 `pre.end > left`（严格大于，因为 $end = left$ 时只是相接、并没有被删到）。
3. **合并条件是 `start <= right` 而非 `<`**：半开区间下 `[0,5)` 与 `[5,10)` 的并就是 `[0,10)`，相接即合并；漏掉等号会破坏「互不相接」不变式。
4. **`removeRange` 的两个残段都要判**：只有 `l < left` 才有左残段，只有 `r > right` 才有右残段；被删除的段若完全落在 $[left,right)$ 内，两段都不产生。
5. **迭代器/下标安全**：C++ 必须先把 `l`、`r` 存下来再 `erase`，并用 `erase` 的返回值继续遍历（`map::erase(it)` 返回下一个迭代器）；Python 必须先算好新片段列表，再做一次切片替换，避免边遍历边改动。
6. **均摊代价与免懒标记**：被删掉的段不会再回来，故「扫描过的段数」整体是 $O(\text{操作数})$ 量级；与线段树相比这里不需要下推/懒标记，表始终处于规范形态，查询天然 $O(\log n)$。
7. **坐标不用离散化**：表里只存端点，$10^9$ 与 $10^2$ 没有区别，这也是本做法相对「坐标压缩 + 线段树」的优势。

## 5. 正确性证明

**引理 1（结构不变式）**：任意时刻表中区间按左端点严格递增，且互不相接；并且它们的并集恰好等于被跟踪的集合。

**证明**：初始为空表，成立。归纳假设操作前成立。`addRange` 只把「与 $[left,right)$ 有交或相接的一段连续区间」替换成它们的并（仍是一个半开区间），替换后左邻段的右端点必小于新段左端点、右邻段的左端点必大于新段右端点（因为被吞并段之前的段右端点 $< left$、之后的段左端点 $> right$，而新段端点取的是被吞并段的端点极值），故仍严格有序且不相接，并集不变；`removeRange` 只把每个被切到的段换成它落在 $[left,right)$ 外的残段，左残段右端点为 $left$、右残段左端点为 $right$，$left < right$ 保证二者之间有空隙，与其他段的空隙也只增不减。两种操作都不改变「并集 = 被跟踪集合」，因为被改写部分的并集在操作前后分别为「原并集」与「原并集 $\cup$（或 $\setminus$）$[left,right)$」。∎

**引理 2（queryRange 判定正确）**：`queryRange(left, right)` 返回 `true` $\iff$ $[left,right) \subseteq$ 被跟踪集合。

**证明**：设 $p$ 为左端点 $\le left$ 的最后一个区间。若 $p$ 不存在，任何区间都不含 $left$，返回 `false` 正确。若 $p.b \ge right$，由引理 1 有 $p = [p.a, p.b) \supseteq [left, right)$，返回 `true` 正确。若 $p.b < right$：当 $p.b \le left$ 时 $left$ 不被任何区间覆盖（$p$ 之后各段左端点都 $> left$），返回 `false`；当 $left < p.b < right$ 时，设 $q$ 为 $p$ 的下一段（不存在时视 $q.a = +\infty$），由互不相接 $q.a > p.b$，开区间 $(p.b,\, \min(q.a, right))$ 非空且其中每个点都不被跟踪、又都在 $[left,right)$ 内，故返回 `false` 正确。∎

**定理**：`RangeModule` 的三个方法均满足题目要求。

**证明**：由引理 1，结构不变式在每次操作后成立。`addRange` 需要吞掉的区间满足 $a \le right$ 且 $b \ge left$；由引理 1，左、右端点都随下标严格递增，故这两个条件各定义一个后缀与前缀，交集是**一段连续区间**，且 `upper_bound(left)` 或它的前驱正好落在它的左端点上——所以上面那次扫描既不会漏掉任何有交/相接的段，也不会误吞不相交的段，插入后集合恰为原集合 $\cup\,[left,right)$。`removeRange` 逐个切掉与 $[left,right)$ 相交的段、保留两侧残段，集合恰为原集合 $\setminus\,[left,right)$。由引理 2，`queryRange` 精确回答整段覆盖。三者合起来即题意。∎

## 6. 复杂度分析

设表中区间个数为 $n$（$n \le$ 操作数 $\le 10^4$），单次操作被改写的区间个数为 $k$。

- **时间**：`addRange`、`removeRange` 为 $O(\log n + k)$（一次二分定位 + 扫描 $k$ 段，每段 $O(\log n)$ 的增删）；`queryRange` 为 $O(\log n)$。由均摊分析，$k$ 的总和在全部操作上不超过 $O(\text{操作数})$，故总时间 $O(T \log T)$。
- **空间**：$O(n)$，只存端点，与坐标值域 $10^9$ 无关。
- **Python 版本的差异**：标准库无有序容器，切片拼接是 $O(n)$，故 Python 单次改写为 $O(n + k)$；在 $T \le 10^4$、$n \le 10^4$ 的规模下，底层 `memmove` 总计约 $10^8$ 字节级移动，实测 $10^4$ 次随机操作约 $0.01$ 秒，完全够用。若追求严格 $O(\log n)$，可换 `sortedcontainers.SortedList`。

## 7. 参考代码

### C++

```cpp
#include <map>
#include <algorithm>
using namespace std;

class RangeModule {
    map<int, int> seg;   // 左端点 -> 右端点；有序且两两不相接
public:
    RangeModule() {}
    void addRange(int left, int right) {
        auto it = seg.upper_bound(left);              // 第一个 start > left
        if (it != seg.begin()) {
            auto pre = prev(it);
            if (pre->second >= left) it = pre;        // 前驱与本区间有交或相接
        }
        while (it != seg.end() && it->first <= right) {
            left  = min(left,  it->first);
            right = max(right, it->second);
            it = seg.erase(it);
        }
        seg[left] = right;
    }
    bool queryRange(int left, int right) {
        auto it = seg.upper_bound(left);
        if (it == seg.begin()) return false;
        --it;                                         // 左端点 <= left 的最后一段
        return it->second >= right;
    }
    void removeRange(int left, int right) {
        auto it = seg.upper_bound(left);
        if (it != seg.begin()) {
            auto pre = prev(it);
            if (pre->second > left) it = pre;         // 前驱伸进了 [left, right)
        }
        while (it != seg.end() && it->first < right) {
            int l = it->first, r = it->second;
            it = seg.erase(it);
            if (l < left)  seg[l] = left;             // 左残段
            if (r > right) seg[right] = r;            // 右残段
        }
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right


class RangeModule:
    def __init__(self):
        self.starts = []   # 有序的左端点，相邻两段之间必有空隙
        self.ends = []     # 与 starts 一一对应的右端点

    def addRange(self, left: int, right: int) -> None:
        i = bisect_left(self.starts, left)
        if i > 0 and self.ends[i - 1] >= left:
            i -= 1                                  # 前驱与本区间有交或相接
        j = i
        while j < len(self.starts) and self.starts[j] <= right:
            left = min(left, self.starts[j])
            right = max(right, self.ends[j])
            j += 1
        self.starts[i:j] = [left]                   # 一次切片替换完成合并
        self.ends[i:j] = [right]

    def queryRange(self, left: int, right: int) -> bool:
        i = bisect_right(self.starts, left) - 1     # 左端点 <= left 的最后一段
        return i >= 0 and self.ends[i] >= right

    def removeRange(self, left: int, right: int) -> None:
        i = bisect_left(self.starts, left)
        if i > 0 and self.ends[i - 1] > left:
            i -= 1
        pieces = []
        j = i
        while j < len(self.starts) and self.starts[j] < right:
            l, r = self.starts[j], self.ends[j]
            if l < left:
                pieces.append((l, left))
            if r > right:
                pieces.append((right, r))
            j += 1
        self.starts[i:j] = [p[0] for p in pieces]
        self.ends[i:j] = [p[1] for p in pieces]
```

## 8. 边界情况与易错点

1. **半开区间的等号**：跟踪 `[10,14)` 时 `queryRange(10,14)` 必须为 `true`，故判定是 `end >= right` 而不是 `end > right`；同理 `removeRange` 里前驱判 `pre.end > left` 而不是 `>=`（$end = left$ 只是相接，不属于被删范围）。
2. **相邻必须合并**：`addRange(1,2)` 之后再 `addRange(2,3)`，表里必须是 `[1,3)` 一段。若保留成两段，`queryRange(1,3)` 会因前驱 `[1,2)` 的 $2 < 3$ 而误判 `false`。
3. **删除时区间两侧都要留残段**：跟踪 `[1,20)` 时 `removeRange(5,15)` 应得到 `[1,5)` 与 `[15,20)` 两段；只写一侧是常见 WA。删除完全覆盖某段（`l >= left` 且 `r <= right`）时两侧都不产生残段。
4. **`addRange` 完全落在已有段内**：`[10,20)` 存在时 `addRange(12,15)` 不改变集合。扫描会吞掉 `[10,20)` 并把 `left/right` 扩展回 `10/20`，结果仍是一段，属于正常路径，不需要特判。
5. **删除无交集 / 空表**：空表上 `removeRange`、或所有段都在 $[left,right)$ 之外时，扫描一轮什么都不改；`queryRange` 在 `upper_bound(left) == seg.begin()` 时直接返回 `false`，不能对 `begin()` 做 `--`（未定义行为）。
6. **坐标范围与下标安全**：不要把 $10^9$ 当成数组下标（也别写 `vector<bool>`），本做法只存端点、天然免疫值域；C++ 中 `erase` 会让指向被删元素的迭代器失效，必须用返回值续跑；Python 中切片赋值的 `i:j` 必须卡在「被吞掉区间的下一个位置」，错一格就多删或少删。
