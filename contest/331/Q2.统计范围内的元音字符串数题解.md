# LeetCode 统计范围内的元音字符串数 题解

## 1. 题目概述

- **标题 / 题号**：统计范围内的元音字符串数（#2559，medium）
- **链接**：https://leetcode.cn/problems/count-vowel-strings-in-ranges/
- **来源**：LeetCode 第 331 场周赛 Q2
- **难度**：中等
- **标签**：数组、字符串、前缀和

**题意**：给定下标从 0 开始的字符串数组 `words` 与二维整数数组 `queries`。每个查询 `queries[j] = [l_j, r_j]` 要求统计 `words` 中下标落在 $[l_j, r_j]$（**闭区间**）内、且**以元音开头并以元音结尾**的字符串个数。返回数组 `ans`，`ans[j]` 为第 $j$ 个查询的答案。元音字母为 `a`、`e`、`i`、`o`、`u`。

**约束**：

- $1 \le \text{words.length} \le 10^5$
- $1 \le |\text{words}[i]| \le 40$，仅由小写英文字母组成，$\sum |\text{words}[i]| \le 3 \times 10^5$
- $1 \le \text{queries.length} \le 10^5$
- $0 \le l_j \le r_j < \text{words.length}$

> 💡 本题另有[每日题解 2559](../../solution/2501-2600/2559_统计范围内的元音字符串数.md)：侧重「标记化前缀和的思想提炼与面试表达」。本文作为周赛复盘，聚焦**赛场上的信号识别与最短路径**（从 `queries` + 闭区间计数秒连前缀和）、**正确性证明**与 **off-by-one 边界**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：words = ["aba","bcb","ece","aa","e"], queries = [[0,2],[1,4],[1,1]]
输出：[2,3,0]
解释：以元音开头和结尾的字符串是 "aba"、"ece"、"aa"、"e"。
  查询 [0,2] → "aba"、"ece"，共 2 个
  查询 [1,4] → "ece"、"aa"、"e"，共 3 个
  查询 [1,1] → "bcb" 不满足，共 0 个
```

**示例 2**

```text
输入：words = ["a","e","i"], queries = [[0,2],[0,1],[2,2]]
输出：[3,2,1]
解释：每个字符串都以元音开头和结尾：[0,2]→3、[0,1]→2、[2,2]→1。
```

**示例 3（自造：单字符、首元尾辅、单点查询）**

```text
输入：words = ["ab","a","uo","x"], queries = [[0,3],[1,2],[3,3]]
输出：[2,2,0]
解释：
- "ab" 首是元音但尾不是 → 不计；"a" 单字符首末同为元音 → 计；"uo" 首尾皆元音 → 计；"x" 皆非 → 不计；
- b = [0,1,1,0]，pre = [0,0,1,2,2]；
- [0,3] → pre[4]−pre[0] = 2−0 = 2；[1,2] → pre[3]−pre[1] = 2−0 = 2；[3,3] → pre[4]−pre[3] = 2−2 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询 $[l, r]$，从 `words[l]` 扫到 `words[r]`，逐个判定首尾字符是否为元音并计数：单次查询 $O(r-l+1)$，最坏 $O(n)$，总计 $O(nq)$。代入 $n = q = 10^5$ 得 $10^{10}$ 量级——**必然超时**，任何常数优化都救不回来。

> ⚠️ 暴力暴露的结构性浪费：**「某个字符串是否元音首尾」是它自身的属性，与任何查询无关**，但暴力让每个查询都把同一段区间的判定与求和重做一遍——重复计算了 $q$ 次。把「判定」和「区间聚合」拆开各做一次，就是本题的全部优化。

### 3.2 核心观察：多次区间计数 → 0/1 标记 + 前缀和差分

![核心观察：判定与查询解耦，0/1 标记前缀和，每查两端点相减](images/cntvowel_331_prefix_diff.svg)

赛场上读题抓三个信号词，本题应当 **3~5 分钟内切入正解**：

1. **「二维数组 `queries`，每项 $[l, r]$」**——多次区间查询，作用在**同一段静态数组**上；
2. **「统计满足某性质的元素个数」**——计数型聚合，且**每个元素的贡献独立、可加**（满足记 1，不满足记 0）；
3. **$n, q$ 均达 $10^5$**——排掉 $O(nq)$，必须做到 $O(n+q)$ 附近。

三者合起来几乎唯一地指向**一维前缀和**：先把每个 `words[i]` 在 $O(1)$ 内压成 0/1 标记

$$b[i] = \mathbb{1}\big[\text{words}[i][0] \in V \ \wedge\ \text{words}[i][-1] \in V\big],\qquad V = \{\texttt{a}, \texttt{e}, \texttt{i}, \texttt{o}, \texttt{u}\}$$

（判定只碰**首尾两个字符**，与 $|\text{words}[i]| \le 40$ 的长度无关），再建半开约定的前缀和

$$\text{pre}[0] = 0,\qquad \text{pre}[i+1] = \text{pre}[i] + b[i]\quad(0 \le i < n)$$

则任意查询 $[l, r]$ 的答案就是**两端点之差**

$$\text{ans} = \text{pre}[r+1] - \text{pre}[l]$$

判定与查询从此彻底解耦：判定做**一次** $O(n)$，$q$ 个查询每个只花**两次数组访问 + 一次减法**。

### 3.3 算法流程

![算法流程：阶段一预处理建 pre，阶段二逐查询差分](images/cntvowel_331_flow.svg)

**阶段 ① 预处理 $O(n)$**：`for i in 0..n-1`：取 `words[i]` 首尾字符各查一次元音集合；`pre[i+1] = pre[i] + 判定值`（`b` 不必单独开数组，边判边并入 `pre`）。

**阶段 ② 回答查询 $O(q)$**：`for (l, r) in queries`：`ans.push_back(pre[r+1] - pre[l])`。

### 3.4 示例演算

![示例 1 逐步演算：标记、前缀和与三查询差分](images/cntvowel_331_walkthrough.svg)

以示例 1 为例（绿 = 元音判定通过，红 = 不通过，蓝 = 前缀和，橙 = 查询结果）：

| $i$ | words[i] | 首 | 末 | $b[i]$ | $\text{pre}[i]$ | $\text{pre}[i+1]$ |
|-----|----------|----|----|--------|------------------|--------------------|
| 0 | "aba" | a | a | 1 | 0 | 1 |
| 1 | "bcb" | b | b | 0 | 1 | 1 |
| 2 | "ece" | e | e | 1 | 1 | 2 |
| 3 | "aa"  | a | a | 1 | 2 | 3 |
| 4 | "e"   | e | e（同一字符） | 1 | 3 | 4 |

三个查询：$[0,2] \to \text{pre}[3]-\text{pre}[0] = 2-0 = 2$；$[1,4] \to \text{pre}[5]-\text{pre}[1] = 4-1 = 3$；$[1,1] \to \text{pre}[2]-\text{pre}[1] = 1-1 = 0$。返回 `[2,3,0]` ✓。

注意 $i=4$ 的 `"e"` 长度为 1：首末是**同一个字符**，依旧判 1，无需任何特判；每行的 $\text{pre}[i+1]$ 恰是下一行的 $\text{pre}[i]$——前缀和是沿阶梯一格一格递推上来的。

## 4. 算法细节

1. **判定 $O(1)$，连哈希都不用**：C++ 写 5 次 `==` 的 `||` 链，Python 用 `w[0] in "aeiou"`（长 5 的子串查找，常数极小）。题目保证全小写，无需 `tolower`。
2. **半开区间约定**：`pre[i]` 定义为「前 $i$ 项标记之和」，长 $n+1$、`pre[0]=0` 当哨兵。查询用 `pre[r+1] - pre[l]`——$l=0$ 时天然合法；若改用闭区间约定 `pre[r]-pre[l-1]`，$l=0$ 直接负下标越界，还得补一个 `if`。**半开约定不是炫技，是少一个特判分支**。
3. **标记并入前缀和**：`b` 不单独存，`pre[i+1] = pre[i] + (判定)` 一步完成，少一个数组、多一分缓存友好。
4. **输出预分配**：C++ `ans.reserve(q)`；Python 用列表推导一次成型。
5. **为什么不上树状数组/线段树**：数组静态无修改，树状数组每次 $O(\log n)$ 的代价是白付的——前缀和是「无修改、只查询」的退化最优解。赛场上**能用前缀和就不碰数据结构**：代码更短、常数更小、写得更快。

## 5. 正确性证明

**引理 1（差分恒等式）**：对任意 $0 \le l \le r < n$，有 $\text{pre}[r+1] - \text{pre}[l] = \sum_{i=l}^{r} b[i]$。

**证明**：由定义 $\text{pre}[k+1] = \text{pre}[k] + b[k]$ 对 $k = l, l+1, \dots, r$ 逐项成立。将这些等式两端分别相加，中间项 $\text{pre}[l+1], \dots, \text{pre}[r]$ 在等号两侧各出现一次，伸缩相消，得 $\text{pre}[r+1] - \text{pre}[l] = \sum_{k=l}^{r} b[k]$。∎

**引理 2（判定的查询无关性）**：$b[i]=1$ 当且仅当 `words[i]` 的首字符与末字符皆为元音；该值仅由 `words[i]` 自身决定，与所有查询无关。特别地，$|\text{words}[i]| = 1$ 时首末为同一字符，判定仍良定义。

**证明**：因 $|\text{words}[i]| \ge 1$，首字符 `words[i][0]` 与末字符 `words[i][|\text{words}[i]|-1]` 都存在；长度为 1 时两下标相等、指向同一字符。判定只读这两个字符，不依赖任何查询参数。∎

**定理**：对每个查询 $[l_j, r_j]$，算法输出等于 `words[l_j..r_j]` 中以元音开头且以元音结尾的字符串个数。

**证明**：`words[i]` 满足「元音首尾」当且仅当 $b[i]=1$（引理 2），故所求个数恰为 $\sum_{i=l_j}^{r_j} b[i]$；由引理 1，该和等于 $\text{pre}[r_j+1] - \text{pre}[l_j]$，正是算法第 $j$ 步压入 `ans` 的值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + q)$（不计读入）。预处理阶段每个字符串只碰首尾两个字符，判定 $O(1)$、建 `pre` 共 $O(n)$；查询阶段 $q$ 次差分各 $O(1)$。读入成本 $O(\sum|\text{words}[i]|) \le 3\times 10^5$ 由 IO 承担。合计约 $2\times 10^5$ 次数组操作，任何语言都轻松通过。
- **空间复杂度**：$O(n)$。`pre` 长 $n+1$（$10^5$ 个 `int`，约 400KB）；`b` 已并入 `pre` 不单独存在；输出 `ans` $O(q)$ 按惯例不计。
- **对照暴力**：$O(nq) \approx 10^{10}$，比正解慢约 5 个数量级——这不是常数差距，是复杂度层面的降维。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> vowelStrings(vector<string>& words, vector<vector<int>>& queries) {
        auto isVowel = [](char c) {
            return c=='a' || c=='e' || c=='i' || c=='o' || c=='u';
        };
        int n = words.size();
        vector<int> pre(n + 1);                        // pre[i] = 前 i 项标记和，pre[0]=0 哨兵
        for (int i = 0; i < n; i++) {
            pre[i + 1] = pre[i] + (isVowel(words[i].front()) && isVowel(words[i].back()));
        }
        vector<int> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            ans.push_back(pre[q[1] + 1] - pre[q[0]]);  // 闭区间 [l,r] ↔ 半开 [l, r+1)
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def vowelStrings(self, words: List[str], queries: List[List[int]]) -> List[int]:
        vowels = set("aeiou")
        n = len(words)
        pre = [0] * (n + 1)
        for i, w in enumerate(words):
            pre[i + 1] = pre[i] + (w[0] in vowels and w[-1] in vowels)  # True/False 当 1/0
        return [pre[r + 1] - pre[l] for l, r in queries]
```

## 8. 边界情况与易错点

![off-by-one 图解：pre[r+1]−pre[l] 才覆盖 b[r]，pre[r]−pre[l] 漏最后一个](images/cntvowel_331_off_by_one.svg)

1. **off-by-one（本题最大坑）**：答案是 $\text{pre}[r+1]-\text{pre}[l]$。写成 $\text{pre}[r]-\text{pre}[l]$ 会**漏掉 $b[r]$**（示例 1 的 $[1,4]$ 会算出 2 而非 3）；写成 $\text{pre}[r+1]-\text{pre}[l+1]$ 会漏掉 $b[l]$。口诀：**闭区间 $[l,r]$ ↔ 半开 $[l, r+1)$，右端「+1」跨过 $b[r]$ 那一步，左端不动**。
2. **`pre` 开 $n+1$**：要访问 `pre[r+1]`，长度必须是 $n+1$；开成 $n$ 会在 $r = n-1$ 时越界（C++ 未定义行为，可能 WA 也可能 RE）。
3. **单字符字符串**：如 `"e"`，首末同一字符，照样判 1——不要画蛇添足写「长度至少为 2」的特判，反而把单字符串误判成 0。
4. **单点查询 $l=r$**：答案即 $b[l]$，公式 $\text{pre}[l+1]-\text{pre}[l]$ 天然正确（示例 1 的 $[1,1] \to 0$、示例 3 的 $[3,3] \to 0$）。
5. **$l=0$**：半开约定下 `pre[0]=0` 天然存在，无需特判；这正是放弃闭区间约定 `pre[r]-pre[l-1]` 的理由（§4.2）。
6. **判定别放进查询循环**：把 `isVowel(words[i]...)` 写进查询的内层循环，就退化回 $O(nq)$ 超时——判定属于预处理，全程只做一次。
7. **元音集合别记错**：只有 `a/e/i/o/u` 五个小写字母（**不含 `y`**）；题目保证全小写，无需处理大写。
8. **无需 `long long`**：答案是计数，上界 $n = 10^5$，`int` 足够——与同场 Q1（总和达 $10^{12}$ 必须 `long long`）形成对照：**先看清「计个数」还是「算总和」，再决定累加类型**。
