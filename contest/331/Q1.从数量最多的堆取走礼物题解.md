# LeetCode 从数量最多的堆取走礼物 题解

## 1. 题目概述

- **标题 / 题号**：从数量最多的堆取走礼物（#2558，easy）
- **链接**：https://leetcode.cn/problems/take-gifts-from-the-richest-pile/
- **来源**：LeetCode 第 331 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、堆（优先队列）

**题意**：给定整数数组 `gifts`，`gifts[i]` 表示第 $i$ 堆礼物的数量。每一秒你必须执行一次操作：**选择礼物数量最多的一堆**（并列最多时任选其一），把该堆的数量**减少到原数量的平方根向下取整** $\lfloor\sqrt{v}\rfloor$（即取走 $v-\lfloor\sqrt v\rfloor$ 个）。返回 $k$ 秒后剩余礼物的**总数量**。

**约束**：

- $1 \le \text{gifts.length} \le 10^3$
- $1 \le \text{gifts}[i] \le 10^9$
- $1 \le k \le 10^3$

> 💡 本题另有[每日题解 2558](../../solution/2501-2600/2558_从数量最多的堆取走礼物.md)：侧重「与 2530 的贪心对照、堆模板的横向迁移」。本文作为周赛复盘，聚焦**赛场上从题面到代码的最短路径**（识别「反复取最大」信号 → 大顶堆模板）与**开方精度、溢出等边界处理**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：gifts = [25,64,9,4,100], k = 4
输出：29
解释：
- 第 1 秒选 100，降到 ⌊√100⌋ = 10，取走 90；
- 第 2 秒选 64，降到 ⌊√64⌋ = 8，取走 56；
- 第 3 秒选 25，降到 ⌊√25⌋ = 5，取走 20；
- 第 4 秒再选 10，降到 ⌊√10⌋ = 3，取走 7；
- 各堆剩余 [5,8,9,4,3]，总数 29。
```

**示例 2**

```text
输入：gifts = [1,1,1,1], k = 4
输出：4
解释：每堆都是 1，⌊√1⌋ = 1 不变，任选哪堆都取走 0，剩余总量仍为 4。
```

**示例 3（单堆反复削弱）**

```text
输入：gifts = [10], k = 3
输出：1
解释：10 → ⌊√10⌋ = 3 → ⌊√3⌋ = 1 → ⌊√1⌋ = 1，连续三秒都命中同一堆，最终剩 1。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的实现：**每秒线性扫一遍 `gifts` 找最大值下标，原地改写为 $\lfloor\sqrt v\rfloor$**，循环 $k$ 次，最后求和。

每步扫描 $O(n)$，总复杂度 $O(n\cdot k)$。代入上限 $n=k=10^3$，约 $10^6$ 次比较，**本题规模完全能过**——签到题用暴力其实是稳的。

> ⚠️ 暴力暴露的结构：每一步都在「一群随时被改写的数里重新找当前最大」。这正是**大顶堆**的标准战场——把「找最大」从 $O(n)$ 摊到 $O(\log n)$。赛场上看到这个信号词，直接套堆模板，比暴力写得更快也更不易错。

### 3.2 核心观察：操作被题目强制 = 纯模拟，大顶堆即最优载体

![核心观察：每秒强制取最大并开方放回，大顶堆「弹顶-开方-压回」四步循环](images/takegifts_331_heap_cycle.svg)

两个关键判断：

1. **没有任何决策自由度**。与 2530「可以任选下标、需证明每步取最大最优」不同，本题**硬性规定**每秒必须操作当前最多的那一堆——你唯一的选择自由是「多个并列最大时选谁」，而这个自由不影响结果（引理 2）。所以这是**纯模拟题**，不存在贪心策略需要证明，按题意一步一步做即可。
2. **「反复取最大并改写放回」是大顶堆的肌肉记忆**。被选中的堆变小后**并不消失**，而是继续参与后续竞争——这不是一次性 Top-K，而是经典的 **pop-max + push-削弱值** 循环：弹出堆顶 $v$，压回 $\lfloor\sqrt v\rfloor$，堆自动重排。配套维护一个滚动总量 `sum`（初始为 $\sum \text{gifts}[i]$），每步 `sum -= v - ⌊√v⌋`，$k$ 步后 `sum` 即答案。

### 3.3 算法流程

1. 把 `gifts` 全部装入大顶堆（C++ `priority_queue<int>` 迭代器区间构造，Floyd 建堆 $O(n)$；Python `heapq` 存 $-x$ 后 `heapify`，$O(n)$），同时 `sum = Σ gifts[i]`；
2. 循环 $k$ 次：
   - 弹出堆顶 $v$（当前最大）；
   - 计算 $s = \lfloor\sqrt v\rfloor$（向下取整，注意精度，见 §8）；
   - `sum -= v - s`（移走 $v-s$ 个礼物）；
   - 把 $s$ 压回堆；
3. 返回 `sum`。

> 💡 **为何维护滚动 `sum` 而非最后遍历堆求和？** `priority_queue` 不暴露迭代器，收尾求和得把 $n$ 个元素逐个 `pop`，多花 $O(n\log n)$。滚动 `sum` 每步 $O(1)$ 更新，结束直接返回。Python 的堆虽是列表可 `sum(heap)`，但存的是负数，不如滚动 `sum` 直观。

### 3.4 示例演算

![示例 1 逐步演算：弹出 100/64/25/10，回写 10/8/5/3，滚动 sum 从 202 减到 29](images/takegifts_331_walkthrough.svg)

以示例 1 为例（红 = 弹出的最大，绿 = 开方回写）：

| 步 | 弹出 $\max\ v$ | 回写 $\lfloor\sqrt v\rfloor$ | 移走 $v-\lfloor\sqrt v\rfloor$ | 堆内剩余（降序） | 合计 |
|----|----------------|------------------------------|--------------------------------|-------------------|------|
| 初始 | — | — | — | $\{100, 64, 25, 9, 4\}$ | 202 |
| 1 | 100 | 10 | 90 | $\{64, 25, 10, 9, 4\}$ | 112 |
| 2 | 64 | 8 | 56 | $\{25, 10, 9, 8, 4\}$ | 56 |
| 3 | 25 | 5 | 20 | $\{10, 9, 8, 5, 4\}$ | 36 |
| 4 | 10 | 3 | 7 | $\{9, 8, 5, 4, 3\}$ | 29 |

$$\text{sum} = 202 - (90+56+20+7) = 29 \ \checkmark$$

注意第 1 步回写的 $10$ 小于 $64$，第 2 步堆自动改弹 $64$；第 4 步堆顶已是 $10$（不再是初始最大）——「当前最大」始终由堆维护，无需任何手动判断。

## 4. 算法细节

1. **建堆 $O(n)$**：C++ 用 `priority_queue<int> pq(gifts.begin(), gifts.end())` 区间构造（底层 Floyd 建堆），优于逐个 `push` 的 $O(n\log n)$；Python 把数组取负后 `heapq.heapify` 原地建堆。
2. **Python 大顶堆套路**：`heapq` 只有小顶堆，**存 $-x$**——`heappop` 弹出最小（最负）即原数最大，取反还原。这是 Python 堆题的标配写法。
3. **整数开方**：$\lfloor\sqrt v\rfloor$ 不能盲目信任浮点 `sqrt` 强转——$v$ 达 $10^9$ 时个别完全平方数边界可能因舍入差 $1$。Python 用 `math.isqrt(v)`（整数精确、零浮点误差）；C++ 先 `s = (int)sqrt((double)v)` 估值，再 `while ((long long)(s+1)*(s+1) <= v) ++s;` 上升修正，**平方必须用 `long long`**（$s\approx 31623$ 时 $(s+1)^2\approx 10^9$ 贴近 32 位上界）。
4. **答案类型**：剩余总量最坏 $10^3 \times 10^9 = 10^{12}$，超出 32 位 `int`（约 $2.1\times 10^9$），C++ 返回值用 `long long`；Python 整数任意精度无此忧。

## 5. 正确性证明

**引理 1（收缩性）**：对 $v \ge 2$，有 $1 \le \lfloor\sqrt v\rfloor < v$；对 $v = 1$，$\lfloor\sqrt 1\rfloor = 1$。

**证明**：$v \ge 2$ 时 $\sqrt v < v$（因 $v > 1$ 且两边平方得 $v < v^2$ 成立），故 $\lfloor\sqrt v\rfloor \le \sqrt v < v$；又 $\sqrt v \ge 1$ 给出 $\lfloor\sqrt v\rfloor \ge 1$。$v=1$ 时 $\sqrt 1 = 1$，开方为不动点。∎

**引理 2（并列不变性）**：某步存在多堆并列最大 $v$ 时，选其中任一堆，$k$ 步后的剩余总量相同。

**证明**：把状态看作**多重集** $S$（只有各堆的数量参与后续竞争，堆的身份无关）。操作为「删去一个最大值 $v$、加入 $\lfloor\sqrt v\rfloor$」——当有多个并列最大 $v$ 时，无论删哪一个，得到的多重集相同，故 $T(S)$ 是**良定义的映射**。对 $k$ 归纳：状态序列 $S_0, T(S_0), \dots, T^k(S_0)$ 由初始多重集与 $k$ 唯一决定，与每步选哪个并列堆无关，剩余总量随之唯一。∎

**定理**：算法返回值等于 $k$ 次操作后的礼物剩余总量。

**证明**：归纳证明**堆不变量**：循环每轮开始时，堆中元素恰为当前各堆数量构成的多重集。初始建堆后成立；每轮弹出堆顶（最大值 $v$，由引理 2 与选哪个并列堆无关）并压回 $\lfloor\sqrt v\rfloor$，恰是题意规定的一步操作，不变量保持。同时 `sum` 初值为总量，每轮减去移走量 $v-\lfloor\sqrt v\rfloor$，归纳知 `sum` 恒等于当前总量。故 $k$ 轮后返回的 `sum` 即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k\log n)$。Floyd 建堆 $O(n)$；$k$ 轮循环各一弹一压，每次 $O(\log n)$；开方 $O(1)$。代入 $n,k\le 10^3$ 约 $10^4$ 量级，微秒级通过。
- **空间复杂度**：$O(n)$。堆存全部 $n$ 个元素（每轮弹一压一，大小恒为 $n$），另有常数个标量。
- **对照暴力**：$O(n\cdot k)$ 约 $10^6$，本题也能过；但堆写法在 $n,k$ 提到 $10^5$ 时依旧从容（2530 即该规模）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long pickGifts(vector<int>& gifts, int k) {
        priority_queue<int> pq(gifts.begin(), gifts.end()); // 大顶堆，O(n) 建堆
        long long sum = 0;
        for (int g : gifts) sum += g;                       // 初始总量（long long）
        while (k-- > 0) {
            int v = pq.top();
            pq.pop();
            int s = (int)sqrt((double)v);                   // ⌊√v⌋ 估值（可能偏小 1）
            while ((long long)(s + 1) * (s + 1) <= v) ++s;  // 上升修正浮点误差
            sum -= (v - s);                                 // 移走 v - s 个
            pq.push(s);
        }
        return sum;
    }
};
```

### Python

```python
class Solution:
    def pickGifts(self, gifts: List[int], k: int) -> int:
        heap = [-x for x in gifts]      # 取负模拟大顶堆
        heapq.heapify(heap)             # 原地建堆 O(n)
        total = sum(gifts)
        for _ in range(k):
            v = -heapq.heappop(heap)    # 弹出当前最大
            s = math.isqrt(v)           # 整数开方，精确无浮点误差
            total -= v - s              # 移走 v - s
            heapq.heappush(heap, -s)    # 削弱后放回
        return total
```

## 8. 边界情况与易错点

![√ 指数收缩、堆顶为 1 提前终止与浮点开方精度修正](images/takegifts_331_sqrt_shrink.svg)

1. **溢出（最大坑）**：剩余总量最坏 $10^3 \times 10^9 = 10^{12}$，超出 32 位 `int`。C++ 的 `sum` 与返回值必须 `long long`；只把开方修正的平方写成 `long long` 而忘改 `sum`，照样 WA。
2. **开方精度**：`(int)sqrt(v)` 在完全平方数边界可能因浮点舍入差 $1$。Python 一律 `math.isqrt`；C++ 估值后用 `while ((s+1)*(s+1) <= v) ++s;` 修正，且**修正里的平方用 `long long`**（$s \approx 31623$ 时 $(s+1)^2 \approx 10^9$ 贴近上界）。
3. **$k$ 远大于有效操作数**：全部堆都降到 $1$ 后，每步弹 $1$ 压 $1$、移走 $0$，循环空转——本题 $k\le 10^3$ 无所谓；若 $k$ 大到 $10^9$，应在堆顶 $v=1$ 时 `break`（堆顶是全局最大，它为 $1$ 则全体为 $1$），复杂度从 $O(k\log n)$ 降为约 $O(n\log n\cdot\log\log(\max))$。
4. **并列最大无需特判**：多个堆同为最大时任选其一，最终结果相同（引理 2），堆天然只会弹出其中任意一个，不需要任何额外逻辑。
5. **单堆 / 全 $1$**：$n=1$ 时同一堆被连续削弱（示例 3）；全 $1$ 时（示例 2）每步移走 $0$，照常循环 $k$ 次即可，不会死循环（循环以 $k$ 计数）。
6. **别把「取走」当成「删除」**：被削弱的堆仍留在堆中参与后续竞争，误用「弹出后不压回」或「先取 $k$ 个最大再各自开方一次」都会 WA——前者丢堆，后者错误地让每堆至多被操作一次。
