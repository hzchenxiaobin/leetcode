# LeetCode 统计重复个数 题解

## 1. 题目概述

- **标题 / 题号**：统计重复个数（#466，hard）
- **链接**：https://leetcode.cn/problems/count-the-repetitions/
- **来源**：LeetCode 第 11 场周赛 Q4
- **难度**：困难
- **标签**：双指针、字符串、动态规划

**题意**：记 $[s, n]$ 为把字符串 $s$ 重复 $n$ 次得到的串。给定 $s_1, n_1, s_2, n_2$，令 $\text{str}_1 = [s_1, n_1]$、$\text{str}_2 = [s_2, n_2]$。若从 $\text{str}_1$ 中删去若干字符能得到 $\text{str}_2$ 重复 $m$ 次，就称 $[\text{str}_2, m]$ 可从 $\text{str}_1$ 获得。求**最大**的 $m$。换句话说：把 $s_2$ 当作模板反复匹配 $\text{str}_1$ 的**子序列**，最多能完整匹配多少份 $s_2$，再按每 $n_2$ 份打包成一个 $\text{str}_2$。

**约束**：

- $1 \le \lvert s_1 \rvert, \lvert s_2 \rvert \le 100$，只含小写英文字母
- $1 \le n_1, n_2 \le 10^6$，于是 $\lvert \text{str}_1 \rvert$ 可达 $10^8$：**字符串本身不可能真的构造出来**，这是本题的核心矛盾

## 2. 示例

**示例 1**

```text
输入：s1 = "acb", n1 = 4, s2 = "ab", n2 = 2
输出：2
解释：str1 = "acbacbacbacb"，从中依次能抠出 4 个 "ab"：
      a(0)b(2) | a(3)b(5) | a(6)b(8) | a(9)b(11)
      所以最多 4 份 s2 = 2 份 [s2, 2]，但抠不出第 5 个 "ab"，故 m = ⌊4 / 2⌋ = 2。
```

**示例 2**

```text
输入：s1 = "acb", n1 = 1, s2 = "acb", n2 = 1
输出：1
解释：str1 = str2 = "acb"，恰好 1 份，m = 1。
```

**补充示例（便于体会环的存在）**

```text
输入：s1 = "a", n1 = 5, s2 = "aa", n2 = 1
输出：2
解释：str1 = "aaaaa"，贪心可凑出 2 份 "aa"（剩 1 个 a 作废），m = ⌊2 / 1⌋ = 2。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是展开出 $\text{str}_1$（长度最高 $10^8$），再用双指针贪心统计能匹配多少份 $s_2$：

- **空间爆炸**：$10^8$ 个字符约 100 MB，直接 MLE；
- **即便流式扫描**：也要 $O(n_1 \lvert s_1 \rvert) = 10^8$ 次逐字符比较，虽然勉强可过，但完全没有利用「$s_1$ 反复出现」这个强结构；
- **更差的写法**：枚举 $m$ 从大到小逐个判定，复杂度再乘一个 $m$，必然 TLE。

真正的浪费在于：**每一块的扫描过程都长得一模一样**，只是入口状态不同。

### 3.2 核心观察：贪心 + 块级状态机

![块划分与状态空间](images/wc11_q4_block_state.svg)

**第一步：贪心就是最优。** 把 $s_2$ 看成模板，维护指针 $p$ 表示「$s_2$ 中下一个待匹配字符的下标」。从左到右扫描 $\text{str}_1$，遇到等于 $s_2[p]$ 的字符就吃掉并 `p++`；$p$ 走到 $\lvert s_2 \rvert$ 时说明凑满一份 $s_2$，计数加一并令 $p = 0$。坚持「能匹配就立刻匹配」不会让后续变差（§5 引理 1 给出证明），于是扫描结束后得到的份数 $cnt$ 就是 $\text{str}_1$ 最多能容纳的 $s_2$ 个数。

**第二步：答案只差一次除法。** $\text{str}_2$ 重复 $m$ 次共需要 $m \cdot n_2$ 份 $s_2$，所以

$$m = \left\lfloor \frac{cnt}{n_2} \right\rfloor$$

问题彻底转化为：**如何在不展开 $\text{str}_1$ 的前提下求出 $cnt$**。

**第三步：按块建立状态机。** 把 $\text{str}_1$ 切成 $n_1$ 块，每块都是一个 $s_1$。把「第 $i$ 块开始前指针停在 $s_2$ 的哪个位置」记作 $p_i$（$p_0 = 0$）。块内扫描只依赖入口 $p_i$，因此可以预处理出确定的转移：

$$p_{i+1} = f(p_i), \qquad \text{第 } i \text{ 块新增份数} = gain(p_i)$$

关键事实：**状态 $p$ 只有 $\lvert s_2 \rvert \le 100$ 种取值**。$n_1$ 最大 $10^6$，而状态序列 $p_0, p_1, \dots$ 落在一个只有 100 个格子的抽屉里——由鸽笼原理，前 $\lvert s_2 \rvert + 1$ 个状态里必有两个相同，即**必然成环**。环一旦出现，后面的过程就是无限复读，可以用一次除法跳完。

### 3.3 算法流程 / 状态转移

![算法流程](images/wc11_q4_cycle_flow.svg)

1. **预处理转移表**：对每个 $p_0 \in [0, \lvert s_2 \rvert)$，实际扫一遍 $s_1$ 得到 $f(p_0)$ 与 $gain(p_0)$。复杂度 $O(\lvert s_2 \rvert \cdot \lvert s_1 \rvert) \le 10^4$。
2. **主循环**：维护 `block`（已处理块数）、`p`（当前状态）、`total`（累计完成的 $s_2$ 份数），并用 `first[p]`、`total_at[p]` 记住状态 $p$ 首次出现的块号与该时刻的 `total`。每轮：若 `first[p]` 尚未记录，则写下 `first[p] = block`、`total_at[p] = total`，再 `total += gain[p]; p = f(p); block++`；若已有记录，则取 $L = block - first[p]$、$G = total - total_at[p]$、$k = \lfloor (n_1 - block)/L \rfloor$，执行 `total += k*G; block += k*L` 后跳出。
3. **尾部补算**：跳出后剩余不足一环的块（少于 $L \le \lvert s_2 \rvert$ 块）逐块累加 `gain[p]`。
4. **返回** `total / n2`（整除）。

由于 $L \le \lvert s_2 \rvert$，主循环最多跑 $\lvert s_2 \rvert + 1$ 轮，整段逻辑与 $n_1$ 无关。

### 3.4 示例演算

![示例演算](images/wc11_q4_walkthrough.svg)

对示例 1 的 $s_1 = \text{"acb"}$、$s_2 = \text{"ab"}$（$n_1 = 4$，$n_2 = 2$），先看转移表：

| 入口 $p$ | 块内扫描 "acb" | 结束 $f(p)$ | $gain(p)$ |
|---|---|---|---|
| 0（缺 "a"） | a@0 命中 → 缺 "b"；b@2 命中 → 完成 1 份 | 0 | 1 |
| 1（缺 "b"） | a@0、c@1 都跳过；b@2 命中 → 完成 1 份 | 0 | 1 |

再跑主循环：

| block | 起始 $p$ | 处理方式 | 累计 total |
|---|---|---|---|
| 0 | 0 | 首次见 0，记录 `first[0]=0, total_at[0]=0`，模拟一块 | 1 |
| 1 | 0 | 0 已出现过 → 成环，$L = 1-0 = 1$，$G = 1-0 = 1$ | — |

$k = \lfloor (4-1)/1 \rfloor = 3$，于是 $total = 1 + 3 \times 1 = 4$，`block = 4` 已到 $n_1$，尾部为空。答案 $m = \lfloor 4/2 \rfloor = 2$，与官方输出一致。

## 4. 算法细节

1. **状态定义必须只含 $p$**：若把「$(p, \text{已完成份数})$」当成状态，状态空间是无限的，环永远检测不到。正确做法是用**块边界上的 $p$**，配合 `first[p]` 同时存下「块号 + 当时的累计份数」，才能算出环长 $L$ 与环增益 $G$。
2. **记录时机**：`first[p]`、`total_at[p]` 必须在「模拟这一块之前」写入，否则环长会算错一位，示例 1 会退化成 $L = 1$、$G = 0$。
3. **$gain$ 不一定是 0/1**：当 $\lvert s_1 \rvert \ge \lvert s_2 \rvert$ 时一块能完成多份（如 $s_1 = \text{"aaaa"}$、$s_2 = \text{"a"}$ 时 $gain = 4$）。跳跃公式必须乘 $G$，不能写成「每环加 1」。
4. **环增益可能为 0（自环）**：$s_1 = \text{"a"}$、$s_2 = \text{"ba"}$ 时 $f(0) = 0$、$gain(0) = 0$，成环后 $G = 0$。跳跃公式必须允许 $G = 0$ 且 $k$ 任意大，并且 `break` 要紧跟在跳跃之后，否则会原地打转。
5. **整数除法方向**：$k$ 用向下取整，`block += k * L` 保证不越界；最后的 `total / n2` 也是向下取整——两者都不能四舍五入。
6. **数据范围**：$cnt \le \lvert s_1 \rvert n_1 / \lvert s_2 \rvert \le 10^8$，$k \cdot G$ 同阶，`int` 足够（$2^{31} \approx 2.1 \times 10^9$）；本解仍用 `long long` 保存 `total`，避免心算失误。
7. **可选剪枝**：若 $s_2$ 中某个字符在 $s_1$ 中根本不出现，则 $cnt$ 恒为 0，可直接返回 0。

## 5. 正确性证明

**引理 1（贪心最优）**：对任意字符串 $T$，设贪心扫描得到的完整 $s_2$ 份数为 $cnt(T)$，则对任意整数 $k \ge 0$，$[s_2, k]$ 是 $T$ 的子序列 $\iff k \le cnt(T)$。

**证明**：
（$\Leftarrow$）贪心确实在 $T$ 中为每个被计数的 $s_2$ 找到了互不重叠、位置递增的字符，取前 $k$ 份即得一个合法嵌入。
（$\Rightarrow$）设 $[s_2, k]$ 有某个嵌入，其字符位置依次为 $q_1 < q_2 < \cdots < q_{k\lvert s_2 \rvert}$。对贪心的第 $t$ 步（$t$ 从 1 计）做归纳：贪心每步都选「当前位置之后最靠前的匹配字符」，故贪心第 $t$ 步选中的位置 $r_t \le q_t$。于是贪心在前 $k\lvert s_2 \rvert$ 步内不会失败，至少完成 $k$ 份，即 $cnt(T) \ge k$。∎

**引理 2（块转移等价）**：设第 $i$ 块（$0$ 起）开始前的指针为 $p_i$，则 $p_{i+1} = f(p_i)$，且第 $i$ 块内完成的份数恰为 $gain(p_i)$；从而 $cnt(\text{str}_1) = \sum_{i=0}^{n_1-1} gain(p_i)$。

**证明**：块内扫描是对 $s_1$ 的确定性循环，「遇到 $s_2[p]$ 就前进」只依赖入口 $p$ 与 $s_1$ 本身，故 $f, gain$ 与块号无关；对 $i$ 归纳即得。再由引理 1 与贪心的定义，逐块累加的结果就是整体贪心的计数。∎

**引理 3（环的周期性与外推）**：若存在 $0 \le a < b \le n_1$ 使 $p_a = p_b$，则对一切满足 $b + j \le n_1$ 的 $j \ge 0$，都有 $p_{b+j} = p_{a+j}$、$gain(p_{b+j}) = gain(p_{a+j})$。

**证明**：对 $j$ 归纳。$j = 0$ 时 $p_a = p_b$ 是题设。设 $p_{b+j} = p_{a+j}$，则 $p_{b+j+1} = f(p_{b+j}) = f(p_{a+j}) = p_{a+j+1}$，且 $gain$ 之值只由状态决定，故相等。∎

**引理 4（答案与 $cnt$ 的关系）**：$[\text{str}_2, m]$ 可从 $\text{str}_1$ 获得 $\iff m \cdot n_2 \le cnt(\text{str}_1)$。

**证明**：$[\text{str}_2, m] = [s_2, m n_2]$，直接套用引理 1（取 $T = \text{str}_1$、$k = m n_2$）。∎

**定理**：算法返回的值就是题面要求的最大 $m$。

**证明**：主循环按引理 2 逐步累加 $gain$，遇环后按引理 3 一次性补上 $k \cdot G$（等价于把剩余 $k \cdot L$ 块的 $gain$ 逐个相加），尾部再逐块补完，故结束时 `total` $= cnt(\text{str}_1)$。返回值为 $\lfloor cnt/n_2 \rfloor$，由引理 4，它使 $m n_2 \le cnt$ 且 $m$ 最大。∎

## 6. 复杂度分析

- **时间**：预处理 $O(\lvert s_2 \rvert \cdot \lvert s_1 \rvert)$（至多 $100 \times 100$）；主循环最多 $\lvert s_2 \rvert + 1$ 轮，每轮 $O(1)$ 查表；尾部不足一环亦为 $O(\lvert s_2 \rvert)$。总计 $O(\lvert s_2 \rvert \cdot \lvert s_1 \rvert)$，**与 $n_1, n_2$ 完全无关**。
- **空间**：转移表 $nxt, gain$、`first`、`total_at` 各 $O(\lvert s_2 \rvert)$，无字符串展开，总计 $O(\lvert s_2 \rvert)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int getMaxRepetitions(string s1, int n1, string s2, int n2) {
        int m2 = s2.size();
        // 预处理：nxt[p] / gain[p] = 从 p 出发扫完一整块 s1 后的指针与新增完成数
        vector<int> nxt(m2), gain(m2);
        for (int p0 = 0; p0 < m2; p0++) {
            int p = p0, g = 0;
            for (char ch : s1) {
                if (ch == s2[p]) {
                    if (++p == m2) { p = 0; g++; }
                }
            }
            nxt[p0] = p;
            gain[p0] = g;
        }

        vector<int> first(m2, -1);      // 状态 p 首次出现在第几块开头
        vector<long long> totalAt(m2, 0); // 那一刻累计完成的 s2 份数
        int p = 0, block = 0;
        long long total = 0;
        while (block < n1) {
            if (first[p] >= 0) {        // 成环：一次跳完剩余块
                long long L = block - first[p];
                long long G = total - totalAt[p];
                long long k = (long long)(n1 - block) / L;
                total += k * G;
                block += (int)(k * L);
                break;
            }
            first[p] = block;
            totalAt[p] = total;
            total += gain[p];
            p = nxt[p];
            block++;
        }
        while (block < n1) {            // 不足一环的尾巴，逐块补算
            total += gain[p];
            p = nxt[p];
            block++;
        }
        return (int)(total / n2);
    }
};
```

### Python

```python
class Solution:
    def getMaxRepetitions(self, s1: str, n1: int, s2: str, n2: int) -> int:
        m2 = len(s2)
        # 预处理：nxt[p] / gain[p] = 从 p 出发扫完一整块 s1 后的指针与新增完成数
        nxt, gain = [0] * m2, [0] * m2
        for p0 in range(m2):
            p, g = p0, 0
            for ch in s1:
                if ch == s2[p]:
                    p += 1
                    if p == m2:
                        p, g = 0, g + 1
            nxt[p0], gain[p0] = p, g

        first = [-1] * m2            # 状态 p 首次出现在第几块开头
        total_at = [0] * m2          # 那时累计完成的 s2 份数
        p = block = total = 0
        while block < n1:
            if first[p] >= 0:        # 成环：一次跳完剩余块
                cyc_len = block - first[p]
                cyc_gain = total - total_at[p]
                k = (n1 - block) // cyc_len
                total += k * cyc_gain
                block += k * cyc_len
                break
            first[p], total_at[p] = block, total
            total += gain[p]
            p = nxt[p]
            block += 1

        while block < n1:            # 不足一环的尾巴，逐块补算
            total += gain[p]
            p = nxt[p]
            block += 1

        return total // n2
```

## 8. 边界情况与易错点

1. **永远匹配不上**：$s_2$ 含有 $s_1$ 里没有的字符（如 $s_1 = \text{"b"}$、$s_2 = \text{"a"}$），此时 `gain` 全为 0，环增益 $G = 0$，`total` 保持 0，返回 0。注意 `k` 必须允许为 0，且循环要有 `break` 出口，否则会死循环。
2. **$n_1 = 1$**：主循环跑一块就结束，`first[p]` 记录后 `block == n1`，不会进入环逻辑，退化为一次普通扫描，结果应当正确（示例 2 即此情况）。
3. **第一块就成环**：示例 1 中 `p₁ = p₀ = 0`，若把「记录 `first[p]`」放在模拟之后，会得到 $L = 1, G = 0$ 的假环，答案错误。顺序必须是「先查环 → 再记录 → 再推进」。
4. **一块完成多份**：$s_1 = \text{"aaaa"}$、$s_2 = \text{"a"}$ 时 $gain = 4$；若跳跃时写成 `total += k`，答案会小 4 倍。
5. **尾部不能省**：$k = \lfloor (n_1 - block)/L \rfloor$ 可能为 0（剩余块数不足一环），跳完后也可能仍有 `(n1 - block) % L` 块余量，这些都必须靠尾部循环逐块补算，否则漏掉最后一截 `gain`。
6. **溢出与取整**：$k \cdot G \le 10^8$，`int` 不会溢出，但把 `total` 统一成 `long long` 更省心；$k$ 与最后的 `total / n2` 两处除法都必须向下取整，不能四舍五入。
