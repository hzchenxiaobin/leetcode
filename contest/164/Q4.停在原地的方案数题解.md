# LeetCode 停在原地的方案数 题解

## 1. 题目概述

- **标题 / 题号**：停在原地的方案数（#1269，hard）
- **链接**：https://leetcode.cn/problems/number-of-ways-to-stay-in-the-same-place-after-some-steps/
- **来源**：LeetCode 第 164 场周赛 Q4
- **难度**：困难
- **标签**：动态规划

**题意**：数组下标为 $0 \sim arrLen-1$，指针一开始在 $0$。每一步三选一：左移 1 格、右移 1 格、原地不动，任何时刻都不能移出数组。求**恰好**执行 $steps$ 步后指针仍在索引 $0$ 的方案数，结果对 $10^9+7$ 取模。

**约束**：

- $1 \le steps \le 500$
- $1 \le arrLen \le 10^6$

> 💡 本题的张力全在两个数字的反差里：$arrLen$ 高达 $10^6$，而 $steps$ 只有 500。谁能把「数组长度」这一维砍掉，谁就能过。

## 2. 示例

**示例 1**

```text
输入：steps = 3, arrLen = 2
输出：4
解释：3 步后停在索引 0 的 4 种走法
      右, 左, 不动
      不动, 右, 左
      右, 不动, 左
      不动, 不动, 不动
```

**示例 2**

```text
输入：steps = 2, arrLen = 4
输出：2
解释：右, 左 与 不动, 不动
```

**示例 3**

```text
输入：steps = 4, arrLen = 2
输出：8
解释：位置只能取 0 或 1，既不能走到 2、也不能走到 -1，
      4 步后回到 0 的走法共 8 条。
```

## 3. 解题思路

### 3.1 暴力思路

三种操作意味着长度为 $steps$ 的操作序列共 $3^{steps}$ 条：DFS 枚举、最后统计停在 0 的条数，复杂度 $O(3^{steps})$。$steps = 500$ 时 $3^{500} \approx 10^{238}$，天文数字。

退一步，「按步数递推」的二维 DP 是很自然的想法：$f(s,p)$ 表示走 $s$ 步后位于 $p$ 的方案数，则

$$f(s,p) = f(s-1,p-1) + f(s-1,p) + f(s-1,p+1)$$

但如果直接把 $p$ 开到 $arrLen$，状态数是 $500 \times 10^6 = 5\times10^8$：时间上 $5\times10^8$ 次加法已经悬，空间上要存 $5\times10^8$ 个 `int`（约 2 GB），**内存直接爆炸**。所以真正的难点不是「转移怎么写」，而是「$p$ 到底需要开多大」。

### 3.2 核心观察：位置只需 $0 \sim \lfloor steps/2\rfloor$

![只保留能回到 0 的位置](images/wc164_q4_state_truncation.svg)

盯着一条**最终回到 0** 的路径看：它在时刻 $t$ 的位置 $p$ 必须满足两个条件。

- 前 $t$ 步每步最多右移 1 格，所以 $p \le t$；
- 后 $steps-t$ 步要从 $p$ 降回 0，每步最多左移 1 格，所以 $p \le steps-t$。

把两笔账加起来（或者直接说：去 $p$ 至少要 $p$ 次右移，回来至少要 $p$ 次左移），得到 $2p \le steps$，即

$$p \le \left\lfloor \frac{steps}{2} \right\rfloor$$

于是 DP 表只需 $m$ 列：

$$m = \min\left(arrLen,\ \left\lfloor \frac{steps}{2}\right\rfloor + 1\right) \le 251$$

这正是官方提示里那句「复杂度与 arrLen 无关」的由来：数组长度从 $10^6$ 被截到 251 封顶，状态数从 $5\times10^8$ 掉到约 $1.3\times10^5$。

> ⚠️ 注意「$+1$」这个边界：位置的最大合法值是 $\lfloor steps/2 \rfloor$，**列数**是它加 1。写成 $m = \lfloor steps/2 \rfloor$ 会漏掉最右一列，$steps$ 为偶数时答案会偏小（例如 $steps=4$ 得到 8 而不是 9）。

### 3.3 状态转移与算法流程

![DP 流程：逐层推进 + 滚动数组](images/wc164_q4_dp_flow.svg)

记 $dp[p]$ 为**当前这一层**（走完 $s$ 步后）位于位置 $p$ 的方案数，转移就是三个邻居求和：

$$ndp[p] = dp[p-1] + dp[p] + dp[p+1], \qquad 0 \le p < m$$

其中 $p-1 < 0$ 或 $p+1 \ge m$ 的项按 0 处理。初始 $dp[0]=1$、其余为 0；每轮把 $ndp$ 滚给 $dp$；$steps$ 轮之后 $dp[0]$ 就是答案。

右边越界为什么能直接当 0？这要分两种情形看：

- 若 $m = arrLen$（数组本来就短），那么 $m$ 就是真实右边界，越界本来就不合法；
- 若 $m = \lfloor steps/2\rfloor+1$（数组很长、被我们截断），被丢掉的格子对应位置 $p \ge \lfloor steps/2\rfloor+1$，由 3.2 的界 $2p > steps$，这种路径**永远回不到 0**，不会出现在答案里。

也就是说：「只统计全程待在 $[0,m-1]$ 内的路径」与「统计所有最终回到 0 的路径」是同一件事。

> 💡 一个容易困惑的现象：截断表里**个别中间格子**的数值会比完整表略小（少算了越出右边、又从右边回来的路径）。例如 $steps=5$、$m=3$ 时第 4 层给出 $dp[2]=8$，而完整表是 9（多出的那条经过位置 3）；但两者的 $dp[5][0]$ 都是 21 —— 因为多出来的路径本来就不可能回到 0。

### 3.4 示例演算

![steps = 5 的逐层演算](images/wc164_q4_walkthrough.svg)

取 $steps = 5$、$arrLen = 10^6$，此时 $m = \min\left(10^6,\ \lfloor 5/2\rfloor + 1\right) = 3$，只需要 3 列：

| $s$ | $p=0$ | $p=1$ | $p=2$ |
|-----|-------|-------|-------|
| 0 | 1 | 0 | 0 |
| 1 | 1 | 1 | 0 |
| 2 | 2 | 2 | 1 |
| 3 | 4 | 5 | 3 |
| 4 | 9 | 12 | 8 |
| 5 | **21** | 29 | 20 |

最后一行 $dp[0]=21$ 即答案；顺便验证 $p=1$ 那格：$29 = 9 + 12 + 8$，正好是上一层三格之和。

再用示例 1 核一遍 $steps=3$、$arrLen=2$（$m=\min(2,2)=2$）：

| $s$ | $p=0$ | $p=1$ |
|-----|-------|-------|
| 0 | 1 | 0 |
| 1 | 1 | 1 |
| 2 | 2 | 2 |
| 3 | **4** | 4 |

答案 4，与官方示例一致；这 4 条路径就是「右左右」「不右左」「右不左」「不不不」。

## 4. 算法细节

1. **列数截断**：$m = \min\left(arrLen,\ \lfloor steps/2\rfloor+1\right)$。它同时扮演两个角色——$steps$ 小的时候用 $\lfloor steps/2\rfloor+1$ 抵挡 $arrLen=10^6$，$arrLen$ 小的时候用 $arrLen$ 挡住越界。
2. **边界处理**：$p=0$ 没有左邻、$p=m-1$ 没有右邻，循环里必须用 `if (p > 0)` / `if (p + 1 < m)` 显式判断；不要用 `dp[max(p-1,0)]` 这类写法，那会把「越界」错算成「留在原地」，凭空多算方案。
3. **取模与溢出**：三格之和最大约 $3 \times (10^9+6) \approx 3\times10^9$，超过 `int` 上限 $2.15\times10^9$，C++ 必须用 `long long` 累加后再取模（或者加两次、每次取模）。Python 的任意精度整数没这个坑。
4. **滚动数组**：`ndp` 的每个下标在每一轮都会被重新赋值，所以既可以每轮新建，也可以 `swap` 后直接覆盖，不必清零；用两行数组即可，不需要二维表。
5. **等价写法**：官方提示给的是「反向」定义 $dp(\text{剩余步数}, p)$，用记忆化递归 + 自然剪枝 $p >$ 剩余步数 直接返回 0，与本文的自底向上写法完全等价，但递归常数大，且本题根本不需要记忆化之外的花招。
6. **可选的更强截断**：第 $s$ 层只需 $p \le \min(s,\ steps-s)$，可以让内层循环再短一点；由于 $m \le 251$，收益很小，代码却更容易写错，取舍上不划算。
7. **与 $arrLen$ 的关系**：$arrLen = 1$ 时 $m=1$，转移退化为 $ndp[0]=dp[0]$，答案恒为 1（只能一直不动），无需特判。

## 5. 正确性证明

**引理 1（位置上界）**：若一条路径从 0 出发、恰走 $steps$ 步后回到 0，则它在时刻 $t$（$0 \le t \le steps$）的位置 $p_t$ 满足 $p_t \le \min(t,\ steps-t)$；特别地 $p_t \le \lfloor steps/2 \rfloor$。

**证明**：每步位置至多变化 1，故 $p_t \le p_0 + t = t$。另一方面，从 $p_t$ 出发还要走 $steps-t$ 步才能到 0，而每步至多让位置减 1，故 $steps - t \ge p_t$。两式相加得 $2p_t \le steps$，即 $p_t \le \lfloor steps/2\rfloor$。∎

**引理 2（转移不重不漏）**：设 $A_s(p)$ 为从 0 出发、走 $s$ 步、全程合法且第 $s$ 步后位于 $p$ 的路径集合。则 $A_s(p)$ 可划分为「最后一步从 $p-1$ 右移」「最后一步原地不动」「最后一步从 $p+1$ 左移」三类，它们分别与 $A_{s-1}(p-1)$、$A_{s-1}(p)$、$A_{s-1}(p+1)$ 一一对应；越界的那一类为空集。

**证明**：任一 $s$ 步路径由「前 $s-1$ 步的路径 + 最后一步」唯一确定，而最后一步只有三种取值，故三类互不相交且并集为全集；去掉最后一步即得所要求的双射。越界时该类路径不合法，故为空。∎

**引理 3（截断安全）**：令 $m = \min(arrLen,\ \lfloor steps/2\rfloor+1)$，在 $[0,m-1]$ 上执行 3.3 的 DP 得到的 $dp'$，满足 $dp'[steps][0]$ 等于全部合法方案的数目。

**证明**：$dp'$ 按引理 2 的转移统计的是「全程位置落在 $[0,m-1]$ 内、最终回到 0」的路径数。一方面这类路径都是合法方案，故 $dp'[steps][0] \le$ 答案；另一方面由引理 1，任何最终回到 0 的合法路径全程 $p_t \le \lfloor steps/2\rfloor \le m-1$，必被 $dp'$ 计入，故答案 $\le dp'[steps][0]$。两边相等。∎

**定理**：算法输出的值等于所有合法方案数对 $10^9+7$ 取模的结果。

**证明**：初值 $dp[0]=1$ 对应「0 步后位于 0」的唯一空路径，配合引理 2 的转移，未截断时 $dp[steps][0]$ 精确等于合法方案数；由引理 3，截断不改变该值。每一步都对 $10^9+7$ 取模，而加法与取模同余（$(a+b) \bmod M$ 与 $a+b$ 同余），故最终输出正是答案的模。∎

## 6. 复杂度分析

- **时间**：$O(steps \cdot m) = O\bigl(steps \cdot \min(arrLen,\ \lfloor steps/2\rfloor+1)\bigr) = O(steps^2)$，与 $arrLen$ 完全无关。上限为 $500 \times 251 \approx 1.3\times10^5$ 次「三次加法 + 一次取模」，参考实现（Python）实测约 20 ms。
- **空间**：$O(m)$。只需两个长度 $m \le 251$ 的滚动数组，共约 502 个整数，与 $arrLen = 10^6$ 无关。
- **对比**：完整二维 DP 是 $O(steps \cdot arrLen)$ 时间、$O(steps \cdot arrLen)$ 空间（约 2 GB），截断后分别降到 $O(steps^2)$ 和 $O(steps)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int numWays(int steps, int arrLen) {
        const int MOD = 1000000007;
        // 只有 0 .. steps/2 这些位置「去得回得来」
        int m = min(arrLen, steps / 2 + 1);
        vector<int> dp(m, 0), ndp(m, 0);
        dp[0] = 1;
        for (int s = 0; s < steps; ++s) {
            for (int p = 0; p < m; ++p) {
                long long v = dp[p];                 // long long：三格之和会超 int
                if (p > 0) v += dp[p - 1];
                if (p + 1 < m) v += dp[p + 1];
                ndp[p] = (int)(v % MOD);
            }
            dp.swap(ndp);                            // 滚动：下一轮会逐格覆盖 ndp
        }
        return dp[0];
    }
};
```

### Python

```python
class Solution:
    def numWays(self, steps: int, arrLen: int) -> int:
        MOD = 10 ** 9 + 7
        m = min(arrLen, steps // 2 + 1)   # 只保留 0 .. steps//2 这些位置
        dp = [0] * m
        dp[0] = 1
        for _ in range(steps):
            ndp = [0] * m
            for p in range(m):
                v = dp[p]
                if p > 0:
                    v += dp[p - 1]
                if p + 1 < m:
                    v += dp[p + 1]
                ndp[p] = v % MOD
            dp = ndp
        return dp[0]
```

## 8. 边界情况与易错点

1. **$steps = 1$**：$m = \min(arrLen, 1) = 1$，只有「不动」一条路，答案 1。此时位置 1 被截掉是对的——去了就回不来。
2. **$arrLen = 1$**：只能原地不动，无论 $steps$ 多大答案都是 1；靠 $m = \min(1, \cdot) = 1$ 自动成立，**不要**因为「$m$ 太小」去写特判。
3. **列数少算 1**：把 $m$ 写成 $\lfloor steps/2\rfloor$ 会漏掉最右一列。$steps=4$、$arrLen=10^6$ 时得到 8 而非 9；$steps=500$ 时错成 374847122（正确值 374847123），只差 1，极难自查，务必用「$+1$」的写法。
4. **`int` 溢出**：$3 \times (10^9+6) > 2^{31}-1$，C++ 里三格直接相加会变成负数，表现为莫名其妙的 WA；用 `long long` 或分步取模。
5. **把「越界」当成「不动」**：写成 `dp[max(p-1, 0)]` 会给位置 0 额外多算一条「假左移」，答案系统性偏大，是最常见的逻辑错误。
6. **「不动」也消耗一步**：初始只有一个方案（空路径），不要把「0 步就停在 0」额外计入，也不要让原地不动变成「免费」。
7. **取模后不单调**：$dp$ 的数值没有单调性，不能用「比某个值大就剪枝」之类的技巧；本题也不需要任何剪枝。
8. **奇偶差异**：$steps=499$ 时 $m \le 250$，$steps=500$ 时 $m \le 251$，别把 251 写死，用 $steps/2+1$ 现算。

**延伸思考**：

1. 若 $steps$ 放大到 $10^9$，$O(steps \cdot m)$ 不再可行，但转移是固定的三对角矩阵，可以做矩阵快速幂，$O(m^3 \log steps)$；更快的是注意到答案序列关于 $steps$ 满足低阶线性递推，用 Berlekamp–Massey 先拟合出递推式，再 $O(m^2 \log steps)$ 求第 $steps$ 项。
2. 若 $arrLen \ge \lfloor steps/2\rfloor+1$（上边界永不生效），答案就是 **Motzkin 数** $M_{steps}$：长度 $steps$ 的「上 / 下 / 平」序列，且任何前缀的上步数不少于下步数、总和为 0。它满足 $M_n = \frac{(2n+1)M_{n-1} + (3n-3)M_{n-2}}{n+2}$，可以 $O(steps)$ 算出。本文 $steps=5$ 的答案 21 正是 $M_5$。
3. 若把左边界也拆掉（允许走到负下标），问题退化为「在整数轴上走 $steps$ 步回到原点的走法数」，答案就是中心三项式系数 $\sum_k \frac{steps!}{k!\,k!\,(steps-2k)!}$；本题与它的差别，正是「不许撞左墙」带来的反射原理修正——这也是为什么有左墙时答案从 $M_n$ 之外还要再受右墙约束。
