# LeetCode 访问所有点的最小时间 题解

## 1. 题目概述

- **标题 / 题号**：访问所有点的最小时间（#1266，easy）
- **链接**：https://leetcode.cn/problems/minimum-time-visiting-all-points/
- **来源**：LeetCode 第 164 场周赛 Q1
- **难度**：简单
- **标签**：几何，数组，数学

**题意**：平面上有 $n$ 个整数坐标点 `points[i] = [xi, yi]`，要**按数组下标顺序**依次访问它们。每一秒只允许做三种动作之一：

- 水平移动 1 个单位（$x$ 变化 $\pm 1$，$y$ 不变）；
- 竖直移动 1 个单位（$y$ 变化 $\pm 1$，$x$ 不变）；
- 沿对角线移动 $\sqrt{2}$（等价于 $x$、$y$ 同时各变化 $\pm 1$）。

求访问完所有点的**最小总秒数**。途中可以经过后面才该访问的点，但经过不算访问。

**约束**：

- $1 \le n \le 100$（`points.length == n`）
- `points[i].length == 2`
- $-1000 \le x_i, y_i \le 1000$
- 访问顺序固定为数组顺序，不能重排

> 💡 一句话本质：答案就是相邻两点的**切比雪夫距离**之和，即 $\sum_{i=1}^{n-1}\max(|x_i-x_{i-1}|,\,|y_i-y_{i-1}|)$。

## 2. 示例

**示例 1**

```text
输入：points = [[1,1],[3,4],[-1,0]]
输出：7
解释：[1,1] -> [2,2] -> [3,3] -> [3,4] -> [2,3] -> [1,2] -> [0,1] -> [-1,0]
      从 [1,1] 到 [3,4] 需要 3 秒（对角 2 步 + 竖直 1 步）
      从 [3,4] 到 [-1,0] 需要 4 秒（全程走对角线）
      一共 3 + 4 = 7 秒
```

**示例 2**

```text
输入：points = [[3,2],[-2,2]]
输出：5
解释：两点 y 相同，只能水平移动 |(-2)-3| = 5 个单位，耗时 5 秒
```

**示例 3（补充，用来说明顺序约束）**

```text
输入：points = [[0,0],[5,0],[0,0]]
输出：10
解释：第一段 (0,0) -> (5,0) 水平 5 秒；第二段 (5,0) -> (0,0) 再水平 5 秒。
      首尾虽是同一个点，但必须先到 (5,0) 才继续，所以答案是 10 而不是 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是把平面当成网格图，对每一对相邻点跑一次 BFS 求最短路，再求和。单次 BFS 的网格规模约 $(2\cdot 10^3)^2 = 4\times 10^6$ 个格点，跑 $n-1 \le 99$ 次就是 $4\times 10^8$ 量级的访问，虽然可能通过但非常浪费。更糟的是「把路径枚举出来」的想法：每步三种走法，秒数一多就是指数级。

暴力做法没有利用**这段路的结构**：走对角线是「赚的」，因为它一条命令同时消耗两个坐标差。

### 3.2 核心观察：每段耗时就是切比雪夫距离

![先走对角线再走直线](images/wc164_q1_chebyshev_move.svg)

只看一段路：从 $A=(x_1,y_1)$ 到 $B=(x_2,y_2)$，记 $dx=\lvert x_2-x_1 \rvert$、$dy=\lvert y_2-y_1 \rvert$。下界与上界恰好重合，于是可以直接定出这一段的最优耗时：

- **下界**：每秒内 $x$ 至多变化 1、$y$ 也至多变化 1。要同时消掉 $dx$ 与 $dy$，至少需要 $dx$ 秒（受 $x$ 限制）也至少需要 $dy$ 秒（受 $y$ 限制），故耗时 $T \ge \max(dx,dy)$。
- **上界（构造）**：先沿对角线走 $m=\min(dx,dy)$ 步，两个坐标差同时缩小 $m$；此时只剩一个坐标还有差，沿该方向直走 $|dx-dy|$ 步即可到达。总步数 $m+|dx-dy| = \max(dx,dy)$。

上下界重合，所以**单独一段**的最短耗时恰为

$$T(A,B) = \max\bigl(\lvert x_2-x_1 \rvert,\ \lvert y_2-y_1 \rvert\bigr).$$

这正是「八方向网格」上的切比雪夫距离。注意它比曼哈顿距离 $dx+dy$ 小、比欧氏距离 $\sqrt{dx^2+dy^2}$ 大。

### 3.3 算法流程 / 状态转移

![算法流程](images/wc164_q1_algorithm_flow.svg)

顺序约束把问题切成互不干扰的若干段：必须先去 $p_0$，然后 $p_1$，……，最后 $p_{n-1}$。第 $i$ 段的起点是 $p_{i-1}$、终点是 $p_i$，与其它段无关，因此

```text
ans = 0
for i = 1 .. n-1:
    dx = |points[i][0] - points[i-1][0]|
    dy = |points[i][1] - points[i-1][1]|
    ans += max(dx, dy)
return ans
```

算法只有一次线性扫描，无需任何 DP 表：每段都取到自身最优，总时间就取到全局最优。**不能用「按欧氏距离直线飞过去」来算**，题目只允许水平、竖直、对角三种单位动作。

### 3.4 示例演算

![示例演算](images/wc164_q1_walkthrough.svg)

以 `points = [[1,1],[3,4],[-1,0]]` 为例：

| 段 | 起点 → 终点 | $\lvert dx \rvert$ | $\lvert dy \rvert$ | $\max$ | 累计 |
|----|-------------|--------|--------|--------|------|
| 1 | $(1,1) \to (3,4)$ | $2$ | $3$ | $3$ | $3$ |
| 2 | $(3,4) \to (-1,0)$ | $4$ | $4$ | $4$ | $7$ |

第 1 段：对角走到 $(3,3)$ 用 2 秒，再竖直 1 秒到 $(3,4)$，共 3 秒。
第 2 段：$dx = dy = 4$，四个对角步直达，共 4 秒。总计 $3+4=7$，与官方答案一致。

再看 `[[3,2],[-2,2]]`：$dx=5$、$dy=0$，$\max=5$，只有一段，答案 5。

## 4. 算法细节

1. **按相邻对遍历**：用 `for i in range(1, n)` 或 `zip(points, points[1:])` 取相邻两点，**不要**把所有点两两配对（那会算成 $\binom{n}{2}$ 条边，等于把路径拆散）。
2. **坐标差先取绝对值再取 max**：`max(abs(x2-x1), abs(y2-y1))`。若先 `max` 再取绝对值，遇到两个负数会得到错误结果。
3. **不要用曼哈顿距离或欧氏距离**：前者会把「对角一步」当成两步（示例 1 会算成 2+3+4+4=13），后者与整数秒无关（示例 1 会得到 $\sqrt{13}+4\sqrt{2}\approx 9.26$）。
4. **累加用整型即可**：单段最大 $2000$，$n-1 \le 99$，答案上界 $99 \times 2000 = 198000$，`int` 完全够，不必开 `long long`。
5. **`n == 1` 时直接返回 0**：循环体一次都不执行，代码自然正确，但要在心里确认 `zip(points, points[1:])` 在长度为 1 时为空、不会越界。
6. **顺序不可交换**：题目要求按数组顺序访问，「顺路经过」不算访问。所以不能对点排序或重排，否则示例 1 会退化成 $A \to C$ 再补 $B$ 的错误模型。
7. **重复点不产生额外耗时**：$p_i = p_{i-1}$ 时 $dx=dy=0$，累加 0，天然被覆盖。

## 5. 正确性证明

记第 $i$ 段（$1 \le i \le n-1$）的起终点为 $p_{i-1}, p_i$，其坐标差为 $dx_i=|x_i-x_{i-1}|$、$dy_i=|y_i-y_{i-1}|$。

**引理 1（单段下界）**：任何从 $p_{i-1}$ 走到 $p_i$ 的合法移动序列，耗时 $T \ge \max(dx_i, dy_i)$。

**证明**：设序列共 $T$ 秒，其中水平步 $a$ 次、竖直步 $b$ 次、对角步 $c$ 次，则 $a+b+c=T$。每一步对 $x$ 坐标的改变量绝对值不超过 1，对 $y$ 坐标也同样不超过 1，因此

$$dx_i \le a + c, \qquad dy_i \le b + c.$$

于是 $T = a+b+c \ge a+c \ge dx_i$ 且 $T \ge b+c \ge dy_i$，取两者较大者得 $T \ge \max(dx_i, dy_i)$。∎

**引理 2（单段可达到下界）**：存在一个恰好耗时 $m = \min(dx_i,dy_i)$ 加 $|dx_i-dy_i|$ 的合法移动序列走到 $p_i$。

**证明**：不妨设 $dx_i \le dy_i$（否则交换 $x,y$ 的角色，论证对称）。令 $s_x = \operatorname{sign}(x_i-x_{i-1})$、$s_y = \operatorname{sign}(y_i-y_{i-1})$（差为 0 时该方向不移动）。先做 $dx_i$ 次对角移动 $(s_x, s_y)$，$x$ 坐标到达目标值，$y$ 坐标前进了 $dx_i$；再做 $dy_i-dx_i$ 次竖直移动 $(0,s_y)$ 补足 $y$。总步数 $dx_i + (dy_i-dx_i) = dy_i = \max(dx_i,dy_i)$。每一步都是合法动作，故该序列合法且耗时正好是 $\max(dx_i,dy_i)$。∎

**引理 3（分段可加）**：在「必须按顺序访问」的约束下，访问全部点的最小总耗时等于 $\sum_{i=1}^{n-1} T(p_{i-1},p_i)$，其中 $T$ 为单段最短耗时。

**证明**：任取一条合法的完整路线，它按时间被 $p_0, p_1, \dots, p_{n-1}$ 的首次到达时刻切成 $n-1$ 段（首次到达之后到下一次首次到达之间的移动属于下一段）。第 $i$ 段是从 $p_{i-1}$ 出发、在 $p_i$ 结束的一段合法移动，由引理 1 其耗时 $\ge T(p_{i-1},p_i)$，故总耗时 $\ge \sum_i T(p_{i-1},p_i)$——这是**下界**。

另一方面，把引理 2 给出的 $n-1$ 条最优段路首尾相接，就得到一条合法的完整路线：第 $i$ 段从 $p_{i-1}$ 出发、恰好在 $p_i$ 结束，因此顺序约束被满足，且总耗时正好是 $\sum_i T(p_{i-1},p_i)$——这是**上界**。两界重合，引理得证。∎

**定理**：算法输出的 `ans` 等于访问所有点的最小总时间。

**证明**：由引理 2，$T(p_{i-1},p_i) = \max(dx_i,dy_i)$，而算法累加的正是这一串值；由引理 3，该和等于最小总耗时。故算法输出正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。只扫描一遍相邻点对，每对做两次减法、两次取绝对值、一次取最大值与一次加法，均 $O(1)$。
- **空间复杂度**：$O(1)$。除输入外只用一个累加变量 `ans`（Python 的 `zip(points, points[1:])` 会额外生成长度为 $n-1$ 的切片，空间 $O(n)$；若要求严格 $O(1)$ 可改用下标循环）。
- 对比暴力 BFS：单次 $O(R^2)$（$R \approx 2000$ 为坐标范围），总计 $O(nR^2)$，比 $O(n)$ 慢约 $4\times 10^6$ 倍，差了六个数量级以上。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <cstdlib>
using namespace std;

class Solution {
public:
    int minTimeToVisitAllPoints(vector<vector<int>>& points) {
        int ans = 0;
        for (size_t i = 1; i < points.size(); ++i) {
            int dx = abs(points[i][0] - points[i - 1][0]);
            int dy = abs(points[i][1] - points[i - 1][1]);
            ans += dx > dy ? dx : dy;   // 切比雪夫距离
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minTimeToVisitAllPoints(self, points: list[list[int]]) -> int:
        ans = 0
        for (x1, y1), (x2, y2) in zip(points, points[1:]):
            # 每段耗时 = 两个坐标差中较大的那个
            ans += max(abs(x2 - x1), abs(y2 - y1))
        return ans
```

## 8. 边界情况与易错点

1. **只有一个点**：`points = [[7,-9]]`，没有任何一段，返回 0。不要初始化成「无穷大」或强行进入循环。
2. **所有点重合**：如 `[[0,0],[0,0],[0,0]]`，每段 $dx=dy=0$，答案 0，代码天然正确。
3. **负坐标**：约束允许 $-1000$，`abs` 必须在减法之后立刻做。C++ 中切勿把坐标差存进 `unsigned`：负数会先回绕成一个巨大的正数，再取绝对值也救不回来。
4. **误用曼哈顿距离**：写成 `ans += dx + dy` 在示例 1 上得到 13（正确 7），示例 2 恰好也是 5，容易「碰巧过官方样例」。务必手推示例 1。
5. **误用欧氏距离**：`ans += sqrt(dx*dx+dy*dy)` 会得到非整数（示例 1 约 9.26），且与「整秒」语义不符；题目要的是步数而非长度。
6. **错误理解「顺路经过」**：题干说可以经过后面的点但不算访问，因此**不能**用「从 $p_0$ 到 $p_{n-1}$ 的一条大路径」来省时间；顺序约束是硬性的，总时长必须逐段相加。
7. **坐标范围导致的溢出**：单段 $\le 2000$、总和 $\le 198000$，`int` 安全；但若把点两两配对（$O(n^2)$ 条边）再累加，数值虽不溢出，逻辑已经错了。

**延伸思考**：

1. 若允许**任意顺序**访问（最小哈密顿路径），问题立刻变成 TSP 的特例：切比雪夫度量下它仍是 NP 难的，没有多项式闭式解，$n \le 100$ 时只能状压或启发式。
2. 若每秒的斜走可以跨越任意长度（代价仍为 1 秒），一段的耗时变成 $1 + \lvert dx-dy \rvert$：先用一步斜走吃掉较短的那个坐标差，再直走剩下的差值。
3. 若把坐标推广到三维，结论原样成立，只需把距离换成 $\max(\lvert dx \rvert, \lvert dy \rvert, \lvert dz \rvert)$——对角线动作变成「三个坐标同时各变 1」。
