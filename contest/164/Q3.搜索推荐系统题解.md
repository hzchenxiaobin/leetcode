# LeetCode 搜索推荐系统 题解

## 1. 题目概述

- **标题 / 题号**：搜索推荐系统（#1268，medium）
- **链接**：https://leetcode.cn/problems/search-suggestions-system/
- **来源**：LeetCode 第 164 场周赛 Q3
- **难度**：中等
- **标签**：字典树、数组、字符串、二分查找、排序、堆（优先队列）

**题意**：给定产品数组 `products` 和搜索词 `searchWord`。系统按照用户逐字符敲入的顺序工作：敲完第 1 个字符时，取所有以该 1 字符为前缀的产品；敲完第 2 个字符时，取以这 2 个字符为前缀的产品……每个前缀都要返回**字典序最小的至多 3 个**产品名。最终返回 $m = \lvert \text{searchWord} \rvert$ 行，第 $i$ 行对应长度为 $i$ 的前缀。

**约束**：

- $1 \le \text{products.length} \le 1000$
- $1 \le \sum \text{products}[i]\text{.length} \le 2 \times 10^4$
- `products[i]` 与 `searchWord` 只含小写英文字母
- $1 \le \text{searchWord.length} \le 1000$

## 2. 示例

**示例 1**

```text
输入：products = ["mobile","mouse","moneypot","monitor","mousepad"], searchWord = "mouse"
输出：[
  ["mobile","moneypot","monitor"],
  ["mobile","moneypot","monitor"],
  ["mouse","mousepad"],
  ["mouse","mousepad"],
  ["mouse","mousepad"]
]
解释：排序后为 [mobile, moneypot, monitor, mouse, mousepad]。
前缀 m / mo 命中全部 5 个，取最小的 3 个 → [mobile, moneypot, monitor]；
前缀 mou / mous / mouse 只剩 [mouse, mousepad]。
```

**示例 3**

```text
输入：products = ["bags","baggage","banner","box","cloths"], searchWord = "bags"
输出：[["baggage","bags","banner"],["baggage","bags","banner"],["baggage","bags"],["bags"]]
解释：排序后为 [baggage, bags, banner, box, cloths]；
前缀 b / ba 有 4+ 个命中，取 3 个；前缀 bag 只剩 2 个；前缀 bags 只剩 1 个。
```

**示例 4**

```text
输入：products = ["havana"], searchWord = "tatiana"
输出：[[],[],[],[],[],[],[]]
解释：一个字符都匹配不上，但返回值仍然要有 7 行空列表，长度等于 searchWord 长度。
```

## 3. 解题思路

### 3.1 暴力思路

对每个前缀 $p_i = \text{searchWord}[0..i)$，遍历全部 $n$ 个产品，用 `startswith` 判断是否命中，再对命中集合排序取前 3。单次判断最坏 $O(L)$（$L$ 为产品长度上限），总时间

$$O\Bigl(m \cdot n \cdot L + \sum_i k_i \log k_i\Bigr),$$

在 $m = n = 1000$、$L = 1000$ 的极端数据下可达 $10^9$ 量级。题目提示里也承认「暴力能过」，但它把每个前缀都当成独立问题，完全没有利用「前缀只会在末尾追加一个字符、命中集合只减不增」这一结构。

### 3.2 核心观察：排序 + 前缀树，每个节点缓存前 3

![核心观察：排序插入的前缀树，每个节点缓存最小的 3 个词](images/wc164_q3_trie_top3.svg)

要同时满足「按前缀筛」和「字典序最小 3 个」，有两个观察把两件事一次做完：

- **观察 1（排序决定「谁先到」）**：把 `products` 按字典序升序排列后再插入 Trie。于是经过同一节点的产品，**插入顺序就是字典序升序**——节点第一次见到的 3 个词，恰好就是它子树里最小的 3 个。
- **观察 2（前缀变长 ⇒ 集合只减不增）**：$p_i$ 的全部命中产品也一定以 $p_{i-1}$ 开头，所以命中集合随 $i$ 增大单调收缩。已经排在最前面的 3 个不会因为前缀变长而被「踢掉」，只会被整体筛掉一部分，剩下的仍然是最小的。
- **结论**：在每个 Trie 节点上挂一个长度上限为 3 的列表，插入时「不满 3 就追加」，查询时直接读该列表即可——查询阶段 $O(1)$ 取答案，不需要排序、不需要堆。

> 💡 另一种等价视角：排序后以同一前缀开头的产品在数组中**连续成段**，答案就是该段的前 3 个。Trie 只是把这个「段」预先物化到了节点上，避免了每次重新定位段首。

### 3.3 算法流程

![算法流程：排序、建树、逐字符查询](images/wc164_q3_build_query_flow.svg)

1. **排序**：`sort(products)`，保证后续插入顺序即字典序。
2. **建树**：对每个产品 $w$（带上它的下标 `id`），从根出发逐字符下降；每一步到达新节点后，若该节点缓存不足 3 个，就把 `id` 追加进去。
3. **查询**：指针 `p` 从根开始，依次读入 `searchWord` 的每个字符 `c`：
   - 若 `p` 有孩子 `c`，`p` 下移，把 `p` 的缓存翻译成产品名作为本行答案；
   - 否则（或此前已断链），本行以及之后所有行都填空列表，用布尔标记 `broken` 短路。
4. **返回**：共 $m$ 行，行数恒等于 `searchWord` 长度。

### 3.4 示例演算

![示例演算：mouse 的 5 个前缀在有序产品表上的收缩过程](images/wc164_q3_walkthrough.svg)

| 前缀 | 命中的产品（有序） | 推荐结果 |
|------|--------------------|----------|
| `m` | mobile, moneypot, monitor, mouse, mousepad | mobile, moneypot, monitor |
| `mo` | 同上 5 个 | mobile, moneypot, monitor |
| `mou` | mouse, mousepad | mouse, mousepad |
| `mous` | mouse, mousepad | mouse, mousepad |
| `mouse` | mouse, mousepad | mouse, mousepad |

关键是第 3 个字符：`mobile` 的该位是 `b`、`moneypot`/`monitor` 是 `n`，都不等于 `u`，于是在 `mou` 节点被整体剪掉；而 `mousepad` 虽然比 `mouse` 长，却同样经过 `mouse` 节点，所以最后一个前缀仍有 2 个答案。再验证示例 3：`bag` 之后 `banner`（第 3 位 `n`）被剪掉，`bags` 之后 `baggage`（第 3 位 `g`）被剪掉，正好得到 `["bags"]`。

## 4. 算法细节

1. **先排序、后插入，顺序不能颠倒**。节点缓存的正确性完全依赖「先到的字典序更小」；反过来先建树再排序，缓存里就是任意 3 个词。
2. **缓存满 3 就停止追加**（`if (p->suggest.size() < 3)`）。不要写成覆盖或「满了再替换」，那会丢掉最小者；也不要用 `>` 3 的判断，越界写入会污染答案。
3. **查询必须补足 $m$ 行**。断链后不能 `break` 跳出循环，而应把剩余前缀逐个填入空列表，否则返回的二维列表长度不足。
4. **节点里存下标而不是字符串**。存 `string` 时，一个长词会在它路径上的每个节点各存一份，最坏字符量达 $O\bigl(\sum |w|^2\bigr)$；存下标则严格 $O\bigl(\sum |w|\bigr)$。
5. **答案要拷贝一份**。C++ 的 `ans.push_back(row)` 天然是值拷贝；Python 中要用列表推导重建 `[products[i] for i in idx]`，不能把节点内部的 list 直接放进答案（否则后续共享同一引用）。
6. **字母表固定为 26**。C++ 用定长数组 `Trie* ch[26]` 寻址最快；Python 用 `dict` 更省内存，`setdefault` 一行完成「取孩子，没有就建」。
7. **备选解法同样值得掌握**：排序后对每个前缀用 `lower_bound` 二分出首个 $\ge$ 前缀的位置，再向后检查 3 个词是否真的以该前缀开头，时间 $O(L n \log n + m \log n + 3L)$；或用双指针夹窗口（前缀变长 ⇒ 窗口只向内收缩），时间 $O(L n \log n + n + m)$。两者都不用建树、代码更短；Trie 的优势在于**一次建树、多个 `searchWord` 复用**。

## 5. 正确性证明

**引理 1（节点缓存正确）**：按字典序升序插入时，任一节点 $u$ 的缓存 $S(u)$ 恰好是「经过 $u$ 的产品」中字典序最小的 $\min(3, k_u)$ 个（$k_u$ 为经过 $u$ 的产品个数，重复产品按出现次数分别计）。

**证明**：设经过 $u$ 的产品按插入顺序为 $w_1, w_2, \dots, w_{k_u}$。排序保证插入顺序即字典序升序，故 $w_1 \le w_2 \le \dots \le w_{k_u}$。算法在每次插入 $w_j$ 经过 $u$ 时，只要 $\lvert S(u) \rvert < 3$ 就追加；一旦达到 3 便不再变更。因此 $S(u)$ 恰为 $w_1, \dots, w_{\min(3,k_u)}$，即最小的那部分。∎

**引理 2（存在性判定等价）**：对任意前缀 $p$，从根沿 $p$ 的字符下降：若每个字符都能走到对应孩子，则到达的节点 $u_p$ 的「经过产品集合」等于「以 $p$ 开头的产品集合」；若某个字符没有孩子，则不存在以 $p$ 开头的产品，且以 $p$ 为前缀的更长前缀也一律不存在。

**证明**：插入 $w$ 时沿 $w$ 逐字符建边，所以「$w$ 以 $p$ 开头」等价于「$w$ 的插入路径经过 $u_p$」。Trie 中边由（父节点，字符）唯一确定，$p$ 的路径唯一且长度固定。若第 $j$ 个字符缺少孩子，说明该节点之下没有任何词，即没有产品以该前缀开头；任何以 $p$ 为前缀的更长串，其路径必须经过这一缺失的边，故同样不存在。∎

**定理**：算法返回的二维列表与题目要求完全一致。

**证明**：第 $i$ 行对应前缀 $p_i = \text{searchWord}[0..i)$。若查询在 $j \le i$ 处断链，由引理 2 知 $p_i$ 没有任何命中产品，算法填入空列表，正确；否则查询到达 $u_{p_i}$，由引理 2 其经过集合正是命中集合，由引理 1 缓存即其中字典序最小的至多 3 个，正是题目所求。所有 $m$ 个前缀都恰好被处理一次，返回行数等于 $m$。∎

## 6. 复杂度分析

- **时间**：排序 $O(L \cdot n \log n)$（字典序比较单次最坏 $O(L)$）；建树对每个字符做一次常数操作，共 $O\bigl(\sum |w|\bigr)$；查询每个字符一次孩子查找 $O(1)$，外加把至多 3 个产品名取出，总 $O(m)$ 次取用。合计
$$O\Bigl(L \cdot n \log n + \sum |w| + m\Bigr),$$
其中输出本身的规模就是 $O(3m)$ 个词，无法再降。
- **空间**：树节点数不超过 $\sum |w| + 1$，每个节点只挂至多 3 个下标，故 Trie 占 $O\bigl(\sum |w|\bigr)$；答案列表 $O(m)$ 行、至多 $3m$ 个词。若节点直接存字符串而不存下标，则字符副本上界要乘一个 $O(L)$ 的因子。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <vector>
using namespace std;

struct Trie {
    Trie* ch[26] = {};
    vector<int> suggest;                 // 存下标，避免重复拷贝长字符串
    void insert(const string& w, int id) {
        Trie* p = this;
        for (char c : w) {
            int k = c - 'a';
            if (!p->ch[k]) p->ch[k] = new Trie();
            p = p->ch[k];
            if (p->suggest.size() < 3) p->suggest.push_back(id);   // 只留最小的 3 个
        }
    }
};

class Solution {
public:
    vector<vector<string>> suggestedProducts(vector<string>& products, string searchWord) {
        sort(products.begin(), products.end());          // 先排序：插入顺序 = 字典序
        Trie* root = new Trie();
        for (int i = 0; i < (int)products.size(); i++) root->insert(products[i], i);

        vector<vector<string>> ans;
        Trie* p = root;
        bool broken = false;                             // 路径已断，之后全为空
        for (char c : searchWord) {
            if (!broken && p->ch[c - 'a']) p = p->ch[c - 'a'];
            else broken = true;
            vector<string> row;
            if (!broken)
                for (int id : p->suggest) row.push_back(products[id]);
            ans.push_back(row);                          // 每行都要有，行数 = |searchWord|
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def suggestedProducts(self, products: List[str], searchWord: str) -> List[List[str]]:
        products.sort()                                  # 插入顺序即字典序
        trie = {}
        for idx, w in enumerate(products):
            node = trie
            for ch in w:
                node = node.setdefault(ch, {})           # 取孩子，没有就建
                lst = node.setdefault('#', [])
                if len(lst) < 3:
                    lst.append(idx)                      # 只存最小的 3 个下标
        ans, node, broken = [], trie, False
        for ch in searchWord:
            if broken or ch not in node:
                broken = True
                ans.append([])                           # 断链之后一律空列表
                continue
            node = node[ch]
            ans.append([products[i] for i in node['#']])  # 拷贝一份，别暴露内部列表
        return ans
```

## 8. 边界情况与易错点

1. **一个都匹配不上**：如示例 4，必须返回 $m$ 个空列表而不是空数组；用 `broken` 标记后仍要继续往 `ans` 里压空行。
2. **前缀比某些产品还长**：产品在 Trie 的中间节点就结束了，继续沿字符走会走到空孩子上，必须先判 `p->ch[k]` 非空再解引用，否则空指针崩溃。
3. **产品有重复**：`["a","a"]` 在前缀 `a` 下应返回两个 `"a"`，即重复产品按出现次数分别占位，与「排序后取前 3」的官方口径一致——存下标天然满足这一点。
4. **命中不足 3 个**：返回全部即可，不要补空串或占位符；示例 3 的最后一行只有 1 个元素。
5. **返回值长度检查**：最容易的 WA 是行数不对（少行），根源就是断链后 `break` 或忘记处理剩余字符。
6. **二分法里别用 `>` 判前缀**：`w > p` 不代表 `w` 以 `p` 开头，必须显式比较 `w.compare(0, p.size(), p) == 0`；同理，排序后段的右端点是「首个不以 $p$ 开头的词」，不是「首个大于 $p$ 的词」的简单外推。
7. **答案副本**：无论 C++ 还是 Python，把节点里的容器直接交给返回值都可能造成后续共享修改；返回前拷贝一份，逻辑上更安全也更符合题库的函数签名。
