# LeetCode 矩阵中的蛇 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中的蛇（#3248，easy）
- **链接**：https://leetcode.cn/problems/snake-in-matrix/
- **来源**：LeetCode 第 410 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、模拟

**题意**：大小为 $n \times n$ 的矩阵中有一条蛇，从单元格 $0$ 出发，按给定指令序列 `commands`（`"UP"` / `"RIGHT"` / `"DOWN"` / `"LEFT"`）逐条移动一格。矩阵中每个单元格的编号为 $grid[i][j] = i \times n + j$（行优先，从左上角 0 开始）。题目保证蛇全程不会移出边界，返回执行完所有指令后蛇所在单元格的编号。

**约束**：

- $2 \le n \le 10$
- $1 \le commands.length \le 100$
- `commands` 仅由 `"UP"`、`"RIGHT"`、`"DOWN"`、`"LEFT"` 四种字符串组成
- 测评数据保证蛇不会移动到矩阵边界外

> 💡 **快速切入**：签到题只需要 30 秒定位两件事——① 矩阵里**没有任何内容**，编号公式 $i \times n + j$ 只是一张「坐标 ↔ 编号」换算表，真正要模拟的状态只有**位置**一个量；② 数据保证不出界，**连边界检查都不用写**。想到这两点，剩下就是查表累加。

## 2. 示例

**示例 1**

```text
输入：n = 2, commands = ["RIGHT","DOWN"]
输出：3
解释：0 →右→ 1 →下→ 3。
```

**示例 2**

```text
输入：n = 3, commands = ["DOWN","RIGHT","UP"]
输出：1
解释：0 →下→ 3 →右→ 4 →上→ 1。
```

## 3. 解题思路

### 3.1 暴力思路：维护坐标 (i, j)，逐条翻译指令

最朴素的模拟：把蛇抽象为坐标 $(i, j)$，从 $(0, 0)$ 出发，每条指令改一个分量——`UP` 则 $i-1$、`DOWN` 则 $i+1$、`LEFT` 则 $j-1$、`RIGHT` 则 $j+1$。最后按公式 $i \times n + j$ 折算成编号返回。

这个做法一次遍历 $O(m)$（$m$ 为指令条数），本身已是最优复杂度；但一条 `if-else` 链要区分四个分支，最后还要做一次乘加折算——坐标在这里只是**中间货币**。$n \le 10$ 的小矩阵完全是烟雾弹：既不需要建矩阵，甚至不需要维护坐标。

### 3.2 核心观察：编号即坐标，指令即增量

![核心观察：pos = i×n + j 是两位 n 进制数，水平指令 ±1、竖直指令 ±n](images/matrix_snake_delta_concept.svg)

编号公式 $pos = i \times n + j$ 恰好把（行， 列）当作（高位， 低位）拼成一个**两位 $n$ 进制数**：行 $i$ 是高位，列 $j$ 是低位。于是四条指令对应四个**固定增量**：

| 指令 | 坐标变化 | 编号变化 |
|------|----------|----------|
| `RIGHT` | $j + 1$ | $+1$ |
| `LEFT` | $j - 1$ | $-1$ |
| `DOWN` | $i + 1$ | $+n$ |
| `UP` | $i - 1$ | $-n$ |

水平移动只动**低位**（同行相邻格，$\pm 1$），竖直移动恰好**跨一整行**（$\pm n$）。又因起点编号为 0，最终编号就是所有增量之和：

$$\text{final} = \sum_{c \in \text{commands}} \Delta(c), \qquad \Delta = \begin{cases} +n, & c = \texttt{DOWN} \\ -n, & c = \texttt{UP} \\ +1, & c = \texttt{RIGHT} \\ -1, & c = \texttt{LEFT} \end{cases}$$

> ⚠️ 直接累加的前提是**不出界**：若允许在列 $n-1$ 时继续右移，编号 $+1$ 会「串」到下一行行首——数值上看似合法，位置上却不存在。本题数据保证全程不出界，增量可以放心累加；若去掉该保证，就必须退回坐标版做边界检查（见第 8 节）。

### 3.3 算法流程

![算法流程：初始化 pos=0，循环查表取增量并累加，返回 pos](images/matrix_snake_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `pos = 0`，建增量表 {UP:−n, DOWN:+n, LEFT:−1, RIGHT:+1} | 状态 = 编号，转移 = 查表 |
| ② 逐条执行 | 对每条指令 `c`：`pos += Δ[c]` | 一趟遍历完成全部移动 |
| ③ 返回 | `return pos` | 免去坐标 → 编号的最后折算 |

### 3.4 示例演算

![示例 2 走查：n=3 时 DOWN/RIGHT/UP 的网格路径与编号逐步变化](images/matrix_snake_walkthrough.svg)

以示例 2（$n = 3$，`["DOWN","RIGHT","UP"]`）逐步演算：

| 步骤 | 指令 | 增量 $\Delta$ | 坐标 $(i, j)$ | pos |
|------|------|---------------|----------------|-----|
| 初始 | — | — | $(0, 0)$ | 0 |
| 1 | `DOWN` | $+n = +3$ | $(1, 0)$ | 3 |
| 2 | `RIGHT` | $+1$ | $(1, 1)$ | 4 |
| 3 | `UP` | $-n = -3$ | $(0, 1)$ | 1 |

$0 + 3 + 1 - 3 = 1$，返回 1。示例 1 同理：$0 + 1 + 2 = 3$。

对照两列可见：**坐标版与编号版每一步都严格等价**——坐标版维护 $(i, j)$ 最后折算，编号版直接维护折算结果本身；既然每条指令的增量都能直接加在编号上，中间过程的坐标就是多余的。

## 4. 算法细节

1. **增量表**：四个方向的增量只有两种绝对值（$1$ 与 $n$），可用哈希表 `{"UP": -n, "DOWN": n, "LEFT": -1, "RIGHT": 1}` 一次建好，循环内 $O(1)$ 查表。
2. **无需建矩阵**：矩阵从未被读写，$n$ 只以增量 $| \Delta | = n$ 的身份出现；$n \le 10$ 的小数据范围纯粹是降低实现压力的烟雾弹。
3. **累加即答案**：起点编号为 $0$，`sum(增量)` 直接就是终局编号；一行 Python 即可完成。
4. **坐标版同样可写**：若不放心增量直加，维护 $(i, j)$ 每步加减 1、最后 `i * n + j` 折算，两版对拍可互相验证。

## 5. 正确性证明

**引理 1**：设某时刻蛇位于 $(i, j)$、编号 $pos = i \times n + j$，则执行任一指令后的新编号等于 $pos + \Delta$（$\Delta$ 如上表）。

**证明**：以 `DOWN` 为例，新坐标 $(i+1, j)$，新编号 $= (i+1) \times n + j = i \times n + j + n = pos + n$；`RIGHT` 同理：$i \times n + (j+1) = pos + 1$；`UP`/`LEFT` 为减方向，对称成立。∎

**引理 2**（编号与坐标一一对应）：在 $0 \le i, j < n$ 的前提下，映射 $(i, j) \mapsto i \times n + j$ 是到 $\{0, 1, \dots, n^2 - 1\}$ 的双射，且每一步移动后编号**不发生跨行的低位进位/借位**。

**证明**：前半是带余除法的唯一性：$i = pos \,//\, n$、$j = pos \bmod n$。后半：水平指令发生在行内且数据保证不出界，故 $j \pm 1 \in [0, n)$，低位加减 1 不触及行边界；竖直指令只改高位 $i$。于是「编号直加」与「坐标移动后再折算」逐步一致。∎

**定理**：算法返回的 `pos` 等于蛇执行全部指令后所停留单元格的编号。

**证明**：对指令条数归纳。初始 $pos_0 = 0$，与起点编号一致（归纳基础）。设执行第 $k$ 条指令前 `pos` 与真实编号一致，由引理 2 数据保证不出界、引理 1 给出增量转移，执行后 `pos` 仍与真实编号一致。指令耗尽时 `pos` 即终局编号。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m)$，其中 $m = commands.length \le 100$。每条指令一次 $O(1)$ 查表与累加，总计 $m$ 次。
- **空间复杂度**：$O(1)$。仅一个整型 `pos`，增量表只含 4 个常数项。

## 7. 参考代码

### C++（坐标版：直观模拟）

```cpp
class Solution {
public:
    int finalPositionOfSnake(int n, vector<string>& commands) {
        int i = 0, j = 0;
        for (string& c : commands) {
            if      (c == "UP")    --i;
            else if (c == "DOWN")  ++i;
            else if (c == "LEFT")  --j;
            else                   ++j;
        }
        return i * n + j;
    }
};
```

### C++（编号版：查表累加）

```cpp
class Solution {
public:
    int finalPositionOfSnake(int n, vector<string>& commands) {
        int pos = 0;
        for (auto& c : commands)
            pos += (c == "UP")    ? -n :
                   (c == "DOWN")  ?  n :
                   (c == "LEFT")  ? -1 : 1;
        return pos;
    }
};
```

### Python（一行查表版）

```python
class Solution:
    def finalPositionOfSnake(self, n: int, commands: List[str]) -> int:
        delta = {"UP": -n, "DOWN": n, "LEFT": -1, "RIGHT": 1}
        return sum(delta[c] for c in commands)
```

## 8. 边界情况与易错点

1. **增量的方向别记反**：`DOWN` 是行号增大（编号 $+n$），因为编号按**行优先**从上往下排；若把矩阵画成 0 在下就容易写反。
2. **水平 $\pm 1$ 与竖直 $\pm n$ 别混淆**：左右是 $1$，上下是 $n$——牢记「行是高位」即可。
3. **不需要建矩阵、不需要边界检查**：数据保证不出界；若误加 `if` 判断越界，不仅多余还可能挡住合法移动。
4. **别被「蛇」吓到**：这里的蛇没有身体、没有自撞判定，只是单个点的移动，与「贪吃蛇」游戏题无关。
5. **若数据保证被去掉**：在列 $n-1$ 时 `RIGHT` 会使编号 $+1$「串」到下一行行首——数值合法但位置不存在。此时必须退回坐标版，每步检查 $0 \le i < n$、$0 \le j < n$。
6. **溢出**：$m \le 100$、每步 $|pos|$ 变化至多 $n \le 10$，全程 $|pos| \le 10 \times 100 \times 10 = 10^4$，`int` 绰绰有余。
