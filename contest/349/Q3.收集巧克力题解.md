# LeetCode 收集巧克力 题解

## 1. 题目概述

- **标题 / 题号**：收集巧克力（#2735，medium）
- **链接**：https://leetcode.cn/problems/collecting-chocolates/
- **来源**：LeetCode 第 349 场周赛 Q3
- **难度**：中等
- **标签**：数组、枚举

**题意**：给定长度为 $n$ 的整数数组 `nums`（下标可视为环形），`nums[i]` 是**收集下标 $i$ 处巧克力**的花费；初始下标 $i$ 处放的是**类型 $i$** 的巧克力。可以任意次执行「操作」：花费 $x$，让所有类型整体沿环**向前挪一格**（下标 $i$ 处的类型变为 $(i+1) \bmod n$ 处的类型，等价于类型 $t$ 从位置 $t$ 移到位置 $(t-1) \bmod n$）。要求把 $n$ 种类型**各收集一次**，返回最小总花费（收集费 + 操作费）。

**约束**：

- $1 \le n \le 1000$
- $1 \le \text{nums[i]} \le 10^9$
- $1 \le x \le 10^9$

> 💡 题眼藏在一句话里：**收集花费只绑定「位置」**（永远是 `nums[p]`），操作改变的只是「类型 ↔ 位置」的对应关系。于是每个类型真正要回答的问题是：**它一生会经过哪些位置，挑其中最便宜的买**。

## 2. 示例

**示例 1**

```text
输入：nums = [20,1,15], x = 5
输出：13
解释：初始类型分布 [0,1,2]：
  - k = 0 时用 1 买类型 1（此时它在位置 1）；
  - 操作一次（花 5），类型分布 [1,2,0]，用 1 买类型 2（它在位置 1）；
  - 操作一次（花 5），类型分布 [2,0,1]，用 1 买类型 0（它在位置 1）。
总成本 = 1 + 5 + 1 + 5 + 1 = 13，为最优方案。
```

**示例 2**

```text
输入：nums = [1,2,3], x = 4
输出：6
解释：操作太贵：k = 1 时收集和虽降到 4，但 4 + 1×4 = 8 > 6，
  不如原地全收（1 + 2 + 3 = 6）。
```

**示例 3**（自拟，覆盖 $n = 1$ 边界）

```text
输入：nums = [7], x = 3
输出：7
解释：唯一的类型就躺在唯一的位置上，任何操作都只是白花钱。
```

## 3. 解题思路

### 3.1 暴力思路：枚举每个类型的收集时刻

把整个过程看成一棵决策树：每个时刻可以「操作」或「收集任意位置」，状态空间指数爆炸。换一个等价的刻画：给每个类型 $t$ 选一个**收集时刻** $s_t \in [0, n-1]$（在第 $s_t$ 次操作之后购买），组合共 $n^n$ 种，$n = 1000$ 时约 $10^{3000}$，完全不可行。

瓶颈在于：各类型看似共享同一条「操作时间线」，收集时刻**互相耦合**。下面证明固定总操作次数后它们**完全独立**——暴力里真正必要的自由度只有总操作次数 $k$ 一个。

### 3.2 核心观察：固定总操作次数 $k$，各类型在「可达窗口」内独立取最小

![核心观察：操作让类型循环前移，类型t的可达窗口随k扩张](images/choco_rotation_window.svg)

三步走：

1. **位移规律**：操作 $k$ 次后，类型 $t$ 位于位置 $(t-k) \bmod n$。位置只由 $k$ 决定，**收集不改变任何类型的位置**——各类型「谁在何时被买走」互不干扰。
2. **时刻归一与独立取最小**：设方案总共操作 $K$ 次，则类型 $t$ 的收集时刻满足 $s_t \le K$，花费 $\text{nums}[(t-s_t) \bmod n]$。固定 $K$ 后各 $s_t$ 的选择互不制约（引理 2），最优收集部分是各类型在 $K+1$ 个**可达位置**中独立取最小，再加上操作费 $K \cdot x$ 得到 $\text{cost}(K)$；且最优方案必有 $K = \max_t s_t$——最后一次收集之后的操作纯属烧钱（引理 1）。
3. **枚举上界**：$K = n-1$ 时窗口已覆盖全部 $n$ 个位置，更大的 $K$ 收集部分不变、操作费只增不减（引理 3）。于是

$$\text{ans} = \min_{0 \le K \le n-1} \left[ \underbrace{\sum_{t=0}^{n-1} \min_{0 \le s \le K} \text{nums}\big[(t-s) \bmod n\big]}_{\text{各类型最优收集费之和}} + K \cdot x \right]$$

> ⚠️ **便宜位置可复用**：收集并不消耗位置上的巧克力——不同类型可以在**不同时刻**先后经过同一个便宜位置、各买一次（示例 1 里三种类型全蹭了位置 1 的「1 元」）。这是「各类型独立取最小」在物理上合法的根基，也是本题最容易想岔的点。

### 3.3 算法流程：枚举 $k$ + 增量维护窗口最小

![算法流程：枚举k，增量更新cost数组，ans取min](images/choco_algo_flow.svg)

按定义对每个 $k$ 重算所有窗口最小，总代价 $\sum_{k} O(n \cdot k) = O(n^3)$，$n = 1000$ 时约 $10^9$，不可行。**增量观察**：$k$ 每加一，类型 $t$ 的窗口只**新增一个位置** $(t-k) \bmod n$，于是

$$\text{cost}[t] \gets \min\big(\text{cost}[t],\; \text{nums}[(t-k) \bmod n]\big)$$

只读不变的 `nums`、只写自家一格 `cost[t]`，各 $t$ 互不依赖 → 每轮 $O(n)$，总计 $O(n^2)$。

```text
cost ← nums 的副本                            # k = 0：每个类型的窗口只有自己
ans ← Σ cost
for k = 1 … n−1:
    for t = 0 … n−1:
        cost[t] ← min(cost[t], nums[(t−k) mod n])   # 窗口新增一个位置
    ans ← min(ans, Σ cost + k·x)
return ans
```

### 3.4 示例演算

![示例演算：k等于0/1/2时cost数组与总成本的演进](images/choco_example_walkthrough.svg)

以示例 1（`nums = [20,1,15]`，`x = 5`，`n = 3`）为例：

- $k=0$：$\text{cost} = [20, 1, 15]$，$\Sigma = 36$，总成本 $36$；
- $k=1$：新增位置 $(t-1) \bmod 3$，$\text{cost} = [15, 1, 1]$（T0 借位置 2、T2 借位置 1），$17 + 5 = 22$；
- $k=2$：新增位置 $(t-2) \bmod 3$，$\text{cost} = [1, 1, 1]$（T0 借位置 1），$3 + 10 = \mathbf{13}$。

答案 $\min\{36, 22, 13\} = 13$。示例 2（`x = 4`）正相反：$k=1$ 时收集和虽降到 $4$，但 $4 + 4 = 8 > 6$，枚举自然停在 $k=0$ 的 $6$——**「用操作换便宜位置」与「操作本身要花钱」之间的权衡曲线**，被枚举 $k$ 一网打尽。

## 4. 算法细节

1. **`cost` 必须是副本**：每一轮都要读**原始** `nums[(t-k) mod n]`；若把更新写回 `nums`，从第 2 轮起读到的就是被污染的值。
2. **循环下标**：$t - k \in [-(n-1),\, n-1]$。Python 负数取模天然归正，`(t-k) % n` 直接合法；C++ 的 `%` 保留符号，须 `idx = t - k; if (idx < 0) idx += n;`——范围保证加一次 $n$ 即可归正（前提是 $k \le n-1$）。
3. **溢出**：$\sum \text{cost} \le 10^{12}$、$k \cdot x \le 10^{12}$，总数约 $2 \times 10^{12}$，C++ 中 `cost`/`sum`/`ans` 全用 `long long`，且 `k * x` 要显式提升后再乘（`x` 形参是 `int`，直接相乘按 `int` 溢出）。
4. **一趟循环顺手求和**：更新 `cost[t]` 的同一趟里累加 `sum`，免掉每轮再扫一遍。
5. **`ans` 初值**：必须是 $k=0$ 的 $\sum \text{nums}$——「一次都不操作」本身是候选方案（示例 2 的最优解），漏掉即错。

## 5. 正确性证明

将任意可行方案刻画为：给每个类型 $t$ 选定收集时刻 $s_t$（在第 $s_t$ 次操作**之后**购买），总操作次数为 $K$；方案合法当且仅当 $s_t \le K$ 对所有 $t$ 成立，总花费为 $\sum_t \text{nums}[(t-s_t) \bmod n] + K \cdot x$。

**引理 1**（无浪费操作）：存在最优方案满足 $K = \max_t s_t$。

**证明**：若 $K > \max_t s_t$，删去时刻 $\max_t s_t$ 之后的全部 $K - \max_t s_t$ 次操作：所有收集都发生在这些操作之前，各 $s_t$ 及其对应位置 $(t - s_t) \bmod n$ 均不变，总花费减少 $(K - \max_t s_t) \cdot x \ge x > 0$，与最优性矛盾。∎

**引理 2**（固定 $K$ 时逐类型独立取最小）：对固定 $K \in [0, n-1]$，合法方案收集部分的最小值恰为 $\sum_t \min_{0 \le s \le K} \text{nums}[(t-s) \bmod n]$，且该值可被某合法方案取到。

**证明**：下界：任一合法方案的每个收集时刻满足 $s_t \le K$，故每项 $\text{nums}[(t-s_t) \bmod n] \ge \min_{0 \le s \le K} \text{nums}[(t-s) \bmod n]$，求和即得。可达：对每个 $t$ 取达到最小值的时刻 $s_t^{*}$（$s_t^{*} \le K$ 保证合法），按 $s_t^{*}$ 从小到大的次序交错执行「操作 → 收集同一时刻的类型」，得到花费恰为该和的合法方案。∎

**引理 3**（枚举上界）：$K \ge n-1$ 时 $\text{cost}(K) \ge \text{cost}(n-1)$，且 $K > n-1$ 时严格不等。

**证明**：$s$ 取遍 $0, \dots, n-1$ 时 $(t-s) \bmod n$ 取遍全部 $n$ 个位置，故 $K \ge n-1$ 的可达窗口与 $K = n-1$ 的相同，收集部分相等；操作部分 $K \cdot x$ 随 $K$ 严格递增（$x \ge 1$）。∎

**定理**：算法返回收集全部类型的最小总花费。

**证明**：先确认算法维护的量：对 $k$ 归纳，第 $k$ 轮结束后 `cost[t]` 恰为 $\min_{0 \le s \le k} \text{nums}[(t-s) \bmod n]$（初始 $k=0$ 窗口只有自身；每轮恰并入新位置 $(t-k) \bmod n$），故 `ans` 为 $\min_{0 \le k \le n-1} \text{cost}(k)$。任一可行方案的花费，由引理 1 不妨设 $K = \max_t s_t$，其收集部分由引理 2 不小于 $\text{cost}(K)$ 的收集部分，故总花费 $\ge \text{cost}(K)$，再由引理 3 $\ge \min_{0 \le k \le n-1} \text{cost}(k)$，即算法输出。反之，引理 2 的「可达」部分说明输出值可被某个合法方案取到，不是空想的下界。两边夹得：输出即最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$——外层枚举 $k \in [1, n-1]$ 共 $n-1$ 轮，每轮对 $n$ 个类型各做一次 $O(1)$ 的 min 更新与累加；$n \le 1000$ 时约 $10^6$ 次基本操作。
- **空间复杂度**：$O(n)$——仅维护一个 `cost` 数组（`nums` 为输入不计）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minCost(vector<int>& nums, int x) {
        int n = nums.size();
        vector<long long> cost(nums.begin(), nums.end()); // k = 0：窗口只有自己
        long long ans = 0;
        for (int t = 0; t < n; t++) ans += cost[t];
        for (int k = 1; k < n; k++) {
            long long sum = 0;
            for (int t = 0; t < n; t++) {
                int idx = t - k;                             // (t - k) mod n
                if (idx < 0) idx += n;
                cost[t] = min(cost[t], (long long)nums[idx]); // 窗口新增一个位置
                sum += cost[t];
            }
            ans = min(ans, sum + (long long)k * x);         // 先提升再乘，防溢出
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minCost(self, nums: List[int], x: int) -> int:
        n = len(nums)
        cost = nums[:]                                  # k = 0：窗口只有自己
        ans = sum(cost)
        for k in range(1, n):
            total = 0
            for t in range(n):
                cost[t] = min(cost[t], nums[(t - k) % n])  # 负数取模天然归正
                total += cost[t]
            ans = min(ans, total + k * x)
        return ans
```

> 💡 Python 的 `%` 对负数返回非负结果，`(t - k) % n` 直接得到合法循环下标，甚至可简写 `nums[t - k]`（负下标自动绕回到 `n + t - k`）；C++ 的 `%` 保留符号，必须手动归正。

## 8. 边界情况与易错点

1. **$n = 1$**：唯一类型唯一位置，答案 `nums[0]`；`k` 循环体不执行，代码天然正确。
2. **溢出**：最坏 $\sum \text{cost} + k \cdot x \approx 2 \times 10^{12}$，远超 32 位上界；C++ 里 `cost`/`sum`/`ans` 用 `long long`，且 `k * x` 须先提升再乘（`x` 形参是 `int`，`k * x` 直接相乘按 `int` 溢出，最大约 $10^{12}$）。
3. **C++ 负数取模**：`t - k` 可为负，`(t - k) % n` 得负数导致越界；`if (idx < 0) idx += n` 一次归正的前提是 $k \le n-1$——若把上界错写成 $k \le n$，一次加 $n$ 就不够了，这是「上界写错只在边界炸」的隐蔽 bug。
4. **别原地改 `nums`**：每轮要读原始 `nums` 的新位置成本；把 `cost` 写回 `nums`，从第 2 轮起读到污染值。
5. **`ans` 初值**：必须是 $k=0$ 的 $\sum \text{nums}$；初始化成 `0` 或只依赖循环内更新，会把「不操作最优」的用例（示例 2）答成 $8$。
6. **「便宜位置可复用」别想岔**：不同类型可在不同时刻各买一次同一位置，无需为类型间「抢位置」做协调——这正是独立取 min 合法的前提（引理 2 的可达部分）。
7. **别自行加「拿走就没了」的设定**：收集既不消耗位置、也不改变类型分布；若误加消耗语义，就会跑偏去做二分图匹配。
8. **枚举上界**：$k$ 到 $n-1$ 为止（引理 3）；$x$ 再小（最小为 $1$）也不会让「多转一圈」变优。
