# LeetCode 既不是最小值也不是最大值 题解

## 1. 题目概述

- **标题 / 题号**：既不是最小值也不是最大值（#2733，easy）
- **链接**：https://leetcode.cn/problems/neither-minimum-nor-maximum/
- **来源**：LeetCode 第 349 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序

**题意**：给定一个由**互不相同**的正整数组成的数组 `nums`，返回其中**任意一个**既不是最小值也不是最大值的元素；若不存在这样的元素，返回 $-1$。

**约束**：

- $1 \le \mathrm{nums.length} \le 100$
- $1 \le \mathrm{nums[i]} \le 100$
- `nums` 中的所有数字互不相同

> 💡 签到题的全部难度都藏在 $n < 3$ 这个分支上：$n \ge 3$ 时，**任取三个数的中位数**就是合法答案——全程只读前三个元素，$O(1)$ 收工。题面保证的「互不相同」正是中位数法的可行性前提，值得想清楚为什么（见第 5 节证明与第 8 节反例）。

## 2. 示例

**示例 1**

```text
输入：nums = [3,2,1,4]
输出：2
解释：最小值是 1，最大值是 4，因此 2 或 3 都是合法答案（返回任意一个即可）。
```

**示例 2**

```text
输入：nums = [1,2]
输出：-1
解释：只有两个数，一个是最小值、一个是最大值，不存在合法答案。
```

**示例 3**

```text
输入：nums = [2,1,3]
输出：2
解释：n = 3 时合法答案恰好唯一（中位数），前三个元素的中位数即 2。
```

**示例 4**（自拟，覆盖 $n = 1$ 的边界）

```text
输入：nums = [7]
输出：-1
解释：唯一的元素既是最小值又是最大值，返回 -1。
```

## 3. 解题思路

### 3.1 暴力思路：排序取第二个

最直接的写法是**整体排序**后取 `nums[1]`：排序后 `nums[0]` 是最小值、`nums[n-1]` 是最大值，中间任何一个都合法。$n \le 100$，$O(n \log n)$ 轻松通过，比赛时这已经够用。

```text
if n < 3: return -1
sort(nums)
return nums[1]
```

另一个等价的暴力是**两遍扫描**：第一遍求出 `minV` 与 `maxV`，第二遍返回第一个既不等于 `minV` 也不等于 `maxV` 的元素，$O(n)$。

两者都对，但都「看完了整个数组」。本题真正值得沉淀的是下面的观察——它连数组都不必看完。

### 3.2 核心观察：任取三个互异数，中位数必可行

![核心观察：任取三个数，中位数既非最小也非最大](images/neither_min_max_concept.svg)

关键 insight：**不需要知道全局最小/最大是谁**。任取三个互异元素 $x < y < z$：

1. 左边有 $x < y$，数组中存在比 $y$ 小的数 ⇒ $y$ **不是全局最小**；
2. 右边有 $z > y$，数组中存在比 $y$ 大的数 ⇒ $y$ **不是全局最大**。

于是全局最小/最大在任取的三个数里**只能占据两端，永远轮不到中间**——返回这组数的中位数即可。特别地，直接取**前三个**元素 `nums[0..2]` 的中位数，答案依然合法，时间降到 $O(1)$。

> ⚠️ 注意上述论证用到了「互不相同」：若允许重复，反例 `[1,1,2]` 的前三个元素中位数是 $1$，恰为最小值，中位数法失效（见第 8 节第 5 条）。

### 3.3 算法流程

![算法流程：n小于3判空加前三个元素取中位数](images/neither_min_max_decision.svg)

```text
1. if len(nums) < 3: return -1
2. a, b, c = nums[0], nums[1], nums[2]
3. 三次比较换序（至多三次 swap），使 a ≤ b ≤ c
4. return b          # b 即中位数
```

### 3.4 示例演算

![示例演算：[3,2,1,4] 取前三个的中位数，[1,2] 返回 -1](images/neither_min_max_example.svg)

以 `nums = [3,2,1,4]` 为例：取前三个元素 $(3,2,1)$，排序得 $1 < 2 < 3$，中位数为 $2$，即答案（输出 $3$ 同样正确；与整体排序后取 `nums[1]` 的结果一致）。而 `nums = [1,2]` 时 $n = 2 < 3$，每个元素非最小即最大，直接返回 $-1$。

## 4. 算法细节

1. **判空分支在取元素之前**：对 `nums[1]`、`nums[2]` 的访问必须在 $n \ge 3$ 成立后进行；C++ 里越界是未定义行为，Python 会抛 `IndexError`。
2. **三次比较换序求中位数**：`if (a>b) swap(a,b); if (b>c) swap(b,c); if (a>b) swap(a,b)`——第三次交换不可省（反例输入 `3,1,2`：两次交换后 `b` 仍可能停在 $3$）。Python 直接写 `sorted(nums[:3])[1]` 更不易错。
3. **「任一」合法答案都接受**：判题只校验返回值是否既非最小也非最大，不要画蛇添足去找最小的合法答案。
4. **互异性是前提**：题面保证互异，因此三个数的中位数严格介于另两个之间；若题面改版允许重复，套路需要相应调整（见第 8 节）。

## 5. 正确性证明

**引理 1**：$n \le 2$ 时不存在合法答案。

**证明**：$n = 1$ 时唯一元素既是最小值又是最大值；$n = 2$ 时两数互异，较小者是最小值、较大者是最大值。两种情形每个元素都是最值，返回 $-1$ 正确。∎

**引理 2**：任取数组中三个互异元素 $x < y < z$，则 $y$ 既非数组最小值也非数组最大值。

**证明**：因元素互异，最小值严格小于其余所有元素。若 $y$ 是最小值，则 $y \le x$，与 $x < y$ 矛盾，故 $y$ 不是最小值。同理最大值严格大于其余所有元素，若 $y$ 是最大值则 $y \ge z$，与 $y < z$ 矛盾，故 $y$ 不是最大值。∎

**定理**：算法返回合法答案，当且仅当合法答案存在。

**证明**：$n < 3$ 时由引理 1 不存在合法答案，算法返回 $-1$；$n \ge 3$ 时前三个元素存在且互异，由引理 2 其中位数既非最小也非最大，算法返回之，为合法答案。∎

## 6. 复杂度分析

- **时间复杂度**：中位数法 $O(1)$——只读前三个元素、做至多三次比较；排序法 $O(n \log n)$、两遍扫描法 $O(n)$，在本题 $n \le 100$ 下同样轻松通过。
- **空间复杂度**：$O(1)$，只用到常数个变量（排序法用语言内置原地排序时递归栈 $O(\log n)$）。

## 7. 参考代码

### C++（$O(1)$：前三个元素取中位数）

```cpp
class Solution {
public:
    int findNonMinOrMax(vector<int>& nums) {
        if (nums.size() < 3) return -1;
        int a = nums[0], b = nums[1], c = nums[2];
        if (a > b) swap(a, b);
        if (b > c) swap(b, c);
        if (a > b) swap(a, b);
        return b;
    }
};
```

### Python（排序切片版，语义等价）

```python
class Solution:
    def findNonMinOrMax(self, nums: List[int]) -> int:
        if len(nums) < 3:
            return -1
        return sorted(nums[:3])[1]
```

比赛时两者任选、手速优先；数据范围放大（如 $n \le 10^6$）或元素只能流式访问时，$O(1)$ 版「不必看完整个数组」的优势才真正体现。

## 8. 边界情况与易错点

1. **$n = 1$**：唯一元素既是最小值又是最大值，返回 $-1$。
2. **$n = 2$**：一个最小值一个最大值，返回 $-1$；判空分支必须放在取 `nums[1]`/`nums[2]` 之前，否则 $n = 1$ 越界、$n = 2$ 答错（如 `[1,2]` 直接返回 `nums[1]` 会输出 $2$，恰是最大值）。
3. **$n = 3$**：合法答案恰好唯一（中位数），如 `[2,1,3]` 只能输出 $2$。
4. **别忽略「任一」**：`[3,2,1,4]` 输出 $2$ 或 $3$ 都对，不要自加「返回最小合法答案」的约束。
5. **互异性不可丢**：若题面改为允许重复，`[1,1,2]` 的前三个元素中位数 $1$ 正是最小值，中位数法失效；此时合法答案存在当且仅当**不同取值个数 $\ge 3$**，需一遍维护最小/次小并检查次小严格大于最小。
6. **值域无关**：算法只做大小比较，`nums[i]` 放大到 $10^{18}$ 也只是把 `int` 换成 `long long`，逻辑不变。
