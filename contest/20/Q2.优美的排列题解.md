# LeetCode 优美的排列 题解

## 1. 题目概述

- **标题 / 题号**：优美的排列（#526，medium）
- **链接**：https://leetcode.cn/problems/beautiful-arrangement/
- **来源**：LeetCode 第 20 场周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、动态规划、回溯、状态压缩

**题意**：把 $1$ 到 $n$ 这 $n$ 个整数各用一次，排成长度 $n$ 的数组 `perm`（**下标从 1 开始**）。若每个位置 $i$ 都满足下面两条之一，则称 `perm` 是一个**优美排列**：

$$\text{perm}[i] \bmod i = 0 \quad\text{或}\quad i \bmod \text{perm}[i] = 0$$

求优美排列的个数。

**约束**：

- $1 \le n \le 15$
- 位置与取值都是 $1$-indexed；$i=1$ 时两条件必成立，即值 $1$ 与任何位置都相容

> 💡 $n \le 15$ 是本题最重要的信号：$2^{15} = 32768$，恰好落在「可以枚举全部子集」的区间，直指**状态压缩 DP**。而 $15! \approx 1.3 \times 10^{12}$，全排列枚举必然超时。

## 2. 示例

**示例 1**

```text
输入：n = 2
输出：2
解释：两个优美排列
  [1,2]：perm[1] = 1 被 i = 1 整除；perm[2] = 2 被 i = 2 整除
  [2,1]：perm[1] = 2 被 i = 1 整除；i = 2 被 perm[2] = 1 整除
```

**示例 2**

```text
输入：n = 1
输出：1
解释：只有 [1]，且 1 能被 1 整除。
```

**示例 3（补充演算，非官方样例）**

```text
输入：n = 3
输出：3
解释：[1,2,3]、[2,1,3]、[3,2,1] 合法；
      [2,3,1] 不合法——位置 2 放 3，3 % 2 = 1 且 2 % 3 = 2，两个方向都不整除。
      注意 [3,2,1] 合法：位置 3 放 1 时靠 i % perm[i] = 0 成立。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是枚举 $1..n$ 的全部 $n!$ 个排列，再逐位检查两个整除条件，复杂度 $O(n \cdot n!)$，$n=15$ 时约 $1.3\times10^{12}$ 次，不可行。

退一步用**带 `used` 标记的回溯**：按位置 $1,2,\dots,n$ 依次放数，只在整除相容时才进入下一层。整除约束很强，剪枝后搜索树远小于 $n!$——实测 $n=15$ 时只递归 **747,961** 次，本题完全能过。但它的最坏复杂度仍是 $O(n!)$ 量级：一旦把条件改弱（比如只要求相邻互质），剪枝立刻失效。要一个**与具体数据无关的上界**，就得把「从不同顺序到达同一局面」的路径合并——这正是状态压缩 DP 的出发点。

### 3.2 核心观察：二分图完美匹配 + 一维位掩码状态

![二分图模型：位置与值的相容关系](images/wc20_q2_bipartite_model.svg)

把「位置」和「值」分列两侧，位置 $i$ 与值 $k$ 连边当且仅当

$$k \mid i \quad\text{或}\quad i \mid k$$

于是一个优美排列就是一个从位置侧到值侧、每个点恰用一次的**完美匹配**，题目数的正是这个二分图的完美匹配条数。这个视角立刻给出两条可用性质：

1. **每个位置的候选集只由它自己决定**：位置 $i$ 的可选值是「$i$ 的约数」并上「不超过 $n$ 的 $i$ 的倍数」，记作 `allowed[i]`。
2. **候选集普遍很小**：$i > n/2$ 时倍数只剩 $i$ 本身；若 $i$ 还是质数，位置 $i$ 只能放 $1$ 或 $i$——约束到后段急剧收紧。

**状态压缩的关键**：从左到右填位置时，「填到第几位」不必单独存。已经用了 $c$ 个值，下一个位置必然是 $c+1$。所以只需记录

$$\text{mask} = \text{已用值的集合}\quad(\text{第 } k-1 \text{ 位为 } 1 \iff \text{值 } k \text{ 已用})$$

一维状态就够，位置由 $pos = \text{popcount}(\text{mask}) + 1$ 现场算出。状态总数不超过 $2^n$，$n=15$ 时为 32768。

### 3.3 算法流程与状态转移

![状压 DP 流程：候选掩码 + lowbit 枚举](images/wc20_q2_algorithm_flow.svg)

1. **预处理候选掩码**：对每个位置 $p$ 求出可接受值集合的位掩码 `allowed[p]`。此后判断相容只需一次 `&`，转移内层不再做取模。
2. **定义状态**：$dp[\text{mask}]$ = 用 `mask` 中的值填满前 $\text{popcount}(\text{mask})$ 个位置的方案数。
3. **初始化**：$dp[0] = 1$（空前缀算一种方案），其余为 $0$，$\text{full} = 2^n - 1$。
4. **转移**：按 `mask` 递增枚举，$pos = \text{popcount}(\text{mask}) + 1$，候选 `cand = allowed[pos] & ~mask`；对 `cand` 中每个位 $b$（对应值 $k$）执行

$$dp[\text{mask} \mid b] \mathrel{+}= dp[\text{mask}]$$

5. **输出**：$dp[\text{full}]$。

![从 mask=0100 出发的三条转移](images/wc20_q2_state_transition.svg)

**为什么「递增枚举 mask」就是拓扑序？** 每次转移都把一个 $0$ 位翻成 $1$，于是 $\text{mask} \mid b > \text{mask}$（数值严格变大）。所以按整数递增遍历时，任何状态在被读取前一定已经算完，既不需要递归，也不需要 BFS 分层。

### 3.4 示例演算（n = 4）

候选表：位置 1 放 $\{1,2,3,4\}$；位置 2 放 $\{1,2,4\}$；位置 3 放 $\{1,3\}$；位置 4 放 $\{1,2,4\}$。

![n=4 的分层 dp 走查](images/wc20_q2_walkthrough.svg)

按 `mask` 递增推一遍（`cand` 列已扣掉 `mask` 中的值）：

| mask | 已用值 | pos | cand | 去向 | dp |
|---|---|---|---|---|---|
| 0000 | ∅ | 1 | {1,2,3,4} | 0001 / 0010 / 0100 / 1000 | 1 |
| 0001 | {1} | 2 | {2,4} | 0011 / 1001 | 1 |
| 0010 | {2} | 2 | {1,4} | 0011 / 1010 | 1 |
| 0100 | {3} | 2 | {1,2,4} | 0101 / 0110 / 1100 | 1 |
| 1000 | {4} | 2 | {1,2} | 1001 / 1010 | 1 |
| 0011 | {1,2} | 3 | {3} | 0111 | 2 |
| 0101 | {1,3} | 3 | ∅ | 死路，无出边 | 1 |
| 0110 | {2,3} | 3 | {1} | 0111 | 1 |
| 1001 | {1,4} | 3 | {3} | 1101 | 2 |
| 1010 | {2,4} | 3 | {1,3} | 1011 / 1110 | 2 |
| 1100 | {3,4} | 3 | {1} | 1101 | 1 |
| 0111 | {1,2,3} | 4 | {4} | 1111 | 3 |
| 1011 | {1,2,4} | 4 | ∅ | 死路，无出边 | 2 |
| 1101 | {1,3,4} | 4 | {2} | 1111 | 3 |
| 1110 | {2,3,4} | 4 | {1} | 1111 | 2 |

汇入终点的三条边分别贡献 $3$、$3$、$2$，故 $dp[1111] = 8$，与 $n=4$ 的正确答案一致。两处细节值得记住：`0011` 由 `0001`、`0010` 两条路径到达，所以 $dp[0011]=2$——这正是状压 DP 比纯回溯省的地方；`0101`、`1011` 虽 $dp$ 非零却已无候选（前者在 `pos=3` 时 `allowed[3]={1,3}` 全被占用，后者在 `pos=4` 时 `allowed[4]={1,2,4}` 全被占用），都是走不到终点的死路。

## 4. 算法细节

1. **候选掩码怎么建**：`for p in 1..n: for k in 1..n: if k % p == 0 or p % k == 0: allowed[p] |= 1 << (k-1)`，$O(n^2)$；$n \le 15$ 时连筛法优化都不值得写。
2. **popcount 每状态只算一次**：C++ 用 `__builtin_popcount`，Python 用 `int.bit_count()`；不要在内层候选循环里重复计算。
3. **`~mask` 的高位**：C++ 中 `~mask` 会把高位全置 1，但 `allowed[pos]` 只有低 $n$ 位为 1，相与后高位自动清零，因此不必写 `& full`；但**绝不能**把 `~mask` 单独拿去遍历或当下标。
4. **lowbit 枚举候选**：`bit = cand & -cand` 取出最低的候选位，`cand ^= bit`（等价 `cand &= cand - 1`）清掉它。循环次数等于候选个数，而不是 $n$。
5. **递推方向与顺序**：`mask` 从 $0$ 到 $\text{full}-1$ 递增，`full` 无后继可跳过；靠 `mask | bit > mask` 保证读到的都是已算完的值。
6. **`dp[0] = 1` 的语义**：「一个值都没放」也算一种方案，它是所有路径的唯一入口；写成 $0$ 会让整张表恒为 $0$。
7. **跳零剪枝**：`dp[mask] == 0` 直接跳过。$n=15$ 时 32768 个状态里只有 **19,393** 个可达，有效转移仅 **34,889** 条，远低于 $n \cdot 2^n$ 的理论上界。
8. **数值范围**：$n=15$ 的答案是 $24{,}679$，`dp` 的最大值同样是 $24{,}679$，`int` 足够；改成「带权计数」时才需要 `long long`。

## 5. 正确性证明

**引理 1（状态完备）**：若 `mask` 中的值恰好是某条合法前缀用掉的值集，则该前缀长度为 $\text{popcount}(\text{mask})$，下一待填位置必为 $pos = \text{popcount}(\text{mask}) + 1$，可用值集为 `allowed[pos] & ~mask`。

**证明**：前缀从位置 1 起逐位填写，每填一位恰好消耗一个互不相同的值，故前缀长度 = 已用值个数 = `popcount(mask)`，下一个位置即长度 +1。某个值此时可放，当且仅当它与该位置相容（在 `allowed[pos]` 中）且尚未使用（不在 `mask` 中）。∎

**引理 2（dp 语义不变式）**：对任意 `mask`，$dp[\text{mask}]$ 等于「用 `mask` 中的值填满前 $\text{popcount}(\text{mask})$ 个位置」的合法方案数。

**证明**：对 $c = \text{popcount}(\text{mask})$ 归纳。$c=0$ 时只有空方案，$dp[0]=1$ 成立。设 $c-1$ 时不变式成立，考察 $c$ 时的 `mask`：任一合法前缀的最后一位是位置 $c$，其值 $k \in \text{mask}$ 且必须 $k \in \text{allowed}[c]$；删去这一位，得到值集为 $\text{mask}\setminus\{k\}$、长度为 $c-1$ 的合法前缀。反之，任一长为 $c-1$ 的合法前缀补上满足条件的 $k$，就得到长为 $c$ 的合法前缀。这个「删去 / 补上末位」的对应是双射，而转移把所有 $k \in \text{allowed}[c] \cap \text{mask}$ 的 $dp[\text{mask}\setminus\{k\}]$ 恰好累加一次进 $dp[\text{mask}]$，故不变式成立。∎

**引理 3（遍历顺序合法）**：按整数从 $0$ 递增到 $\text{full}$ 时，`mask` 的任何前驱都先于它被处理。

**证明**：前驱形如 $\text{mask}\setminus\{k\}$，即把 `mask` 的某个 $1$ 位清零；这样的数在二进制下严格更小，故数值更小，递增遍历必然先处理它。∎

**定理**：算法返回的 $dp[\text{full}]$ 恰为优美排列的个数。

**证明**：`full` 表示 $1..n$ 全部用过，$\text{popcount}(\text{full}) = n$。由引理 2，$dp[\text{full}]$ 就是「用全部值填满全部位置」的合法方案数，即优美排列数。另一方面，每个优美排列按位置顺序读出一条从 $0$ 到 `full`、每次加一个值的转移路径，两个不同排列的首个不同位置决定路径首次分叉，故路径互不相同；由引理 1、3，所有这样的路径也都被枚举并累加。故计数既不重复也不遗漏。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot 2^n)$。预处理 `allowed` 为 $O(n^2)$；主循环遍历 $2^n$ 个状态，每个状态至多枚举 $n$ 个候选位，每次转移 $O(1)$（位运算 + `popcount`）。$n=15$ 时上界约 $15 \times 32768 \approx 4.9\times10^{5}$ 次操作。
- **空间**：$O(2^n)$ 存 `dp`（32768 个 `int`，约 128 KB），$O(n)$ 存 `allowed`。若用自顶向下记忆化，还需同样规模的 `memo` 与 $O(n)$ 的递归栈。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int countArrangement(int n) {
        // allowed[p]：位置 p 可接受的值集合，bit(k-1) 表示值 k
        vector<int> allowed(n + 1, 0);
        for (int p = 1; p <= n; ++p)
            for (int k = 1; k <= n; ++k)
                if (k % p == 0 || p % k == 0) allowed[p] |= 1 << (k - 1);

        int full = (1 << n) - 1;
        vector<int> dp(1 << n, 0);
        dp[0] = 1;                                  // 空前缀：1 种方案
        for (int mask = 0; mask < full; ++mask) {
            if (dp[mask] == 0) continue;            // 不可达状态
            int pos = __builtin_popcount((unsigned)mask) + 1;  // 下一位置
            for (int cand = allowed[pos] & ~mask; cand; cand &= cand - 1) {
                int bit = cand & -cand;             // lowbit：取一个候选值
                dp[mask | bit] += dp[mask];
            }
        }
        return dp[full];
    }
};
```

### Python

```python
class Solution:
    def countArrangement(self, n: int) -> int:
        # allowed[p]：位置 p 可接受的值集合，第 k-1 位表示值 k
        allowed = [0] * (n + 1)
        for p in range(1, n + 1):
            m = 0
            for k in range(1, n + 1):
                if k % p == 0 or p % k == 0:
                    m |= 1 << (k - 1)
            allowed[p] = m

        full = (1 << n) - 1
        dp = [0] * (1 << n)
        dp[0] = 1                                   # 空前缀：1 种方案
        for mask in range(full):                    # full 无后继，可跳过
            cur = dp[mask]
            if cur == 0:                            # 不可达状态
                continue
            pos = bin(mask).count("1") + 1           # 3.10+ 可写 mask.bit_count()
            cand = allowed[pos] & ~mask
            while cand:
                bit = cand & -cand                  # lowbit：取一个候选值
                cand ^= bit
                dp[mask | bit] += cur
        return dp[full]
```

## 8. 边界情况与易错点

1. **$n=1$**：$\text{full}=1$，主循环只处理 `mask=0`，`pos=1`，`cand=allowed[1]=1`，得 $dp[1]=1$，无需任何特判。
2. **1-indexed 与位下标的换算**：位置 `pos` 从 1 开始，值 $k$ 对应第 $k-1$ 位。若把 `pos` 写成 `popcount(mask)`（0-indexed），位置 1 会退化成位置 0，出现除零或整体错位。
3. **两个方向的整除都要判**：只判 $k \bmod pos = 0$ 会漏掉「位置被值整除」的情形；$n=2$ 的 `[2,1]` 正是靠 $2 \bmod 1 = 0$ 才合法。
4. **`~mask` 在 C++ 中高位全为 1**：必须与 `allowed[pos]` 相与后才安全；若直接拿 `~mask` 枚举候选位，会遍历到大于 $n$ 的「幽灵值」。
5. **`dp[mask]` 非零 ≠ 能走到终点**：$n=4$ 的 `0101`（`pos=3`）与 `1011`（`pos=4`）都已无候选值，$dp$ 为 1 和 2 却没有出边。不要因为「当前状态有方案」就提前断言有解或提前返回。
6. **Python 版本差异**：`int.bit_count()` 需要 3.10+；旧环境请用 `bin(mask).count("1")`，否则 `AttributeError`。
7. **纯回溯也能过，但别把它当 $O(n \cdot 2^n)$**：$n=15$ 时带剪枝回溯实测递归 747,961 次；它的复杂度依赖整除约束的强度，换个条件就可能退化，状压 DP 才是与数据无关的稳妥写法。
