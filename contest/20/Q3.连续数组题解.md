# LeetCode 连续数组 题解

## 1. 题目概述

- **标题 / 题号**：连续数组（#525，medium）
- **链接**：https://leetcode.cn/problems/contiguous-array/
- **来源**：LeetCode 第 20 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、前缀和

**题意**：给定一个只含 `0` 和 `1` 的数组 `nums`，找出**最长的连续子数组**，使得其中 `0` 与 `1` 的数量相等，返回该子数组的长度；不存在这样的子数组时返回 `0`。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- `nums[i]` 不是 `0` 就是 `1`

> 💡 题面中的数组只有两种取值，这个「极窄值域」是本题所有加速手段的来源：它让「数量差」可以退化为「一个整数」来维护。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1]
输出：2
解释：[0, 1] 是具有相同数量 0 和 1 的最长连续子数组。
```

**示例 2**

```text
输入：nums = [0,1,0]
输出：2
解释：[0, 1]（或 [1, 0]）是具有相同数量 0 和 1 的最长连续子数组。
      整个数组含 2 个 0、1 个 1，不平衡，故答案是 2 而不是 3。
```

**示例 3**

```text
输入：nums = [0,1,1,1,1,1,0,0,0]
输出：6
解释：[1,1,1,0,0,0] 是满足条件的最长子数组（下标 3..8）。
      注意它并不是从某个端点开始的，说明必须枚举任意区间，不能只做前后缀。
```

## 3. 解题思路

### 3.1 暴力思路

枚举左右端点 $0 \le i \le j < n$，统计区间内 `0` 与 `1` 的个数并比较，复杂度 $O(n^2)$（用两个前缀计数可做到每组 $O(1)$）。$n = 10^5$ 时约 $5 \times 10^9$ 组，必然超时。

更糟的是「从每个起点向右扩展并即时判断」也是 $O(n^2)$——示例 3 的答案区间既不贴左端也不贴右端，任何「只试前后缀」的贪心都无法覆盖。

### 3.2 核心观察：把 0 记作 −1，平衡区间就是零和区间

![把 0 记作 −1 后的前缀和与相等前缀](images/wc20_q3_prefix_sum_equal.svg)

**变换**：令

$$a_i = \begin{cases} +1, & \text{nums}[i] = 1 \\ -1, & \text{nums}[i] = 0 \end{cases}, \qquad S_0 = 0,\quad S_{i+1} = S_i + a_i$$

设区间 `nums[i..j-1]` 中 `1` 有 $p$ 个、`0` 有 $q$ 个，则区间内元素之和为 $p - q$，而

$$S_j - S_i = \sum_{k=i}^{j-1} a_k = p - q$$

于是

$$\text{区间平衡} \iff p = q \iff S_j - S_i = 0 \iff S_j = S_i$$

**问题被改写成**：求最长的 $[i, j)$ 使 $S_i = S_j$，即**两个相等前缀和之间的最大下标距离**。

**关键贪心**：固定右端点 $j$ 时，要让 $j - i$ 最大，$i$ 应尽可能小。所以对每个前缀和值 $s$，只需要记它**第一次**出现的前缀下标 `first[s]`；之后每次在第 $j$ 步再次见到 $s$，候选长度就是 $j - \text{first}[s]$，全表取最大值即可。一次线性扫描足够。

### 3.3 算法流程

![算法流程图：初始化、扫描、命中查表、未命中记录](images/wc20_q3_algorithm_flow.svg)

1. 初始化 `s = 0`、`best = 0`、哈希表 `first = {0 : 0}`：前缀和 0 最早出现在**前缀下标 0**（空前缀）。
2. 令前缀下标 `j` 从 `1` 走到 `n`，滚动更新 `s += (nums[j-1] == 1 ? +1 : -1)`，此刻 `s = S_j`。
3. 若 `s` 已在 `first` 中：令 `best = max(best, j - first[s])`，**不覆盖** `first[s]`。
4. 若 `s` 不在 `first` 中：写入 `first[s] = j`，记下该前缀和最早出现的下标。
5. 扫描结束返回 `best`。

> 💡 第 3、4 步的顺序与「是否覆盖」是本题唯一容易写错的地方：**已存在就只更新答案，绝不覆盖**，否则最早的下标被冲掉，长区间会被算短。

### 3.4 示例演算

以示例 3 的 `nums = [0,1,1,1,1,1,0,0,0]` 为例，前缀和为

$$S = [0,\,-1,\,0,\,1,\,2,\,3,\,4,\,3,\,2,\,1]$$

![示例演算：前缀和序列与相等前缀配对](images/wc20_q3_walkthrough.svg)

相等前缀和共三对，分别给出长度 $2, 4, 6$：

| 相等对 | 对应区间 | 长度 |
|--------|----------|------|
| $S_0 = S_2 = 0$ | `nums[0..1]` = `[0,1]` | 2 |
| $S_4 = S_8 = 2$ | `nums[4..7]` = `[1,1,0,0]` | 4 |
| $S_3 = S_9 = 1$ | `nums[3..8]` = `[1,1,1,0,0,0]` | 6 |

扫描过程中的查表细节（`first[s]` 存该前缀和**最早出现的前缀下标**，初值 `first[0] = 0`）：

| $j$ | `nums[j-1]` | $S_j$ | 查表结果 | $j - \text{first}[S_j]$ | `best` |
|-----|-------------|-------|----------|------------------------|--------|
| 1 | 0 | −1 | 未出现，写入 `first[-1]=1` | — | 0 |
| 2 | 1 | 0 | 已出现，`first[0]=0` | 2 | 2 |
| 3 | 1 | 1 | 未出现，写入 `first[1]=3` | — | 2 |
| 4 | 1 | 2 | 未出现，写入 `first[2]=4` | — | 2 |
| 5 | 1 | 3 | 未出现，写入 `first[3]=5` | — | 2 |
| 6 | 1 | 4 | 未出现，写入 `first[4]=6` | — | 2 |
| 7 | 0 | 3 | 已出现，`first[3]=5` | 2 | 2 |
| 8 | 0 | 2 | 已出现，`first[2]=4` | 4 | 4 |
| 9 | 0 | 1 | 已出现，`first[1]=3` | 6 | 6 |

最终 `best = 6`，与答案一致。

## 4. 算法细节

1. **空前缀 `first[0] = 0`**：前缀下标 0 表示「一个元素都没取」。它让「整个前缀 `nums[0..j-1]` 恰好平衡」这种从数组头部开始的区间也能被捕捉到，长度为 $j - 0 = j$。漏掉这一项，所有从下标 0 开始的答案都会少 1。
2. **只插入不覆盖**：`first` 一旦写入就是该前缀和的**最小**下标，后续命中只更新 `best`。这是把 $O(n^2)$ 的「枚举所有相等对」压成 $O(n)$ 的核心，也是证明里引理 2 的内容。
3. **不需要前缀和数组**：答案只依赖「当前 $s$」和「每个值的首次下标」，用滚动变量 `s` 即可，省掉 $O(n)$ 的额外数组（哈希表本身已 $O(n)$）。
4. **哈希表预分配**：C++ 用 `first.reserve(2 * n + 1)` 避免多次 rehash；`s` 的取值只有 $[-n, n]$ 共 $2n+1$ 种，因此也可以直接用「大小为 $2n+1$ 的数组 + 偏移 $n$」替代哈希表，常数更小、严格 $O(n)$ 最坏复杂度。
5. **取值与溢出**：$|s| \le n \le 10^5$，`j`、`best`、`s` 全在 `int` 范围内，无需 `long long`。
6. **Python 的判空**：用 `if s in first`，不要写 `if first.get(s):`——空前缀对应的值 `0` 是合法值但为假值，用真值判断会把「见过」误判成「没见过」。
7. **C++ 避免 `operator[]`**：命中分支里写 `it->second`，不要写 `first[s]`；`operator[]` 在键不存在时会**插入默认值 0**，而 0 恰好是「空前缀」的合法下标，于是凭空多出一个假命中，答案被算大，且错得极隐蔽。

## 5. 正确性证明

**引理 1（前缀和差分刻画平衡）**：对任意 $0 \le i < j \le n$，子数组 `nums[i..j-1]` 中 `0` 与 `1` 数量相等，当且仅当 $S_j = S_i$。

**证明**：设该子数组含 $p$ 个 `1`、$q$ 个 `0`。由 $a_k$ 的定义，$\sum_{k=i}^{j-1} a_k = p - q$；又有 $\sum_{k=i}^{j-1} a_k = S_j - S_i$。故 $S_j = S_i \iff p - q = 0 \iff p = q$，即数量相等。∎

**引理 2（首次下标最优）**：若处理到第 $j$ 步时 `first[s]` 已有值，则它是所有满足 $S_i = s$、$0 \le i \le j$ 的前缀下标 $i$ 中的**最小值**。因而对任意 $0 \le i < j$ 且 $S_i = S_j = s$，都有 $\text{first}[s] \le i$，从而 $j - \text{first}[s] \ge j - i$。

**证明**：算法只在键不存在时写入，写入时刻之前扫描过的前缀下标都与 $s$ 不同，故写入值就是首次出现的最小下标；又因为此后永不覆盖该键，所以它始终保持最小值。于是 $\text{first}[s] \le i$ 对一切同值下标成立，两端同乘 $-1$ 再加 $j$ 即得长度不等式。∎

**引理 3（答案构造正确）**：记 $L = \max\{\,j - i : 0 \le i < j \le n,\ S_i = S_j\,\}$，则算法输出的 `best` 恰为 $L$。

**证明**：

- `best ≤ L`：每次更新都发生在某个 $j$ 命中 `first[s]` 时，此时 $s = S_j$，`first[s]` 是某个 $i' < j$ 且 $S_{i'} = S_j$ 的前缀下标，于是 $j - i'$ 属于上式中的合法长度集合；`best` 初值 0 也不超过 $L$。故 `best ≤ L`。
- `best ≥ L`：取达到 $L$ 的一对 $(i_0, j_0)$，$i_0 < j_0$ 且 $S_{i_0} = S_{j_0}$。扫描到第 $i_0$ 步时或更早，键 $S_{j_0}$ 已写入表中，因此处理第 $j_0$ 步时必然走命中分支，令 `best ≥ j_0 - first[S_{j_0}]`；由引理 2，$\text{first}[S_{j_0}] \le i_0$，故 `best ≥ j_0 - i_0 = L`。

两者合并得 `best = L`。∎

**定理**：算法返回值等于「`0` 与 `1` 数量相等的最长连续子数组」的长度。

**证明**：由引理 1，平衡子数组与「$S_i = S_j$ 的下标对」一一对应，其长度为 $j - i$；由引理 3，算法输出的正是这类长度的最大值。若不存在相等前缀和，则最大值集合为空，`best` 保持初值 0，与题意「不存在时返回 0」一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$ 期望。只扫描一遍数组，共 $n$ 次哈希表查找 + 至多 $n$ 次插入，均摊 $O(1)$；若改用「偏移数组」实现，则为严格 $O(n)$ 最坏。
- **空间**：$O(n)$。前缀和共 $n+1$ 个（下标 $0\ldots n$），哈希表最多存 $n+1$ 个键值对；无其他辅助数组。
- **常数**：每步只有一个加法和一次查表，是本题在 $n = 10^5$ 下最省的做法。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findMaxLength(vector<int>& nums) {
        int n = (int)nums.size();
        unordered_map<int, int> first;
        first.reserve(n * 2 + 1);
        first[0] = 0;                // 空前缀的前缀下标是 0
        int s = 0, best = 0;
        for (int j = 1; j <= n; ++j) {
            s += (nums[j - 1] == 1 ? 1 : -1);
            auto it = first.find(s);
            if (it == first.end()) first[s] = j;      // 只记最早出现的前缀下标
            else best = max(best, j - it->second);
        }
        return best;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findMaxLength(self, nums: List[int]) -> int:
        n = len(nums)
        first = {0: 0}                 # 前缀和 s -> 最早出现的前缀下标
        s = 0
        best = 0
        for j in range(1, n + 1):
            s += 1 if nums[j - 1] == 1 else -1
            if s in first:
                best = max(best, j - first[s])
            else:
                first[s] = j           # 只在首次出现时写入
        return best
```

## 8. 边界情况与易错点

1. **全 `0` 或全 `1`**：前缀和严格单调，永不重复，`best` 保持 0，返回 `0`（不是 $-1$，也不能返回 `n`）。
2. **`n = 1`**：只有一个元素，必定不平衡，返回 `0`；循环体不进命中分支，天然正确。
3. **整个数组平衡**：如 `[0,1]`、`[0,1,0,1]`，答案 $= n$。这要求初始化时就把 `first[0] = 0` 写进表里，漏写则这类答案统一少 1。
4. **漏写「已存在不覆盖」**：写成 `first[s] = i` 无条件覆盖，则示例 3 中 `first[1]` 会被不断刷新到 8，长度退化为 0。
5. **C++ 误用 `operator[]`**：命中判断后仍用 `first[s]` 取值，键不存在时它会被插入为默认值 `0`，即「空前缀的下标」，会把长度算大；必须用 `it->second`。
6. **Python 的假值陷阱**：`if first.get(s):` 在 `first[s] == 0`（空前缀）时判为假，等于把已见过的键当成没见过；一律用 `if s in first:`。
7. **返回值初值**：`best = 0` 是合法下界（题目允许返回 0），不要初始化为 $-1$ 或 `n`。
8. **数组哈希替代哈希表时忘记偏移**：`s` 可能为负，用 `S[s + n]` 这类数组时要加偏移 $n$，否则负下标越界。
