# LeetCode 检测大写字母 题解

## 1. 题目概述

- **标题 / 题号**：检测大写字母（#520，easy）
- **链接**：https://leetcode.cn/problems/detect-capital/
- **来源**：LeetCode 第 20 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定只含大小写英文字母的字符串 `word`，判断它的大写用法是否「正确」。正确只有三种形态：**全部字母大写**（如 `"USA"`）、**全部字母小写**（如 `"leetcode"`）、**只有首字母大写**（如 `"Google"`）。只要不属于这三种形态之一，就返回 `false`。

**约束**：

- $1 \le \lvert \mathrm{word} \rvert \le 100$
- `word` 仅由大写和小写英文字母组成

> 💡 签到题，但值得把「三种形态」压缩成一个判据。本题的全部结构只有两个量：**大写字母的个数** $u$ 与**首字母是否大写**——抓住这两点，代码可以短到一行表达式，且不需要任何额外空间。

## 2. 示例

**示例 1**

```text
输入：word = "USA"
输出：true
解释：三个字母全是大写，命中规则一「全部字母都是大写」。
```

**示例 2**

```text
输入：word = "FlaG"
输出：false
解释：首字母 F 与末字母 G 是大写，中间是小写——既不是全大写、也不是全小写、
      更不是「只有首字母大写」，三种形态都不满足。
```

**示例 3（题面说明中给出的形态示例）**

```text
输入：word = "leetcode"     输出：true     解释：全小写，命中规则二。
输入：word = "Google"       输出：true     解释：仅首字母 G 大写，其余小写，命中规则三。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是把题面三条规则逐条翻译成三次判断：

```text
形态 A ⟺ word.upper() == word
形态 B ⟺ word.lower() == word
形态 C ⟺ word[0] 是大写 且 word[1:] 全为小写
答案  ⟺ A 或 B 或 C
```

复杂度也是 $O(n)$，$n \le 100$ 时当然能过。它的毛病不在速度，而在**工程性**：

1. `upper()` / `lower()` 各造一个长度为 $n$ 的临时串，空间从 $O(1)$ 变成 $O(n)$；
2. 形态 C 对长度 1 的串要特判（`word[1:]` 为空串，`"".islower()` 与 `"".isupper()` 都是 `false`，直接拼条件会翻车）；
3. 三条规则彼此有重叠（$n = 1$ 时 A、B、C 同时成立），判断顺序写错就容易漏掉某条。

赛时用这版保底没问题，但既然只有三种形态，完全可以换一个**只数个数**的视角，把三次扫描压成一次。

### 3.2 核心观察：用大写个数替代形态匹配

![三种合法形态与统一判据](images/wc20_q1_three_patterns.svg)

记 $u$ 为 `word` 中**大写字母的个数**，$n = \lvert \mathrm{word} \rvert$。把三条规则改写成对 $u$ 的刻画：

| 形态 | 原始描述 | 等价刻画 |
|------|----------|----------|
| A | 全部字母大写 | $u = n$ |
| B | 全部字母小写 | $u = 0$ |
| C | 只有首字母大写 | $u = 1$ 且 `word[0]` 是大写 |

三条都只是关于 $u$ 的**计数条件**，唯一的例外是形态 C 额外需要「那唯一的大写字母恰好排在首位」这一位置信息。于是判据可以合成为

$$\text{valid} \iff u = 0 \ \lor\ u = n \ \lor\ \bigl(u = 1 \land \mathrm{isUpper}(\mathrm{word}[0])\bigr)$$

> 💡 关键洞察：$u \ge 2$ 时答案立刻是 `false`。因为此时既不可能全小写（$u \neq 0$），又不可能全大写（$u < n$），更不可能「只有一个大写字母」——多余的第二个大写字母无处安放。

### 3.3 算法流程

![算法流程：一次扫描加两条件判定](images/wc20_q1_algorithm_flow.svg)

```text
1. u = 0，n = len(word)
2. 遍历 word 的每个字符 c：若 c 是大写字母，则 u = u + 1
3. 若 u == 0 或 u == n：返回 true          ← 全小写 / 全大写
4. 若 u == 1 且 word[0] 是大写：返回 true   ← 仅首字母大写
5. 返回 false                              ← 其余一律非法
```

第 3、4 步可以合写成一行表达式（见 §7 参考代码），但保留分支写法更利于理解「先排除两个极端，再处理唯一混合形态」的顺序：$n = 1$ 时形态 A 与 B 重合，先判极端值就能自然接住 `"a"` 与 `"A"`，不会掉进第二层产生歧义。

### 3.4 示例演算

![示例演算：逐词代入判据](images/wc20_q1_example_walkthrough.svg)

| `word` | $n$ | $u$ | 首字母大写 | 命中判据 | 结果 |
|--------|-----|-----|------------|----------|------|
| `"USA"` | 3 | 3 | 是 | $u = n$ → 全大写 | `true` |
| `"leetcode"` | 8 | 0 | 否 | $u = 0$ → 全小写 | `true` |
| `"Google"` | 6 | 1 | 是 | $u = 1$ 且首字母大写 | `true` |
| `"FlaG"` | 4 | 2 | 是 | $0 < u < n$ 且 $u \neq 1$ | `false` |
| `"aBC"` | 3 | 2 | 否 | 首字母小写却含大写 | `false` |
| `"Z"` | 1 | 1 | 是 | $u = 1$ 且首字母大写（同时 $u = n$） | `true` |

第 4、5 行对照着看最有价值：两串的大写个数都是 2，只是$u$ 之外的位置信息不同，结论却都落在 `false` 上——这说明**计数条件一旦被打破，位置信息再也救不回来**。

## 4. 算法细节

1. **只数个数，不记位置**。除了 `word[0]`，其余大写字母排在哪儿与答案完全无关，这正是能把「形态匹配」降维成「计数」的根本原因；也是本题不需要数组、不需要栈、不需要第二个计数器的原因。
2. **判定顺序有讲究**。先判 $u = 0$ 或 $u = n$，再判混合形态。这样 $n = 1$ 的 `"a"` / `"A"` 在第一层就被接住，第二层的 `word[0]` 访问也不会在空串上越界（题面 $n \ge 1$，但顺序正确时即使允许空串也安全）。
3. **字符判定要带类型**。C++ 的 `isupper` 参数必须可表示为 `unsigned char` 或 `EOF`，直接传 `char` 在 `char` 为有符号的平台上是**未定义行为**，规范写法是 `isupper((unsigned char)c)`；Python 则用 `str.isupper()` 对单个字符判断，或直接比较 `'A' <= c <= 'Z'`。
4. **别用两个条件拼出形态 C**。`word[0].isupper() and word[1:].islower()` 对 `"USA"` 返回 `false`（`"SA".islower()` 为假），直接漏掉全大写；而 `word[1:].islower()` 对空串返回 `false`，长度 1 的串又要额外处理。用 $u$ 判据就没有这些坑。
5. **一行写法与分支写法等价**。`u == 0 || u == n || (u == 1 && isupper(word[0]))` 只在 $1 < u < n$ 且 $u \neq 1$ 时短路为 `false`，逻辑与三分支完全一致，只是少一次 `if`。
6. **不要构造新串**。`word.upper()` / `word.lower()` 版本每次都要 $O(n)$ 额外空间；计数版严格 $O(1)$ 空间，是更值得记住的模板。

## 5. 正确性证明

**引理 1**：若 $u = 0$ 或 $u = n$，则 `word` 的大写用法合法。

**证明**：$u = 0$ 表示没有任何大写字母，即全部字母小写，命中规则二；$u = n$ 表示每个字母都是大写，命中规则一。两种情形都合法。∎

**引理 2**：若 $1 \le u \le n - 1$，则 `word` 合法当且仅当 $u = 1$ 且 `word[0]` 是大写字母。

**证明**：

- （$\Rightarrow$）设 `word` 合法。因 $u \ge 1$ 它不是全小写，因 $u \le n-1$ 它不是全大写，故只能是「只有首字母大写」：于是首字母是大写、且它是唯一的大写字母，即 $u = 1$ 且 `word[0]` 是大写。
- （$\Leftarrow$）设 $u = 1$ 且 `word[0]` 是大写。$u = 1$ 说明全串恰有一个大写字母，而 `word[0]` 已是大写，故它就是那一个，其余 $n-1$ 个字母全为小写——正是规则三。∎

**定理**：对任意满足约束的 `word`，算法返回 `true` 当且仅当 `word` 的大写用法正确。

**证明**：$u$ 只能落在两个互斥的范围内，分别讨论。

- $u = 0$ 或 $u = n$：算法第 3 步返回 `true`，由引理 1 该结果正确。
- $1 \le u \le n-1$：算法第 4 步返回布尔值「$u = 1$ 且 `word[0]` 大写」，由引理 2 该布尔值恰好等于合法性；若不满足则第 5 步返回 `false`，同样正确。

两路覆盖全部可能，且每一步都只依赖 $u$ 与 `word[0]` 这两个「扫描可得的量」，故结论成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，每个字符做一次大写判定（$O(1)$），随后两次整数比较与一次首字符判定都是 $O(1)$。
- **空间**：$O(1)$。只维护计数器 $u$ 与长度 $n$，不构造任何临时字符串、不使用数组。
- **对比**：`upper()` / `lower()` 的三形态写法同为 $O(n)$ 时间，但额外占用 $O(n)$ 空间且常数更大；在 $n \le 100$ 下两者都能过，但计数版是更「无状态」的写法。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <cctype>
using namespace std;

class Solution {
public:
    bool detectCapitalUse(string word) {
        int n = word.size(), u = 0;
        for (char c : word)
            if (isupper((unsigned char)c)) u++;      // 数大写字母个数，注意强转避免 UB
        if (u == 0 || u == n) return true;           // 全小写 / 全大写
        return u == 1 && isupper((unsigned char)word[0]);  // 仅首字母大写
    }
};
```

### Python

```python
class Solution:
    def detectCapitalUse(self, word: str) -> bool:
        u = sum(1 for c in word if c.isupper())      # 数大写字母个数
        if u == 0 or u == len(word):
            return True                              # 全小写 / 全大写
        return u == 1 and word[0].isupper()          # 仅首字母大写
```

## 8. 边界情况与易错点

1. **长度 1**：`"a"` 与 `"A"` 都返回 `true`——前者命中 $u = 0$，后者同时命中 $u = n$ 与形态 C，两条路径结论一致，不会冲突。
2. **两个大写但不是全大写**：`"ABc"`、`"aBC"`、`"FlaG"` 都返回 `false`。容易误以为「前几个字母大写」也算合法，实际上大写必须**要么覆盖全部，要么只剩首字母一个**。
3. **首字母大写 ≠ 合法**：`"AbC"` 首字母大写但 $u = 2$，仍然非法。只检查 `word[0].isupper()` 的写法在这里必错。
4. **漏掉「全小写」分支**：`"leetcode"` 是最容易被写错的合法串——只写了「全大写」和「首字母大写」两条规则时它会返回 `false`。
5. **`isupper` 的未定义行为**：C++ 中把 `char`（可能为负）直接传给 `isupper` 是 UB，必须写 `isupper((unsigned char)c)`。
6. **空串的退化情形**：题面保证 $n \ge 1$；若允许空串，$u = 0 = n$ 会返回 `true`，这符合「没有字母就没有违规」的直觉，不会误判。
