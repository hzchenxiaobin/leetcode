# LeetCode 超级洗衣机 题解

## 1. 题目概述

- **标题 / 题号**：超级洗衣机（#517，hard）
- **链接**：https://leetcode.cn/problems/super-washing-machines/
- **来源**：LeetCode 第 20 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组

**题意**：$n$ 台洗衣机排成一排，第 $i$ 台里有 `machines[i]` 件衣服。每一步操作可以任选若干台洗衣机（可以全选），被选中的每一台**同时**把 1 件衣服递给左右相邻的某一台。要求最终每台洗衣机里的衣服数相同，求最少操作步数；做不到则返回 $-1$。

**约束**：

- $1 \le n \le 10^4$
- $0 \le machines[i] \le 10^5$
- 总件数不超过 $10^9$，答案最大可达 $10^9$ 量级，**不可能**枚举步数去模拟

## 2. 示例

**示例 1**

```text
输入：machines = [1,0,5]
输出：3
解释：
第一步: 1  0 <-- 5   =>  1  1  4
第二步: 1 <-- 1 <-- 4 =>  2  1  3
第三步: 2  1 <-- 3   =>  2  2  2
```

**示例 2**

```text
输入：machines = [0,3,0]
输出：2
解释：
第一步: 0 <-- 3  0   =>  1  2  0
第二步: 1  2 --> 0   =>  1  1  1
```

**示例 3**

```text
输入：machines = [0,2,0]
输出：-1
解释：总件数 2 无法被 3 台平分，因此不可能。
```

## 3. 解题思路

### 3.1 暴力思路

状态是长度为 $n$ 的数组，每一步要枚举「每台送不送、往哪边送」，单步就有 $3^n$ 种选择，状态总数随总件数指数增长。即便用双向 BFS 或迭代加深，也只能在小数据上当验算工具（本文的正确性就是用这种方式对拍出来的），绝不能作为正解。

另一种常见的错误贪心是「每一步挑当前离均值最远的一台拼命送」，它在「同一台机器需要同时向两侧送」的情形下会选错方向，无法保证最优。

### 3.2 核心观察：缝隙净流量 + 机器出件率

![每条缝隙的净流量是唯一确定的](images/wc20_q4_boundary_flow.svg)

先在概念上把数轴切开：**缝隙 $i$ 指第 $i$ 台与第 $i+1$ 台之间**（共 $n-1$ 条内部缝隙）。

设 $avg = \dfrac{\sum machines[i]}{n}$、$d_i = machines[i] - avg$，前缀

$$S_i = d_0 + d_1 + \cdots + d_i \qquad (0 \le i \le n-1)$$

$S_i$ 的含义是「左侧 $0..i$ 这段**净多出**多少件」，因此缝隙 $i$ 必须**净**搬运 $|S_i|$ 件，方向由 $S_i$ 的符号决定（$S_i > 0$ 向右搬，$S_i < 0$ 向左搬）。

这个量**被守恒律完全确定**：最终每台都是 $avg$，第 $i$ 台发出的净件数减收到的净件数必须等于 $d_i$，逐项累加就唯一解出缝隙 $i$ 的净流量为 $S_i$，没有任何自由度可以优化。

由此得到两个必然的下界：

1. **缝隙吞吐**：衣服一次只跨 1 条缝隙，所以同一条缝隙上每步净变化至多 1 件 $\Rightarrow$ 至少 $|S_i|$ 步。
2. **机器出件**：每台机器每步最多送出 1 件（哪怕它两侧都缺货）$\Rightarrow$ 盈余 $d_i > 0$ 的机器至少 $d_i$ 步。

$$\text{答案} \;=\; \max\Bigl(\max_i |S_i|,\ \max_i d_i\Bigr)$$

> 💡 **反直觉之处**：很容易以为还要加上「某件衣服要走的距离」。其实衣服是**不可区分**的，源头不必把同一件衣服一路送到终点：沿路每台机器把自己的 1 件往下游递，整条链在**同一步**里一起挪位，接力不消耗额外步数。例如 `[2,1,2,2,2,3]`（$avg=2$）看似要把最右边的 1 件衣服搬 4 格，实际只需 1 步：中间每台都把手里那 1 件向左递一格，同时接收右边递来的一件，一步之后全部变成 2。

### 3.3 算法流程

![一次遍历求前缀净盈余](images/wc20_q4_algorithm_flow.svg)

1. 求总数 `total`（用 64 位整数），若 `total % n != 0` 直接返回 $-1$。
2. 令 `avg = total / n`，`cur = 0`，`ans = 0`。
3. 从左到右遍历，对每台机器累加 `cur += machines[i] - avg`，并用 `ans = max(ans, |cur|, machines[i] - avg)` 更新答案。
4. 遍历结束返回 `ans`。

注意 `cur` 在遍历到第 $i$ 台时恰好等于 $S_i$，最后一个 $S_{n-1}$ 恒为 $0$（总数正好分完），所以循环里不必特判「最后一条缝隙不存在」。

### 3.4 示例演算

![machines = [1,0,5] 的走查表与三步操作](images/wc20_q4_example_walkthrough.svg)

以示例 1 的 `machines = [1,0,5]` 为例，总件数 $6$、$n = 3$，故 $avg = 2$，可以平分。

| $i$ | $machines[i]$ | $d_i = machines[i]-avg$ | $cur = S_i$ | $ans$ |
|-----|---------------|--------------------------|-------------|-------|
| 0 | 1 | $-1$ | $-1$ | 1 |
| 1 | 0 | $-2$ | $-3$ | 3 |
| 2 | 5 | $+3$ | $0$ | 3 |

两个下界同时取到最大值 $3$：缝隙 $1$（第 1、2 台之间）要向左净搬 $3$ 件，第 2 台每步最多送出 $1$ 件、共需送出 $3$ 件。示例给出的三步操作正是这两条约束同时饱和的执行过程，因此 $3$ 就是最优解。

## 4. 算法细节

1. **总件数用 `long long`**：$n \le 10^4$、$machines[i] \le 10^5$，总和最大 $10^9$，恰好卡在 `int` 上界附近，用 64 位更安全。
2. **先判可行性再算均值**：不可行的唯一原因就是 $n \nmid total$，与「某台机器太多」无关。
3. **`cur` 就是前缀净盈余**：遍历到第 $i$ 台时它等于 $S_i$，代表缝隙 $i$ 的净搬运量；它的绝对值直接给出步数下界。
4. **`ans` 同时吸收两类下界**：`abs(cur)` 对应缝隙吞吐，`machines[i] - avg` 对应单机出件；负的 $d_i$ 一并参与 `max` 也不会出错（只可能被更大的正项盖掉）。
5. **`ans` 的最大值量级**：$\max_i |S_i| \le \sum_{d_i>0} d_i \le 10^9$，所以答案用 `int`/`long long` 都放得下，但不要再乘任何系数。
6. **不要真的模拟**：答案可达 $10^9$ 步，模拟必然超时；本题的价值恰恰在于把「模拟」换成「一次前缀扫描」。

## 5. 正确性证明

**引理 1（可行性）**：能够使所有洗衣机相等，当且仅当 $n \mid total$。

**证明**：操作不改变总件数，最终每台都是同一个整数 $x$，故 $total = nx$，即 $n \mid total$，必要性成立。充分性由引理 4 给出的构造保证。∎

**引理 2（缝隙下界）**：设 $N_i$ 为跨缝隙 $i$ 的净件数（向右为正），则任意可行方案中都有 $N_i = S_i$，从而总步数 $T \ge |S_i|$。

**证明**：最终第 $i$ 台的件数满足
$$machines[i] + N_{i-1} - N_i = avg,$$
其中约定 $N_{-1} = N_{n-1} = 0$（两端没有邻居）。把此式改写为 $N_i = N_{i-1} + d_i$，归纳即得 $N_i = d_0 + \cdots + d_i = S_i$，故净流量与方案无关、被唯一确定。又因每一步跨过缝隙 $i$ 的净件数至多为 $1$（只有第 $i$、$i+1$ 台可能跨过它，各自至多递出 1 件），$T$ 步后 $|N_i| \le T$。∎

**引理 3（机器下界）**：若 $d_i > 0$，则任意方案至少需要 $d_i$ 步。

**证明**：第 $i$ 台最终要减少 $d_i$ 件，而每步它最多递出 1 件，因此至少需要 $d_i$ 步。∎

**引理 4（上界可达）**：令 $T = \max\bigl(\max_i |S_i|,\ \max_i d_i\bigr)$，则 $T$ 步内一定能完成。

**证明**：对 $T$ 归纳。$T = 0$ 时所有 $d_i = 0$，已经满足。设 $T \ge 1$。此时必有 $total > 0$（$total = 0$ 时全部为 $0$，$T = 0$），而 $n \mid total$，故 $total \ge n$，即 $avg \ge 1$。注意两个关键事实：

- **(F1)** 一次跨缝隙 $i$ 的转移只改变 $S_i$（它只改变第 $i$ 台的件数，前缀 $0..i$ 之和只变 1），其它 $S_j$ 不变。
- **(F2)** 若 $S_i = T$ 且 $S_{i-1} = -T$，则 $d_i = S_i - S_{i-1} = 2T > T$，与 $T \ge \max_i d_i$ 矛盾。

本步这样安排输送：对每条满足 $S_i = T$ 的缝隙让第 $i$ 台向右递 1 件，对每条满足 $S_i = -T$ 的缝隙让第 $i+1$ 台向左递 1 件；此外，凡 $d_i = T$ 的机器本步必须送出 1 件（它共需送出 $T$ 件，每步至多 1 件，故不能有任何一步空闲）。逐条检查合法性：

1. **每台机器至多递出 1 件**：一台机器同时被两条缝隙支使，只能是「$S_{i-1} = -T$ 向左」与「$S_i = T$ 向右」同时发生，由 (F2) 已排除；而 $d_i = T$ 又被支使时，那一件正好当作它必须送出的那一件。若某台 $d_i = T$ 的机器没被任何缝隙支使，就任选一个不破坏 $|S| \le T-1$ 的方向递出（$S_i \ge -T+2$ 时向右总安全；唯一的例外 $S_i = -T+1$ 只在 $T = 1$ 时出现，此时向左同样安全）。
2. **递出者手里有货**：$S_i = T$ 时其递出方第 $i$ 台满足 $d_i = T - S_{i-1} \ge 0$（因 $S_{i-1} \le T$），故 $machines[i] = avg + d_i \ge 1$；$S_i = -T$ 时递出方第 $i+1$ 台满足 $d_{i+1} = S_{i+1} + T \ge 0$，同理有货；$d_i = T$ 的机器自然有 $avg + T \ge 1$ 件。
3. **$d_i = T$ 的机器本步收不到件**：能向第 $i$ 台递件的只有「$S_{i-1} = T$ 时第 $i-1$ 台向右」与「$S_i = -T$ 时第 $i+1$ 台向左」两种。前者推出 $d_i = S_i - T \le 0$，后者推出 $d_i \le -T < T$，都与 $d_i = T$ 矛盾。于是这些机器本步「出 1 进 0」。
4. **一步之后下界降为 $T-1$**：由 (F1)，$|S_i| = T$ 的缝隙变成 $T-1$，其余缝隙绝对值不变（本就不等于 $T$，故 $\le T-1$）；$d_i = T$ 的机器变成 $T-1$；其余机器里，收件者的 $d \le 0$（同上一条的论证），所以新值至多为 $1$；$T \ge 2$ 时 $1 \le T-1$，而 $T = 1$ 时收件者要么同时递件（$d$ 不变），要么 $d \le -1$（新值 $\le 0 = T-1$）。

于是新数组满足 $\max(\max|S'_i|,\ \max d'_i) \le T-1$，由归纳假设可在 $T-1$ 步内完成，合计 $T$ 步。∎

**定理**：算法返回的 `ans` 就是最少操作步数。

**证明**：设 $T^* = \max(\max_i |S_i|, \max_i d_i)$。引理 2、3 说明任何方案都至少需要 $T^*$ 步；引理 4 说明 $T^*$ 步足够。算法第 3 步恰好遍历了所有 $i$，取到的 `ans` 正是 $T^*$；而不可行时按引理 1 返回 $-1$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。两次线性扫描（一次求和、一次前缀 + 取最大），每个元素做常数次算术与比较。
- **空间**：$O(1)$。只用了 `total`、`avg`、`cur`、`ans` 四个变量，没有额外数组（题面给的数组只读，不计入）。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <cstdlib>
#include <vector>
using namespace std;

class Solution {
public:
    int findMinMoves(vector<int>& machines) {
        int n = (int)machines.size();
        long long total = 0;
        for (int x : machines) total += x;          // 64 位防溢出
        if (total % n != 0) return -1;              // 不能均分
        int avg = (int)(total / n);
        int cur = 0, ans = 0;
        for (int m : machines) {
            int d = m - avg;
            cur += d;                               // cur == S_i
            ans = max(ans, max(abs(cur), d));       // 缝隙下界 + 机器下界
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findMinMoves(self, machines: List[int]) -> int:
        n = len(machines)
        total = sum(machines)
        if total % n:
            return -1
        avg = total // n
        cur = 0      # 当前缝隙左侧的净盈余 S_i
        ans = 0
        for m in machines:
            d = m - avg
            cur += d
            ans = max(ans, abs(cur), d)
        return ans
```

## 8. 边界情况与易错点

1. **总数无法均分**：只能返回 $-1$，此时不要继续算 `avg`（整数除法会截断，得出无意义的答案）。`machines = [0,2,0]` 就是这类。
2. **只取 `max|S_i|` 会漏解**：`machines = [0,3,0]` 的 $|S_i|$ 最大只有 $1$，但中间那台必须送出 $2$ 件，答案 $2$，必须同时取机器下界。
3. **只取 `max d_i` 会漏解**：`machines = [4,4,4,0,0,0]`（$avg = 2$）的 $d$ 最大只有 $2$，但缝隙 $2$ 要向右净搬 $S_2 = 6$ 件，答案 $6$。
4. **误加「距离项」**：认为某件衣服必须真正走完整条路，会把 `[2,1,2,2,2,3]` 算成 $4$，正确答案是 $1$。衣服不可区分，接力不额外耗时。
5. **$n = 1$**：`total % 1 == 0`，`avg = machines[0]`，`d = 0`、`cur = 0`，返回 $0$，无需特判。
6. **全为 $0$**：返回 $0$，不应返回 $-1$（$0$ 能被任何 $n$ 整除）。
7. **总和溢出**：C++ 中 `int total` 在 $n = 10^4$、$machines[i] = 10^5$ 时是 $10^9$，尚未溢出但已贴近边界，习惯上用 `long long`。

**延伸思考**：

- 把队伍改成**环**（首尾也相邻）：缝隙流量多了一个自由变量（可以整体顺时针/逆时针绕一圈），此时要先决定「绕环的净流量」，再在所有切点里取 $\min$，下界的形式会从「前缀最大」变成「环形前缀最大减去常数」，值得自己推一遍。
