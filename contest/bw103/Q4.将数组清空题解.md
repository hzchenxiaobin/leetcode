# LeetCode 将数组清空 题解

## 1. 题目概述

- **标题 / 题号**：将数组清空（#2659，hard）
- **链接**：https://leetcode.cn/problems/make-array-empty/
- **来源**：LeetCode 第 103 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、树状数组、排序

**题意**：数组 `nums` 内元素**互不相同**。反复执行以下操作直到数组为空，每次操作二选一（都计一次操作）：

- 若队首元素是**当前数组的最小值**，删除它；
- 否则，把队首元素移动到数组**末尾**。

返回清空数组所需的总操作次数。

**约束**：

- $1 \le nums.length \le 10^5$
- $-10^9 \le nums[i] \le 10^9$
- 元素互不相同

## 2. 示例

**示例 1**

```text
输入：nums = [3,4,-1]
输出：5
解释：
操作 1 → [4, -1, 3]   （3 不是最小，移到末尾）
操作 2 → [-1, 3, 4]   （4 不是最小，移到末尾）
操作 3 → [3, 4]        （-1 是最小，删除）
操作 4 → [4]            （3 是最小，删除）
操作 5 → []             （4 是最小，删除）
```

**示例 2**

```text
输入：nums = [1,2,4,3]
输出：5
解释：
操作 1 → [2,4,3]  删 1    操作 2 → [4,3]  删 2
操作 3 → [3,4]    4 移末  操作 4 → [4]    删 3
操作 5 → []       删 4
```

**示例 3**

```text
输入：nums = [1,2,3]
输出：3
解释：已升序，每次队首都是最小值，删除 3 次即清空，无任何移动。
```

## 3. 解题思路

### 3.1 暴力思路

用队列直接模拟：每次操作要么 $O(1)$ 出队，要么 $O(1)$ 轮转，但"队首是不是最小值"需要 $O(n)$ 求最小（或维护单调结构）。真正的死穴是**操作次数本身**：逆序输入时操作数约 $\frac{n^2}{2}$，$n = 10^5$ 即约 $5 \times 10^9$ 次操作——逐次模拟连输出都嫌多。出路是**放弃逐次模拟，批量计数**：我们不关心指针每一步踩的是谁，只关心指针为到达每个目标位置扫过了多少个还活着的元素。

### 3.2 核心观察：环 + 队首指针 + 按值序删除

![核心观察：数组首尾相接成环，“移到末尾”= 队首指针顺时针推进一格，元素按值升序被逐个删除](images/bw103_q4_circle_model.svg)

**观察一（删除顺序是值升序）**：元素互不相同。当前数组的最小值就是"尚未被删除的元素中的最小值"——它被删除之前，其他任何元素在队首时都不可能是最小值，只能被移走；而指针至多再转一圈必然轮到它。因此第 $r$ 个被删除的元素**恰是第 $r$ 小的元素**，删除顺序完全确定。

**观察二（循环序永不改变）**："移到末尾"只是把队首接到队尾，元素之间的**环形相对顺序**自始至终不变。把数组首尾相接看成环，再维护一个"队首指针"：整个流程等价于——指针从初始队首位置出发，顺时针逐格推进（已删除的格子视作洞，直接跳过）；若当前所指元素是未删元素的最小值，删除它并计一次操作；否则指针推进一格并计一次操作。

**观察三（每段步数 = 环形弧上的存活数 − 1）**：设上一次删除发生在位置 $p$（此刻 $p$ 已死），下一个目标是位置 $q$（存活）。删除 $p$ 后队首是 $p$ 顺时针的**下一个存活格**，从它走到 $q$ 所需的移动次数，恰为顺时针弧 $(p, q]$ 内**存活元素数减一**（$q$ 自身占一个名额）。第一次删除前用虚拟位置 $0$（位置 $1$ 的前一格）作为 $p$，此时队首就是原数组第一个元素。

于是答案拆成两块：

$$\text{ans} = \underbrace{n}_{\text{删除操作}} + \sum_{r=0}^{n-1} \text{moves}_r, \qquad \text{moves}_r = \big|\text{存活} \cap (\text{prev}_r, \text{cur}_r]\big| - 1$$

其中 $\text{cur}_r$ 是第 $r$ 小元素的位置（1 下标），$\text{prev}_r$ 是上一个被删位置（$\text{prev}_0 = 0$ 虚拟），弧为顺时针方向。逐个删除过程中动态询问"某段弧上有多少存活元素"——正是树状数组的拿手好戏。

### 3.3 算法流程

![算法流程：排序得到删除顺序，BIT 维护存活标记，环形弧计数用前缀差分处理两种方向](images/bw103_q4_bit_arc_query.svg)

```text
1. order = 按 nums 值升序排序后的原下标序列（转为 1 下标位置）
2. BIT 置 1..n 全为 1（存活标记）
3. ans = n，prev = 0        # 虚拟位置 0：数组首位之前
4. for cur in order:
5.     若 cur > prev：cnt = Q(cur) − Q(prev)            # 弧 (prev, cur] 直接前缀差分
6.     若 cur < prev：cnt = (Q(n) − Q(prev)) + Q(cur)   # 跨过环尾：拆成两段
7.     ans += cnt − 1      # 移动次数
8.     BIT 在 cur 处 −1     # 删除该位置
9.     prev = cur
10. 返回 ans
```

`Q(i)` 为 BIT 的前缀和 = 位置 $1..i$ 中存活元素的个数。$\text{cur} = \text{prev}$ 不会发生（位置互异）。

### 3.4 示例演算

![示例演算：数组 3,4,−1 的三段删除，弧计数 3、1、1，移动 2、0、0](images/bw103_q4_example_walkthrough.svg)

以示例 1（$nums = [3,4,-1]$，1 下标位置 $1{:}3,\ 2{:}4,\ 3{:}-1$，删除顺序 $3 \to 1 \to 2$）演算：

| $r$ | 目标值 | prev → cur | 弧上存活数 cnt | moves | 对应官方操作 |
|-----|--------|------------|----------------|-------|--------------|
| 0 | $-1$ | $0 \to 3$ | $Q(3) - Q(0) = 3$ | 2 | 操作 1、2（转两格） |
| 1 | $3$ | $3 \to 1$（跨环尾） | $(Q(3){-}Q(3)) + Q(1) = 0 + 1 = 1$ | 0 | 操作 3（队首即最小，直接删） |
| 2 | $4$ | $1 \to 2$ | $Q(2) - Q(1) = 1$ | 0 | 操作 4、5（连删两轮无需移动） |

$\text{ans} = 3 + (2 + 0 + 0) = 5$ ✓。示例 2（$[1,2,4,3]$）：moves 依次为 $0, 0, 1, 0$，$\text{ans} = 4 + 1 = 5$ ✓；示例 3 全程 moves $= 0$，$\text{ans} = 3$ ✓。

## 4. 算法细节

1. **下标与位置**：BIT 以 1 为起点，把原下标 $i$ 的位置记作 $i+1$；`prev` 初始为虚拟位置 $0$，使第一步的弧 $(0, \text{cur}_0]$ 覆盖 $[1, \text{cur}_0]$，moves $= \text{cur}_0 - 1$ 恰是"最小值前面隔几个元素"。
2. **环形弧的两种情况**：$\text{cur} > \text{prev}$ 时弧 $(\text{prev}, \text{cur}]$ 就是一段区间，$\text{cnt} = Q(\text{cur}) - Q(\text{prev})$；$\text{cur} < \text{prev}$ 时弧跨过环尾，拆成 $(\text{prev}, n]$ 与 $[1, \text{cur}]$ 两段，$\text{cnt} = (Q(n) - Q(\text{prev})) + Q(\text{cur})$。两式都**含 $\text{cur}$ 不含 $\text{prev}$**——$\text{prev}$ 已死，即使含也不影响，但语义上必须含 $\text{cur}$（它是移动的终点站）。
3. **减一的含义**：弧上存活数至少为 $1$（$q$ 本身存活），减一后是"中途跨过的存活元素个数" = 移动次数。首步同样减一，对应"最小值已到队首则不移动"。
4. **BIT 初始化**：$n$ 个单点 $+1$ 逐个 `upd` 是 $O(n \log n)$；也可以 $O(n)$ 直接建树（`tree[i]` 初值取 $\text{lowbit}(i)$），本题量级两者皆可。
5. **溢出（重要）**：逆序输入是最坏情形，$\text{moves}$ 总和约 $\sum_{r} (n - r - 1) \approx \frac{n^2}{2} = 5 \times 10^9$，加上 $n$ 次删除——**远超 `int` 上界**，必须全程 `long long` 累加（接口返回类型就是 `long long`）。单段 `cnt` 用 `int` 足够（$\le n$）。
6. **排序的比较器**：元素互不相同，`nums[a] < nums[b]` 严格弱序即可；比较的是值而非下标，负数参与无碍。
7. **复杂度瓶颈**：排序 $O(n \log n)$ + $n$ 次 BIT 询问/更新 $O(n \log n)$；无需线段树，单点改 + 前缀查是 BIT 的最简形态。

## 5. 正确性证明

**引理 1（删除顺序 = 值升序）**：第 $r$ 次被删除的元素是全体元素中第 $r$ 小的。

**证明**：对 $r$ 归纳。$r = 0$：删除发生前，任何队首元素 $x$ 若不是全局最小值 $m_0$，规则只允许将其移到末尾；有限次操作后 $m_0$ 必然轮转到队首（队列长度有限，每次移动使队首沿环前进一步，至多 $n-1$ 步内到达），此时 $m_0$ 是当前最小值、被删除。归纳设第 $r$ 次删除的是第 $r$ 小的 $m_r$；此后"当前数组"恰为剩余 $n - r$ 个元素，最小值即第 $r+1$ 小的 $m_{r+1}$，与 $r=0$ 情形同理，下一个被删除的就是它 ∎

**引理 2（环形指针模型）**：把原下标 $0..n-1$ 视作环上顺时针排列的位置，"移到末尾"不改变任意两元素的环形相对顺序；整个流程等价于——队首指针初始指向位置 $1$（原下标 $0$），每次操作指针顺时针推进到下一个**存活**位置并计一次操作；推进后若所指元素是未删元素的最小值，则额外完成删除（该次操作计为删除）。

**证明**：队列在任意时刻的内容，等于环上从队首位置起顺时针读出的存活元素序列。"把队首移到末尾"后，新序列 = 原序列去掉首元素接到尾 = 同一环形顺序从下一存活位置读起，故指针推进一格即完成该操作，环形序不变。删除操作不移动任何元素，只使一格变洞，指针推进到其下一存活格（即删除后的新队首）。两种操作都与模型逐一对应对 ∎

**引理 3（步数公式）**：设某次删除后指针停在位置 $p$（该位置已死，新队首为 $p$ 顺时针的下一存活格），下一目标（下一个被删元素）位于存活位置 $q$，此刻存活集为 $S$（$q \in S$）。则把 $q$ 送至队首所需的移动次数为 $\big|S \cap (p, q]\big| - 1$，其中 $(p, q]$ 为顺时针弧。首次删除前取虚拟 $p = 0$（此时队首为位置 $1$，全位置存活），公式同样成立。

**证明**：删除后队首 $g$ 是弧 $(p, q]$ 内的第一个存活元素（$p$ 已死）。每次移动使队首沿弧前进一步，即依序经过 $S \cap (p, q]$ 中的存活元素，到达 $q$ 时恰经过其中全部 $|S \cap (p, q]|$ 个位置，故移动次数为该数减一。$q \in S$ 保证计数 $\ge 1$、步数 $\ge 0$。首步时队首为位置 $1 \in (0, q]$，同一推导逐字成立 ∎

**定理**：$\text{ans} = n + \sum_{r=0}^{n-1}\big(|S_r \cap (\text{prev}_r, \text{cur}_r]| - 1\big)$，其中 $S_r$ 是第 $r$ 次删除前一刻的存活位置集，$\text{prev}_r = \text{cur}_{r-1}$（$\text{prev}_0 = 0$），$\text{cur}_r$ 为第 $r$ 小元素的位置。算法逐项计算该式并返回正确答案。

**证明**：由引理 1，删除恰发生 $n$ 次、且第 $r$ 次删的即第 $r$ 小元素，其位置为 $\text{cur}_r$；由引理 2，除删除外的一切操作都对应指针顺时针推进且逐次计数；由引理 3，第 $r$ 段（从上一次删除到本次删除）的移动次数恰为 $|S_r \cap (\text{prev}_r, \text{cur}_r]| - 1$。各段互不重叠地覆盖了全部移动操作，加上 $n$ 次删除即总操作数。算法中 BIT 维护的正是 $S_r$（处理 $\text{cur}_r$ 前只撤销了 $\text{cur}_0..\text{cur}_{r-1}$），两条前缀差分公式分别精确计算顺时针弧 $(\text{prev}_r, \text{cur}_r]$ 的存活数（位置互异保证不会出现 $\text{cur}_r = \text{prev}_r$），故求和正确 ∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序一次；随后每个元素一次 BIT 询问（$O(\log n)$）加一次单点更新（$O(\log n)$）。$n = 10^5$ 时约 $2 \times 10^6$ 次 BIT 节点访问，C++ 实测几十毫秒。
- **空间**：$O(n)$。排序下标数组 $O(n)$、BIT 数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
   public:
    long long countOperationsToEmptyArray(vector<int>& nums) {
        int n = nums.size();
        vector<int> order(n);                       // 按值从小到大排序的下标
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(),
             [&](int a, int b) { return nums[a] < nums[b]; });

        tree.assign(n + 1, 0);                      // BIT：位置 1..n，1 = 还活着
        for (int i = 1; i <= n; ++i) upd(i, 1);

        long long ans = n;                           // 删除操作恰有 n 次
        int prev = 0;                                // 虚拟位置 0（首位之前）
        for (int idx : order) {
            int cur = idx + 1;                       // 换成 1 下标
            long long alive;                         // 顺时针弧 (prev, cur] 的存活数
            if (cur > prev)
                alive = qry(cur) - qry(prev);
            else
                alive = (long long)qry(n) - qry(prev) + qry(cur);
            ans += alive - 1;                        // 需要的“移到末尾”次数
            upd(cur, -1);                           // 删除该位置
            prev = cur;
        }
        return ans;
    }

   private:
    vector<int> tree;
    void upd(int i, int d) {
        for (; i < (int)tree.size(); i += i & (-i)) tree[i] += d;
    }
    int qry(int i) {
        int s = 0;
        for (; i > 0; i -= i & (-i)) s += tree[i];
        return s;
    }
};
```

### Python

```python
class Solution:
    def countOperationsToEmptyArray(self, nums: List[int]) -> int:
        n = len(nums)
        order = sorted(range(n), key=lambda i: nums[i])  # 按值从小到大
        tree = [0] * (n + 1)                             # BIT：1 = 还活着

        def upd(i: int, d: int) -> None:
            while i <= n:
                tree[i] += d
                i += i & -i

        def qry(i: int) -> int:
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & -i
            return s

        for i in range(1, n + 1):
            upd(i, 1)

        ans = n                                          # 删除操作恰有 n 次
        prev = 0                                         # 虚拟位置 0
        for idx in order:
            cur = idx + 1
            if cur > prev:
                alive = qry(cur) - qry(prev)
            else:
                alive = qry(n) - qry(prev) + qry(cur)
            ans += alive - 1
            upd(cur, -1)
            prev = cur
        return ans
```

## 8. 边界情况与易错点

1. **答案必须 `long long`**：逆序输入的操作数约 $\frac{n^2}{2} + n \approx 5 \times 10^9$，超 `int` 上界两倍多；任何一处用 `int` 累加都会溢出。接口返回 `long long`，正好。
2. **已升序输入**：每段 moves $= 0$，$\text{ans} = n$——用它快速自检（示例 3）。
3. **`prev` 的虚拟初值 0**：它使第一步弧为 $(0, \text{cur}_0]$，若误把 `prev` 初始化为 $1$ 又未对齐语义，首段会少算一段 $[1, \text{cur}_0)$。
4. **环形弧的方向**：$(\text{prev}, \text{cur}]$ 是**顺时针**（下标增大、越过 $n$ 回到 $1$），写成 $[\text{prev}, \text{cur})$ 或逆时针都会错；wrap 分支记得**两段都要含 $\text{cur}$**。
5. **负值元素**：只参与排序比较，BIT 位置由原下标决定，负数无需特殊处理。
6. **元素互不相同是前提**：删除顺序由值唯一确定。若允许重复，需按"值为主、下标为辅"消歧（重复值谁先到队首先删谁），模型仍可推广但要小心。
7. **BIT 下标从 1 开始**：位置 $0$ 是虚拟哨兵，数组开 $n+1$，`qry(0) = 0` 天然成立。
8. **`cur = prev` 不会发生但别依赖**：位置互异保证分支安全；若写 `if (cur >= prev)` 把相等并进直查分支，恰好也正确，但注释里应说明原因。
