# LeetCode K 个元素的最大和 题解

## 1. 题目概述

- **标题 / 题号**：K 个元素的最大和（#2656，easy）
- **链接**：https://leetcode.cn/problems/maximum-sum-with-exactly-k-elements/
- **来源**：LeetCode 第 103 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、数组

**题意**：给定数组 `nums` 与整数 $k$，执行**恰好 $k$ 次**操作，每次操作为：从 `nums` 中选一个元素 $m$ 并删除，再放回一个新元素 $m+1$，同时得分增加 $m$。求 $k$ 次操作后的最大总得分。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$
- $1 \le k \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,5], k = 3
输出：18
解释：第一次选 5，得 5 分，nums = [1,2,3,4,6]；
      第二次选 6，得 6 分，nums = [1,2,3,4,7]；
      第三次选 7，得 7 分。总分 5 + 6 + 7 = 18。
```

**示例 2**

```text
输入：nums = [5,5,5], k = 2
输出：11
解释：第一次选 5，第二次只能接着选变出来的 6，总分 11。
```

**示例 3（边界补充）**

```text
输入：nums = [2,2], k = 3
输出：9
解释：最大值 m = 2，得分序列 2 + 3 + 4 = 9 = 2×3 + 3×2/2。
      最大值有重复也不影响：删掉一个 2 放回 3，数组仍有另一个 2，
      但每步的最优选择永远是当前最大的那个。
```

## 3. 解题思路

### 3.1 暴力思路

每一步可以从当前数组里任选一个元素，$n$ 种选择、共 $k$ 步，直接搜索是 $O(n^k)$（$100^{100}$），完全不可行。退一步想"逐步模拟"：每步似乎都该选当前最大值——模拟 $k$ 步、每步取 `max`，是 $O(nk)$ 的做法，能过但没必要。真正该做的是发现**得分序列的规律**，把 $k$ 步直接写成公式。

### 3.2 核心观察：反复选最大，得分是一条公差为 1 的等差数列

![核心观察：每步选最大值 m，得分 m，放回 m+1，形成 m→m+1→…→m+k−1 的递增链](images/bw103_q1_greedy_chain.svg)

设 $M = \max(nums)$。贪心策略：**每次都选当前数组中的最大值**。第一次得分 $M$，放回 $M+1$；此时 $M+1$ 必是新的最大值，第二次得分 $M+1$，放回 $M+2$……得分依次为

$$M,\; M+1,\; M+2,\; \dots,\; M+k-1$$

是一条首项 $M$、公差 $1$、共 $k$ 项的等差数列。为什么这样是最优的？关键不变量是：**每次操作让数组元素总和恰好增加 $1$**（删掉 $m$ 放回 $m+1$），因此任何时刻任何元素的值都不会超过 $M + (\text{已操作次数})$——第 $t$ 步（从 $0$ 数起）的得分被硬性封顶在 $M + t$。贪心恰好逐步贴住这条上界，所以总得分

$$\text{ans} = \sum_{t=0}^{k-1} (M + t) = M \cdot k + \frac{k(k-1)}{2}$$

一步到位，连模拟都不需要。

### 3.3 算法流程

```text
1. 扫描 nums 求最大值 M
2. ans = M*k + k*(k-1)/2
3. 返回 ans
```

### 3.4 示例演算

![示例演算：每个位置得分的上界 M+t 与贪心实际得分重合，等差数列求和](images/bw103_q1_upper_bound.svg)

**示例 1**（$M = 5$，$k = 3$）：得分上界依次为 $5, 6, 7$，贪心全部取到，总分 $5+6+7 = 18 = 5 \times 3 + \frac{3 \times 2}{2}$。

**示例 2**（$M = 5$，$k = 2$）：得分 $5 + 6 = 11 = 5 \times 2 + \frac{2 \times 1}{2}$。

| 步 $t$ | 得分上界 $M+t$ | 贪心实际得分 |
|--------|----------------|--------------|
| 0 | 5 | 5（选 5，放回 6） |
| 1 | 6 | 6（选 6，放回 7） |
| 2 | 7 | 7（选 7，放回 8） |

## 4. 算法细节

1. **公式即答案**：不需要真的执行 $k$ 次操作，$O(1)$ 公式替代 $O(nk)$ 模拟。
2. **只需求一次 max**：`max_element` 单趟扫描；排序是浪费（$O(n \log n)$ 且无必要）。
3. **重复最大值无影响**：删掉一个 $M$ 放回 $M+1$ 后，数组里即使还有别的 $M$，也不影响"当前最大值是 $M+1$"，贪心链不中断。
4. **"恰好 $k$ 次"的语义**：即使数组里的值"很大"也必须做满 $k$ 次——贪心链单调递增，多做只会多赚，与题意天然一致。
5. **数值范围**：$M \le 100$、$k \le 100$，答案上界 $100 \times 100 + 4950 = 14950$，`int` 绰绰有余。

## 5. 正确性证明

**引理 1（单步得分上界）**：设 $M = \max(nums)$，执行了 $t$ 次操作后，数组中任意元素的值不超过 $M + t$；从而第 $t+1$ 次操作（0 数起为第 $t$ 步）的得分至多为 $M + t$。

**证明**：对 $t$ 归纳。$t = 0$ 时数组未变，所有元素 $\le M$ ✓。设 $t$ 次操作后结论成立，即全体元素 $\le M + t$。第 $t+1$ 次操作删除某元素 $m \le M + t$ 并放回 $m + 1 \le M + t + 1$，其余元素不变仍 $\le M + t < M + t + 1$，故结论对 $t+1$ 成立 ∎

**引理 2（贪心达成上界）**：每步选当前最大值的策略，第 $t$ 步（$0 \le t \le k-1$）的得分恰为 $M + t$。

**证明**：对 $t$ 归纳。第 $0$ 步当前最大值为 $M$（存在元素等于 $M$），得分 $M$，放回 $M+1$。归纳设第 $t$ 步得分 $M + t$ 且放回了 $M + t + 1$。由引理 1，此刻全体元素 $\le M + t + 1$，而放回的元素恰为 $M + t + 1$，故第 $t+1$ 步的当前最大值为 $M + t + 1$，得分 $M + t + 1$，放回 $M + t + 2$。归纳完成 ∎

**定理**：最大总得分为 $M \cdot k + \frac{k(k-1)}{2}$。

**证明**：任何策略第 $t$ 步得分 $\le M + t$（引理 1），故总得分 $\le \sum_{t=0}^{k-1}(M+t) = Mk + \frac{k(k-1)}{2}$；贪心策略逐步取等（引理 2），达到该上界，故为最优 ∎

## 6. 复杂度分析

- **时间**：$O(n)$，一次扫描求最大值，其余为 $O(1)$ 公式计算。
- **空间**：$O(1)$，只用常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximizeSum(vector<int>& nums, int k) {
        int m = *max_element(nums.begin(), nums.end());
        return m * k + k * (k - 1) / 2;
    }
};
```

### Python

```python
class Solution:
    def maximizeSum(self, nums: List[int], k: int) -> int:
        return max(nums) * k + k * (k - 1) // 2
```

> 💡 两份代码均通过官方示例（`18`、`11`）与边界 `nums=[2,2], k=3`（`9`），并与「穷举每步全部选法」的暴力程序对拍 3005 组随机小数据，`mismatch = 0`。

## 8. 边界情况与易错点

1. **恰好 $k$ 次不能少做**：题目要求恰好 $k$ 次，不存在"提前停手"的问题，但写模拟版时要保证循环恰好 $k$ 轮。
2. **$n = 1$**：唯一元素反复被选中，得分仍是 $m, m+1, \dots$，公式不变。
3. **重复最大值**：如 $[5,5,5]$，贪心不会"卡住"——放回的 $M+1$ 始终严格大于其余重复的 $M$。
4. **别把公式写成 $M \cdot k + \frac{k(k+1)}{2}$**：得分是 $M, M+1, \dots, M+k-1$，求和是 $\frac{(M + M+k-1) \cdot k}{2}$，$k$ 项公差 $1$ 的和里多出的部分是 $\frac{k(k-1)}{2}$。写成 $\frac{k(k+1)}{2}$ 会多加 $k$。
5. **不需要排序**：只要最大值；用排序找 max 是把签到题写复杂了。
