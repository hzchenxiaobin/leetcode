# LeetCode 数位成本和为目标值的最大数字 题解

## 1. 题目概述

- **标题 / 题号**：数位成本和为目标值的最大数字（#1449，hard）
- **链接**：https://leetcode.cn/problems/form-largest-integer-with-digits-that-add-up-to-target/
- **来源**：LeetCode 第 26 场双周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、背包问题、完全背包

**题意**：给定数组 `cost`（长度 9）与整数 `target`。往结果里**添加一个数位 $i+1$ 的成本为 `cost[i]`**（下标从 0 开始）；数位可重复添加；**总成本必须恰好等于 `target`**；数位中不能有 0。在所有满足要求的整数中返回**最大**的；无解返回 `"0"`。答案可能很大，以字符串返回。

**约束**：

- $cost.length = 9$
- $1 \le cost[i] \le 5000$
- $1 \le target \le 5000$

## 2. 示例

**示例 1**

```text
输入：cost = [4,3,2,5,6,7,2,5,5], target = 9
输出："7772"
解释：数位 7 成本 2、数位 2 成本 3，"7772" 总成本 2×3 + 3 = 9；
"977"（5+2+2=9）也满足，但 "7772" 是更大的数（位数更多）。
```

**示例 2**

```text
输入：cost = [7,6,5,5,5,6,8,7,8], target = 12
输出："85"
解释：8 的成本 7、5 的成本 5，7 + 5 = 12。
```

**示例 3**

```text
输入：cost = [2,4,6,2,4,6,4,4,4], target = 5
输出："0"
解释：无法用任何数位组合恰好凑出成本 5。
```

**示例 4**

```text
输入：cost = [6,10,15,40,40,40,40,40,40], target = 47
输出："32211"
解释：15 + 10 + 10 + 6 + 6 = 47，共 5 个数位，是可行方案中位数最多、再字典序最大的。
```

## 3. 解题思路

### 3.1 暴力思路

把"每种数位用多少个"看成一个 9 维向量 $(c_1, \dots, c_9)$，满足 $\sum i\text{-cost} \times c_i = target$。穷举所有向量、每个向量按降序排列成最大数字、再比较取最大——向量总数随 `target` 指数增长（如全 1 成本时等价于 9 重合取整数的拆分数），不可行。但这个暴力在本题是**理想的对拍基准**（见 §7）。

### 3.2 核心观察：先比位数、再比字典序 —— 两阶段贪心

![完全背包模型：数位是物品，成本是体积，1 是价值](images/bw26_q4_knapsack_model.svg)

不含 0 的两个正整数比大小：**位数多者恒大**；位数相同时按**字典序**从高位比较。于是目标分两阶段：

1. **最大位数**：数位 $d$ 是"体积为 $cost[d-1]$、价值为 1"的**无限物品**，求装满容量 `target` 的**完全背包**最大价值。设

$$f[t] = \text{总成本恰为 } t \text{ 时最多能写的位数（} -1 \text{ 表示凑不出）}$$

转移：$f[t] = \max_{d:\ cost[d-1] \le t,\ f[t-cost[d-1]] \ge 0} f[t - cost[d-1]] + 1$，$f[0] = 0$。

2. **字典序最大**：在"每步都能保住剩余最优位数"的前提下，**从高位到低位每步贪心选最大的可行数位**：当前位置剩余成本 $t$、还需写 $L$ 位，选最大的 $d$ 满足 $f[t - cost[d-1]] = L - 1$。

两个阶段复用**同一张 $f$ 表**，无需存转移路径。

### 3.3 算法流程

![贪心重建流程：每步选能保住位数的最大数位](images/bw26_q4_reconstruct_flow.svg)

```text
1. f[0] = 0；对 t = 1..target：
       f[t] = max(f[t - cost[d-1]] + 1) over d=1..9 且 f[t - cost[d-1]] ≥ 0
       （全都不行则 f[t] = -1）
2. 若 f[target] < 0：返回 "0"
3. t = target，L = f[target]，ans = ""
4. 当 L > 0：
       对 d 从 9 到 1（优先大数位）：
           若 cost[d-1] ≤ t 且 f[t - cost[d-1]] == L - 1：
               ans += d；t -= cost[d-1]；L -= 1；跳出
5. 返回 ans
```

### 3.4 示例演算

![示例演算：target=9 的 f 表与重建过程](images/bw26_q4_example_walkthrough.svg)

以示例 1（`cost = [4,3,2,5,6,7,2,5,5]`，`target = 9`）为例，$f$ 表（只列关键项）：

| $t$ | 可行转移 | $f[t]$ |
|-----|---------|--------|
| 0 | — | 0 |
| 2 | $d=3,7$（成本 2） | 1 |
| 3 | $d=2$（成本 3） | 1 |
| 4 | $d=3,7$ 两位 | 2 |
| 5 | $d=2,3$ / $d=3,7$ | 2 |
| 7 | $3+2+2$ 三位 | 3 |
| 9 | $2+2+2+3$ 四位 | **4** |

重建：$t=9, L=4$。试 $d=9$（成本 5）：$f[4]=2 \ne 3$ ✗；$d=8$ ✗；$d=7$（成本 2）：$f[7]=3 = L-1$ ✓ → 写 7；$t=7, L=3$：$d=7$：$f[5]=2$ ✓ → 写 7；$t=5, L=2$：$d=7$：$f[3]=1$ ✓ → 写 7；$t=3, L=1$：$d=9,8$ 成本超，$d=7$：$f[1]=-1$ ✗；$d=6,5,4$ 成本超；$d=3$（成本 2）：$f[1]=-1$ ✗；$d=2$（成本 3）：$f[0]=0 = L-1$ ✓ → 写 2。得 `"7772"` ✓。

## 4. 算法细节

1. **$f$ 的语义是"恰好"而非"不超过"**：不可行必须显式记 $-1$，初值也是 $-1$（只有 $f[0]=0$），与"至少装多少位"的背包区别开——后者会允许成本花不满，违反"恰好等于 target"。
2. **不可行判据**：$f[target] < 0$ 返回 `"0"`；注意 `"0"` 是字符串不是数字 0。
3. **重建时从 9 往 1 试**：高位优先取最大数位；条件 `f[t - cost] == L - 1` 一步把"成本可行"与"保位数最优"合并判断。
4. **答案长度上界**：位数最多 $target$（全 1 成本），最长 5000 个字符，必须**字符串拼接**，任何数值类型都会溢出（这正是题目让返回字符串的原因）。
5. **数位与成本的下标换算**：数位 $d$ 对应 `cost[d - 1]`（成本数组 0 起、数位 1 起），重建循环 `d` 从 9 到 1，两处下标别写反。
6. **同成本不同数位**：如示例 1 中 3 与 7 成本都是 2，背包阶段取谁都行（只关心位数），重建阶段靠"从大到小试"自动偏好 7。
7. **无需滚动优化**：$f$ 本身就是一维的（完全背包空间优化形态），时间 $O(9 \cdot target)$、空间 $O(target)$。

## 5. 正确性证明

**引理 1（数字比较的字典序刻画）**：设 $X, Y$ 都是不含 0 的正整数的十进制表示（无前导零）。若 $|X| > |Y|$ 则 $X > Y$；若 $|X| = |Y|$ 则 $X > Y$ 当且仅当 $X$ 字典序大于 $Y$。

**证明**：不含 0 的 $L$ 位正整数取值范围是 $[\underbrace{1\cdots1}_{L},\ \underbrace{9\cdots9}_{L}]$，位数为 $L$ 的最小值 $11\cdots1 >$ 位数为 $L-1$ 的最大值 $99\cdots9$（因为 $11 \cdots 1 = (10^L - 1)/9 > 10^{L-1} - 1$，后者是 $L-1$ 位最大数）。故位数多者数值大。位数相同时，两数逐位相减等价于字符串逐字符比较，即字典序。∎

**引理 2（$f$ 表的最优性）**：$f[t] \ge 0$ 当且仅当存在多重集 $M$（元素为 $1..9$ 的数位）使 $\sum_{d \in M} cost[d-1] = t$；且 $f[t]$ 等于一切这样的 $M$ 的**最大元素个数**。

**证明**：归纳于 $t$。$t = 0$：空集，$f[0] = 0$ ✓。设对一切 $< t$ 成立。若 $M$ 是成本为 $t$ 的可行多重集，取其中任一数位 $d$，则 $M' = M \setminus \{d\}$ 成本为 $t - cost[d-1] \ge 0$ 且 $f[t - cost[d-1]] \ge |M'| = |M| - 1$（归纳），故转移允许 $f[t] \ge |M|$；反之 $f[t]$ 的每个转移值 $f[t - cost[d-1]] + 1$ 对应"在成本 $t - cost$ 的最优集上添一个 $d$"，是一个可行 $M$ 的元素个数。因此 $f[t]$ 恰是全部可行集大小的最大值，且 $f[t] = -1$ 当且仅当无任何可行集。∎

**引理 3（贪心重建的可行性）**：设 $f[t] = L \ge 1$，则存在数位 $d^\*$ 使 $cost[d^\*-1] \le t$ 且 $f[t - cost[d^\*-1]] = L - 1$；且对一切满足该条件的 $d$，从 $d$ 继续可以重建出成本恰为 $t$、位数恰为 $L$ 的数字。

**证明**：由引理 2，取成本 $t$、大小 $L$ 的最优多重集 $M$，任取 $d \in M$，$M \setminus \{d\}$ 成本 $t - cost[d-1]$、大小 $L - 1$，由引理 2 的"当且仅当"方向，该成本处存在大小至少 $L-1$ 的可行集；又由引理 2 的最大性 $f[t - cost[d-1]] \le f[t] - 1 = L - 1$（若 $> L-1$ 则 $M \cup \{d\}$ 非最优，矛盾于 $f[t] = L$）。故 $f[t - cost[d-1]] = L - 1$，条件成立者非空且逐位可用，归纳可完成整个重建。∎

**定理**：算法返回的字符串在所有"成本恰为 target"的合法整数中最大。

**证明**：设最优位数为 $L^\* = f[target]$（若 $-1$ 则无解，返回 `"0"` 正确）。算法产出串 $A$ 与任一合法串 $B$ 比较：由引理 2，$|B| \le L^* = |A|$。若 $|B| < |A|$，由引理 1，$A > B$。若 $|B| = |A| = L^*$，归纳证明 $A \ge B$：首位上，$A$ 选了使 $f[t - cost] = L^* - 1$ 的**最大**数位 $d_A$；$B$ 的首位 $d_B$ 也必须满足 $f[target - cost[d_B-1]] \ge L^* - 1$（$B$ 的剩余部分是成本 $target - cost[d_B-1]$、大小 $L^* - 1$ 的可行集，由引理 2 上界即得 $=$，故 $d_B$ 满足同样的条件），由选取规则 $d_A \ge d_B$。若 $d_A > d_B$，$A > B$ 成立；若 $d_A = d_B$，则 $A$ 与 $B$ 首位相同、剩余子问题同形（剩余成本、剩余位数均相同），对 $L^* - 1$ 归纳。归纳终点（0 位）两串相等。故 $A \ge B$ 对一切合法 $B$ 成立，$A$ 最大。∎

## 6. 复杂度分析

- **时间**：$O(9 \cdot target + 9 \cdot L)$。DP 一张 $f$ 表 $O(9 \cdot target)$；重建每步至多试 9 个数位、共 $L \le target$ 步，$O(9L)$。总计 $O(target)$ 级别，`target = 5000` 毫秒级。
- **空间**：$O(target)$。$f$ 数组 + 输出字符串（长度 $\le target$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string largestNumber(vector<int>& cost, int target) {
        // f[t]：总成本恰好为 t 时最多能写多少个数位；-1 表示凑不出
        vector<int> f(target + 1, -1);
        f[0] = 0;
        for (int t = 1; t <= target; ++t)
            for (int c : cost)
                if (c <= t && f[t - c] >= 0)
                    f[t] = max(f[t], f[t - c] + 1);
        if (f[target] < 0) return "0";
        // 从高位到低位：在保持位数最优的前提下，每一步贪心选最大的可行数位
        string ans;
        int t = target, len = f[target];
        while (len > 0) {
            for (int d = 9; d >= 1; --d) {
                int c = cost[d - 1];
                if (c <= t && f[t - c] == len - 1) {
                    ans.push_back('0' + d);
                    t -= c;
                    --len;
                    break;
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def largestNumber(self, cost: list[int], target: int) -> str:
        # f[t]：总成本恰好为 t 时最多能写多少个数位；-1 表示凑不出
        f = [-1] * (target + 1)
        f[0] = 0
        for t in range(1, target + 1):
            best = -1
            for c in cost:
                if c <= t and f[t - c] >= 0:
                    best = max(best, f[t - c] + 1)
            f[t] = best
        if f[target] < 0:
            return "0"
        # 从高位到低位：在保持位数最优的前提下，每一步贪心选最大的可行数位
        ans = []
        t, length = target, f[target]
        while length > 0:
            for d in range(9, 0, -1):           # 数位 d 的成本是 cost[d-1]
                c = cost[d - 1]
                if c <= t and f[t - c] == length - 1:
                    ans.append(str(d))
                    t -= c
                    length -= 1
                    break
        return "".join(ans)
```

> 💡 两份代码均通过全部 4 个官方示例；并与「穷举 9 维多重集、逐集降序排列取 (位数, 字典序) 最大」的独立暴力在 6 个特值 + 2500 组随机（$target \le 14$）上对拍 `mismatch = 0`；另做大规模互拍与断言：C++ 与 Python 在 120 组 $target \le 5000$ 随机上输出一致，且答案总成本恰为 target、数位降序排列。

## 8. 边界情况与易错点

1. **`"0"` 的语义**：无解返回字符串 `"0"`，不是空串、不是数字 0；$f[target] < 0$ 的判据别写成 `== 0`。
2. **恰好 vs 不超过**：$f$ 必须是"恰好装满"语义（不可行 $= -1$）。混用"不超过"会把成本花不满的方案也算进来，示例 2（`target=12`）就会答错。
3. **直接 DP 字符串会超时**：$dp[t]$ 存字符串、每次转移做字符串比较拼接，最坏 $O(target^2 \cdot 9)$ 字符操作（约 $10^8$），Python 必超时；先位数后重建是标准替代。
4. **重建条件缺一不可**：`c <= t`（成本够）与 `f[t-c] == len-1`（保位数）都要检查；只查后者可能数组越界（$t - c < 0$）。
5. **下标换算**：数位 $d \to cost[d-1]$；重建循环写 `d--` 时小心从 9 到 1（不是 8）。
6. **全 1 成本的极端规模**：`target = 5000` 时答案为 5000 个 `'9'`，5 KB 字符串——确保用 `push_back`/`append` 增量拼接而不是反复复制整个串（Python 的 `"".join` 与列表 append 天然安全）。
7. **同成本数位的偏好**：成本相同的两个数位（如示例 1 的 3 与 7）在 DP 阶段等价，重建阶段必须靠"从 9 往 1 试"选大者——若从小往大试会把 `"7772"` 写成 `"3332"`。
