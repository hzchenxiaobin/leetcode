# LeetCode 有效数字整数 题解

## 1. 题目概述

- **标题 / 题号**：有效数字整数（#3908，easy）
- **链接**：https://leetcode.cn/problems/valid-digit-number/
- **来源**：LeetCode 第 181 场双周赛 Q1
- **难度**：简单
- **标签**：数学、字符串

**题意**：给定整数 $n$ 与一个数字 $x$（$0 \le x \le 9$）。称 $n$ 是**有效**的，当且仅当下面两条同时成立：

1. $n$ 的十进制表示中**至少出现一次**数字 $x$；
2. $n$ 的十进制表示**不以**数字 $x$ 开头。

返回 $n$ 是否有效。

**约束**：

- $0 \le n \le 10^5$
- $0 \le x \le 9$

## 2. 示例

**示例 1**

```text
输入：n = 101, x = 0
输出：true
解释：下标 1 处出现数字 0；首位是 1，不是 0。两条都满足。
```

**示例 2**

```text
输入：n = 232, x = 2
输出：false
解释：虽然 2 出现了两次，但首位就是 2，违反条件 2。
```

**示例 3**

```text
输入：n = 5, x = 1
输出：false
解释：数字 1 根本没出现，违反条件 1。
```

**示例 4（退化情形）**

```text
输入：n = 0, x = 0
输出：false
解释：0 的十进制表示是 "0"，首位正好是 0，违反条件 2。
```

## 3. 解题思路

### 3.1 暴力思路

对 $n$ 反复取模 $10$ 拆出每一位，收集到数组后：先看**最后**拆出的那一位（即最高位）是否等于 $x$，再看数组中是否出现过 $x$。时间与空间都是 $O(\log_{10} n)$，在 $n \le 10^5$ 下最多 6 位，绰绰有余。

也可以直接枚举「所有十进制数字串」再比对，但那是 $O(10^{\log n})$ 级别的答案空间，完全没有必要——两个条件都只看数字串本身。

### 3.2 核心观察：两个条件都只依赖 $s = \text{to\_string}(n)$

![有效数字整数：一个数字串，两个独立条件](images/bw181_q1_digit_rule.svg)

- **转成字符串后，「首位」就是 `s[0]`，无需考虑位数**。十进制表示没有前导零，所以 `s[0]` 恰好是最高位，`std::to_string` / Python 的 `str()` 都不会产生前导零。
- **「至少出现一次 $x$」等价于 `s.find(c) != npos`**（Python：`c in s`），一次线性扫描即可，不用手写逐位比较。
- **两个条件是「与」关系**：先判首位（$O(1)$），不满足可直接返回 `false`，省掉扫描。

于是整个判定是：`s[0] != c and c in s`，代码只有一行。字符串长度不超过 6，实际复杂度 $O(\log n)$。

### 3.3 算法流程

![示例演算：两个条件互为「与」关系](images/bw181_q1_walkthrough.svg)

```text
1. s = to_string(n)，c = char('0' + x)
2. 若 s[0] == c：返回 false            // 条件 2 不满足
3. 若 s.find(c) == npos：返回 false     // 条件 1 不满足
4. 返回 true
```

**为什么先判首位**：`s[0]` 的判断是 $O(1)$，而「出现性」扫描是 $O(\log n)$；把便宜的判断放前面，绝大多数非法输入可以提前返回。

### 3.4 示例演算

| $n$ | $x$ | $s$ | `s[0] == c`？ | 出现过 $c$？ | 结论 |
|-----|-----|-----|---------------|--------------|------|
| 101 | 0 | `"101"` | 否（`'1' != '0'`） | 是（下标 1） | `true` |
| 232 | 2 | `"232"` | 是（首位即 2） | 是 | `false` |
| 5 | 1 | `"5"` | 否 | 否 | `false` |
| 0 | 0 | `"0"` | 是 | 是 | `false` |

四个用例覆盖了「全满足」「首位命中」「未出现」「$n = 0$ 退化」四类情况。

## 4. 算法细节

1. **字符加法**：`char('0' + x)` 把数字映射成字符；Python 里直接 `str(x)`。
2. **`s[0]` 的安全性**：`to_string(0)` 得到 `"0"`，长度恒为 1 以上，不会空串。
3. **`find` 的返回值**：C++ 用 `s.find(c) != string::npos` 判断存在；不要用 `s.find(c) >= 0`（`npos` 是无符号大数，恒为真）。
4. **Python 的短路**：`s[0] != c and c in s` 依靠 `and` 的短路求值，首位命中时不再扫描。
5. **不必判断位数是否相等**：条件里没有「位数」要求，只有「出现」与「不以它开头」。

## 5. 正确性证明

**引理 1（首位对应最高位）**：设 $s = \text{to\_string}(n)$，则 `s[0]` 是 $n$ 十进制表示的最高位，且 $s$ 没有前导零。

**证明**：`to_string` 输出的正是 $n$ 的标准十进制表示，最高位在前；对 $n = 0$ 输出 `"0"`。十进制标准表示按定义不含前导零，故 `s[0]` 即最高位。∎

**引理 2（两个条件的字符串刻画）**：条件 1 成立 $\iff$ `s.find(c) != npos`；条件 2 成立 $\iff$ `s[0] != c`。

**证明**：字符串 $s$ 的每个字符对应 $n$ 的一位数字，故「存在某位等于 $x$」$\iff$「字符 $c$ 在 $s$ 中出现」$\iff$ `find` 成功。由引理 1，`s[0]` 是最高位，故「不以 $x$ 开头」$\iff$ `s[0] != c`。∎

**定理**：算法返回 `true` 当且仅当 $n$ 是有效数字。

**证明**：算法返回 `true` 仅当同时通过第 2、3 步，即 `s[0] != c` 且 `find` 成功；由引理 2，这等价于条件 1、2 同时成立，即 $n$ 有效。反之若 $n$ 有效，两个条件成立，两步都不会提前返回，最终返回 `true`。∎

## 6. 复杂度分析

- **时间**：$O(\log_{10} n)$。构造字符串与一次 `find` 都是线性扫描数位；$n \le 10^5$ 时至多 6 位，实际为常数。
- **空间**：$O(\log_{10} n)$。存储 $s$ 需要数位长度的空间；若用取模拆位则只需 $O(1)$ 额外变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool validDigit(int n, int x) {
        string s = to_string(n);
        char c = char('0' + x);
        return s[0] != c && s.find(c) != string::npos;
    }
};
```

### Python

```python
class Solution:
    def validDigit(self, n: int, x: int) -> bool:
        s = str(n)
        c = str(x)
        return s[0] != c and c in s
```

## 8. 边界情况与易错点

1. **$n = 0$ 且 $x = 0$**：`"0"` 的首位就是 0，应返回 `false`。若把「数字 0 出现」当成特判单独放行，就会在这里 WA。
2. **首位命中但后面也出现**：如 $n = 232, x = 2$，条件 1 满足而条件 2 不满足，答案仍是 `false`——两个条件缺一不可。
3. **`find` 与 `npos`**：C++ 中 `npos` 是 `size_t` 的极大值，写 `s.find(c) >= 0` 永远为真，必须与 `npos` 比较。
4. **不要用数值取模判首位**：取模只能拿到最低位；判首位要么用字符串，要么在拆位循环结束后取最后拆出的那一位。
5. **`x` 是数字而不是字符**：题目给的是整数 $x$，务必先转成字符 `'0' + x` 或 `str(x)` 再比较，否则会拿数字 $0$ 与字符 `'0'`（ASCII 48）比较。
6. **$n$ 的上界很小**：$10^5$ 意味着最多 6 位，无需担心任何性能问题，写清楚即可。
