# LeetCode 比较双调部分的和 题解

## 1. 题目概述

- **标题 / 题号**：比较双调部分的和（#3909，medium）
- **链接**：https://leetcode.cn/problems/compare-sums-of-bitonic-parts/
- **来源**：LeetCode 第 181 场双周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：给定长度为 $n$ 的**双调**数组 `nums`（先**严格递增**到唯一峰值，再**严格递减**）。把数组切成两段：

- **递增部分**：下标 $0$ 到峰值元素（含）；
- **递减部分**：峰值元素到下标 $n-1$（含）。

峰值元素**同时属于两段**。比较两段之和：递增部分更大返回 $0$，递减部分更大返回 $1$，相等返回 $-1$。

**约束**：

- $3 \le n \le 10^5$
- $1 \le nums[i] \le 10^9$
- `nums` 保证是双调数组

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,2,1]
输出：1
解释：峰值 nums[1] = 3；递增部分 [1,3] 和 4，递减部分 [3,2,1] 和 6，递减更大。
```

**示例 2**

```text
输入：nums = [2,4,5,2]
输出：0
解释：峰值 nums[2] = 5；递增部分 [2,4,5] 和 11，递减部分 [5,2] 和 7，递增更大。
```

**示例 3**

```text
输入：nums = [1,2,4,3]
输出：-1
解释：峰值 nums[2] = 4；递增部分 [1,2,4] 和 7，递减部分 [4,3] 和 7，两者相等。
```

## 3. 解题思路

### 3.1 暴力思路

先找出峰值下标 $p$，再分别累加 $[0, p]$ 与 $[p, n-1]$。即使最直白地「对每个下标判断它在哪一段再累加」，也只是三次线性扫描，$O(n)$，$n \le 10^5$ 完全够用。所谓「暴力」在这里并没有更差的选项——真正的坑在于**峰值下标的定位**和**峰值的重复计入**。

### 3.2 核心观察：峰值是唯一的分界点

![双调数组：峰值是唯一的分界点](images/bw181_q2_peak_split.svg)

- **双调保证 $p$ 唯一且可由一次扫描确定**：从左往右，只要 `nums[i+1] > nums[i]` 就继续右移，第一个不再上升的位置就是峰值。
- **两段只差峰值本身**：设 $S$ 为全数组和，$A = \sum_{i=0}^{p} nums[i]$，$D = \sum_{i=p}^{n-1} nums[i]$，则

$$A + D = S + nums[p]$$

即「峰值的值被计算了两次」。这个恒等式可以当作自检：任何实现算出的 $A + D$ 与 $S + nums[p]$ 不等，就说明边界写错了。

- **比较只需 $A$ 与 $D$ 的大小关系**，无需真的构造两个子数组，也不必担心 $A + D$ 溢出（用 64 位即可，$n \cdot nums[i] \le 10^{14}$）。

### 3.3 算法流程

```text
1. peak = 0
2. while peak + 1 < n 且 nums[peak+1] > nums[peak]:  peak++
3. inc = Σ nums[0..peak]，dec = Σ nums[peak..n-1]      // 峰值各算一次
4. inc > dec → 0；dec > inc → 1；否则 -1
```

### 3.4 示例演算

![示例演算：一次扫描定峰，两段求和比较](images/bw181_q2_walkthrough.svg)

| `nums` | $p$ | 递增部分（和） | 递减部分（和） | 比较 | 返回 |
|--------|-----|----------------|----------------|------|------|
| `[1,3,2,1]` | 1 | `[1,3]` = 4 | `[3,2,1]` = 6 | 递减更大 | 1 |
| `[2,4,5,2]` | 2 | `[2,4,5]` = 11 | `[5,2]` = 7 | 递增更大 | 0 |
| `[1,2,4,3]` | 2 | `[1,2,4]` = 7 | `[4,3]` = 7 | 相等 | -1 |

三个示例分别命中三种返回分支，且 `4 + 6 = 1+3+2+1 + 3`、`11 + 7 = 13 + 5`、`7 + 7 = 10 + 4` 都满足恒等式 $A + D = S + nums[p]$。

## 4. 算法细节

1. **定峰循环**：`while (peak + 1 < n && nums[peak+1] > nums[peak]) peak++;` 严格递增用 `>`，不要写成 `>=`——双调数组严格递增，`>=` 在等值/递减边界会提前停下，虽然本题严格性保证不会出现等值，但语义上应写 `>`。
2. **两段的循环边界**：递增段是 `i <= peak`，递减段是 `i >= peak`，两段的 `peak` 都不能漏。写成 `i < peak` 与 `i > peak` 会少算一次峰值。
3. **64 位求和**：$n \le 10^5$、$nums[i] \le 10^9$，总和可达 $10^{14}$，`int` 必溢出，C++ 用 `long long`。
4. **返回值映射**：题目约定「递增更大返回 0」，容易与「$0$ 表示 false / 更小」的直觉混淆，建议在代码里显式写三个分支。
5. **可选的单调性优化**：若想少扫一遍，可从两端向峰值累加；但既然已经 $O(n)$，直接两段循环更清晰。

## 5. 正确性证明

**引理 1（峰值下标正确）**：设 $p$ 为算法第 2 步结束时的下标，则 `nums[0..p]` 严格递增、`nums[p..n-1]` 严格递减。

**证明**：双调数组存在唯一峰值位置 $q$，满足 $nums[0] < \cdots < nums[q] > \cdots > nums[n-1]$。循环条件 `nums[peak+1] > nums[peak]` 在 $peak < q$ 时为真、在 $peak = q$ 时为假（因为 $nums[q+1] < nums[q]$），故循环恰在 $peak = q$ 时停止，即 $p = q$，两段的单调性由双调定义直接得到。∎

**引理 2（两段之和的定义一致）**：算法算出的 `inc` 等于递增部分之和，`dec` 等于递减部分之和，且 $inc + dec = S + nums[p]$。

**证明**：由引理 1，递增部分按定义就是 `nums[0..p]`、递减部分就是 `nums[p..n-1]`，两个循环分别完整累加这两段，故相等。两段之和把 `nums[p]` 计入两次、其余元素各一次，展开即得 $inc + dec = S + nums[p]$。∎

**定理**：算法返回 $0$ / $1$ / $-1$ 当且仅当递增部分之和更大 / 递减部分之和更大 / 两者相等。

**证明**：由引理 2，`inc`、`dec` 就是两段之和，第 4 步按三种大小关系分别返回 $0$、$1$、$-1$，与题目要求逐一对应，故结论成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$。定峰一次线性扫描；两段求和合计遍历 $n+1$ 个元素（峰值被访问两次）。常数很小，$n = 10^5$ 时不到 $0.1$ ms 量级。
- **空间**：$O(1)$。只用到 `peak`、`inc`、`dec` 三个标量，未额外申请数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int compareBitonicSums(vector<int>& nums) {
        int n = nums.size();
        int peak = 0;
        while (peak + 1 < n && nums[peak + 1] > nums[peak]) peak++;
        long long inc = 0, dec = 0;
        for (int i = 0; i <= peak; i++) inc += nums[i];
        for (int i = peak; i < n; i++) dec += nums[i];
        if (inc > dec) return 0;
        if (dec > inc) return 1;
        return -1;
    }
};
```

### Python

```python
class Solution:
    def compareBitonicSums(self, nums: list[int]) -> int:
        n = len(nums)
        peak = 0
        while peak + 1 < n and nums[peak + 1] > nums[peak]:
            peak += 1
        inc = sum(nums[:peak + 1])
        dec = sum(nums[peak:])
        if inc > dec:
            return 0
        if dec > inc:
            return 1
        return -1
```

## 8. 边界情况与易错点

1. **纯递增 / 纯递减的退化**：题目说「先严格递增再严格递减」，但长度为 2 的递增段或递减段可能为空。例如 `[3,2,1]` 时 $p = 0$，递增部分只有 `[3]`，递减部分是整个数组；`[1,2,3]` 时 $p = 2$，递减部分只有 `[3]`。代码的 `i <= peak` / `i >= peak` 边界天然覆盖这两种情况。
2. **峰值重复计入**：这是本题唯一的「陷阱」。若习惯性写成 `[0, p)` 与 `(p, n-1]`，会漏掉峰值；用 $A + D = S + nums[p]$ 自检最稳。
3. **`int` 溢出**：单元素可达 $10^9$，$10^5$ 个元素之和 $10^{14}$ 远超 `int`，必须 `long long`。
4. **返回值的语义**：「递增更大 → 0」不是「更小 → 0」，别凭直觉写反。
5. **相等分支**：只有 `inc == dec` 才返回 $-1$，不要用 `else` 兜底把「相等」和「递减更大」混在一起。
6. **等值元素**：双调数组保证严格单调，若把定峰条件写成 `>=`，在极端（虽然不合法）输入上会提前停在平台段，导致两段划分错误。
