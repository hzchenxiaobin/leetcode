# LeetCode 装包裹的最小浪费空间 题解

## 1. 题目概述

- **标题 / 题号**：装包裹的最小浪费空间（#1889，hard）
- **链接**：https://leetcode.cn/problems/minimum-space-wasted-from-packaging/
- **来源**：LeetCode 第 244 场周赛 Q4
- **难度**：困难
- **标签**：数组、二分查找、前缀和、排序

**题意**：有 $n$ 个包裹（尺寸数组 `packages`）和 $m$ 个供应商，第 $j$ 个供应商提供一组**互不相同**的箱子尺寸 `boxes[j]`，每种尺寸的箱子**数量无限**。每个箱子只能装一个包裹，且要求包裹尺寸 **小于等于** 箱子尺寸。必须**只选一个供应商**装完所有包裹，使总浪费空间（每箱「箱子尺寸 − 所装包裹尺寸」之和）最小。若存在装不下的包裹则该供应商不可选；所有供应商都不可选时返回 `-1`。答案对 $10^9 + 7$ 取模。

**约束**：

- $1 \le n \le 10^5$，$1 \le m \le 10^5$
- $1 \le \text{packages}[i] \le 10^5$
- $1 \le \text{boxes}[j].\text{length} \le 10^5$，$\sum_j \text{boxes}[j].\text{length} \le 10^5$
- $1 \le \text{boxes}[j][k] \le 10^5$，`boxes[j]` 内元素互不相同

> 💡 **本质**：各供应商互相独立，对每个供应商单独求「用它的箱子装完全部包裹的最小浪费」，再取全局最小。单供应商内部是一个**贪心 + 排序 + 前缀和 + 二分**的分段统计问题。

## 2. 示例

**示例 1**

```text
输入：packages = [2,3,5], boxes = [[4,8],[2,8]]
输出：6
解释：选供应商 0：包裹 2、3 装进尺寸 4 的箱子，包裹 5 装进尺寸 8 的箱子。
      浪费 = (4−2) + (4−3) + (8−5) = 6。
      供应商 1 浪费 = (2−2) + (8−3) + (8−5) = 8，更差。
```

**示例 2**

```text
输入：packages = [2,3,5], boxes = [[1,4],[2,3],[3,4]]
输出：-1
解释：没有任何供应商的箱子能装下尺寸为 5 的包裹。
```

**示例 3**

```text
输入：packages = [3,5,8,10,11,12], boxes = [[12],[11,9],[10,5,14]]
输出：9
解释：选供应商 2：浪费 = (5−3)+(5−5)+(10−8)+(10−10)+(14−11)+(14−12) = 9。
```

## 3. 解题思路

### 3.1 暴力思路

对每个供应商，逐个包裹找「能装下它的最小箱子」并累加浪费。单个包裹的匹配若线性扫描箱子列表，总复杂度为 $O\big(n \cdot \sum_j b_j\big) \approx 10^{10}$（$n$ 与 $\sum b_j$ 均可达 $10^5$），必然超时。即使对包裹和箱子都排序后用双指针做到 $O(n + b_j)$ 每个供应商，$m$ 个供应商求和仍是 $O(m \cdot n)$ 级别，同样不可行——必须让「每个箱子 / 每个包裹」全局只被处理**常数次或对数次**。

### 3.2 核心观察：排序分段 + 前缀和 + 二分定位

![核心观察：排序后按箱子尺寸分段统计浪费](images/packaging_waste_segment_model.svg)

**贪心**：每个包裹应装进**能装下它的最小箱子**。设包裹 $p$ 同时能被箱子 $b_s$、$b_t$（$b_s < b_t$）装下，则用 $b_s$ 浪费 $b_s - p$，用 $b_t$ 浪费 $b_t - p > b_s - p$。由于箱子数量无限，包裹之间的归属互不影响，逐包裹取最小可行箱即为该供应商的最优方案。

**分段统计**：把某供应商的箱子尺寸升序排列 $b_1 < b_2 < \cdots < b_k$，把排序后的 `packages` 切成 $k$ 段：第 $t$ 段是尺寸落在 $(b_{t-1}, b_t]$ 的全部包裹（$b_0 = -\infty$），它们恰好全部用 $b_t$ 装箱。段边界用**二分查找**（`upper_bound`）定位，段内包裹和用**前缀和** $O(1)$ 查询，于是第 $t$ 段的浪费为：

$$\text{waste}_t = b_t \cdot (r_t - r_{t-1}) - \big(\text{prefix}[r_t] - \text{prefix}[r_{t-1}]\big)$$

其中 $r_t$ 是 `packages` 中 $\le b_t$ 的元素个数。这样每个箱子只花 $O(\log n)$，整组箱子合计 $O(b_j \log n)$，与包裹总数无关（包裹的贡献被前缀和压缩了）。

**剪枝**：若供应商的最大箱子 $< \max(\text{packages})$，最大包裹装不下，直接跳过整组，$O(1)$ 判定。

### 3.3 算法流程

![算法流程图：单供应商的处理与全局汇总](images/packaging_waste_algorithm_flow.svg)

1. **全局预处理（一次）**：排序 `packages`，建立前缀和数组 `prefix`。
2. **枚举每个供应商** $j$：
   - 排序 `boxes[j]`；若 `boxes[j].back() < packages.back()`，`continue`；
   - 维护游标 `prev = 0` 与累加器 `waste = 0`（64 位）；
   - 对每个箱子尺寸 $b$（升序）：`idx = upper_bound(packages, b)`；若 `idx > prev`，累加段浪费并令 `prev = idx`；`prev == n` 时提前 `break`。
   - 若最终 `prev == n`，用 `waste` 更新全局最小 `ans`。
3. `ans` 仍为 $+\infty$ 则返回 `-1`，否则返回 `ans % (10^9 + 7)`。

### 3.4 示例演算

![示例演算：三个供应商的对照](images/packaging_waste_example_walkthrough.svg)

以示例 3 `packages = [3,5,8,10,11,12]` 为例，`prefix = [0,3,8,16,26,37,49]`。

**供应商 2**（排序后 `[5,10,14]`）：

| 箱 $b$ | `upper_bound` 得 `idx` | 本段包裹 | 段和 | 段浪费 $b \cdot \text{cnt} - \text{段和}$ |
|--------|------------------------|----------|------|-------------------------------------------|
| 5 | 2（3、5 ≤ 5） | 3, 5 | 8 | $5 \times 2 - 8 = 2$ |
| 10 | 4（8、10 ≤ 10） | 8, 10 | 18 | $10 \times 2 - 18 = 2$ |
| 14 | 6（11、12 ≤ 14） | 11, 12 | 23 | $14 \times 2 - 23 = 5$ |

总浪费 $= 2 + 2 + 5 = 9$，`prev = 6 = n` ✓。

**供应商 0**（`[12]`）：一个箱子装全部 6 个包裹，浪费 $= 12 \times 6 - 49 = 23$。

**供应商 1**（`[11,9]`）：最大箱 $11 <$ 最大包裹 $12$，剪枝跳过。

最终 $\min(9, 23) = 9$ ✓。

## 4. 算法细节

1. **数据结构选择**：`prefix` 用 64 位整型数组（C++ `vector<long long>`）。C++ 的 `upper_bound` / Python 的 `bisect.bisect_right` 均为标准二分，语义是「第一个 $> b$ 的位置」，恰好等于 $\le b$ 的元素个数。
2. **`prev` 游标单调性**：箱子升序处理，`idx` 关于 $b$ 单调不减，故 `prev` 只前进不回退。`idx <= prev` 说明箱子 $b$ 装不下任何新包裹（比如 $b$ 小于最小剩余包裹），跳过即可，不会重复统计。
3. **段和的推导**：第 $t$ 段包裹全用 $b_t$ 装，箱子总容量 $b_t \cdot \text{cnt}_t$，减去包裹实际尺寸和 $\text{prefix}[r_t] - \text{prefix}[r_{t-1}]$ 即该段浪费。这把 $O(\text{cnt}_t)$ 的逐包裹累加压成 $O(1)$。
4. **取模时机**：全程用真值累加、比较，**最后一步**才取模。中途取模会破坏 `min` 比较的大小关系（两个取模后的值无法还原原始大小）。
5. **溢出估算**：$n \le 10^5$，单包裹尺寸、箱子尺寸 $\le 10^5$，总浪费上界约 $10^5 \times 10^5 = 10^{10}$，超出 32 位 `int`（约 $2.1 \times 10^9$），C++ 必须用 `long long`；Python 原生大整数无此问题。

## 5. 正确性证明

**引理 1（单包裹贪心最优）**：固定供应商，其箱子尺寸集合为 $B$。对任意包裹 $p$，在所有 $\ge p$ 的箱子尺寸中选择最小者 $\min\{b \in B : b \ge p\}$，是使该包裹浪费最小的选择。

**证明**：设 $b_s = \min\{b \in B : b \ge p\}$，任取另一可行箱子 $b_t \in B$、$b_t \ge p$。由最小性 $b_t \ge b_s \ge p$，故 $b_t - p \ge b_s - p \ge 0$，即选 $b_s$ 的浪费不超过任何其他可行选择。∎

**引理 2（包裹独立可分解）**：供应商方案的总浪费等于各包裹浪费之和，且箱子供应无限，因此各包裹的选择互不约束。

**证明**：总浪费 $\sum_{i} (\text{box}_i - p_i) = \sum_i \text{box}_i - \sum_i p_i$，按包裹逐项展开即逐包裹浪费之和。任一包裹选用某尺寸的箱子不会耗尽该尺寸（数量无限），故不存在「资源竞争」，$n$ 个单变量最小化问题可以独立求解。∎

**定理**：设某供应商箱子升序为 $b_1 < \cdots < b_k$，$r_t$ 为 `packages` 中 $\le b_t$ 的元素个数（$r_0 = 0$）。若 $r_k = n$，则该供应商的最小总浪费为 $\sum_{t=1}^{k} \big[ b_t (r_t - r_{t-1}) - (\text{prefix}[r_t] - \text{prefix}[r_{t-1}]) \big]$；否则该供应商不可行。

**证明**：由引理 1、2，最优方案中每个包裹 $p$ 装入 $\min\{b \in B : b \ge p\}$。排序后，落在 $(b_{t-1}, b_t]$ 的包裹恰以 $b_t$ 为最小可行箱（它们 $> b_{t-1}$ 装不进更小的箱，又 $\le b_t$），落在 $(-\infty, b_1]$ 的包裹以 $b_1$ 为最小可行箱。因此第 $t$ 段（下标区间 $(r_{t-1}, r_t]$）的包裹全部用 $b_t$，段浪费为 $b_t \cdot (r_t - r_{t-1}) - \sum_{i=r_{t-1}+1}^{r_t} \text{packages}[i]$，后者即 $\text{prefix}[r_t] - \text{prefix}[r_{t-1}]$。各段求和即得结论；若 $r_k < n$，则存在包裹 $> b_k$，无可行箱，该供应商不可行。∎

**推论**：对所有可行供应商取上述表达式最小值，即全局答案；无可行供应商时返回 `-1`。算法输出的正是这些值（流程中 `prev` 即 $r_t$ 的滚动记录），故算法正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(n \log n + \sum_j b_j \log b_j + (\sum_j b_j) \log n\big)$。第一项排序包裹，第二项各供应商排序自己的箱子，第三项每个箱子一次二分。由 $\sum_j b_j \le 10^5$，总量约 $10^5 \cdot 17 \approx 1.7 \times 10^6$ 次比较，轻松通过。
- **空间复杂度**：$O(n)$。前缀和数组；排序视语言实现另需 $O(\log n)$ 栈空间（Python 的 `sort` 为 $O(n)$ 辅助）。`prev`、`waste` 均为 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minWastedSpace(vector<int>& packages, vector<vector<int>>& boxes) {
        const long long MOD = 1e9 + 7;
        sort(packages.begin(), packages.end());
        int n = packages.size();
        vector<long long> prefix(n + 1, 0);
        for (int i = 0; i < n; i++)
            prefix[i + 1] = prefix[i] + packages[i];

        long long ans = LLONG_MAX;
        for (auto& bs : boxes) {
            sort(bs.begin(), bs.end());
            if (bs.back() < packages.back())
                continue;  // 最大包裹装不下，整组剪枝

            long long waste = 0;
            int prev = 0;
            for (int b : bs) {
                int idx = upper_bound(packages.begin(), packages.end(), b) - packages.begin();
                if (idx > prev) {
                    waste += (long long)b * (idx - prev) - (prefix[idx] - prefix[prev]);
                    prev = idx;
                }
                if (prev == n)
                    break;  // 全部装完，提前终止
            }
            if (prev == n)
                ans = min(ans, waste);
        }
        return ans == LLONG_MAX ? -1 : (int)(ans % MOD);
    }
};
```

### Python

```python
import bisect


class Solution:
    def minWastedSpace(self, packages: List[int], boxes: List[List[int]]) -> int:
        MOD = 10**9 + 7
        packages.sort()
        n = len(packages)
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + packages[i]

        ans = float("inf")
        for bs in boxes:
            bs.sort()
            if bs[-1] < packages[-1]:
                continue
            waste = 0
            prev = 0
            for b in bs:
                idx = bisect.bisect_right(packages, b)
                if idx > prev:
                    waste += b * (idx - prev) - (prefix[idx] - prefix[prev])
                    prev = idx
                if prev == n:
                    break
            if prev == n:
                ans = min(ans, waste)
        return -1 if ans == float("inf") else ans % MOD
```

## 8. 边界情况与易错点

1. **64 位溢出**：总浪费上界约 $10^{10}$，C++ 中 `waste`、`prefix`、以及 `b * (idx - prev)` 都必须用 `long long`；尤其 `(long long)b * cnt` 的强制转换不能漏，否则先按 `int` 相乘再赋值已经溢出。
2. **取模时机**：只能最后取模。取模后的值之间做 `min` 会得到错误答案，比较必须基于真值。
3. **不可行判定有两层**：一是 `bs.back() < packages.back()` 的 $O(1)$ 剪枝；二是即使没剪枝（比如箱子最大值恰好等于最大包裹但中间有洞——实际上不会发生，只要 `prev == n` 检查兜底）。最终以 `prev == n` 判定该供应商是否真的装完了所有包裹，二者缺一不可。
4. **`upper_bound` 与 `lower_bound` 的语义**：本题要「$\le b$ 的个数」，用 `upper_bound` / `bisect_right`。误用 `lower_bound` 会把恰好等于 $b$ 的包裹漏掉。
5. **`idx <= prev` 的箱子直接跳过**：箱子小于最小未装包裹时 `idx == prev`，不累加、不更新游标；不跳过也不会算错（条件保护了），但少了这层判断的「无脑累加」版本会把负数段算进去，务必保留 `if (idx > prev)`。
6. **提前终止**：`prev == n` 后剩余箱子无需再二分，`break` 掉能省不少常数（单个供应商箱子可达 $10^5$ 个）。
7. **空箱子列表**：约束保证 `boxes[j].length >= 1`，无需特判；但代码中 `bs.back()`、`bs[-1]` 的写法隐含依赖这一点。
8. **多供应商并列最小**：`min` 天然处理，无影响。

- 若每个箱子只能用**一次**（数量有限），问题升级为最小权匹配，需要用「箱子按尺寸排序 + 反悔贪心 / DP」等手段，复杂度与分析完全不同。
