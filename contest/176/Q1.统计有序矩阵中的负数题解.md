# LeetCode 统计有序矩阵中的负数 题解

## 1. 题目概述

- **标题 / 题号**：统计有序矩阵中的负数（#1351，easy）
- **链接**：https://leetcode.cn/problems/count-negative-numbers-in-a-sorted-matrix/
- **来源**：LeetCode 第 176 场周赛 Q1
- **难度**：简单
- **标签**：数组、二分查找、矩阵

**题意**：给定 $m \times n$ 的矩阵 `grid`，它的每一行、每一列都按**非严格递减**顺序排列。统计并返回矩阵中**负数**的个数。

关键点在于「非严格递减」四个字：同一行从左到右只会变小或持平，同一列从上到下只会变小或持平。因此每个格子不仅能推断出它右边的格子更小，还能推断出它下面的格子更小——**两个方向的单调性叠加**，才产生了 $O(m+n)$ 的做法。

**约束**：

- $m = \text{grid.length}$，$n = \text{grid}[i].\text{length}$
- $1 \le m, n \le 100$
- $-100 \le \text{grid}[i][j] \le 100$
- 行列均非严格递减
- **进阶**：要求 $O(n+m)$ 的解法

## 2. 示例

**示例 1**

```text
输入：grid = [[4,3,2,-1],[3,2,1,-1],[1,1,-1,-2],[-1,-1,-2,-3]]
输出：8
解释：矩阵中共有 8 个负数：
      第 0 行 1 个（-1）、第 1 行 1 个（-1）、
      第 2 行 2 个（-1,-2）、第 3 行 4 个（-1,-1,-2,-3）。
```

**示例 2**

```text
输入：grid = [[3,2],[1,0]]
输出：0
解释：全部的 4 个元素都 ≥ 0；注意 0 不是负数，不能被计入。
```

**示例 3（补充自测，非官方）**

```text
输入：grid = [[1,-1],[-1,-1]]
输出：3
解释：只有左上角的 1 非负，其余 3 格为负 —— 阶梯在最短的 2×2 矩阵上如何拐弯。
```

## 3. 解题思路

### 3.1 暴力思路

把 $m \times n$ 个格子全部看一遍，数 `< 0` 的个数：

$$O(mn) \;\text{时间},\quad O(1) \;\text{空间}$$

当 $m = n = 100$ 时是 $10^4$ 次比较，实际上**足够通过本题的全部测试点**，这也是签到题的宽容之处。但暴力完全忽略了「行列都有序」这个条件，而进阶要求正是 $O(m+n)$，说明出题人期望的是一个**利用单调性跳跃**的扫描。

一个中间方案是**逐行二分**：每行非增，可以二分出「第一个负数的位置」$p_i$，该行贡献 $n - p_i$，总计 $O(m \log n)$。它已经比暴力快一个量级，但仍把每一行当成独立问题，没有利用「行与行之间也单调」这一点。真正的 $O(m+n)$ 做法是把 $m$ 行的分界线串成一条阶梯，从左下角一次走完。

### 3.2 核心观察：负数区是右下角的一块阶梯

![行列非增带来的阶梯边界](images/wc176_q1_staircase_model.svg)

记第 $i$ 行**第一个负数**的列号为 $p_i$（若整行都是非负数，约定 $p_i = n$）。由「行内从左到右非增」可知：一旦某格是负数，它右边的格子必然也是负数，于是

$$\text{第 } i \text{ 行的负数个数} = n - p_i$$

整个答案就是 $\sum_{i=0}^{m-1} (n - p_i)$。现在只用关心 $p_i$ 怎么求。

再看「列内从上到下非增」：$\text{grid}[i+1][j] \le \text{grid}[i][j]$。若 $\text{grid}[i][j] < 0$，那么它正下方那一格更小，也是负数；继续往下推，整列从 $i$ 到 $m-1$ 全是负数。于是有

$$j \ge p_i \;\Longrightarrow\; j \ge p_{i+1} \qquad\text{即}\qquad p_{i+1} \le p_i$$

所以**列号序列是单调不增的**：$p_0 \ge p_1 \ge \dots \ge p_{m-1}$。把每行的分界点标在矩阵上，正好连成一条从右上走向左下的**阶梯**；负数就是阶梯右下侧的全部格子。

### 3.3 算法流程：沿阶梯走到左上角

![算法流程](images/wc176_q1_algorithm_flow.svg)

既然 $p_i$ 只减不增，就**不需要为每一行重新二分**：从最下面一行开始，指针列号只会往右走。具体地，取起点 $(i, j) = (m-1, 0)$，循环：

```text
1. i = m-1, j = 0, ans = 0
2. 当 i ≥ 0 且 j < n：
     2.1 若 grid[i][j] < 0：
            ans += n - j      ← 本行 j..n-1 全为负，整段结算
            i -= 1            ← 本行结束，向上一行
     2.2 否则（grid[i][j] ≥ 0）：
            j += 1            ← 本列 i 及其上方都非负，整列跳过
3. 返回 ans
```

循环维持两个不变量：

- **上一层已结清**：第 $i+1$ 行及以下的所有格子中，负数的个数已经全部计入 `ans`；
- **左边已排除**：当前第 $i$ 行的第 $0 \dots j-1$ 列都是非负数（它们是被 `j += 1` 跳过的）。

命中 `grid[i][j] >= 0` 时为什么能整列跳过？因为列非增意味着**上方**格子更大：对 $i' \le i$ 有 $\text{grid}[i'][j] \ge \text{grid}[i][j] \ge 0$。也就是说这一列在第 $i$ 行及其上方的所有格子里都没有负数，可以安全地不再回头处理。

> 💡 注意指针方向：`i--` 向上走、`j++` 向右走，两个方向都**不回退**。这正是 $O(m+n)$ 的来源；如果向上走时把 `j` 复位成 0，就会退化成 $O(mn)$。

### 3.4 示例演算

![示例 1 走查表](images/wc176_q1_walkthrough.svg)

对示例 1 的 $4 \times 4$ 矩阵，从 $(3, 0)$ 出发：

| 步 | 当前格 | 值 | 判定与动作 | `ans` |
|----|--------|----|------------|-------|
| 1 | $(3, 0)$ | $-1$ | 负数 → `ans += 4`，$i = 2$ | 4 |
| 2 | $(2, 0)$ | $1$ | 非负 → $j = 1$ | 4 |
| 3 | $(2, 1)$ | $1$ | 非负 → $j = 2$ | 4 |
| 4 | $(2, 2)$ | $-1$ | 负数 → `ans += 2`，$i = 1$ | 6 |
| 5 | $(1, 2)$ | $1$ | 非负 → $j = 3$ | 6 |
| 6 | $(1, 3)$ | $-1$ | 负数 → `ans += 1`，$i = 0$ | 7 |
| 7 | $(0, 3)$ | $-1$ | 负数 → `ans += 1`，$i = -1$ | 8 |

$i$ 降到 $-1$ 时退出，答案是 $4 + 2 + 1 + 1 = 8$。注意每次 `ans` 的增量都恰好是「当前行剩余整段」的长度：第 3 行 4 格、第 2 行 2 格、第 1 行 1 格、第 0 行 1 格。7 步就覆盖了 16 格中的全部信息，比逐格扫描省一半以上。

## 4. 算法细节

1. **约定 $p_i = n$ 处理「整行非负」**：约定让公式 $\sum (n-p_i)$ 不用特判；代码里表现为 `j` 一路加到 $n$ 后循环自然结束，此时当前行与它上方所有行都没有负数。
2. **循环条件必须同时判两个边界**：`i >= 0 && j < n`。C++ 与 Python 的 `&&` / `and` 都是短路求值，先判 `i >= 0` 再访问 `grid[i][j]` 才不会越界。Python 尤其危险：`grid[-1]` 不报错，而是**静默回绕到最后一行**，把答案算错。
3. **`i--` 时不要重置 `j`**：这是全题最核心的一行。列单调性保证 $p_{i-1} \ge p_i$，所以上一行的分界点只会更靠右；`j` 保留即可，重置会让复杂度退化到 $O(mn)$。
4. **用 `< 0` 而不是 `<= 0`**：0 既不是正数也不是负数，示例 2 就是为了卡这个边界；矩阵里出现 0 时它属于「非负」，应当被 `j += 1` 跳过。
5. **对称写法：从右上角出发**。取 $(i,j) = (0, n-1)$，若 $\text{grid}[i][j] < 0$ 则整列 $i \dots m-1$ 为负，`ans += m - i` 后 $j$ 左移；若 $\ge 0$ 则本行 $0 \dots j$ 全非负，$i$ 下移。两种写法步数上界同为 $m+n$，可互为对拍手段。
6. **逐行二分可作为 $O(m \log n)$ 的对照**：C++ 用 `upper_bound(row.begin(), row.end(), 0, greater<int>())` 直接得到第一个 $< 0$ 的位置（行降序时，`greater` 让 `upper_bound` 找到第一个满足 $0 > v$ 的元素）；Python 可对 `row` 取负后用 `bisect_right(..., 0)` 计数。数据量小时两者都很快，但只有阶梯法满足进阶要求。
7. **坐标不会溢出、也不需额外数组**：只维护 `i, j, ans` 三个整数；$ans \le mn \le 10^4$，远在 `int` 范围内，无需 `long long`。

## 5. 正确性证明

**引理 1（行内后缀全负）**：若 $\text{grid}[i][j] < 0$，则对任意 $j' \ge j$ 有 $\text{grid}[i][j'] < 0$。

**证明**：行非增给出 $\text{grid}[i][j'] \le \text{grid}[i][j] < 0$（$j' \ge j$）。∎

**引理 2（列内上方非负）**：若 $\text{grid}[i][j] \ge 0$，则对任意 $i' \le i$ 有 $\text{grid}[i'][j] \ge 0$。

**证明**：列非增给出 $\text{grid}[i][j] \le \text{grid}[i'][j]$（$i' \le i$），故 $\text{grid}[i'][j] \ge 0$。∎

**引理 3（分界点单调）**：$p_{i+1} \le p_i$，即列号序列单调不增。

**证明**：设 $j \ge p_i$，由 $p_i$ 的定义及引理 1 有 $\text{grid}[i][j] < 0$；又列非增，$\text{grid}[i+1][j] \le \text{grid}[i][j] < 0$，故 $j \ge p_{i+1}$。于是 $\{p_i, \dots, n-1\} \subseteq \{p_{i+1}, \dots, n-1\}$，两端取下界得 $p_{i+1} \le p_i$。∎

**引理 4（循环不变量）**：每次进入循环体时，(a) 第 $i+1$ 至 $m-1$ 行的负数已全部计入 `ans`，且这些行不再被访问；(b) 第 $i$ 行的第 $0 \dots j-1$ 列均 $\ge 0$；(c) `ans` 恰为已结算格子中负数的个数。

**证明**：对迭代次数归纳。初始 $i = m-1, j = 0$ 时 (a) 为空区间成立，(b) 为空区间成立，(c) `ans = 0` 成立。设进入某轮时不变量成立，分两种情形：

- **`grid[i][j] < 0`**：由引理 1，第 $i$ 行的 $j \dots n-1$ 全为负；由 (b)，第 $i$ 行 $0 \dots j-1$ 全非负。故第 $i$ 行负数恰为 $n-j$ 个，`ans += n - j` 后 (a)(c) 对第 $i$ 行成立。令 $i' = i-1$：对任意 $j' < j$，由 (b) 有 $\text{grid}[i][j'] \ge 0$，再由引理 2 得 $\text{grid}[i'][j'] \ge 0$，故新的 (b) 对 $j' < j$ 成立（`j` 未变）。
- **`grid[i][j] \ge 0`**：令 $j' = j+1$。原 (b) 覆盖 $0 \dots j-1$，本轮又验证了第 $j$ 列非负，故新 (b) 对 $0 \dots j'-1$ 成立；(a) 与 (c) 未被修改，仍成立。∎

**定理**：算法返回的 `ans` 等于矩阵中负数的总数。

**证明**：循环每轮要么 $i$ 减一、要么 $j$ 加一，故至多 $m+n$ 轮后终止，终止时或 $i < 0$、或 $j = n$。

- 若 $i < 0$：由引理 4(a)，第 $0 \dots m-1$ 行全部结算完毕，由 (c) `ans` 即总数。
- 若 $j = n$：由引理 4(b)，第 $i$ 行全为非负；对任意 $i' < i$ 与任意列 $j$，引理 2 给出 $\text{grid}[i'][j] \ge \text{grid}[i][j] \ge 0$，故上方各行也无负数；第 $i+1$ 行及以下已由 (a) 结算。所有格子都被正确计入，`ans` 即总数。若同时 $i < 0$，则属于上一种情形。

两种终止情形下 `ans` 都是负数总数。∎

## 6. 复杂度分析

- **时间**：$O(m+n)$。每轮迭代至少让 $i$ 减一或让 $j$ 加一，而 $i$ 从 $m-1$ 单调降到 $-1$、$j$ 从 $0$ 单调升到 $n$，故总轮数不超过 $m+n$；每轮只做一次比较与一次加法，$O(1)$。
- **空间**：$O(1)$。只用了 `i, j, ans` 三个整型变量，没有辅助数组，也没有递归栈。
- **对比**：暴力逐格扫描 $O(mn)$ 时间；逐行二分 $O(m \log n)$ 时间；阶梯法 $O(m+n)$ 时间。以 $m = n = 100$ 为例，三者分别约 $10^4$、$7 \times 10^2$、$2 \times 10^2$ 次操作。
- **为什么已经够优**：答案只取决于 $m$ 条「首个负数」的分界线，沿阶梯把它们串起来正好需要 $\Theta(m+n)$ 步；想再快就必须跳过某些行或列，而单调性并不保证这些行/列的分界点能被一次比较确定。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int countNegatives(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int i = m - 1, j = 0, ans = 0;
        while (i >= 0 && j < n) {
            if (grid[i][j] < 0) {
                ans += n - j;   // 本行 j..n-1 全为负，整段结算
                --i;            // 本行结束，向上一行
            } else {
                ++j;            // 本列 0..i 全非负，整列跳过
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def countNegatives(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        i, j, ans = m - 1, 0, 0
        while i >= 0 and j < n:
            if grid[i][j] < 0:
                ans += n - j      # 本行 j..n-1 全为负，整段结算
                i -= 1            # 本行结束，向上一行
            else:
                j += 1            # 本列 0..i 全非负，整列跳过
        return ans
```

## 8. 边界情况与易错点

1. **0 不是负数**：`[[3,2],[1,0]]` 的答案是 0，判断必须写 `< 0`。写成 `<= 0` 会把 0 计入，示例 2 直接挂。
2. **Python 的负索引回绕**：循环条件若写成 `while j < n and grid[i][j] ...` 而把 `i >= 0` 放到后面，`i` 减到 $-1$ 后 `grid[-1]` 会静默取到最后一行，得到错误答案且不报错。必须让 `i >= 0` 先短路。
3. **$1 \times 1$ 与单行/单列**：`[[-1]]` → 1，`[[0]]` → 0；单行全负时 `ans += n` 后 $i$ 变 $-1$ 立刻退出；单列则在 $j$ 加到 1 时因 $j < n$ 不再成立而退出。
4. **全负矩阵**：起点就是负数，每轮 `ans += n - 0` 并向上走，共 $m$ 轮得 $mn$，恰好正确；但若把 `ans += n - j` 写成 `ans += n`，遇到阶梯不在最左列的情形就会多算。
5. **全非负矩阵**：`j` 从 0 加到 $n$ 退出，`ans = 0`；注意此时用「从右上角出发」的对称写法会变成 $i$ 一路加到 $m$ 退出，也能得到 0，两种写法都要验证这个用例。
6. **阶梯在中间且多次换向**：示例 1 就是先 `i--`、再 `j++`、再 `i--` 的交替；每一步的动作只由**当前格**的符号决定，不要额外去比较上下左右。
7. **向上走时不复位 `j`**：若复位，最坏会退化为 $O(mn)$，虽然本题数据仍能过，但就失去了进阶意义，也可能在数据放大后 TLE。
