# LeetCode 最后 K 个数的乘积 题解

## 1. 题目概述

- **标题 / 题号**：最后 K 个数的乘积（#1352，medium）
- **链接**：https://leetcode.cn/problems/product-of-the-last-k-numbers/
- **来源**：LeetCode 第 176 场周赛 Q2
- **难度**：中等
- **标签**：设计、数组、数学、数据流、前缀和

**题意**：设计一个支持「追加」和「查询末尾乘积」的数据结构，实现 `ProductOfNumbers` 类：

- `ProductOfNumbers()`：用一个空的整数流初始化对象；
- `void add(int num)`：把 `num` 追加到当前列表末尾；
- `int getProduct(int k)`：返回当前列表里**最后 $k$ 个数**的乘积，调用时保证列表长度 $\ge k$。

题目要求的进阶目标是：`add` 与 `getProduct` **都做到 $O(1)$**（而不是每次查询扫 $k$ 个数）。

**约束**：

- $0 \le \text{num} \le 100$，即 `num` **可能为 0**；
- $1 \le k \le 4 \times 10^4$；
- `add` 与 `getProduct` 合计最多被调用 $4 \times 10^4$ 次；
- 任何时刻、任一段连续数字的乘积都落在 32 位有符号整数范围内（不会溢出）。

## 2. 示例

**示例 1**（官方示例）

```text
输入：
["ProductOfNumbers","add","add","add","add","add","getProduct","getProduct","getProduct","add","getProduct"]
[[],[3],[0],[2],[5],[4],[2],[3],[4],[8],[2]]

输出：[null,null,null,null,null,null,20,40,0,null,32]

解释：
add(3)          -> 列表 [3]
add(0)          -> 列表 [3,0]
add(2)          -> 列表 [3,0,2]
add(5)          -> 列表 [3,0,2,5]
add(4)          -> 列表 [3,0,2,5,4]
getProduct(2)   -> 20，即 5*4
getProduct(3)   -> 40，即 2*5*4
getProduct(4)   -> 0 ，即 0*2*5*4（窗口里含 0）
add(8)          -> 列表 [3,0,2,5,4,8]
getProduct(2)   -> 32，即 4*8
```

## 3. 解题思路

### 3.1 暴力思路

用一个数组（或队列）存下所有 `add` 进来的数。`add` 直接 `append`，$O(1)$；`getProduct(k)` 把末尾 $k$ 个数乘一遍，$O(k)$。

在 $4 \times 10^4$ 次调用、每次 $k$ 都取到 $4 \times 10^4$ 的极端情况下，总工作量是 $O(q \cdot k) \approx 1.6 \times 10^9$，必然超时。更关键的是每次查询都在**重复计算**同一批数的乘积，存在巨大的冗余。

### 3.2 核心观察：遇 0 清空的前缀积

![遇 0 清空：只维护最近一次 0 之后的前缀积](images/wc176_q2_zero_reset_model.svg)

「区间乘积」本来可以用**前缀积相除**降成 $O(1)$，但本题有两个坑：

1. `num` 可以是 0，而 0 **没有乘法逆元**，除法无法「穿过」一个 0；
2. 一旦列表里出现过 0，全局前缀积从那一刻起恒为 0，后面再乘什么都还原不出信息。

所以真正的关键不是「前缀积」，而是**前缀积的作用范围**：任何一个含有 0 的窗口，乘积必然是 0；而**不含 0 的窗口一定整段落在「最近一次 0 之后」**。于是我们可以：

> 把 0 当作**断点**。每次加入 0，就把之前累积的前缀积全部丢掉，从空状态重新累积。

维护数组 $P$，$P[0] = 1$ 为哨兵，$P[i]$ 表示「最近一次 0 之后的前 $i$ 个元素」的累积乘积；同时令 $L = \lvert P \rvert - 1$ 为**段长**（最近一次 0 之后的元素个数）。查询末 $k$ 个数的乘积：

$$P[L] \div P[L-k] \quad (k \le L), \qquad 0 \quad (k > L)$$

后半句（$k > L$ 时答案为 0）的道理是：0 距离末尾恰好 $L+1$ 个元素，所以 $k > L \iff k \ge L+1$，末 $k$ 个里必然含那个 0。

### 3.3 算法流程

![add 与 getProduct 的分支流程](images/wc176_q2_query_flow.svg)

- `add(num)`：
  - 若 `num == 0`：令 $P \gets [1]$，段长归零（旧数据整体作废）；
  - 否则：`P.append(P[-1] * num)`，段长加一。
- `getProduct(k)`：
  - 若 $k > \lvert P \rvert - 1$：直接返回 0（窗口跨过了 0）；
  - 否则返回 `P[-1] // P[-1 - k]`。

两个分支都只有常数次运算，因此单次 $O(1)$。

### 3.4 示例演算

![官方示例走查：P 随 add 增长，遇 0 归零](images/wc176_q2_walkthrough.svg)

对照示例 1：前 5 次 `add` 之后 $P = [1,2,10,40]$，$L = 3$（0 之后的三个数是 2、5、4）。

- `getProduct(2)`：$k = 2 \le 3$，返回 $P[3]/P[1] = 40/2 = 20$；
- `getProduct(3)`：$k = 3 \le 3$，返回 $P[3]/P[0] = 40/1 = 40$（**恰好等于段长**，仍有效）；
- `getProduct(4)`：$k = 4 > 3$，窗口含 0，返回 0；
- `add(8)` 后 $P = [1,2,10,40,320]$，`getProduct(2)` 返回 $320/10 = 32$。

## 4. 算法细节

1. **哨兵 $P[0]=1$**：这样当 $k = L$ 时公式变成 $P[L]/P[0]$，无需为「取满整段」写额外分支；空段（$L=0$）时 $P$ 也保持非空，不会越界。
2. **段长与数组同步**：$L = \lvert P \rvert - 1$，不额外维护变量就不会出现「P 清了但 L 忘了清」这类不一致 bug。若为可读性另存 `L`，必须在清空分支里同时置 0。
3. **判断条件是 $k > L$**：等价写法是 `k >= len(P)`。写成 `k >= L` 会把「窗口刚好铺满整个有效段」误判成 0。
4. **清空的实现**：C++ 用 `pref.assign(1, 1)`，Python 直接 `self.pref = [1]`（或 `del pref[1:]`），不要只把末尾改成 1，否则 $P$ 中残留的旧乘积会被后续除法读到。
5. **除法顺序**：分子是 $P[L]$、分母是 $P[L-k]$，写反会把答案变成倒数（多数情况直接得 0）。整数除法即可，不需要取模逆元，也不需要浮点。
6. **$P$ 中永远不含 0**：因为一遇 0 就清空，所以每个 $P[i] \ge 1$，除法永远安全，不必担心除以 0。
7. **C++ 内部用 `long long`**：题面保证 32 位内，但 `pref.back() * num` 这种中间计算用 64 位更稳；返回值再转 `int`。
8. **Python 必须用 `//`**：`/` 得到 `float`，当乘积超过 $2^{53}$ 时会产生精度误差。

## 5. 正确性证明

**引理 1（不变式）**：任意时刻，若「最近一次 0」之后共有 $L$ 个元素 $a_1, a_2, \dots, a_L$（若从未出现过 0，则取全部元素，并把假想断点放在列表最前面），则数组满足 $P[0] = 1$ 且对 $1 \le i \le L$ 有 $P[i] = a_1 a_2 \cdots a_i$。

**证明**：对 `add` 的次数归纳。初始 $P=[1]$，$L=0$，空乘积的约定成立。设当前成立，新增元素 $x$：若 $x = 0$，则新的最近 0 就是它，$L' = 0$，$P' = [1]$ 满足；若 $x \ne 0$，则 $L' = L+1$，$P'[L'] = P[L] \cdot x = a_1\cdots a_L x$，其余位置不变，仍满足。∎

**引理 2（整除性）**：当 $k \le L$ 时，$P[L-k] \mid P[L]$，且商恰为末 $k$ 个元素的乘积。

**证明**：由引理 1，$P[L] = (a_1\cdots a_{L-k}) \cdot (a_{L-k+1}\cdots a_L) = P[L-k] \cdot \prod_{i=L-k+1}^{L} a_i$。末 $k$ 个元素正是 $a_{L-k+1},\dots,a_L$（$k \le L$ 保证这些下标都存在），故商等于该乘积；又因每个 $a_i$ 为整数，商是精确整数。∎

**引理 3（含 0 判据）**：窗口「末 $k$ 个元素」中含有 0 当且仅当 $k > L$。

**证明**：最近一次 0 出现在倒数第 $L+1$ 个位置（其后恰有 $L$ 个元素，若从未出现 0 则无此位置，此时 $k \le L$ 恒成立且窗口无 0）。末 $k$ 个元素覆盖倒数第 $1$ 到第 $k$ 个位置，包含该 0 $\iff k \ge L+1 \iff k > L$。∎

**引理 4**：末 $k$ 个元素若含 0，其乘积为 0。

**证明**：乘积中有一个因子为 0，整数乘法结果为 0（其他因子均为非负，不影响）。∎

**定理**：`getProduct(k)` 返回的正是当前列表末 $k$ 个数的乘积，且 `add`、`getProduct` 均为 $O(1)$。

**证明**：由引理 3 分两种情形。若 $k > L$，窗口含 0，由引理 4 乘积为 0，算法返回 0，正确。若 $k \le L$，窗口不含 0，完全落在有效段内，由引理 2 商即为所求，算法返回 $P[L]/P[L-k]$，正确。复杂度方面：`add` 至多一次乘法与一次尾部追加，清空为整体重置；`getProduct` 至多一次比较与一次整数除法，故均为 $O(1)$。∎

## 6. 复杂度分析

- **`add` 时间**：$O(1)$ 均摊。正常分支是一次乘法加一次尾部追加（摊还 $O(1)$）；清空分支丢弃的元素都是先前被追加进来的，每个元素一生只被丢弃一次，因此全部 `add` 的丢弃总代价为 $O(q)$。
- **`getProduct` 时间**：$O(1)$，只做一次长度比较与一次整数除法，与 $k$ 无关。
- **总时间**：设调用共 $q$ 次，整体 $O(q)$，$q \le 4 \times 10^4$ 时几乎瞬时。
- **空间**：$O(L) \le O(q)$，即「最近一次 0 之后」的元素个数。最坏情况全为 1 时可存 $4 \times 10^4$ 个 `long long`，约 320 KB；一遇 0 立刻回收。

## 7. 参考代码

### C++

```cpp
class ProductOfNumbers {
public:
    ProductOfNumbers() {
        pref.assign(1, 1);          // 哨兵 P[0] = 1
    }

    void add(int num) {
        if (num == 0) {
            pref.assign(1, 1);      // 遇 0：整段作废，段长归零
        } else {
            pref.push_back(pref.back() * num);
        }
    }

    int getProduct(int k) {
        int len = static_cast<int>(pref.size()) - 1;   // 段长 L
        if (k > len) return 0;                         // 窗口跨过 0
        return static_cast<int>(pref[len] / pref[len - k]);
    }

private:
    std::vector<long long> pref;
};
```

### Python

```python
class ProductOfNumbers:

    def __init__(self):
        self.pref = [1]                 # 哨兵 P[0] = 1

    def add(self, num: int) -> None:
        if num == 0:
            self.pref = [1]             # 遇 0：整段作废，段长归零
        else:
            self.pref.append(self.pref[-1] * num)

    def getProduct(self, k: int) -> int:
        n = len(self.pref) - 1          # 段长 L
        if k > n:
            return 0                    # 窗口跨过 0
        return self.pref[n] // self.pref[n - k]
```

## 8. 边界情况与易错点

1. **`num = 0` 必须清空**：若只在 $P$ 末尾追加 $P[L]\cdot 0 = 0$，之后所有前缀积恒为 0，`getProduct` 全部返回 0，答案必错。
2. **$k = L$ 不能返回 0**：判据是 $k > L$ 而非 $k \ge L$。示例 1 的 `getProduct(3)`（$k = L = 3$）答案 40，就是专门用来区分这两种写法的。
3. **连续的 0**：清空是幂等的，`add(0)` 连打几次仍然是 $P=[1]$，不需要额外特判，也不会把段长算成负数。
4. **清空不彻底**：只把末尾元素改成 1、或用 `pop_back` 只弹一个，都会留下旧乘积，导致后续除法把「跨过 0 的窗口」误算成非零。
5. **C++ 溢出**：题面保证任何连续序列乘积在 32 位内，但 `pref.back() * num` 建议用 `long long` 承接，避免某些测试数据在乘积边界上擦枪走火。
6. **Python 的 `/`**：`/` 返回 `float`，乘积稍大就会丢精度（示例 1 虽小，但真实数据可能到 $2^{31}$），必须用 `//`。
7. **除零风险**：$P$ 中所有元素都 $\ge 1$（0 一出现就清空），所以 `pref[len - k]` 绝不为 0，不会触发除零；反过来说，如果实现里保留了 0，就会在这里崩。
8. **空流查询**：题目保证调用 `getProduct` 时列表长度 $\ge k \ge 1$，因此 $L \ge 1$；即使真的空流查询，$k > 0 = L$ 会返回 0，行为安全而非越界。
