# LeetCode 最多可以参加的会议数目 题解

## 1. 题目概述

- **标题 / 题号**：最多可以参加的会议数目（#1353，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-events-that-can-be-attended/
- **来源**：LeetCode 第 176 场周赛 Q3
- **难度**：中等
- **标签**：贪心，数组，排序，堆（优先队列）

**题意**：给定 $n$ 个会议，第 $i$ 个会议的时间区间是 $[startDay_i, endDay_i]$。对每个会议，你可以在区间内**任选一天**参加（只参加一次，不需要全程出席）；但**一天最多参加一场会议**。求最多能参加的会议数目。

换个说法：把每个会议看成一条数轴上的闭区间，把「第 $d$ 天」看成数轴上的整点 $d$，则本题就是求**区间与整点的最大匹配**——每条区间至多匹配一个落在它内部的整点，每个整点至多匹配一条区间。

**约束**：

- $1 \le n = events.length \le 10^5$
- $events[i].length == 2$
- $1 \le startDay_i \le endDay_i \le 10^5$

> 💡 注意约束里的 $10^5$：天数的上界也是 $10^5$，所以「按天扫描」是允许的；但区间长度之和可以到 $10^{10}$，**不能**把每个会议展开成「可参加的天列表」。

## 2. 示例

**示例 1**

```text
输入：events = [[1,2],[2,3],[3,4]]
输出：3
解释：三个会议可以全部参加：
      第 1 天参加 [1,2]，第 2 天参加 [2,3]，第 3 天参加 [3,4]。
      注意第 2 天既属于 [1,2] 也属于 [2,3]，区间端点重叠是可以的。
```

**示例 2**

```text
输入：events = [[1,2],[2,3],[3,4],[1,2]]
输出：4
解释：仍有办法全部参加：
      第 1 天参加第一个 [1,2]，第 2 天参加第二个 [1,2]（它到第 2 天还没过期），
      第 3 天参加 [2,3]，第 4 天参加 [3,4]。
```

**示例 3（补充，覆盖“长区间包围短区间”的情况）**

```text
输入：events = [[1,5],[1,5],[1,5],[2,3]]
输出：4
解释：把灵活的三个 [1,5] 尽量往后放（第 1、4、5 天），
      把最不灵活的 [2,3] 放在第 2 天，四场会议都能参加。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是「搜索每天参加哪一场」：第 $d$ 天枚举所有还没过期、还没参加的会议，递归下去。分支因子最大可达 $10^5$，状态数是指数级，完全不可行。

把它写成标准模型是**二分图最大匹配**：左侧 $n$ 个会议，右侧最多 $10^5$ 个「天」节点，会议 $i$ 与天 $d$ 连边当且仅当 $startDay_i \le d \le endDay_i$。最大匹配就是答案。但边数最坏是 $n \times 10^5 = 10^{10}$，连图都建不出来；即使是匈牙利算法也要 $O(VE)$。

> 💡 突破口：这是一张**区间—整点**的特殊二分图，具有强烈的「顺序结构」，不需要通用匹配算法，用**贪心扫描**即可。

### 3.2 核心观察：最早截止优先（EDF）

![最早截止优先贪心模型](images/wc176_q3_edf_greedy.svg)

按天从左到右扫描。在某一天 $d$，所有满足 $startDay_i \le d \le endDay_i$ 且尚未参加的会议都是**候选**。关键观察是：

> **当天有多个候选时，参加「结束最早」的那一个不会让答案变差。**

直觉：候选会议在**今天**都可用，区别只在「未来还能用到哪天」。结束更早的会议，未来可用天数的集合更小，是结束更晚者可用天数集合的子集（都从 $d$ 往右看）。先把「窗口快关了」的会议用掉，等于把更宽松的会议留给后面，显然更划算——这就是经典的**最早截止优先（Earliest Deadline First, EDF）**。

于是每天只需要做两件事：维护候选集合，取出 $endDay$ 最小的那一个。这正好是**小根堆**：堆里只存 $endDay$，把会议的开始时间交给扫描过程自然处理（第 $d$ 天把 $startDay = d$ 的会议入堆即可）。

### 3.3 算法流程

![按天扫描 + 小根堆流程](images/wc176_q3_scan_flow.svg)

1. 把所有会议按 $startDay$ 升序排序（$endDay$ 不参与排序）。
2. $day \leftarrow$ 所有 $startDay$ 的最小值，指针 $i \leftarrow 0$，小根堆 $H$ 为空，答案 $ans \leftarrow 0$。
3. 循环，直到「所有会议都入过堆」且「堆为空」：
   - **跳跃**：若堆为空且 $day < startDay_i$，说明今天没有任何候选，直接把 $day$ 跳到 $startDay_i$。
   - **入池**：把所有 $startDay \le day$ 的会议压入堆（只压 $endDay$）。
   - **清过期**：当堆顶 $endDay < day$ 时弹堆——这些会议彻底错过，必须丢弃（用 `while`，可能一次积压很多个）。
   - **参会**：若堆非空，弹出堆顶（$endDay$ 最小的会议）并令 $ans \leftarrow ans + 1$。
   - **前进**：$day \leftarrow day + 1$。
4. 返回 $ans$。

> ⚠️ 顺序不能乱：**先入池、再清过期、最后取最小**。若先取再清，可能取到一个已经过期的会议；若先清再入池，可能把今天刚开始的会议误当成不存在。

### 3.4 示例演算

以 `events = [[1,2],[2,3],[3,4],[1,2]]` 为例，逐天走查：

![示例演算表](images/wc176_q3_walkthrough.svg)

| 天 | 今日入池的 $endDay$ | 堆内容（取前，升序） | 今日参加 | 累计 $ans$ |
|----|--------------------|----------------|----------|------------|
| 1 | 2, 2 | $\{2, 2\}$ | 取 2 | 1 |
| 2 | 3 | $\{2, 3\}$ | 取 2 | 2 |
| 3 | 4 | $\{3, 4\}$ | 取 3 | 3 |
| 4 | — | $\{4\}$ | 取 4 | 4 |

第 1 天两个 $[1,2]$ 同时入堆，先随便用掉一个；第 2 天 $[2,3]$ 入堆后，堆顶仍是 $2$（快过期的那个），优先消费它；到第 4 天堆里只剩 $endDay = 4$，恰好今天可用。最终 $ans = 4$，等于会议总数，达到答案上界，必然最优。

## 4. 算法细节

1. **排序键**：只按 $startDay$ 升序；若 $startDay$ 相同，$endDay$ 的顺序**无关紧要**，因为同一天入堆后由堆统一按 $endDay$ 排序。
2. **堆里只存 $endDay$**：会议的身份对答案没有影响（每个会议只需要「参加一次」，不需要知道是哪一场），因此堆元素用 `int` 即可，省去存 `pair` 的开销。
3. **扫描起点**：$day$ 从最小的 $startDay$ 出发，而不是从 $1$ 出发，可以省掉前面必然无候选的空转。
4. **跳跃优化**：当堆为空而 $day$ 落后于下一个 $startDay_i$ 时，直接 $day \leftarrow startDay_i$。即使不做跳跃，天数上界 $10^5$ 也能过；但跳跃让循环次数与「有候选的连续天段」成正比，更稳健。
5. **过期清理用 `while`**：一批会议可能同时过期（例如 `[[1,1],[1,1],[1,1]]` 到第 2 天时一次过期 3 个），只弹一次会留下脏数据。
6. **终止条件**：`i == n && heap.empty()`。不能只判断 `i == n`，因为这时堆里可能还有会议没被安排；也不能只判断堆空，因为后面的会议还没入池。
7. **$day$ 的上界**：当 $day > \max endDay$ 时所有会议都已过期，可以直接 `break`，避免无谓迭代。
8. **Python 的 `heapq` 本身就是小根堆**，直接 `heappush/heappop`；C++ 的 `priority_queue` 默认是大根堆，必须写成 `priority_queue<int, vector<int>, greater<int>>`。

## 5. 正确性证明

**引理 1（候选堆不变式）**：在贪心处理完第 $d$ 天之后，记 $S_d$ 为「$startDay \le d$ 且 $endDay \ge d$ 且尚未被贪心参加」的会议集合，则堆中元素与 $S_d$ 中的 $endDay$ 构成多重集相等。

**证明**：对 $d$ 归纳。$d$ 取起始天时，$S_d$ 恰为所有 $startDay \le d$ 的会议，步骤「入池」把它们的 $endDay$ 全部压入堆，成立。设第 $d$ 天处理完后不变式成立，考察第 $d \to d+1$ 的那一轮迭代：① 入池把 $startDay = d+1$ 的新会议加入（$startDay \le d$ 的上一轮已全部入堆）；② 清过期删除所有 $endDay < d+1$ 的会议，由不变式这些正是 $endDay = d$ 的会议——恰为 $S_{d+1}$ 要排除的部分；③ 若参会，弹出的是 $endDay$ 最小的会议，它满足 $endDay \ge d+1$（否则已在 ② 被清掉），属于 $S_{d+1}$，被移除。三步合起来恰好把 $S_d$ 变成 $S_{d+1}$。∎

**推论 1**：若第 $d$ 天循环开始时堆为空，则第 $d$ 天**没有任何**会议可参加。

**证明**：堆空意味着所有 $startDay \le d$ 的会议都已过期（$endDay < d$），而 $startDay > d$ 的会议尚未开始，故第 $d$ 天无候选。∎

**引理 2（到期优先可交换）**：设贪心在第 $d$ 天选取了候选堆中 $endDay$ 最小的会议 $A$。则存在一个最优解，它在第 $d$ 天参加 $A$，并且在第 $1 \sim d-1$ 天的安排与贪心完全一致。

**证明**：由归纳假设，存在最优解在第 $1 \sim d-1$ 天与贪心一致（$d=1$ 时前缀为空，取任意最优解即可），在所有这些最优解中取一个。考察 $S$ 在第 $d$ 天的安排。

- 若 $S$ 第 $d$ 天空闲：若 $S$ 之后某天 $d' > d$ 参加了 $A$，把 $A$ 挪到第 $d$ 天（$A$ 在第 $d$ 天可用，因为它在候选堆中），$d'$ 空出，总数不变；若 $S$ 完全没参加 $A$，直接在第 $d$ 天加上 $A$，总数 $+1$，与 $S$ 最优矛盾。故此时可调整为第 $d$ 天参加 $A$。
- 若 $S$ 第 $d$ 天参加的是 $B \ne A$：由 $A$ 是堆中 $endDay$ 最小者，有 $endDay_A \le endDay_B$。若 $S$ 完全没参加 $A$，把 $B$ 换成 $A$，总数不变。若 $S$ 在第 $d'$ 天参加了 $A$：$d' < d$ 不可能，因为 $A$ 此刻还在候选堆里，说明贪心在 $d$ 之前从未参加 $A$，而 $S$ 在 $d$ 之前与贪心完全一致；故 $d' > d$。此时交换两者：$A$ 放到第 $d$ 天，$B$ 放到第 $d'$ 天。可行性：$A$ 在第 $d$ 天可用已证；$B$ 需要 $startDay_B \le d' \le endDay_B$，其中 $startDay_B \le d < d'$，且 $d' \le endDay_A \le endDay_B$，故成立。总数不变，且第 $d$ 天改为 $A$。
- $S$ 第 $d$ 天参加的正是 $A$：已满足。

三种情况都能把 $S$ 调整为在第 $d$ 天参加 $A$ 且前缀不变，引理得证。∎

**定理**：贪心返回的 $ans$ 等于最大可参加会议数 $opt$。

**证明**：贪心的每个选择都是一次合法的「一天一场」安排，因此 $ans \le opt$。另一方面，从空解出发，对 $d = 1, 2, \dots$ 反复应用引理 2：第 $d$ 天若堆非空，总能把某个最优解调整为与贪心在第 $d$ 天相同，而前缀不变；第 $d$ 天若堆为空，由推论 1 任何解在第 $d$ 天都无法安排会议，贪心与所有解一致。归纳到所有天，得到一个最优解与贪心逐天相同，故 $ans \ge opt$。两者结合得 $ans = opt$。∎

## 6. 复杂度分析

- **时间**：排序 $O(n \log n)$；每个会议恰好入堆一次、出堆至多两次（参会一次 + 过期一次），堆操作共 $O(n \log n)$；天循环最多跨越 $\max endDay - \min startDay + 1 \le 10^5$ 个不同的天；所有迭代里的入池与过期弹出合计至多 $O(n)$ 次堆操作。总计 $O(n \log n + D)$，其中 $D \le 10^5$ 为天数跨度。
- **空间**：堆最多同时容纳 $O(n)$ 个 $endDay$；排序若使用额外数组则为 $O(n)$，原地排序为 $O(\log n)$。总体 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxEvents(vector<vector<int>>& events) {
        sort(events.begin(), events.end());          // 只按 startDay 升序
        int n = events.size();
        priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆存 endDay
        int ans = 0, i = 0, day = events[0][0];
        int maxDay = 0;
        for (auto& e : events) maxDay = max(maxDay, e[1]);

        while (i < n || !pq.empty()) {
            if (pq.empty() && i < n && day < events[i][0]) {
                day = events[i][0];                  // 跳跃：今天没有候选
            }
            while (i < n && events[i][0] <= day) {   // 入池
                pq.push(events[i][1]);
                ++i;
            }
            while (!pq.empty() && pq.top() < day) {  // 清过期（可能一次多个）
                pq.pop();
            }
            if (!pq.empty()) {                       // 参加结束最早的一场
                pq.pop();
                ++ans;
            }
            ++day;
            if (day > maxDay) break;                 // 之后不可能再有候选
        }
        return ans;
    }
};
```

### Python

```python
from typing import List
import heapq


class Solution:
    def maxEvents(self, events: List[List[int]]) -> int:
        events.sort()                      # 只按 startDay 升序
        n = len(events)
        heap = []                          # 小根堆，只存 endDay
        ans = 0
        i = 0
        day = events[0][0]
        max_day = max(e for _, e in events)

        while i < n or heap:
            if not heap and i < n and day < events[i][0]:
                day = events[i][0]         # 跳跃：今天没有候选
            while i < n and events[i][0] <= day:      # 入池
                heapq.heappush(heap, events[i][1])
                i += 1
            while heap and heap[0] < day:             # 清过期
                heapq.heappop(heap)
            if heap:                                  # 参加结束最早的一场
                heapq.heappop(heap)
                ans += 1
            day += 1
            if day > max_day:
                break
        return ans
```

## 8. 边界情况与易错点

1. **只有一个会议**：`[[1,1]]` 与 `[[1,100000]]` 都应返回 $1$；代码里 `day` 从 `events[0][0]` 起步，天然覆盖。
2. **同一天到期的一批会议**：`[[1,1],[1,1],[1,1]]` 答案为 $1$。到第 2 天时三个会议同时过期，清过期必须用 `while`，否则堆里残留脏数据、后续统计出错。
3. **`day` 的跳跃与边界**：若堆为空且下一个 $startDay_i > day$，必须跳过去；否则要靠 $day$ 自增空转到 $10^5$，虽然能过，但一旦某天跨度更大就会 TLE。
4. **先入池后清过期的顺序**：反过来会漏掉「今天刚开始、今天结束」的会议（`start == end == day`），把它误判为过期。
5. **C++ 的大根堆陷阱**：`priority_queue<int>` 默认弹出**最大值**，本题必须写 `greater<int>` 才是最早结束优先；写反了样例 1 仍可能对，但随机数据会错。
6. **终止条件**：`i == n` 时堆可能非空（还有会议可安排），`heap.empty()` 时可能还有会议没入池；必须用「或」关系，且 `day > maxDay` 的提前退出不能漏。
7. **答案上界**：$ans \le \min(n, \text{可用天数})$，可以用它自检；示例 2、示例 3 都达到上界 $n$。
8. **区间端点相接**：`[1,2]`、`[2,3]` 共享第 2 天，这是**合法**的（会议只需在区间内任选一天，不是「占用整个区间」），不要误以为区间重叠就要扣减。

**延伸思考**：

1. 若每个会议有**权重**，要求参加会议的权重之和最大，贪心立刻失效，问题变成带权区间—整点匹配，需要最小费用最大流或「按天连边的费用流 + 线段树优化建图」。
2. 若**每天可以参加 $k$ 场**会议，只需把「每天弹一次堆」改成「每天弹至多 $k$ 次」，正确性证明中引理 2 的交换论证完全平行。
3. 若要求**输出具体安排**而不只是数目，可以在堆里存「$endDay$ + 会议下标」，出堆时记录「第 $d$ 天参加会议 $j$」，答案不变。
4. 另一种等价写法是「按 $endDay$ 排序 + 并查集找最近的空闲天」：对每个会议找一个 $\le endDay$ 且未占用的、$\ge startDay$ 的天。它与本解法是同一贪心的两种实现，复杂度同为 $O(n \log n)$，可以作为对拍的第二份实现。
