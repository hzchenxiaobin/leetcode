# LeetCode 相对名次 题解

## 1. 题目概述

- **标题 / 题号**：相对名次（#506，easy）
- **链接**：https://leetcode.cn/problems/relative-ranks/
- **来源**：LeetCode 第 18 场周赛 B 卷 Q5
- **难度**：简单
- **标签**：数组、排序、堆（优先队列）

**题意**：给定长度为 $n$ 的整数数组 `score`，`score[i]` 是第 $i$ 位运动员的得分，**所有得分互不相同**。名次由得分决定：得分最高者名次为 $1$，次高者名次为 $2$，依次类推。名次对应的获奖字符串为：

- 名次 $1$ → `"Gold Medal"`
- 名次 $2$ → `"Silver Medal"`
- 名次 $3$ → `"Bronze Medal"`
- 名次 $x \ge 4$ → 名次编号的字符串形式 `"x"`

要求返回长度为 $n$ 的数组 `answer`，`answer[i]` 是第 $i$ 位运动员的获奖情况——**输出顺序必须与原数组下标顺序一致**，而不是名次顺序。

**约束**：

- $n = \lvert \texttt{score} \rvert$，$1 \le n \le 10^4$
- $0 \le \texttt{score}[i] \le 10^6$
- `score` 中所有值互不相同（因此名次唯一，不存在并列）

## 2. 示例

**示例 1**

```text
输入：score = [5,4,3,2,1]
输出：["Gold Medal","Silver Medal","Bronze Medal","4","5"]
解释：数组本身已降序，名次依次为 1、2、3、4、5；
      前 3 名换成奖牌单词，第 4、5 名保留数字字符串。
```

**示例 2**

```text
输入：score = [10,3,8,9,4]
输出：["Gold Medal","5","Bronze Medal","Silver Medal","4"]
解释：名次依次为 1、5、3、2、4：
      i=0 得 10 分 → 第 1 名 → Gold Medal
      i=1 得 3 分  → 第 5 名 → "5"
      i=2 得 8 分  → 第 3 名 → Bronze Medal
      i=3 得 9 分  → 第 2 名 → Silver Medal
      i=4 得 4 分  → 第 4 名 → "4"
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：对每个 $i$，再扫一遍整个数组，统计有多少个 `score[j]` 严格大于 `score[i]`，名次就是「比它大的人数 $+1$」。

```text
for i in 0..n-1:
    rank = 1 + count(score[j] > score[i])
    answer[i] = medal(rank)
```

每次统计 $O(n)$，总计 $O(n^2)$。$n = 10^4$ 时是 $10^8$ 次比较：C++ 勉强能过，Python 必然超时。

另一种「看起来不同」的暴力是：反复在未处理元素中找最大值，找到一次填一个位置，重复 $n$ 轮——同样是 $O(n^2)$，而且常数更大。

**瓶颈在于信息复用**：每个人「有多少人比他强」这件事，本质上是**一次全局排序**就能一次性算出来的，不必对每个人重复扫描。

### 3.2 核心观察：排序定名次，下标回填顺序

![排序定名次、下标回填](images/wc18_q5_rank_concept.svg)

关键观察有两条：

1. **名次就是降序排列中的位置**。由于所有得分互不相同，把 `score` 从大到小排好，第 $r$ 个（从 $0$ 开始数）元素的名次恰好是 $r + 1$。一次排序，$n$ 个名次全部确定。
2. **输出要按原下标顺序**。所以排序时不能只排数值，必须把「原下标」一起带上：对下标数组 `idx` 按 `score[idx]` 降序排序，则 `idx[r]` 就是「名次第 $r+1$ 的人原来站在哪」。

于是把这两条拼起来，就得到答案的写法：

$$\texttt{answer}\bigl[\texttt{idx}[r]\bigr] = \begin{cases} \text{奖牌}[r] & r < 3 \\ \operatorname{str}(r+1) & r \ge 3 \end{cases}$$

其中 $\text{奖牌} = [\texttt{"Gold Medal"},\ \texttt{"Silver Medal"},\ \texttt{"Bronze Medal"}]$。

这样每个下标恰好被写一次，天然还原了原始顺序，**不需要事后查找或建立「得分 → 名次」的哈希表**（当然建立也可以，见 §4 第 6 条）。

> 💡 **一句话**：排序负责「定名次」，下标数组负责「把名次送回原位」。

### 3.3 算法流程

![算法流程：排下标 → 定名次 → 回填](images/wc18_q5_algorithm_flow.svg)

```text
1. 令 n = len(score)，构造 idx = [0, 1, ..., n-1]
2. 对 idx 排序，关键字为 score[idx] 降序：
       sort(idx, key = lambda i: -score[i])
3. 令奖牌数组 M = ["Gold Medal", "Silver Medal", "Bronze Medal"]
4. 初始化 answer = [""] * n
5. 枚举 r = 0, 1, ..., n-1：
       answer[idx[r]] = M[r]       若 r < 3
       answer[idx[r]] = str(r + 1) 否则
6. 返回 answer
```

核心循环只有 $O(n)$，排序是唯一的时间瓶颈。

### 3.4 示例演算

以 `score = [10, 3, 8, 9, 4]` 走一遍，先看降序排序的结果，再把名次按原下标写回去：

| 排名位置 $r$ | 得分 | 原下标 `idx[r]` | 写入 `answer[idx[r]]` |
|---|---|---|---|
| 0 | 10 | 0 | `Gold Medal` |
| 1 | 9 | 3 | `Silver Medal` |
| 2 | 8 | 2 | `Bronze Medal` |
| 3 | 4 | 4 | `"4"` |
| 4 | 3 | 1 | `"5"` |

按原下标整理后即得 `["Gold Medal","5","Bronze Medal","Silver Medal","4"]`，与官方示例一致。

![示例演算：回填到原下标](images/wc18_q5_walkthrough.svg)

## 4. 算法细节

1. **为什么排下标而不是排 `(score, index)` 对**：两种写法等价，但对下标排序不需要额外构造二元组、也不改动原数组；C++ 用 `iota` + `sort` 配 lambda，Python 用 `sorted(range(n), key=...)`，都是 $O(n)$ 额外空间。
2. **降序的两种写法**：可以直接比较器写 `score[a] > score[b]`，也可以升序排序后令 $r \leftarrow n-1-r$ 再取值。前者可读性更好，推荐前者。
3. **奖牌只发前三**：不要硬编码 `answer[order[2]] = "Bronze Medal"`——当 $n < 3$ 时会越界。统一用「$r < 3$ 取奖牌表、否则取数字」的判据，$n = 1, 2, 3$ 全部自动正确。
4. **`str(r + 1)` 而不是 `str(r)`**：$r$ 是 $0$ 起始的排名位置，名次是 $1$ 起始的，差一位是最常见的笔误。C++ 用 `to_string(r + 1)`。
5. **不要原地排序 `score`**：排序后 `score[i]` 的语义就变了，原始下标信息丢失，后面的回填无从下手；若坚持要排数值，必须同时记录「排序后第 $r$ 个值原来的下标」。
6. **堆 / 优先队列方案**：把 `(score[i], i)` 全部压入大顶堆，反复 `pop` 弹出得分最高者，弹出次序就是名次。复杂度 $O(n \log n)$，与排序同阶但常数更大，适合只想取前 $k$ 名的变体（取满 $k$ 名即可提前结束）。
7. **值域计数方案**：得分上界 $10^6$ 固定，可以开一个长度为 $10^6 + 1$ 的桶，从大到小扫描桶，遇到非空就把该得分对应的下标依次编号，复杂度 $O(n + V)$、$V = 10^6$。本题 $n \le 10^4$，排序更简单也更省空间，计数法只在 $V$ 与 $n$ 同阶时才有优势。
8. **输出的字符串语义**：`"Gold Medal"` 等是题目规定的字面量，注意大小写与空格（`Gold Medal` 而不是 `GoldMedal`）；数字名次必须转成字符串，不能直接塞整数。

## 5. 正确性证明

**引理 1（名次 = 降序位置 + 1）**：设 `idx` 是 `score` 的下标按得分严格降序排列所得的序列，则对任意 $0 \le r < n$，运动员 `idx[r]` 的名次恰为 $r + 1$。

**证明**：由排序定义，对任意 $r' < r$ 有 $\texttt{score}[\texttt{idx}[r']] > \texttt{score}[\texttt{idx}[r]]$，即名次在 `idx[r]` 之前的运动员至少有 $r$ 位；又对任意 $r'' > r$ 有 $\texttt{score}[\texttt{idx}[r'']] < \texttt{score}[\texttt{idx}[r]]$，故得分严格高于它的运动员恰好就是 `idx[0..r)` 这 $r$ 位。名次定义为「得分严格高于自己的人数 $+1$」，所以名次为 $r + 1$。∎

**引理 2（取值函数覆盖且互斥）**：对任意名次 $1 \le \text{rank} \le n$，算法给出的字符串恰为题目要求的字符串。

**证明**：名次 $\text{rank}$ 对应 $r = \text{rank} - 1$。若 $\text{rank} \le 3$，即 $r < 3$，算法取奖牌表的第 $r$ 项，分别是 Gold / Silver / Bronze Medal，与题目对第 $1, 2, 3$ 名的规定一致；若 $\text{rank} \ge 4$，即 $r \ge 3$，算法取 $\operatorname{str}(r + 1) = \operatorname{str}(\text{rank})$，与题目对第 $4$ 名及以后的规定一致。两种情况以 $r = 3$ 为界，互斥且完备。∎

**定理**：算法返回的 `answer` 与题目要求完全一致。

**证明**：循环枚举 $r = 0, 1, \dots, n-1$，每个 $r$ 执行一次赋值 `answer[idx[r]] = ...`。由于 `idx` 是 $0..n-1$ 的一个排列，每个下标恰好被赋值一次，因此循环结束后 `answer` 无空位、无遗漏。对任意下标 $i$，设 $r$ 满足 $\texttt{idx}[r] = i$；由引理 1，$i$ 的名次为 $r + 1$，再由引理 2，写入的字符串恰为该名次对应的获奖情况。故 `answer[i]` 正确，对全部 $i$ 成立。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。构造下标数组 $O(n)$；排序 $O(n \log n)$ 是主导项；回填一遍 $O(n)$ 并做 $O(1)$ 的字符串赋值。$n = 10^4$ 时排序约 $1.3 \times 10^5$ 次比较，可忽略。
- **空间**：$O(n)$。`idx` 与 `answer` 各 $n$ 个槽位；C++ 的 `sort` 递归栈 $O(\log n)$；奖牌表为常数 $3$。字符串本身长度有上界（最长 `"Bronze Medal"` 12 个字符、数字最多 5 位），可视为常数。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <numeric>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> findRelativeRanks(vector<int>& score) {
        int n = (int)score.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);          // idx = [0, 1, ..., n-1]
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return score[a] > score[b];           // 按得分从大到小，等价于名次从 1 开始
        });
        const string medal[3] = {"Gold Medal", "Silver Medal", "Bronze Medal"};
        vector<string> ans(n);
        for (int r = 0; r < n; ++r) {
            // idx[r] 原来的位置就是答案的下标，r + 1 才是名次
            ans[idx[r]] = (r < 3) ? medal[r] : to_string(r + 1);
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findRelativeRanks(self, score: List[int]) -> List[str]:
        n = len(score)
        # 按得分从高到低排列「下标」，而不是直接排分数
        order = sorted(range(n), key=lambda i: -score[i])
        ans = [""] * n
        medals = ("Gold Medal", "Silver Medal", "Bronze Medal")
        for rank, idx in enumerate(order, start=1):
            # rank 从 1 开始，前三名换成奖牌，其余写成数字字符串
            ans[idx] = medals[rank - 1] if rank <= 3 else str(rank)
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有一个人，直接 `"Gold Medal"`。若代码里先写 `ans[idx[1]]` 之类的固定下标就会越界。
2. **$n = 2$**：没有铜牌，只有 Gold / Silver；硬编码三块奖牌的写法在此处崩溃。
3. **$n = 3$**：恰好把三块奖牌发完，$r = 0,1,2$ 都落在 `r < 3` 分支，第 4 名之后的分支一次都不进入。
4. **名次与下标差 1**：输出 `str(r)` 会得到 `"0"`、`"3"` 这样的错值，正确写法是 `str(r + 1)`；同理奖牌表用 `r` 索引、数字用 `r + 1`。
5. **丢失原始顺序**：直接把 `score` 原地排序（`score.sort()`）后再按下标填答案，得到的顺序是名次顺序而非原顺序，这是本题最容易踩的坑。必须排**下标**或**二元组**。
6. **字符串字面量细节**：必须是 `"Gold Medal"`（中间有空格、首字母大写）；第 4 名要输出 `"4"` 而不是 `"4th"`、`"No.4"`。
7. **并列得分（题目保证不会出现，但变体要小心）**：若得分可重复，则「名次 = 更高分人数 + 1」会自然产生并列（如 $1,1,3$），此时按 `idx` 顺序回填仍然正确，但奖牌归属需要额外约定。
