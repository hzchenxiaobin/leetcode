# LeetCode IPO 题解

## 1. 题目概述

- **标题 / 题号**：IPO（#502，hard）
- **链接**：https://leetcode.cn/problems/ipo/
- **来源**：LeetCode 第 18 场周赛 A 卷 Q3
- **难度**：困难
- **标签**：贪心，数组，排序，堆（优先队列）

**题意**：有 $n$ 个项目，第 $i$ 个项目有纯利润 $\text{profits}[i]$，且只有当**当前资本** $w \ge \text{capital}[i]$ 时才能启动它；启动并完成后，利润**立即累加**到资本中。初始资本为 $w$，最多完成 $k$ 个**不同**项目，求最终能获得的**最大资本**。

注意两点：项目做完就消失（"不同项目"）；利润 $\ge 0$，所以资本**只增不减**，这让"解锁"具有单调性——正是贪心的抓手。

**约束**：

- $1 \le k \le 10^5$
- $0 \le w \le 10^9$
- $1 \le n \le 10^5$，$n = \lvert \text{profits} \rvert = \lvert \text{capital} \rvert$
- $0 \le \text{profits}[i] \le 10^4$
- $0 \le \text{capital}[i] \le 10^9$
- 答案保证在 32 位有符号整数范围内

## 2. 示例

**示例 1**

```text
输入：k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]
输出：4
解释：初始资本 0，只能启动项目 0（capital = 0），完成后资本变 1；
      此时项目 1、2 都解锁（capital = 1），最多再做 1 个，
      显然做利润 3 的项目 2 更划算，资本变 1 + 3 = 4。
```

**示例 2**

```text
输入：k = 3, w = 0, profits = [1,2,3], capital = [0,1,2]
输出：6
解释：做项目 0 → 资本 1；做项目 1 → 资本 3；做项目 2 → 资本 6。
      三轮都做满，收益全部拿到。
```

## 3. 解题思路

### 3.1 暴力思路

每轮枚举所有还没做过的项目，挑出 $\text{capital}[i] \le w$ 里利润最大的那个，做完继续。**策略是对的**，但每轮扫一遍全部项目，复杂度 $O(nk)$；$n = k = 10^5$ 时是 $10^{10}$ 次比较，必然超时。

若再考虑"枚举所有选取顺序"的搜索，规模更是 $O(n^{\underline{k}})$，完全不可行。

所以问题只剩一个：**如何在一堆已解锁的项目里快速取出利润最大值**。

### 3.2 核心观察：可做集合单调不减 ⇒ 每轮取利润最大的可行项目

![IPO 贪心核心观察](images/wc18_q3_greedy_concept.svg)

关键性质：**利润非负 ⇒ 资本单调不减 ⇒ 项目一旦解锁就永远可用**。

- 项目 $j$ 在资本 $w$ 时可行，即 $\text{capital}[j] \le w$；
- 做任何项目后资本变为 $w + p \ge w$（因为 $p \ge 0$），于是 $\text{capital}[j] \le w \le w + p$，项目 $j$ 依然可行。

这说明**每一轮的候选集合只会变大、不会变小**，做项目不会"破坏"后续选择——不像背包问题那样存在容量冲突。既然候选集合固定（或更大），当前这轮当然应该拿利润最大的那个：

$$p_t = \max\{\, \text{profits}[j] \;:\; j \text{ 未做过},\ \text{capital}[j] \le w_t \,\}$$

而"取出已解锁项目中的最大利润"正好是**大顶堆**的标准操作。于是：

1. 把项目按 `capital` **升序排序**；
2. 用一个**只前进的指针** $i$ 把 $\text{capital}[i] \le w$ 的项目依次压入大顶堆（每个项目至多入堆一次）；
3. 每轮弹出堆顶、累加到 $w$。

### 3.3 算法流程

![IPO 算法流程图](images/wc18_q3_algorithm_flow.svg)

- **排序**：`projects = sorted(zip(capital, profits))`，保证解锁顺序与指针前进方向一致。
- **解锁**：`while i < n and projects[i].capital <= w`：入堆、`i++`。指针永不回退，全局总入堆次数 $\le n$。
- **贪心**：`w += pop_max(heap)`，执行至多 $k$ 轮。
- **提前结束**：若某一轮解锁后堆为空，说明**当前资本下已经没有未做过且可启动的项目**，再做任何操作都不会让 $w$ 变大，直接返回 $w$。

### 3.4 示例演算

以示例 1（`k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]`）走一遍：

![IPO 示例演算](images/wc18_q3_walkthrough.svg)

| 阶段 | 本轮新解锁（$\text{capital} \le w$） | 堆（大顶堆） | 弹出 | $w$ 变为 |
|------|------------------------------|--------------|------|----------|
| 初始 | 项目 0（cap 0, profit 1） | $[1]$ | — | 0 |
| 第 1 轮 | 无 | $[1]$ | 1 | 1 |
| 第 2 轮 | 项目 1（profit 3）、项目 2（profit 2） | $[3,2]$ | 3 | 4 |

$k = 2$ 用尽，最终资本 $0 + 1 + 3 = 4$。

对照反例：若第 2 轮按"编号小"优先，会拿走利润 2 的项目 2，终值只有 $0+1+2 = 3$ —— **贪心的关键就在"利润最大"这一条**。

## 4. 算法细节

1. **排序键的选择**：把 `(capital[i], profits[i])` 打包成 pair 按第一关键字升序（第二关键字无所谓）。排序后"可解锁"的项目天然是一段前缀，于是单指针扫描即可。
2. **堆里只存利润**：一旦项目解锁，它的 `capital` 就再也不会成为障碍，堆中只需保留 `profits[i]`；C++ 用 `priority_queue<int>`（默认大顶堆），Python 用 `heapq` 存**负数**模拟大顶堆。
3. **指针 $i$ 绝不回退**：每个项目入堆至多一次，这是 $O(n \log n)$ 而非 $O(nk)$ 的根本原因；不要写成"每轮从头扫一遍"。
4. **循环轮数**：`for step in range(k)`，$k$ 可能远大于 $n$；堆空时 `break` 是唯一需要的剪枝，无需特判 $k > n$。
5. **为什么 `break` 是安全的**：堆空 $\iff$ 没有「未做过且 $\text{capital} \le w$」的项目。此时 $w$ 不可能再增加（利润非负、无项目可做），后续轮次只会原地不动，直接返回即可。
6. **利润为 0 的项目**：堆顶可能是 0，弹出后 $w$ 不变，但项目被消耗掉，循环仍严格推进（每轮必然弹出一个元素或 break），不会死循环。
7. **数值范围**：$w$ 上界为 $10^9 + 10^5 \times 10^4 = 2 \times 10^9$，虽仍落在 `int` 范围内（$2^{31}-1 \approx 2.15\times10^9$），C++ 中建议中间量用 `long long`、返回时再转 `int`，避免边界上翻车。
8. **不变量**：循环每轮开始时，堆中恰好是「所有满足 $\text{capital} \le w$ 且尚未做过的项目」的利润集合；由于指针已扫过的项目都已入堆，未扫过的都满足 $\text{capital} > w$，这个等价关系始终成立。

## 5. 正确性证明

**引理 1（解锁单调）**：若项目 $j$ 在资本 $w$ 时可行（$\text{capital}[j] \le w$），则在之后任意时刻资本 $w' \ge w$ 时它仍可行，只要它还没被做掉。

**证明**：每完成一个项目，资本增加 $\text{profits}[i] \ge 0$，故 $w$ 单调不减；$w' \ge w \ge \text{capital}[j]$，由可行定义即得。∎

**引理 2（交换不降收益）**：设某方案的第 $t$ 步做了项目 $q$，当时资本为 $w$；若另有**尚未做过**的项目 $p$ 满足 $\text{capital}[p] \le w$ 且 $\text{profits}[p] \ge \text{profits}[q]$，则把该方案中「做 $p$」与「做 $q$」两步对调（若该方案根本没做 $p$，就把 $q$ 换成 $p$），所得方案仍合法，且最终资本不减。

**证明**：设 $p$ 在该方案中第 $s$ 步被做，$s > t$。对调后第 $t$ 步做 $p$：由 $\text{capital}[p] \le w$ 可知可行，合法；该步结束时资本为 $w + \text{profits}[p] \ge w + \text{profits}[q]$，差值 $\Delta = \text{profits}[p] - \text{profits}[q] \ge 0$。

- 对 $t < r < s$ 的每一步：新方案与旧方案做同一个项目，且由于 $\Delta \ge 0$ 一直保持，每一步开始时的资本都不低于旧方案——旧方案可行，新方案必然也可行。
- 第 $s$ 步改做 $q$：此刻资本 $\ge w \ge \text{capital}[q]$，可行。

新方案做过的项目集合与旧方案完全相同，故最终资本相同，不减。

若该方案不做 $p$：直接在第 $t$ 步把 $q$ 换成 $p$，其后每一步资本都增加 $\Delta \ge 0$，可行性只增不减，最终资本增加 $\Delta \ge 0$。∎

**引理 3（堆空即死局）**：若算法在某轮开始时堆为空、当前资本为 $w$，则不存在尚未做过且 $\text{capital} \le w$ 的项目；从而任何资本 $w' \le w$ 的方案也无法再启动新项目。

**证明**：指针把所有 $\text{capital} \le w$ 的项目都压入过堆（未入堆的项目必然 $\text{capital} > w$）；堆空说明这些项目又全部被弹出，即全部已完成。对 $w' \le w$，集合 $\{\text{capital} \le w'\} \subseteq \{\text{capital} \le w\}$，其中项目都已完成，故无可启动的项目。∎

**定理**：算法返回的资本是"至多 $k$ 个项目"约束下的最大资本。

**证明**：先对轮次 $t = 0,1,\dots$ 归纳证明：算法执行完第 $t$ 轮（未提前返回）后的资本 $W_t$ 不小于任何方案执行完 $t$ 轮后的资本 $V_t$。

- 基础：$t = 0$ 时二者都是初始资本 $w$。
- 归纳：设 $W_{t-1} \ge V_{t-1}$。算法的候选集是 $\{\text{capital} \le W_{t-1}\}$ 中尚未做过的项目，包含该方案的候选集 $\{\text{capital} \le V_{t-1}\}$，故算法本轮取到的最大利润 $\ge$ 该方案本轮所取利润，于是 $W_t = W_{t-1} + p_t \ge V_{t-1} + q_t = V_t$。

再由引理 2，把最优方案中"与算法本轮不同的选择"逐步对调成算法的选择，收益不减，故存在最优方案在算法执行的每一轮里都做同一个项目——这保证"每轮取最大利润"不会错过最优解。

最后分两种收尾：

- **做满 $k$ 轮**：由 $W_k \ge V_k$（任何方案做 $k$ 轮），算法值已是不低于任何方案的值；而算法每轮弹出的项目在入堆时满足 $\text{capital} \le$ 当时资本，此后资本只增，故弹出时仍可行，算法输出本身是合法方案的值。两侧夹逼即得最优。
- **第 $t$ 轮堆空提前返回**：由归纳 $W_t = w \ge V_t$，又由引理 3 任何资本 $\le w$ 的方案都无法再启动项目，故其他方案的最终资本也不超过 $w$，返回 $w$ 仍最优。∎

## 6. 复杂度分析

- **时间**：$O(n \log n + k \log n)$。
  - 排序 $O(n \log n)$；
  - 指针扫描总计 $O(n)$，每个项目入堆一次，每次 $O(\log n)$，合计 $O(n \log n)$；
  - 堆弹出至多 $\min(k, n)$ 次，每次 $O(\log n)$，合计 $O(k \log n)$。
- **空间**：$O(n)$。`(capital, profit)` 数组 $O(n)$，大顶堆最坏存下全部 $n$ 个项目，$O(n)$；不计输入本身。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findMaximizedCapital(int k, int w, vector<int>& profits, vector<int>& capital) {
        int n = profits.size();
        vector<pair<int, int>> projects(n);              // {capital, profit}
        for (int i = 0; i < n; i++) projects[i] = {capital[i], profits[i]};
        sort(projects.begin(), projects.end());          // 按启动资本升序

        priority_queue<int> pq;                          // 大顶堆：已解锁项目的利润
        int i = 0;
        long long cur = w;
        for (int step = 0; step < k; step++) {
            while (i < n && projects[i].first <= cur) {
                pq.push(projects[i].second);
                i++;
            }
            if (pq.empty()) break;                       // 无可解锁项目，提前结束
            cur += pq.top();
            pq.pop();
        }
        return (int)cur;
    }
};
```

### Python

```python
import heapq


class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: list[int], capital: list[int]) -> int:
        n = len(profits)
        # 按启动资本升序排序，双指针扫描「当前已解锁」的项目
        projects = sorted(zip(capital, profits))
        heap = []          # 大顶堆（存负数）
        i = 0
        for _ in range(k):
            while i < n and projects[i][0] <= w:
                heapq.heappush(heap, -projects[i][1])
                i += 1
            if not heap:
                break      # 没有可解锁项目，资本不再增长
            w += -heapq.heappop(heap)
        return w
```

> 💡 注意 `cur` 用 `long long`：$10^9 + 10^5 \times 10^4 = 2 \times 10^9$ 恰好逼近 `int` 上界，虽然本题数据保证答案在 32 位内，但用宽类型零成本。

## 8. 边界情况与易错点

1. **所有项目都启动不了**：如 `k=1, w=0, profits=[1], capital=[5]`，第一轮堆就是空的，必须返回 $w$ 而不是 `INT_MIN` 或 0——初值直接用 $w$，天然正确。
2. **`k` 远大于 `n`**：$k = 10^5$、$n = 1$ 时循环第 2 轮就堆空 `break`。若忘了 `break`，会空转 $10^5$ 次（答案不会错，但白费时间）；若在堆空时仍 `pq.top()`，则直接 UB / 崩溃。
3. **利润为 0**：$\text{profits}[i] = 0$ 时堆顶可能是 0，弹出后资本不变。这是合法操作，仍然消耗一个轮次和一个项目，不会死循环（每轮必弹一个）。
4. **不能只按利润排序取前 $k$ 个**：反例 `k=1, w=0, profits=[3,100], capital=[0,5]`，全局利润最大的是 100，但根本启动不了，只能拿 3。资本约束使"利润大小"必须与"可行性"绑定。
5. **也不能只按资本排序做前 $k$ 个可做的**：`k=2, w=0, profits=[1,1,100], capital=[0,0,1]`，若先做两个利润 1 的项目，就错过了利润 100；正确做法是每轮都在候选里取利润最大的。
6. **指针重复扫描导致退化**：把"解锁"写成每轮 `for j in range(n)` 重新判断 `capital[j] <= w`，复杂度退化为 $O(nk) = 10^{10}$，Python 必超时。
7. **Python 大顶堆写法**：`heapq` 是小顶堆，必须存 `-profits[i]`，弹出后取负；`-0 == 0` 无副作用。
8. **原地修改输入**：`sorted(zip(capital, profits))` 不会改动入参；若在 C++ 里直接对 `capital`、`profits` 排序，必须**同步交换**两个数组，否则项目与利润错配。

**延伸思考**：

1. 如果项目**可以重复做**，结论会退化成"每次都做当前可行项里利润最大的那个"，甚至在最优点上反复做同一个项目，只需把「弹出堆顶」改成「只读堆顶」即可，其余完全不变。
2. 如果利润可以为**负**，引理 1 的单调性失效（做完资本可能变小），问题立刻变得复杂：此时需要同时记录"资本下界"与"已完成集合"，典型做法是状压 DP 或带剪枝的搜索。
3. 如果每个项目有**工期/依赖**（做完 A 才能做 B），这就是"带资本约束的项目调度"，属于 NP-hard，需要整数规划或近似算法——本题的贪心之所以成立，完全依赖"利润非负 + 无依赖 + 无容量上限"这三个前提。
