# LeetCode 下一个更大元素 II 题解

## 1. 题目概述

- **标题 / 题号**：下一个更大元素 II（#503，medium）
- **链接**：https://leetcode.cn/problems/next-greater-element-ii/
- **来源**：LeetCode 第 18 场周赛 B 卷 Q6
- **难度**：中等
- **标签**：栈、数组、单调栈

**题意**：给定**循环数组** `nums`（最后一个元素的下一个是 `nums[0]`），对每个下标 $i$ 求「按遍历顺序、在 $i$ 之后出现的第一个严格大于 `nums[i]` 的数」，搜索可以绕圈，不存在则填 $-1$。返回等长的答案数组。

**约束**：

- $1 \le \text{nums.length} \le 10^4$
- $-10^9 \le \text{nums}[i] \le 10^9$
- 元素可重复、可为负数，因此「更大」必须是**严格**大于

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,1]
输出：[2,-1,2]
解释：第一个 1 的下一个更大数是 2；
      数字 2 绕一整圈都找不到更大的数，填 -1；
      第二个 1 需要循环搜索，下一个更大数同样是 2。
```

**示例 2**

```text
输入：nums = [1,2,3,4,3]
输出：[2,3,4,-1,4]
解释：每个 3 都能在后面（必要时绕圈）找到 4；
      而最大值 4 在整圈中无人能超越，填 -1。
```

**示例 3（补充，单调递减）**

```text
输入：nums = [5,4,3,2,1]
输出：[-1,-1,-1,-1,-1]
解释：整体严格递减，绕圈后每个数的后面都只有更小的数，全部无解。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$，向后枚举步长 $k = 1, 2, \dots, n-1$，检查 `nums[(i+k) % n]` 是否大于 `nums[i]`，遇到即停，扫完一圈仍没有则填 $-1$。

时间复杂度 $O(n^2)$：$n = 10^4$ 时约 $10^8$ 次比较，Python 必然超时，C++ 也只是勉强擦线；而且大量比较是重复的——`[1,2,3,4,3]` 中每个 3 都要重新扫一遍同样的后缀。

### 3.2 核心观察：环形展开 + 单调栈

![环形数组展开成两倍长度](images/wc18_q6_circular_expand.svg)

**观察一：环形搜索 = 在「复制一遍」的数组上做线性搜索。**

把 `nums` 接到自己后面得到 $A = \text{nums} \oplus \text{nums}$，那么 $i$ 的答案就是 $A$ 中 $i$ 右侧**第一个**严格更大的值。而任何元素的下一个更大元素如果存在，与它的距离不超过 $n-1$，所以只需看展开后的前 $2n-1$ 个位置（下标 $0 \sim 2n-2$）就足够，第二圈的尾巴无需真正构造。

**观察二：单调栈把「找右侧第一个更大值」压到摊还 $O(1)$。**

维护一个存**下标**的栈，保证栈内自底向顶对应的值**单调不增**。扫描到位置 $j$（值为 `nums[j]`）时：

- 栈顶对应值若**严格小于** `nums[j]`，说明栈顶的「右侧第一个更大值」就是它——立即结算 `ans[栈顶] = nums[j]` 并弹出；重复此过程直到栈顶不小于 `nums[j]`；
- 然后把 $j$ 压栈，等待后面的元素来结算它。

**为什么弹出时拿到的一定是「第一个」更大值**：假设栈顶 $p$ 与 $j$ 之间存在位置 $k$ 使 `nums[k] > nums[p]`，那么 $k$ 入栈时 $p$ 还在栈中且比 `nums[k]` 小，$p$ 早在 $k$ 那一步就被弹走了，矛盾。这条性质是整道题的灵魂，3.3 与第 5 节会反复用到。

### 3.3 算法流程

![单调栈流程](images/wc18_q6_stack_flow.svg)

```text
ans[0..n-1] ← -1 ；st ← 空栈
for i = 0 .. 2n-2:
    j ← i mod n
    while st 非空 且 nums[st.top] < nums[j]:
        ans[st.top] ← nums[j]
        st.pop()
    if i < n:                 # 第二圈只触发结算，不再入栈
        st.push(j)
return ans
```

三个关键点：

1. **扫描长度** $2n-1$ 而不是 $2n$：$2n-2$ 已经是「距离 $n-1$ 的跨边界最大值」的最远落点。
2. **第二圈不入栈**：每个下标只需要入栈一次；若第二圈重复压入同一下标，它的答案可能被更靠后、更大但并不「最近」的值覆盖。
3. **结算发生在入栈之前**：先清空所有能被当前值超越的栈顶，再压入自己，栈的单调性才得以维持。

### 3.4 示例演算

![示例演算：nums = [1,2,3,4,3]](images/wc18_q6_walkthrough.svg)

以 `nums = [1,2,3,4,3]`（$n=5$）为例，扫描 $i=0 \sim 8$：

| $i$ | $j$ | `nums[j]` | 结算动作 | 栈（底→顶） |
|-----|-----|-----------|----------|-------------|
| 0 | 0 | 1 | 栈空，无结算 | [0] |
| 1 | 1 | 2 | `ans[0] = 2`，弹出 0 | [1] |
| 2 | 2 | 3 | `ans[1] = 3`，弹出 1 | [2] |
| 3 | 3 | 4 | `ans[2] = 4`，弹出 2 | [3] |
| 4 | 4 | 3 | $4 \ge 3$，不弹，压入 4 | [3, 4] |
| 5 | 0 | 1 | $3 \ge 1$，第二圈不入栈 | [3, 4] |
| 6 | 1 | 2 | $3 \ge 2$，第二圈不入栈 | [3, 4] |
| 7 | 2 | 3 | $3 \ge 3$（相等不算更大） | [3, 4] |
| 8 | 3 | 4 | `ans[4] = 4`，弹出 4 | [3] |

扫描结束得到 `ans = [2,3,4,-1,4]`：下标 3 对应的值 4 是全局最大值，始终没被弹走，保持 $-1$，与官方输出一致。注意下标 4 的答案正是在第二圈的 $i=8$（$j=3$）处回填的——这就是「循环」在算法里的具体体现。

## 4. 算法细节

1. **栈里存下标，不存值**。结算时需要知道「是谁的答案」，只有下标能把 `nums[j]` 写回正确位置；存值则无法区分值相同的不同元素。
2. **比较必须用严格小于 `nums[st.top] < nums[j]`**。相等不算「更大」，写 `<=` 会把 `[2,2]` 判成互相更大，答案错成 `[2,2]`。
3. **遍历上界取 `2*n-1`**。第 $i$ 次迭代取 `j = i % n`，$i$ 从 $0$ 到 $2n-2$ 共 $2n-1$ 次；写成 `range(n)` 会漏掉跨边界的答案，写成 `2*n` 则多一次无害的空转。
4. **`if i < n` 才入栈**。保证每个下标恰好入栈一次，既省内存又避免「同一下标二次入栈导致答案被覆盖」的隐蔽 bug。
5. **答案数组初始化为 $-1$**。算法不需要额外判断「有没有解」：扫描结束后仍留在栈里的下标，就是整圈都没有更大元素的那些，天然保持 $-1$。
6. **`n = 1` 的退化情形**：循环只跑 $i=0$ 一次，压入后直接返回 `[-1]`，无需特判。
7. **值域用 `int` 足够**：$|nums[i]| \le 10^9$ 在 32 位有符号整数内，答案存的是元素值本身，不会溢出。但**不要**用 `ans[p] != -1` 去判断「$p$ 是否已结算」——$-1$ 本身也是合法元素值。
8. **均摊分析**：整个过程中入栈恰好 $n$ 次、出栈至多 $n$ 次，`while` 的总执行次数因此是 $O(n)$，不是每轮 $O(n)$。

## 5. 正确性证明

**引理 1（栈的两个不变量）**：算法任意时刻，栈中下标自底向顶严格递增，且对应值单调不增。此外，第一圈中下标 $p$ 被压入栈后，直到它被弹出（或扫描结束）前一直留在栈中。

**证明**：初始空栈成立。压栈前，`while` 循环把所有值 $<$ `nums[j]` 的栈顶弹走，因此新栈顶（若存在）满足 $\text{nums}[\text{top}] \ge \text{nums}[j]$，压入 $j$ 后「值单调不增」保持；又因每次压入的下标严格大于此前所有下标（第一圈按 $0,1,\dots,n-1$ 顺序），「下标递增」保持。下标只由 `push`/`pop` 改变，$p$ 未参与 `pop` 时自然仍在栈中。∎

**引理 2（弹出即最近的更大值）**：设扫描到第 $i$ 步、$j = i \bmod n$ 时弹出下标 $p$，则在展开数组 $A$ 中，$j$ 是 $p$ 右侧第一个满足 $A[j] > A[p]$ 的位置。

**证明**：反设存在 $k$ 满足 $p < k < i$ 且 $A[k] > A[p]$。由引理 1，$p$ 在 $k$ 步之前一直在栈中；当扫描到 $k$ 时，`while` 会把栈中所有值小于 $A[k]$ 的元素弹出，其中就包含 $p$，这与「$p$ 直到第 $i$ 步才被弹出」矛盾。因此 $i$ 之前不存在更大的值，$j$ 即第一个。∎

**引理 3（扫描长度充分）**：若下标 $p$ 在循环数组中存在下一个更大元素，则必然存在 $d \in [1, n-1]$ 使 `nums[(p+d) % n] > nums[p]`，且对应展开下标 $p+d \le p+n-1 \le 2n-2$，落在扫描范围内。

**证明**：循环搜索等价于在 $A$ 上向右搜索至多 $n-1$ 步，取最小的可行 $d$ 即得；上界由 $p \le n-1$ 直接推出。∎

**定理**：算法输出的 `ans` 与题意要求完全一致。

**证明**：分两种情形。

- **`ans[p]` 被赋值**：赋值只发生在第 $i$ 步弹出 $p$ 时，写入 `nums[j]`。由引理 2，$j$ 是 $A$ 中 $p$ 右侧第一个更大位置，也就是循环数组中 $p$ 的下一个更大元素，故写入正确。
- **`ans[p]` 保持 $-1$**：由引理 1，$p$ 全程留在栈中、从未被弹出。若 $A$ 在 $(p, 2n-2]$ 内存在更大的值 $A[i]$，那么第 $i$ 步的 `while` 会一路弹出所有小于 $A[i]$ 的栈项，$p$ 必然被弹出，矛盾。因此 $p$ 的整个搜索窗口内都没有更大值；由引理 3，循环数组中确实不存在下一个更大元素，输出 $-1$ 正确。

两种情形互斥且穷尽，故答案数组正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层固定 $2n-1$ 次迭代；内层 `while` 每次弹出一个下标，而每个下标最多入栈一次（共 $n$ 次 push），故 `while` 全体总计至多 $n$ 次 $O(1)$ 操作。总计 $O(n)$，与暴力的 $O(n^2)$ 相差一个数量级。
- **空间**：$O(n)$。答案数组 $n$ 个元素；栈最多同时存 $n$ 个下标（严格递减数组会一路压栈到底）。不计返回值时为 $O(n)$ 辅助空间。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> nextGreaterElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n, -1);
        vector<int> st;                  // 存下标，栈内对应的值自底向顶单调不增
        st.reserve(n);

        for (int i = 0; i < 2 * n - 1; ++i) {
            int j = i % n;
            // 当前值能结算的栈顶：它们的下一个更大值就是 nums[j]
            while (!st.empty() && nums[st.back()] < nums[j]) {
                ans[st.back()] = nums[j];
                st.pop_back();
            }
            if (i < n) st.push_back(j);  // 第二圈只触发结算，不再入栈
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def nextGreaterElements(self, nums: list[int]) -> list[int]:
        n = len(nums)
        ans = [-1] * n
        st = []                          # 存下标，栈内对应的值自底向顶单调不增

        for i in range(2 * n - 1):
            j = i % n
            # 当前值能结算的栈顶：它们的下一个更大值就是 nums[j]
            while st and nums[st[-1]] < nums[j]:
                ans[st.pop()] = nums[j]
            if i < n:                    # 第二圈只触发结算，不再入栈
                st.append(j)

        return ans
```

## 8. 边界情况与易错点

1. **单元素数组** `[7]`：返回 `[-1]`。自己不是自己的下一个更大元素，迭代次数 $2n-1 = 1$ 恰好只处理下标 0。
2. **元素全部相等** `[2,2,2]`：答案全为 $-1$。比较写成 `<=` 就会互相「结算」成 `[2,2,2]`，这是本题最高频的 WA 原因。
3. **整体递减** `[5,4,3,2,1]`：绕一圈也没有更大值，全 $-1$；此时栈会被压到满（$n$ 个元素），是空间上界。
4. **整体递增** `[1,2,3,4,5]`：答案是 `[2,3,4,5,-1]`，最大值保持 $-1$；每一轮都弹到栈空，`while` 的均摊开销在此充分体现。
5. **最大值出现在中间** `[3,1,4,2]`：下标 3 的值 2 要绕到下标 2 才能拿到 4，跨边界回填只发生在第二圈的迭代里；若上界写成 `n` 就会漏掉它。
6. **第二圈误入栈**：去掉 `if i < n` 后，同一指数可能被压两次，后一个会被某个「更大但不最近」的值结算，覆盖先前正确答案。这个 bug 在小数据上不容易被发现，务必用随机对拍。
7. **负数与 −1 的歧义**：`nums[i] = -1` 时答案可能就是 `-1`，不要用答案值反推状态；判断「是否在栈中」只能靠栈本身。
8. **`2*n-1` 的类型**：`n` 是 `int` 时 $2n$ 对 $n \le 10^4$ 无溢出；若把 `n` 改成 `size_t`，注意 `2 * n - 1` 在 $n=0$ 时的下溢（本题 $n \ge 1$，但仍建议用 `int` 承接）。
