# LeetCode 键盘行 题解

## 1. 题目概述

- **标题 / 题号**：键盘行（#500，easy）
- **链接**：https://leetcode.cn/problems/keyboard-row/
- **来源**：LeetCode 第 18 场周赛 A 卷 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：美式键盘的三行字母分别是 `"qwertyuiop"`（第 1 行）、`"asdfghjkl"`（第 2 行）、`"zxcvbnm"`（第 3 行）。给定字符串数组 `words`，返回其中**所有字母都落在同一行**的单词，按输入顺序给出；大小写不敏感，`'A'` 与 `'a'` 视为同一行、同一按键。

**约束**：

- $1 \le \lvert \text{words} \rvert \le 20$
- $1 \le \lvert \text{words}[i] \rvert \le 100$
- `words[i]` 仅由英文字母（大小写）组成

> 💡 签到题的全部难点在于**把「三行字符集」压成一张 $O(1)$ 的查询表**：只要每个字母的「行号」能 $O(1)$ 查到，题目立刻退化为「同一个单词内所有字母的行号是否相等」。数据量 $L \le 2000$，连逐字符现查都能过，但写对判定结构比压常数重要得多。

## 2. 示例

**示例 1**

```text
输入：words = ["Hello","Alaska","Dad","Peace"]
输出：["Alaska","Dad"]
解释：不区分大小写，'a' 与 'A' 都在第 2 行。
      Hello 含 h(第 2 行) 与 e(第 1 行)，跨行；
      Alaska 六个字母全在第 2 行；
      Dad 三个字母全在第 2 行；
      Peace 含 p/e(第 1 行) 与 a/c(第 2 行)，跨行。
```

**示例 2**

```text
输入：words = ["omk"]
输出：[]
解释：o 在第 1 行、m 在第 3 行、k 在第 2 行，一个字母一行，必然跨行。
```

**示例 3**

```text
输入：words = ["adsdf","sfd"]
输出：["adsdf","sfd"]
解释：两个单词的字母全在第 2 行，全部保留（重复字母不影响判定）。
```

## 3. 解题思路

### 3.1 暴力思路：每个字符现扫三行

最直接的写法：对单词的每个字符，依次在 `"qwertyuiop"`、`"asdfghjkl"`、`"zxcvbnm"` 里 `find`，找到所在行；再把所有字符的行号与首字符比较。单字符最多比 $10+9+7=26$ 次，总计 $O(26L)$，$L \le 2000$ 时约 $5.2\times10^4$ 次比较——**能过，但结构差**：同一个字母被反复查了成百上千遍，而且 `find` 返回的是**下标**，误把 `npos` 与下标 $0$ 混用就会静默出错。

> ⚠️ 签到题的正确姿势不是发明算法，而是识别出「哪些量可以提前算好、算一次就够」：26 个字母的行号是**与输入无关的常量表**。

### 3.2 核心观察：一维行号表 + 位掩码

![美式键盘三行：每个字母对应唯一行号，大小写共享同一行](images/wc18_q1_keyboard_rows.svg)

关键在于：三行字符串拼起来**恰好**是 26 个字母的一个**划分**（$10+9+7=26$，行内互异、行间不交）。因此可以预处理出长度为 26 的表

$$\text{rowOf}[c] \in \{1,2,3\},\qquad c \in [\text{'a'},\text{'z'}]$$

于是「单词合法」有了一个极其干净的等价刻画——**所有字母行号相同**：

$$\text{合法}(w) \iff \text{rowOf}[w_0] = \text{rowOf}[w_1] = \cdots = \text{rowOf}[w_{m-1}]$$

其中 $w_i$ 已统一转成小写。注意基准**只需取首字母**：三行互不相交，一旦有两个字母行号不同，无论拿谁当基准都会判假。

写成**位掩码**形式更紧凑。令

$$M_r = \bigvee_{c \in \text{第 } r \text{ 行}} 2^{\,\text{idx}(c)},\qquad W = \bigvee_{i=0}^{m-1} 2^{\,\text{idx}(w_i)}$$

其中 $\text{idx}(c) = c - \text{'a'} \in [0,25]$，则

$$\text{合法}(w) \iff \exists\, r \in \{1,2,3\},\; W \,\&\, M_r = W$$

即「单词的字母集合是某一行字母集合的子集」。掩码判定一次位运算即可，且天然对重复字母去重（`"adsdf"` 与 `"asd"` 的 $W$ 相同，判定结果也相同）。

### 3.3 算法流程

![算法流程：一次预处理 rowOf 表，逐单词「取基准行 + 全字符校验」](images/wc18_q1_algorithm_flow.svg)

1. **预处理**：把三行字符串扫一遍，写入 `rowOf[26]`（Python 版换成三个行掩码 $M_1, M_2, M_3$）；
2. **逐单词**：取 `r = rowOf[lower(w[0])]` 作为基准行号；
3. **全字符校验**：从左到右检查 `rowOf[lower(ch)] == r`，一旦不等就 `break` 并标记失败（提前退出）；
4. **收集**：全部通过则把**原始大小写形式**的 `w` 追加到答案；
5. **返回** `ans`（可能为空数组）。

### 3.4 示例演算

![示例演算：把每个字母翻译成行号，再看行号是否唯一](images/wc18_q1_walkthrough.svg)

对 `words = ["Hello","Alaska","Dad","Peace"]` 逐词翻译：

| 单词 | 逐字母行号 | 不同行号个数 | 结论 |
|------|-----------|-------------|------|
| `Hello` | H:2 e:1 l:2 l:2 o:1 | 2（第 1、2 行） | ✗ 丢弃 |
| `Alaska` | A:2 l:2 a:2 s:2 k:2 a:2 | 1（第 2 行） | ✓ 保留 |
| `Dad` | D:2 a:2 d:2 | 1（第 2 行） | ✓ 保留 |
| `Peace` | P:1 e:1 a:2 c:2 e:1 | 2（第 1、2 行） | ✗ 丢弃 |

`Hello` 一开始就撞上 `e`（第 1 行）与基准 `H`（第 2 行）不一致，第 2 个字符即 `break`；这正是「提前退出」在真实数据上的收益。最终答案 `["Alaska","Dad"]`，与输入顺序一致。

## 4. 算法细节

1. **预处理只做一次**：26 个字母的行号是常量，放在函数内的 `static const` 表或局部数组均可；不要在每个单词里重建，那是把 $O(26)$ 的固定开销乘上 $\lvert \text{words}\rvert$。
2. **大小写归一化**：统一 `tolower` 后用 `c - 'a'` 建索引。**不要**为大小写写两套分支或把表扩到 52 项——大小写只是同一个按键的两种写法，多一份映射就多一处不一致的风险。
3. **基准取首字母就够**：因为三行互不相交，`rowOf` 的值域只有 3 个且划分完整，「所有行号相同」等价于「所有行号等于首个行号」。无需再与另外两行分别比较。
4. **提前退出**：循环里发现 `rowOf[c] != r` 立即 `break`，最好情况 $O(1)$（如 `Hello` 第 2 个字符就失败），最坏 $O(\lvert w \rvert)$。返回值判定的 `ok` 标志必须在 `break` 前置假。
5. **输出保留原始拼写**：题目要求返回原单词（`"Alaska"` 而非 `"alaska"`），所以判定用 `lower` 后的副本，入答案用原串——别在归一化时把字符串本身改掉。
6. **不去重、不排序**：重复单词（`["a","a"]`）都要保留，顺序按输入。题目没有「结果唯一」的承诺，排序或去重都会 WA。
7. **位掩码版的两个坑**：位运算优先级，Python 中 `m & mask == m` 被解析为 `(m & mask) == m`（`==` 优先级更低），语义正确但建议显式加括号；C++ 中 `&` 优先级**低于** `==`，写 `m & mask == m` 会变成 `m & (mask == m)`，必须写成 `(m & mask) == m`。
8. **空输入的保护**：约束保证 $\lvert \text{words} \rvert \ge 1$、$\lvert \text{words}[i] \rvert \ge 1$，所以取 `w[0]` 安全；若做通用化改造（允许空串），需把空串视为「不跨行」还是「跨行」需显式定义。

## 5. 正确性证明

**引理 1（三行构成划分）**：三行字符串的长度和为 $10+9+7=26$，行内字符互不相同，且任意两行无公共字符；故每个小写字母恰属于一行，`rowOf` 的赋值是良定义的。

**证明**：逐字符核对三行串 $\{"qwertyuiop"\}, \{"asdfghjkl"\}, \{"zxcvbnm"\}$ 即可验证：三个集合两两不交，并集恰为 $\{a,\dots,z\}$（共 26 个元素）。由于两两不交，预处理循环中每个下标只被写入一次，`rowOf[c]` 的值就是 $c$ 所属的唯一行号。∎

**引理 2（判定等价）**：对单词 $w$，循环结束后 `ok == true` 当且仅当 $\forall i,\ \text{rowOf}[w_i] = \text{rowOf}[w_0]$。

**证明**：
（$\Leftarrow$）若所有字符行号都等于 $r = \text{rowOf}[w_0]$，则循环中判定 `rowOf[w_i] != r` 恒假，`ok` 从不被置假，保持初值 `true`。
（$\Rightarrow$）若存在 $j$ 使 $\text{rowOf}[w_j] \ne r$，循环到 $j$ 时条件成立、`ok` 被置假并 `break`；`break` 之后 `ok` 不再被修改，故终值为 `false`。
两个方向合起来即得等价。∎

**引理 3（首字母基准充分）**：若 $w$ 的所有字母同属一行，则该行必为 $\text{rowOf}[w_0]$ 所指的行；反之不存在「以首字母为基准会误判」的情形。

**证明**：由引理 1，每个字母的行号唯一。「所有字母同属一行」意味着存在 $r$ 使 $\forall i,\text{rowOf}[w_i]=r$，取 $i=0$ 得 $r = \text{rowOf}[w_0]$。若字母分属两行，则存在 $j$ 使 $\text{rowOf}[w_j]\ne\text{rowOf}[w_0]$，由引理 2 判定为假——这与「不合法」一致，不会误判。∎

**定理 1（行号表版正确）**：算法返回的序列恰为 `words` 中所有「字母同属一行」的单词，且保持输入顺序、不重不漏。

**证明**：外层循环按输入下标 $0,1,\dots$ 顺序遍历每个单词，每个单词被处理且仅被处理一次。由引理 2，`ok` 精确刻画「所有字母行号相同」；由引理 3 与引理 1，这又等价于「所有字母属于同一键盘行」。(i) 被收录的单词满足该性质，答案不掺假；(ii) 每个满足该性质的单词其 `ok` 必为真，必被收录，故不遗漏；(iii) 追加顺序即遍历顺序，故保序；(iv) 每个下标最多追加一次，故不重复。∎

**定理 2（位掩码版正确）**：对任意非空单词，$\exists r,\ W \,\&\, M_r = W$ 当且仅当该单词所有字母同属一行。

**证明**：$W \,\&\, M_r = W$ 等价于「$W$ 的每一个为 1 的位在 $M_r$ 中也取 1」，即 $w$ 的每个字母都属于第 $r$ 行。由引理 1 的三行是划分：(i) 若某 $r$ 使等式成立，则全部字母都属于第 $r$ 行，单词合法；(ii) 若单词合法、其公共行号为 $r$，则 $W \subseteq M_r$，等式对 $r$ 成立。又因 $w$ 非空，$W \ne 0$，对任意 $r' \ne r$ 有 $W \,\&\, M_{r'} = 0 \ne W$，不会出现「误匹配到别的行」。故 `any(...)` 的返回值与合法性一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(L + 26)$，其中 $L = \sum_i \lvert \text{words}[i] \rvert \le 20 \times 100 = 2000$ 是总字符数。预处理扫三行串共 26 次赋值；判定阶段每个字符至多被检查一次（命中即 `break`，平均更少），故总比较次数不超过 $L$。对照暴力 $O(26L)$，省掉了一个 26 的常数因子。
- **空间复杂度**：$O(1)$ 辅助空间——C++ 版是 26 个 `int`（约 104 字节），Python 版是 3 个整数掩码；输出数组 $O(k)$（$k$ 为合法单词数）不计入辅助空间。
- **常数层面**：位掩码版每字符一次移位 + 一次或运算，行号表版每字符一次数组下标访问。$L \le 2000$ 时两者都是微秒级，比赛选自己写得最稳的那个即可。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> findWords(vector<string>& words) {
        static const string rows[3] = {"qwertyuiop", "asdfghjkl", "zxcvbnm"};
        int rowOf[26] = {0};
        for (int r = 0; r < 3; ++r)
            for (char c : rows[r]) rowOf[c - 'a'] = r;   // 预处理：字母 -> 行号

        vector<string> ans;
        for (const string& w : words) {
            int r = rowOf[tolower(w[0]) - 'a'];          // 以首字母所在行为基准
            bool ok = true;
            for (char c : w) {
                if (rowOf[tolower(c) - 'a'] != r) {      // 出现跨行字符
                    ok = false;
                    break;                               // 提前退出
                }
            }
            if (ok) ans.push_back(w);                    // 保留原始大小写
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findWords(self, words: List[str]) -> List[str]:
        masks = []
        for row in ("qwertyuiop", "asdfghjkl", "zxcvbnm"):
            m = 0
            for ch in row:
                m |= 1 << (ord(ch) - ord('a'))   # 该行字母的位掩码 M_r
            masks.append(m)

        ans = []
        for w in words:
            m = 0
            for ch in w.lower():                 # 大小写归一化
                m |= 1 << (ord(ch) - ord('a'))   # 单词掩码 W
            if any((m & row_mask) == m for row_mask in masks):   # W 是某行掩码的子集
                ans.append(w)
        return ans
```

> 💡 **最短形态**（利用集合判定，可读性优先）：`ans = [w for w in words if any(set(w.lower()) <= set(row) for row in ("qwertyuiop","asdfghjkl","zxcvbnm"))]`——与位掩码版逻辑同构，只是把「位包含」换成「集合包含」。

## 8. 边界情况与易错点

1. **单字符单词永远合法**：`["a"]` 只有一个字母，不可能跨行，答案 `["a"]`。别给它写特判。
2. **空结果返回 `[]`**：示例 2 的 `["omk"]` 返回空数组，不是 `null` 也不是 `[""]`。
3. **大小写混用**：`"Alaska"`、`"Dad"` 首字母大写、其余小写，必须统一转小写再查表；`'A'` 与 `'a'` 同一行，但**返回时保留原拼写**。
4. **重复单词要保留**：`["a","a"]` → `["a","a"]`，两个都算。
5. **C++ 运算符优先级**：位掩码写法中 `&` 的优先级低于 `==`，`m & mask == m` 会编译成 `m & (mask == m)`，得到 `int & bool` 的错误语义；务必写括号 `(m & mask) == m`。
6. **`tolower` 的入参类型**：`char` 在部分平台上是有符号的，若传入 `>= 0x80` 的字节会 UB——本题输入限定英文字母，安全；通用场景应写 `tolower((unsigned char)c)`。
7. **`npos` 陷阱**：若采用 `find` 的暴力写法，`string::npos` 是极大无符号数，判断行号时必须先判「找到」再比较下标，否则会把「没找到」当成第 0 个位置。
8. **预处理与判定解耦**：把 `rowOf` 建成表之后，判定逻辑与键盘布局完全独立；要换布局（Dvorak、法语 AZERTY）只改一张表，这是这道签到题真正值得带走的模板。
