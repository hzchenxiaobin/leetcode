# LeetCode 下一个更大元素 I 题解

## 1. 题目概述

- **标题 / 题号**：下一个更大元素 I（#496，easy）
- **链接**：https://leetcode.cn/problems/next-greater-element-i/
- **来源**：LeetCode 第 18 场周赛 B 卷 Q4
- **难度**：简单
- **标签**：栈、数组、哈希表、单调栈

**题意**：给定两个**元素互不相同**的数组 `nums1` 和 `nums2`，且 `nums1` 是 `nums2` 的子集。对 `nums1` 中的每个值 $x$，先定位它在 `nums2` 中的唯一位置 $j$，再取 `nums2` 中 $j$ **右侧第一个严格大于** $x$ 的元素值；若这样的元素不存在，记为 $-1$。按 `nums1` 的顺序返回所有答案。

**约束**：

- $1 \le \lvert \text{nums1} \rvert \le \lvert \text{nums2} \rvert \le 1000$
- $0 \le \text{nums1}[i],\ \text{nums2}[i] \le 10^4$
- `nums1` 与 `nums2` 中所有整数**互不相同**，且 `nums1` 中每个值都出现在 `nums2` 中
- 进阶要求：把时间复杂度压到 $O(\lvert \text{nums1} \rvert + \lvert \text{nums2} \rvert)$

> 💡 元素互不相同这一条是本题的钥匙：它让「值」可以直接作为哈希表的键，也让单调栈的弹出条件不必纠结相等。

## 2. 示例

**示例 1**

```text
输入：nums1 = [4,1,2], nums2 = [1,3,4,2]
输出：[-1,3,-1]
解释：
  4 在 nums2 下标 2，右侧没有更大元素 → -1
  1 在 nums2 下标 0，右侧第一个更大的是 3 → 3
  2 在 nums2 下标 3，右侧没有元素 → -1
```

**示例 2**

```text
输入：nums1 = [2,4], nums2 = [1,2,3,4]
输出：[3,-1]
解释：
  2 在 nums2 下标 1，右侧第一个更大的是 3 → 3
  4 在 nums2 下标 3，右侧没有更大元素 → -1
```

**示例 3**（全递减，最容易写错的情况）

```text
输入：nums1 = [5,3,1], nums2 = [5,4,3,2,1]
输出：[-1,-1,-1]
解释：整个数组严格递减，任何元素的右侧都不存在更大值。
```

## 3. 解题思路

### 3.1 暴力思路

对 `nums1` 的每个值，先在 `nums2` 里线性找到它的位置 $j$，再从 $j+1$ 开始向右扫描，遇到第一个更大的数就返回，否则返回 $-1$。每次查询 $O(\lvert \text{nums2} \rvert)$，总计

$$O\bigl(\lvert \text{nums1} \rvert \cdot \lvert \text{nums2} \rvert\bigr)$$

在 $1000 \times 1000 = 10^6$ 的数据范围内其实也能通过，但它做了大量重复劳动：`nums1` 里的两个值可能在 `nums2` 中相距很远，却各自把同一段后缀重扫一遍；如果数据范围放大到 $10^5$，$10^{10}$ 就彻底不可行，而题面的「进阶」正是在暗示这一点。

### 3.2 核心观察：递减栈 + 出栈即结算

![单调栈与哈希表](images/wc18_q4_stack_concept.svg)

关键问题不是「$x$ 的右边有什么」，而是反向的问法：**$x$ 的答案在哪一刻被确定？**

从左到右扫描 `nums2`。若当前元素 $x$ 大于某个尚未结算的旧元素 $t$，那么 $x$ 就是 $t$ 的答案——因为在 $t$ 之后扫描到的数都 $\le t$（否则 $t$ 早就被弹掉了）。于是我们只需要维护一个「还在等答案」的元素集合：

- 用一个栈保存「已经出现、但右侧还没有更大值」的元素；
- **栈内自底向顶严格递减**（越靠近栈顶的元素越小、越「容易被满足」）；
- 新元素 $x$ 到来时，把栈顶所有 $< x$ 的元素弹出，并给它们记账 `nxt[弹出值] = x`；
- 最后把 $x$ 压入栈，继续等。

这样一来，每个元素**入栈一次、出栈至多一次**，整趟扫描 $O(\lvert \text{nums2} \rvert)$；查询时 `nums1` 中的值直接查哈希表，未命中即 $-1$。总共 $O(\lvert \text{nums1} \rvert + \lvert \text{nums2} \rvert)$，正好回答题面的进阶要求。

### 3.3 算法流程

![扫描流程](images/wc18_q4_scan_flow.svg)

1. 建一张空哈希表 `nxt`，建一个空栈 `st`。
2. 从左到右遍历 `nums2` 的每个值 $x$：只要栈非空且 `st` 栈顶 $< x$，就弹出栈顶 $t$ 并令 `nxt[t] = x`（循环，直到栈顶 $\ge x$ 或栈空）。
3. 把 $x$ 压栈。
4. 遍历结束后，栈中剩下的元素右侧都没有更大值，`nxt` 中不会有它们的键。
5. 对 `nums1` 中每个 $v$：若 `nxt` 中存在键 $v$ 则输出 `nxt[v]`，否则输出 $-1$。

注意第 2 步的 **while** 是本题的灵魂：一次新元素可以连续「结算」多个旧元素，这正是均摊 $O(1)$ 的来源。

### 3.4 示例演算

![示例演算表](images/wc18_q4_walkthrough.svg)

以 `nums2 = [1,3,4,2]` 走一遍：

| $i$ | $x$ | 出栈并记账 | 栈（底 → 顶） | `nxt` |
|-----|-----|------------|----------------|--------|
| 0 | 1 | 无（栈空） | `[1]` | `{}` |
| 1 | 3 | 弹出 1，`nxt[1]=3` | `[3]` | `{1:3}` |
| 2 | 4 | 弹出 3，`nxt[3]=4` | `[4]` | `{1:3, 3:4}` |
| 3 | 2 | 无（$2 < 4$） | `[4,2]` | `{1:3, 3:4}` |

扫描结束，栈里的 `4` 与 `2` 没有答案。最后按 `nums1 = [4,1,2]` 查表：`nxt[4]` 缺失，得 $-1$；`nxt[1] = 3`；`nxt[2]` 缺失，得 $-1$。答案 $[-1,3,-1]$。

可以看到**栈中遗留的元素恰好就是「没有下一个更大值」的元素**，这是本题一个很直观的自检信号。

## 4. 算法细节

1. **栈里存值而不是下标**：本题只要「下一个更大的值」，值即键；存下标是 [739. 每日温度](https://leetcode.cn/problems/daily-temperatures/) 的需求（它要算距离）。两者的模板只差这一点。
2. **弹出条件是严格小于**：本题元素互不相同，所以不会遇到相等；若扩展到「下一个大于等于」的变体，条件要相应改成 $\le$，否则相等元素会互相阻挡。
3. **哈希表只记录「已被结算」的元素**：`nxt` 里查不到就说明它没有答案，不需要额外初始化成 $-1$，直接 `get(v, -1)` / `find` 判断。
4. **不要对 `nums1` 单独跑单调栈**：`nums1` 是查询集合而不是扫描序列，在它上面跑栈会得到完全错误的结果。
5. **栈用 `vector` 模拟**：C++ 的 `vector` 做 `push_back`/`pop_back` 比 `stack` 更快，也方便 `back()` 取值；`reserve(nums2.size())` 可避免扩容。
6. **哈希表容量**：C++ 的 `unordered_map` 建议 `reserve(nums2.size() * 2)`，`nums2` 最大 1000，这点开销可以忽略，但习惯值得保留。
7. **值域小时可以换数组**：值域 $0 \sim 10^4$ 且非负，可以用长度 $10^4+1$ 的数组代替哈希表（初始化为 $-1$），常数更小；哈希表版本更通用，不依赖值域。
8. **`nums1` 顺序必须保留**：答案要按 `nums1` 的原始顺序输出，不能因为查表而排序。

## 5. 正确性证明

**引理 1（栈的单调性）**：扫描过程中，栈内元素自底向顶严格递减。

**证明**：初始为空，成立。设处理 $x$ 之前栈自底向顶递减为 $a_1 > a_2 > \cdots > a_k$。弹出阶段删掉末尾所有 $< x$ 的元素，剩下的栈顶 $a_t$（若存在）满足 $a_t > x$，因此把 $x$ 压栈后仍有 $a_1 > \cdots > a_t > x$，自底向顶依旧严格递减。∎

**引理 2（出栈时机即答案）**：设元素 $t$ 在位置 $p$ 入栈、在处理位置 $q$ 的元素 $x = \text{nums2}[q]$ 时出栈（$p < q$），则 $x$ 是 $t$ 右侧**第一个**比 $t$ 大的元素。

**证明**：由引理 1，$t$ 入栈时位于栈顶一侧（其上元素均 $< t$），而当 $x > t$ 时弹出过程会先弹掉 $t$ 之上的所有比 $x$ 小的元素，最终把 $t$ 本身弹出，所以 $t$ 确实在这一刻出栈。下面说明区间 $(p, q)$ 中不存在比 $t$ 大的数：反设存在 $r$ 满足 $p < r < q$ 且 $\text{nums2}[r] > t$。处理 $\text{nums2}[r]$ 时，$t$ 尚未出栈（$q$ 才是出栈时刻）；此时 $t$ 之上的元素都 $< t < \text{nums2}[r]$，会连同 $t$ 一起被弹出，矛盾。故 $t$ 右侧第一个更大的元素就是 $x$。∎

**引理 3（未出栈元素无答案）**：扫描结束时仍在栈中的元素，其右侧不存在比它大的元素。

**证明**：设 $t$ 结束时仍在栈中。若其右侧存在更大的 $\text{nums2}[r] > t$，由引理 2 的论证，处理 $\text{nums2}[r]$ 时 $t$ 必被弹出，与假设矛盾。∎

**定理**：算法对 `nums1` 中每个值输出的答案都正确。

**证明**：设 $v = \text{nums1}[i]$，由「元素互不相同」知 $v$ 在 `nums2` 中的出现位置 $p$ 唯一。若 $v$ 右侧存在第一个更大的元素，则它在扫描中出栈，由引理 2 得 `nxt[v]` 恰为该值，输出正确；若不存在，则由引理 3 知 $v$ 从未出栈，`nxt` 中无键 $v$，程序输出 $-1$，同样正确。∎

## 6. 复杂度分析

记 $n = \lvert \text{nums2} \rvert$，$m = \lvert \text{nums1} \rvert$。

- **时间**：$O(n + m)$。扫描 `nums2` 时每个元素压栈一次、出栈至多一次，因此 while 循环的总执行次数不超过 $n$，建表为 $O(n)$；哈希表单次查询均摊 $O(1)$，查表 $O(m)$。
- **空间**：$O(n)$。栈最多存 $n$ 个元素（严格递减序列一个都不弹），哈希表最多 $n$ 个键；返回数组 $O(m)$ 不计入辅助空间。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> nextGreaterElement(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, int> nxt;         // 值 -> 下一个更大值
        nxt.reserve(nums2.size() * 2);
        vector<int> st;                      // 单调递减栈，存值
        st.reserve(nums2.size());

        for (int x : nums2) {
            while (!st.empty() && st.back() < x) {
                nxt[st.back()] = x;          // 出栈即结算
                st.pop_back();
            }
            st.push_back(x);
        }

        vector<int> ans;
        ans.reserve(nums1.size());
        for (int v : nums1) {
            auto it = nxt.find(v);
            ans.push_back(it == nxt.end() ? -1 : it->second);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def nextGreaterElement(self, nums1: list[int], nums2: list[int]) -> list[int]:
        nxt = {}          # 值 -> 下一个更大值
        stack = []        # 单调递减栈，存值
        for x in nums2:
            while stack and stack[-1] < x:
                nxt[stack.pop()] = x
            stack.append(x)
        return [nxt.get(v, -1) for v in nums1]
```

## 8. 边界情况与易错点

1. **严格递减**：`nums2 = [5,4,3,2,1]` 时栈只进不出，答案全为 $-1$，栈空间达到 $O(n)$；若循环条件误写成 `st.back() > x`，递减序列会被成对弹出、记下完全错误的答案。
2. **栈中的最大值**：全局最大值永远不会出栈，对应的查询必然是 $-1$；不要把「没查到」误当成异常。
3. **`nums1` 只有一个元素**：直接走查表分支，注意返回长度与 `nums1` 相同，不要返回栈的长度。
4. **`operator[]` 的副作用**：C++ 里 `nxt[v]` 在键不存在时会**插入** $0$，所以查询必须用 `find` 或 `count`；用 `operator[]` 会把 $-1$ 情况污染成 $0$。
5. **不要用 `while (st.back() < x)` 而漏掉空栈判断**：`nums2` 首元素入栈前栈为空，缺 `!st.empty()` 会越界。
6. **栈里存下标时的取值**：若改用存下标的写法（为兼容重复元素的变体），比较栈顶要写 `nums2[st.back()]`，弹出记账要写 `nxt[nums2[st.back()]] = x`，两处都得转换，容易只改一处。
7. **答案顺序**：按 `nums1` 顺序输出而不是按 `nums2` 扫描顺序，二者只在 `nums1` 恰为递增子序列时才碰巧一致。
