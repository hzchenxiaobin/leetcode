# LeetCode 统计「优美子数组」 题解

## 1. 题目概述

- **标题 / 题号**：统计「优美子数组」（#1248，medium）
- **链接**：https://leetcode.cn/problems/count-number-of-nice-subarrays/
- **来源**：LeetCode 第 161 场周赛 Q2
- **难度**：中等
- **标签**：数组，哈希表，数学，前缀和，滑动窗口

**题意**：给定整数数组 $nums$ 与整数 $k$。若某个**连续子数组**内恰好含有 $k$ 个奇数，则称它为「优美子数组」。求优美子数组的**总数**（只需计数，不需要列出它们，相同值出现在不同位置视为不同子数组）。

**约束**：

- $1 \le nums.length \le 50000$
- $1 \le nums[i] \le 10^5$
- $1 \le k \le nums.length$

> 💡 **第一反应**：题面只关心「奇数**有几个**」，完全不关心每个数具体多大。于是 $[7, 2, 4000, 9]$ 与 $[1, 0, 0, 1]$ 在本题里是**同一个问题**——所有偶数等价成 $0$，所有奇数等价成 $1$。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,1,1], k = 3
输出：2
解释：包含 3 个奇数的子数组只有 [1,1,2,1]（下标 0..3）和 [1,2,1,1]（下标 1..4）。
```

**示例 2**

```text
输入：nums = [2,4,6], k = 1
输出：0
解释：数组里一个奇数都没有，不存在优美子数组。
```

**示例 3**

```text
输入：nums = [2,2,2,1,2,2,1,2,2,2], k = 2
输出：16
解释：两个奇数分别在下标 3 与 6；左端点可取 0..3（4 种），右端点可取 6..9（4 种），4 × 4 = 16。
```

## 3. 解题思路

### 3.1 暴力思路

枚举区间两端点 $i \le j$，再扫一遍统计其中奇数个数，复杂度 $O(n^3)$。把「统计奇数」改成边扩展右端点边累加，可降到 $O(n^2)$：

```text
for i in 0..n-1:
    odd = 0
    for j in i..n-1:
        odd += nums[j] & 1
        if odd == k: ans += 1
        if odd > k: break
```

$n = 5\times 10^4$ 时最坏约 $1.25\times 10^9$ 次内层循环，稳定超时。瓶颈在于：**我们对每个右端点都重新数了一遍前缀信息**。

### 3.2 核心观察：奇偶二值化 + 前缀和计数表

![奇偶二值化、前缀和与计数表](images/wc161_q2_odd_prefix_map.svg)

令 $b_i = nums[i] \bmod 2 \in \{0,1\}$，问题变成「**求和恰好为 $k$ 的连续子数组个数**」。定义前缀和

$$P[0] = 0, \qquad P[j] = \sum_{t=0}^{j-1} b_t \quad (1 \le j \le n)$$

则子数组 $nums[i..j-1]$ 的奇数个数为 $P[j] - P[i]$。「恰好 $k$ 个」等价于

$$P[j] - P[i] = k \iff P[i] = P[j] - k \qquad (0 \le i < j \le n)$$

于是**对每个右端点 $j$，只需数一数「值为 $P[j]-k$ 的前缀出现了几次」**。把每个 $P$ 值的出现次数存进计数表 $cnt$，查询就是 $O(1)$。对所有 $j$ 累加 $cnt[P[j]-k]$ 即答案（累加时表中只含 $P[0..j-1]$）：

$$ans = \sum_{j=1}^{n} cnt\big[P[j] - k\big]$$

> 💡 **关键细节：先查后插**。处理 $P[j]$ 时，表里必须**只含** $P[0..j-1]$，否则 $i = j$ 的「空区间」会被算进来。所以顺序固定为「先累加答案，再把自己的计数加一」。

$P$ 的取值只可能是 $0, 1, \dots, n$ 这 $n+1$ 个整数，所以计数表不需要哈希，直接开长度 $n+2$ 的数组即可（比 `unordered_map` 更快，且无哈希冲突风险）。

### 3.3 算法流程

![一次扫描的流程：先查前驱、再登记自己](images/wc161_q2_algorithm_flow.svg)

1. `pref = 0`，`ans = 0`，`cnt` 数组全 $0$，并令 `cnt[0] = 1`（空前缀 $P[0]=0$ 出现一次）。
2. 依次遍历 `x in nums`：
   - 令 `pref += x & 1`，即得到新的前缀和 $P[j]$；
   - 若 `pref >= k`，则 `ans += cnt[pref - k]`；
   - 再执行 `cnt[pref] += 1`。
3. 遍历结束返回 `ans`。

`pref >= k` 这个判断不是可有可无的优化：它同时保证了 `pref - k` 落在 $[0, n]$ 内，天然规避负下标越界。

### 3.4 示例演算

![示例 1 的逐步演算表](images/wc161_q2_walkthrough.svg)

以 `nums = [1,1,2,1,1]`、`k = 3` 为例，前缀和为 $P = [0,1,2,2,3,4]$：

| $i$ | $nums[i]$ | $P[i+1]$ | 查询 $cnt[P[i+1]-3]$ | 命中 | $ans$ | 插入后 $cnt$ |
|-----|-----------|----------|----------------------|------|-------|--------------|
| 0 | 1（奇） | 1 | $-2$，跳过 | 0 | 0 | $\{0{:}1,\ 1{:}1\}$ |
| 1 | 1（奇） | 2 | $-1$，跳过 | 0 | 0 | $\{0{:}1,\ 1{:}1,\ 2{:}1\}$ |
| 2 | 2（偶） | 2 | $-1$，跳过 | 0 | 0 | $\{0{:}1,\ 1{:}1,\ 2{:}2\}$ |
| 3 | 1（奇） | 3 | $cnt[0]=1$ | 1 | 1 | $\{0{:}1,\ 1{:}1,\ 2{:}2,\ 3{:}1\}$ |
| 4 | 1（奇） | 4 | $cnt[1]=1$ | 1 | 2 | $\{0{:}1,\dots,4{:}1\}$ |

第 4 行命中 $P[0]=0$，对应子数组下标 $0..3$；第 5 行命中 $P[1]=1$，对应下标 $1..4$。两次累加得 $ans = 2$，与官方输出一致。

## 4. 算法细节

1. **奇偶判定用 `x & 1`**：取最低位比 `x % 2` 更直观也更快，且本题 $nums[i] \ge 1$，不必担心负数取模的边界。
2. **计数表用数组而非哈希表**：$P[j] \in [0, n]$，故开 `vector<int> cnt(n + 2, 0)`；下标 $0..n$ 全部合法，末尾多留一格只是防御性写法。数组是连续内存，常数远小于 `unordered_map`。
3. **`cnt[0] = 1` 必须先做**：它代表「空前缀」$P[0] = 0$，是所有从下标 $0$ 开始的子数组的左端点。漏掉它，示例 1 的第 4 步就会得到 $0$ 而不是 $1$。
4. **「先查后插」顺序不可交换**：交换后 $i = j$ 的情形（空子数组）会被计入，答案偏大；这是本类「恰好」计数最常见的错误。
5. **`pref` 单调不减**：因为 $b_i \ge 0$，前缀和只增不减，这是「前缀和 + 计数表」能用 $O(1)$ 查询的结构基础，也是下面两种替代解法可行的原因。
6. **答案范围**：子数组总数上界为 $n(n+1)/2 = 1{,}250{,}025{,}000 < 2^{31}-1$，`int` 恰好装得下，但用 `long long`（Python 无此问题）更稳妥，避免以后改题面时溢出。
7. **两种等价替代**（本解不采用，但可用于交叉验证答案）：
   - **乘法公式**：记所有奇数的下标为 $o_1 < o_2 < \dots < o_m$，两端补哨兵 $o_0 = -1,\ o_{m+1} = n$。固定「第 $i$ 个到第 $i+k-1$ 个奇数」这一组，左端点有 $o_i - o_{i-1}$ 种、右端点有 $o_{i+k} - o_{i+k-1}$ 种，贡献为两者之积，复杂度 $O(m)$。
   - **至多减至多**：$\text{exactly}(k) = \text{atMost}(k) - \text{atMost}(k-1)$，双指针实现，空间 $O(1)$。

## 5. 正确性证明

**引理 1**：对任意 $0 \le i < j \le n$，子数组 $nums[i..j-1]$ 中奇数的个数等于 $P[j] - P[i]$。

**证明**：由前缀和定义 $P[j] = \sum_{t=0}^{j-1} b_t$、$P[i] = \sum_{t=0}^{i-1} b_t$，两式相减得 $\sum_{t=i}^{j-1} b_t$。而 $b_t = 1$ 当且仅当 $nums[t]$ 为奇数，故该和恰为区间内的奇数个数。∎

**引理 2**：执行到第 $j$ 个元素（$1 \le j \le n$）时、尚未执行本次插入前，$cnt[v]$ 恰等于 $\lvert\{\,i : 0 \le i \le j-1,\ P[i] = v\,\}\rvert$。

**证明**：对 $j$ 归纳。$j = 1$ 时表中只有初始化写入的 $cnt[0] = 1$，对应唯一的 $P[0] = 0$，成立。设 $j$ 时成立，则本轮插入 $cnt[P[j]] += 1$ 后，表中恰好补齐了 $P[j]$ 这一次出现，且其余键值未变；下一轮 $j+1$ 的查询前状态正是「$P[0..j]$ 的出现次数」，归纳成立。∎

**定理**：算法返回的 `ans` 等于优美子数组的个数。

**证明**：任意优美子数组 $nums[i..j-1]$ 与数对 $(i, j)$（$0 \le i < j \le n$）一一对应，且由引理 1 它是优美的当且仅当 $P[j] - P[i] = k$。算法在每个 $j$ 处累加 $cnt[P[j]-k]$；由引理 2，这正好把满足 $P[i] = P[j]-k$ 且 $i < j$ 的每个 $i$ 各计一次，既不重复（每个 $(i,j)$ 只在 $j$ 这一轮被统计）也不遗漏（任何满足条件的 $i$ 都已在表内且被查询命中）。故 `ans` 恰为优美子数组总数。∎

## 6. 复杂度分析

- **时间**：一次遍历，每个元素做一次 $b_i$ 计算、一次数组查询、一次数组自增，均 $O(1)$，总计 $O(n)$。若用 `unordered_map` 则为 $O(n)$ 期望时间（最坏 $O(n^2)$），这也是选数组的原因。
- **空间**：计数表长度 $n+2$，$O(n)$；$P$ 无需存数组，只用一个 `pref` 变量滚动，额外 $O(1)$。若改用「至多减至多」的双指针写法，空间可降到 $O(1)$，代价是常数翻倍（扫两遍）。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int numberOfSubarrays(vector<int>& nums, int k) {
        int n = (int)nums.size();
        vector<int> cnt(n + 2, 0);   // cnt[v] = 前缀和 v 出现过的次数
        cnt[0] = 1;                 // 空前缀 P[0] = 0
        long long ans = 0;
        int pref = 0;
        for (int x : nums) {
            pref += x & 1;                    // 奇数记 1，偶数记 0
            if (pref >= k) ans += cnt[pref - k];  // 先查
            ++cnt[pref];                      // 后插
        }
        return (int)ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def numberOfSubarrays(self, nums: List[int], k: int) -> int:
        n = len(nums)
        cnt = [0] * (n + 2)      # cnt[v] = 前缀和 v 出现过的次数
        cnt[0] = 1               # 空前缀 P[0] = 0
        ans = 0
        pref = 0
        for x in nums:
            pref += x & 1            # 奇数记 1，偶数记 0
            if pref >= k:
                ans += cnt[pref - k] # 先查
            cnt[pref] += 1           # 后插
        return ans
```

## 8. 边界情况与易错点

1. **全偶数数组**：`pref` 永远为 $0$，`pref >= k` 恒不成立，直接返回 $0$（示例 2）。不要因为「没有奇数」就写特判去 `return 0`，正常流程自己会给出 $0$。
2. **$k$ 大于奇数总数**：同理返回 $0$；注意约束 $k \le n$ 并不保证 $k$ 不超过奇数个数，不能假设答案非零。
3. **`cnt[0] = 1` 漏写**：最典型错误。凡是「从下标 0 开始」的解都会丢失，示例 1 会输出 $1$ 而不是 $2$。
4. **先查后插写成先插后查**：会把 $i = j$ 的空区间计入；当 $k = 0$ 时错误尤其明显（虽然本题 $k \ge 1$，但同样的模板迁移到 $k$ 可为 $0$ 的题上就会翻车）。
5. **负下标越界**：若省略 `pref >= k` 判断又用数组做表，`pref - k` 为负会越界（C++ 是 UB，可能读到垃圾值）。要么加判断，要么用哈希表。
6. **答案溢出**：上界约 $1.25 \times 10^9$ 虽在 `int` 内，但只在最极端分布下才接近；写 `long long` 无额外代价，可避免后续加题、改数据范围时炸掉。
7. **`nums[i] % 2` 与 `nums[i] & 1`**：本题 $nums[i] \ge 1$ 两者等价；若某变体允许负数，`%` 会得到 $-1$，必须用 `& 1` 或先取绝对值。
8. **把「连续」读成「任意」**：子数组必须连续，若误当子序列，答案会大得多。

**延伸思考**：

1. 若把「奇数」换成「质数」或「满足某个谓词的元素」，前缀和转为「谓词为真的个数」，本解法**逐字不变**——这就是「二值化 + 前缀和」的迁移价值。
2. 若要求「恰好 $k$ 个奇数**且**长度不超过 $L$」：$O(n)$ 前缀和计数不再够用，需要对每个 $j$ 在 $P[j]-k$ 对应的下标集合上做二分/双指针，复杂度 $O(n \log n)$。
3. 若数组带**单点修改**（翻转某位的奇偶）并多次询问「恰好 $k$ 个奇数的子数组数」，则需要线段树维护前缀和的分布并支持区间平移合并，是本题的困难级进阶版。
4. 若 $n$ 达到 $10^7$ 且奇数稀疏（$m \ll n$），§4 第 7 条的**乘法公式**只需 $O(m)$ 时间与 $O(m)$ 空间（只存奇数下标），显著优于 $O(n)$ 的计数表。
