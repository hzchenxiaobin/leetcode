# LeetCode 数组中的最短非公共子字符串 题解

## 1. 题目概述

- **标题 / 题号**：数组中的最短非公共子字符串（#3076，medium）
- **链接**：https://leetcode.cn/problems/shortest-uncommon-substring-in-an-array/
- **来源**：LeetCode 第 388 场周赛 Q3
- **难度**：中等
- **标签**：字典树（Trie）、数组、哈希表、字符串

**题意**：给定 $n$ 个非空字符串 $\text{arr}$。对每个 $\text{arr}[i]$，求它的一个**最短**子字符串，满足该子串**不作为子串出现在其他任何字符串中**（下称「非公共子串」）；若同长有多个，取**字典序最小**者；若不存在，返回空串。

**约束**：

- $2 \le n \le 100$
- $1 \le \text{arr}[i].\text{length} \le 20$
- $\text{arr}[i]$ 只包含小写英文字母

> 💡 读题关键：三条隐藏规则——① 比较的对象是「**其他字符串**」，自己串内重复出现无所谓；② 「子串」是**连续**一段（不是子序列）；③ 优化目标是二元组 $(\text{长度}, \text{字典序})$ 的字典序，**先短后小**。数据范围是本题最大的提示：$n \le 100$、$L \le 20$，全部子串只有约 $2.1$ 万个，暴力哈希就能过。

## 2. 示例

**示例 1**

```text
输入：arr = ["cab","ad","bad","c"]
输出：["ab","","ba",""]

解释：
- "cab" 的非公共子串有 "ca"、"ab"、"cab"，最短的 "ca"/"ab" 同长，取字典序更小的 "ab"；
- "ad" 的所有子串 a、d、ad 都出现在其他串中，答案为 ""；
- "bad" 的最短非公共子串是 "ba"；
- "c" 的唯一子串 c 出现在 "cab" 中，答案为 ""。
```

**示例 2**

```text
输入：arr = ["abc","bcd","abcd"]
输出：["","","abcd"]

解释：短串的子串被长串完全覆盖，全为公共子串；"abcd" 的整串只出现在自己身上 → 答案可以是整串。
```

**示例 3**（自造，演示去重陷阱）

```text
输入：arr = ["aa","bb"]
输出：["a","b"]

解释："aa" 的子串去重后是 {a, aa}，其中 a 只出现在 "aa" 一个字符串中 → 答案 "a"。
若建表时忘记去重，cnt[a] 会被 "aa" 内部的两次出现加成 2，把 "a" 误判为公共子串，错答 "aa"。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每个 $\text{arr}[i]$ 枚举全部子串 $t$，再对每个 $t$ 逐一检查它是否是某个其他字符串的子串（`t in arr[j]`）：

- 子串总数 $O(n \cdot L^2)$，每个子串要与 $n-1$ 个串做子串匹配，单次朴素匹配 $O(L^2)$；
- 总复杂度 $O(n^2 \cdot L^4) \approx 100^2 \times 20^4 = 1.6 \times 10^{10}$ 字符比较，即使落在 C 层的 `in` 上也要数亿到十亿级操作——C++ 勉强能冲，Python 基本超时，且代码写起来啰嗦。

瓶颈在于：**每个子串的「公共性判定」都要付出 $O(n)$ 次匹配的代价**，而这些判定之间存在大量重复信息。

### 3.2 核心观察：一张哈希表把「逐串检查」变成「一次查表」

![核心观察：非公共子串等价于去重计数为1](images/shortest_uncommon_concept.svg)

注意到「$t$ 是否出现在 $\text{arr}[j]$ 中」这一信息与「我们在为哪个 $\text{arr}[i]$ 求答案」**无关**——它是全局性质。于是可以预处理：

1. 对每个字符串 $\text{arr}[k]$，枚举其全部子串，**在该字符串内部去重**成一个集合；
2. 对集合中每个子串 $t$，令 $\text{cnt}[t] \mathrel{+}= 1$。

这样 $\text{cnt}[t]$ 的语义是「**包含 $t$ 的不同字符串的个数**」。于是判定一步到位：

$$t \text{ 是 } \text{arr}[i] \text{ 的非公共子串} \;\iff\; \text{cnt}[t] = 1 \text{（且唯一来源就是 } \text{arr}[i]\text{）}$$

> 💡 本质是把「对每个候选子串做 $O(n)$ 次匹配」**摊销**成一次性建表 + 每次 $O(L)$ 的哈希查询。判定因子 $n$ 从查询循环里彻底消失——这与「前缀和把区间查询的 $O(n)$ 摊销成 $O(1)$」是同一个套路：**静态信息预处理，动态快速查询**。

### 3.3 算法流程

![算法流程：建表计数后枚举子串取长度与字典序最优](images/shortest_uncommon_flow.svg)

```text
阶段一（建表）：
for k ← 0 to n−1:
    S ← arr[k] 的全部子串构成的集合          # 按字符串内部去重
    for t in S: cnt[t] += 1

阶段二（查询）：
for k ← 0 to n−1:
    best ← ""
    for t in arr[k] 的全部子串:
        if cnt[t] = 1:                      # 非公共，是候选
            best ← (|t|, t) 字典序下更小的那个
    answer[k] ← best
```

### 3.4 示例演算

![示例演算：逐串枚举子串查计数表并选最优](images/shortest_uncommon_walkthrough.svg)

- **示例 1**：建表得 $\text{cnt} = \{a{:}3,\, b{:}2,\, c{:}2,\, d{:}2,\, ad{:}2,\, ca{:}1,\, ab{:}1,\, ba{:}1,\, cab{:}1,\, bad{:}1\}$。对 `"cab"`，候选为 `ca`/`ab`/`cab`，最短层的 `ca` 与 `ab` 比字典序得 **`"ab"`**；`"ad"`、`"c"` 无候选得 `""`；`"bad"` 的候选中 `ba` 最短得 **`"ba"`**。
- **示例 2**：`"abc"` 与 `"bcd"` 的每个子串都被 `"abcd"` 覆盖（$\text{cnt} \ge 2$），答案 `""`；`"abcd"` 的整串 $\text{cnt} = 1$，且更短的子串全公共，答案 **`"abcd"`**。
- **示例 3**：去重后 $\text{cnt}[a] = \text{cnt}[b] = 1$，单字符直接成为答案，验证了去重的必要性。

## 4. 算法细节

1. **两趟结构**：第一趟只建表不判定，第二趟只判定不建表。两趟各自独立，写起来不易出错，也方便单独验证（打印 cnt 表对拍）。
2. **去重的实现**：C++ 用 `unordered_set<string>` 收集当前串的子串再统一 `++cnt`；Python 直接用集合推导式 `{s[i:i+L] for ...}` 天然去重。
3. **比较键是 $(|t|, t)$ 二元组**：先长度、后字典序。**不能依赖枚举顺序**——固定长度下按起点从左到右枚举出的子串并不按字典序排列（示例 1 中起点更靠左的 `ca` 反而大于 `ab`），必须显式比较。
4. **为什么标签是 Trie 但我们用哈希**：Trie 的正统做法是把每个字符串的所有后缀插入字典树，树上每个节点维护一个「出现过的字符串编号集合」（$n \le 100$，一个 `uint64_t` 位掩码装两个即可），查询子串 $t$ 即沿树走 $|t|$ 步看集合是否只含第 $i$ 位。建树 $O(\sum |\text{arr}[i]|)$ 更优，但 $L \le 20$ 时哈希法常数更小、代码量减半，赛时性价比碾压（见「延伸思考」的大数据版讨论）。
5. **可选的提前终止**：按长度从 $1$ 到 $L$ 递增枚举，一旦某个长度出现候选，该长度内取完字典序最小即可停止——更长长度不可能更优（§5 引理 2 的向上封闭性）。本题数据下不必要，但值得知道。
6. **`substr` 的隐藏开销**：C++ `s.substr(i, len)` 会拷贝出长度为 `len` 的新串，这正是 $O(L)$ 因子的来源；总量 $O(n \cdot L^3) \approx 8 \times 10^5$ 字符，无压力。

## 5. 正确性证明

**引理 1（计数判定等价）**：设 $\text{cnt}[t]$ 为「包含 $t$ 的不同字符串个数」（每个字符串去重后至多贡献 $1$）。则 $t$ 是 $\text{arr}[i]$ 的非公共子串，当且仅当 $\text{cnt}[t] = 1$ 且唯一包含 $t$ 的字符串是 $\text{arr}[i]$。

**证明**：$t$ 非公共 $\iff$ 不存在 $j \ne i$ 使 $t \sqsubseteq \text{arr}[j]$ $\iff$ 包含 $t$ 的字符串集合恰为 $\{\text{arr}[i]\}$ $\iff$ $\text{cnt}[t] = 1$ 且唯一来源为 $\text{arr}[i]$。第三个等价号正是 $\text{cnt}$ 的定义（去重保证每个字符串对 $\text{cnt}[t]$ 至多加 $1$）。∎

**引理 2（非公共的向上封闭性）**：若 $s$ 是 $\text{arr}[i]$ 的非公共子串，则任何满足 $s \sqsubseteq t \sqsubseteq \text{arr}[i]$ 的子串 $t$ 也是非公共的。

**证明**：反证。若 $t$ 出现在某个 $\text{arr}[j]$（$j \ne i$）中，由 $s \sqsubseteq t \sqsubseteq \text{arr}[j]$ 得 $s$ 也出现在 $\text{arr}[j]$ 中，与 $s$ 非公共矛盾。∎

> 💡 直观读法：**非公共性是「越长越容易保持」的性质**——短串一旦独占，包含它的长子串必然独占。推论：按长度递增枚举时，第一个出现候选的长度就是答案长度，此后只需在同长候选中比字典序（§4 第 5 点提前终止的依据）。

**定理**：算法输出的 $\text{answer}[i]$ 是 $\text{arr}[i]$ 最短的非公共子串，且同长中字典序最小；不存在非公共子串时为空串。

**证明**：算法第二趟枚举 $\text{arr}[i]$ 的全部 $O(L^2)$ 个子串，由引理 1，筛选条件 $\text{cnt}[t] = 1$ 恰好无遗漏、无误差地保留 $\text{arr}[i]$ 的全部非公共子串，构成候选集 $S_i$。比较键 $k(t) = (|t|, t)$（长度为第一关键字、字典序为第二关键字）是 $S_i$ 上的全序，算法在遍历中维护 $k$ 最小的元素。由枚举的完备性与全序上取最小的唯一性，输出即 $S_i$ 中 $(|t|, t)$ 最小者——先最短、再字典序最小，恰为题目要求；$S_i = \varnothing$ 时输出空串。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L^3)$，其中 $L = 20$ 为串长上限。
  - 每个字符串的子串数至多 $\tfrac{L(L+1)}{2} = 210$，全局共 $O(n \cdot L^2) \approx 2.1 \times 10^4$ 个；
  - 每个子串的集合插入与哈希计数各需 $O(L)$（构造、散列、比较），合计约 $8 \times 10^5$ 字符级操作；
  - 相比暴力的 $O(n^2 \cdot L^4)$，判定因子 $n$ 被摊销进一次性建表。
- **空间复杂度**：$O(n \cdot L^3)$ 字符。
  - 哈希表至多存 $O(n \cdot L^2)$ 个互不相同子串，总字符数上界 $100 \times 210 \times 20 \approx 4 \times 10^5$，约 0.5 MB。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<string> shortestSubstrings(vector<string>& arr) {
        int n = arr.size();
        unordered_map<string, int> cnt;

        // 阶段一：建表——每个字符串的子串先去重，再统一 +1
        for (auto& s : arr) {
            unordered_set<string> subs;                  // 字符串内部去重
            int m = s.size();
            for (int i = 0; i < m; ++i)
                for (int len = 1; i + len <= m; ++len)
                    subs.insert(s.substr(i, len));
            for (auto& t : subs) ++cnt[t];               // cnt = 出现在几个不同字符串
        }

        // 阶段二：查询——枚举子串，cnt==1 即候选，按 (长度, 字典序) 取最优
        vector<string> ans(n);
        for (int k = 0; k < n; ++k) {
            auto& s = arr[k];
            int m = s.size();
            for (int i = 0; i < m; ++i)
                for (int len = 1; i + len <= m; ++len) {
                    string t = s.substr(i, len);
                    if (cnt[t] != 1) continue;           // 公共子串，跳过
                    string& cur = ans[k];
                    if (cur.empty() || t.size() < cur.size() ||
                        (t.size() == cur.size() && t < cur))
                        cur = t;
                }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def shortestSubstrings(self, arr: List[str]) -> List[str]:
        # 阶段一：建表——集合推导式天然完成字符串内部去重
        cnt = Counter()
        for s in arr:
            m = len(s)
            for t in {s[i:i + l] for i in range(m) for l in range(1, m - i + 1)}:
                cnt[t] += 1

        # 阶段二：查询——cnt==1 即候选，按 (长度, 字典序) 取最优
        ans = []
        for s in arr:
            m = len(s)
            best = ""
            for i in range(m):
                for l in range(1, m - i + 1):
                    t = s[i:i + l]
                    if cnt[t] == 1 and (not best or (len(t), t) < (len(best), best)):
                        best = t
            ans.append(best)
        return ans
```

## 8. 边界情况与易错点

1. **建表忘去重（本题第一大 WA 点）**：同一子串在自己串内出现多次会重复 `++cnt`。反例 `["aa","bb"]`：不去重时 $\text{cnt}[a] = 2$，把非公共子串 `a` 误判为公共，答案错成 `"aa"`（正确是 `"a"`）。
2. **字典序要显式比较**：同长候选按起点枚举的顺序 ≠ 字典序顺序（示例 1 中 `ca` 先被枚举到，但 `ab` 更小），依赖枚举顺序会拿到 `"ca"`。
3. **答案可以是空串**：`best` 初始化为 `""` 时，「候选为空」与「尚未找到候选」两种状态共用同一个哨兵值是安全的——因为非空候选永远能赢过空串；但若改用 `None` 哨兵就要小心比较逻辑。
4. **答案可以是整串**：枚举长度必须取到 $L$（示例 2 的 `"abcd"`），循环上界写成 `i + len <= m` 而非严格小于。
5. **单字符即可作答**：长度 1 的子串只在自己出现时直接是最短答案（示例 3 的 `"a"`），不要下意识从长度 2 开始。
6. **`cnt[t] == 1` 但当前串不是那个来源**：不可能发生——第二趟枚举的 $t$ 取自 $\text{arr}[k]$ 本身，若 $\text{cnt}[t] = 1$，唯一来源必然是 $\text{arr}[k]$（引理 1）。这一点想清楚后代码无需额外判断「来源是不是自己」。
7. **Trie 路线的坑**：若改用字典树，注意子串计数也要「按字符串去重」（同串的多个后缀共享节点，重复累加会犯与第 1 条同款的错），以及节点上编号集合用位掩码时 $n \le 100$ 需要两个 64 位整数拼接。

**延伸思考**：

- **如果 $L$ 达到 $10^5$ 级别**：$O(n \cdot L^3)$ 的子串枚举彻底失效，需改用**广义后缀自动机 / 后缀数组**——把所有串（加分隔符）拼接后，「恰好出现在一个原串中的最短子串」是经典可解问题：在后缀数组上对每个位置求「向前/向后第一个跨串匹配的位置」，取短板即得该位置起始的最短独占子串。
- **「恰好出现在 $k$ 个字符串」变体**：把位掩码计数改为对出现次数为 $k$ 的判定（或位掩码 `popcount == k`），引理 1 的等价性证明逐字平移。
- **在线版**：若字符串逐个到来、随时查询，哈希表可以增量维护（新串到来时对其子串集合先查后加），两趟结构自然退化为流式算法。
