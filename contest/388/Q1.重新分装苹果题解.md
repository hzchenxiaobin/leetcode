# LeetCode 重新分装苹果 题解

## 1. 题目概述

- **标题 / 题号**：重新分装苹果（#3074，easy）
- **链接**：https://leetcode.cn/problems/apple-redistribution-into-boxes/
- **来源**：LeetCode 第 388 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、排序

**题意**：给定数组 `apple`（$n$ 个包裹，第 $i$ 个装 `apple[i]` 个苹果）与数组 `capacity`（$m$ 个箱子，第 $i$ 个容量为 `capacity[i]`）。选择其中一些箱子，把**全部**苹果重新分装进去，返回所需箱子的**最小**数量。**同一个包裹中的苹果可以拆分到不同的箱子**。

**约束**：

- $1 \le n = \text{apple.length} \le 50$
- $1 \le m = \text{capacity.length} \le 50$
- $1 \le \text{apple}[i],\, \text{capacity}[i] \le 50$
- 输入保证所有苹果一定能被装下（即 $\sum \text{capacity} \ge \sum \text{apple}$）

> 💡 读题关键：**「同一个包裹中的苹果可以分装到不同的箱子中」**是本题题眼——它把一个看似装箱（bin packing）的问题松绑成纯粹的**总量比较**。包裹的内部结构完全不重要，重要的只有 $\sum \text{apple}$ 这一个数；箱子之间也没有任何搭配约束，谁的容量都一样能用。

## 2. 示例

**示例 1**

```text
输入：apple = [1,3,2], capacity = [4,3,1,5,2]
输出：2

解释：使用容量为 4 和 5 的箱子。总容量 9 ≥ 苹果总数 6，可以完成重新分装。
```

**示例 2**

```text
输入：apple = [5,5,5], capacity = [2,4,2,7]
输出：4

解释：需要使用所有箱子。7+4+2+2 = 15 恰好等于苹果总数 15。
```

**示例 3**（自造，演示排序方向）

```text
输入：apple = [1,1,1], capacity = [1,2,3,4]
输出：1

解释：苹果总数 S = 3，降序取最大箱子 4，4 ≥ 3，一个箱子足够。
若误用升序取 1, 2, 3：累计 1 → 3 → 6，要到第 3 个箱子才装够，误答 3。
```

## 3. 解题思路

### 3.1 暴力思路

最容易想到两条歧路：

1. **枚举箱子子集**：对 $m$ 个箱子的每个子集判断总容量是否 $\ge S$，取最小者——$2^{50} \approx 10^{15}$，不可行；
2. **模拟装箱**：把包裹一个个往箱子里塞，考虑包裹与箱子的配对——完全没必要，且如果真的按「整包裹分配」去模拟，反而做错方向（见 §8 易错点 2）。

正确姿势是先**读出题面给的自由度**：包裹可拆 ⇒ 苹果是可以任意流动的「液体」，唯一约束是总量。

### 3.2 核心观察：可拆分 ⇒ 可行性只取决于总容量

![核心观察：包裹可拆分则唯一约束是总容量](images/apple_boxes_split_concept.svg)

两步推理：

1. **松绑约束**：既然同一包裹的苹果可以拆散，那么一组箱子 $T$ 能装下全部苹果，当且仅当
   $$\sum_{c \in T} c \;\ge\; S, \qquad S = \sum_i \text{apple}[i]$$
   「怎么装」不重要，**总量够就行**（§5 引理 1 给出严格证明）。
2. **贪心选择**：现在问题变成「选最少的数，使和 $\ge S$」。同样取 $k$ 个箱子，取容量**最大的 $k$ 个**总容量一定不小（§5 引理 2）——所以从最大的箱子开始取，装够即停，取的个数就是最优解。

> 💡 这就是经典的**「取最大的 k 个支配任意 k 个」**贪心范式：排序 + 前缀和 + 二分/线性扫，一步到位。

### 3.3 算法流程

![算法流程：排序降序后循环扣减剩余需求](images/apple_boxes_greedy_flow.svg)

```text
need ← Σ apple                 # 剩余需求 = 苹果总数 S
capacity ← 按容量降序排序        # 大箱子优先
k ← 0
while need > 0:                # 题目保证 Σcapacity ≥ S，循环必终止
    need ← need − capacity[k]
    k ← k + 1
return k
```

用「剩余需求 `need` 递减」代替「前缀和数组」，一趟扫完，不用额外开数组。

### 3.4 示例演算

![示例演算：两个用例的累计容量走查](images/apple_boxes_walkthrough.svg)

- **示例 1**：$S = 6$，降序 `capacity = [5,4,3,2,1]`。取 5 → 累计 5 < 6 继续；取 4 → 累计 9 ≥ 6 停，答案 **2**；
- **示例 2**：$S = 15$，降序 `capacity = [7,4,2,2]`。累计 7 → 11 → 13 → 15，第 4 个箱子恰好装满，答案 **4**（全部箱子）。

## 4. 算法细节

1. **需求聚合**：先求 $S = \sum \text{apple}$，把「每个包裹多少苹果」的信息压缩成一个标量——这是可拆分条件换来的全部红利，包裹数组此后不再参与计算。
2. **降序排序**：C++ 用 `sort(capacity.rbegin(), capacity.rend())`，Python 用 `sorted(capacity, reverse=True)`。方向**必须从大到小**。
3. **扣减式计数**：维护 `need`（剩余需求）与计数 `k`，每取一个箱子 `need -= capacity[k]; k++`；`need ≤ 0` 即停。等价于「降序前缀和首次 ≥ S 的下标」。
4. **终止性**：题目保证 $\sum \text{capacity} \ge S$，因此循环内 `need` 必然归零，不会数组越界；若去掉该保证，需在循环前检查不足并返回 `-1`。
5. **数据范围**：$S \le 50 \times 50 = 2500$，`int` 毫无溢出风险；排序是唯一非线性开销。

## 5. 正确性证明

**引理 1（可行性刻画）**：箱子集合 $T$ 能装下全部苹果 $\iff$ $\sum_{c \in T} c \ge S$。

**证明**：
（⇐）依次遍历 $T$ 中箱子，只要当前箱子未满就往里放剩余的苹果。假设结束时仍有苹果剩余，则 $T$ 中所有箱子均已装满，已装入数为 $\sum_{c \in T} c \ge S$；但「有剩余」意味着已装入数 $< S$，矛盾。故全部苹果可装入——此方向正是用到**包裹可拆分**：任何一个苹果放进任何一个未满箱子都不违规。
（⇒）装下的苹果总数 $S$ 不超过箱子总容量，故 $\sum_{c \in T} c \ge S$。∎

**引理 2（前 k 大支配）**：设 $c_{(1)} \ge c_{(2)} \ge \dots \ge c_{(m)}$ 为 `capacity` 的降序排列，则对任意大小为 $k$ 的子集 $T$ 有 $\sum_{i=1}^{k} c_{(i)} \ge \sum_{c \in T} c$。

**证明**：将 $T$ 中元素降序排列为 $d_1 \ge d_2 \ge \dots \ge d_k$。对每个 $j$，$T$ 中大于等于 $d_j$ 的元素至多 $j$ 个，故全体中至少有 $j$ 个元素 $\ge d_j$，即 $c_{(j)} \ge d_j$；对 $j = 1, \dots, k$ 逐项相加即得。∎

**定理（贪心最优）**：设 $k^\ast$ 为使 $\sum_{i=1}^{k^\ast} c_{(i)} \ge S$ 成立的最小正整数（题设保证 $k^\ast \le m$），则所需箱子的最小数量为 $k^\ast$。

**证明**：贪心方案取的正是前 $k^\ast$ 大的箱子，由引理 1 可行，故最优值 $\le k^\ast$。反之，设最优方案用了 $t$ 个箱子，由引理 1 其总容量 $\ge S$，再由引理 2 得 $\sum_{i=1}^{t} c_{(i)} \ge S$；由 $k^\ast$ 的最小性得 $t \ge k^\ast$，即最优值 $\ge k^\ast$。综上最优值 $= k^\ast$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m \log m)$。
  - 求苹果总数 $S$ 遍历 `apple` 为 $O(n)$；
  - 排序 `capacity` 为 $O(m \log m)$，是主要开销；
  - 贪心扣减至多走 $m$ 步，每步 $O(1)$。
- **空间复杂度**：$O(1)$（不计排序的栈开销）。
  - 只维护 `need` 与 `k` 两个标量，未使用前缀和数组；原地排序不额外占用与 $m$ 相关的空间。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumBoxes(vector<int>& apple, vector<int>& capacity) {
        int need = accumulate(apple.begin(), apple.end(), 0);  // 剩余需求 = 苹果总数 S
        sort(capacity.rbegin(), capacity.rend());              // 容量降序：大箱子优先
        int k = 0;
        while (need > 0) need -= capacity[k++];                // 题目保证 Σcapacity ≥ need，必不越界
        return k;
    }
};
```

### Python

```python
class Solution:
    def minimumBoxes(self, apple: List[int], capacity: List[int]) -> int:
        need = sum(apple)                                   # 剩余需求 = 苹果总数 S
        for k, c in enumerate(sorted(capacity, reverse=True), 1):
            need -= c
            if need <= 0:                                   # 恰好装满（= S）也要停
                return k
        return len(capacity)                                # 不会到达：题目保证有解
```

## 8. 边界情况与易错点

1. **排序方向写反（本题第一大 WA 点）**：升序取小箱子，示例 1 会算成累计 1 → 3 → 6、误答 3（正确 2）。贪心的方向必须是**容量从大到小**。
2. **误当「不可拆分」问题做**：若包裹必须整体放进一个箱子，就是 bin packing 判定（NP-hard），需要回溯/状压 DP——本题明确「可拆分」，千万别去模拟装箱配对，一个 `sum` 就够了。
3. **停止条件用 `≤` 不是 `<`**：`need == 0`（恰好装满）时必须停，示例 2 恰好在 $15 = 15$ 处收尾；写成 `need < 0` 会多取一个箱子。
4. **题目保证有解 ↔ 防御式写法**：`while` 循环依赖 $\sum \text{capacity} \ge S$ 才不越界；若不放心可先判 `if sum(capacity) < need: return -1`，或在循环条件加 `k < m` 上界。
5. **最小规模**：`n = m = 1` 时直接比较 `capacity[0] ≥ apple[0]`，答案为 1；单个超大箱子（如 `capacity = [50]`）也是一轮即停。
6. **溢出**：$S \le 2500$，`int` 足够；数据范围小到连 `long long` 都不必考虑，赛时应把时间花在读清「可拆分」上。

**延伸思考**：

- **不可拆分版本**：若每个包裹必须整体放入同一箱子，问题变为 bin packing 型 NP-hard：$m$ 小时可状压 DP（$O(2^m \cdot m)$ 子集和 + 装箱判定），$m$ 大只能回溯剪枝或启发式。
- **带成本版本**：若箱子有使用成本 $\text{cost}[i]$，要在总容量 $\ge S$ 的前提下最小化总成本——经典背包模型，$O(mS)$ DP 即可，$S \le 2500$ 时轻松可过。
- **在线版本**：包裹流式到达、必须立刻决定放哪个箱子——First-Fit / Best-Fit 启发式，理论上有 $O(\log m)$ 均摊实现与常数近似比，是装箱理论的入门话题。
