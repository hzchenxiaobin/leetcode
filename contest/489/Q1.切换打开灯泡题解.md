# LeetCode 切换打开灯泡 题解

## 1. 题目概述

- **标题 / 题号**：切换打开灯泡（#3842，easy）
- **链接**：https://leetcode.cn/problems/toggle-light-bulbs/
- **来源**：LeetCode 第 489 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序、模拟

**题意**：有 100 个灯泡，编号 $1 \sim 100$，初始全部**关闭**。给定整数数组 `bulbs`（元素取值 $1 \sim 100$），对其每个元素依次执行：若第 `bulbs[i]` 号灯当前**关闭则打开**、**打开则关闭**（即翻转 toggle）。返回最终处于**打开**状态的灯泡编号列表，**按升序排列**；若无灯打开返回空列表。

**约束**：

- $1 \le |\text{bulbs}| \le 100$
- $1 \le \text{bulbs}[i] \le 100$

> 💡 **审题关键**：① "关则开、开则关"就是**翻转（toggle）**——代码里对状态位取反即可，不必写两个分支；② 输出要求**升序**，而值域只有 $1 \sim 100$，按编号从小到大扫描天然有序，无需排序；③ 数据规模极小怎么写都能过，但值得多想一步：**最终亮不亮到底由什么决定**？

## 2. 示例

**示例 1**

```text
输入：bulbs = [10,30,20,10]
输出：[20,30]
解释：灯 10 被翻两次（开→关）相互抵消；灯 20、30 各被翻一次，最终亮着。
```

**示例 2**

```text
输入：bulbs = [100,100]
输出：[]
解释：灯 100 被翻两次，回到关闭状态，没有灯亮着。
```

**示例 3**

```text
输入：bulbs = [7]
输出：[7]
解释：单元素，灯 7 被翻一次，最终亮着。
```

## 3. 解题思路

### 3.1 暴力思路：直接模拟

开一个长度 101 的布尔数组 `on[]`（下标 $1 \sim 100$），遍历 `bulbs` 对每个 $x$ 执行 `on[x] = !on[x]`，最后扫一遍 $1 \sim 100$ 收集值为 `true` 的编号。

- 时间 $O(n + 100)$、空间 $O(100)$——对这个数据规模已是标答量级。

直接模拟完全正确，但顺着"翻转"再多想一步：**顺序重要吗？** 把 `[10,30,20,10]` 换成 `[20,10,10,30]`，结果会变吗？直觉上不会——把这个直觉说清楚，就能把问题从"时序模拟"降维成"静态计数"。

### 3.2 核心观察：最终态 = 出现次数的奇偶性

![核心观察：翻转两次等于没翻，最终亮不亮只看出出现次数的奇偶](images/wc489_q1_parity_concept.svg)

**观察一：翻转自消。** 对同一盏灯翻转两次，状态回到原点——灯 $x$ 被翻偶数次，等价于从未被碰过。

**观察二：顺序无关。** 灯的状态只有开/关两态，每次翻转等价于在 $\mathbb{Z}_2$（模 2 整数）上做加法：每出现一次就 $+1 \bmod 2$。加法满足交换律与结合律，所以**灯 $x$ 最终亮 $\iff$ $x$ 在 `bulbs` 中出现奇数次**，与元素排列顺序完全无关。

**观察三：值域 $1 \sim 100$ ⇒ 计数数组就是完美哈希表。** 键稠密且极小，无需 `unordered_map` / `Counter`，一个长度 101 的 `int` 数组即可；按 $1 \to 100$ 顺序扫描，输出**天然升序**，连排序都省了（与计数排序同源）。

> 💡 **一句话**：把"模拟翻转"翻译成"统计每个编号出现次数的**奇偶性**"——问题从时序模拟退化为一次计数 + 一次扫描，顺序信息可以整体丢弃。

### 3.3 算法流程

![算法流程：一次计数 + 一次扫描](images/wc489_q1_algorithm_flow.svg)

流程只有两步：

1. 遍历 `bulbs`，对每个 $x$ 执行 `cnt[x]++`；
2. 从 $1$ 到 $100$ 扫描计数数组，`cnt[i]` 为奇数（`cnt[i] & 1`）就把 $i$ 收集进答案。

### 3.4 示例演算

![示例演算：bulbs = 10,30,20,10 的逐步翻转与最终扫描](images/wc489_q1_example_walkthrough.svg)

**示例 1**（`bulbs = [10,30,20,10]`）：

| 元素 | 操作 | 该灯状态 |
|------|------|----------|
| 10 | 灯 10：关 → 开 | 亮 |
| 30 | 灯 30：关 → 开 | 亮 |
| 20 | 灯 20：关 → 开 | 亮 |
| 10 | 灯 10：开 → 关 | 灭 |

扫描 $1 \sim 100$：`cnt[20]`、`cnt[30]` 为奇 → 输出 **[20, 30]** ✓

**示例 2**（`bulbs = [100,100]`）：`cnt[100] = 2` 为偶 → 输出 **[]** ✓

## 4. 算法细节

1. **数据结构选择**：值域 $[1,100]$ 稠密且极小，用长度 101 的计数数组（下标即键值），访问 $O(1)$ 且常数远小于哈希表。
2. **奇偶判断**：`cnt[i] & 1`，与 `cnt[i] % 2` 在非负整数下等价，位与更符合惯用写法。
3. **升序输出**：按编号 $1 \to 100$ 扫描，收集顺序本身就是升序——用有序的遍历顺序替代显式排序。
4. **三种等价写法**：
   - 计数版：`cnt[x]++`，最后收奇数项（本题主推）；
   - 翻转版：`on[x] = !on[x]`，最后收 `true` 项——奇偶性隐含在布尔值里；
   - 集合版：$x$ 在集合中则移除、不在则加入，留在集合里的恰是出现奇数次的编号（最后需排序）。

## 5. 正确性证明

**引理 1（翻转自消）**：对同一盏灯连续执行两次翻转，灯的状态不变。

**证明**：灯状态 $s \in \{0, 1\}$（0 = 关，1 = 开），一次翻转即映射 $s \mapsto 1 - s$。连续两次：$s \mapsto 1 - (1 - s) = s$，回到原状态。即翻转是 $\{0,1\}$ 上的**对合**（involution）。∎

**引理 2（顺序无关）**：灯 $x$ 的最终状态只取决于 $x$ 在 `bulbs` 中出现的总次数 $k_x$，与这些出现位置的先后顺序无关。

**证明**：把灯 $x$ 的状态视为 $\mathbb{Z}_2$ 中的元素，每次 $x$ 出现执行 $s \leftarrow (s + 1) \bmod 2$。模 2 加法满足交换律与结合律，故 $k_x$ 次操作的复合结果为 $s_0 + k_x \cdot 1 \equiv k_x \pmod 2$（初始 $s_0 = 0$），与顺序无关。此外不同编号灯的操作互不干扰，可独立分析。∎

**定理**：灯 $x$ 最终处于打开状态，当且仅当 $x$ 在 `bulbs` 中出现奇数次；按编号 $1 \to 100$ 扫描收集奇数项，得到恰好是答案的升序列表。

**证明**：由引理 2，灯 $x$ 最终状态 $= k_x \bmod 2$，其中 $k_x = \text{cnt}[x]$。$k_x$ 为奇数时 $k_x \bmod 2 = 1$（亮），偶数时为 0（灭）。扫描按 $i = 1, 2, \dots, 100$ 升序进行，仅收集满足 `cnt[i] & 1` 的 $i$，故输出列表恰为所有亮灯编号且严格递增。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + K)$，其中 $K = 100$。计数一遍 $O(n)$，扫描 $1 \sim 100$ 一遍 $O(K)$。
- **空间复杂度**：$O(K)$。长度 101 的计数数组（不计输出数组）。
- **对比**：若值域未知，需改用哈希表 + 排序，时间 $O(n \log n)$、空间 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> toggleLightBulbs(vector<int>& bulbs) {
        int cnt[101] = {0};                 // 值域 1~100：数组即哈希表
        for (int x : bulbs) cnt[x]++;
        vector<int> ans;
        for (int i = 1; i <= 100; i++)      // 按编号扫描，天然升序
            if (cnt[i] & 1) ans.push_back(i);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def toggleLightBulbs(self, bulbs: list[int]) -> list[int]:
        cnt = [0] * 101
        for x in bulbs:
            cnt[x] += 1
        return [i for i in range(1, 101) if cnt[i] & 1]
```

> 💡 也可用翻转版 `on[x] = not on[x]` 或集合增删版，三者完全等价（见 §4），"计数 + 奇偶判断"是值域已知时最直白、最不易错的写法。

## 8. 边界情况与易错点

1. **全部抵消**：所有编号都出现偶数次（如示例 2）→ 返回空列表，扫描收集自然得到 `[]`，无需特判。
2. **输出顺序**：不能按 `bulbs` 的出现顺序输出——`[10,30,20,10]` 按出现顺序会得到 `[30,20]`（错序），必须按编号升序。
3. **数组大小**：计数/布尔数组开 **101**（下标 $1 \sim 100$），下标 0 弃置不用；若开 100 会在 `bulbs[i] = 100` 时越界。
4. **单元素**：$n = 1$ 时灯 `bulbs[0]` 被翻一次，输出 `[bulbs[0]]`。
5. **别写成分支判断**：题面的"关则开、开则关"用取反一行即可，写 `if` 两个分支虽不影响正确性，但容易在状态变量上出低级 bug。
6. **值域思维**：值域已知且小 → 数组计数 + 顺带白拿升序；值域大 → 哈希表 + 显式排序，别硬开大数组。
