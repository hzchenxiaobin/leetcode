# LeetCode 设计电影租借系统 题解

## 1. 题目概述

- **标题 / 题号**：设计电影租借系统（#1912，hard）
- **链接**：https://leetcode.cn/problems/design-movie-rental-system/
- **来源**：LeetCode 第 55 场双周赛 Q4
- **难度**：困难
- **标签**：设计、哈希表、有序集合、堆（优先队列）

**题意**：管理 $n$ 个电影商店与至多 $10^5$ 个拷贝（`entries[i] = [shop, movie, price]`，每店每片至多一份拷贝），实现 `MovieRentingSystem` 类：

- `search(movie)`：拥有**未借出**拷贝的商店中，按「价格升序、价格同按商店编号升序」取**前 5** 个商店；
- `rent(shop, movie)`：借出指定拷贝（题目保证其未借出）；
- `drop(shop, movie)`：归还之前借出的指定拷贝；
- `report()`：所有**已借出**拷贝中，按「价格升序、价格同按商店、商店同按电影编号」取**前 5** 个，输出 `(shop, movie)` 对。

**约束**：

- $1 \le n \le 10^5$，$1 \le \mathit{entries.length} \le 10^5$
- $0 \le \mathit{shop}_i < n$，$1 \le \mathit{movie}_i, \mathit{price}_i \le 10^4$
- 每个商店至多有一份编号 $\mathit{movie}_i$ 的电影拷贝
- `search` / `rent` / `drop` / `report` 的调用总共不超过 $10^5$ 次

## 2. 示例

**示例 1（官方调用序列）**

```text
输入：
["MovieRentingSystem", "search", "rent", "rent", "report", "drop", "search"]
[[3, [[0,1,5],[0,2,6],[0,3,7],[1,1,4],[1,2,7],[2,1,5]]],
 [1], [0,1], [1,2], [], [1,2], [2]]
输出：
[null, [1,0,2], null, null, [[0,1],[1,2]], null, [0,1]]
解释：
search(1) → [1,0,2]：商店 1（价 4）最便宜；商店 0 与 2 同价 5，按编号排。
rent(0,1)、rent(1,2) 后 report() → [[0,1],[1,2]]：5 < 7。
drop(1,2) 后 search(2) → [0,1]：商店 0（价 6）先于商店 1（价 7）。
```

**示例 2（边界补充）**

```text
输入：["MovieRentingSystem","search","report"]
      [[1, [[0,7,9]]], [8], []]
输出：[null, [], []]
解释：查询不存在的电影 8 → 空列表；当前无任何借出 → report 也为空。
```

## 3. 解题思路

### 3.1 暴力思路

把所有拷贝存进数组，每次 `search(movie)` 扫全表筛出该电影的未借出拷贝再排序取前 5，每次 `report()` 扫全表筛已借出再排序。单次 $O(E \log E)$、调用 $10^5$ 次、$E = 10^5$ → 约 $10^{10}$ 量级，不可行。瓶颈在于「**每次查询都从零开始排序**」，而查询的排序键（价格、商店、电影）是**静态**的——拷贝的价格永远不变，变的只有「在柜上还是被借走」这一**二值状态**。这类「静态键 + 动态归属」的 Top-$k$ 查询正是有序集合（平衡树）的用武之地。

### 3.2 核心观察：三个查询视角 → 三个有序容器 + 一张价格索引

![数据结构设计：avail[movie]、priceOf、rented 三容器联动](images/bw55_q4_design_model.svg)

每个拷贝由三元组 `(shop, movie, price)` 唯一确定（每店每片至多一份）。三组操作各自关心一个视角，给每个视角一个**键序恰好匹配题面排序规则**的有序容器：

- **`search` 按「电影」分组**：`avail[movie]` = 该电影所有未借出拷贝的有序集合，键为 `(price, shop)`——正好是题目要求的二级排序；
- **`report` 全局看已借出**：`rented` = 全部已借出拷贝的有序集合，键为 `(price, shop, movie)`——三级排序与题面完全一致；
- **`rent` / `drop` 需要价格**：`(shop, movie)` 查 `price`，用哈希表 `priceOf` 一步取得，避免在容器里反查。

**一条拷贝在两个世界间迁移**：`rent` 把 `(price, shop)` 从 `avail[movie]` 挪进 `rented`；`drop` 反向挪回。两个集合的键不同但元素一一对应，配合 `priceOf` 索引，每次迁移是两次 $O(\log E)$ 的删除加插入。

### 3.3 各操作流程

![rent 与 drop 的容器同步操作流程](images/bw55_q4_operation_flow.svg)

```text
构造：对每个 entries[i]:
    avail[movie] 插入 (price, shop)
    priceOf[(shop, movie)] = price

search(movie):
    若 avail 中无此电影 → 空表
    取有序集合最小端的前 5 个的 shop

rent(shop, movie):
    p = priceOf[(shop, movie)]
    avail[movie] 删除 (p, shop)
    rented 插入 (p, shop, movie)

drop(shop, movie):
    p = priceOf[(shop, movie)]
    rented 删除 (p, shop, movie)
    avail[movie] 插入 (p, shop)

report():
    取 rented 最小端的前 5 个，输出 (shop, movie)
```

### 3.4 官方示例回放

![官方示例回放：search/rent/report/drop 各容器的变化](images/bw55_q4_example_walkthrough.svg)

初始（只列涉影电影 1、2）：`avail[1] = {(4,1), (5,0), (5,2)}`，`avail[2] = {(6,0), (7,1)}`，`rented = {}`。

1. `search(1)`：沿最小端取 `(4,1), (5,0), (5,2)` → 商店序列 `[1, 0, 2]` ✓（同价 5 中 `set` 的第二键自动把商店 0 排在 2 前）；
2. `rent(0,1)`：`avail[1]` 删 `(5,0)` → `{(4,1),(5,2)}`；`rented` 加 `(5,0,1)`；
3. `rent(1,2)`：`avail[2]` 删 `(7,1)`；`rented` 加 `(7,1,2)` → `rented = {(5,0,1), (7,1,2)}`；
4. `report()`：最小端 `(5,0,1), (7,1,2)` → `[[0,1],[1,2]]` ✓；
5. `drop(1,2)`：`rented` 删 `(7,1,2)`；`avail[2]` 加回 `(7,1)` → `{(6,0),(7,1)}`；
6. `search(2)`：`(6,0), (7,1)` → `[0, 1]` ✓。

## 4. 算法细节

1. **排序键与题面逐级对齐**：`search` 要「价格、商店」二级；`report` 要「价格、商店、电影」三级。C++ 里 `set<pair<int,int>>` 与 `set<array<int,3>>` 的字典序**天然**就是这个键序，不需要自定义比较器；Python `SortedList` 里直接放元组同样按字典序。键设计错了，同价场景立刻翻车。
2. **价格索引**：`rent/drop` 的参数只有 `(shop, movie)`，价格要靠 `priceOf[(shop, movie)]` 反查；拷贝唯一性保证这个键不冲突。没有这层索引就得在 `avail[movie]` 里按 `shop` 扫，白白多一个 $\log$ 因子。
3. **删除用精确键值**：`rent` 时 `avail[movie].erase({p, shop})`——`priceOf` 给出 $p$，键完整，一次定位；`drop` 时反向同理。**不要**在 `rented` 里只存 `(shop, movie)`——`report` 的排序需要价格在第一位。
4. **空集合与空键**：某电影全部借出后 `avail[movie]` 变空，留在哈希表里无害；`search` 用 `find` 判存在性后直接遍历，取不满 5 个就全给（循环里 `++k == 5` 自然截断）。
5. **`report` 只取前 5**：有序集合从头遍历 5 个即停，$O(\log E + 5)$；不要 `rented.begin() .. end()` 全量拷贝再截断。
6. **构造复杂度**：$E$ 次有序集合插入共 $O(E \log E)$；`entries` 可达 $10^5$，这部分占总预算但可接受（哈希表插入 $O(1)$ 摊还）。
7. **C++ 结构选择**：`unordered_map<int, set<...>>` 按电影分组 + `map<pair<int,int>,int>` 存价格。`(shop, movie)` 合成单 `long long` 键也能进 `unordered_map`，但 `map` 写法更直观且 $10^5 \log$ 因子无压力。
8. **Python 用 `sortedcontainers.SortedList`**：LeetCode 的 Python 环境预装 `sortedcontainers`；`SortedList` 的 `add/remove` 是 $O(\log n)$ 摊还，切片 `lst[:5]` 取前 5，正合题意。

## 5. 正确性证明

**引理 1（二归属不变量）**：任意时刻，每个拷贝（其 `(shop, movie, price)` 固定不变）**恰好**属于 `avail[movie]` 与 `rented` 之一：未借出 $\iff$ 在 `avail[movie]` 中且不在 `rented` 中；已借出 $\iff$ 在 `rented` 中且不在 `avail[movie]` 中。

**证明**：对操作序列长度归纳。构造后每个拷贝插入 `avail[movie]` 且 `rented` 为空，成立。设某时刻成立：`rent(s,m)` 作用于未借出拷贝，从 `avail[m]` 删除并插入 `rented`，两个归属互换、其余拷贝不动，保持成立；`drop(s,m)` 作用于已借出拷贝，反向同理。∎

**定理（查询正确性）**：每次 `search` / `report` 返回的正是题面要求的有序前 5 列表。

**证明**：由引理 1，`avail[movie]` 恰为「该电影的全部未借出拷贝」，其键序 `(price, shop)` 与题目对 `search` 结果的排序规则逐级一致；有序集合的最小端依次给出全局第 $1, 2, \dots$ 小，故从最小端取的前 5 个（不足则全取）恰为所求。同理 `rented` 恰为全部已借出拷贝，键序 `(price, shop, movie)` 与 `report` 的三级规则一致，最小端前 5 个即所求。∎

## 6. 复杂度分析

- **时间**：构造 $O(E \log E)$（$E = \mathit{entries.length}$）。每次 `search` $O(\log E + 5)$（定位集合 + 遍历 5 个）；每次 `rent` / `drop` $O(\log E)$（两次有序集合的删/插 + 一次哈希查找）；每次 `report` $O(\log E + 5)$。总计 $O((E + Q) \log E)$，$Q$ 为操作次数，$E, Q \le 10^5$ → 约 $6 \times 10^6$ 次比较。
- **空间**：$O(E)$。三个容器各存每份拷贝一份记录（`avail` 存 `(price, shop)`、`priceOf` 存价格、`rented` 只存已借出部分），哈希表的桶开销同阶。

## 7. 参考代码

### C++

```cpp
class MovieRentingSystem {
    unordered_map<int, set<pair<int,int>>> avail;   // movie -> (price, shop) 未租拷贝
    map<pair<int,int>, int> priceOf;                 // (shop, movie) -> price
    set<array<int,3>> rented;                        // (price, shop, movie) 已租拷贝
public:
    MovieRentingSystem(int n, vector<vector<int>>& entries) {
        (void)n;
        for (auto& e : entries) {
            avail[e[1]].insert({e[2], e[0]});
            priceOf[{e[0], e[1]}] = e[2];
        }
    }
    vector<int> search(int movie) {
        vector<int> res;
        auto it = avail.find(movie);
        if (it == avail.end()) return res;
        int k = 0;
        for (auto& [price, shop] : it->second) {    // set 按 (price, shop) 升序
            res.push_back(shop);
            if (++k == 5) break;
        }
        return res;
    }
    void rent(int shop, int movie) {
        int p = priceOf[{shop, movie}];
        avail[movie].erase({p, shop});
        rented.insert({p, shop, movie});
    }
    void drop(int shop, int movie) {
        int p = priceOf[{shop, movie}];
        rented.erase({p, shop, movie});
        avail[movie].insert({p, shop});
    }
    vector<vector<int>> report() {
        vector<vector<int>> res;
        int k = 0;
        for (auto& [p, shop, movie] : rented) {     // set 按 (price, shop, movie) 升序
            res.push_back({shop, movie});
            if (++k == 5) break;
        }
        return res;
    }
};
```

### Python

```python
from sortedcontainers import SortedList

class MovieRentingSystem:
    def __init__(self, n: int, entries: list[list[int]]):
        self.avail = {}                      # movie -> SortedList[(price, shop)]
        self.price_of = {}                   # (shop, movie) -> price
        self.rented = SortedList()           # (price, shop, movie)
        for shop, movie, price in entries:
            self.avail.setdefault(movie, SortedList()).add((price, shop))
            self.price_of[(shop, movie)] = price

    def search(self, movie: int) -> list[int]:
        lst = self.avail.get(movie)
        if not lst:
            return []
        return [shop for _, shop in lst[:5]]  # 切片天然取前 5

    def rent(self, shop: int, movie: int) -> None:
        p = self.price_of[(shop, movie)]
        self.avail[movie].remove((p, shop))
        self.rented.add((p, shop, movie))

    def drop(self, shop: int, movie: int) -> None:
        p = self.price_of[(shop, movie)]
        self.rented.remove((p, shop, movie))
        self.avail[movie].add((p, shop))

    def report(self) -> list[list[int]]:
        return [[shop, movie] for _, shop, movie in self.rented[:5]]
```

> 💡 两份代码均逐项通过官方调用序列回放（`[1,0,2]`、`[[0,1],[1,2]]`、`[0,1]`）；另与「全量扫描 + 排序」的暴力实现在 1.4 万次（C++）/ 5800 次（Python）随机合法操作序列上对拍（`search`/`report` 输出逐项一致），`mismatch = 0`；并冒烟验证 $E = 10^5$、混合 $10^5$ 次操作的性能（C++ 亚秒级）。

## 8. 边界情况与易错点

1. **`report` 的三级排序缺一不可**：同一商店可以同时借出**多部同价电影**，此时必须再按电影编号分先后；只按 `(price, shop)` 排会让这些条目顺序未定义（C++ `set` 中还会因键相同而**丢失重复键**——把拷贝装进 `set<pair>` 会静默吞数据，这是最隐蔽的坑）。
2. **`search` 同价按商店编号**：`(price, shop)` 键序自动满足；若用 `unordered_map` + 每次排序也能对，但每次都 $O(k \log k)$ 且代码丑。
3. **空结果**：查询从未出现的电影、或该电影全部借出 → `search` 返回 `[]`；当前无借出 → `report` 返回 `[]`。C++ 用 `find` 判存在，Python 用 `if not lst`。
4. **删除必须带完整键**：`rent` 时如果忘了先查价格、试图用 `(shop, movie)` 去删 `avail`，要么编译不过要么删错对象；`drop` 后 `avail[movie]` 可能是 `operator[]` 新建的空集合——无害，但别假设它先前一定存在。
5. **`priceOf` 的键类型**：`(shop, movie)` 是两个整数，C++ `map<pair<int,int>,int>` 稳妥；若压成 `shop * 100001 + movie` 的单键，注意位宽与常数选取（`movie ≤ 10^4`，乘子取 $10^4 + 1$ 以上）。
6. **构造别遗漏重复电影**：题目允许不同商店各有一份同电影拷贝（`entries` 中同 `movie` 多行），`avail` 按 `movie` 分组后天然收纳多份。
7. **操作合法性由题目保证**：`rent` 必未租、`drop` 必已租，因此容器删除不会失配；若去掉该保证，需要惰性删除或合法性校验（见延伸思考）。
