# LeetCode 删除一个元素使数组严格递增 题解

## 1. 题目概述

- **标题 / 题号**：删除一个元素使数组严格递增（#1909，easy）
- **链接**：https://leetcode.cn/problems/remove-one-element-to-make-the-array-strictly-increasing/
- **来源**：LeetCode 第 55 场双周赛 Q1
- **难度**：简单
- **标签**：数组、枚举

**题意**：给定下标从 $0$ 开始的整数数组 $\mathit{nums}$，若**恰好删除一个**元素后数组变为**严格递增**，返回 `true`；数组本身已经严格递增时也返回 `true`。严格递增指对所有 $1 \le i < n$ 都有 $\mathit{nums}[i-1] < \mathit{nums}[i]$。

**约束**：

- $2 \le \mathit{nums.length} \le 1000$
- $1 \le \mathit{nums}[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,10,5,7]
输出：true
解释：删除下标 2 处的 10，得到 [1,2,5,7]，严格递增。
```

**示例 2**

```text
输入：nums = [2,3,1,2]
输出：false
解释：删 0 → [3,1,2]，删 1 → [2,1,2]，删 2 → [2,3,2]，删 3 → [2,3,1]，
      没有一个结果严格递增。
```

**示例 3**

```text
输入：nums = [1,1,1]
输出：false
解释：删除任意元素后都是 [1,1]，不严格递增。
```

**示例 4（题面补充）**

```text
输入：nums = [1,2,3]
输出：true
解释：本身已严格递增，无需删除。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**枚举删除每个下标**，再线性检查剩余数组是否严格递增，共 $n$ 次 $O(n)$ 检查，总 $O(n^2)$。本题 $n \le 1000$，$10^6$ 次操作轻松通过，比赛时完全可以直接写。但这类「只允许一处修改」的判定题有一个通用套路值得沉淀：**找到唯一的破坏点，把候选从 $n$ 个压到常数个**。

### 3.2 核心观察：只有「第一个断层」两侧的两个元素是候选

![核心观察：第一个断层 k，只有删 nums[k] 或 nums[k+1] 两种候选](images/bw55_q1_violation_model.svg)

从左往右扫描，找到**第一个**满足 $\mathit{nums}[k] \ge \mathit{nums}[k+1]$ 的下标 $k$（称为**断层**）：

- 若不存在断层，数组本身严格递增，删除任意一个元素后仍然严格递增，直接返回 `true`；
- 若存在断层，则删除任何 $j \notin \{k, k+1\}$ 的元素后，$\mathit{nums}[k]$ 与 $\mathit{nums}[k+1]$ 仍会相邻，断层原样保留——**候选只有两个**：删除 $\mathit{nums}[k]$ 或删除 $\mathit{nums}[k+1]$。

于是只需做两次 $O(n)$ 检查。删除 $\mathit{nums}[k]$ 能成功，当且仅当前缀保持递增（由「$k$ 是首个断层」自动保证）、$\mathit{nums}[k+1]$ 起的后缀递增、且拼接处 $\mathit{nums}[k-1] < \mathit{nums}[k+1]$；删除 $\mathit{nums}[k+1]$ 同理。代码里直接写一个完整的「删除后检查」函数最稳，不必手工拆条件。

### 3.3 算法流程

![算法流程：找断层 → 无断层直接 true → 两种删除各检查一次](images/bw55_q1_algorithm_flow.svg)

```text
1. 扫描找第一个断层 k（nums[k] >= nums[k+1]）
2. 若不存在：返回 true
3. 定义 ok(skip)：跳过下标 skip 后逐对比较，全严格递增则 true
4. 返回 ok(k) 或 ok(k+1)
```

### 3.4 示例演算

![示例演算：[1,2,10,5,7] 删 10 成功；[2,3,1,2] 两种候选都失败](images/bw55_q1_example_walkthrough.svg)

**示例 1**（$[1,2,10,5,7]$）：首个断层 $k = 2$（$10 \ge 5$）。删 $\mathit{nums}[2]$（值 10）得 $[1,2,5,7]$，严格递增 → `true`。

**示例 2**（$[2,3,1,2]$）：首个断层 $k = 1$（$3 \ge 1$）。删 $k = 1$（值 3）得 $[2,1,2]$，$2 \ge 1$ 失败；删 $k+1 = 2$（值 1）得 $[2,3,2]$，$3 \ge 2$ 失败 → `false`。

**示例 3**（$[1,1,1]$）：首个断层 $k = 0$。删任一端得到 $[1,1]$，仍失败 → `false`。

## 4. 算法细节

1. **断层用「大于等于」判定**：严格递增的破坏条件是 $\mathit{nums}[k] \ge \mathit{nums}[k+1]$，相等也算断层（示例 3 的关键）。
2. **只找第一个断层**：`break` 后立即进入候选检查，后面的断层无需记录——若删除候选后数组中仍有断层，`ok` 检查自然会失败。
3. **`ok(skip)` 里用下标追踪前一个保留元素**：`prev` 存上一次未跳过的下标，避免真正构造新数组（省一次拷贝，也让代码更短）。
4. **删除后的拼接条件**：删 $k$ 要求 $\mathit{nums}[k-1] < \mathit{nums}[k+1]$，删 $k+1$ 要求 $\mathit{nums}[k] < \mathit{nums}[k+2]$；两个条件都隐含在通用的 `ok` 检查里。
5. **另一种等价写法（前后缀分解）**：预处理 $\mathit{pre}[i]$ 表示前缀 $[0..i]$ 是否严格递增、$\mathit{suf}[i]$ 表示后缀 $[i..n-1]$ 是否严格递增，则删 $k$ 可行 $\iff \mathit{pre}[k-1] \wedge \mathit{suf}[k+1] \wedge (k=0 \vee \mathit{nums}[k-1] < \mathit{nums}[k+1])$。前后缀数组是这类「删一处」问题的通用武器（也见 8. 相关题目）。

## 5. 正确性证明

**引理 1（严格递增的可删除性）**：严格递增序列删除任意一个元素后仍严格递增。

**证明**：删除后的序列中任取相邻对 $a, b$，它们在原序列中满足 $a < b$，且 $a$ 与 $b$ 之间至多隔着被删除的那个元素 $x$。若中间没有元素则 $a < b$ 原样成立；若有，则 $a < x < b$，故 $a < b$。∎

**引理 2（候选封闭性）**：设 $k$ 是首个断层（$\mathit{nums}[k] \ge \mathit{nums}[k+1]$），则删除任何 $j \notin \{k, k+1\}$ 的元素后，序列都不是严格递增的。

**证明**：删除 $j$ 后，下标 $k$ 与 $k+1$ 的元素（均未被删除）在剩余序列中仍然相邻：$j \le k-1$ 或 $j \ge k+2$ 时，区间 $[k, k+1]$ 内没有元素被删。于是 $\mathit{nums}[k]$ 依旧直接排在 $\mathit{nums}[k+1]$ 前面且 $\mathit{nums}[k] \ge \mathit{nums}[k+1]$，与严格递增矛盾。∎

**定理**：算法返回 `true` 当且仅当存在一个删除方案使数组严格递增。

**证明**：若扫描不到断层，则原数组严格递增，由引理 1 任何删除都成功，返回 `true` 正确。若存在首个断层 $k$：一方面，算法只在 `ok(k)` 或 `ok(k+1)` 为真时返回 `true`，而 `ok(j)` 为真意味着删除 $j$ 后确实严格递增，即方案存在；另一方面，若存在成功的删除方案，其删除位置由引理 2 只能是 $k$ 或 $k+1$，对应 `ok(k)` 或 `ok(k+1)` 为真，算法必返回 `true`。两个方向都成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$。找断层一趟扫描，`ok` 检查至多两次、每次 $O(n)$；总量仍为线性常数倍。
- **空间**：$O(1)$。只用常数个下标变量，不构造新数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canBeIncreasing(vector<int>& nums) {
        int n = nums.size();
        int k = -1;                                  // 第一个断层位置
        for (int i = 0; i + 1 < n; ++i) {
            if (nums[i] >= nums[i + 1]) { k = i; break; }
        }
        if (k < 0) return true;                      // 本身已严格递增
        auto ok = [&](int skip) {                    // 删除下标 skip 后是否严格递增
            int prev = -1;
            for (int i = 0; i < n; ++i) {
                if (i == skip) continue;
                if (prev >= 0 && nums[prev] >= nums[i]) return false;
                prev = i;
            }
            return true;
        };
        return ok(k) || ok(k + 1);                   // 候选只有断层两侧
    }
};
```

### Python

```python
class Solution:
    def canBeIncreasing(self, nums: list[int]) -> bool:
        n = len(nums)
        k = -1                                      # 第一个断层位置
        for i in range(n - 1):
            if nums[i] >= nums[i + 1]:
                k = i
                break
        if k < 0:
            return True                             # 本身已严格递增

        def ok(skip: int) -> bool:                  # 删除下标 skip 后是否严格递增
            prev = None
            for i, v in enumerate(nums):
                if i == skip:
                    continue
                if prev is not None and prev >= v:
                    return False
                prev = v
            return True

        return ok(k) or ok(k + 1)                   # 候选只有断层两侧
```

> 💡 两份代码均通过全部官方示例（`true` / `false` / `false`，及题面补充的 $[1,2,3] \to$ `true`）；另与「枚举删除每个下标再整检」的 $O(n^2)$ 暴力在 5300 组（C++）/ 3000 组（Python）随机数组（含 $n = 2$、全相等、多处断层等模式）上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 2$ 恒为真**：删掉任意一个元素只剩单元素序列，定义上严格递增；$[5,5]$ 应返回 `true`，别按「有断层即失败」误判。
2. **相等即断层**：判定条件是 $\ge$ 而非 $>$，$[1,1,1]$ 这类输入全靠它拦下。
3. **多处断层无需特判**：首个断层之后的第二个断层会让 `ok` 检查失败，逻辑自动覆盖「删一处也救不回来」的情况；但注意 `ok` 必须整条检查，不能只看拼接点（拼接点过了、后面又断了，仍应返回 `false`）。
4. **只检查删除 $k$ 一个候选是错的**：反例 $[1,4,2,3]$——删 $k=1$ 的 4 得 $[1,2,3]$ 才行；而 $[1,2,4,3]$ 要删 $k+1$ 的 3。两种候选都必须试。
5. **拼接条件别写反**：删 $k$ 比较的是 $\mathit{nums}[k-1]$ 与 $\mathit{nums}[k+1]$（越过被删者），不是与 $\mathit{nums}[k]$ 比。
6. **扫描从左开始**：必须取「第一个」断层，否则候选封闭性（引理 2）不成立——后面的断层无法保证其两侧元素在删除后仍相邻。
