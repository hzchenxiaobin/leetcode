# LeetCode 删除一个字符串中所有出现的给定子字符串 题解

## 1. 题目概述

- **标题 / 题号**：删除一个字符串中所有出现的给定子字符串（#1910，medium）
- **链接**：https://leetcode.cn/problems/remove-all-occurrences-of-a-substring/
- **来源**：LeetCode 第 55 场双周赛 Q2
- **难度**：中等
- **标签**：栈、字符串、模拟

**题意**：给定字符串 $s$ 与模式串 $\mathit{part}$，反复执行「找到 $s$ 中**最左边**的 $\mathit{part}$ 出现并删除」直到 $s$ 中不再含有 $\mathit{part}$，返回最终得到的字符串。

**约束**：

- $1 \le s.\mathit{length} \le 1000$
- $1 \le \mathit{part}.\mathit{length} \le 1000$
- $s$ 与 $\mathit{part}$ 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "daabcbaabcbc", part = "abc"
输出："dab"
解释：da[abc]baabcbc → daba[abc]bc → dab[abc] → dab，删除会级联出新匹配。
```

**示例 2**

```text
输入：s = "axxxxyyyyb", part = "xy"
输出："ab"
解释：axxx[xy]yyyb → axx[xy]yyb → ax[xy]yb → a[xy]b → ab。
```

**示例 3（级联效应，来自官方提示的例子）**

```text
输入：s = "ababcc", part = "abc"
输出：""
解释：删下标 2 处的 "abc" 得 "ab" + "c" = "abc"——拼接缝上又拼出了一个新的
      "abc"，再删一次得到空串。删除会级联出新匹配，不能一次扫描定终身；
      另见 §5 末尾 s = "ababa"、part = "aba" 的顺序敏感性反例。
```

## 3. 解题思路

### 3.1 暴力思路

直接模拟题面：每轮在 $s$ 中 `find(part)` 找最左出现，再 `erase` 删除。每轮 $O(n)$ 查找 + $O(n)$ 搬移，最坏 $\lfloor n/m \rfloor$ 轮，总 $O(n^2/m)$。本题 $n \le 1000$ 足够通过，但每次删除后整段字符右移的浪费是刺眼的——被删位置**右侧**的所有字符都要平移，而其中绝大部分与这次删除毫无关系。真正需要的只有拼接缝附近的局部信息。

### 3.2 核心观察：栈维护「已处理前缀的最终形态」，匹配只可能发生在栈顶

![栈模型：字符入栈，栈顶 m 位与 part 相同则整段弹出](images/bw55_q2_stack_model.svg)

把 $s$ 的字符从左到右压入一个栈。维护关键不变量：**栈中从不含 $\mathit{part}$**。压入新字符 $c$ 时，如果栈和 $c$ 拼起来出现了 $\mathit{part}$，这个出现**必然以 $c$ 结尾**——否则它整个落在旧栈里，与不变量矛盾；而「以 $c$ 结尾」的出现至多一个。所以只需检查**栈顶 $m$ 位是否恰好等于 $\mathit{part}$**：是则弹出这 $m$ 个字符（等价于删除拼接缝上的这次出现），否则栈仍然无 $\mathit{part}$。

弹出为什么不会级联出新的匹配？因为弹出后剩下的栈是**原栈的一段前缀**，而原栈本来就不含 $\mathit{part}$——前缀自然也不含。因此每次入栈至多弹出一段，不需要反复检查（这一点与「删除中括号序列」的栈解法略有不同，值得在细节里留意）。

### 3.3 算法流程

![算法流程：入栈 → 比较栈顶 m 位 → 相等则弹出 → 全部入栈后输出栈内容](images/bw55_q2_algorithm_flow.svg)

```text
初始化空栈 st
依次取 s 的每个字符 c：
    st 压入 c
    若 |st| >= m 且 st 顶部的 m 个字符 == part：
        弹出这 m 个字符
处理完所有字符后，栈底到栈顶即为答案
```

### 3.4 示例演算

![示例演算：daabcbaabcbc 按 abc 逐字符入栈/弹出的全过程](images/bw55_q2_example_walkthrough.svg)

以 $s = \text{"daabcbaabcbc"}$、$\mathit{part} = \text{"abc"}$（$m = 3$）为例，关键快照：

| 读入 | 栈内容（操作后） | 动作 |
|------|--------|------|
| d, a, a | `daa` | 依次入栈 |
| b | `daab` | 入栈（顶 3 位 `aab` ≠ `abc`） |
| c | `daa` | 顶 3 位 `abc` 命中 → 弹出 3 个 |
| b, a | `daaba` | 入栈（顶 3 位依次 `aab`、`aba` 不命中） |
| a | `daabaa` | 入栈（顶 3 位 `baa` 不命中） |
| b | `daabaab` | 入栈（顶 3 位 `aab` 不命中） |
| c | `daaba` | 顶 3 位 `abc` 命中 → 弹出 |
| b | `daabab` | 入栈（顶 3 位 `bab` 不命中） |
| c | `dab` | 顶 3 位 `abc` 命中 → 弹出 |

扫描结束栈内为 `dab`，与官方输出一致。

## 4. 算法细节

1. **栈直接用 `string`（C++）或列表（Python）**：`push_back` / `append` 是压栈，`resize(size-m)` / `del st[-m:]` 是弹出 $m$ 个，栈顶就是末尾，比较栈顶 $m$ 位无需额外索引。
2. **比较栈顶 $m$ 位**：C++ 用 `st.compare(st.size() - m, m, part) == 0`（起点是 `size()-m`，长度是 `m`）；Python 先把 `part` 转成列表，再用切片 `st[-m:] == part_list`，每次比较 $O(m)$。
3. **长度不够时跳过比较**：`|st| >= m` 是前置条件，否则 `st[-m:]` 在 C++ 里会越界（Python 切片不报错但语义错误）。
4. **每字符至多弹一次**：弹出后栈是旧栈前缀、仍然无 $\mathit{part}$，不存在连续两次匹配，无需 `while` 循环。这是本题与「括号匹配」类栈题的差别，加了 `while` 不出错，但没有必要。
5. **总复杂度**：每个字符入栈一次、至多被弹出一次，每次入栈附带一次 $O(m)$ 比较，总 $O(nm)$；$n, m \le 1000$ 时最多 $10^6$ 次字符比较。
6. **进阶**：比较可以用字符串哈希或 KMP 把单次比较降到 $O(1)$，但 $O(nm)$ 已绰绰有余，不引入常数与实现复杂度更划算。

## 5. 正确性证明

**引理 1（栈的无匹配不变量）**：若入栈前栈 $S$ 不含 $\mathit{part}$，则按算法压入 $c$ 并（可能）弹出后，栈仍不含 $\mathit{part}$。

**证明**：若 $S + c$ 含 $\mathit{part}$，任一出现要么完全落在 $S$ 内（与 $S$ 无匹配矛盾），要么含末字符 $c$；含 $c$ 的出现必然**以 $c$ 结尾**，而结束位置固定时出现至多一个，且其起终位置唯一确定——即栈顶 $m$ 位。算法恰好检查这一处：命中则弹出后剩余部分是 $S$ 的前缀，从而无匹配；不命中则 $S + c$ 根本不含匹配。两种情况新栈都无匹配。∎

**引理 2（拼接处即最左匹配）**：设 $R = U \cdot v$ 不含 $\mathit{part}$，其中 $v$ 是 $\mathit{part}$ 长度 $m-1$ 的真前缀、$c$ 是 $\mathit{part}$ 的末字符。那么在 $U \cdot \mathit{part} \cdot z$（$z$ 为任意串）中，位置 $|U|$ 处的 $\mathit{part}$ 是**最左**出现。

**证明**：反设存在更左的出现，起点 $q < |U|$。它长度为 $m$，终点为 $q + m - 1 \le |U| + m - 2$，即整个出现都落在 $U \cdot v$（长度 $|U| + m - 1$）之内——与 $R$ 不含 $\mathit{part}$ 矛盾。∎

**定理（与题面过程等价）**：扫描完 $s$ 后，栈中内容恰等于「反复删除最左 $\mathit{part}$」过程的最终结果。

**证明**：记 $\mathrm{LP}(t)$ 为对串 $t$ 反复删除最左 $\mathit{part}$ 后的结果。对已处理前缀长度归纳，证明更强的结论：**对任意不含 $\mathit{part}$ 的栈内容 $R$ 与任意待处理串 $z$，从栈 $R$ 出发扫描 $z$ 后栈内容为 $\mathrm{LP}(R \cdot z)$**。取 $R$ 为空栈、$z$ 为 $s$ 即得定理。

归纳于 $|z|$。$z$ 为空时栈 $R$ 无匹配，$\mathrm{LP}(R) = R$，成立。设 $z = c \cdot z'$。压入 $c$ 后栈为 $R + c$：

- **栈顶 $m$ 位不等于 $\mathit{part}$**：由引理 1 的论证，$R + c$ 不含 $\mathit{part}$，算法等价于从栈 $R+c$ 继续扫描 $z'$，由归纳假设结果为 $\mathrm{LP}((R + c) \cdot z') = \mathrm{LP}(R \cdot z)$，两串完全相同，成立。
- **栈顶 $m$ 位等于 $\mathit{part}$**：此时 $R = U \cdot v$（$v$ 为 $\mathit{part}$ 前 $m-1$ 位，$U$ 为剩余前缀），弹出后栈为 $U$。$R \cdot z = U \cdot v \cdot c \cdot z' = U \cdot \mathit{part} \cdot z'$。由引理 2，位置 $|U|$ 处的 $\mathit{part}$ 是最左出现，故 $\mathrm{LP}(U \cdot \mathit{part} \cdot z') = \mathrm{LP}(U \cdot z')$——先删掉这个最左出现，再对剩余部分继续过程。算法从栈 $U$ 扫描 $z'$，由归纳假设得 $\mathrm{LP}(U \cdot z')$，两路相等。∎

> ⚠️ **顺序并不是无关紧要的**：取 $\mathit{part} = \text{"aba"}$、$s = \text{"ababa"}$，先删左边（下标 0）得 `"ba"`，先删右边（下标 2）得 `"ab"`——两种删法给出不同终态。所以本题答案依赖题面钦定的「最左边」策略，引理 2 正是把「栈的局部弹出」与「最左删除」对上的关键；一般的字符串重写系统并不保证这种一致性。

## 6. 复杂度分析

- **时间**：$O(nm)$。每字符一次入栈、至多一次弹出；每次入栈伴随一次 $O(m)$ 的栈顶比较。$n, m \le 1000$ 时约 $10^6$ 次字符操作。
- **空间**：$O(n)$。栈至多同时保存 $n$ 个字符；无需保存原串的副本之外的任何结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string removeOccurrences(string s, string part) {
        int m = part.size();
        string st;                                   // string 直接当栈，末尾即栈顶
        for (char c : s) {
            st.push_back(c);
            if ((int)st.size() >= m && st.compare((int)st.size() - m, m, part) == 0)
                st.resize((int)st.size() - m);       // 栈顶 m 位恰为 part → 整段弹出
        }
        return st;
    }
};
```

### Python

```python
class Solution:
    def removeOccurrences(self, s: str, part: str) -> str:
        m = len(part)
        plist = list(part)                   # 预转换，避免每次比较都重建
        st = []
        for c in s:
            st.append(c)
            if len(st) >= m and st[-m:] == plist:
                del st[-m:]                   # 栈顶 m 位恰为 part → 整段弹出
        return ''.join(st)
```

> 💡 两份代码均通过全部官方示例（`"dab"`、`"ab"`），并通过顺序敏感样例 `"ababa"`/`"aba"` → `"ba"`；另与「每轮 find 最左 + erase」的题面暴力在 8400 组（C++）/ 4000 组（Python）随机串（小字母表制造密集重叠）与 $10^3$ 长大串上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$\mathit{part}$ 比 $s$ 长**：栈永远凑不齐 $m$ 位，原样返回 $s$；比较前的 `|st| >= m` 检查防越界。
2. **级联匹配的位置在栈里不在原串里**：`"axxxxyyyyb"` 中 `"xy"` 的匹配串位置并不连续，但栈弹出后 $x$ 与 $y$ 会相遇——这是必须用栈而不是原地双指针的原因。
3. **弹出后不要再检查**：弹出后栈是原栈前缀，必无匹配；写 `while` 反复检查虽不至出错，但会把复杂度分析搅浑。
4. **`compare` / 切片的参数**：C++ `st.compare(pos, m, part)` 的 `pos = st.size() - m` 是起点；Python `st[-m:]` 在 $|st| < m$ 时静默返回整个列表，必须先判长度。
5. **答案顺序**：栈从底到顶就是从左到右，直接输出即可，别反向。
6. **相等元素不触发**：$\mathit{part}$ 是普通字符串，比较必须整段一致；`"aa"` 栈顶只有恰好两个 `a` 时才弹，一个不行。
