# LeetCode 最大交替子序列和 题解

## 1. 题目概述

- **标题 / 题号**：最大交替子序列和（#1911，medium）
- **链接**：https://leetcode.cn/problems/maximum-alternating-subsequence-sum/
- **来源**：LeetCode 第 55 场双周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划

**题意**：数组的**交替和**定义为（下标从 $0$ 重新编号）偶数下标元素之和减去奇数下标元素之和。给定正整数数组 $\mathit{nums}$，求其**任意子序列**（可空）的交替和的最大值。

**约束**：

- $1 \le \mathit{nums.length} \le 10^5$
- $1 \le \mathit{nums}[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,5,3]
输出：7
解释：最优子序列 [4,2,5]，交替和 (4 + 5) − 2 = 7。
```

**示例 2**

```text
输入：nums = [5,6,7,8]
输出：8
解释：最优子序列 [8]，交替和为 8。
```

**示例 3**

```text
输入：nums = [6,2,1,2,4,5]
输出：10
解释：最优子序列 [6,1,5]，交替和 (6 + 5) − 1 = 10。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $2^n$ 个子序列、各自重排下标算交替和取最大，$n = 10^5$ 下是天方夜谭。退一步想「交替和」的结构：一个子序列的交替和只取决于**每个被选元素落在子序列的奇数位还是偶数位**，而奇偶位沿着子序列交替。于是从左往右扫数组、逐个决定「不选 / 选为偶位（加）/ 选为奇位（减）」时，影响后续决策的历史信息只有「当前子序列最后一位的奇偶」——这正是 DP 的状态。

### 3.2 核心观察：只需两个状态——子序列末尾落在偶位还是奇位

![双状态模型：even 与 odd 两类子序列，元素可选为 + 位或 − 位](images/bw55_q3_state_model.svg)

定义两个滚动量：

- $\mathit{even}$：已处理前缀中，「末尾元素落在**偶位**（被**加**）」的子序列的最大交替和；
- $\mathit{odd}$：同前缀中，「末尾元素落在**奇位**（被**减**）」的最大交替和。

考察新元素 $x$，只有三种选择：

- **不选 $x$**：两个量不变；
- **选 $x$ 作新的偶位结尾**：接在某个奇位结尾的最优子序列后（$\mathit{odd} + x$），或者单开一个长度为 1 的子序列（$x$）；
- **选 $x$ 作新的奇位结尾**：只能接在偶位结尾的最优子序列后（$\mathit{even} - x$）——长度为 1 的子序列末尾必然是偶位，不存在「天生奇位」。

由于所有元素为正，最优子序列的末项一定落在偶位（把偶数长度的最优解砍掉末项，去掉的是一个被减的数，交替和严格变大），所以**最终答案是 $\mathit{even}$**。

### 3.3 状态转移

![状态转移图：even/odd 互为对方的前驱，含自环与新建](images/bw55_q3_transition_flow.svg)

$$
\begin{aligned}
\mathit{even}' &= \max(\mathit{even},\ \mathit{odd} + x,\ x)\\
\mathit{odd}' &= \max(\mathit{odd},\ \mathit{even} - x)
\end{aligned}
$$

初值 $\mathit{even} = 0$（空子序列），$\mathit{odd} = -\infty$（尚不存在奇位结尾的子序列）。逐元素滚动更新，最后返回 $\mathit{even}$。

### 3.4 示例演算

![示例演算：[6,2,1,2,4,5] 逐步的 even/odd 值](images/bw55_q3_example_walkthrough.svg)

以 $\mathit{nums} = [6,2,1,2,4,5]$ 为例：

| 读入 $x$ | $\mathit{even}$ | $\mathit{odd}$ | 说明 |
|------|------|------|------|
| 初始 | $0$ | $-\infty$ | 空子序列；奇位尚不可行 |
| 6 | $6$ | $-6$ | $\mathit{even}$：单开 $[6]$；$\mathit{odd} = 0 - 6$ 是「空序列 − 6」的记账值 |
| 2 | $6$ | $4$ | $\mathit{even}$ 不动；$\mathit{odd} = 6 - 2$（子序列 $[6,2]$） |
| 1 | $6$ | $5$ | $[6,1]$ 更优 |
| 2 | $7$ | $5$ | $\mathit{even} = \mathit{odd} + 2 = 5+2$（$[6,1,2]$） |
| 4 | $9$ | $5$ | $\mathit{even} = 5 + 4$（$[6,1,4]$） |
| 5 | $10$ | $5$ | $\mathit{even} = 5 + 5$（$[6,1,5]$） |

返回 $\mathit{even} = 10$，对应子序列 $[6,1,5]$，与官方一致。

> ⚠️ 首行的 $\mathit{odd} = -6$ 并不对应任何真实的「奇位结尾」子序列（单元素 $[6]$ 的末项在偶位）——它来自转移 $\mathit{odd} \gets \mathit{even} - x$ 在 $\mathit{even} = 0$（空序列）时的**记账值**。它永远是负数，在后续 $\mathit{odd} + x' \le x' - 1 < x'$ 中被「单开 $x'$」候选支配，因此不会污染答案（见 §5 引理 2 的精确刻画）。

## 4. 算法细节

1. **答案取 $\mathit{even}$ 的依据**：元素全为正，若最优子序列长度为偶数（末项被减），删掉末项会让交替和严格增大，矛盾；空子序列交替和为 $0$，也被任何单元素压过。故最优值必是某个偶位结尾的状态。
2. **$-\infty$ 的实现**：C++ 用 `-(1LL << 60)` 而不是 `LLONG_MIN`——后者在 $\mathit{odd} + x$ 时会直接溢出未定义；Python 用 `float('-inf')`（与整数相加仍是 `inf` 参与比较，不影响取 `max` 的正确性）。
3. **两行转移必须同时更新**：`even, odd = ...` 一次性赋值，C++ 里先算 `ne/no` 两个临时量再赋回，否则用到的新值会是旧值（顺序依赖 bug）。
4. **$\mathit{odd}$ 里的记账值**：$\mathit{odd} \gets \mathit{even} - x$ 在 $\mathit{even} = 0$（空序列）时会得到 $-x$，它不对应真实子序列，但恒为负、总是被「单开 $x'$」候选支配，不影响 $\mathit{even}$ 的正确性（§5 引理 2 有精确刻画）——这是该 DP 写法里最常见的隐性简化，值得心里有数。
5. **返回类型**：交替和最大约 $10^5 \times \lceil n/2 \rceil \approx 5 \times 10^9$，超过 `int`，必须 `long long` / Python 任意精度。
6. **贪心的另一视角**（见延伸思考）：最优解在「峰取正、谷取负」结构下等价于 $\mathit{nums}[0] + \sum_i \max(0, \mathit{nums}[i+1] - \mathit{nums}[i])$，单趟贪心同样 $O(n)$；DP 版不依赖「元素为正」之外的结构性质，更耐变形。

## 5. 正确性证明

**引理 1（最优解以偶位收尾）**：存在一个最优子序列，其长度为奇数（末项落在偶位）。

**证明**：设最优子序列 $T$ 长度为偶数，则其交替和 $\mathit{alt}(T) = \dots - t_{\text{last}}$，删去末项得 $T'$，$\mathit{alt}(T') = \mathit{alt}(T) + t_{\text{last}} > \mathit{alt}(T)$（$t_{\text{last}} \ge 1 > 0$），与 $T$ 最优矛盾。又空序列（$0$）不优于任何单元素子序列（$\ge 1$），故最优子序列非空、长度为奇数。∎

**引理 2（状态刻画）**：处理完前 $i$ 个元素后：

(a) $\mathit{even}_i$ 恰等于「前缀中末项落在偶位的子序列（含空序列，记 $0$）」的交替和最大值 $E_i$；

(b) $\mathit{odd}_i$ 恰等于 $\tilde O_i$：所有「末项落在奇位的子序列」的交替和，与所有「空序列 − 前缀某元素 $x$」的记账值 $-x$ 这两类数的最大值。

**证明**：对 $i$ 归纳。$i = 0$：只有空子序列，$\mathit{even}_0 = 0 = E_0$、$\mathit{odd}_0 = -\infty = \tilde O_0$，成立。设 $i$ 时成立，考察 $i+1$（记 $x = \mathit{nums}[i]$）：

先证 (b)。$\mathit{odd}_{i+1} = \max(\mathit{odd}_i,\ \mathit{even}_i - x)$。前一候选不使用 $x$，恰对应 $\tilde O_i$ 中的存量；后一候选中，$\mathit{even}_i$ 若由非空偶位结尾子序列取得，则接上 $x$ 得真实的奇位结尾子序列；若由空序列取得，则产生记账值 $-x$。两类合起来恰是 $\tilde O_{i+1}$ 的定义。

再证 (a)。$\mathit{even}_{i+1} = \max(\mathit{even}_i,\ \mathit{odd}_i + x,\ x)$。一方面每个候选都不超过 $E_{i+1}$：「不使用 $x$」的候选为 $E_i \le E_{i+1}$；「$\mathit{odd}_i + x$」中，若 $\mathit{odd}_i$ 来自真实奇位结尾子序列，接上 $x$ 是前缀 $i+1$ 的合法偶位结尾子序列，值 $\le E_{i+1}$，若来自记账值 $-x_0$，则 $-x_0 + x \le x - 1 < x \le E_{i+1}$（元素 $\ge 1$），被单开候选支配；「$x$」即单元素 $[x]$。另一方面，$E_{i+1}$ 的最优子序列若不含 $x$ 则 $\le E_i$，若为 $[x]$ 则等于 $x$，若以 $x$ 收尾且更长，则其前缀是真实的奇位结尾子序列、值 $v$ 满足 $v \le O_i \le \mathit{odd}_i$，于是 $E_{i+1} = v + x \le \mathit{odd}_i + x$。三个候选覆盖并达到 $E_{i+1}$，故 $\mathit{even}_{i+1} = E_{i+1}$。∎

**定理**：算法返回 $\mathit{nums}$ 所有子序列交替和的最大值。

**证明**：由引理 2(a)，$\mathit{even}_{n-1} = E_{n-1}$，即末项落在偶位（含空序列）的最大交替和；由引理 1，全局最优值恰等于该值（最优解以偶位收尾，且空序列 $0$ 不优于任何单元素）。算法返回 $\mathit{even}_{n-1}$，得证。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素一次常数时间转移，单趟扫描。
- **空间**：$O(1)$。只维护两个滚动变量，不保留 DP 表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxAlternatingSum(vector<int>& nums) {
        long long even = 0, odd = -(1LL << 60);      // 末尾偶位(+) / 奇位(−) 的最优交替和
        for (int x : nums) {
            long long ne = max({even, odd + x, (long long)x});  // x 作新的偶位结尾
            long long no = max(odd, even - x);        // x 作新的奇位结尾
            even = ne;
            odd = no;
        }
        return even;                                  // 最优解必以偶位(+)收尾
    }
};
```

### Python

```python
class Solution:
    def maxAlternatingSum(self, nums: list[int]) -> int:
        even, odd = 0, float('-inf')          # 末尾偶位(+) / 奇位(−) 的最优交替和
        for x in nums:
            even, odd = max(even, odd + x, x), max(odd, even - x)
        return even                            # 最优解必以偶位(+)收尾
```

> 💡 两份代码均通过全部官方示例（`7`、`8`、`10`）；另与「枚举 $2^n$ 全部子序列」的暴力在 4000 组（C++）/ 2000 组（Python）随机数组（$n \le 12$）上对拍，`mismatch = 0`；另验证 $n = 10^5$、元素全为 $10^5$ 与严格递减等极端输入的单趟性能与已知答案。

## 8. 边界情况与易错点

1. **单元素数组**：`odd` 初值为 $-\infty$ 时第一步转移必须不让它参与有效比较（C++ 的 $-2^{60}$ 加 $10^5$ 不会溢出；若误用 `LLONG_MIN` 则 `odd + x` 溢出为未定义行为）。
2. **答案类型**：最大可达约 $5 \times 10^9$，C++ 返回 `long long`，把累加变量也声明成 `long long`，别在 `int` 里溢出再转。
3. **转移顺序**：`even` 与 `odd` 相互引用，必须同时更新（临时变量或元组赋值），否则第二轮转移用到被覆盖的旧值。
4. **「选作奇位」没有单开选项**：长度为 1 的子序列末项在偶位，奇位状态只能由偶位延伸而来，多写一个 `x` 进 $\mathit{odd}$ 的候选是逻辑错误（会在如 $[5, 6]$ 这类输入上给出 $5 - 6 = -1$ 之类的怪值候选，虽被 $\max$ 淹没但属于错误转移）。
5. **空子序列的 $0$ 不是答案**：元素全正时答案至少是最大单元素；不要把初值 `even = 0` 误设为 $-\infty$ 再丢掉空序列的合法基线——设成 $-\infty$ 反而没错（首个元素必然单开），但要保证 $\mathit{even}$ 的候选里有 `x`。
6. **「先减后加」的两元素局部**：如 $[6, 1, 5]$ 中「谷」被减、两侧「峰」被加，扫描时不要试图局部贪心跳过谷——DP 已经自动处理「跨谷拼接」，手工贪心容易在平顶/平台序列上出错。
