# LeetCode 简易银行系统 题解

## 1. 题目概述

- **标题 / 题号**：简易银行系统（#2043，medium）
- **链接**：https://leetcode.cn/problems/simple-bank-system/
- **来源**：LeetCode 第 263 场周赛 Q2
- **难度**：中等
- **标签**：设计、数组、模拟

**题意**：

为一家有 $n$ 个账户的银行实现一个交易处理程序。账户编号 $1$ 到 $n$，初始余额存放在**下标从 0 开始**的数组 `balance` 中（第 $i+1$ 个账户的初始余额是 `balance[i]`）。要求实现 `Bank` 类的三个方法：

- `transfer(account1, account2, money)`：从 `account1` 向 `account2` 转账 `money`；
- `deposit(account, money)`：向 `account` 存入 `money`；
- `withdraw(account, money)`：从 `account` 取出 `money`。

交易**有效**当且仅当同时满足：① 涉及的账户编号都在 $[1, n]$ 内；② 取款/转账金额**小于或等于**付款账户余额。有效交易执行并返回 `true`；无效交易**不修改任何余额**，返回 `false`。

**约束**：

- $1 \le n \le 10^5$，$1 \le \text{account}, \text{account1}, \text{account2} \le 10^5$
- $0 \le \text{balance[i]}, \text{money} \le 10^{12}$
- `transfer` / `deposit` / `withdraw` 各被调用**至多 $10^4$ 次**

> 💡 数据范围里埋着两个坑：账户编号上界 $10^5$ **可以超过** $n$（越界编号必须拦下，编号合法性与 $n$ 挂钩）；余额与金额到 $10^{12}$ 且可累加（32 位整数存不下）。约束本身就是考点。

## 2. 示例

**示例 1**

```text
输入：
["Bank", "withdraw", "transfer", "deposit", "transfer", "withdraw"]
[[[10, 100, 20, 50, 30]], [3, 10], [5, 1, 20], [5, 20], [3, 4, 15], [10, 50]]
输出：
[null, true, true, true, false, false]

解释：
bank = Bank([10, 100, 20, 50, 30])      // n = 5
withdraw(3, 10)    // true  账户 3 余额 20 ≥ 10，取后 [10, 100, 10, 50, 30]
transfer(5, 1, 20) // true  账户 5 余额 30 ≥ 20，转后 [30, 100, 10, 50, 10]
deposit(5, 20)     // true  编号合法即可存，存后 [30, 100, 10, 50, 30]
transfer(3, 4, 15) // false 账户 3 余额 10 < 15，闸门②拦截
withdraw(10, 50)   // false 编号 10 > n = 5，闸门①拦截
```

**示例 2（自转账）**

```text
输入：Bank([10]) 后依次调用 transfer(1, 1, 20)、transfer(1, 1, 5)
输出：false, true
解释：自转账同样要过余额闸门——余额 10 < 20 时返回 false；
transfer(1, 1, 5) 合法，扣 5 再存 5，余额仍是 10（净变化 0）。
```

**示例 3（零元交易与下界编号）**

```text
输入：Bank([0]) 后依次调用 withdraw(1, 0)、deposit(0, 5)、deposit(1, 0)
输出：true, false, true
解释：money = 0 恒满足 0 ≤ 余额（含余额 0），取 0 元成功；
account = 0 不在 [1, n] 内，闸门①拦截；编号 1 合法，存 0 元成功。
```

## 3. 解题思路

### 3.1 暴力思路

两条「能过但不该写」的路线：

1. **线性扫描找账户**：把账户编号当「名字」，每次操作遍历 `balance` 数组找编号匹配的位置。单次 $O(n)$，总开销 $10^4 \times 10^5 = 10^9$ 量级——C++ 贴着时限，Python 必然超时。更本质的问题是**完全多余**：编号本身就是位置。
2. **哈希表映射**：`unordered_map<int, long long>` 以编号为键，平均 $O(1)$，能过。但键恰好是 $1..n$ 的连续整数——**数组就是最完美的哈希表**，再套一层哈希函数、冲突探测、缓存不友好，全是白送的劣势。周赛里写哈希表不算错，但数组直接寻址是更短的代码与更快的常数。

### 3.2 核心观察：编号即下标 + 两道校验闸门

![核心概念：编号 i 直接映射 bal[i−1]，两道闸门组合出三操作的校验规则](images/wc263_q2_index_gates_concept.svg)

- **观察一（直接寻址）**：编号 $i$ 的账户就是 `bal[i-1]`，一次减法完成 $O(1)$ 定位。全场唯一的心智负担是这个 **−1 偏移**：误写 `bal[account]` 在 `account = n` 时越界。
- **观察二（两道闸门）**：题面的有效性条件拆成两道独立闸门——**闸门①（范围）**：$1 \le \text{account} \le n$；**闸门②（余额）**：$\text{money} \le \text{bal}[\text{account}-1]$。三操作的过闸要求分别是：`deposit` 只过①；`withdraw` 过①②；`transfer` 要求 $a_1, a_2$ 都过①且 $a_1$ 过②。
- **观察三（先校验后修改）**：所有闸门全部放行才触碰数组。这一顺序让失败交易天然**零副作用**——`transfer` 若先扣 $a_1$ 再发现 $a_2$ 越界，就得写回滚逻辑；先过闸再动账，回滚根本不存在。

> 💡 本题是「设计题外衣下的模拟题」：没有算法难度，得分点全在**边界与契约**——下标偏移、双向范围检查、64 位溢出、自转账、零副作用。Q2 的定位就是考手稳。

### 3.3 算法流程

![算法流程：transfer 的两道闸门串行校验，全过才原子入账](images/wc263_q2_transfer_flow.svg)

以最复杂的 `transfer` 为例：

1. **闸门①（双账户）**：`1 ≤ a1 ≤ n` 且 `1 ≤ a2 ≤ n`，任一不满足直接 `return false`；
2. **闸门②（付款方余额）**：`bal[a1-1] >= money`，不满足 `return false`；
3. **原子入账**：`bal[a1-1] -= money; bal[a2-1] += money;`，返回 `true`。

`deposit` / `withdraw` 是同一流程的子集（见流程图左侧姊妹操作）：`deposit` 只有闸门①，`withdraw` 是①+②。三个方法共用一个私有谓词 `valid(acc)`，代码最短。

### 3.4 示例演算

![示例演算：五次调用的余额快照，第 4、5 行被闸门拦截后余额纹丝不动](images/wc263_q2_walkthrough.svg)

| 步骤 | 调用 | 闸门① | 闸门② | 执行后余额 | 返回 |
|---|---|---|---|---|---|
| 0 | 初始化 | — | — | [10, 100, 20, 50, 30] | — |
| 1 | `withdraw(3, 10)` | 3 ✓ | 20 ≥ 10 ✓ | [10, 100, **10**, 50, 30] | true |
| 2 | `transfer(5, 1, 20)` | 5 ✓ 1 ✓ | 30 ≥ 20 ✓ | [**30**, 100, 10, 50, **10**] | true |
| 3 | `deposit(5, 20)` | 5 ✓ | 不查 | [30, 100, 10, 50, **30**] | true |
| 4 | `transfer(3, 4, 15)` | 3 ✓ 4 ✓ | 10 < 15 ✗ | [30, 100, 10, 50, 30]（不变） | false |
| 5 | `withdraw(10, 50)` | 10 > 5 ✗ | 不再检查 | [30, 100, 10, 50, 30]（不变） | false |

两个自检锚点：**资金守恒**——第 2 行 `transfer` 使 5 号 −20、1 号 +20，账户总额不变，全程轨迹 $210 \to 200 \to 200 \to 220 \to 220$（只有 deposit/withdraw 改变总额）；**零副作用**——第 4、5 行校验失败后余额数组原地不动，最终状态停在第 3 行的快照。

## 4. 算法细节

1. **存储**：构造时把 `balance` 拷贝进成员数组。C++ 用 `vector<long long>`（接口已给 `long long`，内部全程别降级成 `int`）；Python 用 `self.bal = balance[:]` 防御性拷贝，避免与外部共享可变状态。
2. **共用谓词**：私有 `valid(acc)` 判断 `1 <= acc && acc <= n`，三个方法复用；`n` 直接用 `bal.size()`，不必单独存成员。
3. **校验顺序**：先①后②。闸门①是 $O(1)$ 纯比较且能挡住一切越界访问，必须放在**任何数组下标之前**——若把 `bal[account-1] < money` 写在范围检查前，`account = 0` 时 Python 取到 `bal[-1]`（静默错账），C++ 直接未定义行为。
4. **transfer 的写法**：两道闸门写进同一个 `if` 条件（`&&` 短路求值天然保证顺序），全过再执行减、加两条赋值。自转账 `a1 == a2` 不需要任何特判——`-= money` 再 `+= money` 净变化为零。
5. **溢出核算**：余额峰值 $\le 10^{12} + 10^4 \times 10^{12} \approx 10^{16}$（初始上界 + 全部存款累计），远超 `int32`（$\approx 2.1 \times 10^9$）而稳居 `int64`（$\approx 9.2 \times 10^{18}$）之内。其实**单次** `deposit` 就可能把某账户推到 $10^{12} + 10^{12} = 2 \times 10^{12}$，`int` 在第一个大样例就炸——不需要等到累积。

## 5. 正确性证明

**引理 1**（非负不变式）：若初始所有余额 $\ge 0$，则任意时刻所有余额 $\ge 0$。

**证明**：对成功调用次数归纳。奠基：构造时余额即初始值 $\ge 0$。归纳步：`deposit` 只增加目标账户余额；`withdraw` 与 `transfer` 成功的前提是闸门② $\text{money} \le \text{bal}[a_1 - 1]$，故付款方扣减后 $\text{bal}[a_1-1] - \text{money} \ge 0$，收款方（若有）只增不减，其余账户不动；失败调用不修改数组。故不变式始终保持。∎

**引理 2**（判定等价）：三个方法返回 `true` 当且仅当该交易按题面定义有效。

**证明**：逐操作对照。`deposit` 的有效条件只有「编号在 $[1,n]$」，算法恰检查闸门①；`withdraw` 的有效条件是①与②的合取，算法检查 `valid(acc) && bal[acc-1] >= money`，逐字对应；`transfer` 的有效条件是 $a_1, a_2$ 编号均合法且转账金额 $\le a_1$ 余额，算法检查 `valid(a1) && valid(a2) && bal[a1-1] >= money`，同样逐字对应。三者的 `false` 分支均不触碰数组，与「无效交易不执行」的要求一致。∎

**定理**：对任意调用序列，算法维护正确的账户状态——每个方法返回 `true` 恰当且仅当交易有效，且此时余额恰按交易语义更新。

**证明**：由引理 2，返回值与题面有效性定义一致。只需再证成功路径的更新语义：`deposit` 使目标账户恰增加 `money`；`withdraw` 使目标账户恰减少 `money`；`transfer` 使 $a_1$ 减少、$a_2$ 增加同一 `money`，其余账户不动——三条均为方法体内两条赋值语句的直接语义，且由引理 1，更新后各账户余额非负（账户状态始终合法）。失败路径不修改数组，与「不执行无效交易」一致。∎

## 6. 复杂度分析

- **时间复杂度**：初始化 $O(n)$（拷贝余额数组）；`transfer` / `deposit` / `withdraw` 均为 $O(1)$——常数次比较加至多两次加减，与 $n$、操作总数无关。全程 $O(n + q)$，$q \le 3 \times 10^4$。
- **空间复杂度**：$O(n)$ 存余额表。若 C++ 用移动构造原地接管传入数组、Python 直接持有引用，可降到 $O(1)$ 额外空间，但会与调用方共享可变状态——防御性拷贝是更稳的默认。

## 7. 参考代码

### C++

```cpp
class Bank {
    vector<long long> bal;

    bool valid(int acc) const {          // 闸门①：双向范围检查
        return 1 <= acc && acc <= (int)bal.size();
    }

public:
    Bank(vector<long long>& balance) : bal(balance) {}

    bool transfer(int account1, int account2, long long money) {
        if (!valid(account1) || !valid(account2)          // 闸门① × 2
            || bal[account1 - 1] < money) return false;   // 闸门②（付款方）
        bal[account1 - 1] -= money;                       // 先校验后修改
        bal[account2 - 1] += money;
        return true;
    }

    bool deposit(int account, long long money) {
        if (!valid(account)) return false;                // 存款只过闸门①
        bal[account - 1] += money;
        return true;
    }

    bool withdraw(int account, long long money) {
        if (!valid(account) || bal[account - 1] < money) return false;
        bal[account - 1] -= money;
        return true;
    }
};
```

### Python

```python
class Bank:
    def __init__(self, balance: List[int]):
        self.bal = balance[:]                      # 防御性拷贝

    def _valid(self, acc: int) -> bool:            # 闸门①：双向范围检查
        return 1 <= acc <= len(self.bal)

    def transfer(self, account1: int, account2: int, money: int) -> bool:
        if not (self._valid(account1) and self._valid(account2)):
            return False                           # 闸门① × 2
        if self.bal[account1 - 1] < money:
            return False                           # 闸门②（付款方）
        self.bal[account1 - 1] -= money            # 先校验后修改
        self.bal[account2 - 1] += money
        return True

    def deposit(self, account: int, money: int) -> bool:
        if not self._valid(account):
            return False                           # 存款只过闸门①
        self.bal[account - 1] += money
        return True

    def withdraw(self, account: int, money: int) -> bool:
        if not self._valid(account) or self.bal[account - 1] < money:
            return False
        self.bal[account - 1] -= money
        return True
```

> 💡 两份实现均已对拍验证：官方示例（`[null, true, true, true, false, false]`）、自转账（`transfer(1,1,20)` 余额 10 → `false`；`transfer(1,1,5)` → `true` 且余额不变）、零元交易（余额 0 取 0 元 → `true`）、`account = 0` 与 `account = n+1` 越界、大数压力（$10^{12}$ 余额连存 $10^4$ 次 $10^{12}$ → 余额 $\approx 10^{16}$，C++ `long long` 与 Python 一致）。

## 8. 边界情况与易错点

1. **下标偏移 −1**：编号 $i$ ↔ `bal[i-1]`。误写 `bal[account]`：`account = n` 时越界（C++ UB / Python `IndexError`）；`account < n` 时改错账户——**不崩溃但答案错**，更隐蔽。
2. **范围检查必须双向**：只写 `account <= n` 漏掉下界，`account = 0` 时 Python `bal[-1]` **静默访问末元素**——返回 `true` 且改动最后一个账户，错账不报错；C++ 则是越界 UB。`1 <= acc` 与 `acc <= n` 一个都不能少。
3. **32 位溢出**：单次 `deposit` 即可把余额推到 $2 \times 10^{12}$，持续存款推到 $\approx 10^{16}$，`int` 必炸。C++ 全程 `long long`（接口已给，内部别转 `int`）；Python 无此忧。
4. **自转账**：`a1 == a2` 无需特判，减加相消。**危险的特判**是直接 `return true`——那会漏掉闸门②，`transfer(1, 1, 20)` 余额 10 时应返回 `false`。
5. **先校验后修改**：`transfer` 必须两个账户、两道闸门全过再动数组。先扣款后发现 `a2` 越界就要回滚；顺序错了不是答案错，是**状态被污染**。
6. **money = 0**：恒满足闸门②（$0 \le$ 任意余额，含余额 0）。余额 0 的账户 `withdraw(acc, 0)` 返回 `true`。
7. **deposit 不查余额**：存款无上限（题面只保证 `money ≥ 0`），闸门②只属于 `withdraw` / `transfer`。误给 `deposit` 加余额检查会错杀合法存款。
8. **编号上界 $10^5 > n$**：约束写 `account ≤ 10^5` 而 `n` 可小到 1——编号合法性与 $n$ 挂钩，与 $10^5$ 无关，别把 $10^5$ 写进校验条件。
