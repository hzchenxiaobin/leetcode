# LeetCode 检查句子中的数字是否递增 题解

## 1. 题目概述

- **标题 / 题号**：检查句子中的数字是否递增（#2042，easy）
- **链接**：https://leetcode.cn/problems/check-if-numbers-are-ascending-in-a-sentence/
- **来源**：LeetCode 第 263 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟、单次遍历

**题意**：给定字符串 `s` 表示一个句子：token 之间用**单个**空格分隔、无前导或尾随空格。每个 token 要么是一个由 `0-9` 组成、**不含前导零**、值小于 100 的正整数，要么是一个纯小写英文字母单词。要求检查 `s` 中的**全部数字**按出现顺序是否**严格递增**（除最后一个数字外，每个数字都严格小于它右侧的数字）。满足返回 `true`，否则返回 `false`。

**约束**：

- $3 \le \text{s.length} \le 200$，`s` 只含小写字母、空格和数字 `0-9`
- token 之间由单个空格分隔，`s` 无前导/尾随空格
- 数字 token 数目在 $[2, 100]$ 之间，`s` 中至少有两个数字
- 每个数字都是小于 $100$ 的正整数，且不含前导零

> 💡 **题目送的最值钱约束**：「token 要么纯数字、要么纯小写字母」——两类 token 的**字符集互不相交**，判别 token 类型只需看首字符，$O(1)$ 完成。签到题的最短路径就藏在这条约束里。

## 2. 示例

**示例 1**

```text
输入：s = "1 box has 3 blue 4 red 6 green and 12 yellow marbles"
输出：true
解释：句子中的数字依次为 1, 3, 4, 6, 12，满足 1 < 3 < 4 < 6 < 12，严格递增。
```

**示例 2**

```text
输入：s = "hello world 5 x 5"
输出：false
解释：数字为 5, 5。5 不严格小于 5（相等也算违规），返回 false。
```

**示例 3**

```text
输入：s = "sunset is at 7 51 pm overnight lows will be in the low 50 and 60 s"
输出：false
解释：数字为 7, 51, 50, 60。其中 51 不小于 50，不满足严格递增。
```

**示例 4**

```text
输入：s = "4 5 11 26"
输出：true
解释：数字为 4, 5, 11, 26，严格递增。
```

## 3. 解题思路

### 3.1 暴力思路

签到题，$n \le 200$，先盘两条「朴素路线」：

1. **两趟 + 数组**：先按空格切分，把数字 token 全部挑出来存进列表 `nums`；再扫一遍 `nums`，检查相邻两数是否严格递增（`nums[i] <= nums[i-1]` 即 `false`）。正确、$O(n)$，签到绰绰有余——但「过滤数字」和「判定递增」两件事明明可以在**同一趟**里做完，中间数组是多余的。
2. **逐字符扫数字（错误！）**：不切 token，直接扫字符、遇到数字字符就当作一个数字。反例 `"1 box 12"`：真实数字序列是 $[1, 12]$（递增，答案 `true`）；逐字符却读出 $1, 1, 2$——`"12"` 被拆成 `'1'`、`'2'` 两个"数字"，$1 \le 1$ 误判 `false`。**数字以 token 为整体单位，绝不能拆成单个字符**。

### 3.2 核心观察：首字符定类型 + 滚动前驱

![核心概念：token 流首字符定类型，过滤数字后滚动前驱判严格递增](images/wc263_q1_token_filter_concept.svg)

三个观察把代码压到最短：

1. **字符集互斥 → 首字符判型**：数字 token 只含 `0-9`（无前导零），单词 token 只含 `a-z`，两类首字符即分胜负——`isdigit(token[0])` 一眼定类型，无需扫全 token，也不必担心 `"a1"` 这类混合体（题面已排除）。
2. **严格递增的判定只需前驱**：序列 $d_1, d_2, \dots, d_k$ 严格递增 $\iff$ 每一对相邻 $(d_{i-1}, d_i)$ 满足 $d_{i-1} < d_i$。判定是**局部**的，只需滚动变量 `prev` 记录"上一个见到的数字"——「过滤」与「归约」合并成一趟扫描。
3. **哨兵 $-1$ 吞掉首元素特判**：`prev` 初始化为 $-1$。题目保证所有数字是正整数（$\ge 1$），首个数字必 $> -1$，无需 `if (prev 为空)` 分支。

> ⚠️ **「严格」二字**：相等即 `false`（示例 2 的 $5, 5$）。判定必须写成 `cur <= prev` 时返回 `false`，误写成 `cur < prev` 会把相等放过。

### 3.3 算法流程

![算法流程：切分、首字符判型、与前驱比较、哨兵初始化](images/wc263_q1_scan_flow.svg)

1. **切分**：Python 用无参 `s.split()`，C++ 用 `istringstream >> token`；
2. **初始化**：`prev = -1`（哨兵）；
3. **逐 token 扫描**：
   - 首字符不是数字（是单词）→ 跳过；
   - 是数字 → 解析 `cur = int(token)`：
     - 若 `cur <= prev` → 立即返回 `false`（短路，后续数字不再看）；
     - 否则 `prev = cur`，继续；
4. 扫描结束未短路 → 返回 `true`。

### 3.4 示例演算

**示例 1（成功）**：`prev` 从哨兵 $-1$ 出发，每个数字 token 与前驱比较通过后滚动更新：$-1 \to 1 \to 3 \to 4 \to 6 \to 12$，全部通过，返回 `true`。

**示例 2（相等违规）**：数字 $5, 5$，第二个 $5$ 满足 $5 \le 5$，短路返回 `false`。

**示例 3（下降短路）**：数字 $7, 51, 50, 60$——$7 < 51$ 通过后 `prev = 51`；$50 \le 51$ 短路返回 `false`，末尾的 $60$ **根本不被检查**。

![示例演算：示例 1 的 prev 演化链与示例 2/3 的失败短路点](images/wc263_q1_walkthrough.svg)

| 步骤 | token | 类型 | cur | prev | 判定 | 动作 |
|------|-------|------|-----|------|------|------|
| 1 | `1` | 数字 | 1 | −1 | ✓ 1 > −1 | prev = 1 |
| 2 | `box` / `has` | 单词 | — | 1 | — | 跳过 |
| 3 | `3` | 数字 | 3 | 1 | ✓ 3 > 1 | prev = 3 |
| 4 | `4` | 数字 | 4 | 3 | ✓ 4 > 3 | prev = 4 |
| 5 | `6` | 数字 | 6 | 4 | ✓ 6 > 4 | prev = 6 |
| 6 | `12` | 数字 | 12 | 6 | ✓ 12 > 6 | prev = 12 |

扫完未短路，数字序列 $[1, 3, 4, 6, 12]$ 严格递增，返回 `true`。

## 4. 算法细节

1. **切分器选择**：无参 `split()` / `iss >> token` 以任意连续空白为分隔且不产生空串。本题保证单空格，`split(' ')` 也安全，但无参版对空格异常更鲁棒（次日第 264 场周赛 Q1 的句子就允许多空格）。
2. **判型只看首字符的合法性依赖**：依赖两条题面约束——token 非纯数字即纯字母（字符集互斥）、数字无前导零。若变体允许混合 token（如 `"a1"`）或负号，判型必须改为全 token 扫描。
3. **哨兵取 $-1$ 不取 $0$**：本题数字均为正数，取 $0$ 恰好也能过；但 $-1$ 是更鲁棒的下界，兼容"非负整数"的约束放宽，且语义上与"哨兵 = 比一切合法值小"的原则一致。
4. **数值范围**：数字 $< 100$，`int` / `stoi` / `int()` 无溢出、无大数问题。
5. **比较方向**：写 `cur <= prev` 即返回 `false`（排除相等），等价于"必须严格大于才放行"。

## 5. 正确性证明

**引理 1**（判型正确性）：对任意 token $t$，`isdigit(t[0])` 为真 $\iff$ $t$ 是数字 token。

**证明**：题面保证 token 恰有两类且穷尽：数字 token 的全部字符 $\in \{0,\dots,9\}$，其首字符是数字；单词 token 的全部字符 $\in \{a,\dots,z\}$，其首字符不是数字。两类互斥，故首字符是否为数字与 token 类别一一对应。∎

**引理 2**（前驱判定等价性）：设句中数字依次为 $d_1, \dots, d_k$（$k \ge 2$）。算法读到 $d_i$（$i \ge 2$）时 `prev` 恰为 $d_{i-1}$；算法返回 `true` $\iff$ 对所有 $2 \le i \le k$ 均有 $d_{i-1} < d_i$。

**证明**：对 $i$ 归纳。读 $d_1$ 前 `prev` 为哨兵 $-1$；因 $d_1 \ge 1 > -1$，比较通过，`prev` 更新为 $d_1$。设读 $d_i$ 前 `prev` $= d_{i-1}$：若 $d_i > d_{i-1}$，则 `prev` 更新为 $d_i$，归纳性质保持；若 $d_i \le d_{i-1}$，算法立即返回 `false`。故算法不短路当且仅当每一次比较 $d_i > d_{i-1}$ 都通过，即所有相邻对严格递增（其中首对 $d_1 > -1$ 恒真，不构成约束）。∎

**定理**：算法返回 `true` $\iff$ `s` 中的全部数字从左到右严格递增。

**证明**：由引理 1，算法恰把每个数字 token 解析为数字、不误收任何单词；由引理 2，返回值与"所有相邻数字对严格递增"等价，而这正是"全部数字严格递增"的定义。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n = |\text{s}|$。切分 $O(n)$；每个 token 判型 $O(1)$、数字 token 解析 $O(|t|)$，所有 token 总长不超过 $n$；短路使实际开销往往更低（失败样例在首个违规对处即停）。
- **空间复杂度**：Python `split()` 产生 token 列表为 $O(n)$；C++ `istringstream` 流式取出可做到 $O(1)$ 额外空间；若 Python 也要求 $O(1)$，可双指针在原串上定位 token 并手动累加解析（见每日姊妹篇第 5 节）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool areNumbersAscending(string s) {
        istringstream iss(s);
        string token;
        int prev = -1;                       // 哨兵：比一切合法数字都小
        while (iss >> token) {
            if (!isdigit(token[0])) continue; // 字符集互斥 → 首字符定类型
            int cur = stoi(token);
            if (cur <= prev) return false;    // 严格递增：相等也违规
            prev = cur;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def areNumbersAscending(self, s: str) -> bool:
        prev = -1                    # 哨兵：正数 >= 1 恒大于 -1
        for token in s.split():
            if not token[0].isdigit():
                continue             # 单词，跳过
            cur = int(token)
            if cur <= prev:          # 相等也返回 False（严格递增）
                return False
            prev = cur
        return True
```

## 8. 边界情况与易错点

1. **「严格」二字**：相等即 `false`——示例 2 的 $5, 5$。判定必须 `cur <= prev` 返回 `false`；写成 `cur < prev` 才返回会把相等放过。
2. **数字以 token 为整体单位**：逐字符扫数字会把 `"12"` 拆成 $1, 2$（`"1 box 12"` 反例，正确答案 `true` 被误判 `false`），必须先切分再整体解析。
3. **哨兵别用 $0$**：本题数字是正数，用 $0$ 恰好能过；一旦约束放宽为非负整数，首数字 $0$ 撞上哨兵即被误判。取 $-1$ 一劳永逸。
4. **`split(' ')` 依赖「单空格」约束**：本题保证单空格、无前后空格才安全；无参 `split()` 与 C++ `iss >> token` 对连续空白天然鲁棒。
5. **首字符判型的前提是字符集互斥**：题面已排除混合 token（如 `"a1"`）与负号。变体题面下判型需全 token 扫描。
6. **无前导零 + 值小于 100**：`int(token)` / `stoi` 无歧义、无溢出；无需大数处理。
7. **"至少两个数字"并非算法依赖**：即便数字少于 2 个（无比较即通过），算法自然返回 `true`，不需要为该约束写特判——约束只是保证测试集必有实际比较。
