# LeetCode 令牌放置 题解

## 1. 题目概述

- **标题 / 题号**：令牌放置（#948，medium）
- **链接**：https://leetcode.cn/problems/bag-of-tokens/
- **来源**：LeetCode 第 112 场周赛 Q4
- **难度**：中等
- **标签**：贪心、数组、双指针、排序

**题意**：初始能量 `power`、初始分数 `0`，令牌值放在 `tokens` 中。每个令牌**最多用一次**，两种用法二选一：

- **朝上**：当前能量 $\ge tokens[i]$ 时，能量减去 $tokens[i]$，**分数 $+1$**；
- **朝下**：当前分数 $\ge 1$ 时，能量加上 $tokens[i]$，**分数 $-1$**。

可以只用一部分令牌，求能得到的**最大分数**。

**约束**：

- $0 \le tokens.length \le 1000$
- $0 \le tokens[i],\ power < 10^4$

## 2. 示例

**示例 1**

```text
输入：tokens = [100], power = 50
输出：0
解释：买不起（50 < 100），也没有分可卖。
```

**示例 2**

```text
输入：tokens = [200,100], power = 150
输出：1
解释：用 100 朝上 → 能量 50、分数 1；200 买不起，卖它又只能换回 1 分，不划算。
```

**示例 3**

```text
输入：tokens = [100,200,300,400], power = 200
输出：2
解释：100 朝上（能量 100、分数 1）→ 400 朝下（能量 500、分数 0）
     → 200 朝上（能量 300、分数 1）→ 300 朝上（能量 0、分数 2）。
```

## 3. 解题思路

### 3.1 暴力思路

把"用了哪些令牌、每个怎么用"都枚举一遍：每个令牌有 3 种状态（不用 / 朝上 / 朝下），共 $3^n$；即便再按状态做记忆化搜索（`(mask, power, score)`），也是 $O(3^n)$ 级别，$n = 1000$ 时完全不可行。

小数据（$n \le 6$）可以用这个暴力做**对拍**，这一点在验证阶段非常有用。

### 3.2 核心观察：朝上买最便宜的，朝下卖最贵的

![排序后：左边花能量换分，右边卖分换能量](images/wc112_q4_two_pointers.svg)

先排序。可以证明（§5 引理 1）存在一个最优方案满足：

- **朝上的令牌是排序后最便宜的若干个**（一个前缀）；
- **朝下的令牌是最贵的若干个**（一个后缀）。

直觉很直接：朝上的目的是 **$+1$ 分**，那么花最少的能量换这 1 分最划算，省钱留给后面的令牌；朝下的目的是**换能量**，那么卖掉最贵的令牌换回最多能量最划算。

于是所有"合理"的方案都可以用两个指针刻画：

- 左指针 `i`：下一个准备**朝上**的令牌（最便宜的那批）；
- 右指针 `j`：下一个准备**朝下**的令牌（最贵的那批）。

![为什么一定在两端取：交换论证](images/wc112_q4_exchange.svg)

**贪心策略**：

1. 若 `power >= tokens[i]`：买下它（朝上），`i++`、`score++`，并更新历史最佳；
2. 否则若 `score > 0`：卖掉 `tokens[j]`（朝下），`j--`、`score--`，能量加回来；
3. 两者都不行：结束（能量不够、也没分可卖）。

**为什么第 2 步"卖分"不亏？** 卖一次会 $-$1 分，但换回的能量通常足以再买 1~2 个便宜令牌，净收益可能为正；所以卖分不是"退步"，而是**投资**。这也是本题容易想漏的地方：只写"能买就买"、不写"能量不足时卖分"的贪心会在示例 3 上得到 1 而不是 2。

### 3.3 算法流程

```text
1. 排序 tokens；i = 0，j = n-1，score = 0，best = 0
2. while i <= j:
       若 power >= tokens[i]:
           power -= tokens[i]; i += 1; score += 1
           best = max(best, score)
       否则若 score > 0:
           power += tokens[j]; j -= 1; score -= 1
       否则:
           break
3. return best
```

注意循环用 `while i <= j`（同一个令牌不能既朝上又朝下），两端指针相遇即结束。

### 3.4 示例演算

![示例 3 演算](images/wc112_q4_walkthrough.svg)

对 `tokens = [100,200,300,400]`、`power = 200`：

| 步 | 动作 | 能量 | 分数 | best |
|----|------|------|------|------|
| 1 | 100 朝上 | 100 | 1 | 1 |
| 2 | 400 朝下 | 500 | 0 | 1 |
| 3 | 200 朝上 | 300 | 1 | 1 |
| 4 | 300 朝上 | 0 | 2 | 2 |

此时 `i = 3 > j = 2`，循环结束，返回 2。可以看到第 2 步"卖分"是关键：不卖 400 就只能得 1 分。

## 4. 算法细节

1. **排序**：升序排序后，最便宜的在前、最贵的在后，双指针天然对应"前缀朝上 / 后缀朝下"。
2. **指针移动方向**：`i` 只增、`j` 只减，两者相遇即停，每个令牌最多被考虑一次。
3. **`best` 的更新时机**：只在**买入**后更新（分数只在买入时上升）；卖出时分数下降，历史最佳不会更差，但也无需更新。
4. **终止条件**：`power < tokens[i]` 且 `score == 0` 时，既买不起最便宜的，也没分可卖，任何后续动作都不可能发生。
5. **能量上界**：$n \le 1000$、$tokens[i] < 10^4$，能量最大约 $10^7$，`int` 足够。
6. **`tokens[i] == 0`**：买 0 能量的令牌是"免费加分"，循环会连续买入；不要漏掉这种边界。
7. **排序不改原问题**：令牌的原始下标无关紧要，只有数值参与运算。
8. **Python 实现**：`tokens.sort()` 原地排序，避免额外拷贝。

## 5. 正确性证明

记排序后令牌为 $a_0 \le a_1 \le \cdots \le a_{n-1}$。一个方案由"朝上集合 $U$、朝下集合 $D$"与执行顺序构成，最终分数 $= \lvert U\rvert - \lvert D\rvert$，净能量

$$P = power - \sum_{i\in U} a_i + \sum_{j\in D} a_j .$$

**引理 1（规范化）**：若存在达到分数 $s$ 的方案，则存在一个达到 $s$ 的方案，其中 $U = \{a_0,\dots,a_{u-1}\}$（最便宜的前 $u$ 个）、$D = \{a_{n-d},\dots,a_{n-1}\}$（最贵的前 $d$ 个），$u = \lvert U\rvert$、$d = \lvert D\rvert$，且 $u - d = s$。

**证明**：设最优方案的 $U, D$。若存在 $i \in U$ 与 $j \notin U$ 且 $a_j < a_i$（$j$ 更便宜），把 $j$ 改为朝上、把 $i$ 改为朝下：新的朝上花费 $a_j \le a_i$，新的朝下收益 $a_i \ge a_j$，因此在**同一执行顺序**下，每一步之后能量都不少于原方案，故仍可行，分数不变。反复交换可把 $U$ 变成"最便宜的 $u$ 个"。同理，若 $j \in D$ 而 $i \notin D$ 且 $a_i > a_j$，把 $i$ 改为朝下、$j$ 改为朝上，能量仍不减少。两轮规范化后 $U$ 是前缀、$D$ 是后缀，且二者不交（令牌只能用一次）。∎

**引理 2（净能量只由 $(u,d)$ 决定）**：若某方案朝上的恰好是前 $u$ 个、朝下的恰好是后 $d$ 个，则其净能量恒为

$$P(u,d) = power - \sum_{i<u} a_i + \sum_{j \ge n-d} a_j,$$

与执行顺序无关。

**证明**：能量变化只取决于"用了哪些令牌、怎么用"，加法可交换。∎

**引理 3（贪心在固定 $d$ 下把 $u$ 推到最大）**：设 $U(d) = \max\{u : \text{存在可行方案使朝上为前 } u \text{ 个、朝下为后 } d \text{ 个}\}$。则贪心在卖出 $d$ 次之后，买入次数恰为 $U(d)$。

**证明**：对 $d$ 归纳。

- $d = 0$：无卖出，每次买入只能花当前能量，而买入前 $u$ 个的花费固定为 $\sum_{i<u} a_i$。贪心买到底，正是最大的可行 $u$。
- 设 $d$ 时贪心已买到 $U(d)$（归纳假设）。此时能量 $< a_{U(d)}$（否则贪心会继续买），贪心卖掉 $a_{n-1-d}$（当前最贵的未卖令牌），这是所有可选卖出中**收益最大**的一个，因而卖出后能量是所有"卖 1 次"方案中的最大值；由引理 2，能量在 $(u, d+1)$ 上对 $u$ 单调不增，故在能量最大时能买的 $u$ 也最大，贪心接着买到不能买为止，即得到 $U(d+1)$。∎

**定理**：算法返回最大可得分。

**证明**：任取可行方案，由引理 1 规范化后设其朝上 $u$ 个、朝下 $d$ 个，分数 $u-d$。由 $U(d)$ 的定义 $u \le U(d)$，故

$$u - d \;\le\; U(d) - d .$$

而贪心依次经过 $d = 0,1,2,\dots$，在每个 $d$ 上都达到 $U(d)$（引理 3），并在买入后把 $U(d)-d$ 记入 `best`。因此

$$\text{best} \;\ge\; \max_{d}\big(U(d)-d\big) \;\ge\; u-d,$$

对任意可行方案成立，故 `best` 是最大值；又 `best` 是某个真实过程的分数（贪心构造出的方案合法），所以恰为最大分数。∎

## 6. 复杂度分析

- **时间**：$O(n\log n)$，排序占主导；双指针部分每个令牌最多被移动一次，$O(n)$。
- **空间**：$O(1)$（不计排序栈开销），只用了 `i, j, score, best, power` 五个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int bagOfTokensScore(vector<int>& tokens, int power) {
        sort(tokens.begin(), tokens.end());
        int i = 0, j = (int)tokens.size() - 1;
        int score = 0, best = 0;
        while (i <= j) {
            if (power >= tokens[i]) {          // 买得起最便宜的：朝上 +1 分
                power -= tokens[i];
                i++;
                score++;
                best = max(best, score);
            } else if (score > 0) {            // 买不起，但有分：卖掉最贵的换能量
                power += tokens[j];
                j--;
                score--;
            } else {
                break;                         // 既买不起也没分可卖
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def bagOfTokensScore(self, tokens: list[int], power: int) -> int:
        tokens.sort()
        i, j = 0, len(tokens) - 1
        score = best = 0
        while i <= j:
            if power >= tokens[i]:          # 朝上：花最少的能量换 1 分
                power -= tokens[i]
                i += 1
                score += 1
                best = max(best, score)
            elif score > 0:                 # 朝下：卖最贵的换能量，分数 -1
                power += tokens[j]
                j -= 1
                score -= 1
            else:
                break
        return best
```

## 8. 边界情况与易错点

1. **漏掉"卖分"分支**：只写"能买就买"会把示例 3 算成 1，必须用 `elif score > 0` 卖出最贵的令牌。
2. **`while i <= j`**：写成 `i < j` 会少考虑"只剩一个令牌"的情形；同一个令牌不能被用两次，所以用 `<=` 再配合指针移动是正确的。
3. **空数组**：`tokens = []` 时循环不执行，返回 0。
4. **`tokens[i] == 0`**：免费加分，必须能连续买入；判断条件写 `power >= tokens[i]` 而不是 `power > tokens[i]`。
5. **先卖后买还是先买后卖**：贪心的顺序是"能买先买、买不起才卖"，这保证 `score` 从不降到 0 以下（卖出要求 `score > 0`）。
6. **`best` 初始化**：从 0 开始（样例 1 的答案就是 0），不要初始化为 1 或 `-1`。
7. **能量溢出**：$1000 \times 10^4 = 10^7$，`int` 足够；Python 无限制。
8. **卖分可能"白卖"**：如果卖掉最贵的令牌后仍买不起任何令牌，那这次卖出没有收益，`best` 已记录历史最高分，不会因此变差。
