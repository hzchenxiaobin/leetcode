# LeetCode 验证栈序列 题解

## 1. 题目概述

- **标题 / 题号**：验证栈序列（#946，medium）
- **链接**：https://leetcode.cn/problems/validate-stack-sequences/
- **来源**：LeetCode 第 112 场周赛 Q2
- **难度**：中等
- **标签**：栈、数组、模拟

**题意**：`pushed` 与 `popped` 是两个**互不重复**且互为排列的序列。判断是否存在一种"入栈 / 出栈"操作序列，使得：按 `pushed` 的顺序**依次入栈**（入栈顺序固定），出栈元素按 `popped` 的顺序恰好依次出现。初始为空栈。

**约束**：

- $1 \le pushed.length \le 1000$
- $0 \le pushed[i] \le 1000$，`pushed` 中元素互不相同
- `popped.length == pushed.length`，`popped` 是 `pushed` 的排列

## 2. 示例

**示例 1**

```text
输入：pushed = [1,2,3,4,5], popped = [4,5,3,2,1]
输出：true
解释：push(1),push(2),push(3),push(4),pop()->4, push(5),pop()->5, pop()->3,pop()->2,pop()->1
```

**示例 2**

```text
输入：pushed = [1,2,3,4,5], popped = [4,3,5,1,2]
输出：false
解释：弹出 4、3 后栈顶是 2，而 popped 下一个要的是 5，5 还在栈底被 2 压着，取不出来。
```

**示例 3（补充，严格逆序）**

```text
输入：pushed = [1,2], popped = [2,1]
输出：true
解释：push(1), push(2), pop()->2, pop()->1，后进先出正好匹配。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有"入栈 / 出栈"的交错序列：$n$ 次入栈、$n$ 次出栈的全部合法交错共 $\binom{2n}{n}$ 种，$n = 1000$ 时约 $10^{600}$，完全不可行。

即使只枚举"先压几个再弹几个"的划分，也是指数级的搜索树。**本题的关键是：每一步的动作其实是被唯一确定的**，根本不需要搜索。

### 3.2 核心观察：动作唯一确定（能弹就必须弹）

![按 pushed 顺序压栈，能弹就弹](images/wc112_q2_stack_sim.svg)

想象我们按 `pushed` 的顺序逐个压栈，同时用指针 `j` 指向 `popped` 中**下一个必须被弹出的元素**。每一步只有两种可能：

1. **栈顶恰好等于 `popped[j]`**：**必须立刻弹**。理由见下；
2. **栈顶不等于 `popped[j]`**：只能继续压入下一个元素（因为出栈只能弹栈顶）。

哪条路完全由当前状态决定，于是整个判定过程**没有任何分支**——一遍模拟即可。

**为什么第 1 种情形"必须弹"？**（见 §5 引理 1）设栈顶为 $t = popped[j]$，如果此时不弹 $t$ 而是继续压入新元素，那么新元素会盖在 $t$ 上面；而 `pushed` 中尚未压入的元素在 `popped` 中的位置必然**都在 $j$ 之后**（因为 $t$ 就是下一个要弹的），所以 $t$ 将**永远无法被取出**——除非先弹掉那些盖在它上面的、本应更晚弹出的元素，这与 $popped$ 的顺序矛盾。

### 3.3 算法流程

![为什么「能弹就弹」不丢解](images/wc112_q2_rule.svg)

```text
1. st = 空栈, j = 0
2. for x in pushed:
       st.push(x)                              // 固定顺序入栈
       while st 非空 且 st.top() == popped[j]:  // 栈顶匹配就一路弹到底
           st.pop(); j += 1
3. return j == len(popped)                      // 全部弹完才算成功
```

### 3.4 示例演算

对 `pushed = [1,2,3,4,5]`、`popped = [4,5,3,2,1]`：

| 步骤 | 动作 | 栈（底 → 顶） | j |
|------|------|--------------|---|
| 1 | push 1 | 1 | 0 |
| 2 | push 2 | 1 2 | 0 |
| 3 | push 3 | 1 2 3 | 0 |
| 4 | push 4 | 1 2 3 4，栈顶 4 = popped[0] | 0 |
| 5 | pop → 4 | 1 2 3 | 1 |
| 6 | push 5 | 1 2 3 5，栈顶 5 = popped[1] | 1 |
| 7 | pop → 5 | 1 2 3，栈顶 3 = popped[2] | 2 |
| 8 | pop → 3 | 1 2，栈顶 2 = popped[3] | 3 |
| 9 | pop → 2 | 1，栈顶 1 = popped[4] | 4 |
| 10 | pop → 1 | 空 | 5 |

$j = 5 = n$，返回 `true`。换成 `popped = [4,3,5,1,2]` 时，弹完 4、3 后栈为 `1 2`，栈顶 2 而 `popped[2] = 5`，继续压入 5 后栈为 `1 2 5`，弹 5 后栈为 `1 2`，而 `popped[3] = 1`、栈顶是 2，压栈已结束，$j = 3 < 5$，返回 `false`。

## 4. 算法细节

1. **`while` 而不是 `if`**：一次压栈可能触发**连续多次**弹出（示例 1 的末尾连弹 3 次），必须用 `while`。
2. **循环上界**：`j < len(popped)` 防止越界（虽然 `popped` 是 `pushed` 的排列，弹出次数不会超过 $n$，但保险起见要判）。
3. **入栈顺序固定**：题目要求"按 `pushed` 的顺序依次入栈"，所以外层天然是对 `pushed` 的 `for` 循环，不能任意挑元素压。
4. **用数组模拟栈**：C++ 用 `vector<int>` 的 `push_back`/`pop_back`/`back` 即可，比 `std::stack` 更快也更好调试。
5. **最后判空**：`j == n` 与"栈为空"等价（因为 `popped` 是排列，弹了 $n$ 个就弹空）。用 `j` 更直观。
6. **不需要哈希或预计算**：值互不相同保证"栈顶等于 `popped[j]`"是唯一的匹配判断，不存在歧义。
7. **`popped` 的下标复用**：`j` 同时是"已成功弹出的个数"和"下一个待弹元素的下标"，语义统一。

## 5. 正确性证明

记 $n = \lvert pushed\rvert$。把一次"压入 $pushed[i]$"或"弹出栈顶"称为一个**动作**。

**引理 1（能弹必须弹）**：若在某状态下栈顶 $t = popped[j]$，则存在合法动作序列（完成全部弹出）**当且仅当**下一步就弹出 $t$。

**证明**：

- "$\Leftarrow$"：若下一步弹 $t$，则 $j$ 加一，问题化为更小的子问题（状态推进），由归纳可完成。
- "$\Rightarrow$"：设存在某个合法序列在弹 $t$ 之前先做了别的动作。由于唯一可做的"别的动作"是压入某个尚未压入的元素 $pushed[k]$（$k$ 递增），此后 $pushed[k]$ 位于 $t$ 之上。要弹出 $t$ 必须先弹 $pushed[k]$。但 $pushed[k]$ 尚未入栈时，$popped$ 中 $t$ 之后的位置里必然包含 $pushed[k]$（因为 `popped` 是 `pushed` 的排列，而 $pushed[k]$ 尚未出现，只能排在 $j$ 之后）。于是"先弹 $pushed[k]$ 再弹 $t$"要求 $pushed[k]$ 在 `popped` 中位于 $t$ **之前**，矛盾。故任何合法序列都必须立刻弹 $t$。∎

**引理 2（无非平凡分支）**：若栈顶 $\ne popped[j]$，则唯一可做的动作是压入下一个元素（若已无元素可压，则无合法动作）。

**证明**：出栈只能取栈顶，而栈顶不是目标，弹出它必然使 `popped` 的第 $j$ 位永远无法达成（被弹出的元素不再可用，而 `popped` 需要它此刻出现）。故只能压入。∎

**定理**：算法返回 `true` 当且仅当存在合法的入栈/出栈序列产生 `popped`。

**证明**：

- 由引理 1、2，任意时刻若存在合法完成序列，则下一步动作被唯一确定，且恰是算法所采取的动作。因此若存在合法序列，它**唯一**，且与算法逐步一致。
- 若算法结束时 $j = n$，说明算法构造的动作序列成功产生了 `popped`，故存在合法序列（返回 `true` 正确）。
- 若算法结束（`pushed` 全部压入且无法再弹）时 $j < n$，则此时栈顶 $\ne popped[j]$ 且无元素可压，由引理 2 该状态是"死局"；又由引理 1、2 算法走的每一步都是唯一被迫的，所以任何合法序列都会到达同一死局，故不存在合法序列（返回 `false` 正确）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层 `for` 执行 $n$ 次，内层 `while` 中每个元素至多被弹出一次，总弹出次数 $\le n$；每次比较与压/弹都是 $O(1)$。
- **空间**：$O(n)$，栈最多同时存 $n$ 个元素。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool validateStackSequences(vector<int>& pushed, vector<int>& popped) {
        vector<int> st;
        size_t j = 0;
        for (int x : pushed) {
            st.push_back(x);                                  // 固定顺序入栈
            while (!st.empty() && j < popped.size() && st.back() == popped[j]) {
                st.pop_back();                                // 栈顶匹配就弹
                j++;
            }
        }
        return j == popped.size();                            // 全部弹完才算成功
    }
};
```

### Python

```python
class Solution:
    def validateStackSequences(self, pushed: list[int], popped: list[int]) -> bool:
        st = []
        j = 0
        for x in pushed:
            st.append(x)                       # 按固定顺序入栈
            while st and j < len(popped) and st[-1] == popped[j]:
                st.pop()                       # 能弹就一路弹到底
                j += 1
        return j == len(popped)
```

## 8. 边界情况与易错点

1. **把 `while` 写成 `if`**：这是本题第一号错误。示例 1 末尾要连弹 3 次，`if` 会漏弹导致误判 `false`。
2. **忘记判 `j < n`**：虽然排列性质保证不会越界，但加上判断更稳妥，也避免"栈里还有元素但 `j` 已到末尾"时读越界。
3. **`popped` 不一定是"部分弹出"**：必须把所有元素都弹出，`j == n` 才算成功；中途 `pushed` 用尽但没弹完就是 `false`。
4. **误以为可以任意选择入栈元素**：入栈顺序被 `pushed` 固定，不能"先压 5 再压 1"。
5. **$n = 1$**：`pushed = popped` 时 `true`；`popped` 只能是同一个元素，所以必然 `true`。
6. **完全逆序**：`popped = reversed(pushed)` 一定 `true`（全部压完后依次弹出），可作为自测用例。
7. **完全同序**：`popped = pushed` 也一定 `true`（压一个弹一个）。
8. **值域限制的误用**：$pushed[i] \le 1000$ 可以开数组做"已压入"标记，但本题用不到——模拟法不需要查询"某值是否已入栈"。
