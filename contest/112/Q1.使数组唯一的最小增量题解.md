# LeetCode 使数组唯一的最小增量 题解

## 1. 题目概述

- **标题 / 题号**：使数组唯一的最小增量（#945，medium）
- **链接**：https://leetcode.cn/problems/minimum-increment-to-make-array-unique/
- **来源**：LeetCode 第 112 场周赛 Q1
- **难度**：中等
- **标签**：贪心、数组、计数、排序

**题意**：每次操作可以把**任意一个**元素 $+1$。求使数组所有元素**互不相同**所需的最少操作次数。

**约束**：

- $1 \le nums.length \le 10^5$
- $0 \le nums[i] \le 10^5$
- 数据保证答案在 32 位整数范围内

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2]
输出：1
解释：把第二个 2 变成 3，数组变为 [1,2,3]。
```

**示例 2**

```text
输入：nums = [3,2,1,2,1,7]
输出：6
解释：一种最优过程：排序 [1,1,2,2,3,7] → 抬成 [1,2,3,4,5,7]，
     代价 0+1+1+2+2+0 = 6。
```

**示例 3（补充，全部相同）**

```text
输入：nums = [1,1,1,1]
输出：6
解释：抬成 [1,2,3,4]，代价 0+1+2+3 = 6。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：对每个元素，只要它的值已经被别的元素占用，就 $+1$，直到不冲突：

```text
seen = 空集合
for x in nums:
    while x in seen: x += 1; ans += 1
    seen.add(x)
```

问题在于**"逐个 +1 试探"的步数可能极大**。考虑 `nums = [1,1,1,...,1]`（$10^5$ 个 1）：第 $k$ 个元素要加 $k-1$ 次，总计 $\sum k = 5\times 10^9$ 次操作，直接超时。

另一类"暴力"是枚举每个元素的增量：$n$ 个元素各有若干选择，$O(n^n)$ 级别，不可行。

### 3.2 核心观察：排序后抬到「前一个数 + 1」

![排序后把每个数抬到「前一个数 + 1」](images/wc112_q1_sort_raise.svg)

先排序，记排序后数组为 $a_0 \le a_1 \le \cdots \le a_{n-1}$。定义目标值

$$b_0 = a_0,\qquad b_i = \max(a_i,\; b_{i-1} + 1).$$

**核心结论**：最小总代价恰好是 $\sum_i (b_i - a_i)$。

为什么"抬到 $b_{i-1}+1$"就够、且不能再少？**可行性**是一眼可见的：$b$ 严格递增、且只做加法。难点全在**下界**——为什么没有别的方案更省。

关键转化：**总代价只取决于最终用到的取值集合**，与"哪个元素分到哪个值"无关。因为

$$\sum_i \big(f(a_i)-a_i\big) = \sum_{s \in S} s - \sum_i a_i,$$

其中 $S=\{f(a_i)\}$ 是最终取值集合（$|S|=n$）。所以问题等价于：**在保证"每个 $a_i$ 都能配到一个不小于它的值"的前提下，选一个 $n$ 元集合 $S$，使元素总和最小**。而"从小到大、每个值尽量小"的贪心正是这个集合，任何"跳得更远"的取法都只会让 $\sum S$ 变大。

### 3.3 算法流程

![minIncrementForUnique：一次排序 + 一次扫描](images/wc112_q1_flow.svg)

```text
1. 排序 nums
2. ans = 0
3. for i in 1..n-1:
       若 nums[i] <= nums[i-1]:
           ans += nums[i-1] + 1 - nums[i]
           nums[i] = nums[i-1] + 1        // 原地抬高，保持严格递增不变式
4. return ans
```

### 3.4 示例演算

![示例 2 逐位抬高的代价累加](images/wc112_q1_sort_raise.svg)

对 `nums = [3,2,1,2,1,7]`，排序后 $a = [1,1,2,2,3,7]$：

| $i$ | $a_i$ | $b_{i-1}+1$ | 是否抬高 | $b_i$ | 代价 |
|-----|-------|-------------|---------|-------|------|
| 0 | 1 | — | 否 | 1 | 0 |
| 1 | 1 | 2 | 是 | 2 | 1 |
| 2 | 2 | 3 | 是 | 3 | 1 |
| 3 | 2 | 4 | 是 | 4 | 2 |
| 4 | 3 | 5 | 是 | 5 | 2 |
| 5 | 7 | 6 | 否（$7>6$） | 7 | 0 |

总代价 $0+1+1+2+2+0 = 6$，与示例输出一致。

## 4. 算法细节

1. **原地修改**：把 `nums[i]` 直接改成 $b_i$，后面只需要和"新的前一个值"比较，无需额外数组。
2. **严格递增不变式**：处理完第 $i$ 位后，前缀 `nums[0..i]` 严格递增，因此下一次比较只依赖 `nums[i-1]`。
3. **只增不减**：当 $a_i > b_{i-1}$ 时不需要动它（动它只会增加代价），这正是 `max` 的含义。
4. **代价累加**：`ans += nums[i-1] + 1 - nums[i]` 等价于 $b_i - a_i$，一次减法即可。
5. **类型**：中间量最大可达 $n \times$ 值域，虽然题目保证答案在 32 位内，C++ 仍建议用 `long long` 累加后转 `int`，避免边界数据溢出。
6. **不需要去重计数**：不需要哈希表或"下一个空位"指针；排序后相邻比较即可，因为冲突一定是"相邻且不严格递增"。
7. **排序稳定性无关**：相同值的相对顺序不影响代价（相同值无论谁先抬，总代价相同）。

## 5. 正确性证明

设排序后数组为 $a_0 \le a_1 \le \cdots \le a_{n-1}$，$b_0=a_0$、$b_i=\max(a_i, b_{i-1}+1)$。

**引理 1（代价只取决于最终取值集合）**：设 $f$ 是一个可行解，$S=\{f(a_i)\}$（$|S|=n$）。则

$$\text{cost}(f)=\sum_{i}\big(f(a_i)-a_i\big)=\sum_{s\in S}s-\sum_{i}a_i .$$

**证明**：直接展开：$\sum_i f(a_i)$ 遍历的正是集合 $S$ 的全部元素（每个一次），故等于 $\sum_{s\in S}s$；而 $\sum_i a_i$ 与配对方式无关。∎

**推论 1**：所有可行解的差别只在**集合 $S$ 的选取**，与"哪个元素抬到哪个值"无关。因此只需最小化 $\sum_{s\in S}s$。

**引理 2（可行集合的逐位下界）**：设 $S$ 是某可行解的取值集合，把 $S$ 升序写作 $s_0<s_1<\cdots<s_{n-1}$，则 $s_i \ge a_i$（$0\le i<n$）。

**证明**：反设存在 $i$ 使 $s_i < a_i$。考虑下标 $j \ge i$ 的这 $n-i$ 个元素，每个都满足 $f(a_j)\ge a_j \ge a_i > s_i$，即 $S$ 中至少有 $n-i$ 个值严格大于 $s_i$。但 $S$ 中严格大于 $s_i$ 的值恰为 $s_{i+1},\dots,s_{n-1}$，只有 $n-1-i$ 个，矛盾。∎

**引理 3（$b$ 是逐位最小解）**：$b$ 严格递增、$b_i \ge a_i$；且对任何严格递增序列 $c_0<c_1<\cdots<c_{n-1}$ 满足 $c_i\ge a_i$，都有 $b_i \le c_i$。

**证明**：$b_i=\max(a_i,b_{i-1}+1)\ge b_{i-1}+1>b_{i-1}$ 给出严格递增与 $b_i\ge a_i$。对 $c$ 归纳：$b_0=a_0\le c_0$；设 $b_{i-1}\le c_{i-1}$，则 $b_i=\max(a_i,b_{i-1}+1)\le\max(c_i, c_{i-1}+1)\le c_i$（末步用 $c$ 严格递增即 $c_i\ge c_{i-1}+1$）。∎

**定理**：$\sum_i (b_i-a_i)$ 是使数组元素互不相同的最小操作次数。

**证明**：

- **可行**：由引理 3，$b$ 严格递增，把 $a_i$ 抬到 $b_i$ 后两两不同，且只做加法，操作次数为 $\sum(b_i-a_i)$，故最小值 $\le\sum(b_i-a_i)$。
- **下界**：任取可行解 $f$，其取值集合升序为 $s$。由引理 2，$s_i\ge a_i$，即 $s$ 是一个"严格递增且逐位不小于 $a$"的序列；由引理 3，$b_i\le s_i$，故 $\sum_i b_i \le \sum_i s_i$。再由引理 1 及推论 1，

$$\text{cost}(f)=\sum_i s_i-\sum_i a_i \;\ge\; \sum_i b_i-\sum_i a_i = \sum_i (b_i-a_i).$$

两边夹得等号，故 $\sum(b_i-a_i)$ 是最小值。∎

## 6. 复杂度分析

- **时间**：$O(n\log n)$，排序是瓶颈；扫描一遍 $O(n)$，每次只做常数次比较与加减。
- **空间**：$O(1)$ 额外空间（原地修改输入数组）；排序本身 $O(\log n)$ 栈空间。
- **对比"逐个 +1"**：那份暴力在 `[1,1,...,1]` 上是 $O(n^2)$，本题 $n=10^5$ 时会 TLE——这正是排序法的价值。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minIncrementForUnique(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        long long ans = 0;
        for (int i = 1; i < (int)nums.size(); i++) {
            if (nums[i] <= nums[i - 1]) {           // 与前一个撞车，抬高到 prev+1
                ans += nums[i - 1] + 1 - nums[i];
                nums[i] = nums[i - 1] + 1;          // 原地修改，保持严格递增
            }
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minIncrementForUnique(self, nums: list[int]) -> int:
        nums.sort()
        ans = 0
        for i in range(1, len(nums)):
            if nums[i] <= nums[i - 1]:              # 与前一个撞车
                ans += nums[i - 1] + 1 - nums[i]
                nums[i] = nums[i - 1] + 1           # 抬高并原地更新
        return ans
```

## 8. 边界情况与易错点

1. **已唯一**：如 `[1,2,3]`，扫描中不触发任何抬高，答案 0。
2. **全部相同**：`[1,1,1,1]` 答案是 $0+1+2+3=6$，是最容易手算错的样例。
3. **值域含 0**：`[0,0]` → `[0,1]`，答案 1；不要把 0 当作"空位"特殊处理。
4. **单个元素**：$n=1$ 时循环不执行，答案 0。
5. **大值不参与抬高**：`[1,1,100]` 排序后第二个 1 抬到 2，100 保持不变——不要写成"所有元素都要往后挤"。
6. **溢出**：`ans` 用 `long long`；虽然题目保证答案在 32 位内，累加过程中的中间值用 `int` 也有风险。
7. **不要用"逐个 +1 试探"**：$O(n^2)$ 会在全相同数据上 TLE。
8. **不要先排序再建哈希**：哈希表做法（找下一个空位）需要并查集加速，代码量与常数都更大，排序法更直接。
9. **原地修改输入**：若调用方复用 `nums`，需注意副作用；面试中可先复制一份。
