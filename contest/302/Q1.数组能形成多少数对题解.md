# LeetCode 数组能形成多少数对 题解

## 1. 题目概述

- **标题 / 题号**：数组能形成多少数对（#2341，easy）
- **链接**：https://leetcode.cn/problems/maximum-number-of-pairs-in-array/
- **来源**：LeetCode 第 302 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定下标从 0 开始的整数数组 `nums`。每一步操作可以从中选出**两个相等的整数**并移除，形成一个**数对**；反复执行直到无法继续。返回 `[answer[0], answer[1]]`，其中 `answer[0]` 是形成的数对数目，`answer[1]` 是操作结束后剩余的整数数目。

**约束**：

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

> 💡 关键词是「多次执行直到无法继续」——即求**最多**能配出多少对。操作顺序不影响结果，因为每次移除的是两个同值元素，整个过程中每个值的出现次数只会减 2。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,2,1,3,2,2]
输出：[3,1]
解释：(1,1)、(3,3)、(2,2) 三对被移除，剩下一个 2。
```

**示例 2**

```text
输入：nums = [1,1]
输出：[1,0]
解释：(1,1) 形成一对，数组被清空。
```

**示例 3**

```text
输入：nums = [0]
输出：[0,1]
解释：无法配对，剩下 1 个数字。
```

## 3. 解题思路

### 3.1 暴力思路

直接模拟：每轮扫描数组找两个相等元素移除，直到找不到为止。每轮 `O(n)`，最多配 `n/2` 轮，总复杂度 `O(n^2)`。在本题 `n ≤ 100` 下也能过，但写起来容易出错（删除元素、下标移动），完全没必要。

### 3.2 核心观察：配对只与出现次数有关

![按值计数配对](images/wc302_q1_counting_concept.svg)

** Insight**：一个数对由两个**同值**元素构成，所以：

- 不同值的元素之间永远不会配对，各值的配对**相互独立**；
- 值 `v` 出现 `cnt` 次，则它最多贡献 `⌊cnt / 2⌋` 个数对，多出的 `cnt mod 2` 个（0 或 1 个）成为「孤儿」。

于是无需模拟移除过程：

$$\text{pairs} = \sum_{v} \left\lfloor \frac{cnt(v)}{2} \right\rfloor, \qquad \text{leftover} = \sum_{v} \big(cnt(v) \bmod 2\big) = n - 2 \times \text{pairs}$$

### 3.3 算法流程

![算法流程](images/wc302_q1_algorithm_flow.svg)

1. 遍历 `nums`，用哈希表统计每个值的出现次数 `cnt`（由于 `0 <= nums[i] <= 100`，也可用长度 101 的定长数组）；
2. 累加每个值的 `cnt / 2`（整除）得到 `pairs`；
3. `leftover = n - 2 * pairs`；
4. 返回 `[pairs, leftover]`。

### 3.4 示例演算

![示例演算](images/wc302_q1_example_walkthrough.svg)

以 `nums = [1,3,2,1,3,2,2]` 为例：

| 值 v | cnt | ⌊cnt/2⌋ 对 | cnt mod 2 剩余 |
|------|-----|-----------|----------------|
| 1    | 2   | 1         | 0              |
| 3    | 2   | 1         | 0              |
| 2    | 3   | 1         | 1              |
| 合计 | 7   | **3**     | **1**          |

验证：`n − 2×3 = 7 − 6 = 1` ✓，返回 `[3, 1]`。

## 4. 算法细节

1. **计数结构选择**：`0 <= nums[i] <= 100`，值域极小，可用 `int cnt[101]` 定长数组（`O(1)` 额外空间）；用 `unordered_map` / `Counter` 也一样正确，且不依赖值域。
2. **整除即配对**：`cnt / 2`（C++ 整数除法、Python `//`）自动丢弃奇数次多出的一个，无需特判奇偶。
3. **剩余数用减法**：`leftover = n - 2 * pairs`，避免再扫一遍取模求和；两者由恒等式 $\sum cnt(v) = n$ 保证一致。
4. **无需真正移除**：题目问的是数目，不是操作序列，计数即答案。

## 5. 正确性证明

**引理 1**：若值 `v` 出现 `cnt` 次，则任何合法操作序列中，`v` 参与的数对数至多为 $\lfloor cnt/2 \rfloor$，且该上界可以达到。

**证明**：每个包含 `v` 的数对消耗 2 个值为 `v` 的元素，若形成 `k` 对则 `2k <= cnt`，故 `k <= ⌊cnt/2⌋`。另一方面，将这 `cnt` 个元素任意两两分组即可形成恰好 `⌊cnt/2⌋` 对（剩余至多 1 个），上界可达。∎

**引理 2**：各值之间的配对互相独立，总数对数为 $\sum_v \lfloor cnt(v)/2 \rfloor$。

**证明**：一个数对的两个元素值相同，故任何数对只消耗单一值的元素；不同值的消耗量互不制约，可各自独立取到引理 1 的上界。∎

**定理**：算法返回的 `[pairs, leftover]` 分别等于「无法继续执行时」的数对总数与剩余元素数。

**证明**：「直到无法继续」即不存在任何值剩余出现次数 `>= 2`，也就是每个值都取到了引理 1 的最大对数，故数对总数为 `pairs = Σ⌊cnt(v)/2⌋`。每对消耗 2 个元素，剩余元素数为 `n − 2·pairs = Σ(cnt(v) mod 2)`，此时每个值至多剩 1 个，确实无法继续。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n + U)`。一次遍历计数 `O(n)`，一次遍历值域 `U = 101`（哈希表则遍历不同值个数）；本题下即 `O(n)`。
- **空间复杂度**：定长数组 `O(U) = O(1)`；哈希表为 `O(min(n, U))`。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> numberOfPairs(vector<int>& nums) {
        int cnt[101] = {0};
        for (int x : nums) cnt[x]++;
        int pairs = 0;
        for (int v = 0; v <= 100; v++) pairs += cnt[v] / 2;
        return {pairs, (int)nums.size() - 2 * pairs};
    }
};
```

### Python

```python
class Solution:
    def numberOfPairs(self, nums: List[int]) -> List[int]:
        cnt = Counter(nums)
        pairs = sum(c // 2 for c in cnt.values())
        return [pairs, len(nums) - 2 * pairs]
```

## 8. 边界情况与易错点

1. **单元素**：`[0]` → `[0,1]`，计数循环自然处理，无需特判。
2. **全部成对**：`[1,1]` → `[1,0]`，`leftover` 用 `n - 2*pairs` 得 0。
3. **值可以为 0**：定长数组要开 `cnt[101]` 而不是 `cnt[100]`，下标 0 也要能存。
4. **返回顺序**：`[数对数, 剩余数]`，别写反。
5. **别过度模拟**：不需要真的删除元素或排序；排序后相邻配对虽也正确，但多花了 `O(n log n)` 且代码更长。
