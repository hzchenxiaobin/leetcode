# LeetCode 数位和相等数对的最大和 题解

## 1. 题目概述

- **标题 / 题号**：数位和相等数对的最大和（#2342，medium）
- **链接**：https://leetcode.cn/problems/max-sum-of-a-pair-with-equal-sum-of-digits/
- **来源**：LeetCode 第 302 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、排序、堆（优先队列）

**题意**：给定下标从 0 开始的正整数数组 `nums`，选出两个**不同下标** `i`、`j`（数值可以相同），使得 `nums[i]` 与 `nums[j]` 的**数位和**（十进制各位数字之和）相等，返回 `nums[i] + nums[j]` 可取得的最大值；若不存在这样的数对，返回 `-1`。

**约束**：

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`

> 💡 两个关键性质：一是配对条件只取决于**数位和**这个派生属性，与数值本身无关，天然适合按数位和分组；二是 `nums[i] <= 10^9` 意味着数位和至多为 $9 \times 9 = 81$（即 $999{,}999{,}999$），**键域极小**，哈希表甚至可以换成定长数组。

## 2. 示例

**示例 1**

```text
输入：nums = [18,43,36,13,7]
输出：54
解释：数位和相等的数对有两组：
- (0, 2)：18 与 36 的数位和都是 9，18 + 36 = 54；
- (1, 4)：43 与 7 的数位和都是 7，43 + 7 = 50。
最大和为 54。
```

**示例 2**

```text
输入：nums = [10,12,19,14]
输出：-1
解释：四个数的数位和分别为 1、3、10、5，互不相同，不存在可配对的数对。
```

**示例 3**（补充：同组超过两个元素）

```text
输入：nums = [4,13,22]
输出：35
解释：三个数的数位和都是 4，同属一组。两两组合 4+13=17、4+22=26、13+22=35，
最优数对取组内最大的两个数 13 与 22，和为 35。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有 $O(n^2)$ 个数对，对每对分别计算数位和并比较，相等则用 `nums[i] + nums[j]` 更新答案。`n = 10^5` 时约需 $5 \times 10^9$ 次比较，**必然超时**。浪费的根源在于：同一个元素被反复拆数位、反复参与比较，而实际上每个数位和分组内我们只关心**最大的两个数**。

### 3.2 核心观察：按数位和分组，组内取前两大

![按数位和分组](images/wc302_q2_digitsum_grouping.svg)

**Insight**：合法数对的两元素数位和相等，必然落在**同一个分组**里：

- 不同分组之间永远无法配对，各组**相互独立**；
- 若组 $G_s$（数位和均为 $s$ 的元素构成的多重集）至少有两个元素，则它能贡献的最大和就是组内**最大与次大**元素之和；
- 数位和取值落在 $[1, 81]$，分组数至多 81 个，开销可忽略。

进一步化简：扫描时每来一个新数 $x$（数位和为 $s$），它若能配对，最优搭档一定是**此前见过的、数位和同为 $s$ 的最大数**。于是只需维护映射 `best[s]`（数位和 → 该组已见过的最大值），单遍扫描即可，连"前两大"都不必显式维护。

### 3.3 算法流程

![算法流程](images/wc302_q2_algorithm_flow.svg)

1. 初始化答案 `ans = -1`，映射 `best` 为空（数位和 → 组内已见最大值）；
2. 依次扫描每个 $x \in \text{nums}$：
   - 计算 $x$ 的数位和 $s$（反复取 `% 10`、`/ 10`）；
   - 若 `best[s]` 存在，用 `best[s] + x` 更新 `ans`；
   - 更新 `best[s] = max(best[s], x)`；
3. 扫描结束，返回 `ans`。

> ⚠️ **顺序不能反**：必须先用**旧** `best[s]` 更新答案，再写入 `best[s]`。反过来的话 `x` 会和自己配对，答案错误地偏大。这是本解法唯一的顺序陷阱。

### 3.4 示例演算

![示例演算](images/wc302_q2_example_walkthrough.svg)

以 `nums = [18,43,36,13,7]` 为例，`ans` 初始为 `-1`：

| $x$ | 数位和 $s$ | best[s] 处理前 | ans 更新 | best[s] 处理后 |
|-----|-----------|----------------|----------|----------------|
| 18  | 9         | ∅              | 不变（−1） | 9 → 18       |
| 43  | 7         | ∅              | 不变（−1） | 7 → 43       |
| 36  | 9         | 18             | max(−1, 18+36) = **54** | 9 → 36 |
| 13  | 4         | ∅              | 不变（54） | 4 → 13       |
| 7   | 7         | 43             | max(54, 43+7) = 54 | 7 → 43（43 仍最大） |

第 3 步命中 $(18, 36)$ 得到 54，第 5 步候选 50 不刷新；组 4 只有 13 一个元素，从未配对。最终返回 **54** ✓。

## 4. 算法细节

1. **数位和计算**：`for (int v = x; v > 0; v /= 10) s += v % 10;`，每个数至多 10 位，单次 $O(\log_{10} V) \approx O(10)$。本题 `nums[i] >= 1` 恒成立，无 `0` 的特判问题（若值域含 `0`，其数位和按约定为 `0`，需改用 do-while 或特判）。
2. **键域分析**：数位和 $s \in [1, 81]$，键小且稠密，`best` 可用长度 90 的定长数组替代哈希表，以 `-1` 作哨兵（元素均为正数，`-1` 不会与真实值混淆），免去哈希开销，空间严格 $O(1)$。
3. **为何只维护最大值就够**：设组内前两大为 $M_1 \ge M_2$，无论二者谁后到，**后到者**被处理时，先到者已在 `best[s]` 中，故 `best[s] + x` ≥ $M_1 + M_2$ 一定会被作为候选算出；又候选本身是合法数对和，不会超过最优。双向夹逼，"只留最大"不漏最优。
4. **答案初始化为 -1**：`nums[i] + nums[j]` 恒为正，`-1` 不会被任何合法和覆盖；结束时 `ans == -1` 即无解，无需额外标记。
5. **等价写法**：也可将数组**降序排序**后，对每个数位和取最先出现的两个元素之和；或每组用大小为 2 的小根堆维护前两大。思想相同，但排序要多花 $O(n \log n)$，堆引入常数，均劣于单遍维护最大值。

## 5. 正确性证明

**引理 1（组内最优 = 前两大之和）**：设 $G_s$ 为数位和等于 $s$ 的全部元素（按出现次数计的多重集），$M_1 \ge M_2$ 为其中最大与次大元素。若 $|G_s| \ge 2$，则 $G_s$ 中两个不同下标元素之和的最大值为 $M_1 + M_2$。

**证明**：任取 $G_s$ 中两个不同下标的元素 $a \ge b$。若 $a$ 是 $M_1$ 的某次出现，则 $b$ 只能取自其余出现，故 $b \le M_2$；若 $a < M_1$，则 $a \le M_2$，且 $b \le a \le M_2$。两种情形均有 $a + b \le M_1 + M_2$。反之，直接取 $M_1$ 与 $M_2$ 对应的两次出现（下标必然不同），和恰为 $M_1 + M_2$，上界可达。∎

**引理 2（分组独立）**：合法数对的两元素同属某一组 $G_s$，故全局最优值为

$$\max_{s:\,|G_s| \ge 2} \big(M_1(s) + M_2(s)\big)$$

若不存在大小 $\ge 2$ 的组，则答案为 $-1$。

**证明**：数位和相等当且仅当同组。由引理 1，每组内可达到的最优配对和为前两大之和；组与组之间无任何配对可能，互相独立，故全局最优为各组最优的最大值。当所有组大小均为 1 时不存在合法数对。∎

**定理**：单遍扫描算法（对每个新元素 $x$，先用 `best[s]` 更新 `ans`，再更新 `best[s]`）返回的 `ans` 等于引理 2 中的最优值。

**证明**：先证 `ans ≤ 最优`（合法性）：每次更新形如 `best[s] + x`，其中 `best[s]` 的写入严格早于当前元素 $x$ 被读取，故二者下标不同且数位和相等，是合法数对之和，不超过最优值。再证 `ans ≥ 最优`（可达性）：对扫描过程归纳可证，处理完每个元素后 `best[s]` 恒等于已扫描前缀中数位和为 $s$ 的最大值。设最优数对为 $(i^*, j^*)$，不妨 $i^* < j^*$，同属组 $s$。处理 $j^*$ 时 $i^*$ 已在前缀中，故 `best[s]` $\ge \text{nums}[i^*]$，于是 `ans` $\ge$ `best[s] + nums[j*]` $\ge \text{nums}[i^*] + \text{nums}[j^*]$，即达到最优。两个方向结合，`ans` 恰为最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log V)$，其中 $V = 10^9$。每个元素计算一次数位和需 $O(\log_{10} V) \approx 10$ 次位运算，查表与更新均为 $O(1)$；总量约 $10^6$ 次基本操作。
- **空间复杂度**：$O(D)$，其中 $D \le 81$ 为不同数位和的个数（定长数组即 $O(1)$；哈希表大小同样被封顶在 82 以内，与 $n$ 无关）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumSum(vector<int>& nums) {
        int best[90];
        fill(begin(best), end(best), -1);
        int ans = -1;
        for (int x : nums) {
            int s = 0;
            for (int v = x; v > 0; v /= 10) s += v % 10;
            if (best[s] != -1) ans = max(ans, best[s] + x);
            best[s] = max(best[s], x);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumSum(self, nums: List[int]) -> int:
        best = {}
        ans = -1
        for x in nums:
            s = sum(map(int, str(x)))
            if s in best:
                ans = max(ans, best[s] + x)
            best[s] = max(best.get(s, x), x)
        return ans
```

## 8. 边界情况与易错点

1. **`n = 1`**：不存在数对，返回 `-1`。`best[s]` 从未被读取两次，`ans` 保持 `-1`，无需特判。
2. **所有数位和互不相同**：如 `[10,12,19,14]`（数位和 1、3、10、5），同样自然返回 `-1`。
3. **重复元素**：`[10, 10]` 应输出 `20`。两个数值相同的元素数位和必然相等，且下标不同即合法；单遍算法中第二个 `10` 会与已入表的第一个 `10` 配对，自动正确。
4. **整型溢出余量**：$2 \times 10^9 < 2^{31} - 1 \approx 2.147 \times 10^9$，`int` **恰好不溢出**但余量极小；若值域稍大（如 $10^{18}$）必须换 `long long`，实战建议直接用 64 位规避风险。
5. **更新顺序**：先更新 `ans` 再更新 `best[s]`，写反会让 `x` 与自己配对，答案偏大（例如 `[18]` 会错误地返回 36）。
6. **数位和不是位数也不是数值**：分组键是各位数字之和，别与 Q1 的"按值计数"或按二进制位运算分组混淆；注意 $10^9$ 的数位和是 $1$ 而不是 $0$，定长数组开 90 已覆盖全部取值 $[1, 81]$。
