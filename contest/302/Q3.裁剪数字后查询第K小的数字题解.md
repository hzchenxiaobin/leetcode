# LeetCode 裁剪数字后查询第 K 小的数字 题解

## 1. 题目概述

- **标题 / 题号**：裁剪数字后查询第 K 小的数字（#2343，medium）
- **链接**：https://leetcode.cn/problems/query-kth-smallest-trimmed-number/
- **来源**：LeetCode 第 302 场周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、排序、基数排序、稳定排序

**题意**：给你下标从 0 开始的字符串数组 `nums`（每个字符串**长度相等**且只含数字）和二维整数数组 `queries`，其中 `queries[i] = [ki, trimi]`。对每个查询：把 `nums` 中每个数字**裁剪**到只剩最右边 $\text{trim}_i$ 个数位，在裁剪结果中找出**第 $k_i$ 小**的元素，返回其**下标**（裁剪后数值相同时，下标小者视为更小）；随后 `nums` 恢复原状。返回与 `queries` 等长的答案数组。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i]\text{.length} \le 100$，所有字符串**等长**，只含数字，可能有前导零
- $1 \le \text{queries.length} \le 100$
- $1 \le k_i \le \text{nums.length}$，$1 \le \text{trim}_i \le \text{nums}[0]\text{.length}$

> 💡 三个派生性质串起本题：**(1)** 等长串裁剪后仍等长，字典序 = 数值序；**(2)** 后缀嵌套——$\text{trim}=t$ 的键恰是 $\text{trim}=t-1$ 的键**前面多一位数字**；**(3)** 平局规则"下标小者在前"正是**稳定排序**的天然副产物。三条叠加，所有查询可以排成一条 **LSD 基数排序流水线**：每轮只做一次 $O(n+10)$ 的稳定分桶。题目"进阶"也明确点名了基数排序。

## 2. 示例

**示例 1**

```text
输入：nums = ["102","473","251","814"], queries = [[1,1],[2,3],[4,2],[1,2]]
输出：[2,2,1,0]
解释：
1. trim=1 → ["2","3","1","4"]，第 1 小是 1，下标 2
2. trim=3 → 原样不变，第 2 小是 251，下标 2
3. trim=2 → ["02","73","51","14"]，第 4 小是 73，下标 1
4. trim=2 → 最小是 "02"（值为 2），下标 0
```

**示例 2**

```text
输入：nums = ["24","37","96","04"], queries = [[2,1],[2,2]]
输出：[3,0]
解释：trim=1 时有两个 4，下标 0 的 4 视为更小 ⟹ 第 2 小是下标 3；
     trim=2 时第 2 小是 24，下标 0。
```

**示例 3**（补充：裁剪后全部相同，纯拼下标序）

```text
输入：nums = ["500","200","100"], queries = [[1,1],[2,1],[3,1]]
输出：[0,1,2]
解释：trim=1 后全为 "0"，平局规则下第 1/2/3 小分别取下标 0/1/2。
```

## 3. 解题思路

### 3.1 暴力思路：每个查询独立排序

最直白的做法：对每个查询 `[k, trim]`，取出每个元素的最右 $\text{trim}$ 位作键，与下标配对后**整体排序**（键相同时下标小者在前），取第 $k-1$ 个位置的下标：

```text
for (k, trim) in queries:
    pairs = sorted((nums[i][-trim:], i) for i in range(n))   # 等长串字典序 = 数值序
    ans.append(pairs[k-1][1])
```

单次查询排序 $O(n \log n \cdot t)$（比较等长串需 $O(t)$），总计 $O(q \cdot n \log n \cdot L)$。以 $n = q = L = 100$ 计约 $7 \times 10^6$，**本题数据下可以直接 AC**——赛时先拿暴力保底完全合理。

但它把同一份劳动做了两遍重复：**相同 `trim` 的查询各自重排一次**；更重要的是它没看到 `trim` 之间的**嵌套结构**——`trim=2` 的排序与 `trim=1` 的排序并非独立，而是"在低位已排好的基础上再按高位分桶"。把这个结构用起来，就是进阶要求的基数排序解法。

### 3.2 核心观察：离线归组 + LSD 基数排序流水线

![裁剪后缀的 LSD 流水线概念图](images/wc302_q3_suffix_pipeline_concept.svg)

**Insight 1（可以离线）**：每次查询后 `nums` 都恢复原状，查询之间**互不影响**，顺序任意。于是把查询**按 `trim` 归组**，`trim` 相同的共享同一次排序结果。

**Insight 2（后缀嵌套）**：记 $d_t(i)$ 为元素 $i$ 从右数第 $t$ 个数字。$\text{trim}=t$ 的后缀串（长为 $t$）恰是 $\text{trim}=t-1$ 的后缀串**在最左边多写一位** $d_t$。等长串比大小从最高位比起——即先比 $d_t$，$d_t$ 相同时落到 $t-1$ 层已经排好的后缀比较。这正是 **LSD 基数排序**的归纳结构：**低位先排，高位稳定分桶**。

**Insight 3（平局规则免费获得）**：LSD 每轮要求**稳定**分桶（同数字保持入桶前顺序）。初始 `order = [0,1,…,n-1]` 即下标序；归纳可得：第 $t$ 轮后，`order` 恰按"最右 $t$ 位的数值序，**平局时下标小者在前**"排列——平局规则不需要任何额外代码。

三条合起来：维护一条 `t = 1, 2, …, L` 的流水线，第 $t$ 轮只做**一次稳定分桶**，然后回答所有 $\text{trim}=t$ 的查询（第 $k$ 小 = `order[k-1]`）。全部查询服务完毕，总计 $L$ 次分桶。

### 3.3 算法流程

![算法流程图](images/wc302_q3_radix_flow.svg)

1. **初始化**：`order = [0, 1, …, n-1]`（下标序）；把每个查询的下标 `qi` 归入 `byTrim[trim]`；
2. **逐轮分桶**（$t = 1, 2, \dots, L$）：按每个元素从右数第 $t$ 位数字（字符 `nums[i][L-t]`）对 `order` 做**稳定**分桶——10 个桶按 $0 \sim 9$ 排列，桶内保持入桶顺序；拼接得新 `order`；
3. **就地回答**：对本轮 `byTrim[t]` 中的每个查询 `qi`：`ans[qi] = order[k_qi − 1]`；
4. $L$ 轮结束（或所有查询已回答），返回 `ans`。

> ⚠️ 两个写代码时的死穴：**分桶必须按当前 `order` 顺序入桶**（稳定性是一切正确性的地基）；**`k` 是 1-indexed**，取 `order[k-1]`。

### 3.4 示例演算

![示例演算图](images/wc302_q3_example_walkthrough.svg)

以示例 1 `nums = ["102","473","251","814"]`、`queries = [[1,1],[2,3],[4,2],[1,2]]` 演算，`order` 初始为 `[0,1,2,3]`：

| 轮次 | 入桶顺序 | 使用的位 | 非空桶（桶号: 下标） | 新 order | 本轮回答 |
|------|----------|----------|----------------------|----------|----------|
| $t=1$ | $[0,1,2,3]$ | 末位 $2,3,1,4$ | 1:[2] 2:[0] 3:[1] 4:[3] | $[2,0,1,3]$ | $(k{=}1)$ → ans[0] = 2 |
| $t=2$ | $[2,0,1,3]$ | 第 2 位 $5,0,7,1$ | 0:[0] 1:[3] 5:[2] 7:[1] | $[0,3,2,1]$ | $(k{=}4)$ → ans[2] = 1；$(k{=}1)$ → ans[3] = 0 |
| $t=3$ | $[0,3,2,1]$ | 第 3 位 $1,8,2,4$ | 1:[0] 2:[2] 4:[1] 8:[3] | $[0,2,1,3]$ | $(k{=}2)$ → ans[1] = 2 |

验证：$t=2$ 轮后裁剪值依次为 `"02","14","51","73"` 升序 ✓；$t=3$ 轮后为 `102, 251, 473, 814` 升序 ✓。三个查询分别在各自 `trim` 的轮次被回答，按查询下标汇总得 **answer = [2, 2, 1, 0]** ✓。

注意本例各轮数字互不相同，稳定性未被动用；平局发生时（如示例 2 的两个末位 4）靠初始下标序自动分先后。

## 4. 算法细节

1. **位序换算**：从右数第 $t$ 位 ⟺ 字符下标 `nums[i][L - t]`（0 起从左数）。流水线 $t$ 严格递增，天然从低位做到高位。
2. **稳定分桶的实现**：键域只有 $\{0,1,\dots,9\}$，两种等价写法——
   - **计数排序**（C++）：`pos[d+1]` 统计数字 $d$ 的个数，做**排他前缀和**得每个桶的起始槽位，再**从左到右**扫 `order` 依次落位 `nxt[pos[d]++] = i`；
   - **显式桶**（Python）：10 个列表，按当前 `order` 顺序 `append`，最后按桶号 $0 \sim 9$ 拼接。
   两者稳定性同源：同桶元素保持入桶顺序。
3. **为什么不能从左往右逐位单趟分桶**：从最高位开始的一趟分桶只按最高位排序，低位信息全部丢失（MSD 基数排序需要对每个桶**递归**再排才正确）。LSD 的正确性依赖"低位已排好 + 高位稳定分桶"的归纳结构，单趟即可，不需要递归。
4. **平局规则的落点**：不需要显式比较下标。初始 `order` 为下标序，是 $t = 0$ 的归纳基；每轮稳定性把"上一轮的先后关系"原封不动传给"当前位相同"的元素，键全等的元素始终保持下标序。
5. **等长 ⟹ 字符串直接比**：裁剪结果都是长度 $\text{trim}$ 的数字串，`'0' < '1' < … < '9'` 的字符序即数值序，前导零天然参与比较，全程**无需转整数**。
6. **查询归组**：`byTrim` 用长度 $L+1$ 的数组即可（$1 \le \text{trim} \le L$），桶里存**原查询下标**，回答时写 `ans[qi]`，天然保持输出顺序、重复查询互不干扰。
7. **"恢复原状"自动满足**：算法只读 `nums` 不写。若按题面字面做"原地裁剪再拼回"，反而引入无谓的拷贝。

## 5. 正确性证明

**引理 1（等长数字串：字典序 = 数值序）**：对任意两个长度同为 $t$、可含前导零的数字串 $a, b$，按字典序比较与按数值比较结果一致。

**证明**：若两串全同，则数值也相等。否则设从左到右第一个不同位置为 $p$，即 $a_p \ne b_p$，前缀 $a_{0..p-1} = b_{0..p-1}$。数值可写为 $\sum_i a_i \cdot 10^{t-1-i}$；公共前缀贡献相同，相消后大小由 $p$ 位及之后决定。不妨 $a_p > b_p$，则

$$\left(\sum_{i \ge p} a_i 10^{t-1-i}\right) - \left(\sum_{i \ge p} b_i 10^{t-1-i}\right) \ge (a_p - b_p) 10^{t-1-p} - \sum_{i > p} 9 \cdot 10^{t-1-i} \ge 10^{t-1-p} - (10^{t-1-p} - 1) = 1 > 0,$$

即 $p$ 位之后的所有位数之差至多 $10^{t-1-p} - 1$，不足以翻转第 $p$ 位造成的大小关系。故字典序大者数值亦大。∎

**引理 2（LSD 流水线不变式）**：记 $\text{key}_t(i) = (d_t(i), d_{t-1}(i), \dots, d_1(i))$，即元素 $i$ 最右 $t$ 位从高到低的数字序列。则第 $t$ 轮分桶结束后，`order` 按 $\text{key}_t$ 的字典序排列；$\text{key}_t$ 相同的元素按**下标升序**排列。

**证明**：对 $t$ 归纳。$t = 0$：`order = [0,1,…,n-1]`，$\text{key}_0$ 为空序列，全体相等，恰为下标序，成立。设结论对 $t-1$ 成立。第 $t$ 轮按 $d_t$ **稳定**分桶：

- 桶与桶按数字 $0 \sim 9$ 排列，$d_t$ 小者在前——即 $\text{key}_t$ 的**首坐标**小者在前；
- 桶内 $d_t$ 相同，顺序继承 $t-1$ 轮顺序，由归纳假设按 $\text{key}_{t-1}$ 字典序（即 $\text{key}_t$ 的后缀）排列；
- $\text{key}_t$ 完全相同的两个元素，每一轮都落入同桶且相对顺序不变，一路归纳到 $t=0$ 时仍为下标序。

三个层次恰是字典序比较的展开式，结论成立。∎

**定理**：对每个查询 $(k, \text{trim})$，算法写入的 `ans[qi]` 恰为"裁剪到最右 $\text{trim}$ 位后第 $k$ 小的元素下标（平局取下标小者）"。

**证明**：元素 $i$ 裁剪后的比较对象是长度为 $\text{trim}$ 的后缀串 $s_i$。由引理 1，$s_i$ 之间的数值序 = 字典序；而等长串从左到右逐位比较，恰是 $\text{key}_{\text{trim}}$ 首坐标优先的字典序。由引理 2，第 $\text{trim}$ 轮结束时 `order` 正按该序排列，平局时下标小者在前——这正是题目规定的全序。第 $k$ 小即该序中第 $k$ 个元素 `order[k-1]`。流水线按 $t$ 递增推进，回答发生在对应轮次分桶完成之后，且约束 $1 \le \text{trim} \le L$ 保证该轮必然执行。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(L \cdot (n + 10)\big) + O(q)$。分桶共 $L$ 轮，每轮一次稳定计数/桶分摊 $O(n + 10)$（每个元素入桶一次 + 前缀和/拼接常数开销）；查询归组与逐轮回答合计 $O(q)$。以 $n = L = q = 100$ 计约 $10^4$ 量级基本操作，比暴力的 $O(q \cdot n \log n \cdot L) \approx 7 \times 10^6$ 低三个数量级；这正是"进阶"一问的答案——基数排序解法为 $O(L \cdot n + q)$（10 为常数）。
- **空间复杂度**：$O(n + q)$。`order` 与落位数组 $O(n)$，查询归组 $O(q)$，计数数组 $O(10)$；全程不复制字符串、不转整数，与位长 $L$ 无关的额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> smallestTrimmedNumbers(vector<string>& nums, vector<vector<int>>& queries) {
        int n = nums.size(), L = nums[0].size(), q = queries.size();
        vector<vector<int>> byTrim(L + 1);
        for (int i = 0; i < q; i++) byTrim[queries[i][1]].push_back(i);
        vector<int> order(n), ans(q);
        iota(order.begin(), order.end(), 0);
        for (int t = 1; t <= L; t++) {
            int pos[11] = {};
            for (int i : order) pos[nums[i][L - t] - '0' + 1]++;
            for (int d = 0; d < 10; d++) pos[d + 1] += pos[d];
            vector<int> nxt(n);
            for (int i : order) nxt[pos[nums[i][L - t] - '0']++] = i;
            order = move(nxt);
            for (int qi : byTrim[t]) ans[qi] = order[queries[qi][0] - 1];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def smallestTrimmedNumbers(self, nums: List[str], queries: List[List[int]]) -> List[int]:
        n, L = len(nums), len(nums[0])
        by_trim = [[] for _ in range(L + 1)]
        for i, (_, trim) in enumerate(queries):
            by_trim[trim].append(i)
        order = list(range(n))
        ans = [0] * len(queries)
        for t in range(1, L + 1):
            buckets = [[] for _ in range(10)]
            for i in order:                       # 按当前 order 入桶 ⟹ 稳定
                buckets[ord(nums[i][L - t]) - 48].append(i)
            order = [i for b in buckets for i in b]  # 按桶号 0~9 拼接
            for qi in by_trim[t]:
                ans[qi] = order[queries[qi][0] - 1]
        return ans
```

## 8. 边界情况与易错点

1. **`k` 是 1-indexed**：答案是 `order[k-1]`；写成 `order[k]` 轻则整体偏一位，重则数组越界。
2. **位序换算写反**：从右数第 $t$ 位是 `nums[i][L - t]`。误写成 `nums[i][t-1]`（从左数）后 MSD 单趟不再正确——例如 `nums = ["12","21"]`、查询 `(k=1, trim=1)`：正确答案 1（末位 $2 > 1$），错版按首位 $1 < 2$ 得 0。
3. **稳定性是平局规则的唯一载体**：分桶必须按当前 `order` 顺序入桶；C++ 计数排序若把落位扫描方向写反（或换用非稳定 `sort`），"按位排序"本身仍对，但平局次序反了——只有出现相同裁剪值的查询才会翻车（如示例 2 的两个末位 4），是极隐蔽的 WA。
4. **初始 `order` 必须是下标序** `[0,1,…,n-1]`：它既是 $t=0$ 的归纳基，也是平局规则的总来源；初始顺序错，后面全错。
5. **前导零**：等长串直接按字符比较即可，`"02" < "14"` 与数值 $2 < 14$ 一致；若自行转 `int` 再排序，必须把下标作为次关键字，否则平局规则丢失、还得额外处理值相等的情况。
6. **`trim = L`（不裁剪）**：循环天然推进到 $t = L$，无需特判；`byTrim` 开 $L+1$ 长即可覆盖。
7. **同 `trim` 多查询要归组**：归组后共享一次分桶；漏掉归组、对每个查询从 $t=1$ 重跑，复杂度退化为 $O(q \cdot L \cdot n)$——本题数据（$\le 10^6$）仍能过，但完全背离流水线的初衷。
8. **"恢复原状"不是操作而是约束**：算法只读 `nums` 即天然满足；题面描述的"裁剪再恢复"只是单查询视角的叙述方式，切勿真去原地改串。
9. **`n = 1` 与全平查询**：`order` 恒为 `[0]`，任意 `k=1` 答 0；裁剪后全相同的输入（示例 3）退化为纯下标序，稳定性保证答案正确。
