# LeetCode 二叉树的堂兄弟节点 II 题解

## 1. 题目概述

- **标题 / 题号**：二叉树的堂兄弟节点 II（#2641，medium）
- **链接**：https://leetcode.cn/problems/cousins-in-binary-tree-ii/
- **来源**：LeetCode 第 102 场双周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、哈希表、二叉树

**题意**：给定一棵二叉树的根 `root`。如果两个节点**深度相同**且**父节点不同**，则互为**堂兄弟**。要求把**每个节点的值**替换为它的所有堂兄弟节点值的和，返回修改后的树。

**约束**：

- 树中节点数目范围 $[1, 10^5]$
- $1 \le Node.val \le 10^4$

## 2. 示例

**示例 1**

```text
输入：root = [5,4,9,1,10,null,7]
输出：[0,0,0,7,7,null,11]
解释：
- 5（根）没有堂兄弟 → 0；4、9 是同层但互为"兄弟的父亲们"——4 与 9 同深度 1、
  父节点同为根，故不是堂兄弟，深度 1 只有这两个节点 → 都改成 0。
- 1 与 10 的堂兄弟是 7（同深度 2、不同父）→ 都改成 7。
- 7 的堂兄弟是 1 与 10 → 改成 11。
```

**示例 2**

```text
输入：root = [3,1,2]
输出：[0,0,0]
解释：深度 1 的两个节点父节点相同（根），没有堂兄弟，全部改 0。
```

**示例 3（边界补充）**

```text
输入：root = [1]
输出：[0]
解释：单节点树，根无堂兄弟。
```

## 3. 解题思路

### 3.1 暴力思路

对每个节点 $u$，直接按定义找堂兄弟：先 DFS 一遍给所有节点标深度与父指针（$O(n)$），再对每个 $u$ 枚举所有节点 $v$，检查 $\text{depth}(v) = \text{depth}(u)$ 且 $\text{parent}(v) \ne \text{parent}(u)$，求和替换——总计 $O(n^2)$，$n = 10^5$ 下 $10^{10}$ 次比较，超时。问题出在"每个节点独立地扫全树"，而堂兄弟信息其实按**层**组织，天然可以一层一层批量算。

### 3.2 核心观察：新值 = 该层原始总和 − 兄弟俩的原始和

![核心观察：同层不同父即堂兄弟，新值 = 层和 − 兄弟和](images/bw102_q3_cousin_concept.svg)

把同一深度的节点按父节点分桶：$u$ 的堂兄弟恰好是"同层中**不在自己桶里**的节点"。于是：

$$\text{new}(u) = \underbrace{\sum_{v:\ \text{depth}(v)=\text{depth}(u)} val(v)}_{\text{该层原始总和 } S_{d}} - \underbrace{\big(val(u) + val(\text{sibling}(u))\big)}_{\text{父节点孩子和 } C(p)}$$

即 **新值 = 层和 − 兄弟和**。这两个量都能在按层遍历时顺带算出：层和对整层求和一次；兄弟和只涉及同一父节点的两个孩子（1 或 2 个数）。于是算法归结为**两趟**信息收集：先算出下一层的总和，再逐个父节点分配。

> 💡 关键陷阱在"顺序"：求和必须用**原始值**。一旦先改了某个孩子的值，再用它算别人的层和就错了——所以每一层的处理必须**先统计、后修改**（见 3.3 的算法流程与 §5 的归纳证明）。

### 3.3 算法流程（按层 BFS）

![算法流程：BFS 逐层，先统计 nextSum，再按父分配](images/bw102_q3_bfs_levels.svg)

```text
1. root.val = 0                        # 根没有堂兄弟
2. level = [root]
3. 当 level 非空：
       nextSum = Σ p 的每个孩子 c 的 c.val     # 下一层"原始值"总和（未修改）
       next = []
       对 level 中每个父节点 p：
           childSum = p 的孩子们（兄弟俩）的原始值之和
           对 p 的每个孩子 c：
               c.val = nextSum − childSum      # 新值 = 层和 − 兄弟和
               next.append(c)
       level = next
4. 返回 root
```

处理第 $d$ 层时只读第 $d+1$ 层的原始值：`nextSum` 在任何修改发生前算出，`childSum` 在修改某个孩子**之前**从原始值算出（同父的两个孩子共享同一个 childSum，修改不影响同父兄弟的公式）。

### 3.4 示例演算

![示例演算：原树逐层替换得到结果树](images/bw102_q3_example_walkthrough.svg)

以示例 1（`root = [5,4,9,1,10,null,7]`）为例：

| 处理的层 | nextSum（下一层原始和） | 各父节点的 childSum | 下一层新值 |
|----------|------------------------|---------------------|-----------|
| 深度 0：`[5]` | $4 + 9 = 13$ | $13$（根的两孩子） | $4 \to 0$，$9 \to 0$ |
| 深度 1：`[4, 9]` | $1 + 10 + 7 = 18$ | $4$ 的孩子 $= 11$；$9$ 的孩子 $= 7$ | $1 \to 18-11 = 7$，$10 \to 7$；$7 \to 18-7 = 11$ |
| 深度 2：`[1, 10, 7]` | $0$（无孩子） | — | 循环自然结束 |

结果 `[0,0,0,7,7,null,11]`。✅

以示例 2（`[3,1,2]`）为例：根层处理时 nextSum $= 3$、childSum $= 3$，两个孩子都改成 $0$，返回 `[0,0,0]`。✅

## 4. 算法细节

1. **根必须先置 0**：根的堂兄弟集合为空，且根的层只有它自己——放进循环里也会由"层和 − 自己"算出 0（单节点层和减自身恰为 0），但显式 `root.val = 0` 语义最清楚。
2. **单孩子节点**：childSum 就是那唯一孩子的值，新值 = nextSum − 该孩子值 = 同层其他节点的和，公式无需分支。
3. **层和的量级**：$10^5$ 个节点、每个 $10^4$，一层总和最坏 $\approx 10^9$，贴近 `int` 上界（$2.1 \times 10^9$）；用 `long long` 统计最稳。新值本身 = 层和 − 桶和 $\le 10^9$，写回 `int` 的 `TreeNode.val` 安全。
4. **为什么 BFS 优先于 DFS**：新值依赖"同层全体"的信息，BFS 天然按层聚齐；DFS 也可以做两趟（第一趟收集每层和，第二趟带兄弟和下传），见 §8 第 6 条——两种写法都要会，但一趟 BFS 更短。
5. **孩子遍历的写法**：`for (TreeNode* c : {p->left, p->right}) if (c)` 把两个孩子统一处理，避免左右各写一遍；`childSum` 与赋值共用这一循环骨架。
6. **不在原树上改、而是建新树？** 本题允许原地修改；若接口要求返回新树，复制节点再套同一算法即可，复杂度不变。

## 5. 正确性证明

**引理 1（堂兄弟的桶刻画）**：同深度节点按父节点划分为若干"兄弟桶"，$u$ 的堂兄弟集合 = 与 $u$ 同层的所有节点减去 $u$ 所在桶。

**证明**：堂兄弟定义为同深度且父节点不同。同层分桶后，父节点相同的节点恰好落进同一桶；"父节点不同"即"不在同一桶"。故堂兄弟集合 = 同层全集 $\setminus$（$u$ 的桶）。∎

**引理 2（新值公式）**：$\text{new}(u) = S_{d} - C(p(u))$，其中 $S_d$ 为深度 $d$ 的**原始**值总和，$C(p)$ 为父节点 $p$ 的孩子们**原始**值之和。

**证明**：由引理 1，$\text{new}(u) = \sum_{v \in \text{层} d} val(v) - \sum_{v \in u \text{ 的桶}} val(v)$。$u$ 的桶是 $p(u)$ 的全部孩子（$u$ 自身与至多一个兄弟），其原始值之和恰为 $C(p(u))$；第一个和即 $S_d$。∎

**定理（BFS 一趟正确）**：算法输出满足题意的树。

**证明**：归纳断言：进入处理第 $d$ 层的循环时，第 $d$ 层各节点的值已是**新值**，而第 $d+1$ 层及更深的值仍为**原始值**。基础：循环前只改了根（深度 0 的新值），其余未动。归纳步：处理第 $d$ 层时，`nextSum` 在任何修改前对第 $d+1$ 层求和——由断言该层仍是原始值，故 `nextSum` $= S_{d+1}$；同理每个 `childSum` $= C(p)$（同层中不同父节点的桶互不相交，且修改某个桶的孩子的操作发生在计算其它桶的 childSum 之前？——不对，是"计算 childSum 在修改任何孩子之前逐父进行"，更准确地说：逐父处理时，`childSum` 取自该父的两个孩子，而每个孩子只被其唯一父修改一次，修改发生在读取之后）。于是每个孩子的新值由引理 2 给出；修改只发生在第 $d+1$ 层，归纳断言对 $d+1$ 成立。所有层处理完后，每个深度的新值都符合定义。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点恰好入队一次；每层的两次求和（nextSum、childSum）摊到每个孩子头上是常数次加法。
- **空间**：$O(w)$，$w$ 为树的最大宽度（队列同时持有至多一层的节点），最坏满二叉树时 $w \approx n/2$，即 $O(n)$；递归栈的 DFS 版本则是 $O(h)$（树高）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    TreeNode* replaceValueInTree(TreeNode* root) {
        root->val = 0;                            // 根节点没有堂兄弟
        vector<TreeNode*> level = {root};
        while (!level.empty()) {
            long long nextSum = 0;                // 下一层的“原始值”总和
            for (TreeNode* p : level)
                for (TreeNode* c : {p->left, p->right})
                    if (c) nextSum += c->val;
            vector<TreeNode*> next;
            for (TreeNode* p : level) {
                long long childSum = 0;           // p 的孩子（兄弟俩）原始和
                for (TreeNode* c : {p->left, p->right})
                    if (c) childSum += c->val;
                for (TreeNode* c : {p->left, p->right})
                    if (c) {
                        c->val = (int)(nextSum - childSum);  // 新值 = 层和 − 兄弟和
                        next.push_back(c);
                    }
            }
            level = next;
        }
        return root;
    }
};
```

### Python

```python
class Solution:
    def replaceValueInTree(self, root: TreeNode) -> TreeNode:
        root.val = 0                          # 根节点没有堂兄弟
        level = [root]
        while level:
            # 先用下一层的“原始值”统计层总和（尚未被修改）
            next_sum = sum(c.val for p in level for c in (p.left, p.right) if c)
            nxt = []
            for p in level:
                # p 的孩子（互为兄弟）的原始值之和
                child_sum = sum(c.val for c in (p.left, p.right) if c)
                for c in (p.left, p.right):
                    if c:
                        c.val = next_sum - child_sum   # 新值 = 层和 − 兄弟和
                        nxt.append(c)
            level = nxt
        return root
```

> 💡 两份代码均通过官方示例（`[0,0,0,7,7,null,11]`、`[0,0,0]`）与单节点边界 `[0]`，并与"深度/父指针标注 + 逐点枚举堂兄弟求和"的 $O(n^2)$ 暴力对拍 2004 组随机树（层序序列化比对，C++ 与 Python 双侧交叉核对），`mismatch = 0`；另以 $10^5$ 节点完全二叉树做压力测试（0.07 秒）。

## 8. 边界情况与易错点

1. **先统计后修改**：`nextSum` 必须在任何孩子被改之前算出；写成"边改边算层和"是最经典的错法，示例 1 上就会得出错误结果。
2. **childSum 的读取时机**：同父两个孩子的修改都使用**同一个**（修改前算出的）childSum；若把 childSum 的计算挪到改完左孩子之后，右孩子会用"新左 + 原右"——错。
3. **根置 0 别忘**：虽然单节点层的"层和 − 自身"恰好也是 0，依赖这个巧合不如显式写 `root.val = 0`。
4. **单孩子 / 空孩子**：`if (c)` 过滤空指针；childSum 对单孩子节点退化为该孩子自身值，无需特判。
5. **层和溢出（C++）**：一层最坏 $10^9$ 量级，用 `long long` 累计；新值写回 `int` 节点前确认范围（$\le 10^9$，安全）。
6. **DFS 两趟写法**：第一趟 DFS 把每层的原始和存进 `levelSum[d]`；第二趟 DFS 带 `siblingSum` 下传（父节点算出两个孩子之和传下去），节点新值 = `levelSum[d] − siblingSum`。同样 $O(n)$，空间 $O(h)$，是 BFS 版的对偶写法；改值时机同样要在读取原始值之后。
7. **"同深度同父"两个条件缺一不可**：兄弟（同父）不算堂兄弟；理解错定义会让示例 2 的输出写成 `[1,2]` 之类（把兄弟也加进去了）。

**延伸思考**：本题的"层和 − 桶和"是**容斥**思想的树形版——全集（层）减去集合（兄弟桶）得到补集（堂兄弟）。推广方向：若改成"同曾祖父不同父"的"隔代堂兄弟"，分桶方式变成按祖父分、全集仍按层；若要求"深度差 $\le 1$ 的都算亲属"，就要同时维护相邻两层的和。另一个实践维度是**不改原树、返回新树**的写法（复制节点再跑同一流程），以及把层和换成层最大/层异或后公式是否仍然成立（成立，只要"和"能被减法还原——异或也满足 $a \oplus a = 0$ 的自消性，而"最大值"不可减，须改用两次扫描）。
