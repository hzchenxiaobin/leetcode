# LeetCode 雇佣 K 位工人的总代价 题解

## 1. 题目概述

- **标题 / 题号**：雇佣 K 位工人的总代价（#2462，medium）
- **链接**：https://leetcode.cn/problems/total-cost-to-hire-k-workers/
- **来源**：LeetCode 第 318 场周赛 Q3
- **难度**：中等
- **标签**：数组、堆（优先队列）、双指针、模拟

**题意**：给定下标从 $0$ 开始的整数数组 `costs`（$\text{costs}[i]$ 为雇佣第 $i$ 位工人的代价）与整数 $k$、$candidates$。共进行 $k$ 轮雇佣，每轮恰好雇一人：

1. 每轮从**剩余工人**中最前 $candidates$ 名与最后 $candidates$ 名中选出候选；若剩余不足 $candidates$ 人，则全员都是候选；
2. 候选中选**代价最小**者，并列时选**下标最小**者；
3. 被雇佣者移除，后续不可再选。

返回恰好雇佣 $k$ 人的**总代价**。

**约束**：

- $1 \le n = \text{costs.length} \le 10^5$
- $1 \le \text{costs}[i] \le 10^5$——总代价可达 $10^{10}$，超 `int` 上界 $\approx 2.1 \times 10^9$，累加器必须用 64 位
- $1 \le k \le n$，$1 \le \text{candidates} \le n$——$candidates$ 可大到覆盖全体，此时结构退化（见 §3.2 观察二）

> 💡 本题在本仓库另有[每日题解 2462](../../solution/2401-2500/2462_雇佣K名工人的总代价.md)：以面试视角讲解统一的「双堆分工 + 前窗下标恒小」不变式。本篇按周赛复盘视角展开，主打赛场上**分支最少、最难写错**的**分流结构**——先判 $2 \cdot \text{candidates} \ge n$ 走单堆退化快路径，两端不相交时才用双堆相向补员，并补全正确性证明与边界清单，两篇互为印证。

```text
  第 1 轮：前窗 [17,12,10,2]，后窗 [2,11,20,8]，两端最小都是 2（下标 3 与 5），
          并列取下标小 → 雇 idx3（代价 2）；前窗吞入中间区 idx4（代价 7）
  第 2 轮：front 堆顶 (7,4) ＞ back 堆顶 (2,5) → 雇 idx5（代价 2）；中间区已空不补
  第 3 轮：front 堆顶 (7,4) ＜ back 堆顶 (8,8) → 雇 idx4（代价 7）
  总代价 = 2 + 2 + 7 = 11
```

## 3. 解题思路

### 3.1 暴力思路

每轮对剩余序列切出前 $candidates$ 名与后 $candidates$ 名，扫一遍取 $(\text{代价}, \text{下标})$ 最小者再删除。单轮 $O(n)$（删除还牵动搬移），$k$ 轮共 $O(nk)$，$n = k = 10^5$ 时达 $10^{10}$，必然超时；即便只扫两端窗口 $O(\text{candidates})$，$\text{candidates}$ 也可达 $n$，量级不变。

> 💡 浪费的根源：候选窗口随雇佣**只从两端相向推进**——每轮实际只有「一个元素出窗、至多一个元素进窗」，而暴力每轮把两端窗口整个重扫一遍。这正是**小顶堆维护动态定长窗口最小值**的招牌场景。

### 3.2 核心观察：三层结构 + 分流

![核心观察：两端候选窗口各配一个小顶堆，弹谁补谁](images/wc318_q3_two_heaps_concept.svg)

**观察一（分层）**：任意时刻全体工人分为三层——**前窗**（剩余的前 $c$ 名）、**后窗**（剩余的后 $c$ 名）、**中间区**（两者之外，暂时谁也选不到）。中间区工人在被某端窗口吞入之前**根本不参与比较**，所以完全不必每轮重扫：两端各配一个小顶堆，堆存 $(\text{cost}, \text{idx})$ 元组，堆顶即窗口最小；中间区等被吞时才入堆。弹谁就从同侧吞中间区补谁（`left++` / `right--`）。

**观察二（退化）**：若 $2c \ge n$，前窗∪后窗从一开始就覆盖全体剩余（且中途人数只减不增，覆盖关系一直成立），中间区不存在，规则退化为「全体剩余中按 $(\text{cost}, \text{idx})$ 取最小」。此时**单堆**就够：全体 $(\text{cost}, \text{idx})$ 建一次堆、连弹 $k$ 次。这是赛场上少一类边界、少一个 WA 点的快路径——不需要初始化守卫，也不需要空堆分支。

**观察三（不变式）**：两端不相交时，由相向初始化与相向补员，**front 堆中下标恒小于 back 堆中下标**。于是「并列取下标小」不需要任何额外逻辑：堆里存 $(\text{cost}, \text{idx})$ 元组，堆内并列由元组字典序自动裁决；跨堆并列时两堆顶直接做元组比较，`front.top() ≤ back.top()` 成立即取 front（前窗下标必然更小）。

### 3.3 算法流程

![算法流程：先按 2·candidates 与 n 分流，再 k 轮「比较·弹出·补员」](images/wc318_q3_algorithm_flow.svg)

1. **分流**：若 $2 \cdot \text{candidates} \ge n$（含恰好相切——中间区为空），走快路径：全体 $(\text{costs}[i], i)$ 一次 `heapify`（$O(n)$），连弹 $k$ 次堆顶累加，返回。
2. **双堆初始化**（$2c < n$，两端不相交）：`front` ← 下标 $[0, c)$，`back` ← 下标 $[n-c, n)$，指针 `left = c`、`right = n−c−1`（中间区两端）。
3. **重复 $k$ 轮**：
   - ① **判空堆**：`front` 空 → 取 `back`；`back` 空 → 取 `front`；
   - ② **比较堆顶**（元组字典序）：`front.top() ≤ back.top()` → 取 `front`，否则取 `back`；
   - ③ **弹出**，`ans += cost`；
   - ④ **同侧补员**：若 `left ≤ right`，取 `front` 则压 $(\text{costs}[left], left{+}{+})$，取 `back` 则压 $(\text{costs}[right], right{-}{-})$。
4. 返回 `ans`。

提交前 3 秒自检：`ans` 用 `long long` ✓、堆里存的是 $(\text{cost}, \text{idx})$ 而非裸 `cost` ✓、补员方向同侧 ✓。

### 3.4 示例演算

![示例演算：三轮雇佣，跨堆并列靠下标裁决，总代价 11](images/wc318_q3_example_walkthrough.svg)

以示例 1 `costs = [17,12,10,2,7,2,11,20,8]`，$k=3$，$c=4$ 为例（$2c = 8 < 9$，双堆路径，中间区仅 idx4）：

| 轮次 | front 堆顶 | back 堆顶 | 雇佣 | ans | 补员 | left/right |
|------|-----------|-----------|------|-----|------|-----------|
| 初始 | — | — | — | 0 | front←idx0-3，back←idx5-8 | left=4, right=4 |
| 1 | (2,3) | (2,5) | idx3，代价 2（**并列→元组取小**） | 2 | front←idx4(7) | left=5, right=4 |
| 2 | (7,4) | (2,5) | idx5，代价 2 | 4 | 不补（left＞right） | — |
| 3 | (7,4) | (8,8) | idx4，代价 7 | **11** | 不补 | — |

- 第 1 轮的跨堆并列（两端堆顶代价均为 2）由元组比较 $(2,3) \le (2,5)$ 直接裁决，与题面「下标更小者」一致——idx4 要到第 3 轮才被雇，前提正是第 1 轮把中间区的它吞入了前窗；
- 第 2 轮起中间区耗尽（`left > right`），两堆只弹不补进入**排空阶段**，哪端堆顶小弹哪端。

快路径以示例 2 演算（$n=4$，$c=3$，$2c = 6 \ge 4$）：单堆元素依次为 $(1,0), (1,3), (2,1), (4,2)$，连弹 3 次 → $1 + 1 + 2 = 4$，与题面逐轮解释（雇 idx0 → idx3 → idx1）完全一致 ✓。

## 4. 算法细节

1. **分流判据 $2c \ge n$ 含相等**：恰好相切（$2c = n$）时中间区为空、前窗右端紧贴后窗左端，同样属退化，归入快路径可省去初始化守卫。
2. **堆存 $(\text{cost}, \text{idx})$ 元组**：Python `heapq` 元组按字典序比较；C++ 用 `greater<pair<int,int>>`。堆内并列、跨堆并列的裁决全部交给比较函数，**不手写下标分支**——这是本题最值得沉淀的写法。若只存裸 `cost`，同堆内并列时会「弹错人」，堆内容与 `left/right` 指针语义脱节，状态机从此错乱。
3. **建堆用 `heapify` / 整容器构造**：快路径 $n$ 可达 $10^5$，$O(n)$ 建堆比逐个 `push` 的 $O(n \log n)$ 快一个因子；C++ 可先填好 `vector` 再以 `(greater{}, move(vec))` 构造 `priority_queue`。
4. **同侧补员**：弹 `front` 补中间区**左端** `left`（向右吞），弹 `back` 补**右端** `right`（向左吞）。方向交叉会把大下标混进 `front`，破坏「front 下标恒小」的不变式，并列裁决随之失效。
5. **守卫 `left ≤ right` 的三重身份**：既是「中间区还有人可补」的标志，也是「排空阶段不补」的开关，还在结构上排除同一工人进两堆的可能（每个下标至多被压一次）。
6. **空间差异**：快路径堆里装全体 $n$ 人，空间 $O(n)$；双堆路径两堆合计至多 $2c$，空间 $O(c)$。本题 $10^5$ 量级两者都无压力。

## 5. 正确性证明

**引理 0（下标等价）**：设剩余工人按原下标排列成序列 $R$，则任意两名剩余工人的**原下标**大小关系与其在 $R$ 中**位置**的大小关系一致。

**证明**：雇佣只删除元素、不重排，$R$ 是原序列的子序列，保持原有相对顺序。∎

由引理 0，题面「并列取下标小」（无论按原下标还是剩余位置理解）与「按 $(\text{cost}, \text{原下标})$ 字典序取最小」等价，下文统一用后者。

**引理 1（候选集不变式）**：双堆路径中，每轮开始时 (a) `front` 堆内任一下标小于 `back` 堆内任一下标；(b) 两堆元素之并恰为本轮候选集（剩余 $m$ 人的前 $\min(c,m)$ 名 ∪ 后 $\min(c,m)$ 名）。

**证明**：对轮数归纳。初始时 $m = n > 2c$，`front` $= \{0,\dots,c-1\}$ 恰为前 $c$ 名、`back` $= \{n-c,\dots,n-1\}$ 恰为后 $c$ 名，两者不相交且 $c-1 < n-c$，(a)(b) 成立。

归纳步分两个阶段。**相向补员阶段**（本轮弹出时刻 `left ≤ right`）：由归纳假设 `front` 为剩余前 $c$ 名、`back` 为后 $c$ 名且不相交。设弹出 $x$ 后从同侧补入中间区端点元素——若弹 `front` 的 $x$，旧前窗剩 $c-1$ 人仍居最前，新的第 $c$ 名恰是中间区最靠前者，即 $(\text{costs}[left], left)$，补员后 `front` 仍是新剩余的前 $c$ 名（弹 `back` 对称）。下标关系 (a)：`back` 内下标恒大于当前 `right`，而新入 `front` 的下标 $= left \le right$，其余 `front` 元素更小；(b) 此时 $m > 2c$（至少 `left` 未入堆），候选集 $=$ 前 $c$ ∪ 后 $c$ $=$ 两堆之并。**排空阶段**（弹出时刻 `left > right`）：`left` 只增、`right` 只减，故此后永不补员。首次进入该阶段时全部 $n$ 人已各入堆一次（压入总数 $2c + \text{补员数} = 2c + (n - 2c) = n$），两堆之并 $=$ 全体剩余 $= m$ 人；且补员数 $\le$ 弹出数 $t$ 给出 $m = n - t \le 2c$，此后 $m$ 单调递减，$\min(c,m) + \min(c,m) \ge m$ 保证候选集覆盖全体剩余，(b) 成立；(a) 由两堆只弹不补、阶段起点已成立而维持。∎

**引理 2（并列裁决）**：每轮算法弹出的是候选集中 $(\text{cost}, \text{idx})$ 字典序最小者。

**证明**：小顶堆顶是堆内字典序最小者，故 `front` 堆顶是前窗内字典序最小、`back` 堆顶是后窗内字典序最小。候选集 $=$ 两堆之并（引理 1），全局字典序最小者必为两堆顶之一，恰是算法比较后弹出者。∎

**引理 3（退化等价）**：若初始 $2c \ge n$，则每轮候选集都是全体剩余工人，且按规则逐轮雇佣的人 $=$ 全体 $(\text{cost}, \text{idx})$ 按字典序排序后的前 $k$ 个。

**证明**：任意轮 $m \le n \le 2c$，前 $\min(c,m)$ ∪ 后 $\min(c,m)$ 覆盖全体剩余，规则退化为「全体剩余中取字典序最小」。对轮归纳：第 $r$ 轮开始时剩余集合 $=$ 全体 $-$ $\{$前 $r-1$ 小$\}$，其字典序最小者即全体第 $r$ 小。故 $k$ 轮的雇佣序列 $=$ 静态堆连弹 $k$ 次的序列。∎

**定理**：算法返回按题目规则恰好雇佣 $k$ 人的总代价。

**证明**：快路径由引理 0、3 直接得出。双堆路径对轮归纳：由引理 1、2，每轮弹出者恰为规则指定的雇员，且轮末状态满足引理 1 的不变式；$k$ 轮后 `ans` 为总代价。∎

## 6. 复杂度分析

- **时间复杂度**：快路径 $O(n + k \log n)$——`heapify` $O(n)$ 加 $k$ 次弹出；双堆路径 $O((n + k) \log c)$——初始化 $O(c)$，$k$ 轮每轮一弹、至多一压各 $O(\log c)$，补员总数不超过 $n - 2c$。$n, k \le 10^5$ 下堆操作约 $2 \times 10^5 \times 17 \approx 3.4 \times 10^6$ 次，轻松通过。
- **空间复杂度**：快路径 $O(n)$（全体入堆）；双堆路径 $O(c)$——两堆合计至多 $2c$ 个元素（弹一补一、排空后单调递减）。

本题 $n \le 10^5$ 远未触及堆的性能边界；赛场上真正的杀手是 §8 的溢出与初始化重叠，而非复杂度。

## 7. 参考代码

### C++（分流 + 双堆相向补员）

```cpp
class Solution {
  public:
    long long totalCost(vector<int>& costs, int k, int candidates) {
        int n = costs.size();
        using pii = pair<int, int>;                       // (代价, 下标)
        long long ans = 0;

        if (candidates * 2 >= n) {                        // 快路径：窗口交叠/相切
            vector<pii> all;                              // 候选集恒为全体剩余
            for (int i = 0; i < n; ++i) all.emplace_back(costs[i], i);
            priority_queue<pii, vector<pii>, greater<pii>> heap(greater<pii>{}, move(all));
            while (k--) {
                ans += heap.top().first;
                heap.pop();
            }
            return ans;
        }

        priority_queue<pii, vector<pii>, greater<pii>> front, back;  // 小顶堆
        for (int i = 0; i < candidates; ++i) front.emplace(costs[i], i);
        for (int i = n - candidates; i < n; ++i) back.emplace(costs[i], i);
        int left = candidates, right = n - candidates - 1; // 中间区两端

        while (k--) {
            bool useFront;
            if (front.empty()) useFront = false;           // 排空阶段：一端先耗尽
            else if (back.empty()) useFront = true;
            else useFront = front.top() <= back.top();     // 并列 → 下标小者在 front

            auto& heap = useFront ? front : back;
            ans += heap.top().first;
            heap.pop();
            if (left <= right) {                           // 同侧补员
                if (useFront) front.emplace(costs[left], left++);
                else back.emplace(costs[right], right--);
            }
        }
        return ans;
    }
};
```

### Python（分流 + 双堆相向补员）

```python
class Solution:
    def totalCost(self, costs: List[int], k: int, candidates: int) -> int:
        n = len(costs)
        if candidates * 2 >= n:                       # 快路径：窗口交叠/相切
            heap = [(c, i) for i, c in enumerate(costs)]
            heapq.heapify(heap)                       # O(n) 建堆
            return sum(heapq.heappop(heap)[0] for _ in range(k))

        front = [(c, i) for i, c in enumerate(costs[:candidates])]
        back = [(c, i) for i, c in enumerate(costs[n - candidates:], n - candidates)]
        heapq.heapify(front)
        heapq.heapify(back)
        left, right = candidates, n - candidates - 1  # 中间区两端

        ans = 0
        for _ in range(k):
            if not front:                             # 排空阶段：一端先耗尽
                use_front = False
            elif not back:
                use_front = True
            else:
                use_front = front[0] <= back[0]       # 并列 → 下标小者在 front
            if use_front:
                ans += heapq.heappop(front)[0]
                if left <= right:                     # 同侧补员
                    heapq.heappush(front, (costs[left], left))
                    left += 1
            else:
                ans += heapq.heappop(back)[0]
                if left <= right:
                    heapq.heappush(back, (costs[right], right))
                    right -= 1
        return ans
```

两版逻辑一致：分流判据 `2*candidates >= n`，堆内一律存 $(\text{cost}, \text{idx})$ 元组，补员方向同侧。实现已对拍验证：官方示例（$11$ / $4$）、题面说明例（$[3,2,7,7,1,2]$，$c=2$ → $3$）、$k = n$ 时答案恒等于 $\sum \text{costs}$ 的对拍断言、$2c = n$ 相切、以及 C++/Python 各 3000 组随机数据与逐轮模拟暴力全部一致；溢出压力用例（$10^5$ 个 $10^5$、$k = n$）正确返回 $10^{10}$。

## 8. 边界情况与易错点

1. **`ans` 必须 64 位**：总代价最坏 $10^5 \times 10^5 = 10^{10}$，超 `int` 上界 $\approx 2.1 \times 10^9$。C++ 用 `long long`；Python 无此问题。本题最典型的 WA。
2. **初始化重叠**：$2c \ge n$ 时若仍机械双堆且无 `left ≤ right` 守卫，同一工人会被压进两个堆、被雇佣两次，答案错且极难肉眼定位。分流快路径从结构上消灭这一类错误。
3. **堆里只存裸 `cost`**：同堆内并列时弹错人，堆内容与 `left/right` 指针脱节，后续全错（见 §4 第 2 点）。并列裁决必须交给 $(\text{cost}, \text{idx})$ 元组。
4. **交叉补员**：弹 `front` 却补 `right`（或反之），破坏「front 下标恒小」不变式，跨堆并列裁决失效。
5. **排空阶段一端先耗尽**：如 `front` 全是大代价、`back` 全是小代价时 `back` 先空——主循环必须保留「先判空、再比堆顶」的三态分支（或以 $(\infty, \infty)$ 哨兵统一比较）。
6. **$2c = n$ 恰好相切**：中间区为空，属快路径（判据用 $\ge$ 而非 $>$）。
7. **$k = n$**：无论规则细节，全体工人最终都被雇佣，答案恒等于 $\sum \text{costs}$——可作快速对拍的 sanity check。
8. **$candidates = 1$**：每轮只比较剩余序列的队头与队尾，双堆各一元素，代码无需特判。
