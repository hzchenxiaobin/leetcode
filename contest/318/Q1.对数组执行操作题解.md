# LeetCode 对数组执行操作 题解

## 1. 题目概述

- **标题 / 题号**：对数组执行操作（#2460，easy）
- **链接**：https://leetcode.cn/problems/apply-operations-to-an-array/
- **来源**：LeetCode 第 318 场周赛 Q1
- **难度**：简单
- **标签**：数组、双指针、模拟

**题意**：给定下标从 0 开始、长度为 $n$ 的非负整数数组 `nums`，需**依次有序**执行 $n-1$ 步操作（第 $i$ 步，$i$ 从 0 计数）：若 `nums[i] == nums[i+1]`，则 `nums[i]` 变为原来的 $2$ 倍、`nums[i+1]` 变为 $0$；否则跳过本步。全部操作执行完后，再将所有 $0$ 移动到数组**末尾**（非零元素保持相对顺序），返回结果数组。

**约束**：

- $2 \le n \le 2000$
- $0 \le \text{nums}[i] \le 1000$，翻倍后至多 $2000$，`int` 无溢出风险

> ⚠️ 「依次有序执行，而不是一次性全部执行」是题面刻意强调的语义：第 $i$ 步置零 `nums[i+1]` 后，第 $i+1$ 步读到的正是修改后的值。好消息是（见 §3.2）这一依赖在「合并后置零」的语义下天然无害，一趟顺序扫描即可忠实模拟，无需任何特殊处理。

> 💡 本题在本仓库另有[每日题解 2460](../../solution/2401-2500/2460_对数组执行操作.md)：侧重面试视角的双指针模板讲解与单趟融合写法的不变量论证。本篇按周赛复盘视角展开，侧重**签到题的最短提交路径**、**「依次执行」语义的两条规则（零吸收、无连锁）**与**两阶段解耦的证明**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,1,1,0]
输出：[1,4,2,0,0,0]
解释：
  i=0: 1≠2，跳过
  i=1: 2==2 → nums[1]=4, nums[2]=0   → [1,4,0,1,1,0]
  i=2: 0≠1，跳过
  i=3: 1==1 → nums[3]=2, nums[4]=0   → [1,4,0,2,0,0]
  i=4: 0==0 → 0×2=0，无变化
  搬零后 → [1,4,2,0,0,0]
```

**示例 2**

```text
输入：nums = [0,1]
输出：[1,0]
解释：无法执行任何合并操作，只需将 0 移动到末尾。
```

**示例 3**（自构造，检验「依次执行」语义）

```text
输入：nums = [2,2,2,2]
输出：[4,4,0,0]
解释：
  i=0: 2==2 → [4,0,2,2]
  i=1: 0≠2，跳过
  i=2: 2==2 → [4,0,4,0]
  两个 4 相等，但不会再合并（第 0 步早已执行完，合并不连锁）
  搬零后 → [4,4,0,0]
```

## 3. 解题思路

### 3.1 暴力思路

照题面直译：一趟 `for` 循环模拟 $n-1$ 步操作——这本来就是正确且 $O(n)$ 的。可能写得「重」的是**搬零**阶段：每遇一个 $0$ 就逐位交换冒泡到末尾是 $O(n^2)$，$n \le 2000$ 时约 $4\times 10^6$ 次操作，比赛时也能过；或者开新数组收集非零再拷回，$O(n)$ 但要 $O(n)$ 额外空间。

> 💡 签到题视角：本题唯一值得多想一步的就是把搬零换成 [283. 移动零](https://leetcode.cn/problems/move-zeroes/) 的**读写双指针**模板——判据 `nums[fast] != 0`，非零前置、末尾补零，$O(n)$ 时间、$O(1)$ 空间。既是最快写法，也是必须沉淀的套路。

### 3.2 核心观察：两阶段解耦——「零吸收」与「无连锁」

![核心观察：零吸收与无连锁两条规则，支撑合并与搬零两阶段解耦](images/wc318_q1_sequential_rules.svg)

题面强调「依次有序执行」，容易让人担心第 $i$ 步置零 `nums[i+1]` 会对后续步骤产生复杂影响。两条语义规则说明这种担心是多余的：

**规则一（零吸收）**：与 $0$ 相关的比较步全是 no-op——若 `nums[i] = 0`：`nums[i+1] ≠ 0` 时条件不满足直接跳过；`nums[i+1] = 0` 时「翻倍」得 $0\times 2 = 0$，数组仍不变。所以**被置零的位置对后续步骤完全「透明」**——顺序扫到它时读到 $0$ 也无需任何特判，一趟顺序扫描就是「依次执行」的忠实模拟。

**规则二（无连锁）**：第 $i$ 步产生的翻倍值 $2v$ 落在位置 $i$，而位置 $i+1$ 已被置 $0$；任何后续步骤只读取更靠右的位置，故 $2v$ **不再参与任何后续比较**。对照示例 3 的 $[2,2,2,2]$：得到 $[4,0,4,0]$ 后两个 $4$ 不会像 2048 那样继续合并。

> 💡 **关键转化**：本题 = 「相邻相等合并」模拟 + 「移动零」读写双指针两个**独立**子任务的串联。阶段①一趟顺序扫描（零吸收保证读到 $0$ 无需特判），阶段②直接复用 283 模板收尾。两阶段各 $O(n)$，合起来 $O(n)$ 时间、$O(1)$ 空间，原地保序。

### 3.3 算法流程

![算法流程：阶段①合并相邻相等，阶段②读写双指针搬零，尾部补零后返回](images/wc318_q1_algorithm_flow.svg)

1. **阶段①（合并）**：`i` 从 $0$ 到 $n-2$，若 `nums[i] == nums[i+1]`，则 `nums[i] *= 2; nums[i+1] = 0`；
2. **阶段②（搬零）**：`slow = 0`；`fast` 从 $0$ 到 $n-1$，若 `nums[fast] != 0`，则 `nums[slow++] = nums[fast]`；
3. **收尾**：把 $[\text{slow},\ n)$ 全部置 $0$，返回 `nums`。

提交前 3 秒自检：顺序执行勿并行 ✓、覆盖写后补零 ✓、翻倍 $\le 2000$ 无溢出 ✓。

### 3.4 示例演算

![示例演算：2,2,2,2 逐步执行，两个 4 不再合并，搬零后得 4,4,0,0](images/wc318_q1_example_walkthrough.svg)

示例 1 的完整走查：

| 步骤 | 比较对 | 动作 | 数组状态 |
|------|--------|------|----------|
| i=0 | 1, 2 | 不等，跳过 | `[1,2,2,1,1,0]` |
| i=1 | 2, 2 | 相等 → 4, 0 | `[1,4,0,1,1,0]` |
| i=2 | 0, 1 | 不等，跳过（零吸收） | `[1,4,0,1,1,0]` |
| i=3 | 1, 1 | 相等 → 2, 0 | `[1,4,0,2,0,0]` |
| i=4 | 0, 0 | 相等 → 无变化 | `[1,4,0,2,0,0]` |
| 搬零 | — | 非零 1, 4, 2 前置，末尾补零 | **`[1,4,2,0,0,0]`** ✓ |

自构造示例 3 的走查（验证「无连锁」）：$[2,2,2,2] \xrightarrow{i=0} [4,0,2,2] \xrightarrow{i=1\ \text{跳过}} [4,0,2,2] \xrightarrow{i=2} [4,0,4,0] \xrightarrow{\text{搬零}} [4,4,0,0]$。

## 4. 算法细节

1. **合并循环条件**写 `i + 1 < n`（或 `i < n - 1`），天然覆盖 $i = n-2$ 的最后一步，无边界特判。
2. **判据直接读当前值**：即使 `nums[i]` 或 `nums[i+1]` 被前面步骤置零，照常比较即可（零吸收），不要画蛇添足地跳过零位。
3. **覆盖式搬零必须尾部补零**：`nums[slow++] = nums[fast]` 只搬非零值，$[\text{slow},\ n)$ 的旧值残留（如示例 1 中位置 3 的旧值 $2$ 被搬走后原位仍是 $2$）。若改用 `swap` 写法零被换到后段、可免补零，但每次交换 3 次赋值，常数更大。
4. **值域安全**：$\text{nums}[i] \le 1000$，一次翻倍至多 $2000$，且无连锁保证不会再翻第二次，`int` / Python 均安全。
5. **原地返回**：题目不禁止修改输入，直接在 `nums` 上改完返回最快，无需新数组。
6. **进阶**：两阶段可融合为单趟（写指针 `slow` 同时承担合并落位与搬零，靠 `slow ≤ i` 的不变量保证不覆盖未读数据），写法见[每日题解 2460](../../solution/2401-2500/2460_对数组执行操作.md) §5——比赛时两阶段写法更稳更快，不易写错。

## 5. 正确性证明

**引理 1（零吸收）**：顺序模拟中，若第 $i$ 步执行前 `nums[i] = 0`，则该步不改变数组。

**证明**：若 `nums[i+1] ≠ 0`，则 `nums[i] ≠ nums[i+1]`，按定义跳过；若 `nums[i+1] = 0`，操作为 `nums[i] ← 0×2 = 0`、`nums[i+1] ← 0`，数组不变。∎

**引理 2（无连锁）**：第 $i$ 步写入的翻倍值 $2v$（$v>0$）不再参与任何后续步骤的比较。

**证明**：第 $i$ 步后位置 $i$ 持有 $2v$，位置 $i+1$ 持有 $0$。位置 $i$ 只会作为步骤 $j \le i$ 的读位（$j=i$ 的 `nums[j]` 或 $j=i-1$ 的 `nums[j+1]`），而这些步骤均已执行完毕；任何未执行步骤 $j > i$ 只读取位置 $j,\ j+1 \ge i+1$，故 $2v$ 不出现在其比较对中。$v=0$ 时 $2v=0$，由引理 1 吸收。∎

**引理 3（搬零 = 稳定过滤）**：「将所有 0 移动到末尾」当且仅当结果数组前段按原相对顺序排列全部非零元素、后段全为 $0$。

**证明**：「移动 0」不改变非零元素之间的相对先后（题面示例 $[1,0,2,0,0,1] \to [1,2,1,0,0,0]$ 亦确认保序），且 $0$ 全部集中于尾部；反之，前段保序非零 + 后段全零的数组与原数组仅 $0$ 的位置不同，即由移动 $0$ 得到。∎

**定理**：两阶段算法的输出等于题面定义的执行结果。

**证明**：阶段①与题面的 $n-1$ 步操作在顺序、判据、动作上一一对应，是同一过程的直接实现（其中被置零位对后续步骤的影响由引理 1 保证无害——顺序扫描自然满足「依次执行」），故阶段①结束时的数组即「执行完全部操作后」的数组。阶段②的读写双指针把非零元素按原相对顺序写入前段、再将余下位置置 $0$，由引理 3 恰为「将所有 0 移动到末尾」。两阶段串联即题面要求的全过程。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。阶段① $n-1$ 次比较，阶段② $n$ 次扫描，收尾至多 $n$ 次补零，总操作数 $\le 3n-1$。
- **空间复杂度**：$O(1)$。仅用 `i` / `slow` / `fast` 三个下标变量，原地修改并返回原数组。

$O(n)$ / $O(1)$ 已是理论下界（至少读一遍、写一遍），比赛时的注意力应放在**语义不翻车**（依次执行、补零）上。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> applyOperations(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i + 1 < n; ++i) {
            if (nums[i] == nums[i + 1]) {
                nums[i] *= 2;
                nums[i + 1] = 0;
            }
        }
        int slow = 0;
        for (int fast = 0; fast < n; ++fast) {
            if (nums[fast] != 0) {
                nums[slow++] = nums[fast];
            }
        }
        for (int i = slow; i < n; ++i) nums[i] = 0;
        return nums;
    }
};
```

### Python

```python
class Solution:
    def applyOperations(self, nums: List[int]) -> List[int]:
        n = len(nums)
        for i in range(n - 1):
            if nums[i] == nums[i + 1]:
                nums[i] *= 2
                nums[i + 1] = 0
        slow = 0
        for fast in range(n):
            if nums[fast] != 0:
                nums[slow] = nums[fast]
                slow += 1
        for i in range(slow, n):
            nums[i] = 0
        return nums
```

两版逻辑一致：合并循环条件 `i + 1 < n` 省去边界判断；搬零完全复用 283 的「覆盖 + 末尾补零」写法。实现已对拍验证：官方示例（$[1,2,2,1,1,0] \to [1,4,2,0,0,0]$、$[0,1] \to [1,0]$）、自构造边界（$[2,2,2,2] \to [4,4,0,0]$、$[0,0] \to [0,0]$、$[1,1,1] \to [2,1,0]$、$[1000,1000] \to [2000,0]$）以及 20000 组随机数据与逐步模拟暴力全部一致。

## 8. 边界情况与易错点

1. **「依次执行」不能理解成并行/一次性**：$[2,2,2,2]$ 依次执行得 $[4,0,4,0]$、最终 $[4,4,0,0]$；若误以为翻倍值可与后续相等值连锁合并（2048 直觉），会算出 $[8,0,0,0]$ 之类的错误结果。
2. **尾部补零不可省**：覆盖式搬零只写非零值，`[slow, n)` 残留旧值是高频 WA；swap 写法可免补零但常数更大。
3. **不要主动跳过零位**：顺序合并时读到 $0$ 照常比较即可（零吸收），额外写「跳过零」的分支虽然结果也对，但纯属增加出错面。
4. **全零与最小规模**：$[0,0] \to [0,0]$；$n=2$ 只有一歩操作；无合并可做时仅剩搬零（示例 2）。
5. **溢出无忧**：$\text{nums}[i] \le 1000$ 且无连锁，翻倍至多 $2000$，`int` 足够。
6. **冒泡搬零也能过**：$n \le 2000$ 时 $O(n^2)$ 约 $4\times 10^6$ 次操作可 AC，签到时若模板记不牢，先用暴力锁定这题，别耗时间。
