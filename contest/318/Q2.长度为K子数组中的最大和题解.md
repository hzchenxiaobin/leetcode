# LeetCode 长度为 K 子数组中的最大和 题解

## 1. 题目概述

- **标题 / 题号**：长度为 K 子数组中的最大和（#2461，medium）
- **链接**：https://leetcode.cn/problems/maximum-sum-of-distinct-subarrays-with-length-k/
- **来源**：LeetCode 第 318 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：给定整数数组 `nums` 与整数 $k$，在所有**长度恰为 $k$** 且**元素互不相同**的子数组中找出最大和；不存在满足条件的子数组时返回 $0$。

**约束**：

- $1 \le k \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^5$——元素非负让 `ans` 初值 $0$ 天然安全，值域小则允许用值域数组代替哈希表

> 💡 本题在本仓库另有[每日题解 2461](../../solution/2401-2500/2461_长度为K子数组中的最大和.md)：以面试视角讲解「定长滑窗 + 频率表」模板与 `freq.size() == k` 键数判据。本篇按周赛复盘视角展开，主打赛场上最快最稳的**值域数组 + dup 重复计数器**写法，并补全正确性证明与边界清单，两篇互为印证。

## 2. 示例

```text
输入：nums = [1,5,4,2,9,9,9], k = 3
输出：15
解释：长度为 3 的子数组共 5 个：
  [1,5,4] 互异，和 10
  [5,4,2] 互异，和 11
  [4,2,9] 互异，和 15 ← 最大

  [9,9,9] 含重复 9，无效（尽管和为 27）
```

```text
输出：0
解释：唯一的长度 3 子数组 [4,4,4] 含重复元素，无满足条件的子数组。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $n-k+1$ 个起点，每个窗口用哈希集合判重（$O(k)$）再求和（$O(k)$），总时间 $O(nk)$：$k \approx n/2$ 时约 $5 \times 10^9$ 次操作，$n = 10^5$ 下必然超时。而且示例 1 里最大的 `sum`（27）恰恰出现在无效窗口，意味着「按和排序再验证」之类的捷径也不存在——判重必须逐窗口进行。

> 💡 浪费的根源：相邻窗口共享 $k-1$ 个元素，只差**一出一进**，集合与和却每窗口从头重建。「连续子数组 + 定长 $k$」正是定长滑动窗口的招牌信号，增量维护把每窗口 $O(k)$ 压到 $O(1)$。

### 3.2 核心观察：一出一进 + dup 重复计数器

![核心观察：定长窗口一出一进，计数跨越 1↔2 界线时更新 dup](images/wc318_q2_fixed_window_dup.svg)

窗口右移一格只需两个 $O(1)$ 动作，`sum` 与计数表同步增量维护：

- **出窗** $u = \text{nums}[i-k]$：`sum -= u`；`cnt[u]--`；
- **进窗** $v = \text{nums}[i]$：`sum += v`；`cnt[v]++`。

判重则交给一个整数计数器 **dup = 窗口内出现次数 $\ge 2$ 的值个数**：计数从 $1$ 变 $2$ 时 `++dup`，从 $2$ 变 $1$ 时 `--dup`，其余翻转（$0\to1$、$1\to0$、$2\to3$、$3\to2$）都不触碰它。于是「$k$ 个元素互异」这一判据被压缩成一次整数比较 `dup == 0`，与窗口长度无关。

> ⚠️ **门控细节**：无效窗口的 `sum` 必须照常维护。示例 1 中 `[2,9,9]`、`[9,9,9]` 的和 20、27 比答案还大，它们只是「不参与 `ans` 更新」；若一见 `dup > 0` 就 `continue`，把进出维护也一起跳掉，后续所有窗口的 `sum` 全错。

### 3.3 算法流程

![算法流程：单趟扫描，先进窗、再出窗、后判 dup 更新 ans](images/wc318_q2_algorithm_flow.svg)

单趟循环 $i: 0 \to n-1$，把「建首窗口」与「滑动」合并在同一段代码：

1. **① 进窗**：`sum += nums[i]`；`++cnt[nums[i]]`，若变为 $2$ 则 `++dup`；
2. **② 出窗**（$i \ge k$ 时）：`sum -= nums[i-k]`；`cnt[nums[i-k]]--`，若原值为 $2$ 则 `--dup`；
3. **③ 判更新**（$i \ge k-1$ 时）：若 `dup == 0`，`ans = max(ans, sum)`；
4. 循环结束返回 `ans`（初值 $0$ 兜底「无有效窗口」）。

提交前 3 秒自检：`sum` 用 `long long` ✓、`cnt` 开 $10^5+1$ ✓、无效窗口照常维护 `sum` ✓。

### 3.4 示例演算

![示例演算：五个窗口逐步走查，最大 sum 27 出现在无效窗口](images/wc318_q2_example_walkthrough.svg)

以示例 1 `nums = [1,5,4,2,9,9,9]`，$k=3$ 为例（$i$ 为窗口右端点）：

| i | 窗口 | dup | sum | 动作 | ans |
|---|------|-----|-----|------|-----|
| 2 | [1, 5, 4] | 0 | 10 | 互异 → 更新 | 10 |
| 3 | [5, 4, 2] | 0 | 11 | 互异 → 更新 | 11 |
| 4 | [4, 2, 9] | 0 | 15 | 互异 → 更新 | **15** |
| 5 | [2, 9, 9] | 1 | 20 | cnt[9] 变 2 → 跳过 | 15 |
| 6 | [9, 9, 9] | 1 | 27 | cnt[9] 变 3 → 跳过 | 15 |

- $i=5$：右端第二个 $9$ 进窗使 `cnt[9]` 由 $1$ 变 $2$，`dup` 升为 $1$；左端 $2$ 出窗 `cnt[2]` 归 $0$，不触碰 `dup`；
- $i=6$：左端 $2$ 换成 $9$——`cnt[9]` 由 $2$ 到 $3$ 不跨越 $1\leftrightarrow2$ 界线，`dup` 保持 $1$；
- **`sum` 一路照常维护到 27**，但两个高和窗口均被判重门控拦下，最终 `ans = 15` ✓。

## 4. 算法细节

1. **值域数组代替哈希表**：$\text{nums}[i] \le 10^5$ 允许开 `cnt[100001]`，更新是纯数组下标操作，无哈希常数，赛场上比 `unordered_map` 快数倍；哈希版空间 $O(\min(k, U))$ 更通用（值域大时改用），本篇 C++ 用值域数组、Python 用字典对照。
2. **dup 的两个翻转点**：进窗判「变为 2」（`++cnt[v] == 2`），出窗判「原值为 2」（`cnt[u]-- == 2`）。误写成 `>= 2`（$2\to3$ 时重复 `++dup`）或 `== 1`（$0\to1$ 时误报）是高频笔误。
3. **建首窗与滑动合一**：用 `i >= k` 触发出窗、`i >= k-1` 触发判更新，前 $k$ 轮只进不出天然完成首窗口构建，增量逻辑只写一遍。
4. **进出同值的次序无关**：若 `nums[i] == nums[i-k]`，先进后出（或先出后进）使计数先升后降回到原值，`dup` 净变化为 $0$，两种次序都正确。
5. **键数判据对照**：`freq.size() == k` 是等价判据（键数 $=k \iff$ 每键计数为 $1$），但必须及时删除计数归 $0$ 的键，否则 `size()` 虚大；本篇判据不依赖表规模，Python 侧无需 `del` 零计键。两版写法对比见[每日题解 2461](../../solution/2401-2500/2461_长度为K子数组中的最大和.md)。
6. **`ans` 初值 $0$**：$\text{nums}[i] \ge 1$ 保证有效窗口和 $\ge k \ge 1 > 0$，初值 $0$ 同时充当「无解返回 0」的语义，无需额外存在性标记。

## 5. 正确性证明

**引理 1（窗口不变量）**：单趟循环第 $i$ 轮结束时（$i \ge k-1$），计数表 `cnt` 恰为窗口 $\text{nums}[i-k+1..i]$ 的多重集计数，`sum` 恰为该窗口元素之和，`dup` 恰为其中计数 $\ge 2$ 的值个数。

**证明**：对 $i$ 归纳。$i = k-1$ 时前 $k$ 轮只执行进窗，`cnt` 为 $\text{nums}[0..k-1]$ 的多重集计数，`sum` 为其和，`dup` 为其中计数 $\ge2$ 的值数，命题成立。设第 $i-1$ 轮末命题成立于窗口 $[i-k,\ i-1]$。第 $i$ 轮先进 $\text{nums}[i]$、再出 $\text{nums}[i-k]$：多重集上叠加 $\{v\}$、消去 $\{u\}$ 后恰为 $[i-k+1,\ i]$ 的多重集；`sum` 加 $v$ 减 $u$ 同步；`dup` 是计数的确定函数，随 `cnt` 一致变化。∎

**引理 2（判重等价）**：长度为 $k$ 的窗口内元素互异 $\iff$ `dup == 0`。

**证明**：窗口恒含 $k$ 个元素。互异 $\iff$ 每个值的计数恰为 $1$ $\iff$ 不存在计数 $\ge 2$ 的值 $\iff$ `dup` $= 0$。∎

**定理**：算法返回所有互异的长度 $k$ 子数组的和的最大值；不存在时返回 $0$。

**证明**：每个长度 $k$ 子数组唯一对应右端点 $i \in [k-1,\ n-1]$，恰在第 $i$ 轮末被检查一次（引理 1）。检查时由引理 2，`dup == 0` 当且仅当该窗口互异，此时用窗口真实和更新 `ans`。故循环结束时 `ans` 为全部互异窗口和的最大值；若不存在互异窗口，`ans` 保持初值 $0$，即题面要求的返回值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + U)$，其中 $U = 10^5 + 1$ 为值域数组初始化开销。每个元素恰一进一出共 $O(1)$ 次计数与求和更新，整体单趟扫描；哈希版为均摊 $O(n)$。
- **空间复杂度**：$O(U)$——值域计数数组；换用哈希表则为 $O(\min(k, U))$，即窗口内不同值的个数。

$n \le 10^5$ 下远低于时限；本题赛场上的真正杀手是 §8 的溢出与判据笔误，而非复杂度。

## 7. 参考代码

### C++（值域数组 + dup 计数器）

```cpp
class Solution {
public:
    long long maximumSubarraySum(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> cnt(100001, 0);        // 值域计数表
        long long sum = 0, ans = 0;
        int dup = 0;                       // 窗口内计数 >= 2 的值个数
        for (int i = 0; i < n; ++i) {
            int v = nums[i];
            sum += v;
            if (++cnt[v] == 2) ++dup;      // 计数 1 -> 2：v 沦为重复
            if (i >= k) {
                int u = nums[i - k];
                sum -= u;
                if (cnt[u]-- == 2) --dup;  // 计数 2 -> 1：u 恢复唯一
            }
            if (i >= k - 1 && dup == 0) ans = max(ans, sum);
        }
        return ans;
    }
};
```

### Python（字典 + dup 计数器）

```python
class Solution:
    def maximumSubarraySum(self, nums: List[int], k: int) -> int:
        freq = defaultdict(int)
        dup = 0
        s = 0
        ans = 0
        for i, v in enumerate(nums):
            s += v
            freq[v] += 1
            if freq[v] == 2:          # 计数 1 -> 2
                dup += 1
            if i >= k:
                u = nums[i - k]
                s -= u
                freq[u] -= 1
                if freq[u] == 1:      # 计数 2 -> 1
                    dup -= 1
            if i >= k - 1 and dup == 0:
                ans = max(ans, s)
        return ans
```

两版逻辑一致：进窗判「变为 2」、出窗判「变回 1」，其余计数翻转不触碰 `dup`。实现已对拍验证：官方示例（$15$ / $0$）、自构造边界（$[1,2,1,3,4]$ → $8$、$k=1$ 全重复 → $\max$、$n=k$）以及 2 万组随机数据与暴力枚举全部一致；溢出压力用例（$1..10^5$ 全互异、$k=n$）正确返回 $5000050000$。

## 8. 边界情况与易错点

1. **`sum` 必须用 `long long`**：无效窗口上的维护和可达 $10^5 \times 10^5 = 10^{10}$（如全 $10^5$、$k=5\times10^4$），答案本身也可达约 $5 \times 10^9$（$1..10^5$ 全互异取 $k=n$），双双超过 `int` 上界 $\approx 2.1 \times 10^9$。本题周赛最典型的 WA。
2. **无效窗口照常维护 `sum`**：见 §3.2 的 ⚠️；「见 `dup > 0` 就 `continue`」会把进出维护一起跳掉。
3. **dup 翻转判据**：进窗 `++cnt[v] == 2`、出窗 `cnt[u]-- == 2`，误写 `>= 2` 或 `== 1` 都会破坏 `dup`（见 §4 第 2 点）。
4. **值域数组开 $10^5+1$**：$\text{nums}[i]$ 可取 $10^5$，只开 $10^5$ 会下标越界。
5. **$k = 1$**：单元素窗口恒互异，答案即 $\max(\text{nums})$；代码天然覆盖（进出同值时 `dup` 先增后减归零），无需特判。
6. **$n = k$ 与全重复**：前者仅一个窗口；后者恒 `dup > 0`，返回 $0$（示例 2）。
7. **`ans` 初值 $0$ 的前提是元素非负**：若变体允许负数，需改用 $-\infty$ 初值并在末尾单独判「是否存在有效窗口」。
