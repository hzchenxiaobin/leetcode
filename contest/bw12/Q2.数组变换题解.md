# LeetCode 数组变换 题解

## 1. 题目概述

- **标题 / 题号**：数组变换（#1243，easy）
- **链接**：https://leetcode.cn/problems/array-transformation/
- **来源**：LeetCode 第 12 场双周赛 Q2
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定初始数组 `arr`。每天根据**前一天**的数组生成新数组：对每个**内部元素**（首尾元素永不变），

- 若**严格小于**左右两个邻居，则加 1；
- 若**严格大于**左右两个邻居，则减 1；
- 否则（含与邻居相等）不变。

关键规则是**同一天的所有增减同时生效**——都基于昨天的数组计算。若干天后数组不再变化，返回最终的稳定数组。

**约束**：

- $1 \le arr.length \le 100$
- $1 \le arr[i] \le 100$

> ⚠️ 题面虽然保证了「若干天后不变」，但**为什么一定会稳定**并不显然——模拟循环写出来前，先得确认它不会死循环（见 §5 的势能论证）。这是本题比一般签到题多出来的一层思考。

## 2. 示例

**示例 1**

```text
输入：arr = [6,2,3,4]
输出：[6,3,3,4]
解释：第 1 天，2 < 6 且 2 < 3 → 2 变 3；其余元素不满足条件。此后数组稳定。
```

**示例 2**

```text
输入：arr = [1,6,3,4,3,5]
输出：[1,4,4,4,4,5]
解释：第 1 天 [1,6,3,4,3,5] → [1,5,4,3,4,5]；
     第 2 天 [1,5,4,3,4,5] → [1,4,4,4,4,5]，此后稳定。
```

**补充示例（两元素/单元素）**

```text
输入：arr = [5, 5]
输出：[5, 5]
解释：没有内部元素，第一天就稳定。
```

示例 2 值得逐日手推一遍（见 §3.4）——第一天里 $6$ 减 $1$ 与 $3$ 加 $1$ **同时**发生，若串行更新会得到不同的中间数组，这是本题唯一的「陷阱点」。

## 3. 解题思路

### 3.1 暴力思路

「暴力」与「正解」在这题几乎重合：逐日生成新数组直到不再变化。真正要处理的问题只有一个——**循环何时停**。最朴素的处理是「迭代 + 判断数组是否与前一天相同」，配合一个很大的安全上限（比如迭代 $10^5$ 天）防死循环。这能过，但把「会不会永远震荡」这个疑问留在了代码之外。更聪明的一步是先证明**必然收敛**（§5 引理 1：相邻差绝对值之和每天严格下降），那么「不变即停」就是安全的，连安全上限都不需要。

### 3.2 核心观察：同时更新 + 势能下降保证必然稳定

![核心观察：山谷+1、山峰−1，同天同时生效](images/bw12_q2_transform_rule.svg)

两件事撑起整个解法：

1. **同时性**：新数组完全由旧数组计算，$\text{nxt}[i]$ 只读 $\text{arr}[i-1], \text{arr}[i], \text{arr}[i+1]$。实现上先生成副本再逐位判定，切忌边扫边改。
2. **必然收敛**：定义**势能**为相邻差绝对值之和
   $$V = \sum_{i=0}^{n-2} \left| a[i+1] - a[i] \right|,$$
   只要当天有任何元素变动，$V$ 必然**严格减小**。直觉：每个变动的元素都是「严格谷底」（上移）或「严格峰顶」（下移），它向两侧邻居**同时靠近**，与邻居的差距被压缩；而首尾元素从不变动，任何一串「峰谷交替」的变动两端都接在不变元素上，总差额入不敷出。$V$ 是非负整数，至多降 $V_0 \le 99 \times 99 \approx 9801$ 次，循环天数有硬上界，**不会死循环**。

于是「重复直到 unchanged」这个朴素循环有了理论保票，不需要额外的循环检测（如记录历史状态哈希）。

### 3.3 算法流程

![算法流程：副本同时更新，稳定即停](images/bw12_q2_simulation_flow.svg)

```text
1. 循环：
2.     nxt = arr 的副本
3.     changed = false
4.     for i = 1 .. n-2:                    # 内部元素
5.         若 arr[i] < arr[i-1] 且 arr[i] < arr[i+1]:
6.             nxt[i] = arr[i] + 1; changed = true
7.         否则若 arr[i] > arr[i-1] 且 arr[i] > arr[i+1]:
8.             nxt[i] = arr[i] - 1; changed = true
9.     若 not changed: 返回 arr            # 已稳定
10.    arr = nxt                           # 换天
```

每天的计算是纯函数式的：`arr` 全程只读，改动落在 `nxt` 上，日末整体替换。

### 3.4 示例演算

![示例演算：示例 2 的两天变迁](images/bw12_q2_example_walkthrough.svg)

**示例 2（$[1,6,3,4,3,5]$）**，每天的全部判定都基于**昨日快照**：

| 下标 | 第 1 天判定（基于 $[1,6,3,4,3,5]$） | 结果 | 第 2 天判定（基于 $[1,5,4,3,4,5]$） | 结果 |
|------|--------------------------------------|------|--------------------------------------|------|
| 0（首） | 永不变 | 1 | 永不变 | 1 |
| 1 | $6>1$ 且 $6>3$ → 峰，减 1 | **5** | $5>1$ 且 $5>4$ → 峰，减 1 | **4** |
| 2 | $3<6$ 且 $3<4$ → 谷，加 1 | **4** | $4<5$ 但 $4>3$ → 介于两邻之间，不变 | 4 |
| 3 | $4>3$ 且 $4>3$ → 峰，减 1 | **3** | $3<4$ 且 $3<4$ → 谷，加 1 | **4** |
| 4 | $3<4$ 且 $3<5$ → 谷，加 1 | **4** | $4>3$ 但 $4<5$ → 介于两邻之间，不变 | 4 |
| 5（尾） | 永不变 | 5 | 永不变 | 5 |

第 1 天得 $[1,5,4,3,4,5]$，第 2 天得 $[1,4,4,4,4,5]$；第 3 天在 $[1,4,4,4,4,5]$ 上逐位检查——$4>1$ 但 $4=4$（右邻相等）、其余位置或相等或居中——无任何变动，返回 $[1,4,4,4,4,5]$ ✓。

注意第 1 天里下标 1 的 $6$ 减 1、下标 3 的 $4$ 减 1、下标 2 与 4 的两个 $3$ 各加 1，**全部同时**基于昨日数组生效；若串行更新，下标 3 会读到已被改动的邻居而误判。势能轨迹：$V_0 = 5{+}3{+}1{+}1{+}2 = 12$ → $V_1 = 4{+}1{+}1{+}1{+}1 = 8$ → $V_2 = 3{+}0{+}0{+}0{+}1 = 4$，逐日递减，与 §5 引理 1 吻合。

**示例 1（$[6,2,3,4]$）**：仅下标 1 是谷（$2 < 6$ 且 $2 < 3$），第 1 天变 $[6,3,3,4]$；第 2 天下标 1 的 $3$ 与右邻相等、无变动 → 稳定，返回 $[6,3,3,4]$ ✓。

## 4. 算法细节

1. **副本先行**：`nxt = arr[:]` 后只改 `nxt`，日末 `arr = nxt`。任何「直接在 arr 上原地 ±1」的写法都在串行更新，样例 2 的第一天就会算错。
2. **严格比较**：条件是「严格小于/大于**两个**邻居」；与任一邻居相等则不动。别写成 `<=` 或只比一侧。
3. **首尾跳过**：循环范围 $[1, n-2]$（闭区间），$n \le 2$ 时循环体不执行、首日即稳定。
4. **终止条件**：用 `changed` 标记当日是否有变动，无变动即返回。由 §5 引理 1、2，循环天数 $\le V_0 \le 9801$，无需额外上限或历史状态判重。
5. **每天的判定顺序无关**：因为读的全是昨日快照，内部循环从左到右或从右到左结果相同——这也提示该过程可以并行，但 $n \le 100$ 规模下无意义。
6. **返回的是最终态**：返回 `arr` 本身（未变动的那天），注意别把 `nxt` 与 `arr` 搞反导致返回「多算一天」的数组。

## 5. 正确性证明

**引理 1（变动日的势能严格下降）**：设某天有至少一个元素变动，记当天前后势能分别为 $V, V'$，则 $V' \le V - 1$。

**证明**：考察相邻对 $(i, i+1)$ 的贡献 $\left| a[i+1] - a[i] \right|$ 如何变化。按每个元素的变动方向分类（U = 谷底 +1，D = 峰顶 −1，S = 不动）。首先注意三个事实：(a) **同向相邻不可能**：U 要求 $a[i] < a[i+1]$ 与 $a[i+1] < a[i]$ 同时成立，矛盾；D 同理；(b) 内部元素才变动，而**首尾元素永为 S**；(c) 变动元素必成极大连续段（段内方向交替 U/D/U/…），段的两侧接 S 或数组边界——由 (b)，不可能是数组边界，故必接 S。于是逐类核对相邻对的贡献变化：S–S 不变；S–U（谷底加 1，向 S 邻居靠拢）该对差绝对值减 1；S–D 同理减 1；U–S、D–S 减 1；U–D（谷向峰双向靠近，原本差 $\ge 2$）减 2；D–U 减 2。**每一对的贡献都不增**，且每个极大变动段至少有一端接 S，该端相邻对严格减 1。故 $V' \le V - 1$。∎

> ⚠️ 引理 1 的 (c) 处依赖首尾永不变动：若没有这条，一个「全数组交替变动」的环可能两端都贴边界而无 S 邻居。这解释了为什么题面强调「首尾元素从不变」——它不只是规则描述，还是收敛性的支柱。

**引理 2（循环必然终止）**：模拟循环至多执行 $V_0 + 1$ 天，其中 $V_0$ 是初始势能。

**证明**：$V_0 \le (n-1) \cdot \max_i |a[i+1]-a[i]| \le 99 \times 99 < 10^4$。由引理 1，每个「变动日」使 $V$ 至少减 1，而 $V$ 非负整数，故变动日至多 $V_0$ 个；某天无变动即触发返回。∎

**定理**：算法返回的数组满足：它是在变换规则下逐日演化后的稳定态（且演化结果唯一）。

**证明**：规则的每一步都由前一天数组唯一决定（同天各位置的判定互不影响、无随机性），故演化轨迹唯一；由引理 2 轨迹在有限天内到达首个无变动日。该日的数组 $a^\ast$ 满足：每个内部元素既非严格谷底也非严格峰顶，按规则再演化一天结果不变，即稳定态。算法维护的不变量是「arr 始终等于当前天数对应的演化结果」（归纳：副本更新恰好执行一步规则），终止时返回的正是首个稳定态。∎

## 6. 复杂度分析

- **时间**：$O(D \cdot n)$，其中 $D$ 为天数。由引理 2，$D \le V_0 + 1 < 10^4$，$n \le 100$，最坏约 $10^6$ 次比较，实际数据下天数通常远小于上界（差值很快被抹平）。若势能上限按值域 $C$、长度 $n$ 计，更紧的界是 $O(n^2 C \cdot n) = O(n^3 C)$，仍极小。
- **空间**：$O(n)$。只额外保存一份当日副本。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> transformArray(vector<int>& arr) {
        int n = (int)arr.size();
        vector<int> nxt(n);
        while (true) {
            bool changed = false;
            nxt = arr;                                   // 昨日快照的副本
            for (int i = 1; i + 1 < n; ++i) {            // 内部元素
                if (arr[i] < arr[i - 1] && arr[i] < arr[i + 1]) {
                    nxt[i] = arr[i] + 1; changed = true; // 严格谷底
                } else if (arr[i] > arr[i - 1] && arr[i] > arr[i + 1]) {
                    nxt[i] = arr[i] - 1; changed = true; // 严格峰顶
                }
            }
            if (!changed) return arr;                    // 无变动即稳定
            swap(arr, nxt);                              // 换天
        }
    }
};
```

### Python

```python
class Solution:
    def transformArray(self, arr: list[int]) -> list[int]:
        n = len(arr)
        while True:
            nxt = arr[:]                                 # 昨日快照的副本
            changed = False
            for i in range(1, n - 1):                    # 内部元素
                if arr[i] < arr[i - 1] and arr[i] < arr[i + 1]:
                    nxt[i] = arr[i] + 1
                    changed = True
                elif arr[i] > arr[i - 1] and arr[i] > arr[i + 1]:
                    nxt[i] = arr[i] - 1
                    changed = True
            if not changed:
                return arr
            arr = nxt
```

**验证记录**：两份代码均通过官方双示例（[6,3,3,4] 与 [1,4,4,4,4,5]）；与独立重写的逐日参照实现（附带「势能每日严格下降」断言）对拍 **20009 组**随机与特构用例（长度 1–12、值域 1–100，含锯齿波、全相等、单调、单峰等极端形态），0 失配且断言全程成立；另以长度 100 的 200 组随机例验证 C++ 与 Python 一致。

## 8. 边界情况与易错点

1. **同天同时更新**：最大陷阱。在 `arr` 上原地改会让后面的元素读到「今天的中间值」。必须副本快照、日末整体替换。
2. **严格性**：与邻居相等不动。`[1,2,2,1]` 中两个 2 都不满足「严格大于两个邻居」（各自有一个邻居相等），保持不变；误用 `>=` 会把平台边缘误判成峰谷。
3. **首尾永不变**：循环范围 $[1, n-2]$；$n = 1$ 或 $2$ 时首日即稳定，直接返回原数组。
4. **稳定 ≠ 单调**：最终数组长这样——`[1,4,4,4,4,5]` 有平台，不要求整体有序，别按「变成锯齿/递增」的错误预期去写特判。
5. **返回时机**：返回**首个**无变动日的数组；多循环一天再返回会输出相同内容但多做一轮（此处无害，但若返回 `nxt` 恰是重复计算的一天，注意与「返回未变的 arr」保持一致，本文统一返回 `arr`）。
6. **无需防死循环的外挂**：见过给循环加「历史哈希判重」或「天数上限 10000 强制跳出」的写法——由引理 1、2 已证明必然收敛，`changed` 标记足够；外挂只会掩盖真正的串行更新 bug。
