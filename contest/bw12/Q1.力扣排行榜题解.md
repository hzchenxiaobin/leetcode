# LeetCode 力扣排行榜 题解

## 1. 题目概述

- **标题 / 题号**：力扣排行榜（#1244，medium）
- **链接**：https://leetcode.cn/problems/design-a-leaderboard/
- **来源**：LeetCode 第 12 场双周赛 Q1
- **难度**：中等
- **标签**：设计、哈希表、排序

**题意**：设计一个 `Leaderboard` 类，支持三种操作：

- `addScore(playerId, score)`：给该玩家的累计分数**加上** `score`；若玩家不在榜上，则以 `score` 入榜；
- `top(K)`：返回分数最高的 $K$ 个玩家的分数之和；
- `reset(playerId)`：把该玩家分数清零（保证此前已入榜）。

**约束**：

- $1 \le playerId, K \le 10^4$
- 保证 $K \le$ 当前玩家数
- $1 \le score \le 100$
- 函数调用总数至多 $1000$ 次

> 💡 这是一道**数据结构选型**题而非算法题：约束里「至多 1000 次调用」是最大的提示——它把 $O(\text{玩家数})$ 的单次 `top` 直接放进了安全区，简单方案不需要为它堆重型的平衡结构。

## 2. 示例

**示例 1**

```text
输入：
["Leaderboard","addScore","addScore","addScore","addScore","addScore","top","reset","reset","addScore","top"]
[[],[1,73],[2,56],[3,39],[4,51],[5,4],[1],[1],[2],[2,51],[3]]
输出：[null,null,null,null,null,null,73,null,null,null,141]
解释：
leaderboard.addScore(1,73);  // [[1,73]]
leaderboard.addScore(2,56);  // [[1,73],[2,56]]
leaderboard.addScore(3,39);  // [[1,73],[2,56],[3,39]]
leaderboard.addScore(4,51);  // [[1,73],[2,56],[3,39],[4,51]]
leaderboard.addScore(5,4);   // [[1,73],[2,56],[3,39],[4,51],[5,4]]
leaderboard.top(1);          // 73
leaderboard.reset(1);        // [[2,56],[3,39],[4,51],[5,4]]
leaderboard.reset(2);        // [[3,39],[4,51],[5,4]]
leaderboard.addScore(2,51);  // [[2,51],[3,39],[4,51],[5,4]]
leaderboard.top(3);          // 51 + 51 + 39 = 141
```

示例 1 演示了两个语义细节：`addScore` 是**累加**（玩家 2 被清零后重新入榜得分 51）；`top(3)` 取的是当前分数最高的 3 人（两个 51 与一个 39）。

## 3. 解题思路

### 3.1 暴力思路

用线性表存 $(playerId, score)$ 对：`addScore` 需要先线性查重再决定更新或追加，$O(m)$；`top` 排序取前 $K$，$O(m \log m)$；`reset` 线性查找，$O(m)$。调用至多 1000 次、$m \le 1000$，最坏约 $10^6$ 量级，居然也能过。但「按 id 查单条记录」正是**哈希表**的招牌场景，暴力方案里三次线性查找全部可以被 $O(1)$ 定位替换——这不是性能焦虑，是选型常识。

### 3.2 核心观察：id → score 用哈希，top(K) 用「部分选择」

![核心观察：哈希表按 id 定位，top 时一次性取出分数做部分排序](images/bw12_q1_design_model.svg)

三个操作对数据结构的诉求其实是**正交**的：

- `addScore` / `reset` 需要「按 playerId $O(1)$ 读写」——`unordered_map<int,int>` 完美匹配；
- `top(K)` 需要「按分数取前 $K$ 大的和」——把哈希表的 value 全部倒进临时数组，做一次**部分排序**即可。

部分排序不必全排：C++ 的 `nth_element` 以期望 $O(m)$ 把前 $K$ 大的分隔到数组头部，比 $O(m \log m)$ 的 `sort` 更省；Python 侧 `sorted(...)[:K]`（或 `heapq.nlargest`）在 $m \le 1000$ 的规模下毫无压力。这样组合出的复杂度画像是：`addScore`/`reset` $O(1)$，`top` $O(m)$（或 $O(m \log m)$），在 1000 次调用的限制下绰绰有余。

> 💡 另一条路线是「哈希 + 平衡树/有序多重集」：额外维护一个按分数组织的 `multiset`，`addScore` 时同步更新（删旧分、插新分），`top` 从大到小迭代 $K$ 次求和，$O(\log m)$ 与 $O(K)$——单次操作更快，但代码量与出错面（两处结构同步）显著增大。在 1000 次调用的题面下，这份优化买不回它的复杂度。这也是设计题的通用心法：**先看操作次数的上限，再决定结构的重量**。

### 3.3 算法流程

![算法流程：三个操作与哈希表的交互](images/bw12_q1_operation_flow.svg)

```text
数据：scores = 哈希表 {playerId -> 累计分}

addScore(pid, s):
1. scores[pid] += s          # 不存在则从 0 起加，天然覆盖"首次入榜"

top(K):
1. vals = scores 的全部 value
2. 部分排序使前 K 个为最大值（nth_element / 排序切片）
3. 返回前 K 个之和

reset(pid):
1. scores[pid] = 0            # 保留键、分数清零
```

`reset` 保留键值为 0 而非删除键：后续 `addScore` 仍从 0 累加，语义与「删了再加」一致；而 0 分玩家在 `top(K)` 中即便被计入也不影响和（题目保证 $K \le$ 玩家数，含 0 分玩家时结论不变）。

### 3.4 示例演算

![示例演算：官方示例的排行榜状态变迁](images/bw12_q1_example_walkthrough.svg)

| 操作 | 哈希表状态（id:score） | 输出 |
|------|------------------------|------|
| addScore(1,73) | {1:73} | null |
| addScore(2,56) | {1:73, 2:56} | null |
| addScore(3,39) | {1:73, 2:56, 3:39} | null |
| addScore(4,51) | {1:73, 2:56, 3:39, 4:51} | null |
| addScore(5,4) | {1:73, 2:56, 3:39, 4:51, 5:4} | null |
| top(1) | 分数 [73,56,39,51,4] → 前 1 大和 | **73** |
| reset(1) | {1:0, 2:56, 3:39, 4:51, 5:4} | null |
| reset(2) | {1:0, 2:0, 3:39, 4:51, 5:4} | null |
| addScore(2,51) | {1:0, 2:51, 3:39, 4:51, 5:4} | null |
| top(3) | 分数 [0,51,39,51,4] → 51+51+39 | **141** ✓ |

注意 `top` 的取法：两个并列的 51（玩家 2 与玩家 4）都被计入，第三大是 39——「前 $K$ 大」按出现计，不按去重值计。

## 4. 算法细节

1. **`addScore` 的累加语义**：`scores[pid] += s` 依赖「不存在时默认为 0」的行为（C++ `map`/`unordered_map` 的 `operator[]` 与 Python `dict` 配 `get(pid, 0)` 或先判存在）。写成「覆盖」语义是常见笔误。
2. **`reset` 置 0 而非删除**：删除键后，若 `top(K)` 的 $K$ 恰等于「含已删除玩家」的计数会越界；置 0 让「玩家数」单调不减，且 0 分不影响 `top` 之和，两种语义在题目约束下等价，但置 0 的实现更皮实。
3. **`top` 的实现选择**：C++ 用 `nth_element(vals.begin(), vals.begin()+K, vals.end(), greater<int>())` 期望 $O(m)$ 完成「前 K 大分隔」，随后求和；Python 用 `sorted(scores.values(), reverse=True)[:K]`，$m \le 10^4$（id 上限）时也仅万级排序。二者都无需手写堆。
4. **溢出与类型**：分数总和上界约「1000 次调用 × 每次 100 分」$= 10^5$，`int` 富余；但若把约束放大（如 $10^5$ 次调用 × $10^4$ 分），`top` 之和应换 `long long`——设计题养成「求和先估上界」的习惯。
5. **并发与一致性**（扩展视角）：本题单线程，无并发语义；真实排行榜要考虑读写锁或 CAS，属系统设计范畴，题解不展开。

## 5. 正确性证明

**引理 1（状态不变量）**：任意操作序列后，`scores[p]` 等于「玩家 $p$ 自创建以来所有 addScore 之和、减去最后一次 reset 时刻之前的累计」（reset 之后重新从 0 累加）。

**证明**：对操作数归纳。初始表为空。`addScore(p, s)` 将 `scores[p]` 增加 $s$：若 $p$ 已在表中即累加；若不在，按「默认 0 起加」得 $s$，与「入榜即 $s$」一致。`reset(p)` 将 `scores[p]` 置 0，此后再发生的 `addScore` 在 0 的基础上累加。归纳成立。∎

**引理 2（top 的正确性）**：`top(K)` 返回当前哈希表中最大的 $K$ 个值之和。

**证明**：`top` 把哈希表全部 value（$m$ 个）取出，经 `nth_element`（比较器取大优先）后，数组前 $K$ 个元素构成原多重集的前 $K$ 大（`nth_element` 的契约：第 $K$ 位归位、左侧不小于它、右侧不大于它，配合降序比较器即前 $K$ 大），求和即所求。排序切片版本同理。∎

**定理**：该实现满足题面三操作的语义。

**证明**：`addScore`、`reset` 的语义由引理 1 直接给出（reset 保证操作对象已在榜，置 0 合法）。`top(K)` 的语义是「分数最高的 $K$ 个玩家分数之和」：由引理 1，哈希表即各玩家当前分数；由引理 2，返回值恰为最大 $K$ 个分数之和。题目保证 $K \le$ 当前玩家数，即 $K \le m$，取前 $K$ 不会越界（即便把 0 分的 reset 玩家计入，和亦不变）。∎

## 6. 复杂度分析

- **时间**：`addScore` 与 `reset` 均 $O(1)$（哈希表单点读写）；`top` 为 $O(m)$（`nth_element` 期望线性，$m$ 为当前玩家数，上界 $10^4$）或 $O(m \log m)$（排序切片版本）。总调用至多 1000 次，最坏总量约 $10^7$，远在时限内。
- **空间**：$O(m)$。哈希表存每个玩家一个条目，`top` 临时数组同阶（用完即弃）。

对照「哈希 + multiset」方案：单次 `top` 从 $O(m)$ 降到 $O(K + \log m)$，代价是 `addScore`/`reset` 升为 $O(\log m)$ 且需要双结构同步维护；在 1000 次调用的约束下两者总耗时同一量级，简单方案胜在低出错率。

## 7. 参考代码

### C++

```cpp
class Leaderboard {
    unordered_map<int, int> scores;          // playerId -> 当前累计分
public:
    Leaderboard() {}

    void addScore(int playerId, int score) {
        scores[playerId] += score;           // 不存在则从 0 起加，天然覆盖首榜
    }

    int top(int K) {
        vector<int> vals;
        vals.reserve(scores.size());
        for (auto& kv : scores) vals.push_back(kv.second);
        int n = (int)vals.size();
        if (K < n)                           // 前 K 大分隔到头部，期望 O(m)
            nth_element(vals.begin(), vals.begin() + K, vals.end(), greater<int>());
        int sum = 0;
        for (int i = 0; i < K && i < n; ++i) sum += vals[i];
        return sum;
    }

    void reset(int playerId) {
        scores[playerId] = 0;                // 保留键、分数清零
    }
};
```

### Python

```python
class Leaderboard:

    def __init__(self):
        self.scores = {}                     # playerId -> 当前累计分

    def addScore(self, playerId: int, score: int) -> None:
        self.scores[playerId] = self.scores.get(playerId, 0) + score

    def top(self, K: int) -> int:
        return sum(sorted(self.scores.values(), reverse=True)[:K])

    def reset(self, playerId: int) -> None:
        self.scores[playerId] = 0
```

**验证记录**：两份代码均通过官方示例（73 与 141）；另以「线性表 + 全排序」的朴素实现为参照，随机生成 3000 组操作序列（含反复 reset/addScore 交叉、并列分数、$K$ 取满玩家数），共 14553 次 `top` 比对，0 失配；同批用例喂给 C++ 与 Python 亦全部一致。

## 8. 边界情况与易错点

1. **`addScore` 是累加不是覆盖**：示例 1 里玩家 2 清零后 `addScore(2,51)` 得 51 而非「覆盖为 51 也恰好一样」——换成 `reset` 后 `addScore(2,30)` 再 `addScore(2,21)`，覆盖语义就会错出 21 vs 51 的差别。
2. **`reset` 后玩家仍在榜**：用「删除键」实现时，若题目后续按「历史玩家数」给 $K$，会取到不足 $K$ 个值；置 0 实现（本文）不受影响。两种理解在本题约束下都合法，置 0 更稳。
3. **并列分数都要计入**：`top(3)` = 51+51+39 而非 51+39+4——「前 $K$ 大」是多重集语义，别在中途去重。
4. **`K = m` 的满取**：`nth_element` 在 `K == n` 时不能调用（越界），代码里用 `if (K < n)` 守卫；排序切片版本天然安全。
5. **构造函数别忘了写**：C++ 的 `Leaderboard()` 与 Python 的 `__init__` 都是判题入口的一部分，漏写导致状态定义在类属性上时会被多实例共享（本题单实例不炸，但是坏习惯）。
6. **`top` 不要顺手排序原表**：哈希表没有顺序语义，把 value 拷出来再排，避免一边遍历一边改表。
