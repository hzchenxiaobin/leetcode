# LeetCode 唯一摩尔斯密码词 题解

## 1. 题目概述

- **标题 / 题号**：唯一摩尔斯密码词（#804，easy）
- **链接**：https://leetcode.cn/problems/unique-morse-code-words/
- **来源**：LeetCode 第 77 场周赛 Q2
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：给定 26 个小写字母到「点划串」的固定码表，对每个单词 `word` 做一次**单词翻译**：按字母顺序把每个字母替换成它的码，再首尾拼接成一个串。要求返回 `words` 中所有单词翻译结果里**不同串的个数**。

完整的 26 字母码表如下（下标 0 对应 `'a'`，下标 25 对应 `'z'`）：

```text
[".-","-...","-.-.","-..",".","..-.","--.","....","..",".---",
 "-.-",".-..","--","-.","---",".--.","--.-",".-.","...","-",
 "..-","...-",".--","-..-","-.--","--.."]
```

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \lvert \text{words}[i] \rvert \le 12$
- `words[i]` 仅由小写英文字母组成

单个单词的翻译串长度落在 $[1, 48]$：最短是 `e`（码长 1）；最长的情形是 12 个字母全部取「四符号码」字母（`b`、`c`、`f`、`h`、`j`、`l`、`p`、`q`、`v`、`x`、`y`、`z` 这 12 个），此时 $12 \times 4 = 48$。

## 2. 示例

**示例 1**

```text
输入：words = ["gin", "zen", "gig", "msg"]
输出：2
解释：各单词翻译如下
  "gin" -> "--." + ".." + "-."    = "--...-."
  "zen" -> "--.." + "." + "-."    = "--...-."
  "gig" -> "--." + ".." + "--."   = "--...--."
  "msg" -> "--" + "..." + "--."   = "--...--."
共有 2 种不同翻译："--...-." 和 "--...--."。
```

**示例 2**

```text
输入：words = ["a"]
输出：1
解释：唯一单词翻译为 ".-"，不同翻译数为 1。
```

**示例 3（补充，非官方）**

```text
输入：words = ["ab", "ab", "ba"]
输出：2
解释："ab" -> ".--..."，"ba" -> "-....-"。
     "ab" 重复出现只贡献 1 个串，与 "ba" 的串不同，故答案为 2；
     若把单词全换成 ["ab","ab","ab"]，答案则为 1。
```

## 3. 解题思路

### 3.1 暴力思路

先把每个单词翻译成串，存进数组 `codes`，然后用**两两比较**统计不同串的个数：

```text
codes = [translate(w) for w in words]
ans = 0
for i in 0 .. n-1:
    if all(codes[i] != codes[j] for j < i):  ans += 1
```

判断「`codes[i]` 之前是否出现过」需要线性扫描前 $i$ 个串，整体

$$T(n, L) = O(n^2 L), \qquad S(n, L) = O(nL)$$

其中 $n$ 为单词数、$L$ 为串长上界（这里 $L \le 48$）。在 $n \le 100$ 的数据范围内，$n^2 L / 2 \approx 2.4 \times 10^5$ 次字符比较其实**能跑过**——但这只是因为数据小，瓶颈在于「判重靠线性扫描」这一结构：一旦 $n$ 换到 $10^5$，就完全不可行。真正需要的是把「是否已经出现过」这件事变成**平均 $O(1)$ 的查询**。

### 3.2 核心观察：字面去重 → 集合大小

![核心观察：逐字母查表拼接，再整串丢进集合](images/wc77_q2_morse_set_concept.svg)

**关键定义**：记 $T(w)$ 为单词 $w$ 的翻译串，即

$$T(w) = \text{morse}[c_0] \,\Vert\, \text{morse}[c_1] \,\Vert\, \cdots \,\Vert\, \text{morse}[c_{m-1}], \qquad c_i = w_i - \text{'a'}$$

其中 $\Vert$ 表示字符串拼接。

**核心观察**：题目要的「不同翻译的个数」就是集合 $\{\,T(w) : w \in \text{words}\,\}$ 的**基数**。集合天生去重：重复插入同一个串，集合大小不变。于是问题从「两两比较」退化成「一遍插入 + 读大小」。

一个必须先说清的反直觉点：**不同的单词可能翻译出同一个串**，所以不能拿原单词去重。

![为什么不同单词会撞码：同一个点划串有两种切分](images/wc77_q2_prefix_ambiguity.svg)

以 `gin` 与 `zen` 为例，两者拼出的都是 `--...-.`，因为 `z` 的码 `--..` 以 `g` 的码 `--.` 为前缀，而 `e` 的码 `.` 恰好补在第 4、5 位之间的歧义上：

$$\underbrace{\texttt{--.}}_{g}\,\underbrace{\texttt{..}}_{i}\,\underbrace{\texttt{-.}}_{n} \;=\; \underbrace{\texttt{--..}}_{z}\,\underbrace{\texttt{.}}_{e}\,\underbrace{\texttt{-.}}_{n}$$

摩斯码是**变长编码且字母之间不留分隔符**，这种前缀重载使翻译不是单射。也正因如此，「统计不同翻译」才是一个有意义的问题；如果加了分隔符，答案会退化成为「不同单词的个数」。

### 3.3 算法流程

![算法流程：外层遍历单词，内层逐字符拼接，最后读集合大小](images/wc77_q2_pipeline_flow.svg)

1. **初始化**：准备码表 `morse[26]`（字符串数组），建空哈希集合 `seen`。
2. **外层遍历**：依次取出 `words` 中的每个单词 `word`。
3. **内层翻译**：`code` 置空，对 `word` 的每个字符 `ch` 执行 `code += morse[ch - 'a']`。
4. **入集合**：`seen.insert(code)`；若该串已存在，插入无副作用。
5. **收尾**：所有单词处理完后返回 `seen.size()`。

这里没有任何「状态转移」或「取舍决策」：每个单词的翻译只依赖码表自身，单词之间**互不影响**，因此可以按任意顺序处理——这是本题比 Q3/Q4 简单得多的根本原因。

### 3.4 示例演算

![示例 1 演算：四个单词逐一翻译，集合大小从 1 涨到 2](images/wc77_q2_walkthrough.svg)

以 `words = ["gin","zen","gig","msg"]` 为例：

| 步骤 | 单词 | 逐字母查表 | 翻译串 | 集合状态 |
|------|------|-----------|--------|----------|
| ① | `gin` | `g=--.` `i=..` `n=-.` | `--...-.` | 新增，$\lvert S \rvert = 1$ |
| ② | `zen` | `z=--..` `e=.` `n=-.` | `--...-.` | 重复，$\lvert S \rvert = 1$ |
| ③ | `gig` | `g=--.` `i=..` `g=--.` | `--...--.` | 新增，$\lvert S \rvert = 2$ |
| ④ | `msg` | `m=--` `s=...` `g=--.` | `--...--.` | 重复，$\lvert S \rvert = 2$ |

遍历结束 $S = \{\texttt{--...-.},\ \texttt{--...--.}\}$，返回 $2$，与示例 1 一致。第 ②、④ 步各撞码一次，但集合大小没有变化——这正是去重的效果。

## 4. 算法细节

1. **码表用字符串数组**：`morse[i]` 与字母 `'a'+i` 一一对应，查询是纯下标访问 $O(1)$，不要用 `map<char,string>` 或 `switch`。
2. **拼接方式**：C++ 用 `string code; code += morse[ch - 'a'];`（单个串最多 48 个字符，均摊 $O(1)$）；Python 用 `"".join(...)` 一次性拼接，避免循环里 `code += ...` 造成 $O(L^2)$ 的重复拷贝。
3. **集合选型**：需要的是「判重 + 计数」，`unordered_set<string>`（C++）/ `set`（Python）即可；C++ 用 `unordered_set` 而非 `set`，因为不需要有序，前者期望 $O(L)$ 插入、后者是 $O(L\log n)$。
4. **减少拷贝**：C++ 里 `seen.insert(std::move(code))` 把临时串直接移入容器，省一次字符串复制；`code` 之后不再使用，移动是安全的。
5. **不要保留 `word → code` 的映射**：题目只要计数，映射关系纯属多余空间；若确实要列出不同翻译串，遍历 `set` 即可。
6. **字符下标**：`ch - 'a'` 的取值范围必须是 $[0,25]$。题面保证全为小写，故无需校验；若输入可能含大写或非字母，应先 `tolower` / 判合法，否则会越界。

## 5. 正确性证明

**引理 1（翻译实现正确）**：对任意单词 $w$，算法内层循环结束时 `code` 恰等于题面定义的 $T(w)$。

**证明**：对 $w$ 的长度 $m$ 归纳。$m = 0$ 时 `code` 为空串，与 $T(w) = \varepsilon$ 一致。设长度 $m-1$ 时成立，则处理最后一个字符 $w_{m-1}$ 时，`code` 已等于前 $m-1$ 个字母的翻译串，再执行 `code += morse[w_{m-1} - 'a']`，得到的正是按顺序拼接全部 $m$ 个字母的码，即 $T(w)$。∎

**引理 2（集合内容正确）**：外层循环结束后恒有

$$\texttt{seen} = \{\,T(w) : w \in \text{words}\,\}.$$

**证明**：分两个方向。

- ($\subseteq$) `seen` 中的每个元素都来自某次 `seen.insert(code)`，而由引理 1，该次插入的 `code` 正是对应单词的 $T(w)$，故 `seen` 的元素都在右端集合中。
- ($\supseteq$) 对任意 $w \in \text{words}$，外层循环必然处理到它，并执行一次 `seen.insert(T(w))`；插入后 $T(w) \in \texttt{seen}$，且后续插入不会删除任何元素，故最终仍在 `seen` 中。∎

**引理 3（集合基数即答案）**：集合 $S = \{T(w) : w \in \text{words}\}$ 的基数等于「不同翻译串的个数」。

**证明**：按集合的定义，$S$ 是由所有翻译串构成的**无重复**汇集，其元素个数 $\lvert S \rvert$ 就是互不相同的翻译串的数目；重复出现的串在集合中只贡献 1 个元素。∎

**定理**：算法返回的值等于 `words` 中不同单词翻译的个数。

**证明**：由引理 2，返回时 `seen` 等于 $\{T(w)\}$；由引理 3，`seen.size()` 即所求。∎

**推论**：$1 \le \text{答案} \le n$；答案等于 $n$ 当且仅当所有 $T(w)$ 两两不同，等于 $1$ 当且仅当所有单词翻译到同一个串。∎

## 6. 复杂度分析

- **时间**：$O(S)$，其中 $S = \sum_{w} \lvert T(w) \rvert \le 48n$ 为所有翻译串的字符总数。每个字符恰好被查表并追加一次（$O(1)$ 摊还）；每个串插入哈希集合需要计算哈希并比较，期望 $O(\lvert T \rvert)$，合计 $O(S)$。最坏情况下（大量哈希冲突）单次插入退化到 $O(S)$，但期望仍是线性的。
- **空间**：$O(S)$。集合最多保存 $n$ 个、总长不超过 $S$ 的串；码表是 26 个定长小串，$O(1)$。按本题上限 $n = 100$、$\lvert T \rvert \le 48$，即 $S \le 4800$ 字节级别。

与 §3.1 的暴力相比：$O(n^2L)$ 与 $O(S)$ 在本题数据下都微不足道，差别只在于后者与 $n$ 线性相关，是可迁移的写法。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_set>
using namespace std;

class Solution {
public:
    int uniqueMorseRepresentations(vector<string>& words) {
        const vector<string> morse = {
            ".-",   "-...", "-.-.", "-..",  ".",    "..-.", "--.",
            "....", "..",   ".---", "-.-",  ".-..", "--",   "-.",
            "---",  ".--.", "--.-", ".-.",  "...",  "-",    "..-",
            "...-", ".--",  "-..-", "-.--", "--.."
        };
        unordered_set<string> seen;
        for (const string& w : words) {
            string code;
            for (char ch : w) {
                code += morse[ch - 'a'];   // 查表并追加，下标由字母偏移得到
            }
            seen.insert(std::move(code));   // 移入集合，重复串自动丢弃
        }
        return (int)seen.size();
    }
};
```

### Python

```python
class Solution:
    def uniqueMorseRepresentations(self, words: List[str]) -> int:
        morse = [
            ".-", "-...", "-.-.", "-..", ".", "..-.", "--.",
            "....", "..", ".---", "-.-", ".-..", "--", "-.",
            "---", ".--.", "--.-", ".-.", "...", "-", "..-",
            "...-", ".--", "-..-", "-.--", "--..",
        ]
        seen = {
            "".join(morse[ord(ch) - ord("a")] for ch in w)
            for w in words
        }
        return len(seen)
```

> 💡 两版逻辑完全一致：查表 → 拼接 → 入集合 → 读大小。Python 用集合推导式把「翻译 + 去重」压成一行；`"".join` 只分配一次结果串，比循环内累加更快。

## 8. 边界情况与易错点

1. **只有一个单词**：$\lvert \text{words} \rvert = 1$，集合大小必为 1，不能因为「没有可比较对象」而返回 0。
2. **单词全部相同**：如 `["ab","ab","ab"]`，答案 1 而不是 3——计数对象是**翻译串**，不是单词出现次数。
3. **不同单词撞码**：`gin` 与 `zen` 同串（示例 1），若改成对原单词去重就会得到 4 而不是 2，这是本题最典型的错误。
4. **最长串**：单词长 12 且每个字母的码都是 4 个符号时翻译串长 48；若用 `char` 数组，长度必须至少 49（多留一个 `'\0'`），否则拼接时越界。用 `std::string` / Python `str` 则无需关心。
5. **字符下标越界**：`ch - 'a'` 只在 `a`–`z` 上合法；若题面放宽到大写，必须先转小写（`tolower`），否则会读到码表之外。
6. **Python 的 `List` 注解**：`def uniqueMorseRepresentations(self, words: List[str]) -> int` 需要 `from typing import List`；LeetCode 环境已预置，但本地跑脚本时要自己导入，或直接用 `list[str]`。
7. **返回值类型**：C++ 中 `seen.size()` 是 `size_t`，返回 `int` 时显式转换，避免某些编译器下的窄化警告。

**延伸思考**：

1. **加分隔符会怎样？** 若在字母码之间插入分隔符（如 `|`），编码就成为唯一可分解的，$T$ 变成单射，答案恒等于**不同单词的个数**，题目随即退化。这也解释了为什么真实摩斯电报必须在字母间留短停顿。
2. **要输出每个翻译对应哪些单词？** 把集合换成 `unordered_map<string, vector<string>>`，键为翻译串、值为原单词列表；时间仍为 $O(S)$，空间变为 $O(S + n)$。
3. **反向问题（解码）**：给定一个点划串，判断它能否由某个单词翻译得到，就变成了在「前缀不唯一」的编码上做切分，需要 DFS / DP 枚举分割点，复杂度和本题完全不是一个量级。
4. **数据放大到 $n = 10^5$、单词长 $10^5$**：$O(S)$ 依然正确，但哈希表要处理大量长串；改用「把所有串排序后数相邻不同项」需要 $O(S \log n)$ 时间、$O(S)$ 空间，可避免哈希最坏情况。
