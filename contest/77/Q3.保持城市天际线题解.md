# LeetCode 保持城市天际线 题解

## 1. 题目概述

- **标题 / 题号**：保持城市天际线（#807，medium）
- **链接**：https://leetcode.cn/problems/max-increase-to-keep-city-skyline/
- **来源**：LeetCode 第 77 场周赛 Q3
- **难度**：中等
- **标签**：贪心, 数组, 矩阵

**题意**：给定 $n \times n$ 矩阵 `grid`，`grid[r][c]` 是第 $r$ 行第 $c$ 列立方体建筑的高度。从东、南、西、北四个方向观察，城市的外部轮廓称为**天际线**。允许把任意多个建筑的高度各自增加任意增量（高度为 $0$ 的也能加），但**不能改变任一方向的天际线**，求可以增加的**最大高度增量总和**。

> 💡 关键转译：从东西方向看，天际线就是**每行的最大值**；从南北方向看，天际线就是**每列的最大值**。所以「不改变天际线」等价于「不改变所有行最大值与所有列最大值」。

**约束**：

- $n = \text{grid.length} = \text{grid}[r]\text{.length}$
- $2 \le n \le 50$
- $0 \le \text{grid}[r][c] \le 100$

## 2. 示例

**示例 1**

```text
输入：grid = [[3,0,8,4],[2,4,5,7],[9,2,6,3],[0,3,1,0]]
输出：35
解释：行最大值 R = [8,7,9,3]，列最大值 C = [9,4,8,7]。
      增高后可为
      gridNew = [[8,4,8,7],
                 [7,4,7,7],
                 [9,4,8,7],
                 [3,3,3,3]]
      行最大值仍为 8/7/9/3，列最大值仍为 9/4/8/7，天际线不变；
      总增量 = 5+4+0+3 + 5+0+2+0 + 0+2+2+4 + 3+0+2+3 = 35。
```

**示例 2**

```text
输入：grid = [[0,0,0],[0,0,0],[0,0,0]]
输出：0
解释：所有行最大值、列最大值都是 0，任何增高都会改变天际线。
```

## 3. 解题思路

### 3.1 暴力思路

最彻底的枚举是「给每个格子选一个新高度」：每格有 $101$ 种选择，共 $101^{n^2}$ 种新矩阵，规模直接爆炸，不可行。

退一步的暴力是**逐格试探**：对每个格子从原高度开始每次 $+1$，一旦某个方向的天际线被抬高就退回。每次检验需要扫一遍该行与该列，复杂度 $O(n^2 \cdot H \cdot n) = O(n^3 H)$，在 $n=50, H=100$ 时约 $1.25 \times 10^7$ 次操作，勉强能过。

但这个做法有两个问题：一是它把「能否加」交给试错，$H$ 一大（比如高度到了 $10^9$）就退化；二是它没有说明**为什么各格子可以独立地顶到最高**——而这正是本题唯一的考点。抓住结构后，只需两趟 $O(n^2)$ 扫描。

### 3.2 核心观察：每格上界 = min(行最大值, 列最大值)

![每格高度上界由行最大值与列最大值共同决定](images/wc77_q3_skyline_bounds_concept.svg)

把两套天际线事先算出来并**冻结**：

$$R[r] = \max_{c} \text{grid}[r][c], \qquad C[c] = \max_{r} \text{grid}[r][c]$$

「天际线不变」的要求等价于：对新矩阵 $G'$，每个 $r$ 都有 $\max_c G'[r][c] = R[r]$，每个 $c$ 都有 $\max_r G'[r][c] = C[c]$。于是对任意格子：

$$G'[r][c] \;\le\; \max_{c'} G'[r][c'] = R[r], \qquad G'[r][c] \;\le\; \max_{r'} G'[r'][c] = C[c]$$

两条约束同时成立，就得到**逐格独立的上界** $\min(R[r], C[c])$。这正是题目的抓手：横向看受行天际线限制，纵向看受列天际线限制，取更紧的那一个。

更关键的是这个上界**可以被同时取到**：令 $G^*[r][c] = \min(R[r], C[c])$，第 $r$ 行最大值所在的那一列 $c^*$ 满足 $C[c^*] \ge \text{grid}[r][c^*] = R[r]$，故 $G^*[r][c^*] = R[r]$，该行最大值恰好保持为 $R[r]$；列方向同理。因此贪心地把**每个格子都顶到上界**既合法、又显然最优。

> 💡 一句话记忆：答案就是 $\sum_{r,c}\bigl(\min(R[r], C[c]) - \text{grid}[r][c]\bigr)$，其中 $R$ 是行最大值、$C$ 是列最大值。

### 3.3 算法流程

![两趟扫描：先冻结天际线，再逐格顶到上界](images/wc77_q3_skyline_flow.svg)

1. **第一趟**：遍历矩阵，同时维护 `rowMax[r]` 与 `colMax[c]`，两者互不影响，可写在一个双循环里。
2. **冻结**：此后 `rowMax` / `colMax` 不得再变，也不要把 `grid` 原地改写（否则后续统计会漂移）。
3. **第二趟**：`ans += min(rowMax[r], colMax[c]) - grid[r][c]`。
4. 返回 `ans`。

伪代码只有四行：

```text
for r, c: R[r] = max(R[r], grid[r][c]); C[c] = max(C[c], grid[r][c])
ans = 0
for r, c: ans += min(R[r], C[c]) - grid[r][c]
return ans
```

### 3.4 示例演算

![示例 1 逐行演算：原值、上界目标与本行增量](images/wc77_q3_skyline_walkthrough.svg)

对 `grid = [[3,0,8,4],[2,4,5,7],[9,2,6,3],[0,3,1,0]]`，先得 $R = [8,7,9,3]$、$C = [9,4,8,7]$，再逐行取 $\min(R[r], C[c])$：

| 行 $r$ | 原值 | $R[r]$ | 目标 $\min(R,C)$ | 本行增量 |
|--------|------|--------|------------------|----------|
| 0 | 3, 0, 8, 4 | 8 | 8, 4, 8, 7 | 5+4+0+3 = 12 |
| 1 | 2, 4, 5, 7 | 7 | 7, 4, 7, 7 | 5+0+2+0 = 7 |
| 2 | 9, 2, 6, 3 | 9 | 9, 4, 8, 7 | 0+2+2+4 = 8 |
| 3 | 0, 3, 1, 0 | 3 | 3, 3, 3, 3 | 3+0+2+3 = 8 |

合计 $12+7+8+8 = 35$，与官方输出一致。反向验算：$\sum G^* = 92$，$\sum \text{grid} = 57$，差值同样是 $35$。

## 4. 算法细节

1. **天际线只统计一次**：`rowMax` / `colMax` 必须来自**原始**矩阵。如果一边改写 `grid` 一边统计，后面的 `max` 会包含已被抬高的格子，天际线被自己越推越高。
2. **取 `min` 而不是 `max`**：行约束与列约束是「与」的关系，任何一侧被突破都非法，所以上界是两个上限中更紧的那个。
3. **增量天然非负**：因为 `grid[r][c] <= rowMax[r]` 且 `grid[r][c] <= colMax[c]`，所以 `min(...) - grid[r][c] >= 0`。代码里无需 `max(0, ...)`，但若复用到「输入不保证方形」的场合可以加一层防御。
4. **统计阶段可以只用一趟**：在同一个双循环里用标量 `rm` 滚动记录当前行最大值、同时更新 `colMax[c]`，就只需要一个长度 $n$ 的数组；本解用两个数组是为了让「两套天际线」在代码里对称可见。
5. **整数范围**：单格增量不超过 $100$，总增量不超过 $n^2 \cdot 100 = 250000$，`int` 完全够用。若把约束放宽到 $n, h \le 10^5$，总和可达 $10^{15}$，必须换 `long long`。
6. **不要用排序或堆**：每个 `max` 都是一次线性扫描，$O(n^2)$ 已是最优——毕竟至少要读一遍 $n^2$ 个输入。
7. **不要条件反射上二分/DP**：上界是「逐格独立、可同时取到」的紧约束，属于无耦合贪心；只有当天际线本身也要优化（见延伸思考）时才需要决策或搜索。

## 5. 正确性证明

**引理 1（上界）**：设 $G'$ 是任意一个不改变天际线的增高方案，则对一切 $r, c$ 有 $G'[r][c] \le \min(R[r], C[c])$。

**证明**：行天际线不变给出 $\max_{c'} G'[r][c'] = R[r]$，而 $G'[r][c]$ 是该行中的一个元素，故 $G'[r][c] \le R[r]$。同理 $\max_{r'} G'[r'][c] = C[c]$ 给出 $G'[r][c] \le C[c]$。两式取更紧者即得 $G'[r][c] \le \min(R[r], C[c])$。∎

**引理 2（上界可达）**：令 $G^*[r][c] = \min(R[r], C[c])$，则 (i) $G^*[r][c] \ge \text{grid}[r][c]$；(ii) $G^*$ 的行最大值恰为 $R[r]$、列最大值恰为 $C[c]$。

**证明**：

(i) 因为 $\text{grid}[r][c] \le R[r]$ 且 $\text{grid}[r][c] \le C[c]$，故 $\text{grid}[r][c] \le \min(R[r], C[c])$。

(ii) 取 $c^*$ 为第 $r$ 行最大值所在的列，即 $\text{grid}[r][c^*] = R[r]$。列最大值 $C[c^*] \ge \text{grid}[r][c^*] = R[r]$，于是 $G^*[r][c^*] = \min(R[r], C[c^*]) = R[r]$，即第 $r$ 行中存在等于 $R[r]$ 的元素；又该行每个元素都不超过 $R[r]$，所以行最大值恰为 $R[r]$。列方向论证完全对称：取 $r^\dagger$ 使 $\text{grid}[r^\dagger][c] = C[c]$，则 $R[r^\dagger] \ge C[c]$，得 $G^*[r^\dagger][c] = C[c]$，故列最大值恰为 $C[c]$。∎

**引理 3（逐项最优）**：对任意合法方案 $G'$，$\sum_{r,c} (G'[r][c] - \text{grid}[r][c]) \le \sum_{r,c} (G^*[r][c] - \text{grid}[r][c])$。

**证明**：由引理 1，每个格子都有 $G'[r][c] - \text{grid}[r][c] \le G^*[r][c] - \text{grid}[r][c]$（被减数相同），逐项求和即得。∎

**定理**：算法输出的总增量是满足天际线约束的最大值。

**证明**：由引理 2，$G^*$ 是一个合法方案，其总增量恰为算法累加的值；由引理 3，任何合法方案的总增量都不超过它，故该值即最大值。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。第一趟同时统计行最大值与列最大值，每格常数次比较；第二趟每格一次 `min`、一次减法、一次加法。共 $2n^2$ 次基本操作，任何合法方案都要读入全部 $n^2$ 个高度，故这是下界。
- **空间**：$O(n)$ 额外空间（`rowMax` 与 `colMax` 两个长度 $n$ 的数组），不计输入矩阵与输出。若把 `rowMax` 改成行内滚动标量，可降到 $O(n)$ 中的一半常数。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxIncreaseKeepingSkyline(vector<vector<int>>& grid) {
        int n = grid.size();
        vector<int> rowMax(n, 0), colMax(n, 0);

        // 第一趟：在原始矩阵上冻结两套天际线
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {
                rowMax[r] = max(rowMax[r], grid[r][c]);
                colMax[c] = max(colMax[c], grid[r][c]);
            }
        }

        // 第二趟：每格顶到上界 min(行最大值, 列最大值)
        int ans = 0;
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {
                ans += min(rowMax[r], colMax[c]) - grid[r][c];
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def maxIncreaseKeepingSkyline(self, grid: List[List[int]]) -> int:
        n = len(grid)
        row_max = [max(row) for row in grid]
        col_max = [max(grid[r][c] for r in range(n)) for c in range(n)]

        ans = 0
        for r in range(n):
            rm = row_max[r]
            for c in range(n):
                ans += min(rm, col_max[c]) - grid[r][c]
        return ans
```

## 8. 边界情况与易错点

1. **全零矩阵**：`rowMax` 与 `colMax` 全为 $0$，每格上界为 $0$，答案为 $0$（示例 2）。若代码里对 `min - grid` 做无符号运算会下溢，用有符号 `int` 即可。
2. **所有建筑同高**：$R$ 与 $C$ 全等于该高度，$\min = \text{grid}$，答案恒为 $0$——不要因为循环跑满就以为算错了。
3. **对角峰值**：如 `[[0,100],[100,0]]`，$R = C = [100,100]$，两个 $0$ 都能抬到 $100$，答案为 $200$。这说明「上界只看 $\min(R,C)$，与自身原值无关」。
4. **别边改边统计**：若在第二趟里直接写 `grid[r][c] = min(...)`，之后再统计列最大值就会把列天际线抬高，答案偏大。
5. **`min` 与 `max` 写反**：用 $\max(R,C)$ 会让至少一个方向的天际线变高，是本题最高频的 WA 原因。
6. **最小规模 $n = 2$**：逻辑无需特判；但把代码复用到 $n = 0$ 的空矩阵时，`max(row)` 会抛异常，需要提前返回。
7. **求和类型**：本题 `int` 足够（上界 $250000$）；若把高度上限放大到 $10^9$，单格增量就能超 $2^{31}$，必须用 64 位整数。
