# LeetCode 写字符串需要的行数 题解

## 1. 题目概述

- **标题 / 题号**：写字符串需要的行数（#806，easy）
- **链接**：https://leetcode.cn/problems/number-of-lines-to-write-string/
- **来源**：LeetCode 第 77 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串

**题意**：`widths[0..25]` 给出 26 个小写字母各自的像素宽度（`widths[0]` 对应 `'a'`）。把字符串 `s` 从第一个字符起按顺序逐行书写，每行总宽度不得超过 100；若写下某个字符会使本行超过 100，就把这个字符整体移到下一行。返回 `[总行数, 最后一行的宽度]`。

**约束**：

- $1 \le |s| \le 1000$
- `s` 只包含小写英文字母
- `widths.length == 26`，$2 \le widths[i] \le 10$

## 2. 示例

**示例 1**

```text
输入：widths = [10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10]
     s = "abcdefghijklmnopqrstuvwxyz"
输出：[3, 60]
解释：abcdefghij  // 100
     klmnopqrst  // 100
     uvwxyz      // 60
```

**示例 2**

```text
输入：widths = [4,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10]
     s = "bbbcccdddaaa"
输出：[2, 4]
解释：bbbcccdddaa 覆盖 9 × 10 + 2 × 4 = 98 单位，最后一个 'a' 换到第二行（宽 4）。
```

**示例 3**（补充，恰好 100 的边界）

```text
输入：widths = [10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10,10]
     s = "aaaaaaaaaa"（10 个 a）
输出：[1, 100]
解释：10 × 10 = 100，恰好等于上限，不算「超过」，全部写在同一行。
```

## 3. 解题思路

### 3.1 暴力思路

- **枚举所有切分方案**：把 `s` 切成若干连续段，共 $2^{n-1}$ 种切法，逐一检查每段宽度是否 $\le 100$ 并取最少行数。$n = 1000$ 时完全不可行，而且**根本没必要**——题面已经把书写过程规定死了（能放就放），切点唯一。
- **朴素模拟**：每试一个字符就把"本行已写的字符"重新求和一次，$O(n^2)$。$n \le 1000$ 时约 $10^6$ 次加法也能过，但纯属浪费：把"本行已用宽度"记成一个**滚动变量**，每个字符只加一次即可 $O(n)$。
- **按 100 一刀切**：宽度不等，切点必须落在字符边界上，"每 100 单位切一刀"会把字符劈开，直接错误。

### 3.2 核心观察：贪心 + 一个滚动变量

![贪心装箱：能放就放，放不下才换行](images/wc77_q1_greedy_packing.svg)

书写过程被题面**唯一确定**：从 `s` 头部开始，只要本行还能容下当前字符就写在本行，否则整块搬到下一行。因此"至少多少行"其实就是"按规则写下来是多少行"，不存在需要权衡的决策，需要的是**精确模拟**。

整个状态只有一个整数：

$$cur = \text{当前行已用宽度}$$

对每个字符（宽度为 $w$）：

- 放得下（$cur + w \le 100$）：$cur \leftarrow cur + w$；
- 放不下（$cur + w > 100$）：行数 $+1$，且 $cur \leftarrow w$。

关键在于换行后的 $cur$ **不是 0**，也不是 $cur + w - 100$：溢出的那部分并不"留在行里"，字形的像素不可拆分，必须整块搬到新行，所以新行从 $w$ 起算。

因为每个 $w \in [2, 10]$ 而每行容量是 100，任何单个字符都放得进一个空行，于是**每行至少前进一个字符**，扫描必然终止，不会出现空行或死循环。

### 3.3 算法流程

![算法流程：单遍扫描 + 一次判定](images/wc77_q1_scan_flow.svg)

```text
lines = 1, cur = 0
for c in s:
    w = widths[c - 'a']
    if cur + w > 100:   lines += 1;  cur = w
    else:               cur += w
return [lines, cur]
```

流程极短：**读字符 → 判一次 → 要么并入本行、要么开新行**，直到 `s` 读完。这正是 Q1 签到题该有的形态——把题面翻译成代码，不需要额外结构。

### 3.4 示例演算

![示例 2 逐字符走查](images/wc77_q1_walkthrough.svg)

对 `s = "bbbcccdddaaa"`（`'a'` 宽 4，其余宽 10），`cur` 的演化是

$$10,\,20,\,30,\,40,\,50,\,60,\,70,\,80,\,90,\,94,\,98,\,\underbrace{102}_{>100}$$

第 12 个字符 `'a'` 使 $98 + 4 = 102 > 100$，触发换行：`lines` 由 1 变 2，`cur` 重置为 4，最终返回 `[2, 4]`。

再对示例 1 心算：26 个字母各宽 10，总量 $260 = 100 + 100 + 60$，前两行各恰好 10 个字符（正好 100，不换行），第三行剩 6 个字符宽 60，故 `[3, 60]`。

## 4. 算法细节

1. **下标映射**：C++ 用 `c - 'a'`，Python 用 `ord(c) - ord('a')`，$O(1)$ 取值，比 26 个分支判断清晰得多。
2. **判定必须是严格大于** `cur + w > 100`。写成 `>=` 会把"恰好 100"的字符错误地挤到下一行——示例 1 每行都正好 100，是最直接的踩坑点。
3. **`lines` 初值为 1**：约束保证 $|s| \ge 1$，第一行一定存在。若从 0 开始计，就必须在循环里额外判断"是否写了第一个字符"，反而更绕。
4. **换行时 `cur = w`**：等价于"清空本行后立刻写入当前字符"。写成 `cur = 0; cur += w` 也对，但只写 `cur = 0` 会丢掉当前字符的宽度。
5. **不要预处理前缀和**：换行会把累加"清零"，`cur` 本身就是"本行的滚动前缀和"，整串前缀和数组在此毫无用武之地。
6. **不会溢出**：$cur \le 100$、$w \le 10$，单次加法最大 110；即使全串宽度累加也只有 $10^4$ 量级，`int` 足够，无需 `long long`。
7. **返回长度为 2 的数组**：C++ 写 `return {lines, cur};`（`vector<int>` 列表初始化），Python 写 `return [lines, cur]`，顺序不能颠倒（先行数，后最后一行宽度）。

## 5. 正确性证明

**引理 1（贪心每行写得最远）**：记算法第 $k$ 行写完后停在下标 $p_k$（即第 $k$ 行为 $s[p_{k-1}..p_k)$，$p_0 = 0$）。则任何把 $s$ 顺序写进各行的合法方案，其第 $k$ 行结束位置 $q_k$ 都满足 $q_k \le p_k$。

**证明**：记 $f(t)$ 为「从下标 $t$ 起、宽度和不超过 100 的前提下最多能写到的下标」，贪心取最长可行前缀，故 $p_k = f(p_{k-1})$。对 $k$ 归纳证明 $q_k \le p_k$。

$k = 1$：任何合法方案的第一行都是 `s` 从下标 0 开始的前缀，且宽度 $\le 100$，故 $q_1 \le f(0) = p_1$。

设 $q_{k-1} \le p_{k-1}$。若 $q_{k-1} = p_{k-1}$，两个方案第 $k$ 行起点相同，方案的那一行是可行前缀，于是 $q_k \le f(p_{k-1}) = p_k$。若 $q_{k-1} < p_{k-1}$：当 $q_k \le p_{k-1}$ 时显然 $q_k \le p_k$；当 $q_k > p_{k-1}$ 时，由所有宽度为正可得

$$\sum_{i=p_{k-1}}^{q_k-1} w_i \le \sum_{i=q_{k-1}}^{q_k-1} w_i \le 100,$$

即从 $p_{k-1}$ 起也能一直写到 $q_k$，故 $q_k \le f(p_{k-1}) = p_k$。∎

**引理 2（状态语义）**：扫描完前 $i$ 个字符后，`lines` 等于按规则写完这 $i$ 个字符所需行数，`cur` 等于最后一行的已用宽度（$i \ge 1$ 时即包含第 $i-1$ 个字符的那一行，$i = 0$ 时取 0）。

**证明**：对 $i$ 归纳。$i = 0$ 时初始 `lines = 1`、`cur = 0`，此时尚无字符、第一行为空，语义成立。设扫完前 $i$ 个字符时成立，处理下标为 $i$ 的字符（宽度 $w$）：若 $cur + w \le 100$，它并入当前行，行数不变、宽度变为 $cur + w$；若 $cur + w > 100$，按规则换行，行数 $+1$、新行宽度恰为 $w$。两种情形都与规则一致，故扫完前 $i+1$ 个字符后语义仍成立。∎

**定理**：算法返回的 `[lines, cur]` 与题面规定的书写过程完全一致，且所用行数最少，`cur` 等于最后一行的宽度。

**证明**：由引理 2，扫描结束后 `lines` 恰是按规则书写所需行数，`cur` 恰是最后一行（含 `s` 末字符的那一行）的宽度，故输出与题面规定的过程一致。至于行数最少：设存在只用 $m$ 行就写完 `s` 的合法方案，且 $m$ 小于算法输出的行数，那么它的第 $m$ 行必然写到串尾，即 $q_m = n$；由引理 1 有 $q_m \le p_m$，于是 $p_m = n$，这与"贪心用了更多行、第 $m$ 行时尚未写完"矛盾。所以不存在行数更少的方案。∎

## 6. 复杂度分析

- **时间**：$O(n)$，$n = |s|$。每个字符做一次数组下标访问、一次加法、一次比较，均为 $O(1)$；没有嵌套循环，也没有对每行重新求和。
- **空间**：$O(1)$ 额外空间。只用了 `lines`、`cur` 两个整数；`widths` 是输入不计入，返回数组长度恒为 2。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <string>
using namespace std;

class Solution {
public:
    vector<int> numberOfLines(vector<int>& widths, string s) {
        int lines = 1, cur = 0;                 // 至少一行
        for (char c : s) {
            int w = widths[c - 'a'];
            if (cur + w > 100) {                // 严格大于才换行
                lines++;
                cur = w;                        // 字符整块搬到新行
            } else {
                cur += w;                       // 并入当前行
            }
        }
        return {lines, cur};
    }
};
```

### Python

```python
from typing import List

class Solution:
    def numberOfLines(self, widths: List[int], s: str) -> List[int]:
        lines, cur = 1, 0
        for ch in s:
            w = widths[ord(ch) - ord('a')]
            if cur + w > 100:        # 恰好 100 不换行
                lines += 1
                cur = w
            else:
                cur += w
        return [lines, cur]
```

## 8. 边界情况与易错点

1. **恰好 100**：`widths` 全 10 且 `s` 长 10 时答案是 `[1, 100]`；把判定写成 `>=` 会得到 `[2, 10]`，这是本题最高频的错误。
2. **单个字符**：`s = "a"`、`widths[0] = 4` → `[1, 4]`。此时 `lines` 必须从 1 起算，`cur` 最终就是该字符的宽度。
3. **最后一字符正好溢出**：示例 2 的最后一个 `'a'` 就是这种情况，新行只有它自己，最后一行宽度等于 $w$，不要误算成 $cur + w - 100 = 2$。
4. **满宽度长串**：`s` 为 1000 个宽 10 的字符 → `[100, 100]`；1000 个宽 2 的字符 → `[20, 100]`。行数上界约 $n/10$，不必担心答案规模。
5. **`lines` 初值为 0**：若初值取 0 又忘记在循环里 `lines++`，会返回 `[0, ...]`，与"非空串至少一行"矛盾。
6. **换行后 `cur` 写错**：`cur = 0` 会漏掉当前字符，导致后续整体偏小、行数偏少；`cur + w - 100` 则把字符当成了可拆分的长条。
7. **非小写字母的防御**：题面保证只含小写字母，但若用在其他场景，`c - 'a'` 可能越界，可加 `if ('a' <= c && c <= 'z')` 保护。
8. **Python 的索引**：用 `ord(ch) - ord('a')`，不要写成 `int(ch)`（会抛异常）或 `ch - 'a'`（字符串不能相减）。
