# LeetCode 统计完全子字符串 题解

## 1. 题目概述

- **标题 / 题号**：统计完全子字符串（#2953，hard）
- **链接**：https://leetcode.cn/problems/count-complete-substrings/
- **来源**：LeetCode 第 374 场周赛 Q3
- **难度**：困难
- **标签**：哈希表、字符串、滑动窗口

**题意**：给定字符串 `word` 与整数 $k$，统计同时满足以下两个条件的**子串**数目：

1. 子串中**每个**出现的字符**恰好**出现 $k$ 次；
2. 子串中**相邻**两个字符的字母表距离**至多**为 2（$|c_1 - c_2| \le 2$）。

满足者称为**完全子字符串**，返回其数目。

**约束**：

- $1 \le word.length \le 10^5$
- `word` 只包含小写英文字母（→ 任何子串的字符种数 $\le 26$）
- $1 \le k \le word.length$

> 💡 两个条件性质截然不同：条件②是**局部**约束（只看相邻对），条件①是**全局**约束（看整个窗口的计数）。解法的全部艺术就在于把二者**解耦**：先用条件②把 `word` 切成若干段，再在段内用**定长滑窗**数条件①。而「定长」之所以能成立，是因为条件①把合法子串的长度**锁死**为「字符种数 $\times\ k$」——合法长度只有 26 档。

## 2. 示例

**示例 1**

```text
输入：word = "igigee", k = 2
输出：3
解释：完全子字符串为 "igig"（下标 0–3，i×2 g×2）、"ee"（下标 4–5，e×2）
      与 "igigee"（整串，i×2 g×2 e×2），共 3 个。
```

**示例 2**

```text
输入：word = "aaabbbccc", k = 3
输出：6
解释："aaa"、"bbb"、"ccc"、"aaabbb"、"bbbccc"、"aaabbbccc"，共 6 个。
```

**示例 3**（自拟，演示断点）

```text
输入：word = "acx", k = 1
输出：4
解释：|c−x| = 21 > 2，断点把串切成段 "ac" 与 "x"。
      完全子串："a"、"c"、"x"、"ac"（|a−c| = 2 ✓，各出现 1 次 ✓）；
      "cx" 与 "acx" 因相邻差 21 出局。
```

## 3. 解题思路

### 3.1 暴力思路：枚举子串 + 逐个验证

枚举每个起点 $l$，向右扩张右端点 $r$，维护 `cnt[26]` 计数：相邻差条件一旦破坏立即 `break`（这其实已经天然完成了分段）；每一步检查「所有非零计数是否都等于 $k$」，借助两个标量（出现字符种数、计数恰为 $k$ 的字符种数）也能做到 $O(1)$ 判定。但窗口数目是 $O(n^2)$ 量级（$n = 10^5$ 时达 $10^{10}$），必然超时。

死结在于**变长窗口的数目是平方级**。突破口：条件①其实把「合法窗口的长度」限定成了**离散的 26 档**。

### 3.2 核心观察：两条性质解耦——先切段，再定长

![核心观察一：相邻差大于2处断开，完全子串不跨段](images/wc374_q3_segment_split_concept.svg)

**观察①（切段）**：条件②只约束**相邻**字符对。凡 $|word[i+1] - word[i]| > 2$ 的位置就是一个**断点**，任何跨过断点的子串必然包含一对违规相邻字符。于是按断点把 `word` 切成若干**极大段**，完全子串整段落入某一段内——各段**独立求解，答案求和**。

**观察②（定长）**：设某完全子串含 $d$ 种不同字符，每种恰 $k$ 次，则其长度**恰为** $d \cdot k$。小写字母只有 26 种，$d \in [1, 26]$——**合法子串的长度只有 26 档**。反过来枚举 $m = 1, 2, \dots, 26$，窗口长度锁定为 $L = m \cdot k$，只需回答：每个定长窗口里是否**恰好** $m$ 种字符、每种恰 $k$ 次？

### 3.3 算法流程：exactly 计数器 + 定长滑窗

![算法流程：定长滑窗与 exactly 计数器](images/wc374_q3_fixed_window_flow.svg)

对每个段、每个 $m$（满足 $m \cdot k \le$ 段长），用**定长滑窗**线性扫一遍：

1. **切段**：双指针，`i` 指向段首，`j` 尽量右伸（`|word[j+1] − word[j]| ≤ 2`），段为 $[i, j]$，处理完 `i = j + 1`；
2. **维护**：`cnt[26]`（窗口内各字符计数）与标量 `exactly`（计数**恰好等于** $k$ 的字符种数）；右端进、左端出各花 $O(1)$ 更新——只有计数**穿越** $k$ 的那一步才触碰 `exactly`；
3. **判定**：窗口长度恰为 $L = m \cdot k$ 时，`exactly == m` 则该窗口完全，答案 $+1$。

**为什么 `exactly == m` 一个比较就够**？这 $m$ 种字符各出现 $k$ 次，已占满 $m \cdot k = L$ 个位置——窗口里**挤不进任何其他字符**，也不可能有字符超次。一次整数比较替代 26 次计数检查。

### 3.4 示例演算

![示例演算：igigee枚举m=1,2,3](images/wc374_q3_example_walkthrough.svg)

以示例 1（`word = "igigee"`，$k = 2$）为例。整串相邻差都是 2，只有一段。枚举 $m$：

- $m = 1$（$L = 2$）：`ig`、`gi`、`ig`、`ge`、`ee`，仅 `ee` 满足 e×2 → 计 1；
- $m = 2$（$L = 4$）：`igig`（i×2 g×2 ✓）、`gige`、`igee` → 计 1；
- $m = 3$（$L = 6$）：`igigee`（i×2 g×2 e×2 ✓）→ 计 1。

合计 $3$ ✓。再验证示例 2（`aaabbbccc`，$k = 3$）：$m=1$ 得 `aaa`/`bbb`/`ccc` 计 3；$m=2$ 得 `aaabbb`/`bbbccc` 计 2；$m=3$ 得 `aaabbbccc` 计 1，共 6 ✓。

## 4. 算法细节

1. **切段实现**：一次线性扫描，总耗时 $O(n)$。段与段互不相交，答案直接累加，无任何去重负担。
2. **m 的枚举范围**：$m \in [1, 26]$ 且 $m \cdot k \le$ 段长；$L$ 随 $m$ 单调递增，超过段长即可 `break`。段长不足 $k$ 的段自动整段跳过。
3. **exactly 的增量更新**（全部 $O(1)$，关键在「穿越 $k$」）：
   - 右端进 `c`：`cnt[c]++` 后，若 `cnt[c] == k` 则 `exactly++`；若 `cnt[c] == k+1`（即更新前恰为 $k$）则 `exactly--`；
   - 左端出 `d`：`cnt[d]--` 后，若 `cnt[d] == k` 则 `exactly++`；若 `cnt[d] == k-1`（即更新前恰为 $k$）则 `exactly--`；
   - 其余变化（计数在远离 $k$ 的区域游动）不触碰 `exactly`。
4. **先加右端、再删左端**：右端点 `p` 每轮先 `cnt[word[p]]++`；当 `p − i + 1 > L` 时删去 `word[p − L]`；随后若 `p − i + 1 ≥ L` 且 `exactly == m` 则计数。「先删后加」等写法亦可行，但**下标与长度判断必须自洽**。
5. **cnt 数组按（段, m）独立新建**：26 个整数的初始化开销可忽略，换取零清零 bug。
6. **答案规模**：每个 $m$ 至多 $n$ 个窗口，答案 $\le 26n \approx 2.6 \times 10^6$，`int` 足够；C++ 代码用 `long long` 累加是双保险。

## 5. 正确性证明

**引理 1（切段引理）**：任何完全子串完整落在某个极大段内。

**证明**：设 $s = word[l..r]$ 完全。若它跨过断点 $(t, t+1)$（即 $l \le t < r$ 且 $|word[t+1] - word[t]| > 2$），则 $word[t]$ 与 $word[t+1]$ 在 $s$ 中相邻，违反条件②，矛盾。故 $s$ 内部不含任何断点，即 $l$ 与 $r$ 同属一段。∎

**引理 2（判定引理）**：段内长度为 $m \cdot k$ 的窗口中，设 $cnt[c]$ 为字符 $c$ 的出现次数，$E = |\{c : cnt[c] = k\}|$。则窗口满足条件①当且仅当 $E = m$。

**证明**：（⟹）条件①成立时每个出现字符恰 $k$ 次，故 $E$ 即出现字符种数 $d$；又 $dk = $ 窗长 $= mk$ 且 $k \ge 1$，得 $d = m$，故 $E = m$。（⟸）$E = m$ 时这 $m$ 种字符共出现 $mk = L$ 次，恰好占满窗口全部 $L$ 个位置，故窗口不含其他字符，且每个出现字符恰 $k$ 次。∎

**定理**：算法返回值恰为完全子串总数。

**证明**：先证**不重**。子串由（起点，长度）唯一确定；窗长 $mk$ 随 $m$ 严格单调（$k \ge 1$），段两两不交且窗口不跨段，故每对（起点，长度）至多在唯一的（段， $m$）轮次中被枚举——每个子串至多被计数一次。

再证**不漏**。设 $s$ 完全、含 $d$ 种字符、长 $dk$，由引理 1 落在某段内，$dk \le$ 段长成立，故该段 $m = d$ 轮会枚举到以 $s$ 起点为起点的 $dk$ 长窗口；此时由引理 2 得 $E = d = m$，判定通过，$s$ 被计数。

最后证**不假**。每个被计数窗口都在段内（相邻差 $\le 2$，条件②成立）且 $E = m$，由引理 2 满足条件①，确为完全子串。

三方面合计：计数对象与完全子串集合之间建立了一一对应，返回值 = 完全子串总数。∎

> 💡 `exactly` 的增量更新维护不变式「$E$ = 当前窗口中计数恰为 $k$ 的字符种数」：每次增删恰使一个字符的计数变动 1，故只有计数**穿越** $k$ 的那一步会改变 $E$，与更新规则逐分支吻合，引理 2 的判定在滑动全程有效。

## 6. 复杂度分析

- **时间复杂度**：$O(26n)$。切段 $O(n)$；每段内每个 $m$ 做一次线性扫描，$\sum_{\text{段}} \sum_{m=1}^{26} \text{段长} \le 26n \approx 2.6 \times 10^6$，每步 $O(1)$。
- **空间复杂度**：$O(26)$。`cnt` 数组与常数个标量，与 $n$ 无关（不计输出）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countCompleteSubstrings(string word, int k) {
        int n = word.size();
        long long ans = 0;
        int i = 0;
        while (i < n) {
            int j = i;
            while (j + 1 < n && abs(word[j + 1] - word[j]) <= 2) j++;
            int len = j - i + 1;
            for (int m = 1; m <= 26 && m * k <= len; m++) {
                int L = m * k;
                int cnt[26] = {0};
                int exactly = 0;
                for (int p = i; p <= j; p++) {
                    int c = word[p] - 'a';
                    cnt[c]++;
                    if (cnt[c] == k) exactly++;
                    else if (cnt[c] == k + 1) exactly--;
                    if (p - i + 1 > L) {
                        int d = word[p - L] - 'a';
                        cnt[d]--;
                        if (cnt[d] == k) exactly++;
                        else if (cnt[d] == k - 1) exactly--;
                    }
                    if (p - i + 1 >= L && exactly == m) ans++;
                }
            }
            i = j + 1;
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countCompleteSubstrings(self, word: str, k: int) -> int:
        n = len(word)
        ans = 0
        i = 0
        while i < n:
            j = i
            while j + 1 < n and abs(ord(word[j + 1]) - ord(word[j])) <= 2:
                j += 1
            seglen = j - i + 1
            for m in range(1, 27):
                L = m * k
                if L > seglen:
                    break
                cnt = [0] * 26
                exactly = 0
                for p in range(i, j + 1):
                    c = ord(word[p]) - 97
                    cnt[c] += 1
                    if cnt[c] == k:
                        exactly += 1
                    elif cnt[c] == k + 1:
                        exactly -= 1
                    if p - i + 1 > L:
                        d = ord(word[p - L]) - 97
                        cnt[d] -= 1
                        if cnt[d] == k:
                            exactly += 1
                        elif cnt[d] == k - 1:
                            exactly -= 1
                    if p - i + 1 >= L and exactly == m:
                        ans += 1
            i = j + 1
        return ans
```

## 8. 边界情况与易错点

1. **忘了先切段**：直接对整串做定长滑窗会把跨断点的窗口误判为合法（条件②被无视）。切段是正确性前提，不是可选优化。
2. **m 上界与 break**：`m ≤ 26` 由字母表大小决定；`m·k > 段长` 必须跳过/`break`（窗长随 $m$ 单调增）。段长 $< k$ 的段一个窗口都出不来。
3. **exactly 更新分支写错**：典型 bug 是把进端「`exactly--`」的条件写成「新值 $> k$」——计数从 $k+1$ 涨到 $k+2$ 时 $E$ 不变。只有**穿越** $k$ 的那次更新才改变 $E$。
4. **左右端更新顺序与下标自洽**：本文「先加 `word[p]`，超长再删 `word[p−L]`」，对应「`p−i+1 > L` 删、`p−i+1 ≥ L` 判」；换更新顺序则两处判断都要联动修改。
5. **k = 1 的退化**：`cnt[c]` 涨到 2 时恰好触发 `exactly--`（旧值 1 即 $k$），逻辑自动覆盖，无需特判。
6. **极端切段**：`word = "aaa…"` 是一个整段（相邻差 0）；`word = "azaz…"` 每个位置都是断点、段长全为 1——$k \ge 2$ 时答案为 0，$k = 1$ 时答案为 $n$。
7. **答案不会溢出**：每个 $m$ 至多贡献 $n$ 个窗口，答案 $\le 26n < 3 \times 10^6$，`int` 安全（代码用 `long long` 累加系双保险）。
8. **性能误判**：看似「26 趟全扫」浪费，实则总步数 $\le 26n = 2.6 \times 10^6$；真正会超时的是 $O(n^2)$ 枚举变长窗口。
