# LeetCode 需要添加的硬币的最小数量 题解

## 1. 题目概述

- **标题 / 题号**：需要添加的硬币的最小数量（#2952，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-coins-to-be-added/
- **来源**：LeetCode 第 374 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：给定整数数组 `coins`（可用硬币**面值**）与整数 `target`。若存在 `coins` 的某个**子序列**总和为 $x$，则 $x$ 是**可取得的金额**。可以往数组中添加**任意面值**的硬币，求使 $[1, target]$ 内**每个整数**都可取得的最少添加枚数。

**约束**：

- $1 \le target \le 10^5$
- $1 \le coins.length \le 10^5$
- $1 \le coins[i] \le target$

> 💡 「子序列」= 每枚硬币**至多用一次**的子集和，顺序无关——这与零钱兑换家族（硬币无限用）划清界限。更关键的信号：$n \cdot target$ 高达 $10^{10}$，任何逐金额验证的 DP 都会爆；但题目只问「每个金额**是否**可达」的真假，且要求的是**连续区间**全覆盖——这正好是 [330. 按要求补齐数组](https://leetcode.cn/problems/patching-array/) 与 [1798. 你能构造出连续值的最大数目](https://leetcode.cn/problems/maximum-number-of-consecutive-values-you-can-make/) 的同款结构，可以把整张可达性真值表压成**一个标量**做贪心。

## 2. 示例

**示例 1**

```text
输入：coins = [1,4,10], target = 19
输出：2
解释：添加面值 2 和 8 的硬币各一枚，得到 [1,2,4,8,10]。
      1 到 19 的所有整数都可用其中的硬币组合得到。
```

**示例 2**

```text
输入：coins = [1,4,10,5,7,19], target = 19
输出：1
解释：只需添加一枚面值 2 的硬币，得到 [1,4,5,7,10,19] 加上 2 后可覆盖 1..19。
```

**示例 3**

```text
输入：coins = [1,1,1], target = 20
输出：3
解释：添加面值 4、8、16 各一枚，得到 [1,1,1,4,8,16]，可覆盖 1..20。
      注意：原生硬币全部吸收完仍不够，必须继续补币翻倍追赶。
```

## 3. 解题思路

### 3.1 暴力思路：子集和验证 + 枚举补币

朴素做法分两层。**验证层**：给定一组硬币，用布尔子集和 DP（`dp[s] |= dp[s−c]`，每枚硬币倒序更新一次）判定 $[1, target]$ 每个值是否可达，$O(n \cdot target) = 10^{10}$，即便 bitset 压位也只够勉强跑一次。**决策层**：添加的面值是任意正整数，候选空间 $[1, target]$，「先选补哪枚、再验证」是组合爆炸；即便二分答案 $k$，也无法高效验证「补 $k$ 枚是否足够」。

死结在于「枚举金额、逐个验证」。换视角：**不枚举金额，只盯住最小的不可达金额 $x$**——它是整个可达结构的唯一瓶颈，把无穷的验证压成对一个缺口的修补。

### 3.2 核心观察：不变式「子集和恰为 $[0, x-1]$」

![核心观察：连续覆盖区间与最小缺口 x](images/wc374_q2_coverage_gap_concept.svg)

将 `coins` **排序**后从小到大处理，维护标量 $x$，配合一条严格不变式：

> **不变式**：由「已吸收的原生硬币 + 已主动添加的硬币」构成的子集和集合，**恰好**是连续区间 $[0, x-1]$（0 对应空子序列）。即 $[1, x-1]$ 全部可取得，而 $x$ 暂时凑不出——$x$ 就是当前**最小缺口**。

初始无硬币被处理，子集和只有 $\{0\}$，故 $x = 1$。逐枚考察排序后的下一枚面值 $c$，只有两种情形：

**情形① $c \le x$（吸收）**：$[0, x-1]$ 中每个和 $v$ 添上 $c$ 得 $v + c \in [c, c+x-1]$，由 $c \le x$ 知新段与旧段相接或重叠，无缝并成 $[0, x+c-1]$。更新 $x \mathrel{+}= c$。

**情形② $c > x$ 或硬币用尽（真缺口）**：已处理硬币的和全在 $[0, x-1]$ 内，未处理面值全 $> x$，任何包含它们的子集和都 $> x$——$x$ 谁也凑不出，**必须补一枚新硬币**。设补面值 $y$：

- $y > x$：单枚就超过 $x$，缺口没堵上，白补；
- $y < x$：新覆盖 $[0, x+y-1]$，增长慢半拍；
- $y = x$：恰接成 $[0, 2x-1]$，覆盖**翻倍**，一步到位。

故最优动作是**补面值 $x$**：$ans{+}{+}$，$x \leftarrow 2x$，且扫描指针 $i$ **原地不动**（下一轮再判同一枚 $c$）。循环直到 $x > target$。

> 💡 **一句话**：`coins[i] ≤ x` 则吸收 `x += coins[i]`；否则补 `x` 本身令 `x *= 2`。与 330 的 `miss`、1798 的「可达区间」是同一不变式的三副面孔。

### 3.3 算法流程

![算法流程：排序后单趟扫描，吸收或补币](images/wc374_q2_algorithm_flow.svg)

1. **初始化**：`coins` 升序排序；`x = 1`（最小缺口），`i = 0`（扫描下标），`ans = 0`；
2. **循环**（当 `x <= target`）：
   - 若 `i < n` 且 `coins[i] <= x`：**吸收**，`x += coins[i]`，`i += 1`；
   - 否则：**补一枚面值 x**，`ans += 1`，`x *= 2`（`i` 不动，下一轮重新判 `coins[i]`）；
3. **返回** `ans`。

### 3.4 示例演算

![示例 1 演算：逐步吸收与补币](images/wc374_q2_example_walkthrough.svg)

以示例 1（`coins = [1,4,10]`，`target = 19`）为例，跟踪 $x$ 的演化：

| 步骤 | $x$（缺口） | 当前面值 $c$ | 判定 | 动作 | 覆盖范围 |
|------|------------|-------------|------|------|----------|
| ① | 1 | 1 | $1 \le 1$ ✓ | 吸收，$x \leftarrow 2$ | $[1, 1]$ |
| ② | 2 | 4 | $4 > 2$ ✗ | **补面值 2**，$ans = 1$，$x \leftarrow 4$ | $[1, 3]$ |
| ③ | 4 | 4 | $4 \le 4$ ✓ | 吸收，$x \leftarrow 8$ | $[1, 7]$ |
| ④ | 8 | 10 | $10 > 8$ ✗ | **补面值 8**，$ans = 2$，$x \leftarrow 16$ | $[1, 15]$ |
| ⑤ | 16 | 10 | $10 \le 16$ ✓ | 吸收，$x \leftarrow 26$ | $[1, 25]$ |
| ⑥ | 26 | — | $26 > 19$ | 终止 | $[1, 25] \supseteq [1, 19]$ ✓ |

补出 $\{2, 8\}$ 两枚，与官方解释一致。注意步骤⑤：补完 8 之后覆盖已到 $[1,15]$，面值 10 被直接**罩进**覆盖里照常吸收——**补币不会让任何原生硬币作废**。再验证示例 3（`[1,1,1]`，`target = 20`）：三枚 1 依次吸收后 $x = 4$，硬币用尽，连补 $4, 8, 16$ 三枚，$x$ 依次变 $8, 16, 32 > 20$，$ans = 3$ ✓。

## 4. 算法细节

1. **排序是前提**：归纳按面值升序进行，保证考察 $c$ 之前所有更小面值已处理；「$c > x$ ⟹ 后续面值全都暂时够不着」依赖排序后的单调性。乱序会在先遇到大面值时误判成缺口。
2. **吸收分支**：`coins[i] <= x` 时执行 `x += coins[i]; i++`。每枚原生硬币**恰好被吸收一次**，指针 $i$ 单调推进，不回退。
3. **补币分支不推进 `i`**：补出的覆盖 $[0, 2x-1]$ 可能已把 `coins[i]` 罩住（下一轮直接吸收它），也可能还不够（继续补）。$i$ 原地等待是正确语义。
4. **终止条件是 `x > target`，不是 `i == n`**：硬币用尽后仍可能 $x \le target$（示例 3），此时每轮都走补币分支连续翻倍。覆盖罩住 $[1, target]$ 即可停，多余的覆盖无所谓。
5. **溢出分析**：只有 $x \le target \le 10^5$ 时才进入循环体，吸收/翻倍后 $x \le 2 \times 10^5$，`int` 足够（对比 330 的 $n$ 可达 $2^{31}-1$ 才必须 `long long`）。

## 5. 正确性证明

**引理 1（吸收引理）**：若已处理硬币的子集和集合恰为 $[0, x-1]$，加入一枚面值 $c \le x$ 的硬币后，子集和集合恰为 $[0, x+c-1]$。

**证明**：新集合的每个子集要么不含 $c$（和 $\in [0, x-1]$），要么含 $c$（和 $\in [c, c+x-1]$），故子集和集合 $= [0, x-1] \cup [c, c+x-1]$。由 $c \le x$ 知两闭区间相接或重叠，并集为连续区间 $[0, x+c-1]$。∎

**引理 2（缺口引理）**：设排序后前 $i$ 枚已处理、覆盖恰为 $[0, x-1]$，且 $i = n$ 或 $coins[i] > x$。若 $x \le target$，则任何使 $[x, target]$ 全可达的方案（在剩余原生硬币之外）**至少添加一枚面值 $y \le x$ 的硬币**。

**证明**：$x$ 必须可达，设凑出 $x$ 的子集为 $T$。$T$ 若不含新硬币：其原生部分要么取自前 $i$ 枚（和 $\le x-1 < x$），要么含第 $i$ 枚及之后（每个面值 $> x$，非空部分和 $> x$），均矛盾。故 $T$ 含新硬币；又 $T$ 的总和为 $x$ 且元素全为正，故 $T$ 中每枚新硬币面值 $\le x$。∎

**引理 3（交换引理）**：条件同引理 2。设 $B$ 是从当前状态出发的可行方案（使 $[x, target]$ 全可达）且 $y \in B$，$y \le x$，则 $B \setminus \{y\}$ 从「补入面值 $x$ 之后的状态」（覆盖恰为 $[0, 2x-1]$，指针 $i$ 不变）出发仍可行。

**证明**：由引理 1，补 $x$ 后覆盖恰为 $[0, 2x-1]$。任取 $v \in [2x, target] \subseteq [x, target]$，$B$ 可行给出 $v = s + b + r$，其中 $s \in [0, x-1]$（已处理部分的子集和），$b$ 是 $B$ 的子集和，$r$ 是剩余原生 $coins[i..]$ 的子集和（可为 0）。分两种情况：

- $b$ 的子集不含 $y$：则 $v = s + b + r$，$s \in [0, x-1] \subseteq [0, 2x-1]$，$b$ 仍是 $B \setminus \{y\}$ 的子集和，$r$ 不变，仍可凑出；
- $b = y + b''$：改写 $v = (s + y) + b'' + r$。由 $s \le x - 1$、$y \le x$ 得 $s + y \in [0, 2x-1]$，恰落入新覆盖谱；$b''$ 是 $B \setminus \{y\}$ 的子集和，$r$ 不变，仍可凑出。∎

> 💡 直觉：把那枚小硬币 $y$ 的贡献「折进」更宽的覆盖谱里——旧谱配 $y$ 能凑的，新谱 $[0, 2x-1]$ 用 $s + y$ 顶替。同法可证**吸收原生硬币不损可行性**（把被吸收的 $c$ 折进谱中），故引理 3 的结论在算法后续自动吸收原生后依然保持。

**定理**：算法返回的补币数 $k$ 等于最优值 $\mathrm{OPT}$。

**证明**：先证 $k \le \mathrm{OPT}$。对算法的补币轮次 $t$ 归纳：第 $t$ 次补币前的真缺口状态处，存在从该状态出发的可行方案 $B_t$ 且 $|B_t| = \mathrm{OPT} - (t-1)$。$t = 1$ 时取 $B_1$ 为任一最优方案。归纳步：$x_t \le target$（未终止），由引理 2，$B_t$ 含某 $y \le x_t$；由引理 3，$B_{t+1} = B_t \setminus \{y\}$ 从补 $x_t$ 后的状态可行，$|B_{t+1}| = |B_t| - 1$；算法随后吸收的原生硬币不损可行性。算法终止时得到可行方案 $B_{k+1}$ 且 $|B_{k+1}| = \mathrm{OPT} - k \ge 0$，故 $k \le \mathrm{OPT}$。

再证 $k \ge \mathrm{OPT}$：算法全程由引理 1 维护「已用硬币子集和恰为 $[0, x-1]$」，终止时 $x > target$，即 $[1, target]$ 全部可达——算法自己补的 $k$ 枚硬币就是一组可行方案，故 $\mathrm{OPT} \le k$。两边夹得 $k = \mathrm{OPT}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导。扫描阶段每枚原生硬币恰好吸收一次（$O(n)$）；每次补币 $x$ 翻倍，至多 $\lceil \log_2 target \rceil + 1 \approx 18$ 次补币。合计 $O(n \log n + \log target)$。
- **空间复杂度**：$O(1)$。忽略排序的栈空间，仅 `x / i / ans` 三个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumAddedCoins(vector<int>& coins, int target) {
        sort(coins.begin(), coins.end());
        int x = 1, ans = 0, i = 0, n = coins.size();
        while (x <= target) {
            if (i < n && coins[i] <= x) {
                x += coins[i++];
            } else {
                ans++;
                x *= 2;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumAddedCoins(self, coins: List[int], target: int) -> int:
        coins.sort()
        x, ans, i, n = 1, 0, 0, len(coins)
        while x <= target:
            if i < n and coins[i] <= x:
                x += coins[i]
                i += 1
            else:
                ans += 1
                x *= 2
        return ans
```

## 8. 边界情况与易错点

1. **忘记排序**：`coins` 乱序输入，不排序则「遇到大面值」无法断定是真缺口，会疯狂误补。这是与 330 唯一的接口差异（330 保证升序输入）。
2. **终止条件写成 `i == n`**：示例 3 中硬币用尽时 $x = 4 < 20$，仍需连补 $4, 8, 16$。必须循环到 `x > target`。
3. **补币后推进了 `i`**：补币分支里若顺手 `i++`，会漏掉 `coins[i]`——它可能已被新覆盖罩住等着被吸收。
4. **最小面值不为 1**：如 `coins = [2, ...]`，第一步 $x = 1$ 即缺口，补面值 1，逻辑自动覆盖，无需特判。
5. **面值可重复**：示例 3 有三个 1，逐枚吸收即可，去重反而错（三枚 1 贡献覆盖 $[0,3]$，去重只剩 $[0,1]$）。
6. **溢出误判**：`x` 进入循环体时 $\le 10^5$，翻倍后 $\le 2 \times 10^5$，`int` 安全；若套用 330 的写法且把 `target` 换成 $2^{31}$ 量级，才需要 `long long`。
