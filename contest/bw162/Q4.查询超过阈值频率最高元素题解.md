# LeetCode 查询超过阈值频率最高元素 题解

## 1. 题目概述

- **标题 / 题号**：查询超过阈值频率最高元素（#3636，hard）
- **链接**：https://leetcode.cn/problems/threshold-majority-queries/
- **来源**：LeetCode 第 162 场双周赛 Q4
- **难度**：困难
- **标签**：数组、哈希表、分块、二分查找

**题意**：给定长度为 $n$ 的数组 `nums` 与 $q$ 个查询 `queries[i] = [l, r, threshold]`。对每个查询，在子数组 `nums[l..r]` 中找出出现次数**至少** `threshold` 次的元素，取**频次最高**者；频次相同取**值最小**者；不存在则返回 $-1$。返回所有查询的答案数组。

**约束**：

- $1 \le n \le 10^4$
- $1 \le \text{nums}[i] \le 10^9$（需要离散化）
- $1 \le q \le 5 \times 10^4$
- $0 \le l \le r < n$，$1 \le \text{threshold} \le r - l + 1$

$n$ 只有 $10^4$，但 $q$ 有 $5\times10^4$，所以要围绕「**每次查询的代价远小于区间长度**」来设计。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,2,1,1], queries = [[0,5,4],[0,3,3],[2,3,2]]
输出：[1,-1,2]
解释：[0,5,4] → 1 出现 4 次、2 出现 2 次，取 1；
      [0,3,3] → 1 与 2 都只出现 2 次 < 3，无答案 → -1；
      [2,3,2] → 子数组 [2,2]，2 出现 2 次 → 2。
```

**示例 2**

```text
输入：nums = [3,2,3,2,3,2,3], queries = [[0,6,4],[1,5,2],[2,4,1],[3,3,1]]
输出：[3,2,3,2]
解释：[0,6,4] → 3 出现 4 次、2 出现 3 次 → 3；
      [1,5,2] → 2 出现 3 次、3 出现 2 次 → 2；
      [2,4,1] → 3 出现 2 次最多 → 3；
      [3,3,1] → 只有一个元素 2 → 2。
```

**示例 3（自造，检查平局取小）**

```text
输入：nums = [5,7,5,7], queries = [[0,3,1]]
输出：[5]
解释：5 与 7 都出现 2 次，平局取更小的 5。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询扫描子数组并用哈希表统计频次，$O(\sum (r-l+1))$，最坏 $5\times10^4 \times 10^4 = 5\times10^8$，C++ 勉强、Python 必超时。而且每次查询都重复统计了大量完全相同的元素，信息浪费严重。

### 3.2 核心观察：候选只有「中间整块段的众数 + 两侧边界元素」

![分块：查询区间 = 左边界 + 一整个「中间块段」 + 右边界](images/bw162_q4_block_decomposition.svg)

把数组按 **$B$ 个一块**切分，块编号 $0, 1, \dots$。任取查询 $[l, r]$，令

- $s$ = 不小于 $l$ 的最小块的**左端点**（$s = \lceil l/B \rceil \cdot B$）；
- $e$ = 不大于 $r$ 的最大块的**右端点**（$e = \lfloor (r+1)/B\rfloor \cdot B - 1$）。

则 $[l, r]$ 被拆成三段：左侧边界 $[l, s-1]$（至多 $B$ 个）、**中间整块段** $[s, e]$（整块）、右侧边界 $[e+1, r]$（至多 $B$ 个）。当 $s > e$ 时没有中间段，整个区间都是边界。

对**中间整块段**，我们**预先**算出它的众数（频次最大的值，平局取最小值），记频次 `modeFreq`、值 `modeVal`。预计算所有块区间 $(bi, bj)$ 的众数只需 $O(\frac{n}{B} \cdot n)$ 时间与 $O((\frac{n}{B})^2)$ 空间（见 §4）。

![为什么候选只有这些：不在边界出现的值，频次全由中间块段决定](images/bw162_q4_candidate_set.svg)

**关键引理**：若某值 $v$ 没有在左、右边界出现，则它在 $[l,r]$ 中的频次等于它在中间块段中的频次，从而不超过 `modeFreq`。

于是答案只可能来自两类：

1. **中间块段的众数** `modeVal`：若 `modeFreq ≥ threshold`，它就是在「没有边界加成」的值中最优的；
2. **出现在两侧边界上的值**：它们的频次可能因为边界上的额外出现而超过众数，必须逐个检查。

候选数至多 $1 + 2B$ 个。对每个候选，用「值 → 出现位置列表」+ 两次二分（`upper_bound(r) - lower_bound(l)`）在 $O(\log n)$ 内算出区间频次，再按「频次降序、值升序」取最优。

取 $B = 64$ 时：预计算约 $\frac{10^4}{64} \times 10^4 \approx 1.6\times10^6$，每查询约 $129$ 个候选 $\times 2$ 次二分，总查询代价约 $1.3\times10^7$ 次比较，完全可接受。

### 3.3 算法流程

```text
预处理：
  1. 离散化 nums → 编号 id[i]，并保存真实值 vals[]（升序）
  2. pos[v] = 值 v 出现的下标列表（天然有序）
  3. 枚举块的左端点 bi，向右扩展 r，用计数数组维护「当前众数」，
     在每到达一个块的右端点时记录 mode[bi][bj] = (众数频次, 众数值)

查询 [l, r, t]：
  1. bestFreq = 0, bestVal = -1
  2. s = ⌈l/B⌉·B, e = ⌊(r+1)/B⌋·B − 1
  3. 若 s ≤ e 且 mode[s/B][e/B].freq ≥ t:
         用该众数作为候选
  4. 候选 += [l, s−1] 与 [e+1, r] 上的所有值（重复无妨）
  5. 对每个候选 v：freq = upper_bound(pos[v], r) − lower_bound(pos[v], l)
     若 freq ≥ t 且（freq > bestFreq 或 freq == bestFreq 且 v < bestVal）→ 更新
  6. 输出 bestVal（可能为 −1）
```

`nums = [1,1,2,2,1,1]`，取 $B = 4$（这里为演示方便，实际代码用 64）：

| 查询 | 子数组 | 边界 / 中间段 | 候选 | 各候选频次 | 答案 |
|---|---|---|---|---|---|
| [0,5,4] | 1 1 2 2 1 1 | 边界 [], 中间 [0,3]，右边界 [4,5] | 众数(中间)=1 或 2（各 2 次）、边界值 1 | 1→4, 2→2 | 1 |
| [0,3,3] | 1 1 2 2 | 边界 [], 中间 [0,3] | 众数 1（2 次） | 1→2, 2→2 | −1（都 < 3） |
| [2,3,2] | 2 2 | 全是边界 | 2 | 2→2 | 2 |

第一问中，边界上的 1 把中间段众数 1 的频次从 2 抬到了 4，这正是「边界必须单独检查」的原因。

## 4. 算法细节

1. **离散化**：`nums[i]` 可达 $10^9$，先排序去重得到 `vals`，再用 `lower_bound` 映射到 $[0, D)$。
2. **众数预计算**：对每个起始块 $bi$，`cnt` 数组清零后从 $bi \cdot B$ 向右逐格累加，实时维护 `(bestCnt, bestVal)`；只在「块右端点」处把当前众数写入 `mode[bi][bj]`。每个 $bi$ 的代价 $O(n)$，共 $O(\frac{n}{B}\cdot n)$。注意平局规则：频次相同时取**更小的值**（`c == bestCnt && vals[v] < bestVal`）。
3. **`mode` 的初值**：用 `(0, -1)`，当区间为空（$s > e$）时不使用。
4. **边界候选的去重**：不去重也不会错（重复检查同一值只是多花常数），代码里直接遍历，最坏 $2B$ 次二分。
5. **`s` 与 `e` 的公式**：$s = \lceil l/B\rceil \cdot B$ 可能 $> r$（例如 $l$ 在最后一块内部），此时中间段为空；$e = \lfloor (r+1)/B\rfloor B - 1$ 可能 $< l$。代码里用 `if (s <= e)` 判空，边界遍历用 `i <= r` 与 `max(e+1, l)` 防越界。
6. **二分统计**：`pos[v]` 是升序下标列表，区间频次 = `upper_bound(r) - lower_bound(l)`，两个函数都是 $O(\log)$。
7. **平局规则**：频次优先、值次之，必须在候选比较时就写对，否则示例 3 会返回 7。
8. **$B$ 的选择**：查询代价 $O(B\log n)$、预处理 $O(\frac{n^2}{B})$。$B \approx \sqrt{n/\log n}$ 附近最优；本题取 $64$ 实测很快（$n = 10^4$ 时预处理 $1.6\times10^6$）。

## 5. 正确性证明

**引理 1（边界外值的频次等于中间段频次）**：若值 $v$ 在 $[l, s-1]$ 与 $[e+1, r]$ 中都不出现，则 $\operatorname{freq}(l, r, v) = \operatorname{freq}(s, e, v)$。

**证明**：$[l, r] = [l, s-1] \cup [s, e] \cup [e+1, r]$ 是三个不相交区间的并，$v$ 在前后的出现次数都是 $0$，故总频次就是中间段的频次。∎

**引理 2（众数上界）**：对任意值 $v$，$\operatorname{freq}(s, e, v) \le \text{modeFreq}$，其中 `modeFreq` 是中间块段众数的频次。

**证明**：`modeFreq` 按定义是 $\max_{u} \operatorname{freq}(s,e,u)$，故对任何 $v$ 成立。∎

**引理 3（候选充分性）**：设 $v^*$ 是查询的答案（频次最大的达标值，平局取最小）。则 $v^*$ 要么等于 `modeVal`，要么在左/右边界中出现过。

**证明**：假设 $v^* \ne$ `modeVal` 且不在边界出现。由引理 1，$\operatorname{freq}(l,r,v^*) = \operatorname{freq}(s,e,v^*) \le \text{modeFreq}$。

另一方面，`modeVal` 若满足 `modeFreq ≥ t`，则它是合法候选，且 $\operatorname{freq}(l,r,\text{modeVal}) \ge \operatorname{freq}(s,e,\text{modeVal}) = \text{modeFreq} \ge \operatorname{freq}(l,r,v^*)$；若频次严格大于则 $v^*$ 不可能是答案，若相等则 `modeVal` 的频次与 $v^*$ 相同、值为 `modeVal`。需要注意的是 `modeVal` 是众数中的**最小值**，若 $v^* <$ `modeVal` 且两者频次相等，则 $v^*$ 也应满足 $\operatorname{freq}(s,e,v^*) = \text{modeFreq}$，此时 `modeVal` 的最小性给出 `modeVal ≤ v^*`，与 $v^* <$ `modeVal` 矛盾。所以 $v^*$ 一定在候选集中。∎

> 上面这段论证的关键是：候选集里的 `modeVal` 用**真实值**比较（平局取小），并且把边界值全部纳入候选，因此「因边界加成而变强的值」不会漏。

**引理 4（众数预计算正确）**：`mode[bi][bj]` 等于块区间 $[bi\cdot B,\ bj\cdot B + B - 1]$ 的众数（频次最大，平局取最小值）。

**证明**：对固定的 $bi$，从 $bi \cdot B$ 向右逐个加入元素，`cnt` 精确统计了当前前缀的频次；`(bestCnt, bestVal)` 在每次加入后按「频次更大，或频次相同且值更小」更新，故它始终是当前前缀的众数。在块右端点处记录，即得该块区间的众数。∎

**定理**：算法对每个查询输出的值等于题目要求的答案（无解时为 $-1$）。

**证明**：由引理 3，答案必在候选集中；由引理 4，`modeVal` 的频次 `modeFreq` 就是中间段众数频次。算法对每个候选都用二分精确计算了其在 $[l,r]$ 中的频次，并按题目的排序规则（频次降序、值升序）取最优，因此输出的就是答案；若所有候选的频次都 $< t$，循环不更新，输出 $-1$，符合「不存在这样的元素」。∎

## 6. 复杂度分析

- **时间**：
  - 离散化与建 `pos`：$O(n\log n)$；
  - 众数预计算：外层 $\frac{n}{B}$ 个起点、每个扫 $O(n)$，共 $O(\frac{n^2}{B})$；
  - 单次查询：候选至多 $2B + 1$ 个，每个两次二分 $O(\log n)$，即 $O(B\log n)$；
  - 总计 $O\big(n\log n + \frac{n^2}{B} + qB\log n\big)$。取 $B = 64$、$n = 10^4$、$q = 5\times10^4$ 时约为 $1.6\times10^6 + 5\times10^7$ 次基本操作。
- **空间**：$O(n)$ 存 `pos` 与离散化数组，$O\big((\frac{n}{B})^2\big)$ 存 `mode`（$n = 10^4, B = 64$ 时约 $157^2 \approx 2.5\times10^4$ 项）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    std::vector<int> subarrayMajority(std::vector<int>& nums, std::vector<std::vector<int>>& queries) {
        int n = (int)nums.size();
        // 1. 离散化
        std::vector<int> vals = nums;
        std::sort(vals.begin(), vals.end());
        vals.erase(std::unique(vals.begin(), vals.end()), vals.end());
        int D = (int)vals.size();
        std::vector<int> id(n);
        for (int i = 0; i < n; i++) id[i] = (int)(std::lower_bound(vals.begin(), vals.end(), nums[i]) - vals.begin());
        // 2. 每个值的出现位置
        std::vector<std::vector<int>> pos(D);
        for (int i = 0; i < n; i++) pos[id[i]].push_back(i);

        // 3. 分块：块内众数（频率最大，平局取最小数值）
        int B = 64;
        int nb = (n + B - 1) / B;
        std::vector<std::vector<std::pair<int, int>>> mode(nb, std::vector<std::pair<int, int>>(nb, {0, -1}));
        std::vector<int> cnt(D, 0);
        for (int bi = 0; bi < nb; bi++) {
            std::fill(cnt.begin(), cnt.end(), 0);
            int bestCnt = 0, bestVal = -1;
            for (int r = bi * B; r < n; r++) {
                int v = id[r];
                int c = ++cnt[v];
                if (c > bestCnt || (c == bestCnt && vals[v] < bestVal)) {
                    bestCnt = c;
                    bestVal = vals[v];
                }
                if ((r + 1) % B == 0 || r == n - 1) mode[bi][r / B] = {bestCnt, bestVal};
            }
        }

        auto countIn = [&](int v, int l, int r) -> int {
            const std::vector<int>& p = pos[v];
            return (int)(std::upper_bound(p.begin(), p.end(), r) - std::lower_bound(p.begin(), p.end(), l));
        };

        std::vector<int> ans;
        ans.reserve(queries.size());
        for (const std::vector<int>& q : queries) {
            int l = q[0], r = q[1], t = q[2];
            int bestCnt = 0, bestVal = -1;
            auto consider = [&](int v) {
                int c = countIn(v, l, r);
                if (c < t) return;
                if (c > bestCnt || (c == bestCnt && vals[v] < bestVal)) {
                    bestCnt = c;
                    bestVal = vals[v];
                }
            };
            int s = ((l + B - 1) / B) * B;          // 中间整块区间起点
            int e = ((r + 1) / B) * B - 1;          // 中间整块区间终点
            if (s <= e) {
                std::pair<int, int> md = mode[s / B][e / B];
                if (md.first >= t) consider((int)(std::lower_bound(vals.begin(), vals.end(), md.second) - vals.begin()));
            }
            for (int i = l; i < s && i <= r; i++) consider(id[i]);
            for (int i = std::max(e + 1, l); i <= r; i++) consider(id[i]);
            ans.push_back(bestVal);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def subarrayMajority(self, nums: list[int], queries: list[list[int]]) -> list[int]:
        from bisect import bisect_left, bisect_right
        n = len(nums)
        vals = sorted(set(nums))
        comp = {v: i for i, v in enumerate(vals)}
        D = len(vals)
        id_ = [comp[v] for v in nums]
        pos = [[] for _ in range(D)]
        for i, v in enumerate(id_):
            pos[v].append(i)

        # 分块预计算：块区间 [bi, bj] 内的众数（频率最大，平局取最小数值）
        B = 64
        nb = (n + B - 1) // B
        mode = [[(0, -1)] * nb for _ in range(nb)]
        for bi in range(nb):
            cnt = [0] * D
            best_cnt, best_val = 0, -1
            for r in range(bi * B, n):
                v = id_[r]
                cnt[v] += 1
                c = cnt[v]
                if c > best_cnt or (c == best_cnt and vals[v] < best_val):
                    best_cnt, best_val = c, vals[v]
                if (r + 1) % B == 0 or r == n - 1:
                    mode[bi][r // B] = (best_cnt, best_val)

        def count_in(v, l, r):
            p = pos[v]
            return bisect_right(p, r) - bisect_left(p, l)

        ans = []
        for l, r, t in queries:
            best_cnt, best_val = 0, -1
            candidates = []
            s = ((l + B - 1) // B) * B
            e = ((r + 1) // B) * B - 1
            if s <= e:
                c0, v0 = mode[s // B][e // B]
                if c0 >= t:
                    candidates.append(comp[v0])
            candidates.extend(id_[i] for i in range(l, min(s, r + 1)))
            candidates.extend(id_[i] for i in range(max(e + 1, l), r + 1))
            for v in candidates:
                c = count_in(v, l, r)
                if c < t:
                    continue
                if c > best_cnt or (c == best_cnt and vals[v] < best_val):
                    best_cnt, best_val = c, vals[v]
            ans.append(best_val)
        return ans
```

## 8. 边界情况与易错点

1. **平局取小值**：只按频次比较、忘记「频次相同取更小值」是最常见的 WA 源（示例 3 专门考它）。
2. **`s > e`（没有中间整块段）**：此时整个区间都在 1~2 个块内，全部当边界处理；若不判空会访问到 `mode` 的无效项。
3. **边界区间可能为空**：`l > s-1` 或 `e+1 > r` 时，`for` 循环的边界必须写成 `i < s && i <= r`、`from max(e+1, l)`，否则越界。
4. **阈值可能比中间段长度还大**：中间众数频次 `modeFreq < t` 时直接跳过它，但边界值仍可能靠「额外出现」达标，不能提前返回 $-1$。
5. **无解返回 $-1$**：用 `bestVal = -1` 作哨兵，注意与「数组中真的有 $-1$」区分（本题 `nums[i] \ge 1`，安全）。
6. **离散化后要保留真实值**：平局比较用的是**原始数值**，不是离散化编号。
7. **`mode` 预计算的平局更新**：`c == bestCnt && vals[v] < bestVal`，且只在块右端点记录，中间过程不要写入。
8. **$B$ 过大或过小**：$B$ 过大会让查询变慢，$B$ 过小会让预计算与 `mode` 空间爆掉；$64$ 左右是本题的合适区间。
9. **重复候选**：同一边界值可能出现多次，重复计算只会多花常数，不会影响正确性。

- [LeetCode 304. 二维区域和检索](https://leetcode.cn/problems/range-sum-query-2d-immutable/)：分块/前缀和的另一类「区间分解」思路。

**延伸思考**：若阈值恒等于「区间长度的一半以上」（真·众数），可以用随机采样：每次查询随机取 ~30 个位置，命中众数的概率极高，再用二分验证，$O(\log n)$ 期望；但本题阈值任意，采样失效。若要求在线插入/删除（动态数组），分块需要改成「块内哈希 + 块间合并」，复杂度升到 $O(\sqrt{n})$ 每次。

**变体**：若把「频次最高」换成「频次最低但至少 $t$ 次」，候选集仍然成立（边界外值的最小频次也由中间段决定），只需把比较方向反过来；若要求返回所有达标值，则需要枚举全部不同的值，复杂度回到 $O(D\log n)$。
