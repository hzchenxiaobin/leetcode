# LeetCode 单词子集 题解

## 1. 题目概述

- **标题 / 题号**：单词子集（#916，medium）
- **链接**：https://leetcode.cn/problems/word-subsets/
- **来源**：LeetCode 第 104 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、字符串

**题意**：给定两个字符串数组 `words1`、`words2`。若字符串 $b$ 的每个字母都出现在 $a$ 中（**计入重复次数**，例如 `"wrr"` 是 `"warrior"` 的子集，但不是 `"world"` 的子集），则称 $b$ 是 $a$ 的子集。若 `words2` 中**每一个**单词都是 $a$ 的子集，则 $a$ 是**通用单词**。返回 `words1` 中所有通用单词（顺序任意）。

**约束**：

- $1 \le words1.length, words2.length \le 10^4$
- $1 \le words1[i].length, words2[i].length \le 10$
- 仅含小写英文字母；`words1` 中字符串互不相同

## 2. 示例

**示例 1**

```text
输入：words1 = ["amazon","apple","facebook","google","leetcode"], words2 = ["e","o"]
输出：["facebook","google","leetcode"]
解释：三个词都同时含有 e 和 o；amazon 有 o 但无 e，apple 有 e 但无 o。
```

**示例 2**

```text
输入：words1 = ["amazon","apple","facebook","google","leetcode"], words2 = ["lc","eo"]
输出：["leetcode"]
解释：需要同时满足「含 l 与 c」和「含 e 与 o」，只有 leetcode 全中。
```

**示例 3**

```text
输入：words1 = ["acaac","cccbb","aacbb","caacc","bcbbb"], words2 = ["c","cc","b"]
输出：["cccbb"]
解释：words2 合并后需要「至少 2 个 c」和「至少 1 个 b」：acaac 只有 2 个 c 但没有 b；
      cccbb 有 3 个 c、2 个 b，满足。
```

## 3. 解题思路

### 3.1 暴力思路

对 `words1` 的每个 $a$、`words2` 的每个 $b$，分别统计字母频次再逐字母比较：$O(|words1| \cdot |words2| \cdot 26)$，$10^4 \times 10^4 \times 26 = 2.6\times 10^9$，超时。

问题在于：同一个 $a$ 要与**所有** $b$ 比较，而 $b$ 的信息其实可以**预先合并**成一份「最严格的要求」。

### 3.2 核心观察：把 words2 压成一个 26 维需求向量

![先把 words2 压成「每个字母需要几个」](images/wc104_q3_max_count_concept.svg)

「$b$ 是 $a$ 的子集」逐字母看就是：对每个字母 $c$，$\text{cnt}_b(c) \le \text{cnt}_a(c)$。

于是「`words2` 中每个 $b$ 都是 $a$ 的子集」等价于：对每个字母 $c$，

$$\max_{b \in words2} \text{cnt}_b(c) \le \text{cnt}_a(c).$$

定义需求向量

$$\text{need}(c) = \max_{b \in words2} \text{cnt}_b(c),$$

那么 $a$ 是通用单词 $\iff$ $a$ 的频次向量逐字母不小于 `need`。

**关键点：合并用 $\max$ 而不是求和。** 因为不同 $b$ 的要求是「各自都要满足」，只要 $a$ 满足其中最严的那个，就同时满足了全部；求和会把要求叠加成不必要的强条件（例如 `["c","cc"]` 的需求是 2 个 c，而不是 3 个）。

这样只需对 `words1` 每个词做一次 $O(26)$ 的检查，总复杂度降到与总字符数线性相关。

### 3.3 算法流程

![合并需求 + 逐词校验](images/wc104_q3_algorithm_flow.svg)

```text
1. need[26] = {0}
2. for b in words2:
3.     cur[26] = {0}
4.     for ch in b:  cur[ch] += 1
5.     for c in 0..25:  need[c] = max(need[c], cur[c])
6. ans = []
7. for a in words1:
8.     have[26] = {0}
9.     for ch in a:  have[ch] += 1
10.    若 ∀c: have[c] >= need[c]:  ans 追加 a
11. 返回 ans
```

## 4. 算法细节

1. **需求合并用 $\max$**：`need[c] = max(need[c], cur[c])`。这是本题最核心的一行，写成 `+=` 就错了。
2. **计数数组用定长 26**：字母表只有小写字母，`int[26]` 比哈希表快且无哈希开销；每处理一个单词清零即可（或每次新建，单词长度 ≤ 10，开销可忽略）。
3. **逐字母比较可以用「减法归零」优化**：先 `have` 计数，再对 `a` 中出现的字母递减需求计数，若最终 `need` 全零则通过。但那样会污染全局需求，需要备份，反而不如直接比较清晰。
4. **`words1` 结果顺序**：题目允许任意顺序，按原顺序追加即可，不要额外排序。
5. **`a` 可以包含 `need` 之外的字母**：只要求「不少于」，多出来的字母不影响通用性。
6. **复杂度中的 26**：$26 \times (|words1| + |words2|)$ 约为 $5\times 10^5$，加上字符扫描的总长度（$\le 2\times 10^5$），总体毫秒级。

## 5. 正确性证明

**引理 1（子集的频次刻画）**：对字符串 $a, b$，$b$ 是 $a$ 的子集 $\iff$ 对每个字母 $c$ 有 $\text{cnt}_b(c) \le \text{cnt}_a(c)$。

**证明**：

*（⇒）* 若 $b$ 是 $a$ 的子集，则可以把 $b$ 的每个字符与 $a$ 中一个**不同位置**的相同字符配对（这正是「计入重复次数的子集」的含义）。于是字母 $c$ 在 $b$ 中出现几次，就至少需要 $a$ 中 $c$ 出现同样多次，即 $\text{cnt}_b(c) \le \text{cnt}_a(c)$。

*（⇐）* 若对所有 $c$ 有 $\text{cnt}_b(c) \le \text{cnt}_a(c)$，则按字母逐个匹配：$b$ 中每个 $c$ 都能在 $a$ 中找到尚未使用的 $c$（因为 $a$ 中 $c$ 的个数不少于 $b$ 中的），匹配是单射，故 $b$ 是 $a$ 的子集。∎

**引理 2（需求向量的充分必要性）**：$a$ 是通用单词 $\iff$ 对每个字母 $c$ 有 $\text{need}(c) \le \text{cnt}_a(c)$，其中 $\text{need}(c) = \max_{b \in words2}\text{cnt}_b(c)$。

**证明**：

*（⇒）* 若 $a$ 通用，则每个 $b$ 都是 $a$ 的子集，由引理 1 得 $\text{cnt}_b(c) \le \text{cnt}_a(c)$ 对所有 $b$ 成立，取最大值即得 $\text{need}(c) \le \text{cnt}_a(c)$。

*（⇐）* 若 $\text{need}(c) \le \text{cnt}_a(c)$，则对任意 $b \in words2$ 与任意 $c$，有 $\text{cnt}_b(c) \le \text{need}(c) \le \text{cnt}_a(c)$，由引理 1 得 $b$ 是 $a$ 的子集；$b$ 任意，故 $a$ 通用。∎

**引理 3（合并过程正确）**：第 2–5 行的循环结束时，`need[c]` 等于 $\max_{b}\text{cnt}_b(c)$。

**证明**：初始全零（空集合的最大值约定为 0，而任何频次都 $\ge 0$，等价）。每轮把一个新词的频次并入，取 $\max$，由归纳即得。∎

**定理**：算法输出恰好是 `words1` 中所有通用单词。

**证明**：由引理 3，第 7–10 行使用的 `need` 是真实需求向量；由引理 2，判定条件与「通用」等价。因此算法对每个 $a$ 的判断都正确，收集的正是全部通用单词，且 `words1` 中字符串互不相同，不会重复。∎

## 6. 复杂度分析

- **时间**：$O\bigl(26 \cdot (|words1| + |words2|) + L\bigr)$，其中 $L$ 是两个数组所有字符的总数（$\le 2\times 10^5$）。合并需求时每个词扫 26 个字母，校验时同理；$ |words1|, |words2| \le 10^4$，故约 $5\times 10^5$ 次操作。
- **空间**：$O(26)$ 的常数空间（两个计数数组），外加输出数组；与输入规模无关（不计输出）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> wordSubsets(vector<string>& words1, vector<string>& words2) {
        int need[26] = {0};
        for (const string& b : words2) {
            int cur[26] = {0};
            for (char ch : b) cur[ch - 'a']++;
            for (int c = 0; c < 26; c++) need[c] = max(need[c], cur[c]);
        }

        vector<string> ans;
        for (const string& a : words1) {
            int have[26] = {0};
            for (char ch : a) have[ch - 'a']++;
            bool ok = true;
            for (int c = 0; c < 26; c++) {
                if (have[c] < need[c]) { ok = false; break; }
            }
            if (ok) ans.push_back(a);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def wordSubsets(self, words1: list[str], words2: list[str]) -> list[str]:
        need = [0] * 26
        for b in words2:
            cur = [0] * 26
            for ch in b:
                cur[ord(ch) - 97] += 1
            for c in range(26):
                if cur[c] > need[c]:
                    need[c] = cur[c]

        ans = []
        for a in words1:
            have = [0] * 26
            for ch in a:
                have[ord(ch) - 97] += 1
            if all(have[c] >= need[c] for c in range(26)):
                ans.append(a)
        return ans
```

## 8. 边界情况与易错点

1. **合并用 $\max$ 而不是求和**：`["c","cc"]` 只需 2 个 c。求和会得到 3 个 c，示例 3 就会判错。
2. **重复字母必须计数**：`"cc"` 要求 $a$ 至少有两个 c；只判「是否出现」会漏掉 `"acaac"` 这种只有 2 个 c 却仍满足 `"cc"` 的情形——注意它恰恰是因为缺 b 才被淘汰，若改成 `["c","cc"]` 它就应当通过。
3. **只比较 26 个字母**：不要遍历 `a` 的字符去查需求，那样会漏掉「需求里有但 $a$ 里没有」的字母；必须按字母表逐位比较。
4. **`need` 全零**：若 `words2` 里都是空串（约束保证非空，但逻辑上要成立），则所有词都通用。
5. **`words1` 互不相同**：无需去重；若题目不保证，则需要额外去重。
6. **返回顺序**：题目允许任意顺序，但保持原顺序最省事，也便于自测比对。
7. **大小写/非字母字符**：约束只有小写字母，`ord(ch)-97` 安全；若有其他字符需要额外处理。
