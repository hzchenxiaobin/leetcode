# LeetCode 分割数组 题解

## 1. 题目概述

- **标题 / 题号**：分割数组（#915，medium）
- **链接**：https://leetcode.cn/problems/partition-array-into-disjoint-intervals/
- **来源**：LeetCode 第 104 场周赛 Q2
- **难度**：中等
- **标签**：数组

**题意**：把数组 `nums` 切成两个**非空连续**子数组 `left`（前缀）与 `right`（后缀），要求 `left` 中每个元素都**小于或等于** `right` 中每个元素。在所有合法切法中，取 `left` **长度最小**的那个，返回其长度。题目保证至少存在一种合法切法。

**约束**：

- $2 \le nums.length \le 10^5$
- $0 \le nums[i] \le 10^6$
- 保证至少存在一种合法划分

## 2. 示例

**示例 1**

```text
输入：nums = [5,0,3,8,6]
输出：3
解释：left = [5,0,3]，right = [8,6]；max(left)=5 ≤ min(right)=6。
      若取 left=[5,0]，则 max=5 > min(3,8,6)=3，不合法。
```

**示例 2**

```text
输入：nums = [1,1,1,0,6,12]
输出：4
解释：left = [1,1,1,0]，right = [6,12]；前面的 0 太靠后，left 必须包含它。
```

**示例 3（自造，切在最后一位之前）**

```text
输入：nums = [1,2]
输出：1
解释：left=[1]，right=[2]，1 ≤ 2。
```

**示例 4（自造，「先非法后合法」）**

```text
输入：nums = [2,1,3]
输出：2
解释：i=0 时 max(2)=2 > min(1,3)=1，不合法；i=1 时 max(2,1)=2 ≤ min(3)=3，合法。
      合法位置不单调，必须顺序扫描。
```

## 3. 解题思路

### 3.1 暴力思路

枚举切点 $i$（`left = nums[0..i]`），每次重新扫一遍求 `max(left)` 与 `min(right)`：$O(n^2)$。$n = 10^5$ 时约 $5\times 10^9$ 次比较，必然超时。

瓶颈在于「每次切点变化都要重算两边的极值」。而切点右移一格时，`left` 只多一个元素、`right` 只少一个元素，极值可以**增量维护**——但 `left` 的最大值可以增量维护，`right` 的最小值在「删掉一个元素」时却不好维护。于是换个方向：**从右往左预处理** `right` 的所有后缀最小值。

### 3.2 核心观察：判据是「左边最大 ≤ 右边最小」

![前缀最大 ≤ 后缀最小 ⇒ 可以在这里切开](images/wc104_q2_prefix_suffix_concept.svg)

记

$$\text{prefMax}(i) = \max(nums[0..i]), \qquad \text{sufMin}(i) = \min(nums[i..n-1]).$$

则切在 $i$ 与 $i+1$ 之间（即 `left = nums[0..i]`）合法的充要条件是

$$\text{prefMax}(i) \le \text{sufMin}(i+1).$$

**为什么？** 「`left` 中每个元素 ≤ `right` 中每个元素」等价于「`left` 的最大值 ≤ `right` 的最小值」——这是「所有对」条件化为「一对极值」的标准转化。

`sufMin` 可以一遍从右往左预处理；`prefMax` 在从左往右扫描时增量更新。于是判定一个切点是 $O(1)$，整体 $O(n)$。

**注意合法位置并不单调**：示例 4 中 $i=1$ 非法而 $i=2$ 合法，所以不能二分，必须**从左到右找第一个**合法位置——第一个合法的就是 `left` 最短的。

### 3.3 算法流程

![两遍预处理 + 一遍扫描](images/wc104_q2_algorithm_flow.svg)

```text
1. sufMin[n-1] = nums[n-1]
2. for i = n-2 .. 0:  sufMin[i] = min(nums[i], sufMin[i+1])
3. prefMax = nums[0]
4. for i = 0 .. n-2:
5.     prefMax = max(prefMax, nums[i])
6.     若 prefMax <= sufMin[i+1]: 返回 i+1
7. 返回 n                      # 题面保证有解，这行不会执行
```

循环上界是 $n-2$：`right` 必须非空，切点最靠右只能到 $n-2$（`left` 长度 $n-1$）。

### 3.4 示例演算

![示例演算：nums = [5,0,3,8,6] → 3](images/wc104_q2_walkthrough.svg)

对 `nums = [5,0,3,8,6]`：

| $i$ | `nums[i]` | `prefMax(i)` | `sufMin(i+1)` | 判定 |
|-----|-----------|--------------|----------------|------|
| 0 | 5 | 5 | 0 | $5 \le 0$ ✗ |
| 1 | 0 | 5 | 3 | $5 \le 3$ ✗ |
| 2 | 3 | 5 | 6 | $5 \le 6$ ✓ |

第一个合法位置是 $i = 2$，故返回 $i+1 = 3$，`left = [5,0,3]`、`right = [8,6]`。

## 4. 算法细节

1. **后缀最小值从右往左算**：`sufMin[i] = min(nums[i], sufMin[i+1])`，起点是最后一位。
2. **前缀最大值边扫边算**：`prefMax = max(prefMax, nums[i])`，注意要先并入 `nums[i]` 再判定，否则会漏掉当前元素。
3. **循环范围 `0 .. n-2`**：`right` 非空是硬约束；`i = n-1` 时 `sufMin[n]` 不存在，会越界。
4. **返回第一个而不是最小的 `prefMax`**：题目要求 `left` 长度最小，而切点从左往右第一个合法的就对应最短的 `left`；不能改成「找 `prefMax` 最小的切点」。
5. **`n = 2`**：`sufMin[1] = nums[1]`，循环只跑 $i = 0$，返回 1。
6. **返回值是长度而非下标**：切在 $i$ 与 $i+1$ 之间时 `left` 长度是 $i+1$。
7. **不变量**：扫描到 $i$ 时 `prefMax == max(nums[0..i])`、`sufMin[i+1] == min(nums[i+1..n-1])`，这正是判据需要的两个量。

## 5. 正确性证明

**引理 1（判据等价）**：切分为 `left = nums[0..i]`、`right = nums[i+1..n-1]` 合法 $\iff$ $\text{prefMax}(i) \le \text{sufMin}(i+1)$。

**证明**：

*（⇒）* 设切分合法，即 $\forall p \le i < q$ 有 $nums[p] \le nums[q]$。取 $p^*$ 使 $nums[p^*] = \text{prefMax}(i)$、$q^*$ 使 $nums[q^*] = \text{sufMin}(i+1)$，则 $p^* \le i < q^*$，故 $\text{prefMax}(i) = nums[p^*] \le nums[q^*] = \text{sufMin}(i+1)$。

*（⇐）* 设 $\text{prefMax}(i) \le \text{sufMin}(i+1)$。对任意 $p \le i < q$，有 $nums[p] \le \text{prefMax}(i) \le \text{sufMin}(i+1) \le nums[q]$，故切分合法。∎

**引理 2（扫描正确性）**：第 4–6 行的循环在第 $i$ 轮时，`prefMax` 恰为 $\text{prefMax}(i)$，且 `sufMin[i+1]` 由第 1–2 行正确预处理。

**证明**：预处理部分按 $i$ 从 $n-1$ 递减归纳，`sufMin[i] = min(nums[i], sufMin[i+1])` 正是后缀最小值的递归定义。前缀最大值部分：初始 `prefMax = nums[0] = prefMax(0)`；每轮先执行 `prefMax = max(prefMax, nums[i])`，由归纳假设与定义得 `prefMax = max(nums[0..i]) = prefMax(i)`。∎

**定理**：算法返回值等于所有合法切法中 `left` 的最小长度。

**证明**：设合法切点的集合为 $S = \{i : \text{prefMax}(i) \le \text{sufMin}(i+1),\ 0 \le i \le n-2\}$，由题面保证 $S \ne \emptyset$。由引理 2，循环按 $i$ 递增顺序逐一判定，且判据等价于 $i \in S$（引理 1），故返回的是 $S$ 中的最小元素 $i_{\min}$，返回值为 $i_{\min} + 1$。

`left` 长度与切点一一对应（切在 $i$ 之后 $\iff$ 长度 $i+1$），且长度随切点单调递增，因此 $i_{\min}$ 对应最短的 `left`。故返回值就是最小合法长度。∎

## 6. 复杂度分析

- **时间**：$O(n)$。预处理后缀最小一遍 $O(n)$；扫描前缀最大一遍 $O(n)$，每轮 $O(1)$。总计 $O(n)$，$n = 10^5$ 时约 $2\times 10^5$ 次操作。
- **空间**：$O(n)$。`sufMin` 数组长度 $n$；其余是常数个变量。（若想省空间，可把 `sufMin` 换成「从右往左记录、再从左往右消耗」的一个数组，空间无法降到 $O(1)$，因为前缀最大与后缀最小需要同时可用。）

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int partitionDisjoint(vector<int>& nums) {
        int n = (int)nums.size();
        vector<int> sufMin(n);
        sufMin[n - 1] = nums[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            sufMin[i] = min(nums[i], sufMin[i + 1]);
        }
        int prefMax = nums[0];
        for (int i = 0; i + 1 < n; i++) {
            prefMax = max(prefMax, nums[i]);
            if (prefMax <= sufMin[i + 1]) return i + 1;
        }
        return n;   // 题面保证有解，不会走到这里
    }
};
```

### Python

```python
class Solution:
    def partitionDisjoint(self, nums: list[int]) -> int:
        n = len(nums)
        suf_min = [0] * n
        suf_min[-1] = nums[-1]
        for i in range(n - 2, -1, -1):
            suf_min[i] = min(nums[i], suf_min[i + 1])

        pref_max = nums[0]
        for i in range(n - 1):
            pref_max = max(pref_max, nums[i])
            if pref_max <= suf_min[i + 1]:
                return i + 1
        return n   # 题面保证有解
```

## 8. 边界情况与易错点

1. **先并入再判定**：`prefMax` 必须包含 `nums[i]` 本身，否则 $i=0$ 时会用未定义的「空前缀最大值」。
2. **循环到 $n-2$ 为止**：`right` 必须非空，`sufMin[n]` 越界。
3. **返回下标还是长度**：切在 $i$ 之后，`left` 长度是 $i+1$；返回 $i$ 会整体少 1。
4. **合法位置不单调**：示例 4 说明「先非法后合法」是可能的，因此必须顺序扫描找第一个，不能二分。
5. **不要找「`prefMax` 最小的切点」**：题目要求 `left` 最短，两者不是一回事（`prefMax` 最小的位置可能更靠右）。
6. **`n = 2`**：直接返回 1，注意预处理数组不越界。
7. **全部元素相等**：如 `[1,1]`，$i=0$ 时 $1 \le 1$ 成立，返回 1。
8. **重复值不破坏判据**：题目要求「小于或等于」，等号成立即合法；若改成「严格小于」，判据要换成 `<`。
