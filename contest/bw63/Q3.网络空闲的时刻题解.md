# LeetCode 网络空闲的时刻 题解

## 1. 题目概述

- **标题 / 题号**：网络空闲的时刻（#2039，medium）
- **链接**：https://leetcode.cn/problems/the-time-when-the-network-becomes-idle/
- **来源**：LeetCode 第 63 场双周赛 Q3
- **难度**：中等
- **标签**：广度优先搜索、图、数组

**题意**：$n$ 台服务器组成的无向连通网络中，0 号是**主服务器**，其余是**数据服务器**。每条线路 1 秒可传任意多条信息。0 秒开始时每台数据服务器都向主服务器发一条信息；从第 1 秒开始，每秒最开始，各数据服务器检查是否收到过任何回复：

- 若尚未收到任何回复，且距离上次发送已过 $patience[i]$ 秒，则重发一条信息（周期重发）；
- 收到过回复后，永不再重发。

信息总是沿**最少时间**（最短路）到达主服务器，主服务器收到后立刻沿原路返回回复。当网络上不再有任何信息在传输或到达时，网络**空闲**。求网络变空闲的最早秒数。

**约束**：

- $2 \le n \le 10^5$，$patience[0] = 0$，$1 \le patience[i] \le 10^5$（$i \ge 1$）
- $1 \le edges.length \le \min(10^5, \tfrac{n(n-1)}{2})$，无重边、无自环、保证连通

## 2. 示例

**示例 1**

```text
输入：edges = [[0,1],[1,2]], patience = [0,2,1]
输出：8
解释：链 0—1—2。dist[1] = 1，dist[2] = 2。
服务器 1：p=2 ≥ 2d=2，只在 0 秒发一条，回复 2 秒到达。
服务器 2：p=1 < 2d=4，在 0,1,2,3 秒各发一条（4 秒时首条回复已到，停止重发），
最后一条在 3 秒发出，回复 3+4=7 秒到达。
最后一个事件是第 7 秒，故第 8 秒起网络空闲，返回 8。
```

**示例 2**

```text
输入：edges = [[0,1],[0,2],[1,2]], patience = [0,10,10]
输出：3
解释：三角形网络，dist[1] = dist[2] = 1，往返 2 秒。
p=10 ≥ 2d=2，两台服务器都只发初始一条信息，回复在第 2 秒到达；
第 3 秒起网络空闲。
```

## 3. 解题思路

### 3.1 暴力思路

逐秒离散事件模拟：维护每台服务器的"在途信息集合"（各自回复的到达时刻）、"是否收到回复"、"上次发送时刻"，每一秒先处理到达事件、再处理重发判定，直到没有任何在途信息。模拟本身是正确的（本文对拍就用了它），但最坏情形下重发次数可达 $\sum_i \lceil 2d_i / p_i \rceil$：链状网络上 $d_i = i$、$p_i = 1$ 时约 $\sum 2i \approx n^2 = 10^{10}$ 次事件，**无法承受**。必须发现"事件全部可由公式预先算出"。

### 3.2 核心观察：每台服务器的行为只取决于 $dist[i]$ 与 $patience[i]$

![核心观察：BFS 分层求最短路，每台数据服务器独立推导](images/bw63_q3_bfs_layers.svg)

三个观察把问题化归为逐点公式：

1. **最短路决定传输时间**：信息按最少时间传输，即沿最短路走。设 $dist[i]$ 为 $i$ 到 0 的边数（BFS 一遍可得），则 $i$ 在 $t$ 秒发出的信息 $t + dist[i]$ 秒到主服务器，回复 $t + 2\,dist[i]$ 秒回到 $i$。
2. **服务器之间互不影响**：线路容量无限（每秒可传任意多条信息），各数据服务器的收发时间线彼此独立，可以逐台单独分析后取全局最大值。
3. **重发在首个回复到达前一刻截止**：$i$ 的首个回复在 $2\,dist[i]$ 秒到达且当秒生效（到达先于重发判定，见示例 1 的"4 秒时回复 2A 到达、不再重发"），故重发只发生在严格早于 $2\,dist[i]$ 的时刻。

于是 $i$ 的发送时刻恰为 $\{0, p, 2p, \dots\}$ 中所有 $< 2d$ 的时刻，其中 $p = patience[i], d = dist[i]$。

### 3.3 算法流程与关键公式

![消息时间线：重发时刻与最后一条回复的到达](images/bw63_q3_timeline.svg)

对每台数据服务器 $i$（$d = dist[i] \ge 1$，$p = patience[i] \ge 1$）：

- **最后一次发送时刻**：$p$ 的倍数中小于 $2d$ 的最大者，
  $$last = \left\lfloor \frac{2d - 1}{p} \right\rfloor \cdot p$$
  （若 $p \ge 2d$，则该值为 $0$，即只发初始那条）。分子取 $2d - 1$ 是因为时刻 $2d$ 的重发判定发生在收到回复**之后**，被"截断"。
- **最后一条回复到达时刻**：$last + 2d$（发送后往返 $2d$ 秒）。

全局答案：

$$ans = \max_{i \ge 1}\left( last_i + 2\,dist[i] \right) + 1$$

整体流程：

```text
1. 建邻接表，从 0 出发 BFS 求 dist[i]
2. 对每个 i ≥ 1：last = (2·dist[i] − 1) / patience[i] · patience[i]（整除）
   ans = max(ans, last + 2·dist[i])
3. 返回 ans + 1
```

### 3.4 示例演算（示例 1：链 0—1—2，patience = [0,2,1]）

| 服务器 | $d$ | $2d$ | $p$ | 重发时刻（$< 2d$） | $last$ | 最后回复到达 $last+2d$ |
|--------|-----|------|-----|--------------------|--------|------------------------|
| 1 | 1 | 2 | 2 | 无（$p \ge 2d$） | 0 | 2 |
| 2 | 2 | 4 | 1 | 0, 1, 2, 3 | 3 | 7 |

$\max = 7$，答案 $7 + 1 = 8$。与官方解释"7 秒时回复 2D 到达、从第 8 秒起空闲"完全一致。其中 2D 正是 3 秒发出的最后一条重发信息（$3 + 4 = 7$）。

## 4. 算法细节

1. **BFS 而非 DFS/Dijkstra**：边权全为 1，BFS 求单源最短路 $O(n + m)$，Dijkstra 是多余的。
2. **整除截断的写法**：$\lfloor (2d-1)/p \rfloor \cdot p$ 就是"严格小于 $2d$ 的最大 $p$ 倍数"。若误写成 $\lfloor 2d/p \rfloor \cdot p$，当 $p \mid 2d$ 时会多算一次已被截断的重发（如 $d=1, p=2$ 会误得 $last=2$、答案 $+2$）。C++ 与 Python 的整除对非负数行为一致，直接 `/` 即可。
3. **到达优先于重发**：模拟与公式都遵循"同一秒先结算回复到达、再做重发判定"。这是示例 1 明确给出的语义（4 秒时回复已到故不重发）。
4. **为什么逐台取最大就够**：所有事件（发送、到达）都是确定性时刻，网络空闲时刻 = 所有信息到达时刻的最大值 + 1；而每台的最后一个到达事件就是 $last_i + 2d_i$，其余事件均更早。
5. **溢出**：$d \le n - 1 < 10^5$，$2d < 2 \times 10^5$，$last + 2d < 4 \times 10^5$，`int` 足够；用 `long long` 也不是负担。
6. **邻接表必须用 O(n+m) 构建**：$m \le 10^5$，`vector<vector<int>>` 足够；不要用矩阵（$10^{10}$ 空间爆炸）。
7. **patience[0] = 0 不可用于公式**：主服务器不发送，循环从 $i = 1$ 开始，天然跳过。

## 5. 正确性证明

**引理 1（传输时刻）**：数据服务器 $i$ 在 $t$ 秒发出的信息，恰在 $t + dist[i]$ 秒到达主服务器，其回复恰在 $t + 2\,dist[i]$ 秒回到 $i$。

**证明**：信息总沿最少时间路线传输， hops 数即最短路边数 $dist[i]$（每条线路耗时 1 秒，转发无额外延迟）；主服务器收到后**立即**按原路反向回复，再耗 $dist[i]$ 秒。故到达 $i$ 的时刻为 $t + dist[i] + dist[i] = t + 2\,dist[i]$。∎

**引理 2（发送时刻集合）**：数据服务器 $i$（$d = dist[i] \ge 1$，$p = patience[i]$）的全部发送时刻恰为 $\{0, p, 2p, \dots, last\}$，其中 $last = \lfloor (2d-1)/p \rfloor \cdot p$；即 $p$ 的非负倍数中严格小于 $2d$ 的全体。

**证明**：对 $t \ge 1$ 归纳。服务器只在"尚未收到任何回复"时重发，且重发条件为 $t - \text{lastsend} = p$。初始发送在 $0$ 秒，$\text{lastsend}$ 初始为 $0$。由引理 1，首个回复（对初始信息的回复）在 $2d$ 秒到达，且到达事件在当秒的重发判定之前结算，故对一切 $t \le 2d$：$t$ 秒的重发判定在"未收到回复"状态下进行当且仅当 $t < 2d$（$t = 2d$ 时回复已到）。而未收到回复期间 $\text{lastsend}$ 每次更新后恰再过 $p$ 秒触发重发，发送时刻保持为 $p$ 的连续倍数：$0, p, 2p, \dots$。设在 $t = kp < 2d$ 处发送，若 $(k+1)p < 2d$ 则 $(k+1)p$ 秒再发，若 $(k+1)p \ge 2d$ 则在 $(k+1)p$ 秒的判定前（当 $(k+1)p = 2d$）或判定时（当 $(k+1)p > 2d$ 时 $t=2d$ 已过、状态为已收到回复）不再发送。因此最后一个发送时刻是 $p$ 的倍数中严格小于 $2d$ 的最大者，即 $\lfloor (2d-1)/p \rfloor \cdot p$（$2d-1$ 是严格小于 $2d$ 的最大整数，除以 $p$ 下取整再乘回即为所求最大倍数）。$t \ge 2d$ 后服务器已收到回复，永久停止发送。∎

**定理（答案公式）**：网络空闲的最早秒数为 $\displaystyle \max_{i \ge 1}\left( last_i + 2\,dist[i] \right) + 1$。

**证明**：网络空闲 ⇔ 不再有信息在传输或到达 ⇔ 所有"信息到达某服务器"事件的时刻均小于当前秒。由引理 1，$i$ 的第 $s$ 次发送（时刻 $t_s = sp \le last$）对应回复到达时刻 $t_s + 2d$，该序列关于 $s$ 严格递增，故 $i$ 的最后一个事件时刻为 $last + 2d$。所有服务器的事件互不干扰（线路容量无限、处理即时），全局最后事件时刻为 $T = \max_i (last_i + 2d_i)$。于是第 $T$ 秒仍有事件发生（最后的回复到达），第 $T+1$ 秒起再无任何事件，网络自第 $T + 1$ 秒起空闲，答案为 $T + 1$。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。建邻接表与 BFS 各 $O(n + m)$，逐台公式计算 $O(n)$；相比逐事件模拟的 $O(\sum_i \lceil 2d_i/p_i \rceil)$ 最坏 $O(n^2)$，是本质性优化。
- **空间**：$O(n + m)$。邻接表 $O(n + m)$，`dist` 数组 $O(n)$，BFS 队列 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int networkBecomesIdle(vector<vector<int>>& edges, vector<int>& patience) {
        int n = (int)patience.size();
        vector<vector<int>> g(n);
        for (auto& e : edges) { g[e[0]].push_back(e[1]); g[e[1]].push_back(e[0]); }
        vector<int> dist(n, -1);
        queue<int> q;
        dist[0] = 0; q.push(0);
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (int v : g[u])
                if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }
        }
        long long ans = 0;
        for (int i = 1; i < n; ++i) {
            long long d = dist[i], p = patience[i];
            long long last = (2 * d - 1) / p * p;   // 最后一次重发时刻（严格早于 2d）
            ans = max(ans, last + 2 * d);           // 该消息的回复到达时刻
        }
        return (int)(ans + 1);
    }
};
```

### Python

```python
class Solution:
    def networkBecomesIdle(self, edges: List[List[int]], patience: List[int]) -> int:
        n = len(patience)
        g = [[] for _ in range(n)]
        for u, v in edges:
            g[u].append(v)
            g[v].append(u)
        dist = [-1] * n
        dist[0] = 0
        q = deque([0])
        while q:
            u = q.popleft()
            for v in g[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)
        ans = 0
        for i in range(1, n):
            d, p = dist[i], patience[i]
            last = (2 * d - 1) // p * p          # 最后一次重发时刻（严格早于 2d）
            ans = max(ans, last + 2 * d)         # 该消息的回复到达时刻
        return ans + 1
```

> 💡 两份代码均通过官方 2 组示例，并与"逐秒离散事件模拟"（先结算到达、再判重发）的暴力实现做了 300 组随机对拍（$n \le 8$、随机连通图、$p \le 6$，覆盖 $p \mid 2d$、$p \ge 2d$ 等临界情形），结果完全一致；另在 $n = 10^5$ 链状网络上验证运行时间（C++ 0.15s / Python 0.29s）。

## 8. 边界情况与易错点

1. **整除边界 $p \mid 2d$**：此刻 $2d$ 恰是重发周期点，但回复先到、不重发。公式必须用 $(2d-1)/p$ 而非 $2d/p$ 下取整，否则多算一次重发、答案偏大。这是本题最高频的 WA 点。
2. **$p \ge 2d$（含 $p \ge 2d$ 且整除）**：$\lfloor (2d-1)/p \rfloor = 0$，$last = 0$，服务器只发初始信息，公式自然覆盖，无需特判。
3. **"到达先于重发"的语义**：示例 1 明确 4 秒时回复到达后不再重发。若先判重发后结算到达，$p \mid 2d$ 的情形全会算错。自建对拍时务必按正确顺序模拟。
4. **答案要 $+1$**：最后事件发生在第 $T$ 秒，网络从第 $T+1$ 秒起才空闲。漏加 1 是第二大高频错误。
5. **从 $i = 1$ 开始**：主服务器不发送，`patience[0] = 0` 不能进公式（除零风险之外语义也不对）。
6. **图必须连通**：题目保证；若自行改编数据（如做对拍生成器），要显式构造连通图（先造生成树再加边）。
7. **最短路必须按边数**：信息"以最少时间到达"，等价于最少边数（边权都是 1 秒）；不要误用 DFS 的任意路径。
8. **溢出评估**：$ans < 4 \times 10^5 + 1$，`int` 安全；中间量用 `long long` 只是保险。
