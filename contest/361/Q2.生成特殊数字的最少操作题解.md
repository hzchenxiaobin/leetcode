# LeetCode 生成特殊数字的最少操作 题解

## 1. 题目概述

- **标题 / 题号**：生成特殊数字的最少操作（#2844，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-a-special-number/
- **来源**：LeetCode 第 361 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数学、字符串、枚举

**题意**：给定表示非负整数的字符串 `num`，一次操作可以删除其中任意一位数字（若删光所有数字，`num` 变为 0）。求最少删除多少位，能使剩下的数是「特殊数字」——即能被 $25$ 整除的数。

**约束**：

- `1 <= num.length <= 100`
- `num` 仅由数字 `'0'` ~ `'9'` 组成，且不含前导零

## 2. 示例

**示例 1**

```text
输入：num = "2245047"
输出：2
解释：删除 num[5] 和 num[6]，得到 "22450"，能被 25 整除。
```

**示例 2**

```text
输入：num = "2908305"
输出：3
解释：删除 num[3]、num[4] 和 num[6]，得到 "2900"，能被 25 整除。
```

**示例 3**

```text
输入：num = "10"
输出：1
解释：删除 num[0]，得到 "0"，0 能被 25 整除。
```

## 3. 解题思路

### 3.1 暴力思路

「删哪几位」的组合有 $2^n$ 种，$n \le 100$ 时不可行。正面枚举删除集合走不通，不妨反过来想：**留下来的数必须长什么样**？「被 $25$ 整除」是一个只关于末尾的局部性质，把它刻画清楚，最优删除方案就自然浮现了。

### 3.2 核心观察：被 25 整除 ⇔ 只看末两位

![被 25 整除的数末两位只能是 00/25/50/75，加上值为 0 的两种形态](images/special_number_endings.svg)

由 $100 \equiv 0 \pmod{25}$，任何数按位拆开都能写成 $x = 100q + r$（$r$ 为末两位数值），于是 $x \equiv r \pmod{25}$。而 $0 \le r \le 99$ 中 $25$ 的倍数只有 $0, 25, 50, 75$，故目标形态一共 6 类：

1. **长度 ≥ 2 的结果**：能被 $25$ 整除 ⇔ 末两位是 `00` / `25` / `50` / `75` 之一；
2. **长度为 1 的结果**：只有 `"0"` 能被 $25$ 整除；
3. **空串**：按题意值为 $0$，也能被 $25$ 整除。

> 💡 删除只减少数字，不改变「整除性只看末尾」这一结构。问题由「删哪些」转化为：**对这 6 类目标形态分别求最少删除次数，取最小**。

删除后出现前导零完全无妨（如 `"100"` 保留 `"00"`）：整除性看的是数值，而数值的整除性由末两位决定，与书写形式无关。

### 3.3 算法流程：右对齐贪心

![右对齐贪心：先锁最右的末位字符，再向左找首位字符](images/special_number_right_scan.svg)

对结尾 `ab`（如 `"50"`），要让结果以 `ab` 结尾，必须保留某处的 `a`（位置 $i$）及其右侧某处的 `b`（位置 $j$，$i < j$），且 $j$ 之后、$i$ 与 $j$ 之间的数字全部删除，$i$ 之前的**前缀全部保留**（保留不影响结尾，删除反而多花代价）。此时：

$$\text{代价} = \underbrace{(n-1-j)}_{j\ \text{之后}} + \underbrace{(j-i-1)}_{i,j\ \text{之间}} = n - i - 2$$

代价**只依赖 $i$**（与选哪个 $j$ 无关），所以贪心方向是让 `a` 尽量靠右：

```text
ans = n                              # 兜底：全删 → 0
for ab in {"00", "25", "50", "75"}:
    j = num 中最右的 b
    if j 不存在 or j == 0: continue  # 左侧放不下 a
    i = j 左侧最右的 a
    if i 不存在: continue
    ans = min(ans, n - 2 - i)        # 以 ab 结尾的代价
if num 含 '0':
    ans = min(ans, n - 1)            # 只留一个 '0' → 0
return ans
```

### 3.4 示例演算

![三个示例的保留/删除方案走查](images/special_number_walkthrough.svg)

| num | 最优目标 | 保留 | 删除 | 结果 | 答案 |
|------|------|------|------|------|------|
| `"2245047"` | 结尾 `50`（$i=3, j=4$） | `224` + `5` + `0` | 下标 5、6 | `22450` | 2 |
| `"2908305"` | 结尾 `00`（$i=2, j=5$） | `29` + `0` + `0` | 下标 3、4、6 | `2900` | 3 |
| `"10"` | 单个 `0` | `0` | 下标 0 | `0` | 1 |
| `"912517"` | 结尾 `25`（$i=2, j=3$） | `91` + `2` + `5` | 下标 4、5 | `9125` | 2 |
| `"111"` | 全删 | —（空串） | 全部 | `0` | 3 |

注意 `"912517"` 一行：前缀 `91` 原样保留即可，**不必**把结果删成裸的 `"25"`——这正是代价公式 $n-2-i$ 允许前缀存在的体现。

## 4. 算法细节

1. **右端对齐的两次 `rfind`**：先取 $j^* = $ `rfind(b)`（`b` 的最右出现），再取 $i^* = $ `rfind(a, 0, j*)`（$j^*$ 左侧 `a` 的最右出现）。这样得到的 $i^*$ 恰是「右侧还有 `b`」的 `a` 中最靠右的一个（引理 3），代价 $n-2-i^*$ 即该结尾的最优。
2. **「单 0」与「全删」两个兜底**：`num` 含 `'0'` 时候选 $n-1$（留任意一个 `'0'`，其余全删）；任何输入都有候选 $n$（空串 = 0）。漏掉这两个候选，在 `"10"`、`"111"` 上必错。
3. **保留前缀的正确姿势**：结果 = `num[0..i-1]` + `num[i]` + `num[j]`，前缀一位都不用删；删除数只数「$j$ 之后」和「$i,j$ 之间」两段，不要重复计数。
4. **全程按字符串处理**：$n \le 100$ 意味着数值可达 $10^{100}$，任何内建整数类型都装不下；`rfind` 每次一线性扫描，总共 4~6 次扫描即可。

## 5. 正确性证明

**引理 1（被 25 整除的刻画）**：对任意数字串 $s$（允许前导零、允许为空）：
- 若 $|s| \ge 2$，记 $r$ 为 $s$ 末两位组成的两位数（$0 \le r \le 99$），则 $v(s) \equiv r \pmod{25}$；
- 若 $|s| = 1$，则 $25 \mid v(s)$ ⇔ $s = \texttt{"0"}$；
- 若 $s$ 为空，$v(s) = 0$，且 $25 \mid 0$。

**证明**：按位展开 $v(s) = \sum_k d_k 10^k = 100 \cdot \big(\sum_{k \ge 2} d_k 10^{k-2}\big) + (10 d_1 + d_0) = 100q + r$，展开式对含前导零的串同样成立。由 $25 \mid 100$ 得 $v(s) \equiv r \pmod{25}$，而 $[0, 99]$ 内 $25$ 的倍数恰为 $\{0, 25, 50, 75\}$。$|s| = 1$ 时 $v(s) \in [0, 9]$，其中仅 $0$ 是 $25$ 的倍数。∎

**引理 2（固定结尾的代价公式）**：若某删除方案的结果以 `ab` 结尾，且结果最后两位来自 `num` 的位置 $i < j$（`num[i] = a`，`num[j] = b`），则该方案至少删除 $n - i - 2$ 位；且「删除 $j$ 之后全部、$i$ 与 $j$ 之间全部、保留 $i$ 之前全部」恰用 $n-i-2$ 次删除得到以 `ab` 结尾的结果。

**证明**：结果的末两位是 `num[i]`、`num[j]`，故 $j$ 之后的 $n-1-j$ 个数字必删（否则会留在末尾）；$i$ 与 $j$ 之间的 $j-i-1$ 个数字必删（否则会夹在 `a`、`b` 之间破坏结尾）。合计至少 $n-i-2$ 位。反之按上述方案删除后，结果为 `num[0..i-1]` + `a` + `b`，长度 $i + 2 \ge 2$，以 `ab` 结尾，由引理 1 是特殊数字。∎

**引理 3（右端对齐取到最右的 i）**：设 $j^*$ 为 `b` 在 `num` 中的最右出现位置，$i^*$ 为 $j^*$ 左侧 `a` 的最右出现位置（若存在），则 $i^*$ 是所有满足「`num[i] = a` 且存在 $j > i$ 使 `num[j] = b`」的位置 $i$ 中的最大值。

**证明**：对任一这样的 $i$，取与之配对的 $j$，则 $j \le j^*$（$j^*$ 的最右性），于是 $i < j \le j^*$，即 $i$ 是 $j^*$ 左侧的 `a` 出现位置，由 $i^*$ 的定义得 $i \le i^*$。∎

**定理**：算法返回的是最少操作次数。

**证明**：*算法输出是可行解的代价*：4 个结尾候选的结果以对应 `ab` 结尾且长度 $\ge 2$，由引理 1 是特殊数字；「留一个 `'0'`」的结果为 `"0"`；「全删」的结果为空串。故输出 $\ge \mathrm{OPT}$。

*OPT 不小于算法输出*：取任一最优方案，其结果是特殊数字，由引理 1 只能属于三类之一：
- 空串：代价恰为 $n$，不低于算法初值 $n$；
- 单个 `"0"`：说明 `num` 含 `'0'`，该方案恰保留 1 位、删除 $n-1$ 位，不低于算法候选 $n-1$；
- 以某 `ab` 结尾（四种之一）：由引理 2 其代价 $\ge n-i-2$，其中 $i \le i^*$（引理 3），故代价 $\ge n-i^*-2$，不低于算法该结尾的候选。

三类代价均 $\ge$ 算法输出，故 $\mathrm{OPT} \ge$ 输出。结合两方面，输出 $= \mathrm{OPT}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每种结尾做常数次 `rfind`（各一次线性扫描），共 4 种结尾再加一次 `'0'` 存在性检查，总计不超过 6 次线性扫描；$n \le 100$ 下绰绰有余。
- **空间复杂度**：$O(1)$ 额外空间（不复制字符串，只用若干下标变量）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumOperations(string num) {
        int n = num.size();
        int ans = n;                                   // 兜底：全删 → 0
        for (string t : {"00", "25", "50", "75"}) {
            size_t j = num.rfind(t[1]);                // ① 最右的末位 b
            if (j == string::npos || j == 0) continue; // j=0 时左侧放不下 a
            size_t i = num.rfind(t[0], j - 1);         // ② j 左侧最右的首位 a
            if (i == string::npos) continue;
            ans = min(ans, n - 2 - (int)i);            // 代价 = n - 2 - i
        }
        if (num.find('0') != string::npos)             // 只留一个 '0' → 0
            ans = min(ans, n - 1);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumOperations(self, num: str) -> int:
        n = len(num)
        ans = n                                  # 兜底：全删 → 0
        for a, b in ("00", "25", "50", "75"):
            j = num.rfind(b)                     # ① 最右的末位 b
            if j <= 0:                           # 不存在，或左侧放不下 a
                continue
            i = num.rfind(a, 0, j)               # ② j 左侧最右的首位 a
            if i == -1:
                continue
            ans = min(ans, n - 2 - i)            # 代价 = n - 2 - i
        if "0" in num:                           # 只留一个 '0' → 0
            ans = min(ans, n - 1)
        return ans
```

## 8. 边界情况与易错点

1. **漏掉「只留一个 `'0'`」**：`"10"` 的答案是 1（删 `'1'` 得 `"0"`），不是 2。以为「必须凑出两位结尾」是最常见的 WA 原因；`"105"` 同理是 2 而非 3。
2. **漏掉「全删 = 0」**：`"1"`、`"111…1"` 这类既无 `'0'` 又凑不出结尾的串，答案就是 $n$（题目明说删光后 `num` 为 0）。
3. **`j == 0` 的下溢坑（C++）**：最右的 `b` 在 0 号位时左侧不可能有 `a`，必须先跳过；否则 `rfind(a, j-1)` 的 `pos` 会下溢成 `npos`，把 `b` 自己当作 `a` 匹配（例如对 `"0"` 试 `"00"` 会算出错误代价 $-1$）。
4. **前缀不必删**：`"912517"` 只删 2 位（得 `"9125"`），不要把结果限制成裸两位数 `25` 而多删。
5. **不要转整数**：`num` 长度可达 100（数值 $10^{100}$），C++ 内建类型装不下；本题全程用字符串下标处理。
6. **输入本身已经特殊**：`"25"`、`"100"`、`"0"` 都应返回 0（`"0"` 靠「含 `'0'`」候选 $n-1=0$ 命中）。
7. **删除后允许前导零**：`"100"` 保留 `"00"` 合法——判整除看数值末两位，不看书写形式。
