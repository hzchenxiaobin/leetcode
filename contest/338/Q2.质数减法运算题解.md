# LeetCode 质数减法运算 题解

## 1. 题目概述

- **标题 / 题号**：质数减法运算（#2601，medium）
- **链接**：https://leetcode.cn/problems/prime-subtraction-operation/
- **来源**：LeetCode 第 338 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、数学、二分查找、数论

**题意**：给定长度为 $n$ 的数组 `nums`。一次运算 = 选择一个**之前未选过的下标** $i$，再选一个**严格小于** `nums[i]` 的质数 $p$，令 `nums[i]` 减去 $p$。每个下标至多操作一次，因此**每个元素至多减去一个质数**（或不减）。问经过若干次运算后能否使 `nums` 变成严格递增数组。

**约束**：

- `1 <= nums.length <= 1000`
- `1 <= nums[i] <= 1000`

## 2. 示例

**示例 1**

```text
输入：nums = [4,9,6,10]
输出：true
解释：i=0 选 p=3 得 [1,9,6,10]；i=1 选 p=7 得 [1,2,6,10]，已严格递增。
```

**示例 2**

```text
输入：nums = [6,8,11,12]
输出：true
解释：数组本身已严格递增，无需任何操作。
```

**示例 3**

```text
输入：nums = [5,8,3]
输出：false
解释：任何操作都无法使数组严格递增。
```

## 3. 解题思路

### 3.1 暴力思路

先弄清每个元素能变成什么。由"每个下标至多操作一次"，第 $i$ 个元素的可达值集合为

$$S_i = \{nums[i]\} \cup \{nums[i] - p : p \text{ 为质数},\ p < nums[i]\}$$

大小不超过 $\pi(1000) + 1 = 169$。从左往右枚举每个元素的可达值做回溯，最坏 $169^{1000}$，不可行；加 $(i, prev)$ 记忆化后状态 $O(nC)$、每状态转移 $O(169)$，约 $1.7 \times 10^8$；还需对每层可达值排序后用"前缀可行标记"才能压到 $O(n \cdot 169)$。能过但绕。数据范围 $n, nums[i] \le 1000$ 明显在欢迎 $O(n + C)$ 的线性做法。

### 3.2 核心观察：每步取「大于前驱的最小可达值」

![贪心核心观察：把每个元素压到大于前驱的最小可达值](images/prime_sub_op_greedy_concept.svg)

**观察 1（可达值只有一层）**：如上，每个元素要么不减、要么恰好减一个严格小于它的质数，可达值集合 $S_i$ 是有限小集合。

**观察 2（前驱越小越有利）**：严格递增的约束是链式的——第 $i$ 个元素唯一的"历史包袱"是前一个元素的最终值 $prev$。$prev$ 越小，后面所有元素的可行空间越大。因此从左到右处理，每一步都在"大于 $prev$"的前提下把当前元素**压到能取到的最小值**。

**观察 3（最小值 = 减去最大可减质数）**：设 $x = nums[i] - prev - 1$。新值 $nums[i] - p > prev \iff p \le x$，新值越小要求 $p$ 越大，所以取**不超过 $x$ 的最大质数** $P(x)$。

> 💡 一句话：`新值 = nums[i] − P(nums[i] − prev − 1)`，把"挑哪个质数"变成一次查表。

### 3.3 算法流程

![算法流程图：预处理查表加一趟扫描](images/prime_sub_op_flow.svg)

1. **预处理**：埃氏筛出 $[2, 1000]$ 内全部质数，再前缀出 $P[x] =$ 不超过 $x$ 的最大质数（$P[0] = P[1] = 0$ 当"无质数可减"哨兵）。
2. **扫描**：`prev = 0`（处理后的元素都 $\ge 1$），从左到右处理每个元素：
   - 计算 $x = nums[i] - prev - 1$；
   - 若 $x \ge 2$：减去 $P[x]$，`prev = nums[i] − P[x]`；
   - 否则若 $nums[i] > prev$：无质数可减，保持不动，`prev = nums[i]`；
   - 否则返回 `false`。
3. 扫描完返回 `true`。

### 3.4 示例演算

![示例演算表：示例1成功与示例3失败](images/prime_sub_op_walkthrough.svg)

示例 1 `[4,9,6,10]` 的贪心过程（$x = v - prev - 1$）：

| $i$ | prev | $v$ | $x$ | $p = P(x)$ | 新值 |
|-----|------|-----|-----|------------|------|
| 0 | 0 | 4  | 3 | 3 | 1 |
| 1 | 1 | 9  | 7 | 7 | 2 |
| 2 | 2 | 6  | 3 | 3 | 3 |
| 3 | 3 | 10 | 6 | 5 | 5 |

得到 `[1,2,3,5]`，严格递增，返回 `true`（官方解释的 `[1,2,6,10]` 同样合法，贪心只是减得更多、给后面留的空间更大）。示例 3 `[5,8,3]`：前两步得 `prev = 3`；第三步 $x = 3 - 3 - 1 = -1$，既没有质数可减、不减也追不上 `prev`，返回 `false`。

## 4. 算法细节

1. **$P[x]$ 表的构建**：埃氏筛标记合数后扫一遍前缀：`x` 为质数则 `P[x] = x`，否则 `P[x] = P[x-1]`；`P[0] = P[1] = 0` 充当哨兵。
2. **prev 初始为 0**：处理后的元素至少为 1（$p < nums[i]$ 保证减完 $\ge 1$），用 0 当"虚拟前驱"使第一个元素也被尽量压小（见易错点 2）。
3. **"严格"藏在 −1 里**：$x = nums[i] - prev - 1$ 的 $-1$ 对应"新值必须 $\ge prev + 1$"。漏写会得到新值恰等于 $prev$ 的错误。
4. **$p < nums[i]$ 自动满足**：$p \le x = nums[i] - prev - 1 \le nums[i] - 1 < nums[i]$（因 $prev \ge 0$），不必额外判断。
5. **二分写法**：也可以只存有序质数表，每步在表上 `upper_bound` / `bisect` 出 $\le x$ 的最大质数——正对应官方标签里的 Binary Search；$P[x]$ 前缀表是把二分结果离线化，查询 $O(1)$ 更直接。
6. **无需回验**：每步新值 $= nums[i] - P[x] \ge prev + 1 \ge 1$，由公式结构性保证，不必再判合法性。

## 5. 正确性证明

**引理 1（单步公式）**：设 $prev \ge 0$，$x = nums[i] - prev - 1$。则 $S_i$ 中大于 $prev$ 的最小元素为：$x \ge 2$ 时 $nums[i] - P(x)$；$x \in \{0, 1\}$ 时 $nums[i]$；$x < 0$ 时不存在。

**证明**：对 $v = nums[i] - p \in S_i$，$v > prev \iff p \le nums[i] - prev - 1 = x$，且 $v$ 随 $p$ 增大而严格减小，故 $v$ 最小当且仅当 $p$ 最大。合法质数还须满足 $p < nums[i]$；由 $prev \ge 0$ 知 $x \le nums[i] - 1$，故 $p \le x$ 已蕴含 $p < nums[i]$。当 $x \ge 2$，最大合法 $p$ 即不超过 $x$ 的最大质数 $P(x)$；当 $x \in \{0,1\}$，没有质数 $\le x$，只能不操作，新值 $nums[i] = prev + 1 + x > prev$ 成立；当 $x < 0$，操作或不操作都使新值 $\le nums[i] \le prev$，不存在合法取值。∎

**引理 2（贪心支配性）**：若存在可行方案 $R = (r_0, \dots, r_{n-1})$（$r_i \in S_i$ 且严格递增），则贪心序列 $g_i = \min\{v \in S_i : v > g_{i-1}\}$（$g_{-1} = 0$）满足 $g_i \le r_i$ 对一切 $i$，且贪心不会中途失败。

**证明**：对 $i$ 归纳。$i = 0$：$r_0 \ge 1 > 0 = g_{-1}$，即 $S_0$ 中存在大于 $g_{-1}$ 的元素，故 $g_0$ 存在且 $g_0 \le r_0$。设 $g_{i-1} \le r_{i-1}$；由 $r_i > r_{i-1} \ge g_{i-1}$ 知 $r_i$ 是 $S_i$ 中一个大于 $g_{i-1}$ 的元素，故 $g_i$ 存在且 $g_i \le r_i$。归纳成立。∎

**定理**：贪心返回 `false` 当且仅当不存在可行方案。

**证明**：若存在可行方案，由引理 2，贪心每步都能取到值并完成整个扫描，返回 `true`；逆否即"返回 `false` ⇒ 无解"。反之，若贪心返回 `true`，产出的序列每项 $g_i \in S_i$ 且 $g_i > g_{i-1}$，即每个元素或不减、或减去一个严格小于原值的质数——这正是一组合法操作方案，故"返回 `true` ⇒ 有解"。∎

## 6. 复杂度分析

- **时间复杂度**：$O(C \log\log C + n)$，其中 $C = \max(nums) \le 1000$。埃氏筛 $O(C \log\log C)$，前缀表 $O(C)$，主循环每元素 $O(1)$ 共 $O(n)$。
- **空间复杂度**：$O(C)$，存放合数标记与 $P[x]$ 表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool primeSubOperation(vector<int>& nums) {
        constexpr int C = 1000;
        int lp[C + 1] = {};
        bool comp[C + 1] = {};
        for (int i = 2; i * i <= C; ++i)
            if (!comp[i])
                for (int j = i * i; j <= C; j += i) comp[j] = true;
        for (int x = 2; x <= C; ++x) lp[x] = comp[x] ? lp[x - 1] : x;

        int prev = 0;
        for (int v : nums) {
            int x = v - prev - 1;
            if (x >= 2) prev = v - lp[x];
            else if (v > prev) prev = v;
            else return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def primeSubOperation(self, nums: List[int]) -> bool:
        C = 1000
        comp = [False] * (C + 1)
        for i in range(2, int(C ** 0.5) + 1):
            if not comp[i]:
                for j in range(i * i, C + 1, i):
                    comp[j] = True
        lp = [0] * (C + 1)
        for x in range(2, C + 1):
            lp[x] = x if not comp[x] else lp[x - 1]

        prev = 0
        for v in nums:
            x = v - prev - 1
            if x >= 2:
                prev = v - lp[x]
            elif v > prev:
                prev = v
            else:
                return False
        return True
```

## 8. 边界情况与易错点

1. **每个下标只能减"一个"质数**：题面"选择一个**之前未选过的下标**"限定每个元素至多操作一次。若误读成"可以反复减"，贪心目标就变成"压到 $prev + 1$"，判定条件完全不同（见延伸思考）。
2. **prev 初始值用 0 而非 $-\infty$ 或 `nums[0]`**：第一个元素也要尽量压小。反例 `[10, 4]`：若 10 不减，4 无论怎么减都无法超过它，误判 `false`；把 10 减 7 得 3，则 $4 > 3$ 成立，答案为 `true`。
3. **漏掉"$x < 2$ 且 $nums[i] \le prev$ ⇒ `false`"分支**：最常见的 WA。例如 `[5,8,3]` 的第三步 $x = -1$，没有质数可减，不减也追不上 `prev`。
4. **"严格递增"不是"非降"**：$x = nums[i] - prev - 1$ 里的 $-1$ 体现严格性；若写成 $p \le nums[i] - prev$，新值可能恰等于 $prev$，违反严格。
5. **$p$ 必须严格小于 $nums[i]$**：保证减完 $\ge 1$。本题由 $p \le x \le nums[i] - 1$ 自动满足，但若改动公式（比如 prev 取负值）需重新检查。
6. **$n = 1$ 恒 `true`**；**已递增数组**（示例 2）贪心会继续压小元素，但每步保证新值 $> prev$，不会误报 `false`——无需"已递增就跳过"的特判。
7. **减完无需再验下界**：新值 $= nums[i] - P[x] \ge prev + 1 \ge 1$，结构性成立。
