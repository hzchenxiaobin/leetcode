# LeetCode 使数组元素全部相等的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组元素全部相等的最少操作次数（#2602，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-all-array-elements-equal/
- **来源**：LeetCode 第 338 场周赛 Q3
- **难度**：中等
- **标签**：数组、排序、前缀和、二分查找

**题意**：给定长度为 $n$ 的正整数数组 `nums` 和长度为 $m$ 的查询数组 `queries`。第 $i$ 次查询要求把 `nums` 中**所有**元素都变成 $q = \text{queries}[i]$；一次操作可把某个元素 **+1 或 −1**，可执行任意次。返回 `answer[i]` 为第 $i$ 次查询的最少操作次数。注意**每次查询后数组恢复原值**，查询之间互不影响。

**约束**：

- `1 <= n, m <= 10^5`
- `1 <= nums[i], queries[i] <= 10^9`

## 2. 示例

**示例 1**

```text
输入：nums = [3,1,6,8], queries = [1,5]
输出：[14,10]
解释：q=1：2 + 0 + 5 + 7 = 14（全部减小到 1）。
      q=5：2 + 4 + 1 + 3 = 10（左侧增大、右侧减小）。
```

**示例 2**

```text
输入：nums = [2,9,6,3], queries = [10]
输出：[20]
解释：全部增大到 10：8 + 1 + 4 + 7 = 20。
```

**示例 3（自拟，覆盖 q 恰等于元素）**

```text
输入：nums = [2,2,4], queries = [2]
输出：[2]
解释：两个 2 恰好等于目标，无需操作；4 减小 2 次即可。
```

## 3. 解题思路

### 3.1 暴力思路

由"一次操作只动一个元素 ±1"且元素之间互不影响，把所有元素变成 $q$ 的代价就是每个元素到 $q$ 的距离之和（证明见 §5 引理 1）。于是对每个查询逐元素累加：

```python
for q in queries:
    ans.append(sum(abs(x - q) for x in nums))
```

单次查询 $O(n)$，总计 $O(n \cdot m)$；$n, m \le 10^5$ 时约 $10^{10}$ 次运算，**超时**。瓶颈在于"每个查询都重新遍历整个数组、逐元素处理绝对值"。要提速，就得把"逐元素求和"升级为"按段批量求和"——而批量求和的前提是**排序**暴露出的单调结构。

### 3.2 核心观察：排序 + 切点 + 前缀和

![核心观察：排序后按 q 切两段，绝对值脱壳](images/wc338_q3_split_concept.svg)

**观察 1（代价可拆）**：操作彼此独立，总代价 $= \sum_i |\text{nums}[i] - q|$，与元素顺序无关——排序不改变答案。

**观察 2（排序使绝对值"脱壳"）**：把 `nums` 升序排序得到 $a$，对查询 $q$ 取切点

$$\text{pos} = \text{lower\_bound}(a, q) = \#\{i : a_i < q\}$$

则**左段**（$i < \text{pos}$）全部 $a_i < q$，绝对值 $= q - a_i$（需增大）；**右段**（$i \ge \text{pos}$）全部 $a_i \ge q$，绝对值 $= a_i - q$（需减小）。两段内绝对值方向固定，不再需要逐个判号。

**观察 3（段和用前缀和 $O(1)$）**：设 $\text{pre}[k] = a_0 + \dots + a_{k-1}$（$\text{pre}[0]=0$），则左段和 $=\text{pre}[\text{pos}]$、右段和 $=\text{pre}[n]-\text{pre}[\text{pos}]$，两段元素个数分别为 $\text{pos}$ 与 $n-\text{pos}$，于是

$$\text{cost}(q) = \underbrace{q \cdot \text{pos} - \text{pre}[\text{pos}]}_{\text{左段：增大}} + \underbrace{(\text{pre}[n] - \text{pre}[\text{pos}]) - q \cdot (n - \text{pos})}_{\text{右段：减小}}$$

> 💡 一句话：每个查询只需一次二分定位 + 一次 $O(1)$ 公式，$10^5$ 个查询轻松通过。

### 3.3 算法流程

![算法流程图：排序、前缀和预处理，每查询二分加公式](images/wc338_q3_algorithm_flow.svg)

1. **预处理**：排序 `nums` 得升序数组 $a$（$O(n\log n)$）；构建前缀和 $\text{pre}[0..n]$（$O(n)$）。
2. **逐查询**：对每个 $q$：
   - 二分 `lower_bound` 求切点 $\text{pos}$（首个 $\ge q$ 的下标，$O(\log n)$）；
   - 套公式算 $\text{cost}(q)$（$O(1)$，注意 64 位）；
   - 存入 `answer[i]`。
3. 返回 `answer`。查询互相独立（数组每次复原），无需对 `queries` 排序。

### 3.4 示例演算

![示例演算：两个查询的切点、公式与逐元素核对](images/wc338_q3_example_walkthrough.svg)

以示例 1 `nums = [3,1,6,8]`, `queries = [1,5]` 走一遍：排序得 $a = [1,3,6,8]$，前缀和 $\text{pre} = [0,1,4,10,18]$（$n=4$）。

| 查询 $q$ | 切点 pos | 左段 $q\cdot\text{pos}-\text{pre}[\text{pos}]$ | 右段 $(\text{pre}[n]-\text{pre}[\text{pos}])-q(n-\text{pos})$ | $\text{cost}(q)$ | 逐元素核对 |
|---|---|---|---|---|---|
| 1 | 0（无元素 < 1） | $1\cdot 0 - 0 = 0$ | $(18-0)-1\cdot 4 = 14$ | **14** | $0+2+5+7=14$ |
| 5 | 2（1、3 < 5） | $5\cdot 2 - 4 = 6$ | $(18-4)-5\cdot 2 = 4$ | **10** | $4+2+1+3=10$ |

两个结果与示例输出 `[14,10]` 一致。示例 2 `nums=[2,9,6,3]`, `q=10`：$a=[2,3,6,9]$，$\text{pre}=[0,2,5,11,20]$，$\text{pos}=4$，$\text{cost} = 10\cdot 4 - 20 + 0 = 20$ ✓。

## 4. 算法细节

1. **切点取 `lower_bound`**：$\text{pos} = $ 首个 $\ge q$ 的下标 $=$ 严格小于 $q$ 的元素个数。等于 $q$ 的元素落入右段、贡献恰为 $0$，因此**用 `upper_bound` 也正确**——两种取法只影响"零贡献元素"归哪一段。
2. **前缀和定义**：$\text{pre}[0]=0$，$\text{pre}[i]=\text{pre}[i-1]+a_{i-1}$，开 $n+1$ 长度避免越界；任一段和 $a[l..r)$ 之和 $=\text{pre}[r]-\text{pre}[l]$。
3. **公式推导**：$\text{cost}(q)=\sum_{i<\text{pos}}(q-a_i)+\sum_{i\ge\text{pos}}(a_i-q)=\big(q\cdot\text{pos}-\text{pre}[\text{pos}]\big)+\big((\text{pre}[n]-\text{pre}[\text{pos}])-q\cdot(n-\text{pos})\big)$。
4. **溢出（本题最大坑）**：$q \le 10^9$、$n \le 10^5$，$q\cdot n$ 可达 $10^{14}$，远超 32 位整数；C++ 中间量与答案必须用 `long long`（官方签名也返回 `vector<long long>`），乘法写 `1LL * q * pos`。Python 无此问题。
5. **排序的合法性**：代价 $\sum|a_i-q|$ 与元素顺序无关，直接对 `nums` 原地排序即可。
6. **不需要模拟操作**："每次查询后数组变回最初的值"说明查询互相独立，只算代价、不要真的去加减数组。

## 5. 正确性证明

**引理 1（单查询代价）**：把数组所有元素变成 $q$ 的最少操作次数恰为 $\sum_i |a_i - q|$。

**证明**：一方面，元素 $a_i$ 每次操作至多变化 1，故其至少需要 $|a_i - q|$ 次操作，各元素的操作互不替代，总次数 $\ge \sum_i |a_i - q|$；另一方面，对每个元素独立执行 $|a_i - q|$ 次 $\pm 1$ 即可达到目标，总次数恰为该值。两方向夹逼得证。∎

**引理 2（切点公式）**：设 $a$ 升序，$\text{pos} = \#\{i : a_i < q\}$，则 $\sum_i |a_i - q| = \big(q\cdot\text{pos}-\text{pre}[\text{pos}]\big) + \big((\text{pre}[n]-\text{pre}[\text{pos}]) - q\cdot(n-\text{pos})\big)$。

**证明**：由 $\text{pos}$ 的定义与 $a$ 的有序性：$i < \text{pos} \Rightarrow a_i < q$，$i \ge \text{pos} \Rightarrow a_i \ge q$（后者是 `lower_bound` 的标准性质：$a_{\text{pos}} \ge q$ 且其后更大）。于是左段 $|a_i - q| = q - a_i$、右段 $|a_i - q| = a_i - q$，分段求和：

$$\sum_{i<\text{pos}} (q - a_i) = q\cdot\text{pos} - \text{pre}[\text{pos}], \qquad \sum_{i\ge\text{pos}} (a_i - q) = (\text{pre}[n]-\text{pre}[\text{pos}]) - q\cdot(n-\text{pos})$$

两式相加即得。∎

**定理**：算法对每个查询返回正确的最少操作次数。

**证明**：由引理 1，第 $i$ 个查询的答案即 $\sum_j |a_j - q_i|$，问题化归为计算该和；二分查找在有序数组上精确返回 $\text{pos}$（比较传递、区间收缩至空，标准性质）；由引理 2，以该 $\text{pos}$ 代入公式所得正是该和值，而前缀和与整数运算无误差。故每个 `answer[i]` 等于最少操作次数。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big((n + m)\log n\big)$。排序 $O(n\log n)$，前缀和 $O(n)$，$m$ 个查询各一次二分 $O(\log n)$ 加 $O(1)$ 公式。对比暴力的 $O(n \cdot m) \approx 10^{10}$。
- **空间复杂度**：$O(n)$，存放排序后的数组与前缀和（不计返回的 `answer` 数组）。若允许原地排序，额外空间仅为前缀和数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<long long> minOperations(vector<int>& nums, vector<int>& queries) {
        int n = nums.size();
        sort(nums.begin(), nums.end());
        vector<long long> pre(n + 1, 0);
        for (int i = 0; i < n; ++i) pre[i + 1] = pre[i] + nums[i];

        vector<long long> ans;
        ans.reserve(queries.size());
        for (int q : queries) {
            int pos = lower_bound(nums.begin(), nums.end(), q) - nums.begin();
            long long left  = 1LL * q * pos - pre[pos];
            long long right = (pre[n] - pre[pos]) - 1LL * q * (n - pos);
            ans.push_back(left + right);
        }
        return ans;
    }
};
```

### Python

```python
from bisect import bisect_left

class Solution:
    def minOperations(self, nums: List[int], queries: List[int]) -> List[int]:
        nums.sort()
        n = len(nums)
        pre = [0] * (n + 1)
        for i, x in enumerate(nums):
            pre[i + 1] = pre[i] + x

        ans = []
        for q in queries:
            pos = bisect_left(nums, q)
            ans.append(q * pos - pre[pos] + (pre[n] - pre[pos]) - q * (n - pos))
        return ans
```

## 8. 边界情况与易错点

1. **溢出（头号易错点）**：$q \cdot \text{pos}$ 最大约 $10^9 \times 10^5 = 10^{14}$，C++ 用 `int` 存中间量或答案必然溢出；乘法要写 `1LL * q * pos` 而非 `(long long)(q * pos)`（后者先按 `int` 溢出再转型）。返回类型官方给的就是 `vector<long long>`。
2. **切点两个极端**：$q \le \min(a)$ 时 $\text{pos}=0$（全部增大），$q > \max(a)$ 时 $\text{pos}=n$（全部减小）——公式在这两个边界自动成立（其中一段为 0），无需特判。
3. **等于 $q$ 的元素**：落入右段贡献 $0$，用 `lower_bound` 或 `upper_bound` 都正确，但**两段公式必须配套同一个切点定义**，不要左段用 `<`、右段用 `<=` 各算各的。
4. **查询不是真实修改**："每次查询后数组变回最初的值"意味着查询互相独立、代价只依赖 $q$；若误把上一次查询的操作累积进数组，或对每个查询真的模拟加减，都方向性错误。
5. **前缀和数组开 $n+1$**：$\text{pre}[0]=0$ 哨兵，避免 $\text{pos}=0$ 或 $\text{pos}=n$ 时越界。
6. **排序破坏原数组顺序没关系**：代价与顺序无关；但若题目改为"只能操作满足某种位置约束的元素"则要重新审视。
7. **$n = 1$**：$\text{cost}(q) = |a_0 - q|$，公式自动覆盖。
