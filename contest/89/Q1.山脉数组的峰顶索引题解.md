# LeetCode 山脉数组的峰顶索引 题解

## 1. 题目概述

- **标题 / 题号**：山脉数组的峰顶索引（#852，medium）
- **链接**：https://leetcode.cn/problems/peak-index-in-a-mountain-array/
- **来源**：LeetCode 第 89 场周赛 Q1
- **难度**：中等
- **标签**：数组、二分查找、三分查找

**题意**：给定一个长度为 $n$ 的**山脉数组** `arr` —— 它的值先**严格递增**到达一个**峰顶元素**，之后**严格递减**。要求返回峰顶元素的下标，并且必须做到 $O(\log n)$。

题目保证 `arr` 一定是山脉数组，所以峰顶唯一存在，既不是首元素也不是末元素。

**约束**：

- $3 \le \text{arr.length} \le 10^5$
- $0 \le \text{arr}[i] \le 10^6$
- 题目数据保证 `arr` 是一个山脉数组

## 2. 示例

**示例 1**

```text
输入：arr = [0,1,0]
输出：1
解释：先升到 1 再降回 0，峰顶下标为 1。
```

**示例 2**

```text
输入：arr = [0,2,1,0]
输出：1
解释：2 是最大值也是峰顶，下标 1。
```

**示例 3**

```text
输入：arr = [0,10,5,2]
输出：1
解释：0 → 10 一路上升，10 → 5 → 2 一路下降，峰顶仍是下标 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：从头扫一遍，找第一个满足 $\text{arr}[i] > \text{arr}[i+1]$ 的下标 $i$，或者直接 `max_element` 取最大值下标。

两种写法都是 $O(n)$，在 $n \le 10^5$ 时当然能过，但题目开宗明义要求 $O(\log n)$，说明出题人想考的是**单调性二分**。暴力没有利用「山脉数组只有一段上升、一段下降」这个结构，面试与复盘时都不算达标。

### 3.2 核心观察：用「相邻两个元素的大小关系」判定峰顶在哪一侧

![峰顶把山脉数组劈成两段：左段单调升、右段单调降](images/wc89_q1_peak_binary_search.svg)

山脉数组的关键结构是：**峰顶左侧严格递增，峰顶右侧严格递减**。于是任意取一个位置 $i$（$i < n-1$），只要比较 `arr[i]` 与 `arr[i+1]` 这两个相邻元素，就知道峰顶在 $i$ 的哪一侧：

- 若 $\text{arr}[i] < \text{arr}[i+1]$：说明 $i$ 还处在**上坡**，峰顶必定在 $i$ 的**右侧**，即下标 $> i$；
- 若 $\text{arr}[i] > \text{arr}[i+1]$：说明 $i$ 已经处在**下坡**（或 $i$ 本身就是峰顶），峰顶必定 $\le i$。

这是一个典型的**「三分支判定 + 区间收缩」**结构：答案所在的区间可以稳定地砍掉一半，因此可以二分。

设答案一定落在闭区间 $[\text{lo}, \text{hi}]$ 内，取中点 $\text{mid} = \lfloor (\text{lo} + \text{hi}) / 2 \rfloor$：

- 若 $\text{arr}[\text{mid}] < \text{arr}[\text{mid}+1]$：峰顶 $> \text{mid}$，令 $\text{lo} = \text{mid} + 1$；
- 否则：峰顶 $\le \text{mid}$，令 $\text{hi} = \text{mid}$。

注意 `mid` 永远不会等于 `hi`（因 $\text{lo} < \text{hi}$ 时 $\text{mid} < \text{hi}$），所以 `arr[mid + 1]` 不会越界。

### 3.3 算法流程

![二分查找流程：每轮砍掉不含峰顶的一半](images/wc89_q1_binary_flow.svg)

```text
1. lo = 0, hi = n - 1
2. while lo < hi:
       mid = (lo + hi) / 2              // 向下取整
       if arr[mid] < arr[mid + 1]:      // 还在上坡
           lo = mid + 1
       else:                            // 已在下坡或正踩峰顶
           hi = mid
3. 返回 lo
```

循环退出时必有 $\text{lo} = \text{hi}$，这个下标就是峰顶。

### 3.4 示例演算

![示例演算：arr = [0, 2, 1, 0]，两轮收缩即锁定峰顶](images/wc89_q1_walkthrough.svg)

以 `arr = [0, 2, 1, 0]`（$n = 4$）为例：

| 轮次 | lo | hi | mid | arr[mid] | arr[mid+1] | 决策 |
|------|----|----|-----|----------|------------|------|
| ① | 0 | 3 | 1 | 2 | 1 | $2 > 1$，已在下坡 → `hi = 1` |
| ② | 0 | 1 | 0 | 0 | 2 | $0 < 2$，仍在上坡 → `lo = 1` |
| ③ | 1 | 1 | — | — | — | `lo == hi` → 返回 1 |

两轮就把区间从 4 个元素收到 1 个，答案 1 正确。

## 4. 算法细节

1. **循环条件用 `lo < hi` 而不是 `lo <= hi`**：我们要找的是「最后一个满足 arr[i] < arr[i+1] 的位置再加 1」，本质是**找左边界**，用左闭右闭区间收缩到单点更自然，也避免了额外判断。
2. **`mid` 必须向下取整**：`lo = mid + 1` 与 `hi = mid` 的组合在向下取整时保证每轮区间长度严格减少（至少减 1），不会死循环。若误用 `lo = mid` / `hi = mid - 1` 的反向写法，则必须向上取整。
3. **只比较相邻两元素**：不需要读 `arr[mid - 1]`，也就不会出现 `mid = 0` 时的越界问题（峰顶不会是下标 0，但代码里根本不访问 `mid - 1`）。
4. **`mid` 的写法**：`lo + (hi - lo) / 2` 与 `(lo + hi) / 2` 在本题数据范围内都安全，但前者是更好的习惯，$n$ 更大时不会溢出。
5. **不用三分查找**：虽然标签里出现了「三分查找」，但三分每次只砍掉 $1/3$，常数也比二分大；本题只需比较一对相邻元素就能得到「在上坡还是下坡」的完整信息，二分是更紧的做法。
6. **返回下标而非值**：题目要求的是**索引**，`arr` 可能有重复值（虽然山脉定义下全局最大唯一），返回 `arr` 的最大值会写错。

## 5. 正确性证明

**引理 1**：对任意 $0 \le i < n - 1$，若 $\text{arr}[i] < \text{arr}[i+1]$，则峰顶下标 $p$ 满足 $p > i$。

**证明**：设峰顶下标为 $p$，由山脉数组的定义，$\text{arr}[0..p]$ 严格递增、$\text{arr}[p..n-1]$ 严格递减，且 $\text{arr}[p] > \text{arr}[p+1]$（因 $p < n-1$）。

反设 $p \le i$。若 $p \le i$，则 $i$ 与 $i+1$ 都落在递减段上（或 $i = p$，此时相邻比较为 $\text{arr}[p] > \text{arr}[p+1]$），于是 $\text{arr}[i] > \text{arr}[i+1]$，与 $\text{arr}[i] < \text{arr}[i+1]$ 矛盾。故 $p > i$。∎

**引理 2**：对任意 $0 \le i < n - 1$，若 $\text{arr}[i] > \text{arr}[i+1]$，则峰顶下标 $p$ 满足 $p \le i$。

**证明**：反设 $p \ge i + 1$。由定义 $\text{arr}[0..p]$ 严格递增，而 $i < i + 1 \le p$，故 $\text{arr}[i] < \text{arr}[i+1]$，与前提矛盾。故 $p \le i$。∎

**定理**：算法返回的 `lo` 等于峰顶下标 $p$。

**证明**：记循环开始前的不变式为「$p \in [\text{lo}, \text{hi}]$」。初始 $\text{lo} = 0$、$\text{hi} = n-1$，而 $0 < p < n-1$，不变式成立。

设某一轮开始时不变式成立且 $\text{lo} < \text{hi}$，取 $\text{mid} = \lfloor (\text{lo}+\text{hi})/2 \rfloor$，则 $\text{lo} \le \text{mid} < \text{hi} \le n-1$，故 `arr[mid+1]` 合法。

- 若 $\text{arr}[\text{mid}] < \text{arr}[\text{mid}+1]$，由引理 1 得 $p > \text{mid}$，即 $p \ge \text{mid}+1$；更新 $\text{lo} = \text{mid}+1$ 后 $p \in [\text{lo}, \text{hi}]$ 仍成立。
- 否则 $\text{arr}[\text{mid}] > \text{arr}[\text{mid}+1]$（山脉数组相邻元素必不相等），由引理 2 得 $p \le \text{mid}$；更新 $\text{hi} = \text{mid}$ 后不变式仍成立。

每轮区间长度严格变小，循环必然终止于 $\text{lo} = \text{hi}$。此时不变式给出 $p \in [\text{lo}, \text{lo}]$，故 $\text{lo} = p$。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。每轮把区间长度至少减半，最多 $\lceil \log_2 n \rceil \le 17$ 轮（$n \le 10^5$），每轮只做一次比较。
- **空间**：$O(1)$。只用了 `lo`、`hi`、`mid` 三个整型变量，没有额外数组或递归栈。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int peakIndexInMountainArray(vector<int>& arr) {
        int lo = 0, hi = (int)arr.size() - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (arr[mid] < arr[mid + 1]) {
                lo = mid + 1;
            } else {
                hi = mid;
            }
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def peakIndexInMountainArray(self, arr: list[int]) -> int:
        lo, hi = 0, len(arr) - 1
        while lo < hi:
            mid = (lo + hi) // 2
            if arr[mid] < arr[mid + 1]:
                lo = mid + 1
            else:
                hi = mid
        return lo
```

## 8. 边界情况与易错点

1. **峰值在倒数第二个位置**：如 `[0, 1, 2, 0]`，峰顶下标 2。若把 `hi` 初始化成 `n - 2`，这类用例会被漏掉；本题写 `n - 1` 更稳妥。
2. **`arr[mid + 1]` 的越界风险**：只要维持 `lo < hi` 进入循环，就有 `mid < hi ≤ n-1`，`mid+1 ≤ n-1` 恒成立。若改成 `lo <= hi` 且 `hi = n-1`，最后一轮会出现 `mid = n-1` 并访问 `arr[n]`。
3. **死循环**：`lo = mid` 配向下取整会在 `hi = lo + 1` 时卡住（`mid = lo`，区间不变）。本解法用 `lo = mid + 1`、`hi = mid`，必须配**向下取整**。
4. **把「山脉」误当成「有平台」**：山脉数组相邻元素严格不等，所以 `arr[mid] == arr[mid+1]` 不会出现；若题目放宽成「单调不减再单调不增」，就要额外处理平台段。
5. **返回值写成元素值**：题目要**下标**。`arr[max_element]` 与 `max_element - begin` 的区别是本题最常见的低级错。
6. **`n = 3` 的最小情形**：`[0, 1, 0]` 只有一种形状，峰顶必为 1；代码不需要特判，但要保证首轮 `mid = 1` 能读到 `arr[2]`，`hi = 3 - 1 = 2` 时正好可行。
