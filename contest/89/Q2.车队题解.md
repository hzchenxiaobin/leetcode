# LeetCode 车队 题解

## 1. 题目概述

- **标题 / 题号**：车队（#853，medium）
- **链接**：https://leetcode.cn/problems/car-fleet/
- **来源**：LeetCode 第 89 场周赛 Q2
- **难度**：中等
- **标签**：数组、排序、栈、单调栈

**题意**：一条单行道上，$n$ 辆车同时朝同一个目的地 `target` 行驶，第 $i$ 辆车从 `position[i]` 出发、速度为 `speed[i]`。车**永远不会超车**：一旦追上前车，就只能贴着它按同样速度并行。并排行驶的一辆或多辆车叫**车队**，车队速度取队内**最慢**的那辆车。即使是在 `target` 处才追上也仍算同一个车队。求最终到达目的地的车队数量。

**约束**：

- $n = \text{position.length} = \text{speed.length}$，$1 \le n \le 10^5$
- $0 < \text{target} \le 10^6$，$0 \le \text{position}[i] < \text{target}$，`position` 中每个值都不同
- $0 < \text{speed}[i] \le 10^6$

## 2. 示例

**示例 1**

```text
输入：target = 12, position = [10,8,0,5,3], speed = [2,4,1,1,3]
输出：3
解释：10 号（v=2）与 8 号（v=4）在终点 12 处相遇 → 车队 ①；
     0 号（v=1）谁也追不上，独自成队 → 车队 ②；
     5 号（v=1）与 3 号（v=3）在 6 处合并成速度 1 的车队 → 车队 ③。
```

**示例 2**

```text
输入：target = 10, position = [3], speed = [3]
输出：1
解释：只有一辆车，天然是一个车队。
```

**示例 3**

```text
输入：target = 100, position = [0,2,4], speed = [4,2,1]
输出：1
解释：0 号最快，先追上 2 号，再和 4 号一起以最慢的 1 前进，最终只有 1 个车队。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**按时间模拟**：把时间切成小片，每片让所有车前进，检查是否追上前车，追上就合并速度。问题是时间连续、碰撞时刻可能是有理数，离散模拟要么丢精度要么超时；而预先两两计算追及时刻又要 $O(n^2)$ 并处理连锁合并，实现非常容易出错。

车队问题的难点在于「合并的连锁性」——但它同时也是一个巨大的提示：**既然车不能互相超越，车队在位置轴上的划分就是天然有序的**。

### 3.2 核心观察：自由到达时间的前缀最大值

![后车更快就会追上并「粘」成车队，车队速度 = 队内最慢车](images/wc89_q2_fleet_merge.svg)

给每辆车算一个**自由到达时间**（假设整条路上只有它自己）：

$$t_i = \frac{\text{target} - \text{position}[i]}{\text{speed}[i]}$$

由于不能超车，后车只要在途中追上前车，就会与前车**同速、同时**到达目的地。于是：

> **结论**：把车按位置从前往后（`position` 降序）排列，第 $i$ 辆车的实际到达时间等于它**及其前方所有车**自由到达时间的最大值。

这条结论可以这样理解：车队的速度只由队内最慢的车决定，而「最慢」等价于「自由到达时间最大」。所有被前车挡住的快车，都被强行拉到前队的时间线上。

于是只要**从前往后扫一遍**，维护一个变量 `cur` = 已经就位的所有车队中最慢那个的到达时间：

- 若 $t_i > \text{cur}$：这辆车比前方所有车队都慢，谁也挡不住它 → **新车队**，`cur = t_i`；
- 否则 $t_i \le \text{cur}$：它一定会在途中（或恰在终点）追上前方某支车队 → **并入**，`cur` 不变。

`t_i = cur` 的边界情形要特别小心：两车同时到达终点仍算**同一个**车队，所以判定必须是**严格大于**才新增。

![按位置从前往后扫描：到达时间出现「新纪录」就是新车队](images/wc89_q2_time_stack.svg)

### 3.3 算法流程

1. 把 `position` 与 `speed` 配对，按 `position` **降序**排序（从最靠近终点的车开始处理）。
2. `fleets = 0`，`cur = 0`（第一辆车之前的「最慢车队」不存在）。
3. 依次处理每辆车，计算 `need = target - position[i]`：
   - 若 `fleets == 0` 或 `need / speed[i] > cur`：`fleets++`，`cur = need / speed[i]`；
   - 否则跳过（已被前方车队吸收）。
4. 返回 `fleets`。

为了避免浮点误差，`need / speed > cur` 用**交叉相乘**比较：设 `cur = num / den`，条件等价于

$$\text{need} \cdot \text{den} > \text{num} \cdot \text{speed}$$

各量上界都是 $10^6$，乘积不超过 $10^{12}$，`long long` 足够。

### 3.4 示例演算

![示例 1 演算：按位置从前往后逐车判定](images/wc89_q2_walkthrough.svg)

`target = 12`，把五辆车按位置降序排好：`(10, 2)`、`(8, 4)`、`(5, 1)`、`(3, 3)`、`(0, 1)`。

| position / speed | $t$ | 更新后 cur | 与旧 cur 比较 | 新车队？ | 车队数 |
|------------------|-----|-----------|--------------|---------|--------|
| 10 / 2 | 1 | 1 | 首车 | 是 | 1 |
| 8 / 4 | 1 | 1 | $1 > 1$ 否 | 否 | 1 |
| 5 / 1 | 7 | 7 | $7 > 1$ 是 | 是 | 2 |

| 0 / 1 | 12 | 12 | $12 > 7$ 是 | 是 | 3 |

答案是 3，与示例一致。注意第二行 $t = 1$ 恰好等于 `cur`：两车同时抵达终点，按题意并入同一车队，不能计数。

## 4. 算法细节

1. **按位置降序处理**：只能从最靠近终点的车开始，因为「谁挡住谁」的方向由位置决定，与输入顺序无关。
2. **维护 `cur` 而不是栈**：虽然标签写了「栈 / 单调栈」，但这里根本不需要保存全部车队的时间——只要记住最后一个（也就是最慢的）车队的到达时间即可，`cur` 天然单调不减，等价于一个只留栈顶的单调栈。
3. **严格大于才新增**：`t_i > cur` 是车队边界的定义；写 `>=` 会把「同时到达」的车误拆成两个车队。
4. **有理数比较**：`need * den > num * spd`，全部整数运算。若直接写 `(double)need / spd > cur`，在 $10^6$ 级别的数据上理论上可能因舍入误判（例如两车本应同时到达却算出微小差值），交叉相乘零风险。
5. **`den` 的初值**：`num = 0, den = 1` 只是为了占位，第一辆车用 `fleets == 0` 兜住，避免除零与无意义比较。
6. **不需要真的模拟碰撞**：合并过程被「取最大值」隐式完成了，这也是本题 $O(n \log n)$ 的根本原因。
7. **底层数据结构**：C++ 用下标数组 `idx` 排序，避免 `pair` 拷贝；Python 直接对 `(position, speed)` 元组排序。

## 5. 正确性证明

设车辆按 `position` **降序**排列为 $c_1, c_2, \dots, c_n$，其自由到达时间为 $t_1, \dots, t_n$。

**引理 1（追及判据）**：若后车 $i$ 与前车 $j$（$\text{position}[j] > \text{position}[i]$）满足 $t_i \le t_j$，则两车必在 `target` 处或之前相遇，从而并入同一车队。

**证明**：记 $p_i = \text{position}[i] < p_j = \text{position}[j]$，$T = \text{target}$，则 $t_i = (T - p_i)/v_i$，$t_j = (T - p_j)/v_j$。分两种情形说明「未合并 $\Rightarrow t_i > t_j$」：

- **$v_i \le v_j$**：两车距离 $d(t) = (p_j - p_i) + (v_j - v_i)t \ge d(0) > 0$ 永不缩小，$i$ 永远追不上；同时由 $p_i < p_j$、$v_i \le v_j$ 得
  $$t_i = \frac{T - p_i}{v_i} \ge \frac{T - p_j}{v_j} = t_j,$$
  当 $v_i < v_j$ 时上式严格不等，即「未合并 $\Rightarrow t_i > t_j$」；当 $v_i = v_j$ 时两车距离恒定、以同一时刻抵达终点，按题意「在 `target` 才赶上也算同一个车队」，这一情形本身就算合并，不构成反例。
- **$v_i > v_j$**：追击时刻 $t^{*} = (p_j - p_i)/(v_i - v_j)$。若未合并，则 $i$ 到达终点时还没追上，即 $t_i < t^{*}$，逐行等价变形：
  $$\frac{T - p_i}{v_i} < \frac{p_j - p_i}{v_i - v_j}
  \iff (T - p_i)(v_i - v_j) < v_i(p_j - p_i)
  \iff v_i\,(T - p_j) < v_j\,(T - p_i)
  \iff \frac{T - p_j}{v_j} < \frac{T - p_i}{v_i},$$
  即 $t_j < t_i$。

两种情形下，只要两车最终没有并成同一车队，就必有 $t_i > t_j$。取逆否命题即得：$t_i \le t_j \Rightarrow$ 两车合并。∎

**引理 2（前缀最大性）**：第 $k$ 辆车的实际到达时间为 $T_k = \max\{t_1, t_2, \dots, t_k\}$。

**证明**：对 $k$ 归纳。

- $k = 1$：前方无车，$T_1 = t_1$，成立。
- 设 $T_{k-1} = \max\{t_1, \dots, t_{k-1}\}$。第 $k$ 辆车只能被**紧邻前方的那支车队**挡住（前面的车队都已连成一体），因此
  $$T_k = \max(t_k,\, T_{k-1}) = \max(t_k,\, \max\{t_1,\dots,t_{k-1}\}) = \max\{t_1,\dots,t_k\}.$$
  这里用到「车队速度 = 队内最慢车」：$T_{k-1}$ 已经把所有更慢的车的影响累计进去了。∎

**引理 3（同队等价）**：相邻两车 $c_{k-1}, c_k$ 属于同一车队 $\iff T_{k-1} = T_k \iff t_k \le T_{k-1}$。

**证明**：由引理 2，$T_{k-1} = T_k \iff \max(t_k, T_{k-1}) = T_{k-1} \iff t_k \le T_{k-1}$。

两个方向分别验证：

- 若 $t_k \le T_{k-1}$，由引理 1 的判据（把「前车」换成整支前队，其速度为队内最慢车、到达时间 $T_{k-1}$）知 $c_k$ 必追上并入，同队。
- 若 $t_k > T_{k-1}$，则没有任何前车能拖住它（$c_k$ 比前方所有车都晚到），它自成车队。∎

**定理**：算法返回的 `fleets` 等于最终到达目的地的车队数。

**证明**：由引理 2，$T_1 \le T_2 \le \dots \le T_n$ 单调不减；由引理 3，车队就是「$T$ 值相同的极大连续段」，因此车队数等于序列 $T_1, \dots, T_n$ 中**严格上升**出现的次数（$T_1$ 本身算第一次）。

算法从 $c_1$ 开始扫描，`cur` 始终等于上一个车队的时间 $T_{k-1}$，仅当 $t_k > \text{cur}$ 时 `fleets` 加一并更新 `cur = t_k`，这恰好统计了严格上升的次数。故 `fleets` 等于车队数。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$ 占主导；随后单次扫描每辆车做 $O(1)$ 次整数运算（一次乘法 + 一次比较），共 $O(n)$。
- **空间**：$O(n)$。C++ 版需要长度为 $n$ 的下标数组 `idx`；Python 版排序生成 $n$ 个元组。除此之外只用了常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int carFleet(int target, vector<int>& position, vector<int>& speed) {
        int n = (int)position.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return position[a] > position[b];
        });

        int fleets = 0;
        long long num = 0, den = 1;
        for (int i : idx) {
            long long need = target - position[i];
            long long spd = speed[i];
            if (fleets == 0 || need * den > num * spd) {
                fleets++;
                num = need;
                den = spd;
            }
        }
        return fleets;
    }
};
```

### Python

```python
class Solution:
    def carFleet(self, target: int, position: list[int], speed: list[int]) -> int:
        cars = sorted(zip(position, speed), key=lambda x: -x[0])
        fleets = 0
        num, den = 0, 1
        for pos, spd in cars:
            need = target - pos
            if fleets == 0 or need * den > num * spd:
                fleets += 1
                num, den = need, spd
        return fleets
```

## 8. 边界情况与易错点

1. **「同时到达」不是新车队**：判定必须写 `t > cur`。示例 1 中 10 号与 8 号车的 $t$ 都是 1，用 `>=` 会输出 4 而不是 3。
2. **浮点精度**：$t$ 可能是有理数（如 $7/3$），用 `double` 比较两个理论相等的值时可能得到不同结果。必须用交叉相乘的整数比较。
3. **溢出**：`need * den` 最大约 $10^6 \times 10^6 = 10^{12}$，超出 `int` 范围，必须用 `long long`（Python 无此问题）。
4. **`n = 1`**：只有一辆车，答案为 1。代码里靠 `fleets == 0` 分支保证首车必计数，不需要单独特判。
5. **只有后车更快才可能合并**：若后车更慢（$t_i > t_j$），它永远追不上，必然是新队。不要把「位置靠后」误当成「一定被吸收」。
6. **不要按平均速度合并**：车队速度取**最慢**车，等价于取最大自由到达时间，用平均值会算错。
7. **`position` 互不相同但速度可以相同**：速度相等且位置靠后的车永远追不上，它的 $t$ 一定更大，会正确计为新车队。
8. **恰好压在 `target` 上追上**：题目明确算同一车队，这与 `t_i = t_j` 的严格判定一致，不要额外写「必须严格在途中相遇」。
