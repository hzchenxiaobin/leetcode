# LeetCode 验证回文串 II 题解

## 1. 题目概述

- **标题 / 题号**：验证回文串 II（#680，easy）
- **链接**：https://leetcode.cn/problems/valid-palindrome-ii/
- **来源**：LeetCode 第 50 场周赛 Q1
- **难度**：简单
- **标签**：贪心、双指针、字符串

**题意**：给定只含小写字母的字符串 `s`，**最多**删除一个字符（也可以不删），判断能否把它变成回文串。返回 `true` / `false`。

**约束**：

- $1 \le \lvert s \rvert \le 10^5$
- `s` 仅由小写英文字母组成
- 「最多一个」意味着**允许不删**，因此原本就是回文的串直接返回 `true`

## 2. 示例

**示例 1**

```text
输入：s = "aba"
输出：true
解释：本身就是回文串，不删除任何字符。
```

**示例 2**

```text
输入：s = "abca"
输出：true
解释：可以删除 'c' 得到 "aba"，也可删除 'b' 得到 "aca"。
      首尾 'a' 已经配对，冲突只出现在中间的 "bc" 上。
```

**示例 3**

```text
输入：s = "abc"
输出：false
解释：删 'a' 得 "bc"、删 'b' 得 "ac"、删 'c' 得 "ab"，都不是回文。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「删除哪个字符」（$n$ 种）或不删，对每种结果用双指针判回文。判一次回文 $O(n)$，总计 $O(n^2)$；$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。更差的是用 `s[:i] + s[i+1:]` 真去构造新串：每次 $O(n)$ 拷贝，常数更大。

暴力的问题在于：**它把 $n$ 个删除位置平等对待，没有利用"哪些位置根本不需要删"这一信息**。

### 3.2 核心观察：夹逼到第一次失配，冲突只剩两种可能

![失配处只有两种删法](images/wc50_q1_two_pointer_mismatch.svg)

用双指针 $i=0$、$j=n-1$ 从两端向中间夹逼。只要 $s[i] = s[j]$，这一对字符就已经配对成功，**把它们删掉的方案永远不是必需的**——因为删掉它们只会让内侧区间变大，而内侧仍然要自己配成回文。于是：

$$\text{若 } s[i]=s[j]，\text{则「原题有解」}\iff\text{「} s[i..j] \text{ 删至多一个字符成回文」}$$

继续内移，直到出现**第一处失配** $s[i] \ne s[j]$。此时 $s[i]$ 与 $s[j]$ 不可能同时保留（它们在最终串里会隔空对位），所以解只能出现在两种情形里：

1. **删掉 $s[i]$**：只需检查剩余区间 $s[i+1..j]$ 是不是回文；
2. **删掉 $s[j]$**：只需检查剩余区间 $s[i..j-1]$ 是不是回文。

两者任一成立就返回 `true`，都不成立返回 `false`。由于全程**最多只有一次失配机会**，整个算法只做了一次分支判断，复杂度从 $O(n^2)$ 直接降到 $O(n)$。

### 3.3 算法流程

![算法流程图](images/wc50_q1_decision_flow.svg)

1. 令 $i=0$、$j=n-1$。
2. **循环**：当 $i<j$ 时比较 $s[i]$ 与 $s[j]$；
   - 相等：$i \mathrel{+}= 1$，$j \mathrel{-}= 1$，继续；
   - 不等：立即返回 `isPal(i+1, j) or isPal(i, j-1)`，**循环到此结束**。
3. 循环自然结束（$i \ge j$）说明每一对都配上了，返回 `true`。

其中 `isPal(lo, hi)` 判断**闭区间** $s[lo..hi]$ 是否回文：`while lo < hi` 比较首尾并内移，区间为空（$lo > hi$）或只剩一个字符（$lo = hi$）时直接返回 `true`。正是这个约定，让「失配已发生在最中间」时不必特判。

### 3.4 示例演算

![示例演算](images/wc50_q1_walkthrough.svg)

对 $s = \text{"abca"}$：

| 轮次 | $i$ | $j$ | 比较 | 动作 |
|------|-----|-----|------|------|
| 1 | 0 | 3 | `a` = `a` ✓ | 内移，$i=1$、$j=2$ |
| 2 | 1 | 2 | `b` ≠ `c` ✗ | 失配，拆成两条分支 |

- 分支 A：删 `b`，校验 $s[2..2] = \text{"c"}$，单字符即回文 ✓；
- 分支 B：删 `c`，校验 $s[1..1] = \text{"b"}$，单字符即回文 ✓。

任一成立即 `true`，与官方输出一致。

对 $s = \text{"abc"}$：首轮 $i=0$、$j=2$ 就失配，分支 A 校验 `"bc"` ✗、分支 B 校验 `"ab"` ✗，两条全灭 → `false`。

## 4. 算法细节

1. **`isPal` 用闭区间**：统一写成 `isPal(lo, hi)` + `while (lo < hi)`，不要写成左闭右开，否则「删掉一个字符后只剩空串」这类边界要额外特判。
2. **短路求值**：`return isPal(i+1, j) || isPal(i, j-1)`。C++ 的 `||` 与 Python 的 `or` 天然短路，第一条分支成功时第二条根本不会执行，平均只需一次扫描。
3. **绝不构造新字符串**：`s.substr(0,i) + s.substr(i+1)` 或 Python 的 `s[:i] + s[i+1:]` 是 $O(n)$ 拷贝，放进循环就是 $O(n^2)$。传下标、共用原串即可。
4. **主循环条件 `i < j`**：交叉后退出，说明所有对称位置都已比较完毕；此时无论 $n$ 是奇数还是偶数都返回 `true`。
5. **失配后必须 `return`**：删掉 $s[i]$ 或 $s[j]$ 之后，剩余区间必须**整体**是回文，不存在「删两个」的机会。如果继续循环而不是立即返回，就会退化成允许删多个字符的错误算法。
6. **只比较字符本身**：题目保证小写字母，直接按字节/码点比较即可；若扩展到一般字符（如 `"a."` 的情形）才需要额外的 `isalnum` 过滤。
7. **空间**：全部是下标与临时变量，$O(1)$；不要为了省事把 `list(s)` 或 `s[::-1]` 复制出来，那会变成 $O(n)$ 空间。

## 5. 正确性证明

**引理 1（已配对的外层可以保留）**：设 $i<j$、$s[i]=s[j]$，且 $s[i..j]$ 以外已逐对配对。则 $s$ 能删至多一个字符变成回文 $\iff$ 子串 $s[i..j]$ 能删至多一个字符变成回文。

**证明**：
（$\Leftarrow$）若 $s[i..j]$ 删一个字符后是回文，把它放回原来的位置，外层字符本来就逐对相等，整串仍是回文。
（$\Rightarrow$）设删除下标 $d$ 后得到回文串 $t$（允许 $d = \text{无}$）。
若 $d < i$ 或 $d > j$：删除发生在区间外侧，$s[i]$ 与 $s[j]$ 在 $t$ 中仍互为对称位（左侧删除使其下标各减 1，右侧删除不改变它们），而 $t$ 是回文，于是 $t$ 中 $s[i+1]$ 与 $s[j-1]$ 也互为对称位，继续递推可知 $s[i+1..j-1]$ 本身是回文，于是 $s[i..j]$ **不删任何字符**就是回文。
若 $d \in [i, j]$：把 $t$ 限制在 $s[i..j]$ 上，得到的就是 $s[i..j]$ 删一个字符的结果，且仍是回文。
故两种情形下 $s[i..j]$ 都能删至多一个字符成为回文。∎

**引理 2（失配处只有两种删法）**：设 $i<j$、$s[i] \ne s[j]$，且外层已配对。则 $s$ 能删至多一个字符变成回文 $\iff$ $s[i+1..j]$ 是回文 **或** $s[i..j-1]$ 是回文。

**证明**：
（$\Leftarrow$）删 $s[i]$ 后 $s[i+1..j]$ 为回文，外层配对，整串为回文；删 $s[j]$ 同理。
（$\Rightarrow$）设删除 $d$ 后得到长度 $n-1$ 的回文 $t$。
首先 $d \notin \{i, j\}$ 且 $d < i$ 或 $d > j$ 的情形不可能：由引理 1 的论证，此时 $s[i..j]$ 不删字符也是回文，与 $s[i] \ne s[j]$ 矛盾。而「不删」（$d$ 不存在）同样直接矛盾。故 $d \in [i, j]$。
在 $t$ 中，下标 $i$ 与 $j-1$ 是一对对称位（因为 $i + (j-1) = j + i - 1 = n - 2$，$t$ 长度为 $n-1$），必须满足 $t[i] = t[j-1]$。
- 若 $d = i$：$t[i..j-1] = s[i+1..j]$ 是回文，第一种情形成立；
- 若 $d = j$：$t[i..j-1] = s[i..j-1]$ 是回文，第二种情形成立；
- 若 $i < d < j$：此时 $d > i$ 使 $t[i] = s[i]$，$d \le j-1$ 使 $t[j-1] = s[j]$，于是 $t[i] \ne t[j-1]$，与 $t$ 为回文矛盾，该情形不存在。

综上必有一种分支成立。∎

**引理 3（`isPal` 正确）**：`isPal(lo, hi)` 返回 `true` 当且仅当 $s[lo..hi]$ 是回文串。

**证明**：循环不变式为「$s[lo..hi]$ 是回文 $\iff$ 初始区间是回文」：每轮比较 $s[lo]$ 与 $s[hi]$，不相等立即返回 `false`（正确）；相等则两端已确定配对，问题等价收缩为 $s[lo+1..hi-1]$。循环退出时 $lo \ge hi$，区间为空或单字符，必为回文，返回 `true`。∎

**定理**：`validPalindrome(s)` 返回 `true` 当且仅当 $s$ 能通过删除至多一个字符变成回文。

**证明**：
若主循环走完全程（$i \ge j$），每一对对称位置都相等，$s$ 本身是回文，删 0 个字符即可，返回 `true` 正确。
否则设循环在 $(i,j)$ 处失配，且此前所有外层对都已配对。由引理 1，$s$ 可解 $\iff$ $s[i..j]$ 可删至多一个字符成回文；由引理 2，后者 $\iff$ $s[i+1..j]$ 回文或 $s[i..j-1]$ 回文；由引理 3，`isPal` 对这两个区间的判定是精确的，代码恰好返回二者的逻辑或。故返回值与题意等价。∎

## 6. 复杂度分析

- **时间**：$O(n)$。夹逼阶段每轮至少内移一个指针，最多 $\lceil n/2 \rceil$ 轮；失配后至多调用两次 `isPal`，每次最多扫完剩余区间，故总比较次数不超过 $\frac{3n}{2}$ 量级。
- **空间**：$O(1)$。只用 $i$、$j$、`lo`、`hi` 四个下标与若干临时变量，没有递归、没有子串拷贝。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    // 判断闭区间 s[lo..hi] 是否为回文串
    bool isPal(const string& s, int lo, int hi) {
        while (lo < hi) {
            if (s[lo] != s[hi]) return false;
            ++lo;
            --hi;
        }
        return true;
    }

    bool validPalindrome(string s) {
        int i = 0, j = (int)s.size() - 1;
        while (i < j) {
            if (s[i] != s[j]) {
                // 只有两种选择：删 s[i] 或删 s[j]
                return isPal(s, i + 1, j) || isPal(s, i, j - 1);
            }
            ++i;
            --j;
        }
        return true;   // 全程无失配，本身就是回文
    }
};
```

### Python

```python
class Solution:
    def validPalindrome(self, s: str) -> bool:
        def is_pal(lo: int, hi: int) -> bool:
            # 闭区间 [lo, hi]，lo > hi 表示空区间，直接算回文
            while lo < hi:
                if s[lo] != s[hi]:
                    return False
                lo += 1
                hi -= 1
            return True

        i, j = 0, len(s) - 1
        while i < j:
            if s[i] != s[j]:
                # 要么删 s[i]，要么删 s[j]；短路：前者成立就不查后者
                return is_pal(i + 1, j) or is_pal(i, j - 1)
            i += 1
            j -= 1
        return True
```

## 8. 边界情况与易错点

1. **长度为 1**：`"a"` → 主循环条件 `i < j` 不成立，直接 `true`。不要写成 `while i <= j`，否则 `isPal` 会被传入越界下标。
2. **本身已是回文**：`"aba"`、`"abba"` → 走完整趟返回 `true`。题目是「最多」删一个，**允许不删**，别漏掉这条路径。
3. **删完只剩一个字符甚至空串**：`"ab"` → 删任一个得单字符，是回文；`isPal` 中 `lo > hi` 必须返回 `true`，若写成 `lo == hi` 判断会出错。
4. **失配发生在最中间**：`"abca"` 中 $i=1$、$j=2$，两条分支的校验区间都退化为单字符 `"c"` / `"b"`，必须判为回文，不能因为「区间长度 1」而特殊处理成 `false`。
5. **失配后不能再删第二个字符**：`"abc"`、`"abcda"` 这类串在失配后若继续内移循环，就会误判为 `true`。失配处的两条分支必须各自**整体**判回文，并在判定后立刻返回。
6. **不要真的构造删除后的串**：`s[:i] + s[i+1:]` 是 $O(n)$ 拷贝，若在循环里尝试 $n$ 次就退化到 $O(n^2)$，$n=10^5$ 时必然超时。
7. **$n = 10^5$ 的最坏分支**：如 `"a" * 50000 + "b" + "a" * 49999` 这类只在尾部附近失配的串，夹逼要走约 $5\times10^4$ 轮，随后 `isPal` 还要扫一遍——总计仍是 $O(n)$，不要误以为需要记忆化。
8. **C++ 下标类型**：`s.size()` 是无符号类型，`int j = s.size() - 1` 在 $n=0$ 时会回绕；本题 $n \ge 1$，但写成 `(int)s.size() - 1` 更稳。

**延伸思考**：把「最多一个」换成「最多 $k$ 个」，双指针 + 记忆化的解形式是 $f(i,j,k)$：$s[i]=s[j]$ 时转向 $f(i+1,j-1,k)$，否则取 $f(i+1,j,k-1)$ 与 $f(i,j-1,k-1)$ 的或；状态数 $O(nk)$。本题正是 $k=1$ 的特殊情形——因为只剩一次删除机会，两条分支各自必须是**完整回文**，不需要再递归，所以能压到 $O(n)$ 且只用 $O(1)$ 空间。另一个可迁移的模板是：**当暴力枚举的 $O(n)$ 个候选里，绝大多数被"前缀已配对"这一不变量排除时，贪心夹逼往往能把候选集缩到常数个**。
