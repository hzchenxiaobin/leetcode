# LeetCode 键值映射 题解

## 1. 题目概述

- **标题 / 题号**：键值映射（#677，medium）
- **链接**：https://leetcode.cn/problems/map-sum-pairs/
- **来源**：LeetCode 第 50 场周赛 Q2
- **难度**：中等
- **标签**：设计，字典树，哈希表，字符串

**题意**：实现 `MapSum` 类，维护「字符串键 → 整数」的映射。`insert(key, val)` 插入键值对；若 `key` **已存在，则用新值覆盖旧值**（不是累加）。`sum(prefix)` 返回所有以 `prefix` 为前缀的键的**当前值之和**。

**约束**：

- $1 \le \lvert key \rvert, \lvert prefix \rvert \le 50$
- `key`、`prefix` 仅由小写英文字母组成
- $1 \le val \le 1000$
- `insert` 与 `sum` 合计最多调用 50 次

## 2. 示例

**示例 1**

```text
输入：
["MapSum", "insert", "sum", "insert", "sum"]
[[], ["apple", 3], ["ap"], ["app", 2], ["ap"]]
输出：[null, null, 3, null, 5]
解释：
mapSum.insert("apple", 3);
mapSum.sum("ap");           // 3，只有 apple 以 ap 为前缀
mapSum.insert("app", 2);
mapSum.sum("ap");           // 5，apple + app = 3 + 2
```

**示例 2（覆盖语义）**

```text
输入：
["MapSum", "insert", "insert", "sum"]
[[], ["apple", 3], ["apple", 10], ["app"]]
输出：[null, null, null, 10]
解释：第二次 insert("apple", 10) 覆盖旧值 3，前缀 app 的答案从 3 变成 10。
```

**示例 3（前缀无匹配）**

```text
输入：
["MapSum", "insert", "sum", "sum"]
[[], ["apple", 3], ["b"], ["applee"]]
输出：[null, null, 0, 0]
解释：没有任何键以 "b" 或 "applee" 开头，返回 0；后者说明前缀比键长也算无匹配。
```

## 3. 解题思路

### 3.1 暴力思路

用一个哈希表 `mp: key → val` 存所有键值对，`insert` 直接覆盖即可 $O(1)$；但 `sum(prefix)` 只能**枚举全部键**，对每个键判断是否以 `prefix` 开头（比较 $O(\lvert prefix \rvert)$ 个字符）再累加：

- 单次 `sum`：$O(n \cdot \lvert prefix \rvert)$，其中 $n$ 是不同键的个数；
- 本题 $n \le 50$、调用 $\le 50$ 次，暴力完全能过。

之所以还要写更优解：一旦把调用规模放大到 $10^5$ 次、每次 50 个键长 50 的键，扫描量就是 $10^5 \times 50 \times 50 = 2.5\times10^{8}$ 起步，且**同一前缀被反复查询时做了大量重复工作**。前缀天然是「树上的路径」，用字典树可以把单次查询压到 $O(\lvert prefix \rvert)$。

### 3.2 核心观察：前缀 = 字典树上的一条路径

![字典树：前缀对应路径，节点存子树值之和](images/wc50_q2_trie_prefix_concept.svg)

把每个键逐字符插入一棵 26 叉字典树，**键就是根到某个节点的路径**。所有以 `prefix` 为前缀的键，恰好是从「`prefix` 结尾节点」出发的整棵子树中的那些「键终止节点」。

**关键设计**：在每个节点 $v$ 上维护

$$\text{sum}(v) = \sum_{\substack{\text{key} \text{ 以 } P(v) \text{ 为前缀}}} \text{val}[\text{key}]$$

其中 $P(v)$ 是根到 $v$ 拼出的字符串。于是 `sum(prefix)` 只需要**沿路径走 $\lvert prefix \rvert$ 步，读一个整数**。

难点在于「覆盖」。设键 `key` 的旧值为 $old$，新值为 $val$：

$$\Delta = val - old$$

那么「以 $P(v)$ 为前缀的键值之和」中，`key` 的贡献恰好变化 $\Delta$，而 $P(v)$ 是 `key` 前缀的那些节点，正好是 `key` 路径上的全部节点（含根）。所以一次 `insert` 就是把 $\Delta$ **加到整条路径上**，和朴素地把每个键的值全量重算相比，省掉了遍历子树。

### 3.3 算法流程

![insert 沿路径累加增量，sum 沿路径读取节点和](images/wc50_q2_insert_sum_flow.svg)

- `insert(key, val)`：`old = mp.get(key, 0)`，$\Delta = val - old$，`mp[key] = val`；从根出发逐字符下沉，缺失节点就地新建，每到一个节点就 `sum[node] += Δ`。
- `sum(prefix)`：从根出发逐字符下沉；**中途没有对应子节点则直接返回 0**（说明没有任何键以它为前缀）；走到头后返回该节点的 `sum`。
- 根节点的 `sum` 维护的是空串前缀（全部键值之和），题目保证 $\lvert prefix \rvert \ge 1$，用不到，但一起加 $\Delta$ 也无害。

### 3.4 示例演算

![示例走查：增量沿路径累加](images/wc50_q2_example_walkthrough.svg)

| 步骤 | 操作 | 旧值 | $\Delta$ | 路径节点 $\text{sum}$ 变化 | 结果 |
|------|------|------|----------|---------------------------|------|
| 1 | `insert("apple", 3)` | 0 | 3 | `a` `ap` `app` `appl` `apple` 各 $+3$ | — |
| 2 | `sum("ap")` | — | — | 读节点 `ap` 的 $\text{sum}$ | 3 |
| 3 | `insert("app", 2)` | 0（新键） | 2 | `a` `ap` `app` 各 $+2$ | — |
| 4 | `sum("ap")` | — | — | 读节点 `ap` 的 $\text{sum}$ | 5 |

注意第 1 步与第 3 步都是**新增**键，所以 $old = 0$、$\Delta = val$；若第 3 步改写成 `insert("apple", 2)`，则 $\Delta = 2 - 3 = -1$，路径上的值会相应减少而不是翻倍。

## 4. 算法细节

1. **节点结构**：只存两样东西——26 个子节点指针（或 `map`/`dict`）与一个整数 `sum`。不需要在节点上另存 `val`，因为「键自身」的值已经包含在它终止节点的 `sum` 里。
2. **覆盖靠增量**：必须先查旧值算 $\Delta$，再统一累加；若直接 `sum[node] += val`，重复插入同一个键会把旧值重复计入，是最容易写错的一处。
3. **哈希表的作用**：字典树只能按前缀查，无法按完整键取旧值，所以需要 `mp: key → 当前 val` 与树并存；两者必须在 `insert` 中同步更新。
4. **节点上界**：所有键互不共享时不重复节点数为 $\sum \lvert key \rvert \le 2500$，C++ 既可用 `new` 动态分配，也可开静态数组 `next[MAXN][26]`（$2500 \times 26$ 个 `int` 约 $260$ KB）。
5. **`sum` 的早停**：路径断开立刻返回 0，不必也不能返回根的 `sum`——根的和是全部键之和，不是该前缀的和。
6. **Python 的节点表示**：用两个平行列表 `child`（每项是 `{字符: 节点下标}`）和 `sum`，节点号即下标，追加新节点就是 `append`，比 26 长度定长数组省 26 倍空间，也免去预分配上界。
7. **数值范围**：键值总和最多 $50 \times 1000 = 5\times10^{4}$，`int` 足够；若把键数放大到 $10^{5}$ 级别，应换 `long long`（C++）或依赖 Python 大整数。
8. **字符映射**：统一用 `c - 'a'` 映射到 $[0, 26)$，不要用 `map<char, ...>` 逐节点查，前者是 $O(1)$ 数组下标。

## 5. 正确性证明

**引理 1（节点和的不变量）**：任意时刻、任意节点 $v$，其 `sum` 字段等于当前所有满足「$P(v)$ 是 `key` 的前缀」的键的 $\text{val}[\text{key}]$ 之和；其中 $P(v)$ 表示根到 $v$ 路径拼成的字符串。

**证明**：对操作序列归纳。初始时树中无键，任何节点的前缀集合为空、`sum` 为 0，成立。设某次 `insert(key, val)` 之前不变量成立，记旧值 $old$（不存在则为 0），$\Delta = val - old$。

- 对 `key` 路径上的节点 $v$：$P(v)$ 是 `key` 的前缀，本次操作后 `key` 的贡献由 $old$ 变为 $val$，恰增加 $\Delta$；其余键的贡献不变。代码对该类节点执行 `sum[v] += Δ`，故其 `sum` 仍等于前缀集合的值之和。
- 对不在 `key` 路径上的节点 $v$：$P(v)$ 不是 `key` 的前缀，故 `key` 不属于其前缀集合；其集合与各键值均未变化，`sum` 保持不动，仍然正确。

新建节点初始 `sum = 0` 后再 `+= Δ`，等价于「先建节点再不变量成立」，归纳完成。∎

**引理 2（查询正确）**：`sum(prefix)` 的返回值等于所有以 `prefix` 为前缀的键的当前值之和。

**证明**：分两种情形。

- 路径存在：设走到的末节点为 $v$，则 $P(v) = prefix$，由引理 1，`sum[v]` 正是所求之和。
- 路径在某个字符处断开：此时不存在任何以 `prefix` 为前缀的键。否则该键插入时必然沿这些字符创建过节点，路径不会断开，矛盾。因此正确答案为 0，与返回值一致。∎

**定理**：`MapSum` 的 `insert` 与 `sum` 均返回题目要求的结果。

**证明**：`insert` 的覆盖语义由 `mp[key] = val` 保证（哈希表存的是当前值），树上的节点和由引理 1 保证始终等于前缀值之和；`sum` 由引理 2 保证正确。故两类操作都符合题意。∎

## 6. 复杂度分析

- **时间复杂度**：`insert` 为 $O(\lvert key \rvert)$——逐字符下沉，每步 $O(1)$ 建点与累加，哈希表一次读写平均 $O(1)$；`sum` 为 $O(\lvert prefix \rvert)$——只走一条路径，不遍历子树。合计 $O\big((\lvert key \rvert + \lvert prefix \rvert) \cdot C\big)$，$C$ 为调用次数（本题 $C \le 50$）。
- **空间复杂度**：$O\big(\sum \lvert key \rvert\big)$，即字典树节点数（互不共享时最多 2500 个），再加上哈希表存 $n$ 个键值对（$n \le 50$）。每个节点的孩子表在 C++ 中是定长 26 数组，在 Python 中是「按需增长」的字典。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <unordered_map>
using namespace std;

class MapSum {
    struct Node {
        int sum = 0;
        Node* next[26] = {nullptr};
    };

    Node* root;
    unordered_map<string, int> mp;   // 记录每个键的当前值，用于算覆盖增量

public:
    MapSum() { root = new Node(); }

    void insert(string key, int val) {
        auto it = mp.find(key);
        int old = (it == mp.end() ? 0 : it->second);
        int delta = val - old;       // 覆盖语义：只把差值加到路径上
        mp[key] = val;

        Node* cur = root;
        cur->sum += delta;           // 空串前缀（本题用不到，一并维护）
        for (char c : key) {
            int i = c - 'a';
            if (cur->next[i] == nullptr) cur->next[i] = new Node();
            cur = cur->next[i];
            cur->sum += delta;
        }
    }

    int sum(string prefix) {
        Node* cur = root;
        for (char c : prefix) {
            int i = c - 'a';
            if (cur->next[i] == nullptr) return 0;   // 没有键以该前缀开头
            cur = cur->next[i];
        }
        return cur->sum;
    }
};

/**
 * Your MapSum object will be instantiated and called as such:
 * MapSum* obj = new MapSum();
 * obj->insert(key,val);
 * int param_2 = obj->sum(prefix);
 */
```

### Python

```python
class MapSum:

    def __init__(self):
        self.child = [{}]    # child[i] = {字符: 子节点下标}
        self.total = [0]     # total[i] = 以该节点路径为前缀的键值之和
        self.vals = {}       # 键 -> 当前值，用于计算覆盖增量

    def insert(self, key: str, val: int) -> None:
        old = self.vals.get(key, 0)
        delta = val - old
        self.vals[key] = val

        node = 0
        self.total[node] += delta
        for ch in key:
            nxt = self.child[node].get(ch)
            if nxt is None:
                nxt = len(self.child)
                self.child[node][ch] = nxt
                self.child.append({})
                self.total.append(0)
            node = nxt
            self.total[node] += delta

    def sum(self, prefix: str) -> int:
        node = 0
        for ch in prefix:
            node = self.child[node].get(ch, -1)
            if node == -1:
                return 0         # 路径断开，说明没有键以该前缀开头
        return self.total[node]


# Your MapSum object will be instantiated and called as such:
# obj = MapSum()
# obj.insert(key,val)
# param_2 = obj.sum(prefix)
```

## 8. 边界情况与易错点

1. **重复插入同一个键**：必须用 $\Delta = val - old$ 做覆盖，直接 `+= val` 会让旧值残留、结果偏大。这是本题唯一的高频错误。
2. **前缀无匹配**：路径断开时返回 0，不能返回根节点的和（那是全部键之和）；前缀比所有键都长（如示例 3 的 `"applee"`）同样走断路径分支。
3. **一个键是另一个键的前缀**：`"app"` 与 `"apple"` 并存时，`sum("app")` 要包含两者，说明节点和必须把「终止于本节点的键」也计入，不能只累加子节点。
4. **覆盖为更小的值**：$\Delta$ 可能为负，Python 无需处理；C++ 用 `int` 也安全（和最大 $5\times10^{4}$），但若换成无符号类型会下溢。
5. **`sum("")` 不存在**：题面保证 $\lvert prefix \rvert \ge 1$，所以根节点不被查询；若自行扩展支持空前缀，根的和应等于全部键值之和——代码已顺手维护，行为自洽。
6. **内存上界**：C++ 用 `new` 时注意最多 2500 个节点，无需 `delete`；若开固定数组，$2500 \times 26$ 即可，不要按 $50 \times 50 \times 26$ 再乘调用次数。
7. **Python 的 `dict.get(ch, -1)`**：节点下标从 0 开始，所以哨兵必须用 `-1` 或 `None`，不能用 `0`，否则会误判为回到根。
