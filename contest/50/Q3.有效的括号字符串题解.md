# LeetCode 有效的括号字符串 题解

## 1. 题目概述

- **标题 / 题号**：有效的括号字符串（#678，medium）
- **链接**：https://leetcode.cn/problems/valid-parenthesis-string/
- **来源**：LeetCode 第 50 场周赛 Q3
- **难度**：中等
- **标签**：栈、贪心、字符串、动态规划、括号序列

**题意**：给定只含 `(`、`)`、`*` 三种字符的字符串 `s`，其中每个 `*` 可以独立地被替换成单个 `(`、单个 `)` 或**空串**。问是否存在一种替换方案，使替换后的括号串**合法**：任意前缀里 `)` 的个数都不超过 `(`，且整串左右括号数量相等。

**约束**：

- $1 \le \lvert s \rvert \le 100$
- `s[i]` 为 `(`、`)` 或 `*`
- `*` 的次数没有额外限制，所以「替换成空串」永远是一个可选项

## 2. 示例

**示例 1**

```text
输入：s = "()"
输出：true
解释：本来就合法，不需要任何替换。
```

**示例 2**

```text
输入：s = "(*)"
输出：true
解释：把 * 替换成空串得到 "()"，合法。
```

**示例 3**

```text
输入：s = "(*))"
输出：true
解释：把 * 替换成 '(' 得到 "(())"，合法。
      另两种选择都不行：换成空串得 "())"，换成 ')' 得 "()))"，
      两者都会留下无法配对的 ')'。
```

**示例 4**

```text
输入：s = "("
输出：false
解释：没有字符能给这个左括号收尾，替换后余额永远不为 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 `*` 独立枚举三种解释，共 $3^{k}$ 种方案（$k$ 为 `*` 的个数），逐个按栈校验合法性：$O(3^{k} \cdot n)$。$n = 100$ 时 $3^{50}$ 级别的搜索完全不可行。

稍微正经一点的替代方案有三种：

1. **区间 DP**：`dp[i][j]` 表示 `s[i..j]` 能否被解释成「合法括号序列」，转移枚举切分点 $k$，$O(n^3)$；`n = 100` 时约 $10^6$，能过但不算优雅。
2. **余额 DP**：`dp[i][b]` 表示「前 $i$ 个字符能否以余额 $b$ 收尾」，状态 $n \times n$、转移 $O(1)$，$O(n^2)$ 时间与空间，同样能过。
3. **双栈**：一个栈存 `(` 的下标，一个栈存 `*` 的下标，遇 `)` 优先弹 `(`、否则弹 `*`，最后让 `*` 去配剩余的 `(`。思路对，但实现细节多、容易写错。

它们都有个共同毛病：**记了太多信息**。我们其实不关心「哪一种解释能成」，只关心「还有哪些余额活着」。

### 3.2 核心观察：活着的余额是「一段」而不是散点

![核心观察：用区间表示所有可能的未匹配左括号数](images/wc50_q3_state_interval.svg)

把「当前未匹配左括号数」称为**余额**。扫描到某个前缀时，不同的 `*` 解释会得到不同的余额，但这些余额**恰好组成一段连续的整数区间** $[lo, hi]$：

- `(` 只能让余额 $+1$，整个区间右移一格；
- `)` 让余额 $-1$，区间左移一格；余额变成 $-1$ 的那些解释此后**永久作废**（它已经违反了「任意前缀 `)` 不超过 `(`」），所以左端可以直接夹到 $0$；
- `*` 产生「$-1$、$0$、$+1$」三种效果，等价于把区间向两侧各撑一格。

「连续整数区间经过平移、扩张、剪掉负半轴后仍然是连续整数区间」——这就是能只用两个数描述全部 $3^{k}$ 种解释的原因。于是状态从 $O(n)$ 个布尔值压缩成两个整数：最悲观的余额 $lo$ 与最乐观的余额 $hi$。

一旦 $hi < 0$，说明**连最乐观的解释**（把所有 `*` 都当 `(`）都还不上这串右括号，可以直接返回 `false`。

### 3.3 算法流程

![贪心区间：一遍扫描的算法流程](images/wc50_q3_greedy_flow.svg)

```text
lo = hi = 0
for c in s:
    if c == '(' → lo += 1, hi += 1
    if c == ')' → lo = max(lo - 1, 0), hi -= 1
    if c == '*' → lo = max(lo - 1, 0), hi += 1
    if hi < 0 → return false          // 右端被击穿，任何解释都失败
return lo == 0                        // 0 落在 [lo, hi] 内即存在解释
```

两个收尾条件要区分清楚：

- **循环中**只需检查 $hi < 0$，它代表「区间空了」；
- **循环结束**要检查 $lo = 0$，因为 $lo \ge 0$ 恒成立，「$0 \in [lo, hi]$」恰好等价于 $lo = 0$（$hi \ge 0$ 已由循环中的检查保证）。

### 3.4 示例演算

![示例演算：s = "(*))" 的区间走查](images/wc50_q3_example_walkthrough.svg)

对 `s = "(*))"` 走一遍：

| 步骤 | 字符 | 区间更新 | lo | hi | 说明 |
|------|------|----------|----|----|------|
| 初始 | — | $lo = hi = 0$ | 0 | 0 | 空串只有余额 0 |
| $i=0$ | `(` | $lo+1$，$hi+1$ | 1 | 1 | 区间整体右移 |
| $i=1$ | `*` | $lo=\max(lo-1,0)$，$hi+1$ | 0 | 2 | 向两侧各撑一格 |
| $i=2$ | `)` | $lo=\max(lo-1,0)$，$hi-1$ | 0 | 1 | $hi$ 降，$lo$ 夹回 0 |
| $i=3$ | `)` | $lo=\max(lo-1,0)$，$hi-1$ | 0 | 0 | $hi$ 归 0，恰好收平 |
| 结束 | — | $lo = 0 \Rightarrow 0 \in [lo, hi]$ | 0 | 0 | 返回 `true` |

对应的解释就是把 $i=1$ 的 `*` 当成 `(`，得到 `(())`，前缀余额依次为 $1, 2, 1, 0$，全程非负且结尾归零。

## 4. 算法细节

1. **`lo` 为什么能直接夹到 0**：余额为负的解释已经违反「任意前缀 `)` 不超过 `(`」，之后再加 `(` 也无法撤销这个既成事实，所以这类解释永久死亡。而剩余余额仍是连续区间，与 $[0, +\infty)$ 求交后左端点正好是 $\max(lo-1, 0)$。
2. **必须先更新、再判断 $hi < 0$**：`hi` 的递减只发生在 `)` 上，但判断要放在每轮末尾，这样写一处检查就覆盖全部情况，也不依赖字符类型。
3. **收尾用 `lo == 0` 而不是 `lo <= 0`**：`lo` 全程被夹在 $0$ 以上，`lo <= 0` 在当前实现里恒真，是典型的「看着对、其实恒返回 true」的坑。
4. **不需要统计 `*` 的个数**：`*` 可以当空串，所以它既不消耗也不强制产生括号，数量不构成约束；只有「当作 `(` 或 `)`」时它才影响余额区间。
5. **整数范围**：$lo, hi \le \lvert s \rvert \le 100$，`int` 完全够用，无需 `long long`。
6. **空间只需两个变量**：整个过程是流式的，不需要栈、不需要数组，读完字符即可丢弃，$O(1)$ 额外空间。

## 5. 正确性证明

对前缀 $s[0..i)$，称一个整数 $b$ 是**可行余额**，若存在对其中 `*` 的解释，使得该前缀的每个前缀（$s[0..j)$，$0 \le j \le i$）余额都非负，且 $s[0..i)$ 的余额等于 $b$。

**引理 1（可行余额集合恰为区间，且按三条规则递推）**：设前 $i$ 个字符的可行余额集合为 $S_i$，则 $S_i = [lo_i, hi_i] \cap \mathbb{Z}$，其中 $lo_i, hi_i$ 正是算法维护的值。

**证明**：对 $i$ 归纳。$S_0 = \{0\} = [0,0]$，成立。设 $S_i = [lo, hi]$：

- 若 $s[i] = ($：每种解释的余额都 $+1$，$S_{i+1} = [lo+1, hi+1]$，与 `lo += 1, hi += 1` 一致；
- 若 $s[i] = )$：余额都 $-1$，得到 $[lo-1, hi-1]$；其中为负的代表该解释在某个前缀出现负余额，已违反合法性且不可挽回，删除后 $S_{i+1} = [\max(lo-1,0), hi-1]$（若 $hi-1 < 0$ 则为空集），与更新规则一致；
- 若 $s[i] = *$：三种解释给出 $[lo-1, hi-1] \cup [lo, hi] \cup [lo+1, hi+1] = [lo-1, hi+1]$，再删去负值得 $[\max(lo-1,0), hi+1]$，与更新规则一致。

三处都保持「连续整数区间」，故归纳成立。∎

**引理 2（前缀无解则整体无解）**：若某个前缀的 $S_i = \varnothing$（即 $hi_i < 0$），则整个 $s$ 不存在合法解释。

**证明**：设存在某个对全部字符的解释使整串合法，则它限制在前缀 $s[0..i)$ 上时每个前缀余额都非负，于是该解释对应的余额属于 $S_i$，$S_i$ 不可能为空，矛盾。∎

**定理**：算法返回 `true` 当且仅当 $s$ 是有效括号字符串。

**证明**：

- （$\Leftarrow$）设存在合法解释，其第 $i$ 步余额为 $b_i$。由合法性，$b_i \ge 0$ 且 $b_0 = 0$，故由引理 1 的精确性有 $b_i \in S_i$，所有 $S_i$ 非空，算法不会中途返回 `false`。又 $b_n = 0 \in S_n$，由引理 1 的连续性得 $lo_n \le 0$；而算法始终把 $lo$ 夹在 $0$ 以上，故 $lo_n = 0$，返回 `true`。
- （$\Rightarrow$）算法返回 `true` 意味着 $S_n \ne \varnothing$ 且 $lo_n = 0$，即 $0 \in S_n$。由 $S_n$ 的定义，存在一种对 `*` 的解释，使该串每个前缀余额非负、整串余额为 $0$，这正是有效括号字符串的定义。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符做一次常数次比较与加减，共一轮扫描；$n \le 100$，实际耗时与输入长度线性相关。
- **空间**：$O(1)$。只维护 $lo$、$hi$ 两个整数，不构造替换后的字符串、不开栈或数组，因此额外空间与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    bool checkValidString(string s) {
        int lo = 0, hi = 0;              // 未匹配 '(' 数的可行区间 [lo, hi]
        for (char c : s) {
            if (c == '(') {
                ++lo;
                ++hi;                    // 区间整体右移
            } else if (c == ')') {
                lo = max(lo - 1, 0);     // 余额为负的解释永久作废
                --hi;
            } else {                     // c == '*'
                lo = max(lo - 1, 0);     // 当 '(' / 空串 / ')' → 区间向两侧各撑一格
                ++hi;
            }
            if (hi < 0) return false;    // 连最乐观的解释都出现负余额
        }
        return lo == 0;                  // 0 ∈ [lo, hi] 且 lo ≥ 0
    }
};
```

### Python

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        lo = hi = 0                      # 可行余额区间 [lo, hi]
        for c in s:
            if c == '(':
                lo += 1
                hi += 1
            elif c == ')':
                lo = max(lo - 1, 0)      # 负数余额的解释已经非法，夹到 0
                hi -= 1
            else:                        # '*'
                lo = max(lo - 1, 0)
                hi += 1
            if hi < 0:                   # 最乐观的解释都被击穿
                return False
        return lo == 0                   # 0 在区间内 ⇔ lo == 0
```

## 8. 边界情况与易错点

1. **全是 `*`**：如 `"***"`，区间一路扩张到 $[0,3]$，结尾 `lo = 0` 返回 `true`（每个 `*` 当空串即可）；若误用 `hi == 0` 收尾就会错判。
2. **只有右括号**：`")"` 在第一步就让 $hi = -1$，必须能立即返回 `false`，不能等到结尾才判断。
3. **只有左括号**：`"("` 结束于 $lo = hi = 1$，`lo != 0` 返回 `false`；`"((*"` 则返回 `true`（`*` 当 `)`）。
4. **`hi` 已归 0 但还没读完**：如 `"()"` 后接 `"("`，$hi$ 会重新变大，说明中间为 0 不代表提前收工，必须扫完再判断。
5. **`lo` 夹 0 的时机**：只对 `)` 和 `*` 生效，`(` 分支绝不能夹 0，否则会漏掉「必须先补左括号」的情形。
6. **不要用 `lo <= 0` 收尾**：由于 `lo` 始终被夹在非负区间，这个条件恒为真，是最常见的 WA 来源。
