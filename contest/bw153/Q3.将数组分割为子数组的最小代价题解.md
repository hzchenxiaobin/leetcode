# LeetCode 将数组分割为子数组的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：将数组分割为子数组的最小代价（#3500，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-divide-array-into-subarrays/
- **来源**：LeetCode 第 153 场双周赛 Q3
- **难度**：困难
- **标签**：数组、动态规划、前缀和、Li Chao 树

**题意**：给定两个长度相同的数组 `nums`、`cost` 和整数 $k$。把 `nums` 划分成若干**非空连续子数组**，若第 $i$ 个子数组（$i$ 从 **1** 开始计数）覆盖区间 $[l, r]$，则它的代价为

$$\Big(\sum_{p=0}^{r} nums[p] + k \cdot i\Big) \cdot \sum_{p=l}^{r} cost[p].$$

注意第一个因子用的是 **`nums` 从头到 $r$ 的前缀和**（不是子数组自身的和），第二个因子是该子数组的 `cost` 之和。求所有划分方案中的最小总代价。

**约束**：

- $1 \le n \le 1000$
- $cost.length = nums.length$
- $1 \le nums[i], cost[i] \le 1000$
- $1 \le k \le 1000$

> ⚠️ 代价里的 $k \cdot i$ 与**子数组序号**绑定，序号取决于「前面切了几刀」，这是本题不能直接套普通区间 DP 的原因。

## 2. 示例

**示例 1**

```text
输入：nums = [3,1,4], cost = [4,6,6], k = 1
输出：110
解释：划分为 [3,1] 和 [4]：
  第 1 段 [3,1]：(3+1 + 1×1) × (4+6) = 5 × 10 = 50
  第 2 段 [4]  ：(3+1+4 + 1×2) × 6 = 10 × 6 = 60
  总代价 110。其他划分（如整段一段）为 (3+1+4+1)×16 = 144，更大。
```

**示例 2**

```text
输入：nums = [4,8,5,1,14,2,2,12,1]
     cost = [7,2,8,4,2,2,1,1,2]
     k = 7
输出：985
解释：最优划分为 [4,8,5,1]、[14,2,2]、[12,1]：
  (18 + 7×1) × 21 = 525
  (36 + 7×2) ×  5 = 250
  (49 + 7×3) ×  3 = 210
  合计 985。
```

**示例 3（自造，单元素）**

```text
输入：nums = [2], cost = [3], k = 100
输出：306
解释：只能分成一段，且它是第 1 段：
      (2 + 100×1) × 3 = 102 × 3 = 306。
```

## 3. 解题思路

### 3.1 暴力思路

划分方案共 $2^{n-1}$ 种，$n = 1000$ 时不可能枚举。

一个自然的 DP 是「记下已经切了几段」：设 $f(i, c)$ 表示从下标 $i$ 开始、下一段序号为 $c$ 时的最小代价，则

$$f(i, c) = \min_{j \ge i} \Big[\big(P[j] + k c\big)\big(C[j+1] - C[i]\big) + f(j+1, c+1)\Big],$$

状态数 $O(n^2)$、转移 $O(n)$，总共 $O(n^3) = 10^9$，太慢。必须把「序号」这一维消掉。

### 3.2 核心观察：序号整体 +1 的代价增量 = $k \times$ 后缀 cost 和

![后缀 DP：编号整体 +1 的代价增量 = k × 后缀 cost 之和](images/bw153_q3_suffix_dp.svg)

关键是把「后缀」当成一个**独立的小问题**来看：定义

$$dp[i] = \text{把 } nums[i..n-1] \text{ 切分，且这段后缀的第一段编号为 } 1 \text{ 时的最小代价}.$$

现在考虑整体：先切出第一段 $[i, j]$（编号 1，代价可算），剩下的 $nums[j+1..n-1]$ 是一个后缀问题，但它的段编号整体**后移了 1**（原来是 $1, 2, \dots$，现在变成 $2, 3, \dots$）。

一次「编号整体 +1」会改变什么？每段的代价里只有 $k \cdot i$ 这一项与 $i$ 有关，第 $i'$ 段加上 $k \cdot 1$ 后代价增加 $k \times (\text{该段的 cost 之和})$。把所有段加起来：

$$\text{总增量} = k \times \sum_{\text{后缀所有元素}} cost[p] = k\big(C[n] - C[j+1]\big).$$

**增量与怎么切完全无关**，只与「后缀的 cost 总和」有关——这就是消掉序号维度的关键。于是

$$dp[i] = \min_{j=i}^{n-1}\Big[\big(P[j] + k\big)\big(C[j+1] - C[i]\big) + dp[j+1] + k\big(C[n] - C[j+1]\big)\Big],$$

其中 $P[j] = nums[0] + \dots + nums[j]$、$C[i] = cost[0] + \dots + cost[i-1]$（前缀和数组）。$dp[n] = 0$，倒序计算，答案 $dp[0]$。

### 3.3 算法流程

![转移方程：把「第一段」和「余下后缀」拆开算](images/bw153_q3_derivation.svg)

```text
1. 预处理 P[j]（nums 前缀和）与 C[i]（cost 前缀和，C[0] = 0）
2. dp[n] ← 0
3. for i = n-1 down to 0:
4.     dp[i] ← +∞
5.     for j = i .. n-1:
6.         cur ← (P[j] + k) × (C[j+1] − C[i])
7.              + dp[j+1]
8.              + k × (C[n] − C[j+1])
9.         dp[i] ← min(dp[i], cur)
10. 返回 dp[0]
```

### 3.4 示例演算

![示例 1 演算：nums=[3,1,4]，cost=[4,6,6]，k=1](images/bw153_q3_walkthrough.svg)

$P = [3, 4, 8]$，$C = [0, 4, 10, 16]$，`dp[3] = 0`。

| $i$ | 候选 $j$ 与取值 | $dp[i]$ |
|---|---|---|
| 3 | 后缀为空 | 0 |
| 2 | $j=2$：$(8+1)\times 6 = 54$ | 54 |
| 1 | $j=1$：$5\times 6 + 54 + 1\times 6 = 90$；$j=2$：$9\times 12 = 108$ | 90 |
| 0 | $j=0$：$4\times 4 + 90 + 12 = 118$；$j=1$：$5\times 10 + 54 + 6 = 110$；$j=2$：$9\times 16 = 144$ | **110** |

以 $dp[0]$ 的 $j=1$ 为例逐步核对：第一段取 `[3,1]`，权重 $P[1] + k = 4 + 1 = 5$，乘该段 cost 和 $C[2]-C[0] = 10$，得 50；余下后缀从下标 2 开始，$dp[2] = 54$ 是按「编号 1」算的，整体后移一位要加 $k \times (C[3]-C[2]) = 1 \times 6 = 6$，于是 $50 + 54 + 6 = 110$——正是题面给出的最优方案。

## 4. 算法细节

1. **前缀和的定义要对齐**：$P[j]$ 是 `nums[0..j]` 的前缀和（含 $j$），$C[i]$ 是 `cost[0..i-1]` 的前缀和（不含 $i$）。这样 $[i,j]$ 的 cost 和就是 $C[j+1]-C[i]$，取 $j=n-1$ 时自然得到 $C[n]$。
2. **第一段的权重是 $P[j] + k$**：$i=1$ 时 $k\cdot i = k$，别写成 $P[j] + k\cdot \text{(前面已切段数}+1)$，因为我们把后缀的编号重置为 1 了。
3. **倒序计算**：$dp[i]$ 依赖所有 $dp[j+1]$（$j \ge i$），即下标更大的状态，故从 $n-1$ 往 0 算；$dp[n]=0$ 是边界。
4. **全部用 `long long`**：单次乘积上界约 $(10^6 + 10^3)\times 10^6 \approx 10^{12}$，累加后仍在 $10^{12}$ 量级，`int` 会溢出；Python 天然大整数，无需处理。
5. **$O(n^2)$ 足够**：$n \le 1000$ 时转移次数 $n(n+1)/2 \approx 5\times 10^5$，实测 C++ 5 ms 内完成。
6. **可优化到 $O(n\log n)$**：把转移写成线性函数形式 $dp[i] = \min_j\big[(P[j]C[j+1] + dp[j+1] + kC[n]) - (P[j]+k)C[i]\big]$，即「斜率 $-(P[j]+k)$、截距 $P[j]C[j+1] + dp[j+1] + kC[n]$」的一组直线在 $x = C[i]$ 处取最小。$P[j]$ 随 $j$ 递增、$C[i]$ 随 $i$ 递减，属于单调凸包 / Li Chao 树的经典场景（题目标签里的 Li Chao 树即指此），但本场数据范围下不必这么写。

## 5. 正确性证明

**引理 1（编号平移引理）**：把一个已经切好的后缀（段编号为 $1,2,\dots,s$）整体后移一位变成 $2,3,\dots,s+1$，总代价恰好增加 $k \cdot \Sigma$，其中 $\Sigma$ 是该后缀中所有元素的 `cost` 之和。

**证明**：第 $i'$ 段的代价为 $\big(P[r_{i'}] + k i'\big)\cdot \Sigma_{i'}$，其中 $\Sigma_{i'}$ 是该段的 cost 和。编号 $i' \to i'+1$ 使该段代价增加 $(ki' + k - ki')\Sigma_{i'} = k\Sigma_{i'}$。对所有段求和得 $k\sum_{i'}\Sigma_{i'} = k\Sigma$，与切法无关。∎

**引理 2（转移完备）**：任意划分都对应某个 $j$，使得「第一段是 $[i,j]$、其余部分由某个后缀划分接上」；反之，任取 $j$ 与任意后缀划分都拼成一个合法划分。

**证明**：合法划分的第一段必然是某个 $[i,j]$（$i \le j \le n-1$，非空）。剩下的 $[j+1, n-1]$ 的划分方案与原划分的其余段一一对应；第一段固定后，编号的偏移由引理 1 唯一确定。反向拼接显然合法。∎

**定理**：$dp[i]$ 等于把 $nums[i..n-1]$ 切分（第一段编号为 1）的最小代价，故 $dp[0]$ 即为题目所求。

**证明**：对后缀长度 $L = n - i$ 作归纳。

- $L = 0$：无可切分元素，代价 0，$dp[n] = 0$ 正确。
- $L \ge 1$：设最优划分的第一段为 $[i, j]$。其代价为 $(P[j] + k)\,(C[j+1]-C[i])$；其余段构成 $nums[j+1..]$ 的一个划分，按引理 1，其余段的总代价 $=$（以编号 1 计的总代价）$+\,k(C[n]-C[j+1])$。由归纳假设，「以编号 1 计的总代价」的最小值就是 $dp[j+1]$。故最优值等于该 $j$ 对应的转移值；对所有可能的 $j$ 取最小即得 $dp[i]$。由引理 2 枚举 $j$ 不漏任何划分，故 $dp[i]$ 恰为最小值。∎

**推论**：$dp[0]$ 是原问题的最小总代价。

## 6. 复杂度分析

- **时间**：$O(n^2)$。前缀和预处理 $O(n)$；状态数 $n+1$，每个状态枚举 $O(n)$ 个 $j$，合计 $\frac{n(n+1)}{2} + O(n) = O(n^2)$。$n = 1000$ 时约 $5\times 10^5$ 次转移。
- **空间**：$O(n)$。`P`、`C`、`dp` 三个长度 $O(n)$ 的数组；无二维表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minimumCost(vector<int>& nums, vector<int>& cost, int k) {
        int n = (int)nums.size();
        // P[j] = nums[0..j] 的前缀和；C[i] = cost[0..i-1] 的前缀和
        vector<long long> P(n), C(n + 1, 0);
        for (int i = 0; i < n; ++i) {
            P[i] = (i ? P[i - 1] : 0) + nums[i];
            C[i + 1] = C[i] + cost[i];
        }
        const long long INF = (long long)4e18;
        // dp[i]：把后缀 nums[i..n-1] 切成若干段，且这段后缀的第一段编号为 1 时的最小代价
        vector<long long> dp(n + 1, INF);
        dp[n] = 0;
        for (int i = n - 1; i >= 0; --i) {
            for (int j = i; j < n; ++j) {
                // 第一段为 nums[i..j]，编号 1；其后每段编号整体 +1，总代价增加 k * cost[j+1..n-1]
                long long cur = (P[j] + k) * (C[j + 1] - C[i]) + dp[j + 1] +
                                (long long)k * (C[n] - C[j + 1]);
                dp[i] = min(dp[i], cur);
            }
        }
        return dp[0];
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, nums: list[int], cost: list[int], k: int) -> int:
        n = len(nums)
        # P[j] = nums[0..j] 的前缀和；C[i] = cost[0..i-1] 的前缀和
        P = [0] * n
        C = [0] * (n + 1)
        for i in range(n):
            P[i] = (P[i - 1] if i else 0) + nums[i]
            C[i + 1] = C[i] + cost[i]
        # dp[i]：把后缀 nums[i..n-1] 切成若干段，且这段后缀的第一段编号为 1 时的最小代价
        INF = float('inf')
        dp = [INF] * (n + 1)
        dp[n] = 0
        for i in range(n - 1, -1, -1):
            for j in range(i, n):
                # 第一段为 nums[i..j]，编号 1；其后每段编号整体 +1，总代价增加 k * cost[j+1..n-1]
                cur = (P[j] + k) * (C[j + 1] - C[i]) + dp[j + 1] + k * (C[n] - C[j + 1])
                if cur < dp[i]:
                    dp[i] = cur
        return dp[0]
```

## 8. 边界情况与易错点

1. **第一个因子是 `nums` 的全局前缀和**：不是子数组自己的和。写成 `sum(nums[l..r])` 会全线跑偏。
2. **序号从 1 开始**：示例 1 的 `[3,1]` 权重是 $3+1+1\times 1 = 5$；若误用 0-based 会得到 $(4+0)\times 10 = 40$，最终答案也会错。
3. **漏掉 $k(C[n]-C[j+1])$ 项**：这是最隐蔽的错误——小数据下 `k` 小时偏差不明显，但 `k` 大时会把「切得越少越好」的结论搞反。可用示例 2（$k=7$）验证。
4. **`int` 溢出**：$P[j]\le 10^6$、$C[n]\le 10^6$，单次乘积可达 $10^{12}$，必须 `long long`。
5. **$n = 1$**：只有一种划分，`dp[0]` 的循环只有 $j = 0$，直接得 $(nums[0]+k)\cdot cost[0]$。
6. **`INF` 的选择**：C++ 用 $4\times 10^{18}$ 而非 `INT_MAX`，避免与真实值相加时溢出。
7. **下标写法**：$j$ 从 $i$ 而不是 $i+1$ 开始，否则漏掉「第一段是单个元素」的情况。

**延伸思考**：

1. **单调凸包优化**：把转移整理成 $dp[i] = \min_j\big[-(P[j]+k)\,C[i] + b_j\big]$，其中 $b_j = P[j]C[j+1] + dp[j+1] + kC[n]$。$j$ 递增时斜率 $-(P[j]+k)$ 单调递减，查询点 $C[i]$ 随 $i$ 递减也单调，可以用双端队列维护下凸壳把复杂度降到 $O(n)$；若查询点不单调则改用 Li Chao 树得 $O(n\log n)$。
2. **若 `cost` 出现 0**：上述单调性仍成立（$C$ 只是非严格递减），凸包要做「三点共线」处理；本题 $cost[i]\ge 1$ 无此问题。
3. **若允许空子数组**：则最优解可能把某些段拆成空段以抬高/降低编号，问题性质完全改变，需要重新建模。
