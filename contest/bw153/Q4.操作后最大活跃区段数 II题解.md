# LeetCode 操作后最大活跃区段数 II 题解

## 1. 题目概述

- **标题 / 题号**：操作后最大活跃区段数 II（#3501，hard）
- **链接**：https://leetcode.cn/problems/maximize-active-section-with-trade-ii/
- **来源**：LeetCode 第 153 场双周赛 Q4
- **难度**：困难
- **标签**：线段树、数组、字符串、二分查找

**题意**：给定二进制字符串 $s$，以及 $q$ 个查询 `queries[i] = [l, r]`。对每个查询，**只在子串 $s[l..r]$ 上**执行与 I 版相同的操作（最多一次）：

1. 把一个**被 `'0'` 包围**的连续 `'1'` 块翻成 `'0'`；
2. 再把一个**被 `'1'` 包围**的连续 `'0'` 块翻成 `'1'`。

处理后统计**整个字符串 $s$** 中 `'1'` 的个数（活跃区段数）。各查询相互独立，且子串两端各视作补了一个 `'1'`（补的不计入答案）。

**约束**：

- $1 \le n \le 10^5$，$1 \le q \le 10^5$
- $0 \le l_i \le r_i < n$

> ⚠️ **最关键的题意细节**：统计对象是**整个 $s$**，而操作范围只是子串 $[l, r]$。示例 3 的第一个查询 $[1,5]$ 对应子串 `"00010"`（长度 5），答案却是 **6** —— 因为串外下标 0 处的 `'1'` 也被计入。若误以为「只数子串里的 `'1'`」，本题会得到 5 并全面错位。

## 2. 示例

**示例 1**

```text
输入：s = "01", queries = [[0,1]]
输出：[1]
解释：子串 "01" 补成 "101"，唯一的 '1' 右侧是补的 '1'，不可翻。
      整个 s 中活跃区段数 1。
```

**示例 2**

```text
输入：s = "0100", queries = [[0,3],[0,2],[1,3],[2,3]]
输出：[4,3,1,1]
解释：
  [0,3] → "0100"：翻中间 1 与其左右 0-段，得 "1111"，答案 4
  [0,2] → "010" ：左侧 0 段 1 个 + 右侧 0 段 1 个，Δ=2，答案 1+2=3
  [1,3] → "100" ：1-段左侧没有 0，不可翻，答案仍为 1
  [2,3] → "00"  ：没有 1-段，答案仍为 1
```

**示例 3**

```text
输入：s = "1000100", queries = [[1,5],[0,6],[0,4]]
输出：[6,7,2]
解释：
  [1,5] → 全局 2 个 1 + Δ(3+1) = 6
  [0,6] → 全局 2 个 1 + Δ(3+2) = 7
  [0,4] → 中间 1-段右侧的 0-段不在查询内，无候选，答案 2
```

**示例 4**

```text
输入：s = "01010", queries = [[0,3],[1,4],[1,3]]
输出：[4,4,2]
解释：
  [0,3] → 用左侧 1-段：Δ=1+1=2，答案 2+2=4
  [1,4] → 用右侧 1-段：Δ=1+1=2，答案 2+2=4
  [1,3] → 两段 1 都缺一侧 0-段，无候选，答案 2
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询：截出子串、补 `'1'`、枚举第一步的 `'1'` 块与第二步的 `'0'` 块、模拟翻转、统计整串 `'1'` 的个数。单次 $O(n^2)$ 甚至 $O(n^3)$，$q = 10^5$ 时完全不可行。

### 3.2 核心观察：只有「完整落在查询内、且两侧 0-段都与查询相交」的 1-段可用

![查询语义：操作只在子串内，活跃区段数统计整串 s](images/bw153_q4_candidates.svg)

先明确两件事：

- **串外的字符不会被改动**，所以答案 $=\text{ones}(s) + \Delta$，$\text{ones}(s)$ 是个与查询无关的常数，只需每次算出最大增益 $\Delta$。
- **第一步翻的 `'1'` 块必须是 $s$ 中某个完整的极大 `'1'` 段**。若该段被 $l$ 或 $r$ 截断，则它在子串内就贴着边界，边界外仍是 `'1'`（或补的 `'1'`），不满足「被 `'0'` 包围」。

于是对某个 `'1'` 段 $j$（记其左右相邻的 `'0'` 段为 $Z_L, Z_R$），它能贡献增益当且仅当：

$$[\,\text{start}(j),\, \text{end}(j)\,] \subseteq [l, r], \quad Z_L \cap [l,r] \ne \varnothing, \quad Z_R \cap [l,r] \ne \varnothing .$$

满足时增益为

$$\Delta_j = \big|Z_L \cap [l,r]\big| + \big|Z_R \cap [l,r]\big|,$$

即**两侧 `'0'` 段落在查询内的长度之和**（中间那段 `'1'` 先失去再拿回，净值不影响结果；第二步只能翻转查询内的部分，所以长度要按交集截断）。

### 3.3 算法流程：游程 + 线段树

![单次查询：两端单独算，中间区间查线段树最大值](images/bw153_q4_query.svg)

把 $s$ 做游程压缩，得到段数组 $S_0, \dots, S_{m-1}$，记录每段的字符、长度、起止下标。对 `'1'` 段 $k$ 预处理

$$\text{val}[k] = \begin{cases} len[k-1] + len[k+1], & \text{段 } k \text{ 是 } \texttt{'1'} \text{ 且两侧都有段}\\ 0, & \text{否则}\end{cases}$$

并在 $\text{val}$ 上建**线段树**维护区间最大值。

对查询 $[l,r]$：

1. 令 $il$、$ir$ 分别是包含 $l$、$r$ 的段编号（用 `runOf[]` 数组 $O(1)$ 查）。候选 `'1'` 段必然落在 $[\,il+1,\; ir-1\,]$ 中（$j \le il$ 的段不可能整体落在查询内，$j \ge ir$ 同理）。
2. 端点候选 $j \in \{il+1,\; ir-1\}$：它们的相邻 `'0'` 段可能被 $l$ 或 $r$ **截断**，需要单独用交集长度计算。
3. 中间候选 $j \in [\,il+2,\; ir-2\,]$：两侧 `'0'` 段都完整落在查询内，增益正是 $\text{val}[j]$，直接在线段树上对 $[\,il+2,\; ir-2\,]$ 做一次区间最大值查询。
4. 答案 $=\text{ones}(s) + \max(0, \text{上述所有候选的增益})$。

### 3.4 示例演算

![示例 3 演算：s = "1000100"，全局 ones = 2](images/bw153_q4_walkthrough.svg)

对示例 3 的 `s = "1000100"`，游程为 $r_0 = \texttt{1}$（长度 1）、$r_1 = \texttt{000}$（3）、$r_2 = \texttt{1}$（1）、$r_3 = \texttt{00}$（2），`val = [0, 0, 5, 0]`（只有 $r_2$ 是两侧都有邻居的 `'1'` 段，`val[2] = 3 + 2 = 5`）。全局 `ones = 2`。

| 查询 $[l,r]$ | $il, ir$ | 候选 $j$ | 增益 $\Delta$ | 答案 |
|---|---|---|---|---|
| $[1,5]$ | $il=1,\ ir=3$ | $j=2$（同时是两端） | 左 $3$（完整）+ 右 $1$（被 $r$ 截断）$=4$ | $2+4=6$ |
| $[0,6]$ | $il=0,\ ir=3$ | $j \in \{1,2\}$，$r_1$ 是 `'0'` 段跳过 | $j=2$：$3+2=5$（两侧完整） | $2+5=7$ |
| $[0,4]$ | $il=0,\ ir=2$ | $jlo=jhi=1$，但 $r_1$ 是 `'0'` 段；唯一候选 $r_2 > jhi$ | 无候选（$r_2$ 的右 0-段从下标 5 开始，落在查询外） | $2+0=2$ |

三个答案 $[6,7,2]$ 与题面示例输出完全一致。特别注意第一个查询：子串长度只有 5，答案却是 6，因为统计对象是整串 $s$。

## 4. 算法细节

1. **游程压缩**：段数 $m \le n$，交替存放字符与长度；同时用 `runOf[i]` 记录下标 $i$ 落在哪一段，供 $O(1)$ 定位 $il, ir$。
2. **`val` 的语义**：`val[k]` 只对「两侧都有邻居的 `'1'` 段」有意义。由于段字符交替，两侧有邻居的 `'1'` 段其邻居必为 `'0'` 段，「被 `'0'` 包围」自动满足。
3. **端点修正公式**：对 $j = il+1$，左邻是 $il$，交集长度 $=\text{end}[il] - l + 1$；对 $j = ir-1$，右邻是 $ir$，交集长度 $= r - \text{start}[ir] + 1$。两端可能同时成立（$ir = il+2$ 时 $j$ 同时是左右端点），一次判定即可。
4. **区间最大值只查中间**：$[\,il+2,\; ir-2\,]$ 中的候选段，其左右邻居都严格位于 $il$ 与 $ir$ 之间，不含截断问题，故可以直接取预处理的 `val`。
5. **线段树实现**：用迭代式（自底向上）线段树，叶子为 `val`，内部结点取 `max`；区间查询 $O(\log m)$，常数小。
6. **答案上界**：$\text{ones}(s) + \Delta \le n$？不一定——$\Delta$ 只来自查询内，而 `ones` 是整串，所以答案可能超过 $r-l+1$（示例 3 的 $[1,5]$），这是正确行为，不要加 `min` 修正。
7. **多个查询独立**：查询之间不共享状态，线段树只读不改。

## 5. 正确性证明

**引理 1（候选刻画）**：对查询 $[l,r]$，第一步能翻转的块恰是某个完整落在 $[l,r]$ 内、且左右 `'0'` 段都与 $[l,r]$ 有非空交集的极大 `'1'` 段。

**证明**：

- *必要性*：设第一步翻转的块为 $B$。$B$ 必须是子串中的极大 `'1'` 块（否则不是「连续 `'1'` 块被 `'0'` 包围」），而子串中的极大 `'1'` 块必然是 $s$ 的某个极大 `'1'` 段与 $[l,r]$ 的交。若该段被截断（即存在 `'1'` 在 $[l,r]$ 之外与 $B$ 相连），则 $B$ 的该侧在 $s$ 中是 `'1'`，且子串内该侧也仍在 $B$ 内，无法形成 `'0'` 包围，矛盾。故 $B$ 是某个完整落在 $[l,r]$ 内的 `'1'` 段 $j$。又 $B$ 两侧必须紧邻 `'0'`（或子串边界外的补 `'1'`）——若 $Z_L$ 与 $[l,r]$ 无交，则 $j$ 的左侧紧邻的仍是 `'1'`（$j$ 前面是别的 `'1'` 段，或 $j$ 已到 $s$ 起点），不满足「被 `'0'` 包围」；右侧同理。
- *充分性*：若 $j$ 完整落在 $[l,r]$ 内且 $Z_L, Z_R$ 与 $[l,r]$ 有交，则在子串视图中 $j$ 两侧紧邻的都是 `'0'`（若交集从子串边界开始，则边界外是补的 `'1'`，但这不影响「$j$ 被 `'0'` 包围」这一判定，因为判定只看向内相邻的字符）。故 $j$ 可翻。∎

**引理 2（增益公式）**：翻转满足引理 1 的段 $j$ 后，若第二步翻转合并出的 `'0'` 块在查询内的部分，则净增益为 $|Z_L\cap[l,r]| + |Z_R\cap[l,r]|$。

**证明**：第一步使 $j$ 内 $len(j)$ 个 `'1'` 变 `'0'`，减少 $len(j)$。此后 $Z_L\cap[l,r]$、$j$、$Z_R\cap[l,r]$ 连成一段长度 $L + len(j) + R$ 的 `'0'` 块（$L,R$ 为两个交集长度），其两侧或为 `'1'`、或为补的 `'1'`，故可整体翻成 `'1'`，增加 $L + len(j) + R$。净变化 $=L+R$。∎

**引理 3（分解不重不漏）**：设 $il$ 为含 $l$ 的段、$ir$ 为含 $r$ 的段，则引理 1 的候选段集合恰为 $\{il+1,\dots,ir-1\}$ 中的 `'1'` 段；其中 $j \in \{il+1, ir-1\}$ 的相邻 `'0'` 段可能被截断、需按交集计算，而 $j \in [il+2, ir-2]$ 的两个相邻 `'0'` 段必完整落在 $[l,r]$ 内。

**证明**：$[l,r]$ 完整包含了段 $il+1, \dots, ir-1$ 的全部字符（因为 $l \le \text{end}(il)$、$r \ge \text{start}(ir)$），而段 $\le il-1$ 或 $\ge ir+1$ 与 $[l,r]$ 不相交，段 $il$ 与 $ir$ 至少一端被截断。故「完整落在 $[l,r]$ 内的段」恰为 $il+1..ir-1$。对 $j = il+1$，其左邻是 $il$（可能被 $l$ 截断），右邻 $il+2$ 完整；对 $j = ir-1$ 对称；对 $j \in [il+2, ir-2]$，左右邻都落在 $[il+1, ir-1]$ 内，必然完整。∎

**定理**：对每个查询，算法输出的 $\text{ones}(s) + \max(0, \max_{\text{候选 } j} \Delta_j)$ 等于最优操作后整串 $s$ 中 `'1'` 的最大个数。

**证明**：

- *可达性*：取使 $\Delta_j$ 最大的候选段 $j$（若不存在候选则 `best = 0`，不操作），按引理 2 执行两步翻转，整串 `'1'` 个数变为 $\text{ones}(s) + \Delta_j$。
- *上界*：任意一次合法操作由引理 1 对应某个候选段 $j$，其增益由引理 2 为 $\Delta_j$（第二步若选别的 `'0'` 块，由 I 版引理 3 同样的论证可知不优于选合并块）。操作只改变 $[l,r]$ 内的字符，串外 `'1'` 全部保留，故操作后 `'1'` 总数 $=\text{ones}(s)+\Delta \le \text{ones}(s)+\max_j \Delta_j$。不操作时为 $\text{ones}(s)$，被 $\max(0,\cdot)$ 覆盖。

两者相合，定理成立。∎

## 6. 复杂度分析

- **预处理**：游程压缩 $O(n)$；`runOf[]` 填充 $O(n)$；`val` 计算 $O(m)$；迭代线段树建树 $O(m)$。合计 $O(n)$。
- **单次查询**：定位 $il, ir$ 为 $O(1)$；两个端点候选 $O(1)$；中间区间最大值 $O(\log m)$。合计 $O(\log n)$。
- **总时间**：$O(n + q\log n)$。$n = q = 10^5$ 时约 $1.7\times 10^6$ 次线段树操作，实测 C++ 0.25 s 内。
- **空间**：$O(n)$。段数组、`runOf`、线段树（$2\cdot 2^{\lceil \log m\rceil}$）与答案数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> maxActiveSectionsAfterTrade(string s, vector<vector<int>>& queries) {
        int n = (int)s.size();
        // 游程压缩：ch[k] 段的字符、[start[k], end[k]]、len[k]
        vector<char> ch;
        vector<int> start, end_, len;
        for (int i = 0; i < n;) {
            int j = i;
            while (j < n && s[j] == s[i]) j++;
            ch.push_back(s[i]);
            start.push_back(i);
            end_.push_back(j - 1);
            len.push_back(j - i);
            i = j;
        }
        int m = (int)len.size();
        vector<int> runOf(n);
        for (int k = 0; k < m; ++k) {
            for (int p = start[k]; p <= end_[k]; ++p) runOf[p] = k;
        }
        // val[k]：把 1-段 k 整体翻转成 0 后再把合并的 0-块翻回来，净增益 = 左右 0-段长度和
        vector<int> val(m, 0);
        for (int k = 0; k < m; ++k) {
            if (ch[k] == '1' && k > 0 && k + 1 < m) val[k] = len[k - 1] + len[k + 1];
        }
        // 迭代式线段树：区间最大值
        int size = 1;
        while (size < m) size <<= 1;
        vector<int> tree(2 * size, 0);
        for (int k = 0; k < m; ++k) tree[size + k] = val[k];
        for (int k = size - 1; k >= 1; --k) tree[k] = max(tree[2 * k], tree[2 * k + 1]);
        auto queryMax = [&](int l, int r) {  // 闭区间 [l, r]
            int res = 0;
            l += size;
            r += size;
            while (l <= r) {
                if (l & 1) res = max(res, tree[l++]);
                if (!(r & 1)) res = max(res, tree[r--]);
                l >>= 1;
                r >>= 1;
            }
            return res;
        };
        int totalOnes = 0;
        for (char c : s) {
            if (c == '1') totalOnes++;
        }
        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            int l = q[0], r = q[1];
            int il = runOf[l], ir = runOf[r];
            int best = 0;
            int jlo = il + 1, jhi = ir - 1;  // 位于查询内部（两侧都有 0-段）的候选 1-段
            if (jlo <= jhi) {
                // 两端候选段的相邻 0-段可能被 l / r 截断，单独算
                for (int j : {jlo, jhi}) {
                    if (ch[j] != '1') continue;
                    int leftLen = (j - 1 == il) ? (end_[il] - l + 1) : len[j - 1];
                    int rightLen = (j + 1 == ir) ? (r - start[ir] + 1) : len[j + 1];
                    best = max(best, leftLen + rightLen);
                }
                // 中间的候选段左右 0-段都完整落在查询内，直接查线段树
                if (jlo + 1 <= jhi - 1) best = max(best, queryMax(jlo + 1, jhi - 1));
            }
            ans.push_back(totalOnes + best);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxActiveSectionsAfterTrade(self, s: str, queries: list[list[int]]) -> list[int]:
        n = len(s)
        # 游程压缩：ch[k] 段的字符、[start[k], end[k]]、length[k]
        ch, start, end, length = [], [], [], []
        i = 0
        while i < n:
            j = i
            while j < n and s[j] == s[i]:
                j += 1
            ch.append(s[i])
            start.append(i)
            end.append(j - 1)
            length.append(j - i)
            i = j
        m = len(ch)
        run_of = [0] * n
        for k in range(m):
            for p in range(start[k], end[k] + 1):
                run_of[p] = k
        # val[k]：把 1-段 k 整体翻转成 0 后再把合并的 0-块翻回来，净增益 = 左右 0-段长度和
        val = [0] * m
        for k in range(m):
            if ch[k] == '1' and k > 0 and k + 1 < m:
                val[k] = length[k - 1] + length[k + 1]
        # 迭代式线段树：区间最大值
        size = 1
        while size < m:
            size <<= 1
        tree = [0] * (2 * size)
        for k in range(m):
            tree[size + k] = val[k]
        for k in range(size - 1, 0, -1):
            tree[k] = max(tree[2 * k], tree[2 * k + 1])

        def query_max(l: int, r: int) -> int:  # 闭区间 [l, r]
            res = 0
            l += size
            r += size
            while l <= r:
                if l & 1:
                    res = max(res, tree[l])
                    l += 1
                if not (r & 1):
                    res = max(res, tree[r])
                    r -= 1
                l >>= 1
                r >>= 1
            return res

        total_ones = s.count('1')
        ans = []
        for l, r in queries:
            il, ir = run_of[l], run_of[r]
            best = 0
            jlo, jhi = il + 1, ir - 1  # 位于查询内部（两侧都有 0-段）的候选 1-段
            if jlo <= jhi:
                # 两端候选段的相邻 0-段可能被 l / r 截断，单独算
                for j in (jlo, jhi):
                    if ch[j] != '1':
                        continue
                    left_len = end[il] - l + 1 if j - 1 == il else length[j - 1]
                    right_len = r - start[ir] + 1 if j + 1 == ir else length[j + 1]
                    best = max(best, left_len + right_len)
                # 中间的候选段左右 0-段都完整落在查询内，直接查线段树
                if jlo + 1 <= jhi - 1:
                    best = max(best, query_max(jlo + 1, jhi - 1))
            ans.append(total_ones + best)
        return ans
```

## 8. 边界情况与易错点

1. **统计对象是整串**：`ones(s)` 是常数累加项，不随查询变化。写成「子串内 1 的个数」会让示例 3 的答案变成 5。
2. **候选段必须完整落在查询内**：被 $l$ 或 $r$ 截断的 `'1'` 段不能翻（两端外仍是 `'1'`），这是 $j \in [il+1, ir-1]$ 而非 $[il, ir]$ 的原因。
3. **两侧 `'0'` 段都要与查询相交**：`[0,4]` 查询里中间 `'1'` 段的右邻 `'0'` 段从下标 5 开始，交集为空 → 不可翻，答案退回 `ones(s)`。
4. **截断长度按交集算**：左端用 `end[il] - l + 1`，右端用 `r - start[ir] + 1`，别直接用 `len[il]` / `len[ir]`。
5. **`jlo > jhi` 时直接跳过**：$l, r$ 落在同一段或相邻段时，没有任何候选段，`best` 保持 0。
6. **`jlo == jhi` 时**：`{jlo, jhi}` 会重复计算同一个 $j$，结果仍是 `max`，无害；但若改成累加就会出错。
7. **中间区间的边界**：`queryMax(jlo + 1, jhi - 1)` 只在 `jlo + 1 <= jhi - 1` 时调用，避免空区间。
8. **线段树大小**：`m` 可能为 1（全 0 或全 1），此时 `size = 1`、`tree` 长度 2，建树与查询都安全；`jlo = il+1 > jhi = ir-1` 会直接跳过。
9. **多查询独立性**：不要缓存上一次的 `il/ir`，`runOf` 每次重查即可。
