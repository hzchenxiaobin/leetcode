# LeetCode 字符串的反转度 题解

## 1. 题目概述

- **标题 / 题号**：字符串的反转度（#3498，easy）
- **链接**：https://leetcode.cn/problems/reverse-degree-of-a-string/
- **来源**：LeetCode 第 153 场双周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定只含小写字母的字符串 $s$，定义字符 $c$ 的**反转位置**为它在反转字母表中的位置：

$$\operatorname{rev}(c) = 26 - (c - \text{'a'})$$

即 `'a' = 26`、`'b' = 25`、…、`'z' = 1`。再把每个字符的反转位置乘上它在字符串中的位置（**下标从 1 开始**），全部加起来就是 $s$ 的**反转度**：

$$\text{degree}(s) = \sum_{i=1}^{n} \operatorname{rev}(s_i) \cdot i$$

要求返回这个总和。

**约束**：

- $1 \le s.length \le 1000$
- $s$ 仅包含小写英文字母

> 💡 题面没有任何额外机关，是标准的「按定义模拟」签到题；关键是别把位置写成从 0 开始。

## 2. 示例

**示例 1**

```text
输入：s = "abc"
输出：148
解释：
  'a'：反转位置 26，字符串位置 1 → 26
  'b'：反转位置 25，字符串位置 2 → 50
  'c'：反转位置 24，字符串位置 3 → 72
  反转度 = 26 + 50 + 72 = 148
```

**示例 2**

```text
输入：s = "zaza"
输出：160
解释：
  'z'：1 × 1 = 1
  'a'：26 × 2 = 52
  'z'：1 × 3 = 3
  'a'：26 × 4 = 104
  反转度 = 1 + 52 + 3 + 104 = 160
```

**示例 3（自造，验证边界）**

```text
输入：s = "z"
输出：1
解释：只有一个字符，反转位置 1、位置 1，乘积为 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是「先把反转字母表建出来，再逐字符查表」。建表需要 $O(26)$，之后扫描 $O(n)$ 并做乘法累加，总复杂度 $O(n)$——能过，但建表其实完全没必要：反转位置与字母序号之间是**一元一次关系**，可以 $O(1)$ 直接算。

真正容易踩的坑不是复杂度，而是**下标的起点**：题面明确要求字符串位置从 1 开始，若从 0 开始遍历而不补 1，示例 1 会算出 $0 + 25 + 48 = 73$，与 148 相去甚远。

### 3.2 核心观察：反转位置是一元一次函数

![反转度：反转字母表位置 × 字符串位置](images/bw153_q1_table.svg)

把两件事分开看：

- **字符侧**：$\operatorname{rev}(c) = 26 - (c - \text{'a'})$，取值随字母递增而**递减**，`'a'` 拿最大值 26、`'z'` 拿最小值 1。它只依赖字符本身，与位置无关。
- **位置侧**：第 $i$ 个字符（$i$ 从 1 开始）的权重恰是 $i$。

于是每个字符对答案的贡献是「常数 × 位置」，一次遍历即可完成；既不需要排序，也不需要前缀和。由于每一项都形如 $\operatorname{rev}(s_i)\cdot i$，扫描顺序任意，但为了拿到正确的 $i$，**按顺序遍历 + 用 `i` 的 1-based 值**是最省事的做法。

### 3.3 算法流程

![算法流程：一遍扫描累加乘积](images/bw153_q1_flow.svg)

```text
1. ans ← 0
2. for i = 1 .. n:                       # i 是 1-based 的字符串位置
3.     rev ← 26 − (ord(s[i]) − ord('a'))
4.     ans ← ans + rev × i
5. 返回 ans
```

### 3.4 示例演算

![示例演算：s = "zaza" → 160](images/bw153_q1_walkthrough.svg)

对示例 2 的 `s = "zaza"` 逐字符走一遍：

| 位置 $i$ | 字符 | 反转位置 $\operatorname{rev}$ | 乘积 |
|---|---|---|---|
| 1 | z | 1 | 1 |
| 2 | a | 26 | 52 |
| 3 | z | 1 | 3 |
| 4 | a | 26 | 104 |

累加得 $1 + 52 + 3 + 104 = 160$，与输出一致。

## 4. 算法细节

1. **位置从 1 开始**：Python 用 `enumerate(s, start=1)`，C++ 用 `i + 1`。这是本题唯一真正的易错点。
2. **字符转序号**：Python 用 `ord(c) - ord('a')`，C++ 用 `s[i] - 'a'`。二者都依赖 ASCII 中字母连续这一事实。
3. **不必建表**：`vector<int> table(26)` 的写法也正确，但公式版更短、无额外空间；若题目改成「任意置换的反转表」，建表才划算。
4. **乘法与累加都用 `int`**：最大情况 $n = 1000$、全为 `'a'`，总和为 $26 \cdot \frac{1000 \cdot 1001}{2} = 13{,}013{,}000$，远小于 `int` 上限。
5. **只遍历一次**：不要先算一遍「字母出现次数」再乘位置——同一个字母在不同位置的权重不同，必须按下标逐项相乘。

## 5. 正确性证明

**引理 1（单项贡献）**：对任意下标 $i \in [1, n]$，算法在第 $i$ 次循环中把 $\operatorname{rev}(s_i) \cdot i$ 加到 `ans` 上。

**证明**：循环变量 `i` 从 1 递增到 $n$，第 $i$ 次循环访问的字符正是 $s[i]$（1-based），即 $s_i$；此时 `rev` 被赋为 $26 - (s[i] - \text{'a'})$，按 ASCII 顺序恰好等于 $\operatorname{rev}(s_i)$。故本次累加的值为 $\operatorname{rev}(s_i) \cdot i$。∎

**引理 2（无重复无遗漏）**：循环体对每个下标恰好执行一次。

**证明**：`for i = 1 .. n` 是步长为 1 的单向循环，$i$ 依次取遍 $1, 2, \ldots, n$ 中每个值各一次，故每个下标恰好被处理一次。∎

**定理**：算法返回的值等于 $s$ 的反转度 $\displaystyle\sum_{i=1}^{n} \operatorname{rev}(s_i)\cdot i$。

**证明**：由引理 1，第 $i$ 次循环向 `ans` 累加 $\operatorname{rev}(s_i)\cdot i$；由引理 2，$i$ 取遍 $1..n$ 各一次。因此循环结束时

$$\texttt{ans} = \sum_{i=1}^{n} \operatorname{rev}(s_i)\cdot i = \text{degree}(s),$$

正是题目要求的量。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符做一次减法、一次乘法、一次加法，共 $n$ 次迭代，无嵌套循环。
- **空间**：$O(1)$ 额外空间（不计输入本身）。只用了 `ans`、`i`、`rev` 三个标量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int reverseDegree(string s) {
        int ans = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            int reversed = 26 - (s[i] - 'a');  // 'a' -> 26, 'z' -> 1
            ans += reversed * (i + 1);         // 字符串中的位置从 1 开始
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def reverseDegree(self, s: str) -> int:
        ans = 0
        for i, ch in enumerate(s, start=1):
            reversed_pos = 26 - (ord(ch) - ord('a'))  # 'a' -> 26, 'z' -> 1
            ans += reversed_pos * i                   # 字符串中的位置从 1 开始
        return ans
```

## 8. 边界情况与易错点

1. **位置 0-based 陷阱**：这是本题最高频 WA。`"abc"` 用 0-based 会得到 73 而不是 148。
2. **`'a'` 是 26 而不是 1**：反转表与正常字母表方向相反，写反会得到 `"abc" = 1 + 4 + 9 = 14` 之类的错误结果。
3. **长度为 1**：`"z"` 应返回 1，`"a"` 应返回 26，循环与公式都自然覆盖，无需特判。
4. **全 `'z'`**：答案退化为 $\sum i = \frac{n(n+1)}{2}$，如 $n = 1000$ 时为 500500，可作为对拍的 sanity check。
5. **不用 long long**：$13{,}013{,}000$ 的规模用 32 位有符号整数绰绰有余；但若把题目改成「反转度的平方和」就要注意溢出。
6. **输入只有小写字母**：不需要处理大写或非字母字符，也无需 `tolower`。
