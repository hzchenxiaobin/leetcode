# LeetCode 供暖器 题解

## 1. 题目概述

- **标题 / 题号**：供暖器（#475，medium）
- **链接**：https://leetcode.cn/problems/heaters/
- **来源**：LeetCode 第 12 场周赛 Q1
- **难度**：中等
- **标签**：数组，双指针，二分查找，排序

**题意**：在一条水平线上给出若干房屋 `houses` 与若干供暖器 `heaters` 的坐标。所有供暖器**共用同一个**加热半径 $R$，一个房屋只要落在某个供暖器的半径范围内（距离 $\le R$）就算被供暖。求能覆盖**所有**房屋的最小半径 $R$。

**约束**：

- $1 \le \lvert \text{houses} \rvert, \lvert \text{heaters} \rvert \le 3 \times 10^4$
- $1 \le \text{houses}[i], \text{heaters}[i] \le 10^9$
- 坐标可以重复，房屋与供暖器也可以在同一个位置
- 供暖器至少有一个，因此答案一定存在

## 2. 示例

**示例 1**

```text
输入：houses = [1,2,3], heaters = [2]
输出：1
解释：只有一个供暖器在位置 2；半径取 1 时覆盖 [1,3]，三个房屋都被供暖。
      半径取 0 时房屋 1、3 无人供暖，故答案为 1。
```

**示例 2**

```text
输入：houses = [1,2,3,4], heaters = [1,4]
输出：1
解释：位置 1、4 各有一个供暖器。半径 1 时覆盖 [0,2]∪[3,5]，
      覆盖全部房屋；半径 0 时房屋 2、3 无人供暖，故答案为 1。
```

**示例 3**

```text
输入：houses = [1,5], heaters = [2]
输出：3
解释：唯一供暖器在 2。房屋 1 需要半径 1，房屋 5 需要半径 3，
      取较大者 3；此时两端都覆盖。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的两个方向都不够快：

1. **枚举半径**：半径 $R$ 从 $0$ 试到 $10^9$，每次判断所有房屋是否被覆盖，代价 $O(C \cdot n \cdot m)$，其中 $C = 10^9$，完全不可行。
2. **每个房屋线性扫供暖器**：对每个房屋求出到所有供暖器的最小距离，再取最大，复杂度 $O(nm)$。$n = m = 3\times10^4$ 时是 $9\times10^8$ 次比较，超时。

瓶颈在于「**内层那个 min 用了线性扫描**」。注意到供暖器的位置是静态的，如果把它排好序，就可以用二分在 $O(\log m)$ 时间内找到最近的供暖器。

### 3.2 核心观察：把「最小半径」拆成 max-min 两重极值

![答案等于每个房屋到最近供暖器距离的最大值](images/wc12_q1_minmax_decomposition.svg)

关键是把**全局的可行性**翻译成**逐房屋的局部条件**。记

$$d(h) = \min_{t \in \text{heaters}} \lvert h - t \rvert$$

即房屋 $h$ 到最近供暖器的距离。那么「半径 $R$ 覆盖所有房屋」等价于

$$\forall h \in \text{houses},\ d(h) \le R \quad \Longleftrightarrow \quad \max_{h} d(h) \le R$$

于是最小可行半径就是

$$R^{*} = \max_{h \in \text{houses}} \min_{t \in \text{heaters}} \lvert h - t \rvert$$

这就是所谓 **max-min 分解**：外层 $\max$ 是「最难覆盖的那个房屋」，内层 $\min$ 是「离它最近的供暖器」，两者互相独立，可以逐个房屋计算。

> 💡 换个角度，也可以直接对答案 $R$ 二分（见文末延伸思考）；但本题更快的做法是对**位置**二分：内层的 $\min$ 在有序供暖器上就是「最近邻查询」，用 `lower_bound` 一次命中，这正是「二分查找」标签的落点。

### 3.3 算法流程

![排序后每个房屋二分找左右邻](images/wc12_q1_binary_search_flow.svg)

1. 把 `heaters` **升序排序**，得到 $t_0 \le t_1 \le \dots \le t_{m-1}$。
2. 对每个房屋 $h$，二分求出 $j = \operatorname{lower\_bound}(t, h)$，即**第一个**满足 $t_j \ge h$ 的下标。
3. 最近的供暖器只可能在这两个位置：

   $$d(h) = \min\bigl(t_j - h,\ h - t_{j-1}\bigr)$$

   其中 $t_j$ 一侧只在 $j < m$ 时存在，$t_{j-1}$ 一侧只在 $j \ge 1$ 时存在。
4. 用 $\text{ans} \leftarrow \max\bigl(\text{ans},\ d(h)\bigr)$ 累积答案。
5. 遍历结束返回 `ans`。

之所以只需看两个候选：`lower_bound` 把有序数组切成「左段全部 $< h$」与「右段全部 $\ge h$」两部分，同一段内元素离 $h$ 只会越来越远，所以每段的**端点**就是该段的最优，全局最优必然在这两个端点之一。

### 3.4 示例演算

![示例 2 的逐步走查表](images/wc12_q1_example_walkthrough.svg)

对示例 2：`houses = [1,2,3,4]`，`heaters = [1,4]`（排序后不变，$m = 2$）。

| 房屋 $h$ | $j$ | 候选供暖器 | $d(h)$ | `ans` |
|----------|-----|------------|--------|-------|
| 1 | 0 | $\{1\}$（无左邻） | 0 | 0 |
| 2 | 1 | $\{1, 4\}$ | $\min(2, 1) = 1$ | 1 |
| 3 | 1 | $\{1, 4\}$ | $\min(1, 2) = 1$ | 1 |
| 4 | 1 | $\{1, 4\}$ | $\min(0, 3) = 0$ | 1 |

最终 `ans = 1`，与官方输出一致。

再走一遍示例 3（`houses = [1,5]`，`heaters = [2]`，$m = 1$）：

| 房屋 $h$ | $j$ | 候选供暖器 | $d(h)$ | `ans` |
|----------|-----|------------|--------|-------|
| 1 | 0 | $\{2\}$（无左邻） | 1 | 1 |
| 5 | 1（$= m$，无右邻） | $\{2\}$ | 3 | 3 |

返回 3。注意第二行的 $j = m$ 正是**右边界越界**的情形，必须跳过不存在的候选。

## 4. 算法细节

1. **必须先排序**：`lower_bound` / `bisect_left` 只对有序序列成立。排序开销 $O(m \log m)$，被后面的 $n \log m$ 摊掉。
2. **`lower_bound` 的语义**：返回第一个 $\ge h$ 的下标（不是「相等」，也不是「最后一个 $\le h$」）。若全数组都 $< h$，返回 $m$，此时只有左邻。
3. **越界保护**：`it == end` 时不能解引用 `*it`；`it == begin` 时不能取 `*(it - 1)`。C++ 里用 `INT_MAX` 作中性元，Python 里用 `float('inf')`，两边都不会污染 `min`。
4. **相减方向天然非负**：$j$ 侧元素 $\ge h$，写 $t_j - h$；$j-1$ 侧元素 $\le h$，写 $h - t_{j-1}$。两式都不需要 `abs`，也避免了 `abs` 与负数极值混用的坑。
5. **用 `min` 而不是分类讨论**：直接把两侧候选塞进 `min`，比 `if (j == 0) ... else if (j == m) ... else ...` 少写分支，也不容易漏掉边界。
6. **外层是 `max` 而非求和**：半径是「覆盖能力」的阈值，多个房屋之间是**取并集**关系，只需要满足最苛刻的那个房屋，累加是没有意义的。
7. **`houses` 不需要排序**：每个房屋互相独立。若为了配合双指针而排序（$O(n\log n)$），可以把复杂度改写成 $O((n+m)\log(n+m))$，但本题没有收益。

## 5. 正确性证明

**引理 1（候选只有两个）**：设供暖器升序为 $t_0 \le \dots \le t_{m-1}$，$j = \operatorname{lower\_bound}(t, h)$。则

$$\min_{0 \le i < m} \lvert h - t_i \rvert = \min\bigl\{\, \lvert h - t_j \rvert \ (j < m),\ \lvert h - t_{j-1} \rvert \ (j \ge 1) \,\bigr\}$$

**证明**：任取 $i \ge j$（若存在），由 $j$ 的定义有 $t_i \ge t_j \ge h$，故 $\lvert h - t_i \rvert = t_i - h \ge t_j - h = \lvert h - t_j \rvert$，左段不可能优于 $t_j$。任取 $i \le j-1$，由 $j$ 的定义有 $t_i \le t_{j-1} < h$，故 $\lvert h - t_i \rvert = h - t_i \ge h - t_{j-1} = \lvert h - t_{j-1} \rvert$，右段不可能优于 $t_{j-1}$。全体下标被 $i \le j-1$ 与 $i \ge j$ 覆盖，故最小值只能在这两个端点取到。∎

**引理 2（$d(h)$ 计算正确）**：算法内层算出的值恰好等于 $d(h) = \min_t \lvert h - t \rvert$。

**证明**：代码对存在的候选取距离并做 `min`，不存在的候选用 $+\infty$ 代替（对 `min` 无影响）。由引理 1 的这些候选已包含全局最优，再取 `min` 即得全局最优。∎

**引理 3（可行性单调）**：记 $f(R)$ 表示「半径 $R$ 能覆盖所有房屋」。若 $f(R)$ 成立，则对任意 $R' \ge R$，$f(R')$ 也成立。

**证明**：半径 $R$ 能覆盖 $h$ 意味着存在 $t$ 使 $\lvert h - t \rvert \le R$，而 $R \le R'$，故同一个 $t$ 也满足 $\lvert h - t \rvert \le R'$。逐房屋成立即得全体成立。∎

**定理**：算法返回的 `ans` 等于最小的可行半径 $R^{*}$。

**证明**：记 $\text{ans} = \max_h d(h)$。

- **可行性**：对任意房屋 $h$，$d(h) \le \text{ans}$，由 $d$ 的定义存在供暖器 $t$ 使 $\lvert h - t \rvert = d(h) \le \text{ans}$，故半径 `ans` 覆盖所有房屋。
- **最小性**：设 $h^{*}$ 取到最大值，即 $d(h^{*}) = \text{ans}$。对任意 $R < \text{ans}$，有 $R < d(h^{*}) = \min_t \lvert h^{*} - t \rvert$，即所有供暖器到 $h^{*}$ 的距离都严格大于 $R$，$h^{*}$ 未被覆盖，$f(R)$ 不成立。

由引理 3，可行集合是一个以 `ans` 为下界的后缀，结合上面两点即得 $R^{*} = \text{ans}$。∎

## 6. 复杂度分析

- **时间**：$O(m \log m + n \log m)$。其中 $n = \lvert \text{houses} \rvert$，$m = \lvert \text{heaters} \rvert$。排序 $O(m\log m)$；每个房屋一次 `lower_bound` 是 $O(\log m)$，共 $n$ 次；其余为 $O(1)$ 的取值与比较。最坏约 $3\times10^4 \times 15 \approx 4.5\times10^5$ 次比较，非常宽裕。
- **空间**：$O(1)$ 额外空间（不算排序用的栈空间，C++ `sort` 为 $O(\log m)$ 递归栈）。若用 Python 的 `heaters.sort()`，同理为原地排序。
- **若改用「二分答案 + 双指针 check」**：时间 $O((n+m)\log(n+m) + (n+m)\log C)$，$C = 10^9$ 时约多 30 轮扫描，常数上不如本方案。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int findRadius(vector<int>& houses, vector<int>& heaters) {
        sort(heaters.begin(), heaters.end());
        int ans = 0;
        for (int h : houses) {
            // 第一个 >= h 的供暖器下标
            auto it = lower_bound(heaters.begin(), heaters.end(), h);
            int best = INT_MAX;
            if (it != heaters.end()) best = min(best, *it - h);      // 右邻
            if (it != heaters.begin()) best = min(best, h - *(it - 1)); // 左邻
            ans = max(ans, best);
        }
        return ans;
    }
};
```

### Python

```python
from bisect import bisect_left
from typing import List

class Solution:
    def findRadius(self, houses: List[int], heaters: List[int]) -> int:
        heaters.sort()
        ans = 0
        for h in houses:
            j = bisect_left(heaters, h)          # 第一个 >= h 的下标
            best = float('inf')
            if j < len(heaters):
                best = min(best, heaters[j] - h)     # 右邻
            if j > 0:
                best = min(best, h - heaters[j - 1])  # 左邻
            ans = max(ans, best)
        return ans
```

## 8. 边界情况与易错点

1. **只有一个供暖器**：例如 `houses=[1,5]`、`heaters=[2]`，答案由最远的房屋决定（3）。此时每个房屋都只有一个候选，左邻/右邻的判断各触发一次。
2. **房屋全部在供暖器左侧**：如 `houses=[1]`、`heaters=[100]`，`lower_bound` 返回 $m$，只能取左邻，答案是 99。若漏判 `j < m` 会越界或算出错误值。
3. **房屋全部在供暖器右侧**：如 `houses=[100]`、`heaters=[1]`，`j = 0`，只能取右邻，答案是 99。若漏判 `j > 0` 会在 `it - 1` 上越界（C++ 是未定义行为）。
4. **房屋与供暖器重合**：$d(h) = 0$，`ans` 不应被 0 「覆盖」掉——只有 `max` 才正确，误写成赋值或 `min` 就错了。
5. **坐标值域到 $10^9$**：差值最大 $10^9 - 1$，仍在 32 位有符号整数范围内（$2^{31}-1 \approx 2.1\times10^9$），C++ 用 `int` 即可；但**不要**在中间过程写 `(t - h) * (t - h)` 之类的平方，会溢出。
6. **重复坐标**：`heaters` 中可能有重复值，`lower_bound` 返回第一个 $\ge h$ 的位置，重复不影响正确性；`houses` 重复也只是重复计算同一个 $d(h)$。
7. **中性元的选择**：C++ 用 `INT_MAX` 后做 `min` 是安全的；但要保证至少有一个候选被赋值，否则 `ans` 会变成 `INT_MAX`——由约束「供暖器至少一个」保证。
8. **不要对半径做贪心收缩**：半径是全局统一的，某个房屋满足后可能掩盖另一个更远的房屋，必须遍历全部房屋取 `max`。

**延伸思考**：

1. **二分答案视角**：令 `check(R)` 用双指针判断「每个房屋是否落在某个供暖器的 $R$ 邻域内」——排序后两个指针各自单向前进，$O(n+m)$。在 $[0, 10^9]$ 上二分 $O(\log C)$ 轮，总复杂度 $O((n+m)\log(n+m) + (n+m)\log C)$。它与 max-min 解法是同一枚硬币的两面：前者二分**答案**，后者二分**位置**。
2. **若半径不再统一**：每个供暖器可以有自己的半径、且总预算固定，问题会从「求最小统一半径」变为带预算的覆盖问题，一维情形可用贪心 + 前缀和 / DP 解决。
3. **若要求放置 $k$ 个供暖器**：这就是一维的 $k$-center 问题，答案同样满足单调性，可以「二分半径 + 贪心放置」，复杂度 $O((n\log n)\log C)$；不能再直接用 max-min，因为供暖器位置也需要搜索。
4. **若房屋和供暖器都在二维平面**：最近邻查询退化为 KD-Tree / Voronoi 图问题，max-min 的结构仍然成立，但内层不再是二分。
