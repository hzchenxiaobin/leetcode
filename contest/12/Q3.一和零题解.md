# LeetCode 一和零 题解

## 1. 题目概述

- **标题 / 题号**：一和零（#474，medium）
- **链接**：https://leetcode.cn/problems/ones-and-zeroes/
- **来源**：LeetCode 第 12 场周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、动态规划、背包问题、0-1 背包

**题意**：给定二进制字符串数组 `strs` 和整数 $m$、$n$，选出元素个数尽可能多的子集，使子集内所有字符串的 `0` 总数不超过 $m$、`1` 总数不超过 $n$，返回最大子集大小。

字符串**内部**的字符顺序对答案没有影响，只有 `0`、`1` 的**个数**才有意义；而 `strs` 的**下标**才是物品身份，两个内容相同的字符串是两件不同的物品。

**约束**：

- $1 \le \lvert\texttt{strs}\rvert \le 600$
- $1 \le \lvert\texttt{strs}[i]\rvert \le 100$，仅由 `0` 和 `1` 组成
- $1 \le m, n \le 100$

这三个数字就是复杂度预算：物品数 $600$、两维容量各 $100$，所以 $O(\lvert\texttt{strs}\rvert \cdot m \cdot n) \approx 6 \times 10^{6}$ 的二维背包正是目标量级。

## 2. 示例

**示例 1**

```text
输入：strs = ["10", "0001", "111001", "1", "0"], m = 5, n = 3
输出：4
解释：最大子集是 {"10", "0001", "1", "0"}：0 共 1+3+0+1 = 5 个、1 共 1+1+1+0 = 3 个，
      两个预算恰好用满；
      而 "111001" 含 4 个 1，超过 n = 3，任何包含它的子集都非法。
```

**示例 2**

```text
输入：strs = ["10", "0", "1"], m = 1, n = 1
输出：2
解释：最大子集是 {"0", "1"}（0 共 1 个、1 共 1 个）。
      含 "10" 的两个元素组合都不行：{"10","0"} 需要 2 个 0，{"10","1"} 需要 2 个 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举全部子集：候选有 $2^{\lvert\texttt{strs}\rvert}$ 个，$\lvert\texttt{strs}\rvert = 600$ 时是天文数字；即使每个候选只需 $O(\lvert\texttt{strs}\rvert)$ 判断，也完全不可接受。

贪心也不行。按「字符串最短优先」选：取 `strs = ["00","11","01"]`、$m = n = 2$，贪心先选最短的 `"01"`，此后 `"00"` 与 `"11"` 都会让某一维超限，只能得 1；而 `{"00","11"}` 用满 $(2,2)$ 得到 2。按「0 或 1 占比」排序同样能构造反例。

根因在于**两个预算必须同时满足**：任一维贪心都会牺牲另一维，一维的取舍无法表达二维的权衡，只能把两个预算一起放进状态。

### 3.2 核心观察：二维费用的 0-1 背包

![二维费用的 0-1 背包模型](images/wc12_q3_knapsack_model.svg)

**观察一（字符串就是物品）**：第 $i$ 个字符串只是一件物品，费用是二元组，价值恒为 1：

$$c_i = (z_i,\ o_i) = (\#\texttt{0}\ \text{在}\ s_i\ \text{中的个数},\ \#\texttt{1}\ \text{的个数}),\qquad v_i = 1$$

目标「件数最多」于是等价于「总价值最大」——因为每件价值都是 1，总价值就是选了几件。

**观察二（两维容量）**：约束 $\sum_{i \in S} z_i \le m$ 与 $\sum_{i \in S} o_i \le n$ 是两个独立的上界，它们构成**同一个**背包的两维费用，而不是两个可以分别优化的问题。

**观察三（超标物品直接剪掉）**：若 $z_i > m$ 或 $o_i > n$，任何合法子集都容不下它，删除它不影响答案。这一步在数据里常常能砍掉一批物品，也就砍掉了它们对应的整片转移。

于是问题化为标准的 **0-1 背包（二维费用）**：物品不可重复使用，容量 $(m, n)$，价值全为 1。

### 3.3 算法流程 / 状态转移

![状态转移与倒序枚举](images/wc12_q3_dp_flow.svg)

**状态**：`dp[i][j]` 表示处理完当前这批物品后，「0 的总数 $\le i$ 且 1 的总数 $\le j$」时能选出的最大件数。

**转移**：对物品 $(z, o)$，把所有装得下它的状态更新一遍

$$dp[i][j] \leftarrow \max\Bigl(dp[i][j],\ dp[i-z][j-o] + 1\Bigr),\qquad i \in [z, m],\ j \in [o, n]$$

**枚举顺序**：外层 $i$ 从 $m$ 递减到 $z$，内层 $j$ 从 $n$ 递减到 $o$。两维都倒序，是为了让 $dp[i-z][j-o]$ 读到的仍是**上一轮**（尚未考虑当前物品）的值，从而保证每件物品最多被用一次——这正是 0-1 背包用滚动数组压缩掉「前 $t$ 件」那一维的前提条件。

**初始化与答案**：`dp` 全 0 初始化（一件都不选在任何预算下都合法），最后返回 $dp[m][n]$。由于状态定义就是「预算至多」，$dp[m][n]$ 本身已是所有 $i \le m,\ j \le n$ 中的最大值，不必再遍历取 max。

### 3.4 示例演算

![示例 1 的逐件走查](images/wc12_q3_walkthrough.svg)

对示例 1（$m = 5$，$n = 3$）依次处理 5 件物品，只盯着目标格 $dp[5][3]$：

| 处理到的字符串 | $z$ | $o$ | $dp[5][3]$ | 说明 |
|---|---|---|---|---|
| `"10"` | 1 | 1 | 1 | 先装它，占用 $(1, 1)$ |
| `"0001"` | 3 | 1 | 2 | 与 `"10"` 合计 $(4, 2)$，仍不超 |
| `"111001"` | 2 | 4 | 2 | $o = 4 > n = 3$，被剪掉，值不变 |
| `"1"` | 0 | 1 | 3 | 合计 $(4, 3)$，预算刚好够 |
| `"0"` | 1 | 0 | 4 | 合计 $(5, 3)$，答案 4 |

处理结束后 $dp[i][3]$ 随 $i = 0,\dots,5$ 依次为 $1, 2, 3, 3, 3, 4$：0 的预算变大件数不会变小，但也不会无限增长——`1` 这一维的预算在 $n = 3$ 处已被用满，`0` 的预算再多也塞不进新物品。

再看示例 2（$m = n = 1$）：`"10"` 单独可装，$dp[1][1] = 1$；`"0"` 进来后 $dp[1][1]$ 仍是 1；最后 `"1"` 让 $dp[1][1] = dp[1][0] + 1 = 2$。而 `"10"` 与 `"0"` 需要 2 个 0、与 `"1"` 需要 2 个 1，都无法共存，故答案 2。

## 4. 算法细节

1. **预处理只保留计数**：`z = s.count('0')`、`o = len(s) - z`（C++ 一次遍历统计 `z`，再用长度减）。字符串的顺序、长度只在计数里体现，之后的 DP 不再碰原串。
2. **先剪枝再转移**：$z > m$ 或 $o > n$ 的物品直接 `continue`。写成 `for i = m; i >= z` 时若 $z > m$ 循环体一次都不执行，结果虽然对，但显式 `continue` 更清楚，也避免了「负数下界」的隐患。
3. **两维都必须倒序**：只倒序一维是错的。以 $z = 0,\ o = 1$ 的物品为例，此时 $i - z = i$，行没有变化，防重复完全依赖内层 $j$ 的倒序；若 $j$ 正序遍历，就会读到本轮刚更新的 $dp[i][j-1]$，同一件物品被反复计入。$z \ge 1,\ o = 0$ 的物品则角色互换，靠外层 $i$ 的倒序兜底。
4. **循环边界含等号**：$i$ 要取到 $z$、$j$ 要取到 $o$，因为「恰好用满预算」是合法状态；写成 `i > z` 会漏掉 $dp[z][o]$ 这一条转移。
5. **初始化全 0，不用 $-\infty$**：状态是「至多」语义，任何预算下空集都合法、值为 0；只有「恰好」语义才需要用 $-\infty$ 屏蔽不可达状态。
6. **直接返回 $dp[m][n]$**：由单调性它已是全表最大值；再写一遍遍历求 max 不会错，只是白花 $O(mn)$。
7. **C++ 内存布局**：`vector<vector<int>>` 每次要多一次行寻址，够用；想更快就展平成 `vector<int> dp((m+1)*(n+1))`，下标 `i*(n+1)+j`，同行连续、缓存友好。
8. **Python 降低常数**：把 `row = dp[i]` 与 `prev = dp[i - z]` 提到内层循环外，避免每格两次列表索引；这一步通常能把运行时间压掉一半以上。
9. **值域安全**：答案 $\le \lvert\texttt{strs}\rvert \le 600$，转移只有 $+1$，`int` 足够，不存在溢出问题。
10. **容量可预缩**：把 $m$ 缩到 $\min(m, \sum z_i)$、$n$ 缩到 $\min(n, \sum o_i)$，容量虚高时能少跑很多格。本题 $m, n \le 100$ 收益不大，但这是可迁移的剪枝。

## 5. 正确性证明

**引理 1（倒序读到的是旧值）**：处理物品 $t$（费用 $z_t, o_t$）时，在更新 $dp[i][j]$ 的瞬间，$dp[i-z_t][j-o_t]$ 仍等于第 $t-1$ 轮结束时的值。

**证明**：由 $\lvert s_t\rvert \ge 1$ 得 $z_t + o_t \ge 1$，故 $(i-z_t,\ j-o_t) \ne (i,j)$，两维中至少有一维严格更小。若 $z_t \ge 1$，则 $i - z_t < i$；外层 $i$ 递减，行 $i-z_t$ 在本轮尚未被访问，其内容仍是第 $t-1$ 轮的值。若 $z_t = 0$，则 $o_t \ge 1$ 且 $i - z_t = i$、$j - o_t < j$；内层 $j$ 递减，列 $j-o_t$ 在本轮尚未被访问，该格同样是旧值。∎

**引理 2（状态正确）**：处理完前 $t$ 件物品后，`dp[i][j]` 等于「从前 $t$ 件中选子集、0 总数 $\le i$、1 总数 $\le j$」的最大件数。

**证明**：对 $t$ 归纳。$t = 0$ 时只有空集，`dp` 全 0，成立。设前 $t-1$ 件时结论成立，考察第 $t$ 件费用 $(z,o)$：任一合法子集要么不含它，件数不超过 $dp^{(t-1)}[i][j]$；要么含它，去掉它之后是前 $t-1$ 件中预算为 $(i-z,\ j-o)$ 的合法子集，件数不超过 $dp^{(t-1)}[i-z][j-o] + 1$。算法对每个 $(i,j)$ 恰好在这两个候选上取 max，而由引理 1 读到的 $dp[i-z][j-o]$ 正是 $dp^{(t-1)}$ 的值，故更新后该格等于 $dp^{(t)}[i][j]$。未被更新的格子满足 $i < z$ 或 $j < o$，此时第 $t$ 件装不下，两轮取值相同，也成立。∎

**引理 3（单调性）**：`dp[i][j]` 关于 $i$ 与 $j$ 均单调不减。

**证明**：预算 $(i,j)$ 下的可行子集集合，是预算 $(i',j')$（$i' \ge i$、$j' \ge j$）下可行集合的子集；在更大的集合上取最大值不会变小。∎

**定理**：算法返回的 $dp[m][n]$ 等于题面所求的最大子集大小。

**证明**：引理 2 取 $t = \lvert\texttt{strs}\rvert$、$(i,j) = (m,n)$，得 $dp[m][n]$ 正是所有合法子集的最大件数；再由引理 3，它是全表最大值，故直接返回它即最优解。剪枝只删除了「任何合法子集都容不下」的物品，不影响最优子集，结论不变。∎

## 6. 复杂度分析

- **时间**：预处理 $O\bigl(\sum_i \lvert s_i\rvert\bigr) \le 6 \times 10^{4}$ 次字符比较；DP 对每件物品在 $(m+1) \times (n+1)$ 的容量网格上转移，每格一次加法、一次比较，总计 $O(\lvert\texttt{strs}\rvert \cdot m \cdot n) \le 600 \times 101 \times 101 \approx 6.1 \times 10^{6}$ 次操作。
- **空间**：$O(mn)$，即 $101 \times 101 \approx 1.0 \times 10^{4}$ 个 `int`（约 40 KB）。滚动数组把「物品维」压掉，空间与字符串总数无关；没有额外的集合或字符串拷贝。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findMaxForm(vector<string>& strs, int m, int n) {
        // dp[i][j]：0 的总数 ≤ i、1 的总数 ≤ j 时能选出的最大件数
        vector<vector<int>> dp(m + 1, vector<int>(n + 1, 0));
        for (const string& s : strs) {
            int z = 0;
            for (char c : s) z += (c == '0');
            int o = (int)s.size() - z;
            if (z > m || o > n) continue;          // 单件就超标：任何子集都容不下
            for (int i = m; i >= z; --i)           // 两维都倒序：每件物品最多用一次
                for (int j = n; j >= o; --j)
                    dp[i][j] = max(dp[i][j], dp[i - z][j - o] + 1);
        }
        return dp[m][n];                           // 状态是「至多」，右上角即答案
    }
};
```

### Python

```python
class Solution:
    def findMaxForm(self, strs, m: int, n: int) -> int:
        # dp[i][j]：0 的总数 ≤ i、1 的总数 ≤ j 时能选出的最大件数
        dp = [[0] * (n + 1) for _ in range(m + 1)]
        for s in strs:
            z = s.count('0')
            o = len(s) - z
            if z > m or o > n:                 # 单件就超标，永远选不进
                continue
            for i in range(m, z - 1, -1):      # 两维都倒序
                row = dp[i]                    # 提到内层外，减少索引开销
                prev = dp[i - z]
                for j in range(n, o - 1, -1):
                    v = prev[j - o] + 1
                    if v > row[j]:
                        row[j] = v
        return dp[m][n]
```

## 8. 边界情况与易错点

1. **全部物品都超标**：例如 `strs = ["111"]`、$m = 1$、$n = 2$，该串含 3 个 1，$o = 3 > n$，被剪掉，返回 0；`dp` 全 0 恰好正确。
2. **费用为 0 的一维必须照常转移**：$z = 0$ 的物品（全是 `1` 的串）不消耗 0 的预算，此时 $i$ 仍要走遍全区间 $[m, z]$；若误以为「费用为 0 不用处理」而跳过，就会漏掉整类物品。
3. **某一维费用恒为 0 的数组**：例如全是 `"0"` 或全是 `"1"` 的输入，防重复完全落在另一维的倒序上，这正是「只倒序一维」最容易翻车的用例。
4. **重复字符串必须各算一件**：`strs = ["1","1"]`、$m = 1$、$n = 2$ 的答案是 2，不能对 `strs` 去重。
5. **循环下界写成 0 会负下标**：必须是 `i >= z`、`j >= o`；`i >= 0` 会访问 `dp[i - z]` 的负行。
6. **正序枚举等价于完全背包**：`strs = ["0"]`、$m = 5$、$n = 1$ 时正序写法会把 `"0"` 用 5 次得到 5，正确答案是 1。
7. **用 $-\infty$ 初始化是错的**：它把状态悄悄改成了「恰好用满」语义。例如 `strs = ["0"]`、$m = 5$、$n = 1$，$dp[5][1]$ 会变成不可达，而正确答案是 1；正确做法是全 0 初始化（若要「恰好」语义，则应在最后统一与 0 取 max 并另行判可达）。
8. **不能省掉「不装」分支**：直接赋值 `dp[i][j] = dp[i-z][j-o] + 1`，会在「装它反而不如不装」时覆盖掉历史最优。
