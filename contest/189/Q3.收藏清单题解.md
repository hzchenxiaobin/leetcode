# LeetCode 收藏清单 题解

## 1. 题目概述

- **标题 / 题号**：收藏清单（#1452，medium）
- **链接**：https://leetcode.cn/problems/people-whose-list-of-favorite-companies-is-not-a-subset-of-another-list/
- **来源**：LeetCode 第 189 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、字符串、位运算

**题意**：给出 $n$ 个字符串列表 `favoriteCompanies`，`favoriteCompanies[i]` 是第 $i$ 个人收藏的公司清单。返回所有满足「**不存在** $j \ne i$ 使 $L_i \subseteq L_j$」的下标 $i$（$L_i$ 表示第 $i$ 份清单），下标按升序排列。换句话说，把所有清单按包含关系看成一个偏序集，返回其中的**极大元**——那些没有被任何别人的清单严格包含的清单。

**约束**：

- $1 \le n \le 100$
- $1 \le \lvert L_i \rvert \le 500$
- 每个公司名长度 $\le 20$，仅含小写字母
- 同一份清单内公司名**互不相同**
- 任意两份清单**互不相同**：即使把各自元素排序后比较，$L_i \ne L_j$

> 💡 最后一条很关键：它保证了「$L_i \subseteq L_j$ 且 $j \ne i$」必然是**真包含**，因此判据可以只看「有没有别人的清单把自己整个装下」，不必担心两份清单完全相等时的平局处理。

## 2. 示例

**示例 1**

```text
输入：favoriteCompanies = [["leetcode","google","facebook"],
                          ["google","microsoft"],
                          ["google","facebook"],
                          ["google"],
                          ["amazon"]]
输出：[0,1,4]
解释：L2 = ["google","facebook"] 是 L0 的子集；
      L3 = ["google"] 是 L0（也是 L1）的子集；
      L0、L1、L4 都没有被别人装下，故答案为 [0,1,4]。
```

**示例 2**

```text
输入：favoriteCompanies = [["leetcode","google","facebook"],
                          ["leetcode","amazon"],
                          ["facebook","google"]]
输出：[0,1]
解释：L2 = ["facebook","google"] 比 L0 只少一家 "leetcode"，作为集合它是 L0 的真子集，故排除；
      L0 与 L1 各有一家别人没有的公司，谁也不是谁的子集，故答案为 [0,1]。
```

**示例 3**

```text
输入：favoriteCompanies = [["leetcode"],["google"],["facebook"],["amazon"]]
输出：[0,1,2,3]
解释：四个清单互不包含（都是单元素且互不相同），全部是极大元。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是两两判定：对每个 $i$，枚举 $j \ne i$，看 $L_i$ 的每个元素是否都在 $L_j$ 里。把每份清单塞进哈希集合后，单次判定 $O(\lvert L_i \rvert)$，总复杂度

$$O\Bigl(n^2 \cdot m\Bigr) = 100^2 \times 500 = 5 \times 10^6$$

从数量级看勉强能过，但有两个明显的浪费：

- **字符串哈希开销大**：$5 \times 10^6$ 次 `unordered_set<string>` 查找，每次都要对最长 20 字节的字符串算哈希，C++ 约 $50\sim100$ ms，Python 用 `set` 也要好几秒，处在 TLE 边缘。
- **信息没被复用**：判定 $L_i \subseteq L_j$ 时，我们已经知道「$L_i$ 里有哪些公司」「$L_j$ 里有哪些公司」这两份**静态**数据，却每次从头扫一遍；而 $n-1$ 个 $j$ 的判定过程中，$L_i$ 侧的信息完全重复。

暴力法的瓶颈在于「**为每个 $j$ 单独跑一趟**」。下面把「逐个 $j$ 比较」换成「一次集合求交」。

### 3.2 核心观察：把「谁包含我」翻成「谁同时收藏了我的每个公司」

![把子集判定转成位集求交](images/wc189_q3_inverted_bitset_idea.svg)

关键是把「集合包含」拆到**元素粒度**：

$$L_i \subseteq L_j \iff \forall c \in L_i,\ c \in L_j$$

现在为每个公司 $c$ 预先记下**收藏它的人**：

$$S_c = \{\, j : c \in L_j \,\}$$

于是「$L_i$ 的每个元素都被 $j$ 收藏」就变成「$j$ 同时属于所有 $S_c$」：

$$L_i \subseteq L_j \iff j \in \bigcap_{c \in L_i} S_c$$

记 $T_i = \bigcap_{c \in L_i} S_c$，则 $T_i$ 恰好是「清单包含 $L_i$ 的**所有人**」的集合。于是判据变成一句话：

$$i \text{ 是答案} \iff T_i = \{i\}$$

这个翻转带来两个好处：

1. **原来对 $j$ 的循环消失了**。求 $T_i$ 只需遍历 $L_i$ 自己的 $\lvert L_i \rvert$ 个元素，与 $n$ 无关——$n$ 被「塞进了位集」。
2. **位集让一次求交几乎免费**。$T_i$ 是 $\{0,\dots,n-1\}$ 的子集且 $n \le 100$，用 $100$ 位位集（C++ `bitset<100>`，Python 任意精度整数）表示后，一次求交只是 $\lceil n/64 \rceil \le 2$ 个机器字的与运算。

此外还有一个免费的剪枝：因为 $i \in S_c$ 对每个 $c \in L_i$ 都成立，所以 $T_i$ **恒包含 $i$**。于是求交过程中一旦 $T_i$ 缩小到只剩 $\{i\}$，它就不可能再变大，可以立即 `break`——这是**早停**的依据。

### 3.3 算法流程

![倒排 + 求交 + 早停的流程](images/wc189_q3_intersect_flow.svg)

1. **建倒排表**：扫一遍所有清单，对第 $i$ 份清单里的每个公司 $c$ 执行 `like[c] |= (1 << i)`。总共 $\sum_i \lvert L_i \rvert$ 次置位，最多 $5 \times 10^4$ 次。
2. **逐人求交**：对 $i = 0,1,\dots,n-1$，令 `inter` 取恒等元「全 1」（Python 直接写 `-1`，C++ 写 `bitset<100> b; b.set();`）。
3. **遍历清单**：对 $c \in L_i$ 执行 `inter &= like[c]`；每次与运算后检查 `inter` 是否已等于 `1 << i`，若相等则立即 `break`。
4. **收集答案**：`inter == (1 << i)` 时把 $i$ 加入答案。因为 $i$ 是递增扫描的，答案**天然升序**，不需要再排序。

### 3.4 示例演算

![示例 1 的逐人求交表](images/wc189_q3_example_walkthrough.svg)

以示例 1 为例，先建好倒排表：

$$\text{like}[\text{google}] = \{0,1,2,3\},\quad \text{like}[\text{facebook}] = \{0,2\},\quad \text{like}[\text{leetcode}] = \{0\}$$
$$\text{like}[\text{microsoft}] = \{1\},\quad \text{like}[\text{amazon}] = \{4\}$$

再逐人求交：

| 用户 $i$ | 清单 $L_i$ | 求交过程 | $T_i$ | 是答案 |
|----------|------------|----------|-------|--------|
| 0 | leetcode, google, facebook | $\{0\} \cap \{0,1,2,3\} \cap \{0,2\}$ | $\{0\}$ | ✓ |
| 1 | google, microsoft | $\{0,1,2,3\} \cap \{1\}$ | $\{1\}$ | ✓ |
| 2 | google, facebook | $\{0,1,2,3\} \cap \{0,2\}$ | $\{0,2\}$ | ✗（被 0 包含） |
| 3 | google | $\{0,1,2,3\}$ | $\{0,1,2,3\}$ | ✗（被 0、1、2 包含） |
| 4 | amazon | $\{4\}$ | $\{4\}$ | ✓ |

用户 3 的清单只有一家公司，一次与运算就得到 $\{0,1,2,3\}$，已经能看出「被三个人包住」，直接 `break`；用户 2 的交集是 $\{0,2\}$，多出来的 $0$ 正是「包含它的人」。最终按升序输出 `[0,1,4]`，与官方答案一致。

整个演算只做了 $3+2+2+1+1 = 9$ 次位集与运算，而两两暴力要跑 $5 \times 4 / 2 = 10$ 对、每对最多 500 次字符串查找。

## 4. 算法细节

1. **倒排表用哈希表**：键是公司名（`string`），值是位集。总条目数不超过 $\min(50000, \sum_i \lvert L_i \rvert)$；C++ 里对 `unordered_map` 调用 `reserve` 可避免多次 rehash，Python 的 `dict` 无需干预。
2. **位宽必须按 $n$ 取，不能是 64**：$n$ 最大 100，`unsigned long long` 只装得下 0 号到 63 号用户，剩下 36 位会被静默截断，表现为大 $n$ 时答案错得莫名其妙。C++ 用 `bitset<100>`（16 字节），Python 用任意精度整数。
3. **恒等元的选择**：求交的起点必须是「全集」而不是空集。Python 用 `-1`（无限位补码，`-1 & x == x`），C++ 用 `bitset` 的 `.set()`；若误写成 `0` 或默认构造（全 0），交集永远是 0，所有人都会被判成答案。
4. **早停条件是 `inter == (1 << i)`**：因为 $i$ 必然留在交集中，「只剩自己」等价于「等于 `1 << i`」。C++ 里也可以用 `inter.count() == 1` 代替，两者等价且 `count()` 只需 2 个机器字的 popcount。
5. **`&=` 之后才判断**：`inter` 初值是全 1（$n=1$ 时恰好就是 `1 << 0`），若把判断放到循环前面，虽然 $n=1$ 时结果碰巧正确，但逻辑上是在「还没查任何公司」时就下结论，属于靠巧合过题。养成「先与、后判」的次序。
6. **不必排序，也不必每轮重算 `1 << i`**：暴力方案常先排序再双指针，但倒排 + 位集完全不需要顺序信息，省掉 $\sum_i \lvert L_i \rvert \log \lvert L_i \rvert$ 的排序开销；Python 里把 `bit = 1 << i` 提到内层循环外即可。
7. **重复公司名天然免疫**：`like[c] |= bit` 是幂等的，即使某份清单里出现重复字符串也不会破坏结果（题面保证不会出现，但这份稳健性是白送的）。

## 5. 正确性证明

**引理 1（交集语义）**：对任意 $i$，有 $\displaystyle\bigcap_{c \in L_i} S_c = \{\, j : L_i \subseteq L_j \,\}$。

**证明**：按定义展开，
$$j \in \bigcap_{c \in L_i} S_c \iff \forall c \in L_i,\ j \in S_c \iff \forall c \in L_i,\ c \in L_j \iff L_i \subseteq L_j$$
三个「$\iff$」分别是交集定义、$S_c$ 的定义、子集定义的直接改写。∎

**引理 2（自己恒在交集中）**：对任意 $i$ 与任意 $c \in L_i$，有 $i \in S_c$；从而 $i \in T_i$。

**证明**：$c \in L_i$ 意味着第 $i$ 个人收藏了 $c$，按 $S_c$ 的定义 $i \in S_c$。对所有 $c \in L_i$ 成立，故 $i$ 属于交集。∎

**引理 3（早停安全）**：若在求交的某一步之后 $T_i = \{i\}$，则继续与剩余的 $S_c$ 求交，结果仍是 $\{i\}$。

**证明**：后续交集是当前交集 $\{i\}$ 的子集，且由引理 2 它恒包含 $i$，故只能等于 $\{i\}$。∎

**定理**：算法输出的集合恰为 $\{\, i : \text{不存在 } j \ne i \text{ 使 } L_i \subseteq L_j \,\}$，且按下标升序。

**证明**：由引理 1，$T_i = \{j : L_i \subseteq L_j\}$，而 $i$ 自身总在其中（引理 2），故

$$T_i = \{i\} \iff \{\, j : L_i \subseteq L_j \,\} = \{i\} \iff \text{不存在 } j \ne i \text{ 使 } L_i \subseteq L_j$$

算法对每个 $i$ 精确地计算并比较了这一条件；引理 3 说明提前 `break` 不会改变 $T_i$ 的取值。收集时 $i$ 从 $0$ 递增，输出的下标自然升序。∎

> 💡 由于「所有清单两两不同」（约束第 5 条），上式中的 $L_i \subseteq L_j$（$j \ne i$）自动是真包含，因此答案也可以等价地描述为「包含偏序下的极大元」。即使去掉这条约束（允许清单重复），上述判据依然正确——重复的清单会互相包含，从而全部被判为非极大元，这与题意「是别人的子集」并不冲突，只是题意希望的行文里不会出现这种输入。

## 6. 复杂度分析

- **时间**：建倒排表 $O\bigl(\sum_i \lvert L_i \rvert\bigr)$ 次字符串哈希 + 置位；求交阶段对每个人做 $\lvert L_i \rvert$ 次位集与运算，每次 $O(\lceil n/64 \rceil)$，合计 $O\bigl(\sum_i \lvert L_i \rvert \cdot \lceil n/64 \rceil\bigr)$。代入上界：$\sum_i \lvert L_i \rvert \le 100 \times 500 = 5 \times 10^4$，$\lceil 100/64 \rceil = 2$，即约 $10^5$ 次机器字运算，只有两两暴力 $5 \times 10^6$ 次字符串查找的 $1/50$；而且字运算比字符串哈希便宜得多，实际差距更大。早停只会让运算更少。
- **空间**：倒排表最多存 $\min(50000, \sum_i \lvert L_i \rvert)$ 个位集，每个 16 字节，约 800 KB 量级；此外只有常数个临时位集。注意这里的空间是 $O(\text{不同公司数} \times n/64)$，与「$O(n^2)$ 的两两比较矩阵」不同——我们并不保存任何 $n \times n$ 的关系表。

## 7. 参考代码

### C++

```cpp
#include <bitset>
#include <string>
#include <unordered_map>
#include <vector>

using namespace std;

class Solution {
public:
    vector<int> peopleIndexes(vector<vector<string>>& favoriteCompanies) {
        const int n = favoriteCompanies.size();

        // 倒排索引：公司 -> 收藏它的用户位集（第 i 位为 1 表示用户 i 收藏了它）
        unordered_map<string, bitset<100>> like;
        like.reserve(1024);
        for (int i = 0; i < n; i++)
            for (const string& c : favoriteCompanies[i])
                like[c].set(i);

        vector<int> ans;
        for (int i = 0; i < n; i++) {
            bitset<100> inter;
            inter.set();                              // 全 1 的恒等元
            for (const string& c : favoriteCompanies[i]) {
                inter &= like[c];
                if (inter.count() == 1) break;        // 只剩自己，继续求交不会变大
            }
            if (inter.count() == 1) ans.push_back(i); // 除自己外没人包含整份清单
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def peopleIndexes(self, favoriteCompanies: List[List[str]]) -> List[int]:
        n = len(favoriteCompanies)

        # 倒排索引：公司名 -> 收藏它的用户位集（第 i 位为 1 表示用户 i 收藏了它）
        like = {}
        for i, lst in enumerate(favoriteCompanies):
            bit = 1 << i
            for c in lst:
                like[c] = like.get(c, 0) | bit

        ans = []
        for i, lst in enumerate(favoriteCompanies):
            inter = -1                       # 全 1 的恒等元（Python 无限位补码）
            for c in lst:
                inter &= like[c]
                if inter == (1 << i):        # 只剩自己，继续求交不会变大
                    break
            if inter == (1 << i):            # 除自己外没人包含整份清单
                ans.append(i)
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有一个人，他的清单不可能被别人包含，答案必为 `[0]`。代码里 `inter` 初值全 1 恰好就是 `1 << 0`，与运算后仍是它，判据成立——但不要依赖这个巧合，正常流程同样得到 `[0]`。
2. **空清单（题面保证不出现）**：若 $L_i = \varnothing$，循环体不执行，`inter` 保持全 1。此时 $n>1$ 会把 $i$ 判为非答案（空集是任何集合的子集，正确）；$n=1$ 会判为答案（空集包含于自身，也正确）。
3. **位宽写小**：用 `long long`（64 位）或 `int` 装 $n=100$ 的用户集合会**静默截断**，第 64 位以后的用户全部丢失，答案会随机性地偏多。必须用 `bitset<100>` 或两个 `uint64_t`。
4. **恒等元写成 0**：`inter = 0` 与任何位集求交仍是 0，于是所有人都「只剩自己」，输出 `[0,1,...,n-1]`。这是本题最容易犯、也最难一眼看出的错误。
5. **忘记「$i$ 必在交集中」这个不变量**：若用「`inter` 里是否还有别人」的判据，必须先扣掉自己（例如 `inter & ~(1 << i)`），语义就绕了；直接比较 `inter == (1 << i)` 或 `count() == 1` 更简洁，也不容易写错。
6. **把「升序」交给排序**：若为了剪枝改成按清单大小降序处理（只与已确认的极大元比较），就必须最后再对答案排序；本解法按 $i$ 递增扫描，天然满足升序，别多此一举地放进 `set` 再取出。
7. **大 $n$ 的 rehash 与空输出**：$\sum_i \lvert L_i \rvert$ 可达 $5 \times 10^4$，`unordered_map` 不 `reserve` 会多次 rehash（`reserve` 到 $2^{10}$ 以上即可）；另外有限偏序集必有极大元，答案不会为空，若返回空 `vector` 多半是恒等元或位宽出了问题。

**延伸思考**：本题只问了偏序里最便宜的一层——「极大元」。若把问题加码，思路会明显不同：

- 若 $n$ 放大到 $10^5$ 而每份清单很短，倒排位集会退化成每人 $12.5$ KB，内存直接爆掉。此时应改走「先按 $\lvert L_i \rvert$ **降序**排序，只与已确认的极大元比较」的路子——因为「被包含」是**传递**的（$L_k \subseteq L_i \subseteq L_j \Rightarrow L_k \subseteq L_j$），一旦某份清单被淘汰，它永远不必再当裁判，实测常数极小。
- 若要求「每份清单被多少人包含」而不是「是否被包含」，把判据换成 $\operatorname{popcount}(T_i) - 1$ 即可，位集方案一行都不用改；若要求偏序上的**最长包含链**则是最长链 DP，若是**最大两两不可比集合**（最大反链）则由 Dilworth 定理转化为二分图匹配——从「极大元」走到「最大反链」，正是偏序问题难度上升的典型阶梯。
