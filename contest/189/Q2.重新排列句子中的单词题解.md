# LeetCode 重新排列句子中的单词 题解

## 1. 题目概述

- **标题 / 题号**：重新排列句子中的单词（#1451，medium）
- **链接**：https://leetcode.cn/problems/rearrange-words-in-a-sentence/
- **来源**：LeetCode 第 189 场周赛 Q2
- **难度**：中等
- **标签**：字符串、排序

**题意**：给定一个句子 `text`，单词之间用**单个空格**分隔，且句子的首字母大写、其余字母小写。把所有单词按**长度升序**重排；长度相同时**保持它们在原句中的相对顺序**。返回重排后的句子，格式要求不变——仍然是「首字母大写 + 单词间单个空格 + 其余字母小写」。注意输出格式的含义：排到第一位的词要**首字母大写**，而原来排在第一位的词一旦挪到后面，它的首字母必须**改回小写**（示例 1 的 `"Leetcode is cool"` → `"Is cool leetcode"` 正是这条规则）。

**约束**：

- $1 \le \lvert \text{text} \rvert \le 10^5$
- `text` 以大写字母开头，随后是小写字母与单词间的单个空格
- 单词只含小写字母（首词首字母除外），不会出现前导/尾随空格或连续空格

## 2. 示例

**示例 1**
```text
输入：text = "Leetcode is cool"
输出："Is cool leetcode"
解释：长度 8 的 "Leetcode"、长度 2 的 "is"、长度 4 的 "cool"；
      按长度升序为 is(2) → cool(4) → Leetcode(8)，
      拼接后首词首字母大写、原首词 "Leetcode" 变回小写 "leetcode"。
```

**示例 2**
```text
输入：text = "Keep calm and code on"
输出："On and keep calm code"
解释：On(2) → and(3) → keep(4) → calm(4) → code(4)；
      三个长度 4 的词保持原相对顺序 keep、calm、code。
```

**示例 3**
```text
输入：text = "To be or not to be"
输出："To be or to be not"
解释：前五个词长度都是 2，顺序原样保留，只有长度 3 的 "not" 被挪到末尾；
      输出恰好与原句只在末尾换位，首词仍需大写（"To"）。
```

> 💡 官方提示（Hint）已经点明方向：**为每个单词记录「长度 + 原始位置」，按长度排序、长度相同则按原始位置排序**。本题的落点是把这句话用最短的代价实现出来。

## 3. 解题思路

### 3.1 暴力思路

把单词看成二元组 $(\text{len}_i, i)$，直接用比较排序：

- **插入排序 / 冒泡排序**：按 $(\text{len}, i)$ 两两比较，比较次数 $O(k^2)$，其中 $k$ 是单词数。当 `text` 全由单字母单词构成时 $k \approx 5 \times 10^4$，$k^2 \approx 2.5 \times 10^9$，常数再小也过不去。
- **每轮线性扫描选「当前最短且最靠前」的词**：同样是 $O(k^2)$，只是把比较换成了扫描。
- **比较排序**（`sort` / `stable_sort`）：$O(k \log k)$ 次比较，$k \le 5\times 10^4$ 时约 $8 \times 10^5$ 次，足够通过。这是「正确但没吃到题目结构」的写法。

暴力的问题在于：它把「长度」当成任意整数去比较。但本题的长度是小整数，且排序键的第二维就是**原始下标**——这两点合起来恰好可以用**线性**的桶排序替代比较。

### 3.2 核心观察：双关键字排序 ⇔ 按长度稳定排序

![按 (长度, 原下标) 升序等价于对长度做稳定排序](images/wc189_q2_stable_sort_key.svg)

**观察一（键的结构）**：排序键是 $(\text{len}_i, i)$，其中 $i$ 是单词在**原句中的下标**，互不相同。于是 $(\text{len}_i, i)$ 构成**全序**，答案唯一，没有「并列时选谁」的歧义。

**观察二（等价于稳定排序）**：因为第二关键字就是原下标，所以「按 $(\text{len}, i)$ 升序」与「**只按长度做一次稳定排序**」的结果完全相同：

$$\text{sort}\big((\text{len}_i, i)\big) \;=\; \text{stable sort}\big(\text{len}_i\big)$$

稳定排序的定义就是「键相等的元素保持原相对顺序」，而原下标升序正是原相对顺序。**推论**：不必真的构造二元组去比较，只要排序过程**稳定**即可——Python 的 `sort` 天生稳定，C++ 则要用 `stable_sort`，而桶排序把稳定性直接「构造」了出来。

**观察三（长度是稠密小整数）**：单词长度取值只有 $1, 2, \dots, \text{maxLen}$，其中 $\text{maxLen}$ 是最长单词长度、且 $\text{maxLen} \le \lvert \text{text} \rvert$。于是可以开 $\text{maxLen} + 1$ 个桶，**按原句顺序**把单词 append 进 `buckets[len]`，再从小到大遍历桶号拼接。桶内「先来先放」，稳定性是**构造出来**的，不需要任何比较。

**观察四（大小写只需改两个字符）**：题面保证全句只有首词首字母是大写。所以先把首词首字母改成小写（$O(1)$），最后把拼接结果的首字符改成大写（$O(1)$），整句就符合格式要求了。**不要**对全句做 `lower()` 或 `title()`：前者多一次扫描，后者会把每个词首字母都大写，直接错。

> 🎯 一句话：**按长度入桶（稳定） + 桶号升序拼接 + 只补一个首字母大写**，三步都是线性的。

### 3.3 算法流程

![算法流程：切词、首词小写化、入桶、升序拼接、补大写](images/wc189_q2_bucket_flow.svg)

1. **切词**：按单个空格切出 `words[0..k-1]`，保留原有顺序（下标即原位置）。
2. **归一大小写**：`words[0]` 的首字母转小写。此后所有单词都是纯小写。
3. **入桶**：按下标从小到大遍历，`buckets[len(words[i])].push_back(words[i])`。
4. **升序拼接**：$L$ 从 $1$ 到 $\text{maxLen}$，依次输出 `buckets[L]` 中的词，词间插一个空格；空桶直接跳过。
5. **补大写**：把结果串的首字符转大写，返回。

这里没有一步需要比较两个单词，全部是「遍历 + 取下标」，因此总代价与句子长度线性相关。

### 3.4 示例演算

![示例 "Keep calm and code on" 的入桶与拼接过程](images/wc189_q2_walkthrough.svg)

以示例 2 的 `text = "Keep calm and code on"` 为例，先记录每个词的 $(\text{len}, i)$：

| 单词 | 长度 | 原下标 | 落入的桶 |
|------|------|--------|----------|
| Keep | 4 | 0 | `buckets[4]` |
| calm | 4 | 1 | `buckets[4]` |
| and | 3 | 2 | `buckets[3]` |
| code | 4 | 3 | `buckets[4]` |
| on | 2 | 4 | `buckets[2]` |

若直接按 $(\text{len}, i)$ 排序，得到 `on(2,4) → and(3,2) → Keep(4,0) → calm(4,1) → code(4,3)`，与原句下标升序完全一致。桶排序的效果相同：

| 步骤 | 内容 |
|------|------|
| 桶 2 | `on` |
| 桶 3 | `and` |
| 桶 4 | `Keep`、`calm`、`code`（按原序，稳定） |
| 拼接（Keep 已小写化） | `"on and keep calm code"` |
| 首字符大写 | `"On and keep calm code"` |

再验证示例 3 的 `"To be or not to be"`：五个长度 2 的词 `To, be, or, to, be` 全在桶 2 中且保持原序，长度 3 的 `not` 在桶 3，拼接即 `"To be or to be not"`，与原句一致。

## 4. 算法细节

1. **大小写归一化必须在入桶之前**：因为原首词可能被排到中间（示例 1 的 `Leetcode` 排到末尾）。提前小写化后，「拼接结果里唯一的大写字母」只可能是最后人为补上的那个首字符，逻辑最简单。
2. **只改两个字符**：入桶前只改 `words[0][0]`，返回前只改 `res[0]`。不要用 Python 的 `str.capitalize()`（它会 `lower()` 整串，正确但多一次 $O(n)$ 扫描），更不要用 `str.title()`——`title()` 会把空格后每个字母都大写，示例 2 会得到 `"On And Keep Calm Code"`。
3. **桶的尺寸取 `maxLen + 1`**：下标 $0$ 的空桶不用（单词长度至少为 1）。先扫一遍求 `maxLen`，再开数组；不要盲开 $10^5 + 1$ 个 `vector`/`list`，虽然也能过，但空桶太多会拖慢常数（$10^5$ 个空容器本身就有分配开销）。
4. **手写切词**：C++ 里逐字符扫描比 `stringstream` 快，且能避免 `>>` 对空格的额外处理；Python 直接 `text.split(' ')`（题面保证只有一个空格，用 `split(' ')` 或 `split()` 都对）。
5. **拼接时少一次判空**：C++ 用 `if (!res.empty()) res += ' ';` 再追加单词，避免「先加空格再去掉末尾空格」的二次修剪；Python 直接 `' '.join(out)`。
6. **比较排序也是合法解**：C++ `stable_sort(words.begin(), words.end(), [](auto& a, auto& b){return a.size() < b.size();})`，Python `sorted(words, key=len)` 本身就是稳定的。$O(n \log n)$ 在 $10^5$ 规模下约 $2 \times 10^6$ 次操作，同样能过；桶排序只是把 $\log n$ 也消掉，且更能体现「键是稠密小整数」这一结构。
7. **`tolower` / `toupper` 的入参类型**：C++ 中 `char` 可能是有符号的，传入负值时是未定义行为，规范写法是 `tolower((unsigned char)c)`。本题字符集只有小写字母和一个大写字母，实际不会出问题，但写成带 `unsigned char` 的版本是习惯。

## 5. 正确性证明

**引理 1（桶内保序）**：对任意长度 $L$，`buckets[L]` 中单词的下标严格递增。

**证明**：入桶时按下标 $i$ 从小到大遍历原句，每个长度为 $L$ 的词按遇到顺序 append 到 `buckets[L]` 尾部，因此桶内下标序列递增。∎

**引理 2（拼接后长度非降）**：拼接结果中相邻两个单词 $w_j, w_{j+1}$ 满足 $\text{len}(w_j) \le \text{len}(w_{j+1})$。

**证明**：拼接按桶号 $L = 1, 2, \dots, \text{maxLen}$ 升序进行，同一桶内全部单词长度都等于 $L$。因此输出序列分成若干段，段内长度相等、段间长度严格递增；一段结束进入下一段时长度只会变大，跨段取相邻两词也满足非降。∎

**引理 3（输出格式正确）**：拼接结果首字符大写、其余字符小写、单词间恰一个空格。

**证明**：算法第 2 步把原首词首字母小写后，所有单词均为纯小写（题面保证其余字符本来就小写）；拼接只在词与词之间插入一个空格，不产生连续空格或尾随空格；返回前把首字符改成大写，其余位置未被改动，故格式符合要求。∎

**定理（算法正确）**：算法输出即题目要求的唯一答案。

**证明**：设正确排列为「只在长度上做一次稳定排序」的结果。由引理 1，桶内下标递增，故同一长度的词之间相对顺序与原句一致；由引理 2，桶号升序拼接给出长度非降的顺序。长度非降 + 同长保原序恰好唯一确定目标排列（$(\text{len}, i)$ 是全序，见 3.2 观察一），故输出顺序正确；再由引理 3，大小写与分隔符正确。∎

## 6. 复杂度分析

- **时间**：$O(n + \text{maxLen})$，其中 $n = \lvert \text{text} \rvert$。切词 $O(n)$；求 `maxLen`、入桶各 $O(n)$；按桶号遍历 $O(\text{maxLen} + n)$（拼接的字符总量不超过 $n$）；大小写两次 $O(1)$。由于 $\text{maxLen} \le n$，总复杂度即 $O(n)$。
- **空间**：$O(n)$。单词本身占用 $O(n)$（C++ 中是子串拷贝，Python 中是不可变字符串的新对象）；桶数组共 $O(\text{maxLen} + k)$ 个槽位，$k \le n$；输出串 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <cctype>
using namespace std;

class Solution {
public:
    string arrangeWords(string text) {
        // 1. 按单个空格切词
        vector<string> words;
        string cur;
        for (char ch : text) {
            if (ch == ' ') {
                words.push_back(cur);
                cur.clear();
            } else {
                cur += ch;
            }
        }
        if (!cur.empty()) words.push_back(cur);
        if (words.empty()) return "";

        // 2. 全句唯一的大写字母：原首词的首字母，先改成小写
        words[0][0] = (char)tolower((unsigned char)words[0][0]);

        // 3. 求最长单词长度并开桶
        int maxLen = 0;
        for (const string& w : words)
            if ((int)w.size() > maxLen) maxLen = (int)w.size();

        vector<vector<string>> buckets(maxLen + 1);
        for (const string& w : words) buckets[w.size()].push_back(w);

        // 4. 桶号升序拼接，桶内保持原序（稳定）
        string res;
        for (int L = 1; L <= maxLen; L++) {
            for (const string& w : buckets[L]) {
                if (!res.empty()) res += ' ';
                res += w;
            }
        }

        // 5. 只给首字符补大写
        res[0] = (char)toupper((unsigned char)res[0]);
        return res;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def arrangeWords(self, text: str) -> str:
        # 1. 按单个空格切词
        words = text.split(' ')

        # 2. 原首词首字母小写化（全句唯一的大写字母就在这里）
        words[0] = words[0][0].lower() + words[0][1:]

        # 3. 求最长单词长度，按长度开桶
        max_len = 0
        for w in words:
            if len(w) > max_len:
                max_len = len(w)

        buckets: List[List[str]] = [[] for _ in range(max_len + 1)]
        for w in words:
            buckets[len(w)].append(w)   # 按原句顺序 append ⇒ 桶内天然稳定

        # 4. 桶号升序拼接
        out: List[str] = []
        for length in range(1, max_len + 1):
            out.extend(buckets[length])

        res = ' '.join(out)

        # 5. 只给首字符补大写，其余保持小写
        return res[0].upper() + res[1:]
```

## 8. 边界情况与易错点

1. **原首词被挪走**：`"Leetcode is cool"` 中 `Leetcode` 排到末尾，输出必须是 `leetcode` 全小写。只做「首词大写」而不做「首词提前小写化」，会得到 `"Is cool Leetcode"`，与答案不符。
2. **误用 `title()` / 逐词大写**：`"Keep calm and code on"` 的正确输出是 `"On and keep calm code"`，只有 `On` 大写。`title()` 会输出 `"On And Keep Calm Code"`，直接 WA。
3. **只有一个单词**：`text = "Hello"` 时入桶、拼接后仍是 `hello`，再补大写回到 `Hello`。代码必须保证 `words` 非空时才能取 `words[0][0]`；本题 $n \ge 1$ 且无前导空格，故不会出现空词，但手写切词时仍应处理「最后一段没有空格结尾」的情况（`if (!cur.empty())`）。
4. **所有单词等长**：`"Ab cd ef"` 全部长度 2，桶里保序 ⇒ 输出与原句相同（首词仍是大写），不要因为「排序后应该变化」而写错。
5. **稳定性只靠 `sort` 不够**：C++ 的 `std::sort` **不稳定**，若用比较排序必须写 `stable_sort` 或把下标作为第二关键字带进比较器；Python 的 `sort` / `sorted` 稳定，可以只写 `key=len`。
6. **桶数组下标越界**：长度为 $L$ 的词要放进 `buckets[L]`，桶数组大小为 `maxLen + 1`；若把 `maxLen` 算成「单词个数」或忘记 `+1`，最长词会越界。
7. **拼接出多余空格**：C++ 中若在每个词后面无条件 `+= ' '`，末尾会多一个空格；正确做法是「非首个词前补空格」或最后 `pop_back`。
8. **`toupper` 的负数入参**：严格来说要传 `unsigned char` 再转换，避免有符号 `char` 为负时触发未定义行为。
