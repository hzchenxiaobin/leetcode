# LeetCode 在既定时间做作业的学生人数 题解

## 1. 题目概述

- **标题 / 题号**：在既定时间做作业的学生人数（#1450，easy）
- **链接**：https://leetcode.cn/problems/number-of-students-doing-homework-at-a-given-time/
- **来源**：LeetCode 第 189 场周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给出两个等长数组 `startTime`、`endTime` 与查询时刻 `queryTime`。第 $i$ 名学生在 `startTime[i]` 开始写作业、在 `endTime[i]` 完成作业。返回满足

$$\text{startTime}[i] \le \text{queryTime} \le \text{endTime}[i]$$

的学生个数，即 `queryTime` 落在闭区间 $[\text{startTime}[i],\, \text{endTime}[i]]$ 内的学生人数。

**约束**：

- `startTime.length == endTime.length`，长度记为 $n$
- $1 \le n \le 100$
- $1 \le \text{startTime}[i] \le \text{endTime}[i] \le 1000$
- $1 \le \text{queryTime} \le 1000$

> 💡 一句话定位：这是一道「翻译题面」的签到题——把「在时刻 $q$ 正在做作业」翻译成「$q$ 落在闭区间内」，然后数一数。真正值得沉淀的是两点：**闭区间与端点**，以及**把两条件拆成两个端点的计数视角**。

## 2. 示例

**示例 1**

```text
输入：startTime = [1,2,3], endTime = [3,2,7], queryTime = 4
输出：1
解释：学生 0 的区间 [1,3] 在 4 之前就结束了；
      学生 1 的区间 [2,2] 是单点，也不含 4；
      只有学生 2 的区间 [3,7] 覆盖 4，故答案为 1。
```

**示例 2**

```text
输入：startTime = [1,1,1,1], endTime = [1,3,2,4], queryTime = 7
输出：0
解释：所有学生最晚在时刻 4 完成作业，时刻 7 一个人都没有，返回 0。
```

**示例 3**

```text
输入：startTime = [9,8,7,6,5,4,3,2,1], endTime = [10,10,10,10,10,10,10,10,10], queryTime = 5
输出：5
解释：startTime 是逆序的，但算法完全不依赖顺序；
      9 个区间都延伸到 10，只需数 startTime[i] ≤ 5 的个数：5,4,3,2,1 共 5 个。
```

## 3. 解题思路

### 3.1 暴力思路

题意没有给出任何「合并」「优化」的余地，暴力写法仍然是可行的，只是**做多了无用功**：

- **按时间枚举**：对时间轴上每个整数时刻 $t$ 统计覆盖它的学生数，最后取 $t = q$。复杂度 $O(Tn) \le 1000 \times 100 = 10^5$。
- **按学生涂色**：对每个学生，把它区间内的每个时刻 $t \in [\text{startTime}[i], \text{endTime}[i]]$ 都打一次标记，再读标记数组下标 $q$。复杂度 $O(\sum (\text{endTime}[i] - \text{startTime}[i] + 1)) \le 10^5$。

两者都能过题，但都把一个 $O(1)$ 的区间判定重复了成千上万次。更本质的问题是：我们只关心**一个时刻**，却铺开了一整条时间轴。本题正解不需要任何数据结构，也不需要排序。

### 3.2 核心观察：区间包含 ⇔ 两个端点不等式

![核心观察：queryTime 落在闭区间内才算命中](images/wc189_q1_interval_containment.svg)

题面说学生 $i$ 在 `startTime[i]` **开始**写作业、在 `endTime[i]` **完成**作业，因此这个学生「正在做作业」的时刻集合恰好是

$$[\text{startTime}[i],\; \text{endTime}[i]] = \{t \in \mathbb{Z} : \text{startTime}[i] \le t \le \text{endTime}[i]\}.$$

于是「$q$ 时刻学生 $i$ 在做作业」等价于两个彼此独立的整数比较同时成立：起点不晚于 $q$，终点不早于 $q$。每个学生只贡献一次 $O(1)$ 判定，$n$ 个学生互不影响，答案就是把命中次数累加起来。

还有一条常被忽略的**分解视角**。因为题面保证 $\text{startTime}[i] \le \text{endTime}[i]$，所以「终点早于 $q$」的学生必然「起点也不晚于 $q$」，即集合 $\{\text{endTime}[i] < q\} \subseteq \{\text{startTime}[i] \le q\}$，于是

$$\#\{\text{startTime}[i] \le q \le \text{endTime}[i]\} = \#\{\text{startTime}[i] \le q\} - \#\{\text{endTime}[i] < q\}.$$

这次查询只需要一次线性扫描，用不上这个恒等式；但它说明**两个端点可以分开处理**，只有一次端点查询的版本就能用「排序 + 二分」做到 $O(\log n)$，用差分前缀和甚至能 $O(1)$ 回答任意时刻——这是后面「延伸思考」的伏笔。

### 3.3 算法流程

![算法流程：线性扫描 + 短路判定](images/wc189_q1_scan_flow.svg)

```text
ans = 0
for i = 0 .. n-1:
    if startTime[i] <= queryTime and queryTime <= endTime[i]:
        ans += 1
return ans
```

循环体只做一件事：判定。由于 `and` 是**短路求值**，一旦 `startTime[i] > queryTime`（区间还没开始）就直接跳过，连 `endTime[i]` 都不会读——在数据里「尚未开始」的学生往往占多数，这个常数优化几乎免费。

这里还有一个值得强调的写法问题：判定条件必须写成 `start <= q && q <= end`（或 `start <= q and q <= end`）。写成 `q in range(start, end)` 之类的构造会在 $O(n)$ 循环里凭空多出 $O(\text{end} - \text{start})$ 的开销，把签到题做成暴力题。

### 3.4 示例演算

![示例演算：q = 4 时逐个学生判定](images/wc189_q1_walkthrough.svg)

走查示例 1（$\text{startTime} = [1,2,3]$，$\text{endTime} = [3,2,7]$，$q = 4$）：

| 学生 $i$ | $\text{startTime}[i]$ | $\text{endTime}[i]$ | $\text{startTime}[i] \le 4$ | $4 \le \text{endTime}[i]$ | 是否命中 |
|----------|----------------------|--------------------|----------------------------|--------------------------|----------|
| 0 | 1 | 3 | 是 | 否 | ✗ |
| 1 | 2 | 2 | 是 | 否 | ✗ |
| 2 | 3 | 7 | 是 | 是 | ✓ |

累加得到 $0 + 0 + 1 = 1$，与官方输出一致。再用 §3.2 的分解视角复核一遍：$\#\{\text{startTime}[i] \le 4\} = 3$（$1,2,3$ 全部满足），$\#\{\text{endTime}[i] < 4\} = 2$（$3$ 与 $2$ 都严格小于 $4$），相减得 $3 - 2 = 1$，两条路径殊途同归。

## 4. 算法细节

1. **区间必须按闭区间判定**：`endTime[i] = queryTime` 表示学生「恰好在这一刻完成」，仍算正在做作业；`startTime[i] = queryTime` 同理。因此两个不等号都要带等号，写成 `<` 会漏掉端点上的学生。
2. **短路顺序**：先写 `startTime[i] <= queryTime`，再写 `queryTime <= endTime[i]`。区间尚未开始时第一个条件即为假，第二个条件被短路跳过，平均比较次数显著低于 2。
3. **两个数组等长**：题面保证 `startTime.length == endTime.length`，可以直接按下标同步访问；Python 用 `zip(startTime, endTime)` 一次取出两端点，C++ 用下标循环，都不需要额外判断长度。
4. **计数器类型**：答案最大为 $n \le 100$，`int` 足够，不必考虑溢出；但返回值是**人数**，不要顺手返回最后一个命中学生的下标。
5. **不依赖顺序**：示例 3 的 `startTime` 是逆序的，算法照样正确。这一点也说明「排序」不是必要步骤——只有把它升级成多查询版本时才需要。
6. **升级为排序 + 二分**：若同一批学生要回答 $Q$ 次查询，先对 `startTime`、`endTime` 分别排序，答案 $=\text{upper\_bound}(\text{startTime}, q) - \text{lower\_bound}(\text{endTime}, q)$，单次 $O(\log n)$。注意第二个二分是**严格小于**，必须用 `lower_bound`（Python 的 `bisect_left`），写成 `upper_bound` 会把 `endTime[i] == q` 的学生错误地扣掉。
7. **升级为差分前缀和**：建长度 `maxTime + 2` 的差分数组，对每个学生做 `diff[startTime[i]] += 1`、`diff[endTime[i] + 1] -= 1`，做一次前缀和就得到每个时刻的人数，单次查询 $O(1)$。`endTime[i] + 1` 可能等于 1001，数组要开到 1002 才能不越界。

## 5. 正确性证明

**引理 1（做作业时刻即闭区间）**：对任意学生 $i$ 与任意整数时刻 $t$，学生 $i$ 在时刻 $t$ 处于「正在做作业」状态，当且仅当 $\text{startTime}[i] \le t \le \text{endTime}[i]$。

**证明**：题面定义学生 $i$ 于 `startTime[i]` 开始写作业、于 `endTime[i]` 完成作业，期间连续不中断；「开始」与「完成」两个时刻本身都包含在做作业的过程中，故状态区间为闭区间 $[\text{startTime}[i], \text{endTime}[i]]$。∎

**引理 2（计数分解）**：设 $S = \{i : \text{startTime}[i] \le q\}$，$E = \{i : \text{endTime}[i] < q\}$，则

$$E \subseteq S \quad\text{且}\quad \{i : \text{startTime}[i] \le q \le \text{endTime}[i]\} = S \setminus E.$$

**证明**：若 $i \in E$，即 $\text{endTime}[i] < q$；由约束 $\text{startTime}[i] \le \text{endTime}[i]$ 传递得 $\text{startTime}[i] < q$，故 $i \in S$，包含关系成立。

再看右边的集合等式。$i \in S \setminus E$ 意味着 $\text{startTime}[i] \le q$ 且 $\text{endTime}[i] \ge q$（$\text{endTime}[i] < q$ 不成立），这正是闭区间包含条件；反之满足包含条件的 $i$ 显然在 $S$ 中，又因 $\text{endTime}[i] \ge q$ 而不在 $E$ 中。两边互相包含，等式成立。∎

**定理**：§3.3 的算法返回的 `ans` 恰好等于在 `queryTime` 时刻正在做作业的学生人数。

**证明**：算法对每个下标 $i \in [0, n)$ 恰好执行一次判定。若判定为真，说明 $\text{startTime}[i] \le q$ 且 $q \le \text{endTime}[i]$，由引理 1 该学生此刻正在做作业，`ans` 加一；若判定为假，则两个不等式中至少一个不成立，由引理 1 的充要性该学生此刻不在做作业，`ans` 不变。因此循环结束时 `ans` 精确等于「做作业学生数」，无重复计数（每个 $i$ 只访问一次）也无遗漏（所有 $i$ 都访问到）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。循环 $n$ 次，每次至多两次整数比较；短路求值只会让实际比较次数更少。$n \le 100$ 时不到 200 次比较。
- **空间**：$O(1)$ 额外空间，只用了计数器与循环变量 $i$，没有复制数组、没有额外容器。
- **对比**：按时间枚举 / 按学生涂色均为 $O(nT)$（$T \le 1000$），常数与实现复杂度都更高；排序 + 二分为 $O(n\log n + \log n)$；差分前缀和为 $O(n + T)$ 预处理、$O(1)$ 查询，适合 $Q$ 次查询的场景。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int busyStudent(vector<int>& startTime, vector<int>& endTime, int queryTime) {
        int ans = 0;
        for (size_t i = 0; i < startTime.size(); ++i) {
            // 闭区间：q 落在 [startTime[i], endTime[i]] 内才算命中
            if (startTime[i] <= queryTime && queryTime <= endTime[i]) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def busyStudent(self, startTime: List[int], endTime: List[int], queryTime: int) -> int:
        ans = 0
        for s, e in zip(startTime, endTime):   # 两数组等长，同步取两端点
            if s <= queryTime <= e:            # 链式比较 <=> s <= q and q <= e
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **单点区间**：如 `startTime = [4]`、`endTime = [4]`、`q = 4`，区间退化为一个点，此时 $4 \le 4 \le 4$ 成立，必须返回 1 而不是 0。用开区间或严格不等号会把它判错。
2. **查询时刻在所有区间之外**：示例 2 中所有区间最晚在时刻 4 结束，离 7 还差很远，返回 0。这类情况不需要特判，循环自然给出 0；但若先算 `min/max` 做提前返回，务必保证空答案分支也返回 0。
3. **`endTime[i] = q` 仍算命中**：学生在那一刻「完成」，按题面定义仍在做作业。反之 `endTime[i] = q - 1` 就不算了，这正是 §3.2 分解式里用严格小于 $\text{endTime}[i] < q$ 的原因。
4. **数组无序**：示例 3 的 `startTime` 是逆序的，任何「假设递增、遇到大于就 break」的写法都会漏算，题目也没有保证有序。
5. **差分写法的越界**：`endTime[i]` 可以取到 1000，`diff[endTime[i] + 1]` 会访问下标 1001，数组必须开到 `maxTime + 2`；只开 `maxTime + 1` 会在最后一组数据上越界。
6. **二分写法的边界**：`upper_bound(start, q) - lower_bound(end, q)` 中第二个必须是 `lower_bound`（严格小于 $q$ 的个数）。写成 `upper_bound` 会把 `endTime[i] == q` 的学生当成「已经结束」，答案偏小——这与第 3 条是同一个坑的两种表现。
7. **`n = 1`**：循环只走一次，正常返回 0 或 1；不要写「至少两个学生才统计」之类的特判。

**延伸思考**：如果同一批学生要回答 $Q$ 次查询（$n, Q \le 10^5$，时刻范围 $10^9$），怎么做到 $O((n + Q)\log n)$？答案是把 §3.2 的两个端点分开——对 `startTime`、`endTime` 各自排序，单次查询做两次二分即可，不需要差分数组，也不受时刻范围限制。若时刻范围很小（$\le 10^6$）而查询极多，则差分前缀和预处理更划算，单次 $O(1)$。再进一步：把「区间」换成「开区间」时，把 `endTime[i]` 换成 `endTime[i] - 1` 即可回到本题；若要求的是「至少有一半时间在写作业」这类带权版本，端点比较就不够了，得回到扫描线。
