# LeetCode 最大加号标志 题解

## 1. 题目概述

- **标题 / 题号**：最大加号标志（#764，medium）
- **链接**：https://leetcode.cn/problems/largest-plus-sign/
- **来源**：LeetCode 第 67 场周赛 Q3
- **难度**：中等
- **标签**：数组，动态规划

**题意**：给你一个 $n \times n$ 的 0/1 矩阵，其中 `mines` 列出的坐标取 0、其余全为 1。一个 $k$ 阶「轴对齐加号标志」指的是：存在中心格 $(r,c)$，它的上下左右四条臂各向外延伸 $k-1$ 格，且这 $4(k-1)+1$ 个格子**全为 1**（臂之外的格子取值不限）。求最大的 $k$；若一格 1 都没有（连中心都放不下），返回 0。

**约束**：

- $1 \le n \le 500$
- $1 \le \text{mines.length} \le 5000$，且每个坐标对互不相同
- $0 \le x_i, y_i < n$，`mines[i] = [x_i, y_i]` 表示 $grid[x_i][y_i] = 0$

数据规模告诉我们：$n^2 = 2.5\times10^5$，允许 $O(n^2)$ 甚至 $O(n^2 \log n)$，但**不允许** $O(n^3)$。

## 2. 示例

**示例 1**

```text
输入：n = 5, mines = [[4, 2]]
输出：2
解释：唯一的雷在最后一行中间，最大加号是 2 阶；
      想凑 3 阶就必须有一条向下的臂穿过这颗雷，所以到不了 3。
```

**示例 2**

```text
输入：n = 1, mines = [[0, 0]]
输出：0
解释：唯一的格子是雷，没有任何 1，也无处放中心，答案为 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每一格作为中心，再从 $k=1$ 开始不断尝试把四条臂各向外推一格——每推一格要检查 4 个新格子。

最坏情况是**全图无雷**：中心有 $n^2$ 个，每个中心能一路推 $n/2$ 步，每步还要检查 4 个新格子，于是

$$T(n) = O\Bigl(n^2 \cdot \frac{n}{2} \cdot 4\Bigr) = O(n^3)$$

取 $n=500$ 时约 $2.5\times10^8$ 次格点检查，Python 下无论常数怎么优化都扛不住。**瓶颈在于：同一个格子的「向上连续 1 有多长」被反复重算了几十次。**

### 3.2 核心观察：四条臂互相独立，各自是一维 DP

![核心观察：阶数等于四条臂长的最小值](images/wc67_q3_four_direction_dp.svg)

给每个格子记录四个数：

- `up[r][c]`：从 $(r,c)$ 起**向上**连续的 1 的个数（含自身）
- `down[r][c]`、`left[r][c]`、`right[r][c]`：同理

它们各自只依赖**同方向的前一格**，所以都能用一维递推在 $O(1)$ 时间内算出：

$$up[r][c] = \begin{cases} 0, & grid[r][c] = 0 \\ up[r-1][c] + 1, & \text{否则} \end{cases}$$

关键是第二句话：**以 $(r,c)$ 为中心能放下的最大阶数，恰好是这四个数的最小值**。

$$\text{order}(r,c) = \min\bigl(up[r][c],\, down[r][c],\, left[r][c],\, right[r][c]\bigr)$$

直觉上也很自然：加号的四条臂彼此不共享格子、也不互相约束，唯一的限制是「最弱的那条臂能伸多长」——木桶效应。于是整个问题从「枚举中心 + 逐层扩展」变成了「四次线性扫描 + 一次逐格取 min」。

### 3.3 算法流程

![算法流程：两趟扫描加一次合并](images/wc67_q3_algorithm_flow.svg)

1. **建图**：开一个 $n\times n$ 的 0/1 矩阵，初始全 1，把 `mines` 里的坐标置 0。
2. **正序扫描**（$r$ 递增、$c$ 递增）：同时算 `up` 与 `left`。因为 $r-1$ 行、$c-1$ 列在本轮之前已经算完，递推合法。
3. **逆序扫描**（$r$ 递减、$c$ 递减）：同时算 `down` 与 `right`，理由对称。
4. **合并**：遍历所有格子，取四者最小值 $k$，用 $\max$ 更新答案；雷格的四个值都是 0，自然贡献 0。
5. 返回答案。

第 4 步完全可以并进第 3 步——逆序扫描到某格时，`down`、`right` 刚算完，`up`、`left` 在第一趟就有了，可以就地取 min 更新答案。代码里保留三趟是为了可读性，实际上**两趟扫描就能结束**。

### 3.4 示例演算

![示例演算：输入网格与阶数表](images/wc67_q3_walkthrough.svg)

以 $n=5$、`mines = [[4,2]]` 为例。取中心 $(2,2)=1$：

| 方向 | 递推得到的值 | 说明 |
|------|--------------|------|
| `up[2][2]` | 3 | 向上经过 $(1,2),(0,2)$，三格连续为 1 |
| `down[2][2]` | 2 | 向下只有 $(3,2)$，再下一格 $(4,2)$ 是雷，断 |
| `left[2][2]` | 3 | 向左经过 $(2,1),(2,0)$ |
| `right[2][2]` | 3 | 向右经过 $(2,3),(2,4)$ |

$\min(3,2,3,3) = 2$，所以中心 $(2,2)$ 只能放 2 阶——**向下是瓶颈**。逐格取 min 后得到整张阶数表：

| 行 \ 列 | 0 | 1 | 2 | 3 | 4 |
|---------|:-:|:-:|:-:|:-:|:-:|
| 0 | 1 | 1 | 1 | 1 | 1 |
| 1 | 1 | 2 | 2 | 2 | 1 |
| 2 | 1 | 2 | **2** | 2 | 1 |
| 3 | 1 | 2 | 1 | 2 | 1 |
| 4 | 1 | 1 | 0 | 1 | 1 |

表里最大值是 2（共 8 个格子取到），所以答案为 2，与官方输出一致。对比一下：如果 $(4,2)$ 不是雷，`down[2][2]` 会变成 3，四条臂齐平为 3，答案升到 3，恰好等于上界 $\lceil 5/2 \rceil = 3$。

## 4. 算法细节

1. **坐标语义**：`mines[i] = [x, y]` 对应 $grid[x][y]$，即「先行后列」，不要按平面直角坐标（$x$ 向右、$y$ 向上）去理解。留个心眼：方阵上整体转置不动答案，所以写反在本题的用例里是**隐形的**。
2. **两趟扫描的顺序不能反**：正序扫描时 `up` 依赖 $(r-1,c)$、`left` 依赖 $(r,c-1)$，两者都已在更早的迭代中算好；逆序扫描时 `down` 依赖 $(r+1,c)$、`right` 依赖 $(r,c+1)$，同理。若在正序扫描里顺手算 `down`，拿到的是上一轮残留的 0，会得到全错的结果。
3. **边界用「外侧视为 0」统一处理**：把递推式写成 `up[r][c] = (r > 0 ? up[r-1][c] : 0) + 1`，就不必为第 0 行、第 0 列单独写特判。C++ 的 `vector` 初值本就是 0，Python 用一个条件表达式兜底即可。
4. **只对 1 格递推**：遇到雷格四张表都保持 0，后续格子从 0 重新起算——一定要 `continue` 跳过，不能写成 +1 的累加，否则雷会「被穿透」。
5. **剪枝 A**：若 `up[r][c] <= ans`，则 $\min(\cdot)\le up \le ans$，该格不可能刷新答案，可以直接跳过（其余三个值都不用取）；更好的写法是在一次取 min 的链上做短路——算到某步发现当前最小值已 $\le ans$ 就中止。
6. **剪枝 B**：答案有硬上界 $\lceil n/2 \rceil$（$k$ 阶加号要吃掉 $2k-1$ 行与 $2k-1$ 列），`ans` 一旦达到上界立即 `return`，在全 1 的大矩阵上能省掉大半扫描。
7. **空间**：四张 $n\times n$ 的 `int` 表，$n=500$ 时约 $4\times250000\times4\text{B}=4$ MB，可以接受。想省一半就只留 `left`、`up` 两张表：逆序扫描时 `down` 用长度 $n$ 的滚动数组维护（上一行的值），`right` 用行内变量维护（右侧一格的值），空间从 $4n^2$ 降到 $2n^2+O(n)$。
8. **Python 性能**：$n=500$ 时四张表共 $10^6$ 次递推，实测 0.18 s，无需任何优化技巧；但要把 `up`, `down` 等表绑定到局部变量，避免在内层循环里反复做属性查找或 `min()` 嵌套调用。

## 5. 正确性证明

**引理 1（dp 的语义）**：扫描结束后，对任意方向 $d$ 与格子 $(r,c)$，$dp_d[r][c]$ 等于从 $(r,c)$ 沿 $d$ 的反方向连续 1 的个数（含 $(r,c)$ 自身）；若 $grid[r][c]=0$ 则为 0。

**证明**：对 `up` 的行号归纳（其余方向对称）。$r=0$ 时：若 $grid[0][c]=1$，递推给出 $up[0][c]=1$，正是含自身的连续 1 个数；若为 0 则取 0，符合定义。设 $r-1$ 行及以前成立。对 $(r,c)$：若 $grid[r][c]=0$，代码置 0，符合定义；若为 1，则 $up[r][c]=up[r-1][c]+1$，由归纳假设 $up[r-1][c]$ 是从 $(r-1,c)$ 向上的连续 1 个数 $L$，于是从 $(r,c)$ 向上连续 1 的个数正是 $L+1$（$(r,c)$ 自身再加上方那段）。∎

**引理 2（阶数判定）**：以 $(r,c)$ 为中心存在 $k$ 阶加号，当且仅当 $grid[r][c]=1$ 且四个方向的 $dp_d[r][c]\ge k$。

**证明**：
- ($\Rightarrow$) 设存在 $k$ 阶加号，则中心与四条臂上距离 $1,\dots,k-1$ 的格子全为 1，于是沿每个方向连续 1 的个数至少是 $k$（含中心），由引理 1 得 $dp_d[r][c]\ge k$。
- ($\Leftarrow$) 设四表都 $\ge k$，由引理 1 每条臂上距离 $1,\dots,k-1$ 的格子都是 1，连同中心共 $4(k-1)+1$ 格全为 1，构成 $k$ 阶加号。∎

**引理 3（扫描顺序合法）**：正序扫描结束时 `up`、`left` 已与最终值一致；逆序扫描结束时 `down`、`right` 已与最终值一致。

**证明**：`up[r][c]` 只依赖 $(r-1,c)$，`left[r][c]` 只依赖 $(r,c-1)$，两者在行主序下都先于 $(r,c)$ 被处理，且只被赋值一次，因此正序扫描算出的值就是递推式的唯一解；反向同理。∎

**定理**：算法返回的值等于 $grid$ 中最大加号标志的阶数。

**证明**：由引理 1、引理 3，合并阶段读到的四张表都是最终值。对每个 1 格，令 $m(r,c)=\min_d dp_d[r][c]$，由引理 2 可知 $(r,c)$ 能放下的最大阶数正是 $m(r,c)$（能放 $k$ 阶当且仅当 $k\le m$）；对雷格 $m=0$。算法遍历全部格子取最大值，故返回值等于全图最大阶数；全图无 1 时所有 $m=0$，返回 0，与「未找到加号标志返回 0」一致。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。建图 $O(n^2 + |mines|)$；正序、逆序两趟各访问 $n^2$ 格、每格 $O(1)$ 次加法；合并一趟 $O(n^2)$ 次比较。总计不超过 $5n^2$ 次常数运算，$n=500$ 时约 $1.2\times10^6$ 次。
- **空间**：$O(n^2)$。0/1 矩阵 $n^2$ 字节 + 四张 `int` 表 $4n^2$ 个整数，$n=500$ 时约 4 MB；若采用细节 7 的压缩方案，额外空间可降到 $O(n^2)$ 的阶数表 + $O(n)$ 滚动数组。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int orderOfLargestPlusSign(int n, vector<vector<int>>& mines) {
        vector<vector<int>> g(n, vector<int>(n, 1));
        for (auto& m : mines) g[m[0]][m[1]] = 0;   // mines[i] = [行, 列]

        vector<vector<int>> up(n, vector<int>(n, 0)), down(n, vector<int>(n, 0)),
                            le(n, vector<int>(n, 0)), ri(n, vector<int>(n, 0));

        // 正序：up 依赖上一行、left 依赖左侧一格，均已算好
        for (int r = 0; r < n; ++r)
            for (int c = 0; c < n; ++c) {
                if (!g[r][c]) continue;            // 雷格四表恒为 0
                up[r][c] = (r > 0 ? up[r - 1][c] : 0) + 1;
                le[r][c] = (c > 0 ? le[r][c - 1] : 0) + 1;
            }
        // 逆序：down 依赖下一行、right 依赖右侧一格
        for (int r = n - 1; r >= 0; --r)
            for (int c = n - 1; c >= 0; --c) {
                if (!g[r][c]) continue;
                down[r][c] = (r + 1 < n ? down[r + 1][c] : 0) + 1;
                ri[r][c]   = (c + 1 < n ? ri[r][c + 1] : 0) + 1;
            }

        int ans = 0;
        for (int r = 0; r < n; ++r)
            for (int c = 0; c < n; ++c) {
                int k = min(min(up[r][c], down[r][c]), min(le[r][c], ri[r][c]));
                ans = max(ans, k);
            }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def orderOfLargestPlusSign(self, n: int, mines: list[list[int]]) -> int:
        grid = [[1] * n for _ in range(n)]
        for r, c in mines:                     # mines[i] = [行, 列]
            grid[r][c] = 0

        up = [[0] * n for _ in range(n)]
        down = [[0] * n for _ in range(n)]
        left = [[0] * n for _ in range(n)]
        right = [[0] * n for _ in range(n)]

        # 正序扫描：算 up 与 left
        for r in range(n):
            for c in range(n):
                if not grid[r][c]:
                    continue                    # 雷格四张表保持 0
                up[r][c] = (up[r - 1][c] if r > 0 else 0) + 1
                left[r][c] = (left[r][c - 1] if c > 0 else 0) + 1

        # 逆序扫描：算 down 与 right
        for r in range(n - 1, -1, -1):
            for c in range(n - 1, -1, -1):
                if not grid[r][c]:
                    continue
                down[r][c] = (down[r + 1][c] if r + 1 < n else 0) + 1
                right[r][c] = (right[r][c + 1] if c + 1 < n else 0) + 1

        # 合并：四次扫描的结论在同一点取最小
        ans = 0
        for r in range(n):
            for c in range(n):
                k = min(up[r][c], down[r][c], left[r][c], right[r][c])
                if k > ans:
                    ans = k
        return ans
```

## 8. 边界情况与易错点

1. **$n=1$**：`mines = [[0,0]]` 时四表全 0，返回 0；无雷时返回 1。上界 $\lceil n/2\rceil = 1$ 也自洽。
2. **坐标语义是「行、列」**：`mines[i] = [x_i, y_i]` 对应 $grid[x_i][y_i]$。注意本题棋盘是方阵，把两个下标整体写反等价于把棋盘转置，而加号在转置下不变，所以**答案一模一样**——示例 1 也抓不住这个错（实测 `[[4,2]]` 与 `[[2,4]]` 都得 2）。一旦换成矩形棋盘或带权棋盘，这类错误才会爆发。
3. **雷格必须 `continue`**：若漏写，雷格会沿用邻居值继续 +1，把「断点」抹平，答案偏大。这类错误在含雷的用例上才会暴露，而示例 1 恰好能抓住它。
4. **答案为 0 的情形**：全图皆雷（或 $n=1$ 且该格是雷）。此时 `ans` 初值必须为 0，不能用「至少 1 阶」的假设。
5. **全图无雷**：答案不是 $n$ 而是 $\lceil n/2 \rceil$——$k$ 阶加号要占 $2k-1$ 行与 $2k-1$ 列，$n=5$ 时上界只有 3；示例 1 里那颗雷恰好把这个 3 阶上界堵死了。
6. **`mines` 为空数组**：虽然本题约束 $|mines|\ge 1$，但通用写法（循环不假设非空）应当照样成立，别写 `mines[0]` 之类的取值。
7. **扫描顺序弄反**：在正序扫描里同时算 `down`/`right` 会读到未赋值的 0，导致所有向下、向右的值都变成 1（看着「像对的」，实则全错）。
8. **性能陷阱**：不要在合并阶段对每格重新沿四个方向数 1（那是 $O(n^3)$）；四张表的意义就是把这步压成 $O(1)$ 取 min。
