# LeetCode 情侣牵手 题解

## 1. 题目概述

- **标题 / 题号**：情侣牵手（#765，hard）
- **链接**：https://leetcode.cn/problems/couples-holding-hands/
- **来源**：LeetCode 第 67 场周赛 Q4
- **难度**：困难
- **标签**：贪心，深度优先搜索，广度优先搜索，并查集，图

**题意**：$n$ 对情侣坐在连续的 $2n$ 个座位上，情侣按 $(0,1), (2,3), \dots, (2n-2, 2n-1)$ 编号，于是人 $x$ 的伴侣恒为 $x \oplus 1$。座位也天然两两成组：相邻座位 $(2i, 2i+1)$ 构成第 $i$ 个**沙发**。目标是把人重新摆放，使**每个沙发上恰好坐着一对情侣**。一次交换可以**任选两个人**互换座位，求最少交换次数。

**约束**：

- $2n = \lvert \text{row} \rvert$，座位下标 $0 \sim 2n-1$（沙发 $i$ 就是座位 $2i, 2i+1$）
- $2 \le n \le 30$
- $0 \le \text{row}[i] < 2n$，`row` 中元素互不相同（即 `row` 是一个排列）

> ⚠️ 中文站题面在约束里多写了一条「$n$ 是偶数」，但英文原题只要求 $2 \le n \le 30$，且本题算法对任意 $n$ 都成立；下面示例 3 就用 $n = 3$ 演示一个 3-环，不受这条多余限制影响。

## 2. 示例

**示例 1**

```text
输入：row = [0,2,1,3]
输出：1
解释：交换 row[1] = 2 与 row[2] = 1，得到 [0,1,2,3]；
      沙发 0 = (0,1)、沙发 1 = (2,3)，全部配对。
```

**示例 2**

```text
输入：row = [3,2,0,1]
输出：0
解释：沙发 0 = (3,2) 正是情侣 (2,3)，沙发 1 = (0,1) 正是情侣 (0,1)，不必交换。
```

**示例 3（补充，非官方，用来看一个 3-环怎么算）**

```text
输入：row = [0,2,4,1,3,5]
输出：2
解释：交换 row[1] 与 row[3] 修好沙发 0，再交换 row[3] 与 row[5] 修好沙发 1，
      剩下的沙发 2 自动成对。
```

## 3. 解题思路

### 3.1 暴力思路

把人看成排列，以「当前座位安排」为状态，每次任选两人交换，BFS 到第一个「所有沙发都配对」的状态，层数就是答案。状态数高达 $(2n)!$，$n = 30$ 时是 $60!$，毫无希望；即使 $n = 4$（8 个座位）也有 $8! = 40320$ 个状态——这个规模刚好够做**对拍用的小数据暴力**，可以拿来验证正解。

一个自然的改进直觉是：**从左到右逐个沙发修复，修好的沙发不再碰**。问题是：凭什么这样最省？答案藏在图论结构里。

### 3.2 核心观察：沙发图是若干个环

![沙发建模：座位折成点，情侣连成边](images/wc67_q4_couch_graph.svg)

把**沙发**看作顶点，对每对情侣 $(2k, 2k+1)$ 连一条边，连接两人各自所在的沙发，得到一张 $n$ 个顶点的**多重图** $G$（允许自环、平行边）：

- 每个沙发坐 2 个人，每人恰好属于一对情侣、只贡献一条边 ⇒ **每个顶点的度数恰为 2**（若沙发上两人正是情侣，则这条边是自环，自环给该点贡献度数 2）。
- 度数全为 2 的多重图，每个连通分量只能是**一个环**：长度 $k=1$ 是自环（该沙发已经配对），$k=2$ 是两条平行边，$k \ge 3$ 是普通环。
- 于是「全部配对」$\iff$ 图变成 $n$ 个自环。

关键结论：**一个长度为 $k$ 的环，恰好需要 $k-1$ 次交换**，所以

$$\text{答案} = \sum_i (k_i - 1) = n - c,$$

其中 $c$ 是 $G$ 的连通分量（环）个数。直觉是：修好环上的一个沙发，等价于把这个点从环上「剪掉」，环长减 1，代价 1 次交换；环缩到只剩 1 个点时它自然是自环，共花 $k-1$ 次。§5 会把「至少 $k-1$ 次」和「$k-1$ 次够用」两边都证清楚。

> 💡 注意 $c$ 不是「已经配对的沙发数」：两条平行边的 2-环里两个沙发都没配对，但它们只值 $2-1=1$ 次交换。

### 3.3 算法流程：贪心扫一遍 + 位置表

![贪心流程：一次交换只修好一个沙发](images/wc67_q4_greedy_flow.svg)

维护 `pos[人] = 座位`，从左到右扫沙发：

1. 取沙发 $i$ 上的两人 $a = \text{row}[2i]$、$b = \text{row}[2i+1]$；
2. 若 $b = a \oplus 1$，这对已经坐在一起，跳过；
3. 否则 $a$ 的伴侣在 $j = \text{pos}[a \oplus 1]$，交换 `row[2i+1]` 与 `row[j]`，答案加一，并同步更新这两格的位置；
4. 扫完返回答案。

为什么贪心恰好达到 $n-c$：交换后沙发 $i$ 成为自环；若原来 $a$ 的边是 $(i,p)$、$b$ 的边是 $(i,q)$，而 $p$ 的另一条边是 $(p,r)$，则换完后 $p$ 的边变成 $(p,q)$ 与 $(p,r)$——原来的环被「绕过 $i$ 重新接上」，剩下的 $n-1$ 个沙发仍是 2-正则图。也就是说每步恰好剪掉环上一个点，长度 $k$ 的环花 $k-1$ 次。

**并查集版本**（等价写法，不修改 `row`）：对每个人 $x$ 执行 $\text{union}(\text{沙发}(\text{pos}[x]), \text{沙发}(\text{pos}[x \oplus 1]))$，最后返回 $n - \text{连通分量数}$。它直接实现了「数环」这一步。

### 3.4 示例演算

![示例演算：row = [0,2,4,1,3,5]](images/wc67_q4_walkthrough.svg)

对 `row = [0,2,4,1,3,5]`，三个沙发被三对情侣首尾串成三角形（3-环），所以答案 $= 3-1 = 2$。贪心的执行过程是：

| 步 | 沙发 $i$ | $a$ | $b$ | 伴侣 $a \oplus 1$ 在哪 | 动作 | 答案 |
|----|----------|-----|-----|------------------------|------|------|
| 1 | 0 | 0 | 2 | 座位 3（沙发 1） | 交换 `row[1]` 与 `row[3]` | 1 |
| 2 | 1 | 4 | 2 | 座位 5（沙发 2） | 交换 `row[3]` 与 `row[5]` | 2 |
| 3 | 2 | 3 | 2 | 已在右座 | 跳过 | 2 |

## 4. 算法细节

1. **伴侣关系用异或**：$x \oplus 1$ 把 $0 \leftrightarrow 1$、$2 \leftrightarrow 3$ 一一配对，比 `x % 2 == 0 ? x + 1 : x - 1` 更短也更快。**不要**用 $\lvert a-b \rvert = 1$ 判断情侣：$a=1, b=2$ 差 1 却不是一对。
2. **位置表在 `swap` 之后同步更新两格**：交换后 `row[j]` 是原来的 $b$、`row[2i+1]$ 是 $a \oplus 1$，所以要在 `swap` 之后写 `pos[row[j]] = j; pos[row[2i+1]] = 2i+1;`。若在 `swap` 之前更新，两个新位置都会写错，后续每次 `j = pos[a ^ 1]` 都指向废弃座位。
3. **循环只需扫到沙发 $n-1$**：每轮要么跳过（沙发已配对），要么修好沙发 $i$，所以处理完前 $n-1$ 个沙发后只剩两个没配对的人，他们必是情侣，最后一个沙发自动成对。
4. **交换的两个位置一定属于不同沙发**：若 $j$ 与 $2i+1$ 同沙发，则 $b = a \oplus 1$，第 2 步已经 `continue`，因此不会出现「自己和自己交换」。
5. **数据结构选型**：只用长度为 $2n$ 的 `pos` 数组，$n \le 30$ 时规模极小；C++ 用 `std::swap`，Python 用元组赋值一次性交换。
6. **并查集替代方案**：只关心「哪些沙发在同一个环」，不关心交换顺序时，用并查集合并 $\text{pos}[x]/2$ 与 $\text{pos}[x \oplus 1]/2$，再数根即可；与贪心同阶，但不需要改动输入。
7. **返回值的范围**：$0 \le \text{答案} \le n-1$（一个整体环时取到上界），用 `int` 完全够。

## 5. 正确性证明

**引理 1（图的结构）**：对任意座位安排，沙发图 $G$ 的每个连通分量都是一个环（自环或长度 $\ge 2$ 的环）。

**证明**：每个沙发坐 2 人，每人属于唯一一对情侣并贡献一条以其所在沙发为端点的边，故每个顶点的度数恰为 2（自环贡献 2）。有限多重图中所有点度数为 2，则每个连通分量内部每个点度数为 2，从任一点出发沿未走过的边走必然回到已访问点，且每个点只能落在一个闭合回路上，故分量就是一个环。∎

**引理 2（势能单调）**：令 $\Phi = n - c$（$c$ 为当前沙发图的连通分量数）。任取一次交换，交换后 $\Phi' \ge \Phi - 1$；并且 $\Phi = 0$ 当且仅当所有沙发都已配对。

**证明**：设交换的是沙发 $u$ 上的人 $x$ 与沙发 $v$ 上的人 $y$（$u = v$ 时座位安排不变，结论显然）。只有**两条边**会变：$x$ 的情侣边由 $(u, p_x)$ 变成 $(v, p_x)$，$y$ 的情侣边由 $(v, p_y)$ 变成 $(u, p_y)$，其中 $p_x, p_y$ 分别是两人伴侣所在的沙发。记 $C = \text{comp}(u) = \text{comp}(p_x)$，$D = \text{comp}(v) = \text{comp}(p_y)$（有边相连，必同分量），其余分量一条边都没动。

**情形一：$C \ne D$。** 由引理 1，$C$ 是一个环，从环上删去一条边后仍然连通，故删掉 $(u,p_x)$ 后 $C$ 连通、删掉 $(v,p_y)$ 后 $D$ 连通；两条新边把 $C$ 与 $D$ 接到一起，于是 $C \cup D$ 在 $G'$ 中是一个连通块，$c' = c - 1$。

**情形二：$C = D$。** 两条边删自同一个环，环被切成两条链；而新边是把两条链的端点「换位重接」（$u\text{-}p_x,\;v\text{-}p_y$ 重接成 $v\text{-}p_x,\;u\text{-}p_y$）。端点换位后要么两条链各自封成环（$c' = c + 1$），要么接成一个大环（$c' = c$）。

两种情形都满足 $c' \le c + 1$，即

$$c' \le c + 1 \;\Longrightarrow\; \Phi' = n - c' \ge n - c - 1 = \Phi - 1,$$

所以一次交换最多让 $\Phi$ 减少 1。

最后，$\Phi = 0 \iff c = n$：$n$ 个顶点各自成一个分量，当且仅当每个顶点只有自环，而自环正是「该沙发上两人互为伴侣」。∎

**引理 3（贪心一步剪掉环上一个点）**：若沙发 $i$ 未配对，按 §3.3 交换后沙发 $i$ 变成自环，其余沙发的图仍是 2-正则图，且 $c$ 恰好加 1（$\Phi$ 恰好减 1）。

**证明**：设 $a = \text{row}[2i]$、$b = \text{row}[2i+1]$、$b \ne a \oplus 1$；$a \oplus 1$ 在沙发 $p \ne i$，$b$ 的伴侣在沙发 $q$，$p$ 上的另一人是 $d$、其伴侣在沙发 $r$。交换前 $i$ 的边是 $(i,p)$ 与 $(i,q)$，$p$ 的边是 $(p,i)$ 与 $(p,r)$。交换后沙发 $i = (a, a \oplus 1)$ 成为自环；沙发 $p = (b, d)$ 的边变成 $(p,q)$ 与 $(p,r)$。

于是 $i$ 独立成自环分量，而 $p, q, r$ 的度数仍为 2、其余点不受影响，原来的环 $\cdots\text{-}q\text{-}i\text{-}p\text{-}r\text{-}\cdots$ 变成 $\cdots\text{-}q\text{-}p\text{-}r\text{-}\cdots$，仍是 2-正则图，长度由 $k$ 变成 $k-1$（$k = 2$ 的两条平行边情形会退化成 $p$ 也成为自环，同样成立）。分量数由「一个环」变成「自环 $i$ + 一个环」，故 $c' = c + 1$，$\Phi$ 恰好减少 1。∎

**定理**：最少交换次数等于 $n - c_0$（$c_0$ 为初始沙发图的环数），且 §3.3 的贪心恰好用 $n - c_0$ 次交换完成任务。

**证明**：

- **下界**：初始势能为 $\Phi_0 = n - c_0$，全部配对时 $\Phi = 0$；由引理 2，每次交换最多让 $\Phi$ 减少 1，故任何方案都至少需要 $\Phi_0$ 次。
- **上界**：贪心只在「沙发 $i$ 未配对」时交换一次并把它修好，此后不再触碰。由引理 3，每次交换把当前所在环的长度减 1、代价 1；初始长度 $k$ 的环最终缩成 1 个自环，恰花 $k-1$ 次。各分量独立，合计 $\sum_i (k_i - 1) = n - c_0$ 次，此时所有沙发都是自环，任务完成。

上下界相合，故最少交换次数为 $n - c_0$，贪心达到该下界。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建 `pos` 表遍历 $2n$ 个座位；主循环 $n$ 个沙发，每次判断 $O(1)$，交换与两格 `pos` 更新也是 $O(1)$。并查集写法的复杂度为 $O(n \alpha(n))$，$n \le 30$ 时两者没有区别。
- **空间**：$O(n)$。只用一个长度为 $2n$ 的 `pos` 数组；并查集写法额外一个长度为 $n$ 的父指针数组。递归、栈均不需要。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minSwapsCouples(vector<int>& row) {
        int m = (int)row.size();
        vector<int> pos(m);                       // pos[人] = 座位
        for (int i = 0; i < m; i++) pos[row[i]] = i;

        int ans = 0;
        for (int i = 0; i < m; i += 2) {          // 逐个沙发修复
            int a = row[i], b = row[i + 1];
            if (b == (a ^ 1)) continue;           // 这一对已经坐在一起
            int j = pos[a ^ 1];                   // a 的伴侣在座位 j
            swap(row[i + 1], row[j]);
            pos[row[j]] = j;                      // 交换后这两格的人变了，同步更新
            pos[row[i + 1]] = i + 1;
            ans++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minSwapsCouples(self, row: list[int]) -> int:
        m = len(row)
        pos = [0] * m                              # pos[人] = 座位
        for i, x in enumerate(row):
            pos[x] = i

        ans = 0
        for i in range(0, m, 2):                   # 逐个沙发修复
            a, b = row[i], row[i + 1]
            if b == (a ^ 1):                       # 这一对已经坐在一起
                continue
            j = pos[a ^ 1]                         # a 的伴侣在座位 j
            row[i + 1], row[j] = row[j], row[i + 1]
            pos[row[j]] = j                        # 交换后同步两格位置
            pos[row[i + 1]] = i + 1
            ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **最小的 $n = 2$**：四个座位，答案只可能是 0 或 1（如 `[0,2,1,3]` → 1，`[1,0,3,2]` → 0），用这段数据可以先跑通流程。
2. **情侣判断写错**：必须用 `b == (a ^ 1)`；`abs(a - b) == 1` 会把 $(1,2)$、$(3,4)$ 误判成情侣，直接算错答案。
3. **`pos` 只更新一格**：漏掉 `pos[row[j]] = j` 后，被换到沙发 $j$ 的人位置信息过期，后续找伴侣会指向旧座位，把错误的人换进来，答案偏大。
4. **下标与人编号混用**：`row[i]` 是「第 $i$ 个座位上的人」，`pos[x]` 是「人 $x$ 的座位」，沙发 $i$ 对应座位 $2i$ 与 $2i+1$。把 `pos[i]` 当成「沙发 $i$ 的座位」或拿人编号直接除以 2 去找沙发，都会得到错误的边。
5. **答案上界是 $n-1$，不是 $n$**：初始沙发图恰好是一个长度 $n$ 的环时答案才取到上界 $n-1$（$n=30$ 时最多 29 次）；写「至多交换 $n$ 次」之类的上界会把边界多算一次。
6. **输入不可修改的场合**：贪心版会改动 `row`，若在评测环境外需要保留原数组，就先拷贝一份，或改用并查集版直接数环。
7. **已全部配对**：如 `[1,0,3,2]`，每个沙发都是自环，循环全程 `continue`，返回 0——不需要任何特殊判断。
