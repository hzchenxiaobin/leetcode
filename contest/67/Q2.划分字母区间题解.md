# LeetCode 划分字母区间 题解

## 1. 题目概述

- **标题 / 题号**：划分字母区间（#763，medium）
- **链接**：https://leetcode.cn/problems/partition-labels/
- **来源**：LeetCode 第 67 场周赛 Q2
- **难度**：中等
- **标签**：贪心、哈希表、双指针、字符串

**题意**：给定字符串 `s`，把它切成若干**连续**片段（按原顺序拼回去仍是 `s`），要求**同一个字母的所有出现都落在同一个片段内**，求片段数最多的切法，返回各段长度。等价说法：在保证「字母不跨段」的前提下尽量多切。

**约束**：

- $1 \le \lvert s \rvert \le 500$
- `s` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：s = "ababcbacadefegdehijhklij"
输出：[9, 7, 8]
解释：切分为 "ababcbaca"、"defegde"、"hijhklij"。
      每段里的字母都不在别处出现；3 段已是最多的切法。
```

**示例 2**

```text
输入：s = "eccbbbbdec"
输出：[10]
解释：'e' 出现在下标 0 与 9，首尾被同一个字母「锁死」，只能整串成一段。
```

**示例 3**（补充小例）

```text
输入：s = "ababcc"
输出：[4, 2]
解释："abab" 中 a、b 的全部出现都在段内；"cc" 同理。
      若切成 ["aba", "bcc"] 或 ["ab", "ab", "cc"] 均非法（a、b 被拆到两段）。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $2^{n-1}$ 种「切 / 不切」方案，逐个校验：把每段的字母集合取出来，核对每个字母的首次、末次出现是否都落在段内，保留合法方案中段数最多者。单次校验 $O(n)$，总计 $O(2^n \cdot n)$，$n = 500$ 时完全不可行。

另一个不那么暴力的起点：对每个字母构造区间 $[\text{first}[c], \text{last}[c]]$，按左端点排序后做区间合并，合并出的每块就是一个片段。它是对的，但要 $O(n + \sigma \log \sigma)$ 的排序与合并代码。真正值得注意的是：**存在一个一遍扫描就完成的贪心，不需要排序**。

### 3.2 核心观察：片段必须「双向闭合」

![片段必须闭合](images/wc67_q2_closed_interval.svg)

记 $\text{first}[c]$、$\text{last}[c]$ 为字母 $c$ 的首次、末次出现下标。区间 $[l, r]$ 能作为划分中的一段，当且仅当段内出现的每个字母「出不去也进不来」：

$$\forall c \in s[l..r]:\quad \text{first}[c] \ge l \ \wedge\ \text{last}[c] \le r$$

$\text{last}$ 把右端往右推，$\text{first}$ 把左端往左推，片段被这两侧约束夹住。注意**单看一侧是不够的**：`s = "abab"` 中的 $[2,3]$ 满足 $\text{last}$ 侧闭合，但 `a` 还在下标 0 出现，单独成段就非法。

本题的关键 twist 是：**贪心只需要盯右端**。因为扫描到某个 `start` 时，`start` 左边的字母已被之前的切分完整消化，不可能再从左伸进来（引理 2 严格证明）。于是每段的右端取

$$r = \max\{\text{last}[c] : c \in s[l..r]\}$$

的最小不动点，它恰好就是「最早的闭合时刻」。

### 3.3 算法流程

![贪心扫描流程](images/wc67_q2_greedy_flow.svg)

1. 预处理 `last[26]`：完整扫一遍 `s`，记录每个字母最后一次出现的下标。
2. `start = 0`，`end = 0`，`ans = []`。
3. 对 $i = 0, 1, \dots, n-1$ 依次执行：
   - `end = max(end, last[s[i]])`：把右端推到当前片段**必须覆盖**的最远处；
   - 若 `i == end`：片段 $[start, i]$ 已闭合，追加长度 `end - start + 1`，并令 `start = i + 1`。
4. 扫描结束，`ans` 即答案。

不变式：`end` 单调不减，且恒有 `end ≥ i`（因为 `last[s[i]] ≥ i`），所以切点一定会被 `i == end` 命中，不会漏切也不会切早。

### 3.4 示例演算

![示例走查](images/wc67_q2_walkthrough.svg)

`s = "ababcbacadefegdehijhklij"`（$n = 24$），`last` 为 a=8, b=5, c=7, d=14, e=15, f=11, g=13, h=19, i=22, j=23, k=20, l=21：

| 段 | `start` | `end` 的扩张轨迹 | 闭合 `i` | 长度 |
|----|---------|------------------|----------|------|
| 1 | 0 | i=0 `a` → 8；i=4 `c` → max(8,7) 仍 8 | 8 | 9 |
| 2 | 9 | i=9 `d` → 14；i=10 `e` → 15；i=11 `f` → max(15,11) 仍 15 | 15 | 7 |
| 3 | 16 | i=16 `h` → 19；i=17 `i` → 22；i=18 `j` → 23 | 23 | 8 |

得到 `[9, 7, 8]`，$9 + 7 + 8 = 24$，恰好覆盖整串。

特别注意第 3 段：若只看段首 `h` 的 `last = 19` 就切，`i`（22）与 `j`（23）就被漏到段外；右端必须**边走边扩张**。

## 4. 算法细节

1. **必须两遍扫描**：先完整求出 `last`，再扫切点。不要在同一个循环里边写 `last` 边判闭合——那一刻 `last` 还没定型。
2. **`end` 的语义**：它是「当前片段已经确定必须覆盖到的最右下标」，不是「上一段的结尾」。初始化为 0 而不是 -1，因为 `end ≥ i ≥ 0` 恒成立。
3. **切点用 `i == end`**：`end ≥ i` 且 `end` 单调不减、`i` 严格递增，故第一次相等就是最早闭合时刻；写成 `i >= end` 结果一致，但 `==` 更贴合不变式。
4. **长度是 `end - start + 1`**：`end - start` 只是段内「间隔数」；更新 `start = i + 1`（此时 `i == end`，写 `start = end + 1` 等价）。
5. **字符表大小固定**：小写字母只有 26 个，用 `int last[26]` 或长度 26 的列表，额外空间 $O(1)$；字符集不定时换成哈希表，空间变 $O(\sigma)$。
6. **不需要回退**：`start`、`i` 都只增不减，整趟是一次线性滑窗，不需要双指针的回退逻辑。
7. **切片按需**：本题只要长度；若要求输出片段内容，在闭合时切一次 `s[start..end]` 即可，所有切片长度之和为 $n$，总复杂度仍是 $O(n)$。

## 5. 正确性证明

约定：称区间 $[l,r]$ **闭合**，若对每个 $c \in s[l..r]$ 都有 $\text{first}[c] \ge l$ 且 $\text{last}[c] \le r$。

**引理 1（闭合即合法）**：若某划分的每一段都闭合，则该划分合法。

**证明**：设其中一段为 $[l,r]$，段内任一字母 $c$ 满足 $\text{first}[c] \ge l$ 且 $\text{last}[c] \le r$，即 $c$ 的全部出现都落在 $[l,r]$ 内，不会出现在别的段。对该划分所有段、所有字母成立，故「同一字母最多出现在一个片段」；各段依次相接又拼回 `s`，故合法。∎

**引理 2（贪心切出的段闭合）**：贪心每次切出的片段 $[start, i]$ 都是闭合的。

**证明**：分两端成立。

- **右端**：`end` 只由 $s[start..i]$ 中字母的 `last` 累积而来，切分发生时 `i == end`，故段内每个 $c$ 都有 $\text{last}[c] \le \text{end} = i$。
- **左端**：对切分次数归纳。首段 `start = 0`，$\text{first}[c] \ge 0$ 显然成立。设此前已在 $e'$ 处切过一刀，当前 `start = e' + 1`，反设段内某 $c$ 有 $\text{first}[c] \le e'$。扫描到 $p = \text{first}[c]$ 时算法已令 `end ≥ last[c]`；而 $c$ 在 $[start, i]$ 内也出现，故 $\text{last}[c] \ge start > e'$。由于 `end` 单调不减，扫描到 $i = e'$ 时仍有 `end > e'`，切分条件 `i == end` 不成立，与「$e'$ 处切过一刀」矛盾。∎

**引理 3（切点最早）**：设贪心当前片段的起点为 $l$（$l = 0$ 或前一切点加一），切点为 $e_0$。则任何把 $s[l..n-1]$ 单独划分的合法方案，其第一段右端 $e$ 都满足 $e \ge e_0$。

**证明**：设该方案第一段为 $[l, e]$，它闭合，故段内每个 $c$ 都有 $\text{last}[c] \le e$。贪心扫描到 $i = e$ 时

$$\text{end} = \max\{\text{last}[c] : c \in s[l..e]\} \le e,$$

又因 $\text{last}[s[e]] \ge e$ 有 $\text{end} \ge e$，故 `end == e`，切分条件在 $i = e$ 处成立。由 `end` 单调不减、`i` 严格递增，第一次满足 `i == end` 的位置不可能晚于 $e$，即 $e_0 \le e$。∎

**定理（最优且唯一）**：贪心输出的划分段数最多，且取到最大段数的划分唯一。

**证明**：对后缀长度归纳（后缀为空或单字符时结论显然）。设贪心在 $s[l..n-1]$ 上的首段为 $[l, e_0]$，其后递归求解后缀 $s[e_0+1..n-1]$；由引理 2，$[l, e_0]$ 闭合，故后缀中出现的字母都不出现在 $[l, e_0]$ 里，子问题独立，记贪心在该后缀上的段数为 $f(e_0+1)$。

任取该后缀的合法划分 $P$，其首段为 $[l, e]$。由引理 3 有 $e \ge e_0$，分两种情形。

- $e = e_0$：$P$ 的其余段把 $s[e_0+1..]$ 合法划分，由归纳假设其段数 $\le f(e_0+1)$，故 $P$ 段数 $\le 1 + f(e_0+1) =$ 贪心段数。
- $e > e_0$：$[l, e_0]$ 闭合，且 $s[e_0+1..e]$ 也闭合——若某字母 $c$ 同时出现在这两段，则由 $[l, e_0]$ 闭合得 $\text{last}[c] \le e_0$，与 $c$ 出现在 $e_0+1$ 之后矛盾。于是把 $P$ 的首段劈成 $[l, e_0]$ 与 $[e_0+1, e]$，由引理 1 仍是合法划分且段数加一；再由归纳假设，劈开后段数 $= P$ 段数 $+ 1 \le 1 + f(e_0+1)$，即 $P$ 的段数严格小于贪心段数。

两种情形都说明贪心段数不少于任何合法划分，即贪心最优。唯一性：若某最优划分的首段满足 $e > e_0$，第二种情形的劈开论证会造出段数更多的合法划分，矛盾；故最优划分首段必为 $[l, e_0]$，对其余部分递归归纳即得最优划分唯一。∎

## 6. 复杂度分析

- **时间**：$O(n)$。求 `last` 一遍 $O(n)$；贪心扫描一遍 $O(n)$，每个下标只做一次 `max` 与一次比较，无嵌套循环。$n \le 500$，实际是常数级开销。
- **空间**：$O(1)$ 额外空间。`last` 大小固定为字母表大小 $\lvert \Sigma \rvert = 26$，与 $n$ 无关；输出数组 $O(k) \le O(n)$ 属于答案本身。若字符集不定，则额外空间为 $O(\lvert \Sigma \rvert)$。
- **下界直觉**：必须至少两遍扫描（先知道全局最右位置，才敢切第一刀），因此 $O(n)$ 时间已是常数级最优。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> partitionLabels(string s) {
        int last[26];
        fill(last, last + 26, -1);
        for (int i = 0; i < (int)s.size(); ++i) {
            last[s[i] - 'a'] = i;               // 每个字母最后一次出现的下标
        }

        vector<int> ans;
        int start = 0, end = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            end = max(end, last[s[i] - 'a']);   // 右端推到必须覆盖的最远处
            if (i == end) {                     // 片段闭合，可以切
                ans.push_back(end - start + 1);
                start = i + 1;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def partitionLabels(self, s: str) -> list[int]:
        last = {}
        for i, ch in enumerate(s):
            last[ch] = i            # 每个字母最后一次出现的下标

        ans = []
        start = end = 0
        for i, ch in enumerate(s):
            end = max(end, last[ch])   # 右端推到必须覆盖的最远处
            if i == end:               # 片段闭合，可以切
                ans.append(end - start + 1)
                start = i + 1
        return ans
```

## 8. 边界情况与易错点

1. **单字符 / 全同字符**：`"a"` → `[1]`；`"aaaa"` → `[4]`。`end` 一次被推到末尾，只切一刀。
2. **每个字母只出现一次**：`"abcde"` → `[1,1,1,1,1]`，每个位置都立即闭合。
3. **首尾同名把整串锁死**：`"eccbbbbdec"` 中 `'e'` 的 `last = 9`，`i = 0` 时 `end` 即为 9，答案 `[10]`。
4. **只看段首字母的 `last` 会切早**：`"hijhklij"` 段首 `h` 的 `last = 19`，而 `i`(22)、`j`(23) 会继续把 `end` 推远——必须边走边取 `max`。
5. **`last` 未定型就判切点**：把「求 `last`」与「扫切点」塞进同一个循环，会在 `last` 还没写全时误闭合。
6. **长度少算 1**：`end - start` 是间隔数，长度必须是 `end - start + 1`；`"a"` 上若漏加一会得到 `[0]` 这种明显错误。
7. **字符集假设**：代码用 `s[i] - 'a'` 索引长度 26 的数组，输入含大写或其他字符时就需换哈希表，否则越界。
8. **误用「字母区间合并」却漏掉间接依赖**：按 `[first, last]` 排序合并时要**迭代**合并（合并后右端可能继续变远），一次遍历不检查新右端会少合并。

**延伸思考**：

1. **恰好 $k$ 段**（$1 \le k \le m$，$m$ 为贪心段数）：相邻两个闭合段的并仍然闭合，所以把贪心结果的相邻段任意合并，就能得到任意 $k \le m$ 段的合法划分；段数最多时划分唯一，合并方式却不唯一。
2. **输出片段内容而非长度**：闭合时切一次 `s[start:end+1]` 即可，代价仍是 $O(n)$。
3. **若允许重排字符**：最大段数等于不同字母的个数——把每个字母的出现聚成连续一段即可，且不可能超过「每段至少含一个新字母」的上界，贪心思路随之失效。
4. **流式输入**：`last` 依赖全局信息，单遍流式处理做不出最优解；至少要让同一字母的两次出现都可见，这解释了为什么 $O(n)$ 里必须有两遍扫描。
