# LeetCode 最大或值 题解

## 1. 题目概述

- **标题 / 题号**：最大或值（#2680，medium）
- **链接**：https://leetcode.cn/problems/maximum-or/
- **来源**：LeetCode 第 104 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、位运算、数组、前缀和

**题意**：给定数组 `nums` 与整数 $k$。每次操作可任选一个数乘 $2$（即二进制左移一位），**至多**执行 $k$ 次。最大化 $\;nums[0] \,|\, nums[1] \,|\, \cdots \,|\, nums[n-1]$ 的值。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$
- $1 \le k \le 15$

## 2. 示例

**示例 1**

```text
输入：nums = [12,9], k = 1
输出：30
解释：对 9 操作：新数组 [12,18]，12 | 18 = 30。
      对照：不操作得 12 | 9 = 13；对 12 操作得 24 | 9 = 25。
```

**示例 2**

```text
输入：nums = [8,1,2], k = 2
输出：35
解释：两次操作都给 8：[32,1,2]，32 | 1 | 2 = 35。
```

**示例 3（边界补充）**

```text
输入：nums = [1,2], k = 1
输出：5
解释：对 2 操作：1 | 4 = 5；对 1 操作：2 | 2 = 2，反而更小——
      说明“次数可少用”的语义真实存在，但最优解仍是把全部次数投给一个元素。
```

## 3. 解题思路

### 3.1 暴力思路

把 $k$ 次左移分配给各元素，即求非负向量 $(a_1, \dots, a_n)$、$\sum a_i \le k$，使 $\big|$ 按位或 $\big|$ 最大。枚举所有分配是 $\binom{n+k}{k}$ 量级（$n = 10^5$ 时天文数字）；DP 也难做——OR 不是可分解的收益函数，"给元素 $i$ 分 $j$ 次"的边际收益依赖其他元素的位覆盖情况。突破口必须来自 OR 的**位结构**：左移 $k$ 位等于把一个元素的整个位段整体抬高 $k$ 格，而 OR 的数值大小由**最高覆盖位**主导。

### 3.2 核心观察：$k$ 次操作应全部集中给同一个元素

![核心观察：左移把位段整体抬高；集中抬高一个元素能产生全场最高的位，分散则最高位不变或更低](images/bw104_q3_consolidate.svg)

记 $\text{top}(x)$ 为 $x$ 的最高位位置。直觉：$\text{top}(x \ll a) = \text{top}(x) + a$，把 $k$ 次全给一个元素，它能贡献出全场唯一的"超级高位" $\text{top}(x) + k$；分散给多个元素，每个的最高位都抬不满 $k$，结果被最高覆盖位压死。

严格论证分两步（完整证明见 §5，此处给骨架）：**其一**，若某方案让至少两个元素被移位，设结果 $T$ 的最高位来自移位元素 $z$；把**全部**移位次数集中给 $z$、其余元素还原，新结果的最高位变成 $\text{top}(z) + K$（$K$ 为总次数）严格高于原最高位——数值必然更大。故存在最优方案只移位一个元素。**其二**，设最优只把 $m < k$ 次给了 $z$：要么全场最大 $\text{top}$ 的元素另投满 $k$ 次能产生更高的位，要么给 $z$ 补满 $k$ 次本身就抬高其最高位——两种情形都能严格改进，矛盾。故**最优方案必是"某个元素恰好吃满 $k$ 次左移"**。

于是答案在 $n$ 个候选里取最大：

$$\text{ans} = \max_{i}\; \big(\text{pre}[i] \;\big|\; (nums[i] \ll k) \;\big|\; \text{suf}[i+1]\big)$$

其中 $\text{pre}[i]$ 是前缀 OR（$nums[0..i-1]$），$\text{suf}[i+1]$ 是后缀 OR（$nums[i+1..n-1]$）——把候选元素从 OR 中"摘出来"再左移 $k$ 位拼回。

### 3.3 算法流程：一遍后缀 OR + 一遍前缀 OR

![算法流程：先从右往左求后缀 OR，再从左往右滚动前缀 OR 并枚举候选取最大](images/bw104_q3_prefix_suffix.svg)

```text
1. suf[n] = 0；从右往左：suf[i] = suf[i+1] | nums[i]
2. pre = 0，ans = 0
3. for i = 0 .. n-1:
4.     cur = pre | (nums[i] << k) | suf[i+1]
5.     ans = max(ans, cur)
6.     pre |= nums[i]
7. 返回 ans
```

### 3.4 示例演算

![示例演算：数组 12,9 在 k=1 下的两个候选 25 与 30；数组 8,1,2 在 k=2 下的三个候选 35、14、9](images/bw104_q3_example_walkthrough.svg)

**示例 1**（$k=1$，二进制直观对照）：

| 候选 $i$ | 表达式 | 二进制 | 值 |
|----------|--------|--------|-----|
| 0（给 12） | $24 \| 9$ | $11000 \| 01001 = 11001$ | 25 |
| 1（给 9） | $12 \| 18$ | $01100 \| 10010 = 11110$ | **30** |

**示例 2**（$k=2$）：给 8 得 $32\|1\|2 = 100011 = 35$；给 1 得 $8\|4\|2 = 1110 = 14$；给 2 得 $8\|1\|8 = 1001 = 9$。答案 $35$。

注意示例 3 的警示：给 1 操作时 $2 \| 2 = 2$ **小于**不动手的 $1\|2 = 3$——"多用操作"可能变亏，这正是题面写"至多 $k$ 次"的原因；但定理保证**最优值仍由"单元素吃满 $k$ 次"的候选达成**。

## 4. 算法细节

1. **候选元素"摘出再拼回"**：OR 对每个位独立，把 $nums[i]$ 的贡献从前缀/后缀中排除后左移 $k$ 位再 OR 回来，等价于"其他元素不动、$nums[i]$ 乘 $2^k$"的最终 OR。
2. **溢出防护（C++ 重点）**：$nums[i] \le 10^9 < 2^{30}$，左移 $k \le 15$ 位可达 $2^{45}$ 量级，**必须先转 `long long` 再移位**：`(long long)nums[i] << k`。写成 `nums[i] << k` 是 `int` 移位，直接越界 UB。接口返回 `long long` 正为此设计。
3. **后缀数组开 $n+1$**：`suf[n] = 0` 作哨兵，省去 $i = n-1$ 的特判。
4. **两遍扫描的次序**：先算后缀（从右往左），再从左往右滚动前缀并同时产出答案——前缀只需一个滚动变量，不必开数组。
5. **"$\ll$"与"$|$"的优先级**：C++ 中 `<<` 高于 `|`，`pre | nums[i] << k | suf` 语义正确，但显式加括号是廉价的保险。
6. **复杂度**：$O(n)$ 时间、$O(n)$ 空间（后缀数组）；值域上限 $2^{45}$ 在 `long long` 内安全。

## 5. 正确性证明

记 $\text{top}(x)$ 为 $x$ 的最高置位（$x \ge 1$ 时良定义）。一个"方案"是各元素的非负移位数 $(s_1, \dots, s_n)$，$\sum s_i \le k$，其值为 $T = \big|\!_i\, (a_i \ll s_i)$（$a_i = nums[i]$）；合法方案集合有限。

**引理 1（集中移位严格改进）**：设某方案的结果 $T$ 最高位为 $p$，且**至少两个**元素的移位数为正。取任一"移位后最高位等于 $p$"的元素 $z$（即 $\text{top}(z) + s_z = p$），令 $K = \sum_i s_i$，把全部 $K$ 次移位集中给 $z$、其余元素还原为不移位，得 $T' = (z \ll K) \,\big|\, \big|\!\big|_{i \ne z} a_i$，则 $T' > T$。

**证明**：$z \ll K$ 拥有位 $\text{top}(z)+K$ 显然。其余元素还原后各自贡献 $\text{top}(a_i) \le \text{top}(a_i \ll s_i) \le p$（左移只抬高位），故 $T'$ 中除 $z$ 外的部分最高位 $\le p$，而 $z \ll K$ 提供位 $\text{top}(z) + K$。若 $K \ge s_z + 1$，则 $\text{top}(z)+K \ge p+1 > p$，即 $T'$ 有高于 $p$ 的位、$T$ 没有，故 $T' > T$。而当至少两个元素移位数为正时，无论 $s_z$ 为正（另一正移位元素使 $K \ge s_z + 1$）还是 $s_z = 0$（两个正移位使 $K \ge 2 \ge 1$），都有 $K \ge s_z + 1$，结论成立 ∎

**引理 2（存在单元素最优方案）**：存在一个最优方案，至多只有一个元素的移位数为正。

**证明**：反证：设所有最优方案都有至少两个正移位元素。任取一个最优方案，由引理 1 构造的 $T'$ 严格大于 $T$，且 $T'$ 仍合法（总次数 $K \le k$ 不变）——与 $T$ 最优矛盾 ∎

**引理 3（最优方案用满 $k$ 次）**：存在最优方案恰好把 $k$ 次全部分配给单一元素。

**证明**：由引理 2 设最优方案为：$z$ 移 $m \le k$ 次、其余不动，值 $T = (z \ll m) \,\big|\, R$，其中 $R = \big|\!\big|_{i \ne z} a_i$。令 $P = \max_i \text{top}(a_i)$。假设 $m < k$：

- 若 $\text{top}(z) + m \le P$：取 $\text{top}(w) = P$ 的元素 $w$，考察候选 $T_w = (w \ll k) \,\big|\, R_w$（$R_w$ 为其余元素原值之 OR）。$T_w$ 拥有位 $P + k > P \ge \max(\text{top}(z)+m,\ \text{top}(R)) = \text{top}(T)$，故 $T_w > T$，与最优矛盾。
- 若 $\text{top}(z) + m > P$：考察候选 $T_z = (z \ll k) \,\big|\, R$，其最高位 $\text{top}(z) + k > \text{top}(z) + m = \text{top}(T)$（此情形 $T$ 的最高位恰由 $z \ll m$ 决定），故 $T_z > T$，与最优矛盾。

两种情形矛盾，故 $m = k$，即最优方案恰把 $k$ 次全给一个元素 ∎

**定理**：$\text{ans} = \max_i \big(\text{pre}[i] \,|\, (a_i \ll k) \,|\, \text{suf}[i+1]\big)$ 是最优值。

**证明**：每个候选都是合法方案（恰把 $k$ 次给元素 $i$），故 ans $\le$ 真最优；由引理 3，真最优由某个"单元素吃满 $k$ 次"方案达成，而该方案的值恰为下标 $i$ 处的候选——前缀 OR 拼上其余元素的原值、$a_i$ 左移 $k$ 位后 OR 回，逐位等价——故 ans $\ge$ 真最优。两侧夹逼即得 ∎

## 6. 复杂度分析

- **时间**：$O(n)$。后缀 OR 一遍、前缀滚动一遍，每个元素常数次 OR 与移位。
- **空间**：$O(n)$。后缀 OR 数组；前缀用滚动变量。可再压到 $O(1)$：先求全体 OR 与"各位置 1 的计数"撤销法，但会显著复杂化，不值。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maximumOr(vector<int>& nums, int k) {
        int n = nums.size();
        vector<long long> suf(n + 1, 0);          // suf[i] = nums[i..n-1] 的 OR
        for (int i = n - 1; i >= 0; --i) suf[i] = suf[i + 1] | (long long)nums[i];
        long long pre = 0, ans = 0;               // pre = nums[0..i-1] 的 OR
        for (int i = 0; i < n; ++i) {
            long long cur = pre | ((long long)nums[i] << k) | suf[i + 1];
            ans = max(ans, cur);
            pre |= (long long)nums[i];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumOr(self, nums: List[int], k: int) -> int:
        n = len(nums)
        suf = [0] * (n + 1)                      # suf[i] = nums[i..n-1] 的 OR
        for i in range(n - 1, -1, -1):
            suf[i] = suf[i + 1] | nums[i]
        pre = 0
        ans = 0
        for i in range(n):
            ans = max(ans, pre | (nums[i] << k) | suf[i + 1])
            pre |= nums[i]
        return ans
```

> 💡 两份代码均通过官方示例（`30`、`35`）与"多用操作反而变小"的构造样例，并与"穷举一切 $\sum a_i \le k$ 分配"的暴力对拍 1512 组随机小数据（$n \le 4$、$k \le 5$，含单元素、低位覆盖等构造），另有 $n = 10^5, k = 15$ 满规模 C++/Python 一致性冒烟，`mismatch = 0`。

## 8. 边界情况与易错点

1. **C++ 溢出是头号杀手**：`nums[i] << k` 在 `int` 上可达 $2^{45}$，必须 `(long long)nums[i] << k`；漏转是隐蔽数据点错误（不是 RE，是 WA）。
2. **"至多 $k$ 次"的语义**：示例 3 表明多做可能变亏，**不能**先算"不动"的 OR 再无脑叠加；但定理保证最优值必在"单元素满 $k$"候选中，直接枚举即可。
3. **$n = 1$**：答案就是 $nums[0] \ll k$（前缀、后缀全 0）。
4. **$k$ 次不必拆开想**：一次性左移 $k$ 位等价于连续乘 $2$ 共 $k$ 次，无需循环。
5. **别用"每次挑收益最大元素"的增量贪心**：OR 收益不具子结构（第二步的最优依赖第一步的选择），增量贪心没有正确性依据，对拍会翻车。
6. **后缀哨兵**：`suf[n] = 0` 让 $i = n-1$ 的候选自然成立，省特判。
