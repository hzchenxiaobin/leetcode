# LeetCode 查找和替换模式 题解

## 1. 题目概述

- **标题 / 题号**：查找和替换模式（#890，medium）
- **链接**：https://leetcode.cn/problems/find-and-replace-pattern/
- **来源**：LeetCode 第 98 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串

**题意**：给定单词列表 `words` 和模式串 `pattern`，返回 `words` 中**与模式匹配**的所有单词。匹配的定义是：存在一个**字母间的双射（置换）** $p$，把 `pattern` 中每个字母 $x$ 替换成 $p(x)$ 后恰好得到该单词。

注意 $p$ 是**双射**：不同字母必须映射到不同字母，不能有两个字母映射到同一个字母。

**约束**：

- $1 \le \text{pattern.length} \le 20$
- $1 \le |\text{words}| \le 50$
- $\text{words}[i].length = \text{pattern.length}$
- 只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：words = ["abc","deq","mee","aqq","dkd","ccc"], pattern = "abb"
输出：["mee","aqq"]
解释：abc → 三字母互不相同，与 a、b、b 的「1 个重复」形状不同；
     mee、aqq 的形状都是 xyy，与 abb 同构；
     dkd → 形状 xyx，不匹配；ccc → 形状 xxx，也不匹配（a、b 会映射到同一个 c）。
```

**示例 2**

```text
输入：words = ["a","b","c"], pattern = "a"
输出：["a","b","c"]
解释：长度 1 时任何字母都能通过置换互相转换（a→a、a→b、a→c），三个都匹配。
```

**示例 3（自造，说明双向性）**

```text
输入：words = ["aa","ab"], pattern = "ab"
输出：["ab"]
解释：aa 的形状是 xx，pattern 的形状是 xy；若只要求 pattern→word 方向，
     a→a、b→a 也「能对上」，但那不是双射，所以 aa 必须被排除。
```

## 3. 解题思路

### 3.1 暴力思路

按定义逐词判定：枚举 `pattern` 中出现的字母到小写字母的所有**单射**，检查替换后是否等于该单词。字母表 26 个、模式长度最多 20，单射数量可达 $26^{20}$ 级别，完全不可行。

稍微聪明一点的暴力是**回溯 + 剪枝**：逐位尝试映射并检查一致性。但它本质上就是在做「双向映射检查」，剪枝后的复杂度与线性做法相同，却多了一层递归开销。真正的暴力思路在这里价值不大——它只是帮我们确认：**判定必须逐位进行、且要同时维护两个方向的映射**。

### 3.2 核心观察：把字符串压成「首次出现编号」

![把字符串压成首次出现编号签名](images/wc98_q2_signature.svg)

两个字符串匹配，本质上是在问「它们是否**同构**」：相同位置的字符重复模式完全一致。

对于长度为 $L$ 的串 $s$，定义它的**签名** $\sigma(s) \in \{0,1,\dots\}^{L}$：从左到右扫描，遇到一个**没见过的字符**就给它分配下一个编号（从 0 开始），$\sigma(s)[i]$ 就是 $s[i]$ 的编号。

例如：

- `"abb"`：`a` 分配 0，`b` 分配 1，第三个字符还是 `b` → $\sigma = [0,1,1]$；
- `"mee"` → `[0,1,1]`；`"aqq"` → `[0,1,1]`；`"abc"` → `[0,1,2]`；`"dkd"` → `[0,1,0]`；`"ccc"` → `[0,0,0]`。

**结论**：$w$ 与 `pattern` 匹配 $\iff \sigma(w) = \sigma(\text{pattern})$。

直观理由：签名完全刻画了「哪些位置字符相同、哪些不同」这张等价关系表。只要两张表一致，就能在字符之间建立双射：把 `pattern` 里编号为 $k$ 的字符映射到 $w$ 里编号为 $k$ 的字符。因为编号是按首次出现顺序分配的，两个串中编号为 $k$ 的字符都恰好只有一个（每个编号对应一个不同的字符），所以这个对应天然是**双射**。

![签名同时保证了两个方向的单射](images/wc98_q2_bijection.svg)

上图说明了为什么必须**双向**：只要求 `pattern → word` 方向时，`"aa"` 也能通过 $a \mapsto a$、$b \mapsto a$ 得到（不单射）；而签名的第 2 位会把这种「两个不同字母压成同一个」的情况暴露出来（`[0,0] ≠ [0,1]`）。

### 3.3 算法流程

![算法流程：对每个单词做线性归一化](images/wc98_q2_flow.svg)

```text
1. target = norm(pattern)                 # norm 计算首次出现编号序列
2. ans = []
3. for w in words:
4.     若 norm(w) == target:  ans.append(w)
5. 返回 ans

norm(s):
    1. idx = 空哈希表，res = []
    2. for ch in s:
    3.     若 ch 不在 idx 中: idx[ch] = len(idx)
    4.     res.append(idx[ch])
    5. 返回 res
```

### 3.4 示例演算

`pattern = "abb"`，签名 `[0,1,1]`：

| 单词 | 签名 | 是否匹配 |
|------|------|----------|
| `abc` | `[0,1,2]` | 否（三字母都不同） |
| `mee` | `[0,1,1]` | **是** |
| `aqq` | `[0,1,1]` | **是** |
| `dkd` | `[0,1,0]` | 否（形状 xyx） |
| `ccc` | `[0,0,0]` | 否（形状 xxx） |

答案为 `["mee","aqq"]`，与题面一致。

## 4. 算法细节

1. **签名的实现**：用 `unordered_map<char,int>`（C++）/ `dict`（Python）记录「字符 → 编号」，编号取 `len(map)`，从 0 递增。
2. **签名的比较**：直接比较两个 `vector<int>` / `list` 即可；也可以把签名拼成字符串（把编号当字符）当哈希键用，适合「统计有多少种不同形状」的变体。
3. **只与 pattern 比较一次**：`target` 在循环外算好，每个单词只算一次签名，避免重复归一化 pattern。
4. **字母表只有 26 个**：也可以用长度 26 的数组代替哈希表，常数更小；但用 `len(map)` 取编号更通用（换成任意字符集都不改代码）。
5. **长度天然一致**：题面保证 `words[i].length == pattern.length`，所以不需要额外判长；若迁移到不保证的输入，应先比较长度。
6. **结果顺序**：按 `words` 的原始顺序输出即可，题目说「任意顺序」。

## 5. 正确性证明

**引理 1（签名相同的必要性）**：若存在双射 $p$ 使 $p(\text{pattern}) = w$，则 $\sigma(w) = \sigma(\text{pattern})$。

**证明**：对 `pattern` 归纳扫描位置。设 $i < j$，我们要证明「`pattern[i] == pattern[j]` ⇔ `w[i] == w[j]`」。

- 若 `pattern[i] == pattern[j]`，则 $w[i] = p(\text{pattern}[i]) = p(\text{pattern}[j]) = w[j]$；
- 反之若 `pattern[i] ≠ pattern[j]`，由 $p$ 是单射得 $p(\text{pattern}[i]) \ne p(\text{pattern}[j])$，即 $w[i] \ne w[j]$。

因此两个串的「相等关系表」完全一致。而签名的定义只依赖这张表：两个字符签名相同当且仅当它们在原串中相等，编号的分配顺序也由首次出现位置决定。关系表相同 ⇒ 每个位置上的编号相同 ⇒ 两个签名逐位相等。∎

**引理 2（签名相同的充分性）**：若 $\sigma(w) = \sigma(\text{pattern}) = c$，则存在双射 $p$ 使 $p(\text{pattern}) = w$。

**证明**：构造 $p$：对 `pattern` 中出现的每个字符 $x$，取其任意一次出现的下标 $i$（`pattern[i] = x`），令 $p(x) = w[i]$。

- **良定义**：若 $x$ 出现在多个位置 $i, j$，则 $c[i] = c[j]$（因为 $\sigma(\text{pattern})$ 在两个位置都给 $x$ 分配同一编号），由 $\sigma(w) = c$ 得 $w[i] = w[j]$，故 $p(x)$ 不依赖下标选择。
- **单射**：若 $x \ne y$ 但 $p(x) = p(y) = z$，取 $x$、$y$ 的出现位置 $i, j$。由 $w[i] = w[j] = z$ 得 $c[i] = c[j]$，再由 $c = \sigma(\text{pattern})$ 得 $\text{pattern}[i] = \text{pattern}[j]$，即 $x = y$，矛盾。
- **满射**：$w$ 中每个出现的字符 $z$ 都来自某个位置 $i$，而 $z = w[i] = p(\text{pattern}[i])$，故 $z$ 在 $p$ 的值域中。

于是 $p$ 是双射，且按定义 $p(\text{pattern}[i]) = w[i]$ 对每个 $i$ 成立，即 $p(\text{pattern}) = w$。∎

**定理**：算法返回的列表恰为 `words` 中与 `pattern` 匹配的全部单词。

**证明**：由引理 1、2，匹配 $\iff$ 签名相同。算法对每个单词计算签名并与 `target` 比较，只在相等时收入答案，故收进来的都匹配（引理 1）、匹配的都不会被漏掉（引理 2 的逆向），且每个单词只处理一次，不重不漏。∎

## 6. 复杂度分析

- **时间**：$O\big(|\text{words}| \cdot L\big)$，$L = \text{pattern.length} \le 20$。计算 pattern 签名 $O(L)$；每个单词计算签名 $O(L)$ 并做一次 $O(L)$ 的比较，共 $|\text{words}| \cdot O(L)$。最坏 $50 \times 20$ 次操作。
- **空间**：$O(L)$。每次归一化只需要一个规模不超过 $\min(L, 26)$ 的映射表和一个长度 $L$ 的签名序列；输出的空间为 $O(|\text{words}| \cdot L)$（答案本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> findAndReplacePattern(vector<string>& words, string pattern) {
        auto norm = [](const string& s) {
            unordered_map<char, int> idx;
            vector<int> res;
            for (char ch : s) {
                auto it = idx.find(ch);
                if (it == idx.end()) {
                    idx[ch] = (int)idx.size();
                }
                res.push_back(idx[ch]);
            }
            return res;
        };
        vector<int> target = norm(pattern);
        vector<string> ans;
        for (auto& w : words) {
            if (norm(w) == target) ans.push_back(w);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findAndReplacePattern(self, words: list[str], pattern: str) -> list[str]:
        def norm(s: str) -> list[int]:
            idx, res = {}, []
            for ch in s:
                if ch not in idx:
                    idx[ch] = len(idx)      # 首次出现的顺序编号
                res.append(idx[ch])
            return res

        target = norm(pattern)
        return [w for w in words if norm(w) == target]
```

## 8. 边界情况与易错点

1. **必须双向**：只维护 `pattern → word` 的映射会漏掉 `"aa"` 对 `"ab"` 这种「多对一」的情况。签名法天然双向，但若改写成「逐位建 map」，务必同时检查 $w[i] \to \text{pattern}[i]$ 方向。
2. **长度必须一致**：题面保证 `words[i].length == pattern.length`，所以可省略长度判断；迁移到其他题目时要先比长度。
3. **单字符模式**：任何长度 1 的单词都匹配（示例 2），因为总有双射把唯一字母映过去。不要因为「字母不同」就排除。
4. **全同字母单词**：`"ccc"` 对应签名 `[0,0,0]`，只有全同字母的模式（如 `"aaa"`）才能匹配它。
5. **编号从 0 开始还是 1 开始无所谓**，只要两个串用同一规则；但不要一个用 0 起、另一个用 1 起。
6. **`unordered_map::size()` 的类型**：`idx.size()` 是 `size_t`，赋给 `int` 编号时要显式转换（编译器可能告警），用 `(int)idx.size()` 更干净。
7. **不要用字符集合比较**：`set(word) == set(pattern)` 完全不够——`"abc"` 与 `"cba"` 字符集合相同但形状不同（前者 `[0,1,2]`、后者 `[2,1,0]`）。
