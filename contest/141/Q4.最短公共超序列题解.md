# LeetCode 最短公共超序列 题解

## 1. 题目概述

- **标题 / 题号**：最短公共超序列（#1092，hard）
- **链接**：https://leetcode.cn/problems/shortest-common-supersequence/
- **来源**：LeetCode 第 141 场周赛 Q4
- **难度**：困难
- **标签**：字符串，动态规划，最长公共子序列

**题意**：给定两个字符串 `str1`、`str2`，返回一个**最短**字符串 $s$，使得 `str1` 与 `str2` 都是 $s$ 的**子序列**（子序列允许跳过任意多个字符，但保持相对顺序）。若最短串有多个，返回其中任意一个即可。

**约束**：

- $1 \le \lvert \text{str1} \rvert,\ \lvert \text{str2} \rvert \le 1000$
- `str1`、`str2` 只含小写英文字母

> 💡 **关键直觉**：答案长度最大 $2000$，$n \times m \le 10^6$ —— 数据规模明确指向 $O(nm)$ 的二维动态规划，而不是任何指数级枚举。

## 2. 示例

**示例 1**

```text
输入：str1 = "abac", str2 = "cab"
输出："cabac"
解释：str1 = "abac" 是 "cabac" 的子序列（删去第一个 'c'）；
      str2 = "cab"  是 "cabac" 的子序列（删去末尾的 "ac"）；
      "cabac" 只是其中一个最优解（答案不唯一，返回任意最短串均可）。
```

**示例 2**

```text
输入：str1 = "aaaaaaaa", str2 = "aaaaaaaa"
输出："aaaaaaaa"
解释：两串完全相同，答案就是它本身（长度 8 = 8 + 8 − 8）。
```

## 3. 解题思路

### 3.1 暴力思路

任何一个公共超序列，都可以看成把 `str1` 与 `str2` 的字符**交错合并**（interleaving）：从两个串的头部各取一个字符、按某种顺序拼接。不同的交错方式共有 $\binom{n+m}{n}$ 种，$n=m=1000$ 时是天文数字，枚举必然超时。

另一种朴素写法是从 $L = \max(n,m)$ 起逐一尝试「是否存在长度为 $L$ 的超序列」，每次判定仍要在 $O(nm)$ 状态图上搜索，外层再套长度循环，白白多出一个 $O(n+m)$ 因子。真正该做的是**把「最短」这个最优化目标交给 DP**，而不是搜索。

### 3.2 核心观察：长度由 LCS 决定

![SCS 长度 = n + m − LCS](images/wc141_q4_scs_length.svg)

把答案 $s$ 的文字位置分成两类：被 `str1`、`str2` **共用**的位置，以及只被其中一个字符串使用的位置。设共用的位置数为 $k$，则

$$\lvert s \rvert = \underbrace{(n-k)}_{\text{仅 str1}} + \underbrace{(m-k)}_{\text{仅 str2}} + \underbrace{k}_{\text{共用}} = n + m - k$$

要让 $\lvert s \rvert$ 最小，就要让**共用的字符尽可能多**。而共用的那些字符，在 `str1` 中按顺序出现、在 `str2` 中也按顺序出现，正是两个串的一个**公共子序列**。于是共用字符最多只能取到最长公共子序列的长度：

$$\lvert \text{SCS} \rvert = n + m - \lvert \text{LCS} \rvert$$

这个等式的**上界方向**（存在这么短的超序列）要靠构造实现，**下界方向**（不可能更短）由 §5 的引理 3 给出。剩下的任务就变成两件事：

1. 用 $O(nm)$ 的 DP 求出 $\text{LCS}$ 长度，顺便把整张 `dp` 表存下来；
2. 从 `dp[n][m]` 沿表**回溯**，边退边写出字符，得到具体的字符串。

### 3.3 算法流程 / 状态转移

![LCS 的 dp 表与回溯路径](images/wc141_q4_lcs_dp_table.svg)

**状态定义**：`dp[i][j]` 表示 `str1` 的前 $i$ 个字符与 `str2` 的前 $j$ 个字符的 LCS 长度。

**转移方程**：

$$dp[i][j] = \begin{cases} dp[i-1][j-1] + 1, & \text{str1}[i-1] = \text{str2}[j-1] \\ \max\bigl(dp[i-1][j],\ dp[i][j-1]\bigr), & \text{否则} \end{cases}$$

边界 `dp[0][*] = dp[*][0] = 0`。按 $i$ 从小到大、$j$ 从小到大填表，$O(nm)$ 时间。

**回溯重建**（从右下角 `(n, m)` 往回走，边倒着收集字符）：

```text
i = n, j = m, res = []
while i > 0 and j > 0:
    if str1[i-1] == str2[j-1]:        # 相等：这个字符被两串共用，只写一次
        res.push(str1[i-1]); i -= 1; j -= 1
    elif dp[i-1][j] >= dp[i][j-1]:    # 向上：str1 的这个字符独占一个位置
        res.push(str1[i-1]); i -= 1
    else:                             # 向左：str2 的这个字符独占一个位置
        res.push(str2[j-1]); j -= 1
while i > 0: res.push(str1[i-1]); i -= 1
while j > 0: res.push(str2[j-1]); j -= 1
return reverse(res)                   # 因为是倒着收集的，最后整体翻转
```

**为什么这样走一定对**：在不等的分支里，`dp[i-1][j]` 与 `dp[i][j-1]` 中至少有一个等于 `dp[i][j]`（因为 `dp[i][j]` 就是二者的较大值），选它意味着**这一步不损失任何共用字符**；在相等的分支里 `dp` 恰好减 1，说明这个字符被计入了共用部分。所以回溯路径上的每个「相等步」都对应 LCS 里的一个字符，一共恰好 $\text{dp}[n][m]$ 步。

### 3.4 示例演算

![示例演算：回溯五步写出 cabac](images/wc141_q4_walkthrough.svg)

对 `str1 = "abac"`、`str2 = "cab"`，表中 `dp[4][3] = 2`，因此答案长度应为 $4 + 3 - 2 = 5$。回溯过程：

| 步 | 状态 $(i,j)$ | 比较 / 依据 | 写出 | 逆序累积 `res` |
|----|--------------|-------------|------|----------------|
| 1 | $(4,3)$ | `c ≠ b`，$dp[3][3]=2 \ge dp[4][2]=1$，向上 | `c`（来自 str1） | `"c"` |
| 2 | $(3,3)$ | `a ≠ b`，$dp[2][3]=2 \ge dp[3][2]=1$，向上 | `a`（来自 str1） | `"ca"` |
| 3 | $(2,3)$ | `b = b`，相等，$i$、$j$ 同减 | `b`（共用） | `"cab"` |
| 4 | $(1,2)$ | `a = a`，相等，$i$、$j$ 同减 | `a`（共用） | `"caba"` |
| 5 | $(0,1)$ | $i = 0$，把 `str2` 剩下的前缀 `"c"` 整段拷入 | `c`（来自 str2） | `"cabac"` |

最后反转得到 `"cabac"`。本例累积结果恰好是回文，所以反转后看着没变；换成别的输入（例如 `"abc"` 与 `"def"`，结果为 `"defabc"`）就能明显看到翻转这一步是必需的。

## 4. 算法细节

1. **相等分支只写一个字符**：`str1[i-1]` 与 `str2[j-1]` 相同时，这个字符同时服务两个串，所以 `res` 只压入一次，而 $i$、$j$ 都减 1。若两个串各压一次，共用的 `b`、`a` 会被写出两遍，示例 1 就会得到长度 7 的 `"caabbac"` 而不是 `"cabac"`。
2. **不等分支的取舍规则**：`dp[i-1][j] >= dp[i][j-1]` 时向上走，否则向左走。取 `>=` 还是 `>` 只影响选到哪一个最优解，不影响长度；但要**自始至终**用同一种规则，否则同一份代码在不同输入上会悄悄改变取舍依据，调试时难以对齐。
3. **回溯的边界顺序**：主循环条件是 `i > 0 and j > 0`；循环结束后还有两段 `while`，把某个串剩余的前缀倒序压入 `res`。这两段不能省，也不能在循环内部处理，否则会与「已写出的字符」顺序错乱。
4. **压入顺序是倒序**：回溯从串尾走到串头，所以 `res` 里的字符是答案的反序，最后必须整体 `reverse`（C++ 用 `std::reverse`，Python 用 `list.append` 收集后 `''.join(reversed(res))`）。
5. **空间选择**：求 LCS 长度只需保留一行，$O(\min(n,m))$ 空间；但**重建必须访问整张表**，所以这里老老实实开 $1001 \times 1001$ 的 `int` 表（约 $4\ \text{MB}$）。若卡的正是内存，可用 **Hirschberg 分治**在 $O(\min(n,m))$ 空间内重建，代价是常数变大、代码量翻倍。
6. **Python 的表结构**：用 `[[0]*(m+1) for _ in range(n+1)]` 建表（$10^6$ 个引用约 $8\ \text{MB}$，小整数有缓存不会额外膨胀）；**不要**用 `[[0]*(m+1)]*(n+1)`，那样每行是同一个列表的别名，赋值会互相覆盖。
7. **常数优化**：C++ 把 `str1[i-1]` 提到循环外、把 `dp[i]` 与 `dp[i-1]` 取成引用；Python 先取出 `row = dp[i]`、`prev = dp[i-1]`、`c1 = str1[i-1]`。答案长度不超过 $n + m$，C++ 再补一句 `res.reserve(n + m)` 避免反复扩容。

## 5. 正确性证明

先固定一个事实：回溯过程中，记 $\Phi(i,j) = dp[i][j]$。

**引理 1（回溯不变量）**：回溯走到状态 $(i,j)$ 时，$dp[i][j]$ 恰好等于「从此刻起还能走出的相等步数」。

**证明**：对剩余状态数归纳。边界 $i=0$ 或 $j=0$ 时 $dp[i][j] = 0$，也没有相等步，成立。设状态 $(i,j)$ 满足 $i,j > 0$：

- 若 `str1[i-1] = str2[j-1]`，由转移方程 $dp[i][j] = dp[i-1][j-1] + 1$，算法走相等步并转到 $(i-1,j-1)$，该状态的 $dp$ 值正好比原来小 1，相等步数加 1，平衡；
- 否则 $dp[i][j] = \max(dp[i-1][j], dp[i][j-1])$，算法跳向其中之一，而所选的格子 $dp$ 值等于 $dp[i][j]$，相等步数为 0，$dp$ 值不变，平衡。

两种情形下不变量都保持。∎

**引理 2（长度正确）**：算法输出的字符串长度恰为 $n + m - \text{dp}[n][m]$。

**证明**：注意每一步只写出**一个**字符，而 $i$、$j$ 的递减次数分别为 $n$ 与 $m$。相等步会同时消耗一次 $i$ 与一次 $j$，却只写一个字符，相当于「省下」一个字符。由引理 1，相等步总数恰为 $dp[n][m]$，故写出字符数 $= n + m - dp[n][m]$。∎

**引理 3（下界）**：设 $s$ 是 `str1` 与 `str2` 的任一公共超序列，则 $\lvert s \rvert \ge n + m - \text{LCS}$。

**证明**：取 `str1` 在 $s$ 中的一次嵌入位置 $p_1 < p_2 < \dots < p_n$，以及 `str2` 的一次嵌入位置 $q_1 < q_2 < \dots < q_m$。$s$ 中被用到的位置集合是 $P \cup Q$，故

$$\lvert s \rvert \ge \lvert P \cup Q \rvert = n + m - \lvert P \cap Q \rvert$$

令 $k = \lvert P \cap Q \rvert$。对交集中的每个位置，它在 `str1` 中对应某个下标 $a$、在 `str2` 中对应某个下标 $b$，把 $(a,b)$ 收集起来并按位置排序：位置递增意味着 $a$ 递增、$b$ 也递增，且该位置上的字符同时等于 $\text{str1}[a]$ 与 $\text{str2}[b]$。于是这些字符构成两个串的一个公共子序列，长度 $k \le \text{LCS}$。代回即得 $\lvert s \rvert \ge n + m - \text{LCS}$。∎

**定理（最优性）**：算法输出的字符串是最短的公共超序列。

**证明**：分两步。

1. **合法性**：把输出（翻转后）记作 $t$。回溯写出的字符分三类：相等步（同时服务两个串）、只减 $i$ 的步（只服务 `str1`）、只减 $j$ 的步（只服务 `str2`）；循环结束后的两段边界处理把某一串剩余的整个前缀倒序写出，它们同样只服务对应的那个串。就此考察 `str1`：它出现在输出里的时刻严格按 $i = n, n-1, \dots, 1$ 递减发生，故翻转之后这些字符在 $t$ 中的相对次序正好是 $1, 2, \dots, n$，与 `str1` 本身一致；每个时刻又占用 $t$ 中一个独立位置（只有相等步的那一个位置允许被两个嵌入共用）。于是把每个 `str1` 字符映到它被写出的位置，就得到一次合法的子序列嵌入，即 `str1` 是 $t$ 的子序列。`str2` 同理。
2. **最短性**：由引理 2，$\lvert t \rvert = n + m - dp[n][m] = n + m - \text{LCS}$；由引理 3，任何公共超序列都不短于这个值。二者相等，故 $t$ 最短。∎

## 6. 复杂度分析

- **时间**：$O(nm)$。填表两层循环共 $nm$ 次状态转移，每次 $O(1)$；回溯每步至少让 $i+j$ 减 1，最多 $n + m$ 步；翻转 $O(n+m)$。总计 $O(nm)$。
- **空间**：$O(nm)$。`dp` 表 $(n+1) \times (m+1)$ 个 `int`（$n=m=1000$ 时约 $4\ \text{MB}$）；答案字符串 $O(n+m)$。若只求长度可压到 $O(\min(n,m))$ 行；若要在同样空间内重建，需改用 Hirschberg 分治（时间仍为 $O(nm)$，常数约翻倍）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    string shortestCommonSupersequence(string str1, string str2) {
        int n = str1.size(), m = str2.size();
        // dp[i][j] = str1[0..i) 与 str2[0..j) 的 LCS 长度
        vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= m; j++) {
                if (str1[i - 1] == str2[j - 1])
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                else
                    dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);
            }
        }

        string res;
        res.reserve(n + m);
        int i = n, j = m;
        while (i > 0 && j > 0) {
            if (str1[i - 1] == str2[j - 1]) {           // 相等：共用这一个字符
                res.push_back(str1[i - 1]);
                --i; --j;
            } else if (dp[i - 1][j] >= dp[i][j - 1]) {  // 向上：str1 的字符独占
                res.push_back(str1[i - 1]);
                --i;
            } else {                                    // 向左：str2 的字符独占
                res.push_back(str2[j - 1]);
                --j;
            }
        }
        while (i > 0) res.push_back(str1[--i]);
        while (j > 0) res.push_back(str2[--j]);
        reverse(res.begin(), res.end());                // 回溯是倒着写的，需翻转
        return res;
    }
};
```

### Python

```python
class Solution:
    def shortestCommonSupersequence(self, str1: str, str2: str) -> str:
        n, m = len(str1), len(str2)
        # dp[i][j] = str1[:i] 与 str2[:j] 的 LCS 长度
        dp = [[0] * (m + 1) for _ in range(n + 1)]
        for i in range(1, n + 1):
            c1, row, prev = str1[i - 1], dp[i], dp[i - 1]
            for j in range(1, m + 1):
                if c1 == str2[j - 1]:
                    row[j] = prev[j - 1] + 1
                else:
                    row[j] = prev[j] if prev[j] >= row[j - 1] else row[j - 1]

        res = []
        i, j = n, m
        while i > 0 and j > 0:
            if str1[i - 1] == str2[j - 1]:        # 相等：共用这一个字符
                res.append(str1[i - 1])
                i -= 1
                j -= 1
            elif dp[i - 1][j] >= dp[i][j - 1]:    # 向上：str1 的字符独占
                res.append(str1[i - 1])
                i -= 1
            else:                                 # 向左：str2 的字符独占
                res.append(str2[j - 1])
                j -= 1
        while i > 0:
            i -= 1
            res.append(str1[i])
        while j > 0:
            j -= 1
            res.append(str2[j])
        return ''.join(reversed(res))             # 回溯是倒着写的，需翻转
```

## 8. 边界情况与易错点

1. **两串完全相同**（示例 2）：回溯会连走 $n$ 个相等步，答案就是原串，长度 $n$ 而不是 $2n$；此时 `dp[n][n] = n`，公式 $n + n - n = n$ 自洽。
2. **完全没有公共字符**（如 `"abc"` 与 `"def"`）：$dp = 0$，回溯一路走边界，答案长度 $n + m$，内容是某个交错结果（例如 `"defabc"`）。这类输入最容易暴露「边界前缀没拷完」的 bug。
3. **一个串是另一个的子序列**（如 `"bc"` 与 `"abc"`）：答案应等于更长的那个串本身，长度 $\max(n,m)$；若代码把相等字符写了两遍，就会多出字符。
4. **相等分支的 `--i; --j;` 漏写一个**：只减 `i` 会让 `j` 处的字符被重复写出，答案长度超过下界，是最常见的 WA 原因。
5. **下标越界**：`str1[i-1]` 只在 $i > 0$ 时安全，主循环的 `i > 0 && j > 0` 条件必须写全；边界段用 `while (i > 0) res.push_back(str1[--i]);` 这种「先减再取」的写法，避免访问 `str1[n]`。
6. **忘记翻转**：`res` 是逆序累积的，直接返回会得到反串。单测时用「两个串都是返回值的子序列」来卡这个错误，比对比字符串更可靠。
7. **规模压测**：$n = m = 1000$ 且字符全为 `a` 时，答案是 $1000$ 个 `a`、回溯连走 $1000$ 个相等步，最容易暴露越界与死循环；先用它自测再提交。
