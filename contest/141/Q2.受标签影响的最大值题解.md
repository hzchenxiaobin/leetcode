# LeetCode 受标签影响的最大值 题解

## 1. 题目概述

- **标题 / 题号**：受标签影响的最大值（#1090，medium）
- **链接**：https://leetcode.cn/problems/largest-values-from-labels/
- **来源**：LeetCode 第 141 场周赛 Q2
- **难度**：中等
- **标签**：贪心，数组，哈希表，计数，排序

**题意**：`values[i]` 与 `labels[i]` 描述第 $i$ 件物品的「值」与「标签」。要挑一个子集 $S$，最大化

$$\sum_{i \in S} \text{values}[i]$$

同时满足两个**上限**：$|S| \le \text{numWanted}$，且对任意标签 $c$，子集中标签为 $c$ 的物品个数不超过 $\text{useLimit}$。返回最大和。

**约束**：

- $n = |\text{values}| = |\text{labels}|$
- $1 \le n \le 2 \times 10^4$
- $0 \le \text{values}[i],\ \text{labels}[i] \le 2 \times 10^4$
- $1 \le \text{numWanted},\ \text{useLimit} \le n$

> 💡 **关键直觉**：两条约束都是「至多」，且每件物品的贡献（值）与别的物品**互不影响**。这种「独立收益 + 上限约束」几乎总是指向**排序后贪心**：先拿值大的，撞到标签名额就跳过。

## 2. 示例

**示例 1**

```text
输入：values = [5,4,3,2,1], labels = [1,1,2,2,3], numWanted = 3, useLimit = 1
输出：9
解释：选第 1、3、5 件（值 5、3、1），标签 1、2、3 各用掉 1 个名额，和 = 9。
```

**示例 2**

```text
输入：values = [5,4,3,2,1], labels = [1,3,3,3,2], numWanted = 3, useLimit = 2
输出：12
解释：选第 1、2、3 件（值 5、4、3）；标签 1 一次、标签 3 两次（正好用满 useLimit），和 = 12。
```

**示例 3**

```text
输入：values = [9,8,8,7,6], labels = [0,0,0,1,1], numWanted = 3, useLimit = 1
输出：16
解释：选第 1、4 件（值 9、7）；标签 0 已满，值 8、8 两件都被跳过，和 = 16。
       注意只选了 2 件——「至多 numWanted 件」不要求选满。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子集，检查两条上限，取合法子集的最大和：子集数 $2^n$，$n = 2\times10^4$ 时完全不可行。若换成分组背包：对每种标签做「取 $0\ldots\text{useLimit}$ 件」的决策，状态是「已选件数 × 每种标签的空闲名额」，$O(n \cdot \text{numWanted} \cdot \text{useLimit}^{\#\text{labels}})$，同样爆炸。

> 暴力的浪费在于：我们**不需要同时决定所有物品**。既然值是独立的、约束只是上限，那么「值最大的那一件，只要名额允许就一定该被选」。

### 3.2 核心观察：值降序 + 标签名额贪心

![核心观察：值降序排列物品，哈希表记录每个标签已用名额](images/wc141_q2_greedy_quota.svg)

把物品按值**降序**排好，从左到右扫描，维护 `used[c]` = 标签 $c$ 已选个数：

- 若 `taken < numWanted` 且 `used[c] < useLimit`：**选它**，累加值、`taken += 1`、`used[c] += 1`；
- 否则**跳过**它（标签名额满，或总量已满）。

直观理由：当扫描到 $(v, c)$ 时，之前考虑过的物品值都 $\ge v$。若它被跳过，唯一原因是「标签 $c$ 的名额已被更值钱的同标签物品占满」或「已经选够件数」。这两种情况下，把 $(v,c)$ 换成任何已选物品都不会变好——这正是**交换论证**的落点。

用公式说，这就是一个**带分组上限的独立集最大化**：

$$\max \sum_{i \in S} v_i \quad \text{s.t.} \quad |S| \le B,\ \ \forall c:\ |S \cap L_c| \le U$$

其中 $L_c$ 是标签为 $c$ 的物品集合，$B = \text{numWanted}$，$U = \text{useLimit}$。可行集族对**子集封闭**（从可行集里删掉任何物品都不会破坏上限），这是贪心能工作的结构性前提；完整证明见 §5，只用到交换论证，不需要拟阵理论。

### 3.3 算法流程

![算法流程：配对排序 → 顺序扫描 → 两条名额检查](images/wc141_q2_algorithm_flow.svg)

1. 把 `values[i]` 与 `labels[i]` 配成二元组 $(v_i, c_i)$；
2. 按 $v_i$ **降序**排序；
3. 初始化哈希表 `used = {}`、`taken = 0`、`ans = 0`；
4. 依次取出 $(v, c)$：若 `taken` 已达 `numWanted` 立即结束；否则若 `used[c] < useLimit` 则选入，`ans += v`，`taken += 1`，`used[c] += 1`；
5. 扫描结束后返回 `ans`。

### 3.4 示例演算

对示例 1（`numWanted = 3`，`useLimit = 1`），排序后顺序恰为 $(5,1),(4,1),(3,2),(2,2),(1,3)$：

![示例 1 演算：每一步的标签计数、已选件数与累计和](images/wc141_q2_walkthrough.svg)

| 步骤 | 值 | 标签 | 检查 | 动作 | 累计和 |
|------|----|------|------|------|--------|
| 1 | 5 | 1 | `used[1]=0 < 1` | 选中 | 5 |
| 2 | 4 | 1 | `used[1]=1 = useLimit` | 跳过 | 5 |
| 3 | 3 | 2 | `used[2]=0 < 1` | 选中 | 8 |
| 4 | 2 | 2 | `used[2]=1 = useLimit` | 跳过 | 8 |
| 5 | 1 | 3 | `used[3]=0 < 1` | 选中，`taken=3` 满 | 9 |

示例 3 更能说明「不必凑满件数」：标签 0 的三件值为 $9,8,8$，`useLimit = 1` 时只能拿最大的 9，两个 8 全部作废；标签 1 的两件 $7,6$ 中再取 7。此时 `taken = 2 < 3`，但剩下的 8、8、6 三件都被各自的标签名额挡住，一件也拿不了，答案是 $9 + 7 = 16$。

## 4. 算法细节

1. **配对方式**：C++ 里对**下标**排序（`vector<int> idx`）比构造 `pair` 再 `sort` 少一次搬运，且排序比较器只读 `values`；Python 里 `sorted(zip(values, labels), key=lambda p: -p[0])` 一行即可，也可以写成 `key=itemgetter(0), reverse=True`。
2. **提前终止**：`taken` 达到 `numWanted` 后直接 `break`。此时剩余物品值都不超过已选的最小值，再选也只会破坏名额或让和不变，纯属浪费。
3. **计数器选型**：标签值域很小（$\le 2\times10^4$），可以直接开 `int used[20001]` 数组，常数远小于 `unordered_map`；用哈希表则要注意 `reserve` 避免 rehash。两种写法复杂度同为 $O(n)$。
4. **候选排序还是分组排序**：也可以先把同标签物品归到一组、每组只保留最大的 `useLimit` 件（用 `nth_element` 或排序），再把所有候选混在一起取前 `numWanted` 大。这条路线与本文贪心等价，见「延伸思考」。
5. **相等值的处理**：值相同的物品先后顺序任意，因为交换它们不改变任何一条约束的计数，也不改变和；比较器写 `values[a] > values[b]` 即可，不必补 tie-break（补了也不影响正确性）。
6. **和的量级**：最多选 $2\times10^4$ 件、每件值 $\le 2\times10^4$，和 $\le 4\times10^8 < 2^{31}-1$，`int` 足够；若约束放宽到 $10^9$ 级别就要换 `long long`。

## 5. 正确性证明

记排序后的物品序列为 $x_1, \dots, x_n$，值满足 $v_1 \ge v_2 \ge \dots \ge v_n$；记 $G_t$ 为贪心处理完前 $t$ 件后的选择集合，$O$ 为某个最优解。

**引理 1（贪心解可行）**：对每个 $t$，$G_t$ 满足 $|G_t| \le \text{numWanted}$ 且任一标签在 $G_t$ 中出现次数 $\le \text{useLimit}$。

**证明**：对 $t$ 归纳。$G_0 = \varnothing$ 显然可行。贪心只在 `taken < numWanted` 且 `used[c] < useLimit` 时才把 $x_{t+1}$ 加入 $G_t$：加入后 $|G_{t+1}| = |G_t| + 1 \le \text{numWanted}$，标签 $c$ 的计数从 $cnt_c(G_t)$ 增为 $cnt_c(G_t) + 1 \le \text{useLimit}$，其余标签计数不变，故 $G_{t+1}$ 仍可行。∎

**引理 2（首个分歧可消除）**：设 $t$ 是最小的下标，使「$x_t$ 是否被选」在贪心与 $O$ 中不同（即 $G_{t-1} = O \cap \{x_1,\dots,x_{t-1}\}$）。若贪心选了 $x_t$ 而 $O$ 没选，则存在最优解 $O'$ 满足 $O' \cap \{x_1,\dots,x_t\} = G_t$ 且 $\text{sum}(O') \ge \text{sum}(O)$。

**证明**：贪心在 $t$ 处选入，说明 $|G_{t-1}| < \text{numWanted}$，$used[c] < \text{useLimit}$（$c = \text{label}(x_t)$）。因 $G_{t-1} \subseteq O$，故 $|O| \ge |G_{t-1}|$、$O$ 中标签 $c$ 的计数 $\ge used[c]$。分两种情形：

- **标签 $c$ 在 $O$ 中已满**（计数 $= \text{useLimit}$）：由 $used[c] < \text{useLimit}$，$O$ 里必有标签为 $c$ 的物品不在 $G_{t-1}$ 中；由 $t$ 的最小性，这样的物品下标 $\ge t$，且不是 $x_t$（$x_t \notin O$），故其下标 $> t$，值 $\le v_t$。取其中一件 $y$，令 $O' = O - \{y\} + \{x_t\}$：件数不变，标签 $c$ 计数仍为 $\text{useLimit}$，其余标签不变，故 $O'$ 可行；$\text{sum}(O') = \text{sum}(O) - v_y + v_t \ge \text{sum}(O)$，故 $O'$ 仍最优。
- **标签 $c$ 在 $O$ 中未满**：若 $|O| = \text{numWanted}$，由 $|G_{t-1}| < \text{numWanted}$ 且 $G_{t-1} \subseteq O$，可取 $y \in O \setminus G_{t-1}$；由 $t$ 的最小性 $y$ 的下标 $\ge t$，又 $x_t \notin O$，故下标 $> t$，$v_y \le v_t$。令 $O' = O - \{y\} + \{x_t\}$：件数仍为 $\text{numWanted}$，标签 $c$ 计数 $+1$ 后仍 $\le \text{useLimit}$，可行且和不减。若 $|O| < \text{numWanted}$，则 $O \cup \{x_t\}$ 同时满足两条上限且和严格更大，与 $O$ 最优矛盾，该情形不会出现。

两种情形都得到满足 $O' \cap \{x_1,\dots,x_t\} = G_t$ 的最优解（$O$ 与 $G_{t-1}$ 在前缀上一致，构造只动了下标 $> t$ 的物品）。∎

**引理 3（贪心不会误跳）**：在同一「首个分歧点」设定下，若贪心跳过了 $x_t$，则 $O$ 也不选 $x_t$。

**证明**：贪心跳过意味着 $|G_{t-1}| = \text{numWanted}$ 或 $used[c] = \text{useLimit}$。由 $G_{t-1} \subseteq O$：若 $used[c] = \text{useLimit}$，则 $O$ 中标签 $c$ 的计数 $\ge \text{useLimit}$，而 $x_t$ 标签也是 $c$，若 $x_t \in O$ 就超限，与 $O$ 可行矛盾；若 $|G_{t-1}| = \text{numWanted}$，由 $G_{t-1} \subseteq O$ 得 $|O| \ge \text{numWanted}$，结合 $O$ 可行得 $|O| = \text{numWanted}$，于是 $G_{t-1} = O$；若再有 $x_t \in O$，因 $x_t \notin G_{t-1}$ 会得到 $|O| = |G_{t-1}| + 1 = \text{numWanted} + 1$，与 $O$ 可行矛盾。∎

**定理**：贪心算法返回最大可能的和。

**证明**：由引理 3，「贪心跳过而最优选」的分歧不存在；由引理 2，「贪心选而最优不选」的分歧总能把某个最优解改造成在该位置与贪心一致、且和不变小。于是从 $t = 1$ 起逐个消除分歧，最多 $n$ 步后可把某个最优解改造成贪心解 $G_n$，且全过程和不减小。由引理 1，$G_n$ 可行，故 $\text{sum}(G_n) \ge \text{sum}(O) = \text{OPT}$，又 $G_n$ 可行意味着 $\text{sum}(G_n) \le \text{OPT}$，故二者相等。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。配对与下标初始化 $O(n)$；排序 $O(n\log n)$ 为瓶颈；扫描每件物品一次，每次 $O(1)$ 的哈希表（或数组）查询与更新，并且选满 `numWanted` 后立即 `break`，最坏 $O(n)$。
- **空间**：$O(n)$。排序用的下标数组 $O(n)$；标签计数表最多 $\min(n, 2\times10^4+1)$ 个条目，用数组则为固定的 $O(\max \text{labels}) = O(2\times10^4)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int largestValsFromLabels(vector<int>& values, vector<int>& labels, int numWanted, int useLimit) {
        int n = values.size();
        vector<int> idx(n);
        for (int i = 0; i < n; ++i) idx[i] = i;
        // 按下标排序：值降序，值相等时顺序任意
        sort(idx.begin(), idx.end(), [&](int a, int b) { return values[a] > values[b]; });

        unordered_map<int, int> used;   // 每个标签已选个数
        used.reserve(n * 2 + 1);

        int ans = 0, taken = 0;
        for (int i = 0; i < n && taken < numWanted; ++i) {
            int c = labels[idx[i]];
            if (used[c] < useLimit) {   // 标签名额未满才选
                ++used[c];
                ans += values[idx[i]];
                ++taken;
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def largestValsFromLabels(self, values: List[int], labels: List[int],
                              numWanted: int, useLimit: int) -> int:
        items = sorted(zip(values, labels), key=lambda p: -p[0])  # 值降序
        used = {}
        ans = taken = 0
        for v, c in items:
            if taken == numWanted:
                break                      # 总量已满，后面的都不用看
            if used.get(c, 0) < useLimit:  # 标签名额未满才选
                used[c] = used.get(c, 0) + 1
                ans += v
                taken += 1
        return ans
```

## 8. 边界情况与易错点

1. **不必选满 `numWanted` 件**：`useLimit` 很小时可能凑不出这么多件（如示例 3 只选 2 件），循环自然结束即可，不要额外补齐，更不能为了凑数选小值。
2. **所有物品同一标签**：此时答案就是该标签**最大的 `useLimit` 件**之和；`useLimit ≥ n` 时退化为「全体物品取前 `numWanted` 大」，注意 `used[c]` 的比较方向别写反。
3. **值为 0 的物品**：`values[i]` 可以为 0，选中它们不改变和，但会占用 `taken` 名额，所以本题答案与「是否选 0」无关、但选出的子集可能不同。不要额外加「`v == 0` 就跳过」的剪枝：虽然本题结果不变，却会让实际选出的集合偏离标准贪心，调试时容易误判。反过来，**若**题目允许负值，则降序扫描到 $v < 0$ 时必须停止（后面只会更小），此时「遇到负数就收手」才是正确剪枝。
4. **和为 0 的合法答案**：全 0 输入时返回 0，与「什么都不选」的 0 相同，别把 0 当成未初始化的哨兵。
5. **溢出的量级**：$2\times10^4 \times 2\times10^4 = 4\times10^8$，`int` 够；但若把 `values` 上限改成 $10^9$，累加就必须用 `long long`。
6. **哈希表的隐式创建**：C++ 里 `used[c]` 会插入默认值 0，直接写 `if (used[c] < useLimit)` 是安全的；Python 里必须用 `used.get(c, 0)`，直接 `used[c]` 会抛 `KeyError`。
7. **`labels[i]` 作数组下标**：若改用 `int used[20001]`，数组要开到 $2\times10^4 + 1$，开成 20000 会在 `labels` 取到 20000 时越界。

**延伸思考**：若把「每个标签**至多** `useLimit` 件」改成「每个标签**恰好** `useLimit` 件」，贪心就失效了——你可能被迫选入很小的值来凑数，问题变成分组约束下的精确覆盖，需要 DP 或最小费用流。若给物品再加一个「重量」维度、要求总重量不超过 $W$，则退化为多约束背包，贪心不再最优（可构造反例），只能 DP。另一个等价视角：先对每个标签用一次排序（或 `nth_element`）取前 `useLimit` 大作为候选，再在全体候选里取前 `numWanted` 大——两条路线结果相同，可作为对拍的第二个实现。
