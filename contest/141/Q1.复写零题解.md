# LeetCode 复写零 题解

## 1. 题目概述

- **标题 / 题号**：复写零（#1089，easy）
- **链接**：https://leetcode.cn/problems/duplicate-zeros/
- **来源**：LeetCode 第 141 场周赛 Q1
- **难度**：简单
- **标签**：数组、双指针

**题意**：给定长度固定的整数数组 `arr`，把其中**每个 0 复写一份**（原 0 保留，紧跟一个 0），其余元素整体右移；长度固定，**超出原长度的部分直接丢弃**；函数必须**就地**修改 `arr`，不返回任何值。

**约束**：

- $1 \le \text{arr.length} \le 10^4$
- $0 \le \text{arr}[i] \le 9$

> 💡 签到题的关键不是「能不能做对」，而是**能否一次写出 O(n) 时间 + O(1) 空间的就地版本**，并且把「末尾被截断」这一处边界想清楚。

## 2. 示例

**示例 1**

```text
输入：arr = [1,0,2,3,0,4,5,0]
输出：[1,0,0,2,3,0,0,4]
解释：三个 0 各复写一份，右移后前 8 个位置留下 [1,0,0,2,3,0,0,4]，
      末尾被挤出的 5 和最后一个 0 直接丢弃。
```

**示例 2**

```text
输入：arr = [1,2,3]
输出：[1,2,3]
解释：没有 0，数组不变。
```

**补充示例（覆盖「末尾截断」）**

```text
输入：arr = [8,0,0,2]
输出：[8,0,0,0]
解释：展开后是 [8,0,0,0,0,2]，只保留前 4 个，最后一个 0 的第二份放不下。
```

## 3. 解题思路

### 3.1 暴力思路

- **开新数组**：把每个元素按「0 展开成两份」写进新数组，再截断写回 `arr`。$O(n)$ 时间、$O(n)$ 空间，能过，但不满足「就地」的强化要求，也没有用到题目给的关键提示。
- **真·原地逐元素右移**：从左往右扫，遇到 0 就把 `arr[i+1..n-1]` 整体右移一格，再在 `arr[i+1]` 补一个 0。单次移位 $O(n)$，总 $O(n^2)$；$n = 10^4$ 时约 $10^8$ 次赋值，Python 会跑到秒级，属于「能过但很脏」的写法。
- **更本质的矛盾**：从左往右写时，右边的元素**还没被读过**就已经被覆盖了。这就是所有错误写法的共同根源。

### 3.2 核心观察：结果只由「原数组的一个前缀」决定

![正向扫描：数清每个元素占几个位置](images/wc141_q1_forward_scan.svg)

把复写想成「展开」：原数组展开后得到一个长度 $L = n + z$ 的序列 $D$（$z$ 是 0 的个数），答案是 $D$ 的**前 $n$ 位**。于是两个事实立刻成立：

1. **每个元素占几个位置是固定的**：0 占 2 个，非 0 占 1 个；
2. **只有前缀参与结果**：从左往右累加「容量」，第一次达到或超过 $n$ 时，后面的元素已经一个位置都分不到，可以整体忽略。

记

$$S(k)=\sum_{t=0}^{k} w(t),\qquad w(t)=\begin{cases}2, & \text{arr}[t]=0\\ 1, & \text{arr}[t]\ne 0\end{cases}$$

正扫找到**最小的** $i$ 使 $S(i-1)\ge n$。此时：

- 若 $S(i-1) = n$：`arr[0..i-1]` 刚好填满，`arr[i..n-1]` 全部被挤出；
- 若 $S(i-1) = n+1$：说明卡在了 $0$ 上，**最后一个 0 只放得下第一份**，第二份被截断。

这就是本题唯一的「坑」：截断恰好发生在 0 上时，只能写一份。

### 3.3 算法流程：两个指针从右往左同步移动

![逆序回填：j 始终在 k 右边](images/wc141_q1_backward_fill.svg)

既然「读」的终点是 $k = i-1$、「写」的终点是 $j = n-1$，就让两个指针**都从右往左**走：

- `arr[k] != 0`：写一个数，`arr[j--] = arr[k]`，然后 `k--`；
- `arr[k] == 0`：连写两个 0，`arr[j--] = 0; arr[j--] = 0`，然后 `k--`。

正向写会踩坏未读数据，逆向写为什么安全？因为回填到下标 $k$ 时恰好有 $j = S(k)-1$，而 $S(k)\ge k+1$，所以 $j\ge k$：**写指针永远在读指针右边（或重合）**，右侧是已经写好的结果区，左侧才是尚未读取的原值。

两个分支都不需要额外数组，指针只朝一个方向走，一次扫描即完成。

### 3.4 示例演算

![六步回填走查](images/wc141_q1_walkthrough.svg)

以 `arr = [1,0,2,3,0,4,5,0]`（$n=8$）为例，正扫得到容量序列 $1,3,4,5,7,8$，停在 `arr[5]`，故 $i=6$、$\text{cnt}=8=n$（无截断），从 $j=7$、$k=5$ 开始：

| 步 | $k$ | `arr[k]` | 写入动作 | $j$ 变化 | 回填后的数组 |
|----|-----|----------|----------|----------|--------------|
| 0 | 5 | 4 | 初始：$i=6,\ j=7,\ k=5$ | 7 | `[1,0,2,3,0,4,5,0]` |
| 1 | 5 | 4 | `arr[7] ← 4` | 7→6 | `[1,0,2,3,0,4,5,4]` |
| 2 | 4 | 0 | `arr[6], arr[5] ← 0` | 6→4 | `[1,0,2,3,0,0,0,4]` |
| 3 | 3 | 3 | `arr[4] ← 3` | 4→3 | `[1,0,2,3,3,0,0,4]` |
| 4 | 2 | 2 | `arr[3] ← 2` | 3→2 | `[1,0,2,2,3,0,0,4]` |
| 5 | 1 | 0 | `arr[2], arr[1] ← 0` | 2→0 | `[1,0,0,2,3,0,0,4]` |
| 6 | 0 | 1 | `arr[0] ← 1` | 0→−1 | `[1,0,0,2,3,0,0,4]` |

第 6 步 `j = k = 0` 属于「自己写自己」，无害；被挤出的 5 和最后一个 0 从未被写入任何位置。

再用截断例子 `arr = [8,0,0,2]`（$n=4$）走一遍：容量 $1,3,5$ 越过了 4，$i=3$、$\text{cnt}=5>n$，说明 `arr[2]` 这个 0 的第二份放不下。于是先写 `arr[3] = 0`、`k` 退到 1，然后正常回填：`arr[3]` 之后写 `arr[2] = 0`（来自 `arr[1]` 的第一份）、`arr[1] = 0`（第二份）、`arr[0] = 8`，得到 `[8,0,0,0]`，与补充示例一致。

## 4. 算法细节

1. **正扫的越界安全性**：循环条件是 `cnt < n`，而进入循环时 $i \le \text{cnt} < n$（每个元素至少贡献 1），所以 `arr[i]` 永不越界，不需要额外的 `i < n` 判断。
2. **`cnt` 只会是 $n$ 或 $n+1$**：每次加 1 或 2，且一达到 $\ge n$ 就停，所以越界量最多为 1 —— 这正是「最多只截断一个 0」的形式化表述。
3. **截断分支只执行一次**：`if (cnt > n) { arr[j--] = 0; k--; }` 放在主循环**之前**，先吃掉那份「只剩一半」的 0，之后主循环里每个 0 都理直气壮地写两份。
4. **`cnt > n` 时不能只 `j--` 不 `k--`**：被截断的那个 0 已经消费掉了（第一份已写），`k` 必须同步左移，否则会把同一个 0 再写两遍。
5. **写完两份 0 不会越界**：`arr[k]==0` 时 $S(k)\ge k+2$，故 $j = S(k)-1\ge k+1\ge 1$，写 `arr[j-1]` 时下标非负。
6. **不要用切片整体赋值**：Python 里 `arr[:] = new_arr` 虽然「就地」了引用，却额外开了 $O(n)$ 空间，违背本题意图；也不要 `return arr`。
7. **接口按题面**：C++ 为 `void duplicateZeros(vector<int>& arr)`，Python 为 `def duplicateZeros(self, arr: list[int]) -> None`，返回值必须是空。
8. **另一种等价写法**：先统计 0 的个数 `z`，再从右往左令目标位置 `i + z`（遇到 0 时 `z--` 并再写一份）。它与本文的「容量记账」思想相同，但边界判断（`i + z < n`）更绕、更易错，面试时更容易写崩。

## 5. 正确性证明

记 $w(t)$、$S(k)$ 如上，$D$ 为原数组展开后的完整序列（长度 $n+z$），题目要求的答案是 $D[0..n)$。

**引理 1（截断点唯一）**：正扫结束时得到的 $i$ 满足 $S(i-1)\ge n > S(i-2)$，且 $i$ 是满足该式的最小下标；此时 $\text{cnt}=S(i-1)\in\{n,n+1\}$。

**证明**：正扫依次累加 $w(0),w(1),\dots$，一旦 $\text{cnt}\ge n$ 立即停止并令 $i$ 加一，故停止时 $i$ 恰为「首次达标」的下标加一，即最小性成立。又每次增量 $w(t)\in\{1,2\}$，停止前一刻 $S(i-2)<n$，故 $S(i-1) < n+2$，结合 $S(i-1)\ge n$ 得 $\text{cnt}\in\{n,n+1\}$。∎

**引理 2（覆盖安全）**：对任意 $0\le k\le i-1$，回填到下标 $k$ 时恒有 $j=S(k)-1\ge k$；且若 $\text{arr}[k]=0$，则更强地有 $j\ge k+1$。

**证明**：由 $w(t)\ge 1$ 得 $S(k)\ge k+1$，故 $j=S(k)-1\ge k$。若 $\text{arr}[k]=0$，则 $w(k)=2$ 且前 $k$ 个元素各贡献至少 1，故 $S(k)\ge k+2$，即 $j\ge k+1$。∎

**引理 3（回填不变量）**：在准备处理下标 $k$ 时，有
$\text{arr}[j+1..n-1] = D[S(k)..n)$ 且 $\text{arr}[0..k]$ 仍等于原值，同时 $j=S(k)-1$。

**证明**：对 $k$ 从 $i-1$ 递减归纳。奠基：$k=i-1$ 时 $j=n-1=S(k)-1$，右侧区间为空，$\text{arr}[0..i-1]$ 尚未被写过，成立。

归纳步：设处理 $k$ 前不变量成立。

- 若 $\text{arr}[k]\ne 0$：元素 $k$ 在 $D$ 中占据位置 $S(k)-1$，值为 $\text{arr}[k]$，故写 $\text{arr}[j]=\text{arr}[k]$ 后 $\text{arr}[j..n-1] = D[S(k)-1..n)$；新 $j=S(k)-1-1=S(k-1)-1$，新右侧区间起点恰为 $S(k-1)$。由引理 2 的 $j\ge k$，写入位置不下探到未读区（$j=k$ 时是自赋值）。
- 若 $\text{arr}[k]=0$：元素 $k$ 在 $D$ 中占据 $S(k)-2$ 与 $S(k)-1$ 两格且都是 0，连写两个 0 后 $\text{arr}[j-1..n-1] = D[S(k)-2..n)$；新 $j=S(k)-3=S(k-1)-1$。由引理 2 有 $j\ge k+1$，故写到的 $j-1\ge k$，仍未触及 $\text{arr}[0..k-1]$。

两种情况新不变量均成立。∎

**引理 4（截断分支正确）**：若 $\text{cnt}=n+1$，则预写操作 $\text{arr}[n-1]=0$ 与随后的状态满足引理 3 的不变量。

**证明**：$\text{cnt}=n+1$ 说明 $\text{arr}[i-1]=0$ 且 $S(i-2)=n-1$。该 0 的两份占 $D[n-1]$ 与 $D[n]$，而答案只取到 $D[n-1]$，故 $\text{arr}[n-1]=0$ 恰好是正确结果；随后 $k=i-2$、$j=n-2=S(k)-1$，引理 3 的前提成立。∎

**定理**：算法结束时 $\text{arr} = D[0..n)$，即答案正确。

**证明**：由引理 3、4，循环在 $k$ 递减到 $-1$（即 $k<0$）时结束，此时不变量给出 $\text{arr}[0..n-1] = D[0..n)$（取 $S(-1)=0$、$j=-1$）。整个过程中没有写入 $n$ 及以后的位置，符合「不写超出长度的部分」。∎

## 6. 复杂度分析

- **时间**：$O(n)$。正扫每个下标最多访问一次（$i$ 单调加一，且 $i\le n$）；回填 $k$ 从 $i-1$ 递减到 $0$，每步常数次赋值与判断；两趟互不嵌套。
- **空间**：$O(1)$。除 `i, cnt, j, k` 四个整型变量外不申请任何与 $n$ 相关的空间，且 `arr` 本身被就地修改（切片整体赋值、`new` 新数组都会破坏这一点）。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    void duplicateZeros(vector<int>& arr) {
        int n = (int)arr.size();

        // 第一趟：正向累加容量，找截断点
        int i = 0, cnt = 0;
        while (cnt < n) {
            cnt += (arr[i] == 0) ? 2 : 1;
            i++;
        }

        // 第二趟：从右往左回填
        int j = n - 1, k = i - 1;
        if (cnt > n) {          // 最后一个 0 的第二份放不下，只写一份
            arr[j--] = 0;
            k--;
        }
        while (k >= 0) {
            if (arr[k] == 0) {
                arr[j--] = 0;
                arr[j--] = 0;
            } else {
                arr[j--] = arr[k];
            }
            k--;
        }
    }
};
```

### Python

```python
class Solution:
    def duplicateZeros(self, arr: list[int]) -> None:
        """
        Do not return anything, modify arr in-place instead.
        """
        n = len(arr)

        # 第一趟：正向累加容量，找截断点
        i = cnt = 0
        while cnt < n:
            cnt += 2 if arr[i] == 0 else 1
            i += 1

        # 第二趟：从右往左回填
        j, k = n - 1, i - 1
        if cnt > n:                 # 末尾那个 0 只能写一份
            arr[j] = 0
            j -= 1
            k -= 1
        while k >= 0:
            if arr[k] == 0:
                arr[j] = 0
                j -= 1
                arr[j] = 0
                j -= 1
            else:
                arr[j] = arr[k]
                j -= 1
            k -= 1
```

## 8. 边界情况与易错点

1. **只有一个元素且为 0**：`arr = [0]`。容量为 2 > 1，走截断分支写一份，结果仍是 `[0]`；若漏掉截断分支，`arr[1]` 就越界了。
2. **全 0 数组**：`[0,0,0]` → `[0,0,0]`。容量 $2,4$ 直接越过 $n=3$，`cnt=4` 说明只能往 `arr[2]` 写**一份** 0；预写后 `k` 退到 $0$，还要再写 `arr[1]` 与 `arr[0]`。
3. **没有 0**：`[1,2,3]` 时 `i=n`、`cnt=n`，主循环里 $j=k$ 逐步自赋值，结果不变（正确但别误以为「什么都没做」）。
4. **截断与否只差一份 0**：`[8,0,2]` 无需截断（容量 $1,3$ 恰好 $=n$，写两份 0 后变为 `[8,0,0]`），而 `[8,0]` 需要截断（容量 $1,3$ 越过 $n=2$）。只能用 `cnt > n` 判断，别靠「最后一位是不是 0」猜。
5. **不要在正扫后继续用 `i` 之前的值**：`i` 是「最后保留下标 + 1」，`k = i - 1`；写成 `k = i` 会多读一个被挤出的元素。
6. **返回值的坑**：C++ 必须 `void`，Python 必须 `return None`（LeetCode 会检查返回类型，`return arr` 会判错）。
7. **复杂度陷阱**：$n=10^4$ 时 $O(n^2)$ 的逐元素右移约 $10^8$ 次赋值，C++ 卡线、Python 超时；而「开新数组再写回」虽然正确，空间是 $O(n)$，属于退让解。
8. **就地 ≠ 覆盖未读**：任何时候写入位置必须在读指针右侧（本算法保证 $j\ge k$），一旦次序颠倒就会把还没读到的数抹掉。
