# LeetCode 最长公共子路径 题解

## 1. 题目概述

- **标题 / 题号**：最长公共子路径（#1923，hard）
- **链接**：https://leetcode.cn/problems/longest-common-subpath/
- **来源**：LeetCode 第 248 场周赛 Q4
- **难度**：困难
- **标签**：二分查找、滚动哈希、哈希函数、数组

**题意**：一个国家有 $n$ 座编号 $0 \sim n-1$ 的城市（任意两城之间皆有道路，这只是背景板）。$m$ 位朋友各自走了一条路径，`paths[i]` 是第 $i$ 位朋友按顺序到过的城市序列；同一城市可在一条路径中**非连续地**重复出现。求**所有人都走过**的**最长公共子路径**的长度——子路径指路径中**连续**的城市序列；不存在则返回 $0$。

**约束**：

- $1 \le n \le 10^5$（城市编号值域，即本题「字符集」大小）
- $m = \text{paths.length}$，$2 \le m \le 10^5$
- $\sum_i \text{paths}[i].\text{length} \le 10^5$（总长记 $S$，是一切复杂度的预算）
- $0 \le \text{paths}[i][j] < n$
- 同一路径中同一城市不会连续出现

> 💡 本题在本仓库另有[每日题解 1923](../../solution/1901-2000/1923_最长公共子路径.md)：侧重「多项式哈希原理、双哈希参数选择与面试问答」。本篇按周赛复盘视角，聚焦「枚举子路径 → 定长判定」的降维识别路径、**防对抗数据的哈希纪律**（本题以卡固定参数哈希闻名）、判定**单侧错误**的证明链与赛场易错清单，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：枚举子路径

子路径由「起点 $\times$ 长度」两个自由度决定。最直接的做法是枚举**最短路径**的全部 $O(\text{minLen}^2)$ 个子路径，再逐个到其余路径中匹配（朴素扫描 $O(S)$，即便预哈希也比较 $O(L)$）——总时间 $O(\text{minLen}^2 \cdot S)$。总长预算 $S = 10^5$ 全给两条路径时 $\text{minLen} = 5\times10^4$，候选子路径多达 $1.25\times10^9$ 个，**还没开始匹配就已经超时**。反过来把每条路径的所有子路径哈希后存表再求交，空间同样 $O(S \cdot \text{minLen})$ 级别，直接爆炸。

> ⚠️ 瓶颈诊断：子路径是**二维对象**（起点、长度），任何显式枚举都落在平方量级。出路是**先固定长度 $L$，把问题降成一维的定长判定**——每条路径的定长窗口只有 $O(\text{len})$ 个；再用单调性把长度维压成对数。这也是 $m=2$ 时经典 DP（[718. 最长重复子数组](https://leetcode.cn/problems/maximum-length-of-repeated-subarray/)，$O(\text{len}_1 \cdot \text{len}_2)$）在本题失效的原因：$S = 10^5$ 时二维表可达 $2.5\times10^9$ 格。

### 3.2 核心观察：定长判定 + 单调性 ⇒ 二分答案

![核心观察：定长判定与可行性单调](images/wc248_q4_monotone_binary_concept.svg)

**观察一（定长判定 = 集合求交）**。固定长度 $L$ 后，每条路径只有 $\text{len}_i - L + 1$ 个定长窗口。在**内容层面**：

$$\text{存在长度 } L \text{ 的公共子路径} \iff S_1 \cap S_2 \cap \cdots \cap S_m \ne \emptyset$$

其中 $S_i$ 是第 $i$ 条路径全部长度 $L$ 窗口构成的集合。「$m$ 条路径的公共」被拆解为**沿路径逐条求交**——无需同时处理 $m$ 条，交集一旦变空立即出局。

**观察二（可行性单调）**。若长度 $L$ 的公共子路径存在，则长度 $L-1$ 的也存在——每条路径截取该子路径的前 $L-1$ 个城市即可。于是可行长度构成前缀区间 $[0, L^*]$，**二分找右端点**，上界取 $\text{minLen}$（公共子路径不可能长过任何一条路径）。

**观察三（滚动哈希）**。窗口右移一格，多项式哈希 $O(1)$ 更新（见 3.3），于是单次 `check(L)` 以 $O(S)$ 完成。

三件套拼起来：二分 $O(\log \text{minLen})$ 轮，每轮 `check` $O(S)$，总计 $O(S \log \text{minLen}) \approx 10^5 \times 17$，稳稳落地。

### 3.3 算法流程：随机双哈希 + 滚动滑窗 + 逐路径求交

![算法流程：滚动哈希滑窗与集合求交](images/wc248_q4_rolling_hash_flow.svg)

**多项式哈希**。对窗口 $a_i, a_{i+1}, \ldots, a_{i+L-1}$ 定义

$$h(i) \equiv \sum_{k=0}^{L-1} a_{i+k} \cdot B^{L-1-k} \pmod{M}$$

从窗口 $[i, i+L-1]$ 滑到 $[i+1, i+L]$，去头、移位、入尾三步 $O(1)$：

$$h(i+1) \equiv \big(h(i) - a_i \cdot B^{L-1}\big) \cdot B + a_{i+L} \pmod{M}$$

**check(L) 流程**：

1. 路径已按长度**升序**排序：最短路径最先建立候选集（集合最小），后续交集越交越小。
2. 对每条路径：$O(L)$ 建首窗口哈希，滑窗 $O(\text{len} - L)$ 枚举全部窗口指纹，存入集合 `cur`（**同一路径内的重复窗口自动去重**）。
3. `common ← common ∩ cur`；`common` 变空立即返回 `false`（提前剪枝）。
4. 全部路径通过后 `common` 非空，返回 `true`。

**双哈希 + 随机底数（本题的生死线）**。单组 $(B, M)$ 可被预先构造的数据定向碰撞——本题恰恰以「卡固定参数哈希」闻名，社区反复报告算法正确但固定参数单哈希 WA 的案例，官方标签也直接把 Hash Function / Rolling Hash 列入。纪律有两条：

- **双哈希**：两组独立参数 $(B_1, M_1)$、$(B_2, M_2)$（$M_1 = 10^9+7$、$M_2 = 10^9+9$）并行计算，指纹取**有序对** $(h_1, h_2)$；
- **随机底数**：$B_1, B_2$ 在 $[n+1, M-1]$ 内**每次运行随机抽取**。对抗构造必须针对固定的 $(B, M)$ 才能设计碰撞，随机化让预构造失去目标。

### 3.4 示例演算

![示例演算：二分轨迹与真实哈希值](images/wc248_q4_example_walkthrough.svg)

以示例 1 为例（演算图取固定 $B_1 = 100003$、$B_2 = 100019$ 便于手算；实战代码用随机底数），排序后 $\text{paths} = [[2,3,4],[0,1,2,3,4],[4,0,1,2,3]]$，$\text{minLen} = 3$。

**二分轨迹**：`(lo, hi) = (0, 3)` → `mid = 2`，`check(2) = true` → `lo = 2` → `mid = 3`，`check(3) = false` → `hi = 2` → 收敛，答案 **2**。

**check(3) 为何失败**：最短路径 $[2,3,4]$ 只有一个窗口，指纹 $(1499891,\ 7900603)$；路径 $[0,1,2,3,4]$ 的三个窗口指纹中含有它，交集保留；但路径 $[4,0,1,2,3]$ 的三个窗口指纹 $(2399757,\ 15201085)$、$(100005,\ 100021)$、$(799948,\ 4000312)$ 都不含它——交集变空，返回 `false`。

**check(2) 为何成功**：三条路径的窗口指纹逐层求交后保留 $(200009,\ 200041)$，正是 $h([2,3]) = 2B_1 + 3 = 2 \times 100003 + 3 = 200009$（$h_2 = 2B_2 + 3 = 200041$ 同理）——长度 $L=2$ 时哈希就是编码本身，模都还没介入。

**滑窗一步**：从 $h([2,3]) = 200009$ 右滑入 $4$：去头 $2 \cdot B_1 = 200006$，余 $3$；移位 $\times B_1$ 得 $300009$；入尾 $+4$ 得 $300013 = h([3,4])$ ✓。而 $h([2,3,4]) = 2B_1^2 + 3B_1 + 4 = 20001500031$，**模从长度 3 开始折叠**（$\bmod\ (10^9+7) = 1499891$）。

> 💡 一个有趣细节：$h([0,1,2]) = (100005,\ 100021) = h([1,2])$——前导零造成**跨长度**碰撞。但 `check(L)` 只在同长度窗口之间比较，跨长度碰撞不构成威胁。

## 4. 算法细节

1. **上界与排序**：二分上界取**最短**路径长度 `minLen`；按长度升序排序让最短路径先建集合，候选集从最小者起步，交集单调收缩。排序后 `L ≤ minLen ≤ 每条路径长度`，「路径比 $L$ 短」的分支成为纯防御，可不写。
2. **随机底数的抽取范围**：$B \in [n+1, M-1]$。下界 $B > n$ 保留「无模时编码单射」的直觉（长度 1 窗口的哈希就是城市号本身）；真正的防碰撞靠双模 + 随机，见 §5 推论 2。
3. **指纹编码**：Python 直接用元组 `(h1, h2)` 作集合键；C++ 拼成单个 `long long`：`h1 * MOD2 + h2`。单射性一行情即可证：若 $a_1 M_2 + b_1 = a_2 M_2 + b_2$ 且 $a_1, a_2 < M_1$、$b_1, b_2 < M_2$，则 $(a_1 - a_2) M_2 = b_2 - b_1$，右边的绝对值小于 $M_2$，只能两边为零。
4. **同一路径内去重**：交集法（`common & cur`）中 `cur` 是集合，天然按路径去重。若改用计数法（哈希 → 出现于几条路径），**必须**先在同一路径内去重（如「上次见于路径 `pi`」标记），否则同一子路径在同一条路径中出现 $k$ 次会被误当成 $k$ 条路径的贡献，直接误判 `true`。
5. **负数取模**：滑窗去头后 $h - a \cdot B^{L-1}$ 可为负，C++ `%` 向零取整，必须 `((x) % M + M) % M` 修正；Python `%` 恒非负可省。
6. **幂表预处理**：`pw[k] = B^k mod M` 只需算到 `minLen`（窗口去头用的最高次幂是 $B^{L-1}$，$L \le \text{minLen}$）。
7. **二分模板**：求**最大可行值**用上取整 `mid = (lo + hi + 1) / 2` 配 `lo = mid / hi = mid - 1`；若用下取整，`lo + 1 == hi` 且 `check` 为真时会原地踏步死循环。
8. **计数法替代**（可选）：一遍扫描全部路径，`unordered_map<指纹, {计数, 上次路径}>`，窗口指纹首次在路径 `pi` 出现时计数加一，结束后看是否存在计数 $= m$ 的指纹。省去交集重建，但哈希表常数更大、去重逻辑更易错，赛场求稳用交集法。

## 5. 正确性证明

**引理 1（可行性单调不增）**：若存在长度为 $L \ge 1$ 的公共子路径，则存在长度为 $L-1$ 的公共子路径。

**证明**：设 $w = (c_0, \ldots, c_{L-1})$ 在每条路径中作为连续段出现。取其前缀 $w' = (c_0, \ldots, c_{L-2})$。在每条路径中，$w$ 出现位置的**同一起点**处取长度 $L-1$ 的连续段即 $w'$，故 $w'$ 也是所有路径的公共子路径。∎

**引理 2（滑窗递推）**：固定 $(B, M)$，记 $h(i) \equiv \sum_{k=0}^{L-1} a_{i+k} B^{L-1-k} \pmod M$，则对 $0 \le i < \text{len} - L$ 有 $h(i+1) \equiv (h(i) - a_i B^{L-1}) B + a_{i+L} \pmod M$。

**证明**：$h(i) = a_i B^{L-1} + \sum_{k=1}^{L-1} a_{i+k} B^{L-1-k}$，去头后乘 $B$ 得 $\sum_{k=1}^{L-1} a_{i+k} B^{L-k} = \sum_{k'=0}^{L-2} a_{i+1+k'} B^{L-1-k'}$（换元 $k' = k-1$），加上 $a_{i+L}$ 即为 $h(i+1)$ 的展开式。各步均为模 $M$ 下的合法同余变形。∎

**引理 3（判定的方向性）**：
（1）若存在长度 $L$ 的公共子路径，则 `check(L)` 返回 `true`——**无条件成立，不依赖无碰撞**；
（2）若 `check(L)` 返回 `true`，且同一次 `check` 中内容互异的窗口指纹互不相同（无碰撞），则存在长度 $L$ 的公共子路径。

**证明**：（1）公共子路径 $w$ 在每条路径中作为某个长度 $L$ 窗口真实出现；哈希计算是确定性的，$w$ 的指纹 $v$ 必进入每条路径的 `cur` 集合，故 $v$ 始终在交集中，`common` 途中不可能变空，最终返回 `true`。（2）取交集中的一个指纹 $v$，每条路径中都有指纹为 $v$ 的窗口，由无碰撞假设这些窗口内容全部相同，记为 $w$；$w$ 是每条路径的连续段，即长度 $L$ 的公共子路径。∎

**定理（二分正确性）**：在无碰撞前提下，算法返回最长公共子路径长度 $L^*$。

**证明**：由引理 1，可行长度集 $F = \{L \in [0, \text{minLen}] : \text{长度 } L \text{ 公共子路径存在}\}$ 形如前缀 $[0, L^*]$（$L=0$ 视空子路径恒可行）。无碰撞时 `check` 与 $L \in F$ 等价（引理 3 双向）。二分不变量：每轮开始 $\text{lo} \le L^* \le \text{hi}$。初始 $\text{lo}=0 \le L^* \le \text{minLen}=\text{hi}$；若 `check(mid)` 为真则 $L^* \ge \text{mid}$，置 `lo = mid` 后不变量保持；若为假则 $L^* < \text{mid}$，置 `hi = mid - 1` 后仍保持。`mid = (lo+hi+1)/2 > lo` 保证区间严格缩小、循环终止；终止时 `lo = hi`，夹逼出 $L^*$。∎

**推论 1（错误单侧性）**：哈希碰撞只可能使答案**偏大**，不可能偏小。

**证明**：引理 3（1）无条件成立，即 `check` **没有假阴性**：凡 $\text{mid} \le L^*$ 必返回真，`hi` 的下修只发生在 $\text{mid} > L^*$ 时，故任意时刻 $\text{hi} \ge L^*$，最终答案 $\ge L^*$ 恒成立。答案超过 $L^*$ 当且仅当某个 $\text{mid} > L^*$ 的 `check` 发生**假阳性**（碰撞）。∎

**推论 2（随机底数的单对碰撞概率）**：$M$ 为素数，$B$ 在 $[n+1, M-1]$ 均匀随机时，对任意两个内容不同的长度 $L$ 窗口 $s \ne t$，$\Pr[h_B(s) = h_B(t)] \le \frac{L-1}{M-1-n}$。

**证明**：$h_B(s) - h_B(t) \equiv D(B) \pmod M$，其中 $D(x) = \sum_k (s_k - t_k) x^{L-1-k}$。系数满足 $|s_k - t_k| < n < M$，故 $s \ne t$ 时 $D$ 是域 $\mathbb{F}_M$ 上次数 $\le L-1$ 的**非零**多项式，至多 $L-1$ 个根；$B$ 的 $M-1-n$ 个取值中至多 $L-1$ 个命中根。∎

双哈希的 $B_1, B_2$ 独立抽取，单对碰撞概率 $\le \frac{(L-1)^2}{(M_1-1-n)(M_2-1-n)}$，$L \le 10^5$、$M \approx 10^9$ 时不超过 $10^{-8}$（粗界）。诚实地说，把所有窗口对联合起来的最坏界并不够小，但「让大量窗口对同时逼近最坏情形」的构造高度依赖对底数与模数的先验知识——**随机底数使赛前预构造失效**，这正是「防卡」的实质；双哈希 + 随机底数是本题对抗数据下被反复实测验证的稳定纪律。若要求绝对确定的正确性，用后缀数组（见延伸思考）。

## 6. 复杂度分析

- **时间复杂度**：$O(S \log \text{minLen})$。二分至多 $\lfloor \log_2 10^5 \rfloor + 1 \approx 17$ 轮；每轮 `check` 中首窗口合计 $O(S)$、滑窗合计 $O(S)$ 次更新（双哈希每次 4 个模乘与若干加减），集合插入/查询期望 $O(1)$，单轮 $O(S)$。总计约 $3.4 \times 10^6$ 次模乘——实测最坏数据 Python 约 0.7 s、C++ 约 60 ms，余量充足。
- **空间复杂度**：$O(S)$。幂表 $O(\text{minLen})$；单条路径的窗口集合 $O(\text{len})$ 用完即弃，交集 `common` 不超过最短路径的窗口数。
- **对照**：暴力枚举 $O(\text{minLen}^2 \cdot S)$；$m=2$ 的二维 DP $O(\text{len}_1 \cdot \text{len}_2) \le 2.5\times10^9$；后缀数组 $O(S \log S)$、广义后缀自动机 $O(S)$（均见延伸思考）。

## 7. 参考代码

### C++（随机底数双哈希 + 逐路径交集）

```cpp
class Solution {
    typedef long long ll;
    static constexpr ll MOD1 = 1000000007, MOD2 = 1000000009;
    ll B1, B2;
    vector<ll> pow1, pow2;
    vector<vector<int>> paths;

    bool check(int L) {
        unordered_set<ll> common;
        for (int pi = 0; pi < (int)paths.size(); pi++) {
            auto& p = paths[pi];
            int len = (int)p.size();
            ll h1 = 0, h2 = 0;                       // 首窗口 [0, L-1]
            for (int i = 0; i < L; i++) {
                h1 = (h1 * B1 + p[i]) % MOD1;
                h2 = (h2 * B2 + p[i]) % MOD2;
            }
            unordered_set<ll> cur;
            cur.reserve(len - L + 1);
            cur.insert(h1 * MOD2 + h2);              // 双哈希拼成单个 long long
            for (int i = L; i < len; i++) {          // 滑窗：去头、移位、入尾
                h1 = ((h1 - (ll)p[i - L] * pow1[L - 1]) % MOD1 + MOD1) % MOD1;
                h1 = (h1 * B1 + p[i]) % MOD1;
                h2 = ((h2 - (ll)p[i - L] * pow2[L - 1]) % MOD2 + MOD2) % MOD2;
                h2 = (h2 * B2 + p[i]) % MOD2;
                cur.insert(h1 * MOD2 + h2);          // 集合天然按路径去重
            }
            if (pi == 0) {
                common = move(cur);
            } else {
                unordered_set<ll> nxt;
                for (ll k : cur)
                    if (common.count(k)) nxt.insert(k);
                common = move(nxt);
            }
            if (common.empty()) return false;        // 交集已空：提前出局
        }
        return true;
    }

public:
    int longestCommonSubpath(int n, vector<vector<int>>& paths_) {
        sort(paths_.begin(), paths_.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a.size() < b.size();          // 最短路径在前
             });
        paths = move(paths_);
        int minLen = (int)paths[0].size();
        if (minLen == 0) return 0;

        mt19937_64 rng(chrono::steady_clock::now().time_since_epoch().count());
        B1 = uniform_int_distribution<ll>(n + 1, MOD1 - 1)(rng);   // 随机底数
        B2 = uniform_int_distribution<ll>(n + 1, MOD2 - 1)(rng);   // 防对抗数据

        pow1.assign(minLen + 1, 1);
        pow2.assign(minLen + 1, 1);
        for (int i = 1; i <= minLen; i++) {
            pow1[i] = pow1[i - 1] * B1 % MOD1;
            pow2[i] = pow2[i - 1] * B2 % MOD2;
        }

        int lo = 0, hi = minLen;                     // 答案 ∈ [0, minLen]
        while (lo < hi) {                            // 上取整模板：求最大可行 L
            int mid = lo + (hi - lo + 1) / 2;
            if (check(mid)) lo = mid;
            else            hi = mid - 1;
        }
        return lo;
    }
};
```

### Python（同构：元组指纹 + `&` 求交）

```python
class Solution:
    def longestCommonSubpath(self, n: int, paths: List[List[int]]) -> int:
        import random
        MOD1, MOD2 = 1_000_000_007, 1_000_000_009
        B1 = random.randint(n + 1, MOD1 - 1)   # 随机底数：让对抗数据失去目标
        B2 = random.randint(n + 1, MOD2 - 1)

        paths.sort(key=len)                    # 最短路径在前：候选集最小
        min_len = len(paths[0])

        pow1 = [1] * (min_len + 1)             # 预处理 B^k，k ≤ minLen
        pow2 = [1] * (min_len + 1)
        for i in range(1, min_len + 1):
            pow1[i] = pow1[i - 1] * B1 % MOD1
            pow2[i] = pow2[i - 1] * B2 % MOD2

        def check(L: int) -> bool:
            common = None
            for p in paths:
                m = len(p)
                h1 = h2 = 0                    # 首窗口 [0, L-1]
                for i in range(L):
                    h1 = (h1 * B1 + p[i]) % MOD1
                    h2 = (h2 * B2 + p[i]) % MOD2
                cur = {(h1, h2)}
                for i in range(L, m):          # 滑窗：去头、移位、入尾
                    h1 = ((h1 - p[i - L] * pow1[L - 1]) % MOD1 + MOD1) % MOD1
                    h1 = (h1 * B1 + p[i]) % MOD1
                    h2 = ((h2 - p[i - L] * pow2[L - 1]) % MOD2 + MOD2) % MOD2
                    h2 = (h2 * B2 + p[i]) % MOD2
                    cur.add((h1, h2))          # 同一路径内重复窗口自动去重
                common = cur if common is None else common & cur
                if not common:                 # 交集已空：提前出局
                    return False
            return True

        lo, hi = 0, min_len                    # 答案 ∈ [0, minLen]
        while lo < hi:                         # 上取整模板：求最大可行 L
            mid = (lo + hi + 1) // 2
            if check(mid):
                lo = mid
            else:
                hi = mid - 1
        return lo
```

> 💡 两版为同构实现：C++ 把指纹对拼成 `h1 * MOD2 + h2`（单射、$< 10^{18}$）塞进 `unordered_set<long long>`；Python 直接用元组。实测均通过官方样例、自制边界（前导零、贴上界、全不交）与 3000 组随机小规模对拍。

## 8. 边界情况与易错点

1. **单哈希被对抗数据卡 WA（本题头号暗礁）**：算法完全正确也可能错——本题测试数据针对固定参数单哈希有对抗记录。**双哈希 + 随机底数**是入场券；且由推论 1，哈希出错的方向只会是**答案偏大**，看到「答案比预期大」先怀疑碰撞。
2. **计数法的同路径去重**：若不用交集法而用「指纹 → 覆盖路径数」计数，同一路径中重复出现的子路径会被重复计数，把「$k$ 次出现」误当「$k$ 条路径」，直接假阳性。交集法的集合语义天然免疫。
3. **负数取模**：滑窗去头 $h - a \cdot B^{L-1}$ 可为负，C++ `%` 向零截断，漏掉 `+M` 修正得到负哈希，集合行为全乱；Python 原生非负。
4. **三处乘法溢出审计**（C++ `long long` 全程安全）：指纹拼接 $h_1 \cdot M_2 + h_2 < 10^{18}$；滑窗乘 $h \cdot B \le 10^9 \times 10^9 = 10^{18}$；去头乘 $a \cdot B^{L-1} \le 10^5 \times 10^9 = 10^{14}$。三处都 $< 2^{63}-1 \approx 9.2 \times 10^{18}$，但任何一处换成 `int` 即爆。
5. **二分死循环**：求最大可行值必须 `mid = (lo + hi + 1) / 2` 上取整；下取整在 `lo + 1 == hi` 且 `check` 为真时永远 `lo = lo`。
6. **上界取最短路径**：`hi = minLen`（排序后 `paths[0]` 的长度），不是最长路径也不是平均值；「路径比 $L$ 短」的防御分支在正确上界下不会触发。
7. **前导零的跨长度碰撞**：$h([0,1,2]) = h([1,2])$ 这类现象真实存在，但 `check(L)` 只在同长度窗口间比较，无需处理；若把不同长度的哈希混入同一集合（如做「任意长度公共子串」），必须把长度编入指纹。
8. **$m = 2$ 的退化即 718**：别顺手写 $O(\text{len}_1 \cdot \text{len}_2)$ 的 DP——本题 $S = 10^5$ 时达 $2.5 \times 10^9$；二分 + 哈希对一切 $m$ 统一成立。
9. **返回 0 的天然覆盖**：完全无公共子路径（示例 2）时所有 `check` 为假、`hi` 一路降到 0；连「某条路径为空」也由 `lo = 0` 初值兜底，无需特判。

**延伸思考**：

- **后缀数组路线（确定性解）**：把 $m$ 条路径用**互不相同**的分隔哨兵（值取 $n \sim n+m-2$，不在城市值域中）拼成一条长 $O(S)$ 的串，建后缀数组与 `height` 表；在排好序的后缀序列上双指针维护「覆盖全部 $m$ 条路径」的最短窗口，答案为窗口内 `height` 的最小值的最大值。分隔哨兵全不相同保证任何跨哨兵的子串全串唯一、不可能成为公共子路径。$O(S \log S)$ 且零碰撞风险——概率正确与确定性正确的取舍。
- **广义后缀自动机**：依次插入 $m$ 条路径，对每个状态维护「被多少条路径覆盖」，答案是覆盖数为 $m$ 的状态中 `len` 的最大值，$O(S)$，理论最优但实现重。
- **假阳性的代价结构**：推论 1 说明碰撞只把答案推高——如果题目改为判定「是否存在长度 $\ge k$ 的公共子路径」（判定题），单侧错误同样成立，可用「双倍模数 + 交换验证」把 Monte Carlo 升级为 Las Vegas（对 check 出的候选指纹回表验真）。
- **在线版**：路径逐条到达、随时询问当前公共子路径长度——二分结构不依赖全量数据即可对新增路径做交，但最短路径变化时上界收缩需重跑，后缀结构则需增量维护，两者代价截然不同。
