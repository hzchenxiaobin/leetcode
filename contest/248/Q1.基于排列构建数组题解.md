# LeetCode 基于排列构建数组 题解

## 1. 题目概述

- **标题 / 题号**：基于排列构建数组（#1920，easy）
- **链接**：https://leetcode.cn/problems/build-array-from-permutation/
- **来源**：LeetCode 第 248 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、原地哈希、数学

**题意**：给定一个从 $0$ 开始的**排列** `nums`（$[0, n-1]$ 中每个整数恰好出现一次），构造同样长度为 $n$ 的数组 `ans`，满足对每个 $0 \le i < n$：

$$\text{ans}[i] = \text{nums}[\text{nums}[i]]$$

即「**先取值、再把值当下标取一次值**」的两跳读取。返回 `ans`。

**约束**：

- $1 \le n \le 1000$
- $0 \le \text{nums}[i] < n$
- `nums` 中元素互不相同（是排列）

**进阶**：你能在不使用额外空间的情况下解决此问题吗（即 $O(1)$ 内存）？

> 💡 本题在本仓库另有[每日题解 1920](../../solution/1901-2000/1920_基于排列构建数组.md)：侧重「一格存两值」技巧向 289 / 448 / 442 / 41 的原地哈希家族推广与面试问答。本篇按周赛复盘视角，聚焦签到题从题面到 AC 的最短路径——「值即下标」的双重身份与进阶原地编码，并补齐引理-定理化的正确性证明与赛场易错清单，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路

「暴力」在时间上已是最优：新建数组 `ans`，一趟循环把定义**逐字翻译**成代码——`ans[i] = nums[nums[i]]`，时间 $O(n)$、额外空间 $O(n)$，$n \le 1000$ 下瞬间 AC。签到题的分差不在复杂度，而在两点：一是**秒看出「排列 ⇒ 值即合法下标」**，不要被两层嵌套的 `nums[]` 唬住；二是题面挂着**进阶：$O(1)$ 额外空间**——比赛中先交朴素版锁分，大局已定再回头做原地优化。朴素的「另开新数组」在空间上差一口气：计算 `ans[i]` 要读 `nums[nums[i]]`，而一旦原地改写 `nums[i]`，存在里面的原值（可能被别的位置当**下标**引用）就丢了——这正是进阶的难点：如何在不丢失原值的前提下原地完成。

### 3.2 核心观察：值即下标，两跳读取

![核心观察：值即下标的两跳读取](images/wc248_q1_double_index_concept.svg)

**观察一（值即下标）**。`nums` 是 $[0, n-1]$ 的排列，因此每个值 $\text{nums}[i]$ 本身就是**合法下标**——`nums[nums[i]]` 永不越界，「读值」与「寻址」可以无缝串联。$\text{ans}[i] = \text{nums}[\text{nums}[i]]$ 就是「**跟着值走两跳**」：第一跳取出 $a = \text{nums}[i]$，第二跳取 $\text{nums}[a]$。

**观察二（值 $< n$ ⇒ 一格可存两值）**。排列还保证所有值严格小于 $n$，于是一个格子可以同时容纳「原值 $a$」与「目标值 $b$」两个小于 $n$ 的数——编码成 $a + n \times b$：`% n` 取回低位 $a$（原值），`// n` 取出高位 $b$（答案）。这正是进阶 $O(1)$ 空间的钥匙：原地改写 `nums[i]` 之前，把两份信息都保存在格子里，信息零丢失。

**观察三（答案仍是排列，可自检）**。`ans[i] = nums[nums[i]]` 是排列与自身的**复合映射**，而 $[0, n-1]$ 上的双射与双射的复合仍是双射——`ans` 必然也是 $[0, n-1]$ 的排列。交前扫一眼「元素互不相同、值域合法」即可排除索引类笔误。

> 💡 **一句话总结**：排列 ⇒ 值即下标，`nums[nums[i]]` 两跳直取；朴素版一趟 $O(n)$ 空间直接 AC，进阶用 $a + n \cdot b$ 编码把空间压到 $O(1)$。

### 3.3 算法流程

![算法流程：朴素版与原地编码两趟版](images/wc248_q1_algorithm_flow.svg)

**朴素版（赛场最短路径）**：

1. 新建长度 $n$ 的数组 `ans`。
2. $i$ 从 $0$ 到 $n-1$：`ans[i] = nums[nums[i]]`。
3. 返回 `ans`。

**原地编码版（进阶，$O(1)$ 额外空间）**：

1. **第一趟 · 编码**（$i$ 从 $0$ 到 $n-1$）：$b \leftarrow \text{nums}[\text{nums}[i]] \bmod n$，再 $\text{nums}[i] \mathrel{+}= n \times b$。
2. **第二趟 · 解码**（$i$ 从 $0$ 到 $n-1$）：$\text{nums}[i] \leftarrow \text{nums}[i] / n$（整除）。
3. 返回 `nums`。

两趟**严格分离**：必须先全部编码完毕，再统一解码——一旦某格被 `// n` 改写成 $b$，「`% n` 取原值」的不变式即被破坏（见 §5 引理 3 与引理 4）。

### 3.4 示例演算

![示例演算：原地编码与解码全过程](images/wc248_q1_walkthrough.svg)

以示例 1 `nums = [0,2,1,5,3,4]`（$n = 6$）演算原地版全过程：

| $i$ | 两跳 $\text{nums}[\text{nums}[i]]$ | 编码 $a + 6 \cdot b$ | 解码 $\div 6$ |
|-----|-----------------------------------|----------------------|---------------|
| 0 | $\text{nums}[0] = 0$（自映射） | $0 + 6 \times 0 = 0$ | 0 |
| 1 | $\text{nums}[2] = 1$ | $2 + 6 \times 1 = 8$ | 1 |
| 2 | $\text{nums}[1] \bmod 6 = 8 \bmod 6 = 2$（**已编码，取模还原**） | $1 + 6 \times 2 = 13$ | 2 |
| 3 | $\text{nums}[5] = 4$ | $5 + 6 \times 4 = 29$ | 4 |
| 4 | $\text{nums}[3] \bmod 6 = 29 \bmod 6 = 5$（已编码） | $3 + 6 \times 5 = 33$ | 5 |
| 5 | $\text{nums}[4] \bmod 6 = 33 \bmod 6 = 3$（已编码） | $4 + 6 \times 3 = 22$ | 3 |

- **编码后数组**：`[0, 8, 13, 29, 33, 22]`——每格恰为 $a + 6b$，低位存原值、高位藏答案；
- **第二趟整除 6**：`[0, 1, 2, 4, 5, 3]`，与官方输出一致 ✓。

> 💡 **观察要点**：① 从 $i=2$ 起 `nums[nums[i]]` 开始命中**已编码**的格子（如 $\text{nums}[1]=8$），$8 \bmod 6 = 2$ 完美还原原值——不变式全程成立；② 自映射位置 $i=0$ 编码后仍为 $0$，是 $a=b=0$ 的退化情形，**零特判**；③ 全程只有常数个临时变量，无任何辅助数组。

## 4. 算法细节

1. **先交朴素版锁分**：签到题的赛场节奏是「读题 → 一行循环 → 提交」，朴素版 30 秒内可 AC；进阶原地版等四题大局已定再回头打磨，避免在 Q1 上过度投入。
2. **Python 一行流**：`return [nums[x] for x in nums]`——循环变量 $x$ 直接取遍 `nums` 的值（即第一跳），`nums[x]` 即第二跳，与定义严格对应，最短且 Pythonic。
3. **原地版读序**：`nums[i] += n * (nums[nums[i]] % n)` 中右值必须**先整体求值**——`nums[nums[i]]` 的下标用的是**尚未改写的原值** $\text{nums}[i]$。切勿先更新 `nums[i]` 再去读 `nums[nums[i]]`，那样下标已被高位污染。
4. **`% n` 的统一性**：无论格子**尚未编码**（值 $< n$，取模不变）还是**已编码**（$a + nb \bmod n = a$），`nums[j] % n` 都等于原值。因此第一趟读 `nums[nums[i]] % n` 无需区分两种状态，一个取模统一天下。
5. **溢出检查**：编码值最大 $(n-1) + n(n-1) = n^2 - 1 \le 10^6 - 1$，`int` 绰绰有余；若 $n$ 放宽到 $10^5$（$n^2 = 10^{10}$），C++ 需换 `long long`，Python 整数任意精度无此虑。
6. **原地版修改入参**：LeetCode 判题不复用入参，可放心原地；工程代码需确认调用方是否依赖 `nums` 保持不变。

## 5. 正确性证明

**引理 1（值即合法下标）**：对一切 $0 \le i < n$，$\text{nums}[i] \in [0, n-1]$ 是合法下标，`nums[nums[i]]` 不越界。

**证明**：`nums` 是 $[0, n-1]$ 的排列，元素互不相同且值域恰为 $[0, n-1]$，故 $\text{nums}[i]$ 可直接作下标访问。∎

**引理 2（朴素版正确）**：朴素版执行后，对一切 $i$ 有 $\text{ans}[i] = \text{原 nums}[\text{原 nums}[i]]$。

**证明**：循环体唯一语句即该等式；朴素版不修改 `nums`，每轮读取的均为原值，且每个下标恰被赋值一次，无覆盖。∎

**引理 3（编码不变式）**：第一趟扫描中的任意时刻，对已改写位置 $j$ 有 $\text{nums}[j] = a_j + n b_j$（$a_j$ 为原值、$b_j$ 为其目标值，均 $< n$），对未改写位置 $j$ 有 $\text{nums}[j] = a_j < n$；两种情形统一满足 $\text{nums}[j] \bmod n = a_j$（原值）。

**证明**：对已完成的改写次数归纳。初始时所有位置值 $< n$，不变式成立。设改写位置 $j$ 时其原值为 $a_j$，读得 $b_j = \text{nums}[a_j] \bmod n$；由归纳假设（无论位置 $a_j$ 是否已改写），$\text{nums}[a_j] \bmod n$ 恰为位置 $a_j$ 的**原值**，故 $b_j$ 与「从原数组读 $\text{原 nums}[a_j]$」一致。写入 $a_j + n b_j$ 后，因 $a_j, b_j < n$ 有 $(a_j + n b_j) \bmod n = a_j$，不变式对位置 $j$ 保持。∎

**引理 4（解码正确）**：第一趟结束后，对一切 $i$ 有 $\text{nums}[i] = a_i + n b_i$ 且 $b_i = \text{原 nums}[\text{原 nums}[i]]$；第二趟整除后 $\text{nums}[i] = b_i$。

**证明**：由引理 3，第一趟写下的 $\text{nums}[i] = a_i + n b_i$，其中 $a_i$ 为位置 $i$ 原值、$b_i$ 为以**原值** $a_i$ 寻址读得的原值，即 $b_i = \text{原 nums}[\text{原 nums}[i]]$。由 $0 \le a_i, b_i < n$，$a_i + n b_i$ 的 $n$ 进制表示唯一，整除 $n$ 恰取出高位 $b_i$。∎

**定理**：原地版两趟扫描后返回的 `nums` 满足 $\text{nums}[i] = \text{原 nums}[\text{原 nums}[i]]$ 对一切 $i$ 成立，且仅用 $O(1)$ 额外空间。

**证明**：由引理 4，第二趟后 $\text{nums}[i] = b_i = \text{原 nums}[\text{原 nums}[i]]$，与题目定义逐下标一致。全程仅用 $i, n, a, b$ 等常数个临时变量。∎

**推论（答案仍是排列）**：返回的 `ans` 是 $[0, n-1]$ 的排列。

**证明**：$\sigma(i) = \text{nums}[i]$ 是 $[0, n-1]$ 上的双射，$\text{ans} = \sigma \circ \sigma$ 是双射的复合，仍为双射，故 `ans` 取遍 $[0, n-1]$ 且元素互不相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。朴素版一趟、原地版两趟，每元素常数次运算（取值、取模、乘加、整除）；$n \le 1000$ 远在时限内。
- **空间复杂度**：朴素版 $O(n)$——输出数组本身（按惯例不计输出则为 $O(1)$ 额外）；原地版 $O(1)$ **额外空间**——答案直接写在 `nums` 上，仅常数个临时变量。

## 7. 参考代码

### C++（朴素版，赛场首选）

```cpp
class Solution {
public:
    vector<int> buildArray(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n);
        for (int i = 0; i < n; i++) {
            ans[i] = nums[nums[i]];    // 两跳：先取值，再当下标
        }
        return ans;
    }
};
```

### C++（原地编码，O(1) 额外空间）

```cpp
class Solution {
public:
    vector<int> buildArray(vector<int>& nums) {
        int n = nums.size();
        for (int i = 0; i < n; i++) {
            nums[i] += n * (nums[nums[i]] % n);   // 编码：低位原值 + 高位答案
        }
        for (int i = 0; i < n; i++) {
            nums[i] /= n;                          // 解码：整除取出高位
        }
        return nums;
    }
};
```

### Python（朴素版，一行流）

```python
class Solution:
    def buildArray(self, nums: list[int]) -> list[int]:
        return [nums[x] for x in nums]
```

### Python（原地编码，O(1) 额外空间）

```python
class Solution:
    def buildArray(self, nums: list[int]) -> list[int]:
        n = len(nums)
        for i in range(n):
            nums[i] += n * (nums[nums[i]] % n)
        for i in range(n):
            nums[i] //= n
        return nums
```

> 💡 **写法对照**：朴素版与定义逐字对应，签到首选；Python 一行流把「第一跳」隐式交给循环变量，最短最快；原地编码版把空间压到 $O(1)$，作为进阶追问的应答。三版时间同为 $O(n)$。

## 8. 边界情况与易错点

1. **$n = 1$ 边界**：`nums = [0]`，自映射 $\text{ans}[0] = \text{nums}[\text{nums}[0]] = 0$，统一公式天然覆盖，**无需特判**。
2. **原地版忘写 `% n`**：直接读 `nums[nums[i]]` 会命中已编码格子（值 $\ge n$）——轻则取错值，重则**下标越界**。`% n` 是还原原值的唯一钥匙。
3. **原地版读序错误**：先改 `nums[i]` 再读 `nums[nums[i]]`，下标被高位污染。C++ 复合赋值 `+=` 的右值先整体求值，天然安全；若拆成多条语句需手动保序。
4. **两趟合并成一趟**：`// n` 解码后该格原值即丢失，后续任何以它为下标的读取全错。编码与解码必须**阶段分离**，不可边编边解。
5. **溢出**：$n \le 1000$ 时编码值 $\le n^2 - 1 \approx 10^6$，`int` 安全；$n$ 放宽到 $10^5$ 才需 `long long`（Python 无此虑）。
6. **误以为必须返回新数组**：题目只要求返回结果数组，原地改写 `nums` 后返回它即可；LeetCode 不检查入参是否被改。
7. **自检**：正确答案必是 $[0, n-1]$ 的排列（双射的复合仍是双射）——元素互异、值域合法，交前扫一眼可排除索引类笔误。
