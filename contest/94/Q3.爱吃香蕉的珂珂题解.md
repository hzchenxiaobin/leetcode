# LeetCode 爱吃香蕉的珂珂 题解

## 1. 题目概述

- **标题 / 题号**：爱吃香蕉的珂珂（#875，medium）
- **链接**：https://leetcode.cn/problems/koko-eating-bananas/
- **来源**：LeetCode 第 94 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找

**题意**：有 $n$ 堆香蕉，第 $i$ 堆有 `piles[i]` 根。珂珂每小时选定一个速度 $k$（根/小时），然后**每个小时只吃一堆**：吃掉这堆中的 $k$ 根；如果这堆不足 $k$ 根，就吃完它并在这一小时内**不再吃别的堆**。警卫将在 $h$ 小时后回来，要求珂珂在 $h$ 小时内吃完所有香蕉，求**最小**的整数速度 $k$。

**关键点**：

- 每堆单独计时，吃一堆耗时 $\lceil piles[i] / k \rceil$ 小时（向上取整）。
- 总耗时 $T(k) = \sum_i \lceil piles[i]/k \rceil$，要求 $T(k) \le h$，求最小 $k$。

**约束**：

- $1 \le n \le 10^4$
- $n \le h \le 10^9$
- $1 \le piles[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：piles = [3,6,7,11], h = 8
输出：4
解释：k=4 时各堆耗时为 1, 2, 2, 3，合计 8 ≤ 8；
     k=3 时各堆耗时为 1, 2, 3, 4，合计 10 > 8，不可行。
```

**示例 2**

```text
输入：piles = [30,11,23,4,20], h = 5
输出：30
解释：h 等于堆数，每小时必须吃完且只吃一堆，所以 k 至少要等于最大堆 30。
```

**示例 3**

```text
输入：piles = [30,11,23,4,20], h = 6
输出：23
解释：k=23 时耗时为 2,1,1,1,1，合计 6 ≤ 6；k=22 时耗时为 2,1,2,1,1，合计 7 > 6。
```

## 3. 解题思路

### 3.1 暴力思路

从 $k = 1$ 开始逐个尝试，对每个 $k$ 计算 $T(k)$，第一个满足 $T(k) \le h$ 的 $k$ 就是答案。单次判定 $O(n)$，$k$ 最大可到 $10^9$，总复杂度 $O(n \cdot \max(piles))$，最坏 $10^{13}$，必然超时。

### 3.2 核心观察：可行性关于 $k$ 单调

![单调性：k 越大越省时间，可行集合是 [k*, ∞)](images/wc94_q3_monotonic.svg)

把「$k$ 是否可行」看成一个判定问题：

$$f(k) = \left[\,T(k) \le h\,\right], \qquad T(k) = \sum_{i=1}^{n}\left\lceil \frac{piles[i]}{k} \right\rceil$$

**单调性**：若 $k_1 \le k_2$，则对每一堆有 $\lceil p_i/k_1 \rceil \ge \lceil p_i/k_2 \rceil$，求和得 $T(k_1) \ge T(k_2)$。因此「可行」的 $k$ 构成一个**后缀** $[k^*, +\infty)$，$k^*$ 就是答案。单调性是二分的前提。

**上下界**：

- 下界 $lo = 1$：速度至少为 $1$。
- 上界 $hi = \max(piles)$：当 $k = \max(piles)$ 时，每堆至多 1 小时，总耗时 $= n \le h$，一定可行。所以答案不会超过最大堆。

**判定函数**：`hours(k) = sum((p + k - 1) // k for p in piles)`。注意累加要用 `long long`：$n \le 10^4$、单堆耗时可达 $10^9$，总和可达 $10^{13}$。

### 3.3 算法流程

```text
1. lo = 1，hi = max(piles)
2. while lo < hi：
   2.1 mid = lo + (hi - lo) // 2
   2.2 若 hours(mid) <= h：hi = mid      // 可行，尝试更小
   2.3 否则：lo = mid + 1                // 不可行，必须更大
3. 返回 lo
```

这是标准的「**求最小可行值**」二分模板：判定为真时收缩右界并**保留** `mid`，判定为假时左界跳到 `mid + 1`。循环结束时 `lo == hi` 且恰为最小的可行值。

### 3.4 示例演算

![二分区间的收缩过程](images/wc94_q3_binary_search.svg)

对示例 1（`piles = [3,6,7,11]`，$h = 8$）：

| 轮次 | `lo, hi` | `mid` | 各堆耗时 | 总耗时 | 与 $8$ 比较 | 动作 |
|------|---------|-------|---------|--------|------------|------|
| 1 | 1, 11 | 6 | 1, 1, 2, 2 | 6 | $6 \le 8$ ✓ | `hi = 6` |
| 2 | 1, 6 | 3 | 1, 2, 3, 4 | 10 | $10 > 8$ ✗ | `lo = 4` |
| 3 | 4, 6 | 5 | 1, 2, 2, 3 | 8 | $8 \le 8$ ✓ | `hi = 5` |
| 4 | 4, 5 | 4 | 1, 2, 2, 3 | 8 | $8 \le 8$ ✓ | `hi = 4` |

此时 `lo == hi == 4`，返回 $4$。共 $4$ 轮，每轮 $O(n)$，总计 $O(n \log \max(piles))$。

## 4. 算法细节

1. **向上取整的写法**：`(p + k - 1) / k`（整数除法，向下取整）。对 $p, k \ge 1$ 该式恒等于 $\lceil p/k \rceil$，且不会溢出（$p + k - 1 \le 2\times10^9$，`int` 勉强够，但建议用 `long long`）。
2. **判定累加用 `long long`**：$T(k)$ 最大可达 $10^4 \times 10^9 = 10^{13}$，`int` 溢出会导致误判为可行，答案偏小。
3. **`mid` 写法**：`lo + (hi - lo) / 2` 避免 `lo + hi` 溢出（本题 $lo, hi \le 10^9$，`int` 加法也不会溢出，但保持好习惯）。
4. **为什么上界取 `max(piles)` 而不是 $10^9$**：$k = \max(piles)$ 时 $T = n \le h$ 必然可行，取更小的上界能减少约 $7$ 轮二分。
5. **不需要特判 $h \ge \sum piles$**：那种情况下 $k=1$ 就可行，二分自然收敛到 $1$。
6. **`n == h` 时答案必为 `max(piles)`**：因为每堆至少 1 小时、总时间刚好等于堆数，任何 $k < \max$ 都会让最大堆耗时 $\ge 2$，总时间超过 $h$。

## 5. 正确性证明

**引理 1（单调性）**：$T(k)$ 关于 $k$ 单调不增，即 $k_1 \le k_2 \Rightarrow T(k_1) \ge T(k_2)$。

**证明**：对任意 $p \ge 1$，$\lceil p/k \rceil$ 随 $k$ 增大而不增（$k$ 越大每份越少，所需份数越少）。逐项相加得 $T(k_1) = \sum \lceil p_i/k_1\rceil \ge \sum \lceil p_i/k_2\rceil = T(k_2)$。∎

**引理 2（二分不变式）**：循环过程中始终有：$hi$ 是可行速度，且 $[1, lo)$ 内不存在可行速度（即答案 $\ge lo$）。

**证明**：初始 $lo = 1$、$hi = \max(piles)$。$lo = 1$ 时空区间 $[1,1)$ 内无元素，条件空真；$hi$ 可行由 $T(\max) = n \le h$ 保证。设当前不变式成立，取 $mid \in [lo, hi)$：

- 若 $T(mid) \le h$：$mid$ 可行，令 $hi \leftarrow mid$。新区间 $[1, lo)$ 未变，且新 $hi$ 可行，不变式保持。
- 若 $T(mid) > h$：由引理 1，所有 $k \le mid$ 都满足 $T(k) \ge T(mid) > h$，即 $[1, mid]$ 内无可行速度。令 $lo \leftarrow mid + 1$，新区间 $[1, mid+1)$ 内无可行速度，且 $hi$ 未变仍可行，不变式保持。∎

**定理**：循环结束时返回的 $lo$ 是最小可行速度。

**证明**：循环在 $lo = hi$ 时结束。由引理 2，$hi$ 可行，故 $lo$ 可行；又由引理 2，$[1, lo)$ 内无可行速度，故 $lo$ 是可行速度中的最小值。∎

## 6. 复杂度分析

- **时间**：$O(n \log M)$，其中 $M = \max(piles) \le 10^9$，二分约 $\lceil \log_2 M \rceil \le 30$ 轮，每轮判定 $O(n)$，总计约 $3 \times 10^5$ 次运算。
- **空间**：$O(1)$。只用了常数个变量（不计输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minEatingSpeed(vector<int>& piles, int h) {
        int lo = 1, hi = *max_element(piles.begin(), piles.end());
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            long long hours = 0;
            for (int p : piles) hours += (p + mid - 1) / mid;
            if (hours <= h) hi = mid;      // 可行：尝试更小的速度
            else lo = mid + 1;             // 不可行：必须提速
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def minEatingSpeed(self, piles: list[int], h: int) -> int:
        lo, hi = 1, max(piles)
        while lo < hi:
            mid = (lo + hi) // 2
            if sum((p + mid - 1) // mid for p in piles) <= h:
                hi = mid            # 可行，收缩右界
            else:
                lo = mid + 1        # 不可行，必须更大
        return lo
```

## 8. 边界情况与易错点

1. **`n == h`**：答案就是 `max(piles)`。若上界取 `max(piles) - 1`，会漏掉这个唯一可行解。
2. **向上取整写成 `p / k`**：整数除法向下取整，会把 $7/4$ 算成 $1$ 而不是 $2$，导致总耗时偏小、答案偏小。必须写 `(p + k - 1) / k`。
3. **总耗时用 `int` 累加**：$10^{13}$ 溢出后可能变成负数或小正数，判定误真。
4. **二分边界写错**：判定为真时必须 `hi = mid`（保留 mid），写成 `hi = mid - 1` 会丢掉答案；判定为假时 `lo = mid + 1`（不加 1 会死循环）。
5. **`k = 0`**：速度必须为正，下界从 $1$ 开始。若写 `lo = 0` 会除零。
6. **`h` 很大**：如 $h = 10^9$，$k=1$ 即可行，二分自然收敛到 $1$，无需特判。
7. **单堆**：$n = 1$ 时答案是 $\lceil piles[0]/h \rceil$，二分同样正确。
