# LeetCode 模拟行走机器人 题解

## 1. 题目概述

- **标题 / 题号**：模拟行走机器人（#874，medium）
- **链接**：https://leetcode.cn/problems/walking-robot-simulation/
- **来源**：LeetCode 第 94 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：机器人在无限大的 XY 网格上从原点 $(0,0)$ 出发，初始朝**北**（$+y$）。它依次执行命令 `commands`：

- `-2`：向左转 $90^\circ$
- `-1`：向右转 $90^\circ$
- $x \in [1, 9]$：沿当前方向前进 $x$ 个单位

网格上有些格子是障碍物 `obstacles[i] = (x_i, y_i)`。机器人**不能走到障碍物上**：一旦下一步会撞上障碍，它就**停在原地**、放弃这条命令剩下的步数，然后继续执行下一条命令。求机器人**曾经到达过的所有位置**中，离原点**欧式距离平方**的最大值。

**关键点**：

- 求的是「历史最远距离的平方」，**不是终点**的距离。机器人可能先走远再走回来。
- 撞墙后剩余步数作废，不会「绕过」障碍。
- 原点 $(0,0)$ 也可能有障碍物（但机器人从那里出发，不影响后续）。

**约束**：

- $1 \le commands.length \le 10^4$，每个命令是 $-2$、$-1$ 或 $[1,9]$ 内的整数
- $0 \le obstacles.length \le 10^4$，$-3\times 10^4 \le x_i, y_i \le 3\times 10^4$
- 答案保证小于 $2^{31}$

## 2. 示例

**示例 1**

```text
输入：commands = [4,-1,3], obstacles = []
输出：25
解释：向北 4 步到 (0,4)，右转向东，向东 3 步到 (3,4)。
     最远点 (3,4)，距离平方 3² + 4² = 25。
```

**示例 2**

```text
输入：commands = [4,-1,4,-2,4], obstacles = [[2,4]]
输出：65
解释：北 4 到 (0,4)；右转东，走 1 步到 (1,4) 时发现 (2,4) 是障碍，停下；
     左转北，走 4 步到 (1,8)。最远点 (1,8)，距离平方 1² + 8² = 65。
```

**示例 3**

```text
输入：commands = [6,-1,-1,6], obstacles = []
输出：36
解释：北 6 到 (0,6)；右转两次变成朝南，向南 6 步回到 (0,0)。
     虽然终点在原点，但途中到达过 (0,6)，所以答案是 36。
```

## 3. 解题思路

### 3.1 暴力思路

直接按定义模拟：每个前进命令 $x$，就循环 $x$ 次、每次走一格、判断下一格是否为障碍。判断障碍时如果**线性扫描** `obstacles` 数组，单次判断 $O(|obstacles|)$，总复杂度 $O(\sum commands \cdot |obstacles|)$，最坏 $10^4 \times 9 \times 10^4 \approx 9\times 10^9$，超时。

另一类错误做法是「一步到位」：直接算出终点再检查路径上有没有障碍。这样做要么漏检中间障碍（机器人本该停在障碍前），要么为了检查而退化成逐格扫描，得不偿失。

所以优化点只有一个：**把障碍物放进哈希集合**，单次查询 $O(1)$。

### 3.2 核心观察：方向数组 + 逐格前进 + 集合查障碍

![方向编码与单位位移表](images/wc94_q2_direction.svg)

**方向编码**：用 $d \in \{0,1,2,3\}$ 表示北、东、南、西，四个方向的单位位移为

$$(dx, dy) \in \{(0,1),\ (1,0),\ (0,-1),\ (-1,0)\}$$

转向就是模 $4$ 的加减：

- 右转：$d \leftarrow (d+1) \bmod 4$
- 左转：$d \leftarrow (d+3) \bmod 4$（等价于 $d-1$，用 $+3$ 避免 C++ 中负数取模的坑）

**为什么必须逐格走？** 因为障碍物可能出现在路径中间。逐格走时每步只判断「下一格是否被占」，撞上就 `break`，自然实现「停在障碍前一格、剩余步数作废」。

**为什么每步都要更新答案？** 因为要求的是历史最远点，而不是终点（示例 3 就是「回到原点但历史最远是 6」）。更新时机可以在每一步移动后，也可以像参考代码那样在每条移动命令结束后更新——后者同样正确，因为一条命令内机器人沿直线单调移动，距离平方沿路径是凸函数，端点处的值不小于中间值（严格说：沿射线 $t \mapsto x^2+y^2$ 是 $t$ 的凸二次函数，在区间端点取到最大值）。为稳妥起见，参考代码在命令结束时取最大值，这已覆盖所有可能的极值点。

### 3.3 算法流程

```text
1. blocked = set(obstacles)              // 哈希集合
2. d = 0（北），x = y = 0，ans = 0
3. for c in commands：
   3.1 c == -2：d = (d + 3) % 4          // 左转
   3.2 c == -1：d = (d + 1) % 4          // 右转
   3.3 否则：重复 c 次：
         nx = x + dx[d]，ny = y + dy[d]
         若 (nx, ny) 在 blocked 中：break    // 撞墙，剩余步数作废
         x = nx，y = ny
       更新 ans = max(ans, x*x + y*y)
4. 返回 ans
```

### 3.4 示例演算

对示例 2（`commands = [4,-1,4,-2,4]`，障碍 `[[2,4]]`）：

| 命令 | 动作 | 位置 | 方向 $d$ | 本次距离平方 | `ans` |
|------|------|------|---------|-------------|-------|
| 初始 | — | $(0,0)$ | 0 北 | 0 | 0 |
| 4 | 前进 4 | $(0,4)$ | 0 | 16 | 16 |
| −1 | 右转 | $(0,4)$ | 1 东 | — | 16 |
| 4 | 前进，第 1 步到 $(1,4)$，第 2 步撞 $(2,4)$ 停 | $(1,4)$ | 1 | 17 | 17 |
| −2 | 左转 | $(1,4)$ | 0 北 | — | 17 |
| 4 | 前进 4 | $(1,8)$ | 0 | 65 | **65** |

最终返回 $65$，与示例一致。注意第 3 条命令只走了 $1$ 步就停下，剩余 $3$ 步全部作废——不是「绕过障碍继续走」。

## 4. 算法细节

1. **障碍物集合的键**：C++ 用 `set<pair<int,int>>` 或把坐标编码成 `long long`（`(x+30000)*100000 + (y+30000)`）放进 `unordered_set`；Python 用 `set(map(tuple, obstacles))`。坐标范围 $[-3\times10^4, 3\times10^4]$，编码时注意偏移。
2. **左转写成 `(d+3)%4`**：C++ 的 `%` 对负数结果为负（如 `-1 % 4 == -1`），直接用 `d = (d-1) % 4` 会得到 $-1$ 这个非法方向。
3. **撞墙用 `break` 而非 `continue`**：撞墙意味着剩余步数全部作废，`break` 跳出内层步数循环。
4. **距离平方用 `long long`**：坐标可达 $3\times10^4 + 9\times10^4$ 量级，平方后约 $10^{10}$，`int` 会溢出——虽然题目保证答案 $< 2^{31}$，但中间计算仍建议用 `long long`（Python 无此问题）。
5. **不要预先把机器人当前位置标记为不可走**：起点若有障碍，机器人仍从那里出发，只是不能「再走进来」；参考代码不特殊处理，因为从内部走出的第一步就会检查下一格。
6. **每条移动命令结束后更新 `ans`**：也有人在每步更新，两者都正确；关键是别只在最后更新。

## 5. 正确性证明

**引理 1（位置模拟正确）**：算法的 `(x, y)` 始终等于机器人执行完已处理命令后的真实位置。

**证明**：对命令序列归纳。初始位置 $(0,0)$ 正确。设处理完前 $k$ 条命令后位置正确：

- 若第 $k+1$ 条是转向命令，位置不变，转向规则与题面一致，正确。
- 若第 $k+1$ 条是前进 $c$ 步，算法逐格推进：每步先算出候选 $(\hat x, \hat y)$，若被占则立即停止（位置保持），否则更新。这与题面「不能走到障碍物上，停在障碍物前一格并继续执行下一个命令」逐字对应。∎

**引理 2（历史最远点在命令边界处取到）**：设某条前进命令使机器人从 $P_0$ 沿方向 $u$（单位向量）走到 $P_t = P_0 + t\,u$（$0 \le t \le c$），则 $\lVert P_t \rVert^2$ 在 $t \in \{0, c'\}$ 处取到最大值，其中 $c'$ 是实际走过的步数。

**证明**：$\lVert P_0 + t u \rVert^2 = \lVert P_0 \rVert^2 + 2t\,(P_0 \cdot u) + t^2$ 是关于 $t$ 的开口向上的二次函数，在闭区间 $[0, c']$ 上的最大值必在端点处取到。∎

**定理**：算法返回的值等于机器人到达过的所有位置中 $\lVert \cdot \rVert^2$ 的最大值。

**证明**：由引理 1，算法访问的位置序列与真实轨迹一致（撞墙时提前停止的那部分位置也一致，因为被占的格子本来就不能到达）。由引理 2，每条命令内的最大值在命令结束（或撞墙停下）处取到，算法每条移动命令后更新 `ans`，因此覆盖了轨迹上的所有极值点；转向命令不改变位置，无需更新。故 `ans` 是所有到达位置的 $\lVert\cdot\rVert^2$ 的最大值。∎

## 6. 复杂度分析

- **时间**：$O(n + m + S)$。建障碍集合 $O(m)$；每条命令 $O(1)$（转向）或 $O(x)$（前进，$x \le 9$）；$S = \sum$ 前进步数 $\le 9 \times 10^4$。总计约 $10^5$ 次集合查询。
- **空间**：$O(m)$ 存障碍集合，其余 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int robotSim(vector<int>& commands, vector<vector<int>>& obstacles) {
        // 北、东、南、西
        const int dx[4] = {0, 1, 0, -1};
        const int dy[4] = {1, 0, -1, 0};
        set<pair<int, int>> blocked;
        for (auto& o : obstacles) blocked.insert({o[0], o[1]});
        long long x = 0, y = 0, best = 0;
        int d = 0;
        for (int c : commands) {
            if (c == -2) d = (d + 3) % 4;        // 左转
            else if (c == -1) d = (d + 1) % 4;   // 右转
            else {
                for (int s = 0; s < c; s++) {    // 逐步前进，撞上就停
                    int nx = x + dx[d], ny = y + dy[d];
                    if (blocked.count({nx, ny})) break;
                    x = nx; y = ny;
                }
                best = max(best, x * x + y * y);
            }
        }
        return (int)best;
    }
};
```

### Python

```python
class Solution:
    def robotSim(self, commands: list[int], obstacles: list[list[int]]) -> int:
        blocked = set(map(tuple, obstacles))
        dx = [0, 1, 0, -1]     # 北 东 南 西
        dy = [1, 0, -1, 0]
        d = 0
        x = y = 0
        ans = 0
        for c in commands:
            if c == -2:
                d = (d + 3) % 4        # 左转
            elif c == -1:
                d = (d + 1) % 4        # 右转
            else:
                for _ in range(c):
                    nx, ny = x + dx[d], y + dy[d]
                    if (nx, ny) in blocked:
                        break          # 撞墙：剩余步数作废
                    x, y = nx, ny
                ans = max(ans, x * x + y * y)
        return ans
```

## 8. 边界情况与易错点

1. **只记终点**：示例 3 会挂——机器人回到原点，终点距离为 $0$，但历史最远是 $36$。必须维护 `ans`。
2. **撞墙后 `continue` 而非 `break`**：会让机器人在原地「踏步」把剩余步数耗尽，行为上等价，但如果写成「跳过障碍继续走」就完全错了。
3. **左转用 `(d-1)%4`**：C++ 中得到 $-1$，访问 `dx[-1]` 是未定义行为。必须写 `(d+3)%4`。
4. **障碍查询用 `set`**：`obstacles` 可能有 $10^4$ 个，逐格线性扫描会超时。
5. **一步跨多格**：直接 `x += c*dx[d]` 会跨过路径上的障碍，得到错误位置。
6. **`int` 溢出**：坐标 $+$ 步数最大约 $1.2\times10^5$，平方约 $1.5\times10^{10}$，C++ 中必须用 `long long`。
7. **障碍在起点**：若 `[[0,0]]` 出现在障碍列表，机器人从 $(0,0)$ 出发不受影响，但它之后不能用「走回原点」的方式穿过——代码逐格检查，行为正确。
8. **命令全是转向**：不产生移动，`ans` 保持 $0$，正确（机器人只到过原点）。
