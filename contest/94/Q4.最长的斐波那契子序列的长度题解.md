# LeetCode 最长的斐波那契子序列的长度 题解

## 1. 题目概述

- **标题 / 题号**：最长的斐波那契子序列的长度（#873，medium）
- **链接**：https://leetcode.cn/problems/length-of-longest-fibonacci-subsequence/
- **来源**：LeetCode 第 94 场周赛 Q4
- **难度**：中等
- **标签**：数组、哈希表、动态规划

**题意**：给定一个**严格递增**的正整数数组 `arr`，求其中最长的「斐波那契式子序列」的长度。斐波那契式序列要求长度 $n \ge 3$，且对任意 $i$ 有 $x_i + x_{i+1} = x_{i+2}$。子序列指从 `arr` 中删去若干元素（可删 $0$ 个）后、保持相对顺序得到的序列。若不存在长度 $\ge 3$ 的斐波那契式子序列，返回 $0$。

**关键点**：

- `arr` **严格递增**，所以任意两项之和大于后一项，且「同一个值只有唯一位置」——这既是难点（不能随便选）也是优化点（可用哈希表定位下标）。
- 返回值是**长度**，不是子序列本身；长度不足 3 时统一返回 0。

**约束**：

- $3 \le arr.length \le 1000$
- $1 \le arr[i] < arr[i+1] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,3,4,5,6,7,8]
输出：5
解释：最长的斐波那契子序列是 [1,2,3,5,8]，长度为 5。
     注意 [1,2,3,5,8] 中 1+2=3、2+3=5、3+5=8，全部满足。
```

**示例 2**

```text
输入：arr = [1,3,7,11,12,14,18]
输出：3
解释：最长的有 [1,11,12]、[3,11,14]、[7,11,18]，长度都是 3。
```

**示例 3**（补充，验证「不存在」的情形）

```text
输入：arr = [1,2,4,8]
输出：0
解释：任取三项都凑不出 a+b=c 的形式（1+2=3 不在数组里，2+4=6 不在…），返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有三元组 $(i,j,k)$ 判断是否满足 $arr[i]+arr[j]=arr[k]$，再尝试往后延伸：单是枚举三元组就 $O(n^3) = 10^9$，$n \le 1000$ 时已不可接受；若还要为每个三元组往后延伸，最坏 $O(n^4)$。

另一种「暴力」是枚举前两项 $(i, j)$（共 $O(n^2)$ 对），然后**贪心地往后接**：每次在数组里二分查找 $arr[i]+arr[j]$ 是否存在，存在就把 $(j, k)$ 作为新的前两项继续。这个做法是 $O(n^2 \log n)$，能过题，但每次延伸都要重新二分，而且会重复计算相同的前缀——「以 $(j,i)$ 结尾的最长长度」被反复求解，这正是 DP 要消除的重复。

### 3.2 核心观察：用「最后两项」作状态

![核心转移：找 arr[i] − arr[j] 对应的下标 k](images/wc94_q4_dp_state.svg)

斐波那契式序列的**下一项只由最后两项决定**：若已知序列以 $arr[j], arr[i]$（$j < i$）结尾，那么下一项必然是 $arr[j] + arr[i]$；而任意「以 $arr[j], arr[i]$ 结尾」的合法序列，其前一项必然是 $arr[i] - arr[j]$。于是定义：

$$dp[j][i] = \text{以 } arr[j], arr[i] \text{ 结尾的最长斐波那契子序列长度}, \quad j < i$$

转移：令 $k$ 为满足 $arr[k] = arr[i] - arr[j]$ 的下标（需 $k < j$，保证下标顺序），则

$$dp[j][i] = dp[k][j] + 1$$

若不存在这样的 $k$，则 $dp[j][i] = 2$（只有两个数，还称不上斐波那契式序列，但可以作为更长序列的起点）。

**为什么必须 $k < j$？** 因为子序列要保持原数组顺序：$arr[k]$ 必须排在 $arr[j]$ 前面。若 $arr[i]-arr[j]$ 存在但其下标 $\ge j$，那么用它接在后面会破坏递增顺序（实际上由于 $arr$ 严格递增且 $arr[i] - arr[j] < arr[j]$（当 $arr[i] < 2arr[j]$ 时）或更大），必须排除。

**答案**：$\max_{j<i} dp[j][i]$，但只在长度 $\ge 3$ 时才有意义；若最大值只有 $2$，按题意返回 $0$。

**用哈希表加速定位**：预处理 `pos[value] = index`，转移时 $O(1)$ 查 $arr[i]-arr[j]$ 的下标，整体 $O(n^2)$。

### 3.3 算法流程

```text
1. n = len(arr)，pos = {arr[i] : i}
2. dp = n × n 的表，全部初始化为 2         // 任意两项都构成长度 2 的起点
3. ans = 0
4. for i in 0..n-1：
       for j in 0..i-1：
           need = arr[i] - arr[j]
           若 need 在 pos 中且 pos[need] < j：
               k = pos[need]
               dp[j][i] = dp[k][j] + 1
               ans = max(ans, dp[j][i])
5. 返回 ans                                 // 从未转移过则为 0
```

### 3.4 示例演算

对示例 1 的 `arr = [1,2,3,4,5,6,7,8]`（下标 $0..7$）：

![逐步转移：从 [1,2] 一路接到 [1,2,3,5,8]](images/wc94_q4_walkthrough.svg)

| $(j,i)$ | $arr[j], arr[i]$ | $arr[i]-arr[j]$ | 查到的 $k$ | $dp[j][i]$ | 对应序列 |
|---------|-----------------|----------------|-----------|-----------|---------|
| $(0,1)$ | 1, 2 | $-1$ | 不存在 | 2 | `[1,2]` |
| $(1,2)$ | 2, 3 | 1 | $k=0 < 1$ ✓ | $dp[0][1]+1 = 3$ | `[1,2,3]` |
| $(2,4)$ | 3, 5 | 2 | $k=1 < 2$ ✓ | $dp[1][2]+1 = 4$ | `[1,2,3,5]` |
| $(4,7)$ | 5, 8 | 3 | $k=2 < 4$ ✓ | $dp[2][4]+1 = 5$ | `[1,2,3,5,8]` |

其余组合（如 $(1,3)$：$4-2=2$，$k=1$ 不满足 $k<j=1$）无法转移，保持长度 $2$。最终 `ans = 5`。

示例 2 中 `arr = [1,3,7,11,12,14,18]`：$(3,4)$ 即 $11,12$，$12-11=1$，$k=0<3$ ✓，得长度 $3$；$(3,5)$ 即 $11,14$，$14-11=3$，$k=1<3$ ✓，长度 $3$；$(3,6)$ 同理得 $3$。最大为 $3$。

## 4. 算法细节

1. **初始化为 2 而不是 0**：长度为 2 的「前两项」是合法状态（虽然还不算斐波那契式序列），只有发生转移才可能变成 $\ge 3$。若初始化成 0，转移时会得到错误的小值。
2. **答案只在转移时更新**：只有发生 $dp[j][i] = dp[k][j]+1$ 才说明找到了长度 $\ge 3$ 的序列，此时才更新 `ans`；若全程无转移，`ans` 保持 $0$，正好满足「不存在则返回 0」。
3. **`k < j` 不可省**：由于 `arr` 严格递增，`need = arr[i] - arr[j]` 可能等于数组中的某个更靠后的值（当 $arr[i] > 2\,arr[j]$），此时下标顺序被破坏。
4. **`need <= 0` 的情形**：$arr[i] - arr[j] < 0$ 时哈希表查不到（值都是正数），无需特判。
5. **哈希表的键是值、值是下标**：因为 `arr` 严格递增，值到下标是单射，不会冲突。
6. **空间优化**：`dp` 是 $n \times n$，$n = 1000$ 时约 $4$ MB（`int`），可接受；若想省空间可只存 `dp[j][i]` 的上三角，但意义不大。

## 5. 正确性证明

**引理 1（状态的充分性）**：任何以 $arr[j], arr[i]$（$j<i$）结尾的斐波那契式子序列，其前面部分必然是以 $arr[k], arr[j]$ 结尾的斐波那契式子序列，其中 $arr[k] = arr[i]-arr[j]$ 且 $k<j$。

**证明**：设序列为 $\ldots, x_{t-1}, x_t, x_{t+1}$，其中 $x_t = arr[j]$、$x_{t+1} = arr[i]$。由斐波那契式定义 $x_{t-1} + x_t = x_{t+1}$，故 $x_{t-1} = arr[i]-arr[j]$。由于子序列保持原数组顺序，$x_{t-1}$ 在数组中的下标必小于 $j$，而 `arr` 严格递增保证值 $arr[i]-arr[j]$ 只对应唯一一个下标 $k$，因此 $k < j$，且去掉末尾一项后的前缀正是以 $arr[k], arr[j]$ 结尾的斐波那契式子序列。∎

**引理 2（转移正确）**：算法对每个 $(j,i)$ 计算出的 $dp[j][i]$ 等于「以 $arr[j], arr[i]$ 结尾的最长斐波那契子序列长度」。

**证明**：对 $i$ 归纳（$j$ 任意）。

- 若不存在满足条件的 $k$：由引理 1，任何以 $arr[j],arr[i]$ 结尾的斐波那契式序列长度都不可能是 $3$ 或更多（否则它的前一项会给出这样的 $k$），故最长长度就是 $2$，与初值一致。
- 若存在 $k<j$：任何以 $arr[j],arr[i]$ 结尾的序列，去掉末尾的 $arr[i]$ 后是以 $arr[k],arr[j]$ 结尾的序列，故其长度 $\le dp[k][j]+1$；反之，把 $arr[i]$ 接到「以 $arr[k],arr[j]$ 结尾的最长序列」之后，由 $arr[k]+arr[j]=arr[i]$ 仍是斐波那契式序列，达到 $dp[k][j]+1$。由于 $k<j<i$，$dp[k][j]$ 在计算 $dp[j][i]$ 时已就绪（外层 $i$ 递增、内层 $j$ 递增即可保证），归纳成立。∎

**定理**：算法返回 `arr` 中最长斐波那契式子序列的长度；不存在时返回 $0$。

**证明**：任一长度 $\ge 3$ 的斐波那契式子序列都有唯一的前两项 $arr[j], arr[i]$，由引理 2 其长度不超过 $dp[j][i]$；而 $dp[j][i]$ 对应的构造也确实给出一个合法子序列，故 $\max dp$ 恰为最长长度。又因为 $\max dp \ge 3$ 当且仅当发生过至少一次转移，算法只在这种情况下更新 `ans`，其余情况 `ans = 0`，与题意一致。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。两层循环枚举 $(j,i)$ 共 $\frac{n(n-1)}{2}$ 对，每对做一次哈希查询 $O(1)$。$n = 1000$ 时约 $5\times10^5$ 次操作。
- **空间**：$O(n^2)$ 的 `dp` 表（$1000^2$ 个 `int`，约 $4$ MB）加 $O(n)$ 的哈希表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int lenLongestFibSubseq(vector<int>& arr) {
        int n = arr.size(), ans = 0;
        unordered_map<int, int> idx;
        for (int i = 0; i < n; i++) idx[arr[i]] = i;
        vector<vector<int>> dp(n, vector<int>(n, 2));
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < i; j++) {
                auto it = idx.find(arr[i] - arr[j]);
                if (it != idx.end() && it->second < j) {
                    dp[j][i] = dp[it->second][j] + 1;
                    ans = max(ans, dp[j][i]);
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def lenLongestFibSubseq(self, arr: list[int]) -> int:
        n = len(arr)
        idx = {v: i for i, v in enumerate(arr)}
        # dp[j][i] = 以 arr[j], arr[i] 结尾的最长斐波那契子序列长度
        dp = [[2] * n for _ in range(n)]
        ans = 0
        for i in range(n):
            for j in range(i):
                k = idx.get(arr[i] - arr[j])
                if k is not None and k < j:
                    dp[j][i] = dp[k][j] + 1
                    ans = max(ans, dp[j][i])
        return ans
```

## 8. 边界情况与易错点

1. **初始化为 0**：会让 $dp[k][j]+1$ 得到 $1,2,\ldots$ 的错误小值，最终答案偏小。必须初始化为 $2$。
2. **漏判 `k < j`**：如 $arr = [1,2,3]$，对 $(1,2)$（$2,3$）有 $3-2=1$、$k=0<1$ ✓，没问题；但对 $arr = [1,2,4,6]$ 的 $(1,3)$（$2,6$），$6-2=4$ 的下标是 $2$，此时 $k=2 \ge j=1$，若误用会得到 $[1,4,2,6]$ 这种乱序序列。
3. **不存在长度 $\ge 3$ 时返回 0**：`ans` 初值取 $0$，只在发生转移时更新，天然满足。
4. **`arr` 有重复值**：题目保证严格递增，所以哈希表不会覆盖；若数据违约（有重复），需要用「值 → 下标列表」并按下标顺序匹配。
5. **值域到 $10^9$**：`arr[i] - arr[j]` 不会溢出 `int`（最大 $10^9$），但若题目放大到 $10^{18}$ 需用 `long long`。
6. **`n = 3`**：最多只有一对可转移，答案要么 $3$ 要么 $0$，二分循环不会越界。
7. **嵌套顺序**：`i` 外层递增、`j` 内层递增即可保证 `dp[k][j]` 先于 `dp[j][i]` 计算（因为 $k<j<i$）。
