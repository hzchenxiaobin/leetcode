# LeetCode 从链表中删去总和值为零的连续节点 题解

## 1. 题目概述

- **标题 / 题号**：从链表中删去总和值为零的连续节点（#1171，medium）
- **链接**：https://leetcode.cn/problems/remove-zero-sum-consecutive-nodes-from-linked-list/
- **来源**：LeetCode 第 151 场周赛 Q3
- **难度**：中等
- **标签**：哈希表，链表

**题意**：给定单链表头节点 `head`，反复删去「节点值之和为 $0$ 的连续节点段」，直到链表中不再存在这样的段，返回最终链表的头节点。答案是**链表节点序列**，不是数组，且可能不唯一（题面明确说明可返回任意满足要求的答案）。

**约束**：

- 节点数 $1 \le n \le 1000$
- $-1000 \le \text{node.val} \le 1000$
- 存在多个合法答案时，返回其中任意一个即可
- 允许改写原节点的 `next`，不必新建节点

> 💡 官方提示「先转数组、反复删掉和为 0 的子数组、再转回来」是**诱导暴力**的写法。本题真正的套路是前缀和 + 哈希：把「反复删」压缩成**一趟指针重接**。

## 2. 示例

**示例 1**

```text
输入：head = [1,2,-3,3,1]
输出：[3,1]
解释：1 + 2 + (-3) = 0，删去前三个节点，剩下 [3,1]。
      提示：答案 [1,2,1] 也是正确的——删 -3 与 3 同样合法（本题多解）。
```

**示例 2**

```text
输入：head = [1,2,3,-3,4]
输出：[1,2,4]
解释：3 + (-3) = 0，删去中间这两个节点，剩下 [1,2,4]。
```

**示例 3**

```text
输入：head = [1,2,3,-3,-2]
输出：[1]
解释：先删 3 与 -3 得到 [1,2,-2]，再删 2 与 -2 得到 [1]；
      等价地，2 + 3 + (-3) + (-2) = 0 可以整段一次删掉。
```

## 3. 解题思路

### 3.1 暴力思路

**版本 A（照题面直译）**：每轮枚举所有 $O(n^2)$ 个连续段，找到和为 $0$ 的一段就删掉，删完重扫，最多删 $\lfloor n/2 \rfloor$ 轮。时间 $O(n^3)$，$n = 1000$ 时接近 $10^9$ 次判定，C++ 都很勉强，Python 必超时。

**版本 B（哈希加速单轮判定）**：每轮用「前缀和 + 哈希表」在 $O(n)$ 内找出一段零和区间，删掉后前缀和全部失效、必须从头重算，总时间 $O(n^2)$。这个复杂度可以过，但每轮都要重建链表、处理删头删尾删中间的边界，代码量大且极易写错。

两个版本共同的毛病是：**把同一件事重复做了很多遍**。每次删除只改变了链表的一小段，而前缀和的信息其实在**原链表**上算一次就够。

### 3.2 核心观察：前缀和相等 ⇒ 中间整段可删

![前缀和相等的两个位置夹出一段和为零的区间](images/wc151_q3_prefix_equal.svg)

设节点值为 $v_1, v_2, \dots, v_n$，定义前缀和

$$p_0 = 0, \qquad p_i = v_1 + v_2 + \dots + v_i \quad (1 \le i \le n)$$

那么区间 $(i, j]$（即第 $i+1$ 到第 $j$ 个节点）之和为 $p_j - p_i$，于是

$$v_{i+1} + \dots + v_j = 0 \iff p_i = p_j$$

**零和段就是「两个前缀和相等的位置」之间夹住的那一段**——这是所有「子数组和」类问题的标准转化（例如 560 题）。

关键的一步是**从「反复删」变成「一次跳」**。设当前节点在原链表中的下标为 $c$、前缀和为 $s$，记 $L(s)$ 为**最后一个**满足 $p_i = s$ 的下标。从当前节点直接跳到 $L(s)$ 之后的那个节点，等于把下标区间 $[c+1, L(s)]$ 整段删掉，这段的和恰好是 $0$。为什么取「最后一个」而不是「第一个」：

- 取最后一个 ⇒ 一次吞掉尽可能多的可删段，且**跳转目标永远在当前节点右边**，指针单调右移，不会成环；
- 若误存「第一次出现」，跳转目标可能落在当前位置**之前**，实测在 $[1,-1,1]$ 上第 3 步就指回下标 $1$，直接形成环。

> 💡 换个说法：把所有「前缀和相等」的位置连成边，一次删除就是沿着这条边往前跳一段；整道题于是变成「沿着这些边一路跳到表尾」。我们的算法固定走「每个点连向它同值的最后一个点」这条最贪心的路线。

### 3.3 算法流程：两遍扫描 + 末次出现表

![两遍扫描：建表、跳指针](images/wc151_q3_algorithm_flow.svg)

1. **建哑结点**：`dummy` 的值为 $0$、`next` 指向 `head`，让 $p_0 = 0$ 有对应的节点，从而「从头开始的零和段」也能被处理。
2. **第一遍（建表）**：从 `dummy` 扫到 `null`，累加 $s$，执行 `last[s] = p`。因为每次都覆盖写，表里留下的是每个前缀和的**最后一次出现**。
3. **第二遍（跳指针）**：$s$ 归零，重新从 `dummy` 开始，每走到一个节点就 `s += p->val`，然后令 `p->next = last[s]->next`，再前进一格。
4. **返回** `dummy->next`（原头节点可能已被整段删掉）。

两遍的伪代码：

```text
pass 1:  s = 0; for p in dummy, v1, ..., vn:  s += p.val;  last[s] = p
pass 2:  s = 0; p = dummy
         while p != null:  s += p.val;  p.next = last[s].next;  p = p.next
return   dummy.next
```

**为什么 $s$ 不用修正**：每次跳过的区间和为 $0$，所以 $s$ 在跳转前后取值不变，第二遍的 $s$ 始终等于当前节点在**原链表**中的前缀和。正因如此，「第一遍建表、第二遍复用同一张表」才是自洽的。

### 3.4 示例演算

![示例 1 的逐跳演算](images/wc151_q3_walkthrough.svg)

以 `head = [1,2,-3,3,1]` 为例，前缀和 $(p_0, p_1, \dots, p_5) = (0, 1, 3, 0, 3, 4)$，所以 `last` 表为 $0 \to 3,\ 1 \to 1,\ 3 \to 4,\ 4 \to 5$（值为下标）。第二遍：

| 步骤 | 当前节点 | $s$ | `last[s]` | 改写后的 `next` | 结果链表 |
|------|----------|-----|-----------|------------------|----------|
| 1 | `dummy`（值 0） | 0 | 下标 3 | 下标 4（值 3） | `[]` |
| 2 | 下标 4（值 3） | 3 | 下标 4 自己 | 下标 5（值 1） | `[3]` |
| 3 | 下标 5（值 1） | 4 | 下标 5 自己 | `null`，链表结束 | `[3, 1]` |

第 1 步一次跳过下标 1..3，正是 $1 + 2 + (-3) = 0$ 的那一段；此后没有再出现同前缀和的点，于是直接走到表尾。

另外两组示例：

- `[1,2,3,-3,4]`：$p = 0,1,3,6,3,7$，`last[3] = 4`，于是下标 3、4 的两个节点（$3$ 与 $-3$）被整段跳过，得到 `[1,2,4]`。
- `[1,2,3,-3,-2]`：$p = 0,1,3,6,3,1$，`last[1] = 5`，从下标 1（值 1）直接跳到 `null`，得到 `[1]`。

## 4. 算法细节

1. **哑结点不是装饰**：$p_0 = 0$ 必须作为「第 0 个节点」进入 `last` 表，否则「左端点落在表头之前」的零和段（如 `[1,-1,2]` 的前两个节点）没有左端点可查，会被漏删。
2. **覆盖写才是「最后位置」**：循环体里无条件执行 `last[s] = p`；如果写成 `if (s not in last)` 只记首次出现，跳转就会向左指，轻则错误、重则成环（见 §8 第 4 条）。
3. **第二遍的 $s$ 必须重新累加**：不能沿用第一遍结束后残留的 $s$，否则第一步就用了错误的前缀和。两遍之间把 $s$ 显式清零。
4. **改写顺序是安全的**：`last[s]` 要么就是当前节点 $p$ 自己（此时 `p->next` 原地不动），要么在 $p$ 的**后面**（第二遍还没扫到，它的 `next` 仍是原链的指针）。所以 `p->next = last[s]->next` 读到的永远是原链信息，不会读到半成品。
5. **指针单调右移 ⇒ 必然终止**：每次前进后，节点的原始下标严格增大，至多 $n+1$ 步就走完；不存在回退、不需要递归、也不需要「删到不动点」的外层循环。
6. **不真的删除、不数组化**：被跳过的节点自然不会出现在结果链表里，无需 `delete`、无需先转 `vector` 再转回来——少一次 $O(n)$ 的搬运和一堆边界。
7. **值域**：$\lvert p_i \rvert \le 1000 \times 1000 = 10^6$，`int` 足够作哈希键；若值域放大到 $10^9$ 级别再用 `long long`。
8. **哈希表容量**：至多 $n+1$ 个不同的键，C++ 里可以 `reserve(2 * n)` 减少 rehash；不 `reserve` 也能过。

## 5. 正确性证明

**引理 1（零和 ⇔ 前缀和相等）**：对 $0 \le i < j \le n$，有 $\sum_{k=i+1}^{j} v_k = 0 \iff p_i = p_j$。

**证明**：$\sum_{k=i+1}^{j} v_k = p_j - p_i$，故段和为 $0$ 当且仅当 $p_j = p_i$。∎

**引理 2（每次跳转都是一次合法的整段删除）**：设第二遍当前节点在原链表中的下标为 $c$，$L$ 为满足 $p_L = p_c$ 的最大下标，则算法把该节点的 `next` 改为下标 $L+1$ 的节点，等价于删除原下标区间 $[c+1, L]$，且该区间之和为 $0$。

**证明**：由 $L$ 的定义 $p_L = p_c$，于是 $\sum_{k=c+1}^{L} v_k = p_L - p_c = 0$；改写 `next` 恰好跳过这段。∎

**引理 3（结果中不含任何零和连续段）**：设结果链表保留的原下标（含哑结点）为 $0 = i_0 < i_1 < \dots < i_m \le n$。则对任意 $0 \le a < b \le m$，都有 $p_{i_a} \ne p_{i_b}$。

**证明**：反设 $p_{i_a} = p_{i_b}$。由构造，$i_{a+1} = L(p_{i_a}) + 1$，而 $L(p_{i_a})$ 是值为 $p_{i_a}$ 的**最后**下标，$i_b$ 也是该值的下标，故 $L(p_{i_a}) \ge i_b$，从而 $i_{a+1} > i_b$。但 $a < b$ 且保留下标严格递增，应有 $i_{a+1} \le i_b$，矛盾。所以同前缀和的点对不会同时被保留，由引理 1 即知不存在零和连续段。∎

**定理**：算法返回的链表是题目要求的合法终态。

**证明**：第一遍只是建表，不改变链表。第二遍由引理 2，每次跳转都等价于删除一个和为零的区间；这些区间互不相交且按原顺序排列，删除其中一段不会打断其他段的连续性，因此可以依次在链表上真实地执行这些删除，得到一个合法过程。过程结束时由引理 3 不再存在零和连续段，满足题目「删到不存在为止」的要求。又由 $i_{a+1} > i_a$ 与节点数有限，跳转至多 $n+1$ 次，算法必然终止。故输出合法。∎

> ⚠️ 题目允许多解（示例 1 的 `[1,2,1]` 同样正确）。本算法固定选择「每个前缀和跳到它最后一次出现」，因此输出的是与官方示例一致的 `[3,1]` 这一支。

## 6. 复杂度分析

- **时间**：$O(n)$。第一遍一次线性扫描，$O(n)$ 次哈希插入；第二遍至多 $n+1$ 次「哈希查询 + 指针改写」，每次平均 $O(1)$；两个被跳过的节点不会单独访问，故总代价线性。相比暴力的 $O(n^3)$ 与多轮哈希版的 $O(n^2)$ 都更优。
- **空间**：$O(n)$。`last` 表最多存 $n+1$ 个键值对；除此之外只用了哑结点和两个游标指针，不新建结果节点（直接复用原节点），也不做数组化，故额外空间就是哈希表本身。
- **常数**：两遍各扫一次链表，缓存友好度不如数组，但 $n \le 1000$ 时完全无压力；即便放大到 $10^6$ 也只需两趟遍历。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    ListNode* removeZeroSumSublists(ListNode* head) {
        ListNode dummy(0, head);                 // 哑结点：给前缀和 0 一个落点
        unordered_map<int, ListNode*> last;
        last.reserve(2048);

        int s = 0;
        for (ListNode* p = &dummy; p != nullptr; p = p->next) {
            s += p->val;
            last[s] = p;                         // 覆盖写：留下最后一次出现
        }

        s = 0;                                   // 第二遍必须重新累加
        for (ListNode* p = &dummy; p != nullptr; p = p->next) {
            s += p->val;
            p->next = last[s]->next;             // 一次跳过整段零和区间
        }
        return dummy.next;                       // 原 head 可能已被删掉
    }
};
```

### Python

```python
from typing import Optional


class Solution:
    def removeZeroSumSublists(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)                # 前缀和 0 的落点
        last = {}
        s = 0
        p = dummy
        while p is not None:
            s += p.val
            last[s] = p                          # 覆盖写：末次出现
            p = p.next

        s = 0
        p = dummy
        while p is not None:
            s += p.val
            p.next = last[s].next                # 跳过整段零和区间
            p = p.next
        return dummy.next
```

## 8. 边界情况与易错点

1. **全是 0**：`[0]`、`[0,0,0]` 都应返回**空链表**。此时 `last[0]` 是最后一个节点，第二遍从 `dummy` 一步跳到 `null`，`dummy.next` 被置空——正确，但若省掉哑结点、直接拿 `head` 当前缀 0 的落点，头节点就同时扮演「虚拟位置 0」和「真实节点」两个角色，前缀和整体错位，`[0,0]` 这类输入必错。
2. **头节点被整段删掉**：`[-1,1,2]` 的答案是 `[2]`。必须从哑结点出发建表与跳转，否则 $p_0 = 0$ 丢失，第 1、2 个节点删不掉。
3. **只有一个节点**：`[0]` 输出空，`[5]` 输出 `[5]`。单节点时第二遍只做一次「自己指自己」的空跳，不会死循环。
4. **首现 vs 末现**：必须覆盖写。若只记录首次出现，跳转可能指回前面：在 `[1,-1,1]` 上第二遍第 3 步会把下标 2 的 `next` 指回下标 1，形成环进而死循环；正确写法在该输入上一步跳到 `null`，输出 `[1]`。
5. **第二遍忘记清零 $s$**：若沿用第一遍结束时的 $s$（等于总和），第一步就用错前缀和，结果完全错乱。两遍之间显式 `s = 0`。
6. **多解不要紧，但别答出非法解**：`[1,2,-3,3,1]` 答 `[3,1]` 或 `[1,2,1]` 都合法，但答 `[1,2,3,1]`（没删干净）或 `[1,1]`（凭空吞掉节点）都错。本文算法恒给出「每次跳最远」的那一支。
7. **C++ 的 `for` 增量**：循环体里改写了 `p->next`，而增量表达式是 `p = p->next`，读到的正是新指针，这是刻意的写法；若提前缓存 `nxt = p->next` 再在循环体里改指针，很容易少跳或多跳。
8. **返回值不是 `head`**：`head` 指向的节点可能已被跳过，返回 `dummy.next` 才行；Python 里返回 `dummy.next` 后原 `head` 对象即被丢弃，无需额外清理。

**延伸思考**：合法终态不唯一，其结构可以精确刻画成一张 DAG。把「已处理到的位置」$i \in [0, n]$ 当作状态，另外补一个虚拟终点 $n+1$：从 $i$ 可以走到 $j$（$i < j \le n$），当且仅当 $p_i = p_{j-1}$（把节点 $i+1 \dots j-1$ 整段删掉、节点 $j$ 保留；$j = i+1$ 时就是什么都不删）；此外还允许 $i \to n+1$，当且仅当 $p_i = p_n$（把 $i+1 \dots n$ 整段删光）。于是每条 $0 \to n+1$ 的路径正好对应一个合法终态，边权 $j-i-1$（最后一跳为 $n-i$）就是这条边删掉的节点数：「保留节点最少 / 最多」是这张 DAG 上的最短路 / 最长路（$O(n^2)$ DP），「一共有多少种不同答案」则是路径计数。本文算法只走「每次跳到同前缀和的最远位置」这一条路径，写法最简单，也足以满足题目「返回任意合法答案」的要求。若把条件改成「删除和为 $k$ 的段」（$k \ne 0$），删除会平移剩余元素的前缀和值，上述「等值合并」的结构立刻失效，问题会退化成需要搜索的形态；若链表本身带环，前缀和不再有终点，必须先判环再谈删除。
