# LeetCode 查询无效交易 题解

## 1. 题目概述

- **标题 / 题号**：查询无效交易（#1169，medium）
- **链接**：https://leetcode.cn/problems/invalid-transactions/
- **来源**：LeetCode 第 151 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序

**题意**：给定交易清单 `transactions`，每笔交易形如 `"{name},{time},{amount},{city}"`。一笔交易**可能无效**当且仅当满足**至少一条**：① 金额**严格大于** $1000$；② 存在**另一笔**交易，与它**姓名相同**、**城市不同**，且**时间差不超过 60 分钟**（含 60）。返回所有可能无效的交易（原样返回，顺序任意，重复交易逐条计入）。

**约束**：

- $1 \le \text{transactions.length} \le 1000$
- 每笔交易严格按 `"{name},{time},{amount},{city}"` 格式给出，`name`、`city` 为长度 $1 \sim 10$ 的小写字母串
- $0 \le \text{time} \le 1000$，$0 \le \text{amount} \le 2000$

> 💡 注意「可能无效」是**双向**的：一旦交易 $i$ 与 $j$ 构成违规配对，**两条都会被标为无效**，而不是只判其中一条。

## 2. 示例

**示例 1**

```text
输入：transactions = ["alice,20,800,mtv","alice,50,100,beijing"]
输出：["alice,20,800,mtv","alice,50,100,beijing"]
解释：两笔金额都 ≤ 1000，但同名、城市不同，且 |20 − 50| = 30 ≤ 60，互相使对方无效。
```

**示例 2**

```text
输入：transactions = ["alice,20,800,mtv","alice,50,1200,mtv"]
输出：["alice,50,1200,mtv"]
解释：城市相同 → 规则 B 不触发；第 2 笔因金额 1200 > 1000 单独无效。
```

**示例 3**

```text
输入：transactions = ["alice,20,800,mtv","bob,50,1200,mtv"]
输出：["bob,50,1200,mtv"]
解释：姓名不同 → 规则 B 不触发；只有金额超限的 bob 那笔无效。
```

## 3. 解题思路

### 3.1 暴力思路

对每笔交易 $i$，再枚举所有 $j \ne i$，检查「同名 + 异城 + $|t_i - t_j| \le 60$」，命中就标记 $i$；金额规则单独判断。时间 $O(n^2)$，空间 $O(n)$。$n \le 1000$ 时 $n^2 = 10^6$，暴力**完全可以通过**（官方提示也是这么写的）。但内层比较的其实是「同名的另一笔交易」，不同姓名之间永远不可能配对——这提示我们把这层无意义的比较砍掉：**按姓名分桶**后，每个桶内部再按时间排序，就得到「只看近邻」的滑动窗口结构。

### 3.2 核心观察：按姓名分组 + 时间窗口

![两条失效规则](images/wc151_q1_invalid_rules.svg)

把判断拆成两个互不影响的「或」项：

- **规则 A（金额）**：`amount > 1000`，单笔自证，$O(1)$ 判定；
- **规则 B（同名 + 异城 + 近时间）**：需要一个**存在性查询**——「是否存在另一笔同名交易，城市不同于我且时间差 ≤ 60」。

规则 B 的关键转化：对交易 $i$ 定义

$$S_i = \{\, j \mid \text{name}_j = \text{name}_i,\ |t_j - t_i| \le 60 \,\}$$

注意 $i$ 自己一定在 $S_i$ 中（时间差为 0）。于是

$$\exists\, j \in S_i,\ \text{city}_j \ne \text{city}_i \iff \bigl|\{\, \text{city}_j : j \in S_i \,\}\bigr| \ge 2$$

也就是说，**不需要逐对比较城市**，只要数一数窗口内出现了几种城市：种数 $\ge 2$ 就说明「除了我这一种，还有别的城市」，交易 $i$ 无效；种数恰好为 1 说明窗口里全是我这种城市，交易 $i$ 在这一条上安全。

### 3.3 算法流程

![分组与滑动窗口](images/wc151_q1_group_window.svg)

1. **解析**：把每笔交易按逗号切成四段，`time`、`amount` 转成整数，四元组按下标分别存进 `name / time / amount / city` 数组。
2. **分桶 + 排序**：`groups[name]` 存该姓名所有交易的**下标**（存下标而不是字符串，最后直接取原串输出），桶内再按 `time` 升序排序。
3. **滑窗**：每个桶独立跑双指针，维护窗口 $[l, r)$、「城市 → 出现次数」哈希表与当前**城市种数** `distinct`：右指针在 $t_r - t_i \le 60$ 时扩张（计数 $0 \to 1$ 则 `distinct` 加一），左指针在 $t_i - t_l > 60$ 时收缩（计数 $1 \to 0$ 则 `distinct` 减一），读完窗口后若 `distinct ≥ 2` 就标记 $i$ 无效。
4. **合并与输出**：遍历一遍把 `amount > 1000` 的也标记无效，再按下标顺序收集被标记的字符串（同一笔只输出一次，但**不同下标上的相同字符串各输出一次**）。

### 3.4 示例演算

![示例 1 走查](images/wc151_q1_walkthrough.svg)

对示例 1，`alice` 桶按时间排序后为 `[(20, mtv, 800), (50, beijing, 100)]`：

| 交易 | 金额规则 | 窗口 $[t-60,\ t+60]$ 内的交易 | 城市种数 | 结论 |
|------|----------|------------------------------|----------|------|
| `alice,20,800,mtv` | $800 \le 1000$ ✓ 通过 | 20（mtv）、50（beijing） | $\{mtv, beijing\}=2$ | 无效 |
| `alice,50,100,beijing` | $100 \le 1000$ ✓ 通过 | 20（mtv）、50（beijing） | $\{mtv, beijing\}=2$ | 无效 |

两笔金额都没超限，但窗口里同时出现了两种城市，于是**互相判定无效**，答案为两条全出。对照示例 2：桶内两笔城市都是 `mtv`，窗口城市种数恒为 1，规则 B 不触发；只有金额 1200 的第二笔被规则 A 命中。

## 4. 算法细节

1. **一次解析、四数组存储**：`split` 只做一次，把 `int` 字段立即转换；后续反复比较时不再切字符串，避免 $O(n^2)$ 次额外解析。
2. **桶里存下标**：`unordered_map<string, vector<int>>` 的 value 是下标列表。这样既能按原串输出（保留重复），又能对 `time/amount/city` 数组直接随机访问。
3. **按时间排序是前提**：只有时间有序，$S_i$ 才是**连续下标区间**，双指针才成立。时间相同的交易相对顺序无所谓，因为窗口只看时间差。
4. **`distinct` 的维护**：加入城市时 `if (cnt[c]++ == 0) distinct++`；移出时 `if (--cnt[c] == 0) distinct--`。这两个 $0 \leftrightarrow 1$ 的跃变是唯一会改变种数的时刻。
5. **先扩张、后收缩**：两者顺序无所谓，但必须在**扩张完成且收缩完成之后**再读 `distinct`，否则读到的是「上一笔的窗口」。两个指针都只单调右移，均摊 $O(1)$。
6. **规则 A 不进窗口、输出不用 `set`**：金额判定与姓名、时间、城市无关，最后统一置 `bad[i] = true` 即可；输出按下标数组收集，用 `set` 去重会把重复交易少输出。

## 5. 正确性证明

**引理 1（窗口即 $S_i$）**：设某姓名桶内下标已按时间升序排列为 $a_0, a_1, \dots, a_{m-1}$。则对任意 $i$，上述双指针过程结束时窗口 $[l, r)$ 恰好满足

$$\{\, a_j \mid l \le j < r \,\} = S_{a_i}.$$

**证明**：时间升序意味着 $S_{a_i}$ 对应一段连续下标。右指针的条件是 $t_{a_r} - t_{a_i} \le 60$，一旦不满足就停止，故 $r$ 是首个满足 $t_{a_r} > t_{a_i} + 60$ 的下标（或 $m$）；左指针收缩到底后，$l$ 是首个满足 $t_{a_l} \ge t_{a_i} - 60$ 的下标。二者合起来正好是 $|t_{a_j} - t_{a_i}| \le 60$ 的全部下标。指针单调性：处理 $i+1$ 时 $t_{a_{i+1}} \ge t_{a_i}$，新区间端点都**不小于**旧区间，$l, r$ 只继续右移而无需回退，上一轮位置可安全沿用；对 $i$ 归纳即得。∎

**引理 2（城市种数判据）**：$\text{distinct}(S_i) \ge 2$ 当且仅当存在 $j \in S_i$ 使 $\text{city}_j \ne \text{city}_i$。

**证明**：
- ($\Leftarrow$) $j$ 与 $i$ 都在 $S_i$ 中，且城市不同，故城市集合至少含 $\text{city}_i$、$\text{city}_j$ 两个元素，种数 $\ge 2$。
- ($\Rightarrow$) 因 $i \in S_i$（时间差 $0 \le 60$），$\text{city}_i$ 必是集合中的一类。若所有 $j \in S_i$ 都满足 $\text{city}_j = \text{city}_i$，则集合只有一类，种数为 1，与 $\ge 2$ 矛盾。故存在异城交易。∎

**定理**：算法输出的集合恰为所有可能无效的交易（按下标计，重复字符串分别保留）。

**证明**：交易 $i$ 被标记当且仅当 $\text{amount}_i > 1000$ 或 $\text{distinct}(S_i) \ge 2$。由引理 1，$S_i$ 恰为所有同名且时间差 $\le 60$ 的交易；由引理 2，$\text{distinct}(S_i) \ge 2$ 等价于存在异城同名近时交易。这正是题面两条规则的并集，故标记正确。输出阶段按下标遍历一次 `bad`，被标记的下标各输出一次、未被标记的不输出，既不遗漏也不重复。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。解析 $O(n)$；分组 $O(n)$（哈希）；组内排序总计 $O(n \log n)$；每组双指针中每个下标至多被加入、移出各一次，合计 $O(n)$，每次操作是哈希表的均摊 $O(1)$；最后输出 $O(n)$。
- **空间**：$O(n)$。四个长度为 $n$ 的数组、`bad` 标记、分组哈希表（共 $n$ 个下标），以及单个桶内的城市计数表（最大 $O(m)$）。与暴力 $O(n^2)$ 的时间相比，这里用线性额外空间换掉了同名交易之间的两两比较。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<string> invalidTransactions(vector<string>& transactions) {
        int n = transactions.size();
        vector<string> name(n), city(n);
        vector<int> tim(n), amt(n);
        for (int i = 0; i < n; i++) {
            vector<string> p;
            string cur;
            for (char ch : transactions[i]) {        // 按逗号切成 4 段
                if (ch == ',') { p.push_back(cur); cur.clear(); }
                else cur.push_back(ch);
            }
            p.push_back(cur);
            name[i] = p[0]; tim[i] = stoi(p[1]);
            amt[i] = stoi(p[2]); city[i] = p[3];
        }

        vector<char> bad(n, 0);
        unordered_map<string, vector<int>> groups;   // 姓名 -> 下标列表
        groups.reserve(n * 2);
        for (int i = 0; i < n; i++) groups[name[i]].push_back(i);

        for (auto& kv : groups) {
            auto& idx = kv.second;
            sort(idx.begin(), idx.end(), [&](int a, int b) { return tim[a] < tim[b]; });
            int m = idx.size(), distinct = 0, l = 0, r = 0;
            unordered_map<string, int> cnt;          // 城市 -> 窗口内出现次数
            for (int i = 0; i < m; i++) {
                while (r < m && tim[idx[r]] - tim[idx[i]] <= 60) {
                    if (cnt[city[idx[r]]]++ == 0) distinct++;
                    r++;
                }
                while (tim[idx[i]] - tim[idx[l]] > 60) {
                    if (--cnt[city[idx[l]]] == 0) distinct--;
                    l++;
                }
                if (distinct >= 2) bad[idx[i]] = 1;  // 窗口内出现异城交易
            }
        }

        vector<string> res;
        for (int i = 0; i < n; i++) {
            if (amt[i] > 1000) bad[i] = 1;           // 规则 A
            if (bad[i]) res.push_back(transactions[i]);
        }
        return res;
    }
};
```

### Python

```python
from typing import List
from collections import defaultdict


class Solution:
    def invalidTransactions(self, transactions: List[str]) -> List[str]:
        n = len(transactions)
        name, city = [""] * n, [""] * n
        tim, amt = [0] * n, [0] * n
        for i, s in enumerate(transactions):
            p = s.split(',')
            name[i], tim[i], amt[i], city[i] = p[0], int(p[1]), int(p[2]), p[3]

        bad = [False] * n
        groups = defaultdict(list)                 # 姓名 -> 下标列表
        for i in range(n):
            groups[name[i]].append(i)

        for idx in groups.values():
            idx.sort(key=lambda i: tim[i])
            m = len(idx)
            cnt, distinct, l, r = {}, 0, 0, 0      # 城市 -> 窗口内出现次数
            for i in range(m):
                while r < m and tim[idx[r]] - tim[idx[i]] <= 60:
                    c = city[idx[r]]
                    if cnt.get(c, 0) == 0:
                        distinct += 1
                    cnt[c] = cnt.get(c, 0) + 1
                    r += 1
                while tim[idx[i]] - tim[idx[l]] > 60:
                    c = city[idx[l]]
                    cnt[c] -= 1
                    if cnt[c] == 0:
                        distinct -= 1
                    l += 1
                if distinct >= 2:                  # 存在异城同名近时交易
                    bad[idx[i]] = True

        res = []
        for i in range(n):
            if amt[i] > 1000:                      # 规则 A
                bad[i] = True
            if bad[i]:
                res.append(transactions[i])
        return res
```

## 8. 边界情况与易错点

1. **金额恰好 1000**：题面要求「超过 \$1000」，必须写 `amt > 1000`；写成 `>=` 会把 `["alice,20,1000,mtv"]` 误判为无效。
2. **时间差恰好 60**：题面「相隔不超过 60 分钟（包含 60）」，必须用 `<= 60`，写成 `< 60` 会漏掉 `20` 与 `80` 这种边界配对。
3. **同城永不违规**：`["alice,20,800,mtv", "alice,80,800,mtv"]` 两条都有效，规则 B 必须同时要求「异城」；而重复串 `["alice,20,800,mtv", "alice,20,800,mtv", "alice,20,800,beijing"]` 应当输出三条——按下标标记再收集，天然保留重复。
4. **单元素数组**：`n = 1` 时桶内只有一个下标，窗口只含自己，`distinct` 恒为 1，只有金额规则可能触发；注意不要写出 `idx[l]` 越界（`l` 永远 $\le i < r \le m$）。
5. **时间可以相同**：同一姓名同一时间的多笔交易时间差为 0，会被同时纳入窗口；右指针条件对 $r = i$ 成立，不会死循环。
6. **先收缩后读值**：读完 `distinct` 再进入下一轮前，窗口状态必须已包含「移出左端过期交易」的结果，否则会拿旧窗口误判。
7. **输出顺序**：任意顺序都可以，但不应打乱到丢掉元素；按下标顺序输出最省心，也方便与暴力对拍。

**延伸思考**：

- 若规则改成「同名、异城、60 分钟内的交易**不少于 $k$ 笔**」，窗口内只需把 `distinct` 换成「异城交易计数」：记录 `cnt[city_i]`，用 `窗口大小 − cnt[city_i]` 与 $k$ 比较，仍是 $O(n \log n)$。
- 若要求输出「导致无效的配对」而不只是无效交易，可放弃「种数」压缩，在窗口内维护「第一个与我异城的交易下标」，输出配对，最坏 $O(n^2)$。
- 若时间范围极大而交易稀疏（如 $t \le 10^9$），排序 + 双指针依然成立；若把「60 分钟」换成任意区间集合，就需要按区间查询的数据结构（线段树 / 有序表）。
