# LeetCode 餐盘栈 题解

## 1. 题目概述

- **标题 / 题号**：餐盘栈（#1172，hard）
- **链接**：https://leetcode.cn/problems/dinner-plate-stacks/
- **来源**：LeetCode 第 151 场周赛 Q4
- **难度**：困难
- **标签**：栈, 设计, 哈希表, 堆（优先队列）

**题意**：把**无限多个**容量同为 `capacity` 的栈从左到右排成一行、编号 $0,1,2,\dots$，实现一个类 `DinnerPlates`：

- `push(val)`：把 `val` 放进**最左边**还没有满的栈的栈顶；
- `pop()`：返回**最右边**非空栈的栈顶并删除它，若所有栈都空返回 $-1$；
- `popAtStack(index)`：返回编号 `index` 的栈的栈顶并删除它，若该栈为空（或还不存在）返回 $-1$。

关键在于两条**端点语义**加一条**保留语义**：push 只关心「最左未满」，pop 只关心「最右非空」，而 `popAtStack` 可以在中间任意掏空一个栈——被掏空的栈**不会消失**，它仍是 push 的合法落点（因为它在行中的位置仍然存在）。

**约束**：

- $1 \le capacity \le 20000$
- $1 \le val \le 20000$
- $0 \le index \le 100000$
- `push`、`pop`、`popAtStack` 合计最多 $2 \times 10^5$ 次调用

## 2. 示例

**示例 1**（官方）

```text
输入：
["DinnerPlates","push","push","push","push","push","popAtStack",
 "push","push","popAtStack","popAtStack","pop","pop","pop","pop","pop"]
[[2],[1],[2],[3],[4],[5],[0],[20],[21],[0],[2],[],[],[],[],[]]
输出：
[null,null,null,null,null,null,2,null,null,20,21,5,4,3,1,-1]
解释：capacity = 2。前 5 次 push 得到 [1,2] [3,4] [5]；popAtStack(0) 返回 2 → [1] [3,4] [5]；
      push(20) 回填栈 0、push(21) 落到栈 2 → [1,20] [3,4] [5,21]；
      两次 popAtStack 返回 20、21；最后 5 次 pop 返回 5,4,3,1,−1。
```

**示例 2**（补充：`capacity = 1`）

```text
输入：["DinnerPlates","push","push","pop","pop","pop"]
      [[1],[7],[8],[],[],[]]
输出：[null,null,null,8,7,-1]
解释：容量为 1 时每次 push 都新开一栈，pop 把最右的栈逐个清空，全空后再 pop 返回 −1。
```

**示例 3**（补充：越界下标与最左回填）

```text
输入：["DinnerPlates","pop","popAtStack","push","push","pop"]
      [[3],[],[5],[1],[2],[]]
输出：[null,-1,-1,null,null,2]
解释：初始没有栈，pop 与 popAtStack(5) 都返回 −1；两次 push 都落在栈 0 得 [1,2]；pop 取最右非空栈顶。
```

## 3. 解题思路

### 3.1 暴力思路

用一个 `vector<vector<int>>` 存所有栈：push 时从左往右线性扫描，找第一个 `size() < capacity` 的栈；pop 时从右往左扫描，找第一个非空栈；`popAtStack` 直接按下标访问。单次 push / pop 最坏 $O(S)$，$S$ 为已创建的栈数。由于 $S$ 可以随 push 一路增长到 $10^5$ 量级，而总操作数 $m \le 2\times 10^5$，最坏要做 $O(m \cdot S) \approx 10^{10}$ 次比较，必然超时。要过关，必须把「找最左未满」和「找最右非空」都压到「看一眼端点」的代价。

### 3.2 核心观察：两个方向各维护一个端点

![最左未满与最右非空](images/wc151_q4_leftmost_rightmost.svg)

- **最右非空很便宜**。栈只会被 push 到「未满」的位置，而 pop 永远从右端开始取值，所以只要把**尾部连续的空栈裁掉**，末尾那个栈就是最右非空栈。裁剪的总代价与「被创建的栈数」同阶，均摊 $O(1)$。
- **最左未满不便宜**。`popAtStack` 会在中间掏出空位，被掏空的老栈必须被优先回填，而 push 又要找**编号最小**的空位。用一个**小根堆**存「当前还有空位的栈编号」，堆顶就是最左未满栈；而堆**不支持删除任意元素**——某个栈被填满或作为尾部空栈被裁掉后，编号还留在堆里，不必急着删，取用时做一次有效性检查即可（**惰性删除**）。

这样每个操作只剩「常数次堆操作 + 常数次数组端点访问」，总复杂度 $O(m \log m)$。

### 3.3 算法流程

![三个操作的流程](images/wc151_q4_heap_flow.svg)

数据成员：`cap`、`st`（`vector<vector<int>>`，`st[i].back()` 是栈顶）、`avail`（小根堆，存有空位的栈编号）。

- `push(val)`：先 `while` 弹掉堆顶的**过期项**（该栈已满，或编号 $\ge |st|$ 说明它已被裁掉）；若堆空则 `st.push_back({val})`（所有已有栈都满，只能在右端开新栈），否则取 `i = avail.top()` 并 `st[i].push_back(val)`；写完后若该栈仍未满，把 `i` 压回堆。
- `pop()`：先 `while` 裁掉尾部空栈；`st` 为空返回 $-1$；否则取 $i = |st| - 1$，弹出 `st[i].back()`，再把 `i` 压回堆（它腾出了一个空位）。
- `popAtStack(i)`：当 $i \ge |st|$ 或 `st[i]` 为空时返回 $-1$；否则弹出栈顶并把 `i` 压回堆。**不**在这里删除变空的栈（中间删元素会让后面所有编号错位），它由 pop 的裁剪统一回收。

![惰性删除：过期编号在出堆时过滤](images/wc151_q4_lazy_delete.svg)

### 3.4 示例演算

![capacity = 2 的 15 步走查](images/wc151_q4_walkthrough.svg)

对官方示例逐步走查，重点看三处：

1. 第 6 步 `popAtStack(0)` 掏空栈 0 的栈顶后，栈 0 变成「未满」，于是第 7 步 `push(20)` 立刻回填**栈 0**而不是往右追加——这正是「最左未满」。
2. 第 9、10 步连续从中间取值（20、21），两个栈又都变成未满，堆里同时有 `0` 和 `2`，push 时取较小者 `0`。
3. 第 11 步 `pop()` 取走 5 后栈 2 变空，但它**仍在行中**（「未满栈」列仍有 2，之后 push 可以回填它）；直到第 12 步 pop 前的裁剪才把它从 `st` 末尾移除。

## 4. 算法细节

1. **编号语义**：栈编号就是它在 `st` 中的下标，等于行内位置。因此只能 `push_back` 新栈、只能 `pop_back` 裁尾，**中间的空栈绝不能 `erase`**，否则其右侧所有编号整体平移，堆里存的旧编号全部失效。
2. **过期项有两种**：`avail.top() >= st.size()`（该位置的栈已被裁掉）与 `st[avail.top()].size() == cap`（已满）。两个条件都要判；漏掉前者会在裁剪后越界访问，漏掉后者会把盘塞进满栈。
3. **允许堆中出现重复编号**：`popAtStack` 作用在一个本来就没满的栈上时，会把已经在堆里的编号再压一次。这不破坏「有空位 ⇒ 编号在堆中」（引理 1），多余的副本在「判满」时被丢弃，代价是均摊的，换来的是不必实现「堆中删除任意元素」。
4. **pop 的四步顺序**：裁尾 → 判空 → 取栈顶 → 编号入堆。顺序一旦颠倒（例如先判空后裁尾），在「全部弹空」的瞬间就会访问空 `vector` 的末尾。
5. **越界判定必须先做**：`index` 最大可达 $10^5$，而实际栈数可能只有个位数，`popAtStack` 里必须先判 `index >= st.size()`，否则直接越界崩溃。
6. **栈顶放在 `vector` 末尾**：`push_back` / `pop_back` 都是 $O(1)$；不要用头部插入（$O(cap)$）或 `deque` 两端操作来假装栈顶。
7. **「空栈」与「不存在的栈」要区分**：二者对 `popAtStack` 都返回 $-1$，但空栈必须留在行中继续参与 push；区分方式就是 `index < st.size()`。

## 5. 正确性证明

**引理 1（入堆不变量）**：在任意操作结束的时刻，若栈 $i$ 存在（$i < |st|$）且未满，则编号 $i$ 在堆 `avail` 中。

**证明**：对操作次数归纳，初始无栈显然成立。设操作前成立，分三种情况：

- **push**：若走「新建栈」分支，新栈未满则立即入堆（已满则无需入堆）；若走「取堆顶 $i$」分支，写入后该栈若未满则立即把 $i$ 压回。其余栈的装满状态不变。
- **pop**：裁剪只删除空栈，不改变剩余栈的内容；被弹出的栈 $i$ 少了一个元素，必然未满，代码随即把 $i$ 压入堆。
- **popAtStack**：同理，$i$ 少了一个元素而未满，随即入堆；其余栈不变。

三种操作都保持「未满且存在的栈编号在堆中」。∎

> 注意引理 1 只保证「**不漏**」，不保证「不多」：堆里可能残留已满或被裁掉的编号，取用时的有效性检查负责剔除多余项。

**引理 2（push 落点正确）**：设 push 前堆为 $H$，清理过期项后得到 $H'$。若 $H'$ 非空，则 $\min H'$ 是最左未满栈；若 $H'$ 为空，则所有已存在的栈都已满，右端新建的栈就是最左未满。

**证明**：$H'$ 非空时，堆顶 $t = \min H'$ 满足 $t < |st|$ 且 $st[t]$ 未满，是合法落点；由引理 1，每个未满栈的编号都在 $H$ 中，而未满编号不会被「已满 / $\ge |st|$」判据丢弃，故它仍在 $H'$ 中，于是 $t$ 是所有未满栈编号的最小值，即最左者。$H'$ 为空时，若存在未满栈 $j$，由引理 1 有 $j \in H$，而 $j$ 既不满也不越界、不会被丢弃，与 $H'$ 为空矛盾，故不存在未满栈；此时新栈编号 $|st|$ 的左侧全部已满，它就是最左未满。∎

**引理 3（pop 落点正确）**：裁剪后若 `st` 非空，则 `st.back()` 是最右非空栈。

**证明**：裁剪删除了尾部所有空栈，故 `st.back()` 非空。设其编号为 $r$；编号大于 $r$ 的栈已被裁掉，说明它们当时为空，而 `popAtStack` 只会把栈掏空、不会删除中间栈，因此这些位置不会再出现非空栈。故 $r$ 是全体非空栈编号的最大值。∎

**定理**：对任意合法操作序列，`push` / `pop` / `popAtStack` 的行为与返回值都与题面定义一致。

**证明**：对调用次数归纳。`push` 的正确性由引理 2 给出；`pop` 由引理 3 给出「取到的是最右非空栈顶」，而「裁剪后 `st` 为空」当且仅当所有栈为空（任何非空栈都不会被裁掉），此时返回 $-1$ 正确；`popAtStack` 直接按下标访问，越界或空栈返回 $-1$、否则返回该栈栈顶，与定义逐字一致。归纳假设保证每步之后栈内容与堆状态满足引理 1，从而引理 2、3 在下一步仍然可用。∎

## 6. 复杂度分析

- **时间**：$O(m \log m)$，其中 $m$ 是操作总数（$\le 2\times10^5$）。每次操作的堆操作次数是常数，单次 $O(\log m)$；push 里的 `while` 清理循环虽然可能一次弹很多项，但每个编号每次入堆后最多被弹出一次，而每步操作只压入常数个编号，故全部清理累计 $O(m)$ 次弹出。pop 的裁剪中，每个被创建的栈最多被裁掉一次，累计 $O(m)$。
- **空间**：$O(m)$。`st` 中总盘数不超过 push 次数加 1；栈对象数量不超过 push 次数；堆中元素数也不超过「历史入堆次数」$O(m)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <functional>
using namespace std;

class DinnerPlates {
    int cap;
    vector<vector<int>> st;                                  // 每个栈的栈顶在末尾
    priority_queue<int, vector<int>, greater<int>> avail;    // 小根堆：有空位的栈编号

public:
    DinnerPlates(int capacity) : cap(capacity) {}

    void push(int val) {
        // 丢掉「已满」或「已被裁掉」的过期堆顶
        while (!avail.empty() &&
               (avail.top() >= (int)st.size() || (int)st[avail.top()].size() == cap))
            avail.pop();
        if (avail.empty()) {
            st.push_back({val});                 // 所有栈都满 → 右端开新栈
            int i = (int)st.size() - 1;
            if ((int)st[i].size() < cap) avail.push(i);
        } else {
            int i = avail.top();
            avail.pop();
            st[i].push_back(val);
            if ((int)st[i].size() < cap) avail.push(i);
        }
    }

    int pop() {
        while (!st.empty() && st.back().empty()) st.pop_back();  // 裁掉右端空栈
        if (st.empty()) return -1;
        int i = (int)st.size() - 1;
        int v = st[i].back();
        st[i].pop_back();
        avail.push(i);                            // 腾出一个位置，重新可用于 push
        return v;
    }

    int popAtStack(int index) {
        if (index >= (int)st.size() || st[index].empty()) return -1;
        int v = st[index].back();
        st[index].pop_back();
        avail.push(index);
        return v;
    }
};
```

### Python

```python
import heapq


class DinnerPlates:

    def __init__(self, capacity: int):
        self.cap = capacity
        self.stacks = []          # 每个元素是一个栈，栈顶在末尾
        self.avail = []           # 最小堆：仍然有空位的栈编号

    def push(self, val: int) -> None:
        # 弹出「已满」或「已被裁掉」的过期堆顶
        while self.avail and (self.avail[0] >= len(self.stacks)
                              or len(self.stacks[self.avail[0]]) == self.cap):
            heapq.heappop(self.avail)
        if not self.avail:
            self.stacks.append([val])              # 所有栈都满 → 右端开新栈
            i = len(self.stacks) - 1
        else:
            i = heapq.heappop(self.avail)
            self.stacks[i].append(val)
        if len(self.stacks[i]) < self.cap:
            heapq.heappush(self.avail, i)

    def pop(self) -> int:
        # 裁掉右端连续的空栈，栈顶即为「从右往左第一个非空栈」
        while self.stacks and not self.stacks[-1]:
            self.stacks.pop()
        if not self.stacks:
            return -1
        i = len(self.stacks) - 1
        v = self.stacks[i].pop()
        heapq.heappush(self.avail, i)              # 该栈腾出一个位置
        return v

    def popAtStack(self, index: int) -> int:
        if index >= len(self.stacks) or not self.stacks[index]:
            return -1
        v = self.stacks[index].pop()
        heapq.heappush(self.avail, index)
        return v
```

## 8. 边界情况与易错点

1. **`capacity = 1`**：每次 push 都必须新开一栈，每次 pop 都会清空一个栈并触发一次裁剪。此时「未满」与「空」完全重合，最容易暴露「忘了把编号压回堆」的 bug。
2. **中间空栈必须被回填**：`capacity = 2` 时 `push(1) push(2) push(3) popAtStack(0) push(9)`，9 必须进**栈 0**。若把 push 写成「总是追加到末尾」，后面所有 pop 的次序都会错。
3. **裁剪后堆里残留过期编号**：全部弹空再 push 时，堆里可能还留着 $\ge |st|$ 的编号，不清理就会越界访问 `st[i]`；这正是 push 里 `while` 的第一条判据。
4. **全部弹空后编号归零**：把所有栈都 pop 空并裁完后 `st` 为空，下一次 push 会重新创建 0 号栈——这与题面一致（此时所有栈为空，最左未满就是最左端）。
5. **push 的写入与入堆是两个动作**：写入后必须重新判断是否未满，再决定是否压回堆；若在写入前就压回，满栈编号会混进堆，导致同一次 push 之后堆顶失效。
6. **不要在 `avail` 为空时直接追加**：只有在「清理完过期项」之后堆为空，才能断定所有已有栈都满；清理之前堆空并不代表没有空位。
