# LeetCode 小于等于 K 的最长二进制子序列 题解

## 1. 题目概述

- **标题 / 题号**：小于等于 K 的最长二进制子序列（#2311，medium）
- **链接**：https://leetcode.cn/problems/longest-binary-subsequence-less-than-or-equal-to-k/
- **来源**：LeetCode 第 298 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、位运算、动态规划

**题意**：给定二进制字符串 `s` 和正整数 `k`，选出 `s` 的一个**子序列**，使其按二进制解读的**数值** $\le k$，返回子序列的**最大长度**。

- 子序列允许**前导 0**（前导 0 不改变数值）；
- 空串视为 $0$；
- 子序列 = 删除若干字符后保持顺序的剩余序列。

**约束**：

- $1 \le \text{s.length} \le 1000$
- `s[i]` 为 `'0'` 或 `'1'`
- $1 \le k \le 10^9 < 2^{30}$

> 💡 本题在本仓库另有[每日题解 2311](../../solution/2301-2400/2311_小于等于K的最长二进制子序列.md)：以「前导零免费 + 值位段长度 $\le \lfloor \log_2 k \rfloor + 1$」为主线。本篇按周赛复盘视角展开：侧重**赛场路线取舍（$O(n^2)$ DP 保底 vs $O(n)$ 贪心）**、贪心正确性的**规范形 + 交换论证**完整证明（引理-定理结构）、C++ 移位溢出陷阱与两版对拍自测，两篇互为印证。


## 3. 解题思路

### 3.1 赛场保底思路：$O(n^2)$ DP

从左往右处理字符，新选中的字符追加在子序列**最右侧（最低位）**，数值变化为 $\text{val} \leftarrow \text{val} \times 2 + \text{bit}$。设

$$dp[j] = \text{已处理的前缀中，选出 } j \text{ 个字符时能达成的最小数值（超过 } k \text{ 就钳到 } k+1）$$

转移（`01 背包`式倒序枚举 $j$，保证 `dp[j-1]` 取自上一个字符）：

```text
dp[0] = 0，其余 dp[j] = k+1
for i = 0 .. n-1:
    for j = min(i+1, …) down to 1:
        dp[j] = min(dp[j], dp[j-1] * 2 + bit(s[i]) 截断到 k+1)
答案 = max{ j : dp[j] ≤ k }
```

$n = 1000$ 时约 $10^6$ 次运算，**赛场 10 分钟写完稳过**，是本题的保底路线。但它把「长度」和「数值」的张力交给状态枚举去硬扛，没有利用二进制数的结构。

> 💡 转机：数值只由**每个保留的 `1` 右边选了多少字符**决定——这件事能推出「`0` 免费、`1` 从最低位挑」的线性贪心。

### 3.2 核心观察：`0` 全免费，`1` 的代价由「右边选中的字符数」决定

![核心观察：0 全免费，1 的代价 = 2^(它右边选中的字符数)](images/wc298_q3_greedy_concept.svg)

子序列的数值可以按位分解（引理 1 见第 5 节）：

$$\text{val} = \sum_{\text{保留的 } 1} 2^{\,e_i}, \qquad e_i = \text{该 } 1 \text{ 右侧保留的字符总数（0 和 1 都算）}$$

三个直接推论：

| 观察 | 依据 | 后果 |
|------|------|------|
| **前导 0 免费** | 位于最左保留 `1` 左侧的 `0` 不进入任何 $e_i$，贡献为 $0$ | `0` 尽量全保留 |
| **`1` 越靠右越便宜** | $e_i$ = 右侧 0 数 + 右侧保留 1 数，位置越右 $e_i$ 越小 | `1` 从最低位（最右）挑起 |
| **高位 `1` 必然出局** | $k < 2^{30}$，$e_i \ge 30$ 的 `1` 代价 $> k$ | 只有最低约 30 位内的 `1` 有机会 |

于是得到**贪心**：从右往左扫描，维护已选长度 `len` 与已构成数值 `val`：

- 遇 `'0'`：必留（`len++`）；
- 遇 `'1'`：若 $val + 2^{len} \le k$ 则留（`val += 2^len`，`len++`），否则**跳过**。

跳过一个 `1` 后 `val` 不变、`len` 不减，所以 $2^{len}$ 不减——**更左的 `1` 必然同样装不下**；最终保留的 `1` 恰为 `s` 中最右的 $m^*$ 个。贪心解形态 = **全部 `0` + 最右 $m^*$ 个 `1`**。

### 3.3 算法流程

![算法流程：自右向左扫一遍，0 必留、1 过预算关](images/wc298_q3_scan_flow.svg)

流程要点：

1. **方向必须自右向左**：判定 `1` 的位权需要知道它右边选了几个字符，从右往左扫时该信息是**已确定的**，判定即精确、无需回溯修正；
2. **跳过之后不能 `break`**：更左的 `1` 固然全装不下，但更左的 `0` 仍是免费长度，必须扫完全程；
3. **C++ 防溢出 guard**：$k \le 10^9 < 2^{30}$，`len ≥ 31` 时 $2^{len} > k$ 必跳，用 `len < 31` 短路掉移位（`1 << len` 在 `len ≥ 31` 时是 UB）。

### 3.4 示例演算

![示例演算：s = "1001010"，k = 5 自右向左 7 步](images/wc298_q3_example_walkthrough.svg)

以**示例 1** `s = "1001010", k = 5` 走查（见上图）：$i=6$ 的 `0` 留；$i=5$ 的 `1` 花费 $2^1 = 2 \le 5$ 留；$i=4$ 的 `0` 留；$i=3$ 的 `1` 需 $2 + 2^3 = 10 > 5$ **丢**；$i=2,1$ 的 `0` 继续免费留；$i=0$ 的 `1` 需 $2 + 2^5 = 34 > 5$ 丢。最终 `len = 5`，子序列 `"00010"`（= 2）✓。

换 **$G$ 视角**看同一过程：记 $z$ 为 `0` 的个数（$=4$），$G(m)$ 为「全部 `0` + 最右 $m$ 个 `1`」的数值（$G(1) = 2$、$G(2) = 10$），则 $m^* = \max\{m : G(m) \le k\} = 1$，答案 $= z + m^* = 5$。示例 2 同理：$z = 5$，$G(1) = 1 \le 1 < G(2) = 9$，答案 $6$ ✓。

## 4. 算法细节

1. **位权公式的依赖关系**：保留右侧一个 `1` 会把左侧所有 `1` 的位权各 $+1$（其 $2^e$ 翻倍）。因此必须**从右往左**处理——判定某个 `1` 时，它右侧的保留情况已经固定，$2^{len}$ 就是它的精确贡献。
2. **跳过单调性**：某 `1` 装不下 ⟹ `val` 冻结、`len` 只增不减 ⟹ 更左的 `1` 全部装不下。所以选中集合恰为「最右 $m^*$ 个 `1`」，$m^* = \max\{m : G(m) \le k\}$（$G$ 单调递增，且贪心过程中判定 $q_r$ 的条件恰是 $G(r) \le k$）。
3. **答案公式**：$\text{ans} = z + m^*$，其中 $z = s$ 中 `0` 的个数。先数 `0` 再处理 `1` 的写法与此公式对应；逐字符扫描则把两者合一（`'0'` 分支即累积 $z$）。
4. **溢出防护（C++）**：`val + (1 << len)` 中 `1 << len` 在 `len ≥ 31` 时对 `int` 是 UB。因 $k \le 10^9 < 2^{30}$，`len ≥ 31` 时必跳，用 `len < 31 &&` 短路；移位写成 `1LL << len` 双保险。`val ≤ k < 2^30` 本身 `int` 够用，但用 `long long` 更稳。Python 大整数无此问题。
5. **DP 版的截断技巧**：`dp[j-1] * 2 + bit` 可能远超 `long long`，用 `min(…, k+1)` 钳制——截断只会把「$> k$ 的值」变成 $k+1$，此后转移结果仍 $> k$，不影响最终「$\le k$」判定。
6. **为什么不对 `0` 挑剔**：直觉上丢一个夹在中间的 `0` 顶多让某些 `1` 的位权减半（省一点预算），却直接损失 $1$ 长度；从右往左贪心会自动权衡位权翻倍，无需刻意丢 `0`。严格论证见第 5 节定理（丢 `0` 省下的预算至多换回等量长度的 `1`，不赚）。

## 5. 正确性证明

**记号**：$z$ = `s` 中 `0` 的总数；`1` 的位置自右向左记 $q_1 > q_2 > \cdots > q_M$；$c_r$ = $q_r$ 右侧的 `0` 总数（$c_1 \le c_2 \le \cdots$，位置越左右侧 `0` 越多）；$w_r = 2^{c_r + r - 1}$ = 「`0` 全保留」时从右数第 $r$ 个 `1` 的位权；$G(m) = \sum_{r=1}^{m} w_r$；$m^* = \max\{m \ge 0 : G(m) \le k\}$（$G(0)=0 \le k$，良定义）。

**引理 1（位权分解）**：子序列 $T$ 的数值 $= \sum_{T \text{ 中保留的 } 1} 2^{e}$，$e$ = 该 `1` 右侧保留元素总数。

**证明**：设 $T$ 长度为 $L$，从右数第 $j$ 个字符位于二进制位 $j-1$，故 $\text{val} = \sum_{j=1}^{L} \text{bit}_j \cdot 2^{j-1}$；某位字符为 `1` 时其右侧恰有 $j - 1$ 个保留元素，即 $e = j-1$，逐项对应。∎

**引理 2（贪心形态）**：从右向左扫描、`'0'` 必留、`'1'` 在 $val + 2^{len} \le k$ 时留——保留的 `1` 恰为 $q_1, \ldots, q_{m^*}$，贪心解 $=$ 全部 `0` $+$ 最右 $m^*$ 个 `1`，数值 $G(m^*) \le k$，长度 $z + m^*$。

**证明**：对 $r$ 归纳：处理 $q_r$ 时已选元素 $=$ $q_r$ 右侧全部 `0` 与 $q_1, \ldots, q_{r-1}$，故 $len = c_r + (r-1)$、$val = G(r-1)$，于是 $q_r$ 被保留 $\iff G(r-1) + 2^{c_r + r - 1} = G(r) \le k$。$G$ 单调递增，故 $r \le m^*$ 时全保留、$r > m^*$ 时全跳过。∎

**引理 3（翻倍与压缩）**：$w_{r+1} \ge 2 w_r$；且 $m \ge 1$ 时 $G(m) < w_{m+1}$。

**证明**：$c_{r+1} \ge c_r$，故 $w_{r+1}/w_r = 2^{\,c_{r+1}-c_r+1} \ge 2$。于是 $G(m) \le w_m(1 + \tfrac12 + \tfrac14 + \cdots) < 2 w_m \le w_{m+1}$。∎

**引理 4（规范形）**：任意可行子序列 $T$ 可调整为可行子序列 $T'$，使得：保留的 `1` 恰为某前缀 $q_1, \ldots, q_t$，且最左保留 `1`（$q_t$）左侧的 `0` 全部保留；调整过程值不增、长度不减。

**证明**：设 $T$ 保留 $t$ 个 `1`（$t \ge 1$）与某个 `0` 子集 $D$。分两步：

① **换 `1`（右移）**：把 $T$ 的保留 `1` 换成最右 $t$ 个。从左数第 $s$ 个保留 `1` 的位置由 $q_{\sigma(s)}$ 变为 $q_{t+1-s}$，其中 $\sigma(s) \ge t+1-s$（任意 $t$ 个下标的第 $s$ 大 $\ge$ $\{1..t\}$ 的第 $s$ 大），故新位置**不左于**原位置。由引理 1，其位权 $= 2^{(\text{右侧保留 }0\text{ 数}) + (t-s)}$：右侧保留 `1` 数仍为 $t - s$ 不变；右侧保留 `0` 数因位置右移而**不增**。逐项位权不增，总值不增，仍 $\le k$。

② **补左 `0`**：把 $q_t$ 左侧的所有 `0` 补入。它们不在任何保留 `1` 的右侧，由引理 1 所有位权不变，数值不变，长度增加。∎

**定理**：任意可行子序列的长度 $\le z + m^*$；贪心达到 $z + m^*$。故答案 $= z + m^*$。

**证明**：贪心可行且长度 $z + m^*$（引理 2）。设 $T$ 为任意可行解，取其规范形 $T'$（引理 4）：保留 $t$ 个 `1`、跳过 $h = z - |D'|$ 个 `0`（由规范形，被跳过的 `0` 全在 $q_t$ 右侧）。记 $E_r$ = $q_r$ 右侧被跳过的 `0` 数，则 $E_r \le h$。由引理 1，

$$\text{val}(T') = \sum_{r=1}^{t} w_r \cdot 2^{-E_r} \ \ge\ \frac{G(t)}{2^h}. \qquad (\ast)$$

- $t = 0$：$|T| \le |T'| \le z = z + 0$，成立。
- $t \le m^*$：$|T| \le |T'| = z - h + t \le z + m^*$，成立。
- $t \ge m^*+1$ 且 $h \ge t - m^*$：同样 $|T'| = z - h + t \le z + m^*$，成立。
- $t \ge m^*+1$ 且 $h \le t - m^* - 1$：往证矛盾。记 $w := w_{m^*+1}$。由引理 3 翻倍求和，$G(t) \ge G(m^*) + w\,(2^{\,t-m^*} - 1)$；由 $m^*$ 定义，$k < G(m^*+1) = G(m^*) + w$；由引理 3，$G(m^*) < w$。于是

$$G(t) - 2^h k > G(t) - 2^h\bigl(G(m^*) + w\bigr) = (2^h - 1)\bigl(w - G(m^*)\bigr) + w\bigl(2^{\,t-m^*} - 2^{h+1}\bigr).$$

  若 $h = 0$：$(\ast)$ 给出 $\text{val}(T') \ge G(t) \ge G(m^*+1) > k$，矛盾。若 $h \ge 1$：上式右端第一项 $> 0$（$w > G(m^*)$），第二项 $\ge 0$（$t - m^* \ge h+1$），故 $G(t) > 2^h k$，代入 $(\ast)$ 得 $\text{val}(T') > k$，与 $T'$ 可行矛盾。∎

> 💡 **证明骨架**：换 `1` 右移（值不增）+ 补左 `0`（值不变）把任意解规范化为「前缀 `1` + 左 `0` 全留」；再证明「多保留 $d$ 个 `1` 就必须多跳过至少 $d$ 个 `0`」——跳过 $h$ 个 `0` 至多把每个 `1` 的位权除以 $2^h$，而多出的 $d \ge h+1$ 个 `1` 因位权逐项翻倍，反而把总和抬得更高（翻倍求和 + 等比压缩两处各用一次），预算必然爆掉。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。自右向左单次扫描，每个字符 $O(1)$ 判定；与 $k$ 的位数无关（`len ≥ 31` 后 `1` 全部短路跳过）。
- **空间复杂度**：$O(1)$，仅 `len`、`val`、下标三个变量。
- **对照（DP 保底版）**：时间 $O(n^2)$（每字符更新至多 $n$ 个长度状态）、空间 $O(n)$；$n = 1000$ 时约 $10^6$ 次运算可过，但慢一个量级，且把二进制结构信息完全交给枚举。

## 7. 参考代码

### C++（主解：贪心，O(n)）

```cpp
class Solution {
public:
    int longestSubsequence(string s, int k) {
        int len = 0;          // 已选长度，同时是下一个字符的位权指数
        long long val = 0;    // 已选部分构成的数值（val ≤ k < 2^30）
        for (int i = (int)s.size() - 1; i >= 0; --i) {
            if (s[i] == '0') {
                ++len;                                    // 0 免费，必留
            } else if (len < 31 && val + (1LL << len) <= k) {
                val += 1LL << len;                        // 低位 1 过预算关才留
                ++len;
            }
            // 装不下的 1 直接跳过；更左的 1 位权只增不减，同样装不下
        }
        return len;
    }
};
```

### Python（主解）

```python
class Solution:
    def longestSubsequence(self, s: str, k: int) -> int:
        length = 0
        val = 0
        for ch in reversed(s):          # 自右向左：低位先决策
            if ch == '0':
                length += 1             # 0 免费
            elif val + (1 << length) <= k:   # 大整数，天然无溢出
                val += 1 << length
                length += 1
        return length
```

### Python（DP 保底版：赛场先锁定分数，再回头优化）

```python
class Solution:
    def longestSubsequence(self, s: str, k: int) -> int:
        n = len(s)
        dp = [0] + [k + 1] * n          # dp[j] = 选 j 个字符的最小数值（截断到 k+1）
        for i, ch in enumerate(s):
            bit = 1 if ch == '1' else 0
            for j in range(i + 1, 0, -1):        # 倒序：dp[j-1] 仍是上一字符的值
                cand = min(dp[j - 1] * 2 + bit, k + 1)
                if cand < dp[j]:
                    dp[j] = cand
        return max(j for j in range(n + 1) if dp[j] <= k)
```

> 💡 赛场节奏建议：Q3 看到 $O(n^2)$ DP 可过就先提交锁定分数，再回头推 $O(n)$ 贪心；两版互为**对拍**工具——随机 $n \le 1000$、$k \le 10^9$ 各一千组比对，可验证贪心（含跳过单调性、guard 边界）无死角。

## 8. 边界情况与易错点

1. **C++ 移位溢出（最大陷阱）**：`1 << len` 在 `len ≥ 31` 时对 `int` 是未定义行为——必须 `len < 31` 短路 guard（`k ≤ 10^9 < 2^30` 保证 `len ≥ 31` 时必跳）；Python 大整数无此问题，可省 guard。
2. **跳过后不能 `break`**：某个 `1` 装不下后更左的 `1` 全装不下，但更左的 `0` 仍是免费长度——提前退出会漏数 `0`，样例 1 中 `i=3` 失败后 `i=2,1` 的 `0` 贡献了 2 个长度。
3. **扫描方向反了**：从左往右无法确定当前 `1` 的位权（右侧保留情况未知），位权依赖决定了必须自右向左。
4. **全 `0` 串**：数值 $0 \le k$ 恒可行，答案 $= n$，贪心自然覆盖（无需特判）。
5. **k 与低位全 `1` 相等的临界**：`s = "1111", k = 15` 全保留；`k = 14` 时最高位 `1`（位权 $2^3 = 8$，需 $7 + 8 = 15 > 14$）被跳，答案 3——`≤` 与 `≤ k` 的边界判定要写对符号。
6. **中间量类型**：`val + (1LL << len)` 的瞬间值可超过 `int` 上界吗？guard 下 $2^{len} \le 2^{30}$、$val \le 10^9$，和可到 $\approx 2 \times 10^9 > 2^{31}-1$——`int` 相加会溢出，用 `long long` 存 `val` 并 `1LL` 移位。
7. **DP 版截断别省**：`dp[j-1] * 2 + bit` 不截断会指数膨胀（Python 无妨，C++ 必须钳到 `k+1`）；截断不破坏「$> k$」语义。
8. **读完题面三条注意**：「允许前导 0」「空串视为 0」「子序列不改顺序」——第一条正是「`0` 免费」的合法性来源，漏读会误以为要去前导零。
