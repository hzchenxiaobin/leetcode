# LeetCode 执行操作后元素的最高频率 I 题解

## 1. 题目概述

- **标题 / 题号**：执行操作后元素的最高频率 I（#3346，medium）
- **链接**：https://leetcode.cn/problems/maximum-frequency-of-an-element-after-performing-operations-i/
- **来源**：LeetCode 第 143 场双周赛 Q2
- **难度**：中等
- **标签**：数组、二分查找、前缀和、排序、滑动窗口

**题意**：给定整数数组 `nums` 和两个整数 $k$、`numOperations`。必须**恰好**执行 `numOperations` 次操作，每次操作：

1. 选择一个**此前从未被选择过**的下标 $i$；
2. 把 `nums[i]` 加上 $[-k, k]$ 中的**任意**整数（可以为 $0$）。

操作结束后，返回数组中出现次数最多的元素的出现次数。

两个语义细节决定了整道题的建模方式：

- **必须是恰好 `numOperations` 次**，但每次允许加 $0$，所以"把操作浪费在别的下标上（甚至原地不动）"永远合法，这意味着"操作次数不超上限"是唯一实质约束；
- **每个下标最多被选一次**，所以一个元素最多被"改造"一次，改造代价恒为 $1$ 次操作。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^5$
- $0 \le k \le 10^5$
- $0 \le numOperations \le nums.length$

值域只有 $10^5$，加上 $k$ 之后目标值上界为 $2 \times 10^5$，这为"枚举目标值 + 前缀和"留下了空间。

## 2. 示例

**示例 1**

```text
输入：nums = [1,4,5], k = 1, numOperations = 2
输出：2
解释：把 5 减 1 得到 [1,4,4]，4 出现 2 次；还能顺手用一次操作（对 1 加 0）凑满 2 次。
```

**示例 2**

```text
输入：nums = [5,11,20,20], k = 5, numOperations = 1
输出：2
解释：目标 20 的距离窗口是 [15,25]，只有两个 20 落在里面，它们本来就是 20，不需要操作，
      所以频率是 2；剩下的那次操作无论怎么用都无法让 5 或 11 到达 20。
```

**示例 3（补充）**

```text
输入：nums = [1,2,3], k = 1, numOperations = 3
输出：3
解释：目标取 2，窗口 [1,3] 覆盖全部三个元素；2 本身已是目标，1 与 3 各用 1 次操作变成 2，
      用掉 2 次操作，剩余 1 次对任意下标加 0 即可，最终 [2,2,2]，频率 3。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的做法：枚举最终要堆成的目标值 $x$，再扫一遍数组统计"有多少元素能变成 $x$"，取最大值。

单次扫描 $O(n)$，而目标值最多有 $O(\max(nums) + k) \approx 2 \times 10^5$ 种，总复杂度 $O(n \cdot V) = 2 \times 10^{10}$，无法接受。

瓶颈很明显：**同一份"能变成 $x$ 的元素个数"信息被反复重算**。值域不大，应该用前缀和把它压到 $O(1)$。

### 3.2 核心观察：固定目标值后的频率上界

![固定目标 x：窗口 [x-k, x+k] 内的元素可被改造成 x](images/bw143_q2_window_model.svg)

**观察一（可改造范围）**：元素 $a$ 能变成 $x$，当且仅当

$$\lvert a - x \rvert \le k .$$

**观察二（代价）**：若 $a \ne x$ 且 $\lvert a - x \rvert \le k$，把它变成 $x$ 需要**恰好 1 次**操作（加 $x - a$，落在 $[-k,k]$ 内）；若 $a = x$，则**不需要**操作。

**观察三（次数上限与下标上限同时生效）**：设窗口 $[x-k, x+k]$ 内共有 $c(x)$ 个元素，其中 $f(x)$ 个本来就等于 $x$。那么

- 最多只有 $c(x)$ 个元素能变成 $x$（下标的物理上限）；
- 除 $f(x)$ 个免费元素外，其余每个都要花 1 次操作，且同一元素不能花 2 次，所以被改造的元素数不超过 $\min\big(c(x) - f(x),\ \text{numOperations}\big)$（操作次数上限 + 每下标一次的上限）。

两者合并得到**真正的上界**：

$$\text{freq}(x) \le f(x) + \min\big(c(x) - f(x),\ m\big) = \min\big(c(x),\ f(x) + m\big), \qquad m = \text{numOperations}.$$

这个上界是**可达**的（见 §5 引理 2），所以答案就是

$$\boxed{\ \max_{x}\ \min\big(c(x),\ f(x) + m\big)\ }$$

**观察四（枚举范围）**：$x$ 只需要枚举到 $\max(nums) + k$。超过它窗口为空；而 $x < 1$ 时窗口只会比 $x = 1$ 更窄且 $f(x) = 0$，不会更优。

**观察五（前缀和）**：把值域开成桶 `cnt`，前缀和 `pre` 之后

$$c(x) = \text{pre}\big[\min(x+k,\,V)\big] - \text{pre}\big[\max(x-k,\,1) - 1\big],$$

一次减法即得，枚举所有 $x$ 的总代价 $O(V)$。

### 3.3 算法流程

![算法流程：开桶 → 前缀和 → 枚举目标值](images/bw143_q2_algorithm_flow.svg)

```text
1. 令 V = max(nums) + k
2. cnt[v] = v 在 nums 中出现的次数            # 桶计数
3. pre[v] = cnt[1] + cnt[2] + ... + cnt[v]     # 前缀和
4. ans = 0
5. for x = 1 .. V:
6.     c = pre[min(x+k, V)] - pre[max(x-k, 1) - 1]
7.     ans = max(ans, min(c, cnt[x] + numOperations))
8. return ans
```

### 3.4 示例演算

![示例 1 的演算：目标 4 与目标 5 都能得到频率 2](images/bw143_q2_example_walkthrough.svg)

对示例 1（`nums = [1,4,5]`，$k = 1$，$m = 2$）逐个目标值检查：

| 目标 $x$ | 窗口 $[x-1, x+1]$ | 窗口内元素 | $c(x)$ | $f(x)$ | $\min(c, f+m)$ |
|----------|-------------------|------------|--------|--------|----------------|
| 1 | [0, 2] | {1} | 1 | 1 | 1 |
| 3 | [2, 4] | {4} | 1 | 0 | 1 |
| 4 | [3, 5] | {4, 5} | 2 | 1 | **2** |
| 5 | [4, 6] | {4, 5} | 2 | 1 | **2** |
| 6 | [5, 7] | {5} | 1 | 0 | 1 |

最大值为 2，与示例输出一致。注意目标 4 时 $c = 2$、$f = 1$，只需要 1 次操作就能把 5 变成 4；剩下的 1 次操作对下标 0 加 $0$ 即可，所以"恰好 $m$ 次"并不妨碍答案。

## 4. 算法细节

1. **桶的大小**：`lim = max(nums) + k`，需要 `lim + 1` 个桶（下标 $0 \sim lim$，但只会用到 $1 \sim lim$）。$k$ 可能为 $0$，此时 `lim = max(nums)`。
2. **前缀和的边界**：`pre[0] = 0`，查询窗口时把左端点裁到 $1$、右端点裁到 $lim$，避免负下标与越界。
3. **`cnt[x]` 的取值**：循环中 $x \le lim$，所以直接查 `cnt[x]` 即可，不会越界；$x$ 超出实际值域但不超 $lim$ 时 `cnt[x] = 0`，语义正是"原本没有元素等于 $x$"。
4. **`min` 的两个参数类型**：$c(x) \le 10^5$、$f(x) + m \le 2 \times 10^5$，`int` 足够，不需要 `long long`（与 II 版的值域放大不同）。
5. **为什么不用排序 + 滑动窗口**：值域小是本题的关键附加条件，前缀和写法更短、常数更小；排序法留到 II 版（值域放大到 $10^9$，桶开不下）。
6. **"恰好 $m$ 次"如何满足**：先按上界改造 $g = \min(c - f, m)$ 个元素，剩余的 $m - g$ 次操作施加在**任意尚未被选中的下标**上并加 $0$。因为 $m \le n$ 且已用下标数为 $g \le m$，未用下标至少有 $n - g \ge m - g$ 个，一定够用。
7. **答案不可能超过 $n$**：$\min(c, f+m) \le c \le n$，无需额外裁剪。

## 5. 正确性证明

**引理 1（固定目标的上界）**：对任意目标值 $x$，操作后等于 $x$ 的元素个数不超过 $\min\big(c(x),\ f(x) + m\big)$，其中 $c(x) = \#\{a \in nums : \lvert a - x \rvert \le k\}$，$f(x) = \#\{a \in nums : a = x\}$，$m = $ `numOperations`。

**证明**：设操作后值为 $x$ 的下标集合为 $S$。

- 任何最终等于 $x$ 的元素，要么原本等于 $x$（不加操作），要么被操作过一次且加上了 $x - a$。由于每次把 $a$ 改变的量不超过 $k$，被操作过的元素必然满足 $\lvert a - x \rvert \le k$。因此 $S$ 中所有下标对应的原始值都落在窗口内，$|S| \le c(x)$。
- 另一方面，$S$ 中原本不等于 $x$ 的元素必须**逐个**消耗一次操作（每个下标最多被选一次，不可能靠两次微调凑到），而操作总次数为 $m$，故 $S$ 中"被改造"的元素不超过 $m$ 个。于是 $|S| \le f(x) + m$。

两者取小即得结论。∎

**引理 2（上界可达）**：对每个 $x$，存在一种合法的操作方案，使操作后等于 $x$ 的元素个数恰为 $\min\big(c(x), f(x)+m\big)$。

**证明**：记 $g = \min\big(c(x) - f(x),\ m\big) \ge 0$，它满足 $g \le c(x) - f(x)$ 且 $g \le m$。取窗口内 $g$ 个"原值不等于 $x$"的元素（一定存在，因为这样的元素有 $c(x) - f(x) \ge g$ 个），对每个施加一次操作，加 $x - a \in [-k, k]$；此时已有 $f(x) + g = \min(c(x), f(x)+m)$ 个元素等于 $x$。

接着处理"必须恰好 $m$ 次"：还剩 $m - g \ge 0$ 次操作。把 $n$ 个下标中已用过的 $g$ 个去掉，还剩 $n - g \ge m - g$ 个可用下标（这里用到 $m \le n$），对其中任意 $m - g$ 个各施加一次"加 $0$"的操作即可。这不会改变任何数值，也不会破坏已经凑出的频率。∎

**引理 3（枚举范围充分）**：$\max_{x \in \mathbb{Z}} \min(c(x), f(x)+m) = \max_{1 \le x \le \max(nums)+k} \min(c(x), f(x)+m)$。

**证明**：分两种情况。

- 若 $x > \max(nums) + k$，则对任意元素 $a$ 都有 $a < x - k$，窗口为空，$c(x) = 0$，目标值为 $0$，不可能优于任何可行解。
- 若 $x < 1$，则窗口为 $[x-k, x+k]$ 与 $[1, lim]$ 的交，等于 $[1, \min(x+k, lim)]$，它是 $x = 1$ 时窗口 $[1, \min(1+k, lim)]$ 的子集，故 $c(x) \le c(1)$；又原始值都 $\ge 1 > x$，所以 $f(x) = 0 \le f(1)$。于是 $\min(c(x), 0 + m) \le \min(c(1), f(1) + m)$。

两者说明只需在 $[1, \max(nums)+k]$ 内枚举。∎

**定理**：算法返回的值等于执行 $m$ 次操作后，数组中可能出现的最高频率。

**证明**：设 $\text{ANS}$ 为真实最优值，它对应某个最终众数 $x^\*$。由引理 3 可把 $x^\*$ 换成范围内的某个 $x$，且目标值不减；由引理 1，$\text{ANS} \le \min(c(x^\*), f(x^\*)+m)$，而该值被算法在枚举 $x^\*$ 时取到，故算法输出 $\ge \text{ANS}$；由引理 2，算法枚举到的每个 $\min(c(x), f(x)+m)$ 都有对应的合法操作方案可以实现，故算法输出 $\le \text{ANS}$。两端夹逼得相等。∎

## 6. 复杂度分析

- **时间**：建桶 $O(n)$；求前缀和 $O(V)$，其中 $V = \max(nums) + k \le 2 \times 10^5$；枚举目标值 $O(V)$，每次 $O(1)$。合计 $O(n + V)$。
- **空间**：桶数组与前缀和数组各 $V + 1$ 个 `int`，$O(V)$；不递归，无额外栈开销。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxFrequency(vector<int>& nums, int k, int numOperations) {
        int maxV = 0;
        for (int v : nums) maxV = max(maxV, v);
        int lim = maxV + k;                       // 候选目标值的上界
        vector<int> cnt(lim + 1, 0);
        for (int v : nums) cnt[v]++;
        vector<int> pre(lim + 1, 0);              // pre[v] = cnt[1..v]
        for (int v = 1; v <= lim; v++) pre[v] = pre[v - 1] + cnt[v];

        int best = 0;
        for (int x = 1; x <= lim; x++) {
            int lo = max(x - k, 1), hi = min(x + k, lim);
            int c = (lo > hi) ? 0 : pre[hi] - pre[lo - 1];
            best = max(best, min(c, cnt[x] + numOperations));
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def maxFrequency(self, nums: list, k: int, numOperations: int) -> int:
        mx = max(nums)
        lim = mx + k                      # 候选目标值的上界
        cnt = [0] * (lim + 1)
        for v in nums:
            cnt[v] += 1
        pre = [0] * (lim + 1)             # pre[v] = cnt[1..v]
        for v in range(1, lim + 1):
            pre[v] = pre[v - 1] + cnt[v]

        def rng(lo: int, hi: int) -> int:  # 落在 [lo, hi] 内的元素个数
            lo, hi = max(lo, 1), min(hi, lim)
            return 0 if lo > hi else pre[hi] - pre[lo - 1]

        best = 0
        for x in range(1, lim + 1):
            c = rng(x - k, x + k)          # 能改成 x 的元素个数
            best = max(best, min(c, cnt[x] + numOperations))
        return best
```

## 8. 边界情况与易错点

1. **$k = 0$**：此时元素无法改变数值，$c(x) = f(x)$，答案为最大频次。代码中 $lo = hi = x$，前缀和自然退化为 `cnt[x]`，无需特判。
2. **`numOperations = 0`**：答案为原始最大频次，$\min(c, f+0) = f$ 自动成立。
3. **$n = 1$**：答案恒为 $1$（单个元素凑不出更高频率），代码会返回 $\min(1, 1+m) = 1$。
4. **"恰好 $m$ 次"不等于"至多 $m$ 次"**：如果只想着"用不超过 $m$ 次操作"，会漏掉"剩余操作加 0 也能合法"的推导；务必确认 $m \le n$ 保证还有空余下标可用。
5. **窗口裁剪**：$x - k$ 可能是负数甚至 $-10^5$，必须裁到 $1$；$x + k$ 可能超过桶上界，必须裁到 $lim$，否则数组越界（C++ 直接 RE）。
6. **目标值不能只取数组里已有的值**：`nums = [1,10]`、$k = 5$、$m = 2$ 时答案是 $2$，而能同时覆盖两者的目标是 $x = 5$ 或 $x = 6$（窗口 $[1,11]$），它们都不是 `nums` 中的元素；只枚举 `nums[i]` 会退化成 $1$。正确做法是把整个值域 $[1, \max(nums)+k]$ 都枚举一遍——这只有在值域小（本题 $\le 2 \times 10^5$）时可行。
7. **不要用 `long long` 反被坑**：本题值域小，`int` 足够；若直接套用 II 版的写法（排序 + 二分）也没错，只是慢一些。
8. **别混淆 $c(x) - f(x)$ 与 $c(x)$**：操作次数上限只约束"被改造"的元素，本来就等于 $x$ 的元素不消耗操作，这正是 $f(x) + m$ 而不是 $c(x) + m$ 的原因。
