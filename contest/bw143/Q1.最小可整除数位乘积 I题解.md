# LeetCode 最小可整除数位乘积 I 题解

## 1. 题目概述

- **标题 / 题号**：最小可整除数位乘积 I（#3345，easy）
- **链接**：https://leetcode.cn/problems/smallest-divisible-digit-product-i/
- **来源**：LeetCode 第 143 场双周赛 Q1
- **难度**：简单
- **标签**：数学、枚举

**题意**：给定两个整数 $n$ 和 $t$，返回**大于等于** $n$ 的**最小**整数 $x$，使得 $x$ 各数位之积能被 $t$ 整除。

这里有一个容易被忽略的细节：**只要 $x$ 的十进制表示中含数位 $0$，它的数位之积就是 $0$**，而 $0$ 能被任何正整数整除，于是这类数天然合法。这个细节既是本题的"送分点"，也是枚举上界的来源。

**约束**：

- $1 \le n \le 100$
- $1 \le t \le 10$

数据范围极小，答案一定在 $n$ 附近，所以这是一道标准的签到题：**把"存在性上界"想清楚，再直接枚举**。

## 2. 示例

**示例 1**

```text
输入：n = 10, t = 2
输出：10
解释：10 的数位乘积为 1 * 0 = 0，能被 2 整除，所以 10 本身就是答案。
```

**示例 2**

```text
输入：n = 15, t = 3
输出：16
解释：15 的数位乘积为 5，不能被 3 整除；16 的数位乘积为 6，能被 3 整除。
```

**示例 3（补充）**

```text
输入：n = 11, t = 10
输出：20
解释：11 ~ 19 的数位乘积分别为 1,2,3,...,9，都不能被 10 整除；
      20 的数位乘积为 2 * 0 = 0，能被 10 整除，故答案是 20。
```

三个例子分别覆盖了三种情形：$n$ 自身就合法、需要前进一位、以及需要靠"数位含 0"兜底。

## 3. 解题思路

### 3.1 暴力思路

从 $x = n$ 开始逐个尝试，对每个 $x$ 用"取模 + 整除"求数位乘积，判定能否被 $t$ 整除，第一个满足条件的就是答案。单次判定的代价是 $O(\log x)$。

真正需要回答的问题是：**最坏要试多少个数？** 如果没有上界保证，这段代码就是"可能无限循环"的。下面给出一个干净的上界。

### 3.2 核心观察：答案不超过 $n + 9$

![从 n 起逐个枚举，10 个连续整数内必有 10 的倍数](images/bw143_q1_zero_digit.svg)

- **观察一**：任意 $10$ 个连续整数中恰好有一个是 $10$ 的倍数，其个位为 $0$，数位乘积为 $0$。
- **观察二**：$0$ 能被任意正整数 $t$ 整除（$t \ge 1$）。

于是区间 $[n, n+9]$ 内必然存在 $10$ 的倍数，它一定是合法解，**答案 $\le n + 9$**。这意味着枚举最多 $10$ 个候选数，每次判定 $O(\log x)$，整体是常数级开销。

> 💡 **一句话总结**：本题不用任何技巧，只要意识到"含 0 的数位乘积恒为 0"给出了一层保底，枚举范围就被限制在 $10$ 个数之内。

### 3.3 算法流程

![算法流程：逐个数计算数位乘积并判定整除](images/bw143_q1_algorithm_flow.svg)

```text
1. for x = n, n+1, n+2, ...:
2.     p = 1
3.     y = x
4.     while y > 0:
5.         p *= y % 10          # 取最低位并累乘
6.         y //= 10             # 去掉最低位
7.     if p % t == 0:
8.         return x             # 第一个满足条件的即最小
```

注意第 5 行把数位 $0$ 也照常乘进去，$p$ 立刻变成 $0$，之后无论再乘什么都还是 $0$，不需要额外特判"含 0"。

### 3.4 示例演算

![示例 2 的演算：15 失败、16 成功](images/bw143_q1_example_walkthrough.svg)

以示例 2（$n = 15$，$t = 3$）为例，逐个数走一遍：

| 候选 $x$ | 数位 | 数位乘积 $p$ | $p \bmod 3$ | 结论 |
|----------|------|--------------|-------------|------|
| 15 | 1, 5 | 5 | 2 | 淘汰 |
| 16 | 1, 6 | 6 | 0 | **答案** |

再看示例 3（$n = 11$，$t = 10$）：11 ~ 19 的数位乘积是 $1 \sim 9$，都不能被 $10$ 整除；$20$ 的数位乘积为 $0$，一次命中。它恰好落在 $[11, 20]$ 这个 $10$ 个数的窗口内，印证了 3.2 的上界。

## 4. 算法细节

1. **数位乘积的求法**：反复取 `y % 10` 累乘、`y /= 10` 截断。当 $x$ 含 $0$ 时乘积自然变成 $0$，无需特判。
2. **数值范围**：$x \le 109$，数位乘积最大不超过 $9^3 = 729$，`int` 足够；即便 $x$ 取到 $10^9$ 级别，乘积也只在 $9^9 \approx 3.9 \times 10^8$ 量级，仍然不溢出。
3. **循环一定能停**：由 3.2 的上界保证，最多 $10$ 轮就会出现答案，不必写"死循环"的担心，但代码顺序必须保证**先判定再前进**——否则 $n$ 自身合法时会被漏掉。
4. **整除判定用 `p % t == 0`**：$t \ge 1$ 保证不会除以 $0$。
5. **不需要预处理数位乘积表**：候选只有 10 个，预处理反而更啰嗦。

## 5. 正确性证明

**引理 1（含 0 即合法）**：若整数 $x \ge 0$ 的十进制表示中含数位 $c = 0$，则其数位乘积 $P(x) = 0$，从而对任意 $t \ge 1$ 有 $P(x) \bmod t = 0$。

**证明**：设 $x = \sum_{k} d_k 10^k$，其中某个 $d_{k_0} = 0$。按定义 $P(x) = \prod_k d_k$ 是若干整数之积，其中因子 $d_{k_0} = 0$，故 $P(x) = 0$。又 $0 = 0 \cdot t$，即 $t \mid 0$。∎

**引理 2（存在上界）**：区间 $[n, n+9]$ 中至少存在一个整数，其个位为 $0$，因此本题至少有一个合法解，且最优解不超过 $n + 9$。

**证明**：$10$ 个连续整数模 $10$ 的余数恰好遍历 $0,1,\dots,9$ 各一次，其中余数为 $0$ 的那一个（记为 $x_0 \in [n, n+9]$）是 $10$ 的倍数，其个位为 $0$。由引理 1，$x_0$ 合法。于是合法解集合非空，最小解不超过 $x_0 \le n + 9$。∎

**定理**：算法返回的值等于所有合法整数中的最小值。

**证明**：算法按 $x = n, n+1, n+2, \dots$ 的**递增**顺序逐个判定，并在**第一次**判定成功时立即返回。设返回值为 $x^\*$，则：

1. $x^\*$ 判定成功，故 $x^\*$ 合法；
2. 对任意 $x \in [n, x^\*-1]$，算法都判定过且失败，故这些 $x$ 均不合法。

因此 $x^\*$ 是合法整数中的最小值。再由引理 2，$x^\* \le n + 9$，循环在有限步内结束，算法必然终止。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$ 量级，更准确地说，枚举轮数不超过 $10$（引理 2），每轮求数位乘积需要 $O(\log x)$，故总时间为 $O(10 \log n) = O(1)$。本题 $n \le 100$，实际运算是几十次取模。
- **空间**：$O(1)$，只用了 `p`、`y`、`x` 几个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int smallestNumber(int n, int t) {
        for (int x = n;; x++) {
            int p = 1, y = x;
            while (y > 0) {
                p *= y % 10;
                y /= 10;
            }
            if (p % t == 0) return x;
        }
    }
};
```

### Python

```python
class Solution:
    def smallestNumber(self, n: int, t: int) -> int:
        x = n
        while True:
            p, y = 1, x
            while y > 0:
                p *= y % 10
                y //= 10
            if p % t == 0:
                return x
            x += 1
```

## 8. 边界情况与易错点

1. **$t = 1$ 时答案恒为 $n$**：任何整数都能被 $1$ 整除，此时必须返回 $n$ 本身，循环一轮就命中。若写成"从 $n+1$ 开始试"就会错。
2. **$n$ 自身合法**：如示例 1 的 $n = 10$。判定必须放在递增之前。
3. **含 0 的数不是"非法"，而是"必合法"**：数位乘积为 $0$ 时 `0 % t == 0` 成立，不要额外写"乘积为 0 则跳过"的错误逻辑。
4. **上界不要写成 $n + 100$ 之类的"感觉安全"**：$10$ 个连续整数内必有 $10$ 的倍数，$n+9$ 是紧的（例如 $n = 1$、$t = 10$ 时答案是 $10$，恰好在边界上）。
5. **进位情形**：$n = 99$、$t = 2$ 时答案要跨过 $99 \to 100$（数位乘积 $0$），此时数位乘积的计算必须正确处理 $0$ 位与位数变长。
6. **乘积变量初值**：必须初始化为 $1$ 而不是 $0$，否则一切乘积都是 $0$，程序会把任何数都判成合法。
7. **别忘记 $t$ 可能大于 $9$**：如 $t = 10$ 时只有数位乘积含因子 $2$ 和 $5$ 才行，单个数位 $9$ 显然不够，这时"含 0"兜底才是主要出路。
