# LeetCode 满足距离约束且字典序最小的字符串 题解

## 1. 题目概述

- **标题 / 题号**：满足距离约束且字典序最小的字符串（#3106，medium）
- **链接**：https://leetcode.cn/problems/lexicographically-smallest-string-after-operations-with-constraint/
- **来源**：LeetCode 第 392 场周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串

**题意**：给定字符串 `s` 和整数 `k`。字母 `'a'` 到 `'z'` 按**循环顺序**排列，两个等长字符串的距离 `distance(s1, s2)` 定义为每一位上两字符**最小环形距离**之和（例如 `distance("a", "z") == 1`，`'a'` 与 `'z'` 在环上相邻）。可以对 `s` 执行**任意次**操作，每次把 `s` 中的一个字母改成任意其他小写字母。返回能得到的**字典序最小**的字符串 `t`，满足 `distance(s, t) <= k`。

**约束**：

- $1 \le \text{s.length} \le 100$
- $0 \le k \le 2000$
- `s` 只包含小写英文字母

> ⚠️ 读题两个陷阱：① 字母表是**环形**的——`'z'` 变 `'a'` 只花 1 步，绝不能按 ASCII 差值算距离；② `distance` 对**全串**求和，预算 $k$ 是**全局共享**的一份，不是每位各给 $k$。

## 2. 示例

**示例 1**

```text
输入：s = "zbbz", k = 3
输出："aaaz"
解释：z 花 1 步变 a（跨 z→a 接缝），两个 b 各花 1 步变 a，
      恰好用满预算 3，末位 z 只能原样保留。
```

**示例 2**

```text
输入：s = "xaxcd", k = 4
输出："aawcd"
解释：x 花 3 步变 a（逆时针跨接缝走近路）；第二位本来就是 a；
      剩 1 步预算不够 x→a（要 3 步），只能朝 a 退 1 步变 w；
      后两位预算已空，原样保留。
```

**示例 3**

```text
输入：s = "lol", k = 0
输出："lol"
解释：k = 0，改任何字符都会使距离大于 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个位置改成哪个字母的全部组合——$26^n$ 种方案逐一验证 $\text{distance} \le k$ 再取字典序最小，指数级直接爆炸。退一步的官方提示做法是**从左到右逐位确定**：每个位置从 `'a'` 到 `'z'` 依次尝试，选中第一个「代价不超过剩余预算」的字母，$O(26n)$ 对 $n \le 100$ 绰绰有余。

但其实每个位置的最优字母可以 **$O(1)$ 直接算出来**，根本不用 26 个一个个试——见 3.2。

### 3.2 核心观察：环上双向取近 + 预算从左往右花

![核心概念：字母表成环双向取近，预算从左往右花](images/wc392_q2_cyclic_distance_concept.svg)

三个关键事实：

1. **环上距离，双向取近**。把 `'a'…'z'` 看成首尾相接的 26 格圆环，记当前字母的序号为 $o$（'a' 记 0、'z' 记 25），则它变到 `'a'` 的最短代价为

$$cost = \min(o,\ 26 - o)$$

   顺时针、逆时针两条路取短：`'x'`（$o=23$）变 `'a'` 逆时针跨接缝只要 **3** 步；`'z'` 变 `'a'` 更是只花 **1** 步。

2. **字典序：靠前的位置绝对优先**。两个串比字典序只看**第一个不同的位置**——谁在那里更小谁整体就更小，后面取什么都无法翻盘。所以预算这份「共享资源」必须**从左往右花**：每个位置在「剩余预算 `rem` 买得起」的前提下取**能买到的最小字母**。任何「前面留大一点、省预算给后面」的方案，字典序必然更差。

3. **每个位置 $O(1)$ 定位**。设当前位置序号 $o$、剩余预算 `rem`：

   - 若 $cost = \min(o, 26-o) \le rem$：直接拉到 `'a'`，$rem \mathrel{-}= cost$；
   - 否则 `'a'` **买不起**：$rem < \min(o, 26-o)$ 同时给出 $rem < o$ 与 $o + rem < 26$——无论往哪边走都**跨不过 z/a 接缝**，可达字母恰好是不回绕的区间 $[\,o - rem,\ o + rem\,]$，最小者就是朝 `'a'` 方向退 $rem$ 步的 $o - rem$，且这一步**恰好花光** `rem`，后续位置只能原样保留。

> 💡 一句话：**能变 'a' 就变 'a'；变不到，就朝 'a' 方向用光剩余预算**。每个位置的最小可达字母及其代价都唯一确定（取 'a' 花固定 $cost$，取 $o-rem$ 恰好花光 `rem`），贪心因此顺畅落地。

### 3.3 算法流程

![算法流程：逐位判断够不够到 'a'，不够则朝 'a' 退 rem 步](images/wc392_q2_algorithm_flow.svg)

流程一句话：初始化 `rem = k` → 从左到右扫描每个位置，计算 `o = s[i] - 'a'` 与 `cost = min(o, 26 - o)` → `rem ≥ cost` 则该位变 `'a'` 并扣预算；否则该位变 `'a' + (o - rem)` 并把 `rem` 清零 → 预算归零或扫描结束后返回。全程一次线性扫描，无 DP、无额外数据结构。

### 3.4 示例演算

![示例演算：s=xaxcd, k=4 逐位决策表](images/wc392_q2_example_walkthrough.svg)

以示例 2（`s = "xaxcd"`，`k = 4`）走一遍（逐步决策见上图）：

| i | s[i] | o | cost | 决策 | t[i] | rem |
|---|------|---|------|------|------|-----|
| 0 | x | 23 | 3 | $3 \le 4$：变 'a' | a | 1 |
| 1 | a | 0 | 0 | 白嫖 'a' | a | 1 |
| 2 | x | 23 | 3 | $3 > 1$：退 1 步变 'w' | w | 0 |
| 3 | c | 2 | 2 | 预算空，原样 | c | 0 |
| 4 | d | 3 | 3 | 预算空，原样 | d | 0 |

结果 `"aawcd"`，验证 $\text{distance} = 3 + 0 + 1 + 0 + 0 = 4 \le k$ ✓。示例 1（`"zbbz"`，k=3）：z 花 1、b 花 1、b 花 1，恰好用满预算得 `"aaaz"`；示例 3（k=0）：一位都动不了，原样返回 `"lol"`。

## 4. 算法细节

1. **代价公式的来历**：环上从 $o$ 到 $0$（'a'）只有两条路——序号一路递减 $o$ 步，或一路递增跨过接缝 $26 - o$ 步，取 $\min$。这与题设 `distance("a", "z") == 1` 自洽（$1 = \min(25, 26-25)$）。
2. **买不起 `'a'` 时为何恰好是 $o - rem$**：$rem < \min(o, 26-o)$ 同时给出 $rem < o$（往回走不到 0）与 $o + rem < 26$（往前跨不过接缝），于是预算 $rem$ 圈出的可达弧是不回绕的整数区间 $[o-rem,\ o+rem]$，最小字母即左端点 $o - rem$；从 $o$ 走到 $o - rem$ 恰花 $rem$ 步，预算一次清零。
3. **提前退出**：`rem` 归零后任何修改都会使 `distance` 超预算，后续字符一律原样保留——循环条件直接并入 `rem > 0`。
4. **实现载体**：C++ 直接原地修改 `s`；Python 字符串不可变，转 `list` 改完 `join`。
5. **接口名**：LeetCode 函数签名为 `getSmallestString(string s, int k)`。

## 5. 正确性证明

**引理 1（单点可达集）**：设某位置原字符序号为 $o$、该位置可花费的预算为 $rem$，记 $\mathrm{dist}(o, c) = \min(|o - c|,\ 26 - |o - c|)$。则该位置可变成的字符集合为 $\{c : \mathrm{dist}(o, c) \le rem\}$，其中的最小字符是：

- `'a'`（序号 0），当 $\min(o, 26 - o) \le rem$，代价为 $\min(o, 26 - o)$；
- 序号 $o - rem$，当 $\min(o, 26 - o) > rem$，代价恰为 $rem$。

**证明**：若 $\min(o, 26-o) \le rem$，则 $\mathrm{dist}(o, 0) = \min(o, 26-o) \le rem$，'a' 可达；而 'a' 是全字符集最小者，结论成立。若 $\min(o, 26-o) > rem$，则 $rem < o$ 且 $rem < 26 - o$。对任意序号 $c \in [0, 25]$：

- $o - rem \le c \le o + rem$ 时 $|o - c| \le rem$，故 $\mathrm{dist}(o, c) \le rem$，可达；
- $c < o - rem$ 时 $o - c \ge rem + 1$，且 $26 - (o - c) \ge 26 - o > rem$，两个方向都超过 $rem$，不可达；
- $c > o + rem$ 时 $c - o \ge rem + 1$，且 $26 - (c - o) \ge 26 - (25 - o) = o + 1 > rem$，不可达。

故可达集恰为区间 $[o - rem,\ o + rem]$，最小字符为 $o - rem$，其代价 $\mathrm{dist}(o, o - rem) = rem$。∎

**引理 2（前缀相同 ⇒ 剩余预算相同）**：任一方案在各位置花费的代价只由该位置的原字符与新字符决定，总代价为逐位求和。故两个方案若在位置 $0..j-1$ 上取值完全相同，则它们到达位置 $j$ 时已花费的预算相同，剩余预算也相同。

**证明**：$\text{distance}(s, t) = \sum_{i=0}^{n-1} \mathrm{dist}(o_i, t_i)$，求和各项互相独立，前 $j$ 项只由前 $j$ 个位置的取值决定。∎

**定理**：贪心算法（每位取当前剩余预算下可达的最小字符）输出的 $t$ 是满足 $\text{distance}(s, t) \le k$ 的字典序最小串。

**证明**：先证**可行性**：由引理 1，每位所选字符的代价都不超过当时的剩余预算（两种情形分别为 $\min(o, 26-o) \le rem$ 与恰好等于 $rem$），逐位扣减后总代价 $\le k$。再证**最小性**：反证，设存在可行解 $t^*$ 满足 $t^* < t$（字典序）。设 $j$ 为第一个 $t^*[j] \ne t[j]$ 的位置，则 $t^*[j] < t[j]$，且两串在 $j$ 之前完全相同。由引理 2，$t^*$ 到达位置 $j$ 时的剩余预算与贪心相同，记为 $rem$。由 $t^*$ 可行，其在 $j$ 及之后各位的代价总和 $\le rem$，特别地 $\mathrm{dist}(o_j, t^*[j]) \le rem$，即 $t^*[j]$ 是预算 $rem$ 下的可达字符。但贪心取的 $t[j]$ 是可达字符中的**最小者**，故 $t[j] \le t^*[j]$，与 $t^*[j] < t[j]$ 矛盾。故不存在比 $t$ 更小的可行解。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个位置一次 $\min$ 加一次比较即 $O(1)$ 定位，单趟线性扫描；对比逐个试字母的 $O(26n)$ 写法，$n \le 100$ 下两者都绰绰有余。
- **空间复杂度**：$O(1)$。C++ 原地修改；Python 需转 `list` 再 `join`（输出本身占 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string getSmallestString(string s, int k) {
        for (int i = 0; i < (int)s.size() && k > 0; ++i) {
            int o = s[i] - 'a';            // 当前字母的环上序号
            int cost = min(o, 26 - o);     // 到 'a' 的最短代价（双向取近）
            if (k >= cost) {               // 买得起：直接拉到 'a'
                s[i] = 'a';
                k -= cost;
            } else {                       // 买不起：朝 'a' 退 k 步，花光预算
                s[i] = 'a' + (o - k);
                k = 0;
            }
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def getSmallestString(self, s: str, k: int) -> str:
        t = list(s)
        for i, ch in enumerate(t):
            if k == 0:
                break
            o = ord(ch) - ord('a')      # 环上序号
            cost = min(o, 26 - o)       # 到 'a' 的最短代价
            if k >= cost:
                t[i] = 'a'
                k -= cost
            else:                       # 朝 'a' 退 k 步，花光预算
                t[i] = chr(ord('a') + o - k)
                k = 0
        return ''.join(t)
```

## 8. 边界情况与易错点

1. **$k = 0$**（示例 3）：一位都不能动，原样返回；循环条件带 `k > 0` 即自然覆盖。
2. **环形陷阱**：`'z'` 变 `'a'` 只花 1 步、`'x'` 变 `'a'` 只要 3 步——按 ASCII 差值算距离必然出错，凡环上距离一律写 $\min(o, 26-o)$。
3. **预算全局共享**：`distance` 是全串求和，不是每位各给 $k$；「前面留大一点、省预算给后面」在字典序标准下永远不优（§5 定理）。
4. **买不起时必须退满 `rem` 步**：朝 'a' 方向每多退一步字符就更小，所以要一步用光预算退到 $o - rem$；只退 1 步既浪费预算又让本位偏大，两头亏。
5. **`'a'` 白嫖**：本来就是 `'a'` 的位置代价为 0，不消耗预算，扫描时自然跳过。
6. **$k$ 富余**：$k$ 上限 2000 可远超最大可能距离 $13n$（$n = 1$ 时仅 13），此时全串变 `'a'`，算法自然处理，无需特判。
7. **无溢出风险**：$n \le 100$、$k \le 2000$，`int` 足够，无需 `long long`。
