# LeetCode 矩阵查询可获得的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：矩阵查询可获得的最大分数（#2588，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-points-from-grid-queries/
- **来源**：LeetCode 第 323 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、堆（优先队列）、排序、离线查询、并查集

**题意**：给定 $m \times n$ 的整数矩阵 `grid` 和长度为 $k$ 的数组 `queries`。对每个 $q = \text{queries}[i]$，从**左上角**单元格出发，重复以下过程：

- 若 $q$ **严格大于**当前单元格的值，且该单元格是第一次访问，则得 $1$ 分，并可以移动到上下左右任一**相邻**单元格；
- 否则不能得分，过程立即结束。

过程结束后 $\text{answer}[i]$ 为可获得的最大分数。同一单元格可以多次经过，但只有首次访问得分。

**约束**：

- $2 \le m, n \le 1000$，$4 \le m \cdot n \le 10^5$
- $k = \text{queries.length}$，$1 \le k \le 10^4$
- $1 \le \text{grid}[i][j], \text{queries}[i] \le 10^6$

> 💡 读题先抓两个信号：①「固定起点 + 阈值比较 + 可达即得分」本质是**连通性问题**；② $k$ 个查询共用同一矩阵，且阈值 $q$ 越大能走的格子越多——**答案关于 $q$ 单调不减**，这强烈暗示把查询离线排序后只做一次整体扩张。

## 2. 示例

**示例 1**

```text
输入：grid = [[1,2,3],[2,5,7],[3,5,1]], queries = [5,6,2]
输出：[5,8,1]

解释：
q = 5：可到达并得分的格子值为 1,2,3,2,3（5 和 7 挡路）→ 5 分
q = 6：除值为 7 的格子外全部可达 → 8 分
q = 2：只有左上角 1 满足 2 > 1 → 1 分
```

**示例 2**

```text
输入：grid = [[5,2,1],[1,1,2]], queries = [3]
输出：[0]

解释：左上角单元格值为 5，不满足 3 > 5，出发即结束，得 0 分。
```

**示例 3（自造，强调「严格小于」与孤立格子）**

```text
输入：grid = [[2,1],[1,3]], queries = [2,3,4]
输出：[0,3,4]

解释：
q = 2：2 > 2 不成立（不是 ≥ 也不是 >），左上角都进不去 → 0 分
q = 3：2、1、1 都可达，但 3 > 3 不成立，右下角进不去 → 3 分
q = 4：全部 4 格可达 → 4 分
```

## 3. 解题思路

### 3.1 暴力思路：每个查询独立 BFS

对每个 $q$ 独立做一次 BFS：从 $(0,0)$ 出发，只走值 $< q$ 的格子，能访问到的格子数就是答案（若 $\text{grid}[0][0] \ge q$ 则答案为 $0$）。

单次 BFS 是 $O(mn)$，总计 $O(k \cdot mn)$。代入本题规模 $k \le 10^4$、$mn \le 10^5$，最坏 $10^9$ 次操作，**超时**。

瓶颈在于：相邻两个查询可能只差一点点阈值，却各自从头 BFS。既然答案单调，就该把 $k$ 次 BFS **合并成一次渐进扩张**。

### 3.2 核心观察：答案是阈值连通块，且关于 q 单调

**观察一（问题转化）**：固定 $q$，过程能得分的格子，恰好是「从 $(0,0)$ 出发、只经过值 $< q$ 的格子」所能到达的**连通块**。因为：

- 想在某格得分，必须先合法地走到它（每一步移动都要求出发格值 $< q$）；
- 反过来，连通块内的格子总能按 BFS 序一个个走过去并各得 1 分。

**观察二（单调性）**：$q_1 \le q_2 \Rightarrow$ 「值 $< q_1$」区域是「值 $< q_2$」区域的子集，因此连通块只增不减，$\text{answer}(q)$ 单调不减。

于是把 `queries` **升序排序后离线处理**：整体只扩张一次，用**最小堆**维护当前扩张边界，每个 $q$ 只处理「增量」格子。

![阈值 q 下的可达连通块](images/wc323_q4_threshold_component.svg)

上图中 $q=5$：绿色 5 格可达；值为 5 的格子因「不严格小于 5」挡住扩张；(2,2) 的值虽为 1，但被 5、5、7 围死，**不可达也不得分**——这正是很多人会算错的地方：不是所有小值格子都能得分，**必须连通**。

### 3.3 算法流程：最小堆维护扩张边界

堆中存放 `(格子值, 行, 列)`，语义是**已发现、尚未计数的边界格子**：

1. 初始把 $(\text{grid}[0][0], 0, 0)$ 入堆并标记 visited，$\text{cnt} = 0$；
2. 按 $q$ 升序遍历查询：当**堆顶格子的值 $< q$** 时，弹出它（$\text{cnt}+1$），把它尚未入过堆的邻居入堆；
3. 堆顶值 $\ge q$（或堆空）时停下，$\text{cnt}$ 即为该查询的答案，回填到其**原下标**。

![离线升序 + 最小堆扩张流程图](images/wc323_q4_heap_flow.svg)

两个关键细节：

- **visited 在入堆时标记**（而非出堆时），保证每个格子至多入堆一次，总代价 $O(mn \log mn)$；
- 堆天然按值升序弹出，等效于「水位上涨时逐格淹没」，既不漏也不重。

### 3.4 示例演算

对示例 1 走查全过程（弹出序列见下图）：

- $q=2$：弹出 $1@(0,0)$，$\text{cnt}=1$；堆顶为 2，不满足 $<2$，停止 → $\text{answer}[2]=1$；
- $q=5$：依次弹出 $2,2,3,3$（堆中留下 $5,5,7$），$\text{cnt}=5$ → $\text{answer}[0]=5$；
- $q=6$：依次弹出 $5,5,1$（堆中留下 $7$），$\text{cnt}=8$ → $\text{answer}[1]=8$。

![示例 1 三次查询的逐步演算](images/wc323_q4_walkthrough.svg)

最终按原下标回填得 $\text{answer} = [5, 8, 1]$，与官方输出一致。

## 4. 算法细节

1. **离线排序**：对查询下标按值升序排序，处理完再按原下标回填，避免打乱输出顺序。
2. **坐标编码**：C++ 中把 $(r, c)$ 编码为 $r \cdot n + c$，堆元素用 `pair<int,int>`（值，位置），比较简洁且省内存。
3. **visited 时机**：入堆时立即标记。若在出堆时才标记，同一格子可能被多个已弹出邻居反复入堆，堆体积退化到 $O(4mn)$ 且常数大。
4. **弹出条件是严格小于**：`heap.top().first < q`，对应题面「queries[i] 严格大于当前单元格」，等于不行。
5. **重复查询值**：排序后相同值相邻，第二个查询进入 while 循环时堆顶条件不变、循环体不执行，直接沿用当前 $\text{cnt}$，天然正确。
6. **替代方案（并查集）**：把所有格子按值升序排序，查询也升序；双指针逐个「激活」值 $< q$ 的格子，激活时与已激活邻居 union。答案为 $(0,0)$ 所在集合大小（若 $(0,0)$ 已激活）。复杂度同为 $O(mn \log mn)$，堆做法常数更小、代码更短，本文采用堆。

## 5. 正确性证明

**引理 1（问题转化）**：对阈值 $q$，能获得的最大分数等于集合 $S(q) = \{c : \text{grid}[c] < q\}$ 中包含 $(0,0)$ 的连通块大小（若 $\text{grid}[0][0] \ge q$ 则为 $0$）。

**证明**：

- （上界）设某次游戏得分为 $t$，按时间顺序踩过的格子依次为 $p_0 = (0,0), p_1, \dots$。要移动出 $p_{i-1}$，必须满足 $q > \text{grid}[p_{i-1}]$；要得分还必须 $q > \text{grid}[p_i]$。一旦踩到值 $\ge q$ 的格子，过程立即终止。因此所有**得分的格子**都在 $S(q)$ 中、相邻连续、且从 $(0,0)$ 出发可达，即落在同一连通块内，$t \le |CC|$。
- （下界）若 $\text{grid}[0][0] < q$，按 BFS 生成树顺序访问连通块：每次从已访问格移动到未访问的相邻格，当前格值 $< q$，移动合法，每格恰好得分一次，故 $t \ge |CC|$。若 $\text{grid}[0][0] \ge q$，第一步判断即失败，得分为 $0$。∎

**引理 2（单调性）**：$q_1 \le q_2 \Rightarrow S(q_1) \subseteq S(q_2)$，故 $\text{answer}(q)$ 单调不减。

**证明**：$c \in S(q_1)$ 即 $\text{grid}[c] < q_1 \le q_2$，即 $c \in S(q_2)$；子图的连通块只会扩大或保持。∎

**引理 3（堆不变量）**：任意时刻，堆中恰为「已发现但未计数」的格子（初始的 $(0,0)$，或某个已计数格子的未发现邻居），且每个格子至多入堆一次。

**证明**：入堆仅发生在初始化与弹出某格之后将其未标记邻居入堆，且入堆时立即标记，故每格至多入堆一次、堆内元素均为已发现未计数者。∎

**定理**：按 $q$ 升序处理，处理完查询 $q$ 后 $\text{cnt} = |CC_{S(q)}((0,0))|$。

**证明**：

- （$\text{cnt} \le |CC|$）：对弹出次序归纳。$(0,0)$ 被弹出说明弹出时堆顶 $< q' \le q$（$q'$ 为当时查询值），故 $(0,0) \in S(q)$。任一格 $u$ 被弹出时，其值 $< q' \le q$，即 $u \in S(q)$；且 $u$ 入堆是因为某相邻格 $w$ 先被弹出，由归纳假设 $w \in CC$，加上 $u \in S(q)$ 且与 $w$ 相邻，得 $u \in CC$。
- （$|CC| \le \text{cnt}$）：反设存在 $u \in CC$ 未被计数。取 $CC$ 中从 $(0,0)$ 到 $u$ 的一条路径，设 $v_i$ 是路径上第一个未计数的格，则 $v_{i-1}$ 已计数，其弹出时已把 $v_i$ 入堆；$v_i$ 至今未弹出，仍在堆中，且 $\text{grid}[v_i] < q$。这与 while 循环终止条件「堆空或堆顶值 $\ge q$」矛盾（堆顶值 $\le \text{grid}[v_i] < q$）。∎

由引理 1、引理 2 与定理，算法对每个查询输出正确的最大得分。

## 6. 复杂度分析

- **时间复杂度**：$O(mn \log(mn) + k \log k)$
  - 每个格子至多入堆、出堆各一次，堆操作单次 $O(\log(mn))$；
  - 查询排序 $O(k \log k)$，内层 while 循环整体摊销到每个格子一次；
  - 代入 $mn \le 10^5$、$k \le 10^4$，约 $2 \times 10^6$ 级别的堆操作，轻松通过。
- **空间复杂度**：$O(mn + k)$
  - `visited` 数组与堆 $O(mn)$，答案与下标数组 $O(k)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> maxPoints(vector<vector<int>>& grid, vector<int>& queries) {
        int m = grid.size(), n = grid[0].size();
        int k = queries.size();

        // 离线：查询按值升序，记录原下标
        vector<int> idx(k);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(),
             [&](int a, int b) { return queries[a] < queries[b]; });

        vector<int> ans(k, 0);
        vector<char> visited(m * n, 0);

        // 最小堆：(格子值, r * n + c)
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> pq;
        pq.push({grid[0][0], 0});
        visited[0] = 1;

        int cnt = 0;
        int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};

        for (int qi : idx) {
            int q = queries[qi];
            // 堆顶值严格小于 q 才弹出
            while (!pq.empty() && pq.top().first < q) {
                auto [v, pos] = pq.top();
                pq.pop();
                ++cnt;
                int r = pos / n, c = pos % n;
                for (int d = 0; d < 4; ++d) {
                    int nr = r + dr[d], nc = c + dc[d];
                    if (nr >= 0 && nr < m && nc >= 0 && nc < n &&
                        !visited[nr * n + nc]) {
                        visited[nr * n + nc] = 1;
                        pq.push({grid[nr][nc], nr * n + nc});
                    }
                }
            }
            ans[qi] = cnt; // 当前累计即为该阈值答案
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxPoints(self, grid: List[List[int]], queries: List[int]) -> List[int]:
        m, n = len(grid), len(grid[0])
        k = len(queries)

        order = sorted(range(k), key=lambda i: queries[i])
        ans = [0] * k
        visited = [[False] * n for _ in range(m)]

        heap = [(grid[0][0], 0, 0)]
        visited[0][0] = True
        cnt = 0

        for qi in order:
            q = queries[qi]
            # 堆顶值严格小于 q 才弹出
            while heap and heap[0][0] < q:
                v, r, c = heappop(heap)
                cnt += 1
                for nr, nc in ((r - 1, c), (r + 1, c), (r, c - 1), (r, c + 1)):
                    if 0 <= nr < m and 0 <= nc < n and not visited[nr][nc]:
                        visited[nr][nc] = True
                        heappush(heap, (grid[nr][nc], nr, nc))
            ans[qi] = cnt
        return ans
```

## 8. 边界情况与易错点

1. **左上角被挡死**：$\text{grid}[0][0] \ge q$ 时答案为 $0$（示例 2）。堆写法无需特判——堆顶条件不满足，$\text{cnt}$ 保持 $0$，自然正确。
2. **「严格大于」陷阱**：$q$ 必须严格大于格子值，$q = \text{grid}$ 值时既不得分也不能通行。示例 3 的 $q=2$ 与 $q=3$ 分别踩中这两个坑。
3. **小值但孤立的格子不可达**：如示例 1 中 $(2,2)=1$，值小于 $q$ 却被大值包围。答案统计的是**连通块**而不是「所有值 $< q$ 的格子」，用错误统计的贪心会多算。
4. **恢复原下标**：输出顺序必须与输入 `queries` 一致，离线排序后要按 `qi` 回填，直接按处理顺序输出必错。
5. **visited 标记时机**：必须在**入堆时**标记，否则同一格子会被多个邻居重复入堆，浪费时间和内存。
6. **重复查询值**：排序后相邻，第二个相同值不触发任何弹出，直接复用 $\text{cnt}$，无需去重。
7. **数据类型**：值域 $\le 10^6$、计数 $\le 10^5$，`int` 足够；但 C++ 堆比较需 `greater<>`（默认 `priority_queue` 是大根堆，方向反了会全错）。
8. **别用 BFS 逐查询**：$O(k \cdot mn)$ 达 $10^9$；也别按格值全局排序后对每个查询二分计数——不检查连通性会踩坑 3。

**延伸思考**：

- **在线查询怎么做？** 一次性把堆扩张跑完，记录每个格子被弹出时的阈值（即沿路径的「最大值瓶颈」最小化），得到每个格子的可达阈值 $\text{th}(c)$；把所有 $\text{th}(c)$ 排序后做前缀计数，每次查询二分即可 $O(\log(mn))$ 回答——本质是最小瓶颈连通性问题，可支持动态到达的查询流。
- **若每格得分是格子的值而非 1 分？** 把扩张时的 `cnt + 1` 改成累加格子值即可（或并查集维护块内和），连通块计数变连通块求和，其余不变。
- **若起点不固定？** 多起点就把所有起点同时入堆（多源 BFS / 虚拟超级源点），或并查集把起点集合预先 union，结论照搬。
