# LeetCode 设计内存分配器 题解

## 1. 题目概述

- **标题 / 题号**：设计内存分配器（#2502，medium）
- **链接**：https://leetcode.cn/problems/design-memory-allocator/
- **来源**：LeetCode 第 323 场周赛 Q3
- **难度**：中等
- **标签**：设计、数组、哈希表、模拟

**题意**：用下标 $0$ 到 $n-1$ 表示 $n$ 个内存单元，初始全部空闲，实现以下接口：

- `Allocator(int n)`：初始化大小为 $n$ 的内存。
- `allocate(int size, int mID)`：找到**最左侧**长度为 `size` 的连续空闲块，将其中每个单元标记为 `mID`，返回块的起始下标；找不到则返回 $-1$。
- `freeMemory(int mID)`：释放所有标记为 `mID` 的单元，返回释放的单元数。

同一个 `mID` 可以分配给多次调用产生的不同内存块；释放时必须把这些块全部释放。

**约束**：

- $1 \le n,\ \text{size},\ \text{mID} \le 1000$
- 最多调用 `allocate` 和 `freeMemory` 共 $1000$ 次

> 💡 约束是本题的关键提示：每次操作扫描整个数组只需 $O(n)$，所有操作合计约 $10^6$ 次单元访问，直接模拟已经足够，不必引入复杂的区间数据结构。
>
> 本仓库另有[每日题解 2502](../../solution/2501-2600/2502_设计内存分配器.md)，其中包含空闲段集合扩展与面试问答。本篇按周赛复盘结构展开，侧重扫描不变式、最左性证明以及释放操作的边界情况。

## 2. 示例

**示例 1**

```text
输入：

[[10], [1,1], [1,2], [1,3], [2], [3,4], [1,1], [1,1], [1], [10,2], [7]]

输出：
[null, 0, 1, 2, 1, 3, 1, 6, 3, -1, 0]

关键过程：
- 前三次分配依次占用下标 0、1、2。
- freeMemory(2) 只释放下标 1，返回 1。
- allocate(3,4) 找到下标 [3,5]，返回 3。
- 接下来两次 allocate(1,1) 分别占用下标 1 和 6。
- freeMemory(1) 同时释放下标 0、1、6，返回 3。
- 此时没有 10 个连续空闲单元，allocate(10,2) 返回 -1；mID=7 不存在，释放返回 0。
```

**示例 2：总空闲空间足够，不代表连续空间足够**

```text
输入：
["Allocator", "allocate", "allocate", "freeMemory", "allocate", "allocate"]
[[5], [2,1], [2,2], [1], [3,3], [2,3]]

输出：
[null, 0, 2, 2, -1, 0]

解释：
释放 mID=1 后，内存为 [·,·,2,2,·]，共有 3 个空闲单元，
```

**示例 3：整块占满与重复释放**

```text

[[3], [3,5], [1,6], [5], [5]]

输出：
[null, 0, -1, 3, 0]

解释：
第一次分配占满整个内存；再次分配失败。
```

## 3. 解题思路

### 3.1 暴力思路：枚举起点，逐格检查

对 `allocate(size, mID)`，可以从小到大枚举每个候选起点 $s$，再检查区间 $[s,s+\text{size}-1]$ 是否全部空闲。找到第一个合法区间后就写入 `mID` 并返回 $s$；全部起点都不合法则返回 $-1$。

这个做法正确，在本题约束下也可能通过，但单次 `allocate` 最坏需要检查 $O(n\cdot\text{size})$ 个单元，即 $O(n^2)$。相邻候选区间大量重叠，同一段空闲内存会被反复检查。

`freeMemory(mID)` 没有额外的位置索引，只能遍历整个数组，将所有等于 `mID` 的单元置为空闲并计数，时间为 $O(n)$。

> ⚠️ 优化的关键不是更换复杂数据结构，而是复用上一次扫描得到的信息：走到下标 $i$ 时，直接知道“以 $i$ 结尾有多少个连续空闲单元”。

### 3.2 核心观察：一次扫描维护连续空闲长度

![连续空闲长度 run 与最左分配起点](images/wc323_q3_free_run.svg)

用一个整数数组 `mem` 表示内存：

- `mem[i] == 0`：单元 $i$ 空闲；
- `mem[i] != 0`：单元 $i$ 已分配给对应的 `mID`。

由于题目保证 $\text{mID}\ge 1$，所以 $0$ 可以安全地作为空闲标记。

扫描时维护变量 `run`，其含义是：**以当前下标 $i$ 结尾的连续空闲单元数**。

- 若 `mem[i] == 0`，执行 `run += 1`；
- 若 `mem[i] != 0`，连续空闲被打断，执行 `run = 0`；
- 当 `run == size` 时，区间 $[i-\text{size}+1,i]$ 恰好是长度为 `size` 的连续空闲块，立即分配并返回起点。

因为扫描方向是从左到右，而且在 `run` **第一次**达到 `size` 时立即停止，所以找到的块一定最左。无需枚举其他块，也无需记录所有空闲区间。

### 3.3 算法流程：分配与释放各扫描一趟

![allocate 与 freeMemory 的单趟扫描流程](images/wc323_q3_algorithm_flow.svg)

`allocate(size, mID)` 的流程：

1. 令 `run = 0`，从下标 $0$ 开始向右扫描。
2. 遇到已分配单元就将 `run` 清零；遇到空闲单元就将 `run` 加一。
3. 若 `run == size`，计算 `start = i - size + 1`，把 `mem[start..i]` 全部写成 `mID`，返回 `start`。
4. 扫描结束仍未命中，返回 $-1$，且不修改任何单元。

`freeMemory(mID)` 的流程：

1. 令计数器 `count = 0`。
2. 遍历整个 `mem`，每当 `mem[i] == mID`，就令 `mem[i] = 0` 并执行 `count += 1`。
3. 返回 `count`。

> 💡 分配成功后的写入最多涉及 `size` 个单元，而 `size <= n`，因此写入不会改变单次操作 $O(n)$ 的复杂度。

### 3.4 示例演算

![题目示例中的内存状态变化](images/wc323_q3_example_walkthrough.svg)

以示例 1 为例，重点关注三次操作：

1. **`allocate(3,4)`**：释放下标 1 后，内存为 `[1,·,3,·,·,·,·,·,·,·]`。下标 1 只有一个空闲单元，不足以容纳长度 3；扫描到下标 5 时，`run` 第一次达到 3，因此分配 $[3,5]$，返回 $3$。
2. **第二次 `allocate(1,1)`**：此前下标 1 已被前一次 `allocate(1,1)` 占用，扫描到下标 6 才首次命中，所以返回 $6$，说明“最左”是相对于**当前内存状态**而言的。
3. **`freeMemory(1)`**：`mID=1` 的单元位于下标 0、1、6，分属不同分配块。全数组扫描会把它们全部清零，返回 $3$，而不是只释放某一块。

最后调用 `allocate(10,2)` 时，虽然还有空闲单元，但最长连续空闲段长度小于 10，`run` 永远无法达到 `size`，因此返回 $-1$ 且内存保持不变。

## 4. 算法细节

1. **只保存每个单元的归属**：本题不需要记录分配块的起止位置。分配结果已经完整编码在 `mem` 中，释放时按单元值匹配即可。
2. **`run` 必须在已分配单元处清零**：否则会跨越占用单元拼接两段空闲区域，把不连续的内存错误地分配给一次调用。
3. **命中后立即返回**：判断应写成 `run == size`。由于命中就返回，`run` 不会继续增长到大于 `size`；同时首次命中保证了最左性。
4. **先完成查找，再统一写入**：只有确认整个区间合法后才修改 `mem`。扫描结束仍未命中时直接返回 $-1$，天然满足失败分配不得修改内存的要求。
5. **释放必须遍历全数组**：同一 `mID` 可以散落在多个不连续块中，找到一处匹配后不能提前停止。
6. **无需合并空闲段**：数组表示下，相邻的空闲单元天然构成连续空闲段，下一次 `allocate` 会通过 `run` 自动识别，不需要额外维护区间合并。

## 5. 正确性证明

**引理 1（`run` 的扫描不变式）**：在 `allocate` 尚未返回时，处理完下标 $i$ 后，`run` 等于以 $i$ 结尾的连续空闲单元数；若 $i$ 已分配，则该值为 $0$。

**证明**：对扫描下标归纳。初始尚未扫描任何单元，`run=0`。假设处理下标 $i-1$ 后结论成立：

- 若 `mem[i]` 已分配，以 $i$ 结尾没有非空的连续空闲段，算法令 `run=0`，结论成立。
- 若 `mem[i]` 空闲，以 $i$ 结尾的连续空闲段恰好是在以 $i-1$ 结尾的连续空闲段后追加单元 $i$。由归纳假设，原 `run` 是前一段长度，加一后即为新长度。

因此归纳成立。∎

**引理 2（最左分配与失败判定）**：`allocate` 返回的起点是所有长度为 `size` 的连续空闲块中最小的起点；若返回 $-1$，则不存在这样的块。

**证明**：若算法在下标 $i$ 处命中，由引理 1，$[i-\text{size}+1,i]$ 中的 `size` 个单元全部空闲，因此返回值 $s=i-\text{size}+1$ 是合法起点。假设还存在更小的合法起点 $s'<s$，其终点为 $i'=s'+\text{size}-1<i$。仍由引理 1，扫描到 $i'$ 时 `run` 应达到 `size`，算法会在那里提前返回，与扫描到 $i$ 才首次命中矛盾。因此 $s$ 最左。

若存在任意合法块，设其终点为 $j$，扫描到 $j$ 时由引理 1 必有 `run == size`，算法必然命中。因此扫描完整数组仍未命中，就等价于不存在合法块，返回 $-1$ 正确。∎

**引理 3（释放的完整性与计数）**：`freeMemory(mID)` 执行后，内存中不再有任何标记为该 `mID` 的单元，其他单元保持不变，返回值恰好等于本次释放的单元数。

**证明**：算法遍历每个下标恰好一次。对于值等于 `mID` 的单元，将其改为 $0$ 并令计数加一；对于其他单元不作修改。因此所有目标单元都被释放，非目标单元不受影响，计数与发生改写的单元一一对应。∎

**定理**：上述 `Allocator` 实现满足题目规定的构造、分配和释放语义。

**证明**：构造函数将所有单元设为 $0$，符合初始全部空闲。由引理 2，`allocate` 成功时找到最左合法块；实现只把该块内的单元写成 `mID` 并返回其起点，其他单元不变。失败时不执行写入并返回 $-1$。由引理 3，`freeMemory` 释放指定 `mID` 的全部单元、保留其他单元并返回正确数量。三个接口均满足题意。∎

## 6. 复杂度分析

- **构造函数**：时间 $O(n)$，用于创建并初始化长度为 $n$ 的数组；空间 $O(n)$。
- **`allocate`**：时间 $O(n)$。查找最多扫描 $n$ 个单元，成功后写入至多 `size` 个单元，而 $\text{size}\le n$；辅助变量只使用 $O(1)$ 额外空间。
- **`freeMemory`**：时间 $O(n)$，需要遍历整个数组；额外空间 $O(1)$。
- **整体**：若共有 $q$ 次分配或释放调用，总时间为 $O(qn)$。本题 $q,n\le 1000$，最多约 $10^6$ 量级的扫描操作；持久存储空间为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Allocator {
    vector<int> mem;

public:
    Allocator(int n) : mem(n, 0) {}

    int allocate(int size, int mID) {
        int run = 0;
        for (int i = 0; i < static_cast<int>(mem.size()); ++i) {
            if (mem[i] != 0) {
                run = 0;
                continue;
            }
            ++run;
            if (run == size) {
                int start = i - size + 1;
                for (int j = start; j <= i; ++j) {
                    mem[j] = mID;
                }
                return start;
            }
        }
        return -1;
    }

    int freeMemory(int mID) {
        int count = 0;
        for (int& value : mem) {
            if (value == mID) {
                value = 0;
                ++count;
            }
        }
        return count;
    }
};
```

### Python

```python
class Allocator:
    def __init__(self, n: int):
        self.mem = [0] * n

    def allocate(self, size: int, mID: int) -> int:
        run = 0
        for i, value in enumerate(self.mem):
            if value != 0:
                run = 0
                continue
            run += 1
            if run == size:
                start = i - size + 1
                self.mem[start:i + 1] = [mID] * size
                return start
        return -1

    def freeMemory(self, mID: int) -> int:
        count = 0
        for i, value in enumerate(self.mem):
            if value == mID:
                self.mem[i] = 0
                count += 1
        return count
```

## 8. 边界情况与易错点

1. **`size > n`**：不需要单独特判。`run` 最大只能达到 $n$，不可能等于 `size`，扫描结束自然返回 $-1$，也不会出现负下标写入。
2. **块恰好位于数组末尾**：当 $i=n-1$ 且 `run == size` 时，起点 $n-\text{size}$ 合法，循环内会立即处理，不会漏掉末尾块。
3. **连续空闲被占用单元打断**：必须在 `mem[i] != 0` 时清零 `run`，否则可能跨过占用单元错误分配。
4. **分配失败不能留下部分写入**：参考实现先找到完整块再写入；不要在尚未确认长度足够时边扫描边占用。
5. **同一 `mID` 对应多个块**：释放时不能在第一处匹配后停止，也不能只释放最近一次分配；必须扫描全数组。
6. **释放不存在的 `mID`**：计数保持为 $0$，内存不变，直接返回 $0$；重复释放同一 `mID` 也遵循这一逻辑。
7. **空闲标记不能取合法 `mID`**：本题 `mID >= 1`，所以使用 $0$ 表示空闲。若扩展题允许 `mID=0`，必须换用其他标记或额外记录占用状态。
8. **总空闲数与连续空闲数不同**：碎片可能导致空闲单元总数足够但分配仍失败，不能用全局空闲计数代替连续段扫描。
