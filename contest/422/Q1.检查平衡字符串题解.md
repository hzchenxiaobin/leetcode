# LeetCode 检查平衡字符串 题解

## 1. 题目概述

- **标题 / 题号**：检查平衡字符串（#3340，easy）
- **链接**：https://leetcode.cn/problems/check-balanced-string/
- **来源**：LeetCode 第 422 场周赛 Q1
- **难度**：简单
- **标签**：字符串、一次遍历、奇偶分桶

**题意**：给定一个仅由数字 $0 \sim 9$ 组成的字符串 `num`。若**偶数下标**处的数字之和等于**奇数下标**处的数字之和，则称 `num` 为**平衡字符串**。是则返回 `true`，否则返回 `false`。

**约束**：

- $2 \le \text{num.length} \le 100$
- `num` 仅由数字 $0 \sim 9$ 组成

> 💡 **读题关键**：判的是**下标 $i$ 的奇偶**，不是数字本身的奇偶。`num[0]` 永远进偶桶（$0$ 也是偶数）。签到题的目标是从题面到代码走最短路径，一遍扫描两个计数器即可。

## 2. 示例

**示例 1**

```text
输入：num = "1234"
输出：false
解释：偶数下标之和为 1 + 3 = 4，奇数下标之和为 2 + 4 = 6，4 ≠ 6。
```

**示例 2**

```text
输入：num = "24123"
输出：true
解释：偶数下标之和为 2 + 1 + 3 = 6，奇数下标之和为 4 + 2 = 6，两者相等。
```

**示例 3**（最短输入）

```text
输入：num = "11"
输出：true
解释：偶数下标之和为 1，奇数下标之和为 1，两者相等。
```

## 3. 解题思路

### 3.1 暴力思路：切片分组再求和

最省事的做法是按下标奇偶把字符分成两组，各自求和再比较。Python 里隔位切片一行就能写完：

```python
sum(map(int, num[::2])) == sum(map(int, num[1::2]))
```

正确性显然，$n \le 100$ 时也完全够快。但拆开看有两个小浪费：**两次遍历**同一段字符串，且切片各拷贝出一份 $O(n)$ 的临时序列。既然每个字符**只属于一个桶**，一遍扫描就能同时喂饱两个累加器——这是签到题里最值得沉淀的一步。

### 3.2 核心观察：下标奇偶是天然的二分桶

![核心观察：下标奇偶天然分桶，双计数器一遍扫](images/balanced_string_odd_even_concept.svg)

三条观察：

**观察一：分桶互斥且完备。** 每个下标 $i$ 要么满足 $i \bmod 2 = 0$（进偶桶 `even`），要么进奇桶 `odd`，没有第三个去处，也不会重复入桶。所以一次遍历里做一次二选一即可。

**观察二：只需求和，无需存桶。** 最终只比较两桶之和，不必真的把字符存进两个列表，两个 `int` 计数器足够。

**观察三：数据规模极小。** 两桶之和至多 $50 \times 9 = 450$，任何整型都毫无溢出压力，考的是**写得干净**，不是算得快。

### 3.3 算法流程

```text
even ← 0, odd ← 0
for i = 0 to n-1:
    d ← num[i] 对应数值
    if i % 2 == 0: even ← even + d
    else:          odd  ← odd + d
return even == odd
```

### 3.4 示例演算

对 `num = "24123"`（true）与 `num = "1234"`（false）各走一遍：

| $i$ | num[$i$] | 入桶 | even | odd |
|-----|----------|------|------|-----|
| 0 | 2 | 偶 | 2 | 0 |
| 1 | 4 | 奇 | 2 | 4 |
| 2 | 1 | 偶 | 3 | 4 |
| 3 | 2 | 奇 | 3 | 6 |
| 4 | 3 | 偶 | **6** | **6** |

$6 = 6$，返回 `true` ✓

![示例演算：一遍扫描双计数器](images/balanced_string_walkthrough.svg)

## 4. 算法细节

1. **字符转数值**：C++ 用 `num[i] - '0'`，Python 用 `int(ch)` 或 `ord(ch) - ord('0')`，别直接拿字符参与求和（见 §8 第 4 条）。
2. **奇偶判断**：`i % 2 == 0` 与 `i & 1 == 0` 等价，位运算稍快，本题无感。
3. **双计数器可合成一个**：维护带符号差 $diff = even - odd$，偶下标加、奇下标减，最后判 $diff = 0$。少一个变量，可读性见仁见智。
4. **Python 切片版**仍是合格的备选（见 3.1），面试口述时两版都值得展示。

## 5. 正确性证明

**引理 1**：下标集合 $\{0, 1, \dots, n-1\}$ 按 $i \bmod 2$ 的取值划分为互斥且完备的两类。

**证明**：由取模定义，$i \bmod 2 \in \{0, 1\}$，每个下标恰取一值，故两类不重不漏。∎

**定理**：算法返回 `true` 当且仅当 `num` 是平衡字符串。

**证明**：遍历中每个字符 `num[i]` 恰被访问一次；由引理 1，其数值恰被累加进 `even`（$i$ 偶）或 `odd`（$i$ 奇）之一，不重不漏。循环结束时

$$\text{even} = \sum_{i \bmod 2 = 0} \text{num}[i], \qquad \text{odd} = \sum_{i \bmod 2 = 1} \text{num}[i]$$

返回值 `even == odd` 与平衡字符串的定义逐字等价。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n = \text{num.length} \le 100$。单次遍历，每个字符常数处理。
- **空间复杂度**：$O(1)$。仅两个整型计数器，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isBalanced(string num) {
        int even = 0, odd = 0;
        for (int i = 0; i < (int)num.size(); ++i) {
            if (i % 2 == 0) even += num[i] - '0';
            else            odd  += num[i] - '0';
        }
        return even == odd;
    }
};
```

### Python

```python
class Solution:
    def isBalanced(self, num: str) -> bool:
        even = odd = 0
        for i, ch in enumerate(num):
            if i % 2 == 0:
                even += int(ch)
            else:
                odd += int(ch)
        return even == odd
```

## 8. 边界情况与易错点

1. **下标从 0 开始**：「偶数下标」= 第 1、3、5… 个字符，`num[0]` 永远进偶桶（$0$ 是偶数）。
2. **下标奇偶 ≠ 数值奇偶**：`num = "12"` 中数字 2 虽是偶数，却因下标为 1 进奇桶，判的是**位置**不是**数字**。
3. **最短输入 $n = 2$**：如 `"11" → true`、`"12" → false`，此时两桶各恰有一个元素。
4. **忘记 `- '0'`**：C++ 直接累加字符会混入 ASCII 偏移 48。两桶元素个数分别为 $\lceil n/2 \rceil$ 与 $\lfloor n/2 \rfloor$，当 $n$ 为偶数时偏移相同**侥幸不错**，$n$ 为奇数时必错——属于"半数用例通过"的隐蔽 bug，排查时优先检查这里。
5. **无溢出风险**：和至多 $50 \times 9 = 450$，`int` 绰绰有余，无需任何特判。
