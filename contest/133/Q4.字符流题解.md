# LeetCode 字符流 题解

## 1. 题目概述

- **标题 / 题号**：字符流（#1032，hard）
- **链接**：https://leetcode.cn/problems/stream-of-characters/
- **来源**：LeetCode 第 133 场周赛 Q4
- **难度**：困难
- **标签**：设计、字典树、字符串、数据流

**题意**：设计一个数据结构 `StreamChecker`：

- `StreamChecker(String[] words)`：用单词表初始化；
- `boolean query(char letter)`：从字符流中接收一个新字符，若**当前字符流的任一非空后缀**恰好等于 `words` 中的某个字符串，返回 `true`，否则返回 `false`。

**约束**：

- $1 \le words.length \le 2000$
- $1 \le words[i].length \le 200$
- `words[i]` 与 `letter` 均为小写字母
- 最多调用 `query` $4 \times 10^4$ 次

> 💡 后缀匹配的反面是**前缀匹配**：把单词反转后建字典树，再从流的**最新字符**往回走，问题就变成「从根出发能否走到某个单词结尾」。

```text
      query('l') → true （流 "...l"，后缀 "kl" 命中）
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：把字符流拼成一个字符串 $S$，每次 `query` 后检查 $S$ 的所有后缀是否在 `words` 中：

- 后缀有 $|S|$ 个，每个要在单词表里查找（用哈希集合是 $O(|S|)$ 的字符串哈希，或 $O(|S| \cdot |w|)$ 的朴素比较）；
- 查询 $Q = 4 \times 10^4$ 次、流长度可达 $4 \times 10^4$ 时，总复杂度 $O(Q \cdot L)$ 或更差，**无法通过**。

即使只检查长度不超过 $\max|w|$ 的后缀，每个后缀的哈希计算也要 $O(1)$ 均摊（滚动哈希），总计 $O(Q \cdot \max|w|) = 8 \times 10^6$——这其实是可行的，但需要处理哈希冲突。字典树给出的是**无冲突**的确定性版本。

### 3.2 核心观察：后缀 → 反向前缀

![反向字典树：从最新字符往回走](images/wc133_q4_reverse_trie.svg)

**观察一（反转）**：$S$ 的后缀 $S[|S|-k..|S|-1]$ 等于 `words` 中的 $w$ $\iff$ 把 $w$ 反转后，它是「流反转串」的**前缀**。于是把每个 $w$ **反转**后插入字典树，问题变成「从根出发沿流的倒序字符走，能否走到某个单词结尾」。

**观察二（只需最近 $\max|w|$ 个字符）**：任何单词长度不超过 $M = \max_i |w_i|$。流的更早字符不可能构成任何一个后缀（后缀最多取 $M$ 个字符），所以只需保留最近 $M$ 个字符。

**观察三（每次查到底）**：每次 `query(c)`：

1. 把 $c$ 放到缓冲区**最前面**（缓冲区按「由新到旧」排列）；
2. 从字典树根出发，按缓冲区顺序（新 → 旧）逐字符下走；
3. 中途若某个节点标记为单词结尾，立即返回 `true`；
4. 走不动（无对应孩子）或缓冲区耗尽，返回 `false`。

单次复杂度 $O(M)$，总复杂度 $O(Q \cdot M) = 4\times10^4 \times 200 = 8 \times 10^6$，轻松通过。

> 💡 为什么不用「AC 自动机」？AC 自动机解决的是「多个模式串在长文本中的出现位置」，本题是**在线**查询且只关心「后缀是否命中」，反转 Trie + 每步 $O(M)$ 已经足够；若查询次数更多，可以保留「上次走到的节点链」做均摊 $O(1)$ 优化。

### 3.3 算法流程

![算法流程：建反向 Trie → 维护缓冲 → 每次回溯走 Trie](images/wc133_q4_algorithm_flow.svg)

```text
构造：
1. trie = 只有根的字典树，M = 0
2. for w in words:
       M = max(M, len(w))
       cur = root
       for ch in reversed(w):
           若 cur 无 ch 孩子: 新建节点
           cur = cur 的 ch 孩子
       cur.isEnd = true
3. buf = 空双端队列（存最近 M 个字符，新字符在前）

query(c):
1. buf.push_front(c)；若 len(buf) > M: buf.pop_back()
2. cur = root
3. for ch in buf（从新到旧）:
       若 cur 无 ch 孩子: 返回 false
       cur = cur 的 ch 孩子
       若 cur.isEnd: 返回 true
4. 返回 false
```

## 4. 算法细节

1. **反转插入**：`for (int k = w.size()-1; k >= 0; k--)`，插入的是 `w[k]`。
2. **缓冲区方向**：把新字符放在**队首**，遍历时天然「从新到旧」，与 Trie 的反向结构对应；用 `deque`（C++ `std::deque`，Python `collections.deque`）。
3. **缓冲区截断**：`if (buf.size() > M) buf.pop_back();`，丢弃最旧的字符。
4. **`isEnd` 标记**：在插入结束的节点上置 true；注意单词可能互为前缀（如 `"a"` 与 `"ab"`），必须每个词尾都标记，遍历时**每走一步都要检查**，不能只看最后一步。
5. **节点存储**：C++ 用 `vector<Node>` + 数组 `next[26]`（或 `unordered_map`），Python 用 `list` + `dict`。$2000 \times 200 = 4\times10^5$ 个字符，节点数不超过这个量级。
6. **提前返回**：走到词尾立即返回 true，不必走完整个缓冲区。
7. **空缓冲区**：第一次 `query` 前缓冲区为空，`query` 会先放入字符，故至少走一步。
8. **不要每次重新扫描整个流**：流长度可达 $4\times10^4$，截断到 $M$ 是性能关键。

## 5. 正确性证明

记字符流当前内容为 $S = s_1 s_2 \cdots s_L$（$s_L$ 是刚加入的字符），$M = \max_i |w_i|$。

**引理 1（反转对应）**：对任意单词 $w$ 与任意 $k = |w|$，$S$ 的长度为 $k$ 的后缀等于 $w$ $\iff$ $w$ 的反转是「$S$ 的反转」的长度为 $k$ 的前缀。

**证明**：$S[L-k+1..L] = w$ 逐字符等价于对 $t = 1..k$ 有 $s_{L-k+t} = w[t]$，即 $S$ 的倒序前 $k$ 个字符 $s_L, s_{L-1}, \dots, s_{L-k+1}$ 依次等于 $w[k], w[k-1], \dots, w[1]$，正是 $\text{reverse}(w)$。∎

**引理 2（缓冲区足够）**：若存在长度 $k \le M$ 的后缀等于某单词，则该后缀完全落在最近 $M$ 个字符之内。

**证明**：长度 $k \le M$ 的后缀由 $S$ 的最后 $k$ 个字符组成，而最后 $k$ 个字符属于最后 $M$ 个字符。长度 $> M$ 的后缀不可能等于任何单词（所有单词长度 $\le M$）。∎

**引理 3（Trie 行走等价于后缀存在性）**：从根出发按缓冲区（新→旧）每走一步，若在第 $k$ 步到达标记为词尾的节点，则存在长度恰为 $k$ 的后缀等于对应单词；反之若某长度 $k \le M$ 的后缀等于单词 $w$，则 Trie 沿缓冲区走 $k$ 步必然成功，并在第 $k$ 步到达 $w$ 的词尾节点。

**证明**：Trie 中从根出发的路径与「反转单词的前缀」一一对应（构造时按反转字符逐层插入）。缓冲区前 $k$ 个字符是 $S$ 的最后 $k$ 个字符的倒序。由引理 1，该倒序前缀等于 $\text{reverse}(w)$ $\iff$ 后缀等于 $w$。因此「能走到词尾节点」与「后缀命中」等价；Trie 是确定性结构，路径唯一，不会误判。∎

**定理**：`query` 返回 true 当且仅当当前字符流存在非空后缀等于 `words` 中某串。

**证明**：（$\Rightarrow$）返回 true 说明某步到达词尾节点，由引理 3 存在对应后缀命中。（$\Leftarrow$）若存在命中后缀，设长度 $k \ge 1$；由引理 2 它在缓冲区中；由引理 3 遍历第 $k$ 步会到达词尾并返回 true。∎

## 6. 复杂度分析

- **构造时间**：$O(\sum_i |w_i|) \le 2000 \times 200 = 4 \times 10^5$ 次插入操作。
- **单次查询时间**：$O(M)$，$M \le 200$；总计 $O(Q \cdot M) = 8 \times 10^6$。
- **空间**：Trie 节点数 $O(\sum_i |w_i|)$，缓冲区 $O(M)$。
- **对比**：暴力「拼全流 + 检查所有后缀」为 $O(Q \cdot L \cdot |w|)$，在 $Q, L = 4\times 10^4$ 时不可行。

## 7. 参考代码

### C++

```cpp
class StreamChecker {
    struct Node {
        int next[26];
        bool isEnd;
        Node() : isEnd(false) { fill(next, next + 26, -1); }
    };

    vector<Node> trie;
    deque<char> buf;          // 最近 M 个字符，新字符在队首
    int maxLen;

public:
    StreamChecker(vector<string>& words) : maxLen(0) {
        trie.emplace_back();                  // 根节点
        for (const string& w : words) {
            maxLen = max(maxLen, (int)w.size());
            int cur = 0;
            for (int k = (int)w.size() - 1; k >= 0; k--) {   // 反向插入
                int c = w[k] - 'a';
                if (trie[cur].next[c] == -1) {
                    trie[cur].next[c] = (int)trie.size();
                    trie.emplace_back();
                }
                cur = trie[cur].next[c];
            }
            trie[cur].isEnd = true;
        }
    }

    bool query(char letter) {
        buf.push_front(letter);
        if ((int)buf.size() > maxLen) buf.pop_back();

        int cur = 0;
        for (char ch : buf) {                 // 从最新字符往回走
            int c = ch - 'a';
            if (trie[cur].next[c] == -1) return false;
            cur = trie[cur].next[c];
            if (trie[cur].isEnd) return true; // 每步都要判词尾（词可能互为前缀）
        }
        return false;
    }
};
```

### Python

```python
from collections import deque


class StreamChecker:
    def __init__(self, words: list[str]):
        self.nxt = [{}]          # 每个节点：字符 → 子节点下标
        self.is_end = [False]
        self.max_len = 0
        for w in words:
            self.max_len = max(self.max_len, len(w))
            cur = 0
            for ch in reversed(w):               # 反向插入
                to = self.nxt[cur].get(ch)
                if to is None:
                    to = len(self.nxt)
                    self.nxt[cur][ch] = to
                    self.nxt.append({})
                    self.is_end.append(False)
                cur = to
            self.is_end[cur] = True
        self.buf = deque()   # 最近 max_len 个字符，新字符在队首

    def query(self, letter: str) -> bool:
        self.buf.appendleft(letter)
        if len(self.buf) > self.max_len:
            self.buf.pop()

        cur = 0
        for ch in self.buf:                      # 从最新字符往回走
            cur = self.nxt[cur].get(ch, -1)
            if cur == -1:
                return False
            if self.is_end[cur]:
                return True                      # 每步都要判词尾
        return False
```

## 8. 边界情况与易错点

1. **单词互为前缀**：`words = ["a","ab"]` 时，`"ba"` 流的后缀 `"a"` 命中；遍历必须在**每一步**检查 `isEnd`，只在末尾检查会漏掉短词。
2. **缓冲区截断**：忘记 `pop_back` 会让缓冲区无限增长，单次查询退化为 $O(L)$，总复杂度爆炸。
3. **反转方向**：插入时必须反转单词（`reversed(w)`），否则匹配的是「前缀」而不是「后缀」。
4. **缓冲区方向**：新字符放队首，遍历顺序即「新→旧」；若放队尾再从后往前遍历，逻辑相同但容易写错。
5. **单词长度 1**：如 `"f"`，走一步就到词尾，必须立即返回 true。
6. **重复单词**：重复插入同一单词只是重复置 `isEnd = true`，无副作用。
7. **查询次数上限**：$4 \times 10^4$ 次，每次 $O(M)$ 足够；不要写 $O(M^2)$ 或 $O(L)$ 的实现。
8. **内存**：节点数不超过 $4 \times 10^5$，C++ 用 `vector<Node>` 时注意 `emplace_back` 后引用失效——用下标访问即可（代码中均用 `cur` 下标）。
