# LeetCode 两个无重叠子数组的最大和 题解

## 1. 题目概述

- **标题 / 题号**：两个无重叠子数组的最大和（#1031，medium）
- **链接**：https://leetcode.cn/problems/maximum-sum-of-two-non-overlapping-subarrays/
- **来源**：LeetCode 第 133 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、滑动窗口、前缀和

**题意**：给定整数数组 `nums` 与两个长度 `firstLen`、`secondLen`，在数组中找两个**不重叠**的子数组（连续），长度分别为 `firstLen` 与 `secondLen`，使二者元素之和最大。返回这个最大和。

两个子数组的先后顺序不限（`firstLen` 的在左或在右都允许），但它们不能有公共下标。

**约束**：

- $1 \le firstLen, secondLen \le 1000$
- $2 \le firstLen + secondLen \le 1000$
- $firstLen + secondLen \le nums.length \le 1000$
- $0 \le nums[i] \le 1000$

> 💡 因为 `nums[i] ≥ 0`，窗口和随长度单调不减；但下面的解法并不依赖非负性，对任意整数都成立。

## 2. 示例

**示例 1**

```text
输入：nums = [0,6,5,2,2,5,1,9,4], firstLen = 1, secondLen = 2
输出：20
解释：选 [9]（下标 7）与 [6,5]（下标 1、2），和 9 + 11 = 20。
```

**示例 2**

```text
输入：nums = [3,8,1,3,2,1,8,9,0], firstLen = 3, secondLen = 2
输出：29
解释：选 [3,8,1]（下标 0..2）与 [8,9]（下标 6、7），和 12 + 17 = 29。
```

**示例 3**

```text
输入：nums = [2,1,5,6,0,9,5,0,3,8], firstLen = 4, secondLen = 3
输出：31
解释：选 [5,6,0,9]（下标 2..5）与 [0,3,8]（下标 6..8），和 20 + 11 = 31。
```

## 3. 解题思路

### 3.1 暴力思路

枚举两个子数组的起点 $(i, j)$，判断是否重叠（$i + L \le j$ 或 $j + M \le i$），再求两段和。

- 起点对共 $O(n^2)$ 个，若每次再累加 $O(L + M)$，总复杂度 $O(n^2(L+M))$，$n = 1000$ 时约 $2 \times 10^9$，超时。
- 即使用前缀和把求和降到 $O(1)$，仍要枚举 $O(n^2)$ 对起点，约 $10^6$ 次——**这个其实能过**，但不是最优，而且实现里容易把「不重叠」判错。

### 3.2 核心观察：固定第二段，第一段只需「它左边的最优窗口」

![前缀最优：第二段左侧任意位置的定长窗口最大值](images/wc133_q3_prefix_best.svg)

设第一段长度为 $L$、第二段长度为 $M$。先只考虑「$L$ 段在左、$M$ 段在右」的情形：

- 枚举 $M$ 段的起点 $i$（它占据 $[i, i+M-1]$）；
- 此时 $L$ 段必须完全落在 $[0, i-1]$ 内，即它的右端点 $\le i - 1$；
- 记

$$pre[i] = \max\{\, sum(nums[j-L+1..j]) : L-1 \le j \le i \,\}$$

即「右端点不超过 $i$ 的所有长度 $L$ 窗口和的最大值」。那么以 $i$ 为 $M$ 段起点时，最优解是

$$pre[i-1] + sum(nums[i..i+M-1])$$

对所有合法的 $i$ 取最大即可。$pre$ 可以在 $O(n)$ 内递推得到：

$$pre[i] = \max\bigl(pre[i-1],\ sum(nums[i-L+1..i])\bigr)$$

**两种顺序都要算**：$L$ 在左、$M$ 在右；以及 $M$ 在左、$L$ 在右。取两者较大值。

> 💡 这是「**定长窗口 + 前缀最优**」的模板：只要约束是「两段不能重叠」，固定其中一段，另一段就退化成「某个前缀上的最优定长窗口」，用一次扫描把 $pre$ 预处理出来即可。

### 3.3 算法流程

![算法流程：前缀和 → 前缀最优 → 枚举第二段](images/wc133_q3_algorithm_flow.svg)

```text
solve(L, M):                    # L 在左，M 在右
    pre = 前缀和，pref[k] = nums[0..k-1] 之和
    best = 0，res = 0
    for i = 0 .. n-M:           # 枚举 M 段起点 i
        j = i - 1               # L 段右端点最多到 i-1
        if j >= L-1:
            best = max(best, pref[j+1] - pref[j+1-L])
        if j >= L-1:
            res = max(res, best + (pref[i+M] - pref[i]))
    return res

答案 = max(solve(firstLen, secondLen), solve(secondLen, firstLen))
```

### 3.4 示例演算

![示例演算：[0,6,5,2,2,5,1,9,4]，L=1，M=2](images/wc133_q3_walkthrough.svg)

对 `nums = [0,6,5,2,2,5,1,9,4]`、$L = 1$、$M = 2$：

| $i$（$M$ 段起点） | 窗口 $nums[i..i+1]$ | 和 | $j = i-1$ | $best$（$L=1$ 的前缀最优） | 候选 |
|---|---|---|---|---|---|
| 0 | [0,6] | 6 | −1 | 不可用 | — |
| 1 | [6,5] | 11 | 0 | 0 | 11 |
| 2 | [5,2] | 7 | 1 | 6 | 13 |
| 3 | [2,2] | 4 | 2 | 6 | 10 |
| 4 | [2,5] | 7 | 3 | 6 | 13 |
| 5 | [5,1] | 6 | 4 | 6 | 12 |
| 6 | [1,9] | 10 | 5 | 6 | 16 |
| 7 | [9,4] | 13 | 6 | 6 | 19 |

咦，这里得到 19，但答案是 20？因为上面算的是「$L=1$ 段在左、$M=2$ 段在右」的情形。最优解的 $L$ 段（`[9]`，下标 7）其实在**右边**，属于另一个方向：$M = 2$ 在左、$L = 1$ 在右。在 `solve(2, 1)` 中，$L=2$ 的段取 `[6,5]`（和 11）、$M=1$ 的段取右侧的 `[9]`（和 9），合计 20 ✓。

这个例子恰好说明：**两种顺序缺一不可**，只算一个方向会漏掉最优解。

## 4. 算法细节

1. **前缀和**：`pref[k] = sum(nums[0..k-1])`，则窗口 $[a, b]$ 的和为 `pref[b+1] - pref[a]`。
2. **`pre` 的语义**：`best` 表示「右端点 $\le i-1$ 的长度 $L$ 窗口最大和」，每轮先尝试把右端点为 $i-1$ 的窗口并入，再与 $M$ 段组合。
3. **合法性判断**：$j \ge L - 1$ 才存在长度 $L$ 的窗口（其右端点为 $j$ 时起点 $j-L+1 \ge 0$）。
4. **两个方向**：`solve(L, M)` 与 `solve(M, L)` 各算一次取 max；两端长度相等时两次结果相同，可以跳过其中一次（不影响正确性）。
5. **初始化**：`best = 0`、`res = 0`；因 `nums[i] \ge 0`，答案非负，用 0 初始化安全；若允许负数，应初始化为极小值并用 `bool` 标记 `best` 是否有效。
6. **复杂度**：每个方向 $O(n)$，总 $O(n)$；空间 $O(n)$（前缀和数组）。
7. **枚举范围**：`i` 从 0 到 `n - M`，保证 $M$ 段不越界。

## 5. 正确性证明

**引理 1（窗口和）**：对任意 $0 \le a \le b < n$，$\sum_{k=a}^{b} nums[k] = pref[b+1] - pref[a]$。

**证明**：前缀和定义直接相减（望远镜求和）。∎

**引理 2（`best` 的含义）**：在 `solve(L, M)` 的第 $i$ 轮（枚举 $M$ 段起点 $i$）中，若 $j = i-1 \ge L-1$，则 `best` 恰好等于

$$\max\{\, \textstyle\sum_{k=t}^{t+L-1} nums[k] \;:\; L-1 \le t+L-1 \le j \,\}$$

即右端点不超过 $j$ 的所有长度 $L$ 窗口和的最大值。

**证明**：对 $i$ 归纳。$i = L$ 时（第一次 $j \ge L-1$），`best` 只并入右端点恰为 $j$ 的窗口，与定义一致。设第 $i-1$ 轮的 `best` 满足定义（覆盖右端点 $\le i-2$），本轮并入右端点为 $i-1$ 的窗口后取 max，恰覆盖右端点 $\le i-1$，即定义。∎

**引理 3（固定 $M$ 段时的最优 $L$ 段）**：若 $M$ 段取 $[i, i+M-1]$，则与之不重叠且位于其左侧的 $L$ 段的最优和，等于引理 2 中的 `best`。

**证明**：$L$ 段在左且不重叠 $\iff$ 其右端点 $\le i-1$；由引理 2，`best` 正是这类窗口的最大和。∎

**引理 4（覆盖所有方案）**：任一合法方案（两段不重叠）必属于以下两类之一：$L$ 段在左、$M$ 段在右；或 $M$ 段在左、$L$ 段在右。

**证明**：两段不重叠意味着一个完全在另一个左侧（区间不交且非空）。∎

**定理**：算法返回最大可能的和。

**证明**：`solve(L, M)` 枚举了所有「$L$ 在左、$M$ 在右」的 $M$ 段位置，并由引理 3 对每个位置取到了该位置下最优的 $L$ 段，故 `solve(L, M)` 的结果是这一类方案的最大值；同理 `solve(M, L)` 覆盖另一类。由引理 4 两类穷尽了全部合法方案，故两者取 max 即全局最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。前缀和 $O(n)$；`solve` 单方向一次扫描 $O(n)$，调用两次共 $O(n)$。
- **空间**：$O(n)$，前缀和数组；其余为 $O(1)$。
- **对比**：暴力枚举起点对 $O(n^2)$（约 $10^6$），本解法快一个量级且更易扩展。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxSumTwoNoOverlap(vector<int>& nums, int firstLen, int secondLen) {
        int n = (int)nums.size();
        vector<int> pref(n + 1, 0);
        for (int i = 0; i < n; i++) pref[i + 1] = pref[i] + nums[i];

        auto solve = [&](int L, int M) {          // L 段在左，M 段在右
            int best = 0, res = 0;
            for (int i = 0; i + M <= n; i++) {
                int j = i - 1;                    // L 段右端点最多到 i-1
                if (j >= L - 1) {
                    best = max(best, pref[j + 1] - pref[j + 1 - L]);
                    res = max(res, best + (pref[i + M] - pref[i]));
                }
            }
            return res;
        };

        return max(solve(firstLen, secondLen), solve(secondLen, firstLen));
    }
};
```

### Python

```python
class Solution:
    def maxSumTwoNoOverlap(self, nums: list[int], firstLen: int, secondLen: int) -> int:
        n = len(nums)
        pref = [0] * (n + 1)
        for i, v in enumerate(nums):
            pref[i + 1] = pref[i] + v

        def solve(L: int, M: int) -> int:
            best = res = 0
            for i in range(n - M + 1):
                j = i - 1                     # L 段右端点最多到 i-1
                if j >= L - 1:
                    best = max(best, pref[j + 1] - pref[j + 1 - L])
                    res = max(res, best + pref[i + M] - pref[i])
            return res

        return max(solve(firstLen, secondLen), solve(secondLen, firstLen))
```

## 8. 边界情况与易错点

1. **只算一个方向**：`L` 在左、`M` 在右只覆盖一半方案，必须再算反向（示例 1 就是反方向取到最优）。
2. **两段长度相等**：两个方向结果相同，代码仍然正确（多算一次而已）。
3. **两段恰好铺满整个数组**（$L + M = n$）：只有一个方案，`i = n - M` 时 $j = n-M-1 = L-1$，恰能取到，注意边界 `j >= L-1` 用 `>=`。
4. **窗口起点越界**：`i + M <= n` 保证 $M$ 段合法；$L$ 段由 `j >= L-1` 保证。
5. **`best` 的初始化**：因 $nums[i] \ge 0$，`best = 0` 安全；若允许负数，应改用「是否已存在窗口」的标记或 `-inf`。
6. **前缀和的偏移**：`pref[j+1] - pref[j+1-L]` 对应窗口 $[j-L+1, j]$，下标别写反。
7. **返回值类型**：$n \le 1000$、$nums[i] \le 1000$，最大和 $\le 10^6$，`int` 足够。
