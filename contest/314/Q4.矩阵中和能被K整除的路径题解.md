# LeetCode 矩阵中和能被 K 整除的路径 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中和能被 K 整除的路径（#2435，hard）
- **链接**：https://leetcode.cn/problems/paths-in-matrix-whose-sum-is-divisible-by-k/
- **来源**：LeetCode 第 314 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、矩阵、计数 DP、同余

**题意**：给定 $m \times n$ 的非负整数矩阵 `grid` 与整数 $k$。从 $(0,0)$ 出发，每步只能**向右**或**向下**，走到 $(m-1, n-1)$。返回**路径上所有元素之和能被 $k$ 整除**的路径数目；答案可能很大，对 $10^9+7$ 取模后返回。

**约束**：

- $1 \le m, n \le 5 \times 10^4$
- $1 \le m \times n \le 5 \times 10^4$
- $0 \le \text{grid}[i][j] \le 100$
- $1 \le k \le 50$

> 💡 **读约束的信号**：$m, n$ 各自可到 $5\times 10^4$，但**乘积**被单独压在 $5\times 10^4$；再加上 $k \le 50$——三者相乘恰为 $2.5 \times 10^6$。这个不寻常的双重约束就是出题人给 $O(m \cdot n \cdot k)$ 三维 DP 留的甜区。

## 2. 示例

**示例 1**

```text
输入：grid = [[5,2,4],[3,0,5],[0,7,2]], k = 3
输出：2

解释：
红路径 (0,0)→(0,1)→(0,2)→(1,2)→(2,2)：和 = 5+2+4+5+2 = 18，18 mod 3 = 0。
蓝路径 (0,0)→(1,0)→(1,1)→(1,2)→(2,2)：和 = 5+3+0+5+2 = 15，15 mod 3 = 0。
其余 4 条路径的和均不是 3 的倍数。
```

**示例 2**

```text
输入：grid = [[0,0]], k = 5
输出：1

解释：唯一路径和 = 0 + 0 = 0，而 0 能被任何 k 整除。
```

**示例 3**

```text
输入：grid = [[7,3,4,9],[2,3,6,2],[2,3,7,0]], k = 1
输出：10

解释：k = 1 时任何和都被整除，答案 = 路径总数 C(3+4-2, 3-1) = C(5,2) = 10。
```

## 3. 解题思路

### 3.1 暴力思路

两条朴素路都走不通：

1. **枚举全部路径**：$(0,0)$ 到 $(m-1,n-1)$ 的路径共 $\binom{m+n-2}{m-1}$ 条。取满足约束的 $m = n = 224$（$224^2 \approx 5\times 10^4$），$\binom{446}{223} \approx 10^{133}$——天文数字，逐条求和判整除完全不可行。
2. **记忆化搜索记 $(i, j, \text{路径和})$**：路径和的上界是 $100 \times (m+n-1) \approx 5\times 10^6$，最坏情况下状态数达 $10^9$ 量级，同样不可承受。

瓶颈在于「和」这个量随路径增长、且看起来无法压缩。但题目只问**能否被 $k$ 整除**，等价于只问**余数是否为 $0$**——余数是可压缩的。

### 3.2 核心观察：同余压缩——路径和只需记余数

由**同余可加性**

$$
(a + b) \bmod k = \big((a \bmod k) + (b \bmod k)\big) \bmod k
$$

路径和模 $k$ 的余数可以**逐格累积**：每走进一个格子，就在当前余数上加 $g = \text{grid}[i][j] \bmod k$ 再取模，与「之前是怎么加到当前余数的」完全无关。于是「无穷大的和」被压缩成 $[0, k)$ 内的整数，把它作为 DP 的第三维状态：

$$
f[i][j][r] = \text{从 }(0,0)\text{ 到 }(i,j)\text{ 且路径和} \equiv r \pmod{k}\text{ 的路径数}
$$

状态数 $m \cdot n \cdot k \le 2.5 \times 10^6$，恰好落进约束给的甜区。这正是「格路计数」家族加上**余数维度**的标准形态：$k = 1$ 时第三维消失，退化为 [62. 不同路径](https://leetcode.cn/problems/unique-paths/)。

![核心观察：路径和按 mod k 分桶与 push 转移](images/2521_mod_bucket_concept.svg)

### 3.3 算法流程：push 转移 + 按行滚动

转移采用 **push（推）方向**：设 $g = \text{grid}[i][j] \bmod k$，把前驱的每个余数分量「推」进目标格子：

$$
f[i][j][(r + g) \bmod k] \mathrel{+}= f[i-1][j][r] + f[i][j-1][r]
$$

（只取存在的方向：$i = 0$ 无上方，$j = 0$ 无左方。）边界为 $f[0][0][\text{grid}[0][0] \bmod k] = 1$，答案为 $f[m-1][n-1][0]$。

空间上 $f[i][j]$ 只依赖**上一行同列**（上方源）与**本行前一列**（左方源），按行从左到右处理即可滚动压缩成一维 $f[j][r]$：

- 读 $f[j]$ 时它**尚未被本行覆写**——存的是上一行的值（上方源）；
- 读 $f[j-1]$ 时它**已被覆写**——存的是本行的值（左方源）；
- 累加结果先写进临时数组 `cur`，整组算完再 `f[j] = cur` 覆写。

![算法流程：push 转移与按行滚动](images/2521_rolling_dp_flow.svg)

### 3.4 示例演算

以示例 1（$k=3$）走查，每格记录向量 $[c_0, c_1, c_2]$（到该格、和 $\equiv 0/1/2 \pmod 3$ 的路径数）：

| $(i,j)$ | 格值 $\to g$ | $f = [c_0,c_1,c_2]$ | 说明 |
|---------|-------------|---------------------|------|
| $(0,0)$ | $5 \to 2$ | $[0,0,1]$ | 起点，唯一路径和 $5 \equiv 2$ |
| $(0,1)$ | $2 \to 2$ | $[0,1,0]$ | 仅左源 $[0,0,1]$ 移 2：分量 2 → $(2{+}2)\bmod 3 = 1$ |
| $(0,2)$ | $4 \to 1$ | $[0,0,1]$ | 仅左源 $[0,1,0]$ 移 1：分量 1 → $(1{+}1)\bmod 3 = 2$ |
| $(1,0)$ | $3 \to 0$ | $[0,0,1]$ | 仅上源，$g=0$ 照搬 |
| $(1,1)$ | $0 \to 0$ | $[0,1,1]$ | 上 $[0,0,1]$ + 左 $[0,0,1]$，$g=0$ 逐位相加 |
| $(1,2)$ | $5 \to 2$ | $[1,2,0]$ | 上 $[0,0,1]$ + 左 $[0,1,1]$，各移 2 后相加 |
| $(2,0)$ | $0 \to 0$ | $[0,0,1]$ | 仅上源照搬 |
| $(2,1)$ | $7 \to 1$ | $[2,0,1]$ | 上 $[0,1,1]$ + 左 $[0,0,1]$，各移 1 后相加 |
| $(2,2)$ | $2 \to 2$ | $[2,1,3]$ | 上 $[1,2,0]$ + 左 $[2,0,1]$，各移 2 后相加 |

![示例 1 的逐格演算表](images/2521_example_walkthrough.svg)

终点 $c_0 = 2$ 即答案。校验：三分量之和 $2+1+3 = 6 = \binom{4}{2}$，恰为路径总数，说明所有路径都被不重不漏地统计。

## 4. 算法细节

1. **push 与 pull 两种写法**：转移也可以「拉」：$pr = (r - g) \bmod k$，$f[i][j][r] = f[i-1][j][pr] + f[i][j-1][pr]$。但 C++/Java 中 `(r - g) % k` 在 $r < g$ 时为**负**（如 `(0-2)%3 = -2`），必须写成 `((r-g)%k+k)%k`；而 push 方向 $(r+g) \bmod k$ 中 $r, g \in [0, k)$，$r + g \le 2k - 2 < 2^{31}$，**取模结果恒非负**，天然规避负数陷阱。实战优先 push。
2. **滚动时序**：必须先把整组 `cur` 算完再覆写 `f[j]`。若在 `f[j]` 上原地边读边写，上方源会在中途被本格的写入破坏。
3. **初始化**：$f[0][0]$ 的唯一非零分量在 $\text{grid}[0][0] \bmod k$ 处（起点格子值计入路径和），不是 $f[0][0][0] = 1$；循环中跳过 $(0,0)$ 防止起点被再次转移。
4. **取模纪律**：两个 $< 10^9+7$ 的 `int` 相加不超过 $2 \times (10^9+6) < 2^{31}-1$，单次加法安全；但必须**每次累加后立即取模**，连续裸加必溢出。全程 `int` 即可，无需 `long long`。
5. **复杂度预算**：$m \cdot n \le 5 \times 10^4$、$k \le 50$，至多 $2.5 \times 10^6$ 次转移，毫秒级；滚动数组 $O(n \cdot k)$，若 $m < n$ 可先转置矩阵，把滚动维换成较短的一边，空间降为 $O(\min(m,n) \cdot k)$。

## 5. 正确性证明

**引理 1（同余可加性）**：对非负整数 $a, b$，$(a + b) \bmod k = \big((a \bmod k) + (b \bmod k)\big) \bmod k$。

**证明**：设 $a = q_1 k + r_1$、$b = q_2 k + r_2$，其中 $0 \le r_1, r_2 < k$。则 $a + b = (q_1 + q_2)k + (r_1 + r_2)$，故 $(a+b) \bmod k = (r_1 + r_2) \bmod k$。∎

**引理 2（路径分解与无后效性）**：对 $i + j \ge 1$，到达 $(i,j)$ 的路径集合按**倒数第二个格子**划分为「最后一步从 $(i-1,j)$ 走来」（$i > 0$ 时）与「从 $(i,j-1)$ 走来」（$j > 0$ 时）两类，两类互斥且完备；且任一条到 $(i,j)$ 的路径的和 $\equiv$ 子路径和 $+ \text{grid}[i][j]$，由引理 1，该余数只依赖子路径的余数与 $g$。

**证明**：移动方向仅限右/下，倒数第二步的位置只能是 $(i-1,j)$ 或 $(i,j-1)$，故划分完备；倒数第二格不同的两条路径必不同，故互斥。和的分解是定义式的；余数性质由引理 1 即得。这同时说明了无后效性：走到 $(i,j)$ 时的余数 $r$ 确定后，后续演化只依赖 $r$ 与后续格子，与「怎样走到 $r$」无关。∎

**定理**：算法结束后，$f[n-1][r]$ 等于从 $(0,0)$ 到 $(m-1,n-1)$ 且路径和 $\equiv r \pmod k$ 的路径数（在 $\bmod\ p$、$p = 10^9+7$ 的意义下）；特别地，返回值 $f[n-1][0]$ 为所求答案。

**证明**：对 $d = i + j$ 归纳。命题 $P(d)$：处理完所有 $i + j = d$ 的格子后，滚动数组中相应列的向量等于真值（mod $p$）。

- **基础**（$d = 0$）：初始化 $f[0][\text{grid}[0][0] \bmod k] = 1$，恰是只含起点的唯一路径的余数分布，成立。
- **归纳步**：设 $P(d)$ 成立，处理 $(i,j)$，$i + j = d + 1$，$g = \text{grid}[i][j] \bmod k$。由滚动时序，此刻 $f[j]$ 存 $(i-1,j)$ 的真值、$f[j-1]$ 存 $(i,j-1)$ 的真值。由引理 2，到 $(i,j)$ 且和 $\equiv r'$ 的路径数 $=$ 到 $(i-1,j)$ 且和 $\equiv r' - g$ 的路径数 $+$ 到 $(i,j-1)$ 且和 $\equiv r' - g$ 的路径数（不存在的方向计 0）。而 push 转移恰把源分量 $r = (r' - g) \bmod k$ 累加进 $cur[(r+g) \bmod k] = cur[r']$，与上式逐分量一致。转移只含模 $p$ 加法，而「真计数 → mod $p$」对加法保持，故 $P(d+1)$ 成立。
- **终点**：$(m-1,n-1)$ 处理完毕后 $f[n-1] = f[m-1][n-1][\cdot]$，取分量 $0$ 即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \cdot n \cdot k)$。每个格子对 $k$ 个余数分量各做常数次加法与取模，总量 $\le 5 \times 10^4 \times 50 = 2.5 \times 10^6$，毫秒级通过。
- **空间复杂度**：$O(n \cdot k)$（按行滚动的一维数组）。不滚动的三维表为 $O(m \cdot n \cdot k) \approx 2.5 \times 10^6$ 个 `int`（约 10 MB），本题也能过，但滚动后更省、缓存更友好。
- **对照**：暴力枚举 $O\big(\binom{m+n-2}{m-1} \cdot (m+n)\big)$，路径数天文数字；记忆化 $(i, j, \text{sum})$ 因和的值域达 $5\times 10^6$ 而状态爆炸。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int numberOfPaths(vector<vector<int>>& grid, int k) {
        constexpr int MOD = 1'000'000'007;
        int m = grid.size(), n = grid[0].size();
        vector<vector<int>> f(n, vector<int>(k));
        f[0][grid[0][0] % k] = 1;
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                if (i == 0 && j == 0) continue;
                int g = grid[i][j] % k;
                vector<int> cur(k, 0);
                if (i > 0)
                    for (int r = 0; r < k; ++r)
                        if (f[j][r]) cur[(r + g) % k] = (cur[(r + g) % k] + f[j][r]) % MOD;
                if (j > 0)
                    for (int r = 0; r < k; ++r)
                        if (f[j - 1][r]) cur[(r + g) % k] = (cur[(r + g) % k] + f[j - 1][r]) % MOD;
                f[j].swap(cur);
            }
        }
        return f[n - 1][0];
    }
};
```

### Python

```python
class Solution:
    def numberOfPaths(self, grid: List[List[int]], k: int) -> int:
        MOD = 1_000_000_007
        m, n = len(grid), len(grid[0])
        f = [[0] * k for _ in range(n)]
        f[0][grid[0][0] % k] = 1
        for i in range(m):
            for j in range(n):
                if i == 0 and j == 0:
                    continue
                g = grid[i][j] % k
                cur = [0] * k
                if i > 0:
                    for r, c in enumerate(f[j]):
                        if c:
                            cur[(r + g) % k] = (cur[(r + g) % k] + c) % MOD
                if j > 0:
                    for r, c in enumerate(f[j - 1]):
                        if c:
                            cur[(r + g) % k] = (cur[(r + g) % k] + c) % MOD
                f[j] = cur
        return f[n - 1][0]
```

## 8. 边界情况与易错点

1. **初始化不是 $f[0][0][0] = 1$**：起点格子值必须计入路径和，正确写法是 $f[0][0][\text{grid}[0][0] \bmod k] = 1$。$1 \times 1$ 矩阵由此天然覆盖：答案为 $\text{grid}[0][0] \bmod k = 0$ 时取 1，否则取 0。
2. **0 能被任何 $k$ 整除**：`grid` 值可为 0，路径和可为 0（示例 2），$0 \bmod k = 0$ 是合法整除。不要把「余数 0」误当作哨兵值或未标记状态。
3. **C++ 负数取模**：pull 写法 `(r - g) % k` 在 $r < g$ 时为负、直接作下标会越界；push 写法 `(r + g) % k` 因 $r, g \in [0,k)$ 恒非负（见 §4 第 1 点）。Python 的 `%` 两种写法都天然非负。
4. **滚动数组禁止原地边读边写**：上方源与写入目标同为 `f[j]`，必须借助 `cur` 整组算完再覆写，否则上源中途被污染。
5. **跳过起点**：循环若不跳过 $(0,0)$，起点会被当作普通格子再转移一次，计数错误。
6. **取模时机**：每次累加后立即 `% MOD`；两个小于 MOD 的 `int` 相加虽不溢出，但连续累加必然溢出。
7. **$k = 1$ 的对拍用法**：此时所有路径都合法，答案 $= \binom{m+n-2}{m-1} \bmod p$（示例 3 的 10），可用独立的组合数计算交叉验证 DP 实现的正确性。
8. **维度错觉**：$m, n$ 各自可达 $5\times 10^4$，但受 $m \cdot n \le 5\times 10^4$ 约束，滚动数组 $O(n \cdot k)$ 至多 $2.5 \times 10^6$ 个 `int`，无需进一步压到 $O(k)$。
9. **读清目标**：统计的是「和能被 $k$ 整除」的路径数，不是路径总数；示例 3 输出 10 只因 $k=1$ 时两者恰好相等。

**延伸思考**：

- 若 $k$ 升到 $10^9$：余数桶不可枚举；且格路每走一步可达余数集合近似翻倍，很快铺满 $[0, k)$，哈希表只存出现过的余数也无渐近增益，需借助数论或生成函数结构。
- 若允许四方向移动：路径可以绕圈，「倒数第二格分解」失效（图不再是 DAG），简单 DP 不再适用，需插头 DP 等高级手段。
- 若改问「和恰好等于 target 的路径数」：把余数维换成和维即可（$target \le 100(m+n)$ 时可行），状态设计与背包一致。
- 若 `grid` 含负数：push 写法中 $g$ 可能为负，$(r+g) \bmod k$ 需修正为 $((r+g) \bmod k + k) \bmod k$；Python 不受影响。
