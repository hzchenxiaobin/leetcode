# LeetCode 处理用时最长的那个任务的员工 题解

## 1. 题目概述

- **标题 / 题号**：处理用时最长的那个任务的员工（#2432，easy）
- **链接**：https://leetcode.cn/problems/the-employee-that-worked-on-the-longest-task/
- **来源**：LeetCode 第 314 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、一次遍历

**题意**：共有 $n$ 位员工（id 为 $0 \sim n-1$）。给定二维整数数组 `logs`，`logs[i] = [id_i, leaveTime_i]` 表示员工 `id_i` 完成第 $i$ 个任务的时刻为 `leaveTime_i`。任务之间**串行无缝衔接**：第 $0$ 个任务从时刻 $0$ 开始，第 $i$ 个任务在第 $i-1$ 个任务结束的时刻立即开始。要求返回**处理用时最长**的那个任务的员工 id；若有多名员工用时相同，返回其中**最小**的 id。

**约束**：

- `2 <= n <= 500`
- `1 <= logs.length <= 500`
- `logs[i].length == 2`，`0 <= idi <= n - 1`
- `1 <= leaveTimei <= 500`，且 `leaveTime` 按严格递增顺序排列（互不相同）
- 相邻两条记录的员工 id 不同（`idi != idi+1`）

> 💡 数据范围只有 500，任何合理做法都能过；Q1 的价值在于**最短路径**：一次遍历、常数空间，并把平局比较写对。

## 2. 示例

**示例 1**

```text
输入：n = 10, logs = [[0,3],[2,5],[0,9],[1,15]]
输出：1

解释：
任务 0 于时刻 0 开始，时刻 3 结束，用时 3（员工 0）。
任务 1 于时刻 3 开始，时刻 5 结束，用时 2（员工 2）。
任务 2 于时刻 5 开始，时刻 9 结束，用时 4（员工 0）。
任务 3 于时刻 9 开始，时刻 15 结束，用时 6（员工 1）。
用时最长的是任务 3，返回员工 1。
```

**示例 2**

```text
输入：n = 26, logs = [[1,1],[3,7],[2,12],[7,17]]
输出：3

解释：
四个任务的用时分别为 1、6、5、5。
用时最长的是任务 1（用时 6），由员工 3 处理，返回 3。
```

**示例 3**

```text
输入：n = 2, logs = [[0,10],[1,20]]
输出：0

```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法分两步：

1. 第一遍扫描：对每个任务计算用时 `dur = t - prev`，并把它累加进一个统计数组 `maxDur[n]`（按员工 id 取最大值）。
2. 第二遍扫描：在 `maxDur[0..n-1]` 中找最大用时，平局取下标最小者。

时间复杂度 $O(n + m)$（$m$ 为 `logs` 长度），空间复杂度 $O(n)$。在本题数据范围下完全够用，但**统计数组是多余的**：我们只关心全局最大用时及其对应的最小 id，不需要"每个员工"的最大用时。

### 3.2 核心观察：用时 = 相邻结束时刻之差

任务是串行无缝衔接的，所以**第 $i$ 个任务的处理用时就是时间轴上相邻两个结束时刻之间的段长**：

$$d_i = t_i - t_{i-1}, \qquad t_{-1} = 0$$

于是问题转化为：在序列 $\{d_i\}$ 中求最大值对应的员工 id，平局取最小 id。这是一个标准的 **argmax + tie-breaking** 问题，两个变量（`bestDur`、`bestId`）一次遍历即可维护。

![任务用时的时间轴表示](images/longest_task_timeline_concept.svg)

### 3.3 算法流程

一次遍历 `logs`，维护三个变量：

- `prev`：上一任务的结束时刻，初始为 $0$（任务 0 从时刻 0 开始）；
- `bestDur`：当前最大用时，初始为 $-1$；
- `bestId`：对应的最小员工 id。

对每条 `log = [id, t]`：计算 `dur = t - prev`；若 `dur > bestDur` **或** `dur == bestDur 且 id < bestId`，则更新；随后 `prev = t`。遍历结束返回 `bestId`。

![一次遍历的算法流程图](images/longest_task_flow.svg)

## 4. 算法细节

1. **用时公式**：`dur = t - prev`，其中 `prev` 初始为 $0$ 而不是 `logs[0][1]`——任务 0 从时刻 0 开始。
2. **更新条件**：`dur > bestDur || (dur == bestDur && id < bestId)`。两个分支分别对应"更大的用时"和"用时相同但 id 更小"。
3. **初始化**：`bestDur = -1`。由于 `leaveTime >= 1` 且严格递增，每个 `dur >= 1`，第一条记录必然触发更新，`bestId` 一定会被赋值。
4. **无需统计数组**：一个员工可以处理多个（互不相邻的）任务，其"最长用时"就是他所做任务用时的最大值；逐任务与全局最优比较，与先按员工聚合再取全局，结果等价。
5. **参数 `n` 用不到**：一次遍历写法中 `n` 只出现在函数签名里，不影响逻辑。

## 5. 正确性证明

**引理 1**：第 $i$ 个任务的处理用时 $d_i = t_i - t_{i-1}$（约定 $t_{-1} = 0$）。

**证明**：任务 $i$ 在任务 $i-1$ 结束的时刻 $t_{i-1}$ 开始（任务 0 在时刻 0 开始），在 $t_i$ 结束，故用时为两者之差。∎

**引理 2**：设员工 $e$ 处理的任务集合为 $S_e$，则员工 $e$ 的最长任务用时为 $\max_{i \in S_e} d_i$；题目所求即所有任务中 $d_i$ 最大者对应的员工，平局取 id 最小。

**证明**：由题意，"处理用时最长的那个任务"是全体任务中的用时最大者；一个员工只有在他处理的任务取得该最大值时才可能是答案，其竞争力由他所处理任务的最大用时决定。∎

**定理**：遍历结束后，`bestDur` 等于所有任务用时的最大值 $D$，`bestId` 等于处理用时为 $D$ 的任务中最小的员工 id。

**证明**：对已处理的前 $k$ 条记录归纳。归纳假设：处理完前 $k$ 条后，`(bestDur, bestId)` 是前 $k$ 个任务中的最优（用时最大、平局最小 id）。基础：`bestDur = -1 < 1 <= d_0`，第一条记录必触发更新，成立。归纳步：处理第 $k+1$ 条 `(id, d)`：

- 若 `d > bestDur`：新记录严格更优，更新后 `(d, id)` 是前 $k+1$ 个任务的最优；
- 若 `d == bestDur` 且 `id < bestId`：用时不变、id 变小，更新后仍是最优；
- 若 `d == bestDur` 且 `id >= bestId`，或 `d < bestDur`：新记录不优于当前最优，不更新，最优不变。

三种情况均保持归纳假设。遍历结束时即得全局结论。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m)$，其中 $m$ 为 `logs` 的长度。每条记录只做常数次比较与赋值。
- **空间复杂度**：$O(1)$。仅使用 `prev`、`bestDur`、`bestId` 三个变量（朴素两遍扫描写法需要 $O(n)$ 的统计数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int hardestWorker(int n, vector<vector<int>>& logs) {
        int bestDur = -1, bestId = -1, prev = 0;
        for (auto& log : logs) {
            int id = log[0], t = log[1];
            int dur = t - prev;
            if (dur > bestDur || (dur == bestDur && id < bestId)) {
                bestDur = dur;
                bestId = id;
            }
            prev = t;
        }
        return bestId;
    }
};
```

### Python

```python
class Solution:
    def hardestWorker(self, n: int, logs: List[List[int]]) -> int:
        best_dur, best_id, prev = -1, -1, 0
        for pid, t in logs:
            dur = t - prev
            if dur > best_dur or (dur == best_dur and pid < best_id):
                best_dur, best_id = dur, pid
            prev = t
        return best_id
```

## 8. 边界情况与易错点

1. **平局必须比较 id**：只写 `dur > bestDur` 会在某些数据上出错。反例：`logs = [[1,5],[0,10]]`，两个任务用时均为 5，正确答案为 0，但只用 `>` 会返回 1。示例 3（`[[0,10],[1,20]]`）中用时相同的员工恰好先小后大，是隐藏陷阱。必须补上 `(dur == bestDur && id < bestId)` 分支。
2. **`prev` 初始值为 0**：任务 0 从时刻 0 开始，首任务用时是 `logs[0][1] - 0`，不要把 `prev` 初始化成 `logs[0][1]`。
3. **`bestDur` 初始值**：用 $-1$ 语义最清晰（任何用时都大于它）；用 $0$ 也可行，因为 `leaveTime >= 1` 保证 `dur >= 1`。但不要把比较写成 `>=`，否则平局且后出现的 id 更小时不会更新——恰与要求相反。
4. **员工可重复出现**：同一员工的多次任务之间隔着其他员工的任务，不需要也不应该"跳过重复员工"，逐任务比较天然正确。
5. **`n` 与 `logs.length` 无需相等**：员工数和任务数是两个独立的量，勿混用。
6. **数据范围**：`leaveTime <= 500`，无溢出风险，`int` 足够。
