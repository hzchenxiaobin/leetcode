# LeetCode 使用机器人打印字典序最小的字符串 题解

## 1. 题目概述

- **标题 / 题号**：使用机器人打印字典序最小的字符串（#2434，medium）
- **链接**：https://leetcode.cn/problems/using-a-robot-to-print-the-lexicographically-smallest-string/
- **来源**：LeetCode 第 314 场周赛 Q3
- **难度**：中等
- **标签**：栈、贪心、字符串、后缀最小

**题意**：给定字符串 `s` 和一个机器人，机器人维护一个空字符串 `t`（栈）。反复执行以下两种操作之一，直到 `s` 和 `t` 都为空：

- **操作 ①**（压入）：删除 `s` 的**第一个**字符，追加到 `t` 的**尾部**——即 `s` 是队列、`t` 是栈，从 `s` 队首压入 `t` 栈顶；
- **操作 ②**（弹出）：删除 `t` 的**最后一个**字符（栈顶），写到纸上的字符串 `p` 的尾部。

求纸上能写出的字典序最小的 `p`。

**约束**：

- $1 \le \text{s.length} \le 10^5$
- `s` 只包含小写英文字母

> 💡 **读题眼**：把 `t` 看成**栈**、`s` 看成**队列**、`p` 看成输出，整个系统就是一台「栈式排序机」：输入序列固定为 `s`，问弹栈顺序能排出的字典序最小结果。$n$ 到 $10^5$ 说明需要 $O(n)$ 或 $O(n \log n)$；只含小写字母提示后缀信息可以用 26 个桶维护。

## 3. 解题思路

### 3.1 暴力思路：搜索全部操作序列

操作序列是一个由 $n$ 次「压入」和 $n$ 次「弹出」构成的合法括号序列，总数是**卡特兰数** $C_n$ 量级，$n = 10^5$ 时天文数字，搜索/记忆化都不可行。状态 `DP(剩余 s, 栈内容 t)` 的状态空间同样是指数级——**必须贪心**。

退一步想：每一步其实只有「弹」或「不弹（压入）」两种选择，而 `p` 是逐字符追加的、字典序比较只看**第一个不同的字符**——这正是贪心天然适用的结构：每一步都让「当前写出的字符」尽量小，且这个选择不会堵死后面的更小字符。

### 3.2 核心观察：弹不弹，只看「栈顶 vs 后缀最小」

![核心观察：栈顶与后缀最小值比较决定弹或压](images/2434_stack_suffix_min_concept.svg)

下一个写到纸上的字符，**只能来自两个地方**：`t` 的栈顶（直接弹），或 `s` 的剩余部分（先压入若干个再弹出）。于是设当前栈顶为 $c$，`s` 剩余字符的最小值为 $m$（`s` 为空时 $m = +\infty$）：

- **若 $c \le m$**：**立即弹出 $c$**。剩余所有字符都不小于 $c$，晚弹只会让 `p` 的前缀先垫上 $\ge c$ 的字符，不可能更优；
- **若 $c > m$**：**按住不弹，继续压入** `s` 的队首。现在弹 $c$ 会让 `p` 以 $c$ 开头，而后缀里还藏着更小的 $m$——把队首一个个压进去，直到 $m$ 进栈（此时 $m \le$ 当时栈中任何字符，会被弹出一串），才能写出更小的前缀。

> ⚠️ **为什么比较是 $\le$ 而不是 $<$**：当 $c = m$ 时，先弹 $c$ 与后弹 $m$ 得到的相邻两字符都是 "$cm$" vs "$mc$"，$c = m$ 时两者相等，先弹**不劣**；而先弹能让算法更早清栈、逻辑更简单。若严格用 $<$，反例 `s = "aca"`：`<` 版会输出 `"aca"`，`≤` 版输出 `"aac"`（正确答案）。

这就是经典的**「栈 + 后缀最小」贪心**模型：与 402（移掉 K 位数字）、316（去除重复字母）同一族——栈外还有未到的字符时，用**后缀信息**决定栈顶的去留。

### 3.3 算法流程

![算法流程：后缀最小数组加单次扫描加尽情弹栈](images/2434_greedy_flow.svg)

1. **预处理后缀最小数组**：$\text{suf}[i] = \min(s[i..n-1])$，倒序一遍递推 $\text{suf}[i] = \min(s[i], \text{suf}[i+1])$，哨兵 $\text{suf}[n] = \{$（即 `'z'+1'`，比任何小写字母大，代表 $+\infty$）；
2. **单次扫描** $i = 0 \to n-1$：先把 $s[i]$ 压入栈 `t`（操作①），然后**尽情弹栈**（操作②）——只要栈非空且栈顶 $\le \text{suf}[i+1]$（注意是 $i+1$，即尚未压入的剩余部分的最小值），就弹出追加到 `p`；
3. **清栈**：扫描结束后 `s` 已空（$m = +\infty$），把 `t` 中剩余字符全部弹出。

每一步的判断恰好实现了 3.2 的两条规则：栈顶 $\le$ 剩余最小 → 弹；否则进入下一轮压入。

### 3.4 示例演算

![示例演算：s等于bdda逐步压栈与弹栈过程](images/2434_example_walkthrough.svg)

以 `s = "bdda"` 为例，$\text{suf} = [\text{a},\text{a},\text{a},\text{a},\texttt{'}\{\texttt{'}]$（每个后缀的最小值都是末尾的 `a`）：

| 步骤 | 压入后栈 t（右为顶） | 判断：top ≤ suf[i+1]? | 纸上 p |
|------|------|------|------|
| i=0 压 b | `b` | b ≤ a？否 | （空） |
| i=1 压 d | `b d` | d ≤ a？否 | （空） |
| i=2 压 d | `b d d` | d ≤ a？否 | （空） |
| i=3 压 a | `b d d a` | a ≤ `{`？是 → 连弹四次 | `addb` |

`b`、`d`、`d` 全被「后缀藏着 a」按住，`a` 一进栈立刻触发清栈，输出 `"addb"`。若 `i=0` 时忍不住弹了 `b`，`p` 将以 `b` 开头，得到 `"bdda" > "addb"`。

## 4. 算法细节

1. **后缀最小数组**：$\text{suf}[i]$ 表示「还没压栈的字符 $s[i..n-1]$ 里的最小值」。在第 $i$ 轮压入 $s[i]$ 后，与栈顶比较的是 $\text{suf}[i+1]$——即**尚未进入系统的字符**的最小值，已被压入栈的字符不算在内（它们只能经栈顶按序出来）。
2. **哨兵**：$\text{suf}[n] = \texttt{'}\{\texttt{'}$（ASCII `123`，恰为 `'z' + 1`）。第 $n-1$ 轮压入最后一个字符后，剩余最小值为 $+\infty$，栈顶必然 $\le$ 哨兵，于是**清栈逻辑被统一进主循环**，无需在循环内特判「s 已空」。
3. **均摊 O(1) 弹栈**：`while` 弹栈总数不超过总压入数 $n$，整个扫描是 $O(n)$ 而非 $O(n^2)$。
4. **后缀最小的替代实现**：也可用 26 个计数桶 `cnt[26]` 维护剩余字符频次，压入时 `cnt[s[i]] -= 1`，查询 $m$ 时从 `a` 到 `z` 找第一个非零桶。单次查询最坏 $O(26)$，总 $O(26n)$，同样可过；后缀数组版更简洁，两版都很常用。
5. **输出构造**：`p` 用列表/`StringBuilder` 逐字符追加，最后拼接，避免不可变字符串的 $O(n^2)$ 拼接。

## 5. 正确性证明

**引理 1**（可达性）：任意时刻，下一个写到 `p` 上的字符，要么是 `t` 的栈顶，要么是 `s` 剩余部分的某个字符。

**证明**：操作②写出的字符只能是 `t` 的栈顶；操作①不写字符。要把 `s` 中某字符写到纸上，必须先经操作①入栈，再经操作②出栈，且出栈时它必须是栈顶。∎

**引理 2**（弹的贪心选择）：设当前栈顶为 $c$，$s$ 剩余字符最小值为 $m$。若 $c \le m$，则存在最优方案，其第一个写到 `p` 的字符是 $c$（且可立即弹出）。

**证明**：设 $O$ 为任意最优方案，其首个输出字符为 $y$，$O$ 在首次输出前先压入了 $k \ge 0$ 个字符。

- 若 $y = c$：即 $O$ 先压 $k$ 个再弹 $c$。构造 $O'$：先弹 $c$，再压那 $k$ 个字符，其余操作与 $O$ 完全一致。$O'$ 中那 $k$ 个字符压在更矮的栈上，原栈剩余部分的相对顺序不变，$O$ 的后续操作照搬依然合法；输出串仅把开头的 $c$ 提前，完全相同。故 $O'$ 也是最优的，且第一步就弹 $c$。
- 若 $y \ne c$：由引理 1，$y$ 来自 `s` 剩余部分，故 $y \ge m \ge c$，结合 $y \ne c$ 得 $y > c$。构造 $O''$：先弹 $c$，然后完全模仿 $O$，仅跳过 $O$ 中「弹出 $c$」的那一步（$c$ 已提前输出）。$O''$ 的输出为 $c + (O\text{ 的输出去掉首个 } c)$，首字符 $c < y$，故 $O''$ 的输出严格小于 $O$ 的输出，与 $O$ 最优矛盾。

两种情形合并，最优方案的首个输出必为 $c$ 且可立即弹出。∎

**引理 3**（压的贪心选择）：若 `t` 为空或栈顶 $c > m$，则存在最优方案，其第一个操作是压入（且最优方案首个输出不可能来自弹栈）。

**证明**：反设某最优方案 $O$ 的首个输出 $y$ 来自弹栈，则 $y = c > m$（或 `t` 非空才可能弹，$y$ 即栈顶）。构造方案 $O'''$：不断执行操作①直到剩余最小字符 $m$ 进栈（$m$ 是最小值，压入过程中不会遇到比它更小的字符），随即弹出 $m$ 写到纸上，之后模仿 $O$ 并跳过 $O$ 中对 $m$ 的那次弹出。$O'''$ 的首字符为 $m < y = c$，输出严格更小，矛盾。故最优方案首个输出来自 `s`，其第一个操作必为压入。∎

**定理**（算法最优性）：上述「压入 $s[i]$ 后，当栈顶 $\le \text{suf}[i+1]$ 时持续弹栈，最后清栈」的算法输出字典序最小的 `p`。

**证明**：对算法的决策步数归纳。归纳不变式：**存在一个最优方案，其操作序列以「算法从初始状态到当前状态已执行的操作」为前缀**。

- 初始时不变式显然（任何方案都含空前缀）。
- 归纳步：设算法当前处于状态（`s` 剩余、栈 `t`、纸上 `p`），且存在最优方案 $O$ 以算法已执行的操作为前缀。看算法本轮动作：
  - 若栈非空且 $c \le \text{suf}[i+1] = m$（算法弹）：由引理 2，存在最优方案在当前状态下首个输出为 $c$，其第一步是弹 $c$，与算法动作一致，不变式保持；
  - 若栈空或 $c > m$（算法压）：由引理 3，存在最优方案第一个操作是压入，与算法动作一致，不变式保持。
- 算法每轮执行一次压入（或若干次弹出），有限步后 `s` 扫空；末轮压入后 $\text{suf}[n] = +\infty$，引理 2 使算法弹空整个栈，所有 $n$ 个字符全部写出。此时「算法已执行的操作」就是完整方案，而以它为前缀的最优方案存在，故算法输出即最优。∎

> 💡 证明骨架就是贪心标准三件套：**可达性刻画（引理 1）→ 贪心选择性质（引理 2/3）→ 归纳合成（定理）**。凡是「逐字符构造 + 字典序目标」的题，几乎都能套这个框架。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。后缀最小一遍倒序递推 $O(n)$；主扫描中每个字符恰好入栈一次、出栈一次，弹栈 `while` 的总轮次被总压入数 $n$ 均摊，总计 $O(n)$。
- **空间复杂度**：$O(n)$。后缀最小数组 $O(n)$、栈 `t` 最坏 $O(n)$（如 `s = "cba"` 全压完再弹）、输出 `p` $O(n)$（不计返回值则后缀数组 + 栈为 $O(n)$；计数桶版后缀信息可降到 $O(26)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string robotWithString(string s) {
        int n = s.size();
        vector<char> suf(n + 1, '{');            // '{' = 'z' + 1，充当 +inf 哨兵
        for (int i = n - 1; i >= 0; --i) {
            suf[i] = min(s[i], suf[i + 1]);
        }
        string t, p;
        for (int i = 0; i < n; ++i) {
            t.push_back(s[i]);                   // 操作①：压栈
            while (!t.empty() && t.back() <= suf[i + 1]) {
                p.push_back(t.back());           // 操作②：弹栈写到纸上
                t.pop_back();
            }
        }
        while (!t.empty()) {                     // 清栈（s 空，m = +inf）
            p.push_back(t.back());
            t.pop_back();
        }
        return p;
    }
};
```

### Python

```python
class Solution:
    def robotWithString(self, s: str) -> str:
        n = len(s)
        suf = ['{'] * (n + 1)                    # '{' = 'z' + 1，充当 +inf 哨兵
        for i in range(n - 1, -1, -1):
            suf[i] = min(s[i], suf[i + 1])
        t, p = [], []
        for i, c in enumerate(s):
            t.append(c)                          # 操作①：压栈
            while t and t[-1] <= suf[i + 1]:
                p.append(t.pop())                # 操作②：弹栈写到纸上
        while t:                                 # 清栈（s 空，m = +inf）
            p.append(t.pop())
        return ''.join(p)
```

### Python（26 计数桶版后缀最小）

```python
class Solution:
    def robotWithString(self, s: str) -> str:
        cnt = [0] * 26
        for c in s:
            cnt[ord(c) - 97] += 1

        def suffix_min() -> str:
            for j in range(26):
                if cnt[j] > 0:
                    return chr(97 + j)
            return '{'

        t, p = [], []
        for c in s:
            t.append(c)
            cnt[ord(c) - 97] -= 1
            m = suffix_min()
            while t and t[-1] <= m:
                p.append(t.pop())
        while t:
            p.append(t.pop())
        return ''.join(p)
```

## 8. 边界情况与易错点

1. **比较必须用 $\le$ 而非 $<$**：栈顶等于后缀最小时，先弹不劣（相邻相等字符交换不影响字典序）；用 `<` 会在 `s = "aca"` 上输出 `"aca"` 而非正确的 `"aac"`。这是本题最阴的坑。
2. **与 `suf[i+1]` 比较而非 `suf[i]`**：第 $i$ 轮已把 $s[i]$ 压栈，剩余部分从 $i+1$ 起。错位比较会把已入栈的字符也算进「后缀威胁」，导致该弹不弹（如 `"bac"` 输出变大）。
3. **哨兵别忘**：$\text{suf}[n]$ 必须是比 `'z'` 大的值（`'{'` / `chr(127)`），否则最后一个字符压栈后 `while` 条件永假，主循环不弹、只剩清栈兜底——结果碰巧仍对，但依赖末尾清栈补弹的逻辑，一旦把清栈漏写就整组 WA。
4. **末尾清栈必须写**：扫描结束后 `t` 里可能还有字符（它们全是被更大的后缀最小值「按住」的），此时 `s` 空、$m = +\infty$，全部弹出即可。漏写则输出长度不足。
5. **单调栈直觉的误用**：本题**不是**「栈顶比下一个小就弹」的单调栈——决定弹不弹的是**整个后缀的最小值**，不是下一个字符。`s = "dda"` 中栈顶 `d` 大于下一个 `d`、但小于后缀最小 `a`，照样不能弹。
6. **`n = 1`**：压入后立即弹出，输出 `s` 本身，哨兵机制天然处理，无需特判。
7. **性能**：`p` 用可变结构（`string` / `list`）追加，最后返回；Python 里 `+=` 字符串在 CPython 有优化但比赛环境不可依赖，`''.join` 最稳。

**延伸思考**：

- 若操作②改为「删除 `t` 的**第一个**字符」（`t` 变成队列）会怎样？——`t` 退化为 FIFO 缓冲，弹出顺序恒等于压入顺序，`p` 只能是 `s` 本身，问题失去趣味。**栈的 LIFO 可逆性正是本题的灵魂**。
- 若再给一个「撤销」操作（把刚写到纸上的最后一个字符拿回 `t`）呢？——这等价于在生成 `p` 的过程中允许回溯，但字典序贪心的每一步本就是「局部最优即全局最优」（引理 2），撤销不会带来改进，答案不变。
- 若要求输出的是 `s` 的排列中字典序最小且**可由栈生成**的序列的**第 k 小**呢？需要用「栈混洗计数」（卡特兰数式的 DP）定位，难度陡增——从「构造最优」升级为「在 reachable 集合上做有序选择」。
