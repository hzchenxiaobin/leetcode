# LeetCode 最后一块石头的重量 II 题解

## 1. 题目概述

- **标题 / 题号**：最后一块石头的重量 II（#1049，medium）
- **链接**：https://leetcode.cn/problems/last-stone-weight-ii/
- **来源**：LeetCode 第 137 场周赛 Q4
- **难度**：中等
- **标签**：数组、动态规划、背包问题、0-1 背包

**题意**：给定石头重量数组 `stones`。每回合可以选出**任意两块**石头粉碎，设重量 $x \le y$：若 $x = y$ 两块都粉碎；否则 $y$ 变成 $y - x$。反复操作直到至多剩一块，求剩下石头**最小可能的重量**；若一块不剩则为 0。

**约束**：

- $1 \le \text{stones.length} \le 30$
- $1 \le \text{stones}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：stones = [2,7,4,1,8,1]
输出：1
解释：2 与 4 → 2；7 与 8 → 1；2 与 1 → 1；1 与 1 → 0；最后剩 1。
      等价于把石头分成 {2,7,1,1}（和 11）与 {4,8}（和 12），差为 1。
```

**示例 2**

```text
输入：stones = [31,26,33,21,40]
输出：5
解释：总和 151，可凑出 73（33+40）与 78，差为 5。
```

## 3. 解题思路

### 3.1 暴力思路

模拟所有粉碎顺序：每步从 $n$ 块中任选两块，方案数爆炸（$O(n!)$ 级别），且大量状态重复。$n \le 30$ 时完全不可行。

### 3.2 核心观察：每块石头最终带一个 ± 号

![± 号模型](images/wc137_q4_sign_model.svg)

给每块石头分配一个符号 $\varepsilon_i \in \{+1, -1\}$，考虑**带符号和**

$$S = \sum_i \varepsilon_i a_i.$$

一次粉碎操作 $x, y \to |y - x|$ 相当于把两个同号项合并（符号保持）或把一正一负抵消。可以证明：

1. **不变性**：过程中 $S$ 始终不变，最后剩下的那块石头的重量就是 $\lvert S \rvert$；
2. **任意性**：**任何一种**符号分配都能通过某种粉碎顺序实现。

于是问题变成：选择符号使 $\lvert S \rvert$ 最小。把取 $+$ 的石头记为集合 $P$、取 $-$ 的记为集合 $N$，则

$$\lvert S \rvert = \bigl\lvert \text{sum}(P) - \text{sum}(N) \bigr\rvert = \bigl\lvert T - 2\cdot\text{sum}(P) \bigr\rvert, \qquad T = \sum_i a_i.$$

要让这个值最小，就要让 $\text{sum}(P)$ **尽量接近 $T/2$ 且不超过 $T/2$**。这正是 **0/1 背包**：物品重量 $a_i$、容量 $\lfloor T/2 \rfloor$，求可达的最大和。

$$\text{answer} = T - 2 \cdot \max\{\, s \le \lfloor T/2 \rfloor : s \text{ 可由若干 } a_i \text{ 凑出} \,\}$$

### 3.3 算法流程

![背包演算](images/wc137_q4_knapsack_walkthrough.svg)

```text
1. T = sum(stones)，half = T // 2
2. dp[0..half] 布尔数组，dp[0] = true
3. for w in stones:                     # 0/1 背包，每块石头只能用一次
       for s = half down to w:
           若 dp[s - w]: dp[s] = true
4. 从 half 向下找第一个 dp[s] 为真的 s
5. 返回 T - 2*s
```

**容量必须从大到小枚举**，否则同一块石头会被重复使用（那就成了完全背包）。

### 3.4 示例演算

对 `[2,7,4,1,8,1]`，$T = 23$，$half = 11$：

| 加入的石头 | 可达和集合（≤ 11 的部分） |
|-----------|--------------------------|
| 2 | 0, 2 |
| 7 | 0, 2, 7, 9 |
| 4 | 0, 2, 4, 6, 7, 9, 11 |
| 8 | 0, 2, 4, 6, 7, 8, 9, 10, 11 |
| 1, 1 | 不超过 11 的最大可达和 = **11** |

答案 $= 23 - 2\times11 = 1$，与示例一致。对应的划分是 $P = \{2,7,1,1\}$（和 11）、$N = \{4,8\}$（和 12）。

示例 2：$T = 151$、$half = 75$，可达的最大和为 73（$33 + 40$），答案 $151 - 146 = 5$ ✓。

## 4. 算法细节

1. **背包容量取 $\lfloor T/2 \rfloor$**：超过一半的方案与「另一半」互补，差值相同（$\lvert T - 2s \rvert = \lvert T - 2(T-s) \rvert$），故只需搜一半。
2. **一维布尔数组**：`dp[s]` 表示「能否凑出和 $s$」，用 `vector<char>` / `bytearray` 省内存；C++ 也可用 `bitset` 做整体移位加速（`dp |= dp << w`）。
3. **逆序更新**：`for (s = half; s >= w; s--)` 是 0/1 背包的标志；写成正序会变成「每块石头无限可用」。
4. **正确答案一定存在**：$s = 0$ 恒可达（全取负号），故循环必能找到。
5. **不必显式构造方案**：题目只要最小重量，不需要给出具体的粉碎顺序。

## 5. 正确性证明

**引理 1（粉碎 = 翻转较轻者的符号后合并）**：设待粉碎的两块石头重量为 $a \le b$，则合并后的重量 $b - a$ 的带符号贡献，恰等于「把较轻者 $a$ 的符号翻转后与 $b$ 合并」；若两者本来异号，则等于「直接合并」。因此整个过程中可以给每块（合并后的）石头维持一个符号，使最终重量 $= \bigl\lvert \sum_i \varepsilon_i a_i \bigr\rvert$。

**证明**：分三种情形核验合并前后的带符号值：

- 两块都为正（$+a$、$+b$）：合并后为 $+(b - a) = (+b) + (-a)$，即把 $a$ 的符号翻成负号；
- 两块都为负（$-a$、$-b$）：合并后为 $-(b - a) = (-b) + (+a)$，同样是把较轻者 $a$ 的符号翻正；
- 一正一负（$+a$、$-b$，$a \le b$）：合并后为 $-(b - a) = (+a) + (-b)$，直接相加即可，无需翻号。

三种情形的合并结果都满足「重量 = 带符号值的绝对值」，且符号规则可递推地维护下去。∎

**引理 2（最终重量的形式）**：任意粉碎顺序结束后，剩下的那块石头的重量（若存在）都等于 $\bigl\lvert\sum_i \varepsilon_i a_i\bigr\rvert$，其中 $\varepsilon_i \in \{+1,-1\}$ 由该顺序决定。

**证明**：对粉碎次数归纳。初始时每块石头单独、符号皆为正。每一步由引理 1，把两块石头的带符号值按规则合并为一个带符号值，合并后「重量 = 带符号值的绝对值」这一性质保持；负号情形说明符号分配会随操作改变，但形式不变。最终只剩一个带符号值时，其绝对值即最终重量。∎

**引理 3（任意符号分配都可实现）**：对任意 $\varepsilon \in \{+1,-1\}^n$，都存在一种粉碎顺序使最终重量恰为 $\lvert\sum \varepsilon_i a_i\rvert$。

**证明**：对 $n$ 归纳。

- $n = 1$：唯一石头，重量 $a_1 = \lvert\varepsilon_1 a_1\rvert$ ✓。
- $n \ge 2$：由抽屉原理，$n \ge 2$ 块石头的符号中必有两块**同号**（只有两种符号）。粉碎这两块（重量 $a, b$，同号），得到新石头 $\lvert a - b\rvert$，并给它保留该符号；此时石头数变为 $n-1$，而总和 $\sum \varepsilon_i a_i$ 中这两项合并为 $\pm\lvert a-b\rvert$，数值不变。由归纳假设，对剩下的 $n-1$ 块可以按同样的符号分配实现。故原分配可实现。∎

**引理 4（子集和等价）**：目标值 $\lvert\sum \varepsilon_i a_i\rvert$ 的最小可能值等于 $T - 2s^*$，其中 $s^*$ 是不超过 $\lfloor T/2\rfloor$ 的最大可达子集和。

**证明**：把取 $+$ 的下标集合记为 $P$，则 $\sum\varepsilon_i a_i = \text{sum}(P) - (T - \text{sum}(P)) = 2\,\text{sum}(P) - T$。于是

$$\min_{\varepsilon} \bigl\lvert 2\,\text{sum}(P) - T\bigr\rvert = T - 2\max\{\text{sum}(P) : \text{sum}(P) \le T/2\}$$

（因为 $x \mapsto \lvert 2x - T\rvert$ 在 $x \le T/2$ 上单调递减，且每个 $x > T/2$ 都被 $T - x < T/2$ 对应同一差值）。$\text{sum}(P)$ 的可达值恰为「若干 $a_i$ 之和」的集合，即背包的可行解集。∎

**定理**：算法返回 $T - 2s^*$，等于最后一块石头可能的最小重量。

**证明**：由引理 2、3，可能的最终重量集合恰为 $\{\lvert\sum\varepsilon_i a_i\rvert\}$ 全体；由引理 4，其最小值等于 $T - 2s^*$。算法正是通过 0/1 背包求出 $s^*$ 并返回 $T - 2s^*$。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot T/2)$。外层 $n$ 块石头，内层枚举容量到 $\lfloor T/2 \rfloor$；$n \le 30$、$T \le 3000$，最多约 $4.5\times10^4$ 次更新。若用 `bitset` 优化可再降一个常数因子（按位并行）。
- **空间**：$O(T/2)$ 的布尔数组（约 1.5 KB）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <numeric>
using namespace std;

class Solution {
public:
    int lastStoneWeightII(vector<int>& stones) {
        int total = 0;
        for (int w : stones) total += w;
        int half = total / 2;
        vector<char> dp(half + 1, 0);        // dp[s]：能否用石子凑出重量和 s
        dp[0] = 1;
        for (int w : stones) {
            for (int s = half; s >= w; s--) {
                if (dp[s - w]) dp[s] = 1;
            }
        }
        for (int s = half; s >= 0; s--) {
            if (dp[s]) return total - 2 * s;  // total - 2*s 即两堆之差
        }
        return total;
    }
};
```

### Python

```python
class Solution:
    def lastStoneWeightII(self, stones: list[int]) -> int:
        total = sum(stones)
        half = total // 2
        dp = bytearray(half + 1)        # dp[s]：能否凑出重量和 s
        dp[0] = 1
        for w in stones:
            for s in range(half, w - 1, -1):
                if dp[s - w]:
                    dp[s] = 1
        best = max(s for s in range(half + 1) if dp[s])
        return total - 2 * best
```

## 8. 边界情况与易错点

1. **只有一块石头**：答案为该石头重量。此时 $half = a/2$，$s^* = 0$，返回 $T - 0 = a$ ✓。
2. **总和为偶数且能对半**：答案是 0（例如 `[2,2]`、`[1,2,3]`）。
3. **逆序更新不能忘**：正序更新会让一块石头被多次使用，等价于「完全背包」，结果是错的（可能返回 0 或负数）。
4. **`half` 取下整**：$T$ 为奇数时 $\lfloor T/2\rfloor$ 已经是最大可能的不超过一半的整数，无需特判。
5. **返回值一定非负**：$s^* \le T/2$，故 $T - 2s^* \ge 0$；若出现负数说明背包写错了。
6. **符号模型的理解陷阱**：不要把「带符号和」误认为「始终等于初始总和」——粉碎会**翻转**较轻者的符号（引理 1），正因如此才能把差值做小；符号分配是实现差值的手段，不是守恒量。
7. **两种语言的布尔数组**：C++ 用 `vector<char>`（`vector<bool>` 是按位压缩，性能反而可能更差），Python 用 `bytearray`。
