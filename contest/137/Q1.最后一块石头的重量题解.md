# LeetCode 最后一块石头的重量 题解

## 1. 题目概述

- **标题 / 题号**：最后一块石头的重量（#1046，easy）
- **链接**：https://leetcode.cn/problems/last-stone-weight/
- **来源**：LeetCode 第 137 场周赛 Q1
- **难度**：简单
- **标签**：数组、堆（优先队列）

**题意**：给定一堆石头的重量（正整数数组 `stones`）。每回合选出**最重的两块**石头，设重量为 $x \le y$：

- 若 $x = y$，两块都完全粉碎；
- 若 $x \ne y$，$x$ 粉碎，$y$ 变成新石头 $y - x$。

重复直到至多剩一块石头，返回这块石头的重量；若一块不剩，返回 0。

**约束**：

- $1 \le \text{stones.length} \le 30$
- $1 \le \text{stones}[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：[2,7,4,1,8,1]
输出：1
解释：取 8 与 7 → 1，集合变 [2,4,1,1,1]；
      取 4 与 2 → 2，集合变 [2,1,1,1]；
      取 2 与 1 → 1，集合变 [1,1,1]；
      取 1 与 1 → 0，集合变 [1]，答案为 1。
```

**示例 2**

```text
输入：[1]
输出：1
解释：只有一块石头，无法操作，直接返回 1。
```

**示例 3（补充）**

```text
输入：[2,2]
输出：0
解释：两块一样重，同时粉碎，一块不剩 → 0。
```

## 3. 解题思路

### 3.1 暴力思路

每回合把数组排序、取末尾两个、处理后再排序。$n \le 30$ 时 $O(n^2 \log n)$ 也能过，但每次排序都重复了「找最大两块」这件事——这正是**堆**的用武之地。

### 3.2 核心观察：只需要「取最大两块」与「插回一个值」

![堆模拟流程](images/wc137_q1_heap_sim.svg)

模拟过程需要支持两种操作：

1. **取出当前最大的两块**；
2. 若两者不等，**把差值插回集合**。

大顶堆（优先队列）恰好把这两个操作都做到 $O(\log n)$。C++ 的 `priority_queue` 默认就是大顶堆；Python 的 `heapq` 是小顶堆，**存相反数**即可模拟。

为什么不贪心/排序一次就够？因为差值 $y - x$ 可能比很多剩余石头都大，必须重新参与比较——所以要么用堆，要么每次重排。

### 3.3 算法流程

```text
1. 把所有 stones 放入大顶堆
2. 当堆大小 > 1：
       x = 弹出最大；y = 弹出次大        # x >= y
       若 x != y：把 x - y 压入堆
3. 返回 堆顶（若堆为空返回 0）
```

### 3.4 示例演算

![示例 1 的逐轮演算](images/wc137_q1_example_walkthrough.svg)

对 `[2,7,4,1,8,1]`：

| 轮次 | 取出的两块 | 操作 | 剩余集合 |
|------|-----------|------|----------|
| 0 | — | 初始 | 2,7,4,1,8,1 |
| 1 | 8, 7 | 差 1 入堆 | 2,4,1,1,1 |
| 2 | 4, 2 | 差 2 入堆 | 2,1,1,1 |
| 3 | 2, 1 | 差 1 入堆 | 1,1,1 |
| 4 | 1, 1 | 相等，都粉碎 | 1 |

堆只剩 1 块，返回 1，与示例一致。

## 4. 算法细节

1. **堆的方向**：C++ `priority_queue<int>` 是大顶堆；Python `heapq` 是小顶堆，必须存 `-w`，弹出后再取负。
2. **相等时不要 push**：`x == y` 时两块都消失，此时堆大小减 2；若误把 0 压回去，会多出一块重量为 0 的石头，虽然不影响最终数值，但会让循环多跑（且 `x == 0` 会与其它石头反复配对）。
3. **空堆处理**：$n = 1$ 且重量为 0 的情况在约束下不存在（$stones[i] \ge 1$），但 `return pq.empty() ? 0 : pq.top()` 的写法更安全。
4. **循环条件**：`while (pq.size() > 1)`，注意是**严格大于 1**；`size() == 1` 时直接返回堆顶。
5. **返回值类型**：`int`，重量不超过 $1000 \times 30$，无溢出风险。

## 5. 正确性证明

**引理 1（堆的每次操作都取到当前最重的两块）**：在大顶堆中，连续两次 `pop` 得到的两个元素恰为当前集合中最大的两个（允许并列）。

**证明**：大顶堆的堆顶是集合最大值，第一次 `pop` 后堆中剩余元素仍是其余元素的堆，第二次 `pop` 得到剩余元素的最大值，即原集合的次大值。∎

**引理 2（单轮处理与题面规则一致）**：设当前两块最重的石头为 $x \ge y$，则题面规定的处理结果与「$x = y$ 时同时删除，否则删除二者并插入 $x-y$」完全一致。

**证明**：题面规则直接转写：$x = y$ 时两块都完全粉碎（删除两块）；$x \ne y$ 时较轻者粉碎、较重者变为 $y - x$（删除两块、插入差值）。∎

**引理 3（终止性）**：循环在有限步内结束，且每轮之后石头总数至少减少 1。

**证明**：每轮弹出 2 块；若相等则不插回（总数减少 2），若不等则插回 1 块（总数减少 1）。总数严格递减且非负，故至多 $n-1$ 轮后总数 $\le 1$，循环结束。∎

**定理**：算法返回的堆顶（或 0）就是按题意模拟到无法继续时剩下的那块石头的重量。

**证明**：由引理 1、2，每轮的状态转移与题面规则一致；由引理 3，模拟有限步后终止且恰在「石头不足两块」时停止，这正是题面的结束条件。故最终堆中（若存在）唯一元素即为答案，空堆时答案为 0。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。建堆 $O(n)$；至多 $n-1$ 轮，每轮 2 次 `pop` + 至多 1 次 `push`，每次 $O(\log n)$。
- **空间**：$O(n)$ 的堆空间。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    int lastStoneWeight(vector<int>& stones) {
        priority_queue<int> pq(stones.begin(), stones.end());
        while (pq.size() > 1) {
            int x = pq.top(); pq.pop();      // 最重
            int y = pq.top(); pq.pop();      // 次重
            if (x != y) pq.push(x - y);      // 相等则两块都粉碎
        }
        return pq.empty() ? 0 : pq.top();
    }
};
```

### Python

```python
import heapq

class Solution:
    def lastStoneWeight(self, stones: list[int]) -> int:
        heap = [-w for w in stones]      # 取负号模拟大顶堆
        heapq.heapify(heap)
        while len(heap) > 1:
            x = -heapq.heappop(heap)     # 最重
            y = -heapq.heappop(heap)     # 次重
            if x != y:
                heapq.heappush(heap, -(x - y))
        return -heap[0] if heap else 0
```

## 8. 边界情况与易错点

1. **只有一块**：直接返回它，不进循环（示例 2）。
2. **两块相等**：都消失，答案可能是 0（示例 3）；注意最后一轮 `x == y` 后堆变空，`pq.top()` 会越界，必须判空。
3. **Python 的负号**：`heapq` 是小顶堆，存 `-w` 后弹出要取反；容易漏掉某处取反导致「取到最轻的」。
4. **别用排序 + 插入**：虽然 $n \le 30$ 也能过，但每轮重排是 $O(n \log n)$，整体 $O(n^2\log n)$，堆的写法更贴近「动态取最值」的本质。
5. **0 重量的石头**：约束下不会出现；若强行 push 0（例如误把相等情形处理成 `push(0)`），会让 `x == 0` 的轮次反复出现，虽不改变答案但多跑循环。
6. **顺序无关**：模拟过程与初始顺序无关，故无需排序输入。
