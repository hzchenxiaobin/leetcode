# LeetCode 通过删除字母匹配到字典里最长单词 题解

## 1. 题目概述

- **标题 / 题号**：通过删除字母匹配到字典里最长单词（#524，medium）
- **链接**：https://leetcode.cn/problems/longest-word-in-dictionary-through-deleting/
- **来源**：LeetCode 第 21 场周赛 Q3
- **难度**：中等
- **标签**：数组、双指针、字符串、排序

**题意**：给定字符串 $s$ 和词表 `dictionary`，从词表中找出所有**可以由 $s$ 删除若干字符得到**的单词（等价说法：单词是 $s$ 的**子序列**），返回其中**长度最长**的一个；长度并列时返回**字典序最小**的；一个都不存在则返回空串 `""`。

**约束**：
- $1 \le \lvert s \rvert \le 1000$
- $1 \le \lvert \text{dictionary} \rvert \le 1000$，且每个词满足 $1 \le \lvert w \rvert \le 1000$
- $s$ 与每个 $w$ 均只含小写英文字母

> 💡 「删除某些字符」既不要求连续，也不要求把 $s$ 删空；保留下来的部分必须**保持原相对顺序**——这正是「子序列」的定义，也是本题唯一需要的结构。

## 2. 示例

**示例 1**

```text
输入：s = "abpcplea", dictionary = ["ale","apple","monkey","plea"]
输出："apple"
解释："ale"、"apple"、"plea" 都是 s 的子序列；
      "monkey" 含有 s 中根本不存在的 'm'，不是子序列。
      合法词中 "apple" 长度 5 最长，故答案为 "apple"。
```

**示例 2**

```text
输入：s = "abpcplea", dictionary = ["a","b","c"]
输出："a"
解释：三个词都是子序列且长度都为 1，取字典序最小的 "a"。
```

**补充样例（自测）**

```text
输入：s = "bab", dictionary = ["ba","ab","a","b"]
输出："ab"
解释："ba" 与 "ab" 都是长度 2 的子序列，此时必须比字典序："ab" < "ba"。
      注意不能因为 "ba" 在词表中更靠前就返回它。
```

## 3. 解题思路

### 3.1 暴力思路

两个方向都会爆：

1. **枚举 $s$ 的全部子序列**：$s$ 的子序列共有 $2^{\lvert s \rvert}$ 个，$n = 1000$ 时是天文数字，即使只保留长度不超过 $\max\lvert w \rvert$ 的也依旧不可行。
2. **对每个词做 LCS 动态规划**：把问题转成「$s$ 与 $w$ 的最长公共子序列是否等于 $w$」，单个词 $O(n\lvert w\rvert)$；$1000$ 个词、每个 $10^{6}$ 的 DP 表 → $10^{9}$ 量级，代码也更长。

关键在于：**判定「$w$ 是否为 $s$ 的子序列」根本不需要 DP**，一次贪心扫描就够。

### 3.2 核心观察：贪心双指针判定 + 全序比较键

![贪心双指针与比较键](images/wc21_q3_greedy_subsequence_insight.svg)

**观察一（判定只值一次扫描）**：让指针 $i$ 指向 $w$ 中下一个待匹配的字符，从左到右扫 $s$；一旦 $s_j = w_i$ 就令 $i \leftarrow i+1$。扫描结束若 $i = \lvert w \rvert$，则 $w$ 是 $s$ 的子序列，复杂度 $O(\lvert s \rvert + \lvert w \rvert)$。

这个贪心的直觉是「能配就配、绝不等待」。它之所以不会错过解，是因为：**尽可能早地匹配当前字符，绝不会让后面的字符更难匹配**（§5 引理 1 用归纳法给出严格证明）。

**观察二（答案是某个全序下的最小值）**：给每个候选词 $w$ 定义键

$$\text{key}(w) = \bigl(-\lvert w \rvert,\; w\bigr)$$

按二元组字典序比较：先比 $-\lvert w \rvert$，等价于长度**从大到小**；长度相同时再比 $w$，等价于字典序**从小到大**。于是「最长且字典序最小」$\iff$「$\text{key}$ 最小」。

整个问题因此变成：**求全部合法词中 $\text{key}$ 最小的那一个**。把词表按 $\text{key}$ 升序排序，从前往后逐个判定，**第一个通过的词就是答案**——既不用维护 best 指针，也不用去重。

### 3.3 算法流程

![算法流程](images/wc21_q3_algorithm_flow.svg)

1. **排序**：把 `dictionary` 按 $(-\lvert w \rvert, w)$ 升序排序（长度降序、同长字典序升序）。
2. **剪枝**：若 $\lvert w \rvert > \lvert s \rvert$，$w$ 一定不是子序列，直接跳过；进一步可预统计 $s$ 的字符频次 $\text{cnt}[26]$，对「$w$ 中某字符的需求量超过 $s$ 中的总量」的候选做 $O(\lvert w \rvert)$ 级淘汰。
3. **判定**：双指针贪心扫描 $s$，只有 $s_j = w_i$ 时 $i$ 才前进。
4. **返回**：首个命中的词立即返回；所有词都不命中则返回 `""`。

> 💡 两个**可选**优化（不改变结果，参考代码保留最简版本）：
> ① 不排序、单遍扫描时用 $\text{key}$ 比较维护 best，省掉 $O(k\log k)$ 次字符串比较；
> ② 对 $s$ 预处理 `nxt[i][c]`（下标 $i$ 之后字符 $c$ 的最早出现位置），把单次判定从 $O(n+\lvert w \rvert)$ 降到 $O(\lvert w \rvert)$，适合 $\lvert s \rvert$ 很大的变体（见文末延伸思考）。

### 3.4 示例演算

![示例演算](images/wc21_q3_example_walkthrough.svg)

对示例 1（$s = \text{"abpcplea"}$，下标 $0\ldots7$ 依次为 `a b p c p l e a`），排序后的候选队列与判定情况：

| 候选词（按 key 排序） | 长度 | 双指针命中下标 | 判定 |
|---|---|---|---|
| `monkey` | 6 | ——（$s$ 中没有 `m`） | 失败 |
| `apple` | 5 | 0 → 2 → 4 → 5 → 6 | **命中，立即返回** |
| `plea` | 4 | 2 → 5 → 6 → 7 | 已返回，不再判定 |
| `ale` | 3 | 0 → 5 → 6 | 已返回，不再判定 |

最长的 `monkey` 因缺字符 `m` 在第一步就出局；`apple` 长度 5 且命中，直接返回，后面的词连 $s$ 都不必再扫。把示例 2 的 `["a","b","c"]` 代入：三者长度相同，排序后为 `a, b, c`，`a` 先命中即返回，正好体现「同长取字典序最小」。

## 4. 算法细节

1. **排序比较器必须写两条规则**：长度降序 + 字典序升序。只写长度排序时，同长候选的先后取决于原始输入顺序，会返回错误的词（如 `["ba","ab"]` 可能返回 `"ba"`）。
2. **双指针的推进位置只有一处**：只有 `s[j] == w[i]` 时 `i++`，`j` 无论是否命中都要前进；把 `i++` 写进不等分支就会误判。
3. **长度剪枝放在判定之前**：$\lvert w \rvert > \lvert s \rvert$ 直接 `continue`，避免白扫一遍 $s$；配合 $\text{cnt}[26]$ 频次剪枝还能让「缺字符」候选在 $O(\lvert w \rvert)$ 内出局。
4. **判定收尾要显式判 `i == m`**：如果循环内不提前 `return`，循环结束后必须再判断一次，否则「最后一个字符恰好落在 $s$ 末尾」的情形（如 `s = "abc"`、`w = "abc"`）会被漏判。
5. **对副本排序，不要改动入参**：C++ 中 `vector<string>& dictionary` 是引用，需 `vector<string> words = dictionary;` 后排序；Python 用 `sorted(dictionary, ...)` 天然返回新列表。
6. **不必去重**：重复词排序后相邻，首个命中即返回，重复项永远不会被读到；去重只是常数级优化，加了反而多一次哈希开销。
7. **字符集假设**：题目限定小写字母，频次剪枝可以直接用 `int cnt[26]`；若字符集扩大到 Unicode，需换成哈希表或 `map`。

## 5. 正确性证明

**引理 1（贪心匹配位置最小）**：设 $w$ 是 $s$ 的子序列，贪心算法把 $w$ 的第 $j$ 个字符匹配到 $s$ 的下标 $p_j$（$j = 0,1,\dots,m-1$）。则对任意一个合法嵌入 $q_0 < q_1 < \cdots < q_{m-1}$（即 $s_{q_j} = w_j$）与任意 $0 \le j < m$，都有 $p_j \le q_j$。

**证明**：对 $j$ 归纳，记 $p_{-1} = q_{-1} = -1$。

- $j = 0$：$p_0$ 是 $s$ 中第一个等于 $w_0$ 的下标，而 $s_{q_0} = w_0$ 也是这样一个下标，故 $p_0 \le q_0$。
- 设 $p_{j-1} \le q_{j-1}$。贪心在 $p_{j-1}$ 之后取**最早**的等于 $w_j$ 的下标；而 $q_j > q_{j-1} \ge p_{j-1}$ 且 $s_{q_j} = w_j$，说明 $q_j$ 属于「$p_{j-1}$ 之后等于 $w_j$ 的下标集合」，取最早者得 $p_j \le q_j$。∎

**引理 2（判定正确）**：双指针贪心扫描结束时 $i = \lvert w \rvert$，当且仅当 $w$ 是 $s$ 的子序列。

**证明**：
- 若 $i = \lvert w \rvert$：贪心依次确定了 $p_0 < p_1 < \cdots < p_{m-1}$ 且 $s_{p_j} = w_j$，构成一个合法嵌入，故 $w$ 是子序列。
- 若 $w$ 是子序列：取任一合法嵌入 $q_0 < q_1 < \cdots < q_{m-1}$。对 $j$ 归纳证明贪心一定能匹配到 $w_j$ 且 $p_j \le q_j$。$j = 0$ 时由 $s_{q_0} = w_0$ 知 $q_0$ 是一个可选位置，取最早者得 $p_0 \le q_0$；若已配到 $p_{j-1} \le q_{j-1}$，则 $q_j > q_{j-1} \ge p_{j-1}$ 且 $s_{q_j} = w_j$，说明贪心在 $p_{j-1}$ 之后搜索时 $q_j$ 仍在候选范围内，故必能取到 $p_j$ 且 $p_j \le q_j$。归纳到 $j = m-1$ 即知 $m$ 个字符全部配齐，$i$ 达到 $m$。∎

**引理 3（排序后首个命中即最优）**：设 $V$ 为 `dictionary` 中全部合法词的集合且 $V \ne \varnothing$。将 `dictionary` 按 $\text{key}$ 升序排序后，第一个合法词 $v$ 满足：$\lvert v \rvert = \max_{u\in V}\lvert u \rvert$，且在全部最长合法词中 $v$ 的字典序最小。

**证明**：排序后 $v$ 是 $V$ 中键最小的元素，即对任意 $u \in V$ 有 $\text{key}(v) \le \text{key}(u)$。
先看第一分量：若 $\lvert v \rvert < \lvert u \rvert$，则 $-\lvert v \rvert > -\lvert u \rvert$，$\text{key}(v) > \text{key}(u)$，矛盾；故 $\lvert v \rvert \ge \lvert u \rvert$，$v$ 是最长的。
再看长度等于 $\lvert v \rvert$ 的那些 $u$：此时第一分量相等，$\text{key}(v) \le \text{key}(u)$ 迫使 $v \le u$（普通字符串字典序），即 $v$ 在最长者中字典序最小。∎

**定理**：算法返回的字符串恰为题目所求答案。

**证明**：由引理 2，算法对每个词的子序列判定与事实一致，故它跳过的词都非法、返回的词都合法。若 $V = \varnothing$，循环结束返回 `""`，符合「答案不存在返回空串」；若 $V \ne \varnothing$，循环在第一个合法词处返回，由引理 3 该词就是「最长且字典序最小」的合法词。∎

## 6. 复杂度分析

- **时间（排序）**：$O(k\log k)$ 次比较，每次字符串比较最坏 $O(L)$，合计 $O(k\log k \cdot L)$，其中 $k = \lvert\text{dictionary}\rvert$，$L$ 为词长上界。
- **时间（判定）**：每个词先花 $O(1)$ 做长度剪枝，判定为 $O(n + \lvert w \rvert) \le O(n + L)$，共 $O\bigl(k(n+L)\bigr)$；命中即提前返回，实际远小于上界。
- **总时间**：$O(k\log k \cdot L + k(n+L))$。取 $k = n = L = 1000$ 时约 $10^{7}$ 以内，远低于时限。
- **空间**：排序副本占 $O(kL)$ 个字符，排序递归栈 $O(\log k)$；若改为原地排序或单遍维护 best，额外空间可降到 $O(1)$（不计输入）。`nxt` 表变体需 $O(26n)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    string findLongestWord(string s, vector<string>& dictionary) {
        vector<string> words = dictionary;                    // 排序副本，避免改动入参
        sort(words.begin(), words.end(), [](const string& a, const string& b) {
            if (a.size() != b.size()) return a.size() > b.size();  // 长度降序
            return a < b;                                          // 同长字典序升序
        });

        for (const string& w : words) {
            int m = (int)w.size();
            if (m > (int)s.size()) continue;                  // 长度剪枝
            int i = 0;
            for (char c : s) {                                // 贪心：能配就配
                if (i < m && c == w[i]) i++;
            }
            if (i == m) return w;                             // 首个命中即答案
        }
        return "";
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findLongestWord(self, s: str, dictionary: List[str]) -> str:
        words = sorted(dictionary, key=lambda w: (-len(w), w))  # 长度降序、同长字典序升序
        n = len(s)
        for w in words:
            m = len(w)
            if m > n:                      # 长度剪枝：比 s 还长不可能是子序列
                continue
            i = 0
            for ch in s:                   # 贪心：能配就配，i 只前进
                if i < m and ch == w[i]:
                    i += 1
            if i == m:                     # 首个命中即答案
                return w
        return ""
```

## 8. 边界情况与易错点

1. **同长必须比字典序**：不排序而「先遇到先返回」会错。例如 `s = "bab"`、`dictionary = ["ba","ab"]`，正解是 `"ab"` 而非 `"ba"`。
2. **无解返回空串**：返回 `""`，不是 `null`、不是 `-1`、也不是词表第一个元素。
3. **长度剪枝**：$\lvert w \rvert > \lvert s \rvert$ 时不可能是子序列，先 `continue`，否则每个超长词都要白扫一遍 $s$。
4. **缺字符的候选**：如示例 1 中的 `monkey`，`m` 完全不在 $s$ 中；用频次剪枝可在 $O(\lvert w \rvert)$ 内出局，而不必扫完 $s$。
5. **最后一个字符落在 $s$ 末尾**：如 `s = "abc"`、`w = "abc"`，必须靠循环结束后的 `i == m` 收尾判断，漏掉就返回错误的空串。
6. **重复词与乱序输入**：`dictionary` 可能乱序、可能含重复项；排序后重复项相邻，首个命中即返回，结果不受影响。
7. **$\lvert s \rvert = 1$ 的极小规模**：只有单字符词可能命中，但仍要按字典序取最小，例如 `s = "a"`、词表 `["b","a"]` 应返回 `"a"`。
