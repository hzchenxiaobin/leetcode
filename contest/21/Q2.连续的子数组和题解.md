# LeetCode 连续的子数组和 题解

## 1. 题目概述

- **标题 / 题号**：连续的子数组和（#523，medium）
- **链接**：https://leetcode.cn/problems/continuous-subarray-sum/
- **来源**：LeetCode 第 21 场周赛 Q2
- **难度**：中等
- **标签**：数组，哈希表，数学，前缀和，抽屉原理

**题意**：给定整数数组 `nums` 与整数 `k`，判断是否存在一个**长度至少为 2** 的连续子数组，其元素之和是 `k` 的整数倍（`0` 视为任何 `k` 的倍数）。存在返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $0 \le \text{nums}[i] \le 10^9$
- $0 \le \sum \text{nums}[i] \le 2^{31} - 1$
- $1 \le k \le 2^{31} - 1$

数据规模决定了 $O(n^2)$ 不可行；总和逼近 `int` 上界，累加必须用 64 位或 Python 大整数。

## 2. 示例

**示例 1**

```text
输入：nums = [23,2,4,6,7], k = 6
输出：true
解释：子数组 [2,4] 长度为 2，和为 6 = 1 × 6，是 6 的倍数。
```

**示例 2**

```text
输入：nums = [23,2,6,4,7], k = 6
输出：true
解释：整个数组长度为 5，和为 42 = 7 × 6，是 6 的倍数。
```

**示例 3**

```text
输入：nums = [23,2,6,4,7], k = 13
输出：false
解释：所有长度 ≥ 2 的连续子数组之和都不是 13 的倍数。
```

## 3. 解题思路

### 3.1 暴力思路

先做前缀和，令 $P[t] = \text{nums}[0] + \cdots + \text{nums}[t-1]$（$P[0] = 0$），于是子数组 $\text{nums}[i..j]$ 的和可以在 $O(1)$ 内得到：

$$\text{sum}(i, j) = P[j+1] - P[i]$$

枚举全部 $\binom{n}{2}$ 个端点对并检查该和能否被 $k$ 整除，时间 $O(n^2)$。$n = 10^5$ 时约 $5 \times 10^9$ 次操作，超时。也无法改用双指针：窗口收缩时「和是否被 $k$ 整除」并不单调（去掉一个元素后余数关系可能反转），滑动窗口没有可依赖的单调性。

### 3.2 核心观察：同余 + 抽屉原理

![前缀和同余：和是 k 的倍数等价于余数相同](images/wc21_q2_prefix_mod_concept.svg)

把「整除」翻译成「同余」。由 $\text{sum}(i,j) = P[j+1] - P[i]$：

$$k \mid \text{sum}(i, j) \iff P[j+1] \equiv P[i] \pmod{k}$$

也就是说：**只要两个前缀和模 $k$ 的余数相同，它们之间的那段子数组就是 $k$ 的倍数**。于是问题变成「找出两个下标相同余数、且下标差至少为 2 的前缀和」。

**抽屉原理**给出的直觉是：$n+1$ 个前缀和只有 $k$ 种余数，当 $n+1 > k$ 时同余对必然存在——但「存在」不等于「下标差 ≥ 2」，例如两个相邻前缀和同余，中间只有一个元素，长度不足 2。因此不能只判同余，还要判距离。

**关键决策**：对每个余数，只记录它**最早**出现的下标。固定右端点 $j+1$ 时，最早的下标给出的子数组最长，最容易满足「长度 ≥ 2」，也最不容易漏判。

### 3.3 算法流程

![一次线性扫描的流程图](images/wc21_q2_one_pass_flow.svg)

维护哈希表 `first`，键是余数 $r$，值是「前缀和 $P$ 取到余数 $r$ 时对应的**元素下标**」——即该前缀最后一个元素的下标，空前缀记为 $-1$。

```text
first = {0: -1}, s = 0
for i, x in enumerate(nums):
    s += x
    r = s mod k
    if r in first:
        if i - first[r] >= 2:  return true     # 长度达标
        # 否则长度只有 1（即 i - first[r] == 1），继续扫描
    else:
        first[r] = i                            # 只写首次，绝不覆盖
return false
```

当循环走到下标 $i$ 时，$s = P[i+1]$，命中 `first[r] = f` 意味着 $P[i+1] \equiv P[f+1] \pmod{k}$，对应子数组 $\text{nums}[f+1..i]$，长度恰为 $i - f$。

### 3.4 示例演算

![示例 1 的逐步演算表](images/wc21_q2_walkthrough.svg)

对 `nums = [23,2,4,6,7]`、$k = 6$：

| $i$ | `nums[i]` | $s = P[i+1]$ | $s \bmod 6$ | `first` 变化 | 判定 |
|-----|-----------|--------------|-------------|--------------|------|
| 0 | 23 | 23 | 5 | `first[5] = 0` | 首次出现 |
| 1 | 2 | 25 | 1 | `first[1] = 1` | 首次出现 |
| 2 | 4 | 29 | 5 | 不写入 | 命中 `first[5] = 0`，$2 - 0 = 2 \ge 2$ → `true` |

命中的左端点是 $\text{first}[5] + 1 = 1$，对应子数组 $\text{nums}[1..2] = [2, 4]$，和 $= 29 - 23 = 6$，正是示例 1 的答案。

再看示例 2 的「差 1」陷阱：`nums = [23,2,6,4,7]`、$k = 6$ 时，$i = 2$ 的 $s = 31 \equiv 1$ 与 `first[1] = 1` 同余，但 $2 - 1 = 1 < 2$，此时**不能返回 `false`**；继续到 $i = 4$，$s = 42 \equiv 0$ 命中 `first[0] = -1`，$4 - (-1) = 5 \ge 2$，返回 `true`。

## 4. 算法细节

1. **前缀和用 64 位**：总和上界 $2^{31}-1$ 恰好贴着 `int` 上界，`s += nums[i]` 在任何一步都不能溢出，C++ 用 `long long`，Python 天然大整数。
2. **哈希表初值**：`first[0] = -1` 代表空前缀 $P[0] = 0$，下标 $-1$。这样「从数组开头开始的子数组」也能被统一处理（长度 $i - (-1) = i + 1$）。
3. **只写首次**：`r` 已存在时不要更新为 $i$。覆盖会丢掉更早的下标，使后续长度判定偏小，直接漏判。
4. **长度公式**：存的是元素下标之差，`i - first[r]` 就是子数组长度，不要写成 `i - first[r] + 1`（那会多算一个元素，把长度 1 误判成长度 2）。
5. **差 1 时继续扫描**：`i - first[r] == 1` 说明这段只有一个元素，虽然和是 $k$ 的倍数，但不满足长度要求，必须往后看，不能当成反例。
6. **哈希表容量**：不同余数最多 $\min(n+1, k)$ 个，$k$ 可达 $2^{31}-1$，所以不能开大小为 $k$ 的数组；用 `unordered_map` 并 `reserve` 避免 rehash，或用 Python `dict`。
7. **余数规范化**：本题 $\text{nums}[i] \ge 0$，`s % k` 天然落在 $[0, k-1]$；若题目允许负数，C++ 需写成 `((s % k) + k) % k`，Python 的 `%` 已返回非负值。
8. **提前剪枝**：$n < 2$ 时直接返回 `false`，省去建表；$k = 1$ 时任何长度 ≥ 2 的子数组都合格，也可特判。二者都不是必需，但能让代码意图更清楚。

## 5. 正确性证明

**引理 1（同余判别）**：对 $0 \le i \le j < n$，有 $k \mid \text{sum}(\text{nums}[i..j]) \iff P[j+1] \equiv P[i] \pmod{k}$。

**证明**：$\text{sum}(\text{nums}[i..j]) = P[j+1] - P[i]$。整数 $k$ 整除该差，当且仅当两个前缀和在模 $k$ 下相等，即 $P[j+1] \equiv P[i] \pmod{k}$。∎

**引理 2（最早下标最优）**：设 $f(r)$ 为余数 $r$ 在所有前缀和中首次出现的下标。若存在下标对 $q < p$ 满足 $P[q] \equiv P[p] \equiv r \pmod{k}$ 且 $p - q \ge 2$，则 $p - f(r) \ge p - q \ge 2$。

**证明**：$q$ 是取余数 $r$ 的合法下标，由 $f(r)$ 的极小性有 $f(r) \le q$，两边同时用 $p$ 相减得 $p - f(r) \ge p - q \ge 2$。故以 $p$ 为右端、$f(r)$ 为左端得到的子数组长度不小于原来那一段，条件依然成立。∎

**引理 3（不变量）**：扫描到元素下标 $i$ 时，`first[r]` 存在当且仅当余数 $r$ 在 $P[0..i]$ 中出现过，且其值等于 $f(r) - 1$（$f(r)$ 为该余数在 $P[0..i]$ 中首次出现的下标；$r = 0$ 时 $f(0) = 0$，表中即为 $-1$）。

**证明**：对 $i$ 归纳。$i = 0$ 前表中仅有 `first[0] = -1`，对应 $P[0] = 0$，成立。每轮只在 `r` 不存在时写入 `first[r] = i`，对应前缀 $P[i+1]$ 取余数 $r$ 的首次出现；已存在时不动，故首次性始终保留。∎

**定理**：算法返回 `true` 当且仅当存在长度 $\ge 2$ 且和能被 $k$ 整除的连续子数组。

**证明**：

- ($\Leftarrow$) 设存在好子数组 $\text{nums}[i..j]$，$j - i + 1 \ge 2$，且由引理 1 有 $P[j+1] \equiv P[i] \pmod{k}$。令 $p = j+1$、$q = i$，则 $p - q = j + 1 - i \ge 2$。循环走到元素下标 $j$ 时 $s = P[p]$，余数 $r = P[p] \bmod k$；由引理 3，此时表中已记录 $f(r)$，且 $f(r) \le q$。于是判定量 $p - f(r) \ge p - q \ge 2$，算法返回 `true`。
- ($\Rightarrow$) 若算法在元素下标 $i$ 处返回 `true`，则存在已记录的 $f = \text{first}[r]$ 使 $i - f \ge 2$，且 $P[i+1] \equiv P[f+1] \pmod{k}$。取子数组 $\text{nums}[f+1..i]$，其长度 $= i - f \ge 2$，由引理 1 其和是 $k$ 的倍数，故它是好子数组。
- 循环正常结束说明对每个 $i$ 都没有出现「同余且下标差 ≥ 2」的前缀对；由引理 2，任何同余对都会以最小下标被捕捉，故此时不存在好子数组，返回 `false` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素做一次加法、一次取模、一次哈希表查询，至多一次插入；哈希表操作均摊 $O(1)$，总计线性。
- **空间**：$O(\min(n+1, k))$。表中每个不同余数只占一个条目，最多 $n+1$ 个；返回值与中间变量为常数。C++ 的 `unordered_map` 另有常数级桶开销。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    bool checkSubarraySum(vector<int>& nums, int k) {
        unordered_map<int, int> first;
        first.reserve(nums.size() * 2 + 1);
        first[0] = -1;                 // 空前缀：余数 0，位置 -1
        long long s = 0;               // 总和可达 2^31-1，用 64 位防溢出
        for (int i = 0; i < (int)nums.size(); ++i) {
            s += nums[i];
            int r = (int)(s % k);
            auto it = first.find(r);
            if (it == first.end()) {
                first[r] = i;          // 只记录最早出现的下标，绝不覆盖
            } else if (i - it->second >= 2) {
                return true;           // 同余且长度达标
            }
            // 差为 1 时长度不足 2，继续扫描
        }
        return false;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def checkSubarraySum(self, nums: List[int], k: int) -> bool:
        # first[r] = 余数 r 首次出现时对应的元素下标，空前缀记为 -1
        first = {0: -1}
        s = 0
        for i, x in enumerate(nums):
            s += x
            r = s % k
            if r in first:
                if i - first[r] >= 2:
                    return True        # 同余且长度达标
                # 差为 1：长度不足 2，继续扫描
            else:
                first[r] = i           # 只写首次，保证配对长度最大
        return False
```

## 8. 边界情况与易错点

1. **$n = 1$**：任何子数组长度都不足 2，答案必为 `false`；代码靠 `i - (-1) = 1 < 2` 自然返回 `false`，无需特判。
2. **`nums = [0]`、$k \ge 1$**：$0$ 是 $k$ 的倍数，但长度只有 1，仍应返回 `false`——这正是「先判长度、再判整除」的原因。
3. **命中但差为 1**：示例 2 的 $i = 2$ 处 $31 \equiv 1$、`first[1] = 1`，长度只有 1；若此时 `return false` 就会得到错误答案。必须继续扫描，直到 $i = 4$ 命中 `first[0] = -1`。
4. **覆盖首次下标**：把命中时也更新 `first[r] = i` 会让后续可用的左端点右移，长度变小，出现漏判。
5. **长度公式写错**：`i - first[r]` 才是长度（两个元素下标之差）；写 `+ 1` 会把单元素子数组误判为长度 2。
6. **整型溢出**：总和上界 $2^{31}-1$ 已贴 `int` 上界，若数据放大到 $10^{14}$，`int` 直接溢出为 UB；统一用 `long long`。
7. **用数组代替哈希表**：$k$ 可达 $2^{31}-1$，开 `vector<int>(k, -1)` 会 MLE；必须用哈希表（或先离散化余数）。
8. **负数余数**：本题 $\text{nums}[i] \ge 0$ 不触发；若允许负数，C++ 的 `s % k` 可能为负，需 `((s % k) + k) % k` 规范化后再查表。
