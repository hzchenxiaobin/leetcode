# LeetCode 向字符串添加空格 题解

## 1. 题目概述

- **标题 / 题号**：向字符串添加空格（#2109，medium）
- **链接**：https://leetcode.cn/problems/adding-spaces-to-a-string/
- **来源**：LeetCode 第 272 场周赛 Q2
- **难度**：中等
- **标签**：数组、双指针、字符串、模拟

**题意**：给定下标从 0 开始的字符串 `s` 与下标从 0 开始的整数数组 `spaces`。`spaces` 描述原字符串中需要添加空格的下标——每个空格都插入到对应下标的字符**之前**。返回添加空格后的字符串。

**约束**：

- $1 \leq \text{s.length} \leq 3 \times 10^5$
- `s` 仅由大小写英文字母组成
- $1 \leq \text{spaces.length} \leq 3 \times 10^5$
- $0 \leq \text{spaces}[i] \leq \text{s.length} - 1$
- `spaces` 中的所有值**严格递增**

## 2. 示例

**示例 1**

```text
输入：s = "LeetcodeHelpsMeLearn", spaces = [8,13,15]
输出："Leetcode Helps Me Learn"
解释：下标 8、13、15 对应字符 'H'、'M'、'L'，在这三个字符之前各插入一个空格。
```

**示例 2**

```text
输入：s = "icodeinpython", spaces = [1,5,7,9]
输出："i code in py thon"
解释：在下标 1、5、7、9 的字符前分别插入空格。
```

**示例 3**

```text
输入：s = "spacing", spaces = [0,1,2,3,4,5,6]
输出：" s p a c i n g"
解释：字符串的第一个字符前也可以添加空格。
```

## 3. 解题思路

### 3.1 暴力思路：逐个 insert，平方级超时

最直白的做法是遍历 `spaces`，对每个下标 `pos` 调用字符串的 `insert(pos, " ")` 把空格插进 `s`。但字符串插入是 $O(n)$ 的——插入点之后的每个字符都要整体后移一位。`spaces` 有 $m$ 个位置，最坏 $m \approx n$，总代价 $O(n \cdot m) = O(n^2)$，在 $n = m = 3 \times 10^5$ 时达到 $9 \times 10^{10}$ 次字符搬运，必然超时。

更糟的是，每次插入后**原下标语义即失效**：插完一个空格，后面所有 `spaces` 值都要 $+1$ 修正，稍不注意就 WA。即使换成 `list` 反复 `insert`，搬移代价也仍是平方级。

> ⚠️ **陷阱**：本题 $n, m$ 同阶且都到 $3 \times 10^5$，任何「在原串上反复插入」的做法都退化到平方级。必须**从左到右一次性构造结果**，让每个字符只被写一次。

### 3.2 核心观察：两个有序序列的一次归并

![核心观察：字符流与空格位的归并](images/wc272_q2_merge_concept.svg)

关键在于题面最后一条约束：`spaces` **严格递增**。它与字符下标 $0, 1, 2, \dots, n-1$ 同为升序序列，因此本题本质是**两个有序序列的归并**：

- **序列 A（字符流）**：$s[0], s[1], \dots, s[n-1]$，由指针 $i$ 从左到右扫描，每步必输出一个字符；
- **序列 B（空格位）**：$\text{spaces}[0] < \text{spaces}[1] < \dots < \text{spaces}[m-1]$，由指针 $j$ 从左到右扫描，每步至多输出一个空格。

归并规则：枚举 $i$，在写字符 $s[i]$ **之前**先「对表」——若 $j < m$ 且 $i = \text{spaces}[j]$，说明这个字符前面要加空格，于是先写一个空格、$j$ 自增，再写 $s[i]$；否则直接写 $s[i]$。

> 💡 **为什么 $j$ 永不回退？** `spaces` 严格递增而 $i$ 单调递增：一旦 $i$ 越过 $\text{spaces}[j]$（越过前必然恰好相等过一次），后续的 $i$ 只会更大，$\text{spaces}[j]$ 永不再被匹配。因此命中后 $j$ 自增一次即可，$j$ 至多走 $m$ 步——这正是**归并两个有序序列时输出指针单调前进**的经典性质，整个构造是严格线性的 $O(n + m)$。

### 3.3 算法流程

![算法流程：单次扫描，先判空格再写字符](images/wc272_q2_merge_flow.svg)

1. 预分配结果缓冲区 `res`，容量 $n + m$（结果长度是确定的）；
2. 双指针 $i = 0$，$j = 0$，外层循环 $i$ 从 $0$ 到 $n-1$；
3. 每轮先判断 $j < m$ 且 $i = \text{spaces}[j]$：命中则先向 `res` 写入 `' '`，$j$ 自增；
4. 再写入 $s[i]$，$i$ 自增，回到第 3 步；
5. $i$ 走到 $n$ 时循环结束（此时 $j$ 必然也走满 $m$），返回 `res`。

### 3.4 示例演算

![示例演算：三个命中位置与最终输出](images/wc272_q2_walkthrough.svg)

以示例 1 为例：`s = "LeetcodeHelpsMeLearn"`，`spaces = [8, 13, 15]`。指针 $i$ 从 0 走到 19，每走到 $8, 13, 15$ 时先写空格再写字符：

| 步骤 | $i$ 区间 | $j$ | $\text{spaces}[j]$ | 命中? | 动作 | 累积输出 |
|------|---------|-----|--------------------|-------|------|---------|
| ① | 0…7 | 0 | 8 | ✗ | 写 $s[0..7]$ | `Leetcode` |
| ② | 8 | 0→1 | 8 | ✓ | 写空格 + `H` | `Leetcode H` |
| ③ | 9…12 | 1 | 13 | ✗ | 写 $s[9..12]$ | `Leetcode Helps` |
| ④ | 13 | 1→2 | 13 | ✓ | 写空格 + `M` | `Leetcode Helps M` |
| ⑤ | 14 | 2 | 15 | ✗ | 写 `e` | `Leetcode Helps Me` |
| ⑥ | 15 | 2→3 | 15 | ✓ | 写空格 + `L` | `Leetcode Helps Me L` |
| ⑦ | 16…19 | 3 | —（已用尽） | ✗ | 写 $s[16..19]$ | `Leetcode Helps Me Learn` |

$i$ 走满 $n = 20$ 步、$j$ 恰好走满 $m = 3$ 步，输出长度恰为 $n + m = 23$，最终结果 `"Leetcode Helps Me Learn"`。每个字符与每个空格都只被写一次——没有任何后移搬移。

## 4. 算法细节

1. **预分配缓冲区**：结果长度确定（$n + m$），C++ 用 `res.reserve(n + m)` 一次分配避免 `push_back` 反复扩容；Python 用列表 `res` 收集、最后 `''.join(res)`，切忌对 `str` 反复 `+=`（每次拼接都构造新串，虽在部分 CPython 版本有原地优化但不可依赖）。
2. **判断条件的短路顺序**：必须写 `j < m && i == spaces[j]`，先判越界后取值——$j$ 走满后 `spaces[j]` 越界，靠 `&&` 的短路求值保护；颠倒顺序直接 RE。
3. **「先空格后字符」的顺序不可颠倒**：空格插在 $s[i]$ **之前**，所以命中时必须先写 `' '` 再写 $s[i]$；顺序反了空格就落到字符后面。
4. **$j$ 无需任何回退或二分**：严格递增保证每个 $\text{spaces}[j]$ 至多被命中一次、且命中次序与 $i$ 同步推进，这是单指针就够的原因（对比：若 `spaces` 无序需先排序，或改哈希集合判命中）。
5. **变体一（预填跳格）**：把 `res` 初始化为 $n + m$ 个空格，写指针 $w$ 在命中时自增跳过一格（那格天然是空格），再写入字符——省去显式写空格，纯赋值常数最小（见 §7 变体代码）。
6. **变体二（分段拼接，Python 竞速）**：把 `spaces` 视为切割点，`s` 被切成 $m + 1$ 段，用 `' '.join(...)` 拼接——空格恰好落在段与段之间（严格递增保证段非退化），一次 `join` 完成（见 §7 变体代码）。

## 5. 正确性证明

**引理 1**（分割不变式）：约定 $\text{spaces}[m] = +\infty$。第 $i$ 轮循环开始时（即准备输出 $s[i]$ 之前），$j$ 恰好分割序列为已消费与未消费两部分：

$$\text{spaces}[0..j-1] < i \leq \text{spaces}[j..m-1]$$

**证明**：对 $i$ 归纳。$i = 0$ 时 $j = 0$：左半为空；右半由约束 $0 \leq \text{spaces}[0]$ 知 $\text{spaces}[0] \geq 0 = i$ 成立。设第 $i$ 轮开始时命题成立，分两种情形：

- 若 $j < m$ 且 $i = \text{spaces}[j]$：算法写空格并令 $j' = j + 1$。新左半 $\text{spaces}[0..j]$ 中，$\text{spaces}[j] = i < i + 1$，其余原本 $< i$；新右半由**严格递增**知 $\text{spaces}[j+1] > \text{spaces}[j] = i$，即 $\geq i + 1$（整数）。命题在第 $i+1$ 轮保持。
- 若 $j = m$ 或 $\text{spaces}[j] > i$：$j$ 不变。此时 $\text{spaces}$ 中不存在等于 $i$ 的元素（左半全部 $< i$，右半最小的 $\text{spaces}[j] > i$），左半仍 $< i < i + 1$，右半仍 $\geq i + 1$。命题保持。∎

**引理 2**（命中刻画）：在第 $i$ 轮，条件「$j < m$ 且 $i = \text{spaces}[j]$」成立 $\iff$ $i \in \text{spaces}$。

**证明**：由引理 1，$\text{spaces}$ 中小于 $i$ 的元素恰为 $\text{spaces}[0..j-1]$（已消费），不小于 $i$ 的元素从 $\text{spaces}[j]$ 开始。若 $i \in \text{spaces}$，则 $i$ 只能是未消费部分的最小者 $\text{spaces}[j]$，且此时必有 $j < m$；反之若 $i = \text{spaces}[j]$ 且 $j < m$，显然 $i \in \text{spaces}$。∎

**定理**：算法返回的字符串恰为：在 $s$ 的每个下标 $p \in \text{spaces}$ 的字符之前各插入一个空格，其余字符保持原序不变。

**证明**：输出由循环逐轮追加而成。第 $i$ 轮先由引理 2 判定 $i$ 是否属于 $\text{spaces}$：属于则先追加恰一个空格（同时消费 $\text{spaces}[j]$，由严格递增知同一 $p$ 不会被二次命中，也即每个命中下标恰得一个空格）；不属于则不追加空格。随后追加 $s[i]$。故 $s$ 的字符按 $i$ 升序、两两之间按命中情况插入空格逐一到齐——重写后的串在去掉这 $m$ 个空格后恰为 $s$，且第 $k$ 个空格恰好位于原下标 $\text{spaces}[k]$ 的字符之前（$\text{spaces}[k]$ 命中发生在第 $\text{spaces}[k]$ 轮、写 $s[\text{spaces}[k]]$ 之前，而后续空格都在更晚的轮次写入）。循环共 $n$ 轮，输出长度 $n + m$，与要求一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。$i$ 恰好走 $n$ 步、每步写一个字符；$j$ 恰好走 $m$ 步、每步写一个空格；每轮的判断是 $O(1)$。相加即输出长度，每个元素只被写一次，无任何搬移。
- **空间复杂度**：$O(n + m)$，即结果字符串本身（长度恰为 $n + m$）；不计输出则仅 $O(1)$ 个指针变量。分段拼接变体额外产生 $m + 1$ 个切片对象，总量仍 $O(n + m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string addSpaces(string s, vector<int>& spaces) {
        int n = s.size(), m = spaces.size();
        string res;
        res.reserve(n + m);              // 结果长度确定，一次分配
        for (int i = 0, j = 0; i < n; i++) {
            if (j < m && i == spaces[j]) { // 短路：先判越界再取值
                res.push_back(' ');
                j++;
            }
            res.push_back(s[i]);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def addSpaces(self, s: str, spaces: List[int]) -> str:
        res = []
        j, m = 0, len(spaces)
        for i, ch in enumerate(s):
            if j < m and i == spaces[j]:
                res.append(' ')
                j += 1
            res.append(ch)
        return ''.join(res)
```

### 变体：预填空格 + 写指针跳格（C++）

```cpp
class Solution {
public:
    string addSpaces(string s, vector<int>& spaces) {
        int n = s.size(), m = spaces.size();
        string res(n + m, ' ');          // 全部预填为空格
        int w = 0;                        // 写指针
        for (int i = 0, j = 0; i < n; i++) {
            if (j < m && i == spaces[j]) {
                w++;                      // 跳过一格，保留预填的空格
                j++;
            }
            res[w++] = s[i];
        }
        return res;
    }
};
```

### 变体：按切割点分段拼接（Python 竞速）

```python
class Solution:
    def addSpaces(self, s: str, spaces: List[int]) -> str:
        parts = []
        prev = 0
        for pos in spaces:
            parts.append(s[prev:pos])
            prev = pos
        parts.append(s[prev:])
        return ' '.join(parts)
```

> 💡 **工程细节**：主解是通用的双指针归并模板；两个变体分别优化 C++（定长分配 + 纯赋值，常数最小）与 Python（`join` 一次成型，实测最快）。三者复杂度相同，比赛任选其一皆可。

## 8. 边界情况与易错点

1. **逐个 `insert` 是头号陷阱**：$O(n \cdot m)$ 在 $3 \times 10^5$ 规模下必然 TLE，且插入后剩余 `spaces` 下标全部失效需 $+1$ 修正——正确性与效率双杀。
2. **短路顺序**：`j < m && i == spaces[j]` 中越界判断必须在取值之前，写成 `spaces[j] == i && j < m` 直接数组越界 RE。
3. **`spaces[0] == 0`（首字符前插空格）合法**：示例 3 即此情形，$i = 0$ 命中 $\text{spaces}[0] = 0$ 时先写空格再写 $s[0]$，与通用逻辑一致，**无需特判**。
4. **`spaces` 最大可到 $n - 1$**（末字符前插空格）：命中后写空格 + 末字符，循环自然结束，末尾不需要任何收尾处理。
5. **空格必须写在字符之前**：命中时先 `append(' ')` 再 `append(s[i])`，顺序颠倒即 WA（空格落到命中字符之后）。
6. **Python 切忌对 `str` 反复 `+=`**：用列表收集 + `''.join`；分段拼接变体中 `' '.join` 的分隔符恰好就是空格，注意此时不能在段内再补空格。
7. **输出长度自检**：结果长度必为 $n + m$，可在对拍时作为快速断言。
8. **`spaces` 严格递增是线性解的前提**：本题白送了有序性；若题目变体允许无序，需先排序 $O(m \log m)$ 或用哈希集合 $O(n + m)$ 判命中，双指针归并不再直接适用。
