# LeetCode 下标覆盖处的最大总和 题解

## 1. 题目概述

- **标题 / 题号**：下标覆盖处的最大总和（#3952，medium）
- **链接**：https://leetcode.cn/problems/maximum-total-value-of-covered-indices/
- **来源**：LeetCode 第 184 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、字符串、动态规划

**题意**：长度为 $n$ 的整数数组 `nums` 与长度为 $n$ 的二进制串 $s$（$s[i] = '1'$ 表示下标 $i$ 初始有一个**标记**）。

可执行任意次操作：选一个当前在 $i > 0$ 且**尚未被移动过**的标记，把它从 $i$ 移到 $i-1$。操作结束后，含标记的下标称**被覆盖**。求被覆盖下标处 `nums` 之和的**最大**值。

注意：每个标记**至多左移一格**，且移动后仍占一格（不会叠加到同一格语义上——「被覆盖」是个布尔判定，两个标记落在同一格不会加倍收益，故最优解不会让它们重叠）。

**约束**：

- $1 \le n \le 10^5$
- $1 \le nums[i] \le 10^5$
- $s[i] \in \{'0', '1'\}$

## 2. 示例

**示例 1**

```text
输入：nums = [9,2,6,1], s = "0101"
输出：15
解释：下标 1、3 各有标记。3 → 2、1 → 0，被覆盖下标 {0,2}，和 9 + 6 = 15。
```

**示例 2**

```text
输入：nums = [5,1,4], s = "001"
输出：4
解释：只有下标 2 有标记。留着不动，被覆盖 {2}，和 4（若左移到 1 只能得 1）。
```

**示例 3**

```text
输入：nums = [9,3,5], s = "011"
输出：14
解释：下标 1、2 有标记。把 1 左移到 0，被覆盖 {0,2}，和 9 + 5 = 14。
```

## 3. 解题思路

### 3.1 暴力思路

每个标记只有「不动」或「左移一格」两种选择，标记有 $c$ 个就是 $2^c$ 种组合（还要排除「两个标记抢同一格」的非法组合），$c$ 可达 $10^5$，指数爆炸。即便写成 DP，把「每个位置是否被占」当状态也是 $O(n \cdot 2^?) $ 量级。必须利用**标记的邻接结构**。

### 3.2 核心观察：连续的 1 块 + 它前面那格 = 一个独立窗口

![每个连续的 1 块 + 它前面那格 0 = 一个窗口](images/bw184_q3_blocks.svg)

把 $s$ 按**极大连续 1 块**切分。设某块为 $[L, R]$（长度 $\ell = R-L+1$），考虑「块内标记 + 块前那一格 $L-1$（若 $L > 0$，且该格必为 0）」：

- 块内 $\ell$ 个标记可以停在自己原位，也可以左移一格；
- 它们的落点只能落在 $[L-1, R]$ 这个共 $\ell+1$ 格的区间里（块内标记 $i$ 的落点是 $i$ 或 $i-1$）；
- 由于「被覆盖」是布尔判定，落点必须互不相同，故 $\ell$ 个标记占用 $\ell$ 个不同格，**恰好丢掉 $[L-1, R]$ 中的一个格**。

**丢哪一个？** 关键结论：**任意一个格子都可以被丢**。构造：若丢掉 $L-1$，所有标记不动；若丢掉 $t \in [L, R]$，则令 $L \to L-1$、$L+1 \to L$、…、$t \to t-1$（$t$ 之前的标记依次左移一格），$t+1$ 及之后的标记不动。检查落点：$\{L-1, L, \dots, t-1\} \cup \{t+1, \dots, R\}$，正好是 $[L-1,R] \setminus \{t\}$ ✓。

于是每块的贡献是

$$\text{贡献} = \sum_{i=L-1}^{R} nums[i] - \min_{L-1 \le i \le R} nums[i] = \left(\text{窗口和}\right) - \left(\text{窗口最小值}\right)$$

**特殊情况 $L = 0$**：块从下标 0 开始，没有「前面那格」，标记的落点恰为 $[0, R]$ 共 $\ell$ 格，必须全占，贡献 $= \sum_{i=0}^{R} nums[i]$，不能丢任何格。

**不同块是否互相影响？** 块与块之间至少隔一个 0。设前一块是 $[L_1, R_1]$，后一块是 $[L_2, R_2]$ 且 $R_1 + 1 < L_2$，则前一块的窗口是 $[L_1-1, R_1]$、后一块是 $[L_2-1, R_2]$，而 $L_2 - 1 \ge R_1 + 1 > R_1$，两窗口不相交；若恰好 $L_2 = R_1 + 2$（只隔一个 0），则后块窗口起点 $L_2 - 1 = R_1+1$，与前块窗口的终点 $R_1$ 相邻但不重叠。所以**各块独立**，答案就是各块贡献之和。

### 3.3 算法流程

```text
ans = 0，i = 0
while i < n:
    若 s[i] == '0'：i++；跳过
    j = i；while j+1 < n 且 s[j+1] == '1'：j++        // 找到块 [i, j]
    若 i == 0：ans += sum(nums[0..j])
    否则：
        sum = Σ nums[i-1..j]，mn = min(nums[i-1..j])
        ans += sum - mn
    i = j + 1
返回 ans
```

总扫描是线性的：每个下标最多被常数次访问。

| 用例 | 块 | 窗口 | 计算 | 结果 |

| `[9,2,6,1]`，`"0101"` | `{1}`、`{3}` | `[0,1]`、`[2,3]` | $(9+2)-2 = 9$；$(6+1)-1 = 6$ | 15 |
| `[5,1,4]`，`"001"` | `{2}` | `[1,2]` | $(1+4)-1 = 4$ | 4 |

## 4. 算法细节

1. **窗口求和与最小值**：对每个块扫一遍 $[i-1, j]$，块总长之和为 $O(n + \text{块数})$，总复杂度 $O(n)$。
2. **`i == 0` 的特判**：块从下标 0 开始时窗口就是 $[0, j]$（$\ell$ 个格、$\ell$ 个标记），必须全占，不能减最小值。
3. **块划分**：靠「下一个字符是否为 1」扩展右端，遇到 0 即断块，天然得到极大块。
4. **落点合法性**：相邻两个标记不会抢同一格——因为我们的构造是「块前缀整体左移一格」，落点严格递增。
5. **答案范围**：$n \cdot nums[i] \le 10^{10}$，`int` 溢出，必须 64 位。
6. **不需要真的移动**：只需按公式累加，避免模拟。

## 5. 正确性证明

**引理 1（窗口划分）**：设 $s$ 的一个极大连续 1 块为 $[L, R]$，则块内标记的落点集合是 $[L-1, R] \cap [0, n-1]$ 的 $\ell$ 元子集（$\ell = R-L+1$），且反向地，该区间内任意 $\ell$ 元子集都可达。

**证明**：标记 $i$ 的落点只能是 $i$ 或 $i-1$，故落点必在 $\bigcup_{i=L}^{R}\{i-1, i\} = [L-1, R]$ 内（$L = 0$ 时为 $[0,R]$）；落点互不相同（被覆盖是布尔量，两个标记同格等价于浪费一个位置且不增加收益），故恰为 $\ell$ 元子集。「任意 $\ell$ 元子集可达」：只需说明任意「丢掉一个格 $t$」可达（丢更多格只会更差，因为 $nums[i] \ge 1 > 0$）：$t = L-1$ 时全员不动；$t \in [L,R]$ 时令 $[L, t]$ 内标记整体左移一格、其余不动，落点集为 $[L-1, t-1] \cup [t+1, R]$，恰为区间去掉 $t$，且每格仅一个标记。∎

**引理 2（每块最优值）**：块 $[L,R]$ 对答案的最大贡献为：$L = 0$ 时是 $\sum_{0}^{R} nums[i]$；$L > 0$ 时是 $\sum_{L-1}^{R} nums[i] - \min_{L-1 \le i \le R} nums[i]$。

**证明**：由引理 1，$L > 0$ 时落点集是 $[L-1,R]$ 去掉任意一个格，故最大化「保留之和」等价于最小化「被去掉的那个值」，即减窗口最小值；$L = 0$ 时落点集只能是 $[0,R]$ 全体（$\ell$ 个格、$\ell$ 个标记），无选择余地。∎

**引理 3（块间独立）**：不同极大块的窗口互不相交，故各块贡献可加。

**证明**：设相邻两块 $[L_1,R_1]$、$[L_2,R_2]$，因块是极大的且 $L_2 > R_1$，必有 $L_2 \ge R_1 + 2$（否则两块的 1 会连成一块）。块 1 的窗口右端为 $R_1$，块 2 的窗口左端为 $L_2 - 1 \ge R_1 + 1$，故两窗口不重叠。∎

**定理**：算法输出等于被覆盖下标和的最大值。

**证明**：任一合法操作方案的总和被分解为各块贡献之和（块内标记不会落到别的块窗口外，引理 1、3），由引理 2 每块贡献不超过该块最优值，故总和不超过算法结果；另一方面，对每块独立取引理 2 的构造，可将各块最优值同时达成（块间窗口不交，互不干扰），故算法结果可达。两者相等。∎

## 6. 复杂度分析

- **时间**：$O(n)$。块划分一遍扫描；每块的窗口求和/求最小是块长 $+1$ 次操作，所有块加起来不超过 $2n$。
- **空间**：$O(1)$ 额外空间（只用若干累加器与下标变量）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxTotal(vector<int>& nums, string s) {
        int n = nums.size();
        long long ans = 0;
        int i = 0;
        while (i < n) {
            if (s[i] == '0') {
                i++;
                continue;
            }
            int j = i;
            while (j + 1 < n && s[j + 1] == '1') j++;
            int from = (i == 0) ? 0 : i - 1;
            long long sum = 0, mn = LLONG_MAX;
            for (int t = from; t <= j; t++) {
                sum += nums[t];
                mn = min(mn, (long long)nums[t]);
            }
            if (i == 0) ans += sum;
            else ans += sum - mn;
            i = j + 1;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxTotal(self, nums: list[int], s: str) -> int:
        n = len(nums)
        ans = 0
        i = 0
        while i < n:
            if s[i] == "0":
                i += 1
                continue
            j = i
            while j + 1 < n and s[j + 1] == "1":
                j += 1
            if i == 0:
                ans += sum(nums[i:j + 1])
            else:
                window = nums[i - 1:j + 1]
                ans += sum(window) - min(window)
            i = j + 1
        return ans
```

## 8. 边界情况与易错点

1. **整串全是 1**：只有一个块 $[0, n-1]$，块从 0 开始，贡献 = 全数组和，不能减最小值（没有多余槽位）。
2. **块从下标 0 开始但不满整串**：如 `s = "110"`，块 $[0,1]$，窗口 $[0,1]$ 共 2 格 2 标记，必须全占——`i == 0` 的特判不可省。
3. **块前面那格是 0**：这是「多出来的槽位」的来源。若块前没有 0（$L = 0$），就没有多余槽位。
4. **`nums[i]` 全为正**：因此「丢一个最小格」一定优于「丢更多格」，无需考虑丢两个。
5. **落点重叠不算收益**：两个标记落在同一格只算一次覆盖，本题最优解一定避免重叠；若误以为可以叠加，会构造出非法方案。
6. **答案溢出**：$10^5 \times 10^5 = 10^{10}$，`int` 溢出，用 `long long`。
7. **不要逐块排序**：求最小值一次扫描即可，排序是多余的 $O(\ell \log \ell)$。
