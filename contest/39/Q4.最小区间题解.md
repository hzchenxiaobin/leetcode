# LeetCode 最小区间 题解

## 1. 题目概述

- **标题 / 题号**：最小区间（#632，hard）
- **链接**：https://leetcode.cn/problems/smallest-range-covering-elements-from-k-lists/
- **来源**：LeetCode 第 39 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、哈希表、排序、滑动窗口、堆（优先队列）

**题意**：给定 $k$ 个**非递减排列**的整数列表 `nums[0..k-1]`，找一个区间 $[a,b]$，使**每个列表至少有一个数**落在 $[a,b]$ 内。若存在多个，按「长度 $b-a$ 更小者优先；长度相同则左端点 $a$ 更小者优先」的规则返回最小者。

**约束**：

- $k = \text{nums.length}$，$1 \le k \le 3500$
- $1 \le \text{nums}[i]\text{.length} \le 50$，故元素总数 $N \le 175000$
- $-10^5 \le \text{nums}[i][j] \le 10^5$
- 每个 `nums[i]` 按非递减顺序排列

## 2. 示例

**示例 1**

```text
输入：nums = [[4,10,15,24,26], [0,9,12,20], [5,18,22,30]]
输出：[20,24]
解释：列表 1 取 24，列表 2 取 20，列表 3 取 22，三者都落在 [20,24] 内；
      长度小于 4 的区间都无法同时覆盖三个列表，故答案为 [20,24]。
```

**示例 2**

```text
输入：nums = [[1,2,3], [1,2,3], [1,2,3]]
输出：[1,1]
解释：三个列表都含 1，区间 [1,1] 长度为 0（最小可能值），左端点也是最小的。
```

**示例 3（补充：退化情况）**

```text
输入：nums = [[1,5,9], [2,6,10], [3,7,11]]
输出：[1,3]
解释：[1,3] 长度 2；长度 1 的候选只有 [1,2]、[5,6] 等，都漏掉某个列表。
```

## 3. 解题思路

### 3.1 暴力思路

答案区间的两个端点只需从「出现过的数值」里取（见 §5 引理 1），于是可以枚举所有值对 $[a,b]$，逐列表检查是否有元素落入其中：候选 $O(N^2)$ 个、每次检查 $O(N)$，总 $O(N^3)$。即便把「检查」优化成对每条列表二分，仍有 $O(N^2 \log k)$；$N$ 最大 $175000$，$N^2 \approx 3\times10^{10}$，完全不可行。

### 3.2 核心观察：归并成一条有序数组 + 滑动窗口

![归并成一条有序带颜色的数组](images/wc39_q4_merge_colors.svg)

把 $k$ 个列表的所有元素摊平成 $(值, 所属列表下标)$，按值排序，得到一条**有序的、每个元素带一种「颜色」**的数组 $A$。于是一个区间 $[a,b]$ 覆盖所有列表，等价于 $A$ 中存在一个**值域为 $[a,b]$ 的窗口，其中 $k$ 种颜色全部出现**。

问题因此变成经典的**最小覆盖窗口**：

> 在有序数组 $A$ 上找一段连续子数组 $A[l..r]$，使其中出现全部 $k$ 种颜色，并最小化「长度 $A[r]-A[l]$，长度相同则 $A[l]$ 更小」。

窗口只需要**右端扩张 + 左端收缩**两个动作。对固定的右端点 $r$，记 $L(r)$ 为「以 $r$ 结尾的最短覆盖窗口」的左端（即最大的可行左端点）：左端点越靠右，区间越短，所以一旦窗口有效就一路右移左端直到失效。又因为 $[L(r), r]$ 有效 $\Rightarrow$ $[L(r), r+1]$ 有效 $\Rightarrow L(r+1) \ge L(r)$，$L$ 关于 $r$ **单调不减**，左指针无需回退——这正是双指针可用的结构，两个指针总移动次数都是 $O(N)$。

### 3.3 算法流程 / 窗口维护

![双指针 + 颜色计数流程](images/wc39_q4_two_pointer_flow.svg)

1. 摊平并排序得到 $A$，长度 $n$；`cnt[j]` 记录窗口内来自列表 $j$ 的元素个数，`have` 记录 `cnt > 0` 的列表种数。
2. `best` 初始化为 $[A[0], A[n-1]]$——全局最值区间必然覆盖所有列表，一定合法。
3. 右指针 `right` 从 $0$ 扫到 $n-1$：加入 $A[\text{right}]$，若 `cnt` 由 $0$ 变 $1$ 则 `have++`。
4. 当 `have == k` 时循环执行：
   - 用 $[A[\text{left}], A[\text{right}]]$ 更新 `best`（先比长度，再比左端点）；
   - 把 $A[\text{left}]$ 移出窗口：`cnt--`，若归零则 `have--`，然后 `left++`。
5. 循环退出（`have < k`）后继续右移；`right` 越界时返回 `best`。

第 4 步的 `while` 一旦进入，就会把左端一路推到失效为止：退出时 `left` 刚好越过最短窗口的左端一位，因此**这一轮最后记录的那个候选**就是「右端点固定为 `right` 时的最短覆盖窗口」。

### 3.4 示例演算

![示例 1 演算表](images/wc39_q4_walkthrough.svg)

对示例 1，归并后 $A = [0,4,5,9,10,12,15,18,20,22,24,26,30]$，颜色（列表下标）依次为 $1,0,2,1,0,1,0,2,1,2,0,0,2$：

| right | 右端点 $b$ | 收缩得到的候选（长度） | best |
|-------|-----------|------------------------|------|
| 2 | 5 | $[0,5]$ (5) | $[0,5]$ |
| 3 | 9 | $[4,9]$ (5) | 不变（等长，$4>0$） |
| 4 | 10 | $[5,10]$ (5) | 不变 |
| 7 | 18 | $[9,18]\to[10,18]\to[12,18]$ (9/8/6) | 不变 |
| 8 | 20 | $[15,20]$ (5) | 不变 |
| 10 | 24 | $[18,24]\to[20,24]$ (6/4) | $[20,24]$ |

`right = 5, 6, 9, 11, 12` 时窗口覆盖不足 $k=3$，不产生候选。最终答案 $[20,24]$：列表 1 取 24、列表 2 取 20、列表 3 取 22。

## 4. 算法细节

1. **排序键**：排序 `(值, 列表下标)` 即可。相同值来自不同列表时谁在前都可以：引理 2 说明覆盖关系只看「值落在区间内」，而窗口可以扩张到整个同值块，故同值内部次序不影响最优值。
2. **颜色计数而非集合**：`cnt[j]` 必须是**计数**。若只记「列表 $j$ 是否出现过」，移动左端点时无法区分「该列表还有别的元素留在窗口里」与「已经被完全移出」，整条列表的覆盖状态就会算错。加减两侧必须对称：入窗时 `0 → 1` 才 `have++`，出窗时归零才 `have--`。
3. **比较规则严格按题意**：先比 $b-a$，等长时比 $a$。实现成
   `if (b-a < best[1]-best[0] || (b-a == best[1]-best[0] && a < best[0]))`
   后半句负责等长时按题意取左端点更小者（候选按右端点递增枚举，等长候选的左端点也随之递增，只写严格小于「恰好」也能过，但显式写出不依赖这种隐式顺序）。
4. **`best` 的初始化**：$[A[0], A[n-1]]$ 往返于「最小值来自某列表、最大值来自某列表」，一定覆盖全部 $k$ 个列表，因此是合法上界；避免用 `INT_MAX` 做哨兵再特判「是否从未更新」。
5. **堆（贪心）等价写法**：维护每条列表的当前指针，用**小根堆**取 $k$ 个当前值中的最小值 $a$、同时维护最大值 $b$，用 $[a,b]$ 更新答案，然后把取到 $a$ 的那条列表的指针后移、把新值入堆。它与本解法一一对应：**堆顶就是窗口左端点，弹出堆顶并换入该列表的下一个元素，正好等于把左端右移一位**，而「$k$ 个当前值的最大值」就是窗口右端。复杂度 $O(N \log k)$，当 $k \ll N$ 时优于此处的 $O(N \log N)$。
6. **值域很小时可换桶**：元素值域仅 $2\times10^5$，可以开桶按值从小到大扫（同时记录每个值出现在哪些列表），把排序换成计数排序，做到 $O(N + V)$；本质仍是同一个滑窗。
7. **不需要去重**：`nums[i]` 内部若含重复值，重复元素只会让 `cnt` 变大，不影响正确性，也无需先 `unique`。

## 5. 正确性证明

**引理 1（端点可收缩到元素值上）**：若存在合法区间 $[a,b]$，则存在合法区间 $[a',b']$，满足 $a \le a' \le b' \le b$、长度 $b'-a' \le b-a$，且 $a'$、$b'$ 都等于某个元素值。

**证明**：在 $[a,b]$ 内为每条列表各取一个落点 $x_1,\dots,x_k$，令 $a' = \min_i x_i$、$b' = \max_i x_i$，则每个 $x_i \in [a',b']$，故 $[a',b']$ 合法；又 $a \le a' \le b' \le b$，长度不增，且两端点都是被取到的元素值。∎

> 由引理 1，最优解一定能在「端点为元素值」的区间里找到，它们正好对应归并数组 $A$ 的两个下标 $l \le r$。

**引理 2（窗口与值区间的对应）**：

(a) 若窗口 $A[l..r]$ 中 $k$ 种颜色全部出现，则值区间 $[A[l], A[r]]$ 覆盖全部 $k$ 个列表；
(b) 反之，若值区间 $[a,b]$ 覆盖全部列表，则把窗口取成「所有取值落在 $[a,b]$ 内的元素」所构成的连续段 $A[i_0..j_0]$（$i_0$ 是值 $a$ 所在块的第一个下标，$j_0$ 是值 $b$ 所在块的最后一个下标），该窗口含全部 $k$ 种颜色，且值域仍恰为 $[a,b]$。

**证明**：(a) 窗口内每个元素的值都在 $[A[l],A[r]]$ 内，故窗口中出现过的颜色所对应的列表都被覆盖。(b) 对每条列表取一个落点 $x_j \in [a,b]$，它的下标介于「值 $a$ 的第一个下标」与「值 $b$ 的最后一个下标」之间（$A$ 有序），故落在 $i_0$ 与 $j_0$ 之间，即该颜色出现在窗口中；而窗口两端取值分别是 $a$ 与 $b$，值域恰为 $[a,b]$。∎

> 引理 2 说明「覆盖 $k$ 个列表」与「窗口含 $k$ 种颜色」在**值域层面**完全等价；同一数值分散在多个列表时，取整块即可，这也是 $A$ 中同值元素可以任意排序的原因。

**引理 3（收缩的停止条件）**：固定右端点 $r$，记 $L(r)$ 为以 $r$ 结尾的最短有效窗口的左端。若进入 `while` 时 `left` $\le L(r)$，则本轮**最后一次**记录的候选恰为 $[A[L(r)], A[r]]$。

**证明**：窗口有效性对左端点单调——若 $[l,r]$ 有效，则窗口更大（左端更小）时仍含全部颜色，故可行左端点集合是前缀 $\{0,1,\dots,L(r)\}$。循环从 `left` 出发，每次先记录候选再把左端右移一位，直到窗口失效；失效当且仅当左端越过 $L(r)$，因此最后一条记录正是 $L(r)$。∎

**引理 4（最优区间不会被跳过）**：设 $[a^*,b^*]$ 是字典序最优的覆盖区间，$j_0$ 为值 $b^*$ 所在块的最后下标。则算法在右端点 $j_0$ 之前或当时，记录过一条长度 $\le b^*-a^*$、且等长时左端点为 $a^*$ 的候选。

**证明**：由引理 2(b)，窗口 $[i_0, j_0]$（值 $a^*$ 块首 到 值 $b^*$ 块尾）含全部 $k$ 种颜色，且 $A[i_0] = a^*$、$A[j_0] = b^*$。记 $L = L(j_0) \ge i_0$。考察右端点为 $j_0$ 的这一轮：

- 若进入时 `left` $\le L$：由引理 3 记录 $[A[L], A[j_0]]$，长度 $A[j_0]-A[L] \le A[j_0]-A[i_0] = b^*-a^*$，且由引理 2(a) 该值区间合法；若严格更短，与最优性矛盾，故等长，于是 $A[L] = A[i_0] = a^*$。
- 若进入时 `left` $> L$：`left` 只能逐一自增，必在某一轮（右端点 $r \le j_0$）恰等于 $L$ 并记录了 $[A[L], A[r]]$。若 $r < j_0$，其长度 $A[r]-A[L] < A[j_0]-A[L] \le b^*-a^*$，得到更短的合法区间，与最优性矛盾；故 $r = j_0$，但那样进入时 `left` 就等于 $L$，与本分支假设矛盾——所以该分支实际不可能发生。

两种情况下都得到所需的候选。∎

**定理**：算法返回的区间是字典序意义下（先长度、后左端点）最小者。

**证明**：返回值是某条被记录的候选，由引理 2(a) 一定合法。设最优覆盖区间为 $[a^*,b^*]$。由引理 1，端点可取为元素值，且左端可取成以 $b^*$ 结尾的最短窗口左端（否则右移左端会更短），故 $[a^*,b^*]$ 对应归并数组中的某两个下标。由引理 4，算法记录过一条长度 $\le b^*-a^*$、等长时左端点为 $a^*$ 的候选；而 `best` 始终取所有候选按（长度，左端点）字典序的最小者，因此 `best` 不劣于 $[a^*,b^*]$，它与最优解相等。∎

## 6. 复杂度分析

- **时间**：归并排序 $O(N \log N)$，其中 $N = \sum_i \lvert \text{nums}[i] \rvert \le 175000$；滑窗部分右指针走 $N$ 步、左指针总共也走不超过 $N$ 步，每步 $O(1)$，即 $O(N)$。总计 $O(N \log N)$，约 $1.75\times10^5 \times 18 \approx 3\times10^6$ 次比较，很宽松。改用小根堆则为 $O(N \log k)$。
- **空间**：$(值, 下标)$ 数组 $O(N)$；`cnt` 数组 $O(k)$；排序的栈空间 $O(\log N)$。合计 $O(N + k)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> smallestRange(vector<vector<int>>& nums) {
        // 1. 摊平成 (值, 所属列表下标) 并排序
        vector<pair<int, int>> elems;
        for (int i = 0; i < (int)nums.size(); ++i)
            for (int v : nums[i]) elems.push_back({v, i});
        sort(elems.begin(), elems.end());

        int k = nums.size();
        vector<int> cnt(k, 0);
        int have = 0, left = 0;
        vector<int> best = {elems.front().first, elems.back().first};  // 必然合法

        for (int right = 0; right < (int)elems.size(); ++right) {
            int j = elems[right].second;
            if (cnt[j]++ == 0) ++have;   // 该列表首次进入窗口

            // 2. 窗口覆盖全部 k 个列表：更新答案，再尽量收缩左端
            while (have == k) {
                int a = elems[left].first, b = elems[right].first;
                if (b - a < best[1] - best[0] ||
                    (b - a == best[1] - best[0] && a < best[0]))
                    best = {a, b};
                int i = elems[left].second;
                if (--cnt[i] == 0) --have;   // 该列表被完全移出窗口
                ++left;
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def smallestRange(self, nums: list[list[int]]) -> list[int]:
        # 摊平成 (值, 列表下标) 并排序
        elements = sorted((v, idx) for idx, arr in enumerate(nums) for v in arr)

        k = len(nums)
        cnt = [0] * k            # 窗口内每个列表贡献的元素个数
        have = 0                 # 窗口内已覆盖的列表种数
        best = [elements[0][0], elements[-1][0]]   # 全局最值区间一定合法
        left = 0

        for right in range(len(elements)):
            j = elements[right][1]
            if cnt[j] == 0:
                have += 1
            cnt[j] += 1

            # 窗口已覆盖 k 个列表：先更新答案，再收缩左端
            while have == k:
                a, b = elements[left][0], elements[right][0]
                if b - a < best[1] - best[0] or (b - a == best[1] - best[0] and a < best[0]):
                    best = [a, b]
                i = elements[left][1]
                cnt[i] -= 1
                if cnt[i] == 0:
                    have -= 1
                left += 1

        return best
```

## 8. 边界情况与易错点

1. **$k = 1$**：只有一个列表，任意单元素区间都合法，长度下界为 $0$。算法会把窗口一路收缩成 $(v,v)$ 并靠「等长比左端点」挑出最小值，返回 `[min, min]`，无需特判。
2. **多条列表含相同值**：如 `[[1,1],[1,1]]`，答案 `[1,1]`。`cnt` 必须按列表计数，同值不同列表各自记账；若用「值集合」判重会漏掉列表维度。
3. **同一列表内部有重复值**：如 `[[5,5,5]]`，窗口内 `cnt` 可达 3，但 `have` 只在 $0\to1$ 时加 1，收缩时也只在归零时减 1——两个方向的对称写法都要照顾到。
4. **`best` 的哨兵**：用 `INT_MAX` 当初始长度会引入「从未更新」的额外判断，且返回 `[-1,-1]` 之类的哨兵容易忘记替换；初始化成 $[A[0], A[n-1]]$ 天然合法，省掉全部分支。
5. **平局判定**：等长时要保证留下左端点更小的那个。由于候选按右端点递增产生，等长候选的左端点也随之递增，只写 `b-a < best[1]-best[0]` 恰好也能留下首个（左端点最小）的候选；但这种正确性依赖隐式的枚举顺序，显式写出 `b-a == ... && a < best[0]` 才与题意一字对应，重构（例如换成堆写法）时也不会踩坑。
6. **负数值域**：差值最大 $2\times10^5$，`int` 完全够用；但若改用桶排序，数组下标要整体偏移 $10^5$，否则负数会直接越界。
7. **`k = 1` 的分支**：此时第一轮就满足 `have == k`，窗口会被收缩到单个元素；靠「等长比左端点」最终收敛到最小元素，不需要在循环外单独特判。
8. **Python 的 `sorted`**：生成器一次性展开成 $N$ 个元组，内存 $O(N)$；不要写成嵌套循环里反复 `sort`，否则退化成 $k$ 次排序。

**延伸思考**：若把条件改成「每条列表**至少两个**数落在区间内」，只需把「达标」阈值从 $1$ 改成 $2$：`have` 统计 `cnt[j] >= 2` 的列表数，窗口有效条件仍是 `have == k`，滑窗结构与证明一字不改，复杂度不变。若要求「返回**所有**最小区间」，则在更新 `best` 时不要覆盖，而是收集所有长度等于当前最小长度、且左端点相同的候选（去重后输出）。若列表并非有序，先各自排序即可，总复杂度仍是 $O(N\log N)$；但若数据是**流式插入**（每次往某条列表加一个数并询问当前答案），静态滑窗失效，需要用 $k$ 个有序多重集 + 全局最小/最大值的可撤销结构（如两个堆或平衡树）把单次更新压到 $O(\log N)$。另一个工程视角是：本题元素值域只有 $2\times10^5$，把排序换成**计数排序/桶**可做到 $O(N+V)$，$V$ 为值域宽度。
