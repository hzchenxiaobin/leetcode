# LeetCode 平方数之和 题解

## 1. 题目概述

- **标题 / 题号**：平方数之和（#633，medium）
- **链接**：https://leetcode.cn/problems/sum-of-square-numbers/
- **来源**：LeetCode 第 39 场周赛 Q1
- **难度**：中等
- **标签**：数学, 双指针, 二分查找

**题意**：给定非负整数 $c$，判断是否存在两个整数 $a,b$ 满足

$$a^2 + b^2 = c$$

因为 $(\pm a)^2 = a^2$，只需考察 $0 \le a \le b$ 的非负组合；若存在这样的组合就返回 `true`，否则返回 `false`。

**约束**：

- $0 \le c \le 2^{31}-1$，即 $c$ 最大约 $2.1\times10^{9}$

> 💡 **关键限制**：$O(c)$ 的枚举会达到 $2^{31}$ 量级，必然超时；而 $\sqrt{c} \approx 46340$，说明 $O(\sqrt{c})$ 才是本题的目标复杂度。

## 2. 示例

**示例 1**

```text
输入：c = 5
输出：true
解释：1 * 1 + 2 * 2 = 5
```

**示例 2**

```text
输入：c = 3
输出：false
解释：a、b 只能取 0 或 1（1² + 1² = 2 已是最接近的），凑不出 3。
```

**示例 3**

```text
输入：c = 2147483647        # 即 2³¹ − 1，约束上界
输出：false
解释：该值是质数且 ≡ 3 (mod 4)，由费马平方和定理知不能表示为两平方数之和。
      双指针一路折返，走到 a = b = 32768 时 a² + b² = 2³¹ = c + 1（就差 1 没命中），
      于是 b 减 1，此时 a > b，循环收敛，返回 false。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举 $a \in [0, \sqrt{c}]$ 与 $b \in [0, \sqrt{c}]$，逐一检查 $a^2+b^2=c$：

$$O(c)\ \text{次检查} \approx 2.1\times 10^{9}$$

显然超时。稍微优化：对每个 $a$，用**哈希集合**存下所有平方数，$O(1)$ 判断 $c-a^2$ 是否平方数，枚举量降到 $O(\sqrt{c})$，但需要 $O(\sqrt{c})$ 的额外空间；也可以用**二分查找**或 `sqrt` 判断，$O(\sqrt{c}\log c)$，代价是浮点精度需要额外小心。

这三种都能过，但都只是「把候选集缩小」；下面给出一个更省空间、常数更小、且**无需任何浮点精度兜底**的写法。

### 3.2 核心观察：双指针夹逼

![双指针夹逼：a 上移、b 下移](images/wc39_q1_two_pointers.svg)

把候选解看成一个二维网格 $(a,b)$，其中 $0 \le a \le b \le \lfloor\sqrt{c}\rfloor$。关键性质是**单调性**：

- 固定 $b$，函数 $a \mapsto a^2+b^2$ 在 $a \ge 0$ 上**严格递增**；
- 固定 $a$，函数 $b \mapsto a^2+b^2$ 在 $b \ge 0$ 上**严格递增**。

于是把 $a$ 钉在小端、$b$ 钉在大端，让两条指针从两端向中间对撞：起点是

$$(a,b) = \bigl(0,\ \lfloor\sqrt{c}\rfloor\bigr)$$

之后 $a$ 只增、$b$ 只减，直到 $a > b$ 时收敛。每一步只有三种可能：

- $s = c$：命中，返回 `true`；
- $s = a^2+b^2 < c$：$a$ 配任何 $b' \le b$ 都只会让和小于 $c$，所以当前 $a$ 不可能是解的一部分，**$a$ 必须增大**；
- $s = a^2+b^2 > c$：$b$ 配任何 $a' \ge a$ 都只会让和大于 $c$，所以当前 $b$ 不可能是解的一部分，**$b$ 必须减小**。

两条指针都只朝对方单向移动，因此整个搜索过程恰好扫过一条「阶梯」，总步数被限制在 $O(\sqrt{c})$。

### 3.3 算法流程

![循环流程：三种去向](images/wc39_q1_loop_flow.svg)

```text
b ← ⌊√c⌋, a ← 0
while a ≤ b:
    s ← a² + b²
    if s = c : return true
    elif s < c: a ← a + 1
    else      : b ← b − 1
return false
```

终止条件是 $a > b$：此时 $a \le b$ 的可行区域被完全扫空，剩下的格子都已被「单调性」排除，说明无解。

### 3.4 示例演算

![c = 21 的逐步走查](images/wc39_q1_walkthrough.svg)

以 $c = 21$ 为例，初始 $a=0,\ b=\lfloor\sqrt{21}\rfloor=4$：

| 步 | $a$ | $b$ | $a^2+b^2$ | 与 21 比较 | 动作 |
|----|-----|-----|-----------|-----------|------|
| 1 | 0 | 4 | 16 | 偏小 | $a{+}{+}$ |
| 2 | 1 | 4 | 17 | 偏小 | $a{+}{+}$ |
| 3 | 2 | 4 | 20 | 偏小 | $a{+}{+}$ |
| 4 | 3 | 4 | 25 | 偏大 | $b{-}{-}$ |
| 5 | 3 | 3 | 18 | 偏小 | $a{+}{+}$ |
| 6 | 4 | 3 | 指针交错 $a>b$ | — | 返回 `false` |

对照 $c = 20$：$(0,4)\to16$、$(1,4)\to17$、$(2,4)\to20$，第 3 步就命中，返回 `true`（$20 = 2^2+4^2$）。

## 4. 算法细节

1. **$b$ 的初值必须是精确的整数开方**。C++ 里 `(long long)sqrt((double)c)` 在 $c$ 接近 $2^{31}$ 时可能偏大或偏小 1，所以要写两个修正循环：`while (b*b > c) b--;` 与 `while ((b+1)*(b+1) <= c) b++;`。Python 直接用 `math.isqrt(c)`，它是整数运算、天然精确。
2. **循环条件用 $a \le b$ 而不是 $a < b$**。$c = 2a^2$（如 $c=2, 8, 18$）的解恰好落在对角线上，用 `<` 会漏解。
3. **只保留 $a \le b$ 的一半网格**。$a^2+b^2$ 关于两个变量对称，$(a,b)$ 与 $(b,a)$ 是同一组解；限制 $a \le b$ 既不漏解，也保证两条指针不会互相越过之后又「回头」。
4. **注意 32 位溢出**。$a^2+b^2 \le 2\bigl(2^{31}-1\bigr) \approx 4.29\times10^{9} > \texttt{INT\_MAX}$，C++ 里必须用 `long long` 承接 $a$、$b$ 与和；Java 同理需 `long`。Python 无此问题。
5. **三个分支互斥且完备**：$s<c$、$s=c$、$s>c$ 覆盖全部情况，每轮必然前进一格，不存在原地打转的可能。
6. **不需要任何特殊哈希或集合**：只用两个整数变量，空间 $O(1)$；相比「哈希存平方数」省下 $O(\sqrt{c})$ 空间。
7. **等价写法（二分）**：固定 $a$ 后 $c-a^2$ 是否为完全平方数可用二分或 `isqrt` 判断，复杂度 $O(\sqrt{c}\log c)$；双指针版本少一个 $\log$，更稳。
8. **等价写法（数论）**：由费马平方和定理，$c$ 可表示为两平方数之和 $\iff$ $c$ 的每个 $\equiv 3 \pmod 4$ 的质因子的指数都是偶数；质因数分解 $O(\sqrt{c})$，同样能过，且能直接推广到「求方案数」。

## 5. 正确性证明

下面先证循环的不变量与终止性质（引理 1–3），再证主定理。

**引理 1（不变量）**：若存在解 $(a^*,b^*)$ 且 $0 \le a^* \le b^*$，则每一轮循环开始时都满足 $a \le a^*$ 且 $b \ge b^*$。

**证明**：初始 $a=0 \le a^*$；又 $b^{*2} \le a^{*2}+b^{*2} = c$，故 $b^* \le \lfloor\sqrt{c}\rfloor = b$，不变量成立。

设某轮开始时成立。若 $s<c$ 而 $a=a^*$，则由 $b \ge b^*$ 得 $s = a^{*2}+b^2 \ge a^{*2}+b^{*2} = c$，与 $s<c$ 矛盾，故 $a<a^*$，执行 $a{+}{+}$ 后仍有 $a \le a^*$，$b$ 不变。若 $s>c$ 而 $b=b^*$，则由 $a \le a^*$ 得 $s = a^2+b^{*2} \le a^{*2}+b^{*2} = c$，与 $s>c$ 矛盾，故 $b>b^*$，执行 $b{-}{-}$ 后仍有 $b \ge b^*$，$a$ 不变。$s=c$ 时直接返回，不进入下一轮。∎

**引理 2（有解必命中）**：在引理 1 的条件下，算法最多 $\bigl(a^*-a\bigr)+\bigl(b-b^*\bigr)$ 轮内返回 `true`。

**证明**：记间距 $g = (a^*-a)+(b-b^*) \ge 0$。只要本轮未返回，就有 $s \ne c$：若 $s<c$，由引理 1 的证明过程知 $a<a^*$，于是 $a{+}{+}$ 使 $g$ 减 1；若 $s>c$，同理 $b>b^*$，$b{-}{-}$ 使 $g$ 减 1。$g$ 是严格递减的非负整数，故在 $g$ 步之内必有 $g=0$，即 $a=a^*,\ b=b^*$，此时 $s = a^{*2}+b^{*2} = c$，返回 `true`。∎

**引理 3（无解时必然终止）**：若不存在解，循环必然在有限步内以 $a>b$ 结束。

**证明**：每轮要么 $a{+}{+}$、要么 $b{-}{-}$，而 $a$ 不减、$b$ 不增，故 $a-b$ 每轮至少增加 1。初始 $a-b = -\lfloor\sqrt{c}\rfloor$，因此不超过 $\lfloor\sqrt{c}\rfloor+1$ 轮后就有 $a>b$，循环退出并返回 `false`。∎

**定理**：算法返回 `true` 当且仅当 $c$ 可表示为两个整数的平方和。

**证明**：

- ($\Leftarrow$) 若 $c = u^2+v^2$，令 $a^* = \min(|u|,|v|)$、$b^* = \max(|u|,|v|)$，则 $0 \le a^* \le b^*$ 且 $a^{*2}+b^{*2} = c$，由引理 1 与引理 2，算法必返回 `true`。
- ($\Rightarrow$) 算法只在 $s = a^2+b^2 = c$ 时返回 `true`，而 $a,b$ 始终是整数，故 $c$ 确实是两个整数的平方和。∎

## 6. 复杂度分析

- **时间**：$O(\sqrt{c})$。每轮只做两次乘法与一次比较，是 $O(1)$ 的；由引理 2、引理 3，总轮数不超过 $2\lfloor\sqrt{c}\rfloor+1$。$c \le 2^{31}-1$ 时 $\lfloor\sqrt{c}\rfloor \le 46340$，最多约 $9.27\times10^{4}$ 次迭代，远低于时限。
- **空间**：$O(1)$。只用两个整型指针（C++ 中为 `long long`），与 $c$ 的大小无关。

## 7. 参考代码

### C++

```cpp
#include <cmath>

class Solution {
public:
    bool judgeSquareSum(int c) {
        long long a = 0, b = (long long)std::sqrt((double)c);
        while (b * b > c) b--;                 // 浮点开方可能偏大
        while ((b + 1) * (b + 1) <= c) b++;    // 也可能偏小
        while (a <= b) {
            long long s = a * a + b * b;       // 必须用 long long，防溢出
            if (s == c) return true;
            if (s < c) a++;                    // 和偏小：抬高 a
            else       b--;                    // 和偏大：压低 b
        }
        return false;                          // a > b，可行区间已扫空
    }
};
```

### Python

```python
import math


class Solution:
    def judgeSquareSum(self, c: int) -> bool:
        a, b = 0, math.isqrt(c)      # isqrt 是精确的整数开方
        while a <= b:
            s = a * a + b * b
            if s == c:
                return True
            if s < c:
                a += 1
            else:
                b -= 1
        return False
```

## 8. 边界情况与易错点

1. **$c = 0$**：$0^2+0^2 = 0$，应返回 `true`。此时初值 $a=b=0$，循环条件 $a \le b$ 成立，第一轮就命中；若写成 `while (a < b)` 或提前对 $c=0$ 特判返回 `false` 都会错。
2. **$c$ 是完全平方数**：如 $c=4=0^2+2^2$、$c=2147395600=46340^2$，答案都是 `true`（允许 $a=0$）。不要漏掉「一个数为 0」的解。
3. **对角线解**：$c=2,8,18$ 形如 $2a^2$，解为 $a=b$，必须用 $a \le b$；用 $a<b$ 会把这类解全部判成 `false`。
4. **32 位溢出**：$a^2+b^2$ 最大约 $4.29\times10^{9}$，超过 `INT_MAX`。C++ 中若把 `a`、`b` 声明成 `int`，$a*a$ 会在赋值给 `long long` **之前**就溢出，必须让 `a`、`b` 本身就是 `long long`。
5. **浮点开方误差**：`sqrt((double)c)` 对接近 $2^{31}$ 的 $c$ 可能返回偏大或偏小的整数部分，直接使用会让某个候选 $b$ 被多算或少算一格；务必用两个 `while` 修正到满足 $b^2 \le c < (b+1)^2$。
6. **比较方向写反**：$s<c$ 却执行 $b{-}{-}$（或 $s>c$ 却 $a{+}{+}$）会让和离 $c$ 越来越远，最终错误地返回 `false`，且难以从样例 $c=5$ 中察觉——务必用 $c=21$、$c=20$ 这种「需要来回折返」的数据自测。
7. **Python 慎用 `int(c ** 0.5)`**：幂运算走浮点路径，$c$ 很大时可能得到 $\lfloor\sqrt{c}\rfloor$ 偏小 1 的结果；`math.isqrt` 是整数算法，精确无误差。

**延伸思考**：

1. **求方案数而不是存在性**：由费马平方和定理，若 $c = 2^{a}\prod p_i^{e_i}\prod q_j^{2f_j}$（$p_i \equiv 1 \pmod 4$，$q_j \equiv 3 \pmod 4$），则表示数 $r_2(c) = 4\prod (e_i+1)$；分解质因数即可 $O(\sqrt{c})$ 求出方案数，比双指针更适合「数解」类变体。
2. **三个平方数之和**：由 Legendre 三平方定理，$c$ 不能表示为三个平方数之和 $\iff c = 4^{k}(8m+7)$，判定是 $O(\log c)$ 的。
3. **四平方和**：Lagrange 定理保证每个非负整数都能写成四个平方数之和，所以「四个」版本退化为平凡问题——这也是本题选「两个」的原因：它刚好落在「有时能、有时不能」的临界难度上。
4. **如果数据范围放大到 $c \le 10^{18}$**：双指针仍是 $O(\sqrt{c}) = 10^9$，会超时；此时应改用费马平方和定理做质因数分解（$O(c^{1/4})$ 级别的 Pollard-Rho），把「枚举」换成「数论」。
