# LeetCode 相同分数的最大操作数目 I 题解

## 1. 题目概述

- **标题 / 题号**：相同分数的最大操作数目 I（#3038，easy）
- **链接**：https://leetcode.cn/problems/maximum-number-of-operations-with-the-same-score-i/
- **来源**：LeetCode 第 124 场双周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定整数数组 nums。只要数组还剩至少 $2$ 个元素，就可以做一次操作：**删除最前面两个元素**，该次操作的**分数**是这两个元素之和。要求所有操作的分数都相同，求最多能做多少次操作。

**约束**：

- $2 \le nums.length \le 100$
- $1 \le nums[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：nums = [3,2,1,4,5]
输出：2
解释：第一次删 3、2，分数 5，剩 [1,4,5]；
      第二次删 1、4，分数 5，剩 [5]；
      只剩 1 个元素，无法继续。共 2 次。
```

**示例 2**

```text
输入：nums = [3,2,6,1,4]
输出：1
解释：第一次删 3、2，分数 5，剩 [6,1,4]；
      下一次只能删 6、1，分数 7 ≠ 5，不允许，于是停下。共 1 次。
```

**示例 3（边界补充）**

```text
输入：nums = [5,3]
输出：1
解释：第一次删 5、3，分数 8，数组清空，无法继续。共 1 次。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法就是**真的模拟**：用列表存 nums，每次检查前两个元素之和是否等于既定分数，是就 `del` 掉前两个并让答案加一，否则退出。$n \le 100$ 时怎么删都不会超时，作为签到场完全够用。

但「删除前两个」这个动作有一个很好的性质，能让我们连删除都省掉。

### 3.2 核心观察：配对方式是唯一的

![前两个一走，配对方式就被钉死了](images/bw124_q1_pairing_chain.svg)

每次操作只能删**当前数组最前面**的两个元素，而当前数组永远是原数组的一个**后缀**。于是：

- 第 $1$ 次操作删原下标 $0, 1$；
- 第 $2$ 次操作删原下标 $2, 3$；
- 第 $t$ 次操作删原下标 $2t-2, 2t-1$。

**没有任何选择余地**：配对方案唯一确定，题目说的「最多」其实是个幌子——能继续就必须继续，不能继续就停。分数由第一对 $nums[0] + nums[1]$ 定死，之后只需顺着检查 $nums[2] + nums[3]$、$nums[4] + nums[5]$……一旦某一对的和不等于该分数，立即停止。

因此算法只需一趟遍历：

```text
score = nums[0] + nums[1]
cnt = 0
i = 0
while i + 1 < n 且 nums[i] + nums[i+1] == score:
    cnt += 1
    i += 2
返回 cnt
```

### 3.3 算法流程

```text
1. score ← nums[0] + nums[1]，cnt ← 0
2. i ← 0
3. 当 i + 1 < n 时：
       若 nums[i] + nums[i+1] != score：跳出
       cnt ← cnt + 1，i ← i + 2
4. 返回 cnt
```

### 3.4 示例演算

![两个示例并排看](images/bw124_q1_example_walkthrough.svg)

- 示例 1：`[3,2,1,4,5]`，score $= 5$。$(3,2) \to 5$ ✓；$(1,4) \to 5$ ✓；剩一个 $5$ 凑不成对。答案 2。
- 示例 2：`[3,2,6,1,4]`，score $= 5$。$(3,2) \to 5$ ✓；$(6,1) \to 7 \ne 5$ ✗，立即停止。答案 1。

## 4. 算法细节

1. **分数只由第一对决定**：因为第一次操作无法回避，`nums[0] + nums[1]` 就是唯一的基准分数，不需要尝试其它可能。
2. **循环步长为 2**：每轮吃掉两个元素，用 `i += 2` 推进即可，不必真的修改数组。
3. **奇数长度会剩一个**：$n$ 为奇数时最后剩下单个元素，`i + 1 < n` 判定会自动结束循环，不参与任何操作。
4. **越界保护**：循环条件必须写成 `i + 1 < n`（Python 里也可用 `i + 1 < len(nums)`），避免奇数长度时访问 `nums[n]`。
5. **随时可以停**：一旦某对分数不同，后续即使再出现相同分数也**不能跳过去做**（因为必须删最前面两个），所以直接 `break` 是安全的。
6. **数据范围**：$nums[i] \le 1000$，两数之和 $\le 2000$，`int` 足够，不存在溢出。

## 5. 正确性证明

**引理 1（配对唯一）**：对任意 $t \ge 1$，若前 $t-1$ 次操作都成立，则第 $t$ 次操作删除的必是原数组下标 $2t-2$ 与 $2t-1$ 的两个元素。

**证明**：对 $t$ 归纳。$t = 1$ 时「最前面两个」即下标 $0, 1$，成立。设第 $t-1$ 次删掉了原下标 $2t-4, 2t-3$，则由归纳假设，前 $t-1$ 次共从原数组头部删去了 $2t-2$ 个元素，当前数组恰为原数组从下标 $2t-2$ 开始的后缀；其最前面两个元素即原下标 $2t-2, 2t-1$。∎

**引理 2**：分数序列 $s_1, s_2, \dots$ 定义为 $s_t = nums[2t-2] + nums[2t-1]$（下标存在时），则第 $t$ 次操作能够执行当且仅当 $2t-1 < n$ 且 $s_t = s_1$。

**证明**：由引理 1，第 $t$ 次操作的分数只能是 $s_t$；操作要求当前数组至少两个元素，即 $2t-2 \le n-2$，等价于 $2t-1 < n$；又要求分数与之前所有操作相同，而归纳地看，只需与第一次相同——因为若 $s_2 = \dots = s_{t-1} = s_1$ 且 $s_t = s_1$，则全部相同；反之若某个 $s_t \ne s_1$，第 $t$ 次就无法执行，过程终止。∎

**定理**：算法返回的 `cnt` 等于最多可执行的操作次数。

**证明**：由引理 2，能执行的操作序列恰好是 $s_1, s_2, \dots$ 的最长前缀（且要求下标存在），其长度就是满足「$2t-1 < n$ 且 $s_t = s_1$」的最大 $t$。算法从 $i = 0$（对应 $t = 1$）开始，逐对检查并在条件成立时让 `cnt` 加一，条件不成立或下标不足时终止，因此 `cnt` 恰为该最长前缀的长度，即最多操作次数。又因为操作序列没有任何分支可选（引理 1 表明配对唯一），「最多」与「唯一可能的次数」相同，算法结果即为最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每轮推进两个下标，最多 $\lfloor n/2 \rfloor$ 轮，每轮常数次操作。
- **空间**：$O(1)$。只用了分数、计数与下标三个变量，未修改输入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxOperations(vector<int>& nums) {
        int score = nums[0] + nums[1], cnt = 0, n = nums.size();
        for (int i = 0; i + 1 < n; i += 2) {
            if (nums[i] + nums[i + 1] != score) break;   // 分数一旦不同，后面不能再做
            ++cnt;
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def maxOperations(self, nums: list[int]) -> int:
        score = nums[0] + nums[1]
        cnt, i = 0, 0
        n = len(nums)
        while i + 1 < n and nums[i] + nums[i + 1] == score:
            cnt += 1
            i += 2
        return cnt
```

> 💡 两份代码通过官方示例（`2`、`1`）以及 `[5,3]`、`[1,1,1]` 等边界，并与「真的删除元素」的模拟实现在 5000 组随机小数组上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n$ 为奇数**：最后会剩一个元素，循环条件 `i + 1 < n` 保证不会越界；不要写成 `i < n`。
2. **第一对必然被执行**：即使整个数组只有两个元素，答案也至少是 1（前提 $n \ge 2$，题目保证）。
3. **分数固定后不能改**：题意要求「所有操作分数相同」，不允许为了提高次数而放弃第一次操作——第一次是强制的。
4. **不能跳过不合规的数对**：只能删最前面两个，遇到分数不同的那一对就必须停，不能「等下一对」。
5. **「最多」没有分支**：不要被措辞误导去搜索；配对方案唯一（引理 1）。
6. **整数范围**：$nums[i] \le 1000$，两数和最大 $2000$，用 `int` 即可。
7. **模拟实现别用 `erase` 起步**：`vector::erase` 是 $O(n)$ 的，虽然 $n \le 100$ 无所谓，但用下标推进更干净、也更容易推广到 II 版。
