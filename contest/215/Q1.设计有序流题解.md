# LeetCode 设计有序流 题解

## 1. 题目概述

- **标题 / 题号**：设计有序流（#1656，easy）
- **链接**：https://leetcode.cn/problems/design-an-ordered-stream/
- **来源**：LeetCode 第 215 场周赛 Q1
- **难度**：简单
- **标签**：设计、数组、模拟、单调指针、均摊分析

**题意**：编号 $1..n$ 的 $n$ 个块按**任意顺序**陆续到达，每个 $(\mathrm{idKey}, \mathrm{value})$ 对把 value 写进编号 idKey 的块（编号互异、恰好写 $n$ 次）。实现数据流类 `OrderedStream`：构造时指针 $\mathrm{ptr} = 1$；每次 `insert(idKey, value)` 写入后——

- 若编号 $\mathrm{ptr}$ 的块**恰好已被填**：把从 $\mathrm{ptr}$ 开始的**最长连续已填编号段**（$\mathrm{ptr}, \mathrm{ptr}+1, \dots$ 直到首个空位或越界）的值**按编号递增**返回，并将 $\mathrm{ptr}$ 更新为段尾编号 $+1$；
- 否则：返回空列表，$\mathrm{ptr}$ 原地不动。

**约束**：

- $1 \le n \le 1000$ → 规模无所谓，但「乱序到达缓冲」是可迁移模板，值得按均摊 $O(1)$ 沉淀
- $1 \le \mathrm{idKey} \le n$，且 $n$ 次 `insert` 恰好用完**互异**的编号 → 值可定址存入长 $n+1$ 的数组，不存在重复写
- value 恒为长度 5 的小写串 → **非空**，空串可安全充当「未填」哨兵

## 2. 示例

**示例 1**

```text
输入：
["OrderedStream","insert","insert","insert","insert","insert"]
[[5],[3,"ccccc"],[1,"aaaaa"],[2,"bbbbb"],[5,"eeeee"],[4,"ddddd"]]
输出：
[null,[],["aaaaa"],["bbbbb","ccccc"],[],["ddddd","eeeee"]]

解释：构造 OrderedStream(5) 后 ptr = 1；
      insert(3,"ccccc")：洞在 1 未补 → []；
      insert(1,"aaaaa")：补上洞 1 → ["aaaaa"]，ptr → 2；
      insert(2,"bbbbb")：2、3 连续已填 → ["bbbbb","ccccc"]，ptr → 4；
      insert(5,"eeeee")：洞在 4 未补 → []；
      insert(4,"ddddd")：4、5 连续已填 → ["ddddd","eeeee"]，ptr → 6。
```

**示例 2（升序到达）**

```text
输入：n = 4，insert 依次为 (1,"aaaa"), (2,"bbbb"), (3,"cccc"), (4,"dddd")
输出：[["aaaa"], ["bbbb"], ["cccc"], ["dddd"]]
解释：每次都恰好补上当前的洞，ptr 逐格前进 1→2→3→4→5，每次只交付一个值。
```

**示例 3（降序到达）**

```text
输入：n = 4，insert 依次为 (4,"dddd"), (3,"cccc"), (2,"bbbb"), (1,"aaaa")
输出：[[], [], [], ["aaaa","bbbb","cccc","dddd"]]
解释：前三次洞（都是编号 1）始终未补；第四次 (1,"aaaa") 补洞后，
      编号 1..4 恰好全部连上，一口气交付全部 4 个值，ptr → 5。
```

## 3. 解题思路

### 3.1 朴素思路：每次从 1 重扫

最不假思索的写法：开一个长 $n+1$ 的数组存值，每次 `insert` 写入后**从下标 1 开始**向右收集连续非空段当作返回值，再把指针挪到段尾。

问题出在「从 1 开始」：前缀 $[1, p)$ 早已交付完毕，与后续每一次询问都毫无关系，却每次都被重复扫描——降序到达时总代价退化为 $O(n^2)$。$n \le 1000$ 时数据上并不致命，但「反复检查已完结的前缀」是必须修掉的结构性浪费，而题面里现成的 `ptr` 正是修复的提示。

### 3.2 核心观察：挡路的只有 ptr 处的一个洞

![乱序缓冲与洞：交付时机由第一个空位决定](images/wc215_q1_hole_concept.svg)

把 ptr 指向的空位称作**洞**，可得到三个观察：

- **写入与交付解耦**：到达顺序任意，但每块只需 $O(1)$ 定址写入，写错位置不产生任何代价——乱序不是负担，是常态，先到的块安安静静缓存即可。
- **交付被洞卡住**：任一时刻能否输出，只取决于**编号最小的空位**（恰为 $\mathrm{ptr}$）是否被填上；它后面的连续已填块像被闸门拦住的水，闸门一开就整段涌出。
- **ptr 只前进**：交付过的前缀从此与算法无关，指针永不回退——这是均摊代价的来源。

> 💡 一句话：**乱序到达、按序输出**——缓存先到的，盯死第一个空位；洞补上的一瞬，把从洞开始的最长连续段一次性吐出。这正是 TCP 接收窗口的交付规则（ptr 对应期望序号 RCV.NXT）。

### 3.3 算法流程

![insert 流程：判洞、收割、推进](images/wc215_q1_insert_flow.svg)

```text
构造 OrderedStream(n)：
    slots ← 长为 n+1 的空串数组（下标 1..n，空串 = 未填）
    ptr ← 1

insert(idKey, value)：
1. slots[idKey] ← value              # 定址写入，O(1)
2. 若 idKey ≠ ptr：返回 [ ]          # 洞未补，ptr 不动
3. res ← [ ]
   当 ptr ≤ n 且 slots[ptr] ≠ ""：    # 从洞口向右收割
       res 追加 slots[ptr]
       ptr ← ptr + 1
4. 返回 res
```

### 3.4 示例演算

![示例 1 全程走查](images/wc215_q1_example_walkthrough.svg)

以官方示例走一遍（$n=5$，到达顺序 $3, 1, 2, 5, 4$）：

| 步 | insert | 槽位 1..5（写入后） | ptr（前→后） | 返回 |
|---|---|---|---|---|
| 1 | (3, ccccc) | · · **c** · · | 1 → 1 | `[ ]` |
| 2 | (1, aaaaa) | **a** · c · · | 1 → 2 | `["aaaaa"]` |
| 3 | (2, bbbbb) | a **b** c · · | 2 → 4 | `["bbbbb","ccccc"]` |
| 4 | (5, eeeee) | a b c · **e** | 4 → 4 | `[ ]` |
| 5 | (4, ddddd) | a b c **d** e | 4 → 6 | `["ddddd","eeeee"]` |

（**加粗** = 本次写入。）注意第 3 步：写入的只是块 2，却连带唤醒了**早已缓存**的块 3 一起交付——这正是乱序缓冲的全部价值。

## 4. 算法细节

1. **1 下标直接定址**：`slots` 长度开 $n+1$，编号即下标，写入/读取都是 $O(1)$；用 `map`/`dict` 也能过，但纯属绕路。
2. **空串当哨兵**：判「未填」用 `slots[ptr] == ""`，前提是 value 非空（本题长度恰为 5）。哨兵让收割循环只需一个条件。
3. **早退分支的依据是洞不变式**：`idKey != ptr` 就返回空，看似漏了「槽 ptr 之前已被填」的情形——其实由引理 1，每次调用**开始**时槽 ptr 必空，故写入后槽 ptr 非空当且仅当 idKey = ptr。不想依赖不变式也可以删掉早退、写入后直接从 ptr 起跑循环，行为完全一致（空槽会让循环体一次都不进）。
4. **推进只发生在收割处**：`ptr++` 与「收集一个值」绑定在同一处，代码结构本身保证指针单调——想回退都无从下手。
5. **交付即遗忘**：收割后的槽位在算法意义上已「死亡」（再也不会被读）；C++ 里可用 `std::move` 把字符串搬走、顺带清空槽位，语义与实现自洽。

## 5. 正确性证明

**引理 1（洞不变式）**：在任意一次 `insert` 调用**开始**时，若 $\mathrm{ptr} \le n$，则槽 $\mathrm{slots}[\mathrm{ptr}]$ 必为空；且此时所有下标 $< \mathrm{ptr}$ 的值都已恰好输出过一次，所有下标 $\ge \mathrm{ptr}$ 的值从未输出。

**证明**：对 insert 调用次数 $k$ 归纳。$k=0$（构造完成）时 $\mathrm{ptr}=1$、所有槽为空、无任何输出，成立。设第 $k$ 次调用开始时成立，考察该次调用：

- 若 $\mathrm{idKey} \ne \mathrm{ptr}$：由归纳假设槽 ptr 为空，写入发生在其他槽；早退返回空列表，$\mathrm{ptr}$ 与输出集合均不变，三个断言原样传递给第 $k+1$ 次调用。
- 若 $\mathrm{idKey} = \mathrm{ptr}$：`while` 循环自 ptr 起逐格推进，仅当「下标在界内且该槽非空」时收割并自增。循环停止只有两个原因：$\mathrm{ptr} > n$（越界），或 $\mathrm{slots}[\mathrm{ptr}]$ 为空——无论哪种，新 $\mathrm{ptr}$ 处（若 $\le n$）必为空槽；被收割的下标恰为 $[\mathrm{ptr}_0,\ \mathrm{ptr}_{\text{新}})$ 的全部下标且首次被输出，更右的下标从未被触碰。

两种情形均使断言在第 $k+1$ 次调用开始时成立。∎

**引理 2（收割段恰为极大连续段）**：设某次调用中 $\mathrm{idKey}=\mathrm{ptr}_0$，循环收集了下标 $\mathrm{ptr}_0, \mathrm{ptr}_0+1, \dots, m$。则 $\mathrm{slots}[\mathrm{ptr}_0..m]$ 全部非空，且 $m+1 > n$ 或 $\mathrm{slots}[m+1]$ 为空——即该段恰是从 $\mathrm{ptr}_0$ 开始的最长 id 连续递增已填段，且循环结束后 $\mathrm{ptr}=m+1$。

**证明**：循环不变式：每轮条件判断时，已收集列表恰为 $\mathrm{slots}[\mathrm{ptr}_0..i-1]$（$i$ 为当前 $\mathrm{ptr}$）且这些槽均非空。首轮 $i=\mathrm{ptr}_0$，列表为空，成立。进入循环体的条件保证槽 $i$ 非空且 $i \le n$，追加后不变式对 $i+1$ 保持。循环终止时条件取反，得「$i>n$ 或 $\mathrm{slots}[i]$ 为空」，此时 $m=i-1$、$\mathrm{ptr}=i=m+1$。收集顺序自左向右，故返回列表按 id 递增排列。∎

**定理**：`OrderedStream` 每次调用的返回值与题面语义一致：写入后，若流中存有 $\mathrm{id}=\mathrm{ptr}$ 的对，则返回从 ptr 起最长连续递增 id 段的值列表并令 ptr 指向段尾 $+1$；否则返回空列表且 ptr 不动。且每个 value 在整个生命周期中恰好被返回一次。

**证明**：归纳基础与引理 1 相同。考察某次调用：由引理 1，调用前槽 ptr 必空，而写入只改变槽 idKey，故写入后「存有 $\mathrm{id}=\mathrm{ptr}$ 的对」$\iff$ 槽 ptr 非空 $\iff \mathrm{idKey}=\mathrm{ptr}$。于是早退分支恰在「应返回空列表」时执行且 ptr 不动；收割分支由引理 2 返回恰为题面所指的最长连续段，并把 ptr 更新为最后一个 id $+1$。「每值恰返回一次」由引理 1 的输出断言逐次累加而得（各次收割段互不重叠且逐次右移）；又恰有 $n$ 次互异 insert，故最终全部 $n$ 个值各输出一次。∎

## 6. 复杂度分析

- **时间复杂度**：均摊每次 insert $O(1)$（输出体积另计）。关键在 ptr **单调不减**：早退分支不动它，收割分支每收集一个值才 +1，而 ptr $\le n+1$，故全程 `while` 的总迭代数 $\le n$；加上 $n$ 次定址写入，$n$ 次 insert 的总时间 $O(n)$。单次调用最坏可为 $O(n)$——降序到达时最后一次一口气交付 $n$ 个值。
- **空间复杂度**：$O(n \cdot L)$，其中 $L=5$ 为值长，即存储全部待交付字符串的缓冲数组；不计输出列表则为 $O(n)$ 缓冲。

## 7. 参考代码

### C++

```cpp
class OrderedStream {
    int n;
    int ptr = 1;
    vector<string> slots;              // slots[i]：编号 i 的块；空串 = 未填
public:
    OrderedStream(int n) : n(n), slots(n + 1) {}

    vector<string> insert(int idKey, string value) {
        slots[idKey] = move(value);
        if (idKey != ptr) return {};   // 洞未补：ptr 不动
        vector<string> res;
        while (ptr <= n && !slots[ptr].empty())
            res.push_back(move(slots[ptr++]));   // 收割一块，指针前进一格
        return res;
    }
};
```

### Python

```python
class OrderedStream:
    def __init__(self, n: int):
        self.n = n
        self.slots = [""] * (n + 1)    # 下标即编号，空串 = 未填
        self.ptr = 1

    def insert(self, idKey: int, value: str) -> list[str]:
        self.slots[idKey] = value
        if idKey != self.ptr:          # 洞未补：ptr 不动
            return []
        res = []
        while self.ptr <= self.n and self.slots[self.ptr]:
            res.append(self.slots[self.ptr])
            self.ptr += 1              # 收割一块，指针前进一格
        return res
```

## 8. 边界情况与易错点

1. **升序到达（1, 2, …, n）**：每次洞恰好补上，每次只返回单元素列表，ptr 最终到 $n+1$——别把「攒一批再吐」当成常态。
2. **降序到达（n, …, 2, 1）**：前 $n-1$ 次全返回空列表，最后一次返回全部 $n$ 个值，是最坏的单次 $O(n)$。
3. **n = 1**：唯一一次 insert 即触发交付，ptr 变为 2，无边界循环。
4. **越界终止**：ptr 可达 $n+1$，循环条件用 `ptr <= n`（1 下标）或 `ptr < slots.size()`（长度 $n+1$ 的数组）；0/1 下标混用、条件误写成 `< n` 是最常见的错误来源。
5. **空串哨兵的前提**：用 `slots[ptr] == ""` 判「未填」依赖 value 非空（本题长度恰为 5）；若题面放宽允许空串，必须改用 `filled` 布尔数组或 `None` 哨兵。
6. **返回空列表时不要动 ptr**：顺手 `ptr++` 会跳过一个未填位置，后续交付起点整体错位。
7. **返回新构造的列表**：每次新建 `res` 返回，不要把内部容器的引用/切片交出去，防止调用方修改污染内部状态。
