# LeetCode 确定两个字符串是否接近 题解

## 1. 题目概述

- **标题 / 题号**：确定两个字符串是否接近（#1657，medium）
- **链接**：https://leetcode.cn/problems/determine-if-two-strings-are-close/
- **来源**：LeetCode 第 215 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、计数、排序、不变量

**题意**：给定字符串 `word1` 与 `word2`。若 `word1` 能经**任意多次**下列两种操作变成 `word2`，则称两串**接近**：

- **操作 1**：交换字符串中任意两个**现有**字符的位置（如 `abcde -> aecdb`）；
- **操作 2**：取两个**都在场**的字符 $x, y$，把所有 $x$ 变为 $y$，**同时**把所有 $y$ 变为 $x$（如 `aacabb -> bbcbaa`，即 $x$ 与 $y$ 的频次整体互换）。

接近则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le |word1|, |word2| \le 10^5$ → 以「字符串状态」为结点的 BFS/DFS 状态空间指数爆炸，唯一出路是找**不变量**
- 仅含小写字母 → 字符域 $|\Sigma| = 26$，计数与排序均为常数级
- 两串长度可以不同 → 长度不等可直接判负（两种操作都不改变长度）

> 💡 读题抓信号：这是一道「**能否到达**」型判定题——先别急着模拟操作，先问「**什么东西在所有操作下永远不变**」。两个操作一个动**位置**、一个动**频次归属**，但都只在**现有字符之间搬运**——不变量已经呼之欲出。

## 2. 示例

**示例 1**

```text
输入：word1 = "abc", word2 = "bca"
输出：true
解释：2 次操作 1：abc -> acb -> bca，只动位置，不动频次。
```

**示例 2**

```text
输入：word1 = "a", word2 = "aa"
输出：false
解释：两种操作都不改变长度，1 ≠ 2，永远追不上。
```

**示例 3**

```text
输入：word1 = "cabbba", word2 = "abbccc"
输出：true
解释：3 次操作：
  操作 1：cabbba -> caabbb（交换位置 2 与 5）
  操作 2：caabbb -> baaccc（b 与 c 的频次互换）
  操作 2：baaccc -> abbccc（a 与 b 的频次互换）
```

（示例 3 的逐帧走查见 §3.4。）

## 3. 解题思路

### 3.1 暴力思路：搜索可达状态

把「字符串」本身当状态结点，从 `word1` 出发 BFS：每层扩展操作 1（$\binom{n}{2} \approx 5 \times 10^9$ 种位置交换）与操作 2（$\binom{26}{2} = 325$ 种频次互换），再用哈希集合去重。状态数上界是 $26^n$——$n = 10^5$ 时连**一个**状态都存得费劲，搜索彻底不可行。

死路的根源在于盯住了「**能变成什么**」。判定「能否到达」的正确姿势是反问「**什么永远变不了**」：找到一组在全部操作下保持的**不变量**，再论证这组不变量**恰好**刻画可达关系（既必要又充分）。

### 3.2 核心观察：不变量刻画可达性

![核心观察：两种操作只在现有字符间搬运频次，字符集合与频次多重集不变](images/wc215_q2_invariant_concept.svg)

逐一检查两种操作对「频次表」（每个字符 $\to$ 出现次数）的作用：

- **操作 1 只是位置重排**：频次表逐项不动——**顺序毫无意义**，比较前可以先忘掉它；
- **操作 2 是频次表中两行的整体互换**：$x$ 与 $y$ 都必须在场（频次 $\ge 1$），互换后仍 $\ge 1$——**在场的字符集合永远不变**；而把两行换来换去，**正频次的多重集合**（那一袋数字）也永远不变。

于是得到本题的心脏：

> **两串接近 $\iff$ ① 在场字符集合相同，且 ② 正频次的多重集相同**

**两个条件缺一不可**。频次多重集相同、字符集合不同的反例：

![反例：频次多重集相同但字符集合不同，答案为 false](images/wc215_q2_counterexample.svg)

`aab`（$a{:}2,\ b{:}1$）与 `aac`（$a{:}2,\ c{:}1$）的频次多重集都是 $\{1,2\}$，但 `word1` 里 `c` 从未在场——操作 2 要求两个字符**都在场**，`c` 永远进不来；`b` 一旦想「腾笼换鸟」也没有场外的对手。**字符类既造不出、也删不掉**，$\{a,b\} \ne \{a,c\}$，答案 `false`。

> ⚠️ 只比较「排序后的频次」是本题最经典的 WA（`aab` vs `aac`、`aa` vs `bb` 全中招）；对称地，只比较字符集合也不行（`aabb` vs `abbb`：集合同为 $\{a,b\}$，但频次 $\{2,2\} \ne \{1,3\}$——频次只能互换，不能增删拆合）。

另一个顺手的观察：两种操作都是**对合**（再做一次自己就复原），于是「可达」关系自反、对称、传递，是个**等价关系**——判定方向（从 `word1` 到 `word2` 还是反过来）无所谓，这给「双向不变量」的直觉又添了一份佐证。

### 3.3 算法流程：两条不变量逐项验收

![判定流程：长度早退、计数、字符集合比较、排序频次比较](images/wc215_q2_decision_flow.svg)

```text
1. 若 |word1| ≠ |word2|：返回 false            # 操作不改变长度（O(1) 早退）
2. 统计两条 26 桶计数数组 c1、c2                # 一次线性扫描
3. 若存在 i 使 (c1[i] > 0) != (c2[i] > 0)：    # 不变量①：字符集合
       返回 false
4. 若 sort(c1) != sort(c2)：                   # 不变量②：频次多重集
       返回 false
5. 返回 true
```

两个「不变量检查」都是 $O(26)$ 常数级操作；真正的开销只剩一次 $O(n)$ 计数。

### 3.4 示例演算

![示例 3 走查：三步操作的字符串与频次表演化](images/wc215_q2_example_walkthrough.svg)

以示例 3 `word1 = cabbba, word2 = abbccc` 为例，逐步跟踪字符串与频次表：

| 步骤 | 字符串 | $a$ | $b$ | $c$ | 操作 |
|---|---|---|---|---|---|
| 初始 | `cabbba` | 2 | 3 | 1 | — |
| 1 | `caabbb` | 2 | 3 | 1 | 操作 1：换位置 2 与 5 |
| 2 | `baaccc` | 2 | 1 | 3 | 操作 2：$b \leftrightarrow c$（3 与 1 互换） |
| 3 | `abbccc` | 1 | 2 | 3 | 操作 2：$a \leftrightarrow b$（2 与 1 互换） |

每一步之后：字符集合恒为 $\{a,b,c\}$，正频次多重集恒为 $\{1,2,3\}$——不变量纹丝不动；终态频次 $a{:}1,\ b{:}2,\ c{:}3$ 与 `word2` 完全一致（此例三步恰好直接落到 `word2`；一般情形频次对齐后还需若干次操作 1 排好位置，构造性证明见 §5 引理 3）。

反向核对：两串集合相同 $\{a,b,c\}$、频次多重集同为 $\{1,2,3\}$——两条不变量验收通过，与「能到达」的事实吻合。

## 4. 算法细节

1. **长度检查其实是冗余的**：频次多重集相同蕴含总和相同、即长度相同（步骤 4 已覆盖）。放在最前只是 $O(1)$ 早退习惯，省掉一次 $O(n)$ 计数，属于性能偏好而非正确性依赖（对照：本场 Q3 滑窗的 `target` 三段式同样「一份代码自然覆盖」）。
2. **字符集合检查的两种等价写法**：显式循环判 `(c1[i] > 0) != (c2[i] > 0)`；或位掩码 $mask = \sum_{ch \in S} 2^{ch-a}$，比较两个 26 位整数。后者把 26 次比较压成 1 次，可读性见仁见智。
3. **频次多重集的比较形式**：多重集相等 $\iff$ 升序排列后逐项相等，故 `sort(c1) == sort(c2)`。C++ 对 `array<int,26>` 排序后直接 `==`（26 个桶含 0，天然对齐）；Python 用 `sorted(c1.values()) == sorted(c2.values())`——`Counter` 只存正频次，恰好就是「正频次多重集」。
4. **为什么不能逐字符比较频次向量**：操作 2 允许频次在字符之间搬家，`cabbba`（$a{:}2$）与 `abbccc`（$a{:}1$）逐字符不同却接近——**排序后比较**恰好消掉「搬家」这个自由度，这正是「多重集」而非「向量」的用意。
5. **等价关系视角**：操作是对合 ⟹ 可达关系是等价关系 ⟹ 只需刻画**任一方向**的可达性；不变量对两串对称，天然契合。
6. **数值范围**：频次 $\le 10^5$、桶和 $\le 10^5$，`int` 毫无压力，无溢出问题。

## 5. 正确性证明

**引理 1（不变量）**：两种操作均保持 (i) 字符串长度；(ii) 在场字符集合 $S = \{\, ch : \mathrm{count}(ch) > 0 \,\}$；(iii) 正频次多重集 $F = \{\, \mathrm{count}(ch) : ch \in S \,\}$。且每种操作都是对合（自逆）。

**证明**：操作 1 交换两个位置的字符，频次向量逐项不变，(i)(ii)(iii) 平凡保持。操作 2 取 $x, y \in S$（在场故频次 $\ge 1$），互换 $\mathrm{count}(x)$ 与 $\mathrm{count}(y)$：长度是频次之和，不变；(ii) $x, y$ 的频次互换后仍 $\ge 1$，其余字符不动，$S$ 不变；(iii) $F$ 是多重集，其中两个元素互换位置仍是同一多重集。对合：操作 1 对同一对位置再交换一次、操作 2 对同一对字符再互换一次，均复原。∎

**引理 2（必要性）**：若两串接近，则 $S_1 = S_2$ 且 $F_1 = F_2$。

**证明**：设操作序列 $\sigma_1, \dots, \sigma_k$ 把 `word1` 变为 `word2`。对 $k$ 归纳：$k = 0$ 时两串相同，各量显然相等。由引理 1，每个 $\sigma_j$ 都保持 $S$ 与 $F$，故终态的 $S, F$ 与初态相同，即 $S_1 = S_2,\ F_1 = F_2$。∎

**引理 3（充分性构造）**：设 $S_1 = S_2 = S$ 且 $F_1 = F_2$，则 `word1` 可经有限次操作变为 `word2`。

**证明**（构造三阶段）：

**(1) 建立频次匹配的置换**。把 $S$ 按 `word1` 频次升序排成 $c_1, \dots, c_k$、按 `word2` 频次升序排成 $d_1, \dots, d_k$。$F_1 = F_2$（同一多重集的升序相同）给出 $\mathrm{cnt}_1(c_i) = \mathrm{cnt}_2(d_i)$。定义 $\sigma(c_i) = d_i$，则 $\sigma$ 是 $S$ 上的**置换**且 $\mathrm{cnt}_2(\sigma(c)) = \mathrm{cnt}_1(c)$ 对一切 $c \in S$ 成立。

**(2) 操作 2 链实现频次对齐**。$\sigma$ 可分解为对换之积 $\sigma = \tau_m \circ \cdots \circ \tau_1$。归纳保证执行第 $j$ 个对换 $\tau_j = (x\ y)$ 时，$S$ 中每个字符的频次恒 $\ge 1$（初始 $\ge 1$；操作 1 不动频次；操作 2 互换两个正数仍正），故 $x, y$ 都在场、操作 2 合法，且效果恰是互换 $x, y$ 的频次——精确实现 $\tau_j$。依次执行 $m$ 次，频次向量变为 $\mathrm{cnt}_2$。

**(3) 操作 1 链排好位置**。此时串与 `word2` 长度相同、逐字符频次相同，故存在位置排列 $\pi$ 使按 $\pi$ 重排后恰为 `word2`。$\pi$ 分解为位置对换之积，每个位置对换由一次操作 1 实现（位置上必有字符，天然「现有」）。执行完毕得到 `word2`。∎

**定理**：`word1` 与 `word2` 接近 $\iff$ 在场字符集合相同且正频次多重集相同。

**证明**：（$\Rightarrow$）引理 2。（$\Leftarrow$）引理 3；又 $F_1 = F_2 \Rightarrow$ 频次总和相等 $\Rightarrow$ 长度相等，引理 3 的前提自动成立。∎

**推论（算法正确性）**：步骤 3 检查 26 桶的正零模式相同，等价于 $S_1 = S_2$（字符域恰为 26 个小写字母，桶非零 ⟺ 在场，穷尽全部字符）；步骤 4 的排序比较等价于 $F_1 = F_2$（升序序列相同 ⟺ 多重集相等）。两次比较恰为定理的两条件，故算法当且仅当两串接近时返回 `true`；长度早退由定理蕴含关系覆盖。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + |\Sigma| \log |\Sigma|) = O(n + 26 \log 26) \approx O(n)$。一次线性扫描计数；两条 26 桶数组的排序与比较是常数级（$26 \log 26 < 130$ 次基本操作）。
- **空间复杂度**：$O(|\Sigma|) = O(26) = O(1)$。仅两条计数数组，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool closeStrings(string word1, string word2) {
        if (word1.size() != word2.size()) return false;
        array<int, 26> c1{}, c2{};
        for (char ch : word1) ++c1[ch - 'a'];
        for (char ch : word2) ++c2[ch - 'a'];
        for (int i = 0; i < 26; ++i)
            if ((c1[i] > 0) != (c2[i] > 0)) return false;
        sort(c1.begin(), c1.end());
        sort(c2.begin(), c2.end());
        return c1 == c2;
    }
};
```

### Python

```python
class Solution:
    def closeStrings(self, word1: str, word2: str) -> bool:
        if len(word1) != len(word2):
            return False
        c1, c2 = Counter(word1), Counter(word2)
        if set(c1) != set(c2):
            return False
        return sorted(c1.values()) == sorted(c2.values())
```

## 8. 边界情况与易错点

1. **长度不同（示例 2 `a` vs `aa`）**：直接 `false`。不做 $O(1)$ 早退也会被频次多重集 $\{1\} \ne \{2\}$ 拦下——长度条件蕴含于频次总和，两道闸门冗余互备。
2. **最典型 WA：漏查字符集合**。`aab` vs `aac`、`aa` vs `bb` 的排序频次完全相同，只写 `sorted(freq1) == sorted(freq2)` 会双双误判 `true`（见 §3.2 反例）。
3. **对偶 WA：漏查频次多重集**。`aabb` vs `abbb` 字符集合同为 $\{a,b\}$，但频次 $\{2,2\} \ne \{1,3\}$——操作 2 只能**互换**频次，不能把 2 拆成 1+3，答案 `false`。
4. **误读「现有」约束**：把操作 2 读成「可以把 $x$ 换成任意字母（含不在场的）」，就能凭空造出新字符，把 `aab` vs `aac` 误判 `true`。原文两处「**现有**」正是集合不变量的来源；正确语义是**双向同步互换**（「并对另一个字符执行相同的操作」），既造不出场外字符、也删不掉场内字符。
5. **Python 的 `Counter` 相等陷阱**：直接 `Counter(word1) == Counter(word2)` 比的是逐字符频次向量，会把 `cabbba` vs `abbccc` 判 `false`——必须比较 `values()` 的排序结果。
6. **相同字符串**：零次操作即相等，两条件自然成立，无需特判；空串情形被约束 $|word| \ge 1$ 排除。
7. **字符域**：仅小写 26 字母，定长数组最优；若放宽到任意 Unicode，改哈希表计数 + `values` 排序，复杂度 $O(n + u \log u)$（$u$ 为实际出现的不同字符数）。
