# LeetCode 将x减到0的最小操作数 题解

## 1. 题目概述

- **标题 / 题号**：将x减到0的最小操作数（#1658，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-reduce-x-to-zero/
- **来源**：LeetCode 第 215 场周赛 Q3
- **难度**：中等
- **标签**：数组、滑动窗口、前缀和、双指针、正难则反

**题意**：给定正整数数组 `nums` 与整数 `x`。每次操作移除数组**最左边**或**最右边**的元素，并从 $x$ 中减去该元素的值（数组随之变短）。若能通过若干次操作把 $x$ **恰好**减到 $0$，返回**最小操作数**；否则返回 $-1$。

**约束**：

- $1 \le n \le 10^5$ → 双重枚举 $(l, r)$ 的 $O(n^2)$ 不可行，需线性或 $O(n \log n)$ 做法
- $1 \le \text{nums}[i] \le 10^4$ → **元素全正**：窗口和随端点移动严格单调，变长滑窗可用；总和至多 $10^9$
- $1 \le x \le 10^9$ → $x$ 可远超数组总和，必须能正确判"无解"

> 💡 读题时抓两个信号：**只能从两端删** ⟹ 被删元素天然构成「一个前缀 + 一个后缀」；**元素全正** ⟹ 求「定和最长子数组」可以上滑动窗口。两者拼起来就是本题的完整解法路径。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,4,2,3], x = 5
输出：2
解释：移除最右的两个元素 [2,3]，2 + 3 = 5 = x，恰好归零，共 2 次操作。
```

**示例 2**

```text
输入：nums = [5,6,7,8,9], x = 4
输出：-1
解释：最小元素为 5 > 4，任何非空删除集合之和都严格大于 4，无法恰好凑出 x。
```

**示例 3**

```text
输入：nums = [3,2,20,1,1,3], x = 10
输出：5
解释：左删 [3,2]（和 5）+ 右删 [1,1,3]（和 5），删除总和 10 = x，
      共 5 次操作，中间保留 [20]。
```

## 3. 解题思路

### 3.1 暴力思路：枚举左删几个、右删几个

设左删 $l$ 个、右删 $r$ 个，合法方案需满足「前 $l$ 项和 + 后 $r$ 项和 $= x$」，操作数即 $l + r$。最直接的做法是双重枚举 $(l, r)$，$O(n^2) \approx 10^{10}$，必然超时。

利用前缀和、后缀和各自的单调性，可以把内层换成二分或哈希表降到 $O(n \log n)$——能过，但始终停留在"正面凑两端"的框架里。**正难则反**才是本题的题眼：与其枚举删什么，不如看**剩下什么**。

### 3.2 核心观察：两端删除 ⟺ 中间保留

![正难则反：从两端删除等价于在中间保留](images/wc215_q3_complement_concept.svg)

被删除的元素永远是**一个前缀 + 一个后缀**（引理 1），于是三个等式一气呵成：

- 删除和 $= x$ ⟺ 保留的**中间连续段**之和 $= \text{total} - x$（记作 $\text{target}$）
- 最小化删除个数 $l + r$ ⟺ 最大化保留段长度 $n - (l + r)$
- 移除顺序不影响删除总和——合法性只由「删了哪些」决定，与「先删哪边」无关

问题一步转化为：**找和恰为 $\text{target}$ 的最长连续子数组**。设其长度为 $L$，答案即 $n - L$；若 $\text{target} < 0$（$x$ 比总和还大）或找不到这样的子数组，返回 $-1$。

### 3.3 算法流程：变长滑动窗口

![变长滑动窗口流程：右扩、过量左缩、命中记最长](images/wc215_q3_sliding_window_flow.svg)

由于元素全正，窗口和随右扩严格增大、随左缩严格减小，变长滑窗 $O(n)$ 即可：

```text
1. target ← total − x
2. left ← 0，sum ← 0，max_len ← −1（哨兵：尚未命中）
3. 对 right = 0 .. n−1：
     sum ← sum + nums[right]              # 右扩一格
     当 sum > target 且 left ≤ right：     # 过量才缩
         sum ← sum − nums[left]
         left ← left + 1
     若 sum == target：                    # 恰好命中
         max_len ← max(max_len, right − left + 1)
4. 返回 max_len = −1 ? −1 : n − max_len
```

> 💡 注意判等发生在**收缩之后**：只要 `sum > target` 就先缩再查。`target = 0` 时窗口每轮被缩空（`left = right + 1`，长度记 0），恰好给出「删光全部」的答案 $n$；`target < 0` 时任何窗口和（$\ge 0$）都不可能等于 `target`，自然返回 $-1$——**整份代码无需任何特判**（严格论证见 §5 定理）。

### 3.4 示例演算

![示例 1 走查：滑动窗口逐步状态](images/wc215_q3_example_walkthrough.svg)

以示例 1 `nums = [1,1,4,2,3], x = 5` 为例，`total = 11`，`target = 6`：

| right | 入窗后窗口 | 收缩 | 终态窗口 | sum | 命中？ | max_len |
|---|---|---|---|---|---|---|
| 0 | [1] | 无 | [1] | 1 | 否（< 6） | −1 |
| 1 | [1,1] | 无 | [1,1] | 2 | 否（< 6） | −1 |
| 2 | [1,1,4] | 无 | [1,1,4] | 6 | **是，len = 3** | 3 |
| 3 | [1,1,4,2] | 缩 2 次 | [4,2] | 6 | 是，len = 2 | 3 |
| 4 | [4,2,3] | 缩 1 次 | [2,3] | 5 | 否（< 6） | 3 |

最长命中窗口为 `[1,1,4]`（保留），答案 $= 5 - 3 = 2$——保留中间、右删 $[2,3]$，与示例输出一致。

## 4. 算法细节

1. **`target` 的三段式**：`target < 0`（$x > \text{total}$，删光都不够）→ 无解；`target = 0`（$x = \text{total}$，须删光）→ 答案 $n$；`target > 0` → 滑窗找最长。三种情形被 §3.3 同一份代码覆盖，显式早退只是可读性偏好，不是正确性依赖。
2. **为什么必须元素全正**：滑窗的贪心收缩依赖「左缩使和严格减小」。若含负数，`sum > target` 时缩左端和可能不降反升，`while` 的停止条件失去意义——那时应改用前缀和 + 哈希（见延伸思考）。
3. **`while` 条件中的 `left <= right` 不可省**：`target < 0` 时 `sum` 恒大于 `target`，靠这个守卫把 `left` 停在 `right + 1`（空窗口，`sum = 0`），否则 `left` 一路冲出数组越界死循环。
4. **`max_len` 哨兵取 −1 而非 0**：要区分「从未命中」（返回 −1）与「命中空窗口」（`target = 0` 时长度 0，返回 $n$）。初始化成 0 会把无解误报成「删光即可」。
5. **记录的是最长而非任意**：对每个 `right`，收缩停在「和 $\le \text{target}$ 的最小左端」，因此命中时取到的正是以 `right` 结尾的**最长**命中窗口（引理 3）。
6. **对偶写法**：也可以建前缀和数组 $P$ 与后缀和数组 $S$，在「删除侧」双指针——$l$ 递增时满足 $P_l + S_r = x$ 的 $r$ 单调递减，统计最小 $l + r$，同为 $O(n)$。滑窗版本不建数组、空间 $O(1)$，且两种写法互为镜像，可交叉验证。
7. **溢出**：$\text{total} \le 10^5 \times 10^4 = 10^9$，`target` 落在 $[-10^9, 10^9]$，`int` 勉强装得下但贴边，C++ 用 `long long` 一劳永逸；Python 无此虞。

## 5. 正确性证明

**引理 1（操作结构）**：任意操作序列移除的元素集合，恰为原数组的一个前缀（长 $l$）与一个不相交的后缀（长 $r$），且 $l + r =$ 操作次数。特别地，$x$ 的最终值只依赖删除元素之**和**，与删除顺序无关。

**证明**：对操作次数 $k$ 归纳。$k = 0$ 时 $l = r = 0$。设 $k$ 次后成立，则当前剩余数组是原数组的连续段 $\text{nums}[l..n-1-r]$；第 $k+1$ 次操作移除其最左（原下标 $l$，令 $l{+}{+}$）或最右（原下标 $n-1-r$，令 $r{+}{+}$），断言保持。又每次操作从 $x$ 减去一个定值，最终值 $= x - $（删除总和），与顺序无关。∎

**引理 2（补集转化）**：记 $\text{total} = \sum_i \text{nums}[i]$，$\text{target} = \text{total} - x$。则「存在 $k$ 次操作使 $x$ 恰减到 $0$」⟺「存在长度为 $n - k$ 的连续子数组（允许空，当 $k = n$）其和为 $\text{target}$」。从而最小操作数 $= n - L$，其中 $L$ 是和为 $\text{target}$ 的连续子数组的最大长度（$\text{target} = 0$ 时空子数组也计入，$L \ge 0$）。

**证明**：（⟹）设方案删除前缀长 $l$、后缀长 $r$，$l + r = k$，删除和 $= x$。剩余元素恰为连续段 $\text{nums}[l..n-1-r]$，长度 $n - k$，其和 $= \text{total} - x = \text{target}$。（⟸）取和为 $\text{target}$ 的连续子数组 $\text{nums}[a..b]$，令 $l = a$、$r = n - 1 - b$，做 $l$ 次左删、$r$ 次右删（顺序由引理 1 无关紧要），删除和 $= \text{total} - \text{target} = x$，操作数 $= l + r = n - (b - a + 1)$。两侧构造互逆，构成一一对应。∎

**引理 3（滑窗精确命中）**：记 $S(l, r) = \sum_{i=l}^{r} \text{nums}[i]$（约定 $S(r+1, r) = 0$）。元素全正使 $S$ 对 $l$（固定 $r$）严格递减、对 $r$（固定 $l$）严格递增。则处理 `right` $= r$ 的收缩后，`left` 是满足 $S(l', r) \le \text{target}$ 的最小 $l'$（`target < 0` 时为 $r + 1$，判等恒假）。因而该轮 `sum == target` 为真 ⟺ 存在 $l$ 使 $S(l, r) = \text{target}$，且为真时命中的恰是以 $r$ 结尾的最长命中窗口。

**证明**：`while` 循环不变式为 `sum = S(left, r)`；`left` 自进入该轮前的位置起逐一遍增，循环停在**首个**满足 $S \le \text{target}$ 的左端（守卫 `left <= right` 至多将其推到 $r + 1$，即空窗口）。先证 `left` 未曾越过最优左端：反设 $S(l^*, r) = \text{target}$ 而 `left` 曾在某轮从 $l^*$ 增至 $l^*{+}1$，则该轮右端 $r' \le r$ 且 $S(l^*, r') > \text{target}$，与单调性 $S(l^*, r') \le S(l^*, r) = \text{target}$ 矛盾。故收缩终点 $\text{left} \le l^*$；又一切 $l' < l^*$ 都有 $S(l', r) > S(l^*, r) = \text{target}$（对 $l$ 严格递减），说明 $l^*$ 正是「首个满足 $S \le \text{target}$ 的左端」，两者相等，判等为真且长度 $r - l^* + 1$ 是以 $r$ 结尾的最大值。反之若判等为真，窗口本身就是和为 $\text{target}$ 的子数组，记录合法。∎

**定理**：算法返回把 $x$ 恰好减到 $0$ 的最小操作数；无方案时返回 $-1$。

**证明**：由引理 3，`max_len` 恰为和为 `target` 的最长连续子数组长度 $L$：对每个 $r$ 取到以其结尾的最长者；`target = 0` 时空窗口每轮命中给出 $L \ge 0$，而正元素保证非空窗口和恒正、不产生虚假命中；`target < 0` 时判等恒假，`max_len` 保持 $-1$。由引理 2，有方案时答案为 $n - L$，无方案（`target < 0`，或 `target ≥ 0` 但无子数组和恰为 `target`）时算法返回 $-1$，与引理 2 的无解条件一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`right` 单调推进 $n$ 步；`left` 全程从 $0$ 单调推进至多到 $n$，`while` 的总收缩次数 $\le n$——每个元素至多入窗一次、出窗一次，合计线性。
- **空间复杂度**：$O(1)$。仅常数变量 `target / sum / left / max_len`，不建前缀和数组（对比「前缀 + 后缀双指针」写法的 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int x) {
        int n = nums.size();
        long long target = accumulate(nums.begin(), nums.end(), 0LL) - x;
        long long sum = 0;
        int left = 0, max_len = -1;
        for (int right = 0; right < n; ++right) {
            sum += nums[right];
            while (sum > target && left <= right)
                sum -= nums[left++];
            if (sum == target)
                max_len = max(max_len, right - left + 1);
        }
        return max_len == -1 ? -1 : n - max_len;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: List[int], x: int) -> int:
        n = len(nums)
        target = sum(nums) - x
        max_len = -1
        left = 0
        window_sum = 0
        for right, val in enumerate(nums):
            window_sum += val
            while window_sum > target and left <= right:
                window_sum -= nums[left]
                left += 1
            if window_sum == target:
                max_len = max(max_len, right - left + 1)
        return -1 if max_len == -1 else n - max_len
```

## 8. 边界情况与易错点

1. **x 大于总和（target < 0）**：删光整个数组都不够减，答案 $-1$。代码靠「窗口和恒 $\ge 0$ ≠ 负 target」自然返回 $-1$，前提是 `while` 里 `left <= right` 守卫在场，否则越界死循环。
2. **x 等于总和（target = 0）**：唯一方案是删光全部 $n$ 个，答案 $n$。滑窗每轮把窗口缩空（长度 0）命中，`max_len = 0` → 返回 $n - 0 = n$；若 `max_len` 误初始化为 0，无解时会误返回 $n$，务必用 $-1$ 哨兵。
3. **单元素数组**：$n = 1$，要么删它（若 $\text{nums}[0] = x$，答案 1），要么无解。
4. **判等时机**：`sum == target` 的检查必须在 `while` 收缩**之后**——收缩途中也可能路过相等，但那对应更短的窗口；引理 3 保证收缩终点恰是最长命中窗口，检查终点即可。
5. **收缩与判等只差一个符号**：收缩条件是 `>`，命中条件是 `==`。误写成「和 $\le \text{target}$ 的最长窗口」语义全变（那是 209 型「至多」问题），本题要求**恰等于**。
6. **先删哪一侧不重要**：比赛时容易纠结「是不是该贪心地先删小的一侧」，但由引理 1，删除总和与顺序无关，方案由 $(l, r)$ 二元组完全刻画，没有「删除顺序上的贪心」。
7. **贴边的数值范围**：$\text{total}$ 上界 $10^9$，`int` 恰好装下；混入 $x$ 的加减后建议统一 `long long`（Python 无此虞）。
