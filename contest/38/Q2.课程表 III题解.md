# LeetCode 课程表 III 题解

## 1. 题目概述

- **标题 / 题号**：课程表 III（#630，hard）
- **链接**：https://leetcode.cn/problems/course-schedule-iii/
- **来源**：LeetCode 第 38 场周赛 Q2
- **难度**：困难
- **标签**：贪心、数组、排序、堆（优先队列）

**题意**：有 $n$ 门课，第 $i$ 门课需要连续上 $d_i$ 天，且必须**在不晚于** $last_i$ 的那天结束（即完成时刻 $\le last_i$）。学期从第 1 天开始，同一时刻只能上一门课，修课顺序不受编号限制，课程之间可以不留空档。求最多能修完多少门课。

**约束**：

- $1 \le n \le 10^4$
- $1 \le d_i, last_i \le 10^4$
- 所有课程的截止时间与时长都不超过 $10^4$，但**总时长可达 $10^8$**，别用 16 位整数存

## 2. 示例

**示例 1**

```text
输入：courses = [[100,200],[200,1300],[1000,1250],[2000,3200]]
输出：3
解释：最多修 3 门 —— 第 1 门（第 100 天完）→ 第 3 门（第 1100 天完）→ 第 2 门（第 1300 天完）。
      第 4 门若修，完成时刻为 3300 > 3200，超期，只能放弃。
```

**示例 2**

```text
输入：courses = [[1,2]]
输出：1
解释：第 1 天修完，1 ≤ 2，可以修。
```

**示例 3**

```text
输入：courses = [[3,2],[4,3]]
输出：0
解释：两门课的时长都超过各自的截止时间，一门也修不完。
```

## 3. 解题思路

### 3.1 暴力思路

先解决子问题：**给定一个课程集合，能否全部修完？** 答案是「按截止时间升序修」（EDF）即可判定（见 §5 引理 1）。但找「最大的可行集合」需要枚举子集：$2^n$ 个集合、每个 $O(n\log n)$ 判定，$n=10^4$ 时完全是天文数字。

另一个方向是按时间做 0/1 背包：$f[t]$ 表示「刚好用掉 $t$ 天时最多能修几门」，$t \le \max last_i = 10^4$，复杂度 $O(n \cdot 10^4) = 10^8$。C++ 勉强、Python 基本没戏，而且这个状态设计还要求对**每一门课**做一次倒序更新，常数不小。需要更锋利的贪心。

### 3.2 核心观察：按截止时间排序 + 大顶堆「以短换长」

![按截止时间排序，超时就踢掉时长最长的一门](images/wc38_q2_greedy_swap.svg)

**观察 1（排序不损失最优性）**：由引理 1，任一组课的可行性与「按截止时间升序」这个顺序绑定。因此我们可以**先把所有课按 $last$ 升序排好**，然后从左到右决定「收下 / 不收下」，收下的课天然就是按 EDF 排列的。

**观察 2（状态只需两个量）**：排好序后，判断「已选的这 $k$ 门 + 新的一门 $i$」是否可行，只需要看一件事——**总时长 $T$ 是否 $\le last_i$**。原因：已选的课都是 EDF 可行的，新来的截止时间最长，放在最后一位，只要它自己的完成时刻 $T + d_i \le last_i$，前面那些课的前缀和一点没变，依然各自不超期。

**观察 3（同课程数下，总时长越小越好）**：在「已经选了 $k$ 门」的所有方案里，总时长 $T$ 最小的那个**支配**其余方案：任何后续能塞进去的课，用更小的 $T$ 都能塞进去。于是我们只维护「$k$ 门课 + 最小总时长」这一个状态。

**观察 4（超期时该放弃谁）**：若 $T + d_i > last_i$，说明这 $k+1$ 门课在当前截止时间下装不下，**必然要放弃其中一门**。放弃「时长最长的那门」最优：课程数从 $k+1$ 掉回 $k$（和不收这门一样），而总时长的削减最多，对后续课程最有利。于是用一个**大顶堆**保存已选课程的时长，超期就弹出堆顶。

这个贪心是「反悔式贪心」：每门课**先无条件收下**，只有在超期时才退掉之前收得最亏的那一门。

### 3.3 算法流程

![算法流程：排序、逐个尝试、超期弹出最长](images/wc38_q2_flow.svg)

```text
把 courses 按 lastDay 升序排序
heap ← 空的大顶堆（存已选课程的时长），total ← 0
for (d, last) in courses:
    total ← total + d
    heap.push(d)                 # 先无条件收下
    if total > last:             # 装不下，反悔
        total ← total - heap.pop_max()
return heap.size()
```

### 3.4 示例演算

![示例 1 的逐门走查表](images/wc38_q2_walkthrough.svg)

对示例 1，排序后依次处理 $[100,200] \to [1000,1250] \to [200,1300] \to [2000,3200]$：前 3 门依次收下，$total$ 从 100 涨到 1300（正好 $=1300$，**不超期**）；第 4 门加入后 $total = 3300 > 3200$，弹出最长的 2000，$total$ 回落到 1300，堆大小仍是 3，答案 3。

再看一个「踢掉已选中课程」的例子 `[[5,5],[4,6],[2,6]]`：

| 步骤 | 课程 | 加入后 total | 判定 | 堆（大小） |
|------|------|--------------|------|------------|
| 1 | `[5,5]` | 5 | $5 \le 5$ 收下 | $\{5\}$（1） |
| 2 | `[4,6]` | 9 | $9 > 6$，弹出 5 | $\{4\}$（1） |
| 3 | `[2,6]` | 6 | $6 \le 6$ 收下 | $\{4,2\}$（2） |

答案 2：第 2 步用「4 天」换掉了「5 天」，课程数不变但省下 1 天，第 3 步才塞得进 2 天的那门课。若不做反悔，第 2 步后就再也收不下新课了。

## 4. 算法细节

1. **排序键**：只按 $last$ 升序即可（$last$ 相同则任意顺序，结论不受影响）；不要按 $d$ 排，也不要按编号排。
2. **大顶堆的实现**：C++ 用 `priority_queue<int>`（默认大顶）；Python 的 `heapq` 是小顶堆，**存负数**取反得到大顶效果，弹栈写作 `total += heapq.heappop(heap)`（弹出的是负值，等价于 `total -= max`）。
3. **只弹一次就够**：因为弹出的 $m \ge d_i$（$m$ 是 $H \cup \{d_i\}$ 的最大值），弹出后 $total' = total + d_i - m \le total$；而 $total \le last_i$（$total$ 是上一轮某个 EDF 可行集合的总时长，其最大截止时间 $\le last_i$），故 $total' \le last_i$ 必然成立，无需 `while`。
4. **边界条件用 `>` 而不是 `>=`**：题目是「不晚于 $last$ 完成」，$total = last_i$ 是合法的（见示例 1 第 3 步）。
5. **总时长类型**：$n \cdot d \le 10^8$ 在 `int` 内（$< 2^{31}$），但为免加错建议 C++ 用 `long long` 存 $total$；Python 无此问题。
6. **不要真的排出时间表**：不需要记录每门课的起止时刻，也不需要回溯具体选了哪些课——答案只是堆的大小。若题目要求输出方案，才需要额外保存堆中元素。
7. **先 push 再判断**：先无条件 `push` 再比较 `total > last`，既保证弹出时堆一定非空，也保证「用新来的短课替换已选的长课」这条路径一定被走到。若写成「`total + d > last` 就直接跳过」，对 `[[5,10],[6,6],[1,6]]`（排序后为 `[6,6],[1,6],[5,10]`）会得到 1，而正确答案是 2（选 `[1,6]` 与 `[5,10]`）。

## 5. 正确性证明

**引理 1（EDF 可行性判定）**：课程集合 $S$ 能全部修完，当且仅当把 $S$ 按 $last$ 升序排成 $i_1,\dots,i_m$ 后，对每个 $j$ 都有 $\sum_{r \le j} d_{i_r} \le last_{i_j}$。

**证明**：充分性显然——就按这个顺序修。必要性：设存在一个可行顺序，若其中有相邻两项 $a,b$ 满足 $last_a > last_b$（逆序），设它们开始于时刻 $t$。交换前有 $t + d_a \le last_a$、$t + d_a + d_b \le last_b$；交换后 $b$ 在 $t + d_b \le t + d_a + d_b \le last_b$ 完成，$a$ 在 $t + d_a + d_b \le last_b < last_a$ 完成，仍然可行。反复消去逆序（冒泡排序）即得到 EDF 顺序，每一步都保持可行，故 EDF 顺序可行，其前缀和条件成立。特别地，可行集合的总时长不超过其最大截止时间。∎

记多重集 $X$ 中最小的 $j$ 个元素之和为 $m_j(X)$（$m_0 = 0$），$\mathrm{OPT}_i$ 为前 $i$ 门课中可行集合的最大大小，$f_i(j)$ 为前 $i$ 门课中**所有可行 $j$ 元集合**的最小总时长（不存在时为 $+\infty$）。课程已按 $last$ 升序排列。

**引理 2（不变量）**：处理完前 $i$ 门课后，堆 $H_i$ 满足：(1) $H_i$ 按 $last$ 升序可全部修完；(2) $|H_i| = \mathrm{OPT}_i$；(3) 对每个 $1 \le j \le |H_i|$ 有 $f_i(j) = m_j(H_i)$。

**证明**：对 $i$ 归纳，$i=0$ 时显然。设 $i-1$ 成立，令 $k = |H_{i-1}|$、$T = \sum H_{i-1}$，新课程时长 $t$、截止 $L$（$L$ 不小于前缀中所有 $last$）。用到两条多重集恒等式：

- (A) $m_j(H_{i-1}\cup\{t\}) = \min\bigl(m_j(H_{i-1}),\ t + m_{j-1}(H_{i-1})\bigr)$——$j$ 元集合要么不含 $t$，要么含 $t$；
- (B) 令 $m = \max(H_{i-1}\cup\{t\})$，则对 $j \le k$ 有 $m_j\bigl((H_{i-1}\cup\{t\})\setminus\{m\}\bigr) = m_j(H_{i-1}\cup\{t\})$——删去最大元不影响「最小的 $j$ 个」（$j \le k = |H_{i-1}\cup\{t\}| - 1$）。

**情形 A：$T + t \le L$（不弹出）**。此时 $H_i = H_{i-1}\cup\{t\}$。(1) 把新课程放最后一位，$T + t \le L$，前面各前缀和不变，可行。(2) 任何可行 $S \subseteq \{1..i\}$ 去掉 $i$ 后是前 $i-1$ 门课的可行集合，故 $|S| \le k+1 = |H_i|$，而 $H_i$ 本身可行，故 $\mathrm{OPT}_i = k+1$。(3) 任何可行 $j$ 元集合或含 $i$ 或不含：不含时和 $\ge f_{i-1}(j) = m_j(H_{i-1})$；含 $i$ 时，余下 $j-1$ 门是前 $i-1$ 门课中的可行集合，和 $\ge f_{i-1}(j-1) = m_{j-1}(H_{i-1})$，且此时 $t + m_{j-1}(H_{i-1}) \le t + T \le L$ 保证「$j-1$ 门 + 第 $i$ 门」确实可行、等号可被取到。两式合起来正是式 (A)，故 $f_i(j) = m_j(H_i)$。

**情形 B：$T + t > L$（弹出 $m$）**。此时 $H_i = (H_{i-1}\cup\{t\})\setminus\{m\}$，$|H_i| = k$。(1) 删去一项只会让各前缀和不变或变小，故 $H_{i-1}$ 的其余元素仍各自不超期；新的总时长为 $T + t - m \le T \le L$（因为 $m \ge t$，且由归纳假设 (1) 与引理 1，$T \le L$），可行。(2) $H_{i-1}$ 已给出 $k$ 门，故 $\mathrm{OPT}_i \ge k$。若存在可行的 $k+1$ 元集合 $S$，则由 $\mathrm{OPT}_{i-1} = k$ 知 $S$ 必含第 $i$ 门，于是 $S \setminus \{i\}$ 是前 $i-1$ 门课中的可行 $k$ 元集合，$\sum S \ge T + t > L$；但由引理 1，可行集合的总时长不超过其最大截止时间 $\le L$，矛盾。故 $\mathrm{OPT}_i = k$。(3) 对 $j \le k$，由式 (A) 与归纳假设，$f_i(j)$ 只可能取 $m_j(H_{i-1})$ 或 $t + m_{j-1}(H_{i-1})$ 中较小的那个，即 $m_j(H_{i-1}\cup\{t\})$：若取前者，它由前 $i-1$ 门课中的可行 $j$ 元集合取到，不需第 $i$ 门；若取后者，则 $t + m_{j-1}(H_{i-1}) \le m_j(H_{i-1}) \le T$，于是 $t + m_{j-1}(H_{i-1}) \le L$，「取到 $m_{j-1}(H_{i-1})$ 的可行集合 + 第 $i$ 门」可行，等号同样可被取到。对 $j = k$ 还需补一句：因为 $m = \max(H_{i-1}\cup\{t\})$，恒有 $T + t - m = \min\bigl(T,\ t + m_{k-1}(H_{i-1})\bigr)$（若 $m = t$ 则左边 $=T \le t + m_{k-1}$；若 $m = \max(H_{i-1})$ 则左边 $= t + m_{k-1} \le T$），即 $m_k(H_i) = m_k(H_{i-1}\cup\{t\})$。结合式 (B) 得 $f_i(j) = m_j(H_i)$。∎

**定理**：算法返回的堆大小 $|H_n|$ 等于最多可修课程数。

**证明**：由引理 2 的性质 (2)，$|H_n| = \mathrm{OPT}_n$，而 $\mathrm{OPT}_n$ 的定义正是「前 $n$ 门课（即全部课程）中可行集合的最大大小」，也就是题目所求的最大修课数。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；随后每门课做一次入堆（$O(\log n)$），至多一次出堆（$O(\log n)$），共 $O(n \log n)$。
- **空间**：$O(n)$。大顶堆最坏存下全部 $n$ 门课的时长；排序本身的额外空间为 $O(\log n)$（原地排序的栈开销）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <queue>
using namespace std;

class Solution {
public:
    int scheduleCourse(vector<vector<int>>& courses) {
        sort(courses.begin(), courses.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });
        priority_queue<int> pq;            // 大顶堆：已选课程的时长
        long long total = 0;               // 已选课程总时长 = 当前时间
        for (const auto& c : courses) {
            total += c[0];
            pq.push(c[0]);                 // 先无条件收下
            if (total > c[1]) {            // 超期，踢掉时长最长的那门
                total -= pq.top();
                pq.pop();
            }
        }
        return (int)pq.size();
    }
};
```

### Python

```python
import heapq
from typing import List

class Solution:
    def scheduleCourse(self, courses: List[List[int]]) -> int:
        courses.sort(key=lambda c: c[1])   # 按截止时间升序
        heap = []                          # 大顶堆（存负数）：已选课程的时长
        total = 0                          # 已选课程总时长 = 当前时间
        for d, last in courses:
            total += d
            heapq.heappush(heap, -d)       # 先无条件收下
            if total > last:               # 超期，踢掉时长最长的那门
                total += heapq.heappop(heap)   # 弹出的是负值，等价于 total -= max
        return len(heap)
```

## 8. 边界情况与易错点

1. **一门都修不完**：`[[3,2],[4,3]]` 应返回 0。此时每门课都会「入堆后立刻被自己弹出」，堆最终为空——注意弹出时堆必须非空，所以顺序上要先 `push` 再判断。
2. **`total == last` 合法**：题目要求「不晚于」，用 `>` 触发弹出。若写成 `>=`，`[[2,3],[1,3]]` 会返回 1（第 2 步把 2 弹出），而正确答案是 2（两天正好排满，第 3 天结束）；`[[1,1]]` 更极端，会返回 0。
3. **单门课 $d_i > last_i$**：如 `[[100,1]]`，返回 0；这是「反悔」发生在同一门课上的特例，逻辑无需特判。
4. **相同截止时间**：如 `[[2,6],[1,6],[3,6]]`，排序顺序任意都不影响答案（同一截止时间下这些课互相可交换），不需要用 $d$ 作次关键字。
5. **Python 的负数堆**：`heapq` 是小顶堆，`heappop` 拿到的是 $-d_{\max}$，所以是 `total += heappop(heap)`；写成 `total -= heappop(heap)` 会把总时长越加越大，是本题最常见的 WA。
6. **误用 `while` 或多弹**：超期后弹一次即可（理由见 §4 第 3 条）。写 `while total > last` 虽然结果也对，但会让人误以为需要多次调整，且多判定一次。
7. **只按总时长比较，不要真的维护时间轴**：把「第几天上哪门课」模拟出来既没必要（可能一天都不能空），也会让复杂度退化；本题只关心「能不能塞下」。
8. **答案与编号顺序无关**：示例 1 的修课顺序是 1 → 3 → 2，不是 1 → 2 → 3；不要假设必须按输入顺序修。
