# LeetCode 设计 Excel 求和公式 题解

## 1. 题目概述

- **标题 / 题号**：设计 Excel 求和公式（#631，hard）
- **链接**：https://leetcode.cn/problems/design-excel-sum-formula/
- **来源**：LeetCode 第 38 场周赛 Q4
- **难度**：困难
- **标签**：图、设计、拓扑排序、数组、哈希表、字符串、矩阵

**题意**：维护一张 $H \times W$ 的表格（行号 $1 \sim H$，列号 `'A' ~ W`），每个格子要么是**常数**，要么挂着一条**求和公式**：`set(row, column, val)` 写入常数并让原公式**立即失效**；`get(row, column)` 返回该格当前值（公式格按依赖实时算）；`sum(row, column, numbers)` 把「`numbers` 中所有格子之和」挂到该格上并返回当前结果，公式一直有效，直到该格被 `set` 或新的 `sum` 覆盖。

`numbers` 的每一项是 `"F7"`（单格）或 `"A1:B2"`（左上角:右下角的矩形）。**同一格被引用几次就要加几次**。

**约束**：

- $1 \le H \le 26$，`'A' ≤ W ≤ 'Z'`，即单元格总数 $V = H \times W \le 676$
- 引用形如 `列字母 + 行数字`，区间用 `:` 连接两个角
- **不会出现循环求和引用**（如 `A1 = sum(B1)` 且 `B1 = sum(A1)`）
- 多个测试用例复用同一个类，类级变量会被保留 → 必须在构造函数里初始化

## 2. 示例

**示例 1（官方示例）**
```text
Excel(3, "C")                        // 3×3 表格，全 0
Set(1, "A", 2)                       // A1 = 2
Sum(3, "C", ["A1", "A1:B2"]) → 4     // C3 = A1 + (A1+B1+A2+B2) = 2 + 2 = 4
Set(2, "B", 2)                       // B2 = 2，C3 依赖它，必须跟着变
Get(3, "C") → 6                      // 2 + (2+0+0+2) = 6
```

**示例 2（补充：重复引用与公式覆盖）**
```text
Excel(2, "B"); Set(1, "A", 5)
Sum(2, "B", ["A1", "A1"]) → 10       // 同一格写两次 = 加两遍，不是 5
Set(1, "A", 7); Get(2, "B") → 14

Excel(3, "C"); Set(1, "A", 1); Set(1, "B", 2)
Sum(1, "C", ["A1:B1"]) → 3           // C1 = 1 + 2
Sum(2, "C", ["C1", "A1:A2"]) → 4     // C2 = C1 + (A1+A2) = 3 + 1
Set(1, "C", 100); Get(2, "C") → 101  // C1 变常数，C2 = 100 + 1，不是 3 + 1
```

## 3. 解题思路

### 3.1 暴力思路

三种典型写法，前两种直接错、第三种复杂度爆炸：

1. **快照法（错）**：`sum` 时把算出的数字存进格子，之后 `get` 直接返回。示例 1 里 `Set(2,"B",2)` 之后 `C3` 仍返回 4（正确值是 6）——公式必须**持续生效**，不能退化成常数。
2. **全表反复重算（能过但笨）**：每次查询把所有公式格重算一遍，循环 $V$ 轮收敛到不动点，单次 $O(V \cdot E)$；$V \le 676$ 时勉强可行，但完全没利用图结构。
3. **无记忆化递归（错复杂度）**：每次 `get` 顺着公式定义递归展开，遇到「菱形依赖」（两条公式引自同一格）时同一子表达式被反复展开，最坏 $O(2^{V})$。

### 3.2 核心观察：依赖图是一张 DAG

![公式格与它引用的每一个格子构成一张无环依赖图](images/wc38_q4_dependency_graph.svg)

把每个格子看成一个节点，公式格向**它引用的每一个格子**连有向边（区间先展开成单格）。题意保证不会循环引用，于是：

> **核心观察**：这张依赖图是一张**有向无环图（DAG）**，求值就是在这张图上按拓扑序自底向上做一次「后缀和」。

因此「递归 + 记忆化」就是拓扑序求值：第一次访问某格时递归求它的全部引用，算完标记 `state=2`，同一次查询里再遇到直接返回缓存，每格每边只走一次；而重复引用天然正确——`deps` 用 `vector` 而不是 `set`，同一格出现几次就加几次（示例 1 的 `A1`、示例 2 的 `["A1","A1"]` 都无需特判）。另外，`Set` 只改常数并清空该格公式，**不必主动通知别人**：下次 `Get` 沿图重算时自然读到新值。

### 3.3 算法流程

![算法流程：解析 numbers → 建立依赖边 → 记忆化 DFS 求值](images/wc38_q4_eval_flow.svg)

数据结构（$V = H\times W$）：`val[V]` 存常数，公式格则借它缓存**本次查询内**的结果；`isFormula[V]` 标记是否挂公式；`deps[V]` 存引用 id 列表（**可重复**）；`state[V]` 取 `0` 未访问、`1` 在递归栈上、`2` 已完成。

流程：

1. `sum(r, c, numbers)` 把每项展开成 id 列表写入 `deps[c]`、`isFormula[c] = 1`，再调用 `dfs(c)`；`get(r, c)` 也走 `dfs(c)`；
2. `dfs(x)`：**每次外部调用前把 `state` 整体清零**；DFS 内常数格返回 `val[x]`，`state[x] == 2` 返回缓存，否则置 `state[x] = 1`，累加 `deps[x]` 中每个引用的递归结果，写回 `val[x]` 并置 `state[x] = 2`。

坐标映射一行搞定：$\text{id} = (row-1)\times W + (column - \text{'A'})$。

### 3.4 示例演算

![官方示例三步走查：A1=2 → C3 挂公式得 4 → B2=2 让 C3 变 6](images/wc38_q4_example_walkthrough.svg)

| 步骤 | 操作 | 结构变化 | `Get(3,"C")` |
| --- | --- | --- | --- |
| 1 | `Set(1,"A",2)` | A1 变成常数 2 | — |
| 2 | `Sum(3,"C",["A1","A1:B2"])` | `deps[C3] = [A1, A1, B1, A2, B2]`（A1 两次） | 4 |
| 3 | `Set(2,"B",2)` | B2 变成常数 2，C3 的引用列表一字未改 | 6 |

即 $C_3 = A_1 + (A_1 + B_1 + A_2 + B_2)$：第 2 步 $2 + (2+0+0+0) = 4$，第 3 步 $2 + (2+0+0+2) = 6$。B2 一变 C3 就算出新值，因为**公式存的是引用，不是快照**。

## 4. 算法细节

1. **行列方向别写反**：`"F7"` 是 F 列第 7 行；`column` 参数是字符，行参数是 1-based 整数。
2. **解析器**：先收集列字母（本题宽度 $\le$ `'Z'`，按 26 进制多字母写更通用），剩余部分转行号；区间按 `':'` 切两半。
3. **区间展开**：二重循环枚举行、列并取 `min/max`（题面保证左上→右下，容错写法更稳），最多展开 $H \times W$ 个 id。
4. **重复引用要重复计数**：`deps` 必须是 `vector` 而非 `set`；`"A1"` 与 `"A1:B2"` 同时出现时 `A1` 计 2 次，这正是示例 1 的答案来源。
5. **缓存只在单次查询内有效**：公式格会把结果写进 `val`，跨操作复用就会返回过期值；每次 `get` / `sum` 前清空 `state`（$O(V)$），追求极致可用 `epoch` 时间戳降到 $O(1)$。
6. **`Set` 要彻底作废公式**：同时 `deps[c].clear()` 与 `isFormula[c] = 0`，否则该格还会被当公式重算（示例 2 的 101 会变回 4）；`state[x] == 1` 命中时返回 0 可防死递归（题面保证无环，仅兜底）。
7. **数值与深度**：长链求和会线性放大数值，C++ 用 `long long` 累加再转 `int`；依赖链最长 $V = 676$ 层，Python 建议 `sys.setrecursionlimit(10000)`。

## 5. 正确性证明

**引理 1（求值可终止）**：依赖图无环，故 `dfs` 递归深度不超过 $V$，每个格子在同一次查询中最多被完整计算一次。

**证明**：若某次递归沿依赖边回到自身，则存在有向环，与「不会出现循环求和引用」矛盾；每次完整计算后置 `state = 2`，之后命中缓存直接返回。∎

**引理 2（单格求值正确）**：对任意时刻的公式定义，`dfs(x)` 返回的值等于「把 $x$ 的公式完全展开成常数格之和」的语义值。

**证明**：对 $x$ 可达依赖子图的最长路径长度归纳。$x$ 为常数格时返回 `val[x]`，正确；$x$ 为公式格时，每个引用 $y$ 的最长路径严格更短（无环），由归纳假设 `dfs(y)` 正确，而 `deps[x]` 按 `numbers` 展开且保留重复，累加即公式语义值。记忆化只改变「何时计算」，同一查询内结构不变，故返回值不变。∎

**引理 3（缓存不污染后续操作）**：任意一次 `get` / `sum` 的求值只依赖当前的 `deps` / `val` 结构，不受此前查询的中间结果影响。

**证明**：进入外部操作前 `state` 全部归零，`state == 2` 的命中不可能发生，每个被访问的公式格都基于当前结构重新计算；常数格由 `Set` 直接写入，与历史无关。∎

**定理**：三类操作的行为均与题意一致。

**证明**：`Set` 写入常数并清空公式，符合「公式持续到被覆盖」；`Sum` 返回 `dfs(c)`，由引理 2、3 等于按当前定义的和；`Get` 同理。∎

## 6. 复杂度分析

- **时间**：`Set` 为 $O(1)$ 加清空 `deps`；`Sum` 为解析 $O(\lvert numbers\rvert + \text{展开格数})$ 加一次求值；`Get` 为一次求值。一次求值遍历 $x$ 可达子图，每格、每条依赖边各访问一次，为 $O(V + E)$，其中 $E$ 为所有公式展开后的引用总数，最坏 $E \le V^2$。
- **空间**：$O(V + E)$；`val`、`state`、`isFormula` 各 $O(V)$，`deps` 合计 $O(E)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <string>
#include <algorithm>
#include <cctype>
using namespace std;

class Excel {
    int W, n;
    vector<long long> val;            // 常数 / 本次查询的公式缓存
    vector<vector<int>> deps;         // 引用 id 列表（可重复）
    vector<char> isFormula, state;    // 是否挂公式；state: 0 / 1 在栈上 / 2 完成
    int id(int r, char c) const { return (r - 1) * W + (c - 'A'); }

    static pair<int, int> parseCell(const string &s) {     // "F7" -> (7, 5)
        int i = 0, col = 0;
        while (i < (int)s.size() && isalpha((unsigned char)s[i]))
            col = col * 26 + (toupper(s[i++]) - 'A' + 1);
        return {stoi(s.substr(i)), col - 1};
    }
    void expand(const string &s, vector<int> &out) const {
        size_t p = s.find(':');
        if (p == string::npos) { auto [r, c] = parseCell(s); out.push_back((r - 1) * W + c); return; }
        auto [r1, c1] = parseCell(s.substr(0, p));
        auto [r2, c2] = parseCell(s.substr(p + 1));
        for (int r = min(r1, r2); r <= max(r1, r2); ++r)
            for (int c = min(c1, c2); c <= max(c1, c2); ++c)
                out.push_back((r - 1) * W + c);           // 重复也照样压入
    }
    long long dfs(int x) {
        if (!isFormula[x]) return val[x];
        if (state[x] == 2) return val[x];   // 本次查询已算过
        if (state[x] == 1) return 0;        // 题面保证无环，仅作防御
        state[x] = 1;
        long long s = 0;
        for (int y : deps[x]) s += dfs(y);
        state[x] = 2;
        return val[x] = s;
    }

public:
    Excel(int height, char width) : W(width - 'A' + 1), n(height * W),
        val(n, 0), deps(n), isFormula(n, 0), state(n, 0) {}
    void set(int row, char column, int v) {
        int x = id(row, column);
        val[x] = v, deps[x].clear(), isFormula[x] = 0;    // 公式失效
    }
    int get(int row, char column) {
        fill(state.begin(), state.end(), 0);              // 结构已变，缓存作废
        return (int)dfs(id(row, column));
    }
    int sum(int row, char column, vector<string> numbers) {
        int x = id(row, column);
        deps[x].clear();
        for (const auto &s : numbers) expand(s, deps[x]);
        isFormula[x] = 1, val[x] = 0;
        fill(state.begin(), state.end(), 0);
        return (int)dfs(x);
    }
};
```

### Python

```python
class Excel:
    def __init__(self, height: int, width: str):
        self.W = ord(width) - ord('A') + 1
        n = height * self.W
        self.val = [0] * n            # 常数，或本次查询的公式缓存
        self.deps = [None] * n        # None = 常数格；否则为引用 id 列表（可重复）
        self.state = [0] * n          # 0 未访问 / 1 在栈上 / 2 已完成

    def _id(self, row, col):
        return (row - 1) * self.W + (ord(col) - ord('A'))

    @staticmethod
    def _parse(s):                    # "F7" -> (7, 5)
        i = next((k for k, ch in enumerate(s) if ch.isdigit()), len(s))
        col = 0
        for ch in s[:i]:
            col = col * 26 + (ord(ch) - ord('A') + 1)
        return int(s[i:]), col - 1

    def _expand(self, numbers):
        out = []
        for s in numbers:
            if ':' not in s:
                r, c = self._parse(s)
                out.append((r - 1) * self.W + c)
                continue
            a, b = s.split(':')
            (r1, c1), (r2, c2) = self._parse(a), self._parse(b)
            for r in range(min(r1, r2), max(r1, r2) + 1):
                for c in range(min(c1, c2), max(c1, c2) + 1):
                    out.append((r - 1) * self.W + c)         # 重复也保留
        return out

    def set(self, row, column, val):
        i = self._id(row, column)
        self.val[i], self.deps[i] = val, None                # 公式立即失效

    def get(self, row, column):
        self.state = [0] * len(self.state)                   # 缓存只在单次查询内有效
        return self._dfs(self._id(row, column))

    def sum(self, row, column, numbers):
        i = self._id(row, column)
        self.deps[i], self.val[i] = self._expand(numbers), 0
        self.state = [0] * len(self.state)
        return self._dfs(i)

    def _dfs(self, i):
        if self.deps[i] is None:
            return self.val[i]
        if self.state[i] == 2:
            return self.val[i]
        if self.state[i] == 1:
            return 0                         # 题面保证无环，仅作防御
        self.state[i] = 1
        self.val[i] = 0
        for j in self.deps[i]:
            self.val[i] += self._dfs(j)
        self.state[i] = 2
        return self.val[i]
```

## 8. 边界情况与易错点

1. **把 `sum` 的结果当常数存下**：示例 1 的 `Get(3,"C")` 会返回 4 而不是 6；公式必须保留依赖边，惰性求值。
2. **重复引用被去重**：`["A1","A1"]` 或 `"A1"` 与 `"A1:B2"` 并存时，用 `set` 存引用会少算（示例 2 期望 10 和 14）。
3. **`Set` 没清掉旧公式**：只改 `val` 不清 `deps`，该格仍会被当公式格重算，示例 2 的 `Get(2,"C")` 会错成 4；跨查询复用缓存同样会读到过期值。
4. **行列写反**：`"F7"` 是 `(row=7, column='F')`；`Excel(3,"C")` 的合法行是 1~3、合法列是 `'A'~'C'`。
5. **区间端点顺序**：题面保证左上/右下，但仍建议取 `min/max`，避免反写导致展开为空。
6. **类级变量残留**：多个测试用例复用同一个类，数组必须在构造函数里初始化，不要用 `static` 或类属性缓存。
7. **递归深度与溢出**：链式公式可达 676 层；长链求和数值会放大，C++ 需 `long long` 累加。
