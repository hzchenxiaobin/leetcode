# LeetCode 出现次数能被 K 整除的元素总和 题解

## 1. 题目概述

- **标题 / 题号**：出现次数能被 K 整除的元素总和（#3712，easy）
- **链接**：https://leetcode.cn/problems/sum-of-elements-with-frequency-divisible-by-k/
- **来源**：LeetCode 第 471 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums` 与整数 `k`，返回其中所有**出现次数能被 `k` 整除**的元素之和；命中元素在求和中被计算**恰好与其出现次数相同的次数**（即贡献为 $x \times \mathrm{cnt}(x)$），若无命中元素则返回 $0$。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 100$
- $1 \le k \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,3,3,3,3,4], k = 2
输出：16
解释：2 出现 2 次、3 出现 4 次（均为偶数次），计入 2+2+3+3+3+3 = 16；
     1 和 4 各出现 1 次（奇数次），不计入。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5], k = 2
输出：0
解释：所有元素都只出现 1 次，没有出现偶数次的元素，返回 0。
```

**示例 3**

```text
输入：nums = [4,4,4,1,2,3], k = 3
输出：12
解释：4 出现 3 次，3 能被 3 整除，贡献 4+4+4 = 12；其余元素各出现 1 次，不计入。
```

**补充示例**

```text
输入：nums = [2,3,3], k = 1
输出：8
解释：k = 1 时任何出现次数都能被 1 整除，全部元素命中，答案退化为数组总和。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是双重循环：外层枚举每个**首次出现**的元素 $x$，内层重扫一遍 `nums` 统计其出现次数 $c$，若 $c \bmod k = 0$ 则累加 $x \times c$。正确性没问题，但每个值的次数被重复数了多遍，时间 $O(n^2)$；本题 $n \le 100$ 勉强能过，却不是该沉淀的写法。

> ⚠️ 签到题真正的坑不在复杂度而在**审题**：把「计算恰好与其出现次数相同的次数」错读成「每个命中值只加一次」（去重和），示例 1 会算出 $2 + 3 = 5$ 而非 $16$；把「出现次数能被 $k$ 整除」错读成「元素值能被 $k$ 整除」，示例 3 会漏掉 $4$。先过这两道审题关，再谈算法。

### 3.2 核心观察：定长计数桶 + 贡献乘回次数

![核心观察：判定看次数，贡献 = 值 × 次数](images/freq_div_k_bucket_concept.svg)

三个关键观察：

1. **值域 $1 \sim 100$ 小而稠密，定长数组就是最优哈希表**：开一个 `cnt[101]`，一趟扫描 `cnt[x]++` 完成全部统计，零哈希开销。
2. **判定与加权用的是同一份数据**：计数完成后对每个桶判定 $\mathrm{cnt}(x) \bmod k = 0$，命中者贡献 $x \times \mathrm{cnt}(x)$——次数存在桶里，乘回来零成本。这是「统计 → 过滤 → 按频次加权」骨架的最小实例。
3. **空桶天然无害**：扫描值域时未出现的值满足 $0 \bmod k = 0$，看似被「误命中」，但其贡献 $x \times 0 = 0$，对和式毫无影响——本题恰好宽容（见第 8 节的变体讨论）。

> 💡 一句话：本题 = 一趟入桶 + `cnt % k == 0` 则累加 $x \cdot \mathrm{cnt}(x)$。

### 3.3 算法流程

![算法流程：一趟入桶 + 一趟过滤加权](images/freq_div_k_flow.svg)

两趟线性扫描，伪代码：

```text
cnt[0..100] = 0, ans = 0
for x in nums:            # 第一趟：入桶统计，O(n)
    cnt[x] += 1
for x in 1..100:          # 第二趟：逐桶判定 + 加权，O(100)
    if cnt[x] % k == 0:
        ans += x * cnt[x]
return ans
```

### 3.4 示例演算

![示例演算：入桶、判定与加权走查](images/freq_div_k_walkthrough.svg)

**示例 1（$k = 2$，答案 16）**：

| $x$ | $\mathrm{cnt}[x]$ | $\mathrm{cnt} \bmod 2$ | 判定 | 贡献 |
|-----|------------------|----------------------|------|------|
| 1 | 1 | 1 | ✗ | 0 |
| 2 | 2 | 0 | ✓ | $2 \times 2 = 4$ |
| 3 | 4 | 0 | ✓ | $3 \times 4 = 12$ |
| 4 | 1 | 1 | ✗ | 0 |

累加 $4 + 12 = 16$。

**示例 3（$k = 3$，答案 12）**：只有 $4$ 的次数 $3$ 满足 $3 \bmod 3 = 0$，贡献 $4 \times 3 = 12$——注意 $4$ 这个**值**并不能被 $3$ 整除，判定对象始终是**次数**。

**边界情形**：$k = 1$ 时全部桶命中，答案 = 数组总和；所有元素互异且 $k \ge 2$ 时（示例 2）无桶命中，答案为 $0$。

## 4. 算法细节

1. **数据结构选择**：值域 $1 \sim 100$ 稠密，用定长数组 `cnt[101]`（下标 $0$ 弃用，天然避开「元素值 $\ge 1$」的下标偏移）；值域大而稀疏或含负数时换 `unordered_map` / `Counter`，并改为**只遍历出现过的键**。
2. **贡献式求和**：$\text{ans} = \sum_{x :\, k \mid \mathrm{cnt}(x)} x \cdot \mathrm{cnt}(x)$。判定条件（次数的整除性）与加权项（乘回次数）是两个独立旋钮，不要混淆。
3. **$k = 1$ 的退化**：任何正次数都能被 $1$ 整除，所有出现过的桶全部命中，答案即 $\sum \text{nums}$——可作免费自测用例。
4. **溢出分析**：$n \le 100$、$\text{nums}[i] \le 100$，答案上界 $100 \times 100 = 10^4$，`int` 毫无压力。
5. **空桶处理**：第二趟扫全值域时 `cnt[x] = 0` 的桶满足 `0 % k == 0` 会被「命中」，但累加的是 $x \times 0 = 0$，无需特判；若想彻底回避，可遍历哈希表键集。

## 5. 正确性证明

**引理 1（计数正确性）**：一趟扫描后，对每个 $x \in [1, 100]$，`cnt[x]` 恰等于 $x$ 在 `nums` 中的出现次数 $\mathrm{cnt}(x)$。

**证明**：对已处理元素个数 $i$ 归纳。$i = 0$ 时 `cnt` 全零，成立。设处理前 $i$ 个元素后结论成立；处理第 $i+1$ 个元素时，设其值为 $v$，算法仅执行 `cnt[v] += 1`，其余桶不变，故处理后每个桶恰等于前 $i+1$ 个元素中该值的出现次数。扫描完全部 $n$ 个元素即得引理。∎

**引理 2（贡献分解）**：所求答案 $= \sum_{x :\, k \mid \mathrm{cnt}(x)} x \cdot \mathrm{cnt}(x)$。

**证明**：题设规定命中元素「被计算恰好与其出现次数相同的次数」，即在总和中贡献 $\mathrm{cnt}(x)$ 个 $x$，合计 $x \cdot \mathrm{cnt}(x)$；未命中元素贡献 $0$。将总和按元素值分组：同值元素的贡献合并为同一项，不同值的项互不干扰，故总和等于各命中值的 $x \cdot \mathrm{cnt}(x)$ 之和。∎

**定理**：上述算法返回所求答案。

**证明**：由约束 $\text{nums}[i] \in [1, 100]$，值域扫描 $1 \sim 100$ 覆盖所有可能取到的值。由引理 1，第二趟扫描中每个 `cnt[x]` 均为真实出现次数；算法对每个 $x$ 判定 $k \mid \mathrm{cnt}(x)$，命中则累加 $x \cdot \mathrm{cnt}(x)$，与引理 2 的和式逐项一致。对未出现的值 $x$，`cnt[x] = 0` 虽满足 $k \mid 0$ 而被「命中」，但其项 $x \cdot 0 = 0$ 不改变和式的值。故算法输出等于所求答案；特别地，无命中元素时输出 $0$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + D)$，其中 $D = 100$ 为值域宽度——入桶一趟 $O(n)$，逐桶判定加权一趟 $O(D)$，均为线性扫描。
- **空间复杂度**：$O(D)$——定长 $101$ 个计数桶与常数个变量，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int sumDivisibleByK(vector<int>& nums, int k) {
        int cnt[101] = {0};
        for (int x : nums) cnt[x]++;
        int ans = 0;
        for (int x = 1; x <= 100; ++x) {
            if (cnt[x] % k == 0) {
                ans += x * cnt[x];
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def sumDivisibleByK(self, nums: List[int], k: int) -> int:
        cnt = [0] * 101
        for x in nums:
            cnt[x] += 1
        return sum(x * cnt[x] for x in range(1, 101) if cnt[x] % k == 0)
```

> 💡 Python 亦可用 `collections.Counter`：`sum(x * c for x, c in Counter(nums).items() if c % k == 0)`，键集天然只含出现过的元素，空桶问题彻底消失。

## 8. 边界情况与易错点

1. **判定对象是「次数」不是「值」**：示例 3 中值 $4$ 不被 $3$ 整除，但其次数 $3$ 能，照样入选；反过来值能被 $k$ 整除但次数不能的元素（如示例 1 中的 $4$，$4 \bmod 2 = 0$ 但次数 $1$ 为奇）不计入。
2. **贡献必须乘回次数**：写成去重和（每个命中值只加一次）是最典型的 WA，示例 1 会得到 $5$ 而非 $16$。
3. **$k = 1$ 退化**：所有元素命中，答案 = 数组总和，可用 `sum(nums)` 对拍验证判定条件没写反。
4. **空桶的假阳性命中**：`0 % k == 0` 使未出现元素被「命中」，但贡献为 $0$，求和题无害；**若变体题改统计满足条件的元素种类数，全值域遍历会把没出现的值全数进去而翻车**，必须改为遍历出现过的键。
5. **无命中返回 0**：`ans` 初始为 $0$ 且只增不改，无需特判。
6. **桶大小与下标**：值域含端点 $100$，桶开 $101$；元素值 $\ge 1$，下标 $0$ 恒为空桶（且贡献 $0$），弃用即可。
