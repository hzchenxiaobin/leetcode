# LeetCode 链表组件 题解

## 1. 题目概述

- **标题 / 题号**：链表组件（#817，medium）
- **链接**：https://leetcode.cn/problems/linked-list-components/
- **来源**：LeetCode 第 80 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、链表

**题意**：给定一个节点值互不相同的单链表 `head`，以及一个整数数组 `nums`——它是链表值的一个子集。把「值都属于 `nums` 的连续节点段」中**极大**的那些段称为组件：段内每个节点的值都在 `nums` 中，且这一段不能再向左右延展（左邻、右邻要么不存在，要么值不在 `nums` 里）。求组件的个数。

因为值互不相同，「节点的值是否在 `nums` 中」就是对每个节点打的一个布尔标记。于是题目等价于：**在链表上数「标记序列里有多少个极大的全 `nums` 连续段」**，与节点的具体数值无关，只看集合成员关系。

**约束**：

- 节点数 $1 \le n \le 10^4$
- $0 \le \text{Node.val} < n$，所有 `Node.val` **互不相同**
- $1 \le \lvert \text{nums} \rvert \le n$，$0 \le \text{nums}[i] < n$，`nums` 内元素**互不相同**
- `nums` 是链表值的子集，所以每个 `nums[i]` 恰好命中一个节点

## 2. 示例

**示例 1**

```text
输入：head = [0,1,2,3]，nums = [0,1,3]
输出：2
解释：0 与 1 相邻且都在 nums 中 → 组件 [0,1]；
      2 不在 nums 中，把链表断开；3 单独成组件 [3]。共 2 个。
```

**示例 2**

```text
输入：head = [0,1,2,3,4]，nums = [0,3,1,4]
输出：2
解释：0、1 相邻都在 nums 中 → [0,1]；3、4 相邻都在 nums 中 → [3,4]；
      2 是它们之间的「断点」。注意 nums 的书写顺序与链表顺序无关。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的想法是「数组件的**起点**」：它的值在 `nums` 中，且它的**前驱**不存在或前驱值不在 `nums` 中。

麻烦在于单链表**没有前驱指针**。为拿到前驱，只有三种笨办法：

1. 对每个节点都从头遍历一次找前驱：$O(n^2)$，$n = 10^4$ 时最坏约 $10^8$ 次指针跳转——C++ 里勉强能过、Python 里必超时，而且这些跳转没有任何信息增量；
2. 先开一个「值 → 前驱值」的映射（或把链表拍平成数组）再扫描：正确，但等于先复制一遍链表，$O(n)$ 额外空间；
3. 把相邻且都属于 `nums` 的节点对用并查集合并，最后数根的个数：正确，但要为「只数几段」这种简单问题写一份 $O(n)$ 的并查集。

这些做法的共同根源是：**把「段首」当成了唯一的计数入口**。

### 3.2 核心观察：数「段尾」，只看后继

![组件 = 值属于 nums 的极大连续段](images/wc80_q2_component_model.svg)

一个组件有两个端点：**段首**（前驱不在 `nums` 中）与**段尾**（后继不在 `nums` 中）。在一条链上，段首与段尾**一一配对**——每个组件恰好一进一出，所以

$$\text{段首个数} = \text{段尾个数} = \text{组件个数}$$

而这两种口径在单向链表上的代价完全不同：

| 口径 | 需要的邻居 | 单向链表是否可访问 |
| --- | --- | --- |
| 段首 | **前驱** `prev` | ✗ 需要额外指针或重扫 |
| 段尾 | **后继** `next` | ✓ `cur.next` 直接可读 |

于是把计数改写成

$$\text{ans} = \#\Bigl\{\, cur \ \Bigm|\ cur.\text{val} \in S \ \wedge\ \bigl(cur.\text{next} = \varnothing \ \vee\ cur.\text{next}.\text{val} \notin S\bigr) \Bigr\},\qquad S = \text{set}(\text{nums})$$

就一次性摆脱了对前驱的依赖，一趟正向遍历就能出答案。

> 💡 **一句话记住**：组件数 = 进入全 `nums` 段的次数 = 离开全 `nums` 段的次数；单向链表只能看「离开」，那就数离开。

### 3.3 算法流程

![一遍扫描：只看当前节点与后继](images/wc80_q2_scan_flow.svg)

1. 把 `nums` 的全部元素放进哈希集合 $S$，耗时 $O(\lvert nums \rvert)$；
2. 初始化 `ans = 0`、`cur = head`；
3. 只要 `cur` 非空就检查：若 `cur.val ∈ S`，且 `cur.next` 为空**或** `cur.next.val ∉ S`，则 `ans += 1`；
4. 令 `cur = cur.next` 继续，直到 `cur` 为空，返回 `ans`。

整个过程**只读不写**：没有 `prev`、没有反转、没有额外链表，原链表遍历结束后保持原样。

### 3.4 示例演算

![示例演算：head = [0,1,2,3,4]，nums = [0,3,1,4]](images/wc80_q2_walkthrough.svg)

对示例 2 逐节点走一遍（$S = \{0,1,3,4\}$）：

| $i$ | `val` | `val ∈ S` | `next.val` | `next ∈ S` | 是否计入 |
| --- | --- | --- | --- | --- | --- |
| 0 | 0 | 是 | 1 | 是 | 否 |
| 1 | 1 | 是 | 2 | 否 | **是**（`ans` = 1） |
| 2 | 2 | 否 | 3 | 是 | 否 |
| 3 | 3 | 是 | 4 | 是 | 否 |
| 4 | 4 | 是 | 尾节点 | — | **是**（`ans` = 2） |

结论 `ans = 2`，与官方输出一致。特别注意 $i = 4$：它是**尾节点**，没有后继，因此必须按段尾计数——这正是「先判 `cur.next` 是否为空」的意义。

## 4. 算法细节

1. **用集合而不是排序/二分**：`nums` 与链表值的对应关系是「成员判定」，不是「大小关系」，哈希集合均摊 $O(1)$ 比排序后二分（$O(\lvert nums \rvert \log \lvert nums \rvert)$ + 每步 $O(\log n)$）更直接。
2. **判定顺序不能换**：必须先判 `cur` 是否在集合中，再判后继；必须先用 `cur.next` 判空，再访问 `cur.next.val`。C++ 里 `!cur->next || !present.count(cur->next->val)` 依赖 `||` 的短路求值，把两个条件写反会直接段错误。
3. **Python 习惯写法**：`cur.next is None or cur.next.val not in present`，同样依赖短路；不要写 `cur.next.val not in present or cur.next is None`。
4. **值域很小时可用布尔数组**：约束里 $0 \le \text{Node.val} < n$，理论上可开 `vector<char> in(n)`，查询更快也几乎不占内存；但哈希集合在值域未知或更大时更通用，本题两种都能过。
5. **不需要 `prev`、也不需要反转链表**：反转会在数完段首后留下一条被破坏的链表，若外层复用 `head` 会出错；本解法全程只读。
6. **计数只增不减**：每个节点最多让 `ans` 加一次，不存在回退，所以一趟扫描即可，无需二次遍历。
7. **提前退化的情形**：若 `nums` 为空（题目约束下不会出现），答案应为 0；代码天然返回 0，因为没有任何节点能进入判定。

## 5. 正确性证明

**引理 1（每个组件都贡献一个段尾）**：设 $C$ 是从节点 $a$ 到节点 $b$ 的一段连续节点，且 $C$ 是组件。则 $b.\text{val} \in S$，并且 $b.\text{next}$ 为空或 $b.\text{next}.\text{val} \notin S$。

**证明**：组件内所有节点的值都属于 $S$，故 $b.\text{val} \in S$。若 $b$ 不是链表尾节点，则 $b.\text{next}$ 存在；由极大性，$b.\text{next}.\text{val} \notin S$，否则 $C \cup \{b.\text{next}\}$ 仍是全 $S$ 的连续段，与 $C$ 极大矛盾。故两种情形下判定条件都成立。∎

**引理 2（被计数的节点恰是某个组件的段尾）**：若节点 $v$ 被算法计数，则 $v$ 是它所在组件的最后一个节点。

**证明**：$v$ 被计数意味着 $v.\text{val} \in S$，且 $v$ 的后继不存在或其后继值不在 $S$。因此「以 $v$ 结尾、值全属于 $S$ 的连续节点段」无法把 $v.\text{next}$ 也包含进来；把向左方向上一切与之相连的全 $S$ 节点都并进来，得到一个以 $v$ 为末节点的极大连续段，它正是 $v$ 所在的组件。故 $v$ 是这个组件的段尾。∎

**引理 3（段尾映射是单射）**：不同组件不可能共享同一个段尾。

**证明**：段尾是它所在组件中位置最靠后的节点；一个节点只属于一个组件（组件的极大连续段两两不交），故不同组件的段尾必是不同节点。∎

**定理**：算法返回的 `ans` 等于组件个数 $k$。

**证明**：设组件集合为 $\mathcal{C}$，$\lvert \mathcal{C} \rvert = k$。

- 由引理 1，每个组件都提供一个满足判定条件的节点，且由引理 3 这些节点互不相同，因此 `ans` $\ge k$；
- 由引理 2 与引理 3，每个被计数的节点都是某个组件的段尾，而每个组件只有一个段尾，因此 `ans` $\le k$。

两边夹逼，得 `ans` $= k$。∎

## 6. 复杂度分析

- **时间**：$O(n + \lvert nums \rvert) = O(n)$。建集合 $O(\lvert nums \rvert)$；链表只遍历一遍，每个节点做至多两次哈希查询，均摊 $O(1)$；$n \le 10^4$ 时总操作量在 $10^4$ 量级。
- **空间**：$O(\lvert nums \rvert) \le O(n)$，全部开销来自哈希集合；遍历本身只用 `cur`、`ans` 两个变量。若改用布尔数组，空间固定为 $O(n)$。
- **对比**：并查集做法 $O(n\,\alpha(n))$ 时间、$O(n)$ 空间，常数更大；本解法已是线性下界——必须至少读一遍链表才能知道哪些值出现。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
using namespace std;

class Solution {
public:
    int numComponents(ListNode* head, vector<int>& nums) {
        unordered_set<int> present(nums.begin(), nums.end());
        int ans = 0;
        for (ListNode* cur = head; cur; cur = cur->next) {
            // 属于 nums，且后继不存在或后继不属于 nums → 这是一段的段尾
            if (present.count(cur->val) &&
                (!cur->next || !present.count(cur->next->val))) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numComponents(self, head: ListNode | None, nums: list[int]) -> int:
        present = set(nums)          # 哈希集合：成员判定 O(1)
        ans = 0
        cur = head
        while cur:
            if cur.val in present and (cur.next is None or cur.next.val not in present):
                ans += 1             # 当前节点是一段的段尾
            cur = cur.next
        return ans
```

## 8. 边界情况与易错点

1. **尾节点属于 `nums` 时必须计数**。示例 2 的节点 4 没有后继，按「后继不属于 `nums`」处理；如果写成「必须存在后继且后继不在集合中」，最后一个组件会整段漏掉，答案变成 1。
2. **单节点链表**：`head = [5]`、`nums = [5]` → 答案 1。判定里 `cur.next is None` 这一支就是为它准备的。
3. **`nums` 覆盖全部节点**：整条链表是一个组件，答案 1，而不是 $n-1$。若把「相邻两节点都在 `nums` 中就合并」误解成「数相邻对数」，会得到 $n-1$。
4. **被选中节点两两不相邻**：例如 `[0,1,2,3,4,5]` 配 `nums = [0,2,4]` → 答案 3，每个节点各自成为组件。
5. **空指针顺序**：C++ 的 `!cur->next || ...` 与 Python 的 `cur.next is None or ...` 都靠短路保护；交换顺序会运行时段错误 / `AttributeError`。
6. **不要为了数段首而反转链表**：反转后原 `head` 变成尾节点，若外层还拿着它复用就会出问题；本题数段尾，完全不需要改动链表。
7. **`nums` 的顺序无关**：`nums = [0,3,1,4]` 与 `[0,1,3,4]` 结果相同，切勿按 `nums` 数组顺序在链表里「找下一个」——那会把组件判成一串孤岛。
8. **`nums` 是子集的前提**：题目保证 `nums` 的每个值都在链表中出现。若数据不合法（含有链表中不存在的值），算法照样给出正确的组件数（没有节点会命中它），但此时不能再用 $\lvert \text{nums} \rvert$ 去推断答案的上界。

**延伸思考**：

- **输出组件本身**：只数段尾会丢掉内容。若要返回每个组件的值列表，可在段首（`cur` 在集合中而 `prev` 不在）开启一段、段尾收束；为拿到 `prev`，只需在遍历时多维护一个前驱指针，仍是 $O(n)$。
- **`nums` 不是子集时**：题目保证是子集；若放宽这一条，算法不需要任何修改——集合里多出的值不会命中任何节点。
- **值域极大或链表成环**：哈希集合照样适用；但链表若成环，`while (cur)` 永不终止，需要先用快慢指针判环并把环切开，再套用本解法。
