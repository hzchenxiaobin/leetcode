# LeetCode 卡车上的最大单元数 题解

## 1. 题目概述

- **标题 / 题号**：卡车上的最大单元数（#1710，easy）
- **链接**：https://leetcode.cn/problems/maximum-units-on-a-truck/
- **来源**：LeetCode 第 222 场周赛 Q1
- **难度**：简单
- **标签**：贪心、排序、数组

**题意**：要用一辆卡车装箱子。给定二维数组 `boxTypes`，其中 `boxTypes[i] = [numberOfBoxes_i, numberOfUnitsPerBox_i]`：第 $i$ 类箱子有 `numberOfBoxes_i` 个，**每个**箱子装 `numberOfUnitsPerBox_i` 个单元。整数 `truckSize` 是卡车上可装载**箱子**的最大数量（不是单元数）。只要箱子总数不超过 `truckSize`，可以任意挑选箱子装车。返回卡车能装载**单元的最大总数**。

**约束**：

- $1 \le \text{boxTypes.length} \le 1000$
- $1 \le \text{numberOfBoxes}_i,\ \text{numberOfUnitsPerBox}_i \le 1000$
- $1 \le \text{truckSize} \le 10^6$

> 💡 读题关键：`truckSize` 的单位是**箱子数**而非单元数——**无论哪类箱子，装一个都恰好消耗 1 个车位**。这意味着「装一个高单元箱子」与「装一个低单元箱子」**代价相同、收益不同**。等代价下最大化收益，正是贪心可解的典型信号（§5 会给出严格证明）。

## 2. 示例

**示例 1**

```text
输入：boxTypes = [[1,3],[2,2],[3,1]], truckSize = 4
输出：8

解释：1 个第一类箱子（每个 3 单元）、2 个第二类（每个 2 单元）、3 个第三类（每个 1 单元）。
装第一类全部 1 个 + 第二类全部 2 个 + 第三类取 1 个：
单元总数 = 1×3 + 2×2 + 1×1 = 8，用掉车位 1+2+1 = 4。
```

**示例 2**

```text
输入：boxTypes = [[5,10],[2,5],[4,7],[3,9]], truckSize = 10
输出：91

解释：按单元数降序：5 个(10)、3 个(9)、4 个(7)、2 个(5)。
装 5 个(10) → 50；装 3 个(9) → 27；装 2 个(7) → 14。
车位 5+3+2 = 10 恰好用尽，合计 50+27+14 = 91。
```

**示例 3**（自造，演示车位盈余）

```text
输入：boxTypes = [[3,2]], truckSize = 100
输出：6

解释：全部箱子只有 3 个，远少于车位数 100 → 全装。
答案 = 3×2 = 6，装不满也不浪费——没有别的箱子可装。
```

## 3. 解题思路

### 3.1 暴力思路

两条朴素路线都走不通或没必要：

1. **枚举方案**：对每类箱子枚举「取多少个」，回溯搜索所有组合——状态数是乘积级的，$n = 1000$ 时直接爆炸；
2. **背包 DP**：把每类箱子展开成单个物品，做「容量为 `truckSize`、物品重量为 1、价值为 `units_i` 的背包」——状态 $O(n \times \text{truckSize})$ 高达 $1000 \times 10^6 = 10^9$，时间与空间都不可行。

但换个角度看这个背包：**所有物品的重量都等于 1**。重量全相同的背包，没有任何「权衡余地」——选哪 $k$ 个箱子占的车位都一样多，唯一区别是价值。那就没有理由不先拿价值最大的：**贪心**。

### 3.2 核心观察：等代价（1 个车位）、异收益（单元数）

![核心观察：每个箱子都占一个车位，代价相同，按单元数降序装车](images/wc222_q1_units_first_concept.svg)

把 `boxTypes[i] = [cnt_i, units_i]` 想象成「$cnt_i$ 个完全相同的箱子，每个价值 $units_i$、都占 1 个车位」：

- **代价维度塌缩**：装哪个箱子对车位的消耗毫无差别，于是问题只剩一维——在至多 $\min(N, \text{truckSize})$ 个箱子里（$N = \sum cnt_i$），最大化单元总数；
- **收益排序即解**：同样取 $k$ 个箱子，取单元数**最大**的 $k$ 个，总单元一定不小（重排不等式，§5 引理 1）。

> 💡 「重量全 1 的背包 = 排序贪心」是可迁移的等价转换：一旦发现所有候选的**代价相同**，排序 + 从收益最大的开始取，就是最优解的标准形态。

### 3.3 算法流程

![算法流程：按单元数降序排序，逐类装 min(cnt, rem) 个箱子](images/wc222_q1_greedy_flow.svg)

```text
boxTypes ← 按 units（第二列）降序排序      # 排序键是单元数，不是箱子数！
rem    ← truckSize                        # 剩余车位
total  ← 0
for (cnt, units) in boxTypes:
    if rem ≤ 0: break                     # 车位用尽，提前收工
    take  ← min(cnt, rem)                 # 最后一类可能只装一部分
    total ← total + take × units
    rem   ← rem − take
return total
```

不需要真的把 $N \le 10^6$ 个箱子展开成数组——**按类整块处理**，每类 $O(1)$；只有「正在装的最后那一类」需要 `min(cnt, rem)` 截断。

### 3.4 示例演算

![示例演算：示例2逐步走查，降序装箱直到车位用尽](images/wc222_q1_walkthrough.svg)

以示例 2 走查（`truckSize = 10`，降序后依次是 $10 \times 5,\ 9 \times 3,\ 7 \times 4,\ 5 \times 2$ 个箱子）：

| 单元/箱 | 剩余车位 | 装箱数 | 单元增量 | 累计 |
|---|---|---|---|---|
| 10 | 10 → 5 | 5 | +50 | 50 |
| 9 | 5 → 2 | 3 | +27 | 77 |
| 7 | 2 → 0 | 2 | +14 | **91** |
| 5 | 0（车位用尽） | — | — | 91 |

车位 $5+3+2 = 10$ 恰好耗尽，$5\times10 + 3\times9 + 2\times7 = 91$，与期望输出一致。

## 4. 算法细节

1. **排序键是第二列**：按 $\text{numberOfUnitsPerBox}$ **降序**，与箱子数量（第一列）无关。C++ 用自定义 lambda `a[1] > b[1]`；Python 用 `key=lambda b: -b[1]` 或 `key=lambda b: b[1], reverse=True`。
2. **按类整块装载**：不需要展开成 $10^6$ 个单箱，对每类一次算 `take = min(cnt, rem)`、`total += take * units`，全程 $O(n)$。
3. **部分装载截断**：只有装到「车位不够装整类」的那一步才会出现 `take < cnt`；此前各类必然全装。
4. **提前终止**：`rem ≤ 0` 即 `break`，后续更大的单元也无车位可用——注意用 `≤ 0` 而不是 `== 0` 做防御（若误多减一次导致负数也能退出）。
5. **溢出评估**：答案上界为 $\text{truckSize} \times \max(\text{units}) = 10^6 \times 10^3 = 10^9 < 2^{31} - 1$，`int` 恰好够但贴着上限；C++/Java 求稳可换 `long long`，Python 无需考虑。
6. **排序不稳定无影响**：同类内箱子完全同质，任意顺序等价。

## 5. 正确性证明

将 `boxTypes` 展开成 $N = \sum_i \text{cnt}_i$ 个「物品」，第 $i$ 类展开出 $cnt_i$ 个价值全为 $units_i$ 的物品；记全体物品价值降序排列为 $u_{(1)} \ge u_{(2)} \ge \dots \ge u_{(N)}$。装车方案即从中选至多 $\text{truckSize}$ 个物品，目标最大化价值和。记 $m = \min(N, \text{truckSize})$。

**引理 1（前 $k$ 大支配任意 $k$ 个）**：对任意 $k \le N$ 与任意大小为 $k$ 的物品子集 $T$，有 $\sum_{j=1}^{k} u_{(j)} \ge \sum_{v \in T} v$。

**证明**：将 $T$ 中物品降序排列为 $v_1 \ge v_2 \ge \dots \ge v_k$。对每个 $j$，$T$ 中值 $\ge v_j$ 的物品至多 $j$ 个，故全体中至少有 $j$ 个物品值 $\ge v_j$，从而第 $j$ 大者 $u_{(j)} \ge v_j$（否则值 $\ge v_j$ 的不足 $j$ 个，矛盾）。对 $j = 1, \dots, k$ 逐项相加即得。∎（这正是重排不等式的特例。）

**引理 2（多装不亏）**：任何可行方案装不满 $m$ 个箱子时，总可以再补装一个使总值严格增加且仍可行。

**证明**：每个箱子单元数 $units_i \ge 1 > 0$。若某方案装了 $t < m$ 个箱子，则 $t < N$ 说明仍有箱子剩余、$t < \text{truckSize}$ 说明仍有车位剩余，任取一个剩余箱子装车：总单元至少增加 1，箱子数仍 $\le \text{truckSize}$，仍可行。∎

**定理（贪心最优）**：按单元数降序、逐类装满直到车位用尽所得到的总单元，即最大总单元，且最优值等于 $\sum_{j=1}^{m} u_{(j)}$。

**证明**：贪心过程恰好装入单元数最大的 $m$ 个物品（装到车位耗尽或箱子耗尽为止，且始终优先取最大者），取得总值 $\sum_{j=1}^{m} u_{(j)}$。由引理 2，存在最优方案装满 $m$ 个箱子（否则可继续增值，与最优性矛盾）；设该最优方案选的集合为 $T^\ast$（$|T^\ast| = m$），由引理 1 得 $\sum_{j=1}^{m} u_{(j)} \ge \sum_{v \in T^\ast} v$，即贪心值 $\ge$ 最优值。又贪心本身是可行方案，贪心值 $\le$ 最优值。故贪心值 $=$ 最优值 $= \sum_{j=1}^{m} u_{(j)}$。∎

> 💡 证明骨架是通用的**「前 k 大支配 + 多取不亏」**两引理模式：前者来自重排不等式，后者来自「每件收益为正」。任何「等代价、正收益」的选取型贪心都可以照此套写。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，其中 $n = \text{boxTypes.length} \le 1000$。
  - 排序是唯一非线性开销，$O(n \log n)$；
  - 贪心扫描每类 $O(1)$，共 $O(n)$；
  - 无需展开物品，$N$ 最多 $10^6$ 但从不显式构造。
- **空间复杂度**：$O(1)$（不计排序自身栈开销）。
  - 原地排序，只维护 `total` 与 `rem` 两个标量；
  - C++ `sort` 递归栈深 $O(\log n)$，可忽略。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maximumUnits(vector<vector<int>>& boxTypes, int truckSize) {
        sort(boxTypes.begin(), boxTypes.end(),
             [](const vector<int>& a, const vector<int>& b) {
                 return a[1] > b[1];                        // 排序键：单元数（第二列）降序
             });
        int total = 0;
        for (const vector<int>& box : boxTypes) {
            if (truckSize <= 0) break;                      // 车位用尽，提前收工
            int take = min(box[0], truckSize);              // 最后一类可能只装一部分
            total += take * box[1];
            truckSize -= take;
        }
        return total;
    }
};
```

### Python

```python
class Solution:
    def maximumUnits(self, boxTypes: List[List[int]], truckSize: int) -> int:
        total = 0
        for cnt, units in sorted(boxTypes, key=lambda b: -b[1]):   # 单元数降序
            if truckSize <= 0:
                break
            take = min(cnt, truckSize)                            # 最后一类可能只装一部分
            total += take * units
            truckSize -= take
        return total
```

## 8. 边界情况与易错点

1. **排序键写错（本题第一大 WA 点）**：题面两组数（箱子数、单元数）顺序极易看混——必须按**第二列** `numberOfUnitsPerBox` 降序。若按第一列箱子数降序，示例 2 会得到错误排序 $[[5,10],[4,7],[3,9],[2,5]]$（先 4 个 7 再 3 个 9）……算出 $5\times10+4\times7+1\times9 = 87 \ne 91$。
2. **忘记部分装载截断**：若不加 `min(cnt, rem)`，最后一类会「整类计入」导致单元多算、车位透支成负数；负车位还会让后续 `if (truckSize <= 0) break` 逻辑混乱。
3. **`truckSize` 语义混淆**：它限制的是**箱子数**而非单元数。把 `truckSize` 当单元预算去减 `units` 是方向性错误。
4. **车位盈余（示例 3 型）**：$\sum \text{cnt}_i \le \text{truckSize}$ 时全部装箱即答案；循环天然处理，无需特判，但别在 `rem == 0` 才停的地方写成死等「装满」。
5. **停止条件用 `≤ 0`**：写成 `== 0` 在正常流程下等价，但一旦某步 `rem` 已为负（防御性考虑），`== 0` 永远不再触发，循环会继续空转甚至越界。
6. **溢出**：答案上界 $10^9 < 2^{31} - 1$，`int` 能过但贴近上限；赛时若不确定就用 `long long`，Python 无此问题。中间量 `take * box[1]` 同界，不会单步爆 `int`。

**延伸思考**：

- **异代价版本（背包化）**：若每类箱子占用**不同**车位数（体积 $w_i$），等代价塌缩失效，退化为多重背包：$O(n \times \text{truckSize})$ DP，$\text{truckSize} \le 10^6$ 时需滚动数组或二进制拆分。
- **单元数允许为 0**：收益非正的箱子装不装无所谓（引理 2 失效但结论不变：贪心仍最优，只是「装不满也无所谓」）；若允许**负**收益则必须跳过——贪心仍对，排序后取前 $m$ 个正收益者即可。
- **两类资源约束**：卡车同时限箱子数与总重量 → 二维费用背包，或按「单位密度」贪心不再保证最优（密度贪心在 0-1 情形无交换论证），需 DP。
