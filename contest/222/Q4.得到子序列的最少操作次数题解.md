# LeetCode 得到子序列的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：得到子序列的最少操作次数（#1713，hard）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-a-subsequence/
- **来源**：LeetCode 第 222 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、哈希表、二分查找、最长上升子序列

**题意**：给定数组 `target`（元素**互不相同**）与数组 `arr`（**可能含重复**）。每次操作可以往 `arr` 的**任意位置**插入**任意**整数。求最少操作次数，使 `target` 成为 `arr` 的一个**子序列**（子序列 = 删去若干元素、保持其余元素相对顺序得到的数组）。

**约束**：

- $1 \le \text{target.length},\ \text{arr.length} \le 10^5$
- $1 \le \text{target[i]},\ \text{arr[i]} \le 10^9$
- `target` 不包含任何重复元素

> 💡 读题关键：插入是**万能修补**——值随便挑、位置随便放。所以真正要算的不是「怎么插」，而是「target 有多少已经免费地、按顺序躺在 arr 里」。这个「免费部分」的最长长度正是 LCS；而 **target 互异**这一条件会把 LCS 悄悄压成一个 LIS，把 $O(nm)$ 的二维 DP 干成 $O(m \log n)$——本题的全部难度都藏在这步归约里（§5 引理 1、2 给出严格证明）。

## 2. 示例

**示例 1**

```text
输入：target = [5,1,3], arr = [9,4,2,3,4]
输出：2
解释：arr 里只有 3 命中 target，免费部分长度 1。
保留 3，插入 5 和 1：[5, 9, 4, 1, 2, 3, 4]，target = [5,1,3] 已按序出现。
```

**示例 2**

```text
输入：target = [6,4,8,1,3,2], arr = [4,7,6,2,3,8,6,1]
输出：3
解释：arr 中按 target 顺序出现的最长一段是 6, 8, 1（arr 下标 2, 5, 7），
长度 3；补插 4, 3, 2 三个数即可。
```

**示例 3**（自造，演示重复元素）

```text
输入：target = [3,1,2], arr = [1,1,2,2,1]
输出：1
解释：保留一个 1 和一个 2（如下标 0、2 的 1, 2），开头插入 3 即可。
arr 里的重复 1、2 不会让答案更小——每个 target 元素只能匹配一次。
```

## 3. 解题思路

### 3.1 暴力思路：LCS 的 O(nm) DP

「往哪儿插、插什么」的搜索空间是无穷的，直接模拟没有意义；反过来问「**有多少不用插**」才有抓手：target 成为 `arr` 子序列，等价于 target 的每个元素都在插入后的数组中按序出现，而**不插就能匹配上的部分**恰是 target 与 arr 的**最长公共子序列**（LCS）。经典 LCS DP 是 $O(nm)$：$n = m = 10^5$ 时约 $10^{10}$ 次转移，**超时百倍**。必须抓住题面的特殊条件——**target 互异**——压掉一维。

### 3.2 核心观察：答案 = n − L，互异把 LCS 压成 LIS

![核心观察：插入万能 ⇒ 答案 = n − LCS；target 互异 ⇒ LCS 归约为 LIS](images/wc222_q4_lcs_to_lis_concept.svg)

两步归约：

1. **操作数 = n − L**（引理 1）：插入万能 ⇒ 凡是能在 `arr` 中按 target 顺序「白嫖」的 $L$ 个元素（即一条长为 $L$ 的公共子序列）一分钱不花；剩下 $n - L$ 个元素每个恰需一次插入。
2. **L = LIS(s)**（引理 2）：target 互异 ⇒ 值与下标一一对应。把 `arr` 中出现在 target 里的元素换成它在 target 里的下标，得到序列 $s$；「公共子序列」⇔「$s$ 的**严格上升**子序列」。于是 $L$ 就是 $s$ 的 LIS 长度，贪心 + 二分 $O(m \log n)$ 可解。

### 3.3 算法流程：哈希投影 + 贪心维护 tails

![算法流程：哈希投影到下标，贪心 LIS 维护 tails 数组](images/wc222_q4_lis_tails_flow.svg)

维护数组 `tails`：`tails[k]` = 已扫描前缀中「长度为 $k+1$ 的严格上升子序列」的**最小结尾**（引理 3 保证它严格递增、可二分）。扫描 `arr`，对每个元素 $x$：

- $x$ 不在 `target` 中 → 丢弃（对匹配毫无贡献）；
- 否则取下标 $i = \text{pos}[x]$，在 `tails` 中 `lower_bound` 找**首个 $\ge i$** 的槽位：找不到（$i$ 比所有结尾都大）→ **追加**，LIS 长度 $+1$；找到 → **覆盖**该槽，让这个长度的结尾更小、后面更容易接。

结束时答案 $= n - |\text{tails}|$。全程**无需**显式存 $s$，更无需构造插入后的数组。

### 3.4 示例演算

![示例演算：arr 投影成 s，贪心 LIS 七步走查](images/wc222_q4_walkthrough.svg)

示例 2：$\text{pos} = \{6{\to}0,\ 4{\to}1,\ 8{\to}2,\ 1{\to}3,\ 3{\to}4,\ 2{\to}5\}$，`arr` 投影得 $s = [1,0,5,4,2,0,3]$（丢掉 7）：

| 步 | 读到 $i$ | 动作（lower_bound：首个 $\ge i$ 的槽） | tails 之后 | LIS 长度 |
|----|---------|----------------------------------------|-----------|---------|
| 1 | 1 | tails 空 → 追加 | $[1]$ | 1 |
| 2 | 0 | $1 \ge 0$ → 替换槽 0 | $[0]$ | 1 |
| 3 | 5 | 比 0 大 → 追加 | $[0,5]$ | 2 |
| 4 | 4 | $5 \ge 4$ → 替换槽 1 | $[0,4]$ | 2 |
| 5 | 2 | $4 \ge 2$ → 替换槽 1 | $[0,2]$ | 2 |
| 6 | 0 | $0 \ge 0$ → 替换槽 0（值相同，无变化） | $[0,2]$ | 2 |
| 7 | 3 | 比 2 大 → 追加 | $[0,2,3]$ | 3 |

$L = 3$，答案 $= 6 - 3 = 3$ ✓。保留方案：$s$ 中的 $0, 2, 3$，即 `arr` 中的 $6, 8, 1$（`arr` 下标 2, 5, 7）；补插 $4, 3, 2$。

**示例 1 / 3 快验**：

- 示例 1：`arr` 中只有 3 命中 → $s = [2]$，LIS $= 1$，答案 $3 - 1 = 2$ ✓。
- 示例 3：$s = [1,1,2,2,1]$，严格 LIS $= [1,2]$ 长度 2，答案 $3 - 2 = 1$ ✓——重复下标被「严格上升」自动挡住。

## 4. 算法细节

1. **哈希表建 pos**：`pos[v] = v 在 target 中的下标`，$O(n)$。target 互异保证无冲突；值域 $10^9$ 无需离散化，直接哈希。
2. **边扫边投影**：遍历 `arr`，`pos` 查不到直接跳过——**不显式构造** $s$，省一趟循环与一份内存。
3. **二分用 `lower_bound`（首个 $\ge i$）**：LIS 要求**严格**上升，相等也必须「替换」而非「接在后面」；`tails` 严格递增（引理 3）是二分正确的前提。
4. **两种更新**：`lower_bound` 落到末尾 ⇒ 追加（更长的上升子序列出现）；否则覆盖命中槽（同长度换更小结尾）。替换成相同值（重复元素）是合法 no-op，无需特判。
5. **答案**：$n - |\text{tails}|$。注意减的是 **target 的长度 $n$**，不是 `arr` 的长度 $m$。

## 5. 正确性证明

**引理 1（操作数 = n − L）**：记 $L = \mathrm{LCS}(\text{target}, \text{arr})$，$n = |\text{target}|$，则最少操作次数恰为 $n - L$。

**证明**：下界：设 $k$ 次操作后 target 成为 $\text{arr}'$ 的子序列，$\text{arr}'$ 由 arr 插入 $k$ 个元素得到。考察 target 在 $\text{arr}'$ 中的一组匹配：落在**插入元素**上的至多 $k$ 个，其余落在 arr 原有元素上，且按匹配顺序构成 arr 的一个子序列、同时对应 target 中按序的一段——即一条长度 $\ge n - k$ 的公共子序列。故 $L \ge n - k$，即 $k \ge n - L$。上界：取一条长 $L$ 的公共子序列，其在 arr 中的匹配位置为 $p_1 < \cdots < p_L$。把 target 中不属于它的 $n - L$ 个元素**按 target 中的顺序**逐个插入：每个元素插到「公共子序列中排在它后面的首个元素当前位置」之前（无则插到末尾）。插入不移动已有元素，逐个插完后 target 全部元素按序出现，共 $n - L$ 次。∎

**引理 2（互异 ⇒ LCS 归约为 LIS）**：设 $s$ 为 arr 中属于 target 的元素依原顺序替换为 pos 下标所得的序列，则 target 与 arr 的公共子序列与 $s$ 的**严格上升**子序列一一对应（且长度相同），从而 $L = \mathrm{LIS}(s)$。

**证明**：设 arr 的子序列 $a_{i_1}, \dots, a_{i_\ell}$（$i_1 < \cdots < i_\ell$）是公共子序列，即存在 $j_1 < \cdots < j_\ell$ 使 $a_{i_t} = \text{target}[j_t]$。因 target 互异，$j_t = \text{pos}[a_{i_t}]$ 被**唯一确定**且严格递增，故 $(\text{pos}[a_{i_t}])_{t}$ 是 $s$ 的严格上升子列；不在 target 中的元素不参与任何公共子序列。反之，$s$ 的任一严格上升子列 $j_1 < \cdots < j_\ell$（对应 arr 位置 $i_1 < \cdots < i_\ell$）还原成值，即 target 的 $j_1, \dots, j_\ell$ 处元素按序匹配 arr 的 $i_1, \dots, i_\ell$ 处元素，是一条公共子序列。两个方向的构造互逆，故一一对应。∎

**引理 3（tails 不变量）**：任一时刻，记 $T(k)$ 为已扫描前缀中「长度为 $k+1$ 的严格上升子序列」的最小结尾（不存在记 $+\infty$）。则算法不变量为：`tails` 恰是 $T$ 的全部有限值按 $k$ 递增排列（特别地 tails 严格递增，$|\text{tails}|$ = 当前 LIS 长度）。

**证明**：先注意 $T$ 在有限处严格递增：若 $T(k{+}1) = y < \infty$，删去该子序列末项得长度 $k{+}1$、结尾 $y' < y$ 者，故 $T(k) \le y' < y$。归纳：设处理 $i$ 前不变量成立，$k$ 为 tails 中首个 $\ge i$ 的下标。以 $i$ 结尾的新子序列 = 某条旧子序列（结尾 $< i$）接上 $i$：能接的最长旧长度为 $k$（因 $\text{tails}[k-1] < i \le \text{tails}[k]$，更长者最小结尾 $\text{tails}[k] \ge i$ 接不上），故以 $i$ 结尾者最长 $k{+}1$、结尾值恒为 $i$；更短的以 $i$ 结尾者因 $i > \text{tails}[\ell]\ (\ell < k)$ 不会刷新 $T(\ell)$。于是处理 $i$ 至多把 $T(k)$ 改为 $\min(\text{tails}[k],\, i) = i$，其余不变——这正是「落在末尾则追加、否则覆盖槽 $k$」；且 $\text{tails}[k-1] < i \le \text{tails}[k]$ 保证覆盖后仍严格递增。归纳完成。∎

**定理**：算法返回最少操作次数。

**证明**：由引理 3，扫描结束时 $|\text{tails}| = \mathrm{LIS}(s)$；由引理 2，$\mathrm{LIS}(s) = L$；由引理 1，最少操作次数 $= n - L = n - |\text{tails}|$，即返回值。∎

> 💡 三个引理各管一段：引理 1 把「插入」翻译成「数免费」，引理 2 用**互异**把二维匹配压成一维序，引理 3 是贪心 LIS 的标准不变量。抽掉任何一个，结论都接不上。

## 6. 复杂度分析

- **时间复杂度**：$O(n + m \log n)$。建 pos 为 $O(n)$；扫描 arr 每元素一次 $O(1)$ 哈希查询，命中者至多一次 $O(\log |\text{tails}|) \le O(\log n)$ 的二分。$n = m = 10^5$ 时约 $1.7 \times 10^6$ 次比较，轻松通过。
- **空间复杂度**：$O(n)$。pos 与 tails；$s$ 不显式存储，arr 只读一遍。

## 7. 参考代码

### C++（哈希投影 + 贪心 LIS，$O(n + m \log n)$）

```cpp
class Solution {
  public:
    int minOperations(vector<int>& target, vector<int>& arr) {
        int n = target.size();
        unordered_map<int, int> pos;
        for (int i = 0; i < n; i++) pos[target[i]] = i;

        vector<int> tails;               // tails[k]：长度 k+1 的上升子序列的最小结尾
        for (int x : arr) {
            auto it = pos.find(x);
            if (it == pos.end()) continue;   // 不在 target 中：永远用不上
            int i = it->second;
            auto p = lower_bound(tails.begin(), tails.end(), i);
            if (p == tails.end()) tails.push_back(i);   // 能接长就接长
            else *p = i;                                // 结尾变小，后面更好接
        }
        return n - (int)tails.size();
    }
};
```

### Python（同思路）

```python
from bisect import bisect_left

class Solution:
    def minOperations(self, target: List[int], arr: List[int]) -> int:
        pos = {v: i for i, v in enumerate(target)}
        tails = []                       # tails[k]：长度 k+1 的上升子序列的最小结尾
        for x in arr:
            i = pos.get(x)
            if i is None:                # 不在 target 中：永远用不上
                continue
            k = bisect_left(tails, i)    # 严格上升 → lower_bound
            if k == len(tails):
                tails.append(i)          # 能接长就接长
            else:
                tails[k] = i             # 结尾变小，后面更好接
        return len(target) - len(tails)
```

> ⚠️ 两处 API 对应别记混：C++ `lower_bound` ↔ Python `bisect_left`（首个 $\ge i$）。若写成 `upper_bound` / `bisect_right`，相等下标会被接到后面——等于同一个 target 元素匹配了两次（见 §8 第 3 条反例）。

## 8. 边界情况与易错点

1. **互异是归约的命门**（头号坑）：「值 ↔ 下标」单射、公共子序列 ⇔ 严格上升，全部建立在 target 互异上。若 target 有重复，这套做法直接错（见延伸思考）。
2. **不在 target 的元素必须丢弃**：它们无法映射下标，对匹配毫无贡献；忘了跳过轻则 WA、重则把哈希查询写崩。
3. **严格上升 ⇒ `lower_bound` 而非 `upper_bound`**：`upper_bound` 会把**相等**下标也接到后面。反例：$s = [1,1]$ 应得 LIS $= 1$（同一个 1 不能匹配两次），`upper_bound` 版会算出 2。
4. **答案是 n − LIS，不是 m − LIS**：减的是 **target** 的长度。顺手写成 `arr.size()` 是经典手滑。
5. **重复元素无需特判**：arr 的重复值产生重复下标，`lower_bound` 定位到相同槽、替换成相同值，天然 no-op（走查第 6 步）。
6. **极端规模**：arr 全部不在 target 中 ⇒ tails 空、答案 $n$（全靠插入）；arr 完全按序包含 target ⇒ 答案 0。$n \le 10^5$、值 $\le 10^9$，`int` 与返回值均无溢出。
7. **不要构造插入后的数组**：题目只要次数；真去模拟插入位置可能带出 $O(nm)$ 的额外代价，还容易在插入顺序上绕晕（引理 1 的上界证法已给出构造思路，仅在需要输出方案时才用）。

**延伸思考**：

- **target 含重复怎么办**：pos 不再是单射，「公共子序列 ⇔ 严格上升」断裂，只能回到一般 LCS 的 $O(nm)$ DP（基于 SETH，一般 LCS 想做到严格次线性空间/次平方时间都很困难）。互异性正是本题把 $10^{10}$ 降到 $10^6$ 的全部本钱。
- **要输出具体插入方案呢**：次数之外还需方案——为每个进过 tails 的元素记录「它替换时接在哪个槽的旧值后面」（前驱），结束时从 tails 末槽回溯出一条 LIS，再按引理 1 上界证法逐个插入其余元素。
- **换一种 LIS 求法**：值域 $10^9$ 需先离散化，再用树状数组/线段树维护「以每个下标结尾的最长长度」；本题下标天然落在 $[0, n)$，贪心 tails 最简单。若题目改成**带权** LIS 或要求区间查询，数据结构版更通用。
