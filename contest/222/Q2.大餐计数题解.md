# LeetCode 大餐计数 题解

## 1. 题目概述

- **标题 / 题号**：大餐计数（#1711，medium）
- **链接**：https://leetcode.cn/problems/count-good-meals/
- **来源**：LeetCode 第 222 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表

**题意**：给定整数数组 `deliciousness`，其中 `deliciousness[i]` 是第 $i$ 道餐品的美味程度。一顿**大餐**由**两道不同下标**的餐品组成，且二者美味程度之和恰好是 $2$ 的幂。返回能做出的大餐数量，结果对 $10^9 + 7$ 取余。只要下标不同就算不同餐品——即使美味程度相同——即统计满足条件的**下标对** $(i, j)$（$i < j$）的个数。

**约束**：

- $1 \le \text{deliciousness.length} \le 10^5$
- $0 \le \text{deliciousness}[i] \le 2^{20}$

> 💡 读题关键有两处。其一，这是「**下标对计数**」而非「数值组合计数」——同值元素两两之间也算不同大餐，所以哈希表里必须存**出现次数**而非存在性。其二，$2^0 = 1$ 也是合法的「和」：$0 + 1 = 1$ 是大餐，别把幂默认成从 $2$ 开始。

## 2. 示例

**示例 1**

```text
输入：deliciousness = [1,3,5,7,9]
输出：4

解释：(1,3)、(1,7)、(3,5)、(7,9) 四对，和分别为 4、8、8、16，都是 2 的幂。
```

**示例 2**

```text
输入：deliciousness = [1,1,1,3,3,3,7]
输出：15

解释：同值也两两配对——3 对 (1,1) 和为 2，9 对 (1,3) 和为 4，3 对 (1,7) 和为 8。
而 (3,3)=6、(3,7)=10、(7,7)=14 都不是 2 的幂，不计入。
```

**示例 3**（自造，演示 $2^0 = 1$ 与数值 $0$）

```text
输入：deliciousness = [0,1,4]
输出：2

解释：(0,1) 和为 1 = 2⁰ ✓；(0,4) 和为 4 = 2² ✓；(1,4) 和为 5 ✗。
注意两个 0 相加得 0，不是 2 的幂（2 的幂从 1 开始），不配对。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i, j)$，判断 $d_i + d_j$ 是否为 $2$ 的幂。判断本身 $O(1)$（非负且二进制中恰有一个 $1$），但 $n = 10^5$ 时对数高达 $\binom{10^5}{2} \approx 5 \times 10^9$，平方级枚举不可行。

突破口不在「怎么更快地判断一对」，而在「**和的合法取值太少**」。

### 3.2 核心观察：合法目标只有 22 个

![核心观察：和为2的幂，候选目标只有22个，固定d后搭档唯一](images/wc222_q2_power_targets_concept.svg)

两个观察把平方级直接砍成线性：

1. **目标集合极小**：$0 \le d_i \le 2^{20}$，故任意两数之和 $\le 2 \times 2^{20} = 2^{21}$。而 $[1, 2^{21}]$ 内 $2$ 的幂只有 $2^0, 2^1, \dots, 2^{21}$ **共 22 个**——合法「和」的全集是常数个，与 $n$ 无关！
2. **搭档唯一**：固定餐品 $d$ 和目标 $2^k$ 后，搭档必须等于 $2^k - d$——一元一次方程，**每种目标至多对应一个搭档值**。

于是原问题等价于：**做 22 次「Two Sum 计数」**——对每个目标 $2^k$，数有多少对 $(i, j)$ 满足 $d_j = 2^k - d_i$。这正是哈希表的看家本领。

> 💡 这是「值域稀疏目标」型计数题的通用套路：合法和集合的大小是常数（本题 22），与 $n$ 无关 → 每个元素只需 $O(22)$ 次哈希查询。值域再大也不慌：$2$ 的幂在 $[0, 2^{31}]$ 内也只有 32 个。

### 3.3 算法流程：一次遍历 + 22 次查表

![算法流程：先查后插的一次遍历流程](images/wc222_q2_onepass_flow.svg)

```text
cnt  ← 空哈希表（值 → 已出现次数）
ans  ← 0
for d in deliciousness:                 # 从左到右一次遍历
    for k = 0 … 21:                     # 目标和 2^0 … 2^21，共 22 个
        ans ← ans + cnt[2^k − d]        # 查「更早的」搭档，查不到即为 0
    cnt[d] ← cnt[d] + 1                 # 先查后插：d 此刻才入表
return ans mod (10^9 + 7)
```

**先查后插**是防重的关键：处理 $d_j$ 时表中恰好只有下标 $< j$ 的元素，于是每对合法的 $(i, j)$ 只在处理 $j$ 时被数到一次——既不重复，元素也永远不会和自己配对。

### 3.4 示例演算

![示例演算：示例2数组一次遍历的逐步查表过程](images/wc222_q2_walkthrough.svg)

以示例 2 `[1,1,1,3,3,3,7]` 走查（只列命中的目标，其余 22 个目标贡献为 0）：

| $j$ | $d_j$ | 命中查找 | 贡献 | 处理后哈希表 | ans |
|---|---|---|---|---|---|
| 0 | 1 | 表空，全部查空 | +0 | `{1:1}` | 0 |
| 1 | 1 | $2^1-1=1$ → cnt=1 | +1 | `{1:2}` | 1 |
| 2 | 1 | $2^1-1=1$ → cnt=2 | +2 | `{1:3}` | 3 |
| 3 | 3 | $2^2-3=1$ → cnt=3 | +3 | `{1:3, 3:1}` | 6 |
| 4 | 3 | $2^2-3=1$ → cnt=3 | +3 | `{1:3, 3:2}` | 9 |
| 5 | 3 | $2^2-3=1$ → cnt=3 | +3 | `{1:3, 3:3}` | 12 |
| 6 | 7 | $2^3-7=1$ → cnt=3 | +3 | `{1:3, 3:3, 7:1}` | **15** |

合计 $15$，与期望输出一致；分解看正是 $3$ 对 $(1,1)$、$9$ 对 $(1,3)$、$3$ 对 $(1,7)$。

## 4. 算法细节

1. **幂的上界是 $2^{21}$ 不是 $2^{20}$**：最大和 $= 2^{20} + 2^{20} = 2^{21}$，$k$ 的范围是 $[0, 21]$ 共 22 个。且和为 $2^{21}$ 的对**只有** $(2^{20}, 2^{20})$ 一种取值（由 $x + y \le 2 \times 2^{20}$ 取等条件决定）——只枚举到 $2^{20}$ 恰好会漏掉它。
2. **下界是 $2^0 = 1$**：$0 + 1 = 1$ 合法，$k$ 从 $0$ 开始。
3. **哈希表存次数**：`cnt[v]` 是值 $v$ 已出现的次数；查询命中时把整个次数累加——同值的多道餐品每个都能和当前元素配成一对。
4. **先查后插**：22 次查询全部完成后才 `cnt[d]++`。若顺序写反，当 $2^k - d = d$（如 $d = 2^{20}$、目标 $2^{21}$，或 $d = 1$、目标 $2^1$）时元素会把自己算进搭档。
5. **互补数为负天然安全**：$2^k - d$ 可能为负，哈希表 `find` 不到即为 0，无需特判；若改用数组桶实现，必须先判断下标落在 $[0, 2^{20}]$ 再访问，防止负下标越界。
6. **溢出与取模**：答案上界 $\binom{10^5}{2} \approx 5 \times 10^9 > 2^{31} - 1$。C++ 用 `long long` 累加、返回前统一取模即可（中途不会超 `long long`）；Python 原生大整数无此虑。
7. **实现变体（按值分桶）**：先统计完整哈希表，再枚举每个出现过的值 $v$ 与 22 个目标：$c = 2^k - v > v$ 时累加 $\text{cnt}[v] \times \text{cnt}[c]$，$c = v$ 时累加 $\binom{\text{cnt}[v]}{2}$。正确但要小心「$v$ 与 $c$ 各数一遍」的去重，不如一次遍历版简洁防错。

## 5. 正确性证明

记 $d_0, d_1, \dots, d_{n-1}$ 为输入数组，$S = \{(i, j) : 0 \le i < j \le n-1,\ d_i + d_j \text{ 是 } 2 \text{ 的幂}\}$。

**引理 1（目标有界）**：若 $0 \le x, y \le 2^{20}$ 且 $x + y = 2^k$，则 $k \le 21$。

**证明**：$2^k = x + y \le 2 \times 2^{20} = 2^{21}$，故 $k \le 21$。∎

**引理 2（搭档唯一）**：固定 $x \in [0, 2^{20}]$ 与整数 $k \in [0, 21]$，满足 $x + y = 2^k$ 的整数 $y$ 若存在则唯一，且 $y = 2^k - x$。

**证明**：移项即得，一元一次方程解唯一。∎

**引理 3（一次遍历不重不漏）**：按「先查后插」处理到下标 $j$ 之前，哈希表按值聚合计次的内容恰为 $\{d_i : i < j\}$；且第 $j$ 步的累加量恰为 $\left|\{i < j : d_i + d_j \text{ 是 } 2 \text{ 的幂}\}\right|$。

**证明**：对 $j$ 归纳。$j = 0$ 时表空，22 次查询全为 0，且 $\{i < 0\} = \varnothing$，成立。设处理 $j$ 前表中恰为 $\{d_i : i < j\}$。第 $j$ 步先查询后插入：查询 $k$ 时若 $c = 2^k - d_j$ 在表中，`cnt[c]` 恰为 $\{i < j : d_i = c\}$ 的元素个数；由引理 2，这些 $i$ 与 $j$ 恰构成和为 $2^k$ 的对。又不同 $k$ 对应不同 $c$（因 $2^k$ 互异），22 次查询覆盖的下标子集两两不交；而 $d_i + d_j$ 取值唯一，只能等于唯一的 $2^k$，故每个合法 $i$ 恰被一次查询计入、不会重复。查询完成后 `cnt[d_j]++`，表变为 $\{d_i : i \le j\}$，归纳完成。∎

**定理**：算法返回 $|S| \bmod (10^9 + 7)$。

**证明**：由引理 1，$S$ 中任意对的和都是 $2^0 \sim 2^{21}$ 之一，全部落在枚举范围内；由引理 2，每个目标对应的搭档值被精确查到；由引理 3，每对 $(i, j) \in S$ 恰在其右端点 $j$ 被处理时统计一次（处理左端点 $i$ 时 $j$ 尚未入表），不在 $S$ 中的对从不被统计。故累加总和恰为 $|S|$，输出为其对 $10^9 + 7$ 的余数。∎

> 💡 「先查后插 ⇒ 每对恰数一次」是一次遍历计数类的通用不变量，与 1. 两数之和、560. 和为 K 的子数组 同源，值得作为引理单独沉淀。

## 6. 复杂度分析

- **时间复杂度**：$O(22n) = O(n)$，其中 $n \le 10^5$。
  - 每个元素固定做 22 次哈希查询 + 1 次插入，均为均摊 $O(1)$；
  - 22 是由值域 $2^{20}$ 决定的常数，与 $n$ 无关，总查询量约 $2.2 \times 10^6$ 次。
- **空间复杂度**：$O(D)$，$D$ 为不同美味程度的个数，$D \le \min(n, 2^{21})$。
  - 哈希表只存「值 → 次数」二元组；若改用数组桶则为 $O(2^{21})$（约 200 万个 `int`，8 MB 内可容纳）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int countPairs(vector<int>& deliciousness) {
        const long long MOD = 1e9 + 7;
        unordered_map<int, long long> cnt;          // 值 → 已出现次数
        long long ans = 0;                          // 上界 C(1e5,2)≈5e9，必须 long long
        for (int d : deliciousness) {
            for (int k = 0; k <= 21; ++k) {          // 目标和 2^0 … 2^21，共 22 个
                auto it = cnt.find((1 << k) - d);    // 搭档值可能为负：查不到即为 0
                if (it != cnt.end()) ans += it->second;
            }
            ++cnt[d];                                // 先查后插：保证只数 i < j
        }
        return ans % MOD;
    }
};
```

### Python

```python
class Solution:
    def countPairs(self, deliciousness: List[int]) -> int:
        MOD = 10**9 + 7
        cnt = {}
        ans = 0
        for d in deliciousness:
            for k in range(22):              # 目标和 2^0 … 2^21
                ans += cnt.get((1 << k) - d, 0)   # 查「更早的」搭档
            cnt[d] = cnt.get(d, 0) + 1       # 先查后插
        return ans % MOD
```

## 8. 边界情况与易错点

1. **幂上界写成 $2^{20}$（本题第一大 WA 点）**：最大和是 $2^{21}$，而和为 $2^{21}$ 的对只有 $(2^{20}, 2^{20})$——只枚举 21 个目标必漏掉它。反向同理：写 `while (p < d)` 之类以元素为界的循环也会漏。
2. **漏掉 $2^0 = 1$**：$0$ 是合法美味程度，$0 + 1 = 1$ 是大餐。若 $k$ 从 $1$ 起会漏掉所有含 $0$ 与 $1$ 的对。
3. **答案溢出 `int`**：$n = 10^5$ 全同值且能配对时，答案接近 $\binom{10^5}{2} \approx 4.99995 \times 10^9 > 2^{31} - 1$。C++ 忘用 `long long` 会得到溢出后的错值。
4. **先查后插写反**：先 `cnt[d]++` 再查会让元素把自己当搭档——凡 $2d$ 是幂的元素（如 $d = 2^{20}$、$d = 1$）都会多数。
5. **哈希表存 bool 而非计数**：$(1,1,1)$ 内部就有 $\binom{3}{2} = 3$ 对，存「是否存在」会算成 $1$ 对。
6. **数组桶下标越界**：$2^k - d$ 可能为负或超过 $2^{20}$，数组实现必须先判范围；哈希表无此问题。
7. **取模时机**：`long long` 全程可容纳 $5 \times 10^9$，最后取一次模即可；若坚持用 `int` 累加则须每步取模，且注意 `(a += b) %= MOD` 中先加后模的顺序。

**延伸思考**：

- **目标集合不再稀疏时怎么办**：若合法和是「完全平方数」或「质数」（候选目标达 $O(\sqrt{V})$ 甚至 $O(V / \log V)$ 个，与 $n$ 同阶以上），逐目标查表不再高效。值域小时可对值域建桶，用 **FFT 卷积** $O(V \log V)$ 一次统计所有两两和的出现次数，再对合法和求和（注意自配对 $v + v$ 的修正与同下标去重）。
- **值域更大还适用吗**：适用。本题做法对 $0 \le d_i \le 10^9$ 依然成立——$2$ 的幂在 $[0, 2^{31}]$ 内只有 31 个，每元素查 31 次，「目标集合大小是常数」与值域规模无关，这正是幂目标题的通用解形态。
