# LeetCode 单线程 CPU 题解

## 1. 题目概述

- **标题 / 题号**：单线程 CPU（#1834，medium）
- **链接**：https://leetcode.cn/problems/single-threaded-cpu/
- **来源**：LeetCode 第 237 场周赛 Q3
- **难度**：中等
- **标签**：堆、优先队列、排序、模拟、调度

**题意**：给定 $n$ 项任务，`tasks[i] = [enqueueTime_i, processingTime_i]` 表示任务 $i$ 在 `enqueueTime_i` 时刻进入队列、需执行 `processingTime_i` 单位时间。单线程 CPU 同一时刻至多执行一项任务，规则如下：

1. CPU 空闲且队列无任务 → 保持空闲；
2. CPU 空闲且队列有任务 → 选择 **执行时间最短** 的任务，并列时选 **下标最小** 者；
3. 任务一旦开始，执行完才可能切换（**不可抢占**）；
4. 完成一项后可立即开始下一项。

返回 CPU 处理任务的 **下标顺序**。

**约束**：

- $\text{tasks.length} = n$，$1 \le n \le 10^5$
- $1 \le \text{enqueueTime}_i, \text{processingTime}_i \le 10^9$

> 💡 本题在本仓库另有[每日题解 1834](../../solution/1801-1900/1834_单线程CPU.md)，两篇为姊妹篇：每日版侧重「时间驱动解锁 + 堆取最值」的直觉切入、SJF 调度理论与面试问答。本篇按周赛复盘视角展开：**逐秒模拟的复杂度账**（为什么必 TLE）、**时间快进为何无损**、**模拟一致性的引理-定理链证明**，以及比赛中最伤的三个翻车点（全部入堆、并列下标、`int` 溢出）的反例复盘。

## 2. 示例

**示例 1**

```text
输入：tasks = [[1,2],[2,4],[3,2],[4,1]]
输出：[0,2,3,1]
解释：t=1 执行 #0 [1,3)；t=3 完成 #0 时 #1、#2 均已就绪，选 2s 的 #2 [3,5)；
      t=5 完成 #2，选 1s 的 #3 [5,6)；t=6 只剩 #1 [6,10)。
```

**示例 2**

```text
输入：tasks = [[7,10],[7,12],[7,5],[7,4],[7,2]]
输出：[4,3,2,0,1]
解释：五项任务同刻到达，纯按 (proc, idx) 字典序执行：
      2s 的 #4 → 4s 的 #3 → 5s 的 #2 → 10s 的 #0 → 12s 的 #1。
```

**示例 3（并列下标 + 时间快进）**

```text
输入：tasks = [[1,2],[1,2],[10,1]]
输出：[0,1,2]
解释：t=1 #0、#1 同时入堆，proc 并列按下标取 #0 [1,3)、再 #1 [3,5)；
      堆空后快进到 t=10 执行 #2 [10,11)。
```

## 3. 解题思路

### 3.1 暴力思路：两种朴素做法都活不过 n = 10^5

**扫描法**：每次 CPU 空闲时线性扫全部未执行任务，筛出已到达者再取最短——单轮 $O(n)$、共 $n$ 轮，总 $O(n^2) = 10^{10}$，超时。

**逐秒模拟**：更符合直觉、也更隐蔽的 TLE——让 `time` 从 0 开始每步 `+1`，每秒先把新到达的任务入堆、CPU 空闲时取堆顶。问题出在**时间跨度**：$n$ 项任务串行执行的总完成时刻最高 $\sum \text{proc}_i \le 10^5 \times 10^9 = 10^{14}$，就算每秒 $10^9$ 次基本操作也要跑约一昼夜，必然超时。

> ⚠️ **比赛教训**：`enqueueTime` 高达 $10^9$ 的模拟题，**时间必须按事件跳跃推进，绝不能逐单位空转**。关键观察是：CPU 的决策只发生在「有任务到达」或「有任务完成」的时刻，其余时间系统状态完全不变。

### 3.2 核心观察：游标解锁 + 小顶堆 + 时间快进

![核心模型：排序数组按 enq 解锁入小顶堆，堆空时时间快进](images/1834_cpu_heap_model.svg)

把模拟拆成三个各司其职的部件：

1. **排序管理到达顺序**：任务按 `enqueueTime` 排序（附原始下标）。到达是时间驱动的——不能一次全进堆，要用游标 `ptr` 逐个放行：`enq ≤ time` 者才入堆。
2. **小顶堆管理就绪集**：堆键为 `(processingTime, index)`，堆顶恰是「执行时间最短、并列则下标最小」——与题目选择规则逐字对应，`pop` 即选择。
3. **空闲即快进**：堆空且仍有未到达任务时，`time` 直接跳到 `sorted[ptr].enq`——中间没有任何事件，跳过去不改变任何后续行为（引理 2 严格化）。

三者互不纠缠：排序管「谁能进堆」，堆管「选谁」，快进管「时钟走到哪」。右下两个翻车点（全部入堆、逐秒空转）正是部件缺失时的症状：没有游标 → ①；没有快进 → ②。

### 3.3 算法流程

![算法流程：外层 while 转 4 个动作](images/1834_cpu_flow.svg)

```text
sorted ← tasks 按 (enq, proc, idx) 排序
time = 0, ptr = 0, heap = ∅, result = []
while ptr < n 或 heap 非空:
    if heap 空:   time = max(time, sorted[ptr].enq)    # ① 快进
    while ptr < n 且 sorted[ptr].enq ≤ time:           # ② 解锁
        push(heap, (sorted[ptr].proc, sorted[ptr].idx)); ptr++
    (proc, idx) = pop(heap)                            # ③ 选择
    result.append(idx); time += proc                   # ④ 执行
return result
```

### 3.4 示例演算

![示例 1 的甘特图演算：事件时刻与就绪堆快照](images/1834_cpu_gantt.svg)

以示例 1 为例，每个选择点先看「堆里有什么」：

| 选择点 | time | 选择前动作 | 就绪堆（proc, idx） | 选中 | 执行区间 |
|--------|------|-----------|---------------------|------|----------|
| ① | 1 | 堆空 → 快进到 1，#0 入堆 | {(2,0)} | #0 | [1,3) |
| ② | 3 | #1、#2 入堆（enq 2,3 ≤ 3） | {(2,2),(4,1)} | #2 | [3,5) |
| ③ | 5 | #3 入堆（enq 4 ≤ 5） | {(1,3),(4,1)} | #3 | [5,6) |
| ④ | 6 | 无新任务 | {(4,1)} | #1 | [6,10) |

返回 `[0,2,3,1]` ✓。注意选择点 ②：`#1` 先到（t=2）但耗时 4，`#2` 后到（t=3）耗时 2——CPU 完全无视到达先后，只看耗时。**到达顺序与执行顺序解耦**，这正是必须用堆维护动态最值、而不是按到达顺序排队的原因。

## 4. 算法细节

1. **排序必须携带下标**：不能原地 `sort(tasks)`——输出要的是原始下标。构造三元组 `(enq, proc, idx)` 再排序，或改为排序下标数组。
2. **堆键是 `(proc, idx)` 双关键字**：C++ 用 `priority_queue<pair<int,int>, vector<...>, greater<...>>`，`pair` 字典序比较恰好实现「先比 proc、并列比 idx」；Python `heapq` 对元组天然按字典序。
3. **入堆后 enq 即弃**：任务进了堆就只以 `(proc, idx)` 身份参与比较，堆中无需保留 `enq`，多存反而干扰并列判定。
4. **快进写 `max(time, enq)` 是防御式**：由就绪集不变量（引理 1），堆空时必有 `sorted[ptr].enq > time`，直接赋值也对；`max` 零成本兜底，防止把时钟拨回过去。
5. **同 enq 任务的排序次序无关紧要**：它们会在同一选择点前统一入堆，相对次序由堆重排——排序在 `enq` 相同时按 `proc` 还是 `idx` 续排都不影响正确性。
6. **C++ 时钟用 `long long`**：全部任务执行完的时刻上界 $\sum \text{proc}_i \le 10^{14}$，`int` 必炸；Python 大整数无此虞。

## 5. 正确性证明

**引理 1（就绪集不变量）**：在每个选择点（即将 `pop` 堆顶）时刻 $T$，堆中元素恰为 $\{i : \text{enq}_i \le T,\ i\ \text{未执行}\}$。

**证明**：对选择轮次 $k$ 归纳。$k=1$ 前：堆空触发快进，$T = \max(0, \min_i \text{enq}_i) \ge 1$；入堆循环把所有 $\text{enq}_i \le T$ 的任务入堆，且无任务被执行，成立。设第 $k$ 轮成立，弹出的任务 $j$ 使时钟推进到下一选择点 $T'$（$T' = T + p_j$；若途中堆空则经引理 2 的快进落到最小剩余 $\text{enq}$，论证相同）：第 $k+1$ 轮的入堆循环把所有 $\text{enq} \in (T, T']$ 的任务补入；$\text{enq} \le T$ 的未执行者由归纳假设已在堆且未被弹出（本轮只弹出 $j$）；已执行者已离堆。故不变量在第 $k+1$ 轮保持。∎

**引理 2（快进无损）**：堆空时把 `time` 跳到 `sorted[ptr].enq`（最小未入堆 `enq`，记为 $T'$），不改变任何任务的就绪判定与选择结果。

**证明**：堆空时由引理 1，所有 $\text{enq} \le T$ 的任务已执行，剩余任务均 $\text{enq} > T$，最小者即 $T'$。开区间 $(T, T')$ 内无任何到达事件，就绪集保持为空；由题意 CPU 在此期间只能空闲，系统状态除时钟外零变化。跳到 $T'$ 后的入堆与选择，与逐秒推进到 $T'$ 再执行完全一致。∎

**引理 3（堆序即规则）**：就绪集中 `(proc, idx)` 字典序最小者，恰为题目规则选中的任务。

**证明**：`pair`/元组比较先比第一关键字 `proc`，严格小者胜；并列时比第二关键字 `idx`。这正是「执行时间最短，若并列选下标最小」的形式化重述。∎

**定理**：算法输出恰为 CPU 的处理顺序。

**证明**：对选择轮次归纳，证每轮算法与真实 CPU 做出相同选择并推进相同时钟。由引理 1，两边的就绪集相同；由引理 3，从同一集合中选出同一任务 $j$；两边的时钟均推进 $p_j$（真实 CPU 在空闲期的行为由引理 2 保证与快进等价）。故 $n$ 轮选择逐轮相同，且两边都恰执行 $n$ 项任务后终止。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序 $O(n \log n)$；每个任务恰入堆、出堆各一次，堆操作共 $2n$ 次、每次 $O(\log n)$；快进至多 $n$ 次、每次 $O(1)$。内层解锁 `while` 每轮使 `ptr++`，游标单调推进使总迭代恰 $n$ 次（摊还），不与外层相乘。
- **空间复杂度**：$O(n)$。排序三元组数组 $O(n)$，堆峰值 $O(n)$（不计输出数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> getOrder(vector<vector<int>>& tasks) {
        int n = tasks.size();
        vector<array<int, 3>> sorted(n);                    // (enq, proc, idx)
        for (int i = 0; i < n; ++i) {
            sorted[i] = {tasks[i][0], tasks[i][1], i};
        }
        sort(sorted.begin(), sorted.end());

        // 小顶堆：(proc, idx)，pair 字典序 = 题目选择规则
        priority_queue<pair<int, int>, vector<pair<int, int>>,
                       greater<pair<int, int>>> pq;
        vector<int> result;
        result.reserve(n);
        long long time = 0;
        int ptr = 0;

        while (ptr < n || !pq.empty()) {
            if (pq.empty()) {
                time = max(time, (long long)sorted[ptr][0]);  // ① 快进
            }
            while (ptr < n && sorted[ptr][0] <= time) {       // ② 解锁
                pq.emplace(sorted[ptr][1], sorted[ptr][2]);
                ++ptr;
            }
            auto [proc, idx] = pq.top();                      // ③ 选择
            pq.pop();
            result.push_back(idx);
            time += proc;                                     // ④ 执行
        }
        return result;
    }
};
```

### Python

```python
import heapq

class Solution:
    def getOrder(self, tasks: List[List[int]]) -> List[int]:
        n = len(tasks)
        sorted_tasks = sorted(
            (enq, proc, i) for i, (enq, proc) in enumerate(tasks)
        )

        result = []
        heap = []          # (proc, idx)，元组字典序 = 题目选择规则
        time = 0
        ptr = 0

        while ptr < n or heap:
            if not heap:
                time = max(time, sorted_tasks[ptr][0])        # ① 快进
            while ptr < n and sorted_tasks[ptr][0] <= time:   # ② 解锁
                heapq.heappush(heap, (sorted_tasks[ptr][1],
                                      sorted_tasks[ptr][2]))
                ptr += 1
            proc, idx = heapq.heappop(heap)                    # ③ 选择
            result.append(idx)                                 # ④ 执行
            time += proc

        return result
```

## 8. 边界情况与易错点

1. **一次性全部入堆（WA）**：忽略 `enq` 约束，CPU 在 t=1 就「偷跑」t=$10^9$ 才到达的任务。反例 `[[1,5],[10^9,1]]`：正确 `[0,1]`，全入堆得 `[1,0]`。
2. **逐秒推进（TLE）**：时间跨度最高 $\sum \text{proc} \approx 10^{14}$，必须事件式快进——决策只发生在「到达」与「完成」时刻。
3. **并列 proc 忘比下标（WA）**：堆只存 `proc` 时同耗任务次序不定；若并列时补比的是 `enq` 而非 `idx`，`[[1,2],[1,2],[10,1]]` 会输出错序——正确答案 `[0,1,2]`。
4. **完成时刻的到达用 ≤（易错）**：`enq ≤ time` 的等号必须保留——示例 1 的 #2 恰在 t=3 到达并同刻被选中，写成 `<` 会漏选。
5. **C++ `int` 溢出（WA）**：`time` 累加可达 $10^{14} \gg 2^{31}-1$，必须 `long long`。
6. **快进分支的 `ptr` 有效性**：进入「堆空」分支时外层条件保证 `ptr < n`，访问 `sorted[ptr]` 安全；若重排代码顺序，勿在 `ptr = n` 时解引用。
7. **两端极端天然覆盖**：`n = 1` 单任务、示例 2 的全部同刻到达（退化为纯 `(proc, idx)` 排序），均无需特判。
