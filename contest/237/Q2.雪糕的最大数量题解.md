# LeetCode 雪糕的最大数量 题解

## 1. 题目概述

- **标题 / 题号**：雪糕的最大数量（#1833，medium）
- **链接**：https://leetcode.cn/problems/maximum-ice-cream-bars/
- **来源**：LeetCode 第 237 场周赛 Q2
- **难度**：中等
- **标签**：贪心、排序、计数排序、数组

**题意**：商店有 `n` 支雪糕，`costs[i]` 是第 `i` 支的价格。Tony 有 `coins` 元现金，想买**尽可能多**的雪糕（可按任意顺序购买）。返回能买到的最大数量。

**约束**：

- $\text{costs.length} = n$
- $1 \le n \le 10^5$
- $1 \le \text{costs}[i] \le 10^5$
- $1 \le \text{coins} \le 10^8$

> ⚠️ **题面硬性要求**：必须用**计数排序**解决（题面原句「你必须使用计数排序解决此问题」）。幸运的是值域恰好很小（$\text{costs}[i] \le 10^5$），这正是计数排序的甜区。

## 2. 示例

**示例 1**

```text
输入：costs = [1,3,2,4,1], coins = 7
输出：4
解释：买下标 0、1、2、4 的雪糕，总价 1 + 3 + 2 + 1 = 7
```

**示例 2**

```text
输入：costs = [10,6,8,7,7,8], coins = 5
输出：0
解释：钱不够买任何一支雪糕
```

**示例 3**

```text
输入：costs = [1,6,3,1,2,5], coins = 20
输出：6
解释：全部买下，总价 1 + 6 + 3 + 1 + 2 + 5 = 18
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子集再检验总价，$2^n$ 种组合在 $n = 10^5$ 下完全不可行。换 DP 视角：这是「容量 `coins`、每件物品价值恒为 1」的 0-1 背包，但 `coins` 高达 $10^8$，DP 表直接爆内存——而且每件物品价值全相同，用通用背包显然杀鸡用牛刀，暗示存在更直接的贪心结构。

### 3.2 核心观察：等贡献、异代价 → 先买最便宜的

![核心观察：交换论证——贵的换成便宜的，数量不变总价不增](images/icecream_exchange_argument.svg)

每支雪糕对「数量」的贡献都是 **+1**（等贡献），但价格各异（异代价）。要让支数最多，直觉是**便宜的优先**。严谨性由**交换论证**保证：

> 若某个可行方案买了较贵的 $b$，却漏掉了更便宜的 $a$（$\text{costs}[a] \le \text{costs}[b]$），把 $b$ 换成 $a$：**支数不变、总价不增**，仍是可行方案。反复交换，任何方案都能在不损失支数的前提下调整成「最便宜前缀」的形态——所以最优解就是排序后从最便宜开始、能买则买的最长前缀。

反过来看不排序的危害：`[1,3,2,4,1]` 按原序贪心，买到 `[1,3,2]`（花 6）后遇 4 卡住，漏掉了第二支 1 元的雪糕；排序成 `[1,1,2,3,4]` 后能买 4 支。**必须先建立「便宜在前」的次序**。

### 3.3 算法流程：计数排序 + 按价位批量购买

![算法流程：建频率表后从价位 1 向上扫描，能买则批量买](images/icecream_counting_flow.svg)

题面要求计数排序，且值域 $V = 10^5$ 与 $n$ 同阶，恰好契合计数排序的甜区：不比较、只数数。

1. **建频率表**：一遍扫 `costs`，执行 `freq[c]++`，开销 $O(n)$。
2. **从价位 1 到 $V$ 扫描**：价位天然升序，等价于排完序的数组。
3. **批量购买**：价位 `price` 有 `freq[price]` 支，一次买 $can = \min(\text{freq}[price],\ \lfloor \text{coins} / \text{price} \rfloor)$ 支——同价雪糕无差别，无需逐支循环。
4. **提前终止**：一旦 `price > coins`，后面的价位只会更贵，直接 `break`。

### 3.4 示例演算

![示例演算：频率表与逐价位批量购买](images/icecream_walkthrough.svg)

以 `costs = [1,3,2,4,1]`，`coins = 7` 为例。频率表为价位 1×2、2×1、3×1、4×1（等价排序结果 `[1,1,2,3,4]`）：

| 价位 | freq | coins（买前） | can = min(freq, coins/price) | 买后 |
|------|------|---------------|------------------------------|------|
| 1 | 2 | 7 | $\min(2, 7) = 2$ | coins=5，ans=2 |
| 2 | 1 | 5 | $\min(1, 2) = 1$ | coins=3，ans=3 |
| 3 | 1 | 3 | $\min(1, 1) = 1$ | coins=0，ans=4 |
| 4 | 1 | 0 | coins=0 < 4 → break | — |

返回 $4$ ✓

## 4. 算法细节

1. **频率表即排序**：`freq[c]` 记录价格 `c` 的支数；从 1 到 $10^5$ 依序扫描天然升序，省去比较排序的 $O(n \log n)$。
2. **批量购买公式**：$can = \min(\text{freq}[price],\ \lfloor \text{coins} / \text{price} \rfloor)$——同价位要么全买、要么买到钱不够，二者取小。买完后剩余 $\text{coins} \bmod \text{price} < \text{price}$，若下一价位更大必然触发终止。
3. **终止条件**：循环条件带 `coins >= price`（或扫描内判断 `price > coins` 即 `break`）；价位递增保证「买不起当前就买不起后面」的正确性。
4. **溢出核算**：$can \times price \le \text{coins} \le 10^8 < 2^{31} - 1$，`int` 足够；不放心可全程 `long long`（Python 大整数无此问题）。
5. **为什么可以批量**：同价位雪糕完全同质，买哪支无所谓；「逐支买」与「按价位整批买」得到相同的 `ans` 与剩余 `coins`。

## 5. 正确性证明

记排序后价格为 $c_1 \le c_2 \le \cdots \le c_n$，前缀和 $S_k = \sum_{i=1}^{k} c_i$（$S_0 = 0$）。

**引理 1（前缀最小性）**：任意买 $k$ 支的方案，其总价 $\ge S_k$；且取最便宜 $k$ 支恰为 $S_k$。

**证明**：把所选 $k$ 支的价格升序记为 $t_1 \le \cdots \le t_k$。断言对每个 $j$ 均有 $t_j \ge c_j$：若 $t_j < c_j$，则 $t_1, \ldots, t_j$ 是 $j$ 个严格小于 $c_j$ 的价格，但整个数组中严格小于 $c_j$ 的元素至多 $j - 1$ 个（$c_j$ 是第 $j$ 小），所选子集不可能包含更多，矛盾。对 $j$ 求和即总价 $\ge S_k$；取 $T = \{c_1, \ldots, c_k\}$ 时等号成立。∎

**引理 2（可行性单调）**：若 $S_k \le \text{coins}$，则一切 $j < k$ 有 $S_j \le \text{coins}$；若 $S_k > \text{coins}$，则一切 $j > k$ 有 $S_j > \text{coins}$。

**证明**：$c_i \ge 1 > 0$，故前缀和严格递增 $S_0 < S_1 < \cdots < S_n$，两个方向均由单调性直接得出。∎

**定理**：能买到的最大数量为 $k^* = \max\{k : S_k \le \text{coins}\}$（集合为空时 $k^* = 0$）。

**证明**：(≥) 前缀 $\{c_1, \ldots, c_{k^*}\}$ 总价 $S_{k^*} \le \text{coins}$，是可行方案，故最大数量至少为 $k^*$。(≤) 若 $k^* = n$ 则不存在支数更多的方案，显然。若 $k^* < n$，反证某可行方案买到 $k > k^*$ 支：由引理 1 其总价 $\ge S_k \ge S_{k^*+1} > \text{coins}$（最后一步由 $k^*$ 的最大性），与可行性矛盾。∎

**推论**：算法（按价位升序批量购买，直到 `price > coins`）返回 $k^*$。

**证明**：算法扫描到价位 `price` 时，累计购买的恰是排序后所有价格 $\le$ 当前已处理价位的雪糕，即最长可负担前缀；由引理 2，终止发生在第一个 $S_k > \text{coins}$ 处，此时 `ans` 恰为 $k^*$。批量公式与逐支购买等价：同价位雪糕无差别，$\lfloor \text{coins} / \text{price} \rfloor$ 恰为该价位至多可买支数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + V)$，其中 $V = 10^5$。建频率表 $O(n)$，扫值域 $O(V)$；批量购买把同价位的逐支循环压缩为一次乘除。
- **空间复杂度**：$O(V)$，频率数组 `freq` 长 $V + 1$。对照：库排序版为 $O(n \log n)$ 时间 / $O(\log n)$ 排序栈空间。

## 7. 参考代码

### C++（计数排序版，满足题面要求）

```cpp
class Solution {
public:
    int maxIceCream(vector<int>& costs, int coins) {
        const int V = 100000;
        vector<int> freq(V + 1, 0);
        for (int c : costs) freq[c]++;

        int ans = 0;
        for (int price = 1; price <= V && coins >= price; price++) {
            if (freq[price] == 0) continue;
            int can = min(freq[price], coins / price);
            ans += can;
            coins -= can * price;
        }
        return ans;
    }
};
```

### Python（计数排序版）

```python
class Solution:
    def maxIceCream(self, costs: List[int], coins: int) -> int:
        V = 100000
        freq = [0] * (V + 1)
        for c in costs:
            freq[c] += 1

        ans = 0
        for price in range(1, V + 1):
            if coins < price:
                break
            if freq[price] == 0:
                continue
            can = min(freq[price], coins // price)
            ans += can
            coins -= can * price
        return ans
```

### Python（库排序对照版，验证贪心本质）

```python
class Solution:
    def maxIceCream(self, costs: List[int], coins: int) -> int:
        costs.sort()
        ans = 0
        for c in costs:
            if c > coins:
                break
            coins -= c
            ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **不排序必错**：`[1,3,2,4,1]` 按原序贪心只得 3 支，排序后 4 支。购买顺序任意 ⇒ 必须先建立「便宜在前」的次序。
2. **提前终止依赖升序**：只有确认后续更贵才能 `break`；计数排序按价位递增扫描天然满足，未排序时「当前买不起」不代表「后面都买不起」。
3. **整除下取整**：C++ 的 `coins / price` 对非负整数即下取整，恰为该价位至多可买支数；Python 用 `//`。
4. **溢出误判**：`can * price ≤ coins ≤ 10^8`，`int` 不溢出——注意 `can` 同时受 `coins / price` 约束，勿按 $n \times \max(\text{costs})$ 误估成 $10^{10}$。
5. **值域即桶数**：桶开 $10^5 + 1$，价格从 1 起；若值域升到 $10^9$，计数排序空间爆炸，只能回比较排序。
6. **两端的极端**：全买得起（示例 3，`ans = n`）与全买不起（示例 2，`ans = 0`），循环条件天然覆盖，无需特判。
