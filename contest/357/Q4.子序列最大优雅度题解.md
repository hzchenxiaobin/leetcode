# LeetCode 子序列最大优雅度 题解

## 1. 题目概述

- **标题 / 题号**：子序列最大优雅度（#2813，hard）
- **链接**：https://leetcode.cn/problems/maximum-elegance-of-a-k-length-subsequence/
- **来源**：LeetCode 第 357 场周赛 Q4
- **难度**：困难
- **标签**：贪心、排序、栈、哈希表

**题意**：给定 $n$ 件物品，每件物品表示为 `items[i] = [profit_i, category_i]`，分别代表利润和类别。选择恰好 $k$ 件物品组成子序列，其优雅度定义为

$$
\text{elegance} = \text{totalProfit} + \text{distinctCategories}^2,
$$

其中 $\text{totalProfit}$ 是所选物品的利润总和，$\text{distinctCategories}$ 是不同类别的数量。求最大优雅度。

子序列只需保持所选物品的相对顺序；由于优雅度与排列顺序无关，本题实际上只需决定**选哪些物品**。

**约束**：

- $1 \le n = \text{items.length} \le 10^5$
- $1 \le \text{profit}_i \le 10^9$
- $1 \le \text{category}_i \le n$
- $1 \le k \le n$

> **数据范围提示**：利润总和最大可达 $10^{14}$，类别数平方最大可达 $10^{10}$。C++ 中累计利润与答案都必须使用 `long long`。

## 2. 示例

**示例 1**

```text
输入：items = [[3,2],[5,1],[10,1]], k = 2
输出：17
解释：选择 [3,2] 和 [10,1]。
      总利润为 3 + 10 = 13，类别数为 2，优雅度为 13 + 2² = 17。
```

**示例 2**

```text
输入：items = [[3,1],[3,1],[2,2],[5,3]], k = 3
输出：19
解释：选择 [3,1]、[2,2] 和 [5,3]。
      总利润为 10，类别数为 3，优雅度为 10 + 3² = 19。
```

**示例 3**

```text
输入：items = [[1,1],[2,1],[3,1]], k = 3
输出：7
解释：所有物品都必须选择。总利润为 6，类别数为 1，优雅度为 6 + 1² = 7。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有长度为 $k$ 的子序列，计算利润和与类别数，共有 $\binom{n}{k}$ 种方案，无法承受。

困难来自两个目标之间的冲突：

- 只追求利润，可能选到许多同类别物品；
- 只追求类别数，又可能被迫放弃高利润物品。

直接枚举类别或枚举物品都不可行，需要用交换把不同类别数下的最优利润依次求出来。

### 3.2 核心观察：先取前 k 项，再用重复项换新类别

将所有物品按利润**从大到小**排序，先选择前 $k$ 件，记这个方案为 $S_0$。

$S_0$ 有两个重要性质：

1. 在所有大小为 $k$ 的方案中，它的利润总和最大；
2. 同类别物品中，只有第一件增加了类别数，其余物品都是**可替换的重复项**。

设 $S_0$ 有 $d$ 个类别。若某件未选物品属于一个新类别，可以用它替换一件已选的重复类别物品：

- 替换后仍恰好有 $k$ 件物品；
- 被替换物品的类别仍有其他物品保留，所以该类别不会消失；
- 新物品带来一个类别，类别数由 $d$ 变为 $d+1$；
- 利润变化为 $p_{new}-p_{removed}$。

为了让利润损失最小，每次应当：

- **换出**当前利润最小的重复类别物品；
- **换入**当前利润最大的未选新类别物品。

排序后遍历物品，每个类别第一次被处理到的物品就是该类别中利润最高者；初始重复项按利润降序入栈，因此**栈顶正好是利润最小的重复项**。

### 3.3 为什么每一步都要更新答案

设当前类别数为 $d$，换成新类别后，类别数平方的增量为

$$
(d+1)^2-d^2=2d+1.
$$

若换出利润为 $r$、换入利润为 $p$，优雅度的实际变化为

$$
\Delta = p-r+2d+1.
$$

它可能为正，也可能为负。随着替换继续，利润总和单调不增，而类别数平方单调递增，两者之和并不单调，所以不能只返回最后一次替换的结果，而要对**初始状态及每个交换前缀**取最大值。

### 3.4 算法流程

1. 按利润降序排序。
2. 选择前 $k$ 件物品，累计 `total`。
3. 用集合 `categories` 记录已选类别；若当前物品的类别已经出现，就把它的利润加入反悔栈 `dup`。
4. 用初始方案计算一次答案。
5. 从第 $k+1$ 件物品继续按降序扫描：
   - 类别已经出现：跳过，替换它不会增加类别数；
   - 类别未出现且 `dup` 非空：弹出栈顶利润 $r$，执行替换，`total += p-r`，加入新类别并更新答案；
   - `dup` 为空：不再存在可换出的重复项，可以结束。
6. 返回所有状态中的最大优雅度。

### 3.5 示例演算

以示例 2 为例，排序后得到

```text
[[5,3], [3,1], [3,1], [2,2]]
```

初始选择前三项：

| 已选物品 | total | 类别集合 | dup（栈顶在右） | 优雅度 |
|---|---:|---|---|---:|
| [5,3]、[3,1]、[3,1] | 11 | {1,3} | [3] | 11 + 2² = 15 |

扫描到 `[2,2]`，类别 2 尚未出现，弹出重复项利润 3：

| 操作 | total | 类别集合 | 优雅度 |
|---|---:|---|---:|
| 换出利润 3 的重复项，换入 [2,2] | 10 | {1,2,3} | 10 + 3² = 19 |

最大值为 $\max(15,19)=19$。

再看示例 1，初始选择 `[10,1]、[5,1]`，优雅度为 $15+1^2=16$；随后用 `[3,2]` 替换利润 5 的重复项，得到 $13+2^2=17$。这说明**最后一次交换可能更优，也可能更差，必须沿途取最大值**。

## 4. 算法细节

1. **为什么只把重复项放入栈**：换出某类别唯一的已选物品会使该类别消失，无法保证类别数净增 1；换出重复项则不会影响原类别。
2. **为什么栈顶就是最小利润**：物品按利润降序扫描，重复项也按利润降序入栈，所以最后入栈的利润最小，使用 `vector` / 列表尾部即可 $O(1)$ 弹出。
3. **为什么新类别只处理一次**：同一类别第一次扫描到的物品利润最高。若它没有用于交换，之后同类物品利润不更高，换入只会增加利润损失而不会带来更多类别。
4. **为什么可以原地排序**：优雅度只与所选物品有关，与原来的相对顺序无关，因此排序不会改变答案。
5. **整数范围**：`total` 与 `ans` 使用 64 位整数；计算 $d^2$ 前也应确保乘法在 64 位整数中进行。
6. **提前结束**：`dup` 为空时，当前方案的每个类别都只有一件已选物品，此后任何替换都无法净增类别数。

## 5. 正确性证明

**引理 1（初始方案的利润最大性）**：按利润降序选择前 $k$ 件物品，得到所有大小为 $k$ 的方案中利润总和最大的方案。

**证明**：任取一个大小为 $k$ 的方案 $T$。若 $T$ 不是前 $k$ 项，则存在未选物品 $x$ 和已选物品 $y$，使得 $x$ 排在 $y$ 前面，因而 $p_x \ge p_y$。用 $x$ 替换 $y$ 不会减少利润总和。重复这一交换即可得到前 $k$ 项，故其利润总和不小于任意 $T$。∎

**引理 2（替换不变量）**：每次算法执行替换后，方案仍含恰好 $k$ 件物品，类别数恰好增加 1，且利润变化为 $p-r$，其中 $p$ 是换入物品利润，$r$ 是栈顶重复项利润。

**证明**：换入一件、换出一件，物品总数不变。被换出的是重复项，其类别至少还有一件物品保留，所以旧类别不会消失；换入物品的类别此前不存在，因此只新增一个类别。其余物品不变，利润变化自然是 $p-r$。∎

**引理 3（交换前缀的最优性）**：设初始方案有 $d_0$ 个类别。完成 $s$ 次替换后，算法得到恰有 $d_0+s$ 个类别的方案，并在所有该类别数的方案中取得最大利润总和。

**证明**：对 $s$ 使用交换论证。$s=0$ 时由引理 1 成立。考虑从 $d$ 个类别扩展到 $d+1$ 个类别：任何这样的扩展都必须加入一个此前未出现类别的物品，并移除一件重复类别物品，否则无法同时保持物品数为 $k$ 且类别数净增 1。排序扫描保证当前换入的是所有可用新类别中利润最高的物品；栈保证换出的是当前所有重复项中利润最低的物品。因此这次交换使利润损失最小。若某个同类别数方案采用了不同交换，把这两处选择分别换成算法选择的物品，利润总和不会下降；由归纳假设，交换前的方案也可转化为算法的前一状态而不降低利润。故替换后的方案在 $d+1$ 个类别下利润最大。∎

**定理**：算法返回最大优雅度。

**证明**：初始方案的利润总和已经全局最大，因此类别数少于 $d_0$ 的方案不可能更优：它们的利润不更高，类别数平方还更小。对于类别数 $d_0+s$（$s\ge 0$）的方案，由引理 3，算法对应的交换前缀具有最大利润总和，因而也具有该类别数下的最大优雅度。算法对初始状态和每个交换前缀都取最大值，覆盖了所有可能成为最优解的类别数，所以返回全局最大优雅度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n\log n)$，瓶颈是排序。两次扫描合计 $O(n)$，集合与栈操作均为 $O(1)$ 均摊。
- **空间复杂度**：辅助集合与栈最多保存 $O(k)$ 个元素；若计入排序使用的辅助空间，整体可记为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long findMaximumElegance(vector<vector<int>>& items, int k) {
        sort(items.begin(), items.end(), [](const auto& a, const auto& b) {
            return a[0] > b[0];
        });

        long long total = 0;
        unordered_set<int> categories;
        vector<int> dup;

        for (int i = 0; i < k; ++i) {
            int p = items[i][0], c = items[i][1];
            total += p;
            if (categories.count(c)) {
                dup.push_back(p);
            } else {
                categories.insert(c);
            }
        }

        long long d = categories.size();
        long long ans = total + d * d;

        for (int i = k; i < (int) items.size() && !dup.empty(); ++i) {
            int p = items[i][0], c = items[i][1];
            if (categories.count(c)) {
                continue;
            }
            total += p - dup.back();
            dup.pop_back();
            categories.insert(c);
            ++d;
            ans = max(ans, total + d * d);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findMaximumElegance(self, items: List[List[int]], k: int) -> int:
        items.sort(key=lambda item: -item[0])

        total = 0
        categories = set()
        dup = []

        for p, c in items[:k]:
            total += p
            if c in categories:
                dup.append(p)
            else:
                categories.add(c)

        d = len(categories)
        ans = total + d * d

        for p, c in items[k:]:
            if not dup:
                break
            if c in categories:
                continue
            total += p - dup.pop()
            categories.add(c)
            d += 1
            ans = max(ans, total + d * d)

        return ans
```

## 8. 边界情况与易错点

1. **初始状态也要更新答案**：可能任何新类别交换都不划算，答案就是前 $k$ 项的优雅度。
2. **不能换出唯一类别物品**：那样旧类别消失，新类别加入，类别数未必增加，交换模型会被破坏。
3. **不能换入已出现类别**：它不会增加类别数，而排序后利润又不可能超过被换出项，因此无收益。
4. **栈中只保存利润不够的场景**：本题只需累计利润，所以保存利润即可；若题目要求输出具体方案，还需同时记录物品下标。
5. **不要只在最后计算答案**：利润递减、类别数平方递增，优雅度没有单调性。
6. **重复项入栈顺序不要颠倒**：从利润降序序列中收集重复项后，最小利润在栈尾，代码使用 `back()` / `pop()`。
7. **C++ 溢出**：答案可达 $10^{14}+10^{10}$，`int` 无法保存，返回值、累计利润和类别数平方均需使用 `long long`。
8. **前 k 项不是最终最优解的固定骨架**：它只是最大利润的起点；最终答案可能换掉其中多件重复物品，不能把初始选择直接当作最优方案。
