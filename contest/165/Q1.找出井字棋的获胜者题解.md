# LeetCode 找出井字棋的获胜者 题解

## 1. 题目概述

- **标题 / 题号**：找出井字棋的获胜者（#1275，easy）
- **链接**：https://leetcode.cn/problems/find-winner-on-a-tic-tac-toe-game/
- **来源**：LeetCode 第 165 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、矩阵、模拟

**题意**：A 和 B 在 $3 \times 3$ 棋盘上轮流落子，A 先手、永远下 `X`，B 下 `O`，`moves[i] = [r_i, c_i]` 按时间顺序给出每次落点。只要有某一方在**行、列、两条对角线**之一上占满 3 格，游戏立刻结束；若 9 格被填满仍无人三连，则为平局。要求返回 `"A"`、`"B"`、`"Draw"`（棋盘已满且无人获胜）或 `"Pending"`（还有人能走）。

关键在于：`moves` 保证是一局**合法对局**——落点不重复、且一旦有人三连就**不会再有后续手**。这条保证让「边下边判、一命中就返回」成为正确做法。

**约束**：

- $1 \le \lvert \text{moves} \rvert \le 9$
- $\text{moves}[i]$ 长度恒为 $2$，且 $0 \le r_i, c_i \le 2$
- `moves` 中**没有重复**的坐标
- `moves` 遵循井字棋规则（合法对局）

## 2. 示例

**示例 1**

```text
输入：moves = [[0,0],[2,0],[1,1],[2,1],[2,2]]
输出："A"
解释：A 依次落在 (0,0) (1,1) (2,2)，占满主对角线，第 5 手即获胜。
```

**示例 2**

```text
输入：moves = [[0,0],[1,1],[0,1],[0,2],[1,0],[2,0]]
输出："B"
解释：B 依次落在 (1,1) (0,2) (2,0)，占满副对角线（r + c == 2）。
```

**示例 3**

```text
输入：moves = [[0,0],[1,1],[2,0],[1,0],[1,2],[2,1],[0,1],[0,2],[2,2]]
输出："Draw"
解释：9 格全部填满，但没有任何一方三连，平局。
```

**示例 4（自补，考察 Pending）**

```text
输入：moves = [[0,0],[1,1],[2,0]]
输出："Pending"
解释：只走了 3 手，棋盘还有 6 个空位，游戏未结束。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法：开一个 $3 \times 3$ 的格子数组，按 `moves` 顺序把第 $i$ 手填成 `X`（$i$ 偶）或 `O`（$i$ 奇），最后检查 8 条线（3 行 + 3 列 + 2 对角线）里有没有整条都是同一个非空字符。

- 时间：$O\bigl(\lvert\text{moves}\rvert + 8 \times 3\bigr)$，本题规模下就是一个常数；
- 空间：$O(1)$（9 个格子）。

**这个做法完全能过**，签到题不必为了炫技而绕路。但它有两个毛病：一是必须等**全部**落子结束才能判定，无法在中途回答「现在谁赢」；二是每次判定都要重新扫一遍棋盘，若把题目改成「每落一子都输出当前状态」（这就是会员题 348 的要求），复杂度立刻退化成 $O(n^2)$。

### 3.2 核心观察：胜负只取决于「某条线的 3 格归谁」

![井字棋的 8 条线与计数器](images/wc165_q1_three_lines_model.svg)

棋盘上能决定胜负的线一共只有 $3 + 3 + 1 + 1 = 8$ 条，且**每条线恰好 3 格**。于是「某方在这条线上三连」等价于「这条线的 3 格全是这方的子」，等价于「这方在这条线上的棋子数等于 3」。

给每个玩家 $p \in \{0, 1\}$（$0$ 表示 A/X，$1$ 表示 B/O）各维护一套计数器：

- `row[p][r]`：玩家 $p$ 落在第 $r$ 行的子数，$r \in \{0,1,2\}$；
- `col[p][c]`：玩家 $p$ 落在第 $c$ 列的子数；
- `diag[p]`：玩家 $p$ 落在主对角线（$r = c$）的子数；
- `anti[p]`：玩家 $p$ 落在副对角线（$r + c = 2$）的子数。

玩家 $p$ 在 $(r, c)$ 落一子，只会让 **4 个**计数器加一：`row[p][r]`、`col[p][c]`，以及 $r = c$ 时的 `diag[p]`、$r + c = 2$ 时的 `anti[p]`。所以「这一手有没有造成三连」只需要检查这 4 个数是否变成 3——不用看棋盘，也不用看其他任何格子。

> 💡 一句话：把「扫 8 条线共 24 格」换成「查这 4 个数」，判定与棋盘规模解耦。

### 3.3 算法流程

![一次遍历的计数流程](images/wc165_q1_counter_flow.svg)

1. 初始化 16 个计数器为 $0$；
2. 枚举 $i = 0, 1, \dots, n-1$，取 $p = i \bmod 2$、$(r, c) = \text{moves}[i]$；
3. 落子：`++row[p][r]`、`++col[p][c]`，若 $r = c$ 再 `++diag[p]`，若 $r + c = 2$ 再 `++anti[p]`；
4. 若这 4 个计数器中任一等于 $3$，立刻返回 `p == 0 ? "A" : "B"`；
5. 循环正常结束说明无人三连：$n = 9$ 返回 `"Draw"`，否则返回 `"Pending"`。

第 4 步之所以能**立刻**返回，是因为输入保证合法对局——一旦三连，游戏终结，后面不可能再有落子，所以首个命中者就是最终胜者。

### 3.4 示例演算

![示例 1 的计数轨迹](images/wc165_q1_walkthrough.svg)

对示例 1（`moves = [[0,0],[2,0],[1,1],[2,1],[2,2]]`），只列出被改动的那几个计数器：

| 步 $i$ | 落点 | 玩家 | 变化的计数 | 是否出现 3 |
|--------|------|------|------------|------------|
| 0 | (0,0) | A | `row0=1` `col0=1` `diag=1` | 否 |
| 1 | (2,0) | B | `row2=1` `col0=1` | 否 |
| 2 | (1,1) | A | `row1=1` `col1=1` `diag=2` `anti=1` | 否 |
| 3 | (2,1) | B | `row2=2` `col1=2` | 否 |
| 4 | (2,2) | A | `row2=1` `col2=1` **`diag=3`** | **是 → 返回 “A”** |

注意第 2 步的 $(1,1)$ 同时落在主、副两条对角线上，所以 `diag` 与 `anti` 都被加一；第 4 步只有 `diag` 走到 3，正是 A 的那条主对角线。

再验示例 2：B 的三手是 $(1,1)$、$(0,2)$、$(2,0)$，三者都满足 $r + c = 2$，所以 `anti[B]` 依次为 $1, 2, 3$，第 6 手返回 `"B"`，与题面一致。

## 4. 算法细节

1. **手番由下标决定，不需要额外状态**：第 $i$ 手（0 基）属于 A 当且仅当 $i$ 是偶数，写成 `i & 1` 或 `i % 2` 都可以，省掉一个 `bool turn` 变量。
2. **两条对角线要分开数**：主对角线条件是 $r = c$，副对角线条件是 $r + c = 2$（即 $r + c = N - 1$，$N = 3$）。$(1,1)$ 同属两条线，会同时让两个计数器加一，这是正确行为而不是重复计数。
3. **用 `== 3` 还是 `>= 3`**：合法对局里单条线最多 3 格，计数器不可能超过 3；但写 `>= 3` 更稳，遇到非法输入也不会漏判。本文代码用 `== 3`，并在证明中依赖「每条线恰好 3 格」这一事实。
4. **只检查这 4 个计数器就够**：落子只可能改变与 $(r, c)$ 相关的行、列、两条对角线，其他线的计数没有变化，第 $i$ 手之前也没人赢过，所以不可能出现「别人的线刚好凑满」的情况。
5. **终局判定只看手数**：`n == 9` 就是棋盘满（`moves` 无重复落点），不需要维护空格计数；`n < 9` 且无人获胜则一定还有空位可下。
6. **不建棋盘不担心覆盖**：题目保证 `moves` 无重复坐标；若要在变体里允许重复，必须先判「该格已被占用」再更新计数，否则计数器会虚高。
7. **等价的「只查最后一手」写法**：胜者的最后一手必然参与构成三连线，因此也可以先化简出胜者、再只检查 `moves.back()` 所在的行/列/对角线。两种写法等价，但计数法在「每手都要输出状态」的场景下更有优势。
8. **返回值是四种字符串**：`"A"`、`"B"`、`"Draw"`、`"Pending"`，注意首字母大写、拼写准确，`Pending` 不是 `"Playing"`。

## 5. 正确性证明

**引理 1（手番）**：对任意 $0 \le i < n$，第 $i$ 手由 A 落 `X`，当且仅当 $i$ 为偶数。

**证明**：A 先手，两人严格轮流落子，合法对局不存在「跳过」或「连下两手」。对 $i$ 归纳：$i = 0$ 时是 A；若第 $i$ 手是 A 则第 $i+1$ 手是 B，反之亦然，故奇偶性与玩家一一对应。∎

**引理 2（计数正确性）**：处理完第 $i$ 手后，`row[p][r]` 等于前 $i+1$ 手中玩家 $p$ 落在第 $r$ 行的子数；`col[p][c]`、`diag[p]`、`anti[p]` 同理，分别统计第 $c$ 列、主对角线与副对角线。

**证明**：对 $i$ 归纳。$i = -1$（尚未落子）时四个计数器全为 $0$，等式成立。设处理完第 $i-1$ 手后成立，考察第 $i$ 手：由引理 1 玩家为 $p = i \bmod 2$，落点 $(r, c)$。该子确实落在第 $r$ 行、第 $c$ 列，故 `row[p][r]`、`col[p][c]` 各加一是正确的；当 $r = c$ 时它落在主对角线，当 $r + c = 2$ 时它落在副对角线，代码恰好在这两种情况下分别给 `diag[p]`、`anti[p]` 加一。其余计数器与这一手无关，保持原值也正确。∎

**引理 3（三连判定）**：处理完第 $i$ 手后，玩家 $p$ 在行 $r$、列 $c$、主对角线、副对角线之一上三连，当且仅当对应计数器等于 $3$。

**证明**：每条线恰好含 3 个格子，所以「该线 3 格全是 $p$ 的子」等价于「$p$ 在这条线上的子数为 3」。由引理 2，计数器正是这个子数；又因为计数器只统计 $p$ 自己的子，另一方的子不会混入，故两者等价。∎

**引理 4（合法性 ⇒ 首次命中即终局）**：若处理完第 $i$ 手后某个计数器为 $3$，则不存在第 $j > i$ 手。

**证明**：由引理 3，此时玩家 $p$ 已三连，按规则「只要有 3 个相同的棋子排成一条直线，游戏结束」，而题面保证 `moves` 是一局合法对局，故 $i$ 就是最后一手。∎

**定理**：算法返回的字符串与题目要求一致。

**证明**：分三种情形。

1. **循环中命中**：设首次命中发生在第 $i$ 手、玩家为 $p$。由引理 3，$p$ 在该手之后三连；由引理 4，$i$ 是最后一手，故 $p$ 是唯一的获胜者，返回 `"A"`（$p = 0$）或 `"B"`（$p = 1$）正确。又因为此前从无计数器到 3，由引理 3 逆否命题可知此前无人获胜，所以「首次」命中正是获胜的那一手，不存在误判。
2. **循环结束、$n = 9$**：全程无计数器到 3，由引理 3 逆否命题，任何玩家在任何线上都没有三连；9 手且落点互不重复（题目保证）意味着 9 格全满，因此是平局，返回 `"Draw"` 正确。
3. **循环结束、$n < 9$**：同样无人三连；9 格中只占了 $n < 9$ 格，至少还有一个空位，双方都还能继续落子，因此游戏未结束，返回 `"Pending"` 正确。

三种情形互斥且穷尽，故返回值恒与题意一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$，其中 $n = \lvert\text{moves}\rvert \le 9$。每手做 $O(1)$ 次自增（最多 4 次）与 4 次比较，无内层循环、无棋盘扫描；总操作数与棋盘大小 $N^2$ 无关。
- **空间**：$O(1)$。仅 $2 \times 3 \times 2 + 2 \times 2 = 16$ 个整数，不建 $3 \times 3$ 棋盘，也不开哈希表（题目标签虽含「哈希表」，但本题用定长数组即可，等价且更省）。
- **与暴力对比**：暴力一次终局判定是 $8 \times 3 = 24$ 次比较，且必须等全部落子结束；计数法把「判定」摊到每一手上，若改成「每手都输出状态」，总代价仍是 $O(n)$，而暴力会退化成 $O(n^2)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string tictactoe(vector<vector<int>>& moves) {
        int row[2][3] = {}, col[2][3] = {};   // 两名玩家 × 3 行 / 3 列
        int diag[2] = {}, anti[2] = {};       // 主对角线 r == c，副对角线 r + c == 2
        for (int i = 0; i < (int)moves.size(); ++i) {
            int r = moves[i][0], c = moves[i][1];
            int p = i & 1;                    // 0 -> A(X)，1 -> B(O)
            ++row[p][r];
            ++col[p][c];
            if (r == c) ++diag[p];
            if (r + c == 2) ++anti[p];
            // 落子只可能让这 4 条线凑满，检查它们即可
            if (row[p][r] == 3 || col[p][c] == 3 || diag[p] == 3 || anti[p] == 3)
                return p == 0 ? "A" : "B";
        }
        return (int)moves.size() == 9 ? "Draw" : "Pending";
    }
};
```

### Python

```python
class Solution:
    def tictactoe(self, moves: list[list[int]]) -> str:
        row = [[0, 0, 0], [0, 0, 0]]          # row[p][r]：玩家 p 在第 r 行的子数
        col = [[0, 0, 0], [0, 0, 0]]          # col[p][c]：玩家 p 在第 c 列的子数
        diag = [0, 0]                         # 主对角线 r == c
        anti = [0, 0]                         # 副对角线 r + c == 2

        for i, (r, c) in enumerate(moves):
            p = i & 1                         # 0 -> A(X)，1 -> B(O)
            row[p][r] += 1
            col[p][c] += 1
            if r == c:
                diag[p] += 1
            if r + c == 2:
                anti[p] += 1
            # 只需检查这一手触及的 4 条线
            if row[p][r] == 3 or col[p][c] == 3 or diag[p] == 3 or anti[p] == 3:
                return "A" if p == 0 else "B"

        return "Draw" if len(moves) == 9 else "Pending"
```

## 8. 边界情况与易错点

1. **8 手无人获胜 → `Pending` 而不是 `Draw`**：棋盘还剩 1 格，游戏继续。把 `n == 9` 写成 `n >= 8` 是最常见的错误。
2. **9 手无人三连 → `Draw`**：示例 3 就是这种局面；此时所有计数器都 $\le 2$，循环自然走完。
3. **先判胜者、再判满盘**：判断顺序必须是「命中就返回」，否则 9 手时若有人三连（合法输入下 9 手必有结果）会被误判成平局。代码里 return 在循环内、满盘判断在循环后，顺序天然正确。
4. **副对角线的条件写成 $r + c = 2$**：$N = 3$ 时副对角线是 $(0,2),(1,1),(2,0)$，容易错写成 $r + c = 3$ 或 $r = 2 - c$ 的变体（后者其实等价，但要确认符号）。
5. **$(1,1)$ 属于两条对角线**：它会同时让 `diag` 和 `anti` 加一，这不是重复计数；若只更新其中一个，示例 2 会漏判。
6. **`moves` 长度下界是 1**：不会出现空数组；即便出现，代码返回 `"Pending"`（`0 != 9`）也是合理语义，不会越界。
7. **不可能有人赢却返回 `Draw`**：`Draw` 只由「循环结束 + 满 9 手」触发，而循环结束意味着无人三连，两者一致；若把 `len(moves) == 9` 的判断挪到循环前，就会把「第 9 手绝杀」错判为平局。
8. **返回值大小写**：`"Draw"`、`"Pending"`、`"A"`、`"B"`，LeetCode 按字符串精确比对，`"draw"` 或 `"PENDING"` 都会 WA。
