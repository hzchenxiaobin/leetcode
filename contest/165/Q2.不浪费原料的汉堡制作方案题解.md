# LeetCode 不浪费原料的汉堡制作方案 题解

## 1. 题目概述

- **标题 / 题号**：不浪费原料的汉堡制作方案（#1276，medium）
- **链接**：https://leetcode.cn/problems/number-of-burgers-with-no-waste-of-ingredients/
- **来源**：LeetCode 第 165 场周赛 Q2
- **难度**：中等
- **标签**：数学

**题意**：给定番茄片数 $T$ 与奶酪片数 $C$。巨无霸汉堡每份消耗 4 片番茄 + 1 片奶酪，小皇堡每份消耗 2 片番茄 + 1 片奶酪。求巨无霸与小皇堡各做多少个，使得两种原料**恰好全部用完**；返回 `[total_jumbo, total_small]`，无解返回 `[]`。

**约束**：

- $0 \le \text{tomatoSlices} \le 10^7$
- $0 \le \text{cheeseSlices} \le 10^7$
- 边界：$T=C=0$ 时答案为 `[0, 0]`（一个汉堡都不做也是合法方案）

## 2. 示例

**示例 1**

```text
输入：tomatoSlices = 16, cheeseSlices = 7
输出：[1, 6]
解释：4×1 + 2×6 = 16 片番茄，1 + 6 = 7 片奶酪，两种原料都不剩。
```

**示例 2**

```text
输入：tomatoSlices = 17, cheeseSlices = 4
输出：[]
解释：两种汉堡消耗的番茄数都是偶数，17 片番茄永远用不完。
```

**示例 3**

```text
输入：tomatoSlices = 4, cheeseSlices = 17
输出：[]
解释：17 片奶酪意味着至少 17 个汉堡、至少 34 片番茄，番茄远远不够。
```

官方另有 `(0, 0) → [0, 0]` 与 `(2, 1) → [0, 1]` 两组，一并在 §3.4 的走查表中验证。

## 3. 解题思路

### 3.1 暴力思路

设巨无霸 $x$ 个、小皇堡 $y$ 个。每份汉堡恰好用 1 片奶酪，因此 $x+y=C$ 是绕不开的硬约束——只要定下 $x$，$y=C-x$ 就定了，再检查 $4x+2(C-x)$ 是否等于 $T$。

最朴素的做法是枚举 $x \in [0, C]$ 逐个验证，时间 $O(C)$；若两重循环枚举 $(x, y)$ 则是 $O(C^2)$。

$C$ 最大 $10^7$：$O(C^2)$ 显然不可行，$O(C)$ 在 C++ 里勉强能过（约 $10^7$ 次迭代），但 Python 很容易超时。更重要的是，本题存在 $O(1)$ 的闭式解，枚举完全是多余的。

### 3.2 核心观察：奶酪定个数，番茄定差价

![两种汉堡的原料配方与方程推导](images/wc165_q2_recipe_model.svg)

把两种汉堡并排看，立刻能读出两条信息：

- **奶酪只和「个数」有关**：巨无霸、小皇堡都只用 1 片奶酪，所以 $x+y=C$，奶酪数直接就是汉堡总数。
- **番茄只和「差价」有关**：两种汉堡都要 2 片番茄「打底」，巨无霸额外多花 2 片，于是 $T = 2(x+y) + 2x = 2C + 2x$——多出来的番茄对数，恰好就是巨无霸的个数。

两式联立立刻得到闭式解：

$$x = \frac{T - 2C}{2}, \qquad y = C - x$$

这正是「鸡兔同笼」：奶酪数是头数，番茄数是脚数，巨无霸是 4 条腿的兔子。

### 3.3 算法流程

![三条判定与闭式求解流程](images/wc165_q2_decision_flow.svg)

$x$、$y$ 必须是**非负整数**，这给出三条判定：

1. **奇偶性**：$T-2C$ 必须为偶数。因为 $2C$ 一定是偶数，等价于 $T$ 为偶数；否则 $x$ 不是整数。
2. **下界**：$x \ge 0 \iff T \ge 2C$，番茄至少要够给每个汉堡「2 片打底」。
3. **上界**：$y \ge 0 \iff x \le C \iff T \le 4C$，巨无霸太多会把奶酪提前耗尽。

三条全部满足则返回 $[x, y]$，否则返回 `[]`。等价的区间说法是：有解 $\iff 2C \le T \le 4C$ 且 $T$ 为偶数。

注意满足三条判定时解是**唯一**的（系数行列式非零），因此不存在「多个方案挑一个」的问题。

### 3.4 示例演算

![五组示例的走查表](images/wc165_q2_walkthrough.svg)

以示例 1 为例：$T-2C = 16-14 = 2$，故 $x = 2/2 = 1$，$y = 7-1 = 6$。回代验证 $4 \times 1 + 2 \times 6 = 16$ 片番茄、$1+6 = 7$ 片奶酪，两组原料同时清零，输出 `[1, 6]`。

示例 2 的 $T-2C = 9$ 是奇数，示例 3 的 $T-2C = 4-34 = -30 < 0$，分别被奇偶判定与下界判定拦下，输出 `[]`。而 `(0, 0)` 与 `(2, 1)` 的 $T-2C = 0$，算出 $x = 0$，分别得到 `[0, 0]` 与 `[0, 1]`。

## 4. 算法细节

1. **先判奇偶，再做除法**。C++ 的整数除法向零取整，`(17 - 8) / 2` 会得到 `4` 而不是 4.5；若把奇偶判定放到除法之后，就会拿一个「看起来合法」的错答案。
2. **用有符号类型**。$T-2C$ 可以是负数（示例 3 得 $-30$），若用 `unsigned` 会回绕成极大正数，把无解误判为有解。
3. **判定顺序**：奇偶 → 下界 → 上界，三条缺一不可，任一条失败立即返回空容器。
4. **不要用浮点**。$\frac{T-2C}{2}$ 虽然最大只有 $5\times10^6$，浮点精度足够，但为了「恰好」「整除」这类语义，整数除法更安全也更清晰。
5. **判定式优先用 $2C \le T \le 4C$**，而不是先算出 $x$ 再判 $0 \le x \le C$：前者少一次除法，也避免负数参与比较。
6. **单解性**：系数行列式 $4\cdot1 - 2\cdot1 = 2 \ne 0$，方程组至多一解，所以一旦判定通过，算出的就是唯一答案，不需要在任何意义上「最优化」。
7. **返回值**：C++ 用 `return {}`，Python 用 `return []`；无解绝不能返回 `[0, 0]`。
8. **数据范围**：$4C \le 4\times 10^7 < 2^{31}-1$，`int` 装得下；但为习惯起见，用 `long long` 承接 $T-2C$ 与 $2C$ 也完全没有代价。

## 5. 正确性证明

**引理 1（奶酪给出汉堡总数）**：任何恰好用完奶酪的方案都满足 $x+y=C$。

**证明**：每个汉堡无论大小都用 1 片奶酪，$x$ 个巨无霸与 $y$ 个小皇堡共消耗 $x+y$ 片奶酪；奶酪必须一片不剩，故 $x+y=C$。∎

**引理 2（番茄公式）**：若 $x+y=C$，则番茄消耗量为 $2C+2x$。

**证明**：$4x+2y = 2(x+y)+2x = 2C+2x$。∎

**引理 3（闭式解与可行充要条件）**：方程组

$$\begin{cases} 4x+2y = T \\ x+y = C \end{cases}$$

存在非负整数解，当且仅当 $T$ 为偶数且 $2C \le T \le 4C$；此时解唯一，为 $x=(T-2C)/2,\ y=C-x$。

**证明**：由引理 2 消去 $y$，得 $2C+2x = T$，即 $x=(T-2C)/2$，再由引理 1 得 $y=C-x$。方程组的系数行列式为 $4\cdot1-2\cdot1 = 2 \ne 0$，故至多一解，上述形式是唯一候选。

必要性：$x$ 为整数要求 $T-2C$ 为偶数（$2C$ 为偶，故等价于 $T$ 偶）；$x \ge 0 \iff T \ge 2C$；$y \ge 0 \iff C-x \ge 0 \iff T-2C \le 2C \iff T \le 4C$。

充分性：若三条件成立，取 $x=(T-2C)/2$、$y=C-x$，则 $x,y$ 均为非负整数，且由引理 2 的恒等式 $4x+2y = 2C+2x = T$，由构造 $x+y = C$，确实是非负整数解。∎

**定理（算法正确）**：算法在三条判定全过时返回唯一正确方案，否则返回 `[]`；返回 `[]` 当且仅当不存在方案。

**证明**：若三条判定全过，由引理 3 得到的 $[x, y]$ 是非负整数解，恰好用光两种原料，且解唯一，故返回正确。若某条判定失败，由引理 3 的必要性方向，方程组不存在非负整数解，即任何制作方案都不可能同时清零两种原料，返回 `[]` 正确。∎

## 6. 复杂度分析

- **时间**：$O(1)$。一次取模判奇偶、两次比较、一次减法与一次整除，均为常数次算术运算，与输入规模无关。
- **空间**：$O(1)$。只使用两个临时整数变量；返回的数组长度固定为 2，不计入额外空间。
- **对比**：暴力枚举 $x$ 需要 $O(C)$ 次迭代，最坏 $10^7$ 次；闭式解把这部分彻底消掉。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> numOfBurgers(int tomatoSlices, int cheeseSlices) {
        long long t = tomatoSlices, c = cheeseSlices;
        if (t % 2 != 0) return {};                    // T 必须为偶数，否则 x 不是整数
        if (t < 2 * c || t > 4 * c) return {};        // 等价于 x >= 0 且 y >= 0
        long long x = (t - 2 * c) / 2;
        return {(int)x, (int)(c - x)};
    }
};
```

### Python

```python
from typing import List

class Solution:
    def numOfBurgers(self, tomatoSlices: int, cheeseSlices: int) -> List[int]:
        t, c = tomatoSlices, cheeseSlices
        if t % 2 != 0 or t < 2 * c or t > 4 * c:
            return []                 # 奇数 / 番茄不够 / 番茄太多
        x = (t - 2 * c) // 2
        return [x, c - x]
```

## 8. 边界情况与易错点

1. **$T=C=0$**：三条判定全通过，答案是 `[0, 0]` 而不是 `[]`——「一个都不做」也是合法方案，别把空方案和无解混淆。
2. **奇数番茄**：如 `(17, 7)`，此时 $2C = 14 \le 17 \le 28 = 4C$ 完全落区间内，但 $T-2C = 3$ 是奇数，$x$ 不是整数；两种汉堡的番茄消耗都是偶数，奇数的 $T$ 一定用不完。`(17, 4)` 更糟，奇偶与上界同时不满足。
3. **奶酪过多**：如 `(4, 17)`，$T < 2C$ 时算出的 $x < 0$，必须由下界判定拦下。
4. **番茄过多**：如 `(20, 4)`，$x = (20-8)/2 = 6 > C = 4$，会得到 $y = -2$，必须由上界判定拦下。
5. **只有一种汉堡**：`(4, 1) → [1, 0]` 与 `(2, 1) → [0, 1]`，恰好是可行区间 $2C \le T \le 4C$ 的两个端点，说明边界是闭区间。
6. **C++ 负数除法**：`(17 - 8) / 2 == 4`（向零取整），不先判奇偶就会拿到一个「看起来合法」的错答案；`(4 - 34) / 2 == -15` 同样说明不能指望除法自己暴露问题，边界必须在算之前判定。
7. **无符号下溢**：$T-2C$ 为负时若用 `unsigned`，会回绕成接近 $2^{32}$ 的正数，误判为可行。
8. **返回空容器**：C++ 用 `{}`、Python 用 `[]`；不要返回 `[0, 0]` 表示无解，也不要漏掉 `#include <vector>`。
