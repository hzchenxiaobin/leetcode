# LeetCode 分割回文串 III 题解

## 1. 题目概述

- **标题 / 题号**：分割回文串 III（#1278，hard）
- **链接**：https://leetcode.cn/problems/palindrome-partitioning-iii/
- **来源**：LeetCode 第 165 场周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划

**题意**：给定小写字符串 $s$ 与整数 $k$。允许先把 $s$ 中任意位置的字符改成别的字母（每改一个字符记 1 次代价），再把 $s$ 切成 $k$ 段**非空连续**子串，要求每一段都是回文串，求最小的总修改次数。修改发生在切分之前，但可以等价地理解成：先选定切法，再对每段独立地决定要改哪些位置——切法只影响「哪些位置需要互相配对」。

**约束**：

- $1 \le k \le \lvert s \rvert \le 100$
- `s` 仅由小写英文字母组成

**可行性前提**：题目保证 $k \le n$，所以「切成 $k$ 段非空子串」总有可行切法；要优化的只有代价，不存在无解的情况。

## 2. 示例

**示例 1**

```text
输入：s = "abc", k = 2
输出：1
解释：切分成 "ab" 与 "c"；"ab" 中把 b 改成 a（或 a 改成 b）即成为回文，
      共修改 1 个字符，这是最优解。
```

**示例 2**

```text
输入：s = "aabbc", k = 3
输出：0
解释：切分成 "aa"、"bb"、"c"，三段本来都是回文串，无需任何修改。
```

**示例 3**

```text
输入：s = "leetcode", k = 8
输出：0
解释：长度恰好为 8，只能每段一个字符；单字符必为回文，故代价为 0。
```

## 3. 解题思路

### 3.1 暴力思路

先把所有切法枚举出来：在 $n-1$ 个空隙中选 $k-1$ 个，共 $\binom{n-1}{k-1}$ 种。对每种切法，每一段用双指针从两端向中间数「不相等的配对」，把数量加起来。总代价 $O\!\left(\binom{n-1}{k-1}\cdot n\right)$，当 $n = 100$、$k = 50$ 时组合数约为 $5 \times 10^{28}$，完全不可行。

即便改用「只枚举最后一段」的 DP 雏形，若每枚举一个切点都现场重新数一遍不匹配对，复杂度仍是 $O(k n^3) \approx 5\times 10^{7}$——勉强能过，却把一个可以预处理的结果重复计算了几万次。真正的瓶颈是：**同一个区间的代价被反复求解**。

### 3.2 核心观察：单段代价可预计算，总代价可加

![对折比较：cost(i, j) 就是对称位置不匹配的配对数](images/wc165_q4_cost_pairs.svg)

**观察 1（单段代价只由自身决定）**：固定一段 $s[i..j]$，把它变成回文最少要改的次数，只取决于它自己。把这段「对折」，位置 $i+t$ 与 $j-t$ 必须相等：

- 若 $s[i+t] = s[j-t]$，这一列不用动，贡献 0；
- 若 $s[i+t] \ne s[j-t]$，回文的定义要求两端相等，而一次修改只动一个位置，所以这一对**至少改 1 次**，并且改 1 次就够了。

不同的配对之间没有共享位置（正中间的字符自成一体），因此各项代价可以相加，于是

$$\text{cost}(i,j) = \#\{\,t : 0 \le t < \lfloor (j-i+1)/2 \rfloor,\ s[i+t] \ne s[j-t]\,\}$$

**观察 2（总代价可加）**：一次切分把 $s$ 拆成若干段，总修改次数等于各段代价之和，段与段之间互不影响。这正是**最优子结构**：若前缀切成 $c-1$ 段的最优方案在某个 $j$ 处结束，那么「前 $j$ 个字符的最优切法」加上「最后一段的代价」就是候选答案。

**观察 3（递推关系，$O(1)$ 填一格）**：把最外层的一对剥掉，

$$\text{cost}(i,j) = \text{cost}(i+1,j-1) + [\,s[i] \ne s[j]\,]$$

按区间长度从 $1$ 到 $n$ 递增填表，每个格子只依赖长度小 $2$ 的格子，整张表 $O(n^2)$ 就能全部算出；此后任意区间的代价都是 $O(1)$ 查表。

### 3.3 状态定义与转移

![dp[c][i] 的转移：枚举最后一段的起点 j](images/wc165_q4_dp_transition.svg)

令 $n = \lvert s \rvert$，定义

$$dp[c][i] = \text{前 } i \text{ 个字符} \ (s[0..i)) \text{ 切成 } c \text{ 段的最小修改次数}$$

最外层的一刀决定最后一段从哪里开始，设起点为 $j$（$0 \le j < i$），则最后一段是 $s[j..i-1]$：

$$dp[c][i] = \min_{c-1 \le j \le i-1}\Bigl(dp[c-1][j] + \text{cost}(j,\, i-1)\Bigr)$$

- **边界**：$dp[0][0] = 0$（0 个字符切 0 段），$dp[0][i] = \infty\ (i > 0)$；
- **答案**：$dp[k][n]$；
- **$j$ 的范围**：前 $c-1$ 段每段非空，故 $j \ge c-1$；最后一段非空，故 $j \le i-1$。

转移是「把一段切下来 + 一个规模更小的子问题」，$j$ 枚举了最后一段的所有可能起点，因此覆盖了全部切法。

### 3.4 示例演算

![s = "aabbc"、k = 3 的区间代价表与 DP 表](images/wc165_q4_walkthrough.svg)

以 $s = \texttt{"aabbc"}$、$k = 3$ 为例，先填区间代价表（上三角）：

| $\text{cost}(i,j)$ | $j=0$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ |
|---|---|---|---|---|---|
| $i=0$ (a) | 0 | 0 | 1 | 2 | 2 |
| $i=1$ (a) | — | 0 | 1 | 1 | 1 |
| $i=2$ (b) | — | — | 0 | 0 | 1 |
| $i=3$ (b) | — | — | — | 0 | 1 |
| $i=4$ (c) | — | — | — | — | 0 |

例如 $\text{cost}(1,4)$ 对应 `"abbc"`：$a$ 与 $c$ 不匹配、$b$ 与 $b$ 匹配，所以是 1。

再按段数推进 DP（$\infty$ 表示不可行）：

- $c=1$：$dp[1][i] = \text{cost}(0,i-1)$，得到 $0, 0, 1, 2, 2$（$i=1..5$）；
- $c=2$：$dp[2][2]=0$、$dp[2][3]=0$、$dp[2][4]=0$、$dp[2][5]=1$；
- $c=3$：只需算 $i=5$ 附近的格子，其中
  $$dp[3][5] = \min\bigl(0+\text{cost}(2,4),\ 0+\text{cost}(3,4),\ 0+\text{cost}(4,4)\bigr) = \min(1,1,0) = 0$$

三个候选分别对应切法 `"a"|"a"|"bbc"`、`"aa"|"b"|"bc"`（前两段都已是回文，只有最后一段各需 1 次修改）与 `"aa"|"bb"|"c"`（0 次），最优值为 0，与示例一致。

## 4. 算法细节

1. **区间代价的递推方向**：外层枚举区间长度 `len`（从 2 到 n），内层枚举起点 `i`，则 `j = i + len - 1`；`cost[i][j]` 依赖长度小 2 的 `cost[i+1][j-1]`，该格在之前的外层轮次已算好，顺序天然正确。
2. **长度为 2 的边界**：`len = 2` 时内层区间是空的（`i+1 > j-1`），直接读 `cost[i+1][j-1]` 会拿到矩阵下三角中从未被写入的格子——它恰好是初始值 0，结果碰巧正确。但这种「靠零初始化兜底」的写法一旦换成别的填表顺序或复用数组就会出错，显式用 `len > 2` 判断（或把内层视作 0）才安全。
3. **两个下标体系**：`cost` 用 0-based 下标 $(i,j)$，`dp` 用「前缀长度」1-based 的 $i$。最后一段是 $s[j..i-1]$，所以取 `cost[j][i-1]`，这个平移最容易写错。
4. **$j$ 的枚举区间**：下界 $c-1$（保证前 $c-1$ 段各至少一个字符），上界 $i-1$（保证最后一段非空）；写成 $[0, i-1]$ 会把「前 $c-1$ 段装不下」的 $\infty$ 状态也算进来（结果不错误，但多做无用功）。
5. **$\infty$ 的选取**：C++ 用 `1e9` 而不是 `INT_MAX`。`INT_MAX + cost` 会溢出成负数，被 `min` 误当成最优解；`1e9 + 100` 仍在 `int` 范围内且远大于任何真实答案（答案不超过 $n$）。
6. **填表顺序**：外层 $c$ 递增、内层 $i$ 递增、最内层枚举 $j$。这样计算 $dp[c][\cdot]$ 时，整行 $dp[c-1][\cdot]$ 都已就绪；若把 $c$ 放进内层就会读到尚未计算的值。
7. **空间可压缩**：$dp[c]$ 只依赖 $dp[c-1]$，可以用两个长度为 $n+1$ 的数组滚动，把空间从 $O(kn)$ 降到 $O(n)$；本题规模小，保留二维表更易读、便于输出中间过程。
8. **不重不漏**：同一个切法只会在「最后一段起点 $j$」处被计算一次，因此既不重复统计也不会漏解。

## 5. 正确性证明

**引理 1（单段代价公式）**：把 $s[i..j]$ 变成回文所需的最少修改次数恰好等于 $\text{cost}(i,j)$，即对称位置上字符不相同的配对数。

**证明**：记 $L = j-i+1$，配对集合为 $\{(i+t,\ j-t)\}$，$0 \le t < \lfloor L/2 \rfloor$。

- **下界**：最终每段必须是回文，故任意配对的两个位置最终必须相等。若初始时 $s[i+t] \ne s[j-t]$，则至少有一个位置被改过；而一次修改只影响一个位置，且各配对的位置互不重叠（每个下标至多属于一个配对），所以总修改次数 $\ge$ 不匹配的配对数。
- **上界**：保留每个配对中的 $s[i+t]$ 不动，把 $s[j-t]$ 改成 $s[i+t]$；长度为奇数时中心字符不动。这样每个配对都相等，得到回文，修改次数恰好等于不匹配的配对数。

上下界相同，引理成立。∎

**引理 2（最优子结构）**：设 $dp[c][i]$ 为有限值，则存在某个 $j \in [c-1, i-1]$ 使
$$dp[c][i] = dp[c-1][j] + \text{cost}(j, i-1).$$

**证明**：取达到最优的一个切法，其最后一段的起点记为 $j$，则前 $j$ 个字符被切成 $c-1$ 段且各段非空，故 $c-1 \le j \le i-1$；由引理 1，总代价 $= (\text{前 } j \text{ 个字符的代价}) + \text{cost}(j, i-1)$。又前 $j$ 个字符的切法代价必为 $dp[c-1][j]$——否则用更优的切法替换会得到更小的总代价，与最优性矛盾。∎

**引理 3（转移可行）**：对任意 $j \in [c-1, i-1]$，若 $dp[c-1][j]$ 有限，则 $dp[c-1][j] + \text{cost}(j, i-1)$ 对应一个合法的 $c$ 段切法。

**证明**：$dp[c-1][j]$ 有限的充要条件是存在把前 $j$ 个字符切成 $c-1$ 段非空子串的切法（对 $c-1$ 归纳，$j \ge c-1$ 时总存在）。在此基础上再切出最后一段 $s[j..i-1]$，它非空且与前缀不交，合计 $c$ 段，覆盖整个前缀 $s[0..i)$，故合法。∎

**定理**：算法返回的 $dp[k][n]$ 就是题目要求的最小修改次数。

**证明**：对段数 $c$ 归纳证明 $dp[c][i]$ 等于「前 $i$ 个字符切成 $c$ 段」的最小代价。

- 基础 $c=0$：只有 $i=0$ 可行且代价为 0，与边界一致。
- 归纳步：设 $dp[c-1][\cdot]$ 均为对应的最优值。一方面，由引理 3，每个被枚举的候选都对应一个合法的 $c$ 段切法，其真实代价等于该候选值，故 $dp[c][i] \ge$ 最优解；另一方面，由引理 2，最优切法对应的那个 $j$ 会被枚举到，且候选值恰等于最优代价，故 $dp[c][i] \le$ 最优解。两侧夹住即得相等。∎

## 6. 复杂度分析

- **预处理**：区间代价表共 $\frac{n(n+1)}{2}$ 个格子，每格 $O(1)$ 递推，时间 $O(n^2)$，空间 $O(n^2)$。
- **DP 时间**：状态数 $O(kn)$，每个状态枚举 $O(n)$ 个切点，转移 $O(1)$（查表），合计 $O(k n^2)$。取 $n = k = 100$ 时约 $5 \times 10^{5}$ 次加法比较，远低于时限。
- **DP 空间**：二维表 $O(kn)$；若滚动数组则 $O(n)$。
- **总复杂度**：时间 $O(n^2 + kn^2) = O(kn^2)$，空间 $O(n^2 + kn)$（$k \le n$ 时可写作 $O(n^2)$）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int palindromePartition(string s, int k) {
        int n = (int)s.size();
        // cost[i][j]：把 s[i..j] 变成回文的最少修改次数
        vector<vector<int>> cost(n, vector<int>(n, 0));
        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                int inner = (len > 2) ? cost[i + 1][j - 1] : 0;  // len == 2 时内层为空
                cost[i][j] = inner + (s[i] != s[j] ? 1 : 0);
            }
        }

        const int INF = 1000000000;  // 不用 INT_MAX，避免 INF + cost 溢出
        vector<vector<int>> dp(k + 1, vector<int>(n + 1, INF));
        dp[0][0] = 0;
        for (int c = 1; c <= k; c++) {
            for (int i = c; i <= n; i++) {          // i < c 时字符不够分，跳过
                for (int j = c - 1; j < i; j++) {    // 前 c-1 段非空，最后一段非空
                    dp[c][i] = min(dp[c][i], dp[c - 1][j] + cost[j][i - 1]);
                }
            }
        }
        return dp[k][n];
    }
};
```

### Python

```python
class Solution:
    def palindromePartition(self, s: str, k: int) -> int:
        n = len(s)

        # cost[i][j]：把 s[i..j] 变成回文的最少修改次数
        cost = [[0] * n for _ in range(n)]
        for length in range(2, n + 1):
            for i in range(n - length + 1):
                j = i + length - 1
                inner = cost[i + 1][j - 1] if length > 2 else 0
                cost[i][j] = inner + (s[i] != s[j])

        INF = float('inf')
        # dp[c][i]：前 i 个字符切成 c 段的最小代价
        dp = [[INF] * (n + 1) for _ in range(k + 1)]
        dp[0][0] = 0
        for c in range(1, k + 1):
            for i in range(c, n + 1):
                best = INF
                for j in range(c - 1, i):
                    v = dp[c - 1][j] + cost[j][i - 1]
                    if v < best:
                        best = v
                dp[c][i] = best
        return dp[k][n]
```

## 8. 边界情况与易错点

1. **$k = 1$**：只能整串当一段，答案退化为 $\text{cost}(0, n-1)$；此时 $j$ 只能取 0，转移自动得到该值，无需特判，但可以用它自测。
2. **$k = \lvert s \rvert$**：每段一个字符，答案恒为 0；代码里 $dp[c][i]$ 只在 $i \ge c$ 时计算，$i = c$ 时只有 $j = c-1$ 一个候选，最终 $dp[n][n] = 0$。
3. **长度 2 的区间**：`cost[i][i+1]` 的内层区间为空，此时 `cost[i+1][i-1]` 指的是下三角里从未写入的格子，虽然值为 0 让结果碰巧正确，但必须用 `len > 2` 显式特判，不能依赖初始化。
4. **`cost` 与 `dp` 的下标错位**：最后一段是 $s[j..i-1]$（闭区间），所以是 `cost[j][i-1]`；写成 `cost[j][i]` 会多算一个字符，在 $i = n$ 时越界。
5. **$\infty$ 溢出**：用 `INT_MAX` 时 `INT_MAX + cost` 溢出成负数，会被 `min` 选中，导致答案变成无意义的负数；统一用 `1e9`，它比任何真实答案（$\le n \le 100$）都大得多。
6. **$j$ 的下界**：写成 $j \ge 0$ 虽然不会算错（$\infty$ 状态加正数仍很大），但会让「前 $c-1$ 段装不下」的非法状态参与比较；写成 $j \ge c-1$ 更清晰也更快。
7. **字符比较的返回值**：C++ 中 `s[i] != s[j]` 是 `bool`，参与加法自动转成 0/1，可以直接相加；但不要写成 `s[i] - s[j]`，那是两个 ASCII 码之差，可能是负数。
8. **Python 的 `bool` 与 `inf`**：`s[i] != s[j]` 是 `bool`，与 `int` 相加得到 `int`；`float('inf')` 与整数混算不会溢出。本题 $k \le n$ 保证 $dp[k][n]$ 有限，不需要处理返回 `inf` 的分支。
