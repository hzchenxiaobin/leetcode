# LeetCode 将 1 移动到末尾的最大操作次数 题解

## 1. 题目概述

- **标题 / 题号**：将 1 移动到末尾的最大操作次数（#3228，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-operations-to-move-ones-to-the-end/
- **来源**：LeetCode 第 407 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、计数

**题意**：给定二进制字符串 $s$。每次操作可选择一个下标 $i$（$i + 1 < |s|$），满足 $s[i] = \text{'1'}$ 且 $s[i+1] = \text{'0'}$，然后把 $s[i]$ 的这个 1 向右移动，直到它到达字符串末端或撞上另一个 '1'（即一次性滑过右侧整段连续的 0）。返回能执行的**最大**操作次数。

**约束**：

- $1 \le |s| \le 10^5$
- $s[i]$ 为 '0' 或 '1'

> 💡 **审题关键**：操作的两个细节决定一切。① 能动的前提是「1 右边紧贴 0」；② 移动是「**滑行**」而不是「交换」——这个 1 一路右移，跨过整段连续的 0，停在下一个 1 的紧左侧或串尾。因此一次操作能吞掉一整段 0，「最多操作几次」本质是在问：**1 与 0 段之间总共能发生多少次跨越**。

## 2. 示例

**示例 1**

```text
输入：s = "1001101"
输出：4
解释：依次选 i = 0、4、3、2：
     "1001101" → "0011101" → "0011011" → "0010111" → "0001111"
```

**示例 2**

```text
输入：s = "00111"
输出：0
解释：所有 1 连成一片压在末尾，不存在「1 紧跟 0」的位置，无法操作。
```

**补充示例 3**

```text
输入：s = "1010"
输出：3
解释："1010" → "0110" → "0101" → "0011"。
     尾部的 0 段照样能被跨越：左侧 2 个 1 各跨一次贡献 2，加上第 1 段 0 的贡献 1，共 3。
```

## 3. 解题思路

### 3.1 暴力思路

**暴力一（搜索所有操作序列）**：把字符串本身视作状态，枚举每个满足 $s[i]=\text{'1'}$、$s[i+1]=\text{'0'}$ 的下标尝试操作，递归求最大深度。不同操作顺序会产生大量互不相同的中间串，状态数最坏指数级，$n = 10^5$ 下彻底不可行——但它是绝佳的对拍程序。

**暴力二（按 hint 直接模拟）**：赛时 hint 提示「每次操作最左的 "10" 是最优的」，于是老老实实模拟、数步数——正确，但依然超时：**操作次数本身就可以达到 $\Theta(n^2)$ 量级**（形如 `1010…10` 的串约 $n^2/8 \approx 1.25 \times 10^9$ 次操作），光是数步数就要跑十亿量级。

> ⚠️ 暴力二的困境正是本题题眼：**答案的规模是 $\Theta(n^2)$，而时限只允许 $O(n)$ 左右**——所以答案必须由一个公式直接算出，而不是一步步数出来。

### 3.2 核心观察：一次操作 = 一个 1 跨过一整段 0

![核心观察：按 0 段计数而非按 0 的个数](images/move_ones_segment_concept.svg)

把 $s$ 切成交替的「1 段」与「0 段」，三个观察层层递进：

**观察一（操作的语义）**：被移动的 1 总是越过其右侧紧邻的**整段连续 0**（长度任意），落在下一个 1 的紧左侧或串尾——**跨越一段 0 恰好 1 次操作，与段长无关**。

**观察二（单向性，给出上界）**：1 相对 0 只会右移。某个 1 一旦越过某段 0 就永远留在它右边，不可逆——所以**每个（1，其右侧的某个初始 0 段）组合至多贡献 1 次操作**。

**观察三（最左贪心取满上界）**：每次操作**最左**的 "10" 时，各 0 段像传送带一样从左到右逐段「清算」：轮到第 $k$ 段 0 时，它左侧的 $m_k$ 个 1 已连成一整块，自右向左**逐个**跨越这段 0（每人恰好 1 次操作）；清算完的 0 段沉入串首 0 区，永不再被跨越。

三条观察合起来得到计数公式：

$$
\text{答案} \;=\; \sum_{\text{左侧有 1 的极大 0 段}} \big(\text{该段左侧 1 的总数}\big) \;=\; \sum_{\text{每个 1}} \big(\text{它右侧的 0 段数}\big)
$$

两种求和方向完全等价。对示例 1 验证：`1001101` 切成 `1 | 00 | 11 | 0 | 1`——0 段① 左侧 1 个 1（贡献 1），0 段② 左侧 3 个 1（贡献 3），合计 $4$ ✓。

> ⚠️ **最典型的错误**：按「每个 1 右侧 0 的**个数**」累加——那是**逆序对**数。`1001101` 的逆序对是 5，但答案是 4：最左的 1 一次跨过 `00` 两个 0，只记 1 次。**按段计数，不按个数计数**。

### 3.3 算法流程：一遍扫描计数

![算法流程：遇「新 0 段开头」累加 ones](images/move_ones_scan_flow.svg)

公式落到代码上是一次线性扫描：

| 步骤 | 条件 | 动作 | 语义 |
|------|------|------|------|
| ① | $s[i] = \text{'1'}$ | `ones += 1` | 维护「已扫前缀中 1 的总数」 |
| ② | $s[i] = \text{'0'}$ 且 $s[i-1] = \text{'1'}$ | `ans += ones` | 一段**新** 0 的开头：左侧每个 1 都将跨越它一次 |
| ③ | $s[i] = \text{'0'}$ 且 $s[i-1] = \text{'0'}$ | 什么都不做 | 还在同一段 0 里，不产生新操作 |

条件 ② 中的 $s[i-1] = \text{'1'}$ 保证**每段 0 只在开头累加一次**；串首的 0 段因左侧没有 1（`ones = 0`），加了也是 0，天然被正确处理。

### 3.4 示例演算

![示例演算：贪心模拟与扫描计数对照](images/move_ones_walkthrough.svg)

**贪心模拟**（每次操作最左的 "10"，橙 = 刚落位的 1，红 = 刚被跨过的 0）：

| 步骤 | 选 $i$ | 跨过 | 操作后的 $s$ |
|------|:---:|------|------|
| ① | 0 | 0 段①（2 个 0 一次跨完） | `0011101` |
| ② | 4 | 0 段② | `0011011` |
| ③ | 3 | 0 段②（**还是那一个 0**） | `0010111` |
| ④ | 2 | 0 段②（仍是它） | `0001111` ✓ |

注意 ②③④ 跨的是**同一个物理 0**（原下标 5）：它左边的 3 个 1 自右向左逐个跨过它——这正是「0 段② 贡献 3」的由来；① 中最左的 1 一次跨完原下标 1–2 的两个 0——「0 段① 贡献 1」。

**一遍扫描计数**（同一示例）：

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|------|---|---|---|---|---|---|---|
| $s[i]$ | 1 | 0 | 0 | 1 | 1 | 0 | 1 |
| ones | 1 | 1 | 1 | 2 | 3 | 3 | 4 |
| ans | 0 | **1** | 1 | 1 | 1 | **4** | 4 |

$i=1$ 处触发「新 0 段」`ans += 1`，$i=5$ 处触发 `ans += 3`，最终 $ans = 4$ ✓。**模拟数出的每一步，都被公式一次性加总**——这正是 $O(n)$ 公式能够替代 $\Theta(n^2)$ 模拟的原因。

## 4. 算法细节

1. **「新 0 段开头」的判定**：`s[i] == '0' && i > 0 && s[i-1] == '1'`。`i > 0` 防止越界；该条件保证每段 0 只在首字符处累加一次，段内其余 0 全部走分支 ③。
2. **两个计数器的语义**：`ones` 是「已扫过前缀中 1 的总数」，随扫描单调递增、与 0 段位置无关；`ans` 是「各已清算 0 段的左侧 1 总数之和」。
3. **首尾 0 段**：串首 0 段左侧无 1，`ans += 0` 自动正确；串尾 0 段**必须计入**——1 可以一路滑到串尾（见补充示例 3 的 `1010`），别把「0 段后面必须有 1」当成计数条件。
4. **等价的按段写法**：用 `itertools.groupby` 把串切成段，遇 `1` 段累进 `ones`，遇前面有 1 的 `0` 段整体 `ans += ones`——与逐字符写法完全等价，只是把「新段开头」的判断交给了分组。
5. **答案的量级与整型选择**：最坏形如 `1010…10`，$\sum m_k \approx n^2/8 \approx 1.25 \times 10^9$（$n = 10^5$），恰好在 `int` 上限（约 $2.15 \times 10^9$）之内但已过半程；C++ 保险起见可用 `long long`，Python 无需关心。

## 5. 正确性证明

**引理 1（滑行语义与 0 段不分裂）**：任意时刻的每个极大 0 段都是若干**初始** 0 段的粘连；0 段既不会分裂，也不会新增。

**证明**：操作落点只能是「某个 1 的紧左侧」或串尾，绝不会停进 0 段中间，因此被跨越的 0 段保持连续完整；该段左侧的 1 移到段右侧后，段与更左侧的 0（若有）粘连成更大的段。对操作次数归纳即得结论。∎

**引理 2（单向性）**：某个 1 越过某批 0 后，永远位于这批 0 的右侧。

**证明**：操作只把被选中的 1 向右移，其余字符相对位置不变，故除「被移动的 1 与被跨过的 0」外，任意两个字符的相对顺序均不变；而这一翻转发生后，该 1 后续只能继续右移、这批 0 相对只会继续左移，不可能再翻转回来。∎

**定理 1（上界）**：任意合法操作序列的长度不超过 $\sum_k m_k$，其中 $m_k$ 为初始第 $k$ 个极大 0 段左侧 1 的总数。

**证明**（计票 / 势能论证）：给每个有序对（1 $x$，初始 0 段 $Z$，且 $x$ 初始位于 $Z$ 左侧）发一张票，共 $\sum_k m_k$ 张。由引理 1，每次操作中被移动的 1 完整越过至少一个初始 0 段（若当前粘连段含多个初始段则一次越过多个），即**每次操作至少撕掉一张票**；由引理 2，每张票**至多被撕一次**。故操作次数 $\le \sum_k m_k$。∎

**定理 2（可达性）**：每次操作**最左**的 "10"，总操作数恰为 $\sum_k m_k$。

**证明**：最左优先时，对过程归纳可证各初始 0 段**从左到右**依次清算：轮到第 $k$ 段时，其左侧的 1 已全部聚成一个紧贴该段的 1 块（更左的段已清算完毕，块间再无阻隔）。块内最右的 1 紧贴 0 段，构成当前最左的 "10"，被操作后落到段右侧；随后块内倒数第二个 1 成为新的最左 "10"……如此该段恰好被左侧全部 $m_k$ 个 1 自右向左各跨一次，随后沉入串首 0 区不再参与。每个（1，初始 0 段）组合恰好贡献一次操作，总数为 $\sum_k m_k$。∎

**推论**：最大操作次数 $= \sum_k m_k$，即 3.3 中扫描算法的返回值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n$ 为 $s$ 的长度。单次线性扫描，每个字符 $O(1)$ 处理。对照 3.1：直接模拟是 $\Omega(\text{答案}) = \Omega(n^2)$——$O(n)$ 公式可行，正因为它**不逐次数操作**，而是按「0 段 × 左侧 1 数」把所有操作一次性加总。
- **空间复杂度**：$O(1)$。只用 `ans`、`ones` 两个计数器（不计输入串本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxOperations(string s) {
        int ans = 0, ones = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            if (s[i] == '1') {
                ++ones;
            } else if (i > 0 && s[i - 1] == '1') {
                ans += ones;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxOperations(self, s: str) -> int:
        ans = ones = 0
        for i, c in enumerate(s):
            if c == '1':
                ones += 1
            elif i > 0 and s[i - 1] == '1':
                ans += ones
        return ans
```

## 8. 边界情况与易错点

1. **别按 0 的个数计数**：那是逆序对（`1001101` 为 5），正确答案是 4——一次滑行跨过一整段 0 只记 1 次。**按段计，不按个数计**。
2. **同一段 0 的后续字符不再累加**：只有 `s[i-1]=='1' && s[i]=='0'`（新段开头）才 `ans += ones`——漏掉这个判断会把答案放大成逆序对数。
3. **尾部 0 段照样贡献**：1 能一路滑到串尾，`1010` 的答案 3 里尾段贡献了 2。
4. **`i = 0` 的越界**：判定 `s[i-1]` 前先判 `i > 0`（或从 $i = 1$ 起扫、单独处理 `s[0]`）。
5. **全 0 串 / 全 1 串 / 1 全在尾部**：均无合法操作，扫描自然返回 0，无需特判。
6. **答案上界约 $n^2/8 \approx 1.25 \times 10^9$**：`int` 勉强装下但已过半程；C++ 直接用 `long long` 更稳妥，Python 天然无溢出。
7. **比赛策略**：赛时若想不到公式，写「最左 "10"」的模拟器可用于小样例对拍；公式出来后，用暴力搜索对拍全部长度 $\le 12$ 的二进制串是稳妥的自验手段。
