# LeetCode 掷骰子等于目标和的方法数 题解

## 1. 题目概述

- **标题 / 题号**：掷骰子等于目标和的方法数（#1155，medium）
- **链接**：https://leetcode.cn/problems/number-of-dice-rolls-with-target-sum/
- **来源**：LeetCode 第 149 场周赛 Q2
- **难度**：中等
- **标签**：动态规划

**题意**：有 $n$ 个完全相同的骰子，每个骰子有 $k$ 个面，分别标号 $1$ 到 $k$。一次投掷的结果是一个有序 $n$ 元组 $(v_1, v_2, \dots, v_n)$，其中 $v_i \in [1,k]$，共 $k^n$ 种等可能结果。求满足 $\sum_{i=1}^{n} v_i = target$ 的元组个数，对 $10^9+7$ 取模。

「骰子相同」只是物理设定，计数时**骰子是有序的**：$1+6$ 与 $6+1$ 是两种不同方案（示例 2 的答案 6 正是这样数出来的）。

**约束**：

- $1 \le n, k \le 30$
- $1 \le target \le 1000$

## 2. 示例

**示例 1**

```text
输入：n = 1, k = 6, target = 3
输出：1
解释：只有一个骰子且 6 个面，点数和为 3 的方案只有 3 这一种。
```

**示例 2**

```text
输入：n = 2, k = 6, target = 7
输出：6
解释：1+6, 2+5, 3+4, 4+3, 5+2, 6+1；顺序不同算不同方案。
```

**示例 3**

```text
输入：n = 30, k = 30, target = 500
输出：222616187
解释：答案很大，必须对 10^9 + 7 取模。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举全部 $k^n$ 个有序元组，统计和为 $target$ 的个数。当 $n = k = 30$ 时 $k^n = 30^{30} \approx 2\times 10^{44}$，完全不可行。

暴力浪费在哪？大量元组**共享前缀**：前 $i$ 个骰子的和一旦确定，剩下 $n-i$ 个骰子怎么掷只与「离目标和还差多少」有关。于是把指数级枚举换成按「已掷骰子数 $i$」与「当前点数和 $s$」分层的计数 DP。

### 3.2 核心观察：每格只依赖上一层一段连续窗口

![按骰子数与点数和分层，每格由上一层连续 k 格汇总](images/wc149_q2_state_model.svg)

定义

$$dp[i][s] = \text{掷完前 } i \text{ 个骰子、点数和恰为 } s \text{ 的有序方案数}$$

第 $i$ 个骰子可以掷出 $1,2,\dots,k$ 中的任意一个，最后一个分量单独拆出来：

$$dp[i][s] = \sum_{v=1}^{k} dp[i-1][s-v]$$

把下标换成 $t = s-v$，则 $t \in [s-k,\, s-1]$：第 $i$ 层的每个格子只依赖第 $i-1$ 层**一段长度为 $k$ 的连续窗口**。边界为 $dp[0][0] = 1$，$dp[0][s>0] = 0$。

另外，$i$ 个骰子的和必然落在 $[i,\, i\cdot k]$ 内，因此只有 $i \le s \le i\cdot k$ 的状态可能非零，其余整段恒为 0。

### 3.3 算法流程：滚动数组 + 前缀和差分

![滚动数组 + 前缀和差分的算法流程](images/wc149_q2_dp_flow.svg)

按上式直接实现是 $O(n \cdot k \cdot target)$（$30\times30\times1000 = 9\times10^5$，其实已经够快）。窗口求和还能再压一层：设上一层的**前缀和**为

$$P[j] = \sum_{t=0}^{j-1} dp[i-1][t], \qquad P[0] = 0$$

窗口和就是两个前缀和之差：

$$dp[i][s] = P[s] - P[\max(0,\, s-k)]$$

每个状态 $O(1)$ 转移，每层只扫一遍 $s$，总复杂度 $O(n \cdot target)$。

流程：

1. **剪枝**：若 $target < n$ 或 $target > n\cdot k$，答案必为 0，直接返回。
2. **初始化**：$dp[0] = 1$，其余为 0（0 个骰子、和为 0 的空方案算 1 种）。
3. **逐层递推**：对 $i = 1,2,\dots,n$，先用当前 $dp$ 求出前缀和数组 $P$。
4. **差分填表**：对 $s \in [i,\, \min(i\cdot k,\, target)]$，令 $ndp[s] = P[s] - P[\max(0, s-k)]$。
5. **滚动**：$dp \leftarrow ndp$，始终只保留一层，空间 $O(target)$。
6. 返回 $dp[target]$。

> 💡 也可以真正维护一个滑动窗口（右端进 $dp[s-1]$、左端出 $dp[s-k-1]$），效果等价；用完整前缀和数组不容易写错下标，推荐后者。

### 3.4 示例演算

![示例 2 与继续算一层的逐格演算](images/wc149_q2_walkthrough.svg)

以示例 2（$n=2,\ k=6,\ target=7$）为例：

| 层 | $dp[0]$ | $dp[1]$ | $dp[2]$ | $dp[3]$ | $dp[4]$ | $dp[5]$ | $dp[6]$ | $dp[7]$ |
|---|---|---|---|---|---|---|---|---|
| $i=1$ | 0 | 1 | 1 | 1 | 1 | 1 | 1 | 0 |
| $i=2$ | 0 | 0 | 1 | 2 | 3 | 4 | 5 | **6** |

橙色窗口是 $[\,7-6,\,6\,] = [1,6]$，$dp[2][7] = P[7] - P[1] = 6 - 0 = 6$，与官方答案一致。

再续算一层（$n=3,\ k=6,\ target=10$）：$dp[2]$ 在 $s = 2$ 到 $12$ 上的值为 $1,2,3,4,5,6,5,4,3,2,1$，窗口 $[4,9]$ 内

$$dp[3][10] = 3+4+5+6+5+4 = 27$$

差分式同样给出 $P[10] - P[4] = 30 - 3 = 27$，两法互相印证。

**自检恒等式**：$\sum_{s} dp[i][s] = k^i$（$k=6$ 时逐层总和为 $6, 36, 216$），实现出错时可用它快速定位。

## 4. 算法细节

1. **前缀和下标约定**：取 $P[j] = \sum_{t<j} dp[t]$，数组长度开到 $target+2$。窗口 $[l, s-1]$ 的和为 $P[s] - P[l]$，天然避开 $s-k-1 = -1$ 的越界。
2. **窗口左端要 clamp**：$l = \max(0,\, s-k)$。当 $s \le k$ 时整段前缀 $[0, s-1]$ 都参与求和，取 $P[0] = 0$ 即自动处理。
3. **只遍历有效区间**：$s$ 从 $i$ 取到 $\min(i\cdot k,\, target)$；若 $i > target$，区间为空，可提前 `break`（此后每层都填不出非零值）。
4. **滚动数组必须两个数组**：$dp[i][s]$ 依赖 $dp[i-1]$ 的整段窗口，原地覆盖会污染同层后续状态。先算完 $ndp$ 再交换。
5. **减法取模**：$P[s]-P[l]$ 可能为负。C++ 先 `+MOD` 再取模；Python 的 `%` 结果恒非负。
6. **C++ 中间量用 `long long`**：两数相加最大约 $2\times10^9+12$，虽仍在 `int` 范围内，但用 `long long` 更稳妥。
7. **前缀和每层重算**：$P$ 是**上一层**的前缀和，换层后必须重新累加，不能跨层复用。

## 5. 正确性证明

**引理 1**（状态含义）：对任意 $i \ge 0,\ s \ge 0$，按 $dp[0][0]=1$、$dp[i][s]=\sum_{v=1}^{k} dp[i-1][s-v]$ 递推得到的 $dp[i][s]$，恰等于「长度 $i$、每项取值在 $[1,k]$ 内、元素和为 $s$ 的有序元组个数」。

**证明**：对 $i$ 归纳。$i=0$ 时只有空元组，和为 0，与 $dp[0][0]=1$、$dp[0][s>0]=0$ 相符。设结论对 $i-1$ 成立；长度 $i$ 的元组可按最后一个分量 $v \in [1,k]$ 唯一分解为「长度 $i-1$ 的元组 + $v$」，要求和为 $s$ 则前缀和须为 $s-v$，由归纳假设这类前缀恰有 $dp[i-1][s-v]$ 个，对 $v$ 求和即得全部方案；分解按 $v$ 互不重叠且覆盖完整，故计数不重不漏。∎

**引理 2**（差分等价）：设 $P[j] = \sum_{t=0}^{j-1} dp[i-1][t]$，$l = \max(0, s-k)$，则 $\sum_{t=l}^{s-1} dp[i-1][t] = P[s] - P[l]$。

**证明**：$P[s] = \sum_{t=0}^{s-1} dp[i-1][t]$，$P[l] = \sum_{t=0}^{l-1} dp[i-1][t]$。两式相减，$t < l$ 的项全部抵消，只剩 $t \in [l, s-1]$ 的项；当 $l=0$ 时 $P[0]=0$，结论仍成立。∎

**定理**：算法返回 $dp[n][target] \bmod (10^9+7)$，即所求方案数。

**证明**：由引理 1，$dp[n][target]$ 恰是全部合法有序元组中元素和为 $target$ 的个数。引理 2 说明第 3.3 节的差分式与引理 1 的递推式逐项相等，故算法算出的每个 $dp[i][s]$ 都与定义一致。剪枝处：$n$ 个骰子的和必在 $[n, n\cdot k]$ 内，$target$ 落在区间外时方案数为 0，提前返回不改变答案。全过程每步对 $MOD$ 取模，而取模与加、减可交换，故最终结果正确。∎

## 6. 复杂度分析

- **时间**：外层 $n$ 层，每层求前缀和 $O(target)$、填表 $O(target)$，合计 $O(n \cdot target)$，最坏约 $30 \times 1000 = 3\times10^4$ 次基本运算。若不用前缀和优化，朴素转移为 $O(n \cdot k \cdot target) = 9\times10^5$，同样能通过。
- **空间**：两个长度 $target+1$ 的滚动数组加一个长度 $target+2$ 的前缀和数组，共 $O(target)$；若不滚动则需 $O(n \cdot target)$。
- **常数**：每格两次查表、一次减法、一次取模，实际运行在毫秒级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numRollsToTarget(int n, int k, int target) {
        const int MOD = 1000000007;
        if (target < n || (long long)target > (long long)n * k) return 0;

        vector<long long> dp(target + 1, 0), ndp(target + 1, 0), pref(target + 2, 0);
        dp[0] = 1;
        for (int i = 1; i <= n; ++i) {
            pref[0] = 0;
            for (int s = 0; s <= target; ++s) pref[s + 1] = (pref[s] + dp[s]) % MOD;
            fill(ndp.begin(), ndp.end(), 0);
            int lo = i, hi = min(i * k, target);
            for (int s = lo; s <= hi; ++s) {
                int l = max(0, s - k);
                long long v = pref[s] - pref[l];   // 窗口 [l, s-1] 的和
                if (v < 0) v += MOD;
                ndp[s] = v;
            }
            dp.swap(ndp);
        }
        return (int)dp[target];
    }
};
```

### Python

```python
class Solution:
    def numRollsToTarget(self, n: int, k: int, target: int) -> int:
        MOD = 10 ** 9 + 7
        if target < n or target > n * k:
            return 0

        dp = [0] * (target + 1)
        dp[0] = 1
        for i in range(1, n + 1):
            pref = [0] * (target + 2)
            for s in range(target + 1):
                pref[s + 1] = (pref[s] + dp[s]) % MOD

            ndp = [0] * (target + 1)
            for s in range(i, min(i * k, target) + 1):
                ndp[s] = (pref[s] - pref[max(0, s - k)]) % MOD
            dp = ndp
        return dp[target]
```

## 8. 边界情况与易错点

1. **无解区间**：$target < n$（每个骰子至少 1）或 $target > n\cdot k$（每个骰子至多 $k$）时答案为 0，例如 `n=1, k=1, target=2`。
2. **$k = 1$ 退化**：只有一个面，仅当 $target = n$ 时答案为 1，否则为 0。
3. **$target = n\cdot k$**：所有骰子都必须掷出 $k$，答案恒为 1（如 `n=30, k=30, target=900`）。
4. **取模负值**：$P[s]-P[l]$ 为负时，C++ 必须 `+MOD` 修正；Python 的 `%` 已保证非负。
5. **前缀和下标**：数组长度取 $target+2$，只访问 $P[s]$（$s \le target$）与 $P[\max(0,s-k)]$；不要写成 $P[s-k]$，否则 $s<k$ 时越界。
6. **滚动数组污染**：若在递推中就地更新 $dp[s]$，后续 $s$ 会读到已被覆盖的值，答案偏大。
7. **别用 $k^n$ 硬算**：$30^{30}$ 远超 64 位整数范围，且取模后无法用除法还原。

**延伸思考**：

- **面值不连续**：若骰子面是集合 $S$ 而非 $1 \le v \le k$，窗口不再是连续段，前缀和优化失效，退化为 $O(n \cdot target \cdot |S|)$。
- **生成函数视角**：答案即 $(x + x^2 + \cdots + x^k)^n$ 中 $x^{target}$ 的系数。当 $k$ 很大而 $target$ 很小时，可用多项式快速幂 / NTT 计算。
- **附加约束**：若要求「每个面都至少出现一次」，可用容斥：先算无约束方案，再减去禁用若干面后的方案。
- **反向极限**：若 $n$ 极大（如 $10^9$）而 $target$ 固定，转移是固定矩阵的幂，可上矩阵快速幂或线性递推 + Berlekamp–Massey 加速。
