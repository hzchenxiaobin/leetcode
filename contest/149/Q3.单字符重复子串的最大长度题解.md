# LeetCode 单字符重复子串的最大长度 题解

## 1. 题目概述

- **标题 / 题号**：单字符重复子串的最大长度（#1156，medium）
- **链接**：https://leetcode.cn/problems/swap-for-longest-repeated-character-substring/
- **来源**：LeetCode 第 149 场周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、滑动窗口

**题意**：给一个字符串 `text`。你**最多进行一次**「交换两个字符」的操作（也可以什么都不做），交换之后字符串里会出现若干「所有字符都相同」的连续子串，求其中最长者的长度。

注意三件事：交换**不是必须**做的；交换的两个位置**可以任意**（不必相邻）；交换后只看**连续同字符**的段，不看子序列。

**约束**：

- $1 \le \lvert \text{text} \rvert \le 2\times 10^4$
- `text` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：text = "aaabaaa"
输出：6
解释：把中间的 b 与最后一个 a 交换，得到 "aaaaaab"，
      前 6 个 a 连成一片；总共有 6 个 a，不可能更长。
```

**示例 2**

```text
输入：text = "aaabbaaa"
输出：4
解释：两段 a 之间隔着 "bb"，一次交换只能填掉一个洞，拼不起来；
      只能在第一段或第三段旁边补 1 个 a，得 3 + 1 = 4。
```

**示例 3**

```text
输入：text = "ababa"
输出：3
解释：把下标 1 的 b 与下标 4 的 a 交换，得到 "aaabb"，
      前 3 个 a 连成一片；全串只有 3 个 a，不可能更长。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有交换对 $(i,j)$（含「不交换」），每次交换后线性扫描最长同字符段，复杂度 $O(n^3)$。$n = 2\times10^4$ 时约有 $2\times10^8$ 个交换对，仅枚举就已经超时，扫描还得再乘 $O(n)$，完全不可行。

暴力之所以浪费，是因为**一次交换能改变的东西极少**：它只影响两个位置，其余 $n-2$ 个位置纹丝不动。所以答案必然由原串里现成的「同字符段」拼成，关键是把这些段先找出来。

### 3.2 核心观察：游程编码后只剩两种增广方式

![一次交换只能做两件事：单段 +1，或跨过单个异字符拼接](images/wc149_q3_two_cases.svg)

先把 `text` 做**游程编码**（run-length encoding）：把连续相同的字符合成一段，得到 $(\text{字符}, \text{段长})$ 的序列。设字符 `c` 在整串中总共出现 $\text{cnt}[c]$ 次。

最终那个「最长单字符重复子串」里的字符全部是某个 `c`。它对应到**原串**上，只可能是下面两种形态：

- **形态一：一段**。这个区间在原串里本来就是一段连续的 `c`，长度为 $L$。若 $\text{cnt}[c] > L$，说明别处还有 `c`，可以把它换到这段旁边，长度变成 $L+1$；否则只能保持 $L$。于是候选值
  $$\min(L+1,\ \text{cnt}[c])$$
- **形态二：两段拼接**。区间在原串里由两段 `c` 段构成，中间只隔**一个**异字符，把这个异字符换走即可拼成一片，长度为 $L_1 + L_2 + 1$；同样受总数限制。于是候选值
  $$\min(L_1+L_2+1,\ \text{cnt}[c])$$

**为什么最多只能隔一个洞**：一次交换只能把一个外来的 `c` 搬进一个位置，所以被打断的位置最多一个。隔两个异字符（如示例 2 的 `bb`）就永远拼不起来。

**为什么两段之间最多只能隔一段**：游程是极大段，相邻两段字符必不相同，所以同字符的两段之间**至少**夹着一段；夹的段长恰为 $1$ 时才是「只隔一个洞」，可以靠一次交换填平。

### 3.3 算法流程

![算法流程：统计计数 → 游程编码 → 每段算两种候选 → 取最大](images/wc149_q3_scan_flow.svg)

1. 扫一遍 `text`，统计 $\text{cnt}[c]$（`c` 从 `a` 到 `z`）。
2. 再扫一遍做游程编码，把每段的字符与长度存进 `runChar[]`、`runLen[]`，段数为 $m$。
3. 对每个段 $k$（字符 `c`、长度 $L$）：
   - 候选一：$\min(L+1,\ \text{cnt}[c])$；
   - 候选二：若 $k+2 < m$ 且 `runChar[k+2] == c` 且 `runLen[k+1] == 1`，则 $\min(L + \text{runLen}[k+2] + 1,\ \text{cnt}[c])$。
4. 所有候选取最大值返回。

两个候选都是 $O(1)$ 计算，整体一次线性扫描，没有二分、没有滑窗、也没有排序。

### 3.4 示例演算

![两个示例的走查：aaabbaaa 得 4，aaabaaa 得 6](images/wc149_q3_walkthrough.svg)

以 `text = "aaabbaaa"`（示例 2）为例，`cnt[a] = 6`、`cnt[b] = 2`，游程为 $a\times 3$、$b\times 2$、$a\times 3$：

| 段 | 字符 / 段长 | 候选一 $\min(L+1,\text{cnt})$ | 候选二（拼接） |
|----|-------------|-------------------------------|----------------|
| 1 | `a` / 3 | $\min(4,6)=4$ | 与段 3 之间隔 $b\times 2$，不能拼 |
| 2 | `b` / 2 | $\min(3,2)=2$ | 后面没有同类段 |
| 3 | `a` / 3 | $\min(4,6)=4$ | 后面没有同类段 |

答案为 $4$。

再看 `text = "aaabaaa"`（示例 1），游程为 $a\times 3$、$b\times 1$、$a\times 3$，$\text{cnt}[a] = 6$：段 1 的候选二是 $\min(3+3+1,\ 6) = 6$——中间恰好只隔一个 `b`，换掉它即可，答案 $6$。

`text = "ababa"`（示例 3）：游程 $a\times 1$、$b\times 1$、$a\times 1$、$b\times 1$、$a\times 1$，$\text{cnt}[a]=3$、$\text{cnt}[b]=2$。段 1 的候选一 $\min(2,3)=2$，候选二（与段 3 合并）$\min(1+1+1,3)=3$ → 答案 $3$。

## 4. 算法细节

1. **两个候选都要算**：只算「拼接」会漏掉「单段 +1」，只算「单段」会漏掉「两段拼接」。对照着看：`"aab"` 的答案 2 来自单段 +1（拼接无从谈起），`"aba"` 的答案 2 才来自拼接（$\min(1+1+1,2)=2$）；而示例 1 的 6 只能由拼接得到。
2. **`min` 截断不能省**：候选值算的是「拼出来的长度」，但字符总量只有 $\text{cnt}[c]$，不可能更多。例如 `"aaaaa"` 若直接取 $L+1 = 6$ 就错了，$\min(6,5) = 5$ 才是正确答案。
3. **拼接只查 $k$ 与 $k+2$**：游程中相邻两段字符必然不同，所以「同字符的两段」最小间隔是一段；只需检查向前两段，不必枚举所有段对。
4. **间隔长度必须恰为 1**：条件是 `runLen[k+1] == 1`。等于 2 就拼不上（示例 2 的 `bb`），这时候选二直接放弃，不能「近似地用两段之和」。
5. **没有富余字符时，拼接候选依然可达**：当 $\text{cnt}[c] = L_1 + L_2$ 时 $\min$ 给出 $L_1+L_2$，实现方式是「把间隔那个字符与第二段末尾的 `c` 交换」，第二段整体前移一格，长度正好是 $L_1+L_2$。所以公式不会高估。
6. **下标越界**：候选二访问 `k+2`，循环里必须先判 `k+2 < m`；候选一没有越界风险。
7. **答案为全局最大值**：一个字符的候选值只决定该字符的最好成绩，最终要对 26 个字母（实际是全部段）取最大。
8. **不需要真的交换字符串**：我们只在「段」的抽象上算长度，$O(1)$ 空间完成每次判定，避免了任何字符串拷贝。

## 5. 正确性证明

约定：对字符 `c`，称一个区间「最终全为 `c`」指交换后该区间内每个位置都是 `c`。

**引理 1（形态完备性）**：设交换后存在长度 $A$ 的、全为 `c` 的连续区间 $[l, r]$（$A = r-l+1$）。则以下两者至少成立一个：

1. 原串中 $[l,r]$ 全为 `c`，且 $[l,r]$ 包含在一段长为 $L \ge A$ 的 `c` 游程内；
2. 原串中 $[l,r]$ 恰有一个位置不是 `c`，且 $[l,r]$ 由两段 `c` 游程夹一个长度为 $1$ 的异字符游程构成，此时 $A = L_1 + L_2 + 1$。

**证明**：交换只改变两个位置 $i$、$j$，其余位置字符不变。$[l,r]$ 中每个位置最终都是 `c`，所以其中**原字符不是 `c`** 的位置只能是 $i$ 或 $j$。

- 若 $[l,r]$ 中不存在原字符非 `c` 的位置，即情形 1。此时 $[l,r]$ 连续且全为 `c`，被某段 `c` 游程包含，故 $L \ge A$。
- 若存在这样的位置，至多两个。若有两个（就是 $i$ 与 $j$），交换后二者都变 `c`，说明 $i$ 的 `c` 来自 $j$、$j$ 的 `c` 来自 $i$，即两者原字符都是 `c`，矛盾。故恰有一个位置 $p$，原字符非 `c`。它的 `c` 来自另一处交换点 $j$；若 $j \in [l,r]$，则 $j$ 换走 `c` 后变成 $p$ 原来的非 `c` 字符，与「区间全为 `c`」矛盾，故 $j$ 在区间外。于是 $[l,p-1]$ 与 $[p+1,r]$ 在原串中都是连续的 `c`，且两端紧邻非 `c`，故它们各自**完整**等于一段 `c` 游程（记为 $L_1$、$L_2$），中间 $p$ 单独构成一段长为 $1$ 的游程，即情形 2，此时 $A = L_1+L_2+1$。∎

**引理 2（候选可达）**：对任意一段字符为 `c`、长度为 $L$ 的游程：

1. $\min(L+1,\text{cnt}[c])$ 可以用至多一次交换实现；
2. 若下一段（$k+1$）长度为 $1$、再下一段（$k+2$）字符同为 `c`、长度为 $L_2$，则 $\min(L+L_2+1,\text{cnt}[c])$ 可以用至多一次交换实现。

**证明**：

1. 若 $\text{cnt}[c] > L$，则游程外存在一个 `c`，位置记为 $j$；游程长度为 $L<n$，所以它至少有一个紧邻位置 $q$（左或右）。交换 $j$ 与 $q$，把 `c` 搬到游程旁，得到 $L+1$ 个连续 `c`。若 $\text{cnt}[c] = L$，则 $\min = L$，原游程本身就是 $L$ 个连续 `c`，无需交换。
2. 设两段为 $[s_1,e_1]$、$[s_2,e_2]$，中间插入段就是位置 $p=e_1+1$，$e_2 = s_2 + L_2 - 1$，拼接后区间是 $[s_1,e_2]$，长度 $L+L_2+1$。
   - 若 $\text{cnt}[c] > L+L_2$，取区间外的 `c` 所在位置 $j$，交换 $j$ 与 $p$，则 $[s_1,e_2]$ 全为 `c`，得 $L+L_2+1$。
   - 若 $\text{cnt}[c] = L+L_2$，交换 $p$ 与 $e_2$：$p$ 变成 `c`，$e_2$ 变成原先 $p$ 上的异字符，于是 $[s_1, e_2-1]$ 全为 `c`，长度 $e_2 - s_1 = (L+L_2+1)-1 = L+L_2 = \min(L+L_2+1,\text{cnt}[c])$。

   两种情形都只用了一次交换。∎

**定理**：算法输出的 `ans` 等于最优答案。

**证明**：

- **不超过**：任取交换后的最优区间，长度 $A$，字符为 `c`。由引理 1，它落入情形 1 或情形 2。情形 1 中 $A \le L \le \min(L+1,\text{cnt}[c])$（$L \le \text{cnt}[c]$ 显然成立）；情形 2 中 $A = L_1+L_2+1$，而 $A$ 个位置两两不同且都是 `c`，故 $A \le \text{cnt}[c]$，即 $A \le \min(L_1+L_2+1,\text{cnt}[c])$。两种情况都对应算法枚举过的候选，故 $A \le \text{ans}$。
- **不少于**：对每个被枚举的候选，引理 2 给出了一次合法交换（或「不操作」）把它实现出来，所以 `ans` 是某个真实可达的长度，$\text{ans} \le$ 最优值。

两侧合并即得相等。又 $n \ge 1$ 时至少存在长度 1 的区间，算法中每段都贡献 $\ge 1$ 的候选，故 `ans` 有定义且 $\ge 1$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。统计计数扫一遍 $O(n)$；游程编码再扫一遍 $O(n)$，每段做常数次比较与取小；段数 $m \le n$，总循环 $O(m) = O(n)$。
- **空间**：$O(n)$。开销是游程数组（段数最多 $n$，如 `"ababab..."` 时每段长为 1）；字符计数数组固定 26，是 $O(1)$。若把「只保留最近两段」写进扫描过程，可把额外空间压到 $O(1)$，代价是代码稍繁。
- 与「枚举交换对」的 $O(n^3)$ 相比，本解法把「试」变成了「算」：不需要真的构造任何交换后的字符串。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxRepOpt1(string text) {
        int n = text.size();
        vector<int> cnt(26, 0);
        for (char ch : text) cnt[ch - 'a']++;

        // 游程编码：把连续相同的字符合成一段，记录 (字符, 段长)
        vector<int> runChar, runLen;
        for (int i = 0; i < n; ) {
            int j = i;
            while (j < n && text[j] == text[i]) j++;
            runChar.push_back(text[i] - 'a');
            runLen.push_back(j - i);
            i = j;
        }

        int m = runLen.size(), ans = 0;
        for (int k = 0; k < m; k++) {
            int c = runChar[k], L = runLen[k];
            // 情况一：单段旁边补一个同类字符，受总数 cnt[c] 限制
            ans = max(ans, min(L + 1, cnt[c]));
            // 情况二：k 与 k+2 两段同类，且中间那段长度恰为 1
            if (k + 2 < m && runChar[k + 2] == c && runLen[k + 1] == 1)
                ans = max(ans, min(L + runLen[k + 2] + 1, cnt[c]));
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxRepOpt1(self, text: str) -> int:
        n = len(text)

        cnt = [0] * 26
        for ch in text:
            cnt[ord(ch) - 97] += 1

        # 游程编码：(字符, 段长)
        runs = []
        i = 0
        while i < n:
            j = i
            while j < n and text[j] == text[i]:
                j += 1
            runs.append((ord(text[i]) - 97, j - i))
            i = j

        ans = 0
        m = len(runs)
        for k in range(m):
            c, L = runs[k]
            # 情况一：单段旁边补一个同类字符，受总数 cnt[c] 限制
            ans = max(ans, min(L + 1, cnt[c]))
            # 情况二：k 与 k+2 两段同类，且中间那段长度恰为 1
            if k + 2 < m and runs[k + 2][0] == c and runs[k + 1][1] == 1:
                ans = max(ans, min(L + runs[k + 2][1] + 1, cnt[c]))
        return ans
```

## 8. 边界情况与易错点

1. **长度为 1**：`text = "a"`，只有一段 $a\times 1$，候选一 $\min(2,1)=1$，返回 1，正确。
2. **全串同一字符**：`"aaaaa"` 的候选一是 $6$，必须由 $\min(6,5)$ 截回 5；漏掉这层截断就会输出 6，直接错。
3. **允许不交换**：题面是「交换一次**或者什么都不做**」。把「必须交换」当条件，就会漏掉 `text = "aaaaa"` 返回 5 这类答案。
4. **间隔为 2 不能拼**：`"aaabbaaa"` 里两段 `a` 隔着 `bb`，若按「两段之和 + 1」硬算会得到 7，正确是 4。判定条件必须是中间段长**恰好等于 1**。
5. **用总计数而不是段长**：截断用 $\text{cnt}[c]$（全串该字符总数），不是当前段长；用段长会让候选一恒等于 $L+1$，在 `"aaaaa"`、`"aaabaaa"` 上直接错。
6. **拼接方向**：`k` 与 `k+2` 同字符才可能拼接；写成 `k` 与 `k+1` 比较永远不成立（相邻游程字符必不同），会静默漏解。
7. **别用递归分治**：$n = 2\times10^4$ 时递归拆串在退化输入（全同字符）上深度过大；本解法全程迭代。
8. **多字符覆盖**：答案可能来自任意字母，必须对所有段取最大，不能只统计出现最多的那个字母。

**延伸思考**：

1. **允许交换 $k$ 次**：形态从「单段 / 两段拼一段」变成「最多跨 $k$ 个洞」。可以用双指针维护「窗口内异字符个数 $\le k$ 且窗口内该字符个数 $\le \text{cnt}[c]$」的窗口，答案取窗口长度与该字符总数的较小值。
2. **只允许交换相邻字符**：结论会变——一次交换只能把一个字符挪一格，能拼接的条件变成「洞与可用字符的距离为 1」，需要额外记录距离信息。
3. **要求输出具体子串**：在枚举候选时顺手记下区间端点，注意「拼接可用但字符不够」的情形要退回到 $L_1+L_2$ 的区间（即第二段整体前移一格后的位置），而不是简单截断长度。
