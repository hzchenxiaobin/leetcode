# LeetCode 一年中的第几天 题解

## 1. 题目概述

- **标题 / 题号**：一年中的第几天（#1154，easy）
- **链接**：https://leetcode.cn/problems/day-of-the-year/
- **来源**：LeetCode 第 149 场周赛 Q1
- **难度**：简单
- **标签**：数学、字符串

**题意**：给定 `YYYY-MM-DD` 格式的字符串 `date`，它表示现行公元纪年法（格里高利历）下的一个真实日期。返回这个日期是**当年的第几天**——也就是把同一年的所有日期从 1 月 1 日开始按 1、2、3……依次编号后，`date` 对应的编号。

**约束**：

- `date.length == 10`，`date[4] == date[7] == '-'`，其余字符全是数字
- 日期落在 1900 年 1 月 1 日 ~ 2019 年 12 月 31 日之间，且保证是真实存在的日期
- 返回值范围 $[1, 366]$：闰年 12 月 31 日是第 366 天

> 💡 签到题定位：本题没有算法难度，全部工作量集中在两个知识点——**月长表**与**闰年规则**。周赛里能在 3 分钟内写对、且一次提交通过，才是 Q1 的正确打开方式。

## 2. 示例

**示例 1**

```text
输入：date = "2019-01-09"
输出：9
解释：1 月之前的整月为空，C[0] = 0，答案就是本月的第 9 天，0 + 9 = 9。
```

**示例 2**

```text
输入：date = "2019-02-10"
输出：41
解释：1 月整月 31 天已经全部过去，再加上本月的第 10 天，31 + 10 = 41。
```

**示例 3（边界自测，非官方）**

```text
输入：date = "2016-03-01"     输出：61
解释：2016 是闰年，1 月 31 天 + 2 月 29 天 = 60，再加本月的第 1 天，60 + 1 = 61。
输入：date = "1900-03-01"     输出：60
解释：1900 能被 100 整除但不能被 400 整除，不是闰年，31 + 28 + 1 = 60。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是把「第几天」真的数出来，有两种写法：

1. **逐日推进**：从当年 1 月 1 日开始一天一天往后加，走到目标日期时数了多少步就是答案。Python 里用 `datetime.date` 加 `timedelta` 三行就能写，C++ 要自己处理「月末进位 + 闰年 2 月 29 日」。
2. **逐月累加**：令 $ans = 0$，对 $m' = 1, 2, \dots, m-1$ 依次加上该月天数，最后 $ans \leftarrow ans + d$。

第一种写法每次最多走 365 步，而本题只问一次，性能上完全跑得动；但它把「闰年」藏进了日期库或自写的进位逻辑里，代码更长、出错面更大。第二种已经抓住了本题的本质，只是「逐月累加」这个循环还可以进一步压成一张预先算好的表。

> 结论：这道题不存在「暴力过不去」的性能瓶颈，真正的风险是**闰年规则的细节**与**下标偏移**。

### 3.2 核心观察：前缀表 + 一次闰年修正

![前面整月的天数之和 + 本月第几天](images/wc149_q1_month_prefix_model.svg)

把「第几天」拆成两段互不干扰的部分：

- **前面整月**：从 1 月 1 日到 $m$ 月 1 日之前，共 $C[m-1]$ 天，其中

$$C[0] = 0,\quad C[1] = 31,\quad C[2] = 59,\quad \dots,\quad C[11] = 334,\quad C[12] = 365$$

$C$ 就是平年的「月末累计天数」，只有 13 个常数，写成静态数组即可查表。
- **本月之内**：$m$ 月 $d$ 日之前还有 $d-1$ 天，算上自己一共 $d$ 天。

于是 $ans = C[m-1] + d$，而**唯一的变量是闰年**。闰年相对平年只多一天，就是 2 月 29 日；这一天会不会落进「前面整月」这一段，完全由 $m$ 决定：

- $m \ge 3$ 时，2 月整月都在前缀里 → 答案要 $+1$；
- $m \le 2$ 时，前缀里一个 2 月的日子都没有 → 答案不变。

所以最终公式只有一行：

$$ans = C[m-1] + d + [\,\text{闰年} \wedge m \ge 3\,]$$

这里的方括号 $[\cdot]$ 是 Iverson 括号：条件成立取 1，不成立取 0。一次查表、一次加法、一次布尔判定，$O(1)$ 收工。

### 3.3 算法流程

![解析 → 查表 → 闰年修正 → 返回](images/wc149_q1_leap_adjust_flow.svg)

1. **切字段**：年份 $y$ 取 `date[0..3]`，月份 $m$ 取 `date[5..6]`，日 $d$ 取 `date[8..9]`，跳过两个 `'-'`。
2. **查表求前缀**：$ans = C[m-1] + d$。
3. **闰年判定**：

$$\text{leap}(y) \iff y \bmod 4 = 0 \ \wedge\ \bigl(y \bmod 100 \ne 0 \ \vee\ y \bmod 400 = 0\bigr)$$

4. **闰年修正**：若 $\text{leap}(y)$ 且 $m \ge 3$，则 $ans \leftarrow ans + 1$。
5. **返回** `ans`。

### 3.4 示例演算

![五组日期的查表与修正过程](images/wc149_q1_walkthrough.svg)

| 日期 | $(y,m,d)$ | $C[m-1]$ | $d$ | 闰年 | $m \ge 3$ | 修正 | 答案 |
|---|---|---|---|---|---|---|---|
| `2019-01-09` | (2019, 1, 9) | 0 | 9 | 否 | 否 | 0 | **9** |
| `2019-02-10` | (2019, 2, 10) | 31 | 10 | 否 | 否 | 0 | **41** |
| `2016-03-01` | (2016, 3, 1) | 59 | 1 | 是 | 是 | +1 | **61** |
| `1900-03-01` | (1900, 3, 1) | 59 | 1 | 否 | 是 | 0 | **60** |
| `2019-12-31` | (2019, 12, 31) | 334 | 31 | 否 | 是 | 0 | **365** |

前两行正是官方示例；第 3、4 行只差一个闰年判定，答案就差 1（61 对 60）——这就是本题唯一需要小心的地方。

## 4. 算法细节

1. **切字段的三种写法**：`stoi(date.substr(0,4))` / `sscanf(date.c_str(), "%d-%d-%d", &y, &m, &d)` / 直接按位取字符（月份 `(date[5]-'0')*10 + (date[6]-'0')`，日 `(date[8]-'0')*10 + (date[9]-'0')`）。第一种最易读，第三种最快，周赛里任选其一即可。
2. **下标别错位**：`date[0..3]` 是年，`date[5..6]` 是月，`date[8..9]` 是日。常见错误是月份只取 `date[5]` 一个字符，前 9 个月侥幸正确，10 月以后立刻错。
3. **月长表 vs 前缀表**：逐月累加是 $O(12)$，查前缀表是 $O(1)$；本题两者都是常数级，但**前缀表把「查哪一格」的推导固定下来**，不容易写错边界（$C[m-1]$ 而不是 $C[m]$）。
4. **闰年规则必须写全**：$y \bmod 4 = 0$ 且（$y \bmod 100 \ne 0$ 或 $y \bmod 400 = 0$）。在本题范围内 1900 与 2000 正好卡在两个分支上：1900 不是闰年、2000 是闰年。只写 $y \bmod 4 = 0$ 会让 `1900-03-01` 错答 61；漏掉 400 分支会让 `2000-03-01` 错答 60。
5. **修正条件是 $m \ge 3$**：等价写法是 $m > 2$。注意不能写成 $m \ne 2$（那 1 月会被错误地 $+1$），也不能写成 $m \ge 2$（2 月本身还没跨过 2 月 29 日）。
6. **表要静态化**：C++ 用 `static const int C[13]`（函数内的 `static` 只初始化一次），Python 用元组常量 `PRE`（编译期常量，不会每次调用重建）。
7. **不要用 `mktime` / `tm_yday` 走捷径**：`struct tm` 的年是「相对 1900 的偏移」（`tm_year = y - 1900`），`tm_yday` 从 0 开始（要再 $+1$），而且 `tm_isdst` 不初始化时结果依赖本地时区与夏令时设置——判题机换个时区就可能错，得不偿失。
8. **日期合法性无需校验**：题面保证输入是真实存在的日期，因此不必判断 2 月 29 日是否越界，省掉一组分支。

## 5. 正确性证明

**引理 1（闰年判定与历法定义等价）**：对任意整数 $y \ge 1$，$\text{leap}(y)$ 为真当且仅当格里高利历中 $y$ 年的 2 月有 29 天。

**证明**：格里高利历的闰年定义即「$y$ 被 4 整除，且当 $y$ 被 100 整除时必须被 400 整除」，逐字对应判定式 $y \bmod 4 = 0 \wedge (y \bmod 100 \ne 0 \vee y \bmod 400 = 0)$，故两者等价。∎

**引理 2（前缀表刻画前面的整月）**：在平年，1 月 1 日到 $m$ 月 1 日（不含）之间的天数恰好是 $C[m-1]$，其中 $1 \le m \le 12$。

**证明**：对 $m$ 归纳。$m = 1$ 时区间为空，天数为 $0 = C[0]$。设结论对 $m$ 成立，则 1 月 1 日到 $m+1$ 月 1 日的天数为 $C[m-1]$ 加上平年 $m$ 月的天数；按月长表逐项相加得 $C[m] = C[m-1] + \text{days}(m)$，与 $C$ 的定义一致。故对 $1 \le m \le 12$ 都成立。∎

**引理 3（闰年修正的充要条件）**：对闰年 $y$，1 月 1 日到 $m$ 月 1 日（不含）之间的天数比平年同月份多 1 天，当且仅当 $m \ge 3$；否则两者相等。

**证明**：由引理 1，闰年与平年的月长仅在 2 月不同（29 对 28），其余 11 个月完全相同。

- 若 $m \ge 3$：区间 $[1/1,\ m/1)$ 完整包含 2 月，两年的时间差恰为 $29 - 28 = 1$。
- 若 $m \le 2$：区间只含 1 月（$m = 1$ 时为空、$m = 2$ 时只含整个 1 月），不含任何 2 月的日子，故两年天差为 0。

两方向均得证。∎

**引理 4（段内计数）**：设 $S$ 为 1 月 1 日到 $m$ 月 1 日（不含）之间的天数，则 $m$ 月 $d$ 日是当年的第 $S + d$ 天。

**证明**：$m$ 月 1 日之前有 $S$ 天，$m$ 月 1 日是第 $S+1$ 天；每过一天编号加 1，故 $m$ 月 $d$ 日是第 $S + d$ 天。∎

**定理**：算法对约束内任意合法日期返回其「当年第几天」。

**证明**：设 $S$ 为「1 月 1 日到 $m$ 月 1 日（不含）」在**当前这个具体年份**（已含闰年修正）里的天数。算法先按平年查表得 $C[m-1]$，由引理 2 它等于平年前面整月的天数；再由引理 1 得到正确的闰年判定、由引理 3 得到正确的修正项（闰年且 $m \ge 3$ 时补 1 天，其余情况不补），故 $C[m-1] + [\text{闰年} \wedge m \ge 3]$ 恰等于 $S$，返回值就是 $S + d$。由引理 4，$S + d$ 正是 $m$ 月 $d$ 日的编号，故返回值正确。∎

## 6. 复杂度分析

- **时间**：$O(1)$。三次定长子串解析（各 2~4 个字符）、一次数组下标、若干次整数运算与布尔判定，全部与输入规模无关；即使写成「逐月累加」的循环版本也只是固定的 12 次加法，仍是 $O(1)$。
- **空间**：$O(1)$。只用 13 个整数的常量表与几个标量变量，没有随输入增长的辅助结构。
- **对比**：逐日推进法时间 $O(366)$、空间 $O(1)$；日期库方案时间也是 $O(1)$ 但常数大、且依赖时区与平台实现。本题解把「月长」这一层完全预计算，是这类「历法换算」题的标准形态。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <cstdlib>
using namespace std;

class Solution {
public:
    int dayOfYear(string date) {
        // C[k] = 平年下前 k 个月的总天数（即 k 月末的累计天数），C[0] = 0
        static const int C[13] = {0, 31, 59, 90, 120, 151, 181,
                                  212, 243, 273, 304, 334, 365};
        int y = stoi(date.substr(0, 4));
        int m = stoi(date.substr(5, 2));
        int d = stoi(date.substr(8, 2));

        int ans = C[m - 1] + d;                   // 前面整月 + 本月第几天
        bool leap = (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
        if (leap && m >= 3) ++ans;                // 只有跨过 2 月才补 1 天
        return ans;
    }
};
```

### Python

```python
class Solution:
    def dayOfYear(self, date: str) -> int:
        # PRE[k] = 平年下前 k 个月的总天数（即 k 月末的累计天数），PRE[0] = 0
        PRE = (0, 31, 59, 90, 120, 151, 181, 212, 243, 273, 304, 334, 365)
        y, m, d = int(date[0:4]), int(date[5:7]), int(date[8:10])

        ans = PRE[m - 1] + d                      # 前面整月 + 本月第几天
        leap = (y % 4 == 0 and y % 100 != 0) or y % 400 == 0
        if leap and m >= 3:                       # 只有跨过 2 月才补 1 天
            ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **1 月**：$C[0] = 0$ 与前缀表首元素重合，写成 $C[m-1]$ 后天然正确；若表从下标 1 开始装「本月天数」，就要小心别把 1 月的空前缀漏掉。
2. **1900 与 2000 的分水岭**：`1900-03-01` 应为 60，`2000-03-01` 应为 61。只写 $y \bmod 4 = 0$ 会把前者错答 61；漏掉 400 分支会把后者错答 60。这两组是本题最有效的自测数据。
3. **2 月 29 日**：`2016-02-29` 的答案是 60。此时 $m = 2 < 3$ 不触发修正，但 $d = 29$ 本身已经包含了这一天，不必额外 +1。
4. **12 月 31 日**：平年是 365（$C[11] = 334$ 加 31），闰年是 366。若把闰年修正写成「月份 $\ge 2$」就会在 1 月、2 月多算一天，年底反而看不出来，容易漏测。
5. **月份取位**：`date[5..6]` 才是月份。只取 `date[5]` 会让 1~9 月全对、10~12 月全错，属于最隐蔽的一类 bug。
6. **`stoi` 的异常**：输入保证合法，不会抛异常；但如果用 `atoi(date.c_str())` 只取到第一个 `'-'` 之前，得到的只是年份，属于另一类错。
7. **返回值类型**：答案最大 366，`int` 足够；不要在 Python 里用浮点运算（`/` 会得到 `float`），一律用整数运算与 `//`。
8. **别滥用日期库**：`mktime` 的 `tm_yday` 从 0 开始、`tm_year` 是 `y - 1900` 的偏移，且与本地时区耦合；周赛里用它等于给自己引入不可控变量。
