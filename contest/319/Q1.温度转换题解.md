# LeetCode 温度转换 题解

## 1. 题目概述

- **标题 / 题号**：温度转换（#2469，easy）
- **链接**：https://leetcode.cn/problems/convert-the-temperature/
- **来源**：LeetCode 第 319 场周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：给定四舍五入到两位小数的非负浮点数 $\text{celsius}$（摄氏度），将其换算为**开氏度**（Kelvin）与**华氏度**（Fahrenheit），以数组 $\text{ans}=[\text{kelvin},\text{fahrenheit}]$ 的形式返回。题面直接给出两条公式：

$$K = C + 273.15 \qquad F = C \times 1.80 + 32.00$$

与实际答案误差不超过 $10^{-5}$ 视为正确。

**约束**：

- $0 \le \text{celsius} \le 1000$，输入已四舍五入到两位小数
- 判题按数值容差 $10^{-5}$ 比较，与输出的小数位数无关

> 💡 本题在本仓库另有[每日题解 2469](../../solution/2401-2500/2469_温度转换.md)：侧重**温标公式的物理推导**（仿射映射由水的冰点/沸点两点标定）与面试问答。本篇按周赛复盘视角展开，侧重**签到题的最短提交路径**（读题 → 抄公式 → 一行代码）、**浮点误差界的定量证明**与**容差判题下的边界处理**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：celsius = 36.50
输出：[309.65000, 97.70000]
解释：K = 36.50 + 273.15 = 309.65；F = 36.50 × 1.80 + 32.00 = 97.70。
```

**示例 2**

```text
输入：celsius = 122.11
输出：[395.26000, 251.79800]
解释：K = 122.11 + 273.15 = 395.26；F = 122.11 × 1.80 + 32.00 = 251.798。
```

**示例 3**（自构造，下边界）

```text
输入：celsius = 0
输出：[273.15000, 32.00000]
解释：开氏度不是 0 —— 0K 是绝对零度；华氏度恰为水冰点读数 32。
```

## 3. 解题思路

### 3.1 朴素思路：抄公式，就是最优

本题的「暴力」与「最优」完全重合：无循环、无分支、无数据结构，把题面两条公式原样翻译成代码即可，$O(1)$ 时间、$O(1)$ 空间，不存在可优化的维度。

签到题的复盘价值不在「怎么优化」，而在两件事：

1. **最短路径**：从读题到提交控制在一分钟内，把时间留给后面的 Q3/Q4；
2. **不翻车**：本题能 WA 的点只有「返回顺序」「公式方向」「画蛇添足的精度处理」三处，逐条见 §8。

> ⚠️ 唯一值得多想一步的是「$10^{-5}$ 容差下浮点直算是否安全」——答案是安全，且裕度高达 8 个数量级，见 §3.2 的直觉判断与 §5 的定量证明。

### 3.2 核心观察：两路独立的一次仿射运算

![核心观察：两路无依赖的一次仿射运算，误差比容差低八个数量级](images/wc319_tempconvert_formulas.svg)

两条公式结构极简：

- **开氏路**：一次加法（纯平移，$a=1,\ b=273.15$）；
- **华氏路**：一次乘法 + 一次加法（缩放 + 平移，$a=1.8,\ b=32$）。

两路之间**无任何数据依赖**，只是对同一个输入各做一次一元仿射变换。这意味着：

1. 代码就是两条独立表达式，写法、求值顺序随意，没有状态、没有分支；
2. 浮点结果至多经历 $1\sim 2$ 次运算舍入外加常数表示误差，量级 $\sim 10^{-13}$，比容差 $10^{-5}$ 低 **8 个数量级**——`double` 直算必然通过，不需要定点化、高精度或任何舍入处理。

> 💡 「误差比容差低几个数量级」是判断浮点题要不要做精度处理的唯一标准：低 3 个数量级以上就放心直算。本题低 8 个，属于「闭着眼交」。

### 3.3 算法流程

![算法流程：读入 celsius，两路并行套公式，按开氏在前拼装返回](images/wc319_tempconvert_flow.svg)

1. 读入 `celsius`（`double`，输入接口本身是浮点，无需解析字符串）；
2. 左路：$\text{kelvin} \leftarrow \text{celsius} + 273.15$；
3. 右路：$\text{fahrenheit} \leftarrow \text{celsius} \times 1.80 + 32.00$；
4. 按**开氏在前、华氏在后**的顺序拼装数组返回。

提交前 3 秒自检：顺序 $[K, F]$ ✓、公式方向照抄题面 ✓、不做多余 round ✓。

### 3.4 示例演算

![示例演算：36.50、122.11 与边界 0 三组输入的两路计算](images/wc319_tempconvert_walkthrough.svg)

| celsius | 开氏路 $C+273.15$ | 华氏路 $C\times 1.8+32$ | 返回 |
|---------|-------------------|--------------------------|------|
| $36.50$ | $36.50+273.15=309.65$ | $65.70+32=97.70$ | $[309.65,\ 97.70]$ |
| $122.11$ | $395.26$ | $219.798+32=251.798$ | $[395.26,\ 251.798]$ |
| $0$（边界） | $273.15$ | $32.00$ | $[273.15,\ 32.00]$ |

注意示例 2 的华氏度出现**三位小数** $251.798$：$122.11\times 1.8$ 的尾数由 $1.8=\frac{9}{5}$ 的分母 $5$ 与输入百分位组合产生。判题按容差比较数值、不固定位数，输出 `251.798` 与 `251.79800` 等价。

## 4. 算法细节

1. **返回顺序**：`[kelvin, fahrenheit]`，开氏在前。顺序反了是数值完全不同的数组，判题直接 WA。
2. **常数照抄题面**：`273.15`、`1.80`、`32.00` 三个常数按题面原样写字面量，不预先合并、不化简（把 $F=1.8C+32$ 改写成 $F=1.8\,(C+17.77\ldots)$ 之类只会引入多余舍入与笔误风险）。
3. **类型**：全程 `double`（C++），Python 浮点即 IEEE-754 双精度。输入接口就是浮点数，直接使用。
4. **无需输出格式化**：示例中的 `309.65000` 五位小数只是**展示格式**；判题按 $|\text{ans}-\text{expected}|\le 10^{-5}$ 做数值比较，`round` / `printf` 补零属于画蛇添足——`round(x, 5)` 至多引入 $0.5\times 10^{-5}$ 的额外偏差，白白吃掉一半容差预算。
5. **过度设计警告**：把 `celsius` 放大 $100$ 倍转整数做定点运算，或引入 `decimal` / `BigDecimal`，在本题容差下毫无收益，只会扩大出错面。

## 5. 正确性证明

**引理 1（误差单元上界）**：本题涉及的所有数值——输入（$\le 1000$）、三个常数、中间积（$\le 1800.0002$）、两个输出（$\le 1273.15$ 与 $\le 1832$）——都落在 $[0, 2048)$ 内。该区间内 ulp 至大为 $2^{-42}$，故任何一次**表示误差或加减法舍入误差**均 $\le 2^{-43} < 1.2\times 10^{-13}$；乘法舍入的相对误差 $\le 2^{-53}$，积的量级 $\le 1801$，故乘法舍入的绝对误差 $\le 1801\times 2^{-53} < 2.1\times 10^{-13}$。

**证明**：IEEE-754 双精度含隐含位共 53 位尾数，采用最近舍入时误差不超过半 ulp；$v\in[2^e, 2^{e+1})$ 时 $\text{ulp}(v)=2^{e-52}$。由 $v < 2048 = 2^{11}$ 得 $e \le 10$，ulp $\le 2^{-42}$，半 ulp $\le 2^{-43}$。正确舍入的基本运算结果相对误差 $\le 2^{-53}$，将积的上界代入即得。∎

**引理 2（输出误差界）**：算法输出的 $\text{kelvin}$ 与 $\text{fahrenheit}$ 与精确十进制结果之差分别小于 $3\times 10^{-13}$ 与 $10^{-12}$。

**证明**：开氏路共 1 次加法：输入表示误差 $\le 2^{-44}$（$c \le 1000 < 1024$ 的半 ulp）$+\ 2^{-45}$（$273.15 \in [256,512)$ 的半 ulp）$< 9\times 10^{-14}$；加法结果 $1273.15 \in [1024,2048)$，舍入误差 $\le 2^{-43}$。合计 $< 2.1\times 10^{-13} < 3\times 10^{-13}$。华氏路 1 次乘法 1 次加法：乘法舍入 $\le 2.1\times 10^{-13}$（引理 1）；输入表示误差经乘法线性传递 $\le 1.8\times 2^{-44} + 1000\times 1.11\times 10^{-16} < 2.2\times 10^{-13}$；$32.00$ 的表示误差 $\le 2^{-48}$；加法结果 $1832 \in [1024, 2048)$，舍入误差 $\le 2^{-43}$。逐项合计 $< 5.6\times 10^{-13} < 10^{-12}$。∎

**定理**：算法输出通过判题。

**证明**：由引理 2，两个输出分量与精确十进制答案的偏差均 $< 10^{-12}$，比判题容差 $10^{-5}$ 低 7 个数量级以上，故 $|\text{ans}_i - \text{expected}_i| < 10^{-5}$ 对两个分量成立。∎

> 💡 上述是对「精确十进制答案」的保守界。实际上判题的 expected 值本身也按 `double` 计算，两边的浮点路径通常完全一致、偏差恰为 $0$；证明取最坏情形依然宽裕，结论更稳。

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。一次加法 + 一次乘加，共常数次浮点运算，与任何规模量无关（输入本身就是一个数）。
- **空间复杂度**：$O(1)$。仅构造长度为 $2$ 的返回数组。

$O(1)$ / $O(1)$ 已是理论下界（至少读一个输入、写两个输出），复杂度上无可打磨；比赛时的全部注意力应放在**不翻车**上。

    }

```

```

两版都是一行返回：初始化列表直接构造返回容器，两条表达式互不依赖。常数写成 `1.80`、`32.00` 与题面保持一致（字面量类型均为 `double`）。

## 8. 边界情况与易错点

1. **返回顺序 $[K, F]$**：开氏度在前。按「华氏度更常见」的直觉写成 $[F, K]$ 是本题最高频 WA。
2. **公式方向**：$F = C\times 1.8 + 32$，别记成逆公式 $C = (F-32)/1.8$ 的方向；$K = C + 273.15$ 是**加** $273.15$，不是减。
3. **$\text{celsius} = 0$ 不是零输出**：返回 $[273.15,\ 32.00]$，下边界无需任何特判。
4. **`float` 裕度薄**：单精度约 7 位有效数字，$1832$ 量级的绝对误差达 $\sim 10^{-4}$，贴着容差；统一用 `double`（误差 $\sim 10^{-13}$）。
5. **不要 round / 格式化输出**：判题按数值容差，示例的五位小数只是展示；`round(x, 5)` 至多吃掉一半容差预算。
6. **整数化 / 高精度属过度设计**：容差 $10^{-5}$ 下毫无收益，只增加出错面（放大倍数、符号、还原除法都可能引错）。
