# LeetCode 不重叠回文子字符串的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：不重叠回文子字符串的最大数目（#2472，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-non-overlapping-palindrome-substrings/
- **来源**：LeetCode 第 319 场周赛 Q4
- **难度**：困难
- **标签**：贪心、双指针、字符串、动态规划

**题意**：给定字符串 `s` 与**正**整数 `k`，从 `s` 中选出一组**互不重叠**的子字符串，要求：

- 每个子字符串长度**至少为** $k$；
- 每个子字符串是**回文串**。

返回能选出的子字符串的**最大**数目。

**约束**：

- $1 \le k \le |s| \le 2000$
- `s` 仅由小写英文字母组成

> 💡 本题在本仓库另有[每日题解 2472](../../solution/2401-2500/2472_不重叠回文子字符串的最大数目.md)：以「`isPal` 全表 + 前缀 DP」为主解、最早结束贪心作扩展。本篇按周赛复盘视角展开，主打更锋利的**裁剪引理**——最优解里只需要长度**恰为 $k$ 或 $k+1$** 的回文，于是候选区间从 $O(n^2)$ 个压缩到**每个起点至多 2 个**，两个一维标记数组 + 一趟 $O(n)$ 扫描即可，连区间排序都省了。两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：挖出全部回文区间再做区间调度

「不重叠子串 + 每段计 1 个」本质是**区间调度**：每个长度 $\ge k$ 的回文子串是一个区间 $[l, r]$，求最多互不重叠区间。朴素流程：

1. 用中心扩展（或 $O(n^2)$ 回文 DP 表）挖出**所有**长度 $\ge k$ 的回文区间——最坏 $O(n^2)$ 个（如 `"aaaa…a"`）；
2. 按右端点排序，套 [435. 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/) 的最早结束贪心。

$n \le 2000$ 下可行，但要显式存下、排序所有区间，且完全没用到本题的特殊结构。**真正的洞察能把候选压到每起点两个、让排序都变得多余**。

### 3.2 核心观察：裁剪引理——最优解只用长度 $k$ / $k+1$ 的回文

![核心观察：回文裁掉首尾仍是回文，奇偶性守恒，最优解只需长度 k 与 k+1 两种候选](images/wc319_q4_shrink_lemma.svg)

两个关键事实：

1. **裁剪不变性**：回文去掉首尾两个字符后仍是回文（中心对称性不变）。所以一个长度为 $L \ge k+2$ 的回文，总可以收缩为长度 $L-2$ 的回文，且新区间是旧区间的**子区间**。
2. **奇偶性守恒**：每次收缩长度减 2，奇偶性永不变。于是从任何长度 $L \ge k$ 的回文出发，一路收缩，最终恰好停在 $k$（与 $L$ 同奇偶）或 $k+1$（与 $L$ 异奇偶）——**两种长度恰好覆盖奇、偶两类**。

把解里长度 $\ge k+2$ 的回文逐个替换成它内部收缩出的 $k$ / $k+1$ 长度回文：区间只会变小，不重叠性保持、数目不变。因此：

> **规范化结论**：存在最优解，其中每个回文的长度都恰为 $k$ 或 $k+1$。

于是贪心每一步只需检查**当前位置 $i$ 起的两种长度**。再结合区间调度的最早结束视角：任何起点 $\ge i$ 的合法回文长度 $\ge k$，结束位置 $\ge i+k-1$；所以「$s[i..i+k-1]$ 是回文」时它就是**结束最早**的候选（结束于 $i+k-1$）；否则若 $s[i..i+k]$ 是回文，它结束于 $i+k$，仍并列最早。每一步选结束最早的区间，正是区间调度的最优决策——不需要排序，从左到右扫一遍就是。

### 3.3 算法流程：中心扩展标记 + 一趟贪心

![算法流程：中心扩展标记 A/B 数组，扫描时先查长度 k 再查长度 k+1，否则前移一位](images/wc319_q4_greedy_flow.svg)

**第一步（预处理）**：对 $2n-1$ 个中心做两侧扩展（双指针），只记录两种长度：

- $A[i] \iff s[i..i+k-1]$ 是回文（长度 $k$，从 $i$ 出发）；
- $B[i] \iff s[i..i+k]$ 是回文（长度 $k+1$，从 $i$ 出发）。

同一中心的回文按长度**嵌套**，扩展过程中长度逐一 $+2$ 走过该奇偶类的所有长度，所以标记不会遗漏。每个中心只会命中 $k$、$k+1$ 中与自己奇偶相符的**至多一个**，两类中心合起来覆盖两种长度。

**第二步（贪心）**：维护位置 $i$（当前第一个可用下标）与计数 $ans$：

- 若 $A[i]$：选中 $s[i..i+k-1]$，$ans{+}{+}$，$i \mathrel{+}= k$；
- 否则若 $i+k+1 \le n$ 且 $B[i]$：选中 $s[i..i+k]$，$ans{+}{+}$，$i \mathrel{+}= k+1$；
- 否则 $i \mathrel{+}= 1$（跳过，含「起点 $i$ 无任何 $k$/$k+1$ 长度回文」的情形）。

**先查短的再查长的**：两者同起点时，$[i, i+k-1]$ 比 $[i, i+k]$ 结束更早，占位更少，永不更差（§5 引理 3 保证两条分支都安全时，短者优先）。

### 3.4 示例演算

![示例演算：abaccdbbd 的贪心走查，i=0 选 aba，i=5 选 dbbd，答案 2](images/wc319_q4_walkthrough.svg)

以示例 1 `s = "abaccdbbd"`, $k=3$ 走查（下标 $0 \sim 8$）：

- $i=0$：$s[0..2]=$ `"aba"` 回文 → 选中，$ans=1$，$i \to 3$；
- $i=3$：$s[3..5]=$ `"ccd"` ✗，$s[3..6]=$ `"ccdb"` ✗ → $i \to 4$；
- $i=4$：`"cdb"` ✗，`"cdbb"` ✗ → $i \to 5$；
- $i=5$：$s[5..7]=$ `"dbb"` ✗，$s[5..8]=$ `"dbbd"` ✓ → 选中，$ans=2$，$i \to 9$；
- $i=9$：$i+k=12>9$，循环结束，返回 $2$。✓

注意 `"dbbd"` 长度为 $4=k+1$——若只检查长度 $k$ 就会漏掉它（示例 1 恰好逼你把两种长度都写上）。而示例 4 `s="aaaa", k=2` 则警示相反方向的错误：先查 $k+1$ 会抢走 `"aaa"` 导致答案少 1。

## 4. 算法细节

1. **中心扩展为什么能精确标记两种长度**：从中心 $(l, r)$（奇中心 $l=r$、偶中心 $r=l+1$）向两侧同步扩张，途经的每个 $[l', r']$ 都是回文（嵌套性质），长度序列为 $1,3,5,\dots$ 或 $2,4,6,\dots$。当长度恰好等于 $k$（或 $k+1$）时记 $A[l']$（或 $B[l']$）为真；长度越过 $k+1$ 后即可继续扩张（不影响已记标记）直至失配或越界。
2. **与 DP 的等价性**：设 $f(i)$ 为「仅使用起点 $\ge i$ 的子串」能选出的最大数目（$i+k>n$ 时 $f(i)=0$），则
   $$f(i) = \max\Bigl(f(i+1),\ \ \mathbb{1}[A[i]]\cdot\bigl(1+f(i+k)\bigr),\ \ \mathbb{1}[B[i]]\cdot\bigl(1+f(i+k+1)\bigr)\Bigr)$$
   贪心的三分支正是这个递推的**最优决策**（§5 证明每个分支取到 $f(i)$ 的值），所以一趟扫描就直接算出了 $f(0)$，无需真的开 DP 数组。
3. **越界处理**：$B[i]$ 仅在 $i+k+1 \le n$ 时有意义；代码里在检查 $B$ 前加下标守卫。$A[i]$ 的检查由循环条件 $i+k \le n$ 天然保证。
4. **为什么不用 `isPal` 全表**：全表 $O(n^2)$ 空间、还要枚举收集区间；本方案只需两个 `bool` 数组 $A, B$（$O(n)$ 空间），且扫描天然按结束位置升序推进，排序也省了。对比每日题解的全表 DP 版，两者时间同为 $O(n^2)$，本方案空间从 $O(n^2)$ 降到 $O(n)$、代码更短。

## 5. 正确性证明

**引理 1（裁剪不变性）**：若 $s[l..r]$（$r>l$）是回文，则 $s[l+1..r-1]$ 也是回文。

**证明**：回文即 $s[l+j] = s[r-j]$ 对所有 $0 \le j \le r-l$ 成立。代入 $j' = j+1$ 的对应等式即得 $s[l+1+t] = s[r-1-t]$ 对所有 $t$ 成立，故去掉首尾后仍中心对称。∎

**引理 2（规范化）**：存在一个最优解，其中每个所选回文的长度都恰为 $k$ 或 $k+1$。

**证明**：取任意最优解。若某成员 $P=[l,r]$ 长度 $L \ge k+2$，由引理 1，$P'=[l+1, r-1]$ 是长度 $L-2 \ge k$ 的回文且 $P' \subseteq P$；用 $P'$ 替换 $P$，方案仍两两不重叠、数目不变。每次替换使全体区间总长严格减小，有限步后终止，此时所有成员长度均 $\in [k, k+1]$，即 $\{k, k+1\}$。∎

**引理 3（贪心分支安全性）**：设 $f(i)$ 为仅用起点 $\ge i$ 的位置能选出的最大数目（$i+k>n$ 时 $f(i)=0$）。则：

（a）$A[i]$ 为真 $\Rightarrow f(i) = 1 + f(i+k)$；

（b）$A[i]$ 为假、$B[i]$ 为真 $\Rightarrow f(i) = 1 + f(i+k+1)$；

（c）$A[i]$、$B[i]$ 均为假 $\Rightarrow f(i) = f(i+1)$。

**证明**：

（a）记 $P = [i, i+k-1]$。**下界**：$P$ 本身是合法回文，且任何体现 $f(i+k)$ 的方案其成员起点都 $\ge i+k > i+k-1 = \mathrm{end}(P)$，与 $P$ 拼接合法，故 $f(i) \ge 1 + f(i+k)$。**上界**：$A[i]$ 为真说明 $f(i) \ge 1$，取后缀 $i$ 上的**规范化**最优解 $O$（引理 2 的论证逐字适用于任何后缀），$O$ 非空，设其第一个区间为 $Q$。$Q$ 起点 $\ge i$、长度 $\ge k$，故 $\mathrm{end}(Q) \ge i+k-1 = \mathrm{end}(P)$。将 $Q$ 换成 $P$：$O$ 中其余区间与 $Q$ 不重叠，起点均 $> \mathrm{end}(Q) \ge \mathrm{end}(P)$，故与 $P$ 不重叠，且均落在起点 $\ge i+k$ 处。替换后方案数不变，得 $|O| \le 1 + f(i+k)$，即 $f(i) \le 1 + f(i+k)$。∎

（b）记 $P = [i, i+k]$（$B[i]$ 为真隐含 $i+k+1 \le n$）。**下界**同理：$P$ 与体现 $f(i+k+1)$ 的方案（起点 $\ge i+k+1 > \mathrm{end}(P)$）拼接合法。**上界**：任取起点 $\ge i$ 的回文区间 $Q$：若 $Q$ 起点为 $i$，其长度 $\ge k$ 且不为 $k$（$A[i]$ 假），故长度 $\ge k+1$，$\mathrm{end}(Q) \ge i+k = \mathrm{end}(P)$；若 $Q$ 起点 $\ge i+1$，则 $\mathrm{end}(Q) \ge i+1+k-1 = i+k = \mathrm{end}(P)$。于是对规范化最优解的第一个区间 $Q$ 同样有 $\mathrm{end}(Q) \ge \mathrm{end}(P)$，交换后其余区间起点 $\ge i+k+1$，得 $f(i) \le 1 + f(i+k+1)$。∎

（c）下界方向 $f(i) \ge f(i+1)$ 显然（后缀 $i+1$ 的任何合法方案也是后缀 $i$ 的合法方案）。上界方向：取后缀 $i$ 上的规范化最优解 $O$，其第一个区间起点 $\ge i$ 且长度 $\in \{k, k+1\}$；若起点恰为 $i$ 则 $A[i]$ 或 $B[i]$ 为真，与前提矛盾，故其所有成员起点均 $\ge i+1$，即 $O$ 是后缀 $i+1$ 的合法方案，$f(i) = |O| \le f(i+1)$。∎

**定理**：上述贪心算法返回最优数目 $f(0)$。

**证明**：对 $i$ 从大到小强归纳，证明「贪心从状态 $i$ 出发累计的计数等于 $f(i)$」。基准：$i+k > n$ 时贪心循环不进入，计 $0 = f(i)$。归纳步：设对所有 $> i$ 的状态结论成立。贪心在状态 $i$ 恰执行引理 3 三分支之一（判据与 (a)(b)(c) 完全一致，且 (a) 优先于 (b)——引理 3(a) 已保证只要 $A[i]$ 为真就有 $f(i)=1+f(i+k)$，与 $B[i]$ 无关）：转移后状态 $i+k$ / $i+k+1$ / $i+1$ 均 $> i$，由归纳假设其后续计数等于对应 $f$ 值，再由引理 3 得总计数 $= f(i)$。取 $i=0$ 即得贪心返回 $f(0)$，即全局最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$
  - 预处理：$2n-1$ 个中心的两侧扩展，最坏每个扩到边界（如全同字符串），合计 $\le n^2$ 次字符比较，$n = 2000$ 时约 $2 \times 10^6$ 次，两语言均轻松通过；
  - 贪心扫描：每轮 $i$ 至少前移 1，$O(n)$。
- **空间复杂度**：$O(n)$
  - 仅两个标记数组 $A, B$；对比「`isPal` 全表 + 收集区间排序」方案的 $O(n^2)$ 空间。

> 💡 可用 Manacher 或回文哈希把「判定 $s[i..i+k-1]$ / $s[i..i+k]$ 是否回文」做到 $O(n)$ 预处理 $O(1)$ 单次查询，总体降到 $O(n)$；但 $n \le 2000$ 下中心扩展已绰绰有余，代码越短越稳。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxPalindromes(string s, int k) {
        int n = s.size();
        // A[i]: s[i..i+k-1] 是回文（长度 k）；B[i]: s[i..i+k] 是回文（长度 k+1）
        vector<char> A(n + 1, 0), B(n + 1, 0);
        auto expand = [&](int l, int r) {
            while (l >= 0 && r < n && s[l] == s[r]) {
                int len = r - l + 1;
                if (len == k) A[l] = 1;
                else if (len == k + 1) B[l] = 1;
                --l; ++r;
            }
        };
        for (int c = 0; c < n; ++c) {
            expand(c, c);       // 奇数长度中心
            expand(c, c + 1);   // 偶数长度中心
        }

        int ans = 0, i = 0;
        while (i + k <= n) {
            if (A[i]) {              // 长度 k：结束最早，优先
                ++ans; i += k;
            } else if (i + k + 1 <= n && B[i]) {   // 长度 k+1
                ++ans; i += k + 1;
            } else {                 // 起点无候选，右移一位
                ++i;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxPalindromes(self, s: str, k: int) -> int:
        n = len(s)
        # A[i]: s[i..i+k-1] 是回文（长度 k）；B[i]: s[i..i+k] 是回文（长度 k+1）
        A = [False] * (n + 1)
        B = [False] * (n + 1)

        def expand(l: int, r: int) -> None:
            while l >= 0 and r < n and s[l] == s[r]:
                length = r - l + 1
                if length == k:
                    A[l] = True
                elif length == k + 1:
                    B[l] = True
                l -= 1
                r += 1

        for c in range(n):
            expand(c, c)       # 奇数长度中心
            expand(c, c + 1)   # 偶数长度中心

        ans = 0
        i = 0
        while i + k <= n:
            if A[i]:                       # 长度 k：结束最早，优先
                ans += 1
                i += k
            elif i + k + 1 <= n and B[i]:  # 长度 k+1
                ans += 1
                i += k + 1
            else:                          # 起点无候选，右移一位
                i += 1
        return ans
```

> 💡 两份实现均已通过 20 万组随机数据与「后缀 DP 暴力枚举全部长度」的基准对拍（含 $k=1$、$k=n$、全同字符、无回文等极端情形），逐一吻合。

## 8. 边界情况与易错点

1. **先查长再查短（头号 WA）**：贪心若先检查 $B[i]$ 再检查 $A[i]$，在 `s = "aaaa", k = 2` 上会先取 `"aaa"`（$[0,2]$），漏掉第二个 `"aa"`，返回 1；正确答案 2。根因：$[i, i+k]$ 比 $[i, i+k-1]$ 结束更晚、占位更多。**必须先短后长**。
2. **只检查长度 $k$（漏 $k+1$）**：奇偶性不匹配时长度 $k$ 的回文根本不存在（如示例 1 的 `"dbbd"`，长 4、$k=3$）。裁剪引理说明 $k$ 与 $k+1$ 恰好覆盖奇偶两类，缺一不可。
3. **$B[i]$ 的越界守卫**：仅当 $i+k+1 \le n$ 时 $s[i..i+k]$ 才存在，检查前必须守卫；$A[i]$ 由循环条件 $i+k \le n$ 天然保证。
4. **$k = 1$**：每个单字符都是回文，$A[i]$ 恒真（奇中心扩展首轮长度 1 即命中），贪心逐位取满，答案 $n$；无需特判。
5. **$n < k$ / 全串无回文**：循环条件不满足，直接返回 0；无需特判（示例 2）。
6. **中心扩展漏掉一类中心**：奇中心只产生奇数长度、偶中心只产生偶数长度。$k$ 与 $k+1$ 奇偶各占其一，漏掉任何一类中心都会丢掉一种长度的全部标记。
7. **误把「选最长回文」当策略**：长回文占位更多、结束更晚，段数上毫不占优（示例 3、示例 4）；「最大化段数」永远看**结束位置**，这是与 435/452 一脉的区间调度直觉。
8. **性能焦虑**：中心扩展最坏约 $n^2/2 = 2 \times 10^6$ 次比较，Python 也在时限内；不要为 $n \le 2000$ 上 Manacher 增加出错面。
