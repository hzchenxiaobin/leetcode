# LeetCode 上升下降字符串 题解

## 1. 题目概述

- **标题 / 题号**：上升下降字符串（#1370，easy）
- **链接**：https://leetcode.cn/problems/increasing-decreasing-string/
- **来源**：LeetCode 第 21 场双周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、计数

**题意**：给定字符串 $s$，按如下算法重排：先从中选出**最小**的字符接在结果后，再每次选出**比上一个字符大的最小**字符，直到选不出（步骤 1–3，即「严格上升段」）；接着选**最大**的字符，再每次选**比上一个字符小的最大**字符，直到选不出（步骤 4–6，即「严格下降段」）；重复上述过程直到 $s$ 中字符全部用完。同一时刻若最值不唯一可任选其一。返回重排后的结果字符串。

**约束**：

- $1 \le |s| \le 500$
- $s$ 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "aaaabbbbcccc"
输出："abccbaabccba"
解释：第一轮上升段取 "abc"，下降段取 "cba"，得 "abccba"，剩余 "aabbcc"；
      第二轮同样得 "abccba"，拼接为 "abccbaabccba"。
```

**示例 2**

```text
输入：s = "rat"
输出："art"
解释：上升段取 "art"（a → r → t，r 是比 a 大的最小剩余字符，t 是比 r 大的最小剩余字符），
      此时字符已取空，下降段无从取起，算法结束。
```

**示例 3（边界补充）**

```text
输入：s = "a"
输出："a"
解释：只有一个字符，一轮上升段取走 "a" 后即结束。
```

## 3. 解题思路

### 3.1 暴力思路

把 $s$ 放进多重集合（或排序数组），每一步在剩余字符里线性扫描找「比上一个大的最小字符」/「比上一个小的最大字符」。$|s| \le 500$，最坏 $O(|s|^2) = 2.5 \times 10^5$ 次操作也能过，但每步扫描既啰嗦又容易在「严格大于/小于」的边界上写错。签到题的正确姿势是观察到：**每一步根本不需要动态查找——字符集只有 26 个**。

### 3.2 核心观察：桶计数 + 双向扫描

![桶计数：升序取一遍、降序取一遍，循环到取空](images/bw21_q1_bucket_rounds.svg)

关键观察有两条：

1. **「比上一个字符大的最小字符」就是字符集里下一个非空桶**。每轮上升段等价于按 `a → z` 顺序把 26 个桶各取走 1 个（空桶跳过）；下降段同理按 `z → a` 各取 1 个。桶计数把「查找下一个可用字符」变成 $O(26)$ 的线性扫桶。
2. **「不唯一时任选其一」不改变结果**：因为同字符是多重集合里的相同元素，选哪个对结果串无影响（详见 §5 引理 1）。

于是算法退化为：统计 26 个桶的计数，然后循环「升序扫一遍、降序扫一遍」，每桶各扣 1 个，直到所有桶清空。

### 3.3 算法流程

![算法流程：双扫描循环，直到剩余计数归零](images/bw21_q1_flow.svg)

```text
1. 统计 cnt[0..25]，remain = |s|
2. 当 remain > 0：
     2a. i 从 0 到 25（升序）：若 cnt[i] > 0，取走 1 个，追加到 res
     2b. i 从 25 到 0（降序）：若 cnt[i] > 0，取走 1 个，追加到 res
3. 返回 res
```

注意循环条件是 `remain > 0` 而不是固定轮数：单种字符的串（如 `"aaa"`）在一轮上升段就取空，随后的下降段无事可做；$k$ 个字符的最坏情况是 $\lceil \max cnt / 1 \rceil$ 轮。

### 3.4 示例演算

以 $s = $ `"aaaabbbbcccc"` 为例（每个桶计数 4）：

| 轮次 | 升序取 | 降序取 | 拼接结果 | 剩余计数 (a,b,c) |
|------|--------|--------|----------|------------------|
| 1 | a, b, c | c, b, a | abccba | (3, 3, 3) |
| 2 | a, b, c | c, b, a | abccbaabccba | (2, 2, 2) |
| 3 | a, b, c | c, b, a | ···abccba | (1, 1, 1) |
| 4 | a, b, c | c, b, a | ···abccba | (0, 0, 0) |

4 轮后桶全部清空，结果为 `"abccbaabccba"`，与示例一致。

## 4. 算法细节

1. **桶下标即字符序**：`cnt[c - 'a']`，取字符时 `'a' + i` 反解，全程无需哈希函数。
2. **remain 计数器**：单独维护剩余总数，避免每轮结束都扫一遍 26 个桶判断是否清空。也可以省略 remain，直接 `while (res.size() < s.size())`。
3. **提前退出的另一种写法**：若某轮「升序 + 降序」一个字符都没取到（全空桶），说明早已取空——用 remain 计数则天然不会多扫一轮。
4. **单字符集特例**：`"zzz"` 这类串，升序段把 3 个 z 一次取完（每桶取 1 个？不——升序段每桶只取 1 个！）。容易写错的地方：**每轮每桶只取 1 个**，不是把桶倒空。`"zzz"` 需要 3 轮，每轮升序段取 1 个 z。
5. **复杂度与规模无关的地板**：$|s| \le 500$，任何 $O(26 \cdot |s|)$ 的写法都在 1.3 万次操作量级，毫无压力。

## 5. 正确性证明

**引理 1（选择的确定性）**：算法每一步「选最小 / 选比上一个大的最小 / 选最大 / 选比上一个小的最大」在多重集合意义下结果唯一，即题面中「不唯一时任选其一」不影响输出。

**证明**：某步要选字符 $c$ 时，多重集合中所有等于 $c$ 的副本不可区分——它们作为字符值完全相同，从集合中删除任何一个副本后集合的计数向量不变，后续所有选择只依赖计数向量。故任选副本不改变后续过程，输出串逐字符相同。∎

**定理**：设 $T(c)$ 为字符 $c$ 的出现次数。桶计数 + 双向扫描算法的输出与题面算法的输出相同。

**证明**：对题面算法归纳证明每一「轮」（步骤 1–6 的一次执行）恰好从每个非空桶各取 1 个字符，且按「升序段 + 降序段」的顺序取出。上升段（步骤 1–3）中：步骤 1 取当前最小字符 $c_1$，即最小非空桶；步骤 2 要求比上一个字符**大**，由于每个桶至少还剩 0 个、且值等于上一字符的桶被「严格大于」排除，下一个可取的是比 $c_1$ 大的最小非空桶 $c_2 > c_1$；以此类推，上升段从最小非空桶出发、按字符值严格递增地每桶各取 1 个，直到没有更大的非空桶。下降段（步骤 4–6）对称：从最大非空桶出发按值严格递减每桶各取 1 个。而桶计数算法的每轮「升序扫一遍、降序扫一遍」执行的正是同一序列——升序扫描从 $a$ 到 $z$ 访问每个非空桶取 1 个（得到递增序列），降序扫描从 $z$ 到 $a$ 访问每个非空桶取 1 个（得到递减序列）。两者的每轮动作逐字符一致，归纳得全程输出一致。∎

## 6. 复杂度分析

- **时间**：$O(|s| + 26 \cdot R)$，其中 $R$ 为轮数。每轮无论取走多少字符都要扫 26 个桶；最坏 $R = |s|$（单字符集，每轮只取 1 个），故上界 $O(26 |s|)$；由于 $|s| \le 500$，实际至多 1.3 万次桶访问。计数本身 $O(|s|)$。
- **空间**：$O(26)$ 桶计数数组（不计输出串），常数级。输出串 $O(|s|)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string sortString(string s) {
        int cnt[26] = {0};
        for (char c : s) ++cnt[c - 'a'];
        string res;
        res.reserve(s.size());
        int remain = (int)s.size();
        while (remain > 0) {
            for (int i = 0; i < 26; ++i)                 // 升序取
                if (cnt[i] > 0) { res.push_back('a' + i); --cnt[i]; --remain; }
            for (int i = 25; i >= 0; --i)                // 降序取
                if (cnt[i] > 0) { res.push_back('a' + i); --cnt[i]; --remain; }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def sortString(self, s: str) -> str:
        cnt = [0] * 26
        for c in s:
            cnt[ord(c) - 97] += 1
        res = []
        remain = len(s)
        while remain:
            for i in range(26):              # 升序：a → z
                if cnt[i]:
                    res.append(chr(97 + i)); cnt[i] -= 1; remain -= 1
            for i in range(25, -1, -1):      # 降序：z → a
                if cnt[i]:
                    res.append(chr(97 + i)); cnt[i] -= 1; remain -= 1
        return ''.join(res)
```

> 💡 两份代码均通过官方示例（`abccbaabccba`、`art`）与单字符边界（`"a"`、`"zzz"`），并与「按题意逐步模拟」的暴力实现（用 `Counter` 逐步找最值）对拍 2000 组随机串，逐字符一致。

## 8. 边界情况与易错点

1. **每轮每桶只取 1 个**：升序扫描是「对每个非空桶取 1 个」而不是「把桶倒空」。`"zzz"` 的答案是 `"zzz"`（3 轮各取 1 个），若一轮倒空则也得到 `"zzz"`，但 `"aab"` 会暴露错误：正确答案是 `"aba"`（第 1 轮升序取 a、降序取 b，第 2 轮升序取 a），一轮倒空会得到 `"aba"` 之外的错误顺序。
2. **下降段可以整体为空**：最后一轮可能升序段就取空了字符（如剩余 `"ab"`，升序取 a、b 后无字符可降序），下降段零输出，直接进入下一轮判定并退出——不要假设每轮必有下降段。
3. **循环终止条件**：用剩余计数 `remain` 或 `res.size() < s.size()`；不要写「固定 $\lceil |s| / 26 \rceil$ 轮」之类的猜测公式，单字符集需要 $|s|$ 轮。
4. **`reserve` 预分配**（C++）：`res.reserve(s.size())` 避免逐步扩容，非必须但顺手。
5. **别用 `sort` 模拟**：直接对 $s$ 排序再「正取一遍反取一遍」是常见错误写法——它等价于桶计数，但其实不必要（桶计数无需排序），且若把「每桶 1 个」错写成「整段取完」就全错了。
