# LeetCode 灌溉花园的最少水龙头数目 题解

## 1. 题目概述

- **标题 / 题号**：灌溉花园的最少水龙头数目（#1326，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-taps-to-open-to-water-a-garden/
- **来源**：LeetCode 第 172 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、动态规划、区间覆盖

**题意**：花园是 x 轴上从 $0$ 到 $n$ 的一条线段，$n+1$ 个水龙头分别位于整数点 $0,1,\dots,n$。打开点 $i$ 的水龙头，可灌溉连续区间 $[i-\text{ranges}[i],\ i+\text{ranges}[i]]$。求能灌溉整个 $[0,n]$ 的**最少水龙头个数**；若无论打开哪些都盖不满，返回 $-1$。

**约束**：

- $1 \le n \le 10^4$
- `ranges.length == n + 1`
- $0 \le \text{ranges}[i] \le 100$

> 💡 一句话抓住本质：每个水龙头就是一个**区间**，要求用**最少的区间**无缝拼满 $[0,n]$——注意是「拼接覆盖」，不是「选不重叠区间」。抓住这一点，问题立刻退化成跳跃游戏。

## 2. 示例

**示例 1**

```text
输入：n = 5, ranges = [3,4,1,1,0,0]
输出：1
解释：六个水龙头的灌溉区间依次为
      [-3,3]、[-3,5]、[1,3]、[2,4]、[4,4]、[5,5]
      只开点 1 的水龙头（区间 [-3,5]）就盖住了整个 [0,5]。
```

**示例 2**

```text
输入：n = 3, ranges = [0,0,0,0]
输出：-1
解释：每个水龙头只能灌溉自己所在的那一个点，点与点之间全是空洞，
      开动全部水龙头仍无法覆盖 [0,3]。
```

**示例 3（补充，用于演算走查）**

```text
输入：n = 5, ranges = [1,2,1,0,2,1]
输出：2
解释：开点 1 的水龙头盖 [0,3]，再开点 4 的水龙头盖 [2,5]，
      两段拼接恰好覆盖 [0,5]，且 1 个水龙头盖不满，故答案为 2。
```

## 3. 解题思路

### 3.1 暴力思路

- **枚举子集**：水龙头有 $n+1$ 个，判每个子集能否覆盖是 $O(n)$，总计 $O(2^n n)$，$n=10^4$ 时不可行。
- **区间 DP**：设 $dp[j]$ 为把 $[0,j]$ 整段盖住的最少水龙头数。一步之内能把覆盖边界从 $l_i$ 推到 $r_i$ 的水龙头才可用，于是 $dp[j]=\min\{\,dp[l_i]+1 : r_i\ge j\,\}$。状态 $O(n)$、每个状态枚举 $O(n)$ 个水龙头，总 $O(n^2)=10^8$，$n=10^4$ 时勉强能过但毫无必要——它完全没用上「$l_i$ 必是 $0\dots n$ 内的整数、可以直接当桶下标」这一强结构。
- **按右端点排序的「活动选择」贪心**：那是「选最多不重叠区间」的范式，本题要求**拼接**，会直接失效——比如示例 3 里两个最优区间 $[0,3]$ 与 $[2,5]$ 是重叠的。

> ⚠️ 覆盖型与活动选择型是两种完全不同的贪心，混用是本题最常见的跑偏方向。

### 3.2 核心观察：区间覆盖 → reach[] 跳跃数组

![水龙头区间 → reach[] 跳跃数组](images/wc172_q4_tap_to_interval.svg)

把每个水龙头写成区间后，先做两件事：

1. **裁剪**：$l_i=\max(0,\,i-\text{ranges}[i])$，$r_i=\min(n,\,i+\text{ranges}[i])$。花园外的部分对覆盖 $[0,n]$ 毫无贡献，裁掉后所有左端点都落在 $[0,n]$ 内，才有资格当数组下标。
2. **支配消除**：同一左端点只保留 $r$ 最大的那个——若 $l_a=l_b$ 且 $r_a\ge r_b$，任何用到 $b$ 的方案把 $b$ 换成 $a$ 都不会变差。

于是得到长度为 $n+1$ 的数组

$$\text{reach}[l]=\max\{\,r_i : l_i=l\,\}$$

含义变得非常直白：**站在位置 $l$，可以一步跳到 $\text{reach}[l]$**。问题随之变成——从 $0$ 出发，最少跳几步能到 $\ge n$？这就是 [45. 跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/) 的模板。

> 💡 关键收益：$l_i$ 全是 $0\dots n$ 的整数，可以**直接当桶用**，连排序都省了，复杂度从 $O(n\log n)$ 降成 $O(n)$。

### 3.3 算法流程：按层扩张的贪心

![贪心按层扩张](images/wc172_q4_greedy_layers.svg)

维护三个量：

- `end`：当前这一步能**连续覆盖**到的右边界（已确认无空洞）；
- `far`：扫描 $[0,\text{end}]$ 期间见到的最大 `reach[i]`，即下一层能推到的最远点；
- `steps`：已打开的水龙头个数。

流程：

1. 预处理 `reach[]`；
2. `i` 从 $0$ 扫到 $n-1$，`far = max(far, reach[i])`；
3. 当 `i == end`，说明这一层所有落脚点都已展开完：
   - 若 `far <= end`，再往后没有任何水龙头能跨过 `end`，返回 $-1$；
   - 否则 `steps++`、`end = far`（进入下一层），若 `end >= n` 立即返回 `steps`。

> 💡 这与 BFS 完全同构：`end` 是当前队列的右边界，`far` 是下一层的右边界，「层数」就是最少水龙头数。区别只在于本层的位置是一条连续的线段，不需要逐个入队。

### 3.4 示例演算

![示例 3 演算表](images/wc172_q4_walkthrough.svg)

以示例 3（`n=5, ranges=[1,2,1,0,2,1]`）为例：区间依次为 $[0,1],[0,3],[1,3],[3,3],[2,5],[4,5]$，预处理得 `reach = [3,3,5,3,5,5]`。

| `i` | `reach[i]` | `far` | `i == end` | 动作 |
|-----|-----------|-------|------------|------|
| 0 | 3 | 3 | 是（$0=0$） | `steps=1`，`end=3` |
| 1 | 3 | 3 | 否 | 继续扫描 |
| 2 | 5 | 5 | 否 | `far` 扩到 5 |
| 3 | 3 | 5 | 是（$3=3$） | `steps=2`，`end=5 ≥ n` → 返回 2 |
| 4 | 5 | — | — | 已返回，不再扫描 |

对照：若贪心地「先选最左」拿了 $[0,1]$，后面只能走 $1\to3\to5$，需要 3 个水龙头。**先把这一层扫完再跳**，正是贪心不劣于最优的关键。

## 4. 算法细节

1. **裁剪必须做**：$\text{ranges}[i]\le 100$ 而 $n$ 可以更大，$i+\text{ranges}[i]$ 可能超过 $n$，不裁剪会让 `reach` 越界，或让答案误以为还需要往后铺。
2. **支配消除不用排序**：左端点是 $0\dots n$ 的整数，`reach[max(0, i-r)] = max(·, min(n, i+r))` 一次遍历即完成，天然 $O(n)$。
3. **`far` 是累积量**：它是在扫描 $[0,\text{end}]$ 的整个过程中取最大值，而不是只看 `reach[end]`——只盯 `reach[end]` 会漏掉「从中间某个点起跳更远」的情况（示例 3 的答案正来自 `reach[2]=5`）。
4. **结算时机是 `i == end`**：此时本层所有起跳点都已被考察，可以安全地一次性把 `end` 推到 `far`；提前跳会丢失选择权。
5. **卡死判定用 `far <= end`**：`far == end` 说明这一层里没有任何水龙头能跨过 `end`，属于「没有严格推进」，同样判 $-1$。
6. **循环只到 `i = n-1`**：位置 $n$ 是终点，一旦 `end >= n` 就返回；`reach[n]` 只可能来自点 $n$ 且 $r=0$ 的单点区间，对连续覆盖没有贡献，无需扫描。
7. **`end >= n` 必须就地返回**：漏掉这行会出事——`end` 变成 $n$ 后 `i` 最大只到 $n-1$，`i == end` 永不成立，循环结束时若统一返回 $-1$ 就会把正确答案吞掉。

## 5. 正确性证明

先给出贪心的形式化描述。令 $\mathcal{I}=\{(l_i,r_i)\}$ 为裁剪后的区间集合，定义

$$F(c)=\max\{\,r_i : l_i\le c\,\}\qquad (\text{空集时取 } -\infty)$$

贪心即 $c_0=0$，$c_k=F(c_{k-1})$，只当 $c_k>c_{k-1}$ 时才计一个水龙头。

**引理 1（裁剪不改变最优值）**：对任意水龙头子集 $S$，$\bigcup_{i\in S}[l_i,r_i]\supseteq[0,n]\iff \bigcup_{i\in S}[i-\text{ranges}[i],\,i+\text{ranges}[i]]\supseteq[0,n]$。

**证明**：裁剪只是把每个区间与 $[0,n]$ 求交，即 $[l_i,r_i]=[i-r_i,i+r_i]\cap[0,n]$。并对每个区间求交后，并集与 $[0,n]$ 的交不变：$\bigl(\bigcup A_i\bigr)\cap[0,n]=\bigcup(A_i\cap[0,n])$。故两者覆盖 $[0,n]$ 的判定完全等价，最优子集亦相同。∎

**引理 2（支配消除）**：若 $l_a=l_b$ 且 $r_a\ge r_b$，则对任意可行子集 $S$ 含 $b$，$S'=(S\setminus\{b\})\cup\{a\}$ 仍可行且 $|S'|\le|S|$。

**证明**：$[l_a,r_a]\supseteq[l_b,r_b]$，用更大的区间替换不会减少并集，故仍覆盖 $[0,n]$；元素个数不变。由此每个左端点上只需保留 $r$ 最大者，`reach[]` 与原集合覆盖能力相同。∎

**引理 3（层不变式）**：把「$k$ 链」定义为 $k$ 个区间的一个排列 $i_1,\dots,i_k$，满足 $l_{i_1}\le 0$ 且 $l_{i_t}\le \max(r_{i_1},\dots,r_{i_{t-1}})$（即并集从 $0$ 起连续、无空洞），记其触达的右端点为 $d_k=\max(r_{i_1},\dots,r_{i_k})$，记 $R_k$ 为所有 $k$ 链的 $d_k$ 最大值（$R_0=0$）。则对一切 $k\ge 0$ 有 $c_k=R_k$，其中卡死时约定 $c_{k+1}=c_k$。

**证明**：对 $k$ 归纳，$k=0$ 时 $R_0=c_0=0$ 显然。

设 $R_k=c_k$。任取一条 $(k+1)$ 链，其前 $k$ 个区间构成 $k$ 链，故 $d_k\le R_k=c_k$；而第 $k+1$ 个区间满足 $l_{i_{k+1}}\le d_k\le c_k$，于是 $r_{i_{k+1}}\le F(c_k)=c_{k+1}$，从而 $d_{k+1}=\max(d_k,r_{i_{k+1}})\le c_{k+1}$，即 $R_{k+1}\le c_{k+1}$。

反过来，若贪心未卡死，则 $F(c_k)=c_{k+1}>c_k$，说明存在 $l\le c_k$、$r=c_{k+1}$ 的区间；由归纳假设存在 $k$ 链触达 $c_k$，在其后接上该区间（$l\le c_k$ 满足链的条件）即得触达 $c_{k+1}$ 的 $(k+1)$ 链，故 $R_{k+1}\ge c_{k+1}$，夹逼得 $c_{k+1}=R_{k+1}$。若贪心卡死（$F(c_k)=c_k$，约定 $c_{k+1}=c_k$），则最优 $k$ 链后接任意一个满足 $l\le c_k$ 的区间仍是 $(k+1)$ 链，故 $R_{k+1}\ge R_k=c_k$，与上界 $R_{k+1}\le c_k$ 夹逼得 $R_{k+1}=c_k=c_{k+1}$。∎

**定理**：算法返回的是最少水龙头数；花园不可覆盖时返回 $-1$。

**证明**：$c_k$ 单调不减，且只要还有推进就严格增大，取值始终是 $[0,n]$ 内的整数，故至多 $n$ 步就会到达 $n$ 或卡死，算法必然终止。

设存在覆盖 $[0,n]$ 的方案 $S$，把 $S$ 按左端点升序排列。排序后每个区间的左端点都不晚于此前并集的右端点——否则中间会留下空洞，与「覆盖 $[0,n]$」矛盾——故 $S$ 构成一条 $|S|$ 链，其触达 $d_{|S|}\ge n$（覆盖含端点 $n$，而 $r\le n$，故恰为 $n$）。由引理 3 得 $c_{|S|}\ge n$，即贪心的步数不超过 $|S|$，于是贪心步数 $\le m^*=\min|S|$。

另一方面，贪心每推进一层都对应一个**真实存在**的区间（$F$ 的定义即取某个 $r_i$），这些区间按推进顺序排列满足链的条件、并触达 $n$，因此是一个规模等于贪心步数的合法方案，故 $m^*\le$ 贪心步数。双向夹逼得贪心步数 $=m^*$，即最少水龙头数。

若贪心在 $c_k<n$ 处卡死，则由引理 3，任何 $k'\ge k$ 的链触达 $R_{k'}=c_k<n$；$k'<k$ 时 $R_{k'}=c_{k'}\le c_k<n$。也就是任意规模的水龙头集合都无法覆盖到 $n$，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。预处理遍历 $n+1$ 个水龙头做两次 $\max/\min$ 与一次 `reach` 更新，$O(n)$；贪心扫描 `i = 0 … n-1`，每个位置 $O(1)$，共 $O(n)$。没有排序、没有二重循环。
- **空间**：$O(n)$，仅一个长度 $n+1$ 的 `reach` 数组（若允许改写输入，可原地复用 `ranges`，但会破坏入参，不推荐）。返回值与过程中只用到 $O(1)$ 个额外变量。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minTaps(int n, vector<int>& ranges) {
        // ① 预处理：区间裁剪 + 同一左端点留最远
        vector<int> reach(n + 1, 0);
        for (int i = 0; i <= n; ++i) {
            int left  = max(0, i - ranges[i]);
            int right = min(n, i + ranges[i]);
            reach[left] = max(reach[left], right);
        }

        // ② 按层贪心：end 为当前边界，far 为下一层边界
        int steps = 0, end = 0, far = 0;
        for (int i = 0; i < n; ++i) {
            far = max(far, reach[i]);
            if (i == end) {                 // 本层展开完毕，结算
                if (far <= end) return -1;  // 无法继续向右推进
                ++steps;
                end = far;
                if (end >= n) return steps; // 已覆盖 [0, n]
            }
        }
        return -1;                          // 防御性兜底
    }
};
```

### Python

```python
class Solution:
    def minTaps(self, n: int, ranges: list[int]) -> int:
        # ① 预处理：区间裁剪 + 同一左端点留最远
        reach = [0] * (n + 1)
        for i, r in enumerate(ranges):
            left, right = max(0, i - r), min(n, i + r)
            if right > reach[left]:
                reach[left] = right

        # ② 按层贪心：end 为当前边界，far 为下一层边界
        steps = end = far = 0
        for i in range(n):
            far = max(far, reach[i])
            if i == end:                    # 本层展开完毕，结算
                if far <= end:              # 无法继续向右推进
                    return -1
                steps += 1
                end = far
                if end >= n:                # 已覆盖 [0, n]
                    return steps
        return -1                            # 防御性兜底
```

## 8. 边界情况与易错点

1. **示例 2 型全零输入**：`ranges` 全为 $0$ 时 `reach[i] = i`，第一次 `i == end == 0` 就发现 `far <= end`，立即返回 $-1$，不会死循环。
2. **$n=1$ 的「假覆盖」**：`n=1, ranges=[0,0]` 时点 $0$、$1$ 各自被自己的水龙头「覆盖」，但开区间 $(0,1)$ 是空的，答案应为 $-1$。**不能**把题目理解成「每个整数点都要被覆盖」。
3. **半径大于花园长度**：`ranges[i]` 最大 100，而 $n$ 可能更小，如 `n=1, ranges=[0,1]`（点 1 覆盖 $[0,2]$）。不写 `min(n, i+r)` 会让 `reach` 下标或答案越界。
4. **`far <= end` 的等号**：`far == end` 说明本层内无人能越过 `end`，属于卡死。写成 `far < end` 虽然最终结果仍是 $-1$（`end` 原地不动，`i` 一路越过它，循环结束时返回 $-1$），但会凭空多记一个 `steps`，也不利于读代码的人理解「没有严格推进」这一语义，建议直接用 `<=` 当场判死。
5. **漏掉 `end >= n` 的提前返回**：`end` 变成 $n$ 后 `i` 最多走到 $n-1$，`i == end` 永不再成立，若循环末尾统一返回 $-1$，正确答案会被吞掉（示例 1 就是这种情形）。
6. **误用「选不重叠区间」的排序贪心**：按右端点排序后贪心选不重叠，会拒绝 $[0,3]$ 与 $[2,5]$ 这类必须重叠拼接的组合，示例 3 会得 $-1$ 或更大值。
7. **`reach` 的 `n` 号位置**：只有点 $n$ 且 `ranges[n]=0` 才会写入 `reach[n]`，它是单点区间，对连续覆盖毫无贡献；漏扫它不影响正确性，把循环写成 `i <= n` 也只是多一次无用的 $\max$。

**延伸思考**：若每个水龙头有开启代价 $c_i$，要求总代价最小，则「层数最少」的贪心失效——同一层内应该留代价最小的组合，此时退化为加权区间覆盖，需要 $$dp[j]=\min\{\,dp[l_i]+c_i : r_i\ge j\,\}$$（按右端点排序后，用线段树做「区间取 $\min$」可优化到 $O(n\log n)$）。若还要求输出具体方案，只需在 `far` 被更新时同步记下取得最大值的那个 `i`，沿 `end` 回溯即可；若把花园换成二维矩形、水龙头换成矩形覆盖，问题即变为 NP-hard，只能近似或指数搜索。
