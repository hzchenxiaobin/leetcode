# LeetCode 6 和 9 组成的最大数字 题解

## 1. 题目概述

- **标题 / 题号**：6 和 9 组成的最大数字（#1323，easy）
- **链接**：https://leetcode.cn/problems/maximum-69-number/
- **来源**：LeetCode 第 172 场周赛 Q1
- **难度**：简单
- **标签**：贪心，数学

**题意**：给出一个只由数字 6 和 9 组成的正整数 `num`，最多允许翻转一位数字（把 6 变成 9，或把 9 变成 6），求翻转后能得到的最大数字。

**约束**：

- $1 \le num \le 10^4$
- `num` 的每一位都是 6 或 9

> 💡 关键词是**「最多」**：它不是「必须改一位」，而是「允许改 0 位或 1 位」。所以像 `9999` 这种全是 9 的输入，答案就是原数本身。

## 2. 示例

**示例 1**

```text
输入：num = 9669
输出：9969
解释：
  改第 1 位（最高位）：6669
  改第 2 位：9969
  改第 3 位：9699
  改第 4 位：9666
其中最大的数字是 9969。
```

**示例 2**

```text
输入：num = 9996
输出：9999
解释：把最后一位的 6 变成 9，得到 9999，这是最大的数。
```

**示例 3**

```text
输入：num = 9999
输出：9999
解释：已经全是 9，任何改动都会让数字变小，因此一次都不改。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**枚举每一位**：对每个位置尝试翻转，把得到的数字和原数一起取最大值。位数最多 4 位（因为 `num <= 10^4` 且只含 6/9），候选只有 5 个，常数极小，提交也一定通过。

但暴力有两处浪费，而且**无法推广**到位数更大（比如以字符串形式给出 $10^5$ 位）的版本：

- **9 → 6 永远不划算**：把某一位的 9 改成 6，等于在这一位的位权上减去 3，数值必然变小，枚举它没有意义；
- **6 → 9 的收益由位权决定**：每位收益是一个固定的 $3 \times 10^k$，高位收益大、低位收益小，只要挑收益最大（即最靠左）的那个 6 即可，不必逐个比较候选数。

换句话说，暴力在 $n$ 位时要做 $O(n)$ 次「构造数 + 比较数」，每次 $O(n)$，合计 $O(n^2)$；而「挑收益最大的那一项」只需要扫描一遍，$O(n)$。

### 3.2 核心观察：只改「最左边的 6」

![最左边的 6 收益最大](images/wc172_q1_leftmost_six_rule.svg)

设 `num` 有 $n$ 位，从左往右编号 $i = 0, 1, \dots, n-1$，第 $i$ 位的位权是

$$w_i = 10^{\,n-1-i}$$

对第 $i$ 位做一次翻转，新数与旧数之差恒为 $\pm 3 w_i$：

$$
\text{翻转后} =
\begin{cases}
num + 3 w_i, & s_i = 6 \ (\text{6 变 9，收益为正}) \\
num - 3 w_i, & s_i = 9 \ (\text{收益负})
\end{cases}
$$

从这个式子直接读出三条结论：

1. **9 → 6 一律不做**：收益 $-3w_i$ 严格为负，而不做任何改动的收益是 $0$，所以「不改」严格优于任何「9 → 6」；
2. **6 → 9 要做，且最多做一次**：题目只允许改一位，所以只需在所有正收益里挑最大的那一次；
3. **收益最大 = 位权最大 = 最靠左**：因为 $w_0 > w_1 > \dots > w_{n-1}$，所以只需挑**最左边（最高位）的那个 6**。

于是答案有闭式：

$$\text{answer} = num + 3 \times 10^{\,n-1-i^{*}}, \quad i^{*} = \text{最小的满足 } s_{i}=6 \text{ 的下标}$$

若不存在这样的 $i^{*}$（即全部是 9），答案就是 $num$ 本身。

### 3.3 算法流程

![扫描找最左边的 6](images/wc172_q1_scan_flow.svg)

1. 把 `num` 转成字符串 `s`（或按位取模收集各位），得到位数 $n = \lvert s \rvert$；
2. 从左往右扫描，找到**第一个**字符 `'6'` 的下标 $i$；
3. 若不存在（等价于 `s.find('6') == -1`），说明全部是 9，直接返回 `num`；
4. 否则返回 $num + 3 \times 10^{\,n-1-i}$。

整个过程只有一次线性扫描加一次幂运算，没有回溯，也没有候选比较。

### 3.4 示例演算

![三组官方示例走查](images/wc172_q1_walkthrough.svg)

以 `num = 9669` 为例，$n = 4$，第一个 6 出现在下标 $i = 1$：

$$k = n - 1 - i = 4 - 1 - 1 = 2, \qquad \text{answer} = 9669 + 3 \times 10^{2} = 9669 + 300 = 9969$$

再逐位对比四张「只改一位」的答卷：

| 改动位置 | 位权 $w_i$ | 增量 | 结果 |
|----------|------------|------|------|
| 第 0 位（9 → 6） | 1000 | $-3000$ | 6669 |
| 第 1 位（6 → 9） | 100 | $+300$ | **9969** |
| 第 2 位（6 → 9） | 10 | $+30$ | 9699 |
| 第 3 位（9 → 6） | 1 | $-3$ | 9666 |

只有「改第 1 位」和「改第 2 位」是正收益，其中第 1 位收益更大，与「取最左边的 6」完全一致。

## 4. 算法细节

1. **位数 $n$ 必须由实际位数决定**，不能硬编码成 4。`num = 6` 时 $n = 1$、$k = 0$，答案是 $6 + 3 = 9$；若误用 $n = 4$ 就会算出 $6 + 3000 = 3006$，直接错。
2. **用加法而不是字符串替换**：`num + 3 * 10^k` 一步到位，避免「逐字符改 + 转回整数」的双重转换；Python 的 `int` 与 C++ 的 `int` 在本题范围内都不会溢出。
3. **C++ 求 $10^k$ 用整数循环**：`pow(10, k)` 返回 `double`，虽然本题 $k \le 3$ 不会出现精度问题，但用 `for` 累乘或预置 `{1,10,100,1000}` 更稳妥，也避免引入 `<cmath>`。
4. **`find('6')` 的返回值要判 `-1`**：这是唯一的失败分支，漏判会导致 `10 ** (n-1-(-1))` 这类越界 `k`，答案变成 $num + 3 \times 10^{n}$（多进一位，错得很隐蔽）。
5. **不要把「最多一位」写成「恰好一位」**：全 9 时如果强行翻转，只能把某个 9 变成 6，答案从 9999 掉到 6999 之类，这是本题最常见的 WA。
6. **不要贪心地把所有 6 都改成 9**：题目只允许改一位。`9966` 全改虽然能到 9999，但按规则只有两个正收益候选——改第一个 6 得 9996、改第二个 6 得 9969，取前者。这就是「只动一位，且动最左的 6」的直接体现。
7. **纯算术写法（空间 $O(1)$）**：先求出最高位的位权 $p = 10^{\,n-1}$，然后从左往右逐位判断，判断时把 $p$ 逐位除以 10 向下移动；遇到第一个 6 就把 $3p$ 加到 $num$ 上返回。字符串写法更短，算术写法不依赖字符集，二者等价。

## 5. 正确性证明

**引理 1（高位主导）**：设 $A, B$ 是两个 $n$ 位、每位均属于 $\{6, 9\}$ 的整数。若它们从最高位起**第一次不同**的位置是 $p$，且 $A_p = 9, B_p = 6$，则 $A > B$。

**证明**：记 $m = n-1-p \ge 0$ 为 $p$ 之后剩余的位置数。有

$$A - B = 3 \cdot 10^{m} + \sum_{i=p+1}^{n-1} (A_i - B_i)\, 10^{\,n-1-i}$$

每一位差值 $A_i - B_i \in \{-3, 0, 3\}$，故

$$A - B \ge 3 \cdot 10^{m} - 3\sum_{j=0}^{m-1} 10^{j} = 3\cdot 10^{m} - 3\cdot\frac{10^{m}-1}{9} = \frac{8 \cdot 10^{m} + 1}{3} > 0$$

即 $A > B$。∎

**引理 2（9 → 6 必劣）**：对任意把某位 9 改成 6 的候选 $C$，都有 $C < num$。

**证明**：设改动位置为 $i$，则 $C = num - 3w_i$，而 $w_i > 0$，故 $C < num$。∎

**引理 3（最左的 6 最优）**：设下标 $i < j$ 两位都是 6，$A_i = num + 3w_i$，$A_j = num + 3w_j$，则 $A_i > A_j$。

**证明**：由 $i < j$ 得 $n-1-i > n-1-j$，即 $w_i > w_j$，于是

$$A_i - A_j = 3(w_i - w_j) > 0$$

∎

**定理**：算法返回的数是「最多翻转一位」所能得到的最大数字。

**证明**：把全部合法操作（改 0 位、改某位 6、改某位 9）的候选集合记为 $\mathcal{C}$。

- 由引理 2，所有「9 → 6」候选都严格小于 $num$，故它们不可能成为最大值；
- 由引理 3，所有「6 → 9」候选中最大的是改动**最左边那个 6** 得到的数，记为 $A^{*}$；若没有 6，则集合中只有 $num$（以及更小的候选），最大值为 $num$；
- 算法：有 6 时返回 $A^{*}$，无 6 时返回 $num$，恰好是上述最大值。

故算法输出 $\max \mathcal{C}$，即题目所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$，$n$ 为位数（本题 $n \le 4$）。转字符串 / 取各位 $O(n)$，从左到右找第一个 6 是 $O(n)$，求 $10^k$ 是 $O(n)$（也可用查表降为 $O(1)$），总计一次线性扫描。
- **空间**：字符串写法 $O(n)$（存放 $n$ 个字符）；纯算术写法只用一个位权变量，$O(1)$。本题 $n \le 4$，两者没有实际差别。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    int maximum69Number(int num) {
        string s = to_string(num);
        int n = (int)s.size();
        for (int i = 0; i < n; ++i) {
            if (s[i] == '6') {                  // 最左边的 6
                int p = 1;                      // p = 10^(n-1-i)
                for (int k = 0; k < n - 1 - i; ++k) p *= 10;
                return num + 3 * p;             // 直接做加法，避免字符串回填
            }
        }
        return num;                             // 全是 9，一次都不改
    }
};
```

### Python

```python
class Solution:
    def maximum69Number(self, num: int) -> int:
        s = str(num)
        i = s.find('6')                 # 最左边 6 的下标，找不到返回 -1
        if i == -1:
            return num                  # 全是 9，不改动
        return num + 3 * 10 ** (len(s) - 1 - i)
```

## 8. 边界情况与易错点

1. **全是 9**：`9999` 的 `find('6')` 返回 $-1$，必须原样返回；若强行翻转得到的是 6999 / 9699 之类，答案偏小。
2. **单位数**：`num = 6` 时 $n = 1, k = 0$，返回 9；`num = 9` 时返回 9。位数硬编码成 4 会在这里出错。
3. **6 在最后一位**：`9996` 的收益只有 $+3$，但依然是唯一的正收益，答案 9999；不要因为「收益小」就跳过。
4. **`find` 的 `-1` 没有判**：会算出 $k = n$，相当于多乘一个 10，把结果放大到错误的量级。
5. **把「最多一位」误解为「恰好一位」**：见第 1 条，这是本题最典型的错误来源。
6. **一次改多位**：`9966` 只允许改一位，答案是 9996（改第一个 6）而非 9999；「全部 6 变 9」属于另一道题。
7. **浮点幂**：本题 $k \le 3$ 时 `pow(10, k)` 尚可靠，但工程写法应使用整数幂，避免「答案差 1」这类难以复现的 WA。

**延伸思考**：

- 若允许改**恰好 $k$ 位**，最优策略仍是「把最左边的 $k$ 个 6 全改成 9」（若 6 不足 $k$ 个，再改最右边的若干个 9，因为损失的位权最小）。本题就是 $k = 1$ 且允许不改的特例。
- 若要求**最小**数字，结论对称：改最左边的 9 为 6；没有 9 则不动。
- 若允许**任意次**互换 6 与 9，数字的多重集合不变，答案只能是「把 9 全排到高位、6 全排到低位」，与贪心选位无关，说明「只能改一位」这个限制是本题贪心成立的关键。
