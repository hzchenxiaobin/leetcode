# LeetCode 删除给定值的叶子节点 题解

## 1. 题目概述

- **标题 / 题号**：删除给定值的叶子节点（#1325，medium）
- **链接**：https://leetcode.cn/problems/delete-leaves-with-a-given-value/
- **来源**：LeetCode 第 172 场周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、二叉树

**题意**：给定二叉树根 `root` 与整数 `target`，反复删除**值为 `target` 的叶子节点**。删掉一层叶子后，原本不是叶子的父节点可能退化成叶子；若它此时的值也是 `target`，就要继续删除。重复到不能再删为止，返回最终的树根（整棵树可能被删空）。

**约束**：

- 树中节点数 $n \in [1, 3000]$
- $1 \le \text{Node.val},\ \text{target} \le 1000$

$n$ 只有 $3000$，这暗示 $O(n \log n)$ 甚至 $O(n \cdot h)$ 的做法都能过，但本题的正解是**一趟后序遍历**：把「反复删除」直接摊平成一次自底向上的归约，复杂度 $O(n)$。

## 2. 示例

**示例 1**

```text
输入：root = [1,2,3,2,null,2,4], target = 2
输出：[1,null,3,null,4]
解释：第 1 轮删掉两个值为 2 的叶子（左子树下的 2、右子树 3 的左孩子 2）；
      第 2 轮左侧的 2 变成叶子，值仍是 2，再删掉；
      此时 1 的右子树还剩 3 -> 4，3 因为有右孩子 4 而保留。
```

**示例 2**

```text
输入：root = [1,3,3,3,2], target = 3
输出：[1,3,null,null,2]
解释：叶子 3（1 的右孩子）与叶子 3（左侧 3 的左孩子）先被删；
      左侧的 3 还有右孩子 2，不是叶子，故保留，2 的值不是 target 也保留。
```

**示例 3**

```text
输入：root = [1,2,null,2,null,2], target = 2
输出：[1]
解释：这是一条 1 -> 2 -> 2 -> 2 的左链，每轮从链尾删一个 2，三轮删到只剩根 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**照着题面模拟**：每轮遍历整棵树，收集所有「左右孩子都为空且值等于 `target`」的节点，把它们删掉，再进入下一轮，直到某一轮一个都没删。

这个做法**在本题数据下能过**（每轮 $O(n)$，最多 $h$ 轮，$h \le 3000$，总共不超过 $9 \times 10^6$ 次操作），但它有两个毛病：

1. **复杂度依赖树高**。轮数等于「最长可删链」的长度，链形树上 $h = n$，退化为 $O(n^2)$；把 $n$ 换成 $10^5$ 就直接超时。
2. **实现上极易写错**。若在同一轮里边遍历边删，删掉一个节点会立刻让它的父节点变成叶子，而父节点是否该删又取决于「兄弟子树本轮是否也被删」。想「本轮只删原本就是叶子的节点」就必须先收集再统一删除，代码里到处是「一轮」的边界，稍不留神就漏删或多删。

真正的浪费在于：**每一轮我们都在重复检查整棵树，而一棵子树的删除状态一旦确定就再也不会改变**。只要把检查顺序改成「先孩子、后自己」，所有轮次就能合并成一次遍历。

### 3.2 核心观察：删除只沿父边向上传播，后序一趟即达不动点

![后序归约：子树定型后才判断父节点是否成了叶子](images/wc172_q3_postorder_reduction.svg)

关键观察有三条，依次收紧。

**观察 ①（删除只影响父亲）**：一个节点被删，唯一的结构性后果是「它的父亲少了一个孩子」。兄弟子树、祖先的其它分支完全不受影响。

**观察 ②（删除条件的结构刻画）**：一个节点被删，当且仅当它的整棵子树被删空、且它自己的值等于 `target`。要让它变成叶子，两个孩子的子树必须先被删空；而它值不等于 `target` 时，就算成了叶子也不会被删（题面只删值为 `target` 的叶子）。于是可以定义一个纯结构的判定函数

$$D(\text{null}) = \text{true}, \qquad D(v) = \bigl(v.\text{val} = \text{target}\bigr) \wedge D(v.\text{left}) \wedge D(v.\text{right})$$

**观察 ③（终态唯一）**：「谁被删」与删除先后无关——$D$ 只依赖原始树的结构与值，不依赖任何顺序；而保留下来的节点之间的父子关系也没有变化（删掉的边都是指向被删子树的那一条）。所以最终形态**唯一**，就是 $D$ 定义的那个归约结果 $f$：

$$f(\text{null}) = \text{null}, \qquad f(v) = \begin{cases} \text{null}, & D(v) = \text{true} \\ v\ \text{带着孩子}\ f(v.\text{left}),\ f(v.\text{right}), & D(v) = \text{false} \end{cases}$$

有了这个刻画，问题就从「反复迭代到不动点」变成「按 $f$ 自底向上算一遍」。$f(v)$ 依赖两个孩子的结果，正是一个标准的**后序（先左右、后自己）**结构：递归返回时，孩子子树的终态已经算好，此时才知道自己是不是叶子。

> 💡 一句话总结：**「变成叶子」这件事只能由孩子告诉父亲，所以必须后序**。先序遍历时你看到的是「当前」状态，无法预知孩子等下会不会被删光。

### 3.3 算法流程

![后序 DFS：先归约左右子树，再判断自己是否成了叶子](images/wc172_q3_dfs_flow.svg)

```text
dfs(node):
    if node == null: return null          # 空子树恒为「已删空」
    node.left  = dfs(node.left)           # 先把左子树归约好
    node.right = dfs(node.right)          # 再把右子树归约好
    if node.left == null and node.right == null and node.val == target:
        return null                       # 自己成了值为 target 的叶子 -> 删除
    return node                           # 否则保留（哪怕值等于 target，只要还有孩子）
```

整个递归维护一条不变式：**`dfs(v)` 返回的是「$v$ 这棵子树反复删除到不动点之后」的根**；返回 `null` 当且仅当整棵子树被删空。第 5 节用它来证明正确性。

三种返回情形值得单独记住：空节点返回 `null`（递归出口）；左右都空且值等于 `target` 返回 `null`（等价于「再删一轮」）；其余一律返回 `node`（含「是叶子但值不是 `target`」）。

### 3.4 示例演算

![示例 1 的三阶段走查](images/wc172_q3_walkthrough.svg)

以示例 1（`root = [1,2,3,2,null,2,4]`，`target = 2`）为例，后序访问顺序与每步的返回值如下（「左/右」写的是**归约后**的孩子）：

| 访问次序 | 节点 | 归约后的左 / 右 | 返回值 | 说明 |
|---------|------|----------------|--------|------|
| 1 | 2（最深，左子树） | null / null | `null` | 是叶子且值为 2，删 |
| 2 | 2（1 的左孩子） | null / null | `null` | 孩子已被删空，自己成了叶子，继续删 |
| 3 | 4 | null / null | `4` | 是叶子但值不是 2，保留 |
| 4 | 2（3 的左孩子） | null / null | `null` | 是叶子且值为 2，删 |
| 5 | 3 | null / 4 | `3` | 右孩子 4 非空，自己不是叶子，保留 |
| 6 | 1 | null / 3 | `1` | 右孩子 3 非空，保留 |

最终返回 `1`，结构为 `[1,null,3,null,4]`，与题面完全一致。注意第 2 行就是题面说的「删除后父节点变成叶子、再删一次」——在后序里它只是**同一次遍历中的下一步**，不需要额外一轮。

示例 3（`root = [1,2,null,2,null,2]`）更能说明问题：这条左链上有 3 个 2。后序会从链尾开始，依次返回 `null`、`null`、`null`，最后 1 的孩子为空但 `1 != 2`，返回 `1`，结果 `[1]`——本该三轮的删除被压成了一条自底向上的返回链。

## 4. 算法细节

1. **必须用后序位置判断**。判断「自己是否成了叶子」需要孩子子树的最终状态，所以两行 `dfs` 递归**必须写在判断之前**。写成先序（先判断再递归）会漏删所有「孩子被删后才变成叶子」的父节点，示例 1 会错误地返回 `[1,2,3,null,null,null,4]`。
2. **一定要把返回值接回指针，并原地修改**。C++ 里写成 `dfs(root->left, target);`（不接收返回值）等于什么都没删；正确写法是 `root->left = removeLeafNodes(root->left, target);`。返回的 `node` 就是原节点，只改写左右指针，不要为「纯函数」而复制整棵树。
3. **递归出口写 `null` 判断，不要写「是叶子就返回」**。把叶子判断提前会让「非 target 的叶子」也走特殊分支，逻辑变复杂且容易漏掉 `target` 比较。
4. **根也可能被删空**。返回值直接就是答案，不要假设 `root` 一定非空；LeetCode 用 `[]` 表示空树，正好对应返回 `nullptr` / `None`。
5. **Python 要放开递归深度**。$n = 3000$ 的链形树深度就是 $3000$，超过默认上限 $1000$，不加 `sys.setrecursionlimit` 会直接 `RecursionError`；C++ 的递归栈按每帧几十字节算，3000 层无压力。
6. **需要绝对稳妥时用显式栈**。手写后序（压栈时用「访问标记」或把节点压两次）可以把递归栈换成堆上的 `vector`，空间仍是 $O(n)$ 但不受系统栈限制，适合把 $n$ 放到 $10^5$ 的场景。
7. **别用求和/计数代替判空**。判断「是否成了叶子」只能看两个指针是否都为 `null`；用「子树节点数是否为 0」「子树和是否为 0」在本题都不可靠（值域 $1 \sim 1000$ 全为正，求和判空看似可行，但一旦值域含 0 或负数就崩，属于没必要的技巧）。

## 5. 正确性证明

记 $D(v)$ 如上，$f(v)$ 为归约函数；约定空子树 $D(\text{null}) = \text{true}$、$f(\text{null}) = \text{null}$，「$v$ 的子树被删空」指子树内所有节点都被删除。

**引理 1（删除只沿父边传播）**：删除节点 $u$ 只会把 $u$ 从它父亲的对应孩子指针上摘掉，不会改变其它任何节点的值、也不会改变其它任何指针。

**证明**：删除操作由「$u$ 是叶子」触发，此时 $u$ 没有孩子，摘除它只涉及 $u$ 的父亲这一个指针；其余节点与其孩子的连接未被触碰。∎

**引理 2（$D$ 的语义）**：对任意节点 $v$，有

- 若 $D(v) = \text{true}$，则 $v$ 的整棵子树中每个节点最终都会被删除；
- 若 $D(v) = \text{false}$，则 $v$ 本身永远不会被删除。

**证明**：对子树高度归纳。

先证第一条。设 $D(v) = \text{true}$，则 $v.\text{val} = \text{target}$ 且 $D(v.\text{left})$、$D(v.\text{right})$ 均为真。由归纳假设，左右子树中每个节点最终都会被删除（空子树情形为空真）。删除只减不增，故某个时刻之后两个孩子的指针均为 `null`，此时 $v$ 是叶子且值等于 `target`。若 $v$ 到过程结束仍未删除，则结束时它仍是「值为 `target` 的叶子」，过程尚未到不动点，与结束条件矛盾。故 $v$ 也被删除。

再证第二条。设 $D(v) = \text{false}$，分两种情形：

- $v.\text{val} \ne \text{target}$：删除只会删除值为 `target` 的节点，故 $v$ 永不被删。
- $v.\text{val} = \text{target}$：此时必有某个孩子 $c$ 满足 $D(c) = \text{false}$。由归纳假设 $c$ 永不被删，由引理 1 删除不会改动「$v$ 与 $c$ 之间的那条指针」，故 $v$ 始终有孩子、永远不是叶子，也就永远不满足删除条件。∎

**引理 3（终态等于 $f$）**：反复删除到不动点后，保留下来的节点恰是 $\{v : D(v) = \text{false}\}$，且每个保留节点的孩子就是它原本的、同样被保留的孩子。

**证明**：集合部分由引理 2 直接得到（$D$ 真者全删，$D$ 假者全留）。边的部分：一个孩子指针变为 `null` 只可能因为该孩子被删除（引理 1），所以保留节点 $v$ 的某个孩子指针仍指向原孩子 $c$ 当且仅当 $c$ 未被删除，即 $D(c) = \text{false}$。这正是 $f$ 的构造。∎

**定理**：`dfs(v)` 返回 $f(v)$，因此 `removeLeafNodes` 返回的是题目要求的唯一终态。

**证明**：对子树高度归纳。空节点时 `dfs` 返回 `null` $= f(\text{null})$。设 $v$ 非空，由归纳假设两次递归分别得到 $f(v.\text{left})$、$f(v.\text{right})$，且它们等于左右子树各自的终态（引理 3）。于是判断时：

- 两个孩子都为空 $\iff$ 左右子树都被删空 $\iff D(v.\text{left}) \wedge D(v.\text{right})$ 为真；
- 再与 $v.\text{val} = \text{target}$ 相与，恰是 $D(v)$。

所以 `dfs` 在 $D(v)$ 为真时返回 `null`，否则返回 $v$ 并把两个孩子设为 $f(v.\text{left})$、$f(v.\text{right})$——两种情形都与 $f(v)$ 的定义一致。由引理 3，$f$ 就是反复删除的终态，故返回值即为所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点恰好被 `dfs` 访问一次，另对每个空指针位置各调用一次（共 $n+1$ 个空指针），每次只做常数次比较与赋值，总计 $O(n)$。$n = 3000$ 时约 $6 \times 10^3$ 次调用。
- **空间**：$O(h)$，$h$ 为树高，来自递归调用栈（每层常数个局部变量）。平衡树上 $h = O(\log n)$；链形树上 $h = n = 3000$，是本题的空间上界。除栈以外不额外开数组，指针全部原地改写。
- 与暴力法的对比：暴力法每轮都要遍历全树，时间 $O(n \cdot h)$、且不产生任何复用；后序版把「轮」压进了「返回」，时间降到 $O(n)$，空间不变。

## 7. 参考代码

### C++

```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
public:
    TreeNode* removeLeafNodes(TreeNode* root, int target) {
        if (root == nullptr) return nullptr;                  // 空子树视为「已删空」

        root->left = removeLeafNodes(root->left, target);      // 先把左子树归约好
        root->right = removeLeafNodes(root->right, target);    // 再把右子树归约好

        // 孩子都被删空后，自己才可能变成叶子
        if (root->left == nullptr && root->right == nullptr && root->val == target) {
            return nullptr;                                   // 等价于「再删一轮」
        }
        return root;                                          // 否则保留
    }
};
```

### Python

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
import sys
from typing import Optional


class Solution:
    def removeLeafNodes(self, root: Optional[TreeNode], target: int) -> Optional[TreeNode]:
        sys.setrecursionlimit(10000)          # 链形树深度可达 3000，超过默认上限 1000

        def dfs(node: Optional[TreeNode]) -> Optional[TreeNode]:
            if node is None:
                return None                   # 空子树视为「已删空」

            node.left = dfs(node.left)        # 先把左子树归约好
            node.right = dfs(node.right)      # 再把右子树归约好

            # 孩子都被删空后，自己才可能变成叶子
            if node.left is None and node.right is None and node.val == target:
                return None                   # 等价于「再删一轮」
            return node

        return dfs(root)
```

## 8. 边界情况与易错点

1. **整棵树被删空**：`root = [2,2]`、`target = 2` 时先删叶子 2，根随后变成叶子也被删，返回 `null`，LeetCode 期望 `[]`。不要因为「根节点必须存在」而把根的特判写死。
2. **单节点**：`[1]` 配 `target = 1` 返回 `[]`；配 `target = 2` 返回 `[1]`（是叶子但值不等于 `target`）。注意「是叶子」只是删除的**必要**条件。
3. **全部值都等于 `target`**：`[5,5,5,5,5,5,5]`、`target = 5` 会被整棵删空（每删完一层，上一层又变成叶子）。后序一趟从最深处删到根，不要以为需要手写外层循环反复跑。
4. **非 `target` 节点阻断传播**：`[1,2,2,2,2]`、`target = 2` 结果为 `[1]`；若把链顶的 1 也换成 2，结果就变成 `[]`——阻断点是否被删，决定了上面所有节点能否继续被删。
5. **根值为 `target` 但有孩子**：`[2,1,2]`、`target = 2` 结果是 `[2,1]`：右侧叶子 2 被删，根 2 仍带着孩子 1，不满足叶子条件，保留。
6. **实现层面的两个坑**：一是 C++ 写成 `removeLeafNodes(root->left, target);` 不接收返回值，编译器不报错却一个节点都删不掉，是本题最隐蔽的错误；二是把判断写在两次递归之前（先序），示例 1 会得到 `[1,2,3,null,null,null,4]`——左侧那个 2 检查时还有孩子，等孩子被删光时它已被「检查过」，再没人管它。
7. **Python 递归深度**：$[2,2,\dots,2]$ 的链形输入深度 3000，默认上限 1000 会抛 `RecursionError`；必须 `sys.setrecursionlimit`（或改写显式栈的迭代后序）。本地用小数据测不出这个问题。
8. **空树输入**：虽然约束保证 $n \ge 1$，但 `dfs` 里保留 `node is None` 的出口既是递归终止条件，也顺便让代码对空树安全，不要为了「省一次判断」把它删掉。

- [LeetCode 669. 修剪二叉搜索树](https://leetcode.cn/problems/trim-a-binary-search-tree/)：利用 BST 有序性决定剪哪一边，剪完要把子树「接回来」，与本题「返回值接回指针」的写法同源。
- [LeetCode 450. 删除二叉搜索树中的节点](https://leetcode.cn/problems/delete-node-in-a-bst/)：删除任意节点需要处理「两个孩子」的情形，比本题的「只删叶子」复杂一档，可对照体会「删除的难点在于接孩子」。

**延伸思考**：

1. **删除条件改成「值等于 target 的节点及其子树」**：判断不再依赖孩子是否被删空，先序即可完成，但要把被删节点的孩子收集成森林（即 1110 题）；这说明「删除是否需要后序」取决于**删除条件是否依赖孩子状态**。
2. **target 变成一个集合**：只需把 `node.val == target` 换成哈希集合判定，结构不变，仍是 $O(n)$。
3. **要求输出删除的轮次**：后序返回时顺手记录 $g(v) = 0$（不删）或 $g(v) = 1 + \max(g(\text{left}), g(\text{right}))$（删），最大轮次就是 $\max_v g(v)$，即删除沿最长链传播的深度。
4. **$n$ 放大到 $10^6$ 且树退化成链**：递归必然爆栈，需改写显式栈的迭代后序（压栈时打「访问标记」，或用 `prev` 指针判断是从左子树还是右子树返回），或者干脆把树先做一次链式展开再自底向上扫。
