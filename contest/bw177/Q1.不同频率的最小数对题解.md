# LeetCode 不同频率的最小数对 题解

## 1. 题目概述

- **标题 / 题号**：不同频率的最小数对（#3852，easy）
- **链接**：https://leetcode.cn/problems/smallest-pair-with-different-frequencies/
- **来源**：LeetCode 第 177 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums`，从里面挑两个**值互不相同**的数 $x, y$（自然要求 $x < y$），使得 $x$ 与 $y$ 在数组中出现的**频率不同**。在所有满足条件的数对里，先让 $x$ 尽可能小，$x$ 相同时再让 $y$ 尽可能小，返回这个数对 $[x, y]$；若不存在这样的数对，返回 $[-1, -1]$。

一个值的**频率**就是它在数组中出现的次数。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,2,3,4]
输出：[1,3]
解释：最小值 1 的频率为 2。比 1 大且频率与 1 不同的最小值是 3（频率 1）。
      2 虽然比 3 小，但它的频率也是 2，与 1 相同，被淘汰。
```

**示例 2**

```text
输入：nums = [1,5]
输出：[-1,-1]
解释：两个值各出现 1 次，频率相同，不存在合法数对。
```

**示例 3**

```text
输入：nums = [7]
输出：[-1,-1]
解释：数组中只有一个不同的值，凑不出「两个互不相同的值」。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：先把每个值的频率数出来，然后枚举所有值对 $(x, y)$，检查 $x < y$ 且频率不同，在合法的里面按「$x$ 最小、其次 $y$ 最小」挑一个。

因为不同值最多只有 100 个（值域 $[1,100]$），枚举值对是 $O(V^2)$，完全够用。真正需要想清楚的只有一件事：**「$x$ 最小、其次 $y$ 最小」这个目标，能不能边枚举边剪枝**——答案是能，因为它是标准的**字典序最小**目标。

### 3.2 核心观察：字典序目标 ⇒ 双层「第一个满足即停」

![不同频率的最小数对：频次表 + 从小到大试 x](images/bw177_q1_freq_table.svg)

把目标拆成两层来看：

1. **外层选 $x$**：$x$ 要尽可能小。所以按值升序逐个试 $x$，**第一个「能找到搭档」的 $x$ 就是答案的 $x$**，后面更大的 $x$ 一律不用看。
2. **内层选 $y$**：$x$ 定下来后，$y$ 也必须尽可能小。所以对固定 $x$，从 $x+1$ 开始升序找第一个满足 $\text{freq}[y] \ne \text{freq}[x]$ 的值，它就是答案的 $y$。

两个循环都是「从小到大、第一个满足即返回」，因此不需要任何额外的比较逻辑，也不需要记录当前最优解。

> 💡 **为什么关注「频率」而不是「下标」**：题目只关心某个值出现了几次，与出现在哪里无关。所以只需要一张频次表，加上一个去重后的有序值列表，就覆盖了全部信息。

### 3.3 算法流程

![算法流程：枚举最小 x，再找最小 y](images/bw177_q1_flow.svg)

```text
1. freq = 空哈希表
2. for v in nums:            freq[v] += 1
3. vals = freq 的键，按升序排序
4. for x in vals（升序）:
5.     for y in vals 且 y > x（升序）:
6.         若 freq[y] != freq[x]:  返回 [x, y]      # x 已最小，y 也已最小
7. 返回 [-1, -1]                                    # 没有任何 x 有合法搭档
```

### 3.4 示例演算

对示例 1 的 `nums = [1,1,2,2,3,4]`，频次表为 $\{1\!:\!2,\ 2\!:\!2,\ 3\!:\!1,\ 4\!:\!1\}$，值列表 $[1,2,3,4]$：

| 外层 $x$ | $\text{freq}[x]$ | 内层逐个试 $y$ | 结论 |
|---------|-----------------|---------------|------|
| 1 | 2 | $y=2$：频率 2，相同 ✗；$y=3$：频率 1，不同 ✓ | 返回 $[1,3]$ |

因为 $x=1$ 就已经有搭档，算法直接返回，$x=2,3,4$ 根本不会被检查。示例 2 中值列表为 $[1,5]$，两者频率都是 1，外层两个 $x$ 都找不到搭档，返回 $[-1,-1]$；示例 3 只有一个值，内层循环体一次都不执行，同样返回 $[-1,-1]$。

## 4. 算法细节

1. **频次表选型**：值域 $[1,100]$ 很小，开一个长度 101 的桶数组即可；用 `unordered_map` / `dict` 则天然支持任意值域，写起来更通用。本文代码用哈希表。
2. **去重 + 升序**：哈希表的键本身就是去重后的集合，排序后内层循环的顺序就自动是「$y$ 递增」，不需要再判重。
3. **命中即返回**：外层一旦返回就结束，所以不需要维护「最优答案」变量，也不存在比较两个候选数对的问题。
4. **两个「不同」要分清**：
   - 值必须**互不相同**（$x \ne y$，且代码里用 $y > x$ 保证这是两个不同的值，不是同一个值的两个下标）；
   - 频率也必须**不同**（$\text{freq}[x] \ne \text{freq}[y]$）。
5. **返回类型**：返回 `vector<int>` / `list[int]`，无解时返回的是**两个元素**的 $[-1,-1]$，不是单个 $-1$。

## 5. 正确性证明

**引理 1（频次表精确）**：对每个在 `nums` 中出现过的值 $v$，算法结束时 $\text{freq}[v]$ 恰等于 $v$ 在 `nums` 中的出现次数。

**证明**：算法对 `nums` 的每个元素恰好访问一次，访问到 $v$ 时执行一次 $\text{freq}[v] \mathrel{+}= 1$，因此 $\text{freq}[v]$ 的最终值就是 $v$ 被访问的次数，即出现次数。∎

**引理 2（外层正确性）**：设值列表为 $v_1 < v_2 < \cdots < v_m$。若存在合法数对，则算法返回的 $x$ 是所有合法数对中最小的 $x$ 分量。

**证明**：算法按 $v_1, v_2, \dots$ 升序逐个尝试。对 $x = v_i$，内层完整扫描了所有 $y > v_i$ 的值，因此「$v_i$ 存在搭档」这一判断是准确的。算法返回的第一个 $x$ 记为 $v_k$，则 $v_1, \dots, v_{k-1}$ 都不存在搭档，而 $v_k$ 存在搭档，故 $v_k$ 是字典序意义上最小的可行 $x$。∎

**引理 3（内层正确性）**：固定 $x$ 时，算法返回的 $y$ 是所有满足 $y > x$ 且 $\text{freq}[y] \ne \text{freq}[x]$ 的值中最小的一个。

**证明**：内层按值升序枚举所有 $y > x$，遇到第一个频率不同的值立即返回，故返回的 $y$ 之前不存在可行值，即它是最小可行 $y$。∎

**定理**：算法返回值等于题目要求的最优数对；当且仅当不存在合法数对时返回 $[-1,-1]$。

**证明**：先看存在性。若存在合法数对 $(x_0, y_0)$，那么外层试到 $x_0$ 时，内层一定能找到 $y_0$ 这个候选，故算法不会跳过 $x_0$ 而返回；由引理 2、引理 3，返回的数对在两层的选择上都取到了最小值，即按「$x$ 最小、其次 $y$ 最小」的字典序最优。反之若不存在任何合法数对，则外层每个 $x$ 的内层扫描都以失败告终，算法走到末尾返回 $[-1,-1]$，与题目要求的无解返回值一致。∎

## 6. 复杂度分析

- **时间**：$O(n + V \log V + V^2)$，其中 $V$ 是不同值的个数。统计频次一遍 $O(n)$；键排序 $O(V \log V)$；双层枚举最坏 $O(V^2)$。本题 $n \le 100$、$V \le 100$，总计不超过一万次基本操作。
- **空间**：$O(V)$。频次表存 $V$ 个键值对，值列表存 $V$ 个整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minDistinctFreqPair(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int x : nums) freq[x]++;
        vector<int> vals;
        for (auto& kv : freq) vals.push_back(kv.first);
        sort(vals.begin(), vals.end());
        for (size_t i = 0; i < vals.size(); i++) {
            for (size_t j = i + 1; j < vals.size(); j++) {
                if (freq[vals[j]] != freq[vals[i]]) {
                    return {vals[i], vals[j]};
                }
            }
        }
        return {-1, -1};
    }
};
```

### Python

```python
class Solution:
    def minDistinctFreqPair(self, nums: list[int]) -> list[int]:
        freq = {}
        for x in nums:
            freq[x] = freq.get(x, 0) + 1
        vals = sorted(freq)
        for x in vals:
            for y in vals:
                if y > x and freq[y] != freq[x]:
                    return [x, y]
        return [-1, -1]
```

## 8. 边界情况与易错点

1. **所有值的频率都相同**：例如 `[1,5]`、`[2,2,7,7]`，此时内层永远匹配不到，必须返回 $[-1,-1]$，不能返回空数组或 $-1$。
2. **只有一个不同的值**：例如 `[7]`、`[3,3,3]`，连「两个互不相同的值」都凑不出，直接走无解分支。
3. **「值不同」不等于「下标不同」**：不能把同一个值的两个下标当成 $(x, y)$。代码用 $y > x$ 强制两个值不同。
4. **早期返回值**：外层第一个命中的 $x$ 就要立刻返回，若写成「先存一个候选、继续找更优」反而容易把「更小的 $y$」写错方向。
5. **频率为 1 的情况**：出现一次的值频率是 1，出现两次是 2，两者不同，可以直接配对——不要误以为「频率 1 表示没出现」。
6. **值域与哈希**：用桶数组要注意值为 0 或负数时越界（本题 $nums[i] \ge 1$，安全）；用哈希表则没有这个问题，代价是多一次排序。
