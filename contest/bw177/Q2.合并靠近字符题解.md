# LeetCode 合并靠近字符 题解

## 1. 题目概述

- **标题 / 题号**：合并靠近字符（#3853，medium）
- **链接**：https://leetcode.cn/problems/merge-close-characters/
- **来源**：LeetCode 第 177 场双周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、模拟

**题意**：给定小写字母串 `s` 和整数 $k$。在**当前**字符串中，如果两个**相同**字符的下标距离不超过 $k$，就称它们「靠近」；一旦靠近，就把**右边那个合并到左边**（等价于删掉右侧字符）。合并一次只处理一对，串随即更新，直到再也找不到靠近的同值字符为止。

题目额外规定了两条**决胜规则**，保证整个过程唯一确定：每轮总是选「**左侧下标最小**」的那一对；若左侧下标相同，则选「**右侧下标最小**」的那一对。返回最终的字符串。

**约束**：

- $1 \le \text{s.length} \le 100$
- $1 \le k \le \text{s.length}$
- `s` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：s = "abca", k = 3
输出："abc"
解释：下标 0 和 3 的 'a' 距离 3 <= k，合并到左边的 'a'，删掉下标 3 → "abc"。
      之后没有其它相同字符靠近，结束。
```

**示例 2**

```text
输入：s = "aabca", k = 2
输出："abca"
解释：下标 0 和 1 的 'a' 距离 1 <= 2，先合并 → "abca"。
      此时两个 'a' 位于下标 0 和 3，距离 3 > k = 2，不能再合并（下标左移了，但还不够近）。
```

**示例 3**

```text
输入：s = "yybyzybz", k = 2
输出："ybzybz"
解释：第 1 轮合并下标 0、1 的 'y' → "ybyzybz"；
      第 2 轮合并下标 0、2 的 'y' → "ybzybz"；
      此后任意同值字符的距离都超过 2，结束。
```

## 3. 解题思路

### 3.1 暴力思路

题意已经把流程写得很细了：每轮**重新**扫描当前串，找到字典序最小（先左下标、后右下标）的可行同值对，删掉右侧字符，重复到找不到为止。

直接照做即可：一轮扫描 $O(n^2)$ 对下标，最多删 $n-1$ 次，总复杂度 $O(n^3)$。本题 $n \le 100$，$10^6$ 级别的操作绰绰有余——**这道题的关键不是优化复杂度，而是别把「合并」的语义写错**。

### 3.2 核心观察：一个 $i$ 只需看它右边「最近」的同值字符

![合并规则：同字符且下标距离 ≤ k，删掉右侧那个](images/bw177_q2_merge_rule.svg)

把「找最小右端点」这件事想清楚，代码就能短很多：

1. 对固定的左下标 $i$，所有可配对的 $j$ 都满足 $s[j] = s[i]$ 且 $j > i$。这些 $j$ 里**最小的那个**距离也最小。因此只要最近的同值字符距离都超过 $k$，更远的更不可能满足，$i$ 就可以**直接放弃**——这一点让内层循环可以「遇到第一个同值字符就 break」。
2. 删除右侧字符后，被删位置之后的字符整体左移一位，**原本距离刚好超限的一对可能因此变得合法**。所以不能只扫描一遍，必须每轮从下标 0 重新开始。
3. 合并方向固定为「左吞右」，说明结果串始终是原串的一个**子序列**，长度等于 $n$ 减去合并次数。

![示例演算：s = "yybyzybz"，k = 2](images/bw177_q2_walkthrough.svg)

上图把示例 3 的三轮压缩成了一个画面：红色格子是本轮被合并的两个字符（右侧那个随后消失），绿色是仍然存在的 `y`，蓝色是其它字符。可以看到第 2 轮合并后，两个 `y` 之间只剩 2 个字符，距离恰好等于 $k$，所以还能再合一次；而第 3 轮里 `y` 与 `y` 相距 3，规则不再允许。

### 3.3 算法流程

```text
1. cur = list(s)                      # 可变字符数组
2. loop:
3.     merged = false
4.     for i = 0 .. len(cur)-1:                  # 左侧下标从小到大：字典序第一关键字
5.         for j = i+1 .. len(cur)-1:
6.             若 cur[j] == cur[i]:
7.                 若 j - i <= k: 删除 cur[j]; merged = true      # 字典序第二关键字：最近的 j
8.                 break                                        # 更远的同值必然更远，无需再看
9.         若 merged: break                                      # 本轮只合并一对，重新扫描
10.    若 not merged: 返回 cur
```

### 3.4 示例演算

以示例 2 的 `s = "aabca"`、$k = 2$ 为例：

| 轮次 | 当前串 | 选中的对 $(i,j)$ | 距离 | 判定 | 合并后 |
|------|--------|-----------------|------|------|--------|
| 1 | `aabca` | $(0,1)$：两个 `a` | 1 | $1 \le 2$ ✓ | `abca` |
| 2 | `abca` | $(0,3)$：两个 `a` | 3 | $3 > 2$ ✗ | 不变，结束 |

注意第 2 轮里两个 `a` 的下标从 $(0,4)$ 变成了 $(0,3)$——删掉夹在它们**之间**的字符会让同值字符**变近**（原本距离 4，删掉下标 1 后距离 3）。这正是必须每轮重扫、不能沿用旧距离的原因。

## 4. 算法细节

1. **可变容器**：C++ 用 `string` 并配合 `erase(s.begin() + j)`；Python 用 `list(s)` 后 `del cur[j]`。两者都是 $O(n)$ 的单次删除，在本数据范围内完全够用。
2. **内层 break 的位置**：找到第一个 `cur[j] == cur[i]` 就必须 `break`——无论它是否满足距离条件。因为后续同值字符距离只会更大。
3. **外层命中即重来**：一轮只合并一对，合并后立刻 `break` 出两层循环并重新从下标 0 扫描，才能复现「左侧下标最小优先」的规则。
4. **终止条件**：某一轮扫描完全部 $i$ 都没有发生合并，即当前串已无靠近的同值字符。
5. **不要用「栈」硬套**：经典「删除相邻重复项」可以用栈，但这里允许 $j - i \le k$（不要求相邻），且删除后仍要从头复检，栈的线性结构对不上，直接用模拟最稳。

## 5. 正确性证明

**引理 1（最近同值判定充分）**：对固定的 $i$，设 $j_0$ 是满足 $j > i$ 且 $s[j] = s[i]$ 的最小下标。则 $i$ 存在合法右端点当且仅当 $j_0 - i \le k$。

**证明**：所有候选右端点都形如 $j \ge j_0$ 且 $s[j] = s[i]$，因此它们的距离 $j - i \ge j_0 - i$。若 $j_0 - i > k$，则任何候选都超限，$i$ 无解；若 $j_0 - i \le k$，则 $j_0$ 本身就是合法右端点。∎

**引理 2（字典序最小对唯一确定）**：若当前串存在至少一对靠近的同值字符，则按「左下标最小、其次右下标最小」选出的对 $(i^*, j^*)$ 存在且唯一。

**证明**：存在性由前提给出。唯一性：所有可行对的左下标构成非空整数集合，取最小值 $i^*$；在左下标等于 $i^*$ 的可行对中，右下标也构成非空整数集合，取最小值 $j^*$。整数集合的最小值唯一，故 $(i^*, j^*)$ 唯一。∎

**引理 3（每轮选择正确）**：算法第 4–9 行选出的对恰为引理 2 中的 $(i^*, j^*)$。

**证明**：外层 $i$ 从 0 递增，遇到第一个「存在合法右端点」的 $i$ 就停止继续外层循环，由引理 1 的判定与可行对左下标最小的定义，这个 $i$ 就是 $i^*$；内层 $j$ 从 $i+1$ 递增，取到第一个同值且距离合法的 $j$，即该 $i$ 下最小的可行右端点 $j^*$。∎

**定理**：算法返回的字符串等于题目规则下反复合并得到的最终字符串。

**证明**：题目规则每一轮做的事是：在当前串上取字典序最小的可行对，删除其右侧字符。由引理 3，算法每一轮做的正是同一件事；两边从同一初始串出发、每轮执行相同的一步，故归纳可得第 $t$ 轮的串完全相同。此外算法只在「当前串已无可行对」时停止，与题目「直到无法再进行合并为止」的终止条件一致。因此终态相同。∎

**推论**：合并次数最多为 $n-1$，故算法必然终止。

## 6. 复杂度分析

- **时间**：最坏 $O(n^3)$。合并至多 $n-1$ 轮，每轮双重扫描 $O(n^2)$，单次删除 $O(n)$ 被 $O(n^2)$ 吸收。$n \le 100$ 时上界约 $10^6$ 次字符比较。
- **空间**：$O(n)$，保存当前串的可变副本；除此之外只有常数个临时变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string mergeCharacters(string s, int k) {
        bool merged = true;
        while (merged) {
            merged = false;
            for (int i = 0; i < (int)s.size() && !merged; i++) {
                for (int j = i + 1; j < (int)s.size(); j++) {
                    if (s[j] == s[i]) {
                        if (j - i <= k) {
                            s.erase(s.begin() + j);
                            merged = true;
                        }
                        break;
                    }
                }
            }
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def mergeCharacters(self, s: str, k: int) -> str:
        cur = list(s)
        merged = True
        while merged:
            merged = False
            for i in range(len(cur)):
                for j in range(i + 1, len(cur)):
                    if cur[j] == cur[i]:
                        if j - i <= k:
                            del cur[j]
                            merged = True
                        break
                if merged:
                    break
        return "".join(cur)
```

## 8. 边界情况与易错点

1. **$k = 1$**：只能合并**相邻**的同值字符，例如 `"aab"` 合并成 `"ab"`；写代码时别把条件写成 `j - i < k`（严格小于就漏掉了距离恰好为 $k$ 的情况）。
2. **全同字符**：`s = "aaaa"`、$k = 1$ 时逐轮合并，最终只剩 `"a"`。注意每轮都要重新扫描，一次性顺序压缩会算错轮次对应的字符串。
3. **删除导致左移、并且会改变距离**：这是最容易 WA 的点。`"aabca"` 中两个 `a` 原本相距 $4-0=4$；第 1 轮删掉下标 1 的 `a` 后，最后一个 `a` 从下标 4 移到 3，两者距离变成 3，但仍大于 $k=2$。删除**两字符之间**的字符会让它们变近，删除其它位置的字符则不影响——所以必须每轮重新测量。
4. **`break` 只写在内层**：内层找到第一个同值字符就 `break`，但外层要**整个重来**；若只 `break` 内层而继续外层，会漏掉「删除后前面对变近」的情况。
5. **单字符串**：长度为 1 时两层循环都不执行，直接返回原串，不需要特判。
6. **$k \ge n$**：此时同值字符总能合并，结果串中每种字符最多出现一次——可以用来做快速自检（例如 `"abca"`、$k \ge 3$ 的结果是 `"abc"`）。
