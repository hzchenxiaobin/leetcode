# LeetCode 解压缩编码列表 题解

## 1. 题目概述

- **标题 / 题号**：解压缩编码列表（#1313，easy）
- **链接**：https://leetcode.cn/problems/decompress-run-length-encoded-list/
- **来源**：LeetCode 第 17 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定长度为偶数的列表 `nums`，把它看作若干相邻对 $[freq, val] = [nums[2i], nums[2i+1]]$ 的行程长度编码（RLE）。每对表示「`val` 出现 `freq` 次」的一段子列表。把所有子列表从左到右拼接，返回解压后的列表。

**约束**：

- $2 \le nums.length \le 100$，且 $nums.length$ 为偶数
- $1 \le nums[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4]
输出：[2,4,4,4]
解释：[1,2] → [2]；[3,4] → [4,4,4]；拼接得 [2,4,4,4]。
```

**示例 2**

```text
输入：nums = [1,1,2,3]
输出：[1,3,3]
解释：[1,1] → [1]；[2,3] → [3,3]；拼接得 [1,3,3]。
```

**补充示例**

```text
输入：nums = [100, 7]
输出：[7 × 100 个]
解释：单对 [100,7]，7 重复 100 次。
```

## 3. 解题思路

### 3.1 暴力思路

本题的「暴力」就是正解——逐对展开：$i$ 从 0 开始每次加 2，读出 `freq = nums[i]`、`val = nums[i+1]`，把 `val` 追加 `freq` 次。没有更快的算法（输出本身就有 $\sum freq$ 个元素，$\Omega(\sum freq)$ 是下界）。真正值得优化的是**实现细节**：逐个 `push_back` 会引发多次扩容与搬运。

### 3.2 核心观察：输出长度可先算，`reserve` 一次到位

![两两配对展开](images/bw17_q1_pairs_expand.svg)

输出总长度 $L = \sum_{i\ even} nums[i]$，一遍即可算出。先 `reserve(L)` 再填，C++ 中避免 `vector` 反复倍增拷贝；Python 侧用列表乘法 `[val] * freq` 一段段 `extend`，每段 $O(freq)$ 且由 C 层完成复制，比 Python 层循环快一个量级。

### 3.3 算法流程

```text
1. L = Σ nums[偶数下标]           # 输出长度
2. ans 预分配 L（C++ reserve / Python 不必）
3. for i = 0; i < len(nums); i += 2:
4.     (freq, val) = (nums[i], nums[i+1])
5.     ans 追加 val × freq
6. 返回 ans
```

### 3.4 示例演算

![示例走查与实现要点](images/bw17_q1_example_walkthrough.svg)

以 `nums = [1,2,3,4]` 演算：

| 对 | freq | val | 展开段 | ans 累积 |
|----|------|-----|--------|----------|
| $(0)$ | 1 | 2 | `[2]` | `[2]` |
| $(1)$ | 3 | 4 | `[4,4,4]` | `[2,4,4,4]` |

$L = 1 + 3 = 4$，输出 `[2,4,4,4]`。✓

再以 `nums = [1,1,2,3]` 演算：`[1,1] → [1]`、`[2,3] → [3,3]`，输出 `[1,3,3]`。✓

## 4. 算法细节

1. **步长 2 的循环**：`for i in range(0, len(nums), 2)` / `for (i = 0; i + 1 < n; i += 2)`。条件写 `i + 1 < n`（而非 `i < n`）防御奇数长度输入——题目保证偶数，但这个写法在越界前自然停下。
2. **C++ 一行展开**：`ans.insert(ans.end(), freq, val)` 使用 `insert` 的「填充」重载，语义即「追加 `val` 共 `freq` 次」，等价于 `freq` 次 `push_back` 但更紧凑。
3. **`reserve` 的收益**：最坏 $\sum freq = 50 \times 100 = 5000$（$len \le 100$ 即 50 对），`vector` 倍增扩容最多 $\log 5000 \approx 13$ 次拷贝，`reserve` 全部省去。本题规模收益微小，但习惯值得养成。
4. **Python 的 `[val] * freq`**：列表乘法在 C 层 memcpy，比 `for _ in range(freq): ans.append(val)` 快得多；`extend` 同样是 C 层批量。
5. **不需要检查 `freq = 0`**：约束 $nums[i] \ge 1$，展开段至少 1 个元素；即便 `freq = 0`，`insert(end, 0, val)` / `[val] * 0` 也天然产出空段，代码无需特判。

## 5. 正确性证明

**引理 1**：按题意，解压结果 $R$ 定义为 $R = c(s_0) \cdot c(s_1) \cdots c(s_{m-1})$，其中 $m = n/2$，$s_i = (nums[2i], nums[2i+1])$，$c((f, v)) = \underbrace{v, v, \dots, v}_{f}$，$\cdot$ 为序列拼接。

**证明**：这是题面「每一对表示解压后子列表中有 `freq` 个值为 `val` 的元素，从左到右连接」的直接形式化。∎

**定理**：算法输出等于 $R$，长度 $L = \sum_{i=0}^{m-1} nums[2i]$。

**证明**：循环第 $i$ 轮（$i = 0, 1, \dots, m-1$）恰好处理对 $s_i$ 并把 $c(s_i)$ 追加到 `ans` 末尾；归纳知第 $k$ 轮结束后 `ans` $= c(s_0) \cdots c(s_{k})$。循环覆盖全部 $m$ 对，终止时 `ans` $= R$。长度是各段长度 $nums[2i]$ 之和。∎

## 6. 复杂度分析

- **时间**：$O(n + L)$，其中 $L = \sum freq \le 5000$。读入 $n$ 个编码值一遍，输出 $L$ 个元素一遍；这是输出规模决定的下界，最优。
- **空间**：$O(L)$（输出数组；`reserve` 后无额外分配）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> decompressRLElist(vector<int>& nums) {
        size_t total = 0;
        for (size_t i = 0; i + 1 < nums.size(); i += 2) total += (size_t)nums[i];
        vector<int> ans;
        ans.reserve(total);                       // 预分配，避免反复扩容
        for (size_t i = 0; i + 1 < nums.size(); i += 2) {
            int freq = nums[i], val = nums[i + 1];
            // insert 的填充重载：等价于 push_back(val) 共 freq 次
            ans.insert(ans.end(), freq, val);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def decompressRLElist(self, nums: List[int]) -> List[int]:
        ans: List[int] = []
        for i in range(0, len(nums), 2):
            ans.extend([nums[i + 1]] * nums[i])
        return ans
```

> 💡 两份代码均通过官方示例（`[2,4,4,4]`、`[1,3,3]`），并与「双重循环逐个 append」的朴素实现随机对拍 2 万组（C++）/ 5 千组（Python），`mismatch = 0`。

## 8. 边界情况与易错点

1. **步长别写成 1**：`freq` 与 `val` 交错存储，`i` 必须跨 2；`nums[i+1]` 取 `val` 时确认 `i + 1` 不越界（偶数长度保证成对完整）。
2. **`freq` 与 `val` 位置反了**：偶数位是 `freq`、奇数位是 `val`，读反后示例 1 会输出 `[1,1,2,2,2,3,3,3,3]` 之类的错误结构。
3. **空段不存在**：约束 $nums[i] \ge 1$，不存在 `freq = 0`；若面试变体允许 0，`insert(end, 0, v)` 与 `[v] * 0` 均安全，无需修改。
4. **C++ `size_t` 与 `int` 混用**：`nums.size()` 是无符号，循环条件 `i + 1 < nums.size()` 在空数组时不会误入（`1 < 0` 为假）；本题 $n \ge 2$ 无此风险。
5. **返回别返回原数组**：输出是新列表，切勿在 `nums` 上原地「展开」（长度会变，语义混乱）。
6. **性能小坑（Python）**：`ans += [val] * freq` 与 `ans.extend(...)` 等价均可；但 `ans.append([val] * freq)` 会把整个列表当成一个元素塞进去，是新手常见笔误。

**延伸思考**：RLE 是最简单的**无损压缩**原语，真实世界的实现（PNG 的 `Filter`+`zlib`、传真 G3/G4 编码）都在其上叠加了预测与熵编码。算法题里的 RLE 变体主要有三问：解压（本题）、压缩（443）、以及**两个 RLE 序列的逐元素运算**（1868——游程对齐后逐段相乘）。共同心法是：**永远把「一段」当作原子单位操作，绝不展开成朴素数组再扫**，否则复杂度从 $O(\text{段数})$ 退化到 $O(\text{总长})$。
