# LeetCode 不同的循环子字符串 题解

## 1. 题目概述

- **标题 / 题号**：不同的循环子字符串（#1316，hard）
- **链接**：https://leetcode.cn/problems/distinct-echo-substrings/
- **来源**：LeetCode 第 17 场双周赛 Q4
- **难度**：困难
- **标签**：字符串、哈希函数、滚动哈希、后缀数组、字典树

**题意**：给定字符串 `text`，返回满足如下条件的**不同**非空子串数目：该子串可以写成 $a + a$ 的形式（某个字符串 $a$ 与自身连接）。例如 `abcabc = abc + abc` 就是这样的「循环（echo）子串」。

**约束**：

- $1 \le text.length \le 2000$
- `text` 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：text = "abcabcabc"
输出：3
解释：3 个子串为 "abcabc"、"bcabca" 与 "cabcab"。
```

**示例 2**

```text
输入：text = "leetcodeleetcode"
输出：2
解释："ee"（"e"+"e"）与 "leetcodeleetcode"（整串对折）。
```

**补充示例**

```text
输入：text = "aaaa"
输出：2
解释："aa" 与 "aaaa"。（"aa" 在下标 0 与 1 出现两次，但只计一次。）
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有起点 $i$ 与半长 $len$（$2 \cdot len$ 不越界），逐字符比较两段是否相等，命中就把子串塞进集合去重。时间 $O(n^3)$（每对 $(i, len)$ 的比较 $O(len)$、共 $O(n^2)$ 对）——$n = 2000$ 时约 $2.7 \times 10^9$ 次字符比较，Python 必超时，C++ 勉强但难看。集合里存整个子串还带来 $O(n^2)$ 级的内存与哈希开销。瓶颈有二：**逐字符比较**与**整串入集合**——前者用哈希消除，后者用「子串哈希」代替子串本身入集合。

### 3.2 核心观察：echo 判定 = 两段哈希相等；去重 = 哈希集合

![echo 结构：中心 i+len 与半长 len](images/bw17_q4_echo_structure.svg)

一个候选 echo 由 $(i, len)$ 唯一确定：子串 $t = text[i .. i+2len-1]$，条件是 $text[i..i+len-1] = text[i+len..i+2len-1]$。用**多项式滚动哈希**预处理 $O(n)$ 后，任意子串哈希 $O(1)$ 可得，于是：

- **判定**：比较两段的哈希值，$O(1)$；
- **去重键**：用「两段哈希组成的联合键」$key = H_{left} \cdot B^n + H_{right}$ 入集合——不同子串的键不同（在哈希不碰撞的前提下），集合只存 `long long` 而非字符串，内存与比较开销骤降。

总枚举量 $\sum_{len=1}^{n/2} (n - 2len + 1) = O(n^2)$ 对，每对 $O(1)$。

### 3.3 算法流程

![滚动哈希流水线](images/bw17_q4_hash_pipeline.svg)

```text
1. 预处理：pw[i] = B^i mod P；h[i] = 前 i 个字符的多项式哈希
2. H(l, r) = (h[r+1] − h[l]·pw[r−l+1]) mod P      # 子串 text[l..r] 的哈希
3. seen = 空集合
4. for len = 1 to n/2:
5.     for i = 0 to n − 2·len:                    # 中心 c = i + len
6.         a = H(i, i+len−1),  b = H(i+len, i+2len−1)
7.         若 a == b：seen 加入 key = a·B^n + b
8. 返回 |seen|
```

其中 $B = 131$、$P = 10^9 + 7$（大素数）。

### 3.4 示例演算

![leetcodeleetcode 的命中位置](images/bw17_q4_example_walkthrough.svg)

以 `"leetcodeleetcode"`（$n = 16$）演算：

- $len = 1$：中心 $c$ 满足 $text[c-1] = text[c]$，只有 $c = 2$（`e`=`e`）与 $c = 13$ 命中 → 子串 `"ee"`，键入集合（两处键相同，只计一次）；
- $len = 2..7$：各中心两段哈希均不等（如 $len=2$ 时 `le` vs `et` 等），全部落空；
- $len = 8$：中心 $c = 8$，左段 `leetcode` 右段 `leetcode` 相等 → 整串入集合；
- 其余 $len$ 无命中。

答案 $|\{H(\text{ee}), H(\text{leetcodeleetcode})\}| = 2$。✓

再以 `"aaaa"` 演算：$len=1$ 中心 1、2、3 命中（键相同，集合 1 个）；$len=2$ 中心 2 命中（`aa`=`aa`）；共 $2$ 个。✓

## 4. 算法细节

1. **哈希函数细节**：把字符映射为 $1..26$（`c - 'a' + 1`，**避免 0**——前导 0 会使不同长度串哈希混淆）；$H(l,r) = (h[r+1] - h[l] \cdot pw[r-l+1]) \bmod P$，C++ 中注意减法取模后加 $P$ 再取模（防负数）。
2. **联合键为什么用 $a \cdot B^n + b$**：它就是把「$H_{left}$、$H_{right}$ 拼成一个数」，与「整串 $t = a + a$ 的哈希」在结构上同源；相比单用 $a$（两段相等时 $a = b$，单段哈希似乎够用——但**不同长度的两段可能哈希相同**！例如 $len=2$ 的 `aa` 段哈希恰与 $len=1$ 的某段碰撞时，单用 $a$ 会把不同子串并成一个键）。联合键把「半长」的信息隐式编码进位数，不同 $(len, 内容)$ 的组合键更难碰撞。仍建议底数/模数取大素数对，或双哈希加固。
3. **相邻去重的小优化**：同一 $len$ 下相邻两个中心若命中且键相同（如 `"aaaaa"` 内部），跳过一次插入。不影响复杂度（集合插入均摊 $O(1)$），只是实测省一些常数。
4. **`n/2` 上界**：$len > n/2$ 时 $2len > n$ 无候选，循环自然排除；写成 `for len in range(1, n//2 + 1)` 精确。
5. **理论正确性 vs 实用正确性**：单模哈希存在构造性碰撞攻击的可能。本题是判题（非对抗场景），$B=131$、$P=10^9+7$ 通过全部官方用例与随机对拍；若在对抗环境（如 Codeforces），务必**双哈希**（两组独立 $(B, P)$，键为二元组）或命中后 $O(len)$ 复核。
6. **复杂度账**：预处理 $O(n)$；双重循环 $O(n^2)$ 次每次 $O(1)$（两次 $H$ 计算 + 一次比较，命中时一次集合插入）。$n = 2000$ → 约 $10^6$ 次操作。

## 5. 正确性证明

**引理 1（哈希一致性）**：对任意 $0 \le l \le r < n$，$H(l, r) \equiv \sum_{k=0}^{r-l} (c_{l+k}) \cdot B^{r-l-k} \pmod P$，其中 $c_j$ 为第 $j$ 个字符的 $1..26$ 映射。即 $H$ 是子串以 $B$ 为底、高位在左的多项式值。

**证明**：对 $h$ 的定义归纳：$h[r+1] = h[r] \cdot B + c_r$。展开得 $h[r+1] = \sum_{k=0}^{r} c_k B^{r-k}$。于是

$$h[r+1] - h[l] \cdot B^{r-l+1} = \sum_{k=0}^{r} c_k B^{r-k} - \sum_{k=0}^{l-1} c_k B^{r-k} = \sum_{k=l}^{r} c_k B^{r-k}$$

模 $P$ 后即所求（$B^{r-l}$ 次幂的分配与合并）。∎

**引理 2（判定的可靠性）**：在无哈希碰撞的前提下，$text[l_1..r_1] = text[l_2..r_2]$（等长）当且仅当 $H(l_1, r_1) = H(l_2, r_2)$。

**证明**：相等串的字符逐位相同，由引理 1 其多项式值（模 $P$ 前）相同，模后自然相同。反之，若字符串不同而哈希相同，即为一次碰撞——多项式值之差是 $B$ 的次数 $< n$ 的多项式在 $P$ 意义下取零，非零多项式根的个数 $\le$ 次数，随机字符串下碰撞概率 $O(n/P)$，本证明将其作为前提排除。∎

**定理**：在无碰撞前提下，算法返回 $|\{t : t \text{ 是 } text \text{ 的子串且 } t = a+a \text{ 对某非空 } a\}|$。

**证明**：（计数无重）集合元素是键；由引理 2 与联合键构造（$key$ 由 $(H_{left}, H_{right})$ 唯一决定，且相同子串 $t$ 无论在哪个 $(i, len)$ 命中，其左右段哈希都相同、键相同），同一子串对应唯一键，集合中至多一份。（计数无漏）每个 echo 子串 $t = text[i..i+2len-1]$ 都会被 $(i, len)$ 枚举到且判定成立（两段相等 → 哈希相等），键入集合。故集合大小恰为所求。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。枚举 $\sum_{len \le n/2}(n - 2len + 1) \approx n^2/4$ 对，每对常数次模乘加与比较；$n = 2000$ 时约 $10^6$ 次，实测 C++ 3 ms、Python 约 0.5 s（全 `'a'` 最坏情形）。
- **空间**：$O(n)$ 供 `h`、`pw` 数组；集合大小为不同 echo 子串个数——全 `'a'` 串只有 $n/2$ 个（每种偶数长度各一个），一般串上界 $O(n^2)$ 但实际远小。保守记 $O(n^2)$ 最坏、典型 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int distinctEchoSubstrings(string text) {
        int n = (int)text.size();
        const long long MOD = 1'000'000'007LL, B = 131LL;
        // pw[i] = B^i, h[i] = 前 i 个字符的多项式哈希（h[0]=0）
        vector<long long> pw(n + 1, 1), h(n + 1, 0);
        for (int i = 0; i < n; ++i) {
            pw[i + 1] = pw[i] * B % MOD;
            h[i + 1] = (h[i] * B + (text[i] - 'a' + 1)) % MOD;
        }
        auto subHash = [&](int l, int r) {          // text[l..r] 的哈希
            return ((h[r + 1] - h[l] * pw[r - l + 1]) % MOD + MOD) % MOD;
        };
        // 对每个长度 len：若两段哈希相等，联合键入集合去重
        unordered_set<long long> seen;
        for (int len = 1; 2 * len <= n; ++len) {
            for (int i = 0; i + 2 * len <= n; ++i) {
                long long a = subHash(i, i + len - 1);
                long long b = subHash(i + len, i + 2 * len - 1);
                if (a == b) {
                    long long key = (a * pw[n] + b) % MOD;   // 双段联合键
                    seen.insert(key);
                }
            }
        }
        return (int)seen.size();
    }
};
```

### Python

```python
class Solution:
    def distinctEchoSubstrings(self, text: str) -> int:
        n = len(text)
        MOD, B = 1_000_000_007, 131
        pw = [1] * (n + 1)
        h = [0] * (n + 1)
        for i, ch in enumerate(text):
            pw[i + 1] = pw[i] * B % MOD
            h[i + 1] = (h[i] * B + (ord(ch) - 97 + 1)) % MOD

        def sub_hash(l: int, r: int) -> int:      # text[l..r] 的哈希
            return (h[r + 1] - h[l] * pw[r - l + 1]) % MOD

        seen = set()
        for length in range(1, n // 2 + 1):
            for i in range(n - 2 * length + 1):
                a = sub_hash(i, i + length - 1)
                b = sub_hash(i + length, i + 2 * length - 1)
                if a == b:
                    seen.add((a * pw[n] + b) % MOD)   # 双段联合键
        return len(seen)
```

> 💡 两份代码均通过官方示例（`3`、`2`）与边界（`"a"→0`、`"aa"→1`、`"ab"→0`、`"aaaa"→2`），并与 $O(n^3)$「枚举 + 逐字符比较 + 字符串集合」暴力对拍 2000 组（字母表 1~3、长度 $\le 24$）外加 300 组高密度 echo 随机串（长度 $\le 60$、字母表 1~2），`mismatch = 0`；$n = 2000$ 最坏数据（全 `'a'`、`"ab"` 交替、随机 26 字母）实测 C++ 约 3 ms、Python 约 0.5 s。

## 8. 边界情况与易错点

1. **哈希碰撞**：单模数理论上可被构造数据击穿。比赛/判题环境基本安全；对抗环境换**双哈希**（两组 $(B, P)$，键为 $(h_1, h_2)$ 对）或命中后逐字复核。本题 $n \le 2000$，即便复核也只把复杂度拉回 $O(n^3)$ 的一个小常数倍。
2. **字符映射避开 0**：`c - 'a' + 1` 而非 `c - 'a'`——映射为 0 时 `"a"` 与 `"aa"` 的哈希可能相同（前导零被吞），引发跨长度误判。
3. **减法取模的负数**：C++ 中 `(x % MOD + MOD) % MOD` 三件套不能省；Python `%` 恒非负，天然安全。
4. **联合键 vs 单段键**：两段相等时单用 $a$ 似乎可行，但**不同半长的串可能同哈希**（跨长度碰撞），联合键 $a \cdot B^n + b$ 把位数对齐，等价于把 $(len, a)$ 一起编码，更稳。
5. **`len` 的上界**：`2 * len <= n`（等价 `len <= n/2`），写 `len < n/2` 会漏掉偶数长度整串（如 `"abab"` 的 `len=2`）。
6. **去重对象是子串不是位置**：`"aaaa"` 中 `"aa"` 出现 3 次，答案只计 1 次——靠集合天然去重；若误按「命中次数」计数会得到 4。
7. **`n = 1`**：任何 echo 需要 $|t| \ge 2$，返回 0；循环上界自动为空，无需特判。
8. **性能：Python 慢在三重属性访问**：把 `h`、`pw` 局部化、`sub_hash` 内联（或用循环内直接算）能再省常数；本题 $n=2000$ 规模下均可通过。
