# LeetCode 移山所需的最少秒数 题解

## 1. 题目概述

- **标题 / 题号**：移山所需的最少秒数（#3296，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-seconds-to-make-mountain-height-zero/
- **来源**：LeetCode 第 416 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、数学、二分查找、堆（优先队列）

**题意**：给定山的高度 `mountainHeight` 与工人数组 `workerTimes`。工人 $i$ 挖第 $x$ 个单位高度需要 $workerTimes_i \cdot x$ 秒（第 1 单位 $w_i$ 秒、第 2 单位 $2w_i$ 秒、……），且只能按顺序连续挖。所有工人**同时开工**，总耗时为各工人耗时的**最大值**。求把山挖到 0 的最少秒数。

**约束**：

- `1 <= mountainHeight <= 10^5`
- `1 <= workerTimes.length <= 10^4`
- `1 <= workerTimes[i] <= 10^6`

## 2. 示例

**示例 1**

```text
输入：mountainHeight = 4, workerTimes = [2,1,1]
输出：3
解释：工人 0 挖 1 单位（2 秒）；工人 1 挖 2 单位（1+2=3 秒）；工人 2 挖 1 单位（1 秒）。max = 3。
```

**示例 2**

```text
输入：mountainHeight = 10, workerTimes = [3,2,2,4]
输出：12
解释：四个工人分别挖 2, 3, 3, 2 单位，耗时 9, 12, 12, 12 秒，max = 12。
```

**示例 3（单工人）**

```text
输入：mountainHeight = 5, workerTimes = [1]
输出：15
解释：唯一工人挖 5 单位：1+2+3+4+5 = 15 秒。
```

## 3. 解题思路

### 3.1 暴力思路

两条朴素路线都走不通：

- **枚举分配方案**：把 $H$ 个单位分给 $n$ 个工人，方案数是组合爆炸级别的，$H=10^5$ 直接排除。
- **从小到大枚举答案 $T$**：逐秒检查「$T$ 秒能否挖平」。$T$ 的上界约 $10^6 \times \frac{10^5 \times (10^5+1)}{2} \approx 5 \times 10^{15}$，线性扫描不可行。

但第二条路线揭示了好消息：**「$T$ 秒能否挖平」是一个关于 $T$ 的单调谓词**——$T$ 越大越可行。这正是**二分答案**的标准信号。

### 3.2 核心观察：二分答案 + 单工人工作量 O(1) 计算

先把单个工人的成本写成闭式：工人 $i$ 连续挖 $x$ 单位的总耗时为等差数列求和

$$w_i \cdot (1 + 2 + \cdots + x) = w_i \cdot \frac{x(x+1)}{2}$$

于是给定总时间预算 $T$，工人 $i$ 最多能挖的单位数 $x_i$ 是**二次不等式** $w_i \cdot \frac{x(x+1)}{2} \le T$ 的最大整数解，用求根公式 $O(1)$ 解出：

$$x_i = \left\lfloor \frac{\sqrt{8T/w_i + 1} - 1}{2} \right\rfloor$$

**可行性判定**：$\sum_i x_i \ge H \iff T$ 秒内能挖平山（工人之间互不干扰，各取各的最大值即可，见 §5 引理 3）。

![核心思路：单个工人的成本台阶与最小化最大值](images/mtn_seconds_cost_stairs.svg)

### 3.3 算法流程

![算法流程：二分总时间 T，每次 O(n) 检查可行性](images/mtn_seconds_binary_search_flow.svg)

1. 二分区间 $[lo, hi]$：$lo = 0$；$hi = w_{\min} \cdot \frac{H(H+1)}{2}$（最快的工人独力挖完整座山，必然可行）
2. 取 $mid$，对每个工人 $O(1)$ 算出预算 $mid$ 内的最大工作量 $x_i$，求和（累加满 $H$ 即提前剪枝返回）
3. $\sum x_i \ge H$ 则 $hi = mid$，否则 $lo = mid + 1$
4. 收敛后 $lo$ 即答案

### 3.4 示例演算

以示例 2（$H=10$，$ws=[3,2,2,4]$）验证可行性在 $T=12$ 处翻转：

| 工人 | 前缀耗时序列 | 12 秒内最大 $x$ | 11 秒内最大 $x$ |
|------|--------------|----------------|-----------------|
| $w=3$ | 3, 9, 18 | 2（$9 \le 12 < 18$） | 2 |
| $w=2$ | 2, 6, 12 | 3（$12 \le 12$） | 2 |
| $w=2$ | 2, 6, 12 | 3 | 2 |
| $w=4$ | 4, 12 | 2（$12 \le 12$） | 1 |
| **合计** | | **$10 \ge H$ ✓** | **$7 < H$ ✗** |

### 3.5 另一等价视角：多重集第 $H$ 小（小根堆做法）

把每个工人的每个**前缀完成时刻** $w_i \cdot \frac{k(k+1)}{2}$（$k \ge 1$）看成多重集 $M$ 中的一个元素，则答案是 $M$ 的**第 $H$ 小元素**（§5 定理）。

用小根堆模拟：堆中每人工人存「再做 1 单位后的完成时刻」，弹 $H$ 次，第 $H$ 次弹出的键即答案，复杂度 $O(H \log n)$。两种做法殊途同归（本页代码以二分为主）。

## 4. 算法细节

1. **上界选取**：$hi = w_{\min} \cdot \frac{H(H+1)}{2}$ 比 $w_{\max}$ 版本更紧，少二分几轮；两者都正确。
2. **整数求根**：$w \cdot \frac{x(x+1)}{2} \le T \iff x(x+1) \le \lfloor 2T/w \rfloor \iff (2x+1)^2 \le 4\lfloor 2T/w \rfloor + 1$。Python 用 `math.isqrt` 精确整数开方，得 $x = (\mathrm{isqrt}(4m+1)-1) // 2$，其中 $m = 2T // w$，全程无浮点误差。
3. **C++ 精度防御**：`4m+1` 可达 $4 \times 10^{16}$，超出 `double` 的 53 位精确整数范围，`floor(sqrt(...))` 可能差 1。用 `sqrtl`（long double）再对结果做 $\pm 1$ 邻域修正，保证精确。
4. **提前剪枝**：`check` 内累加一旦 $\ge H$ 立即返回，避免无意义求和。
5. **溢出**：$hi \approx 5 \times 10^{15}$，中间量 $2T \le 10^{16}$，C++ 必须全程 `long long`。

## 5. 正确性证明

**引理 1（单调性）**：定义 $\mathrm{ok}(T)$ 为「存在分配方案使各工人耗时均 $\le T$ 且总工作量 $\ge H$」。若 $\mathrm{ok}(T)$ 成立，则任意 $T' \ge T$ 也成立。

**证明**：同一方案在更宽的预算下仍然合法。∎

**引理 2（成本刻画）**：工人 $i$ 恰挖 $x$ 单位的耗时为 $w_i \frac{x(x+1)}{2}$。

**证明**：第 $k$ 单位耗时 $w_i k$，求和即得。∎

**引理 3（预算-工作量等价）**：记 $f_i(T) = \max\{x \ge 0 : w_i \frac{x(x+1)}{2} \le T\}$，则 $\mathrm{ok}(T) \iff \sum_i f_i(T) \ge H$。

**证明**：（$\Rightarrow$）合法方案中工人 $i$ 挖 $x_i$ 单位，耗时 $w_i\frac{x_i(x_i+1)}{2} \le T$，故 $x_i \le f_i(T)$，求和即 $\ge H$。（$\Leftarrow$）取 $x_i = f_i(T)$：每个工人耗时 $\le T$，总量 $\sum f_i(T) \ge H$，是合法方案（工人互相独立）。∎

**定理**：答案为多重集 $M = \{\, w_i \cdot \frac{k(k+1)}{2} : i \in [n],\ k \ge 1 \,\}$ 的第 $H$ 小元素 $T^*$，且二分算法返回 $T^*$。

**证明**：对每个 $i$，前缀耗时 $w_i\frac{k(k+1)}{2}$ 随 $k$ 严格递增（$w_i \ge 1$），故 $f_i(T)$ 恰为 $M$ 中属于工人 $i$ 且 $\le T$ 的元素个数，$\sum_i f_i(T)$ 即 $M$ 中 $\le T$ 的元素总数。由引理 3：

$$\mathrm{ok}(T) \iff |\{m \in M : m \le T\}| \ge H \iff T \ge T^*$$

即 $\mathrm{ok}$ 恰在 $[T^*, +\infty)$ 上为真。由引理 1 谓词单调，二分收敛到最小真值 $T^*$。∎

**推论**：小根堆做法每次弹出的键恰为 $M$ 中未弹出的最小元素（各工人的键序列严格递增，堆弹出全局最小），故第 $H$ 次弹出值 $= T^*$，与二分等价。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log T_{\max})$。每轮 `check` 遍历 $n$ 个工人各 $O(1)$；$T_{\max} \approx 5 \times 10^{15}$，$\log_2 \approx 53$ 轮，总计约 $5 \times 10^5$ 次基本运算，轻松通过。
- **空间复杂度**：$O(1)$，仅若干标量（堆做法为 $O(n)$ 存堆，时间 $O(H \log n) \approx 1.4 \times 10^6$，同样能过）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minNumberOfSeconds(int mountainHeight, vector<int>& workerTimes) {
        long long H = mountainHeight;
        long long lo = 0;
        long long hi = (long long)*min_element(workerTimes.begin(), workerTimes.end())
                       * H * (H + 1) / 2;   // 最快工人独力挖完，必然可行
        while (lo < hi) {
            long long mid = lo + (hi - lo) / 2;
            long long done = 0;
            for (int w : workerTimes) {
                long long m = 2 * mid / w;
                long long x = (long long)((sqrtl(4.0L * m + 1) - 1) / 2);
                while ((long long)w * (x + 1) * (x + 2) / 2 <= mid) x++;  // 浮点误差修正
                while (x > 0 && (long long)w * x * (x + 1) / 2 > mid) x--;
                done += x;
                if (done >= H) break;      // 提前剪枝
            }
            if (done >= H) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
};
```

### Python

```python
import math
from typing import List

class Solution:
    def minNumberOfSeconds(self, mountainHeight: int, workerTimes: List[int]) -> int:
        def check(t: int) -> bool:
            done = 0
            for w in workerTimes:
                m = 2 * t // w
                x = (math.isqrt(4 * m + 1) - 1) // 2   # w·x(x+1)/2 <= t 的最大整数 x
                done += x
                if done >= mountainHeight:
                    return True
            return done >= mountainHeight

        lo, hi = 0, min(workerTimes) * mountainHeight * (mountainHeight + 1) // 2
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

等价的小根堆做法（多重集第 $H$ 小）：

```python
import heapq
from typing import List

class Solution:
    def minNumberOfSeconds(self, mountainHeight: int, workerTimes: List[int]) -> int:
        # 堆元素：(再做 1 单位后的完成时刻, w, 下一单位序号 k)
        h = [(w, w, 1) for w in workerTimes]
        heapq.heapify(h)
        ans = 0
        for _ in range(mountainHeight):
            ans, w, k = heapq.heappop(h)          # 弹出全局最早完工的单位
            heapq.heappush(h, (ans + w * (k + 1), w, k + 1))
        return ans
```

## 8. 边界情况与易错点

1. **读题陷阱**：「降低 $x$ 需要 $w \cdot x$ 秒」说的是**第 $x$ 个单位**的耗时，挖 $x$ 单位的总时间是 $w\frac{x(x+1)}{2}$ 而非 $w \cdot x$——误读成后者会导致整体逻辑错误（如示例 3 算成 5 而非 15）。
2. **溢出**：$hi \approx 5 \times 10^{15}$、$2T \le 10^{16}$ 均超 `int` 范围，C++ 全程 `long long`；返回类型本身就是 `long long`，这是出题人的明确提示。
3. **浮点精度**：`4m+1` 可达 $4 \times 10^{16} > 2^{53} \approx 9 \times 10^{15}$，`double` 开方后取整可能差 1。Python 用 `math.isqrt`（精确整数开方）；C++ 用 `sqrtl` 加 $\pm 1$ 修正循环（见参考代码），切勿裸 `sqrt` + `floor`。
4. **单工人**：即二分上界取等的情形，$n=1$ 时答案恰为 $hi$，算法自然覆盖，无需特判。
5. **工人多于山高**：$n > H$ 时部分工人 $x_i = 0$ 闲置，公式天然给出 $x=0$（$T \ge 0$ 恒有 $m \ge 0$、$x \ge 0$），无需特判。
6. **二分模板**：用 $[lo, hi)$ 风格 `lo < hi` + `hi = mid` / `lo = mid + 1`，配合「上界本身可行」的构造，收敛值即最小可行 $T$；若用闭区间模板需小心死循环。
7. **提前剪枝的位置**：`done >= H` 的判断要放在累加循环**内部**，放在外面最坏仍要加满 $10^4$ 项（不致超时，但白白多做功）。

**延伸思考**：

- **凸成本推广**：二分答案框架不依赖等差成本，只要「给定预算 $T$，单人最大工作量可 $O(1)$ 或 $O(\log)$ 求出」即可——把单位成本换成任意递增凸序列 $c_1 \le c_2 \le \cdots$ 结论照旧（§5 证明只用到前缀和递增）。
- **在线多次询问**：若要回答多个不同 $H$ 的询问，可离线把堆做法的弹出序列存下来回答任意前缀询问；或对若干组 $(w_i, k)$ 的前缀完成时刻做归并 + 二分第 $k$ 小。
- **为什么贪心分配单位不行**：朴素「每次把下一单位分给累计耗时最小的工人」若按边际成本比较会在平手时出错（如 $ws=[1,3], H=3$，边际成本 3 既可给工人 1 也可给工人 2，给后者才有最优解 3）；按**完成时刻**建堆则与多重集视角严格等价，正确性由 §5 推论保证。
