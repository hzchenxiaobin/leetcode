# LeetCode 统计重新排列后包含另一个字符串的子字符串数目 II 题解

## 1. 题目概述

- **标题 / 题号**：统计重新排列后包含另一个字符串的子字符串数目 II（#3298，hard）
- **链接**：https://leetcode.cn/problems/count-substrings-that-can-be-rearranged-to-contain-a-string-ii/
- **来源**：LeetCode 第 416 场周赛 Q4
- **难度**：困难
- **标签**：哈希表、字符串、滑动窗口

**题意**：给定字符串 `word1` 和 `word2`。若字符串 $x$ 重新排列后，`word2` 恰好是重排结果的**前缀**，则称 $x$ **合法**。统计 `word1` 中合法**子字符串**的数目。题意与判定同场 Q3（#3297）完全相同，**变的只有资源预算**：$n$ 放大十倍到 $10^6$，且题面罕见地写明——**内存限制比其他题目更小，必须实现线性复杂度的解法**。

**约束**：

- `1 <= word1.length <= 10^6`
- `1 <= word2.length <= 10^4`
- `word1` 和 `word2` 都只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：word1 = "bcca", word2 = "abc"
输出：1
解释：唯一合法的子字符串是 "bcca"，重排为 "abcc" 后 "abc" 是它的前缀。
```

**示例 2**

```text
输入：word1 = "abcabc", word2 = "abc"
输出：10
解释：除了长度为 1 和 2 的子字符串（共 21 个中的 10 个）之外全部合法。
```

**示例 3（word2 需要重复字符）**

```text
输入：word1 = "abcabc", word2 = "aaabc"
输出：0
解释：任何子串中 'a' 至多出现 2 次，凑不出 "aaabc" 需要的 3 个 'a'。
```

## 3. 解题思路

### 3.1 暴力出局与做法审计

子串总数达 $\frac{n(n+1)}{2} \approx 5 \times 10^{11}$，枚举彻底出局。合法性的刻画与双指针框架，同场 Q3 题解已完整给出（多重集包含 + 固定右端点数左边）。Q4 真正的考点是题面那句加粗警告：**内存收紧、必须线性**——它等于预告了几种「Q3 能过、Q4 倒下」的写法。设 $n = 10^6$、$\Sigma = 26$，对三类典型做法做预算审计：

| 做法 | 时间 | 额外内存 | $n = 10^6$ 下的命运 |
|------|------|----------|---------------------|
| A. 逐字符前缀计数 + 对每个 $r$ 二分最左合法 $l$ | $O(\Sigma n \log n) \approx 5 \times 10^8$ | $O(\Sigma n) \approx 104\,\mathrm{MB}$ | 超时又超内存，双双阵亡 |
| B. 双指针 + 每步全量比较 26 个计数 | $O(\Sigma n) \approx 10^7 \sim 10^8$ | $O(\Sigma)$ | C++ 或许侥幸；Python 内层比较 $10^7$ 次以上必超时；且严格说不是线性 |
| C. 双指针 + `less` 计数器 | $O(n + m + \Sigma)$ | $O(\Sigma) \approx 200\,\mathrm{B}$ | ✓ 线性时间 + 与 $n$ 无关的内存 |

![Q3 到 Q4 的规模放大与三类做法的资源审计](images/wc416_q4_scale_memory_wall.svg)

> 💡 做法 B → C 的关键一步：**一次只加/删一个字符，至多让一种字符的计数跨越「够 / 不够」的分界**。把「26 个计数逐个比」换成「维护还欠几种字符」的 `less`，每步判定就从 $O(\Sigma)$ 降到 $O(1)$——这差不多是本题标为困难的全部技术含量。

### 3.2 核心观察：合法 ⟺ 多重集包含（承自 Q3）

**引理 1（等价刻画）**：子串 $x$ 合法 $\iff$ 对每种字符 $c$ 都有 $\mathrm{cnt}_x[c] \ge \mathrm{need}[c]$，其中 $\mathrm{need}$ 是 `word2` 的字符计数。

「重排后是前缀」与顺序无关，只与每种字符的**个数下限**有关——把 `word2` 需要的字符全部摆最前、其余随便排即可。这是**至少型**条件：扩窗永不破坏合法性。于是以 $r$ 结尾的合法左端点是一段前缀 $[0, l_{\max}(r)]$，且 $l_{\max}(r)$ 单调不减（引理 2 与完整推导见 §5 及同场 Q3 题解）。

### 3.3 算法流程：单趟扫描

![线性解法流程：入窗、弹到失合法、ans 累加 l](images/wc416_q4_algorithm_flow.svg)

1. 统计 `need[26]`，`less` = `need` 中非零项个数（尚未达标的字符种数），`l = 0`，`ans = 0`；
2. $r$ 从左到右扫描：`word1[r]` 入窗，若恰好使 `cnt[c]` 追平 `need[c]` 则 `less--`；
3. **当 `less == 0` 时不断弹出 `word1[l]`**（删前判：若 `cnt[d] == need[d]` 这一弹会跌破，则 `less++`），弹到刚破坏合法性为止；
4. `ans += l`——多弹一步使 $l$ 恰等于以 $r$ 结尾的合法左端点个数；
5. $r$ 右移，$l$ 永不回退。

整个流程靠一条**不变量**兜底（定理见 §5）：每轮 while 结束时，**要么 $l = 0$ 且 $[0, r]$ 不合法，要么 $[l-1, r]$ 合法且 $[l, r]$ 不合法**。它同时覆盖两种情况：本轮窗口从未合法（贡献 0），以及 while 一次未执行（上一轮的 $l$ 继续有效）。

### 3.4 示例演算

取 `word1 = "abcba"`、`word2 = "abc"`（$\mathrm{need}$：a×1、b×1、c×1，`less` 初值 3）：

| $r$ | 入窗 | less 变化 | while 弹出（弹到失合法） | 循环后 $l$ | 贡献 | ans 累计 |
|-----|------|-----------|--------------------------|-----------|------|----------|
| 0 | a | 3 → 2 | —（窗口不合法） | 0 | 0 | 0 |
| 1 | b | 2 → 1 | — | 0 | 0 | 0 |
| 2 | c | 1 → 0 ✓ | 弹 a（跌破） | 1 | 1 | 1 |
| 3 | b | 1（富余，不动） | —（[1,3] 仍缺 a） | 1 | 1 | 2 |
| 4 | a | 1 → 0 ✓ | 弹 b（富余）、c（跌破） | 3 | 3 | 5 |

![abcba 演算：不变量兜底与连弹两步的细节](images/wc416_q4_walkthrough.svg)

两个细节值得盯着看：

- **$r = 3$**：入窗的 b 已富余，`less` 不动，while 一次都没执行——但 $[l-1, r] = [0, 3]$ 依旧合法（它包含 $[0,2]$），`ans += l = 1` 恰好只计入 "abcb"。不变量代替了特判。
- **$r = 4$**：弹出先走一个**富余**的 b（`less` 不变、循环继续），再弹 c 才跌破——while 的条件是「还合法就继续弹」，富余弹出正是它自动跳过冗余前缀的方式。

答案 $5$：合法子串为 `abc`（$r=2$）、`abcb`（$r=3$）、`cba`、`bcba`、`abcba`（$r=4$）。

### 3.5 $n = 10^6$ 的工程细节

- **C++**：答案上限 $\approx 5 \times 10^{11}$ 爆 `int`，必须 `long long`（接口返回类型本身就是提示）；计数用两个 26 槽栈数组，**不要**换成 `unordered_map`（更慢也更费内存）；循环里不要 `substr` / 不要构造临时串——单趟下标访问即可，$10^6$ 毫无压力。
- **Python**：主要开销是 $10^6$ 轮纯 Python 循环。`word1.encode()` 后直接迭代 bytes 拿到 ASCII 码，省掉 $10^6$ 次 `ord()`；`need`/`cnt`/`less` 保持局部变量访问。while 的总弹出次数 $\le n$ 由均摊保证，最坏也只是多一趟循环。
- **任何 $O(n)$ 辅助数组**（`l_max` 表、前缀计数矩阵）都会撞上收紧的内存墙——写代码前先想清楚每个数组的量级。

## 4. 算法细节

1. **`less` 初值**是 `word2` 中**不同字符的种数**（不是长度）：`"aaabc"` 的初值是 3 不是 5。
2. **跨越等号才更新**：入窗判 `cnt[c] == need[c]`（恰好追平），出窗**删前**判 `cnt[d] == need[d]`（再删就跌破）。富余字符的进出不触碰 `less`，每个计数每跨越一次等号只更新一次。
3. **弹到失合法、多弹的不还**：while 出口 `less > 0`，此时 $[l-1, r]$ 合法、$[l, r]$ 不合法，`ans += l` 既不用 `+1`、也不用特判「本轮从未合法」——不变量已兜底（见 §3.4 的 $r=3$）。
4. **先缩窗后计数**：`ans += l` 必须在 while 之后，否则同一 $r$ 重复累加。
5. **内存清单**：`need[26]` + `cnt[26]` 共 52 个 `int` 加 `l` / `less` / `ans` 若干标量，合计约 200 余字节，**与 $n$ 完全无关**——这正是题面「内存限制更小」想逼出的形态。
6. **`m > n` 或 `word2` 含 `word1` 没有的字符**：答案 0，无需特判（多重集包含天然蕴含长度够、字符够）。

## 5. 正确性证明

以下给出紧凑证明，逐步展开的详版见同场 Q3 题解 §5。

**引理 1（多重集刻画）**：$x$ 重排后以 `word2` 为前缀 $\iff$ 对每种字符 $c$ 有 $\mathrm{cnt}_x[c] \ge \mathrm{need}[c]$。

**证明**：（$\Rightarrow$）重排不改变字符多重集，而前 $m$ 位（$m = |\text{word2}|$）恰好消耗 `word2` 的全部字符，故 $x$ 的多重集包含 `word2` 的多重集。（$\Leftarrow$）条件保证能从 $x$ 中取出 `word2` 所需的全部字符依次排在最前，其余字符任意排在后面，得到以 `word2` 为前缀的重排。∎

**引理 2（左端点前缀性与单调性）**：若 $[l, r]$ 合法，则任意 $l' \le l$、$r' \ge r$ 的 $[l', r']$ 合法；从而以 $r$ 结尾的合法左端点集合或为空、或恰为 $[0, l_{\max}(r)]$，且 $l_{\max}(r)$ 随 $r$ 单调不减。

**证明**：扩窗只增不减逐字符计数，由引理 1 即得；空集对应 $[0, r]$ 不合法的情形。∎

**定理（计数正确性与线性性）**：设不变量「每轮 while 结束时，要么 $l = 0$ 且 $[0, r]$ 不合法，要么 $[l-1, r]$ 合法且 $[l, r]$ 不合法」。则每轮 `ans += l` 恰等于以 $r$ 结尾的合法子串数；算法总时间 $O(n + m + \Sigma)$、额外空间 $O(\Sigma)$。

**证明**：先证不变量归纳成立。while 出口 `less > 0` 给出 $[l, r]$ 不合法；若本轮 while 执行过，最后一次弹出的前一状态满足 `less == 0`，即 $[l-1, r]$ 合法；若未执行，则沿用上一轮的 $l$——上一轮已有 $[l-1, r-1]$ 合法（或 $l = 0$），而 $[l-1, r] \supseteq [l-1, r-1]$ 由引理 2 仍合法。再证计数：$l \ge 1$ 时 $l_{\max}(r) = l - 1$，合法左端点 $0..l-1$ 共 $l$ 个，`ans += l` 正确；$l = 0$ 时以 $r$ 结尾的合法子串不存在，贡献 $0 = l$ 亦正确。最后证线性：$r$ 恰走 $n$ 步；由引理 2，$l$ 单调不减且 $\le n$，两指针合计 $\le 2n$ 次移动，每次 $O(1)$ 维护 `cnt` 与 `less`；`need` 统计 $O(m + \Sigma)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m + \Sigma)$，其中 $n = 10^6$、$m = 10^4$、$\Sigma = 26$。左右指针各走至多 $n$ 步，每步 $O(1)$；`less` 把每步合法性判定从 $O(\Sigma)$ 压到 $O(1)$，是线性的最后一块拼图。
- **空间复杂度**：$O(\Sigma)$——两个 26 槽计数数组加常数个标量，约 200 字节，**与 $n$ 无关**。任何 $O(n)$ 及以上的辅助数组（`l_max` 表、逐字符前缀矩阵）都会撞上本题收紧的内存墙。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long validSubstringCount(string word1, string word2) {
        int need[26] = {0}, cnt[26] = {0};
        for (char c : word2) need[c - 'a']++;
        int less = 0;
        for (int c = 0; c < 26; c++) less += (need[c] > 0);   // 初始：所需字符全部欠账
        long long ans = 0;
        int l = 0, n = word1.size();
        for (int r = 0; r < n; r++) {
            int c = word1[r] - 'a';
            cnt[c]++;
            if (need[c] > 0 && cnt[c] == need[c]) less--;     // 恰好追平等号
            while (less == 0) {                               // 合法就继续弹，弹到失合法
                int d = word1[l] - 'a';
                if (need[d] > 0 && cnt[d] == need[d]) less++; // 这一弹会跌破等号
                cnt[d]--;
                l++;
            }
            ans += l;   // 左端点 0..l-1 共 l 个合法
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def validSubstringCount(self, word1: str, word2: str) -> int:
        s = word1.encode()                        # 迭代 bytes 直接拿 ASCII 码，省掉 10^6 次 ord()
        need = [0] * 26
        for b in word2.encode():
            need[b - 97] += 1
        less = 26 - need.count(0)                 # word2 中不同字符的种数
        cnt = [0] * 26
        ans = 0
        l = 0
        for b in s:
            c = b - 97
            cnt[c] += 1
            if need[c] and cnt[c] == need[c]:     # 恰好追平等号
                less -= 1
            while less == 0:                      # 合法就继续弹，弹到失合法
                d = s[l] - 97
                if need[d] and cnt[d] == need[d]: # 这一弹会跌破等号
                    less += 1
                cnt[d] -= 1
                l += 1
            ans += l
        return ans
```

## 8. 边界情况与易错点

1. **答案爆 `int`**：上限 $\frac{10^6 \times (10^6+1)}{2} \approx 5 \times 10^{11} > 2^{31}-1$，C++ 必须 `long long`。注意这**不是 II 版新增的坑**——Q3 的 $10^5$ 规模就已超过 `int` 上限。
2. **撞内存墙的写法**：逐字符前缀计数（$O(\Sigma n)$ 个 int）、`l_max` 数组、`unordered_map` 逐位计数都可能 MLE。题面已预警，任何辅助数组都要先审量级。
3. **`less` 初值是种数不是长度**：`"aaabc"` → 3 不是 5。
4. **跨越等号才更新 `less`**：入窗判 `cnt[c] == need[c]`、出窗删**前**判 `cnt[d] == need[d]`，写成 `>=` 或删后再判都会算错欠账。
5. **while 弹到失合法才停**：`ans += l` 而非 `l + 1`，也别在 while 内部累加；while 可能连续弹掉多个**富余**字符（见 §3.4 的 $r=4$），这是正常行为。
6. **Python 性能**：别在循环里做 26 长度列表的全量比较（$O(\Sigma n)$ 必超时）；用 bytes 迭代 + 局部变量。
7. **`m > n` / `word2` 含 `word1` 没有的字符**：答案 0，算法无需特判。
8. **别套定长异位词模板**（438 那套）：合法子串长度任意，本质约束是「计数下限」。
