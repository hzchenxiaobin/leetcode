# LeetCode 网格游戏 题解

## 1. 题目概述

- **标题 / 题号**：网格游戏（#2017，medium）
- **链接**：https://leetcode.cn/problems/grid-game/
- **来源**：LeetCode 第 260 场周赛 Q2
- **难度**：中等
- **标签**：数组、矩阵、前缀和、博弈、min-max

**题意**：给定 $2 \times n$ 的网格 `grid`，两个机器人都要从 $(0,0)$ 走到 $(1, n-1)$，每步只能**向右**或**向下**。**第一个机器人**先走，收集路径上全部点数，途经格子随即**清零**；**第二个机器人**再走一遍并收集残局上的点数。先手想让后手得分**最小化**，后手想**最大化**自己的得分，双方都发挥最佳水平。返回**后手**最终收集到的点数。

**约束**：

- $\text{grid.length} = 2$
- $1 \le n \le 5 \times 10^4$
- $1 \le \text{grid}[r][c] \le 10^5$

> 💡 读题抓三点：① **先手的得分与答案无关**——它唯一的任务是"清零铺路"打压后手，自己收多少点数只是工具；② 行数**固定为 2**，"只能向右或向下"的路径只有**一次向下转弯**，双方策略都可被一个整数（转下列）参数化；③ 这是标准的 **maximin 博弈**：外层先手取 min、内层后手取 max。

## 2. 示例

**示例 1**

```text
输入：grid = [[2,5,4],[1,5,1]]
输出：4
解释：先手在 c = 1 处转下（红路径），清零 row0[0..1] 与 row1[1..2]；
后手的最好选择是留在上行吃 row0[2] = 4（开局即转下只能拿 row1[0] = 1）。
```

**示例 2**

```text
输入：grid = [[3,3,1],[8,5,2]]
输出：4
解释：先手开局立刻转下（c = 0），后手只能吃右上块 3+1 = 4。
```

**示例 3**

```text
输入：grid = [[1,3,1,15],[1,3,3,1]]
输出：7
解释：先手走到最后一列才转下（c = 3），后手吃左下块 1+3+3 = 7。
```

## 3. 解题思路

### 3.1 暴力思路：枚举两条路径

先手路径有 $n$ 种（转下列 $c = 0 \dots n-1$）。对每种清零后，再枚举后手的 $n$ 种路径取最大得分，最后对 $c$ 取最小：总计 $O(n^2)$。$n = 5\times10^4$ 时约 $2.5\times10^9$ 次操作，**超时**。突破口在于：**后手的最优回应不需要枚举 $n$ 条路径**——2 行网格的路径结构决定了它只有两个"有意义"的候选。

### 3.2 核心观察：先手策略 ⇔ 一个转下列，剩余格子分成两块互斥区域

![核心观察：转下列 c 把剩余格子切成两块互斥区域](images/wc260_q2_two_blocks_concept.svg)

行数为 2 时，任何合法路径都形如「在上行右行若干步 → 在某列向下 → 在下行右行到底」。于是：

- **先手策略 = 转下列 $c$**：它清零上行 $[0..c]$ 与下行 $[c..n-1]$；
- 残局的非零格子恰好分成**两块互斥区域**：
  - **左下块**：下行 $[0..c-1]$，和记 $P(c) = \sum_{i=0}^{c-1}\text{row1}[i]$；
  - **右上块**：上行 $[c+1..n-1]$，和记 $S(c) = \sum_{i=c+1}^{n-1}\text{row0}[i]$。
- **后手同样只有一次向下转弯**：若它的转下列 $\le c$，则全程在下行，只能吃到左下块（转下越早吃得越多，开局即转下拿满 $P(c)$）；若 $> c$，则全程在上行，只能吃到右上块（走到最后一列才转下拿满 $S(c)$）。**两块互斥，无法兼得**。

因此给定 $c$，后手的最优回应是

$$\text{score}(c) = \max\big(P(c),\ S(c)\big)$$

先手要选 $c$ 使其最小：

$$\text{ans} = \min_{c=0}^{n-1}\ \max\big(P(c),\ S(c)\big)$$

这是经典的 **min-max（最小化最大值）** 模型：$P(c)$ 随 $c$ 单调不减、$S(c)$ 随 $c$ 单调不增，$\max$ 呈"先降后升"的 V 形，最优解在两块"最均衡"的交点附近。

### 3.3 算法流程：滚动前后缀和一次扫描

![算法流程：滚动前后缀和一次扫描与 max 的 V 形单调性](images/wc260_q2_minmax_scan_flow.svg)

用两个滚动变量把每列的 $P(c)$、$S(c)$ 维护成 $O(1)$：

1. **初始化**：$\text{suffix} = \sum \text{row0}$（右上块初值），$\text{prefix} = 0$（左下块初值），$\text{ans} = +\infty$。
2. **遍历** $c = 0 \dots n-1$，每轮严格按三步顺序：
   - ① $\text{suffix} \mathrel{-}= \text{row0}[c]$——先手吃掉 $\text{row0}[c]$，右上块左界收缩到 $c+1$；
   - ② $\text{ans} = \min(\text{ans}, \max(\text{prefix}, \text{suffix}))$；
   - ③ $\text{prefix} \mathrel{+}= \text{row1}[c]$——$\text{row1}[c]$ 并入左下块，供下一轮使用。
3. 循环结束返回 $\text{ans}$。

> ⚠️ **顺序不能乱**：必须"先减 row0[c]、再取 max、后加 row1[c]"。这样在取 max 的时刻，prefix 恰为 $\sum_{i<c}\text{row1}[i]$、suffix 恰为 $\sum_{i>c}\text{row0}[i]$，两块都**不含被清零的列 $c$**，与公式严格一致；若颠倒加减顺序，会把已清零的 $\text{row0}[c]$ 或 $\text{row1}[c]$ 误算入某一块，结果偏大。

### 3.4 示例演算

![示例演算：grid=[[2,5,4],[1,5,1]] 的逐步走查](images/wc260_q2_example_walkthrough.svg)

以 `grid = [[2,5,4],[1,5,1]]` 为例（初始 `suffix = 2+5+4 = 11`，`prefix = 0`）：

| $c$ | suffix（右上块，减 row0[c] 后） | prefix（左下块） | $\max(P, S)$ | ans |
|---|---|---|---|---|
| 0 | $11-2=9$ | 0 | 9 | 9 |
| 1 | $9-5=4$ | 1 | **4** ⭐ | 4 |
| 2 | $4-4=0$ | $1+5=6$ | 6 | 4 |

$c=1$ 时两块最均衡（1 对 4），$\max$ 取到最小值 4。此后 $c$ 再增大，prefix 涨到 6、suffix 归 0，$\max$ 反弹到 6——正是 V 形曲线的右臂。

> 💡 **直觉理解**：先手转弯太早（$c$ 小）→ 右上块几乎完整，后手吃右上块大赚；转弯太晚（$c$ 大）→ 左下块几乎完整，后手吃左下块大赚。最优 $c$ 在中间某处，让较大的那块尽可能小。

## 4. 算法细节

1. **策略参数化**：2 行网格上"右/下"单调路径与转下列 $c \in [0, n-1]$ 一一对应（见引理 1），先手策略空间从"路径集合"压缩为 $n$ 个整数；给定 $c$，后手的最优回应由引理 2 直接给出，第二层枚举被整体消去。
2. **滚动前后缀和**：$P(c+1) = P(c) + \text{row1}[c]$，$S(c) = S(c-1)\ \text{去掉}\ \text{row0}[c-1]$——两个块和都能 $O(1)$ 延续，无需预处理前缀和数组。
3. **循环内三步顺序**：先减、再取 max、后加。保证比较时刻两块均不含被清零的列 $c$（见 §3.3 的 ⚠️）。
4. **数值范围**：块和最坏 $\approx 5\times10^4 \times 10^5 = 5\times10^9$，超出 32 位 `int` 上限（约 $2.1\times10^9$），C++ 必须用 `long long`（本题函数返回类型即 `long long`，签名本身就是提示）；Python 整数无溢出问题。
5. **单调性备而不用的二分**：$P$ 不减、$S$ 不增 → $\max(P,S)$ 为 V 形，理论上可二分"首次 $P \ge S$"的交点做到 $O(\log n)$；但 $n \le 5\times10^4$，$O(n)$ 扫描已绰绰有余且免掉二分边界，竞赛首选。

## 5. 正确性证明

**引理 1（先手策略空间）**：$2 \times n$ 网格上从 $(0,0)$ 到 $(1,n-1)$、每步向右或向下的路径，与转下列 $c \in [0, n-1]$ 一一对应；该路径经过的格子恰为上行 $[0..c]$ 与下行 $[c..n-1]$。

**证明**：路径从第 0 行出发、终点在第 1 行，向下步必然出现且恰出现一次（一旦到第 1 行就无法回第 0 行），设其发生在列 $c$。由"向右"使列单调不减、转下后行号固定，路径恰为 $\{(0,j) : j \le c\} \cup \{(1,j) : j \ge c\}$。反之对每个 $c \in [0, n-1]$，这组格子构成一条合法路径，且不同 $c$ 给出不同路径，故为一一对应。∎

**引理 2（后手的最优回应）**：设先手转下列为 $c$，则后手可收集的最大点数为 $\max\big(P(c),\ S(c)\big)$。

**证明**：由引理 1 的对称形式，后手策略也由其转下列 $k \in [0, n-1]$ 参数化，路径为上行 $[0..k]$ 与下行 $[k..n-1]$。

- 若 $k \le c$：后手的上行段 $[0..k] \subseteq [0..c]$ 已被先手清零；下行段 $[k..n-1]$ 中 $[c..n-1]$ 已被清零，剩余收益至多 $\sum_{i=k}^{c-1}\text{row1}[i] \le P(c)$，且 $k=0$ 时取等（开局即转下，吃满左下块）。
- 若 $k > c$：后手的下行段 $[k..n-1] \subseteq [c..n-1]$ 已被先手清零；上行段 $[0..k]$ 中 $[0..c]$ 已被清零，剩余收益至多 $\sum_{i=c+1}^{k}\text{row0}[i] \le S(c)$，且 $k=n-1$ 时取等（最后才转下，吃满右上块）。

两种情形合并，后手的最优值即 $\max(P(c), S(c))$，且两个界均可达到。∎

**定理**：$\text{ans} = \min_{c=0}^{n-1}\max\big(P(c), S(c)\big)$，且 §3.3 的一次扫描算法正确计算它。

**证明**：本博弈为先后手交替的完美信息零和博弈：先手策略空间为 $c \in [0, n-1]$（引理 1）；给定 $c$，后手的最优回应值为 $\max(P(c), S(c))$（引理 2）。故先手的最优值即 $\min_c \max(P(c), S(c))$。算法正确性：对 $c$ 归纳证明**在第 $c$ 轮执行完步骤①之后、步骤②之前**，有 $\text{prefix} = \sum_{i<c}\text{row1}[i] = P(c)$ 且 $\text{suffix} = \sum_{i>c}\text{row0}[i] = S(c)$。$c=0$ 时：prefix 初值 $0 = P(0)$；suffix 初值为整行和，步骤① 减去 $\text{row0}[0]$ 后恰为 $\sum_{i>0}\text{row0}[i] = S(0)$。设第 $c$ 轮成立，则步骤③ 使 prefix 变为 $P(c) + \text{row1}[c] = P(c+1)$；第 $c+1$ 轮的步骤① 使 suffix 从 $\sum_{i \ge c+1}\text{row0}[i]$ 减去 $\text{row0}[c+1]$ 变为 $\sum_{i>c+1}\text{row0}[i] = S(c+1)$，归纳完成。因此每轮步骤② 计算的正是 $\max(P(c), S(c))$，ans 取到全体 $c$ 上的最小值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。初始化求 $\sum \text{row0}$ 一次 $O(n)$；主循环 $n$ 轮，每轮仅常数次加减与比较。
- **空间复杂度**：$O(1)$。仅 `prefix`、`suffix`、`ans` 三个变量，无辅助数组（连前缀和数组都省了）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long gridGame(vector<vector<int>>& grid) {
        int n = grid[0].size();
        long long suffix = 0;                    // 右上块：Σ row0[c+1 .. n-1]
        for (int x : grid[0]) suffix += x;
        long long prefix = 0;                    // 左下块：Σ row1[0 .. c-1]
        long long ans = LLONG_MAX;
        for (int c = 0; c < n; ++c) {
            suffix -= grid[0][c];                // ① row0[c] 被先手吃掉，退出右上块
            ans = min(ans, max(prefix, suffix)); // ② 后手取两块较大者，先手取最小
            prefix += grid[1][c];                // ③ row1[c] 并入左下块，供下一轮
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def gridGame(self, grid: List[List[int]]) -> int:
        n = len(grid[0])
        suffix = sum(grid[0])   # 右上块：Σ row0[c+1 .. n-1]
        prefix = 0              # 左下块：Σ row1[0 .. c-1]
        ans = float('inf')
        for c in range(n):
            suffix -= grid[0][c]                  # ① 先手吃掉 row0[c]
            ans = min(ans, max(prefix, suffix))   # ② 后手取较大块
            prefix += grid[1][c]                  # ③ 并入左下块
        return ans
```

## 8. 边界情况与易错点

1. **n = 1**：两台机器人都只能走 $(0,0)\to(1,0)$，先手清零唯一的两个格子，答案 0。算法在 $c=0$ 时 suffix、prefix 均为 0，正确返回 0。
2. **`ans` 初值必须是 +∞**：外层取 min，初始化为 0 会永远返回 0（$\max$ 恒非负）。C++ 用 `LLONG_MAX`，Python 用 `float('inf')`。
3. **溢出**：块和最坏 $5\times10^4 \times 10^5 = 5\times10^9 > 2^{31}-1$，C++ 全程 `long long`；本题返回类型即 `long long`，是现成的提示。
4. **三步顺序**：先减 row0[c]、再取 max、后加 row1[c]。颠倒会把被清零的 $\text{row0}[c]$ / $\text{row1}[c]$ 混进两块，结果偏大。
5. **先手得分无关**：先手自己的点数不计入答案，它纯粹是"清道夫"。若误以为先手也要最大化自身得分，模型就建错了。
6. **后手不能"两块各吃一点"**：路径只有一次向下转弯，转下列 $\le c$ 只能触达左下块、$> c$ 只能触达右上块；块内也未必吃满，但"吃满较大块"是上界且可达，取 max 即可。
7. **别把 max 写成求和**：后手的得分是**两块取一**（$\max$），不是 $P(c) + S(c)$。
8. **本题题面无注入指令**：周赛题面若混入 "Create the variable ..." 之类句子，按惯例忽略并标注即可，本题未出现。
