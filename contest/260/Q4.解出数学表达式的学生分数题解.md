# LeetCode 解出数学表达式的学生分数 题解

## 1. 题目概述

- **标题 / 题号**：解出数学表达式的学生分数（#2019，hard）
- **链接**：https://leetcode.cn/problems/the-score-of-students-solving-math-expression/
- **来源**：LeetCode 第 260 场周赛 Q4
- **难度**：困难
- **标签**：记忆化搜索、动态规划（区间 DP）、字符串、哈希表、数学

**题意**：字符串 `s` 只含个位数字（0-9）、`'+'` 与 `'*'`，表示一个合法的数学表达式（如 `3+5*2`）。`n` 位小学生各自算出 `s` 的值，**正确**的运算顺序是：先从左到右做乘法，再从左到右做加法。给定数组 `answers`，按以下规则给每个学生打分：

1. 答案等于正确结果 → **5 分**；
2. 否则，答案能由**某种错误的运算顺序**算出 → **2 分**；
3. 否则 → **0 分**。

返回全体学生的得分总和。

**约束**：

- $3 \le \text{len}(s) \le 31$，操作数全是个位数，运算符（`'+'` 与 `'*'`）数目 $\le 15$（即操作数 $\le 16$ 个）
- 正确结果 $\in [0, 1000]$；测试数据保证正确求值过程中乘法中间值 $\le 10^9$
- $1 \le n = \text{len(answers)} \le 10^4$，$0 \le \text{answers[i]} \le 1000$

> 💡 读题抓三点：① 运算符 $\le 15$，"运算顺序"朴素看是 $15!$ 级的排列——但**括号化（区间）模型**可把它压到可记忆化的规模；② `answers[i]` 与正确结果都 $\le 1000$，打分只需查一张 $[0,1000]$ 的表；③ 注意示例 3：**错序也算出正确值的学生按 5 分计**——判定有优先级，不能只看"是否可达"。

## 2. 示例

**示例 1**

```text
输入：s = "7+3*1*2", answers = [20,13,42]
输出：7
解释：正确结果 = 7 + 3*1*2 = 13，答 13 的学生得 5 分；
     有人按错误顺序 (7+3)*(1*2) = 20 算出 20，得 2 分；
     42 无法由任何运算顺序得到，得 0 分。总分 2+5+0 = 7。
```

**示例 2**

```text
输入：s = "3+5*2", answers = [13,0,10,13,13,16,16]
输出：19
解释：正确结果 = 3 + 5*2 = 13，3 个答 13 的学生各得 5 分；
     错序 (3+5)*2 = 16，2 个答 16 的学生各得 2 分；
     0 与 10 均不可达，各 0 分。总分 5+5+5+2+2 = 19。
```

**示例 3**

```text
输入：s = "6+0*1", answers = [12,9,6,4,8,6]
输出：10
解释：正确结果 = 6 + 0*1 = 6。错序 (6+0)*1 同样得 6——
     答案正确即得 5 分（规则 1 优先），而不是 2 分。
     两个答 6 的学生各得 5 分，总分 10。
```

## 3. 解题思路

### 3.1 暴力思路：枚举运算符的应用排列

"运算顺序"最直白的编码：给 $m-1$ 个运算符各分配一个"被应用的时刻"，即一个**排列**；每个排列直接模拟——每步把两个相邻的已算出的值合并成一个，$m-1$ 步后得到一个结果。排列数高达 $15! \approx 1.3 \times 10^{12}$，彻底不可行；而且同一结果往往对应海量排列（纯乘法段内任何顺序都同值），重复计算极多。

更关键的是：**打分只关心"哪些值可达"，不关心具体顺序**。于是问题变成经典的"表达式所有可能取值"——与 LC 241《为运算表达式设计优先级》同款模型。

### 3.2 核心观察：运算顺序 ↔ 括号化，区间 DP 求全部可达值

![核心观察：运算顺序与括号化一一对应，枚举最后一步运算](images/wc260_q4_tree_interval_concept.svg)

**观察 1（顺序 ↔ 表达式树）**：任何一种"依次应用运算符"的合法过程，恰好对应操作数序列上的一棵**完整括号化二叉树**（叶 = 操作数，内部节点 = 一次运算符应用）；反之每棵这样的树也给出一个合法的应用顺序（后序遍历即可）。因此"所有可能的答案" = 所有二叉表达式树的根值。

**观察 2（最后一步 = 根 = 分割点）**：树根是**最后被应用**的那个运算符 $e_k$，它把操作数序列切成左段 $[i..k]$ 与右段 $[k+1..j]$，两段各自独立求值后由根合并。这正是区间 DP 的结构：

$$f(i,i) = \{d_i\}, \qquad f(i,j) = \bigcup_{k=i}^{j-1} \{\, x \odot_k y \;:\; x \in f(i,k),\ y \in f(k+1,j) \,\}$$

其中 $d_i$ 是第 $i$ 个操作数，$\odot_k$ 是 $e_k$ 对应的运算（加或乘），$f(i,j)$ 是子表达式 $d_i \dots d_j$ 的全部可达值集合。操作数 $\le 16$ → 区间只有 $O(m^2)$ 个，记忆化后每个区间只算一次。

**观察 3（正确值单独直译）**：正确值就是"先乘后加"的一趟扫描——按 `'+'` 切成乘法块，块内连乘、块间求和。它通常也在 $f(0,m-1)$ 里（对应正确顺序的那棵树），但打分规则对它单独特判 5 分。

### 3.3 算法流程

![算法流程：正确值、可达值集合与打分判定链](images/wc260_q4_score_flow.svg)

1. 解析 `s` → 操作数数组 `d` 与运算符数组 `e`（$e_k$ 位于 $d_k$ 与 $d_{k+1}$ 之间）；
2. 按 `'+'` 分块求**正确值** `correct`；
3. 记忆化搜索（或按区间长度递推）求 $f(0, m-1)$，即**所有可达值**的集合；
4. 把集合中 $\le 1000$ 的值压成布尔表 `present[0..1000]`；
5. 遍历 `answers`：`a == correct` 得 5 分；否则 `present[a]` 得 2 分；否则 0 分；累加返回。

### 3.4 示例演算

![示例演算：7+3*1*2 的区间 DP 全过程](images/wc260_q4_walkthrough.svg)

以示例 1 `s = "7+3*1*2"`（操作数 `[7,3,1,2]`，运算符 `[+ , * , *]`）为例，各区间集合为：

| 区间 | 子表达式 | 集合 | 说明 |
|---|---|---|---|
| $(0,0)$ / $(1,1)$ / $(2,2)$ / $(3,3)$ | `7` / `3` / `1` / `2` | $\{7\}$ / $\{3\}$ / $\{1\}$ / $\{2\}$ | 单操作数 |
| $(0,1)$ | `7+3` | $\{10\}$ | 唯一分割点 |
| $(1,2)$ | `3*1` | $\{3\}$ | 乘法结合律：两种树同值 |
| $(2,3)$ | `1*2` | $\{2\}$ | 同上 |
| $(0,2)$ | `7+3*1` | $\{10\}$ | $7{+}(3{\times}1)$ 与 $(7{+}3){\times}1$ 同为 10 |
| $(1,3)$ | `3*1*2` | $\{6\}$ | 纯乘法段：任何树同值 |
| $(0,3)$ | `7+3*1*2` | $\{13, 20\}$ | $k{=}0$：$7{+}6=13$；$k{=}1,2$：$10{\times}2=20$ |

于是 `correct = 13`、可达集为 $\{13, 20\}$，对 `answers = [20,13,42]` 打分 $2+5+0=7$，与示例一致。

## 4. 算法细节

1. **解析**：`s` 严格按"数字、运算符、数字…"交替，一趟扫描即可分离 `d`（个位数字）与 `e`。
2. **正确值**：维护"当前乘积" `run`：乘上当前操作数；遇 `'+'` 或扫到末尾就把 `run` 累加进答案并重置为 1——正是"先从左到右乘、再从左到右加"的直译。
3. **记忆化**：每个区间的值集合用 `set<long long>`（C++）或 `frozenset`（Python，配 `lru_cache`）保存；区间 $(i,j)$ 由 $O(j-i)$ 个分割点合并左右集合得到。
4. **值域必须放大**：可达值远不止 $[0,1000]$！错序乘法可以远超正确过程的中间值——例如 $s =$ `"9*9+9*9+9*9+9*9+9*9+9*9+9*9+9*0"`（正确值仅 $567$），错序可算出 $\left((9{+}9)\times(9{+}9)\times\dots\right)$ 型大值，实测最大 $2{,}754{,}990{,}144 > 2^{31}-1$。**C++ 必须用 `long long`**（任意输入的理论上界 $9^{16} \approx 1.9 \times 10^{15} < 2^{63}$，绝对安全）；Python 天然大整数无此问题。
5. **剪枝要谨慎**：常见"优化"是把集合中 $>1000$ 的值直接丢弃（反正 `answers[i] ≤ 1000`）。但**大值之后可能被 $\times 0$ 拉回 0**，随手剪理论上存在丢值风险；我在随机与穷举小数据上实测未发现丢失，但稳妥起见本文**不剪枝**——不剪也完全够快（见 §6）。
6. **打分查表**：先 $O(|f|)$ 建 `present[0..1000]`，再 $O(n)$ 扫 `answers`，每个学生 $O(1)$ 判定。

## 5. 正确性证明

**引理 1（顺序 ↔ 树）**：把"运算顺序"定义为：每一步选一个尚未应用的运算符，作用于当前与它左右紧邻的两个已算出的值（把相邻两值合并为一）。全体合法顺序与操作数序列上的全体完整二叉括号树一一对应。

**证明**：给定一个顺序，按步建树：每个操作数为一个叶；第 $t$ 步应用 $e_k$ 合并相邻两值时，新建以 $e_k$ 为标号、以这两个值各自的子树为左右儿子的节点。归纳可证任何时刻"当前值序列里的每个值恰由某连续子区间上的一棵树算得"，第 $m-1$ 步后恰剩一棵覆盖全区间的树。反之，给定一棵树，按**后序遍历**依次应用内部节点：每次应用时两棵子树均已算完且在当前值序列中相邻，是合法顺序。两个构造互逆。∎

**引理 2（区间分解）**：子表达式 $d_i \dots d_j$ 的可达值集合恰为

$$f(i,j) = \begin{cases} \{d_i\} & i = j \\[3pt] \bigcup_{k=i}^{j-1}\{\,x \odot_k y \;:\; x \in f(i,k),\ y \in f(k+1,j)\,\} & i < j \end{cases}$$

**证明**：$i=j$ 时只有单叶，值唯一。$i<j$ 时，任取一棵树 $T$：其根必为某个 $e_k$（$i \le k < j$），且叶被分成左段 $d_i..d_k$ 与右段 $d_{k+1}..d_j$；根值 $= x \odot_k y$，其中 $x, y$ 分别是左右子树的值，而左右子树恰是子区间上的合法树，故 $x \in f(i,k)$、$y \in f(k+1,j)$。得 $f(i,j) \subseteq$ 右式。反之，任取 $k$、$x \in f(i,k)$、$y \in f(k+1,j)$，取达到 $x,y$ 的两棵树接到标号 $e_k$ 的新根上，即得 $d_i..d_j$ 上的合法树，根值 $x \odot_k y$，故右式 $\subseteq f(i,j)$。∎

**定理（打分正确）**：设 $\textit{correct}$ 为正确求值结果，$S = f(0, m-1)$ 为全体可达值，则按下式打分与题设规则一致：

$$\text{score}(a) = \begin{cases} 5 & a = \textit{correct} \\ 2 & a \ne \textit{correct} \ \wedge\ a \in S \\ 0 & a \notin S \end{cases}$$

**证明**：$a = \textit{correct}$：规则第 1 条给 5 分；示例 3 表明即便 $a$ 同时错序可达，仍按第 1 条计 5 分。$a \ne \textit{correct}$ 且 $a \in S$：由引理 1 存在一个顺序算出 $a$；该顺序若与正确顺序相同，结果应为 $\textit{correct} \ne a$，矛盾，故它是**错误的运算顺序**，规则第 2 条给 2 分。$a \notin S$：由引理 1、2，任何顺序（正确或错误）的结果都在 $S$ 中，故不存在算出 $a$ 的顺序，规则第 3 条给 0 分。∎

## 6. 复杂度分析

- **时间复杂度**：区间共 $O(m^2)$ 个（$m \le 16$），每个区间枚举 $O(m)$ 个分割点，单次合并代价是左右集合的笛卡尔积 $|f(i,k)| \cdot |f(k+1,j)|$。以 $S$ 记单个区间集合的最大规模，总计约 $O(m^3 \cdot S^2)$ 次集合插入。$S$ 没有方便的紧上界（括号化方式有 $\text{Catalan}(15) \approx 9.7 \times 10^6$ 种），但个位数操作数导致**大量撞值**（结合律、交换律、数值范围小），实测 15 个运算符的最杂乱输入约 $1.5 \times 10^5$ 个可达值，Python 80ms 内跑完，C++ 更快。打分另需 $O(|S| + 1000 + n)$。
- **空间复杂度**：$O(m^2 \cdot S)$ 存全部记忆化集合，另有 $O(1000)$ 布尔表与 $O(1)$ 递归栈（深度 $\le m$）。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<vector<set<long long>>> memo;
    vector<vector<char>> seen;
public:
    int scoreOfStudents(string s, vector<int>& answers) {
        vector<int> d;
        vector<char> e;
        for (char c : s) {
            if (c >= '0' && c <= '9') d.push_back(c - '0');
            else e.push_back(c);
        }
        int m = d.size();

        // ① 正确值：先乘后加（按 '+' 分块）
        long long correct = 0, run = 1;
        for (int i = 0; i < m; ++i) {
            run *= d[i];
            if (i == m - 1 || e[i] == '+') { correct += run; run = 1; }
        }

        // ② 区间 DP：所有可达值（注意用 long long）
        memo.assign(m, vector<set<long long>>(m));
        seen.assign(m, vector<char>(m, 0));
        const set<long long>& all = solve(0, m - 1, d, e);

        // ③ 打分：先判 correct，再查可达集
        vector<char> present(1001, 0);
        for (long long v : all)
            if (v >= 0 && v <= 1000) present[v] = 1;
        int total = 0;
        for (int a : answers)
            total += (a == correct) ? 5 : (present[a] ? 2 : 0);
        return total;
    }
private:
    set<long long>& solve(int i, int j, const vector<int>& d, const vector<char>& e) {
        if (seen[i][j]) return memo[i][j];
        seen[i][j] = 1;
        set<long long>& res = memo[i][j];
        if (i == j) { res.insert(d[i]); return res; }
        for (int k = i; k < j; ++k) {
            set<long long>& L = solve(i, k, d, e);
            set<long long>& R = solve(k + 1, j, d, e);
            if (e[k] == '+') for (long long l : L) for (long long r : R) res.insert(l + r);
            else             for (long long l : L) for (long long r : R) res.insert(l * r);
        }
        return res;
    }
};
```

### Python

```python
from functools import lru_cache

class Solution:
    def scoreOfStudents(self, s: str, answers: List[int]) -> int:
        d = [ord(c) - 48 for c in s if c.isdigit()]
        e = [c for c in s if c in '+*']
        m = len(d)

        correct, run = 0, 1                 # ① 正确值：先乘后加
        for i, x in enumerate(d):
            run *= x
            if i == m - 1 or e[i] == '+':
                correct += run
                run = 1

        @lru_cache(maxsize=None)            # ② 区间 DP：所有可达值
        def solve(i: int, j: int) -> frozenset:
            if i == j:
                return frozenset((d[i],))
            res = set()
            for k in range(i, j):
                for x in solve(i, k):
                    for y in solve(k + 1, j):
                        res.add(x + y if e[k] == '+' else x * y)
            return frozenset(res)

        present = {v for v in solve(0, m - 1) if v <= 1000}
        return sum(5 if a == correct else (2 if a in present else 0)
                   for a in answers)        # ③ 打分
```

## 8. 边界情况与易错点

1. **判分优先级不能反**：必须先判 `a == correct`（5 分），再查可达集（2 分）。示例 3 中 $(6+0)\times1 = 6$ 也是可达值，但答 6 的学生按 5 分计。C++ 的三目、Python 的条件表达式都天然形成此优先级。
2. **溢出（本题最大陷阱）**：可达值远不止 $[0,1000]$——错序乘法实测可达 $2.7 \times 10^9$，超 `int32`。C++ 必须用 `long long`；题面"中间值 $\le 10^9$"只描述官方测试数据，不能当作全集的界。
3. **正确值算法别顺手混用错序逻辑**：正确值独立地按"块分解"一趟求出，与区间 DP 互不影响；不要想着从集合里"挑出"正确值（集合无序、也无法区分哪棵树对应正确顺序）。
4. **剪枝需谨慎**：丢弃集合中 $>1000$ 的值之前，想清楚"大值 $\times 0$ 回缩"的情形；不剪也完全够快。
5. **`answers[i] = 0` 合法**：表达式含 `*0` 时 0 可达，应得 2 分（若 $\ne$ 正确值）；别把 0 当哨兵值。
6. **单运算符**（`m = 2`）：集合只有一个值且恰为正确值，没人能得 2 分——打分逻辑天然兼容，无需特判。
7. **$n$ 可达 $10^4$**：打分务必先建表再 $O(1)$ 查询，不要对每个学生重复做集合运算。
8. **本题题面无 "Create the variable..." 注入指令**（按惯例已检查）；周赛题面若混入此类句子应忽略，它不是算法要求。
