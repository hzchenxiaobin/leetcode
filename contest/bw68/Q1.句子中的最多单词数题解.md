# LeetCode 句子中的最多单词数 题解

## 1. 题目概述

- **标题 / 题号**：句子中的最多单词数（#2114，easy）
- **链接**：https://leetcode.cn/problems/maximum-number-of-words-found-in-sentences/
- **来源**：LeetCode 第 68 场双周赛 Q1
- **难度**：简单
- **标签**：数组、字符串

**题意**：一个**句子**由若干**单词**和它们之间的**单个空格**组成，且句子的开头和结尾没有多余空格。给定字符串数组 `sentences`，返回**单个句子中出现的最多单词数目**。

**约束**：

- $1 \le sentences.length \le 100$
- $1 \le sentences[i].length \le 100$
- `sentences[i]` 只包含小写英文字母和空格 `' '`
- `sentences[i]` 的开头和结尾没有空格
- `sentences[i]` 中所有单词由**单个空格**分隔

## 2. 示例

**示例 1**

```text
输入：sentences = ["alice and bob love leetcode", "i think so too",
                  "this is great thanks very much"]
输出：6
解释：三个句子分别有 5、4、6 个单词，最多的是第三个句子。
```

**示例 2**

```text
输入：sentences = ["please wait", "continue to fight", "continue to win"]
输出：3
解释：第二、三个句子都有 3 个单词，取最大值 3。
```

**示例 3（边界补充）**

```text
输入：sentences = ["a"]
输出：1
解释：单个单词、没有空格的句子，单词数就是 1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个句子调用 `split(' ')`（或 Python 的 `s.split()`）切出单词列表，统计列表长度后取最大。这个做法的正确性没问题，复杂度也是 $O(L)$（$L$ 为全部字符数），但它为「数个数」这件小事分配了整个单词数组，白白多了 $O(L)$ 的临时空间与切分开销。签到题的正确打开方式是：**从数据格式的保证里挖出公式，让代码缩到一行**。

### 3.2 核心观察：单词数 = 空格数 + 1

![核心观察：每个空格都是一个单词边界，单词数恰为空格数加一](images/bw68_q1_count_spaces.svg)

题面**保证**了句子的规范格式：首尾无空格、单词间恰好一个空格。于是空格就是全部的单词边界：

- 1 个单词的句子有 0 个空格；
- 每多一个单词，就多一个分隔空格。

单词数 $w$ 与空格数 $c$ 满足 $w = c + 1$。这个关系对单个空格分隔的规范句子是**恒等式**，因此整个问题化为：对每个句子数一遍空格，加一后取最大。

> 💡 **一句话总结**：别把句子「切开」再数，直接数「刀口」（空格）就行，切口数 + 1 = 块数。

### 3.3 算法流程

![算法流程：逐句数空格，+1 后取最大](images/bw68_q1_algorithm_flow.svg)

```text
best = 0
对每个句子 s：
    c = s 中空格字符的个数
    best = max(best, c + 1)
返回 best
```

### 3.4 示例演算

以示例 1 为例：

| 句子 | 空格数 | 单词数 |
|------|--------|--------|
| "alice and bob love leetcode" | 4 | 5 |
| "i think so too" | 3 | 4 |
| "this is great thanks very much" | 5 | 6 |

最大值 6，与官方输出一致。注意第三句若不规范（如双空格），「空格数 + 1」会高估——本题约束排除了这种情况。

## 4. 算法细节

1. **数空格的实现**：C++ 手写单层循环 `if (c == ' ') ++cnt`；Python 用内建 `str.count(' ')`，其 C 实现是一次快速线性扫描，比生成器表达式更快。
2. **`+1` 的位置**：先数空格再统一加一（$c+1$），或每句加一，都行；但注意 `max` 的初值取 0 即可——任何句子至少 1 个单词，`best` 必然被更新。
3. **无需 `split`**：切分徒增 $O(L)$ 临时分配；本题只需计数。若输入不规范（双空格、首尾空格），`count` 方案会错，而 `len(s.split())` 恰好更稳（Python 的无参 `split()` 按任意空白切分并自动去空）——但本题约束明确，按规范做即可。
4. **复杂度与数据规模**：$L \le 100 \times 100 = 10^4$，任何 $O(L)$ 写法都瞬过；不需要任何花哨优化。

## 5. 正确性证明

**引理（单词与空格的对应）**：若字符串 $s$ 由 $w$ 个非空单词 $u_1, u_2, \dots, u_w$ 依次排列、相邻单词间恰一个空格、首尾无空格组成，则 $s$ 中空格字符的数目 $c = w - 1$。

**证明**：对 $w$ 归纳。$w = 1$：$s = u_1$ 不含空格，$c = 0 = w - 1$ ✓。设 $w = n$ 时成立。$w = n+1$ 时，$s = t + ' ' + u_{n+1}$，其中 $t$ 是前 $n$ 个单词按规范拼成的句子。$t$ 的空格数由归纳假设为 $n - 1$，加上拼接处恰一个空格，$c = n = w - 1$ ✓。∎

**定理**：算法返回值等于各句子的单词数的最大值。

**证明**：`sentences[i]` 满足题面规范格式，由引理其单词数为 $c_i + 1$（$c_i$ 为其空格数）；算法对每个 $i$ 计算 $c_i + 1$ 并取最大，恰为所求。∎

## 6. 复杂度分析

- **时间**：$O(L)$，$L = \sum_i |sentences[i]| \le 10^4$。每个字符至多被常数次访问（数空格一次）。
- **空间**：$O(1)$ 额外空间。只用常数个计数器；相比 `split` 方案的 $O(L)$ 临时数组更省。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int mostWordsFound(vector<string>& sentences) {
        int best = 0;
        for (const string& s : sentences) {
            int words = 1;                          // 单词数 = 空格数 + 1
            for (char c : s)
                if (c == ' ') ++words;
            best = max(best, words);
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def mostWordsFound(self, sentences: list[str]) -> int:
        return max(s.count(' ') for s in sentences) + 1   # 单词数 = 空格数 + 1
```

> 💡 两份代码均通过官方示例（`6`、`3`）与单单词句（输出 `1`）等边界检查。

## 8. 边界情况与易错点

1. **忘记 `+1`**：只返回空格数会把每个句子的单词数都少一（示例 1 会错成 5）。
2. **单个单词的句子**：0 个空格，答案 1——`+1` 正是为此；若先给 `best` 初始化为 1 再只对含空格句子更新，逻辑同样对，但要小心空数组（本题 $length \ge 1$ 不存在）。
3. **依赖题面规范**：题目保证「单个空格、首尾无空格」才能用 $c+1$。如果面试中被问到**不规范输入**（连续空格、首尾空格、制表符），应改用「按空白切分并过滤空串后计数」的通用方案。
4. **别把 `max` 写在循环外**：把「数空格」复用同一个计数器且忘记清零，会导致跨句累加——C++ 里计数器 `words` 要么每句重置、要么像参考代码那样在循环体内初始化。
5. **返回类型**：单词数是 `int`；本题规模下不存在溢出问题。
