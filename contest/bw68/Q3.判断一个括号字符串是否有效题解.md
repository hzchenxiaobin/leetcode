# LeetCode 判断一个括号字符串是否有效 题解

## 1. 题目概述

- **标题 / 题号**：判断一个括号字符串是否有效（#2116，medium）
- **链接**：https://leetcode.cn/problems/check-if-a-parentheses-string-can-be-valid/
- **来源**：LeetCode 第 68 场双周赛 Q3
- **难度**：中等
- **标签**：栈、贪心、字符串、括号序列

**题意**：括号字符串 `s` 只含 `(` 和 `)`；同长度的 01 串 `locked` 中，`locked[i] == '1'` 表示 `s[i]` **锁定不可改**，`locked[i] == '0'` 表示 `s[i]` 是**通配符**，可自由改成 `(` 或 `)`。判断是否存在一种改法，使 `s` 成为**有效括号字符串**（可分解为 `()`、`AB`、`(A)` 的标准定义，等价于：每个前缀的 `(` 减 `)` 差值非负，且总差值为 0）。

**约束**：

- $1 \le n = |s| = |locked| \le 10^5$
- `s[i]` 要么 `(` 要么 `)`；`locked[i]` 要么 `0` 要么 `1`

## 2. 示例

**示例 1**

```text
输入：s = "))()))", locked = "010100"
输出：true
解释：s[1]、s[3] 锁定为 ')' 不可动；把 s[0]、s[4] 改成 '('，得到 "()(())"，有效。
```

**示例 2**

```text
输入：s = "()()", locked = "0000"
输出：true
解释：四个位置全可改，s 本身已是有效串，无需改动。
```

**示例 3**

```text
输入：s = ")", locked = "0"
输出：false
解释：长度为 1 是奇数，不可能有效。
```

**示例 4**

```text
输入：s = "(((())(((())", locked = "111111010111"
输出：true
解释：只有 s[6]、s[8] 可改，把它们都改成 ')'，得到 "(((()))((()))"，有效。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个通配位置取 `(` 还是 `)`，共 $2^w$ 种组合（$w$ 为通配个数），每种再 $O(n)$ 扫一遍验证平衡。$w$ 到 20 就已经百万级，$n = 10^5$ 时通配可能上万个，指数级不可行。需要的是**放弃具体方案、只跟踪「前缀平衡值的可能范围」**的贪心视角。

### 3.2 核心观察：平衡值的可能范围是一个「区间 + 奇偶类」

![核心观察：每步维护未匹配左括号数的可达区间 [lo, hi]](images/bw68_q3_lohi_model.svg)

定义**平衡值** $b_i$ = 前缀 $s[0..i]$ 中 `(` 与 `)` 的个数差。括号串有效 $\iff$ 每个 $b_i \ge 0$ 且 $b_{n-1} = 0$。

锁定字符对 $b$ 的影响是确定的 ±1；通配字符则**两种都行**。于是从左往右扫，维护两个量：

- $lo$：当前前缀平衡值**可能的最小值**（尽量取 `)`）；
- $hi$：当前前缀平衡值**可能的最大值**（尽量取 `(`）。

每步转移：锁定 `(` 则 $lo, hi$ 同加一；锁定 `)` 则同减一；通配则 $lo$ 减一、$hi$ 加一（两头各取一个极端）。三个关键维护规则：

1. **$lo$ 截到 0**：$lo < 0$ 说明「全取右括号」会跌破 0，但我们可以**回头把前面某个通配位改成 `(`** 把整条后缀抬高 2——只要那个前缀还到不了「连抬高都救不回」的程度。$lo = \max(lo, 0)$。
2. **$hi < lo$ 立即判死**：$hi < 0$ 说明「全取左括号」都救不回负平衡——某个锁定 `)` 之前没有足够的 `(`/通配可配对，前缀必然失败，提前返回 false。
3. **奇数长度直接排除**：每个字符贡献 ±1，$b_{n-1}$ 的奇偶性与 $n$ 相同；$n$ 为奇数时 $b_{n-1} = 0$ 不可能达到。

扫描结束后，$lo = 0$ 当且仅当存在一种方案使末尾平衡值归零（结合奇偶类，见 §5）。

### 3.3 算法流程

![算法流程：一步内的更新顺序——先更新、再截 lo、后判 hi](images/bw68_q3_scan_flow.svg)

```text
1. 若 n 为奇数，返回 false
2. lo = hi = 0
3. 对 i = 0..n-1：
       locked[i]=='0'      → lo--, hi++
       locked[i]=='1' 且 s[i]=='('  → lo++, hi++
       locked[i]=='1' 且 s[i]==')'  → lo--, hi--
       若 lo < 0：lo = 0                 # 截断（回头改通配）
       若 hi < lo：返回 false            # 连全 '(' 都救不回 → 前缀必败
4. 返回 (lo == 0)
```

注意一步之内的**顺序**：先更新、再截 $lo$、最后比较 $hi < lo$（等价于 $hi < 0$ 的判死，因 $lo$ 已非负）。

### 3.4 示例演算

![示例演算：示例1逐步 [lo,hi] 演化与示例4的收敛](images/bw68_q3_example_walkthrough.svg)

**示例 1**（`s = "))()))", locked = "010100"`，通配取第 0、2、4 位）：

| $i$ | 字符 / 锁定 | 转移 | $[lo, hi]$ | 说明 |
|-----|------------|------|-----------|------|
| 0 | `)` / 0 | lo−1, hi+1 | $[0, 1]$ | lo 截 0：全 `)` 会跌破，须把 i0 取 `(` |
| 1 | `)` / 1 | lo−1, hi−1 | $[0, 0]$ | 与 i0 的 `(` 配对，平衡恰为 0 |
| 2 | `)` / 0 | lo−1, hi+1 | $[0, 1]$ | |
| 3 | `(` / 1 | lo+1, hi+1 | $[1, 2]$ | 锁定左括号推高下界 |
| 4 | `)` / 0 | lo−1, hi+1 | $[0, 3]$ | |
| 5 | `)` / 0 | lo−1, hi+1 | $[0, 4]$ | |

末尾 $lo = 0$（偶数长度、奇偶类含 0）→ **true**，对应方案 `()(())` ✓。

**示例 4**（`s = "(((())(((())", locked = "111111010111"`）：前 9 个字符产生 $[3, 5]$ 的区间，两个通配（第 6、8 位）各把 $hi$ 抬 1、$lo$ 压 1 后截回，末段三个锁定 `)` 把区间收拢，最终 $lo = 0$ → **true**。

## 4. 算法细节

1. **$lo$ 的截断含义**：不是「假装没发生」，而是「用一次通配回改修正」。$lo$ 跌到 $-1$ 时，把**当前位置左侧最近的那个「本想取 `)`」的通配**改成 `(`，其后的平衡全部 +2，恰好回到 0 以上；这也是为什么截断后 $lo$ 与真实可达下界一致（严格论证见 §5 引理 2 的集合代数证明，比「翻转」直觉更强）。
2. **判死必须即时**：$hi < 0$ 一旦发生就应返回 false，不能等下一轮——负信息（「某前缀已无法配对」）不会被后续翻转修复。
3. **奇偶剪枝不可省**：若去掉 $n$ 偶数检查，对 `s = "(", locked = "0"` 算得 $[0, 1]$、末尾 $lo = 0$ 会错判 true。$lo$ 截断会掩盖「0 不在奇偶类里」的事实，因此奇偶剪枝是**正确性的一部分**而非优化（详见 §8）。
4. **等价的两遍贪心**：正序扫锁定 `)` 是否都能配上（`(` 与通配计数），再逆序扫锁定 `(`，也能得解；一遍 $[lo, hi]$ 版代码最短。
5. **常数**：单层循环、纯整数运算，$n = 10^5$ 远低于时限。

## 5. 正确性证明

**定义**：对前缀长度 $\ell$（处理完前 $\ell$ 个字符），令 $A_\ell$ 为「使 $s[0..\ell-1]$ 每个前缀平衡值 $\ge 0$ 的通配取法」所能达到的**末尾平衡值集合**；$L_\ell$ 为前缀长度 $\ell$ 的奇偶类，即与 $\ell \bmod 2$ 同余的整数。

**引理 1（区间间隙恒偶）**：算法中任何时刻 $hi - lo$ 为偶数，且 $0 \le lo \le hi$（除判死前）。

**证明**：初始 $lo = hi = 0$。锁定字符把两数同移 $\pm 1$，差不减；通配把 $lo$ 减 $1$、$hi$ 加 $1$，差加 2。故差始终为偶数。$lo \le hi$ 在截断前保持（三类转移均不交叉）；截断只把 $lo$ 抬到 0，若抬后 $lo > hi$ 则立即判死返回。∎

**引理 2（可达集 = 区间 ∩ 奇偶类）**：$A_\ell = \{\, b : lo_\ell \le b \le hi_\ell,\ b \equiv \ell \pmod 2 \,\}$（非空当且仅当算法未判死）。

**证明**：对 $\ell$ 归纳。$\ell = 0$：$A_0 = \{0\}$，$[lo, hi] = [0, 0]$，奇偶类含 0 ✓。

设对 $\ell$ 成立，考虑第 $\ell + 1$ 个字符的转移：

- **锁定 `(`**：末尾平衡必然 $+1$，故 $A_{\ell+1} = \{b + 1 : b \in A_\ell\} = \{b' : lo + 1 \le b' \le hi + 1,\ b' \equiv \ell + 1\}$；算法恰更新为 $(lo, hi) \to (lo+1, hi+1)$，且非空性显然 ✓。
- **锁定 `)`**：合法条件是**新前缀平衡 $\ge 0$**，即 $b - 1 \ge 0$：$A_{\ell+1} = \{b - 1 : b \in A_\ell,\ b \ge 1\} = \{b' : \max(lo - 1, 0) \le b' \le hi - 1,\ b' \equiv \ell + 1\}$。这正是算法的 $(lo, hi) \to (\max(lo-1, 0),\ hi-1)$。剩下核实非空性的等价（由引理 1，$hi - lo$ 为偶数）：
  - 若 $lo \ge 1$：$A_\ell$ 的元素全部 $\ge 1$，$A_{\ell+1} = \{b-1 : b \in A_\ell\}$ 是非空集的平移，必非空 ✓；
  - 若 $lo = 0$：由间隙偶，$hi$ 为偶数。若 $hi \ge 2$：类 $\ell$ 的同余点在 $[0, hi]$ 中以步长 2 排列、至少两个，除可能存在的 0 外其余都 $\ge 1$，故 $A_{\ell+1}$ 非空 ✓；若 $hi = 0$：算法活到当前步意味着 $A_\ell = \{0\}$（区间仅含 0 且非空），$b \ge 1$ 无从满足，$A_{\ell+1}$ 确为空，而算法得到 $lo' = 0 > hi' = -1$，恰好触发 $hi < lo$ 判死 ✓。两处完全对合。
- **通配**：$A_{\ell+1} = \{b + 1 : b \in A_\ell\} \cup \{b - 1 : b \in A_\ell,\ b \ge 1\}$（取 `)` 的合法条件同上）。两个像集同属奇偶类 $\ell + 1$，分别占据 $[lo+1, hi+1]$ 与 $[\max(lo-1, 0), hi-1]$ 中同余点。由间隙偶，两段同余点步长 2 且端点衔接（$lo+1 \le (hi-1)+2$ 恒成立），合并恰为 $[\max(lo-1, 0),\ hi+1]$ 的同余点全体。这正是算法的 $(lo, hi) \to (\max(lo-1, 0),\ hi+1)$，非空性显然（$\ge A_\ell + 1$ 非空）✓。

归纳完成。∎

**引理 3（奇偶约束）**：任何取法下 $b_\ell \equiv \ell \pmod 2$，故 $n$ 为奇数时 $b_{n-1} = 0$ 不可达，答案必为 false。

**证明**：每个字符使平衡变化 $\pm 1$，$\ell$ 步后平衡与 $\ell$ 同奇偶。∎

**定理**：算法返回 true 当且仅当存在合法改法使 `s` 成为有效括号串。

**证明**：`s` 有效 $\iff$（每个前缀平衡 $\ge 0$）且 $b_n = 0$ $\iff$ $0 \in A_n$（前缀约束已编码进 $A_n$ 的定义）。由引理 3，$n$ 为奇数时算法已在第 1 行返回 false 且 $0 \notin A_n$（奇偶类不符）✓。$n$ 为偶数时 $0 \equiv n \pmod 2$，由引理 2，$0 \in A_n \iff lo_n \le 0 \le hi_n$；算法未判死保证 $hi_n \ge lo_n \ge 0$，故条件化为 $lo_n = 0$——恰为算法第 4 步的返回条件。∎

## 6. 复杂度分析

- **时间**：$O(n)$。单层扫描，每步 $O(1)$；奇偶剪枝 $O(1)$。$n = 10^5$ 微秒级完成。
- **空间**：$O(1)$ 额外。仅两个计数器与循环变量；输入串本身不计入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canBeValid(string s, string locked) {
        int n = s.size();
        if (n % 2) return false;                      // 奇数长度必失败（奇偶类不含 0）
        int lo = 0, hi = 0;                           // 前缀平衡值的最小 / 最大可达值
        for (int i = 0; i < n; ++i) {
            if (locked[i] == '1') {
                if (s[i] == '(') { ++lo; ++hi; }
                else { --lo; --hi; }
            } else { --lo; ++hi; }                    // 通配：两种都可能
            lo = max(lo, 0);                          // 负值可回头把某个通配改回 '('
            if (hi < lo) return false;                // 连全 '(' 都救不回 → 前缀必败
        }
        return lo == 0;                               // 存在方案使末尾平衡归零
    }
};
```

### Python

```python
class Solution:
    def canBeValid(self, s: str, locked: str) -> bool:
        if len(s) % 2:
            return False
        lo = hi = 0                            # 前缀平衡值的最小 / 最大可达值
        for c, lock in zip(s, locked):
            if lock == '0':                    # 通配：两种都可能
                lo -= 1
                hi += 1
            elif c == '(':
                lo += 1
                hi += 1
            else:
                lo -= 1
                hi -= 1
            if lo < 0:
                lo = 0                         # 负值可把某个通配改回 '(' 修正
            if hi < lo:
                return False                   # 连全 '(' 都救不回
        return lo == 0
```

> 💡 两份代码均通过全部官方示例（`true`、`true`、`false`、`true`），并与「枚举全部 $2^w$ 种通配取法后逐个验证」的暴力对拍：C++ 6000 组、Python 5000 组随机数据（长度覆盖奇偶、锁定/通配比例随机、含全锁定与全通向的极端模式），无一失配。

## 8. 边界情况与易错点

1. **奇数长度必须先判**：否则 `s = "(", locked = "0"` 会在末尾算出 $lo = 0$ 错判 true——截断破坏了奇偶信息（详见 §5 引理 3）。这是本题最隐蔽的坑。
2. **三步顺序不能乱**：更新 → 截 $lo$ → 比较 $hi < lo$。若先比较后截断（如 $hi = lo = -1$ 时先比较 $-1 < -1$ 不成立），会漏判一步必败，错误地「多活一步」后被截断污染状态。
3. **判死条件是 $hi < lo$（截断后）**，初学者常把判死写成 $hi < 0$ 再单独截断——两者在「截断在前」的顺序下等价，但如果截断放在比较之后就会出错（见上条）。
4. **末尾判 $lo = 0$ 而非 $hi = 0$**：$hi$ 只是可达上界；例如 $[0, 4]$ 表示「存在方案归零」而非「所有方案归零」。判断方向写反会把 `s = "((", locked = "00"`（可行，改成 `"()"`）与 `s = "))"` 全通配（不可行）混为一谈。
5. **锁定位置别看错字符**：通配位上的 `s[i]` 是**无关信息**（可以显示为 `(` 或 `)`），转移只看 `locked[i]`；错把通配位的 `s[i]` 纳入判断会整体错。
6. **不要用栈**：本题不需要匹配结构，栈思维（配对弹栈）会把通配的处理复杂化；区间计数是最短路径。
