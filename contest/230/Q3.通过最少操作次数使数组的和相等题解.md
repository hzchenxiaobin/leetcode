# LeetCode 通过最少操作次数使数组的和相等 题解

## 1. 题目概述

- **标题 / 题号**：通过最少操作次数使数组的和相等（#1775，medium）
- **链接**：https://leetcode.cn/problems/equal-sum-arrays-with-minimum-number-of-operations/
- **来源**：LeetCode 第 230 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、哈希表、计数

**题意**：
给定长度可能不等的两个整数数组 $\text{nums1}$ 与 $\text{nums2}$，所有元素都落在 $1 \sim 6$ 之间。每次操作可以任选**一个**数组中的**一个**元素，把它改成 $1 \sim 6$ 之间的任意整数。求使两数组的**元素和相等**的最少操作次数；若无论怎么改都不可能相等，返回 $-1$。

**约束**：

- $1 \le \text{nums1.length}, \text{nums2.length} \le 10^5$
- $1 \le \text{nums1}[i], \text{nums2}[i] \le 6$

> 💡 **比赛视角**：值域只有 $1 \sim 6$ 是本题最大的提示——数组虽长达 $10^5$，但每个元素的「可改动空间」只有 $0 \sim 5$ 共 **6 档**，数一遍就能把整个问题压到 6 个计数桶上，连排序都不需要。示例 2 还亮出了全场唯一的陷阱：全 $1$ 的长数组对上 $[6]$，**先想清楚 $-1$ 何时发生再谈贪心**。这是典型的「分场胜负」题：把「改元素」抽象成「消耗一份封顶改动力」的人 3 分钟写完，没想到这一层的人容易在「两边各改谁、改多少」的细节里打转。

## 2. 示例

**示例 1**

```text
输入：nums1 = [1,2,3,4,5,6], nums2 = [1,1,2,2,2,2]
输出：3
解释：nums2[0] 变为 6（和 10→15），nums2[1] 变为 6（15→20），
      nums1[5] 从 6 变为 5（和 21→20），两边相等。
```

**示例 2（无解）**

```text
输入：nums1 = [1,1,1,1,1,1,1], nums2 = [6]
输出：-1
解释：nums1 的和为 7，元素全是 1，已无法再压低；
      nums2 的和为 6，元素已是最大值 6，已无法再抬高。
      两边和的可调节区间 [7, 42] 与 [1, 6] 没有公共点。
```

**示例 3**

```text
输入：nums1 = [6,6], nums2 = [1]
输出：3
解释：nums1[0] 6→2，nums1[1] 6→2（和 12→4），nums2[0] 1→4（和 1→4），
      两边相等，共 3 次操作。
```

## 3. 解题思路

### 3.1 暴力思路：排序封顶值逐个榨干

朴素地想：设两数组的和分别为 $s_1 \le s_2$，差值 $\text{diff} = s_2 - s_1 > 0$。要把 $\text{diff}$ 缩到 $0$，每个元素能出的力是**封顶**的：

- 小和数组里的元素 $x$ 最多抬升 $6 - x$；
- 大和数组里的元素 $y$ 最多压低 $y - 1$。

直接把全部 $n + m$ 个封顶值排个序，**从大到小逐个消费**：每次消费 $\min(\text{封顶}, \text{剩余 diff})$，操作数 $+1$，直到 $\text{diff} \le 0$；消费完仍不够则返回 $-1$。这个做法 $O((n+m)\log(n+m))$，在 $2 \times 10^5$ 的规模下也能过，但它没有吃透两个性质：

1. **封顶值只有 $0 \sim 5$ 共 6 种取值**——排序是浪费，计数即可；
2. 「逐个消费」隐含了「增益必须用满或用到剩余量」的逐次判断，其实可以**按桶整批取**，一步算清本档取几个。

### 3.2 核心观察：差值、封顶改动力与 6 个计数桶

![核心观察：只盯差值，每个元素有一份封顶改动力，只需 6 个计数桶](images/wc230_q3_equal_sum_concept.svg)

三个层层递进的洞察：

**观察 A（只关心差值）**：目标只有一个——把 $\text{diff} = s_2 - s_1$ 缩到 $0$。抬升小和数组的元素、压低大和数组的元素，是**同一件事**的两个方向：都让 $\text{diff}$ 变小。两边数组因此在贪心眼里**无差别**，只贡献「缩差力量」。

**观察 B（每个元素是一份封顶改动力）**：一次操作把元素改成 $1 \sim 6$ 的任意值，所以**每个元素至多值得改一次**（改两次同一个元素，净效果等于一次直接改到最终值）；且单次改动的增益可以是 $[0, \text{封顶}]$ 内的**任意整数**——不必非得改成 $6$ 或 $1$。于是问题彻底改写：

> 选**最少**的元素，使它们的封顶值之和 $\ge \text{diff}$。

**观察 C（值域 $1 \sim 6$ → 6 个桶）**：封顶值只能取 $0 \sim 5$。用长度为 6 的计数数组统计：小和数组的元素 $x$ 落进桶 $\text{cnt}[6-x]$，大和数组的元素 $y$ 落进桶 $\text{cnt}[y-1]$，$O(n+m)$ 一遍完成。桶 $\text{cnt}[0]$ 里的元素（已在「错误方向」的极端上）永远无助于缩差，直接无视。

> 💡 **一句话**：问题从「改 $10^5$ 个元素」坍缩成「从 5 个桶里取最少个数、总和凑够 $\text{diff}$」——因为**操作次数只与封顶值够不够大有关，与元素具体数值无关**。

### 3.3 算法流程：从 g=5 到 g=1 榨取

![算法流程：建桶后从高档往低档榨取，diff 清零返回 ans，榨干仍不清零返回 -1](images/wc230_q3_equal_sum_greedy_flow.svg)

1. **求和归一**：算出 $s_1, s_2$；若 $s_1 > s_2$ 交换两数组，统一成 $s_1 \le s_2$。$\text{diff} = s_2 - s_1$，若 $\text{diff} = 0$ 直接返回 $0$。
2. **建桶**：小和数组元素 $x$ 执行 $\text{cnt}[6-x]{+}{+}$，大和数组元素 $y$ 执行 $\text{cnt}[y-1]{+}{+}$。
3. **榨取**：$g$ 从 $5$ 递减到 $1$，每档取 $\text{use} = \min\big(\text{cnt}[g],\ \lceil \text{diff}/g \rceil\big)$，答案累加 $\text{use}$，$\text{diff} \mathrel{-}= \text{use} \cdot g$；一旦 $\text{diff} \le 0$ 停止。
4. **收尾**：$\text{diff} \le 0$ 返回 $\text{ans}$；所有档榨干仍 $\text{diff} > 0$，返回 $-1$。

> ⚠️ **上取整是本算法的灵魂**：$\lceil \text{diff}/g \rceil$ 表示「当前档位至多需要几个就能收工」。本档够用就绝不多花一次操作、更不去动更小的档——因为增益可以**不用满**，最后一个元素改到「恰好补齐」即可。

### 3.4 示例演算

![示例 1 演算：建桶得到 cnt[5]=3，贪心只用最高档就凑够 diff=11](images/wc230_q3_equal_sum_walkthrough.svg)

以示例 1 为例：$\text{nums1} = [1,2,3,4,5,6]$（$\Sigma = 21$，大和），$\text{nums2} = [1,1,2,2,2,2]$（$\Sigma = 10$，小和），$\text{diff} = 11$。

**建桶**（绿色为封顶，标在元素下方）：

| 封顶 g | 5 | 4 | 3 | 2 | 1 |
|--------|---|---|---|---|---|
| 来源 | nums2 的两个 $1$（各抬 $+5$）＋ nums1 的 $6$（最多压 $-5$） | nums2 的四个 $2$ ＋ nums1 的 $5$ | nums1 的 $4$ | nums1 的 $3$ | nums1 的 $2$ |
| cnt[g] | **3** | 5 | 1 | 1 | 1 |

（nums1 的 $1$ 封顶为 $0$，进 $\text{cnt}[0]$，无用。）

**榨取**：$g = 5$ 档：$\lceil 11/5 \rceil = 3 \le \text{cnt}[5] = 3$，取 $3$ 个，$\text{ans} = 3$，$\text{diff} = 11 - 15 = -4 \le 0$，收工。低档全没动。

**具体方案**（增益不必用满）：$\text{nums2}$ 的两个 $1 \to 6$（各 $+5$，和 $10 \to 20$），$\text{nums1}$ 的 $6 \to 5$（缩差 $1$，和 $21 \to 20$），共 $3$ 次，两边都是 $20$。

## 4. 算法细节

1. **swap 归一方向**：先保证 $s_1 \le s_2$，后面所有逻辑只写「抬小压大」一份。C++ 直接 `swap(nums1, nums2)`（$O(1)$ 交换缓冲区）；Python 交换引用即可。**封顶方向**：小和数组 $\text{cnt}[6-x]$（抬升空间），大和数组 $\text{cnt}[y-1]$（压低空间）。
2. **建桶**：两个方向的封顶都天然落在 $[0, 5]$，由值域 $1 \sim 6$ 保证，无需任何防越界判断。$\text{cnt}[0]$（小和数组里的 $6$、大和数组里的 $1$）永远不被消费。
3. **use 的上取整**：$\text{use} = \min(\text{cnt}[g], \lceil \text{diff}/g \rceil)$。若 $\lceil \text{diff}/g \rceil \le \text{cnt}[g]$，本档取 $\lceil \text{diff}/g \rceil$ 个即收工——最后一个不必用满增益；否则整档取完，$\text{diff}$ 减去 $\text{cnt}[g] \cdot g$，去下一档。
4. **diff 打成负数是正常现象**：它只说明「最后一次操作没把增益用满」，操作数不因此变化，不要为此写特判。
5. **$-1$ 的两种等价判定**：一是循环后兜底（本文写法）：所有档榨干仍 $\text{diff} > 0$ 即无解；二是前置判定 $6 \cdot \min(\text{len}_1, \text{len}_2) < \max(\text{len}_1, \text{len}_2)$ 返回 $-1$（两数组「和的可达区间」$[\text{len}, 6\,\text{len}]$ 无公共点，等价性见 §5 引理 4）。
6. **数值范围**：两边的和至多 $6 \times 10^5$，`int` 全程安全，无溢出风险。
7. **为什么不排序**：封顶只有 6 种取值，计数桶就是值域受限的桶排序，$O(n+m)$ 一步到位；对 $10^5$ 规模而言，比 $O((n+m)\log(n+m))$ 的排序干净且快。

## 5. 正确性证明

**引理 1（操作归一化）**：存在最优解，其中每个元素至多被修改一次，且一次直接改成最终值。

**证明**：若某元素被修改多次，把「初值 → 终值」的净效果合并为一次操作，操作数不增；若某操作前后元素的值相同（或该操作增益为 $0$），删掉它，两边的和不变、依然相等，操作数减一。反复应用，得到每个元素至多改一次的最优解。∎

**引理 2（答案刻画）**：设 $s_1 \le s_2$、$\text{diff} = s_2 - s_1 > 0$，元素 $x$（小和数组）的封顶为 $c(x) = 6 - x$，元素 $y$（大和数组）的封顶为 $c(y) = y - 1$。将全部 $n + m$ 个封顶值降序排列，则最少操作次数为

$$
k^* = \min\{\, k \;:\; \text{前 } k \text{ 大封顶值之和} \ge \text{diff} \,\}.
$$

**证明**：**下界**：任取一个达成相等的方案，由引理 1 可设其改动集合为 $S$、$|S| = k$。改动 $i \in S$ 的缩差量为 $x_i - a_i \le 6 - x_i = c$（小和方向，$a_i$ 为终值；终值更小则左边为负，不等式仍成立）或 $y_i - b_i \le y_i - 1 = c$（大和方向）。于是 $\text{diff} \le \sum_{i \in S} c_i \le$ 前 $k$ 大封顶之和，故任何可行方案的 $k \ge k^*$。**上界**：取前 $k^*$ 大封顶对应的元素，令 $\text{rem} = \text{diff}$，逐个赋增益 $g_i = \min(c_i, \text{rem})$、$\text{rem} \mathrel{-}= g_i$。由 $\sum c_i \ge \text{diff}$ 知最后 $\text{rem} = 0$；每个 $g_i \in [0, c_i]$，落在该元素一次改动的合法区间内（$x \to x + g_i \le 6$，$y \to y - g_i \ge 1$）。故 $k^*$ 次操作可达相等。两方面夹逼，答案 $= k^*$。∎

**引理 3（贪心正确性）**：榨取循环（$g$ 从 $5$ 到 $1$，$\text{use} = \min(\text{cnt}[g], \lceil \text{rem}/g \rceil)$）输出的 $\text{ans}$ 恰为 $k^*$。

**证明**：设循环首次在档位 $g^*$ 处 $\text{rem} \le 0$。此前所有封顶 $> g^*$ 的元素被整档取完，共 $A$ 个、封顶总和 $S_A$，且 $\text{rem}_0 = \text{diff} - S_A > 0$（否则更早停）；本轮取 $t = \lceil \text{rem}_0/g^* \rceil \le \text{cnt}[g^*]$，输出 $\text{ans} = A + t$。**可行**：前 $\text{ans}$ 大封顶之和 $\ge S_A + t \cdot g^* \ge S_A + \text{rem}_0 = \text{diff}$，故 $k^* \le \text{ans}$。**不浪费**：对任何 $k < \text{ans}$：若 $k \le A$，前 $k$ 大之和 $\le S_A < \text{diff}$；若 $A < k < A + t$，前 $k$ 大之和 $\le S_A + (k - A) g^* \le S_A + (t-1) g^* < S_A + \text{rem}_0 = \text{diff}$（$(t-1)g^* < \text{rem}_0$ 由上取整定义保证）。故 $k$ 个封顶必不够，$k^* \ge \text{ans}$。夹逼得 $\text{ans} = k^*$。∎

**引理 4（无解判定）**：以下三命题等价：(a) 问题无解；(b) 榨取循环结束仍 $\text{diff} > 0$；(c) $6 \cdot n < m$，其中 $n$、$m$ 分别是小和、大和数组的长度。

**证明**：长度为 $\ell$ 的数组，其和的可调节区间恰为 $[\ell, 6\ell]$（每个元素可独立取 $1 \sim 6$ 的任意整数），故 (a) $\iff$ 区间 $[n, 6n]$ 与 $[m, 6m]$ 不相交 $\iff$ $6n < m$ 或 $6m < n$。由 $s_1 \le s_2$ 得 $n \le s_1 \le s_2 \le 6m$，排除 $6m < n$，故 (a) $\iff$ (c)。又循环结束仍 $\text{diff} > 0$ $\iff$ 全部封顶之和 $(6n - s_1) + (s_2 - m) < \text{diff} = s_2 - s_1 \iff 6n < m$，故 (b) $\iff$ (c)。∎

**定理**：算法返回最少操作次数；且当且仅当问题无解时返回 $-1$。

**证明**：由引理 2，答案为 $k^*$ 或无解；由引理 3，循环在 $\text{diff} \le 0$ 时输出的正是 $k^*$；由引理 4，循环耗尽仍 $\text{diff} > 0$ 的情况恰与无解一一对应，此时返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$——求和 $O(n+m)$，建桶 $O(n+m)$，榨取循环至多 $5$ 轮 $O(1)$。相比排序版 $O((n+m)\log(n+m))$，利用值域只有 $6$ 档省掉了排序。
- **空间复杂度**：$O(1)$ 额外空间——只有一个长度 $6$ 的计数数组（不计输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums1, vector<int>& nums2) {
        int s1 = accumulate(nums1.begin(), nums1.end(), 0);
        int s2 = accumulate(nums2.begin(), nums2.end(), 0);
        if (s1 == s2) return 0;
        if (s1 > s2) {                       // 统一成 s1 <= s2：小的抬，大的压
            swap(nums1, nums2);
            swap(s1, s2);
        }
        int diff = s2 - s1;
        int cnt[6] = {0};
        for (int x : nums1) cnt[6 - x]++;    // 小和数组：抬升空间 6 - x
        for (int y : nums2) cnt[y - 1]++;    // 大和数组：压低空间 y - 1
        int ans = 0;
        for (int g = 5; g >= 1 && diff > 0; g--) {
            int use = min(cnt[g], (diff + g - 1) / g);   // 上取整：本档够用就不动更小的档
            ans += use;
            diff -= use * g;
        }
        return diff > 0 ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums1: List[int], nums2: List[int]) -> int:
        s1, s2 = sum(nums1), sum(nums2)
        if s1 == s2:
            return 0
        if s1 > s2:
            nums1, nums2 = nums2, nums1      # 统一成 s1 <= s2
        diff = abs(s1 - s2)
        cnt = [0] * 6
        for x in nums1:
            cnt[6 - x] += 1
        for y in nums2:
            cnt[y - 1] += 1
        ans = 0
        for g in range(5, 0, -1):
            if diff <= 0:
                break
            use = min(cnt[g], (diff + g - 1) // g)
            ans += use
            diff -= use * g
        return ans if diff <= 0 else -1
```

> 💡 Python 版 `swap` 用多重赋值交换引用；`(diff + g - 1) // g` 即 $\lceil \text{diff}/g \rceil$。两版代码均已通过随机小数据与暴力 DP 对拍验证。

## 8. 边界情况与易错点

1. **封顶方向搞反（最高频 WA）**：小和数组用 $6 - x$（往大改）、大和数组用 $y - 1$（往小改）。写反后示例 2 会把「$[6]$ 该被抬高却没有空间」算成有空间，错误地返回 $1$ 而非 $-1$。
2. **use 必须上取整**：反例——$\text{diff} = 3$、只有一个封顶 $5$ 的元素。上取整取 $1$ 次正确；若写成 $\text{diff}/g$ 向下取整则 $\text{use} = 0$，该元素永远不被使用，错误地返回 $-1$。上取整正是「增益不必用满」的代码化身。
3. **忘判 $-1$**：示例 2 是官方唯一的 $-1$ 样例。循环后兜底（本文写法）与前置 $6 \cdot \min(\text{len}) < \max(\text{len})$ 判定等价（引理 4），任选其一。
4. **diff = 0 直接返回 0**：别让空转的榨取循环处理它，虽然循环也能正确给出 $0$，但提前返回语义更清楚。
5. **diff 被打成负数是正常的**：表示最后一次操作没用满封顶，操作数已经最优，不要加「diff 恰好为 0」之类的特判。
6. **不要写循环逐元素交换两数组**：C++ `swap(vector)` 是 $O(1)$ 的缓冲区交换；逐元素 copy 到临时数组是 $O(n)$ 且容易写错下标。
7. **桶下标无需防越界**：$6 - x$ 与 $y - 1$ 都落在 $[0, 5]$，由值域 $1 \sim 6$ 保证。
8. **无溢出**：两边和至多 $6 \times 10^5$，`int` 安全（对照第 231 场 Q2 的 $10^{11}$ 溢出教训，本题的坑全在贪心方向与取整，不在数值范围）。

**延伸思考**：若值域从 $1 \sim 6$ 放宽到 $1 \sim K$，桶变成 $K$ 个、榨取循环 $O(K)$；$K$ 很大时退化为对封顶值排序 $O((n+m)\log(n+m))$。若目标放宽为 $|s_1 - s_2| \le t$，只需把 $\text{diff}$ 换成 $\max(0, \text{diff} - t)$ 再贪心。若只允许改其中一个数组，封顶只剩单边，同样按桶榨取，无解判定相应放宽为「单边封顶总和 $< \text{diff}$」。若问「使两边和相等的方案数」，则转入背包计数——那是另一个世界了。
