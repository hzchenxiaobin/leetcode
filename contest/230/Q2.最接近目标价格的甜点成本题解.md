# LeetCode 最接近目标价格的甜点成本 题解

## 1. 题目概述

- **标题 / 题号**：最接近目标价格的甜点成本（#1774，medium）
- **链接**：https://leetcode.cn/problems/closest-dessert-cost/
- **来源**：LeetCode 第 230 场周赛 Q2
- **难度**：中等
- **标签**：数组、回溯、动态规划、背包问题

**题意**：
做一道甜点：现有 $n$ 种冰激凌基料与 $m$ 种配料。规则是**必须恰好选一种基料**；配料可以添加**一种或多种**，也可以**一种都不加**，但每种配料**最多两份**。甜点总成本 = 基料价格 + 各配料份数 × 单价。给定目标价格 $\text{target}$，返回与它**最接近**的总成本；若多个方案与 $\text{target}$ 距离相同，返回**成本相对较低**的那个。

**约束**：

- $n = \text{baseCosts.length}$，$m = \text{toppingCosts.length}$
- $1 \le n, m \le 10$
- $1 \le \text{baseCosts}[i],\ \text{toppingCosts}[i] \le 10^4$
- $1 \le \text{target} \le 10^4$

> 💡 **比赛视角**：数据范围把解法递到嘴边——$n, m \le 10$ 意味着全组合 $n \cdot 3^m \le 10 \times 59049 \approx 5.9 \times 10^5$，直接枚举就能过，**回溯是最短路径**；而「每种配料 0/1/2 份」又是教科书级的**多重背包可行性**模型，一条 DFS、一条集合 DP 都在十行以内。本题值得沉淀两样东西：「回溯 ↔ 背包」的互译模板，以及「距离最近 + 并列取低」的**双关键字比较器**。

## 2. 示例

**示例 1**

```text
输入：baseCosts = [1,7], toppingCosts = [3,4], target = 10
输出：10
解释：选 1 号基料（成本 7）+ 1 份 0 号配料（3），总成本 7 + 3 = 10，恰好命中目标。
```

**示例 2**

```text
输入：baseCosts = [2,3], toppingCosts = [4,5,100], target = 18
输出：17
解释：选 1 号基料（3）+ 1 份 0 号配料（4）+ 2 份 1 号配料（5×2），
      总成本 3 + 4 + 10 = 17。不存在总成本恰为 18 的方案。
```

**示例 3（并列取更低）**

```text
输入：baseCosts = [3,10], toppingCosts = [2,5], target = 9
输出：8
解释：可凑出 8（3 + 5，距离 1）与 10（3 + 2×5 或裸买基料，距离 1），
      距离并列，返回成本更低的 8。
```

**示例 4（必须选基料）**

```text
输入：baseCosts = [10], toppingCosts = [1], target = 1
输出：10
解释：可以不加任何配料，但必须选一种基料；10 已远超 target，加配料只会更远。
```

## 3. 解题思路

### 3.1 暴力思路：全组合三叉枚举

最朴素的做法是把解空间整个铺开：基料选 $n$ 种之一，每种配料份数 $k_i \in \{0, 1, 2\}$ 独立取值，共 $n \cdot 3^m$ 个方案，逐个算成本、维护最近者：

```text
best = +∞
for b in baseCosts:                 # n 种基料
    for (k1, …, km) in {0,1,2}^m:   # 每种配料份数的全部组合
        c = b + Σ ki·ti
        用 ( |c − target| , c ) 更新 best     # 双关键字：先近后低
return best
```

由约束 $n, m \le 10$，方案数至多 $10 \times 3^{10} = 590490$，**这个暴力在本题范围下直接能过**。但两个隐患值得警惕：

1. **指数规模对 $m$ 极敏感**：$m = 20$ 时 $3^m \approx 3.5 \times 10^9$，立刻爆炸；
2. **大量分支明显无用**：所有单价为正，一旦部分和已越过 $\text{target}$，还在埋头给后面的配料选份数——这些子树里不可能再出最优解。

### 3.2 核心观察：正价格的单调性 + 可达和的背包结构

![核心观察：成本结构、单调剪枝与可达和集合两条路线](images/wc230_q2_dessert_concept.svg)

把暴力里浪费的部分拧干，得到两个互补的观察：

**观察 A（单调剪枝）**：所有价格都是**正整数**，沿任何购买顺序部分和**只增不减**。设当前部分成本为 $\text{cur}$：

- 若 $\text{cur} \ge \text{target}$，再买任何配料只会让成本更大、距离 $\text{target}$ 更远；
- 即使后代中冒出**等距**方案，其成本也只会 $\ge \text{cur}$，而并列规则偏偏取**更低**成本——后代连「追平反超」的机会都没有。

所以进入节点时**先记录 $\text{cur}$ 这个候选**，随后若 $\text{cur} \ge \text{target}$ **整棵子树剪掉**。搜索树在每条路径上一旦越过 $\text{target}$ 就停止展开。

**观察 B（可达和集合）**：固定解空间结构 $c = b + \sum_i k_i t_i$，$k_i \in \{0,1,2\}$。基料与配料**解耦**：先把「配料加价和」的可达集合

$$
T = \Big\{\, \textstyle\sum_{i=1}^{m} k_i\, t_i \;:\; k_i \in \{0,1,2\} \,\Big\}
$$

用**多重背包可行性**的方式求出来——从 $\{0\}$ 出发，每轮并入「已可达和 $+t_i$、$+2t_i$」；再对每个基料 $b$ 与每个 $s \in T$ 组合出候选 $b + s$，双关键字取最小。上界 $U = 2\sum_i t_i \le 2 \times 10^5$，规模完全无压力。

> 💡 两条路线共用同一个**比较器**：候选 $c$ 优于 $c'$ 当且仅当 $(|c - \text{target}|,\ c)$ 按字典序小于 $(|c' - \text{target}|,\ c')$——第一关键字是距离，第二关键字是成本本身。这个元组序天然实现「距离最近、并列取低」。

### 3.3 算法流程：回溯 + 单调剪枝（比赛首选）

![回溯三叉树与剪枝：每个节点先记录候选，cur ≥ target 立即剪枝](images/wc230_q2_dessert_prune_tree.svg)

1. **初始化**：`best = baseCosts[0]`——「单基料不加配料」恒为合法候选，作保底值。
2. **外层**：以每个基料 $b$ 为根，调用 `dfs(0, b)`（`i` 为下一个待决策的配料下标，`cur` 为当前成本）。
3. **进入节点先记录**：用 $(|\text{cur} - \text{target}|,\ \text{cur})$ 双关键字更新 `best`。
4. **后剪枝 / 终止**：若 $\text{cur} \ge \text{target}$ 或 $i = m$（配料决策完毕），返回。
5. **三叉分支**：对第 $i$ 种配料分别取 $0, 1, 2$ 份，递归 `dfs(i+1, …)`。
6. 所有基料跑完，返回 `best`。

> ⚠️ **顺序不能反**：「记录 → 剪枝 → 分支」。若先剪枝再记录，会漏掉 $\text{cur}$ 本身——尤其是 $\text{cur} = \text{target}$ 的命中，以及 $\text{cur} = \text{target} + 1$ 这类「上界最近」候选。

### 3.4 示例演算

![示例 2 演算：配料和集合、两条基料线的总成本与最优 17](images/wc230_q2_dessert_walkthrough.svg)

以示例 2（`baseCosts = [2,3]`，`toppingCosts = [4,5,100]`，`target = 18`）为例。¥100 的配料一上场总价就 $\ge 102$（距离 $\ge 84$），只会被「记录后剪枝」当场处理掉，先无视它。配料 $\{4, 5\}$ 各取 $0/1/2$ 份的加价和为 $T = \{0, 4, 5, 8, 9, 10, 13, 14, 18\}$。两条基料线：

- 基料 2：总成本 $\{2, 6, 7, 10, 11, 12, 15, 16, 20\}$，最近者 $16$ 与 $20$，距离均为 $2$；
- 基料 3：总成本 $\{3, 7, 8, 11, 12, 13, 16, 17, 21\}$，最近者 $17$，距离 $1$。

沿基料 3 的最优路径走一遍回溯：

| 步骤 | 状态 | 动作 | 记录的候选 |
|------|------|------|-----------|
| ① | 以基料 3 为根 | $\text{cur} = 3$（$d = 15$），$3 < 18$ 继续分支 | $3$ |
| ② | 配料 0（¥4）取 1 份 | $\text{cur} = 7$（$d = 11$） | $7$ |
| ③ | 配料 1（¥5）取 2 份 | $\text{cur} = 17$（$d = 1$） | **17** |
| ④ | 配料 2（¥100）取 0 份 | $\text{cur} = 17$，$i = m$ 叶节点 | $17$ |
| ⑤ | 兄弟分支 +100 / +200 | $\text{cur} = 117 / 217 \ge 18$ | 记录后剪枝 ✂ |

`best` 演进 $3 \to 7 \to 17$；基料 2 那棵树最好只到 $16$（$d = 2$），不敌 $17$。注意 $18$ 本身凑不出：需要配料和 $15$（配基料 3）或 $16$（配基料 2），都不在 $T$ 中——这正是「最近」而非「恰好」的意义。

## 4. 算法细节

1. **双关键字比较器**：候选 $c$ 更优 $\iff (|c-\text{target}|,\ c) < (|\text{best}-\text{target}|,\ \text{best})$（字典序）。Python 直接比较元组一行搞定；C++ 写显式 `dc < db || (dc == db && cur < best)`，切勿写成 `dc <= db` 无条件覆盖（等距时会把大值盖到小值上）。
2. **先记录、后剪枝**：`update(cur)` 必须在 `cur >= target` 判断之前执行，否则剪枝分支上的合法候选（命中值、上界最近值）全部丢失。
3. **剪枝强度的选择**：`cur >= target` 与 `cur > target` **都正确**（$\text{cur} = \text{target}$ 时距离 $0$ 已是全局最优，后代严格更差）。用 $\ge$ 剪得更狠——省掉「全 0 份」继续空转的链；用 $>$ 更保守。本文代码取 $\ge$。
4. **`best` 的初始化**：用 `baseCosts[0]`（恒可达的合法候选），语义干净、不参与任何哨兵比较；用哨兵 $10^9$ 也可行（$|10^9 - \text{target}|$ 不溢出 `int`），但首个真实候选到来前的比较纯属浪费。
5. **DP 版的集合扩张**：`sums` 从 $\{0\}$ 出发，每轮 `sums |= {s + t, s + 2t for s in sums}`。注意上界是 $2\sum t_i$（每种**两份**），别漏乘 2。更狠的截断：总成本超过 $\text{target} + 10^4$ 的方案可安全丢弃——「最便宜基料裸买」这个保底候选的距离 $\le 10^4 - 1$ 恒存在（$\text{base} \le 10^4$，$\text{target} \ge 1$），距离 $> 10^4 - 1$ 者必非最优。
6. **数值范围**：最大总成本 $= 10^4 + 2 \times 10 \times 10^4 = 2.1 \times 10^5$，远在 `int` 之内，全程无溢出风险（对照 231 场 Q2 的 $10^{11}$ 教训，本题真正的坑在比较逻辑而非数值范围）。

## 5. 正确性证明

**引理 1（解空间刻画）**：合法甜点成本的全集为
$$
C = \Big\{\, b + \textstyle\sum_{i=1}^{m} k_i t_i \;:\; b \in \text{baseCosts},\ k_i \in \{0,1,2\} \,\Big\}.
$$

**证明**：**必要性**：任一合法方案由「所选基料 $b$ 与各配料份数 $k_i \in \{0,1,2\}$」完全决定，其成本即该式。**充分性**：任取 $b$ 与一组 $k_i$，按规则「选基料 $b$、第 $i$ 种配料加 $k_i$ 份」构造出的方案合法，成本与该式一致。∎

**引理 2（剪枝安全性）**：设某节点处部分成本 $\text{cur} \ge \text{target}$，则其子树中任何后代节点的成本 $c$ 都不优于 $\text{cur}$，即 $(|c-\text{target}|,\ c)$ 的字典序不小于 $(|\text{cur}-\text{target}|,\ \text{cur})$。

**证明**：所有单价为正，树中每向下一步的增量 $\Delta \in \{0,\ t_i,\ 2t_i\}$ 且 $t_i \ge 1$，故 $c \ge \text{cur} \ge \text{target}$。于是 $|c - \text{target}| = c - \text{target} \ge \text{cur} - \text{target} = |\text{cur} - \text{target}|$；若等号成立，则 $c = \text{cur}$，两候选的距离与成本完全相同。故子树内不存在字典序严格更小的候选；而 $\text{cur}$ 在进入节点时已被记录，剪去该子树不丢失最优解。∎

**引理 3（集合扩张完备性）**：记 $T_i = \{\sum_{j=1}^{i} k_j t_j : k_j \in \{0,1,2\}$。DP 第 $i$ 轮执行 $T_i = T_{i-1} \cup (T_{i-1} + t_i) \cup (T_{i-1} + 2t_i)$ 后，集合恰为 $T_i$。

**证明**：归纳。$i = 0$ 时 $T_0 = \{0\}$，即空选。设第 $i-1$ 轮后集合恰为 $T_{i-1}$：第 $i$ 轮的三个并集分别对应 $k_i = 0, 1, 2$ 与前 $i-1$ 种配料任意组合的乘积，故恰为 $T_i$。∎

**定理**：回溯 + 剪枝算法返回 $\arg\min_{c \in C} \big(|c - \text{target}|,\ c\big)$（字典序）。

**证明**：由引理 1，外层枚举（每个基料为根）与三叉递归（每步 $0/1/2$ 份）生成的 `cur` 集合恰为 $C$，故最优候选必在某节点处被访问。由引理 2，被剪子树不含优于其根的候选，而根已被记录，剪枝无损。`best` 的更新规则是字典序最小值的流式维护，访问候选全集后即为全局字典序最小，即「距离最近、并列取更低」。∎

> 💡 **DP 版同理最优**：由引理 1 与引理 3，$C = \{b + s : b \in \text{baseCosts},\ s \in T_m\}$，对该集合做一次双关键字 `min` 即得同一最优值。

## 6. 复杂度分析

- **时间复杂度（回溯 + 剪枝）**：最坏 $O(n \cdot 3^m)$——每棵树至多 $3^m$ 个节点，$n, m \le 10$ 时上界 $\approx 5.9 \times 10^5$；剪枝后实际访问量远小于上界（每条根到叶路径一旦越过 $\text{target}$ 即停）。
- **空间复杂度（回溯 + 剪枝）**：$O(m)$ 递归栈深度，$m \le 10$。
- **时间复杂度（背包 DP）**：$O(m \cdot U + n \cdot |T|)$，其中 $U = 2\sum t_i \le 2 \times 10^5$ 为加价和上界，总计约 $2 \times 10^6$ 次集合操作。
- **空间复杂度（背包 DP）**：$O(U)$ 存放可达和集合。

> 💡 两条路线在本题范围下都是「秒级零头」，比赛里选回溯——代码最短、剪枝写完基本不可能错；DP 的价值在于 $m$ 增大时仍保持多项式（值域）规模。

## 7. 参考代码

### C++（回溯 + 剪枝）

```cpp
class Solution {
    int best, target;
    vector<int> tops;

    void dfs(int i, int cur) {
        int dc = abs(cur - target), db = abs(best - target);
        if (dc < db || (dc == db && cur < best)) best = cur;   // 先记录
        if (cur >= target || i == (int)tops.size()) return;     // 后剪枝 / 终止
        dfs(i + 1, cur);                    // 第 i 种配料取 0 份
        dfs(i + 1, cur + tops[i]);          // 取 1 份
        dfs(i + 1, cur + 2 * tops[i]);      // 取 2 份
    }

public:
    int closestCost(vector<int>& baseCosts, vector<int>& toppingCosts, int target) {
        this->target = target;
        tops = toppingCosts;
        best = baseCosts[0];                // 单基料裸买，恒为合法候选
        for (int b : baseCosts) dfs(0, b);
        return best;
    }
};
```

### Python（回溯 + 剪枝）

```python
class Solution:
    def closestCost(self, baseCosts: List[int], toppingCosts: List[int], target: int) -> int:
        best = baseCosts[0]
        m = len(toppingCosts)

        def dfs(i: int, cur: int) -> None:
            nonlocal best
            if (abs(cur - target), cur) < (abs(best - target), best):
                best = cur
            if cur >= target or i == m:
                return
            for k in (0, 1, 2):
                dfs(i + 1, cur + k * toppingCosts[i])

        for b in baseCosts:
            dfs(0, b)
        return best
```

> 💡 Python 版用元组比较 `(距离, 成本)` 一行实现双关键字更新，天然处理「并列取更低」。

### Python（背包 DP 版）

```python
class Solution:
    def closestCost(self, baseCosts: List[int], toppingCosts: List[int], target: int) -> int:
        sums = {0}
        for t in toppingCosts:
            sums |= {s + k * t for s in sums for k in (1, 2)}
        return min((abs(b + s - target), b + s) for b in baseCosts for s in sums)[1]
```

> 💡 三行集合扩张即引理 3 的直译；最后一行对 $(\text{距离}, \text{成本})$ 取字典序最小后取第二分量。

## 8. 边界情况与易错点

1. **并列取更低成本（最高频 WA）**：示例 3 中 $8$ 与 $10$ 距 $9$ 同为 $1$，必须返回 $8$。比较逻辑必须是双关键字；写成 `dc <= da` 无条件覆盖，等距时会把大值盖上去。
2. **必须选基料、可以零配料**：示例 4 中 $\text{target} = 1$ 而最便宜基料已是 $10$，答案就是 $10$。`best` 绝不能初始化为 $0$（$0$ 不可达，却会在距离比较中「虚赢」污染答案）。
3. **先记录、后剪枝**：`update` 与剪枝判断的顺序颠倒，会漏掉剪枝节点自身的候选（尤其 $\text{cur} = \text{target}$ 的命中）。这是本解法唯一的顺序敏感点。
4. **剪枝条件 $\ge$ 与 $>$ 均正确**：差别只在 $\text{cur} = \text{target}$ 时是否继续展开「全 0 份」空转链；证明见 §5 引理 2（对两种写法都成立）。
5. **DP 版上界别忘乘 2**：加价和上界是 $2\sum t_i$（每种最多两份），写成 $\sum t_i$ 会丢掉「双份」方案。截断到 $\text{target} + 10^4$ 安全（§4 第 5 点），但非必需。
6. **无溢出**：最大总成本 $2.1 \times 10^5$，`int` 全程安全；真正的坑在比较逻辑而非数值范围（与 231 场 Q2 的 $10^{11}$ 溢出形成对照）。
7. **递归深度无压力**：$m \le 10$，Python 默认递归限制绰绰有余；若把三叉展开写成循环 + 显式栈也仅是风格差异。

**延伸思考**：若每种配料上限从 2 份放宽到 $K$ 份（$K$ 大），集合扩张退化为 $O(m \cdot U \cdot K)$，应改用**二进制拆分**的多重背包；若 $m \le 40$，转 1755 的折半枚举。若改问「成本恰等于 $\text{target}$ 的方案数」，则是 494. 目标和式的背包计数。若允许价格为 $0$ 或负数，单调性剪枝（引理 2）立即失效——这正说明「正权」是剪枝的命门，而值域 DP 只要和有界仍然可用。
