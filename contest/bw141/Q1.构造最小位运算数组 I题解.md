# LeetCode 构造最小位运算数组 I 题解

## 1. 题目概述

- **标题 / 题号**：构造最小位运算数组 I（#3314，easy）
- **链接**：https://leetcode.cn/problems/construct-the-minimum-bitwise-array-i/
- **来源**：LeetCode 第 141 场双周赛 Q1
- **难度**：简单
- **标签**：位运算、数组

**题意**：给定长度为 $n$ 的**质数**数组 `nums`，要求构造等长数组 `ans`，使每个下标 $i$ 满足

$$\text{ans}[i] \;\text{OR}\; (\text{ans}[i] + 1) = \text{nums}[i]$$

且在该等式成立的前提下，`ans[i]` 要**尽可能小**；若不存在满足等式的 `ans[i]`，则令 `ans[i] = -1`。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $2 \le \text{nums}[i] \le 1000$
- `nums[i]` 是**质数**

> **注意**：题面没有附加无关的变量注入指令，正文只有「质数」这一术语定义需要留意——它只是背景说明，不改变算法。

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,5,7]
输出：[-1,1,4,3]
解释：
  i = 0：不存在 ans[0] 使 ans[0] | (ans[0]+1) = 2，故为 -1；
  i = 1：1 | 2 = 3，最小解 1；
  i = 2：4 | 5 = 5，最小解 4；
  i = 3：3 | 4 = 7，最小解 3。
```

**示例 2**

```text
输入：nums = [11,13,31]
输出：[9,12,15]
解释：
  9  | 10 = 11；
  12 | 13 = 13；
  15 | 16 = 31。
  三者分别是各自等式的最小解。
```

**示例 3（边界自测）**

```text
输入：nums = [2]
输出：[-1]
解释：偶数天然无解，见下文性质一。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每个 `nums[i]` 从 $x = 0$ 开始逐个试，检查 $x \;\text{OR}\; (x+1)$ 是否等于 `nums[i]`，**第一个命中的 $x$ 就是最小的 `ans[i]`**（因为按值从小到大枚举）。若扫到某个上界都没命中，就返回 $-1$。

复杂度为 $O(n \cdot V)$，其中 $V$ 是枚举上界。本题 `nums[i] ≤ 1000`、$n \le 100$，即使 $V = 1000$ 也只有 $10^5$ 次位运算，完全够用。真正需要想清楚的是两件事：**上界取多少**、**哪些值根本不可能有解**。

### 3.2 核心观察：奇偶性与候选上界

![两条性质：结果必为奇数、末尾连续 1 决定进位方式](images/bw141_q1_or_properties.svg)

**性质一（奇偶性）**：$x \;\text{OR}\; (x+1)$ 恒为**奇数**。

- $x$ 为偶数时，$x+1$ 就是把最低位 $0$ 变成 $1$，其余位不变，因此 $x \;\text{OR}\; (x+1) = x + 1$，是奇数。
- $x$ 为奇数时，最低位本来就是 $1$，或运算之后仍为 $1$，所以结果也是奇数。

于是**偶数 `nums[i]` 一定无解**，直接输出 $-1$。本题 `nums[i]` 是质数，偶数质数只有 $2$，这正好解释了示例 1 里唯一的 $-1$。

**性质二（进位范围）**：设 $x$ 的二进制末尾有连续 $t$ 个 $1$（即 bit $0 \sim t-1$ 为 $1$、bit $t$ 为 $0$），则

$$x \;\text{OR}\; (x+1) = x + 2^t$$

因为 $x+1$ 会把低 $t$ 位清零、把第 $t$ 位置 $1$，而或运算又把低 $t$ 位的 $1$ 补回来。例如 $x = 3 = 011_2$，$t = 2$，$3 \;\text{OR}\; 4 = 7 = 3 + 2^2$。

**由性质二立刻得到一个候选上界**：等式 $x \;\text{OR}\; (x+1) = \text{nums}[i]$ 的左边**至少**是 $x + 1$，所以任何解都满足 $x < \text{nums}[i]$。枚举范围收成 $x \in [0, \text{nums}[i])$，既不用猜上界，也不会漏解。

### 3.3 算法流程

![算法流程：逐值枚举候选 x，命中即最小](images/bw141_q1_example_walkthrough.svg)

```text
1. ans = []
2. 对每个 n = nums[i]：
     best = -1
     for x = 0 .. n-1:
         若 (x | (x+1)) == n:  best = x;  break     # 从小到大第一个命中即最小
     ans 追加 best
3. 返回 ans
```

朴素枚举顺序天然对应「最小化」要求，不需要额外比较。

### 3.4 示例演算

![示例演算表：每个 nums[i] 的枚举过程与结果](images/bw141_q1_example_walkthrough.svg)

对 `nums = [2,3,5,7]`：

| nums[i] | 枚举过程 | 命中的 x | ans[i] |
|---------|----------|----------|--------|
| 2 | $0\|1=1$，$1\|2=3$，都不等于 2 | 无 | $-1$ |
| 3 | $1\|2=3$ | 1 | 1 |
| 5 | $3\|4=7$，$4\|5=5$ | 4 | 4 |
| 7 | $2\|3=3$，$3\|4=7$ | 3 | 3 |

对 `nums = [11,13,31]`：$9 \| 10 = 11$、$12 \| 13 = 13$、$15 \| 16 = 31$，分别得到 $9, 12, 15$，与示例 2 一致。注意 $11 = 1011_2$ 的末尾只有 $2$ 个连续的 $1$，所以候选 $x = 11 - 4 = 7$ 不成立（$7 \| 8 = 15$），必须退到 $x = 9$。

## 4. 算法细节

1. **枚举顺序**：必须**从 $0$ 往上**扫，第一个满足等式的 $x$ 就是最小值。若从大到小扫，就得额外记录并比较。
2. **候选上界**：由 $x \;\text{OR}\; (x+1) \ge x+1$，只需扫到 $\text{nums}[i] - 1$。写 `for (int x = 0; x < n; x++)` 即可，不必开到 $n$ 或固定 $1000$。
3. **无解判定**：循环结束仍未命中，`best` 保持 $-1$。也可以先用奇偶性快速返回（`n % 2 == 0` 与 `n == 2` 等价），但保留统一循环更不易写错。
4. **位运算不溢出**：$x < 1000$，$x+1$ 与或运算都在 `int` 范围内，无需 `long long`。
5. **数组尺度**：`ans` 与 `nums` 等长，逐个 `push_back` 或用下标赋值均可。
6. **与 II 版的关系**：本题靠枚举即可；II 版 `nums[i]` 可达 $10^9$，枚举退化，必须用「末尾连续 $1$ 的个数」这一结构写成 $O(1)$ 公式。思路已在上面的性质二里给出。

## 5. 正确性证明

**引理 1（上界）**：若 $x \;\text{OR}\; (x+1) = N$，则 $x < N$。

**证明**：对任意非负整数 $x$，$x \;\text{OR}\; (x+1) \ge x + 1 > x$（或运算的结果不小于任一操作数）。故 $N > x$。∎

**引理 2（无解判定）**：$N$ 为偶数时，不存在非负整数 $x$ 满足 $x \;\text{OR}\; (x+1) = N$。

**证明**：$x$ 为偶数时 $x \;\text{OR}\; (x+1) = x+1$ 为奇数；$x$ 为奇数时 bit $0$ 为 $1$，结果 bit $0$ 也为 $1$，仍是奇数。故左边恒为奇数，不可能等于偶数 $N$。∎

**引理 3（枚举完备）**：若存在解，则解必落在枚举区间 $[0, N)$ 内，且算法会命中第一个（即最小的）解。

**证明**：由引理 1，任何解都 $< N$，故区间覆盖全部解；算法按 $x = 0, 1, \dots, N-1$ 升序检验，条件与等式完全一致，因此命中的第一个 $x$ 是所有解中的最小值。∎

**定理**：算法输出的 `ans[i]` 等于满足等式的最小非负整数，若不存在则等于 $-1$。

**证明**：若存在解，由引理 3 算法返回最小的那个；若不存在，引理 3 说明整个区间内都无解，`best` 保持初值 $-1$，与题面要求一致。两种情况都对。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot V)$，其中 $V = \max \text{nums}[i] \le 1000$。每个元素最多检验 $V$ 个候选值，单次判定是 $O(1)$ 位运算；最坏 $100 \times 1000 = 10^5$ 次操作。
- **空间**：$O(1)$ 额外空间（不计输出数组）。循环只用常数个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minBitwiseArray(vector<int>& nums) {
        vector<int> ans;
        ans.reserve(nums.size());
        for (int n : nums) {
            int best = -1;
            for (int x = 0; x < n; x++) {      // 解必然 < n
                if ((x | (x + 1)) == n) {
                    best = x;                  // 升序枚举，首次命中即最小
                    break;
                }
            }
            ans.push_back(best);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minBitwiseArray(self, nums: list[int]) -> list[int]:
        ans = []
        for n in nums:
            best = -1
            for x in range(n):          # 解必然 < n
                if (x | (x + 1)) == n:
                    best = x            # 升序枚举，首次命中即最小
                    break
            ans.append(best)
        return ans
```

## 8. 边界情况与易错点

1. **`nums[i] = 2` 是唯一必错的偶数**：视野里只有质数，$2$ 是唯一的偶数质数，必定输出 $-1$；不要试图给 $x = 1$ 找补（$1 \| 2 = 3 \ne 2$）。
2. **枚举上界写错**：写成 `x <= n` 不影响正确性但多一次无用检验；写成 `x < n / 2` 会漏解（如 $n = 5$ 的解是 $4$，超过 $n/2$）。
3. **忘记 `break`**：不 `break` 会继续往后扫，最后留下的是**最大**解而不是最小解，这是本题最常见的 WA。
4. **`-1` 初值被覆盖**：只有命中时才赋值，避免在循环里无脑赋值导致无解情况输出成别的数。
5. **位运算优先级**：`(x | (x + 1)) == n` 中 `|` 的优先级低于 `==`，必须显式加括号，否则会先算 `x + 1 == n`。
6. **`nums` 长度 1**：单元素输入也要正常走完循环，不能假设 $n \ge 2$。
7. **不要硬编码公式**：本题数据小，枚举足够；若把 II 版的公式抄来用，虽然结果也对，但忽略了 Q1 的定位——先能写对，再谈优化。
