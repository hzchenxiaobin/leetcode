# LeetCode RLE 迭代器 题解

## 1. 题目概述

- **标题 / 题号**：RLE 迭代器（#900，medium）
- **链接**：https://leetcode.cn/problems/rle-iterator/
- **来源**：LeetCode 第 101 场周赛 Q1
- **难度**：中等
- **标签**：设计、数组、计数、迭代器

**题意**：给定偶数长度的游程编码数组 `encoding`，对每个偶数下标 $i$，`encoding[i]` 表示数值 `encoding[i+1]` 连续出现的次数。例如 $[3,8,0,9,2,5]$ 表示序列 $8,8,8,5,5$（计数为 0 的段等于不存在）。

要求实现迭代器 `RLEIterator`：

- `RLEIterator(int[] encoding)`：用编码数组初始化；
- `int next(int n)`：**消耗**序列中接下来的 $n$ 个元素，返回**最后一个**被消耗的元素；若剩余元素不足 $n$ 个，则把剩余元素全部消耗并返回 $-1$。

**约束**：

- $2 \le \text{encoding.length} \le 1000$，长度为偶数
- $0 \le \text{encoding}[i] \le 10^9$
- $1 \le n \le 10^9$
- 每个测试用例调用 `next` 不超过 $1000$ 次

> 💡 关键在「消耗」语义：不足 $n$ 个时并不是什么都不做，而是**把剩下的全部吃掉**，再返回 $-1$。下一次调用面对的是空序列。

## 2. 示例

**示例 1**

```text
输入：
["RLEIterator","next","next","next","next"]
[[[3,8,0,9,2,5]],[2],[1],[1],[2]]
输出：[null,8,8,5,-1]

解释：编码映射到序列 [8,8,8,5,5]。
next(2) 耗去 2 个，返回 8，剩余 [8,5,5]；
next(1) 耗去 1 个，返回 8，剩余 [5,5]；
next(1) 耗去 1 个，返回 5，剩余 [5]；
next(2) 只剩 1 个 5，耗去它后不足 2 个，返回 -1。
```

**示例 2**

```text
输入：encoding = [0,9,1,7], next(1)
输出：7
解释：计数为 0 的 [0,9] 段不存在，序列实际是 [7]。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是按 `encoding` 把整个序列**展开**成一个数组，然后用一个下标模拟消耗。正确性显然，但计数可以到 $10^9$、段数可以到 $500$，展开后的长度可达 $5 \times 10^{11}$，内存与时间都不可接受。即使只展开到「够用为止」，单次 `next` 也可能要新建上亿个元素。

### 3.2 核心观察：RLE 是惰性视图，只需两个游标

![RLE 惰性视图：编码分段 + 指针与剩余计数](images/wc101_q1_rle_lazy_concept.svg)

真正需要的信息只有两个：

1. **当前游程下标** $i$（$i$ 为偶数，指向「计数」那一格）；
2. 该游程还剩多少元素——它可以直接记录在 `encoding[i]` 里，**原地扣减**。

于是「展开」被彻底省掉：`next(n)` 从当前段开始整段整段地跳过，直到某一段的剩余计数 $\ge n$，在段内扣掉 $n$ 并返回该段的值。整个过程中 $i$ **只增不减**，每个游程最多被跨越一次，因此单次 `next` 的**均摊**代价是 $O(1)$。

### 3.3 算法流程

![next(n) 流程：整段跳 + 段内扣减](images/wc101_q1_next_flow.svg)

```text
next(n):
    当 i < len(encoding) 且 encoding[i] < n:
        n -= encoding[i]        # 整段被吃掉
        i += 2
    若 i >= len(encoding):       # 剩余元素不够 n 个
        return -1
    encoding[i] -= n            # 只吃掉当前段的一部分
    return encoding[i + 1]
```

### 3.4 示例演算

![示例演算：四次 next 调用](images/wc101_q1_walkthrough.svg)

对 `encoding = [3,8,0,9,2,5]`（序列 $8,8,8,5,5$）：

| 调用 | 动作 | 返回 | 剩余编码 |
|------|------|------|----------|
| `next(2)` | $3 \ge 2$，段内扣 2 | 8 | `[1,8] [0,9] [2,5]` |
| `next(1)` | $1 \ge 1$，扣成 0 | 8 | `[0,8] [0,9] [2,5]` |
| `next(1)` | 跳过 0 段，扣 5 | 5 | `[0,8] [0,9] [1,5]` |
| `next(2)` | 只剩 1 个 5，不够 | $-1$ | 序列耗尽 |

注意第 3 次调用：计数为 0 的 `[0,9]` 段被 `encoding[i] < n` 判为「不够」，直接跳过，无需特判。

## 4. 算法细节

1. **为什么用 `encoding[i] < n` 而不是 `<= n`**：当 `encoding[i] == n` 时，这一段恰好被吃完，但**返回值就是该段的值** `encoding[i+1]`，所以不能跳过它；把它扣成 0 后返回，语义与「最后一格」一致。下一次调用时该 0 段会被 `0 < n` 自然跳过。
2. **原地扣减**：直接改 `encoding[i]`，省掉额外的「剩余计数」变量；C++ 构造函数接收 `vector<int>&` 时会拷贝一份，不会污染调用方的数组。
3. **`i` 的奇偶不变式**：`i` 从 0 出发、每次加 2，永远是偶数，因此 `encoding[i+1]` 必然合法（只要 `i` 没越界）。
4. **越界判定**：循环结束后若 `i >= len`，说明所有段都被吃完仍不够 $n$，返回 $-1$。
5. **大整数**：$n$ 与计数都可达 $10^9$，但每次只做减法，`int` 范围内不会溢出；段内扣减也不会让计数变负。
6. **零长段**：计数为 0 的段在循环里被立刻跨越，不需要在构造时预先过滤——预过滤也能 AC，但会破坏「下标与编码一一对应」的直觉。

## 5. 正确性证明

设编码数组长度为 $2m$，第 $k$ 段为 $(\text{cnt}_k, \text{val}_k)$，$k = 0, \dots, m-1$，其对应的原序列为 $\text{val}_k$ 重复 $\text{cnt}_k$ 次（$\text{cnt}_k = 0$ 时为空）。把全部非空段依次拼接得到序列 $A$，记 $|A| = S$。

**引理 1（前缀耗尽不变式）**：每次 `next` 开始前，`encoding[0..i-1]` 中的计数全部为 0，`encoding[i]` 是第 $\lceil i/2 \rceil$ 段的剩余计数，且序列 $A$ 中尚未被消耗的部分恰好是「第 $i/2$ 段剩余部分接上其后所有段」。

**证明**：对调用次数归纳。初始 $i = 0$，没有任何段被消耗，结论显然。一次调用中，循环每执行一轮就把 `encoding[i]` 代表的整段全部消耗并把 $i$ 前移 2，这一段剩余计数归零；循环结束后对当前段扣减 $n$（可能扣成 0）。两种操作都只消耗「当前及之后」的元素，且保持「前缀全 0、$i$ 指向未耗尽段」的形式不变。∎

**引理 2（返回值语义）**：若剩余元素数 $\ge n$，`next(n)` 返回第 $n$ 个被消耗的元素；若剩余元素数 $< n$，`next(n)` 返回 $-1$。

**证明**：由引理 1，未消耗部分是以第 $i/2$ 段剩余部分开头的连续序列。循环的每一轮跨越一整段（该段长度 $< n$），相当于把「第 $n$ 个元素」的目标位置向前推，累计正好跳过了这些段的全部元素；循环退出时，目标元素一定落在第 $i/2$ 段的剩余部分之内（因为 `encoding[i] >= n`），而该段每个元素都等于 `encoding[i+1]`，故返回 `encoding[i+1]` 就是第 $n$ 个被消耗的元素。反之若 $i$ 越界，说明所有剩余元素都被跨越完仍不足 $n$ 个，此时循环已把它们全部消耗（计数归 0、$i$ 前移越过末尾），返回 $-1$ 符合题目要求。∎

**定理**：该迭代器对任意合法的调用序列，其返回值与「把 `encoding` 展开成序列 $A$ 后逐元素消耗」的朴素模拟完全一致。

**证明**：两种实现消耗的元素个数相同（引理 1 表明消耗位置逐一对应），且返回的都是「本次调用最后一个被消耗的元素」或「元素不足时的 $-1$」（引理 2）。因此对每次调用二者输出相同。∎

## 6. 复杂度分析

- **时间**：单次 `next` 中，循环跨越的每个游程都会让 $i$ 前进 2，而 $i$ 只增不减、取值范围 $[0, 2m]$，故所有调用合计最多跨越 $O(m)$ 段；段内扣减是 $O(1)$。于是 $q$ 次调用的总时间为 $O(m + q)$，**均摊**到每次 `next` 是 $O(1)$，最坏单次 $O(m)$。
- **空间**：$O(1)$ 额外空间（只维护下标 $i$）；构造时拷贝编码数组为 $O(m)$，若允许原地修改输入则可省去。

## 7. 参考代码

### C++

```cpp
class RLEIterator {
    vector<int> enc;                 // 游程编码数组
    int i = 0;                       // 当前游程的计数下标（偶数位）

public:
    RLEIterator(vector<int>& encoding) : enc(encoding) {}

    int next(int n) {
        while (i < (int)enc.size() && enc[i] < n) {
            n -= enc[i];             // 整个游程被耗尽
            i += 2;
        }
        if (i >= (int)enc.size()) return -1;   // 剩余元素不够
        enc[i] -= n;                            // 只消耗当前游程的一部分
        return enc[i + 1];
    }
};
```

### Python

```python
class RLEIterator:
    def __init__(self, encoding: List[int]):
        self.enc = encoding
        self.i = 0                       # 当前游程的计数下标（偶数位）

    def next(self, n: int) -> int:
        enc = self.enc
        while self.i < len(enc):
            if enc[self.i] >= n:         # 当前游程够用，只消耗一部分
                enc[self.i] -= n
                return enc[self.i + 1]
            n -= enc[self.i]             # 整个游程被耗尽
            self.i += 2
        return -1                        # 剩余元素不够
```

## 8. 边界情况与易错点

1. **`encoding[i] == n` 必须在本段返回**：若把循环条件写成 `<=`，恰好吃完的段会被跳过，返回下一段的值，答案整体错位。
2. **元素不足时要把剩下的吃光**：越界返回 $-1$ 之前，前面的段已经在循环里被扣成 0，语义正确；但若实现里「先判断够不够、不够就直接返回 $-1$ 而不消耗」，随后的 `next` 会重复返回旧值，示例 1 的第 4 次调用就会暴露。
3. **零长段**：`[0,9]` 这类段要能被自然跳过，循环条件 `enc[i] < n` 已覆盖；不要假设「段计数都为正」。
4. **`n` 与计数同阶**：两者都可到 $10^9$，只用减法不会溢出；但若写成「累加已消耗数量」并与总长比较，`int` 在极端数据下可能溢出（$5 \times 10^{11}$），必须用 `long long`。
5. **下标越界**：循环结束后先判 `i >= len` 再访问 `enc[i]`、`enc[i+1]`，顺序不能颠倒。
6. **单次调用最坏 $O(m)$**：虽均摊 $O(1)$，但极端情况下（大量零长段 + 小 $n$）一次调用会跨越很多段，这是允许的，总量仍线性。
7. **不要真的展开序列**：展开是本题最典型的 TLE/MLE 陷阱，计数 $10^9$ 只是障眼法。
