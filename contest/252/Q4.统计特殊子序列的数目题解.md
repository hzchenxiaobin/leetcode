# LeetCode 统计特殊子序列的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计特殊子序列的数目（#1955，hard）
- **链接**：https://leetcode.cn/problems/count-number-of-special-subsequences/
- **来源**：LeetCode 第 252 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划

**题意**：**特殊序列**由**正整数**个 `0`、紧接着**正整数**个 `1`、最后**正整数**个 `2` 三段拼成，如 `[0,1,2]`、`[0,0,1,1,1,2]`；而 `[2,1,0]`、`[1]`、`[0,1,2,0]` 都不是（乱序 / 缺段 / 2 段后回 0）。给定**只含 0/1/2** 的数组 `nums`，统计其中有多少个子序列（保序删除若干元素所得）恰好是特殊序列；两个子序列**下标集合不同**即视为不同。答案对 $10^9+7$ 取余。

**约束**：

- $1 \le n \le 10^5$——排除 $O(n^2)$ 及以上，目标一趟线性扫描；
- $\text{nums}[i] \in \{0,1,2\}$——值域恰好与三段编号一一对应，这是状态设计的入口。

> 💡 本题在本仓库另有[每日题解 1955](../../solution/1901-2000/1955_统计特殊子序列的数目.md)，两篇为姊妹篇：那边侧重「取 / 不取」的转移直觉、面试五问与计数上界。本篇按周赛复盘视角，聚焦**从考场最自然的四状态前缀 DP 出发、压缩成三计数器**的完整路径，并补上**按「最大选中下标」分类的严格归纳证明**、`+1` 项的统一解释（$f_{-1} \equiv 1$）与 C++ 中间值溢出等实战细节。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,2,2]
输出：3
解释：三个特殊子序列的下标集合分别为 {0,1,2,3}（即 [0,1,2,2] 整个序列）、
      {0,1,2}（取第 1 个 2）、{0,1,3}（取第 2 个 2）。
```

**示例 2**

```text
输入：nums = [2,2,0,0]
输出：0
解释：没有 1，凑不出「0⁺1⁺2⁺」的中间段。
```

**示例 3**

```text
输入：nums = [0,1,2,0,1,2]
输出：7
解释：7 个特殊子序列的下标集合：
      {0,1,2}、{0,1,5}、{0,1,2,5}、{0,4,5}、{0,1,4,5}、{3,4,5}、{0,3,4,5}。
```

## 3. 解题思路

### 3.1 暴力思路与「组合数的诱惑」

枚举全部子序列再逐个检查形状是 $2^n$，$n = 10^5$ 直接爆炸。但比赛里真正的坑是一个**看起来很美的组合数做法**：设数组中共有 $c_0, c_1, c_2$ 个 0/1/2，以为答案是

$$(2^{c_0}-1)(2^{c_1}-1)(2^{c_2}-1)$$

（每段从各自值的下标里非空地任选一撮）。它**只在数组按值有序时正确**：`[0,0,1,1,2,2]` 时 $= 3^3 = 27$ ✓。一旦交错就崩——示例 3 中 $c_0 = c_1 = c_2 = 2$，公式给 27，真值只有 7。原因：选了靠后的 0（下标 3），就必须放弃它之前的所有 1 和 2，**顺序约束把三段的选择耦合在了一起**，独立乘积不再成立。破局点：把「位置」作为推进维度、每一步只面对一个元素的去留决定，顺序约束便自动内建。

### 3.2 核心观察：状态 = 凑到第几段（阶段无后效性）

![核心观察：0⁺1⁺2⁺ 三段单向推进，三个计数器分阶段累计](images/wc252_q4_stage_counters_concept.svg)

值域只有 $\{0,1,2\}$ 且特殊序列的形状固定为 $0^+1^+2^+$，于是「一条正在被凑的子序列」的全部有效信息只剩：**当前凑到第几段**。

- 末段是 0 段（形态 $0^+$）：后续只能再接 0（延长）或接 1（升段），接 2 报废；
- 末段是 1 段（形态 $0^+1^+$）：后续只能再接 1 或接 2；
- 末段是 2 段（形态 $0^+1^+2^+$）：后续只能再接 2——凑成了！

阶段只增不减，且「能否接值 $v$」仅由当前阶段决定——**无后效性**成立。计数型 DP 不必记住每条子序列，只需为每个阶段维护**一个计数器**：$f_j$ = 已凑出形态 $j$ 的子序列数。给每个阶段补上位置维度，就是考场最稳的保底写法：$dp[i][j]$（前 $i$ 个元素、形态 $j$）。

### 3.3 状态转移：二维前缀表 → 三个计数器

![转移推导：dp[i][j] 前缀表与压缩成三计数器的三个观察](images/wc252_q4_dp_table_compression.svg)

设 $dp[i][j]$（$j \in \{-1, 0, 1, 2\}$，$j = -1$ 表示**空序列**）：只用前 $i$ 个元素、形态为 $j$ 的子序列数。边界 $dp[0][-1] = 1$、$dp[0][j \ge 0] = 0$。考察第 $i$ 个元素 $v$：

- **不取 $v$**：每一列原样继承上一行；
- **取 $v$ 作末元素**：形状约束要求「末元素的值 = 末段编号」（2 段的末元素只能是 2，等等），所以只有 $j = v$ 这一列变化——把 $v$ **延长**某条形态 $v$ 子序列的末段（$dp[i-1][v]$ 条），或把某条形态 $v-1$ 子序列**升段**（$dp[i-1][v-1]$ 条，$v = 0$ 时就是「空序列开局」的那 1 条）。

$$dp[i][v] = 2\,dp[i-1][v] + dp[i-1][v-1],\qquad dp[\cdot][-1] \equiv 1$$

对照上图的前缀表读出三个观察：① 「空」列恒为 1，它就是 $+1$ 项的来源；② 每行恰有一格被改写（$v$ 唯一），其余列原样继承；③ 本行只读上一行，$i$ 维可以滚动掉。于是压缩成三个标量、原地更新：

$$\boxed{\;f_v \leftarrow 2f_v + f_{v-1} \pmod{10^9+7},\qquad f_{-1} \equiv 1\;}$$

扫一遍 `nums`，遇到 $v$ 就只执行这一条公式；答案是 $f_2$。

### 3.4 示例演算

![示例演算：三计数器六步演化与 7 个下标集合](images/wc252_q4_example_walkthrough.svg)

以 `nums = [0,1,2,0,1,2]` 走一遍（`MOD` 较大，中间不取余）：

| 步 | $v$ | 转移 | $f_0$ | $f_1$ | $f_2$ | 说明 |
|----|-----|------|-------|-------|-------|------|
| 初 | — | — | 0 | 0 | 0 | 全空 |
| 1 | 0 | $f_0 \leftarrow 2\cdot0+1$ | 1 | 0 | 0 | 空序列开局 `[0]` |
| 2 | 1 | $f_1 \leftarrow 2\cdot0+f_0$ | 1 | 1 | 0 | `[0]` 升段成 `[0,1]` |
| 3 | 2 | $f_2 \leftarrow 2\cdot0+f_1$ | 1 | 1 | 1 | `[0,1]` 升段成 `[0,1,2]` |
| 4 | 0 | $f_0 \leftarrow 2\cdot1+1$ | 3 | 1 | 1 | 不取 / 延长 / 再开局 → 3 条 `0⁺` |
| 5 | 1 | $f_1 \leftarrow 2\cdot1+f_0$ | 3 | 5 | 1 | 旧 `0⁺1⁺` 翻倍 + 3 条 `0⁺` 升段 |
| 6 | 2 | $f_2 \leftarrow 2\cdot1+f_1$ | 3 | 5 | 7 | 旧 `0⁺1⁺2⁺` 翻倍 + 5 条升段 |

$f_2 = 7$ 与示例一致，7 个下标集合见上图。注意 `{0,1,2}` 与 `{0,1,5}` 取值同为 `[0,1,2]`——**按下标集合计数**，各算一个，这正是题面「不同」的定义。

## 4. 算法细节

1. **保底写法与压缩两步走**：先写 $dp[i][4]$（含 $j = -1$ 空列）的二维版，$O(4n)$ 空间、逻辑最不容易错，先过样例；再按三条观察原地压缩成 $f_0, f_1, f_2$ 三个变量。两版转移逐字等价。
2. **为什么不需要暂存旧值**：每步只写 $f_v$，读的是 $f_v$ 与 $f_{v-1}$ 的**旧值**，而 $v - 1 \ne v$，被读的变量本步不会被写——天然无读写冲突。只有推广到「一步更新多个相互依赖计数器」的题（如 940 型）才需要先拷贝旧值。
3. **$+1$ 的统一解释**：把空序列视作 $f_{-1} \equiv 1$，三个分支的公式完全同形；「开新局」只对 $v = 0$ 存在，因为 1、2 不能作为特殊序列的开头。
4. **取模时机**：每步转移后立即 `% MOD`。计数器随扫描指数增长（每遇同值翻倍），$n = 10^5$ 时不取模的数值远超 64 位。
5. **中间量防溢出（C++）**：$2f_v + f_{v-1}$ 在 $f \approx 10^9$ 时约 $3 \times 10^9 > 2^{31}-1$，计数器必须 `long long`（或拆成两次取模）。Python 天然大数，无此虞。
6. **无需特判**：缺 0、缺 1 或缺 2 时，对应计数器恒为 0 并自动向下游传导成 $f_2 = 0$（示例 2），不需要任何分支。

## 5. 正确性证明

以下称下标集合 $S$ 为**形态 $j$**（$j \in \{0,1,2\}$）子序列，若 $S$ 非空且按下标递增取值恰为 $0^{a_0}1^{a_1}\cdots j^{a_j}$（各 $a_t \ge 1$，共 $j+1$ 个非空段）。特殊子序列即形态 2 子序列。

**引理 1（末元素定阶段）**：形态 $j$ 子序列的最大下标处的值必为 $j$。

**证明**：形态 $j$ 的取值序列共 $j+1$ 段，末段全由值 $j$ 组成；子序列的最大下标对应取值序列的最后一个元素，落在末段中，值为 $j$。∎

**引理 2（前缀不变量）**：处理完前 $i$ 个元素后，$f_j$ 等于「仅使用下标 $< i$ 的形态 $j$ 子序列个数」。

**证明**：对 $i$ 归纳。$i = 0$：无非空子序列，$f_j = 0$ 成立。设 $i-1$ 时成立，考察第 $i$ 个元素 $v = \text{nums}[i-1]$。使用下标 $< i$ 的形态 $j$ 子序列按「是否含下标 $i-1$」分类：

- **不含**：即使用下标 $< i-1$ 者，由归纳假设共 $f_j^{\mathrm{old}}$ 个；
- **含**：$i-1$ 是可用下标中最大者，故它是该子序列的最大下标；由引理 1 必有 $j = v$。删去下标 $i-1$，剩余部分或为形态 $v$（末段长 $\ge 2$），或为形态 $v-1$（末段恰长 1 且非空），或为空序列（仅当 $v = 0$，单元素序列只能是 `[0]`）。反之，把 $i-1$ 追加到这三类剩余中任何一者的尾部，都还原出一个以 $i-1$ 为最大下标的形态 $v$ 子序列，且追加与删除互为逆映射——**双射**。三类剩余的数目分别为旧 $f_v$、旧 $f_{v-1}$ 与 1（后者并入 $f_{-1} \equiv 1$）。

合并两类得 $f_v^{\mathrm{new}} = f_v^{\mathrm{old}} + f_v^{\mathrm{old}} + f_{v-1}^{\mathrm{old}} = 2f_v^{\mathrm{old}} + f_{v-1}^{\mathrm{old}}$；$j \ne v$ 时「含」类为空，$f_j$ 只剩「不含」类，不变。这正是算法执行的转移。∎

**定理**：算法返回 $f_2 \bmod (10^9+7)$，等于特殊子序列总数对 $10^9+7$ 的余数。

**证明**：特殊子序列即形态 2 子序列。由引理 2，处理完全部 $n$ 个元素后 $f_2$ 恰为其总数。归纳过程中每步对非负中间值先加后模，模运算保持同余，故返回值为真值 $\bmod\ (10^9+7)$。∎

> 💡 **证明的关键动作**是「按最大选中下标分类 + 删除 / 追加末元素」的双射：它同时解释了**为什么每步只有 $f_v$ 动**（引理 1）与**公式三项的来源**（不取 / 延长末段 / 升段，含 $v=0$ 的空序列开局）。这套论证可逐字迁移到任意 $k$ 段的推广。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每步一次分支、常数次乘加与取模。
- **空间复杂度**：$O(1)$。三个标量计数器；二维保底版为 $O(4n)$，滚动压缩后与 $n$ 无关。

> 💡 对照：组合数诱惑 $O(1)$ 但**错误**；暴力 $2^n$；正确性与速度兼得的落点是「按位置推进、按值触发」的线性状态机 DP——至少要读完整个输入，$O(n)$ 已是量级下界。

## 7. 参考代码

### C++（三计数器）

```cpp
using ll = long long;
const ll MOD = 1e9 + 7;

class Solution {
public:
    int countSpecialSubsequences(vector<int>& nums) {
        ll f0 = 0, f1 = 0, f2 = 0;
        for (int v : nums) {
            if (v == 0)      f0 = (2 * f0 + 1) % MOD;  // f[-1] = 1：空序列开局
            else if (v == 1) f1 = (2 * f1 + f0) % MOD;
            else             f2 = (2 * f2 + f1) % MOD;
        }
        return (int)f2;
    }
};
```

### Python（三计数器）

```python
class Solution:
    def countSpecialSubsequences(self, nums: List[int]) -> int:
        MOD = 10**9 + 7
        f0 = f1 = f2 = 0
        for v in nums:
            if v == 0:
                f0 = (2 * f0 + 1) % MOD
            elif v == 1:
                f1 = (2 * f1 + f0) % MOD
            else:
                f2 = (2 * f2 + f1) % MOD
        return f2
```

### Python（四状态滚动数组，保底对照版）

```python
class Solution:
    def countSpecialSubsequences(self, nums: List[int]) -> int:
        MOD = 10**9 + 7
        dp = [1, 0, 0, 0]          # [空, 0⁺, 0⁺1⁺, 0⁺1⁺2⁺]，dp[0] 即 f[-1] ≡ 1
        for v in nums:
            dp[v + 1] = (2 * dp[v + 1] + dp[v]) % MOD
        return dp[3]
```

> 💡 **写法对照**：三计数器版是压缩后的最终形态；`dp[4]` 版直接翻译二维前缀表，把「空」列显式带在身边（`dp[0] ≡ 1`），单独的 `+1` 消失在 `dp[v]` 里。考场先写后者再化简，两版逐字等价。

## 8. 边界情况与易错点

1. **C++ 中间值溢出（头号陷阱）**：$2f_1 + f_0$ 最大约 $3 \times 10^9$，超 `int` 上限 $2^{31}-1 \approx 2.1 \times 10^9$；计数器必须 `long long`，或写成 `((f * 2) % MOD + g) % MOD` 拆两次取模。
2. **`+1` 只出现在 $v = 0$ 的分支**：1、2 不能开局；把它写进别的分支会凭空多出非法子序列。
3. **别套「不同的子序列 II」的去重公式**：940 按值序列去重、转移要减 `last[v]`；本题明确**按下标集合**计数，同值不同源的子序列都要算，不加任何去重项。
4. **更新顺序天然安全**：每步只写 $f_v$、只读 $f_v$ 与 $f_{v-1}$ 的旧值（$v-1 \ne v$），无需暂存、无需倒序；只有推广成一步更新多个相互依赖的计数器时才要小心。
5. **每步取模**：计数最多 $2^n$ 量级，攒到最后再模必炸（Python 也会被大整数运算拖慢）。
6. **短输入与缺值**：$n = 1$ 时 `[0]`/`[1]`/`[2]` 答案均为 0；`[2,2,0,0]`（示例 2）靠 $f_1 \equiv 0$ 自动传导成 0，无需特判。
7. **答案取 $f_2$，不是 $f_0$ 或 $f_1$**：只有三段全凑齐的形态 2 才是特殊子序列，半成品不算。
