# LeetCode 能否连接形成数组 题解

## 1. 题目概述

- **标题 / 题号**：能否连接形成数组（#1640，easy）
- **链接**：https://leetcode.cn/problems/check-array-formation-through-concatenation/
- **来源**：LeetCode 第 213 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定整数数组 `arr`，其中每个整数**互不相同**；另有一个由整数数组构成的数组 `pieces`，扁平化后所有整数也**互不相同**。问能否以**任意顺序**连接 `pieces` 中的各子数组拼成 `arr`——但**不允许**重新排列任何 `pieces[i]` 内部的整数。能拼成返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{pieces.length} \le \text{arr.length} \le 100$
- $\sum_i \text{pieces[i].length} = \text{arr.length}$（元素总数恰好相等）
- $1 \le \text{pieces[i].length} \le \text{arr.length}$
- $1 \le \text{arr[i]},\ \text{pieces[i][j]} \le 100$
- `arr` 中的整数**互不相同**；`pieces` 扁平化后的整数**互不相同**

> 💡 签到题的**最短路径**就藏在两条「互不相同」里：`pieces` 首元素唯一 ⇒ 可以当哈希键；`arr` 元素唯一 ⇒ 每一步该取哪段完全确定。识破这一点，题目形态就从「排列枚举」塌缩成「线性查表取货」。

## 2. 示例

**示例 1**

```text
输入：arr = [15,88], pieces = [[88],[15]]
输出：true
解释：依次连接 [15] 和 [88]
```

**示例 2**

```text
输入：arr = [49,18,16], pieces = [[16,18,49]]
输出：false
解释：即便数字相符，也不能重新排列 pieces[0]
```

**示例 3**

```text
输入：arr = [91,4,64,78], pieces = [[78],[4,64],[91]]
输出：true
解释：依次连接 [91]、[4,64] 和 [78]
```

## 3. 解题思路

### 3.1 暴力思路：枚举 pieces 的全排列

题面字面意思是「以任意顺序连接」，最直接的做法是枚举 `pieces` 的全部 $k!$ 种排列，逐一拼接后与 `arr` 比较，复杂度 $O(k! \cdot n)$。$k = 12$ 时已有 $12! \approx 4.8 \times 10^8$ 种排列，而本题 $k$ 最大可达 100，阶乘规模直接爆炸。

退一步的朴素做法：不建表，指针扫 `arr`，每个段起点线性扫一遍 `pieces` 找首元素匹配的段再核对——$O(k^2 + n)$，在 $n \le 100$ 下也能过。但这仍是「每一步都翻箱倒柜」，根本问题是**没有利用「整数互不相同」**——它本可把查找降为 $O(1)$、把匹配变成无分支的。

### 3.2 核心观察：首元素即「身份证」

![核心观察：首元素即身份证，建表后按 arr 顺序查表取货](images/cfa_first_key_concept.svg)

两条约束合击，问题瞬间退化：

1. **`pieces` 扁平化后互不相同** ⇒ 任意两个子数组的首元素必不相同（否则该值出现两次）⇒ **首元素唯一**，可作哈希键：$\text{first} \to \text{piece}$。
2. **`arr` 元素互不相同** ⇒ 扫描到 `arr[i]` 时，以 `arr[i]` 为首元素的 piece **至多一个**——该取哪段完全确定，**没有任何选择分支**。

于是算法变成「按 `arr` 顺序查表取货」：指针 `i` 扫 `arr`，每轮查表取回首元素为 `arr[i]` 的整段 piece，整段核对后 `i` 跳过这一段。无搜索、无回溯、无记忆化——一次线性扫描定答案。

> ⚠️ **不能只比首元素**：命中后必须**整段逐位核对**。反例：`arr = [1,2,3]`、`pieces = [[1,3,2]]`——首元素 `1` 命中，但段内顺序不符，答案应为 `false`。

### 3.3 算法流程

![算法流程：建表，查表取货，整段核对，跳段前进的循环](images/cfa_scan_match_flow.svg)

```text
1. 建表：遍历 pieces，令 first[p[0]] = p
2. i = 0
3. 当 i < n：
   a. 查表取 p = first[arr[i]]；查不到 → 返回 false
   b. 整段核对：arr[i+j] == p[j] 对 j = 0..len(p)-1；任一位不等 → 返回 false
   c. i += len(p)   （跳过整段，绝不逐位 +1）
4. i == n：arr 恰好被拼满，返回 true
```

### 3.4 示例演算

![示例演算：示例 3 三步取货跳跃前进，两种失败方式对比](images/cfa_example_walkthrough.svg)

以示例 3 为例，`arr = [91,4,64,78]`，`pieces = [[78],[4,64],[91]]`：

| 步骤 | 指针 i | 查 arr[i] | 取回 piece | 整段核对 | i 跳到 |
|------|--------|-----------|------------|----------|--------|
| ① | 0 | 91 | `[91]` | `arr[0..0] == [91]` ✓ | 1 |
| ② | 1 | 4 | `[4,64]` | `arr[1..2] == [4,64]` ✓ | 3 |
| ③ | 3 | 78 | `[78]` | `arr[3..3] == [78]` ✓ | 4 |

`i = 4 = n`，三段恰好拼满 `arr`，返回 `true`。

对照两种失败方式：示例 2 中 `i = 0` 查 `49` 即未命中（表中只有键 `16`）；反例 `arr = [1,2,3]`、`pieces = [[1,3,2]]` 中查表命中 `[1,3,2]`，但整段核对时第 2 位 `2 ≠ 3` 失败——两种失败都**即时短路**返回 `false`。

## 4. 算法细节

1. **建表**：键为 `piece[0]`，值存 piece 的**下标或引用**（C++ 存下标/地址，避免拷贝子数组本体），一趟 $O(k)$ 建完。
2. **值域开桶**：值域仅 $1 \sim 100$，可用长度 101 的数组替代哈希表（初始化 `-1`），比 `unordered_map` 常数更小。**「看到小值域就开桶」**是周赛签到题值得养成的肌肉记忆。
3. **跳跃扫描**：`i` 每轮前进整个 piece 长度，从不回退；`arr` 的每个元素至多参与一次整段核对。
4. **无需 used 标记**：同一 piece 不可能被命中两次——若在 $i' < i$ 两处命中同一段，则 `arr[i'] = arr[i]`，与 `arr` 互不相同矛盾（见 §5）。省去「已用集合」的簿记。
5. **短路返回**：查表未命中、或整段核对任一位不符，立即返回 `false`，不做多余工作。
6. **Python 切片核对**：`arr[i:i+len(p)] != p` 一行完成整段比较，且切片自动截断，天然不会越界（C++ 的越界安全性见 §8 第 5 条）。

## 5. 正确性证明

记 `arr` 长度为 $n$，`pieces` 的子数组为 $P_1, \dots, P_k$，「连接」记作 $\cdot$。

**引理 1（键唯一）**：任意两个不同的子数组 $P_a \ne P_b$ 首元素不同；从而对任意值 $v$，`pieces` 中至多一个子数组以 $v$ 为首元素。

**证明**：若 $P_a[0] = P_b[0]$（$a \ne b$），则 `pieces` 扁平化后该值至少出现两次，与「互不相同」约束矛盾。∎

**引理 2（首段强制与子问题同构）**：若存在排列 $\sigma$ 使 $P_{\sigma(1)} \cdot P_{\sigma(2)} \cdots P_{\sigma(k)} = arr$，则：

(a) $P_{\sigma(1)}[0] = arr[0]$，且 $P_{\sigma(1)}$ 逐位等于 $arr[0 .. |P_{\sigma(1)}| - 1]$；

(b) $P_{\sigma(2)} \cdots P_{\sigma(k)} = arr[|P_{\sigma(1)}| .. n-1]$，即剩余部分构成与原问题同构的子问题。

**证明**：(a) 连接结果的第 1 个元素恰为第 1 个子数组的首元素，且该子数组顺序占用 `arr` 的前 $|P_{\sigma(1)}|$ 个位置。(b) 连接按段顺序前缀占用，等式两边同时删去该前缀即得。∎

**定理**：算法返回 `true` 当且仅当存在 `pieces` 的排列连接后等于 `arr`。

**证明**：

（⇐ 充分性）设算法返回 `true`，则扫描把 `arr` 划分为连续段 $S_1, \dots, S_m$（互不重叠、总长为 $n$），第 $t$ 段逐位等于查表命中的子数组 $Q_t$，按序连接 $Q_1 \cdots Q_m$ 即重构 `arr`。再证 $Q_1, \dots, Q_m$ **两两不同**：若 $Q_s = Q_t$（$s < t$，段起点 $i_s < i_t$），则 $arr[i_s] = Q_s[0] = Q_t[0] = arr[i_t]$，与 `arr` 互不相同矛盾。于是 $\sum_t |Q_t| = n$ 恰等于**全部**子数组长度之和（约束 $\sum_j |P_j| = n$），故 $Q_1, \dots, Q_m$ 必然穷尽所有子数组，构成 `pieces` 的一个排列——存在合法拼接。

（⇒ 必要性）设存在排列 $\sigma$ 满足连接等于 `arr`。由引理 2(a)，任何合法拼接的第一段必须以 `arr[0]` 为首元素；由引理 1 这样的子数组至多一个，而 $P_{\sigma(1)}[0] = arr[0]$ 说明查表**必然命中**且命中的恰是 $Q_1 = P_{\sigma(1)}$。又 $P_{\sigma(1)}$ 逐位等于 `arr` 的前 $|P_{\sigma(1)}|$ 位，整段核对必然通过，`i` 跳到 $|P_{\sigma(1)}|$。由引理 2(b)，剩余部分「$arr$ 的后缀能否由剩余子数组拼成」与原问题同构，对段数归纳知算法逐段通过，最终 $i = n$ 返回 `true`。∎

**推论（不越界）**：整段核对中 `arr[i + j]` 恒在界内。

**证明**：设当前指针为 $i$，已匹配段覆盖 $arr[0..i-1]$，其命中的子数组两两不同，且元素全落在 $arr[0..i-1]$ 中，而当前键 $arr[i]$ 不在其中，故当前命中的 $Q$ 与它们都不同。于是已用子数组与 $Q$ 的长度之和不超过全部子数组之和 $n$，即 $i + |Q| \le n$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。建表遍历全部元素一次 $O(n)$；扫描阶段 `i` 按段跳跃、从不回退，`arr` 的每个元素恰参与一次整段核对，比较总次数 $\le n$；每轮查表 $O(1)$（哈希或值域桶）。
- **空间复杂度**：$O(k)$ 存哈希表（$k \le n$，上界 $O(n)$）；用值域桶则为 $O(C)$（$C = 101$），与 $n$ 无关。只存下标/引用，不拷贝子数组本体。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canFormArray(vector<int>& arr, vector<vector<int>>& pieces) {
        unordered_map<int, int> firstToIdx;          // 首元素 -> piece 下标
        for (int k = 0; k < (int)pieces.size(); ++k) {
            firstToIdx[pieces[k][0]] = k;
        }
        int i = 0, n = arr.size();
        while (i < n) {
            auto it = firstToIdx.find(arr[i]);
            if (it == firstToIdx.end()) return false; // 查表未命中
            vector<int>& p = pieces[it->second];      // 引用，避免拷贝
            for (int j = 0; j < (int)p.size(); ++j) {
                if (arr[i + j] != p[j]) return false; // 整段核对
            }
            i += p.size();                            // 跳过整段
        }
        return true;                                  // i == n，恰好拼满
    }
};
```

值域桶版本（值域 $1 \sim 100$，常数更小）：

```cpp
class Solution {
public:
    bool canFormArray(vector<int>& arr, vector<vector<int>>& pieces) {
        vector<int> idx(101, -1);                     // first -> piece 下标
        for (int k = 0; k < (int)pieces.size(); ++k) {
            idx[pieces[k][0]] = k;
        }
        int i = 0, n = arr.size();
        while (i < n) {
            int k = idx[arr[i]];
            if (k < 0) return false;
            vector<int>& p = pieces[k];
            for (int j = 0; j < (int)p.size(); ++j) {
                if (arr[i + j] != p[j]) return false;
            }
            i += p.size();
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canFormArray(self, arr: list[int], pieces: list[list[int]]) -> bool:
        first_to_piece = {p[0]: p for p in pieces}
        i, n = 0, len(arr)
        while i < n:
            p = first_to_piece.get(arr[i])
            if p is None or arr[i:i + len(p)] != p:
                return False
            i += len(p)
        return True
```

## 8. 边界情况与易错点

1. **只比首元素 = 经典 WA**：命中后必须整段逐位核对。反例 `arr = [1,2,3]`、`pieces = [[1,3,2]]`，首元素命中但内部顺序不符，正确答案是 `false`。
2. **`i` 跳整段，不是 +1**：逐位 +1 会让已消耗段的中部元素再去查表——如示例 3 中若 `i=2` 时查 `64` 必然未命中，错返 `false`。
3. **查表未命中即时 `false`**：如示例 2，`arr[0] = 49` 不在任何 piece 的首位。
4. **不需要回溯、不需要 used 数组**：值互不相同使匹配完全确定且段不重用（§5 定理证明）。误加回溯会无谓地把 $O(n)$ 写成指数级。
5. **整段核对的越界**：本题约束下由 §5 推论保证 `arr[i+j]` 不越界；若写不依赖 $\sum \text{len} = n$ 的通用版本，加一句 `i + len(p) <= n` 更稳。Python 切片比较天然安全。
6. **空 piece 不存在**：约束 $1 \le \text{pieces[i].length}$，建表取 `p[0]` 不会崩；若放宽约束需先跳过空段。
7. **别忽略 $\sum \text{pieces[i].length} = \text{arr.length}$**：它保证「拼满」与「用完」同时发生——返回 `true` 时所有 piece 必然全部用光（§5 充分性证明），无需再检查剩余。
