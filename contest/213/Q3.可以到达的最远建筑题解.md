# LeetCode 可以到达的最远建筑 题解

## 1. 题目概述

- **标题 / 题号**：可以到达的最远建筑（#1642，medium）
- **链接**：https://leetcode.cn/problems/furthest-building-you-can-reach/
- **来源**：LeetCode 第 213 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）、反悔贪心

**题意**：给定高度数组 `heights`、砖块数 `bricks` 与梯子数 `ladders`，从建筑 $0$ 出发依次向右移动。从建筑 $i$ 移到 $i+1$ 时：

- 若 $heights[i] \ge heights[i+1]$（下坡或等高），**免费通过**；
- 否则（上坡，设 $d = heights[i+1] - heights[i] > 0$）必须二选一：消耗**一架梯子**，或消耗 $d$ **个砖块**。

求以最佳方式使用资源时，能到达的**最远建筑下标**。

**约束**：

- $1 \le heights.length \le 10^5$——线性扫描可承受，嵌套循环不可
- $1 \le heights[i] \le 10^6$——单段差 $d \le 10^6 - 1$，涉及溢出审计
- $0 \le bricks \le 10^9$，$0 \le ladders \le heights.length$——两种资源都可能为零

> 💡 **一句话破题**：梯子是**无面额支票**（一架能跨越任意大的 gap），砖块**按面额支付**（gap 多大就花多少块）。直觉立刻浮现——**把宝贵的梯子押给最大的 gap，砖块去填小坑**。难点在于：gap 是逐段揭晓的，你不能预知后面还有没有更大的坑；本题的正解是**反悔贪心**：先让梯子占位，堆溢出时把最小的 gap「反悔」改用砖块支付。
>
> 本题在本仓库另有[每日题解 1642](../../solution/1601-1700/1642_可以到达的最远建筑.md)：侧重「最小堆降级的直白讲解、对偶的最大堆写法与面试问答」。本篇按周赛复盘视角，聚焦「二分答案路线的取舍、交换论证与堆不变式的完整证明、赛场易错清单」，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：枚举分配 / 二分答案 + 逐次验证

- **暴力一（枚举分配）**：设前缀里有 $u$ 个上坡段，每段「梯子 or 砖块」二选一，共 $2^u$ 种组合，取能走最远者。$u$ 可达 $10^5$，指数爆炸。稍聪明一点枚举「选哪些段给梯子」也是 $\binom{u}{l}$ 级别，同样不可行。病根：**在信息不全时试图一次性定死全局方案**。
- **暴力二（二分答案 + 贪心验证，赛场保底 AC 路）**：答案具有**前缀单调性**——能到 $j$ 就必然能到 $j-1$（后文引理 1），于是可以二分最远下标 $r$，`check(r)` 收集前缀 $[1..r]$ 的全部正差、排序后把最大的 $\min(m, ladders)$ 个给梯子、其余求和与 $bricks$ 比较。单次 $O(n \log n)$，总 $O(n \log^2 n)$，$n = 10^5$ 下约 $10^8$ 量级的常数级运算，能过但写起来又长又险。

二分的浪费一眼可见：**每做一次 check 都从头重算 top-$l$，而前缀每延长一段，top-$l$ 候选集至多变化一个元素**。「排序取前 $l$ 大」这个结构本来就是**增量可维护**的——数据结构教材里它的名字叫**最小堆维护 top-K**。把二分砍掉，一遍扫描即得正解。

### 3.2 核心观察：交换论证 + 反悔贪心

![核心观察：梯子押给最大的 gap，砖块按面额付小 gap](images/wc213_q3_ladder_for_biggest_gap_concept.svg)

**观察 1（可达集是前缀）**：到达 $j$ 的任何方案，其前 $j-1$ 段的支付本身就是到达 $j-1$ 的方案。因此可达集合形如 $\{0, 1, \dots, R\}$，问题等价于求**最长可行前缀**——这是二分答案可行的原因，也是「一路扫到走不动为止」的线性算法的合法性来源。

**观察 2（梯子押最大——交换论证）**：设某方案中梯子支付了较小的差 $a$，而砖块支付了较大的差 $b$（$a < b$）。把两者交换：梯子改付 $b$、砖块改付 $a$，砖块消耗变化 $-b + a < 0$，严格变省。于是**任何方案都可经若干次交换变成「梯子付最大的 $\min(m, ladders)$ 个正差」且砖耗不增**——最优分配结构唯一确定：

$$\text{前缀可行} \iff \text{top-} \min(m, l) \text{ 之外的正差之和} \le bricks$$

**观察 3（最小堆增量维护 top-$l$）**：从左到右扫描，维护一个**最小堆**充当「梯子组」：

- 新正差 $d$ **无条件入堆**（先占住梯子位，哪怕暂时超编）；
- 若堆大小超过 $ladders$，**弹出堆顶**（当前最小的 gap）——它正是被挤出 top-$l$ 的那一个——改用砖块支付，$bricks \mathrel{-}= \text{堆顶}$；
- 若砖块赤字（$bricks < 0$），当前前缀不可行，返回 $i$。

> ⚠️ **为什么必须「先入堆再弹」，不能「先比较再决定用不用梯子」**：假设堆已满（$l$ 个梯子位占满），新来一个差值就立刻用砖块支付——那这架「被挤掉」的梯子到底该给谁？如果后面的差比堆里某个元素大，此刻的砖块就花冤枉了。正确姿势是**先入堆再挑最小的踢出**：被踢出的永远是截至目前最小的 $l+1$ 个中的落选者，梯子始终留给截至目前最大的 $l$ 个。这正是「反悔」二字的含义——**贪心决策不必一次定终身，用堆把已做的决策存起来，资源不够时换回最划算的那单**。

### 3.3 算法流程：一遍扫描 + 最小堆降级

![算法流程：入堆占位、溢出降级、砖块赤字即停](images/wc213_q3_minheap_scan_flow.svg)

```text
1. 建空最小堆 heap（存放「当前由梯子支付的正差」）
2. for i = 0 .. n−2：
     d ← h[i+1] − h[i]
     若 d ≤ 0：continue                    # 下坡/等高，免费
     push(heap, d)                          # 先占梯子位
     若 size(heap) > ladders：              # 梯子超编
         x ← pop(heap)                      # 弹出最小的 gap
         bricks −= x                        # 反悔：这单改用砖块付
     若 bricks < 0：返回 i                  # 砖块赤字，最远到 i
3. 循环自然结束：返回 n−1                   # 走完全程
```

### 3.4 示例演算：示例 1 全程走查

![示例演算：示例 1 逐步走查，梯子付 5、砖付 3、赤字止步](images/wc213_q3_example_walkthrough.svg)

以示例 1 为例，`heights = [4,2,7,6,9,14,12]`，`bricks = 5`，`ladders = 1`：

| 步 | 段 | $d$ | 堆（梯子组） | 砖余额 | 动作 |
|----|--------|-----|--------------|--------|------|
| ① | 4→2 | −2 | ∅ | 5 | 下坡免费 |
| ② | 2→7 | +5 | {5} | 5 | 入堆占梯子位，size 1 ≤ 1 ✓ |
| ③ | 7→6 | −1 | {5} | 5 | 下坡免费 |
| ④ | 6→9 | +3 | {3,5}→{5} | 2 | 入堆超编 → 弹 3 用砖，5−3=2 |
| ⑤ | 9→14 | +5 | {5,5}→{5} | −3 | 弹 5 用砖，2−5=−3 ✗ → **返回 4** |

**步 ④ 是全题的戏眼**：$d=3$ 来的时候梯子位已被 5 占着，**不是**「梯子已满就直接给 3 用砖」——而是让 3 入堆、由堆来裁决谁留谁走。弹 3 留 5，等价于宣布「这两个 gap 里，梯子给大的」。步 ⑤ 第二个 5 入堆后再弹 5（两个 5 相等，弹谁都一样），砖块 $2-5=-3$ 赤字，前缀 $[0..5]$ 不可行，最远建筑即 $i=4$ ✓。

> 💡 **贪错的代价看得见**：本例里即使把梯子错配给 3（砖付 5），也能勉强到 4，但砖块一分不剩（0 vs 正确配法的 2）。把砖块改成 4 再看：错配方案 $4-5 < 0$ 连楼 4 都上不去，正确配法 $4-3=1$ 依旧登顶——**贪心省下的每一块砖，都是后面的路**。

## 4. 算法细节

1. **「先入堆再弹」的顺序不可颠倒**：这是反悔贪心的骨架。先 push 后判 `size > ladders` 再 pop，保证堆中始终是「迄今最大的 $\min(\text{正差数}, l)$ 个」；写成「先判断堆满再决定」会把本该用梯子的大 gap 提前花掉砖块。
2. **弹堆顶即「降级」，砖块赤字即「终止」**：`bricks -= heap.top()` 之后**立刻**检查 `< 0`，失败返回的是当前所在下标 $i$（失败段的左端点），不是 $i+1$。
3. **对偶写法（最大堆反悔）**：也可以一开始全用砖块、把差值压入**最大堆**，砖块赤字时弹**最大**的已付差值退还砖块、改用一架梯子，梯子用尽仍赤字则停。两写法完全对称：最小堆维护「梯子组」溢出降级，最大堆维护「砖块组」赤字升级。最小堆版无须在赤字时回溯，更简洁（详见每日题解第 5 节）。
4. **`ladders = 0` 的退化**：每个正差入堆后立即因 `size > 0` 被弹出扣砖，堆始终为空，算法退化为线性累加正差、首次赤字即停，$O(n)$ 时间 $O(1)$ 空间。**`ladders` 巨大**（≥ 正差总数）时堆永不满、砖块一块不花，直接走完全程。
5. **堆的容量**：push 后至多超标 1 再弹回，堆大小 $\le ladders + 1$，空间 $O(\min(n, ladders+1))$；堆操作代价 $O(\log \min(n, l+2))$。
6. **C++ 堆的方向**：`priority_queue<long long, vector<long long>, greater<long long>>` 是最小堆（默认 `less` 是最大堆，方向写反全程弹最大值，答案错得毫无规律）。

## 5. 正确性证明

**引理 1（前缀封闭）**：若能到达下标 $j$（$j \ge 1$），则能到达 $j-1$。因此可达集合形如 $\{0, 1, \dots, R\}$。

**证明**：到达 $j$ 的方案由「每一段的支付方式」构成；截取其前 $j-1$ 段，是一个资源消耗只少不多的、到达 $j-1$ 的合法方案。∎

**引理 2（最优分配结构）**：设前缀 $[0..j]$ 内正差集合为 $D = \{d_1, \dots, d_m\}$，$k = \min(m, ladders)$。该前缀可达，当且仅当「$D$ 中最大的 $k$ 个用梯子、其余用砖」时砖块消耗 $\le bricks$。

**证明**：（⇐）该分配本身是合法方案，消耗即为其余正差之和。（⇒）设某可行方案中梯子支付集合 $L$（$|L| \le ladders$）、砖块支付 $D \setminus L$，且存在 $a \in L$、$b \notin L$ 满足 $a < b$。交换二者：$L' = L \setminus \{a\} \cup \{b\}$，梯子数不变，砖块消耗变化 $-b + a < 0$，仍可行。每次这样的交换严格减少「$L$ 与 top-$k$ 的不一致对数」，有限步后 $L$ 变为最大的 $k$ 个（$|L| < k$ 时若有未被梯子支付的差，直接补一架梯子只会更省），且砖块消耗不增，故 top-$k$ 分配也满足 $\le bricks$。∎

**引理 3（堆不变式）**：算法按 3.3 扫描，若前 $t$ 段均未触发返回，则处理完第 $t$ 段后：最小堆恰含「前 $t$ 段全部正差中最大的 $\min(m_t, ladders)$ 个」（$m_t$ 为前 $t$ 段正差总数），且 `bricks` 的累计减少量 = 其余正差之和。

**证明**：对 $t$ 归纳。$t = 0$：空堆、零消耗，成立。设 $t$ 时成立，处理第 $t+1$ 段：

- 若该段 $d \le 0$：无操作，$m_{t+1} = m_t$，不变式保持。
- 若 $d > 0$：push 后堆 = 旧 top-$\min(m_t, l)$ 与 $\{d\}$ 之并。若 $m_t + 1 \le ladders$，堆含全部 $m_t + 1$ 个正差，恰为 top-$(m_{t+1})$，无弹出、砖不变，成立。若 $m_t + 1 > ladders$（即 $m_t \ge ladders$），归纳假设堆原含最大的 $l$ 个，push $d$ 后堆中是「旧 top-$l$ ∪ $\{d\}$」这 $l+1$ 个数，弹出的堆顶是这 $l+1$ 个中的最小者——恰为新前缀 top-$l$ 的落选者（若它在 top-$l$ 内，则 top-$l$ 外还有更大的 $l$ 个，矛盾）；弹出并扣砖后，堆 = 新 top-$l$，砖耗恰增该落选者之值，成立。∎

**定理（算法正确性）**：算法的返回值 $R$ 是最大可达下标。

**证明**：分两种情形。

- **全程未失败**：每段处理完 `bricks` ≥ 0。由引理 3，对每个前缀 $[0..j]$（$1 \le j \le n-1$），算法内部的堆与砖耗恰构成引理 2 的 top-$k$ 分配且消耗 $\le bricks$，由引理 2 各前缀均可达，$R = n-1$。
- **首次失败于段 $t$（连接 $t$ 与 $t+1$）**：处理该段时（无论是否弹出）后 `bricks` < 0。由引理 3，此刻「堆 + 砖耗」恰为前缀 $[0..t+1]$ 的 top-$k$ 分配，其砖块消耗 $> bricks$，由引理 2 前缀 $[0..t+1]$ 不可达，结合引理 1 得 $R \le t$；而段 $t-1$ 处理完时未失败，同法可证前缀 $[0..t]$ 可达，$R \ge t$。故 $R = t$，即算法返回值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，更精确地是 $O\bigl(n \log \min(n, ladders + 2)\bigr)$。每个正差至多一次 push、一次 pop，共 $\le 2(n-1)$ 次堆操作，每次 $O(\log)$ 于堆大小（$\le ladders + 1$）；`ladders = 0` 时退化为 $O(n)$。$n = 10^5$ 时堆高至多 17 层，轻松通过。
- **空间复杂度**：$O(\min(n, ladders + 1))$，即堆容量。`ladders` 与 $n$ 同阶时为 $O(n)$；`ladders` 很小时接近 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int furthestBuilding(vector<int>& heights, int bricks, int ladders) {
        // 最小堆：当前由梯子支付的正差（梯子组 = 迄今最大的 l 个 gap）
        priority_queue<long long, vector<long long>, greater<long long>> heap;
        long long rest = bricks;                  // 剩余砖块
        int n = heights.size();
        for (int i = 0; i + 1 < n; ++i) {
            long long d = heights[i + 1] - heights[i];
            if (d <= 0) continue;                 // 下坡/等高：免费
            heap.push(d);                         // 先占住梯子位
            if ((int)heap.size() > ladders) {     // 梯子超编
                rest -= heap.top();               // 反悔：最小的 gap 改用砖
                heap.pop();
            }
            if (rest < 0) return i;               // 砖块赤字，最远到 i
        }
        return n - 1;                             // 走完全程
    }
};
```

### Python

```python
import heapq

class Solution:
    def furthestBuilding(self, heights: List[int], bricks: int, ladders: int) -> int:
        heap = []                                  # 最小堆：梯子组
        for i in range(len(heights) - 1):
            d = heights[i + 1] - heights[i]
            if d <= 0:                             # 下坡/等高：免费
                continue
            heapq.heappush(heap, d)                # 先占住梯子位
            if len(heap) > ladders:                # 梯子超编
                bricks -= heapq.heappop(heap)      # 反悔：最小的 gap 改用砖
            if bricks < 0:                         # 砖块赤字，最远到 i
                return i
        return len(heights) - 1                    # 走完全程
```

## 8. 边界情况与易错点

1. **返回值是失败段的左端点 $i$**：循环变量 `i` 处理「$i \to i+1$」这段，失败即「到不了 $i+1$」，最远建筑是 $i$。写成 `return i + 1` 或 `i - 1` 都是差一错误。
2. **每次扣砖后立即判负**：`bricks -= x` 与 `if (bricks < 0)` 必须同轮成对出现。攒到最后统一判，中途已赤字的堆状态就不可信了。
3. **溢出审计**：本算法单次扣砖至多使 `bricks` 降到 $-(10^6 - 1)$ 且当轮即查，`int` 恰好安全；但若改写成「累计总消耗 `sum` 再与 `bricks` 比较」，总和至多 $10^5 \times 10^6 = 10^{11}$，**必须 `long long`**。参考代码统一用 `long long` 是零成本保险。
4. **`ladders = 0`**：堆每入即弹、始终为空，逻辑自然退化，无须特判（手写特判反而容易漏 `d <= 0` 的免费段）。
5. **`ladders ≥` 正差总数**：堆永不满，砖块一块不花，直接返回 $n-1$；同样无须特判。
6. **$n = 1$**：循环不执行，返回 $0$。
7. **等高段**：$h[i+1] = h[i]$ 时 $d = 0$，免费、不入堆——`d <= 0` 的判断把等高和下坡一并挡掉。
8. **C++ 最小堆方向**：`priority_queue` 默认是**最大堆**，必须显式写 `greater<long long>`；方向反了等于「梯子留给最小的 gap」，恰好把贪心做反，样例都过不了。
9. **走二分答案路线的坑**：`check` 里必须「排序取 top-$l$」，不能「梯子优先付先遇到的 gap」——那正是交换论证否定的错误结构；另外 `check` 的 $r$ 上界是 $n-1$，二分边界建议闭区间写法。
10. **相等差值弹谁都行**：堆内出现重复值（如示例 1 的两个 5）时弹出任何一个都对应相同的砖耗，不影响正确性。

**延伸思考**：

- **反悔贪心的通用模板**：当「每一步的局部最优选择依赖未来信息」时，让决策先入袋（占位），维护一个按「反悔收益」排序的堆；资源不足或更优者到来时，弹出堆顶反悔。本题反悔收益 = 弹出的 gap 值（越小越该反悔），630 是耗时（越长越该退），871 是油量（越多越该喝）。识别「对称的资源结构」是套模板的第一步。
- **三种资源会怎样**：若再添一种「按面积计费的直升机」，贪心结构不再可交换排序（三种支付方式两两之间无可比的全序），一般需要更复杂的建模（如凸优化 / 流），堆反悔不再够用。
- **如果允许向左走**：支付仍只发生在向上爬时，而向左再向右会重复爬同一段上坡——答案不变，反悔贪心依旧最优，但证明里要补「最优解不会回头」的引理。
- **同场复盘**：第 213 场是一条「模拟签到 → 组合计数 → 贪心反悔 → 组合定位」的阶梯——Q3 是**分水岭**：识破「梯子无面额、砖块按面额」的双资源结构，配上最小堆反悔，$O(n \log n)$ 干净收尾；识不破则在二分 + 排序的 $O(n \log^2 n)$ 里打转，甚至陷进指数枚举。Q3 的启示：**两种资源取用时，先问「谁该用贵的」——一次交换论证，胜过千万次枚举**。
