# LeetCode 第 K 条最小指令 题解

## 1. 题目概述

- **标题 / 题号**：第 K 条最小指令（#1643，hard）
- **链接**：https://leetcode.cn/problems/kth-smallest-instructions/
- **来源**：LeetCode 第 213 场周赛 Q4
- **难度**：困难
- **标签**：数组、数学、动态规划、组合数学

**题意**：Bob 站在 $(0, 0)$，要去 `destination = [row, column]`，只能**向右**（指令字符 `'H'`）或**向下**（指令字符 `'V'`）走。一条**指令**是长为 $row + column$ 的字符串，合法当且仅当它恰含 $column$ 个 `'H'` 与 $row$ 个 `'V'`。把所有合法指令按**字典序**升序排列（`'H'` 的 ASCII 为 72、`'V'` 为 86，故 `'H' < 'V'`），返回第 $k$ 小的那条（$k$ 从 1 开始编号）。

**约束**：

- `destination.length == 2`，$1 \le row, column \le 15$——指令长度 $n = row + column \le 30$
- $1 \le k \le \binom{row + column}{row}$——$k$ 必落在合法范围内，总数至多 $\binom{30}{15} = 155\,117\,520 \approx 1.55 \times 10^8$

> 💡 翻译一下：这是**求多重集（$column$ 个 `H` + $row$ 个 `V`）的全排列中字典序第 $k$ 小者**——康托展开的「多重集版」。本场 Q2（#1641）问「有多少条」，本题问「第 $k$ 条是哪条」：计数与定位是一枚硬币的两面，而定位的正解是**数块跳块**——用组合数一步算出一整块的条数，整块整块地跳过去，而不是一条一条生成。
>
> 本题在本仓库另有[每日题解 1643](../../solution/1601-1700/1643_第K条最小指令.md)：侧重「康托展开的视角、多重集通用化公式与面试问答」。本篇按周赛复盘视角，聚焦「row/column 与 H/V 的对应、分块计数的证明、逐位确定的不变式与赛场易错清单」，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：生成再排序 / 逐条跳

- **暴力一（生成 + 排序）**：回溯生成全部 $\binom{row+column}{row}$ 条指令再排序取第 $k$ 条。最坏 $\binom{30}{15} \approx 1.55 \times 10^8$ 条、每条 30 字符——光存放就要约 4.8 GB，排序比较更是天文数字，内存与时间双爆炸。
- **暴力二（`next_permutation` 逐条跳）**：从最小串 `HH...HVV...V` 出发连跳 $k-1$ 步。免掉了存储，但最坏仍要 $1.55 \times 10^8$ 次调用、每次从右向左找转折点——C++ 赌常数贴着时限，Python 直接出局。

两条路病根一致：**只要第 $k$ 条，却把前 $k$ 条全部生成了一遍**。字典序定位问题的正解从来不是「生成」，而是「计数」——先算出一整块有多少条，就能整块整块地跳。

### 3.2 核心观察：数块跳块——组合数定界，逐位确定

![核心观察：字典序按首字符分块，数块跳块](images/wc213_q4_block_partition_concept.svg)

**观察 1（合法指令 = 多重集排列）**：合法指令与「$column$ 个 `H`、$row$ 个 `V` 组成的多重集排列」一一对应，总数 $\binom{row+column}{row}$（在 $n$ 个位置里选 $row$ 个放 `V`）。

**观察 2（字典序按首字符分块）**：设某一步还剩 $h$ 个 `H`、$v$ 个 `V` 待定。所有候选串按下一字符切成两块：

| 块 | 首字符 | 条数 | 含义 |
|----|--------|------|------|
| H 块 | `'H'` | $\binom{h+v-1}{v}$ | 定下 `'H'` 后，剩余 $h-1$ 个 `H`、$v$ 个 `V` 的排列数 |
| V 块 | `'V'` | $\binom{h+v-1}{h}$ | 定下 `'V'` 后，剩余 $h$ 个 `H`、$v-1$ 个 `V` 的排列数 |

由 **Pascal 恒等式**两块之和恰为 $\binom{h+v}{h}$（当前总数）——分块**不重不漏**。又因 `'H' < 'V'` 且所有串等长，**H 块整体排在 V 块之前**。

**观察 3（前缀不影响后缀的相对序）**：块内所有串共享相同前缀，它们之间的字典序完全由后缀决定，而后缀正是剩余多重集的全体排列。于是「块内第 $k$ 小」=「定下这一位后，继续在剩余多重集上做同样的定位」——**同一个子问题**，逐位归纳即得完整算法。

于是每一步只做一次比较：

- 若 $k \le \binom{h+v-1}{v}$：第 $k$ 条落在 H 块，本位填 `'H'`，$h \gets h-1$，**$k$ 不变**；
- 否则：跳过整个 H 块，本位填 `'V'`，$v \gets v-1$，$k \gets k - \binom{h+v-1}{v}$。

> ⚠️ **为什么选 `V` 才减 $k$**：选 `'H'` 时目标仍在 H 块内，而 H 块是当前候选序列的前 $\binom{h+v-1}{v}$ 条，块内相对排名仍是 $k$；只有跳进 V 块时，排名才要减去被整块跳过的条数。这正是康托展开解码的标志性操作。

### 3.3 算法流程：杨辉三角 + 逐位确定

![算法流程：预计算杨辉三角，再逐位数块跳块](images/wc213_q4_digit_by_digit_flow.svg)

```text
1. 预计算杨辉三角 C[0..n][0..n]（n = row + column）
   —— C[i][j] = C[i−1][j−1] + C[i−1][j]，标签里「动态规划」的来由
2. h ← column（'H' 的个数），v ← row（'V' 的个数），ans ← 空串
3. 循环，直到 h = 0 或 v = 0：
     block ← C[h−1+v][v]                    # 首字符填 'H' 的条数
     若 k ≤ block：ans += 'H'，h ← h−1      # 落在 H 块，k 不变
     否则：        k ← k−block，ans += 'V'，v ← v−1   # 跳过 H 块
4. 收尾：剩余位置全填同一种字符（ans += 'H'×h + 'V'×v），返回 ans
```

### 3.4 示例演算：destination = [2,3]，k = 5

![示例演算：k=5 逐位确定，得 HVHVH](images/wc213_q4_k5_walkthrough.svg)

$h = 3$、$v = 2$，在 $\binom{5}{2} = 10$ 条中定位第 5 条，逐位走查：

| 步 | 已定前缀 | $h, v$ | $\text{block} = \binom{h+v-1}{v}$ | $k$ 与块 | 动作 |
|----|---------|--------|-----------------------------------|----------|------|
| ① | （空） | 3, 2 | $\binom{4}{2} = 6$ | $5 \le 6$ ✓ | 填 `'H'`，$k$ 不变 |
| ② | `H` | 2, 2 | $\binom{3}{2} = 3$ | $5 > 3$ ✗ | $k \gets 5-3=2$，填 `'V'` |
| ③ | `HV` | 2, 1 | $\binom{2}{1} = 2$ | $2 \le 2$ ✓ | 填 `'H'`，$k$ 不变 |
| ④ | `HVH` | 1, 1 | $\binom{1}{1} = 1$ | $2 > 1$ ✗ | $k \gets 2-1=1$，填 `'V'` |
| ⑤ | `HVHV` | 1, 0 | —（$v=0$ 收尾） | — | 补 `'H'` |

答案 **`"HVHVH"`**，与示例 1 排序表的第 5 条一致 ✓。**步 ② 是精髓**：此刻若填 `'H'`，以 `HH` 开头的串只有 $\binom{3}{2} = 3$ 条（`HHHVV`、`HHVHV`、`HHVVH`），而 $k = 5$ 超过 3——目标不在这一块，整块跳过（$k \gets 2$），在「`H` 后接 `V`」的块内继续定位。步 ④ 同理再跳 1 条。**两步共跳 $3 + 1 = 4$ 条，收尾落位第 1 条，$4 + 1 = 5$**——排名账目严丝合缝。

## 4. 算法细节

1. **row / column 与 H / V 的对应（本场头号坑）**：`destination = [row, column]`，**`V` 的个数 = row**（向下走行号 +1），**`H` 的个数 = column**（向右走列号 +1）。写反后 $k=1$ 会输出 `VV...HH`，而 `[2,3]` 的样例恰好对称、错得不显眼——务必用 $k=1 \Rightarrow$ `"HHHVV"` 自检。
2. **杨辉三角即 DP**：$C[i][j] = C[i-1][j-1] + C[i-1][j]$、$C[i][0] = 1$，双重循环填表 $O(n^2)$（$n \le 30$，约 465 次加法）——标签里的「动态规划」指的就是这张表。Python 亦可直接 `math.comb` 逐步现算。
3. **块大小公式的两种写法**：$\binom{h+v-1}{v} = \binom{h+v-1}{h-1}$，怎么顺手怎么来；循环条件 `while (h && v)` 保证下标 $h-1+v \ge 0$ 恒成立。
4. **收尾放在循环外**：`h = 0` 或 `v = 0` 时退出循环、把剩余位置一次性补齐。此刻合法补全只剩一种，不变式保证 $k = 1$，无须再比较（若坚持在循环内算块，$h = 0$ 时会碰到 $\binom{v-1}{v}$ 这类「下出界」组合数，语义含糊）。
5. **比较与减法只在「进 V 块」时发生**：填 `'H'` 不动 $k$；填 `'V'` 前先 `k -= block`。「先判后减」，别写成先减再判。
6. **数据规模审计**：全表最大值 $\binom{30}{15} = 155\,117\,520 < 2^{31} - 1 \approx 2.15 \times 10^9$，`int` 恰好装得下、杨辉三角中间值同界；C++ 用 `long long` 是零成本保险，Python 原生大整数无此虑。

## 5. 正确性证明

**引理 1（合法指令 ↔ 多重集排列）**：从 $(0,0)$ 出发的指令串能到达 $(row, column)$，当且仅当它恰含 $column$ 个 `'H'` 与 $row$ 个 `'V'`；此类串共 $\binom{row+column}{row}$ 条。

**证明**：每步移动使坐标和 $x + y$ 恰增 1，而终点坐标和为 $row + column$，故指令长度必为 $row+column$；到达 $(row, column)$ 当且仅当水平位移总和为 $column$、竖直位移总和为 $row$，即 `'H'`、`'V'` 的个数分别为 $column$、$row$。在此前提下任意排列都合法（右移与下移的先后不影响可达性）。计数：在 $row+column$ 个位置中选 $row$ 个放 `'V'`。∎

**引理 2（块计数与划分）**：设剩余 $h$ 个 `'H'`、$v$ 个 `'V'`，某固定合法前缀的全体补全共 $\binom{h+v}{h}$ 条，按下一字符分成两块：填 `'H'` 的 $\binom{h+v-1}{v}$ 条在前，填 `'V'` 的 $\binom{h+v-1}{h}$ 条在后。

**证明**：补全即剩余多重集的排列，由引理 1 的计数即得总数与两块的大小。任取 H 块串 $s$ 与 V 块串 $t$：二者下一字符不同且 `'H' < 'V'`，而所有串等长，故 $s < t$——H 块整体在前。两块之和由 Pascal 恒等式 $\binom{h+v-1}{v} + \binom{h+v-1}{h} = \binom{h+v}{h}$ 等于总数，划分不重不漏。∎

**引理 3（公共前缀下的相对序）**：设 $P$ 为固定前缀，$s_1, s_2$ 是下一字符相同的两个补全，则 $Ps_1 < Ps_2 \iff s_1 < s_2$。

**证明**：比较 $Ps_1$ 与 $Ps_2$ 时，前缀 $P$ 与共同的下一字符逐位相同，首个差异出现在 $s_1$ 与 $s_2$ 对应的位置，故字典序关系由 $s_1, s_2$ 完全决定。∎

**定理（逐位确定算法的正确性）**：算法输出的串是全部合法指令中字典序第 $k$ 小的。

**证明**：对剩余长度归纳，维护不变式：**当前已定前缀 $P$、剩余 $h$ 个 `'H'` 与 $v$ 个 `'V'`，所求答案是「$P$ 的全体合法补全」中字典序第 $k$ 小者**。初始 $P$ 为空、$k$ 为题给排名，成立。每轮由引理 2，补全按下一字符分为 H 块（前 $\binom{h+v-1}{v}$ 条）与 V 块：

- 若 $k \le \binom{h+v-1}{v}$：目标在 H 块内，且 H 块是候选序列的前 $\binom{h+v-1}{v}$ 条，故目标在块内排名仍为 $k$；由引理 3，这等价于「$P$ 加 `'H'` 后的补全」中第 $k$ 小——算法填 `'H'`、$k$ 不变，不变式保持。
- 否则目标在 V 块，其前有整块 $\binom{h+v-1}{v}$ 条，块内排名为 $k - \binom{h+v-1}{v}$；由引理 3 同理，算法填 `'V'` 并同步减 $k$，不变式保持。

当 $h = 0$ 或 $v = 0$ 时补全唯一，不变式中 $1 \le k \le \binom{h+v}{h} = 1$ 迫使 $k = 1$，算法补齐剩余字符恰为该唯一补全。归纳至长度归零，输出即全局第 $k$ 小。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$，$n = row + column \le 30$。杨辉三角预计算 $O(n^2)$（约 465 次加法），主循环 $n$ 轮、每轮 $O(1)$ 查表比较；若用 `math.comb` 每步现算，单次 $O(\min(h, v))$，总计 $O(n \cdot \min(h,v)) \le 450$，同一量级。**关键在于完全没有枚举 $\binom{n}{row}$ 条排列**——把指数级的生成压成了多项式级的构造。
- **空间复杂度**：$O(n^2)$ 存杨辉三角（至多 $31 \times 31$）；改为逐步现算组合数可降到 $O(1)$ 附加空间（输出串不计入）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string kthSmallestPath(vector<int>& destination, int k) {
        int v = destination[0];               // row 个 'V'（向下）
        int h = destination[1];               // column 个 'H'（向右）
        int n = h + v;

        // 杨辉三角：C[i][j] = C(i, j)，标签里「动态规划」即此表
        vector<vector<int>> C(n + 1, vector<int>(n + 1, 0));
        for (int i = 0; i <= n; ++i) {
            C[i][0] = 1;
            for (int j = 1; j <= i; ++j)
                C[i][j] = C[i - 1][j - 1] + C[i - 1][j];
        }

        string ans;
        while (h > 0 && v > 0) {
            int block = C[h - 1 + v][v];      // 首字符填 'H' 的条数
            if (k <= block) {
                ans.push_back('H');           // 落在 H 块，k 不变
                --h;
            } else {
                k -= block;                   // 跳过整个 H 块
                ans.push_back('V');
                --v;
            }
        }
        ans.append(h, 'H');                   // 某一边用尽，剩余全填同一种
        ans.append(v, 'V');
        return ans;
    }
};
```

### Python

```python
from math import comb

class Solution:
    def kthSmallestPath(self, destination: List[int], k: int) -> str:
        v, h = destination                    # v = row 个 'V'，h = column 个 'H'
        ans = []
        while h and v:
            block = comb(h - 1 + v, v)        # 首字符填 'H' 的条数
            if k <= block:
                ans.append('H')               # 落在 H 块，k 不变
                h -= 1
            else:
                k -= block                    # 跳过整个 H 块
                ans.append('V')
                v -= 1
        return ''.join(ans) + 'H' * h + 'V' * v
```

## 8. 边界情况与易错点

1. **row / column 与 H / V 搞反（最高频 WA）**：`V` 的个数 = `destination[0]`、`H` 的个数 = `destination[1]`。自检：`[2,3], k=1` 必须输出 `"HHHVV"`；输成 `"VVHHH"` 即反。
2. **字典序方向**：`'H'`（ASCII 72）< `'V'`（86），**H 块在前**——别按「先 V 后 H」的直觉排。
3. **k 只在跳块时减**：填 `'H'` 时 $k$ 不变；只有 $k > \text{block}$ 才先 `k -= block` 再填 `'V'`。「先判后减」，顺序颠倒会把 H 块也扣掉。
4. **收尾处理**：`h = 0` 或 `v = 0` 时直接补齐剩余字符；此时 $k$ 必为 1，无须也不能再进循环比较（$h = 0$ 时块公式会算到 $\binom{v-1}{v}$）。
5. **溢出审计**：$\binom{30}{15} = 155\,117\,520 < 2^{31} - 1$，`int` 恰好够、杨辉三角中间值同界；C++ 求稳用 `long long`，Python 无忧。
6. **k 的 1-indexed 语义**：题目保证 $1 \le k \le \binom{row+column}{row}$，无须越界特判；若自造数据测通用性，需先做范围截断。
7. **别用 `next_permutation` 逐条跳**：最坏 $1.55 \times 10^8$ 次调用，C++ 赌常数、Python 必挂——定位题用计数，不用生成。
8. **最小规模**：`[1,1]` 只有 `"HV"`、`"VH"` 两条，$k = 1/2$ 分别对应——首尾样例一把过的代码基本没有方向性错误。

**延伸思考**：

- **m 种字符的推广**：配额为 $c_1, \dots, c_m$ 的多重集求第 $k$ 小排列——逐位按字符从小到大尝试，选 $a_i$ 的块大小为多项式系数 $\dfrac{\left(\left(\sum_j c_j\right) - 1\right)!}{(c_i - 1)! \, \prod_{j \ne i} c_j!}$，本题 $m = 2$ 时退化为组合数 $\binom{h+v-1}{v}$。
- **第 k 大**：对称处理 $k' = \binom{row+column}{row} - k + 1$，或把分块顺序换成 V 块在前。
- **组合数实现选型**：$n \le 30$ 用杨辉三角最稳；$n$ 大且带取模用阶乘 + 逆元 $O(n)$ 预处理；Python `math.comb` 任意精度免操心。
- **同场复盘**：第 213 场是一条「模拟签到 → 组合计数 → 贪心 + 堆 → 组合定位」的阶梯——Q1（#1640）按片段还原数组、Q2（#1641）隔板法闭式计数、Q3（#1642）梯子换砖的贪心反悔、Q4（#1643）把计数升级为定位。Q4 的启示：**「第 k 小 / 大」类问题，先问「一块有多少条」——能数块，就绝不逐条生成**。
