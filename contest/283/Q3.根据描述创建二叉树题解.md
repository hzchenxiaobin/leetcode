# LeetCode 根据描述创建二叉树 题解

## 1. 题目概述

- **标题 / 题号**：根据描述创建二叉树（#2196，medium）
- **链接**：https://leetcode.cn/problems/create-binary-tree-from-descriptions/
- **来源**：LeetCode 第 283 场周赛 Q3
- **难度**：中等
- **标签**：树、二叉树、哈希表、数组、构造

**题意**：给定二维整数数组 `descriptions`，其中 `descriptions[i] = [parent_i, child_i, isLeft_i]` 表示 `parent_i` 是 `child_i` 在二叉树中的父节点，且二叉树中**各节点值互不相同**；`isLeft_i = 1` 时 `child_i` 是左子节点，`isLeft_i = 0` 时是右子节点。请按描述构造出这棵二叉树并返回**根节点**。测试用例保证可以构造出有效二叉树。

**约束**：

- $1 \le \text{descriptions.length} \le 10^4$
- $\text{descriptions[i].length} = 3$
- $1 \le \text{parent}_i,\ \text{child}_i \le 10^5$
- $0 \le \text{isLeft}_i \le 1$
- `descriptions` 描述的是一棵**有效**二叉树（无环、无多父、连通）

> ⚠️ 本题在本仓库另有[每日题解 2196](../../solution/2101-2200/2196_根据描述创建二叉树.md)，两篇互为印证：本篇是周赛复盘视角（引理–定理证明链、**上溯法带完整代码**、赛场易错点清单）；每日版侧重面试问答与「找根两视角」的文字对比。

> 💡 **题眼两层**：① 节点值**互不相同** → val 即天然主键，哈希表把「按值找节点」压到 $O(1)$，无需 DFS、无需森林合并，**任意顺序**读入都正确；② 根是唯一**从未作为 child 出现**的节点 → 用 `children` 集合做差集，一次扫描定根。全程一次遍历建边 + 一次扫描找根，是「显式父子边 + 节点唯一标识」构造题的标准模板。

## 2. 示例

**示例 1**

```text
输入：descriptions = [[20,15,1],[20,17,0],[50,20,1],[50,80,0],[80,19,1]]
输出：[50,20,80,15,17,19]
解释：根节点是值为 50 的节点（没有父节点）。父子关系：
      50 的左孩子 20、右孩子 80；20 的左孩子 15、右孩子 17；80 的左孩子 19。
      层序遍历即输出。
```

**示例 2（链形退化）**

```text
输入：descriptions = [[1,2,1],[2,3,0],[3,4,1]]
输出：[1,2,null,null,3,4]
解释：根为 1；1 的左孩子 2，2 的右孩子 3，3 的左孩子 4。
      树退化成一条链，输出层序中夹杂 null。
```

**示例 3（边乱序到达，自构造）**

```text
输入：descriptions = [[50,20,1],[20,15,1],[80,19,1],[50,80,0],[20,17,0]]
输出：[50,20,80,15,17,19]
解释：与示例 1 完全相同的树，只是边的给出顺序打乱：
      第 2 条边 [20,15,1] 处理时，20 在第 1 条边中已作为 child 建出；
      第 3 条边 [80,19,1] 处理时，80 尚未作为 child 出现（第 4 条边才出现）。
      哈希表保证「先当 child 后当 parent」与「先当 parent 后当 child」取到同一对象，
      结果与示例 1 一致 —— 顺序无关性正是暴力森林法的痛点（见 §3.1、§5 引理 3）。
```

## 3. 解题思路

### 3.1 暴力思路：森林 + 逐边 DFS 找父节点

最直白的做法：维护一个「森林」（若干棵局部子树的根列表）。每来一条 $[p, c, \ell]$：

1. 在森林的所有树里 DFS 查找值为 $p$ 的节点——每条边 $O(V)$；
2. 找到就把 $c$ 挂到对应孩子位；$p$ 不在任何树中就新建一棵以 $p$ 为根的树；
3. 后续发现某棵树的根其实是另一棵树中某节点的孩子时，还要把两棵树**合并**。

- 时间 $O(V \cdot E) \approx 10^4 \times 10^4 = 10^8$，C++ 勉强、Python 必然超时
- 空间 $O(V)$
- 更致命的是「森林合并」分支极易写错：根降级为孩子时要同时改挂指针、删根、并维护根列表

瓶颈的根因是**没有索引**——查节点靠全树遍历；顺序依赖是第二重坑——边以任意顺序到达时局部树要反复重组。只要把「值 → 节点指针」的映射建起来，两个痛点同时消失。

### 3.2 核心观察：val 即主键 + 差集找根

![核心观察：哈希表存节点指针 + children 集合差集定位根](images/createbtree_rootdiff_concept.svg)

**观察一（val 即主键）**：节点值互不相同，val 就是天然唯一键。维护哈希表 `nodes: val → TreeNode*`，每条边来时**先查后建**（懒建节点），$O(1)$ 取出或新建 parent/child，直接挂指针。不存在「找不到父节点」，也不存在「两棵树要合并」——同一个 val 永远映射到同一个对象。

**观察二（差集找根）**：根是唯一**从未作为 child 出现**的节点。遍历时顺手把每个 $c$ 丢进 `children` 集合；建完所有边后扫一遍 `nodes`，不在 `children` 里的键就是根。

**为什么差集恰有一个元素**（直觉版，严格证明见 §5）：$n$ 个节点的树有 $n - 1$ 条边，每条边恰贡献一个 child；有效树中每个非根节点恰有一条父边，所以 `children` **不多不少**恰好覆盖除根外的全部 $n - 1$ 个节点——差集必然只剩根一个。

> ⚠️ **「互不相同」是整套做法的前提**。若节点值可重复，val 不能当唯一键（哈希表只认最后一次写入，指针会连错对象），需改用「节点 id 化 + 入度表 + 拓扑排序」（类似 [207. 课程表](https://leetcode.cn/problems/course-schedule/)）。本题保证唯一，直接用 val。

### 3.3 算法流程

![算法流程：一次遍历建边 + 一次扫描找根](images/createbtree_edge_loop_flow.svg)

1. **初始化**：空哈希表 `nodes`、空集合 `children`
2. **遍历每条 $[p, c, \ell]$**（一个原子动作四步）：
   - `nodes` 中无 `p` → `nodes[p] = new TreeNode(p)`
   - `nodes` 中无 `c` → `nodes[c] = new TreeNode(c)`
   - $\ell = 1$ → `nodes[p].left = nodes[c]`；否则 `nodes[p].right = nodes[c]`
   - `children.insert(c)`
3. **找根**：扫描 `nodes` 的所有键，返回第一个 $\notin$ `children` 的键对应的节点
4. 返回该节点

每条边只做 3 次哈希查询 + 1 次集合插入，全程无 DFS、无递归、无森林合并。

### 3.4 示例演算

![示例演算：5 条边逐条消化，根自动浮现](images/createbtree_edges_walkthrough.svg)

以 **示例 1** 为例：

| 步 | 当前边 | 动作 | 新增节点 | children（累计） |
|----|--------|------|----------|------------------|
| ① | `[20,15,1]` | 建 20、15；20.left ← 15 | 20, 15 | {15} |
| ② | `[20,17,0]` | 建 17；20.right ← 17 | 17 | {15, 17} |
| ③ | `[50,20,1]` | 建 50；50.left ← 20 | 50 | {15, 17, 20} |
| ④ | `[50,80,0]` | 建 80；50.right ← 80 | 80 | {15, 17, 20, 80} |
| ⑤ | `[80,19,1]` | 建 19；80.left ← 19 | 19 | {15, 17, 20, 80, 19} |
| 找根 | — | 扫 `nodes`：键 ∉ children | — | 差集 = {50} |

- **步 ③ 是关键**：`20` 在步 ① 已作为 parent 建出，此刻又作为 child 出现——哈希表保证两次取到**同一对象**，`50.left` 直接连上，不存在暴力法里「把 20 从根降级为孩子再合并两棵树」的分支
- **找根**：`nodes` 有 6 个键，`children` 有 5 个值，差集恰为 {50}，返回节点 50 ✓
- **顺序无关验证**（示例 3）：把 5 条边任意打乱，每一步的「先查后建」都保证对象唯一，最终指针结构与示例 1 完全一致

### 3.5 方法二：父指针上溯

找根还有一条**主动追寻**的路径：遍历时改记 `childToParent: val → parentVal`（代替 `children` 集合），建完边后从**任意**节点出发（如 `descriptions[0][0]`），沿 `val ← childToParent[val]` 一路上溯，查不到父记录的那个值就是根。

- **方法一（缺失视角）**：被动排除——筛掉所有有父的节点，需第二次全表扫描
- **方法二（上溯视角）**：主动追寻——沿父链爬到顶，最坏走树高 $h$ 步（链形树 $h = n - 1$）

两种视角本质相同（「根无父」），$n \le 10^4 + 1$ 下都瞬完成；每日题解以文字对比两者，本篇补齐方法二的完整代码（§7）与终止性证明（§5 定理 2）。

## 4. 算法细节

1. **懒建节点（先查后建）**：节点在**首次出现**时创建——无论首次以 parent 还是 child 身份出现。这保证任意输入顺序正确；若先无条件 `new` 再覆盖 `nodes[p]`，先前挂在旧对象上的孩子指针全部作废（内存泄漏 + WA，见 §8 易错点 7）
2. **`children` 用集合而非列表**：有效树中同一 child 只出现一次，但集合的存在性判定是 $O(1)$；若不信任输入可改为计数（`> 1` 即多父异常）
3. **找根扫描与哈希遍历顺序无关**：`unordered_map` / `dict` 的遍历顺序不定，但差集唯一（§5 引理 2），先扫到谁返回谁都一样
4. **上溯法的起点**：任意出现在某条边中的值都可行；取 `descriptions[0][0]` 或 `[0][1]` 最省事（两者必在 `nodes` 中）。若起点本身无父记录，循环一次都不进，直接就是根
5. **`childToParent` 与 `children` 的取舍**：前者多存一份 parent 值（$O(n)$ int），换来免去第二次全表扫描；后者只存存在性。空间同阶，按口味选
6. **C++ 哈希抗性**：值域仅 $10^5$、$n \le 10^4$，LeetCode 数据一般不卡 `unordered_map`；赛场习惯可换 `map`（$O(m \log m)$ 依旧宽松）或自定义哈希，本题非必需

## 5. 正确性证明

记 `descriptions` 的边集为 $E$，$|E| = m$；由题目有效性保证，$E$ 恰描述一棵 $n$ 个节点的二叉树 $T$，且 $n = m + 1$。

**引理 1（节点全集）**：遍历结束后，`nodes` 的键集恰为 $T$ 的全部 $n$ 个节点值。

**证明**：$m \ge 1$ 故 $n \ge 2$，根至少有一个孩子，即根在某条边中作为 parent 出现；任一非根节点在某条边中作为 child 出现。算法对每条边将 parent 与 child 都「先查后建」，故 $T$ 的每个节点值都进入 `nodes`。反之，`nodes` 只在处理边时插入该边中出现的值，均为 $T$ 的节点。∎

**引理 2（children 恰覆盖非根节点）**：`children` 集合恰为 $T$ 中除根外的全部 $n - 1$ 个节点值，从而 `nodes` 键集减 `children` 为单元素集 $\{\text{root}\}$。

**证明**：每条边把其 child 插入 `children`。有效二叉树中每个非根节点恰有一条父边（指向它的边），故每个非根节点恰被插入一次；根没有任何指向它的边，永不被插入。结合引理 1，差集 $=$ `nodes` 键集 $-$ `children` $= \{\text{root}\}$。∎

**引理 3（顺序无关性）**：以任意顺序处理 $E$ 的边，结束后每个值对应的 `TreeNode` 对象唯一，且已设置的孩子指针恰实现 $E$ 的全部父子关系。

**证明**：对已处理边数 $k$ 归纳，设不变量：(a) `nodes` 键集为前 $k$ 条边出现过的值，且每键只 `new` 过一次；(b) 已赋值的孩子指针恰为前 $k$ 条边规定的指针。$k = 0$ 平凡。处理第 $k+1$ 条边 $[p, c, \ell]$：「先查后建」只新建尚未出现的值，不破坏 (a)；由 (a)，`nodes[p]` 与 `nodes[c]` 是确定的对象，对 `left`/`right` 的赋值只依赖本边的 $(p, c, \ell)$，与此前边的顺序无关，(b) 增量恰为本边。∎

**定理 1**：方法一（差集法）返回 $T$ 的根。

**证明**：由引理 3，循环结束时指针结构恰为 $E$ 描述的树；由引理 2，`nodes` 键集减 `children` 为 $\{\text{root}\}$，扫描必命中且仅命中根。∎

**定理 2（上溯法）**：从任一节点值 $v$ 出发，迭代 $v \leftarrow \text{childToParent}[v]$ 直到 $v$ 不在键集中，必在至多 $n - 1$ 步内终止，且终止值为根。

**证明**：`childToParent` 的每个键值对是 $E$ 中某条边的反向，沿其迭代即沿 $T$ 的父链上行。树有限无环，任一节点的父链长度不超过树高 $\le n - 1$，故迭代有限步后到达链顶端——一个没有父记录的值。由引理 2，这样的值唯一且为根。∎

## 6. 复杂度分析

- **时间**：$O(m)$ 期望——每条边 3 次哈希查询 + 1 次集合插入 + 常数次指针赋值；末尾找根扫描 $O(n)$（方法二改为至多 $n-1$ 步上溯，同阶）。若用有序 `map` 则 $O(m \log m)$。$m \le 10^4$ 下全部宽松，对照暴力 $O(V \cdot E) \approx 10^8$ 是两个量级的差距
- **空间**：$O(n)$——`nodes` 存全部 $n$ 个 `TreeNode`（输出必需，无法省）；`children` 集合或 `childToParent` 映射 $O(n)$ 辅助。哈希表本身有装载因子开销，仍是线性

## 7. 参考代码

### C++（方法一：哈希表 + children 差集）

```cpp
class Solution {
public:
    TreeNode* createBinaryTree(vector<vector<int>>& descriptions) {
        unordered_map<int, TreeNode*> nodes;
        unordered_set<int> children;
        for (auto& d : descriptions) {
            int p = d[0], c = d[1], isLeft = d[2];
            if (!nodes.count(p)) nodes[p] = new TreeNode(p);   // 先查后建
            if (!nodes.count(c)) nodes[c] = new TreeNode(c);
            if (isLeft) nodes[p]->left  = nodes[c];            // 1 → 左
            else        nodes[p]->right = nodes[c];            // 0 → 右
            children.insert(c);                                // 标记 child 身份
        }
        for (auto& [v, node] : nodes)                          // 差集唯一 → 根
            if (!children.count(v)) return node;
        return nullptr;  // 题目保证有效，不会走到
    }
};
```

### Python（方法一：哈希表 + children 差集）

```python
class Solution:
    def createBinaryTree(self, descriptions: List[List[int]]) -> Optional[TreeNode]:
        nodes: dict[int, TreeNode] = {}
        children: set[int] = set()
        for p, c, isLeft in descriptions:
            if p not in nodes:
                nodes[p] = TreeNode(p)          # 先查后建
            if c not in nodes:
                nodes[c] = TreeNode(c)
            if isLeft:
                nodes[p].left = nodes[c]        # 1 → 左
            else:
                nodes[p].right = nodes[c]       # 0 → 右
            children.add(c)                     # 标记 child 身份
        for v, node in nodes.items():           # 差集唯一 → 根
            if v not in children:
                return node
        return None  # 题目保证有效，不会走到
```

### C++（方法二：childToParent 上溯）

```cpp
class Solution {
public:
    TreeNode* createBinaryTree(vector<vector<int>>& descriptions) {
        unordered_map<int, TreeNode*> nodes;
        unordered_map<int, int> par;                     // child -> parent
        for (auto& d : descriptions) {
            int p = d[0], c = d[1], isLeft = d[2];
            if (!nodes.count(p)) nodes[p] = new TreeNode(p);
            if (!nodes.count(c)) nodes[c] = new TreeNode(c);
            if (isLeft) nodes[p]->left  = nodes[c];
            else        nodes[p]->right = nodes[c];
            par[c] = p;
        }
        int v = descriptions[0][0];                      // 从任一节点出发
        while (par.count(v)) v = par[v];                 // 沿父链上溯到顶
        return nodes[v];
    }
};
```

### Python（方法二：childToParent 上溯）

```python
class Solution:
    def createBinaryTree(self, descriptions: List[List[int]]) -> Optional[TreeNode]:
        nodes: dict[int, TreeNode] = {}
        par: dict[int, int] = {}                        # child -> parent
        for p, c, isLeft in descriptions:
            if p not in nodes:
                nodes[p] = TreeNode(p)
            if c not in nodes:
                nodes[c] = TreeNode(c)
            if isLeft:
                nodes[p].left = nodes[c]
            else:
                nodes[p].right = nodes[c]
            par[c] = p

        v = descriptions[0][0]                          # 从任一节点出发
        while v in par:                                 # 沿父链上溯到顶
            v = par[v]
        return nodes[v]
```

> 💡 方法二的 `par` 只记「child → parent」，用一次上溯替代第二次全表差集扫描；代价是链形树时上溯 $O(n)$——$n \le 10^4 + 1$ 完全无感。两法一体两面：被动筛除 vs 主动追寻。

## 8. 边界情况与易错点

1. **忘记把 `c` 加入 `children`**：找根判定直接失效——所有「局部根」看起来都像根，扫描可能返回非根节点（如示例 1 中的 20 或 80）。把「建节点 / 连指针 / 标 child」写成一个原子动作可避免遗漏
2. **只给 parent 建节点、漏给 child 建节点**：child 可能首次就以 child 身份出现（示例 2 的 `[1,2,1]` 中 2 从未当过 parent），漏建则解引用空指针直接 RE
3. **`isLeft` 语义挂反**：题面 **1 = 左、0 = 右**。示例 2 的输出 `[1,2,null,null,3,4]` 是天然检测——挂反会输出形如 `[1,null,2,...]` 的错误层序
4. **暴力森林法的合并遗漏**：根降级为 child 时要同步「挂指针 + 从根列表删除 + 合并两树」，任一步漏改即 WA/TLE。哈希表法从结构上消除了这个分支，别回头冒险
5. **无条件 `new` 覆盖 map**：`nodes[p] = new TreeNode(p)` 不先查就写，会把先前挂在旧对象上的孩子全部丢掉（示例 3 的乱序输入必踩）——这也是「顺序无关性」的隐形前提
6. **上溯法起点不在 `nodes` 中**：起点必须取某条边中出现过的值（如 `descriptions[0][0]`）；凭空取值会在 `nodes[v]` 处查空
7. **C++17 结构化绑定**：`for (auto& [v, node] : nodes)` 需 C++17；防御式 `return nullptr` 兜底行别漏（题目保证有效，但写上无害且明确意图）

**延伸思考**：

- 若节点值**可重复**：val 失去主键资格，需先把值离散化成节点 id（按出现次序编号），再走「id 哈希 + 入度」流程；找根退化为「入度为 0 且唯一」的判定
- 若要求**校验有效性**（题目不再保证）：需三重检测——多父（child 计数 > 1）、环（边数 $\ge$ 节点数或并查集）、多根（差集大小 > 1），任一触发即返回空
- 若**在线流式**加边（边一条条到达，随时问当前根）：本算法天然单遍流式，`nodes`/`children` 增量维护即可；根只有从「非 child」变为「child」时才会更替，维护候选根计数即可 $O(1)$ 应答
