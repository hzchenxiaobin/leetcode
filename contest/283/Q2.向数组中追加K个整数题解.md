# LeetCode 向数组中追加 K 个整数 题解

## 1. 题目概述

- **标题 / 题号**：向数组中追加 K 个整数（#2195，medium）
- **链接**：https://leetcode.cn/problems/append-k-integers-with-minimal-sum/
- **来源**：LeetCode 第 283 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数学、排序、二分查找

**题意**：给定整数数组 `nums` 和整数 $k$，向 `nums` 中追加 $k$ 个**未出现在 `nums` 中**、**互不相同**的**正**整数，使结果数组的**元素和最小**。返回追加到 `nums` 中的这 $k$ 个整数之和（注意：不是数组总和）。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums[i]},\ k \le 10^9$

> ⚠️ 本题在本仓库另有[每日题解 2195](../../solution/2101-2200/2195_向数组中追加K个整数.md)，两篇互为印证：本篇是周赛复盘视角（引理–定理证明链、赛场易错点清单），并补充带代码的**二分取数上界**法；每日版侧重面试问答与「自洽方程」迭代收敛的文字推导。

> 💡 **题眼两层**：① 最小化和 ⟺ 取**最小的 $k$ 个**可用正整数（贪心，见 §5 引理 1）；② $k$ 高达 $10^9$，从 $1$ 逐个枚举必然超时——必须把数轴按 `nums` 切成**连续缺口**，每个缺口用**等差数列求和** $O(1)$ 吃掉，或直接**二分**出取数上界。两种做法都与 $k$ 无关。

## 2. 示例

**示例 1**

```text
输入：nums = [1,4,25,10,25], k = 2
输出：5
解释：追加的两个互不相同且未出现的正整数是 2 和 3。
nums 最终元素和 1+4+25+10+25+2+3 = 70 为所有方案中最小，追加数之和为 2+3 = 5。
```

**示例 2**

```text
输入：nums = [5,6], k = 6
输出：25
解释：追加 1、2、3、4、7、8，和为 25。5 与 6 已被占用，只能向后找。
```

**示例 3（挤占后移陷阱，自构造）**

```text
输入：nums = [1], k = 2
输出：5
解释：1 已被占用，最小的两个可用数是 2 和 3，和为 5。
若按「1+2 减去 nums 中不超过 2 的数」计算会得到 2 —— 典型错误。
```

## 3. 解题思路

### 3.1 暴力思路：从 1 开始逐个枚举

把 `nums` 倒进哈希集合，从 $x = 1$ 起递增：$x$ 在集合中就跳过，不在就累加并令 $k$ 减一，取满 $k$ 个为止。

- 时间 $O(k + n)$：当 `nums` 恰好是 $1, 2, \ldots, 10^5$ 而 $k = 10^9$ 时，要一直枚举到 $10^5 + 10^9$ 才取够——约 $10^9$ 次循环，**必然超时**
- 空间 $O(n)$

瓶颈在于「一个一个数」。而 `nums` 只有至多 $10^5$ 个值，它们在数轴上是**稀疏的挡板**：挡板之间的可用数**成段连续**。这个结构正是「逐个枚举 → 按段求和」的升级点。

### 3.2 核心观察：贪心取最小 + 缺口等差求和

![核心观察：挡板与缺口](images/append_k_gaps_concept.svg)

**观察一（贪心）**：要使追加的 $k$ 个数之和最小，就取**最小的 $k$ 个可用正整数**——把任何取数方案里的较大数换成被跳过的较小可用数，和严格变小且仍合法（严格证明见 §5 引理 1）。于是问题转化为：**求数轴上不在 `nums` 中的最小 $k$ 个正整数之和**。

**观察二（缺口结构）**：把 `nums` **排序去重**后，每个值是一块**挡板**；挡板之间的正整数全部可用且**连续**：

- 第一个缺口：$[1,\ v_1 - 1]$（首个挡板之前）
- 中间缺口：$[v_i + 1,\ v_{i+1} - 1]$（相邻挡板之间）
- 末尾缺口：$[v_m + 1,\ +\infty)$（最后一个挡板之后，**无限长**，永远够用）

**观察三（等差求和）**：每个缺口都是公差为 1 的等差数列，$O(1)$ 求和：

$$\sum_{i=a}^{b} i = \frac{(a+b)(b-a+1)}{2}$$

于是从左到右依次「吃」缺口：缺口不够就整段吃掉，够就只吃前 `need` 个；挡板全部吃完还不够，就在末尾无限缺口里一次补齐。总代价 $O(n)$ 次缺口处理、每次 $O(1)$，**与 $k$ 无关**——这是从 $10^9$ 次循环到毫秒级的决定性优化。

### 3.3 算法流程

![算法流程：排序去重 + 缺口遍历 + 等差求和](images/append_k_gap_flow.svg)

1. **排序去重**：挡板严格递增，保证下文的 $v \ge \text{next}$ 恒成立（重复值只挡一个位置，不产生额外缺口）
2. **初始化**：`next = 1`（下一个候选数）、`need = k`（还差几个）、`sum = 0`
3. **遍历每个挡板 `v`**（升序）：
   - `gap = v - next`：即缺口 $[\text{next},\ v-1]$ 中的可用数个数
   - `gap ≥ need`：缺口够大，只取前 `need` 个，`sum += (2·next + need − 1) · need / 2`，`need = 0`
   - `0 < gap < need`：缺口不够，整段取走，`sum += (next + v − 1) · gap / 2`，`need -= gap`
   - `gap = 0`：挡板紧贴候选，跳过（不取数）
   - 每轮结束 `next = v + 1`；`need == 0` 后可提前结束
4. **末尾兜底**：挡板遍历完仍有 `need > 0`，从 `next` 起在无限缺口中再取 `need` 个连续正整数，公式同部分取分支
5. 返回 `sum`

### 3.4 示例演算

![示例演算：nums=[5,6], k=6](images/append_k_walkthrough.svg)

以 **示例 2** `nums = [5, 6], k = 6` 为例（排序去重后挡板为 `[5, 6]`）：

| 步 | 挡板 v | next | 缺口 | gap | need | 操作 | sum |
|----|--------|------|------|-----|------|------|-----|
| 1 | 5 | 1 | $[1, 4]$ | 4 | 6 → 2 | $4 < 6$，整段取走 1+2+3+4 | 10 |
| 2 | 6 | 6 | $[6, 5]$（空） | 0 | 2 | 挡板紧贴候选，跳过 | 10 |
| 3 | — | 7 | $[7, +\infty)$（兜底） | — | 2 → 0 | 取 7、8 | 25 |

- **步 1**：挡板 5 之前的缺口 $[1,4]$ 有 4 个数，但需要 6 个，全取走 $1+2+3+4 = 10$，`next` 推进到 6
- **步 2**：挡板 6 紧贴 `next = 6`（`gap = 0`），该数被占用不可取，跳过，`next` 推进到 7
- **步 3**：挡板已遍历完而 `need = 2 > 0`，在末尾无限缺口中取 7、8

最终追加 $\{1,2,3,4,7,8\}$，和 $= 10 + 15 = 25$ ✓——恰好 $k=6$ 个、全部 $\notin$ `nums`、互不相同，且都是最小可用数。

**示例 1** 同理：挡板 `[1, 4, 10, 25]`（两个 25 去重后只剩一块），`k = 2`：挡板 1 紧贴 `next=1` 跳过；挡板 4 前缺口 $[2,3]$ 恰好 `gap = 2 ≥ need = 2`，取 2、3 即满，返回 5。

**陷阱验证**（示例 3）：`nums = [1], k = 2`——挡板 1 跳过后兜底取 2、3，答案 5。若按「$\sum_{i=1}^{k} i$ 减去 `nums` 中 $\le k$ 的数」会算出 $1+2-1 = 2$，**错在忽略「占用一个位置就把取数上界后移一位」**（见 §8 易错点 2）。

### 3.5 方法二：二分取数上界

缺口遍历是「从左往右模拟取数」；还有一个整体视角——**先猜取数上界 $m$，再一次性求和**。设

$$f(x) = x - \big|\{v \in \mathrm{distinct}(\text{nums}) : v \le x\}\big|$$

表示 $[1, x]$ 中**可用**正整数的个数（$x$ 个数减去被挡板占用的）。$f$ 单调不减、$f(0) = 0$，于是可**二分**最小的 $m$ 使 $f(m) \ge k$（上界取 $k + n$ 即可：$f(k+n) \ge k$ 恒成立）。可证该 $m$ 必满足 $m \notin \text{nums}$ 且 $f(m) = k$（§5 引理 4），于是 $k$ 个最小的可用数恰好就是 $[1, m]$ 去掉 `nums` 中 $\le m$ 的那些值，前缀求和相减即得：

$$\text{ans} = \frac{m(m+1)}{2} \; - \sum_{v \in \mathrm{distinct}(\text{nums}),\, v \le m} v$$

> 💡 两种方法一体两面：遍历法好想好写，是赛场主推；二分法只需一次 `bisect` 计数、代码更短更难写错，也是每日题解中「自洽方程 $m = k + |\{x \le m\}|$」的严格化版本——方程的解正是这个最小 $m$。

## 4. 算法细节

1. **去重的意义**：去重让挡板**严格递增**，从而处理完 $v_i$ 置 `next = v_i + 1` 后，下一个挡板 $v_{i+1} \ge v_i + 1 = \text{next}$，`gap ≥ 0` 恒成立，三个分支覆盖所有情况。示例 1 的两个 25 只挡一个位置，若不去重且分支误写成 `else`，重复挡板会算出 `gap = −1` 掉进求和公式污染答案
2. **三分支互斥且完备**：`gap = 0`（跳过）/ `0 < gap < need`（整段取）/ `gap ≥ need`（部分取、收尾）。部分取的公式取的是 $\text{next}, \text{next}+1, \ldots, \text{next}+\text{need}-1$ 这 `need` 个连续数——即缺口内最小的 `need` 个，保证贪心取最小的语义
3. **兜底分支不可省**：末尾缺口 $[\max+1, +\infty)$ 无限长，任何剩余 `need` 都能一次吃满；公式与部分取分支完全相同（也是取连续 `need` 个数）
4. **提前 break 只是优化**：`need = 0` 后继续遍历也无害——后续任何 `gap ≥ 0 = need` 都走部分取分支「取 0 个」，加上 $(2 \cdot \text{next} - 1) \cdot 0 / 2 = 0$。但显式 `break` 更清晰
5. **整数除法安全**：等差求和 $\frac{(a+b)(b-a+1)}{2}$ 中 $(a+b)$ 与 $(b-a+1)$ 一奇一偶（其和为 $2b+1$，奇数），乘积必为偶数，`/ 2`（C++）与 `// 2`（Python）都不丢精度
6. **二分的实现要点**：上界 $hi = k + n$（$n$ 为去重后长度，$f(hi) \ge k$ 由「挡板至多占 $n$ 个位置」保证）；判据写 `f(mid) >= k` 求**最小** $m$；最后求和时**只对去重后的值**累减，重复值不能减两次

## 5. 正确性证明

记可用正整数集合 $A = \{x \in \mathbb{Z}^+ : x \notin \text{nums}\}$，$T$ 为 $A$ 中最小的 $k$ 个数。

**引理 1（贪心最优性）**：任何由 $k$ 个互异可用数组成的方案 $S$，都有 $\sum T \le \sum S$，且等号当且仅当 $S = T$。

**证明**：将 $S$ 与 $T$ 各自升序排成 $s_1 < \cdots < s_k$ 与 $t_1 < \cdots < t_k$。$t_i$ 是全集 $A$ 中第 $i$ 小的数，而 $s_i$ 是 $A$ 的某个 $k$ 元子集的第 $i$ 小，故 $A$ 中至少有 $i$ 个数 $\le s_i$，于是对每个 $i$ 都有 $t_i \le s_i$。若 $S \ne T$，取两序列首个不同的下标 $j$，则 $t_j < s_j$，而其余每一项仍满足 $t_i \le s_i$，于是 $\sum T = \sum_i t_i < \sum_i s_i = \sum S$。∎

**引理 2（缺口划分）**：设去重后挡板为 $v_1 < \cdots < v_m$。$A$ 中的数按升序排列，恰为各缺口 $[1, v_1-1],\ [v_1+1, v_2-1],\ \ldots,\ [v_{m-1}+1, v_m-1],\ [v_m+1, \ldots]$ 内的数依序串接。

**证明**：$[1, v_m]$ 被挡板划分为 $\{v_i\}$ 与诸缺口的不交并（去重保证每块挡板只占一个数），故 $[1, v_m]$ 内的可用数按升序即各缺口按左到右串接；大于 $v_m$ 的正整数全部可用，即末尾无限缺口。∎

**引理 3（循环不变量）**：缺口遍历中，任一时刻已被取走的数恰为 $A$ 中**最小的 $k - \text{need}$ 个**，且 `sum` 等于它们之和。

**证明**：归纳。初始 `need = k`、未取数，成立。设某轮处理挡板 $v$ 前已有：已取集合 $D$ = $A$ 中最小的 $k-\text{need}$ 个。归纳基础与递推的关键都是：**下一个**该取的最小可用数是 `next`（由 `next = 上一挡板 + 1` 与引理 2，`next` 之前的可用数已全取）。该轮缺口 $[\text{next}, v-1]$ 内的数即 $A$ 中 $\ge \text{next}$ 的最小的 `gap` 个可用数，算法取走其中前 $\min(\text{gap}, \text{need})$ 个——整段取走（`gap < need`）或部分取走（`gap ≥ need`，恰好取满）均保持不变量；`gap = 0` 不取。循环结束后若 `need > 0`，末尾缺口从 `next` 起无限长，取前 `need` 个仍保持不变量。∎

**定理 1**：缺口遍历法返回 $\sum T$，且这是最优答案。

**证明**：由引理 3，算法终止时（`need = 0`）已取的 $k$ 个数恰为 $T$，返回值 $\text{sum} = \sum T$；终止性显然（每轮要么 `need` 清零，要么处理完一块挡板，最多 $n$ 轮加一次兜底）。由引理 1，$\sum T$ 为最优。∎

**引理 4（二分上界的性质）**：设 $m$ 为满足 $f(m) \ge k$ 的最小正整数，则 $m \notin \text{nums}$ 且 $f(m) = k$。

**证明**：$f(x+1) - f(x) = 1 - [x + 1 \in \mathrm{distinct}(\text{nums})] \in \{0, 1\}$，故 $f$ 单调不减，且 $m$ 在 $x$ 与 $x+1$ 间取到 $f$ 的跳变当且仅当 $x + 1 \notin \text{nums}$。若 $m \in \text{nums}$，则 $f(m) = f(m-1) \ge k$，与 $m$ 的最小性矛盾（$f(0) = 0 < k$ 保证 $m \ge 1$）。故 $m \notin \text{nums}$，$f(m) = f(m-1) + 1$，由最小性 $f(m-1) \le k - 1$，得 $f(m) = k$。∎

**定理 2**：二分法公式 $\frac{m(m+1)}{2} - \sum_{v \le m} v$ 返回最优答案。

**证明**：由引理 4，$[1, m]$ 中恰有 $f(m) = k$ 个可用数，且 $m$ 本身可用；任何 $> m$ 的可用数不小于 $m+1 > m$，故这 $k$ 个数就是 $A$ 中最小的 $k$ 个，即 $T$。$[1,m]$ 的总和减去其中被挡板占用的值（对**去重后**的挡板求和，每块挡板只占一个数）即 $\sum T$，由引理 1 为最优。∎

## 6. 复杂度分析

- **时间**：方法一 $O(n \log n)$（排序主导；缺口遍历 $O(n)$，每个缺口 $O(1)$ 求和）。方法二 $O(n \log n)$（排序）$+ O(\log(k+n))$ 轮二分、每轮 $O(\log n)$ 计数。当 $k = 10^9,\ n = 10^5$ 时，暴力约 $10^9$ 次操作，两种方法都只需约 $10^6$ 量级——**复杂度与 $k$ 无关**正是本题的考点
- **空间**：C++ 原地 `sort + unique` 去重，额外 $O(\log n)$（内省排序递归栈）；Python `sorted(set(...))` 生成新列表，$O(n)$

## 7. 参考代码

### C++（方法一：缺口遍历）

```cpp
class Solution {
public:
    long long minimalKSum(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        nums.erase(unique(nums.begin(), nums.end()), nums.end());

        long long sum = 0, need = k, next = 1;
        for (int v : nums) {
            if (need == 0) break;
            long long gap = (long long)v - next;          // 缺口 [next, v-1] 的可用数个数
            if (gap >= need) {                            // 够大：只取前 need 个
                sum += (next + next + need - 1) * need / 2;
                need = 0;
            } else if (gap > 0) {                         // 不够：整段取走
                sum += (next + (long long)v - 1) * gap / 2;
                need -= gap;
            }
            next = (long long)v + 1;                      // gap == 0 时仅跳过挡板
        }
        if (need > 0)                                     // 末尾无限缺口兜底
            sum += (next + next + need - 1) * need / 2;
        return sum;
    }
};
```

### Python（方法一：缺口遍历）

```python
class Solution:
    def minimalKSum(self, nums: List[int], k: int) -> int:
        uniq = sorted(set(nums))

        total, need, nxt = 0, k, 1
        for v in uniq:
            if need == 0:
                break
            gap = v - nxt                                 # 缺口 [nxt, v-1] 的可用数个数
            if gap >= need:                               # 够大：只取前 need 个
                total += (nxt + nxt + need - 1) * need // 2
                need = 0
            elif gap > 0:                                 # 不够：整段取走
                total += (nxt + v - 1) * gap // 2
                need -= gap
            nxt = v + 1

        if need > 0:                                      # 末尾无限缺口兜底
            total += (nxt + nxt + need - 1) * need // 2
        return total
```

### C++（方法二：二分取数上界）

```cpp
class Solution {
public:
    long long minimalKSum(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        nums.erase(unique(nums.begin(), nums.end()), nums.end());
        int n = nums.size();

        long long lo = 1, hi = (long long)k + n;         // f(hi) >= k 恒成立
        while (lo < hi) {
            long long mid = lo + (hi - lo) / 2;
            long long cnt = upper_bound(nums.begin(), nums.end(), mid) - nums.begin();
            if (mid - cnt >= k) hi = mid;                // f(mid) >= k
            else lo = mid + 1;
        }
        long long m = lo;                                 // 最小 m：f(m) = k，且 m ∉ nums
        long long sum = m * (m + 1) / 2;
        for (int v : nums)
            if (v <= m) sum -= v;                         // 挡板只占一个数（已去重）
        return sum;
    }
};
```

### Python（方法二：二分取数上界）

```python
class Solution:
    def minimalKSum(self, nums: List[int], k: int) -> int:
        arr = sorted(set(nums))
        n = len(arr)

        def f(x: int) -> int:                            # [1, x] 中可用正整数个数
            return x - bisect_right(arr, x)

        lo, hi = 1, k + n
        while lo < hi:
            mid = (lo + hi) // 2
            if f(mid) >= k:
                hi = mid
            else:
                lo = mid + 1
        m = lo                                           # 最小 m：f(m) = k，且 m ∉ nums
        return m * (m + 1) // 2 - sum(v for v in arr if v <= m)
```

> ⚠️ **类型陷阱**：$k$、$\text{nums[i]}$ 均可达 $10^9$。答案最大约 $5 \times 10^{17}$，部分取分支的中间乘积 $(2 \cdot \text{next} + \text{need} - 1) \cdot \text{need}$ 最大约 $3 \times 10^{18}$，都超出 32 位 `int` 上界（约 $2.1 \times 10^9$）但在 `long long`（约 $9.2 \times 10^{18}$）范围内。C++ 须全程 `long long`，`v` 参与乘法前显式转换；Python 整数无上限，但求和公式必须用 `//` 而非 `/`（`/` 会得到浮点数，$10^{17}$ 量级下丢失精度）。

## 8. 边界情况与易错点

1. **溢出（最高频 WA）**：见上文类型陷阱。32 位 `int` 在 `need * next` 第一次乘法就炸，C++ 忘开 `long long` 交上去是典型的一发罚时
2. **陷阱公式「$\sum_{i=1}^{k} i - \sum_{x \in \text{nums}, x \le k} x$」**：错在 `nums` 中 $\le k$ 的值会**挤占**前 $k$ 个位置，把取数上界整体后移。反例 `nums=[1], k=2`：算出 2，正确为 5（取 2、3）。二分法正是这一直觉的修正版——先用 $f(m) \ge k$ 解出**真正的上界**再求和
3. **忘记末尾兜底分支**：`nums = [1,2,3], k = 2` 时所有缺口为空，答案全靠兜底（取 4、5 得 9）；漏写则返回 0
4. **忘记排序去重**：不排序则 `next` 语义失效；不去重则重复挡板可能产生 `gap = −1`（若分支写成 `else` 而非 `else if (gap > 0)`，负 gap 掉进求和公式污染答案——示例 1 的两个 25 就在测试点里）
5. **`gap = 0` 的挡板**：`nums` 含 1 时首个挡板即紧贴 `next = 1`，正确跳过；示例 1 的第一个操作就是这个情况
6. **二分上界取得太小**：`hi` 必须至少 $k + n$（或 $\max(\text{nums}) + k$）。取 `hi = k` 不够：`nums=[1], k=2` 时 $f(2) = 1 < 2$，真正的 $m = 3$
7. **二分求和重复扣减**：`nums` 未去重时把所有 $\le m$ 的值都减一遍，重复值（如两个 25）会被减两次——必须对去重后的值求和
8. **返回值语义**：返回的是**追加数之和**，不是数组总和——示例 1 返回 5 而不是 70，别把 `nums` 的和加进来

**延伸思考**：

- 若 `nums` 可含**非正数**：它们不挡正整数，排序后跳过 $\le 0$ 的前缀即可，主体算法不变
- 若要支持**在线**（`nums` 动态插入，多次查询「当前最小 $k$ 个可用数之和」）：把挡板塞进离散化树状数组或平衡树，$f(x)$ 仍是前缀计数，二分框架原样保留，单次查询 $O(\log^2)$
- 若改成「追加的 $k$ 个数还须与 `nums` 中所有数互质」：缺口结构被 `nums` 的因子集合破坏，需换用莫比乌斯容斥重定义「可用性」——难度直接上一个档次的另一道题
