# LeetCode 使数组元素互不相同所需的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组元素互不相同所需的最少操作次数（#3396，easy）
- **链接**：https://leetcode.cn/problems/minimum-number-of-operations-to-make-elements-in-array-distinct/
- **来源**：LeetCode 第 429 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定整数数组 `nums`，每次操作从数组**开头**移除 3 个元素（若剩余不足 3 个则全部移除）。空数组也视为元素互不相同。返回使数组元素互不相同所需的**最少**操作次数。

**约束**：

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,2,3,3,5,7]
输出：2
解释：
第 1 次操作：移除前 3 个元素，数组变为 [4,2,3,3,5,7]。
第 2 次操作：再移除前 3 个元素，数组变为 [3,5,7]，元素互不相同。
```

**示例 2**

```text
输入：nums = [4,5,6,4,4]
输出：2
解释：
第 1 次操作：移除前 3 个元素，数组变为 [4,4]，仍有重复。
第 2 次操作：只剩 2 个元素，全部移除，数组变为空。
```

**示例 3（自造，覆盖重复值连成一片的情况）**

```text
输入：nums = [7,7,7,7]
输出：1
解释：最晚冲突下标 i* = 2（nums[2] 与右侧的 nums[3] 重复），
1 次操作移除前 3 个元素后剩 [7]，互不相同。
```

## 3. 解题思路

### 3.1 暴力思路（模拟）

反复检查当前数组是否互异（哈希集合比较 `len(set(nums)) == len(nums)`），不满足就砍掉前 3 个元素、计数加一。每轮检查 $O(n)$，最多 $\lceil n/3 \rceil$ 轮，总时间 $O(n^2/3)$；$n \le 100$ 时只有三千多次元素访问，稳过。但这套模拟每一轮都把扫过的判重信息全部丢掉重来——签到题的胜负手在于**能不能一步把答案算出来**。

### 3.2 核心观察：操作只删前缀，答案由「最晚冲突下标」唯一决定

![k 次操作后剩下的一定是后缀](images/distinct3_conflict_index.svg)

每次操作砍掉的永远是开头 3 个元素，执行 $k$ 次后剩下的数组**必然是后缀** $nums[3k:]$（$3k \ge n$ 时为空）。于是问题改写为：**求最小的 $k$，使后缀 $nums[3k:]$ 互异**。

对每一对重复 $nums[i] = nums[j]$（$i < j$）：$j$ 靠后、天然更容易留下，因此唯一的硬性要求是**靠前的 $i$ 必须被删掉**，即 $3k > i$。定义**最晚冲突下标**

$$i^* = \max\{\, i \mid \exists\, j > i,\ nums[i] = nums[j] \,\}$$

则所有重复对的约束中 $3k > i^*$ 最紧（其余冲突下标都 $\le i^*$，被它一并覆盖），一步得到

$$\text{答案} = \left\lfloor \frac{i^*}{3} \right\rfloor + 1 \qquad (\text{无重复时为 } 0)$$

### 3.3 算法流程：从右往左扫，首次撞见重复即得 $i^*$

![算法流程：从右往左一趟扫描](images/distinct3_scan_flow.svg)

1. 维护哈希集合 `seen`（右侧已出现过的值），`i` 从 `n-1` 出发向左。
2. 若 `nums[i]` 已在 `seen` 中——它就是 $i^*$，立即返回 `i / 3 + 1`。
3. 否则把 `nums[i]` 加入 `seen`，`i` 左移，回到第 2 步。
4. 扫到底都没撞见重复：原数组本就互异，返回 `0`。

### 3.4 示例演算

![示例演算：nums = [1,2,3,4,2,3,3,5,7]](images/distinct3_walkthrough.svg)

从右往左扫 `nums = [1,2,3,4,2,3,3,5,7]`：

| i | nums[i] | 扫描前的 seen | 判定 |
|---|---------|---------------|------|
| 8 | 7 | { } | 新值，加入 |
| 7 | 5 | {7} | 新值，加入 |
| 6 | 3 | {5,7} | 新值，加入 |
| 5 | 3 | {3,5,7} | **重复！即 $i^* = 5$，停止** |

答案 $= 5 // 3 + 1 = 2$：删掉前 6 个元素，剩 $[3,5,7]$ 互异，与示例一致。注意扫描停在 $i = 5$ 即可，不必再看更早的冲突（值 2 在 $i = 1$ 的冲突）——$i^*$ 是**最大**冲突下标，天然覆盖所有更早的约束。

## 4. 算法细节

1. **「不足 3 个则全删」无需特判**：它只影响「最后一次操作删 1~2 个元素后数组变空」，而空数组天然互异，公式 $3k > i^*$ 已涵盖这一情形。
2. **seen 的选型**：值域 $1 \le nums[i] \le 100$，C++ 用 `bool seen[101]`（长度为**值域 + 1**），Python 直接用 `set`，两者空间都相当于 $O(1)$。
3. **等价视角**：需要删除的前缀长度 $k = i^* + 1$（$i^*$ 及其左侧全部删光），答案也可写成 $\lceil k/3 \rceil$，两种表述完全一致——$\lceil (i^*+1)/3 \rceil = \lfloor i^*/3 \rfloor + 1$。
4. **提前返回**：撞见第一个重复就 `return`，不必扫完全程再取最大；从右往左撞见的**第一个**重复恰好就是最大冲突下标 $i^*$。

## 5. 正确性证明

**引理 1**（后缀不变式）：执行 $k$ 次操作后，数组恰为 $nums[3k:]$，其中约定 $3k \ge n$ 时表示空数组。

**证明**：对 $k$ 归纳。$k = 0$ 时显然。设 $k$ 次操作后数组为 $nums[3k:]$ 且非空（即 $3k < n$），第 $k+1$ 次操作移除其开头 $\min(3,\, n - 3k)$ 个元素：若 $n - 3k \ge 3$，剩 $nums[3k+3:]$；若 $n - 3k < 3$，剩空数组，正对应 $3(k+1) \ge n$ 的约定。∎

**引理 2**（互异判定）：设 $i^*$ 存在，则后缀 $nums[3k:]$ 互异当且仅当 $3k > i^*$。

**证明**：后缀含重复 $\iff$ 存在 $i < j$ 使 $i, j \ge 3k$ 且 $nums[i] = nums[j]$ $\iff$ 存在冲突下标 $i \ge 3k$ $\iff$ $i^* \ge 3k$（$i^*$ 是全部冲突下标中的最大者）。取否命题即得。∎

**定理**：算法返回使数组元素互不相同的最少操作次数。

**证明**：若原数组无重复，算法扫完全程返回 $0$，显然最优。否则由引理 1，$k$ 次操作后数组为 $nums[3k:]$，故 $k$ 可行 $\iff nums[3k:]$ 互异 $\iff 3k > i^*$（引理 2）；而满足 $3k > i^*$ 的最小整数解为 $k = \lfloor i^*/3 \rfloor + 1$（因 $3\lfloor i^*/3 \rfloor \le i^*$ 且 $3(\lfloor i^*/3 \rfloor + 1) > i^*$）。又，从右往左扫描过程中 `seen` 恰等于 $\{nums[j] \mid j > i\}$，故首次撞见重复的下标正是 $\max\{\, i : \exists\, j > i,\ nums[i] = nums[j] \,\} = i^*$，算法返回的 $i^*/3 + 1$ 与最优值一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。从右往左单趟扫描，撞见第一个重复立即返回；最坏情况（无重复）也只扫完一遍。
- **空间复杂度**：$O(\min(n, 100)) = O(1)$。`seen` 至多存 100 个值，用 `bool seen[101]` 时为严格 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        bool seen[101] = {false};
        for (int i = (int)nums.size() - 1; i >= 0; i--) {
            if (seen[nums[i]]) return i / 3 + 1;
            seen[nums[i]] = true;
        }
        return 0;
    }
};
```

### Python

```python
class Solution:
    def minimumOperations(self, nums: List[int]) -> int:
        seen = set()
        for i in range(len(nums) - 1, -1, -1):
            if nums[i] in seen:
                return i // 3 + 1
            seen.add(nums[i])
        return 0
```

## 8. 边界情况与易错点

1. **长度不足 3 且有重复**（如 `[4,4]`、`[5,5]`）：$i^* = 0$，公式给 $0//3+1 = 1$，一次操作全删——「不足 3 个全删」分支被公式自然覆盖，不要手写特判。
2. **公式别写错**：答案是 $\lfloor i^*/3 \rfloor + 1$（即 $\lceil (i^*+1)/3 \rceil$），写成 `i/3` 或 `(i+1)/3` 都会在 $i^* = 3$ 时出错（给出 1，正确为 2：1 次操作只删 3 个，下标 3 还留在后缀里，重复未消除）。
3. **不要从左往右找第一个重复**：从左撞见的第一个冲突下标（如示例 1 的 $i=1$）**不是** $i^*$，据此算出 $1//3+1 = 1 \ne 2$，必错。冲突下标必须取**最大**。
4. **全部元素相同**：$i^* = n-2$，答案 $= \lceil (n-1)/3 \rceil$，即「删到只剩最后一个」所需次数，如 $n = 100$ 时为 33；`int` 无溢出风险。
5. **空数组合法**：全删光也算互异，因此 $\lceil n/3 \rceil$ 次操作必是可行解，算法循环必有出口，不存在无解情形。
6. **`bool seen[101]` 按值域开**：长度须 $\ge 101$（`nums[i]` 最大为 100），开成 `seen[100]` 会数组越界。
