# LeetCode 三角形的最大高度 题解

## 1. 题目概述

- **标题 / 题号**：三角形的最大高度（#3200）
- **链接**：https://leetcode.cn/problems/maximum-height-of-a-triangle/
- **来源**：LeetCode 第 404 场周赛 Q1
- **难度**：简单
- **标签**：数组、枚举、模拟、贪心

**题意**：给定 `red` 个红球和 `blue` 个蓝球，用它们堆一个金字塔形三角形：第 1 行放 1 个球，第 2 行放 2 个球，第 3 行放 3 个球……**每一行内所有球同色**，且**相邻两行颜色必须不同**。返回能堆出的三角形的最大高度（行数）。

**约束**：

- `1 <= red, blue <= 100`

## 2. 示例

**示例 1**

```text
输入：red = 2, blue = 4
输出：3
解释：蓝球打头——行1 放 1 蓝，行2 放 2 红，行3 放 3 蓝，恰好用完 4 蓝 2 红。
```

**示例 2**

```text
输入：red = 2, blue = 1
输出：2
解释：蓝球打头——行1 放 1 蓝，行2 放 2 红；红球打头只能堆 1 行。取较大者 2。
```

**示例 3**

```text
输入：red = 10, blue = 1
输出：2
解释：数量悬殊时注意：红球打头只能堆 1 行（行2 需要 2 个蓝球而蓝球只有 1 个）；
蓝球打头反而能堆 2 行。这说明不能只让「多的颜色」打头，两种方案都要试。
```

## 3. 解题思路

### 3.1 朴素思路：枚举高度逐一检查

最直接的想法：高度上限很小（`red + blue <= 200`，而 $1+2+\cdots+19 = 190$，故高度 $h \le 19$）。可以从大到小枚举高度 $h$、再枚举两种顶色方案，用等差数列求和检查红蓝需求是否都不超量，复杂度 $O(H)$，$H \approx 19$。

这当然能过，但需要写求和公式、注意奇偶行个数的取整，代码反而容易写错。签到题的正确姿势是**先把结构想清楚，再写最不容易错的代码**。

### 3.2 核心观察：整个三角形只有两种着色方案

**每行同色 + 相邻行不同色 + 总共只有两种颜色**，这三条约束叠加起来意味着：行 1、3、5、… 全部同色 $c_1$，行 2、4、6、… 全部同色 $c_2 \ne c_1$——「不同色」在只有两种颜色时就等于「恰好是另一种颜色」，交替关系沿着行号传递。

于是**整个三角形的着色由「顶行颜色」唯一确定**，全部合法方案只有两种：

- 方案①：红顶（奇数行红、偶数行蓝）；
- 方案②：蓝顶（奇数行蓝、偶数行红）。

对每种方案，逐行贪心放置：放第 $i$ 行需要 $i$ 个当前颜色的球，够就放、不够就停。由于高度 $h$ 的方案确定后每种颜色的需求量也确定（奇数行需求 $m^2$、偶数行需求 $n(n+1)$，见 §4），**可行性关于 $h$ 单调**——高度 $h$ 能堆出来则 $h-1$ 也一定能堆出来（去掉最后一行即可）。所以「逐行放置直到放不下」得到的就是该方案的最大高度。

![核心观察：两种着色方案](images/max_triangle_two_patterns.svg)

### 3.3 算法流程

```text
height(first, second):        # first: 顶行颜色的剩余球数, second: 另一色
    cnt = [first, second]     # cnt[0] = 奇数行（顶色）, cnt[1] = 偶数行
    h = 0                     # 已成功放置的行数
    while cnt[h % 2] >= h+1:  # 第 h+1 行需要 h+1 个 (h%2) 色的球
        cnt[h % 2] -= h+1
        h += 1
    return h

答案 = max(height(red, blue), height(blue, red))
```

### 3.4 示例演算

以 `red = 2, blue = 4` 为例：

| 方案 | 行1 | 行2 | 行3 | 行4 | 高度 |
|------|-----|-----|-----|-----|------|
| ① 红顶 | 需 1 红 ✓（红剩 1） | 需 2 蓝 ✓（蓝剩 2） | 需 3 红 ✗（红仅剩 1） | — | **2** |
| ② 蓝顶 | 需 1 蓝 ✓（蓝剩 3） | 需 2 红 ✓（红剩 0） | 需 3 蓝 ✓（蓝剩 0） | 需 4 红 ✗（红仅剩 0） | **3** |

答案 $= \max(2, 3) = 3$。

## 4. 算法细节

1. **颜色与行号的映射**：已完成 $h$ 行后，下一行是第 $h+1$ 行，颜色下标 $(h+1-1) \bmod 2 = h \bmod 2$。用数组 `cnt[2]` 存两种颜色的剩余量，`cnt[h % 2]` 即当前行的颜色，避免写 if-else 切换分支。

2. **两种方案的调用**：`height(red, blue)` 对应红顶方案，`height(blue, red)` 对应蓝顶方案——只需交换参数顺序，helper 完全复用。

3. **需求的闭式**（用于验证 / 大数据版本）：高度 $h$ 的三角形中奇数行有 $m = \lceil h/2 \rceil$ 个，行号和为 $1+3+\cdots+(2m-1) = m^2$；偶数行有 $n = \lfloor h/2 \rfloor$ 个，行号和为 $2+4+\cdots+2n = n(n+1)$。方案可行 $\iff$ 顶色球数 $\ge m^2$ 且另一色球数 $\ge n(n+1)$。本题用逐行模拟即可，不必动用公式。

4. **循环上限**：`red, blue <= 100` ⟹ 总球数 $\le 200$ ⟹ $h \le 19$（因为 $1+2+\cdots+19=190 \le 200 < 210 = 1+2+\cdots+20$），循环至多跑 20 步。

## 5. 正确性证明

**引理 1（结构唯一性）**：任何合法三角形中，所有奇数行同色，所有偶数行同色，且两组颜色互异。

**证明**：对行号归纳。行 1 颜色记为 $c$。由于相邻行不同色且只有红蓝两色，「不同色」即「恰为另一色」，故行 2 颜色为 $\bar c$。设行 $k$ 颜色为 $c$（$k$ 奇），则行 $k+1$ 为 $\bar c$，行 $k+2$ 与行 $k+1$ 不同色，又为 $c$。归纳得知奇数行恒为 $c$、偶数行恒为 $\bar c$。∎

**引理 2（需求确定性）**：顶行颜色确定后，高度 $h$ 的三角形恰好消耗顶色球 $m^2$ 个、另一色球 $n(n+1)$ 个（$m = \lceil h/2 \rceil, n = \lfloor h/2 \rfloor$）。

**证明**：第 $i$ 行恰好放 $i$ 个球；奇数行（顶色）行号之和为 $1+3+\cdots+(2m-1) = m^2$，偶数行（另一色）行号之和为 $2+4+\cdots+2n = n(n+1)$。∎

**引理 3（单调性）**：若某方案下高度 $h$ 可行，则同方案下高度 $h-1$ 也可行。

**证明**：去掉第 $h$ 行后，剩余 $h-1$ 行仍满足「每行同色、相邻异色」，且两种颜色的消耗量只减不增，不超量约束依然成立。∎

**定理**：算法输出等于最大可行高度。

**证明**：

- **可行性（输出 ≤ 最优）**：算法输出的 $h$ 对应一个真实放置过程——每一步放置前都检查了该颜色剩余球数 $\ge$ 行号，故这个 $h$ 行的三角形真实可堆出。
- **最优性（输出 ≥ 最优）**：设最优高度为 $H$，其三角形由引理 1 必属于红顶或蓝顶方案之一，不妨设为 `height(first, second)` 对应的方案。由引理 2，该方案下前 $i$ 行（$i \le H$）的顶色总需求与另一色总需求均不超过供给。贪心放置第 $i$ 行时已消耗的球量等于前 $i-1$ 行的需求，不超过供给，故第 $i$ 行也放得下。归纳可知贪心至少到达高度 $H$，即该方案的返回值 $\ge H$，`max` 之后算法输出 $\ge H$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\sqrt{red + blue})$。两方案各至多放置 $\lfloor \frac{\sqrt{8(red+blue)+1}-1}{2} \rfloor + 1 \approx \sqrt{2(red+blue)}$ 行就耗尽所有球；本题范围内即常数级（$\le 20$ 步）。
- **空间复杂度**：$O(1)$。仅用一个长度为 2 的数组与几个整数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxHeightOfTriangle(int red, int blue) {
        auto height = [](int first, int second) {
            int cnt[2] = {first, second};
            int h = 0;
            while (cnt[h % 2] >= h + 1) {
                cnt[h % 2] -= h + 1;
                ++h;
            }
            return h;
        };
        return max(height(red, blue), height(blue, red));
    }
};
```

### Python

```python
class Solution:
    def maxHeightOfTriangle(self, red: int, blue: int) -> int:
        def height(first: int, second: int) -> int:
            cnt = [first, second]
            h = 0
            while cnt[h % 2] >= h + 1:
                cnt[h % 2] -= h + 1
                h += 1
            return h
        return max(height(red, blue), height(blue, red))
```

## 8. 边界情况与易错点

1. **两种方案都必须试**：`red = 10, blue = 1` 时红顶只能堆 1 行、蓝顶能堆 2 行。若想当然地让数量多的颜色打头（或只枚举一种方案），会得到错误答案 1。这是本题最经典的陷阱。

2. **最小输入** `red = blue = 1`：两方案都只能放行 1，答案 1。由约束 `red, blue >= 1` 保证答案至少为 1，无需特判返回 0。

3. **行号与颜色下标的映射**：第 $h+1$ 行的颜色是 `cnt[h % 2]`（已完成 $h$ 行）。若把「行号从 1 开始」与「数组下标从 0 开始」搞混（误写成 `cnt[(h+1) % 2]`），红蓝恰好互换，两个方案也就悄悄互换了——单看某个方案结果可能「碰巧」差 1，务必对拍示例。

4. **不要用浮点求和**：用 $\frac{h(h+1)}{2}$ 之类公式配合取整容易在奇偶性上出错；逐行整型模拟无任何精度与取整风险，是签到题的稳健写法。

5. **循环条件是「够放下一行」**：`cnt[h % 2] >= h + 1` 中右端是**行号** $h+1$ 而不是已放行数 $h$，差一错误会把答案放大 1。
