# LeetCode 重排字符形成目标字符串 题解

## 1. 题目概述

- **标题 / 题号**：重排字符形成目标字符串（#2287，easy）
- **链接**：https://leetcode.cn/problems/rearrange-characters-to-make-target-string/
- **来源**：LeetCode 第 295 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、计数

**题意**：给定两个字符串 `s` 和 `target`，每次从 `s` 中取出若干字符（**每个下标只能用一次**）并重排，拼出一个 `target`。求最多能拼出多少个 `target` 的副本。

**约束**：

- `1 <= s.length <= 100`
- `1 <= target.length <= 10`
- `s` 和 `target` 由小写英文字母组成

> 💡 「重排」意味着**只关心字母个数、不关心顺序**——这是本题能转化为纯计数问题的关键信号。

## 2. 示例

**示例 1**

```text
输入：s = "ilovecodingonleetcode", target = "code"
输出：2
解释：下标 4、5、6、7 取出 "ecod"，下标 17、18、19、20 取出 "code"，
      两者重排后均为 "code"，共 2 份。
```

**示例 2**

```text
输入：s = "abcba", target = "abc"
输出：1
解释：a、b 各有 2 个，但 c 只有 1 个，卡住了第 2 份副本。
```

**示例 3**

```text
输入：s = "abbaccaddaeea", target = "aaaaa"
输出：1
解释：s 中恰有 5 个 'a'，正好拼 1 份。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `s` 的每个子序列、判断能否重排成 `target` 并不断移除——组合爆炸，无法实现。退一步想：即使真的拼出一份，本质只是「从池子里扣掉一组字母」，**顺序完全无关**，所以任何基于"位置"的枚举都是浪费。

### 3.2 核心观察：计数 + 木桶效应

![木桶效应：每个字符份数取最小](images/2287_bottleneck_concept.svg)

既然重排后只看字母组成，那么设 `cntS[c]` 为 `s` 中字母 `c` 的个数、`cntT[c]` 为拼一份 `target` 所需 `c` 的个数，则：

- 字母 `c` 单独看，至多支持 $\lfloor \mathrm{cntS}[c] / \mathrm{cntT}[c] \rfloor$ 份；
- 所有字母必须同时凑齐，份数由**最稀缺的字母**决定——典型木桶效应：

$$\text{ans} = \min_{c \in \mathrm{target}} \left\lfloor \frac{\mathrm{cntS}[c]}{\mathrm{cntT}[c]} \right\rfloor$$

### 3.3 算法流程

![算法流程：两次计数、逐字符求商取最小](images/2287_counting_flow.svg)

1. 一次遍历 `s`，统计 `cntS`；
2. 一次遍历 `target`，统计 `cntT`；
3. `ans` 初始化为无穷大，对 `target` 中每种字母 `c`，用 `cntS[c] / cntT[c]`（整数除法）更新 `ans`；
4. 返回 `ans`。

### 3.4 示例演算

![示例演算：ilovecodingonleetcode 拼 code](images/2287_example_walkthrough.svg)

以示例 1 为例，`s = "ilovecodingonleetcode"`，`target = "code"`：

| 字母 | cntS（s 中个数） | cntT（每份需求） | 可拼份数 ⌊cntS/cntT⌋ |
|------|------|------|------|
| c | 2 | 1 | **2**（min） |
| o | 4 | 1 | 4 |
| d | 2 | 1 | **2**（min） |
| e | 4 | 1 | 4 |

答案 = min(2, 4, 2, 4) = **2** ✓（与官方解释中圈选的下标 4~7、17~20 完全吻合）。

## 4. 算法细节

1. **计数用数组即可**：只有小写字母，`int cntS[26]` / `cntT[26]`，比哈希表更快更短。
2. **min 只对 `target` 中出现的字母取**：`s` 独有的字母不构成约束，跳过即可。实现上直接遍历 `target` 的 26 个桶中非零者。
3. **整数除法自动向下取整**：`3 / 2 == 1`，剩余 1 个字母浪费掉，正是"每个下标只用一次"的语义。
4. **除零安全**：进入除法的字母必然在 `target` 中出现，`cntT[c] >= 1`，无风险。
5. **初值**：`ans` 初始设为 `s.length()`（或足够大的数）均可——份数不会超过 `|s|`。

## 5. 正确性证明

**引理 1**：能拼出 $k$ 份 `target`，当且仅当对 `target` 中每种字母 $c$ 都有 $\mathrm{cntS}[c] \ge k \cdot \mathrm{cntT}[c]$。

**证明**：（必要性）$k$ 份副本共消耗 $k \cdot \mathrm{cntT}[c]$ 个字母 $c$，且每个下标仅用一次，故消耗数不超过存量 $\mathrm{cntS}[c]$。（充分性）按任意顺序为第 $1, \dots, k$ 份副本各分配 $\mathrm{cntT}[c]$ 个字母 $c$ 的未用下标，条件保证下标足够；份内字母可任意重排成 `target`。∎

**定理**：算法返回能拼出的最大份数 $\max\{\,k : \forall c,\ \mathrm{cntS}[c] \ge k \cdot \mathrm{cntT}[c]\,\}$。

**证明**：引理 1 中不等式等价于 $k \le \lfloor \mathrm{cntS}[c] / \mathrm{cntT}[c] \rfloor$（因 $k$ 为整数），对所有 $c$ 同时成立等价于 $k \le \min_c \lfloor \mathrm{cntS}[c] / \mathrm{cntT}[c] \rfloor$。算法返回的正是该最小值，故为最大可行份数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m + 26)$，其中 $n = |s|$、$m = |target|$。两次线性扫描加至多 26 次除法，本题为 $O(100 + 10 + 26)$ 级别。
- **空间复杂度**：$O(26) = O(1)$，只开两个 26 长度的计数数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int rearrangeCharacters(string s, string target) {
        int cntS[26] = {0}, cntT[26] = {0};
        for (char c : s)      cntS[c - 'a']++;
        for (char c : target) cntT[c - 'a']++;

        int ans = s.size();
        for (int c = 0; c < 26; c++) {
            if (cntT[c] > 0) {
                ans = min(ans, cntS[c] / cntT[c]);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def rearrangeCharacters(self, s: str, target: str) -> int:
        cnt_s = Counter(s)
        cnt_t = Counter(target)
        return min(cnt_s[c] // cnt_t[c] for c in cnt_t)
```

## 8. 边界情况与易错点

1. **某字母在 `s` 中不存在**：如 `s = "a"`, `target = "b"`，`⌊0/1⌋ = 0`，答案为 0，除法自然处理，无需特判。
2. **字母有富余**：示例 2 中 `a`、`b` 富余但 `c` 稀缺——别忘了 min 是对**所有** `target` 字母取，漏掉任何一个都会算大。
3. **除法用整数除法**：若先算 `cnt_s * 1.0 / cnt_t` 再取整，浮点误差在 32 位下通常没事，但整数除法是唯一正确且简洁的写法。
4. **min 的初值**：不要初始化为 0；用 `|s|` 或大数，否则答案恒为 0。
5. **`target` 中重复字母**：如示例 3 的 `"aaaaa"`，`cntT['a'] = 5`，商为 1——必须整份扣 5 个，不是逐个扣。
6. **不要对 `s` 独有字母取 min**：它们的"份数"是无穷，混入 min 会出错。
