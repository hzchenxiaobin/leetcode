# LeetCode 规划兼职工作 题解

## 1. 题目概述

- **标题 / 题号**：规划兼职工作（#1235，hard）
- **链接**：https://leetcode.cn/problems/maximum-profit-in-job-scheduling/
- **来源**：LeetCode 第 159 场周赛 Q4
- **难度**：困难
- **标签**：数组、二分查找、动态规划、排序

**题意**：有 $n$ 份兼职，第 $i$ 份占用时间区间 $[startTime_i, endTime_i)$，报酬为 $profit_i$。选出一个子集，使任意两份的时间区间**不重叠**（一份在时刻 $X$ 结束，另一份可以从 $X$ 开始，即端点相接合法），求子集报酬之和的最大值。

等价说法：在数轴上选一组互不重叠的带权区间，最大化权重和——这就是经典的**加权区间调度**（weighted interval scheduling）。

**约束**：

- $1 \le n \le 5 \times 10^4$
- $1 \le startTime_i < endTime_i \le 10^9$（时间跨度大，不能按时间开数组）
- $1 \le profit_i \le 10^4$（报酬全为正，且总和上界为 $5\times10^4 \times 10^4 = 5\times10^8$）

## 2. 示例

**示例 1**

```text
输入：startTime = [1,2,3,3], endTime = [3,4,5,6], profit = [50,10,40,70]
输出：120
解释：选第 1 份（[1,3]，50）与第 4 份（[3,6]，70），
      时间上 3 与 3 相接，不重叠，共得 120。
```

**示例 2**

```text
输入：startTime = [1,2,3,4,6], endTime = [3,5,10,6,9], profit = [20,20,100,70,60]
输出：150
解释：选第 1、4、5 份：20 + 70 + 60 = 150，
      区间 [1,3] + [4,6] + [6,9] 首尾恰好相接。
      注意报酬最高的第 3 份（[3,10]，100）会挡住 [4,6] 与 [6,9]，
      选它最多再带上 [1,3]，共 120，仍不如 150。
```

**示例 3**

```text
输入：startTime = [1,1,1], endTime = [2,3,4], profit = [5,6,4]
输出：6
解释：三份工作都从 1 开始、两两重叠，最多选一份，取报酬最大的 6。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子集（$2^n$ 个），对每个子集检查两两是否重叠，取合法子集的报酬最大值。$n = 5\times10^4$ 时 $2^n$ 完全不可行；即使退一步用「按时间轴做线性 DP」，时间戳最大到 $10^9$，也必须先离散化才能开数组。

两个自然的贪心都会失败：

- **按报酬从大到小选**：$(1,10,51)$ 与 $(1,2,50)$、$(2,3,50)$ 三份工作中，先选 51 就再也放不下任何工作，只得 51；最优是后两份共 100。
- **按结束时间最早选**（区间调度题求「最多能参加几个」时的正确贪心）：$(1,2,5)$、$(1,10,100)$、$(2,3,5)$ 中先选最早结束的 $(1,2,5)$，再能接 $(2,3,5)$，共 10；最优是单独选 $(1,10,100)$ 得 100。

**根本原因**：带权之后「数量最多」不再等于「收益最大」，局部最优不再能推出全局最优。必须上 DP，而 DP 的难点在于——**状态怎么定义，才能让「与当前工作不重叠」的前驱变成一个可以直接查表的下标。**

### 3.2 核心观察：按结束时间排序后，兼容工作恰好是一个前缀

![按结束时间排序后兼容工作是前缀](images/wc159_q4_interval_dp_model.svg)

把三份信息打包成三元组，按**结束时间升序**排序，得到工作序列 $1,2,\dots,n$，记第 $i$ 个工作的区间为 $[s_i, e_i)$、报酬 $w_i$，于是

$$e_1 \le e_2 \le \cdots \le e_n$$

定义状态：

$$\text{dp}[i] = \text{只考虑前 } i \text{ 个工作（即 } 1..i \text{）时能获得的最大报酬}$$

现在考察「第 $i$ 个工作要不要选」。若选它，其余被选中的工作都不能与它重叠。对 $j < i$（结束时间不晚于 $i$）的工作，由引理 2 可知它必须满足 $e_j \le s_i$ 才能与 $i$ 共存；而由于 $e$ 数组升序，满足 $e_j \le s_i$ 的下标**恰好是开头连续的一段**：

$$\{j < i : e_j \le s_i\} = \{1, 2, \dots, p(i)\}, \qquad p(i) = \bigl|\{j < i : e_j \le s_i\}\bigr|$$

于是「接在第 $i$ 个工作前面能达到的最优值」正是 $\text{dp}[p(i)]$——**一个现成的、已算好的表项**。这就是把二维的「与哪些工作兼容」压成一维下标的全部秘密。

状态转移：

$$\text{dp}[i] = \max\bigl(\text{dp}[i-1],\ \text{dp}[p(i)] + w_i\bigr)$$

- 不选 $i$：继承 $\text{dp}[i-1]$；
- 选 $i$：前面只能接前缀里的最优解，得 $\text{dp}[p(i)] + w_i$。

$p(i)$ 由一次二分求出：在升序的 $e[1..i-1]$ 上找**第一个 $> s_i$** 的位置，它前面的元素个数就是 $p(i)$（即 `upper_bound` 的返回值）。

注意判定用的是 $e_j \le s_i$ 而不是 $e_j < s_i$：题目明确允许「在 $X$ 结束的工作后面立刻接从 $X$ 开始的工作」，示例 1 的 $50+70=120$ 就依赖这条。

### 3.3 算法流程

![排序 + 二分 + 线性 DP 的流程](images/wc159_q4_bisect_flow.svg)

1. 把 $(startTime_i, endTime_i, profit_i)$ 打包成三元组，按 $endTime$ 升序排序；
2. 抽出排好序的 $e$ 数组（自然升序），开 $\text{dp}[0..n]$，$\text{dp}[0]=0$；
3. 对 $i = 1 \dots n$：在 $e[1..i-1]$ 上 `upper_bound(start_i)` 得到 $p(i)$，然后 $\text{dp}[i] = \max(\text{dp}[i-1], \text{dp}[p(i)] + profit_i)$；
4. 返回 $\text{dp}[n]$。

```text
排序 O(n log n)  →  循环 i = 1..n:
                      p = upper_bound(e[0 .. i-1), s_i)      // O(log n)
                      dp[i] = max(dp[i-1], dp[p] + w_i)      // O(1)
```

### 3.4 示例演算

![示例 2 逐行转移](images/wc159_q4_walkthrough.svg)

以示例 2（$start=[1,2,3,4,6]$，$end=[3,5,10,6,9]$，$profit=[20,20,100,70,60]$）为例，按结束时间排序后为 $(3,1,20),\ (5,2,20),\ (6,4,70),\ (9,6,60),\ (10,3,100)$，于是 $e = [3,5,6,9,10]$：

| $i$ | 工作 $(e_i, s_i, w_i)$ | $p(i)$ | $\text{dp}[i-1]$ | $\text{dp}[p(i)] + w_i$ | $\text{dp}[i]$ |
|----|------------------------|--------|------------------|-------------------------|----------------|
| 1 | $(3, 1, 20)$ | 0 | 0 | $0 + 20 = 20$ | 20 |
| 2 | $(5, 2, 20)$ | 0 | 20 | $0 + 20 = 20$ | 20 |
| 3 | $(6, 4, 70)$ | 1 | 20 | $20 + 70 = 90$ | 90 |
| 4 | $(9, 6, 60)$ | 3 | 90 | $90 + 60 = 150$ | **150** |
| 5 | $(10, 3, 100)$ | 1 | 150 | $20 + 100 = 120$ | 150 |

第 4 行的 $p(4)=3$ 是因为 $e[1..3]=[3,5,6]$ 全部 $\le s_4=6$，第 3 个工作结束于 6、第 4 个开始于 6，端点相接合法；第 5 行虽然 $w=100$ 最大，但 $s_5=3$ 只能接前缀 $\{1\}$，$20+100=120 < 150$，因此 $\text{dp}[5]$ 继承 $\text{dp}[4]$。最终答案 $150$，与官方输出一致。

## 4. 算法细节

1. **排序键必须是结束时间**。按开始时间排序会让「兼容集是前缀」不成立（一个晚开始但早结束的工作可能排在中间）；只有按结束时间升序，才有 $j \le i \Rightarrow e_j \le e_i$ 的单调性，前缀性才成立。
2. **三元组打包，不要分开排**。只对 `endTime` 排序而不同步移动 `startTime`/`profit` 会立刻下标错位；C++ 用 `index` 数组按 `endTime` 排序，Python 用 `sorted(zip(end, start, profit))`。
3. **用 `upper_bound` 而不是 `lower_bound`**。要求的是 $e_j \le s_i$，`upper_bound`（`bisect_right`）返回第一个 $> s_i$ 的位置，它前面正好是「$\le s_i$ 的个数」；`lower_bound` 对应 $< s_i$，会把端点相接的组合全部漏掉。
4. **二分的区间上界取 $i-1$**。兼容工作必须已经决策过（$j < i$）；虽然 $s_i < e_i$ 保证工作 $i$ 本身不会被算进来，显式限定上界让「只在已决策前缀里查」这一语义更清楚，也避免了任何自我引用的怀疑。C++ 写 `ends.begin(), ends.begin() + (i - 1)`；Python 写 `bisect_right(ends, s, 0, i - 1)`（`hi` 是开区间，正好是 $[0, i-1)$）。
5. **$p(i)$ 是「个数」，直接当下标用**。它既是满足条件的元素个数，也是前缀长度，所以转移里写 $\text{dp}[p(i)]$ 而**不是** $\text{dp}[p(i)+1]$ 或 $\text{dp}[p(i)-1]$——这是本题最容易错一位的地方。
6. **一维 $\text{dp}$ 就够，不需要滚动数组**。转移只回看 $i-1$ 与 $p(i) < i$，开 $n+1$ 个槽位、$\text{dp}[0]=0$ 作哨兵即可，$O(n)$ 空间。
7. **数值范围**。$n \le 5\times10^4$、$profit_i \le 10^4$，答案上界 $5\times10^8$，`int` 足够；但求和过程中若你顺手用 `long long` 也不会错，不要用更窄的类型。

## 5. 正确性证明

约定：工作已按结束时间升序编号为 $1..n$，$e_1 \le \cdots \le e_n$；$p(i) = |\{j < i : e_j \le s_i\}|$；$F(i)$ 表示只考虑前 $i$ 个工作时的最大报酬。

**引理 1（兼容集是前缀）**：对任意 $i$，$\{j : 1 \le j < i,\ e_j \le s_i\} = \{1, 2, \dots, p(i)\}$，且 $0 \le p(i) \le i-1$。

**证明**：若 $j$ 在集合中、$1 \le k \le j$，则由 $e$ 升序有 $e_k \le e_j \le s_i$ 且 $k \le j < i$，故 $k$ 也在集合中；集合非空时其最小元必为 $1$，故集合是前缀 $\{1..p(i)\}$。$p(i)$ 显然不超过 $i-1$。∎

**引理 2（更早的工作必在 $i$ 开始前结束）**：若 $S$ 是一组两两不重叠的工作，$i \in S$、$j \in S$ 且 $j < i$，则 $e_j \le s_i$。

**证明**：两两不重叠意味着 $e_j \le s_i$ 或 $e_i \le s_j$。若 $e_i \le s_j$，结合 $s_j < e_j$ 得 $e_i < e_j$，与 $j < i$ 时 $e_j \le e_i$（升序）矛盾。故只能是 $e_j \le s_i$。∎

**引理 3（最优子结构）**：$F(i) = \max\bigl(F(i-1),\ F(p(i)) + w_i\bigr)$，其中 $F(0)=0$。

**证明**：

- **上界**：取前 $i$ 个工作的任一可行解 $S$。若 $i \notin S$，则 $S$ 也是前 $i-1$ 个工作的可行解，$val(S) \le F(i-1)$。若 $i \in S$，由引理 2，$S \setminus \{i\}$ 中每个工作 $j$ 满足 $j < i$ 且 $e_j \le s_i$，故 $j \le p(i)$（引理 1），于是 $S \setminus \{i\}$ 是前 $p(i)$ 个工作的可行解，$val(S) - w_i \le F(p(i))$。两种情形都有 $val(S) \le \max(F(i-1), F(p(i)) + w_i)$，取 $S$ 最优即得上界。
- **可达**：前 $i-1$ 个工作的最优解在前 $i$ 个中仍可行，故 $F(i) \ge F(i-1)$。设 $T$ 是前 $p(i)$ 个工作的最优解，把工作 $i$ 加进去：$T$ 内部两两不重叠，且每个 $j \in T$ 满足 $j \le p(i) < i$、$e_j \le e_{p(i)} \le s_i$，故 $e_j \le s_i$，与 $i$ 不重叠；于是 $T \cup \{i\}$ 可行，$F(i) \ge F(p(i)) + w_i$。

两者合并即得等式。∎

**定理**：算法返回的 $\text{dp}[n]$ 就是最大报酬。

**证明**：对 $i$ 归纳证明 $\text{dp}[i] = F(i)$。$i=0$ 时 $\text{dp}[0]=F(0)=0$。设对 $i-1$ 及所有 $p(i) < i$ 的表项都成立，则 $\text{dp}[i] = \max(\text{dp}[i-1], \text{dp}[p(i)] + w_i) = \max(F(i-1), F(p(i)) + w_i) = F(i)$，归纳成立。又「考虑前 $n$ 个工作」就是原问题的全部工作，故 $\text{dp}[n] = F(n)$ 即答案。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；DP 循环 $n$ 轮，每轮一次二分 $O(\log n)$ 加 $O(1)$ 转移，共 $O(n \log n)$；没有额外的枚举或回溯。
- **空间**：$O(n)$。排序后的三元组（或下标数组）$O(n)$、升序的 $e$ 数组 $O(n)$、$\text{dp}$ 数组 $O(n+1)$；不存在与时间戳大小相关的开销（这正是不能按时间开数组时该走的路）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <numeric>

using namespace std;

class Solution {
public:
    int jobScheduling(vector<int>& startTime, vector<int>& endTime, vector<int>& profit) {
        int n = startTime.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        // 按结束时间升序排序
        sort(idx.begin(), idx.end(), [&](int a, int b) { return endTime[a] < endTime[b]; });

        vector<int> ends(n), dp(n + 1, 0);
        for (int i = 0; i < n; i++) ends[i] = endTime[idx[i]];

        for (int i = 1; i <= n; i++) {
            int id = idx[i - 1];
            int s = startTime[id], w = profit[id];
            // 在已决策的前缀 ends[0 .. i-1) 中找第一个 > s 的位置，
            // 其下标正好等于满足 end <= s 的工作个数 p(i)
            int j = upper_bound(ends.begin(), ends.begin() + (i - 1), s) - ends.begin();
            dp[i] = max(dp[i - 1], dp[j] + w);
        }
        return dp[n];
    }
};
```

### Python

```python
from bisect import bisect_right
from typing import List


class Solution:
    def jobScheduling(self, startTime: List[int], endTime: List[int], profit: List[int]) -> int:
        n = len(startTime)
        # 按结束时间升序排列，(end, start, profit) 一起移动，避免下标错位
        jobs = sorted(zip(endTime, startTime, profit))
        ends = [e for e, s, w in jobs]

        dp = [0] * (n + 1)                      # dp[0] = 0 为哨兵
        for i in range(1, n + 1):
            e, s, w = jobs[i - 1]
            # 在 ends[0 .. i-1) 中找第一个 > s 的位置 = 满足 end <= s 的个数 p(i)
            p = bisect_right(ends, s, 0, i - 1)
            dp[i] = max(dp[i - 1], dp[p] + w)
        return dp[n]
```

## 8. 边界情况与易错点

1. **端点相接必须算兼容**：若写成 `lower_bound`（严格小于），示例 1 的答案会从 120 掉到 70——端点相接的 $[1,3]$ 与 $[3,6]$ 被错判成冲突。题目原话是「在 $X$ 结束的工作后面可以立刻开始 $X$ 开始的工作」，判定式是 $e_j \le s_i$。
2. **$p(i)$ 当个数用，不要 ±1**：$p(i) \in [0, i-1]$，正好是 $\text{dp}$ 的合法下标；写成 $\text{dp}[p(i)+1]$ 会把某个本不兼容的工作算进来，写成 $\text{dp}[p(i)-1]$ 在 $p(i)=0$ 时越界。
3. **完全相同的区间**：如三份工作都是 $[1,2]$，此时彼此的 $e = 2 > s = 1$，$p(i) = 0$，$\text{dp}$ 只保留最大的那一份报酬，不会错误叠加。
4. **排序键写错**：按 `startTime` 排序后「兼容集是前缀」不成立，二分出来的 $p(i)$ 会指向一组包含不兼容工作的前缀，答案偏大且难以察觉——这类错误在小数据上常常碰巧正确。
5. **必须打包排序**：只排 `endTime` 而不同步移动 `startTime`/`profit`，会让后续所有取值错位；Python 用 `zip` 一次性排序最稳，C++ 用下标数组最稳。
6. **二分上界**：`bisect_right(ends, s, 0, i - 1)` 的第三个参数是开区间上界，对应数组下标 $[0, i-1)$；写成 `i` 虽然因为 $s_i < e_i$ 结果不变，但语义上是把「当前工作自己」也纳入了搜索范围。
7. **$n=1$**：$p(1)=0$，$\text{dp}[1] = \max(0, w_1) = w_1$，无需特判；但若把 $\text{dp}$ 开成 $n$ 长度就会越界，务必开 $n+1$。
8. **答案规模**：最大 $5\times10^8$，在 32 位有符号范围内；若题目把 $profit$ 上限调大，就要整体换成 `long long`。
