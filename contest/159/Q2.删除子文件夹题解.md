# LeetCode 删除子文件夹 题解

## 1. 题目概述

- **标题 / 题号**：删除子文件夹（#1233，medium）
- **链接**：https://leetcode.cn/problems/remove-sub-folders-from-the-filesystem/
- **来源**：LeetCode 第 159 场周赛 Q2
- **难度**：中等
- **标签**：数组、字符串、排序、深度优先搜索、字典树

**题意**：给定一组互不相同的绝对路径 `folder`（形如 `/a/b/c`，以 `/` 开头，段与段之间用 `/` 分隔，无尾随 `/`）。若 `folder[i]` 位于 `folder[j]` 之下——即 `folder[i]` 以 `folder[j]` 开头、并且紧接着一个 `/`——则 `folder[i]` 是子文件夹，必须删除。要求以**任意顺序**返回删除所有子文件夹后剩下的文件夹。

换一种说法：只保留那些**在列表中不存在任何祖先**的路径。

**约束**：

- $1 \le \lvert \text{folder} \rvert \le 4 \times 10^4$
- $2 \le \lvert \text{folder}[i] \rvert \le 100$
- `folder[i]` 只包含小写英文字母和 `/`，且总是以 `/` 起始
- `folder` 中每个元素**唯一**（这一点让下文的前缀判定不必处理相等的情况）

## 2. 示例

**示例 1**

```text
输入：folder = ["/a","/a/b","/c/d","/c/d/e","/c/f"]
输出：["/a","/c/d","/c/f"]
解释："/a/b" 是 "/a" 的子文件夹，"/c/d/e" 是 "/c/d" 的子文件夹，都要删除。
```

**示例 2**

```text
输入：folder = ["/a","/a/b/c","/a/b/d"]
输出：["/a"]
解释："/a/b/c" 与 "/a/b/d" 都是 "/a" 的子文件夹；注意中间层 "/a/b" 不在列表里。
```

**示例 3**

```text
输入：folder = ["/a/b/c","/a/b/ca","/a/b/d"]
输出：["/a/b/c","/a/b/ca","/a/b/d"]
解释："/a/b/ca" 虽然以 "/a/b/c" 开头，但下一位是 'a' 而不是 '/'，
      按定义它不是子文件夹，三者全部保留。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：对每个 `folder[i]`，枚举其余每个 `folder[j]`，检查 `folder[i]` 是否以 `folder[j] + "/"` 开头。

- 共有 $n^2$ 个有序对，每次前缀判定最坏 $O(L)$（$L$ 为路径长度），总复杂度 $O(n^2 L)$。
- 代入 $n = 4 \times 10^4$、$L \le 100$，最坏约 $1.6 \times 10^{11}$ 次字符比较，必然超时。

瓶颈很清楚：**对每个路径，我们都在盲目地猜「谁可能是它的祖先」**。只要给路径排个序，这个「猜」就能变成「看前一个」。

### 3.2 核心观察：字典序排序 + 「父 + /」边界判定

![判定引理与排序后的区间封闭性](images/wc159_q2_boundary_rule.svg)

**观察一（判定要带分隔符）**：`f` 是 `g` 的子文件夹 $\iff$ `f` 以 `g + "/"` 开头。少了那个 `/`，`/a/b/ca` 就会被当成 `/a/b/c` 的子文件夹误删（示例 3 的陷阱）。

**观察二（排序后祖先紧邻在前）**：把路径按字典序升序排列，父目录一定排在它的所有后代之前，而且**夹在父与某个后代之间的元素，全都是这个父的后代**。原因是字符 `/` 的 ASCII 码是 47，比任何小写字母（97–122）都小：任何「在 `p` 之后、又在 `p + "/" + ...` 之前」的字符串，只可能第 $|p|$ 位正好是 `/`，也就是 `p` 的后代。

有了这两条，维护一个「最后被保留的路径」`prev` 就够了：扫描到一个新路径 `f` 时，它要么是 `prev` 的后代（跳过），要么已经走出了 `prev` 的子树（保留，并把 `prev` 换成 `f`）。**更早的祖先永远不需要回头看**，因为它们的后代区间已经结束。

### 3.3 算法流程

![排序 + 单遍扫描的流程图](images/wc159_q2_scan_flow.svg)

1. 把 `folder` 按字典序升序排序；
2. `ans = [folder[0]]`，队尾 `prev = folder[0]`；
3. 对 `i = 1 .. n-1`，令 `key = prev + "/"`：
   - 若 `folder[i]` 以 `key` 开头 → 它是子文件夹，**跳过**；
   - 否则 → **保留** `folder[i]`，并令 `prev = folder[i]`；
4. 返回 `ans`。

### 3.4 示例演算

以示例 1（输入恰好已有序）为例，逐个比对队尾：

![示例 1 的逐行走查表](images/wc159_q2_walkthrough.svg)

| i | folder[i] | prev | prev + "/" | 匹配？ | 动作 | ans |
|---|-----------|------|------------|--------|------|-----|
| 0 | `/a` | —（初始） | — | — | 保留，prev = `/a` | `[/a]` |
| 1 | `/a/b` | `/a` | `/a/` | ✓ | 跳过 | `[/a]` |
| 2 | `/c/d` | `/a` | `/a/` | ✗ | 保留，prev = `/c/d` | `[/a, /c/d]` |
| 3 | `/c/d/e` | `/c/d` | `/c/d/` | ✓ | 跳过 | `[/a, /c/d]` |
| 4 | `/c/f` | `/c/d` | `/c/d/` | ✗ | 保留（结束） | `[/a, /c/d, /c/f]` |

- 第 2 步 `/c/d` 不匹配 `/a/`，说明已经走出 `/a` 的子树，于是换父；此后 `/a` 再也不会参与比较。
- 第 4 步 `/c/f` 与 `/c/d/` 在 `d` 处失配，走出 `/c/d` 的子树，再次保留。
- 结果 `[/a, /c/d, /c/f]` 与示例 1 的输出一致（顺序也相同，但判题不要求顺序）。

## 4. 算法细节

1. **为什么排序就能保证「父在前」**：`g` 是 `g + "/" + rest` 的严格前缀，而严格前缀在字典序中恒小于被扩展串，所以父必然排在前面。这条性质与目录树的先序遍历顺序一致。
2. **前缀判定必须拼上分隔符**：C++ 里写 `folder[i].compare(0, key.size(), key) == 0`（`key = prev + "/"`），Python 里写 `f.startswith(prev + "/")`。若省掉 `/`，示例 3 立刻出错。
3. **C++ 避免每次拼接字符串**：`prev + "/"` 每个元素都会新建一个字符串（$O(L)$ 分配）。可以改成三个条件：长度严格更大、前 `prev.size()` 个字符相等、第 `prev.size()` 个字符恰好是 `/`。总开销从「每轮一次分配」降为纯比较。
4. **长度检查必须放在下标访问之前**：`folder[i][prev.size()]` 要求 $\lvert f \rvert > \lvert prev \rvert$。虽然排序后 `f >= prev` 恒成立，但 `f` 完全可能比 `prev` 短（例如 `prev = /c/d`、`f = /c/e` 长度相同，或 `prev` 更深），越界访问是未定义行为。
5. **`prev` 就是答案数组的末尾**：可以直接用 `ans.back()`（Python 用 `ans[-1]`），不必额外维护变量；单独存 `prev` 只是让代码可读性更好。
6. **不要用「对每个前缀查哈希表」的重型写法**：虽然也能做到 $O(\sum |folder[i]|)$（哈希集合 + 逐层剥掉最后一段），但常数远大于排序法，且需要切分字符串。本题排序法几行就能写完，$n \log n$ 次比较在 $4 \times 10^4$ 规模下毫秒级完成。
7. **注意排序是原地修改**：C++ 的参数是 `vector<string>&`，`sort` 会改掉调用方的数组。LeetCode 判题不在意，但如果线上代码里这份列表还要复用，应先拷贝一份。

## 5. 正确性证明

**引理 1（判定引理）**：对两个不同的合法路径 $f, g$，$f$ 是 $g$ 的子文件夹 $\iff$ $f$ 以 $g + "/"$ 开头。

**证明**：

- ($\Rightarrow$) 设 $f$ 位于 $g$ 之下，按定义 $f$ 以 $g$ 开头且紧跟一个 `/`，故 $f$ 以 $g + "/"$ 开头。
- ($\Leftarrow$) 若 $f$ 以 $g + "/"$ 开头，则 $f$ 由 $g$、一个 `/` 和其后若干段组成，即 $f$ 位于 $g$ 之下。∎

**引理 2（区间封闭性）**：设 $S$ 是 `folder` 升序排序后的数组。若 $i < j$ 且 $S[j]$ 以 $S[i] + "/"$ 开头，则对任意 $i < k < j$，$S[k]$ 也以 $S[i] + "/"$ 开头。

**证明**：记 $p = S[i]$，$m = |p|$。由排序有 $p < S[k] < S[j]$，且 $S[j]$ 的前 $m$ 个字符正是 $p$。

先证 $S[k]$ 以 $p$ 为前缀。若否，设 $t < m$ 是 $S[k]$ 与 $p$ 的第一个不同位置：若 $S[k][t] > p[t]$，则因 $S[j]$ 的第 $t$ 位也是 $p[t]$，得 $S[k] > S[j]$，矛盾；若 $S[k][t] < p[t]$，则 $S[k] < p$，矛盾。

再证 $|S[k]| > m$。若 $|S[k]| = m$，则 $S[k] = p = S[i]$，与元素互不相同矛盾。

最后证 $S[k][m] = "/"$。若 $S[k][m] > "/"$，则 $S[k] > S[j]$（两者第 $m$ 位分别是该字符与 `/`），矛盾；若 $S[k][m] < "/"$，则 $S[k] < p$，矛盾。故 $S[k][m] = "/"$，即 $S[k]$ 以 $p + "/"$ 开头。∎

**引理 3（队尾即祖先）**：扫描到下标 $j$ 时，若 $S[j]$ 在 $S[0..j)$ 中存在祖先，则此时 `prev` 是 $S[j]$ 的某个祖先。

**证明**：设 $a$ 是 $S[j]$ 在 $S[0..j)$ 中**最浅**（长度最短）的祖先。

- $a$ 一定被保留：若 $a$ 有祖先 $b \in S[0..a)$，则 $b$ 也是 $S[j]$ 的祖先且比 $a$ 更浅，与 $a$ 的最浅性矛盾。
- 由引理 2，$a$ 与 $j$ 之间的每个元素都以 $a + "/"$ 开头，扫描时全部被跳过，因此 `prev` 从 $a$ 被保留之后一直保持为 $a$，直到处理 $S[j]$。

故此时 `prev` 恰为 $a$，它确实是 $S[j]$ 的祖先。∎

**定理**：算法输出的集合恰为「在 `folder` 中不存在祖先」的全部路径。

**证明**：

- （只保留合法的）设 $f$ 被保留。若 $f$ 在 `folder` 中有祖先 $a$，不妨取最浅的 $a$：由引理 3，处理 $f$ 时 `prev` 恰为 $a$，于是 $f$ 以 $a + "/"$ 开头会被跳过，与「被保留」矛盾。故被保留者没有祖先。
- （合法的都保留）设 $f$ 没有祖先。跳过只会发生在「$f$ 以 `prev` 拼上 `/` 为前缀」时，而 `prev` 是先前被保留的某个 `folder` 元素（属于 `folder`），由引理 1 它就是 $f$ 的祖先，矛盾。故 $f$ 必定被保留。

两边合起来，输出恰好是所有「无祖先」的路径，而删除的恰好是所有「有祖先」的路径。∎

## 6. 复杂度分析

- **时间**：$O(n \log n \cdot L + n L)$，其中 $n = \lvert \text{folder} \rvert$、$L$ 为路径长度上界。排序需要 $O(n \log n)$ 次字符串比较，每次最坏 $O(L)$；扫描一遍，每个元素做一次 $O(L)$ 的前缀比较。取 $n = 4\times10^4$、$L = 100$，约为 $10^7$ 量级，完全够快。
- **空间**：$O(\log n)$ 为排序的递归栈；答案数组 $O(nL)$ 属于输出，不计入额外空间。若用三条件版本的前缀判定，除输出外**没有**与 $L$ 相关的临时字符串分配。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> removeSubfolders(vector<string>& folder) {
        sort(folder.begin(), folder.end());          // 父目录必在后代之前
        vector<string> ans;
        ans.push_back(folder[0]);
        for (size_t i = 1; i < folder.size(); ++i) {
            const string& prev = ans.back();
            // f 以 prev + '/' 开头  <=>  f 是 prev 的子文件夹
            bool isSub = folder[i].size() > prev.size() &&
                         folder[i].compare(0, prev.size(), prev) == 0 &&
                         folder[i][prev.size()] == '/';
            if (!isSub) {
                ans.push_back(folder[i]);            // 走出旧子树，换队尾
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def removeSubfolders(self, folder: List[str]) -> List[str]:
        folder.sort()                    # 父目录必在后代之前
        ans = [folder[0]]
        for f in folder[1:]:
            # 只要不以「队尾 + /」开头，就说明走出了旧子树
            if not f.startswith(ans[-1] + '/'):
                ans.append(f)
        return ans
```

## 8. 边界情况与易错点

1. **只有一个文件夹**：`n = 1` 时循环不执行，直接返回该元素；注意不要写成「先假设答案为空再在循环里填」，否则会漏掉首项。
2. **前缀相同但不是子文件夹**：`/a/b/c` 与 `/a/b/ca` 必须都保留。判定一定要带 `/`，且要比较「第 $|prev|$ 个字符」，不能只做 `startswith(prev)`。
3. **深层嵌套**：`["/a", "/a/b", "/a/b/c"]` 只保留 `/a`。中间层被跳过后 `prev` 依旧是 `/a`，第三个元素仍然匹配 `/a/`，不能因为「上一项被跳过」就把 `prev` 更新成 `/a/b`。
4. **C++ 下标越界**：`folder[i][prev.size()]` 只有在 $|f| > |prev|$ 时才合法；三个条件的顺序不能调换，否则 `compare` 之后先取下标就是 UB。
5. **返回顺序**：题目允许任意顺序，排序后的顺序同样合法；不要为了「还原输入顺序」多做一次映射。
6. **全是兄弟目录**：如 `["/a", "/b", "/c"]`，每次都不匹配，`ans` 逐项增长，输出与输入一致——这也是最容易漏测的「零删除」场景。
7. **只读/复用输入**：C++ 版本会原地排序 `folder`；若调用方后续还要用原顺序，需先 `auto copy = folder;`。
