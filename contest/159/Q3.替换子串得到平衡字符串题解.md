# LeetCode 替换子串得到平衡字符串 题解

## 1. 题目概述

- **标题 / 题号**：替换子串得到平衡字符串（#1234，Medium）
- **链接**：https://leetcode.cn/problems/replace-the-substring-for-balanced-string/
- **来源**：LeetCode 第 159 场周赛 Q3
- **难度**：中等
- **标签**：字符串、滑动窗口

**题意**：字符串只含 `Q`、`W`、`E`、`R` 四种字符，长度 $n$ 是 4 的倍数。若四种字符各出现 $n/4$ 次，称其为**平衡字符串**。现在可以选出**一段连续子串**，用**等长的任意字符串**整体替换它，要求替换后整个字符串平衡，求这段子串的**最小可能长度**；原串已平衡则返回 0。

**约束**：

- $1 \le n \le 10^5$，且 $n$ 是 4 的倍数
- `s` 中只含 `Q`、`W`、`E`、`R`
- 替换串长度必须与被替换子串相同，内容任意

> 💡 关键理解：并不是「缺什么字符就把它补进去」那么简单——替换会**同时删掉**窗口里原有的字符，所以窗口之外的计数才是真正被固定住的部分。

## 2. 示例

**示例 1**

```text
输入：s = "QWER"
输出：0
解释：s 本身已经平衡，不需要替换。
```

**示例 2**

```text
输入：s = "QQQW"
输出：2
解释：Q 出现 3 次，超出配额 1 次共 2 个；把前两个 'Q' 换成 "ER"，
      得到 "ERQW"，四种字符各 1 个。
```

**示例 3**

```text
输入：s = "QQQQ"
输出：3
解释：配额为 1，Q 超出 3 个；替换后三个 'Q' 为 "WER"，得到 "QWER"。
      （留下唯一的 1 个 Q 正好满足配额，所以不需要替换 4 个。）
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子串（$O(n^2)$ 个），对每个子串统计窗口外的字符计数、判断是否都不超过 $n/4$，取最短的合法子串；$n = 10^5$ 时有 $5 \times 10^9$ 个窗口，稳稳超时。另一个常见误区是「按需要的字符数排序后贪心挑字符」——窗口是**连续**的，字符位置不能任意挑选，贪心不成立。

### 3.2 核心观察：配额 + 超额 → 最短窗口

![配额与超额模型](images/wc159_q3_quota_excess_model.svg)

记 $t = n/4$，$T(c)$ 为字符 $c$ 在整串中的出现次数，定义**超额**

$$\text{need}(c) = \max\bigl(0,\ T(c) - t\bigr)$$

因为替换只动窗口内部，**窗口外的计数是固定的**：设窗口为 $[l, r]$，长度为 $L$，窗口外计数为 $\text{out}(c)$，则

$$\text{out}(c) = T(c) - \text{in}(c)$$

于是「替换后能平衡」$\iff$ 对所有 $c$ 有 $\text{out}(c) \le t$，移项即

$$\text{in}(c) \ \ge\ T(c) - t \quad\Longleftrightarrow\quad \text{in}(c) \ge \text{need}(c)$$

也就是说：**窗口必须把每个字符的「超额部分」全部吞进去**。对于 $T(c) \le t$ 的字符，$\text{need}(c) = 0$，窗口内一个都不需要。

这样问题变成：找一个**最短的连续窗口**，使得每种字符在窗口内的出现次数不少于 $\text{need}(c)$。这是一个标准的「最短覆盖窗口」问题——条件对窗口扩张**单调**（加入字符只会让 $\text{in}$ 变大），所以双指针可行。

### 3.3 算法流程

![双指针流程](images/wc159_q3_two_pointer_flow.svg)

维护窗口内的计数数组 $\text{in}$，以及

$$m = \#\{\,c : \text{need}(c) > 0 \ \text{且}\ \text{in}(c) < \text{need}(c)\,\}$$

即「还有几个字符没被窗口补齐」。$m = 0$ 就等价于窗口合法（见 §5 引理 2）。

1. 统计 $T(c)$，算出 $\text{need}(c)$；若全部为 0，直接返回 0。
2. 右指针 $r$ 从左往右扫，把 `s[r]` 加入窗口；若加入后 $\text{in}(s[r])$ 恰好等于 $\text{need}(s[r])$，说明这个字符由「未补齐」变成「已补齐」，$m$ 减 1。
3. 当 $m = 0$ 时不断收缩：用当前窗口长度更新答案，然后把 `s[l]` 移出窗口、$l$ 右移；若移出的字符原本恰好「刚好达标」（$\text{in} = \text{need}$），$m$ 加 1，收缩停止。
4. $r$ 走到末尾后返回记录的答案。

$r$ 与 $l$ 都**只增不减**，每个字符最多进出窗口各一次，总时间 $O(n)$，空间 $O(1)$（只有 4 个计数器）。

### 3.4 示例演算

![示例演算](images/wc159_q3_walkthrough.svg)

以 `s = "QQQQWWWW"`（$n = 8$，$t = 2$）为例：$T = (Q{:}4, W{:}4, E{:}0, R{:}0)$，故 $\text{need} = (2, 2, 0, 0)$，初始 $m = 2$。

| 步骤 | $l$ | $r$ | 窗口 | $\text{in}(Q, W)$ | $m$ | 答案 |
|------|-----|-----|------|-------------------|-----|------|
| $r$ 扩到 5 | 0 | 5 | `QQQQWW` | $(4, 2)$ | 0 | 6 |
| 收缩 $l \to 1$ | 1 | 5 | `QQQWW` | $(3, 2)$ | 0 | 5 |
| 收缩 $l \to 2$ | 2 | 5 | `QQWW` | $(2, 2)$ | 0 | **4** |
| 再收缩 $l \to 3$ | 3 | 5 | `QWW` | $(1, 2)$ | 1 | 4 |
| $r$ 扩到 7 | 3 | 7 | `QWWWW` | $(1, 4)$ | 1 | 4 |

$l = 3$ 时窗口内只剩 1 个 `Q`，欠 1 个超额，$m$ 回到 1，收缩必须停止；之后 $r$ 继续右移也无法补回 `Q`（右侧已没有 `Q`），因此最终答案为 4，对应窗口 `[2, 5]`。

## 4. 算法细节

1. **`need` 一定要取 $\max(0, \cdot)$**：字符不足配额时 $\text{need}$ 为 0，不能写成负数——否则「窗口内计数 ≥ 负数」恒成立，会把非法窗口误判为合法。
2. **`m` 的精确维护**：加入字符时只有 `in == need` 这一**恰好相等**的时刻才让 $m$ 减 1（否则同一字符会被重复计数）；收缩时同理，只有 `in == need` 的时刻让 $m$ 加 1。两个方向的判据都是「跨越边界」，保证 $m$ 始终等于「未达标字符个数」。
3. **必须排除 `need == 0` 的字符**：这类字符永远达标，不参与 $m$；代码里用 `need[c] > 0` 短路，避免 `in == need == 0` 时误操作。收缩时 `s[l]` 必在窗口内，`in > 0`，所以它不会触发误判，但显式判断更稳妥。
4. **答案初值取 $n$ 是安全的**：整串必然合法（$\text{in} = T \ge \text{need}$），而首次 $m$ 归零之前 $l$ 一直停在 0，所以第一次归零时考察的正是某个前缀 $[0, r]$，$r = n-1$ 时该前缀一定合法，故答案必然被更新过，无需额外兜底。
5. **用数组而非哈希表**：字符集只有 4 个，把 $Q,W,E,R$ 映射到 $0..3$，`total` / `need` / `in` 都用长度 4 的数组，比 `unordered_map` 快一个数量级；也正因为判据已改写成「窗口内 ≥ 超额」，无需再维护窗口外计数。
6. **字符映射不要留隐式假设**：若换成「全部 26 个大写字母、26 等分」，只需把数组长度 `4` 换成 `26`，逻辑完全不变。

## 5. 正确性证明

**引理 1（合法性判据）**：对窗口 $[l, r]$，存在一种等长替换使整个字符串平衡 $\iff$ 对所有字符 $c$ 有 $\text{out}(c) \le t$。

**证明**：

- 必要性：替换只改动窗口内的 $L$ 个位置，窗口外的 $n - L$ 个字符不变；替换后要求每种字符都恰好 $t$ 个，故窗口外计数必须满足 $\text{out}(c) \le t$。
- 充分性：条件 $\text{out}(c) \le t$ 下，把窗口内填成「每个字符补足到 $t$」即可。所需数量为 $\delta(c) = t - \text{out}(c) \ge 0$，而

$$\sum_{c} \delta(c) = 4t - \sum_{c}\text{out}(c) = n - (n - L) = L$$

恰好等于窗口长度，因此可以精确填满窗口；填进去的字符都属于 $\{Q,W,E,R\}$，满足长度与内容要求。∎

**引理 2（$m$ 的语义）**：算法运行过程中恒有

$$m = \#\{\,c : \text{need}(c) > 0 \ \text{且}\ \text{in}(c) < \text{need}(c)\,\}$$
从而 $m = 0 \iff$ 对所有 $c$ 有 $\text{in}(c) \ge \text{need}(c)$。

**证明**：初始时 $\text{in} \equiv 0$，$m$ 初始化为 $\#\{c : \text{need}(c) > 0\}$，等式成立。加入字符 $c$ 时 $\text{in}(c)$ 加 1：若此前 $\text{in}(c) < \text{need}(c)$，则 $c$ 属于集合；加 1 后只有当 $\text{in}(c)$ 达到 $\text{need}(c)$ 时才离开集合，恰对应「$m$ 减 1」的条件 `in == need`（且 $\text{need}(c) > 0$，因为 $\text{need}(c)=0$ 时 $c$ 本就不在集合里）。收缩时 $\text{in}(c)$ 减 1：若此前 $\text{in}(c) = \text{need}(c) > 0$，减 1 后 $c$ 重新进入集合，恰对应「$m$ 加 1」。其余字符的计数不变，故不变式保持。

又因 $\text{need}(c) = 0$ 时 $\text{in}(c) \ge 0 = \text{need}(c)$ 自动成立，所以 $m = 0$ 与「全部 $c$ 满足 $\text{in}(c) \ge \text{need}(c)$」等价。∎

**定理**：算法的返回值等于最小可能的替换长度。

**证明**：分两步。

（1）**答案不会偏小**：算法只在 $m = 0$ 时用窗口长度更新答案，由引理 2 此时全部 $\text{in}(c) \ge \text{need}(c)$，即 $\text{out}(c) \le t$，由引理 1 该窗口确实可以替换成平衡串，故记录的每个长度都是可行长度，答案 $\ge$ 最优值。

（2）**答案不会偏大**：设最优窗口为 $[l^{*}, r^{*}]$，长度 $\mathrm{OPT} = r^{*} - l^{*} + 1$。合法性对左端点单调：$[l, r]$ 合法则 $[l-1, r]$ 也合法（窗口只会变大），故固定 $r$ 时合法的左端点构成一个前缀。记处理 $r$ 时收缩起点为 $l_0(r)$：若 $l_0(r^{*}) > l^{*}$，则 $l_0(r^{*}) - 1$ 必是某一步 $r' \le r^{*}-1$ 记录过的合法窗口左端点，且 $l_0(r^{*}) - 1 \ge l^{*}$，于是记录了长度 $r' - l_0(r^{*}) + 2 \le r^{*} - l^{*} < \mathrm{OPT}$ 的合法窗口，与 $\mathrm{OPT}$ 的最小性矛盾。故 $l_0(r^{*}) \le l^{*}$，收缩循环必然推进到 $l = l^{*}$；此时 $[l^{*}, r^{*}]$ 合法（引理 2 给出 $m = 0$）并记录长度 $\mathrm{OPT}$，即答案 $\le \mathrm{OPT}$。

两步合起来，返回值 $= \mathrm{OPT}$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。预处理统计 $T(c)$ 一次 $O(n)$；右指针 $r$ 前进 $n$ 步，左指针 $l$ 累计前进不超过 $n$ 步，每次进出窗口都是 $O(1)$ 的数组操作与比较，总计 $O(n)$。
- **空间**：$O(1)$。只需 `total`、`need`、`in` 三个长度 4 的数组和若干标量，与 $n$ 无关（不计输入本身）。若把字符集推广到 $k$ 种则为 $O(k)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    int balancedString(string s) {
        int n = (int)s.size(), t = n / 4;
        auto id = [](char c) -> int {
            if (c == 'Q') return 0;
            if (c == 'W') return 1;
            if (c == 'E') return 2;
            return 3;
        };

        int total[4] = {0, 0, 0, 0};
        for (char c : s) total[id(c)]++;

        int need[4], missing = 0;
        for (int i = 0; i < 4; i++) {
            need[i] = max(0, total[i] - t);
            if (need[i] > 0) missing++;
        }
        if (missing == 0) return 0;          // 原串已平衡

        int in[4] = {0, 0, 0, 0};
        int ans = n, l = 0;
        for (int r = 0; r < n; r++) {
            int c = id(s[r]);
            in[c]++;
            if (need[c] > 0 && in[c] == need[c]) missing--;   // 恰好补齐

            while (missing == 0) {                            // 窗口外已合法
                ans = min(ans, r - l + 1);
                int d = id(s[l]);
                if (need[d] > 0 && in[d] == need[d]) missing++; // 即将欠账
                in[d]--;
                l++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def balancedString(self, s: str) -> int:
        n = len(s)
        t = n // 4
        idx = {'Q': 0, 'W': 1, 'E': 2, 'R': 3}

        total = [0, 0, 0, 0]
        for ch in s:
            total[idx[ch]] += 1

        need = [max(0, total[i] - t) for i in range(4)]
        missing = sum(1 for i in range(4) if need[i] > 0)
        if missing == 0:
            return 0                       # 原串已平衡

        inside = [0, 0, 0, 0]
        ans = n
        l = 0
        for r in range(n):
            c = idx[s[r]]
            inside[c] += 1
            if need[c] > 0 and inside[c] == need[c]:
                missing -= 1               # 这个字符补齐了

            while missing == 0:            # 窗口外全部不超过配额
                if r - l + 1 < ans:
                    ans = r - l + 1
                d = idx[s[l]]
                if need[d] > 0 and inside[d] == need[d]:
                    missing += 1           # 移走后就要欠账
                inside[d] -= 1
                l += 1

        return ans
```

## 8. 边界情况与易错点

1. **原串已平衡必须先返回 0**：`"QWER"` 的 `missing` 初值就是 0，若不提前返回，内层收缩循环会一直成立（没有需要补齐的字符），$l$ 一路推过 $r$ 直到 `s[l]` 越界——既是死循环也是数组越界。
2. **替换整串没有任何意义也不一定最优**：`"QQQQ"` 的答案是 3 而不是 4——留下一个 `Q` 恰好满足配额，说明「窗口外计数 ≤ 配额」是**不等式**而非等式。
3. **$n$ 是 4 的倍数**：若题目数据不满足，$t$ 向下取整会让 $\sum \delta(c) \ne L$，引理 1 的构造失效。本题保证 $n \bmod 4 = 0$。
4. **`need` 必须截断到 0**：写成 `total[i] - t` 会出现负数，导致窗口内计数永远「达标」，最短窗口退化为 0。
5. **`missing` 的加减条件写成「恰好相等」**：若写成 `in[c] >= need[c]`，同一个字符每加一次都会让 `missing` 减 1，最终 `missing` 变成负数，内层 `while (missing == 0)` 不再成立，答案会偏大。
6. **下标越界**：收缩循环里 `s[l]` 的访问必须保证 $l \le r$。由于 `missing == 0` 时窗口非空（$m$ 的初值来自 `need`，空窗口不可能补齐任何正超额），$l \le r$ 自动成立，不必额外判断。
