# LeetCode 找出数组的最大公约数 题解

## 1. 题目概述

- **标题 / 题号**:找出数组的最大公约数(#1979,Easy)
- **链接**:https://leetcode.cn/problems/find-greatest-common-divisor-of-array/
- **来源**:LeetCode 第 255 场周赛 Q1
- **难度**:简单
- **标签**:数组、数学、最大公约数、欧几里得算法

**题意**:给定整数数组 `nums`,找出其中的**最小值** `mn` 与**最大值** `mx`,返回 $\gcd(mn, mx)$。最大公约数定义为能同时整除两个数的最大正整数。

**约束**:

- $2 \le \mathrm{nums.length} \le 1000$
- $1 \le \mathrm{nums[i]} \le 1000$

## 2. 示例

**示例 1**

```text
输入:nums = [2,5,6,9,10]
输出:2
解释:最小值是 2,最大值是 10,gcd(2, 10) = 2。
```

**示例 2**

```text
输入:nums = [7,5,6,8,3]
输出:1
解释:最小值是 3,最大值是 8,gcd(3, 8) = 1。
```

**示例 3**

```text
输入:nums = [3,3]
输出:3
解释:最小值与最大值都是 3,gcd(3, 3) = 3。
```

## 3. 解题思路

### 3.1 朴素思路

题目分两步:找 `mn`/`mx`,再求 gcd。最容易想到的写法是**排序**,取首尾两个元素做辗转相除——正确,但多做了一层 $O(n \log n)$ 的排序。另一个朴素想法是按 gcd **定义**枚举:从 $d = \min(mn, mx)$ 往下找第一个同时整除两者的数,复杂度 $O(V)$($V \le 1000$),本题也能过,但数据范围一放大立刻失效。

签到题的目标是**从题面到代码走最短路径**:求 `mn`/`mx` 一遍线性扫描即可,gcd 交给欧几里得辗转相除,$O(\log V)$ 步封顶。

### 3.2 核心观察:答案只依赖 mn 与 mx 两个数

数组中除最小值、最大值之外的元素**全部与答案无关**,因此既不需要排序也不需要任何预处理。而 gcd 有经典递推式:

$$\gcd(a, b) = \gcd(b, a \bmod b), \qquad \gcd(a, 0) = a$$

即"大数对 小数取余,余数顶替小数继续算",直到小数变为 $0$,剩下的大数就是答案。

![核心观察](images/c255_min_max_gcd_concept.svg)

> 💡 **一句话**:签到题的最短路径 = 「一遍扫描求 `mn`/`mx`」+「辗转相除求 gcd」,两段都是模板,值得形成肌肉记忆。

### 3.3 算法流程

1. 初始化 `mn = mx = nums[0]`;
2. 扫描每个元素 $x$:`mn = min(mn, x)`,`mx = max(mx, x)`;
3. 令 $(a, b) = (mx, mn)$,循环执行 $(a, b) \leftarrow (b, a \bmod b)$ 直到 $b = 0$;
4. 返回 $a$。

![算法流程](images/c255_euclid_flow.svg)

### 3.4 示例演算

以示例 2(`nums = [7,5,6,8,3]`,`mn = 3`,`mx = 8`)为例:

| 轮次 | $(a, b)$ | 带余除法 | 下一对 |
|------|----------|----------|--------|
| 1 | $(8, 3)$ | $8 = 3 \times 2 + 2$ | $(3, 2)$ |
| 2 | $(3, 2)$ | $3 = 2 \times 1 + 1$ | $(2, 1)$ |
| 3 | $(2, 1)$ | $2 = 1 \times 2 + 0$ | $(1, 0)$ |
| 4 | $(1, 0)$ | $b = 0$,终止 | 返回 $a = 1$ ✓ |

示例 1(`mn = 2`,`mx = 10`)一步整除:$10 = 2 \times 5 + 0$,直接得 $\gcd = 2$。

![示例演算](images/c255_example_walkthrough.svg)

## 4. 算法细节

1. **一遍扫描同时维护两个量**:`mn = min(mn, x)` 与 `mx = max(mx, x)` 互相独立,写两个独立 `if` 或直接用 `min`/`max` 函数均可,扫完即得全局最小与最大。
2. **辗转相除的迭代写法**:`while (b) { r = a % b; a = b; b = r; }`,返回 `a`。参数顺序不要求 $a \ge b$:若 $a < b$,第一步 $a \bmod b = a$ 会自动完成一次交换;但初始化成 `(mx, mn)` 更直观。
3. **内置函数**:C++17 起可用头文件 `<numeric>` 中的 `std::gcd`,GCC 另有扩展 `__gcd`;Python 一行 `math.gcd(min(nums), max(nums))` 即可。比赛求稳,**内置函数优先**。
4. **数据范围**:$1 \le \mathrm{nums[i]} \le 1000$,`int` 绰绰有余,无溢出风险,连 `long long` 都不必。

## 5. 正确性证明

**引理 1(辗转相除)**:设 $a \ge b \ge 1$,带余除法 $a = qb + r$($0 \le r < b$),则 $\gcd(a, b) = \gcd(b, r)$。

**证明**:只需证数对 $(a, b)$ 与 $(b, r)$ 的公因数集合完全相同。若 $d \mid a$ 且 $d \mid b$,则 $d \mid (a - qb) = r$;反之若 $d \mid b$ 且 $d \mid r$,则 $d \mid (qb + r) = a$。公因数集合相同,其最大元(即最大公因数)自然相等。∎

**引理 2(终止性)**:从任意 $b_0 \ge 1$ 出发,每轮 $b \leftarrow a \bmod b$ 满足新 $b < $ 旧 $b$,故有限轮后 $b = 0$,此时返回 $a$ 恰为所求。

**证明**:$b$ 的取值构成非负整数上的严格递减序列,至多 $b_0$ 轮内必到 $0$。到达 $(a, 0)$ 时:$a$ 的每个正因数显然整除 $0$;反之任何整除 $0$ 与 $a$ 的正整数必整除 $a$,故 $(a, 0)$ 的公因数集合即 $a$ 的因数集合,$\gcd(a, 0) = a$。∎

**定理**:上述算法返回 $\gcd(\min \mathrm{nums}, \max \mathrm{nums})$。

**证明**:对扫描过程归纳:处理完前 $k$ 个元素后 `mn`、`mx` 恰为它们的最小值与最大值——$k = 1$ 时初始化成立;每读入 $x$ 取 `min`/`max` 保持不变量。扫描结束后由引理 2,辗转相除循环必终止;由引理 1,每轮 $(a, b) \leftarrow (b, a \bmod b)$ 保持 gcd 不变,故终止时返回的 $a = \gcd(mn, mx)$。∎

## 6. 复杂度分析

- **时间复杂度**:$O(n + \log V)$,其中 $V = \max(\mathrm{nums})$。线性扫描 $O(n)$;由 Lamé 定理,辗转相除的步数不超过 $\min(a, b)$ 十进制位数的 $5$ 倍,即 $O(\log \min(mn, mx))$。本题 $V \le 1000$,辗转相除至多十余轮。
- **空间复杂度**:$O(1)$,只使用常数个额外变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int findGCD(vector<int>& nums) {
        int mn = nums[0], mx = nums[0];
        for (int x : nums) {
            mn = min(mn, x);
            mx = max(mx, x);
        }
        // 辗转相除:gcd(a, b) = gcd(b, a mod b)
        int a = mx, b = mn;
        while (b) {
            int r = a % b;
            a = b;
            b = r;
        }
        return a;
    }
};
```

### Python

```python
class Solution:
    def findGCD(self, nums: List[int]) -> int:
        mn = mx = nums[0]
        for x in nums:
            mn = min(mn, x)
            mx = max(mx, x)
        # 辗转相除:gcd(a, b) = gcd(b, a mod b)
        a, b = mx, mn
        while b:
            a, b = b, a % b
        return a
```

## 8. 边界情况与易错点

1. **所有元素相同**(示例 3):`mn == mx`,第一轮 `a % b == 0` 直接返回,答案即元素本身,无需特判。
2. **min = 1**:任何数与 $1$ 的 gcd 为 $1$,同样一轮出解($a \bmod 1 = 0$)。
3. **n = 2**:两个元素本身就是 `mn`/`mx`,流程照常工作,是最小的手写测试用例。
4. **参数顺序**:迭代写法不要求 $a \ge b$(第一步自动交换),但把 `(mx, mn)` 作为初始顺序最不容易想岔;递归写法注意 `gcd(a, 0)` 的**收敛出口**,漏掉会栈溢出。
5. **内置函数的坑**:C++ `std::gcd` 需要头文件 `<numeric>` 且要求 C++17;`__gcd` 是 GCC 扩展非标准。本题元素均为正数不涉及 $0$/负数;若推广到含 $0$ 的数组,注意 $\gcd(x, 0) = x$、含负数时应取绝对值。
6. **别把题读歪**:求的是「最大数与最小数这两个数」的 gcd,**不是**「数组整体 gcd」也不是「相邻元素的 gcd」——周赛 Q1 的最大风险是读题不细。

**延伸思考**:

- 求整个数组**所有元素**的 gcd:由结合律逐个滚动 $\gcd(\gcd(a, b), c)$ 即可;gcd 随元素加入单调不增,一旦变成 $1$ 可立即剪枝返回。
- 辗转相除的最坏步数出现在**相邻斐波那契数**上($\gcd(F_{k+1}, F_k)$ 每轮余数恰为前一个斐波那契数),这就是 Lamé 定理中"位数 5 倍"上界的来源。
- 大整数场景可换**二进制 gcd(Stein 算法)**:只用减法与移位,避开昂贵的除法,是不少大数库的底层实现。
