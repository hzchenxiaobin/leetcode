# LeetCode 最小化目标值与所选元素的差 题解

## 1. 题目概述

- **标题 / 题号**：最小化目标值与所选元素的差（#1981，medium）
- **链接**：https://leetcode.cn/problems/minimize-the-difference-between-target-and-chosen-elements/
- **来源**：LeetCode 第 255 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、可达和 DP、背包、剪枝

**题意**：给定 $m \times n$ 的正整数矩阵 `mat` 与整数 `target`。需要从**每一行**恰好选一个整数，设选中元素之和为 $S$，目标是最小化 $|S - \text{target}|$，返回这个最小绝对差。

**约束**：

- $1 \le m, n \le 70$
- $1 \le \text{mat}[i][j] \le 70$
- $1 \le \text{target} \le 800$

> 💡 关键数据画像：最大可能和为 $70 \times 70 = 4900$，但 `target` 至多 $800$。**「和的上界远大于 target」与「元素全为正」**这两件事合在一起，就是本题所有优化的出发点。

## 2. 示例

**示例 1**

```text
输入：mat = [[1,2,3],[4,5,6],[7,8,9]], target = 13
输出：0
解释：第一行选 1、第二行选 5、第三行选 7，和为 13，恰好等于目标。
```

**示例 2**

```text
输入：mat = [[1],[2],[3]], target = 100
输出：94
解释：每行只有一个元素，唯一方案和为 6，|6 - 100| = 94。
```

**示例 3**

```text
输入：mat = [[1,2,9,8,7]], target = 6
输出：1
解释：只有一行，最优是选 7，|7 - 6| = 1。
```

> ⚠️ 示例 2 是重要的"反向信号"：**所有方案的总和可能全部低于 target**；相应地也存在**全部超过 target** 的输入（如每行都是大元素、`target` 很小）。DP 状态设计必须同时照顾两侧。

## 3. 解题思路

### 3.1 暴力思路：枚举全部组合与"不剪枝"的可达和 DP

**纯暴力**：每行 $n$ 个选择、共 $m$ 行，组合数 $n^m$，$m = n = 70$ 时是天文数字，显然不可行。根本原因在于**子问题重叠**：前两行选 $(1,5)$ 与 $(2,4)$ 凑出的部分和同为 $6$，后续完全一致，暴力却各算一遍。

**朴素可达和 DP**：注意到"前 $i$ 行凑出哪些和"才是真正需要的信息。维护可达和集合，初始 $\{0\}$，每处理一行做一次"笛卡尔加法"：

$$dp' = \{\, s + v \mid s \in dp,\ v \in \text{mat}[i] \,\}$$

不封顶时和最大到 $4900$，集合大小 $\le 4901$，总时间 $O(m \cdot n \cdot 4900) \approx 24\text{M}$——比赛时直接这么写**也能过**。但它把大量"早已远离 target 的超额和"也一视同仁地滚动下去，浪费严重。

### 3.2 核心观察：超额折叠——dp 只开到 target

元素**全为正**意味着：部分和一旦越过 `target`，后续每行还要继续增大，**离 target 只会越来越远**。由此得到两个直接推论：

1. **$\le \text{target}$ 的可达和**：每个都仍有机会在后续行中被"微调"到更近的位置，**一个都不能丢**——用布尔数组 $dp[0..\text{target}]$ 无损保留；
2. **$> \text{target}$ 的可达和**：其中只有**最小者** `over` 值得记录。任何一个更大的超额部分和，其所有后续延伸都被"从 `over` 出发选同样后续元素"的对应方案**支配**（后者更小、仍然超额、离 target 更近），可以整块丢弃。

这就是"超额折叠"：把整个超额侧压缩成**一个整数**。状态数从 $4901$ 降到 $\text{target} + 2 \approx 802$。

![核心观察](images/c1981_reach_sum_concept.svg)

> 💡 一句话：**target 左侧逐格记账，target 右侧只记最小值**。左右两半各有归宿，合起来恰好覆盖所有候选答案。

### 3.3 算法流程

![算法流程](images/c1981_prune_flow.svg)

1. 初始化 $dp[0] = 1$（和 $0$ 可达，处理了 $0$ 行），$over \leftarrow \infty$；
2. 逐行处理。设当前行为 `row`，$r_{\min} = \min(\text{row})$：
   - 对每个可达的 $s$（$dp[s]=1$）与每个 $v \in \text{row}$：
     - 若 $s + v \le \text{target}$：置 $ndp[s+v] = 1$；
     - 否则：$nover \leftarrow \min(nover,\ s + v)$（折叠）；
   - 若 $over < \infty$：$nover \leftarrow \min(nover,\ over + r_{\min})$（超额状态的最优延续是"每行选最小"）；
   - 滚动：$dp \leftarrow ndp$，$over \leftarrow nover$；
3. 处理完全部 $m$ 行后，$dp$ 中可达的 $s$ 与 $over$（若有限）都是完整方案的和，返回

$$\min\Big(\,\min_{dp[s]=1} |s - \text{target}|,\ \ over - \text{target}\,\Big)$$

### 3.4 示例演算

以示例 1（`mat = [[1,2,3],[4,5,6],[7,8,9]]`，`target = 13`）为例：

![示例演算](images/c1981_example_walkthrough.svg)

| 阶段 | 转移 | $dp$（$\le 13$ 的可达和） | $over$ |
|------|------|------|------|
| 初始 | — | $\{0\}$ | $\infty$ |
| 第 0 行 $[1,2,3]$ | $0+1,0+2,0+3$ | $\{1,2,3\}$ | $\infty$ |
| 第 1 行 $[4,5,6]$ | $9$ 组合并去重 | $\{5,6,7,8,9\}$ | $\infty$ |
| 第 2 行 $[7,8,9]$ | $15$ 组合并；$\le 13$ 保留，超额折叠 | $\{12,13\}$ | $14$ |

答案 $= \min(|12-13|,\ |13-13|,\ 14-13) = 0$。

> 💡 看第 2 行的折叠瞬间：$15$ 个新部分和中只有 $12,13$ 落在 `target` 以内，$14 \sim 18$ 五个超额和被压缩成一个 `over = 14`。**越到后面、和越大，折叠砍掉的状态越多**——这正是该优化在深层行发挥作用的原因。

## 4. 算法细节

1. **状态含义的精确表述**：处理完前 $i$ 行后，$dp[s]=1 \iff$ 存在选法使前 $i$ 行部分和恰为 $s$ 且 $s \le \text{target}$；$over$ = 前 $i$ 行所有**超过** `target` 的部分和中的最小值（不存在则 $\infty$）。注意"部分和"在 $i = m$ 时就是完整方案的和。
2. **over 的转移为什么是 $over + r_{\min}$**：从超额状态出发，加任何元素都保持超额，新超额集合为 $\{over + v \mid v \in \text{row}\}$，其最小值恰为 $over + \min(\text{row})$。与左侧的折叠合并，统一取 $\min$。
3. **两种等价写法**：把 $over$ 塞回集合统一转移也对（从 $over$ 出发的新和全部超额，会被再次折叠到 $over + r_{\min}$），但分离维护更省事，也避免了把"超额"与"不超额"混在一层循环里造成语义混乱。
4. **行内去重**：元素值域仅 $[1,70]$，行内重复值对转移无增益，先 `set` 去重可减少内层枚举（对 $n = 70$ 全同值的极端行，从 $70$ 次降到 $1$ 次）。
5. **可选的快速通道**：若每行最小值之和 $\text{minSum} \ge \text{target}$，则任何方案的和 $\ge \text{minSum} \ge \text{target}$，答案直接为 $\text{minSum} - \text{target}$，可整体跳过 DP。这是引理 2 的直接推论，写上纯属白赚，不写也不影响正确性。
6. **滚动数组**：`ndp` 每行新建（或复用两个数组交替），转移是"由旧推新"的前向批量转移，与 0-1 背包的逆序原地滚动不同——本题每行**必选**一个元素，不存在"不选"的跳过转移，不能套用一维 0-1 背包的原地写法。

## 5. 正确性证明

**引理 1（部分和单调不减）**：任意方案中，元素全为正（$\text{mat}[i][j] \ge 1$），故完整方案的和严格大于其任何真前缀部分和；特别地，若某前缀部分和 $s > \text{target}$，则该方案的最终和也 $> \text{target}$。

**证明**：设方案在第 $1..i$ 行的选择为 $v_1, \dots, v_i$（前缀）与 $v_{i+1}, \dots, v_m$（后缀）。最终和 $S = \sum_{k=1}^{m} v_k = s + \sum_{k=i+1}^{m} v_k \ge s + (m - i) > s > \text{target}$。∎

**引理 2（超额支配性）**：处理完前 $i$ 行后，设 $s_1 < s_2$ 都是可达部分和且均 $> \text{target}$。则从 $s_2$ 出发的任何完整延伸，其目标值都不小于从 $s_1$ 出发、后续各行选择**相同元素**的对应方案。

**证明**：设后续选择为 $w_{i+1}, \dots, w_m$，两个最终和分别为 $S_1 = s_1 + W$，$S_2 = s_2 + W$，其中 $W = \sum w_k \ge m - i \ge 0$。由引理 1 的推理，$S_1 > \text{target}$ 且 $S_2 > \text{target}$，于是 $|S_1 - \text{target}| = S_1 - \text{target} < S_2 - \text{target} = |S_2 - \text{target}|$。即 $s_2$ 的该延伸被 $s_1$ 的对应延伸严格支配。∎

> 💡 引理 2 是"折叠"的许可证：超额侧只需留下**一个**代表（最小者），其余状态的任何未来都已被代表的患者安排得明明白白。

**定理（算法正确性）**：上述算法返回 $\min_S |S - \text{target}|$，其中 $S$ 取遍所有 $n^m$ 个方案的完整和。

**证明**：**（算法输出的每个值都对应真实方案）** $dp$ 的每次置位与 $over$ 的每次更新都源于"旧状态 + 某行某元素"的具体组合，对 $dp[0]=1$（空方案）归纳可知所有记录状态均有选法支撑；最终输出是若干真实方案的 $|S - \text{target}|$ 的最小值，故输出 $\ge$ 最优值。**（最优值被算法覆盖）** 对最优方案 $S^*$ 逐行考察其前缀部分和序列 $0 = p_0, p_1, \dots, p_m = S^*$：
- 若所有 $p_i \le \text{target}$：归纳可证每个 $p_i$ 都在 $dp$ 中被保留（转移规则第一条无损搬运），故最终 $dp[S^*] = 1$，算法覆盖 $S^*$；
- 若存在首个越界下标 $j$（$p_j > \text{target}$，而 $p_0..p_{j-1} \le \text{target}$）：此时 $p_{j-1}$ 在 $dp$ 中，转移时 $p_j$ 作为超额候选参与 $nover$ 的 $\min$，故处理完第 $j$ 行后 $over \le p_j$。此后每行，$over$ 按引理 2 的支配性以"每行加 $r_{\min}$"的方式延续到第 $m$ 行，得到某个最终和 $\widehat{S} = over_m \le p_j + \sum_{k>j}(\text{第 } k \text{ 行在 } S^* \text{ 中的选择}) = S^*$，且 $\widehat{S} > \text{target}$（引理 1）。于是 $|\widehat{S} - \text{target}| \le |S^* - \text{target}|$，算法至少覆盖了一个不劣于 $S^*$ 的候选。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(m \cdot (\text{target} + 1) \cdot n\big)$。每行要对 $\le \text{target}+1$ 个可达和各枚举 $n$ 个元素；代入上界 $70 \times 801 \times 70 \approx 3.9\text{M}$，比不封顶的 $24\text{M}$ 快约 $6$ 倍。
- **空间复杂度**：$O(\text{target})$。两个长度 $\text{target}+1$ 的布尔数组加常数个整数，与 $m, n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimizeTheDifference(vector<vector<int>>& mat, int target) {
        vector<char> dp(target + 1, 0);
        dp[0] = 1;
        int over = INT_MAX;                    // 超过 target 的最小可达和
        for (auto& row : mat) {
            vector<char> ndp(target + 1, 0);
            int nover = INT_MAX;
            int rowMin = *min_element(row.begin(), row.end());
            for (int s = 0; s <= target; ++s) {
                if (!dp[s]) continue;
                for (int v : row) {
                    if (s + v <= target) ndp[s + v] = 1;
                    else nover = min(nover, s + v);   // 超额折叠
                }
            }
            if (over < INT_MAX)                       // 先判有限,防 INT_MAX 溢出
                nover = min(nover, over + rowMin);    // 超额状态的最优延续
            dp = move(ndp);
            over = nover;
        }
        int ans = (over < INT_MAX) ? over - target : INT_MAX;
        for (int s = 0; s <= target; ++s)
            if (dp[s]) ans = min(ans, abs(target - s));
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimizeTheDifference(self, mat: List[List[int]], target: int) -> int:
        dp = [False] * (target + 1)
        dp[0] = True
        over = None                          # 超过 target 的最小可达和
        for row in mat:
            ndp = [False] * (target + 1)
            nover = None
            row_min = min(row)
            for s in range(target + 1):
                if not dp[s]:
                    continue
                for v in set(row):           # 行内去重
                    if s + v <= target:
                        ndp[s + v] = True
                    elif nover is None or s + v < nover:
                        nover = s + v        # 超额折叠
            if over is not None:
                cand = over + row_min        # 超额状态的最优延续
                if nover is None or cand < nover:
                    nover = cand
            dp, over = ndp, nover
        ans = over - target if over is not None else target
        for s in range(target + 1):
            if dp[s] and abs(target - s) < ans:
                ans = abs(target - s)
        return ans
```

## 8. 边界情况与易错点

1. **只截断不折叠（最常见翻车点）**：若只维护 $\le \text{target}$ 的 `dp` 而不记录 `over`，当**所有**方案都超过 `target` 时 `dp` 会变空、答案算错。反例：`mat = [[70,70],[70,70]], target = 2`，唯一和为 $140$，正确答案 $138$，纯截断版会输出垃圾值。示例 2（全部**低于** `target`）提示了双侧都要照顾，超额侧同样不能裸奔。
2. **C++ 溢出**：`over` 用 `INT_MAX` 表示 $\infty$ 时，`over + rowMin` 会溢出，必须**先判断 `over < INT_MAX`** 再相加；Python 用 `None` 语义则无此坑，但判断别写成 `if over:`（`over` 为 $0$ 不会发生，可一旦换成别的语义就埋雷）。
3. **数组大小**：`dp` 开 `target + 1`（下标 $0..target$），少开一格会在 $s + v = \text{target}$ 时越界。
4. **"dp 与 over 至少一方有效"不变量**：每行必选一个元素，处理完任何一行后 `dp` 非空或 `over` 有限必居其一，最终 `ans` 必然被更新——若你的实现里两者可以同时失效，说明转移写错了。
5. **不要套 0-1 背包的原地逆序滚动**：本题每行必选一个，转移是"旧集合整体推新集合"，用两份数组最稳；一维原地滚动会产生"本行选两次"的假方案。
6. **去重的位置**：对**行内元素**去重（值域 $[1,70]$），而不是对可达和去重后再保留（布尔数组天然去重）。
7. **m = 1**：单行时 `dp` 就是该行 $\le \text{target}$ 的元素集，`over` 是 $> \text{target}$ 元素的最小值，无需特判。
8. **性能预期**：不封顶的朴素版（和开到 $4900$）在 LeetCode 上也能通过，周赛时若时间紧张可先交朴素版再回来优化；但折叠版状态数与 $m$ 无关，是更"耐加强"的写法。

**延伸思考**：

- **若 `target` 高达 $10^9$**（值域仍小）：折叠后的 `dp` 也开不下了，但 $m \le 30$ 时可对行做 **meet in the middle**：前后各半求可达和集合（各自去重后 $\le 70^{15}$ 仍爆炸……退一步，若 $m \le 20$ 且每行值去重后很少，可行），排序后双指针/二分找最接近的和。

- **bitset 加速**：把 $dp$ 压成位整数，转移变为 `bits |= bits << v` 再与 $\text{target}$ 以内的掩码求交、超额部分单独折叠，可将内层复杂度除以机器字长，是 C++ 里的常数级优化。
