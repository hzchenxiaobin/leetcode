# LeetCode 交替按位异或分割的数目 题解

## 1. 题目概述

- **标题 / 题号**：交替按位异或分割的数目（#3811，medium）
- **链接**：https://leetcode.cn/problems/number-of-alternating-xor-partitions/
- **来源**：LeetCode 第 174 场双周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、哈希表、动态规划

**题意**：把 `nums` 切成若干**连续非空**块，要求各块的异或值依次等于 `target1, target2, target1, …`（**从 target1 开始**交替）。求合法切法数对 $10^9+7$ 取模。只有一个块且其异或为 `target1` 也算合法。

**约束**：

- $1 \le nums.length \le 10^5$
- $0 \le nums[i], target1, target2 \le 10^5$
- $target1 \ne target2$

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,1,4], target1 = 1, target2 = 5
输出：1
解释：[2,3] 异或为 1，[1,4] 异或为 5，唯一合法切法。
```

**示例 2**

```text
输入：nums = [1,0,0], target1 = 1, target2 = 0
输出：3
解释：三种切法：[1,0,0]；[1]|[0,0]；[1,0]|[0]。
```

**示例 3**

```text
输入：nums = [7], target1 = 1, target2 = 7
输出：0
解释：整块异或为 7 ≠ target1，无法切分。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有切分（$2^{n-1}$ 种），对每种切分逐块求异或并校验交替性，复杂度 $O(2^n \cdot n)$，$n = 10^5$ 时不可行。改成普通 DP：$dp[i]$ 表示"前缀 $i$ 的合法切法数"，需要枚举最后一块的起点 $j$，即 $O(n^2)$，也会 TLE。

### 3.2 核心观察：状态只有"最后一块是 target1 还是 target2"

![状态设计：按最后一块的异或值分两类](images/bw174_q3_dp_states.svg)

交替性意味着：只要知道**最后一块**等于哪个 target，下一块该等于什么就确定了。于是设

- $dp_1[i]$：把前缀 $nums[0..i-1]$ 切成合法交替序列、且**最后一块异或 = target1** 的方案数；
- $dp_2[i]$：同上，但最后一块异或 = target2。

转移按"最后一块的起点 $j$"分类：

$$dp_1[i] = \sum_{\substack{0 \le j < i \\ \text{xor}(j, i-1) = target1}} \big( dp_2[j] + [\,j = 0\,] \big), \qquad dp_2[i] = \sum_{\substack{0 \le j < i \\ \text{xor}(j, i-1) = target2}} dp_1[j]$$

其中 $[j=0]$ 表示"空前缀 + 一整块"这种起手方式。

### 3.3 算法流程

![前缀异或 + 哈希表：把 O(n²) 的枚举压成 O(1) 查表](images/bw174_q3_prefix_xor_map.svg)

用**前缀异或** $px[i] = nums[0] \oplus \cdots \oplus nums[i-1]$（$px[0] = 0$），则

$$\text{xor}(j, i-1) = px[i] \oplus px[j]$$

于是"异或等于 target"等价于"$px[j] = px[i] \oplus target$"，把转移变成**查表**：

```text
1. forT1 = {0: 1}（px = 0 处有“空前缀”这 1 种起手方式）；forT2 = {}
2. px = 0
3. for x in nums:
       px ^= x
       cur1 = forT1.get(px ^ target1, 0)      # 以 target1 结尾
       cur2 = forT2.get(px ^ target2, 0)      # 以 target2 结尾
       forT1[px] += cur2                      # 供“下一块是 target1”复用
       forT2[px] += cur1
4. 返回 cur1 + cur2
```

**注意两个表的"身份"**：`forT1` 存的是"以 target2 结尾的方案数之和（外加空前缀 1 种）"——因为接 target1 块的前驱只能是 target2 结尾（或空前缀）；`forT2` 存的才是"以 target1 结尾的方案数之和"。

### 3.4 示例演算

![示例演算：nums = [1,0,0]、target1 = 1、target2 = 0](images/bw174_q3_walkthrough.svg)

| $i$ | $px[i]$ | $dp_1[i]$ | $dp_2[i]$ | 说明 |
|-----|---------|-----------|-----------|------|
| 1 | 1 | 1 | 0 | `[1]` 单块 = target1 |
| 2 | 1 | 1 | 1 | `[1,0]` 单块；`[1]\|[0]` |
| 3 | 1 | 1 | 2 | `[1,0,0]` 单块；`[1]\|[0,0]`；`[1,0]\|[0]` |

答案为 $dp_1[3] + dp_2[3] = 1 + 2 = 3$，与示例一致。注意 $px$ 一直等于 1："新块异或为 0"的块对应 $px[j] = px[i] \oplus 0 = 1$，所以两次 `dp_2` 都查到同一个桶。

## 4. 算法细节

1. **两个映射的分工**：`forT1` 里既有 $dp_2[j]$ 又有空前缀的 $1$，它服务于"下一块 = target1"；`forT2` 里只有 $dp_1[j]$。写反了就会出现示例 1 输出 0 的错误。
2. **先查表、后登记**：必须先算 `cur1/cur2` 再把 $px[i]$ 记入两个表，否则同一位置会自己转给自己（块长为 0）。
3. **空前缀只对 target1 生效**：`forT1[0] = 1` 而不是两个表都加 1，否则会出现"以 target2 开头的分割"这种非法起手。
4. **取模**：加法随时 `% MOD`；Python 用取模运算天然安全。
5. **哈希表 vs 数组**：$px$ 可达 $2^{17}$ 级别（$nums[i] \le 10^5 < 2^{17}$），值域不大可以开数组，但 `unordered_map` 更通用。
6. **目标值可能为 0**：`nums[i] = 0` 与 `target = 0` 都要正常参与异或，不要漏掉 0 值桶。

## 5. 正确性证明

**引理 1（前缀异或表示区间异或）**：对任意 $0 \le j \le i$，$\text{xor}(j, i-1) = px[i] \oplus px[j]$。

**证明**：$px[i] = \bigoplus_{k<i} nums[k]$，$px[j] = \bigoplus_{k<j} nums[k]$，异或相消得 $\bigoplus_{j \le k < i} nums[k]$，即该区间异或。∎

**引理 2（转移完备且不重）**：任意合法切分按"最后一块的起点 $j$"与"最后一块是 target1 / target2"唯一分类，且每类的方案数为引理前的转移式。

**证明**：给定合法的前缀 $i$ 切分，其最后一块区间必是 $[j, i-1]$（$j$ 唯一），且异或必须等于当前该轮的目标值；去掉最后一块后是前缀 $j$ 的合法交替切分（或以 $j=0$ 表示没有前块）。反过来，任取 $j$、一个合法的前缀 $j$ 切分，再拼上异或等于目标的 $[j, i-1]$ 块，得到的仍是合法交替切分。因此是双射，计数即转移式。∎

**引理 3（查表等价）**：`cur1 = forT1[px[i] ^ target1]` 恰等于 $dp_1[i]$；`cur2 = forT2[px[i] ^ target2]` 恰等于 $dp_2[i]$（循环到第 $i$ 个元素时，两个表里的键值对已经收集了所有 $j < i$）。

**证明**：由引理 1，"$\text{xor}(j,i-1) = target1$"$\iff$ "$px[j] = px[i] \oplus target1$"。`forT1` 在键 $v$ 上累计的正是所有满足 $px[j] = v$ 的 $dp_2[j]$（外加 $v=0$ 时的空前缀 1 种），且只包含已处理的 $j < i$；对 `forT2` 同理。∎

**定理**：循环结束后 `cur1 + cur2` 等于 `nums` 的合法交替分割数。

**证明**：由引理 2、3，对每个 $i$ 有 `cur1 = dp_1[i]`、`cur2 = dp_2[i]`。合法分割的最后一块只可能是 target1 或 target2（交替序列的最后一项由块数奇偶决定），故 $dp_1[n] + dp_2[n]$ 覆盖全部合法分割，且两类互斥，相加不重不漏。取模保持加法同态。∎

## 6. 复杂度分析

- **时间**：$O(n)$ 平均。每个元素做两次哈希查找与两次哈希更新，均摊 $O(1)$。
- **空间**：$O(D)$，$D$ 为不同前缀异或值的个数，$D \le n+1$；两个哈希表各存一份。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int alternatingXOR(vector<int>& nums, int target1, int target2) {
        const int MOD = 1000000007;
        // forT1[v]：前缀异或为 v 的位置 j 上「以 target2 结尾的方案数」之和，
        //            外加空前缀 j = 0 的 1 种（此时下一块应等于 target1）。
        // forT2[v]：前缀异或为 v 的位置 j 上「以 target1 结尾的方案数」之和。
        unordered_map<int, long long> forT1, forT2;
        forT1[0] = 1;
        int px = 0;
        long long cur1 = 0, cur2 = 0;      // 以当前前缀结尾、最后一块为 target1 / target2 的方案数
        for (int x : nums) {
            px ^= x;
            cur1 = forT1.count(px ^ target1) ? forT1[px ^ target1] : 0;
            cur2 = forT2.count(px ^ target2) ? forT2[px ^ target2] : 0;
            forT1[px] = (forT1[px] + cur2) % MOD;
            forT2[px] = (forT2[px] + cur1) % MOD;
        }
        return (int)((cur1 + cur2) % MOD);
    }
};
```

### Python

```python
class Solution:
    def alternatingXOR(self, nums: list[int], target1: int, target2: int) -> int:
        MOD = 10 ** 9 + 7
        for_t1 = {0: 1}   # 前缀异或 -> 以 target2 结尾的方案数之和（含空前缀的 1 种）
        for_t2 = {}       # 前缀异或 -> 以 target1 结尾的方案数之和
        px = 0
        cur1 = cur2 = 0
        for x in nums:
            px ^= x
            cur1 = for_t1.get(px ^ target1, 0)
            cur2 = for_t2.get(px ^ target2, 0)
            for_t1[px] = (for_t1.get(px, 0) + cur2) % MOD
            for_t2[px] = (for_t2.get(px, 0) + cur1) % MOD
        return (cur1 + cur2) % MOD
```

## 8. 边界情况与易错点

1. **两个表写反**：`cur1` 必须查 `forT1`（里面是 $dp_2$ 与空前缀 1），`cur2` 查 `forT2`（里面是 $dp_1$）。写反后示例 1 输出 0、示例 3 输出 1，很容易被样例抓住，但也会漏掉"只有一个块"的情形。
2. **空前缀的位置**：`forT1[0] = 1` 只加一次，且不能加进 `forT2`。
3. **先查后写**：如果先把 $px[i]$ 登记再查询，会出现"自身转移到自身"的零长块。
4. **块必须非空**：推导中 $j < i$ 天然保证非空，实现上靠"先查后写"保证。
5. **取模**：`cur1 + cur2` 可能超过 `int`，C++ 用 `long long` 或先取模再相加。
6. **$target1 \neq target2$**：题目保证，因此两个桶不会互相污染；若相等则题意本身会退化（两种状态重合）。
7. **`target` 为 0**：`px ^ 0 == px`，此时查的就是当前 $px$ 对应的桶，容易误以为出 bug，实际合法。
