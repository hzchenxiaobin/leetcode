# LeetCode 删除系统中的重复文件夹 题解

## 1. 题目概述

- **标题 / 题号**：删除系统中的重复文件夹（#1948，hard）
- **链接**：https://leetcode.cn/problems/delete-duplicate-folders-in-system/
- **来源**：LeetCode 第 251 场周赛 Q4
- **难度**：困难
- **标签**：字典树、树的同构、后序遍历、哈希表、递归

**题意**：给定二维数组 `paths`，`paths[i]` 表示文件系统中第 $i$ 个文件夹的绝对路径（如 `["a","b"]` 表示 `/a/b`）。若两个文件夹（不必同层）包含**非空且相同**的子文件夹集合、且结构完全一致，则称它们**相同**。存在两个及以上相同文件夹时，这些文件夹**及其全部子文件夹**都要标记删除；文件系统**只执行一次删除**。返回删除后剩余文件夹的路径，顺序任意。

**约束**：

- $1 \le \text{paths.length} \le 2 \times 10^4$，$1 \le \text{paths[i].length} \le 500$
- $1 \le \text{paths[i][j].length} \le 10$，名字仅含小写字母
- $1 \le \sum \text{paths[i][j].length} \le 2 \times 10^5$ ← 决定性规模约束：**Trie 结点数 $N \le 2 \times 10^5$**
- 无两条路径指向同一文件夹；任意非根文件夹的父文件夹也在输入中（⟹ 输入恰好构成一棵完整的树）

> ⚠️ **三条题意红线**：① 子文件夹集合必须**非空**——两个空（叶子）文件夹永远不算相同；② 重复时**全部删除**，不是保留一份；③ 删除**只执行一次**——判定全部基于删除前的原树，删除后新出现的相同不再处理。

> 💡 本题在本仓库另有[每日题解 1948](../../solution/1901-2000/1948_删除系统中的重复文件夹.md)，两篇为姊妹篇：那边以「整树字符串序列化」为主线，附面试问答与 Merkle 哈希扩展；本篇按周赛复盘视角，聚焦赛场上真正的分水岭——**直接序列化会 $O(N \cdot D)$ 空间爆炸，必须用「结构 ID」让签名长度与深度脱钩**——并给出完整的引理-定理证明与边界清单。

## 2. 示例

**示例 1**

```text
输入：paths = [["a"],["c"],["d"],["a","b"],["c","b"],["d","a"]]
输出：[["d"],["d","a"]]
解释：/a 与 /c 都只包含名为 b 的空文件夹，二者相同，连同子文件夹一起删除；
      /d 只包含 a，不与任何文件夹相同，保留。
```

**示例 2**

```text
输入：paths = [["a"],["c"],["a","b"],["c","b"],["a","b","x"],["a","b","x","y"],["w"],["w","y"]]
输出：[["a"],["a","b"],["c"],["c","b"]]
解释：/a/b/x 与 /w 都只包含名为 y 的空文件夹 → 二者（及各自的子文件夹）删除。
      删除后 /a 与 /c 都只剩一个空文件夹 b，变得相同——但删除只执行一次，不再处理。
```

**示例 4**

```text
输入：paths = [["a"],["a","x"],["a","x","y"],["a","z"],["b"],["b","x"],["b","x","y"],["b","z"]]
输出：[]
解释：/a/x ≡ /b/x（都只含 y）→ 标记；/a ≡ /b（都含结构 x→y 与空文件夹 z）→ 标记。
      两层重复叠加，整棵树删空。
```

**示例 5**

```text
输入：paths = [["a"],["a","x"],["a","x","y"],["a","z"],["b"],["b","x"],["b","x","y"],["b","z"],["b","w"]]
输出：[["a"],["a","z"],["b"],["b","w"],["b","z"]]
解释：与示例 4 仅差一个 /b/w。/a/x ≡ /b/x 仍被标记删除；
      但 /a ≢ /b（b 多了 w）；/a/z 与 /b/z 是空文件夹，不判重，双双保留。
```

## 3. 解题思路

### 3.1 暴力思路：两两判同构 / 整树序列化

路径天然构成一棵多叉 **Trie**（父文件夹必在输入中 ⟹ 输入就是完整的树）。最直接的暴力是建树后**每一对结点**做递归结构比较：共 $O(N^2)$ 对、每对比较代价 $O(\text{子树大小})$，$N \le 2 \times 10^5$ 直接爆炸。

正确的方向是[652. 寻找重复的子树](https://leetcode.cn/problems/find-duplicate-subtrees/)的套路：**后序序列化每棵子树为一个签名，哈希表计数，出现 $\ge 2$ 次即重复**。但照搬到本题会栽在一个隐藏的坑上——

> ⚠️ **整树序列化的空间爆炸**：朴素签名（如 `x(y())z()`）把**全部后代的名字**都抄进父签名。树上每个结点都会被它的**所有祖先**各抄写一次，签名总长最坏达 $O(N \cdot D) \le 2 \times 10^5 \times 500 = 10^8$ 个字符——赛场上不少选手思路完全正确、写完直接 MLE/TLE，就卡在这一步。

### 3.2 核心观察：子树同构 + 结构 ID 压缩签名

![核心观察：相同文件夹即子树同构](images/wc251_q4_trie_isomorphism.svg)

**观察一：相同文件夹 = 子树同构。** 同一目录下子文件夹名字互异（题目保证无重复路径），所以「子文件夹集合相同且结构一致」就是「以二者为根的子树**同构**：孩子按名字一一配对，配对的孩子子树又同构」——一个自顶向下递归定义的结构等价关系。

**观察二：用「结构 ID」压缩签名。** 签名的职责只是**代表子树结构**，那就不必抄写全部后代——每个结点先领一个代表自身结构的整数 ID，父结点的签名只记录**排序后的 $(\text{子名},\ \text{子ID})$ 列表**：

$$\text{sig}(v) = \big[\,(\text{name}_c,\ \text{id}_c) \;\big|\; c \in \text{children}(v)\,\big]_{\text{按名排序}}$$

子 ID 一个整数就打包了整棵子子树的全部信息，于是**签名长度 = 孩子数**，与深度、子树大小彻底脱钩。ID 的来源是「首次出现」式分配：`sig → id` 哈希表中，新签名发新号、旧签名复用旧号——**sig 相同当且仅当 ID 相同**（分配机制的单射性），因此用 ID 参与父签名与用完整子签名参与，判重效果完全等价。

**观察三：叶子不判重。** 叶子的子文件夹集合为空，不满足「非空」条件，固定 $\text{id} = 0$ 且**永不计数**——但它仍以 $(\text{名字}, 0)$ 的身份参与父签名的构造（空结构之间当然同构）。

### 3.3 算法流程

![算法流程：建树、后序签名、分配结构 ID、剪枝输出](images/wc251_q4_struct_id_flow.svg)

1. **建 Trie**：逐条路径插入，共享前缀；结点数 $N \le 2 \times 10^5$，深度 $\le 500$。
2. **后序 DFS 求签名并分配 ID**：对孩子按名字排序（C++ `map` 天然有序），拼出 $\text{sig}(v)$；查 `sig→id` 表——新签名发新 ID，旧签名复用；然后 $\text{cnt}[\text{id}]{+}{+}$，并把 ID 记在该结点上。叶子直接记 $\text{id} = 0$、不计数。
3. **剪枝输出**：从 root 再走一遍，某结点 $\text{id} \ne 0$ 且 $\text{cnt}[\text{id}] \ge 2$ → 它和整棵子树都被删，**直接剪枝返回**（不收集、不递归）；否则收集当前路径（root 本身除外）并递归。

> 💡 **「只删一次」的落地**：第 2 步的全部计数都基于**原树**一次性完成，第 3 步只消费计数、不做任何二次判定——删除后新出现的相同（如示例 2 的 `/a` 与 `/c`）自然不会被误删。同时被删子树内部的结点也**参与了计数**：若 `/c/x` 与被删的 `/a/x` 同构，它同样是「相同文件夹」之一，也要删——这正是题意「基于原树标记」的正确语义。

### 3.4 示例演算

![示例 5 演算：签名、结构 ID 与计数](images/wc251_q4_example_walkthrough.svg)

以示例 5 演算（后序访问顺序）：

| 结点 | 签名 sig | 结构 ID | cnt | 判定 |
|------|----------|:---:|:---:|------|
| $y, z, w$（叶） | $\varnothing$ | 0 | 不计 | 空集合不判重 |
| `/a/x` | $(y,0)$ | 1 | 1 | |
| `/a` | $(x,1)(z,0)$ | 2 | 1 | |
| `/b/x` | $(y,0)$ | 1 | **2** | ✗ **重复，删除** |
| `/b` | $(w,0)(x,1)(z,0)$ | 3 | 1 | 与 `/a` 的签名不同 |
| root | $(a,2)(b,3)$ | 4 | 1 | |

- 只有 ID 1 计数达到 2：`/a/x` 与 `/b/x` 标记删除，连同各自的 `y`。
- `/a` 的签名 $(x,1)(z,0)$ 与 `/b` 的 $(w,0)(x,1)(z,0)$ 不同——差一个 `w`，不删。
- 空文件夹 `z`、`w` 是叶子（ID 0），永不判重，保留。

**输出**：`["a"] ["a","z"] ["b"] ["b","w"] ["b","z"]`，与官方答案一致。✓

## 4. 算法细节

1. **结点数上界**：每个 Trie 结点的名字至少 1 个字符，且名字由输入路径段「付费」（不同结点对应不同的（父， 名）对，同名也要各自出现在输入段中），故 $N \le \sum \text{paths[i][j].length} \le 2 \times 10^5$。
2. **签名构造的歧义检查**：C++ 拼接 `名字 + to_string(子ID) + ','`——名字全为小写字母、ID 全为数字、逗号作分隔，三段字符集互不相交，**任何两棵不同子树拼出的签名串必不相同的位置可被唯一回读**，无拼接歧义；Python 直接用 `tuple(sorted((名, 子ID)))` 作哈希键，元组结构天然无歧义。
3. **C++ 用 `map<string,int>` 存孩子**：红黑树按键有序，构造签名时**免显式排序**；Python 的 dict 无序，需 `sorted`（名字互异保证排序比较不会触及第二个元素）。
4. **`id = 0` 保留给空结构**：叶子统一记 0、不进 `cnt`；非叶结点从 1 开始编号。判重条件 `id != 0 && cnt[id] >= 2` 同时排除叶子和唯一结构。
5. **输出剪枝代替标记数组**：无需单独的 `mark` 布尔数组，输出 DFS 里现场判断 `cnt[nid[v]] >= 2` 即可；进入被标记结点立即 return，其子树整体不输出。
6. **路径回溯**：输出 DFS 维护 `path` 栈，进孩子 `push`、退出来 `pop`；收集时拷贝（`path[:]` / `push_back(path)`）。
7. **递归深度**：路径最长 500 段 ⟹ 树深 $\le 501$，Python 默认递归上限（1000）内安全，C++ 栈无压力。

## 5. 正确性证明

**性质 A（ID 与签名的一致性）**：算法结束后，任意两个已访问结点 $u, v$：$\text{id}(u) = \text{id}(v) \iff \text{sig}(u) = \text{sig}(v)$。

**证明**：`sig→id` 表中每个键唯一。若 $\text{sig}(u) = \text{sig}(v)$，二者查到同一表项，得同一 ID；反之若 $\text{id}(u) = \text{id}(v)$，则它们对应同一表项，而表项的键唯一，故 $\text{sig}(u) = \text{sig}(v)$。此性质纯粹来自分配机制，与同构概念无关。∎

**引理 1（题意翻译）**：文件夹 $F$ 与 $G$ 是相同文件夹 $\iff$ 子树 $T(F)$ 与 $T(G)$ 同构（存在孩子间双射 $\varphi$，保持名字且配对子树同构）。

**证明**：题面「包含非空且相同的子文件夹集合，并具有相同的子文件夹结构」逐字对应「孩子名字集合相同（非空）且按名字配对的孩子子树递归相同」。同一父文件夹下名字互异（无重复路径），故配对关系由名字唯一决定，构成双射。∎

**引理 2（签名的刻画）**：对任意结点 $u, v$：$\text{sig}(u) = \text{sig}(v) \iff T(u) \cong T(v)$。

**证明**：对子树高度归纳。高度 $0$（叶子）：sig 均为空序列且均无孩子，平凡成立。高度 $\ge 1$：

$$\text{sig}(u) = \text{sig}(v) \iff \text{排序后的 } (\text{名}, \text{ID}) \text{ 序列逐项相等} \iff \text{孩子名集合相同且按名配对孩子 ID 相同}$$

对最后一个「$\iff$」应用性质 A，配对孩子的签名相同；再由归纳假设（孩子高度更小），配对孩子子树同构。综上 $\text{sig}(u) = \text{sig}(v) \iff$ 孩子按名配对且配对子树同构 $\iff T(u) \cong T(v)$。∎

**引理 3（标记集合刻画）**：按题意应删除的文件夹集合恰为 $D = \bigcup \{\, T(v) \mid v \text{ 非叶且 } \text{cnt}[\text{id}(v)] \ge 2 \,\}$。

**证明**：$v$ 应被标记 $\iff$ 存在 $u \ne v$ 与 $v$ 相同（引理 1，且 $v$ 非叶）$\iff$ 存在 $u \ne v$ 使 $T(u) \cong T(v)$ $\iff$ 存在 $u \ne v$ 使 $\text{sig}(u) = \text{sig}(v)$（引理 2）$\iff \text{cnt}[\text{id}(v)] \ge 2$——因为 $\text{cnt}$ 恰好统计了原树中拥有同一签名的**非叶**结点数（叶子不计数，故空集合结构永不触发）。标记 $v$ 则 $T(v)$ 整体删除，故被删集合为这些 $T(v)$ 之并。∎

**定理（算法正确性）**：算法输出 = 全体文件夹 $\setminus D$，且符合「仅执行一次删除」的语义。

**证明**：输出 DFS 从 root 出发，进入满足引理 3 标记条件的结点即剪枝，其子树整体不输出；其余结点（含 path 非空的自身）全部被收集，故输出恰为全集减 $D$。所有 $\text{cnt}$ 在原树上一遍统计完成，输出阶段无二次判定，故删除后新出现的相同（示例 2 的 `/a` 与 `/c`）不会被删。∎

**推论（无哈希碰撞）**：结构 ID 法不使用任何哈希压缩——签名是 $(\text{名}, \text{ID})$ 的序列、ID 由签名经单射分配，因此**不存在哈希碰撞导致的误判**，严格优于多项式哈希签名（后者有极小概率碰撞，需双哈希兜底）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(S + N \log N)$，其中 $S = \sum \text{paths[i][j].length} \le 2 \times 10^5$。建树 $O(S)$；后序 DFS 中每个结点对孩子排序，合计 $O(\sum \deg \log \deg) \le O(N \log N)$；签名构造与查表合计 $O(N)$——每个结点对父签名恰好贡献一个 $(\text{名}, \text{ID})$ 项；输出 $O(\text{答案规模})$。
- **空间复杂度**：$O(S + N)$。Trie 名字字符 $O(S)$；`sig→id` 表与 `cnt` 数组 $O(\text{不同结构数}) \le O(N)$；每结点存自己的 ID，$O(N)$。
- **对照整树序列化**：签名总长从最坏 $O(N \cdot D) = 10^8$ 降到 $O(N)$——这正是结构 ID 法的本命优势。

## 7. 参考代码

### C++（map 存孩子，签名串 + 结构 ID）

```cpp
class Solution {
public:
    vector<vector<string>> deleteDuplicateFolder(vector<vector<string>>& paths) {
        int n = 1;                              // 0 号为虚拟根
        vector<map<string, int>> ch(1);
        for (auto& p : paths) {
            int cur = 0;
            for (auto& s : p) {
                auto it = ch[cur].find(s);
                if (it == ch[cur].end()) {
                    ch[cur].emplace(s, n);
                    ch.emplace_back();
                    cur = n++;
                } else {
                    cur = it->second;
                }
            }
        }

        unordered_map<string, int> sigToId;     // 签名 -> 结构 ID
        vector<int> cnt(1, 0);                  // cnt[0] 恒为 0：空结构不判重
        vector<int> nid(n, 0);                  // 每个结点的结构 ID

        function<int(int)> dfs1 = [&](int v) -> int {
            if (ch[v].empty()) return 0;        // 叶子：固定 ID 0，不计数
            string sig;
            for (auto& [name, c] : ch[v]) {     // map 已按名字排序
                dfs1(c);
                sig += name;                    // 名字：小写字母
                sig += to_string(nid[c]);       // 子 ID：数字
                sig += ',';                     // 分隔符：字符集互不相交
            }
            auto [it, ok] = sigToId.emplace(sig, (int)cnt.size());
            if (ok) cnt.push_back(0);
            nid[v] = it->second;
            cnt[it->second]++;
            return nid[v];
        };
        dfs1(0);

        vector<vector<string>> ans;
        vector<string> path;
        function<void(int)> dfs2 = [&](int v) {
            if (nid[v] != 0 && cnt[nid[v]] >= 2) return;   // 整棵子树剪枝
            if (!path.empty()) ans.push_back(path);
            for (auto& [name, c] : ch[v]) {
                path.push_back(name);
                dfs2(c);
                path.pop_back();
            }
        };
        dfs2(0);
        return ans;
    }
};
```

### Python（嵌套 dict，元组签名 + 结构 ID）

```python
class Solution:
    def deleteDuplicateFolder(self, paths: List[List[str]]) -> List[List[str]]:
        root = {}
        for p in paths:
            d = root
            for name in p:
                d = d.setdefault(name, {})

        sig_id = {}                 # 签名 -> 结构 ID（0 保留给空结构）
        cnt = defaultdict(int)
        nid = {}                    # 结点对象 -> 结构 ID

        def dfs1(d):
            if not d:
                nid[id(d)] = 0      # 叶子：固定 ID 0，不计数
                return 0
            sig = tuple(sorted((name, dfs1(c)) for name, c in d.items()))
            i = sig_id.setdefault(sig, len(sig_id) + 1)
            cnt[i] += 1
            nid[id(d)] = i
            return i

        dfs1(root)

        ans, path = [], []

        def dfs2(d):
            i = nid[id(d)]
            if i != 0 and cnt[i] >= 2:      # 整棵子树剪枝
                return
            if path:
                ans.append(path[:])
            for name, c in d.items():
                path.append(name)
                dfs2(c)
                path.pop()

        dfs2(root)
        return ans
```

> 💡 **两个实现细节**：① `setdefault(sig, len(sig_id) + 1)` 的默认值参数**先于插入求值**，`len(sig_id) + 1` 恰为新 ID（从 1 起编号）；② Python 用 `id(d)`（对象身份）做 `nid` 的键——Trie 结点在算法全程被 root 引用持有，身份稳定安全。

## 8. 边界情况与易错点

1. **叶子不判重（示例 5 考点）**：`/a/z` 与 `/b/z` 都是空文件夹，不算相同。实现上叶子固定 `id = 0` 且**不进 cnt**；若把空签名也计数，所有叶子会共享同一「重复结构」而被全删——典型 WA。
2. **删除只执行一次（示例 2 考点）**：删完 `/a/b/x` 与 `/w` 后 `/a` 与 `/c` 变得相同，但不再删。所有计数必须**基于原树**一遍完成，输出阶段绝不二次标记。
3. **整树序列化会 MLE**：朴素签名把后代名字层层上抄，总长最坏 $O(N \cdot D) = 10^8$；必须用结构 ID 让签名长度 $= O(\text{孩子数})$。
4. **签名拼接歧义**：名字（字母）与 ID（数字）直接相连时靠字符集区分才安全；若题目放宽名字含数字，必须加显式分隔符（如括号或逗号）。
5. **重复是「全删」不是「留一份」**：与 652 题（保留一个副本）语义相反，别把 652 的代码直接搬来改个返回值。
6. **被删子树内的结点也参与计数**：判定基于原树——若 `/c/x` 与被删的 `/a/x`、`/b/x` 同构（cnt = 3），`/c/x` 同样要删。
7. **root 是虚拟结点**：不对应任何文件夹、不输出；path 为空时跳过收集。
8. **Python 的 `nid` 要覆盖叶子**：若只在非叶分支写 `nid`，输出阶段查叶子会 `KeyError`（或漏判）；用 `nid.get(id(d), 0)` 可兜底但显式记录更清晰。
9. **回溯别忘 `pop`**：输出 DFS 的 path 栈进出要配对；收集时必须拷贝（`path[:]`）。
10. **递归深度**：树深 $\le 501$，Python 默认上限够用；若数据约束放宽（如路径长 $10^4$），需 `sys.setrecursionlimit` 或改显式栈。

- **哈希进一步压缩**：把 $(\text{名}, \text{ID})$ 序列换成多项式滚动哈希，比较与存储都降到 $O(1)$ 每结点，但引入碰撞风险——竞赛中可用双哈希，工程中（如文件系统去重）可借鉴 Merkle 树校验。
