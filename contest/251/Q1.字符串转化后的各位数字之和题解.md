# LeetCode 字符串转化后的各位数字之和 题解

## 1. 题目概述

- **标题 / 题号**：字符串转化后的各位数字之和（#1945，easy）
- **链接**：https://leetcode.cn/problems/sum-of-digits-of-string-after-convert/
- **来源**：LeetCode 第 251 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟、数学

**题意**：给定小写字母串 $s$ 与整数 $k$，先做一次**转化**——把每个字母替换为字母表位置（`'a'`→1, …, `'z'`→26）并**拼接**成一个整数 $N$；再做 $k$ 次**转换**——每次把当前整数换成其**各位数字之和**。返回第 $k$ 次转换后的结果。

**约束**：

- $1 \le s.length \le 100$
- $1 \le k \le 10$
- $s$ 由小写英文字母组成

> 💡 本题在本仓库另有[每日题解 1945](../../solution/1901-2000/1945_字符串转化后的各位数字之和.md)，两篇为姊妹篇：那边侧重审题三关键、与 258 数字根的模 9 关联、三种写法对照与面试问答。本篇按周赛复盘视角，聚焦**签到题从题面到代码的最短路径**——「数位和对拼接的加法性 ⟹ 第一轮逐字母累加即可跳过大整数」的一步观察、C++ 选手 200 位拼接串撞上 `long long` 的溢出陷阱复盘，以及加法性的引理-定理化证明。两篇互为印证。

## 3. 解题思路

### 3.1 赛场直觉：构造大数 + 循环数位和（暴力）

最直觉的写法是严格照题面模拟：先把每个字母转成数值字符串拼接得到 $N$，再循环 $k$ 次数位求和。

- **Python**：`int` 任意精度，`int(''.join(str(ord(c)-96) for c in s))` 一行构造大数，循环 $k$ 次 `sum(int(d) for d in str(num))`，直接 AC——这是 Python 选手的零风险保底。
- **C++ 的致命陷阱**：$n = 100$ 时每个字母对应 1~2 位，拼接串长达 **200 位**，而 `long long` 只装得下约 **19 位** 十进制数。`stoi` / `stoll` 转换 200 位串会直接抛 `out_of_range`——照抄题面模拟的 C++ 代码连样例 2（11 位）都过不了 `long long` 虽能过，$n$ 一大必挂。C++ 若走暴力，必须**全程以 `string` 存数字位、逐字符 `'d'-'0'` 求和**，永远不转整型。

暴力法没有利用题目最关键的结构：**题目根本不关心大数 $N$ 本身，只关心它的数位和**——而数位和恰恰是可以「分段算再相加」的。

### 3.2 核心观察：数位和对拼接的加法性

![核心观察：数位和对拼接的加法性](images/wc251_q1_additivity_concept.svg)

关键洞察：**数位和对拼接具有加法性**。把若干数字串拼在一起再整体求数位和，等于各串分别求数位和再相加：

$$\text{digit\_sum}(A \frown B) = \text{digit\_sum}(A) + \text{digit\_sum}(B)$$

原因很朴素：数位和只是把**所有数字位**加起来，与每位所处的位置（位权）无关——拼接只是把更多数字位排成一列，逐位求和的结果自然等于各段数位和之和。

**推论**：第 1 次转换的结果 $R_1 = \text{digit\_sum}(N)$ 可以逐字母直接累加，**完全跳过大整数的构造**：

$$\boxed{R_1 = \sum_{c \in s} \text{digit\_sum}\big(\text{val}(c)\big), \quad \text{val}(c) = c - \texttt{'a'} + 1 \in [1, 26]}$$

每个字母的数值 $v \in [1, 26]$，其数位和就是 $v/10 + v\%10$（如 $26 \to 2+6 = 8$，$5 \to 0+5 = 5$），一趟扫描算出 $R_1$。

**规模上界**：$n \le 100$、每字母数位和 $\le 10$（最大是 `'s'`=19 → $1+9=10$），故

$$R_1 \le 100 \times 10 = 1000$$

$R_1$ 至多 4 位数；此后 $R_2 \le \text{digit\_sum}(999) = 27$、$R_3 \le 10$、$R_4$ 起必为一位数——后续 $k-1$ 轮全是小整数运算，每轮 $O(1)$，`int` 绰绰有余。

### 3.3 算法流程

![算法流程：一趟累加 + k−1 轮数位和](images/wc251_q1_algorithm_flow.svg)

整体是「一趟累加 + $k-1$ 轮数位和」的线性流程：

1. **求 $R_1$**：`R = 0`；遍历 $s$，对每个字符 $c$ 取 $v = c - \texttt{'a'} + 1$，执行 `R += v/10 + v%10`。这一趟同时完成了「转化」与「第 1 次转换」。
2. **循环 $k-1$ 次**：对 `R` 做一次数位求和（`t += R%10; R /= 10`，结束令 `R = t`）。
3. **返回 `R`**。

> 💡 **循环次数是 $k-1$ 不是 $k$**：第 1 步的累加本身就是第 1 次转换的结果，别在循环里多做一轮。$k = 1$ 时循环零次，直接返回 $R_1$——这正是示例 1（`"iiii"` 返回 36 而不是 9）的考点。

### 3.4 示例演算

![示例演算：leetcode k=2 逐字母累加与两轮转换](images/wc251_q1_example_walkthrough.svg)

以 $s = \text{"leetcode"},\ k = 2$ 演示：

**第 1 趟累加得 $R_1$**：

| 字母 | l | e | e | t | c | o | d | e |
|------|---|---|---|---|---|---|---|---|
| 数值 $v$ | 12 | 5 | 5 | 20 | 3 | 15 | 4 | 5 |
| 数位和 | 3 | 5 | 5 | 2 | 3 | 6 | 4 | 5 |

$$R_1 = 3+5+5+2+3+6+4+5 = 33$$

**第 2 轮数位和**（$k=2$，再做 1 次）：

$$R_2 = \text{digit\_sum}(33) = 3 + 3 = 6$$

> 💡 **对照暴力路径**："leetcode" → 拼接 "12552031545" → 数位和 33 → 数位和 6。两条路径结果一致，但加法性路径全程未构造 11 位大数，$R$ 最大只到 33。

## 4. 算法细节

1. **$v/10 + v\%10$ 即 $[1,26]$ 内数值的数位和**：$v < 10$ 时十位为 0，表达式退化为 $v$ 本身，无需分类讨论。
2. **第一趟 = 转化 + 第 1 次转换**：逐字母累加 $\text{digit\_sum}(\text{val}(c))$ 同时完成两步，循环只做 $k-1$ 轮——「先合并哪几步」是签到题提速的典型思考点。
3. **内层数位和用取余逐位**：`for (; R; R /= 10) t += R % 10;` 处理至多 4 位数（$R \le 1000$），常数极小；Python 直接 `sum(int(d) for d in str(R))`。
4. **$R_1 \le 1000$ 的推导链**：$n \le 100$ × 每字母数位和 $\le 10$（'s'=19 最大）$= 1000$；随后每轮至少缩到 $\text{digit\_sum}(999) = 27$，再一轮 $\le 10$。全程 `int` 安全，这也是 C++ 能绕开大数库的原因。
5. **字符映射**：C++ 写 `c - 'a' + 1`；Python `ord(c) - 96` 与 `ord(c) - ord('a') + 1` 等价（`ord('a')` = 97），前者紧凑后者可读。

## 5. 正确性证明

**引理 1（数位和的加法性）**：设 $A$、$B$ 是两个十进制正整数的数字串，$A \frown B$ 表示拼接，则 $\text{digit\_sum}(A \frown B) = \text{digit\_sum}(A) + \text{digit\_sum}(B)$。

**证明**：数字串 $X$ 的数位和 $\text{digit\_sum}(X) = \sum_i x_i$，其中 $x_i$ 逐一枚举 $X$ 的每一位数字，与位权 $10^i$ 无关。拼接 $A \frown B$ 得到的串，其数字位多重集合恰为 $A$ 的数字位与 $B$ 的数字位之**不交并**，故逐位求和可拆成两段各自求和再相加。∎

**引理 2（映射与拆分）**：$\text{val}(c) = c - \texttt{'a'} + 1 \in [1, 26]$；对 $v \in [1, 26]$，$\text{digit\_sum}(v) = \lfloor v/10 \rfloor + (v \bmod 10)$。

**证明**：小写字母编码连续，`'a'` 为 97，故 `val` 是字母到 $[1,26]$ 的双射。$v \le 26 < 100$ 是两位以内十进制数，十位为 $\lfloor v/10 \rfloor$、个位为 $v \bmod 10$，两者之和即数位和。∎

**定理（算法正确性）**：设 $N$ 为按题意转化得到的大整数，$R_i$ 为第 $i$ 次转换后的结果，则算法返回 $R_k$。

**证明**：先证第一趟累加得到 $R_1$。转化串 $N$ 的数字串是各字母数值串按 $s$ 的顺序拼接：$N = \text{val}(c_1) \frown \text{val}(c_2) \frown \cdots \frown \text{val}(c_n)$。对 $n$ 归纳、反复应用引理 1，得

$$\text{digit\_sum}(N) = \sum_{j=1}^{n} \text{digit\_sum}(\text{val}(c_j)) = \sum_{c \in s} \big(\lfloor \text{val}(c)/10 \rfloor + (\text{val}(c) \bmod 10)\big),$$

后者正是算法第一趟的累加式（引理 2），故循环开始前 `R` $= R_1$。随后第 $i$ 轮循环（$i = 1, \dots, k-1$）把 `R` 替换为其数位和，恰为 $R_{i+1}$ 的定义；归纳得循环结束时 `R` $= R_k$，算法返回之。∎

**推论（值域）**：$R_1 \le 100 \times 10 = 1000$（每字母 $\text{digit\_sum} \le 10$），且 $R_i$ 随 $i$ 严格不增于数位和轨道上，全程 `int` 无溢出。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k)$。第一趟遍历 $s$ 为 $O(n)$；后续 $k - 1$ 轮每轮处理至多 4 位数（$R \le 1000$），每轮 $O(\log R) = O(1)$，合计 $O(k)$，$k \le 10$ 时几乎可忽略。对照暴力法 $O(n + kL)$（$L$ 为拼接串长度，初始达 $2n$）：渐近同阶但常数更小，且不依赖大数运算。
- **空间复杂度**：$O(1)$。仅常数个整型变量；对照暴力法需 $O(n)$ 存储拼接串（Python 大数还要额外开销）。

## 7. 参考代码

### C++（逐字母数位和 + $k-1$ 轮循环）

```cpp
class Solution {
public:
    int getLucky(string s, int k) {
        int R = 0;
        for (char c : s) {
            int v = c - 'a' + 1;
            R += v / 10 + v % 10;
        }
        for (int i = 1; i < k; ++i) {
            int t = 0;
            for (; R; R /= 10) t += R % 10;
            R = t;
        }
        return R;
    }
};
```

### C++（字符串暴力保底：全程不转整型）

```cpp
class Solution {
public:
    int getLucky(string s, int k) {
        string t;
        for (char c : s) t += to_string(c - 'a' + 1);
        while (k--) {
            int sum = 0;
            for (char d : t) sum += d - '0';
            t = to_string(sum);
        }
        return stoi(t);
    }
};
```

### Python（逐字母数位和 + $k-1$ 轮循环）

```python
class Solution:
    def getLucky(self, s: str, k: int) -> int:
        R = 0
        for c in s:
            v = ord(c) - ord('a') + 1
            R += v // 10 + v % 10
        for _ in range(k - 1):
            R = sum(int(d) for d in str(R))
        return R
```

### Python（赛场保底：任意精度一行构造）

```python
class Solution:
    def getLucky(self, s: str, k: int) -> int:
        num = int(''.join(str(ord(c) - 96) for c in s))
        for _ in range(k):
            num = sum(int(d) for d in str(num))
        return num
```

> 💡 **写法对照**：① 加法性版直接翻译核心观察，$O(n + k)$、$O(1)$ 空间，不依赖语言大数支持，C++/Python 通吃，是值得沉淀的写法；② C++ 字符串暴力版是「照题面模拟」的修正形态——拼接串全程以 `string` 存放、逐字符求数位和，`stoi` 只在循环结束后对至多 4 位的结果调用，安全；③ Python 一行流利用任意精度 `int`，最短但构造了不必要的大数对象。三者对本题数据规模都是瞬时，差距要到字符集/规模扩大时才显现。

## 8. 边界情况与易错点

1. **C++ 拼接串溢出（本题最经典 WA）**：$n = 100$ 时拼接串可达 200 位，`stoi`/`stoll` 直接抛 `out_of_range`。要么走加法性版（根本不构造大数），要么全程 `string` 逐字符求和。
2. **循环次数 $k$ vs $k-1$**：第一趟累加已含第 1 次转换，写成 `for _ in range(k)` 会多做一轮——`"iiii", k=1` 会被错算成 $\text{digit\_sum}(36) = 9$ 而非 36。反之，字符串暴力版第一趟只做转化，循环就得老老实实做 $k$ 轮：**两个版本的循环次数不同，别混用**。
3. **$k = 1$ 直接返回 $R_1$**：循环零次；测试时专门用示例 1 验证这一边界。
4. **单字母串**：`s = "a"` 返回 1；`s = "z"` 的 $R_1 = 8$（$2+6$），别顺手写成 26。
5. **别当数字根做**：题目是固定 $k$ 次，不是「求到一位为止」——`"iiii", k=1` 答案是 36 不是 9。套 $1 + (n-1) \% 9$ 公式仅在 $k \ge 4$（结果已收敛到一位）时才碰巧等价。
6. **$R_1$ 的上界意识**：$100 \times 10 = 1000$，`int` 即可；放宽约束（如 $n \le 10^5$）时 $R_1 \le 10^6$ 仍安全，但值得养成「先估上界再选类型」的习惯。
7. **Python `-96` 与 `-'a'+1` 等价**：`ord('a')` = 97，两种写法都对，混用无碍但全文保持一致更可读。
