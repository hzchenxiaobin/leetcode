# LeetCode 千位分隔数 题解

## 1. 题目概述

- **标题 / 题号**：千位分隔数（#1556，easy）
- **链接**：https://leetcode.cn/problems/thousand-separator/
- **来源**：LeetCode 第 33 场双周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定整数 $n$，把它转成十进制字符串，并**从右往左每三位插入一个点 `.` 作为千位分隔符**，返回结果。最左边的一组可以不足三位，但不允许出现前导点或尾随点。

**约束**：

- $0 \le n < 2^{31}$，十进制表示最多 10 位（如 $2147483647$）。
- $n$ 非负，因此无需考虑负号的处理。

## 2. 示例

**示例 1**

```text
输入：n = 987
输出："987"
解释：一共只有 3 位，不足一组千位分隔，原样返回。
```

**示例 2**

```text
输入：n = 1234
输出："1.234"
解释：从右往左第一组是 "234"，剩下 "1" 作为最左组，组间插点。
```

**示例 3**

```text
输入：n = 123456789
输出："123.456.789"
解释：9 位恰好分成 3 组，每组 3 位，两个点分别插在第 3、6 位数字之前。
```

**示例 4（边界）**

```text
输入：n = 0
输出："0"
解释：单字符 "0"，无点。
```

## 3. 解题思路

### 3.1 暴力思路：从左往右逐位插点

从左往右处理时，第一组的长度取决于总位数 $d$ 对 3 的余数（$d \bmod 3$），后面每组固定 3 位。这个「首组特殊」的写法容易在余数为 0 时误判首组长度，也容易把点插错位置，属于典型的 off-by-one 重灾区。既然分隔符的定义本身就是「从右往左数」，那么顺着定义、**从右往左**处理就能让每一组都等价——没有特例。

### 3.2 核心观察：从右往左每 3 位一组，只有最左一组是「余数」

![从右往左每三位分组插入点号](images/bw33_q1_group_from_right.svg)

设 $s$ 是 $n$ 的十进制串，$d = |s|$。从右端起每 3 位划为一组：$s$ 的后 3 位、再前 3 位……最左一组长度为 $1 \sim 3$（它就是 $d \bmod 3$ 对应的余数，余 0 时恰好 3 位）。**点只插在相邻两组之间**，因此：

- 点的个数恰为 $\left\lfloor \frac{d-1}{3} \right\rfloor$；
- 从右往左数的第 $k$ 个点，插在倒数第 $3k$ 位数字的前面（要求 $3k < d$）。

换句话说，只要在**下标 $i = d-3,\ d-6,\ \dots$（所有 $> 0$ 者）处插入点**即可——下标从左数从 0 开始，$i$ 是「从右数第 $3, 6, 9$ 位」的左邻居位置。

### 3.3 算法流程

```text
1. s = to_string(n)
2. for i = d-3; i > 0; i -= 3:      # d-3 是从右数第 3 位数字的下标
       在 s[i] 之前插入 "."
3. 返回 s
```

### 3.4 示例演算

![123456789 的插点演算过程](images/bw33_q1_walkthrough.svg)

以 $n = 123456789$（$d = 9$）为例：第一轮 $i = 6$，在下标 6（字符 `7`）前插点得 `123456.789`；第二轮 $i = 3$，在字符 `4` 前插点得 `123.456.789`；$i = 0$ 时循环终止（下标 0 之前不允许有点）。$d = 3$ 时初始 $i = 0$，循环直接不执行，返回原串——这正是「不足 4 位无分隔符」的统一处理。

## 4. 算法细节

1. **插入方向**：循环变量从 $d - 3$ 开始、每次减 3，**从小下标到大下标依次插入也可以**（先插 $i = 3$ 再插 $i = 6$ 时，插后面的点不会影响前面点的相对位置），但从右往左插入（先大 $i$ 后小 $i$）更贴合「从右往左分组」的直觉，两种顺序都正确。
2. **C++ 的 `string::insert`**：`s.insert(i, ".")` 表示在下标 $i$ 前插入，每次调用是 $O(d)$ 的移动，总代价 $O(d^2)$；由于 $d \le 10$，完全可以忽略。若追求 $O(d)$，可以倒序拼接（见 Python 版：从右往左切出长度为 3 的段，最后 `join`）。
3. **Python 的切片分组**：`s[-3:]` 取末 3 位、`s = s[:-3]` 去掉末 3 位，循环到剩余长度 $\le 3$ 为止，把每段压栈再反转 `join`，天然避免任何下标运算。
4. **不用 `printf` 系千分位格式**：标准 C 的 `printf` 没有跨平台的千分位标志（`%'d` 是 glibc 扩展），自己插点最稳。

## 5. 正确性证明

**引理 1（合法性刻画）**：字符串 $t$ 是 $n$ 的合法千位分隔表示，当且仅当去掉所有点后 $t$ 等于 $n$ 的十进制表示 $s$，且 $t$ 满足：最右一段恰 3 位，其余每段恰 3 位、段数不限，最左一段 $1 \sim 3$ 位且不含点。

**证明**：由题意，点只能把数字串切成若干段，段从右往左编号 $1, 2, \dots$；千位分隔符的定义即「第 $k \ge 2$ 段与第 $k+1$ 段之间有点」，等价于每相邻两段间都插点。去掉点恢复 $s$ 说明数字未变；每段长度恰 3（除最左段）即定义本身。∎

**定理**：算法输出为 $n$ 的合法千位分隔表示，且合法表示唯一。

**证明**：设 $d = |s|$。算法插入点的位置集合为 $P = \{d-3, d-6, \dots\} \cap [1, d-1]$，即从右数第 $3, 6, \dots$ 位（小于 $d$ 者）之前。按引理 1，合法表示要求从右往左每 3 位一段、段间插点：第 $j$ 段（$j \ge 2$）与第 $j-1$ 段的分界恰在「从右数第 $3(j-1)$ 位」之前，即下标 $d - 3(j-1)$，与 $P$ 完全一致；而 $3(j-1) < d$ 的限制对应 $P$ 中只取 $\ge 1$ 的下标，保证最左一段非空且不以点开头。故算法输出合法。唯一性：$P$ 被定义唯一确定，没有自由度。∎

## 6. 复杂度分析

- **时间**：$O(d)$，$d \le 10$ 为数字位数。C++ 版逐次 `insert` 最坏 $O(d^2)$ 次字符移动，量级仍为常数；Python 版一次线性扫描加 `join`，$O(d)$。
- **空间**：$O(d)$，存放结果字符串（不计输出则 $O(1)$ 额外）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string thousandSeparator(int n) {
        string s = to_string(n);
        for (int i = (int)s.size() - 3; i > 0; i -= 3)
            s.insert(i, ".");
        return s;
    }
};
```

### Python

```python
class Solution:
    def thousandSeparator(self, n: int) -> str:
        s = str(n)
        parts = []
        while len(s) > 3:              # 从右往左切出长度 3 的段
            parts.append(s[-3:])
            s = s[:-3]
        parts.append(s)                # 最左一段（1~3 位）
        return ".".join(reversed(parts))
```

> 💡 两份代码均通过官方示例（`"987"`、`"1.234"`）及 $n = 123456789$、$n = 0$、$n = 2^{31}-1$ 等边界（输出 `"2.147.483.647"`），C++ 与 Python 结果一致。

## 8. 边界情况与易错点

1. **$n = 0$**：输出 `"0"`，`d - 3 = -2 < 1`，循环不执行，无需特判。
2. **恰好 3 位**（$987$）：`i = 0` 不进循环，无点。若循环条件写成 `i >= 0` 会在开头插出 `".987"`。
3. **10 位上界**：$n < 2^{31}$ 最多 10 位，最多 3 个点；`int` 无溢出风险（只做字符串操作）。
4. **从左往右的余数陷阱**：若坚持从左往右，首段长度应为 $d \bmod 3$（为 0 时取 3），漏判会把 `1234` 变成 `123.4`——从右往左处理可彻底规避。
5. **不要用 `%'d` 等 printf 扩展**：不可移植，评测环境未必支持。
