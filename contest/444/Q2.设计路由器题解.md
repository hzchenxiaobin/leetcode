# LeetCode 设计路由器 题解

## 1. 题目概述

- **标题 / 题号**：设计路由器（#3508，medium）
- **链接**：https://leetcode.cn/problems/implement-router/
- **来源**：LeetCode 第 444 场周赛 Q2
- **难度**：中等
- **标签**：设计、哈希表、队列、二分查找

**题意**：设计一个固定内存上限的路由器 `Router`，管理三元组数据包 `(source, destination, timestamp)`，支持四个操作：

- `Router(memoryLimit)`：初始化，任意时刻最多存 `memoryLimit` 个包；
- `addPacket(s, d, t)`：入队新包。若**当前存储中**已有完全相同的三元组，返回 `false`（重复包，不入队）；否则若入队会超容量，先移除**最旧**的包再入队，返回 `true`；
- `forwardPacket()`：按 **FIFO** 转发队头包（移除并返回 `[s, d, t]`），无包可转时返回空数组；
- `getCount(d, startTime, endTime)`：统计**当前存储中**目的地为 `d` 且时间戳落在闭区间 $[\text{startTime}, \text{endTime}]$ 内的包数。

**约束**：

- $2 \le \text{memoryLimit} \le 10^5$
- $1 \le \text{source},\ \text{destination} \le 2 \times 10^5$，$1 \le \text{timestamp} \le 10^9$
- $1 \le \text{startTime} \le \text{endTime} \le 10^9$
- 三个方法总调用次数 $\le 10^5$，且 `addPacket` 的调用按 `timestamp` **非递减**给出

> 💡 **读题关键**：三个操作各需要一样「专用器件」——FIFO 转发与容量淘汰、三元组查重、按 dest 的区间计数。而题面最后一行「timestamp 非递减」是白送的单调性：它直接决定 `getCount` 能不能免排序二分。设计题的第一步永远是「给每个操作找到刚好够用的数据结构」，而不是维护一个全能大容器后每次全量扫描。

## 2. 示例

**示例 1**（官方）

```text
输入：
["Router", "addPacket", "addPacket", "addPacket", "addPacket", "addPacket", "forwardPacket", "addPacket", "getCount"]
[[3], [1, 4, 90], [2, 5, 90], [1, 4, 90], [3, 5, 95], [4, 5, 105], [], [5, 2, 110], [5, 100, 110]]

输出：[null, true, true, false, true, true, [2, 5, 90], true, 1]

解释：
Router(3)                 // 内存限制 3
addPacket(1,4,90)         // true，入库
addPacket(2,5,90)         // true，入库
addPacket(1,4,90)         // false：与在存包重复，不触发淘汰
addPacket(3,5,95)         // true，已存满 3 个
addPacket(4,5,105)        // true：满员 → 最旧的 (1,4,90) 被淘汰，再插入
forwardPacket()           // [2,5,90]：FIFO 弹队首并三本账销账
addPacket(5,2,110)        // true，入库
getCount(5,100,110)       // 1：桶 5 有效区间 [95,105]，与 [100,110] 相交仅 105
```

## 3. 解题思路

### 3.1 暴力思路

用一个数组从头到尾存所有包，每个操作直接扫全表：`addPacket` 线性查三元组重复 $O(L)$，`getCount` 全表扫描逐个判断 $O(L)$。总调用次数 $Q \le 10^5$、队列长度 $L \le 10^5$，最坏 $Q \cdot L \approx 10^{10}$——必然超时。**病根**：三个操作各自为政地用全量扫描换信息，而「查重、FIFO、区间计数」各有一个 $O(1)$ / $O(\log n)$ 的专用结构。

### 3.2 核心观察：一个包三本账，非递减时间戳送来有序桶

![三本账数据结构](images/c444_q2_ds_concept.svg)

维护三套结构，一次入队三处同步写、一次出队三处同步销：

| 账本 | 存什么 | 服侍谁 |
|------|--------|--------|
| 双端队列 `q` | 三元组包序列（队头 = 最旧） | `forwardPacket`（队头出）与容量淘汰（也是队头出），`addPacket` 队尾进 |
| 查重集合 `seen` | 当前在存包的 $(s, d, t)$ | `addPacket` 判重，$O(1)$ / $O(\log n)$ |
| 时间戳桶 `ts[dest]` | 每个目的地一条**有序**时间戳序列 | `getCount` 二分计数，$O(\log n)$ |

真正的题眼是两条**题设性质**，它们把所有维护成本降到零：

1. **时间戳非递减** → 新包追加到 `ts[d]` 尾部时必然不小于队尾 → 每条序列**追加即有序**，全程不需要一次主动排序；
2. **删除只发生在全局队头** → 队头是全体中最早入队的包；对它的目的地 $d$ 而言，它也是 $d$ 的所有包中最早入队的 → 被删的**一定是 `ts[d]` 的头部** → 每条桶退化成「队尾进、队头出」的队列，头删 $O(1)$。

> 💡 于是「有序」与「可头删」都是免费的：C++ 的 `unordered_map<int, deque<int>>` 里 `std::deque` 头删 $O(1)$、随机访问 $O(1)$，二分直接可用；Python 的 `collections.deque` 随机访问是 $O(n)$，`bisect` 会退化，要用 `list` + `head` 惰性指针（见 §4 与参考代码）。

### 3.3 算法流程：先查重、后淘汰、再登记

![addPacket 流程与另两个操作](images/c444_q2_addpacket_flow.svg)

`addPacket` 是唯一有决策分支的操作，三步顺序固定为「查重 → 淘汰 → 登记」，其中两个顺序极易写反：

1. **为什么先查重再淘汰？** 设想队列已满且队头恰是 `(1,4,90)`，此时又来一个 `(1,4,90)`：它**在存**，语义是重复包，应返回 `false` 且**不发生淘汰**。若先淘汰再查重，会把在存的旧包踢掉再放行新包，返回 `true`——两个答案都错。
2. **查重集合何时销账？** 与出队**严格同步**。查重的语义是「当前存储中」：漏销会把已转发/已淘汰的包误判为重复（`addPacket` 错误返回 `false`）。

`forwardPacket` 与容量淘汰删的是**同一个位置**（全局队头 = 最旧），共用一个出队销账函数 `retire()` 即可；`getCount` 则完全无脑：取桶 `d` 的有效区间，`upper_bound(en) − lower_bound(st)`。

### 3.4 示例演算

![示例 1 九步走查](images/c444_q2_example_walkthrough.svg)

对官方示例 1 的九步操作逐步走查（见上图）：第 ④ 步重复包直接 `false`、不动队列；第 ⑥ 步满员插入 = 先销 `(1,4,90)` 的三本账、再登记 `(4,5,105)`；第 ⑨ 步 `getCount(5,100,110)` 时桶 5 的有效区间是 `[95, 105]`——其中 `90` 已随 `forward` 销账，`95` 落在区间左侧外，二分只命中 `105`，返回 1。

## 4. 算法细节

1. **查重集合**：Python 直接用元组的 `set`，$O(1)$；C++ 用 `set<array<int,3>>`，单次 $O(\log n)$，$10^5$ 次调用毫无压力。**不要**尝试把三元组打包进一个 64 位整数——$18 + 18 + 30 = 66$ bit 放不下，宁可换 `unordered_set` + 自定义哈希。
2. **出队销账 `retire()`**：转发与容量淘汰共用。队头出队后，同步 `seen.erase` 与桶头删（Python 是 `head[d] += 1` 惰性删除，不搬移元素）。
3. **桶的删除必是桶首**（见 §5 引理 2），所以桶只需要支持「队尾追加 + 队头弹出」，$O(1)$。
4. **`getCount` 二分**：桶允许重复时间戳（同 dest 同 timestamp 不同 source 合法），序列**非降**而非严格升；`lower_bound`/`upper_bound` 对闭区间 $[\text{st}, \text{en}]$ 的计数恰好正确。
5. **Python 的桶不能是 `deque`**：`bisect` 需要随机访问，`collections.deque` 的索引是 $O(n)$，二分整体退化为 $O(n)$，最坏 $10^5 \times 10^5$ 直接超时。正解是 `list` 只追加 + `head` 字典记每个桶的有效起点，二分时把 `head` 作为 `lo` 参数传入。
6. **不存在的 dest**：`defaultdict` / `operator[]` 访问不存在的键自动建空桶，`ub = lb = begin`，差值为 0，天然返回正确答案，无需特判。

## 5. 正确性证明

**引理 1（桶内非降）**：任意时刻，每个 dest 的桶中有效时间戳序列非降。

**证明**：对操作序列归纳。初始为空，平凡成立。设某时刻成立，考察下一次状态变化：若是追加，题设保证新包 `timestamp` 非递减于此前一切 `addPacket`，故不小于该桶中所有在存时间戳，追加到尾部后仍非降；若是销账，只删首元素，剩余序列是原序列的后缀，仍非降。∎

**引理 2（删除必是桶首）**：容量淘汰与 `forwardPacket` 移除的包，恰为其 dest 桶中的首个有效元素。

**证明**：两种删除都移除全局队列的队头，即当前在存包中**最早入队**者。对固定 dest $d$，桶中元素按入队先后排列（只从尾部追加），故全局最早入队的 $d$ 包就是桶中最先入队的，即桶首。归纳可知：任意时刻，桶 $d$ 的有效元素集合恰等于该 dest 当前在存包的时间戳多重集。∎

**定理**：三个操作均返回正确结果。

**证明**：
`addPacket`：由引理 2，`seen` 与队列严格同步，三元组查询等价于「当前存储中是否已有同键包」；查重在淘汰之前执行，重复时直接返回 `false` 且队列不变，与题面「重复包不触发淘汰」一致；非重复且满员时先移除最旧（全局队头）再入队，容量恒为 $\min(\text{历史包数}, \text{limit})$，不超限。
`forwardPacket`：队列即入队序，队头即最旧，FIFO 语义显然；空队列返回空数组。
`getCount`：由引理 2，桶 $d$ 的有效区间恰是该 dest 在存包的时间戳全体；由引理 1 其非降，故 `upper_bound(en) − lower_bound(st)` 精确给出落在闭区间的元素个数。∎

## 6. 复杂度分析

- **时间复杂度**：单次 `addPacket` / `forwardPacket` / `getCount` 均为 $O(\log L)$（查重集合操作与二分主导；队列与桶的增删均摊 $O(1)$），$L \le \min(\text{memoryLimit}, 10^5)$。总代价 $\le 10^5 \times \log 10^5 \approx 1.7 \times 10^6$。
- **空间复杂度**：$O(L)$。三本账各自是当前在存包的投影，共三份线性空间；`head` 惰性删除使 Python 桶内已销元素暂存至桶彻底清空，总量仍受 $O(L + \text{已销总量}) \le O(10^5)$ 控制。

## 7. 参考代码

### C++

```cpp
class Router {
  public:
    Router(int memoryLimit) : limit(memoryLimit) {}

    bool addPacket(int source, int destination, int timestamp) {
        array<int, 3> p{source, destination, timestamp};
        if (!seen.insert(p).second) return false;  // 先查重：重复包不触发淘汰
        if ((int)q.size() == limit) retire();      // 后淘汰：满员才移除最旧
        q.push_back(p);
        ts[destination].push_back(timestamp);      // timestamp 非递减 ⇒ 追加即有序
        return true;
    }

    vector<int> forwardPacket() {
        if (q.empty()) return {};
        array<int, 3> p = retire();                // 转发 = 出队 + 三本账销账
        return {p[0], p[1], p[2]};
    }

    int getCount(int destination, int startTime, int endTime) {
        deque<int>& v = ts[destination];            // 空桶亦正确：ub = lb = begin，差 0
        return upper_bound(v.begin(), v.end(), endTime)
             - lower_bound(v.begin(), v.end(), startTime);
    }

  private:
    array<int, 3> retire() {                        // 容量淘汰与转发共用
        array<int, 3> p = q.front();
        q.pop_front();
        seen.erase(p);
        ts[p[1]].pop_front();                       // 被删者必是桶首（引理 2）
        return p;
    }

    int limit;
    deque<array<int, 3>> q;                 // 账本①：FIFO 顺序
    set<array<int, 3>> seen;                // 账本②：三元组查重
    unordered_map<int, deque<int>> ts;      // 账本③：dest → 非降时间戳
};
```

### Python

```python
from bisect import bisect_left, bisect_right
from collections import deque, defaultdict
from typing import List


class Router:
    def __init__(self, memoryLimit: int):
        self.limit = memoryLimit
        self.q = deque()                # 账本①：FIFO 顺序
        self.seen = set()               # 账本②：三元组查重
        self.ts = defaultdict(list)      # 账本③：dest -> 时间戳（只追加）
        self.head = defaultdict(int)    # 各桶首个有效元素下标（代替 pop_front）

    def addPacket(self, source: int, destination: int, timestamp: int) -> bool:
        p = (source, destination, timestamp)
        if p in self.seen:              # 先查重：重复包不触发淘汰
            return False
        if len(self.q) == self.limit:   # 后淘汰：满员才移除最旧
            self._retire()
        self.q.append(p)
        self.seen.add(p)
        self.ts[destination].append(timestamp)
        return True

    def forwardPacket(self) -> List[int]:
        if not self.q:
            return []
        return list(self._retire())

    def getCount(self, destination: int, startTime: int, endTime: int) -> int:
        v = self.ts[destination]        # 空桶：两个 bisect 同得 0
        h = self.head[destination]
        return bisect_right(v, endTime, h) - bisect_left(v, startTime, h)

    def _retire(self):
        s, d, t = self.q.popleft()
        self.seen.remove((s, d, t))     # 三本账同步销账
        self.head[d] += 1               # 惰性删除：桶不搬移元素
        return s, d, t
```

> 💡 Python 千万别把桶做成 `collections.deque` 再 `bisect`——deque 的随机访问是 $O(n)$，二分整体退化成 $O(n)$；`list` + `head` 惰性指针才是正解。另外 `bisect` 的第三个参数正好传 `lo=head`，把已销前缀天然挡在搜索区间外。

## 8. 边界情况与易错点

1. **先查重后淘汰**：满员且新包与某在存包同键时，必须返回 `false` 且队列一动不动；「先踢再收」会把 `false`/`true` 和队列状态全改错——本题赛中最常见的 WA。
2. **淘汰条件是 `== limit`**：插入前队列长度已达上限才销账；写成 `>` 会短暂超容，写成判 `q.back()` 更是语义错误——被淘汰的永远是**最旧**的队头。
3. **三本账必须同步销账**：漏销 `seen` → 已出队包被误判重复（`addPacket` 错返回 `false`）；漏销桶 → `getCount` 多算（示例 3 里两问从 2 变 1 的瞬时变化就是销账的直接体现）。
4. **非严格有序**：同 dest 同 timestamp 不同 source 的包合法，桶是非降而非严格升序列；`lower_bound` / `upper_bound` 对重复值的闭区间计数恰好正确，不要改用「找到就 +1」的单点判断。
5. **Python 的 deque-bisect 陷阱**：桶用 `deque` 会把 `getCount` 拖成 $O(n)$；必须 `list` + `head`。
6. **C++ 查重键放不进 64 位**：$s, d \le 2\times10^5$ 各需 18 bit、$t \le 10^9$ 需 30 bit，共 66 bit；`set<array<int,3>>` 稳妥，需要更快再换 `unordered_set` + 自定义哈希。
7. **空输入**：空队列 `forwardPacket` 返回 `[]`/`{}`；查询从未出现过的 dest 返回 0——`defaultdict` 与 `operator[]` 自动建空桶，两处天然安全。
8. **重复判定的范围是「当前存储」**：已转发或已淘汰的包不算重复——这正是 `seen` 必须随每次出队删除的原因，也是引理 2 的用武之地。
