# LeetCode 统计追加字母可以获得的单词数 题解

## 1. 题目概述

- **标题 / 题号**：统计追加字母可以获得的单词数（#2135，medium）
- **链接**：https://leetcode.cn/problems/count-words-obtained-after-adding-a-letter/
- **来源**：LeetCode 第 275 场周赛 Q3
- **难度**：中等
- **标签**：位运算、哈希表、字符串

**题意**：给定两个字符串数组 `startWords` 与 `targetWords`（每个字符串都由**互异**的小写字母组成）。一次**转换**分两步：先向某个 start 单词末尾**追加一个它不包含的小写字母**，再将新字符串**任意重排**。问 `targetWords` 中有多少个字符串能由 `startWords` 中**任一**字符串经一次转换得到（start 单词本身不变）。

**约束**：

- $1 \le startWords.length, targetWords.length \le 5 \times 10^4$
- $1 \le startWords[i].length, targetWords[j].length \le 26$
- 每个字符串中每个字母至多出现一次（**字母互异**）

> 💡 题面里最值钱的一句话是最后一条约束：**字母互异**意味着单词与「字母集合」一一对应，26 个字母刚好装进一个整数的低 26 位——位掩码 + 哈希集合的套路直接成立。

## 2. 示例

**示例 1**

```text
输入：startWords = ["ant","act","tack"], targetWords = ["tack","act","acti"]
输出：2
解释：
- "tack" ← 选 "act"，追加 'k' 得 "actk"，重排为 "tack" ✓
- "act"  ✗："act" 虽在 startWords 中，但必须先追加一个字母再重排，不能原样得到
- "acti" ← 选 "act"，追加 'i' 得 "acti"，重排为自身 ✓
```

**示例 2**

```text
输入：startWords = ["ab","a"], targetWords = ["abc","abcd"]
输出：1
解释：
- "abc"  ← "ab" 追加 'c' ✓
- "abcd" ✗："ab" 追加一位后只有 3 个字母，"a" 追加一位后只有 2 个字母，都到不了 4 个
```

**示例 3（补充边界：长度为 1 的 target）**

```text
输入：startWords = ["a"], targetWords = ["a","b"]
输出：0
解释：任何 start 单词长度 ≥ 1，追加一个字母后长度 ≥ 2，长度为 1 的 target 一律不可行。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是两两枚举：对每对 $(s, t) \in startWords \times targetWords$，判断 $t$ 是否能由 $s$ 转换得到（例如把两者分别排序，看 $t$ 的排序结果删掉某个字符后是否等于 $s$ 的排序结果）。共有 $5 \times 10^4 \times 5 \times 10^4 = 2.5 \times 10^9$ 对，每对还要 $O(26)$ 判断——**超时**。

问题出在「对每个 target 都把所有 start 扫一遍」。要打破平方，需要把判定压缩成**一次哈希查询**：把 start 侧预处理成可 $O(1)$ 查询的结构，前提是想清楚「一次转换」到底对单词做了什么。

### 3.2 核心观察：互异字母 ⇒ 单词即 26 位掩码，转换 = 掩码恰多一个 1

![核心观察：单词、字母集合与 26 位掩码的对应](images/2135_bitmask_concept.svg)

三个环环相扣的观察：

1. **重排被掩码吸收**：转换第二步「任意重排」不改变单词的字母多重集；又因字母**互异**，多重集就是集合。于是单词的规范形就是它的**字母集合**，用 26 位掩码编码：$mask(w) = \sum_{c \in w} 2^{\,c - \texttt{a}}$，其中 $c - \texttt{a}$ 是字母 $c$ 的位号（a→0，z→25）。两个互异字母的单词互为重排，当且仅当掩码相同。
2. **追加 = 置一个新位**：第一步「追加一个不存在于 $s$ 的字母 $x$」在掩码层面就是 $mask(s) \to mask(s) \,\vert\, 2^{\,x - \texttt{a}}$，且该位原先是 0。于是「两步转换」合起来只剩一件事：**掩码恰好多出一个 1**。
3. **判定变查询**：$t$ 可由 $s$ 转换得到 $\iff$ $mask(s)$ 等于 $mask(t)$ **去掉恰好一个 1 位**。把所有 start 单词的掩码放进哈希集合 $S$，对每个 target 枚举删哪一位（至多 26 种），查询 $mask(t) \oplus 2^b$ 是否落在 $S$ 里。

> 💡 一句话：**互异字母把「单词 + 追加 + 重排」压缩成「26 位整数 + 置一位」，重排完全消失，每个 target 的判定只剩至多 26 次整数哈希查询。**

顺带一提，两个隐含约束都不需要单独检查：从 $mask(t)$ 里删掉位 $b$ 得到的候选 $mask(s)$ 必然不含 $b$（「追加的字母不存在」自动满足），且 $|s| = |t| - 1$（长度恰差 1 自动满足）。

### 3.3 算法流程：预处理入集合 + 删一位查询

![算法流程：掩码哈希集合与删位查询](images/2135_remove_bit_flow.svg)

1. **预处理**：遍历 `startWords`，对每个单词 $w$ 计算 $mask(w)$，插入哈希集合 $S$（重复单词自动去重）；
2. **查询**：遍历 `targetWords`，对每个 $t$ 计算 $m = mask(t)$；用 lowbit 技巧（$b = t \,\&\, (-t)$，$t \mathrel{\&}= t - 1$）枚举 $m$ 的每个为 1 的位 $b$，若 $m \oplus 2^b \in S$ 则计数并 `break`；
3. 所有 target 处理完，返回计数。

### 3.4 示例演算

以示例 1 完整走一遍。预处理后（集合内以字母集合示意）：

$$S = \big\{\, \{a,n,t\},\ \{a,c,t\},\ \{a,c,t,k\} \,\big\}$$

| target | 掩码 | 逐位删除后的候选（查 $S$） | 判定 |
|---|---|---|---|
| `"tack"` | $\{a,c,t,k\}$ | 删 $a \to \{c,t,k\}$ ✗ · 删 $c \to \{a,t,k\}$ ✗ · 删 $t \to \{a,c,k\}$ ✗ · 删 $k \to \{a,c,t\}$ ✓ | 计数（`"act"` + k） |
| `"act"` | $\{a,c,t\}$ | 删 $a \to \{c,t\}$ ✗ · 删 $c \to \{a,t\}$ ✗ · 删 $t \to \{a,c\}$ ✗ | 不计数 |
| `"acti"` | $\{a,c,t,i\}$ | 删 $a \to \{c,t,i\}$ ✗ · 删 $c \to \{a,t,i\}$ ✗ · 删 $t \to \{a,c,i\}$ ✗ · 删 $i \to \{a,c,t\}$ ✓ | 计数（`"act"` + i） |

答案 $= 2$ ✓。注意第二行：`"act"` 的掩码**本身就在** $S$ 里，但它不是任何「删一位」候选，判不上——这正是示例 1 想强调的「必须追加一个字母」。

## 4. 算法细节

1. **掩码计算**：一遍扫字符累加位即可，$O(|w|)$；掩码是 26 位以内的非负整数（最大 $2^{26} - 1$），`int` 装得下。
2. **枚举 1 位用 lowbit**：`for (int t = m; t; t &= t - 1)` 每次取出最低的 1 位，只循环 $\mathrm{popcount}(m)$ 次而非固定 26 次；直接 `for (b = 0; b < 26; ++b)` 也能过，两者都是 $O(26)$ 上界。
3. **哈希集合选择**：C++ 用 `unordered_set<int>`（`reserve` 一下减少扩容），Python 直接 `set`。存整数比存排序后的字符串 key 快得多——整数哈希 $O(1)$，字符串哈希 $O(L)$ 且比较开销大。
4. **两个自动成立的条件**：删位候选 $mask(t) \setminus \{b\}$ 天然保证 (a) 追加字母 $b \notin s$；(b) $|s| = |t| - 1$。代码里完全不需要显式检查这两个约束。
5. **对称的另一种写法**：反过来对每个 start 单词枚举**可追加**的字母（$26 - |s|$ 种），把 $mask(s) \,|\, 2^b$ 全部插入「可达集合」，target 直接一次查询。复杂度同为 $O(26n)$，两种方向等价，删位法写起来更短。
6. **重复单词**：`startWords` 内部重复由集合去重；`targetWords` 内部重复按出现次数**各计一次**（数的是字符串实例，不是去重后的种类）。

## 5. 正确性证明

**引理 1（重排不变性）**：设 $w$ 是字母互异的单词，$\rho(w)$ 是它的任意重排，则 $mask(\rho(w)) = mask(w)$。反之，字母互异且掩码相同的两个单词互为重排。

**证明**：重排是字母多重集合上的置换，不改变「哪些字母各出现多少次」；字母互异时每个字母恰出现一次，故「出现的字母集合」在重排下不变，即掩码不变。反之，掩码相同即字母集合相同，两个互异字母集合相同的单词只是同一集合的两种排列，互为重排。∎

**引理 2（转换的掩码刻画）**：$t$ 可由 $s$ 经一次转换得到 $\iff$ 存在 $mask(t)$ 的某个为 1 的位 $b$，使得 $mask(s) = mask(t) \oplus 2^b$。

**证明**：（⇒）转换先向 $s$ 追加不在其中的字母 $x$，得 $s'$。设 $b = x - \texttt{a}$，则 $mask(s') = mask(s) \cup \{b\}$ 且 $b \notin mask(s)$（并上一位单独的 1）；再重排为 $t$，由引理 1 得 $mask(t) = mask(s') = mask(s) \cup \{b\}$。由于 $b \notin mask(s)$，这个并集不重叠，故 $mask(t) \oplus 2^b = mask(s)$。（⇐）设 $mask(s) = mask(t) \oplus 2^b$，其中 $b$ 是 $mask(t)$ 的 1 位。则 $b \notin mask(s)$ 且 $mask(s) \cup \{b\} = mask(t)$：给 $s$ 追加字母 $x = \texttt{a} + b$（合法，$x$ 不在 $s$ 中），得 $s + x$，其掩码为 $mask(t)$；由引理 1，$s + x$ 可重排为 $t$。∎

**定理**：算法返回值等于 `targetWords` 中可由 `startWords` 中某单词经一次转换得到的字符串个数。

**证明**：target $t$ 被计数 $\iff$ 枚举中存在 $mask(t)$ 的 1 位 $b$ 使 $mask(t) \oplus 2^b \in S$。由 $S$ 的构造，这 $\iff$ 存在 $s \in startWords$ 使 $mask(s) = mask(t) \oplus 2^b$；由引理 2，这 $\iff$ $t$ 可由某个 $s$ 经一次转换得到。枚举覆盖 $mask(t)$ 的**全部** 1 位，故不漏；每个 $t$ 命中即 `break`，故不重。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(\sum_i |startWords_i| + 26 \cdot m\big)$，其中 $m = |targetWords|$。预处理每个字符 $O(1)$；每个 target 计算掩码 $O(|t|)$，枚举删位至多 26 次整数哈希查询。由 $|w| \le 26$，总上界 $O(26(n + m)) \approx 2.6 \times 10^6$ 次整数运算。
- **空间复杂度**：$O(n)$，$n = |startWords|$，哈希集合存至多 $n$ 个 26 位整数（去重后）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int wordCount(vector<string>& startWords, vector<string>& targetWords) {
        unordered_set<int> masks;
        masks.reserve(startWords.size() * 2);
        for (const string& w : startWords) {
            int m = 0;
            for (char c : w) m |= 1 << (c - 'a');
            masks.insert(m);
        }
        int ans = 0;
        for (const string& w : targetWords) {
            int m = 0;
            for (char c : w) m |= 1 << (c - 'a');
            for (int t = m; t; t &= t - 1) {          // lowbit 枚举每个 1 位
                if (masks.count(m ^ (t & -t))) {       // 删掉该位后查集合
                    ++ans;
                    break;
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def wordCount(self, startWords: List[str], targetWords: List[str]) -> int:
        masks = set()
        for w in startWords:
            m = 0
            for c in w:
                m |= 1 << (ord(c) - 97)
            masks.add(m)

        ans = 0
        for w in targetWords:
            m = 0
            for c in w:
                m |= 1 << (ord(c) - 97)
            t = m
            while t:
                if m ^ (t & -t) in masks:   # 删掉最低的 1 位后查询
                    ans += 1
                    break
                t &= t - 1                  # 移除该位，试下一个
        return ans
```

## 8. 边界情况与易错点

1. **「子集」不等于「可行」**：判定必须要求**恰好多一位**。$mask(s) \subset mask(t)$ 但 $|t| \ge |s| + 2$ 时不可行（如 `"a"` 与 `"abc"`）。删一位的写法天然排除；若误写成「子集包含」判断就会错。
2. **必须追加字母**：target 原样出现在 `startWords` 中也不算（示例 1 的 `"act"`）。判定基于「更短的候选掩码」，自动排除，无需特判。
3. **长度 1 的 target**：删掉唯一字母得空掩码 $0$；`startWords` 单词长度 $\ge 1$，$0$ 永远不在集合中，自然返回不可行。
4. **lowbit 笔误**：`t & -t` 取出的是**仅含最低 1 位**的掩码，与 `m ^ (t & -t)` 配合删的正是该位；若误写成 `m ^ t` 会把 $m$ 与 $t$ 不同的多个位一起翻转，语义完全错误。
5. **C++ `unordered_set` 扩容**：$5 \times 10^4$ 个元素问题不大，`reserve` 一下更稳；极端卡常可换排序数组 + `std::binary_search`，$O(26 \log n)$ 也够。
6. **别用排序字符串当 key**：功能上等价（每 target 生成 $\le 26$ 个删位子串查 set），但每次子串构造是 $O(L)$，常数明显大于整数异或 + 整数哈希。
7. **重复计数语义**：`targetWords` 里重复的单词各自计数一次（数实例，不是数种类），不要先去重。

**延伸思考**：

- **反向构造**：对每个 start 枚举可追加的字母构造「可达集合」，target 直接 $O(1)$ 查询——与删位法对称，元素至多 $26n$ 个，适合 target 远多于 start 的数据分布。
- **允许追加 $k$ 个字母**：判定变为「$mask(t)$ 的某个大小 $|t| - k$ 的子集在集合中」，可对每个 target 枚举子集（$O(2^{|t|})$）或从 start 掩码出发做 $k$ 层 BFS 扩展（每层乘 26）。
- **允许字母重复**：掩码信息不足，规范形需换成「排序后的字符串」，判定变为「$t$ 的排序串删一个字符是否在集合中」，查询退化为 $O(L)$ 字符串哈希。
- **允许追加或删除一个字母（±1 位）**：把删位与增位候选都查询即可，仍是每单词 $O(26)$。
