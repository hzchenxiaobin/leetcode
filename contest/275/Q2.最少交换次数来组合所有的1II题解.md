# LeetCode 最少交换次数来组合所有的 1 II 题解

## 1. 题目概述

- **标题 / 题号**：最少交换次数来组合所有的 1 II（#2134，medium）
- **链接**：https://leetcode.cn/problems/minimum-swaps-to-group-all-1s-together-ii/
- **来源**：LeetCode 第 275 场周赛 Q2
- **难度**：中等
- **标签**：数组、滑动窗口

**题意**：**交换**指选中数组中两个**互不相同**的位置并互换二者的值。**环形**数组认为第一个元素与最后一个元素相邻。给定一个**二进制环形**数组 `nums`，返回把所有 $1$ 聚集到环上**任意**一段连续位置所需的最少交换次数。

**约束**：

- $1 \le nums.length \le 10^5$
- `nums[i]` 为 `0` 或 `1`

> 💡 两个建模要点藏在题面里：**环形**（最优的连续段可能横跨首尾）与**交换任意两位置**（不是相邻交换，一次交换直接对调两格）。另外窗口长度题目并没有给——它由 $1$ 的个数自己决定（见 3.2）。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,0,1,1,0,0]
输出：1
解释：交换下标 1 和 2（或 3 和 5 等），得到 [0,0,1,1,1,0,0]，所有 1 连续。
```

**示例 2**

```text
输入：nums = [0,1,1,1,0,0,1,1,0]
输出：2
解释：利用环形特性可两次交换聚齐（见 3.4 演算）。
```

**示例 3**

```text
输入：nums = [1,1,0,0,1]
输出：0
解释：环形视角下 [1,1,...,1] 已连续（下标 4、0、1 相邻），无需交换。
```

**示例 4（补充边界：全 0）**

```text
输入：nums = [0,0,0]
输出：0
解释：没有 1，无需交换即视为已聚集。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的是把「聚齐」当成目标做 BFS：每个状态是整个数组，一次交换有 $O(n^2)$ 种选择，状态数指数级，$n$ 上到 $10^5$ 完全不可行。

退一步，先想清楚**枚举什么**：由交换不改变 $1$ 的总数 $t$，最终所有 $1$ 一定占满某个长度为 $t$ 的环形窗口。于是可以暴力枚举窗口起点 $s \in [0, n)$，对每个起点花 $O(t)$ 数一遍窗口内的 $0$（这就是该窗口的代价，见 3.2 的证明），取最小。总复杂度 $O(n \cdot t) = O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次操作，**超时**。

但相邻起点之间窗口只移动了一格：**进一个新元素、出一个旧元素**。这正是定长滑动窗口的形状，$O(1)$ 即可转移——$O(n)$ 解决。

### 3.2 核心观察：终态是环上长为 $t$ 的窗口，窗口代价 = 窗内 0 的个数

![核心观察：终态窗口与交换代价模型](images/ones_ring_window_concept.svg)

三个环环相扣的事实：

1. **终态刻画**：交换不改变 $1$ 的个数，设 $t = \sum nums$。「所有 $1$ 聚在一起」的终态中，$1$ 恰好占满某个**长度为 $t$ 的环形窗口** $W$，$W$ 外全为 $0$。于是候选终态只有 $n$ 个（以窗口起点区分），答案就是这 $n$ 个代价的最小值。
2. **守恒配对**：固定窗口 $W$，设窗内有 $z$ 个 $0$，则窗内有 $t - z$ 个 $1$，故**窗外恰有 $z$ 个 $1$**——窗内的 $0$ 与窗外的 $1$ 数量相等，可两两配对。
3. **代价恰为 $z$**：每次「窗内 $0 \leftrightarrow$ 窗外 $1$」的交换让窗内 $1$ 数恰增 $1$，其他任何交换都不增；而窗内 $1$ 数需要从 $t - z$ 补到 $t$，缺口 $z$。所以到达 $W$ 至少要 $z$ 次，且按配对逐对交换 $z$ 次恰好完成。

> 💡 一句话：**选定窗口后，「把窗外的 1 换进窗内的 0」是一次交换换一个好一个，代价就是窗内 0 的个数。** 再由「窗内 1 数 + 窗内 0 数 = 窗口长 $t$」，答案也可写成 $t - \max$（窗口内 1 数）——滑窗时维护 1 的个数更顺手。

### 3.3 算法流程：长度为 $t$ 的环形定长滑窗

![算法流程：环形定长滑动窗口](images/ones_ring_sliding_flow.svg)

1. 统计 $t = \sum nums$；若 $t = 0$（无 $1$）或 $t = n$（全 $1$），直接返回 $0$；
2. 初始窗口取起点 $s = 0$ 的 $\{0, 1, \dots, t-1\}$，统计窗内 $1$ 数 `ones`，`best = ones`；
3. 起点 $s$ 从 $1$ 滑到 $n - 1$：**进**新覆盖的下标 $(s + t - 1) \bmod n$，**出**离开的下标 $s - 1$，$O(1)$ 更新 `ones`，并更新 `best = max(best, ones)`；
4. 返回 $t - \mathrm{best}$。

**环形的实现**有两种等价写法：**取模**（如上，$O(1)$ 额外空间）或**加倍数组**（把 `nums` 拼成 `nums + nums`，对起点 $0 \dots n-1$ 滑窗，$O(n)$ 额外空间）。

### 3.4 示例演算

以示例 2 `nums = [0,1,1,1,0,0,1,1,0]`（$n = 9$，$t = 5$）完整走一遍，滑动过程（进/出下标与 `ones` 的变化）：

| 起点s | 窗口下标 | 窗口值 | 1 数 | 进 / 出 |
|---|---|---|---|---|
| 0 | 0–4 | `0 1 1 1 0` | 3 | 初始 |
| 1 | 1–5 | `1 1 1 0 0` | 3 | 进 `nums[5]=0`，出 `nums[0]=0` |
| 2 | 2–6 | `1 1 0 0 1` | 3 | 进 `nums[6]=1`，出 `nums[1]=1` |
| 3 | 3–7 | `1 0 0 1 1` | 3 | 进 `nums[7]=1`，出 `nums[2]=1` |
| 4 | 4–8 | `0 0 1 1 0` | 2 | 进 `nums[8]=0`，出 `nums[3]=1` |
| 5 | 5,6,7,8,**0** | `0 1 1 0 0` | 2 | 进 `nums[0]=0`，出 `nums[4]=0` |
| 6 | 6,7,8,**0,1** | `1 1 0 0 1` | 3 | 进 `nums[1]=1`，出 `nums[5]=0` |
| 7 | 7,8,**0,1,2** | `1 0 0 1 1` | 3 | 进 `nums[2]=1`，出 `nums[6]=1` |
| 8 | 8,**0,1,2,3** | `0 0 1 1 1` | 3 | 进 `nums[3]=1`，出 `nums[7]=1` |

`best = 3`（多个窗口并列），答案 $= t - \mathrm{best} = 5 - 3 = 2$ ✓。注意 $s \ge 5$ 的窗口下标开始**回绕**——这正是环形取模发挥作用的地方，线性滑动会漏掉这些窗口。

![示例 2 的 9 个环形窗口演算](images/ones_ring_walkthrough.svg)

具体换法（取 $s = 0$ 的窗口）：窗内 $0$ 在下标 $0$、$4$，窗外 $1$ 在下标 $6$、$7$，两次交换 $(0 \leftrightarrow 6)$、$(4 \leftrightarrow 7)$ 得到 `[1,1,1,1,1,0,0,0,0]`。

## 4. 算法细节

1. **窗口长度由数据自己决定**：不是题目给定的 $k$，而是 $t = \sum nums$——「聚齐所有 $1$」的段长就是 $1$ 的个数。想通这一点，本题就变成一道普通定长滑窗。
2. **环形取模滑窗**：起点 $s$ 右移一格时，新覆盖下标 $(s + t - 1) \bmod n$，离开下标 $s - 1$。该式最大为 $(n-1) + (n-1) = 2n - 2 < 2n$，取一次模即可。加倍数组写法更短（`nums[s + t - 1]` 直接索引），代价是 $O(n)$ 空间。
3. **初始窗口**：先对 `nums[0..t-1]` 求和（$t \le n$ 不越界）作为 `ones` 初值，`best` 初始化为**该值**而非 $0$，起点从 $s = 1$ 滑到 $n-1$，恰好覆盖全部 $n$ 个起点。
4. **维护 1 数而非 0 数**：滑动时「进 1 加、出 1 减」直接加减元素值即可（元素就是 0/1），最后用 $t - \mathrm{best}$ 换算答案，省去单独统计 0 的逻辑。
5. **特判 $t = 0$ 与 $t = n$**：语义上「窗口长为 0」与「窗口即整个环」都应返回 $0$。取模写法下不特判数值上也不会错（进出下标恰好抵消），但显式特判可读性更好。

## 5. 正确性证明

**引理 1（终态刻画）**：设数组中 $1$ 的总数为 $t$。一个状态满足「所有 $1$ 在环形意义上连续」当且仅当存在长度为 $t$ 的环形窗口 $W$，使 $1$ 恰好占满 $W$ 且 $W$ 外全为 $0$。

**证明**：（⇒）$t$ 个 $1$ 两两环形相邻，设其在环上顺时针依次占据下标 $s, s+1, \dots, s+t-1$（模 $n$），即窗口 $W$；又 $1$ 的总数为 $t$ 且全部落在 $W$ 内，故 $W$ 外全为 $0$。（⇐）$W$ 是长度 $t$ 的连续段且被 $1$ 占满，显然所有 $1$ 连续。∎

**引理 2（窗口代价）**：固定长度 $t$ 的环形窗口 $W$，设初始时 $W$ 内有 $z$ 个 $0$。将数组变为「$1$ 恰占满 $W$」所需的最少交换次数恰为 $z$。

**证明**：
（下界）令 $f$ 为当前 $W$ 内 $1$ 的个数，初值 $t - z$，目标 $t$，缺口 $z$。按两个交换位置与 $W$ 的关系分类讨论一次交换对 $f$ 的影响：窗内 $0 \leftrightarrow$ 窗外 $1$ 使 $f$ 增 $1$；窗内 $1 \leftrightarrow$ 窗外 $0$ 使 $f$ 减 $1$；其余情形（两位置同侧，或两位置值相同而交换无效果）$f$ 不变。故每次交换 $f$ 至多增 $1$，补齐缺口至少需要 $z$ 次交换。
（可达性）$W$ 内恰有 $z$ 个 $0$；又 $1$ 总数为 $t$ 而 $W$ 内只有 $t - z$ 个，故 $W$ 外恰有 $z$ 个 $1$。把窗内的 $0$ 与窗外的 $1$ 任意两两配对，逐对交换，每次都是「窗内 $0 \leftrightarrow$ 窗外 $1$」，$f$ 恰增 $1$；$z$ 次后 $f = t$，即 $1$ 占满 $W$。∎

**定理**：所求最少交换次数等于 $\min_{W} z(W)$，其中 $W$ 取遍所有长度为 $t$ 的环形窗口；等价地，等于 $t - \max_{W} \mathrm{ones}(W)$。

**证明**：任何交换序列的终点都是某个「$1$ 聚集」状态，由引理 1 它对应某个窗口 $W$；由引理 2，到达该状态的最少交换次数为 $z(W)$（至少要这么多，且这么多就够了）。因此最优值 $= \min_{W} z(W)$。又每个窗口长度固定为 $t$，窗内 $1$ 数与 $0$ 数之和为 $t$，即 $z(W) = t - \mathrm{ones}(W)$，故两种表述等价。∎

**算法正确性**：滑动过程枚举起点 $s = 0, 1, \dots, n-1$ 共 $n$ 个环形窗口。当 $0 < t < n$ 时，长度 $t$ 的环形窗口（作为下标集合）与其唯一起点一一对应（弧长小于 $n$，起点是弧上唯一的前驱不在集合内的下标），故 $n$ 个起点恰好取遍全部候选窗口；$t \in \{0, n\}$ 已特判返回 $0$。每步滑动按「进新出旧」$O(1)$ 维护窗内 $1$ 数，与窗口实际内容一致，`best` 取到 $\max \mathrm{ones}(W)$，由定理返回值正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟求和 $O(n)$；初始窗口统计 $O(t)$；$n - 1$ 步滑动，每步 $O(1)$ 增减并更新最值。
- **空间复杂度**：取模写法 $O(1)$ 额外空间；加倍数组写法 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minSwaps(vector<int>& nums) {
        int n = nums.size();
        int total = accumulate(nums.begin(), nums.end(), 0);
        if (total == 0 || total == n) return 0;
        int ones = 0;
        for (int i = 0; i < total; ++i) ones += nums[i];   // 初始窗口 [0, t)
        int best = ones;
        for (int s = 1; s < n; ++s) {                      // 环形滑动 n 个起点
            ones += nums[(s + total - 1) % n] - nums[s - 1];
            best = max(best, ones);
        }
        return total - best;                               // t - max ones
    }
};
```

### Python

```python
class Solution:
    def minSwaps(self, nums: List[int]) -> int:
        n = len(nums)
        total = sum(nums)
        if total == 0 or total == n:
            return 0
        ones = sum(nums[:total])          # 初始窗口 [0, t)
        best = ones
        for s in range(1, n):             # 环形滑动 n 个起点
            ones += nums[(s + total - 1) % n] - nums[s - 1]
            best = max(best, ones)
        return total - best               # t - max ones
```

## 8. 边界情况与易错点

1. **忘记环形（最常见错误）**：只在 $[0, n - t]$ 上做线性滑窗会漏掉跨首尾的窗口。示例 3 `[1,1,0,0,1]` 的最优窗口是跨界的 $\{4, 0, 1\}$，线性写法只能找到 2 个 1，误答 $1$（正确为 $0$）。
2. **取模遗漏**：$s + t - 1$ 最大到 $2n - 2$，忘记 `% n` 直接越界；加倍数组写法则要保证起点枚举到 $n - 1$（只枚举到 $n - t$ 同样漏跨界窗口）。
3. **窗口长度写错**：段长必须是 $1$ 的个数 $t$，不是 $0$ 的个数、也不是 $n - t$。
4. **答案换算错**：是 $t - \max\mathrm{ones}$，不是 $n - \max\mathrm{ones}$。
5. **漏掉初始窗口**：从 $s = 1$ 开始滑却把 `best` 初始化为 $0$，当最优恰是起点 $0$ 时（如 `[1,1,1,0,0,0]`）会误答 $1$。`best` 必须以初始窗口的 `ones` 为初值。
6. **误当相邻交换**：本题一次交换对调**任意**两个位置（如 `[0,1,0,0,1]` 答案为 $1$：下标 2 与 4 直接对调），若套用相邻交换的模型（中位数 + 前缀和）会系统性算多。
7. **$t = 0$ / $t = n$ / $n = 1$**：全部被开头的特判覆盖（$n = 1$ 时 $t \in \{0, 1\} = \{0, n\}$），无需额外处理。
