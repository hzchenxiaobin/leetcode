# LeetCode 全部开花的最早一天 题解

## 1. 题目概述

- **标题 / 题号**：全部开花的最早一天（#2136，hard）
- **链接**：https://leetcode.cn/problems/earliest-possible-day-of-full-bloom/
- **来源**：LeetCode 第 275 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、排序

**题意**：有 $n$ 枚种子，第 $i$ 枚必须先**播种**再**生长**：播种需要累计劳作 `plantTime[i]` 个整天（每天只能为一枚种子劳作，**无须连续**，干满即算种完）；种完后生长 `growTime[i]` 个整天（**无需看管**），生长的最后一天之后开花。从第 0 天起可按任意方式播种，返回**所有种子都开花**的最早日子。

**约束**：

- $1 \le n \le 10^5$
- $1 \le plantTime[i], growTime[i] \le 10^4$

> 💡 读题关键在三句话：①「每天只能为一枚种子劳作」⇒ 播种是**串行独占资源**；②「无须连续」⇒ 决定开花时刻的只有「累计干满 `plantTime` 的那一天」，与穿插方式无关；③「生长无需看管」⇒ 生长是**免费并行资源**。总播种量 $\sum plantTime$ 是无论如何省不掉的常量——于是本题本质是**单机调度**：每项任务有加工时间 $p$ 与尾部延迟 $q$，最小化 $\max_j(C_j + q_j)$。

> 💡 本题在本仓库另有[每日题解 2136](../../solution/2101-2200/2136_全部开花的最早一天.md)：主线同为「按 `growTime` 降序 + 交换论证」。本篇按**周赛复盘视角**展开：给出规范化（连续化）、目标函数、交换论证的完整引理-定理证明链，$P + g$ 的 off-by-one 校准，以及「排序键混入 plantTime」等赛场高频翻车点。本篇是第 275 场收官题：同场 Q1（#2133 行列检查模拟）、Q2（#2134 环形定长滑窗）、Q3（#2135 位掩码 + 哈希）均已成文。

## 2. 示例

**示例 1**

```text
输入：plantTime = [1,4,3], growTime = [2,3,1]
输出：9
解释：一种最优安排——
- 第 0 天播种种子 0（p=1），生长 2 天（第 1、2 天），第 3 天开花；
- 第 1~4 天播种种子 1（p=4），生长 3 天（第 5、6、7 天），第 8 天开花；
- 第 5~7 天播种种子 2（p=3），生长 1 天（第 8 天），第 9 天开花。
所有种子开花的最早一天是第 9 天。
```

**示例 2**

```text
输入：plantTime = [1,2,3,2], growTime = [2,1,2,1]
输出：9
解释：按 growTime 降序种：种子 0 → 种子 2 → 种子 1 → 种子 3，
完成播种时刻依次为 1、4、6、8，开花日依次为 3、6、7、9，取最大 9。
```

**示例 3（校准 off-by-one 的最小样例）**

```text
输入：plantTime = [1], growTime = [1]
输出：2
解释：第 0 天播种收工，第 1 天生长，第 2 天开花——开花日 = plantTime + growTime。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是枚举**播种顺序的全排列**：对每个排列 $O(n)$ 计算全部开花日。$n = 10^5$ 时有 $10^5!$ 种排列，天文数字。

退一步想 DP：把「已种完的种子集合 + 已用天数」当状态？「已用天数」就是集合内 `plantTime` 之和（总量守恒，冗余），而剩下的核心——**按什么顺序种**——无法压缩成多项式状态（本质是排列型问题）。暴力与 DP 都死路，指向**贪心 + 邻项交换论证**：猜测一个局部排序规则，证明任意逆序对都可交换且不变差。

### 3.2 核心观察：播种独占园丁，生长免费并行 ⇒ 生长慢的先种

![核心观察：播种串行、生长并行的调度视角](images/2136_greedy_concept.svg)

三个环环相扣的观察：

1. **调度可规范化**：种子的开花时刻只取决于它「干满 `plantTime` 的那一天」。任何穿插、闲置的日程都能重排成「按某个顺序**逐枚连续播种**」而不推迟任何种子的播种完成时刻（证明见 §5 引理 1）。于是搜索空间从「无穷的日程」坍缩为「$n!$ 个顺序」，再由贪心直接锁定最优顺序。
2. **目标函数是一个 max**：按顺序 $\sigma$ 连续播种时，第 $k$ 枚在累计第 $P_k = \sum_{j \le k} plantTime[\sigma_j]$ 天收工（即第 $P_k - 1$ 天干完最后一锹土），生长占第 $P_k$ 至 $P_k + g - 1$ 天，开花日为 $P_k + g$。答案 $= \max_k (P_k + g_{\sigma_k})$。
3. **贪心规则**：按 `growTime` **从大到小**播种。直觉：$g$ 大的种子是「长尾巴」，越早扔进土里，越能把它的生长期**藏进你种别的种子的日子里**（并行免费）；$g$ 小的种子留到最后，它的小尾巴最后甩出来也只延后一点点。排序键**与 `plantTime` 完全无关**——交换论证里 $p_a, p_b$ 只是平移量，比较时被 $\max$ 吸收。

> 💡 一句话：**总量守恒（$\sum p$ 定死）+ 单机串行（顺序决定完成时刻）+ 免费尾巴（$g$ 只做加法）⇒ 长尾巴先出门**。这是运筹学里带尾延的单机调度问题（$1 \,|\, q_j \,|\, C_{\max}$，Jackson 法则）的教科书形态。

### 3.3 算法流程：排序 + 前缀和扫描

![算法流程：按 growTime 降序排序后一遍前缀和](images/2136_sort_prefix_flow.svg)

1. 把种子下标按 `growTime` **降序**排序（相等者任意）；
2. 维护前缀和 `cur`（已消耗的播种天数）与答案 `ans`；
3. 依次遍历排序后的种子：`cur += plantTime[i]`，`ans = max(ans, cur + growTime[i])`；
4. 返回 `ans`。

### 3.4 示例演算

以示例 1 走一遍。按 $g$ 降序排序后：**种子 1** $(p=4, g=3)$ → **种子 0** $(p=1, g=2)$ → **种子 2** $(p=3, g=1)$。

| 播种顺序 | $p$ | 收工时刻 $P$（前缀和） | $g$ | 开花日 $P + g$ | 生长占用的天 |
|---|---|---|---|---|---|
| 种子 1 | 4 | 4 | 3 | **7** | 第 4、5、6 天 |
| 种子 0 | 1 | 5 | 2 | **7** | 第 5、6 天（与种子 1 并行！） |
| 种子 2 | 3 | 8 | 1 | **9** | 第 8 天 |

答案 $= \max(7, 7, 9) = 9$ ✓。注意两点：种子 0 的生长期完全**叠在**种子 1 的生长期上（并行免费的直观体现）；第 8 天园丁已经闲下来（播种总量 $\sum p = 8$ 一天没省），纯粹在等种子 2 的一天生长期。

![示例 1 的甘特图演算](images/2136_walkthrough.svg)

另外，官方解释给出的顺序「种子 0 → 1 → 2」算出开花日 $3, 8, 9$，同样是 9——**最优顺序不唯一**，贪心给出的是其中最容易构造的一种。反过来若按 $g$ **升序**种（种子 2 → 0 → 1），开花日为 $4, 6, 11$，答案劣化为 11。

## 4. 算法细节

1. **只存顺序，不存日程**：由引理 1，穿插与闲置都可抹掉。代码里完全没有「第几天种哪枚」的模拟——一个前缀和走天下，这正是「无须连续」这句话送给玩家的礼物。
2. **开花日公式**：完成播种 = 第 $P-1$ 天收工，生长占第 $P$ 至 $P+g-1$ 天，「生长最后一天之后开花」⇒ 开花日 $= P + g$。务必用示例 3（`[1],[1]` → 2）校准，这是全场最高频的 off-by-one。
3. **排序键只有 `growTime`**：不要把 `plantTime` 混进比较函数（比如按 $p+g$ 或 $p \cdot g$ 排），任何混合键都能被交换论证的反例击穿——例如 $(p=1, g=1)$ 与 $(p=5, g=2)$：按 $p+g$ 排序会先种前者，但先种 $(5,2)$ 才不劣。
4. **并列的 $g$**：顺序任意，答案不变（引理 3 中 $g_a = g_b$ 时交换前后的目标值相等），无需稳定排序。
5. **溢出审计**：$P \le 10^5 \times 10^4 = 10^9$，$P + g \le 10^9 + 10^4 < 2^{31} - 1 \approx 2.147 \times 10^9$，`int` 恰好装得下但贴着上限；C++ 建议用 `long long` 累加前缀和，返回前再截断，一劳永逸。
6. **复杂度瓶颈在排序**：$O(n \log n)$。由于 $g \le 10^4$ 值域很小，也可按 $g$ 桶排（从大到小遍历桶）做到 $O(n + V)$，在本题数据规模下没有必要。

## 5. 正确性证明

**引理 1（规范化）**：任意可行日程中，设种子按「完成播种」的先后次序为 $\sigma_1, \sigma_2, \dots, \sigma_n$，则「按 $\sigma$ 逐枚连续播种」的日程使每枚种子完成播种的时刻**不晚于**原日程。

**证明**：任取 $k$。原日程中 $\sigma_1, \dots, \sigma_k$ 的全部播种劳动都发生在第 $0$ 至 $d$ 天内（$d$ 为 $\sigma_k$ 的完成日，且每天至多一锹），共 $d + 1$ 个日子，故 $\sum_{j \le k} plantTime[\sigma_j] \le d + 1$。连续播种时 $\sigma_k$ 在第 $\big(\sum_{j \le k} plantTime[\sigma_j]\big) - 1 \le d$ 天收工。∎

（推论：最优解总可在「逐枚连续播种」的日程中取到，搜索空间坍缩为顺序集合。）

**引理 2（目标函数）**：按顺序 $\sigma$ 连续播种时，全部开花日为 $\max_k \big(P_k + g_{\sigma_k}\big)$，其中 $P_k = \sum_{j \le k} plantTime[\sigma_j]$。

**证明**：$\sigma_k$ 于第 $P_k - 1$ 天完成播种；生长占第 $P_k, \dots, P_k + g_{\sigma_k} - 1$ 天；由题意开花在生长最后一天之后，即第 $P_k + g_{\sigma_k}$ 天。全体开花取逐枚开花日的最大值。∎

**引理 3（交换论证）**：设顺序中相邻两枚种子 $a$（先）、$b$（后）满足 $g_a < g_b$，则交换二者后目标值不变大。

**证明**：设 $a$ 之前的播种总量为 $P$。交换前，$a, b$ 贡献的目标候选为 $P + p_a + g_a$ 与 $P + p_a + p_b + g_b$，故交换前的最大值 $\ge P + p_a + p_b + g_b$。交换后候选为 $P + p_b + g_b$ 与 $P + p_a + p_b + g_a$，最大值为 $P + p_b + \max(g_b,\; p_a + g_a)$。分两种情况：

- 若 $g_b \ge p_a + g_a$：交换后最大值 $= P + p_b + g_b \le P + p_a + p_b + g_b \le$ 交换前最大值；
- 若 $g_b < p_a + g_a$：交换后最大值 $= P + p_a + p_b + g_a < P + p_a + p_b + g_b \le$ 交换前最大值。

其余种子的前缀和不受相邻交换影响，目标不变。∎

**定理**：按 `growTime` 降序播种所得的全部开花日为最优值。

**证明**：取任意最优顺序。若其中存在相邻逆序对（$g$ 小者在前），由引理 3 交换后目标值不增，仍为最优。每次交换严格减少一个逆序对，有限步后得到无逆序的顺序——即按 $g$ 非升序排列——且目标值一路不增，故该顺序的目标值 $\le$ 最优值；又它是可行解，目标值 $\ge$ 最优值，故相等。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$——排序占主导；随后一遍扫描累加前缀和取 max 为 $O(n)$。$n = 10^5$ 时约 $1.7 \times 10^6$ 次比较，远低于时限。
- **空间复杂度**：$O(n)$——C++ 的下标数组（或 `pair` 数组）、Python 的 `zip` 列表；排序递归栈 $O(\log n)$。若在原数组上就地按 pair 排序，额外空间仍为 $O(n)$ 级别（下标重排不可避免）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int earliestFullBloom(vector<int>& plantTime, vector<int>& growTime) {
        int n = plantTime.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return growTime[a] > growTime[b];      // 生长慢的先种
        });
        long long cur = 0, ans = 0;
        for (int i : idx) {
            cur += plantTime[i];                   // cur = 完成播种的前缀和
            ans = max(ans, cur + growTime[i]);     // 开花日 = cur + g
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def earliestFullBloom(self, plantTime: List[int], growTime: List[int]) -> int:
        ans = cur = 0
        for p, g in sorted(zip(plantTime, growTime), key=lambda x: -x[1]):
            cur += p
            ans = max(ans, cur + g)
        return ans
```

## 8. 边界情况与易错点

1. **开花日 off-by-one（全场最高频）**：正确公式是 $P + g$，不是 $P + g + 1$（开花当天不算天数）、也不是 $P - 1 + g$（把收工当天错当生长第一天）。用示例 3 校准：`[1],[1]` → 第 0 天种完、第 1 天生长、第 2 天开花。
2. **排序方向写反**：必须 `growTime` **降序**。升序在示例 1 得 11 而非 9。
3. **排序键混入 plantTime**：任何含 $p$ 的排序键（$p+g$、$p \cdot g$、$g/p$……）都是错的——引理 3 的证明中 $p$ 只出现在两侧共同的平移量里，排序键只由 $g$ 的相对大小决定。
4. **被「无须连续」带偏写日程模拟**：想维护「今天种谁」的优先队列或按天模拟是死路（天数上限 $10^9$）；由引理 1 连续化，前缀和就是全部。
5. **溢出**：$P + g$ 上界 $\approx 1.00001 \times 10^9 < 2^{31} - 1$，`int` 恰好够；但前缀和累加过程中的中间量同量级，C++ 用 `long long` 更稳（Python 无此虑）。
6. **并列的 `growTime`**：顺序任意（引理 3 中 $g_a = g_b$ 情形），无需稳定排序，无需额外比较键。
7. **n = 1**：直接 $p_0 + g_0$，公式自然覆盖，无需特判。
8. **ans 初值**：$p, g \ge 1$ 保证答案 $\ge 2$，初值 0 安全；但别把 `ans` 初始化成 `INT_MAX` 再取 min——方向是取 max。
