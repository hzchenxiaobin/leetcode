# LeetCode 最高频元素的频数 题解

## 1. 题目概述

- **标题 / 题号**：最高频元素的频数（#1838，medium）
- **链接**：https://leetcode.cn/problems/frequency-of-the-most-frequent-element/
- **来源**：LeetCode 第 238 场周赛 Q2
- **难度**：中等
- **标签**：排序、滑动窗口、前缀和、贪心

**题意**：给定整数数组 `nums` 和整数 `k`。每步操作可任选一个下标，将其元素值 **加 1**。最多执行 `k` 步操作后，返回数组中最高频元素的**最大可能频数**（即让尽可能多的元素取同一个值）。

**约束**：

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `1 <= k <= 10^5`

> 💡 读题抓三个信号：① 操作是**单向 +1**，元素只能变大——这决定了"归拢目标"必须取一组元素中的**最大值**（与可 ±1 的题取中位数截然不同）；② `n` 与 `k` 都是 `10^5` 级，`O(n²)` 枚举必超时，需要单调性把组合枚举压成线性扫描；③ 答案只关心**个数**不关心具体值，于是问题坍缩为"排序数组上找最长合法连续段"——滑动窗口信号拉满。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4], k = 5
输出：3
解释：对 1 执行 3 次操作、对 2 执行 2 次操作，得 [4,4,4]，频数 3。
```

**示例 2**

```text
输入：nums = [1,4,8,13], k = 5
输出：2
解释：预算只够把两个元素归拢：如 1→4（3 步）得 [4,4,8,13]，或 4→8（4 步）得 [1,8,8,13]，频数均为 2。
```

**示例 3**

```text
输入：nums = [3,9,6], k = 2
输出：1
解释：任何两个元素之间的差值都超过 2，预算无法归拢任何一对，频数只能为 1。
```

**补充示例**

```text
输入：nums = [5,5,5], k = 1
输出：3
解释：数组已经全部相同，代价恒为 0，一步操作都不用做，频数 3。
```

## 3. 解题思路

### 3.1 暴力思路：枚举"归拢目标"与"参与元素"

最终变成同一个值 `t` 的那组元素，加上目标值 `t`，共同决定了操作总数。朴素做法枚举每一对 `(t, 参与元素集合)`：固定 `t` 后，参与元素应贪心地从"值最接近 `t`"的那些里选（离 `t` 越近越便宜）。排序后这等价于枚举所有连续区间 `[l, r]` 并检查总代价——`O(n²)` 个区间，每个 `O(1)` 判代价，总量 `10^10`，必然超时。

> ⚠️ 痛点在"区间对"的组合爆炸：`(l, r)` 有 `n²` 组。突破口只能是**单调性**——让两个指针都只前进不后退，把 `n²` 压成 `n`。

### 3.2 核心观察：单向 +1 ⇒ 连续段抬到右端点

![核心观察：只能 +1，目标取段内最大值，最优解为排序后连续段](images/1838_freq_sort_window_concept.svg)

三个环环相扣的观察：

1. **目标取组内最大值**：+1 只能把元素变大，所以一组元素要变成同一个值 `t`，必须 `t ≥ 组内最大值`；而把 `t` 定得比最大值更高，每个元素都要多花同样的步数，频数不变、纯浪费。故最优 `t` 恰为组内最大值。
2. **排序后选连续段**：设排序后存在"跳着选"的方案——选了值小的边缘元素、却跳过了夹在中间的值大元素。把最左的小值换成被跳过的大值，代价只减不增（见 §5 引理 2）。直觉：**离目标近的元素更便宜，跳过便宜的选贵的不可能最优**。于是存在最优解，其选中元素是排序后的连续段 `[l, r]`，目标恰为右端点 `nums[r]`。
3. **代价 O(1) 可算**：把段 `[l, r]` 全部抬到 `nums[r]` 的代价为

$$cost(l, r) = \sum_{m=l}^{r} \big(nums[r] - nums[m]\big) = (r - l + 1) \cdot nums[r] - \sum_{m=l}^{r} nums[m]$$

   用窗口元素和（或前缀和）即可 `O(1)` 求出。

问题就此坍缩为：**在升序数组上找最长的窗口 `[l, r]`，使 `cost(l, r) ≤ k`**——标准的滑动窗口模型。

### 3.3 算法流程：双指针滑动窗口

![算法流程：排序后双指针滑动窗口，代价超 k 收缩左端](images/1838_freq_sliding_window_flow.svg)

单调性是滑窗的合法性依据（§5 引理 3）：固定 `r` 左移 `l` 代价不增、固定 `l` 右移 `r` 代价不减，因此两个指针都无需回头：

```text
1. 将 nums 升序排序
2. l = 0，维护窗口元素和 sum，ans = 0
3. r 逐格右移进窗（sum += nums[r]）：
     while nums[r] × (r − l + 1) − sum > k:
         sum −= nums[l]，l += 1        # 抛掉贡献最大的最左元素
     ans = max(ans, r − l + 1)
4. r 走完整个数组，返回 ans
```

### 3.4 示例演算

![示例演算：nums = [1,4,8,13], k = 5 滑窗全过程](images/1838_freq_walkthrough.svg)

以 `nums = [1, 4, 8, 13]`（已排序）、`k = 5` 为例：

| r | 进窗后窗口 | cost 计算 | 判定与动作 | ans |
|---|-----------|-----------|-----------|-----|
| 0 | `[1]` | $1 \times 1 - 1 = 0 \le 5$ | 直接合法 | 1 |
| 1 | `[1,4]` | $4 \times 2 - 5 = 3 \le 5$ | 直接合法 | 2 |
| 2 | `[1,4,8]` | $8 \times 3 - 13 = 11 > 5$ | 抛 `1` → `[4,8]`：$8 \times 2 - 12 = 4 \le 5$ | 2 |
| 3 | `[4,8,13]` | $13 \times 3 - 25 = 14 > 5$ | 抛 `4` → `[8,13]`：$13 \times 2 - 21 = 5 \le 5$ | 2 |

最终 `ans = 2`，与示例 2 一致 ✓。注意两处收缩都只抛了**一个**元素就恢复合法——这正是"最左元素贡献最大"的体现。

## 4. 算法细节

1. **排序的双重作用**：既让"选中组 = 连续段"成为可能（观察 2），又提供了滑窗所需的代价单调性（引理 3）。排序 `O(n log n)` 是全算法的复杂度瓶颈。
2. **代价的增量维护**：窗口扩张/收缩时同步增减 `sum`，代价判定保持 `O(1)`。等价写法是预处理前缀和数组 `prefix`，`cost(l, r) = (r-l+1)·nums[r] − (prefix[r+1] − prefix[l])`，空间换写法，二者复杂度相同。
3. **收缩从最左抛起**：窗口内 `nums[l]` 最小，离目标 `nums[r]` 最远，单个元素贡献 `nums[r] − nums[l]` 最大——抛它代价下降最快。由单调性，while 循环恰在恢复合法的瞬间停下，不会多抛。
4. **收缩不会越过 r**：单元素窗口 `cost(r, r) = 0 ≤ k`（`k ≥ 1`）恒合法，while 循环最多推进到 `l = r`，无需下标越界保护。
5. **溢出分析**：`nums[r] × (r−l+1)` 与 `sum` 均可达 $10^5 \times 10^5 = 10^{10}$，超出 32 位 `int` 上界（约 $2.1 \times 10^9$）——**C++ 必须全程用 `long long`**，这是本题最高频的 WA/RE 原因。Python 无此顾虑。
6. **二分替代方案**：由引理 3，固定 `r` 时 `cost(l, r)` 随 `l` 单调不增，可对每个 `r` 二分最小合法 `l`，总复杂度 $O(n \log n)$，与排序同阶。滑窗版少一个 $\log$ 且代码更短，推荐滑窗。

## 5. 正确性证明

**引理 1（目标取组内最大值）**：任何合法方案都可调整为"目标值等于选中组最大值"的合法方案，且频数不变、操作数不增。

**证明**：设方案把集合 $S$ 中每个元素变为 $t$。因操作只有 +1，须 $x \le t$ 对一切 $x \in S$ 成立，故 $t \ge \max(S)$；且每个 $x$ 至少需 $t - x$ 步（一步至多 +1），总操作数为 $\sum_{x \in S}(t - x)$。若 $t > \max(S)$，改目标为 $t' = \max(S)$：每个元素操作数减少 $t - t' > 0$，总操作数减少 $|S| \cdot (t - t')$，仍 $\le k$，频数 $|S|$ 不变。∎

**引理 2（连续段引理）**：存在最优方案，其选中元素是升序数组的连续段 $[l, r]$，目标值为 $nums[r]$。

**证明**：由引理 1 只需考虑 $t = \max(S)$ 的方案。设 $S$ 在升序数组中占据下标集 $P$，记 $l = \min P$、$r = \max P$，则 $t = nums[r]$。若 $(l, r)$ 内存在未选中的下标 $m$，则 $nums[l] \le nums[m] \le nums[r] = t$。用下标 $m$ 替换最左下标 $l$：代价变化 $(t - nums[m]) - (t - nums[l]) = nums[l] - nums[m] \le 0$，频数不变，且 $nums[m] \le t$ 保证操作数仍非负。替换后最小下标严格右移（移除的是最小者 $l$，加入的 $m > l$），$r$ 保持不变、$t = nums[r]$ 不变。最小下标严格递增且有界，至多 $n$ 次替换后 $(\min P, r)$ 内不再有未选中下标；此时 $P$ 中恰有 $|S|$ 个下标且无夹层，故 $P = [\min P, r]$ 是连续段，代价不增、频数不变、目标为 $nums[r]$。∎

**引理 3（代价公式与单调性）**：
(i) 把区间 $[l, r]$ 全部抬到 $nums[r]$ 的最少操作数为 $cost(l, r) = (r - l + 1) \cdot nums[r] - \sum_{m=l}^{r} nums[m]$；
(ii) 固定 $r$，$cost(l+1, r) - cost(l, r) = nums[l] - nums[r] \le 0$，即左端右移代价不增；
(iii) 固定 $l$，$cost(l, r+1) - cost(l, r) = (r - l + 1)(nums[r+1] - nums[r]) \ge 0$，即右端右移代价不减。

**证明**：(i) 元素 $nums[m]$ 至少需 $nums[r] - nums[m]$ 步且逐步 +1 恰可取到，求和后重组即得公式。(ii)(iii) 直接展开差式，符号由升序保证。∎

**定理**：滑动窗口算法返回最高频元素的最大可能频数。

**证明**：
（上界）每次更新 `ans` 前收缩循环已结束，窗口满足 $cost \le k$；由引理 3(i)，把该段全部抬到 $nums[r]$ 用不超过 $k$ 步即得频数 $r - l + 1$。故 `ans` 是可达频数，`ans ≤ OPT`。
（下界）由引理 2 取最优连续段 $[l_0, r_0]$，$cost(l_0, r_0) \le k$。先证断言：处理完每个 $r$ 后，左指针 $L_r$ 恰为 $l_{\min}(r) := \min\{l : cost(l, r) \le k\}$。由引理 3(ii)，合法左端集是后缀区间 $[l_{\min}(r), r]$，且 $cost(r, r) = 0$ 保证非空。归纳：$r = 0$ 时 $cost(0,0) = 0 \le k$，断言成立。设 $L_{r-1} = l_{\min}(r-1)$，进入第 $r$ 轮时若 $L_{r-1} > l_{\min}(r)$，则 $cost(L_{r-1} - 1, r) \le k$，由 (iii) 得 $cost(L_{r-1} - 1, r - 1) \le cost(L_{r-1} - 1, r) \le k$，即 $L_{r-1} - 1$ 是第 $r-1$ 轮的合法左端，与 $l_{\min}(r-1)$ 的最小性矛盾；故起点 $L_{r-1} \le l_{\min}(r)$。由 (ii)，while 循环按左端从小到大依次判定、恰停在第一个合法处，即 $L_r = l_{\min}(r)$。于是第 $r_0$ 轮窗口长 $r_0 - l_{\min}(r_0) + 1 \ge r_0 - l_0 + 1 = OPT$，得 `ans ≥ OPT`。
两向合并，`ans = OPT`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序占 $O(n \log n)$；滑动窗口部分，$r$ 与 $l$ 各自单调前进至多 $n$ 步，每步 `O(1)` 维护 `sum` 与判定，为 $O(n)$。总体由排序主导。
- **空间复杂度**：$O(1)$ 额外空间（双指针 + 滚动求和，不计排序的递归栈）。若采用前缀和数组写法则为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxFrequency(vector<int>& nums, int k) {
        sort(nums.begin(), nums.end());
        int n = nums.size(), ans = 0, l = 0;
        long long sum = 0;   // 窗口元素和，最大 1e10，必须 long long
        for (int r = 0; r < n; r++) {
            sum += nums[r];
            // 代价 = nums[r] * (r - l + 1) - sum > k 时收缩
            while ((long long)nums[r] * (r - l + 1) - sum > k) {
                sum -= nums[l];
                l++;
            }
            ans = max(ans, r - l + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxFrequency(self, nums: List[int], k: int) -> int:
        nums.sort()
        l, s, ans = 0, 0, 0
        for r, x in enumerate(nums):
            s += x
            while nums[r] * (r - l + 1) - s > k:
                s -= nums[l]
                l += 1
            ans = max(ans, r - l + 1)
        return ans
```

## 8. 边界情况与易错点

1. **C++ 溢出（头号坑）**：$nums[r] \times (r-l+1)$ 与 `sum` 最大 $10^{10}$，`int` 必炸。乘法两边至少一侧转 `long long`，仅把结果声明成 `long long` 而仍用 `int` 相乘同样会先溢出。
2. **全相同元素**：任意窗口 $cost = 0$，收缩循环永不触发，答案 `n`，代码天然覆盖，无需特判。
3. **k 很大**：窗口可一直扩张到整个数组，答案 `n`；`k ≥ 1` 保证单元素窗口恒合法，`l` 永不越过 `r`。
4. **单元素数组**：循环只跑一轮，答案 1。
5. **忘排序**：连续段引理与代价单调性全部失效，双指针逻辑彻底崩坏——先 `sort` 再谈别的。
6. **目标值取右端点而非中位数**：单向 +1 决定目标取**窗口最大值**；可 ±1 的题（如 2968）才取中位数。两题滑窗板子同构，判定公式不同，别背串。
7. **频数与元素值无关**：答案只数个数，"最终变成哪个值"根本不用输出，切勿在值域上做多余枚举。
