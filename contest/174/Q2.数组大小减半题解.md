# LeetCode 数组大小减半 题解

## 1. 题目概述

- **标题 / 题号**：数组大小减半（#1338，medium）
- **链接**：https://leetcode.cn/problems/reduce-array-size-to-the-half/
- **来源**：LeetCode 第 174 场周赛 Q2
- **难度**：中等
- **标签**：贪心，数组，哈希表，排序，堆（优先队列）

**题意**：给定整数数组 `arr`，选一个**整数集合** $S$，把 $S$ 里每个值在数组中的**所有出现**一次性删除。要求被删除的元素个数**至少**为 $\lvert arr\rvert/2$，求 $\lvert S\rvert$ 的最小值。

关键在于：选中值 $v$ 就等于删掉 $c_v$ 个元素（$c_v$ 是 $v$ 的出现次数）。删除量与值的**位置**、**数值大小**都无关，只看**频率**；删除总量就是所选值的频率之和。

**约束**：

- $2 \le \lvert arr \rvert \le 10^5$，且 $\lvert arr \rvert$ 为偶数，故「一半」恰好是整数 $n/2$
- $1 \le arr[i] \le 10^5$
- 答案一定存在：把所有不同值都选上就能删光整个数组

## 2. 示例

**示例 1**

```text
输入：arr = [3,3,3,3,5,5,5,2,2,7]
输出：2
解释：选 {3,7}，剩下的数组是 [5,5,5,2,2]，长度 5 = 原长度的一半。
      大小为 2 的可行集合还有 {3,5}、{3,2}；
      而 {2,7} 不可行，剩下 [3,3,3,3,5,5,5] 长度为 7 > 5。
```

**示例 2**

```text
输入：arr = [7,7,7,7,7,7]
输出：1
解释：只有一种值，选 {7} 后数组为空。
```

**示例 3**（补充，题面未给，用于覆盖「频率差距大 + 需要跨过阈值」的情形）

```text
输入：arr = [1,1,1,1,2,2,2,3,3,4]      n = 10，要删 ≥ 5
输出：2
解释：频率为 1:4、2:3、3:2、4:1。只选 1 个值最多删 4 < 5，不够；
      选 {1,2} 删 4 + 3 = 7 ≥ 5，所以答案是 2。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：枚举所有「值的子集」，对每个子集累加频率、检查是否 $\ge n/2$，取最小的可行子集大小。不同值最多 $10^5$ 个，子集数 $2^{m}$，指数级，完全不可行。

另一个常见的错解是**按值的大小或首次出现顺序**贪心。反例：`arr = [1,1,2,2,2,2]`（$n=6$，要删 3 个）。若先选先出现的 1（频率 2），还得再选 2，答案 2；而直接选 2（频率 4）一次就够，答案 1。可见贪心的关键字必须是**频率**，不能是数值或位置。

### 3.2 核心观察：按频率降序取「前 $k$ 大」

![按频率降序贪心，累加到跨过一半](images/wc174_q2_freq_greedy.svg)

设不同值共 $m$ 个，频率降序排列为 $c_1 \ge c_2 \ge \dots \ge c_m$，前缀和

$$F_k = c_1 + c_2 + \dots + c_k, \qquad F_0 = 0$$

两句观察就把问题锁死了：

1. **上界**：任取 $k$ 个值，删掉的元素数不超过「频率最大的 $k$ 个」之和，即 $D(S) \le F_k$——因为从 $\{c_i\}$ 里挑 $k$ 个不同的项，和最大就是挑前 $k$ 大。
2. **可达**：直接取前 $k$ 大频率对应的值，删掉的恰好是 $F_k$。

于是「$k$ 个值够不够」只取决于 $F_k \ge n/2$；而 $F_k$ 随 $k$ 单调不减（频率都是正数），所以答案是

$$k^{*} = \min\{\,k : F_k \ge n/2\,\}$$

这同时给出了贪心正确性的来源——**交换论证**：若某个最优集合里含有一个频率较小的值 $u$，而频率更大的值 $w$ 没被选中，把 $u$ 换成 $w$ 后删除量不会减少，集合大小不变且仍可行。反复交换，总能得到「取前 $k$ 大」形态的最优解。

### 3.3 算法流程

![计数、降序、贪心累加、判停](images/wc174_q2_greedy_flow.svg)

1. **计数**：遍历 `arr`，用哈希表（或值域数组）统计每个值的出现次数 `freq[v]`。
2. **降序**：把所有频率取出来降序排序，得到 $c_1 \ge c_2 \ge \dots \ge c_m$。
3. **贪心累加**：从最大的一份开始依次累加 `removed`，同时令 `k` 加一。
4. **判停**：一旦 `removed >= n/2` 立即返回 `k`；由于按降序累加，这个 `k` 正是 $k^*$。
5. 全部加完仍未停（不可能发生）时返回 $m$。

### 3.4 示例演算

![两个官方示例的走查表](images/wc174_q2_walkthrough.svg)

以示例 1 为例，$n = 10$，目标是删够 5 个：

| $k$ | 取的值 | 该值频率 | 累计删除 $F_k$ | 判断 |
| --- | --- | --- | --- | --- |
| 1 | 3 | 4 | 4 | $4 < 5$，继续 |
| 2 | 5 | 3 | 7 | $7 \ge 5$，返回 2 |

示例 2 中只有一种值，$F_1 = 6 \ge 3$，第一轮就返回 1。

## 4. 算法细节

1. **只保留频率，丢掉值本身**：判定只依赖频率的多重集 $\{c_i\}$，排序后原始值信息可以完全丢弃，也不需要记录「答案集合是哪些值」。
2. **计数优先用数组**：$arr[i] \le 10^5$，直接开 `vector<int> cnt(100001)` 计数，比 `unordered_map` 少一层哈希开销；若值域未知（负数、超过 $10^9$）再退回哈希表并 `reserve(n*2)`。
3. **判停用 `>=`**：题目是「至少删一半」，`removed == n/2` 时已满足，必须停；写成 `>` 会多选一个值。$n$ 为偶数时 `n/2` 与 `(n+1)/2` 相同，写后者对奇数长度也安全。
4. **提前返回**：按降序累加，第一次满足即返回，此时一定最小——前 $k-1$ 大连加起来都不够，任何 $k-1$ 元集合都不够（见 §5 引理 3）。
5. **可选的 $O(n + m)$ 桶排序**：频率一定落在 $[1, n]$ 内，用桶 `bucket[c]` 记录「频率为 $c$ 的值有几个」，再从 $c = n$ 递减扫描。一个桶里的值频率相同，可以用一次除法确定要吞掉几个，把排序的 $O(m \log m)$ 降成 $O(n + m)$：

```python
need = (n + 1) // 2                    # 目标是删掉 need 个元素
bucket = [0] * (n + 1)                 # bucket[c] = 频率恰好为 c 的值有几个
for c in freq.values():
    bucket[c] += 1
removed = k = 0
for c in range(n, 0, -1):              # 从频率最大的桶开始往下吞
    if bucket[c] == 0:
        continue
    take = min(bucket[c], -(-(need - removed) // c))   # 还差这么多，每个值只能删 c 个
    k += take
    removed += take * c
    if removed >= need:
        break
```

6. **堆写法**：把频率压进大顶堆，每轮弹一个最大值，复杂度 $O(n + k \log m)$；当 $k$ 接近 $m$（例如全部频率都是 1）时退化为 $O(n \log n)$，并不比排序好，只在「$k$ 小、$m$ 大」时略优。
7. **不要真的删除元素**：题目问的是集合大小，不是删除后的数组，模拟删除会把复杂度抬到 $O(nk)$。

## 5. 正确性证明

**引理 1（$k$ 元集合的删除上界）**：对任意满足 $\lvert S \rvert = k$ 的值集合 $S$，有 $D(S) = \sum_{v \in S} c_v \le F_k$。

**证明**：$S$ 含 $k$ 个不同的值，其频率是 $\{c_1, \dots, c_m\}$ 中 $k$ 个互不相同的项。把 $S$ 的频率降序记为 $d_1 \ge d_2 \ge \dots \ge d_k$，则第 $j$ 大的项 $d_j$ 不可能超过全局第 $j$ 大的 $c_j$（否则 $\{c_i\}$ 里至少有 $j$ 项 $\ge d_j > c_j$，与 $c_j$ 是第 $j$ 大矛盾）。逐项相加得 $D(S) = \sum_{j=1}^{k} d_j \le \sum_{j=1}^{k} c_j = F_k$。∎

**引理 2（前 $k$ 大可达上界）**：令 $S_k$ 为频率最大的 $k$ 个值构成的集合，则 $D(S_k) = F_k$。

**证明**：$S_k$ 恰好包含频率 $c_1, \dots, c_k$ 对应的值，删除量即 $c_1 + \dots + c_k = F_k$。∎

**引理 3（最小性）**：设 $k^{*} = \min\{\,k : F_k \ge n/2\,\}$（由 $F_0 = 0 < n/2$、$F_m = n \ge n/2$ 知 $k^{*}$ 存在且 $1 \le k^{*} \le m$），则不存在大小 $< k^{*}$ 的可行集合。

**证明**：反设存在 $\lvert S \rvert = k' < k^{*}$ 且 $D(S) \ge n/2$。由引理 1，$D(S) \le F_{k'}$，故 $F_{k'} \ge n/2$；但 $k' < k^{*}$ 与 $k^{*}$ 的定义（它是满足 $F_k \ge n/2$ 的最小下标）矛盾。∎

**定理**：算法返回的 `k` 等于 $k^{*}$，即题目所求的最小集合大小。

**证明**：算法沿降序累加，由归纳可知累加到第 $k$ 项时 `removed` 恰为 $F_k$（初始 $F_0 = 0$，每轮加 $c_k$）。它在第一个满足 $F_k \ge n/2$ 的 $k$ 处返回，正是 $k^{*}$。又由引理 2，$S_{k^{*}}$ 可行，故答案 $\le k^{*}$；由引理 3，答案 $\ge k^{*}$。两侧夹逼得答案 $= k^{*}$，与算法输出一致。∎

## 6. 复杂度分析

- **时间**：计数 $O(n)$；取出 $m$ 个频率 $O(m)$；降序排序 $O(m \log m)$，其中 $m \le n$；累加最坏 $O(m)$。合计 $O(n + m \log m)$，最坏 $O(n \log n)$，$n = 10^5$ 时约 $10^6$ 量级操作。若改用 §4.5 的桶实现，降为 $O(n + m)$。
- **空间**：计数结构 $O(V)$（$V = 10^5$，用哈希表则为 $O(m)$）；频率数组 $O(m)$。合计 $O(n + V)$，与输入同阶。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <functional>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    int minSetSize(vector<int>& arr) {
        int n = (int)arr.size();
        unordered_map<int, int> freq;            // 值 -> 出现次数
        freq.reserve((size_t)n * 2);             // 预留桶，避免反复 rehash
        for (int x : arr) ++freq[x];

        vector<int> f;                           // 只要频率，值的身份可以丢掉
        f.reserve(freq.size());
        for (auto& kv : freq) f.push_back(kv.second);
        sort(f.begin(), f.end(), greater<int>());  // 降序

        int need = (n + 1) / 2, removed = 0, k = 0;
        for (int c : f) {
            removed += c;
            ++k;
            if (removed >= need) break;          // 至少删掉一半就停
        }
        return k;
    }
};
```

### Python

```python
from collections import Counter


class Solution:
    def minSetSize(self, arr: list[int]) -> int:
        n = len(arr)
        need = (n + 1) // 2                      # n 为偶数时即 n/2
        removed = 0
        for k, c in enumerate(sorted(Counter(arr).values(), reverse=True), 1):
            removed += c
            if removed >= need:
                return k
        return 0                                 # 不会到达：全选必能删光
```

## 8. 边界情况与易错点

1. **全部元素相同**：如 `[7,7,7,7,7,7]`，答案是 1 而不是 0——必须选中这个值才能删掉元素。
2. **恰好等于一半**：`removed == n/2` 就该停，判断必须是 `>=`；示例 1 的 `{3,7}`（4 + 1 = 5）正是这种临界情形。
3. **`n = 2`**：两个数相同或不同，答案都是 1（删任意一个值都恰好删掉 $2/2 = 1$ 个元素）。
4. **不能按数值大小 / 首次出现顺序贪心**：`[1,1,2,2,2,2]` 的答案由频率更大的 2 决定，按顺序选会得到 2 而非 1。
5. **计数数组越界**：$arr[i]$ 最大 $10^5$，数组要开到 $10^5 + 1$；若为了省空间把值映射到 0 下标（`--arr[i]`），注意别在后续统计里把原数组算错。
6. **误以为可以「只删某个值的一部分」**：题目删除的是该值的**每次出现**，贡献固定为 $c_v$，这正是「按频率贪心」成立的前提。
7. **哈希表退化**：`unordered_map` 不 `reserve` 时，$10^5$ 次插入会触发多次 rehash，在 C++ 上容易 TLE；改用值域数组可以彻底避开。
