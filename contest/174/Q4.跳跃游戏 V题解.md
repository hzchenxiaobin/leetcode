# LeetCode 跳跃游戏 V 题解

## 1. 题目概述

- **标题 / 题号**：跳跃游戏 V（#1340，hard）
- **链接**：https://leetcode.cn/problems/jump-game-v/
- **来源**：LeetCode 第 174 场周赛 Q4
- **难度**：困难
- **标签**：数组，动态规划，排序

**题意**：给定整数数组 $arr$ 与步长上限 $d$。从下标 $i$ 可以跳到下标 $j$，当且仅当

1. $0 < \lvert i - j \rvert \le d$；
2. $arr[i] > arr[j]$，且 $i$ 与 $j$ 之间（不含两端）的每个下标 $k$ 都满足 $arr[i] > arr[k]$。

可以从任意下标起跳、连续跳任意多次，求一条路径最多能经过多少个下标。

**约束**：

- $1 \le arr.length \le 1000$
- $1 \le arr[i] \le 10^5$
- $1 \le d \le arr.length$

> 💡 第 2 条同时约束了**终点更矮**与**中途不挡路**，正是这两点把"能跳到谁"压成了一段连续窗口，也把整张跳转图变成了无环图。

## 2. 示例

**示例 1**

```text
输入：arr = [6,4,14,6,8,13,9,7,10,6,12], d = 2
输出：4
解释：从下标 10 出发，路径 10 → 8 → 6 → 7，对应值 12 → 10 → 9 → 7，共 4 个下标。
      从下标 6（值 9）出发只能到下标 7：下标 5 的值 13 比 9 大，跳不过去；
      而下标 5 又夹在 6 与 4 之间，所以下标 4 也永远到不了。
```

**示例 2**

```text
输入：arr = [3,3,3,3,3], d = 3
输出：1
解释：所有值相等，而跳跃要求严格变矮，于是任何下标都动不了，答案只能是 1。
```

**示例 3**

```text
输入：arr = [7,6,5,4,3,2,1], d = 1
输出：7
解释：从下标 0 出发，每次落到右边更矮的柱子上，可以走完 7 个下标。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是枚举所有点对 $(i, j)$，对每一对再花 $O(d)$ 扫描区间检查"中间是否都比 $arr[i]$ 矮"，在得到的合法边上求最长路：边数 $O(n^2)$，每条边 $O(d)$ 验证，总代价 $O(n^2 d)$，取 $n = d = 1000$ 就是 $10^9$ 量级，必然超时。

另一条"直接模拟"的路子更糟：从每个起点 DFS 枚举所有跳跃路径再取最长，路径条数在随机数据下随 $d$ 指数膨胀，完全没有可用上界。

**瓶颈在"验证一条边是否合法"上**——每对 $(i,j)$ 都重新扫一遍区间，把大量重复信息丢掉了。如果能证明"合法终点天然是连续的一段"，验证就能被扫描过程本身吸收掉。

### 3.2 核心观察：可达集合是一段连续窗口

![可达窗口：从 i 出发能落脚的位置是连续的一段](images/wc174_q4_reachable_window.svg)

**观察一（窗口性）**：固定 $i$，只看右侧。若存在 $k$ 满足 $i < k \le i + d$ 且 $arr[k] \ge arr[i]$，那么

- $k$ 本身不能落脚，因为不满足 $arr[i] > arr[k]$；
- $k$ 右侧任何 $j$（$k < j \le i+d$）也不能落脚，因为 $k$ 夹在 $i$ 与 $j$ 之间且不矮于 $arr[i]$，违反第 2 条。

也就是说：**右侧候选一定是从 $i+1$ 开始的一段前缀，撞到第一个 $arr[k] \ge arr[i]$ 就整体作废**；左侧完全对称。于是"枚举终点 + 检查区间"退化成每个方向一次线性扫描，$O(d)$ 就能吃干榨净。

**观察二（无环）**：每次跳跃都让高度严格下降，$arr$ 的值沿路径严格递减，所以同一下标不可能被重复访问，跳转图是 DAG，并且**按 $arr$ 升序就是它的拓扑序**：把下标由矮到高处理，计算 $dp[i]$ 时所有可能被引用的 $j$ 都已定稿。

$$dp[i] = 1 + \max\{\, dp[j] : j \text{ 可由 } i \text{ 一步到达} \,\}, \qquad ans = \max_{0 \le i < n} dp[i]$$

其中 $dp[i]$ 表示**以下标 $i$ 为起点**最多能访问的下标数（把 $i$ 自己算进去）。

### 3.3 算法流程 / 状态转移

![算法流程：升序处理 + 左右各一次截断扫描](images/wc174_q4_dp_flow.svg)

1. 令 $order$ 为全部下标按 $arr$ 升序排列的结果，$dp$ 数组初值全为 $1$。
2. 依次取出 $i \in order$（最矮的先处理）。
3. 向右扫 $j = i+1, \dots, \min(i+d, n-1)$：一旦 $arr[j] \ge arr[i]$ 立即 `break`，否则用 $dp[j]+1$ 更新 $dp[i]$。
4. 向左扫 $j = i-1, \dots, \max(i-d, 0)$：同样的截断规则、同样的更新。
5. 用 $dp[i]$ 更新全局答案 $ans$。
6. $order$ 处理完后输出 $ans$。

> 💡 也可以写成自顶向下的记忆化 DFS，状态转移是 $dp(i) = 1 + \max\{dp(j)\}$，其中 $j$ 取窗口内的位置。两者状态转移完全相同，只是拓扑序一个显式（排序）、一个隐式（递归回溯）；Python 里 $n = 1000$ 的严格递减数组会让递归深度达到 1000，需要额外抬高递归上限，因此正文代码采用迭代版。

### 3.4 示例演算

![示例 1 走查：dp 与最长路径](images/wc174_q4_walkthrough.svg)

以示例 1（$d = 2$）为例，按高度升序处理后得到：

| 下标 $i$ | $arr[i]$ | 窗口内可落脚的下标 $j$ | $dp[i]$ |
|----------|----------|------------------------|---------|
| 0 | 6 | 1 | 2 |
| 1 | 4 | 无 | 1 |
| 2 | 14 | 0, 1, 3, 4 | 3 |
| 3 | 6 | 无 | 1 |
| 4 | 8 | 3 | 2 |
| 5 | 13 | 3, 4, 6, 7 | 3 |
| 6 | 9 | 7 | 2 |
| 7 | 7 | 无 | 1 |
| 8 | 10 | 6, 7, 9 | 3 |
| 9 | 6 | 无 | 1 |
| 10 | 12 | 8, 9 | 4 |

最大值 $dp[10] = 4$，回溯路径 $10 \to 8 \to 6 \to 7$，对应值 $12 \to 10 \to 9 \to 7$。注意最高点 $arr[2] = 14$ 只有 $dp = 3$：它两侧确实都比它矮，但一步能踩到的最好邻居 $dp$ 仅为 2（$14 \to 8 \to 6$），高度优势并不等于路径优势。

## 4. 算法细节

1. **排序比较器要用严格小于**：比较函数写 $arr[a] < arr[b]$。值相等时二者之间不可能有跳跃（跳跃要求严格变矮），谁先谁后都不影响结果，不需要额外的下标次序做 tie-break。
2. **扫描顺序与短路**：每步先判越界（$j \ge n$ 或 $j < 0$）再判高度，两个条件都必须能 `break`——越界继续往后扫没有意义，高度挡住则后面全部作废。
3. **$dp$ 初值为 1 而非 0**：起跳点自身也算一个被访问的下标，初值写 0 会让全平数组返回 0。
4. **只允许严格下降**：必须 $arr[j] < arr[i]$ 才能落脚，若写成 $arr[j] \le arr[i]$ 放行等高的下标，就会互相可达，破坏无环性并让答案虚高。
5. **距离上界是闭区间**：$j \in [\max(0, i-d), \min(n-1, i+d)]$，下标差恰好等于 $d$ 时仍然合法，别写成 $\lvert i-j \rvert < d$。
6. **递归实现的坑**：自顶向下记忆化 DFS 的深度最坏为 $n = 1000$，Python 默认递归上限也是 1000，`[1000, 999, ..., 1]` 这类输入会直接 `RecursionError`；要么 `sys.setrecursionlimit(10000)`，要么像正文那样改成升序迭代。
7. **进阶做法（$n$ 很大时）**：用单调栈求出每个 $i$ 左右两侧"第一个 $\ge arr[i]$"的位置 $L_i, R_i$（不受 $d$ 限制），再把窗口截断为 $[\max(L_i, i-d), \min(R_i, i+d)]$，配合线段树查询区间 $dp$ 最大值，可把复杂度降到 $O(n \log n)$；本题 $n \le 1000$，$O(nd)$ 已经足够，不必上重武器。

## 5. 正确性证明

**引理 1（边刻画）**：从 $i$ 一步能到 $j$ $\iff$ $0 < \lvert i-j \rvert \le d$，且 $\min(i,j) < k < \max(i,j)$ 的所有 $k$ 满足 $arr[k] < arr[i]$，且 $arr[j] < arr[i]$。

**证明**：这正是题面两条规则的逐字翻译：第一条给出距离约束，第二条给出"终点更矮"与"中途都不挡路"。∎

**引理 2（截断不漏）**：向右扫描到第一个满足 $arr[k] \ge arr[i]$ 的 $k$ 就 `break`，不会漏掉任何合法终点。

**证明**：设 $k$ 是第一个不矮于 $arr[i]$ 的位置。对任意 $j > k$，由引理 1 需要 $arr[k] < arr[i]$，而 $arr[k] \ge arr[i]$，故 $j$ 不是合法终点；对任意 $i < j < k$，扫描过程完整访问了它。左侧同理。∎

**引理 3（拓扑序）**：按 $arr$ 升序处理下标时，计算 $dp[i]$ 所需的每个 $dp[j]$ 都已定稿。

**证明**：由引理 1，$j$ 合法蕴含 $arr[j] < arr[i]$，故 $j$ 在 $order$ 中排在 $i$ 之前，已被处理；而 $dp[j]$ 一旦写入就不再变化（后续处理只会读取它）。∎

**定理**：算法输出的 $ans$ 等于最长跳跃路径上的下标个数。

**证明**：先证"$dp[i] \le$ 真实最长值"：对处理顺序归纳。$dp[i]$ 的每个来源是 $1 + dp[j]$，由归纳假设 $dp[j]$ 对应一条从 $j$ 出发的真实路径，前置一步 $i \to j$ 后仍是合法路径（引理 1），故 $1 + dp[j]$ 不超过从 $i$ 出发的最长路径长度；取最大后结论成立。

再证"$dp[i] \ge$ 真实最长值"：设从 $i$ 出发的最长路径依次是 $i = i_0, i_1, \dots, i_m$，共 $m+1$ 个下标（高度严格递减故不重复）。由引理 2，$i_1$ 必在 $i$ 的扫描窗口内被访问到，故 $dp[i] \ge 1 + dp[i_1]$；对 $i_1$ 递归展开（每次跳转都严格变矮，递归必然终止），并用引理 3 保证每一层读到的是定稿值，累加得 $dp[i] \ge m+1$。两个方向合并，$dp[i]$ 恰为从 $i$ 出发的最长路径上的下标个数；$ans = \max_i dp[i]$ 即为全局答案。∎

## 6. 复杂度分析

- **时间**：$O(n \log n + n d)$。排序 $O(n \log n)$；每个下标左右各扫描至多 $d$ 步，单步 $O(1)$，合计 $O(nd)$。$n, d \le 1000$ 时总操作数约 $10^6$ 量级。
- **空间**：$O(n)$。$dp$ 数组与下标排序数组各占 $n$；迭代写法没有递归栈开销（记忆化 DFS 版额外占用最坏 $O(n)$ 的调用栈）。
- **与暴力对比**：暴力 $O(n^2 d)$ 约 $10^9$，本做法把"每对点都验证区间"降为"每个点只扫一遍自己的窗口"，降了一个 $n$ 的因子。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <numeric>
#include <vector>
using namespace std;

class Solution {
public:
    int maxJumps(vector<int>& arr, int d) {
        int n = arr.size();
        vector<int> idx(n), dp(n, 1);
        iota(idx.begin(), idx.end(), 0);
        // 按高度升序处理：所有可能的下一个落脚点（更矮）都已定稿
        sort(idx.begin(), idx.end(), [&](int a, int b) { return arr[a] < arr[b]; });

        int ans = 1;
        for (int id : idx) {
            for (int k = 1; k <= d && id + k < n; ++k) {   // 向右：越界即停
                if (arr[id + k] >= arr[id]) break;         // 撞到不矮的柱子：整体截断
                dp[id] = max(dp[id], dp[id + k] + 1);
            }
            for (int k = 1; k <= d && id - k >= 0; ++k) {  // 向左：规则对称
                if (arr[id - k] >= arr[id]) break;
                dp[id] = max(dp[id], dp[id - k] + 1);
            }
            ans = max(ans, dp[id]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxJumps(self, arr: list[int], d: int) -> int:
        n = len(arr)
        dp = [1] * n
        # 按高度升序处理，保证算 dp[i] 时所有更矮的位置都已定稿
        order = sorted(range(n), key=lambda i: arr[i])
        ans = 1
        for i in order:
            # 向右扫：只允许落在更矮的位置上，遇到不矮于 arr[i] 的立刻截断
            for j in range(i + 1, min(i + d + 1, n)):
                if arr[j] >= arr[i]:
                    break
                if dp[j] + 1 > dp[i]:
                    dp[i] = dp[j] + 1
            # 向左扫：同样的截断规则
            for j in range(i - 1, max(i - d - 1, -1), -1):
                if arr[j] >= arr[i]:
                    break
                if dp[j] + 1 > dp[i]:
                    dp[i] = dp[j] + 1
            ans = max(ans, dp[i])
        return ans
```

## 8. 边界情况与易错点

1. **长度为 1**：`arr = [66], d = 1` 只能待着不动，答案恒为 1，循环一次都不会进入内层扫描。
2. **全部相等**：`[3,3,3,3,3]` 中任何一对都不满足严格变矮，答案 1；若把落脚条件放宽成 $arr[j] \le arr[i]$，等高的下标就会互相可达，跳转图出现环，"升序即拓扑序"的前提失效，这类输入会给出大于 1 的错误答案。
3. **单调递减 + $d = 1$**：`[7,6,5,4,3,2,1]` 答案 7，是"一路走到底"的极端，用来检验距离上界是否被写成开区间 $\lvert i-j \rvert < d$——那样一步都跳不出去，答案会退化成 1。
4. **中间挡路的柱子**：示例 1 中 $arr[6] = 9$ 不能跳到 $arr[4] = 8$，因为中间的下标 5 值为 13；这类"终点更矮但中途被挡"的情况最容易在只检查端点高度时漏判。
5. **窄窗口与宽窗口**：$d = 1$ 时窗口只有相邻下标，$d = n$ 时窗口被两侧边界截断，两者的循环边界都要能正常退出，不要写出负数下标。
6. **递归深度**：自顶向下写法在严格递减数组上深度可达 $n = 1000$，Python 默认递归上限 1000 会抛 `RecursionError`，务必改迭代或抬高上限。
7. **排序稳定性无影响**：等值下标之间不存在合法跳跃，所以 $arr[a] = arr[b]$ 时不需要任何 tie-break，不要为此引入下标比较而破坏"升序即拓扑序"的前提。
