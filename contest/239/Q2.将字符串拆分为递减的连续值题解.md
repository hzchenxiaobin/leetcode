# LeetCode 将字符串拆分为递减的连续值 题解

## 1. 题目概述

- **标题 / 题号**：将字符串拆分为递减的连续值（#1849，medium）
- **链接**：https://leetcode.cn/problems/splitting-a-string-into-descending-consecutive-values/
- **来源**：LeetCode 第 239 场周赛 Q2
- **难度**：中等
- **标签**：字符串、回溯、枚举

**题意**：给定仅由数字组成的字符串 `s`，判断能否将其拆分成**两个或更多**非空子串，使各子串的**数值**按降序排列，且每两个相邻子串的数值之**差恰好等于 1**。例如 `"0090089"` 可拆成 `["0090","089"]`，数值为 `[90,89]`，可行；而 `"001"` 的所有拆分（`[0,1]`、`[0,1]`、`[0,0,1]`）都不降序，不可行。

**约束**：

- $1 \le s.\text{length} \le 20$
- `s` 仅由数字组成

> 💡 **审题关键**：三处细节决定成败——①比较的是**数值**而非字典序，且数值允许**前导零**（`"099"` 的数值是 99，`"00"` 的数值是 0）；②差**恰好为 1** 且降序，即后一段数值必须等于前一段减 1，升序（如 `"1234"`）或差为其他值都不行；③至少**两段**，整串不切（1 段）不算拆分。

## 3. 解题思路

### 3.1 朴素思路：枚举全部切分方案

字符串有 $n-1$ 个缝隙，每个缝隙切或不切，共 $2^{n-1}$ 种划分。对每种划分逐段转成数值，检查「段数 $\ge 2$、相邻差恰为 1 且降序」。$n \le 20$ 时 $2^{19} \approx 5 \times 10^5$ 种、每种 $O(n)$ 解析，总计约 $10^7$ 次操作，比赛时能过。但 C++ 里 19 位的子串数值超出 `long long` 范围（如 20 个 `'9'`），要么按长度特判要么上大数，代码不干净；更重要的是这种做法**完全没利用题面结构**。

### 3.2 核心观察：首段确定整条链

![核心观察：首段数值确定整条链](images/wc239_q2_chain_determined_concept.svg)

**关键观察**：相邻差恰好为 1 且降序，意味着一旦首段数值为 $v$，后续每段的数值就被**唯一确定**：第 $k$ 段必须是 $v-(k-1)$。不是「满足某种性质」，而是**精确等于这个数**。

于是问题从「枚举指数级切分方案」坍缩为两步：

1. 枚举首段的终点（至多 $n-1$ 种），得到首段数值 $v$；
2. 在剩余串中**精确匹配** $v-1$，再匹配 $v-2$，……直到串尾。

**前导零带来回溯分支**：同一起点处 `"0"`、`"00"`、`"000"` 的数值都是 0——同一个期望值可能对应**多个终点**，一个失败还要试更长的。这正是回溯的用武之地：定义 `dfs(pos, expect)` 表示「从下标 `pos` 起，期望拼出数值 `expect`、`expect−1`、……直到串尾」。

**单调性剪枝**：固定起点逐位累加 `val = 10 × val + digit`，`val` 随终点推移单调不减（只有前导零会让它停滞在 0；一旦非零便严格递增）。所以一旦 `val > expect`，再延长只会更大，立即 `break`。特别地，首段数值为 0 时 `expect = -1`，任何非负 `val` 都大于它——扫第一个字符就剪掉，负数期望天然无解。

### 3.3 算法流程

![回溯算法流程：枚举首段 + 按期望值逐段精确匹配](images/wc239_q2_backtrack_flow.svg)

1. 外层枚举首段终点 `end`（$0 \le \text{end} \le n-2$，保证首段后至少还剩 1 个字符），增量累加首段数值 `first`；
2. 若 `first ≥ 10^10`，直接 `break`（引理 2：合法拆分的首段到不了这个量级，兼作 C++ 溢出防护）；
3. 调用 `dfs(end+1, first−1)`：期望下一段数值为 `first−1`；
4. `dfs(pos, expect)`：若 `pos == n`，返回 `true`——整串被链**恰好**覆盖；
5. 否则从 `pos` 起逐位累加 `val`，每到一个终点：
   - `val == expect` → 递归 `dfs(end+1, expect−1)`，成功即 `true`；**失败不返回、继续尝试更长终点**（前导零同值多写法）；
   - `val > expect` → `break`（单调剪枝）；
6. 某层所有终点都失败 → 返回 `false`，回溯到上一层；所有首段都失败 → 答案为 `false`。

### 3.4 示例演算

![示例演算：s = 10009998 的三次首段尝试与回溯](images/wc239_q2_example_walkthrough.svg)

以示例 4 `s = "10009998"` 走查（下表「匹配」列给出从剩余串起点逐位累加的过程）：

| 首段 | v / expect | 匹配过程 | 结果 |
|------|------------|----------|------|
| `"1"` | 1 / 0 | `"0"`、`"00"`、`"000"` 均等于 0 ✓，但下层 expect = −1 无解 ✗；`"0009"` = 9 > 0 剪枝 | ✗ |
| `"10"` | 10 / 9 | `"009"` = 9 ✓，下层 expect = 8：`"9"` = 9 > 8 ✗；回溯同层延长：`"0099"` = 99 > 9 剪枝 | ✗ |
| `"100"` | 100 / 99 | `"099"` = 99 ✓ → 下层 expect = 98：`"98"` = 98 ✓ → 到串尾 | ✓ |

成功拆分为 `["100", "099", "98"]`，数值 `[100, 99, 98]`。前两次失败都死在「下一层接不上」：先在**同层**试更长终点（前导零），全部失败后**回溯到外层**换首段终点——这正是回溯的两层含义。示例 2 `"050043"` 同理：首段 `"0"`、`"05"` 的前缀尝试中，`"05"` = 5 → 匹配 `"004"` = 4 → 匹配 `"3"` = 3 → 串尾，得 `["05","004","3"]`。

## 4. 算法细节

1. **状态设计**：`dfs(pos, expect)`——从下标 `pos` 起，期望下一段数值为 `expect`，其后按 `expect−1`、`expect−2` 递推直到串尾；返回能否匹配成功。期望值把「整条链的剩余部分」压缩成了一个参数。
2. **外层枚举**：首段终点 `end` 上界为 $n-2$（`end + 1 < n`），天然保证「至少两段」；首段数值用 `first = first × 10 + digit` 增量维护，避免反复调用转字符串接口。
3. **匹配与分支**：`dfs` 内从 `pos` 逐位累加 `val`；每到一处终点，`val == expect` 才递归 `dfs(end+1, expect−1)`——成功立即向上传播 `true`，**失败则继续循环尝试更长终点**；`val > expect` 立即 `break`。
4. **终止判定**：`pos == n` 返回 `true`，这是「整串恰好匹配完」的唯一判定点；配合外层 `end ≤ n−2`，同时保证段数 $\ge 2$。
5. **C++ 防溢出**：由引理 2，合法拆分中首段数值 $< 10^{10}$，链上所有数值亦然；外层累加一旦 $\ge 10^{10}$ 即 `break`（首段只增不减，不会漏解）。此后 `dfs` 中 `val ≤ 10 \times \text{expect} + 9 < 10^{11}$，全程安全落在 `long long` 范围内。Python 无此顾虑。

## 5. 正确性证明

**引理 1（首段确定整条链）**：设 $a_1, a_2, \dots, a_m$（$m \ge 2$）为任一合法拆分各段的数值，则 $a_k = a_1 - (k-1)$ 对所有 $1 \le k \le m$ 成立。

**证明**：合法拆分要求相邻数值降序且差恰为 1，即 $a_{k+1} = a_k - 1$（$1 \le k < m$）。对 $k$ 归纳：$k=1$ 平凡；若 $a_k = a_1-(k-1)$，则 $a_{k+1} = a_k - 1 = a_1 - k$。∎

**引理 2（首段长度上界）**：任何合法拆分中，首段的位数 $L \le 10$，即首段数值 $< 10^{10}$。

**证明**：$L = 1$ 时首段数值 $\le 9 < 10^{10}$，结论成立。设 $L \ge 2$：首段数值 $v \ge 10^{L-1}$，故第二段数值 $v - 1 \ge 10^{L-1} - 1 \ge 10^{L-2}$，即第二段（写上任意前导零也）至少需要 $L-1$ 个字符。于是总长 $n \ge L + (L-1) = 2L-1$。若 $L \ge 11$，则 $n \ge 21 > 20$，与 $n \le 20$ 矛盾。∎

> 💡 引理 2 同时是 C++ 实现的**溢出防护**依据：链上所有数值 $< 10^{10}$、累加中间量 $< 10^{11}$，`long long` 绰绰有余。

**定理（算法正确性）**：`splitString(s)` 返回 `true` 当且仅当 `s` 存在合法拆分。

**证明**：

（**可靠性**）设算法返回 `true`，考察对应的那条成功递归路径：外层选中首段 $s[0..e_1)$，数值为 `first`；此后每一步都在 `val == expect` 时才递归，即第 $k$ 段的数值恰为 $\text{first}-(k-1)$；终止于 `pos == n` 说明这些段首尾相接、恰好覆盖整串。由外层 $e_1 \le n-2$ 知首段后至少还有一个字符，故段数 $\ge 2$；相邻数值差恰为 1 且严格递减。故这是一份合法拆分。

（**完备性**）设存在合法拆分，段边界为 $0 = e_0 < e_1 < \dots < e_m = n$（$m \ge 2$），各段数值由引理 1 为 $v_k = v_1 - (k-1)$。外层枚举到 $e_1$ 时构造出同一首段数值（数值由子串内容唯一决定），调用 `dfs(e_1, v_1 - 1)`。归纳设算法处于 `dfs(e_{k-1}, v_k)`：从 $e_{k-1}$ 逐位累加，累加值在终点 $e_k$ 处恰为子串 $s[e_{k-1}..e_k)$ 的数值 $v_k$，触发 `val == expect` 并递归进入 `dfs(e_k, v_{k+1})`。累加过程不会在 $e_k$ 之前因 `val > expect` 提前 `break`：对 $e < e_k$，$s[e_{k-1}..e)$ 是整段的前缀，其数值不超过整段数值（整段 = 前缀 $\times 10^{r}$ + 后缀 $\ge$ 前缀，$r \ge 1$）。最终递归进入 `dfs(e_m, ·) = dfs(n, ·)`，返回 `true`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^3)$（宽松上界，$n \le 20$ 时至多数千次基本操作）。外层 $n-1$ 个首段；每个首段的搜索树中，`expect ≥ 1` 的结点至多有一个「有效孩子」——`val` 一旦非零便严格递增，同值多终点只可能出现在 `expect = 0` 的前导零停滞处，而其子层期望为 $-1$、扫一个字符即失败。因此有效结点数 $O(n^2)$（路径上 `pos` 严格递增），每个结点扫描 $O(n)$。
- **空间复杂度**：$O(n)$。递归深度不超过 $n$（每段至少消耗 1 个字符），只额外维护 `first`、`val` 等常数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool splitString(string s) {
        int n = s.size();
        long long first = 0;
        for (int end = 0; end + 1 < n; ++end) {      // 给后面至少留 1 个字符 → 至少两段
            first = first * 10 + (s[end] - '0');
            if (first >= 10000000000LL) break;        // 引理 2：合法首段 < 10^10，兼防溢出
            if (dfs(s, end + 1, first - 1)) return true;
        }
        return false;
    }

private:
    // 从 pos 起，期望拼出 expect、expect-1、… 直到串尾
    bool dfs(const string& s, int pos, long long expect) {
        if (pos == (int)s.size()) return true;        // 整串恰好匹配完
        long long val = 0;
        for (int end = pos; end < (int)s.size(); ++end) {
            val = val * 10 + (s[end] - '0');
            if (val == expect && dfs(s, end + 1, expect - 1)) return true;
            if (val > expect) break;                  // val 单调不减，后面只会更大
            // val == expect 但递归失败：不 break，继续尝试更长终点（前导零）
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def splitString(self, s: str) -> bool:
        n = len(s)

        def dfs(pos: int, expect: int) -> bool:
            if pos == n:
                return True                           # 整串恰好匹配完
            val = 0
            for end in range(pos, n):
                val = val * 10 + int(s[end])
                if val == expect and dfs(end + 1, expect - 1):
                    return True
                if val > expect:                      # 单调剪枝
                    break
                # val == expect 但递归失败：继续尝试更长终点（前导零）
            return False

        first = 0
        for end in range(n - 1):                      # 至少留 1 个字符 → 至少两段
            first = first * 10 + int(s[end])
            if dfs(end + 1, first - 1):
                return True
        return False
```

## 8. 边界情况与易错点

1. **前导零多终点**：`val == expect` 递归失败后**必须继续循环**尝试更长终点。如 `s = "100"`：首段 `"1"`、expect = 0 时，`"0"` 失败后还要试 `"00"` 才能成功（`[1, 0]`）。若把 `==` 失败也当作 `break`，会错判 `false`。⚠️ 本题最大的坑。
2. **至少两段**：外层 `end` 上界取 $n-2$（`end + 1 < n`）；$n = 1$ 时循环不执行，直接 `false`。
3. **首段数值为 0**：`expect = -1` 为负，任何非负 `val` 都大于它 → 首字符即 `break`，天然剪枝，无需特判。
4. **C++ 溢出**：朴素做法里 19 位子串数值超出 `long long`（如 20 个 `'9'`，有符号溢出是 UB）。本解法由引理 2 在 $10^{10}$ 处剪枝，所有数值与中间量均安全。
5. **终止条件别漏**：`pos == n` 返回 `true` 是「整串恰好匹配完」的唯一判定点；漏写则最后一段永远无法确认，`"050043"` 这类答案会被错判。
6. **比较的是数值不是字典序**：`"0090089"` 拆成 `["0090","089"]` 数值 `[90,89]` 合法；若按字符串比较，`"089" < "0090"` 会得出相反结论。
