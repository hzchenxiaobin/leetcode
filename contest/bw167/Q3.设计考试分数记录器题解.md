# LeetCode 设计考试分数记录器 题解

## 1. 题目概述

- **标题 / 题号**：设计考试分数记录器（#3709，medium）
- **链接**：https://leetcode.cn/problems/design-exam-scores-tracker/
- **来源**：LeetCode 第 167 场双周赛 Q3
- **难度**：中等
- **标签**：设计、数组、二分查找、前缀和

**题意**：实现 `ExamTracker` 类：

- `ExamTracker()`：初始化对象；
- `void record(int time, int score)`：Alice 在时刻 `time` 参加了一场考试，得分 `score`；
- `long long totalScore(int startTime, int endTime)`：返回时刻落在 $[startTime, endTime]$（闭区间）内的所有考试得分**之和**；区间内没有考试则返回 0。

**保证**：

- `record` 的调用按 `time` **严格递增**；
- 每次 `totalScore(startTime, endTime)` 都满足 $startTime \le endTime \le t$，其中 $t$ 是最近一次 `record` 的时刻（即不会查询未来）；
- 第一次调用一定是 `record`；
- 总调用次数不超过 $10^5$。

**约束**：

- $1 \le time \le 10^9$，$1 \le score \le 10^9$
- $1 \le startTime \le endTime \le t$
- 对 `record` 与 `totalScore` 的总调用次数 $\le 10^5$

## 2. 示例

**示例 1**

```text
输入：
["ExamTracker","record","totalScore","record","totalScore","totalScore","totalScore","totalScore"]
[[],[1,98],[1,1],[5,99],[1,3],[1,5],[3,4],[2,5]]
输出：
[null,null,98,null,98,197,0,99]

解释：
record(1, 98)
totalScore(1, 1) → 时刻 1 的 98 分            → 98
record(5, 99)
totalScore(1, 3) → 只有时刻 1 的考试          → 98
totalScore(1, 5) → 时刻 1 与 5 两场            → 98 + 99 = 197
totalScore(3, 4) → 区间内没有考试              → 0
totalScore(2, 5) → 只有时刻 5 的考试           → 99
```

**示例 2（补充例子）**

```text
输入：
["ExamTracker","record","record","record","totalScore","totalScore"]
[[],[2,10],[4,20],[6,30],[2,6],[5,6]]
输出：
[null,null,null,null,60,30]

解释：三次记录后，totalScore(2,6) 覆盖全部三场 = 60；totalScore(5,6) 只含时刻 6 的 30 分。
```

## 3. 解题思路

### 3.1 暴力思路

用一个数组按顺序存下所有 $(time, score)$。每次 `totalScore(startTime, endTime)` 时从头到尾扫一遍，把时间落在区间内的分数累加。单次查询 $O(m)$（$m$ 为已有记录数），总复杂度 $O(Q \cdot R) = O(10^{10})$，$10^5$ 次调用下必然超时。

### 3.2 核心观察：时间严格递增 ⇒ 已存记录天然有序

![记录天然按时间有序，前缀和让区间求和变成一次减法](images/bw167_q3_prefix_and_binary_search.svg)

题目保证 `record` 按 `time` **严格递增**调用，这带来两个直接好处：

1. **无需排序、无需插入**：新记录总是追加到末尾，`times` 数组永久有序；
2. **区间查询 = 两次二分 + 一次减法**：设 `times[0..m-1]` 递增、`pref[0..m]` 为前缀和（`pref[i]` = 前 $i$ 场总分），则时刻落在 $[startTime, endTime]$ 内的记录恰为下标区间 $[l, r)$，其中

$$l = \operatorname{lower\_bound}(times, startTime), \qquad r = \operatorname{upper\_bound}(times, endTime),$$

答案为 `pref[r] - pref[l]`。若 $l = r$ 说明区间内没有考试，减法自然给出 0。

注意 $r$ 用 **upper_bound**（第一个 $> endTime$ 的位置）而不是 lower_bound，因为区间是**闭区间**：时间恰为 `endTime` 的考试必须计入。

![二分定位：l 用 lower_bound，r 用 upper_bound](images/bw167_q3_bisect_boundaries.svg)

### 3.3 算法流程

```text
record(time, score):
    times.append(time)
    pref.append(pref.back() + score)      // pref 长度 = times 长度 + 1

totalScore(startTime, endTime):
    l = lower_bound(times, startTime)     // 第一个 >= startTime 的位置
    r = upper_bound(times, endTime)       // 第一个 >  endTime  的位置
    return pref[r] - pref[l]
```

两个操作分别是 $O(1)$（均摊）与 $O(\log m)$，总复杂度 $O((R + Q)\log R)$，其中 $R$ 是 `record` 次数、$Q$ 是 `totalScore` 次数。

### 3.4 示例演算

![示例 1 的调用过程与二分结果](images/bw167_q3_example_walkthrough.svg)

按示例 1 的调用顺序：

| 步骤 | 操作 | `times` | `pref` | 查询区间 $[l, r)$ | 返回 |
|------|------|---------|--------|--------------------|------|
| 1 | record(1, 98) | [1] | [0, 98] | — | null |
| 2 | totalScore(1, 1) | [1] | [0, 98] | $l=0, r=1$ | 98 − 0 = **98** |
| 3 | record(5, 99) | [1, 5] | [0, 98, 197] | — | null |
| 4 | totalScore(1, 3) | [1, 5] | [0, 98, 197] | $l=0, r=1$ | 98 − 0 = **98** |
| 5 | totalScore(1, 5) | [1, 5] | [0, 98, 197] | $l=0, r=2$ | 197 − 0 = **197** |
| 6 | totalScore(3, 4) | [1, 5] | [0, 98, 197] | $l=1, r=1$ | 98 − 98 = **0** |
| 7 | totalScore(2, 5) | [1, 5] | [0, 98, 197] | $l=1, r=2$ | 197 − 98 = **99** |

与题面输出 `[null,null,98,null,98,197,0,99]` 完全一致。

## 4. 算法细节

1. **前缀和数组的长度**：`pref` 比 `times` 多一个元素，`pref[0] = 0`，这样 `pref[r] - pref[l]` 对任意 $0 \le l \le r \le m$ 都成立，无需特判。
2. **`long long` 必不可少**：单场最高 $10^9$，$10^5$ 场总和可达 $10^{14}$，超出 `int`。C++ 用 `long long` 存 `pref`，Python 自动大整数。
3. **`lower_bound` 与 `upper_bound` 都要用**：前者定位左端点（含），后者定位右端点（不含）。若两个都用 `lower_bound`，会漏掉恰好在 `endTime` 的考试。
4. **不需要处理乱序插入**：题面保证严格递增；若改写成允许乱序，就要用 `map` 或 `vector` 插入 + 树状数组，复杂度会上升。
5. **空查询**：$l = r$ 时返回 0，公式自动成立，不必单独判。
6. **`record` 的时刻不重复**：严格递增保证二分无歧义。
7. **可以只存一个数组**：把 $(time, score)$ 打包成 `pair` 数组 + 惰性前缀和也行，但双数组最直观。

## 5. 正确性证明

**引理 1（有序性）**：任意时刻 `times[0..m-1]` 严格递增。

**证明**：初始为空；每次 `record` 追加的 `time` 严格大于此前所有 `time`（题面保证），故递增性保持。∎

**引理 2（下标区间刻画）**：设 $l = \operatorname{lower\_bound}(times, startTime)$、$r = \operatorname{upper\_bound}(times, endTime)$，则时刻落在 $[startTime, endTime]$ 内的记录集合恰为下标 $l, l+1, \dots, r-1$。

**证明**：由引理 1，`times` 递增。$l$ 是第一个满足 $times[i] \ge startTime$ 的下标，故 $i \ge l \iff times[i] \ge startTime$；$r$ 是第一个满足 $times[i] > endTime$ 的下标，故 $i < r \iff times[i] \le endTime$。两者合取即 $startTime \le times[i] \le endTime$。∎

**引理 3（前缀和公式）**：`pref[i]` 等于前 $i$ 场考试的得分之和，且对 $0 \le l \le r \le m$ 有 `pref[r] - pref[l]` 等于下标 $[l, r)$ 内得分之和。

**证明**：归纳：`pref[0] = 0`；每次 `record` 令 `pref[m+1] = pref[m] + score`，即前缀和定义。相减得 $\sum_{i=l}^{r-1} score_i$。∎

**定理**：`totalScore(startTime, endTime)` 返回时刻在 $[startTime, endTime]$ 内的所有考试得分之和。

**证明**：由引理 2，满足时间条件的记录恰为下标 $[l, r)$；由引理 3，`pref[r] - pref[l]` 正是这些记录的得分之和。若区间内无记录则 $l = r$，和为 0。∎

## 6. 复杂度分析

- **`record`**：$O(1)$。两次 `push_back`。
- **`totalScore`**：$O(\log m)$。两次二分查找，$m$ 为当前记录数。
- **总计**：$R$ 次 `record` 与 $Q$ 次 `totalScore` 共 $O(R + Q \log R)$；$R, Q \le 10^5$ 时约 $1.7 \times 10^6$ 次操作。
- **空间**：$O(R)$。`times` 与 `pref` 各存 $R$ 或 $R+1$ 个 64 位整数。

## 7. 参考代码

### C++

```cpp
class ExamTracker {
    vector<long long> times;
    vector<long long> pref;

public:
    ExamTracker() {
        pref.push_back(0);
    }

    void record(int time, int score) {
        times.push_back(time);
        pref.push_back(pref.back() + score);
    }

    long long totalScore(int startTime, int endTime) {
        int l = (int)(lower_bound(times.begin(), times.end(), (long long)startTime) - times.begin());
        int r = (int)(upper_bound(times.begin(), times.end(), (long long)endTime) - times.begin());
        return pref[r] - pref[l];
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right

class ExamTracker:
    def __init__(self):
        self.times = []
        self.pref = [0]

    def record(self, time: int, score: int) -> None:
        self.times.append(time)
        self.pref.append(self.pref[-1] + score)

    def totalScore(self, startTime: int, endTime: int) -> int:
        l = bisect_left(self.times, startTime)
        r = bisect_right(self.times, endTime)
        return self.pref[r] - self.pref[l]
```

## 8. 边界情况与易错点

1. **`upper_bound` 写成 `lower_bound`**：会漏掉时间恰好等于 `endTime` 的那场考试（示例 1 第 5 步会得 98 而不是 197）。
2. **`int` 溢出**：$10^5 \times 10^9 = 10^{14}$，必须 `long long`；示例 1 数值小看不出问题，但评测里必然有大和。
3. **`pref` 少一个元素**：若 `pref` 与 `times` 等长，`pref[r]` 在 $r = m$ 时越界；记得初始化 `pref = [0]`。
4. **查询区间为空**：$l = r$ 时返回 0，公式自然成立，不要写成「返回 -1」。
5. **时刻很大**：`time` 到 $10^9$，但只是下标比较，不参与寻址，`long long` 存即可。
6. **第一次调用必为 `record`**：所以 `times` 不会为空；即使为空，二分也会返回 0，`pref[0]-pref[0]=0` 依然安全。
7. **Python 的 `bisect` 参数**：`bisect_left(a, x)` 返回第一个 $\ge x$ 的位置，`bisect_right(a, x)` 返回第一个 $> x$ 的位置，正好对应闭区间。
