# LeetCode 用栈操作构建数组 题解

## 1. 题目概述

- **标题 / 题号**：用栈操作构建数组（#1441，medium）
- **链接**：https://leetcode.cn/problems/build-an-array-with-stack-operations/
- **来源**：LeetCode 第 188 场周赛 Q1
- **难度**：中等
- **标签**：栈、数组、模拟

**题意**：有一个从 $1$ 到 $n$ 依次到来的整数流，和一个初始为空的栈；只允许两种操作——`"Push"`（读入流中下一个整数并压栈）与 `"Pop"`（弹出栈顶）。规则是：流不空就能读下一个数压栈，栈不空就能弹栈顶；**一旦某一刻栈内元素（从底到顶）恰好等于 `target`，立刻停止**，既不读新数也不再操作。要求返回构造出 `target` 的操作序列，多解时返回任意一个。

**约束**：

- $1 \le \text{target.length} \le 100$
- $1 \le n \le 100$
- $1 \le \text{target}[i] \le n$
- `target` **严格递增**

> 💡 一句话定位：乍看像「用栈凑序列」的搜索题，实际上规则把自由度压成了零——每个数读进来之后留不留，完全由「它是否等于下一个待构造的目标」决定，签到题的全部难度就在识破这一点。

## 2. 示例

**示例 1**

```text
输入：target = [1,3], n = 3
输出：["Push","Push","Pop","Push"]
解释：读 1 → 栈 [1]；读 2 → 栈 [1,2]，2 不是目标 → Pop 成 [1]；
      读 3 → 栈 [1,3]，等于 target，停止。
```

**示例 2**

```text
输入：target = [1,2,3], n = 3
输出：["Push","Push","Push"]
解释：三个数连续命中目标，全程不需要任何 Pop。
```

**示例 3**

```text
输入：target = [1,2], n = 4
输出：["Push","Push"]
解释：两次 Push 后栈已等于 target，必须立刻停止；
      若继续读 3（哪怕读后立刻 Pop），这个答案就不合法。
```

## 3. 解题思路

### 3.1 暴力思路：搜索所有操作序列

把「Push / Pop」看成深度无限的决策树：每个状态（流指针 + 栈内容）都能分出两条边，搜到「栈等于 target」为止。合法序列的空隙里还夹着无数「压入再弹掉」的无效动作，搜索树几乎无穷，且大部分分支连正确性的边都摸不到。

更关键的是：**搜索空间其实是退化的**。读入顺序被流锁死（只能 $1, 2, 3, \dots$ 依次读），一个数「留还是丢」由它是否属于 `target` 唯一决定，唯一能自由安排的只有「丢弃时的 `Pop` 什么时候执行」——而这一点既不影响正确性，也不影响总操作数（引理 1）。所以暴力搜索不仅慢，方向也是错的：该做的是**把被迫的流程写出来**。

### 3.2 核心观察：不想留的数必定「Push 一次 + Pop 一次」

![核心观察：target 内的数保留，其余数 Push + Pop 成对丢弃](images/wc188_q1_keep_discard_model.svg)

记 $k = \lvert \text{target} \rvert$、$M = \text{target}[k-1]$（流里最大会被读到的数）。设要构造的第 $i$ 位（从 $0$ 计）目标是 $x = \text{target}[i]$，当前流里下一个数是 $v$：

- 若 $v = x$：正是要的，`Push` 一次，这一位就落定，**永不弹出**（弹出后流已越过 $v$，再也读不回来）。
- 若 $v < x$：$v$ 不该出现在最终栈里，**迟早要被弹掉**。这一步是硬性的——读取是单向的，读过 $v$ 之后不会再有第二次机会。

「丢弃」的代价也固定下来：`Push` 一次必然配 `Pop` 一次，两者净效果为零。真正剩下的自由度只有**弹出时机**：

- **就地弹**：读完 $v$ 立刻 `Pop`，栈马上回到原样；
- **攒着弹**：先连着读 $v, v+1, \dots$，等需要时再一路 `Pop` 回去（`target = [1,4]` 就存在 `["Push","Push","Push","Pop","Pop","Push"]` 这种写法）。

两种写法总长度相同，但**就地弹**最省心：除了「刚压入待丢弃的数、还没弹」的那一瞬，栈始终只是 `target` 的一个前缀，读指针 $cur$ 单调前进，也不必回头处理攒下来的元素。于是贪心构造为——对每个 $x = \text{target}[i]$，把缺口 $[cur, x)$ 里的数逐个「Push + Pop」现场消耗掉，再 `Push` 一次 $x$。

### 3.3 算法流程：逐段补缺口

![算法流程：对每个 target[i]，先补齐缺口再 Push](images/wc188_q1_gap_fill_flow.svg)

```
ops = []; cur = 1
for x in target:            # target 严格递增，天然就是「下一个目标」
    while cur < x:          # 缺口 [cur, x) 全是不要的数
        ops += ["Push", "Pop"]
        cur += 1
    ops += ["Push"]         # 命中目标，保留
    cur = x + 1
return ops
```

循环体做两件事：**清障**（把跳过的数成对丢掉）与**落子**（Push 目标值）。内层 `while` 每轮消耗一个数、代价恰好 $2$ 次操作；外层每个目标值贡献 $1$ 次 `Push`。

处理完最后一个 $x = \text{target}[k-1]$ 后栈已等于 `target`，**必须立即返回**——$x+1, \dots, n$ 一个都不能读（示例 3 正是卡在这里）。

### 3.4 示例演算

![示例演算：target = [1,3] 的四步走查](images/wc188_q1_example_walkthrough.svg)

走查 `target = [1,3]`、$n = 3$：

| 步骤 | 读入 | 操作 | 栈（底 → 顶） | 说明 |
|------|------|------|----------------|------|
| 0 | — | — | `[]` | 初始 |
| 1 | 1 | `Push` | `[1]` | 命中 target[0] |
| 2 | 2 | `Push` | `[1,2]` | 2 不在 target 中 |
| 3 | — | `Pop` | `[1]` | 丢弃刚读的 2 |
| 4 | 3 | `Push` | `[1,3]` | 命中 target[1]，等于目标，停止 |

共 $4$ 次操作，与官方输出 `["Push","Push","Pop","Push"]` 一致。再验证两条短序列：`target = [2], n = 3` 得到 `["Push","Pop","Push"]`（跳过 1）；`target = [1,2], n = 4` 得到 `["Push","Push"]`（两次命中即停，3、4 从未被读入）。

顺带看一眼「攒着弹」的写法：`target = [1,4], n = 4` 时 `["Push","Push","Push","Pop","Pop","Push"]` 同样合法（栈依次为 `[1] → [1,2] → [1,2,3] → [1,2] → [1] → [1,4]`，中途从未等于 `target`），它的长度是 $6$，与就地弹的 `["Push","Push","Pop","Push","Pop","Push"]` 一样长——这并非巧合，见下面的引理 1。

## 4. 算法细节

1. **用游标代替集合**：$v \in \text{target}$ 的判断不需要哈希表——`target` 严格递增，处理到 $\text{target}[i]$ 时，$[cur, x)$ 整段必然不在 `target` 里，$x$ 必然在。游标 $cur$ 一次单调前进，总代价线性。
2. **缺口长度即跳过个数**：内层循环执行 $x - cur$ 次，贡献 $2(x-cur)$ 次操作；把相邻两个目标之间的差值累加起来就是总跳过数。
3. **停止时机**：处理完 $\text{target}[k-1]$ 的 `Push` 后立刻结束。不要在循环外再补「读到 $n$」的动作，那会违反「栈等于 `target` 即停止」的规则。
4. **不需要 $n$**：$n$ 只用于保证 $\text{target}[i] \le n$，算法里最多读到 $\text{target}[k-1]$。数据范围给到 $100$，即便给到 $10^9$ 也不影响复杂度。
5. **操作数恒为 $2M-k$**：设 $k = \text{target.length}$、$M = \text{target}[k-1]$，被跳过 $M-k$ 个数，故 $\lvert \text{ops} \rvert = k + 2(M-k) = 2M - k \le 2n-1$（引理 1 说明这个长度与写法无关）。C++ 里可以 `ops.reserve(2 * n)` 一次分配到位。
6. **中间状态一定不是 `target`**：处理到 $\text{target}[i]$（$i < k-1$）后栈长恰为 $i+1 < k$，而 `target` 长度为 $k$，长度都对不上，绝不会提前触发停止条件。

## 5. 正确性证明

记 $k = \lvert \text{target} \rvert$、$M = \text{target}[k-1]$。

**引理 1（操作多重集被固定）**：任何合法答案中，流里被读入的整数恰为 $1, 2, \dots, M$ 各一次；`target` 中的每个数被 `Push` 一次且从不被 `Pop`；其余 $M-k$ 个数各被 `Push` 一次、`Pop` 一次。因此总操作数恒为

$$k + 2(M-k) = 2M - k.$$

**证明**：

1. $\text{target}[k-1] = M$ 必须出现在最终栈里，而栈中的数只能来自流，故 $M$ 必被读入；流是顺序的，读 $M$ 之前必须依次读掉 $1..M-1$。所以读入集合恰为 $1..M$，且每个数只被读一次。
2. `target` 里的数一旦被弹出就永久缺席（流已越过它，无法重读），而最终栈必须包含它，故它们只 `Push`、不被 `Pop`。
3. 其余 $M-k$ 个数不在最终栈中，却都被读过，因此必然都被 `Pop`（`Push` 与 `Pop` 一一配对，且同一个数只读一次），各贡献一次 `Push` 与一次 `Pop`。
4. 合计 $M$ 次 `Push` 与 $M-k$ 次 `Pop`，即 $2M-k$ 次操作。∎

> 引理 1 说明：**答案不唯一**（弹出时机可攒可散），但**长度唯一**——`3.3` 的贪心恰好取到这个下界，因此它是最短答案。

**引理 2（贪心过程中栈的形态）**：在算法的任意两个操作之间，栈内容都是 `target` 的某个前缀 $\text{target}[0..i)$（$0 \le i \le k$）。唯一的例外是「刚 `Push` 了一个待丢弃的数 $v$、还没来得及 `Pop`」这一瞬间，此时栈为 $\text{target}[0..i) + [v]$ 且 $v < \text{target}[i]$。

**证明**：对 $i$ 归纳。处理 $\text{target}[i]$ 之前，栈为 $\text{target}[0..i)$，指针 $cur = \text{target}[i-1]+1$（约定 $\text{target}[-1] = 0$）。内层循环对每个 $v \in [cur, \text{target}[i])$ 先 `Push`（栈变为 $\text{target}[0..i) + [v]$，即上述例外形态，注意 $v < \text{target}[i]$）再 `Pop`（栈复原为 $\text{target}[0..i)$）；缺口清空后 `Push` 一次 $\text{target}[i]$，栈变为 $\text{target}[0..i+1)$，归纳前进一格。∎

**引理 3（不会提前停止）**：算法执行过程中，除最后一击之外，任何时刻栈都不等于 `target`。

**证明**：由引理 2，两操作之间的栈是前缀 $\text{target}[0..i)$，若 $i < k$ 则长度不足 $k$，不可能等于 `target`；只有最后一次命中 `Push` 后 $i = k$ 才相等。再看例外瞬间，栈为 $\text{target}[0..i) + [v]$、长度 $i+1$：若 $i+1 < k$ 则长度不足；若 $i+1 = k$（即 $i = k-1$）则末元素 $v < \text{target}[k-1]$，仍与 `target` 不同。故算法只在最后一步之后达到 `target`。∎

**定理**：算法返回的操作序列合法，且把栈恰好构造成 `target`，长度达到最小值 $2M-k$。

**证明**：

- **操作合法**：`Push` 读入的数不超过 $M = \text{target}[k-1] \le n$，流非空；每次 `Pop` 都紧跟在本轮的一次 `Push` 之后，栈非空。
- **停止规则**：由引理 3，算法途中从不出现「栈等于 `target` 却继续操作」，只有最后一次 `Push` 之后立即返回，符合题目要求。
- **终态正确**：最后一个 `Push` 使栈变为 $\text{target}[0..k) = \text{target}$。
- **最短性**：由引理 1，任何合法答案的操作数恒为 $2M-k$；算法的 `Push` 次数为 $k + (M-k) = M$、`Pop` 次数为 $M-k$，总数恰好 $2M-k$，取到下界。∎

## 6. 复杂度分析

- **时间**：$O(M + k)$，其中 $M = \text{target}[k-1] \le n$。游标 $cur$ 从 $1$ 单调推进到 $M$，每个整数至多被读入一次；每个 `target` 元素贡献一次 `Push`。最坏 $O(n)$，即 $100$ 次级别。
- **空间**：$O(1)$ 额外空间——只有游标与循环变量，判断「是否属于 `target`」靠递增性而非哈希表。输出序列本身占 $O(n)$，不计入额外空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> buildArray(vector<int>& target, int n) {
        vector<string> ops;
        ops.reserve(2 * n);          // 操作数上界 2n-1
        int cur = 1;                 // 流里下一个待读的数
        for (int x : target) {
            while (cur < x) {        // 缺口 [cur, x) 全是不要的数
                ops.push_back("Push");
                ops.push_back("Pop");
                ++cur;
            }
            ops.push_back("Push");   // 命中目标，保留
            cur = x + 1;
        }
        return ops;                  // target.back() 之后不再读流
    }
};
```

### Python

```python
from typing import List

class Solution:
    def buildArray(self, target: List[int], n: int) -> List[str]:
        ops: List[str] = []
        cur = 1                       # 流里下一个待读的数
        for x in target:              # target 严格递增
            while cur < x:            # 缺口里的数：Push 后立刻 Pop
                ops.append("Push")
                ops.append("Pop")
                cur += 1
            ops.append("Push")        # 命中 target[i]
            cur = x + 1
        return ops                    # 最后一个目标之后必须停手
```

## 8. 边界情况与易错点

1. **`target = [1]`**：$cur$ 初值取 $1$、与 $\text{target}[0]$ 相等，内层循环不执行，直接输出 `["Push"]`。若把 $cur$ 初始化成 $0$，会多出一对 `Push`/`Pop`（先读入 0 这个不存在的数），答案非法。
2. **`target[0] > 1`**：如 `target = [3], n = 5`，需先丢弃 $1,2$，输出 `["Push","Pop","Push","Pop","Push"]`。注意 `Pop` 一定发生在 `Push` 之后，栈非空，不会出现空栈弹出。
3. **越过末尾继续读**：处理完 $\text{target}[k-1]$ 后若继续读 $x+1 \dots n$，示例 3 会直接判错。停止条件写在「栈等于 `target`」而不是「读满 $n$」。
4. **$n$ 与 `target` 末尾不相等**：$n > \text{target}[k-1]$ 是常态，靠的是**提前停止**而不是「把 $n$ 个数都处理完再截断」，两者答案不同。
5. **严格递增既是便利也是「可解」的前提**：判「$v$ 是否属于 `target`」靠递增性用游标完成，不需要集合；但更根本的是，流里每个数只读一次，若 `target` 含重复元素（如 `[1,1]`）则无论怎么操作都构造不出来——这条约束不能省，也不是靠计数能绕过的。
6. **返回类型**：接口名 `buildArray`，参数顺序 `(vector<int>& target, int n)`，返回值是 `vector<string>`；`"Push"`/`"Pop"` 是字符串字面量，C++ 中多次 `push_back` 同一字面量不会出问题。
