# LeetCode 形成两个异或相等数组的三元组数目 题解

## 1. 题目概述

- **标题 / 题号**：形成两个异或相等数组的三元组数目（#1442，medium）
- **链接**：https://leetcode.cn/problems/count-triplets-that-can-form-two-arrays-of-equal-xor/
- **来源**：LeetCode 第 188 场周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、哈希表、数学、前缀和

**题意**：给定整数数组 `arr`，统计满足 $0 \le i < j \le k < n$ 的下标三元组 $(i, j, k)$ 的数目，其中

$$a = \text{arr}[i] \oplus \text{arr}[i+1] \oplus \cdots \oplus \text{arr}[j-1], \qquad b = \text{arr}[j] \oplus \text{arr}[j+1] \oplus \cdots \oplus \text{arr}[k]$$

要求 $a = b$。注意两段都非空：前段是 $[i, j-1]$，后段是 $[j, k]$，所以 $j$ 的取值范围是 $i+1 \le j \le k$。

**约束**：

- $1 \le n = \lvert \text{arr} \rvert \le 300$
- $1 \le \text{arr}[i] \le 10^8$

## 2. 示例

**示例 1**

```text
输入：arr = [2,3,1,6,7]
输出：4
解释：合法三元组为 (0,1,2)、(0,2,2)、(2,3,4)、(2,4,4)。
      以 (0,2,2) 为例：a = 2 ^ 3 = 1，b = 1，两段相等。
      以 (2,4,4) 为例：a = 1 ^ 6 = 7，b = 7，同样相等。
```

**示例 2**

```text
输入：arr = [1,1,1,1,1]
输出：10
解释：两段各由若干个 1 异或而成，异或值就是各自长度的奇偶性，
      只有两段长度奇偶性相同的三元组才合法；20 个候选三元组中恰有 10 个满足。
```

**示例 3**

```text
输入：arr = [2,3]
输出：0
解释：唯一候选 (0,1,1)：a = 2，b = 3，不相等。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是三重循环枚举 $i < j \le k$，再对每个三元组线性扫一遍求两段异或，复杂度 $O(n^4)$，$n = 300$ 时约 $10^9$ 量级次操作，无法接受。

加上**前缀异或**后，任意区间的异或可以 $O(1)$ 求出，复杂度降到 $O(n^3)$：$n = 300$ 时满足 $i < j \le k$ 的三元组约 $4.5 \times 10^6$ 个，C++ 勉强能过。但 $O(n^3)$ 仍然把 $j$ 当成一个独立的枚举维度——而本题最重要的观察恰恰是：**$j$ 是自由变量，根本不需要枚举**。看清这一点可以直接把复杂度压到 $O(n^2)$，再配合哈希表做到 $O(n)$。

### 3.2 核心观察：$a = b \iff$ 整段异或为 $0$

![核心观察：两段异或相等等价于整段异或为 0](images/wc188_q2_xor_zero_equivalence.svg)

把两段异或"接"起来，恰好是整段 $[i, k]$，于是

$$a \oplus b = \text{arr}[i] \oplus \cdots \oplus \text{arr}[k] = \text{xor}(i, k) \quad \Longrightarrow \quad a = b \iff \text{xor}(i, k) = 0$$

再引入**异或前缀** $P[0] = 0$、$P[m] = \text{arr}[0] \oplus \cdots \oplus \text{arr}[m-1]$，则

$$\text{xor}(i, k) = P[i] \oplus P[k+1] = 0 \iff P[i] = P[k+1]$$

**更关键的一点**：一旦 $P[i] = P[k+1]$ 成立，那么无论 $j$ 取 $[i+1, k]$ 中的哪一个位置，都有 $a \oplus b = \text{xor}(i,k) = 0$，即 $a = b$。也就是说这一对 $(i, k)$ 一次性贡献 $k + 1 - i - 1 = k - i$ 个三元组，而不是 1 个。

> 💡 这就是本题的"降维"：三元组 $(i, j, k)$ 实际上由 $(i, k)$ 与"切点 $j$"组成，而 $j$ 与 $a = b$ 无关。把 $j$ 从枚举维度里删掉，问题就变成"数前缀异或相等的下标对"，并按对贡献 $k - i$。

令 $m = k + 1 \in [i+1, n]$，则每对相等的 $(i, m)$ 贡献 $m - i - 1$ 个三元组，答案即

$$\text{ans} = \sum_{i < m,\ P[i] = P[m]} (m - i - 1)$$

### 3.3 算法流程：从 $O(n^2)$ 枚举到 $O(n)$ 批量求和

![算法流程：前缀异或 + 哈希表批量计数](images/wc188_q2_prefix_hash_flow.svg)

**写法一（$O(n^2)$，官方提示的思路）**：先算出全部 $P[0..n]$，然后二重循环枚举 $i < m$，若 $P[i] = P[m]$ 就累加 $m - i - 1$。$n = 300$ 时只有约 $4.5 \times 10^4$ 对，稳过。

**写法二（$O(n)$，本题的最优解）**：把"对所有历史下标求和"这一步用哈希表压缩。设当前处理到 $m$，哈希表记录此前所有下标 $i < m$ 的信息：

- $\text{cnt}[x]$：满足 $P[i] = x$ 的历史下标个数；
- $\text{sumIdx}[x]$：这些下标之和 $\sum i$。

那么当 $P[m] = x$ 时，这一批下标的贡献是

$$\sum_{i}\ (m - 1 - i) = \text{cnt}[x] \cdot (m - 1) - \text{sumIdx}[x]$$

整个过程只需按 $m = 1, 2, \dots, n$ 顺序扫一遍，每个 $m$ 做一次查表、一次累加、一次登记：

```text
for m = 1 .. n:
    px ^= arr[m-1]                 # px = P[m]
    ans += cnt[px] * (m - 1) - sumIdx[px]   # 先结算（只含 i < m）
    cnt[px] += 1                   # 再把自己登记进去
    sumIdx[px] += m
```

初始时把 $P[0] = 0$ 作为"第 0 个下标"放入表：$\text{cnt}[0] = 1$、$\text{sumIdx}[0] = 0$。

### 3.4 示例演算

![示例演算：arr = [2,3,1,6,7] 的前缀异或与贡献](images/wc188_q2_walkthrough.svg)

以 `arr = [2,3,1,6,7]` 为例，前缀异或为 $P = [0, 2, 1, 0, 6, 1]$，其中 $P[m]$ 与 $k = m - 1$ 对应：

| $m$ | $P[m]$ | 命中的历史下标 | 新增三元组 | 累计 |
|-----|--------|----------------|-----------|------|
| 0 | 0 | 种子（$i = 0$） | — | 0 |
| 1 | 2 | — | 0 | 0 |
| 2 | 1 | — | 0 | 0 |
| 3 | 0 | $i = 0$ | $1 \times 2 - 0 = 2$ | 2 |
| 4 | 6 | — | 0 | 2 |
| 5 | 1 | $i = 2$ | $1 \times 4 - 2 = 2$ | 4 |

- $m = 3$：$P[3] = P[0] = 0$，对应 $k = 2$ 的子数组 $[2,3,1]$ 异或为 $0$，$j$ 可取 $1,2$，得到 $(0,1,2)$、$(0,2,2)$。
- $m = 5$：$P[5] = P[2] = 1$，对应 $k = 4$ 的子数组 $[1,6,7]$ 异或为 $0$，$j$ 可取 $3,4$，得到 $(2,3,4)$、$(2,4,4)$。

合计 $2 + 2 = 4$，与示例输出一致。✓

## 4. 算法细节

1. **前缀定义**：$P[0] = 0$，$P[m] = P[m-1] \oplus \text{arr}[m-1]$，数组长度是 $n+1$，下标范围 $0 \dots n$；$m$ 对应区间的右端 $k = m - 1$。
2. **下标映射**：三元组 $(i, j, k)$ 与"前缀对 $(i, m = k+1)$ + 切点 $j \in [i+1, m-1]$"一一对应，贡献 $m - 1 - i$ 个。$k \le n-1$ 保证 $m \le n$。
3. **先结算、后登记**：查表时必须保证表里只有 $i < m$ 的历史下标。若先把 $m$ 登记进去再结算，同一个 $m$ 会给自己贡献 $m - 1 - m = -1$，答案直接变负。
4. **两个哈希表**：$\text{cnt}$ 与 $\text{sumIdx}$；也可以合并成一个 `unordered_map<int, pair<long long,long long>>`。异或值域并不连续（最大可到 $2^{27}$ 量级），不要用数组当桶。
5. **缺失键的处理**：键不存在时 $\text{cnt} = 0$、$\text{sumIdx} = 0$，贡献为 $0$，无需特判；只是登记时要先建键再自增。
6. **数值范围**：答案的粗略上界是 $\sum_{i<m} (m-1-i) \approx n^3/6 \approx 4.5 \times 10^6$（$n = 300$ 全为 1 时实测 $2\,250\,050$），32 位 `int` 足够；中间量 $\text{cnt} \times (m-1) \le 300 \times 300$，同样安全。C++ 里用 `long long` 累加只是习惯上的保险。
7. **两种写法的取舍**：$O(n^2)$ 版本代码更短、无哈希开销，$n = 300$ 时 4.5 万次比较极快；$O(n)$ 版本是通解，把 $n$ 放大到 $10^5$ 也不虚。赛时建议先写 $O(n^2)$ 保命，再顺手升级。

## 5. 正确性证明

**引理 1（相等 ⇔ 整段异或为 0）**：对任意 $i < j \le k$，记 $a = \text{xor}(i, j-1)$、$b = \text{xor}(j, k)$，则 $a = b$ 当且仅当 $\text{xor}(i, k) = 0$。

**证明**：由异或的结合律与交换律，

$$a \oplus b = \text{xor}(i, j-1) \oplus \text{xor}(j, k) = \text{xor}(i, k)$$

若 $a = b$，则 $a \oplus b = 0$；反之若 $\text{xor}(i,k) = 0$，则 $a \oplus b = 0$，两边同时异或 $b$ 得 $a = 0 \oplus b = b$（逐位看：每一位上 $a$ 与 $b$ 的位值相同）。∎

**引理 2（切点自由）**：若固定 $i \le k$ 满足 $\text{xor}(i, k) = 0$，则每个 $j \in [i+1, k]$ 都使 $a = b$ 成立，共 $k - i$ 个切点。

**证明**：对任意 $j \in [i+1, k]$，前段 $[i, j-1]$ 与后段 $[j, k]$ 都非空，由引理 1 即得 $a = b$。切点取值个数为 $k - (i+1) + 1 = k - i$。∎

**引理 3（批量求和）**：设处理到 $m$ 时，哈希表中 $\text{cnt}[x]$、$\text{sumIdx}[x]$ 恰为集合 $S_x = \{\, i < m : P[i] = x \,\}$ 的大小与元素和，则 $\sum_{i \in S_x} (m - 1 - i) = \text{cnt}[x] \cdot (m-1) - \text{sumIdx}[x]$。

**证明**：把求和拆开，$\sum_{i \in S_x} (m-1-i) = (m-1)\lvert S_x \rvert - \sum_{i \in S_x} i$，代入定义即得。∎

**定理**：算法返回的计数等于合法三元组总数。

**证明**：由引理 1，一个三元组合法当且仅当 $P[i] = P[k+1]$，即只由 $i$ 与 $m = k+1$ 决定；由引理 2，给定这样一对 $(i, m)$ 后，$j$ 可在 $[i+1, m-1]$ 中任取且必合法，而且不在该区间内的 $j$ 会使某一侧为空、不构成三元组。故"合法三元组"与"满足 $P[i] = P[m]$（$i < m$）的对 + 区间内切点"一一对应，每对恰贡献 $m - 1 - i$ 个。

$O(n^2)$ 版本逐对枚举，全部计入；$O(n)$ 版本按 $m$ 递增扫描，引理 3 的不变式说明每次结算的正是所有 $i < m$ 且 $P[i] = P[m]$ 的对的贡献，且各 $m$ 互不重叠，故总和等于全部对数贡献之和。两种写法都返回正确计数。∎

## 6. 复杂度分析

- **时间复杂度（$O(n)$ 版本）**：$O(n)$ 期望。按 $m = 1 \dots n$ 扫一遍，每次做常数次哈希查找与插入，期望 $O(1)$；本题 $n \le 300$，不必为最坏情况设计防御性哈希。
- **空间复杂度（$O(n)$ 版本）**：$O(n)$。前缀异或值最多 $n+1$ 个不同取值，两张哈希表各存至多 $n+1$ 项；只需滚动变量 `px`，不必存整个前缀数组。
- **时间复杂度（$O(n^2)$ 版本）**：$O(n^2)$。约 $n^2/2 = 4.5 \times 10^4$ 对比较，需额外 $O(n)$ 的前缀数组。
- **对比**：不带前缀的暴力 $O(n^4)$；带前缀但枚举 $j$ 的 $O(n^3) \approx 4.5 \times 10^6$。本题的正解核心是把 $j$ 消掉。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countTriplets(vector<int>& arr) {
        int n = arr.size();
        unordered_map<int, long long> cnt, sumIdx;   // 值 -> 出现次数 / 下标和
        cnt[0] = 1;                                  // 种子：P[0] = 0，i = 0
        sumIdx[0] = 0;
        long long ans = 0;
        int px = 0;
        for (int m = 1; m <= n; ++m) {
            px ^= arr[m - 1];                        // px = P[m]
            if (cnt.count(px)) {
                ans += cnt[px] * (m - 1) - sumIdx[px];   // 先结算历史下标 i < m
            }
            cnt[px] += 1;                            // 再登记自己
            sumIdx[px] += m;
        }
        return (int)ans;
    }
};
```

**变体：$O(n^2)$ 前缀枚举（无哈希，代码更短）**

```cpp
class Solution {
public:
    int countTriplets(vector<int>& arr) {
        int n = arr.size();
        vector<int> P(n + 1, 0);
        for (int m = 1; m <= n; ++m) P[m] = P[m - 1] ^ arr[m - 1];
        long long ans = 0;
        for (int i = 0; i < n; ++i)
            for (int m = i + 1; m <= n; ++m)
                if (P[i] == P[m]) ans += m - i - 1;   // j 可取 i+1 ... m-1
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countTriplets(self, arr: List[int]) -> int:
        cnt = {0: 1}        # 前缀异或值 -> 出现次数
        sum_idx = {0: 0}    # 前缀异或值 -> 出现下标之和
        ans = px = 0
        for m, v in enumerate(arr, 1):
            px ^= v                         # px = P[m]
            c = cnt.get(px, 0)
            if c:
                ans += c * (m - 1) - sum_idx[px]   # 先结算
            cnt[px] = c + 1                        # 再登记
            sum_idx[px] = sum_idx.get(px, 0) + m
        return ans
```

## 8. 边界情况与易错点

1. **结算与登记的顺序不能反**：必须先查表累加、再把当前 $m$ 写进表。顺序颠倒会让每个 $m$ 给自己贡献 $m-1-m = -1$，答案整体偏小甚至为负（见引理 3 的适用范围 $i < m$）。
2. **忘记乘切点个数**：只把"前缀异或相等的对数"当成答案会明显偏小。示例 1 中前缀值相等的对只有 $(0,3)$、$(2,5)$ 两对，正确答案却是 $2 + 2 = 4$——每对还要乘 $m - 1 - i$。
3. **$P[0] = 0$ 的种子必须入表**：漏掉它就丢掉所有 $i = 0$ 的答案。示例 1 中 $(0,1,2)$、$(0,2,2)$ 两个三元组正是靠这个种子才被数到。
4. **$k$ 与 $m$ 差一**：$m = k + 1$，写代码时容易把 $k$ 直接当 $m$ 用；一旦差一，贡献会整体偏移。
5. **$n \le 2$ 时没有合法三元组**：需要 $i < j \le k < n$ 至少三个不同位置，循环自然不产生任何项，返回 0（示例 3）；不需要额外特判。
6. **不要用数组做桶**：$\text{arr}[i] \le 10^8$，异或值可落在 $[0, 2^{27})$ 的稀疏集合里，开 $2^{27}$ 的数组既浪费又可能越界，必须用哈希表。
7. **答案范围**：$n = 300$ 时最大约 $2.25 \times 10^6$，`int` 安全；但如果把题面放宽到 $n = 10^5$，答案会到 $10^{14}$ 量级，返回值类型要换 64 位。

**延伸思考**：

1. 若把问题改成"统计异或和为 $0$ 的**子数组个数**"，答案就是满足 $P[i] = P[m]$ 的对数——即本题把每对的权重从 $m - 1 - i$ 改成 $1$，哈希表只需存 $\text{cnt}$，这是 2588 的标准做法。
2. 若要求 $a = b$ 且两段**等长**（$j$ 必须是中点），只需筛出 $k - i$ 为奇数的对、令 $j = (i + k + 1)/2$，再验证 $P[i] = P[k+1]$ 即可，复杂度回到 $O(n^2)$。
3. 若把异或换成加法并要求 $a = b$，需要处理负数与前缀和相等，哈希表思路依旧，但要注意 $0$ 元素会带来大量等价对；换成乘法则要处理 $0$ 与模意义下的逆元，结构完全不同。
4. 若 $n$ 放大到 $10^5$ 且异或值域极大（如 64 位整数），可以用排序代替哈希：把 $(P[i], i)$ 按值分组，组内对下标排序后仍可用"次数 × $(m-1)$ − 下标和"批量计算，最坏 $O(n \log n)$ 且无哈希碰撞风险。
