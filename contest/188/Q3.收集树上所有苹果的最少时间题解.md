# LeetCode 收集树上所有苹果的最少时间 题解

## 1. 题目概述

- **标题 / 题号**：收集树上所有苹果的最少时间（#1443，medium）
- **链接**：https://leetcode.cn/problems/minimum-time-to-collect-all-apples-in-a-tree/
- **来源**：LeetCode 第 188 场周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、哈希表、树形 DP

**题意**：给一棵 $n$ 个节点（编号 $0 \sim n-1$）的**无向树**，边由 `edges` 给出，`hasApple[i] = true` 表示节点 $i$ 上有苹果。从节点 $0$ 出发，走过一条边耗 1 秒，求收集**所有**苹果并**回到节点 0** 的最少秒数。

**关键限制**：树中没有环，任意两点间路径唯一；起点与终点都是根 $0$，因此所有「跑出去」的路都必须「原路返回」。

**约束**：

- $1 \le n \le 10^5$
- `edges.length == n - 1`，`edges[i].length == 2`
- $0 \le a_i < b_i \le n - 1$
- `hasApple.length == n`

> 💡 本题输入保证 `edges` 构成一棵以 $0$ 可达的树，无需再做连通性检查。

## 2. 示例

**示例 1**

```text
输入：n = 7, edges = [[0,1],[0,2],[1,4],[1,5],[2,3],[2,6]]
      hasApple = [false,false,true,false,true,true,false]
输出：8
解释：苹果在 2、4、5。最优路线只需走 4 条边各往返一次：
      (0,1)、(1,4)、(1,5)、(0,2)，4 × 2 = 8 秒。
```

**示例 2**

```text
      hasApple = [false,false,true,false,false,true,false]
输出：6
解释：苹果在 2、5。只需走 (0,2)、(0,1)、(1,5) 三条边，3 × 2 = 6 秒；
      4、3、6 这三棵子树上没有苹果，任何路线都不该拐进去。
```

**示例 3**

```text
输入：n = 7, edges = [[0,1],[0,2],[1,4],[1,5],[2,3],[2,6]]
      hasApple = [false,false,false,false,false,false,false]
输出：0
解释：一个苹果都没有，原地不动即可。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的写法是搜索所有行走方案：状态为「当前所在点 + 已收集苹果集合」，用 BFS 求最短路，状态数上界约为 $n \cdot 2^{n}$，$n = 10^5$ 时完全不可行。

另一种「看起来能跑」的暴力是：对每个有苹果的节点单独走一遍从 $0$ 到它的路径，把边数累加。但同一条边会被多个苹果节点重复计算——例如示例 1 中节点 $4$ 与 $5$ 共用边 $(0,1)$，简单累加会得到 $2 \times (9) = 18$ 而不是 $8$。**去重**正是本题要解决的核心问题。

### 3.2 核心观察：没苹果的子树整枝剪掉，留下的边必然往返两次

![只有子树含苹果的边才需要走，且来回各一次](images/wc188_q3_used_edge_model.svg)

把树以 $0$ 为根定向，记 $u$ 的父节点为 $p(u)$，考察边 $e = (p(u), u)$。这条边把整棵树切成两半：$u$ 的子树 $S_u$ 和其余部分。于是有

**判据**：$e$ 需要被经过 $\iff$ $S_u$ 中至少有一个苹果。

- 若 $S_u$ 无苹果：每次跨过 $e$ 进去，都只能原路返回，纯属浪费，最优方案一定不跨。
- 若 $S_u$ 有苹果：要拿到其中的苹果，路线**必须**从 $0$ 侧跨到 $u$ 侧；又因为最终要回到 $0$，还得再跨回来一次。这条边是连接两侧的**唯一通道**，所以至少两次。

进一步，被保留的边构成一棵以 $0$ 为根的连通子树 $T'$（剪枝后仍然连通，因为 $p(u)$ 必然也在其中）。在 $T'$ 上做一次深度优先遍历并原路返回，每条边恰好去一次、回一次，总步数 $2 \lvert E(T') \rvert$，与下界吻合。因此

$$\text{答案} = 2 \times \#\{\, u \ne 0 : S_u \text{ 中含苹果} \,\}$$

这就把「求一条最优回路」转化成了「统计有多少个非根节点的子树含苹果」，一次自底向上的标记即可。

### 3.3 算法流程 / 状态转移

![从叶到根自底向上传播 need 标记](images/wc188_q3_dfs_flow.svg)

用 `need[u]` 表示「子树 $u$ 中含苹果」，则有状态转移

$$\text{need}[u] = \text{hasApple}[u] \;\lor\; \bigvee_{v \in \text{child}(u)} \text{need}[v]$$

实现上不需要真的递归，只要**按访问序倒着扫**：

1. 用 `edges` 建邻接表（无向边双向存）。
2. 从 $0$ 出发做 BFS（或迭代 DFS），记录 `parent[v]` 与访问序 `order`。
3. `need[u]` 初值取 `hasApple[u]`。
4. 倒序遍历 `order`（此时保证子节点先于父节点被处理），若 `need[u]` 为真则把 `need[parent[u]]` 置真。
5. 统计 `u != 0` 且 `need[u]` 为真的节点数，乘以 2 即为答案。

### 3.4 示例演算

![示例 1 中 6 条边的取舍与最终计数](images/wc188_q3_example_walkthrough.svg)

对示例 1（$n = 7$，苹果在 $2, 4, 5$）：

| 节点 $u$ | `hasApple[u]` | 子树含苹果？ | 边 $(p(u),u)$ 计入 |
|----------|---------------|--------------|--------------------|
| 4 | true | 是（自己） | 是 |
| 5 | true | 是（自己） | 是 |
| 3 | false | 否 | 否 |
| 6 | false | 否 | 否 |
| 1 | false | 是（经 4、5） | 是 |
| 2 | true | 是（自己） | 是 |

`need` 为真的非根节点共 $4$ 个，答案 $= 2 \times 4 = 8$，与官方输出一致。示例 2 把节点 $4$ 的苹果去掉后，$S_4$ 变空，边 $(1,4)$ 被剪掉，剩下 $(0,1)、(0,2)、(1,5)$ 三条，输出 $6$。

## 4. 算法细节

1. **一律用迭代**：$n$ 可达 $10^5$，树退化成链时递归深度也是 $10^5$，Python 默认递归上限 1000 会直接 `RecursionError`，C++ 也有爆栈风险。用 `order` 列表当队列（BFS）或栈（迭代 DFS）即可。
2. **用父节点判回边，不用 visited**：树无环，`v != parent[u]` 就足以保证不回头；这比维护 `visited` 少一个数组，也避免「根被重复访问」的细节。
3. **倒序遍历的正确性来源**：BFS/DFS 的 `order` 满足「父一定先于子被加入」，倒着扫即「子一定先于父被处理」，因此处理 $u$ 时它的所有子节点的 `need` 已定稿。
4. **统计的是点，不是边**：每条边由它的下端点唯一确定，所以 `# { u != 0 : need[u] }` 恰好是用到的边数，不需要额外存边表。
5. **提前结束**：若整棵树没有任何苹果（`sum(hasApple) == 0`），可以直接返回 0；这既是特判，也避免了一次无意义的 $O(n)$ 标记。
6. **`need` 用轻量类型**：C++ 用 `vector<char>` 而不是 `vector<bool>`，避开位压缩代理引用带来的取址/赋值坑（尤其不要对 `vector<bool>` 元素取引用）。
7. **`hasApple` 不要原地改**：LeetCode 可能复用入参对象，复制一份到 `need` 再传播更安全（Python 用 `list(hasApple)`）。

## 5. 正确性证明

**引理 1（下界）**：对任意节点 $u \ne 0$，若 $S_u$ 含苹果，则任何合法路线中边 $(p(u), u)$ 至少被经过 2 次。

**证明**：删去边 $(p(u),u)$ 后树分成 $S_u$ 与 $V \setminus S_u$，二者之间只有这一条边相连。设 $a \in S_u$ 有苹果，路线必须到达 $a$，而起点 $0 \notin S_u$，所以路线至少要跨过该边一次进入 $S_u$；又终点是 $0 \notin S_u$，必须再跨出一次。两个方向的跨越各计 1 次，共至少 2 次。∎

**引理 2（`need` 的语义）**：算法结束后，对每个 $u$ 有 `need[u]` 为真 $\iff$ $S_u$ 中含苹果。

**证明**：对 $S_u$ 的高度做归纳。叶子节点：倒序扫到它时无子节点，`need[u] = hasApple[u]`，而 $S_u = \{u\}$，命题成立。非叶子：倒序遍历保证处理 $u$ 时所有子节点 $v$ 的 `need[v]` 已定稿，由归纳假设 `need[v]` 为真 $\iff S_v$ 含苹果；又 $S_u = \{u\} \cup \bigcup_v S_v$，故 `need[u] = hasApple[u] ∨ ⋁_v need[v]` 为真 $\iff S_u$ 含苹果。∎

**引理 3（上界 / 构造）**：令 $E' = \{(p(u),u) : u \ne 0,\ \text{need}[u]\}$，则存在一条从 $0$ 出发、收集全部苹果、回到 $0$ 且总长恰为 $2\lvert E' \rvert$ 的路线。

**证明**：由引理 2，$E'$ 正是「子树含苹果」的边集。这些边连同端点构成连通子树 $T'$ 且包含所有苹果节点（若苹果在 $a$，则从 $0$ 到 $a$ 路径上每条边的下端子树都含 $a$，故全在 $E'$ 中）。在 $T'$ 上从 $0$ 做 DFS：每条边向下走一次、回溯一次，遍历结束回到 $0$，总步数 $2\lvert E' \rvert$，且访问了 $T'$ 的所有节点，苹果全部收集。∎

**定理**：算法输出 $2 \times \#\{u \ne 0 : \text{need}[u]\}$ 即为最少时间。

**证明**：由引理 2，该式等于 $2\lvert E' \rvert$。由引理 1，任何合法路线对每条 $e \in E'$ 至少贡献 2 步，对 $e \notin E'$ 贡献非负，故总步数 $\ge 2\lvert E' \rvert$；由引理 3 该下界可达。故最小值就是 $2\lvert E' \rvert$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建邻接表 $O(n)$；定根遍历每条边被看两次 $O(n)$；倒序传播一次 $O(n)$；最后统计 $O(n)$。总计 $O(n)$，与树的形状无关。
- **空间**：$O(n)$。邻接表存 $2(n-1)$ 个端点；`parent`、`order`、`need` 各 $n$ 个元素。没有递归栈开销。

## 7. 参考代码

### C++

```cpp
#include <vector>

using namespace std;

class Solution {
public:
    int minTime(int n, vector<vector<int>>& edges, vector<bool>& hasApple) {
        vector<vector<int>> adj(n);
        for (auto& e : edges) {
            adj[e[0]].push_back(e[1]);
            adj[e[1]].push_back(e[0]);
        }

        // 1) 从 0 出发定根：parent 判回边，order 记录「父先子后」的顺序
        vector<int> parent(n, -1), order;
        parent[0] = 0;
        order.push_back(0);
        for (size_t i = 0; i < order.size(); i++) {
            int u = order[i];
            for (int v : adj[u]) {
                if (v != parent[u]) {
                    parent[v] = u;
                    order.push_back(v);
                }
            }
        }

        // 2) need[u]：子树 u 中是否有苹果（先继承自己）
        vector<char> need(n, 0);
        for (int i = 0; i < n; i++) need[i] = hasApple[i] ? 1 : 0;

        // 3) 倒序上推：孩子先算完，再告诉父亲
        for (int i = n - 1; i >= 1; i--) {
            int u = order[i];
            if (need[u]) need[parent[u]] = 1;
        }

        // 4) 每个 need 为真的非根点对应一条必须往返的边
        int usedEdges = 0;
        for (int i = 1; i < n; i++)
            if (need[order[i]]) usedEdges++;
        return 2 * usedEdges;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def minTime(self, n: int, edges: List[List[int]], hasApple: List[bool]) -> int:
        adj = [[] for _ in range(n)]
        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)

        # 迭代定根，避免链状树上的递归深度问题
        parent = [-1] * n
        parent[0] = 0
        order = [0]
        for u in order:                      # 边遍历边追加，等价于 BFS
            for v in adj[u]:
                if v != parent[u]:
                    parent[v] = u
                    order.append(v)

        need = list(hasApple)                # 复制，避免污染入参
        for u in reversed(order[1:]):        # 叶 → 根
            if need[u]:
                need[parent[u]] = True

        return 2 * sum(1 for u in order[1:] if need[u])
```

## 8. 边界情况与易错点

1. **$n = 1$**：没有任何边，若 `hasApple[0]` 为真，苹果已在原地，答案是 0；代码中 `order[1:]` 为空、`usedEdges = 0`，自然输出 0。
2. **只有根有苹果**：`hasApple[0] = true` 会让 `need[0]` 为真，但根不计数（`u != 0` 或从 `order[1:]` 开始），答案 0——不能把「有苹果」直接乘 2。
3. **全 false**：应当输出 0；若实现里把「每个节点都走一遍」当默认行为会得到 $2(n-1)$，这是最典型的错误。
4. **深链导致爆栈**：$n = 10^5$ 的链（$0-1-2-\cdots$）在 Python 递归或未加栈大小的 C++ 递归下会崩，务必用迭代。
5. **`vector<bool>` 的坑**：`vector<bool>` 是位压缩特化，不能对元素取引用或地址；传播时写 `need[parent[u]] = 1` 用 `vector<char>` 更稳妥。
6. **边方向**：`edges` 里只给了 $a_i < b_i$ 的无向边，必须双向建图，否则从 $0$ 出发会漏掉一半节点（树不连通就统计出错）。
7. **误把「边数」算成「节点数」**：$k$ 条边的子树有 $k+1$ 个节点，只有非根且 `need` 为真的节点才与边一一对应，别用 `sum(need)` 直接乘 2。

**延伸思考**：如果题目**不要求回到 $0$**，只需要收集到所有苹果后停在某个点，那么最优解是「走完 $2\lvert E' \rvert$ 步后省掉最后一段归途」——最终停在离 $0$ 最远的那个苹果节点上，答案变成

$$2\lvert E' \rvert - \max_{a:\ \text{hasApple}[a]} \text{depth}(a)$$

因为对每条有用的边，可以省去「从最远苹果回根」这段路径上的单程，其余边仍然必须往返。若再进一步，允许从任意点出发、到任意点结束，则需要求 $T'$ 的**直径**，答案变成 $2\lvert E' \rvert - \operatorname{diam}(T')$，这就退化成一棵带权树的「中国邮递员问题」特例了。
