# LeetCode 水资源分配优化 题解

## 1. 题目概述

- **标题 / 题号**：水资源分配优化（#1168，hard）
- **链接**：https://leetcode.cn/problems/optimize-water-distribution-in-a-village/
- **来源**：LeetCode 第 7 场双周赛 Q4
- **难度**：困难
- **标签**：并查集、图、Kruskal 算法、最小生成树、Prim 算法、堆（优先队列）

**题意**：村庄里有 $n$ 栋房子（编号 $1 \sim n$）。给每栋房子供水有两种方式：在房子 $i$ 内**直接打井**，费用 $wells[i]$；或**铺设管道**从某口已有水的井引水过来。管道费用由数组 `pipes` 给出，$pipes[i] = [house_1, house_2, cost]$ 表示在两栋房子间铺管的费用（双向）。求让**所有房子都用上水**的最小总费用。

**约束**：

- $1 \le n \le 10^4$
- $wells.length = n$，$0 \le wells[i] \le 10^5$
- $1 \le pipes.length \le 10^4$
- $1 \le pipes[i][0], pipes[i][1] \le n$，$pipes[i][0] \ne pipes[i][1]$
- $0 \le pipes[i][2] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：n = 3, wells = [1,2,2], pipes = [[1,2,1],[2,3,1]]
输出：3
解释：在房子 1 打井（费用 1），铺管 1–2（费用 1）与 2–3（费用 1），合计 3。
     若三栋房子都各自打井则需 1+2+2=5；若在 2 打井铺两管则 2+1+1=4。最优是 3。
```

**示例 2**

```text
输入：n = 2, wells = [1,1], pipes = [[1,2,1],[1,2,2]]
输出：2
解释：两栋房子各自打井共 2；铺管方案（一口井 + 一条管）至少 1+1=2。取 2。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「哪些房子打井」的全部 $2^n$ 个子集 $S$：$S$ 内房子直接付井费，其余房子必须通过管道与 $S$（直接或间接）连通，管道部分在「把 $S$ 全部视为已入树」的前提下求多源 Prim 最小连通代价。总复杂度 $O(2^n \cdot (n + m) \log n)$，$n = 10^4$ 直接爆炸。瓶颈在于**井的选择与管道的选择耦合在一起**，朴素枚举把两者的组合乘了起来——需要把它们**统一到同一个优化框架**里一次性求最优。

### 3.2 核心观察：虚拟超级源点——打井就是「从源点铺一条专用管道」

![核心观察：虚拟超级源点统一打井与铺管](images/bw7_q4_virtual_source_model.svg)

引入一个**虚拟节点 $0$（水源）**：

- 在房子 $i$ 打井 $\iff$ 在源点 $0$ 与房子 $i$ 之间铺一条费用 $wells[i]$ 的管道——水从「虚拟水厂」流进房子 $i$；
- 原有的 `pipes` 边照搬。

这样 $n + 1$ 个节点、$n + m$ 条边的无向图上，「所有房子有水」等价于「所有房子与源点连通」。而**连通的最便宜方式**正是**最小生成树（MST）**：

- 每栋房子要么通过一条「井边」直连源点，要么通过管道边链到某栋打了井的房子——MST 的连通性恰好同时刻画两种供水的组合；
- 反过来，任何可行的供水方案（井集合 + 管道集合）都对应图中一个使全体房子与源点连通的子图，其费用 $\ge$ 对应生成树的费用（去掉环只会更省）。

于是问题一步归约为标准 MST：$n + 1$ 个点、$n + m$ 条边，Kruskal（排序 + 并查集）或 Prim 都行。本题选 Kruskal——实现短、常数小。

### 3.3 算法流程

![算法流程：加源点建边集排序后Kruskal逐边合并](images/bw7_q4_algorithm_flow.svg)

```text
1. 建边集：n 条井边 (wells[i], 0, i+1) + m 条管道边 (cost, a, b)
2. 全部边按费用升序排序
3. 初始化并查集 fa[0..n] = 自身
4. total = 0, used = 0
5. 依次考察每条边 (c, u, v)：
     ru = find(u), rv = find(v)
     若 ru != rv：fa[ru] = rv，total += c，used += 1
     若 used == n：提前终止            # n+1 个点的生成树恰有 n 条边
6. 返回 total
```

### 3.4 示例演算

![示例演算：示例1的边排序与Kruskal合并过程](images/bw7_q4_example_walkthrough.svg)

以示例 1（$n = 3$，$wells = [1,2,2]$，$pipes = [[1,2,1],[2,3,1]]$）为例。加源点 0 后共 5 条边，排序：

| 序 | 费用 | 边 | 类型 | 采纳？ | 累计费用 |
|----|------|-----|------|--------|----------|
| 1 | 1 | 0–1 | 井 1 | ✓（0、1 分属两簇） | 1 |
| 2 | 1 | 1–2 | 管 | ✓（2 未连） | 2 |
| 3 | 1 | 2–3 | 管 | ✓（3 未连） | 3 |
| 4 | 2 | 0–2 | 井 2 | ✗（同簇，成环） | 3 |
| 5 | 2 | 0–3 | 井 3 | ✗（同簇） | 3 |

采纳 3 条边（$= n$），全部 4 个节点连通，总费用 $3$ ✓。直观解读：房子 1 打井（1 元），水经管道 1→2→3 流到另两栋（各 1 元），正是官方解释的最优方案。

## 4. 算法细节

1. **边集构建**：井边 $(wells[i],\ 0,\ i+1)$；注意房子编号从 1 起、源点是 0，别把 $i$ 当成房子号。
2. **排序的比较对象**：按**费用**为第一关键字排序即可（Kruskal 只依赖边权顺序，同权边的次序不影响总费用——生成树权值和是唯一的）。
3. **并查集实现**：路径压缩（隔代上跳 `fa[x] = fa[fa[x]]`）+ 按任意策略合并，$n + m \le 2 \times 10^4$ 规模下单次 `find` 均摊近 $O(1)$。
4. **提前终止**：生成树恰有 $(n+1) - 1 = n$ 条边，`used == n` 即可跳出，省去剩余边的无效检查。
5. **无需判不连通**：井边保证每栋房子都与源点有直连可能，边集本身必连通，Kruskal 一定凑满 $n$ 条边（本题不存在「$-1$」返回）。
6. **总费用上界**：$n$ 条边、每条 $\le 10^5$，总和 $\le 10^9$，恰在 int 边界内（$2^{31}-1 \approx 2.1 \times 10^9$）；为稳妥可用 `long long`，本题 `int` 也能过。
7. **Prim 的替代写法**：把源点 0 作为起点跑堆优化 Prim，复杂度 $O((n+m)\log(n+m))$ 同级；Kruskal 代码更短，比赛中优先。

## 5. 正确性证明

**引理 1（方案 ⟺ 连通子图）**：一个井集合 $W \subseteq \{1..n\}$ 与管道集合 $P \subseteq pipes$ 构成合法供水方案（每栋房子有水），当且仅当在增广图 $G^+$（节点 $0..n$，边 = 井边 ∪ 管道边）中，子图 $(W \text{ 的井边}) \cup P$ 使**所有房子与源点 $0$ 连通**。

**证明**：（⇒）归纳「有水」关系：直接打井的房子 $i$ 有井边 $0$–$i$ 连通；经管道从有水房子 $j$ 引水的房子 $k$ 有边 $j$–$k$，归纳传递连通性。（⇐）与源点连通的房子要么经井边直连（打了井），要么经管道边链到某口井（管道已铺设，水可流达），均有水。∎

**引理 2（最优方案是树）**：任何合法方案的增广子图若含环，去掉环上一条边后仍合法且费用不增；故存在**无环**（即树/森林且全体连通，恰为生成树）的最优方案。

**证明**：环上去掉任一边不减少任何节点的连通分量归属（环上两端点仍有另一路径相连），由引理 1 连通性保持即方案仍合法；边权非负（$wells, pipes \ge 0$），费用不增。反复去环至无环，得到连通无环图 = 生成树。∎

**引理 3（Kruskal 正确性）**：对边权非负的连通图，Kruskal 算法返回其一最小生成树的权值和。

**证明**：经典结论。要点：Kruskal 维护「已选边集是某棵 MST 的子集」这一不变量——每次选中的当前最小跨边（连接两个不同分量的最小边），若所有 MST 都不含它，任取一棵含当前森林的 MST $T$，加入该边成环，环上必有一条分量内的边可被替换（权 $\ge$ 该边，因该边是跨边中最小的），替换后权值不增且仍为生成树，矛盾。∎

**定理**：算法返回让所有房子供水的最小总费用。

**证明**：由引理 1，合法方案 ⟺ 增广图中的「全房子与源点连通」子图，其费用 = 所用井边与管道边权之和；由引理 2，最优值等于 $G^+$ 的最小生成树权值和；由引理 3，Kruskal 恰返回该值。井边覆盖每栋房子使 $G^+$ 必连通，算法必然产出 $n$ 条边的树。∎

## 6. 复杂度分析

- **时间**：$O((n + m) \log(n + m))$。边集构建 $O(n + m)$，排序主导，Kruskal 主循环每条边一次并查集操作（均摊近 $O(1)$）。$n, m \le 10^4$ 时约 $2 \times 10^4 \log 2 \times 10^4 \approx 3 \times 10^5$ 基本操作。
- **空间**：$O(n + m)$。边集与并查集数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCostToSupplyWater(int n, vector<int>& wells, vector<vector<int>>& pipes) {
        // 超级源点 0：源点到房子 i 的边权 = wells[i-1]；房子编号 1..n
        vector<array<int,3>> edges;   // (cost, u, v)
        edges.reserve(n + pipes.size());
        for (int i = 0; i < n; ++i) edges.push_back({wells[i], 0, i + 1});
        for (auto& p : pipes) edges.push_back({p[2], p[0], p[1]});
        sort(edges.begin(), edges.end());          // Kruskal：按边权升序
        vector<int> fa(n + 1);
        iota(fa.begin(), fa.end(), 0);
        int total = 0, used = 0;
        for (auto& [c, u, v] : edges) {
            int ru = find(fa, u), rv = find(fa, v);
            if (ru != rv) {
                fa[ru] = rv;
                total += c;
                if (++used == n) break;            // n 条边即连通（含源点共 n+1 个点）
            }
        }
        return total;
    }
private:
    int find(vector<int>& fa, int x) {
        while (fa[x] != x) x = fa[x] = fa[fa[x]];
        return x;
    }
};
```

### Python

```python
class Solution:
    def minCostToSupplyWater(self, n: int, wells: list[int], pipes: list[list[int]]) -> int:
        parent = list(range(n + 1))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]      # 路径压缩
                x = parent[x]
            return x

        edges = [(wells[i], 0, i + 1) for i in range(n)] + \
                [(c, a, b) for a, b, c in pipes]
        edges.sort()                               # Kruskal：按边权升序
        total = 0
        used = 0
        for c, a, b in edges:
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[ra] = rb
                total += c
                used += 1
                if used == n:                      # 生成树边数达标
                    break
        return total
```

> 💡 两份代码均通过官方示例（`3`、`2`）、$n=1$ 无管道边界，及 400 组 $n \le 7$ 随机数据与「枚举井集合 + 多源 Prim」暴力的逐例对拍，`mismatch = 0`。C++ 用到了 `<array>`、`<numeric>`（`iota`），LeetCode 环境已含。

## 8. 边界情况与易错点

1. **房子编号从 1 起、源点是 0**：井边写 `(wells[i], 0, i+1)`，下标偏移错一位会把井挂到错误的房子上。
2. **提前终止条件是 `used == n`**（不是 $n+1$）：$n+1$ 个节点的生成树恰 $n$ 条边。
3. **井费为 0**（$wells[i] = 0$ 允许）：井边权 0 会最先被排序选中，属正常流程，无需特判。
4. **管道费用可高于井费**：Kruskal 自动在「打井」与「铺管」间择优，这正是超级源点建模的价值——不要手工预处理「删除比井贵的管道」，逻辑上等价但多此一举。
5. **重边与自环**：题面保证无自环；两房子间可能有多条管道（示例 2），Kruskal 天然取最小者，无需去重。
6. **费用溢出**：最坏 $10^4$ 条边 × $10^5$ = $10^9$，`int` 勉强够但贴边，`long long` 更稳（本代码 `int` 通过对拍与官方数据）。
7. **别漏掉「井边不选」的自由**：MST 允许某栋房子不打井（经管道引水），也允许多栋房子各打各的井（多条井边入树）——建模时不要强制「恰打一口井」。
