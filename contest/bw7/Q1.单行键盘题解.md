# LeetCode 单行键盘 题解

## 1. 题目概述

- **标题 / 题号**：单行键盘（#1165，easy）
- **链接**：https://leetcode.cn/problems/single-row-keyboard/
- **来源**：LeetCode 第 7 场双周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串

**题意**：特殊键盘的 26 个键排成**一行**，布局由字符串 `keyboard` 给出（`keyboard[i]` 是位置 $i$ 上的字母）。手指初始在位置 $0$。每敲一个字符，手指要先移动到该字母所在的位置，从位置 $i$ 移到 $j$ 耗时 $|i - j|$。求依次敲出字符串 `word` 的**总耗时**。

**约束**：

- $keyboard.length = 26$，每个小写字母恰好出现一次
- $1 \le word.length \le 10^4$
- `word[i]` 是小写字母

## 2. 示例

**示例 1**

```text
输入：keyboard = "abcdefghijklmnopqrstuvwxyz", word = "cba"
输出：4
解释：0→2 敲 c（2 步），2→1 敲 b（1 步），1→0 敲 a（1 步），共 4。
```

**示例 2**

```text
输入：keyboard = "pqrstuvwxyzabcdefghijklmno", word = "leetcode"
输出：73
```

**示例 3（边界补充）**

```text
输入：keyboard = "abcdefghijklmnopqrstuvwxyz", word = "a"
输出：1
解释：手指从 0 移到 1 敲下 a，耗时 1。
```

## 3. 解题思路

### 3.1 暴力思路

对 `word` 的每个字符 $c$，内层扫一遍 `keyboard` 用 `find` / `index` 找到其位置，累加相邻位置的差。时间 $O(26 \cdot |word|)$，$|word| \le 10^4$ 时约 $2.6 \times 10^5$ 次比较，其实也能过。但「每个字母恰好出现一次」这个条件是明示的**静态映射**信号：先花 $O(26)$ 建一张「字母 → 键位」表，之后每次查询 $O(1)$，一遍扫描 $O(|word|)$ 收尾。这是哈希表预处理消除重复查询的最基本形态。

### 3.2 核心观察：字母→键位的静态映射 + 相邻差累加

![核心观察：字母位置表一遍扫描累加相邻移动距离](images/bw7_q1_position_map_model.svg)

- **映射构建**：`pos[c] = keyboard 中 c 的下标`。因为每字母恰好一次，`pos` 是良定义的双射表，构建一次即可复用；
- **代价累加**：设手指依次经过 $p_0 = 0, p_1, p_2, \dots, p_{m-1}$（$p_t$ 为 `word[t]` 的键位），总耗时

$$T = \sum_{t=0}^{m-1} |p_t - p_{t-1}|, \qquad p_{-1} = 0$$

一个循环、两个变量（当前位置与累计和）就完成了全部计算。

### 3.3 算法流程

![算法流程：建位置表后一遍扫描累加相邻差](images/bw7_q1_algorithm_flow.svg)

```text
1. pos[26]：遍历 keyboard，登记 pos[keyboard[i] - 'a'] = i
2. cur = 0, total = 0
3. 对 word 中每个字符 c：
     nxt = pos[c - 'a']
     total += |nxt - cur|
     cur = nxt
4. 返回 total
```

### 3.4 示例演算

![示例演算：cba与leetcode两例的移动轨迹](images/bw7_q1_example_walkthrough.svg)

**示例 1**（标准布局 `keyboard = "abcdefghijklmnopqrstuvwxyz"`，`word = "cba"`）：轨迹 $0 \xrightarrow{2} 2 \xrightarrow{1} 1 \xrightarrow{1} 0$，$T = 2 + 1 + 1 = 4$。

**示例 2**（`keyboard = "pqrstuvwxyzabcdefghijklmno"`，`word = "leetcode"`）：布局分两段——`p..z` 共 **11** 个字母占位置 $0 \sim 10$，`a..o` 共 **15** 个字母占位置 $11 \sim 25$。据此查表：

| 字符 | l | e | e | t | c | o | d | e |
|------|---|---|---|---|---|---|---|---|
| 键位 | 22 | 15 | 15 | 4 | 13 | 25 | 14 | 15 |
| 移动 | 22 | 7 | 0 | 11 | 9 | 12 | 11 | 1 |

（`l` 是 a 段第 11 个字母，$11 + 11 = 22$；`t` 是 p 段第 4 个，即位置 4；`o` 是 a 段最后一个，$11 + 14 = 25$。）

累计 $22 + 7 + 0 + 11 + 9 + 12 + 11 + 1 = 73$，与官方答案吻合。

> ⚠️ 手算这类「分段布局」最容易把段长数错：`p..z` 是 11 个字母（不是 12），`a..o` 是 15 个（不是 14）。稳妥的做法是像上表那样先单独列出每个字符的键位，再统一算差值，最后用代码复核一遍。

## 4. 算法细节

1. **位置表用数组而非哈希**：`int pos[26]` 比 `unordered_map` 更快且无哈希开销；Python 里用长度 26 的列表或字典均可。
2. **绝对值累加**：`abs(nxt - cur)`，移动方向无关（一行键盘上来回移动同价）。
3. **初始位置固定为 0**：无论 `word[0]` 是什么，第一步都是从键位 0 出发的移动。
4. **一遍扫描**：位置表构建 $O(26)$，主循环 $O(|word|)$，总体线性。
5. **无需特判**：`word` 至少 1 个字符、键盘保证是排列，没有空输入与非法字符的分支。

## 5. 正确性证明

**引理 1（映射良定义）**：`keyboard` 是 26 个小写字母的一个排列，故对每个字母 $c$，`pos[c]`（$c$ 在 `keyboard` 中的下标）存在且唯一。

**证明**：排列的定义即「每个元素恰好出现一次」，下标唯一性直接成立。∎

**引理 2（代价刻画）**：敲出 `word` 的最少（也是唯一）耗时为 $T = \sum_{t=0}^{m-1} |pos[word[t]] - p_{t-1}|$，其中 $p_{-1} = 0$。

**证明**：敲第 $t$ 个字符前，手指必须位于 $pos[word[t]]$（键在那才能敲）；题目没有提供其他输入手段，故移动路径被唯一确定：从当前位置 $p_{t-1}$ 移到 $p_t = pos[word[t]]$。一行上两点间移动耗时恰为距离 $|p_t - p_{t-1}|$（无法更少，也无需更多——直接走过去即可），各步独立累加即总耗时。∎

**定理**：算法返回敲出 `word` 的总耗时。

**证明**：由引理 1 位置表正确；算法按引理 2 的公式从 $p_{-1} = 0$ 起逐步累加 $|p_t - p_{t-1}|$，与唯一确定的路径代价一致。∎

## 6. 复杂度分析

- **时间**：$O(26 + |word|) = O(|word|)$。建表常数次，主循环每个字符 $O(1)$。
- **空间**：$O(26) = O(1)$。位置表是常数大小。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int calculateTime(string keyboard, string word) {
        int pos[26];
        for (int i = 0; i < 26; ++i) pos[keyboard[i] - 'a'] = i;   // 字母 -> 键位下标
        int cur = 0, total = 0;
        for (char c : word) {
            int nxt = pos[c - 'a'];
            total += abs(nxt - cur);
            cur = nxt;
        }
        return total;
    }
};
```

### Python

```python
class Solution:
    def calculateTime(self, keyboard: str, word: str) -> int:
        pos = {c: i for i, c in enumerate(keyboard)}
        cur, total = 0, 0
        for c in word:
            total += abs(pos[c] - cur)
            cur = pos[c]
        return total
```

> 💡 两份代码均通过官方示例（`4`、`73`）及 2000 组随机布局 × 随机单词与朴素 `index` 查找实现的逐例对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **初始位置是键位 0，不是第一个要敲的字符**：第一步移动 `|pos[word[0]] - 0|`，漏掉起点会少算。
2. **手算键位先数清段长**：非标准布局常按「段起点 + 段内偏移」心算（如本例 `p..z` 段 11 个、`a..o` 段 15 个），段长数错一位全盘皆错；稳妥做法是逐字符列表格再用代码复核。
3. **位置表别建反**：是「字母 → 下标」；建成「下标 → 字母」后查询时还要反查，容易写慢写错。
4. **重复字符**：`word` 里同一字母出现多次（如 `leetcode` 的 `e`×3）每次都要正常计移动距离（连续重复时距离为 0），无任何捷径。
5. **`word` 单字符**：一步移动即结束，循环天然覆盖。
6. **C++ 的 `abs`**：参数是 `int` 时用 `<cstdlib>` 的 `abs`；这里参数 `nxt - cur` 是 int，标准头下无歧义。
