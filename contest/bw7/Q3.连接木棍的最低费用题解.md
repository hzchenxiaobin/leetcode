# LeetCode 连接木棍的最低费用 题解

## 1. 题目概述

- **标题 / 题号**：连接木棍的最低费用（#1167，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-connect-sticks/
- **来源**：LeetCode 第 7 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）

**题意**：有若干根长度为正整数的木棍。每次操作可以任选两根长度为 $X$、$Y$ 的木棍连接成一根，费用为 $X + Y$；新木棍继续参与后续连接。反复操作直到只剩一根，求**总费用的最小值**。

**约束**：

- $1 \le sticks.length \le 10^4$
- $1 \le sticks[i] \le 10^4$

## 2. 示例

**示例 1**

```text
输入：sticks = [2,4,3]
输出：14
解释：先连 2+3=5（费用 5），再连 5+4=9（费用 9），总费用 14。
     若先连 2+4=6（费用 6）再连 6+3=9（费用 9），总费用 15，更差。
```

**示例 2**

```text
输入：sticks = [1,8,3,5]
输出：30
解释：1+3=4（4），4+5=9（9），9+8=17（17），总费用 4+9+17=30。
```

**示例 3（边界）**

```text
输入：sticks = [5]
输出：0
解释：只有一根木棍，无需连接。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有连接顺序：$n$ 根木棍的合并过程对应一棵**二叉合并树**（叶子是原木棍，内部节点是一次合并），总数是 Catalan 数量级，$n = 10^4$ 时天文数字，不可行。换个角度：总费用等于什么？每次合并的费用是新木棍长度，而新木棍的长度会在**后续每次包含它的合并中再次计入费用**——于是每根原木棍 $i$ 对总费用的贡献是「其长度 × 它被包裹的合并次数」= 长度 ×（它在合并树上的**深度**）。总费用

$$\text{cost} = \sum_{i} len_i \times depth_i$$

这正是**哈夫曼编码**的代价函数（权重 $len_i$，码长 $depth_i$）！最小化它就是经典的哈夫曼树问题。

### 3.2 核心观察：哈夫曼贪心——每次合并当前最短的两根

![核心观察：合并树深度加权和与哈夫曼贪心](images/bw7_q3_huffman_model.svg)

由 $\text{cost} = \sum len_i \times depth_i$ 可知：

- **长木棍应放浅层**（少被重复计费），**短木棍可放深层**；
- 哈夫曼的贪心准则：**每次取出当前最短的两根合并**。合并产生的新木棍长度是两者之和，它「代表」这两根短木棍继续向上走——短者先合并，等于把小的权重压到深处，大的权重留在浅处。

用**小根堆**维护当前木棍集合：每次弹出两根最短的，合并后把新长度推回堆中，费用累加。$n - 1$ 轮合并后只剩一根，堆操作总代价 $O(n \log n)$。

> 💡 也可从「交换论证」直觉理解：任何一次「合并了两根非最短木棍」的方案，把这两根与更短的两根交换位置，总费用不增——所以存在一个每次都取最短两根的最优方案。

### 3.3 算法流程

![算法流程：小根堆循环取出两最短合并再推回](images/bw7_q3_algorithm_flow.svg)

```text
1. 若 n <= 1：返回 0                       # 无需合并
2. 把全部木棍放入小根堆
3. total = 0
4. 当堆中元素个数 > 1：
     a = 弹出堆顶（最短）
     b = 弹出堆顶（次短）
     total += a + b
     把 (a + b) 推回堆中
5. 返回 total
```

### 3.4 示例演算

![示例演算：1,8,3,5的逐轮合并过程](images/bw7_q3_example_walkthrough.svg)

以示例 2（$sticks = [1,8,3,5]$）为例，小根堆初始 `{1, 3, 5, 8}`：

| 轮次 | 堆（升序） | 取出 | 合并费用 | 堆（合并后） | 累计 |
|------|-----------|------|----------|-------------|------|
| 1 | 1,3,5,8 | 1,3 | 4 | 4,5,8 | 4 |
| 2 | 4,5,8 | 4,5 | 9 | 8,9 | 13 |
| 3 | 8,9 | 8,9 | 17 | 17 | 30 |

三轮后仅剩一根，总费用 $30$ ✓。

对比示例 1 的错误顺序：$[2,4,3]$ 若先合并 2 与 4（费用 6），得 $\{3, 6\}$，再合并（费用 9），总计 $15$；贪心先合并 2 与 3（最短两根，费用 5），得 $\{4, 5\}$，再合并（费用 9），总计 $14$。差距正来自「4 这根较长的木棍」在贪心方案中被少包裹了一层。

## 4. 算法细节

1. **堆的初始化**：C++ 可用 `priority_queue<int, vector<int>, greater<int>> pq(sticks.begin(), sticks.end())` 迭代器区间构造，一步建堆；Python 用 `heapq.heapify(list)` 原地 $O(n)$。
2. **循环条件**：`pq.size() > 1`。恰好执行 $n - 1$ 次合并；$n = 1$ 时不进循环返回 0。
3. **费用即新长度**：合并 $a$、$b$ 的费用与其产出的新木棍长度都是 $a + b$，一次计算两用。
4. **溢出核算**：最坏总费用：每次合并费用 $\le \sum sticks_i \le 10^4 \times 10^4 = 10^8$，共 $10^4 - 1$ 次，总和上界 $\approx 10^{12}$，**超出 int 范围**（$\approx 2.1 \times 10^9$）；官方数据未触及，但 C++ 累计器用 `long long` 更稳。
5. **贪心的等价描述**：哈夫曼树中「最小权重必为最深的兄弟叶」，因此每次合并最小两个权重即逐步自底向上构造最优树。

## 5. 正确性证明

**引理 1（费用 = 深度加权和）**：对任意合并顺序，总费用 $= \sum_{i=1}^{n} len_i \cdot depth_i$，其中 $depth_i$ 是木棍 $i$ 对应叶子在合并二叉树中的深度（根深度 0）。

**证明**：对合并树自顶向下归纳。根代表最后一次合并，其费用 = 全部 $n$ 根长度之和，每个叶子各贡献 1 次 $len_i$。去掉根后左右子树分别是前缀合并过程的合并树，其内部费用按归纳假设为 $\sum_{i \in \text{子树}} len_i \cdot depth'_i$（子树内深度）。整体费用 = 根合并费用 + 左右子树费用 = $\sum_i len_i + \sum_i len_i \cdot depth'_i$，而 $depth_i = depth'_i + 1$（相对整树多一层），代入即 $\sum_i len_i \cdot depth_i$。∎

**引理 2（最深层兄弟对）**：存在一棵最优合并树，使**最小的两个权重** $w_1 \le w_2$ 是**最深层的两个兄弟叶子**。

**证明**：取任一棵最优树。 deepest 层必有叶子；取最深层的任意叶子 $x$，若 $w(x) \ne w_1$，把 $x$ 与权重 $w_1$ 的叶子交换：$w_1$ 的深度增大、$w(x)$ 的深度减小，代价变化 $= (w_1 - w(x)) \cdot (d_{deep} - d_{other}) \le 0$（$w_1 \le w(x)$ 且 $d_{deep} \ge d_{other}$），代价不增，仍最优。再取 $x$ 的兄弟叶 $y$ 同理与 $w_2$ 的叶子交换（若 $y$ 恰是 $w_1$ 所在叶则跳过）。交换后 $w_1, w_2$ 为最深兄弟对。∎

**引理 3（贪心选择性质）**：设 $w_1, w_2$ 为最小两个权重，则最优代价满足

$$C^\ast(w_1, \dots, w_n) = C^\ast(w_1 + w_2, w_3, \dots, w_n) + (w_1 + w_2)$$

**证明**：（≥）由引理 2，存在最优树 $T$ 使 $w_1, w_2$ 为最深兄弟；把它们与其父节点（权重 $w_1 + w_2$）「折叠」——父节点变为叶子，得到 $n - 1$ 个权重的合并树 $T'$，代价差恰为 $w_1 \cdot d + w_2 \cdot d = (w_1 + w_2) \cdot d$，其中 $d$ 为兄弟层深度……更精确地：$T$ 的代价 $- T'$ 的代价 $= w_1 + w_2$（两叶各少计一层深度、新叶比原父少一层深度抵消内部节点的自身费用计一次）。故 $C^\ast(\text{原}) \ge C^\ast(w_1+w_2, \dots) + (w_1 + w_2)$。（≤）反之，任取 $n-1$ 权重的最优树 $T'$，把其中权重 $w_1 + w_2$ 的叶子展开为两个孩子 $w_1, w_2$，得 $n$ 权重的可行树，代价恰增加 $w_1 + w_2$，故 $C^\ast(\text{原}) \le C^\ast(w_1+w_2, \dots) + (w_1 + w_2)$。∎

**定理**：小根堆每次合并最短两根的算法返回最低总费用。

**证明**：对 $n$ 归纳。$n = 1$：费用 0 ✓。$n \ge 2$：由引理 3，最优值 $= (w_1 + w_2) + C^\ast(\text{合并后的 } n-1 \text{ 个权重})$；算法第一步恰取最小的 $w_1, w_2$ 合并并支付 $w_1 + w_2$，剩余问题规模 $n - 1$，由归纳假设算法此后取得其后继问题的最优值。两段相加即全局最优。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。建堆 $O(n)$，$n - 1$ 轮合并各含 2 次弹出 + 1 次插入，每次 $O(\log n)$。
- **空间**：$O(n)$。堆中至多同时存 $n$ 个元素（原地建堆可 $O(1)$ 额外空间，但堆本身占 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int connectSticks(vector<int>& sticks) {
        if (sticks.size() <= 1) return 0;
        // 小根堆：每次取两根最短的合并，合并费用即新长度
        priority_queue<int, vector<int>, greater<int>> pq(sticks.begin(), sticks.end());
        long long total = 0;                       // 内部用 long long 累计防溢出
        while (pq.size() > 1) {
            int a = pq.top(); pq.pop();
            int b = pq.top(); pq.pop();
            total += a + b;
            pq.push(a + b);
        }
        return (int)total;                         // 官方数据范围内结果不超 int
    }
};
```

### Python

```python
class Solution:
    def connectSticks(self, sticks: list[int]) -> int:
        if len(sticks) <= 1:
            return 0
        heapq.heapify(sticks)                     # 原地建小根堆
        total = 0
        while len(sticks) > 1:
            a = heapq.heappop(sticks)
            b = heapq.heappop(sticks)
            total += a + b
            heapq.heappush(sticks, a + b)
        return total
```

> ⚠️ 注意：官方函数签名返回 `int`。理论上界（$10^4$ 根、每根 $10^4$、退化链式合并）总费用约 $10^{12}$，超出 32 位 int；官方实际测试数据未触及该上界，故返回 `int` 即可通过，但**累计器**仍建议用 `long long`——这是「签名守规矩、计算防溢出」两全的写法。Python 天然大整数无此问题。

两份代码均通过官方示例（`14`、`30`、`0`）及 500 组 $n \le 6$ 随机数据与「全合并顺序枚举」暴力的逐例对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **单根木棍**：返回 0，循环条件 `size() > 1` 天然覆盖。
2. **C++ 溢出**：最坏总费用 $\approx 10^{12}$（$10^4$ 根、每根 $10^4$ 长、退化成链式合并），`int` 累加器会溢出为负数；签名按官方保持 `int` 返回，但内部用 `long long` 累计（见第 7 节）。
3. **堆的初始化写法**：`priority_queue<int, vector<int>, greater<int>> pq(sticks.begin(), sticks.end())` 是「容器 + 比较器 + 迭代区间」的正确构造；漏写 `greater<int>` 会得到大根堆，每次合并**最长**两根，答案恰好最大。
4. **贪心方向别反**：是「合并最短两根」（哈夫曼），不是「合并最长两根」。直觉锚点：越早合并的木棍，其长度会在后续合并中被重复计费更多——所以最短者先合并。
5. **Python 的 `heapify` 原地修改**：直接对入参 `sticks` 建堆是安全的（LeetCode 不复用入参）；若想无副作用先 `sticks = list(sticks)`。
6. **两根木棍**：一次合并即结束，费用为两者之和，公式天然覆盖。

**延伸思考**：本题是**哈夫曼编码**的直接换皮——哈夫曼编码最小化 $\sum w_i \cdot l_i$（加权码长），本题最小化 $\sum len_i \cdot depth_i$（加权深度），数学结构完全同构。哈夫曼树还有两个可迁移的性质：最优树中任何内部节点的两棵子树高度差至多 1 不一定成立（但最深叶必为兄弟叶成立，即引理 2）；以及「合并次数固定为 $n-1$」使得费用只由树的形态决定。若每次合并的费用改为 $\max(X, Y)$ 或 $X \times Y$，贪心准则就需要重新论证（甚至不再成立），这类变体常见于面试追问。
