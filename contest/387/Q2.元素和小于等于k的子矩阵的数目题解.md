# LeetCode 元素和小于等于 k 的子矩阵的数目 题解

## 1. 题目概述

- **标题 / 题号**：元素和小于等于 k 的子矩阵的数目（#3070，medium）
- **链接**：https://leetcode.cn/problems/count-submatrices-with-top-left-element-and-sum-less-than-k/
- **来源**：LeetCode 第 387 场周赛 Q2
- **难度**：中等
- **标签**：数组、矩阵、前缀和、单调剪枝

**题意**：给定 $m \times n$ 的非负整数矩阵 `grid` 与整数 $k$，统计同时满足以下两个条件的**子矩阵**（连续矩形区域）个数：

1. 包含左上角元素 `grid[0][0]`；
2. 元素和 $\le k$。

**约束**：

- $1 \le m, n \le 1000$（候选规模至多 $10^6$，必须是近线性做法）
- $0 \le \text{grid}[i][j] \le 1000$（**非负**是第二个关键条件）
- $1 \le k \le 10^9$（全矩阵和上限恰为 $10^9$，贴近 `int` 上限）

> 💡 读题抓两点：**「包含左上角」**直接砍掉子矩阵四个自由度中的两个——这是难度骤降的机关；**「元素非负」**保证前缀和单调，使行内可以提前 break。两个条件叠加，本题从 $O(m^2 n^2)$ 级的矩形计数题坍缩成 $O(mn)$ 的一趟扫描。

## 3. 解题思路

### 3.1 暴力思路

子矩阵由「上、下、左、右」四个边界决定，任意子矩阵计数是 $O(m^2 n^2)$ 个候选；$m, n \le 1000$ 时高达 $10^{12}$，即使每个候选用前缀和 $O(1)$ 查询也无法承受，逐个求和更是 $O(m^3 n^3)$。

但题目限定**必须包含左上角**：子矩阵是连续矩形，行区间与列区间都必须包含 0，只能形如 $[0..i] \times [0..j]$——**四个自由度塌缩成右下角一个点**，候选骤减为 $O(mn)$ 个。剩下的问题只有一个：如何 $O(1)$ 地知道每个右下角对应的和。

### 3.2 核心观察：右下角唯一确定子矩阵，和恰为二维前缀和

![核心观察：含左上角的子矩阵与右下角一一对应](images/count_submatrices_concept.svg)

三个环环相扣的观察：

1. **双射**：含 `(0,0)` 的子矩阵 ↔ 右下角 $(i, j)$，一一对应（引理 1）。答案就是满足 $P[i][j] \le k$ 的格子数，其中 $P[i][j] = \sum_{r \le i,\, c \le j} \text{grid}[r][c]$ 正是**二维前缀和**。
2. **非负 ⇒ 单调 ⇒ 行前缀**：$\text{grid}[i][j] \ge 0$ 使固定行内 $P[i][j]$ 随 $j$ 单调不减，于是每行的合格格子必是一段**前缀**——行内从左到右累加，一旦 $s > k$ 立即 break，同行右侧全部无需再看。
3. **一维滚动代替二维表**：访问顺序恰好「逐行、行内从左到右」，与「列前缀和滚动 + 行内累加」的节奏完全对齐：

$$\underbrace{\text{col}[j] = \sum_{r \le i} \text{grid}[r][j]}_{\text{列方向：逐行滚动}} \quad\Longrightarrow\quad P[i][j] = \sum_{c \le j} \text{col}[c]\ \text{（行方向：累加）}$$

   无需容斥公式，空间从 $O(mn)$ 降到 $O(n)$，且与 break 剪枝天然兼容。

> ⚠️ **溢出提醒**：全矩阵和最大 $1000 \times 1000 \times 1000 = 10^9$，贴近 `int` 上限（约 $2.1 \times 10^9$）。C++ 中 `col` 与 `s` 直接用 `long long` 最稳；Python 无此顾虑。

### 3.3 算法流程

![算法流程：一维列前缀和滚动加行内 break](images/count_submatrices_flow.svg)

```text
col[0..n-1] ← 0                         # 列前缀和（滚动）
ans ← 0
for i ← 0 to m-1:                       # 外层：逐行
    s ← 0                               # 行内累加器
    for j ← 0 to n-1:                   # 内层：行内从左到右
        col[j] += grid[i][j]            # 列 j 滚动进第 i 行（先更新）
        s += col[j]                     # 此刻 s = P[i][j]
        if s > k: break                 # 非负 ⇒ 同行右侧必然超标
        ans ← ans + 1
return ans
```

### 3.4 示例演算

![示例演算：k=20 的逐行扫描与阶梯形合格区域](images/count_submatrices_walkthrough.svg)

以示例 2 `grid = [[7,2,9],[1,5,0],[2,6,6]]`、$k = 20$ 走查：

| 行 $i$ | 处理后 `col[]` | 行内 $s$ 依次取值 | 本行计数 |
|--------|---------------|-------------------|---------|
| 0 | $[7, 2, 9]$ | $7$✓，$9$✓，$18$✓ | 3 |
| 1 | $[8, 7, 9]$ | $8$✓，$15$✓，$24$✗ → break | 2 |
| 2 | $[10, 13, 15]$ | $10$✓，$21$✗ → break | 1 |

答案 $= 3 + 2 + 1 = 6$ ✓。注意两个细节：行 2 的第 2、3 格压根没被访问；绿色合格区域呈**阶梯形**逐行收窄——这正是「列方向也单调」（$P[i][j] \ge P[i-1][j]$）的直观体现。

## 4. 算法细节

1. **col 与 s 的分工**：`col[j]` 维护「第 $j$ 列、第 $0 \sim i$ 行的纵向和」，行内累加器 $s$ 把 $\text{col}[0..j]$ 横向求和。两个一维动作（列方向滚动、行方向累加）拼出整个二维前缀和，且顺序与扫描顺序严格对齐，全程无需容斥公式。
2. **更新先于判断**：`col[j] += grid[i][j]` 必须发生在 `s > k` 判断**之前**（本行该列的贡献不能漏），循环体内三条语句的顺序不可交换。
3. **break 的「懒惰更新」是安全的**：break 跳出后，本行剩余列的 `col` 没有加上当前行贡献，看似留下脏数据——但由阶梯单调性（引理 3），下一行的 break 位置只会更靠左，**永远读不到那些未更新的列**（严格论证见 §5 定理证明的 (b) 段）。
4. **不建二维前缀和表的理由**：$O(mn)$ 的表要 4~8 MB 且要写容斥公式；滚动版 $O(n)$ 空间、零容斥。若追求 $O(1)$ 额外空间也可原地改写 `grid` 存 $P$，但破坏输入且数值贴近 `int` 上限，得不偿失。
5. **可选的小优化**：若某行在 $j = 0$ 就超标（$P[i][0] > k$），则其后所有行的第 0 列只会更大、整行必然全灭，可直接 `return ans`。这种情况真实存在：$k \ge 1$ 而 `grid[0][0]` 可达 1000，答案可以为 0。

## 5. 正确性证明

**引理 1（双射）**：含 `(0,0)` 的子矩阵与右下角坐标 $(i, j)$（$0 \le i < m$，$0 \le j < n$）一一对应。

**证明**：子矩阵是连续矩形区域，等于行区间 $[r_1, r_2]$ 与列区间 $[c_1, c_2]$ 的笛卡尔积。它包含 $(0,0)$ 当且仅当 $r_1 \le 0 \le r_2$ 且 $c_1 \le 0 \le c_2$；由下标非负知 $r_1, c_1 \ge 0$，故 $r_1 = c_1 = 0$。于是子矩阵由 $(r_2, c_2) = (i, j)$ 唯一确定；反过来每个 $(i, j)$ 恰好给出一个这样的子矩阵 $[0..i] \times [0..j]$。∎

**引理 2（扫描不变量）**：第 $i$ 行内层循环处理完第 $j$ 列时（无论是否随后 break），$s = P[i][j]$，且 $\text{col}[0..j]$ 已包含第 $i$ 行的贡献。

**证明**：对 $i$ 归纳。行间：设第 $i-1$ 行结束时对所有被访问过的 $j$ 有 $\text{col}[j] = \sum_{r \le i-1} \text{grid}[r][j]$；第 $i$ 行访问 $j$ 时**先执行** $\text{col}[j] \mathrel{+}= \text{grid}[i][j]$，故访问后 $\text{col}[j] = \sum_{r \le i} \text{grid}[r][j]$。行内：$s$ 从 0 起依次累加 $\text{col}[0], \dots, \text{col}[j]$，故 $s = \sum_{c \le j} \sum_{r \le i} \text{grid}[r][c] = P[i][j]$。∎

**引理 3（单调性与阶梯形）**：元素非负时，固定行 $i$ 有 $P[i][j] \le P[i][j+1]$，固定列 $j$ 有 $P[i][j] \le P[i+1][j]$；从而每行的 break 位置 $b_i$ 随 $i$ 单调不增。

**证明**：$P[i][j+1] - P[i][j] = \sum_{r \le i} \text{grid}[r][j+1] \ge 0$，$P[i+1][j] - P[i][j] = \text{grid}[i+1][j] \ge 0$，单调性得证。若第 $i$ 行在 $b_i$ 处 break，即 $P[i][b_i] > k$，则 $P[i+1][b_i] \ge P[i][b_i] > k$，故第 $i+1$ 行至多扫到 $b_i$ 即 break，$b_{i+1} \le b_i$。∎

**定理（计数正确）**：算法返回值恰为满足条件的子矩阵个数。

**证明**：由引理 1，所求个数 $= \left| \{(i,j) : P[i][j] \le k\} \right|$。算法每访问一个格子 $(i,j)$，由引理 2 其判断的正是 $P[i][j] \le k$，访问到的格子计数无偏差。还需说明不重不漏：

（a）**break 不漏**：由引理 3，$P[i][j] > k$ 时同行更右的 $j'$ 满足 $P[i][j'] \ge P[i][j] > k$，跳过它们不损失任何合法解；

（b）**懒惰更新不脏读**：第 $i$ 行只更新了 $\text{col}[0..b_i]$，但第 $i+1$ 行只访问列号 $\le b_{i+1} \le b_i$ 的格子（引理 3），归纳可知任何被读取的 `col[j]` 都已完成包含当前行在内的全部累加，引理 2 的前提在每一行都成立。

综上，每个合法子矩阵（即每个合法右下角）恰好被计数一次。∎

## 6. 复杂度分析

- **时间复杂度**：$O(mn)$。最坏情况（如全 0 矩阵、$k$ 极大）每个格子访问一次、每次 $O(1)$；一般情形下 break 剪枝使实际访问量远小于上界——合格前缀越短，剪得越狠。
- **空间复杂度**：$O(n)$，即一维列前缀和数组 `col`（不计输入）。若预建完整二维前缀和表则为 $O(mn)$（4~8 MB），滚动版明显更优。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int countSubmatrices(vector<vector<int>>& grid, int k) {
        int m = grid.size(), n = grid[0].size();
        vector<long long> col(n, 0);          // col[j]：第 j 列从第 0 行到当前行的和
        int ans = 0;
        for (int i = 0; i < m; i++) {
            long long s = 0;                  // 行内累加，s = P[i][j]
            for (int j = 0; j < n; j++) {
                col[j] += grid[i][j];         // 更新先于判断
                s += col[j];
                if (s > k) break;             // 非负 ⇒ 同行更右必然超标
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countSubmatrices(self, grid: List[List[int]], k: int) -> int:
        n = len(grid[0])
        col = [0] * n                    # col[j]：第 j 列从第 0 行到当前行的和
        ans = 0
        for row in grid:
            s = 0                        # 行内累加，s = P[i][j]
            for j, x in enumerate(row):
                col[j] += x              # 更新先于判断
                s += col[j]
                if s > k:                # 非负 ⇒ 同行更右必然超标
                    break
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **数对对象**：必须「包含左上角」，不是任意子矩阵。忽略这一条件做 $O(m^2 n^2)$ 枚举直接 TLE；把 1074 那套行压缩 + 哈希搬来则既超时又答错对象。
2. **break 只跳出本行**：写在**内层**循环；不要因某行超标就整体 `return`——下一行的合格前缀可能仍在（只是宽度不增）。若确要提前终止，正确姿势是「某行在 $j=0$ 即超标才可整体返回」（见 §4 第 5 点）。
3. **C++ 溢出**：全矩阵和上限 $10^9$，贴 `int` 上限；`col` 与 `s` 用 `long long`。`s` 与 `int` 型 `k` 比较会自动提升，无碍，但 `s` 本身别声明成 `int`。
4. **答案可以为 0**：如 `grid = [[1000]]`、`k = 1`——首格即超标。$k \ge 1$ 不保证 `grid[0][0] ≤ k`。
5. **元素可为 0**：单调是**不严格**的（$P$ 可相等），break 条件必须是 `s > k`（$\le k$ 一律计入）；0 值不会破坏「合格段是前缀」的性质。
6. **break 后 `col` 尾部「漏加」当前行不是 bug**：由阶梯单调性，后续行 break 更早，永远读不到未更新的列（§5 定理 (b) 段）。若不放心可先整行更新再扫描，但会失去剪枝收益。
7. **单行 / 单列矩阵**：$m = 1$ 或 $n = 1$ 退化为数组前缀和，算法天然覆盖，无需特判。
8. **「子矩阵」是连续矩形**：这正是引理 1 成立的前提；若题面改成「任意包含 `(0,0)` 的格子集合」，双射与单调性全部失效，是完全不同的另一道题。
