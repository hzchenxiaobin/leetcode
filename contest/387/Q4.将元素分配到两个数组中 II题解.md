# LeetCode 将元素分配到两个数组中 II 题解

## 1. 题目概述

- **标题 / 题号**：将元素分配到两个数组中 II（#3072，hard）
- **链接**：https://leetcode.cn/problems/distribute-elements-into-two-arrays-ii/
- **来源**：LeetCode 第 387 场周赛 Q4
- **难度**：困难
- **标签**：树状数组、线段树、数组、模拟

**题意**：给定下标从 1 开始、长度为 $n$ 的整数数组 `nums`。定义 $\text{greaterCount}(arr, val)$ 为 `arr` 中**严格大于** $val$ 的元素个数。用 $n$ 次操作把所有元素分进两个数组：第 1、2 次固定把 `nums[1]`、`nums[2]` 分别追加到 `arr1`、`arr2`；第 $i$（$i \ge 3$）次比较 $\text{greaterCount}(\text{arr1}, \text{nums}[i])$ 与 $\text{greaterCount}(\text{arr2}, \text{nums}[i])$：大者胜出接纳该元素；相等时归**元素更少**的一方；仍相等归 `arr1`。返回连接 $\text{arr1} + \text{arr2}$ 得到的 `result`。

**约束**：

- $3 \le n \le 10^5$——每次操作都要对两个数组计数，暴力 $O(n^2)$ 高达 $10^{10}$，必须压到 $O(n \log n)$
- $1 \le \text{nums}[i] \le 10^9$——值域开桶不可行，需要离散化
- 与 Q1（#3069）不同，**元素可以重复**——「严格大于」的边界处理是隐藏坑

> 💡 读题抓对照：同场 Q1 比较的是两个数组的**尾元素**，$O(1)$ 决策纯模拟；Q4 把决策依据换成「双侧**严格大于计数**」，要对两个不断追加元素的动态集合反复执行「计数查询 + 插入」。「单点修改 + 前缀查询」交替出现，正是树状数组 / 线段树的标准信号。

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,3,3]
输出：[2,3,1,3]

解释：① ② 固定后 arr1 = [2]，arr2 = [1]。
  ③ x = 3：两侧大于 3 的个数都是 0（0 = 0），且等长（1 = 1）→ 归 arr1；
  ④ x = 3：仍都为 0，但 |arr1| = 2 ＞ |arr2| = 1 → 归更短的 arr2。
  最终 arr1 = [2,3]，arr2 = [1,3]，result = [2,3,1,3]。
```

**示例 2**

```text
输入：nums = [5,14,3,1,2]
输出：[5,3,1,2,14]

解释：③ x = 3：两侧大于 3 的个数都是 1（5 与 14），等长 → 归 arr1；
  ④ x = 1：arr1 有 2 个（5、3）、arr2 有 1 个（14）→ 2 ＞ 1 归 arr1；
  ⑤ x = 2：arr1 有 2 个（5、3）、arr2 有 1 个（14）→ 归 arr1。
  最终 arr1 = [5,3,1,2]，arr2 = [14]。
```

**示例 3**（覆盖「全部重复值」）

```text
输入：nums = [3,3,3,3]
输出：[3,3,3,3]

解释：任何时刻两侧「严格大于 3」的个数都是 0，全程走平局分支：
  ③ 等长归 arr1；④ arr2 更短归 arr2。最终 arr1 = [3,3]，arr2 = [3,3]。
```

**示例 4**（自造，覆盖「$c_1 < c_2$ 入 arr2」分支）

```text
输入：nums = [1,5,2,0]
输出：[1,5,2,0]

解释：③ x = 2：arr1 中大于 2 的个数为 0，arr2 中为 1（元素 5）→ 0 ＜ 1 归 arr2；
  ④ x = 0：1 ＜ 2 继续归 arr2。最终 arr1 = [1]，arr2 = [5,2,0]。
```

## 3. 解题思路

### 3.1 暴力思路

按题意逐步模拟：第 $i$ 次操作时，线性扫描 `arr1`、`arr2` 各数一遍「严格大于 `nums[i]`」的元素个数，再按规则归类。单次计数 $O(\text{len})$、共 $n$ 次，总计 $O(n^2)$；$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。

瓶颈定位清晰：**查询 $O(\text{len})$ × 查询次数 $n$，且每次查询后紧跟一次插入**。要让「计数」与「插入」都降到 $O(\log n)$，树状数组（BIT）是代码量最小的选择。

> ⚠️ 另一个直觉陷阱是「有序数组 + 二分」：二分查询确实 $O(\log n)$，但**中间插入**要整体搬移 $O(n)$，总计仍退回 $O(n^2)$。需要「既有序、又可动态插入」时，BIT / 线段树 / 平衡树才是正解。

### 3.2 核心观察：减法公式 + 离散化 + 双树状数组

![核心观察：严格大于 x 的个数 = 长度 − 「值 ≤ x」的前缀计数](images/distribute_arrays_ii_concept.svg)

**观察 1：把「严格大于」翻译成减法。** 任意时刻数组元素要么 $\le x$ 要么 $> x$，于是

$$\text{greaterCount}(arr, x) = |arr| - \#\{v \in arr : v \le x\}$$

$|arr|$ 就是当前长度，用变量 $O(1)$ 维护；$\#\{v \le x\}$ 是**值域上的频次前缀和**——只需要一个能按值计数、支持前缀查询的结构。

**观察 2：值域 $10^9$，但询问只涉及 `nums` 中的值——离散化。** 把 `nums` 排序去重得 `sorted`，每个值映射为名次 $\text{rank}(x) \in [1, m]$（$m \le n$ 为不同值个数）。离散化是**保序映射**：$x \le y \iff \text{rank}(x) \le \text{rank}(y)$，于是「值 $\le x$」等价于「名次 $\le \text{rank}(x)$」，桶数组只需开 $m$ 个。`nums` 开局全量给出，所有可能被询问的值集合已知——**离线离散化、在线模拟**两不相误。

**观察 3：「一插两查」交替进行，树状数组 × 2。** 给 `arr1`、`arr2` 各配一棵维护**名次频次**的 BIT：插入 $x$ 即在 $\text{rank}(x)$ 处单点 $+1$；查询即取前缀 $\text{query}(\text{rank}(x))$。每轮操作（记 $r = \text{rank}(\text{nums}[i])$）：

$$c_1 = \text{len}_1 - \text{query}(\text{tree}_1, r), \qquad c_2 = \text{len}_2 - \text{query}(\text{tree}_2, r)$$

比较 $c_1, c_2$ 决定去向，插入后同步 `update` 对应的树。

> 💡 **重复值为什么天然正确**：相等的值共享同一名次，$\text{query}(r)$ 恰好把所有等于 $x$ 的元素数进「$\le x$」一侧，随后被减法整体剔除——「严格大于」的边界**不需要任何特判**。这正是示例 3（全 3）能全程走平局分支的原因。

### 3.3 算法流程

![第 i 次操作的决策流程](images/distribute_arrays_ii_flow.svg)

```text
1. 离散化：sorted ← nums 排序去重；rank ← 值 → 名次的映射（从 1 开始）
2. 初始化：arr1 = [nums[0]]，arr2 = [nums[1]]，
   两棵 BIT 分别在 rank(nums[0])、rank(nums[1]) 处 +1
3. 模拟 i = 2 … n−1（0 下标）：
     r ← rank(nums[i])
     c1 ← len1 − query(tree1, r)；c2 ← len2 − query(tree2, r)
     若 c1 > c2 或（c1 = c2 且 len1 ≤ len2）：nums[i] 入 arr1，update(tree1, r)
     否则：nums[i] 入 arr2，update(tree2, r)
4. 返回 arr1 + arr2
```

> ⚠️ 平局规则是一条**两级链**：先比 greaterCount（$c_1$ vs $c_2$），相等再比长度，长度也相等归 `arr1`。合并成一个布尔条件：「入 arr1 $\iff c_1 > c_2$ **或**（$c_1 = c_2$ 且 $\text{len}_1 \le \text{len}_2$）」，注意 $\le$ 的等号正是「等长归 arr1」。

### 3.4 示例演算

![示例 2 演算：逐步计算 c1 与 c2](images/distribute_arrays_ii_walkthrough.svg)

以示例 2 `nums = [5,14,3,1,2]` 走查。离散化 `sorted = [1,2,3,5,14]`，$\text{rank}$：$1{\to}1$、$2{\to}2$、$3{\to}3$、$5{\to}4$、$14{\to}5$。

| 操作 | $x$（名次 $r$） | $c_1 = \text{len}_1 - q_1(r)$ | $c_2 = \text{len}_2 - q_2(r)$ | 判定 | 去向 |
|------|------|------|------|------|------|
| ① | 5（r=4） | — | — | 第 1 次规定 | arr1 |
| ② | 14（r=5） | — | — | 第 2 次规定 | arr2 |
| ③ | 3（r=3） | $1-0=1$ | $1-0=1$ | $1=1$ 且等长 → arr1 | arr1 |
| ④ | 1（r=1） | $2-0=2$ | $1-0=1$ | $2>1$ → arr1 | arr1 |
| ⑤ | 2（r=2） | $3-1=2$ | $1-0=1$ | $2>1$ → arr1 | arr1 |

三个关键瞬间：**③** 是平局链的完整展示（计数相等且等长归 arr1）；**⑤** 是减法公式的生效时刻——$q_1(2)$ 数出 arr1 中值 $\le 2$ 的元素恰为 1 个（只有值 1），于是 $c_1 = 3 - 1 = 2$；而 arr2 的 14 不受影响，$c_2 = 1$。最终 $\text{arr1} = [5,3,1,2]$、$\text{arr2} = [14]$，`result = [5,3,1,2,14]`，与官方输出一致。

## 4. 算法细节

1. **减法公式的两部分分开维护**：长度 $\text{len}_1, \text{len}_2$ 用普通计数变量 $O(1)$ 维护，绝不去树里求和；BIT 只负责名次频次的前缀计数。两棵树结构相同、互不影响。
2. **离散化的两种实现**：Python 用 `sorted(set(nums))` + 字典 $O(1)$ 查名次；C++ 用 `sort` + `unique` + `lower_bound` 二分查名次。名次从 1 开始（BIT 下标 $1 \dots m$）。
3. **BIT 的两条 lowbit 链**：`update` 沿 $i \mathrel{+}= i \,\&\, (-i)$ 向上更新所有覆盖 $i$ 的区间节点；`query` 沿 $i \mathrel{-}= i \,\&\, (-i)$ 把前缀 $[1, i]$ 拆成 $O(\log n)$ 个不重叠区间求和。两条链长度都是 $O(\log n)$，恰好匹配「每轮一插两查」的节奏。
4. **平局链合并为单条件**：入 arr1 $\iff c_1 > c_2 \lor (c_1 = c_2 \land \text{len}_1 \le \text{len}_2)$；其余入 arr2。两级判定顺序不可交换——先计数后长度，「等长归 arr1」由 $\le$ 的等号吸收。
5. **离线离散化可行性的来源**：`nums` 全量预知，询问值 $\text{nums}[i]$ 无论是否已出现在 arr1 / arr2 中，名次都已存在——离散化必须覆盖**全体** `nums`，而非「已插入部分」。
6. **等价替换**：线段树（单点 +1、区间 $[1, r]$ 求和）同样 $O(\log n)$；Python 的 `SortedList` 用 `bisect_right(x)` 直接得「$\le x$ 的个数」。本题选 BIT 因其代码最短。

## 5. 正确性证明

**引理 1（离散化的保序性）**：设 `sorted` 为 `nums` 去重后的严格递增序列，$\text{rank}(x)$ 为 $x$ 在其中的下标加 1。对任意 $v, x \in \text{nums}$：$v \le x \iff \text{rank}(v) \le \text{rank}(x)$；特别地，$v > x \iff \text{rank}(v) > \text{rank}(x)$。

**证明**：`sorted` 严格递增，故 rank 是「值 ↔ 下标」的保序双射（重复值共享同一名次）。若 $v \le x$：当 $v = x$ 时两者名次相等；当 $v < x$ 时 $v$ 在 `sorted` 中的下标严格小于 $x$ 的下标（严格递增序列中较小值必排在前面），故 $\text{rank}(v) < \text{rank}(x)$。反之，若 $\text{rank}(v) \le \text{rank}(x)$：下标不大于即值不大于（严格递增保证不同下标对应不同值且保序，相同下标即相同值），故 $v \le x$。两方向合并即得。∎

**引理 2（greaterCount 的计数公式）**：任意时刻，设 $\text{tree}_k$ 为 arr$_k$ 中全部已插入元素名次的频次 BIT，则

$$\text{greaterCount}(\text{arr}_k, x) = \text{len}_k - \text{query}(\text{tree}_k, \text{rank}(x)).$$

**证明**：BIT 的前缀查询返回 $\text{query}(\text{tree}_k, r) = \#\{v \in \text{arr}_k : \text{rank}(v) \le r\}$。取 $r = \text{rank}(x)$，由引理 1，该集合恰为 $\{v \in \text{arr}_k : v \le x\}$（含所有等于 $x$ 的元素）。arr$_k$ 中每个元素要么 $v \le x$ 要么 $v > x$，两类不重不漏地覆盖全集，故严格大于 $x$ 的个数 $= \text{len}_k - \#\{v \le x\} = \text{len}_k - \text{query}(\text{tree}_k, \text{rank}(x))$。∎

**定理（模拟等价性）**：按 §3.3 流程产生的 `result` 与按题意逐条定义（每步暴力扫描计算 greaterCount）产生的 `result` 完全一致。

**证明**：对操作轮数 $i$ 归纳。**基础**：第 1、2 次操作是硬性规定，两法一致；此后两法维护的 arr1 / arr2 分别相同，两棵 BIT 的插入集合分别是 arr1 / arr2 的全体元素，归纳前提成立。**归纳步骤**：设第 $i$（$i \ge 3$）次决策前两法的 arr1 / arr2 完全相同，从而 $\text{len}_1, \text{len}_2$ 与两棵 BIT 的内容相同。题意以 $\big(\text{greaterCount}(\text{arr1}, x),\ \text{greaterCount}(\text{arr2}, x)\big)$（$x = \text{nums}[i]$）的比较结果决策；由引理 2，流程计算出的 $(c_1, c_2)$ 与这两个定义值逐一相等，因此「$c_1 > c_2$ / $c_1 < c_2$ / 相等时短者优先、等长归 arr1」的三分支与题意逐字对应，去向一致。追加 $x$ 后两法的 arr1 / arr2 仍相同，且流程在对应树上执行 $\text{update}(\text{rank}(x))$，BIT 内容继续保持与「arr1 / arr2 全体元素」同步，归纳前提延续到下一轮。归纳完成：$n$ 轮后两法的 arr1、arr2 分别相同，连接所得 `result` 相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。离散化排序 $O(n \log n)$；$n - 2$ 轮模拟中，每轮一次名次查找（哈希 $O(1)$ 或二分 $O(\log n)$）、两次前缀查询与一次单点更新各 $O(\log m)$（$m \le n$ 为不同值个数）。
- **空间复杂度**：$O(n)$。两棵 BIT 各 $m + 1$ 个桶；离散化数组、rank 映射与输出数组各 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> resultArray(vector<int>& nums) {
        int n = nums.size();
        // 离散化：排序去重，值 -> 名次 [1, m]（覆盖全体 nums，询问值必有名次）
        vector<int> sorted(nums);
        sort(sorted.begin(), sorted.end());
        sorted.erase(unique(sorted.begin(), sorted.end()), sorted.end());
        int m = sorted.size();
        auto rank = [&](int x) {
            return int(lower_bound(sorted.begin(), sorted.end(), x) - sorted.begin()) + 1;
        };

        // 两棵树状数组：tree_k 维护 arr_k 中各名次的频次
        vector<int> tree1(m + 1, 0), tree2(m + 1, 0);
        auto update = [&](vector<int>& t, int i) {
            for (; i <= m; i += i & (-i)) t[i]++;
        };
        auto query = [&](vector<int>& t, int i) {   // 名次 <= i 的元素个数
            int s = 0;
            for (; i > 0; i -= i & (-i)) s += t[i];
            return s;
        };

        vector<int> arr1{nums[0]}, arr2{nums[1]};
        int len1 = 1, len2 = 1;
        update(tree1, rank(nums[0]));
        update(tree2, rank(nums[1]));

        for (int i = 2; i < n; i++) {
            int r = rank(nums[i]);
            int c1 = len1 - query(tree1, r);        // arr1 中严格大于 x 的个数
            int c2 = len2 - query(tree2, r);        // arr2 中严格大于 x 的个数
            if (c1 > c2 || (c1 == c2 && len1 <= len2)) {   // 平局链并入 <= 等号
                arr1.push_back(nums[i]);
                update(tree1, r);
                len1++;
            } else {
                arr2.push_back(nums[i]);
                update(tree2, r);
                len2++;
            }
        }
        arr1.insert(arr1.end(), arr2.begin(), arr2.end());
        return arr1;
    }
};
```

### Python

```python
class Solution:
    def resultArray(self, nums: List[int]) -> List[int]:
        sorted_vals = sorted(set(nums))            # 离散化：排序去重
        m = len(sorted_vals)
        rank = {v: i + 1 for i, v in enumerate(sorted_vals)}  # 值 -> 名次（从 1 开始）

        tree1, tree2 = [0] * (m + 1), [0] * (m + 1)

        def update(tree, i):
            while i <= m:
                tree[i] += 1
                i += i & (-i)

        def query(tree, i):                        # 名次 <= i 的元素个数
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & (-i)
            return s

        arr1, arr2 = [nums[0]], [nums[1]]
        len1 = len2 = 1
        update(tree1, rank[nums[0]])
        update(tree2, rank[nums[1]])

        for x in nums[2:]:
            r = rank[x]
            c1 = len1 - query(tree1, r)            # arr1 中严格大于 x 的个数
            c2 = len2 - query(tree2, r)            # arr2 中严格大于 x 的个数
            if c1 > c2 or (c1 == c2 and len1 <= len2):
                arr1.append(x)
                update(tree1, r)
                len1 += 1
            else:
                arr2.append(x)
                update(tree2, r)
                len2 += 1

        return arr1 + arr2
```

## 8. 边界情况与易错点

1. **暴力 $O(n^2)$ 超时**：$n = 10^5$ 时约 $10^{10}$ 次比较；「有序数组 + 二分」也不行——中间插入搬移 $O(n)$，同样退回平方级。
2. **「严格大于」不是「大于等于」**：$\text{query}(\text{rank}(x))$ 恰好数进所有等于 $x$ 的元素再被减法剔除；若误用 $\text{rank}(x) + 1$ 或 `bisect_left`，重复值会被算成「大于」。本题元素可重复（与 Q1 的互不相同不同），示例 3（全 3）是最直接的试金石。
3. **平局链两级顺序**：先比 greaterCount、再比长度、等长归 arr1。漏掉任一级或交换顺序都会 WA；合并条件里 $\text{len}_1 \le \text{len}_2$ 的等号承担「等长归 arr1」。
4. **前两次操作无条件**：不要把 `nums[1]`、`nums[2]` 也送进比较分支；从 0 下标的 `i = 2` 起循环天然正确（$n \ge 3$ 保证至少走一次比较）。
5. **值域 $10^9$ 不能开桶**：必须离散化，且要覆盖**全体** `nums`——询问值 `nums[i]` 可能尚未出现在任何数组中，名次仍须存在。
6. **BIT 下标从 1 开始**：名次若从 0 起，`update` 的 $i \mathrel{+}= i \,\&\, (-i)$ 在 $i = 0$ 处死循环；`query(0)` 返回 0 虽安全，但名次映射务必统一从 1 起。
7. **`result` 保持插入顺序**：是 `arr1 + arr2` 顺序连接，不是排序、也不是按值归并。
8. **长度用变量维护**：长度是减法公式的左操作数，用计数变量跟随插入 $+1$；不要每次去数组的 `size()` 取值后再忘了同步，更不要把两棵树的频次总和当长度用。

**延伸思考**：

- **单 BIT 的 ±1 技巧**：arr1 的插入记 $+1$、arr2 记 $-1$，一棵树即可同时编码两个集合的差值：$\text{query}_{\pm}(r) = \#\{\text{arr1} \le x\} - \#\{\text{arr2} \le x\}$，于是 $c_1 - c_2 = (\text{len}_1 - \text{len}_2) - \text{query}_{\pm}(r)$。只需判断差值符号，空间减半、每轮只查一次树——但语义更抽象，赛时建议用直观的双 BIT。
- **流式版本**：若元素在线到达且值域无界，「先离线离散化」不再可行，需平衡树（Python `SortedList`、C++ `pb_ds`）或动态开点线段树。
- **统计需求升级**：若问「第 $k$ 大」或区间名次，需名次树（order-statistic tree）或 BIT 上倍增定位第 $k$ 小。
- **同场复盘**：第 387 场是一条难度阶梯——Q1（#3069）尾元素比较纯模拟、Q2（#3070）二维前缀和剪枝、Q3（#3071）静态几何分区 + 小值域枚举、Q4（#3072）动态集合计数逼出 BIT。Q1 与 Q4 是同一分配规则的「轻 / 重」两版，赛后放在一起对照，最能看清**数据规模如何倒逼数据结构**。
