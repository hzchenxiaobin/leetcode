# LeetCode 将元素分配到两个数组中 I 题解

## 1. 题目概述

- **标题 / 题号**：将元素分配到两个数组中 I（#3069，easy）
- **链接**：https://leetcode.cn/problems/distribute-elements-into-two-arrays-i/
- **来源**：LeetCode 第 387 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、双指针

**题意**：给定下标从 1 开始、长度为 $n$ 且元素**互不相同**的数组 `nums`，通过 $n$ 次操作把所有元素分配到两个数组 `arr1`、`arr2` 中：

- 第 1 次操作：`nums[1]` 放入 `arr1`（固定）；
- 第 2 次操作：`nums[2]` 放入 `arr2`（固定）；
- 第 $i$（$i \ge 3$）次操作：**比较两个数组当前的最后一个元素**——若 `arr1` 的尾元素**大于** `arr2` 的尾元素，`nums[i]` 追加到 `arr1`；**否则**追加到 `arr2`。

最后把 `arr2` 整体拼接在 `arr1` 之后得到 `result`，返回 `result`。

**约束**：

- $3 \le n \le 50$
- $1 \le \text{nums}[i] \le 100$
- `nums` 中所有元素互不相同

> 💡 读题关键有三点：**比较对象是尾元素**（不是最大值、不是总和）；**元素互不相同 ⇒ 比较永无平局**，「否则」即严格小于；**尾大者胜出并接收新元素**——胜的一方接收后尾元素立刻被新来的数替换，下一步的胜负可能就此反转。

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,3]
输出：[2,3,1]

解释：操作 1、2 后 arr1 = [2]，arr2 = [1]。
操作 3：arr1 尾 2 ＞ arr2 尾 1，故 3 归 arr1。
最终 arr1 = [2,3]，arr2 = [1]，result = [2,3,1]。
```

**示例 2**

```text
输入：nums = [5,4,3,8]
输出：[5,3,4,8]

解释：操作 1、2 后 arr1 = [5]，arr2 = [4]。
操作 3：5 ＞ 4 → 3 归 arr1，arr1 = [5,3]。
操作 4：3 ＜ 4 → 8 归 arr2，arr2 = [4,8]。
result = [5,3] ++ [4,8] = [5,3,4,8]。
```

**示例 3**（自造，覆盖「比较方向中途反转」的情况）

```text
输入：nums = [4,2,5,1,3]
输出：[4,5,1,2,3]

解释：操作 1、2 后 arr1 = [4]，arr2 = [2]。
操作 3：4 ＞ 2 → 5 归 arr1，arr1 = [4,5]。
操作 4：5 ＞ 2 → 1 归 arr1，arr1 = [4,5,1]。
操作 5：1 ＜ 2 → 3 归 arr2，arr2 = [2,3]。
result = [4,5,1,2,3]。注意操作 4 之后 arr1 的尾变成了 1，
下一轮「胜者」立即从 arr1 换成了 arr2。
```

## 3. 解题思路

### 3.1 暴力思路

本题**按题意直译就是最优解**：规则本身已把过程完全确定，不存在需要搜索或优化的选择空间。任何「更聪明」的尝试（排序、贪心分配、DP）都是画蛇添足，而唯一会翻车的方式是**误读规则**——比如比较最大值、总和，或者把「尾大者接收」想成「尾小者接收」。

复杂度下界分析：输出需要全部 $n$ 个元素，故 $O(n)$ 时间不可再省；模拟每步 $O(1)$，已经贴住下界。

### 3.2 核心观察：决策只依赖两个尾元素

![核心观察：新元素只看两个数组的尾元素](images/distribute_arrays_i_concept.svg)

三个关键观察：

1. **决策的输入只有两个数**：任意第 $i \ge 3$ 步只看 $\text{arr1}[-1]$ 与 $\text{arr2}[-1]$，两个数组此前的所有历史**不直接参与决策**——它们只通过「尾元素是什么」间接影响当前一步。因此用数组天然 $O(1)$ 取尾，无需任何额外结构。
2. **互不相同 ⇒ 无平局**：$\text{arr1}[-1]$ 与 $\text{arr2}[-1]$ 是 `nums` 中两个不同下标的元素，必不相等。于是「$\text{arr1}[-1] > \text{arr2}[-1]$」与其补集恰好把所有情形二分，「否则」分支即严格小于，条件写**严格大于**即可，不存在歧义。
3. **追加即换尾**：新元素落进某数组后立刻成为该数组的新尾，会直接改变下一步的比较结果（见示例 3 的反转）。整个过程可以看作状态 $(\text{尾}_1, \text{尾}_2)$ 随输入序列演化的**尾部状态机**。

### 3.3 算法流程

![算法流程：一趟扫描加尾元素比较](images/distribute_arrays_i_flow.svg)

```text
arr1 ← [nums[0]]                  # 操作 1 固定（0 起下标）
arr2 ← [nums[1]]                  # 操作 2 固定
for i ← 2 to n-1:                 # 操作 3..n
    if arr1[-1] > arr2[-1]:
        arr1.append(nums[i])      # 尾大者接收
    else:
        arr2.append(nums[i])      # 否则（含平局的题面语义）归 arr2
return arr1 ++ arr2                # arr2 拼在 arr1 之后
```

### 3.4 示例演算

![示例演算：示例2的完整走查表](images/distribute_arrays_i_walkthrough.svg)

以示例 2 `nums = [5,4,3,8]` 走查四步操作：

| 步骤 | 新元素 | 尾元素比较 | arr1 | arr2 |
|------|--------|-----------|------|------|
| 操作 1 | 5 | —（固定） | **[5]** | — |
| 操作 2 | 4 | —（固定） | [5] | **[4]** |
| 操作 3 | 3 | 5 ＞ 4 → 归 arr1 | **[5, 3]** | [4] |
| 操作 4 | 8 | 3 ＜ 4 → 归 arr2 | [5, 3] | **[4, 8]** |

拼接得 `result = [5,3] ++ [4,8] = [5,3,4,8]` ✓。特别注意第 4 步：第 3 步把 3 放进 `arr1` 后其尾从 5 变为 3，比较方向随之反转，这正是「追加即换尾」观察的体现。

## 4. 算法细节

1. **下标换算**：题面 1 起下标、代码 0 起下标。前两次操作是**固定的**——`nums[0]` 进 `arr1`、`nums[1]` 进 `arr2`，不发生任何比较；循环从下标 2 开始。
2. **取尾 O(1)**：C++ 用 `arr1.back()` / `arr2.back()`，Python 用 `arr1[-1]` / `arr2[-1]`；数组只增不减，尾元素永远有效。
3. **条件写严格大于**：`if arr1[-1] > arr2[-1]` 与题面「大于→arr1，否则→arr2」逐字对应。本题因元素互异，`>` 与 `>=` 实际等价，但照抄题面语义最不易错（也最耐变化）。
4. **拼接**：C++ 用 `arr1.insert(arr1.end(), arr2.begin(), arr2.end())`；Python 直接 `arr1 + arr2`。拼接顺序固定 `arr1` 在前。
5. **数据范围**：$n \le 50$、值域 $[1,100]$，`int` 绰绰有余，无任何性能与溢出压力——本题拼的是**读题与手速**。

## 5. 正确性证明

**引理 1（过程良定义）**：对每个 $i \ge 3$ 的操作时刻，`arr1` 与 `arr2` 均非空，「尾元素」存在。

**证明**：操作 1 放入 `nums[1]`、操作 2 放入 `nums[2]`，且约束 $n \ge 3$ 保证两次操作先于一切比较发生；此后操作只追加、从不删除，非空性始终保持。∎

**引理 2（无平局）**：任意比较时刻 $\text{arr1}[-1] \ne \text{arr2}[-1]$。

**证明**：$\text{arr1}[-1]$ 与 $\text{arr2}[-1]$ 来自 `nums` 中两个不同下标的元素（一次只追加到一个数组，二者不同时），而 `nums` 元素互不相同，故二者必不相等。于是「$\text{arr1}[-1] > \text{arr2}[-1]$」要么成立要么其否定（严格小于）成立，题面的条件分支覆盖所有情形且无重叠。∎

**定理（模拟保真）**：算法输出恰为题面过程唯一确定的结果。

**证明**：对操作序号 $i$ 归纳。基础：操作 1、2 按题面固定放入，两数组的构成与过程一致。归纳步骤：设第 $i$ 步前 `arr1`、`arr2` 与过程一致；由引理 1 第 $i$ 步的比较合法，由引理 2 比较结果唯一，算法严格按题面规则把 `nums[i]` 追加到对应数组，追加后归纳假设保持。归纳成立，即全程逐字符复现题面过程；最终按「`arr1` 在前、`arr2` 在后」拼接，与题面定义的 `result` 一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素被处理一次，每步取尾、比较、追加均为 $O(1)$（`vector` 追加均摊 $O(1)$）；末尾拼接整体 $O(n)$。$O(n)$ 也是输出规模的下界，无法再优化。
- **空间复杂度**：$O(n)$ 为输出数组本身所占；若不计输出，仅用两个数组的中间状态（它们随后被拼进输出），辅助空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> resultArray(vector<int>& nums) {
        vector<int> arr1{nums[0]}, arr2{nums[1]};   // 前两次操作固定
        for (int i = 2; i < (int)nums.size(); ++i) {
            if (arr1.back() > arr2.back())          // 尾大者接收
                arr1.push_back(nums[i]);
            else
                arr2.push_back(nums[i]);
        }
        arr1.insert(arr1.end(), arr2.begin(), arr2.end());  // arr2 拼在后面
        return arr1;
    }
};
```

### Python

```python
class Solution:
    def resultArray(self, nums: List[int]) -> List[int]:
        arr1, arr2 = [nums[0]], [nums[1]]          # 前两次操作固定
        for x in nums[2:]:
            if arr1[-1] > arr2[-1]:                # 尾大者接收
                arr1.append(x)
            else:
                arr2.append(x)
        return arr1 + arr2                         # arr2 拼在后面
```

## 8. 边界情况与易错点

1. **下标换算（最容易翻车）**：前两次操作是固定的，千万别把 `nums[0]` 也拿去比较、或把 `nums[1]` 错放进 `arr1`。题面 1 起下标 ↔ 代码 0 起下标，循环起点是第三个元素。
2. **比较对象是尾元素**：不是两个数组的最大值、总和或长度。同场 Q4（#3072）才把规则换成「严格大于 `nums[i]` 的**元素个数**」，需要树状数组；本题若混淆两者方向，直接 WA。
3. **方向别写反**：是**尾更大的一方接收**新元素（强者恒强的发牌）。写反后示例 1 得 `[2,1,3]`、示例 2 得 `[5,4,3,8]`，两个示例都会 WA，正好构成天然对拍。
4. **`>` 与 `>=` 的取舍**：元素互异时二者等价，但题面语义是「大于→arr1，否则（含相等）→arr2」，按原样写 `>` 最稳；若元素可能相等（假设的变体），`>=` 会把平局错误地送给 `arr1`。
5. **拼接顺序**：`result = arr1 ++ arr2`，`arr1` 在前。拼接只是组装答案，**不改变**分配过程，别在循环里边比边拼。
6. **最小规模 $n = 3$**：恰好发生一次比较；由引理 1 不会出现空数组取尾的越界/异常，无需特判。
7. **心态提示**：签到题目标是 3 分钟内 AC——先把题面规则逐句翻译成代码，再用两个样例快速心算验证，不要在此题上「优化」或犹豫。
