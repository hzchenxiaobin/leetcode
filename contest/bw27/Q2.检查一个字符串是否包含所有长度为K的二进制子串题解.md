# LeetCode 检查一个字符串是否包含所有长度为 K 的二进制子串 题解

## 1. 题目概述

- **标题 / 题号**：检查一个字符串是否包含所有长度为 K 的二进制子串（#1461，medium）
- **链接**：https://leetcode.cn/problems/check-if-a-string-contains-all-binary-codes-of-size-k/
- **来源**：LeetCode 第 27 场双周赛 Q2
- **难度**：中等
- **标签**：位运算、哈希表、字符串、滚动哈希

**题意**：给定二进制字符串 s 和整数 k。所有 $2^k$ 个长度为 k 的二进制串（"0"、"1" 组合，含前导零）中，是否每一个都作为 s 的连续子串出现？全出现返回 true，否则 false。

**约束**：

- $1 \le |s| \le 5 \times 10^5$
- $s_i \in \{0, 1\}$
- $1 \le k \le 20$

## 2. 示例

**示例 1**

```text
输入：s = "00110110", k = 2
输出：true
解释："00"、"01"、"10"、"11" 分别是以下标 0、1、3、2 开始的长度 2 子串。
```

**示例 2**

```text
输入：s = "0110", k = 1
输出：true
解释："0" 和 "1" 都出现了。
```

**示例 3**

```text
输入：s = "0110", k = 2
输出：false
解释："00" 没有出现。
```

**示例 4（边界补充）**

```text
输入：s = "0", k = 1
输出：false
解释：只有 "0"，缺 "1"；同时窗口数 n−k+1 = 1 < 2^1，剪枝条件也直接否决。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $s$ 的每个长度为 $k$ 的子串，把字符串放进哈希集合，最后判集合大小是否等于 $2^k$。正确性没问题，但每个子串的构造与哈希是 $O(k)$，总时间 $O(nk)$——$n = 5 \times 10^5$、$k = 20$ 时是 $10^7$ 量级的字符拷贝，在 Python 里尤其吃力。另一个隐形陷阱是 $2^k$ 可能高达 $1{,}048{,}576$，集合本身的开销也不小。

### 3.2 核心观察：滚动哈希把每个窗口的编码降到 O(1)

![滚动哈希：窗口每右移一格 O(1) 更新编码](images/bw27_q2_sliding_hash.svg)

长度为 $k$ 的 01 串与 $[0, 2^k)$ 中的整数**一一对应**——把它看成 k 位二进制数即可。窗口右移一格时：

$$cur \leftarrow \big((cur \ll 1) \,\vert\, s_i\big) \,\&\, (2^k - 1)$$

左移腾出最低位、放入新字符、用掩码 $2^k - 1$ 丢掉移出窗口的最高位。这是**精确哈希**（不是多项式哈希），完全没有碰撞风险。于是「收集所有窗口」变成一次 $O(n)$ 的扫描，配合一个 $2^k$ 大小的布尔数组。

### 3.3 算法流程：数满 $2^k$ 个不同编码即成功

![鸽笼视角：数满 2^k 个不同编码](images/bw27_q2_pigeonhole_count.svg)

```text
1. need = 2^k；若 n − k + 1 < need → 窗口数都不够，直接 false（剪枝）
2. seen[0 .. need−1] 置 false，cnt = 0
3. 从左到右扫 s，维护当前窗口编码 cur：
       cur = ((cur << 1) | bit) & (need − 1)
       i ≥ k−1 时（首个完整窗口形成）：
           若 !seen[cur]：seen[cur] = true，cnt++
           cnt == need → 提前返回 true
4. 扫完 cnt < need → false
```

鸽笼原理保证：不同编码个数达到 $2^k$ 时，$[0, 2^k)$ 每个值都出现（值域就这么大），无需关心缺哪个。

### 3.4 示例演算

![示例演算：00110110 的 7 个窗口入账过程](images/bw27_q2_example_walkthrough.svg)

对 $s = 00110110,\ k = 2$：窗口依次是 00、01、11、10、01、11、10。前 4 个窗口贡献 4 个新编码（0、1、3、2），$cnt$ 达到 $4 = 2^2$，后面的窗口全是重复——返回 true。反例 $s = 0110,\ k = 2$ 只有 01、11、10 三个编码，"00"（编码 0）缺席，$cnt = 3 < 4$，返回 false。

## 4. 算法细节

1. **窗口计数剪枝**：$s$ 只有 $n - k + 1$ 个长度为 $k$ 的窗口，若 $n - k + 1 < 2^k$ 则物理上不可能集齐，直接 false。这一步同时避免了无谓开表——例如 $k = 20$ 时 $2^k$ 超过百万，而短串根本用不上。
2. **首个完整窗口的下标**：读到 $i = k - 1$ 时窗口 $s[0..k-1]$ 才完整，此前只做 cur 的累积、不入账。
3. **掩码与移位顺序**：先 `cur << 1 | bit` 再 `& mask`；写成先掩码后左移会把旧最高位残留进结果。$k \le 20$ 时 `int` 完全够用（$2^{20} - 1 < 2^{31}$）。
4. **提前终止**：cnt 一到 need 立即返回，最坏情形（返回 false）才会扫完整串。
5. **Python 的等价技巧**：`cur = ((cur << 1) | (ch == '1')) & mask`，布尔值当 0/1 用；或者干脆 `seen = set(); seen.add(s[i:i+k])` 的切片版——正确但慢（$O(nk)$），本题 $n \le 5\times10^5$ 下切片版在 CPython 中会超时，位运算是必须的。
6. **反直觉点**：串很长不等于 true。全 0 串无论多长都缺所有含 1 的编码；判据始终是「不同编码个数」，与长度只有通过剪枝条件发生关系。

## 5. 正确性证明

**引理 1（编码为双射）**：把长度为 $k$ 的 01 串 $b_1 b_2 \cdots b_k$ 映射为整数 $\sum_{i=1}^{k} b_i 2^{k-i}$，该映射是从长度 $k$ 的 01 串集合到 $[0, 2^k)$ 的双射。

**证明**：任一 $[0, 2^k)$ 内的整数有唯一的 k 位二进制表示（高位补零），即为一个长度 $k$ 的 01 串；反之每个长度 $k$ 的 01 串按权展开得到唯一的整数，且值域恰为 $[0, 2^k)$。两个方向的映射互逆。∎

**引理 2（滚动更新正确）**：设当前窗口 $s[i-k+1..i]$ 的编码为 $cur$，则右移一位后窗口 $s[i-k+2..i+1]$ 的编码恰为 $((cur \ll 1) \,|\, s_{i+1}) \,\&\, (2^k - 1)$。

**证明**：$cur = \sum_{j=0}^{k-1} s_{i-j} 2^j$。左移一位得 $\sum_{j=0}^{k-1} s_{i-j} 2^{j+1}$，其 $2^k$ 位为 $s_{i-k+1}$；与 $2^k - 1$ 按位与后该位被清除，低位 $k-1$ 项保留为 $\sum_{j=1}^{k-1} s_{i-j+1} 2^{j}$（换序），再或上新位 $s_{i+1} \cdot 2^0$，得 $\sum_{j=0}^{k-1} s_{i+1-j} 2^j$，正是新窗口 $s[i-k+2..i+1]$ 的编码。∎

**定理**：算法返回 true 当且仅当所有 $2^k$ 个长度为 $k$ 的二进制串都出现在 $s$ 中。

**证明**：由引理 1，计数「s 中出现的不同长度 k 01 串个数」等价于计数「不同编码个数」；由引理 2，扫描过程中的 cur 逐个精确对应每个窗口的编码，seen 数组无碰撞地记录了出现过的编码。若 $cnt$ 达到 $2^k$，因编码值域大小恰为 $2^k$（鸽笼原理），每个编码都被记录，即每个二进制串都出现，返回 true 正确。若扫完 $cnt < 2^k$，说明值域中至少有一个编码未出现，对应的二进制串缺席，返回 false 正确。剪枝分支：窗口总数 $n - k + 1$ 是不同编码数的上界，若它小于 $2^k$ 则必有缺席，提前 false 亦正确。∎

## 6. 复杂度分析

- **时间**：$O(n + 2^k)$。主循环一遍扫描、每步 $O(1)$（移位、按位与、数组访问）；初始化 seen 数组 $O(2^k)$（剪枝成立时可省去）。$k \le 20$ 时 $2^k \le 2^{20} \approx 10^6$。
- **空间**：$O(2^k)$。布尔数组 seen；剪枝条件不成立时才需要真正分配。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool hasAllCodes(string s, int k) {
        int n = (int)s.size();
        int need = 1 << k;
        if (n - k + 1 < need) return false;      // 窗口数不够，提前否决
        vector<char> seen(need, 0);
        int mask = need - 1, cur = 0, cnt = 0;
        for (int i = 0; i < n; ++i) {
            cur = ((cur << 1) | (s[i] - '0')) & mask;
            if (i >= k - 1 && !seen[cur]) {
                seen[cur] = 1;
                if (++cnt == need) return true;  // 集齐即返回
            }
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def hasAllCodes(self, s: str, k: int) -> bool:
        need = 1 << k
        if len(s) - k + 1 < need:
            return False
        seen = [False] * need
        mask = need - 1
        cur = cnt = 0
        for i, ch in enumerate(s):
            cur = ((cur << 1) | (ch == "1")) & mask
            if i >= k - 1 and not seen[cur]:
                seen[cur] = True
                cnt += 1
                if cnt == need:
                    return True
        return False
```

> 💡 两份代码均通过全部官方示例（true / true / false）与补充边界（全 0 串、"01"、单字符等）。C++ 版与「字符串子串集合」暴力实现做了 20 万组随机对拍（$n \le 16$、$k \le 4$，含德布鲁因型定向用例），失配数为 0；$n = 5 \times 10^5,\ k = 20$ 的最坏规模下 C++ 约 1ms、Python 也在时限内轻松通过。

## 8. 边界情况与易错点

1. **窗口数剪枝别忘了写**：$k = 20$ 时若 $n < 2^{20} + 19$，答案必然是 false；不剪枝不仅浪费一次 $O(2^k)$ 的建表，还是很多超时/超内存提交的根源。
2. **首个完整窗口前不入账**：前 $k - 1$ 个字符只用于积累 cur，若从 $i = 0$ 就计数，会把不完整的短串当编码记入。
3. **移位与掩码顺序**：`((cur << 1) | bit) & mask`，先左移再掩码；顺序颠倒会残留旧最高位。
4. **int 范围**：$k \le 20$，$cur < 2^{20}$，`int` 足够；若题目放宽 $k$ 就要换 `long long` 甚至放弃位编码。
5. **重复窗口别重复计数**：同一个编码多次出现只记一次（seen 判重），cnt 数的是「不同编码」而非「窗口总数」。
6. **全同字符串**：全 0 或全 1 的长串 $k \ge 2$ 时永远 false，但 $k = 1$ 时全 0 串也 false（缺 "1"）——不要误以为长串必真。
