# LeetCode 课程表 IV 题解

## 1. 题目概述

- **标题 / 题号**：课程表 IV（#1462，medium）
- **链接**：https://leetcode.cn/problems/course-schedule-iv/
- **来源**：LeetCode 第 27 场双周赛 Q3
- **难度**：中等
- **标签**：图、广度优先搜索、深度优先搜索、拓扑排序、传递闭包

**题意**：共 $numCourses$ 门课（编号 $0 \sim numCourses - 1$），先修关系 $prerequisites[i] = [a_i, b_i]$ 表示修 $b_i$ 前必须先修 $a_i$。先修关系可传递：$a \to b$、$b \to c$ 则 $a \to c$。给定 $queries[j] = [u_j, v_j]$，逐个回答「$u_j$ 是否为 $v_j$ 的（直接或间接）先修课」，返回布尔数组。

**约束**：

- $2 \le numCourses \le 100$
- $0 \le prerequisites.length \le \frac{n(n-1)}{2}$，数对互不相同，$a_i \ne b_i$
- 先修关系构成**无环**图（DAG）
- $1 \le queries.length \le 10^4$，$u_i \ne v_i$

## 2. 示例

**示例 1**

```text
输入：numCourses = 2, prerequisites = [[1,0]], queries = [[0,1],[1,0]]
输出：[false,true]
解释：[1,0] 表示修 0 之前要先修 1。于是 1 是 0 的先修课，反之不是。
```

**示例 2**

```text
输入：numCourses = 2, prerequisites = [], queries = [[1,0],[0,1]]
输出：[false,false]
解释：没有任何先修关系，各课相互独立。
```

**示例 3**

```text
输入：numCourses = 3, prerequisites = [[1,2],[1,0],[2,0]], queries = [[1,0],[1,2]]
输出：[true,true]
解释：1 直接先修 0 与 2；1 经 2 也间接先修 0（传递性）。
```

**示例 4（赛题用例）**

```text
输入：numCourses = 6, prerequisites = [[4,5],[3,4],[2,3],[1,2],[0,1]], queries = [[0,5]]
输出：[true]
解释：链 0→1→2→3→4→5 上 0 经四步传递间接先修 5。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询 $(u, v)$ 现场跑一遍 DFS/BFS 判断 $u$ 是否可达 $v$，单次查询 $O(n + m)$，总代价 $O(q(n + m))$——$q = 10^4$、$n = 100$ 时约 $10^4 \times 10^4 = 10^8$ 次（$m$ 可达 $\binom{100}{2} \approx 5000$，$n + m \approx 5 \times 10^3$，总计 $5 \times 10^7$）勉强能过但很浪费：查询之间共享同一张图，可达关系完全可以**预处理**出来，每次查询 $O(1)$ 读表。

### 3.2 核心观察：查询即「可达性」，预处理传递闭包一劳永逸

![核心观察：先修链是 DAG，查询即可达性判定](images/bw27_q3_dag_closure.svg)

把课程看作节点、$a \to b$ 画有向边，「$u$ 是 $v$ 的先修课」$\iff$ 图上存在 $u$ 到 $v$ 的路径。批量查询的标准套路是**传递闭包**（transitive closure）：布尔矩阵 $reach[i][j]$ 表示 $i$ 可达 $j$，一次预处理后所有查询都变成数组读数。

数据范围 $n \le 100$ 是最强的暗示：$n^3 = 10^6$，**Floyd-Warshall 求闭包**轻而易举。这是 Floyd 最经典的「非最短路」用法——把「取 min」换成「按位或」。

### 3.3 算法流程：Floyd 传递闭包

![Floyd 求传递闭包：中转站 k 逐个登场](images/bw27_q3_floyd_closure.svg)

```text
1. reach[n][n] 初始化：reach[i][i] = 1；对每条边 (a,b)：reach[a][b] = 1
2. for k = 0 .. n−1:            # 允许经过中转点 k
       for i = 0 .. n−1:
           if reach[i][k]:
               for j = 0 .. n−1:
                   if reach[k][j]: reach[i][j] = 1
3. 每个查询 (u,v) 直接返回 reach[u][v]
```

三重循环的含义：外层逐步引入中转点 $k$，内层检查「$i$ 能到 $k$ 且 $k$ 能到 $j$」则 $i$ 能到 $j$。$k$ 放最外层是 Floyd 正确性的命门（见 §5）。

### 3.4 示例演算

![示例演算：链式 DAG 的闭包逐步铺满](images/bw27_q3_closure_walkthrough.svg)

以示例 4 的链 $0 \to 1 \to 2 \to 3 \to 4 \to 5$ 为例：初始闭包只有 5 条直接边；$k = 1$ 转完后补出 $0 \to 2$；$k = 2$ 补出 $0 \to 3,\ 1 \to 3$；……直到 $k = 5$ 转完，整个上三角全为 1。查询 $[0,5]$ 读 $reach[0][5] = 1$ 得 true。

## 4. 算法细节

1. **自环占位**：初始化时设 $reach[i][i] = 1$。虽然查询保证 $u \ne v$ 用不到它，但这个设置在实现上是「单元布尔矩阵」的惯例，且不干扰正确性（$i \to i \to j$ 与 $i \to j$ 等价）。若想严格些，不设自环也完全正确。
2. **循环顺序不可动摇**：$k$ 必须是最外层。若把 $k$ 放最内层，同一轮里刚写入的 $reach[i][j]$ 可能立刻被当作「经过更大 $k$」的路径使用，虽然对闭包这个终点式语义恰好不致出错，但会破坏 Floyd 系算法的统一正确性论证习惯；按标准顺序写永远不会错。
3. **短路优化**：`if reach[i][k]` 不成立就整行跳过 $j$ 循环；稀疏图上平均省一大截。$j$ 循环还可以换成对 `reach[k]` 整行的按位或（bitset 化，见 §6）。
4. **邻接表 + BFS 的替代方案**：从每个起点 $i$ 各跑一次 BFS，把沿途所有点标记 $reach[i][\cdot] = 1$，总复杂度 $O(n(n + m))$，比 Floyd 的 $O(n^3)$ 在稀疏图上更优，稠密图上相当。两种写法都值得掌握。
5. **查询数组转储**：答案按 queries 顺序输出 $reach[u][v]$，注意查询数最多 $10^4$、而闭包只有 $10^4$ 个布尔位，读表部分毫无压力。

## 5. 正确性证明

**引理 1（路径的中转分解）**：有向图中存在路径 $u \leadsto v$ 当且仅当存在路径，其所有**中间节点**（起点终点除外）编号都不超过某个 $k$ 的前提下逐步扩展……严格地说：对任意 $k$，定义 $R_k[u][v] = 1$ 当且仅当存在路径 $u \leadsto v$ 且中间节点均 $\le k$。则 $R_k[u][v] = 1 \iff R_{k-1}[u][v] = 1$ 或（$R_{k-1}[u][k] = 1$ 且 $R_{k-1}[k][v] = 1$）。

**证明**：（$\Leftarrow$）两种情形都直接给出一条中间节点 $\le k$ 的路径：后者把 $u \leadsto k$ 与 $k \leadsto v$ 在 $k$ 处拼接即可（拼接点 $k$ 作为新中间节点编号恰为 $k$，不超过 $k$）。（$\Rightarrow$）设 $P$ 是一条中间节点均 $\le k$ 的 $u \leadsto v$ 路径。若 $P$ 不经过 $k$，其中间节点均 $\le k - 1$，$R_{k-1}[u][v] = 1$；若 $P$ 经过 $k$，把 $P$ 在 $k$ 处切成两段 $u \leadsto k$ 与 $k \leadsto v$，两段的中间节点都是 $P$ 的中间节点（除去 $k$ 本身），均 $\le k - 1$，故 $R_{k-1}[u][k] = 1$ 且 $R_{k-1}[k][v] = 1$。∎

**定理（Floyd 闭包正确）**：算法终止时 $reach[u][v] = 1$ 当且仅当图中存在路径 $u \leadsto v$。

**证明**：对 $k$ 归纳：处理完第 $k$ 轮外层循环后，$reach = R_k$。$k = -1$（未开始）时 $reach$ 只含直接边与自环，恰为 $R_{-1}$（中间节点集合为空）。设第 $k - 1$ 轮后 $reach = R_{k-1}$；第 $k$ 轮中，算法对每对 $(i, j)$ 检查「$reach[i][k]$ 且 $reach[k][j]$」——由归纳假设即 $R_{k-1}[i][k]$ 与 $R_{k-1}[k][j]$——为真则置 $reach[i][j] = 1$，否则保持原值；又因 $reach[k][k] = 1$（自环），当 $R_{k-1}[i][j] = 1$ 时即使不做任何事值也为 1，且置位操作只增不减不会误清。对照引理 1 的递推式，第 $k$ 轮后 $reach = R_k$。归纳成立。终止时 $reach = R_{n-1}$，而任意路径的中间节点编号必然 $\le n - 1$，故 $R_{n-1}[u][v] = 1 \iff$ 存在路径 $u \leadsto v$。查询返回 $reach[u][v]$ 正确判定先修关系（先修 $\iff$ 有向路径，题目 DAG 保证与「课程先后」语义一致）。∎

## 6. 复杂度分析

- **时间**：$O(n^3 + q)$。三重循环 $100^3 = 10^6$；每查询 $O(1)$ 读表，$q \le 10^4$。若用 bitset 把内层 $j$ 循环整行合并（每行一个 $n$ 位整数，或运算一条指令处理 $w$ 个点），降为 $O(n^3 / w)$，本题规模下无必要。
- **空间**：$O(n^2)$。闭包矩阵 $100 \times 100$ 布尔；邻接信息直接融入闭包，无需另存。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<bool> checkIfPrerequisite(int numCourses, vector<vector<int>>& prerequisites, vector<vector<int>>& queries) {
        vector<vector<char>> reach(numCourses, vector<char>(numCourses, 0));
        for (auto& p : prerequisites) reach[p[0]][p[1]] = 1;
        for (int i = 0; i < numCourses; ++i) reach[i][i] = 1;   // 自环占位
        for (int k = 0; k < numCourses; ++k)
            for (int i = 0; i < numCourses; ++i)
                if (reach[i][k])
                    for (int j = 0; j < numCourses; ++j)
                        if (reach[k][j]) reach[i][j] = 1;
        vector<bool> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) ans.push_back(reach[q[0]][q[1]] == 1);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def checkIfPrerequisite(self, numCourses: int, prerequisites: List[List[int]],
                            queries: List[List[int]]) -> List[bool]:
        reach = [[False] * numCourses for _ in range(numCourses)]
        for a, b in prerequisites:
            reach[a][b] = True
        for i in range(numCourses):
            reach[i][i] = True
        for k in range(numCourses):
            rk = reach[k]
            for i in range(numCourses):
                if reach[i][k]:
                    ri = reach[i]
                    for j in range(numCourses):
                        if rk[j]:
                            ri[j] = True
        return [reach[u][v] for u, v in queries]
```

> 💡 两份代码均通过全部官方示例（含赛题链式用例与「无先修课」空边用例）。C++ 版与「逐源 BFS 求可达」的独立实现在 3000 组随机 DAG（$n \le 100$、随机查询）上对拍，失配数为 0。

## 8. 边界情况与易错点

1. **无边（空 prerequisites）**：所有查询答案为 false（课程独立）。Floyd 初始矩阵只剩自环，循环后不变，天然正确。
2. **u = v 不会出现**：题目保证 $u_i \ne v_i$，所以自环 $reach[i][i]$ 的值不影响任何答案；但仍建议保留自环写法，它是单元布尔矩阵的标准初始化。
3. **重复查询**：同一查询可能出现多次，读表方案毫无压力；现场搜索方案则会重复劳动——这也是预处理思路的直接动机。
4. **DAG 保证不可少**：题目承诺无环。若图有环，闭包照样能算（强连通分量内互相可达），但「先修」的语义就崩塌了；不必为此特判。
5. **k 循环的位置**：写成 `for i { for j { for k ... } }` 是 Floyd 的经典错误形态；对闭包语义虽常能蒙对，但请从一开始就按标准三重循环（k 最外）写。
6. **查询下标越界**：$u, v \in [0, numCourses)$ 由约束保证，读表前无需再判。

**延伸思考**：传递闭包的计算还有两条路。其一是 **bitset 压位的 Floyd**：把 $reach[i]$ 存为 $n$ 位整数，内层 `reach[i] |= reach[k]`，复杂度除以机器字长 $w$，$n = 10^4$ 也能跑。其二是 **拓扑序 DP**：按拓扑序处理，$reach[v] = \bigcup_{u \to v} (reach[u] \cup \{u\})$，配合 bitset 同样是 $O((n + m) n / w)$，适合稀疏大图。更理论的方向：传递闭包的计算复杂度与**布尔矩阵乘法**等价（目前下界 $\Omega(n^2)$、上界随 BMM 算法改进），这也是「Floyd $O(n^3)$」六十年来仍是工程默认的原因。
