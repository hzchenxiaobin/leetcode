# LeetCode 通过翻转子数组使两个数组相等 题解

## 1. 题目概述

- **标题 / 题号**：通过翻转子数组使两个数组相等（#1460，easy）
- **链接**：https://leetcode.cn/problems/make-two-arrays-equal-by-reversing-subarrays/
- **来源**：LeetCode 第 27 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序

**题意**：给定两个长度相同的整数数组 target 和 arr。每一步可以选择 arr 的任意非空子数组并将其翻转，操作次数不限。问能否通过若干次翻转使 arr 与 target 完全相同。

**约束**：

- $target.length = arr.length$，$1 \le n \le 1000$
- $1 \le target[i], arr[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：target = [1,2,3,4], arr = [2,4,1,3]
输出：true
解释：翻转 [2,4,1] 得 [1,4,2,3]，再翻转 [4,2] 得 [1,2,4,3]，最后翻转 [4,3] 即得 [1,2,3,4]。
```

**示例 2**

```text
输入：target = [7], arr = [7]
输出：true
解释：无需任何翻转。
```

**示例 3**

```text
输入：target = [3,7,9], arr = [3,7,11]
输出：false
解释：arr 中没有 9，元素构成就不同，无论怎么翻转都无济于事。
```

## 3. 解题思路

### 3.1 暴力思路

模拟题面：在 arr 上做各种翻转，搜索所有可达的排列（状态空间最坏 $n! = 1000!$），用 BFS 判定 target 是否可达——直接爆炸。另一条暴力路是**随机打乱**：随机翻转若干次看是否碰巧相等，既不正确也不可靠。

退一步想：翻转不增删元素，只改变顺序。所以**元素的多重集合（可重集）是翻转过程中的不变量**——这提示我们根本不需要关心顺序。

### 3.2 核心观察：反转不改变可重集，可重集相同即可互相变换

![核心观察：翻转不改变元素的可重集](images/bw27_q1_reversal_multiset.svg)

两个方向的观察合起来就是完整判定：

- **必要性**：每次翻转只是把某段元素逆序重排，任何时刻 arr 的可重集都与初始相同。若 arr 能变成 target，两者可重集必然相等。
- **充分性**：长度为 2 的子数组翻转就是**相邻交换**，而相邻交换能生成任意排列（冒泡排序的原理）。只要可重集相等，就能一步步把 arr「冒泡」成 target。

因此答案只取决于：$\operatorname{multiset}(target) = \operatorname{multiset}(arr)$ 是否成立。

### 3.3 算法流程：计数判等

![算法流程：计数统计、逐一抵消、归零判定](images/bw27_q1_count_flow.svg)

```text
1. cnt[1..1000] 清零
2. 对 target 中每个 x：cnt[x]++
3. 对 arr 中每个 x：cnt[x]--；一旦 cnt[x] < 0 → 返回 false
4. 扫完无负数 → 返回 true
```

由于两数组长度相同，若中途没有出现负数，最终所有计数必然恰好归零（总数加了多少就减了多少），无需再检查剩余计数。

### 3.4 示例演算

![示例演算：相邻交换如何把 arr 换成 target](images/bw27_q1_adjacent_swap.svg)

以示例 1 为例：$arr = [2,4,1,3]$，$target = [1,2,3,4]$。计数统计后 $cnt = \{1{:}1,\ 2{:}1,\ 3{:}1,\ 4{:}1\}$，arr 逐个抵消全部归零、从未为负 → true。

反过来对示例 3：$cnt[9] = 1$，但 arr 抵消时 $cnt[11]$ 直接减成 $-1$ → false。

## 4. 算法细节

1. **为什么不用排序**：排序判等 $O(n \log n)$ 也完全能过（$n \le 1000$），但计数判等是 $O(n + V)$（$V = 1000$ 为值域），一遍线性扫描更直接，也是值域小时更「模板化」的写法。
2. **计数数组大小**：值为 $1 \sim 1000$，开 `int cnt[1001]`，下标 $0$ 闲置，避免与哨兵冲突。
3. **提前失败**：arr 中某个值出现次数超过 target 中的次数时立即返回 false，平均情形更快；最坏也是一次完整扫描。
4. **等长保证的妙用**：两数组长度相等意味着「多出来的」和「少掉的」必然成对出现，所以只要一侧不超计数，另一侧必然也不超——只需单向检查。
5. **哈希表替代**：若值域更大（如 $10^9$），用 `unordered_map` / `Counter` 同理，复杂度退化为期望 $O(n)$。

## 5. 正确性证明

**引理 1（不变量）**：任意次子数组翻转操作不改变数组的可重集。

**证明**：翻转 $arr[l..r]$ 仅将这一段的元素顺序逆置，$arr[l..r]$ 中的元素集合（含重复）不变，前后元素完全相同，仅位置互换。可重集是「与位置无关」的量，故保持不变。∎

**引理 2（相邻交换生成任意排列）**：若两个数组 $A, B$ 可重集相同，则 $A$ 可经若干次**长度为 2 的子数组翻转**（即相邻交换）变为 $B$。

**证明**：对 $n$ 归纳。$n = 1$ 时两数组相同（可重集相同且各只有一个元素），无需操作。设对 $n$ 成立。考察长度 $n+1$ 的 $A, B$：$B[0]$ 必出现在 $A$ 中某位置 $p$（可重集相同）。用相邻交换把 $A[p]$ 一步步移到下标 $0$（每次交换相邻两位，共 $p$ 次），得 $A'$，满足 $A'[0] = B[0]$。去掉首位后 $A'[1..n]$ 与 $B[1..n]$ 的可重集仍相同（两边同时移除了同一元素），由归纳假设 $A'[1..n]$ 可经相邻交换变为 $B[1..n]$，这些交换在 $A'$ 上同样合法。合并即得 $A \to B$ 的变换序列。∎

**定理**：arr 能经任意次子数组翻转变为 target，当且仅当两数组的可重集相等。

**证明**：（$\Rightarrow$）每次翻转保持可重集（引理 1），故可重集是整个操作过程的不变量；若最终 arr 与 target 逐位相等，则两者可重集相等。（$\Leftarrow$）长度为 2 的子数组翻转是题目允许操作的特例，由引理 2，可重集相同时存在一条由相邻交换组成的合法操作序列把 arr 变为 target。两个方向合并即得。∎

## 6. 复杂度分析

- **时间**：$O(n + V)$。统计 target 与抵消 arr 各一遍线性扫描，$V = 1000$ 为值域大小（清零与隐式检查）；$n \le 1000$，总计约几千次操作。
- **空间**：$O(V)$。计数数组 `cnt[1001]`；不随 $n$ 增长（若改用哈希表则为 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canBeEqual(vector<int>& target, vector<int>& arr) {
        int cnt[1001] = {0};
        for (int x : target) ++cnt[x];
        for (int x : arr)
            if (--cnt[x] < 0) return false;   // arr 里该值太多，立刻出局
        return true;                          // 两数组等长 → 计数必然全部归零
    }
};
```

### Python

```python
class Solution:
    def canBeEqual(self, target: List[int], arr: List[int]) -> bool:
        cnt = [0] * 1001
        for x in target:
            cnt[x] += 1
        for x in arr:
            cnt[x] -= 1
            if cnt[x] < 0:
                return False
        return True
```

> 💡 两份代码均通过全部官方示例（`true` / `true` / `false`），并与「排序判等」暴力实现做了 20 万组随机对拍（一半构造为重排），失配数为 0。

## 8. 边界情况与易错点

1. **单元素数组**（$n = 1$）：可重集判等退化为 $target[0] = arr[0]$，计数法天然正确。
2. **重复元素**：题目允许重复（如 $target = [5,5]$，$arr = [5,6]$），排序判等与计数判等都能正确区分「值相同但个数不同」的情形；若用 `set`（去重集合）判等就会误判为 true——这是本题最典型的错误。
3. **等长但值域外**：约束保证 $1 \le x \le 1000$，若开 `cnt[1000]` 会越界（值 1000 访问 `cnt[1000]`），必须开 1001。
4. **只单向检查即可**：不必检查「target 中有而 arr 中没有」的值——两数组等长，若 arr 没超计数，target 侧也必然恰好用完。
5. **别真去模拟翻转**：任何试图搜索/模拟翻转过程的写法在 $n = 1000$ 时都不可行，识别「可重集不变量」才是本题考点。
