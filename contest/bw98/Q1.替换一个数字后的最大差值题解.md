# LeetCode 替换一个数字后的最大差值 题解

## 1. 题目概述

- **标题 / 题号**：替换一个数字后的最大差值（#2566，easy）
- **链接**：https://leetcode.cn/problems/maximum-difference-by-remapping-a-digit/
- **来源**：LeetCode 第 98 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、数学

**题意**：给定整数 $num$（$1 \le num \le 10^8$）。一次「重映射」指：选定数字 $d_1$ 与 $d_2$（$0 \le d_1, d_2 \le 9$），把 $num$ 十进制表示中**所有** $d_1$ 都替换成 $d_2$。分别通过一次重映射得到**最大值**与**最小值**（允许用不同的 $d_1, d_2$），返回两者之差。替换成的数字可以含前导零，$d_1 = d_2$（即不变）也允许。

**约束**：

- $1 \le num \le 10^8$

## 2. 示例

**示例 1**

```text
输入：num = 11891
输出：99009
解释：最大值：把 1 全换成 9 → 99899；最小值：把 1 全换成 0 → 00890 = 890。差 = 99899 − 890 = 99009。
```

**示例 2**

```text
输入：num = 90
输出：99
解释：最大值：把 0 换成 9 → 99；最小值：把 9 换成 0 → 00 = 0。差 = 99 − 0 = 99。
```

**示例 3（边界补充）**

```text
输入：num = 999
输出：999
解释：最大值只能还是 999（没有非 9 数字可换）；最小值：9 全换 0 → 0。差 = 999 − 0 = 999。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $(d_1, d_2)$ 共 $10 \times 10 = 100$ 种重映射，每种 $O(\text{位数})$ 地构造新数，取最大、最小作差。总复杂度 $O(100 \times 9) = O(1)$（位数 $\le 9$），完全可行——$num \le 10^8$，位数最多 9 位，暴力本身已经是常数级操作。这不是「不可行」的暴力，而是「可以更优雅」的暴力：贪心把它压到两遍扫描。

### 3.2 核心观察：最大值换「第一个非 9」，最小值换「第一个数字为 0」

![核心观察：换第一个非 9 得最大，换最高位为 0 得最小](images/bw98_q1_remap_max_min.svg)

**最大化**：数位从左到右权重递减（第 $i$ 位权重 $10^{m-1-i}$），想让数变大，应把**尽量靠左**的数位变大。替换必须对所有相同数字统一进行，于是：

- 找**最左边不是 9** 的数字 $d$，把它全部换成 9——比它左边的数字都是 9（无需换也换不动更大），$d$ 所在的每一位都从 $d < 9$ 升到 9，且越靠左收益越大。任何其他选择（换更靠右的数字、或把 $d$ 换成非 9）都不会更优。
- 若所有数位都是 9，无数字可提升，最大值就是原数。

**最小化**：对称地，想让数变小，应把**最左边（最高位）的数字** $d_0 = $ 最高位全部换成 0——前导零在数值上被自然丢弃。最高位从 $d_0 \ge 1$ 降为 0，使数直接掉一个数量级，这是可能的最大降幅；换其他数字最多影响低位。注意：如果换的不是最高位数字，被换的位再怎么降也保不住最高位；而换最高位数字时**它出现的每一位**都归零，包括它可能出现的高位。任何最小化方案都不可能绕过「把最高位归零」这一步（详见 §5）。

### 3.3 算法流程

![算法流程：两次单遍扫描求 max 与 min](images/bw98_q1_algorithm_flow.svg)

```text
1. s ← num 的十进制字符串
2. 最大值 mx：
       d ← s 中第一个不等于 '9' 的字符（若存在）
       mx ← 把 s 中所有 d 替换成 '9'（若不存在这样的 d，mx = num）
3. 最小值 mn：
       d0 ← s[0]（最高位数字）
       mn ← 把 s 中所有 d0 替换成 '0'（前导零按数值处理自动丢弃）
4. 返回 mx − mn
```

### 3.4 示例演算

**示例 1**（`num = 11891`，`s = "11891"`）：

| 目标 | 选中的数字 | 替换后字符串 | 数值 |
|------|-----------|--------------|------|
| 最大 | $d = 1$（第一个非 9） | "99899" | 99899 |
| 最小 | $d_0 = 1$（最高位） | "00890" | 890 |

差 $= 99899 - 890 = 99009$ ✓。

**示例 2**（`num = 90`）：最大：第一个非 9 是 '0' → "99" = 99；最小：最高位 '9' → "00" = 0；差 $99$ ✓。

**边界**（`num = 999`）：最大：无非 9 数字 → 999；最小："000" = 0；差 $999$ ✓。再如 `num = 10`：最大：'1'→"90" = 90？不对——第一个非 9 是 '1'，换成 9 得 "90" = 90；但更优的是换 '0' 得 "19" = 19 < 90。验证：90 是不是真实最大？$num = 10$ 的所有重映射：换 1→9 得 90；换 0→9 得 19；其他不增。最大确为 90 ✓（换最靠左的非 9 数字正确）。最小：最高位 '1' → "00" = 0 ✓。差 $90$。

## 4. 算法细节

1. **为什么最大值选「第一个非 9」而不是「任意非 9」**：设 $s$ 中位置 $i < j$ 都是非 9 数字 $d_i \ne d_j$。换 $d_i$ 时位置 $i$ 从 $d_i$ 升到 9，收益 $\ge (9 - d_i) \cdot 10^{m-1-i}$；换 $d_j$ 时位置 $i$ 不变（$d_i \ne d_j$），收益 $\le (9 - 0) \cdot 10^{m-1-j} < 10^{m-1-i} \le$ 前者（当 $d_i \le 8$ 时 $(9-d_i) \ge 1$，故 $(9-d_i) \cdot 10^{m-1-i} \ge 10^{m-1-i} > 9 \cdot 10^{m-1-j}$？需 $10^{m-1-i} > 9 \cdot 10^{m-1-j}$ 即 $10^{j-i} > 9$，$j > i$ 时成立）。故换更靠左的严格更优。
2. **为什么最小值选「最高位数字」**：最高位 $d_0 \ge 1$（无前导零），把它归零使数值至少减 $d_0 \cdot 10^{m-1} \ge 10^{m-1}$，即至少砍掉一个数量级。换任何其他数字 $d$（$d \ne d_0$）最多让各位降 $(d - 0) \cdot 10^{pos} \le 9 \cdot 10^{m-2} < 10^{m-1}$（最高位分毫未动）。故归零最高位严格最优（$m \ge 2$ 时；$m = 1$ 时两者一致，最高位也是唯一位）。
3. **前导零处理**：`"00890"` 数值化为 890 由 `stoi`/`int()` 自动完成；若手写按位累加，从左到右乘 10 加位也天然正确，无需删零。
4. **`d_1 = d_2` 的退化**：允许「不变」对应 $d_1 = d_2$ 或 $d_1$ 不出现在 $s$ 中，两种都不会超过贪心选出的最优，无需特判。
5. **一遍实现**：最大与最小可共用同一个「找到目标字符 → 全串替换」的辅助逻辑；C++ 用 `std::string::replace` 循环或逐字符重建，Python 一行 `s.replace(c, '9')`。
6. **位数与规模**：$num \le 10^8$，位数 $\le 9$，替换与转换均为常数操作。

## 5. 正确性证明

**引理 1（最大值刻画）**：设 $s$ 为 $num$ 的 $m$ 位十进制表示，$i^*$ 为最左非 9 数位下标（若存在）。则所有重映射能得到的最大值为「把 $s_{i^*}$ 全部换成 9」的结果；若不存在 $i^*$（全 9），最大值为 $num$ 本身。

**证明**：重映射 $(d_1, d_2)$ 只改变 $d_1$ 出现的数位。若 $d_2 \le d_1$，新数 $\le num$，不超过候选方案（候选 $\ge num$，因它把 $< 9$ 的位换成 9 而不动其他位……严格地：候选把 $s_{i^*}$ 位升为 9、其余位不变，故候选 $\ge num$）。考虑 $d_2 > d_1$ 的映射：只有含 $d_1$ 的位上升。对任意这样的映射，构造比较：设 $j$ 为 $d_1$ 在 $s$ 中出现的最左位置。若 $j > i^*$：位置 $i^*$ 的数字 $s_{i^*} \ne d_1$（否则 $d_1$ 最左出现 $\le i^*$），不受该映射影响，保持 $s_{i^*} \le 8$；而候选方案在位置 $i^*$ 是 9，且候选与该映射在位置 $< i^*$ 处：候选不动（全 9），该映射要么不动要么把某 9 换走？——$d_2 \le 9$，若 $d_1$ 出现在 $i^*$ 之前则那一位是 9（因 $i^*$ 是最左非 9），被换成 $d_2 \le 9$ 不增。故两数从高位向低位比较，第一个不同位处候选 $\ge$ 该映射（位置 $i^*$：候选 9 vs 原值 $\le 8$，或更早位置候选不小于它），得候选 $\ge$ 任意映射结果。若 $j = i^*$（即 $d_1 = s_{i^*}$）：该映射把含 $d_1$ 的位升到 $d_2 \le 9$，候选升到 9，且两方案改变的位集合相同（都是 $d_1$ 出现的位），候选在每一位的升幅 $\ge$ 该映射，故候选 $\ge$。若 $j < i^*$ 不可能（$i^*$ 之前全 9，$d_1$ 出现在那里意味着 $d_1 = 9$，与 $d_2 > d_1$ 矛盾）。全 9 时任何 $d_2 > d_1 = 9$ 不存在，任何映射不增，最大为 $num$。∎

**引理 2（最小值刻画）**：所有重映射能得到的最小值为「把最高位数字 $s_0$ 全部换成 0」的结果。

**证明**：候选值把含 $s_0$ 的位全归零，最高位变 0，数值 $< 10^{m-1}$（前导零丢弃后位数 $\le m-1$，或直接说最高有效位至多在第 $m-1$ 位）。任取映射 $(d_1, d_2)$：若 $d_1 \ne s_0$，最高位 $s_0 \ge 1$ 保持不变，结果 $\ge 10^{m-1} >$ 候选。若 $d_1 = s_0$：若 $d_2 = 0$ 结果恰为候选；若 $d_2 \ge 1$，最高位变为 $d_2 \ge 1$，结果 $\ge 10^{m-1} >$ 候选（候选最高位为 0）。故候选最小。∎

**定理**：算法返回值为 $\max_{\text{映射}} v - \min_{\text{映射}} v$。

**证明**：由引理 1、引理 2，算法分别取到最大值 $mx$ 与最小值 $mn$（最大与最小允许用不同映射，题面明示），返回 $mx - mn$ 即所求差值。∎

## 6. 复杂度分析

- **时间**：$O(m)$，$m = \lfloor \log_{10} num \rfloor + 1 \le 9$。找目标字符一遍、替换一遍、字符串转整数一遍，合计常数次 $O(m)$ 扫描。
- **空间**：$O(m)$ 存字符串副本（$m \le 9$，常数级）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minMaxDifference(int num) {
        string s = to_string(num);
        string mx = s, mn = s;
        for (char c : s) {                      // 第一个非 9 数字 → 9
            if (c != '9') {
                for (char& t : mx) if (t == c) t = '9';
                break;
            }
        }
        char lead = s[0];                       // 最高位数字 → 0
        for (char& t : mn) if (t == lead) t = '0';
        return stoi(mx) - stoi(mn);             // 前导零在转整数时自动消失
    }
};
```

### Python

```python
class Solution:
    def minMaxDifference(self, num: int) -> int:
        s = str(num)
        mx = s
        for c in s:                             # 第一个非 9 数字全部换成 9
            if c != '9':
                mx = s.replace(c, '9')
                break
        mn = s.replace(s[0], '0')               # 最高位数字全部换成 0
        return int(mx) - int(mn)
```

> 💡 两份代码均通过官方示例（`99009`、`99`）、全 9 边界（`999 → 999`）以及 3000 组随机数与「枚举全部 $10 \times 10$ 重映射」暴力的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **全 9 数**：`999` 没有可提升的数字，最大值即原数——循环自然不触发替换，`mx = s` 正确；易错点是强行找「第一个非 9」并解引用不存在位置。
2. **单一位数**：`num = 5`，最大 5（无可换），最小 0（最高位归零），返回 5。`s[0]` 即唯一位，逻辑不变。
3. **最高位数字在低位重复出现**：如 `11891` 的最高位 1 出现三次，最小化必须**全部**归零（映射对所有相同数字生效），漏掉低位出现会得到 `90890` 之类的错误最小值。
4. **前导零不是错误**：`"00890"` 合法且数值为 890，不要试图手动删零或特判「替换后位数变短」。
5. **最大化别选错目标**：换「第一个非 9」而不是「最大的非 9 数字」或「任意非 9」。反例 `19`：换 1 得 99，换 9（不存在更优路径）——若误选「数值最大的非 9 数字」在 `91` 中选 9 换成…… 9 已是 9，只剩 1，恰好也对；但 `29` 中第一个非 9 是 2 → 99（对），而「最大非 9」也是 2，看似一致——真正的反例是 `92`：第一个非 9 是 2 → 99 ✓；「选最大非 9」也是 2。两者只在多重非 9 数字时分化：`123`：第一个非 9 是 1 → 923 ✓（最优）；若选最大非 9 数字 3 → 129 ✗。务必按位置选。
6. **差值范围**：$mx \le 10^9 - 1$（9 位全 9 是 $999999999 > 10^8$？$num \le 10^8$ 即最高 9 位是 $100000000$，其最大映射为 $900000000$），$mn \ge 0$，差 $\le 9 \times 10^8$，`int` 足够。
