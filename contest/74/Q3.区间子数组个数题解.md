# LeetCode 区间子数组个数 题解

## 1. 题目概述

- **标题 / 题号**：区间子数组个数（#795，medium）
- **链接**：https://leetcode.cn/problems/number-of-subarrays-with-bounded-maximum/
- **来源**：LeetCode 第 74 场周赛 Q3
- **难度**：中等
- **标签**：数组、双指针

**题意**：给定整数数组 `nums` 和两个整数 $left \le right$。统计所有**连续、非空**的子数组 $A$ 中，满足 $\max(A) \in [left, right]$（子数组的最大值落在闭区间内）的个数。

关键点：被判定的对象是「**整个子数组**的最大值」，不是单个元素是否符合；同一个子数组只计一次。

**约束**：

- $1 \le n = \text{nums.length} \le 10^5$
- $0 \le \text{nums}[i] \le 10^9$
- $0 \le left \le right \le 10^9$
- 测试用例保证答案落在 32 位有符号整数范围内

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,4,3]，left = 2，right = 3
输出：3
解释：最大值落在 [2, 3] 的子数组是 [2]、[2,1]、[3]。
      [1] 的 max = 1 < left；任何含 4 的子数组 max = 4 > right，都不合格。
```

**示例 2**

```text
输入：nums = [2,9,2,5,6]，left = 2，right = 8
输出：7
解释：9 是唯一的「超界元素」，它把数组切成 [2] 与 [2,5,6] 两段（跨段的子数组必含 9，全部不合格）；
      前一段只有 [2] 合格；后一段 3 个元素的 6 个子数组最大值为 2/5/6，全部合格，共 1 + 3×4/2 = 7 个。
```

**补充示例**（下文演算与边界会用到）

```text
输入：nums = [0,1,2]，left = 1，right = 2  →  5（[1]、[1,2]、[2]、[0,1]、[0,1,2]）
输入：nums = [5,5]，left = 3，right = 3     →  0（每个子数组的 max 都是 5 > right）
输入：nums = [0]，left = 0，right = 0       →  1（left = 0 的边界）
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子数组 $[l,r]$，边向右扩展边维护最大值，落在区间内就计数：共有 $\frac{n(n+1)}{2}$ 个子数组，时间 $O(n^2)$、空间 $O(1)$。$n = 10^5$ 时约有 $5 \times 10^9$ 个区间，远超时限。

另一种常见的「伪优化」：把每个元素当作最大值，向左右扩展求它的贡献。当数组大量重复（例如全为同一个数）时，每个元素都能扩展到 $O(n)$，依旧 $O(n^2)$。

瓶颈在于「一个子数组要判一次」。要降到 $O(n)$，必须让**一整段连续的子数组被一次性计数**。

### 3.2 核心观察：「最大值 ≤ x」比「最大值 ∈ [left, right]」好数

![三类元素与集合差](images/wc74_q3_bounded_split.svg)

按元素与 $[left, right]$ 的关系分成三类：

- **锚**：$left \le \text{nums}[i] \le right$，子数组含锚就保证最大值 $\ge left$；
- **陪衬**：$\text{nums}[i] < left$，自身不满足下界，只能挂在锚后面；
- **墙**：$\text{nums}[i] > right$，任何包含它的子数组直接出局，并把数组切成互不影响的几段。

直接数「必须包含锚」还是有点绕，于是换成**只带一个上界**的条件。记

$$g(x) = \#\{\, A \mid A \text{ 是连续非空子数组，且 } \max(A) \le x \,\}$$

它等价于「$A$ 的**所有**元素都 $\le x$」——这个条件对子数组是**封闭**的：一段区间全部 $\le x$，则它的任意子区间也全部 $\le x$。于是把 $> x$ 的元素当作墙，数组被切成若干**极大段**，长度 $L$ 的段内部任取一对端点都合法，贡献 $\frac{L(L+1)}{2}$。

再用集合差回到原问题：

$$\max(A) \in [left, right] \iff \max(A) \le right \ \wedge\ \neg\bigl(\max(A) \le left-1\bigr)$$

于是

$$\text{ans} = g(right) - g(left-1)$$

**两次同构的扫描 + 一次减法**，就把「双边界」拆成了两次「单边界」。

### 3.3 算法流程 / 状态转移

![两次计数扫描的流程](images/wc74_q3_count_flow.svg)

$g(x)$ 不必真的先分段再套公式，扫描时用两个计数器即可：

- `run`：以当前位结尾、且全部元素 $\le x$ 的子数组个数；
- `total`：到目前为止所有元素 $\le x$ 的子数组个数。

递推式

$$\text{run}_i = \begin{cases}\text{run}_{i-1}+1, & \text{nums}[i] \le x\\[2pt] 0, & \text{nums}[i] > x\end{cases} \qquad\qquad \text{total} \mathrel{+}= \text{run}_i$$

因为以 $i$ 结尾的合法子数组，起点恰好可取 $[\,i-\text{run}_i+1,\ i\,]$ 中任意一个，共 $\text{run}_i$ 个。扫完一遍 `total` 就是 $g(x)$，两次调用相减即得答案。

> 💡 `run` 的物理含义是「当前这一段已经走到第几个元素」，所以逐位累加 $1+2+\cdots+L$ 恰好等于 $\frac{L(L+1)}{2}$，与分段公式完全一致。

**等价写法：单趟双指针**。也可以只扫一遍，维护两个下标：

![双指针 j − i 计数](images/wc74_q3_two_pointer_scan.svg)

- $i$ = 最后一个 $> right$ 的下标（墙），$j$ = 最后一个 $\ge left$ 的下标（锚），初值都为 $-1$；
- 遇 $\text{nums}[r] > right$：$i \leftarrow r$，$j \leftarrow -1$（旧锚全部作废）；
- 遇 $left \le \text{nums}[r] \le right$：$j \leftarrow r$；
- 遇 $\text{nums}[r] < left$：两者都不动；
- 每步累加 $\max(0,\, j-i)$。

固定右端 $r$ 时，起点必须 $> i$（否则把墙包了进来），又必须 $\le j$（否则取不到任何锚、最大值 $< left$），合法起点恰有 $j-i$ 个。

### 3.4 示例演算

![示例演算](images/wc74_q3_walkthrough.svg)

以 `nums = [2,1,4,3]`、$left = 2$、$right = 3$ 走一遍：$x = 3$ 时数组被 4 切成 `[2,1]` 与 `[3]`，$g(3) = 3 + 1 = 4$；$x = left-1 = 1$ 时只剩单元素 `[1]`，$g(1) = 1$；答案 $4 - 1 = 3$。

同一组数据用双指针写法：

| 右端 $r$ | $\text{nums}[r]$ | 类型 | $i$ | $j$ | 累加 $j-i$ | ans |
|---------|------------------|------|-----|-----|-----------|-----|
| 0 | 2 | 锚 | −1 | 0 | 1 | 1 |
| 1 | 1 | 陪衬 | −1 | 0 | 1 | 2 |
| 2 | 4 | 墙 | 2 | −1 | 0 | 2 |
| 3 | 3 | 锚 | 2 | 3 | 1 | 3 |

两种写法都得到 3，与暴力枚举全部 10 个子数组的结果一致。

## 4. 算法细节

1. **拆成两次扫描**：把「上界」与「下界」解耦，每次只判一个不等式，逻辑与证明都变简单，代价仅是常数 2。
2. **`total += run` 的顺序**：必须先更新 `run`，再累加 `total`。若在 `run = 0` 之后累加，会漏掉「只有当前位一个元素」的那批区间。
3. **中间量要用 64 位**：单段长度最大 $10^5$，$\frac{L(L+1)}{2} \approx 5 \times 10^9 > 2^{31}-1$。即使答案保证在 32 位内，$g(right)$ 本身也可能溢出——例如元素全为 $1$、$left = 5$、$right = 10^9$ 时答案是 $0$，但 $g(right) = 5 \times 10^9$。所以 `run`、`total` 用 `long long`，只在返回值处收窄。
4. **$left = 0$ 的哨兵**：此时 $x = left-1 = -1$，而 $\text{nums}[i] \ge 0$，故 $g(-1) = 0$ 天然成立，不需要写特判分支（特判反而容易写错方向）。
5. **双指针必须同时重置 $i$ 与 $j$**：遇到墙时要 $i \leftarrow r$ 且 $j \leftarrow -1$。只更新 $i$ 会让墙左边的旧锚「越界存活」，$j-i$ 变成负数或把墙计入区间。
6. **别用 $O(n^2)$ 的写法**：不要「枚举左端点 + 单调队列维护最大值」，也不要「每个元素向两侧扩展」。$n = 10^5$ 时都过不去。
7. **答案下界是 0**：全 $< left$ 或全 $> right$ 时两次 $g$ 相减天然得 0，无需额外分支；但手写双指针时必须写成 $\max(0, j-i)$。

## 5. 正确性证明

**引理 1（分段公式）**：固定 $x$，设数组被所有 $> x$ 的元素切成极大段，段长为 $L_1, \dots, L_m$，则

$$g(x) = \sum_{k=1}^{m} \frac{L_k(L_k+1)}{2}$$

**证明**：若子数组 $A$ 满足 $\max(A) \le x$，则 $A$ 的每个元素都 $\le x$，故 $A$ 不可能跨过任何一个 $> x$ 的元素，必整体落在某个极大段内；反之，极大段内任取连续区间，其元素都 $\le x$。长度为 $L$ 的段内共有 $\frac{L(L+1)}{2}$ 个连续区间，不同段的区间互不相同（被墙隔开、不会重复），求和即得。∎

**引理 2（`run` / `total` 递推正确）**：扫描到下标 $i$ 时，`run` 等于「以 $i$ 结尾、且所有元素 $\le x$ 的子数组个数」，`total` 等于「只使用下标 $\le i$ 的元素、且所有元素 $\le x$ 的子数组个数」。

**证明**：对 $i$ 归纳。$i = -1$ 时两者为 0，成立。设 $i-1$ 时成立。

- 若 $\text{nums}[i] > x$：任何以 $i$ 结尾的子数组都含 $\text{nums}[i] > x$，个数为 $0$，与 `run = 0` 一致；`total` 不变也正确，因为新增的候选子数组全部不合格。
- 若 $\text{nums}[i] \le x$：以 $i$ 结尾的合法子数组，其起点必须大于「上一个 $> x$ 元素的下标」，而「以 $i-1$ 结尾的合法子数组的起点集合」正是 $[\,i-\text{run}_{i-1},\ i-1\,]$；给每个这样的子数组尾部接上 $\text{nums}[i]$ 仍然全部 $\le x$，再加上单元素 $[i]$，共 $\text{run}_{i-1}+1 = \text{run}_i$ 个，且起点再往左必然撞墙。故 `run` 正确。

`total` 是「每个位置作为右端点的个数」累加，每个合格子数组有唯一右端点，故不重不漏。∎

**引理 3（集合差）**：对任意非空连续子数组 $A$：$\max(A) \le right$ 且 $\max(A) \not\le left-1$，当且仅当 $left \le \max(A) \le right$。

**证明**：$\max(A)$ 是整数，$\max(A) > left-1 \iff \max(A) \ge left$。故左侧条件等价于 $\max(A) \le right$ 且 $\max(A) \ge left$，即 $left \le \max(A) \le right$；反向显然。∎

**引理 4（双指针的 $j-i$）**：固定右端 $r$，维护量 $i$ / $j$ 如上，则以 $r$ 结尾的合格子数组个数为 $\max(0, j-i)$。

**证明**：设起点为 $s \le r$。$[s,\, r]$ 内没有 $> right$ 的元素 $\iff s > i$（$i$ 是 $\le r$ 的最后一个 $> right$ 下标）。在 $s > i$ 的前提下，$j$ 是 $\le r$ 的最后一个 $\ge left$ 的下标，且 $j > i$ 当且仅当这段里存在锚；此时 $[s,\,r]$ 包含 $\text{nums}[j]$ $\iff s \le j$。综上合法起点集合为 $\{\,i+1, \dots, j\,\}$，元素个数 $\max(0, j-i)$。∎

**定理**：`numSubarrayBoundedMax` 返回满足条件的子数组个数。

**证明**：由引理 2，`count(x)` 返回 $g(x)$；由引理 1，$g(x)$ 的取值等于分段公式（两条路径互证，实现与公式无矛盾）。由引理 3，$g(right) - g(left-1)$ 恰为 $\max(A) \in [left, right]$ 的子数组个数，且 $g(right) \ge g(left-1)$ 保证差值非负。故返回值正确。§3.3 的等价写法由引理 4 逐步累加同一类子数组，结果必然相同。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`count(x)` 是一次线性扫描（一次比较 + 常数次加法），调用两次共 $2n$ 步；双指针写法一趟 $n$ 步。没有排序或对数因子。
- **空间**：$O(1)$。只用 `run` / `total`（或 `i` / `j` / `ans`）常数个变量，原地读取输入，不额外开数组。
- 常数层面：每步都是一次整数比较和一次加法，$n = 10^5$ 时远低于时限。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int numSubarrayBoundedMax(vector<int>& nums, int left, int right) {
        // 统计「所有元素都 <= x」的子数组个数
        auto count = [&](int x) -> long long {
            long long total = 0, run = 0;
            for (int v : nums) {
                if (v <= x) {
                    ++run;
                    total += run;
                } else {
                    run = 0;
                }
            }
            return total;
        };
        return (int)(count(right) - count(left - 1));
    }
};
```

### Python

```python
class Solution:
    def numSubarrayBoundedMax(self, nums: list[int], left: int, right: int) -> int:
        def count(x: int) -> int:
            # 所有元素都 <= x 的子数组个数
            total = run = 0
            for v in nums:
                if v <= x:
                    run += 1
                    total += run
                else:
                    run = 0
            return total

        return count(right) - count(left - 1)
```

## 8. 边界情况与易错点

1. **32 位溢出**：`run`、`total` 用 `long long`（Python 无此问题）。答案虽然保证在 32 位内，但 $g(right)$ 本身可能达到 $5 \times 10^9$，见 §4 第 3 条。
2. **$left = 0$**：$x = left - 1 = -1$，$g(-1) = 0$ 自然成立，不要为它写特判分支。
3. **单元素与全越界**：`nums = [5]`、$left = right = 3$ 返回 0；`nums = [5]`、$left = right = 5$ 返回 1；`nums = [1,1]`、$left = right = 2$ 返回 0。
4. **$\le$ 不能写成 $<$**：`count(x)` 判的是「所有元素 $\le x$」，边界元素（如 $\text{nums}[i] = left$）必须计入，否则示例 1 会少算 `[2]`。
5. **双指针忘记重置 $j$**：遇墙时只改 $i$ 不改 $j$，会让 $j-i$ 变负或把墙计入，是最常见的错误写法。
6. **`total += run` 的位置**：必须先自增 `run` 再累加，顺序颠倒会漏掉单元素区间。
7. **手动双指针要取 $\max$**：$j \le i$ 时贡献为 0，直接累加 `j - i` 会遇到负数。

**延伸思考**：

- 若要求 $\max(A) = k$（恰好等于），直接算 $g(k) - g(k-1)$，仍是 $O(n)$；若要求**次大值**落在区间内，双指针不再够用，需要同时跟踪最大与次大，或改用单调栈 + 分治。
- 若元素允许为负数，结论不变：推导只用到「$\max \le x$ 对子区间封闭」和整数比较，与元素符号无关。把题目的「最大值」换成「最小值」，只需把所有 $\le$ 改成 $\ge$，对称可解。
- 若要求「子数组和」在 $[L, R]$ 内，计数变成经典的前缀和 + 归并排序 / 树状数组，$O(n \log n)$，与本题的极值技巧无关。
