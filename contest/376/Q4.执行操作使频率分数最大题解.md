# LeetCode 执行操作使频率分数最大 题解

## 1. 题目概述

- **标题 / 题号**：执行操作使频率分数最大（#2968，hard）
- **链接**：https://leetcode.cn/problems/apply-operations-to-maximize-frequency-score/
- **来源**：LeetCode 第 376 场周赛 Q4
- **难度**：困难
- **标签**：数组、排序、滑动窗口、前缀和、二分

**题意**：给定下标从 $0$ 开始的整数数组 `nums` 和整数 $k$。每次操作可任选一个下标 $i$，把 `nums[i]` **加 1 或减 1**，至多执行 $k$ 次。操作完成后，数组的**频率分数**定义为众数（出现次数最多的数）的出现次数。求能得到的最大频率分数。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$
- $0 \le k \le 10^{14}$

> 💡 读题抓三个信号：① 操作是 $\pm 1$ 且**双向**，代价就是元素与目标值的绝对差——这是「归拢」型问题的标志，区别于只能加的 [LC 1838](https://leetcode.cn/problems/frequency-of-the-most-frequent-element/)；② $k$ 高达 $10^{14}$，逐次模拟必死，必须把「把一堆元素变成同一个数的最小步数」压成 $O(1)$ 计算；③ 众数只关心**出现次数**，不关心是哪个值——于是问题从「值域上选目标」坍缩为「排序数组上选连续段」。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,6,4], k = 3
输出：3
解释：把 1 加 1 变成 2，把 4 减两次变成 2，正好花 3 步：
      [1,2,6,4] → [2,2,6,4] → [2,2,6,3] → [2,2,6,2]，众数 2 出现 3 次。
```

**示例 2**

```text
输入：nums = [1,4,4,2,4], k = 0
输出：3
解释：k = 0 无法操作，答案就是原数组众数 4 的频率 3。
```

**示例 3（自造，k 充裕）**

```text
输入：nums = [1, 1000000000], k = 999999999
输出：2
解释：排序后 [1, 10^9]，以 1 为中位数，代价 = 10^9 − 1 = k，恰好够 → 全部归拢。
```

**示例 4（自造，单元素）**

```text
输入：nums = [7], k = 0
输出：1
解释：长度 1 的窗口代价恒为 0，答案至少是 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的暴力是**枚举目标值 + 枚举元素集合**：选定一个目标值 $v$，再从 $n$ 个元素里挑 $m$ 个变成 $v$，代价是所选元素 $\sum |a_i - v|$，问代价 $\le k$ 下 $m$ 最大能到多少。

- 目标值取遍值域 $[1, 10^9]$：直接爆炸；
- 退一步，$v$ 只需取 $n$ 个已有元素值（第 5 节会证明更紧的形式——只需取段中位数），对每个 $v$ 把所有 $|a_i - v|$ 排序后贪心取最小的 $m$ 个：单次 $O(n \log n)$，总计 $O(n^2 \log n)$，$n = 10^5$ 时约 $10^{11}$ 量级，仍不可行；
- 更朴素地逐次模拟 $k$ 次操作更是无从谈起（$k \le 10^{14}$）。

暴力的困境在于「值域」和「子集」两个维度都在爆炸。突破口是第 1 节的信号 ③：**众数不关心值，只关心个数**——把数组排序后，最优方案里被归拢的元素必然可以取成**连续段**，两个爆炸维度同时消失。

### 3.2 核心观察：排序后取连续段，目标值取中位数

![核心观察：排序后取连续段，目标值取中位数](images/wc376_q4_median_window_concept.svg)

三个观察层层递进：

- **观察 1（连续段）**：固定目标值 $v$ 和个数 $m$，代价最小的选法是按 $|a_i - v|$ 从小到大挑选 $m$ 个（交换论证：若弃了近的 $y$ 选了远的 $x$，换回来代价不增）。而这些「距离 $v$ 不超过阈值」的元素恰是排序数组中**围绕 $v$ 的一段连续区间**——于是**存在最优解，其选中集合是排序后的连续段**（引理 1）。
- **观察 2（中位数）**：段 $[l, r]$ 选定后，把段内元素变成 $t$ 的代价 $\sum_{i=l}^{r} |a_i - t|$ 是关于 $t$ 的凸函数，最小值恰在段内**中位数**处取到（引理 2，同 [LC 462](https://leetcode.cn/problems/minimum-moves-to-equal-array-elements-ii/) 的中位数引理）。
- **观察 3（众数频率 = 段长）**：段内元素全部变成 $t$ 后，$t$ 至少出现 $r - l + 1$ 次；未被选中的元素若恰好等于 $t$ 只会更多。于是**最大化频率分数 ⟺ 找最长的连续段，使「归拢到中位数」的代价 $\le k$**。

$$\boxed{\ \text{最大频率分数}\ =\ \max\{\, r - l + 1 \ :\ \text{cost}(l, r) \le k\ \}\ }$$

其中 $\text{cost}(l, r) = \min_{t} \sum_{i=l}^{r} |a_i - t|$，最优 $t$ 取 $a\!\left\lfloor \frac{l+r}{2} \right\rfloor$。

### 3.3 算法流程：前缀和 $O(1)$ 算代价 + 双指针滑动窗口

段是「连续」的，且代价只与端点有关——这正是滑动窗口的标准形态。

![算法流程：排序、前缀和与双指针滑动窗口](images/wc376_q4_sliding_window_flow.svg)

1. **排序**，建前缀和 $pre$，$pre[i] = \sum_{j<i} a_j$；
2. 右端点 $r$ 从左往右扫；对每个 $r$，维护最小的可行 $l$：用中位数公式 $O(1)$ 算出 $\text{cost}(l, r)$，若 $> k$ 则 $l$ 右移；
3. 每步用 $r - l + 1$ 更新答案。

窗口「越长代价越大」的单调性（引理 3）保证 $l$ 不回退，两端各扫一遍，窗口部分 $O(n)$。

> ⚠️ 另一条路线是**二分答案**（本题标签里的 Binary Search）：二分频率 $f$，`check` 扫所有长度为 $f$ 的窗口看最小代价是否 $\le k$，由引理 3 可行性关于 $f$ 单调。复杂度同为 $O(n \log n)$ 量级，但滑窗版把二分也省了，代码更短，是更优写法。

### 3.4 示例演算

![示例演算：nums=[1,2,6,4], k=3 的滑动窗口全过程](images/wc376_q4_example_walkthrough.svg)

以示例 1 走一遍（排序后 $a = [1,2,4,6]$，$pre = [0,1,3,7,13]$）：

| $r$ | 窗口 | 中位数 $t$ | $\text{cost}$ | 动作 | $ans$ |
|-----|--------|-----------|--------------|--------------|-------|
| 0 | $[1]$ | 1 | $0 \le 3$ | 记录 | 1 |
| 1 | $[1,2]$ | 1 | $1 \le 3$ | 记录 | 2 |
| 2 | $[1,2,4]$ | 2 | $3 \le 3$ | 记录 | **3** |
| 3 | $[1,2,4,6]$ | 2 | $7 > 3$ | $l\!+\!+$ → $[2,4,6]$ 代价 $4 > 3$，再 $l\!+\!+$ → $[4,6]$ 代价 $2 \le 3$ | 3 |

最终答案 $3$，对应方案「把 1、4、6 都改成 2」，与官方解释一致。

## 4. 算法细节

**代价公式**。设 $m = \left\lfloor \frac{l+r}{2} \right\rfloor$（中位数下标，偶数长窗口取偏左中位数），$t = a[m]$。中位数把窗口切成左半（都 $\le t$，要抬高）与右半（都 $\ge t$，要压低）：

![代价的 O(1) 计算：中位数切开，两侧前缀和](images/wc376_q4_prefix_cost_formula.svg)

$$\text{cost}_L = t \cdot (m - l + 1) - \big(pre[m+1] - pre[l]\big)$$

$$\text{cost}_R = \big(pre[r+1] - pre[m+1]\big) - t \cdot (r - m)$$

$$\text{cost}(l, r) = \text{cost}_L + \text{cost}_R$$

实现要点：

1. **排序**是一切前提——连续段、中位数、前缀和全部定义在有序数组上；
2. **偶数长窗口**的中位数取 $a[m]$ 或 $a[m+1]$ 代价相同（两中位元素之间任何整点都是最优点），代码统一取 $m = \lfloor (l+r)/2 \rfloor$，无需分类讨论；
3. **双指针不变式**：处理完 $r$ 后恒有 $\text{cost}(l, r) \le k$。收缩循环不会越过 $l = r$——单元素窗口代价恒为 $0 \le k$；
4. **量级**：$t \cdot (m - l + 1)$ 最大约 $10^9 \times 10^5 = 10^{14}$，且 $k$ 本身可达 $10^{14}$——C++ 全程 `long long`，Python 天然大整数无忧。

## 5. 正确性证明

**引理 1（连续段引理）**：存在一个最优方案，使得「被变成众数值的元素集合」在排序后数组中是连续段。

**证明**：任取一个最优方案，设众数值为 $v$，被变为 $v$ 的原值多重集合为 $S$（$|S| = f$ 为其频率），操作代价 $\text{cost}(S, v) = \sum_{x \in S} |x - v| \le k$。固定 $v$ 与 $f$，把所有元素按 $|a_i - v|$ 从小到大重排，取前 $f$ 个构成的集合 $S^*$ 满足 $\text{cost}(S^*, v) \le \text{cost}(S, v)$（交换论证：若 $S$ 弃了近的 $y$ 选了远的 $x$，用 $y$ 换 $x$ 代价不增）。而 $\{a_i : |a_i - v| < d\}$ 是数轴区间 $(v-d, v+d)$ 内的元素，在排序数组中连续；距离恰为阈值 $d$ 的元素紧邻其两侧——故 $S^*$ 可取为连续段。段的可行性与 $S$ 相同，且长度同为 $f$。∎

**引理 2（中位数引理）**：对固定段 $[l, r]$，$f(t) = \sum_{i=l}^{r} |a_i - t|$ 的最小值在 $t$ 为段中位数时取到，且可取 $t = a[\lfloor (l+r)/2 \rfloor]$（段内元素）。

**证明**：$f$ 是分段线性凸函数。$t$ 右移 $\delta > 0$ 时，每个 $a_i < t$ 的项贡献 $+\delta$，每个 $a_i > t + \delta$ 的项贡献 $-\delta$（忽略跨越点，其变化不超过 $\delta$ 且凸性保证不等式方向）。故当「小于 $t$ 的元素个数」多于「大于 $t$ 的元素个数」时 $f$ 随 $t$ 增大而减小，反之增大；最小值恰在两侧计数翻转处——即中位数。段长为奇数时中位元素唯一，取 $a[m]$，$m = \lfloor (l+r)/2 \rfloor$；段长为偶数时区间 $[a[m], a[m+1]]$ 内每个整点都是最优点，$a[m]$ 亦属之。∎

**引理 3（窗口单调引理）**：若 $[l', r'] \supseteq [l, r]$，则 $\text{cost}(l', r') \ge \text{cost}(l, r)$。

**证明**：对任意 $t$，$\sum_{i \in [l', r']} |a_i - t| = \sum_{i \in [l, r]} |a_i - t| + \sum_{i \in [l', r'] \setminus [l, r]} |a_i - t| \ge \sum_{i \in [l, r]} |a_i - t|$。两边对 $t$ 取最小值，不等号保持。∎

**推论**：固定 $r$，$\text{cost}(l, r)$ 随 $l$ 增大不增，可行 $l$ 构成后缀 $\{l_{\min}(r), \dots, r\}$；且 $l_{\min}(r)$ 随 $r$ 单调不减。

**证明**：前者由引理 3（窗口随 $l$ 增大而缩小）直接得。后者：若 $l < l_{\min}(r)$，则 $\text{cost}(l, r) > k$，由引理 3 有 $\text{cost}(l, r+1) \ge \text{cost}(l, r) > k$，故 $l$ 对 $r+1$ 也不可行，即 $l_{\min}(r+1) \ge l_{\min}(r)$。∎

**定理**：滑动窗口算法返回的 $ans = \max_r \{ r - l + 1 : \text{cost}(l, r) \le k \}$ 等于最大频率分数。

**证明**：

- *双指针算出的确是最大可行窗口*：由推论，$l_{\min}$ 单调不减，双指针每轮 `while` 结束时恰有 $l = l_{\min}(r)$（归纳：$l$ 从 $l_{\min}(r-1) \le l_{\min}(r)$ 起只需右移，不会跳过也不会多余），故 $ans$ 覆盖了每个右端点的最长可行窗口。
- *$ans \ge$ 最优频率 $f^*$*：设最优方案频率 $f^*$、目标值 $v$、被改集合 $S$。由引理 1，存在长 $f^*$ 的连续段 $[l, r]$ 使 $\text{cost}(l, r) \le \text{cost}(S, v) \le k$，故该段可行，$ans \ge r - l + 1 = f^*$。
- *$ans \le$ 最优频率 $f^*$*：算法找到的窗口 $[l, r]$ 满足 $\text{cost}(l, r) \le k$，由引理 2 这正是「把段内元素变成 $t = a[m]$」的最少步数，执行后 $t$ 至少出现 $r - l + 1 = ans$ 次；若段外原有元素等于 $t$，频率更高。故频率分数 $\ge ans$，从而 $f^* \ge ans$。

三边合围，$ans = f^*$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$
  - 排序 $O(n \log n)$；
  - 前缀和 $O(n)$；
  - 滑动窗口中 $l$、$r$ 各至多移动 $n$ 次，每次代价计算 $O(1)$，窗口部分 $O(n)$。
  - 排序是瓶颈；若值域受限可换计数排序做到 $O(n + V)$，本题 $10^9$ 值域不适用。
- **空间复杂度**：$O(n)$
  - 前缀和数组 $O(n)$；排序递归栈 $O(\log n)$。滑窗本身只存端点，$O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxFrequencyScore(vector<int>& nums, long long k) {
        int n = nums.size();
        sort(nums.begin(), nums.end());

        vector<long long> pre(n + 1);
        for (int i = 0; i < n; ++i)
            pre[i + 1] = pre[i] + nums[i];

        auto cost = [&](int l, int r) -> long long {
            int m = (l + r) / 2;
            long long left = 1LL * nums[m] * (m - l + 1) - (pre[m + 1] - pre[l]);
            long long right = (pre[r + 1] - pre[m + 1]) - 1LL * nums[m] * (r - m);
            return left + right;
        };

        int ans = 0, l = 0;
        for (int r = 0; r < n; ++r) {
            while (cost(l, r) > k)
                ++l;
            ans = max(ans, r - l + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxFrequencyScore(self, nums: List[int], k: int) -> int:
        nums.sort()
        n = len(nums)
        pre = [0] * (n + 1)
        for i, x in enumerate(nums):
            pre[i + 1] = pre[i] + x

        def cost(l: int, r: int) -> int:
            m = (l + r) // 2
            left = nums[m] * (m - l + 1) - (pre[m + 1] - pre[l])
            right = (pre[r + 1] - pre[m + 1]) - nums[m] * (r - m)
            return left + right

        ans, l = 0, 0
        for r in range(n):
            while cost(l, r) > k:
                l += 1
            ans = max(ans, r - l + 1)
        return ans
```

## 8. 边界情况与易错点

1. **整数溢出（本题主坑）**：$n \cdot \max(a)$ 可达 $10^5 \times 10^9 = 10^{14}$，前缀和、代价、$k$ 全部超 `int`。C++ 用 `long long`，且 $k$ 的函数签名本身就是 `long long`——拿 `int` 接会当场溢出。
2. **别套 [LC 1838](https://leetcode.cn/problems/frequency-of-the-most-frequent-element/) 的公式**：1838 只能 $+1$，目标值固定为窗口**右端点**；本题双向移动，目标值是**中位数**。直接把 1838 的滑窗板子抄过来必 WA。
3. **偶数长窗口的中位数**：中间两元素 $a[m], a[m+1]$ 之间任何整点代价相同，代码统一取 $\lfloor (l+r)/2 \rfloor$；若写成「奇偶分类讨论」反而容易出 off-by-one。
4. **$k = 0$**：无需特判——排序后相同元素天然聚成连续段，段内代价为 $0$，滑窗自动退化为「数最长重复段」。
5. **收缩越界**：`while (cost(l, r) > k) ++l;` 在 $l = r$ 时必停（单元素代价 $0 \le k$ 恒真），不会把 $l$ 推过 $r$。
6. **段外元素等于中位数**：把它们算进窗口只会更长且代价不变，双指针取的是「最小可行 $l$」即最长窗口，不会低估；即便真的取到不含它们的段，实际频率也只会高于答案，方向安全。
7. **$k$ 巨大**：当 $k \ge n \cdot (\max - \min)$ 时答案直接是 $n$，滑窗自然得出，同样无需特判。

**延伸思考**：

- **二分答案写法**：二分频率 $f$，`check` 对每个右端点 $O(1)$ 算长度为 $f$ 的窗口代价取最小值，由引理 3 的单调性可直接二分。复杂度 $O(n \log n)$，是本题标签里 Binary Search 的出处——可作为滑窗写法的交叉验证。
- **若操作次数恰好用完**：多余步数可以对同一个元素来回 $\pm 1$ 消耗掉（只要 $n \ge 1$），答案不变；若强制每步作用于不同下标则需重新分析奇偶性。
- **若众数值被指定为某个给定 $x$**：退化成按 $|a_i - x|$ 排序贪心取前 $m$ 个，一次排序解决，不再需要中位数。
- **若要求改完后众数唯一**：本题证明里「段外元素等于 $t$」只会让频率更高，因此最优解总可以取到严格众数；唯一性约束反而是个有趣的小变形。
