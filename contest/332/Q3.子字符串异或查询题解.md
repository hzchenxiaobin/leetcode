# LeetCode 子字符串异或查询 题解

## 1. 题目概述

- **标题 / 题号**：子字符串异或查询（#2564，medium）
- **链接**：https://leetcode.cn/problems/substring-xor-queries/
- **来源**：LeetCode 第 332 场周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、哈希表、字符串

**题意**：给定二进制字符串 `s` 和查询数组 `queries`，其中 `queries[i] = [first_i, second_i]`。对第 $i$ 个查询，找 `s` 的**最短**子字符串，其十进制值 $val$ 满足 $val \oplus first_i = second_i$；返回该子字符串的端点 $[left_i, right_i]$（下标从 $0$ 开始），不存在则返回 $[-1, -1]$；长度并列时取 $left_i$ 最小者。

**约束**：

- $1 \le s.length \le 10^4$，$s[i]$ 为 `'0'` 或 `'1'`
- $1 \le queries.length \le 10^5$
- $0 \le first_i, second_i \le 10^9$

> 💡 题眼有两层：其一，异或是**自逆运算**，方程 $val \oplus first = second$ 两边同异或 $first$ 即得唯一解 $val = first \oplus second$——「带条件的搜索」瞬间坍缩为「定值查找」，天然适配哈希表；其二，$first, second \le 10^9 < 2^{30}$，目标值**至多 30 个二进制位**，答案子串长度有常数上界，于是「$O(30n)$ 预处理全部候选 + $O(1)$ 应答 $10^5$ 组查询」水到渠成。

## 2. 示例

**示例 1**

```text
输入：s = "101101", queries = [[0,5],[1,2]]
输出：[[0,2],[2,3]]

解释：查询 1：target = 0 ^ 5 = 5 = "101"，s[0..2] = "101"，验证 5 ^ 0 = 5；
     查询 2：target = 1 ^ 2 = 3 = "11"，s[2..3] = "11"，验证 3 ^ 1 = 2。
```

**示例 2（目标子串不存在）**

```text
输入：s = "0101", queries = [[12,8]]
输出：[[-1,-1]]

解释：target = 12 ^ 8 = 4 = "100"。s 中以 '1' 开头的子串只有
     "1"、"10"、"101"、"1"，不含 "100"，故返回 [-1,-1]。
```

**示例 3（单字符命中）**

```text
输入：s = "1", queries = [[4,5]]
输出：[[0,0]]

解释：target = 4 ^ 5 = 1 = "1"，s[0..0] = "1"，验证 1 ^ 4 = 5。
```

**示例 4（补充：first == second，目标值为 0）**

```text
输入：s = "101101", queries = [[7,7]]
输出：[[1,1]]

解释：target = 7 ^ 7 = 0，值为 0 的最短子串是单个字符 "0"。
     s 中最左的 '0' 在下标 1，答案 [1,1]；"01"、"0110" 等也能表示 0，但都更长。
```

## 3. 解题思路

### 3.1 暴力思路

对每组查询枚举 `s` 的全部 $O(n^2) \approx 10^8$ 个子字符串、逐个转成十进制判等，共 $O(q \cdot n^2) \approx 10^{13}$，完全不可行。退一步：把**所有**子串的值预处理进哈希表、再 $O(1)$ 应答查询——预处理本身要生成 $5 \times 10^7$ 个子串（转换还要各花 $O(L)$，最大值达 $2^{10^4}$），时间与内存同样吃不消。两版暴力共同的问题是**没有利用目标值的位数**：绝大多数子串远比任何可能的目标长，先把「答案长度 $\le 30$」这条界挖出来，搜索空间立刻从平方级塌缩到常数倍线性。

### 3.2 核心观察：异或方程唯一解 + 30 位长度上界

![核心观察：异或自逆给出唯一目标值，目标至多 30 位给出候选长度上界](images/substring_xor_concept.svg)

**观察 ①（异或方程唯一解）**：由 $x \oplus x = 0$、$x \oplus 0 = x$ 及交换结合律，在 $val \oplus first = second$ 两边同时异或 $first$ 得

$$val = first \oplus second$$

且反之亦成立。于是每组查询的本质是：**在 `s` 中找值恰好等于 $target = first \oplus second$ 的最短、最靠左子字符串**。

**观察 ②（目标至多 30 位）**：$0 \le first, second \le 10^9 < 2^{30}$，故 $target = first \oplus second < 2^{30}$，二进制位数 $\mathrm{bitlen}(target) \le 30$。

**观察 ③（值决定最短长度）**：以 `'1'` 开头、长度为 $L$ 的子串值落在 $[2^{L-1},\ 2^L - 1]$，这些区间对不同的 $L$ 两两不交。因此**正值 $v$ 的无前导零表示长度唯一**：$L = \mathrm{bitlen}(v)$；带前导零的表示必然更长。三条推论：

1. 长度 $> 30$ 且无前导零的子串值 $\ge 2^{30} > target$，永不可能是答案；
2. 带前导零的等值子串去掉前导零后**值不变、更短**，也轮不到它当答案；
3. $target = 0$（即 $first = second$）时，最短子串是**单个字符 `'0'`**。

三点合一：**只需枚举「以 `'1'` 开头、长度 $1 \sim 30$」的全部子串（至多 $30n$ 个）加上最左的 `'0'`，就覆盖了所有可能的答案**。

### 3.3 算法流程：预处理哈希表 + O(1) 查询

![算法流程：预处理 30n 个候选入哈希，查询一次异或加一次哈希应答](images/substring_xor_flow.svg)

**预处理**（从左到右扫描）：

1. 对每个满足 $s[i]$ 为 `'1'` 的起点 $i$：置 $val = 0$，向右延伸 $L = 1, 2, \dots, \min(30,\ n - i)$，每步增量更新 $val \leftarrow (val \ll 1) \mid s[i + L - 1]$；
2. 值 $val$ **首次**出现时登记 $\text{pos}[val] = (i,\ i + L - 1)$，已存在则跳过；
3. 扫描结束后，若 `s` 含 `'0'`，登记 $\text{pos}[0] = (j, j)$，$j$ 为最左 `'0'` 的下标。

**应答**：每组查询算 $target = first \oplus second$，查 `pos`：命中输出端点，未命中输出 $[-1, -1]$。

> 💡 同一值的所有无前导零候选**长度全等**（都是 $\mathrm{bitlen}(val)$），所以「最短」自动满足；起点从左到右扫描，「首见」即「最左」——两条并列规则一次「不存在才登记」全部拿下。$10^5$ 组查询里大量重复的 $target$ 也被哈希自动去重。

### 3.4 示例演算

![示例演算：s=101101 的 pos 构建与两组查询命中](images/substring_xor_walkthrough.svg)

以 `s = "101101"`、`queries = [[0,5],[1,2]]` 为例，预处理按插入顺序得到（节选）：

| 起点 | 逐长度延伸：值 → 端点（首见登记，重复跳过） |
|------|----------------------------------------------|
| $i = 0$ | $1 \to [0,0]$，$2 \to [0,1]$，$\mathbf{5 \to [0,2]}$，$11 \to [0,3]$，$22 \to [0,4]$，$45 \to [0,5]$ |
| $i = 2$ | $1$ 已存在跳过，$\mathbf{3 \to [2,3]}$，$6 \to [2,4]$，$13 \to [2,5]$ |
| $i = 3$ | $1$、$2$、$5$ 均已存在，全部跳过 |
| $i = 5$ | $1$ 已存在跳过 |
| 最左 `'0'`（$j = 1$） | $0 \to [1,1]$ |

**查询 ①** $[0, 5]$：$target = 0 \oplus 5 = 5$，查得 $\text{pos}[5] = [0, 2]$，即子串 `"101"`，验证 $5 \oplus 0 = 5$ ✓。

**查询 ②** $[1, 2]$：$target = 1 \oplus 2 = 3$，查得 $\text{pos}[3] = [2, 3]$，即子串 `"11"`，验证 $3 \oplus 1 = 2$ ✓。

## 4. 算法细节

1. **长度上界 30 的来历**：$10^9 < 2^{30} = 1073741824$，故 $target < 2^{30}$、$\mathrm{bitlen}(target) \le 30$；内层循环上界取 $\min(30, n - i)$。想更保险取 31、32 也无妨，复杂度不变。
2. **增量求值**：固定起点后每延伸一位执行 $val = (val \ll 1) \mid bit$，单步 $O(1)$；不要每个子串都重新 `int(s[i:i+L], 2)`（转换是 $O(L)$，白白放大常数）。
3. **首见即最优**：外层起点升序扫描 +「不存在才登记」，同值首见记录天然同时满足「最短 + 最左」，无需比较更新。反过来，若把带前导零的串也入库（如 `"01"` 也算 $1$），更长的等值串可能抢先占位，输出长度就错了——**只收 `'1'` 开头的候选**。
4. **值 0 特殊处理**：$first = second$ 时 $target = 0$，答案是**最左的单个 `'0'`**；全 `'1'` 串则无解。`'1'` 开头的候选值都 $\ge 1$，与 $\text{pos}[0]$ 天然无键冲突。
5. **数据结构**：值域名义上 $[0, 2^{30})$ 太大不能开数组，但实际键数 $\le 30n + 1 \approx 3 \times 10^5$，用哈希表（C++ `unordered_map` / Python `dict`）即可；查询侧每组只做一次异或加一次查找。
6. **端点与无解**：登记 $(left, right) = (i, i + L - 1)$；哈希未命中统一返回 $[-1, -1]$，不需要任何存在性预判。

## 5. 正确性证明

**引理 1（异或方程唯一解）**：$val \oplus first = second \iff val = first \oplus second$。

**证明**：（⇒）两边同异或 $first$：$val \oplus first \oplus first = second \oplus first$，左边 $= val \oplus (first \oplus first) = val \oplus 0 = val$。（⇐）把 $val = first \oplus second$ 代回：$first \oplus second \oplus first = second \oplus (first \oplus first) = second$。∎

**引理 2（值定长度）**：以 `'1'` 开头、长度为 $L$ 的子串值落在 $I_L = [2^{L-1},\ 2^L - 1]$；区间 $I_1, I_2, \dots$ 两两不交且并集为全部正整数。因此任一正值 $v$ 恰属于唯一的 $I_{L^\ast}$，其无前导零表示长度唯一为 $L^\ast = \mathrm{bitlen}(v)$；任何带 $z \ge 1$ 个前导零的等值表示长度为 $L^\ast + z$，严格更长。

**证明**：以 `'1'` 开头、长度 $L$ 的串形如 $1b_{L-1} \cdots b_1$，值为 $2^{L-1} + \sum_{k=1}^{L-1} b_k 2^{k-1} \in [2^{L-1},\ 2^{L-1} + (2^{L-1} - 1)] = I_L$。对 $L < L'$ 有 $2^L - 1 < 2^{L'-1}$，即 $I_L$ 整体位于 $I_{L'}$ 左侧，两两不交；每个正整数 $v$ 取 $L^\ast = \lfloor \log_2 v \rfloor + 1$ 则 $2^{L^\ast - 1} \le v \le 2^{L^\ast} - 1$，故并集覆盖全部正整数。前导零不改变数值：串 $0^z t$ 与 $t$ 的值相同，长度多 $z$。∎

**引理 3（最优候选被枚举覆盖）**：若 `s` 中存在值为 $target$ 的子字符串，则其中「最短、最左」的最优者 $T^\ast$ 满足：$target > 0$ 时以 `'1'` 开头且长度 $\mathrm{bitlen}(target) \le 30$；$target = 0$ 时是 `s` 的第一个 `'0'`。二者均在算法的枚举集合内。

**证明**：$target = 0$ 时所有等值子串都是全零串，长度 $\ge 1$，最左的单字符 `'0'` 即最优。$target > 0$ 时，若 $T^\ast$ 带前导零，去掉全部前导零得其后缀 $T'$：仍是 `s` 的连续子串、值仍为 $target$（引理 2）、以 `'1'` 开头且严格更短，与 $T^\ast$ 最短矛盾。故 $T^\ast$ 无前导零，由引理 2 其长度 $= \mathrm{bitlen}(target) \le 30$（观察 ②）。而「起点遍历所有 `'1'` 位置、长度遍历 $1 \sim \min(30, n - i)$」的双重循环必然枚举到每个这样的子串；单字符 `'0'` 由预处理第 3 步登记。∎

**定理**：算法对每组查询输出正确的 $[left, right]$ 或 $[-1, -1]$。

**证明**：由引理 1，查询等价于求值为 $target$ 的最优（最短、最左）子串。先看 $\text{pos}[v]$ 存的是什么：固定 $v > 0$，其全部枚举候选长度都等于 $\mathrm{bitlen}(v)$（引理 2），且该长度正是所有值为 $v$ 的子串的长度下界（带前导零者更长），故「最短」自动满足；外层起点升序扫描使首次登记的起点最小，故 $\text{pos}[v]$ 恰为最优端点；$v = 0$ 时登记的正是最左 `'0'`，同理最优。有解时，由引理 3 最优解在枚举集合内，查询必命中且输出即最优；无解时，若 `s` 中存在值为 $target$ 的子串，则其去前导零版本（$target = 0$ 时为单 `'0'`）必被枚举（引理 3 的证明给出了该构造），$\text{pos}$ 就会含有 $target$——逆否即得：未命中 ⟺ 无解，输出 $[-1, -1]$ 正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(30n + q)$。预处理双重循环至多 $30n \approx 3 \times 10^5$ 次增量更新与哈希插入；每组查询一次异或加一次哈希查找，共 $O(q) \approx 10^5$。对照：暴力 $O(qn^2)$、全子串预处理 $O(n^2)$ 均不可行。
- **空间复杂度**：$O(30n)$。哈希表键数 $\le 30n + 1 \approx 3 \times 10^5$（值域虽宽至 $2^{30}$，实际键数受枚举量限制）；输出数组 $O(q)$ 为必要开销。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> substringXorQueries(string s, vector<vector<int>>& queries) {
        int n = (int)s.size();
        unordered_map<int, pair<int, int>> pos;
        for (int i = 0; i < n; ++i) {
            if (s[i] != '1') continue;
            int val = 0;
            for (int L = 1; L <= 30 && i + L <= n; ++L) {   // 上界 30：target < 2^30
                val = (val << 1) | (s[i + L - 1] - '0');     // 增量求值
                if (!pos.count(val)) pos[val] = {i, i + L - 1};  // 首见 = 最短 + 最左
            }
        }
        for (int i = 0; i < n; ++i) {                       // 值 0：最左的 '0'
            if (s[i] == '0') { pos[0] = {i, i}; break; }
        }
        vector<vector<int>> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            int target = q[0] ^ q[1];
            auto it = pos.find(target);
            if (it != pos.end()) ans.push_back({it->second.first, it->second.second});
            else ans.push_back({-1, -1});
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def substringXorQueries(self, s: str, queries: List[List[int]]) -> List[List[int]]:
        n = len(s)
        pos = {}
        for i, ch in enumerate(s):
            if ch != '1':
                continue
            val = 0
            for L in range(1, min(30, n - i) + 1):   # 上界 30：target < 2^30
                val = (val << 1) | (s[i + L - 1] == '1')
                if val not in pos:                    # 首见 = 最短 + 最左
                    pos[val] = [i, i + L - 1]
        j = s.find('0')                               # 值 0：最左的 '0'
        if j != -1:
            pos[0] = [j, j]
        return [pos.get(f ^ sec, [-1, -1]) for f, sec in queries]
```

## 8. 边界情况与易错点

1. **忘登记值 0（头号坑）**：$first = second$ 时 $target = 0$，答案是**最左的单字符 `'0'`**（示例 4）；全 `'1'` 串（如 `s = "1"` 配查询 `[4,4]`）必须返回 $[-1,-1]$。忘写这条会直接 WA。
2. **把带前导零的子串入库**：若从 `'0'` 起步也按值登记（如 `"01"` 抢占 $\text{pos}[1]$），更长的等值串会占位，输出长度非最短。正确做法是 `'0'` 只以单字符形式进表，其余候选一律以 `'1'` 开头。
3. **长度上界写错**：$10^9 < 2^{30}$，上界是 **30 不是 29**（$2^{29} \approx 5.4 \times 10^8 < 10^9$，30 位的目标真实存在，例如 `first = 10^9, second = 0`）；取 31~32 是无害冗余，取 29 会 WA。
4. **内层越界**：上界必须是 $\min(30, n - i)$；直接写 $L \le 30$ 而不判 $i + L \le n$ 会数组越界 RE。
5. **int 溢出（C++）**：$val \le 2^{30} - 1$、$target < 2^{30}$，`int` 足够；但若把上界放大到 $\ge 31$ 位仍用 `int` 做移位累加就会越界，需要改 `long long` 或收回上界。
6. **答案的并列规则**：先比长度、再比左端点；「首见登记」恰好同时实现两条。同值候选长度全等是它成立的前提——理解这一点，才不会在改动枚举集合（比如混入前导零候选）后踩坑。
7. **重复查询**：$10^5$ 组查询可能有海量重复 $target$，无需去重或离线化，哈希查找天然幂等，$O(1)$ 已无优化空间。
8. **端点格式**：无解输出 $[-1,-1]$ 两端都是 $-1$；命中输出的是闭区间端点 $(i, i + L - 1)$，别把右端点写成开区间的 $i + L$。
