# LeetCode 我的日程安排表 II 题解

## 1. 题目概述

- **标题 / 题号**：我的日程安排表 II（#731，medium）
- **链接**：https://leetcode.cn/problems/my-calendar-ii/
- **来源**：LeetCode 第 59 场周赛 Q4
- **难度**：中等
- **标签**：设计、线段树、数组、二分查找、有序集合、前缀和

**题意**：实现日历类 `MyCalendarTwo`，维护一个预订集合。每次 `book(startTime, endTime)` 申请加入半开区间 $[startTime, endTime)$；如果加入后**存在某个时刻被 3 个及以上的预订同时覆盖**（三重预订），则拒绝该请求、返回 `false`，并且**不修改任何已存状态**；否则接受并返回 `true`。注意双重预订是允许的。

**约束**：

- $0 \le start < end \le 10^9$
- 最多调用 `book` $1000$ 次

> 💡 坐标范围到 $10^9$ 但调用次数只有 $1000$，所以「按坐标开数组做差分」不可行，而「按区间做线性扫描」完全可行——**复杂度要由调用次数 $m$ 决定，而不是由坐标值决定**。

## 2. 示例

**示例 1**（官方）

```text
输入：
["MyCalendarTwo","book","book","book","book","book","book"]
[[],[10,20],[50,60],[10,40],[5,15],[5,10],[25,55]]
输出：[null,true,true,true,false,true,true]
解释：
book(10,20) → true   日历：{[10,20)}
book(50,60) → true   日历：{[10,20), [50,60)}
book(10,40) → true   双重区间出现：[10,20) 被覆盖 2 次
book(5,15)  → false  它与双重区间 [10,20) 交于 [10,15)，那里将出现三重
book(5,10)  → true   只在端点 10 与 [10,20) 相接，半开区间无公共时刻
book(25,55) → true   新增双重区间 [25,40) 与 [50,55)
```

**示例 2**（补充：端点相接不算重叠）

```text
输入：
["MyCalendarTwo","book","book","book","book"]
[[],[10,20],[10,20],[20,30],[5,10]]
输出：[null,true,true,true,true]
解释：第二次 book(10,20) 与第一次完全重合，形成双重预订，允许；
      之后 book(20,30) 只在端点 20 与 [10,20) 相接，book(5,10) 只在端点 10 相接，层数不增加。
```

**示例 3**（补充：被拒绝的请求不改变状态）

```text
输入：
["MyCalendarTwo","book","book","book","book"]
[[],[10,20],[10,20],[10,20],[10,20]]
输出：[null,true,true,false,false]
解释：前两次构成双重区间 [10,20)；第 3 次再订同一区间会形成三重 → false；
      第 4 次依旧 false，证明失败的请求没有污染任何结构。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：每次 `book` 先把候选区间塞进去，再对所有端点排序、跑一遍前缀和，看最大层数是否超过 2，超了就回滚。单次 $O(m \log m)$，总 $O(m^2 \log m)$，在 $m \le 1000$ 时约 $10^7$ 量级，其实**能过**，但每次都要重排全部端点，常数大、代码也长。

更朴素的版本是「枚举所有三元组判断是否有公共时刻」，$O(m^3)$，$m = 1000$ 时 $10^9$，必然超时。

两个版本都说明：真正的瓶颈是**判定三重需要多大力气**。如果能只看「已经覆盖 2 次的时刻」，判定就能降到线性。

### 3.2 核心观察：只盯住「双重区间」

![只维护一重与双重两组区间](images/wc59_q4_double_cover_model.svg)

维护两个集合：

- `singles`：所有**已被接受**的预订区间（保持原样，不拆分）；
- `doubles`：所有**被覆盖至少 2 次**的时刻，用若干互不重叠的区间表示。

**关键观察**：加入候选区间 $I$ 后出现三重，等价于存在时刻 $x \in I$ 使 $x$ 在加入前已被 $\ge 2$ 个区间覆盖，也就是

$$I \text{ 与 } \texttt{doubles} \text{ 中某一段相交}$$

于是判定退化为「$I$ 与一组互不重叠的区间做相交检测」，一次线性扫描即可；而且 `doubles` 里段与段不重叠，是下面这个不变式保证的：

> 新请求只有在**不碰** `doubles` 时才会被接受，因此它新增的交点段既不与旧段相交，彼此之间也不相交。

### 3.3 算法流程

![book 的线性流程](images/wc59_q4_book_flow.svg)

`book(s, e)` 依次执行：

1. 遍历 `doubles` 中每一段 $[a, b)$，若 $\max(s, a) < \min(e, b)$，说明候选与它相交 → 立即返回 `false`（**此时什么也不写**）；
2. 全部通过后，遍历 `singles` 中每一段 $[a, b)$，令 $l = \max(s, a)$、$r = \min(e, b)$，若 $l < r$ 则把 $[l, r)$ 追加进 `doubles`（这段从 1 次覆盖升为 2 次）；
3. 把 $[s, e)$ 追加进 `singles`，返回 `true`。

$\max(s,a) < \min(e,b)$ 正是半开区间 $[s,e)$ 与 $[a,b)$ 有公共时刻的充要条件；等号成立意味着只在端点相接，不算重叠（示例 1 的 `book(5,10)` 就靠这一条通过）。

### 3.4 示例演算

![官方示例的六步走查](images/wc59_q4_walkthrough.svg)

| 步骤 | 请求 $I$ | 与 `doubles` 相交 | 新增 `doubles` | 返回 |
|------|-----------|--------------------|-----------------|------|
| 1 | $[10,20)$ | 无（空集） | — | true |
| 2 | $[50,60)$ | 无 | — | true |
| 3 | $[10,40)$ | 无 | $[10,20)$ | true |
| 4 | $[5,15)$ | 交于 $[10,15)$ → 三重 | 不变更 | false |
| 5 | $[5,10)$ | 无（端点 10 相接） | — | true |
| 6 | $[25,55)$ | 无 | $[25,40)$、$[50,55)$ | true |

第 6 步值得细看：新候选与两段单重区间分别交出 $[25,40)$（与 $[10,40)$）和 $[50,55)$（与 $[50,60)$），正好对应题面解释里的两段双重区间；它们互不重叠，于是 `doubles` 追加后依然保持互不重叠。

## 4. 算法细节

1. **相交判定必须用半开区间**：条件写 $\max(s,a) < \min(e,b)$，不能用 $\le$。写成 $\le$ 会把「端点相接」误判为重叠，示例 1 的 `book(5,10)`、示例 2 的 `book(20,30)` 都会错。
2. **先检查、后写入**：必须把 `doubles` 全扫完再动手写。若边扫边追加，正在追加的新段会被同一轮扫描读到，既能自锁，也会把状态写脏。
3. **失败即原子操作**：返回 `false` 的分支里不要做任何 `push_back`，也就不用回滚。这是比「先加再撤销」更安全的写法。
4. **`singles` 不拆分**：求交时需要用完整区间去和候选相交，所以 `singles` 里始终保存原始 $[s,e)$；交点只写进 `doubles`。若把 `singles` 也拆成「单重段」，就必须每次重算，反而复杂。
5. **不需要排序与合并**：`doubles` 天然互不重叠（见 §5 引理 1），追加新段后仍然互不重叠，因此既不用维护有序结构，也不用合并相邻段。这一点是 $O(m)$ 单次复杂度的来源。
6. **`doubles` 规模**：所有段的端点都取自 $2m$ 个原始端点，而段与段互不重叠，故 $|\texttt{doubles}| \le 2m-1 = O(m)$；`singles` 显然 $O(m)$。
7. **与 729 / 732 的关系**：本题是「最多 2 重」的特例；把 `doubles` 换成「覆盖 $k$ 次的段」或者改用差分 + 有序表 / 线段树，就能求解 My Calendar III 的任意 $k$ 重。

## 5. 正确性证明

**引理 1（不变式）**：每次 `book` 返回之后，`singles` 恰好是全部被接受的区间；`doubles` 是集合 $\{x \mid \text{覆盖 } x \text{ 的已接受区间数} \ge 2\}$ 的一个区间分解，且其中各段两两不重叠。

**证明**：对调用次数归纳。初始 `singles` 与 `doubles` 皆空，命题成立。

设调用前命题成立，候选为 $I = [s, e)$，旧的双重集合为 $D$，旧的单重集合为 $S$。

情形一：返回 `false`。此时流程未修改任何结构，命题保持不变。

情形二：返回 `true`。此时 $\mathrm{cov}'(x) = \mathrm{cov}(x) + [x \in I]$，被覆盖至少 2 次的时刻集合为

$$\{x \mid \mathrm{cov}'(x) \ge 2\} = D \cup \bigl(I \cap \{x \mid \mathrm{cov}(x) \ge 1\}\bigr) = D \cup \bigcup_{J \in S} (I \cap J)$$

算法把每个非空的 $I \cap J$ 追加进 `doubles`，正好补齐第二项，故并集相等。

再看不重叠性：由归纳假设 $D$ 内各段互不重叠，且 $I \cap D = \varnothing$（否则第 1 步就会返回 `false`），故新段与旧段不相交；若新段 $I \cap J_1$ 与 $I \cap J_2$ 有公共时刻 $x$，则 $x \in I$ 且同时被 $J_1, J_2$ 覆盖，即 $\mathrm{cov}(x) \ge 2$，于是 $x \in D$，与 $I \cap D = \varnothing$ 矛盾。因此新段彼此也不相交。∎

**引理 2（判定等价）**：`book(I)` 返回 `false` $\iff$ 把 $I$ 加入日历会产生三重预订。

**证明**：

- ($\Rightarrow$) 返回 `false` 意味着存在 $x \in I \cap D$。由引理 1，$\mathrm{cov}(x) \ge 2$，加入后 $\mathrm{cov}'(x) \ge 3$，确有三重。
- ($\Leftarrow$) 若加入后存在 $x$ 使 $\mathrm{cov}'(x) \ge 3$，则 $x \in I$（否则 $\mathrm{cov}(x) = \mathrm{cov}'(x) \ge 3$，与归纳假设下日历从无三重矛盾），且 $\mathrm{cov}(x) \ge 2$，故 $x \in D$，扫描必然命中并返回 `false`。∎

**定理**：算法对每次 `book` 的返回值都与题意一致，且任意时刻日历中不存在三重预订。

**证明**：由引理 2，返回值与「是否产生三重」严格等价；被接受时由引理 1 覆盖数 $\le 2$，被拒绝时状态不变，故任意时刻都不存在三重。两个方向合起来即得正确性。∎

## 6. 复杂度分析

- **时间**：单次 `book` 为 $O(|\texttt{singles}| + |\texttt{doubles}|) = O(m)$，其中 $m$ 为已接受的预订数；由引理 1，`doubles` 各段不重叠且端点均取自 $2m$ 个原始端点，故 $|\texttt{doubles}| \le 2m - 1$。总计 $O(m^2)$，$m \le 1000$ 时约 $10^6$ 次比较，远低于时限。
- **空间**：$O(m)$。`singles` 存 $m$ 个区间；`doubles` 至多 $2m-1$ 段，共 $O(m)$ 个端点。

> 💡 对比：差分 + 有序表每次 $O(m \log m)$、线段树（坐标压缩）每次 $O(\log m)$，本题的 $O(m)$ 已经足够，且常数最小、最不容易写错。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <utility>
#include <vector>
using namespace std;

class MyCalendarTwo {
public:
    MyCalendarTwo() {}

    bool book(int startTime, int endTime) {
        // 1. 只要和某个双重区间有公共时刻，加入就会造成三重
        for (auto &d : doubles) {
            if (max(startTime, d.first) < min(endTime, d.second)) return false;
        }
        // 2. 全部检查通过后，才与每个一重区间求交，交点升为双重
        for (auto &s : singles) {
            int l = max(startTime, s.first), r = min(endTime, s.second);
            if (l < r) doubles.push_back({l, r});
        }
        singles.push_back({startTime, endTime});
        return true;
    }

private:
    vector<pair<int, int>> singles;  // 所有被接受的区间
    vector<pair<int, int>> doubles;  // 被覆盖 >= 2 次的区间，互不重叠
};

/**
 * Your MyCalendarTwo object will be instantiated and called as such:
 * MyCalendarTwo* obj = new MyCalendarTwo();
 * bool param_1 = obj->book(startTime, endTime);
 */
```

### Python

```python
class MyCalendarTwo:

    def __init__(self):
        self.singles = []   # 所有被接受的区间
        self.doubles = []   # 被覆盖 >= 2 次的区间，互不重叠

    def book(self, startTime: int, endTime: int) -> bool:
        # 1. 只要和某个双重区间有公共时刻，加入就会造成三重
        for a, b in self.doubles:
            if max(startTime, a) < min(endTime, b):
                return False
        # 2. 全部检查通过后，才与每个一重区间求交，交点升为双重
        for a, b in self.singles:
            l, r = max(startTime, a), min(endTime, b)
            if l < r:
                self.doubles.append((l, r))
        self.singles.append((startTime, endTime))
        return True
```

## 8. 边界情况与易错点

1. **端点相接**：相交条件必须是 $\max < \min$ 而非 $\le$。`book(5,10)` 与 `[10,20)` 只在 10 处相接，半开区间下无公共时刻，应返回 `true`。
2. **先检查后写入**：把「求交并追加」写在 `doubles` 扫描循环内部，会导致新段被本轮扫描看到，甚至自己和自己相交，结果错乱。
3. **拒绝时必须零副作用**：题面要求「不要将该日程安排添加到日历中」。若先 `push_back` 再判断失败才回滚，一旦回滚写错（例如漏删新加的交点），后续判定会连环出错。
4. **完全重合的请求**：第二次预订同一区间应返回 `true`（构成双重），第三次才 `false`。判断交点非空要用 $l < r$ 而不是 $l \le r$，否则被压成一点的退化区间会被误加进 `doubles`。
5. **坐标边界**：$start = 0$、$end = 10^9$ 都在 `int` 范围内，但求和/求长度时（例如 $end - start$）在 C++ 中仍建议用 `long long` 习惯写法防溢出；本题只需要 `max`/`min`，不涉及加减。
6. **空日历首调用**：`singles` 与 `doubles` 均为空，两个循环都不执行，直接返回 `true`。
7. **`doubles` 的数量不会爆炸**：不必担心「每次追加 $O(m)$ 段导致 $O(m^2)$ 段积压」——由引理 1，段互不重叠，总量始终 $O(m)$。
