# LeetCode 我的日程安排表 I 题解

## 1. 题目概述

- **标题 / 题号**：我的日程安排表 I（#729，medium）
- **链接**：https://leetcode.cn/problems/my-calendar-i/
- **来源**：LeetCode 第 59 场周赛 Q2
- **难度**：中等
- **标签**：设计, 线段树, 数组, 二分查找, 有序集合

**题意**：实现 `MyCalendar` 类，维护一个初始为空的日历。`book(startTime, endTime)` 尝试把半开区间 $[startTime, endTime)$ 加入日历：若它与日历中**已有任何**预约存在非空交集，则返回 `false` 且**不加入**；否则加入并返回 `true`。

形式化地，设已接受区间集合为 $S$，接受新区间 $[s,e)$ 的条件是：对任意 $[s',e')\in S$，
$$\max(s,s') \;\ge\; \min(e,e')$$
即两个区间「没有公共内点」。反之，二者冲突等价于 $s' < e$ 且 $s < e'$。

**约束**：

- $0 \le start < end \le 10^9$
- 每个测试用例中 `book` 的调用次数不超过 $1000$

> 💡 **关键语义**：区间是**半开**的，$[10,20)$ 与 $[20,30)$ 在端点 20 处只是「相接」，**不算**重复预订。这是本题最容易写错的一处。

## 2. 示例

**示例 1（官方）**

```text
输入：
["MyCalendar", "book", "book", "book"]
[[], [10, 20], [15, 25], [20, 30]]
输出：
[null, true, false, true]
解释：
book(10, 20) -> true，日历空，直接加入；
book(15, 25) -> false，15 已落在 [10, 20) 内，冲突且不加入；
book(20, 30) -> true，[10, 20) 的每个时刻都 < 20，且不含 20，端点相接不算冲突。
```

**补充示例 2（自拟：完全被包含）**

```text
调用：book(10, 100), book(20, 30), book(100, 150)
输出：true, false, true
解释：[20, 30) 整个落在 [10, 100) 内部，冲突；
      [100, 150) 的起点 100 与 [10, 100) 端点相接，可以加入。
```

**补充示例 3（自拟：向左侧插入与完全重复）**

```text
调用：book(50, 60), book(10, 50), book(55, 70), book(50, 60)
输出：true, true, false, false
解释：[10, 50) 与 [50, 60) 端点相接，合法；
      [55, 70) 与 [50, 60) 真重叠；重复预订同一个 [50, 60) 必然失败。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是用数组存下所有**已接受**的区间，每次 `book` 扫一遍全部区间判定是否重叠：

$$\text{conflict} \iff \max(s,s') < \min(e,e')$$

单次 `book` 是 $O(n)$，$n$ 次调用总计 $O(n^2)$。在 $n \le 1000$ 的本题数据下只有 $10^6$ 次比较，**其实完全能过**，这也是赛场上最稳的写法。

但它没有利用任何结构信息：一旦调用次数上到 $10^4 \sim 10^5$（例如同系列的日历类题目把上限放宽），或者需要支持「最多 k 重预订」的扩展题，$O(n^2)$ 就会退化到 $10^8 \sim 10^{10}$。题面标签给出的有序集合 / 二分查找 / 线段树，正是在提示我们挖掘**已接受区间集合的结构**。

### 3.2 核心观察：互不相交 ⇒ 候选只剩两个邻居

![核心观察：已接受区间两两不相交，只需检查分界点两侧](images/wc59_q2_interval_neighbors.svg)

每次成功 `book` 都保证新加入的区间与已有区间**全都不相交**，因此整个集合始终满足：

> **不变式**：集合中的区间**两两不相交**。

于是把它们按起点升序排列，终点也必然随之升序（起点更小的区间若终点更大，两者就会相交）。这条「双升序」性质是全部优化的来源。

对新区间 $[s,e)$ 与某个已存区间 $[s',e')$，冲突条件是 $s' < e$ 且 $s < e'$。令 $i$ 为**第一个满足 $\text{start}_i \ge s$ 的下标**（即 `lower_bound(s)`）：

$$i = \min\{\,k \mid \text{start}_k \ge s\,\}$$

它把集合切成「起点 $< s$ 的前驱部分」和「起点 $\ge s$ 的后继部分」：

- **后继**：若 $i$ 存在且 $\text{start}_i < e$，说明 $[\text{start}_i, \text{end}_i)$ 的起点落在新区间内部 → 冲突。若 $\text{start}_i \ge e$，则所有更右区间的起点更大，都不可能冲突。
- **前驱**：令 $j = i-1$（起点 $< s$ 中起点最大的那个）。若 $j$ 存在且 $\text{end}_j > s$，说明新区间起点 $s$ 被它覆盖 → 冲突。若 $\text{end}_j \le s$，则由终点升序知所有更左区间的终点都 $\le \text{end}_j \le s$，也不可能冲突。

所以**二分定位分界点后，两侧各查一个区间**就够了，单次判定 $O(\log n)$。

### 3.3 算法流程

![book 判定流程：lower_bound 定位，前驱/自身各查一次](images/wc59_q2_book_flow.svg)

1. 用 `events.lower_bound(s)`（Python 用 `bisect_left(starts, s)`）找到第一个起点 $\ge s$ 的位置 `it`。
2. 若 `it` 有效且 `it->first < e`：与后继区间重叠，**返回 `false`**（不插入）。
3. 若 `it` 不是 `begin()` 且 `prev(it)->second > s`：与前驱区间重叠，**返回 `false`**。
4. 两侧都通过 ⇒ 集合中没有任何区间与 $[s,e)$ 相交：插入 `{s, e}`，返回 `true`。

C++ 用 `map<int,int>` 直接承担「有序 + 查找前驱后继」；Python 没有内置平衡树，用 `bisect` 维护 `starts` 与 `ends` 两个**平行有序数组**，插入位置同一下标。

### 3.4 示例演算

![示例演算：四次 book 调用中集合的演化](images/wc59_q2_walkthrough.svg)

以官方示例为例，集合按起点升序维护：

| 调用 | `lower_bound` 定位 | 前驱检查 | 后继检查 | 结果 |
|------|--------------------|----------|----------|------|
| `book(10,20)` | 空集合，`i = 0` | 无 | 无 | 插入 `[10,20)`，`true` |
| `book(15,25)` | `i = 1`（末尾） | $\text{end}=20 > 15$ 冲突 | 无 | `false` |
| `book(20,30)` | `i = 1`（末尾） | $\text{end}=20 \le 20$ 通过 | 无 | 插入，`true` |
| `book(20,30)` | `i = 1` 命中 `[20,30)` | — | $\text{start}=20 < 30$ 冲突 | `false` |

第 2 次调用是「被左侧区间覆盖」的典型：新区间起点 15 落在 $[10,20)$ 内部，只需拿前驱终点与 $s$ 比一次即可发现；第 4 次则是 `lower_bound` 直接命中同一个键，后继检查立刻拦下。

## 4. 算法细节

1. **半开区间用严格不等号**：后继判 $start < e$、前驱判 $end > s$。若误写成 $start \le e$ 或 $end \ge s$，像 `[10,20)` 与 `[20,30)` 这种合法的端点相接就会被误判为冲突。
2. **`lower_bound` 的语义要清楚**：它返回第一个 $key \ge s$ 的位置，而不是「小于 $s$ 的最后一个」。这个问题用 `upper_bound` 也能写出等价判定，但必须把「相等键」的归属想清楚，否则重复预订会漏判。
3. **前驱必须判空**：`prev(begin())` 是未定义行为，C++ 里必须先 `it != events.begin()`；Python 对应 `i > 0`。
4. **冲突后绝不能写入**：被拒绝的区间一旦插入，就会破坏「两两不相交」不变式，之后所有判定都不可信。代码里所有 `return false` 都必须发生在插入之前。
5. **C++ 选 `map<int,int>` 而不是 `set<pair<int,int>>`**：`map` 的 `lower_bound` 直接给出迭代器，`prev(it)` 取前驱、`it->second` 取终点都很自然；`set` 虽然也能工作，但读取区间端点要解构 `pair`，可读性差。
6. **Python 的平行数组必须同步**：`starts.insert(i, s)` 与 `ends.insert(i, e)` 要用**同一个** `i`，否则起点与终点错位，后续前驱终点会张冠李戴。也不要再调一次 `insort` 重新定位（重复二分还可能插到不同下标）。
7. **值域 $10^9$ 无关紧要**：只存端点，不做离散化、不建树。线段树/动态开点是同系列 II、III 的解法，I 题不需要。
8. **起点不会重复**：两个区间若起点相同必然重叠（因 $e > s$），所以已接受集合里起点互不相同，`map` 的键唯一性天然成立；若 $s$ 已作为键存在，`lower_bound` 命中它且 $start = s < e$ 成立，会立刻被后继检查判为冲突。

## 5. 正确性证明

先约定：把集合 $S$ 的区间按起点升序排列后记作 $(\text{start}_k, \text{end}_k)$，$i$ 为第一个满足 $\text{start}_i \ge s$ 的下标。

**引理 1（邻居充分性）**：设执行本算法得到的集合 $S$ 中区间两两不相交（因而起点互不相同，且按起点升序时终点也升序）。若 $[s,e)$ 与某个 $[s',e')\in S$ 冲突（即 $s' < e$ 且 $s < e'$），则该区间必是下标 $i$ 对应的区间，或它的前驱（下标 $i-1$）。

**证明**：由冲突条件 $s' < e$。分两种情形。

- 若 $s' \ge s$：则 $s'$ 是满足「起点 $\ge s$」的起点之一，由 $i$ 的最小性有 $\text{start}_i \le s' < e$，后继检查以 $\text{start}_i < e$ 命中。又因起点互不相同，起点 $\ge s$ 的区间中起点最小者唯一，故 $[s',e')$ 正是下标 $i$ 的区间。
- 若 $s' < s$：则 $s'$ 属于「起点 $< s$」的区间，其下标 $\le i-1$；而 $j = i-1$ 是这类区间中起点最大者，故 $s' \le \text{start}_j$，由终点升序得 $e' \le \text{end}_j$。于是 $\text{end}_j \ge e' > s$，前驱检查以 $\text{end}_j > s$ 命中。∎

**引理 2（检查命中有真冲突）**：

（a）若后继检查命中，即 $\text{start}_i \ge s$ 且 $\text{start}_i < e$，则 $[s,e)$ 与 $[\text{start}_i,\text{end}_i)$ 确实相交；

（b）若前驱检查命中，即 $\text{start}_j < s$ 且 $\text{end}_j > s$，则 $[s,e)$ 与 $[\text{start}_j,\text{end}_j)$ 确实相交。

**证明**：（a）中 $\text{start}_i \in [\text{start}_i,\text{end}_i)$ 且 $\text{start}_i \in [s,e)$（因 $\text{start}_i \ge s$、$\text{start}_i < e$），故这个点同属两区间；（b）中 $s \in [\text{start}_j,\text{end}_j)$（因 $\text{start}_j < s < \text{end}_j$）且 $s \in [s,e)$。∎

**引理 3（不变式保持）**：对 `book` 的调用序列做归纳，算法每次执行后 $S$ 恒满足「区间两两不相交，且按起点升序时终点也升序」。

**证明**：初始 $S=\varnothing$，不变式平凡成立。设执行前不变式成立。

- 若任一次检查命中：由引理 2 确实存在冲突，算法返回 `false` 且不写入，$S$ 不变，不变式保持。
- 若两次检查都未命中：由引理 1 的逆否命题，$S$ 中不存在与 $[s,e)$ 冲突的区间，故插入后仍两两不相交。再验终点升序：新区间位于下标 $i$，其前驱满足 $\text{start}_{i-1} < s$ 且 $\text{end}_{i-1} \le s$（否则前驱检查命中），故 $\text{end}_{i-1} < e$；其后继满足 $\text{start}_i \ge e$（否则后继检查命中），故 $e \le \text{start}_i < \text{end}_i$，即 $e < \text{end}_i$。因此「前驱终点 < 新终点 < 后继终点」，终点序列依然严格递增。∎

**定理**：`book(s,e)` 返回 `true` 当且仅当把 $[s,e)$ 加入日历后不产生重复预订。

**证明**：

- （真 ⇒ 无冲突）返回 `true` 说明两次检查都未命中；由引理 1 的逆否命题，$S$ 中不存在与 $[s,e)$ 冲突的区间，插入合法。
- （无冲突 ⇒ 真）若无冲突，则引理 1 的两个候选位置都不满足命中条件（否则由引理 2 会真的冲突），算法必走到插入并返回 `true`。
- （假 ⇒ 有冲突）返回 `false` 只在某次检查命中时发生，由引理 2 此时确有重复预订，且算法未写入集合。

三种情形合起来即得结论。∎

## 6. 复杂度分析

设当前已接受区间数为 $n$（本题 $n \le 1000$）。

- **时间（C++）**：每次 `book` 一次 `map::lower_bound` 加一次插入，均为 $O(\log n)$；$n$ 次调用总计 $O(n \log n)$。
- **时间（Python）**：`bisect_left` 是 $O(\log n)$，但 `list.insert` 需要搬移 $O(n)$ 个元素，故单次 $O(n)$、总计 $O(n^2)$；实测 $n=1000$ 时约 $10^6$ 量级的指针搬移，远快于同阶的 Python 循环比较。
- **空间**：$O(n)$，只存 $n$ 个区间的两个端点；不随值域 $10^9$ 增长（这正是不能直接开数组做差分的原因）。

## 7. 参考代码

### C++

```cpp
#include <map>
#include <iterator>
using namespace std;

class MyCalendar {
    map<int, int> events;   // start -> end，按键（起点）升序
public:
    MyCalendar() {}

    bool book(int startTime, int endTime) {
        auto it = events.lower_bound(startTime);   // 第一个起点 >= startTime 的区间
        // 后继：起点落在新区间内部
        if (it != events.end() && it->first < endTime) return false;
        // 前驱：终点越过新区间起点（含"新区间被完全包含"的情形）
        if (it != events.begin() && prev(it)->second > startTime) return false;
        events[startTime] = endTime;
        return true;
    }
};
```

### Python

```python
import bisect


class MyCalendar:

    def __init__(self):
        self.starts = []   # 已接受区间的起点，升序
        self.ends = []     # 与 starts 一一对应的终点

    def book(self, startTime: int, endTime: int) -> bool:
        i = bisect.bisect_left(self.starts, startTime)
        # 后继：第一个起点 >= startTime 的区间，其起点若 < endTime 则重叠
        if i < len(self.starts) and self.starts[i] < endTime:
            return False
        # 前驱：起点 < startTime 的最后一个区间，其终点若 > startTime 则重叠
        if i > 0 and self.ends[i - 1] > startTime:
            return False
        self.starts.insert(i, startTime)
        self.ends.insert(i, endTime)
        return True
```

## 8. 边界情况与易错点

1. **端点相接**：`[10,20)` 后插入 `[20,30)` 必须返回 `true`。把判定写成 $start \le e$ 或 $end \ge s$ 会在这一组数据上直接 WA，这也是本题最经典的错法。
2. **空日历首发**：第一次 `book` 恒为 `true`。此时 `lower_bound` 返回 `end()`，前驱判断也不能越界。
3. **前驱不存在**：新区间就是最小的那个（如 `s = 0`），`it == begin()`，必须提前短路，不能对 `begin()` 求 `prev`。
4. **完全重复预订**：同一区间 $[s,e)$ 第二次调用时 `lower_bound` 命中已有的键，$start = s < e$ 成立，后继检查直接拒绝；不要期待 `map` 的赋值会「覆盖」出一个合法状态。
5. **被完全包含**：`[20,30)` 插入已有 `[10,100)` 时，`lower_bound(20)` 返回末尾（没有起点 $\ge 20$），只有前驱检查能发现冲突——说明**前驱检查不可省略**。
6. **只增不删**：本题不需要合并、也不需要支持取消预约，所以不必像「Range 模块」那样处理区间拆分与合并。
7. **Python 数组错位**：`starts` 与 `ends` 是平行数组，插入下标必须一致；一旦错位，`ends[i-1]` 对应的就不再是 `starts[i-1]` 那个区间。
8. **整数范围**：端点最大 $10^9$，`int` 足够；若后续扩展要计算区间长度或做端点 $+1$ 的离散化，应改用 `long long` 防溢出。
