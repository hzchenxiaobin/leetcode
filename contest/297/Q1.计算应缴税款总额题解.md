# LeetCode 计算应缴税款总额 题解

## 1. 题目概述

- **标题 / 题号**：计算应缴税款总额（#2303，easy）
- **链接**：https://leetcode.cn/problems/calculate-amount-paid-in-taxes/
- **来源**：LeetCode 第 297 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、数学

**题意**：给定下标从 $0$ 开始的二维整数数组 `brackets`，其中 `brackets[i] = [upper_i, percent_i]` 表示第 $i$ 个**税级**的上限是 `upper_i`、税率是 `percent_i`（百分数 $0 \sim 100$）。税级按上限**从低到高严格递增**排列。税收按**分段累进**：

- 不超过 $u_0$ 的收入按 $p_0$ 缴纳；
- 接着 $u_1 - u_0$ 的部分按 $p_1$ 缴纳；
- 以此类推。

给定整数 `income` 表示总收入，返回应缴税款总额（答案容差 $10^{-5}$）。

**约束**：

- $1 \le \text{brackets.length} \le 100$
- $1 \le u_i \le 1000$，且 `upper` **互异、升序**（无需自己排序）
- $0 \le p_i \le 100$
- $0 \le \text{income} \le 1000$
- **最后一个税级的上限 $\ge$ income**

> 💡 本题在本仓库另有[每日题解 2303](../../solution/2301-2400/2303_计算应缴税款总额.md)：以「游标右移 + 段式批量」为主线展开，含面试问答与同类练习。本篇按**周赛复盘视角**展开，侧重签到题从题面到公式的**最短切入路径**、两类高频 WA（**整除截断 / 负值段扣减**）、引理-定理证明与边界清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：brackets = [[3,50],[7,10],[12,25]], income = 10
输出：2.65000
解释：前 $3 税率 50% → $1.50；接着 $4（7−3）税率 10% → $0.40；
      最后 $3（10−7）税率 25% → $0.75；合计 $2.65。
```

**示例 2**

```text
输入：brackets = [[1,0],[4,25],[5,50]], income = 2
输出：0.25000
解释：前 $1 税率 0% → $0；剩 $1（2−1）税率 25% → $0.25。
```

**示例 3**

```text
输入：brackets = [[2,50]], income = 0
输出：0.00000
解释：没有收入，无需纳税。
```

**补充示例：income 之后的税级（负值段，守卫的必要性）**

```text
输入：brackets = [[3,50],[7,10],[12,25],[20,30]], income = 10
输出：2.65000
解释：输入完全合法（末段上限 20 ≥ income，upper 互异升序）。
      但第 3 段计完后 prev = 12 ＞ income = 10，第 4 段的
      taxable = min(10,20) − 12 = −2 是负值段——若不加守卫
      直接累加，会错误地「扣减」税款 2 × 30% = 0.60，得 2.05。
```

> ⚠️ 这个补充示例揭示本题最容易忽略的事实：**「最后税级上限 ≥ income」并不蕴含「income 之前的段都盖不住它」**——中间段的上限完全可能越过 income，负值段在合法输入里真实存在，守卫不是可有可无的防御性代码。

## 3. 解题思路

### 3.1 暴力思路：逐美元查表

最直译题面的做法：把收入**逐美元**模拟——对第 $d \in [1, \text{income}]$ 元，线性扫 `brackets` 找到首个 $u_i \ge d$ 的税级，把 $p_i / 100$ 累进税款。

- 正确，时间 $O(\text{income} \cdot n) \approx 10^5$，本题规模下**必然 AC**，作为签到提交够用；
- 冗余在于：相邻美元几乎总落在**同一税级**（示例 1 的第 1~3 元都属第 1 级），逐元重查把「一段一次乘法能算完的事」拆成上千次查询；
- 若 $n$ 与 `income` 各放大两个数量级，这个写法就会吃紧。

另有一种**错误**的「一步到位」写法：对每段直接按全长计税（$u_i - u_{i-1}$ 乘税率）而**不封顶在 income**——收入超过所在段中间时立刻多算，WA 起点正是漏掉 $\min$。

### 3.2 核心观察：升序上限把收入轴分段，min 封顶 + prev 游标

![核心观察：升序上限把收入轴分段，min 封顶 + prev 游标](images/wc297_q1_bracket_segments_concept.svg)

记 $u_{-1} := 0$ 为**虚拟首段下界**，三层观察如下：

1. **升序互异 ⟹ 收入轴被切成连续段**：$(u_{i-1}, u_i]$ 是第 $i$ 段的势力范围，段内税率恒为 $p_i$。属于同一段的所有美元税率相同 → 可以**段式批量**，一段一次乘法。
2. **本段应税元数**：$\text{taxable}_i = \min(\text{income}, u_i) - \text{prev}$，其中 $\text{prev} = u_{i-1}$ 是游标。$\min$ 把本段**封顶**在收入处（收入中途截止就只算到 income，不会多算）；$-\ \text{prev}$ 把已计税的前缀**扣掉**，只留本段独占的元数。
3. **收入计满即止**：一旦 $\text{prev} \ge \text{income}$，后续段 $\min(\text{income}, u_i) - \text{prev} \le 0$——**负值段绝不能累加**（会扣减税款），用 `break` 守卫拦下。

```python
tax += (min(income, upper) - prev) * percent / 100
```

一行公式就是整个算法；`prev` 游标随段右移，单趟扫完。

### 3.3 算法流程

![算法流程：单趟扫描税级，prev 游标 + break 守卫](images/wc297_q1_algorithm_flow.svg)

1. 初始化 `tax = 0`，`prev = 0`（游标 = 上一段上限）；
2. 对每个税级 `[upper, percent]`：
   - 若 $\text{income} \le \text{prev}$：收入已全部计税，`break`；
   - 否则 $\text{taxable} = \min(\text{income}, \text{upper}) - \text{prev}$；
   - `tax += taxable * percent / 100.0`；
   - `prev = upper`（游标右移）；
3. 返回 `tax`。

无排序、无回溯、无嵌套循环；每段常数次运算，收入计满立即短路退出。

### 3.4 示例演算

![示例演算：示例 1 逐段走查 + 守卫反例](images/wc297_q1_example_walkthrough.svg)

以**示例 1** `brackets = [[3,50],[7,10],[12,25]]`、`income = 10` 走查：

| 段 | 税级 $[u, p]$ | $\text{prev} \to u$ | $\text{taxable}$ | 段税 | 累计 tax |
|----|---------------|--------------------|------------------|------|----------|
| 1 | $[3, 50]$ | $0 \to 3$ | $\min(10,3)-0 = 3$ | $3 \times 50\% = 1.50$ | $1.50$ |
| 2 | $[7, 10]$ | $3 \to 7$ | $\min(10,7)-3 = 4$ | $4 \times 10\% = 0.40$ | $1.90$ |
| 3 | $[12, 25]$ | $7 \to 12$ | $\min(10,12)-7 = 3$ | $3 \times 25\% = 0.75$ | $\mathbf{2.65}$ |

返回 $2.65$ ✓。关键在第 3 段：收入 $10$ 落在本段**中间**（段跨 $7 \to 12$ 共 5 元），$\min$ 只放行 $3$ 元；随后 `prev = 12 ＞ 10`，若有后续税级在下轮开头被守卫拦下（见补充示例的 $-2$ 元负值段）。

示例 2 中 $p_0 = 0$ 的段贡献恰为 $0$，无需特判；示例 3 中 `income = 0` 首轮即满足 $0 \le 0$ 直接 `break`，返回 $0$，同样无需特判——**两个天然边界都被通用循环覆盖**。

## 4. 算法细节

1. **prev 游标语义**：处理完第 $i$ 段后 $\text{prev} = u_i$；初值 $0 = u_{-1}$ 是虚拟首段下界，让第 0 段的公式与后续段**完全同构**，无需特判首段。
2. **$\min$ 的双重作用**：$\text{income} \ge u_i$ 时取 $u_i$（整段计入）；$\text{income} < u_i$ 时取 $\text{income}$（本段截断，只计到收入处）。一个 $\min$ 同时覆盖「整段」与「中途截止」两种情形。
3. **守卫的两种等价写法**：`if (income <= prev) break;` 与 `taxable = max(0, min(income, upper) - prev)` 二选一。由 $u_i$ 严格升序可证 $\text{income} > \text{prev} \iff \text{taxable} > 0$（见引理 2），两写法在**所有合法输入**上逐段等价；推荐前者——提前退出、语义直白（「收入计满了」而非「钳成零」）。
4. **浮点写法**：`taxable * percent` 是整数精确运算，务必 `/100.0`（C++ 中 `int / 100` 是**整除截断**，见第 8 节头号 WA）。每段只做一次除法，$n \le 100$ 次累加，`double` 舍入误差 $\ll 10^{-5}$ 容差。Python 的 `/` 本就是真除法，写 `/100.0` 仅为与 C++ 对齐。
5. **无需排序**：题面保证 `upper` 互异且升序；若去掉该保证，先按 `upper` 排序（$O(n \log n)$）即可复用全部逻辑。
6. **「末段上限 ≥ income」的实际含义**：收入必然落在某个税级内（存在覆盖它的段），算法一定会在某轮把收入计满后停住；但它**不保证中间段上限 < income**——补充示例正是中间段（第 3 段，$u = 12$）越过 income 的合法输入，负值段由此产生，这是守卫必须存在的根本原因。

## 5. 正确性证明

**引理 1（游标不变量）**：进入第 $i$ 轮循环时，$\text{prev} = u_{i-1}$（$i = 0$ 时 $\text{prev} = 0$），且 `tax` 等于题面规则下「第 $1 \sim \min(\text{income},\, \text{prev})$ 元」已产生的税款。

**证明**：对 $i$ 归纳。$i = 0$ 时 $\text{prev} = 0$，零元收入的税款为 $0$，`tax = 0` 成立。设第 $i$ 轮进入时成立：若触发 `break`（$\text{income} \le \text{prev}$），此后 `tax` 不再被修改，量保持且 $\min(\text{income}, \text{prev}) = \text{income}$，即已是全额税款。若未触发，由引理 2 知 $\text{taxable}_i = \min(\text{income}, u_i) - \text{prev} \ge 1$，恰是第 $\text{prev}+1 \sim \min(\text{income}, u_i)$ 元的个数；这些元此前未被计过税（归纳量只覆盖到 $\text{prev}$），本轮以 $p_i / 100$ 逐元计入，与题面对该段的规定一致；随后 $\text{prev} \leftarrow u_i$。故第 $i+1$ 轮进入时不变量成立。∎

**引理 2（taxable 的刻画与非负性）**：若第 $i$ 轮未触发守卫（$\text{income} > \text{prev}$），则 $\text{taxable}_i = \min(\text{income}, u_i) - \text{prev} \ge 1$，且恰为「收入中落在第 $i$ 段势力范围 $(\text{prev}, u_i]$ 内的元数」。反之，$\text{income} \le \text{prev}$ 时任何写法得到的该轮贡献必为非正。

**证明**：前提给出 $\text{income} > \text{prev}$；升序互异给出 $u_i > u_{i-1} = \text{prev}$。分两种情形：① $\text{income} \ge u_i$：$\min = u_i$，$\text{taxable}_i = u_i - \text{prev} \ge 1$，为整段元数（第 $\text{prev}+1 \sim u_i$ 元，全部 $\le \text{income}$，应计税）；② $\text{prev} < \text{income} < u_i$：$\min = \text{income}$，$\text{taxable}_i = \text{income} - \text{prev} \ge 1$，为第 $\text{prev}+1 \sim \text{income}$ 元，即收入在本段中途截止处的已计元数。两种情形合并即「$(\text{prev}, \min(\text{income}, u_i)]$ 内的元数」，且 $\min(\text{income}, u_i) > \text{prev}$ 保证非负性（整数为正）。反向：$\text{income} \le \text{prev}$ 时 $\min(\text{income}, u_i) \le \text{income} \le \text{prev}$，差非正；若不设守卫而累加，即引入非正贡献——其中严格为负时（$u_i > \text{income} \ge$ 某后续情形）将**错误扣减**税款。∎

**定理**：算法返回题面定义的税款总额 $\mathrm{Tax}(\text{income})$。

**证明**：若 $\text{income} = 0$：首轮 $\text{income} \le \text{prev}$（$0 \le 0$）即 `break`，返回 $0 = \mathrm{Tax}(0)$。若 $\text{income} \ge 1$：由约束「末段上限 $\ge \text{income}$」知存在最小下标 $k$ 使 $u_k \ge \text{income}$（覆盖收入的段）。对 $i < k$：$u_i < \text{income}$，故 $\text{prev} \le u_{i} < \text{income}$，守卫不触发，逐段整段计入；第 $k$ 段由引理 2 计入恰 $u_k \wedge \text{income}$ 截断后的剩余元数，把收入**恰好计满**（$\min(\text{income}, u_k) = \text{income}$）。此后 $\text{prev} = u_k \ge \text{income}$，第 $k+1$ 轮必 `break`（若存在）。由引理 1 及两引理的「段不交、每元恰计一次」，累计恰为 $\sum_i \text{taxable}_i = \text{income}$ 且每元按其所属段税率计税——与 $\mathrm{Tax}(\text{income})$ 的分段定义逐元一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n = \text{brackets.length} \le 100$。单趟扫描，每段常数次运算（一次比较守卫、一次 $\min$、一次乘法、一次除法、一次加法）；`break` 使收入计满后立即终止，最坏也不过走完 $n$ 段。对 `income` 的循环依赖被段式批量**完全消去**——即便 $\text{income}$ 放大到 $10^9$ 仍是 $O(n)$。
- **空间复杂度**：$O(1)$。仅 `tax`、`prev`、`upper`、`percent`、`taxable` 常数个变量，不随输入规模增长。

## 7. 参考代码

### C++（主解：单趟扫描 + break 守卫）

```cpp
class Solution {
public:
    double calculateTax(vector<vector<int>>& brackets, int income) {
        double tax = 0.0;
        int prev = 0;
        for (auto& b : brackets) {
            if (income <= prev) break;               // 收入已计满：拦下负值段
            int taxable = min(income, b[0]) - prev;  // min 封顶 + prev 扣前
            tax += taxable * b[1] / 100.0;           // /100.0 而非 /100
            prev = b[0];                             // 游标右移
        }
        return tax;
    }
};
```

### C++（变体：max 钳零，不用 break）

```cpp
class Solution {
public:
    double calculateTax(vector<vector<int>>& brackets, int income) {
        double tax = 0.0;
        int prev = 0;
        for (auto& b : brackets) {
            int span = min(income, b[0]);         // 封顶后的本段右端
            tax += max(0, span - prev) * b[1] / 100.0;
            prev = b[0];
        }
        return tax;
    }
};
```

> 💡 变体与主解逐段等价（引理 2）：`span - prev` 一旦非正，后续段因 $u$ 升序恒非正，钳零后循环空转到结尾，结果相同；主解短路更早、意图更直白。

### Python（与主解同构）

```python
class Solution:
    def calculateTax(self, brackets: List[List[int]], income: int) -> float:
        tax, prev = 0.0, 0
        for upper, percent in brackets:
            if income <= prev:
                break
            taxable = min(income, upper) - prev
            tax += taxable * percent / 100.0
            prev = upper
        return tax
```

> ⚠️ Python 的 `/` 是真除法，`/100` 也正确；写 `/100.0` 只为与 C++ 版逐字对齐。C++ 中若写 `taxable * b[1] / 100`，`int / int` 整除截断——如 $3 \times 50 / 100 = 1$ 而非 $1.5$，这是本题**头号 WA**。

## 8. 边界情况与易错点

1. **整除截断（头号 WA）**：C++ 中 `taxable * percent / 100` 是整型除法，会把 $1.5$ 截成 $1$。必须 `/100.0` 或 `tax += 1.0 * taxable * percent / 100`。
2. **负值段必须拦**：合法输入真实存在负值段（补充示例第 4 段 $\min(10,20)-12 = -2$），不设守卫会把税款**扣减**而非只是多算。`income ≤ prev` 与 `max(0, ·)` 择一。
3. **守卫用 `≤` 而非 `<`**：收入恰等于某段上限时（$\text{income} = \text{prev}$），当轮 $\text{taxable} = 0$，写 `<` 不会算错但多扫一轮；`≤` 立即停，语义即「收入计满」。
4. **income = 0**：首轮 $0 \le 0$ 即 `break` 返回 $0$（示例 3），无需特判。
5. **percent = 0 的段**：贡献恰为 $0$，天然处理（示例 2 第 1 段），不要为「零税率」写任何分支。
6. **不要漏掉 min**：对每段直接按全长 $u_i - u_{i-1}$ 计税而不封顶，收入中途截止时立刻多算——$\min$ 才是「只计到收入」的闸门。
7. **percent 是百分数不是小数**：题面 $0 \le p_i \le 100$，须除以 $100$；直接把 `percent` 当 $0 \sim 1$ 小数乘会放大百倍。
8. **不用排序、不用浮点存 prev**：题面保证升序互异；`prev`、`taxable` 均为 `int`（精确），只有乘税率那一步进浮点，量级 $\le 1000$、累加 $\le 100$ 项，`double` 误差 $\ll 10^{-5}$ 容差，无需任何补偿求和。
