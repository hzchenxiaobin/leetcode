# LeetCode 公司命名 题解

## 1. 题目概述

- **标题 / 题号**：公司命名（#2306，hard）
- **链接**：https://leetcode.cn/problems/naming-a-company/
- **来源**：LeetCode 第 297 场周赛 Q4
- **难度**：困难
- **标签**：哈希表、字符串、枚举、计数、位运算

**题意**：给定互异单词数组 $\textit{ideas}$。从中选两个不同单词 $A$、$B$，**交换二者的首字母**得到新词 $\textit{newA}$、$\textit{newB}$；若两个新词**都不在** $\textit{ideas}$ 中，则「$\textit{newA newB}$」（中间一个空格）是一个有效公司名。求**不同**且有效的公司名数目。注意 $A$、$B$ 是**有序**的：同一对单词正反两个方向算两个名字（示例 1 中 ("coffee","donuts") 与 ("donuts","coffee") 各计一次）。

**约束**：

- $2 \le n \le 5 \times 10^4$
- $1 \le |\textit{ideas}[i]| \le 10$，仅小写字母
- $\textit{ideas}$ 内单词互不相同

> 💡 本题在本仓库另有[每日题解 2306](../../solution/2301-2400/2306_公司命名.md)：以「分桶 + 后缀集合 + 26×26 交集矩阵」为主线、附面试问答。本篇按**周赛复盘视角**展开：暴力差的是哪个数量级、乘法计数的「独立性」从哪来、用引理-定理把「不同名字 ↔ 有效有序对」的一一对应补严（这是最容易被直觉略过的一步）、bitset 版实现与边界清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：ideas = ["coffee", "donuts", "time", "toffee"]
输出：6
解释：(coffee, donuts) → "doffee conuts"      (donuts, coffee) → "conuts doffee"
      (donuts, time)  → "tonuts dime"         (donuts, toffee) → "tonuts doffee"
      (time, donuts)  → "dime tonuts"         (toffee, donuts) → "doffee tonuts"
而 (coffee, time) 无效：换头得到 "toffee"，它本身就在 ideas 中。
```

**示例 2**

```text
输入：ideas = ["lack", "back"]
输出：0
解释：两词后缀同为 "ack"，换头得到 "back" / "lack"，均已在 ideas 中。
```

**补充示例：长度为 1 的单词，后缀是空串**

```text
输入：ideas = ["a", "b", "ab"]
输出：0
解释：("a","b") 换头互得 "b"、"a"（都在 ideas）；("b","ab") 换头得 "bb"（不在）
      与 "a"（在 ideas）——"a" 撞车。注意 "a"、"b" 的后缀都是空串 ""，
      空串落在 S_a ∩ S_b 里，恰好把 (a,b) 对的乘积清零（见 §3.2 / §5）。
```

## 3. 解题思路

### 3.1 暴力思路：$O(n^2 L)$，差一个数量级

把 $\textit{ideas}$ 存入哈希集，枚举全部有序对 $(A, B)$，每对构造 $\textit{newA}$、$\textit{newB}$ 各查一次哈希（构造 + 查询 $O(L)$）：

$$n^2 \cdot L = (5 \times 10^4)^2 \times 10 = 2.5 \times 10^{10}$$

**二十五亿次**换头判定，C++ 也跑不动；改成无序对再减半仍是 $10^{10}$ 级。瓶颈不在判重而在**对数本身**——$n^2$ 个对里绝大多数「命运相同」，必须把对压缩成等价类。

### 3.2 核心观察：首字母分桶，「换头」= 后缀去对方桶里查重

![核心观察：首字母分桶与换头判定](images/wc297_q4_suffix_group_concept.svg)

四步观察，从题面到正解：

1. **拆词**：单词 = 首字母 + 后缀。按首字母分 26 个桶，桶内存**后缀集合** $S_a$（哈希集）。$n \le 5\times10^4$ 个后缀、每个 $\le 9$ 字符。
2. **换头的本质**：$A = a + s$、$B = b + t$，换头后 $\textit{newA} = b + s$。而 $\textit{newA} \in \textit{ideas}$ 当且仅当**存在以 $b$ 开头、后缀为 $s$ 的词**，即 $s \in S_b$——判定只依赖 $(s, b)$ 这对小对象，与两个桶里的其他任何后缀无关。
3. **同首字母必无效**：$a = b$ 时 $\textit{newA} = a + s = A$ 本身就在 $\textit{ideas}$ 中，整类直接排除。
4. **独立性 ⇒ 乘法**：$(A, B)$ 有效 $\iff s \notin S_b$ 且 $t \notin S_a$。前者只约束 $s$、后者只约束 $t$，**两个条件独立**——对固定字母对 $(a, b)$，有效有序对数一步乘出来：

$$\textit{valid}(a, b) = \bigl(|S_a| - |S_a \cap S_b|\bigr) \times \bigl(|S_b| - |S_a \cap S_b|\bigr)$$

直观读法：**左边选出「后缀不在 $b$ 桶」的 $A$，右边选出「后缀不在 $a$ 桶」的 $B$，两边自由组合**。补充示例里空串 "" 同时在两桶 ⇒ 交集非空 ⇒ 某一侧被清零，正是这条公式的具象。

### 3.3 算法流程

![算法流程：分桶 → 两两求交集 → 乘法计数](images/wc297_q4_algorithm_flow.svg)

1. **分桶**：遍历 $\textit{ideas}$，`g[w[0]].insert(w.substr(1))`，$O(nL)$；
2. **枚举字母对** $a < b$（至多 $\binom{26}{2} = 325$ 对，空桶跳过）；
3. **求交集** $\textit{inter} = |S_a \cap S_b|$：遍历**较小**的桶、逐个查询较大桶，$O(\min(|S_a|, |S_b|) \cdot L)$；
4. **计数累加**：$\textit{ans} \mathrel{+}= 2 \times (|S_a| - \textit{inter}) \times (|S_b| - \textit{inter})$。

$O(n^2)$ 的单词对被压缩进 $O(26^2)$ 个等价类，每类 $O(1)$ 计数——「**按等价类贡献计数**」是周赛计数题的高频打法（与 [Q3 状压 DP](Q3.公平分发饼干题解.md) 的「集合即状态」同一哲学：先找到命运相同的整块，再整块计数）。

### 3.4 示例演算

![示例 1 演算：三桶两两配对，答案 6 逐一落地](images/wc297_q4_example_walkthrough.svg)

以**示例 1** 走查（$\textit{ideas} = $ [coffee, donuts, time, toffee]）。分桶：

$$S_c = \{\text{offee}\},\quad S_d = \{\text{onuts}\},\quad S_t = \{\text{ime},\ \text{offee}\}$$

三个字母对逐一清算：

| 字母对 | $S_a \cap S_b$ | $S_a \setminus S_b$ | $S_b \setminus S_a$ | 有效有序对 |
|---|---|---|---|---|
| $(c, d)$ | $\varnothing$ | {offee}（1 个） | {onuts}（1 个） | $2 \times 1 \times 1 = 2$ |
| $(c, t)$ | {offee} | $\varnothing$（**被清零**） | {ime}（1 个） | $2 \times 0 \times 1 = 0$ |
| $(d, t)$ | $\varnothing$ | {onuts}（1 个） | {ime, offee}（2 个） | $2 \times 1 \times 2 = 4$ |

- $(c, d)$：coffee 换成 doffee、donuts 换成 conuts，两个新词都不存在 ⇒ 正反两个名字；
- $(c, t)$：offee 同时住在 $c$、$t$ 两桶，coffee 换头必得 toffee ⇒ 整对报废（coffee×time、coffee×toffee 全灭）；
- $(d, t)$：onuts 不在 $t$ 桶、ime/offee 不在 $d$ 桶，donuts 与 time、toffee 任意组合 ⇒ $1 \times 2$ 个无序对、$4$ 个名字。

**答案** $= 2 + 0 + 4 = 6$ ✓，与官方解释的六个名字逐一对应；另三对（coffee×time、coffee×toffee 撞 toffee，time×toffee 同首字母）全灭 ✓。

## 4. 算法细节

1. **后缀提取**：`substr(1)`。长度 1 的单词后缀是**空串**，它是合法后缀、正常参与分桶与交集（补充示例）；实现时千万别「特判空串跳过」。
2. **交集求法**：遍历较小集合、在较大集合里 `count`，单次 $O(\min \cdot L)$。Python 直接 `len(g[a] & g[b])`，CPython 在 C 层做同样的「小集驱动」优化。
3. **×2 与循环写法的配对**：`a < b` 循环里乘 2；等价写法是 `a ≠ b` 双层循环**不乘** 2。两套写法只取一套——`a ≠ b` 循环又乘 2 是答案翻倍的经典 WA（§8 第 2 条）。
4. **空桶剪枝**：`g[a].empty()` 直接 `continue`（乘积必为 0，纯常数优化，n 全部同首字母时省掉 25/26 的空转）。
5. **每对字母只算一次**：交集用完即弃，无需 26×26 缓存矩阵（每日题解的矩阵版是为「顺带复用」教学，本题单遍不需要）。
6. **桶内天然无重**：单词互异 ⇒ 同桶后缀互异，桶内不用去重；**跨桶**的后缀重复（如 offee）正是 inter 要捕捉的信息，严禁全局去重。

## 5. 正确性证明

**引理 1（换头判定）**：设 $A = a + s$、$B = b + t$ 且 $a \ne b$，则 $\textit{newA} = b + s \in \textit{ideas} \iff s \in S_b$；$\textit{newB} = a + t \in \textit{ideas} \iff t \in S_a$。

**证明**：$\textit{newA} = b + s \in \textit{ideas}$ 即存在首字母为 $b$、后缀为 $s$ 的词，按 $S_b$ 的定义恰为 $s \in S_b$；$\textit{newB}$ 同理。∎

**引理 2（同首字母对必无效）**：$a = b$ 时 $(A, B)$ 必无效。

**证明**：$\textit{newA} = b + s = a + s = A \in \textit{ideas}$，换头产物撞回原词。∎

**引理 3（按字母对计数）**：对 $a \ne b$，满足「$A$ 以 $a$ 开头、$B$ 以 $b$ 开头」的有效有序对 $(A, B)$ 恰有 $(|S_a| - |S_a \cap S_b|)\,(|S_b| - |S_a \cap S_b|)$ 个。

**证明**：首字母固定为 $a$ 后，$A$ 与其后缀 $s \in S_a$ 一一对应（单词互异 ⇒ 同桶后缀互异），$B$ 同理。由引理 1，$(A, B)$ 有效 $\iff s \in S_a \setminus S_b$ 且 $t \in S_b \setminus S_a$；$s$ 与 $t$ 在各自集合中独立选取，计数相乘。∎

**引理 4（名字与有序对一一对应）**：不同的有效有序对产生不同的公司名。

**证明**：有效名字形如「$X\ Y$」。先证 $X \ne Y$：若 $X = Y$，比较首字母得 $b = a$，与 $a \ne b$ 矛盾。于是名字按唯一空格切分为 $(X, Y)$；又 $b = X[0]$、$s = X[1:]$、$a = Y[0]$、$t = Y[1:]$（单词仅含小写字母、内部无空格），故 $(A, B) = (a + s,\ b + t)$ 由名字**唯一恢复**，映射是单射。∎

**定理**：所求答案 $= \displaystyle\sum_{a \ne b} \bigl(|S_a| - |S_a \cap S_b|\bigr)\bigl(|S_b| - |S_a \cap S_b|\bigr)$。

**证明**：答案 = 不同有效公司名数 = 有效有序对数（引理 4）。按（$A$ 的首字母 $a$，$B$ 的首字母 $b$）给有效有序对分类：$a = b$ 类为空（引理 2）；$a \ne b$ 类的数目由引理 3 给出。各类相加即得。∎

> 💡 引理 4 最容易被「名字怎么会重」的直觉略过，但它依赖两个非平凡事实：**换头产物首字母不同**（保证 $X \ne Y$、空格切分唯一）与**单词内部无空格**。补上这条，按「有序对」计数与按「名字」计数才真正闭合——比赛时它是隐式假设，复盘时应当显式化。

## 6. 复杂度分析

- **时间复杂度**：$O(nL)$ 分桶 + $\sum_{a<b} O(\min(|S_a|,|S_b|) \cdot L)$ 求交 + $O(26^2)$ 求和。由 $\sum_{a<b} \min(|S_a|,|S_b|) \le 25 \sum_a |S_a| = 25n$，总计 $O(26\,n\,L) \approx 26 \times 5\times10^4 \times 10 = 1.3 \times 10^7$ 字符级操作。
- **空间复杂度**：$O(nL)$——26 个桶合计存 $n$ 个后缀串；bitset 版 $O(26n/8)$ 比特 $\approx 162$ KB。
- 对照暴力 $O(n^2 L) = 2.5 \times 10^{10}$：**三个数量级**的差距全部来自「单词对 → 字母等价类」的压缩，单次判定从 $O(n^2)$ 降到 $O(26^2)$ 类 × 每类 $O(\min)$ 桶扫描。

## 7. 参考代码

### C++（哈希分桶 + 小桶求交）

```cpp
class Solution {
public:
    long long distinctNames(vector<string>& ideas) {
        vector<unordered_set<string>> g(26);
        for (const auto& s : ideas)
            g[s[0] - 'a'].insert(s.substr(1));      // 后缀入桶（含空串）

        long long ans = 0;
        for (int a = 0; a < 26; ++a) {
            if (g[a].empty()) continue;
            for (int b = a + 1; b < 26; ++b) {
                if (g[b].empty()) continue;
                const auto& small = g[a].size() <= g[b].size() ? g[a] : g[b];
                const auto& big   = g[a].size() <= g[b].size() ? g[b] : g[a];
                long long inter = 0;
                for (const auto& suf : small)       // 遍历小桶查大桶
                    if (big.count(suf)) ++inter;
                ans += 2 * ((long long)g[a].size() - inter)
                          * ((long long)g[b].size() - inter);
            }
        }
        return ans;
    }
};
```

### Python（与 C++ 同构）

```python
class Solution:
    def distinctNames(self, ideas: List[str]) -> int:
        g = defaultdict(set)
        for s in ideas:
            g[s[0]].add(s[1:])                      # 后缀入桶（含空串）

        ans = 0
        keys = [c for c in g if g[c]]
        for i, a in enumerate(keys):
            for b in keys[i + 1:]:
                inter = len(g[a] & g[b])            # C 层：小集驱动求交
                ans += (len(g[a]) - inter) * (len(g[b]) - inter)
        return ans * 2
```

### 附：bitset 求交集版（官方位运算标签的由来，常数更优）

```cpp
class Solution {
public:
    long long distinctNames(vector<string>& ideas) {
        unordered_map<string, int> id;              // 后缀 → bit 下标
        for (const auto& s : ideas) id.emplace(s.substr(1), 0);
        int m = 0;
        for (auto& [s, i] : id) i = m++;

        vector<bitset<50000>> B(26);                // 每桶一张位图
        for (const auto& s : ideas)
            B[s[0] - 'a'][id[s.substr(1)]] = 1;

        long long ans = 0;
        for (int a = 0; a < 26; ++a)
            for (int b = a + 1; b < 26; ++b) {
                long long inter = (B[a] & B[b]).count();
                ans += 2 * ((long long)B[a].count() - inter)
                          * ((long long)B[b].count() - inter);
            }
        return ans;
    }
};
```

后缀编号后每桶是一张 $n$ 位位图，交集退化为一次按位与：325 对 × $5\times10^4/64 \approx 782$ 个机器字 ≈ $2.5\times10^5$ 字操作，比哈希版再快约一个常数级，代价是 $O(26n/8)$ 的整型空间。

## 8. 边界情况与易错点

1. **long long 溢出**（头号 WA）：全部单词两两可配时答案接近 $n^2 = 2.5 \times 10^9 > 2^{31}-1$；中间乘积 $(5\times10^4)^2$ 同样超 int。C++ 里 `(long long)` 要在**乘法之前**转型（函数签名虽是 `long long`，表达式仍按 int 计算）。
2. **×2 的加减**：`a < b` 循环必须乘 2（正反两个名字）；`a ≠ b` 双层循环**不乘**。两套写法混用是本题最经典的 WA——答案恰差一倍。
3. **同首字母对**：`a = b` 时 newA 就是 $A$ 本身，必无效；`a < b` 写法天然排除，若用交集矩阵则 `inter[a][a]` 无意义，别让它参与求和。
4. **空串后缀**：长度 1 的单词后缀为 ""，合法且必须参与交集（见补充示例：空串把 (a,b) 对清零）。`substr(1)` 天然正确，额外「特判空串」反而错。
5. **答案按「名字」计、不按「对」计**：引理 4 保证有效有序对与名字一一对应，直接数对即可；**不要**再用名字字符串建集合去重（$2.5\times10^9$ 个名字，MLE/TLE 双杀）。
6. **跨桶后缀重复是信号不是脏数据**：offee 双桶在列正是 inter 的用途；若「顺手」全局去重后缀，(c,t) 类会被错误地计入。
7. **哈希性能**：$n = 5\times10^4$、$L \le 10$，`unordered_set<string>` 稳过；极端卡常可换「排序 + 双指针求交」或 bitset 版（§7 附）。
8. **示例的「善意」**：示例 1 恰好三个字母桶、答案 6；容易让人以为「无交集就随便乘」。构造 (c,t) 这种被清零的对（coffee/toffee 同后缀）压测自己的公式，是赛内 30 秒自检的好习惯。
