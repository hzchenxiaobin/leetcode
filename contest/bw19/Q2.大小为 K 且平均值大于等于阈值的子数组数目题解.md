# LeetCode 大小为 K 且平均值大于等于阈值的子数组数目 题解

## 1. 题目概述

- **标题 / 题号**：大小为 K 且平均值大于等于阈值的子数组数目（#1343，medium）
- **链接**：https://leetcode.cn/problems/number-of-sub-arrays-of-size-k-and-average-greater-than-or-equal-to-threshold/
- **来源**：LeetCode 第 19 场双周赛 Q2
- **难度**：中等
- **标签**：数组、滑动窗口

**题意**：给定整数数组 `arr` 与整数 $k$、$threshold$，统计有多少个**长度恰为 $k$** 且**平均值 $\ge threshold$** 的**连续**子数组。

**约束**：

- $1 \le arr.length \le 10^5$
- $1 \le arr[i] \le 10^4$
- $1 \le k \le arr.length$
- $0 \le threshold \le 10^4$

## 2. 示例

**示例 1**

```text
输入：arr = [2,2,2,2,5,5,5,8], k = 3, threshold = 4
输出：3
解释：子数组 [2,5,5]、[5,5,5]、[5,5,8] 的平均值分别为 4、5、6，
      其余长度为 3 的子数组平均值都小于 4。
```

**示例 2**

```text
输入：arr = [11,13,17,23,29,31,7,5,2,3], k = 3, threshold = 5
输出：6
解释：前 6 个长度为 3 的子数组平均值都大于 5。注意平均值可以不是整数。
```

**示例 3（边界补充）**

```text
输入：arr = [1], k = 1, threshold = 0
输出：1
解释：k = n 时只有唯一一个窗口；threshold = 0 时任何正数子数组都满足。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $n - k + 1$ 个起点，每个起点重新累加 $k$ 个元素求均值：$O(nk)$，最坏 $10^5 \times 10^5 = 10^{10}$ 次操作，必然超时。症结在于**相邻窗口只差两个元素**，却把 $k$ 个数全部重算了一遍。

### 3.2 核心观察：定长滑窗——和的增量更新，比较转成整数域

![定长滑窗：窗口右移一格，和只需+新进−旧出](images/bw19_q2_sliding_window.svg)

长度为 $k$ 的窗口每右移一格，**进入**一个新元素、**离开**一个旧元素，窗口和只需一次加、一次减：

$$S_{i} = S_{i-1} + arr[i + k - 1] - arr[i - 1]$$

于是「每个窗口 $O(k)$」降为「每个窗口 $O(1)$」。

另一个等价观察：均值比较可以**去掉除法**——$\frac{S}{k} \ge threshold$ 与 $S \ge k \cdot threshold$ 等价（$k > 0$），后者是纯整数比较，既省浮点开销，又彻底避开 `0.1 + 0.2` 式的精度问题。

### 3.3 算法流程

```text
1. target = k × threshold                 # 整数化阈值
2. S = 0, ans = 0
3. 依次读入 arr[i]（i = 0..n−1）：
       S += arr[i]                        # 新元素进窗
       若 i >= k：S −= arr[i − k]         # 旧元素出窗
       若 i >= k − 1 且 S >= target：ans += 1   # 窗口完整且达标
4. 返回 ans
```

一次遍历，前 $k-1$ 步只累加不成窗；从 $i = k-1$ 起每步都恰好对应一个完整窗口。

### 3.4 示例演算

![示例1走查：六个窗口的和与判定](images/bw19_q2_walkthrough.svg)

对示例 1（$k=3$，$threshold=4$，即窗口和 $\ge 12$）：六个窗口的和依次为 $6, 6, 9, 12, 15, 18$，后三个 $\ge 12$，答案 $3$。注意第 4 个窗口 $[2,5,5]$ 和恰为 $12$——**「大于等于」包含等于**，且 $12/3 = 4$ 正好压线，整数化比较在这里毫不含糊。

## 4. 算法细节

1. **阈值整数化**：`target = k * threshold` 最大 $10^5 \times 10^4 = 10^9$，贴近 `int` 上界（$2^{31}-1 \approx 2.1 \times 10^9$），C++ 中用 `long long` 承载，杜绝任何溢出可能。
2. **窗口和同样可能到 $10^9$**（$k \le 10^5$ 个 $\le 10^4$ 的数），同样用 `long long` 累加。
3. **入窗/出窗顺序**：先加 `arr[i]`，当 `i >= k` 再减 `arr[i-k]`；判定放在 `i >= k-1` 之后。三个下标条件不要写混——`i >= k` 是出窗，`i >= k-1` 是成窗。
4. **首窗处理**：也可以先算前 $k$ 个之和再从 $i = k$ 起滑动，两种写法等价；上面「边读边维护」的版本省去一次显式初始化。
5. **为什么不用前缀和**：前缀和同样 $O(n)$ 预处理 + $O(1)$ 查询，但要多开一个数组；定长滑窗是它的「压缩版」，空间 $O(1)$。
6. **浮点替代方案**：若坚持算均值，用 `sum * 1.0 / k >= threshold` 也能过（容差宽松），但整数比较是零成本的正确性，没有理由引入浮点。

## 5. 正确性证明

**引理 1（增量正确性）**：记 $S_i = \sum_{t=i}^{i+k-1} arr[t]$ 为起点为 $i$ 的窗口和，则 $S_i = S_{i-1} + arr[i+k-1] - arr[i-1]$ 对所有 $1 \le i \le n-k$ 成立。

**证明**：按定义展开：
$$S_{i-1} = arr[i-1] + \sum_{t=i}^{i+k-2} arr[t], \qquad S_i = \Big(\sum_{t=i}^{i+k-2} arr[t]\Big) + arr[i+k-1].$$
两式相减即得 $S_i - S_{i-1} = arr[i+k-1] - arr[i-1]$。∎

**引理 2（判据等价）**：对 $k \ge 1$，$\frac{S_i}{k} \ge threshold \iff S_i \ge k \cdot threshold$。

**证明**：$k > 0$，不等式两边同乘 $k$ 不改变方向。∎

**定理**：算法返回的 `ans` 恰等于满足条件的长度为 $k$ 的子数组个数。

**证明**：以 $i$ 为终点的判定（$i \ge k-1$）与起点 $s = i - k + 1$ 的窗口一一对应，循环恰好对每个 $s \in [0, n-k]$ 判定一次、不多不少。由引理 1，每步维护的 $S$ 与窗口和严格相等（归纳基础 $S_{k-1} = \sum_{t=0}^{k-1} arr[t]$ 为前 $k$ 步累加所得）；由引理 2，判定条件与「均值 $\ge threshold$」等价。故 `ans` 恰统计全部合法窗口。∎

## 6. 复杂度分析

- **时间**：$O(n)$——单趟遍历，每个元素一次进窗、至多一次出窗，加 $O(1)$ 次比较；$n \le 10^5$ 时远低于时限。
- **空间**：$O(1)$——只维护 `S`、`target`、`ans` 三个标量，不随 $n$ 增长（前缀和版需 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numOfSubarrays(vector<int>& arr, int k, int threshold) {
        long long target = 1LL * k * threshold;   // 均值 >= threshold <=> 和 >= k*threshold
        long long sum = 0;
        int n = (int)arr.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            sum += arr[i];                        // 新元素进窗
            if (i >= k) sum -= arr[i - k];        // 旧元素出窗
            if (i >= k - 1 && sum >= target) ++ans;   // 完整窗口判定
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numOfSubarrays(self, arr: List[int], k: int, threshold: int) -> int:
        target = k * threshold
        s = 0
        ans = 0
        for i, x in enumerate(arr):
            s += x                          # 新元素进窗
            if i >= k:
                s -= arr[i - k]             # 旧元素出窗
            if i >= k - 1 and s >= target:  # 完整窗口判定
                ans += 1
        return ans
```

> 💡 两份代码均通过官方示例（`3`、`6`）与 $k = n$、`threshold = 0` 边界，并与「逐窗口重算均值」的 $O(nk)$ 暴力对拍 3000 组随机数据，结果全部一致。

## 8. 边界情况与易错点

1. **$k = n$**：只有唯一窗口；`i >= k - 1` 在最后一步才成立，判定一次。
2. **$threshold = 0$**：所有窗口必然满足（$arr[i] \ge 1$），答案即 $n - k + 1$，可作 sanity check。
3. **「等于阈值」**：均值恰为 `threshold` 也计数（`>=` 而非 `>`），示例 1 的 $[2,5,5]$ 专门考察这一点。
4. **溢出**：`k * threshold` 与窗口和峰值均约 $10^9$，C++ 一定要 `long long`（尤其 `1LL * k * threshold` 的乘法左边先转型），`int` 相乘再赋值会在乘法处先溢出。
5. **下标条件混淆**：出窗是 `i >= k`（离开的是 `arr[i-k]`），成窗是 `i >= k - 1`；写反会把窗口长度变成 $k+1$ 或 $k-1$。
6. **不要用浮点均值当判据**：$10^5$ 个元素累加再除，虽然本题量级下 `double` 仍精确到个位（$10^9 < 2^{53}$），但整数化比较零成本更稳。
