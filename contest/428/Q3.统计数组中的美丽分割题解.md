# LeetCode 统计数组中的美丽分割 题解

## 1. 题目概述

- **标题 / 题号**：统计数组中的美丽分割（#3388，medium）
- **链接**：https://leetcode.cn/problems/count-beautiful-splits-in-an-array/
- **来源**：LeetCode 第 428 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、字符串（后缀 LCP / Z 函数思想）

**题意**：把整数数组 `nums` 切成三段**非空**连续子数组 $nums_1$、$nums_2$、$nums_3$（按顺序连接恰好还原 `nums`）。若 $nums_1$ 是 $nums_2$ 的**前缀**，或 $nums_2$ 是 $nums_3$ 的**前缀**，则称这是一个**美丽分割**。返回美丽分割的数目。

**约束**：

- $1 \le nums.length \le 5000$
- $0 \le nums[i] \le 50$

> 💡 **读题关键**：① 分割由两个切点 $(i, j)$ 唯一确定（$nums_1 = nums[0..i)$，$nums_2 = nums[i..j)$，$nums_3 = nums[j..n)$），总数 $\binom{n-1}{2}$ 约 1250 万——**枚举本身不慌，慌的是每次判定**；② 「A 是 B 的前缀」是**内容 + 长度**的双重约束：逐位相同，且 B 装得下 A；③ $n \le 5000$ 暗示 $O(n^2)$ 正是复杂度甜区。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,1]
输出：2
解释：美丽分割有：
  ① nums1=[1], nums2=[1,2], nums3=[1]    （nums1 是 nums2 的前缀）
  ② nums1=[1], nums2=[1],   nums3=[2,1]  （nums1 是 nums2 的前缀）
```

**示例 2**

```text
输入：nums = [1,2,3,4]
输出：0
解释：元素两两不同，任何前缀关系都无从谈起，没有美丽分割。
```

**示例 3**（自编，覆盖「全相等数组」）

```text
输入：nums = [3,3,3,3]
输出：3
解释：3 种分割 (1,2)、(1,3)、(2,3) 全部美丽——
  (1,2)、(1,3) 由条件 A 成立（lcp[0][1]=3 ≥ 1 且 j ≥ 2）；
  (2,3) 由条件 B 成立（lcp[2][3]=2 ≥ 1）。
```

## 3. 解题思路

### 3.1 暴力思路：枚举 + 逐位比较

枚举两个切点 $1 \le i < j \le n-1$，对每组 $(i, j)$ 直接逐位比较判前缀：条件 A 比较前 $i$ 位，条件 B 比较前 $j-i$ 位，单次最坏 $O(n)$，总计 $O(n^3)$，$n = 5000$ 时约 $2 \times 10^{10}$ 次比较，完全不可行。

要害在于：**同一起点对的前缀匹配信息被反复重算**。判断各种 $nums_2$ 是否为 $nums_3$ 的前缀，本质上都在问「后缀 $i$ 与后缀 $j$ 从头匹配多远」——这正是**后缀 LCP 表**一口气回答的问题。

### 3.2 核心观察：后缀 LCP 表，把每次判定降到 O(1)

![分割结构与两个判定条件](images/beautiful_splits_split_conditions.svg)

定义 $\mathrm{lcp}[i][j]$ 为后缀 $nums[i..n)$ 与 $nums[j..n)$ 的**最长公共前缀**长度，倒序递推（与 718 最长重复子数组完全同款）：

$$
\mathrm{lcp}[i][j] = \begin{cases} \mathrm{lcp}[i+1][j+1] + 1, & nums[i] = nums[j] \\ 0, & nums[i] \ne nums[j] \end{cases}
$$

边界 $\mathrm{lcp}[n][\cdot] = \mathrm{lcp}[\cdot][n] = 0$（空后缀）。一次 $O(n^2)$ 预处理后，两个条件都变成**一次查表**。

### 3.3 两个条件的化简：不对称的长度检查

- **条件 A**（$nums_1$ 是 $nums_2$ 的前缀）：内容上要求 $nums[0..i) = nums[i..2i)$，即 $\mathrm{lcp}[0][i] \ge i$；长度上要求 $nums_2$ 装得下 $nums_1$，即 $j \ge 2i$。故

  **A $\iff j \ge 2i$ 且 $\mathrm{lcp}[0][i] \ge i$**。

- **条件 B**（$nums_2$ 是 $nums_3$ 的前缀）：内容上要求 $nums[i..j) = nums[j..2(j-i))$，即 $\mathrm{lcp}[i][j] \ge j-i$；而长度检查**竟然可以省略**——因为 $\mathrm{lcp}[i][j] \le n-j$（后缀 $j$ 的长度封顶），一旦 $\mathrm{lcp}[i][j] \ge j-i$ 便自动有 $j-i \le n-j$，即 $nums_3$ 装得下 $nums_2$。故

  **B $\iff \mathrm{lcp}[i][j] \ge j-i$**。

> ⚠️ **不对称的根源**：条件 B 里被匹配的「容器」恰好是后缀 $j$ 本身，LCP 天然被它的长度封顶；条件 A 里的容器 $nums_2$ 只是后缀 $i$ 的**开头一段**，$\mathrm{lcp}[0][i]$ 的上界 $n-i$ 管不住 $nums_2$ 的实际长度 $j-i$，所以必须显式判 $j \ge 2i$。这是本题最易踩的坑（见 §8）。

### 3.4 算法流程

![后缀 LCP 表的递推与全貌](images/beautiful_splits_lcp_table.svg)

1. 倒序填 $\mathrm{lcp}$ 表：$i$ 从 $n-1$ 到 0，$j$ 从 $n-1$ 到 0，只依赖右下角一格，可滚动成两行（见 §4）；
2. 枚举切点 $i \in [1, n-2]$、$j \in (i, n)$；
3. 查表判定 A 或 B，任一成立则计数 +1；
4. 枚举完毕，返回答案。

### 3.5 示例演算

![示例 [1,1,2,1] 三种分割的判定过程](images/beautiful_splits_example_walkthrough.svg)

对 `nums = [1,1,2,1]`（$n = 4$），关键 LCP 值：$\mathrm{lcp}[0][1] = 1$、$\mathrm{lcp}[1][2] = 0$、$\mathrm{lcp}[1][3] = 1$、$\mathrm{lcp}[2][3] = 0$。逐一检验全部 $3$ 种分割：

| $(i, j)$ | 分割 | 条件 A | 条件 B | 美丽？ |
|---|---|---|---|---|
| (1, 2) | [1] ‖ [1] ‖ [2,1] | $j{=}2 \ge 2$ 且 $\mathrm{lcp}[0][1]{=}1 \ge 1$ ✓ | $\mathrm{lcp}[1][2]{=}0 < 1$ ✗ | ✓ |
| (1, 3) | [1] ‖ [1,2] ‖ [1] | $j{=}3 \ge 2$ 且 $\mathrm{lcp}[0][1]{=}1 \ge 1$ ✓ | $\mathrm{lcp}[1][3]{=}1 < 2$ ✗ | ✓ |
| (2, 3) | [1,1] ‖ [2] ‖ [1] | $j{=}3 < 4$ ✗，$\mathrm{lcp}[0][2]{=}0 < 2$ ✗ | $\mathrm{lcp}[2][3]{=}0 < 1$ ✗ | ✗ |

答案 **2** ✓。示例 2 中元素两两不同，LCP 全为 0，两个条件都不可能成立，答案 0。示例 3 中 B 在 $(2,3)$ 处首次立功：$\mathrm{lcp}[2][3] = 2 \ge 1$。

## 4. 算法细节

1. **倒序滚动，只留相邻两行**：递推只依赖右下角 $\mathrm{lcp}[i+1][j+1]$，按 $i$ 从 $n-1$ 倒序滚动两个一维数组即可；$\mathrm{row}[n]$ 从未被写入、恒为 0，恰好充当 $\mathrm{lcp}[i][n] = 0$ 的边界锚点。

2. **对称性读出条件 A**：滚动到第 $i$ 行时顺手取 $\mathrm{row}[0] = \mathrm{lcp}[i][0]$，由 LCP 定义的对称性 $\mathrm{lcp}[i][0] = \mathrm{lcp}[0][i]$——**无需单独跑一遍 Z 函数**预处理条件 A。当 $2i > n$ 时 $\mathrm{lcp}[0][i] \le n-i < i$ 自动判假，无需特判。

3. **内存账本**：直接开 $(n+1)^2$ 的 `int` 表在 $n = 5000$ 时约 **100 MB**，有 MLE 风险；换 `unsigned short` 减半仍达 50 MB。滚动后只剩两个 `int[n+1]`，约 **40 KB**——从 $O(n^2)$ 空间压到 $O(n)$。

4. **计数不重不漏**：C++ 版对每对 $(i, j)$ 直接判 $A \lor B$，天然不重；Python 版按行计数用**容斥**：先数整行的 B，若 $\mathrm{lcp}[0][i] \ge i$ 再补上区间 $[2i, n)$ 的 $n - 2i$ 个 A，减去其中已被 B 数过的部分。

5. **值域 $0 \le nums[i] \le 50$ 其实用不上**：算法只做元素相等比较，与值域无关（也无需离散化），换成任意可比较对象照跑。

## 5. 正确性证明

**引理 1（LCP 递推）**：对 $0 \le i, j \le n-1$，$\mathrm{lcp}[i][j] = \mathrm{lcp}[i+1][j+1] + 1$ 若 $nums[i] = nums[j]$，否则为 $0$。

**证明**：若 $nums[i] \ne nums[j]$，两后缀首元素不同，公共前缀为空，$\mathrm{lcp} = 0$。若相等，任一公共前缀必为「$nums[i]$ + 后缀 $i{+}1$ 与 $j{+}1$ 的公共前缀」，且反之亦然——两边公共前缀与「首元素拼接后的公共前缀」一一对应，长度恰差 1，故 $\mathrm{lcp}[i][j] = 1 + \mathrm{lcp}[i+1][j+1]$。边界行/列为空后缀，值为 0。∎

**引理 2（条件 A）**：$nums_1$ 是 $nums_2$ 的前缀 $\iff$ $j \ge 2i$ 且 $\mathrm{lcp}[0][i] \ge i$。

**证明**：（$\Rightarrow$）前缀要求容器更长：$|nums_2| = j - i \ge |nums_1| = i$，即 $j \ge 2i$；且 $nums_2$ 的前 $i$ 位与 $nums[0..i)$ 逐位相同，而 $j \ge 2i$ 保证这前 $i$ 位恰是 $nums[i..2i)$，逐位相同即后缀 0 与后缀 $i$ 的公共前缀 $\ge i$。（$\Leftarrow$）$\mathrm{lcp}[0][i] \ge i$ 给出 $nums[0..i) = nums[i..2i)$（首 $i$ 位逐位相同）；$j \ge 2i$ 保证 $nums_2$ 的前 $i$ 位恰为 $nums[i..2i)$ 且 $nums_2$ 至少 $i$ 位，故 $nums_1$ 是 $nums_2$ 的前缀。∎

**引理 3（条件 B）**：$nums_2$ 是 $nums_3$ 的前缀 $\iff$ $\mathrm{lcp}[i][j] \ge j-i$。

**证明**：记 $d = j - i$。（$\Rightarrow$）前缀给出 $|nums_3| = n - j \ge d$ 且 $nums[i..i+d) = nums[j..j+d)$，后者即两后缀的公共前缀 $\ge d$。（$\Leftarrow$）若 $\mathrm{lcp}[i][j] \ge d$，则 $nums[i..i+d) = nums[j..j+d)$，内容条件成立；又 $\mathrm{lcp}[i][j] \le n - j$（后缀 $j$ 的长度封顶），故 $d \le n-j$，长度条件自动成立。∎

**定理**：算法返回的计数等于美丽分割数，且不超过 $\binom{n-1}{2} \le 12497501$（`int` 足够）。

**证明**：三段非空分割与切点对 $(i, j)$（$1 \le i < j \le n-1$）一一对应；算法对每对 $(i, j)$ 恰好判定一次，判定式由引理 2、3 与美丽分割的定义等价（$A \lor B$），故计数无重无漏。上界即切点对总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。填表每格 $O(1)$ 共 $(n+1)^2$ 格；枚举 $\binom{n-1}{2}$ 对切点，每对 $O(1)$ 查表。$n = 5000$ 时约 2500 万格填表 + 1250 万次查询，C++ 实测约 30 ms，Python 需按行向量化（约 0.2 s，见 §7）。
- **空间复杂度**：$O(n)$。滚动只保留相邻两行；若坚持整表则为 $O(n^2)$（约 100 MB `int`，风险见 §8）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int beautifulSplits(vector<int>& nums) {
        int n = nums.size();
        // prev = lcp[i+1][·]，cur = lcp[i][·]；cur[n] 恒 0 充当边界锚点
        vector<int> prev(n + 1, 0), cur(n + 1, 0);
        int ans = 0;
        for (int i = n - 1; i >= 1; --i) {
            for (int j = 0; j < n; ++j)
                cur[j] = (nums[i] == nums[j]) ? prev[j + 1] + 1 : 0;
            // 对称性：cur[0] = lcp[i][0] = lcp[0][i]，条件 A 的内容部分顺手可得
            bool condA = cur[0] >= i;
            for (int j = i + 1; j < n; ++j)
                if ((condA && j >= 2 * i) || cur[j] >= j - i)
                    ++ans;
            swap(cur, prev);
        }
        return ans;
    }
};
```

### Python

```python
import numpy as np

class Solution:
    def beautifulSplits(self, nums: List[int]) -> int:
        n = len(nums)
        if n < 3:
            return 0
        a = np.array(nums, dtype=np.int32)
        idx = np.arange(n, dtype=np.int32)
        # goodA[i] = lcp[0][i] >= i（即 nums[0..i) == nums[i..2i)），切片比较为 C 速度
        goodA = [nums[:i] == nums[i:2 * i] for i in range(1, n)]
        ans = 0
        # row[j] = lcp[i][j]，初始为 i = n 的全零行（空后缀）
        row = np.zeros(n + 1, dtype=np.int32)
        for i in range(n - 1, 0, -1):
            # 用第 i+1 行滚出第 i 行：相等则右下 +1，不等归 0
            row[:n] = np.where(a == a[i], row[1:] + 1, 0)
            # 条件 B：j ∈ (i, n)，lcp[i][j] >= j - i
            ans += int(np.count_nonzero(row[i + 1:n] >= idx[i + 1:n] - i))
            # 条件 A：goodA[i] 且 j >= 2i（共 n - 2i 个），
            # 减去其中已被 B 数过的，容斥避免重复计数
            if goodA[i - 1] and 2 * i < n:
                ans += n - 2 * i
                ans -= int(np.count_nonzero(row[2 * i:n] >= idx[2 * i:n] - i))
        return ans
```

> 💡 Python 版说明：$n = 5000$ 时纯 Python 双重循环要执行上千万次解释器操作，容易超时。这里按**行滚动 + 整行向量化**：递推交给 `np.where`，计数交给 `np.count_nonzero`；条件 A 与 $j$ 无关，整段计数后做一次容斥。`goodA[i]` 用切片相等（C 级速度）代替 Z 函数，语义就是「前 $i$ 个元素与接下来 $i$ 个元素逐一相同」。

## 8. 边界情况与易错点

1. **$n < 3$ 切不出三段非空**：答案 0。C++ 版循环边界自然覆盖；Python 版显式特判更稳。

2. **条件 A 漏判 $j \ge 2i$（本题最高频错误）**：如 `nums = [1,1,1,1]` 取 $(i, j) = (2, 3)$，$\mathrm{lcp}[0][2] = 2 \ge 2$ 内容成立，但 $nums_2 = [1]$ 只有 1 位装不下 $nums_1 = [1,1]$，不美丽——漏判长度会多数一个。

3. **条件 B 不必加长度判断**：$\mathrm{lcp}[i][j] \le n-j$ 封顶已经蕴含 $j - i \le n - j$。加上不会错，但说明没吃透「LCP 被后缀长度封顶」这层保险；真正要想明白的是**为什么条件 A 没有这层保险**（容器只是后缀开头一段）。

4. **整表 `int` 的内存坑**：$(n+1)^2 \approx 2.5 \times 10^7$ 格 $\times$ 4 字节 $\approx$ 100 MB，有 MLE 风险。递推只依赖右下角，按行滚动即降到 $O(n)$；条件 A 所需的 $\mathrm{lcp}[0][i]$ 由对称性 $\mathrm{lcp}[i][0] = \mathrm{row}[0]$ 顺手读出。

5. **全相等数组并非全部美丽**：长度条件真的在起作用。如 $n = 12$ 全 1 数组取 $(i, j) = (6, 10)$：$j < 2i$（A ✗）且 $n - j = 2 < j - i = 4$（B ✗）。

6. **对角线与边界**：$\mathrm{lcp}[i][i] = n - i$（后缀与自身）在填表时会写入但从不被查询（$j > i$ 严格）；边界行/列全 0 是递推的锚，滚动时 $\mathrm{row}[n]$ 恒不写入即为 0。

7. **答案规模**：至多 $\binom{4999}{2} = 12497501$，`int` 足够，无需 `long long`。

**延伸思考**：
