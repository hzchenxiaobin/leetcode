# LeetCode 按下时间最长的按钮 题解

## 1. 题目概述

- **标题 / 题号**：按下时间最长的按钮（#3386，easy）
- **链接**：https://leetcode.cn/problems/button-with-longest-push-time/
- **来源**：LeetCode 第 428 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定按时间递增排序的按钮事件数组 `events`，每个 `events[i] = [index_i, time_i]` 表示在时刻 `time_i` 按下了下标为 `index_i` 的按钮。**一次按下的耗时**规定为：首次按下 = 其时间戳本身（相当于从时刻 0 起算）；之后每次按下 = 与上一次按下的时间差。返回**单次按下耗时最大**的按钮下标；若多个按钮并列，返回其中下标最小的。

**约束**：

- `1 <= events.length <= 1000`
- `events[i].length == 2`，即 `events[i] == [index_i, time_i]`
- `1 <= index_i, time_i <= 10^5`
- 输入保证 `events` 按时间 `time_i` 递增排序

## 2. 示例

**示例 1**

```text
输入：events = [[1,2],[2,5],[3,9],[1,15]]
输出：1
解释：按钮 1 首次按下耗时 2；按钮 2 耗时 5−2=3；按钮 3 耗时 9−5=4；
      按钮 1 再次按下耗时 15−9=6。
      单次按下耗时最大为 6，属于按钮 1，返回 1。
```

**示例 2**

```text
输入：events = [[10,5],[1,7]]
输出：10
解释：按钮 10 耗时 5；按钮 1 耗时 7−5=2。返回按钮 10。
```

## 3. 解题思路

### 3.1 朴素思路

签到题。题面已经把每次按下的耗时定义清楚，且 `events` 天然按时间有序，**按定义逐个计算耗时、维护最大值**的朴素模拟就是最优解：一次遍历，`O(n)`。不需要排序，更不需要哈希表去累加每个按钮的总耗时（见下文易错点）。

### 3.2 核心观察：相邻事件做差，一次遍历

![相邻事件做差求单次按下耗时](images/button_push_time_concept.svg)

1. **耗时只与相邻两个事件的 `time` 有关**：第 $i$ 次按下的耗时 $d_i = t_i - t_{i-1}$，首次按下 $d_0 = t_0$，与按的是哪个按钮无关。
2. **单次最大，不累加**：同一按钮被多次按下时，各次耗时不求和，只看**单次**最大值。示例 1 中按钮 1 两次按下耗时分别为 2 与 6，按 6 计（不是 2+6=8）。
3. **平局取下标最小**：并列时比较的是按钮 `index` 的**数值大小**，不是出现顺序。

### 3.3 算法流程：维护 (maxD, idx) 最优对

![平局时取下标最小的决策流程](images/button_push_time_tiebreak.svg)

1. 用 `events[0]` 初始化答案：`idx = events[0][0]`，`maxD = events[0][1]`。
2. 从 `i = 1` 起遍历：计算 `d = t_i - t_{i-1}`。
3. 若 `d > maxD`，或 `d == maxD` 且 `index_i < idx`，则更新 `idx = index_i`、`maxD = d`。
4. 遍历结束，返回 `idx`。

本质上是维护二元组 `(d, idx)` 的字典序最优：`d` 尽量大，`d` 相同时 `idx` 尽量小。

### 3.4 示例演算

![示例 1 的时间轴演算](images/button_push_time_walkthrough.svg)

示例 1 `events = [[1,2],[2,5],[3,9],[1,15]]`：

| 事件 | 时间戳 | 耗时 d | 当前 (maxD, idx) |
|------|--------|--------|------------------|
| `[1,2]` | 2 | 2（首次，= 时间戳） | (2, 1) |
| `[2,5]` | 5 | 5 − 2 = 3 | (3, 2) |
| `[3,9]` | 9 | 9 − 5 = 4 | (4, 3) |
| `[1,15]` | 15 | 15 − 9 = 6 | (6, 1) |

最终 `(maxD, idx) = (6, 1)`，返回 **1** ✓

## 4. 算法细节

1. **初始化**：直接用第一个事件初始化 `(idx, maxD)`，天然覆盖 `n == 1` 的情形，无需 `maxD = 0` 之类的哨兵。
2. **做差方向**：`events` 按时间递增，`d = t_i - t_{i-1}` 非负，无需特判。
3. **平局条件**：`d == maxD && index_i < idx`——遍历从左到右，只有"耗时并列且下标更小"才替换，保证平局取到下标最小的按钮。
4. **比较的量纲**：比较对象是 `(d, idx)` 二元组，按 `d` 降序、`idx` 升序取最优，与按下发生的先后次序无关。

## 5. 正确性证明

**引理 1**：每次按下的耗时由 $d_0 = t_0$ 与 $d_i = t_i - t_{i-1}\ (i \ge 1)$ 给出。

**证明**：题面规定：首次按下的耗时即其时间戳本身（等价于与时刻 0 做差）；此后每次按下的耗时是"连续两次按下的时间差"。逐条对应即得。∎

**定理**：算法返回单次按下耗时最大的按钮中，下标最小的那个。

**证明**：归纳维护不变量——遍历完前 $k$ 个事件后，`(maxD, idx)` 是前 $k$ 次按下中"单次耗时最大、平局取下标最小"的按钮。

- **基础**：$k = 1$ 时 `(maxD, idx) = (t_0, index_0)`，由引理 1 即前 1 次按下的最优，成立。
- **归纳**：设前 $k$ 个事件后不变量成立，考察第 $k+1$ 个事件（按钮 `index`，耗时 `d`）：
  - 若 `d > maxD`：该次耗时严格更大，更新后 `(d, index)` 成为新的最优，不变量保持；
  - 若 `d < maxD`：不更新，最优仍在前 $k$ 个事件中，不变量保持；
  - 若 `d == maxD`：最优耗时不变；若 `index < idx`，则出现并列中下标更小的按钮，替换后仍为并列最小下标；否则不变。不变量保持。

  三种情形均保持不变量。遍历结束时不变量即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n$ 为 `events` 的长度。一次遍历，每个事件仅做常数次比较与减法。
- **空间复杂度**：$O(1)$，只维护 `idx` 与 `maxD` 两个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int buttonWithLongestTime(vector<vector<int>>& events) {
        int idx = events[0][0], maxD = events[0][1];
        for (int i = 1; i < (int)events.size(); i++) {
            int d = events[i][1] - events[i - 1][1];
            if (d > maxD || (d == maxD && events[i][0] < idx)) {
                idx = events[i][0];
                maxD = d;
            }
        }
        return idx;
    }
};
```

### Python

```python
class Solution:
    def buttonWithLongestTime(self, events: List[List[int]]) -> int:
        idx, max_d = events[0]
        for (prev_i, prev_t), (cur_i, cur_t) in zip(events, events[1:]):
            d = cur_t - prev_t
            if d > max_d or (d == max_d and cur_i < idx):
                idx, max_d = cur_i, d
        return idx
```

## 8. 边界情况与易错点

1. **单次 vs 累加（本题最大的坑）**：同一按钮多次按下，耗时**不累加**。示例 1 中按钮 1 两次按下（耗时 2 与 6）按 6 计而非 8；若误用哈希表累加"每个按钮的总耗时"，在"某按钮多次小耗时之和超过别按钮单次大耗时"的用例上会判错。题面表述有歧义，以官方判定（单次最大）为准。
2. **平局取下标最小**：是比较按钮 `index` 的数值，不是最早出现的次序。如 `[[5,1],[3,2]]`：两次耗时均为 1，答案为 3。
3. **单事件**：`n == 1` 时答案即 `events[0][0]`；用第一个事件初始化即可覆盖，无需额外特判。
4. **首次按下的耗时**：是时间戳本身（相当于从时刻 0 起算），容易误写成 0 或漏掉首事件的比较。
5. **数据范围**：$n \le 1000$、$t_i \le 10^5$，差值与比较均在 `int` 范围内，无溢出风险。
