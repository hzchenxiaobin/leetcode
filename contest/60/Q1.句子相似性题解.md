# LeetCode 句子相似性 题解

## 1. 题目概述

- **标题 / 题号**：句子相似性（#734，easy）
- **链接**：https://leetcode.cn/problems/sentence-similarity/
- **来源**：LeetCode 第 60 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：给定两个句子 `words1`、`words2`（以单词数组表示）和一组相似词对 `pairs`，判断两个句子是否**相似**。相似需要同时满足两条：

1. 两个句子的**词数相同**；
2. 对每个下标 $i$，`words1[i]` 与 `words2[i]` 满足下列之一：两者相同；`(words1[i], words2[i])` 出现在 `pairs` 中；`(words2[i], words1[i])` 出现在 `pairs` 中。

这个相似关系**自反**（任何词与自己相似，不需要 `pairs` 里出现）、**对称**（$a \sim b \iff b \sim a$）、但**不传递**（$a \sim b$、$b \sim c$ 推不出 $a \sim c$）。

**约束**：

- 两个句子数组的长度都不超过 $1000$；长度不同时直接不相似
- $0 \le \lvert \text{pairs} \rvert \le 2000$，每个 `pairs[i]` 恰好含 2 个字符串
- 每个单词、每个词对中的字符串长度 $\in [1, 20]$，只含小写英文字母（本解法不依赖字母表，编码对任意字符都无歧义）
- 词对可以重复、可以自反（如 `["great", "great"]`），也可以完全与句子无关

## 2. 示例

**示例 1**

```text
输入：words1 = ["great","acting","skills"]
      words2 = ["fine","drama","talent"]
      pairs  = [["great","fine"],["drama","acting"],["skills","talent"]]
输出：true
解释：三个位置分别命中 great~fine、acting~drama（pairs 里写的是反向的
      ["drama","acting"]）、skills~talent，词数也相同。
```

**示例 2**

```text
输入：words1 = ["great"]，words2 = ["great"]，pairs = []
输出：true
解释：同一位置上的词完全相等，自身相似，与 pairs 是否为空无关。
```

**示例 3**

```text
输入：words1 = ["great"]，words2 = ["doubleplus","good"]，pairs = [["great","doubleplus"]]
输出：false
解释：词数 1 ≠ 2，句子不可能相似；长度门在第一步就把这种情况拒绝掉。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法：先比长度，再逐位判断「$a = b$ 或 `pairs` 中存在 `[a,b]` 或 `[b,a]`」——每次都在 `pairs` 里线性扫一遍。

时间是 $O(n \cdot m \cdot L)$：$n \le 1000$ 位、$m \le 2000$ 对、每次字符串比较至多 $L = 20$ 个字符，约 $4 \times 10^7$ 次字符比较。C++ 靠常数小还能过，Python 大概率超时；更糟的是**做法本身浪费**：同一对词可能被反复查询，而 `pairs` 在两次查询之间根本没变。

另一个常见误区是把 `pairs` 当成无向图做 BFS / 并查集，求「连通块」来判断相似。这会引入**题目明确否认的传递性**：`["great"]` 与 `["good"]` 在 `pairs = [["great","fine"],["fine","good"]]` 下会被误判为相似，而正确答案是 `false`。

### 3.2 核心观察：逐位独立 + 离线建池

![相似关系的三条性质](images/wc60_q1_relation_props.svg)

**观察 1（局部性）**：整句相似的定义本身就是「**每个位置**都相似」。第 $i$ 位相似与否只取决于 `words1[i]`、`words2[i]` 这一对词，与其它位置、与顺序都无关。所以整句判断可以拆成 $n$ 次互不影响的**独立查询**。

**观察 2（查询集合固定）**：每次查询的形式都是「有向词对 $(a,b)$ 是否直接相似」，而 $a,b$ 来自两个句子、`pairs` 在查询期间不变。这正好是「**离线预处理 + 在线查询**」的模板：把 `pairs` 一次性摊平成一个哈希集合，之后每次查询都是 $O(1)$ 期望时间。

**观察 3（对称性在插入时消化）**：由于相似是对称的，一条 `[a, b]` 等价于两条有向关系 $(a,b)$ 与 $(b,a)$。插入时就把两个方向都放进去，查询时就只需查**一个**方向——比「查询时分别查 $(a,b)$ 与 $(b,a)$」少一半哈希计算，代码也更短。

**观察 4（不做闭包）**：集合里只放 `pairs` 的字面内容，绝不做传递闭包。自反性通过「$a = b$ 直接跳过」单独处理，不占集合空间。

### 3.3 算法流程

![算法流程](images/wc60_q1_flow.svg)

1. 若 `len(words1) != len(words2)`，返回 `false`（示例 3）。
2. 建键池：对每个 `[a, b]`，把 $\mathrm{key}(a,b)$ 与 $\mathrm{key}(b,a)$ 都插入哈希集合。
3. 逐位比较：若 `words1[i] == words2[i]` 则跳过；否则查询 $\mathrm{key}(\text{words1}[i], \text{words2}[i])$ 是否在池中，不在就立即返回 `false`。
4. 所有位置都通过，返回 `true`。

**键的编码**：直接用字符串相等来判断词对，需要把「一对字符串」压成一个键。这里用**长度前缀**编码：

$$\mathrm{key}(a,b) = \mathrm{dec}(|a|) \,\Vert\, \# \,\Vert\, a \,\Vert\, b$$

其中 $\mathrm{dec}(|a|)$ 是 $|a|$ 的十进制表示，$\Vert$ 表示字符串拼接。解码方式唯一：读到 `#` 之前的数字就是 $|a|$，随后取恰好 $|a|$ 个字符得到 $a$，剩下的全部是 $b$。

为什么不直接拼成 `a + b`？因为 `("ab", "c")` 与 `("a", "bc")` 都会得到 `"abc"`，产生**假命中**。加长度前缀后两者分别编码为 `2#abc` 与 `1#abc`，不再混淆；而且不需要额外分隔符，即使单词里出现 `#` 也不会歧义。

### 3.4 示例演算

![示例 1 演算](images/wc60_q1_walkthrough.svg)

对示例 1，建池后池中恰好有 6 个键（每条 `pairs` 贡献两个方向）：

| 键 | 来源 | 键 | 来源 |
|---|---|---|---|
| `5#greatfine` | `["great","fine"]` 正向 | `4#finegreat` | 同一对反向 |
| `5#dramaacting` | `["drama","acting"]` 正向 | `6#actingdrama` | 同一对反向 |
| `6#skillstalent` | `["skills","talent"]` 正向 | `6#talentskills` | 同一对反向 |

逐位走查：

| $i$ | `words1[i]` | `words2[i]` | 相等？ | 查询键 | 在池中？ |
|---|---|---|---|---|---|
| 0 | `great` | `fine` | 否 | `5#greatfine` | 是 |
| 1 | `acting` | `drama` | 否 | `6#actingdrama` | 是（靠反向键） |
| 2 | `skills` | `talent` | 否 | `6#skillstalent` | 是 |

三位全部通过，返回 `true`。注意下标 1：`pairs` 里写的是 `["drama","acting"]`，若只存正向、或只查一个固定方向，就会漏掉它。

## 4. 算法细节

1. **先判长度，再建池**：长度不同时做任何键查询都没有意义，早退能省掉整个建池开销；更重要的是避免 Python `zip` 的静默截断。
2. **对称性放在插入阶段**：每对插两个键，查询只写一种方向。若两边都写「查两个方向」，逻辑正确但代码重复、哈希次数翻倍。
3. **编码函数只写一次**：把 `key(a, b)` 抽成局部函数（Python 里是闭包，C++ 里是 lambda），插入和查询共用，避免两处手写拼接导致不一致。
4. **提前返回**：任何一位不相似立刻 `false`，不必扫完整个句子；全部位通过才 `true`。
5. **哈希表容量**：键池最多 $2m = 4000$ 项，C++ 用 `reserve(2m + 1)` 一次性预留，避免多次 rehash；Python 的 `set` 无需手动处理。
6. **键长上界**：单词长度 $\le 20$，键长至多 $2 + 1 + 40 = 43$ 字节（长度前缀最多 2 位数字），构造与比较都很便宜。
7. **自反不占空间**：`a == b` 的情况在循环里直接 `continue`，不要往池里预插「每个词和自己」——那会需要遍历全部词，纯属浪费。
8. **重复词对与自反对**：集合天然去重，`[a,b]` 出现多次、或出现 `[a,a]`，插入的都是已存在的键，不影响答案。

## 5. 正确性证明

记 $P$ 为 `pairs` 给出的词对集合，定义
$$\mathrm{sim}(a,b) \iff a = b \ \lor\ (a,b) \in P \ \lor\ (b,a) \in P.$$

**引理 1（编码是单射）**：对任意字符串 $a,b,c,d$，若 $\mathrm{key}(a,b) = \mathrm{key}(c,d)$，则 $a = c$ 且 $b = d$。

**证明**：$\mathrm{key}$ 的第一段是 $|a|$ 的十进制表示，后接唯一的 `#`；由于十进制表示不含 `#`，从左向右读到第一个 `#` 就能唯一确定 $|a|$，从而确定 $a$ 的长度。断言后取恰好 $|a|$ 个字符，得到唯一的 $a$；剩余后缀唯一的 $b$。于是 $\mathrm{key}$ 的像可以唯一还原 $(a,b)$，映射是单射。∎

**引理 2（池成员判定精确）**：建池完成后，对任意词对 $(a,b)$，有
$$\mathrm{key}(a,b) \in \mathrm{Pool} \iff (a,b) \in P \ \lor\ (b,a) \in P.$$

**证明**：建池时对每条 $[x,y] \in P$ 插入 $\mathrm{key}(x,y)$ 与 $\mathrm{key}(y,x)$，故
$$\mathrm{Pool} = \{\mathrm{key}(x,y) : (x,y) \in P\} \cup \{\mathrm{key}(y,x) : (x,y) \in P\} = \{\mathrm{key}(x,y) : (x,y) \in P \lor (y,x) \in P\}.$$

- ($\Leftarrow$) 若 $(a,b) \in P$ 或 $(b,a) \in P$，取 $(x,y) = (a,b)$ 或 $(b,a)$ 即知 $\mathrm{key}(a,b)$ 被插入。
- ($\Rightarrow$) 若 $\mathrm{key}(a,b) \in \mathrm{Pool}$，则存在 $(x,y)$ 使 $(x,y) \in P$ 或 $(y,x) \in P$，且 $\mathrm{key}(x,y) = \mathrm{key}(a,b)$；由引理 1 得 $(x,y) = (a,b)$，代回即得 $(a,b) \in P$ 或 $(b,a) \in P$。∎

**引理 3（局部性）**：两个句子相似 $\iff$ 词数相同且对每个 $i$ 有 $\mathrm{sim}(\text{words1}[i], \text{words2}[i])$。

**证明**：这正是题面给出的相似定义，逐条对照即可。∎

**定理**：算法返回 `true` $\iff$ 两个句子相似。

**证明**：

- 若词数不同：由定义两句不相似，算法在第 1 步返回 `false`，一致。
- 若词数相同：算法返回 `true` $\iff$ 每个位置都满足「$a = b$ 或 $\mathrm{key}(a,b) \in \mathrm{Pool}$」。由引理 2，后者等价于 $(a,b) \in P \lor (b,a) \in P$；结合 $a=b$ 即 $\mathrm{sim}(a,b)$。于是「所有位置都通过」$\iff$ 所有位置满足 $\mathrm{sim}$，由引理 3 等价于两句相似。∎

## 6. 复杂度分析

- **时间**：建池 $O(m \cdot L)$——每条词对构造两个键，每个键长度 $O(L)$；逐位检查 $O(n \cdot L)$，每次至多构造一个键并做一次期望 $O(1)$ 的哈希查找（哈希本身要扫键的 $O(L)$ 字节）。总时间 $O\bigl((n + m) \cdot L\bigr)$，期望意义下成立。
- **空间**：键池 $O(m \cdot L)$——至多 $2m$ 个键，每个键至多 $2L + 3$ 字节，$m = 2000$、$L = 20$ 时不超过约 170 KB；此外只用了若干常数变量。相对于输入规模，额外空间是 $O(mL)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_set>
using namespace std;

class Solution {
public:
    bool areSentencesSimilar(vector<string>& sentence1, vector<string>& sentence2,
                             vector<vector<string>>& similarPairs) {
        if (sentence1.size() != sentence2.size()) return false;   // 词数必须相同

        auto key = [](const string& a, const string& b) {
            return to_string(a.size()) + '#' + a + b;             // 长度前缀编码，单射
        };

        unordered_set<string> pool;
        pool.reserve(similarPairs.size() * 2 + 1);
        for (auto& p : similarPairs) {
            pool.insert(key(p[0], p[1]));                         // a ~ b
            pool.insert(key(p[1], p[0]));                         // 对称：b ~ a
        }

        for (size_t i = 0; i < sentence1.size(); i++) {
            if (sentence1[i] == sentence2[i]) continue;           // 自身相似
            if (pool.find(key(sentence1[i], sentence2[i])) == pool.end()) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def areSentencesSimilar(self, sentence1, sentence2, similarPairs):
        if len(sentence1) != len(sentence2):        # 词数必须相同
            return False

        def key(a, b):
            # 长度前缀编码：单射，且不需要额外分隔符
            return f"{len(a)}#{a}{b}"

        # 对称闭包在插入时完成：一条 [a, b] 同时给出 a~b 与 b~a
        pool = set()
        for a, b in similarPairs:
            pool.add(key(a, b))
            pool.add(key(b, a))

        for a, b in zip(sentence1, sentence2):
            if a != b and key(a, b) not in pool:
                return False                       # 有一位不相似，整句不相似
        return True
```

## 8. 边界情况与易错点

1. **词数不同**（示例 3）：必须第一步就拒绝。Python 直接写 `zip(sentence1, sentence2)` 会**静默截断**到较短的一方，漏掉长度检查就会把 `["great"]` 与 `["doubleplus","good"]` 误判为 `true`。
2. **空句子**：两边都是空数组时词数相同（都为 0），循环体不执行，返回 `true`，与「逐位条件全满足」的定义一致；一边空一边非空则被长度门拦下。
3. **单词完全相等**：如示例 2，`pairs` 为空也必须返回 `true`。判等要放在查表之前（或作为 `sim` 的一个分支），不能只依赖 `pairs`。
4. **反向词对**：`pairs` 里写 `["drama","acting"]` 而句子是 `acting` 对 `drama`（示例 1 下标 1）。只存正向、或查询时漏查 `(b,a)` 都会 WA——本题最典型的失分点。
5. **传递性陷阱**：在 `pairs = [["great","fine"],["fine","good"]]` 下，`["great"]` 与 `["good"]` 的答案是 `false`。用并查集 / BFS 求连通块会得到 `true`，把简单题做成错题。
6. **裸拼接产生假命中**：`("ab","c")` 与 `("a","bc")` 裸拼都是 `"abc"`。这类碰撞不会报错，只会在特定数据上悄悄返回错误的 `true`；用长度前缀或不可能出现的分隔符规避。
7. **键的构造要一致**：插入用 `len(a)+'#'+a+b`、查询写成 `a+'#'+b` 之类的不一致，是极难发现的 bug；务必抽成同一个函数。
8. **哈希表退化**：极端数据下 `unordered_set` 可能退化到 $O(m)$ 查找，但总键数只有 4000，实际影响可以忽略；若追求严格上界可换 `map`，代价是 $O(\log m)$。
