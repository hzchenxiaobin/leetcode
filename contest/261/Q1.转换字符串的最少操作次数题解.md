# LeetCode 转换字符串的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：转换字符串的最少操作次数（#2027，easy）
- **链接**：https://leetcode.cn/problems/minimum-moves-to-convert-string/
- **来源**：LeetCode 第 261 场周赛 Q1
- **难度**：简单
- **标签**：贪心、字符串、区间覆盖

**题意**：给定长度为 $n$ 的字符串 `s`，每个字符是 `'X'` 或 `'O'`。一次**操作**：从 `s` 中选出**三个连续字符**，将选中的每个字符都转换为 `'O'`（已是 `'O'` 的保持不变）。返回把所有字符都变成 `'O'` 的**最少操作次数**。

**约束**：

- $3 \le \text{s.length} \le 1000$
- `s[i]` 为 `'X'` 或 `'O'`

> 💡 **审题关键**：① 窗口里已是 `'O'` 的字符「保持不变」→ **窗口可以包含 O**，被一窗带走的 X 不必连续成段；② 求最少次数 → 本质是「用最少的长度 3 区间覆盖所有 X 的位置」；③ $n \ge 3$ 保证末尾的 X 永远有合法窗口可放（大不了钳制到 $[n-3, n-1]$）。

## 2. 示例

**示例 1**

```text
输入：s = "XXX"
输出：1
解释：XXX -> OOO。一次操作选中全部 3 个字符。
```

**示例 2**

```text
输入：s = "XXOX"
输出：2
解释：XXOX -> OOOX -> OOOO。
第一步选前 3 个字符 [0,2]；末尾的 X 只能靠 [1,3] 盖住（窗口右端越界，需钳制）。
```

**示例 3**

```text
输入：s = "OOOO"
输出：0
解释：s 中不存在需要转换的 'X'。
```

**示例 4（自造，检验"窗口可跨 O"与右端钳制）**

```text
输入：s = "OXOXOXO"
输出：2
解释：X 在 1、3、5：窗口 [1,3] 一窗带走前两个（中间隔着的 O 不碍事）；
      窗口 [4,6] 盖住 5 号 X。1 与 5 相距 4 ≥ 3，一窗盖不住两者 → 2 次是下限。
```

## 3. 解题思路

### 3.1 暴力思路

先盘朴素路线：

1. **操作序列搜索**：每次操作有 $n-2$ 个起点可选，BFS/DFS 搜"全 O"状态。状态是"哪些位置已变 O"，最坏 $2^n$ 种（$n \le 1000$），直接爆炸；且操作只会 X→O（单向单调），搜索毫无剪枝收益。
2. **逐 X 开窗、逐格前进**：从左到右，每见一个 X 就开一次窗，然后只前进 1 格。可行但**不最优**：`"XXXX"` 会给 4，而正确答案是 2（一窗顺带盖掉右侧 2 格）。错在没利用"一次操作能带走整个窗口"。
3. **区间覆盖 DP**：形式化为覆盖问题后，令 $dp[i]$ 为修好后缀 $s[i..]$ 的最少操作，转移为 $dp[i] = dp[i+1]$（`s[i]='O'`）或 $1 + \min(dp[i{+}1], dp[i{+}2], dp[i{+}3])$（`s[i]='X'`，覆盖它的窗口右端 $\in \{i, i+1, i+2\}$），$O(n)$ 正确——但把转移想透的那一刻就会发现它塌缩成贪心（见 §4 第 4 点）。

签到题的最短路径是路线 2 修一修：**见 X 开窗没错，错在开完窗只走 1 格——应该跳 3 格**。

### 3.2 核心观察：最左 X 开窗 + 跳 3

![核心概念：最左未覆盖 X 从它开窗，窗口可跨 O，跳 3 格](images/wc261_q1_cover_concept.svg)

从左到右扫描，维护下标 $i$，三个观察把代码压到最短：

1. **最左未覆盖 X 是硬需求**：扫到 `s[i] == 'X'` 时，$i$ 左侧全是 O（或已被之前的窗口盖住）——它是当前**最左的未覆盖 X**，某个操作窗口**必须**罩住它，躲不掉。
2. **窗口从它开 = 右缘最远**：罩住 $i$ 的窗口起点 $j \in [i-2, i]$。$j < i$ 时窗口左侧盖的是"已搞定的位置"，纯浪费；取 $j = i$（窗口 $[i, i+2]$）右缘最远，顺带消灭右侧最多 2 个 X。**交换论证**：把最优解里那个偏左的窗口换成 $[i, i+2]$，覆盖不减、操作数不增（§5 有严格版）。
3. **窗口可跨 O（审题！）**：O「保持不变」意味着窗口内混 O 完全合法——不必对齐什么"X 段"，从最左 X 直接开窗即可，`X@4` 和 `X@6` 中间隔个 O 也能一窗带走。
4. **跳 3**：窗口 $[i, i+2]$ 盖住三格，$i+1$、$i+2$ 无需再看，从 $i+3$ 起重新找最左未覆盖 X。

> 💡 **范式提炼**：「固定长度区间覆盖一维点集」通用解 = **从最左未覆盖点开区间、跳 $L$ 格**。区间长度可变的版本（1024 视频拼接、1326 灌溉花园）在此之上多一步"选右端最远"。

### 3.3 算法流程

![算法流程：一趟扫描，遇 X 开窗跳 3，遇 O 前进 1](images/wc261_q1_greedy_flow.svg)

1. 初始化 `i = 0`、`ans = 0`；
2. 循环（$i < n$）：
   - 若 `s[i] == 'X'`：`ans += 1`，`i += 3`（窗口 $[i, i+2]$ 三格一并搞定）；
   - 否则：`i += 1`（O 无需操作）；
3. 返回 `ans`。

### 3.4 示例演算

![示例演算：XXOX 的右端钳制、XXX 单窗、OOOO 零操作](images/wc261_q1_walkthrough.svg)

以示例 2 `s = "XXOX"` 演算（重点看第二步的右端钳制）：

| 步骤 | $i$ | `s[i]` | 动作 | `ans` | 下一 $i$ |
|------|-----|--------|------|-------|---------|
| ① | 0 | `X` | 开窗 $[0,2]$，整段跳过 | 1 | 3 |
| ② | 3 | `X` | 开窗：理想 $[3,5]$ 越界 → 钳制 $[1,3]$ | 2 | 6 ≥ n，结束 |

串的演变：`XXOX → OOOX → OOOO`，返回 2 ✓。示例 1（`XXX` 单窗收工，1 次）与示例 3（`OOOO` 全程无 X，0 次）见上图；自造示例 4 `OXOXOXO` 把"跨 O 一窗双杀"与"钳制"串进一条轨迹：$i=1$ 开窗 $[1,3]$ 跳到 4，$i=4$ 为 O 前进，$i=5$ 开窗（钳制为 $[4,6]$），得 2。

## 4. 算法细节

1. **只动下标，不动字符串**：`i += 3` 已隐含"$i$、$i+1$、$i+2$ 三格被本次操作盖住"，无需真把 X 改成 O 再扫。Python 字符串不可变，真要模拟还得 `list(s)` 拷贝——跳格写法 $O(1)$ 空间，最干净。
2. **右边界钳制，但计数免特判**：最左未覆盖 X 落在 $i > n-3$（倒数两格）时，窗口 $[i, i+2]$ 越界不存在，实际窗口是 $[n-3, n-1]$——由 $i \ge n-2$ 知它必然罩住 $i$ 且盖到串尾，一次操作收尾。`i += 3` 后越界自然退出循环，`ans` 不多不少。**贪心统计的是"要几次"，不是"窗口精确落在哪"**。
3. **领袖（leader）视角**：贪心计数的位置恰是那些"距上一个开窗点 ≥ 3"的 X（§5 引理 1）。每开一窗，最多顺带带走窗口内另外 2 个 X；下一个必须开窗的位置必然在 3 格之外——这正是下界的来源。
4. **贪心 = DP 的退化形态**：$dp[i] = 1 + \min(dp[i{+}1], dp[i{+}2], dp[i{+}3])$，而点集变小操作数不增（$dp$ 关于下标单调不增），$\min$ 必取在 $dp[i+3]$——转移塌缩成 $dp[i] = 1 + dp[i+3]$，正是跳 3 贪心。
5. **两个错误变体对照**：① 开窗后 `i += 1`：`"XXXX"` → 4 ✗（正确 2）；② 按连续 X 段分别算 $\lceil$段长$/3\rceil$：`"XOX"` → 2 ✗（正确 1，一窗 $[0,2]$ 双杀）——窗口盖的是**位置**，不是 X 段。

## 5. 正确性证明

设 X 的位置为 $x_1 < x_2 < \dots < x_k$（$k = 0$ 时答案为 0，显然）。定义**领袖** $\ell_1 < \ell_2 < \dots < \ell_m$：$\ell_1 = x_1$，$\ell_{t+1} = \min\{\, x_j : x_j \ge \ell_t + 3 \,\}$（该集合为空则终止）。

**引理 1（贪心 = 数领袖）**：贪心循环中执行 `ans += 1` 的位置恰为 $\ell_1, \dots, \ell_m$，故输出为 $m$。

**证明**：对开窗次数归纳。首次遇到 X 的位置是全串最左 X，即 $\ell_1$。设在某 $\ell_t$ 开窗，则下一步从 $\ell_t + 3$ 起扫描，其后遇到的**首个** X 位置即 $\min\{x_j : x_j \ge \ell_t + 3\} = \ell_{t+1}$；若该集合为空，则扫描至 $n$ 结束，不再开窗。∎

**引理 2（下界）**：任何可行解的操作数 $\ge m$。

**证明**：由定义 $\ell_{t+1} \ge \ell_t + 3$，传递可得任意两领袖间距 $\ge 3$。一个操作窗口是 3 个连续位置，其中任意两位置之差 $\le 2 < 3$，故**一个窗口至多覆盖一个领袖**。每个领袖都是 X、都必须被某次操作覆盖，而不同领袖不能共享窗口，故至少需要 $m$ 次操作。∎

**引理 3（上界）**：$m$ 个窗口足以覆盖所有 X。

**证明**：第 $t$ 个窗口取 $W_t = [\ell_t, \ell_t + 2]$；若 $\ell_m + 2 > n - 1$（末领袖落在倒数两格），末窗钳制为 $[n-3, n-1]$。注意对 $t < m$ 有 $\ell_{t+1} \le n - 1$ 且 $\ell_{t+1} \ge \ell_t + 3$，故 $\ell_t + 2 \le n - 2$，中间各窗均合法。任取 X 位置 $x$：

- **$x \ge \ell_m$**：若 $x \ge \ell_m + 3$，则 $x$ 会成为下一个领袖，与 $\ell_m$ 的极大性矛盾，故 $x \le \ell_m + 2$。当 $\ell_m \le n-3$ 时 $x \in W_m$；当 $\ell_m > n-3$ 时 $\ell_m \ge n-2$，钳制窗 $[n-3, n-1] \supseteq [\ell_m, n-1] \ni x$。
- **$\ell_t \le x < \ell_{t+1}$（某 $t < m$）**：$\ell_{t+1}$ 是首个位置 $\ge \ell_t + 3$ 的 X，而 $x$ 是 X 且 $x < \ell_{t+1}$，故必有 $x < \ell_t + 3$ 即 $x \le \ell_t + 2$，被 $W_t$ 覆盖。

所有 X 均被覆盖，$m$ 次操作构成可行解。∎

**定理**：贪心输出 $m$ 即最少操作数。

**证明**：由引理 3，$f(s) \le m$；由引理 2，$f(s) \ge m$；故 $f(s) = m$，而由引理 1 贪心恰输出 $m$。∎

> 💡 **另一视角（交换论证）**：最优解中覆盖最左未覆盖 X（位置 $i$）的窗口若起点 $j < i$，将 $[j, j+2]$ 换成 $[i, i+2]$：$[j, i-1]$ 内没有未覆盖的 X（左侧干净），右侧覆盖范围不减（$i + 2 \ge j + 2$）——替换后仍可行且操作数不变。逐次交换可知，存在与贪心完全一致的最优解。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每轮循环 $i$ 至少 +1（遇 O）、至多 +3（遇 X 开窗），总轮数 $\le n$，每轮 $O(1)$；$n \le 1000$，运算量千级。
- **空间复杂度**：$O(1)$。仅 `i`、`ans`、`n` 三个变量，不修改原串（对比真模拟改串的写法需 $O(n)$ 额外空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumMoves(string s) {
        int n = s.size(), ans = 0;
        for (int i = 0; i < n; ) {
            if (s[i] == 'X') {   // 最左未覆盖 X：从它开窗 [i, i+2]
                ++ans;
                i += 3;          // 三格一并搞定，从 i+3 重新找最左 X
            } else {
                ++i;             // O 无需操作
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumMoves(self, s: str) -> int:
        ans, i, n = 0, 0, len(s)
        while i < n:
            if s[i] == 'X':
                ans += 1
                i += 3           # 窗口 [i, i+2] 整段跳过
            else:
                i += 1
        return ans
```

### Python 备选：直观模拟版

```python
class Solution:
    def minimumMoves(self, s: str) -> int:
        a = list(s)
        ans = 0
        for i in range(len(a)):
            if a[i] == 'X':                       # 最左未覆盖 X：开窗并就地改 O
                ans += 1
                for j in range(i, min(i + 3, len(a))):
                    a[j] = 'O'
        return ans
```

> ⚠️ 备选版把"覆盖"显式写成改 `'O'`，窗口被 `min(i+3, n)` 自然截断（右端钳制的直白体现）；与跳格版逐位等价，但多用 $O(n)$ 空间。比赛时两者皆可，跳格版更短。

## 8. 边界情况与易错点

1. **右端越界（头号坑）**：最左未覆盖 X 在 $i > n-3$ 时窗口 $[i, i+2]$ 不存在，实际钳制为 $[n-3, n-1]$（示例 2 第二步：`s="XXOX"`、$i=3$）。**计数不受影响**——`i += 3` 越界退出即可，别为此写特判，更别把答案算多。
2. **跳 3 不是跳 1**：开窗后必须跳过整个窗口。逐格推进得到的是可行但非最优解（`"XXXX"` → 4，正确 2）。
3. **窗口可跨 O**：别按"连续 X 段"分段算 $\lceil$段长$/3\rceil$——`"XOX"` 一窗 $[0,2]$ 搞定，分段法误给 2。窗口覆盖的是**位置**，不是 X 段。
4. **全 O 串**：答案 0（示例 3），循环自然返回，无需特判。
5. **最小规模 $n = 3$**：单窗全覆盖（示例 1）；同时保证钳制窗 $[n-3, n-1] = [0, 2]$ 恒合法。
6. **别真去改字符串**：`i += 3` 已隐含覆盖信息；Python 里 `list(s)` 拷贝纯属多余（除非写模拟版）。
7. **读题别脑补**："选出三个连续字符" ≠ "三个连续的 X"；已是 O 的字符允许被重复选中且保持不变。
8. **规模与溢出**：$n \le 1000$，$ans \le \lceil 1000/3 \rceil = 334$，`int` 绰绰有余。
