# LeetCode 在长度 2N 的数组中找出重复 N 次的元素 题解

## 1. 题目概述

- **标题 / 题号**：在长度 2N 的数组中找出重复 N 次的元素（#961，easy）
- **链接**：https://leetcode.cn/problems/n-repeated-element-in-size-2n-array/
- **来源**：LeetCode 第 116 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、抽屉原理

**题意**：给定长度为 $2n$ 的整数数组 `nums`，它满足：

- `nums` 共有 $n+1$ 个**不同**的值；
- 其中 $n$ 个值各出现**恰好一次**；
- 恰有**一个**值出现 $n$ 次。

找出并返回这个出现了 $n$ 次的值。注意题面里的 $n$ 指的是**数组长度的一半**，不是数组长度。

**约束**：

- $2 \le n \le 5000$，故 $nums.length = 2n \le 10^4$
- $0 \le nums[i] \le 10^4$
- 输入保证符合上述结构

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,3]
输出：3
解释：n = 2，数组有 3 个不同的值 {1,2,3}，其中 1、2 各出现一次，3 出现两次 = n 次。
```

**示例 2**

```text
输入：nums = [2,1,2,5,3,2]
输出：2
解释：n = 3，不同值 {1,2,3,5}，2 出现 3 次。
```

**示例 3**

```text
输入：nums = [5,1,5,2,5,3,5,4]
输出：5
解释：n = 4，5 出现 4 次，其余各一次。
```

## 3. 解题思路

### 3.1 暴力思路

两种朴素做法：

1. **双重循环计数**：对每个 `nums[i]` 再扫一遍数组统计出现次数，第一个计数等于 $n$ 的即为答案。时间 $O(n^2) = O((2n)^2)$，$n = 5000$ 时约 $10^8$ 次比较，Python 必然超时；
2. **排序后看相邻**：排序后相同元素聚在一起，出现 $n \ge 2$ 次的相邻对就是答案。时间 $O(n\log n)$，虽然能过，但多做了一次完全不必要的排序。

两种做法都没有利用题面给出的**强结构**：只有一个值会重复。

### 3.2 核心观察：只有一个值会重复，第一次"撞车"就是答案

![结构：n 个值各一次 + 1 个值 n 次，只有它会被第二次遇到](images/wc116_q1_structure.svg)

由题设：

- 除了那个出现 $n$ 次的值 $x$，其余 $n$ 个值**都只出现一次**；
- 所以从左到右扫描时，**任何**元素被第二次遇到，它只能是 $x$（别的值根本不会出现第二次）。

于是算法极其简单：

> 维护一个"见过的值"集合。顺序扫描 `nums`，若当前值已在集合中，立即返回它；否则加入集合。

![算法流程：顺序扫描 + 哈希集合检测首次重复](images/wc116_q1_flow.svg)

值域只有 $[0, 10^4]$，甚至可以用一个 `bool[10001]` 的标记数组代替哈希集合，常数更小。

### 3.3 算法流程

```text
1. seen = 空集合
2. for v in nums:
       若 v 已在 seen 中:  return v        // 唯一的重复值，必是答案
       seen.add(v)
3. （题面保证有解，不会走到这里）
```

### 3.4 示例演算

![示例 2 的扫描过程：[2,1,2,5,3,2]](images/wc116_q1_walkthrough.svg)

对示例 2 的 `nums = [2,1,2,5,3,2]`：

| 下标 | 值 | 扫描前 seen | 是否已存在 | 动作 |
|------|----|-------------|------------|------|
| 0 | 2 | {} | 否 | 加入，seen = {2} |
| 1 | 1 | {2} | 否 | 加入，seen = {1,2} |
| 2 | **2** | {1,2} | **是** | 返回 2 ✓ |
| 3 | 5 | — | — | 不再执行 |

示例 1 的 `[1,2,3,3]` 同理：前三个值 1、2、3 依次入集合，下标 3 的 3 撞车，返回 3。

## 4. 算法细节

1. **集合 vs 计数表**：本题只需判断"是否出现过"，用集合（或 `bool` 数组）即可，不需要完整计数。
2. **值域很小**：$0 \le nums[i] \le 10^4$，用 `bool seen[10001]` 标记数组比 `unordered_set` 更快，也没有哈希开销。
3. **提前返回**：一旦撞车立即返回，平均只需扫描到答案的第二次出现，最坏 $O(2n)$。
4. **下标无关**：答案可能出现在任何位置（开头、结尾、中间），算法不依赖位置假设。
5. **不要用"出现次数最多"来猜**：虽然答案确实出现次数最多，但统计全部频次要多扫一遍，直接检测重复就够。
6. **不要用 Boyer-Moore 多数投票**：答案恰好占一半（不是严格多数），投票法的候选者可能被"抵消"成错误的值（例如 `[1,1,2,3]` 会得到 3）。
7. **返回值类型**：答案一定存在，函数末尾可以不写返回值（C++ 需返回一个占位值以消除警告）。
8. **$n$ 的含义**：$n = nums.length / 2$；题面的"重复 $n$ 次"就是"重复一半的次数"。

## 5. 正确性证明

**引理 1（唯一重复值）**：设出现 $n$ 次的那个值为 $x$，则对任意 $y \ne x$，$y$ 在 `nums` 中恰好出现一次。

**证明**：由题设，除 $x$ 外还有 $n$ 个不同的值，它们各出现恰好一次（$n$ 个值合计 $n$ 个位置，加上 $x$ 的 $n$ 个位置正好 $2n$）。故 $y$ 只出现一次。∎

**引理 2（首次撞车检测正确）**：算法返回的值等于 $x$。

**证明**：设扫描到下标 $k$ 时首次发现 `nums[k]` 已存在于 `seen` 中，即存在 $k' < k$ 使 $nums[k'] = nums[k]$。于是 `nums[k]` 出现了至少两次，由引理 1 它不能是 $x$ 以外的值，故 `nums[k] = x`。

还需说明算法一定会返回：$x$ 出现 $n \ge 2$ 次，设其前两次出现的下标为 $k_1 < k_2$。扫描到 $k_2$ 时，$x$ 已在 $k_1$ 处加入 `seen`，于是发生撞车；在此之前不可能撞车（否则返回的也是 $x$，因为只有 $x$ 重复）。故算法必然返回 $x$。∎

**定理**：算法返回数组中重复 $n$ 次的那个元素。

**证明**：由引理 2 直接得到。∎

## 6. 复杂度分析

- **时间**：$O(n)$（这里 $n$ 指数组长度 $2n$ 的量级）。每个元素做一次集合查询与一次插入，最坏扫描整个数组；哈希集合摊还 $O(1)$，`bool` 数组严格 $O(1)$。总计 $O(nums.length)$。
- **空间**：$O(\min(nums.length, 10^4+1))$。集合最多存 $n+1$ 个值；标记数组固定 $10^4+1$ 个布尔位。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>

using namespace std;

class Solution {
public:
    int repeatedNTimes(vector<int>& nums) {
        unordered_set<int> seen;
        for (int v : nums) {
            if (seen.count(v)) return v;   // 唯一的重复值，必是答案
            seen.insert(v);
        }
        return -1;                         // 题面保证有解，不会到达
    }
};
```

### Python

```python
class Solution:
    def repeatedNTimes(self, nums: list[int]) -> int:
        seen = set()
        for v in nums:
            if v in seen:                  # 唯一的重复值，必是答案
                return v
            seen.add(v)
        return -1                          # 题面保证有解，不会到达
```

## 8. 边界情况与易错点

1. **$n = 2$**：数组只有 4 个元素，如 `[1,2,3,3]`，答案可能出现两次且位置任意；算法与位置无关，天然正确。
2. **答案的两次出现相距很远**：如 `[3,1,2,3]`，第二次出现在末尾才撞车，算法仍能返回 3，只是要多扫几步。
3. **相等的元素相邻**：如 `[5,1,5,2,5,3,5,4]` 中 5 分散出现，`[9,9,1,2]` 中相邻出现，两种都能被"已存在"判断覆盖。
4. **值可以为 0**：标记数组的下标 $0$ 合法，不要用"0 表示未访问"的哨兵写法（会漏掉值为 0 的答案）。
5. **不要用排序**：$O(n\log n)$ 能过但不是最优，且会破坏"边扫边判"的简洁性。
6. **不要用多数投票**：答案恰好占一半而非严格多数，Boyer-Moore 可能返回别的值。
7. **不要假设答案在某个固定区间**：题目只保证结构，不保证位置。
8. **`n` 不要与数组长度混淆**：判断条件是"出现次数等于长度的一半"，代码里根本不需要显式用 $n$。

**延伸思考**：本题还有一类"$O(1)$ 空间"的巧解，依赖如下观察：设答案出现 $n$ 次，其余 $n$ 个位置是互不相同的其它值。若相邻两次出现（按出现位置排序）的间隔都 $\ge 3$，则 $n$ 次出现至少要跨 $3(n-1)+1$ 个位置，而当 $n \ge 3$ 时 $3n-2 > 2n$，矛盾。因此 $n \ge 3$ 时必定存在一对相隔 1 或 2 的答案，只需比较 `nums[i]` 与 `nums[i+1]`、`nums[i+2]` 即可。**但当 $n = 2$ 时该结论失效**（`[3,1,2,3]` 的两次出现相隔 3），必须补上"距离 3"的比较，这也是很多人写 $O(1)$ 空间版本却在 `[3,1,2,3]` 上 WA 的原因。
