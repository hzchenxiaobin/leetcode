# LeetCode K 次增加后的最大乘积 题解

## 1. 题目概述

- **标题 / 题号**：K 次增加后的最大乘积（#2233，medium）
- **链接**：https://leetcode.cn/problems/maximum-product-after-k-increments/
- **来源**：LeetCode 第 288 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）

**题意**：给定非负整数数组 `nums` 和整数 `k`。每次操作可以任选 `nums` 中**一个**元素并 **+1**，问**至多** $k$ 次操作后能得到的**最大乘积**。答案对 $10^9 + 7$ 取模后返回。

**约束**：

- $1 \le \text{nums.length},\ k \le 10^5$
- $0 \le \text{nums}[i] \le 10^6$

> 💡 **题眼**：乘积是「连乘」结构——给某个元素 $a$ 一次 +1，整体乘积放大为 $P \cdot \frac{a+1}{a}$，**相对增益只取决于被加元素自身的大小**，且越小增益越大。这指向贪心：**每次 +1 都给当前最小值**。本题是周赛里典型的「三行结论 + 一份严谨证明」型中等题：结论好猜（堆模板 5 分钟写完），但「为什么逐次给最小值全局最优」并不显然——增益会随元素被抬升而衰减，纯局部比较不足以构成证明，需要交换论证兜底（见第 5 节）。

> 💡 本题在本仓库另有[每日题解 2233](../../solution/2201-2300/2233_K次增加后的最大乘积.md)：主线同为最小堆贪心，附面试问答与 $k$ 极大时「水位填充」$O(n\log n)$ 批量优化。本篇按**周赛复盘视角**展开，补齐「花光不亏 → 单步交换不等式 → 序列交换 → 多重集确定性」的完整引理-定理证明链与赛场易错清单。

## 2. 示例

**示例 1**

```text
输入：nums = [0,4], k = 5
输出：20
解释：将第一个数 +1 五次 → [5, 4]，乘积 5 × 4 = 20。
```

**示例 2**

```text
输入：nums = [6,3,3,2], k = 2
输出：216
解释：第二个数 +1、第四个数 +1 → [6, 4, 3, 3]，乘积 6 × 4 × 3 × 3 = 216。
```

**补充示例 3（0 不够分）**

```text
输入：nums = [0,0,0], k = 2
输出：0
解释：两个 +1 无论怎么分（[1,1,0] 或 [2,0,0]），总有元素保持 0，
      乘积仍为 0。0 的个数超过 k 时答案必为 0，无需特判。
```

**补充示例 4（增量别一股脑砸给初始最小值）**

```text
输入：nums = [10,4,4], k = 3
输出：300
解释：贪心逐次给当前最小 → [5,6,10]，乘积 300；
      若把 3 次 +1 全砸给同一个初始最小值 4 → [10,7,4]，只有 280。
```

> ⚠️ 示例 4 说明：**「最小值」是动态的**——每抬一次，最小值可能换成别的元素。一次性把 $k$ 全押给初始最小值（排序后无脑加给 `nums[0]`）会错过更均衡的分配，这是本题最常见的错误贪心。

## 3. 解题思路

### 3.1 暴力思路

朴素做法是枚举「把 $k$ 个不可区分的 +1 分给 $n$ 个元素」的所有方案，方案数是组合数 $\binom{k+n-1}{n-1}$，$n, k \le 10^5$ 时是天文数字。

退一步考虑 DP：设 $f[i][j]$ 为把 $j$ 次增量分给前 $i$ 个元素的最大乘积，转移 $f[i][j] = \max_c f[i-1][j-c] \cdot (a_i + c)$。两层死因：

- **状态数** $n \times k = 10^{10}$，直接超时；
- **取模破坏比较**：DP 需要比较候选乘积的大小，而真值乘积可达 $10^{6 \times 10^5}$ 位数（大数算术），取模后又失去序关系——最大值既不能存真值也不能存模值。

两条路都死，必须寻找「每一步局部最优即全局最优」的结构。

### 3.2 核心观察：一次 +1 给谁——边际增益递减

设当前乘积 $P = \prod_i a_i$，给元素 $a_i$ 一次 +1，新乘积

$$P' = P \cdot \frac{a_i + 1}{a_i} = P \cdot \left(1 + \frac{1}{a_i}\right)$$

**关键洞察**：增益系数 $1 + \frac{1}{a_i}$ 只依赖被加元素自身的值，且**严格递减**：

- $a_i = 2$：增益 $\frac{3}{2} = 1.5$；
- $a_i = 6$：增益 $\frac{7}{6} \approx 1.17$；
- $a_i = 0$：乘积当前为 $0$，加 1 使乘积**从 0 变正**——增益可视作无穷大，**必须最先消除 0**。

于是每一步的局部最优选择都是「当前最小值」。这一直觉也有一个漂亮的**面积模型**：比较 $(a+1) \cdot b$ 与 $a \cdot (b+1)$（$a \le b$），差恰为 $b - a$——同样的 1 单位增量，贴在矩形的短边上比贴在长边上多挣 $b-a$ 的面积。

![核心观察：一次 +1 应该给最小的元素（面积模型交换不等式）](images/wc288_q3_exchange_concept.svg)

> ⚠️ **为什么这不是完整证明**：增益系数会随元素被抬升而衰减，且「当前最小」在 +1 之后可能易主——纯局部比较没有排除「现在加小的、以后更小的出现」这类跨期安排。严谨性由第 5 节的**序列交换论证**兜底：任何最优操作序列都能被逐步改造成「每步都取当前最小」而不损失乘积。

### 3.3 算法流程：最小堆 + k 轮「弹最小 → +1 → 回填」

「当前最小值」用**最小堆**维护：堆顶永远是最该被加的元素。每轮弹出堆顶 $x$、压回 $x+1$，共 $k$ 轮；最后堆中元素依次取出累乘取模。

![算法流程：建最小堆 → k 轮「弹最小 → +1 → 回填」→ 求积取模](images/wc288_q3_algorithm_flow.svg)

1. `nums` 全部装入最小堆（`heapify` / 迭代器构造，$O(n)$）；
2. 重复 $k$ 次：弹出堆顶 $x$，压回 $x + 1$；
3. 依次取出堆中元素，$\text{ans} = \text{ans} \cdot x \bmod (10^9 + 7)$，返回。

0 不需要任何特判：0 是天然堆顶，最先被 +1 消除；若 0 的个数超过 $k$，剩余的 0 在第 3 步累乘时自然把答案归零（补充示例 3）。

### 3.4 示例演算

![示例演算：每一步都抬最矮的柱子](images/wc288_q3_example_walkthrough.svg)

以示例 2 `nums = [6,3,3,2]`, `k = 2` 展开（堆按升序示意）：

| 步骤 | 堆（升序示意） | 操作 | $k$ 剩余 |
|------|---------------|------|--------|
| 初始 | 2, 3, 3, 6 | — | 2 |
| 第 1 步 | 3, 3, 3, 6 | 弹 2 → 3 回填 | 1 |
| 第 2 步 | 3, 3, 4, 6 | 弹 3 → 4 回填 | 0 |

停止后乘积 $= 3 \times 3 \times 4 \times 6 = 216$ ✓

> 💡 第 2 步弹的是「其中一个 3」而非 6：给 3 的增益 $\frac{4}{3} \approx 1.33$ 远大于给 6 的 $\frac{7}{6} \approx 1.17$。对照补充示例 4：贪心把 $[10,4,4]$ 逐步抬成 $[5,6,10]$（乘积 300），而「全砸给一个 4」只得 $[10,7,4]$（280）——增量像水位一样把矮柱逐层抬平，正是 AM-GM「和固定、越均衡积越大」的离散版。

## 4. 算法细节

1. **建堆 $O(n)$**：C++ 用 `priority_queue` 的迭代器构造 `pq(nums.begin(), nums.end())`（第三模板参 `greater<int>` 经默认实参生效）；Python 用 `heapq.heapify(nums)` 原地建堆。逐个 `push` 是 $O(n\log n)$，本题也能过，但既然有线性建堆就用线性。
2. **堆里存真值，绝不取模**：元素上界 $10^6 + 10^5 = 1.1 \times 10^6 < 2^{31} - 1$，`int` 安全；而取模会破坏堆序比较（模值大小 ≠ 真值大小）。
3. **取模时机只在最终累乘**：每步 $\text{ans} \leftarrow \text{ans} \cdot x \bmod p$，中间积上界 $(10^9+6) \times 1.1 \times 10^6 \approx 1.1 \times 10^{15}$，远小于 `long long` 上界 $9.2 \times 10^{18}$，不会溢出。
4. **0 的处理零成本**：0 天然堆顶、最先被抬；$k$ 不够消除全部 0 时，剩余 0 在累乘阶段把答案自然归零。不需要计数、特判或提前退出。
5. **并列最小任选其一**：一次「取当前最小 $\mu$ 并 +1」对多重集的效果恒为「把一个 $\mu$ 换成 $\mu+1$」，与选哪个并列元素无关——终态多重集确定（第 5 节引理 3），并列时的选择不影响答案。
6. **「至多 $k$ 次」当「恰好 $k$ 次」做**：多花一次 +1 绝不亏（第 5 节引理 0），循环固定执行 $k$ 轮即可，不必试图「省着花」。

## 5. 正确性证明

**约定**：操作序列 $\sigma = (o_1, \dots, o_k)$，每步 $o_t$ 选一个下标使其值 +1。**操作可交换**：最终向量由「各下标被选次数」唯一决定，与次序无关。乘积指最终向量的全体元素之积。

**引理 0（花光不亏）**：任何至多 $k$ 次操作的方案，都能扩成恰好 $k$ 次的操作序列，且乘积不降。从而 $\mathrm{OPT}$ 可在「恰好 $k$ 次」的序列上取到。

**证明**：给某元素 $v \to v+1$，其余元素乘积 $R \ge 0$，新旧乘积 $R(v+1) \ge Rv$。故任意不足 $k$ 次的方案补足任意操作后乘积不降。∎

**引理 1（单步交换不等式）**：对整数 $0 \le a \le b$，有 $(a+1)b \ge a(b+1)$，差为 $b - a \ge 0$；$a < b$ 时严格成立。$a = 0$ 时左式把「含 0 的零积」变成正积（其余为正时）。

**证明**：$(a+1)b - a(b+1) = (ab + b) - (ab + a) = b - a$。∎

这正是 3.2 节面积模型的代数内容。以下把它升级到「序列」层面。

**引理 2（序列交换）**：设 $\sigma$ 是某最优序列，$t$ 是 $\sigma$ 中**第一个**「所选元素严格大于当前最小值」的步（不存在则 $\sigma$ 已每步取最小）。则可构造另一个最优序列 $\sigma'$，其前 $t$ 步每步都取当前最小值。

**证明**：$\sigma'$ 的前 $t-1$ 步与 $\sigma$ 相同（每步取最小），故 $t$ 时刻的当前值向量 $v$ 相同。设 $\sigma$ 第 $t$ 步选下标 $j$，$v_j > \mu := \min v$；取 $p \in \arg\min v$。记 $c_i$ 为 $\sigma$ 在第 $t$ 步**之后**选下标 $i$ 的次数。

- **情形 1（$c_p \ge 1$）**：设 $s > t$ 是 $t$ 之后首次选 $p$ 的时刻。交换第 $t$ 步与第 $s$ 步的目标（$t$ 改选 $p$，$s$ 改选 $j$）。各下标被选次数不变 ⇒ 最终向量不变 ⇒ 乘积不变，$\sigma'$ 仍最优，且第 $t$ 步已取当前最小。
- **情形 2（$c_p = 0$）**：把第 $t$ 步的这次 +1 从 $j$ 挪给 $p$，**其余步骤全部不动**。最终向量仅两处变化：$p$ 由 $v_p$ 变 $v_p + 1$；$j$ 由 $w := v_j + 1 + c_j$ 变 $w - 1$。记其余元素乘积 $R \ge 0$，则

$$P' - P = R\big[(v_p + 1)(w - 1) - v_p \, w\big] = R\,(w - 1 - v_p)$$

  由 $v_j \ge v_p + 1$（整数、严格大）与 $c_j \ge 0$ 得 $w \ge v_p + 2$，故 $w - 1 - v_p \ge 1 > 0$，于是 $P' \ge P$。$\sigma$ 最优 ⇒ $P = \mathrm{OPT}$，而 $P'$ 可达 ⇒ $P' \le \mathrm{OPT}$，夹逼得 $P' = \mathrm{OPT}$，$\sigma'$ 仍最优，且第 $t$ 步已取当前最小。∎

**引理 3（多重集确定性）**：所有「每步都取当前最小值」的序列，给定初始数组后终态多重集唯一，与并列最小时的选择无关。

**证明**：对剩余步数归纳。0 步时显然。设某步取当前最小 $\mu$：不论选中 $\mu$ 的哪个副本，多重集都变为「去掉一个 $\mu$、加入一个 $\mu + 1$」，效果唯一；后续由归纳假设亦唯一。∎

**定理（贪心最优性）**：「每步给当前最小值 +1」执行 $k$ 次后的乘积等于 $\mathrm{OPT}$。

**证明**：由引理 0 取「恰好 $k$ 次」的最优序列 $\sigma$。若 $\sigma$ 存在违规步，对其反复应用引理 2：每次改造保持最优性且首个违规位置 $t$ 严格后移，至多 $k$ 轮后得到每步都取当前最小值的最优序列 $\sigma^*$。由引理 3，算法（最小堆弹顶 → +1 → 回填，恰是这样一个过程）的终态多重集与 $\sigma^*$ 相同，乘积相等，即算法输出 $= \mathrm{OPT}$。∎

> 💡 **与 AM-GM 的呼应**：$\sum \log$ 是 Schur-凹函数——总和固定时越「均衡」的向量乘积越大。贪心的终态呈「水位填充」形（低层齐平），恰是整数约束下被任何可行解控制的那个最均衡向量；交换论证本质上是这一凸性的离散化。直觉与证明在此汇合。

## 6. 复杂度分析

- **时间复杂度**：$O(n + k \log n)$。建堆 $O(n)$；$k$ 轮「弹 + 压」各 $O(\log n)$；最终求积 $O(n)$。$n, k \le 10^5$ 时 $k \log n \approx 1.7 \times 10^6$ 次堆调整，轻松通过。
- **空间复杂度**：$O(n)$，即最小堆本身。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maximumProduct(vector<int>& nums, int k) {
        // 最小堆：迭代器构造 O(n)，greater 经默认实参生效
        priority_queue<int, vector<int>, greater<int>> pq(nums.begin(), nums.end());
        while (k--) {
            int x = pq.top();          // 当前最小值（0 天然堆顶，最先消除）
            pq.pop();
            pq.push(x + 1);
        }
        const long long MOD = 1000000007;
        long long ans = 1;             // 空乘积单位元；剩余 0 会自然把 ans 归零
        while (!pq.empty()) {
            ans = ans * pq.top() % MOD;
            pq.pop();
        }
        return (int)ans;
    }
};
```

### Python

```python
import heapq

class Solution:
    def maximumProduct(self, nums: List[int], k: int) -> int:
        heapq.heapify(nums)                  # 原地建堆 O(n)
        for _ in range(k):
            x = heapq.heappop(nums)          # 当前最小值
            heapq.heappush(nums, x + 1)
        MOD = 10**9 + 7
        ans = 1
        for x in nums:                       # 堆即原数组，直接遍历
            ans = ans * x % MOD
        return ans
```

> 💡 **工程细节**：堆内存真值（$\le 1.1 \times 10^6$，`int` 安全），取模只发生在最终累乘——中间积 $\approx 1.1 \times 10^{15}$ 在 `long long` 安全区内；Python 大整数无溢出，逐步取模只为控制数值大小。两份实现均通过与暴力对拍的随机测试（含两个官方示例、补充示例 3/4、$n = 1$、全 0 等边界）。

## 8. 边界情况与易错点

1. **0 是头号坑**：$k <$ 0 的个数时答案必为 0（补充示例 3）。无需特判——堆天然先抬 0，剩余 0 在累乘时把答案归零；但若把 `ans` 初始化成 0（正确起点是乘法单位元 1），或试图在堆里对值取模，都会翻车。
2. **「至多 $k$」别理解成「省着花」**：多花一次 +1 绝不亏（引理 0），固定循环 $k$ 轮即可。
3. **别把 $k$ 全砸给初始最小值**：补充示例 4 中 $[10,4,4]$、$k=3$，逐次给当前最小得 300，全砸一个 4 只得 280。排序后无脑 `nums[0] += k` 是本题最高频的错误贪心。
4. **溢出审计**：堆内真值 $\le 1.1 \times 10^6$（`int` 安全）；爆的只有乘积——中间积 $\le (10^9+6) \times 1.1 \times 10^6 \approx 1.1 \times 10^{15} < 9.2 \times 10^{18}$（`long long` 安全），每步取模即可，无需大数。
5. **取模不能进堆**：堆序比较需要真值大小关系，模值会破坏序（$a \bmod p < b \bmod p \not\Rightarrow a < b$）。
6. **建堆用 $O(n)$ 方式**：C++ `priority_queue` 迭代器构造 / Python `heapify`；逐个 push 的 $O(n \log n)$ 本题也能过，但属于无谓浪费。
7. **并列最小任选**：终态多重集与并列选择无关（引理 3），不需要任何「选最靠前的最小」之类的心智负担。
8. **$n = 1$ 退化**：堆退化为单元素，$k$ 次全给它，答案 $(\text{nums}[0] + k) \bmod p$，代码无需特判。
9. **求积前别忘堆已操作完**：C++ 从堆里弹空累乘与 Python 直接遍历 `nums`（`heapify`/`heappop`/`heappush` 都在原列表上进行）等价，但别在 $k$ 轮循环中途就去算乘积。

- **AM-GM / 均衡视角的进阶**：$\sum \log$ 的 Schur-凹性给出「固定总和、越均衡积越大」；贪心水位填充的终态恰是整数约束下最均衡的可达向量。可用「majorization 控制」把本篇的交换论证重写一遍，得到更短的证明。
- **允许 ±1 自由增减（保证非负）**：答案退化为「全部均摊到 $\lfloor S/n \rfloor$ 或 $\lceil S/n \rceil$」（AM-GM 取等条件），排序后 $O(n)$ 分配即可——堆与交换论证双双退场，对照可见「只能 +1」的单向约束才是本题难度所在。
