# LeetCode 向表达式添加括号后的最小结果 题解

## 1. 题目概述

- **标题 / 题号**：向表达式添加括号后的最小结果（#2232，medium）
- **链接**：https://leetcode.cn/problems/minimize-result-by-adding-parentheses-to-expression/
- **来源**：LeetCode 第 288 场周赛 Q2
- **难度**：中等
- **标签**：字符串、枚举、数学

**题意**：给定形如 `"<num1>+<num2>"` 的字符串 `expression`（两段都是正整数），要求添加**恰好一对括号**，且**左括号必须加在 `'+'` 的左侧**、**右括号必须加在 `'+'` 的右侧**，使整个表达式计算后得到**最小**值。返回加括号后的表达式字符串；若有多个答案取值相同，返回任意一个。

**约束**：

- $3 \le \text{expression.length} \le 10$
- `expression` 仅由数字 `'1'`–`'9'` 和**恰好一个** `'+'` 组成，以数字开头和结尾
- 原始值与任意合法加括号后的值均在 32-bit 带符号整数范围内

> 💡 本题在本仓库另有[每日题解 2232](../../solution/2201-2300/2232_向表达式添加括号后的最小结果.md)：主线同为四段拆分 + 双重枚举，附面试问答、`itertools.product` 一行解与无前导零讨论。本篇按**周赛复盘视角**展开，补齐「合法方案 ⇔ 切分对」的双射证明与贪心失效的形式化论证。

## 2. 示例

**示例 1**

```text
输入：expression = "247+38"
输出："2(47+38)"
解释：表达式计算得到 2 * (47 + 38) = 2 * 85 = 170。
  注意 "2(4)7+38" 不是有效结果，因为右括号必须添加在 '+' 的右侧。
  可以证明 170 是最小可能值。
```

**示例 2**

```text
输入：expression = "12+34"
输出："1(2+3)4"
解释：表达式计算得到 1 * (2 + 3) * 4 = 1 * 5 * 4 = 20。
```

**示例 3**

```text
输入：expression = "999+999"
输出："(999+999)"
解释：表达式计算得到 999 + 999 = 1998，两侧空段各按乘法单位元 1 处理。
```

**补充示例 4（括号包得多 ≠ 更优）**

```text
输入：expression = "5+22"
输出："(5+2)2"
解释：全部 4 种合法切分——
  "(5+2)2"  = (5+2) × 2   = 14  ← 最小
  "(5+22)"  = 5 + 22      = 27
  "5(2+2)2" = 5 × 4 × 2   = 40
  "5(2+22)" = 5 × 24      = 120
```

> ⚠️ 示例 4 说明：**让括号尽量「包得多」并不总是更优**——`(5+22)=27` 被 `(5+2)2=14` 击败，因为右括号提前收尾能留出一个外乘数 2。切分点没有显然的最优方向，这正是必须枚举的信号。

## 3. 解题思路

### 3.1 暴力思路

把 `'+'` 定位后，左括号能插入的位置只有 `len(num1)` 个间隙（num1 的每个字符之前），右括号能插入的位置只有 `len(num2)` 个间隙（num2 的每个字符之后）。由于 $n \le 10$，合法组合至多 $5 \times 5 = 25$ 个——**暴力枚举本身就是标算**，不存在「更优解法会不会更好」的问题。

赛时真正要做的不是「想出算法」，而是**把三个建模细节一次做对**：

1. 加括号后的表达式长什么样（值公式）；
2. 哪些切分合法、哪些非法（$b$、$c$ 非空）；
3. 空段如何取值（当 1 而不是 0）。

### 3.2 核心观察：一对括号把表达式刚性切成四段 $a(b+c)d$

![核心观察：一对括号把表达式刚性切成四段 a(b+c)d](images/wc288_q2_split_model.svg)

设左括号插在 `num1` 的第 $i$ 位前，右括号插在 `num2` 的第 $j$ 位后，则表达式被切为四段：

$$\underbrace{a}_{\text{num1 前缀}}\;\big(\;\underbrace{b}_{\text{num1 后缀}} + \underbrace{c}_{\text{num2 前缀}}\;\big)\;\underbrace{d}_{\text{num2 后缀}}$$

- **$b$ 非空**：左括号若紧贴 `'+'`（即插在 num1 之后），会得到 `num1(+...`，括号内 `'+'` 左侧无数字，非法。所以 $i \in [0, \mathrm{len}(\text{num1})-1]$。
- **$c$ 非空**：右括号若紧贴 `'+'`（即插在 num2 之前），会得到 `...+)num2` 的前段 `+` 右侧无数字，非法。所以 $j \in [1, \mathrm{len}(\text{num2})]$。
- **$a$、$d$ 可空**：$i=0$ 时左括号顶到 num1 首位（$a$ 空），$j=\mathrm{len}(\text{num2})$ 时右括号收在 num2 末尾（$d$ 空），均合法。

数字与括号相邻并置即**隐含乘法**，所以值为三因子乘积：

$$\text{val} = A \times (B + C) \times D,\qquad A = \begin{cases}\mathrm{int}(a) & a \neq \varepsilon\\ 1 & a = \varepsilon\end{cases},\quad D = \begin{cases}\mathrm{int}(d) & d \neq \varepsilon\\ 1 & d = \varepsilon\end{cases}$$

> 💡 **为什么空段当 1 而不是 0？** 空段表示「该位置没有数字出现」，因子直接从表达式中消失。乘法中「什么都不乘」是乘以单位元 1，不是 0——若当 0，则任何 $a$ 或 $d$ 为空的方案值恒为 0，与示例 3 的 `(999+999) = 1998` 矛盾。

### 3.3 算法流程

![算法流程：双重枚举切分点 (i, j) 取最小](images/wc288_q2_enum_flow.svg)

1. **定位 `'+'`**：拆出 `num1`、`num2`。
2. **外层枚举 $i$**：$a = \text{num1}[:i]$（可空）、$b = \text{num1}[i:]$（非空），预算 $A$（空取 1）、$B$。
3. **内层枚举 $j$**：$c = \text{num2}[:j]$（非空）、$d = \text{num2}[j:]$（可空），计算 $C$、$D$（空取 1）。
4. **求值更新**：$\text{val} = A \times (B+C) \times D$，若 $\text{val} < \text{best}$ 则更新 $\text{best}$ 与答案串 $a + \text{"("} + b + \text{"+"} + c + \text{")"} + d$。
5. **返回答案串**。

### 3.4 示例演算

![示例演算：247+38 的全部 6 种合法切分](images/wc288_q2_walkthrough.svg)

以 `"247+38"` 为例，$\text{num1}=\text{"247"}$、$\text{num2}=\text{"38"}$，共 $3 \times 2 = 6$ 组合：

| $i$ | $j$ | 表达式 | 求值 | 结果 |
|-----|-----|--------|------|------|
| 0 | 1 | `(247+3)8` | $1 \times (247+3) \times 8$ | 2000 |
| 0 | 2 | `(247+38)` | $1 \times (247+38) \times 1$ | 285 |
| 1 | 1 | `2(47+3)8` | $2 \times (47+3) \times 8$ | 800 |
| **1** | **2** | **`2(47+38)`** | $2 \times (47+38) \times 1$ | **170** ✓ |
| 2 | 1 | `24(7+3)8` | $24 \times (7+3) \times 8$ | 1920 |
| 2 | 2 | `24(7+38)` | $24 \times (7+38) \times 1$ | 1080 |

最小值 $170$ 落在 $(i,j) = (1,2)$，输出 `"2(47+38)"`。

## 4. 算法细节

### 4.1 切分点的语义

- 外层 $i$ 定义为 **$b$ 的首字符下标**：$b = \text{num1}[i:]$。$b$ 非空要求 $i \le \mathrm{len}(\text{num1})-1$，故循环写 `for i in range(len(num1))` 天然满足；$i=0$ 使 $a$ 为空（左括号顶到最前）。
- 内层 $j$ 定义为 **$c$ 的截断长度**：$c = \text{num2}[:j]$。$c$ 非空要求 $j \ge 1$，故循环写 `for j in range(1, len(num2)+1)`；$j=\mathrm{len}(\text{num2})$ 使 $d$ 为空（右括号收到最后）。

> ⚠️ 这两个循环边界是本题**最高频的 WA 点**：`range(len(num1)+1)` 会枚举出 $b$ 为空的非法切分（左括号紧贴 `'+'`），`range(len(num2)+1)` 会枚举出 $c$ 为空的非法切分。

### 4.2 求值规则：空段三元判断

```text
A = int(a) if a 非空 else 1
D = int(d) if d 非空 else 1
val = A * (int(b) + int(c)) * D
```

$B$、$C$ 永远非空，直接 `int(b)`、`int(c)`。**判空必须在转整数之前**：C++ 对空串调用 `stoll("")` 抛 `std::invalid_argument`，Python `int("")` 抛 `ValueError`——都是运行时错误而非答案错误，赛时对拍不容易发现。

### 4.3 答案串拼接

更新最优时同步拼接 $\text{ans} = a + \texttt{"("} + b + \texttt{"+"} + c + \texttt{")"} + d$，其中空段自然贡献空串，无需特判。用 `val < best` 严格小于比较，保证并列最小时返回**先枚举到**的那个，题目允许任意一个最优解。

### 4.4 数据类型

题目保证任何合法方案的值都在 32-bit 范围内，`int` 足够；用 `long long` / `float('inf')` 初始化 `best` 只是赛时的稳妥习惯（防御读错约束、防御中间乘积溢出的边界担忧）。

## 5. 正确性证明

**引理 1（双射）**：合法加括号方案与切分对 $(i,j)$（$0 \le i \le \mathrm{len}_1 - 1$，$1 \le j \le \mathrm{len}_2$）一一对应，且方案对应表达式的值为 $A \times (B+C) \times D$（空段取 1）。

**证明**：

- **从方案到切分**：左括号必须在 `'+'` 左侧，故其插入位置只能是 `num1` 的某个字符间隙之前（含 num1 首位之前），设落在下标 $i$ 的字符前；若 $i = \mathrm{len}_1$（即插在 num1 与 `'+'` 之间），括号内 `'+'` 紧邻左侧无数字，表达式非法，故 $i \le \mathrm{len}_1 - 1$。同理右括号插在 `num2` 的下标 $j$ 的字符之后且 $j \ge 1$。方案唯一确定 $(i,j)$。
- **从切分到方案**：给定 $(i,j)$，把左括号插在 $\text{num1}[i]$ 前、右括号插在 $\text{num2}[j-1]$ 后，得到的串形如 $a(b+c)d$，括号内至少含 `'+'` 两侧各一位数字，是合法数学表达式。切分唯一确定方案。
- **值公式**：合法表达式的运算是「括号内先求和，再与左右相邻数字并置相乘」，即三个因子 $a$、$(b+c)$、$d$ 的连乘。$a$ 为空 ⇒ 左因子不存在 ⇒ 该位置乘以单位元 1；$d$ 同理。∎

**引理 2（贪心失效）**：不存在仅依赖「局部调整括号位置」的贪心规则保证最优。

**证明**：固定 $j = \mathrm{len}_2$，考察 $\text{val}(i) = A(i) \times (B(i) + C)$。当 $i$ 增大时 $A(i)$ 单调不减（前缀变长）而 $B(i)$ 单调不增（后缀变短），一增一减的乘积**无单调性**。以 `"247+38"` 为反例：$\text{val}(0) = 1 \times 285 = 285$，$\text{val}(1) = 2 \times 85 = 170$，$\text{val}(2) = 24 \times 45 = 1080$——先降后升。任何「让外乘数最小（$i$ 取 0）」或「让括号内和最小」的单向贪心都会错过 $170$（见 3.4 演算图中的反贪心标注）。同理固定 $i$ 对 $j$ 也非单调（如补充示例 4 中 `(5+22)=27` 被 `(5+2)2=14` 击败）。∎

**定理（枚举正确性）**：双重循环枚举全部 $(i,j)$ 并维护最小值及对应拼接串，返回值即为题目所求。

**证明**：由引理 1，枚举空间与合法方案集**不重不漏地一一对应**，故有限集合上的 $\min$ 恰为全局最小值；输出串由所选 $(i,j)$ 按引理 1 的构造拼接而成，是该最小值的一个合法方案。由引理 2，不能缩小枚举空间，但在 $n \le 10$ 下全枚举至多 25 组合，代价可忽略。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\mathrm{len}_1 \times \mathrm{len}_2 \times n) \subseteq O(n^2)$，其中 $n = \text{expression.length} \le 10$。双重循环组合至多 $5 \times 5 = 25$，每组切串 + 转整数 $O(n)$。实际总量数百次字符操作，视为常数级。
- **空间复杂度**：$O(n)$。仅存 `num1`、`num2` 的切片与当前最优答案串，与输入同阶。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string minimizeResult(string expression) {
        int plus = expression.find('+');
        string num1 = expression.substr(0, plus);
        string num2 = expression.substr(plus + 1);
        int n1 = num1.size(), n2 = num2.size();

        long long best = LLONG_MAX;
        string ans;
        // i 是 b 的首字符下标：b = num1[i:] 非空
        for (int i = 0; i < n1; i++) {
            string a = num1.substr(0, i);
            string b = num1.substr(i);
            long long A = a.empty() ? 1 : stoll(a);
            long long B = stoll(b);
            // j 是 c 的截断长度：c = num2[:j] 非空
            for (int j = 1; j <= n2; j++) {
                string c = num2.substr(0, j);
                string d = num2.substr(j);
                long long C = stoll(c);
                long long D = d.empty() ? 1 : stoll(d);
                long long val = A * (B + C) * D;
                if (val < best) {
                    best = val;
                    ans = a + "(" + b + "+" + c + ")" + d;
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimizeResult(self, expression: str) -> str:
        plus = expression.index('+')
        num1, num2 = expression[:plus], expression[plus + 1:]

        best = None
        ans = ""
        # i 是 b 的首字符下标：b = num1[i:] 非空
        for i in range(len(num1)):
            a, b = num1[:i], num1[i:]
            A = int(a) if a else 1
            B = int(b)
            # j 是 c 的截断长度：c = num2[:j] 非空
            for j in range(1, len(num2) + 1):
                c, d = num2[:j], num2[j:]
                C = int(c)
                D = int(d) if d else 1
                val = A * (B + C) * D
                if best is None or val < best:
                    best = val
                    ans = f"{a}({b}+{c}){d}"
        return ans
```

## 8. 边界情况与易错点

1. **$b$ 非空（左括号不贴 `'+'`）**：外层 $i$ 上界是 $\mathrm{len}(\text{num1})-1$。写成 `range(len(num1)+1)` 会枚举出 `num1(+...` 的非法切分——它不仅答案错，还可能让拼接串格式非法。

2. **$c$ 非空（右括号不贴 `'+'`）**：内层 $j$ 下界是 1。写成 `range(len(num2)+1)` 会枚举出 $c$ 为空的 `...+)...` 切分。

3. **空段当 1 而非 0**：$i=0$（$a$ 空）与 $j=\mathrm{len}(\text{num2})$（$d$ 空）都是**合法**方案，因子按乘法单位元 1 计。当 0 处理会漏掉示例 3 的 `(999+999) = 1998` 这类最优解。

4. **先判空再转整数**：`stoll("")` 抛异常（C++）、`int("")` 抛 `ValueError`（Python）。三元判断必须包裹住空串分支，赛时这是「RE 而非 WA」的隐蔽坑。

5. **并列最优返回任意一个**：用严格小于 `<` 更新即可；不必记录字典序最小方案，也不必担心多解判定。

6. **无需处理前导零**：题面限定数字仅 `'1'`–`'9'`（无 `'0'`），任意子串转整数都无歧义。若题目放宽含 `'0'`，需额外跳过「长度 > 1 且首位为 `'0'`」的非法段——这是本类枚举题的常见升级方向。

7. **返回的是字符串不是数值**：全程维护 `best`（数值）与 `ans`（串）两个量，只比较数值、只拼接串，别把两者混在一个变量里。
