# LeetCode 使数组成为递增数组的最少右移次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组成为递增数组的最少右移次数（#2855，easy）
- **链接**：https://leetcode.cn/problems/minimum-right-shifts-to-sort-the-array/
- **来源**：LeetCode 第 113 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定长度为 $n$ 的数组 `nums`，元素为**互不相同**的正整数。一次**右移**把下标 $i$ 处的元素同时移到下标 $(i+1) \bmod n$。返回让 `nums` 变成递增数组的最少右移次数；若无论怎么移都不行，返回 $-1$。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$，且互不相同

## 2. 示例

**示例 1**

```text
输入：nums = [3,4,5,1,2]
输出：2
解释：右移 1 次得 [2,3,4,5,1]，右移 2 次得 [1,2,3,4,5]。
```

**示例 2**

```text
输入：nums = [1,3,5]
输出：0
解释：已经是递增数组。
```

**示例 3**

```text
输入：nums = [2,1,4]
输出：-1
解释：任何右移都无法得到递增数组。
```

## 3. 解题思路

### 3.1 暴力思路

枚举右移次数 $s = 0, 1, \dots, n-1$，模拟出旋转后的数组再检查是否递增，时间 $O(n^2)$。$n \le 100$ 时最多 $10^4$ 次比较，完全可以通过。但这个做法没有利用「旋转」的结构性质，签到题也值得多想一步：**递增数组旋转之后长什么样？** 想清楚这一点，就能得到一次遍历的 $O(n)$ 做法。

### 3.2 核心观察：环形视角数「下降点」

![核心观察：环形视角找下降点](images/bw113_q1_breakpoint.svg)

右移不改变元素的**环形相对顺序**，只改变「谁排在开头」。把递增数组 $b_0 < b_1 < \dots < b_{n-1}$（互异 ⇒ 严格递增）从任意位置剪开平铺，得到的数组在**环形**视角下恰有一个「下降点」——最大值 $b_{n-1}$ 绕回最小值 $b_0$ 的交界处。

于是把 `nums` 当成环形序列，比较每一对 $nums[i]$ 与 $nums[(i+1) \bmod n]$（**含首尾环绕**）：

- **恰有 1 个下降点**（$nums[i] > nums[(i+1)\bmod n]$）：`nums` 是某个递增数组旋转而来，把下标 $i+1$ 转到开头即得递增数组，需要右移 $n - i - 1$ 次（$i = n-1$ 时环绕下降，得 $0$ 次，即本来就递增）；
- **下降点 $\ge 2$ 个**：无论从哪里剪开，平铺序列中都会残留一个「中间高两头低」的断口，返回 $-1$。

> ⚠️ 注意：元素互不相同保证了 $n \ge 2$ 时环形序列**至少有 1 个下降点**（最大值的环形后继一定比它小），所以真正的判定是「恰好 1 个还是至少 2 个」；$n = 1$ 是特例（无下降点，答案 0）。

### 3.3 算法流程

![三种情况一览](images/bw113_q1_cases.svg)

```text
1. down = -1
2. for i = 0 .. n-1:
       若 nums[i] > nums[(i+1) mod n]:
           若 down != -1：返回 -1     # 第二个下降点
           down = i
3. 若 down == -1：返回 0             # 只可能是 n = 1
4. 返回 n - down - 1                  # 把下标 down+1 转到开头
```

### 3.4 示例演算

- `[3,4,5,1,2]`：比较对 $(3,4),(4,5),(5,1),(1,2),(2,3)$，只有 $5>1$ 下降，`down = 2`，答案 $5-2-1=2$；
- `[1,3,5]`：比较对 $(1,3),(3,5),(5,1)$，下降点在环绕处 $i=2$，答案 $5-2-1=0$（已递增）；
- `[2,1,4]`：$2>1$ 与环绕处 $4>2$ 两个下降点，返回 $-1$；
- `[2,3,4,5,1]`：只有 $5>1$ 下降（$1>2$ 不成立），`down = 3`，答案 $5-3-1=1$，验证：右移 1 次得 `[1,2,3,4,5]`。

## 4. 算法细节

1. **环形比较**：循环里用 $(i+1) \bmod n$ 而不是 $i+1$，别漏掉「最后一个 vs 第一个」的环绕对——`[1,3,5]` 的下降点恰好在环绕处。
2. **答案公式**：右移 $s$ 次后，原下标 $j$ 的元素位于 $(j+s) \bmod n$；要让递增段的起点 $i+1$ 落到下标 $0$，解 $(i+1+s) \equiv 0 \pmod n$ 得 $s = n-i-1$（$0 \le s \le n-1$，唯一）。
3. **互异性是关键**：互不相同使得「递增」=「严格递增」，且 $a_i = a_{i+1}$ 不会出现，用严格大于判下降即可。若允许重复，非降数组的旋转判定会复杂不少。
4. **单元素**：$n=1$ 时循环里 `nums[0] > nums[0]` 恒假，`down` 保持 $-1$，返回 0，无需特判。

## 5. 正确性证明

**引理 1（旋转的结构）**：$n \ge 2$、元素互异时，数组 $a$ 能由某个严格递增数组右移得到 ⟺ $a$ 的环形下降点数恰为 $1$。

**证明**：（必要性）设 $a$ 是 $b_0 < \dots < b_{n-1}$ 右移 $s$ 次的结果，即 $a_i = b_{(i-s) \bmod n}$。相邻对 $a_i, a_{i+1}$ 下降当且仅当 $(i-s) \bmod n = n-1$，即 $i \equiv s-1 \pmod n$，唯一。（充分性）设唯一下降点在 $i$，则其余所有环形相邻对（含环绕对）都满足前 $\le$ 后，元素互异即严格小于。于是从 $i+1$ 出发的环形序列 $a_{i+1}, \dots, a_{n-1}, a_0, \dots, a_i$ 严格递增，故 $a$ 是它右移 $n-i-1$ 次的结果。∎

**定理**：上述算法返回正确的最少右移次数。

**证明**：环形下降点数 $\ge 2$ 时，由引理 1 的逆否命题，$a$ 不是任何递增数组的旋转，而右移只改变起点、不改环形顺序，故任何次数的右移都不能得到递增数组，返回 $-1$ 正确。下降点恰 1 个（在 $i$）时，由引理 1，起点必须取 $i+1$ 才可能递增：严格递增的平铺序列首元素必为最小元，而最小元恰在 $i+1$（它是唯一下降点的后继）；把 $i+1$ 转到 $0$ 需要 $s = n-i-1$ 次右移（细节见 §4），且这是唯一的可行起点，故该 $s$ 既可行又最小。$n=1$ 时数组平凡递增，返回 0。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次遍历，每步做一次环形比较。
- **空间**：$O(1)$。只维护 `down` 一个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumRightShifts(vector<int>& nums) {
        int n = nums.size();
        int down = -1;                            // 唯一下降点：nums[down] > nums[down+1]
        for (int i = 0; i < n; ++i) {
            if (nums[i] > nums[(i + 1) % n]) {    // 环形比较，覆盖首尾交界
                if (down != -1) return -1;       // 第二个下降点 → 怎么移都不行
                down = i;
            }
        }
        if (down == -1) return 0;                 // 本来就是递增数组
        return n - down - 1;                      // 把下标 down+1 转到开头需要 n-down-1 次右移
    }
};
```

### Python

```python
class Solution:
    def minimumRightShifts(self, nums: list[int]) -> int:
        n = len(nums)
        down = -1                                # 唯一下降点
        for i in range(n):
            if nums[i] > nums[(i + 1) % n]:      # 环形比较
                if down != -1:
                    return -1                    # 出现第二个下降点
                down = i
        return 0 if down == -1 else n - down - 1
```

> 💡 两份代码均通过全部官方示例（`2`、`0`、`-1`），并与「逐一尝试 $0..n-1$ 次右移再判递增」的暴力做了 10000 组随机对拍（含随机排列与随机旋转构造），`mismatch = 0`。

## 8. 边界情况与易错点

1. **漏掉环绕比较**：只比较 $i$ 与 $i+1$（不取模）会把 `[1,3,5]` 误判为「无下降点」（它在环绕处 $5>1$ 有一个），本例碰巧答案也是 0，但如 `[2,3,4,5,1]` 就必须靠环绕对排除 $1>2$ 不成立、只剩 $5>1$ 这个事实。
2. **下降点在 $i = n-1$**：公式 $n-i-1 = 0$，对应「已经递增」，不要误写成 $n - i$。
3. **两个下降点要立刻返回 $-1$**：不要试图「取更晚的那个」或类似修补——环形顺序不变，两个断口无法同时消除。
4. **$n = 1$**：无下降点，返回 0；代码里 `down == -1` 分支天然覆盖。
5. **互异性**：题目保证元素互不相同；若没有该保证（允许相等），严格大于的判定与「恰一个下降点」的充分性都需要重新讨论。
