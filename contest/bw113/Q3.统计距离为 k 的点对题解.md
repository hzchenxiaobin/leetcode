# LeetCode 统计距离为 k 的点对 题解

## 1. 题目概述

- **标题 / 题号**：统计距离为 k 的点对（#2857，medium）
- **链接**：https://leetcode.cn/problems/count-pairs-of-points-with-distance-k/
- **来源**：LeetCode 第 113 场双周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、哈希表

**题意**：给定二维整数数组 `coordinates`（可能含重复点）与整数 $k$。两点 $(x_1,y_1)$、$(x_2,y_2)$ 的**距离**定义为 $(x_1 \oplus x_2) + (y_1 \oplus y_2)$（按位异或之和，**不是**曼哈顿距离）。统计满足 $i < j$ 且距离恰为 $k$ 的点对数目。

**约束**：

- $2 \le coordinates.length \le 5 \times 10^4$
- $0 \le x_i, y_i \le 10^6$
- $0 \le k \le 100$

## 2. 示例

**示例 1**

```text
输入：coordinates = [[1,2],[4,2],[1,3],[5,2]], k = 5
输出：2
解释：(0,1)：(1⊕4) + (2⊕2) = 5；(2,3)：(1⊕5) + (3⊕2) = 5。
```

**示例 2**

```text
输入：coordinates = [[1,3],[1,3],[1,3],[1,3],[1,3]], k = 0
输出：10
解释：任意两点距离为 0，共 C(5,2) = 10 对。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有点对直接算距离：$O(n^2)$。$n = 5\times10^4$ 时约 $1.25 \times 10^9$ 次运算，超时。瓶颈在于：对每个点，我们在**全平面**里盲目找配对。突破口藏在约束里——$k \le 100$ 极小，它限制了「合法搭档」的可能形态。

### 3.2 核心观察：XOR 距离 + 小 k ⇒ 每个点只有 k+1 个候选搭档

![距离 = (x1⊕x2) + (y1⊕y2) = k：枚举 dx](images/bw113_q3_xor_enum.svg)

设点 $P = (x_1, y_1)$，它的搭档 $Q$ 必须满足 $(x_1 \oplus x_2) + (y_1 \oplus y_2) = k$。记 $dx = x_1 \oplus x_2$、$dy = y_1 \oplus y_2$，两个异或值都非负，且 $dx + dy = k$，因此 $dx$ 只能取 $0, 1, \dots, k$。

由**异或的自反性**（$a \oplus b \oplus b = a$），一旦确定 $dx$，搭档就被完全钉死：

$$
x_2 = x_1 \oplus dx, \qquad y_2 = y_1 \oplus (k - dx)
$$

也就是说，$P$ 的合法搭档只可能是 $k+1 \le 101$ 个具体坐标之一，直接查哈希表就能知道每个坐标有多少个点。把「全平面找配对」变成「$k+1$ 次哈希查询」，这是本题从 $O(n^2)$ 到 $O(nk)$ 的全部秘密。

### 3.3 算法流程

![先查询、后插入：天然保证 i < j](images/bw113_q3_flow.svg)

```text
1. cnt = 空哈希表（坐标 → 出现次数）
2. 依序处理每个点 P = (x, y)：
       for dx in 0..k:                    # 枚举 x⊕x'
           累加 cnt[(x ⊕ dx, y ⊕ (k − dx))]
       cnt[(x, y)] += 1                   # 查询完再加入
3. 返回累加值
```

**先查询、后插入**的顺序让每对点恰被统计一次：处理点 $i$ 时表中只有下标更小的点，统计的自然是 $j < i$ 的对；$k = 0$ 时 $dx = dy = 0$ 的目标恰是自己，但自己还没插入，不会被数到——无需任何去重或除 2 处理。

### 3.4 示例演算

以示例 1（$k = 5$）过一遍：

- 处理 $(1,2)$：表空，$+0$；插入 $(1,2)$；
- 处理 $(4,2)$：$dx = 5$ 时目标 $(4 \oplus 5, 2 \oplus 0) = (1, 2)$ 在表中，$+1$；插入 $(4,2)$；
- 处理 $(1,3)$：$dx = 4$ 时目标 $(1\oplus4, 3\oplus1) = (5,2)$ **尚未入表**，落空，$+0$；插入 $(1,3)$；
- 处理 $(5,2)$：$dx = 4$ 时目标 $(5\oplus4, 2\oplus1) = (1,3)$ 在表中，$+1$；插入 $(5,2)$。

合计 $2$，与官方输出一致。注意点对 $(2,3)$ 是在处理**较晚**的点 $(5,2)$ 时才被数到的。

## 4. 算法细节

1. **候选不重复**：不同的 $dx$ 给出不同的 $x_2 = x_1 \oplus dx$（异或是双射），$k+1$ 个候选坐标两两不同，不会把一对点数两遍。
2. **坐标编码**：$x, y \le 10^6 < 2^{20}$，而 $dx \le 100 < 2^7$ 只翻转低 7 位，故 $x \oplus dx < 2^{20}$ 仍然成立。C++ 里把坐标打包成单个 `long long` 键 `x << 21 | y`（留一位余量，$y < 2^{21}$ 无碰撞）；Python 直接用元组 `(x, y)` 作键。
3. **哈希表选择**：C++ `unordered_map` 在 $n \cdot (k+1) \approx 5 \times 10^6$ 次查询下毫无压力（实测 0.13 秒）；若担心极端哈希碰撞可换成 `map`（多一个 log）或自定义哈希。
4. **先查后插 vs 先建表再查**：后者会把每对数两次、$k=0$ 时还会数到自己，需要 $(total - n_{self}) / 2$ 修正，容易写错；先查后插一步到位。
5. **答案上限**：$\binom{50000}{2} \approx 1.25 \times 10^9$，贴着 `int` 上界（$2^{31}-1 \approx 2.15 \times 10^9$），C++ 内部用 `long long` 累加最稳。

## 5. 正确性证明

**引理 1（候选完备性与正确性）**：对点 $P=(x_1,y_1)$，点 $Q=(x_2,y_2)$ 与 $P$ 的距离为 $k$，当且仅当存在 $dx \in [0, k]$ 使得 $x_2 = x_1 \oplus dx$ 且 $y_2 = y_1 \oplus (k - dx)$。

**证明**：（必要性）取 $dx = x_1 \oplus x_2$、$dy = y_1 \oplus y_2$，二者非负且 $dx + dy = k$，故 $dx \in [0,k]$；由异或自反性 $x_1 \oplus dx = x_2$、$y_1 \oplus (k - dx) = y_1 \oplus dy = y_2$。（充分性）这样的 $Q$ 到 $P$ 的距离 $= (x_1 \oplus (x_1 \oplus dx)) + (y_1 \oplus (y_1 \oplus (k-dx))) = dx + (k - dx) = k$。∎

**引理 2（不重不漏）**：按「先查询、后插入」处理点序列，累加值恰为距离为 $k$ 的无序点对数。

**证明**：处理点 $p_i$（第 $i$ 个，从 0 计）时，表中恰包含 $p_0, \dots, p_{i-1}$（含重复点的多重计数）。对无序对 $\{p_i, p_j\}$（$j < i$，两点距离为 $k$）：由引理 1，存在唯一 $dx$ 使 $p_j$ 等于 $p_i$ 的该候选坐标，于是处理 $p_i$ 时这一对被累加 $p_j$ 的重数次；处理 $p_j$ 时 $p_i$ 尚不在表中，不会被累加。故每对恰好按「较晚者处理时」统计一次。自身：处理 $p_i$ 时 $p_i$ 未入表，即使 $k=0$（候选即自身）也不会统计 $(p_i, p_i)$。∎

**定理**：算法返回值等于满足 $i < j$ 且距离为 $k$ 的点对数。

**证明**：引理 1 保证候选枚举覆盖所有可能搭档且每个候选确实距离为 $k$；引理 2 保证计数恰为无序对数目一次。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot (k+1))$。每个点做 $k+1 \le 101$ 次哈希查询与一次插入，总量约 $5 \times 10^6$，实测 C++ 0.13 秒、Python 约 1 秒。
- **空间**：$O(n)$。哈希表至多存 $n$ 个不同坐标。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countPairs(vector<vector<int>>& coordinates, int k) {
        unordered_map<long long, int> cnt;
        long long total = 0;
        for (const auto& p : coordinates) {
            int x = p[0], y = p[1];
            for (int dx = 0; dx <= k; ++dx) {     // 枚举 x1 XOR x2 = dx
                int dy = k - dx;                  // 则 y1 XOR y2 = k - dx
                auto it = cnt.find(key(x ^ dx, y ^ dy));
                if (it != cnt.end()) total += it->second;
            }
            ++cnt[key(x, y)];                     // 查询完再加入，天然保证 i < j
        }
        return (int)total;
    }
private:
    static long long key(long long x, long long y) { return x << 21 | y; }
};
```

### Python

```python
class Solution:
    def countPairs(self, coordinates: list[list[int]], k: int) -> int:
        cnt: dict[tuple[int, int], int] = {}
        total = 0
        for x, y in coordinates:
            for dx in range(k + 1):              # 枚举 x1 XOR x2 = dx
                total += cnt.get((x ^ dx, y ^ (k - dx)), 0)
            cnt[(x, y)] = cnt.get((x, y), 0) + 1  # 查询完再加入，天然保证 i < j
        return total
```

> 💡 两份代码均通过全部官方示例（`2`、`10`），并与「$O(n^2)$ 双循环按定义计算距离」的暴力对拍 2400 组随机数据（含大量重复点、小坐标域、$10^6$ 大坐标、$k=0$ 等），`mismatch = 0`；最坏规模（$n = 5\times10^4$、$k=100$）实测 C++ 0.13s、Python 0.96s。

## 8. 边界情况与易错点

1. **读题！距离是 XOR 不是曼哈顿**：$(x_1 \oplus x_2) + (y_1 \oplus y_2)$，如果按 $|x_1 - x_2| + |y_1 - y_2|$ 建模（枚举四个象限偏移），样例都过不了。
2. **$k = 0$ 的自配对陷阱**：$dx = dy = 0$ 时目标点就是自己；「先查后插」顺序天然避免，若先建全表再查询则会把每个点数一次自己，且每对数两次，需要 $(total - n)/2$ 修正——公式容易漏减。
3. **候选不在输入范围内**：$x \oplus dx$ 可能是平面上没有点的坐标，哈希查不到返回 0，无需特判；但**不要**据此剪枝坐标范围。
4. **重复点**：$k=0$ 时重复点互相配对（示例 2），哈希计数天然支持多重计数；别用 `set` 去重。
5. **编码碰撞**：`x << 21 | y` 要求 $y < 2^{21}$；若用 `x << 20 | y` 也够（$y \le 10^6 < 2^{20}$，异或 $dx \le 100$ 后仍 $< 2^{20}$），但移位量写小了（如 `<< 16`）就会碰撞出错误答案。
6. **答案溢出**：极端情况约 $1.25 \times 10^9$，C++ 用 `int` 返回值刚好放得下，但累加器建议 `long long`。
7. **复杂度误估**：$O(n(k+1))$ 中 $k$ 与 $n$ 独立（$k \le 100$ 是常数级），不要误以为要枚举 $dx \le 10^6$。
