# LeetCode 推多米诺 题解

## 1. 题目概述

- **标题 / 题号**：推多米诺（#838，medium）
- **链接**：https://leetcode.cn/problems/push-dominoes/
- **来源**：LeetCode 第 85 场周赛 Q2
- **难度**：中等
- **标签**：双指针、字符串、动态规划

**题意**：$n$ 张骨牌排成一行竖直站立，某些骨牌一开始就被推向左（`'L'`）或右（`'R'`），其余不动（`'.'`）。每过一秒，正在倒下的骨牌会推动**紧邻**的那一张：向左倒的推左邻，向右倒的推右邻。若某张竖立的骨牌两侧**同时**有骨牌倒向它，则受力平衡，它保持竖立。正在倒下的骨牌不会对已经倒下或同样在倒的骨牌施加额外推力。求最终的完整状态串。

**约束**：

- $1 \le n \le 10^5$
- `dominoes[i]` 只能是 `'L'`、`'R'`、`'.'`

## 2. 示例

**示例 1**

```text
输入：dominoes = "RR.L"
输出："RR.L"
解释：第 0 张向右倒，第 1 张已经是 R；第 2 张被左边推右、同时第 3 张 L 推左，
     两侧同时受力 → 保持竖立，故第 2 张仍是 '.'。
```

**示例 2**

```text
输入：dominoes = ".L.R...LR..L.."
输出："LL.RR.LLRRLL.."
解释：开头的 '.' 被第 1 张 L 推成 L；"R...L" 段两端对推，正中间一张保持 '.'。
```

**示例 3（补充）**

```text
输入：dominoes = "..."
输出："..."
解释：没有任何推力，全部保持竖立。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是**逐秒模拟**：每一秒扫描全串，对每个 `'.'` 检查左邻是否 `'R'`、右邻是否 `'L'`：

- 左边推来、右边没推来 → 变 `'R'`；
- 右边推来、左边没推来 → 变 `'L'`；
- 两边同时推来 → 保持 `'.'`。

这完全符合物理，但它最多要跑 $n$ 秒（例如 `"R...."` 全靠一秒一张地推过去），每秒 $O(n)$，总复杂度 $O(n^2)$。$n = 10^5$ 时是 $10^{10}$ 量级，必然超时。不过它的语义最直白，非常适合作为**对拍用的暴力**。

### 3.2 核心观察：把串切成「两端已定向」的空档

![空档最终形态只由两端骨牌决定，共四种组合](images/wc85_q2_segments.svg)

关键事实：力只向**紧邻**传播，且已经确定方向的骨牌不会再改变。于是取任意两张非 `'.'` 的骨牌 $i < j$，中间全是 `'.'`，这一段（称为**空档**）的最终形态**只由 $s[i]$ 与 $s[j]$ 决定**，与空档之外的一切无关。四种组合：

| 两端 | 含义 | 最终形态 |
|------|------|----------|
| `R … R` | 两者同向右倒 | 全部变 `R` |
| `L … L` | 两者同向左倒 | 全部变 `L` |
| `L … R` | 两者背向而行 | 全部保持 `'.'` |
| `R … L` | 两者向中间对推 | 前半 `R`、后半 `L`；空档长度为奇数时正中间保持 `'.'` |

`L … R` 保持 `'.'` 的理由很干脆：左边的 `L` 只往左推、右边的 `R` 只往右推，空档里的骨牌永远收不到任何力。

### 3.3 算法流程：加哨兵 + 双指针

![双指针扫过每个空档，按两端规则填一次](images/wc85_q2_flow.svg)

边界（开头和结尾的空档）只有一端有骨牌，直接写会多出两组特判。用一个经典技巧消掉它们：在串两端各加一张**虚拟骨牌**，左端设为 `'L'`、右端设为 `'R'`。

- 开头 `...L`：虚拟 `L` 与真实的 `L` 形成 `L … L` → 全填 `L` ✓
- 开头 `...R`：虚拟 `L` 与 `R` 形成 `L … R` → 保持 `'.'` ✓
- 结尾 `R...`：真实的 `R` 与虚拟 `R` 形成 `R … R` → 全填 `R` ✓
- 结尾 `L...`：真实的 `L` 与虚拟 `R` 形成 `L … R` → 保持 `'.'` ✓

四种边界行为全部由同一套规则给出。于是：

```text
1. s = "L" + dominoes + "R"，m = n + 2
2. i = 0
3. while i < m:
       j = i + 1；while s[j] == '.'：j++        # 找到下一个已定向骨牌
       填 s[i+1 .. j-1]：按四种组合之一处理
       i = j
4. 返回 s[1 .. n]
```

填充 `R … L` 时用左右双指针 `l = i+1, r = j-1`，只要 `l < r` 就 `s[l++] = 'R'; s[r--] = 'L'`，循环结束条件天然处理了「长度为奇数时正中间留 `'.'`」。

### 3.4 示例演算

![示例 2 的六个空档与处理结果](images/wc85_q2_walkthrough.svg)

对 `dominoes = ".L.R...LR..L.."`，加上哨兵后共有 6 个空档：

| # | 空档（含两端） | 组合 | 处理 |
|---|----------------|------|------|
| 1 | 哨兵 `L` ␣ `.` ␣ `L` | `L … L` | 首位填 `L` |
| 2 | `L` ␣ `.` ␣ `R` | `L … R` | 保持 `'.'` |
| 3 | `R` ␣ `...` ␣ `L` | `R … L` | 填 `R R . L L`（中间留 `'.'`） |
| 4 | `L` ␣ `R` | 相邻无空档 | 跳过 |
| 5 | `R` ␣ `..` ␣ `L` | `R … L` | 填 `R L`（无中间位） |
| 6 | `L` ␣ `..` ␣ 哨兵 `R` | `L … R` | 末尾保持 `'..'` |

拼接得到 `"LL.RR.LLRRLL.."`，与示例输出一致。

## 4. 算法细节

1. **哨兵是本题最大的简化**：不加哨兵就必须分别处理「首个 `L` 之前」「首个 `R` 之前」「末个 `L` 之后」「末个 `R` 之后」四种情况，且「整串没有 `L` 也没有 `R`」还要再特判一次。
2. **填充顺序**：`R … L` 必须从两端向中间填，用 `l < r` 控制，这样奇数长度时正中间那张**不会被任何一边覆盖**，自动保持 `'.'`。
3. **`j` 的越界保护**：C++ 里 `while (j < m && s[j] == '.') ++j;` 之后要判断 `j >= m` 再访问 `s[j]`——虽然 `std::string` 的 `s[size()]` 在标准里能读到 `'\0'`，但那属于「碰巧对」，不该依赖。Python 里越界会直接抛 `IndexError`，我第一版代码就是在这里崩的。
4. **字符串不可变**：Python 用 `list(s)` 就地改，最后 `"".join(...)` 一次成型；`str` 拼接在 $10^5$ 长度下是 $O(n^2)$。
5. **一次遍历**：`i` 只前进不回头，每个位置至多被访问两次（一次找 `j`、一次填充），总线性。
6. **返回切片**：`s.substr(1, n)` / `s[1:-1]`，长度恰为 $n$，不会把哨兵带出去。

## 5. 正确性证明

**引理 1（局部性）**：设 $i < j$ 且 $s[i], s[j]$ 非 `'.'`，中间全为 `'.'`。则这一段内每个位置的最终状态只取决于 $s[i]$、$s[j]$ 与空档长度 $g = j - i - 1$，与空档外部无关。

**证明**：力每秒只传播一条边，且只有 `'.'` 能受力改变、`'L'`/`'R'` 一旦确定方向就不再改变（题面明确「正在倒下的骨牌不会对其它正在倒下或已经倒下的骨牌施加额外的力」）。因此空档内部任一点只能被来自 $i$（向右推）与来自 $j$（向左推）的力影响；$i$ 左侧与 $j$ 右侧的骨牌距离更远，其力要先穿过 $i$ 或 $j$，而后者状态已固定、不会传导，故不产生影响。∎

**引理 2（四种组合的最终形态）**：对引理 1 的空档，最终形态为

1. $s[i]=s[j]=\text{'R'}$：全部为 `'R'`；
2. $s[i]=s[j]=\text{'L'}$：全部为 `'L'`；
3. $s[i]=\text{'L'}, s[j]=\text{'R'}$：全部保持 `'.'`；
4. $s[i]=\text{'R'}, s[j]=\text{'L'}$：位置 $i+t$ 与 $j-t$（$1 \le t \le \lfloor g/2 \rfloor$）分别为 `'R'` 与 `'L'`；若 $g$ 为奇数，正中间 $m=(i+j)/2$ 保持 `'.'`。

**证明**：逐条归纳。

1. 第 1 秒时，$i$ 向右推 $i+1$，它变 `'R'`；第 $t$ 秒时 $i+t-1$ 已变 `'R'` 并向右推 $i+t$，故第 $g$ 秒后全部为 `'R'`。同向推力只来自左方，从不冲突。
2. 与 1 对称，逐秒从右向左变 `'L'`。
3. $i$ 处为 `'L'`，只向左推；$j$ 处为 `'R'`，只向右推。空档内每张骨牌的两侧都不会出现朝向自己的推力，故永远保持 `'.'`。
4. 第 $t$ 秒时，由 $i$ 向右的推力使 $i+t$ 变 `'R'`（$1 \le t \le g$）；由 $j$ 向左的推力使 $j-t$ 变 `'L'`（$1 \le t \le g$）。两股波相遇的位置由 $i+t = j-t$ 决定，即 $t = (g+1)/2$。
   - 若 $g$ 为偶数（$g = 2h$），$(g+1)/2$ 不是整数，两股波永不在同一张骨牌上会合：第 $h$ 秒时分别推到 $i+h$ 与 $j-h = i+h+1$ 两张**相邻**骨牌，恰好把空档填满，故全部为 `R`/`L` 各半。
   - 若 $g$ 为奇数（$g = 2h+1$），$(g+1)/2 = h+1$ 为整数，正中间 $m = i+h+1 = j-h-1$ 在第 $h+1$ 秒同时受到左方「推右」与右方「推左」两股力，受力平衡，保持 `'.'`；其余位置仍按上式被填满。
   ∎

**引理 3（哨兵正确）**：把 $s[-1]$ 视为 `'L'`、$s[n]$ 视为 `'R'`，即可用引理 2 的四种组合精确描述首尾两段空档。

**证明**：首段（$i = -1$，$j$ 为首个非 `'.'` 位置）：左端真实情况是「没有骨牌」，等价于「左方推力不存在」。虚拟 `'L'` 只向左推、不向右推，恰好在空档内不产生任何向右的力；若 $s[j] = \text{'L'}$ 则组合为 `L … L`，空档被 $j$ 向左推满为 `'L'`，符合「开头一串 `'.'` 遇到 L 全变 L」；若 $s[j] = \text{'R'}$ 则组合为 `L … R`，保持 `'.'`，符合「R 向右推、不会波及左侧」。尾段（$j = n$，虚拟 `'R'`）完全对称：$s[i]=\text{'R'}$ 时 `R … R` 推满为 `'R'`，$s[i]=\text{'L'}$ 时 `L … R` 保持 `'.'`。∎

**定理**：算法输出的字符串等于多米诺的最终状态。

**证明**：算法把整串唯一地划分为若干空档（相邻两个已定向位置之间，含首尾两段），每个空档按其两端组合、依引理 2 填出最终形态；划分互不重叠且覆盖全部 `'.'` 位置，已定向位置保持原值。由引理 1，各空档互不影响，故拼接即全局最终状态；由引理 3，首尾两段的哨兵处理与真实物理一致。因此输出等于真实最终状态。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`i` 单调前进、`j` 也单调前进，两指针合计走 $O(n)$ 步；填充时每个 `'.'` 位置至多被写一次，总计 $O(n)$。
- **空间**：$O(n)$。哨兵版把串复制为长度 $n+2$ 的新串（C++ 的 `s.substr` 与 Python 的 `join` 各再产生一份结果），除此之外只有常数个指针。若要求原地修改，可去掉哨兵、单独处理首尾，空间降到 $O(1)$（不含入参）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string pushDominoes(string dominoes) {
        int n = dominoes.size();
        // 左右各加一个虚拟骨牌：左端视作 'L'（挡住左边），右端视作 'R'（挡住右边）
        string s = "L" + dominoes + "R";
        int m = s.size();
        int i = 0;
        while (i < m) {
            if (s[i] == '.') { ++i; continue; }
            int j = i + 1;
            while (j < m && s[j] == '.') ++j;      // (i, j) 是两枚已确定骨牌之间的空档
            if (j >= m) break;                     // 已到最右的虚拟骨牌，后面没有空档
            if (s[i] == s[j]) {
                for (int t = i + 1; t < j; ++t) s[t] = s[i];   // R...R / L...L：同向推满
            } else if (s[i] == 'R' && s[j] == 'L') {
                int l = i + 1, r = j - 1;
                while (l < r) { s[l++] = 'R'; s[r--] = 'L'; }  // R...L：两端对推，中间可能留下 '.'
            }
            // L...R：互相背离，空档保持 '.'
            i = j;
        }
        return s.substr(1, n);   // 去掉两端虚拟骨牌
    }
};
```

### Python

```python
class Solution:
    def pushDominoes(self, dominoes: str) -> str:
        # 左右各加一个虚拟骨牌：左端 'L'、右端 'R'，把边界并入同一套规则
        s = ["L"] + list(dominoes) + ["R"]
        m = len(s)
        i = 0
        while i < m:
            if s[i] == ".":
                i += 1
                continue
            j = i + 1
            while j < m and s[j] == ".":
                j += 1
            if j >= m:                       # 已到最右的虚拟骨牌，后面没有空档
                break
            if s[i] == s[j]:
                for t in range(i + 1, j):
                    s[t] = s[i]              # R...R / L...L：同向推满
            elif s[i] == "R" and s[j] == "L":
                l, r = i + 1, j - 1
                while l < r:                 # R...L：两端对推，正中间可能留下 '.'
                    s[l] = "R"
                    s[r] = "L"
                    l += 1
                    r -= 1
            # L...R：互相背离，空档保持 '.'
            i = j
        return "".join(s[1:-1])
```

> 💡 两份代码均通过 2 个官方示例与 `"..."`、`"R"`、`"L"`、`"R...."`、`"...L"`、`"R...L"` 等边界用例；另与「逐秒模拟」的独立暴力在 $n \le 9$ 的全部 $3^n$ 量级随机串上对拍 400 组，`mismatch = 0`；$n = 10^5$ 的随机串各耗时约 0.01 秒（C++）/ 0.02 秒（Python）。

## 8. 边界情况与易错点

1. **全 `'.'` 的串**：没有任何已定向骨牌，哨兵法下只会遇到「哨兵 `L` … 哨兵 `R`」这一个空档，属 `L … R`，正确保持原样。
2. **开头一段 `'.'` 后面跟 `R`**：必须保持 `'.'` 而不是变 `R`——右边的 `R` 只向右推。这是最常见的错误，哨兵 `'L'` 恰好把这种情况归入 `L … R`。
3. **结尾一段 `'.'` 前面是 `L`**：同理保持 `'.'`。
4. **`R … L` 且空档长度为奇数**：正中间那张必须保持 `'.'`，用 `while (l < r)`（严格小于）即可，写成 `l <= r` 会让中间被后写的一方覆盖。
5. **`R … L` 且空档长度为偶数**：如 `"R..L"`，应得 `"RRLL"`，中间**没有**剩余 `'.'`。
6. **`j` 越界**：找空档右端时要先判 `j < m` 再访问 `s[j]`；Python 会直接抛 `IndexError`。
7. **相邻已定向骨牌**：如 `"LR"`，`j = i + 1`，填充循环 `i+1 .. j-1` 为空，天然跳过，不要写成死循环。
8. **$n = 1$**：单张骨牌，任何取值都直接返回原串。
9. **不要真的按秒模拟**：$O(n^2)$ 在 $10^5$ 上必然 TLE，这是本题区分度所在。
