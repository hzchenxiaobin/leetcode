# LeetCode 新 21 点 题解

## 1. 题目概述

- **标题 / 题号**：新 21 点（#837，medium）
- **链接**：https://leetcode.cn/problems/new-21-game/
- **来源**：LeetCode 第 85 场周赛 Q3
- **难度**：中等
- **标签**：数学、动态规划、滑动窗口、概率与统计

**题意**：Alice 从 $0$ 分开始。只要当前分数 **严格小于** $k$，她就从 $[1, \text{maxPts}]$ 中等概率随机抽取一个整数累加；一旦分数 **$\ge k$** 就立即停止抽牌。问她最终分数**不超过 $n$** 的概率。与标准答案误差在 $10^{-5}$ 以内即算通过。

**约束**：

- $0 \le k \le n \le 10^4$
- $1 \le \text{maxPts} \le 10^4$

## 2. 示例

**示例 1**

```text
输入：n = 10, k = 1, maxPts = 10
输出：1.00000
解释：起手 0 < 1 必须抽一张，抽到的数在 [1,10] 内，随后立即停止；
     任何结果都 ≤ n = 10，概率为 1。
```

**示例 2**

```text
输入：n = 6, k = 1, maxPts = 10
输出：0.60000
解释：同样只抽一张，10 种等可能结果里只有 1..6 满足要求，概率 6/10 = 0.6。
```

**示例 3**

```text
输入：n = 21, k = 17, maxPts = 10
输出：0.73278
解释：需要做多轮抽牌的概率递推，答案约 0.73278（误差 1e-5 内）。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是按「抽取轮数」做 DP，或者把所有可能的抽取序列枚举出来。抽取轮数最多 $k$ 轮、每轮 $\text{maxPts}$ 种选择，序列总数是 $\text{maxPts}^{k}$ 级别的——$k = 10^4$ 时完全不可行。

退一步可以写一个「朴素 DP」：设 $dp[i]$ 为**过程中恰好停在 $i$ 分**的概率，则

$$dp[i] = \frac{1}{\text{maxPts}} \sum_{j = \max(0, i - \text{maxPts})}^{i-1} [j < k] \cdot dp[j]$$

直接按这个式子对每个 $i$ 累加窗口内 $O(\text{maxPts})$ 项，复杂度 $O(n \cdot \text{maxPts}) = 10^8$：C++ 勉强能过，Python 必超时，而且完全没必要——窗口是滑动前进的，可以做到 $O(1)$ 转移。

### 3.2 核心观察：状态含义 + 滑动窗口

![dp 数组表示恰好停在 i 分的概率，成功区为 k 到 n](images/wc85_q3_state_dp.svg)

**状态定义**是本题最容易被绕晕的地方。必须区分两种理解：

- $dp[i]$ 表示「Alice **最终**得分为 $i$」的概率，那么只有 $i \ge k$ 有意义；
- $dp[i]$ 表示「**过程中某一刻** Alice 的分数恰好为 $i$」的概率，那么 $i < k$ 的状态会继续转移，$i \ge k$ 的状态就永远停在那里。

采用第二种定义，转移就非常干净：

$$dp[0] = 1, \qquad dp[i] = \frac{1}{\text{maxPts}} \sum_{j \,:\, i - \text{maxPts} \le j \le i-1,\ j < k} dp[j]$$

其中 $j < k$ 这个条件至关重要：**只有分数还小于 $k$ 时才会再抽一张**，$j \ge k$ 的 $dp[j]$ 已经「停住」，不能再向外转移。最终答案是

$$\text{ans} = \sum_{i = k}^{n} dp[i]$$

因为分数一旦 $\ge k$ 就定格不动，落在 $[k, n]$ 的概率就是答案；落在 $> n$ 的部分正是失败情形，不参与求和。

### 3.3 算法流程：维护窗口和

![滑动窗口维护转移所需的区间和](images/wc85_q3_window.svg)

把转移式里的求和记作窗口 $W_i = \sum_{j = \max(0,i-\text{maxPts})}^{i-1} [j<k]\, dp[j]$。从 $i-1$ 到 $i$，窗口只做三件事：进一项、出一项、算一次值。

```text
1. 特判：k == 0            → 返回 1.0
2. 特判：n >= k-1+maxPts   → 返回 1.0
3. dp[0] = 1，W = 0
4. for i = 1 .. n:
       if i-1 < k:                       W += dp[i-1]        # 新进窗口
       if 0 <= i-maxPts-1 < k:           W -= dp[i-maxPts-1] # 滑出窗口
       dp[i] = W / maxPts
5. 返回 sum(dp[k..n])
```

两个提前返回都值得写：

- $k = 0$：一开始就满足「分数 $\ge k$」，一张都不抽，分数为 $0 \le n$，概率 1。
- $n \ge k - 1 + \text{maxPts}$：分数最多停在 $k-1$，再抽一张最大也只有 $k-1+\text{maxPts} \le n$，所以**任何**结果都 $\le n$，概率 1。这条特判还顺带避免了大数组分配。

### 3.4 示例演算

![示例 3 的 dp 递推表](images/wc85_q3_walkthrough.svg)

对 $n=21, k=17, \text{maxPts}=10$：前 10 步窗口还没满，且 $dp[j]$ 从没被移出过，于是 $W_i = \sum_{j<i} dp[j]$ 恰好满足 $W_i = 1.1\,W_{i-1}$，得 $dp[i] = 0.1 \cdot 1.1^{\,i-1}$：

| $i$ | $W_i$ | $dp[i]$ | 说明 |
|-----|-------|---------|------|
| 1 | 1.0 | 0.1 | 只有 $dp[0]$ 在窗口里 |
| 2 | 1.1 | 0.11 | 加入 $dp[1]$ |
| 3 | 1.21 | 0.121 | 加入 $dp[2]$ |
| 10 | 2.35795 | 0.23579 | 窗口第 10 项 |
| 11 | 1.59374 | 0.15937 | $dp[0]$ 滑出窗口 |
| 17 | 1.85711 | 0.18571 | 首次进入成功区，开始累加 |
| 21 | 1.03492 | 0.10349 | 最后一项 |

$$\text{ans} = 0.18571 + 0.16799 + 0.14851 + 0.12707 + 0.10349 = 0.73278$$

与示例输出一致。

## 4. 算法细节

1. **窗口的「进出」条件不对称**：进窗口时判断 `i-1 < k`，出窗口时要同时判断下标非负**且** `< k`。因为 $j \ge k$ 的项从来没被加进窗口，滑出时也就不该减——漏掉这个判断会把答案算小。
2. **先加后减的顺序**：$i-1$ 与 $i-\text{maxPts}-1$ 一定不相等（$\text{maxPts} \ge 1$），顺序无所谓，但要保证「加」的是当前新进的那一项。
3. **数组只开到 $n$**：$dp$ 的下标到 $n$ 为止，滑出项的下标 $i-\text{maxPts}-1$ 可能为负，必须先判 `>= 0` 再访问。
4. **浮点累加**：$n \le 10^4$，误差累积远小于 $10^{-5}$ 的容差；用 `double` / Python `float` 足够，不需要高精度。
5. **答案是求和而不是单个 $dp[n]$**：$dp[n]$ 只是「恰好停在第 $n$ 分」的概率，$[k, n]$ 里每个值都要算进去（示例 3 正是 5 项相加）。
6. **特判顺序**：先判 $k=0$ 再判 $n \ge k-1+\text{maxPts}$，两者都返回 1.0，顺序其实无关，但 $k=0$ 时 $k-1$ 为负，先判更安全。
7. **不用二维 DP**：本题无「轮数」维度，因为分数一旦确定，后续与轮数无关——这正是它能压到 $O(n)$ 的原因。

## 5. 正确性证明

**引理 1（状态可达性）**：对任意 $i \ge 0$，$dp[i] > 0$ 的充要条件是 $i = 0$ 或「存在一条从 $0$ 出发、步长 $\in [1, \text{maxPts}]$、中途所有前缀和都 $< k$ 的路径到达 $i$」。

**证明**：$dp$ 的递推正是按「一步转移」构造的：$dp[0]=1$ 对应空路径；递推只从 $j<k$ 的状态向 $j+d$ 转移，故每条被计入的路径都满足「转移出 $j$ 时 $j<k$」，即前缀和 $<k$。反之任何满足条件（中途前缀和 $<k$）的路径，其每个前缀的转移都被递推计入。∎

**引理 2（递推式正确）**：按 3.2 的递推计算出的 $dp[i]$ 等于「Alice 过程中某一刻分数恰为 $i$」的概率。

**证明**：对到达 $i$ 所经过的抽牌次数做归纳。$i=0$ 时为 1。设对 $< i$ 均成立。分数恰为 $i$ 当且仅当：上一步停在某个 $j \in [i-\text{maxPts}, i-1]$ 且 $j < k$（否则不会继续抽），并且抽到 $i - j \in [1, \text{maxPts}]$（概率 $1/\text{maxPts}$）。这些事件对不同的 $j$ 互斥（上一步的分数唯一），故概率相加即得递推式；$j$ 的取值范围保证了抽到的点数合法。∎

**引理 3（终止性）**：每抽一张分数至少加 1，故抽牌轮数不超过 $k$，过程必然以概率 1 在有限步内停止。

**证明**：只要还在抽牌，分数就 $< k$；每轮 $+1$ 以上，故至多 $k$ 轮后分数 $\ge k$，此时停止。∎

**定理**：算法返回的概率等于「最终分数不超过 $n$」的概率。

**证明**：由引理 3，过程必然终止于某个分数 $s$。终态集合 $\{s : s \ge k\}$ 与「过程中某一刻分数为 $i$」的事件构成完备划分：$s = i \ge k$ 的路径，在第一次到达 $i$ 时停止，对应事件「过程中分数恰为 $i$」且不再向外转移（递推中 $j \ge k$ 的项被排除在转移之外，正体现了这一点）。于是

$$\Pr[\text{终态} = i] = dp[i]\quad (i \ge k),\qquad \Pr[\text{成功}] = \sum_{i=k}^{n} \Pr[\text{终态}=i] = \sum_{i=k}^{n} dp[i]$$

而滑窗实现逐项复现了引理 2 的求和（进窗口加 $dp[i-1]$、出窗口减 $dp[i-\text{maxPts}-1]$，并始终只保留 $j<k$ 的项），故数值上与递推式完全一致。∎

**引理 4（两个特判的正确性）**：$k = 0$ 或 $n \ge k-1+\text{maxPts}$ 时答案为 1。

**证明**：$k=0$ 时分数 0 已满足停止条件，终态 $0 \le n$。若 $n \ge k-1+\text{maxPts}$，终态 $s$ 是最后一次抽牌的结果；抽牌前分数 $< k$ 即 $\le k-1$，加上点数至多 $\text{maxPts}$，故 $s \le k-1+\text{maxPts} \le n$，必成功。∎

## 6. 复杂度分析

- **时间**：$O(n)$（未触发特判时）。循环 $n$ 次，每次 $O(1)$ 的加法、减法、除法；最后求和 $O(n - k)$。
- **空间**：$O(n)$，存放 $dp[0..n]$。若只需答案，可把 $dp$ 换成滑动窗口式的循环数组（$O(\text{maxPts})$），但 $n \le 10^4$ 时没必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    double new21Game(int n, int k, int maxPts) {
        if (k == 0) return 1.0;                      // 一开始就不抽牌，分数 0 必不超过 n
        if (n >= k - 1 + maxPts) return 1.0;         // 最多停在 k-1，再抽一张也不会超过 n
        vector<double> dp(n + 1, 0.0);               // dp[i]：过程中恰好停在 i 分的概率
        dp[0] = 1.0;
        double window = 0.0;                          // 窗口 = Σ dp[j]，j ∈ [i-maxPts, i-1] 且 j < k
        for (int i = 1; i <= n; ++i) {
            if (i - 1 < k) window += dp[i - 1];       // 只有 j < k 的状态还能继续抽牌
            if (i - maxPts - 1 >= 0 && i - maxPts - 1 < k) window -= dp[i - maxPts - 1];
            dp[i] = window / maxPts;                  // 每个 j 以 1/maxPts 的概率一步跳到 i
        }
        double ans = 0.0;
        for (int i = k; i <= n; ++i) ans += dp[i];    // 停在 [k, n] 即成功
        return ans;
    }
};
```

### Python

```python
class Solution:
    def new21Game(self, n: int, k: int, maxPts: int) -> float:
        if k == 0:
            return 1.0                     # 一开始就不抽牌，分数 0 必不超过 n
        if n >= k - 1 + maxPts:
            return 1.0                     # 最多停在 k-1，再抽一张也不会超过 n
        dp = [0.0] * (n + 1)               # dp[i]：过程中恰好停在 i 分的概率
        dp[0] = 1.0
        window = 0.0                       # Σ dp[j]，j ∈ [i-maxPts, i-1] 且 j < k
        for i in range(1, n + 1):
            if i - 1 < k:
                window += dp[i - 1]        # 只有 j < k 的状态还能继续抽牌
            if 0 <= i - maxPts - 1 < k:
                window -= dp[i - maxPts - 1]
            dp[i] = window / maxPts        # 每个 j 以 1/maxPts 的概率一步跳到 i
        return sum(dp[k:])                 # 停在 [k, n] 即成功
```

> 💡 两份代码均通过 3 个官方示例；另与「$O(n \cdot \text{maxPts})$ 朴素 DP」独立实现对拍 200 组随机数据（$n \le 40$、$k \le n$、$\text{maxPts} \le 12$），最大偏差 $< 10^{-9}$，`mismatch = 0`；$n = k = 10^4$、$\text{maxPts} = 10^4$ 时耗时约 5 毫秒（Python）/ 不到 1 毫秒（C++）。

## 8. 边界情况与易错点

1. **$k = 0$**：直接返回 1.0。若漏掉这个特判，循环里 `dp[k:]` 为空、返回 0，与正确答案 1 相反。
2. **$n \ge k-1+\text{maxPts}$**：此时答案必为 1，写特判可避免「$dp$ 数组只有 $n+1$ 项、窗口取样越界」以及大数组分配。
3. **`j < k` 条件漏写**：若把 $j \ge k$ 的 $dp[j]$ 也加进窗口，会把「已经停住的概率」再转移出去，导致概率总量超过 1。
4. **滑出条件只判了 `>= 0`**：必须同时判 `< k`，否则会减去从未加入的项（结果为负或偏小）。
5. **答案是 `dp[k..n]` 之和**：只取 $dp[n]$ 或误取 `dp[0..n]`（含 $<k$ 的部分）都是错的。
6. **整数除法**：C++ 里 `window / maxPts` 中 `window` 是 `double`，不会截断；Python 的 `/` 本身就是浮点除法，勿误用 `//`。
7. **返回类型**：C++ 返回 `double`，精度足够；比较判题用的是 $10^{-5}$ 的绝对/相对误差。
8. **概率上界**：所有 $dp[i] \le 1$，累加不会溢出；但若误用 `float` 在 $10^4$ 次加法后仍可接受，用 `double` 更稳妥。
