# LeetCode 字符串中的查找与替换 题解

## 1. 题目概述

- **标题 / 题号**：字符串中的查找与替换（#833，medium）
- **链接**：https://leetcode.cn/problems/find-and-replace-in-string/
- **来源**：LeetCode 第 84 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序

**题意**：给定字符串 $s$ 与三个等长数组 `indices`、`sources`、`targets`，共 $k$ 个替换操作。第 $i$ 个操作：若**原串** $s$ 在位置 `indices[i]` 处出现的子串恰好等于 `sources[i]`，则把它替换成 `targets[i]`；否则什么也不做。所有替换**同时发生**（互不影响索引），且测试数据保证各操作的区间**不重叠**。返回替换后的字符串。

**约束**：

- $1 \le |s| \le 1000$
- $k = \text{indices.length} = \text{sources.length} = \text{targets.length}$，$1 \le k \le 100$
- $0 \le \text{indices}[i] < |s|$
- $1 \le |\text{sources}[i]|, |\text{targets}[i]| \le 50$
- $s$、`sources[i]`、`targets[i]` 仅含小写字母

**关键信息**：三条规则决定了解法形态——**基于原串比对**、**同时发生**、**互不重叠**。前两条否定了「边替换边用新串」的做法，第三条否定了「需要处理区间冲突」的复杂性。

## 2. 示例

**示例 1**

```text
输入：s = "abcd", indices = [0,2], sources = ["a","cd"], targets = ["eee","ffff"]
输出："eeebffff"
解释："a" 从索引 0 开始，替换为 "eee"；"cd" 从索引 2 开始，替换为 "ffff"。
```

**示例 2**

```text
输入：s = "abcd", indices = [0,2], sources = ["ab","ec"], targets = ["eee","ffff"]
输出："eeecd"
解释："ab" 在索引 0 处匹配，替换为 "eee"；"ec" 与 s[2..3] = "cd" 不同，不替换，
      最终为 "eee" + "cd" = "eeecd"。
```

**示例 3（补充，索引乱序 + 末位操作）**

```text
输入：s = "vmokgggqzp", indices = [3,5,1],
      sources = ["kg","ggq","mo"], targets = ["s","so","bfr"]
输出："vbfrssozp"
解释：按索引升序处理：1 处 "mo"→"bfr"，3 处 "kg"→"s"，5 处 "ggq"→"so"。
```

## 3. 解题思路

### 3.1 暴力思路

最容易想到、也最容易写错的做法是「按 `indices` 的顺序逐个调用 `string::replace`」：

```text
for i in 0..k-1:
    if s 在 indices[i] 处匹配 sources[i]:
        s = s[0..indices[i]) + targets[i] + s[indices[i]+|sources[i]|..)
```

它错在两处：

1. **索引漂移**：第一次替换改变了字符串长度，后续操作的 `indices[i]` 指的是**原串**下标，此时已指向别的位置；
2. **比对对象错误**：第 2 次之后的匹配检查会用**已被修改**的串，违背「同时发生」。

即便改成「按 `indices` 从大到小处理」来避免漂移，也仍然要求先比对、后统一改写——这正是正解的思路起点。

### 3.2 核心观察：先比对原串，再一次性拼接

![所有替换基于原串，一次扫描拼出结果](images/wc84_q2_snapshot.svg)

因为有「互不重叠」的保证，被替换的区间两两不交，所以可以：

1. 把所有操作**按 `indices` 升序**排列；
2. 维护指针 `cur`，表示「原串中尚未输出的部分」的起点；
3. 依次处理每个操作：若在原串位置 $p$ 处匹配，就先输出 $s[\text{cur}..p)$、再输出 `target`，并令 $\text{cur} = p + |\text{source}|$；若不匹配，直接跳过（`cur` 不变）；
4. 所有操作处理完后，补上尾段 $s[\text{cur}..n)$。

由于操作按起点递增、区间互不重叠，`cur` 单调不减，每段原串都只会被输出一次。所有比对用的都是**原串** $s$ 的片段，天然满足「同时发生」。

### 3.3 算法流程

![按索引升序的单次扫描](images/wc84_q2_sorted_scan.svg)

```text
1. order = [0..k-1] 按 indices 升序排序
2. res = "", cur = 0
3. for id in order:
       p = indices[id]
       若 p < cur: 跳过（与前一个已替换区间重叠，题目保证不会发生，防御性处理）
       若 s[p..p+|sources[id]|) == sources[id]:
              res += s[cur..p)
              res += targets[id]
              cur = p + |sources[id]|
4. res += s[cur..n)
5. 返回 res
```

### 3.4 示例演算

![示例演算：索引 2 的 source 对不上](images/wc84_q2_walkthrough.svg)

对示例 2（`s = "abcd"`，`indices = [0,2]`，`sources = ["ab","ec"]`，`targets = ["eee","ffff"]`）：

| 处理顺序 | 索引 | source | 原串对应片段 | 是否匹配 | 处理 |
|----------|------|--------|--------------|----------|------|
| 1 | 0 | "ab" | "ab" | ✓ | 输出 `eee`，`cur = 2` |
| 2 | 2 | "ec" | "cd" | ✗ | 跳过，`cur` 仍为 2 |

收尾追加 $s[2..4)$ = `"cd"`，结果 `"eee" + "cd" = "eeecd"` ✓。

## 4. 算法细节

1. **排序还是建桶**：$k \le 100$，按 `indices` 排序 $O(k \log k)$ 足够；也可以把操作按位置放进哈希表 `map<int,int>`，然后顺序扫描原串，效果相同。排序写法更通用（不依赖 $|s|$ 的大小）。
2. **匹配检查**：C++ 用 `s.compare(p, src.size(), src) == 0`。注意 `compare(pos, count, str)` 比较的是 $s[p,\ p+\text{count})$ 与 `str`：当剩余长度不足时，参与比较的子串会变短、长度与 `str` 不等，返回值必然非 0，因此**不需要**额外判 $p + |\text{src}| \le n$。Python 用 `s.startswith(src, p)`，语义即「从 $p$ 开始的前缀匹配」，越界自动为 `False`。
3. **`cur` 的含义**：始终指向「原串里下一个还没写进结果的下标」。匹配时先补 $s[\text{cur}..p)$，再写 `target`，最后把 `cur` 推到区间末尾。
4. **不匹配就什么都不做**：这一段原串没有操作覆盖，留到下一次匹配（或收尾）时被整体追加，不需要单独写。
5. **`p < cur` 的防御**：题目保证不重叠，正常不会触发；加上它可以避免 `s.substr(cur, p-cur)` 在 $p < \text{cur}$ 时出现负长度（C++ 会抛 `out_of_range`）。
6. **输出顺序即原串顺序**：排序后处理，`res` 的片段天然按原串从左到右排列，无需再做拼接后的重排。

## 5. 正确性证明

约定：称一个操作**有效**，当且仅当它在原串 $s$ 的 `indices[i]` 处匹配 `sources[i]`；有效操作的区间记作 $I_i = [p_i, p_i + |\text{source}_i|)$。

**引理 1（有效区间两两不交且可按起点排序）**：任意两个有效操作 $i \ne j$ 的区间 $I_i, I_j$ 满足 $p_i \ne p_j$，且若 $p_i < p_j$ 则 $p_i + |\text{source}_i| \le p_j$。

**证明**：题目保证「元素间不会重叠」，即任意两个操作的替换区间不重叠；有效操作是操作集合的子集，故其区间仍两两不交，端点不重叠即得 $p_i + |\text{source}_i| \le p_j$。若 $p_i = p_j$，两个长度为正的区间必然相交，与不重叠矛盾，故起点互异。∎

**引理 2（`cur` 单调且不越界）**：循环中 `cur` 单调不减，且始终满足 $0 \le \text{cur} \le n$；每次成功匹配时都有 $\text{cur} \le p$。

**证明**：`cur` 只在匹配时更新为 $p + |\text{source}|$，由引理 1，下一个处理的起点 $p' \ge p + |\text{source}| = \text{cur}$，故新 `cur` 不超过后续任何起点，也即 $\text{cur} \le p'$ 恒成立；`cur` 只在 $p \ge \text{cur}$ 且 $p + |\text{source}| \le n$ 时更新（匹配成功隐含 $p + |\text{source}| \le n$），故不越界。∎

**引理 3（每段原串恰好被输出一次）**：算法结束时，原串的每个下标恰好出现在结果的一个片段中，且片段顺序与原串一致。

**证明**：把原串按下标切成若干段：有效区间 $I_{i_1}, I_{i_2}, \dots$（按起点升序）以及它们之间的空隙。处理 $I_{i_t}$ 时输出的 $s[\text{cur}..p_{i_t})$ 正是 $I_{i_{t-1}}$ 与 $I_{i_t}$ 之间的空隙（或开头段），随后 `target` 覆盖 $I_{i_t}$，并把 `cur` 移到 $I_{i_t}$ 末尾；最后一段空隙由收尾的 $s[\text{cur}..n)$ 输出。由引理 2，各段互不重叠且覆盖 $[0, n)$，故每段恰好输出一次、顺序正确。无效操作不改变任何片段，被其「跳过的位置」仍属于某个空隙或有效区间，同样被输出。∎

**定理**：算法返回的字符串等于题目定义的「同时执行所有有效替换」的结果。

**证明**：题目要求的结果是把原串中每个**有效**操作的区间替换为对应 `targets[i]`、其余字符保持原样，并把结果按原顺序连接。由引理 3，算法输出的正是这些片段按原顺序的连接；区间内容被 `target` 替换、空隙内容原样保留，与定义一致。又因所有比对都发生在**原串** $s$ 上（`cur` 只用于输出、不参与比对），且替换是统一在拼接阶段完成的，故等价于「同时发生」。∎

## 6. 复杂度分析

- **时间**：$O(k \log k + n + \sum_i |\text{sources}_i|)$。排序为 $O(k \log k)$；每个操作做一次长度 $|\text{source}_i|$ 的比对（最坏 $O(k \cdot 50)$）；拼接结果串的总长度不超过 $n + \sum |\text{targets}_i|$，写入是线性的。
- **空间**：$O(k + n + \sum |\text{targets}_i|)$。`order` 占 $O(k)$，结果串占输出长度；若用哈希表按位置索引操作，额外空间为 $O(k)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string findReplaceString(string s, vector<int>& indices, vector<string>& sources, vector<string>& targets) {
        int k = indices.size();
        vector<int> order(k);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) { return indices[a] < indices[b]; });
        string res;
        int cur = 0;
        for (int id : order) {
            int p = indices[id];
            if (p < cur) continue;
            if (s.compare(p, sources[id].size(), sources[id]) == 0) {
                res += s.substr(cur, p - cur);
                res += targets[id];
                cur = p + sources[id].size();
            }
        }
        res += s.substr(cur);
        return res;
    }
};
```

### Python

```python
class Solution:
    def findReplaceString(self, s: str, indices: list[int], sources: list[str], targets: list[str]) -> str:
        order = sorted(range(len(indices)), key=lambda i: indices[i])
        res = []
        cur = 0
        for i in order:
            p = indices[i]
            if p < cur:
                continue
            if s.startswith(sources[i], p):
                res.append(s[cur:p])
                res.append(targets[i])
                cur = p + len(sources[i])
        res.append(s[cur:])
        return ''.join(res)
```

## 8. 边界情况与易错点

1. **索引乱序**：`indices` 不保证递增（如示例 3 的 `[3,5,1]`），必须先排序，否则 `cur` 会回退、输出错位。
2. **一个都不匹配**：所有操作都被跳过，结果就是原串 $s$；收尾的 `s.substr(cur)` 保证这一点。
3. **`compare` 的 `count` 必须取 `src.size()`**：只要 `count` 与 `str.size()` 相等，长度不等就一定返回非 0，越界检查可省。反过来，若图省事写成 `s.compare(p, n - p, src)` 之类，`count` 与 `src.size()` 不一致时可能出现「短前缀被判定相等」的假匹配。
4. **匹配失败不要推进 `cur`**：被跳过的位置要留给后续（或收尾）输出，否则会丢字符。
5. **替换后长度变化**：`target` 可以比 `source` 长或短，这正是必须先记下所有区间、最后统一拼接的原因。
6. **空 `source` 不可能出现**：约束保证 $|\text{sources}[i]| \ge 1$，所以不会出现「零长度替换」导致的死循环。
7. **`p < cur` 时不要调用 `substr`**：$p - \text{cur}$ 为负会让 C++ 抛异常；排序 + 不重叠保证不会走到，但防御性 `continue` 更安全。
8. **结果可能比原串短很多**：`targets` 可能都是空串之外的最短串，不要预设结果长度上界，动态拼接即可。

> 💡 **实测确认**：$s = \text{"abc"}$、`compare(1, 4, "bcde")` 返回 $-1$（短串更小），因此 `indices = [1]`、`sources = ["bcde"]` 这种「source 超出串尾」的输入不会被误判为匹配，结果保持 `"abc"`。测试用例已验证这一点。

**延伸思考**：如果取消「不重叠」的保证，问题就变成**区间调度**：同一位置可能有多个操作竞争，需要按题目规则（最长 `source`、或给出优先级）选择，选中后跳过其后与之重叠的操作，`cur` 仍单调推进，复杂度只增加一次排序。如果允许「链式替换」（用替换后的结果继续参与后续匹配），则必须反复扫描直到不再变化，最坏需要 $O(k)$ 轮，且要防止长度增长导致的死循环——这类需求通常直接改用正则的全局替换。
