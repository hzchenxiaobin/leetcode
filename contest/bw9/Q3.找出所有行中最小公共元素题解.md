# LeetCode 找出所有行中最小公共元素 题解

## 1. 题目概述

- **标题 / 题号**：找出所有行中最小公共元素（#1198，medium）
- **链接**：https://leetcode.cn/problems/find-smallest-common-element-in-all-rows/
- **来源**：LeetCode 第 9 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、二分查找、计数、矩阵

**题意**：给定矩阵 `mat`，其中**每一行都按递增序排列**（行内元素互不相同）。返回**所有行都出现过的元素**中的**最小值**；若没有公共元素，返回 $-1$。

**约束**：

- $1 \le mat.length, mat[i].length \le 500$
- $1 \le mat[i][j] \le 10^4$
- $mat[i]$ 按递增序排列

## 2. 示例

**示例 1**

```text
输入：mat = [[1,2,3,4,5],[2,4,5,8,10],[3,5,7,9,11],[1,3,5,7,9]]
输出：5
解释：5 是唯一在四行都出现的元素。
```

**示例 2**

```text
输入：mat = [[1,2,3],[2,3,4],[2,3,5]]
输出：2
```

**示例 3（补充）**

```text
输入：mat = [[1,7,11],[2,8,12],[3,9,13]]
输出：-1
解释：三行互不相交，没有公共元素。
```

## 3. 解题思路

### 3.1 暴力思路

不利用「行内有序」的条件，把每一行塞进哈希集合，然后做行间交集，最后取交集最小值；或者开一个值域 $10^4$ 的计数数组，逐行逐元素加一，扫到某个值计数恰为行数 $n$ 时记录。两种做法都是 $O(nm)$ 时间，但需要 $O(nm)$ 或 $O(V)$ 的额外空间，而且完全没吃到「**每行有序**」这个题面白送的属性——有序性通常意味着二分或者双指针，本题值得往这个方向压榨。

### 3.2 核心观察：候选只有第一行，判定靠二分

![核心观察：候选锁定第一行，有序行内二分判定](images/bw9_q3_binary_search_model.svg)

两条关键观察：

1. **公共元素必然出现在第一行**。若 $v$ 是所有行的公共元素，它当然出现在 `mat[0]` 里。于是候选集从「值域 $10^4$」直接缩小为「第一行的 $m$ 个元素」。
2. **「某行是否含 $v$」可以二分判定**。每行递增，判定 $v$ 是否出现在 `mat[i]` 中只需 $O(\log m)$ 的二分查找，而不是 $O(m)$ 的线性扫。

再把两件事串起来：**按顺序枚举第一行的元素**（第一行本身递增，所以枚举顺序就是值从小到大的顺序），对每个候选 $v$ 依次在第 $2 \sim n$ 行里二分查找；**第一个在所有行都命中的候选就是答案**，可以直接返回。无公共元素则枚举完第一行返回 $-1$。

> 💡 对比暴力：$O(nm)$ 的计数法把「候选」和「判定」都摊平了；本题的做法把候选压到 $m$ 个、把判定压到 $\log$ 级别，总代价 $O(m \cdot n \log m)$，在 $n = m = 500$ 时约 $2.4 \times 10^6$ 次比较，且额外空间 $O(1)$。

### 3.3 算法流程

![算法流程：按序枚举候选，逐行二分验证](images/bw9_q3_algorithm_flow.svg)

```text
1. for v in mat[0]：                       # 第一行递增，枚举序即值序
2.     inAll = true
3.     for i in 1..n-1：
4.         若 v 不在 mat[i] 中（二分查找）：
5.             inAll = false，跳出本层循环
6.     若 inAll：返回 v                     # 首个全命中候选即最小
7. 返回 -1                                  # 无公共元素
```

### 3.4 示例演算

![示例演算：示例 1 逐候选二分判定的过程](images/bw9_q3_example_walkthrough.svg)

以示例 1 的 `mat = [[1,2,3,4,5],[2,4,5,8,10],[3,5,7,9,11],[1,3,5,7,9]]` 为例：

| 候选 $v$ | 第 2 行 [2,4,5,8,10] | 第 3 行 [3,5,7,9,11] | 第 4 行 [1,3,5,7,9] | 结论 |
|---|---|---|---|---|
| 1 | ✗（无 1） | — | — | 换下一个 |
| 2 | ✓ | ✗（无 2） | — | 换下一个 |
| 3 | ✗（无 3） | — | — | 换下一个 |
| 4 | ✓ | ✗（无 4） | — | 换下一个 |
| 5 | ✓ | ✓ | ✓ | **返回 5** |

可以看到：候选按第一行顺序枚举，失败的候选**只判到第一处失败就停**（第 3 行、第 4 行直接跳过），而 5 是首个三行全命中的候选——由于枚举序即值序，无需再比较，立即返回。

## 4. 算法细节

1. **二分用「存在性判定」语义**：C++ 的 `std::binary_search` 返回布尔值恰好是「存在性」；Python 中 `bisect_left` 返回插入位置，需要再判 `row[i] == v`（以及 `i < len(row)`），两者语义等价。
2. **提前退出的写法**：内层循环条件把 `inAll` 写进循环判断（`i < n && inAll`），失败即跳出，避免多余行白做一次二分。
3. **正确性不依赖行内互异**：即使某行有重复值，`binary_search`/`bisect` 的存在性判定也依然正确——但按题意行严格递增，本就无重复。
4. **另一种 $O(nm)$ 做法（多指针归并）**：为每行维护一个指针，反复取各行当前值的最小者推进，当 $n$ 个指针所指值全部相等时即命中。复杂度更优，但代码繁琐；计数法（值域数组，每行累加，计数恰为 $n$ 的最小值）是「空间换时间」的第三条路，官方提示即指向它。
5. **值域很小不是必须利用的条件**：$10^4$ 的值域只是让计数法成为可能；二分做法对值域完全不敏感，可迁移性更强。

## 5. 正确性证明

**引理 1（候选集）**：若存在公共元素，则最小的公共元素 $v^\ast$ 满足 $v^\ast \in mat[0]$。

**证明**：公共元素按定义出现在每一行中，第一行自然包含；最小公共元素也是公共元素。∎

**引理 2（判定正确性）**：对递增数组 `row` 与候选 $v$，二分查找返回 true 当且仅当 $v$ 出现在 `row` 中。

**证明**：这是标准二分查找的完备性——每次比较排除一半区间且不排除任何可能位置：`row[mid] < v` 时 $v$ 只能在右半（递增性），`row[mid] > v` 时只能在左半，相等即命中。区间缩空仍未命中则不存在。∎

**引理 3（首个命中即最小）**：算法按第一行元素的顺序（即严格递增的值序）枚举候选，因此第一个「全行命中」的候选就是所有公共元素的最小者。

**证明**：设公共元素按从小到大为 $c_1 < c_2 < \cdots$（每个 $c_j$ 都在第一行中出现，由引理 1）。第一行严格递增，故枚举序列就是第一行本身，$c_1$ 是枚举序列的元素且一切先于 $c_1$ 被枚举的值都 $< c_1$，不可能是公共元素（$c_1$ 是最小公共元素），从而它们必在某行二分失败。于是算法恰在枚举到 $c_1$ 时首次全命中并返回。若不存在公共元素，所有候选都失败，返回 $-1$。∎

**定理**：算法返回所有行的最小公共元素；不存在时返回 $-1$。

**证明**：由引理 1，答案在候选集（第一行）内；由引理 2，每个候选的行内判定正确，故「全行命中」当且仅当候选是公共元素；由引理 3，返回值是公共元素中的最小者。∎

## 6. 复杂度分析

- **时间**：$O(m \cdot n \log m)$。最坏情况下第一行 $m$ 个候选、每个候选在 $n-1$ 行各做一次 $O(\log m)$ 二分；$n = m = 500$ 时约 $500 \times 500 \times 9 \approx 2.3 \times 10^6$ 次比较。实际远快于最坏值——多数候选在第一两行就被否决。
- **空间**：$O(1)$ 额外空间。不复制、不建哈希、不开值域数组，这是相对计数法的显著优势。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int smallestCommonElement(vector<vector<int>>& mat) {
        int n = mat.size();
        for (int v : mat[0]) {                   // 答案必是第一行中的元素
            bool inAll = true;
            for (int i = 1; i < n && inAll; ++i)
                if (!binary_search(mat[i].begin(), mat[i].end(), v))
                    inAll = false;                // 该行没有 v，换下一个候选
            if (inAll) return v;                  // 第一行递增，首个命中即最小
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def smallestCommonElement(self, mat: list[list[int]]) -> int:
        from bisect import bisect_left
        for v in mat[0]:                    # 答案必是第一行中的元素
            ok = True
            for row in mat[1:]:
                i = bisect_left(row, v)     # 行内有序 → 二分查找
                if i == len(row) or row[i] != v:
                    ok = False              # 该行没有 v，换下一个候选
                    break
            if ok:
                return v                    # 第一行递增，首个命中即最小
        return -1
```

## 8. 边界情况与易错点

1. **无公共元素**：全部候选失败后返回 $-1$（补充示例），别在循环里忘记这条兜底路径。
2. **只有一行**：$n = 1$ 时任何 $mat[0][j]$ 都满足「在所有行出现」，答案是 $mat[0][0]$——内层循环体一次都不执行，`inAll` 保持 true，代码天然正确。
3. **只有一列**：$m = 1$ 时候选只有一个，一次判定即出结论。
4. **`bisect_left` 的判等**：返回位置可能等于 `len(row)`（越界），必须先判越界再判等，顺序颠倒会数组越界。
5. **不要假设「最小值在所有行都靠前」**：例如第一行是 [1, 90]，答案完全可能是 90；判定顺序由第一行决定，与其他行无关。
6. **别把「每行有序」误读为「按列也有序」**：列方向毫无保证（示例 1 中第 1 列是 1,2,3,1），任何依赖列序的优化都不成立。
7. **计数法的坑**：若改用「计数 == 行数」判定，依赖行内无重复；题面递增保证这一点，但若值域扩大（如 $10^9$）计数法立刻失效，而二分法不受影响——这是选择二分作为主解的另一个理由。
