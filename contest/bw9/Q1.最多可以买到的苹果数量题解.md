# LeetCode 最多可以买到的苹果数量 题解

## 1. 题目概述

- **标题 / 题号**：最多可以买到的苹果数量（#1196，easy）
- **链接**：https://leetcode.cn/problems/how-many-apples-can-you-put-into-the-basket/
- **来源**：LeetCode 第 9 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、排序

**题意**：给定数组 `weight`，其中 $weight[i]$ 是第 $i$ 个苹果的重量。有一个承重上限为 **5000** 的篮子，返回最多能向篮子里放入**多少个**苹果（只看个数，不看是哪几个）。

**约束**：

- $1 \le weight.length \le 10^3$
- $1 \le weight[i] \le 10^3$

## 2. 示例

**示例 1**

```text
输入：weight = [100,200,150,1000]
输出：4
解释：4 个苹果总重 100+200+150+1000 = 1450 <= 5000，可以全部放入。
```

**示例 2**

```text
输入：weight = [900,950,800,1000,700,800]
输出：5
解释：6 个苹果总重 5150 超重；挑最小的 5 个：700+800+800+900+950 = 4150 <= 5000。
```

**示例 3（补充）**

```text
输入：weight = [5000, 1, 1]
输出：2
解释：5000 单个就顶满承重，但为了个数更多，应选 [1,1]。
```

## 3. 解题思路

### 3.1 暴力思路

枚举苹果的所有子集（$2^n$ 个），对每个子集检查总重是否 $\le 5000$，取合法子集的最大大小。$n \le 1000$ 时 $2^{1000}$ 完全不可行；即使把「枚举个数 $k$、再枚举大小为 $k$ 的组合」折中，也是组合爆炸。观察题面可以发现本题**只关心个数**，不关心具体是哪些苹果——这正提示我们：在固定个数的前提下，总重最小的选法一定存在。

### 3.2 核心观察：固定个数时，「挑最轻的 k 个」总重最小

![核心观察：固定个数时挑最轻的 k 个，总重最小](images/bw9_q1_greedy_model.svg)

要最大化个数 $k$，只需要判断「**是否存在** $k$ 个苹果总重 $\le 5000$」。而对于固定的 $k$：

- 若某个 $k$ 元子集 $S$ 可行（$\sum_{i \in S} weight_i \le 5000$），那么**全局最轻的 $k$ 个**苹果的总重 $\le \sum_{i \in S} weight_i \le 5000$，同样可行。

也就是说，判断「$k$ 是否可行」根本不需要枚举组合——**将数组排序，前 $k$ 个的总重就是所有 $k$ 元子集中最小的**。又因为前缀和随 $k$ 单调不减，可行的 $k$ 恰好是一段前缀 $\{0,1,\dots,K\}$，答案是最大的那个 $K$。这就是经典的「排序 + 贪心累加」。

> 💡 一句话：**想装得多，就先装轻的**。这是交换论证（exchange argument）能直接证明的贪心。

### 3.3 算法流程

![算法流程：排序后贪心累加，首个超重处停笔](images/bw9_q1_algorithm_flow.svg)

```text
1. 将 weight 从小到大排序
2. sum = 0, cnt = 0
3. 从头到尾扫描：
   3.1 若 sum + weight[i] > 5000：跳出循环
   3.2 否则 sum += weight[i], cnt += 1
4. 返回 cnt
```

### 3.4 示例演算

![示例演算：两组官方示例的排序与累加过程](images/bw9_q1_example_walkthrough.svg)

| 输入 | 排序后 | 前缀和序列 | 首个超重处 | 答案 |
|------|--------|-----------|-----------|------|
| [100,200,150,1000] | [100,150,200,1000] | 100, 250, 450, **1450** | 无（1450 ≤ 5000） | 4 |
| [900,950,800,1000,700,800] | [700,800,800,900,950,1000] | 700, 1500, 2300, 3200, 4150, **5150** | 第 6 个（5150 > 5000） | 5 |

第二组数据是本题的「陷阱」：若不排序直接按原顺序累加，前 5 个是 $900+950+800+1000+700 = 4350 \le 5000$，看似也能得到 5，但只要数据构造得再刁钻一点（例如最重的苹果排在最前），不排序就会漏掉「跳过重苹果、换取更多轻苹果」的更优选择。排序保证了对任何数据都取到「最轻的 $k$ 个」。

## 4. 算法细节

1. **排序是核心**：贪心的正确性完全建立在「前 $k$ 个是最轻的 $k$ 个」之上，排序不可省。
2. **判定用 $\le$**：承重上限是「**至多** 5000」，恰好等于 5000 仍然合法，注意别写成 `<`。
3. **提前跳出**：前缀和一旦超过 5000，后面的苹果只会更重，直接 `break`，不必扫完。
4. **数值范围**：$n \le 10^3$、$weight[i] \le 10^3$，总重至多 $10^6$，`int` 绰绰有余，无需 `long long`。
5. **一个有趣的下界**：因为任意 5 个苹果总重 $\le 5 \times 1000 = 5000$，所以当 $n \ge 5$ 时答案至少为 5——贪心算法天然满足这一点，无需特判。

## 5. 正确性证明

**引理 1（最轻前缀）**：设排序后 $w_1 \le w_2 \le \cdots \le w_n$。对任意大小为 $k$ 的下标子集 $S$，有 $w_1 + w_2 + \cdots + w_k \le \sum_{i \in S} w_i$。

**证明**：把 $S$ 对应的元素从小到大排成 $s_1 \le s_2 \le \cdots \le s_k$。对每个 $1 \le j \le k$，全体中第 $j$ 小的元素不超过任何 $k$ 元子集中的第 $j$ 小元素（否则说明全体前 $j$ 小有超过 $j$ 个来自 $S$ 之外，与 $|S|=k$ 矛盾），即 $w_j \le s_j$。逐项相加即得。∎

**引理 2（可行性前缀性）**：记 $P_k = w_1 + \cdots + w_k$（$P_0 = 0$），则 $P_k$ 关于 $k$ 单调不减，因此 $\{\,k : P_k \le 5000\,\}$ 形如 $\{0, 1, \ldots, K\}$。

**证明**：$P_{k+1} = P_k + w_{k+1} \ge P_k$（ weights 为正），单调性显然；若 $P_K \le 5000$，则对一切 $k \le K$ 有 $P_k \le P_K \le 5000$。∎

**定理**：算法返回能放入篮子的苹果数量的最大值 $K^\ast$。

**证明**：设算法返回 $t$，即 $P_1, \ldots, P_t \le 5000$ 且（若 $t < n$）$P_{t+1} > 5000$。一方面，取最轻的 $t$ 个苹果即得一个合法方案，故 $K^\ast \ge t$。另一方面，用反证法设 $K^\ast \ge t+1$，即存在大小为 $t+1$ 的子集 $S$ 总重 $\le 5000$；由引理 1，$P_{t+1} \le \sum_{i \in S} w_i \le 5000$，与 $P_{t+1} > 5000$ 矛盾（若 $t = n$ 则 $K^\ast \le n = t$ 平凡成立）。故 $K^\ast = t$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序占主导；随后的一次线性扫描为 $O(n)$。$n \le 10^3$ 时约几千次比较。
- **空间**：$O(1)$ 额外空间（原地排序，不算排序递归栈）。Python 中 `sorted` 会生成副本，为 $O(n)$，若想原地可对下标操作。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxNumberOfApples(vector<int>& weight) {
        sort(weight.begin(), weight.end());      // 从轻到重
        int cnt = 0, sum = 0;
        for (int w : weight) {
            if (sum + w > 5000) break;           // 再放就超重
            sum += w;
            ++cnt;
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def maxNumberOfApples(self, weight: list[int]) -> int:
        weight = sorted(weight)          # 从轻到重
        cnt = total = 0
        for w in weight:
            if total + w > 5000:         # 再放就超重
                break
            total += w
            cnt += 1
        return cnt
```

## 8. 边界情况与易错点

1. **忘记排序**是本题唯一的大坑：不排序时前缀和不代表「最轻 $k$ 个」，构造数据可以轻易卡掉。
2. **5000 是闭上界**：恰好装到 5000 仍算合法（判 $\le$），用 `<` 会把边界数据判错。
3. **全部能装下**：如示例 1，扫描完整个数组也不超重，正常返回 $n$，`break` 不触发。
4. **单个苹果顶满**：如补充示例中的 5000，说明「重量大的苹果不一定要选」，贪心自动跳过。
5. **至少能装 5 个**（当 $n \ge 5$）：因 $5 \times 10^3 = 5000$ 恰好不超重，无需担心答案为 0 的情形，但代码的通用写法（`cnt` 从 0 开始）本身也正确覆盖。
6. **别用浮点**：所有数据都是整数，前缀和比较用整数即可。
