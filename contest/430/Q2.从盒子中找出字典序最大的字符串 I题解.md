# LeetCode 从盒子中找出字典序最大的字符串 I 题解

## 1. 题目概述

- **标题 / 题号**：从盒子中找出字典序最大的字符串 I（#3403，medium）
- **链接**：https://leetcode.cn/problems/find-the-lexicographically-largest-string-from-the-box-i/
- **来源**：LeetCode 第 430 场周赛 Q2
- **难度**：中等
- **标签**：字符串、枚举、贪心

**题意**：给定字符串 `word` 与整数 `numFriends`。游戏进行多个回合：每一回合把 `word` 分割成 $k$ 个**非空**字符串（$k = numFriends$，且每种分法与之前所有回合都不完全相同），分割出的所有字符串都放入一个盒子。所有回合结束后，返回盒子中**字典序最大**的字符串。

**约束**：

- $1 \le word.length \le 5 \times 10^3$
- `word` 仅由小写英文字母组成
- $1 \le numFriends \le word.length$

> 💡 **读题关键**：①「每一回合分法互不相同」合起来等于把**每一种**分割方式都玩一遍，盒子就是所有分割产出的全部片段的并集——问题与"回合顺序"无关；② 分割保序，每个片段都是 `word` 的**连续子串** `word[i..j]`；③ 于是问题从「枚举分割」转化为「**刻画哪些子串能进盒子**，再在其中取字典序最大」。

## 2. 示例

**示例 1**

```text
输入：word = "dbca", numFriends = 2
输出："dbc"
解释：所有分割方式为 "d"|"bca"、"db"|"ca"、"dbc"|"a"，
     盒子中共 6 个字符串，字典序最大的是 "dbc"。
```

**示例 2**

```text
输入：word = "gggg", numFriends = 4
输出："g"
解释：唯一分割方式："g"|"g"|"g"|"g"，盒子中只有 "g"。
```

**示例 3（自造，本场最大的坑）**

```text
输入：word = "abz", numFriends = 2
输出："z"
解释：分割方式为 "a"|"bz" 与 "ab"|"z"，盒子 = {a, bz, ab, z}。
     注意 "z" > "bz"（首位 z > b）——长度恰为 L = 2 的最大子串 "bz" 不是答案！
```

## 3. 解题思路

### 3.1 暴力思路

最直接的暴力是枚举全部 $\binom{n-1}{k-1}$ 种分割（在 $n-1$ 个字符缝隙里选 $k-1$ 处下刀），收集所有片段再取最大——$n = 5000$ 时组合数是天文数字，连"回合数"都数不完。退一步的暴力：枚举所有 $O(n^2)$ 个子串、逐个判定「能否作为某个合法分割的一段」再取最大，判定本身又要构造分割，又绕又慢。正确姿势是反过来：**直接刻画「能进盒子的子串」长什么样**，让枚举空间瞬间塌缩成 $n$ 个候选。

### 3.2 核心观察：盒子 = 「长度 ≤ L 的子串」，每个起点只留最长候选

![核心观察：盒子视角与滑窗视角等价](images/wc430_q2_box_to_window.svg)

记 $n = |word|$，$k = numFriends$，$L = n - k + 1$。三个观察环环相扣：

- **观察一（长度上界）**：$k$ 段都非空，一段拿走 $L$ 个字符后其余 $k-1$ 段至少各占 1 个字符，故任何片段长度 $\le L = n - k + 1$。
- **观察二（同起点越长越大）**：同一起点的候选里，短的真是长的**真前缀**，而真前缀必更小（`"db" < "dbc"`），所以每个起点 $i$ 只需看最长候选 $c_i = word[i : \min(i+L,\ n)]$（切片越界自动截断到串尾）。
- **观察三（候选可达）**：每个 $c_i$ 确实能成为某个合法分割中的一段（构造见 §5 引理 2）——前半拆单字符、中间拿走窗口、后半拆单字符，段数恰好凑满 $k$。

三个观察合起来，只需 $n$ 个候选打擂台：

$$answer = \max_{0 \le i < n}\; word[i : \min(i+L,\ n)]$$

> ⚠️ **本题头号陷阱：答案不是「长度恰为 $L$ 的最大子串」！** 凭直觉只枚举满长窗口 $word[i:i+L],\ i \le n-L$ 是错的。反例就是示例 3：`word = "abz"`，$k = 2$，满长候选 `"ab"`、`"bz"` 的最大值是 `"bz"`，但盒子里有分割 `"ab"|"z"` 的第二段 `"z"`——首位 `z > b` 直接反杀。**尾部截断出的短候选一个都不能丢**：起点越靠后窗口越短，但字典序只由第一个不同字符决定，短后缀完全可能碾压一切满长窗口。我在随机小用例上统计过，「只看满长窗口」约 **19%** 的用例会答错——这不是边角，是主坑。

![陷阱：短后缀反杀满长窗口](images/wc430_q2_trap_suffix.svg)

> 💡 另一个方向的直觉：把 $k-1$ 个朋友都当成"每人只拿 1 个字符的陪跑"，主角段就能取到从任意起点 $i$ 开始、最多延伸 $L$ 个字符（或直到串尾）的窗口——这就是 $n$ 个候选的来历。

### 3.3 算法流程

![算法流程：特判、定窗长、逐起点打擂台](images/wc430_q2_algorithm_flow.svg)

1. **特判**：$k = 1$ 时唯一的分割就是整串，直接返回 `word`。
2. **定窗长**：$L = n - k + 1$，`best` 初始化为空串。
3. **枚举起点**：$i$ 从 $0$ 到 $n-1$，候选 `c = word[i : i+L]`（Python 切片 / C++ `substr` 越界自动截断，天然实现 $\min(n-i, L)$）。
4. **打擂台**：`c` 与 `best` 比字典序，更大则替换。
5. 循环结束返回 `best`。

### 3.4 示例演算

以示例 1（`word = "dbca"`，$k = 2$，$n = 4$，$L = 3$）走一遍（候选高亮见 3.2 图右列）：

| 起点 $i$ | 候选 $c_i$ | 长度 | 截断？ | $c_i$ 出现于的一个合法分割 |
|---|---|---|---|---|
| 0 | `"dbc"` | 3 | 否 | `"dbc" \| "a"` 的第 1 段 |
| 1 | `"bca"` | 3 | 否 | `"d" \| "bca"` 的第 2 段 |
| 2 | `"ca"` | 2 | 是（取到串尾） | `"db" \| "ca"` 的第 2 段 |
| 3 | `"a"` | 1 | 是（取到串尾） | `"dbc" \| "a"` 的第 2 段 |

四个候选中 `"dbc"` 最大 ✓。示例 2（`"gggg"`，$k = 4$）：$L = 1$，四个候选全是 `"g"`，返回 `"g"` ✓。示例 3（`"abz"`，$k = 2$）：候选 `"ab"`、`"bz"`、`"z"`（截断），max 为 `"z"` ✓——正是截断候选夺冠。

## 4. 算法细节

1. **$k = 1$ 特判不能省**：此时唯一分割是整串；硬套公式（$L = n$）会枚举出所有**后缀**，而单段分割下起点 $i \ge 1$ 的后缀不对应任何合法分割（`word = "ab"` 会错误地返回 `"b"`）。
2. **截断语义**：`word[i : i+L]` 与 C++ `word.substr(i, L)` 都自动截断到串尾，等价于 `word[i : min(i+L, n)]`；若手写下标循环比较，务必自己加 `min` 封口。
3. **`best` 初始化为空串**：任何非空串都大于空串，而 $i < n$ 保证每个候选至少 1 个字符，空串是安全的初始擂主，免去特判 $i = 0$。
4. **可选剪枝**：答案必然以 `word` 的全局最大字符开头（最大字符所在起点的候选压制一切更小首字符的候选），故可只枚举最大字符的**全部**出现位置——但必须逐一完整比较，"只看首次出现"是错的（`"aann"`，$k = 2$：首现起点给 `"ann"`，真答案是起点 2 的 `"nn"`）。$n \le 5000$ 时无此必要。
5. **进阶预告**：把「全体候选取 max」换成「**字典序最大后缀**截断 $L$ 个字符」可降到 $O(n)$，双指针同 [1163. 按字典序排在最后的子串](https://leetcode.cn/problems/last-substring-in-lexicographical-order/)，见文末延伸思考与同题意大数据版 3406。

## 5. 正确性证明

记 $n = |word|$，$k = numFriends$，$L = n - k + 1$，候选 $c_i = word[i..\,\min(i+L, n) - 1]$（$0 \le i < n$）。称一个字符串**可达**，若它等于某个合法分割（切成 $k$ 个非空段）中的某一段。

**引理 1（必要性 / 长度上界）**：盒子中任何字符串都是 `word` 的连续子串，且长度 $\le L$。

**证明**：分割保序且各段连续，故每段是子串。设某段长为 $m$，其余 $k - 1$ 段非空、合计至少占 $k - 1$ 个字符，故 $m \le n - (k - 1) = L$。∎

**引理 2（候选可达）**：$k \ge 2$ 时，每个候选 $c_i$ 都可达。

**证明**：分两种情形构造分割。

- **情形 a：$i + L \le n$（即 $i \le k - 1$）**。取分割：前缀 $word[0..i-1]$ 拆成 $i$ 个单字符段（$i = 0$ 时没有前缀段），中间段为 $c_i = word[i..i+L-1]$，尾部剩余 $n - i - L = k - 1 - i \ge 0$ 个字符逐个拆成单字符段。总段数 $i + 1 + (k - 1 - i) = k$，每段非空。
- **情形 b：$i + L > n$（即 $i \ge k$）**。此时 $c_i = word[i..n-1]$ 是取到串尾的后缀，长度 $n - i < L$。取分割：前缀 $word[0..i-1]$（共 $i \ge k > k - 1$ 个字符）拆成 $k - 1$ 个非空段，$c_i$ 作为第 $k$ 段。

两种情形都给出 $c_i$ 恰为某段。∎

**引理 3（同起点支配）**：对 `word` 的任一长度 $\le L$ 的子串 $t = word[i..j]$，有 $t \le c_i$。

**证明**：由 $j - i + 1 \le L$ 与 $j \le n - 1$ 得 $j \le \min(i + L, n) - 1$，故 $t$ 是 $c_i$ 的前缀。字典序比较中，串不小于其任何前缀（逐位全相等时，更长者更大），故 $t \le c_i$。∎

**定理**：$k = 1$ 时答案为 `word`；$k \ge 2$ 时答案为 $\max_{0 \le i < n} c_i$。

**证明**：$k = 1$ 时唯一分割为整串，盒子 $= \{word\}$，得证。设 $k \ge 2$，记 $M = \max_i c_i$。

- **（答案 $\ge M$）**：由引理 2，$M$ 是某个合法分割中某段的取值，故 $M$ 在盒子里，答案 $\ge M$。
- **（答案 $\le M$）**：盒子中任何字符串 $s$ 是某分割的一段，由引理 1 它是长度 $\le L$ 的子串 $word[i..j]$，由引理 3 得 $s \le c_i \le M$。

两向合拢，答案 $= M$。∎

> 💡 **证明的分工**很清晰：引理 1 给**上界**（盒子被「长度 $\le L$ 的子串」罩住），引理 2 给**可达性**（每个候选真的能进盒子），引理 3 负责**收紧**（任意子串被同起点的最长候选支配）。「短后缀反杀」之所以可能，正是引理 3 只保证 $c_i$ 支配**从 $i$ 出发**的更短子串——它自己可以很短，却仍能凭首字符压过别处的满长窗口。

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L) \le O(n^2)$。$n$ 个起点，每个候选的切片与字典序比较至多 $L = n - k + 1$ 个字符；$n = 5000$ 最坏约 $2.5 \times 10^7$ 次字符操作，且 Python 的切片与 `max` 都是 C 级实现，轻松通过。
- **空间复杂度**：$O(L)$。打擂台时只需暂存当前最优 `best` 与当前候选 `c`（各至多 $L$ 个字符），无需预生成全部候选。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string answerString(string word, int numFriends) {
        if (numFriends == 1) return word;   // 唯一分法：整串
        int n = word.size();
        int L = n - numFriends + 1;
        string best;
        for (int i = 0; i < n; i++) {
            string cand = word.substr(i, L);  // 越界自动截断
            if (cand > best) best = move(cand);
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def answerString(self, word: str, numFriends: int) -> str:
        if numFriends == 1:
            return word  # 唯一分法：整串
        L = len(word) - numFriends + 1
        # 切片越界自动截断到末尾，正好实现 min(n - i, L)
        return max(word[i:i + L] for i in range(len(word)))
```

## 8. 边界情况与易错点

1. **头号陷阱：只枚举满长窗口**。`"abz"`，$k = 2$：满长候选最大是 `"bz"`，真答案是 `"z"`（分割 `"ab"|"z"` 的第二段，首位 `z > b`）。尾部截断的短候选必须保留——随机小用例约 19% 会踩中此坑。
2. **$k = 1$ 忘记特判**：硬套公式返回的是最大后缀，`"ab"` 会错答 `"b"`；正确答案是整串 `"ab"`。
3. **$k = n$**：$L = 1$，每段恰一个字符，答案即 `word` 的最大字符——公式自动覆盖，可当 sanity check（`"gggg"` → `"g"`）。
4. **切片越界**：`word[i:i+L]` / `substr(i, L)` 自动截断；若手写逐字符比较，务必 `min(i + L, n)` 封口，否则要么越界、要么漏掉短后缀。
5. **"只看最大字符首次出现"**：`"aann"`，$k = 2$：首现起点 1 给 `"ann"`，真答案是起点 2 的 `"nn"`。同首字符必须继续比后续；剪枝只能限定"全部出现位置"。
6. **`best` 初值**：空串可安全充当初始擂主（一切非空候选更大），省去对 $i = 0$ 的特判。
7. **重复字符 / 单调串无特殊性**：`max` 语义照常。顺带一提 `"abc"`，$k = 2$ 的答案是 `"c"` 而非 `"bc"`——又是"短后缀反杀"。
