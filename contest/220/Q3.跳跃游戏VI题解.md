# LeetCode 跳跃游戏 VI 题解

## 1. 题目概述

- **标题 / 题号**：跳跃游戏 VI（#1696，medium）
- **链接**：https://leetcode.cn/problems/jump-game-vi/
- **来源**：LeetCode 第 220 场周赛 Q3
- **难度**：中等
- **标签**：动态规划、单调队列、滑动窗口、队列

**题意**：给定下标从 `0` 开始的整数数组 `nums` 与整数 `k`。从下标 `0` 出发，每一步可从下标 `i` 跳到 $[i+1,\ \min(n-1,\ i+k)]$ 内的任意下标（不能跳出数组边界）；**得分**为路径上经过的所有数字之和。必须到达最后一个位置 $n-1$，返回能得到的**最大得分**。

**约束**：

- $1 \le \text{nums.length} \le 10^5$，$1 \le k \le 10^5$
- $-10^4 \le \text{nums}[i] \le 10^4$

> 💡 一句话定位：路径的**相邻两跳步长 $\le k$** 翻译成 DP 语言，就是「`dp[i]` 的前驱只能落在长度 $k$ 的窗口 $[i-k,\ i-1]$ 内」——转移依赖**滑动窗口内 `dp` 的最大值**，把 [239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/) 的单调队列从 `nums` 平移到 `dp` 上即可，整体 $O(n)$。

## 2. 示例

**示例 1**

```text
输入：nums = [1,-1,-2,4,-7,3], k = 2
输出：7
解释：路径 0→1→3→5，得分 1+(−1)+4+3 = 7；每步跨度 1、2、2，均 ≤ k。
```

**示例 2**

```text
输入：nums = [10,-5,-2,4,0,3], k = 3
输出：17
解释：路径 0→3→5，得分 10+4+3 = 17；跨度 3、2，均 ≤ k。
```

**示例 3**（负数再多也得走完：起点终点固定，中途不能退出）

```text
输入：nums = [1,-5,-20,4,-1,3,-6,-3], k = 2
输出：0
解释：最优路径 0→1→3→5→7，得分 1−5+4+3−3 = 0；dp 全程可能为负，但每步都必须落脚。
```

## 3. 解题思路

### 3.1 暴力思路：DP + 逐格扫描窗口

**状态定义**：`dp[i]` = 从下标 `0` 跳到下标 `i` 的**最大得分**（必须经过 `i`）。

**转移**：到达 `i` 的最后一跳必从某个 $j \in [\max(0, i-k),\ i-1]$ 出发，在所有合法前驱中取最优：

$$dp[i] = \text{nums}[i] + \max_{\max(0,\,i-k) \le j \le i-1} dp[j]$$

- 边界：$dp[0] = \text{nums}[0]$（起点固定，得分即 `nums[0]`）。
- 答案：$dp[n-1]$（终点固定，**不是** $\max_i dp[i]$）。

暴力实现对每个 $i$ 线性扫描窗口求 $\max$，时间 $O(nk)$。$n, k$ 均可达 $10^5$，最坏 $10^{10}$ 次运算，**严重超时**。

> ⚠️ 瓶颈在于「对每个 $i$ 从头重扫一遍窗口」。相邻两个 $i$ 的窗口只差「右进一个、左出一个」，暴力完全没有复用——这正是 [239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/) 暴力 $O(nk)$ 的翻版。用**单调队列**维护窗口内 `dp` 的最大值，每次查询降到均摊 $O(1)$。

### 3.2 核心观察：转移 = 滑动窗口最大值查询 → 单调队列

![核心观察：步长 ≤ k ⇔ 转移依赖窗口内 dp 最大值，单调队列维护](images/wc220_q3_window_dp_concept.svg)

从**正向**看，步长限制规定「从 `i` 一步可达 $[i+1,\ i+k]$」；反过来从**反向**看，它等价于「`dp[i]` 的前驱只能取自窗口 $[i-k,\ i-1]$」。于是 DP 的每一步转移就是一次**长度为 $k$ 的滑动窗口最大值查询**——查询对象从 239 的 `nums` 换成了 `dp`，其余一字不差：

1. **过期出队（左端）**：队头下标 $< i-k$（滑出窗口），从队头弹出；
2. **入队弹尾（右端）**：新算出的 $dp[i]$ 入队前，从队尾弹出所有 $dp[\cdot] \le dp[i]$ 的下标——它们**更小且更早**，只要 $i$ 还在窗口里，这些旧值就不可能是最大，可安全丢弃。

**查询**：队头对应的 $dp[\text{front}]$ 即窗口最大，$O(1)$ 取得：

$$dp[i] = \text{nums}[i] + dp[\text{front}]$$

> 💡 **与 239 的同构关系**：239 维护「`nums` 的窗口最大」，本题维护「`dp` 的窗口最大」。区别仅在窗口对齐：239 的窗口是 $[i-k+1,\ i]$（**含**当前元素），过期条件 `front ≤ i−k`；本题的窗口是 $[i-k,\ i-1]$（**不含**当前，因为 $dp[i]$ 还没算出来），过期条件 `front < i−k`。差一个等号，务必对齐。

> ⚠️ **为什么本题没有 $\max(0,\ \cdot)$？** 与 [1425. 带限制的子序列和](https://leetcode.cn/problems/constrained-subsequence-sum/) 的关键差异：1425 的子序列可从任意位置开始（前驱全负时不如单开一段），故转移带 $\max(0,\cdot)$、答案取 $\max_i dp[i]$。本题**起点固定 0、终点固定 $n-1$**，每个 $i \ge 1$ 都必须从某个前驱跳过来，没有「另起一段」的退路——窗口必含 $i-1$，队列非空，直接取最大值即可。1696 是 1425 的「固定首尾路径版」。

### 3.3 算法流程

![算法流程：过期出队 → 查询算 dp[i] → 弹尾入队](images/wc220_q3_monotonic_deque_flow.svg)

```text
输入：nums, k
1. dp[0] = nums[0]；下标 0 入队（队列存下标，对应 dp 从队头到队尾递减）
2. for i = 1 .. n−1：
   a. 过期出队：while 队头 < i−k：pop_front
   b. 查询：dp[i] = nums[i] + dp[队头]
   c. 弹尾入队：while dp[队尾] ≤ dp[i]：pop_back；push_back(i)
3. 返回 dp[n−1]
```

> ⚠️ **顺序不能反**：先过期出队（清掉窗口外的队头），再查询（此时队头是合法窗口内的最大），再算 $dp[i]$，最后弹尾入队（$dp[i]$ 供后续轮次使用）。若把 (c) 提前，未算出的「自己」会混进窗口，转移就错了。

### 3.4 示例演算

![示例演算：nums=[1,−1,−2,4,−7,3], k=2 六轮填充](images/wc220_q3_example_walkthrough.svg)

以示例 1 `nums = [1, -1, -2, 4, -7, 3], k = 2` 为例（队列内容记「下标:dp」）：

| i | nums[i] | 窗口 | 队列（查询前，队头→队尾） | best | dp[i] | 队列（入队后） |
|---|---------|------|--------------------------|------|-------|----------------|
| 0 | 1 | — | 起点：下标 0 入队 | — | 1 | `[0:1]` |
| 1 | −1 | [0,0] | `[0:1]` | 1 | 0 | `[0:1, 1:0]` |
| 2 | −2 | [0,1] | `[0:1, 1:0]` | 1 | −1 | `[0:1, 1:0, 2:−1]` |
| 3 | 4 | [1,2] | 过期弹 0 → `[1:0, 2:−1]` | 0 | 4 | 弹 2、1 → `[3:4]` |
| 4 | −7 | [2,3] | `[3:4]` | 4 | −3 | `[3:4, 4:−3]` |
| 5 | 3 | [3,4] | `[3:4, 4:−3]`（3 未过期） | 4 | 7 | 弹 4、3 → `[5:7]` |

两处关键：

- **i = 3 的弹尾「清场」**：$dp[3]=4$ 入队时一次压走 `2:−1` 和 `1:0`——它们比 4 小且下标更早（先滑出窗口），此后永不可能成为最大，弹掉后队头直接是 `[3:4]`，后续 $dp[4]$、$dp[5]$ 一查即得 4。
- **i = 5 的过期判定**：窗口为 $[5-2,\ 5-1]=[3,4]$，队头下标 3 满足 $3 \ge 5-2$，**未过期**（过期条件是严格小于）。故 best 取 $dp[3]=4$ 而非 $dp[4]=-3$——若误把过期条件写成 `≤`，会在这里错丢 $dp[3]=4$，得到错误答案 0。

最终 $dp = [1, 0, -1, 4, -3, 7]$，答案 $= dp[5] = 7$，对应路径 $0 \to 1 \to 3 \to 5$（跨过 $-2, -7$ 的坑，在 4 和 3 上得分）。

## 4. 算法细节

1. **队列存下标而非 dp 值**：过期判定需要下标（队头是否 $< i-k$），单调判定需要 dp 值（$dp[\text{back}] \le dp[i]$）。存下标后两者都可 $O(1)$ 读取（`dp[back]` 随手可查）；存值则丢失位置信息，无法判断过期。
2. **窗口边界对齐**：本题窗口 $[i-k,\ i-1]$ **不含当前元素**，故过期条件为 `front < i−k`（下标 $i-k$ 距 $i$ 恰好 $k$ 步，仍合法）；对比 239 的窗口 $[i-k+1,\ i]$ **含当前**，过期条件为 `front ≤ i−k`。两题窗口定义差 1，过期条件差一个等号。
3. **弹尾条件用 `≤` 而非 `<`**：dp 相同时只保留下标更大（更新）者——它更晚过期、能服务更多后续查询，队列更紧凑。用 `<` 同样正确但队列偏长。
4. **查询无需判空**：$i \ge 1$ 时，下标 $i-1$ 在上一轮刚入队，且 $i-1 \ge i-k$（因 $k \ge 1$）永不因过期被弹出，故查询时队列必然非空。代码中的判空只是防御性写法。
5. **没有 $\max(0,\ \cdot)$ 兜底**：起点终点固定，不存在「从 `nums[i]` 另起一段」的选项——见 3.2 的对照说明，这是与 1425 的本质差异。
6. **空间可优化到 $O(k)$**：队列任意时刻只含长度 $k+1$ 的下标区间 $[i-k,\ i]$ 的子集，至多 $k+1$ 个元素；若连 `dp` 数组也想省掉，可让队列改存 `(下标, dp)` 二元组，过期与单调判定都不再依赖外部数组。
7. **堆 + 懒惰删除的替代**：不熟悉单调队列时，可用大顶堆存 `(dp, 下标)`，每次取堆顶前弹出下标 $< i-k$ 的过期项，$O(n \log n)$。窗口连续滑动时单调队列更快（见文末每日题解链接）。

## 5. 正确性证明

**引理 1（最优子结构）**：设 $P: 0 = p_0 \to p_1 \to \cdots \to p_m = i$ 为到达 $i$ 的得分最大路径，则其真前缀 $P': 0 = p_0 \to \cdots \to p_{m-1}$ 是到达 $p_{m-1}$ 的得分最大路径。

**证明**：$P'$ 的每步跨度与 $P$ 相同，故合法。若存在到达 $p_{m-1}$ 的合法路径 $Q$ 得分更高，则 $Q$ 接上最后一跳 $p_{m-1} \to i$（跨度不变，仍 $\le k$）得到到达 $i$ 的合法路径，得分比 $P$ 更高，与 $P$ 最优矛盾。∎

**引理 2（转移方程刻画最优）**：对 $i \ge 1$，到达 $i$ 的最大得分恰为 $\text{nums}[i] + \max\{dp[j] : \max(0, i-k) \le j \le i-1\}$。

**证明**：任一到达 $i$ 的合法路径的最后一跳必从某 $j \in [\max(0,i-k),\ i-1]$ 出发，由引理 1 其前缀得分 $\le dp[j]$，故路径得分 $\le \text{nums}[i] + \max_j dp[j]$。反之，取达到 $\max_j dp[j]$ 的 $j^*$，「到 $j^*$ 的最优路径 + 一跳到 $i$」是合法路径且得分恰为右端。两向合逼即证。∎

**引理 3（队头即窗口最大）**：每轮执行完过期出队后的查询时刻，队列中下标全部落在窗口 $[\max(0, i-k),\ i-1]$ 内、对应 dp 值从队头到队尾严格递减，且 $dp[\text{front}] = \max\{dp[j] : j \in \text{窗口}\}$。

**证明**：先看两条结构不变式。**下标递增**：元素按 $0, 1, \cdots$ 顺序入队，两端出队不破坏剩余序列的递增序。**dp 严格递减**：初始队列 $[0]$ 平凡；唯一改动队列的操作是队头弹出（删前缀保持递减）与「弹尾所有 $\le dp[i]$ 者后压入 $i$」（队尾保持严格递减，因相等的都被弹掉了）。

窗口内：过期条件 $< i-k$ 随 $i$ 右移而阈值递增，故下标 $< i-k$ 的元素全部堆积在队头（下标递增），步骤 (a) 恰好弹出它们；又 $i$ 尚未入队、历史元素 $\le i-1$，故队列元素全落窗口内。

队头为最大：设 $M$ 为窗口内 dp 最大值，取窗口内达到 $M$ 的**最大**下标 $j^*$。因 $j^* \ge i-k$，而历史各轮的过期阈值均不超过 $i-k$，故 $j^*$ 从未因过期出队。若 $j^*$ 已不在队列，它必在某轮 $t \in (j^*,\ i-1]$ 被弹尾，弹出条件给出 $dp[t] \ge dp[j^*] = M$；而 $j^* < t \le i-1$ 且 $t > j^* \ge \max(0, i-k)$，故 $t$ 也在当前窗口内且 $dp[t] = M$，与 $j^*$ 的最大性矛盾。故 $j^*$ 在队列中，由严格递减知队头 $dp \ge dp[j^*] = M$，又队头在窗口内故 $\le M$，得 $dp[\text{front}] = M$。∎

**引理 4（弹尾安全性）**：步骤 (c) 中被弹出的下标 $j$（$dp[j] \le dp[i]$，$j < i$）在之后任何查询中都不可能贡献窗口最大值。

**证明**：$j < i$ 蕴含 $j$ 比 $i$ 先滑出窗口。在之后任意查询时刻，若 $j$ 尚在窗口内，则 $i$ 也在（更晚过期）且 $dp[i] \ge dp[j]$，故窗口最大 $\ge dp[i] \ge dp[j]$，最大值不因丢弃 $j$ 而损失（即便并列，仍有在队的 $i$ 代表同一值）。∎

**定理（正确性与复杂度）**：算法返回从 $0$ 到 $n-1$ 的最大得分，时间 $O(n)$。

**证明**：由引理 3，每轮查询的 $dp[\text{front}]$ 即窗口最大；由引理 2，按此递推的 $dp[i]$ 是到达 $i$ 的最大得分，引理 4 保证弹尾无损。起点 $dp[0] = \text{nums}[0]$ 正确，终点固定，故返回 $dp[n-1]$ 为答案。复杂度：每个下标入队恰一次、出队至多一次（过期或弹尾），队列总操作 $\le 2n$，均摊每轮 $O(1)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`for` 循环 $n-1$ 轮；两个 `while` 的总弹出次数 $\le 2n$（每个下标至多被弹出一次），均摊到每轮 $O(1)$；窗口最大查询为队头 $O(1)$ 读取。
- **空间复杂度**：$O(n)$，即 `dp` 数组；队列至多存 $k+1$ 个下标，为 $O(\min(n, k))$。若队列改存 `(下标, dp)` 二元组省去 `dp` 数组，可降到 $O(\min(n, k))$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxResult(vector<int>& nums, int k) {
        int n = nums.size();
        vector<long long> dp(n);          // |dp| 上界 1e9，long long 防御性写法
        deque<int> dq;                    // 存下标，对应 dp 从队头到队尾严格递减
        dp[0] = nums[0];
        dq.push_back(0);
        for (int i = 1; i < n; ++i) {
            while (!dq.empty() && dq.front() < i - k)  // ① 过期出队（i−1 恒在窗口，判空仅防御）
                dq.pop_front();
            dp[i] = (long long)nums[i] + dp[dq.front()]; // ② 队头即窗口内 dp 最大
            while (!dq.empty() && dp[dq.back()] <= dp[i]) // ③ 弹尾：更小且更早，永不复用
                dq.pop_back();
            dq.push_back(i);
        }
        return (int)dp[n - 1];
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def maxResult(self, nums: List[int], k: int) -> int:
        n = len(nums)
        dp = [0] * n
        dp[0] = nums[0]
        dq = deque([0])                         # 存下标，dp 从队头到队尾递减
        for i in range(1, n):
            while dq and dq[0] < i - k:         # ① 过期出队
                dq.popleft()
            dp[i] = nums[i] + dp[dq[0]]         # ② 队头即窗口内 dp 最大
            while dq and dp[dq[-1]] <= dp[i]:   # ③ 弹尾：更小且更早，永不复用
                dq.pop()
            dq.append(i)
        return dp[n - 1]
```

> 💡 两份代码逐行对应，唯一语言差异是 C++ 用 `long long` 防 $10^9$ 贴边溢出、Python 无此虑。对照 239 的模板改两处即可迁移：窗口从「含当前」改为「不含当前」，维护对象从 `nums` 改为 `dp`。

## 8. 边界情况与易错点

1. **$n = 1$**：答案即 `nums[0]`，循环不执行，`dp[0]` 直接返回。
2. **$k = 1$**：每步只能前进 1，路径唯一，答案 = $\sum \text{nums}$。
3. **$k \ge n-1$**：任何下标互为合法前驱，退化为「全局最优前缀路径」，单调队列照常工作（队头几乎不因过期弹出）。
4. **和的溢出**：$|dp[i]| \le n \times 10^4 = 10^9$，恰在 C++ `int` 上限 $2.1 \times 10^9$ 之内但相当贴边，内部建议 `long long`（Python 无碍）。
5. **过期条件是 `<` 不是 `≤`**：窗口 $[i-k,\ i-1]$ 含左端点 $i-k$（距 $i$ 恰 $k$ 步）。写错一个等号，会在恰好距离 $k$ 处错丢最优前驱（见 3.4 的 $i=5$）。
6. **先过期、后查询、最后入队**：三步顺序不能乱；把入队提前会让「未算出的自己」混进窗口。
7. **答案取 `dp[n-1]` 而非 `max(dp)`**：终点固定；取全局最大是 1425（子序列版）的答案形式，在本题是错的。
8. **没有 $\max(0,\ \cdot)$ 兜底**：起点固定、必须逐步落脚，最优得分可为负（如 `nums = [-5,-3]`，正确答案 $-5 + (-3) = -8$）。若照搬 1425 的转移加上 `max(0, ·)`，会算出 $-3$——相当于允许「跳过起点重新计分」，与题意不符。
9. **队列存下标而不是值**：存值无法做过期判定；这是把 239 模板迁移过来时最容易顺手写错的一处。

- [LeetCode 53. 最大子数组和](https://leetcode.cn/problems/maximum-subarray/)：Kadane 是「续接前一位」的无约束版，本题是「续接窗口内最优前驱」的受限版。
- [LeetCode 45. 跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/)：同属跳跃游戏系列，求最少跳跃次数（贪心），本题求最大得分（DP），对照两种视角。
- 本题另有每日题解视角的完整分析（含堆 + 懒惰删除的 $O(n\log n)$ 解法与面试问答）：[1696. 跳跃游戏 VI](../../solution/1601-1700/1696_跳跃游戏VI.md)

**延伸思考**：① 步长限制改为区间 $[a, b]$（至少 $a$ 步、至多 $b$ 步）：转移窗口变为 $[i-b,\ i-a]$，仍连续滑动，单调队列照用；② 若允许往回跳：路径不再天然是 DAG 上的顺序推进，需建图后跑 DAG 最长路或缩环处理；③ 在线变体（随时修改 `nums[i]` 并查询答案）：单调队列失效，改用线段树维护区间 max 的 DP，$O(n \log n)$；④ $k$ 极小时队列极短，$k$ 极大时接近「全局最优前缀」——两种极端下可分别退化为暴力窗口扫描与单调栈，理解极端情形有助于检验模板边界。
