# LeetCode 重新格式化电话号码 题解

## 1. 题目概述

- **标题 / 题号**：重新格式化电话号码（#1694，easy）
- **链接**：https://leetcode.cn/problems/reformat-phone-number/
- **来源**：LeetCode 第 220 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定字符串形式的电话号码 `number`，由**数字**、空格 `' '` 与破折号 `'-'` 组成。重新格式化规则：先**删除**所有空格和破折号；再将数字从左到右**每 3 个一组**分块，**直到剩下 4 个或更少数字**；剩余数字按 2 个成一块、3 个成一块、4 个**拆成两个 2-块**处理；最后用 `'-'` 连接所有块。**不允许出现仅含 1 个数字的块，2-块至多两个**。

**约束**：

- $2 \leq \text{number.length} \leq 100$
- `number` 由数字、`'-'` 与 `' '` 组成，且**至少含 2 个数字**

> 💡 一句话定位：**过滤 + 定长分块 + 尾部特判**。签到题的全部难度集中在「尾部剩 4」这一个特例上。

## 2. 示例

**示例 1**

```text
输入：number = "1-23-45 6"
输出："123-456"
解释：数字 "123456" 共 6 位 → 两个 3-块。
```

**示例 2**

```text
输入：number = "123 4-567"
输出："123-45-67"
解释：数字 "1234567" 共 7 位 → 一个 3-块 + 末 4 位拆 "45"、"67"。
```

**示例 3**

```text
输入：number = "123 4-5678"
输出："123-456-78"
解释：数字 "12345678" 共 8 位 → 两个 3-块 + 尾 2-块 "78"。
```

**示例 4**

```text
输入：number = "--17-5 229 35-39475 "
输出："175-229-353-94-75"
解释：数字 "1752293539475" 共 13 位 → 三个 3-块 + 末 4 位拆 "94"、"75"。
```

## 3. 解题思路

### 3.1 朴素思路：照题面直译的「边扫边判」

按题面文字机械翻译：过滤出纯数字串后，循环里**每轮看剩余量**——大于 4 就切一个 3-块，等于 4 拆 2+2，剩 2 或 3 整体收尾。这是赛场上的自然写法，正确性与最优解同阶。

但它把尾部结构的判断**散布在循环的每一轮**里，且分支顺序藏着坑：必须**先判 `== 4` 再判 `< 4`**——4 既满足「$\leq 4$」又必须拆成两块，一旦写反就把 4 当成了整块输出。签到题想要又稳又快，最好把尾部结构**在循环外一次性算清**。

### 3.2 核心观察：尾部结构由 $n \bmod 3$ 唯一决定

![核心观察：n mod 3 决定尾部结构，余 1 时末 4 位拆 2+2](images/wc220_q1_tail_structure_concept.svg)

设过滤后数字串长度为 $n$，$r = n \bmod 3$。整个分块方案其实由 $r$ **唯一决定**：

| $r$ | 尾部形态 | 分块方案 |
|---|---|---|
| $0$ | 无尾部 | 全部 3-块 |
| $2$ | 剩 2 | 前 $n-2$ 位每 3 一块 + 尾部一个 2-块 |
| $1$ | 剩 1（**非法！**） | 前 $n-4$ 位每 3 一块 + **末 4 位拆成两个 2-块** |

$r = 1$ 是唯一特例：继续按 3 切会在尾部剩下一个孤零零的 1-块，违反规则。解决办法是**提前停在剩 4 位处**，把 4 拆成 $2+2$——逻辑上等价于从最后一个 3-块「借」1 位凑成 4，但实现时无需真的移动字符。另外注意 $n \equiv 1 \pmod 3$ 且 $n \geq 2$ 推出 $n \geq 4$，所以「前 $n-4$ 位」长度永远非负，特例自洽。

> 💡 为什么拆 $2+2$ 是必然的：4 是能避免 1-块的最小尾部长度；拆成 $2+2$ 恰好用满「至多两个 2-块」的配额。规则的所有约束在这一拆法下同时取等——这不是巧合，而是规则的内在结构。

### 3.3 算法流程

![算法流程：按 n mod 3 三分支闭式切分](images/wc220_q1_algorithm_flow.svg)

```text
输入：number
1. digits ← number 中所有数字字符；n ← digits 长度
2. r ← n mod 3
3. 按 r 分支：
   r = 0：整串每 3 位一块
   r = 2：前 n−2 位每 3 位一块，末 2 位一块
   r = 1：前 n−4 位每 3 位一块，末 4 位拆两个 2-块
4. 用 '-' 连接所有块并返回
```

### 3.4 示例演算

![示例演算：13 位数字走 r=1 特例分支](images/wc220_q1_example_walkthrough.svg)

以示例 4 `number = "--17-5 229 35-39475 "` 为例，过滤后 `digits = "1752293539475"`，$n = 13$：

| 步骤 | 依据 | 动作 | 块列表 |
|------|------|------|--------|
| 1 | $13 \bmod 3 = 1$，前段长 $13 - 4 = 9$ | 前 9 位切 3-块 | `["175","229","353"]` |
| 2 | 特例尾部 | 末 4 位拆两块 | `["175","229","353","94","75"]` |
| 3 | 结束 | join | `"175-229-353-94-75"` |

对照：若机械地按 3 切到底，会得到 `"175-229-353-947-5"`——末块孤 1，非法。特例处理的价值正在于此。

## 4. 算法细节

1. **先过滤、后分块**：尾部方案依赖数字总数 $n$，因此必须先过滤得到 $n$ 再切块；边扫边切时 $n$ 未知，无法判断是否已进入尾部特例区。
2. **过滤实现**：Python 用 `c.isdigit()`，C++ 用 `isdigit(c)`，空格与破折号一视同仁地丢弃。
3. **三分支互斥**：$r \in \{0, 1, 2\}$ 无遗漏地覆盖所有 $n \geq 2$，分支内不再需要任何条件判断——这正是闭式写法比「边扫边判」稳的原因。
4. **切片边界**：$r=1$ 时前段终点恰为 $n-4$（3 的倍数），末段在 $n-4$ 与 $n-2$ 两处下刀。Python `s[i:i+3]` 越界自动截断；C++ `substr(pos, len)` 的 `pos` 必须合法，本写法中恒满足。
5. **等价的单循环写法**（赛场速写）：`while` 剩余量 `> 4` 就取 3-块；剩 `== 4` 拆 2+2；剩 2 或 3 整体收尾。与闭式完全等价，但**必须先判 `== 4`**——判断顺序是本题最经典的 WA 点。

## 5. 正确性证明

**引理 1（合法性）**：对任意 $n \geq 2$，闭式三分支产生的划分不含 1-块，且 2-块至多两个。

**证明**：按 $r = n \bmod 3$ 分类。
- $r = 0$：全为 3-块，无 2-块、无 1-块。
- $r = 2$：$n - 2 \equiv 0 \pmod 3$，前段全为 3-块；尾部恰产生一个 2-块。
- $r = 1$：由 $n \equiv 1 \pmod 3$ 且 $n \geq 2$ 得 $n \geq 4$，故前段长度 $n - 4 \geq 0$ 且为 3 的倍数，全为 3-块；尾部 4 位恰拆出两个 2-块。

三种情形均无 1-块，且 2-块数 $\leq 2$。∎

**引理 2（与题面过程一致）**：题面「每 3 一组直到剩 $\leq 4$」的过程唯一确定，且结果恰为闭式三分支的划分。

**证明**：从 $n$ 出发每步减 3，剩余量构成严格递减序列，首次到达 $\leq 4$ 的值 $m$ 唯一。逐类验证：$r = 0$ 时序列中 $\leq 4$ 的首个值为 $0$（整除，无尾部）；$r = 2$ 时为 $2$；$r = 1$ 时序列每项 $\equiv 1 \pmod 3$，而 $4 \equiv 1 \pmod 3$ 且 $4 > 1$，故 $4$ 先于 $1$ 出现，首次 $\leq 4$ 的值为 $m = 4$（含 $n = 4$ 时序列即 $\{4\}$）。停在 $m$ 后按题面规则：$m = 4$ 拆 2+2，$m \in \{2, 3\}$ 单块收尾，$m = 0$ 结束。所得划分与闭式三分支逐块相同。∎

**定理**：算法返回的字符串是题面规则下的唯一合法输出。

**证明**：题面过程每步「取走 3 个」无歧义，停点与尾部分块由 $n$ 唯一确定（引理 2），故合法输出唯一。算法按 $n \bmod 3$ 产生与之逐块相同的划分（引理 2），且该划分满足「无 1-块、2-块至多两个」的全部约束（引理 1）。因此算法输出即题面唯一合法输出。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。过滤一遍扫描 $O(n)$；切分时每个字符恰好进入一个块，连接操作总量与输出长度同阶，共 $O(n)$。
- **空间复杂度**：$O(n)$。数字缓冲串、块列表与最终字符串均与 $n$ 同阶；$n \leq 100$ 的约束下毫无压力，即便放大到 $10^6$ 线性做法也轻松通过。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string reformatNumber(string number) {
        string s;
        for (char c : number)
            if (isdigit(c)) s.push_back(c);
        int n = s.size();
        int r = n % 3;
        int end = (r == 1) ? n - 4 : (r == 2 ? n - 2 : n);
        vector<string> parts;
        for (int i = 0; i < end; i += 3)
            parts.push_back(s.substr(i, 3));
        if (r == 1) {                       // 特例：末 4 位拆 2 + 2
            parts.push_back(s.substr(n - 4, 2));
            parts.push_back(s.substr(n - 2, 2));
        } else if (r == 2) {                // 尾 2 位一块
            parts.push_back(s.substr(n - 2, 2));
        }
        string ans;
        for (int k = 0; k < (int)parts.size(); ++k) {
            if (k) ans += "-";
            ans += parts[k];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def reformatNumber(self, number: str) -> str:
        s = [c for c in number if c.isdigit()]
        n = len(s)
        r = n % 3
        end = n - 4 if r == 1 else n - 2 if r == 2 else n
        parts = [''.join(s[i:i+3]) for i in range(0, end, 3)]
        if r == 1:                          # 特例：末 4 位拆 2 + 2
            parts += [''.join(s[n-4:n-2]), ''.join(s[n-2:n])]
        elif r == 2:                        # 尾 2 位一块
            parts.append(''.join(s[n-2:n]))
        return '-'.join(parts)
```

> 💡 代码只做一次 $n \bmod 3$ 分类，循环内零条件判断——把「边扫边判」的上百次比较压缩成了一次，也彻底规避了判断顺序写反的风险。

## 8. 边界情况与易错点

1. **$n = 2$ 或 $3$**：输出不含破折号（`"12"`、`"123"`），`join` 天然处理，无需特判。
2. **$n = 4$**：必须输出 `"12-34"` 而非 `"123-4"`——后者含 1-块。这是 $r = 1$ 的最小情形，也印证了「$n \bmod 3 = 1 \Rightarrow n \geq 4$」的自洽性。
3. **杂质位置任意**：`'-'` 与 `' '` 可出现在首、尾、中间（示例 4 首尾都有），过滤时一视同仁。
4. **单循环写法的判断顺序**：必须先判 `== 4` 再判 `< 4`；把 `< 4` 误写成 `<= 4` 或调换顺序，都会把 4 吞成整块。
5. **C++ `substr` 语义**：第二参数是**长度**；$r = 1$ 分支的 `s.substr(n-4, 2)`、`s.substr(n-2, 2)` 依赖 $n \geq 4$，由数论关系自动保证，无需运行时检查。
6. **不要输出多余破折号**：首块之前、末块之后都不能有 `'-'`；用 join 或「首块跳过」的拼接写法天然避免。
7. **空串不会出现**：题面保证至少 2 个数字，无需判空。
