# LeetCode 检查边长度限制的路径是否存在 题解

## 1. 题目概述

- **标题 / 题号**：检查边长度限制的路径是否存在（#1697，hard）
- **链接**：https://leetcode.cn/problems/checking-existence-of-edge-length-limited-paths/
- **来源**：LeetCode 第 220 场周赛 Q4
- **难度**：困难
- **标签**：并查集、图、排序、双指针（离线）

**题意**：给定 $n$ 个点的无向带权图边集 `edgeList`，其中 $[u, v, w]$ 表示点 $u$、$v$ 之间有一条权为 $w$ 的边（**两点间可能有重边**）。另有查询数组 `queries`，每个查询 $[p, q, \text{limit}]$ 问：是否存在一条从 $p$ 到 $q$ 的路径，使得路径上**每一条边的边权都严格小于** $\text{limit}$。对每个查询返回 `true` / `false`。

**约束**：

- $2 \le n \le 10^5$，$1 \le \text{edgeList.length},\ \text{queries.length} \le 10^5$
- $0 \le u_i, v_i, p_j, q_j \le n-1$，$u_i \ne v_i$，$p_j \ne q_j$
- $1 \le \text{dis}_i,\ \text{limit}_j \le 10^9$

> 💡 一句话定位：「路径上所有边都 $< \text{limit}$」等价于「$p$、$q$ 在**只保留边权 $< \text{limit}$ 的子图**里是否连通」。水位升高可用边只增不减、连通块只合并不分裂——把**查询按 limit 排序、边按权排序**，一次双指针扫描让并查集增量重放整个 Kruskal 加边过程，即经典的「**离线 + 并查集**」套路。

## 2. 示例

**示例 1**（重边 + 严格小于）

```text
输入：n = 3, edgeList = [[0,1,2],[1,2,4],[2,0,8],[1,0,16]], queries = [[0,1,2],[0,2,5]]
输出：[false, true]
解释：0 和 1 之间有两条重边（权 2 与 16）。
查询 (0,1,2)：不存在边权 < 2 的 0→1 路径（权 2 的边不满足 2 < 2）→ false。
查询 (0,2,5)：路径 0→1→2 的两条边权 2、4 均严格小于 5 → true。
```

**示例 2**（水位推进）

```text
输入：n = 5, edgeList = [[0,1,10],[1,2,5],[2,3,9],[3,4,13]], queries = [[0,4,14],[1,4,13]]
输出：[true, false]
解释：查询 (0,4,14)：w < 14 的边 {10, 5, 9, 13} 全部可用，全图连通 → true。
查询 (1,4,13)：w < 13 的边只有 {10, 5, 9}，点 4 孤立 → false。
```

**示例 3**（极端：一条边都不够用）

```text
输入：n = 2, edgeList = [[0,1,3]], queries = [[0,1,3],[0,1,4]]
输出：[false, true]
解释：边权 3 恰等于第一个 limit，3 < 3 不成立 → false；limit = 4 时该边可用 → true。
```

## 3. 解题思路

### 3.1 暴力思路：逐查询建图 BFS

对每个查询单独处理：筛出所有 $w < \text{limit}$ 的边构成子图，从 $p$ 出发 BFS / DFS，看 $q$ 是否可达。单次查询 $O(V + E)$，总计

$$O\big(Q \cdot (V + E)\big) = 10^5 \times (10^5 + 10^5) = 2 \times 10^{10}$$

严重超时。换「预处理」角度也不行：定义**最小瓶颈距离** $f(p,q) = \min_{\text{路径}}\ \max_{\text{路径上的边}} w$，则查询即问 $f(p,q) < \text{limit}$；但用 Floyd 变形 $f(i,j) = \min\big(f(i,j),\ \max(f(i,k),\ f(k,j))\big)$ 需要 $O(n^3)$ 时间与 $O(n^2)$ 空间，$n = 10^5$ 直接爆炸。

> ⚠️ 瓶颈的根源：把每个查询当成孤立问题，毫无复用。实际上 limit 相近的查询对应的子图几乎一样——**可用水位升高时图只会加边、不会删边**，而「只加边的连通性维护」恰是并查集的看家本领。

### 3.2 核心观察：临界子图连通性 + 连通块单调合并

![核心观察：查询等价于临界子图连通性，连通块随水位只合并不分裂](images/wc220_q4_threshold_subgraph_concept.svg)

**观察 1（判定转化）**：路径上每条边都严格小于 limit ⟺ $p$、$q$ 在临界子图

$$G_{\text{limit}} = \big(V,\ \{\, e \in E : w_e < \text{limit} \,\}\big)$$

中连通。limit 把「路径的瓶颈」一刀切开，剩下的问题纯而又纯：**连通性判定**——与路径的长短、形状完全无关。

**观察 2（单调性）**：$\text{limit}_1 \le \text{limit}_2 \Rightarrow E_{<\text{limit}_1} \subseteq E_{<\text{limit}_2}$，故 $G_{\text{limit}}$ 的连通块随 limit 升高**只合并、不分裂**。把每个 limit 值对应的连通块划分排成一列，得到一条逐步合并的链。

**观察 3（离线化）**：既然连通块演化单调，查询不必按给定顺序处理——按 limit **升序**离线重排（记录原下标），边按 $w$ **升序**排序；处理查询 $j$ 前用双指针把所有 $w < \text{limit}_j$ 的边 union 进并查集，然后 $O(\alpha(n))$ 查 $\text{find}(p) \stackrel{?}{=} \text{find}(q)$。每条边在整个算法中**至多被加入一次**。

> 💡 **与 Kruskal 的关系**：按边权升序往并查集里加边，正是 Kruskal 求 MST 的过程；不同 limit 的查询，等价于在这条加边时间线上的**不同时刻**询问两点是否已连通。本题是「离线 + 并查集」的教科书案例（同套路：按时间戳加边的 [1101. 彼此熟识的最早时间](https://leetcode.cn/problems/the-earliest-moment-when-everyone-become-friends/)）。

### 3.3 算法流程

![算法流程：边与查询各自排序后双指针扫描，并查集判连通](images/wc220_q4_offline_dsu_flow.svg)

```text
输入：n, edgeList, queries
1. 边 edgeList 按 w 升序排序
2. 查询下标 idx = [0..k−1] 按 limit 升序排序（答案要写回原下标）
3. 初始化并查集 fa[i] = i；边指针 e = 0
4. for j in idx（limit 单调不减）：
   a. while e < m 且 w[e] < limit_j：union(u[e], v[e])；e ← e + 1
   b. ans[j] ← ( find(p_j) == find(q_j) )
5. 返回 ans（已按原下标就位）
```

> ⚠️ 两处「差一个等号」的细节：加边条件是**严格小于** $w[e] < \text{limit}$（不是 $\le$，见示例 1 的查询 $(0,1,2)$）；查询按 limit 排序后，答案必须写回**原下标** $ans[j]$，不能按排序后的顺序输出。

### 3.4 示例演算

![示例演算：示例 2 水位 13 与 14 的两轮处理](images/wc220_q4_example_walkthrough.svg)

以示例 2 `edgeList = [[0,1,10],[1,2,5],[2,3,9],[3,4,13]]`、`queries = [[0,4,14],[1,4,13]]` 为例。边升序：$(1,2,5),\ (2,3,9),\ (0,1,10),\ (3,4,13)$；查询按 limit 升序：$(1,4,13)$（原下标 1）→ $(0,4,14)$（原下标 0）。

| 查询（升序） | limit | 新加入的边（$w < \text{limit}$） | 加边后连通块 | 判定 | 写回 |
|---|---|---|---|---|---|
| $(1,4,13)$，原下标 1 | 13 | $(1,2,5),\ (2,3,9),\ (0,1,10)$ | $\{0,1,2,3\},\ \{4\}$ | $\text{find}(1) \ne \text{find}(4)$ | `ans[1] = false` |
| $(0,4,14)$，原下标 0 | 14 | $(3,4,13)$ | $\{0,1,2,3,4\}$ | $\text{find}(0) = \text{find}(4)$ | `ans[0] = true` |

指针 $e$ 从 0 一路推进到 4，四条边各 union 恰一次；按原下标还原输出 $[\text{true}, \text{false}]$。

再看示例 1 的重边：$0$–$1$ 之间有权 $2$ 与权 $16$ 两条边，升序排序天然让权 $2$ 的边先进入；轮到权 $16$ 的边时两点早已同根，union 是空操作——**重边无需任何特殊处理**。

## 4. 算法细节

1. **查询排序存下标**：对下标数组 `idx = [0..k−1]` 按 `queries[j][2]` 排序，而不是直接排序 `queries`——答案要写回 `ans[原下标]`，原数组的顺序不能动。
2. **双指针不变式**：处理查询 $j$ 之前，已加入的边集恰为 $\{\, e : w_e < \text{limit}_j \,\}$。由于查询按 limit 升序、边按 $w$ 升序，指针 $e$ 单向前进、永不回退——这是「每条边至多 union 一次」的来源。
3. **并查集实现**：路径压缩（`find` 边走边改父指针）+ 按大小合并（小根挂大根）可保证均摊 $O(\alpha(n))$；$10^5$ 规模下只写路径压缩也完全够用。
4. **union 写法**：`fa[find(u)] = find(v)`——先把两端各自 find 到根，再挂接两个根，别把非根节点直接挂走。
5. **严格小于的位置**：`while (e < m && edgeList[e][2] < limit)`——边权恰等于 limit 的边**不加入**也不应加入（示例 1 查询 $(0,1,2)$ 即此陷阱）。
6. **答案容器**：`vector<bool>` / `list[bool]` 初始化为 `false`，循环中按原下标逐个覆写，最后整体返回，无需额外的「还原顺序」步骤。

## 5. 正确性证明

**引理 1（判定准则）**：查询 $(p, q, \text{limit})$ 的答案为 true ⟺ $p$、$q$ 在临界子图 $G_{\text{limit}}$ 中连通。

**证明**：若存在 $p \to q$ 路径使其每条边 $w < \text{limit}$，则这些边全部属于 $G_{\text{limit}}$ 的边集，该路径即 $G_{\text{limit}}$ 中的连通见证。反之，$G_{\text{limit}}$ 中任何 $p \to q$ 路径的每条边都满足 $w < \text{limit}$，即为所求路径。∎

**引理 2（连通块单调合并）**：若 $\text{limit}_1 \le \text{limit}_2$，则 $E_{<\text{limit}_1} \subseteq E_{<\text{limit}_2}$；且若 $x, y$ 在 $G_{\text{limit}_1}$ 中连通，则必在 $G_{\text{limit}_2}$ 中连通。

**证明**：边集包含关系由 $w < \text{limit}_1 \Rightarrow w < \text{limit}_2$ 立得。连通性：$G_{\text{limit}_1}$ 中 $x \to y$ 路径的每条边也在 $E_{<\text{limit}_2}$ 中，同一路径在 $G_{\text{limit}_2}$ 中依然存在。∎

**引理 3（升序加边与子图连通性同步）**：把所有边按 $w$ 升序排列，设 $S_t$ 为前 $t$ 条边构成的图。从 $n$ 个单点开始，对前 $t$ 条边逐条执行 union（两端点已同根则空操作）后，并查集的等价类恰为 $S_t$ 的连通块。

**证明**：对 $t$ 归纳。$t = 0$ 时两者均为 $n$ 个孤立单点，结论成立。设结论对 $t$ 成立，考察第 $t+1$ 条边 $(u, v)$：图上，$S_{t+1}$ 的连通块 = $S_t$ 的连通块合并 $u, v$ 所在的两块（若本就同块则不变）；并查集上，`union(u, v)` 恰好执行同样的合并（同根则不变）。两侧行为完全同步，归纳完成。∎

**定理（算法正确性）**：按 limit 升序处理查询、双指针将所有 $w < \text{limit}_j$ 的边 union 后查询 $\text{find}(p_j) = \text{find}(q_j)$，所得结果与真实答案一致；且每条边至多被 union 一次。

**证明**：先证加边集合的精确性。处理查询 $j$ 时：此前的加边均由 limit 不超过 $\text{limit}_j$ 的查询触发，故指针左侧的边全满足 $w < \text{limit}_j$；边序列按 $w$ 升序，故所有 $w < \text{limit}_j$ 的边构成排序后的前缀，本轮 `while` 循环恰好把它们全部加完，且条件 $w[e] < \text{limit}_j$ 保证指针停在第一条 $w \ge \text{limit}_j$ 的边上，未混入任何不可用边。由引理 3，此时并查集等价类恰为 $G_{\text{limit}_j}$ 的连通块；由引理 1，$\text{find}(p_j) = \text{find}(q_j)$ 即查询 $j$ 的答案。由引理 2，查询序列 limit 单调不减、可用边集单调不缩，故指针 $e$ 单向前进，每条边至多加入一次。答案按原下标写回，返回顺序正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(E \log E + Q \log Q + (E + Q)\,\alpha(n)\big)$。排序边 $O(E \log E)$、排序查询下标 $O(Q \log Q)$ 是瓶颈；主循环中指针 $e$ 从 $0$ 单向推进到 $m$（每条边恰一次 union），每个查询两次 `find`，合计 $O((E + Q)\,\alpha(n))$。
- **空间复杂度**：$O(n + Q)$。并查集父指针数组 $O(n)$；查询下标数组与答案数组 $O(Q)$（排序若原地完成则无额外开销）。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<int> fa;

    int find(int x) {                          // 路径压缩
        return fa[x] == x ? x : fa[x] = find(fa[x]);
    }

public:
    vector<bool> distanceLimitedPathsExist(int n, vector<vector<int>>& edgeList,
                                           vector<vector<int>>& queries) {
        int m = edgeList.size(), k = queries.size();

        fa.resize(n);
        iota(fa.begin(), fa.end(), 0);          // fa[i] = i

        sort(edgeList.begin(), edgeList.end(),
             [](const auto& a, const auto& b) { return a[2] < b[2]; });  // 边按 w 升序

        vector<int> idx(k);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(),                                          // 查询按 limit 升序
             [&](int a, int b) { return queries[a][2] < queries[b][2]; });

        vector<bool> ans(k);
        int e = 0;
        for (int j : idx) {
            while (e < m && edgeList[e][2] < queries[j][2]) {     // ① 严格小于
                fa[find(edgeList[e][0])] = find(edgeList[e][1]); //    两根挂接
                ++e;                                             //    指针单向前进
            }
            ans[j] = find(queries[j][0]) == find(queries[j][1]); // ② 写回原下标
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def distanceLimitedPathsExist(self, n: int, edgeList: List[List[int]],
                                  queries: List[List[int]]) -> List[bool]:
        fa = list(range(n))

        def find(x: int) -> int:                 # 路径压缩（迭代 + 折半）
            while fa[x] != x:
                fa[x] = fa[fa[x]]
                x = fa[x]
            return x

        edgeList.sort(key=lambda e: e[2])        # 边按 w 升序
        idx = sorted(range(len(queries)), key=lambda j: queries[j][2])

        ans = [False] * len(queries)
        e = 0
        for j in idx:
            while e < len(edgeList) and edgeList[e][2] < queries[j][2]:  # ① 严格小于
                fa[find(edgeList[e][0])] = find(edgeList[e][1])
                e += 1
            ans[j] = find(queries[j][0]) == find(queries[j][1])          # ② 写回原下标
        return ans
```

> 💡 两份代码逐行对应，核心就三步：排序边、排序查询下标、`while (w[e] < limit) union; e++`。查询的单调性交给排序维护，指针就永远不需要回退。

## 8. 边界情况与易错点

1. **严格小于，不是小于等于**：加边条件 `w[e] < limit`。limit 恰等于某边权时该边不可用（示例 1 查询 $(0,1,2)$：边权 2 不满足 $2 < 2$）。写成 `<=` 会把本应 `false` 的答案错判成 `true`。
2. **答案必须写回原下标**：查询按 limit 排序后处理顺序变了，`ans[j]` 的 `j` 是**原下标**；按排序后顺序直接 append 会整体错位。
3. **重边无需去重**：升序排序天然优先小边；后到的重边 union 时两点已同根，是空操作（示例 1 的权 16 重边）。
4. **并查集必须带路径压缩**：$10^5$ 规模下朴素 `find` 最坏退化成链，单次 $O(n)$；路径压缩（± 按大小合并）保证均摊 $O(\alpha(n))$。
5. **一条边都不加的查询**：limit 很小时（如示例 1 的 limit = 2）`while` 一次都不进，`find(p)`、`find(q)` 各自为根，正确返回 `false`；无需特判。
6. **limit 相同的多个查询**：排序后相邻处理，第二轮 `while` 条件不成立、指针不动，天然复用同一并查集状态，无需额外处理。
7. **递归 find 的栈深**：C++ 递归路径压缩在链状数据上可达 $10^5$ 层，保险起见可写迭代版（Python 参考代码即为迭代 + 路径折半）。
8. **别用最短路思维硬算**：本题只问连通性不问距离，Dijkstra / Floyd 一律超范围；「最小化路径最大边」的结构由 MST 承担（见延伸思考）。
