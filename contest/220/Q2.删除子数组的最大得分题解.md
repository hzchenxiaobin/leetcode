# LeetCode 删除子数组的最大得分 题解

## 1. 题目概述

- **标题 / 题号**：删除子数组的最大得分（#1695，medium）
- **链接**：https://leetcode.cn/problems/maximum-erasure-value/
- **来源**：LeetCode 第 220 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：给定正整数数组 `nums`，从中**删除恰好一个非空子数组**（连续一段），要求该子数组内**元素互不相同**；删除的**得分**为子数组各元素之**和**。返回只删除一个子数组可获得的**最大得分**。

**约束**：

- $1 \leq \text{nums.length} \leq 10^5$
- $1 \leq \text{nums}[i] \leq 10^4$

> 💡 一句话定位：「删除」只是叙事包装，本质是**在数组中选一段元素互异的连续子数组，使其和最大**——正是「无重复字符的最长子串」的**求和版**，正数约束保证了滑窗模板可以直接迁移。

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,4,5,6]
输出：17
解释：最优子数组是 [2,4,5,6]，元素互不相同，和为 2+4+5+6 = 17。
```

**示例 2**

```text
输入：nums = [5,2,1,2,5,2,1,2,5]
输出：8
解释：最优子数组是 [5,2,1] 或 [1,2,5]，和为 8。
```

**示例 3**（补充：全部元素相同）

```text
输入：nums = [7,7,7,7]
输出：7
解释：任何含两个 7 的子数组都非法，只能删除单个 [7]，得分 7。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有子数组

枚举全部 $O(n^2)$ 个子数组 $[l, r]$，对每个子数组用哈希集合判重并累加和，取合法者的最大值；固定 $l$ 让 $r$ 递增并增量维护集合，可做到 $O(n^2)$。$n = 10^5$ 时约 $10^{10}$ 次基本操作，远超时限。

瓶颈在于**重复检查**：固定右端点 $r$ 向左扩展时，一旦 $[l, r]$ 出现重复，更左的 $l$ 必然也非法——这个「一旦非法、永远非法」的单调性正是滑动窗口的切入点。

### 3.2 核心观察：无重复滑窗 + 「正数 ⇒ 最长即最大」

![核心观察：遇重复收缩左端，正数保证越宽和越大](images/wc220_q2_sliding_window_concept.svg)

两个性质联合支撑滑动窗口：

1. **合法性对子区间封闭**（无重复的单调性）：若 $[l, r]$ 互异，则其任意子区间也互异。于是固定 $r$ 时，合法左端点构成一段连续区间 $[\text{lo}_r, r]$，且 $\text{lo}_r$ 随 $r$ 增大**单调不降**——双指针不必回退。
2. **正数保证「越宽和越大」**：$\text{nums}[i] \geq 1$，同一右端点下更宽的合法窗口和严格更大。于是对每个 $r$，**只需考察以 $r$ 结尾的最长互异子数组**，其余候选一律被它压制。

> 💡 与「无重复字符的最长子串」的关系：两题的窗口扩张/收缩逻辑完全一致，只是把「记录长度 $\text{right} - \text{left} + 1$」换成「记录窗口和 $\text{sum}$」，判重结构从字符集换成整数哈希/计数数组即可。

> ⚠️ **为什么正数前提重要**：若含负数，同一右端点下「最长」不再等于「最大和」（更长但含大负数的窗口可能更差），滑窗只收缩一次就会漏解。本题 $\text{nums}[i] \geq 1$，模板天然成立。

### 3.3 算法流程

![算法流程：变长滑动窗口](images/wc220_q2_algorithm_flow.svg)

```text
输入：nums
1. left = 0，window_sum = 0，ans = 0，计数数组 cnt 清零
2. 遍历 right = 0 .. n−1，记 v = nums[right]：
   a. 去重收缩：当 cnt[v] > 0（v 已在窗口）时
      循环执行 cnt[nums[left]]−−、window_sum −= nums[left]、left++
   b. 入窗：cnt[v]++，window_sum += v
   c. 更新：ans = max(ans, window_sum)
3. 返回 ans
```

### 3.4 示例演算

![示例演算：nums=[4,2,4,5,6] 的窗口演化](images/wc220_q2_example_walkthrough.svg)

以示例 1 `nums = [4,2,4,5,6]` 为例：

| 步骤 | right | 动作 | 窗口 | window_sum | ans |
|------|-------|------|------|-----------|-----|
| 1 | 0 | 4 入窗 | [4] | 4 | 4 |
| 2 | 1 | 2 入窗 | [4,2] | 6 | 6 |
| 3 | 2 | 4 重复 → 移出左端 4，再入窗 | [2,4] | 6 | 6 |
| 4 | 3 | 5 入窗 | [2,4,5] | 11 | 11 |
| 5 | 4 | 6 入窗 | [2,4,5,6] | 17 | 17 |

全程仅第 3 步发生收缩（`left` 由 0 推进到 1），最终 `ans = 17`（子数组 `[2,4,5,6]`）。

## 4. 算法细节

1. **「删除」的包装要拆掉**：题面叙事是「删除子数组」，但数组并未真的发生变化——本质是**选择**一段互异子数组，千万不要模拟删除后的元素位移。
2. **判重结构按值域选型**：$1 \leq \text{nums}[i] \leq 10^4$，值域极小，用长度 $10^4 + 1$ 的**计数数组**（Python 可用 `bytearray(10001)`）比哈希集合更快、常数更小；值域大时退回哈希集合。
3. **窗口和增量维护**：入窗加、出窗减，每步 $O(1)$；切忌每次重算区间和（那样单步 $O(\text{len})$，最坏退化到 $O(n^2)$）。
4. **先收缩、后入窗**：必须先把 `v` 从窗口中「挤」出去，再执行 `cnt[v]++`；顺序写反会把重复元素留在窗口里，破坏互异不变式。
5. **收缩判据只看 `cnt[v]`**：不需要记录下标、不需要比较位置——`cnt[v] > 0` 等价于「v 在当前窗口中」。
6. **均摊视角**：`while` 嵌套在 `for` 内并不可怕——`left` 从 $0$ 单调推进到 $n-1$，每个元素至多入窗、出窗各一次，两指针合计移动 $O(n)$ 步。

## 5. 正确性证明

**引理 1（子区间封闭性）**：若子数组 $[l, r]$ 元素互异，则其任意子区间 $[l', r'] \subseteq [l, r]$ 元素也互异。

**证明**：$[l', r']$ 中每个值的出现次数不超过其在 $[l, r]$ 中的出现次数。若 $[l', r']$ 中某值 $v$ 出现 $\geq 2$ 次，则 $v$ 在 $[l, r]$ 中同样出现 $\geq 2$ 次，与 $[l, r]$ 互异矛盾。∎

**引理 2（合法左端点构成连续段）**：对每个右端点 $r$，记 $\text{lo}_r$ 为使 $[l, r]$ 互异的最小 $l$（单元素段 $[r, r]$ 总互异，故 $\text{lo}_r$ 存在），则合法左端点恰为 $[\text{lo}_r, r]$ 中的全部整数，且 $\text{lo}_r$ 随 $r$ 单调不降。

**证明**：$l \in [\text{lo}_r, r]$ 时 $[l, r] \subseteq [\text{lo}_r, r]$，由引理 1 互异；$l < \text{lo}_r$ 时若 $[l, r]$ 互异则与 $\text{lo}_r$ 的最小性矛盾。单调性：$[\text{lo}_{r+1}, r+1]$ 互异蕴含其子区间 $[\text{lo}_{r+1}, r]$ 互异（引理 1），故 $\text{lo}_r \leq \text{lo}_{r+1}$。∎

**引理 3（正数下最长即最大）**：若 $\text{nums}[i] \geq 1$，则以 $r$ 结尾的互异子数组中，最长的 $[\text{lo}_r, r]$ 和最大。

**证明**：任取合法 $[l, r]$，由引理 2 知 $l \geq \text{lo}_r$，于是

$$\text{sum}(l..r) = \text{sum}(\text{lo}_r..r) - \text{sum}(\text{lo}_r..l-1) \leq \text{sum}(\text{lo}_r..r)$$

因为被减去的 $\text{sum}(\text{lo}_r..l-1)$ 是若干正数之和（$l > \text{lo}_r$ 时严格不等）。∎

**定理（窗口不变式与正确性）**：算法处理完每个 $r$ 后，窗口恰为 $[\text{lo}_r, r]$，`window_sum` 为其和；最终返回值等于所有互异子数组的最大和。

**证明**：对 $r$ 归纳。$r = 0$ 时收缩不触发，窗口 $[0, 0] = [\text{lo}_0, 0]$。设处理完 $r-1$ 后窗口为 $[\text{lo}_{r-1}, r-1]$。处理 $r$，记 $v = \text{nums}[r]$：

- **$v$ 不在窗口中**：对 $l < \text{lo}_{r-1}$，$[l, r-1]$ 是以 $r-1$ 结尾且比 $[\text{lo}_{r-1}, r-1]$ 更长的互异子数组，与归纳假设矛盾，故 $[l, r-1]$ 非法，从而其超区间 $[l, r]$ 也非法（重复元素会保留）。而 $[\text{lo}_{r-1}, r]$ 互异（$v$ 不在窗口中出现，$v$ 即便出现在窗口左侧更远处，那类左端点也早已非法），故 $\text{lo}_r = \text{lo}_{r-1}$，收缩恰好零步，结论成立。
- **$v$ 在窗口中**：窗口互异保证 $v$ 恰出现一次，设位于 $p \in [\text{lo}_{r-1}, r-1]$。收缩循环在 `cnt[v] > 0` 时持续移出左端：位置 $p$ 被移出前 $v$ 始终在窗，循环不停；恰好移出 $p$ 后 `cnt[v] = 0` 停止，故新左端为 $p + 1$。$l \leq p$ 时 $[l, r-1]$ 含 $v$，$[l, r]$ 必有重复，非法；$l \in [p+1, r-1]$ 时 $[l, r-1] \subseteq [\text{lo}_{r-1}, r-1]$ 互异（引理 1）且 $v \notin [l, r-1]$，加入 $v$ 后仍互异。故 $\text{lo}_r = p + 1$，与算法所得一致。

两种情形下算法都把窗口停在最长合法位置，`window_sum` 的增量维护无误。由引理 3，每个 $r$ 处 `ans` 记录了以 $r$ 结尾的最大和；最优子数组必以某个 $r$ 结尾，且算法记录的每个值都对应真实合法子数组的和，故返回值既不超过也不小于最优值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`right` 遍历 $n$ 步；`left` 单调不回退，全程至多推进 $n$ 步，均摊到每次外层循环为 $O(1)$；计数数组读写均为 $O(1)$。
- **空间复杂度**：$O(V)$，$V = 10^4 + 1$ 为计数数组大小，是与 $n$ 无关的定值；若值域无界改用哈希集合，则为 $O(\min(n, V))$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumUniqueSubarray(vector<int>& nums) {
        int cnt[10001] = {0};              // 值域 1..1e4，计数数组判重
        int left = 0;
        long long windowSum = 0, ans = 0;  // 和上界 1e9，long long 防御性写法
        for (int right = 0; right < (int)nums.size(); ++right) {
            int v = nums[right];
            while (cnt[v] > 0) {           // v 已在窗口 → 收缩左端
                cnt[nums[left]]--;
                windowSum -= nums[left];
                ++left;
            }
            cnt[v]++;
            windowSum += v;
            ans = max(ans, windowSum);
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maximumUniqueSubarray(self, nums: List[int]) -> int:
        seen = set()
        left = 0
        window_sum = 0
        ans = 0
        for v in nums:
            while v in seen:               # v 已在窗口 → 收缩左端
                seen.remove(nums[left])
                window_sum -= nums[left]
                left += 1
            seen.add(v)
            window_sum += v
            ans = max(ans, window_sum)
        return ans
```

> 💡 两份代码逐行对应，判重结构（计数数组 / 集合）是唯一差异——滑窗模板「接口化」的体现：换判重结构不换窗口逻辑。

## 8. 边界情况与易错点

1. **$n = 1$**：答案即 `nums[0]`，循环一轮自然返回。
2. **全部元素相同**（如 `[7,7,7,7]`）：每个新元素都触发收缩把窗口清成只剩自己，答案为 $7$。收缩是 `while` 循环，一步到位于重复值之后，不会漏删。
3. **全部互异**：一次收缩都不发生，答案为整个数组之和。
4. **必须删除非空子数组**：答案 $\geq \max(\text{nums}) \geq 1$；`ans` 初始化为 $0$ 安全（正数保证任何真实窗口和 $\geq 1 > 0$）。若题目允许 $0$ 或负数，初值须改为 $-\infty$。
5. **和的溢出**：上界 $10^5 \times 10^4 = 10^9$，恰在 `int` 上限 $2.1 \times 10^9$ 之内但相当贴边，C++ 建议内部用 `long long` 累加更稳妥。
6. **先收缩后加入**：`while` 必须在 `cnt[v]++` 之前执行；写反则窗口中会出现两个 $v$，互异不变式被破坏，后续判重全部失真。
7. **不要模拟删除**：题面「删除」不改变数组本身——若误把删除后的数组拼接起来重新扫描，既超时又答错（最多只删一段，剩余部分不可再选）。
8. **计数数组大小**：值 $10^4$ 合法，数组须开到 `10001`（下标 $0..10^4$），只开 `10000` 会越界。
