# LeetCode 股票价格波动 题解

## 1. 题目概述

- **标题 / 题号**：股票价格波动（#2034，medium）
- **链接**：https://leetcode.cn/problems/stock-price-fluctuation/
- **来源**：LeetCode 第 262 场周赛 Q3
- **难度**：中等
- **标签**：设计、哈希表、有序集合、堆、数据流

**题意**：给定股票价格的**数据流**，每条记录含一个**时间戳** `timestamp` 与该时刻的**价格** `price`。记录**乱序到达**；同一时间戳重复出现时，**后到的记录更正先到的**（旧的作废）。请实现 `StockPrice` 类：`update(t, p)` 更新（或更正）某时间戳的价格；`current()` 返回**最新价格**（时间戳最晚的记录的价格）；`maximum()` / `minimum()` 返回当前所有**有效记录**中的最高 / 最低价格。

**约束**：

- $1 \le \text{timestamp},\ \text{price} \le 10^9$（值域大，排除值域桶 / 计数数组）
- 四个接口的**总调用次数**不超过 $10^5$
- `current` / `maximum` / `minimum` 被调用时，`update` 至少已被调用过一次（无需判空记录）

> 💡 **审题关键**：① 「更正」意味着同一时间戳只认**最近一次** `update`，**旧价格必须从最值统计中剔除**——这是全题唯一的难点；② 「最新」指**最大时间戳**，而非最后一次调用的时刻（记录乱序到达！）；③ 价格上界 $10^9$，必须用**基于比较**的结构（平衡树 / 堆）。

## 2. 示例

**示例 1**

```text
输入：
["StockPrice","update","update","current","maximum","update","maximum","update","minimum"]
[[],[1,10],[2,5],[],[],[1,3],[],[4,2],[]]
输出：
[null,null,null,5,10,null,5,null,2]

解释：
update(1,10)   // 时间戳 [1]，价格 [10]
update(2,5)    // 时间戳 [1,2]，价格 [10,5]
current()      // 返回 5（最新时间戳 2 → 价格 5）
maximum()      // 返回 10（最高价格对应时间戳 1）
update(1,3)    // 更正时间戳 1 的价格：10 → 3，价格 [3,5]
maximum()      // 返回 5（更正后最高价格为 5）
update(4,2)    // 时间戳 [1,2,4]，价格 [3,5,2]
minimum()      // 返回 2（最低价格对应时间戳 4）
```

**示例 2（乱序 + 更正叠加）**

```text
输入：
["StockPrice","update","update","update","current","maximum","minimum"]
[[],[3,7],[1,9],[3,1],[],[],[]]
输出：[null,null,null,null,1,9,1]

解释：时间戳乱序到达：先 3 后 1；update(3,1) 更正时间戳 3 的价格。
      最终 {1:9, 3:1}：current = ts2price[3] = 1（更正会改变最新价），

```

## 3. 解题思路

### 3.1 暴力思路

1. **哈希表 + 全表扫描**：`ts2price` 哈希表存「时间戳 → 当前有效价」，`update` 直接覆盖，$O(1)$；`current` / `maximum` / `minimum` 各扫一遍全表，$O(n)$。总调用 $10^5$ 时整体 $O(n^2) \approx 10^{10}$——**必超时**。`current` 可用单独维护的 `maxTs` 降到 $O(1)$，但 `maximum` / `minimum` 仍无救。
2. **维护单个 curMax / curMin 标量**：遇到更高的价就 `curMax = max(curMax, p)`，看似可行；但**更正**可能把 `curMax` 对应的旧价改小，此时需要「次大值」顶上——而标量早已把次大值信息丢掉。**只增不减的最值缓存无法支持删除**。
3. **瓶颈定位**：更正操作要求候选集支持「**删除任意元素 + 插入 + 取最值**」。`multiset`（平衡树）三样全支持，$O(\log n)$；堆支持后两样但不支持任意删——这正是**延迟删除**（lazy deletion）登场的经典场景。

### 3.2 核心观察：真相源与候选集分离

![核心概念：哈希表定真相，multiset 直接删或双堆延迟删维护最值](images/wc262_q3_concept.svg)

三个观察串成一条链：

1. **真相源唯一**：`ts2price`（哈希表）保存「时间戳 → 当前有效价格」，`update` **直接覆盖**；任何时刻、任何结构的有效性判断都以它为基准。配套一个标量 `maxTs` 记录见过的最大时间戳，则 `current() = ts2price[maxTs]`，$O(1)$——注意乱序到达，必须用 `max` 维护而非记「最后一次」。
2. **候选集要支持增删查最值**：当前有效价格全体构成一个会「改元素」的多重集。两套等价实现：
   - **方案 A（有序多重集）**：C++ `multiset<int>`。更正时**删旧插新**（`erase(find(old))` + `insert(p)`）；`maximum()` = `*rbegin()`、`minimum()` = `*begin()`，取顶 $O(1)$，全程**严格** $O(\log n)$，空间只存当前有效价。
   - **方案 B（双堆 + 延迟删除）**：堆只 `push` 不删；查询时**校验堆顶** $(p, t)$：若 `ts2price[t] == p` 则条目仍有效、直接返回；否则该条目过时（时间戳 $t$ 的价格已被更正），**弹出后继续看下一个堆顶**。适合没有平衡树标准库的语言（Python `heapq`）。
3. **延迟删除为什么可靠**：过时条目虽残留在堆里，但它自带的时间戳 $t$ 去查 `ts2price[t]` 必然对不上——**一查便知**。旧条目从不主动删，只在挡住堆顶时被「当场识破」弹出；每个条目至多被 push 一次、pop 一次，均摊 $O(\log n)$。

> 💡 **范式提炼**：「流式数据 + 可更正 + 最值查询」的通用骨架 = **哈希真相源 + 有序候选集**。候选集选型：语言有平衡树 → `multiset` 直接删；只有堆 → 延迟删除。这套骨架与 [239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)的「过期就弹出」、[1801. 积压订单](https://leetcode.cn/problems/number-of-orders-in-the-backlog/)的「按条件消费堆顶」同宗——本质都是**用真相源校验候选集顶部的时效性**。

### 3.3 算法流程

![算法流程：update 覆盖真相并增删或入堆，查询取表或校验堆顶](images/wc262_q3_flow.svg)

**`update(timestamp, price)`**：

1. 若 `timestamp` 已有记录：方案 A `prices.erase(prices.find(old))`；方案 B **什么都不做**（旧条目留在堆里当"死数据"）；
2. `ts2price[timestamp] = price`（覆盖，确立新真相）；`maxTs = max(maxTs, timestamp)`；
3. 方案 A：`prices.insert(price)`；方案 B：`maxHeap`、`minHeap` 各 push 一条 `(price, timestamp)`。

**`current()`**：返回 `ts2price[maxTs]`，$O(1)$。

**`maximum()`**：方案 A 返回 `*prices.rbegin()`；方案 B 循环——堆顶 $(p, t)$ 满足 `ts2price[t] != p` 就 pop，直到堆顶有效，返回 $p$。

**`minimum()`**：对称（`*prices.begin()` / 校验 `minHeap`）。

### 3.4 示例演算

![示例演算：update(1,3) 更正后过时堆顶在查询时被弹出](images/wc262_q3_walkthrough.svg)

按示例 1 逐步演算，两套方案并排对照（重点在第 5、6 步的更正瞬间）：

| 步骤 | 操作 | `ts2price` | `maxTs` | 方案 A `prices` | 方案 B `maxHeap` | 结果 |
|------|------|-----------|---------|----------------|-----------------|------|
| 1 | `update(1,10)` | `{1:10}` | 1 | `{10}` | `[(10,1)]` | — |
| 2 | `update(2,5)` | `{1:10, 2:5}` | 2 | `{5, 10}` | `[(10,1), (5,2)]` | — |
| 3 | `current()` | — | — | — | — | 5 |
| 4 | `maximum()` | — | — | `rbegin()=10` | 堆顶 `(10,1)` 有效 | 10 |
| 5 | `update(1,3)` | `{1:3, 2:5}` | 2 | `erase(10)`,`insert(3)` → `{3, 5}` | push `(3,1)`，**(10,1) 残留** | — |
| 6 | `maximum()` | — | — | `rbegin()=5` | 弹 `(10,1)`（过时），`(5,2)` 有效 | 5 |
| 7 | `update(4,2)` | `{1:3, 2:5, 4:2}` | 4 | `{2, 3, 5}` | push `(2,4)` 入双堆 | — |
| 8 | `minimum()` | — | — | `begin()=2` | `minHeap` 顶 `(2,4)` 有效 | 2 |

## 4. 算法细节

1. **真相源唯一**：一切校验 / 增删以 `ts2price` 为准，候选集（multiset 或堆）只是加速结构，永不另行记账。
2. **multiset 删旧必须传迭代器**：`prices.erase(prices.find(old))` 只删**一个**；写成 `prices.erase(old)` 会把**所有**等于 `old` 的价格一并删光——两个不同时间戳恰好同价时直接 WA（详见 §8 第 1 条）。
3. **延迟删除的校验条件**：必须拿堆顶条目**自己的**时间戳 $t$ 去查 `ts2price[t]`，再与条目自带的价格 $p$ 比；不能拿「当前查询的答案」或「最新时间戳」去比——查询前并不知道答案。
4. **maxTs 用 max 维护**：乱序到达下「最后一次 update 的时间戳」≠「最新时间戳」（示例 2 中先到 3 后到 1）。
5. **同价重更**：`update(1,10)` 之后又 `update(1,10)`——方案 A「删旧插新」同值无害；方案 B 堆中留两条 `(10,1)`，校验都通过，重复条目无害。
6. **价格「复活」**：`update(1,10) → update(1,3) → update(1,10)`——方案 B 堆里有两条 `(10,1)` 和一条 `(3,1)`，而 `ts2price[1] = 10`：`(3,1)` 过时被弹，两条 `(10,1)` 均有效。校验按**条目独立**进行，等价条目可互换，结论不受影响。
7. **堆的存储**：C++ `priority_queue<pair<int,int>>` 默认按 `first` 大顶、`greater<>` 切小顶；Python `heapq` 只有小顶堆，用 `-price` 取反模拟大顶堆（比较关系反两次，取出再取反还原）。
8. **内存账**：方案 B 堆中条目数上限 = `update` 调用次数 $\le 10^5$，每条目几十字节，MB 级——残留条目不清理也不爆内存；方案 A 更省，`prices` 只存当前有效价。

## 5. 正确性证明

**引理 1**（真相源不变量）：任意时刻，`ts2price[t] = p` 当且仅当 $p$ 是时间戳 $t$ 的**最近一次** `update` 的价格；哈希表的键集恰为已出现过的时间戳集。

**证明**：对 `update` 调用次数归纳。初始两集皆空。每次 `update(t, p)` 对键 $t$ 做覆盖赋值：若 $t$ 已存在则其值变为 $p$（成为最近一次），否则新增键 $t$。归纳即得。∎

**引理 2**（方案 A 不变量）：每次操作完成后，`multiset` 中的元素多重集恰为 $\{\, \text{ts2price}[t] : t \in \text{ts2price} \,\}$（当前有效价格全体，计重数）。

**证明**：归纳。初始 multiset 与哈希表同为空，成立。设某次 `update(t, p)` 前不变量成立：若 $t$ 是新键，`insert(p)` 使两边同步增加一个 $p$；若 $t$ 已有旧价 $old$，算法执行 `erase(find(old))`（恰删一个 $old$）再 `insert(p)`，与哈希覆盖 $old \to p$ 同步。查询操作不修改任一结构。∎

**引理 3**（延迟删除的可靠性与终止性）：方案 B 中称堆中条目 $(p, t)$ **有效**当且仅当 $\text{ts2price}[t] = p$。则 (a) 查询时堆中恒有有效条目，校验循环必终止于某个有效堆顶；(b) `maximum()` 返回值为当前有效价格的最大值（`minimum()` 对称）。

**证明**：(a) 两个事实：其一，每次 `update(t, p)` 都把 $(p, t)$ 压入两堆；其二，弹出只发生在校验循环里，且只弹**过时**堆顶（满足 $\text{ts2price}[t] \ne p$）。对每个出现过的时刻 $t$，其**最近一次** `update(t, p)` 压入的条目 $(p, t)$ 由引理 1 知此后恒满足 $\text{ts2price}[t] = p$，即**始终有效**；而有效条目一旦成为堆顶，循环立即返回、不会执行弹出，故**有效条目永不被弹出**。题面保证至少一次 `update`，故查询时至少一个时间戳的"最新条目"仍在堆中且有效，循环必停。(b) 大顶堆的堆顶总是剩余元素的最大者，故出堆审视的顺序按价格**从大到小**。设返回条目 $(p^*, t^*)$。凡价格 $> p^*$ 的条目，若仍留在堆中，则堆顶不可能轮到 $(p^*, t^*)$（它比堆顶大），矛盾；故它们都已被审视过——审视时未触发返回，说明它们当时即为过时条目（且价格只依赖条目本身，过时性不随时间恢复，被弹出合理）。于是不存在价格 $> p^*$ 的有效条目，而 $(p^*, t^*)$ 自身有效，故 $p^*$ 是有效价格的最大值。∎

> ⚠️ 严格地说，(b) 中「过时条目被弹出后不再参与」正是删除语义；即便某过时条目 $(p, t)$ 的价格后来「复活」（$t$ 再次被 update 回 $p$），堆中也另有**新压入**的有效条目 $(p, t)$ 承担该价格，被弹出的旧条目不影响答案。

**定理**：两方案四个接口均返回正确答案；方案 A 每操作严格 $O(\log n)$（查询 $O(1)$），方案 B 每操作均摊 $O(\log n)$，其中 $n$ 为 `update` 调用次数。

**证明**：**正确性**：`current` 由 `maxTs` 的维护与引理 1 直接得出；`maximum` / `minimum` 的正确性对方案 A 由引理 2（multiset 的最大 / 最小键即有效价格的最大 / 最小值）、对方案 B 由引理 3。**复杂度**：方案 A 的 `erase` / `insert` 为 $O(\log n)$，`begin()` / `rbegin()` / 哈希取值为 $O(1)$。方案 B：每次 `update` push 两个条目，总 push $\le 2n$；每次 pop 消耗一个曾 push 的条目，总 pop $\le 2n$；故全部堆操作总量 $O(n)$、每次 $O(\log n)$，均摊 $O(\log n)$——即便某次查询连续弹出大量积压条目，也是在偿还此前 push 的"债务"，总账不超额。∎

## 6. 复杂度分析

- **时间复杂度**：`update` $O(\log n)$（方案 A 严格，方案 B 均摊）；`current` $O(1)$；`maximum` / `minimum`：方案 A 取顶 $O(1)$，方案 B 均摊 $O(\log n)$（单次可能连弹多个过时条目，但总 pop 数受总 push 数约束）。$n \le 10^5$，整体约 $10^5 \times 17 \approx 2 \times 10^6$ 次比较，轻松通过。
- **空间复杂度**：方案 A 为 $O(\text{不同时间戳数})$——multiset 只存当前有效价；方案 B 为 $O(n)$——两堆存全部 `update` 产生的条目（含未清理的过时残留）。均为 MB 级，无压力。

## 7. 参考代码

### C++（方案 A：multiset，赛场最短路径）

```cpp
class StockPrice {
    unordered_map<int, int> ts2price;   // 真相源：时间戳 → 当前有效价
    multiset<int> prices;               // 候选集：当前全部有效价
    int maxTs = 0;                      // 见过的最大时间戳
public:
    void update(int timestamp, int price) {
        auto it = ts2price.find(timestamp);
        if (it != ts2price.end())
            prices.erase(prices.find(it->second));   // 删旧：必须传迭代器！
        ts2price[timestamp] = price;                 // 覆盖，确立新真相
        prices.insert(price);                        // 插新
        maxTs = max(maxTs, timestamp);
    }
    int current() { return ts2price[maxTs]; }        // O(1)
    int maximum() { return *prices.rbegin(); }       // O(1) 取顶
    int minimum() { return *prices.begin(); }        // O(1) 取顶
};
```

### Python（方案 B：双堆 + 延迟删除）

```python
import heapq

class StockPrice:
    def __init__(self):
        self.ts2price = {}          # 真相源：时间戳 → 当前有效价
        self.max_ts = 0             # 见过的最大时间戳
        self.max_heap = []          # 大顶堆：存 (-price, timestamp)
        self.min_heap = []          # 小顶堆：存 (price, timestamp)

    def update(self, timestamp: int, price: int) -> None:
        self.ts2price[timestamp] = price            # 覆盖，确立新真相
        self.max_ts = max(self.max_ts, timestamp)
        heapq.heappush(self.max_heap, (-price, timestamp))   # 只 push 不删
        heapq.heappush(self.min_heap, (price, timestamp))

    def current(self) -> int:
        return self.ts2price[self.max_ts]           # O(1)

    def maximum(self) -> int:
        while self.ts2price[self.max_heap[0][1]] != -self.max_heap[0][0]:
            heapq.heappop(self.max_heap)            # 过时条目，当场识破
        return -self.max_heap[0][0]

    def minimum(self) -> int:
        while self.ts2price[self.min_heap[0][1]] != self.min_heap[0][0]:
            heapq.heappop(self.min_heap)
        return self.min_heap[0][0]
```

> ⚠️ C++ 的 `erase(find(old))` 与 `erase(old)` 一字之差、天壤之别：前者删**一个**，后者删**所有**同值——两个不同时间戳恰好同价时后者直接 WA（构造 `update(1,5)`、`update(2,5)`、`update(1,3)` 后 `maximum()` 应为 5，传值删除会把它误删成 3）。Python 的校验条件必须用堆顶条目**自己的**时间戳查表，两份代码都不要顺手抄错。

## 8. 边界情况与易错点

1. **`multiset::erase(value)` 删光所有同值**（最大坑）：删旧价必须 `erase(find(old))`；`erase(old)` 在「不同时间戳同价 + 更正其一」时把别人的价格也删掉。
2. **延迟删除校验用条目自己的 $t$**：`ts2price[t] == p` 中的 $t$ 是堆顶条目自带的时间戳，不是 `maxTs`，也不是「当前查询值」。
3. **`maxTs` 必须 `max` 维护**：乱序到达下，最后一次 `update` 的时间戳未必最大（示例 2：先 `update(3,·)` 后 `update(1,·)`，最新仍是 3）。
4. **更正可能让最值变小**（示例 1 第 6 步 `maximum` 从 10 变 5），也可能变大——别写「最值只增不减」的错误缓存逻辑（§3.1 第 2 条）。
5. **`current` 会被更正改变**：`update(maxTs, newP)` 后 `current()` 应返回 `newP`——每次现查 `ts2price[maxTs]`，不缓存价格。
6. **同价重更与价格「复活」**：`10 → 3 → 10` 的反复横跳两方案都天然正确（§4 第 5、6 条），但值得对拍验证。
7. **查询不判空**：题面保证查询前至少一次 `update`，且引理 3 保证堆里恒有有效条目、引理 2 保证 multiset 非空——防御性判空可省。
8. **数值范围**：`timestamp`、`price` $\le 10^9$，`int` 装得下（上界 $\approx 2.1 \times 10^9$）；Python 天然大整数，`-price` 取反模拟大顶堆不受正负影响。
