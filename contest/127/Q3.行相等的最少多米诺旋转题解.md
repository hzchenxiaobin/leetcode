# LeetCode 行相等的最少多米诺旋转 题解

## 1. 题目概述

- **标题 / 题号**：行相等的最少多米诺旋转（#1007，medium）
- **链接**：https://leetcode.cn/problems/minimum-domino-rotations-for-equal-row/
- **来源**：LeetCode 第 127 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组

**题意**：一排多米诺骨牌，第 $i$ 张的上半部分是 `tops[i]`、下半部分是 `bottoms[i]`（取值 $1 \sim 6$）。可以旋转任意若干张牌（交换该牌的上下两半）。求使 **`tops` 全部相同** 或 **`bottoms` 全部相同** 所需的**最少旋转次数**；做不到返回 $-1$。

**约束**：

- $2 \le tops.length \le 2 \times 10^4$
- $bottoms.length = tops.length$
- $1 \le tops[i], bottoms[i] \le 6$

## 2. 示例

**示例 1**

```text
输入：tops = [2,1,2,4,2,2], bottoms = [5,2,6,2,3,2]
输出：2
解释：旋转第 1、3 张（0-indexed），上面一行全变成 2，共 2 次。
      若改让下面一行全变成 2，需要翻第 0、2、4 张共 3 次，反而更贵。
```

**示例 2**

```text
输入：tops = [3,5,1,2,3], bottoms = [3,6,3,3,4]
输出：-1
解释：tops[0] = bottoms[0] = 3，候选值只有 3；而第 2 张牌是 (1,6)，两面都不是 3，所以无法让任一行全等。
```

**示例 3**

```text
输入：tops = [1,1,1,1], bottoms = [2,2,2,2]
输出：0
解释：上面一行本来就全等，不需要旋转。
```

## 3. 解题思路

### 3.1 暴力思路

每张牌有「转 / 不转」两种状态，共 $2^n$ 种组合；对每种组合检查两行是否全等，取旋转次数最小值。复杂度 $O(2^n \cdot n)$，$n = 2\times 10^4$ 时是天文数字。

另一种「稍聪明」的暴力：枚举目标值 $v \in [1,6]$，对每个 $v$ 独立求最小旋转次数。这个方向是对的，因为**目标值只有 6 种可能**——再压缩一下就是正解：真正可能的 $v$ 只有 **2 个**。

### 3.2 核心观察：目标值只能是第 0 张牌的两个面

![目标值只能是第一张牌的上半或下半](images/wc127_q3_candidates_concept.svg)

设最终 `tops` 全为 $v$。**第 0 张牌也必须满足 `tops[0] == v`**，而这张牌旋转后朝上的那一面只能是 `tops[0]` 或 `bottoms[0]`。所以

$$v \in \{\, tops[0],\ bottoms[0] \,\}$$

目标值最多只有 **2 个候选**（若 `tops[0] == bottoms[0]` 则只有 1 个）。同理，若目标是 `bottoms` 全等，结论相同。

于是问题变成：对每个候选 $v$，求出「让整行都等于 $v$」的最少旋转次数。

**固定 $v$ 之后，每张牌的选择是独立的**：

- 若 `tops[i] == v`：不转就对上面行有贡献（此时 `bottoms[i]` 可能不等于 $v$，对下面行无贡献）；
- 若 `tops[i] != v` 而 `bottoms[i] == v`：**必须转**，否则这张牌无法让上面行等于 $v$；
- 若两面都不等于 $v$：这个 $v$ 办不到，直接否决。

因此「让 `tops` 全为 $v$」的旋转次数是一个**确定的数**：

$$\text{rot}_{\text{top}}(v) = \#\{\, i : tops[i] \ne v \,\}$$

（上面不等就必须转；上面相等则不必转。）同理

$$\text{rot}_{\text{bottom}}(v) = \#\{\, i : bottoms[i] \ne v \,\}$$

对该候选取 $\min(\text{rot}_{\text{top}}, \text{rot}_{\text{bottom}})$，再对两个候选取最小，就是答案。

### 3.3 算法流程

![算法流程：两个候选值，各扫一遍统计两行需要旋转的次数](images/wc127_q3_flow.svg)

```text
1. ans = -1
2. for v in { tops[0], bottoms[0] }:
        rt = rb = 0；ok = true
        for i in 0 .. n-1:
            若 tops[i] != v 且 bottoms[i] != v:  ok = false; break
            若 tops[i] != v:  rt++
            若 bottoms[i] != v:  rb++
        若 ok:  ans = min(ans, min(rt, rb))
3. 返回 ans
```

注意 `rt` 与 `rb` 都是「必须旋转的牌数」，而不是「随意选择的牌数」——因为一张牌要么必须转（保持 $v$ 露在上面或翻上来），要么不必转，没有第二种自由度。

### 3.4 示例演算

![示例演算：候选值 2 的两行计数](images/wc127_q3_walkthrough.svg)

对示例 1 的 `tops = [2,1,2,4,2,2]`、`bottoms = [5,2,6,2,3,2]`，候选 $v = 2$：

| $i$ | tops | bottoms | 含 2 吗 | 上面 ≠2（需转） | 下面 ≠2（需转） |
|---|---|---|---|---|---|
| 0 | 2 | 5 | ✓ | 否 | 是 |
| 1 | 1 | 2 | ✓ | 是 | 否 |
| 2 | 2 | 6 | ✓ | 否 | 是 |
| 3 | 4 | 2 | ✓ | 是 | 否 |
| 4 | 2 | 3 | ✓ | 否 | 是 |
| 5 | 2 | 2 | ✓ | 否 | 否 |
| 合计 | | | | $\text{rt} = 2$ | $\text{rb} = 3$ |

该候选的代价 $\min(2, 3) = 2$（上面一行更便宜）。另一个候选 $v = bottoms[0] = 5$：第 1 张牌是 $(1, 2)$，两面都不是 5 → 否决。最终答案 2 ✓。

再看示例 2：候选 $v = 3$，第 2 张牌 $(1,6)$ 两面都不是 3 → 否决；候选 $v = bottoms[0] = 3$，同一个候选 → 还是否决，返回 $-1$ ✓（注意示例 2 中 `tops[0] == bottoms[0] == 3`，两个候选重合）。

## 4. 算法细节

1. **候选去重**：`tops[0] == bottoms[0]` 时两个候选相同，会重复扫一遍，不影响正确性；想省常数可以先判断，但收益很小。
2. **提前否决**：一旦发现某张牌两面都不是 $v$，立刻 `break`，不必继续统计——此时 `rt/rb` 已无意义。
3. **计数含义**：`rt` 统计「上面不等于 $v$ 的牌数」，这些牌**必须**旋转（因为它们的 $v$ 在下面，且每张牌至少有一面是 $v$）。同理 `rb`。
4. **不能取 `min` 的误区**：有人会想「对每张牌选代价小的那面」，但目标是一整行统一，不是逐张独立优化——必须全行同一个目标值。
5. **复杂度**：两个候选 × 一次线性扫描 = $O(n)$，$n = 2\times 10^4$ 时约 $4\times 10^4$ 次比较。
6. **只关心「是否等于 $v$」**：牌的具体面值除 $v$ 外没有作用，所以不需要排序、不需要计数数组。
7. **答案为 0 的情形**：某一行本来就全等，对应候选的 `rt` 或 `rb` 为 0。

## 5. 正确性证明

**引理 1（候选值限制）**：若存在合法方案使 `tops` 全为 $v$（或 `bottoms` 全为 $v$），则 $v \in \{tops[0], bottoms[0]\}$。

**证明**：第 0 张牌旋转后朝上的面只能是 `tops[0]` 或 `bottoms[0]`。若方案使 `tops` 全为 $v$，则第 0 张牌朝上的面必须是 $v$，故 $v$ 等于两者之一。对 `bottoms` 同理（朝下的面也是这两个值之一）。∎

**引理 2（可行性判定）**：对固定 $v$，能使 `tops` 全为 $v$ 当且仅当对每个 $i$ 都有 `tops[i] == v` 或 `bottoms[i] == v`。

**证明**：必要性：若某张牌两面都不是 $v$，则无论转不转，它朝上的面都不可能是 $v$。充分性：对每张牌，若 `tops[i] == v` 则不转，否则 `bottoms[i] == v`，转一次即可让朝上面为 $v$；逐张处理后整行全为 $v$。∎

**引理 3（旋转次数被钉死）**：在引理 2 的可行前提下，使 `tops` 全为 $v$ 的最少旋转次数恰为 $\#\{i : tops[i] \ne v\}$。

**证明**：设 $A = \{i : tops[i] \ne v\}$。对 $i \in A$，因该牌至少一面是 $v$ 且上面不是 $v$，$v$ 只能在下面，故该牌**必须**旋转，否则上面仍不是 $v$；下界 $|A|$ 成立。另一方面，只旋转 $A$ 中的牌：$i \in A$ 旋转后上面变成 $v$；$i \notin A$ 本来上面就是 $v$，不需旋转。故 $|A|$ 可达。∎

**定理**：算法返回最少旋转次数，无解时返回 $-1$。

**证明**：设最优方案使某一行全为 $v$，旋转次数为 $c$。由引理 1，$v$ 是算法枚举的两个候选之一。若目标是 `tops`，由引理 3 有 $c \ge \#\{i: tops[i]\ne v\} = \text{rt}(v)$，故 $c \ge \min(\text{rt}(v), \text{rb}(v))$；若目标是 `bottoms` 同理。因此 $c \ge$ 算法对该候选给出的值 $\ge$ 算法最终答案。反之，对每个可行候选，算法取 $\text{rt}$ 或 $\text{rb}$ 都对应一个真实可行的旋转方案（引理 2、3），故答案可达。二者夹逼，算法输出即最优值。若两个候选都不可行，由引理 1 不存在任何合法方案，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。至多 2 个候选，每个候选一次线性扫描；`break` 只会更早结束。
- **空间**：$O(1)$。只用几个计数器，未使用额外数组。
- 对比：暴力 $O(2^n n)$；枚举 $v \in [1,6]$ 是 $O(6n)$，同样正确但没必要——候选只有 2 个。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minDominoRotations(vector<int>& tops, vector<int>& bottoms) {
        int ans = -1;
        for (int v : {tops[0], bottoms[0]}) {
            int rt = 0, rb = 0;
            bool ok = true;
            for (size_t i = 0; i < tops.size(); i++) {
                if (tops[i] != v && bottoms[i] != v) {
                    ok = false;
                    break;
                }
                if (tops[i] != v) rt++;
                if (bottoms[i] != v) rb++;
            }
            if (ok) {
                int c = min(rt, rb);
                if (ans < 0 || c < ans) ans = c;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minDominoRotations(self, tops: list[int], bottoms: list[int]) -> int:
        ans = -1
        for v in (tops[0], bottoms[0]):
            rt = rb = 0
            ok = True
            for t, b in zip(tops, bottoms):
                if t != v and b != v:
                    ok = False
                    break
                if t != v:
                    rt += 1
                if b != v:
                    rb += 1
            if ok:
                c = min(rt, rb)
                if ans < 0 or c < ans:
                    ans = c
        return ans
```

## 8. 边界情况与易错点

1. **`tops[0] == bottoms[0]`**：两个候选重合，重复扫描不影响正确性，但要确保 `ans` 的初值 `-1` 与「0 次旋转」区分开——用 `ans < 0 || c < ans` 判断，不能直接 `min(ans, c)`（`-1` 会一直保留）。
2. **`ans = 0` 被误判为「没找到」**：若用 `if (ans == 0) return 0` 之类的短路是安全的，但用「`ans` 为 0 即失败」做哨兵就错了。
3. **只检查了一行**：必须同时统计 `rt` 与 `rb` 并取 `min`；只算 `rt` 会漏掉「让下面一行全等更便宜」的情况。
4. **把「必须旋转」当成「可以自由选择」**：固定 $v$ 后每张牌的旋转与否是被决定的（引理 3），不存在「转或不转都行」的自由度。
5. **提前 `break` 后仍使用计数**：否决后 `rt/rb` 是半成品，必须用 `ok` 标记整体不可行，不能直接把 `min(rt, rb)` 计入答案。
6. **`n = 2`**：只有两张牌，逻辑不变；可能答案是 0、1 或 -1。
7. **有解但候选只在 `bottoms[0]`**：例如 `tops = [1,2]`、`bottoms = [2,2]`。目标值 2 来自 `bottoms[0]`，两个候选都要试。
8. **值域是 $1\sim6$**：不要假设牌面是 0/1，也不要用位运算压缩两张牌的面值。
