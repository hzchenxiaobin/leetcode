# LeetCode 统计相似字符串对的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计相似字符串对的数目（#2506，easy）
- **链接**：https://leetcode.cn/problems/count-pairs-of-similar-strings/
- **来源**：LeetCode 第 324 场周赛 Q1
- **难度**：简单
- **标签**：位运算、数组、哈希表、字符串、计数

**题意**：给定字符串数组 `words`，若两个字符串由**相同的字符集合**组成（与每个字符的出现次数、出现顺序都无关），则称它们**相似**。统计满足 `words[i]` 与 `words[j]` 相似的下标对 $(i, j)$ 的数目，其中 $0 \le i < j \le n - 1$。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \text{words[i].length} \le 100$
- `words[i]` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：words = ["aba","aabb","abcd","bac","aabc"]
输出：2
解释：满足条件的下标对共 2 对：
  - (0, 1)："aba" 与 "aabb" 都只由 {a, b} 组成
  - (3, 4)："bac" 与 "aabc" 都只由 {a, b, c} 组成
```

**示例 2**

```text
输入：words = ["aabb","ab","ba"]
输出：3
解释：三者字符集合均为 {a, b}，两两相似，共 C(3, 2) = 3 对。
```

**示例 3**

```text
输入：words = ["nba","cba","dba"]
输出：0
解释：三个字符串的字符集合分别为 {a,b,n}、{a,b,c}、{a,b,d}，互不相同，无相似对。
```

## 3. 解题思路

签到题的目标是**从题面到代码的最短路径**。本题题面只有一个关键定义：「由相同的字符组成」——即字符集合相等，与频次、顺序无关。抓住这一点，剩下的就是「等值对计数」的标准套路。

### 3.1 暴力思路

枚举所有下标对 $(i, j)$，对每对分别求出字符集合再判等，$O(n^2 \cdot L)$。本题 $n \le 100$、$L \le 100$，约 $10^6$ 次字符操作可以过。但它没有利用「同掩码的词天然成组」的结构——同一组 $k$ 个词本就贡献 $\binom{k}{2}$ 对，逐对判定把这层分组关系重复算了多遍。

### 3.2 核心观察：相似 ⇔ 字符集合相同 ⇔ 26 位掩码相等

![核心观察：字符集合编码为 26 位掩码](images/similar_pairs_mask_concept.svg)

- **相似只看集合**：`"aba"`（a×2, b×1）与 `"aabb"`（a×2, b×2）频次不同，但集合都是 $\{a, b\}$，故相似。
- **26 位掩码编码集合**：`words[i]` 仅含小写字母，用整数 `mask` 的第 $k$ 位记录第 $k$ 个字母是否出现。**集合相等 ⇔ 掩码相等**，建掩码一趟 $O(L)$。
- 于是原问题退化为：**统计掩码相等的下标对**——标准哈希计数题。

> 💡 **一句话直觉**：相似不看「成对」，看「分组」——掩码相同的词自然聚成一组，组里有 $k$ 个就配 $\binom{k}{2}$ 对。位掩码让「集合相等」变成「整数相等」，哈希让「分组计数」变成一趟扫描。

### 3.3 算法流程：一次遍历 + 哈希计数

![算法流程：一次遍历建掩码并累加计数](images/similar_pairs_counting_flow.svg)

维护哈希表 `cnt`（掩码 → 已出现次数），一趟扫描：

1. 对每个词 `w`：遍历字符建掩码，`mask |= 1 << (c - 'a')`；
2. **先累加**：`ans += cnt[mask]`——当前词与之前每个同掩码词各成一对；
3. **再登记**：`cnt[mask] += 1`。

等价视角：掩码 $m$ 共出现 $k_m$ 次，则答案 $= \sum_m \binom{k_m}{2}$；边扫边加正是这个组合数和的增量求和。

> ⚠️ 第 2、3 步**顺序不可换**：必须先取 `cnt[mask]` 的旧值（不含自己）累加，再自增入表，否则自己会和自己配成一对。

### 3.4 示例演算

![示例演算：逐行累加得到 2 对](images/similar_pairs_example_walkthrough.svg)

| $i$ | words[i] | 字符集合 | 此前同掩码数 | ans |
|-----|----------|----------|--------------|-----|
| 0 | "aba" | {a, b} | 0 | 0 |
| 1 | "aabb" | {a, b} | 1 | 1 |
| 2 | "abcd" | {a, b, c, d} | 0 | 1 |
| 3 | "bac" | {a, b, c} | 0 | 1 |
| 4 | "aabc" | {a, b, c} | 1 | 2 |

`ans = 2` ✓。注意 $i=2$ 的 $\{a,b,c,d\}$ 与 $i=3$ 的 $\{a,b,c\}$ **不相似**——成员必须完全一致，多一个 `d` 都不行；频次无关但**成员集**必须逐一相同。

## 4. 算法细节

1. **掩码构造**：`mask |= 1 << (c - 'a')`，每字符 $O(1)$；掩码取值范围 $[0, 2^{26})$，`int` 足够装下。
2. **计数顺序**：必须**先取旧值累加、再自增入表**，C++ 可合写为 `ans += cnt[mask]++`（后缀自增返回旧值）。
3. **哈希表选型**：C++ 用 `unordered_map<int, int>`；**不要**开 `int cnt[1 << 26]`（约 256MB，超内存）。Python 用 `dict`，也可直接以 `frozenset(w)` 为键，可读性更好。
4. **每对恰计一次**：处理词 $i$ 时累加的 `cnt[mask]` 只统计下标 $j < i$ 的词，因此无序对 $(j, i)$ 只在处理较大下标时被计入，天然去重。

## 5. 正确性证明

**引理 1**：`words[i]` 与 `words[j]` 相似 ⇔ $\text{mask}_i = \text{mask}_j$。

**证明**：`mask` 的第 $b$ 位为 $1$ 当且仅当字母表中第 $b$ 个字母在该词中出现，故 `mask` 是字符集合的二进制指示编码，「字符集合 → 掩码」是双射。而相似定义为字符集合相等，故相似 ⇔ 掩码相等。∎

**定理**：上述一次遍历算法返回的 `ans` 等于相似对总数。

**证明**：对遍历位置归纳。不变式：处理词 $i$ **之前**，`cnt[m]` 恰为满足 $j < i$ 且 $\text{mask}_j = m$ 的下标个数。执行 `ans += cnt[mask_i]` 时，由引理 1，这些 $j$ 恰是与 $i$ 相似的全部更小下标，每个相似对 $(j, i)$ 被计入恰一次；随后 `cnt[mask_i] += 1` 恢复不变式。遍历结束后，每个无序相似对 $(i, j)$（$i < j$）恰在处理较大下标 $j$ 时被计入一次，不重不漏。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L)$，$n$ 为词数、$L$ 为串长。每个词建掩码 $O(L)$，哈希查询与更新均摊 $O(1)$。
- **空间复杂度**：$O(n)$。哈希表至多存 $n$ 个不同掩码，掩码本身只占一个整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int similarPairs(vector<string>& words) {
        int ans = 0;
        unordered_map<int, int> cnt;
        for (const string& w : words) {
            int mask = 0;
            for (char c : w) mask |= 1 << (c - 'a');
            ans += cnt[mask]++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def similarPairs(self, words: List[str]) -> int:
        ans = 0
        cnt = {}
        for w in words:
            mask = 0
            for c in w:
                mask |= 1 << (ord(c) - ord('a'))
            prev = cnt.get(mask, 0)
            ans += prev
            cnt[mask] = prev + 1
        return ans
```

## 8. 边界情况与易错点

1. **单个词**（$n = 1$）：无下标对，返回 0。
2. **相似与频次无关**：`"ab"` 与 `"aabbb"` 相似。若误用 `sorted(w)`（保留重复字符）或频次向量作签名，会把相似判成不相似而漏算——签名必须**去重**（`frozenset(w)`、`sorted(set(w))` 或位掩码均可）。
3. **先加后登记**：`ans += cnt[mask]` 与 `cnt[mask] += 1` 顺序不可换，否则每个词会和自己配对，多算 $n$ 对。
4. **C++ 内存陷阱**：掩码范围 $2^{26}$，别用 `int cnt[1 << 26]` 数组（约 256MB），用 `unordered_map`。
5. **全员同集合**：$k$ 个同掩码词贡献 $\binom{k}{2}$ 对，如示例 2 的 3 对，注意别按 $k^2$ 或 $k(k-1)$ 计算。
