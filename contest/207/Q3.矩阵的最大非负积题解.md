# LeetCode 矩阵的最大非负积 题解

## 1. 题目概述

- **标题 / 题号**：矩阵的最大非负积（#1594，medium）
- **链接**：https://leetcode.cn/problems/maximum-non-negative-product-in-a-matrix/
- **来源**：LeetCode 第 207 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、矩阵

**题意**：给定 $m \times n$ 的矩阵 `grid`，从左上角 $(0,0)$ 出发，每步只能**向右**或**向下**，走到右下角 $(m-1, n-1)$。路径的**积**是路径上所有格子值的乘积。在所有路径中找**最大非负积**：若最大积 $\ge 0$，返回它对 $10^9+7$ 取模的结果；若所有路径的积都是负数，返回 $-1$。**取余是在得到最大积之后执行的**。

**约束**：

- $1 \le m, n \le 15$
- $-4 \le grid[i][j] \le 4$

> 💡 本题在本仓库另有[每日题解 1594](../../solution/1501-1600/1594_矩阵的最大非负积.md)，含面试问答与滚动数组版本。本篇按**周赛复盘视角**重写：侧重 **负数破坏最优子结构的「翻转化」理解**、**题面为何强调取模时机（取模不保序的构造性反例与证明）**、**值域 $4^{29}$ 恰好塞进 int64 的出题人意图**，以及**单轨 DP 在真实样例上翻车的逐步演算**。

## 2. 示例

**示例 1**

```text
输入：grid = [[-1,-2,-3],[-2,-3,-3],[-3,-3,-2]]
输出：-1
解释：3×3 网格任意路径都经过 5 个格子，全是负数 → 5 个负数相乘仍为负，
      不存在非负积路径。
```

**示例 2**

```text
输入：grid = [[1,-2,1],[1,-2,1],[3,-4,1]]
输出：8
解释：最优路径 1 × 1 × (−2) × (−4) × 1 = 8 —— 两个负数相乘翻身成正数。
```

**示例 3**

```text
输入：grid = [[1,3],[0,-4]]
输出：0
解释：路径 1 × 0 × (−4) = 0。0 是合法的非负积，输出 0 而不是 -1。
```

## 3. 解题思路

### 3.1 赛时切入：右下走网格 +「积」→ 教科书 DP，但要过负数关

「只能向右或向下」意味着路径是 DAG 上的拓扑序，62 / 64 / 174 一路的**网格路径 DP 定式**直接套：到 $(i,j)$ 的最优值由上、左两个前驱转移。

保底暴力：路径总数 $\binom{m+n-2}{m-1}$，$m=n=15$ 时 $\binom{28}{14} \approx 4 \times 10^7$ 条，每条乘 29 个数约 $1.2 \times 10^9$ 次乘法——C++ 勉强、Python 必 TLE；而 DP 只要 $O(mn) = 225$ 个格子，没有理由选暴力。

真正的坑在「积」这个字上：加法保序（大 + 大仍大），**乘法遇到负数就翻序**。这一下让「只存最大积」的经典 DP 直接失效，也让「边 DP 边取模」变成错误写法（§3.3 与 §5）。

### 3.2 核心观察：乘负数 = max/min 互换 → 每格双轨 (max, min)

用样例 2 实测（完整演算见 §3.4）：

- 到 $(1,1)$ 的路径积集合是 $\{4, -2\}$：走上路 $1 \times (-2) \times (-2) = 4$，走下路 $1 \times 1 \times (-2) = -2$；
- 只存 max 的 DP 在 $(1,1)$ 留下 4、丢掉 $-2$；可进入 $(2,1)$（格子值 $-4$）时翻身发生了：$(-2) \times (-4) = 8 > 4 \times (-4) = -16$——**被丢掉的最小积恰恰是最大积的原料**；
- 单轨 DP 终点得 4（WA），双轨终点得 8（AC）。

![核心观察：乘负数让 max/min 互换，每格必须双轨维护](images/wc207_q3_maxmin_model.svg)

结论：与 [152. 乘积最大子数组](https://leetcode.cn/problems/maximum-product-subarray/) 完全同构——**只要还可能乘到负数，最大与最小随时互换角色，两轨都必须维护**。区别只在维度：152 是一维单前驱（候选 2 个），本题是二维双前驱（候选最多 4 个）。

### 3.3 状态转移与算法流程：双轨填表 + 最后一步取模

**状态**：$mx[i][j]$ / $mn[i][j]$ = 从 $(0,0)$ 到 $(i,j)$ 的所有路径积的最大值 / 最小值。

**转移**（$g = grid[i][j]$，候选最多 4 个，前驱不存在则去掉）：

$$mx[i][j] = \max\big(mx[i-1][j] \cdot g,\ mn[i-1][j] \cdot g,\ mx[i][j-1] \cdot g,\ mn[i][j-1] \cdot g\big)$$

$$mn[i][j] = \min\big(mx[i-1][j] \cdot g,\ mn[i-1][j] \cdot g,\ mx[i][j-1] \cdot g,\ mn[i][j-1] \cdot g\big)$$

**初始化**：$mx[0][0] = mn[0][0] = grid[0][0]$。**答案**：$mx[m-1][n-1] < 0$ 返回 $-1$，否则返回 $mx[m-1][n-1] \bmod (10^9+7)$。

![算法流程：行优先逐格填双轨表，终点判号后取模](images/wc207_q3_algorithm_flow.svg)

> ⚠️ **取模时机是本题最大坑**：题面明说「取余是在得到最大积之后执行的」。中途取模**不保序**——$4^{15} = 1073741824$ 与 $4^{14} \times 3 = 805306368$ 比较本是前者大，模 $10^9+7$ 后却变成 $73741817 < 805306368$，DP 会保留错误的「最大值」（构造性反例见 §4.2，证明见 §5 引理 3）。正解：全程 64 位整数免模（值域恰好装得下，见 §4.1），最后一步才取模。

### 3.4 示例演算

对样例 2 的 $3 \times 3$ 网格行优先填表，每格记 $(mx, mn)$：

![示例演算：样例 2 双轨填表与两个翻身时刻](images/wc207_q3_walkthrough.svg)

```text
(0,0) (1,  1)   (0,1) (−2, −2)   (0,2) (−2, −2)
(1,0) (1,  1)   (1,1) ( 4, −2)★  (1,2) ( 4, −2)
(2,0) (3,  3)   (2,1) ( 8,−16)★★ (2,2) ( 8,−16)
```

三个关键格：

- $(1,1)$（$g=-2$）：候选 $\{(-2)\times(-2),\ 1\times(-2)\} = \{4, -2\}$ → $(4, -2)$。min 轨的 $-2$ 被保留，是翻身的火种；
- $(2,1)$（$g=-4$）：候选 $\{4\times(-4),\ (-2)\times(-4),\ 3\times(-4)\} = \{-16, 8, -12\}$ → $(8, -16)$。$(-2)\times(-4) = 8$ **从 min 轨翻身成 max**，原 max $4$ 同时跌成 $-16$ 进 min 轨；
- 终点 $(2,2)$：候选 $\{4, -2, 8, -16\}$ → $(8, -16)$，$mx = 8 \ge 0$ → 输出 $8 \bmod (10^9+7) = 8$。

若只维护 max：$(1,1)$ 只剩 4 → $(2,1)$ 候选 $\{-16, -12\}$ 得 $-12$ → 终点 $\max(4, -12) = 4$ ✗，与正解 8 相差一倍还全然不知。

## 4. 算法细节

### 4.1 值域估算：为什么敢全程不取模

路径长 $m + n - 1 \le 29$，每格绝对值 $\le 4$：

$$|\text{积}| \le 4^{29} = 2^{58} \approx 2.9 \times 10^{17} < 2^{63} - 1 \approx 9.2 \times 10^{18}$$

`long long` 安全装下；而 `int` 在 $4^{16} = 2^{32} \approx 4.3 \times 10^9$ 就溢出（`int` 上界 $\approx 2.1 \times 10^9$），16 个格子的全 4 路径即爆。**$-4 \le grid[i][j] \le 4$ 与 $m, n \le 15$ 的组合不是随手写的**：$4 = 2^2$、$29$ 格 → 恰好 $2^{58}$，卡进 int64 又放不进 int32——出题人在用数据范围提示「免模 + 64 位」。

### 4.2 取模时机：取模不保序的构造性反例

15 列网格可构造出某格的两个前驱积 $a = 4^{15} = 1073741824$（顶行 15 个 4）与 $b = 4^{14} \times 3 = 805306368$（第二行 14 个格子里 13 个 4 加 1 个 3）。真实大小 $a > b$，dp_max 该留 $a$；但模 $10^9 + 7$ 后 $a \equiv 73741817$（回绕），$b \equiv 805306368$（原样），比较反转为 $a' < b'$，DP 留下错误的 $b$，最终输出 $805306368$ 而非 $73741817$——WA。

![取模时机：取模不保序，模意义下 max 比较失效](images/wc207_q3_mod_timing.svg)

顺带一提：C++ 的 `%` 结果符号跟随被除数（$-5 \bmod M = -5$），负数轨看起来「没坏」，但正数轨一旦回绕，正负混比照样全乱。结论只有一条：**除最后一步外，全程不取模**。Python 天然大数无溢出之忧，但同理要忍住不在循环里写 `%`。

### 4.3 候选收集的写法

把「上、左两个前驱的 max/min 各乘 $g$」共 4 个候选统一收进临时变量 / 列表再取 max/min，比在两个 `if` 里分别维护更不易漏。**漏掉前驱的 min 是高频手误**——min 平时不发光，只在负数格发光。首行 / 首列的单一前驱用 `if (i > 0)` / `if (j > 0)` 保护。

### 4.4 空间压缩（模板价值）

每格只依赖上、左，可滚动成一维 $O(n)$：更新前的 `mx[j]` 是上方值、`mx[j-1]` 是左方值。本题 $m, n \le 15$ 无所谓，但「依赖仅上左 → 一维滚动」是网格 DP 的通用压缩套路，大矩阵场景直接迁移。

## 5. 正确性证明

**引理 1（乘法翻转化）**：对有限实数集 $P$ 与整数 $g$，记 $M^* = \max P$，$m^* = \min P$，则

$$\max_{p \in P} p \cdot g = \max(M^* g,\ m^* g), \qquad \min_{p \in P} p \cdot g = \min(M^* g,\ m^* g)$$

**证明**：分三种情形。$g = 0$：两边均为 0。$g > 0$：乘 $g$ 严格保序，$\max_{p} p \cdot g = M^* g \ge m^* g$，$\min$ 对称。$g < 0$：乘 $g$ 严格反序，$\max_{p} p \cdot g = m^* g \ge M^* g$，$\min$ 对称。∎

**引理 2（双轨不变式）**：按行优先顺序填表后，对每格 $(i,j)$ 有 $mx[i][j] = \max P_{i,j}$ 且 $mn[i][j] = \min P_{i,j}$，其中 $P_{i,j}$ 是 $(0,0)$ 到 $(i,j)$ 全部路径的积集合。

**证明**：对 $i + j$ 归纳。奠基 $i = j = 0$：唯一路径的积为 $grid[0][0]$，与初始化一致。归纳步：$i + j > 0$ 时任何路径的最后一步必来自 $(i-1,j)$（若 $i > 0$）或 $(i,j-1)$（若 $j > 0$），故

$$P_{i,j} = \bigcup_{\text{pred}} \{\, p \cdot g : p \in P_{\text{pred}} \,\}$$

对每个前驱应用引理 1：$\{p \cdot g\}$ 的极值恰为 $mx_{\text{pred}} \cdot g$ 与 $mn_{\text{pred}} \cdot g$ 中的较大 / 较小者；再对至多两个前驱取并集的极值，正是算法收集的至多 4 个候选的 max 与 min。由归纳假设前驱的 dp 值正确，故 $mx[i][j]$、$mn[i][j]$ 正确。∎

**引理 3（取模不保序）**：存在合法输入，使中途取模的 DP 输出错误答案。

**证明**：构造 $15 \times 15$ 网格：顶行全 4；第二行前 14 列恰有一个 3 其余为 4，$(1,14) = 1$；其余格子全 1。则 $(1,14)$ 的两个前驱积为 $a = 4^{15} = 1073741824$（沿顶行）与 $b = 4^{14} \times 3 = 805306368$（沿第二行）。真实 $a > b$，后续全乘 1，正确答案为 $a \bmod M = 73741817$。中途取模版在 $(1,14)$ 处比较 $a \bmod M = 73741817 < b \bmod M = 805306368$，保留 $b$ 轨，最终输出 $805306368 \ne 73741817$。∎

**定理**：算法返回值为：若 $\max P_{m-1,n-1} \ge 0$ 则其 $\bmod\,(10^9+7)$，否则 $-1$。

**证明**：由引理 2，终点 $mx$ 即 $\max P_{m-1,n-1}$。由 §4.1，全程 $|\text{积}| \le 4^{29} < 2^{63}$，64 位乘法与比较精确无溢出，dp 值均为真值。输出分支与题意逐句对应（$0$ 属非负，走取模分支返回 $0 \bmod M = 0$）。∎

> 💡 引理 1 是整套双轨 DP 的引擎：它说明「前驱的 $(max, min) \times g$」这至多 4 个数已穷尽所有路径积的极值可能——不必知道每条路径的积，只需知道极值，这正是 DP 状态压缩合法性的来源。

## 6. 复杂度分析

- **时间复杂度**：$O(mn)$。每个格子收集至多 4 个候选、常数次比较；$m, n \le 15$ 时至多 225 格，毫秒级。
- **空间复杂度**：$O(mn)$，两张 DP 表；滚动数组可压至 $O(n)$。纯迭代无递归栈开销。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxProductPath(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        const long long MOD = 1e9 + 7;

        vector<vector<long long>> mx(m, vector<long long>(n));
        vector<vector<long long>> mn(m, vector<long long>(n));
        mx[0][0] = mn[0][0] = grid[0][0];

        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                if (i == 0 && j == 0) continue;
                long long g = grid[i][j];
                long long best = LLONG_MIN, worst = LLONG_MAX;
                if (i > 0) {  // 上方前驱：max 与 min 都要收
                    best = max(best, mx[i - 1][j] * g);
                    best = max(best, mn[i - 1][j] * g);
                    worst = min(worst, mx[i - 1][j] * g);
                    worst = min(worst, mn[i - 1][j] * g);
                }
                if (j > 0) {  // 左方前驱：同理
                    best = max(best, mx[i][j - 1] * g);
                    best = max(best, mn[i][j - 1] * g);
                    worst = min(worst, mx[i][j - 1] * g);
                    worst = min(worst, mn[i][j - 1] * g);
                }
                mx[i][j] = best;
                mn[i][j] = worst;
            }
        }

        long long ans = mx[m - 1][n - 1];  // 全程未取模：|积| ≤ 4^29 < 2^63
        if (ans < 0) return -1;
        return (int)(ans % MOD);           // 得到最大积之后才取模
    }
};
```

### Python

```python
class Solution:
    def maxProductPath(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        MOD = 10 ** 9 + 7

        mx = [[0] * n for _ in range(m)]
        mn = [[0] * n for _ in range(m)]
        mx[0][0] = mn[0][0] = grid[0][0]

        for i in range(m):
            for j in range(n):
                if i == 0 and j == 0:
                    continue
                g = grid[i][j]
                cands = []
                if i > 0:  # 上方前驱
                    cands += [mx[i - 1][j] * g, mn[i - 1][j] * g]
                if j > 0:  # 左方前驱
                    cands += [mx[i][j - 1] * g, mn[i][j - 1] * g]
                mx[i][j] = max(cands)
                mn[i][j] = min(cands)

        ans = mx[m - 1][n - 1]  # 大数免模，最后一步才取
        return -1 if ans < 0 else ans % MOD
```

## 8. 边界情况与易错点

1. **中途取模（头号坑）**：取模不保序（§4.2 反例、§5 引理 3），边 DP 边 `%` 会保留错误轨并输出错误答案。正解：全程 64 位免模，终点判号后取模。题面特意写「取余是在得到最大积之后执行的」，读题时应当场标红。

2. **只维护 max**：样例 2 单轨 DP 得 4、正解 8。前驱的 min 平时不出力，只在负数格翻身——收集候选时两个前驱的 min 都别漏。

3. **0 是合法非负积**：样例 3 输出 0 而非 $-1$；判号条件是 `< 0` 不是 `<= 0`。路径一旦乘到 0，积恒为 0，可能恰好是「保底非负」。

4. **int 溢出**：$4^{16} \approx 4.3 \times 10^9$ 已超 `int`（$\approx 2.1 \times 10^9$），29 格路径积远超；C++ 必须用 `long long`（Python 天然大数无此忧）。

5. **$1 \times 1$ 矩阵**：唯一路径就是格子本身，$mx[0][0] = grid[0][0]$；若为负返回 $-1$（如 `[[-1]]`），为 0 返回 0，为正返回模后值。循环体整体被 `continue` 跳过，无需特判。

6. **首行 / 首列单前驱**：首行只看左、首列只看上，用 `if (i > 0)` / `if (j > 0)` 保护，否则越界或读到脏值。

7. **全负矩阵的奇偶性**：$3 \times 3$ 全负时路径长 5（奇数），积必为负（样例 1）。赛时可用它快速自测返回 $-1$ 的分支。

8. **终点取模的符号**：只有 $ans \ge 0$ 才取模，C++ 的 `ans % MOD` 非负，无需再写 `(ans % MOD + MOD) % MOD`（写了也不错，纯属多余）。
