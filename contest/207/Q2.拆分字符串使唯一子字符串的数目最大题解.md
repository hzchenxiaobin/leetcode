# LeetCode 拆分字符串使唯一子字符串的数目最大 题解

## 1. 题目概述

- **标题 / 题号**：拆分字符串使唯一子字符串的数目最大（#1593，medium）
- **链接**：https://leetcode.cn/problems/split-a-string-into-the-max-number-of-unique-substrings/
- **来源**：LeetCode 第 207 场周赛 Q2
- **难度**：中等
- **标签**：字符串、回溯、哈希表、剪枝

**题意**：给定字符串 `s`，将其拆分为若干**非空子字符串**，要求按原顺序拼接后能还原 `s`，且**每个子字符串互不相同**（唯一）。返回满足条件的拆分中，子字符串数目的**最大值**。

**约束**：

- $1 \le s.length \le 16$
- `s` 仅包含小写英文字母

> 💡 本题在本仓库另有[每日题解 1593](../../solution/1501-1600/1593_拆分字符串使唯一子字符串的数目最大.md)，含回溯三要素拆解与面试问答。本篇按**周赛复盘视角**重写：侧重 **$n \le 16$ 的规模定式识别**、**贪心为何必然失效**、**上界剪枝的引理-定理证明**，以及 `string_view`、`insert` 返回值两个赛时提速细节。

## 2. 示例

**示例 1**

```text
输入：s = "ababccc"
输出：5
解释：一种最大拆分为 ['a', 'b', 'ab', 'c', 'cc']。
      像 ['a', 'b', 'a', 'b', 'c', 'cc'] 不满足，因为 'a' 和 'b' 重复出现。
```

**示例 2**

```text
输入：s = "aba"
输出：2
解释：一种最大拆分为 ['a', 'ba']。不能拆成 ['a', 'b', 'a']，因为 'a' 重复。
```

**示例 3**

```text
输入：s = "aa"
输出：1
解释：['a', 'a'] 中 'a' 重复，只能整体作为一段。
```

## 3. 解题思路

### 3.1 赛时切入：$n \le 16$ 暗示指数级搜索

周赛读到数据范围 $n \le 16$（或 20、24 这类"奇怪的"小上界），应立即形成条件反射：**出题人在暗示 $O(2^n)$ 级别的指数做法**——回溯、状压 DP 或折半搜索三选一。

本题的暴力形态很直白：长度为 $n$ 的串有 $n - 1$ 个缝隙，每个缝隙「切 / 不切」，共 $2^{n-1}$ 种拆分方案；对每种方案检查所有段互不相同即可。$n = 16$ 时 $2^{15} = 32768$ 种，每种检查 $O(n)$，总量约 $5 \times 10^5$，暴力也能过。

但逐个枚举切分位掩码的写法笨拙：无法**增量判重**（每检查一种方案都要从头比对所有段），更无法**剪枝**。把「切分」建模成从左到右的决策过程，就是回溯——天然支持边走边判重、边走边估计上界。

### 3.2 核心观察：唯一性是全局约束 → 贪心失效，回溯 + `seen` 集合

「每段互不相同」这个约束的特殊之处在于：**第 $k$ 段能不能选，取决于前面选过哪些段**——这是一个作用于整条路径的全局约束，没有最优子结构，任何不回撤的贪心都不可靠。

以样例 2 的 `"aba"` 为例，最短优先的贪心先切 `"a"`、再切 `"b"`，剩下 `"a"` 与已用集合重复，**直接卡死**；而正确答案要先预见这一点，改选 `"ba"`（或一开始就切 `"ab"`）。局部最优的选择会连锁影响后续所有选择，只能靠「**能撤销**」的完整搜索保证正确性。

![核心观察：拆分是从左到右的决策，seen 集合守住全局互异，上界剪枝砍掉追平分支](images/wc207_q2_backtrack_model.svg)

回溯的框架：

- **状态**：游标 `start`（待切分的起始位置）+ 哈希集合 `seen`（当前路径上已用的子串）；
- **选择**：枚举终点 `end`，切出子串 `s[start..end]`，若不在 `seen` 中即可选；
- **终止**：`start == n` 时切完整串，用 $|\text{seen}|$ 更新全局最优 `best`。

**上界剪枝**是本题从"枚举完备"到"高效"的关键：剩余 $n - \text{start}$ 个字符，每段至少 1 个字符，**至多**再贡献 $n - \text{start}$ 段。若

$$|\text{seen}| + (n - \text{start}) \le \text{best}$$

则当前子树无论怎么切都不可能**严格超过**已知最优，整棵剪掉。

### 3.3 算法流程

![算法流程：剪枝 → 终止判定 → 枚举 end → 判重插入 → 递归 → 回溯擦除](images/wc207_q2_algorithm_flow.svg)

```text
dfs(start)：
  1. 若 |seen| + (n − start) ≤ best → return（上界剪枝）
  2. 若 start == n → best = max(best, |seen|)，return
  3. for end = start … n−1：
       sub = s[start..end]
       若 sub ∈ seen → 跳过该 end
       否则 seen.insert(sub) → dfs(end+1) → seen.erase(sub)（回溯）
```

注意两个顺序细节：**剪枝放在终止判定之前**（先算便宜的上界）；**`end` 从短到长枚举**（见 §4.1）。

### 3.4 示例演算

先用 `"aba"` 看清贪心卡死与回溯救场的全过程：

![示例演算：s=aba 的回溯决策树，死路与回溯](images/wc207_q2_backtrack_tree.svg)

```text
start=0, seen={}
├─ 切 "a" → seen={a}
│   ├─ 切 "b" → seen={a,b}
│   │   └─ 候选 "a" ∈ seen ✗ 死路 → 回溯：erase("b")
│   └─ 切 "ba" → seen={a,ba} → start=3=n ✓ 记录 2 段
├─ 切 "ab" → seen={ab}
│   └─ 切 "a" → seen={ab,a} → start=3=n ✓ 记录 2 段
└─ 切 "aba" → seen={aba} → start=3=n ✓ 记录 1 段
```

答案为 **2**，对应 `['a', 'ba']` 与 `['ab', 'a']` 两种方案。贪心路径 `a → b` 在唯一候选 `"a"` 处撞上重复，是纯粹的死路；回溯撤销 `"b"` 后改选 `"ba"` 才走出最优。

再看 `"ababccc"` 的完整过程——**短子串优先让第一条 DFS 路径直达最优**，之后上界剪枝收割其余分支：

![示例演算：s=ababccc 首条路径直达最优 5 段，随后剪枝收割](images/wc207_q2_walkthrough.svg)

第一条路径依次切出 `a | b | ab | c | cc`，`best = 5`。此后绝大多数分支在进入递归的瞬间即被剪掉，例如：

- 根的第三分支切 `"aba"` 后进入 `dfs(3)`：$1 + 4 = 5 \le 5$ → 整棵子树剪掉；
- 分支 `a | b | aba` 走到 `dfs(5)`：$3 + 2 = 5 \le 5$ → 剪掉。这棵子树原本最好也就是 `a|b|aba|c|cc`（5 段追平），剪掉不损失任何严格更优的可能。

## 4. 算法细节

### 4.1 搜索顺序：短子串优先

`end` 从 `start` 递增枚举，意味着**优先尝试单字符**。第一条 DFS 路径接近贪心路径，段数涨得最快，`best` 早早被抬到一个较高的水位——上界剪枝随之大幅生效。反之若先切长子串，早期 `best` 很小（整串成段只有 1），剪枝几乎不工作，搜索树会白白膨胀。

### 4.2 一次哈希完成「判重 + 插入」

C++ 中 `seen.insert(sub).second` 的返回值即"是否插入成功"，天然等价于"原来不在集合中"。相比先 `find` 再 `insert`，每个选择少一次哈希查找。

### 4.3 `string_view` 零拷贝

回溯过程中子串只是 `s` 的一个**视图**，而 `s` 的生命周期覆盖整个递归，因此 `seen` 可以用 `unordered_set<string_view>`：插入、判重、擦除都不发生字符串拷贝与内存分配（哈希比较仍是 $O(\text{len})$，但省掉了每步 $O(\text{len})$ 的分配开销）。

### 4.4 回溯必须恢复现场

`seen` 被同一层的所有兄弟分支共享。进入下一层前 `insert`，返回后必须 `erase`；否则兄弟分支会看到不属于自己路径的子串，把可选的段误判为"已用"，**漏解导致答案偏小**。

## 5. 正确性证明

**引理 1（枚举完备性）**：回溯树中每条从根到叶的路径对应一个合法拆分；反之，每个合法拆分对应树中唯一一条路径。

**证明**：路径上每步切出一段 $s[\text{start}..\text{end}]$，各段首尾相接、互不重叠地覆盖 $[0, n)$，拼接还原 $s$；只有不在 `seen` 中的段才被扩展，而由 `insert`/`erase` 的严格配对（归纳于递归深度），`seen` 恰等于当前路径已选段的集合，故路径上各段互不相同。反之，对合法拆分 $(t_1, \dots, t_k)$，从根依次沿边 $t_1, \dots, t_k$ 走：第 $i$ 步时 $\text{seen} = \{t_1, \dots, t_{i-1}\}$，由拆分合法 $t_i \notin \text{seen}$，边存在；由每步 `end` 唯一确定，路径唯一。∎

**引理 2（剩余上界）**：设某状态已选 $|\text{seen}|$ 段、游标在 `start`，则其任何后代完成方案的段数 $\le |\text{seen}| + (n - \text{start})$。

**证明**：完成方案是在已选段之后追加 $m$ 段**非空**子串，覆盖剩余 $n - \text{start}$ 个字符；每段至少 1 个字符，故 $m \le n - \text{start}$。∎

**定理**：算法返回的 `best` 等于最优值 $\mathrm{OPT}$。

**证明**：`best` 仅在叶节点被更新为某个合法拆分的段数，故 $\text{best} \le \mathrm{OPT}$。再证 $\mathrm{OPT} \le \text{best}$：取最优拆分对应的路径（引理 1）。若该路径被完整走到，其段数计入 `best`，Done；否则它在某祖先状态处被剪枝，由引理 2，该状态子树内任何完成方案的段数 $\le |\text{seen}| + (n - \text{start}) \le$ 剪枝时刻的 `best` $\le$ 最终 `best`，而最优拆分也在其中，故 $\mathrm{OPT} \le \text{best}$。∎

> 💡 剪枝条件用 $\le$ 而非 $<$：被剪掉的分支**至多追平** `best`。对"求最大值"而言追平无意义，所以 $\le$ 比 $<$ 多剪一类分支且不损失正确性——这正是 §3.4 中 `a|b|aba` 子树可被放心剪掉的依据。

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot 2^n)$。搜索树对应全部拆分前缀，最坏 $2^{n-1}$ 条完整路径，每条边上生成子串并哈希 $O(n)$。$n = 16$ 时约 $5 \times 10^5 \sim 10^6$ 次基本操作；上界剪枝 + 短子串优先的实际搜索量远小于该上界。
- **空间复杂度**：$O(n^2)$。`seen` 中至多 $n$ 个子串、每个最长 $n$，合计 $O(n^2)$ 字符（`string_view` 版仅存视图 $O(n)$ 个指针）；递归栈深 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxUniqueSplit(string s) {
        int n = s.size();
        unordered_set<string_view> seen;  // 视图零拷贝：s 生命周期覆盖整个递归
        int best = 0;
        dfs(s, 0, seen, best);
        return best;
    }

  private:
    void dfs(const string& s, int start, unordered_set<string_view>& seen, int& best) {
        int n = s.size();
        if ((int)seen.size() + (n - start) <= best) return;  // 上界剪枝（≤：追平也剪）
        if (start == n) {                                    // 切完整串
            best = max(best, (int)seen.size());
            return;
        }
        for (int end = start; end < n; ++end) {              // 短子串优先
            string_view sub(s.data() + start, end - start + 1);
            if (seen.insert(sub).second) {                   // 一次哈希：判重 + 插入
                dfs(s, end + 1, seen, best);
                seen.erase(sub);                             // 回溯：恢复现场
            }
        }
    }
};
```

### Python

```python
class Solution:
    def maxUniqueSplit(self, s: str) -> int:
        n = len(s)
        seen = set()
        best = 0

        def dfs(start: int) -> None:
            nonlocal best
            if len(seen) + (n - start) <= best:  # 上界剪枝（≤：追平也剪）
                return
            if start == n:                        # 切完整串
                best = max(best, len(seen))
                return
            for end in range(start, n):           # 短子串优先
                sub = s[start:end + 1]
                if sub not in seen:
                    seen.add(sub)
                    dfs(end + 1)
                    seen.remove(sub)              # 回溯：恢复现场

        dfs(0)
        return best
```

## 8. 边界情况与易错点

1. **$n = 1$**：如 `"a"`，整串成一段，答案 1。首条 DFS 路径直接记录，无需特判。

2. **全同字符**：`"aa"` → 1（样例 3，`['a','a']` 非法）；`"aaaa"` → 2（`a|aaa` 或 `aaa|a`）。答案不必也不可能是"全部切成单字符"。

3. **贪心诱惑**：`"aba"` 上最短优先贪心直接卡死。赛时若先写了贪心，交前务必用样例 2 自测——它是专门的贪心反例。

4. **忘记 `erase`**：兄弟分支共享 `seen`，漏掉回溯擦除会把可选段误判为已用，答案偏小且往往"看着能过样例"。

5. **剪枝条件的方向与放号**：应为 `len(seen) + (n - start) <= best`。写成 `<` 仍正确（剪得更弱）；写成 `>=` 方向反了会剪掉所有活分支。另外本写法中**剪枝先于终止判定**是安全的：`best` 初值为 0 而 $n \ge 1$，任何状态下 $|\text{seen}| + (n - \text{start}) \ge 1 > 0$，首个完整解不会被误剪。

6. **`substr` / 切片长度**：子串长度是 `end - start + 1`（闭区间 $[\text{start}, \text{end}]$），C++ 里误写成 `end - start` 会少切一个字符且不报错。

7. **不要用"不同字符数"当答案上界**：`"ababccc"` 只有 3 种字符，答案是 5——多字符段（`ab`、`cc`）也是互异集合的一员。合法的粗上界只有 $n$（每段 $\ge 1$ 字符）。
