# LeetCode 求出数字答案 题解

## 1. 题目概述

- **标题 / 题号**：求出数字答案（#3270，easy）
- **链接**：https://leetcode.cn/problems/find-the-key-of-the-numbers/
- **来源**：LeetCode 第 138 场双周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：给定三个正整数 `num1`、`num2`、`num3`（都不超过 9999）。先把不足四位的数**补前导 0**，得到三个四位数；答案 `key` 的第 $i$ 位（$1 \le i \le 4$，从高位到低位）取三个数第 $i$ 位的**最小值**。返回这个四位数（去掉前导 0 后的整数）。

例如 $num1 = 1$、$num2 = 10$、$num3 = 1000$，补零后是 `"0001"`、`"0010"`、`"1000"`，逐位取最小值得到 `"0000"`，即 $0$。

**约束**：

- $1 \le num1, num2, num3 \le 9999$

## 2. 示例

**示例 1**

```text
输入：num1 = 1, num2 = 10, num3 = 1000
输出：0
解释：补零为 0001、0010、1000
     第 1 位 min(0,0,1)=0，第 2 位 min(0,0,0)=0
     第 3 位 min(0,1,0)=0，第 4 位 min(1,0,0)=0
     答案 "0000" → 0
```

**示例 2**

```text
输入：num1 = 987, num2 = 879, num3 = 798
输出：777
解释：补零为 0987、0879、0798
     第 1 位 min(0,0,0)=0，第 2 位 min(9,8,7)=7
     第 3 位 min(8,7,9)=7，第 4 位 min(7,9,8)=7
     答案 "0777" → 777
```

**示例 3**

```text
输入：num1 = 1, num2 = 2, num3 = 3
输出：1
解释：补零为 0001、0002、0003，只有个位最小值非零，答案是 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：用 `to_string` / `str` 把三个数转成字符串，左侧用 `'0'` 补齐到长度 4，然后逐位比较取 `min`，最后把结果串转成整数。这样写直观，但要处理字符串拼接、`atoi` 等细节，容易在小地方出错。

### 3.2 核心观察：补零 = 取余时的高位自然为 0

![补前导零对齐后逐位取最小值](images/bw138_q1_pad_align.svg)

观察两点：

- **补零是"免费"的**：一个不足四位的数，反复对 10 取余，超出位数的位置自然得到 $0$，等价于在左边补了前导 0。例如 $1$ 连续取余四次得到 $1, 0, 0, 0$。
- **结果按十进制位权累加**：从个位开始处理，第 $t$ 轮（$t$ 从 0 开始）的位权是 $10^t$，把该轮的最小值乘上位权累加即可，无需再反转字符串。

于是整个算法只用一个循环 4 次，纯整数运算。

### 3.3 算法流程

![从低位到高位循环 4 次](images/bw138_q1_flow.svg)

```text
1. ans = 0，p = 1
2. 重复 4 次：
       d = min(num1 % 10, num2 % 10, num3 % 10)
       ans += d * p
       p *= 10
       num1 /= 10，num2 /= 10，num3 /= 10
3. 返回 ans
```

### 3.4 示例演算

以示例 2 的 $987, 879, 798$ 为例（从低位开始）：

| 轮次 | num1 % 10 | num2 % 10 | num3 % 10 | min | 位权 | 累加后 ans |
|------|-----------|-----------|-----------|-----|------|-----------|
| 0 | 7 | 9 | 8 | 7 | 1 | 7 |
| 1 | 8 | 7 | 9 | 7 | 10 | 77 |
| 2 | 9 | 8 | 7 | 7 | 100 | 777 |
| 3 | 0 | 0 | 0 | 0 | 1000 | 777 |

三轮之后三个数都变成 0，第四轮最小值仍是 0，故答案为 `777`，与示例一致。

## 4. 算法细节

1. **轮数固定为 4**：三个数都不超过 9999，补零后统一是四位数，循环 4 次正好覆盖千位到个位。
2. **位权累加**：`p` 从 1 开始每轮乘以 10，等价于"倒着构造答案"，避免字符串反转。
3. **同时整除**：每轮结束后三个数都要 `/= 10`，否则下一轮读到的还是同一位。
4. **前导零自动消失**：`ans` 是整数，最高位的 0 对数值没有贡献，天然满足"返回没有前导 0 的数字答案"。
5. **不需要判断位数**：无需 `if (num < 10)` 之类的特判，取余天然处理到位数不足的情况。

## 5. 正确性证明

**引理 1（取余序列即补零后的各位）**：对任意 $1 \le x \le 9999$，令 $d_t$ 为第 $t$ 轮（$t = 0,1,2,3$）的 $x \bmod 10$，则 $d_t$ 恰是 $x$ 补前导 0 后的四位数中从低位起的第 $t+1$ 位。

**证明**：$x$ 的十进制表示自低位起为 $x \bmod 10$、$\lfloor x/10 \rfloor \bmod 10$、……，第 $t$ 轮时 $x$ 已被整除 $t$ 次，故取到的正是低位起第 $t+1$ 位；当 $t$ 超过 $x$ 的位数时，$x$ 已变成 $0$，取余得 $0$，正是补前导 0 的结果。∎

**引理 2（位权构造）**：若第 $t$ 轮的最小值为 $m_t$，则 $\sum_{t=0}^{3} m_t \cdot 10^t$ 的十进制表示（去掉前导零后）恰为四位串 $m_3 m_2 m_1 m_0$。

**证明**：由位权展开的唯一性，$\sum m_t 10^t$ 的第 $t+1$ 位（低位起）就是 $m_t$（因为 $m_t \in [0,9]$）。前导零对整数取值无影响。∎

**定理**：算法返回的值等于题目定义的"数字答案"。

**证明**：由引理 1，第 $t$ 轮的 `min` 正是三个数补零后第 $t+1$ 位的最小值 $m_t$；算法把它乘上 $10^t$ 累加，由引理 2，最终 `ans` 的十进制表示恰为逐位最小值组成的四位数，去掉前导零后即为所求。∎

## 6. 复杂度分析

- **时间**：$O(1)$。固定 4 轮循环，每轮常数次取模、整除与比较。
- **空间**：$O(1)$。只用常数个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int generateKey(int num1, int num2, int num3) {
        int ans = 0, p = 1;
        for (int t = 0; t < 4; t++) {
            int d = min({num1 % 10, num2 % 10, num3 % 10});
            ans += d * p;
            p *= 10;
            num1 /= 10; num2 /= 10; num3 /= 10;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def generateKey(self, num1: int, num2: int, num3: int) -> int:
        ans, p = 0, 1
        for _ in range(4):
            ans += min(num1 % 10, num2 % 10, num3 % 10) * p
            num1 //= 10
            num2 //= 10
            num3 //= 10
            p *= 10
        return ans
```

## 8. 边界情况与易错点

1. **最高位可能是 0**：如示例 1、2，答案 "0000" / "0777" 要按整数返回 $0$ / $777$，不要返回字符串。
2. **轮数不足**：只循环 3 次会丢掉千位；只补三位会漏掉 $num \ge 1000$ 的情况，固定 4 次最稳。
3. **字符串补零易错**：`string(4 - len(s), '0') + s` 在 `len(s) == 4` 时长度参数为 0，没问题；但若用 `stoi` 处理带多个前导零的串也正确——不过整数取余更省事。
4. **位权顺序**：从低位起累加时位权是 $1, 10, 100, 1000$；若误把高位当首位会得到反序结果。
5. **三个数位数不同**：不要按"最长位数"循环，短数高位补 0 后结果依然是 4 位，统一 4 次最简单。
6. **Python 的整除用 `//`**：用 `/` 会变成浮点，导致后续取余得到意外结果。
