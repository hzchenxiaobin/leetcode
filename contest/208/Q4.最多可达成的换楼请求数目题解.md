# LeetCode 最多可达成的换楼请求数目 题解

## 1. 题目概述

- **标题 / 题号**：最多可达成的换楼请求数目（#1601，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-achievable-transfer-requests/
- **来源**：LeetCode 第 208 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、回溯、枚举

**题意**：$n$ 栋楼编号 $0 \sim n-1$，开始时全部满员。`requests[i] = [from_i, to_i]` 表示一名员工请求从楼 $from_i$ 搬到楼 $to_i$。从请求列表中选出若干条，若选出后**每栋楼的员工净变化为 0**（搬出人数 = 搬入人数），该子集就是可行的。返回可行子集的最大请求数。

**约束**：

- $1 \le n \le 20$
- $1 \le \text{requests.length} \le 16$
- $\text{requests[i].length} = 2$
- $0 \le from_i, to_i \lt n$

> 💡 **本题的钥匙藏在约束里**：请求数 $m \le 16$，子集总数 $2^{16} = 65536$——这几乎是在明示"直接枚举所有选 / 不选组合"。

## 2. 示例

**示例 1**

```text
输入：n = 5, requests = [[0,1],[1,0],[0,1],[1,2],[2,0],[3,4]]
输出：5

解释：全选 6 条时 3 号楼净变化 −1、4 号楼净变化 +1，不可行；
丢掉 [3,4] 后剩下 5 条恰好构成两个闭环：
{[0,1],[1,0]} 两人互换、{[0,1],[1,2],[2,0]} 三角轮换，每栋楼一进一出。
```

**示例 2**

```text
输入：n = 3, requests = [[0,0],[1,2],[2,1]]
输出：3

解释：[0,0] 是自环，delta 不变；[1,2] 与 [2,1] 互逆。
三条全选时每栋楼净变化均为 0。
```

**示例 3**

```text
输入：n = 4, requests = [[0,3],[3,1],[1,2],[2,0]]
输出：4

解释：四条请求连成一条闭环 0→3→1→2→0，全选即每栋楼一进一出。
```

## 3. 解题思路

### 3.1 陷阱与暴力思路：别被"配对交换"带偏

题面用"让 x 和 b 交换""y、a、z 三人轮换"来解释示例，很容易把问题理解成"设计一套搬迁方案"，进而往**匹配、网络流**方向想。但题目对"可行"的定义只有一条计数规则：**每栋楼搬出人数 = 搬入人数**，员工是谁、具体住哪间房完全不影响判定。

于是问题退化为纯组合问题：在 $2^m$ 个"选 / 不选"组合中，找净变化全零且请求数最多的组合。朴素做法是枚举每个子集、从零重算一遍每栋楼的进出计数再验证，单次 $O(m + n)$，总计 $O(2^m \cdot (m + n))$。代入上界 $m = 16, n = 20$：约 $65536 \times 36 \approx 2.4 \times 10^6$——**暴力枚举本身就是正解**。本题的"困难"在于敢不敢直接枚举，而不在算法复杂。

### 3.2 核心观察：净变化抵消

![一条请求对两栋楼净变化的影响与闭环可行示例](images/wc208_q4_delta_concept.svg)

- **单条请求的效果**：选中 $(from, to)$ 使 $\mathrm{delta}[from]$ 减 1、$\mathrm{delta}[to]$ 加 1（自环 $[x,x]$ 原地抵消）。
- **可行性判据**：子集 $S$ 可行 $\iff$ 所有 $\mathrm{delta}[b] = 0$，与员工如何配对无关。
- **图论视角**（彩蛋）：把每条请求看作有向边（可重边、可自环），可行子集恰是"每点入度 = 出度"的**欧拉子图**，总可分解为若干边不相交的环——示例 1 的"互换 + 三角轮换"正是一组环分解。

### 3.3 算法流程：两种等价实现

**实现一：位掩码枚举（迭代）**

![位掩码子集枚举流程图](images/wc208_q4_subset_enum_flow.svg)

1. `mask` 从 $1$ 到 $2^m - 1$，第 $i$ 位为 1 表示选请求 $i$；
2. 先算 $cnt = \mathrm{popcount}(mask)$，若 $cnt \le ans$ 直接跳过（剪枝）；
3. 重置 `delta`，对 `mask` 的每个 1 位执行 $\mathrm{delta}[from] \leftarrow \mathrm{delta}[from] - 1$、$\mathrm{delta}[to] \leftarrow \mathrm{delta}[to] + 1$；
4. 若 `delta` 全零，则 $ans \leftarrow cnt$。

**实现二：回溯（DFS + 两个加速器）**

![回溯版决策树与两种加速器](images/wc208_q4_backtrack_tree.svg)

1. 递归参数 $(i, cnt)$：前 $i$ 条已决策、当前选中 $cnt$ 条；全局维护 `delta` 数组与计数器 `nonzero`；
2. **选优先**：先走"选第 $i$ 条"分支（$cnt + 1$），回溯撤销后再走"不选"分支——让 $ans$ 尽早变大，剪枝更锋利；
3. **加速器① 上界剪枝**：$cnt + (m - i) \le ans$ 时整棵子树剪掉；
4. **加速器② nonzero 计数器**：$\mathrm{delta}[b]$ 离开 0 时 `nonzero` 加 1、回到 0 时减 1，叶子上 `nonzero == 0` 即可行，把 $O(n)$ 检查摊销成 $O(1)$ 增量维护。

### 3.4 示例演算

![示例 1 的子集尝试走查](images/wc208_q4_walkthrough.svg)

以示例 1（$m = 6$）走查位掩码版：

| 尝试 | mask | 选中请求 | delta[0..4] | 可行？ | ans |
|------|------|----------|-------------|--------|-----|
| ① | 111111₂ | 全部 6 条 | $[0,0,0,-1,+1]$ | ✗（3、4 号楼不平衡） | 0 |
| ② | 011111₂ | 丢掉 $r_5$ = [3,4] | $[0,0,0,0,0]$ | ✓ | 5 |

此后任何 1 的个数 $\le 5$ 的 mask 都被 `popcount ≤ ans` 剪掉，答案锁定为 5。

回溯版（选优先）的实际访问路径更少：先探到全选叶 {r₀…r₅}（`nonzero=2` ✗），回溯后第一个可行叶是 {r₀,…,r₄} → $ans = 5$；随后"不选 $r_0$"子树的上界 $0 + 5 = 5 \le ans$ 被整棵剪掉，"不选 $r_1$"同理，搜索随即结束。

## 4. 算法细节

1. **两种实现的取舍**：位掩码版代码短、无递归、行为确定；回溯版最坏同阶，但剪枝生效后实际访问结点往往远少于 $2^m$，且天然支持还原具体方案。
2. **popcount 剪枝的收益**：1 的个数不超过 $ans$ 的 mask 比例不低（$ans$ 越大占比越高），一条 `if` 换掉整段 $O(m + n)$ 工作。
3. **nonzero 计数器**：把"扫一遍 delta 是否全零"的 $O(n)$ 检查，摊销为每次 apply / undo 的 $O(1)$ 增量维护；撤销走的是与施加完全相反的修改，对称无需记忆。
4. **选优先的顺序**：先探"选"分支能更早拿到大 $ans$，反过来（不选优先）会让上界剪枝几乎失效。
5. **自环与重边**：$[x,x]$ 在 delta 上原地抵消；两条相同请求是两条独立的边，各计一次——两种写法都无需任何特判。
6. **提前终止**：$ans$ 达到 $m$（全选可行）时，popcount 剪枝与上界剪枝会自动封锁全部剩余分支，无需手写终止逻辑。

## 5. 正确性证明

**引理 1（净变化判据）**：对子集 $S$，定义 $\mathrm{delta}_S[b] = \mathrm{in}_S(b) - \mathrm{out}_S(b)$，其中 $\mathrm{in}_S(b)$、$\mathrm{out}_S(b)$ 分别是 $S$ 中进入、离开楼 $b$ 的请求数。则 $S$ 可行 $\iff$ 对所有楼 $b$ 有 $\mathrm{delta}_S[b] = 0$。

**证明**：被选请求 $(from, to)$ 恰表示一名员工从楼 $from$ 搬到楼 $to$，使楼 $from$ 人数减 1、楼 $to$ 人数加 1。因此执行 $S$ 后楼 $b$ 的人数变化恰为 $\mathrm{delta}_S[b]$。可行要求每栋楼人数不变，即所有 $\mathrm{delta}_S[b] = 0$。∎

**引理 2（增量维护正确性）**：算法对 $S$ 逐条执行 $\mathrm{delta}[from] \mathrel{-}= 1$、$\mathrm{delta}[to] \mathrel{+}= 1$ 后，数组恰等于 $\mathrm{delta}_S$；回溯版中 `nonzero` 恒等于 $|\{b : \mathrm{delta}[b] \ne 0\}|$。

**证明**：对已处理的选中请求数归纳：处理第 $k$ 条 $(from_k, to_k)$ 前，数组等于前 $k-1$ 条的净变化；按定义修改两分量后即等于前 $k$ 条。自环 $from = to$ 时两步同楼抵消，与"该楼人数不变"一致。对 `nonzero`：每次单点修改只可能改变一个分量"是否为零"的状态，按"离开 0 加 1、回到 0 减 1"维护即得不变量。∎

**引理 3（两种剪枝的安全性）**：(a) 位掩码版中满足 $\mathrm{popcount}(mask) \le ans$ 的子集可跳过；(b) 回溯版中满足 $cnt + (m - i) \le ans$ 的结点可整棵剪掉。

**证明**：(a) 该子集即使可行，请求数也不超过当前 $ans$，不可能改进答案。(b) 该结点的任何后代方案至多含 $cnt$ 条已选请求与剩余 $m - i$ 条，总数 $\le cnt + (m - i) \le ans$，同样不可能改进。∎

**定理**：两个算法都返回可行子集的最大请求数。

**证明**：位掩码版遍历全部 $2^m$ 个子集，由引理 1、2 每个子集的可行性判定正确，返回值是全体可行子集大小的最大值；由引理 3(a)，跳过的子集不改变该最大值。回溯版从根到叶的每条路径双向对应一个子集（第 $i$ 层的选择决定请求 $i$ 是否入选），完整展开即覆盖全部 $2^m$ 个子集；由引理 3(b)，被剪分支不含更优解；叶子上由引理 2，`nonzero == 0` 等价于引理 1 的可行判据。故两者都返回最优值。∎

## 6. 复杂度分析

- **时间复杂度**：位掩码版 $O(2^m \cdot (m + n))$。$m = 16, n = 20$ 时约 $2.4 \times 10^6$ 次基本操作：每个 mask 花 $O(n)$ 重置、$O(m)$ 按位更新、$O(n)$ 验证。回溯版最坏同阶（每个结点 $O(1)$ 更新、叶子 $O(1)$ 判定），剪枝生效后实际远快于上界。
- **空间复杂度**：$O(n + m)$。位掩码版只需 $O(n)$ 的 delta 数组；回溯版另有深度为 $O(m)$ 的递归栈。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumRequests(int n, vector<vector<int>>& requests) {
        int m = requests.size();
        vector<int> delta(n, 0);
        int ans = 0;
        // mask 的第 i 位为 1 表示选中请求 i
        for (int mask = 1; mask < (1 << m); ++mask) {
            int cnt = __builtin_popcount(mask);
            if (cnt <= ans) continue;  // 剪枝：1 的个数不超过当前答案
            fill(delta.begin(), delta.end(), 0);
            for (int i = 0; i < m; ++i) {
                if (mask >> i & 1) {
                    --delta[requests[i][0]];
                    ++delta[requests[i][1]];
                }
            }
            bool ok = true;
            for (int d : delta) {
                if (d != 0) { ok = false; break; }
            }
            if (ok) ans = cnt;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumRequests(self, n: int, requests: List[List[int]]) -> int:
        m = len(requests)
        delta = [0] * n
        nonzero = 0   # delta 不为零的楼数，为 0 即当前选择可行
        ans = 0

        def apply(b: int, d: int) -> None:
            nonlocal nonzero
            if delta[b] == 0:
                nonzero += 1
            delta[b] += d
            if delta[b] == 0:
                nonzero -= 1

        def dfs(i: int, cnt: int) -> None:
            nonlocal ans
            if cnt + (m - i) <= ans:   # 加速器①：上界剪枝
                return
            if i == m:                  # 叶子：cnt 必然 > ans
                if nonzero == 0:        # 加速器②：O(1) 判定可行
                    ans = cnt
                return
            f, t = requests[i]
            apply(f, -1)                # 选第 i 条
            apply(t, 1)
            dfs(i + 1, cnt + 1)
            apply(f, 1)                 # 撤销
            apply(t, -1)
            dfs(i + 1, cnt)             # 不选第 i 条

        dfs(0, 0)
        return ans
```

## 8. 边界情况与易错点

1. **自环请求 $[x,x]$**：delta 原地抵消、恒可行，两种写法都自动正确（示例 2 的 $[0,0]$），无需特判。
2. **叶子必须查 `nonzero`**：回溯版到达 $i = m$ 时不能只凭 $cnt \gt ans$ 就更新答案，必须确认 `nonzero == 0`。
3. **剪枝条件用 $\le$ 而非 $\lt$**：`cnt <= ans`、`cnt + (m - i) <= ans`——并列最优无需再访问；写成 $\lt$ 不会出错但白白多搜。
4. **delta 数值范围**：$|\mathrm{delta}[b]| \le m \le 16$，`int` 足够，无溢出。
5. **mask 从 1 开始枚举**：空集（mask = 0）大小为 0，与 `ans` 初值相同，跳过即可；`ans` 初值必须是 0（一个请求都不选恒可行）。
6. **别忘 popcount 剪枝**：位掩码版不加也能过（$2^{16}$ 很小），但这条 `if` 平均能省下近一半的验证工作。
7. **撤销要与施加严格对称**：回溯版撤销时按相反顺序反号修改，否则 `nonzero` 不变量被破坏。

**延伸思考**：

- 若要求输出一组具体方案：回溯版沿途记录"选了哪些请求"的掩码，找到最优时保存一份即可，$O(m)$ 还原。
- 若 $m \le 40$：折半搜索——两半各枚举 $2^{20}$ 个子集，以 delta 向量为键建哈希表，合并时查询互补向量。
- 若 $m$ 很大而 $n$ 很小：把相同 $(from, to)$ 的请求合并成容量 $c_{from,to}$ 的重边，"选最多请求且每点进出平衡"变成最大循环流问题（约束是有向图关联矩阵形式，存在整数最优解），可用网络流 / 线性规划求解。
