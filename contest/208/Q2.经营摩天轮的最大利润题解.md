# LeetCode 经营摩天轮的最大利润 题解

## 1. 题目概述

- **标题 / 题号**：经营摩天轮的最大利润（#1599，medium）
- **链接**：https://leetcode.cn/problems/maximum-profit-of-operating-a-centennial-wheel/
- **来源**：LeetCode 第 208 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟、贪心

**题意**：摩天轮共有 4 个座舱、每舱最多容纳 4 人，逆时针轮转，每转一次支付运行成本 `runningCost`。`customers[i]` 是第 `i` 次轮转**之前**到达的新游客数（即为接待他们你必须已轮转 `i` 次）。游客登舱时各付 `boardingCost`，座舱再次抵达地面即离开。**有空舱就不能让游客等待**（等待超过 4 人时每轮也只能上 4 人）。你可以随时停转，停转后所有后续轮转免费（只负责让游客安全落地）。求**取得最大利润所需的最小轮转次数**；若不存在利润为正的方案，返回 `-1`。

**约束**：

- $1 \le n = \text{customers.length} \le 10^5$
- $0 \le \text{customers}[i] \le 50$
- $1 \le \text{boardingCost}, \text{runningCost} \le 100$

> 💡 **读题要点**：真正能做的决策只有一个——**什么时候停**。登舱人数、运行成本全部被规则写死，这是本题最重要的观察。

## 2. 示例

**示例 1**

```text
输入：customers = [8,3], boardingCost = 5, runningCost = 6
输出：3
解释：
第 1 轮：8 人到达，4 人登舱、4 人等待，利润 = 4×5 − 1×6 = 14
第 2 轮：3 人到达，与等待的 4 人中 4 人登舱，利润 = 8×5 − 2×6 = 28
第 3 轮：最后 3 人登舱，利润 = 11×5 − 3×6 = 37
最大利润 37 在第 3 轮首次出现，返回 3。
```

**示例 2**

```text
输入：customers = [10,9,6], boardingCost = 6, runningCost = 4
输出：7
解释：前 3 轮每轮上 4 人，第 4~6 轮消化存量各上 4 人，第 7 轮上最后 1 人，
利润依次为 20, 40, 60, 80, 100, 120, 122，最大值 122 首次出现在第 7 轮。
```

**示例 3**

```text
输入：customers = [3,4,0,5,1], boardingCost = 1, runningCost = 92
输出：-1
解释：每轮收入远低于运行成本，利润序列为 −89, −177, −269, −357, −447，
始终为负；不运营（0 轮）利润为 0 也不为正，故返回 -1。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法：枚举停止时刻 $k$，对每个 $k$ 从头模拟 $k$ 轮、算出利润 $P(k) = \text{bc} \cdot B(k) - \text{rc} \cdot k$（$B(k)$ 为前 $k$ 轮登舱总数），再取最大者。总轮数 $K \le n + \lceil S/4 \rceil$（$S = \sum \text{customers}$），朴素重放的总代价是 $O(K^2)$，按上界约 $10^{12}$，不可行。

观察利润的递推关系：$P(k) = P(k-1) + \text{bc} \cdot \min(w_{k-1}, 4) - \text{rc}$，只依赖上一轮状态——**一次扫描就能增量维护出整条利润数列**，暴力重放的绝大部分工作是重复的。

### 3.2 核心观察：过程完全确定，唯一自由度是"何时停"

![利润数列概念图](images/wc208_q2_profit_sequence_concept.svg)

1. **登舱被规则锁死**：4 个座舱每舱限 4 人，但每轮只有 1 个座舱抵达地面；"有空舱就不能让游客等待"意味着每轮必须登 $\min(\text{waiting}, 4)$ 人，**没有任何选择余地**。于是等待人数序列、登舱序列、利润数列 $P(0), P(1), \dots, P(K)$ 全部唯一确定——这不是一道"策略"题，而是一道"求确定数列最值"的题。
2. **停转免费的意义**：停在第 $k$ 轮后，后续轮转全部免费、剩余游客安全落地，不再有任何收支。因此**停在 $k$ 的最终利润恰为 $P(k)$**——不需要把等待的游客送完，利润当场锁定。
3. **答案 = 最早的最大正利润**：在确定的数列 $P(k)$ 上找最大值；题目要求"最小轮转次数"，即取**首次**达到最大值的 $k$；若 $\max_k P(k) \le 0$（注意 $P(0) = 0$ 也不为正），返回 `-1`。
4. **$P(k)$ 不是单峰的**：例如 `customers = [0,0,50]`、`bc = 5`、`rc = 6` 时，$P = 0, -6, -12, 2, 16, \dots, 160$——前两轮空转亏损，随后持续拉升。所以**不能中途贪心剪枝，也不能只在服务完所有人后取终点**，必须逐轮记账、随时刷新最大值。

### 3.3 算法流程

![单次扫描模拟流程图](images/wc208_q2_simulation_flow.svg)

1. 初始化 `waiting = 0`、`profit = 0`、`rot = 0`、`best = 0`、`ans = -1`、下标 `i = 0`；
2. 循环条件 `i < n || waiting > 0`（还有游客没到或还有人等待）：
   - 若 `i < n`：`waiting += customers[i]`（新游客到达）；
   - `board = min(waiting, 4)`，`waiting -= board`（被迫登舱）；
   - `profit += board × boardingCost − runningCost`，`rot++`，`i++`；
   - 若 `profit > best`（**严格大于**）：`best = profit`，`ans = rot`；
3. 循环结束返回 `ans`——`best` 从 0 起步且只在严格变大时更新，若全程没有正利润，`ans` 自然保持 `-1`。

## 4. 算法细节

1. **循环条件必须包含两个分支**：`i < n` 保证空转轮也被记账（`customers[i] = 0` 时照样要付 `runningCost`，因为必须轮转 `i` 次才能迎接第 `i` 批游客）；`waiting > 0` 保证数组耗尽后继续消化等待存量。写成只有 `i < n` 会漏掉尾部轮次，写成只有 `waiting > 0` 会漏掉空转成本。
2. **`best` 初值为 0 而非 $-\infty$**：配合"严格大于才更新"，把"最大利润必须为正"和"并列取最小轮次"两条规则一次性编码进比较里，无需任何特判。
3. **利润增量维护**：每轮 $O(1)$ 更新 `profit`，避免重新累计登舱总人数。
4. **可选的尾部提前退出**：进入尾部（$i \ge n$）后每轮登舱数 $\min(\text{waiting},4)$ 单调不增，一旦某轮利润增量 $\le 0$，后续只会更差，可 `break`。但 $K \le n + \lceil S/4 \rceil \approx 1.35 \times 10^6$，全量模拟也毫无压力，加速可写可不写。注意**主循环（$i < n$）内不能提前退出**——新游客可能随时把利润拉回正增长（见 3.2 第 4 点）。
5. **数据范围**：收入上界 $S \times \text{bc} \le 5 \times 10^6 \times 100 = 5 \times 10^8$，`int` 尚可容纳，但 C++ 中乘法建议用 `long long` 防手滑。

## 5. 正确性证明

**引理 1（过程确定性）**：记 $w_k$ 为第 $k+1$ 轮开始前的等待人数，则任何运营方式下 $w_0 = 0$，$w_{k+1} = w_k + [k < n] \cdot \text{customers}[k] - \min(w_k, 4)$，且第 $k+1$ 轮登舱人数恰为 $\min(w_k, 4)$；从而累计登舱数 $B(k)$ 与利润 $P(k) = \text{bc} \cdot B(k) - \text{rc} \cdot k$ 都是唯一确定的数列。

**证明**：题面规定"每个座舱最多 4 人"且"每轮仅一个座舱到达地面"，故单轮登舱上限为 4；"有座舱空闲就不能让游客等待"禁止少上，上限约束禁止多上，故登舱人数只能是 $\min(w_k, 4)$，无选择余地。$w_k$ 的递推式由此唯一确定，对 $k$ 归纳即得整条数列唯一。∎

**引理 2（停止策略归约）**：设 $K$ 为首个满足 $i \ge n$ 且 $w = 0$ 的轮次（服务完所有游客）。运营者的全部决策是停止时刻 $k \in \{0, 1, \dots, K\}$；停在 $k$ 的最终利润恰为 $P(k)$。存在利润为正的方案 $\iff \max_{0 \le k \le K} P(k) > 0$，且最优利润即该最大值，取得最优的最小轮转次数为 $\min\{k : P(k) = \max_j P(j)\}$。

**证明**：停止后所有后续轮转免费、游客安全离舱，不再产生收支，故最终利润锁定为 $P(k)$。$k > K$ 的停止劣于 $k = K$：第 $K$ 轮后等待人数为 0，再轮转登舱数为 0，每轮只亏 $\text{rc}$，故只需考虑 $k \le K$。于是"最大化利润"就是"在确定的数列 $P(0..K)$ 上取最大"，最小轮转次数对应最早的 argmax。"利润为正"要求 $P(k) > 0$；若所有 $P(k) \le 0$（含 $P(0) = 0$），任何方案（包括不运营）利润都不为正，返回 `-1`。∎

**定理**：算法返回取得最大利润的最小轮转次数；若无正利润方案则返回 `-1`。

**证明**：循环每步按引理 1 的递推式更新 `waiting` 与 `profit`，归纳可得第 `rot` 轮结束时 `profit` $= P(\text{rot})$；循环恰好执行到 $K$ 轮（`i < n || waiting > 0` 在 $i \ge n$ 且 `waiting = 0` 时终止），覆盖了引理 2 的全部候选时刻。`best` 初值 0、仅当 `profit > best` 时更新并记录 `rot`：若 $M = \max_k P(k) > 0$，则 `ans` 为首个满足 $P(k) = M$ 的 $k$（后续并列的 $M$ 不再触发严格大于，更小的值亦不触发）；若 $M \le 0$，则 `profit > best = 0` 永不成立，`ans` 保持 `-1`。与引理 2 的结论一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + S/4)$，其中 $S = \sum_i \text{customers}[i] \le 5 \times 10^6$。总轮数 $K \le n + \lceil S/4 \rceil$（前 $n$ 轮迎接到达，之后每轮至少消化 4 名等待游客），上界约 $1.35 \times 10^6$ 次常数操作。
- **空间复杂度**：$O(1)$，只维护 `waiting / profit / rot / best / ans` 五个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperationsMaxProfit(vector<int>& customers, int boardingCost, int runningCost) {
        int n = customers.size();
        int i = 0, waiting = 0, rot = 0;
        long long profit = 0, best = 0;   // best 从 0 起步：利润必须为正
        int ans = -1;
        while (i < n || waiting > 0) {
            if (i < n) waiting += customers[i];
            int board = min(waiting, 4);  // 有空舱不能让游客等，被迫上满
            waiting -= board;
            profit += 1LL * board * boardingCost - runningCost;
            ++rot; ++i;
            if (profit > best) {          // 严格大于：并列时保留最小轮次
                best = profit;
                ans = rot;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minOperationsMaxProfit(self, customers: List[int], boardingCost: int, runningCost: int) -> int:
        i, n = 0, len(customers)
        waiting = profit = rot = 0
        best, ans = 0, -1
        while i < n or waiting:
            if i < n:
                waiting += customers[i]
            board = min(waiting, 4)      # 被迫登舱：min(等待, 4)
            waiting -= board
            profit += board * boardingCost - runningCost
            rot += 1
            i += 1
            if profit > best:            # 严格大于：并列取最小轮次
                best, ans = profit, rot
        return ans
```

## 8. 边界情况与易错点

1. **只在终点取答案是错的**：$P(k)$ 可能先降后升、也可能先升后降。例如 `customers = [4,1], bc = 5, rc = 6`：$P(1) = 14$、$P(2) = 13$，最大利润在第 1 轮，正确答案是 1 而非 2。必须逐轮刷新。
2. **空转轮照常扣费**：`customers[i] = 0` 且 `waiting = 0` 时仍需轮转（题目强制"必须在新游客到来前轮转 i 次"），漏掉这些轮会让轮次计数和成本双双出错。
3. **循环条件别写漏**：`i < n || waiting > 0` 缺一不可（见算法细节第 1 点）。
4. **比较必须严格大于**：写成 `>=` 会在并列最大值时返回**最晚**的轮次，与"最小轮转次数"的要求相反。
5. **`best` 初值必须是 0**：若初始化为 $-\infty$，全程亏损时会把利润为 0 或负的轮次当答案返回；初值 0 让 `-1` 的语义自动成立。
6. **返回的是轮转次数，不是利润**：两个量在代码里只差一个变量名，提交前务必确认。
7. **溢出**：C++ 中 `board * boardingCost` 用 `1LL` 提升后再累加（虽然 $5 \times 10^8$ 未超 `int`，防御性写法更稳）。
