# LeetCode 王位继承顺序 题解

## 1. 题目概述

- **标题 / 题号**：王位继承顺序（#1600，medium）
- **链接**：https://leetcode.cn/problems/throne-inheritance/
- **来源**：LeetCode 第 208 场周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、设计、哈希表

**题意**：

王国由国王及其后代构成一棵家族树。题目用递归函数 `Successor(x, curOrder)` 定义继承顺序：给定某人 `x` 与当前继承顺序 `curOrder`，

- 若 `x` 没有孩子，或 `x` 的孩子都已在 `curOrder` 中：`x` 是国王则返回 `null`，否则返回 `Successor(x 的父亲, curOrder)`；
- 否则返回 `x` 不在 `curOrder` 中**最年长**的孩子。

要求实现 `ThroneInheritance` 类：`birth(parent, child)` 记录新生儿、`death(name)` 记录死亡、`getInheritanceOrder()` 返回**剔除死者后**的当前继承顺序列表。

**约束**：

- `1 <= kingName.length, parentName.length, childName.length, name.length <= 15`，名字仅含小写英文字母
- 所有 `childName` 与 `kingName` 互不相同（名字可作唯一标识）
- `death` 的对象要么是国王、要么是已出生人员；每次 `birth` 时 `parentName` 一定在世
- 最多调用 $10^5$ 次 `birth` 和 `death`；最多调用 $10$ 次 `getInheritanceOrder`

## 2. 示例

**示例 1**

```text
输入：
["ThroneInheritance","birth","birth","birth","birth","birth","birth","getInheritanceOrder","death","getInheritanceOrder"]
[["king"],["king","andy"],["king","bob"],["king","catherine"],["andy","matthew"],["bob","alex"],["bob","asha"],[null],["bob"],[null]]

输出：
[null,null,null,null,null,null,null,["king","andy","matthew","bob","alex","asha","catherine"],null,["king","andy","matthew","alex","asha","catherine"]]

解释：bob 死后从结果中消失，但其子 alex、asha 依然继承，且相对位置不变。
```

**补充示例 2（国王驾崩）**

```text
ThroneInheritance t = new ThroneInheritance("king");
t.birth("king", "alice");
t.birth("king", "bob");
t.death("king");
t.getInheritanceOrder();   // 返回 ["alice", "bob"]
```

国王死亡只影响"是否出现在结果里"：遍历仍从根 `king` 出发，两个孩子照常继承。

**补充示例 3（全员死亡）**

```text
接示例 2：t.death("alice"); t.death("bob");
t.getInheritanceOrder();   // 返回 []
```

全树皆亡时返回空列表，这是合法输出。

## 3. 解题思路

### 3.1 暴力思路：照抄 Successor 逐个求后继

最直接的做法是把 `Successor` 原样翻译成代码：维护 `curOrder = [king]`，反复以 `curOrder` 末尾的人为 `x` 调用 `Successor`，把返回者追加进序列，直到返回 `null`。

问题出在开销上：每次调用都要**扫 `x` 的整个孩子列表**判断"是否都已在 `curOrder` 中"，不行还要**沿父链逐层回溯**。构造一个反例：国王一人拥有 $10^5$ 个孩子且全是叶子，则第 $i$ 次调用会从孩子回溯到国王并扫过前 $i-1$ 个已访问孩子，单次 $O(i)$，构造完整序列总计

$$\sum_{i=1}^{n} O(i) = O(n^2) = 10^{10}$$

远超时限。根源在于这种模拟**没有记忆**——每一步都从零开始重查"谁访问过了"，而 DFS 天然带着这份进度。

### 3.2 核心观察：反复调用 Successor = 一次前序遍历

![Successor 规则与前序遍历的等价关系](images/throne_preorder_equivalence.svg)

比赛时的快速切入路径：别急着写 `Successor`，先拿题面给的四人小例子（king、Alice、Bob、Jack）手玩一遍——生成顺序是 `king → Alice → Jack → Bob`，这正是家族树的**前序遍历**。再逐条对照规则即可确认这不是巧合：

- **`birth` 尾插保序**：新孩子追加在 `parent` 子女列表末尾，列表序即长幼序（年长者下标小）；
- **规则一 ↔ 前序下行**：`x` 有未访问孩子时返回最年长者——前序遍历访问完 `x` 后，下一个进入的正是其长子的子树首节点；
- **规则二 ↔ DFS 回溯**：`x` 的孩子全部访问完才转问父亲——这就是 DFS 完成子树后沿父链返回的标准行为；
- **问到国王仍无后继 ↔ 遍历结束**：整棵树走完，序列生成完毕。

于是 `getInheritanceOrder()` 不再需要维护 `curOrder` 增量地"问"后继，**从国王做一次前序 DFS，产出的序列就是继承顺序**。

> ⚠️ **`death` 的陷阱**：题目明说死亡"不影响 `Successor` 函数，也不影响继承顺序"，且示例 1 中 `bob` 死后 `alex`、`asha` 仍在序列里——所以**只标记、不删节点**，死者后代的顺位原样保留。

### 3.3 算法流程：哈希表存树 + 前序遍历过滤

![ThroneInheritance 类的数据结构与三个操作](images/throne_class_design_flow.svg)

| 成员 | 结构 | 作用 |
|------|------|------|
| `king` | 字符串 | 树根，遍历起点 |
| `children` | 哈希表：名字 → 子女列表 | 存树形；尾插保证长幼序 |
| `dead` | 哈希集合 | $O(1)$ 标记 / 查询死亡 |

| 操作 | 实现 | 复杂度 |
|------|------|--------|
| `birth(parent, child)` | `children[parent].append(child)` | $O(1)$ 均摊 |
| `death(name)` | `dead.add(name)` | $O(1)$ |
| `getInheritanceOrder()` | 从 `king` 前序 DFS，遇 `dead` 成员不输出但照常深入子树 | $O(n)$ |

### 3.4 示例演算

![示例演算：death 只标记不删除](images/throne_death_skip_walkthrough.svg)

以示例 1 走查（图见上）：

| 阶段 | 动作 | 结果 |
|------|------|------|
| 建树 | 构造 + `birth` × 7 | king 下有 andy、bob、catherine；andy 下有 matthew；bob 下有 alex、asha |
| 查询 ① | 前序 DFS | `[king, andy, matthew, bob, alex, asha, catherine]` |
| 死亡 | `death("bob")` | `dead = {bob}`，`children` 与树形零改动 |
| 查询 ② | 前序 DFS，遇 bob 跳过 | `[king, andy, matthew, alex, asha, catherine]` |

对比两次输出：只有 `bob` 一项消失，其余六人顺位原封不动——"跳过"而非"删除"，继承权由 `bob` 的后代顶替。

## 4. 算法细节

1. **名字即主键**：题目保证所有 `childName`、`kingName` 互不相同，字符串可直接做哈希键，不需要离散化成编号。名字长度 $\le 15$、总量 $\le 10^5$，字符串哈希的常数完全无压力。
2. **尾插 = 长幼序**：`children[x]` 只在 `birth(x, ·)` 时 `push_back`，新孩子永远排在末尾；前序按列表顺序递归，自然实现"兄姐及其后代先于弟妹"。
3. **`dead` 用集合天然幂等**：同一人被 `death` 多次也不需特判，集合去重。
4. **C++ `operator[]` 的自动插入**：DFS 里写 `children[name]`，对叶子节点会自动插入一个空列表，不影响正确性（总条目数仍是 $O(n)$）；若想严格避免副作用可改用 `find`。
5. **Python 必须防递归深度**：家族树可以退化成 $10^5$ 深的链（每人只生一个孩子），超过默认递归上限。参考代码的 Python 版用**显式栈**做迭代前序：孩子**逆序**入栈，保证最年长者先出栈。
6. **`death(king)` 一视同仁**：遍历起点永远是 `king` 这个树根，与它死活无关；国王驾崩只是结果里少第一项。

## 5. 正确性证明

**引理 1（子女保序）**：对任意人 `x`，`children[x]` 中子女的排列顺序与其出生顺序一致，即年长者下标更小。

**证明**：`children[x]` 只在 `birth(x, child)` 时于末尾追加新元素；出生顺序即 `birth` 调用顺序，故列表序 = 长幼序。∎

**引理 2（Successor 即前序后继）**：记 $P$ 为从国王出发、按 `children` 列表顺序递归的前序遍历序列。若 `curOrder` 恰为 $P$ 的前 $i$ 项，则 $i < n$ 时 $\text{Successor}(P_{i-1},\ curOrder) = P_i$；$i = n$ 时返回 `null`。

**证明**：记 $v = P_{i-1}$（前缀最后一个元素），考察前序中 $v$ 的后继：

- **情形一：$v$ 有孩子**。前序中 $v$ 的孩子都排在 $v$ 之后，故都不在前缀中；$v$ 之后紧跟着访问的是 $v$ 的第一棵子树首节点，即 $v$ 最年长的孩子 $P_i$（由引理 1 与前序定义）。`Successor` 的规则一"返回不在 `curOrder` 中最年长的孩子"返回同一人，且因所有孩子均未访问，"最年长的未访问孩子"就是最年长的孩子。
- **情形二：$v$ 无孩子**。$v$ 的子树（仅 $v$ 自身）已在前缀中，前序遍历按定义回退到 $v$ 的父亲 $p$：若 $p$ 有未访问的孩子，下一步访问 $p$ 的最年长未访问孩子 $P_i$；否则继续回退。这正是逐层上溯的过程，与 `Successor` 规则二"转到 $\text{Successor}(v\ 的父亲)$"逐步一致。若一路回退到国王仍无未访问孩子，说明整棵树都在前缀中（$i = n$），此时规则二对国王返回 `null`。∎

**定理**：`getInheritanceOrder()` 返回的列表，等于按 `Successor` 规则生成的完整继承顺序剔除死亡人员后的结果。

**证明**：由引理 2，从 `[king]` 起反复调用 `Successor` 逐个产出 $P$，即题目定义的唯一继承顺序；算法的前序 DFS 恰好依次产出 $P$ 的每个成员，仅在成员属于 `dead` 时不写入结果。`death` 只修改 `dead` 集合、不改 `children` 与 `king`（题面亦明确死亡不影响继承顺序），故被剔除的恰为死亡人员，其余成员的相对次序与 $P$ 完全一致。∎

## 6. 复杂度分析

- **时间**：`birth`、`death` 各 $O(1)$ 均摊（字符串长度 $\le 15$，哈希开销为常数）；`getInheritanceOrder` 为一次全树遍历 $O(n)$，其中 $n \le 10^5 + 1$ 为累计出生人数。最坏总开销 $10^5 \times O(1) + 10 \times O(n) \approx 2 \times 10^6$，轻松通过。
- **空间**：$O(n)$——`children` 存全部节点与边，`dead` 最坏存全部人员，输出缓冲至多 $n$ 项。

## 7. 参考代码

### C++

```cpp
class ThroneInheritance {
public:
    ThroneInheritance(string kingName) : king(kingName) {}

    void birth(string parentName, string childName) {
        children[parentName].push_back(childName);
    }

    void death(string name) {
        dead.insert(name);
    }

    vector<string> getInheritanceOrder() {
        vector<string> order;
        dfs(king, order);
        return order;
    }

private:
    void dfs(const string& name, vector<string>& order) {
        if (!dead.count(name)) order.push_back(name);
        for (const string& child : children[name]) dfs(child, order);
    }

    string king;
    unordered_map<string, vector<string>> children;
    unordered_set<string> dead;
};
```

### Python

```python
class ThroneInheritance:
    def __init__(self, kingName: str):
        self.king = kingName
        self.children = defaultdict(list)
        self.dead = set()

    def birth(self, parentName: str, childName: str) -> None:
        self.children[parentName].append(childName)

    def death(self, name: str) -> None:
        self.dead.add(name)

    def getInheritanceOrder(self) -> List[str]:
        order = []
        stack = [self.king]
        while stack:
            name = stack.pop()
            if name not in self.dead:
                order.append(name)
            # 逆序入栈：最年长的孩子最先进栈顶 → 先被访问
            stack.extend(reversed(self.children[name]))
        return order
```

> 💡 Python 版刻意用迭代而非递归：链形家族树深度可达 $10^5$，默认递归上限 1000 会直接 `RecursionError`。C++ 版递归传递 `const string&`，栈帧很小，一般可过；求稳也可按同样思路改写成显式栈。

## 8. 边界情况与易错点

1. **死者后代必须保留**（本题最大陷阱）：把 `bob` 从树里"删除"会让 `alex`、`asha` 彻底消失。正确做法是只进 `dead` 集合、输出时跳过。示例 1 的 `death("bob")` 正是官方埋的这颗雷。
2. **国王死亡**：结果可能不含 `king`，但遍历起点永远是 `king`，绝不能因为根死了就不从根出发（见补充示例 2）。
3. **全员死亡**：返回空列表 `[]` 是合法输出，不要对空结果做特殊处理（见补充示例 3）。
4. **递归深度**：链形树深达 $10^5$，Python 递归必挂；C++ 传 `const string&` 控制栈帧，或干脆写迭代版。
5. **重复 `death` 与 `birth` 时 parent 在世**：前者靠集合幂等天然解决；后者题目已保证，无需校验——即使父已死，往其名下"添孩子"也不影响算法正确性。
6. **`unordered_map` 的 `operator[]` 副作用**：DFS 中对叶子节点访问 `children[name]` 会插入空列表，无害；但若在 `const` 成员函数里这么写会编译失败，需改 `find`。
7. **输出的是"活人全表"而非前 $k$ 位**：每次查询都是全量遍历，题目限定查询次数 $\le 10$，正是为了让 $O(n)$ 查询可行。
