# LeetCode 文件夹操作日志搜集器 题解

## 1. 题目概述

- **标题 / 题号**：文件夹操作日志搜集器（#1598，easy）
- **链接**：https://leetcode.cn/problems/crawler-log-folder/
- **来源**：LeetCode 第 208 场周赛 Q1
- **难度**：简单
- **标签**：栈、数组、字符串、模拟

**题意**：LeetCode 文件系统启动时位于主文件夹，每条日志 `logs[i]` 记录一次变更文件夹操作：`"../"` 移到父文件夹（已在主文件夹则原地停留）、`"./"` 原地停留、`"x/"` 进入题目保证存在的子文件夹 `x`。按顺序执行完所有操作后，求**返回主文件夹所需的最小步数**。

**约束**：

- `1 <= logs.length <= 10^3`
- `2 <= logs[i].length <= 10`
- `logs[i]` 仅含小写英文字母、数字、`'.'` 和 `'/'`
- 文件夹名称只由小写英文字母和数字组成

## 2. 示例

**示例 1**

```text
输入：logs = ["d1/","d2/","../","d21/","./"]
输出：2
解释：执行后位于 d1/d21，距主文件夹 2 层，需 2 次 "../" 返回。
```

**示例 2**

```text
输入：logs = ["d1/","d2/","./","d3/","../","d31/"]
输出：3
解释：执行后位于 d1/d2/d31，深度为 3。
```

**示例 3**

```text
输入：logs = ["d1/","../","../","../"]
输出：0
解释：第 2 条日志已回到主文件夹，后续多余的 "../" 原地停留，深度保持 0。
```

## 3. 解题思路

### 3.1 暴力思路

用**栈**真实模拟整个路径：`"x/"` 把文件夹名压栈，`"../"` 弹栈（栈空则不动），`"./"` 跳过，最后栈的大小即答案。

这个做法完全正确，$O(n)$ 也能轻松通过。但栈里存的名字**从头到尾没有被使用**——我们只关心"离主文件夹还有几层"，不关心路上经过哪些文件夹，栈是惯性思维带出的冗余结构。

### 3.2 核心观察：只需一个深度计数器

![深度计数器概念图](images/crawler_log_folder_depth_concept.svg)

"返回主文件夹的最小步数"**只取决于当前文件夹的深度**（嵌套层数），与路径上具体是哪些文件夹无关。于是栈可以退化成一个整数 `depth`：

| 日志 | 对 depth 的效果 | 说明 |
|------|----------------|------|
| `"../"` | `max(0, depth - 1)` | 已在主文件夹则原地停留 |
| `"./"` | 不变 | 原地等待 |
| `"x/"` | `depth + 1` | 题目保证子文件夹存在 |

扫完所有日志，**答案就是最终 `depth`**。

> 💡 **一句话套路**：当栈只被用来回答"还剩几层"、从不关心内容时，一个 `int` 计数器就能替代整个栈。

### 3.3 算法流程

1. 初始化 `depth = 0`（主文件夹）。
2. 逐条扫描日志，整串比较分类：
   - `log == "../"`：`depth = max(0, depth - 1)`；
   - `log == "./"`：跳过；
   - 其余必为 `"x/"` 形式：`depth += 1`。
3. 返回 `depth`。

### 3.4 示例演算

![示例 1 走查图](images/crawler_log_folder_walkthrough.svg)

以示例 1 `logs = ["d1/","d2/","../","d21/","./"]` 走查：

| 步骤 | 操作 | depth | 所在位置 |
|------|------|-------|----------|
| 初始 | — | 0 | 主文件夹 |
| 1 | `"d1/"` | 1 | d1 |
| 2 | `"d2/"` | 2 | d1/d2 |
| 3 | `"../"` | 1 | d1 |
| 4 | `"d21/"` | 2 | d1/d21 |
| 5 | `"./"` | 2 | d1/d21 |

最终 `depth = 2`，答案为 **2** ✓

## 4. 算法细节

1. **三类日志的判别**：文件夹名只含小写字母和数字，**不可能**叫 `.` 或 `..`，因此用整串 `==` 精确匹配 `"../"` 与 `"./"` 即可无歧义分类，剩下的必然是 `"x/"`。
2. **深度下界封顶**：`"../"` 在 `depth == 0` 时不能减成负数，必须 `max(0, depth - 1)`——这正对应"已在主文件夹则停留原地"的规则。
3. **无需校验子文件夹存在**：题目保证 `"x/"` 的目标存在，直接加 1 即可。
4. **计数器代替栈**：与"括号匹配只问最大深度"时用计数器替代栈是同一套路，把 $O(n)$ 空间压到 $O(1)$。

## 5. 正确性证明

**引理 1**：按规则维护的 `depth` 恒等于当前文件夹的真实深度（距主文件夹的层数）。

**证明**：对已执行的操作数归纳。初始时位于主文件夹，`depth = 0`，成立。设某时刻 `depth` 等于真实深度 $d$：执行 `"x/"` 后真实深度变为 $d+1$，规则同步加 1；执行 `"./"` 两者均不变；执行 `"../"` 时，若 $d \ge 1$ 真实深度变为 $d-1$，若 $d = 0$ 按题意原地不动，两种情形都与 $\max(0, d-1)$ 一致。归纳完成。∎

**引理 2**：从深度 $d$ 出发，返回主文件夹的最小操作步数为 $d$。

**证明**：上界：连续执行 $d$ 次 `"../"` 恰好回到主文件夹，步数 $\le d$。下界：任何一条操作使深度至多减少 1（`"../"` 恰减 1，`"./"` 与 `"x/"` 不减），深度从 $d$ 降到 0 至少需要 $d$ 条操作，步数 $\ge d$。两界相等，最小步数为 $d$。∎

**定理**：算法的返回值等于返回主文件夹所需的最小步数。

**证明**：由引理 1，扫描结束时的 `depth` 即当前文件夹的真实深度；由引理 2，该深度正是所求最小步数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(nL)$，其中 $n \le 10^3$ 为日志条数，$L \le 10$ 为单条日志长度，即线性于输入总大小；每条日志只做一次字符串比较与常数次整数运算。
- **空间复杂度**：$O(1)$，仅一个整数计数器（栈模拟则需要 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<string>& logs) {
        int depth = 0;
        for (const string& log : logs) {
            if (log == "../") depth = max(depth - 1, 0);
            else if (log == "./") continue;
            else ++depth;
        }
        return depth;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, logs: List[str]) -> int:
        depth = 0
        for log in logs:
            if log == "../":
                depth = max(depth - 1, 0)
            elif log == "./":
                continue
            else:
                depth += 1
        return depth
```

## 8. 边界情况与易错点

1. **主文件夹处的 `"../"`**：必须 `max(0, depth - 1)`；若直接 `depth - 1` 减成负数，后续 `"x/"` 会把答案算小（示例 3 覆盖此点）。
2. **`"./"` 与 `"../"` 的区分**：二者都以 `'.'` 开头，只看首字符会混淆，务必整串比较。
3. **文件夹名含数字**：`"d1/"`、`"d31/"` 都是合法的深入操作，不能用"仅字母"的方式判断名字。
4. **多余 `"../"` 不报错**：在主文件夹连按 `"../"` 只是原地停留，不是非法操作。
5. **数值范围**：$n \le 10^3$，`depth` 上界 $10^3$，`int` 无溢出风险。
