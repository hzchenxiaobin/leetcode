# LeetCode 单词方块 题解

## 1. 题目概述

- **标题 / 题号**：单词方块（#425，hard）
- **链接**：https://leetcode.cn/problems/word-squares/
- **来源**：LeetCode 第 9 场周赛 Q4
- **难度**：困难
- **标签**：字典树、数组、字符串、回溯

**题意**：给定 $n$ 个**互不相同**、长度**全部相同**的单词（长度为 $L$），用它们拼出所有「单词方块」：一个由 $L$ 个单词构成的方阵，要求对每个 $k \in [0, L)$，第 $k$ **行**与第 $k$ **列**是同一个字符串。返回全部方块，方块的顺序任意，但方块内单词的**顺序有意义**。

两个容易忽略的细节：单词可以在同一个方块里**重复使用**（示例 2 的 `baba` 就出现了两次），而输出列表里不会出现两个相同的方块。

**约束**：

- $1 \le n \le 1000$，单词互不相同
- 所有单词长度相同，且 $1 \le L \le 5$
- 单词仅含小写英文字母 `a`–`z`

## 2. 示例

**示例 1**

```text
输入：["area","lead","wall","lady","ball"]
输出：[["wall","area","lead","lady"],
      ["ball","area","lead","lady"]]
解释：四个单词都是 4 字母。以 ["wall","area","lead","lady"] 为例：
      w a l l       第 0 行 wall = 第 0 列 w,a,l,l
      a r e a       第 1 行 area = 第 1 列 a,r,e,a
      l e a d       第 2 行 lead = 第 2 列 l,e,a,d
      l a d y       第 3 行 lady = 第 3 列 l,a,d,y
```

**示例 2**

```text
输入：["abat","baba","atan","atal"]
输出：[["baba","abat","baba","atan"],
      ["baba","abat","baba","atal"]]
解释：baba 在同一个方块里被用了两次 → 单词可重复使用。
      两个答案只在最后一格（第 3 行第 3 列）不同：n 与 l。
```

**示例 3（补充边界）**

```text
输入：["a"]
输出：[["a"]]
解释：L = 1 的退化情况，一个单词本身就是一个方块。
```

## 3. 解题思路

### 3.1 暴力思路

方阵有 $L$ 行，每行从 $n$ 个单词里挑一个，共 $n^L$ 种组合，每种花 $O(L^2)$ 校验行列相等：总复杂度 $O(n^L L^2)$。$n = 1000, L = 5$ 时是 $10^{15}$ 量级，完全不可行。

即便暴力，也能看出浪费：校验是在**整个方阵填完之后**才做的，而实际上**第 1 行选定的瞬间**，第 1 列的第一个字符就已经确定，后续行的首个字符随之被锁死。把这份约束提前，就是本题的核心。

### 3.2 核心观察：按列定向，第 $k$ 行只由第 $k$ 列前 $k$ 个字符决定

![前缀索引：把逐字符校验压成一次查表](images/wc9_q4_prefix_index.svg)

假设前 $k$ 行 `sq[0..k)` 已经填好，下标从 $0$ 开始。现在要挑第 $k$ 行的单词 $w$。合法性要求「第 $k$ 行 = 第 $k$ 列」，于是

$$\forall\, j \in [0, k):\quad w[j] = \text{sq}[j][k]$$

右边完全由已填内容决定，所以 $w$ 的**前 $k$ 个字符被唯一确定**：

$$\text{need}_k = \text{sq}[0][k] + \text{sq}[1][k] + \cdots + \text{sq}[k-1][k]$$

$w$ 必须是**以 `need` 为前缀**的单词。把「每个单词的每个前缀」预先登记到哈希表或字典树里，

$$\text{pref}[p] = \{\, w \in \text{words} : w \text{ 的前 } |p| \text{ 个字符等于 } p \,\}$$

第 $k$ 步的候选集就直接是 $\text{pref}[\text{need}_k]$，一次查表即可，$k = 0$ 时 `need` 为空串，候选为全部单词。

### 3.3 算法流程

![回溯流程：按列为每一行挑候选](images/wc9_q4_backtrack_flow.svg)

1. 建索引：对每个单词 $w$ 的每个前缀长度 $k \in [0, L]$，把 $w$ 追加到 $\text{pref}[w[0..k)]$。空前缀 `""` 也要登记（否则 $k=0$ 与 $L=1$ 都会没候选）。
2. 从 `dfs(0)` 开始，用一个长度为 $L$ 的数组 `sq` 记录已选的行。
3. `dfs(k)`：若 $k = L$，把 `sq` 的**深拷贝**加入答案并返回。
4. 否则按上式拼出 `need`，遍历 $\text{pref}[\text{need}]$ 中的每个单词：压入 `sq` → 递归 `dfs(k+1)` → 弹出（回溯）。
5. 候选为空自然什么都不做，等价于「该分支判死，立即回溯」。

**为什么不会漏解**：任何合法方块的第 $k$ 行必然以 $\text{need}_k$ 开头（$k=0$ 时前缀为空串，任何单词都满足），所以它一定在候选集里；DFS 每层把所有候选都试一遍，因此所有合法方块都被走到。

**为什么不需要 `used` 数组**：题面只说输入单词互不相同，并没有说方块里的单词不能重复——示例 2 直接证明了可以重复。加了 `used` 反而会漏解。

### 3.4 示例演算

![演算：首行 wall 后前缀被逐列锁死](images/wc9_q4_walkthrough.svg)

以 `words = [area, lead, wall, lady, ball]`、首行取 `wall` 为例：

| 步骤 $k$ | 已填 `sq` | `need` | 候选 $\text{pref}[\text{need}]$ |
|-----------|------------|--------|----------------------------------|
| 0 | （空） | `""` | area, lead, wall, lady, ball |
| 1 | wall | `sq[0][1]` = `"a"` | area |
| 2 | wall, area | `"l"+"e"` = `"le"` | lead |
| 3 | wall, area, lead | `"l"+"a"+"d"` = `"lad"` | lady |
| 4 | wall, area, lead, lady | — | 填满 4 行，输出 |

表格中 `sq[0][1]` 表示已填的首行（`wall`）第 $1$ 个字符 `a`，它正好是第 $1$ 列自上而下的第一个字符。

首行换成 `ball` 后，$k=1$ 仍是 `"a"`、$k=2$ 是 `"l"+"e"` = `"le"`、$k=3$ 是 `"lad"`，三条 need 与 `wall` 分支完全重合，于是得到第二个方块——这正是示例 1 只有两个答案、且它们只差首行的原因。

## 4. 算法细节

1. **空前缀必须登记**：循环写成 `k` 从 `0` 到 `L`（含两端）。若从 `1` 开始，$k=0$ 时 `pref[""]` 不存在 → 第一个候选就为空 → 直接返回空答案，$L=1$ 时同样全军覆没。
2. **索引结构二选一**：哈希表 `unordered_map<string, vector<int>>` / `dict` 写法最短；字典树（Trie）把建表从 $O(nL^2)$ 降到 $O(nL)$ 且不必存重复前缀，$L \le 5$ 时两者都够用，本文给哈希表版。
3. **`need` 的构造顺序**：`need[j] = sq[j][k]`，$j$ 从 $0$ 到 $k-1$，即「自上而下取第 $k$ 列」。写错成 `sq[k][j]` 就变成了「第 $k$ 行已填字符」，与题意的行列对称关系对不上。
4. **输出要深拷贝**：`res.append(sq[:])` / `res.push_back(sq)`。回溯过程中 `sq` 被反复压栈弹栈，直接存引用会让答案全变成空数组或最后一个状态。
5. **候选表只存下标（C++）**：`unordered_map<string, vector<int>>` 比存 `vector<string>` 省一次字符串拷贝，回溯时用 `words[idx]` 取词；Python 里字符串不可变，直接存单词即可。
6. **剪枝本身就是复杂度来源**：每层枚举的候选数等于「该前缀下的单词数」，而非 $n$。字母表越大、单词越随机，候选越少；反过来说，答案数量会爆炸（例如 $\{a,b\}$ 上全部 32 个 5 字母单词，实测可产出 32768 个方块），所以复杂度必须按**输出规模**来算。
7. **不要给结果去重/排序**：不同下标的序列必然给出不同的字符串序列（单词互不相同），DFS 不会重复产出；排序输出只会白花时间。

## 5. 正确性证明

**引理 1（第 $k$ 行的必要条件）**：设方块 $S = (s_0, \dots, s_{L-1})$ 合法，则对任意 $k$，$s_k$ 的前 $k$ 个字符等于 $\text{need}_k = s_0[k] s_1[k] \cdots s_{k-1}[k]$。

**证明**：合法性要求第 $k$ 行等于第 $k$ 列，即 $s_k[j] = s_j[k]$ 对一切 $j$ 成立。取 $j < k$，得 $s_k[j] = s_j[k]$，逐位拼接即 $s_k[0..k) = \text{need}_k$。∎

**引理 2（完备性）**：设 `sq` 是某个合法方块的长度为 $k$ 的前缀（即 `sq[j] = s_j`，$j < k$），则 $\text{pref}[\text{need}_k]$ 含有 $s_k$。

**证明**：由引理 1，$s_k$ 以 $\text{need}_k$ 开头；而建表时把每个单词的每个前缀都登记进了 `pref`，故 $s_k \in \text{pref}[\text{need}_k]$。∎

**引理 3（部分解可扩展）**：DFS 到达深度 $k$ 时，`sq` 恰好是一个满足「前 $k$ 行各自与对应列在前 $k$ 位上相等」的部分解，即 $s_i[j] = s_j[i]$ 对一切 $i, j < k$ 成立。

**证明**：对 $k$ 归纳。$k=0$ 时为空，成立。若 $k$ 时成立，DFS 在第 $k$ 步只会从 $\text{pref}[\text{need}_k]$ 中挑 $w$，故 $w[j] = \text{need}_k[j] = s_j[k]$ 对 $j < k$ 成立，新加入的第 $k$ 行与所有已存在的列位一致；原有的 $i,j < k$ 的对称性未被破坏。∎

**定理**：算法输出的集合恰好等于全部合法单词方块。

**证明**：

- **可靠性（不漏错误答案）**：由引理 3，DFS 在 $k=L$ 输出时，对一切 $i, j \in [0, L)$ 有 $s_i[j] = s_j[i]$。于是第 $i$ 行 $s_i = s_i[0] s_i[1] \cdots s_i[L-1]$，第 $i$ 列 $= s_0[i] s_1[i] \cdots s_{L-1}[i]$，逐位相同，故 $S$ 合法。
- **完备性（不漏正确答案）**：设 $S$ 合法，对 $k$ 归纳证明 DFS 能走到 `sq = s_0..s_{k-1}` 的状态。$k=0$ 时 `need = ""`，候选为全部单词（含 $s_0$）。若已走到 $k$，由引理 2 有 $s_k \in \text{pref}[\text{need}_k]$，DFS 会枚举到它并递归到 $k+1$。故 $k=L$ 时该方块被输出。
- **无重复**：输入单词互不相同，DFS 的每个输出对应唯一的下标序列，而不同下标序列在某个位置取到不同字符串，故输出两两不同。∎

## 6. 复杂度分析

- **建索引时间**：$O(nL^2)$。共 $n(L+1)$ 条「前缀 → 单词」记录，每条键长度 $\le L$，切片/取子串是 $O(L)$；$L \le 5$ 时为常数，可视为 $O(n)$。
- **搜索时间**：设答案数为 $A$。每个 DFS 结点花 $O(L)$ 拼 `need`、$O(L)$ 做哈希查找；结点总数与「部分解 + 死分支」成正比，约为 $O(LA)$，故总时间 $O(L^2 A)$，即**输出敏感的线性时间**。注意 $A$ 本身可能指数级（$\{a,b\}$ 上 32 个 5 字母单词可产出 32768 个方块），题目通过限制输出总规模保证可过。
- **空间**：索引 $O(nL^2)$ 个字符（哈希表键的最坏总长）；递归栈深 $L$，`sq` 占 $O(L)$ 个引用；输出 $O(L^2 A)$ 个字符，属于答案本身的开销。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
#include <functional>
using namespace std;

class Solution {
public:
    vector<vector<string>> wordSquares(vector<string>& words) {
        int n = words.size(), L = words[0].size();
        unordered_map<string, vector<int>> pref;      // 前缀 -> 单词下标（"" 匹配全部）
        pref.reserve((size_t)n * (L + 1) * 2 + 16);
        for (int i = 0; i < n; i++)
            for (int k = 0; k <= L; k++)              // k 从 0 开始：空前缀也要登记
                pref[words[i].substr(0, k)].push_back(i);

        vector<vector<string>> res;
        vector<string> sq;
        function<void(int)> dfs = [&](int k) {
            if (k == L) { res.push_back(sq); return; }  // 深拷贝当前方块
            string need;
            for (int j = 0; j < k; j++) need.push_back(sq[j][k]);  // 第 k 列前 k 个字符
            auto it = pref.find(need);
            if (it == pref.end()) return;               // 无候选：剪枝回溯
            for (int idx : it->second) {
                sq.push_back(words[idx]);
                dfs(k + 1);
                sq.pop_back();                          // 回溯
            }
        };
        dfs(0);
        return res;
    }
};
```

### Python

```python
from typing import List
from collections import defaultdict


class Solution:
    def wordSquares(self, words: List[str]) -> List[List[str]]:
        L = len(words[0])
        pref = defaultdict(list)          # 前缀 -> 以它开头的所有单词（"" 匹配全部）
        for w in words:
            for k in range(L + 1):        # k 从 0 开始：空前缀也要登记
                pref[w[:k]].append(w)

        res, sq = [], []

        def dfs(k: int) -> None:
            if k == L:
                res.append(sq[:])         # 深拷贝
                return
            need = ''.join(sq[j][k] for j in range(k))   # 第 k 列已确定的前 k 个字符
            for w in pref.get(need, ()):
                sq.append(w)
                dfs(k + 1)
                sq.pop()                  # 回溯

        dfs(0)
        return res
```

## 8. 边界情况与易错点

1. **$L = 1$**：`["a"]` → `[["a"]]`。若索引没有登记空串前缀，$k=0$ 时候选集为空，会错误返回 `[]`；这是最容易踩的坑。
2. **单词可重复使用**：示例 2 的 `baba` 用了两次。不要照搬「单词搜索」那类题的 `used` 数组，否则答案变少甚至为空。
3. **输出必须深拷贝**：C++ 的 `res.push_back(sq)` 是按值拷贝没问题，但若写成 `res.push_back(move(sq))` 或存指针，回溯后内容全被清空；Python 必须写 `sq[:]`。
4. **单个单词无法构成方块（$L > 1$）**：如 `["ab"]`，$k=1$ 时 `need = "b"` 无候选 → 返回 `[]`，不能因为「只有一个单词」就默认它成方块。
5. **前缀长度**：`need` 的长度恰为 $k \le L$，所以索引里前缀最长也就 $L$；不要把 `need` 截断到 $L-1$，否则最后一行永远匹配不上。
6. **分隔符/大小写**：题面保证全小写，不需要额外归一化；若扩展到大写或数字，只要索引与 `need` 用同一字符集即可，无需改结构。
7. **不用担心重复输出**：单词互不相同 ⇒ 每个下标序列产生的字符串序列唯一；若输入允许重复单词（比如 `["aa","aa"]`），才需要额外去重或按下标去重。

**延伸思考**：

- **不可重复使用单词**：只需在 DFS 中额外维护 `used` 集合（或下标位掩码，$n$ 小时），并在建索引时跳过已用单词——索引查询后要再过滤一次，代价是每层多 $O(\text{cand})$ 的检查。
- **只要任意一个答案**：DFS 找到一个即可 `return true` 逐层短路，最坏仍是指数级，但平均快很多；配合「按候选数量升序填行」的启发式更稳。
- **计数 / 去重（旋转、镜像视作同一个）**：计数就是把 `res` 换成计数器；去重需要把方块规范化（取 4 个旋转方向里字典序最小者作代表）再放进 `set`。
- **$L$ 更大时**（如 8–10）：$O(nL^2)$ 的哈希表索引开始吃内存，应改用字典树 + 逐层下探（把「当前在树上的结点」随递归传下去，$k$ 增加时沿子结点走一步），单步从 $O(L)$ 降到 $O(1)$，总时间降到 $O(L A)$。
