# LeetCode 替换后的最长重复字符 题解

## 1. 题目概述

- **标题 / 题号**：替换后的最长重复字符（#424，medium）
- **链接**：https://leetcode.cn/problems/longest-repeating-character-replacement/
- **来源**：LeetCode 第 9 场周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、滑动窗口

**题意**：给定只含大写字母的字符串 `s` 和整数 `k`，你可以任选字符串中的至多 `k` 个位置，把它们改成任意其他大写字母。问操作之后，**所有字符都相同**的连续子串最长能有多长。

只有落在子串内部的改写才有意义（改子串外的字符不影响该子串），所以问题等价于：**找一个最长的窗口，窗口内「非众数字符」的个数不超过 $k$**。

**约束**：

- $1 \le n = \lvert s \rvert \le 10^5$
- `s` 仅由大写英文字母组成
- $0 \le k \le n$

> 💡 字母表固定为 26 个大写字母，这决定了「统计窗口内频次」只需要 26 个桶，也是双指针能保持 $O(1)$ 空间的原因。

## 2. 示例

**示例 1**

```text
输入：s = "ABAB", k = 2
输出：4
解释：把两个 'A' 改成 'B'（或把两个 'B' 改成 'A'），得到 "BBBB"，
      整串长度 4；不可能超过 4。
```

**示例 2**

```text
输入：s = "AABABBA", k = 1
输出：4
解释：把中间的一个 'A' 改成 'B'，得到 "AABBBBA"，其中子串 "BBBB" 长度为 4。
      窗口 [2,5] = "BABB"：3 个 B + 1 个 A，只需改写 1 个字符。
```

**示例 3**（补充自测，非官方）

```text
输入：s = "ABCD", k = 1
输出：2
解释：任意相邻两个字符都能改成一个字母（如 "AB" → "AA"），但长度 3 需要改 2 个字符，超过 k。
      特例：k = 0 时答案退化为「最长的一段连续相同字符」，如 "AAAA" → 4。
```

## 3. 解题思路

### 3.1 暴力思路

枚举左右端点得到 $O(n^2)$ 个窗口，对每个窗口统计 26 个字母的出现次数、求最大值，判定 $L - \max \le k$：

- 复杂度 $O(26n^2) \approx 2.6 \times 10^{11}$（$n = 10^5$），远超时限；
- 即使改用前缀和把「统计频次」降到 $O(26)$ 每次，$O(n^2)$ 本身仍有 $10^{10}$ 量级，依然不可行。

暴力之所以浪费，是因为它重新计算了大量互相重叠的窗口。关键是要找出**窗口移动时可行性如何变化**。

### 3.2 核心观察：窗口代价 = 长度 − 众数频次

![窗口可行性判定：len − maxfreq ≤ k](images/wc9_q3_window_model.svg)

设窗口为 $[l, r]$，长度 $L = r - l + 1$，窗口内出现次数最多的字母出现了 $M$ 次（$M$ 即 maxfreq）。则把这个窗口变成「全同字符」所需的**最少**操作次数是

$$\text{cost}(l,r) = L - M$$

- **上界（贪心可行）**：把出现最多的字母 $x$ 定为目标，其余 $L - M$ 个字符逐个改成 $x$，操作 $L - M$ 次即可；
- **下界（不可能更少）**：任何方案最终都会让某个字母 $y$ 填满窗口。设 $y$ 原来出现 $c_y$ 次，则至少要把另外 $L - c_y$ 个位置改掉；由于 $c_y \le M$，有 $L - c_y \ge L - M$。

> 💡 一句话：**目标字母取窗口内的众数，代价最小**，所以判定条件就是

$$[l,r]\ \text{可行} \iff L - M \le k$$

这也是本题唯一需要的观察——它把一个「枚举改哪几个字符」的组合问题，压缩成了一次算术比较。

### 3.3 算法流程：双指针（滑动窗口）

![滑动窗口流程：右指针扩张、左指针收缩](images/wc9_q3_two_pointer_flow.svg)

既然可行性只依赖 $L - M$，就可以用一个窗口在字符串上滑动：

1. 右指针 $r$ 从 $0$ 扫到 $n-1$，把 $s[r]$ 纳入窗口，`cnt[s[r] - 'A'] += 1`；
2. 若当前窗口 $L - M > k$，说明窗口太长，**左指针连续右移**（每移一格就把该字符从计数里减掉），直到窗口重新可行；
3. 用收缩后的窗口长度更新答案：`ans = max(ans, r - l + 1)`；
4. 扫描结束返回 `ans`。

左指针**不需要回退**，因为「可行性对左端点单调」：固定右端点 $r$，若 $[l,r]$ 不可行，那么更长的 $[l-1,r]$ 也不可行。这条单调性由 §5 的引理 2 给出，它是双指针成立的全部依据。

### 3.4 示例演算

![示例 "AABABBA"、k = 1 的逐行演算](images/wc9_q3_walkthrough.svg)

以 $s = \texttt{"AABABBA"}$、$k = 1$ 为例，逐行状态如下：

| $r$ | $s[r]$ | 窗口 $[l,r]$ | len | maxf | len−maxf | 动作 |
|-----|--------|--------------|-----|------|----------|------|
| 0 | A | $[0,0]$ "A" | 1 | 1 | 0 | 可行，ans=1 |
| 1 | A | $[0,1]$ "AA" | 2 | 2 | 0 | 可行，ans=2 |
| 2 | B | $[0,2]$ "AAB" | 3 | 2 | 1 | 可行，ans=3 |
| 3 | A | $[0,3]$ "AABA" | 4 | 3 | 1 | 可行，ans=4 |
| 4 | B | $[0,4]$ "AABAB" | 5 | 3 | 2 | 超标，连缩到 $l=2$，窗口 "BAB" |
| 5 | B | $[2,5]$ "BABB" | 4 | 3 | 1 | 可行，ans=4 |
| 6 | A | $[2,6]$ "BABBA" | 5 | 3 | 2 | 超标，连缩到 $l=4$，窗口 "BBA" |

注意 $r = 4$ 这一行：加入 `'B'` 后差值为 2，弹掉 $s[0]$ 后窗口 $[1,4] = \texttt{"ABAB"}$ 的 maxf 从 3 掉到 2，差值仍是 2，**必须再弹一次**。这正说明收缩要用 `while` 而不是 `if`。

最终答案 4，来自 $r = 5$ 时的窗口 $[2,5] = \texttt{"BABB"}$：把其中唯一的 `'A'` 改成 `'B'` 即得 `"BBBB"`。

## 4. 算法细节

1. **字符桶**：用长度 26 的数组 `cnt`，下标取 `c = s[i] - 'A'`（Python `ord(ch) - 65`）。字母表大小固定，因此空间是常数。
2. **`maxf` 必须是「当前窗口的真实最大频次」**：每次判定都重新求 `max(cnt)`。若为了省常数把它缓存成历史最大值，$L - M$ 会被低估，收缩提前停止，窗口不再保证可行。
3. **收缩用 `while`**：一次扩张可能触发多次收缩（见上表 $r=4$）。收缩一格时长度减 1、maxfreq 减 0 或 1，所以差值每轮只减 0 或 1，需要循环直到满足条件。
4. **答案更新位置**：必须在 `while` 结束之后。若在收缩前更新，会把不可行的窗口计入答案（如 `"AABABBA"` 的 $r=4$ 会错误地得到 5）。
5. **收缩的终止性**：$l$ 最多推进到 $r$（窗口只剩 1 个字符，$L - M = 0 \le k$ 必然成立），因此 `while` 不会越界，`l` 永不超过 `r`。
6. **常数与剪枝**：`max(cnt)` 每次 26 次比较，总开销约 $26 \times 2n$；当 $k \ge n-1$ 时整串都能改成一个字母，可直接返回 $n$，算法本身也能得到同样结果，提前返回只是剪枝。
7. **不必枚举目标字母**：因为目标一定取众数（引理 1 的下界部分），所以不需要「对 26 个候选字母各跑一次双指针」。
8. **语言细节**：C++ 的 `max_element` 返回迭代器要解引用；Python 的 `max(cnt)` 在 C 层循环，$n = 10^5$ 实测约 0.1 s，无需手写循环。

## 5. 正确性证明

**引理 1（代价公式）**：窗口 $[l,r]$ 能通过至多 $k$ 次改写变成全同字符，当且仅当 $L - M \le k$，其中 $L = r-l+1$，$M$ 是窗口内的最大频次。

**证明**：

- ($\Leftarrow$) 取窗口内出现最多的字母 $x$（出现 $M$ 次），把其余 $L-M$ 个位置全改成 $x$。由 $L-M \le k$，操作次数合法，且改完后窗口全为 $x$，可行。
- ($\Rightarrow$) 设存在一种不超过 $k$ 次的改写，使窗口全为字母 $y$。原窗口中 $y$ 出现 $c_y$ 次，凡不是 $y$ 的位置都必须被改写，故改写次数 $t \ge L - c_y$。又 $c_y \le M$，于是 $L - M \le L - c_y \le t \le k$。∎

**引理 2（可行性对左端点单调）**：固定 $r$，若 $[l,r]$ 不可行，则对任意 $l' < l$，$[l',r]$ 也不可行。

**证明**：记 $D(l) = (r-l+1) - \text{maxfreq}(l)$。从 $[l,r]$ 扩张到 $[l-1,r]$ 只多了一个字符 $s[l-1]$：长度 $+1$，而某个字母的计数 $+1$，故 maxfreq 至多 $+1$，于是 $D(l-1) \ge D(l) > k$。由引理 1，$[l-1,r]$ 不可行；再对 $l' < l-1$ 反复使用同一论证即得。∎

**引理 3（循环结束时左指针最优）**：对每个固定的 $r$，`while` 结束时 $l$ 恰好是以 $r$ 结尾的最长可行窗口的左端点 $l^{*}_r$。

**证明**：收缩一格时长度 $-1$，maxfreq 减 $0$ 或 $1$，因此 $D$ 变为 $D-1$ 或 $D$，单调不增，循环必然终止（最晚 $l = r$ 时窗口只剩一个字符，$D = 0 \le k$）。终止时 $[l,r]$ 可行（引理 1 的 $\Leftarrow$ 方向），而由引理 2，任何更小的左端都不可行，故 $l = l^{*}_r$。∎

**定理**：算法返回最优答案 $\mathrm{OPT}$。

**证明**：由引理 3，每一轮 `while` 结束后窗口就是「以 $r$ 结尾的最长可行窗口」，故算法输出 $\text{ans} = \max_{0 \le r < n} \left( r - l^{*}_r + 1 \right)$。

- $\text{ans} \le \mathrm{OPT}$：每个 $r - l^{*}_r + 1$ 都对应一个真实可行窗口（引理 1 的 $\Leftarrow$），其长度不可能超过最优值。
- $\text{ans} \ge \mathrm{OPT}$：设最优窗口为 $[i,j]$，长度 $\mathrm{OPT}$。固定右端 $j$ 时 $[i,j]$ 可行，由 $l^{*}_j$ 的最长性得 $l^{*}_j \le i$，于是 $\text{ans} \ge j - l^{*}_j + 1 \ge j - i + 1 = \mathrm{OPT}$。

两边夹得 $\text{ans} = \mathrm{OPT}$。∎

## 6. 复杂度分析

- **时间**：$O(26n)$，即 $O(n)$。右指针走 $n$ 步；左指针总共只前进不超过 $n$ 步，故 `while` 全体轮数 $O(n)$；每轮判定 `max(cnt)` 扫描 26 个桶，总比较次数约 $26 \cdot 2n$，是线性量级。
- **空间**：$O(1)$。只有 26 个计数桶、左右指针与答案变量，与 $n$ 无关（严格写作 $O(\lvert \Sigma \rvert) = O(26)$）。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
using namespace std;

class Solution {
public:
    int characterReplacement(string s, int k) {
        int cnt[26] = {0};
        int n = (int)s.size();
        int l = 0, ans = 0;
        for (int r = 0; r < n; ++r) {
            ++cnt[s[r] - 'A'];
            // 窗口内需要改写的字符数 = 长度 - 众数频次
            while ((r - l + 1) - *max_element(cnt, cnt + 26) > k) {
                --cnt[s[l] - 'A'];
                ++l;
            }
            ans = max(ans, r - l + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        cnt = [0] * 26
        l = 0
        ans = 0
        for r, ch in enumerate(s):
            cnt[ord(ch) - 65] += 1
            # 超出 k 次改写能力：左指针连续右移，直到窗口可行
            while (r - l + 1) - max(cnt) > k:
                cnt[ord(s[l]) - 65] -= 1
                l += 1
            ans = max(ans, r - l + 1)
        return ans
```

## 8. 边界情况与易错点

1. **$k \ge n-1$**：整串都能改成一个字母，答案 $n$。算法同样正确，因为 $L - M \le n - 1 \le k$ 恒成立，窗口一路扩张到结尾。
2. **$k = 0$**：退化为「最长的一段连续相同字符」。此时 `while` 的条件变成「窗口内必须全同」，弹字符的动作等价于跳过不匹配的位置。
3. **$n = 1$**：返回 1。`l` 最多推进到 `r`，`s[l]` 的访问不会越界。
4. **收缩必须用 `while`**：一次扩张可能需要收缩多次（$r=4$ 的 `"AABABBA"` 连弹两次）。改成 `if` 是流传很广的写法（通常配合「历史最大频次」），它也能得到正确答案，但窗口本身可能不可行，正确性论证需要额外引理；本文统一用 `while`，窗口始终真实可行。
5. **不要把 maxfreq 缓存成历史最大值**：$L - M$ 被低估会让收缩过早停止，与 `if` 混用时尤其容易写出「窗口不可行但被计入答案」的代码。
6. **答案更新必须在收缩之后**：在收缩前更新会把「刚变长但已不可行」的窗口计入答案，例如 `"AABABBA"`、$k=1$ 时会错误地得到 5。
7. **下标换算**：大写字母用 `s[i] - 'A'` / `ord(ch) - 65`；写成 `- 'a'` 或 `- 96` 会越界或错乱（那是小写字母的偏移）。
8. **`max_element` 的返回值**：C++ 中返回的是迭代器，必须写成 `*max_element(cnt, cnt + 26)`，漏掉解引用是编译错误。
