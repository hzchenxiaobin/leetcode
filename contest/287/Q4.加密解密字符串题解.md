# LeetCode 加密解密字符串 题解

## 1. 题目概述

- **标题 / 题号**：加密解密字符串（#2227，hard）
- **链接**：https://leetcode.cn/problems/encrypt-and-decrypt-strings/
- **来源**：LeetCode 第 287 场周赛 Q4
- **难度**：困难
- **标签**：设计、哈希表、Trie、字符串

**题意**：给定互不相同字符数组 `keys`、等长的字符串数组 `values`（每个 `values[i]` 长度恰为 2）与字符串数组 `dictionary`（允许的原串集合）。实现 `Encrypter` 类：

- **加密 `encrypt(word1)`**：对 `word1` 每个字符 `c`，找到 `keys[i] == c` 的下标 `i`，用 `values[i]` 替换 `c`；若 `c` 不在 `keys` 中，返回空串 `""`。
- **解密 `decrypt(word2)`**：把 `word2` 按相邻 2 字符分段，每段 `s` 可还原为**任意**满足 `values[i] == s` 的 `keys[i]`——一段可能有多个候选，故解密结果不唯一。统计「能由 `word2` 解密得到且出现在 `dictionary` 中」的字符串数目。

**约束**：

- $1 \le \text{keys.length} = \text{values.length} \le 26$，`keys` 内字符互不相同；`values[i]` 长度恒为 2，**允许重复**
- $1 \le \text{dictionary.length} \le 100$，$1 \le \text{dictionary[i].length} \le 100$
- $1 \le \text{word1.length} \le 2000$；$1 \le \text{word2.length} \le 200$ 且为偶数
- `word1` 的字符都在 `keys` 中；`encrypt` 与 `decrypt` 合计至多调用 200 次

> 💡 本题在本仓库另有[每日题解 2227](../../solution/2201-2300/2227_加密解密字符串.md)：同样以「反向加密字典建计数表」为主线，附面试问答与变体讨论。本篇按**周赛复盘视角**展开：补齐「$w$ 能由 `word2` 解密 $\iff$ `encrypt(w) = word2`」这一等价翻转的引理-定理化证明，完整复盘官方标签中的 **Trie DFS** 变体（赛场上没看出翻转观察时的救命写法），并整理边界与易错清单，两篇互为印证。

## 2. 示例

**示例 1（官方）**

```text
输入：
["Encrypter", "encrypt", "decrypt"]
[[['a', 'b', 'c', 'd'], ["ei", "zf", "ei", "am"],
   ["abcd", "acbd", "adbc", "badc", "dacb", "cadb", "cbda", "abad"]],
  ["abcd"], ["eizfeiam"]]
输出：[null, "eizfeiam", 2]

解释：
映射：'a'→"ei"，'b'→"zf"，'c'→"ei"，'d'→"am"
encrypt("abcd") = "ei"+"zf"+"ei"+"am" = "eizfeiam"
decrypt("eizfeiam") 拆成 "ei"/"zf"/"ei"/"am"
  "ei"→'a' 或 'c'，"zf"→'b'，"am"→'d'
  解密候选：abad / abcd / cbad / cbcd（共 4 个分支）
  其中 abad、abcd 在 dictionary 中 → 返回 2
```

```text
decrypt("eizf") → 2
解释："axy" 含 keys 外字符 'x'、'y'，无法加密（返回 ""），永不参与计数；
     "ei"→'a' 或 'c'，"zf"→'b'，候选 "ab"、"cb" 都在 dictionary 中 → 2。
```


## 3. 解题思路

### 3.1 暴力思路：正向解密 + 笛卡尔积

最直觉的写法是「老老实实按题意解密」：把 `word2` 按 2 字符切段，对每段找出**所有**满足 `values[i] == s` 的 `keys[i]`，做笛卡尔积枚举全部解密串，再逐一查 `dictionary` 计数。

死穴立刻暴露：

1. **指数分支**：`values` 允许重复，若每段有 $k$ 个候选字符，长度 $2m$ 的 `word2` 可还原出 $k^m$ 个串。$m \le 100$，即便 $k = 2$ 也有 $2^{100} \approx 1.3 \times 10^{30}$ 个组合，不可行；
2. **重复劳动**：多次 `decrypt` 各自重新枚举，互不复用；
3. **方向错误**：解密是「一对多」的**模糊**方向，加密是「一对一」的**确定**方向——沿模糊方向枚举，注定与指数级分支硬碰硬。

### 3.2 核心观察：加密是函数、解密是关系——把问题翻到确定的一侧

![核心观察：加密多对一、解密一对多的非双射映射](images/wc287_q4_mapping_concept.svg)

本题全部的「困难」都来自一个事实：**这不是双射**。

- `keys` 互不相同 → 每个明文字符有**唯一**下标 $i$ → 加密是**确定性函数**：给定 $w$，$\text{encrypt}(w)$ 唯一；
- `values` 可以重复 → 一个密文段可对应**多个** `keys[i]` → 解密是**一对多关系**：一段二选一，$m$ 段就是 $k^m$ 个分支。

于是把问题**整体翻转到确定的一侧**：

$$\text{decrypt}(word2) = \#\{\, w \in \text{dictionary} \mid \text{encrypt}(w) = word2 \,\}$$

**为什么翻转成立**？「`word2` 能解密出 $w$」与「$w$ 加密后等于 `word2`」是**同一事件的两个方向**——加密把 $w$ 唯一地压成 `word2`，解密把 `word2` 模糊地展开成候选集合，二者互为逆过程（严格证明见 §5）。原问题问的是「模糊展开的结果与 `dictionary` 的交集大小」，翻转后变成「对 `dictionary` 里每个**固定**的 $w$ 算一次确定的 `encrypt(w)`」——指数枚举被整体绕开。

> 💡 **方法论**：凡遇到「模糊展开 + 在已知集合中计数」的问题，先问一句「**能不能把已知集合预先正向变换，建成计数表**」。加密/编码/压缩还原皆适用——**确定性方向建表，模糊方向只查询**。

### 3.3 算法流程：构造时反向建表，查询 O(1) 命中

![算法流程：构造一次反向建表，查询直接命中](images/wc287_q4_counter_flow.svg)

**初始化**（构造函数，执行一次）：

1. 建 `keyToVal[26]`：字符 → 2 字符串（下标 `c - 'a'`，$O(1)$ 查询；空串作「不在 keys」的哨兵）；
2. 遍历 `dictionary`，对每个词 $w$ 调内部 `encrypt` 得 $e$；若 $e$ 非空，`cnt[e] += 1`。

**查询**：

- `encrypt(word1)`：逐字符查 `keyToVal` 拼接，$O(|word1|)$；
- `decrypt(word2)`：直接返回 `cnt[word2]`，不存在则 0，$O(1)$ 均摊。

### 3.4 赛场变体：Trie 存原词 + DFS 逐段下钻（不依赖翻转观察）

![Trie 变体：原词建 Trie，decrypt 逐段下钻与剪枝](images/wc287_q4_trie_dfs.svg)

官方标签里的 **Trie** 来自另一条思路——如果赛场上没看出 §3.2 的翻转，还能这样过：

1. 把 `dictionary` 的**原词**逐字符插入 Trie，词尾结点记 `cnt`（本例词互不相同，`cnt` 恒为 1）；
2. 预处理 `valToKeys`：把 `keys` 按 `value` 分组，得到每个 2 字符段的候选字符集（如 `"ei"→{a, c}`）；
3. `decrypt(word2)` 从根出发 DFS：处理到第 $j$ 段时，对候选集里**每个**字符 $c$，若当前结点有 $c$ 边则下钻；走完 $m$ 段后累加词尾 `cnt`。

它能过靠的是 **Trie 剪枝**：候选字符必须正好是「某个 dictionary 词在当前位置的字符」才继续走。每个 Trie 结点从根出发路径唯一，**每次 `decrypt` 至多访问每个结点一次**，单次复杂度 $O(26 \cdot V)$（$V$ 为结点数 $\le \sum|w| + 1 \le 10^4 + 1$），200 次调用约 $5 \times 10^7$ 次数组寻址，稳过。两条路线殊途同归——都能数出 $\{w \in \text{dictionary} : \text{encrypt}(w) = word2\}$（§5 推论）。

### 3.5 示例演算

![示例演算：8 个词各自加密建计数表，decrypt 一次命中](images/wc287_q4_counter_walkthrough.svg)

以官方示例展开，映射 `'a'→"ei"`、`'b'→"zf"`、`'c'→"ei"`、`'d'→"am"`。**预处理——逐词加密 `dictionary`**：

| dictionary 词 $w$ | 逐字符加密 | $\text{encrypt}(w)$ | `cnt` 累计 |
|------------------|-----------|--------------|-----------|
| `"abcd"` | ei/zf/ei/am | `eizfeiam` | `cnt[eizfeiam] = 1` |
| `"abad"` | ei/zf/ei/am | `eizfeiam` | `cnt[eizfeiam] = 2`（两词同密文） |
| `"acbd"` | ei/ei/zf/am | `eieizfam` | `cnt[eieizfam] = 1` |
| `"adbc"` | ei/am/zf/ei | `eiamzfei` | `cnt[eiamzfei] = 1` |
| `"badc"` | zf/ei/am/ei | `zfeiamei` | `cnt[zfeiamei] = 1` |
| `"dacb"` | am/ei/ei/zf | `ameieizf` | `cnt[ameieizf] = 1` |
| `"cadb"` | ei/ei/am/zf | `eieiamzf` | `cnt[eieiamzf] = 1` |
| `"cbda"` | ei/zf/am/ei | `eizfamei` | `cnt[eizfamei] = 1` |

**查询**：`encrypt("abcd") = "eizfeiam"` ✓；`decrypt("eizfeiam") = cnt["eizfeiam"] = 2` ✓。

> 💡 注意 `"abcd"` 与 `"abad"` 的密文**完全相同**——'a' 和 'c' 同映 `"ei"`，明文第 3 位是 'a' 还是 'c' 不影响密文。这正是「加密多对一」的体现：反向计数表天然把不同明文归并进同一桶，而正向解密却要为这一位付出 2 倍分支。

## 4. 算法细节

1. **映射表**：C++ 用 `string keyToVal[26]` 按下标 `c - 'a'` 索引，空串兼作「字符不在 keys」的哨兵——`encrypt` 遇空串立即返回 `""`，一套逻辑同时服务接口与预处理；Python 用 `dict.get(c)` 判缺失。
2. **预处理只做一次**：全部重活放在构造函数。`dictionary` 词含 keys 外字符时 `encrypt` 返回 `""`，用 `if (!e.empty())` 显式跳过最干净（`word2` 非空，`cnt[""]` 不会被查询命中，插入本也无害——但显式跳过可读性更好）。
3. **计数语义**：`cnt` 的值可大于 1——不同明文可加密成同一密文（示例中 2，理论上限 `dictionary.length = 100`），`int` 足够。
4. **Trie 版的候选分组**：`valToKeys` 必须在构造时按 `value` 分组预建；若在 DFS 里对每段现扫一遍 `values` 找候选，单次复杂度多乘 $O(26)$ 的常数且写法易错。
5. **字符串拼接**：`encrypt` 的 `word1` 长达 2000，Python 用片段列表 + `join`（避免 `+=` 的 $O(n^2)$）；C++ `reserve(2n)` 后 `+=` 即可。

## 5. 正确性证明

**引理 1（加密的确定性）**：`keys` 两两互不相同，故对每个字符 $c \in \text{keys}$，满足 $\text{keys}[i] = c$ 的下标 $i$ 唯一。于是对每个只含 `keys` 字符的串 $w$，$\text{encrypt}(w)$ 是唯一确定的、长 $2|w|$ 的串；若 $w$ 含 `keys` 外字符，则 $\text{encrypt}(w) = ``""$（题目定义）。

**证明**：下标唯一性由互不相同直接给出；逐字符替换的每一步输出唯一，拼接结果唯一。∎

**引理 2（解密结果的刻画）**：设 $|word2| = 2m$。串 $t$ 是 `word2` 的合法解密结果 $\iff$ $|t| = m$、$t$ 只含 `keys` 中字符，且 $\text{encrypt}(t) = word2$。

**证明**：

（$\Leftarrow$）设 $|t| = m$、$t \subseteq \text{keys}$ 且 $\text{encrypt}(t) = word2$。记 $c_j$ 为 $t$ 的第 $j$ 个字符、$i_j$ 为满足 $\text{keys}[i_j] = c_j$ 的唯一下标（引理 1）。由加密定义，`word2` 的第 $j$ 段等于 $\text{values}[i_j]$。于是「第 $j$ 段选取下标 $i_j$」是一个合法的解密选择，且其结果恰为 $t$——故 $t$ 是 `word2` 的解密结果。

（$\Rightarrow$）设按解密规则得到 $t$：对 `word2` 的第 $j$ 段存在下标 $i_j$ 使 $\text{values}[i_j]$ 等于该段，且 $t$ 的第 $j$ 个字符为 $\text{keys}[i_j]$。显然 $|t| = m$ 且 $t$ 只含 `keys` 字符。再算 $\text{encrypt}(t)$：$t$ 的第 $j$ 个字符 $c_j = \text{keys}[i_j]$，由 `keys` 互不相同，满足 $\text{keys}[i] = c_j$ 的唯一下标就是 $i_j$，故 $\text{encrypt}(t)$ 的第 $j$ 段 $= \text{values}[i_j] = $ `word2` 的第 $j$ 段，从而 $\text{encrypt}(t) = word2$。∎

**定理**：`decrypt(word2)` 的正确返回值为 $\#\{w \in \text{dictionary} : \text{encrypt}(w) = word2\}$，即 §3.3 预处理后 `cnt[word2]` 的值。

**证明**：`decrypt` 应返回 $|D(word2) \cap \text{dictionary}|$，其中 $D(word2)$ 是解密结果集合。由引理 2，

$$D(word2) = \{t : |t| = m,\ t \text{ 只含 keys 字符},\ \text{encrypt}(t) = word2\},$$

故 $|D(word2) \cap \text{dictionary}| = \#\{w \in \text{dictionary} : \text{encrypt}(w) = word2 \text{ 且 } w \text{ 只含 keys 字符}\}$。又 `word2` 非空，而含 `keys` 外字符的词加密为 `""` $\ne word2$，该附加条件可去掉；剩下的计数正是预处理中累入 `cnt[word2]` 的次数。∎

**推论（Trie-DFS 等价）**：§3.4 的 DFS 与计数表版返回相同结果。

**证明**：`dictionary` 中每个词 $w$ 对应 Trie 中从根出发的唯一路径。DFS 恰在「路径第 $j$ 个字符 $\in$ 第 $j$ 段候选集 $\{\text{keys}[i] : \text{values}[i] = \text{第} j \text{段}\}$」时下钻，而

$$c_j \in \text{候选集} \iff \text{values}[\text{keys}^{-1}(c_j)] = \text{第} j \text{段} \iff \text{encrypt}(w) \text{ 的第 } j \text{ 段} = \text{第} j \text{段},$$

故 $w$ 的路径被完整走完且词尾 $\text{cnt} > 0$ $\iff$ $\text{encrypt}(w) = word2$。每个 $w$ 仅经其唯一路径被计数一次，无重复、无遗漏。∎

## 6. 复杂度分析

- **时间**：初始化 $O\big(26 + \sum_{w} |w|\big)$，$\sum|w| \le 100 \times 100 = 10^4$；`encrypt` 每次 $O(|word1|) \le 2000$；`decrypt` 每次 $O(1)$ 均摊（严格界 $O(|word2|)$：哈希需读完整个键）。Trie 变体的 `decrypt` 为 $O(26 V)$，$V \le 10^4 + 1$。
- **空间**：计数表存各密文及计数，共 $O\big(\sum_w |w|\big)$ 字符（密文总长 $2\sum|w| \le 2 \times 10^4$）；`keyToVal` 为 $O(26)$ 常数；Trie 变体结点数 $\le \sum|w| + 1$。

> 💡 预处理把「每次 `decrypt` 枚举 $k^m$ 个组合」摊成「初始化一次 $O(10^4)$」，之后所有查询近乎免费——典型的**空间换时间 + 预处理摊还**。

## 7. 参考代码

### C++（哈希计数表，主推）

```cpp
class Encrypter {
  public:
    Encrypter(vector<char>& keys, vector<string>& values, vector<string>& dictionary) {
        keyToVal.assign(26, "");
        for (int i = 0; i < (int)keys.size(); ++i) {
            keyToVal[keys[i] - 'a'] = values[i];
        }
        for (const string& w : dictionary) {
            string e = encrypt(w);
            if (!e.empty()) cnt[e]++;
        }
    }

    string encrypt(const string& word1) {
        string res;
        res.reserve(word1.size() * 2);
        for (char c : word1) {
            const string& v = keyToVal[c - 'a'];
            if (v.empty()) return "";
            res += v;
        }
        return res;
    }

    int decrypt(const string& word2) {
        auto it = cnt.find(word2);
        return it == cnt.end() ? 0 : it->second;
    }

  private:
    vector<string> keyToVal;
    unordered_map<string, int> cnt;
};
```

### Python（哈希计数表，主推）

```python
class Encrypter:
    def __init__(self, keys: List[str], values: List[str], dictionary: List[str]):
        self.key_to_val = dict(zip(keys, values))
        self.cnt: dict[str, int] = {}
        for w in dictionary:
            e = self.encrypt(w)
            if e:
                self.cnt[e] = self.cnt.get(e, 0) + 1

    def encrypt(self, word1: str) -> str:
        parts = []
        for c in word1:
            v = self.key_to_val.get(c)
            if v is None:
                return ""
            parts.append(v)
        return "".join(parts)

    def decrypt(self, word2: str) -> int:
        return self.cnt.get(word2, 0)
```

### 备选：Trie + DFS（不依赖翻转观察的赛场写法）

```python
class Encrypter:
    def __init__(self, keys: List[str], values: List[str], dictionary: List[str]):
        self.key_to_val = dict(zip(keys, values))
        self.val_to_keys: dict[str, list[str]] = {}
        for k, v in zip(keys, values):
            self.val_to_keys.setdefault(v, []).append(k)
        self.root = {}
        for w in dictionary:
            node = self.root
            for c in w:
                node = node.setdefault(c, {})
            node['#'] = node.get('#', 0) + 1

    def encrypt(self, word1: str) -> str:
        parts = []
        for c in word1:
            v = self.key_to_val.get(c)
            if v is None:
                return ""
            parts.append(v)
        return "".join(parts)

    def decrypt(self, word2: str) -> int:
        def dfs(node: dict, i: int) -> int:
            if i == len(word2):
                return node.get('#', 0)
            total = 0
            for c in self.val_to_keys.get(word2[i:i + 2], ()):
                nxt = node.get(c)
                if nxt is not None:
                    total += dfs(nxt, i + 2)
            return total
        return dfs(self.root, 0)
```

```cpp
class Encrypter {
  public:
    Encrypter(vector<char>& keys, vector<string>& values, vector<string>& dictionary) {
        keyToVal.assign(26, "");
        for (int i = 0; i < (int)keys.size(); ++i) {
            keyToVal[keys[i] - 'a'] = values[i];
            valToKeys[values[i]].push_back(keys[i]);
        }
        for (const string& w : dictionary) {
            Node* node = &root;
            for (char c : w) {
                if (!node->next[c - 'a']) node->next[c - 'a'] = make_unique<Node>();
                node = node->next[c - 'a'].get();
            }
            node->cnt++;
        }
    }

    string encrypt(const string& word1) {
        string res;
        res.reserve(word1.size() * 2);
        for (char c : word1) {
            const string& v = keyToVal[c - 'a'];
            if (v.empty()) return "";
            res += v;
        }
        return res;
    }

    int decrypt(const string& word2) { return dfs(&root, word2, 0); }

  private:
    struct Node {
        array<unique_ptr<Node>, 26> next;
        int cnt = 0;
    };
    Node root;
    vector<string> keyToVal;
    unordered_map<string, vector<char>> valToKeys;

    int dfs(Node* node, const string& w, int i) {
        if (i == (int)w.size()) return node->cnt;
        auto it = valToKeys.find(w.substr(i, 2));
        if (it == valToKeys.end()) return 0;
        int total = 0;
        for (char c : it->second) {
            Node* nxt = node->next[c - 'a'].get();
            if (nxt) total += dfs(nxt, w, i + 2);
        }
        return total;
    }
};
```

## 8. 边界情况与易错点

1. **`dictionary` 词含 `keys` 外字符**：`encrypt` 返回 `""`。`word2` 长度 $\ge 2$ 恒非空，`cnt[""]` 永不被查询命中，故跳过与不跳过结果相同——但显式 `if (!e.empty())` 跳过可读性最好，也避免无意义的表项。
2. **`values` 重复是特性不是 bug**：多对一正是「正向爆炸、反向仍确定」的根因。若 `values` 也互异，加解密互为双射，本题难度骤降为中等。
3. **不同词可同密文**：计数可为 2…100（`dictionary` 上限），别把 `cnt` 当 0/1 判定用；同理 Trie 词尾要累加 `cnt` 而非布尔的「存在」标记。
4. **`word2` 恒为偶数长度且非空**：题目已保证，无需处理奇数/空串；但若自己写正向暴力，奇数长度应返回 0 而非越界。
5. **`encrypt` 的接口语义**：`word1` 含 `keys` 外字符返回 `""`——约束保证调用不会触发，但实现必须遵守题意（哨兵空串同时服务预处理过滤，见 §4.1）。
6. **重活必须前置**：所有预处理放构造函数。即使每次 `decrypt` 重建计数表（$200 \times 10^4 = 2 \times 10^6$）也能过，但「构造一次、查询免费」才是设计类题的正解姿态；真正的生死线是**绝不沿解密方向枚举组合**。
7. **Trie 版细节**：候选集按 `value` 分组预建（`valToKeys`）；`dfs` 里先查 `node` 是否有对应孩子再递归；C++ 用 `substr(i, 2)` 取段，注意 `word2` 用 `int` 比较避免无符号陷阱。
8. **Python 拼接**：`word1` 长达 2000，`encrypt` 用列表收集 + `join`；直接 `res += v` 在 CPython 中因字符串驻留优化通常也能过，但 `join` 是无脑安全写法。
9. **`decrypt` 的严格复杂度**：哈希查询均摊 $O(1)$，但字符串哈希需读完整个键，严格界 $O(|word2|)$——写复杂度分析时别写成绝对 $O(1)$。
