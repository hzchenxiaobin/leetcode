# LeetCode 转化时间需要的最少操作数 题解

## 1. 题目概述

- **标题 / 题号**：转化时间需要的最少操作数（#2224，easy）
- **链接**：https://leetcode.cn/problems/minimum-number-of-operations-to-convert-time/
- **来源**：LeetCode 第 287 场周赛 Q1
- **难度**：简单
- **标签**：贪心、字符串、数学

**题意**：给定两个 `"HH:MM"` 格式的 24 小时制时间字符串 `current` 与 `correct`（保证 `current <= correct`）。每一步操作可以把 `current` 增加 1、5、15 或 60 分钟，操作可执行任意次。求把 `current` 变成 `correct` 所需的**最少操作数**。

**约束**：

- `current` 和 `correct` 都符合 `"HH:MM"` 格式（`00 <= HH <= 23`，`00 <= MM <= 59`）
- `current <= correct`，即时间只会**向前**推进，不存在跨天回绕

## 2. 示例

**示例 1**

```text
输入：current = "02:30", correct = "04:35"
输出：3
解释：+60 → "03:30"，+60 → "04:30"，+5 → "04:35"，共 3 步。
```

**示例 2**

```text
输入：current = "11:00", correct = "11:01"
输出：1
解释：只差 1 分钟，一次 "+1" 操作即可。
```

**补充示例（最大差值）**

```text
输入：current = "00:00", correct = "23:59"
输出：32
解释：diff = 1439 = 23×60 + 3×15 + 2×5 + 4×1，23 + 3 + 2 + 4 = 32 步，为全局最大答案。
```

## 3. 解题思路

### 3.1 暴力思路

从 `current` 出发做 BFS，每个状态向 4 个后继（+1/+5/+15/+60）扩展，直到命中 `correct`。时间状态一共只有 $24 \times 60 = 1440$ 个，BFS 必然能过；也可以枚举四类操作的使用次数组合，验证总和等于 `diff` 后取最小。作为签到题这已经够用，但完全没必要——本题有 $O(1)$ 公式。

### 3.2 核心观察：分钟差 + 币值贪心

![核心观察：分钟差转硬币贪心](images/convert_time_greedy_concept.svg)

把两个时间都折算成从 `00:00` 起的**分钟数**，问题被一击即碎：

- **时钟问题 → 整数问题**：$diff = (H_2 - H_1) \times 60 + (M_2 - M_1) \in [0, 1439]$，由 `current <= correct` 保证非负。
- **四种操作 = 四种币值**：把 `current` 增加 60/15/5/1 分钟，相当于投入一枚面值为 60/15/5/1 的硬币。
- 原问题等价于：**用面值 $\{60, 15, 5, 1\}$ 的硬币凑出 `diff`，最少要几枚？**

关键在于这套币值构成**整除链**：

$$60 = 4 \times 15, \quad 15 = 3 \times 5, \quad 5 = 5 \times 1$$

每一级币值都是下一级的整数倍。直觉上：若若干枚小币能合成 1 枚更大的币，合并后总增量不变、步数严格变少，所以最优解一定「能合并的都合并了」——这正是**贪心**（每次取不超过剩余量的最大币值）的解。严格证明见 §5。

### 3.3 算法流程

对 `diff` 依次用 $60, 15, 5, 1$ 做**整除取余**：

```text
ops = 0
for d in [60, 15, 5, 1]:
    ops += diff / d      # 整除：当前币值能用几枚就先用几枚
    diff %= d
```

等价的闭式：

$$ops = \left\lfloor \frac{diff}{60} \right\rfloor + \left\lfloor \frac{diff \bmod 60}{15} \right\rfloor + \left\lfloor \frac{diff \bmod 15}{5} \right\rfloor + (diff \bmod 5)$$

### 3.4 示例演算

`current = "02:30"`，`correct = "04:35"`：$diff = 275 - 150 = 125$。

![示例演算：02:30 到 04:35 的贪心分解](images/convert_time_walkthrough.svg)

| 币值 | 整除（用几枚） | 取余后剩余 |
|------|------|------|
| 60 | 125 / 60 = 2 | 125 mod 60 = 5 |
| 15 | 5 / 15 = 0 | 5 |
| 5 | 5 / 5 = 1 | 0 |
| 1 | 0 / 1 = 0 | 0 |

答案 $= 2 + 0 + 1 + 0 = 3$ ✓，对应操作序列 `+60 → +60 → +5`。

## 4. 算法细节

1. **解析**：`"HH:MM"` 定长 5，时 = `s[0:2]`、分 = `s[3:5]`（或 `split(":")`），转整数。
2. **折算分钟**：$t = H \times 60 + M$，`diff = t(correct) - t(current)`，约束保证非负，无需取绝对值。
3. **贪心循环**：`for d in [60,15,5,1]` 依次整除累加商、对余数继续，比手写四行更不易错。
4. **不必担心「先取大会不会不优」**：整除链币值下贪心最优（§5 证明）；若币值任意（如 $\{1, 3, 4\}$）则贪心可能出错。

## 5. 正确性证明

![交换论证：小币合并成大币](images/convert_time_exchange.svg)

**引理 1（合并替换）**：把 5 次「+1」换成 1 次「+5」，总增量不变、操作数减少 4。同理，3 次「+5」可换 1 次「+15」（减 2 步），4 次「+15」可换 1 次「+60」（减 3 步）。因此任意最优解中「+1」的次数 $x_1 \le 4$，「+5」的次数 $x_5 \le 2$，「+15」的次数 $x_{15} \le 3$。

**证明**：四种操作对总增量的贡献只是简单相加，替换只改变「分组方式」、不改变总和，故替换后仍是从 `current` 到 `correct` 的合法方案。若最优解中 $x_1 \ge 5$，则可替换使操作数严格减少，与最优性矛盾；$x_5$、$x_{15}$ 同理。∎

**引理 2（受限表示唯一）**：设 $diff = 60x_{60} + 15x_{15} + 5x_5 + x_1$，其中 $0 \le x_1 \le 4$、$0 \le x_5 \le 2$、$0 \le x_{15} \le 3$，则四个系数唯一确定，且恰为贪心解的输出。

**证明**：由上界，$x_1 + 5x_5 + 15x_{15} \le 4 + 10 + 45 = 59 < 60$，而该式模 60 必须等于 $diff \bmod 60$，故 $x_{60} = \lfloor diff / 60 \rfloor$ 被唯一确定，剩余 $r_1 = diff \bmod 60$。同理 $x_1 + 5x_5 \le 14 < 15$ 唯一确定 $x_{15} = \lfloor r_1 / 15 \rfloor$，剩余 $r_2 = r_1 \bmod 15$；再由 $x_1 \le 4 < 5$ 唯一确定 $x_5 = \lfloor r_2 / 5 \rfloor$ 与 $x_1 = r_2 \bmod 5$。这组取值正是 §3.3 贪心流程逐步算出的结果。∎

**定理**：贪心算法返回最少操作数。

**证明**：任取一个把 `current` 变为 `correct` 的最优操作序列，其各操作次数满足 $x_1 + 5x_5 + 15x_{15} + 60x_{60} = diff$。由引理 1，最优解必满足引理 2 的约束（否则可合并替换使步数更少，与最优性矛盾）。由引理 2，满足约束的表示唯一且等于贪心解，故贪心解的操作数与最优解相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。字符串定长 5，解析与四次整除取余均为常数操作。
- **空间复杂度**：$O(1)$。仅若干整数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int convertTime(string current, string correct) {
        auto toMinutes = [](const string& s) {
            int h = stoi(s.substr(0, 2));
            int m = stoi(s.substr(3, 2));
            return h * 60 + m;
        };
        int diff = toMinutes(correct) - toMinutes(current);
        int ops = 0;
        for (int d : {60, 15, 5, 1}) {
            ops += diff / d;
            diff %= d;
        }
        return ops;
    }
};
```

### Python

```python
class Solution:
    def convertTime(self, current: str, correct: str) -> int:
        def to_minutes(s: str) -> int:
            h, m = map(int, s.split(":"))
            return h * 60 + m
        diff = to_minutes(correct) - to_minutes(current)
        ops = 0
        for d in (60, 15, 5, 1):
            ops += diff // d
            diff %= d
        return ops
```

## 8. 边界情况与易错点

1. **current == correct**：`diff` 为 0，贪心循环四轮商全为 0，自动返回 0，无需特判。
2. **分钟「借位」**：如 `"09:59" → "10:00"` 实际只差 1 分钟；若逐字段直接相减（0−9 时、0−59 分）会得到错误结果，必须先整体折算成分钟再做差。
3. **不要处理跨天**：约束 `current <= correct`，任何「加 1440 取模」的回绕逻辑都是画蛇添足。
4. **最大差值**：`00:00 → 23:59` 即 `diff = 1439`，答案 32，`int` 绰绰有余，无溢出风险。
5. **贪心的适用前提**：本题币值构成整除链（60=4×15，15=3×5，5=5×1）贪心才最优；任意币值集合（如 $\{1, 3, 4\}$ 凑 6：贪心 4+1+1 需 3 枚，最优 3+3 只要 2 枚）必须改用 DP。
