# LeetCode 不含 AAA 或 BBB 的字符串 题解

## 1. 题目概述

- **标题 / 题号**：不含 AAA 或 BBB 的字符串（#984，medium）
- **链接**：https://leetcode.cn/problems/string-without-aaa-or-bbb/
- **来源**：LeetCode 第 121 场周赛 Q1
- **难度**：中等
- **标签**：贪心、字符串

**题意**：给定两个整数 $a$ 与 $b$，返回**任意**一个字符串 $s$，满足：

1. 长度恰为 $a+b$，且恰好含 $a$ 个 `'a'` 与 $b$ 个 `'b'`；
2. 不出现子串 `"aaa"`；
3. 不出现子串 `"bbb"`。

**约束**：

- $0 \le a, b \le 100$
- 对于给定的 $a, b$，**保证存在**满足要求的字符串

> 💡 存在性条件是 $\max(a,b) \le 2\min(a,b) + 2$：多的那个字母最多被少的隔成 $\min+1$ 段，每段至多 2 个。

## 2. 示例

**示例 1**

```text
输入：a = 1, b = 2
输出："bab"
解释："abb"、"bab"、"bba" 都正确；这里按「多的排前面」得到 "bab"。
```

**示例 2**

```text
输入：a = 4, b = 1
输出："aabaa"
解释：a 多，需要 aabaa 这种「2 + 1 + 2」分块；"aaa" 被一个 b 隔开。
```

**示例 3**

```text
输入：a = 0, b = 0
输出：""
解释：空串合法，长度为 0。
```

## 3. 解题思路

### 3.1 暴力思路

从空串开始搜索：每步尝试放 `'a'` 或 `'b'`，检查是否形成三连、剩余数量是否还够，回溯找解。总状态是指数级的，$a = b = 100$ 时不可行。而且这题**不需要搜索**——每次「放哪个字母」几乎是被数量关系决定的。

### 3.2 核心观察：数量多的字母优先，必要时用少的隔开

![把多的字母分块：每块至多 2 个，块间用少的字母隔开](images/wc121_q1_block_idea.svg)

以 $a > b$ 为例。$b$ 个 `'b'` 最多把 `'a'` 切成 $b+1$ 段，所以每段放 $\lceil a/(b+1) \rceil \le 2$ 个 `'a'` 即可（存在性保证了这个上界不超过 2）。构造时只需遵守一条规则：

> **每一步优先放当前剩余较多的字母；如果放它会形成三连，就改放另一个。**

为什么这条贪心可行？

- 放较多者能尽快消化数量差，避免「多的剩太多、少的用完」的僵局；
- 只有「已经连续两个相同」时才会被强制换字母，此时换过去的那一个恰好起到「隔断」作用；
- 题目保证存在解，因此「另一个字母」在需要隔断时一定还有剩余。

### 3.3 算法流程

![贪心流程：优先放多的，若会三连则放少的](images/wc121_q1_greedy_flow.svg)

```text
res = ""
while a > 0 或 b > 0:
    canA = a > 0 且 res 末尾不是两个 'a'
    canB = b > 0 且 res 末尾不是两个 'b'
    若 canA 与 canB:
        放剩余较多的那个（a >= b 放 'a'，否则放 'b'）
    否则:
        放唯一允许的那个
返回 res
```

### 3.4 示例演算

对示例 2 的 $a = 4, b = 1$：

| 步 | 剩余 (a,b) | 当前串 | canA | canB | 决策 |
|---|---|---|---|---|---|
| 1 | (4,1) | "" | ✓ | ✓ | a ≥ b → 放 `a` |
| 2 | (3,1) | "a" | ✓ | ✓ | a ≥ b → 放 `a` |
| 3 | (2,1) | "aa" | ✗（会三连） | ✓ | 只能放 `b` |
| 4 | (2,0) | "aab" | ✓ | ✗ | 放 `a` |
| 5 | (1,0) | "aaba" | ✓ | ✗ | 放 `a` |

得到 `"aabaa"`，长度 5、含 4 个 `a` 和 1 个 `b`、无三连 ✓。

## 4. 算法细节

1. **「末尾是否两个相同」的判断**：只需看 `res[-1]` 与 `res[-2]`，长度不足 2 时不可能三连。
2. **优先放较多的**：`a >= b` 时优先 `'a'`，相等时任选（这里选 `'a'`，不会影响可行性）。
3. **两个都不能放**：在保证有解的前提下不会发生；但代码里应避免死循环，可加 `break` 防御。
4. **空串**：$a = b = 0$ 时循环不执行，返回 `""`。
5. **不需要「分块」的显式实现**：分块是分析工具，实际代码用「逐字符贪心」更简单，且自动处理 $a = b$ 的对称情形。
6. **字符串拼接**：C++ 用 `res += 'a'`（`push_back`）避免 $O(n^2)$ 的 `res = res + 'a'`；Python 的 `+=` 对小串没问题，也可用列表 `append` 后 `join`。

## 5. 正确性证明

**引理 1（不会写出三连）**：算法的每一步都保证最终串不含 `"aaa"` 或 `"bbb"`。

**证明**：算法只在 `canA` 为真时放 `'a'`，而 `canA` 的定义就是「`res` 末尾不是两个 `'a'`」，故放完后新串末尾至多两个 `'a'`，不会出现 `"aaa"`；`'b'` 同理。历史部分在之前各步已保证合法，故整体无三连。∎

**引理 2（不会卡死）**：在题目保证有解的前提下，循环每轮至少有一个 `can*` 为真，且不会出现「想放的字母已用完」的情况。

**证明**：若 `a > 0` 且 `b > 0`，只要不出现「`a` 连续两个且 `b` 也为 0」这种局面就至少能放一个。假设某轮两个 `can` 都为假：则 `a > 0` 时末尾已是 `"aa"`（或 `a = 0`），`b` 同理。若 `a, b` 都大于 0，末尾不可能同时是 `"aa"` 和 `"bb"`，矛盾；若某个为 0，则另一个字母的全部剩余无法被隔断，与「存在解」矛盾（剩余串已无法构造成立）。故至少一个 `can` 为真。∎

**引理 3（数量守恒）**：算法恰好使用 $a$ 个 `'a'` 与 $b$ 个 `'b'`。

**证明**：每轮放一个字母就把对应计数减一，循环条件是「至少一个计数大于 0」，且只在计数大于 0 时才可能放该字母（`canA` 蕴含 `a > 0`）。故循环结束时两计数都为 0，总共放了 $a$ 个 `'a'`、$b$ 个 `'b'`。∎

**定理**：算法返回的字符串满足题目全部要求。

**证明**：长度与字符数量由引理 3 保证；无 `"aaa"`/`"bbb"` 由引理 1 保证；算法能正常终止由引理 2 保证。三条正是题目要求，故正确。∎

## 6. 复杂度分析

- **时间**：$O(a+b)$，每轮输出一个字符，末尾判断 $O(1)$。
- **空间**：$O(a+b)$ 存结果串（不计返回值则 $O(1)$ 额外空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string strWithout3a3b(int a, int b) {
        string res;
        res.reserve(a + b);
        while (a > 0 || b > 0) {
            bool canA = a > 0 && !(res.size() >= 2 && res[res.size() - 1] == 'a'
                                             && res[res.size() - 2] == 'a');
            bool canB = b > 0 && !(res.size() >= 2 && res[res.size() - 1] == 'b'
                                             && res[res.size() - 2] == 'b');
            if (canA && (!canB || a >= b)) {
                res.push_back('a');
                a--;
            } else if (canB) {
                res.push_back('b');
                b--;
            } else {
                break;   // 输入无解时的防御，题目保证不会走到这里
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def strWithout3a3b(self, a: int, b: int) -> str:
        res = []
        while a > 0 or b > 0:
            can_a = a > 0 and not (len(res) >= 2 and res[-1] == 'a' and res[-2] == 'a')
            can_b = b > 0 and not (len(res) >= 2 and res[-1] == 'b' and res[-2] == 'b')
            if can_a and (not can_b or a >= b):
                res.append('a')
                a -= 1
            elif can_b:
                res.append('b')
                b -= 1
            else:
                break
        return "".join(res)
```

## 8. 边界情况与易错点

1. **$a = b = 0$**：返回空串，循环不进入。
2. **单边为 0**：如 $(2, 0)$ → `"aa"`；$(3, 0)$ 无解（题目不会给）。
3. **相等数量**：如 $(3,3)$ → `"ababab"` 类结果，贪心天然交替。
4. **相差悬殊但可行**：如 $(4,1)$，必须靠「2+1+2」分块，贪心在第 3 步被迫换字母，正好实现隔断。
5. **把「优先较多」写成「优先 `'a'`」**：$b > a$ 时会连续放 `'a'` 直到用尽，然后 `b` 大量剩余形成三连，直接错。
6. **忘记检查末尾长度**：`res[-2]` 在长度 1 时越界（Python 会取到别的字符导致误判）。
7. **死循环防御**：虽然题目保证有解，但写一个 `else: break` 更安全（尤其是本地随机测试时）。
8. **`res.reserve`**：$a+b \le 200$，可省略；但养成预留容量的习惯能避免多次扩容。
