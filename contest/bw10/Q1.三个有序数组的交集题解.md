# LeetCode 三个有序数组的交集 题解

## 1. 题目概述

- **标题 / 题号**：三个有序数组的交集（#1213，easy）
- **链接**：https://leetcode.cn/problems/intersection-of-three-sorted-arrays/
- **来源**：LeetCode 第 10 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、二分查找、计数

**题意**：给定三个**严格递增**的整数数组 `arr1`、`arr2`、`arr3`，返回一个**升序**数组，包含所有同时出现在三个数组中的元素。

**约束**：

- $1 \le arr1.length, arr2.length, arr3.length \le 1000$
- $1 \le arr1[i], arr2[i], arr3[i] \le 2000$

## 2. 示例

**示例 1**

```text
输入：arr1 = [1,2,3,4,5], arr2 = [1,2,5,7,9], arr3 = [1,3,4,5,8]
输出：[1,5]
解释：只有 1 和 5 同时出现在三个数组中。
```

**示例 2**

```text
输入：arr1 = [197,418,523,876,1356], arr2 = [501,880,1593,1710,1870],
     arr3 = [521,682,1337,1395,1764]
输出：[]
解释：三个数组两两不相交。
```

**示例 3（补充）**

```text
输入：arr1 = [1,2,3], arr2 = [1,2,3], arr3 = [1,2,3]
输出：[1,2,3]
解释：三数组完全相同，交集就是它本身。
```

## 3. 解题思路

### 3.1 暴力思路

三重循环枚举三元组 $(i, j, k)$，判断 `arr1[i] == arr2[j] == arr3[k]`，$O(n_1 n_2 n_3) = 10^9$，显然不可行。改进：用哈希表（或值域计数数组，值只有 $2000$）对三个数组计数，统计出现次数为 $3$ 的值——$O(n_1 + n_2 + n_3)$ 时间、$O(V)$ 或 $O(n)$ 空间，能过，但既没利用**有序**，也吃掉一份哈希空间。既然题面强调三个数组都严格递增，理应走出**零额外空间**的归并式做法。

### 3.2 核心观察：三指针归并，小者先行

![核心观察：三条有序跑道上的三指针归并](images/bw10_q1_three_pointer_model.svg)

对两个有序数组求交集的标准手法是双指针：两指针指向的值相等即命中，否则**推进指向较小值的指针**（较大值不可能是交集——另一个数组已经越过它了）。三个数组是自然推广：

- 三个指针 $i, j, k$ 分别指向三个数组的当前位置；
- 若三个当前值**相等**，该值必属于交集，收集并三指针同进；
- 否则求出三者的**最小值**，**所有**指向最小值的指针各推进一格——被推过的值都比「三者最大公共候选」小，且严格递增保证每个值在每个数组中只出现一次，推掉绝不会漏。

由于每次至少推进一个指针、每个指针至多走完自己的数组，整个过程是线性的，且输出顺序天然升序（收集到的值严格递增）。

> 💡 这就是 $k$ 路归并求交集的通用模板：任何时刻，落后（值小）的指针前进，齐平即命中。

### 3.3 算法流程

![算法流程：全等收集，否则推进所有最小指针](images/bw10_q1_algorithm_flow.svg)

```text
1. i = j = k = 0
2. 当 i、j、k 都未越界：
   2.1 a = arr1[i], b = arr2[j], c = arr3[k]
   2.2 若 a == b == c：收集 a；i++, j++, k++
   2.3 否则：mn = min(a, b, c)
         若 a == mn: i++      # 指向最小值的指针全部推进（可同时多个）
         若 b == mn: j++
         若 c == mn: k++
3. 返回收集结果（天然升序）
```

### 3.4 示例演算

![示例演算：示例 1 的指针推进轨迹](images/bw10_q1_example_walkthrough.svg)

以示例 1（arr1 = [1,2,3,4,5]，arr2 = [1,2,5,7,9]，arr3 = [1,3,4,5,8]）逐步走查：

| 步骤 | $(i,j,k)$ | 当前三元组 | 判定 | 动作 |
|---|---|---|---|---|
| 1 | (0,0,0) | (1, 1, 1) | 全等 | **收集 1**，三指针同进 |
| 2 | (1,1,1) | (2, 2, 3) | 最小值 2（两数组） | i++, j++ |
| 3 | (2,2,1) | (3, 5, 3) | 最小值 3（arr1、arr3） | i++, k++ |
| 4 | (3,2,2) | (4, 5, 4) | 最小值 4（两数组） | i++, k++ |
| 5 | (4,2,3) | (5, 5, 5) | 全等 | **收集 5**，三指针同进 |
| 6 | (5,3,4) | arr1 越界 | — | 结束，输出 [1,5] |

注意步骤 3：arr1 与 arr3 同时指向最小值 3，**两个指针同时推进**——只推进一个会陷入「原地等待另一个不相等值」的空转，这是本题最经典的实现 bug。

## 4. 算法细节

1. **推进所有等于最小值的指针**：一步内可能有两个（极端时三个）数组同时处于最小值，必须一次性全部推进，否则循环可能不推进任何指针以外的东西、甚至死循环。
2. **全等情形单独处理**：全等时三个指针都要推进，不能走「最小值推进」分支（否则会推掉三份后才判等，逻辑混乱且会漏收集）。
3. **终止条件**：任一数组耗尽即可停止——交集元素必须在每个数组中出现，某数组越界后再无候选。
4. **输出顺序**：收集到的值严格递增（数组严格递增 + 指针单调右移），无需再排序。
5. **`min(a, b, c)` 的写法**：C++ 里 `min({a,b,c})` 初始化列表形式或嵌套 `min(a, min(b,c))` 均可；Python 直接 `min(a, b, c)`。
6. **值域小的额外福利**：值 $\le 2000$，计数数组法也可行；但三指针法对值域不敏感、零额外空间，是更值得沉淀的模板。

## 5. 正确性证明

**引理 1（扫描不变量）**：在算法任意时刻，设指针为 $(i, j, k)$，则每个公共元素 $v$ 要么已被收集，要么 $v$ 在三个数组中的（唯一）出现位置都 $\ge$ 当前的 $(i, j, k)$。

**证明**：对指针推进总次数归纳。初始 $(0,0,0)$ 显然成立。设时刻 $t$ 成立，考察一次推进：

- **全等分支**（值 $v_0$，三指针同进）：$v_0$ 刚被收集。对未被收集的公共元素 $v \ne v_0$：由归纳假设 $v$ 的位置 $\ge (i,j,k)$；又三数组严格递增、每值至多出现一次，若 $v$ 的某位置恰等于当前指针，则该数组当前值就是 $v = v_0$，与全等矛盾；故 $v$ 的每个位置都 $> $ 当前指针，即 $\ge$ 推进后的新指针。
- **最小值分支**（设推进的指针集合为 $S$，被推值为 $m$）：先证「若 $m$ 是公共元素，则必已被收集」。反设 $m$ 未被收集：由归纳假设 $m$ 的位置 $\ge (i,j,k)$；对任一未推进的数组（当前值 $> m$，因 $m$ 是最小值且不全等），$m$ 出现在该数组中的位置必须 $<$ 当前指针（严格递增性），矛盾。故 $m$ 要么不是公共元素、要么已收集，推掉 $m$ 的指针不破坏不变量；其余值的位置关系不变。∎

**引理 2（全等即公共元素）**：全等分支收集的值 $v_0$ 确实出现在三个数组中，且收集序列严格递增。

**证明**：全等意味着三个指针所指的当前元素都是 $v_0$，即 $v_0$ 同时属于三个数组。每次收集后三指针各右移一位，后续当前值都 $> v_0$（严格递增），故收集值严格递增。∎

**定理**：算法输出恰为三个数组的交集，且升序。

**证明**：**完整性**：算法终止时任一数组已耗尽，由引理 1，未被收集的公共元素的位置仍 $\ge$ 终止时的指针，但某数组指针已越界，矛盾，故所有公共元素均被收集。**正确性**：由引理 2，收集的都是公共元素且升序。**终止性**：每轮至少推进一个指针、指针总量有限。∎

## 6. 复杂度分析

- **时间**：$O(n_1 + n_2 + n_3)$。每轮至少一个指针前进，总推进次数不超过三数组长度之和。
- **空间**：$O(1)$ 额外空间（不计返回数组）。相比计数法的 $O(V)$ 或哈希的 $O(n)$，这是干净的下限。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> arraysIntersection(vector<int>& arr1, vector<int>& arr2, vector<int>& arr3) {
        vector<int> res;
        int i = 0, j = 0, k = 0;
        int n1 = arr1.size(), n2 = arr2.size(), n3 = arr3.size();
        while (i < n1 && j < n2 && k < n3) {
            int a = arr1[i], b = arr2[j], c = arr3[k];
            if (a == b && b == c) {              // 三指针同值：交集中的元素
                res.push_back(a);
                ++i; ++j; ++k;
            } else {                             // 推进指向最小值的指针（可能不止一个）
                int mn = min(a, min(b, c));
                if (a == mn) ++i;
                if (b == mn) ++j;
                if (c == mn) ++k;
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def arraysIntersection(self, arr1: list[int], arr2: list[int],
                           arr3: list[int]) -> list[int]:
        res = []
        i = j = k = 0
        while i < len(arr1) and j < len(arr2) and k < len(arr3):
            a, b, c = arr1[i], arr2[j], arr3[k]
            if a == b == c:                 # 三指针同值：交集中的元素
                res.append(a)
                i += 1; j += 1; k += 1
            else:                           # 推进指向最小值的指针（可能不止一个）
                mn = min(a, b, c)
                if a == mn: i += 1
                if b == mn: j += 1
                if c == mn: k += 1
        return res
```

## 8. 边界情况与易错点

1. **只推一个最小指针**：最常见的错误——两个数组同时处于最小值时只推进一个，下一轮三元组依旧不全等、指针原地打转甚至死循环。
2. **空交集**：如示例 2，循环自然走完返回 `[]`，无需特判。
3. **三数组完全相同**：每轮都是全等分支，一路收集到底（补充示例 3）。
4. **某数组先耗尽**：终止条件写在 `while` 里，越界即刻停；若误写成 `while (true)` 加手动 break，容易漏判第一个耗尽的数组。
5. **严格递增是「无重复」的保证**：若数组非严格（有重复），三指针法收集的每个值仍只出现一次，但值在数组中的多份拷贝会让「位置 $\ge$ 指针」的不变量变弱，需要改用「计数」语义——本题题面明确严格递增，不必担心。
6. **别忘输出升序**：本题要求返回**有序**数组；三指针法天然有序，若用哈希集合实现则**必须显式排序**，否则示例 3 这类全重叠数据会输出错序。
