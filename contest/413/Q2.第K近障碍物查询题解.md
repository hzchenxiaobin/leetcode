# LeetCode 第 K 近障碍物查询 题解

## 1. 题目概述

- **标题 / 题号**：第 K 近障碍物查询（#3275，medium）
- **链接**：https://leetcode.cn/problems/k-th-nearest-obstacle-queries/
- **来源**：LeetCode 第 413 场周赛 Q2
- **难度**：中等
- **标签**：数组、堆（优先队列）

**题意**：无限大二维平面上依次处理查询数组 `queries`，第 `i` 次查询 `queries[i] = [x, y]` 表示在坐标 `(x, y)` 处建一个障碍物（坐标保证互不相同）。每次建完后，求**离原点第 k 近**的障碍物到原点的距离；距离定义为曼哈顿距离 $|x| + |y|$。若当前障碍物数不足 `k` 个，答案为 `-1`。返回答案数组 `results`。

**约束**：

- $1 \le \text{queries.length} \le 2 \times 10^5$
- 所有 `queries[i]` 互不相同
- $-10^9 \le x, y \le 10^9$
- $1 \le k \le 10^5$

## 2. 示例

**示例 1**

```text
输入：queries = [[1,2],[3,4],[2,3],[-3,0]], k = 2
输出：[-1,7,5,3]
解释：
- queries[0] 之后：只有 1 个障碍物，不足 2 个 → -1
- queries[1] 之后：距离集合 {3, 7}，第 2 近 = 7
- queries[2] 之后：距离集合 {3, 5, 7}，第 2 近 = 5
- queries[3] 之后：距离集合 {3, 3, 5, 7}，第 2 近 = 3（距离并列按个数计）
```

**示例 2**

```text
输入：queries = [[5,5],[4,4],[3,3]], k = 1
输出：[10,8,6]
解释：
- queries[0] 之后：距离集合 {10}，第 1 近 = 10
- queries[1] 之后：距离集合 {8, 10}，第 1 近 = 8
- queries[2] 之后：距离集合 {6, 8, 10}，第 1 近 = 6
```

## 3. 解题思路

### 3.1 暴力思路：每次重排

每个查询后，把当前所有障碍物的距离收集起来排序，取升序第 `k` 个。单次 $O(n \log n)$，总计 $O(n^2 \log n)$；$n = 2 \times 10^5$ 时达 $10^{12}$ 量级，必然超时。即便换成维护有序数组（二分定位 + 整体挪动插入），挪动开销也是 $O(n^2)$，同样不可行。

> 💡 浪费的根源：相邻两次查询只多了一个新距离，前一轮辛苦排好的序全部作废。增量场景下真正需要记住的只有一个数——**"当前第 k 近是多大"**。

### 3.2 核心观察：容量 k 的大根堆维护「最小 k 个」

![第k近等于最小k个距离中的最大值](images/c413_q2_topk_heap_concept.svg)

第 k 近 = 全体距离的**第 k 小** = **最小的 k 个距离中的最大值**。于是只需维护一个容量为 k 的**大根堆**：

- 堆里永远只装当前"最小 k 个"距离；
- **堆顶**就是其中最大者，即第 k 近，$O(1)$ 直接读出；
- 新距离 $d$ 只有**严格小于堆顶**时才可能挤进"最小 k 个"（弹出堆顶、压入 $d$）；$d \ge$ 堆顶的直接丢弃，堆纹丝不动。

这是 top-k 维护的经典套路：求第 k **大**用容量 k 的**小根堆**（如 703 题），求第 k **小**就镜像地用容量 k 的**大根堆**。

### 3.3 算法流程

![算法流程图](images/c413_q2_algorithm_flow.svg)

```text
1. 建空的大根堆 pq（容量上限 k）
2. 对每个查询 [x, y]：
   a. d = |x| + |y|
   b. 若 |pq| < k      → d 入堆
      否则若 d < 堆顶   → 弹出堆顶，d 入堆
      否则              → 堆不变
   c. results[i] = (|pq| == k) ? 堆顶 : -1
3. 返回 results
```

### 3.4 示例演算

![示例1演算](images/c413_q2_example_walkthrough.svg)

对示例 1（k = 2）逐步走查：

| i | 查询 | d | 全部距离 | 堆（容量 2） | 动作 | results[i] |
|---|------|---|----------|--------------|------|-----------|
| 0 | (1,2) | 3 | {3} | {3} | 堆未满，3 入堆 | -1 |
| 1 | (3,4) | 7 | {3,7} | {3,7} | 堆未满，7 入堆，堆首次装满 | 7 |
| 2 | (2,3) | 5 | {3,5,7} | {3,5} | 5 < 堆顶 7 → 7 出堆、5 入堆 | 5 |
| 3 | (-3,0) | 3 | {3,3,5,7} | {3,3} | 3 < 堆顶 5 → 5 出堆、3 入堆 | 3 |

得到 `[-1, 7, 5, 3]`，与示例一致。注意第 3 步：距离可以**并列**（`(1,2)` 与 `(-3,0)` 都是 3），按多重集计数第 2 近仍是 3。

## 4. 算法细节

1. **距离计算**：$d = |x| + |y|$，纯整数加减，无乘除开方，坐标范围 $10^9$ 内也不会引入浮点误差。
2. **堆的方向**：C++ `priority_queue<int>` 默认就是大根堆，堆顶即答案；Python `heapq` 是小根堆，**存 $-d$** 模拟大根堆，答案取 $-\text{heap}[0]$。
3. **替换条件用严格小于**：$d <$ 堆顶才替换。相等时替换不改变堆顶值（并列按多重集计数），纯属浪费一次 $O(\log k)$ 操作，直接跳过。
4. **堆满才有答案**：`results[i]` 只在堆大小恰为 `k` 时输出堆顶，否则 `-1`；`k` 可能大于 `n`（如 $k = 10^5$、$n = 1$），此时全程 `-1`，同一判断天然覆盖。
5. **先更新再取值**：第 `i` 个答案是建立第 `i` 个障碍物**之后**的状态，必须先执行堆操作再读堆顶，顺序颠倒会把上一轮答案写进 `results[i]`。

## 5. 正确性证明

**引理 1（堆不变量）**：设已插入 $m$ 个障碍物，则堆中元素（按多重集计）恰为这 $m$ 个距离中最小的 $\min(m, k)$ 个，且堆顶是其中的最大值。

**证明**：对 $m$ 归纳。$m = 0$ 时堆空，平凡成立。设结论对 $m$ 成立，考察第 $m+1$ 个距离 $d$：

- **堆未满**（$m < k$）：由归纳假设，堆中原有 $m$ 个元素恰是前 $m$ 个距离的全部（$\min(m,k) = m$），也即最小的 $m$ 个。压入 $d$ 后堆中是前 $m+1$ 个的全部；又 $m + 1 \le k$，故恰为最小的 $\min(m+1, k) = m+1$ 个。
- **堆已满**（$m \ge k$）：记堆中多重集为 $H$，堆顶 $t = \max H$。把前 $m$ 个距离升序排列，$H$ 恰为前 $k$ 个，故任何不在 $H$ 中的距离都 $\ge t$。于是前 $m+1$ 个距离的最小 $k$ 个只能出自 $H \cup \{d\}$（共 $k+1$ 个候选）：
  - 若 $d < t$：候选中的最大者是 $t$，将其剔除后剩下的 $H \setminus \{t\} \cup \{d\}$ 即最小 $k$ 个——恰对应"弹出堆顶、压入 $d$"；
  - 若 $d \ge t$：$d$ 不小于 $H$ 中任何元素，最小 $k$ 个仍为 $H$，堆保持不变。

两种操作后堆顶均为新集合的最大值（大根堆性质）。归纳完成。∎

**定理**：每次查询后，算法输出的值恰为当前第 k 近障碍物的距离；障碍物不足 k 个时输出 $-1$。

**证明**：第 k 近即全体距离（多重集）升序排列的第 $k$ 位，等于最小 $k$ 个距离的最大值。堆大小为 $k$ 时，由引理 1，堆中恰为最小 $k$ 个且堆顶为其最大值，输出堆顶正确；堆大小 $< k$ 时已插入个数 $< k$，按题意输出 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log k)$。每个查询至多一次弹出 + 一次压入，各 $O(\log k)$；$n = 2 \times 10^5$、$k \le 10^5$ 时约 $3 \times 10^6$ 次基本堆操作，远低于暴力的 $O(n^2 \log n)$。
- **空间复杂度**：$O(n + k)$。堆最多存 $k$ 个元素，输出数组 $n$ 个；由于 $k \le n$ 时堆开销被输出数组的 $O(n)$ 覆盖，总体即 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> resultsArray(vector<vector<int>>& queries, int k) {
        priority_queue<int> pq;                 // 大根堆：只装「最小 k 个」距离
        vector<int> res;
        res.reserve(queries.size());
        for (const auto& q : queries) {
            int d = abs(q[0]) + abs(q[1]);
            if ((int)pq.size() < k) {
                pq.push(d);                     // 堆未满，直接放行
            } else if (d < pq.top()) {          // 比堆顶更近才挤得进来
                pq.pop();
                pq.push(d);
            }
            res.push_back((int)pq.size() == k ? pq.top() : -1);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def resultsArray(self, queries: List[List[int]], k: int) -> List[int]:
        heap = []                               # 存 -d：小根堆当大根堆用
        res = []
        for x, y in queries:
            d = abs(x) + abs(y)
            if len(heap) < k:
                heapq.heappush(heap, -d)
            elif d < -heap[0]:
                heapq.heapreplace(heap, -d)     # 一步完成「弹最大 + 压新」
            res.append(-heap[0] if len(heap) == k else -1)
        return res
```

## 8. 边界情况与易错点

1. **先更新堆再取答案**：`results[i]` 对应"建立第 i 个障碍物之后"的状态，顺序颠倒会让答案整体错位一轮。
2. **k > n**：障碍物总数始终不足 k（如 $k = 10^5$、$n = 1$），全程输出 `-1`；判断条件务必是"堆大小 == k"，而非"处理到第 k 个查询"。
3. **距离并列**：坐标互异但距离可相等（`(1,2)` 与 `(-3,0)` 都是 3），第 k 近按**多重集**计数；替换条件用严格小于 `d < top`，写成 `<=` 不影响正确性但会白做功。
4. **数值范围**：$|x| + |y| \le 2 \times 10^9$，恰好卡在 32 位有符号整数上限（$\approx 2.147 \times 10^9$）之内；C++ 用 `int` 恰好安全但已贴边，求稳可换 `long long`，Python 天然无虞。
5. **别把所有距离塞进小根堆**：小根堆堆顶是"最近"而非"第 k 近"；正确姿势是**容量 k 的大根堆**（Python 里即存负数模拟）。
6. **坐标互异的保证其实用不上**：算法只消费距离值，该保证只是排除了"同一障碍物被加两次"的歧义，无需额外去重。
