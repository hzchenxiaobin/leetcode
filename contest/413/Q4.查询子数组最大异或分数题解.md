# LeetCode 查询子数组最大异或分数 题解

## 1. 题目概述

- **标题 / 题号**：查询子数组最大异或分数（#3277，hard）
- **链接**：https://leetcode.cn/problems/maximum-xor-score-subarray-queries/
- **来源**：LeetCode 第 413 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、位运算

**题意**：定义数组的**异或分数**：每一轮把除最后一个下标外的所有 $a_i$ 同时替换为 $a_i \oplus a_{i+1}$，然后移除末尾元素；数组长度不断减一，最后剩下的那个数就是分数。给定数组 `nums` 与查询数组 `queries`，第 $i$ 个查询 $[l_i, r_i]$ 要求 `nums` 在区间 $[l_i, r_i]$ 内**任意子数组**的异或分数的**最大值**，返回长度为 $q$ 的答案数组。

**约束**：

- $1 \le n = \text{nums.length} \le 2000$
- $0 \le \text{nums}[i] \le 2^{31} - 1$
- $1 \le q = \text{queries.length} \le 10^5$
- $0 \le l_i \le r_i \le n - 1$

> 💡 **数据范围的信号**：$n \le 2000$ 但 $q \le 10^5$——不同的 $(l, r)$ 至多 $\frac{n(n+1)}{2} \approx 2 \times 10^6$ 个，远小于查询数，这是「预处理 $O(n^2)$ 区间答案表、每次查询 $O(1)$」的经典模板题面。

## 2. 示例

**示例 1**

```text
输入：nums = [2,8,4,32,16,1], queries = [[0,2],[1,4],[0,5]]
输出：[12,60,60]
解释：
- 查询 [0,2]：子数组 [2],[8],[4],[2,8],[8,4],[2,8,4] 的分数分别为
  2, 8, 4, 10, 12, 6，最大值 12 来自子数组 [8,4]。
- 查询 [1,4]：整段 [8,4,32,16] 折叠到底恰为 60，就是最大值。
- 查询 [0,5]：最大值仍来自内部子数组 nums[1..4]，即 60。
```

**示例 2**

```text
输入：nums = [0,7,3,2,8,5,1], queries = [[0,3],[1,5],[2,4],[2,6],[5,6]]
输出：[7,14,11,14,5]
解释：
- [0,3]：最优是单元素子数组 [7]，分数 7。
- [1,5]：最优是 [7,3,2,8]，分数 14。
- [2,4]：整段 [3,2,8] 的分数 11。
- [2,6]：子数组 [2,8,5,1] 的分数 14。
- [5,6]：单元素 [5] 分数 5（[5,1] 折叠得 4，反而更小）。
```

## 3. 解题思路

### 3.1 暴力思路：两个瓶颈

最直接的暴力对每个查询 $[l, r]$ 枚举其中所有 $O(L^2)$ 个子数组、每个子数组模拟折叠一遍 $O(L)$，单查询 $O(L^3)$，总计 $O(q \cdot n^3) \approx 10^5 \times 8 \times 10^9 = 8 \times 10^{14}$，完全不可行。即使先把每个子数组的分数算好存起来，回答单个查询仍要枚举 $O(L^2)$ 个子数组取最大，总计 $O(n^3 + q \cdot n^2) \approx 4 \times 10^{11}$，同样不可行。

> 💡 暴力卡在两个独立的地方：**「一个子数组的分数」**算得太慢，以及**「一个区间内所有子数组的最大值」**取得太慢。两个瓶颈各用一个 $O(1)$ 递推解决，就是本题的两层 DP。

### 3.2 核心观察一：折叠过程是一座「异或帕斯卡三角」

![核心观察：折叠过程是异或帕斯卡三角](images/c413_q4_xor_triangle_concept.svg)

把折叠过程逐层画出来：第 0 行是原数组，每一行由上一行**相邻两数异或**得到、长度减一，像一座金字塔。设 $f[l][r]$ 表示子数组 $\text{nums}[l..r]$ 的异或分数，则这座三角有个惊人的性质：

- **第 $m$ 行的第 $i$ 格恰好是 $f[i][i+m]$**——即整张三角以「斜层」的方式装下了全部 $O(n^2)$ 个区间的分数；
- 于是**转移式就是折叠操作本身**：

$$f[l][r] = f[l][r-1] \oplus f[l+1][r], \qquad f[l][l] = \text{nums}[l]$$

一个格子的值 = 正上方两个格子之异或（帕斯卡三角的异或版）。这样不用反复模拟，$O(n^2)$ 次异或即可求出**所有**区间的分数。

> ⚠️ 常见误区是想当然地写 $f[l][r] = f[l+1][r-1] \oplus \cdots$ 之类的「对称」式子。正确性来自引理 1 的严格对应（见 §5），不是直觉。

顺带一个有趣的洞察（算法不需要）：展开到底时，$\text{nums}[l+k]$ 参与异或的次数是 $\binom{m}{k}$（从金字塔顶走到该格的路径数），偶数次成对抵消，所以只有 $\binom{m}{k}$ 为**奇数**的元素存活——这正是帕斯卡三角模 2 的 Lucas 定理形态（见 §4、延伸思考）。

### 3.3 核心观察二：答案表的 max 递推

![第二层DP：区间内任意子数组的最大分数](images/c413_q4_g_max_dp_model.svg)

$f$ 只给出「区间本身」的分数，而查询要的是「区间**内**任意子数组」的最大分数。设 $g[l][r]$ 为查询 $[l, r]$ 的答案，对最优子数组 $[i, j]$ 的边界做三分：

- $j \le r - 1$：最优子数组整个落在 $[l, r-1]$ 内 → 已含于 $g[l][r-1]$；
- $i \ge l + 1$：整个落在 $[l+1, r]$ 内 → 已含于 $g[l+1][r]$；
- $i = l$ 且 $j = r$：恰好是整段 → 就是 $f[l][r]$。

三类不重不漏，故

$$g[l][r] = \max\{\, g[l][r-1],\ g[l+1][r],\ f[l][r] \,\}, \qquad g[l][l] = \text{nums}[l]$$

算法流程整理如下：

```text
1. 初始化对角线：f[l][l] = g[l][l] = nums[l]
2. 按 l 从 n−1 倒序到 0（此时 l+1 行已就绪），r 从 l+1 正序到 n−1：
   f[l][r] = f[l][r−1] ⊕ f[l+1][r]
   g[l][r] = max(g[l][r−1], g[l+1][r], f[l][r])
3. 每个查询 [li, ri] 直接读 g[li][ri]，O(1)
```

两张表在同一套双重循环里同步填出，填完之后任何查询都是一次数组访问。

### 3.4 示例演算

![示例演算：f表与g表](images/c413_q4_example_walkthrough.svg)

对示例 1（`nums = [2,8,4,32,16,1]`）把两张上三角表全部填出（见上图）。以查询 $[1,4]$ 追一遍转移链：

- $f[1][4] = f[1][3] \oplus f[2][4] = 40 \oplus 20 = 60$——整段 $[8,4,32,16]$ 的分数；
- $g[1][4] = \max(g[1][3],\, g[2][4],\, f[1][4]) = \max(40, 48, 60) = 60$。

三个查询直接读表：$g[0][2] = 12$、$g[1][4] = 60$、$g[0][5] = 60$，与预期输出 `[12,60,60]` 一致。注意 $g[0][5]$ 的 60 同样来自 $f[1][4]$——最优子数组可以在查询区间**内部任意位置**，这正是第二层 max 递推要传递的信息。

## 4. 算法细节

1. **计算顺序**：$f[l][r]$ 依赖「同行左邻」$f[l][r-1]$ 与「下一行同列」$f[l+1][r]$，因此 **$l$ 必须倒序**（保证第 $l+1$ 行先算好）、**$r$ 必须正序**（保证左邻先算好）；$g$ 的依赖方向完全相同，可共用循环。等价写法是按区间长度 $r - l$ 从小到大枚举。
2. **组合数视角（可选洞察）**：由帕斯卡恒等式 $\binom{m}{k} = \binom{m-1}{k} + \binom{m-1}{k-1}$ 模 2 即得递推式。例如 $m = 2$ 时 $\binom{2}{1} = 2$ 为偶，中间元素被抵消：$[a, b, c]$ 折叠两次后恰为 $a \oplus c$——可用来人工抽查实现。
3. **值域与位宽**：$0 \le \text{nums}[i] \le 2^{31} - 1$，而异或不会产生新的高位，全程值 $\le 2^{31} - 1$，C++ 用 32 位 `int` 恰好安全（不需 `long long`）。
4. **同步填表**：$g[l][r]$ 的转移要用本行的 $f[l][r]$，二者在同一循环体里按「先 $f$ 后 $g$」的顺序计算即可，无需分两遍扫。
5. **内存优化（可选）**：两张表的转移都只依赖「当前行 + 下一行」，若内存紧张（如 Python），可把查询**按 $l$ 离线分组**，$f$、$g$ 各滚动一行，工作内存降到 $O(n + q)$；C++ 直接开两张 $n \times n$ 的 `int` 表（约 32 MB）更直观。

## 5. 正确性证明

**引理 1（折叠过程 = 三角的锥）**：对数组 $a$ 定义三角 $T$：第 0 行为 $a$，第 $m$ 行由第 $m-1$ 行相邻异或得到。则窗口 $[l, r]$（记 $m = r - l$）折叠 $k$（$0 \le k \le m$）次后的剩余数组，等于第 $k$ 行限制在下标 $[l, r-k]$ 上的部分；特别地 $f[l][r] = $ 第 $m$ 行第 $l$ 格。

**证明**：对 $k$ 归纳。$k = 0$：剩余数组就是 $a[l..r]$，与第 0 行在 $[l, r]$ 上一致。设折叠 $k-1$ 次后剩余数组等于第 $k-1$ 行在 $[l, r-k+1]$ 上的部分；再折叠一次，窗口内每个新元素是窗口内相邻两元素之异或，而「第 $k$ 行」正是「第 $k-1$ 行相邻异或」，两个下标都落在 $[l, r-k+1]$ 内，故折叠 $k$ 次后剩余数组等于第 $k$ 行在 $[l, r-k]$ 上的部分。$k = m$ 时窗口只剩单个格子，即第 $m$ 行第 $l$ 格。∎

**推论 1（分数递推）**：$l < r$ 时 $f[l][r] = f[l][r-1] \oplus f[l+1][r]$，且按该式与 $f[l][l] = \text{nums}[l]$ 填出的每个 $f[l][r]$ 都等于折叠分数。

**证明**：记 $m = r - l$。由引理 1，$f[l][r]$、$f[l][r-1]$、$f[l+1][r]$ 分别是 $T$ 的第 $m$ 行第 $l$ 格、第 $m-1$ 行第 $l$ 格、第 $m-1$ 行第 $l+1$ 格；而 $T$ 的定义恰是「每格 = 正上方两格之异或」，三式相合。又因递推式、初值与 $T$ 的生成规则完全相同，按式填出的表逐格等于 $T$，即等于折叠分数。∎

**引理 2（帕斯卡权重，选读）**：$f[l][r] = \bigoplus_{0 \le k \le m,\ \binom{m}{k}\ \text{为奇}} \text{nums}[l+k]$，$m = r - l$。

**证明**：对 $m$ 归纳，初值 $m = 0$ 平凡。由推论 1 与归纳假设，$\text{nums}[l+j]$ 在 $f[l][r]$ 中出现与否（模 2 系数）为 $\binom{m-1}{j} + \binom{m-1}{j-1} \equiv \binom{m}{j} \pmod 2$（帕斯卡恒等式，越界按 0）。∎

**引理 3（子数组三分）**：$[l, r]$ 的任一子数组 $[i, j]$（$l \le i \le j \le r$）恰属下述三类之一：(a) $j \le r-1$；(b) $j = r$ 且 $i \ge l+1$；(c) $[i,j] = [l,r]$。

**证明**：按 $j < r$、$j = r \wedge i > l$、$j = r \wedge i = l$ 穷举，互斥且完备。∎

**定理**：按 $g[l][l] = \text{nums}[l]$ 与 $g[l][r] = \max\{g[l][r-1], g[l+1][r], f[l][r]\}$ 递推出的 $g[l][r]$ 等于查询 $[l, r]$ 的答案（区间内全部子数组分数的最大值）。

**证明**：对 $m = r - l$ 归纳。$m = 0$：唯一子数组是 $[l, l]$ 自身，分数 $\text{nums}[l]$，与初值一致。设结论对更短的区间成立。由引理 3，$[l, r]$ 的子数组分三类：类 (a) 的子数组全含于 $[l, r-1]$，其分数最大值由归纳假设等于 $g[l][r-1]$；类 (b) 全含于 $[l+1, r]$，最大值为 $g[l+1][r]$；类 (c) 只有整段自身，分数为 $f[l][r]$（由推论 1，递推出的 $f$ 值就是折叠分数）。三类取最大即 $[l, r]$ 的答案，与递推式右端一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 + q)$。预处理填两张上三角表共 $\frac{n(n+1)}{2} \approx 2 \times 10^6$ 个状态，每步 $O(1)$（一次异或 + 一次三元 max）；随后 $q \le 10^5$ 个查询各一次数组访问。相比暴力的 $O(q \cdot n^3)$ 下降了约九个数量级。
- **空间复杂度**：$O(n^2)$，两张 `int` 表共约 32 MB（$n = 2000$）。由 §4 第 5 点，配合离线分组查询可压到 $O(n + q)$，本题无此必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> maximumSubarrayXor(vector<int>& nums, vector<vector<int>>& queries) {
        int n = nums.size();
        // f[l][r]: nums[l..r] 的异或分数；g[l][r]: [l,r] 内所有子数组的最大分数
        vector<vector<int>> f(n, vector<int>(n)), g(n, vector<int>(n));
        for (int l = n - 1; l >= 0; l--) {          // l 倒序：先备好第 l+1 行
            f[l][l] = g[l][l] = nums[l];
            for (int r = l + 1; r < n; r++) {       // r 正序：先备好左邻
                f[l][r] = f[l][r - 1] ^ f[l + 1][r];
                g[l][r] = max({g[l][r - 1], g[l + 1][r], f[l][r]});
            }
        }
        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            ans.push_back(g[q[0]][q[1]]);           // 查询 O(1) 读表
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumSubarrayXor(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        n = len(nums)
        f = [[0] * n for _ in range(n)]   # f[l][r]: nums[l..r] 的异或分数
        g = [[0] * n for _ in range(n)]   # g[l][r]: [l,r] 内所有子数组的最大分数
        for l in range(n - 1, -1, -1):    # l 倒序：先备好第 l+1 行
            fl, gl = f[l], g[l]           # 绑定行引用，避免循环内反复二次寻址
            fl[l] = gl[l] = nums[l]
            if l + 1 < n:
                fl1, gl1 = f[l + 1], g[l + 1]
                for r in range(l + 1, n):  # r 正序：先备好左邻
                    fl[r] = fl[r - 1] ^ fl1[r]
                    gl[r] = max(gl[r - 1], gl1[r], fl[r])
        return [g[l][r] for l, r in queries]
```

## 8. 边界情况与易错点

1. **单元素查询（$l = r$）**：答案就是 $\text{nums}[l]$，「任意子数组」包括长度 1 的；对角线初始化 $f[l][l] = g[l][l] = \text{nums}[l]$ 别漏。
2. **循环顺序写反**：$l$ 正序会在算 $f[l][r]$ 时引用尚未计算的 $f[l+1][\cdot]$；$r$ 倒序会引用尚未计算的 $f[l][r-1]$。正确方向是 **$l$ 从大到小、$r$ 从小到大**（或等价地按区间长度枚举）。
3. **max 的三项缺一不可**：漏掉 $f[l][r]$ 会答错「最优恰为整段」的查询（如示例 1 的 $[1,4]$ 就是整段最优）；漏掉 $g[l][r-1]$ 或 $g[l+1][r]$ 会丢失贴边界的子数组。C++ 记得用 `max({...})` 三元形式。
4. **别把 $f$ 表当答案表**：$f[l][r]$ 只是「区间本身」的分数，示例 1 第三个查询 $[0,5]$ 的答案是 60 而非 $f[0][5] = 27$——最大值来自内部子数组，必须经 $g$ 递推。
5. **溢出误区**：异或不产生进位与新高位，全程值 $\le 2^{31} - 1$，`int` 恰好够用；以为「数越来越大」而换 `long long` 没有必要（当然用了也不错）。
6. **查询无需排序去重**：$q$ 个查询可能大量重复或嵌套，直接逐一 $O(1)$ 读表即可，任何预处理都是多余的。
7. **Python 性能**：双重循环约 $2 \times 10^6$ 次纯 Python 迭代，务必像参考代码那样把 `f[l]`、`f[l+1]` 提前绑定成局部变量；若内存吃紧，改用按 $l$ 滚动数组 + 查询离线分组（§4 第 5 点），转移完全一致。
8. **调试技巧**：打印小数组（如 $[2,8,4,32,16,1]$）的整座异或三角，逐格与 $f$ 表核对——「斜层」$m$ 应当等于折叠 $m$ 次后的窗口内容。

**延伸思考**：

- **Lucas 定理视角**：由引理 2，$f[l][r]$ 只异或那些偏移 $k$ 满足 $\binom{m}{k}$ 为奇数的元素；而 $\binom{m}{k}$ 为奇 $\iff$ $k$ 与 $m - k$ 相加无进位 $\iff$ $k$ 的二进制是 $m$ 的子掩码。例如 $m = 3$（`11`）时四个元素全部参与，$m = 2$（`10`）时只有两端参与。若 $n$ 增大到 $10^5$，$O(n^2)$ 表不可行，就得围绕这个子掩码结构做按位统计——这是本题的深水区，$q$ 大 $n$ 小的设定正是对 $O(n^2 + q)$ 做法的友好放行。
- **动态修改**：若题目允许「修改 $\text{nums}$ 再查询」，$f$ 依赖区间整段结构、单点修改会波及 $O(n^2)$ 个表项，朴素表结构无法支持高效更新；需要面向位的其它数据结构才能继续。
