# LeetCode 重新排列数组 题解

## 1. 题目概述

- **标题 / 题号**：重新排列数组（#1470，easy）
- **链接**：https://leetcode.cn/problems/shuffle-the-array/
- **来源**：LeetCode 第 192 场周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：`nums` 的长度为 $2n$，前半段是 $x_1,x_2,\dots,x_n$，后半段是 $y_1,y_2,\dots,y_n$。要求把它重排成交错形式

$$[x_1,y_1,x_2,y_2,\dots,x_n,y_n]$$

也就是把「两段」按对抽出来，交织成「一条」序列。元素的值不参与任何比较、求和或取模，整个过程只是**按下标搬运**。

**约束**：

- $1 \le n \le 500$，且 $\text{nums.length} = 2n$
- $1 \le \text{nums}[i] \le 10^{3}$

> 💡 Q1 签到题的价值不在难度，而在它给出的模板：**输出下标是输入下标的仿射函数**。本题是 $2i \leftrightarrow i$、$2i+1 \leftrightarrow n+i$，看穿之后代码只有三行；同样的「下标映射」在完美洗牌、矩阵按行展开、多路归并的落位上反复出现。

## 2. 示例

**示例 1**

```text
输入：nums = [2,5,1,3,4,7]，n = 3
输出：[2,3,5,4,1,7]
解释：x1=2, x2=5, x3=1；y1=3, y2=4, y3=7，
      交替排列即 [x1,y1,x2,y2,x3,y3] = [2,3,5,4,1,7]。
```

**示例 2**

```text
输入：nums = [1,2,3,4,4,3,2,1]，n = 4
输出：[1,4,2,3,3,2,4,1]
解释：x = [1,2,3,4]，y = [4,3,2,1]，
      逐对交错得 [1,4,2,3,3,2,4,1]。
```

**示例 3**

```text
输入：nums = [1,1,2,2]，n = 2
输出：[1,2,1,2]
解释：x = [1,1]，y = [2,2]，值有重复但下标不同，
      答案按位置逐对给出 [1,2,1,2]。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的两种写法：

- **拆成两半再合并**：取 `x = nums[0:n]`、`y = nums[n:2n]`，再用一个循环把两者交替 `append` 进答案。时间是 $O(n)$，但要额外开两个长度 $n$ 的临时数组，加上答案共三份空间。
- **真的「原地插」**：反复把后半段的元素逐个插到前面（或反复 `insert`/`erase`）。每次插入都要把后面的元素整体后移，单次 $O(n)$，总计 $O(n^2)$。$n = 500$ 时约 $1.25\times10^{5}$ 次搬移，勉强能过，但完全没有必要。

两种写法都没有「读懂」题目：输出结构与输入下标之间存在一一对应，不需要中间容器，也不需要任何搬移。

### 3.2 核心观察：输出下标是输入下标的仿射函数

![输入数组与输出数组之间的下标映射](images/wc192_q1_index_mapping.svg)

设 $0 \le i < n$。输出的第 $i$ **对**是 $(x_{i+1}, y_{i+1})$，它们落在输出的下标 $2i$ 与 $2i+1$；而 $x_{i+1}$ 在输入里的下标是 $i$，$y_{i+1}$ 在输入里的下标是 $n+i$。于是得到两条公式：

$$\text{res}[2i] = \text{nums}[i], \qquad \text{res}[2i+1] = \text{nums}[n+i]$$

两式合起来恰好覆盖输出全部 $2n$ 个位置，也恰好把输入全部 $2n$ 个元素各用一次。所以**一趟循环、两个赋值**就够，不需要排序、不需要临时数组（除答案本身）。

这个观察可以推广：把 $k$ 段长度为 $n$ 的序列交错（$k$ 路洗牌），落位公式是

$$\text{res}[k\cdot i + j] = \text{nums}[j\cdot n + i] \qquad (0 \le i < n,\ 0 \le j < k)$$

$k=2$ 时退化为本题的两条公式。

也可以用**双指针**描述同一件事：指针 $p$ 从 $0$ 出发、$q$ 从 $n$ 出发，每轮交替取 `nums[p]` 与 `nums[q]` 并各前进一格——这正是官方提示的写法，与下标公式完全等价。

### 3.3 算法流程

![算法流程：一次遍历、每轮成对写入](images/wc192_q1_algorithm_flow.svg)

1. 新建长度 $2n$ 的答案数组 `res`；
2. 令 `i` 从 $0$ 递增到 $n-1$：
   - `res[2*i] = nums[i]`，取出 $x_{i+1}$ 放到偶数位；
   - `res[2*i+1] = nums[n+i]`，取出 $y_{i+1}$ 放到奇数位；
3. 返回 `res`。

两次写入的下标一奇一偶，**互不覆盖、互不依赖**，因此两行赋值的先后顺序随意，写成一行合并也可以。

### 3.4 示例演算

以示例 1 `nums = [2,5,1,3,4,7]`、`n = 3` 为例：

![示例演算：i = 0,1,2 逐对落位](images/wc192_q1_walkthrough.svg)

| $i$ | $\text{nums}[i]$ | $\text{nums}[n+i]$ | 写入 $\text{res}[2i]$ | 写入 $\text{res}[2i+1]$ | 此时 `res` |
|-----|------------------|--------------------|------------------------|--------------------------|------------|
| 0 | 2 | 3 | 2 | 3 | [2,3,_,_,_,_] |
| 1 | 5 | 4 | 5 | 4 | [2,3,5,4,_,_] |
| 2 | 1 | 7 | 1 | 7 | [2,3,5,4,1,7] |

$i$ 走完 $0\sim n-1$ 时，$2i$ 扫过 $0,2,\dots,2n-2$，$2i+1$ 扫过 $1,3,\dots,2n-1$，两组并起来正好是全部 $2n$ 个位置，不多不少。

## 4. 算法细节

1. **预分配优于追加**：C++ 写 `vector<int> res(2 * n);` 直接按下标写，不会出现长度错位；若用 `reserve` + `push_back`，则必须保证压入顺序与最终顺序一致（要么先 x 后 y 再交错，要么严格交替），容易写错。
2. **不要写回 `nums`**：`nums[i]` 与 `nums[n+i]` 在后续轮次还要被读，把结果写回原数组时，若 $2i < n$ 就会覆盖尚未读取的 $x$ 元素（$n = 3$、$i = 0$ 时 `nums[1]` 被覆盖），所以必须新开数组。
3. **双指针的两个初值**：`p = 0`、`q = n`。$q$ 的初值是 $n$ 而不是 $n+1$：题面里 $y_1$ 正是下标 $n$。
4. **Python 一行写法**：`[v for pair in zip(nums[:n], nums[n:]) for v in pair]`，或 `list(chain.from_iterable(zip(x, y)))`；两个切片各产生一个长度 $n$ 的副本，若强调空间就用下标循环。
5. **值不参与运算**：不比较、不取模、不求和，因此值域 $10^3$ 与正负号都不影响正确性，也不存在溢出问题；即使把 $\text{nums}[i]$ 放大到 $10^{9}$，这段代码依然原样正确。
6. **返回的是新数组**：题目按返回值判题，修改 `nums` 本身不产生任何效果（LeetCode 只比较返回的数组）。
7. **复杂度已达下界**：答案有 $2n$ 个元素，任何算法至少要写 $2n$ 次，$O(n)$ 就是最优，不存在更快的做法。

## 5. 正确性证明

**引理 1（下标双射）**：映射 $i \mapsto 2i$ 与 $i \mapsto 2i+1$（$0 \le i < n$）合起来是集合 $\{0,1,\dots,2n-1\}$ 的一个排列。

**证明**：偶映射的值域是偶下标集 $\{0,2,\dots,2n-2\}$，奇映射的值域是奇下标集 $\{1,3,\dots,2n-1\}$，两者不相交且并集恰为全体 $2n$ 个下标；在每个映射自己的定义域上，$2i$ 与 $2i+1$ 都随 $i$ 严格单调，故各为单射。∎

**引理 2（写入的值正确）**：对每个 $i$，循环第 $i$ 轮写下的两个值满足 $\text{res}[2i] = x_{i+1}$、$\text{res}[2i+1] = y_{i+1}$。

**证明**：由题意，前缀段满足 $\text{nums}[i] = x_{i+1}$，后缀段满足 $\text{nums}[n+i] = y_{i+1}$（$y$ 的第 $i+1$ 个元素位于下标 $n+i$）。代码把这两个位置上的值原样读出并写到指定下标，中间没有任何修改或运算。∎

**引理 3（不互相覆盖）**：任意两轮写入的目标下标互不相同。

**证明**：由引理 1，全部 $2n$ 次写入的目标下标恰好遍历 $\{0,\dots,2n-1\}$ 各一次，故不存在两个写入落在同一下标。∎

**定理**：算法返回的数组恰为 $[x_1,y_1,x_2,y_2,\dots,x_n,y_n]$。

**证明**：由引理 3，循环结束时 `res` 的每个位置都被写入且只被写入一次，因此每个位置存的都是最终值。由引理 2，位置 $2i$ 上是 $x_{i+1}$、位置 $2i+1$ 上是 $y_{i+1}$。把 $i = 0,1,\dots,n-1$ 依次拼接，得到 $[x_1,y_1,x_2,y_2,\dots,x_n,y_n]$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。循环 $n$ 轮，每轮两次读、两次写，共 $4n$ 次基本操作，是 $\Theta(n)$；下界为 $\Omega(n)$（必须写出 $2n$ 个元素），故已达最优。
- **空间复杂度**：$O(n)$，且这部分空间全部来自返回值（长度 $2n$ 的答案数组）。除输出之外的辅助空间是 $O(1)$：只有循环变量 `i` 与几个下标表达式。
- **对比**：「拆两半再合并」多出 $2n$ 个元素的临时副本，辅助空间 $O(n)$；「原地插入」是 $O(n^2)$ 时间。下标公式写法在时间和空间上都是最优的。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> shuffle(vector<int>& nums, int n) {
        vector<int> res(2 * n);              // 预分配 2n 个位置
        for (int i = 0; i < n; ++i) {
            res[2 * i]     = nums[i];        // 偶数位：x[i+1]
            res[2 * i + 1] = nums[n + i];    // 奇数位：y[i+1]
        }
        return res;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def shuffle(self, nums: List[int], n: int) -> List[int]:
        res = [0] * (2 * n)                  # 预分配，避免追加顺序出错
        for i in range(n):
            res[2 * i] = nums[i]             # 偶数位：x_{i+1}
            res[2 * i + 1] = nums[n + i]     # 奇数位：y_{i+1}
        return res
```

## 8. 边界情况与易错点

1. **$n = 1$**：循环只跑一轮，返回 `[nums[0], nums[1]]`，不要画蛇添足地加 `if (n == 1) return nums;`。
2. **$q$ 的初值写成 $n+1$**：官方提示说的是「第 $n+1$ 个位置」，那是**从 1 开始计数**的说法，等价于下标 $n$；写成 `n + 1` 会漏掉 $y_1$ 并越界。
3. **原地覆盖**：把结果写回 `nums` 时，$2i < n$ 会踩坏还没读的 $x$ 元素。除非改成「循环节置换」（见延伸思考），否则必须新开数组。
4. **有重复元素时不要比「值」**：示例 3 里 $x$ 与 $y$ 都有重复值，正确性靠的是**下标来源**，不是数值；调试时应打印下标而非值来核对。
5. **长度必须为 $2n$**：用 `push_back` 时若循环次数写错，数组会静默变短，LeetCode 报的是「输出长度不符」而不是答案错误，容易误判成逻辑问题。
6. **切片语义**：Python 的 `nums[:n]` 是副本，安全；Java 的 `Arrays.copyOfRange` 同理；C++ 若用迭代器区间构造 `vector`，注意别让源和目标是同一块内存。

- [完美洗牌（perfect shuffle）](https://en.wikipedia.org/wiki/Faro_shuffle)：本题就是一次完美的「交错洗牌」，$n=26$（一副 52 张牌）时对应把一副牌对半切开再交错。

**延伸思考（$O(1)$ 辅助空间的原地交错）**：本题的下标映射

$$f(i) = \begin{cases} 2i, & 0 \le i < n \\ 2(i-n)+1, & n \le i < 2n \end{cases}$$

是 $\{0,\dots,2n-1\}$ 上的置换，可以分解成若干循环节，按循环节逐个搬移即可原地完成，额外空间只需要「访问标记」。由于 $\text{nums}[i] \le 10^{3} < 2^{10}$，第 $10$ 位（值 $1024$）天然空闲，可以借它当标记位：

```python
def shuffle_inplace(nums, n):
    m = 2 * n
    def nxt(i):                        # 下标 i 的元素最终要去的位置
        return 2 * i if i < n else 2 * (i - n) + 1
    for s in range(m):
        if nums[s] & 1024:             # 该位置已就位
            continue
        cur, carry = s, nums[s] & 1023
        while True:
            j = nxt(cur)
            nums[j], carry = carry, nums[j] & 1023   # 搬过去，换出原值
            nums[j] |= 1024                          # 标记 j 已就位
            cur = j
            if cur == s:               # 回到起点，循环节闭合
                break
    for i in range(m):
        nums[i] &= 1023                # 清掉标记位
    return nums
```

时间仍是 $O(n)$（每个下标只被搬一次），辅助空间 $O(1)$。代价是**依赖值域**：若值域未知，就得用 $O(n)$ 的 visited 数组，或改用基于旋转/分治的完美洗牌算法（见 [189. 轮转数组](https://leetcode.cn/problems/rotate-array/) 的三次反转思想）。这也说明「下标映射」不仅能写短代码，还能把 $O(n)$ 空间压到 $O(1)$。
