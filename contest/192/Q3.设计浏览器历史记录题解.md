# LeetCode 设计浏览器历史记录 题解

## 1. 题目概述

- **标题 / 题号**：设计浏览器历史记录（#1472，medium）
- **链接**：https://leetcode.cn/problems/design-browser-history/
- **来源**：LeetCode 第 192 场周赛 Q3
- **难度**：中等
- **标签**：栈、设计、数组、链表、数据流、双向链表

**题意**：实现一个只支持**单个标签页**的浏览器。初始页面是 `homepage`；`visit(url)` 从当前页跳到 `url`，并把**当前页之后的全部前进记录作废**；`back(steps)` / `forward(steps)` 在历史中后退 / 前进**至多** `steps` 步（步数不够就走到端点为止），返回落地页的 `url`。

**约束**：

- $1 \le \lvert \text{homepage} \rvert \le 20$，$1 \le \lvert \text{url} \rvert \le 20$
- $1 \le \text{steps} \le 100$
- `homepage` 与 `url` 只含 `.` 和小写英文字母
- 最多调用 $5000$ 次 `visit`、`back`、`forward`

## 2. 示例

**示例 1**

```text
输入：
["BrowserHistory","visit","visit","visit","back","back","forward","visit","forward","back","back"]
[["leetcode.com"],["google.com"],["facebook.com"],["youtube.com"],[1],[1],[1],["linkedin.com"],[2],[2],[7]]
输出：
[null,null,null,null,"facebook.com","google.com","facebook.com",null,"linkedin.com","google.com","leetcode.com"]
解释：依次访问 google → facebook → youtube，此时历史为
      [leetcode, google, facebook, youtube]，当前页 youtube；
      back(1) → facebook；back(1) → google；forward(1) → facebook；
      visit(linkedin) 把 youtube 这条前进记录作废，历史变成
      [leetcode, google, facebook, linkedin]；
      forward(2) 无路可走，仍返回 linkedin；
      back(2) → google；back(7) 只能退到端点 → leetcode。
```

```text
      此后 forward 已无记录，永远返回 d.com。
```

## 3. 解题思路

### 3.1 暴力思路

题目提示给了「双栈」写法：一个栈存后退历史，一个栈存前进历史。`visit` 把页面压入后退栈并清空前进栈；`back(steps)` 把页面逐页从后退栈搬到前进栈；`forward` 反向搬。它是**正确**的，但有两个问题：

1. 每次 `back` / `forward` 要搬 `steps` 次，单次最坏 $O(\text{steps})$，而两个栈的状态必须时刻同步，`visit` 里漏掉一次清空就会出错；
2. 语感上把「历史内容」和「当前位置」两件事混在了一起，`back` 居然在**修改数据**。

另一种朴素写法是用 `vector` 在中间 `insert` / `erase` 新页面，单次 $O(n)$。$5000$ 次调用下 $n \le 5001$，其实也能过，但它同样把「写到哪」和「站在哪」耦合在一个下标里。

### 3.2 核心观察：历史是一条链，位置只是一个下标

![历史数组与当前指针](images/wc192_q3_history_array_model.svg)

把所有页面按访问顺序排成**一条线性链**，再额外记一个下标 `cur` 指向当前页。于是三种操作变成：

- `visit(url)`：`cur` 之后的一切都失效（它们本来就不该再被前进到），新页面接在 `cur + 1` 上；
- `back(steps)`：`cur` 往左平移，撞到 0 就停；
- `forward(steps)`：`cur` 往右平移，撞到 `n - 1` 就停。

关键点在于：**前进记录不需要单独维护**。它天然就是「`cur` 右边还剩下的那一段」，而 `visit` 只要把这截尾巴砍掉即可。双栈里那套「搬来搬去」的记账工作，被一个下标完全取代。

### 3.3 算法流程

![三种操作的实现](images/wc192_q3_ops_flow.svg)

维护 `vector<string> hist` 与下标 `cur`（`n = hist.size()`）：

- `visit(url)`：先用 `hist.resize(cur + 1)` 把 `cur` 之后的尾巴一次性砍掉，再 `push_back(url)`，最后 `cur = hist.size() - 1`；
- `back(steps)`：`cur = max(0, cur - steps)`，返回 `hist[cur]`；
- `forward(steps)`：`cur = min(n - 1, cur + steps)`，返回 `hist[cur]`。

三个操作的返回值都只是 `hist[cur]` 的一次下标访问，没有任何循环。

### 3.4 示例演算

![官方示例走查](images/wc192_q3_walkthrough.svg)

对示例 1 的 11 步操作：`visit` 连续三次把 `cur` 推到 3，历史长度为 4；`back(1)` 两次把 `cur` 拉回 1；`forward(1)` 又推到 2；此时 `visit("linkedin.com")` 执行 `resize(cur + 1) = resize(3)`，`youtube.com` 被丢弃，`linkedin.com` 落在下标 3，长度回到 4；之后 `forward(2)` 因为 `cur` 已在末尾而原地返回，`back(2)`、`back(7)` 分别落在下标 1 和 0。整条链上 `cur` 始终满足 $0 \le \text{cur} \le n - 1$。

## 4. 算法细节

1. **用 `resize` 而不是逐个 `pop_back`**：`hist.resize(cur + 1)` 一条语句就完成截断，被丢弃的那段元素一次性析构（每个元素至多被丢弃一次，均摊到每次 `visit` 仍是 $O(1)$）；写成 `while (hist.size() > cur + 1) hist.pop_back();` 虽然也对，但把「一步到位」写成了显式循环，且更容易手滑漏掉边界。
2. **`visit` 末尾必须重设 `cur`**：`cur = (int)hist.size() - 1`。如果沿用旧值，`cur` 指向的就是刚被丢弃的旧页面，`forward` 会越过新页面；先加 1 再截断也是错的，那样尾巴根本没被砍掉。
3. **夹取而非循环**：`back` 用 `max(0, cur - steps)`，`forward` 用 `min(n - 1, cur + steps)`。两处 `steps` 都是正的，所以「步数不够就走到底」被一个 `max` / `min` 精确表达，避免 $O(\text{steps})$ 的循环。
4. **严格 $O(1)$ 的变体**：如果不想承担 `resize` 的析构开销，可以额外维护逻辑长度 `cnt`：`visit` 时先 `cur += 1`，若 `cur < hist.size()` 就直接**覆盖** `hist[cur]`、否则 `push_back`，再令 `cnt = cur + 1`，边界全部改用 `cnt`。两种写法都正确，本文采用 `resize` 版，因为代码最短、语义最直白。
5. **不要换成 `list` / `deque`**：链表的中间插入虽然是 $O(1)$，但要先走 `steps` 步才能定位，`back` / `forward` 反而退化成 $O(\text{steps})$；这里最需要的是**随机访问**，数组才是最优结构。
6. **容量与内存**：`resize` 只改 `size` 不释放 `capacity`，所以被砍掉的槽位会被下一次 `push_back` 复用，最多 $5001$ 个 `string`，每个 $\le 20$ 字节，内存可忽略。
7. **接口签名按 `metaData`**：构造函数接收 `string homepage`，`visit` 返回 `void`，`back` / `forward` 返回 `string`；C++ 里 `hist.size()` 是 `size_t`，与 `int` 比较前要转换，避免负数下标的隐式无符号提升。

## 5. 正确性证明

**引理 1（结构不变量）**：任意时刻，`hist[0..n)` 恰好是从 `homepage` 到当前页的完整访问序列（已被丢弃的分支不在其中），且 `cur` 指向当前页，$0 \le \text{cur} < n$。

**证明**：初始时 `hist = [homepage]`、`cur = 0`，成立。
`visit(url)`：由归纳假设，当前页是 `hist[cur]`，新历史应为旧前缀 `hist[0..cur]` 接上 `url`。`resize(cur + 1)` 后数组恰为 `hist[0..cur]`，`push_back(url)` 接在其后，`cur` 更新为末位，成立。
`back` / `forward` 只修改 `cur`，不改动 `hist` 的内容；夹取公式保证新 `cur` 落在 $[0, n-1]$ 内，成立。∎

**引理 2（步数语义）**：`back(s)` 返回的页面，等于「从当前页沿历史后退 $\min(s, \text{cur})$ 步」的页面；`forward(s)` 返回的页面，等于「前进 $\min(s,\ n - 1 - \text{cur})$ 步」的页面。

**证明**：由引理 1，下标减 1 恰好对应沿历史后退一页，故最多能退 `cur` 步；夹取结果为 $\max(0, \text{cur} - s) = \text{cur} - \min(s, \text{cur})$，正是退 $\min(s,\text{cur})$ 步后的下标。前进同理，最多能进 $n - 1 - \text{cur}$ 步，$\min(n-1, \text{cur}+s)$ 即 $\text{cur} + \min(s, n-1-\text{cur})$。∎

**定理**：上述实现的行为与题面描述的浏览器历史语义完全一致。

**证明**：题面的全部接口只有构造函数与 `visit` / `back` / `forward` 三个方法。构造函数由引理 1 的初始情形保证；`visit` 的「删除前进记录并追加新页面」由引理 1 的归纳步保证；`back` / `forward` 的「至多 `steps` 步、不足则到端点、返回落地页」由引理 2 保证。三者合起来覆盖全部调用序列，故实现正确。∎

## 6. 复杂度分析

- **时间**：`visit` 均摊 $O(1)$ —— `resize` 截断时析构的元素总数不超过此前 `push_back` 过的元素总数，均摊到每次访问是常数；`back` / `forward` 严格 $O(1)$。设总调用次数为 $m \le 5000$，总时间 $O(m)$。
- **空间**：$O(m)$ 个 `string`，最坏 $5001 \times 20$ 字节量级；每次 `visit` 最多新增 1 个元素，`cur` 与 `capacity` 只是常数。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
using namespace std;

class BrowserHistory {
public:
    vector<string> hist;
    int cur;

    BrowserHistory(string homepage) {
        hist.push_back(homepage);
        cur = 0;
    }

    void visit(string url) {
        hist.resize(cur + 1);          // 丢弃 cur 之后的全部前进记录
        hist.push_back(url);
        cur = (int)hist.size() - 1;
    }

    string back(int steps) {
        cur = max(0, cur - steps);     // 步数不够就停在 0 号位置
        return hist[cur];
    }

    string forward(int steps) {
        cur = min((int)hist.size() - 1, cur + steps);
        return hist[cur];
    }
};
```

### Python

```python
class BrowserHistory:

    def __init__(self, homepage: str):
        self.hist = [homepage]
        self.cur = 0

    def visit(self, url: str) -> None:
        del self.hist[self.cur + 1:]   # 丢弃全部前进记录
        self.hist.append(url)
        self.cur = len(self.hist) - 1

    def back(self, steps: int) -> str:
        self.cur = max(0, self.cur - steps)
        return self.hist[self.cur]

    def forward(self, steps: int) -> str:
        self.cur = min(len(self.hist) - 1, self.cur + steps)
        return self.hist[self.cur]
```

## 8. 边界情况与易错点

1. **历史只有一页**：`back(100)` 与 `forward(100)` 都必须返回 `homepage`，且不能越界；`max(0, ...)` / `min(n-1, ...)` 天然覆盖，若手写循环要小心 `cur` 变负。
2. **`steps` 远大于历史长度**：`steps` 最大 100 而历史可能只有 1 页，夹取公式一步到位；若改用循环，注意不能让 `cur` 下溢——把 `cur -= steps` 作用在 `size_t` 上会绕成极大值，C++ 里 `cur` 要用有符号 `int`。
3. **后退之后再 `visit`**：这是最容易忘的一步，`resize(cur + 1)` 必须写在 `push_back` **之前**，否则新页面会接在旧尾巴后面，旧的前进记录复活。
4. **`visit` 后忘记复位 `cur`**：只写 `push_back` 不更新 `cur`，下一次 `back` 会从错误位置出发；务必让 `cur` 恒等于末位下标。
5. **前进记录为空时 `forward` 的返回值**：应返回当前页而不是空串；代码里 `min(n-1, ...)` 保证落在端点，返回值仍是合法 `url`。
6. **边界量只能有一个来源**：`resize` 版统一用 `hist.size()`，`cnt` 版统一用 `cnt`；混着写（`visit` 用 `cnt`、`forward` 用 `size()`）在截断之后必然对不上。
7. **`resize` 语义**：`resize(cur + 1)` 在 `cur + 1` 小于当前长度时截断、大于时补默认 `string`；本算法只会在「截断或恰好相等」时调用，所以不会产生空字符串页面。
