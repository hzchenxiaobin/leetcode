# LeetCode 重构字符串 题解

## 1. 题目概述

- **标题 / 题号**：重构字符串（#767，medium）
- **链接**：https://leetcode.cn/problems/reorganize-string/
- **来源**：LeetCode 第 68 场周赛 Q2
- **难度**：中等
- **标签**：贪心、哈希表、字符串、计数、排序、堆（优先队列）

**题意**：给定只含小写字母的字符串 $s$，把它的字符**全部**重新排列，使得任意两个相邻位置的字符都不相同，返回任意一种可行的排列；若不存在这样的排列，返回空字符串 `""`。

**约束**：

- $1 \le \lvert s \rvert \le 500$
- $s$ 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：s = "aab"
输出："aba"
解释：把两个 a 分开放在两端，"aba" 中任意相邻字符都不同。
      "aab"、"baa" 都存在相邻的 a，因此不合法；题目只要求返回任意一个合法答案。
```

**示例 2**

```text
输入：s = "aaab"
输出：""
解释：a 有 3 个而其他字符只有 1 个，任何排列中必有两个 a 相邻，故无解。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $s$ 的所有不同排列，检查相邻字符，返回第一个合法的；无则返回 `""`。排列数是 $\frac{n!}{\prod c_i!}$，$n = 500$ 时是天文学数字，完全不可行。

即使改成回溯 + 剪枝（每层只选与上一位不同的字符），最坏情况仍然会大量回溯——因为「选哪个字符」的顺序会直接影响后面是否死路，只有加上**频次优先**的贪心才能把搜索树压成一条链。

### 3.2 核心观察：可行性的充要条件是 $k \le \lceil n/2 \rceil$

![可行条件：最多字符次数不超过 n 的一半](images/wc68_q2_capacity_bound.svg)

设出现次数最多的字符为 $c$，次数为 $k$。

**上界（鸽巢）**：把 $k$ 个 $c$ 放进最终长度为 $n$ 的串里，它们两两不能相邻，因此相邻两个 $c$ 之间**至少**要夹一个非 $c$ 字符，共需 $k-1$ 个「隔板」；而全部非 $c$ 字符只有 $n-k$ 个。于是可行必须满足

$$k-1 \le n-k \iff 2k \le n+1 \iff k \le \left\lceil \frac{n}{2} \right\rceil$$

**下界（构造）**：只要 $k \le \lceil n/2 \rceil$，就一定能排出来——把出现最多的字符先摆在 $0, 2, 4, \dots$ 这些「隔位」上，它最多占 $\lceil n/2 \rceil$ 个位置；剩下的 $n-k$ 个字符依次填入其它空位即可，空档数 $k-1 \le n-k$ 保证填得满。所以这个上界是**紧的**。

因此算法分成两步：**先用这条判据处理无解**，再用下面的贪心构造在有解时输出一个答案。

### 3.3 算法流程：大顶堆每次取两个最高频的不同字符

![大顶堆配对输出的算法流程](images/wc68_q2_heap_flow.svg)

判据通过后，用一个**大顶堆**维护「(剩余次数, 字符)」，每轮做三件事：

1. 弹出次数最多的两个字符 $x, y$（堆中字符互不相同，故 $x \ne y$）；
2. 先把 $x$ 后把 $y$ 追加到答案末尾；
3. 两者次数各减 1，仍大于 0 的压回堆。

循环到堆中只剩 1 个元素（或为空）为止；若剩 1 个，其次数必为 1，直接追加。

> 💡 为什么不一次只取一个、再补一个「上一个用过的字符」？配对写法更简洁，且**天然保证** $x \ne y$；「不会与上一轮末尾相同」由出堆顺序保证（见 §5 引理 2）。

等价的、不需要堆的构造：把字符按次数**降序**排好，依次填入下标 $0, 2, 4, \dots$，填满后再填 $1, 3, 5, \dots$。同一字符的落点同奇偶、彼此至少隔一格，只要次数降序就同样合法；本文的证明与代码走堆路线，因为它更容易推广到「相同字符至少间隔 $d$」的变体。

### 3.4 示例演算

![示例 "aab" 的堆走查与反例 "aaab"](images/wc68_q2_walkthrough.svg)

对 $s = \texttt{"aab"}$（$n = 3$，$k = 2 \le 2$，判据通过）：

| 轮次 | 堆内容 | 弹出 | 答案 | 回堆 |
|------|--------|------|------|------|
| 初始 | a:2, b:1 | — | `""` | — |
| 第 1 轮 | a:2, b:1 | a, b | `"ab"` | a:1 |
| 第 2 轮 | a:1 | a | `"aba"` | 空 |

最后堆空，答案 `"aba"`，相邻字符两两不同。

对 $s = \texttt{"aaab"}$（$n = 4$，$k = 3 > \lceil 4/2 \rceil = 2$）：判据直接拦下，返回 `""`，不需要进入贪心阶段。

## 4. 算法细节

1. **上界写成整数运算**：`(n + 1) / 2` 就是 $\lceil n/2 \rceil$（向下取整的整数除法），不要写成 `n / 2`——$n = 3, k = 2$ 时 `n/2 = 1` 会误判 `"aab"` 无解。
2. **频次用定长数组**：26 个桶统计，$O(n)$ 时间、$O(1)$ 额外空间，比 `unordered_map` 更快也更稳。
3. **堆元素的设计**：C++ 用 `pair<int,int>` 存 `(次数, 字母下标)`，默认大顶堆先比次数、次数相同比下标，是确定的全序；Python 的 `heapq` 是小顶堆，用 `(-次数, 字符)` 达到同样效果，元组第二维保证同次数时排序确定。
4. **一次取两个而不是取一个**：每轮必弹两个，是因为堆中元素字符互不相同，配对必然合法；若只取一个再想「避开上一个」，反而要额外维护上次输出的字符与次数。
5. **终止条件**：循环写 `while heap.size() > 1`，循环结束后单独处理「剩 1 个」。这个残留元素的次数一定为 1（引理 5 给出的上界），直接追加即可；为健壮性仍可断言 `cnt == 1`。
6. **字符串拼接**：C++ 先 `res.reserve(n)` 再 `push_back`，避免多次扩容；Python 用 `list` 收集后 `"".join`，避免 $O(n^2)$ 的字符串相加。
7. **不重建堆**：每轮只做 2 次弹出、至多 2 次压入，单次 $O(\log 26)$，总代价与 $n$ 同阶，不需要每轮排序。

## 5. 正确性证明

**引理 1（必要性）**：若 $k > \lceil n/2 \rceil$，则不存在合法重排。

**证明**：设出现最多的字符为 $c$，出现了 $k$ 次。在任意排列中，这 $k$ 个 $c$ 占据 $k$ 个位置，且任意两个 $c$ 不能相邻，故相邻两个 $c$ 之间至少有一个非 $c$ 字符，至少需要 $k-1$ 个非 $c$ 字符；而全部非 $c$ 字符只有 $n-k$ 个，因此必须有 $k-1 \le n-k$，即 $2k \le n+1$，亦即 $k \le \lceil n/2 \rceil$。若此式不成立，则无论怎么排都会出现相邻的 $c$。∎

**引理 2（贪心每轮都合法）**：在第 $r$ 轮开始时，若已有答案 $res$ 内部相邻字符互不相同，则本轮追加的两个字符 $x, y$ 满足 $x \ne y$，且 $res$ 非空时 $x$ 不等于 $res$ 的末字符。

**证明**：

- $x \ne y$：堆中每个字符至多出现一次（同一字符只维护一个计数），弹出的是两个不同字符。
- 末字符不同：只需看上一轮。设上一轮弹出的是 $x', y'$（先 $x'$ 后 $y'$，故 $res$ 的末字符是 $y'$）。按堆的全序有 $x' \ge y'$，且两者被**同样地**减 1，相对顺序不变，因此只要 $x'$ 仍有剩余，$x'$ 就排在 $y'$ 前面，堆顶不可能是 $y'$；若 $x'$ 没有剩余（$c_{x'} - 1 = 0$），由 $c_{y'} \le c_{x'}$ 得 $c_{y'} - 1 \le 0$，$y'$ 也不会被压回堆。两种情况都说明本轮弹出的第一个字符 $x$（即堆顶）不等于 $y' = res$ 的末字符。∎

**引理 3（不重不漏）**：算法输出的串长度恰为 $n$，且字符多重集与 $s$ 相同。

**证明**：每轮从堆中取出两个字符、各消耗 1 次，并把剩余次数压回，因此堆中「总次数」每轮恰好减少 2；初始总次数为 $n$，结束时总次数为 $n-2m$（$m$ 为轮数），且这些剩余次数也全部追加到答案中。每次追加都对应原串中的一个字符，且没有字符被凭空创造，故长度与多重集都守恒。∎

**引理 4（判据在剩余实例上保持）**：若当前剩余多重集满足 $k \le \lceil n/2 \rceil$，则每轮弹掉两个不同字符后，新的剩余多重集仍满足同一形式的不等式。

**证明**：设本轮弹出 $x, y$（$x$ 为次数最多者），新规模 $n' = n-2$，需证新最大次数 $k' \le \lceil n/2 \rceil - 1 = \lceil n'/2 \rceil$。对任意字符 $z$：若 $z \in \{x, y\}$，则 $cnt'[z] = cnt[z] - 1 \le k - 1 \le \lceil n/2 \rceil - 1$。若 $z \notin \{x, y\}$，需证 $cnt[z] \le \lceil n/2 \rceil - 1$：$n$ 为奇数时，次数达到 $\lceil n/2 \rceil = (n+1)/2$ 的字符至多一个（两个之和就超过 $n$），而 $x$ 已占据这个名额，故 $cnt[z]$ 更小；$n$ 为偶数时，若 $cnt[z] = n/2$，由 $cnt[x] \ge cnt[z] = n/2$ 可知字符总数已全部由 $x, z$ 两个字符占满，此时 $y$ 只能是 $z$，与 $y \notin \{x,z\}$ 矛盾。故 $k' \le \lceil n'/2 \rceil$。∎

**引理 5（循环停止时残留次数至多为 1）**：循环结束时堆为空，或堆中唯一的元素次数为 1。

**证明**：若循环在最后一轮后停下且堆非空，则最后一轮开始前堆中**恰有 2 个元素**——否则弹出两个后仍剩元素，且至少有一个被压回，堆大小 $\ge 2$，循环不会停。设这两个元素次数为 $c_1 \ge c_2$。循环停止说明这一轮至多压回一个元素，故必有 $c_2 = 1$（若 $c_2 \ge 2$，两个都被压回）。由引理 4，该二元素实例可行，即 $c_1 \le \lceil (c_1+1)/2 \rceil$，解得 $c_1 \le 2$。于是残留次数 $c_1 - 1 \le 1$。∎

**定理（算法正确）**：算法返回的字符串是合法重排；且当且仅当不存在合法重排时返回 `""`。

**证明**：

- 判据不通过时，由引理 1 无解，返回 `""` 正确。
- 判据通过时，引理 2 保证相邻字符两两不同（每轮内部 $x \ne y$，跨轮 $x \ne$ 上一轮末字符，已覆盖全部相邻对），引理 3 保证长度与字符集不重不漏，引理 5 保证末尾残留的单个字符只被追加一次且次数确为 1，故输出是合法重排。
- 判据通过则一定有解（§3.2 的构造说明 $k \le \lceil n/2 \rceil$ 时可行），而算法在判据通过时必能输出，因此不会出现「有解却返回空串」。∎

## 6. 复杂度分析

- **时间**：$O(n)$。统计频次 $O(n)$；建堆 $O(26)$；每轮 2 次弹出 + 至多 2 次压入，单次 $O(\log 26) = O(1)$，最多 $\lceil n/2 \rceil$ 轮，合计 $O(n)$；拼串 $O(n)$。总时间 $O(n)$。
- **空间**：$O(1)$（不计输出）。频次数组与堆都只有 26 个槽位；答案本身占 $O(n)$，属于输出，不计入辅助空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <queue>
#include <utility>
#include <algorithm>
using namespace std;

class Solution {
public:
    string reorganizeString(string s) {
        int n = (int)s.size();
        vector<int> cnt(26, 0);
        for (char c : s) cnt[c - 'a']++;

        int best = 0;
        for (int i = 0; i < 26; i++) best = max(best, cnt[i]);
        if (best > (n + 1) / 2) return "";      // ceil(n/2) 的整数写法

        // 大顶堆：(剩余次数, 字符下标)，次数相同按字符下标排序，保证全序
        priority_queue<pair<int, int>> pq;
        for (int i = 0; i < 26; i++)
            if (cnt[i] > 0) pq.push({cnt[i], i});

        string res;
        res.reserve(n);
        while (pq.size() > 1) {
            auto [c1, a] = pq.top(); pq.pop();
            auto [c2, b] = pq.top(); pq.pop();
            res.push_back(char('a' + a));       // 先追加次数最多的
            res.push_back(char('a' + b));
            if (--c1 > 0) pq.push({c1, a});
            if (--c2 > 0) pq.push({c2, b});
        }
        if (!pq.empty()) {
            auto [c, a] = pq.top();
            if (c > 1) return "";               // 理论上不会触发，防御性保留
            res.push_back(char('a' + a));
        }
        return res;
    }
};
```

### Python

```python
import heapq
from collections import Counter


class Solution:
    def reorganizeString(self, s: str) -> str:
        n = len(s)
        cnt = Counter(s)

        # 可行性判据：出现最多的字符不能超过 ceil(n/2)
        if max(cnt.values()) > (n + 1) // 2:
            return ""

        # 小顶堆存 (-次数, 字符)，等价于按次数降序取字符
        heap = [(-c, ch) for ch, c in cnt.items()]
        heapq.heapify(heap)

        res = []
        while len(heap) > 1:
            c1, ch1 = heapq.heappop(heap)
            c2, ch2 = heapq.heappop(heap)
            res.append(ch1)
            res.append(ch2)
            if c1 + 1 < 0:                      # 负数计数，减 1 后仍有余量
                heapq.heappush(heap, (c1 + 1, ch1))
            if c2 + 1 < 0:
                heapq.heappush(heap, (c2 + 1, ch2))

        if heap:
            c, ch = heap[0]
            if c < -1:                          # 防御性检查
                return ""
            res.append(ch)

        return "".join(res)
```

## 8. 边界情况与易错点

1. **单字符**：`s = "a"`，$1 \le \lceil 1/2 \rceil = 1$，堆中只有一个元素，循环体不执行，直接追加得到 `"a"`。
2. **两个相同字符**：`s = "aa"`，$k = 2 > \lceil 2/2 \rceil = 1$，返回 `""`；不要漏掉这个判据而让堆逻辑自己处理。
3. **上取整写成下取整**：`n / 2` 与 `(n + 1) / 2` 在 $n$ 为奇数时不同。`s = "aab"`（$n = 3$，$k = 2$）用 `n/2` 会误判无解。
4. **残留字符的处理**：循环条件是 `size() > 1`，最后可能剩 1 个字符；它必须被追加，否则答案长度少 1。同时不要把它无条件追加——若其次数大于 1 说明判据或循环写错了。
5. **跨轮相邻的判定**：本轮第一个字符只需要和**上一轮最后追加的字符**比较（也就是上一轮的 $y'$），而不是上一轮的 $x'$；写反了会在 `"aabb"` 这类输入上误判。
6. **Python 的负数计数**：`c1 + 1 < 0` 等价于「减 1 后仍大于 0」，千万别写成 `c1 + 1 <= 0` 的条件取反，否则会丢掉只剩 1 次的字符，导致答案长度不足。
7. **C++ 的结构化绑定**：`auto [c1, a] = pq.top();` 得到的是**拷贝**，随后 `pq.pop()` 不会影响它；若写成引用 `auto &[c1, a]` 再 `pop()`，会读到已销毁的堆顶元素。
8. **不要把无解判据放到循环里**：判据只在开头检查一次，$O(1)$；在循环里反复检查最大频次纯属浪费。
