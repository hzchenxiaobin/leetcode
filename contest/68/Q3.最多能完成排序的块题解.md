# LeetCode 最多能完成排序的块 题解

## 1. 题目概述

- **标题 / 题号**：最多能完成排序的块（#769，medium）
- **链接**：https://leetcode.cn/problems/max-chunks-to-make-sorted/
- **来源**：LeetCode 第 68 场周赛 Q3
- **难度**：中等
- **标签**：数组，栈，贪心，排序，单调栈

**题意**：给定一个长度为 $n$ 的整数数组 `arr`，它是 $[0, n-1]$ 的一个**排列**。把 `arr` 切成若干**连续**的块，每块**内部单独排序**，再按原顺序拼接。要求拼接结果恰好等于升序数组 $[0, 1, \dots, n-1]$，求最多能切出多少块。

**约束**：

- $n = \text{arr.length}$，$1 \le n \le 10$
- $0 \le \text{arr}[i] < n$，且 `arr` 中元素**互不相同**（即 `arr` 是 $0$ 到 $n-1$ 的排列）

> 💡 数据范围只有 $n \le 10$，暴力枚举切法也能过。但本题真正的价值在于：下面这个 $O(n)$ 贪心**完全不依赖 $n \le 10$**，只依赖「排列」这一条性质，可以直接推广到任意长的数组，也是下一题 [768. 最多能完成排序的块 II](https://leetcode.cn/problems/max-chunks-to-make-sorted-ii/)（元素可重复）的起点。

## 2. 示例

**示例 1**

```text
输入：arr = [4,3,2,1,0]
输出：1
解释：
分成 2 块或更多块都无法得到有序结果。
例如 [4,3] + [2,1,0] 各自排序后拼成 [3,4,0,1,2]，不是升序。
只有整串作为一块，排序后恰好是 [0,1,2,3,4]。
```

**示例 2**

```text
输入：arr = [1,0,2,3,4]
输出：4
解释：
切成 [1,0] [2] [3] [4]，各自排序得 [0,1] [2] [3] [4]，拼接即 [0,1,2,3,4]。
注意也可以切成 [1,0] + [2,3,4] 两块，但不是最多的切法。
```

**补充示例**（非官方，用来说明「部分位置切得开、部分切不开」）

```text
输入：arr = [0,2,1,3]
输出：3
解释：
m = [0,2,2,3]：i = 0 对齐（切一刀）、i = 2 对齐（切一刀）、i = 3 对齐（收尾）。
切成 [0] [2,1] [3]，排序拼接得 [0] [1,2] [3] = [0,1,2,3]，共 3 块。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「枚举切法 + 逐块验证」：共有 $2^{n-1}$ 种切 / 不切的选择，对每种选择把每块排序后拼接，与 $[0,1,\dots,n-1]$ 比较，取合法方案中块数最多者。单次验证 $O(n \log n)$，总复杂度 $O(2^{n-1} \cdot n \log n)$。

$n \le 10$ 时完全跑得动（$2^{9} \times 10 \log 10 \approx 1.7 \times 10^4$ 次基本操作），但它**没有用上「排列」这个结构**：一旦 $n$ 变成 $10^5$，暴力立刻崩掉。更糟的是，暴力无法回答「哪些位置**本质上是不能切**的」这个真正的问题。

### 3.2 核心观察：前缀最大值锁住块的右端

![可切位置：前缀最大值 m(i) 恰好等于下标 i](images/wc68_q3_cut_condition.svg)

记 $m(i) = \max(\text{arr}[0..i])$。因为 `arr` 是排列，**值 $v$ 在有序结果里的位置恰好是 $v$**，于是「块内排序」相当于「块内的值就地归位」。

**关键等价**：位置 $i$ 可以作为一个块的右端（即块边界落在 $i$ 与 $i+1$ 之间；$i = n-1$ 表示整串收尾），当且仅当

$$m(i) = i.$$

两个方向都好理解：

- **能切 $\Rightarrow m(i) = i$**：若在这里切，前缀 $[0..i]$ 由若干个完整的块组成。每个块排序后只在自己那一段内落位，所以前缀里装的**值集**必须正好是 $\{0, 1, \dots, i\}$，其最大值当然是 $i$。
- **$m(i) = i \Rightarrow$ 能切**：前缀有 $i+1$ 个互不相同的值，全部 $\le m(i) = i$，而 $0$ 到 $i$ 恰好只有 $i+1$ 个数，于是前缀的值集被「挤满」成了 $\{0, \dots, i\}$——它**自给自足**，砍断后不会牵连右边的元素。

反过来，若 $m(i) > i$，说明前 $i+1$ 个格子里藏着一个「值 $> i$、按有序结果必须去右边」的大数；块内元素只能在块内重排，它跨不过这条边界，所以这条边界**在任何合法划分里都不能出现**。

> 💡 一句话记住：**左侧的最大值追上了下标，左边的数就收齐了。**

### 3.3 算法流程

![贪心扫描流程](images/wc68_q3_greedy_flow.svg)

既然「可切位置」就是「$m(i) = i$ 的位置」，而所有可切位置可以**同时**切（每一段都形如 $[l, r]$，其值集为 $\{0..r\} \setminus \{0..l-1\} = \{l..r\}$，同样自给自足），那么答案就是**可切位置的个数**。注意 $i = n-1$ 只是收尾、不是真正的刀口，所以块数 $=$ 对齐次数，而不是「对齐次数 $+ 1$」：

1. `cur = -1`，`ans = 0`；
2. 从左到右枚举 $i$，`cur = max(cur, arr[i])`；
3. 若 `cur == i`，说明位置 $i$ 可切，`ans += 1`；
4. 扫完返回 `ans`。

整个过程只需维护 `cur` 与 `ans` 两个变量，一次扫描，$O(n)$ 时间、$O(1)$ 空间，连排序都不需要——只是**用贪心模拟了排序的效果**。

**与单调栈的关系**：本题也可以写成 768 的标准姿势「维护一个栈保存各候选块的右端最大值，遇到更小的值就弹栈合并」（已对拍验证）。但在 769 里栈的大小恰好等于「前缀最大值与下标对齐」的次数，而栈顶恰好等于 `cur`——于是整个栈可以直接压掉，只留一个计数器和一个最大值。含重复元素的 768 中这个压掉不成立，因为「前缀最大值 = 下标」不再刻画值集对齐。

### 3.4 示例演算

![两个例子的走查表](images/wc68_q3_walkthrough.svg)

`arr = [1,0,2,3,4]`：`m` 依次为 $1,1,2,3,4$，在 $i = 1,2,3,4$ 处对齐（$i=0$ 时 $m(0)=1 \ne 0$），其中 $i=4$ 是收尾，于是收出 4 块：`[1,0] [2] [3] [4]`。

`arr = [4,3,2,1,0]`：`m` 恒为 $4$，只有 $i = 4$ 处对齐，且这一次就是收尾 → **1 块**。开头那个 $4$ 与末尾那个 $0$ 把整串首尾锁死，中间任何位置切开都会让 $4$ 卡在左边。

| 例子 | `i` 与 `m(i)` 对齐的位置 | 块数 |
|------|--------------------------|------|
| `[1,0,2,3,4]` | 1, 2, 3, 4 | 4 |
| `[0,2,1,3]` | 0, 2, 3 | 3 |
| `[4,3,2,1,0]` | 4 | 1 |

## 4. 算法细节

1. **只用了一条性质**：「排列」保证值 $v$ 的目标下标是 $v$。因此 `arr` 换成任意 $0$ 到 $n-1$ 的排列都成立；含重复值（768）时这条推理失效：前缀的最大值追平下标不再能保证值集对齐，只能改成「前缀最大值 $\le$ 后缀最小值」，即所有左侧元素都不大于所有右侧元素。
2. **`cur` 的初值**：取 $-1$（或 `arr[0]`），保证 $i = 0$ 时比较的是 `arr[0]` 与 $0$。取 $0$ 在本值域下也正确，但 `-1` 的写法对「值域含负数」的变体依然安全。
3. **判定写 `cur == i`**：排列下 `cur` 永远不小于 `i`，所以两者等价；但写 `==` 直接对应「对齐」这一几何含义，读代码的人一眼就懂，也不会在变体中误用。
4. **不需要真的切**：题目只问块数。若要求输出每块长度，在 `cur == i` 时记录长度 `i - prev + 1` 并令 `prev = i + 1` 即可，代价仍是 $O(n)$。
5. **`m(n-1) = n-1` 恒成立**：因为整串的最大值必然是 $n-1$。这保证最后一次对齐一定发生，答案至少为 $1$，循环结束后无需补刀。
6. **前缀和也能判，但不推荐**：对排列而言，$i+1$ 个互异非负整数之和 $\ge 0+1+\dots+i = \frac{i(i+1)}{2}$，等号成立当且仅当集合恰为 $\{0..i\}$，所以「前缀和 $= \frac{i(i+1)}{2}$」同样等价于可切。但前缀和在大 $n$ 下有溢出风险，而且也丢掉了「最大值 = 下标」这个几何直觉，取最大值更稳。
7. **可流式处理**：`cur` 只依赖已读入的前缀，因此支持边读边算、内存 $O(1)$——这是任何「先排序再比对」的写法都做不到的。

## 5. 正确性证明

**引理 1（块合法 $\Rightarrow$ 值集对齐）**：若完整划分合法，则每一块 $[l, r]$ 内的值集恰为 $\{l, l+1, \dots, r\}$。

**证明**：合法意味着「每块内部排序后按原顺序拼接 $=$ 升序数组」。该块排序后占据结果的第 $l$ 到第 $r$ 个位置，而结果是 $[0, 1, \dots, n-1]$，故这些位置上的值恰为 $l, \dots, r$；这些值又只来自该块本身，故块内值集就是 $\{l..r\}$。∎

**引理 2（前缀值集与最大值）**：前缀 $[0..i]$ 的值集为 $\{0..i\}$ $\iff$ $m(i) = i$。

**证明**：

- （$\Rightarrow$）值集是 $\{0..i\}$，最大值为 $i$，即 $m(i) = i$。
- （$\Leftarrow$）前缀含 $i+1$ 个互不相同的值，且每个值 $\le m(i) = i$，即都落在 $\{0..i\}$ 这 $i+1$ 个位置里；由抽屉原理，$i+1$ 个互异值恰好填满它，值集即 $\{0..i\}$。∎

**引理 3（可切位置刻画）**：设 $S = \{i : m(i) = i\}$。则

1. 任何合法划分中，**每一块的右端**都属于 $S$；
2. 把 $S$ 中每个位置都当作块的右端，得到的划分合法。

**证明**：

1. 设某块的右端为 $r$。前缀 $[0..r]$ 是若干个完整块的并，每块的值只在自己块内落位（引理 1），而拼接结果的前 $r+1$ 个位置恰是 $0, \dots, r$，故前缀值集为 $\{0..r\}$，由引理 2 得 $m(r) = r$，即 $r \in S$。
2. 把 $S$ 中元素升序记为 $0 \le i_1 < i_2 < \dots < i_k = n-1$（$n-1 \in S$ 因为 $m(n-1) = n-1$），并令 $i_0 = -1$。第 $j$ 块为 $[i_{j-1}+1,\ i_j]$，由引理 2，前缀 $[0..i_j]$ 的值集为 $\{0..i_j\}$，前缀 $[0..i_{j-1}]$ 的值集为 $\{0..i_{j-1}\}$，两者作差得该块值集为 $\{i_{j-1}+1, \dots, i_j\}$，恰好是它自身占据的下标区间。于是该块排序后每个值都落在原位，逐块成立即整体拼接为升序。∎

**定理**：算法返回的块数等于最大块数，且等于 $|S|$。

**证明**：算法统计的正是满足 `cur == i` 的下标个数，而 `cur` 就是 $m(i)$，故返回 $|S|$。

- **上界**：任取合法划分，其每一块的右端都属于 $S$（引理 3.1），右端互不相同，故块数 $\le |S|$。
- **可达**：把 $S$ 中每个位置都当作右端的划分合法（引理 3.2），块数恰为 $|S|$。

故最大块数为 $|S|$，与算法输出一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。单层循环，每个下标只做一次 `max` 比较与一次相等判断，无嵌套、无排序。
- **空间**：$O(1)$ 额外空间。只有 `cur`、`ans` 与循环变量；输入原地读取，未复制数组。
- **最优性直觉**：答案依赖全局信息——开头的大值会把第一块的右端一路顶到很后面，不读完数组就不知道第一块在哪收尾。故任何正确算法都必须至少把 $n$ 个数读一遍，$\Omega(n)$ 是下界，本算法达到最优。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int maxChunksToSorted(vector<int>& arr) {
        int ans = 0, curMax = -1;                    // curMax = max(arr[0..i])
        for (int i = 0; i < (int)arr.size(); ++i) {
            curMax = max(curMax, arr[i]);
            if (curMax == i) ++ans;                  // 前缀值集恰为 {0..i}，收块
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxChunksToSorted(self, arr: list[int]) -> int:
        ans = 0
        cur = -1                     # 前缀最大值 max(arr[0..i])
        for i, x in enumerate(arr):
            cur = max(cur, x)
            if cur == i:             # 前缀值集恰为 {0..i}，此处可切
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有 $i = 0$，`arr[0] = 0` 时 `cur == i` 成立，返回 $1$；不会出现 $0$ 块。
2. **首元素就是 $0$**：$i = 0$ 立即对齐，第一块长度为 $1$；这正是「能切就切」的体现，不要因为「块太小」而犹豫。
3. **整体降序**：`m` 一开始就被 $n-1$ 顶住，直到 $i = n-1$ 才对上，答案 $1$——此时任何切法都会让大值卡在左侧。
4. **`cur` 初值写错**：若写成 `arr[0]` 却在循环里从 $i = 1$ 开始统计，会漏掉 $i = 0$ 这一刀（`[0,1,2]` 会错答 $2$ 而不是 $3$）。
5. **误用「前缀和」却不加校验**：只比较 `sum(arr[0..i]) == i*(i+1)/2` 在排列下确实等价，但若把它照搬到 768 这类**含重复**的输入上就会失效——`arr = [1,1,1,3]` 的前缀 `[1,1,1]` 和为 $3 = \frac{2 \cdot 3}{2}$，会被误判成可切，而它的值集只是 $\{1\}$。
6. **与 768 混淆**：769 的判定是 `max == i`；768 有重复元素，「目标位置」不再唯一，判据要换成「前缀最大值 $\le$ 后缀最小值」（等价于左侧所有元素 $\le$ 右侧所有元素），仅靠 `max == i` 会多切。
7. **以为「切得越多越好所以要从小块切起」**：块长与最优性无关，唯一的标准是边界是否属于 $S$；所有 $S$ 中的位置都切即可，不存在取舍。

**延伸思考**：

1. **输出每块的内容而不只是块数**：在 `cur == i` 处切一次 `arr[prev..i]`，所有切片总长 $n$，复杂度不变。
2. **块数最少是多少**：恒为 $1$（整串排序必然得到升序），所以问题只有在「最大化」时才有意思；这也说明判定标准必须是**局部自给自足**。
3. **若允许块内任意置换而不仅是排序**：条件不变，因为排序已经是块内能做到的「最规整」的重排，值集对齐后排序必然归位。
4. **若 `arr` 不是排列而是任意互异整数**：先把值离散化（rank），把「值 $v$ 的目标下标是 $v$」换成「rank 的目标下标是 rank 序号」，同一算法照常工作。
5. **在线询问**：支持在数组末尾追加元素并随时询问当前最大块数——因为块数只由前缀最大值决定，追加一个元素只会让最后一个块的右端继续右移，可用一个栈维护「待定块数」，均摊 $O(1)$。
