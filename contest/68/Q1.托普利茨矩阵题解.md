# LeetCode 托普利茨矩阵 题解

## 1. 题目概述

- **标题 / 题号**：托普利茨矩阵（#766，easy）
- **链接**：https://leetcode.cn/problems/toeplitz-matrix/
- **来源**：LeetCode 第 68 场周赛 Q1
- **难度**：简单
- **标签**：数组、矩阵

**题意**：给定 $m \times n$ 的矩阵 `matrix`，如果每一条**从左上到右下**的对角线上的元素都相同，则称它是**托普利茨矩阵**，返回 `true`，否则返回 `false`。

**约束**：

- $m = \text{matrix.length}$，$n = \text{matrix[i].length}$
- $1 \le m, n \le 20$
- $0 \le \text{matrix}[i][j] \le 99$

## 2. 示例

**示例 1**

```text
输入：matrix = [[1,2,3,4],[5,1,2,3],[9,5,1,2]]
输出：true
解释：对角线依次为 [9]、[5,5]、[1,1,1]、[2,2,2]、[3,3]、[4]，
      每条对角线上的元素都相同。
```

**示例 2**

```text
输入：matrix = [[1,2],[2,2]]
输出：false
解释：对角线 [1,2]（即 matrix[0][0] 与 matrix[1][1]）上的元素不同。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**按对角线成组检查**：一条对角线由它的起点唯一确定，起点要么在第 0 行（共 $n$ 个），要么在第 0 列（共 $m$ 个，$[0][0]$ 重复一次），合计 $m+n-1$ 条。枚举每条对角线，记下第一个元素，沿着「行 +1、列 +1」走到底逐个比较。

这种写法本身是 $O(mn)$ 的，但有两个小毛病：

- 需要额外维护「起点从哪来」的两段循环（第 0 行一段、第 0 列一段），代码重复；
- 更容易写错的是「对每个格子都回溯到对角线起点再走一遍」，那样每个格子被访问 $O(\min(i,j))$ 次，最坏退化到 $O(mn\min(m,n))$。

既然「同一条对角线」这个条件在**相邻两格**之间就体现出来了，就没必要绕道去分组。两种朴素写法与最优写法的对比如下：

| 写法 | 时间 | 额外空间 | 说明 |
|---|---|---|---|
| 每格回溯到对角线起点 | $O(mn\min(m,n))$ | $O(1)$ | 同一格被反复比较 |
| 按 $i-j$ 分组进哈希表 | $O(mn)$ | $O(m+n)$ | 通用，但要存全部元素 |
| **相邻格一次扫描** | $O(mn)$ | $O(1)$ | 本题最优，代码最短 |

### 3.2 核心观察：只需比较左上方邻居

![每条左上到右下对角线对应一个固定的 i−j](images/wc68_q1_diagonals.svg)

记 $d = i - j$。格子沿左上→右下方向移动时，$i$ 与 $j$ **同时加 1**，因此 $d$ 保持不变；反过来，$d$ 相同的格子必然落在同一条这样的对角线上。于是

$$(i,j)\ \text{与}\ (i',j')\ \text{同对角线}\iff i-j=i'-j'$$

这样一来，「每条对角线同值」就化归为**只看相邻格**的条件：

$$\forall\, i \ge 1,\ j \ge 1:\quad \text{matrix}[i][j] = \text{matrix}[i-1][j-1]$$

- **必要性**：$(i,j)$ 与 $(i-1,j-1)$ 的 $d$ 都是 $i-j$，属于同一条对角线，由定义二者相等。
- **充分性**：任一格子不断向左上走，每走一步都被上式保证「与左上邻居相等」，最终走到该对角线的起点，一路传递下来就说明整条对角线同值。

换句话说，只要每个格子与它的**左上方邻居**相等，整张矩阵就是托普利茨矩阵。每个格子只被看一次，不需要真的沿对角线走一遍。

### 3.3 算法流程

![一次扫描：每格只和左上方邻居比较](images/wc68_q1_topleft_check.svg)

1. 外层 $i$ 从 $1$ 到 $m-1$，内层 $j$ 从 $1$ 到 $n-1$ 顺序扫描（第 0 行与第 0 列没有左上方邻居，自然跳过）。
2. 若 `matrix[i][j] != matrix[i-1][j-1]`，立即返回 `false`。
3. 所有比较都通过，返回 `true`。

> 💡 换个视角：这等价于把**上一行整体右移一格**后与当前行对齐比较——`prev[0..n-2]` 对 `cur[1..n-1]`。这个视角直接给出题面「进阶」的流式解法。

### 3.4 示例演算

![示例 1 的六次比较走查](images/wc68_q1_walkthrough.svg)

**示例 1**（$m=3,n=4$）共 $(m-1)(n-1)=6$ 次比较：$(1,1)\leftarrow(0,0)$ 得 $1=1$、$(1,2)\leftarrow(0,1)$ 得 $2=2$、$(1,3)\leftarrow(0,2)$ 得 $3=3$、$(2,1)\leftarrow(1,0)$ 得 $5=5$、$(2,2)\leftarrow(1,1)$ 得 $1=1$、$(2,3)\leftarrow(1,2)$ 得 $2=2$。六次全部成立，返回 `true`。

**示例 2**（$m=n=2$）只有一次比较：$(1,1)\leftarrow(0,0)$，即 $2$ 与 $1$ 不等，立即返回 `false`。注意失败点是 $(1,1)$ 与 $(0,0)$，而不是同一行里的两个 $2$。

## 4. 算法细节

1. **下标范围**：0-indexed 下循环条件是 $i < m$、$j < n$，不是 $i \le m$；内层从 $j=1$ 起步，才能安全访问 $j-1$。
2. **行列分别取**：$m = \text{matrix.size}()$、$n = \text{matrix}[0].\text{size}()$，不要假设方阵，也不要拿 $m$ 当列数。
3. **防御性判空**：题面保证 $m,n \ge 1$，但工程代码里 `matrix[0]` 前应判 `matrix.empty()`（以及 `matrix[0].empty()`），否则空输入直接崩溃。
4. **提前返回**：一旦发现不等就 `return false`，反例矩阵往往在前几行就被拦下，实测远快于跑满 $(m-1)(n-1)$ 次比较。
5. **不加辅助结构**：本题可以做到 $O(1)$ 额外空间，不要为了「看起来清晰」去转置矩阵、复制矩阵或建 `i-j` 的哈希表（那是 $O(m+n)$ 空间）。
6. **类型选择**：元素范围 $0 \sim 99$，`int` 直接比较即可，没有溢出、也没有浮点误差问题，不需要 `long long`。
7. **C++ 传参用引用**：`vector<vector<int>>& matrix`，避免整矩阵拷贝——拷贝本身就是 $O(mn)$ 的时间和空间。

## 5. 正确性证明

**引理 1（必要条件）**：若 `matrix` 是托普利茨矩阵，则对所有 $i \ge 1,\ j \ge 1$ 都有 $\text{matrix}[i][j] = \text{matrix}[i-1][j-1]$。

**证明**：$(i,j)$ 与 $(i-1,j-1)$ 的 $i-j$ 取值相同，故二者位于同一条左上到右下的对角线上。由托普利茨矩阵的定义，同一条对角线上任意两元素相等，所以二者相等。∎

**引理 2（对角线内传递）**：若对所有 $i \ge 1,\ j \ge 1$ 都有 $\text{matrix}[i][j] = \text{matrix}[i-1][j-1]$，则同一条对角线（即 $i-j$ 相同）上的任意两格相等。

**证明**：取同对角线上两格 $(i,j)$、$(i',j')$，不妨设 $i \ge i'$，令 $k = i - i' = j - j' \ge 0$。对 $k$ 作归纳：

- $k = 0$：两格重合，结论成立。
- $k \ge 1$：由条件 $\text{matrix}[i][j] = \text{matrix}[i-1][j-1]$，而 $(i-1,j-1)$ 与 $(i',j')$ 的行列差同为 $k-1$，由归纳假设二者相等。由相等关系的传递性得 $\text{matrix}[i][j] = \text{matrix}[i'][j']$。∎

**定理**：算法返回 `true` 当且仅当 `matrix` 是托普利茨矩阵。

**证明**：

- （$\Leftarrow$）若 `matrix` 是托普利茨矩阵，由引理 1，算法检查的每一对相邻格都相等，因此不会在中途返回 `false`，循环结束后返回 `true`。
- （$\Rightarrow$）若算法返回 `true`，说明所有 $i \ge 1,\ j \ge 1$ 的比较都相等，由引理 2，每条左上到右下对角线上的元素两两相等，符合托普利茨矩阵的定义。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个格子至多与它的左上方邻居比较一次，每次比较 $O(1)$；最坏 $(m-1)(n-1) < mn$ 次，提前返回只会更少。判定至少要读完全部 $mn$ 个元素，故 $O(mn)$ 已是下界。
- **空间**：$O(1)$ 额外空间（不计输入矩阵），只有循环变量与若干临时值，无递归、无辅助数组。
- 代入 $m,n \le 20$：最多 $19 \times 19 = 361$ 次比较，任何写法都远低于时限；这里的复杂度分析主要是习惯问题。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool isToeplitzMatrix(vector<vector<int>>& matrix) {
        int m = matrix.size(), n = matrix[0].size();
        for (int i = 1; i < m; ++i)
            for (int j = 1; j < n; ++j)
                if (matrix[i][j] != matrix[i - 1][j - 1])
                    return false;          // 与左上方邻居不同，立即失败
        return true;
    }
};
```

### Python

```python
class Solution:
    def isToeplitzMatrix(self, matrix: list[list[int]]) -> bool:
        m, n = len(matrix), len(matrix[0])
        for i in range(1, m):
            for j in range(1, n):
                if matrix[i][j] != matrix[i - 1][j - 1]:
                    return False           # 与左上方邻居不同，立即失败
        return True
```

> 💡 两份代码均通过 2 组官方示例（`true`、`false`），并与「枚举全部 $m+n-1$ 条对角线、逐条走到底比较」的独立暴力对拍 40 组随机小矩阵（$m,n \le 5$，元素 $0 \sim 3$，含人工构造的托普利茨样本），`mismatch = 0`。

## 8. 边界情况与易错点

1. **单行、单列、$1\times1$**：如 `[[1,2,3]]`、`[[1],[2]]`、`[[5]]`，不存在 $i \ge 1 \wedge j \ge 1$ 的格子，双重循环一次也不执行，直接返回 `true`——每条对角线只有一个元素，必然同值，这是正确的。
2. **方向别搞反**：托普利茨要求「左上→右下」对角线同值，对应 $i-j$ 恒定；若误按 $i+j$ 恒定（右上→左下）去判断，会把反例 `[[1,2],[2,2]]` 判成 `true`。
3. **只比较同一行**：`matrix[i][j]` 要与 `matrix[i-1][j-1]` 比，而不是与 `matrix[i][j-1]` 比；后者是「每行内部单调/相同」的另一种条件。
4. **非方阵**：$m \ne n$ 时行列上界不同（例如 $3\times4$），行列都要用各自的长度，写死一个维度必然越界或漏判。
5. **越界访问**：内层循环从 $j=1$ 开始，外层从 $i=1$ 开始，才能安全取 `i-1`、`j-1`；写成 `j=0` 会访问 `matrix[i][-1]`。
6. **进阶的内存约束**：题面追问「一次只能读一行」时，不能把整个矩阵读进内存，必须滚动保留上一行（$O(n)$ 空间）；见「相关题目与扩展」的延伸思考。

**延伸思考**：题面的两个进阶问题——

1. **一次只能读一整行**：读入第 $i$ 行后，与缓存的上—行比较 `cur[1..n-1]` 与 `prev[0..n-2]`，然后令 `prev = cur`。额外空间 $O(n)$，时间仍是 $O(mn)$。
2. **一次只能读不完整的一行**：按块（行块 × 列块）读入，块内元素与块内左上方邻居比较；每个块的**第一行**（除首列）依赖上一块的最后一列，需缓存 $O(\text{块高})$ 个边界元素，列方向同理。总时间 $O(mn)$，空间 $O(\text{块高} + \text{块宽})$。
