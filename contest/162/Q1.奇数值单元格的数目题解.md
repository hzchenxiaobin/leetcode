# LeetCode 奇数值单元格的数目 题解

## 1. 题目概述

- **标题 / 题号**：奇数值单元格的数目（#1252，easy）
- **链接**：https://leetcode.cn/problems/cells-with-odd-values-in-a-matrix/
- **来源**：LeetCode 第 162 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学、模拟

**题意**：有一个 $m \times n$ 的矩阵，初始全为 $0$。对 `indices` 中的每个二元组 $[r_i, c_i]$，同时把**第 $r_i$ 行**所有格子加 $1$、把**第 $c_i$ 列**所有格子加 $1$（交点处被加了两次，等于加 $2$）。执行完全部操作后，返回矩阵中**值为奇数**的单元格个数。

注意操作是「同时」作用于整行与整列，不是只改一个格子——这是本题最容易读错的地方。

**约束**：

- $1 \le m, n \le 50$
- $1 \le \text{indices.length} \le 100$
- $0 \le r_i < m$，$0 \le c_i < n$
- **进阶**：能否做到 $O(m + n + \lvert\text{indices}\rvert)$ 时间、$O(m + n)$ 额外空间？

## 2. 示例

**示例 1**

```text
输入：m = 2, n = 3, indices = [[0,1],[1,1]]
输出：6
解释：初始 [[0,0,0],[0,0,0]]
      [0,1] → [[1,2,1],[0,1,0]]     （第 0 行 +1，第 1 列 +1）
      [1,1] → [[1,3,1],[1,3,1]]     （第 1 行 +1，第 1 列 +1）
      6 个格子为奇数，答案 6。
```

**示例 2**

```text
输入：m = 2, n = 2, indices = [[1,1],[0,0]]
输出：0
解释：最终矩阵 [[2,2],[2,2]]，全部是偶数。
```

**示例 3（自补，考察同一行/列被多次操作）**

```text
输入：m = 1, n = 1, indices = [[0,0],[0,0]]
输出：0
解释：唯一格子被加 4 次（每次行 1 次 + 列 1 次），为偶数。
```

## 3. 解题思路

### 3.1 暴力思路

老老实实建出 $m \times n$ 矩阵，对每个 $[r_i, c_i]$ 把整行、整列各加 $1$，最后数一遍奇数。

- 时间：$O\bigl(\lvert\text{indices}\rvert \cdot (m + n) + m n\bigr)$；
- 空间：$O(mn)$。

在 $m, n \le 50$、$\lvert\text{indices}\rvert \le 100$ 的数据范围内，这个做法**完全能过**。但它把「每次操作影响一整行 + 一整列」这个强结构浪费了，也回答不了题目的进阶要求。真正的信息量其实只有 $m + n$ 个计数器。

> 💡 签到题的最短路径：先问自己「每个格子的值由什么决定」，而不是「我该怎样模拟」。

### 3.2 核心观察：格子值 = 行增量 + 列增量，奇偶只看异或

![单元格只关心行增量与列增量的奇偶](images/wc162_q1_parity_concept.svg)

设 `rowAdd[i]` 表示第 $i$ 行被加的总次数，`colAdd[j]` 表示第 $j$ 列被加的总次数。那么

$$a[i][j] = \text{rowAdd}[i] + \text{colAdd}[j]$$

因为格子 $(i,j)$ 收到的所有 $+1$ 只来自两类操作：命中第 $i$ 行的操作和命中第 $j$ 列的操作，二者互不重叠地累加。

既然只问奇偶，就把每个数对 $2$ 取模，记 `rowParity[i] = rowAdd[i] mod 2`、`colParity[j] = colAdd[j] mod 2`，则

$$a[i][j] \text{ 为奇数} \iff \text{rowParity}[i] \oplus \text{colParity}[j] = 1$$

也就是「行奇、列偶」或「行偶、列奇」。令 $R$ 为行奇偶为 $1$ 的行数、$C$ 为列奇偶为 $1$ 的列数，两类格子数分别是 $R(n-C)$ 与 $(m-R)C$，两者互斥，直接相加：

$$\text{answer} = R\,(n - C) + (m - R)\,C$$

### 3.3 算法流程

![两趟扫描的算法流程](images/wc162_q1_flow.svg)

1. 开两个数组 `row[m]`、`col[n]`，初值 $0$；
2. 遍历 `indices`，对每个 $[r, c]$ 执行 `row[r] ^= 1`、`col[c] ^= 1`——**加一次就等于翻转一次奇偶**，不必真的累加；
3. 统计 $R = \sum_i \text{row}[i]$、$C = \sum_j \text{col}[j]$；
4. 返回 $R(n-C) + (m-R)C$。

因为中途只保留 $0/1$，第 2 步天然处理了「同一行被操作多次」的抵消问题。

### 3.4 示例演算

![示例 1 的逐步演算与计数器](images/wc162_q1_walkthrough.svg)

对示例 1（$m = 2$，$n = 3$，`indices = [[0,1],[1,1]]`）：

| 步骤 | rowParity | colParity | $R$ | $C$ | $R(n-C)+(m-R)C$ |
|------|-----------|-----------|-----|-----|------------------|
| 初始 | `[0,0]` | `[0,0,0]` | 0 | 0 | 0 |
| 执行 `[0,1]` | `[1,0]` | `[0,1,0]` | 1 | 1 | $1\cdot2 + 1\cdot1 = 3$ |
| 执行 `[1,1]` | `[1,1]` | `[0,0,0]` | 2 | 0 | $2\cdot3 + 0\cdot0 = 6$ |

第 2 行中间那次 $3$ 恰好等于当时矩阵 `[[1,2,1],[0,1,0]]` 里的奇数个数，可以互相印证；最终 $6$ 与逐格模拟一致。

再对示例 2 验算：`[[1,1],[0,0]]` 使两行各被加 $1$ 次、两列也各被加 $1$ 次，故 $R = 2$、$C = 2$，答案 $2(2-2) + (2-2)\cdot 2 = 0$，与题面一致。

## 4. 算法细节

1. **用异或代替加法**：本题只关心模 $2$ 的结果，`x += 1` 与 `x ^= 1` 在只看奇偶时等价，而后者天然不会溢出、语义也直接。
2. **「同时」的含义体现在公式里**：交点 $a[r][c]$ 收到行贡献与列贡献各一次，正好是两个 parity 相加，不需要任何特判；暴力写法里也**不能**把交点只加 $1$。
3. **两块的互斥性**：奇数格被「行奇 / 行偶」这条线切成两类，第一类 $R(n-C)$ 个、第二类 $(m-R)C$ 个，不重不漏，因此可以相加；若把「行奇列奇」也算进去就会重复计数。
4. **不需要知道具体值**：全程没有出现 $a[i][j]$ 的数值，也没有建 $m \times n$ 的矩阵，这是达成进阶要求 $O(m+n)$ 空间的关键。
5. **统计 $R$、$C$ 用一次遍历**：`for (int x : row) R += x;`，因为数组里只有 $0/1$，求和即计数；也可以在第 2 步里边翻转边维护 $R, C$（翻转后由 $0$ 变 $1$ 则 $R{+}{+}$，反之 $R{-}{-}$），这样连最后一遍都不用。
6. **答案范围安全**：$R \le m \le 50$、$C \le n \le 50$，答案不超过 $mn = 2500$，`int` 足够；若把范围放大到 $10^9$ 量级，则需 `long long`，因为 $R(n-C)$ 会到 $10^{18}$。
7. **参数顺序**：接口为 `oddCells(int m, int n, vector<vector<int>>& indices)`，返回 `int`，注意 C++ 中 `indices` 是引用，别写成传值拷贝（虽然不影响正确性，但多一次拷贝）。

## 5. 正确性证明

**引理 1（值的分解）**：全部操作执行完后，对任意 $0 \le i < m$、$0 \le j < n$，有

$$a[i][j] = \text{rowAdd}[i] + \text{colAdd}[j]$$

**证明**：对操作个数 $k$ 归纳。$k = 0$ 时两边都是 $0$。设执行完前 $k$ 个操作后成立，考虑第 $k+1$ 个操作 $[r, c]$：它使所有 $a[r][\cdot]$ 加 $1$、所有 $a[\cdot][c]$ 加 $1$，即 `rowAdd[r]` 与 `colAdd[c]` 各加 $1$。对任意 $(i,j)$，若 $i = r$ 则 $a[i][j]$ 与 `rowAdd[i]` 同步 $+1$；若 $j = c$ 则 $a[i][j]$ 与 `colAdd[j]` 同步 $+1$；两者同时成立时 $a[i][j]$ 加 $2$，而右式也加 $2$。其余情况两边都不变。故等式保持。∎

**引理 2（奇偶判定）**：$a[i][j]$ 为奇数 $\iff$ `rowParity[i]` $\ne$ `colParity[j]`，其中 `rowParity[i] = rowAdd[i] mod 2`、`colParity[j] = colAdd[j] mod 2`。

**证明**：由引理 1，$a[i][j] \bmod 2 = (\text{rowAdd}[i] + \text{colAdd}[j]) \bmod 2 = (\text{rowParity}[i] + \text{colParity}[j]) \bmod 2$，而两个比特之和对 $2$ 取模恰是异或，它为 $1$ 当且仅当两个比特不同。∎

**引理 3（计数公式）**：矩阵中奇数值单元格的个数为 $R(n-C) + (m-R)C$，其中 $R = \sum_i \text{rowParity}[i]$、$C = \sum_j \text{colParity}[j]$。

**证明**：把格子按行分成「行奇」与「行偶」两组，大小分别为 $R$ 与 $m - R$；在每组内再按列分成「列奇」与「列偶」两组，列偶组大小为 $n - C$、列奇组大小为 $C$。由引理 2，奇数格恰是「行奇列偶」（$R(n-C)$ 个）与「行偶列奇」（$(m-R)C$ 个），两组按行奇偶互斥，故总数即两者之和。∎

**定理**：算法返回的值等于全部操作执行后矩阵中奇数值单元格的数目。

**证明**：算法的 $R, C$ 由 `row[]`、`col[]` 求和得到，而 `row[r] ^= 1` 执行奇数次即得 $1$、偶数次即得 $0$，所以 `row[i] = rowAdd[i] mod 2`，`col[j] = colAdd[j] mod 2`，$R, C$ 与引理 3 中的定义一致。由引理 3，返回值即奇数格个数。∎

## 6. 复杂度分析

- **时间**：$O\bigl(\lvert\text{indices}\rvert + m + n\bigr)$。第一趟遍历 `indices` 每次 $O(1)$；第二趟扫描两个计数器数组。总时间与矩阵大小 $mn$ 无关。
- **空间**：$O(m + n)$。仅两个长度分别为 $m$、$n$ 的辅助数组，没有 $m \times n$ 的矩阵。
- 与暴力对比：暴力是 $O(\lvert\text{indices}\rvert(m+n) + mn)$ 时间、$O(mn)$ 空间，本题的优化在渐进阶上严格更优，且正好满足题目「进阶」的要求。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int oddCells(int m, int n, vector<vector<int>>& indices) {
        vector<int> row(m, 0), col(n, 0);
        for (const auto& p : indices) {
            row[p[0]] ^= 1;   // 只关心奇偶：被加一次就翻转一次
            col[p[1]] ^= 1;
        }
        int R = 0, C = 0;     // 行奇偶为 1 的行数、列奇偶为 1 的列数
        for (int x : row) R += x;
        for (int x : col) C += x;
        return R * (n - C) + (m - R) * C;
    }
};
```

### Python

```python
class Solution:
    def oddCells(self, m: int, n: int, indices: list[list[int]]) -> int:
        row = [0] * m
        col = [0] * n
        for r, c in indices:
            row[r] ^= 1       # 行奇偶翻转
            col[c] ^= 1       # 列奇偶翻转
        R = sum(row)          # 行奇偶为 1 的行数
        C = sum(col)          # 列奇偶为 1 的列数
        # 奇数格 = 行奇列偶 + 行偶列奇
        return R * (n - C) + (m - R) * C
```

## 8. 边界情况与易错点

1. **把操作理解成只加一个格子**：题面是「整行 $+1$ 且整列 $+1$」，交点被加 $2$。若误写成只给 $(r, c)$ 加 $1$，示例 1 会得到 $3$ 而不是 $6$。
2. **同一行/列被多次操作不叠加成奇偶之外的东西**：例如 `indices = [[0,0],[0,0]]`，第 $0$ 行与第 $0$ 列各被加 $2$ 次，全部格子为偶数，答案 $0$。用异或写法自动正确处理，用「按操作次数统计」的写法则要记得取模。
3. **$m = 1$ 或 $n = 1$**：公式依然成立。如 $m = 1, n = 3$，`row` 只有一行，$R$ 只能是 $0$ 或 $1$，$R(n-C) + (1-R)C$ 仍正确。不要给 $m=1$ 写特殊分支。
4. **行奇列奇既不是「算两次」也不是「算零次」**：它是**偶数**格，属于计数公式中被排除的部分；把四象限全加起来会得到 $mn$。
5. **结果类型**：答案上界 $mn \le 2500$，`int` 安全；但若把乘积写成 `R * (n - C) + (m - R) * C` 而 $m, n$ 放大到 $10^9$，则需要 `long long`，中间积会溢出 `int`。
6. **`indices` 为空**：本题约束保证 $\lvert\text{indices}\rvert \ge 1$，但代码对空输入也安全（$R = C = 0$，返回 $0$）。
7. **下标从 $0$ 开始**：`r_i < m`、`c_i < n` 已由约束保证，不需要做越界检查；若自己造数据测试，注意别把 $1$ 基混进来。

**延伸思考**：若每次操作不是对整行、整列各加 $1$，而是加一个**权重** $w_i$（行）与 $v_j$（列），则格子值为 $\sum_{r_k = i} w_k + \sum_{c_k = j} v_k$，奇偶判定变为「行加权和的奇偶」与「列加权和的奇偶」的异或——四象限计数框架完全不变，只需把每个计数器换成「被加权重之和 $\bmod 2$」。进一步地，若把模 $2$ 换成模 $k$，答案不再是 $R(n-C)+(m-R)C$ 这样的两个乘积，而要统计每个余数类 $i$ 的行数与列数的分布，再对每个目标余数 $t$ 累加 $\sum_{i} \text{rowCnt}[i] \cdot \text{colCnt}[(t-i) \bmod k]$，这就退化成了一个「卷积」结构的计数问题。
