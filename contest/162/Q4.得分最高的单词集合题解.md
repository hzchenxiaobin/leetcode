# LeetCode 得分最高的单词集合 题解

## 1. 题目概述

- **标题 / 题号**：得分最高的单词集合（#1255，hard）
- **链接**：https://leetcode.cn/problems/maximum-score-words-formed-by-letters/
- **来源**：LeetCode 第 162 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、哈希表、字符串、动态规划、回溯、状态压缩、计数

**题意**：给定单词表 `words`、字母表 `letters`（可能含重复字母）、26 个字母的分值表 `score`。从 `words` 中选一个子集，要求子集里所有单词能用 `letters` 的字母**一次性拼完**（每个字母的使用次数不超过它在 `letters` 中的出现次数，每个单词最多使用一次，每个单词只计分一次），把实际用掉的字母按 `score` 求和，返回能得到的最大总分。可以不选任何单词，此时得分为 0。

**约束**：

- $1 \le \text{words.length} \le 14$ —— 子集总数最多 $2^{14} = 16384$
- $1 \le \text{words}[i]\text{.length} \le 15$
- $1 \le \text{letters.length} \le 100$；$\text{score.length} = 26$，$0 \le \text{score}[i] \le 10$
- `words[i]` 与 `letters[i]` 仅含小写英文字母

## 3. 解题思路

### 3.1 暴力思路

把每个单词看成一个「物品」，做选 / 不选决策，一共 $2^{14}$ 个子集；对每个子集累加 26 维字母需求，与字母表逐维比较，取可行子集的最大得分。这个上界本身可以接受（约 $1.6 \times 10^4 \times 26$ 次比较），所以本题的难点**不在规模，而在别走错方向**：

- **按单词分值从高到低贪心**是错的。反例：`score` 取 a=10、b=10、c=1、d=1，`letters = ["a","b","c","d"]`，`words = ["ab","ac","bd"]`；贪心先取价值 20 的 "ab"，字母 a、b 用尽只得 20，最优却是 "ac"+"bd" = 11+11 = 22。
- **直接做 26 维背包 DP** 也不现实：状态空间是 $\prod_j (C[j]+1)$，`letters.length` 到 100 时状态数远超枚举子集；而物品只有 14 件，枚举反而更划算。

所以正确方向是：**枚举子集，但把「可行性判定」和「剪枝」做得足够便宜**。

### 3.2 核心观察：单词 → 26 维计数向量，子集可行性逐维判定

![把单词压成字母计数向量](images/wc162_q4_subset_model.svg)

给每个单词定义**计数向量** $c_w \in \mathbb{N}^{26}$（$c_w[j]$ 是字母 $j$ 在 $w$ 中出现的次数），字母表同样有计数向量 $C$；单词价值取 $v_w = \sum_{j=0}^{25} c_w[j] \cdot \text{score}[j]$。由此得到两条把原问题「化归为纯计数」的性质（§5 中给出证明）：

- **可行性**：子集 $S$ 能拼出 $\iff$ $\sum_{w \in S} c_w \le C$（26 个维度逐一满足）；
- **可加性**：$\text{score}(S) = \sum_{w \in S} v_w$。

于是本题就是一件**只有 14 个物品、约束是 26 维向量的 0/1 背包**。物品数极小、维度却很高，所以「枚举子集」比「DP 状态」更合适。在枚举上再加两层结构性剪枝：

1. **单点剔除**：若 $c_w \not\le C$，则 $w$ 永远不可选（含它的集合一定不可行），直接从候选集中删掉，$n$ 只会变小。
2. **剩余价值上界**：把候选单词按任意固定顺序排好，令 $\text{suffix}[i] = \sum_{k=i}^{n-1} v_k$。搜索到第 $i$ 层、当前得分 `cur` 时，继续往下最多再加 $\text{suffix}[i]$，若 $\text{cur} + \text{suffix}[i] \le \text{best}$，整棵子树可以剪掉。由于所有 $v_k \ge 0$，这是**合法上界**。

> 💡 因为价值全部非负，「最优解一定是极大子集」，所以先走「选」的分支能让 `best` 迅速变大，上界剪枝效果显著。

### 3.3 算法流程

![回溯流程：选 / 不选 + 上界剪枝](images/wc162_q4_dfs_flow.svg)

1. 统计 `avail`（`letters` 各字母次数），令预算 `rem = avail`；遍历 `words` 算 $c_w$，若存在维度 $c_w[j] > \text{avail}[j]$ 就丢弃，否则连同 $v_w$ 一起保存（剩余单词数记为 $n$）。
2. 从后往前求 `suffix[i]`，令 `best = 0`。
3. `dfs(i, cur)`：
   - 若 `cur + suffix[i] <= best`，直接返回（上界剪枝）；
   - 若 `i == n`，用 `cur` 更新 `best` 并返回；
   - **选**：若 $c_i \le \text{rem}$，则逐维 `rem -= c_i`，递归 `dfs(i+1, cur+v_i)`，返回后逐维 `rem += c_i`；
   - **不选**：直接 `dfs(i+1, cur)`。
4. 返回 `best`。

### 3.4 示例演算

![示例 1 走查](images/wc162_q4_walkthrough.svg)

以示例 1 为例，预算 a×2、c×1、d×3、g×1、o×2。四个单词依次是 `dog`=(d1 g1 o1) 值 10、`cat`=(a1 c1 t1) 值 10、`dad`=(a1 d2) 值 11、`good`=(d1 g1 o2) 值 12；其中 `cat` 因 `letters` 中没有 t 而在预处理阶段被剔除，故 $n = 3$、`suffix = [33, 23, 12, 0]`。

| 步骤 | 决策 | 预算 `rem`（a,c,d,g,o） | `cur` | `best` |
|------|------|--------------------------|-------|--------|
| 1 | 选 `dog` | 2,1,2,0,1 | 10 | 10 |
| 2 | 选 `dad` | 1,1,0,0,1 | 21 | 21 |
| 3 | 试选 `good`：d 预算已为 0 → 跳过；回退第 1 层改「不选 `dog`」 | 2,1,3,1,2 | 0 | 21 |
| 4 | 选 `dad`，再选 `good`，字母恰好用尽 | 1,1,0,0,0 | 23 | 23 |
| 5 | 其余分支被上界剪枝（如 `suffix = 12` 已追不上 23） | — | — | 23 |

最终 `best = 23`，与官方输出一致。

## 4. 算法细节

1. **计数向量用定长 26 数组**：C++ 用 `array<int,26>` 或 `vector<int>`，Python 用 `list`。不要用 `Counter`/`map`，否则每层判定都要哈希，常数大且不便逐维比较。
2. **剔除放在预处理里做**：$c_w \le \text{avail}$ 不成立即丢弃，既减少搜索层数，又顺手保证「价值非负 + 上界剪枝」不会因不可行物品而失真。
3. **可行性判定用短路循环**：一旦某维 $c_i[j] > \text{rem}[j]$ 立即跳出，绝大多数分支只需比较一两个维度，不要为判定拷贝整个数组。
4. **回溯必须原位恢复**：先 `rem[j] -= c_i[j]`，递归，再 `rem[j] += c_i[j]`，两段循环成对出现。复制整个 `rem` 虽然也能写对，但每层多 26 次拷贝，且容易与剪枝逻辑搅在一起出错。
5. **上界数组长度取 $n+1$，剪枝用 `<=`**：`suffix[n] = 0` 使 `i == n` 那层也能先判剪枝再更新；打平不改进答案故可剪，若要求输出方案则改成 `<` 并在相等时覆盖。
6. **等价的迭代写法（了解即可）**：按 `mask` 从 0 到 $2^n-1$ 枚举，用 `cnt[mask] = cnt[mask ^ lowbit] + cnt[lowbit]` 递推出 26 维需求向量再判可行；时间同为 $O(2^n \cdot 26)$，但要存 $2^{14}$ 个 26 维向量（约 170 万个 `int`），空间远不如回溯优雅。

## 5. 正确性证明

**引理 1（可行性 = 逐维支配）**：子集 $S$ 能被拼出 $\iff$ $\sum_{w \in S} c_w \le C$ 在 26 个维度上全部成立。

**证明**：

- ($\Leftarrow$) 按任意顺序依次消耗字母：处理 $w$ 时所需的 $c_w[j]$ 不超过「尚未使用」的 $C[j] - \sum_{\text{已处理}} c_u[j]$——由总量支配关系可归纳得到。于是每个字母都不会被用到超过 $C$ 次，$S$ 可拼出。
- ($\Rightarrow$) `letters` 中每个字母最多被使用 $C[j]$ 次，故 $S$ 中所有单词对字母 $j$ 的需求总量不超过 $C[j]$。∎

**引理 2（得分可加）**：若 $S$ 可拼出，则 $\text{score}(S) = \sum_{w \in S} v_w$。

**证明**：$S$ 用掉的字母总量为 $\sum_{w \in S} c_w$，按定义 $\text{score}(S) = \sum_{j} \bigl(\sum_{w \in S} c_w[j]\bigr)\text{score}[j] = \sum_{w \in S}\sum_{j} c_w[j]\,\text{score}[j] = \sum_{w \in S} v_w$。∎

**引理 3（剔除安全）**：若 $c_w \not\le C$，则任何包含 $w$ 的子集都不可行。

**证明**：设 $w \in S$，存在维度 $j$ 使 $c_w[j] > C[j]$。又 $c_u[j] \ge 0$，故 $\sum_{u \in S} c_u[j] \ge c_w[j] > C[j]$，由引理 1 知 $S$ 不可行。∎

**引理 4（预算不变式）**：`dfs(i, cur)` 入口处恒有 $\text{rem}[j] = C[j] - \sum_{u \in T} c_u[j]$，其中 $T$ 是当前已选的单词集合；且 `cur` 等于 $T$ 中单词在 `words` 里的前 $i$ 个位置上的价值之和。

**证明**：对递归层数归纳。$i=0$ 时 $T = \varnothing$、`rem = C`，成立。「选」分支先验证 $c_i \le \text{rem}$，再逐维减去，进入子调用时不变式成立；子调用返回后逐维加回，`rem` 复原；「不选」分支不修改 `rem`。`cur` 的更新与减法同步，故同时成立。∎

**引理 5（剪枝安全）**：若在 `dfs(i, cur)` 处因 $\text{cur} + \text{suffix}[i] \le \text{best}$ 返回，则该子树中任何可行解的得分都不超过 `best`。

**证明**：子树中选出的单词都来自下标区间 $[i, n)$，新增得分 $\sum_{w \in S' \cap [i,n)} v_w \le \sum_{w \in [i,n)} v_w = \text{suffix}[i]$（用到 $v_w \ge 0$）。故子树内总分 $\le \text{cur} + \text{suffix}[i] \le \text{best}$，不可能产生更优解。∎

**定理**：算法返回的 `best` 等于所有可行子集得分的最大值。

**证明**：先证「记录的都合法」：由引理 4，`i == n` 时 `cur` 等于某个满足 $c_i \le \text{rem}$ 的已选集合的价值和，而引理 4 的不变式保证了该集合逐维不超过 $C$，由引理 1 可行、引理 2 其得分正是 `cur`，故 `best` 始终对应一个可行解。再证「不漏最优」：设 $S^{*}$ 为得分最大的可行子集，沿 $S^{*}$ 的选 / 不选序列在决策树上行走。走到第 $i$ 层时剩余预算 $\text{rem} = C - \sum_{u \in S^{*}\cap[0,i)} c_u \ge \sum_{u \in S^{*}\cap[i,n)} c_u \ge c_i$（由引理 1 与 $c_i$ 属于右端和式），故「选」分支不会被预算挡住；同时该处 $\text{cur} + \text{suffix}[i] \ge \text{cur} + \sum_{u\in S^{*}\cap[i,n)} v_u = \text{score}(S^{*})$，只要 `best` 还小于 $\text{score}(S^{*})$ 就不会触发引理 5 的剪枝条件。于是这条路径必被走通，并在 $i = n$ 处把 `best` 更新为 $\text{score}(S^{*})$。结合引理 3（剔除的单词不可能出现在任何可行解中），得 `best` 即最优值。∎

## 6. 复杂度分析

- **时间**：预处理 $O(\lvert \text{letters} \rvert + \sum_i \lvert \text{words}[i] \rvert + 26n)$；回溯最坏 $O(2^{n} \cdot 26)$，其中 $n \le 14$ 是剔除后的单词数，上界约 $4.3 \times 10^{5}$ 次基本操作。实际上「选」分支受字母预算限制、又被 `suffix` 上界剪掉大量子树，运行时间通常只有上界的几个百分点。
- **空间**：计数向量 $O(26n)$；`suffix` 数组 $O(n)$；递归栈深度 $O(n)$；字母预算 $O(26)$。合计 $O(26n)$，即 $n \le 14$ 时的常数级空间。

## 7. 参考代码

### C++

```cpp
#include <functional>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int maxScoreWords(vector<string>& words, vector<char>& letters, vector<int>& score) {
        vector<int> avail(26, 0);
        for (char ch : letters) avail[ch - 'a']++;
        vector<vector<int>> cnts;                 // 每个候选单词的 26 维计数向量
        vector<int> vals;                         // 对应价值
        for (const string& w : words) {
            vector<int> c(26, 0);
            for (char ch : w) c[ch - 'a']++;
            bool ok = true;
            for (int j = 0; j < 26; j++)
                if (c[j] > avail[j]) { ok = false; break; }
            if (!ok) continue;                    // 单个单词都拼不出，永远不可选
            int v = 0;
            for (int j = 0; j < 26; j++) v += c[j] * score[j];
            cnts.push_back(c);
            vals.push_back(v);
        }
        int n = (int)cnts.size();
        vector<int> suffix(n + 1, 0);             // suffix[i]：i..n-1 的价值和（上界）
        for (int i = n - 1; i >= 0; i--) suffix[i] = suffix[i + 1] + vals[i];
        vector<int> rem = avail;
        int best = 0;
        function<void(int, int)> dfs = [&](int i, int cur) {
            if (cur + suffix[i] <= best) return;  // 剩余全取也追不上，剪枝
            if (i == n) { best = cur; return; }   // 记录合法解
            bool ok = true;
            for (int j = 0; j < 26; j++)
                if (cnts[i][j] > rem[j]) { ok = false; break; }
            if (ok) {                             // 分支一：选第 i 个单词
                for (int j = 0; j < 26; j++) rem[j] -= cnts[i][j];
                dfs(i + 1, cur + vals[i]);
                for (int j = 0; j < 26; j++) rem[j] += cnts[i][j];
            }
            dfs(i + 1, cur);                      // 分支二：不选
        };
        dfs(0, 0);
        return best;
    }
};
```

### Python

```python
class Solution:
    def maxScoreWords(self, words: list[str], letters: list[str], score: list[int]) -> int:
        avail = [0] * 26
        for ch in letters:
            avail[ord(ch) - 97] += 1
        cnts, vals = [], []
        for w in words:
            c = [0] * 26
            for ch in w:
                c[ord(ch) - 97] += 1
            if any(c[j] > avail[j] for j in range(26)):
                continue                      # 单个单词都拼不出，永远不可选
            cnts.append(c)
            vals.append(sum(c[j] * score[j] for j in range(26)))
        n = len(cnts)
        suffix = [0] * (n + 1)                # suffix[i]：i..n-1 的价值和（上界）
        for i in range(n - 1, -1, -1):
            suffix[i] = suffix[i + 1] + vals[i]
        rem = avail[:]
        best = 0

        def dfs(i: int, cur: int) -> None:
            nonlocal best
            if cur + suffix[i] <= best:       # 剩余全取也追不上，剪枝
                return
            if i == n:
                best = cur                    # 记录合法解
                return
            c = cnts[i]
            if all(c[j] <= rem[j] for j in range(26)):     # 分支一：选
                for j in range(26):
                    rem[j] -= c[j]
                dfs(i + 1, cur + vals[i])
                for j in range(26):
                    rem[j] += c[j]
            dfs(i + 1, cur)                   # 分支二：不选

        dfs(0, 0)
        return best
```

## 8. 边界情况与易错点

1. **0 分字母依然要占字母表**：示例 1 的 `cat` 恰好 10 分，但 `letters` 里没有 `t`，所以它不可选。不要因为 `score` 为 0 就跳过字母可用性检查——这是本题最隐蔽的坑。
2. **单词内部重复字母**（`good` 要 2 个 o，`xxxz` 要 3 个 x）：必须用计数而不是 `set`，否则会误判可行。
3. **空子集合法且要防 `n == 0`**：`best` 初值为 0，允许一个单词都不选（示例 3 答案即 0）；全部单词被剔除时 `dfs(0, 0)` 会因 `0 + suffix[0] = 0 <= best` 直接返回，`suffix` 长度取 $n+1$ 保证 `i == n` 不越界。
4. **回溯忘记恢复 `rem`**：只减不加，后续兄弟分支的预算会偏小，出现难以定位的系统性 WA；减法和加法必须在同一层成对出现。
5. **把「贪心」当结论**：按分值排序后能拼就拼会漏掉「两件中价值之和更大」的组合（§3.1 的反例），必须做完整的子集搜索。
6. **剪枝符号写反**：若写成 `cur + suffix[i] < best` 只是少剪一点、不影响正确性；但若误写成「`cur + suffix[i] <= best` 继续搜索」或把 `suffix` 算成前缀和，就会直接丢掉最优解。
7. **整数范围**：单次得分上界 $14 \times 15 \times 10 = 2100$，`int` 足够，无需 `long long`。
