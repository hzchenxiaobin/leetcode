# LeetCode 最小元素和最大元素的最小平均值 题解

## 1. 题目概述

- **标题 / 题号**：最小元素和最大元素的最小平均值（#3194）
- **链接**：https://leetcode.cn/problems/minimum-average-of-smallest-and-largest-elements/
- **来源**：LeetCode 第 403 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序、双指针

**题意**：给定长度为偶数 $n$ 的整数数组 `nums` 与一个初始为空的浮点数数组 `averages`。重复以下操作 $n/2$ 次，直到 `nums` 为空：

- 从 `nums` 中移除**最小**的元素 $\text{minElement}$ 与**最大**的元素 $\text{maxElement}$；
- 将 $(\text{minElement} + \text{maxElement}) / 2$ 加入 `averages`。

返回 `averages` 中的**最小**元素。

**约束**：

- $2 \le n = \text{nums.length} \le 50$，且 $n$ 为偶数
- $1 \le \text{nums}[i] \le 50$

> 💡 读题关键：整个过程是一个**确定性模拟**——每轮「掐头去尾」配对求平均，共恰好 $n/2$ 轮；而题目只问所有平均值的**最小值**。`averages` 只是叙述载体，不必真的建立；真正的考点是看出**每一轮配对的是谁**，从而把整个模拟降维成一次线性扫描。

## 2. 示例

**示例 1**

```text
输入：nums = [7,8,3,4,15,13,4,1]
输出：5.5
解释：四轮移除的配对依次是 (1,15)、(3,13)、(4,8)、(4,7)，
     averages = [8, 8, 6, 5.5]，最小元素为 5.5。
```

**示例 2**

```text
输入：nums = [1,9,8,3,10,5]
输出：5.5
解释：三轮配对为 (1,10) → 5.5，(3,9) → 6，(5,8) → 6.5，最小为 5.5。
```

**示例 3**

```text
输入：nums = [1,2,3,7,8,9]
输出：5.0
解释：三轮配对为 (1,9)、(2,8)、(3,7)，平均值全为 5.0——数组「对称均匀」时
     所有平均值相同。
```

**补充：全相等**

```text
输入：nums = [5,5,5,5]
输出：5.0
解释：每轮移除两个 5，平均值恒为 5.0，最小值 = 最大值 = 5.0。
```

## 3. 解题思路

### 3.1 暴力思路：按题面逐步模拟

按题意直译：每轮线性扫描找最小 / 最大（$O(n)$），从数组中删除（$O(n)$），把平均值 append 进 `averages`；最后取 `min(averages)`。总计 $O(n^2)$，本题 $n \le 50$ 即至多约 $2500$ 次基本操作，稳过。

时间上毫无压力，但这个写法有两处结构性冗余：

- **`averages` 列表是多余的**——只需求最小值，一个滚动变量 `best` 就够；
- **删除操作是多余的**——每轮「移除当前最小 / 最大」并不改变剩余元素的相对次序，配对关系从头到尾是**确定**的，根本不必动态维护。

签到题的正确姿势是把这两处冗余砍掉，找到从题面到代码的最短路径。

### 3.2 核心观察：排序后「第 k 小」必配「第 k 大」

![核心观察：排序后第 k 小配第 k 大](images/min_max_avg_pairing_concept.svg)

把 `nums` 升序排序得到 $a_0 \le a_1 \le \cdots \le a_{n-1}$，逐轮看移除的是谁：

- 第 1 轮移除**全局最小** $a_0$ 与**全局最大** $a_{n-1}$；
- 剩下的元素仍保持升序，于是第 2 轮移除**全局第 2 小** $a_1$ 与**第 2 大** $a_{n-2}$；
- 归纳可得：**第 $k$ 轮恰好移除第 $k$ 小 $a_{k-1}$ 与第 $k$ 大 $a_{n-k}$**。

于是整个模拟的产物可以一步写出：

$$\text{ans} = \min_{0 \le i < n/2} \frac{a_i + a_{n-1-i}}{2}$$

用**对撞双指针** $i$ 从左、$j$ 从右向中间靠拢，$n/2$ 对一趟扫完，无需任何删除。

两个值得强调的细节：

- **反直觉点：最小平均值未必来自最外层 $(a_0 + a_{n-1})/2$**。示例 1 中最外层是 $(1+15)/2 = 8.0$，答案却藏在最内层 $(4+7)/2 = 5.5$——中间元素挤在一起时内层配对的「跨度」更小。所以 $n/2$ 对**必须逐一比较**，不能只算一对。
- **浮点细节**：$\frac{x}{2}$ 关于 $x$ 单调递增，故**最小化平均值 $\iff$ 最小化整数和**。全程只比较整数 $a_i + a_j \le 100$，最后统一除以 2——既无浮点比较，也不必提前引入 `double`。

### 3.3 算法流程：排序 + 对撞双指针

![算法流程图](images/min_max_avg_two_pointer_flow.svg)

流程只有四步：

```text
sort(nums)                          # 升序
i, j = 0, n - 1                     # 对撞双指针
best = +∞                           # 存「整数和」，不是平均值
while i < j:
    best = min(best, nums[i] + nums[j])
    i, j = i + 1, j - 1             # 两端各向中间走一步
return best / 2                     # 除法只做一次
```

### 3.4 示例演算

![示例演算：逐轮模拟与两端配对等价](images/min_max_avg_simulation_vs_pairing.svg)

以示例 1 为例，排序后 $a = [1,3,4,4,7,8,13,15]$：

| 轮次 | 指针 $(i,j)$ | 配对 | 整数和 | 平均值 | `best`（存整数和） |
|------|--------------|------|--------|--------|--------------------|
| 1 | $(0,7)$ | $1+15$ | 16 | 8.0 | 16 |
| 2 | $(1,6)$ | $3+13$ | 16 | 8.0 | 16 |
| 3 | $(2,5)$ | $4+8$ | 12 | 6.0 | 12 |
| 4 | $(3,4)$ | $4+7$ | 11 ★ | **5.5** | 11 |

最终 $11 / 2 = 5.5$。注意 `best` 全程只存**整数和**，除法只在 `return` 处做一次。示例 3 则是另一个极端：$[1,2,3,7,8,9]$ 三对平均值全为 5.0。

## 4. 算法细节

1. **排序一次即够**：删除当前最小 / 最大不会破坏剩余元素的升序结构（这正是引理 1 的内容），所以「逐轮删除」与「排序后两端配对」完全等价，删除步骤可以整体省略。
2. **双指针循环条件写 `i < j`**：$n$ 为偶数时两指针恰好在中间交叉——第 $n/2$ 轮后 $i = n/2$、$j = n/2 - 1$，自然退出，恰好覆盖全部 $n/2$ 对，不多不少。
3. **`best` 存整数和**：由 $x \mapsto x/2$ 的单调性，最小化平均值等价于最小化 $a_i + a_j \le 100$。本题数值小（`.5` 在二进制浮点下可精确表示），误差本不致命，但「整数域比较、最后一步转浮点」是无浮点坑的通用习惯。
4. **`averages` 不必真实存在**：题面引入它只是为了叙述过程，实际只需一个滚动最小值变量；同理也不需要 `min`/`max`/删除等任何模拟设施。
5. **写法盘点**：Python 中 `nums[n-1-i]` 可写成 `nums[~i]`（$\lnot i = -i-1$，正序下标与倒序下标一步互换），配合生成器表达式可压成一行 `min(a[i] + a[~i] for i in range(len(a)//2)) / 2`。

## 5. 正确性证明

**引理 1（配对结构）**：将 `nums` 升序排序为 $a_0 \le a_1 \le \cdots \le a_{n-1}$。第 $k$ 轮（$1 \le k \le n/2$）移除的两个元素**按值**恰为 $a_{k-1}$ 与 $a_{n-k}$。

**证明**：对 $k$ 归纳。归纳假设：第 $k$ 轮开始前，剩余元素的多重集合为 $\{a_{k-1}, a_k, \ldots, a_{n-k}\}$。$k=1$ 时即全体元素，成立。该多重集合升序后的最小值为 $a_{k-1}$、最大值为 $a_{n-k}$，故本轮移除的就是这两个值各一个（若 $a_{k-1} = a_{n-k}$，剩余元素全相等，「移除最小与最大」即移除两个同值元素，与按值移除 $a_{k-1}$、$a_{n-k}$ 一致；此时剩余个数 $n - 2(k-1) \ge 2$，两个同值元素总是存在的）。移除后剩余 $\{a_k, \ldots, a_{n-k-1}\}$，即第 $k+1$ 轮的归纳假设。∎

**引理 2（平均值集合）**：`averages` 作为多重集合，恰为 $\left\{ \dfrac{a_i + a_{n-1-i}}{2} \ :\ 0 \le i < n/2 \right\}$。

**证明**：由引理 1，第 $i+1$ 轮移除的值为 $a_i$ 与 $a_{n-1-i}$，加入的平均值即 $\frac{a_i + a_{n-1-i}}{2}$；$i$ 取遍 $0, \ldots, n/2-1$ 共 $n/2$ 轮，恰生成该集合的全部元素。∎

**定理**：排序后取 $\min\limits_{0 \le i < n/2} \left( a_i + a_{n-1-i} \right)$、最后除以 2，返回值即题目所求。

**证明**：由引理 2，所求为 $\min_i \frac{a_i + a_{n-1-i}}{2}$。记 $s_i = a_i + a_{n-1-i}$，由 $x \mapsto x/2$ 严格单调递增知 $\min_i \frac{s_i}{2} = \frac{\min_i s_i}{2}$。对撞双指针从 $(0, n-1)$ 起每轮处理 $(i, n-1-i)$ 后两端各进一格，恰好遍历 $i = 0, \ldots, n/2 - 1$ 全部 $n/2$ 对（$n$ 为偶数），故 `best` $= \min_i s_i$，返回 `best / 2` 即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导；对撞双指针恰扫描 $n/2$ 对，仅 $O(n)$。作为对照，逐轮模拟为 $O(n^2)$，在 $n \le 50$ 下同样能过——本题优化的收益主要是代码更短、更不容易写错。
- **空间复杂度**：$O(1)$。原地排序加两个下标与一个 `best` 变量（不计语言排序自身的递归栈）；朴素模拟则还需 $O(n)$ 的 `averages` 数组。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    double minimumAverage(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size(), best = INT_MAX;
        for (int i = 0, j = n - 1; i < j; ++i, --j) {
            best = min(best, nums[i] + nums[j]);
        }
        return best / 2.0;
    }
};
```

### Python

```python
class Solution:
    def minimumAverage(self, nums: List[int]) -> float:
        nums.sort()
        i, j = 0, len(nums) - 1
        best = float("inf")
        while i < j:
            best = min(best, nums[i] + nums[j])
            i += 1
            j -= 1
        return best / 2
```

> 💡 C++ 必须写 `best / 2.0`（或 `best * 0.5`）：整数相除会截断，丢掉 `.5`。Python 的 `/` 天生返回浮点，无此坑。`n >= 2` 保证循环至少执行一次，`best` 必被更新。

## 8. 边界情况与易错点

1. **不能只算最外层一对**：示例 1 是现成反例——最外层 $(1+15)/2 = 8.0$，最内层 $(4+7)/2 = 5.5$ 才是答案。最小平均值可能出现在任意一层，$n/2$ 对必须逐一比较后取 `min`。
2. **最小规模 $n = 2$**：只有一对，循环恰执行一次，`best` 必被赋值，无未初始化返回的风险（前提是初值用 $+\infty$ 或直接用第一对初始化）。
3. **全相等 / 大量重复元素**：多重集合语义下「最小 = 最大」时一轮移除两个同值元素，排序 + 两端配对自动正确，无需任何特判（见引理 1 证明中的括号说明）。
4. **循环条件写 `i < j` 而非 `i <= j`**：本题 $n$ 恒为偶数，两者等价；但若约束改成 $n$ 可为奇数，`i <= j` 会在 $i = j$ 处多算一次「自配对」$(a_i + a_i)/2 = a_i$，把中位数错误地塞进候选。防御性写 `i < j` 并想清楚相遇 / 交叉语义，是双指针题的基本功。
5. **C++ 整数除法截断**：`best / 2` 会把 5.5 变成 5.0，必须除以 `2.0`；这是本题最典型的 WA 点。
6. **不要真去维护 `averages` 与删除操作**：虽然 $n/2 \le 25$ 个元素的开销可以忽略，但多一份 append / erase 逻辑就多一处下标出错的机会——签到题追求的是从题面到代码的最短路径。

**延伸思考**：

- **「强制配对」vs「自由配对」**：若把规则改成「每轮任取两个元素配对，目标是让 `averages` 的最小值尽可能大」，最优策略仍然是**最小配最大**。交换论证：设某方案中全局最小 $x$ 与 $p$ 配对、全局最大 $z$ 与 $q$ 配对（$x \le p, q \le z$），改为 $x$ 配 $z$、$p$ 配 $q$ 后，新配对和 $x + z \ge x + p$ 且 $p + q \ge x + p$，均不小于原两对中较小者，故最小值不降；反复交换即收敛到首尾配对。也就是说，本题的强制规则恰好落在最优点上——与 1877 殊途同归。
- **值域信号**：约束 $1 \le \text{nums}[i] \le 50$ 提示计数排序可把排序降到 $O(n + V)$（在值域数组上做对撞双指针，空桶跳过、同桶自配）。对 $n \le 50$ 属于杀鸡用牛刀，但值域出现在约束里时就值得条件反射地想到桶。
- **若 $n$ 为奇数**：最后一轮只剩一个元素，「移除最小与最大」变成移除同一个元素两次，规则需要另行约定（例如中位数是否单独入 `averages`）——这也是第 8 节第 4 条强调 `i < j` 的原因。
