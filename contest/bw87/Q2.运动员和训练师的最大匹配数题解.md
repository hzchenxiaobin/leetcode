# LeetCode 运动员和训练师的最大匹配数 题解

> 💡 本题在本仓库另有[每日题解 2410](../../solution/2401-2500/2410_运动员和训练师的最大匹配数.md)，侧重面试视角的双指针模板。本篇按**周赛复盘视角**展开：以交换论证为纲的引理–定理证明链、指针不回退的摊还解释，以及「能带 vs 带得动」的语义细节清单。

## 1. 题目概述

- **标题 / 题号**：运动员和训练师的最大匹配数（#2410，medium）
- **链接**：https://leetcode.cn/problems/maximum-matching-of-players-with-trainers/
- **来源**：LeetCode 第 87 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、双指针、排序

**题意**：`players[i]` 是第 $i$ 名运动员的能力值，`trainers[j]` 是第 $j$ 名训练师的训练能力值。若 $\text{players}[i] \le \text{trainers}[j]$，则运动员 $i$ **可以匹配**训练师 $j$。每人至多匹配一位对侧成员。求最大匹配数。

**约束**：

- $1 \le \text{players.length}, \text{trainers.length} \le 10^5$
- $1 \le \text{players}[i], \text{trainers}[j] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：players = [4,7,9], trainers = [8,2,5,8]
输出：2
解释：players[0] 配 trainers[0]（4 ≤ 8），players[1] 配 trainers[3]（7 ≤ 8）。
```

**示例 2**

```text
输入：players = [1,1,1], trainers = [10]
输出：1
解释：唯一的训练师只能带一名运动员，三选一。
```

**示例 3（边界补充）**

```text
输入：players = [5], trainers = [4]
输出：0
解释：最强训练师也带不动最弱运动员，一个都配不上。
```

## 3. 解题思路

### 3.1 暴力思路

这是标准的二分图最大匹配：建图后跑匈牙利算法 $O(V \cdot E)$ 或 Dinic $O(E\sqrt V)$。$V, E \sim 10^{10}$ 量级的上界（$10^5 \times 10^5$ 条边建都建不完），显然不可行。盲目套网络流是本题最大的陷阱——**可匹配条件只与两边的数值大小有关**，这是一张「阈值图」，其匹配问题可以贪心。

### 3.2 核心观察：排序后「小配小」，双方指针都只前进

![排序+双指针：最弱的运动员配刚够用的训练师](images/bw87_q2_greedy_model.svg)

把两个数组都升序排序后，按运动员从弱到强依次处理，为其分配**当前剩余的、能带他的训练师中最弱的一个**（弱训练师带弱运动员，强训练师留给后面更强的人）。若连最弱的可用训练师都带不动当前运动员，说明剩余训练师全部带不动（排序后更强运动员只会更难带）——这个训练师永远没用了，直接跳过。

```text
按能力升序排序 players 与 trainers
j = 0（训练师指针），ans = 0
for p in players:                 # 从最弱开始
    while j < m 且 trainers[j] < p:  # 带不动 → 该训练师永久出局
        j += 1
    if j < m:                     # trainers[j] 是「刚够用」的那位
        ans += 1
        j += 1                     # 双方各消耗一个
return ans
```

### 3.3 为什么指针 j 不回退

`j` 指向的训练师被跳过，是因为他**连当前最弱的未处理运动员都带不动**；后续运动员只会更强，因此他永远不会出现在任何匹配里——跳过是安全的、不可逆的。每个训练师至多被 `j` 越过或消耗一次，匹配逻辑与归并的双指针同构，只是「相等即消耗」换成了「足够强才消耗」。

### 3.4 示例演算

![示例 1 演算表](images/bw87_q2_example_walkthrough.svg)

**示例 1**：排序后 players = `[4,7,9]`，trainers = `[2,5,8,8]`。

| 步骤 | 当前运动员 | 训练师指针动作 | 结果 |
|------|-----------|----------------|------|
| 1 | 4 | 跳过 2（$2 < 4$），取 5 | 匹配，`ans = 1` |
| 2 | 7 | 8 ≥ 7，直接取 8 | 匹配，`ans = 2` |
| 3 | 9 | 剩余 8 带不动（$8 < 9$），跳过 | 出局 |

返回 $2$。

**示例 2**：players = `[1,1,1]`，trainers = `[10]`。第一个 1 消耗掉 10，后两个 1 面对空训练师序列，返回 $1$。

## 4. 算法细节

1. **匹配方向**：题意是「运动员能力 ≤ 训练师能力」才可匹配——「训练师带运动员」，不是双向比较。排序后条件变成 `trainers[j] >= p` 即可消耗。
2. **跳过与消耗共用一个指针**：`while (trainers[j] < p) ++j` 负责淘汰废训练师；`++j` 负责消耗。两件事写在一个循环里最容易错，拆开反而清晰（见参考代码）。
3. **「刚够用」的最优性**：给当前运动员分配**最弱可用**训练师，等价于保留所有更强训练师给后续——这是贪心的核心交换空间，证明见 §5。
4. **不要重复合并**：有写法把两个数组归并成一个 `(值, 类型)` 序列再扫描，本质相同但代码更长、排序关键字更绕，双指针直白版更不易错。
5. **溢出**：只有比较没有求和，`int` 足够（$10^9 < 2^{31}$）。

## 5. 正确性证明

**引理（存在与贪心一致的最优解）**：设 $P$ 为当前最弱的未匹配运动员，$T$ 为所有能带 $P$ 的训练师中最弱的一个。若 $P$ 根本无可行训练师，则任何最优解都不含 $P$，删掉 $P$ 不影响匹配数；否则**存在**一个最大匹配把 $P$ 与 $T$ 配成一对。

**证明**：取任意最大匹配 $\text{OPT}$。

- 若 $T$ 在 $\text{OPT}$ 中空闲：若 $P$ 在 $\text{OPT}$ 中也空闲，加上边 $(P, T)$ 得到更大的匹配，与最优性矛盾——故此情形只可能是 $P$ 已配上某个训练师 $T'$，把 $(P, T')$ 换成 $(P, T)$（由 $T$ 的定义 $P \le T$ 可行），仍是最大匹配且包含 $(P,T)$。
- 若 $T$ 在 $\text{OPT}$ 中被某运动员 $P'$ 占用：把 $(P', T)$ 换成 $(P, T)$ 与 $(P', T')$，其中 $T'$ 是 $\text{OPT}$ 中原本配给 $P$ 的训练师（若 $P$ 原本空闲，则改为单换，匹配数不变）。可行性链：$P \le T$（$T$ 的定义）；$T \le T'$（$T$ 是能带 $P$ 的训练师中最弱的，而 $T' \ge P$ 说明 $T'$ 也能带 $P$，故 $T \le T'$）；于是 $P' \le T \le T'$（$P'$ 原本配 $T$）。交换后匹配数不增不减，仍是最大匹配且包含 $(P, T)$。∎

![交换论证：把任意最优解改造成小配小](images/bw87_q2_exchange_argument.svg)

**定理（贪心最优）**：排序后「弱运动员配最弱可行训练师」的贪心输出的匹配数等于二分图最大匹配。

**证明**：对运动员总数归纳。第一轮：$P$ 是全体最弱者，$T$ 是其最弱可行训练师，由引理存在包含 $(P, T)$ 的最大匹配 $\text{OPT}$。将 $P, T$ 从两侧删去，剩下的子问题中贪心的后续决策与「$\text{OPT} \setminus \{(P,T)\}$ 是其最大匹配」完全同构（贪心在剩余运动员上的行为恰是子问题上的同一贪心）。由归纳假设贪心在子问题上取到最大值，故贪心总数 $= 1 + |\text{OPT} \setminus \{(P,T)\}| = |\text{OPT}|$。若 $P$ 无可行训练师，贪心跳过 $P$，同理归纳于其余运动员。∎

## 6. 复杂度分析

- **时间**：$O(n \log n + m \log m)$——排序主导；扫描阶段两个指针各走到底，$O(n + m)$。
- **空间**：$O(1)$ 额外（C++ 原地 `sort`）；Python 的 `list.sort()` 同样原地，只有递归栈 $O(\log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int matchPlayersAndTrainers(vector<int>& players, vector<int>& trainers) {
        sort(players.begin(), players.end());
        sort(trainers.begin(), trainers.end());
        int m = (int)trainers.size(), j = 0, ans = 0;
        for (int p : players) {                      // 从最弱的运动员开始
            while (j < m && trainers[j] < p) ++j;    // 太弱的训练师永远没用了
            if (j < m) { ++ans; ++j; }               // 匹配成功，双方各进一步
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def matchPlayersAndTrainers(self, players: list[int], trainers: list[int]) -> int:
        players.sort()
        trainers.sort()
        j = ans = 0
        m = len(trainers)
        for p in players:                     # 从最弱的运动员开始
            while j < m and trainers[j] < p:  # 训练师太弱，永久淘汰
                j += 1
            if j < m:                         # 匹配成功，各前进一位
                ans += 1
                j += 1
        return ans
```

> 💡 两份代码均通过官方示例（`2`、`1`）与全灭边界（`0`），并与**独立实现的匈牙利算法**（增广路最大匹配）做了 2 万组（C++）/ 4 千组（Python）随机对拍（$n, m \le 7$，值域 $[1,12]$ 保证重复值密集），`mismatch = 0`。

## 8. 边界情况与易错点

1. **条件是 `players[i] <= trainers[j]`**：相等时可以匹配（"能力值小于等于"），比较写成 `<` 会漏解——示例 1 中 `players[1]=7` 配 `8` 没问题，但 `[7]` 配 `[7]` 应输出 1。
2. **跳过训练师后别让运动员出局**：`while` 只淘汰训练师；训练师耗尽（`j == m`）时当前运动员出局，但**不能 break 外层**——后面的运动员本来也配不上（更弱训练师已没了），`if (j < m)` 判断自然处理，但写成内层 `else break` 也对；千万别在外层直接 `return`。
3. **两边都必须排序**：只排一边会错——贪心依赖「运动员递增处理 + 训练师升序可用」两个前提。
4. **重复值**：大量相同能力值是常态（$10^5$ 个值挤在 $[1,10^9]$），双指针天然处理重复，无需去重。
5. **指针语义**：`j` 同时承担「淘汰」和「消耗」两个职责，写混会导致训练师被重复使用或提前废弃；参考代码把两者分开在 `while` 与 `if` 里。
6. **规模**：$O(n \log n)$ 在 $10^5$ 下约 $10^6$ 量级操作，远低于限制；但若误写 $O(n^2)$（每个运动员重新线性扫训练师），$10^{10}$ 必然超时。
