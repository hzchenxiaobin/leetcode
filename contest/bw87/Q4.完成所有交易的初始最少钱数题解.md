# LeetCode 完成所有交易的初始最少钱数 题解

## 1. 题目概述

- **标题 / 题号**：完成所有交易的初始最少钱数（#2412，hard）
- **链接**：https://leetcode.cn/problems/minimum-money-required-before-transactions/
- **来源**：LeetCode 第 87 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、排序（实现只需一次线性扫描）

**题意**：`transactions[i] = [cost_i, cashback_i]` 描述第 $i$ 笔交易：做它之前手里必须**至少有** `cost_i` 的钱，做完后钱数变化 $-\text{cost}_i + \text{cashback}_i$。所有交易要以**某种顺序**恰好各做一次，而题目要求：无论对方采用**哪一种**顺序，你都能全程走完。求满足这一保证的最少初始钱数。

**约束**：

- $1 \le \text{transactions.length} \le 10^5$
- $0 \le \text{cost}_i, \text{cashback}_i \le 10^9$

## 2. 示例

**示例 1**

```text
输入：transactions = [[2,1],[5,0],[4,2]]
输出：10
解释：初始 10 元时任意顺序都能完成；可以证明 9 元不行
      （顺序 [2,1] → [5,0] → [4,2] 在第三步前只剩 3 < 4）。
```

**示例 2**

```text
输入：transactions = [[3,0],[0,3]]
输出：3
解释：顺序 [[3,0],[0,3]] 需要初始 3 元；顺序 [[0,3],[3,0]] 需要 0 元。
      要扛住最坏顺序，初始钱数取 3。
```

**示例 3（自造，两类交易并存）**

```text
输入：transactions = [[10,5],[5,10]]
输出：10
解释：亏损块 Σloss = 5，亏损最大 cashback = 5，盈利最大 cost = 5；
      answer = 5 + max(5, 5) = 10。最坏顺序 [10,5] → [5,10]：
      10 ≥ 10 → 5，5 ≥ 5 → 10，峰值需求恰为 10。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $n!$ 个顺序，对每个顺序模拟一遍取「所需初始钱数」的最大值。$n \ge 9$ 就跑不动，$n \le 10^5$ 完全不可行。但暴力给了我们一个关键的**公式化**视角（见引理 1）：固定顺序下所需的钱数不需要逐步模拟，它是若干「峰值」的最大值。本题的胜负手正是把这个 $\max$ 的 $\max$（对顺序再取最大）**直接算出来**。

### 3.2 核心观察：交易二分 + 最坏顺序「先亏后赚」

![交易二分：亏损块与盈利块](images/bw87_q4_split_model.svg)

按净变化 $d_i = \text{cost}_i - \text{cashback}_i$ 的符号把交易分成两类：

- **亏损交易**（$\text{cashback}_i < \text{cost}_i$，$d_i > 0$）：做一笔钱包薄一层，记集合 $L$，净损失总和 $\text{Σloss} = \sum_{i \in L} d_i$；
- **盈利交易**（$\text{cashback}_i \ge \text{cost}_i$，$d_i \le 0$）：做一笔钱包不降反（可能）升，记集合 $E$。

「任意顺序都能完成」=「**最坏顺序**也能完成」。最坏顺序的结构非常清晰：**所有亏损交易在前**（把钱包一路压到最低），**盈利交易在后**（收成被推迟到最后）。直观上，越早做盈利越「缓解」，所以对手会把这些缓解全部押后；而亏损怎么排都不影响最终亏损总量 $\text{Σloss}$，只影响中途哪一步最卡。

### 3.3 峰值公式：answer = Σloss + max(最大亏损 cashback, 最大盈利 cost)

![峰值推导：谁在最瘪的钱包前伸手](images/bw87_q4_peak_formula.svg)

固定顺序后，做第 $k$ 笔交易前的钱数是「初始钱减去前面各笔净损失之和」，于是第 $k$ 步的约束
$$M \ge \text{cost}_k + \sum_{\text{排在 } k \text{ 前面的 } t} d_t\text{。}$$
要扛住所有顺序，就取「顺序 × 步骤」的双重最大值。对每个关键交易 $k$，让上式最大化的排法是：把所有 $d_t > 0$ 的交易（亏损交易）排到 $k$ 前面，其余往后。于是峰值只可能是两种形态：

- $k$ 是**亏损**交易：前面能放「其他所有亏损」（自己不能再放自己），峰值 $= \text{cost}_k + (\text{Σloss} - d_k) = \text{Σloss} + \text{cashback}_k$，对 $k \in L$ 取最大即 $\text{Σloss} + \max_L \text{cashback}$；
- $k$ 是**盈利**交易：前面能放「全部亏损」，峰值 $= \text{cost}_k + \text{Σloss}$，对 $k \in E$ 取最大即 $\text{Σloss} + \max_E \text{cost}$。

两者取大：
$$\boxed{\ \text{answer} = \text{Σloss} + \max\bigl(\max_{L} \text{cashback},\ \max_{E} \text{cost}\bigr)\ }$$
（某一类为空时跳过对应项；两类都空不可能——每笔交易必属其一。）

### 3.4 示例演算

![示例演算：资金曲线与卡脖子的一步](images/bw87_q4_example_walkthrough.svg)

**示例 1**：三笔全是亏损，$d = 1, 5, 2$，$\text{Σloss} = 8$；最大 cashback $= 2$（来自 `[4,2]`）。answer $= 8 + 2 = 10$。对应最坏顺序 `[2,1] → [5,0] → [4,2]`：$10 \to 9 \to 4 \to 2$，第三步动手前钱包恰剩 4，正好卡在 cost $=4$ 上——少一分钱这个顺序就断在 `[4,2]` 的门口。

**示例 2**：$L = \{[3,0]\}$（$d = 3$），$E = \{[0,3]\}$。$\text{Σloss} = 3$，$\max_L \text{cashback} = 0$，$\max_E \text{cost} = 0$，answer $= 3 + \max(0,0) = 3$。

## 4. 算法细节

1. **一次线性扫描足够**：公式只用到三个统计量——$\text{Σloss}$、$\max_L \text{cashback}$、$\max_E \text{cost}$。官方标签里的「排序」是**推导视角**（把最坏顺序想清楚需要排序思想），实现上不必排序。
2. **分类边界**：`cashback < cost` 为亏损、`cashback >= cost` 为盈利。$d_i = 0$ 的「打平」交易归入盈利类——它不进 $\text{Σloss}$，但它的 cost 参与 $\max_E \text{cost}$，这样上界证明里的不等式方向才一致。
3. **两类都空不存在**，但**单类为空**要处理：全盈利时 answer $= \max \text{cost}$；全亏损时 answer $= \text{Σloss} + \max \text{cashback}$。用 $-1$ 哨兵或分别判空都可以，参考代码用 `bestBack` / `bestCost` 初始 $-1$ 再统一取 max。
4. **溢出是本题最大陷阱**：$n \le 10^5$、每笔净损失至多 $10^9$，$\text{Σloss}$ 可达 $10^{14}$，加上 cashback 后仍在 $10^{14}$ 量级——**必须 `long long`**（C++）；Python 无此虑。返回类型 metaData 也标了 `long`。
5. **cashback 为 0 的亏损交易**：完全合法（`[5,0]` 就是），不要在分类时把它当边界特判掉。
6. **cost 为 0 的盈利交易**：动手门槛为 0，但它的 cashback 照常进钱包；它对 answer 的贡献只可能通过 $\max_E \text{cost} = 0$ 体现。

## 5. 正确性证明

**引理 1（固定顺序的需求公式）**：对固定顺序 $t_1, t_2, \dots, t_n$（$d_k = \text{cost}_k - \text{cashback}_k$），以初始钱数 $M$ 依次完成全部交易的充要条件是
$$M \ \ge\ \max_{1 \le k \le n} \Bigl(\text{cost}_{t_k} + \sum_{s < k} d_{t_s}\Bigr)\text{，}$$
且该式右端就是此顺序所需的最少初始钱数。

**证明**：做第 $k$ 笔前手里的钱为 $M - \sum_{s<k} d_{t_s}$，约束它 $\ge \text{cost}_{t_k}$，移项即上式中第 $k$ 项。对全部 $k$ 取交即得充要条件；右端等于「所有步骤约束的最大值」，取等号的 $M$ 可行，再小一步即违反。∎

**引理 2（上界）**：令 $W = \max\bigl(\max_{L} \text{cashback},\ \max_{E} \text{cost}\bigr)$（空类跳过），则 $M^{\star} = \text{Σloss} + W$ 使得**任意**顺序都能完成。

**证明**：任取顺序与其中第 $k$ 步。前缀净损失 $\sum_{s<k} d_{t_s}$ 中，所有 $d > 0$ 的项都来自亏损类，故不超过 $\sum_{i \in L} d_i = \text{Σloss}$；盈利类的 $d \le 0$ 放进前缀只会变小。分两种情形放大引理 1 的第 $k$ 项：

- 若 $k \in L$：前缀里属于 $L$ 的至多是 $L \setminus \{k\}$（自己不可能排在自己前面），于是
  $$\text{cost}_k + \sum_{s<k} d_{t_s} \le \text{cost}_k + \text{Σloss} - d_k = \text{Σloss} + \text{cashback}_k \le \text{Σloss} + W\text{；}$$
- 若 $k \in E$：$\text{cost}_k + \sum_{s<k} d_{t_s} \le \text{cost}_k + \text{Σloss} \le \text{Σloss} + W$。

两种情形都 $\le M^{\star}$，由引理 1 该顺序在 $M^{\star}$ 下可行。∎

**引理 3（下界）**：存在一个顺序，其所需初始钱数恰为 $M^{\star} = \text{Σloss} + W$，故答案不能小于 $M^{\star}$。

**证明**：按 $W$ 的取值分两种构造：

- 若 $W = \text{cashback}_{k^{\star}}$（$k^{\star} \in L$）：取顺序「$L \setminus \{k^{\star}\}$ 任意排 $\to k^{\star} \to$ 盈利类任意排」。第 $k^{\star}$ 步的前缀净损失恰为 $\text{Σloss} - d_{k^{\star}}$，于是该步需求 $= \text{cost}_{k^{\star}} + \text{Σloss} - d_{k^{\star}} = \text{Σloss} + \text{cashback}_{k^{\star}} = M^{\star}$。
- 若 $W = \text{cost}_{k^{\star}}$（$k^{\star} \in E$）：取顺序「$L$ 全在前 $\to k^{\star} \to$ 其余盈利任意排」。第 $k^{\star}$ 步的前缀净损失恰为 $\text{Σloss}$，该步需求 $= \text{cost}_{k^{\star}} + \text{Σloss} = M^{\star}$。

两种构造都让该顺序的最少初始钱数 $\ge M^{\star}$（引理 1 的最大值中至少含这一项）。∎

**定理**：答案 $= \text{Σloss} + \max\bigl(\max_{L} \text{cashback},\ \max_{E} \text{cost}\bigr)$。

**证明**：引理 2 说明 $M^{\star}$ 对所有顺序可行（充分），引理 3 说明任何更小的钱数都会在构造出的那个顺序下失败（必要），故 $M^{\star}$ 是最小的满足「任意顺序可完成」的钱数。∎

## 6. 复杂度分析

- **时间**：$O(n)$——一次扫描，每笔交易 $O(1)$ 分类与更新。
- **空间**：$O(1)$——三个统计变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minimumMoney(vector<vector<int>>& transactions) {
        long long loss = 0;              // 亏损交易(cashback < cost)的净损失总和
        long long bestBack = -1;         // 亏损交易中的最大 cashback
        long long bestCost = -1;         // 盈利交易中的最大 cost
        for (auto& t : transactions) {
            if (t[1] < t[0]) {           // 亏损：累计净损失
                loss += t[0] - t[1];
                bestBack = max(bestBack, (long long)t[1]);
            } else {                     // 盈利：只关心最大 cost
                bestCost = max(bestCost, (long long)t[0]);
            }
        }
        long long extra = 0;
        if (bestBack >= 0) extra = bestBack;
        if (bestCost >= 0) extra = max(extra, bestCost);
        return loss + extra;
    }
};
```

### Python

```python
class Solution:
    def minimumMoney(self, transactions: list[list[int]]) -> int:
        loss = 0                            # 亏损交易的净损失总和
        best_back = best_cost = -1          # 亏损最大 cashback / 盈利最大 cost
        for cost, cashback in transactions:
            if cashback < cost:              # 亏损：累计净损失
                loss += cost - cashback
                best_back = max(best_back, cashback)
            else:                            # 盈利：只留最大 cost
                best_cost = max(best_cost, cost)
        return loss + max(best_back, best_cost)
```

> 💡 两份代码均通过官方示例（`10`、`3`）与自造双类并存用例（`10`），并与「枚举全部 $n!$ 顺序取峰值最大」的暴力实现做了 **6 万组（C++，$n \le 7$）/ 1500 组（Python）** 随机对拍（值域 $[0,13]$，覆盖 cost=0、cashback=0、打平交易），`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出**：$\text{Σloss} \le 10^5 \times 10^9 = 10^{14}$，`int` 必炸，C++ 全程 `long long`，包括 `bestBack`/`bestCost` 的中转（避免 `max(int, long long)` 的隐式转换坑，参考代码显式转型）。
2. **全盈利 / 全亏损**：单类为空时直接跳过对应项——判空逻辑别写成 `max(bestBack, bestCost)` 初值 0 的偷懒版：当两类都存在但亏损 cashback 与盈利 cost 均为 0 时两者等价，可一旦初值取 0 而某类为空、另一类的 max 恰为 0，结果碰巧也对；真正危险的是**初值取正数**或把 $-1$ 直接加进答案。参考代码的「先判存在再合并」最稳。
3. **`cashback == cost` 归盈利**：打平交易不进 $\text{Σloss}$，但其 cost 参与 $\max_E$；若错误归入亏损类，$\text{Σloss}$ 不变但 $\max_L \text{cashback}$ 会虚高（把 cost 当 cashback 用），会算大。
4. **别真的去排序**：按 cost 降序、cashback 升序排是推导最坏顺序时的思想工具；实现只需两个 max，排序版（先亏后赚拼一个具体顺序再扫峰值）同样正确但多 $O(n \log n)$ 且代码长。
5. **「任意顺序」是全称量词**：答案是「最坏顺序」的需求，不是「最好顺序」的——示例 2 里最优顺序只要 0 元，但答案必须是 3。读题时把「任意一种」圈出来。
6. **钱可以为 0**：`cost = 0` 的交易随时能做，`cashback = 0` 的亏损交易一分不回，都不需要特判。
