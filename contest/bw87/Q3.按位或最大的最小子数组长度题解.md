# LeetCode 按位或最大的最小子数组长度 题解

## 1. 题目概述

- **标题 / 题号**：按位或最大的最小子数组长度（#2411，medium）
- **链接**：https://leetcode.cn/problems/smallest-subarrays-with-maximum-bitwise-or/
- **来源**：LeetCode 第 87 场双周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、二分查找、滑动窗口

**题意**：给定长度为 $n$ 的非负整数数组 `nums`。对每个下标 $i$，在所有**以 $i$ 开头**的非空子数组中，找出按位或运算值**最大**的那些；再在其中挑**最短**的。返回 `answer[i]` 为这个最短长度。换言之，`answer[i]` 是最小的 $j - i + 1$，使得 $\text{OR}(\text{nums}[i..j]) = \max_{i \le k \le n-1} \text{OR}(\text{nums}[i..k])$。

**约束**：

- $1 \le n \le 10^5$
- $0 \le \text{nums}[i] \le 10^9$（注意有 $0$，且不足 $2^{30}$）

## 2. 示例

**示例 1**

```text
输入：nums = [1,0,2,1,3]
输出：[3,3,2,2,1]
解释：任何起点开始，能达到的最大 OR 都是 3。
- i=0：最短子数组 [1,0,2]；i=1：[0,2,1]；i=2：[2,1]；i=3：[1,3]；i=4：[3]。
```

**示例 2**

```text
输入：nums = [1,2]
输出：[2,1]
解释：i=0 时 [1,2] 的 OR = 3 是最大的；i=1 只能取 [2]。
```

**示例 3（边界补充）**

```text
输入：nums = [0,0,0]
输出：[1,1,1]
解释：后缀 OR 全为 0，取 nums[i] 自己即可，长度恒为 1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 从左到右累加 OR，直到追平后缀 OR——单次最坏 $O(n)$（如 `nums = [大值, 0, 0, ..., 0]` 时每个 $i$ 都要扫到底... 反例上更常见的是「高位 1 稀疏」的数据），总体 $O(n^2)$，$n = 10^5$ 时 $10^{10}$ 次操作，超时。

一个「正确但不优」的中间档是**二分 + 可重复贡献的区间 OR 稀疏表**：固定 $i$ 时 $\text{OR}(i..j)$ 关于 $j$ 单调不减，可以二分最小 $j$，配合 $O(1)$ 查询的稀疏表做到 $O(n \log n)$。能过，但码量大（$n \log n$ 张表），且没有利用「**每个 bit 只关心最近的置位**」这一结构。

### 3.2 核心观察：目标是后缀 OR，OR 只增不减

![核心观察：后缀OR是最大目标，窗口OR只增不减](images/bw87_q3_suffix_or_monotone.svg)

以 $i$ 开头的子数组都是后缀 $\text{nums}[i..n-1]$ 的子段，而 OR 随元素增多**只会添位、不会撤位**，所以「最大 OR」就是整个后缀的 OR：$\text{sufOR}[i] = \text{nums}[i] \,|\, \text{sufOR}[i+1]$。于是问题变成：找最小的 $j \ge i$ 使 $\text{OR}(i..j) = \text{sufOR}[i]$。

滑动窗口在这里**失灵**：左端右移需要「从 OR 中撤销一个元素」，OR 不支持逆运算。突破口是把 OR 拆到每个二进制位上看。

### 3.3 逐位处理：每个 bit 的「最近置位下标」

![逐位观察：每个bit的最近置位下标决定最短终点](images/bw87_q3_perbit_next.svg)

维护数组 $\text{nxt}[b]$：**当前下标 $i$ 及其右侧**，第一个第 $b$ 位为 1 的位置（不存在则记 $n$）。窗口 $[i, j]$ 的 OR 等于 $\text{sufOR}[i]$，当且仅当后缀中出现的每个 bit $b$ 都在窗口里有代表，即
$$j \ \ge\ \max_{b\ \text{出现在后缀中}} \text{nxt}[b]\text{。}$$
而 $\text{end}(i) = \max\bigl(i,\ \max_b \text{nxt}[b]\bigr)$ 本身就 $\ge i$，所以
$$\text{answer}[i] = \text{end}(i) - i + 1\text{。}$$

从右往左扫一遍：处理 $i$ 时先用 $\text{nums}[i]$ 的二进制刷新各 $\text{nxt}[b]$（若 $\text{nums}[i]$ 第 $b$ 位为 1，则 $\text{nxt}[b] = i$，否则保留来自 $i+1$ 的值——依然正确，因为 $i$ 处这一位没有置位）；再取所有「值 $< n$ 的 $\text{nxt}[b]$」的最大值作为 $\text{end}$。全程 $O(n \cdot 30)$。

> 💡 `nxt[b] < n` 恰好等价于「bit $b$ 出现在后缀中」；全 0 后缀没有任何 bit 满足该条件，$\text{end} = i$ 退化为单元素窗口，公式自然覆盖。

### 3.4 示例演算

![示例全程演算表](images/bw87_q3_example_walkthrough.svg)

以 `nums = [1,0,2,1,3]`（二进制 `001, 000, 010, 001, 011`）为例：

| $i$ | 后缀 OR | bit0 最近 | bit1 最近 | end | answer |
|-----|---------|-----------|-----------|-----|--------|
| 0 | 3 | 0 | 2 | 2 | 3 |
| 1 | 3 | 3 | 2 | 3 | 3 |
| 2 | 3 | 3 | 2 | 3 | 2 |
| 3 | 3 | 3 | 4 | 4 | 2 |
| 4 | 3 | 4 | 4 | 4 | 1 |

例如 $i = 1$ 时：后缀里 bit0 最近的 1 在下标 3（值 1）、bit1 最近的 1 在下标 2（值 2），两者都必须纳进窗口，$\text{end} = \max(3, 2) = 3$，长度 $3 - 1 + 1 = 3$，即 `[0,2,1]`。

## 4. 算法细节

1. **位数取 30**：$\text{nums}[i] \le 10^9 < 2^{30}$，第 $29$ 位是最高可能位，`B = 30` 覆盖 $b \in [0, 29]$。取大无妨（多扫常数个位），取小（如 20）会漏高位。
2. **`nxt` 初值设 $n$**：充当「正无穷 / 不存在」哨兵。判断「bit 是否出现在后缀」就是 `nxt[b] < n`，与「是否参与 max」合二为一，不需要再维护一个后缀 OR 变量（当然同时维护 `suf |= nums[i]` 再检查其位也可以，两者等价）。
3. **end 的初值是 $i$**：至少要取 $\text{nums}[i]$ 自己；全 0 后缀时没有 bit 参与 max，答案恰为 1。
4. **从右往左**的方向由信息流向决定：`nxt[b]` 是「右侧最近置位」，天然由右向左传播；若坚持从左往右则需「右侧最近」的前向信息，写起来别扭且易错。
5. **刷新与查询的顺序**：先刷新（把 $i$ 自己的位并进 `nxt`）再取 max；顺序颠倒会把 $i$ 自己贡献的位漏掉（当 $\text{nums}[i]$ 的某位是后缀中该位的唯一来源时答案会偏大）。
6. **复杂度权衡**：$O(n \cdot 30)$ 在 $10^5$ 规模约 $3 \times 10^6$ 次位运算，比稀疏表 $O(n \log n)$（$\sim 1.7 \times 10^6$ 个表项，还要二分 $O(\log n)$ 次）更省内存且常数小。

## 5. 正确性证明

**引理 1（OR 的单调性与目标）**：固定 $i$，记 $B_{ij} = \text{OR}(\text{nums}[i..j])$，则 $B_{ij}$ 关于 $j$ 单调不减（按位集包含意义），且 $\max_{j \ge i} B_{ij} = \text{OR}(\text{nums}[i..n-1]) = \text{sufOR}[i]$。

**证明**：窗口变大只增元素，OR 的位集是各元素位集之并，只增不减；取 $j = n-1$ 即取到整个后缀的并，显然是上界且可达到。∎

**引理 2（逐位等价条件）**：设 $\text{nxt}[b](i) = \min\{k \ge i : \text{nums}[k] \text{ 的第 } b \text{ 位为 } 1\}$（不存在记 $+\infty$）。则 $B_{ij} = \text{sufOR}[i]$ 当且仅当对**每个**满足 $\text{nxt}[b](i) < \infty$ 的 $b$ 都有 $j \ge \text{nxt}[b](i)$。

**证明**：$B_{ij}$ 的位集 $= \{b : \exists k \in [i, j],\ \text{nums}[k] \text{ 第 } b \text{ 位为 } 1\} = \{b : \text{nxt}[b](i) \le j\}$；$\text{sufOR}[i]$ 的位集 $= \{b : \text{nxt}[b](i) < \infty\}$。由引理 1 的单调性，前者是后者的子集；相等当且仅当所有 $\text{nxt}[b](i) < \infty$ 的位都满足 $\text{nxt}[b](i) \le j$。∎

**定理（算法正确）**：从右向左一次扫描中，处理完下标 $i$ 后数组满足「$\text{nxt}[b] = \text{nxt}[b](i)$（若存在）否则 $n$」，且 $\text{answer}[i] = \max(i, \max_{\text{nxt}[b] < n} \text{nxt}[b]) - i + 1$ 是正确答案。

**证明**：对 $i$ 从 $n-1$ 到 $0$ 归纳。初始（尚未处理任何下标）$\text{nxt}[b] = n$，视为 $\text{nxt}[b](n) = \infty$ 的表示，成立。设处理 $i+1$ 后成立。处理 $i$ 时：若 $\text{nums}[i]$ 第 $b$ 位为 1，则 $i$ 是 $\ge i$ 的第一个置位，置 $\text{nxt}[b] = i$ 正确；否则 $i$ 处无置位，$\text{nxt}[b](i) = \text{nxt}[b](i+1)$，保留旧值正确。故不变量保持。又「$\text{nxt}[b] < n$」与「$b$ 出现在后缀 $\text{nums}[i..]$ 中」互为充要，由引理 2，最小的合法 $j$ 即所有这些 $\text{nxt}[b]$ 的最大值；同时 $j \ge i$ 自动满足（每个 $\text{nxt}[b] \ge i$），且 $B_{ii} \le \text{sufOR}[i]$ 保证答案至少为 1，与 $\max(i, \cdot)$ 的写法一致。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot B)$，$B = 30$——每个下标常数次刷新加一次全位扫描，约 $6 \times 10^6$ 次位运算（$n = 10^5$）。
- **空间**：$O(B)$ 额外（`nxt` 数组 30 个整数），不计输出数组 `answer` 的 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> smallestSubarrays(vector<int>& nums) {
        int n = (int)nums.size(), B = 30;
        vector<int> nxt(B, n), ans(n);   // nxt[b]: 下标 >= i 处 bit b 的最近置位位置
        for (int i = n - 1; i >= 0; --i) {
            for (int b = 0; b < B; ++b)
                if (nums[i] >> b & 1) nxt[b] = i;
            int end = i;                 // 至少要取 nums[i] 自己
            for (int b = 0; b < B; ++b)
                if (nxt[b] < n) end = max(end, nxt[b]);
            ans[i] = end - i + 1;        // 最短终点 = 后缀所需各 bit 的最远来源
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def smallestSubarrays(self, nums: list[int]) -> list[int]:
        n, B = len(nums), 30
        nxt = [n] * B                       # nxt[b]: >= i 处 bit b 的最近置位下标
        ans = [0] * n
        for i in range(n - 1, -1, -1):
            for b in range(B):
                if nums[i] >> b & 1:
                    nxt[b] = i
            end = i                         # 至少取 nums[i] 自己
            for b in range(B):
                if nxt[b] < n:              # bit b 出现在后缀中
                    end = max(end, nxt[b])
            ans[i] = end - i + 1
        return ans
```

> 💡 两份代码均通过官方示例（`[3,3,2,2,1]`、`[2,1]`）与全零数组边界，并与「对每个 $i$ 从右扩展直到 OR 追平后缀 OR」的暴力实现做了 4 万组（C++，交替 $[0,8)$ 小值域与 $[0,10^9]$ 大值域）/ 6 千组（Python）随机对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **全 0 数组**：后缀 OR 为 0，没有任何 bit 满足 `nxt[b] < n`，答案全为 1。`end` 初值必须是 $i$ 而不是 $n$ 或 $0$。
2. **单元素**：$n = 1$ 时答案恒为 `[1]`，循环只跑一轮，公式自然覆盖。
3. **位数上界**：$\text{nums}[i]$ 可达 $10^9$，二进制占 30 位（$2^{30} \approx 1.07 \times 10^9$）。`B = 30` 是安全下限；写成 `B = 31` 也行，写成 20 则在 $[2^{20}, 10^9]$ 的大值数据上必错。
4. **方向搞反**：从左往右扫需要「右侧最近置位」这种未卜先知的信息；除非再倒一遍，否则必然出错。本题的信息天然从右向左流。
5. **刷新顺序**：先用 `nums[i]` 刷新 `nxt`、再算 `end`。若先算 end 后刷新，会把 `nums[i]` 独有的高位漏算（该位在后缀中唯一来源就是 $i$ 自己时，答案会错误地越过 $i$ 往右找）。
6. **答案定义里的「最短」**：由于 OR 单调不减，「OR 最大且最短」=「第一次追平后缀 OR 的位置」——前提是引理 1 的单调性；若把 OR 换成异或（无单调性），本题的整套论证全部失效。
7. **别用滑动窗口硬撤左端**：OR 不满足可减性，`B = B | x` 容易、`B 去掉 x 的贡献` 不可能——这是本题与「最长子数组」类滑窗题的本质区别。

**延伸思考**：本题的通用武器是「**OR 问题按位拆解**」：OR 的代数结构（幂等、交换、单调）使每一位独立，于是「最短窗口」=「每个所需 bit 的最近来源的最大值」。同一思想可以解决：或值恰好为 $X$ 的最短子数组（把「所需位集合」换成 $X$ 与后缀 OR 的交）、或值至多为 $X$ 的子数组计数（按位独立后转成滑窗乘积）、以及动态版（支持修改的逐位线段树，每个节点维护 30 个 bit 的存在性）。反过来，如果运算换成 GCD（同样幂等但「撤回」困难）、换成乘积（可以除但有 0 的干扰），处理手法都要重新设计——按位拆解是 OR/AND 的专属红利。
