# LeetCode 分割数组为连续子序列 题解

## 1. 题目概述

- **标题 / 题号**：分割数组为连续子序列（#659，medium）
- **链接**：https://leetcode.cn/problems/split-array-into-consecutive-subsequences/
- **来源**：LeetCode 第 45 场周赛 Q3
- **难度**：中等
- **标签**：贪心，数组，哈希表，堆（优先队列）

**题意**：给定一个**非递减**数组 `nums`，判断能否把它**整体**切成一个或多个子序列（每个元素恰好用一次、不重不漏），使得每个子序列都是**公差为 1 的连续递增序列**，并且每个子序列的长度都**至少为 3**。能则返回 `true`，否则 `false`。

注意子序列不要求连续（可以跳过元素），所以本质是「给每个元素找一个前驱 `x−1` 或自己当链头」，把整张数组拆成若干条连续数链。

**约束**：

- $1 \le \text{nums.length} \le 10^4$
- $-1000 \le \text{nums}[i] \le 1000$
- `nums` 按非递减顺序排列（相同值连续出现）

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,3,4,5]
输出：true
解释：[1,2,3] 与 [3,4,5] 两条链，长度都 ≥ 3。
```

**示例 2**

```text
输入：nums = [1,2,3,3,4,4,5,5]
输出：true
解释：[1,2,3,4,5] 与 [3,4,5]，两条链长度分别为 5 和 3。
```

**示例 3**

```text
输入：nums = [1,2,3,4,4,5]
输出：false
解释：第二个 4 既接不上任何以 3 结尾的链（只有一条且已被第一个 4 用掉），
      也凑不出 5、6 来新开一条链，无解。
```

## 3. 解题思路

### 3.1 暴力思路

按值从小到大的顺序处理每个元素，每个元素有两种归宿：接到某条**以 `v−1` 结尾**的链尾部，或自己开一条新链。回溯枚举所有接法，最后检查是否所有链长度都 $\ge 3$。

分支数随重复元素个数指数增长，且状态是「每条链的（结尾值，当前长度）」集合，规模指数级，$n = 10^4$ 完全不可行。必须找到一种「不用回头」的决策规则。

### 3.2 核心观察：延长永远优于新建

![延长优先与新建兜底两条分支](images/wc45_q3_greedy_priority.svg)

**观察 1（长度只有两种有效状态）**：一条链相对于未来的全部意义，只取决于它「还欠不欠元素」。长度 $< 3$ 的链**必须**被继续延长，否则永远无法达标；长度 $\ge 3$ 的链**随时可以收尾**，没有任何义务。所以「长度」这个维度可以被压成两档。

**观察 2（只造长链，就没有欠账）**：如果每次新建链都一次性吃掉 `x`、`x+1`、`x+2` 三个元素，那么新链**出生即达标**，之后只会更长。于是「长度 $\ge 3$」这条约束根本不需要在过程中反复检查，只在**建链那一刻**检查一对 `cnt[x+1]`、`cnt[x+2]` 即可。这正是贪心能「一遍过」的关键：把全局的长度约束转换成了局部的资源检查。

**观察 3（延长优于新建）**：处理值 $x$ 时只有三种选择——

1. 有链以 $x-1$ 结尾 → 用 $x$ 延长它，只消耗 1 个元素；
2. 没有链可接，但 `cnt[x+1]`、`cnt[x+2]` 都还有剩 → 新开一条 $(x, x+1, x+2)$，一次消耗 3 个元素；
3. 两者都不行 → $x$ 无处安放，直接 `false`。

**为什么必须优先选 1 而不是 2？** 因为「在 $x$ 处新建一条链」等价于「先把某条链延长到 $x$，再立刻连延长两次到 $x+1$、$x+2$」。两种做法消耗的 $x$ 个数相同，但新建会**提前锁死** $x+1$、$x+2$ 这两个更大的值；而延长把这两步推迟到真正需要时再花。值越大越稀缺（大值只能往后配，没有更小的数能来接它），所以省下 `x+1`、`x+2` 永远是好事——延长是弱占优的选择，且不需要任何回溯。

### 3.3 算法流程

![算法流程图](images/wc45_q3_algorithm_flow.svg)

```text
cnt[v]  = 值 v 还没被使用的个数
tail[v] = 当前以 v 结尾、长度 ≥ 3 的链的条数
for x in 所有不同值（升序）:
    while cnt[x] > 0:
        if tail[x-1] > 0:                       # ① 延长
            tail[x-1] -= 1; tail[x] += 1; cnt[x] -= 1
        elif cnt[x+1] > 0 and cnt[x+2] > 0:     # ② 新建长度 3 的链
            cnt[x] -= 1; cnt[x+1] -= 1; cnt[x+2] -= 1; tail[x+2] += 1
        else:
            return False                        # ③ 无处安放
return True
```

数组已经非递减，直接顺序扫描 `nums` 就等价于「按值升序处理」，不必额外排序；用哈希表存不同值时排序不同值即可。因为值域只有 $[-1000, 1000]$，也可以直接开 2001 个桶做到线性。

### 3.4 示例演算

![示例走查表](images/wc45_q3_example_walkthrough.svg)

对 `nums = [1,2,3,3,4,4,5,5]`（示例 2）：

| 步骤 | $x$ | `cnt[x]` | `tail` 进入时 | 动作 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 空 | `tail[0]=0`，但 `cnt[2]`、`cnt[3]` 有 → 新建 `[1,2,3]` |
| 2 | 2 | 0 | `{3:1}` | `cnt[2]=0`，跳过 |
| 3 | 3 | 1 | `{3:1}` | `tail[2]=0`，`cnt[4]`、`cnt[5]` 有 → 新建 `[3,4,5]` |
| 4 | 4 | 1 | `{3:1, 5:1}` | `tail[3]=1` → 延长，`[1,2,3]` 变 `[1,2,3,4]` |
| 5 | 5 | 1 | `{4:1, 5:1}` | `tail[4]=1` → 延长，变 `[1,2,3,4,5]` |

全部元素用完，返回 `true`，最终两条链是 `[1,2,3,4,5]` 与 `[3,4,5]`。

反例 `nums = [1,2,3,4,4,5]`（示例 3）：`x=1` 时新建 `[1,2,3]`，此时 `tail[3]=1`；`x=4` 的**第一个** 4 把这条链接走了，`tail[3]` 归零；**第二个** 4 想新建，需要 `cnt[6] > 0`，但没有 6，于是返回 `false`。

## 4. 算法细节

1. **`tail` 只统计「长度 $\ge 3$」的链，不记录具体长度**。这是整个贪心能用两个哈希表搞定的原因：既然建链时就已经是 3 个元素，之后所有链都达标，长度再没有区分价值。若允许建长度 1、2 的链，`tail` 就必须按长度分组（那才是堆/优先队列版本要维护的东西）。
2. **必须用 `while` 而不是 `if`**。同一个值 $x$ 可能出现很多次，每消耗一个 $x$，`tail[x-1]` 和 `cnt[x+1]` 都在变化，必须重新决策一次，直到 `cnt[x]` 归零。
3. **新建时要立刻扣掉 `cnt[x+1]`、`cnt[x+2]`**。因为建链已经「预订」了它们；如果只扣 `cnt[x]`，后面轮到 $x+1$、$x+2$ 时会把同一批元素再用一次，链就重叠了。
4. **判断条件是 `tail[x-1] > 0`，不是 `cnt[x-1] > 0`**。能接上去的只有「当前链尾正好是 $x-1$」的链；`cnt[x-1] > 0` 只说明还有没用的 $x-1$，那些元素再也接不到 $x$ 后面了（连续递增必须紧邻）。
5. **升序处理是必须的**。只有按值从小到大处理，才能保证「处理 $x$ 时，所有能接在 $x-1$ 后的链都已成型」。数组本身已非递减，按顺序扫一遍即可；若按哈希表的键遍历，记得先排序键。
6. **`tail` 减到 0 的键可以留着**（Python `Counter` 会自动返回 0），不需要删除，省掉判空逻辑。
7. **不需要回溯**：一旦进入分支 ③，说明当前的 $x$ 既接不上任何链、也凑不出后两个值，任何「换一种分法」的方案都不可能给它找到位置（见 §5 引理 3）。

## 5. 正确性证明

**引理 1（不变量）**：贪心运行过程中，它提交的每条链都是公差为 1 的连续递增序列，且长度恒 $\ge 3$。

**证明**：建链分支总是同时取出 $x, x+1, x+2$，新链长度恰为 3 且公差为 1；延长分支在「以 $x-1$ 结尾」的链尾追加 $x$，连续性与公差保持，长度只增不减。故不变。∎

**引理 2（延长不劣于新建）**：设处理值 $x$ 时贪心有一条以 $x-1$ 结尾的链 $C$，且 $C$ 长度 $\ge 3$。则「用 $x$ 延长 $C$」不会让任何合法划分从可行变为不可行。

**证明**：设 $P$ 是任意合法划分，考察 $P$ 中值 $x$ 的去处，只有两类：

- **$x$ 接在某条以 $x-1$ 结尾的链后**：把这条链「从 $x$ 起的尾巴」整体移交给 $C$（两条链在同一值 $x-1$ 处对接，对接后仍连续、且 $C$ 更长），原链保留下来的前缀因 $P$ 中每条链长度都 $\ge 3$ 而依然合法。改造后仍是合法划分，且 $C$ 拿到了 $x$。
- **$x$ 是某条新链 $D=(x, x+1, x+2, \dots)$ 的首元素**：把整条 $D$ 接到 $C$ 后面。$C$ 以 $x-1$ 结尾、$D$ 从 $x$ 开始，首尾相接得到一条更长的连续链，$D$ 原占用的元素一个不少地留在某条合法链里，链的总数减少但每条都 $\ge 3$。改造后 $C$ 同样包含 $x$。

两类的改造都只移动元素、不裁短任何链，因此 $P$ 改造后仍合法；也就是说，贪心选择延长后依然存在与之相容的合法划分。反之，如果 $P$ 把 $x$ 用在别处以省下 $x+1, x+2$，改造只会让 $x+1,x+2$ 更晚被占用，不会更差。∎

> 💡 一句话直觉：**新建 = 延长 + 立刻再延长两次**，两者消耗的 $x$ 相同，延长只是把对 $x+1$、$x+2$ 的占用向后推。推迟占用永远不会减少未来可选的方案数。

**引理 3（失败即不可行）**：若贪心在处理值 $x$ 时既没有以 $x-1$ 结尾的链，又缺少 $x+1$ 或 $x+2$ 可用，则不存在合法划分。

**证明**：由引理 2，可设合法划分 $P$ 与贪心此前所有决策相容，即 $P$ 的每条链都以贪心提交的某条链为前缀。此时「以 $x-1$ 结尾的链」在 $P$ 中同样不存在（否则该前缀会在贪心的 `tail` 里体现），所以 $P$ 中每个 $x$ 都只能作为新链的首元素；而任何合法链从 $x$ 开始，就必须包含 $x+1$ 与 $x+2$。贪心已把所有 $\le x$ 的元素安排完毕，`cnt[x+1]=0` 意味着 $P$ 也拿不出 $x+1$（同理 $x+2$），矛盾。故 $P$ 不存在。∎

**定理**：贪心返回 `true` 当且仅当 `nums` 可以被分割为若干长度 $\ge 3$ 的连续递增子序列。

**证明**：

- （$\Leftarrow$）设存在合法划分。由引理 2，每一步都可在保持合法性的前提下与贪心对齐；贪心用的每个判断都是「延长 / 新建 / 失败」三选一，前两者都由引理 2 保证不破坏可行性，因此不会走到失败分支，最终所有元素被消耗完，返回 `true`。
- （$\Rightarrow$）贪心返回 `true` 时，它提交的链覆盖了全部元素、互不相交，且由引理 1 每条长度 $\ge 3$、公差为 1，这本身就是一个合法划分。

结合引理 3（失败分支只在确实无解时触发），两者互为充要。∎

## 6. 复杂度分析

- **时间**：$O(n + U \log U)$，其中 $U$ 为不同值的个数。主循环里每个元素恰好被消耗一次（要么延长、要么作为新建链的一员），所以 `while` 的总迭代次数是 $n$；哈希表每次操作期望 $O(1)$。若用排序键遍历不同值，额外 $O(U \log U)$；值域仅 2001，直接开桶可降到 $O(n + V)$。由于 `nums` 已排序，用 `unordered_map` 统计后按键排序是最省事的写法，最坏 $O(n \log n)$ 也远在 $10^4$ 之内。
- **空间**：$O(U) \le O(n)$。`cnt` 与 `tail` 各存至多 $U$ 个键值对，`keys` 数组 $O(U)$，没有别的辅助结构。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    bool isPossible(vector<int>& nums) {
        unordered_map<int, int> cnt, tail;   // cnt: 剩余个数；tail: 以 v 结尾的长链条数
        for (int v : nums) cnt[v]++;
        vector<int> keys;
        for (auto& kv : cnt) keys.push_back(kv.first);
        sort(keys.begin(), keys.end());      // 按值升序处理

        for (int x : keys) {
            while (cnt[x] > 0) {
                if (tail[x - 1] > 0) {              // ① 优先延长
                    tail[x - 1]--;
                    tail[x]++;
                    cnt[x]--;
                } else if (cnt[x + 1] > 0 && cnt[x + 2] > 0) {   // ② 新建长度 3 的链
                    cnt[x]--;
                    cnt[x + 1]--;
                    cnt[x + 2]--;
                    tail[x + 2]++;
                } else {
                    return false;                   // ③ 无处安放
                }
            }
        }
        return true;
    }
};
```

### Python

```python
from collections import Counter
from typing import List

class Solution:
    def isPossible(self, nums: List[int]) -> bool:
        cnt = Counter(nums)      # 每个值的剩余个数
        tail = Counter()         # tail[v] = 以 v 结尾、长度 >= 3 的链条数
        for x in sorted(cnt):
            while cnt[x] > 0:
                if tail[x - 1] > 0:                          # ① 优先延长
                    tail[x - 1] -= 1
                    tail[x] += 1
                    cnt[x] -= 1
                elif cnt[x + 1] > 0 and cnt[x + 2] > 0:      # ② 新建长度 3 的链
                    cnt[x] -= 1
                    cnt[x + 1] -= 1
                    cnt[x + 2] -= 1
                    tail[x + 2] += 1
                else:
                    return False                             # ③ 无处安放
        return True
```

## 8. 边界情况与易错点

1. **元素不足 3 个**：`nums = [1,2]`、`[7]` 直接 `false`。贪心会走到失败分支（建链时 `cnt[x+1]` 或 `cnt[x+2]` 为 0），无需特判。
2. **所有值相同**：`[2,2,2,2]` → `false`。`tail[x-1]` 恒为 0，建链需要 `x+1`，不存在。
3. **负数与下标越界**：`nums[i]` 可以是 $-1000$，若用数组直接下标会越界或需要偏移；C++ 用 `unordered_map`、Python 用 `Counter` 最稳（`Counter` 缺键返回 0）。
4. **`while` 写成 `if`**：`[1,1,2,2,3,3]` 里值 1 有两个副本，第一次建出 `[1,2,3]` 之后还剩一个 1；`if` 只迭代一次就换下一个值，会把这个 1 漏掉并误判为 `false`（正确答案是 `true`）。
5. **新建时忘记扣 `cnt[x+1]`、`cnt[x+2]`**：同一元素会被多条链重复使用，例如 `[1,2,2,3,4,5]` 会被误判为 `true`（正确答案是 `false`）。
6. **用 `cnt[x-1] > 0` 代替 `tail[x-1] > 0`**：处理 $x$ 时所有比 $x$ 小的值都已被消费完，`cnt[x-1]` 必然是 0，判断会退化成「永不延长」，`[1,2,3,4,5]` 被误判成 `false`。
7. **不要在多值重复时贪心不足**：每消耗一个 $x$ 都要重新看一遍 `tail[x-1]`，因为延长会**消耗**一条以 $x-1$ 结尾的链（`tail[x-1]--`），也可能新产生一条以 $x$ 结尾的链供后续使用。
