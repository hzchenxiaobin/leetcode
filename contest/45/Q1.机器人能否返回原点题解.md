# LeetCode 机器人能否返回原点 题解

## 1. 题目概述

- **标题 / 题号**：机器人能否返回原点（#657，easy）
- **链接**：https://leetcode.cn/problems/robot-return-to-origin/
- **来源**：LeetCode 第 45 场周赛 Q1
- **难度**：简单
- **标签**：字符串，模拟

**题意**：机器人一开始站在二维平面的原点 $(0,0)$。给定一个只含 `'R'`、`'L'`、`'U'`、`'D'` 的字符串 `moves`，第 $i$ 个字符表示第 $i$ 次移动的方向，每次移动幅度相同（即单位长度）。四类动作的含义固定，与机器人当前朝向无关：`'R'` 向右、`'L'` 向左、`'U'` 向上、`'D'` 向下。判断走完全部动作后机器人是否恰好停在原点，是则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \lvert \text{moves} \rvert \le 2 \times 10^4$
- `moves` 只包含字符 `'U'`、`'D'`、`'L'`、`'R'`

规模只有 $2 \times 10^4$，$O(n)$ 的一趟扫描绰绰有余。所以这题的难点不在复杂度，而在一个容易错过的观察：**答案只取决于终点坐标**，中间路径可以完全丢弃。

## 2. 示例

**示例 1**

```text
输入：moves = "UD"
输出：true
解释：先向上走一次、再向下走一次，两次位移恰好抵消，
      机器人回到起点 (0, 0)。
```

**示例 2**

```text
输入：moves = "LL"
输出：false
解释：向左走两次，最终停在 (-2, 0)，离原点两个单位的距离，
      因此返回 false。
```

**补充示例（非官方，用于演示走查）**

```text
输入：moves = "RLUURDDDLU"
输出：true
解释：第 2 步时机器人曾短暂回到原点，之后又跑出去，直到第 10 步
      才再次回到 (0, 0)。全程 #R = #L = 2、#U = #D = 3，两轴同时归零。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的写法是**把整条路径都记下来**：开一个 `vector<pair<int,int>>`，每走一步就把当前坐标 push 进去，走完以后检查最后一个元素是不是 $(0,0)$。

这个做法时间 $O(n)$、空间 $O(n)$，对 $n = 2\times 10^4$ 当然能过。但它是「过度模拟」：

- 题目只问**终点**，中间任何一步的坐标我们根本不关心，存下来纯属浪费；
- 一旦把「路径」当成数据，就容易被带去更复杂的方向——比如有人会顺手把每一步塞进 `set` 去判重（判重是 874 题的需求，不是本题的）；
- 类似地，把字符先翻译成一个长度 $n$ 的位移数组再求和，也是多开了一份 $O(n)$ 空间。

一句话概括暴力的毛病：**它保留了不需要的信息**。下面把它砍到一个常数。

### 3.2 核心观察：水平位移与竖直位移互相独立

![核心观察：两个轴互不干扰](images/wc45_q1_axis_decomposition.svg)

位移是**向量加法**，而二维向量加法等于两个一维加法各算各的。四个动作写成向量是

$$\text{'R'}=(1,0),\quad \text{'L'}=(-1,0),\quad \text{'U'}=(0,1),\quad \text{'D'}=(0,-1)$$

于是立刻看出：`'R'` / `'L'` 只改横坐标，`'U'` / `'D'` 只改纵坐标，**两个轴之间没有任何耦合**。终点坐标因此可以拆成两个独立的计数：

$$x_{\text{end}} = \#R - \#L, \qquad y_{\text{end}} = \#U - \#D$$

回到原点等价于两个分量同时为 $0$：

$$\text{回到原点} \iff \#R = \#L \ \text{且}\ \#U = \#D$$

这就把「记录一条路径」压成了「维护两个整数」。还有一种更形象的等效说法：把 `'R'` 与 `'L'` 两两配对抵消（就像括号匹配），剩下的个数正是 $\lvert \#R - \#L \rvert$；`'U'` 与 `'D'` 同理。两族各自抵消干净，机器人才会回到原点。

> 💡 **为什么这题值得记**：$O(n)$ 空间的模拟几乎是所有人的第一反应，而「只保留对答案有用的状态」是模拟题最常见的优化动作。本题的答案是两个整数，那就只留两个整数。

### 3.3 算法流程

![算法流程：一趟扫描累加位移](images/wc45_q1_scan_flow.svg)

1. 记 $n = \lvert \text{moves} \rvert$。**可选剪枝**：若 $n$ 为奇数，直接返回 `false`（原因见 §4 与引理 3）。
2. 初始化两个计数器 $x = 0$、$y = 0$。
3. 从左到右扫描 `moves` 的每个字符 $ch$，按下面的对应关系更新：
   - $ch = \text{'R'} \Rightarrow x \mathrel{+}= 1$
   - $ch = \text{'L'} \Rightarrow x \mathrel{-}= 1$
   - $ch = \text{'U'} \Rightarrow y \mathrel{+}= 1$
   - $ch = \text{'D'} \Rightarrow y \mathrel{-}= 1$
4. 扫描结束后返回 `x == 0 && y == 0`。

全程只有一个循环、两个整数，没有任何容器。剪枝那一步即使不写也完全正确，只是省几次判断。

### 3.4 示例演算

![示例演算：moves = "RLUURDDDLU"](images/wc45_q1_walkthrough.svg)

以 `moves = "RLUURDDDLU"` 为例，逐步记录 $(x, y)$：

| 步 $i$ | 字符 | $x$ | $y$ | 说明 |
|--------|------|-----|-----|------|
| 0（起点） | — | 0 | 0 | — |
| 1 | `'R'` | 1 | 0 | 向右 |
| 2 | `'L'` | 0 | 0 | 与第 1 步抵消，**短暂回到原点** |
| 3 | `'U'` | 0 | 1 | 向上 |
| 4 | `'U'` | 0 | 2 | 向上 |
| 5 | `'R'` | 1 | 2 | 向右 |
| 6 | `'D'` | 1 | 1 | 向下 |
| 7 | `'D'` | 1 | 0 | 向下 |
| 8 | `'D'` | 1 | −1 | 向下，越过 $x$ 轴 |
| 9 | `'L'` | 0 | −1 | 向左 |
| 10 | `'U'` | 0 | 0 | 终点回到原点 → `true` |

对照计数法：$\#R = 2 = \#L$，$\#U = 3 = \#D$，所以 $x = 0$、$y = 0$，返回 `true`，与逐步模拟一致。注意第 2 步也出现过 $(0,0)$，但那只是「路过」——**题目只问终点**，中间回到原点不算数。

再看 `moves = "LL"`：$\#R = 0$、$\#L = 2$，故 $x = -2 \ne 0$，立刻得到 `false`，无须模拟。

## 4. 算法细节

1. **用两个整数而不是四个计数器**：$\#R - \#L$ 与 $\#U - \#D$ 可以边扫边算，符号已经蕴含在加减里，因此不需要分别统计四个方向再相减。两种写法等价，前者少两次比较、少四个变量。
2. **分支写法**：C++ 用 `if / else if / else` 链，最后一个 `else` 兜底为 `'D'`（题面保证字符合法，因此不必再判断一次 `c == 'D'`）；Python 用同样顺序的 `if / elif / else`。**不要把 `'D'` 写成漏掉的分支**，否则 `'D'` 会被静默忽略。
3. **奇偶剪枝（可选）**：每条指令恰好把 $x + y$ 的奇偶性翻转一次（`'R'` 让 $x$ 加 1、`'L'` 减 1，两者对 $x+y$ 的奇偶影响相同；`'U'` / `'D'` 同理）。起点 $x+y = 0$ 是偶数，走 $n$ 步后奇偶性为 $n \bmod 2$；而回到原点要求 $x + y = 0$ 为偶数，故 $n$ 为奇数时必然失败。这条剪枝不改变复杂度，只是让奇数长度输入 $O(1)$ 返回。
4. **数据范围足够小**：$\lvert x \rvert, \lvert y \rvert \le n \le 2 \times 10^4$，`int` 完全够，不需要 `long long`，也不会溢出。
5. **不要滥用容器**：用 `unordered_map<char,int>` 统计四个方向的频次在 $n = 2\times10^4$ 时既慢又重；用 `std::count` 扫四遍则是 $4n$ 次遍历，可读性也没有提升。本题两个 `int` 就是最优的数据结构。
6. **不要构造中间字符串**：有人会先把 `moves` 反转、或用 `replace` 成对消去 `"RL"` / `"LR"` / `"UD"` / `"DU"`，那是 $O(n^2)$ 的字符串操作，纯属自找麻烦。
7. **接口签名**：`bool judgeCircle(string moves)`（C++）/ `def judgeCircle(self, moves: str) -> bool`（Python），参数名为 `moves`，`class Solution` 完整类定义。

## 5. 正确性证明

**引理 1（终点坐标公式）**：执行完 `moves` 后，机器人的位置为 $(\#R - \#L,\ \#U - \#D)$。

**证明**：对已执行步数 $k$ 归纳（$0 \le k \le n$）。$k = 0$ 时机器人在 $(0,0)$，而四个计数全为 $0$，公式成立。设执行完前 $k$ 步后位置为 $(x_k, y_k) = (\#R_k - \#L_k,\ \#U_k - \#D_k)$，考虑第 $k+1$ 步的字符：

- 若为 `'R'`，则 $x_{k+1} = x_k + 1$，且 $\#R_{k+1} = \#R_k + 1$，其余计数不变，公式两边同时加 $1$，成立；
- 若为 `'L'`，则 $x_{k+1} = x_k - 1$，且 $\#L_{k+1} = \#L_k + 1$，即 $\#R - \#L$ 减 $1$，成立；
- 若为 `'U'` / `'D'`，只影响 $y$ 与 $\#U$ / $\#D$，同理论证。

四种情况覆盖全部合法输入，故公式对所有 $n$ 成立。∎

**引理 2（算法不变量）**：扫描到任意前缀 `moves[0..k)` 时，循环变量满足 $x = \#R_k - \#L_k$ 与 $y = \#U_k - \#D_k$。

**证明**：初始 $x = y = 0$，前缀为空，等式成立。每读入一个字符，算法按 §3.3 的对应关系对 $x$ 或 $y$ 做 $+1$ / $-1$，与引理 1 证明中的更新完全一致，故不变量沿扫描保持。∎

**引理 3（奇偶剪枝正确）**：若 $n$ 为奇数，机器人不可能回到原点。

**证明**：只需注意每个动作都使 $x + y$ 的奇偶性翻转：`'R'`、`'L'` 改变 $x$ 的奇偶性，`'U'`、`'D'` 改变 $y$ 的奇偶性。因此走 $n$ 步后 $(x+y) \bmod 2 = n \bmod 2$。回到原点要求 $x + y = 0$，其奇偶性为 $0$，故必须有 $n$ 为偶数。∎

**定理**：`judgeCircle(moves)` 返回 `true`，当且仅当机器人执行完 `moves` 后位于原点。

**证明**：

- （$\Leftarrow$）设机器人最终位于原点，即终点坐标为 $(0,0)$。由引理 1，$(0,0) = (\#R - \#L,\ \#U - \#D)$，于是 $\#R = \#L$ 且 $\#U = \#D$。由引理 2，扫描结束时 $x = \#R - \#L = 0$、$y = \#U - \#D = 0$，返回值 `x == 0 && y == 0` 为 `true`。
- （$\Rightarrow$）设返回 `true`，则 $x = y = 0$。由引理 2，终点坐标为 $(0,0)$，即机器人回到了原点。

两种情况合起来即得等价关系。若走了奇数步，由引理 3 机器人不可能在原点，而算法此时也直接返回 `false`，与主结论一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。扫描 `moves` 一趟，每个字符做一次常数次的比较与加减，无嵌套循环、无对容器的额外操作；奇偶剪枝只增加一次 $O(1)$ 判断，不改变量级。
- **空间**：$O(1)$。只用两个整型变量 $x$、$y$（以及一个循环变量），与输入规模无关；相比「记录整条路径」的 $O(n)$ 方案省掉了一整个数组。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    bool judgeCircle(string moves) {
        int x = 0, y = 0;                 // 当前坐标，起点为 (0, 0)
        for (char c : moves) {
            if (c == 'R')      x += 1;    // 向右：x 增
            else if (c == 'L') x -= 1;    // 向左：x 减
            else if (c == 'U') y += 1;    // 向上：y 增
            else               y -= 1;    // 剩下的只可能是 'D'
        }
        return x == 0 && y == 0;
    }
};
```

### Python

```python
class Solution:
    def judgeCircle(self, moves: str) -> bool:
        if len(moves) % 2:              # 奇数步不可能回到原点（可选剪枝）
            return False
        x = y = 0                       # 当前坐标，起点为 (0, 0)
        for ch in moves:
            if ch == 'R':
                x += 1                  # 向右
            elif ch == 'L':
                x -= 1                  # 向左
            elif ch == 'U':
                y += 1                  # 向上
            else:                       # 剩下的只可能是 'D'
                y -= 1                  # 向下
        return x == 0 and y == 0
```

> 也可以直接写成计数比较：`return moves.count('R') == moves.count('L') and moves.count('U') == moves.count('D')`。它扫四遍，复杂度仍是 $O(n)$，适合面试时一句话说清思路；但单趟累加的写法在常数和可读性上都更好。

## 8. 边界情况与易错点

1. **奇数长度输入**：如 `moves = "U"`、`"UUD"`，永远返回 `false`。可以靠奇偶剪枝提前返回，也可以正常跑完——两种写法都要保证结果正确，不要在剪枝分支里误写 `true`。
2. **中间回到原点 ≠ 终点回到原点**：`"RLUURDDDLU"` 第 2 步就在 $(0,0)$，但终点才是答案。不能用「路径上是否出现过原点」来判断，除非专门统计并取最后一次。
3. **只判一个轴**：`moves = "LL"` 提示了横轴，但 `"RRLL"` 与 `"UUDD"` 都能过；反例 `"RRLLU"` 则横轴归零、纵轴不归零，返回 `false`。必须 **两个轴同时为 $0$**，不能写成 `x == 0 || y == 0`。
4. **漏掉 `'D'` 分支**：四分支写成 `if / else if / else if` 却没有兜底，`'D'` 会被静默丢弃，`"UD"` 就会误判成 `false`。用 `else` 兜底并注释清楚。
5. **初始化位置错误**：$x$、$y$ 必须在循环外初始化为 $0$；若误写在循环体内，每轮都被清零，最终只剩最后一步的位移，几乎必然判错。
6. **漏写或写错分支**：如果 `'L'` 被漏掉（或当成空操作），`"LL"` 就会误判成 `true`——官方示例 2 正是用来卡这类错误的。顺带一提，把 `'R'`/`'L'` 的加减号**同时**对调其实不影响结果（等价于把 $x$ 整体取反，而 $x = 0$ 的判定对取反不变），但只改其中一个分支就必错。
7. **返回类型**：函数返回布尔值，C++ 返回 `bool`、Python 返回 `True/False`；不要把布尔比较写成返回整数 `0/1`。

**延伸思考**：

- 若题目改成「**是否曾经**回到原点（含中途）」，只需在循环里每步更新后判一次 $x = y = 0$（注意第 $0$ 步也算），复杂度不变，但「起点」这个边界必须显式处理。
- 若改成「第几步**第一次**回到原点」，则在命中时立即返回下标；此时奇偶剪枝依然成立，因为 $x+y$ 的奇偶性论证与终点无关。
- 若同时要求记录**朝向**（1041 题），则状态变成 $(x, y, \text{dir})$。判定「轨迹有界」时不要真的模拟无限步：位置回到 $(0,0)$ 且朝向与初始一致，就落入了周期；或者位置回到原点、朝向旋转了 $90^\circ$/$270^\circ$，四轮之后同样复位。
- 若要判断路径**是否自交**，就不得不把经过的点全部放进 `set`，空间回到 $O(n)$——这也反过来说明：本题之所以能做到 $O(1)$ 空间，是因为**答案只依赖终点的两个分量**，而不是整条路径。
