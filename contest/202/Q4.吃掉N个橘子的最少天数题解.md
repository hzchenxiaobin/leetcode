# LeetCode 吃掉 N 个橘子的最少天数 题解

## 1. 题目概述

- **标题 / 题号**：吃掉 N 个橘子的最少天数（#1553，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-days-to-eat-n-oranges/
- **来源**：LeetCode 第 202 场周赛 Q4
- **难度**：困难
- **标签**：记忆化搜索、动态规划、数学

**题意**：厨房里有 $n$ 个橘子，每天从三种方式中**选一种**：

1. 吃掉 $1$ 个橘子；
2. 若当前橘子数能被 $2$ 整除，吃掉 $n/2$ 个（剩余 $n/2$）；
3. 若当前橘子数能被 $3$ 整除，吃掉 $2(n/3)$ 个（剩余 $n/3$）。

返回吃掉**全部** $n$ 个橘子的最少天数。

**约束**：

- $1 \le n \le 2 \times 10^9$

> ⚠️ $n$ 高达 $2 \times 10^9$：任何「逐个橘子数过去」的做法（线性 DP、朴素 BFS）在内存和时间上双双不可行，必须把状态压到**对数级**。

> 💡 本题在本仓库另有[每日题解 1553](../../solution/1501-1600/1553_吃掉N个橘子的最少天数.md)：侧重入门引导、BFS/Dijkstra 扩展与面试表达。本篇按周赛复盘视角展开，主推「**余数打包 → 两条对数级跳跃边 → 哈希记忆化 DFS**」三步骨架，并补全打包定理的严格证明（含「过冲」情形的交换论证）、贪心反例与无记忆化递归的定量对比。

## 3. 解题思路

### 3.1 暴力思路

三条「直觉路线」在本题的约束下全部阵亡：

- **线性 DP**：$f(n) = 1 + \min\big(f(n-1),\ [n \bmod 2 = 0]\, f(n/2),\ [n \bmod 3 = 0]\, f(n/3)\big)$。转移含 $f(n-1)$，被迫从 $1$ 逐格填到 $n$：$n = 2\times10^9$ 时数组约 8 GB、时间 $O(n)$，双双爆炸。✗
- **朴素 BFS**：把 $n \to n-1$、$n \to n/2$、$n \to n/3$ 看成边权均为 1 的图，求 $n$ 到 $0$ 的最短路。$n-1$ 这条边让可达状态膨胀到 $O(n)$ 个，队列直接爆内存。✗
- **贪心**（能用除法就用除法）：在 $n = 10$ 处翻车——无论「÷3 优先」还是「÷2 优先」，$10 \to 5 \to 4 \to 2 \to 1 \to 0$ 都要 **5** 天；而先吃 $1$ 个凑出 $\div 3$（$10 \to 9 \to 3 \to 1 \to 0$）只要 **4** 天。✗

> 💡 症结在于 $f(n-1)$ 这条边把状态图拉成了一条 $O(n)$ 长链。破局点：链上连续的「吃 1」大多只有一个目的——**凑整除**。把它们整段打包，链就坍缩成对数级的格点。

### 3.2 核心观察：把「吃 1」打包进除法——状态数 $O(n) \to O(\log^2 n)$

![核心观察：把「吃 1」打包进除法，逐天模拟坍缩为两条跳跃边](images/wc202_q4_batch_jump_concept.svg)

**关键洞察**：「吃 1」的**唯一价值**是消余数凑整除——要执行 $\div 2$ 须先消掉 $n \bmod 2$（至多 $1$ 个），要执行 $\div 3$ 须先消掉 $n \bmod 3$（至多 $2$ 个）。于是「吃余数个 1 + 一次除法」可以看作一个**原子跳跃**：

| 跳跃 | 语义 | 代价 |
|------|------|------|
| $n \to \lfloor n/2 \rfloor$ | 先吃 $n \bmod 2$ 个（逐天吃 1），再 $\div 2$ | $n \bmod 2 + 1$ 天 |
| $n \to \lfloor n/3 \rfloor$ | 先吃 $n \bmod 3$ 个（逐天吃 1），再 $\div 3$ | $n \bmod 3 + 1$ 天 |
| $n \to 0$（兜底） | 一路吃 1 吃到底 | $n$ 天 |

由此得到精简递推式：

$$f(n) = \min\big(n,\;\; n \bmod 2 + 1 + f(\lfloor n/2 \rfloor),\;\; n \bmod 3 + 1 + f(\lfloor n/3 \rfloor)\big)$$

边界 $f(0) = 0$、$f(1) = 1$。**每一步状态都除以 2 或 3**，可达状态全部形如

$$\left\lfloor \frac{n}{2^a \cdot 3^b} \right\rfloor,\qquad a, b \ge 0$$

![状态全集：⌊n/2ᵃ·3ᵇ⌋ 只落在 log₂n × log₃n 的格点上](images/wc202_q4_state_lattice_concept.svg)

由嵌套取整等式 $\lfloor \lfloor n/2 \rfloor / 3 \rfloor = \lfloor n/6 \rfloor$，除法的先后顺序不影响结果，状态只由 $(a, b)$ 计数决定。满足 $2^a 3^b \le n$ 的组合至多 $(\lfloor \log_2 n \rfloor + 1)(\lfloor \log_3 n \rfloor + 1)$ 个：$n = 2\times10^9$ 时上界 $31 \times 20 = 620$，**实测去重后仅 259 个状态，递归深度 31，答案 32 天**。

> 💡 一句话总结：把「平凡步」打包成带权跳跃，$O(n)$ 的长链就坍缩成 $O(\log^2 n)$ 的二维格点——这正是 $n \le 2\times10^9$ 还能毫秒级出解的原因。

### 3.3 算法流程：哈希表记忆化 DFS

![算法流程：哈希表记忆化 DFS，两个判断 + 三步计算](images/wc202_q4_memo_dfs_flow.svg)

1. 维护哈希表 `memo`（键为状态值，值为 $f$）。
2. `dfs(n)`：
   - $n \le 1$ 直接返回 $n$（$f(0)=0$，$f(1)=1$，触底不入表）；
   - `memo` 中已有 $n$ 直接返回（重复子问题整棵子树免算）；
   - 否则 $ans \leftarrow n$（全吃兜底），再依次与 $n\%2 + 1 + \mathrm{dfs}(\lfloor n/2 \rfloor)$、$n\%3 + 1 + \mathrm{dfs}(\lfloor n/3 \rfloor)$ 取最小；
   - 存入 `memo` 并返回。
3. 两个分支**必须都完整计算**——贪心剪掉任何一个都会在 $n = 10$ 出错。

### 3.4 示例演算

![示例演算：n = 56 的递归树，灰虚线为 memo 命中，粗橙边为最优决策](images/wc202_q4_walkthrough.svg)

以示例 4 的 $n = 56$ 为例（$\div 2$ 分支先求值），逐状态展开：

| 状态 $n$ | $\div 2$ 分支：$n\%2+1+f(\lfloor n/2 \rfloor)$ | $\div 3$ 分支：$n\%3+1+f(\lfloor n/3 \rfloor)$ | 选取 | $f(n)$ |
|----------|--------------------------------------------|--------------------------------------------|------|--------|
| 56 | $0+1+f(28)=6$ ✓ | $2+1+f(18)=7$ | $\div 2$ | 6 |
| 28 | $0+1+f(14)=6$ | $1+1+f(9)=5$ ✓ | $\div 3$ | 5 |
| 18 | $0+1+f(9)=4$ ✓ | $0+1+f(6)=4$ ✓ | 并列 | 4 |
| 14 | $0+1+f(7)=5$ ✓ | $2+1+f(4)=6$ | $\div 2$ | 5 |
| 9 | $1+1+f(4)=5$ | $0+1+f(3)=3$ ✓ | $\div 3$ | 3 |
| 7 | $1+1+f(3)=4$ ✓ | $1+1+f(2)=4$ ✓ | 并列 | 4 |
| 6 | $0+1+f(3)=3$ ✓ | $0+1+f(2)=3$ ✓ | 并列 | 3 |
| 4 | $0+1+f(2)=3$ ✓ | $1+1+f(1)=3$ ✓ | 并列 | 3 |
| 3 | $1+1+f(1)=3$ | $0+1+f(1)=2$ ✓ | $\div 3$ | 2 |
| 2 | $0+1+f(1)=2$ ✓ | $2+1+f(0)=3$ | $\div 2$ | 2 |
| 1 | — 边界，直接返回 — | | | 1 |

回代得最优路径 $56 \to 28 \to 9 \to 3 \to 1 \to 0$，展开成天数：

$$56 \xrightarrow{\ \div 2\ } 28 \xrightarrow{\ \text{吃 }1\ } 27 \xrightarrow{\ \div 3\ } 9 \xrightarrow{\ \div 3\ } 3 \xrightarrow{\ \div 3\ } 1 \xrightarrow{\ \text{吃 }1\ } 0 \quad = 1+2+1+1+1 = 6 \text{ 天} \checkmark$$

> 💡 全程只访问 $12$ 个状态（含触底的 $0,1$），$6$ 次 memo 命中；若不记忆化，同一棵递归树要展开 $41$ 次调用。$n$ 越大差距越悬殊：$n = 2\times10^9$ 时是 **259 个状态 vs 约 $3.7\times10^7$ 次调用**。

## 4. 算法细节

1. **打包边的代价公式**：跳到 $\lfloor n/2 \rfloor$ 花 $n \bmod 2 + 1$ 天（余数天 + 除法天），跳到 $\lfloor n/3 \rfloor$ 花 $n \bmod 3 + 1$ 天。取模与整除同源：先吃掉 $n \bmod d$ 个后恰好剩下 $d \lfloor n/d \rfloor$ 个，正好能除。
2. **`min` 中的 $n$ 项是「全吃」兜底**：它保证 $n \le 2$ 时公式自然成立、无需特判。可证 $n \ge 3$ 时它从不严格最优——$n \ge 4$ 时 $\div 2$ 分支 $\le n \bmod 2 + 1 + \lfloor n/2 \rfloor \le \frac{n+3}{2} < n$，$n = 3$ 时 $\div 3$ 分支 $= 0 + 1 + f(1) = 2 < 3$。保留它换来实现与证明双干净。
3. **memo 必须用哈希表**：状态值 $\lfloor n/2^a 3^b \rfloor$ 只有 $O(\log^2 n)$ 个，但散布在 $[1, n]$ 全值域，无法开数组索引；`unordered_map` / `dict` 按需存储。
4. **递归深度** $\le \lfloor \log_2 n \rfloor + 1 \approx 31$，远低于栈限制，无需改迭代。
5. **C++ 把 `memo` 放成员**：跨测试用例残留**无害且有益**——$f$ 是确定性函数，命中即免费复用；Python 用调用内闭包 `dict`（或 `@lru_cache`，多组用例间同样无害，只是注意内存）。
6. **求值顺序无所谓，但两支都要算**：`min` 的两个递归都必须执行，任何「先算一支、看着小就跳过另一支」的剪枝都是贪心，$n = 10$ 即反例。

## 5. 正确性证明

记 $f(m)$ 为吃掉 $m$ 个橘子的最少天数，$f(0) = 0$。以下证明「打包」不丢失最优解。

**引理 1（平移上界）**：对 $0 \le t \le a$，有 $f(a) \le t + f(a - t)$。

**证明**：从 $a$ 出发先连续 $t$ 天每天吃 $1$ 个，到达 $a - t$，再接 $a-t$ 的最优方案。这是一个合法方案，故其天数 $t + f(a-t)$ 不小于 $f(a)$，即 $f(a) \le t + f(a-t)$。∎

> 💡 直观含义：状态每压低 $t$，最优天数**至多**省 $t$ 天——「多 $t$ 个橘子至多多花 $t$ 天」。它是下面处理「过冲」情形的唯一工具。

**引理 2（打包定理）**：对一切 $m \ge 1$，

$$f(m) = \min\big(m,\;\; m \bmod 2 + 1 + f(\lfloor m/2 \rfloor),\;\; m \bmod 3 + 1 + f(\lfloor m/3 \rfloor)\big)$$

**证明**：

（$\le$，三个候选都是可行策略）① 全部逐天吃 1，共 $m$ 天；② 先吃 $m \bmod 2$ 个（每天 1 个）到 $2\lfloor m/2 \rfloor$——能被 2 整除——再用 1 天 $\div 2$ 到 $\lfloor m/2 \rfloor$，接最优方案，共 $m \bmod 2 + 1 + f(\lfloor m/2 \rfloor)$ 天；③ 同理 $\div 3$。三者的最小值自然是 $f(m)$ 的上界。

（$\ge$，最优解不劣于打包）设 $S$ 为 $m$ 的一条最优操作序列，$T = f(m)$。若 $S$ 不含除法，则 $T = m \ge$ 右端。否则设第 $k$ 步是 $S$ 中**第一次**除法（$\div d$，$d \in \{2,3\}$），其前 $L = k - 1$ 步全是「吃 1」。记 $r = m \bmod d$：$\div d$ 合法要求 $m - L$ 被 $d$ 整除，即 $L \equiv r \pmod d$。分两种情形：

- **恰好消余数**（$L = r$，含首步即除法时 $L = r = 0$）：除法后状态为 $(m - r)/d = \lfloor m/d \rfloor$，故
  $$T = r + 1 + f(\lfloor m/d \rfloor) \ge \text{右端}.$$
- **过冲**（$L > r$）：由 $L \equiv r \pmod d$ 可写 $L = r + d\,t$（$t \ge 1$），除法后状态为 $\lfloor m/d \rfloor - t$，故
  $$T = r + d\,t + 1 + f(\lfloor m/d \rfloor - t) \ \overset{\text{引理 1}}{\ge}\ r + d\,t + 1 + f(\lfloor m/d \rfloor) - t = r + 1 + f(\lfloor m/d \rfloor) + (d-1)\,t \ge r + 1 + f(\lfloor m/d \rfloor) \ge \text{右端}.$$

两种情形均证得 $T \ge$ 右端，与（$\le$）合并即得等式。∎

> 💡 过冲情形的直观：多凑 $d\,t$ 个再除 = 白花 $d\,t$ 天、只把除法后的状态多压低 $t$；而状态压低 $t$ 至多省 $t$ 天（引理 1），净亏 $(d-1)t \ge 1$ 天。所以「吃 1」永远只需吃到**恰好整除**为止——这正是打包合法性的来源。

**引理 3（状态集有限）**：递归只会访问形如 $\lfloor n / 2^a 3^b \rfloor$ 的状态，总个数至多 $(\lfloor \log_2 n \rfloor + 1)(\lfloor \log_3 n \rfloor + 1)$。

**证明**：对递归深度归纳：一次转移即 $m \mapsto \lfloor m/2 \rfloor$ 或 $m \mapsto \lfloor m/3 \rfloor$；由嵌套取整等式 $\lfloor \lfloor x/u \rfloor / v \rfloor = \lfloor x/(uv) \rfloor$（正整数 $u, v$），任意顺序复合 $a$ 次 $\div 2$ 与 $b$ 次 $\div 3$ 等于一次 $\div 2^a 3^b$。当 $2^a 3^b > n$ 时状态触底为 $0$，故只有 $2^a 3^b \le n$ 的 $(a,b)$ 会产生有效状态，即 $a \le \lfloor \log_2 n \rfloor$、$b \le \lfloor \log_3 n \rfloor$。∎

**定理（算法正确性）**：记忆化 DFS 返回值 $g(n) = f(n)$，且算法在有限步内终止。

**证明**：对 $m$ 强归纳。$g(0) = 0 = f(0)$、$g(1) = 1 = f(1)$（代码中 $n \le 1$ 直接返回）。$m \ge 2$ 时递归仅依赖 $\lfloor m/2 \rfloor$ 与 $\lfloor m/3 \rfloor$，两者均严格小于 $m$，由归纳假设分别为 $f(\lfloor m/2 \rfloor)$、$f(\lfloor m/3 \rfloor)$；代入代码的计算式，由引理 2 右端恰为 $f(m)$，故 $g(m) = f(m)$。终止性由引理 3 的有限状态集与 `memo` 的去重保证。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\log_2 n \cdot \log_3 n)$。状态数上界 $(\lfloor \log_2 n \rfloor + 1)(\lfloor \log_3 n \rfloor + 1)$，$n = 2\times10^9$ 时为 $31 \times 20 = 620$（实测去重 259 个）；每个状态 $O(1)$：两次取模、两次整除、两次哈希操作。整体微秒级。
- **空间复杂度**：$O(\log^2 n)$ 哈希表 + $O(\log n)$ 递归栈（深度 $\le 31$）。
- **对比（不记忆化的代价）**：朴素递归的调用次数满足 $C(m) = 1 + C(\lfloor m/2 \rfloor) + C(\lfloor m/3 \rfloor) = \Theta(n^{\alpha})$，其中 $2^{-\alpha} + 3^{-\alpha} = 1$，$\alpha \approx 0.79$。$n = 2\times10^9$ 时实测 **37,279,879** 次调用——Python 必然超时，C++ 也悬；记忆化把工作量压缩约 **14 万倍**。

## 7. 参考代码

### 方法一：余数打包 + 记忆化 DFS（推荐）

#### C++

```cpp
class Solution {
public:
    int minDays(int n) {
        if (n <= 1) return n;                      // f(0)=0, f(1)=1，触底不入表
        auto it = memo.find(n);
        if (it != memo.end()) return it->second;   // 命中：整棵子树免算
        int ans = min(n, n % 2 + 1 + minDays(n / 2));  // 打包跳跃 ÷2
        ans = min(ans, n % 3 + 1 + minDays(n / 3));    // 打包跳跃 ÷3
        memo[n] = ans;
        return ans;
    }
private:
    unordered_map<int, int> memo;  // 状态散布全值域，只能哈希
};
```

> 💡 `memo` 作为成员在多组测试用例间残留是**免费缓存**：$f$ 是确定性函数，命中即复用，无正确性风险。

#### Python

```python
class Solution:
    def minDays(self, n: int) -> int:
        memo = {0: 0, 1: 1}

        def dfs(k: int) -> int:
            if k in memo:
                return memo[k]
            memo[k] = min(k, k % 2 + 1 + dfs(k // 2),
                          k % 3 + 1 + dfs(k // 3))
            return memo[k]

        return dfs(n)
```

### 方法二：朴素 BFS（对拍验证用）

```python
from collections import deque

class Solution:
    def minDays(self, n: int) -> int:
        dist = {n: 0}
        q = deque([n])
        while q:
            cur = q.popleft()
            if cur == 0:
                return dist[cur]
            nxts = {cur - 1}
            if cur % 2 == 0:
                nxts.add(cur // 2)
            if cur % 3 == 0:
                nxts.add(cur // 3)
            for nxt in nxts:
                if nxt not in dist:
                    dist[nxt] = dist[cur] + 1
                    q.append(nxt)
```

> 💡 方法二保留 $n-1$ 边、状态数 $O(n)$，仅用于小数据（$n \le 10^5$ 量级）随机对拍——与方法一核对一致后放心提交。压缩图上做图搜亦可，但两条跳跃边**权不等**（$n\%2+1 \ne n\%3+1$），须用 Dijkstra；记忆化 DFS 更简单直接。

## 8. 边界情况与易错点

1. **$n = 1$ 与 $n = 2$**：答案分别为 $1$、$2$（「吃吃」与「$\div 2$ + 吃」并列）。代码用 `n <= 1` 触底即可，无需更多特判。
2. **`min` 里别丢 $n$ 项**：它是「全吃」兜底，使 $n \le 2$ 自然正确；虽然 $n \ge 3$ 时被除法分支严格超越（见 §4 第 2 点），删掉它就得多写边界且证明变啰嗦。
3. **贪心剪枝必错**：$n = 10$ 时无论「÷3 优先」还是「÷2 优先」的除法贪心都给 5 天，最优是 4 天——两个递归分支必须都算。
4. **忘记记忆化**：递归树是 $\Theta(n^{0.79})$ 个节点，$n = 2\times10^9$ 时约 $3.7\times10^7$ 次调用（实测），Python 必超时、C++ 也危险。
5. **memo 不能开数组**：状态值散布 $[1, 2\times10^9]$，开数组即 8 GB；必须哈希表。
6. **压缩图上别用普通 BFS**：两条跳跃边权不等，层序 BFS 会算错「天数」；要么 Dijkstra，要么干脆记忆化 DFS。
7. **溢出评估**：$n \le 2\times10^9 < 2^{31} - 1$，`int` 刚好安全；若约束抬到 $10^{18}$ 需换 64 位整数（状态数约 $60 \times 38 \approx 2300$，依然轻松）。
8. **递归深度**：$\le 31$，C++/Python 均无爆栈风险。
9. **嵌套取整**：$\lfloor \lfloor n/2 \rfloor / 3 \rfloor = \lfloor n/6 \rfloor$ 保证「先 ÷2 后 ÷3」与「先 ÷3 后 ÷2」殊途同归——状态只看 $(a, b)$ 计数，与求值顺序无关。
