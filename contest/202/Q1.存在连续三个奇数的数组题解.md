# LeetCode 存在连续三个奇数的数组 题解

## 1. 题目概述

- **标题 / 题号**：存在连续三个奇数的数组（#1550，easy）
- **链接**：https://leetcode.cn/problems/three-consecutive-odds/
- **来源**：LeetCode 第 202 场周赛 Q1
- **难度**：简单
- **标签**：数组、计数、一次遍历

**题意**：给定整数数组 $\mathrm{arr}$，判断其中是否存在**下标连续**的三个元素均为奇数：存在返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \mathrm{arr.length} \le 1000$
- $1 \le \mathrm{arr}[i] \le 1000$

> 💡 签到题，$n \le 1000$ 怎么写都能过。赛时最短路径：枚举每个长度为 3 的窗口，或维护「连续奇数计数器」，两分钟内收工。复盘价值在于后者——它与 [485. 最大连续 1 的个数](https://leetcode.cn/problems/max-consecutive-ones/) 完全同构，是「**定长连续段存在性判定**」的通用模板：**遇断清零，达限即真**。

## 2. 示例

**示例 1**

```text
输入：arr = [2,6,4,1]
输出：false
解释：不存在连续三个元素都是奇数的情况。
```

**示例 2**

```text
输入：arr = [1,2,34,3,4,5,7,23,12]
输出：true
解释：存在连续三个奇数 [5,7,23]（下标 5、6、7）。
```

**示例 3（边界自拟）**

```text
输入：arr = [1,3]
输出：false
解释：数组长度不足 3，不可能存在连续三个奇数。
```

## 3. 解题思路

### 3.1 暴力思路：枚举每个长度为 3 的窗口

对每个起点 $i \in [0, n-3]$，检查 $\mathrm{arr}[i]$、$\mathrm{arr}[i+1]$、$\mathrm{arr}[i+2]$ 是否均为奇数：

```text
for i in 0 .. n-3:
    if arr[i] 奇 and arr[i+1] 奇 and arr[i+2] 奇:
        return true
return false
```

时间 $O(n)$（$n-2$ 个窗口、每个 3 次判定），空间 $O(1)$，对 $n \le 1000$ 绰绰有余，赛时直接写这版完全没问题。它的小瑕疵是**相邻窗口重叠复判**：$\mathrm{arr}[i+1]$、$\mathrm{arr}[i+2]$ 在窗口 $i$ 里查过一遍，在窗口 $i+1$ 里又查一遍。下面的计数器做法让每个元素只被判定一次，且命中即可提前退出。

### 3.2 核心观察：连续奇数计数器——遇奇加一，遇偶清零

![核心观察：连续奇数计数器，遇奇加一遇偶清零](images/wc202_q1_counter_concept.svg)

「三个连续奇数」= 一段**长度达到 3 的奇数连续段**。维护计数器 $\mathrm{cnt}$，语义是**以当前元素结尾的连续奇数个数**：

- 当前元素是**奇数**：$\mathrm{cnt} \gets \mathrm{cnt} + 1$；若 $\mathrm{cnt} = 3$，立即返回 `true`；
- 当前元素是**偶数**：$\mathrm{cnt} \gets 0$。

> 💡 **为什么遇偶数是清零而不是减一？** 「连续」要求三个奇数**相邻**。中间一旦出现偶数，前面累积的奇数与后面的奇数就不可能再拼成连续段——**跨越偶数的连续段不存在**，所以必须从零重数。这是「遇断清零」类计数器的共同直觉（同样的逻辑见 [1566. 重复至少 K 次且长度为 M 的模式](https://leetcode.cn/problems/detect-pattern-of-length-m-repeated-k-or-more-times/) 的匹配计数）。

### 3.3 算法流程

![算法流程：一趟扫描，计数器增减与提前返回](images/wc202_q1_algorithm_flow.svg)

单层循环：判定奇偶 → 奇则累加并检查是否达 3，偶则清零 → 移动到下一元素。$\mathrm{cnt} = 3$ 时短路返回 `true`；遍历完仍未触发则返回 `false`。

### 3.4 示例演算

![示例演算：arr = [1,2,34,3,4,5,7,23,12] 的计数器变化](images/wc202_q1_example_walkthrough.svg)

以示例 2 为例：

| $i$ | $\mathrm{arr}[i]$ | 奇偶 | $\mathrm{cnt}$ | 说明 |
|-----|------------------|------|----------------|------|
| 0 | 1 | 奇 | 1 | 开始计数 |
| 1 | 2 | 偶 | 0 | 清零 |
| 2 | 34 | 偶 | 0 | 保持 0 |
| 3 | 3 | 奇 | 1 | 重新计数 |
| 4 | 4 | 偶 | 0 | 清零 |
| 5 | 5 | 奇 | 1 | 计数 |
| 6 | 7 | 奇 | 2 | 计数 |
| 7 | 23 | 奇 | 3 | **达到 3，返回 true** ✓ |
| 8 | 12 | — | — | 已提前退出，不再处理 |

## 4. 算法细节

1. **奇偶判定**：`x % 2 != 0` 对任意整数都正确；`x & 1` 是位运算写法，非负数下两者等价。C++/Java 中 `x % 2 == 1` 对**负奇数**会误判（得 $-1$），本题 $1 \le \mathrm{arr}[i]$ 不触发，但模板要养成写 `!= 0` 的习惯。
2. **计数器不变量**：处理完下标 $i$ 后，$\mathrm{cnt}$ 等于 $\mathrm{arr}[0..i]$ 中以 $i$ 结尾的最长全奇后缀的长度（未触发返回时取值 $\in \{0,1,2\}$）。累加与清零都由这一条不变量统一解释，详见 §5。
3. **提前退出**：存在性判定一旦命中立即返回；最坏情况（全偶数或无三连）仍是一趟 $O(n)$。
4. **窗口枚举的边界**：若采用 §3.1 写法，起点上界是 $n-3$（含）；$n < 3$ 时循环体不执行，自然返回 `false`，无需特判。

## 5. 正确性证明

**引理 1（计数器不变量）**：只要算法在处理完下标 $0, \dots, i-1$ 后仍未返回，则处理完下标 $i$ 后（无论是否随即触发返回）都有 $\mathrm{cnt}_i = \ell_i$，其中 $\ell_i$ 是 $\mathrm{arr}[0..i]$ 中以 $i$ 结尾的最长全奇后缀的长度，满足递推

$$\ell_i = \begin{cases} \ell_{i-1} + 1, & \mathrm{arr}[i] \text{ 为奇数} \\ 0, & \mathrm{arr}[i] \text{ 为偶数} \end{cases} \qquad (\ell_{-1} = 0).$$

**证明**：对 $i$ 归纳。$i = 0$：奇则 $\ell_0 = 1 = \mathrm{cnt}_0$，偶则 $\ell_0 = 0 = \mathrm{cnt}_0$。设对 $i-1$ 成立且算法尚未返回。若 $\mathrm{arr}[i]$ 为偶，以 $i$ 结尾的全奇后缀不存在（末元素已是偶数），$\ell_i = 0$，算法置 $\mathrm{cnt}_i = 0$。若 $\mathrm{arr}[i]$ 为奇，任一以 $i$ 结尾的全奇后缀去掉末元素后是以 $i-1$ 结尾的全奇后缀，故最长者由「以 $i-1$ 结尾的最长全奇后缀」拼接 $\mathrm{arr}[i]$ 得到，即 $\ell_i = \ell_{i-1} + 1 = \mathrm{cnt}_{i-1} + 1 = \mathrm{cnt}_i$。∎

**定理**：算法返回 `true` 当且仅当存在下标 $i \in [0, n-3]$ 使 $\mathrm{arr}[i], \mathrm{arr}[i+1], \mathrm{arr}[i+2]$ 均为奇数。

**证明**：（⇒）设算法在下标 $j$ 处返回 `true`，则 $\mathrm{cnt}_j = 3$；由 $\mathrm{cnt}$ 从 0 出发每步至多 $+1$ 知 $j \ge 2$。在 $j$ 之前算法未返回，引理 1 适用，$\ell_j = 3$，即 $\mathrm{arr}[j-2], \mathrm{arr}[j-1], \mathrm{arr}[j]$ 全奇，取 $i = j - 2 \in [0, n-3]$。（⇐）设 $\mathrm{arr}[i..i+2]$ 全奇。考虑以 $i+2$ 结尾的最长全奇后缀，设其起点为 $s$，则 $s \le i$，且 $s = 0$ 或 $\mathrm{arr}[s-1]$ 为偶，于是该后缀的前三个元素恰为 $\mathrm{arr}[s..s+2]$，即 $\ell_s = 1$、$\ell_{s+1} = 2$、$\ell_{s+2} = 3$。若算法在处理到 $s+2$ 之前已返回，返回值必为 `true`（唯一的提前返回路径是 $\mathrm{cnt} = 3$）；否则由引理 1，$\mathrm{cnt}$ 在 $s, s+1, s+2$ 处依次为 $1, 2, 3$，于是在 $s + 2 \le i + 2$ 处触发返回 `true`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素恰好一次奇偶判定加常数次比较；最好第 3 个元素即返回，最坏全数组扫完。相比窗口枚举的 $3(n-2)$ 次判定，每个元素只看一次，常数更小。
- **空间复杂度**：$O(1)$。仅一个计数器变量。

## 7. 参考代码

### 方法一：连续奇数计数器（推荐）

#### C++

```cpp
class Solution {
public:
    bool threeConsecutiveOdds(vector<int>& arr) {
        int cnt = 0;
        for (int x : arr) {
            if (x % 2 != 0) {
                if (++cnt == 3) return true;
            } else {
                cnt = 0;
            }
        }
        return false;
    }
};
```

#### Python

```python
class Solution:
    def threeConsecutiveOdds(self, arr: List[int]) -> bool:
        cnt = 0
        for x in arr:
            if x % 2 != 0:
                cnt += 1
                if cnt == 3:
                    return True
            else:
                cnt = 0
        return False
```

### 方法二：枚举长度为 3 的窗口（赛时保底）

```python
class Solution:
    def threeConsecutiveOdds(self, arr: List[int]) -> bool:
        n = len(arr)
        for i in range(n - 2):
            if arr[i] % 2 and arr[i + 1] % 2 and arr[i + 2] % 2:
                return True
        return False
```

> 💡 Python 里还可压成一行：`return any(a & b & c & 1 for a, b, c in zip(arr, arr[1:], arr[2:]))`——`a & b & c & 1` 对三个末位按位与，同时为奇数时才等于 1。

## 8. 边界情况与易错点

1. **$n < 3$**：不可能存在连续三个元素，返回 `false`。计数器法 $\mathrm{cnt}$ 最大只到 $n \le 2$，窗口法循环不执行（`range(n-2)` 为空），均自然处理，无需特判。
2. **奇偶判定的负数坑**：C++/Java 中 `-3 % 2 == -1`，写 `x % 2 == 1` 会漏判负奇数；规范写法是 `x % 2 != 0` 或 `x & 1`。本题元素 $\ge 1$ 不触发，但换个题面就可能翻车。
3. **窗口法下标越界**：起点上界是 $n-3$（含）；写成 $n-1$ 或 $n$ 会越界。Python 用 `range(n - 2)` 自动规避。
4. **只加不清零**：若遇偶数不清零，`[1,2,1,2,1]` 会被误判 `true`——三段奇数被偶数隔开，实际不存在三连奇数。清零是「连续」二字的正确翻译。
5. **误读「连续」**：连续指**下标连续**，与数值是否相邻无关——`[3,5,7]` 和 `[1,9,101]` 都算三连奇数；误当成「数值连续的奇数」（如必须是 $2k+1, 2k+3, 2k+5$）会把题做错。
6. **「三个」是至少三个**：四个连续奇数（如 `[1,3,5,7]`）内部包含三连，答案同样是 `true`；不要误判为「恰好长度为 3」。
