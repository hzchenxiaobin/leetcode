# LeetCode 统计从两个字符串形成目标字符串的不同方案数 题解

## 1. 题目概述

- **标题 / 题号**：统计从两个字符串形成目标字符串的不同方案数（#3981，hard）
- **链接**：https://leetcode.cn/problems/count-distinct-ways-to-form-target-from-two-strings/
- **来源**：LeetCode 第 186 场双周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划、前缀和、计数

**题意**：给定字符串 `word1`、`word2` 与 `target`，为 `target` 的**每一个**位置选一个字符，满足：

1. 第 $t$ 个位置选的字符必须等于 `target[t]`，且必须取自 `word1` 或 `word2` 的某个下标；
2. 从 `word1` 选出的下标序列必须**严格递增**，`word2` 同理；
3. 两个字符串**都至少**被选到一个字符。

若两种方案在至少一个位置上的「来源字符串或下标」不同，就视为不同方案。求方案数对 $10^9+7$ 取模。

**约束**：

- $1 \le |\textit{word1}|, |\textit{word2}|, |\textit{target}| \le 100$
- 三个串只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：word1 = "abc", word2 = "bac", target = "abc"
输出：5
解释：5 种方案分别是
  w1[0],w1[1],w2[2]      w1[0],w2[0],w1[2]
  w1[0],w2[0],w2[2]      w2[1],w1[1],w1[2]
  w2[1],w1[1],w2[2]
```

**示例 2**

```text
输入：word1 = "cd", word2 = "cd", target = "ccd"
输出：4
解释：两个 'c' 必须分别来自两个字符串，最后的 'd' 有 2 种选择 → 2×2 = 4。
```

**示例 3**

```text
输入：word1 = "xy", word2 = "xy", target = "xyxy"
输出：2
解释：target 的前半 "xy" 与后半 "xy" 必须整体来自不同的字符串 → 2 种。
```

**示例 4**

```text
输入：word1 = "ab", word2 = "cde", target = "ace"
输出：1
解释：唯一方案 w1[0]='a'、w2[0]='c'、w2[2]='e'。
```

## 3. 解题思路

### 3.1 暴力思路

对 `target` 的每个位置枚举「从 `word1` 的哪个下标取」或「从 `word2` 的哪个下标取」，递归到底再检查两个字符串是否都被用到。每个位置最多 $|\textit{word1}| + |\textit{word2}|$ 种选择，复杂度 $O\big((L_1+L_2)^{T}\big)$，$100$ 的长度下完全不可行；但它在 $L \le 4$ 时可以枚举所有方案，非常适合**对拍验证**。

### 3.2 核心观察：状态只需「两个下一个可用下标 + 使用掩码」

![状态设计：mask、p1、p2 三维 DP](images/bw186_q4_state.svg)

递推的三个关键点：

**其一，下标只需记住「下界」。** 题目只要求每个字符串内部下标**严格递增**，并不要求连续。因此处理到 `target` 的第 $t$ 个字符时，`word1` 的历史信息可以压缩成一个整数

$$p_1 = \text{已用过的最大下标} + 1$$

即「下一个可用下标的下界」。任何 $i \ge p_1$ 且 `word1[i] == target[t]` 的下标都可以选，选完之后状态变成 $i+1$。原本「选过哪些下标」的 $2^{L}$ 种历史被压成了 $L+1$ 种状态。

**其二，目标位置无需额外维度。** 因为每步恰好消耗 `target` 的一个位置，处于第 $t$ 步时 $t$ 就是「已选字符数」，天然由外层循环给出。

**其三，用 2 位掩码记录两串是否被用过。** `mask` 的第 0 位表示「用过 `word1`」、第 1 位表示「用过 `word2`」，最终只累加 `mask = 0b11` 的状态。

于是状态为 $dp[\textit{mask}][p_1][p_2]$，转移时枚举「选 `word1` 的下标 $j-1$」或「选 `word2` 的下标 $j-1$」：

$$dp'[\textit{mask}\mid 1][j][p_2] \mathrel{+}= \sum_{p_1 < j,\ \textit{word1}[j-1] = c} dp[\textit{mask}][p_1][p_2]$$

### 3.3 算法流程：前缀和把内层枚举压掉

![用前缀和把「枚举 p1」降成一次累加](images/bw186_q4_prefix.svg)

如果直接按上面的式子转移，每个 $(mask, p_2)$ 还要枚举 $j$ 与 $p_1$，复杂度 $O(T \cdot L_1^2 L_2)$，$100^4$ 级别偏慢。注意转移里对 $p_1$ 的求和是**前缀和**：

$$\text{run}(j) = \sum_{p_1 = 0}^{j-1} dp[\textit{mask}][p_1][p_2]$$

只要固定 $p_2$、让 $j$ 从小到大扫，`run` 可以边走边加，一次 $O(L_1)$ 就完成整个方向：

```text
for ch in target:
    nxt = 全 0
    for mask in 0..3:
        // 方向 1：从 word1 取
        for p2 in 0..L2:
            run = 0
            for j in 1..L1:
                run += dp[mask][j-1][p2]
                if word1[j-1] == ch:
                    nxt[mask|1][j][p2] += run
        // 方向 2：从 word2 取
        for p1 in 0..L1:
            run = 0
            for j in 1..L2:
                run += dp[mask][p1][j-1]
                if word2[j-1] == ch:
                    nxt[mask|2][p1][j] += run
    dp = nxt
answer = Σ dp[0b11][p1][p2]
```

复杂度 $O\big(T \cdot 4 \cdot L_1 L_2\big)$，$T, L \le 100$ 时约 $4 \times 10^6$ 次加法，完全够快。

### 3.4 示例演算

**示例 1**：`word1 = "abc"`，`word2 = "bac"`，`target = "abc"`。

![示例 2 的计数口径](images/bw186_q4_example.svg)

逐个字符看：

| 目标位置 | 字符 | 可选来源 |
|---------|------|---------|
| 0 | `a` | `w1[0]`、`w2[1]` |
| 1 | `b` | `w1[1]`、`w2[0]` |
| 2 | `c` | `w1[2]`、`w2[2]` |

组合共 $2 \times 2 \times 2 = 8$ 种「来源字符串」搭配，其中需要排除不满足「严格递增」或「两串都用上」的：

- `w2[1] → w2[0]`、`w1[1] → w1[0]` 这类下标倒退的组合被排除；
- 三个字符全部来自同一个字符串的组合被排除（必须两串都用）。

剩下的正是示例列出的 $5$ 种：`(w1[0],w1[1],w2[2])`、`(w1[0],w2[0],w1[2])`、`(w1[0],w2[0],w2[2])`、`(w2[1],w1[1],w1[2])`、`(w2[1],w1[1],w2[2])`。注意这些方案里 `w1[0]='a'` 有的被跳过、有的被使用——**下标可以跳**，这正是 $p_1$ 用「下界」而非「长度」的原因。

**示例 2**：`word1 = word2 = "cd"`，`target = "ccd"`。两个 `c` 必须分别来自两个串（同一个串只有一个 `c`），最后的 `d` 有 $2$ 种来源，合计 $2 \times 2 = 4$。

## 4. 算法细节

1. **$p_1$ 的语义统一**：初值 $p_1 = p_2 = 0$（都还没用）；选下标 $j-1$ 后变成 $j$。这保证「严格递增」被自动实现，且允许跳号。
2. **两个方向要分别做前缀累加**：`word1` 方向固定 $p_2$ 对 $p_1$ 求和，`word2` 方向固定 $p_1$ 对 $p_2$ 求和，不能合并。
3. **滚动数组**：每个目标字符只依赖上一轮，`dp` 与 `nxt` 交替使用即可，空间 $O(L_1 L_2)$。
4. **取模时机**：每次加法后立刻 `% MOD`，避免中间值膨胀；`run` 也要取模（否则 `run` 可能在很多次累加后溢出，C++ 里 `run` 用 `long long` 更稳）。
5. **`mask` 的合并**：`mask | 1` 与 `mask | 2` 保证「用过的字符串」只增不减。
6. **最终答案的范围**：只累加 `mask == 3`，因为题目要求两串至少各用一次；若题目不要求，则累加所有 mask。

## 5. 正确性证明

**引理 1（方案与「选择序列」一一对应）**：一个方案等价于一个长度为 $T$ 的序列 $\big((\sigma_t, k_t)\big)_{t=0}^{T-1}$，其中 $\sigma_t \in \{1,2\}$ 表示来源字符串，$k_t$ 为该串中的下标，满足 $\textit{word}_{\sigma_t}[k_t] = \textit{target}[t]$，同一字符串内的下标严格递增，且两种来源都被用到。

**证明**：题目对「不同方案」的定义正是「存在某个目标位置，其来源字符串或下标不同」，即序列中某一项 $(\sigma_t, k_t)$ 不同；反之序列相同则所有位置来源一致。故方案集合与满足条件的序列集合之间存在自然双射。∎

**引理 2（状态完备）**：在 DP 处理第 $t$ 个目标字符前，$dp[\textit{mask}][p_1][p_2]$ 恰好统计了所有「前 $t$ 个位置已选定、`word1` 已用下标的最大值 $+1 = p_1$、`word2` 已用下标的最大值 $+1 = p_2$、使用情况为 `mask`」的方案数。

**证明**：对 $t$ 归纳。$t = 0$ 时只有空方案，$p_1 = p_2 = 0$、`mask = 0`，计数为 $1$，成立。设 $t$ 时成立，考虑第 $t$ 个字符 $c$。任一 $\sigma = 1$ 的合法选择是某个 $j-1 \ge p_1$ 且 $\textit{word1}[j-1] = c$ 的下标，选后新下界为 $j$、`mask` 变为 `mask|1`。由归纳假设，对每个固定 $(p_2, mask)$，所有满足 $p_1 < j$ 的状态都会且只会被累加到 $nxt[mask|1][j][p_2]$ 上，这正是「所有以前缀 $p_1 < j$ 结尾的方案 + 本次选择 $j-1$」的集合，且不同的 $(p_1, \text{历史})$ 组合对应不同方案，不会重复计数。$\sigma = 2$ 对称。故 $t+1$ 时结论成立。∎

**引理 3（前缀和与原式等价）**：转移中 `run` 的累加结果等于 $\sum_{p_1 < j} dp[mask][p_1][p_2]$。

**证明**：`run` 在 $j$ 处累加了 $dp[mask][0..j-1][p_2]$ 共 $j$ 项，正是该前缀和。∎

**定理**：算法返回值等于满足题意的方案数（对 $10^9+7$ 取模）。

**证明**：由引理 1，方案数等于合法序列数。由引理 2，跑完 $T$ 轮后 $dp[mask][p_1][p_2]$ 统计了所有「用完 `target` 且使用情况为 `mask`」的合法序列；由引理 3 转移与原式等价。对 $mask = 0b11$（两串都被用到）的所有 $(p_1,p_2)$ 求和，即得题目要求的方案总数。取模不改变计数语义。∎

## 6. 复杂度分析

- **时间**：$O\big(T \cdot 4 \cdot (L_1 + 1)(L_2 + 1)\big)$。每轮对 4 个 mask 各做两个方向的前缀扫描，每个方向是 $O(L_1 L_2)$；$T, L_1, L_2 \le 100$ 时约 $4 \times 10^6$ 次加法。
- **空间**：$O(4 \cdot (L_1+1)(L_2+1))$，即 $O(L_1 L_2)$（滚动数组，两组状态表）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>

using namespace std;

class Solution {
public:
    int interleaveCharacters(string word1, string word2, string target) {
        const int MOD = 1000000007;
        int L1 = (int)word1.size(), L2 = (int)word2.size();
        // dp[mask][p1][p2]: 已用 word1 中下标 < p1、word2 中下标 < p2
        vector<vector<vector<long long>>> dp(4, vector<vector<long long>>(L1 + 1, vector<long long>(L2 + 1, 0)));
        dp[0][0][0] = 1;
        for (char ch : target) {
            vector<vector<vector<long long>>> nxt(4, vector<vector<long long>>(L1 + 1, vector<long long>(L2 + 1, 0)));
            for (int mask = 0; mask < 4; mask++) {
                // 选 word1 的下标 j-1: 之前用到的下标必须 < j
                for (int p2 = 0; p2 <= L2; p2++) {
                    long long run = 0;
                    for (int j = 1; j <= L1; j++) {
                        run += dp[mask][j - 1][p2];
                        if (word1[j - 1] == ch) {
                            nxt[mask | 1][j][p2] = (nxt[mask | 1][j][p2] + run) % MOD;
                        }
                    }
                }
                // 选 word2 的下标 j-1
                for (int p1 = 0; p1 <= L1; p1++) {
                    long long run = 0;
                    for (int j = 1; j <= L2; j++) {
                        run += dp[mask][p1][j - 1];
                        if (word2[j - 1] == ch) {
                            nxt[mask | 2][p1][j] = (nxt[mask | 2][p1][j] + run) % MOD;
                        }
                    }
                }
            }
            dp = nxt;
        }
        long long total = 0;
        for (int p1 = 0; p1 <= L1; p1++) {
            for (int p2 = 0; p2 <= L2; p2++) {
                total = (total + dp[3][p1][p2]) % MOD;
            }
        }
        return (int)total;
    }
};
```

### Python

```python
MOD = 10 ** 9 + 7

class Solution:
    def interleaveCharacters(self, word1: str, word2: str, target: str) -> int:
        L1, L2 = len(word1), len(word2)
        dp = [[[0] * (L2 + 1) for _ in range(L1 + 1)] for _ in range(4)]
        dp[0][0][0] = 1
        for ch in target:
            new = [[[0] * (L2 + 1) for _ in range(L1 + 1)] for _ in range(4)]
            for mask in range(4):
                f = dp[mask]
                # 从 word1 取: 目标位置 t 选下标 j-1, 上一状态要求已用下标 < j
                for p2 in range(L2 + 1):
                    run = 0
                    for j in range(1, L1 + 1):
                        run += f[j - 1][p2]
                        if word1[j - 1] == ch:
                            new[mask | 1][j][p2] = (new[mask | 1][j][p2] + run) % MOD
                for p1 in range(L1 + 1):
                    run = 0
                    row = f[p1]
                    for j in range(1, L2 + 1):
                        run += row[j - 1]
                        if word2[j - 1] == ch:
                            new[mask | 2][p1][j] = (new[mask | 2][p1][j] + run) % MOD
            dp = new
        total = 0
        for p1 in range(L1 + 1):
            for p2 in range(L2 + 1):
                total += dp[3][p1][p2]
        return total % MOD
```

## 8. 边界情况与易错点

1. **必须两串都用**：只累加 `mask == 3`。示例 3（`"xy","xy" → "xyxy"`）若把 `mask` 判断去掉会得到 $6$ 而不是 $2$。
2. **下标可跳号**：`p1` 表示「下界」而不是「已用个数」，转移写成 `j-1 >= p1`。若误以为下标必须连续，会漏掉大量方案（示例 1 的第 4、5 种方案就跳过了 `w1[0]`）。
3. **`run` 的累加顺序**：先 `run += dp[mask][j-1][p2]` 再判断 `word1[j-1] == ch` 后累加，保证 $p_1 < j$ 的前缀语义；顺序写反会变成 $p_1 \le j$，把「自己配自己」算进去。
4. **两个方向不能合并**：`word1` 方向固定 $p_2$、`word2` 方向固定 $p_1$，前缀和的维度不同。
5. **`target` 太长**：若 $|\textit{target}| > L_1 + L_2$，答案必然为 $0$；算法会自然得到 $0$，但可以提前返回省时间。
6. **`target` 只有一个字符**：两串都用上不可能（一个字符只能来自一个串），答案 $0$；DP 累加 `mask == 3` 时自然为 $0$。
7. **重复字符**：同一字符串中相同字符出现在多个位置时，**不同下标算不同方案**，所以转移里对每个 $j$ 都要累加，不能「按字符去重」。
8. **取模**：`run` 与累加结果都要取模；C++ 中 `run` 用 `long long`，`nxt` 用 `long long` 存中间值。
