# LeetCode 最大有效数对和 题解

## 1. 题目概述

- **标题 / 题号**：最大有效数对和（#3979，medium）
- **链接**：https://leetcode.cn/problems/maximum-valid-pair-sum/
- **来源**：LeetCode 第 186 场双周赛 Q2
- **难度**：中等
- **标签**：数组、枚举、前缀最大值

**题意**：给定长度为 $n$ 的数组 `nums` 与整数 $k$。下标对 $(i, j)$ 称为**有效**，当且仅当

$$0 \le i < j < n,\qquad j - i \ge k$$

求所有有效对中 $\textit{nums}[i] + \textit{nums}[j]$ 的**最大值**。

**约束**：

- $2 \le n \le 10^5$
- $1 \le \textit{nums}[i] \le 10^9$
- $1 \le k \le n - 1$（保证至少存在一对有效下标）

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,5,2,8], k = 2
输出：13
解释：有效对中最大的是 (2,4)：nums[2]+nums[4] = 5+8 = 13。
```

**示例 2**

```text
输入：nums = [5,1,9], k = 1
输出：14
解释：k=1 时所有 i<j 都有效，最大为 (0,2)：5+9 = 14。
```

**示例 3**

```text
输入：nums = [1,2], k = 1
输出：3
解释：只有一对 (0,1)，答案 1+2 = 3（k = n-1 的退化情形）。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $i < j$ 且 $j - i \ge k$ 的下标对，取和的最大值：

```text
ans = -inf
for i = 0 .. n-1:
    for j = i+k .. n-1:
        ans = max(ans, nums[i] + nums[j])
```

共约 $\binom{n}{2}$ 对，$n = 10^5$ 时是 $5 \times 10^9$ 次加法，必然超时。因此必须把内层的「枚举 $j$」或「枚举 $i$」消掉。

### 3.2 核心观察：固定 $j$，左端点只剩「前缀最大值」

![固定右端点 j：左端点只能取 0..j−k，取其中最大值](images/bw186_q2_window.svg)

把视角从「数对」切换到「右端点 $j$」：

$$ \textit{ans} = \max_{k \le j < n}\left( \textit{nums}[j] + \max_{0 \le i \le j-k} \textit{nums}[i] \right) $$

对数对 $(i,j)$ 的约束可以拆成两层：$j$ 一旦固定，$i$ 的可行集合就是**前缀** $[0, j-k]$。而「在前缀里取最大」这件事是**可以增量维护**的：

$$\textit{best}_j = \max(\textit{best}_{j-1},\ \textit{nums}[j-k])$$

于是扫描 $j$ 从 $k$ 到 $n-1$，每次 $O(1)$ 更新 `best` 并计算候选值，总复杂度 $O(n)$。

![示例 1 的逐步演算](images/bw186_q2_example.svg)

关键点在于：**加法使「取最大左端点」与「取最大和」等价**。因为 $\textit{nums}[j]$ 与 $i$ 无关，固定 $j$ 后要让 $\textit{nums}[i] + \textit{nums}[j]$ 最大，只需让 $\textit{nums}[i]$ 最大，不需要考虑「下标接近」等额外因素。

### 3.3 算法流程

```text
1. best = nums[0]                  // max(nums[0..j-k])，先放入 i=0
2. ans = -inf
3. for j = k .. n-1:
4.     best = max(best, nums[j - k])   // 把新进入窗口的 j-k 并入
5.     ans  = max(ans, best + nums[j])
6. return ans
```

注意第 3～5 行的顺序：`j = k` 时窗口是 $[0, 0]$，正好由初始化 + 第 4 行覆盖；窗口随着 $j$ 增大而右扩，绝不会缩小，所以 `best` 只增不减，**不需要滑动窗口的删除操作**。

### 3.4 示例演算

以示例 1（`nums = [1,3,5,2,8]`，$k = 2$）为例：

| $j$ | 可行 $i$ | `best` $=\max\textit{nums}[0..j-2]$ | 候选和 | 当前答案 |
|-----|---------|--------------------------------------|--------|---------|
| 2 | $i \le 0$ | $\max(1) = 1$ | $1+5 = 6$ | 6 |
| 3 | $i \le 1$ | $\max(1,3) = 3$ | $3+2 = 5$ | 6 |
| 4 | $i \le 2$ | $\max(1,3,5) = 5$ | $5+8 = 13$ | **13** |

最终答案 $13$，与示例一致。注意 $j = 3$ 时候选和反而变小了——这正是「不能贪心地取最近的 $i$」的直观体现。

## 4. 算法细节

1. **`best` 的初值**：`nums[0]`。因为 $j$ 从 $k$ 开始，第一步的窗口就是 $[0, j-k] = [0,0]$。
2. **`ans` 的初值**：用 `INT_MIN` / `-inf`，不要用 $0$——虽然本题 $\textit{nums}[i] \ge 1$，用 $0$ 也碰巧正确，但养成习惯更安全。
3. **循环顺序**：先把 `nums[j-k]` 并入 `best`，再计算候选。若顺序反了，$j = k$ 时窗口为空，会把 `nums[j]` 与自己配对。
4. **不需要单调队列**：因为窗口只有「右扩」没有「左缩」（$i$ 的上界 $j-k$ 随 $j$ 单调递增），所以维护一个标量最大值即可，比滑动窗口最大值问题简单一档。
5. **求和不会溢出 `int`**：$\textit{nums}[i] \le 10^9$，两数之和不超过 $2 \times 10^9 < 2^{31}-1$；但若题目把上界改成 $2 \times 10^9$ 就必须用 `long long`，C++ 里建议中间量写成 `long long` 更保险。
6. **$k = n-1$**：只可能取 $(0, n-1)$ 这一对，循环执行一次，逻辑自然正确。

## 5. 正确性证明

**引理 1（固定 $j$ 时的最优左端点）**：对固定的 $j \ge k$，令 $i^{*}$ 为 $[0, j-k]$ 中使 $\textit{nums}[i]$ 最大的下标，则对所有合法 $i$ 有 $\textit{nums}[i] + \textit{nums}[j] \le \textit{nums}[i^{*}] + \textit{nums}[j]$。

**证明**：由 $i^{*}$ 的定义，$\textit{nums}[i] \le \textit{nums}[i^{*}]$ 对任意 $i \in [0, j-k]$ 成立；两边同加常数 $\textit{nums}[j]$，不等号方向不变。∎

**引理 2（`best` 的语义）**：算法在第 5 行计算候选时，`best` 恰等于 $\max_{0 \le i \le j-k} \textit{nums}[i]$。

**证明**：对 $j$ 归纳。$j = k$ 时，第 4 行把 $\textit{nums}[0]$ 并入 `best`，而初值就是 $\textit{nums}[0]$，故 `best` $= \max_{0 \le i \le 0}\textit{nums}[i]$。设 $j$ 时成立，则 $j+1$ 时第 4 行把 $\textit{nums}[j+1-k]$ 并入，得到 $\max\big(\max_{0\le i \le j-k}\textit{nums}[i],\ \textit{nums}[j+1-k]\big) = \max_{0 \le i \le j+1-k}\textit{nums}[i]$。∎

**定理**：算法返回值等于所有有效对的 $\textit{nums}[i] + \textit{nums}[j]$ 的最大值。

**证明**：设 $M$ 为全体有效对的最大和，$A$ 为算法返回值。

- $A \le M$：算法每个候选值都由某个合法对 $(i, j)$ 产生（由引理 2，$i \in [0, j-k]$ 即 $j - i \ge k$，且 $i < j$），故 $A$ 是某个有效对的和，$A \le M$。
- $A \ge M$：设 $M$ 由有效对 $(i_0, j_0)$ 取得。算法在 $j = j_0$ 这一轮有候选值 $\textit{nums}[j_0] + \textit{best}$，由引理 2 及引理 1，$\textit{best} \ge \textit{nums}[i_0]$，故该轮候选值 $\ge M$，从而 $A \ge M$。

综上 $A = M$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。循环 $j$ 从 $k$ 到 $n-1$ 共 $n-k \le n$ 轮，每轮两次比较与一次加法。
- **空间**：$O(1)$。只维护 `best` 与 `ans` 两个变量，未使用额外数组。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>

using namespace std;

class Solution {
public:
    int maxValidPairSum(vector<int>& nums, int k) {
        int best_first = nums[0];  // max(nums[0..j-k])
        int ans = INT_MIN;
        for (int j = k; j < (int)nums.size(); j++) {
            best_first = max(best_first, nums[j - k]);
            ans = max(ans, best_first + nums[j]);
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxValidPairSum(self, nums: List[int], k: int) -> int:
        best_first = nums[0]
        ans = float("-inf")
        for j in range(k, len(nums)):
            best_first = max(best_first, nums[j - k])
            ans = max(ans, best_first + nums[j])
        return ans
```

## 8. 边界情况与易错点

1. **$k = n-1$**：只有 $(0, n-1)$ 一对有效，循环只跑一轮；若把 `best` 初值写成 `nums[k]` 之类会直接错。
2. **$k = 1$**：所有 $i < j$ 都有效，答案等于「最大值 + 次大值」（若两者下标不同）。代码无需特判。
3. **先更新 `best` 再算候选**：顺序写反会让 $j = k$ 时窗口为空，退化成「自己配自己」。
4. **`ans` 用 $0$ 初始化**：本题因 $\textit{nums}[i] \ge 1$ 侥幸正确，但一旦数组含负数就会错。用 `INT_MIN` / `-inf`。
5. **求和溢出**：$\textit{nums}[i] \le 10^9$ 时和不超过 $2 \times 10^9$，刚好在 `int` 范围内；但若上界提高到 $2\times10^9$ 就溢出，建议中间量用 `long long`。
6. **误用「相邻最大」思路**：合法对不要求相邻，只看下标距离 $\ge k$，所以不能取「最大的两个相邻元素」。
7. **下标越界**：`j - k` 最小为 $0$（$j = k$），最大为 $n-1-k \le n-1$，不会越界；反之若循环写成 $j$ 从 $k-1$ 开始就会取到负数下标。
