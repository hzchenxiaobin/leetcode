# LeetCode 至少有 K 个重复字符的最长子串 题解

## 1. 题目概述

- **标题 / 题号**：至少有 K 个重复字符的最长子串（#395，medium）
- **链接**：https://leetcode.cn/problems/longest-substring-with-at-least-k-repeating-characters/
- **来源**：LeetCode 第 3 场周赛 Q4
- **难度**：中等
- **标签**：哈希表、字符串、分治、滑动窗口

**题意**：给定字符串 `s` 与整数 `k`，求 `s` 的一个**连续子串**的最大长度，要求该子串中**每一种出现过的字符**都至少出现 $k$ 次；不存在这样的子串时返回 0。

**约束**：

- $1 \le \lvert s \rvert \le 10^4$
- `s` 仅由小写英文字母组成
- $1 \le k \le 10^5$

## 2. 示例

**示例 1**

```text
输入：s = "aaabb", k = 3
输出：3
解释：最长子串为 "aaa"，其中 'a' 重复了 3 次。
      "aaabb" 含 'b' 两次 < 3，整串不合格；"aaab" 同理。
```

**示例 2**

```text
输入：s = "ababbc", k = 2
输出：5
解释：最长子串为 "ababb"，其中 'a' 重复 2 次、'b' 重复 3 次，都 ≥ 2。
      整串多了 'c'（只出现 1 次），所以不能取长度 6。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子串 $[i,j]$（$O(n^2)$ 个），对每个子串用长度 26 的计数数组检查是否每种字符都 $\ge k$。由于 $[i,j]$ 的计数可以从 $[i,j-1]$ 增量更新，单次判定是 $O(1)$，总复杂度 $O(n^2)$：$n = 10^4$ 时约 $5\times 10^7$ 次操作，勉强能过但没有任何余地（$n$ 再大一个量级就死）。

更诱人的是「一个双指针直接滑」：维护窗口，遇到不合格就移出左边。这条路**是错的**，因为**「不合法」对扩张没有单调性**：

$$s = \texttt{ab},\ k = 2 \text{ 时窗口不合法};\qquad s = \texttt{abab},\ k = 2 \text{ 时却合法}$$

`"ab"` 里 `a`、`b` 各 1 次都不合格，但往右扩两个字符就变成了合法窗口。既然「暂时不合法」不等于「永远不合法」，就**不能在窗口不合法时收缩**——标准双指针赖以成立的前提（窗口越大越难满足约束）在这里不成立。

### 3.2 核心观察：把「种数」从变量变成枚举量

![枚举不同字符种数 d](images/wc3_q4_distinct_enum.svg)

突破口在于：答案子串里出现的字符**种数**虽然事先不知道，但它只能是 $1 \sim 26$ 之间的一个整数。于是我们**把这个未知量枚举掉**：外层令 $d = 1,2,\dots,\sigma$（$\sigma$ 为 `s` 中实际出现的种数），内层只解决一个被简化的问题：

> 在「窗口内**至多** $d$ 种字符」的限制下，求所有字符次数都 $\ge k$ 的最长窗口。

一旦种数被限定，约束就变成**单调**的了：窗口越长、越容易超出 $d$ 种。于是「种数 $> d$ 就收缩左端」是安全的，双指针重新成立。而任意一个合法子串的种数都是某个确定的 $d^*$，它一定会在第 $d^*$ 轮被考察到。

代价是外层 26 轮，收益是内层从 $O(n^2)$ 降到 $O(n)$，总计 $O(26n)$。

> 💡 一句话记忆：**「种类数未知」就枚举种类数**，把「两个约束」的双指针降成「一个约束」的双指针。

### 3.3 算法流程

![固定 d 后的双指针流程](images/wc3_q4_window_flow.svg)

窗口 $[\text{left}, \text{right}]$ 上维护两个计数器，它们的值都由 26 个计数 `cnt[26]` 决定：

$$\text{distinct} = \bigl\lvert\{\,c : \text{cnt}[c] > 0\,\}\bigr\rvert, \qquad \text{good} = \bigl\lvert\{\,c : \text{cnt}[c] \ge k\,\}\bigr\rvert$$

于是「窗口合法」等价于 $\text{distinct} = \text{good}$（所有出现过的字符都够 $k$ 次），而本轮的目标窗口还要求 $\text{distinct} = d$。

```text
best = 0
for d in 1 .. σ:                     # σ = s 中出现的字符种数
    cnt[26] = {0}; left = 0; distinct = 0; good = 0
    for right in 0 .. n-1:
        把 s[right] 加入窗口，维护 distinct / good
        while distinct > d:          # 种数超了，只能缩
            把 s[left] 移出窗口，left += 1
        if distinct == d and good == d:
            best = max(best, right - left + 1)
return best
```

关键点：

1. **加入**：`cnt[c]` 由 $0 \to 1$ 时 `distinct++`；由 $k-1 \to k$ 时 `good++`。
2. **移出**：`cnt[c]` 由 $k \to k-1$ 时 `good--`（必须在减之前判）；由 $1 \to 0$ 时 `distinct--`（必须在减之后判）。
3. **收缩是 while 不是 if**：加入一个字符最多让种数 $+1$，但要让多出来的那个字符**彻底离开窗口**，得把它在窗口内的每一次出现都移走——它可能位于窗口中段，一次收缩远远不够。

### 3.4 示例演算

![s = "ababbc"，k = 2，d = 2 的窗口走查](images/wc3_q4_walkthrough.svg)

以示例 2 的 `s = "ababbc"`、$k = 2$ 为例，$d = 2$ 这一轮的走查：

| right | 加入 | 窗口 | distinct | good | 动作 |
|---|---|---|---|---|---|
| 0 | a | `"a"` [0,0] | 1 | 0 | 种数不足 2，跳过 |
| 1 | b | `"ab"` [0,1] | 2 | 0 | good = 0 < 2，跳过 |
| 2 | a | `"aba"` [0,2] | 2 | 1 | good = 1 < 2，跳过 |
| 3 | b | `"abab"` [0,3] | 2 | 2 | 合法，best = 4 |
| 4 | b | `"ababb"` [0,4] | 2 | 2 | 合法，best = 5 |
| 5 | c | `"abbc"` [2,5]（缩 2 次） | 2 | 1 | 移出 a、b 后 c 仅 1 次，不更新 |

第 5 行是唯一需要收缩的时刻：加入 `c` 后 `distinct` 变成 3，`left` 连续右移两次（移出下标 0 的 `a`、下标 1 的 `b`）才回到 2 种，此时窗口是 `"abbc"`，`c` 只有 1 次，`good = 1 ≠ 2`，答案保持 5。

三轮的汇总：$d = 1$ 得到 `"bb"` 长度 2，$d = 2$ 得到 `"ababb"` 长度 5，$d = 3$ 得到 0（整串里 `c` 只出现 1 次），取最大即 **5**。注意 $d=1$ 的答案是 2 而不是 0——这正是必须逐轮枚举、不能只看某一个 $d$ 的原因。

## 4. 算法细节

1. **计数器的两个「触发时刻」**：`distinct` 在计数 $0 \leftrightarrow 1$ 之间翻转，`good` 在计数 $k-1 \leftrightarrow k$ 之间翻转。加入时先 `cnt[c]++` 再比较 `cnt[c] == k`；移出时先比较 `cnt[d] == k` 再 `cnt[d]--`。顺序写反会让 `good` 永远差 1。
2. **收缩必须用 `while`**：超限的那个字符可能在窗口中段，要连续移出它之前的全部字符它才会消失。用 `if` 只保证缩一次，会留下 `distinct > d` 的非法窗口，破坏引理 2 的不变量（窗口不再是 $[L_d(r), r]$），进而漏解。
3. **判定条件写全**：`distinct == d and good == d`。单写 `good == d` 也可以（因为 $\text{good} \le \text{distinct} \le d$），但显式写出两种相等更能表达「种数正好是 $d$、且每种都够 $k$ 次」的含义，也避免日后改成「至少 $d$ 种」时改错。
4. **$d$ 的上界取真实种数**：`total = len(set(s))`，而不是硬编码 26。$d > \text{total}$ 时窗口永远凑不满 $d$ 种，跑一遍纯属浪费；若 `s` 只有 2 种字符，外层只跑 2 轮。
5. **特判 $k \le 1$**：此时任何子串（包括整串）都合法，直接返回 $n$，省掉全部循环。这也是唯一能让「空窗口」合法的参数。
6. **字符先映射成 $0\sim25$，并用定长数组计数**：C++ 里 `s[i] - 'a'` 得到非负下标（`char` 是否有符号与本题无关，但仍建议先转 `int`）；Python 里先用列表推导算好 `code`，避免在 $O(26n)$ 的内层反复调用 `ord`。字符集只有 26 个，`vector<int>(26)` / `[0]*26` 比 `unordered_map` 快一个量级；每轮重新分配一个 26 元素数组的总代价只有 $O(26\sigma)$。
7. **提前结束**：若某一轮结束 `best == n`，答案已取到上界，`break` 掉剩余轮次（C++ 里写成循环条件 `best < n`）。
8. **另一条等价路线（分治）**：若某字符在整段中总出现次数 $< k$，它**不可能出现在答案里**，于是答案必在它切开的某一段中；对每段递归即可。每次切分都让「段内种数」严格减少，递归深度 $\le \sigma$，每层总扫描量 $O(n)$，复杂度同样是 $O(26n)$，且大多数数据上更快（能跳过大量无效区间），但最坏情况仍是 $O(26n)$，代码略长。

## 5. 正确性证明

固定一轮的 $d$。定义

$$L_d(r) = \min\{\,l : [l, r] \text{ 中含至多 } d \text{ 种字符}\,\}$$

由于 $l = r$ 时只有 1 种字符，该集合非空，$L_d(r)$ 有意义。

**引理 1（判定通过即合法）**：若某窗口满足 $\text{distinct} = \text{good} = d$，则该窗口内每种字符都至少出现 $k$ 次。

**证明**：`good` 统计的是计数 $\ge k$ 的字符种数，`distinct` 统计的是计数 $> 0$ 的字符种数。二者相等意味着「出现过的字符」与「出现够 $k$ 次的字符」是同一批，故窗口内每个出现过的字符次数都 $\ge k$。∎

**引理 2（窗口不变量）**：每轮 $d$ 中，处理完 `s[right]` 并完成收缩后，窗口恰为 $[L_d(\text{right}), \text{right}]$。

**证明**：先证 $L_d(r)$ 关于 $r$ 单调不减。设 $l < L_d(r-1)$，则 $[l, r-1]$ 含超过 $d$ 种字符；加入 `s[r]` 只会让种数不减，故 $[l, r]$ 仍含超过 $d$ 种，即 $l < L_d(r)$。于是 $L_d(r) \ge L_d(r-1)$。

对 $r$ 归纳。$r = 0$：加入单字符后 `distinct` $= 1 \le d$（$d \ge 1$），不收缩，`left` $= 0 = L_d(0)$。设处理 $r-1$ 后 `left` $= L_d(r-1)$。加入 `s[r]` 后 `left` 不动，由单调性有 `left` $= L_d(r-1) \le L_d(r)$；循环把 `left` 逐一右移，而「窗口种数 $\le d$」关于 `left` 单调（`left` 越大种数越少），循环停下的第一个位置正是满足条件的最小下标，即 $L_d(r)$。∎

**引理 3（覆盖性）**：若存在合法子串 $[a,b]$ 恰含 $d$ 种字符，则在第 $d$ 轮、$r = b$ 时，窗口 $[L_d(b), b]$ 合法且长度不小于 $b-a+1$。

**证明**：$[a,b]$ 只含 $d$ 种字符，故由 $L_d$ 的最小性得 $L_d(b) \le a$，窗口包含 $[a,b]$。子串中的字符计数关于包含关系单调，故窗口内每种字符的次数不少于它在 $[a,b]$ 中的次数，而后者 $\ge k$，于是窗口里每个出现过的字符都够 $k$ 次，即 $\text{good} = \text{distinct}$。另一方面窗口含至多 $d$ 种字符（定义），又包含 $[a,b]$ 的 $d$ 种字符，故 $\text{distinct} = d$，判定必然通过。长度 $b - L_d(b) + 1 \ge b - a + 1$。∎

**定理**：算法返回的 `best` 等于最长合法子串的长度 $OPT$。

**证明**：先证 `best` $\le OPT$。`best` 每次更新都取 `right - left + 1`，而更新前判定已通过，由引理 1 该窗口合法，故它的长度不超过 $OPT$。

再证 `best` $\ge OPT$。若 $OPT = 0$，结论显然。否则设最长合法子串 $W$ 恰含 $d^*$ 种字符，由约束 $1 \le d^* \le \sigma$，第 $d^*$ 轮会被执行。由引理 3，该轮在 $r$ 等于 $W$ 的右端点时得到一个长度 $\ge OPT$ 的合法窗口，判定通过并更新 `best`；而长度不可能超过 $OPT$，故该轮 `best` $= OPT$，且此后只会被同样合法的窗口覆盖为不超过 $OPT$ 的值。综上 `best` $= OPT$。∎

## 6. 复杂度分析

- **时间**：外层至多 $\sigma \le 26$ 轮；每轮 `right` 前进 $n$ 步、`left` 单调右移累计不超过 $n$ 步，每次移动都是 $O(1)$ 的数组操作，判定 $O(1)$。总时间 $O(\sigma n) \le O(26n) = O(n)$（字符集常数），$n = 10^4$ 时约 $2.6\times10^5$ 次窗口操作。
- **空间**：每轮一个长度 26 的计数数组、一个长度 $n$ 的字符编码数组，$O(\sigma + n)$；若直接从字符串取字符则额外空间只有 $O(\sigma) = O(1)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int longestSubstring(string s, int k) {
        int n = (int)s.size();
        if (k <= 1) return n;              // 每个只出现 1 次的字符也满足「至少 k 次」

        vector<int> code(n);
        vector<bool> present(26, false);
        int total = 0;
        for (int i = 0; i < n; ++i) {
            code[i] = s[i] - 'a';
            if (!present[code[i]]) { present[code[i]] = true; ++total; }
        }

        int best = 0;
        for (int target = 1; target <= total && best < n; ++target) {
            vector<int> cnt(26, 0);
            int left = 0, distinct = 0, good = 0;
            for (int right = 0; right < n; ++right) {
                int c = code[right];
                if (cnt[c] == 0) ++distinct;   // 0 -> 1，种数 +1
                if (++cnt[c] == k) ++good;     // k-1 -> k，达标种数 +1
                while (distinct > target) {    // 种数超限，只能缩左端
                    int d = code[left++];
                    if (cnt[d] == k) --good;   // k -> k-1
                    if (--cnt[d] == 0) --distinct;  // 1 -> 0
                }
                if (distinct == target && good == target) {
                    int len = right - left + 1;
                    if (len > best) best = len;
                }
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def longestSubstring(self, s: str, k: int) -> int:
        n = len(s)
        if k <= 1:                      # 每个只出现 1 次的字符也满足「至少 k 次」
            return n

        code = [ord(ch) - 97 for ch in s]
        total = len(set(code))
        best = 0
        for target in range(1, total + 1):
            if best == n:
                break
            cnt = [0] * 26
            left = distinct = good = 0
            for right in range(n):
                c = code[right]
                if cnt[c] == 0:
                    distinct += 1
                cnt[c] += 1
                if cnt[c] == k:
                    good += 1
                while distinct > target:
                    d = code[left]
                    left += 1
                    if cnt[d] == k:
                        good -= 1
                    cnt[d] -= 1
                    if cnt[d] == 0:
                        distinct -= 1
                if distinct == target and good == target:
                    if right - left + 1 > best:
                        best = right - left + 1
        return best
```

## 8. 边界情况与易错点

1. **$k = 1$**：任何子串都合法，答案是 $n$。若不特判，代码也能正确（$d = \sigma$ 那轮整串满足 `distinct == good == σ`），但会白跑 $\sigma$ 轮。
2. **$k > n$**：任何一种字符都不可能凑够 $k$ 次，答案必为 0。代码里所有轮次的 `good` 都停在 0，`best` 保持 0，无需额外特判。
3. **答案为 0 的输入**：如 `"ababacb", k = 3`，不要因为「至少能取一个字符」就返回 1——单个字符出现 1 次 $< k$，并不合法。
4. **收缩用 `if`**：只缩一次会留下 `distinct > d` 的窗口，破坏引理 2 的不变量。它不会算大（判定要求 `distinct == d`），但会**漏解**：如 `"aaabaaacc", k = 2` 正确答案是 5，只缩一次会得到 3。
5. **`good` 的更新顺序**：移出时必须先判 `cnt[d] == k`（此时正要跌到 $k-1$），再自减；若先自减再判 `== k`，就永远不成立，`good` 只增不减。
6. **`distinct` 的更新顺序**：移出时必须先自减再判 `== 0`；加入时先判 `== 0` 再自增。
7. **$d$ 从 1 开始**：若从 0 开始，窗口会被缩成空窗口，`distinct == good == 0 == target` 成立，虽然只贡献长度 0 不影响答案，但语义混乱。
8. **Python 的性能陷阱**：内层循环里不要写 `s[right]` 反复索引字符串（每次都产生新的一字符字符串），先转成整数列表；也不要在循环里用 `Counter` 或 `set(window)`，那会把 $O(1)$ 的更新退化成 $O(26)$ 甚至 $O(\text{窗口长})$。
9. **`best < n` 作为循环条件**：C++ 中写成 `target <= total && best < n` 可以提前结束；若误写成 `best <= n` 则永远不会提前退出。
