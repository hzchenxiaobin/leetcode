# LeetCode 判断子序列 题解

## 1. 题目概述

- **标题 / 题号**：判断子序列（#392，easy）
- **链接**：https://leetcode.cn/problems/is-subsequence/
- **来源**：LeetCode 第 3 场周赛 Q1
- **难度**：简单
- **标签**：双指针、字符串、动态规划

**题意**：给定字符串 `s` 与 `t`，判断 `s` 是否为 `t` 的**子序列**，即能否从 `t` 中删去若干字符（也可不删）且**不改变剩余字符的相对顺序**，得到 `s`。返回 `true` / `false`。

**约束**：

- $0 \le \lvert s \rvert \le 100$
- $0 \le \lvert t \rvert \le 10^4$
- `s`、`t` 只由小写英文字母组成

**进阶**：若 $k \ge 10^9$ 个 `S_i` 依次询问同一个 `T`，要如何改代码？（§3.1 已说明为何「每次查询重跑一遍」不可行，§4 第 6 条给出 $O(26\lvert t\rvert)$ 预处理的方案。）

## 2. 示例

**示例 1**

```text
输入：s = "abc", t = "ahbgdc"
输出：true
解释：a、b、c 依次出现在 t 的下标 0、2、5，相对顺序与 s 一致。
```

**示例 2**

```text
输入：s = "axc", t = "ahbgdc"
输出：false
解释：a 与 c 都能找到，但 t 中不存在 x，因此 s 无法被完整匹配。
```

**补充（空串边界，非官方示例）**

```text
输入：s = "", t = ""
输出：true
解释：空串是任意字符串（包括空串）的子序列，两种「一个空、一个非空」的组合同理。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「枚举 `t` 的所有子序列，看是否等于 `s`」：枚举量 $2^{\lvert t \rvert}$，$\lvert t \rvert = 10^4$ 时天文数字，完全不可行。

稍好一点的是最长公共子序列 DP：$f(i,j)$ 表示 `s` 前 $i$ 个字符与 `t` 前 $j$ 个字符的 LCS 长度，转移

$$f(i,j) = \begin{cases} f(i-1,j-1) + 1, & s_{i-1} = t_{j-1} \\ \max\bigl(f(i-1,j),\, f(i,j-1)\bigr), & s_{i-1} \ne t_{j-1} \end{cases}$$

最后判断 $f(\lvert s\rvert, \lvert t\rvert) = \lvert s\rvert$。复杂度 $O(\lvert s \rvert \lvert t \rvert)$，本题最多 $10^6$ 次运算**能过**，但它把一个只需「按序扫描」的问题做成了二维 DP，既浪费空间也丢掉了结构信息。而且进阶版「$10^9$ 次查询」下，每个查询都重跑一遍 DP 是不可接受的。

### 3.2 核心观察：贪心双指针

![双指针贪心：t 上顺序扫描，s 只能向后推进](images/wc3_q1_two_pointer_concept.svg)

**关键观察**：子序列要求「顺序一致」，一旦确定了 `s` 中字符的匹配顺序（就是 `s` 自身的顺序），每一步都**没有选择的余地**——只有「匹配到哪个位置」的自由。而「匹配到**尽可能靠前**的位置」永远不吃亏：

- 把 `s[i]` 匹配到 `t` 中更靠前的 `j`，留下的后缀 `t[j+1..)` 更长；
- 后缀更长，后续字符可用的位置集合是后者的**超集**，因此绝不会比「匹配到更后面」的方案更差。

这是标准的**交换论证（exchange argument）**：假设存在某个合法嵌入把 `s[i]` 放在 $j' > j$，由于 `t[j] = s[i]`，把这一处改成 $j$ 后，后面的匹配位置全部保持不动仍然严格递增，嵌入依然合法。所以「最早匹配」的贪心不会漏解。

于是只需要两个指针：`i` 指向 `s` 中下一个待匹配字符，`j` 在 `t` 上从左到右扫描。若 `t[j] == s[i]`，说明 `s[i]` 在当前位置可以被最早地匹配掉，`i++`；然后无论是否匹配，`j++` 继续。`i` 走到 $\lvert s \rvert$ 即返回 `true`，`j` 走到 $\lvert t \rvert$ 而 `i` 还没到头即返回 `false`。

> 💡 **一句话记忆**：子序列判定 = 「`s` 的字符按顺序去 `t` 里捡，捡到就往前走」。这也是子序列自动机（$\text{nxt}$ 表）做法的出发点。

### 3.3 算法流程 / 状态转移

![算法流程：一次扫描，两个退出条件](images/wc3_q1_greedy_flow.svg)

流程只有一层循环，两个退出条件：

1. 初始化 `i = 0, j = 0`；
2. 若 $i = \lvert s \rvert$，返回 `true`（`s` 已全部匹配完，剩余 `t` 随意丢弃）；
3. 若 $j = \lvert t \rvert$，返回 `false`（`t` 用完了还有字符没匹配）；
4. 若 `t[j] == s[i]`，则 `i++`；
5. `j++`，回到第 2 步。

把第 2、4 步合并，就是常见的紧凑写法：循环条件 `j < m && i < n`，循环体内 `if (t[j] == s[i]) i++;`，循环结束后 `return i == n;`。注意第 2 步的判定必须放在循环条件里，否则「`s` 提前匹配完」时还会白扫 `t` 的后半段（语义不错，但白白多花时间；极端情况如 `s = "a"`、`t` 以 `a` 开头且后面还有 $10^4$ 个其他字母，差别明显）。

### 3.4 示例演算

![示例演算：s = abc，t = ahbgdc](images/wc3_q1_walkthrough_abc.svg)

对 `s = "abc"`、`t = "ahbgdc"`，逐字符走查：

| `j` | `t[j]` | 当前 `s[i]` | 相等？ | `i` 更新后 |
|-----|--------|-------------|--------|------------|
| 0 | a | a | ✓ | 1 |
| 1 | h | b | ✗ | 1 |
| 2 | b | b | ✓ | 2 |
| 3 | g | c | ✗ | 2 |
| 4 | d | c | ✗ | 2 |
| 5 | c | c | ✓ | 3 = $\lvert s \rvert$ → `true` |

`j = 1` 的 `h`、`j = 3` 的 `g`、`j = 4` 的 `d` 都是「多余字符」，被直接跳过；`i` 一共推进 3 次，正好等于 `s` 的长度。

反例 `s = "axc"`、`t = "ahbgdc"`：`j = 0` 命中 `a` 后 `i = 1`，此后 `t` 中再也没有 `x`，`j` 扫到 6 时 `i` 仍是 1，小于 3，返回 `false`。

## 4. 算法细节

1. **循环条件必须同时判两个指针**：写成 `for (int j = 0; j < m && i < n; ++j)`。若只判 `j < m`，在 `s` 已经匹配完后仍会访问 `s[i]`（C++ 中 `s[size()]` 返回 `'\0'` 不崩溃但属于越界语义，Python 的 `s[i]` 直接抛 `IndexError`）。
2. **空串优先**：$\lvert s \rvert = 0$ 时循环一次都不执行，末尾的 `return i == n;` 自然给出 `true`；$\lvert t \rvert = 0$ 而 $\lvert s \rvert > 0$ 时循环同样不执行，返回 `false`。两个边界被同一句 `return i == n;` 覆盖，不需要额外特判。
3. **可选剪枝**：入口处先判 $\lvert s \rvert > \lvert t \rvert$ 就返回 `false`，这是 $O(1)$ 的必要条件（子序列长度不可能超过原串），能让「长 `s` + 短 `t`」的用例立刻返回。
4. **只用下标、不做切片**：C++ 用 `t[j]` / `s[i]`，Python 用逐字符遍历 `for ch in t`。切忌写 `s[i] in t[j:]` 或 `t.find(...)` 之类的子串操作——**子序列不等于子串**，`"ace"` 是 `"abcde"` 的子序列但不是子串，这是本题最常见的概念性错误。
5. **Python 的迭代器一行写法**：`it = iter(t); return all(c in it for c in s)`。对迭代器做 `in` 会**顺序消费**元素直到命中（或耗尽），恰好复现「找到就前进到其后」的贪心语义，等价于双指针（耗尽的迭代器上再做 `in` 恒为 `False`）。可读性一般，面试时建议还是写显式双指针。
6. **进阶：$k \ge 10^9$ 次查询的预处理**。把所有查询的 `t` 固定，预处理「下一个出现位置」表：

   ![nxt 表：把每次查询压到 O(|s|)](images/wc3_q1_next_occurrence_table.svg)

   设 $m = \lvert t \rvert$，`nxt[i][c]` 表示「下标 $\ge i$ 的第一个字符 $c$ 的位置」，不存在记为 $m$（哨兵）。从后往前递推：

   $$\text{nxt}[i][c] = \begin{cases} i, & t[i] = c \\ \text{nxt}[i+1][c], & t[i] \ne c \end{cases}, \qquad \text{nxt}[m][c] = m$$

   查询时 `p = 0`，对 `s` 的每个字符 `c` 令 `p = nxt[p][c]`；若 `p == m` 则该字符在剩余后缀中不存在，返回 `false`；否则 `p = p + 1` 继续。预处理 $O(26m)$ 时间与空间，单次查询 $O(\lvert s \rvert)$。

   ```python
   # 预处理（t 固定，只做一次）
   m = len(t)
   nxt = [[m] * 26 for _ in range(m + 1)]
   for i in range(m - 1, -1, -1):
       nxt[i] = nxt[i + 1][:]
       nxt[i][ord(t[i]) - ord('a')] = i

   # 单次查询
   def query(s: str) -> bool:
       p = 0
       for c in s:
           idx = nxt[p][ord(c) - ord('a')]
           if idx == m:
               return False
           p = idx + 1
       return True
   ```

7. **进阶的省空间变体**：不建二维表，只记录每个字母出现的**位置列表**，查询时用二分找「第一个 $\ge p$ 的位置」：`pos = bisect_left(where[c], p)`，若 `pos` 越界则 `false`，否则 `p = where[c][pos] + 1`。空间 $O(m)$，单次查询 $O(\lvert s \rvert \log m)$，适合 $t$ 很长而查询字符集很稀疏的场景。
8. **常数优化**：把 $\lvert s \rvert$、$\lvert t \rvert$ 预先存进局部变量（`int n = s.size(), m = t.size();`），避免在循环条件里反复调用 `size()`；Python 用 `for ch in t` 逐字符迭代，比 `for j in range(m): t[j]` 少一层下标开销。本题数据极小，但这些习惯在进阶版（$\lvert t \rvert$ 大、查询多）下会直接体现到运行时间上。

## 5. 正确性证明

**引理 1（最早结束位置最优）**：对 $k = 0,1,\dots,\lvert s\rvert$，定义

$$p_0 = -1, \qquad p_{k+1} = \min\{\, j > p_k \mid t[j] = s[k] \,\}$$

（若集合为空则记 $p_{k+1} = +\infty$）。则 $p_k$ 是「`s` 的前 $k$ 个字符能嵌入 `t`」的最小结束下标，且任何合法的嵌入方案中，`s` 前 $k$ 个字符的最后一个匹配位置都 $\ge p_k$。

**证明**：对 $k$ 归纳。$k = 0$ 时 `s` 前缀为空，不占用任何位置，$p_0 = -1$ 成立。

设结论对 $k$ 成立。考虑 `s` 前 $k+1$ 个字符的任一合法嵌入，设它把 `s[k]` 放在下标 $j$，则前 $k$ 个字符嵌入在 `t[0..j)` 中，其结束位置 $j'$ 满足 $p_k \le j' < j$（归纳假设给出下界），故 $j > p_k$ 且 $t[j] = s[k]$，于是 $j$ 属于引理中 $p_{k+1}$ 的定义集合，$j \ge p_{k+1}$。又由构造，把前 $k$ 个字符按 $p_0,\dots,p_{k-1}$、第 $k+1$ 个放在 $p_{k+1}$ 本身就是合法嵌入，故 $p_{k+1}$ 可达且最小。∎

**引理 2（指针含义）**：算法扫描完 `t` 的前 `j` 个字符（即下一个待看字符为 `t[j]`）时，`i` 恰等于 $\max\{\, k \mid p_k < j \,\}$，即「`s` 中最长的、已能嵌入 `t[0..j)` 的前缀长度」。

**证明**：对 `j` 归纳。$j = 0$ 时 $p_0 = -1 < 0$、$p_1 \ge 0$，故 $\max\{k \mid p_k < 0\} = 0 = i$。

设 `j` 时结论成立，即 $i = \max\{k \mid p_k < j\}$。处理 `t[j]` 后 `j' = j+1`：

- 若 `t[j] != s[i]`，则 $p_{i+1} \ne j$（$p_{i+1}$ 必须是等于 $s[i]$ 的下标），由定义 $p_{i+1} > j$，即 $p_{i+1} \ge j+1$，所以 $\max\{k \mid p_k < j+1\} = i$，`i` 不变，结论成立。
- 若 `t[j] == s[i]`，则由 $i = \max\{k \mid p_k < j\}$ 知 $p_{i+1} \ge j$，又 $t[j] = s[i]$ 且 $j > p_i$，故 $p_{i+1} = j < j+1$；而 $p_{i+2} > p_{i+1} = j$ 即 $p_{i+2} \ge j+1$。于是 $\max\{k \mid p_k < j+1\} = i+1$，算法同样把 `i` 加一，结论成立。∎

**定理**：算法返回 `true` 当且仅当 `s` 是 `t` 的子序列。

**证明**：

- （$\Leftarrow$）设 `s` 是 `t` 的子序列，则由引理 1，$p_{\lvert s\rvert}$ 有限且 $p_{\lvert s \rvert} \le \lvert t\rvert - 1$。取 $j = p_{\lvert s\rvert} + 1 \le \lvert t \rvert$。由引理 2，扫描到此处时 $i = \max\{k \mid p_k < j\} \ge \lvert s \rvert$；而 $i$ 至多加到 $\lvert s \rvert$，故 $i = \lvert s \rvert$，算法在 `j` 到达 $\lvert t \rvert$ 之前就已返回 `true`。
- （$\Rightarrow$）若算法返回 `true`，说明某时刻 $i = \lvert s \rvert$ 且此时 $j \le \lvert t \rvert$。由引理 2，$p_{\lvert s\rvert} < j \le \lvert t \rvert$，即存在严格递增的下标序列把 `s` 的每个字符依次匹配到 `t` 中，`s` 是 `t` 的子序列。∎

**推论（进阶版正确性）**：`nxt` 表查询中，`p` 始终等于引理 1 中的 $p_k + 1$（`k` 为已匹配字符数），由引理 1 的递推式即得；`p == m` 等价于 $p_k = +\infty$，即该字符无法在剩余后缀中匹配。故查询结果与双指针一致。∎

## 6. 复杂度分析

- **时间**：$O(\lvert s \rvert + \lvert t \rvert)$。`j` 单调递增、最多前进 $\lvert t \rvert$ 次；`i` 单调递增、最多前进 $\lvert s \rvert$ 次；循环体每次 $O(1)$。实际运行中一旦 `i` 到达 $\lvert s \rvert$ 就提前退出，最坏情况（返回 `false`）才扫满整个 `t`。
- **空间**：$O(1)$。只有两个下标变量，与输入规模无关（不复制字符串、不做切片）。
- **进阶版**：预处理 $O(26\lvert t\rvert)$ 时间、$O(26\lvert t\rvert)$ 空间（本题 $\lvert t \rvert = 10^4$ 时约 $2.6 \times 10^5$ 个整数）；每次查询 $O(\lvert s \rvert)$，$k$ 次查询总计 $O(26\lvert t\rvert + \sum \lvert s_i \rvert)$。若改成「位置列表 + 二分」，则空间降到 $O(\lvert t \rvert)$、单次查询 $O(\lvert s\rvert \log \lvert t \rvert)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isSubsequence(string s, string t) {
        int n = (int)s.size(), m = (int)t.size();
        if (n > m) return false;              // 长度必要条件，O(1) 剪枝
        int i = 0;
        for (int j = 0; j < m && i < n; ++j) {
            if (t[j] == s[i]) ++i;            // 命中即推进 s 的指针
        }
        return i == n;                        // s 全部匹配完才是子序列
    }
};
```

### Python

```python
class Solution:
    def isSubsequence(self, s: str, t: str) -> bool:
        if len(s) > len(t):                   # 长度必要条件，O(1) 剪枝
            return False
        i, n = 0, len(s)
        for ch in t:                          # j 在 t 上顺序扫描
            if i < n and ch == s[i]:
                i += 1                        # 命中即推进 s 的指针
                if i == n:
                    break                     # s 已匹配完，提前退出
        return i == n
```

## 8. 边界情况与易错点

1. **`s` 为空**：空串是任何串的子序列，应返回 `true`。上面的循环不执行，`i == 0 == len(s)` 自然成立；不要写 `if not s: return False` 之类的反向特判。
2. **`t` 为空而 `s` 非空**：返回 `false`。长度剪枝 `len(s) > len(t)` 会先拦住；即便没有剪枝，循环不执行、`i = 0 != len(s)` 也正确。
3. **`s == t`**：逐个字符命中，返回 `true`；`s` 恰为 `t` 的子序列且用满全部位置，不要误以为需要「真子序列」。
4. **重复字符**：`s = "aaa", t = "aa"` → `false`（数量不够）；`s = "aab", t = "aaab"` → `true`。贪心「见一个吃一个」在重复字符下依然正确，因为吃掉的越早、剩余越多。
5. **子序列 ≠ 子串**：`s = "ace", t = "abcde"` 应返回 `true`。误用 `t.find(s)`、`s in t` 会得到 `false`，这是本题最高频的 WA 原因。
6. **循环里访问 `s[i]` 越界**：循环条件只写 `j < m` 时，`s` 匹配完后继续访问 `s[i]`；Python 直接抛 `IndexError`，C++ 读到 `'\0'` 后结果可能侥幸正确但属于未定义行为。务必同时判 `i < n`。
7. **返回条件写错**：应返回 `i == n`（是否匹配满），而不是「是否匹配过任何字符」或「`i >= n - 1`」；差一位在 `s` 长度 1 时就会暴露。
8. **进阶版哨兵**：`nxt` 表用 $m$（而不是 $-1$ 或 $m-1$）作「不存在」标记，配合 `p = idx + 1` 可以无分支地处理末尾；若误用 `m-1`，会把「恰好在最后一个位置匹配」误判为失败。
9. **进阶版忘记右移**：命中后必须是 `p = idx + 1` 而不是 `p = idx`，否则同一个 `t` 位置会被重复使用，`s = "aa", t = "a"` 之类的用例会误判为 `true`。

**延伸思考**：

1. **计数版**：若要求 `s` 在 `t` 中的嵌入方案数，双指针的「唯一路径」假设被打破，需要 $O(\lvert s\rvert \lvert t\rvert)$ 的 DP（115 题），或用生成函数/组合数在 `t` 的游程上加速。
2. **带通配符版**：若 `s` 中含 `?`（可匹配任意单字符）或 `*`（可匹配任意串），问题退化为正则匹配（44 题），贪心不再成立，`*` 的处理需要回溯或 DP。
3. **在线加字符版**：若 `t` 会不断在**末尾**追加字符，维护 `nxt` 表的均摊代价是 $O(26)$ 每次追加（只需把新字符的位置回填到所有「此前该字符不存在」的前缀行上，用并查集/单调栈可以把均摊压到近似 $O(1)$）。
4. **多模式版**：$k$ 个查询串总长为 $L$ 时，把查询串建成 Trie 并在 `t` 上跑「子序列自动机上的 DFS」，可以做到 $O(26\lvert t\rvert + L)$ 级别，这正是 792 题的高阶解法。
