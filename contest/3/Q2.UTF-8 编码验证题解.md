# LeetCode UTF-8 编码验证 题解

## 1. 题目概述

- **标题 / 题号**：UTF-8 编码验证（#393，medium）
- **链接**：https://leetcode.cn/problems/utf-8-validation/
- **来源**：LeetCode 第 3 场周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、状态机

**题意**：`data` 中每个整数只有最低 8 位有意义，代表**一个字节**；把它们按顺序拼成字节流，判断该字节流能否**恰好**划分成若干合法 UTF-8 字符。合法字符只有四种形态：1 字节字符为 `0xxxxxxx`；$n$ 字节字符（$n \in \{2,3,4\}$）的首字节是「$n$ 个 `1` 紧跟一个 `0`」再加 $8-n-1$ 个数据位，其后必须紧跟 $n-1$ 个 `10xxxxxx` 续字节。整段必须划分完，不允许剩下任何字节。

**约束**：

- $1 \le \text{data.length} \le 2 \times 10^4$
- $0 \le \text{data}[i] \le 255$（每个整数只贡献最低 8 位）
- 只需校验**位模式**，无需校验 overlong、代理区、码点上限等真实 UTF-8 的额外约束

## 2. 示例

**示例 1**

```text
输入：data = [197, 130, 1]
输出：true
解释：字节序列 11000101 10000010 00000001
      197 = 11000101 → 2 字节首字节（need = 1）
      130 = 10000010 → 续字节 10xxxxxx，合法，第一个字符结束
      1   = 00000001 → 1 字节字符
      恰好划分成 [197,130] + [1]，返回 true
```

**示例 2**

```text
输入：data = [235, 140, 4]
输出：false
解释：235 = 11101011 → 3 字节首字节（need = 2）
      140 = 10001100 → 续字节合法
      4   = 00000100 → 不以 10 开头，不是续字节，而字符还差一个续字节
      返回 false
```

**示例 3（补充，非官方）**

```text
输入：data = [240, 162, 138, 147]
输出：true
解释：240 = 11110000 → 4 字节首字节（need = 3）
      162/138/147 = 10100010/10001010/10010011，三个续字节全部合法
      4 字节字符正好在数组末尾收尾，返回 true
```

## 3. 解题思路

### 3.1 暴力思路

从位置 $i$ 出发，枚举「当前字符可能是 1/2/3/4 字节」四种情况，分别校验首字节与后续续字节，再递归处理下一个位置：这是 $O(4^{n})$ 量级的回溯。

它慢得毫无必要，因为 UTF-8 是**前缀码**：四种首字节模式互斥，一个字节最多只能声明一种长度，所以「该切成几段」从来不是选择题，长度由字节自己写死在最高位里。回溯只是在反复验证同一个唯一答案。

另一类常见错解更隐蔽：只检查「每个字节本身是否属于某类合法字节」，却不检查**续字节的个数是否与首字节声明的一致**。此时 `[197]`（声明 2 字节却只有 1 个）、`[235,140]`（声明 3 字节却只有 2 个）、`[128]`（孤立续字节）都会被误判为 `true`。

### 3.2 核心观察：首字节自带长度信息

![UTF-8 四种字节模式与首字节裁决](images/wc3_q2_utf8_pattern.svg)

把题面的四种形态翻译成掩码判定（`b` 为字节的最低 8 位）：

| 首字节模式 | 掩码判定 | 字符总长 | 还需续字节 `need` |
|---|---|---|---|
| `0xxxxxxx` | `b >> 7 == 0` | 1 | 0 |
| `110xxxxx` | `b >> 5 == 0b110` | 2 | 1 |
| `1110xxxx` | `b >> 4 == 0b1110` | 3 | 2 |
| `11110xxx` | `b >> 3 == 0b11110` | 4 | 3 |

四个条件**互斥**：右移位数分别取 5/4/3，正好只保留模式所需的 2/3/4 个高位，`110`、`1110`、`11110` 互相不可能相等，`0xxxxxxx` 更与它们不重叠。于是每个字节对应的 `need` **唯一确定**，整段字节流的切分方式也唯一确定。

续字节的判定同样是一行掩码：`10xxxxxx` 等价于 `b >> 6 == 0b10`，也就是 $b \in [\text{0x80}, \text{0xBF}]$。

> 💡 一句话：**不需要搜索结构，只需要一个「还剩几个续字节」的计数器**，从左到右一次扫描即可。

### 3.3 算法流程

![线性扫描流程图](images/wc3_q2_scan_flow.svg)

1. 令 `i = 0`（`i` 始终指向下一个待解析字符的首字节）。
2. 若 `i == n`，说明全部字节都已划分完毕，返回 `true`。
3. 取 `b = data[i] & 0xFF`，按 §3.2 的掩码表求出 `need`；一个都不匹配（`10xxxxxx` 孤立续字节、`11111xxx`）则返回 `false`。
4. 若 `i + need >= n`，说明声明的续字节数超出数组长度，返回 `false`。
5. 依次检查 `j = 1..need` 的 `data[i+j]`：只要有一个不满足 `(b >> 6) == 0b10` 就返回 `false`。
6. 令 `i += need + 1`，跳过整个字符，回到第 2 步。

### 3.4 示例演算

![三组示例的逐字节走查](images/wc3_q2_walkthrough.svg)

对 `data = [235, 140, 4]` 的逐步状态（`i` 为当前首字节下标，`need` 为本字符还缺的续字节数）：

| 步骤 | `i` | `b` | 二进制 | 判定 | `need` | 动作 |
|---|---|---|---|---|---|---|
| 1 | 0 | 235 | `11101011` | `b>>4 == 0b1110` | 2 | 检查后 2 个字节 |
| 2 | 1 | 140 | `10001100` | `b>>6 == 0b10` ✓ | 1 | 继续检查 |
| 3 | 2 | 4 | `00000100` | `b>>6 == 0b00` ✗ | — | 返回 `false` |

对照 `[197, 130, 1]`：第 1 步 `need = 1`，第 2 步续字节通过后 `i` 跳到 2；第 3 步 `b = 1` 是 `0xxxxxxx`，`need = 0`，`i` 跳到 3 结束，返回 `true`。

## 4. 算法细节

1. **判定顺序与互斥性**：先判 `b >> 7 == 0`，再用 `b >> 5`、`b >> 4`、`b >> 3`。右移位数必须与模式长度匹配：只取高两位（`b >> 6`）的话，`110xxxxx` 与 `10xxxxxx` 都得到 2、`1110xxxx` 与 `11110xxx` 都得到 3，长度信息就被压掉了。
2. **越界检查写成 `i + need >= n`**：`need` 个续字节的合法下标范围是 $[i+1, i+need]$，要求 $i + need \le n-1$。若误写成 `i + need > n`，`i + need == n` 的「还差一个字节」会被放过并越界读取；写成 `i + need > n - 1` 虽然等价，但符号更容易写错。
3. **先判长度再访问**：必须先确认 `i + need < n`，再去读 `data[i+j]`，否则 `[197]` 这类输入会直接越界（C++ 是未定义行为，Python 会抛 `IndexError`）。
4. **`& 0xFF` 的作用**：题面保证 `data[i] <= 255`，所以它不改变结果；但含义上强调「只取最低 8 位」，即使混入更大的脏数据也不会误判。续字节检查里同样要 `& 0xFF`。
5. **非法首字节集合**：`0x80`–`0xBF`（孤立的续字节）与 `0xF8`–`0xFF`（5/6 字节首字节、全 1）不在任何模式内，必须直接 `false`；注意 `0xC0`、`0xC1` 仍然属于 `110xxxxx`，按题目规则是**合法首字节**（尽管它们只能编码 overlong 形式）。
6. **用 `need` 而不是递减计数器**：另一种写法是维护 `pending`（还需消费几个续字节），读到续字节就 `pending--`。两版等价，但 `need` 版本把「一个字符」当成整体处理，失败时能一次性定位，代码也更短。
7. **只校验模式，不做语义校验**：`[193,191]`（`11000001 10111111`，overlong 编码 `U+007F`）、`[237,160,128]`（代理区 `U+D800`）、`[244,144,128,128]`（超出 `U+10FFFF`）在本题都返回 `true`，而真实解码器会拒绝。写题解/代码时不要「顺手加严」，否则会和官方答案不一致。
8. **不构造新数组**：一次下标扫描即可，不需要切片或 `vector` 拷贝，常数更小。

## 5. 正确性证明

**引理 1（首字节判定正确且唯一）**：对任意 $b \in [0, 255]$，算法给出的 `need` 等于「$b$ 作为首字节时可声明的字符长度减一」，且至多有一个长度合法；若算法走到兜底分支，则 $b$ 不能作为任何合法字符的首字节。

**证明**：按区间分情况。$b \in [\text{0x00},\text{0x7F}]$ 时最高位为 0，恰为 `0xxxxxxx`，$b \gg 7 = 0$；$b \in [\text{0xC0},\text{0xDF}]$ 时高 3 位为 `110`，$b \gg 5 = 6$；$b \in [\text{0xE0},\text{0xEF}]$ 时高 4 位为 `1110`，$b \gg 4 = 14$；$b \in [\text{0xF0},\text{0xF7}]$ 时高 5 位为 `11110`，$b \gg 3 = 30$。四个区间的右移值 $0, 6, 14, 30$ 互不相同，故命中唯一，且与题面的四种形态一一对应。剩下的 $[\text{0x80},\text{0xBF}]$ 高两位为 `10`（续字节，不能当首字节），$[\text{0xF8},\text{0xFF}]$ 高五位 $\geq 31$，二者都被兜底分支拒绝，符合题面「长度只能是 1~4 字节」。∎

**引理 2（续字节判定正确）**：对任意字节 $b$，$b \gg 6 = \text{0b10} \iff b \in [\text{0x80},\text{0xBF}] \iff b$ 的高两位是 `10`。

**证明**：$b \gg 6$ 取的是最高的 2 位，其值等于 2 即二进制 `10`；而高两位为 `10` 的 8 位整数正是 $128 \sim 191$，即 $[\text{0x80},\text{0xBF}]$。∎

**引理 3（循环不变量）**：每次进入循环第 2 步时，`data[0..i)` 已被划分成 $k$ 个合法字符（每个都满足引理 1 的首字节模式与引理 2 的续字节条件），且 `i` 恰为第 $k+1$ 个字符的首字节下标。

**证明**：对循环轮数归纳。初始 $i=0$，前缀为空，成立。设某轮开始时成立：若算法在第 3 步返回，则按引理 1，`data[i]` 不能作为任何合法字符的首字节，不存在以 `i` 为起点的新字符；若在第 4、5 步返回，说明首字节声明了 `need` 个续字节但数组剩余不足或其中某个高两位不是 `10`，同样无法构成一个合法字符，循环不变量在失败前的状态仍成立。若全部检查通过，则由引理 1、2，`data[i..i+need]` 恰好是一个合法字符，`i' = i + need + 1` 是下一个字符的首字节下标，不变量保持。∎

**定理**：`validUtf8(data)` 返回 `true` 当且仅当 `data` 能被恰好划分为若干合法 UTF-8 字符。

**证明**：

- （$\Leftarrow$）设存在一种合法划分。由引理 1，该划分的第一个字符长度只能是 `need + 1`（唯一），所以算法第 3 步求出的 `need` 与它一致；该划分的续字节都满足题面条件，由引理 2 算法第 5 步必然通过；第 4 步也不会失败，因为划分本身证明了这些字节存在。于是算法消费掉与真实划分相同的长度，`i` 前移相同。对剩余部分重复该论证，每轮 `i` 严格增大，最终 `i = n`，返回 `true`。
- （$\Rightarrow$）设算法返回 `true`。按引理 3，终止时 `data[0..n)` 被划分成若干段，每段的首字节匹配四种模式之一、其余字节高两位为 `10`，正是题面定义的合法字符；且 `i = n` 说明没有剩余字节，划分是「恰好」的，故 `data` 是合法 UTF-8 编码。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层每轮 `i` 至少前进 1（`need >= 0`），总轮数不超过 $n$；内层检查的续字节互不重叠，累计不超过 $n-1$ 次。每次判定都是常数次移位与比较，故总时间与字节数成正比，$n = 2\times10^4$ 时远低于时限。
- **空间**：$O(1)$ 额外空间。只用了 `i`、`need`、`b` 等常数个变量，不复制数组、不递归（递归写法会有 $O(n)$ 栈深度，迭代版没有这个隐患）。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool validUtf8(vector<int>& data) {
        int n = (int)data.size(), i = 0;
        while (i < n) {
            int b = data[i] & 0xFF;                 // 只用最低 8 位
            int need;
            if ((b >> 7) == 0)         need = 0;    // 0xxxxxxx
            else if ((b >> 5) == 0x6)  need = 1;    // 110xxxxx
            else if ((b >> 4) == 0xE)  need = 2;    // 1110xxxx
            else if ((b >> 3) == 0x1E) need = 3;    // 11110xxx
            else return false;                      // 10xxxxxx / 11111xxx

            if (i + need >= n) return false;        // 续字节不够，截断
            for (int j = 1; j <= need; ++j)
                if (((data[i + j] & 0xFF) >> 6) != 0x2)
                    return false;                   // 不是 10xxxxxx
            i += need + 1;                          // 跳过整个字符
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def validUtf8(self, data: list[int]) -> bool:
        i, n = 0, len(data)
        while i < n:
            b = data[i] & 0xFF                  # 只用最低 8 位
            if b >> 7 == 0:                     # 0xxxxxxx
                need = 0
            elif b >> 5 == 0b110:               # 110xxxxx
                need = 1
            elif b >> 4 == 0b1110:              # 1110xxxx
                need = 2
            elif b >> 3 == 0b11110:             # 11110xxx
                need = 3
            else:                               # 10xxxxxx / 11111xxx
                return False

            if i + need >= n:                   # 续字节不够，截断
                return False
            for j in range(1, need + 1):
                if (data[i + j] & 0xFF) >> 6 != 0b10:
                    return False                # 不是 10xxxxxx
            i += need + 1                       # 跳过整个字符
        return True
```

## 8. 边界情况与易错点

1. **孤立续字节**：`[128]`、`[130, 1]` 以 `10xxxxxx` 开头，任何划分都不合法 → `false`。这是最容易漏的分支，因为它在掩码表里「看起来像字节」。
2. **截断的字符**：`[197]`、`[235, 140]`、`[240, 162, 138]` 声明的续字节数超出数组 → `false`。必须用 `i + need >= n` 在读取前拦住，否则越界。
3. **恰好收尾**：`[240, 162, 138, 147]` 中最后一个续字节的下标是 $n-1$，`i + need == n - 1` **合法**。把条件写成 `>= n - 1` 就会把这类正确答案误杀。
4. **`0xF8`–`0xFF`**：`[255]`、`[254, 1]` 的高 5 位是 `11111`，不在 1~4 字节模式内 → `false`；注意不要把它们当成「4 字节首字节 + 续字节」。
5. **`0xC0`/`0xC1` 不是非法字节**：`[192, 128]`（overlong 编码 `U+0000`）按本题规则返回 `true`；同理 `[193, 191]`、代理区的 `[237, 160, 128]`、超范围的 `[244, 144, 128, 128]` 也都是 `true`。加严校验会 WA。
6. **不能跳过坏字节继续往后扫**：题目要求「恰好划分」，一旦某个字符不成立必须立刻返回 `false`，不存在「修复」或「跳过」的余地。
7. **空数组与单字节**：约束保证 $n \ge 1$；`[0]`、`[127]` 是合法 1 字节字符，`while` 循环自然返回 `true`，无需特判。
8. **运算符优先级**：Python 里 `b >> 5 == 0b110` 按 `(b >> 5) == 0b110` 解析（移位优先级高于比较），C++ 同理；但为了可读性与避免笔误，建议照上面代码那样加括号。
