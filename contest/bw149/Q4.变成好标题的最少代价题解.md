# LeetCode 变成好标题的最少代价 题解

## 1. 题目概述

- **标题 / 题号**：变成好标题的最少代价（#3441，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-good-caption/
- **来源**：LeetCode 第 149 场双周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划

**题意**：称字符串是**好标题**，当且仅当其中**每一个**字符都属于一个「连续出现至少 3 次」的相同字符组。例如 `"aaabbb"`（3+3）与 `"aaaaccc"`（4+3）是好标题，`"aabbb"`（2+3）与 `"ccccd"`（4+1）不是。

一次操作可以把某个字符改成字母表中**前一个**或**后一个**字母（`'a'` 不能减、`'z'` 不能加）。求：

1. 把 `caption` 变成好标题所需的**最少操作次数**；
2. 在达到最少次数的所有结果中，返回**字典序最小**的那个；
3. 若无法变成好标题，返回 `""`。

**约束**：

- $1 \le |\text{caption}| \le 5 \times 10^4$
- `caption` 只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：caption = "cdcd"
输出："cccc"
解释：至少需要 2 次操作。"dddd"（改第 0、2 位）与 "cccc"（改第 1、3 位）都是 2 次，
      取字典序更小的 "cccc"。
```

**示例 2**

```text
输入：caption = "aca"
输出："aaa"
解释：把中间的 'c' 减两次变成 'a'，得到 "aaa"，共 2 次操作。
```

**示例 3**

```text
输入：caption = "bc"
输出：""
解释：长度小于 3，任何分组都无法让每个组至少 3 个字符，无解。
```

## 3. 解题思路

### 3.1 暴力思路

好标题的结构是「切成若干段、每段长度 $\ge 3$、段内字符相同」。于是最直接的想法是：

- 枚举所有「每段长度 $\ge 3$」的切分方案（斐波那契级别，$n = 5\times10^4$ 时天文数字）；
- 或直接枚举所有长度为 $n$ 的字符串（$26^n$）。

两种都不可行。注意到一个关键性质：**代价是可加的**，且**每段的字符可以独立决定**（取该段字符的中位数最省）。这就提示用 DP，把"这一段的字符是什么、这一段已经有多长"作为状态。

### 3.2 核心观察：状态只需「当前段字符 + 段长封顶 3」

![状态机：段长 1 → 2 → 3，只有段长达到 3 才允许换字符](images/bw149_q4_dp_states.svg)

两个关键观察：

1. **段长只需区分 1、2、≥3**。填到某个位置时，未来是否合法只取决于"当前段还能不能换字符"：段长 1、2 时**必须**继续填同一字符，否则这个段永远凑不满 3 个；段长 $\ge 3$ 时既可以选择继续延长，也可以选择换成任意别的字符开新段。更长的段长（4、5、……）与 3 在决策能力上完全等价，所以封顶为 3，状态数从 $O(n)$ 压到 $O(1)$。
2. **换字符的代价只依赖新字符**。把位置 $i$ 的字符改成 $c$ 的代价是 $\lvert \text{caption}[i] - c \rvert$（每步只能 ±1，所以距离就是操作次数），与之前是什么字符无关。因此"从段长 $\ge 3$ 换到 $c'$"的最优值是

$$v[c'] = \text{cost}_i[c'] + f[i+1][c'][1]$$

对所有 $c'$ 求最小值与**次小值**，就能在 $O(1)$ 时间内回答"换成某个与当前字符不同的 $c$ 的最优值"（只需排除取到最小值的那个字符）。

于是定义后缀 DP：

$$f[i][c][t] = \text{把位置 } i \sim n-1 \text{ 填完的最小代价（已知位置 } i \text{ 之前最后一段的字符为 } c \text{、长度为 } t\text{）}$$

其中 $t \in \{1,2,3\}$，$t=3$ 表示长度 $\ge 3$。

### 3.3 算法流程

![转移：续同字符 or 换字符，用最小/次小值把 O(26) 压成 O(1)](images/bw149_q4_transition.svg)

**边界**（$i = n$）：

$$f[n][c][3] = 0, \qquad f[n][c][1] = f[n][c][2] = +\infty$$

含义是：整串填完时最后一段必须已经 $\ge 3$。

**转移**（$i$ 从 $n-1$ 倒推到 $0$）：

$$\begin{aligned}
f[i][c][1] &= \text{cost}_i[c] + f[i+1][c][2] \\
f[i][c][2] &= \text{cost}_i[c] + f[i+1][c][3] \\
f[i][c][3] &= \min\Big(\text{cost}_i[c] + f[i+1][c][3],\ \min_{c' \ne c} v[c']\Big)
\end{aligned}$$

前两行体现"段长不足 3 只能继续放 $c$"；第三行括号内第一项是"继续延长"，第二项是"换字符开新段"。

**起点**（还没有任何段）：

$$\text{OPT} = \min_{c} \Big(\text{cost}_0[c] + f[1][c][1]\Big)$$

$\text{OPT} = +\infty$ 时说明 $n < 3$，返回 `""`。

**重建答案**（贪心，从左到右）：在每一步，于所有"保持总代价 = OPT"的字符中取**最小**的字符。具体地：

- 若此前没有任何段：取使 $\text{cost}_i[c] + f[i+1][c][1]$ 最小的 $c$，并列取最小字母；
- 若当前段长 1 或 2：字符被锁死，只能放当前字符；
- 若当前段长 $\ge 3$：比较"继续放当前字符"与"换成其它字符"的总代价，取更小者；**代价相等时取字母更小的那个**（哪怕它需要换字符）。

### 3.4 示例演算

![示例 1 的重建过程：第 0 位 c 与 d 代价并列，取更小的 c](images/bw149_q4_example_walkthrough.svg)

对 `caption = "cdcd"`（字母编号 `c = 2`、`d = 3`）：

- 第 0 位若取 `'c'`：本位代价 0，后面 `"dcd"` 三位必须全填 `c`，后两位 `'d'` 各改 1 次，合计 $0 + 2 = 2$；
- 第 0 位若取 `'d'`：本位代价 1，后面三位全填 `d`，只需把第 2 位 `'c'` 改 1 次，合计 $1 + 1 = 2$；
- 两者并列，取字母更小的 `'c'`；随后段长不足 3，第 1、2 位锁死为 `c`；第 3 位继续 `c`（代价 1），换成别的字符代价更高。

结果 `"cccc"`，总代价 2。对照题面给出的 `"dddd"` 也是 2 次，但字典序更大，因此被淘汰 —— 这正是"并列时取小字母"的意义。

## 4. 算法细节

1. **状态压缩**：C++ 用一个扁平数组 `f[(i*26+c)*4+t]`，只用到 $t = 1,2,3$；Python 用三个列表 `f1[i]`、`f2[i]`、`f3[i]`，每个存 26 个整数的 `array('i')`，把 $5\times10^4 \times 3 \times 26$ 个状态压到约 15 MB。
2. **最小/次小值**：枚举 $c$ 时同时维护 `best1`（最小值）、`arg1`（取到它的字符）、`best2`（次小值）。换字符到 $c$ 的最优值 = `best1`（若 $c \ne \text{arg1}$）否则 `best2`。
3. **"次小"必须来自不同字符**：`best2` 只在 `v[c]` 比 `best1` 大时更新，天然满足"$\text{arg} \ne \text{arg1}$"。
4. **$+\infty$ 的处理**：取 $10^{15}$（C++ 用 `long long`，Python 用 `10**9` 配合 `array('i')`）。累加代价最多 $25n \approx 1.25\times10^6$，远小于 $+\infty$，不会溢出，但判定"不可行"要写 `>= INF` 而不是 `==`。
5. **重建的并列判断**：`best < stay || (best == stay && pick < ch)` —— 前者是代价更小，后者是代价相同时字母更小。漏掉后者会得到代价正确但字典序偏大的答案。
6. **不必存完整方案**：DP 已把每个位置的最优值存下，重建时只需回查 $f[i+1]$ 的三张表。
7. **可行性**：$n \ge 3$ 时总可以整串填成同一个字母，所以只有 $n < 3$ 无解；代码里用 $n < 3$ 直接返回 `""`。

## 5. 正确性证明

**引理 1（状态的充分性）**：判断"从位置 $i$ 起能否把后缀填成合法结尾、最小代价是多少"，只与 $(i,\ c,\ \min(t,3))$ 有关，其中 $c$ 是位置 $i$ 之前最后一段的字符、$t$ 是该段当前长度。

**证明**：合法性的约束只涉及两件事：(a) 每个被"封口"的段长度必须 $\ge 3$；(b) 位置 $i$ 能否改字符，取决于 $i-1$ 所在的段是否已经 $\ge 3$。段长 $\ge 3$ 之后，继续延长或封口都与具体长度无关；段长 $< 3$ 时唯一的出路是继续放 $c$。历史中更早的部分已经封口且合法，不再影响未来。故 $(i, c, \min(t,3))$ 是充分状态。∎

**引理 2（转移完备）**：上述三条转移式枚举了位置 $i$ 的全部合法选择，且每条都取到对应选择下的最小代价。

**证明**：按段长分情况。$t = 1,2$ 时若在 $i$ 放 $c' \ne c$，则位置 $i-1$ 处长度为 $t < 3$ 的段被封口且长度不足 3，非法；故只能放 $c$，代价 $\text{cost}_i[c]$，新状态 $(c, t+1)$。$t = 3$ 时可放 $c$（状态仍为 $(c,3)$）或任意 $c' \ne c$（新段状态 $(c',1)$），前者代价 $\text{cost}_i[c] + f[i+1][c][3]$，后者代价 $\text{cost}_i[c'] + f[i+1][c'][1] = v[c']$，对所有 $c' \ne c$ 取最小即得。由引理 1，状态足够描述未来，故按 $i$ 倒推得到的 $f$ 是精确最小值。∎

**引理 3（贪心重建给出字典序最小）**：设 OPT 为最小总代价。从左到右逐位确定：在第 $i$ 位、已确定前缀代价 $P$ 时，选择"使 $P + \text{cost}_i[c] + f[\text{next}][\cdot][\cdot] = \text{OPT}$ 成立"的最小字符 $c$。则最终得到的串在所有最优解中字典序最小。

**证明**：对位数归纳。设前 $i$ 位已与所有最优解的最长公共前缀一致。若存在某个最优解在第 $i$ 位取字符 $x$，则 $x$ 是"保持最优"的候选，故贪心选的 $c \le x$；若 $c < x$，则贪心解的字典序严格更小；若 $c = x$，则继续归纳下一位。由于 $f$ 精确保存后缀最小代价（引理 2），"$P + \text{cost}_i[c] + f[\text{next}] = \text{OPT}$"这一判据与"存在以该前缀开头的最优解"完全等价，故贪心不会误判。∎

**定理**：算法输出的字符串是所有好标题中操作次数最少、且同代价下字典序最小的那个；若 $n < 3$ 返回 `""` 正确。

**证明**：由引理 1、2，起点值 $\text{OPT}$ 等于最小操作次数；由引理 3，重建串达到 $\text{OPT}$ 且字典序最小。$n < 3$ 时任何分组都无法满足"每组 $\ge 3$"，无解；反过来 $n \ge 3$ 时整串填同一字母即合法，故有解。∎

## 6. 复杂度分析

- **时间**：$O(26n)$。每个位置 $i$ 计算 26 个代价、26 个 $v$、求最小与次小、再填三张表各 26 个值，全部是常数次遍历；重建过程 $O(26n)$（每个位置最多扫 26 个字符）。总计约 $5\times10^4 \times 26 \approx 1.3\times10^6$ 次基本操作级别。
- **空间**：$O(26n)$。C++ 扁平 `long long` 数组约 $5\times10^4\times26\times4\times8 \approx 41$ MB；Python 用 `array('i')` 存三张表约 15 MB，滚动数组可进一步降到 $O(26)$，但重建需要历史值，故保留。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string minCostGoodCaption(string caption) {
        int n = (int)caption.size();
        if (n < 3) return "";
        const long long INF = (long long)1e15;

        // f[(i*26+c)*4+k]：从位置 i 起填完的最小代价，
        // 位置 i 所在连续段长度为 k（1/2/3 表示 >=3），字符为 c
        vector<long long> f((size_t)(n + 1) * 26 * 4, INF);
        for (int c = 0; c < 26; c++) {
            f[((size_t)n * 26 + c) * 4 + 1] = INF;
            f[((size_t)n * 26 + c) * 4 + 2] = INF;
            f[((size_t)n * 26 + c) * 4 + 3] = 0;
        }

        for (int i = n - 1; i >= 0; i--) {
            long long cost[26];
            for (int c = 0; c < 26; c++) cost[c] = abs(caption[i] - 'a' - c);
            long long best1 = INF, best2 = INF;
            int arg1 = -1;
            for (int c = 0; c < 26; c++) {
                long long v = cost[c] + f[((size_t)(i + 1) * 26 + c) * 4 + 1];
                if (v < best1) {
                    best2 = best1; best1 = v; arg1 = c;
                } else if (v < best2) {
                    best2 = v;
                }
            }
            for (int c = 0; c < 26; c++) {
                long long same = cost[c] + f[((size_t)(i + 1) * 26 + c) * 4 + 3];
                long long other = (c != arg1) ? best1 : best2;
                size_t base = ((size_t)i * 26 + c) * 4;
                f[base + 1] = cost[c] + f[((size_t)(i + 1) * 26 + c) * 4 + 2];
                f[base + 2] = same;
                f[base + 3] = min(same, other);
            }
        }

        string res;
        res.reserve(n);
        int pos = 0, run = 0, ch = -1;
        while (pos < n) {
            long long cost[26];
            for (int c = 0; c < 26; c++) cost[c] = abs(caption[pos] - 'a' - c);
            if (run == 0) {
                long long best = INF; int pick = 0;
                for (int c = 0; c < 26; c++) {
                    long long v = cost[c] + f[((size_t)(pos + 1) * 26 + c) * 4 + 1];
                    if (v < best) { best = v; pick = c; }
                }
                ch = pick; run = 1;
            } else if (run < 3) {
                run++;
            } else {
                long long stay = cost[ch] + f[((size_t)(pos + 1) * 26 + ch) * 4 + 3];
                long long best = INF; int pick = -1;
                for (int c = 0; c < 26; c++) {
                    if (c == ch) continue;
                    long long v = cost[c] + f[((size_t)(pos + 1) * 26 + c) * 4 + 1];
                    if (v < best) { best = v; pick = c; }
                }
                if (best < stay || (best == stay && pick < ch)) { ch = pick; run = 1; }
            }
            res.push_back((char)('a' + ch));
            pos++;
        }
        return res;
    }
};
```

### Python

```python
from array import array


class Solution:
    def minCostGoodCaption(self, caption: str) -> str:
        n = len(caption)
        if n < 3:
            return ""

        INF = 10 ** 9
        base = [ord(ch) - 97 for ch in caption]

        # f1[i][c] / f2[i][c] / f3[i][c]：从位置 i 向后填完的最小代价，
        # 前提是位置 i 处“当前连续段”的长度为 1 / 2 / >=3，且该段字符为 c。
        f1 = [None] * (n + 1)
        f2 = [None] * (n + 1)
        f3 = [None] * (n + 1)
        f1[n] = array('i', [INF]) * 26
        f2[n] = array('i', [INF]) * 26
        f3[n] = array('i', [0]) * 26

        for i in range(n - 1, -1, -1):
            ci = base[i]
            cost = [abs(ci - c) for c in range(26)]
            n1, n2, n3 = f1[i + 1], f2[i + 1], f3[i + 1]
            # 在一个长度 >= 3 的段后面另起新段时，新字符 c' 的候选代价
            v = [cost[c] + n1[c] for c in range(26)]
            best1 = best2 = INF
            arg1 = -1
            for c in range(26):
                if v[c] < best1:
                    best2, best1, arg1 = best1, v[c], c
                elif v[c] < best2:
                    best2 = v[c]
            r1 = array('i', [0]) * 26
            r2 = array('i', [0]) * 26
            r3 = array('i', [0]) * 26
            for c in range(26):
                r1[c] = cost[c] + n2[c]
                r2[c] = cost[c] + n3[c]
                stay = cost[c] + n3[c]
                other = best1 if c != arg1 else best2
                r3[c] = stay if stay < other else other
            f1[i], f2[i], f3[i] = r1, r2, r3

        res = []
        pos, run, ch = 0, 0, -1
        while pos < n:
            cost = [abs(base[pos] - c) for c in range(26)]
            if run == 0:
                best, pick = INF, 0
                for c in range(26):
                    val = cost[c] + f1[pos + 1][c]
                    if val < best:
                        best, pick = val, c
                ch, run = pick, 1
            elif run < 3:
                run += 1
            else:
                stay = cost[ch] + f3[pos + 1][ch]
                best, pick = INF, -1
                for c in range(26):
                    if c == ch:
                        continue
                    val = cost[c] + f1[pos + 1][c]
                    if val < best:
                        best, pick = val, c
                if best < stay or (best == stay and pick < ch):
                    ch, run = pick, 1
            res.append(chr(97 + ch))
            pos += 1
        return ''.join(res)
```

## 8. 边界情况与易错点

1. **$n < 3$ 直接无解**：返回 `""`，不要试图输出原串（长度为 1、2 的串永远不合法）。
2. **$n = 4$、$n = 5$ 仍可解**：整段长度为 4 或 5 是合法的（单段 $\ge 3$），不要误以为"必须恰好 3 个一段"。`"cdcd"` 的答案就是 4 个字符一段。
3. **字典序并列**：代价相同的解很多（示例 1 的 `"cccc"` 与 `"dddd"`），必须在**每一位**都取最小可行字符；只在最后全串比较会很难写，且容易超时。
4. **"换字符"的候选不能包含当前字符**：`best1` 与 `best2` 必须来自不同字符，否则 $t = 3$ 的转移会把"换成自己"重复计算，虽然值相同但会让 `arg1` 判断失效。
5. **$+\infty$ 的传播**：状态 $(c,1)$、$(c,2)$ 在末尾附近是 $+\infty$，转移时不要让它"降级"成有限值（比如漏判 `n` 行的初值）。
6. **`'a'` 与 `'z'` 的边界**：操作只能 ±1 且不能越界，但把 $x$ 改成 $c$ 仍恰好需要 $\lvert x - c \rvert$ 步（字母表是一条直路，中间没有障碍），无需特判。
7. **数组下标**：C++ 中 `(size_t)` 转换要在乘法之前，否则 $5\times10^4 \times 26 \times 4$ 仍在 `int` 范围但混合运算容易踩坑；Python 里 `array('i')` 只能放 32 位整数，`INF = 10**9` 足够。
8. **答案一定存在（$n \ge 3$）**：整串填同一个字母总是合法，所以不要写"无解"分支去猜。

**延伸思考**：若把"每个段至少 3"改成"每个段恰好长度在 $[L, R]$ 之间"，状态里就需要记当前段长（最多 $R$ 种），转移仍是 $O(26)$，总复杂度 $O(26Rn)$；若代价函数不是 $\lvert x-c\rvert$ 而是任意非凸函数，则"最小/次小"技巧失效，必须回到 $O(26^2)$ 的换字符枚举。
