# LeetCode 重新安排会议得到最多空余时间 I 题解

## 1. 题目概述

- **标题 / 题号**：重新安排会议得到最多空余时间 I（#3439，medium）
- **链接**：https://leetcode.cn/problems/reschedule-meetings-for-maximum-free-time-i/
- **来源**：LeetCode 第 149 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、滑动窗口

**题意**：活动区间是 $[0, \text{eventTime}]$，其中安排了 $n$ 个互不重叠、且已按时间升序排列的会议 $[\text{startTime}[i], \text{endTime}[i]]$。你可以**至多移动 $k$ 个会议**（平移、保持时长不变），要求：

1. 会议之间**相对顺序不变**；
2. 任意两会议**互不重叠**，且整体不越出 $[0, \text{eventTime}]$。

最大化移动后**最长的一段连续空余时间**，返回这个长度。

**约束**：

- $1 \le \text{eventTime} \le 10^9$
- $2 \le n \le 10^5$
- $1 \le k \le n$
- $0 \le \text{startTime}[i] < \text{endTime}[i] \le \text{eventTime}$，且 $\text{endTime}[i] \le \text{startTime}[i+1]$

> **注意**：题目要求"移动前后会议相对顺序保持不变"，这一点是本题（以及同场 Q3）的核心分水岭——顺序可变时结论完全不同。

## 2. 示例

**示例 1**

```text
输入：eventTime = 5, k = 1, startTime = [1,3], endTime = [2,5]
输出：2
解释：把 [1,2] 平移到 [2,3]，两个会议变成 [2,3] 与 [3,5]，
      空余只剩 [0,2] 一整段，长度 2。
```

**示例 2**

```text
输入：eventTime = 10, k = 1, startTime = [0,2,9], endTime = [1,4,10]
输出：6
解释：把 [2,4] 左移贴到 [0,1] 之后变成 [1,3]，空余 [3,9] 长度 6。
```

**示例 3**

```text
输入：eventTime = 5, k = 2, startTime = [0,1,2,3,4], endTime = [1,2,3,4,5]
输出：0
解释：会议总长正好等于 eventTime，无论怎么摆都没有空余。
```

## 3. 解题思路

### 3.1 暴力思路

会议位置是连续的实数/整数坐标，直接枚举"移动到哪"的状态空间是 $O(\text{eventTime}^n)$，完全不可行。即便只看"移走哪些会议"（$\sum_{i\le k}\binom{n}{i}$ 种），每种还要决定怎么摆放，仍然是组合爆炸。

真正的可行做法是先转换视角：**空余时间只看"空档"**。

### 3.2 核心观察：空档序列 + "移走 k 个会议 = 合并 k+1 个空档"

![把时间轴切成 n+1 段空档，移走中间会议就是把相邻空档拼起来](images/bw149_q2_gap_model.svg)

定义 $n+1$ 段**空档**：

$$g_0 = \text{startTime}[0], \quad g_i = \text{startTime}[i] - \text{endTime}[i-1]\ (1 \le i \le n-1), \quad g_n = \text{eventTime} - \text{endTime}[n-1]$$

显然 $\sum g_i$ 是活动的总空余时间，且**这个总和与怎么移动无关**（会议总长固定）。

现在考虑"移走一个会议"的几何效果：会议 $i$ 夹在 $g_i$ 与 $g_{i+1}$ 之间，把它挪走后，这两段空档连同它自身占的长度就连成了一整段。于是：

> 💡 **核心结论**：移走 $k$ 个会议，等价于把这 $k$ 个会议两侧的 $k+1$ 段**相邻**空档拼成一整段，得到的连续空余恰好是这 $k+1$ 段空档之和。

因此答案就是

$$\max_{0 \le i \le n-k} \sum_{j=i}^{i+k} g_j$$

即空档数组上长度为 $k+1$ 的**滑动窗口最大和**。

### 3.3 算法流程

![合并窗口内 k 个会议贴边摆放，空余正好是窗口内空档之和](images/bw149_q2_window_merge.svg)

先说明"挪到窗口外"并不必要（下图第二段）：窗口的左右边界由窗口外的会议（或活动边界）卡死，窗口内 $k$ 个会议总长 $S$ 固定，把这 $k$ 个会议**贴着窗口一侧排紧**，窗口跨度减去 $S$ 剩下的连续空余正好等于窗口内空档之和。因此窗口内空档和是**可达**的。

```text
1. 计算 gap[0..n]（n+1 段）
2. cur = gap[0] + ... + gap[k]        // 第一个长度为 k+1 的窗口
   best = cur
3. for i = k+1 .. n:
       cur += gap[i] - gap[i-k-1]      // 窗口右移一位
       best = max(best, cur)
4. 返回 best
```

### 3.4 示例演算

![示例 2：空档 [0,1,5,0]，窗口长 2，取 [1,2] 得 6](images/bw149_q2_example_walkthrough.svg)

对示例 2（`eventTime = 10`，会议 `[0,1]、[2,4]、[9,10]`）：

- $g_0 = 0$，$g_1 = 2-1 = 1$，$g_2 = 9-4 = 5$，$g_3 = 10-10 = 0$
- 窗口长度 $k+1 = 2$：$g_0+g_1 = 1$，$g_1+g_2 = 6$，$g_2+g_3 = 5$

最大为 6：把 `[2,4]` 贴到 `[0,1]` 后面变成 `[1,3]`，空余 `[3,9]` 长 6，与题面解释一致。

| 窗口 | 空档和 | 是否最优 |
|------|--------|----------|
| $[g_0, g_1]$ | 1 | — |
| $[g_1, g_2]$ | **6** | 最优 |
| $[g_2, g_3]$ | 5 | — |

示例 1 的空档是 $[1,1,0]$，$k=1$ 时窗口和最大为 2；示例 3 的空档全为 0，答案为 0。

## 4. 算法细节

1. **空档数组长度是 $n+1$**：两端的"半开空档" $g_0$（从 0 到第一个会议开始）与 $g_n$（最后一个会议结束到 eventTime）必须保留，它们让窗口在边界处同样成立（示例 1 的答案 2 正是 $g_0+g_1$）。
2. **窗口长度 $k+1$**：窗口内恰好包含 $k$ 个会议，移走它们不会破坏窗口外的相对顺序。
3. **$k = n$ 的极端情况**：窗口长度 $n+1$ 覆盖全部空档，答案就是总空余 $\text{eventTime} - \sum(\text{endTime}-\text{startTime})$，代码里用 `min(k, n)` 做初始窗口长度即可。
4. **"至多"与"恰好"等价**：所有 $g_i \ge 0$，把窗口从 $k'+1$ 扩大到 $k+1$（$k' < k$）只会让和不减，所以按恰好 $k+1$ 求最大值不会漏掉更优的"少移"方案。
5. **用 `long long`**：$\text{eventTime} \le 10^9$，单段空档可能达到 $10^9$，但求和最多 $10^9$（空档总和不超过 eventTime），`int` 其实也够；C++ 里仍用 `long long` 中间量更稳妥。
6. **不需要构造方案**：只求长度最大值，不必记录窗口下标与具体摆法。

## 5. 正确性证明

**引理 1（空档分解）**：对任意合法（不重叠、按序）的会议布局，最长连续空余不超过某个"由相邻若干段原始空档拼成"的区间的原始空档之和。

更精确地，设被移动的会议集合为 $S$（$|S| \le k$）。固定 $S$ 后，$S$ 之外的会议**位置不动**，它们把时间轴切成若干**区域**：每两段相邻的"未移动会议"（或活动边界）之间构成一个区域，区域内部只有若干段原始空档与若干 $S$ 中的会议。

**证明**：未移动的会议 $m \notin S$ 的位置与原布局完全一致，且由"相对顺序不变"，任何会议都不能越过一个未移动的会议。因此每个 $S$ 中会议只能落回它原来的那个区域，区域内可自由平移（顺序保持）。于是每个区域内的空余总量固定为"区域跨度 $-$ 区域内会议总长"，而区域跨度与区域内的原始空档和 + 会议长度和相等，故区域内连续空余的上界正是区域内**原始空档之和**；贴着区域边界排紧即可达到。∎

**引理 2（区域规模）**：上述任一区域内恰有 $\lvert S \cap \text{区域} \rvert + 1$ 段空档。

**证明**：区域由若干"会议 + 空档"交替构成，被边界（未移动会议或活动端点）夹住。若区域内含 $t$ 个会议，则这些会议之间、以及它们与两侧边界之间共有 $t+1$ 段空档，而区域内的会议全部属于 $S$，故 $t = \lvert S \cap \text{区域} \rvert$。∎

**定理**：算法输出等于最优布局下的最长连续空余。

**证明**：两方面。

1. **可达性**：对任意 $i \le n-k$，取 $S = \{\text{会议 } i, i+1, \dots, i+k-1\}$（即夹在 $g_i$ 与 $g_{i+k}$ 之间的 $k$ 个会议）。把 $S$ 在区间 $[\text{endTime}[i-1], \text{startTime}[i+k]]$ 内贴着左端依次排紧，它们仍是合法的不重叠会议、顺序不变、且不越界，形成的连续空余长度正是 $g_i + \dots + g_{i+k}$。故答案 $\ge$ 窗口最大和。
2. **上界**：对任意合法布局，设其最长空余所在的区域为 $R$。由引理 1，该空余 $\le$ $R$ 内原始空档之和；由引理 2 与 $\lvert S \rvert \le k$，$R$ 内空档段数 $\le k+1$，且它们是**相邻**的若干段空档。故该空余 $\le$ 某个长度不超过 $k+1$ 的连续窗口和 $\le$ 长度恰为 $k+1$ 的窗口和（因空档非负）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。构造空档数组一遍 $O(n)$；滑动窗口一次遍历 $O(n)$。总时间线性，$n \le 10^5$ 只需毫秒级。
- **空间**：$O(n)$。空档数组 $n+1$ 个元素；若边算边滑可进一步压到 $O(k)$，但没有必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxFreeTime(int eventTime, int k, vector<int>& startTime, vector<int>& endTime) {
        int n = (int)startTime.size();
        vector<long long> gap(n + 1);
        gap[0] = startTime[0];
        for (int i = 1; i < n; i++) gap[i] = (long long)startTime[i] - endTime[i - 1];
        gap[n] = (long long)eventTime - endTime[n - 1];

        long long cur = 0;
        for (int i = 0; i <= k && i <= n; i++) cur += gap[i];
        long long best = cur;
        for (int i = k + 1; i <= n; i++) {
            cur += gap[i] - gap[i - k - 1];
            if (cur > best) best = cur;
        }
        return (int)best;
    }
};
```

### Python

```python
class Solution:
    def maxFreeTime(self, eventTime: int, k: int, startTime: list[int], endTime: list[int]) -> int:
        n = len(startTime)
        gap = [0] * (n + 1)
        gap[0] = startTime[0]
        for i in range(1, n):
            gap[i] = startTime[i] - endTime[i - 1]
        gap[n] = eventTime - endTime[n - 1]
        # 移除 k 个会议，等于把 k+1 段相邻空余时间拼成一段
        cur = sum(gap[:k + 1])
        best = cur
        for i in range(k + 1, n + 1):
            cur += gap[i] - gap[i - k - 1]
            if cur > best:
                best = cur
        return best
```

## 8. 边界情况与易错点

1. **两端空档不能漏**：$g_0$、$g_n$ 常常就是答案的一部分（示例 1 的答案正是 $g_0+g_1$）。只统计"会议之间"的空档会系统性偏小。
2. **窗口长度是 $k+1$ 而不是 $k$**：$k$ 个会议之间夹着 $k+1$ 段空档，这是最容易写错的下标。
3. **"相对顺序不变"必须用上**：如果允许改变顺序，就能把会议挪到更远的空档里，答案可能更大（见同场 Q3）；本题滑窗结论只对"顺序不变"成立。
4. **$k = n$ 时窗口越界**：窗口长度 $n+1$ 时下标到 $n$，循环体 `i = k+1 .. n` 不会执行，初始窗口必须用 `min` 截断。
5. **总空余为 0**（示例 3）：所有 $g_i = 0$，滑窗结果是 0，不要特判成"无解"。
6. **`eventTime` 与 `startTime[0]` 的关系**：允许 $\text{startTime}[0] = 0$（$g_0 = 0$），也允许 $\text{endTime}[n-1] = \text{eventTime}$（$g_n = 0$），都不影响算法。
7. **不要真的去"模拟移动"**：模拟会议位置需要记录坐标，容易在浮点与整数边界上出错；空档和的观点是纯整数运算。
