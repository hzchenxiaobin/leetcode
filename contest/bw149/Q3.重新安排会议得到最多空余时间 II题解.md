# LeetCode 重新安排会议得到最多空余时间 II 题解

## 1. 题目概述

- **标题 / 题号**：重新安排会议得到最多空余时间 II（#3440，medium）
- **链接**：https://leetcode.cn/problems/reschedule-meetings-for-maximum-free-time-ii/
- **来源**：LeetCode 第 149 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、枚举

**题意**：活动区间是 $[0, \text{eventTime}]$，其中有 $n$ 个互不重叠、按时间升序给出的会议 $[\text{startTime}[i], \text{endTime}[i]]$。你可以**至多重新安排一个会议**（平移、时长不变），要求会议不越界且两两不重叠；与 I 版的关键区别是：

> **移动后会议的相对顺序可以任意改变**。

求移动后能得到的**最长连续空余时间**。

**约束**：

- $1 \le \text{eventTime} \le 10^9$
- $2 \le n \le 10^5$
- $0 \le \text{startTime}[i] < \text{endTime}[i] \le \text{eventTime}$，且 $\text{endTime}[i] \le \text{startTime}[i+1]$

## 2. 示例

**示例 1**

```text
输入：eventTime = 5, startTime = [1,3], endTime = [2,5]
输出：2
解释：把 [1,2] 移到 [2,3]，会议变成 [2,3] 与 [3,5]，空余 [0,2] 长度 2。
```

**示例 2**

```text
输入：eventTime = 10, startTime = [0,7,9], endTime = [1,8,10]
输出：7
解释：把 [0,1] 挪到 [8,9]（顺序变了），空余 [0,7] 长度 7。
```

**示例 3**

```text
输入：eventTime = 10, startTime = [0,3,7,9], endTime = [1,4,8,10]
输出：6
解释：把 [3,4] 挪进空档 [8,9]，空余 [1,7] 长度 6。
```

**示例 4**

```text
输入：eventTime = 5, startTime = [0,1,2,3,4], endTime = [1,2,3,4,5]
输出：0
解释：会议恰好铺满整个活动区间，任何摆法都没有空余。
```

## 3. 解题思路

### 3.1 暴力思路

只有一个会议能动，所以"动哪个会议"是 $n$ 种选择；但"把它放到哪"是 $O(\text{eventTime})$ 个位置，逐个尝试还要重新计算最长空余，复杂度 $O(n \cdot \text{eventTime})$，在 $\text{eventTime} \le 10^9$ 时不可行。即使把位置离散化到"某个空档的端点"，也需要一套论证把候选位置压到 $O(n)$，不如直接从"空档"结构出发。

先定义空档（与 I 版相同）：

$$g_0 = \text{startTime}[0], \quad g_i = \text{startTime}[i] - \text{endTime}[i-1], \quad g_n = \text{eventTime} - \text{endTime}[n-1]$$

### 3.2 核心观察：只动一个会议 → 只影响它两侧的空档

![移动会议 i 时，只有 gap[i] + len(i) + gap[i+1] 这一段结构被改写](images/bw149_q3_merge_model.svg)

移动会议 $i$ 后，**其他会议都不动**，因此：

- 会议 $i$ 原来占的位置空出来，它左右两段空档 $g_i$、$g_{i+1}$ 连成一片，跨度是 $g_i + \text{len}(i) + g_{i+1}$；
- 会议 $i$ 必须落到某个位置。如果某个**别的**空档 $g_j$（$j \ne i, i+1$）长度 $\ge \text{len}(i)$，就把它塞进去，合并段可以**完整保留**：

$$\text{候选}_i = g_i + \text{len}(i) + g_{i+1}$$

- 如果所有别的空档都装不下它，只能把它**贴进合并段的一端**，此时它吃掉 $\text{len}(i)$，剩下的连续空余是

$$\text{候选}_i = g_i + g_{i+1}$$

> 💡 **一句话**：能力（只动一个会议）决定了视野（只看它两侧）；顺序可变决定了"塞到别处"这条路必须考虑。

于是答案就是所有 $i$ 的候选值取最大。"别处有没有空档装得下"只需**排除 $i$、$i+1$ 之后的最大空档**，用前缀最大值 + 后缀最大值 $O(1)$ 查询。

### 3.3 算法流程

![算法流程：枚举被动会议 i，用前后缀最大值判断能否“寄存”](images/bw149_q3_algorithm_flow.svg)

```text
1. 计算 gap[0..n] 与 len[i] = endTime[i] - startTime[i]
2. pre[i] = max(gap[0..i])，suf[i] = max(gap[i..n])
3. ans = 0
   for i = 0 .. n-1:
       merged = gap[i] + len[i] + gap[i+1]
       other = max(pre[i-1] (若 i >= 1), suf[i+2] (若 i+2 <= n))   // 0 表示没有别的空档
       cand = merged          若 other >= len[i]
              否则 gap[i] + gap[i+1]
       ans = max(ans, cand)
4. 返回 ans
```

### 3.4 示例演算

![示例 3：逐个会议计算候选值，i = 1 时得到 6](images/bw149_q3_example_walkthrough.svg)

对示例 3（`eventTime = 10`，会议 `[0,1]、[3,4]、[7,8]、[9,10]`）：

- 空档：$g_0=0,\ g_1=2,\ g_2=3,\ g_3=1,\ g_4=0$；会议长度全为 1

| $i$ | $\text{len}(i)$ | $\text{merged}_i$ | 别的空档最大值 | 是否装得下 | 候选值 |
|-----|------|--------|--------|--------|--------|
| 0 | 1 | $0+1+2=3$ | $\max(g_2,g_3,g_4)=3$ | 3 ≥ 1 ✓ | 3 |
| 1 | 1 | $2+1+3=6$ | $\max(g_0,g_3,g_4)=1$ | 1 ≥ 1 ✓ | **6** |
| 2 | 1 | $3+1+1=5$ | $\max(g_0,g_1,g_4)=2$ | 2 ≥ 1 ✓ | 5 |
| 3 | 1 | $1+1+0=2$ | $\max(g_0,g_1,g_2)=3$ | 3 ≥ 1 ✓ | 2 |

最优操作是把 `[3,4]` 塞进空档 $g_3 = [8,9]$，空出 `[1,7]` 长度 6，与题面解释一致。

示例 1 走的则是"装不下"分支：空档 $[1,1,0]$、长度 $[1,2]$，$i=0$ 时别的空档只有 $g_2=0 < 1$，候选退化为 $g_0+g_1=2$。

## 4. 算法细节

1. **空档数组 $n+1$ 段**，两端的 $g_0$、$g_n$ 参与"寄存"判断，也是合并段的边界（示例 2 的答案 7 就来自 $g_0 = 0$ 的合并段 $0+1+6$）。
2. **排除下标**：查询"别的空档"时必须排除 $g_i$ 与 $g_{i+1}$（它们在合并段里）。用 `pre[i-1]` 与 `suf[i+2]` 拼出区间外的最大值。
3. **`other` 初值为 0**：$n = 2$ 且 $i$ 为端点时可能没有任何"别的空档"，此时 $0 \ge \text{len}$ 恒不成立，自动落入"装不下"分支，逻辑自洽。
4. **`len` 用 `long long`**：$g_i + \text{len}(i) + g_{i+1}$ 的最大值不超过 $\text{eventTime} \le 10^9$，`int` 也够，但中间量用 `long long` 更保险。
5. **不移动会议的情况被覆盖**：不移动时最优是 $\max_j g_j$，而 $g_j \le g_i + g_{i+1}$（取包含 $j$ 的窗口）$\le$ 对应候选值，故不必单独处理。
6. **顺序可变只影响判断**：实现里完全不关心"新顺序"，因为只需判断能否找到一个长度足够的空档把会议塞进去，塞进去后其他会议位置不变。

## 5. 正确性证明

**引理 1（只有一段结构被改写）**：设最终只移动了会议 $i$，其余会议不动，则最终布局中的空余区间只可能来自以下三类：① 合并段 $[\text{endTime}[i-1], \text{startTime}[i+1]]$（端点按边界处理）内部的空余；② 被会议 $i$ 挤入的那个空档 $g_j$ 被切开后剩下的部分；③ 其他未被触及的空档。

**证明**：移动只改变会议 $i$ 的位置。其他会议、以及活动两端不动，所以所有空档里只有 $g_i$、$g_{i+1}$（因会议 $i$ 离开而合并）与 $g_j$（因会议 $i$ 进入而被切开）发生变化，其余空档原样保留。∎

**引理 2（三类空余的上界）**：沿用引理 1 的记号，三类空余长度分别不超过 $\text{merged}_i$、$g_j$、$g_j$，其中 $\text{merged}_i = g_i + \text{len}(i) + g_{i+1}$。

**证明**：① 合并段的总跨度就是 $\text{merged}_i$，其中还要放下会议 $i$ 自身，故空余 $\le \text{merged}_i$；② 切开的空档两段之和为 $g_j - \text{len}(i) < g_j$，每段都 $< g_j$；③ 未触及的空档长度就是 $g_j$。∎

**定理**：算法输出等于最优布局下的最长连续空余。

**证明**：记 $\text{cand}_i$ 为算法对会议 $i$ 算出的候选值，$M = \max_i \text{cand}_i$。

1. **可达（$M$ 能取到）**：对任意 $i$，若存在 $j \notin \{i, i+1\}$ 使 $g_j \ge \text{len}(i)$，把会议 $i$ 平移进空档 $g_j$（不越界、不重叠，且顺序可变），由引理 1 的 ①，合并段内部完全空出，长度恰为 $\text{merged}_i = \text{cand}_i$。否则把会议 $i$ 贴着合并段的一端摆放，合并段剩下的连续空余为 $\text{merged}_i - \text{len}(i) = g_i + g_{i+1} = \text{cand}_i$。故 $M$ 可达。
2. **上界（任何布局都超不过 $M$）**：若布局不移动任何会议，最长空余为 $\max_j g_j$，它不超过"包含 $g_j$ 的那个合并段去掉会议长度"的候选，即 $\le M$。若移动了会议 $i$，由引理 2，最长空余 $\le \max(\text{merged}_i,\ g_j)$。若 $g_j \ge \text{len}(i)$，则 $\text{cand}_i = \text{merged}_i \ge g_j$，故 $\le \text{cand}_i$；若没有 $g_j \ge \text{len}(i)$，则会议 $i$ 只能落在合并段内部（含 $g_i$、$g_{i+1}$），空余 $\le \text{merged}_i - \text{len}(i) = \text{cand}_i$。两种情况都有最长空余 $\le \text{cand}_i \le M$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。算空档 $O(n)$、前后缀最大值 $O(n)$、枚举 $n$ 个会议各 $O(1)$ 查询。$n \le 10^5$ 时线性即可。
- **空间**：$O(n)$。空档数组与前后缀最大值数组各 $n+1$ 个元素。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxFreeTime(int eventTime, vector<int>& startTime, vector<int>& endTime) {
        int n = (int)startTime.size();
        vector<long long> gap(n + 1);
        gap[0] = startTime[0];
        for (int i = 1; i < n; i++) gap[i] = (long long)startTime[i] - endTime[i - 1];
        gap[n] = (long long)eventTime - endTime[n - 1];

        vector<long long> pre(n + 1), suf(n + 1);
        pre[0] = gap[0];
        for (int i = 1; i <= n; i++) pre[i] = max(pre[i - 1], gap[i]);
        suf[n] = gap[n];
        for (int i = n - 1; i >= 0; i--) suf[i] = max(suf[i + 1], gap[i]);

        long long best = 0;
        for (int i = 0; i < n; i++) {
            long long len = (long long)endTime[i] - startTime[i];
            long long merged = gap[i] + len + gap[i + 1];
            long long other = 0;  // 其余空档里的最大者
            if (i >= 1) other = max(other, pre[i - 1]);
            if (i + 2 <= n) other = max(other, suf[i + 2]);
            long long cand = (other >= len) ? merged : gap[i] + gap[i + 1];
            if (cand > best) best = cand;
        }
        return (int)best;
    }
};
```

### Python

```python
class Solution:
    def maxFreeTime(self, eventTime: int, startTime: list[int], endTime: list[int]) -> int:
        n = len(startTime)
        gap = [0] * (n + 1)
        gap[0] = startTime[0]
        for i in range(1, n):
            gap[i] = startTime[i] - endTime[i - 1]
        gap[n] = eventTime - endTime[n - 1]
        pre = [0] * (n + 1)
        pre[0] = gap[0]
        for i in range(1, n + 1):
            pre[i] = max(pre[i - 1], gap[i])
        suf = [0] * (n + 1)
        suf[n] = gap[n]
        for i in range(n - 1, -1, -1):
            suf[i] = max(suf[i + 1], gap[i])
        best = 0
        for i in range(n):
            length = endTime[i] - startTime[i]
            merged = gap[i] + length + gap[i + 1]
            other = 0
            if i >= 1:
                other = max(other, pre[i - 1])
            if i + 2 <= n:
                other = max(other, suf[i + 2])
            cand = merged if other >= length else gap[i] + gap[i + 1]
            if cand > best:
                best = cand
        return best
```

## 8. 边界情况与易错点

1. **别漏掉"顺序可变"带来的寄存**：只会算 $\text{merged}_i$ 而不判断"别处有没有空档装得下"，会在示例 1 这类数据上偏大（把装不下的会议硬算成空出来了）。
2. **别把 $g_i$、$g_{i+1}$ 也算进"别处"**：它们在合并段内部，用它们判断会导致永远"装得下"，答案偏大。
3. **`other` 的初值**：没有别的空档时应视为 0（装不下），不要初始化成 $-1$ 再和长度比较，也不要直接返回 $-1$。
4. **两端空档是合法的寄存目标**：$g_0$、$g_n$ 也是空档（示例 2 的会议 `[0,1]` 就是挪到了 $g_3=[8,9]$ 里）。
5. **"至多一个"包含"不移动"**：不移动的最优值总被某个候选值支配，无需特判，但不要写出"必须移动一个"的约束。
6. **`eventTime` 与会议完全铺满**（示例 4）：所有 $g_i = 0$、$\text{merged}_i = \text{len}(i)$，但"别的空档"全是 0，装不下，候选全为 0，答案 0 正确。
7. **`i + 2 <= n` 与 `i >= 1` 的越界保护**：$i=0$ 时没有 $g_{i-1}$；$i=n-1$ 时 $i+2 = n+1 > n$，不要访问 `suf[n+1]`。
