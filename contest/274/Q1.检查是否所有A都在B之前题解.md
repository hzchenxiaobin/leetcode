# LeetCode 检查是否所有 A 都在 B 之前 题解

## 1. 题目概述

- **标题 / 题号**：检查是否所有 A 都在 B 之前（#2124，easy）
- **链接**：https://leetcode.cn/problems/check-if-all-as-appears-before-all-bs/
- **来源**：LeetCode 第 274 场周赛 Q1
- **难度**：简单
- **标签**：字符串、线性扫描

**题意**：给定仅由字符 'a' 和 'b' 组成的字符串 `s`。若字符串中**每个** 'a' 都出现在**每个** 'b' 之前，返回 `true`；否则返回 `false`。换言之，合法的字符串必形如「一段 a 接一段 b」，两段均可为空。

**约束**：

- $1 \le |s| \le 100$
- $s[i]$ 为 `'a'` 或 `'b'`

> 💡 签到题的价值在于用最短时间把「定义」翻译成「判据」：本题的关键不是怎么扫描，而是想清楚「所有 a 在所有 b 之前」的**等价形状**——一旦想到那个一眼可判的形式，代码就只剩一行。

## 2. 示例

**示例 1**

```text
输入：s = "aaabbb"
输出：true
解释：'a' 位于下标 0、1、2；'b' 位于下标 3、4、5。
      每个 'a' 都在每个 'b' 之前。
```

**示例 2**

```text
输入：s = "abab"
输出：false
解释：下标 2 处有 'a'，而下标 1 处有 'b'，存在 'b' 出现在 'a' 之前。
```

**示例 3**

```text
输入：s = "bbb"
输出：true
解释：不存在 'a'，条件空成立（空 a 段也视为在 b 段之前）。
```

## 3. 解题思路

### 3.1 暴力思路

按定义直接枚举：检查所有下标对 $(i, j)$（$i < j$），一旦发现 $s[i] = $ 'b' 且 $s[j] = $ 'a' 即返回 `false`。时间复杂度 $O(n^2)$，在 $n \le 100$ 下完全能过，但这是「没有消化定义」的写法——条件里藏着更强的结构，签到题也值得多看一眼。

### 3.2 核心观察：合法 ⇔ 两段结构 ⇔ 不出现相邻 "ba"

![核心观察：两段结构与相邻 ba 判据](images/ab_order_partition_model.svg)

「每个 'a' 都在**每个** 'b' 之前」描述的是一个**整体形状**约束，它等价于以下三种判据（等价性证明见 §5）：

1. **两段结构**：$s$ 形如 $a^* b^*$——先一串 'a'（可为空），再一串 'b'（可为空）；
2. **位置判据**：最后一个 'a' 的下标 < 第一个 'b' 的下标（某字符缺席时视为空段，条件空成立）；
3. **相邻判据**：$s$ 中**不出现子串 "ba"**——只要某处相邻出现 'b' 后跟 'a' 即违规；反之，任何违规必然浓缩成一处相邻的 "ba"。

其中判据 3 是「从题面到代码的最短路径」：C++ 一句 `s.find("ba") == string::npos`、Python 一句 `"ba" not in s` 即为完整提交（见 §7）。判据 2 看似直观，但「字符不存在」的位置语义是个陷阱（见 §8）。

### 3.3 算法流程：单遍 flag 扫描（可迁移模板）

![算法流程：单遍扫描状态机](images/ab_order_scan_flow.svg)

若不依赖语言库，可手写一个对任何「两类字符有序出现」都通用的模板：维护标志变量 `seenB`（是否已见过 'b'），从左到右扫描，一旦在 `seenB` 为真时再遇 'a' 即违规：

```text
1. seenB = false
2. 对每个字符 c（从左到右）：
     若 c == 'a'：
         若 seenB 已为 true → 返回 false（b 之后又见 a）
     若 c == 'b'：
         seenB = true
3. 扫描结束仍未违规 → 返回 true
```

### 3.4 示例演算

![示例演算：三个示例的扫描走查](images/ab_order_walkthrough.svg)

| 示例 | 扫描过程 | 判定 |
|------|----------|------|
| "aaabbb" | 前 3 个 'a' 时 `seenB` 始终为 false；下标 3 起 `seenB = true`，其后全是 'b'，不再触发检查 | true |
| "abab" | 下标 0 的 'a' 通过；下标 1 的 'b' 置 `seenB = true`；下标 2 又遇 'a' 且 `seenB` 已置位 | false |
| "bbb" | 全程无 'a'，`seenB` 置位后再无违规可能 | true |

## 4. 算法细节

1. **三种判据的取舍**：相邻判据（找 "ba"）代码最短且无边界分支；位置判据（lastA < firstB）需要小心处理「字符不存在」的返回值语义（见 §8 第 1、2 条）；flag 扫描最通用，不依赖语言库，套上任意两类字符即用。
2. **为什么找相邻 "ba" 就够了**：违规对 $(i, j)$ 可能相距很远，但取 $i$ 之后**第一个** 'a' 的位置 $j'$，则 $s[j'-1]$ 必为 'b'（否则 $j'-1$ 是更早的 'a'），于是任意违规必然产生一处相邻 "ba"（引理 1）。这一步把 $O(n^2)$ 的对枚举塌缩成 $O(n)$ 的子串查找。
3. **C++ 细节**：`string::find` 找不到时返回 `string::npos`（`size_t` 类型的极大值），判断必须显式与 `npos` 比较；Python 的 `in` 直接做子串判定，平均 $O(n)$。
4. **排序彩蛋**：由于 'a' < 'b'，$s$ 合法 ⇔ $s$ 非降序，故 `is_sorted(s.begin(), s.end())`（C++）与 `list(s) == sorted(s)`（Python）同样正确，但为 $O(n \log n)$ 且仅当字符集有序时成立，作为思路对照即可，不必作为主解。

## 5. 正确性证明

**引理 1**：$s$ 满足「每个 'a' 都在每个 'b' 之前」⇔ $s$ 中不出现相邻子串 "ba"。

**证明**：（⇐）若 "ba" 在下标 $k, k+1$ 处出现，则 $s[k] = $ 'b' 出现在 $s[k+1] = $ 'a' 之前，违反条件。（⇒）设条件被违反，即存在 $i < j$ 使 $s[i] = $ 'b' 且 $s[j] = $ 'a'。取 $i$ 之后**第一个** 'a' 的位置 $j'$（存在且 $j' \le j$）。由 $j'$ 的最小性，$s[j'-1] \ne$ 'a'；又字符集只有 'a'、'b'，故 $s[j'-1] = $ 'b'。于是 "ba" 恰在 $j'-1, j'$ 处相邻出现。∎

**定理**：算法（检查 "ba" 是否作为子串出现，出现则返回 `false`，否则返回 `true`）的返回值与题目定义一致；单遍 flag 扫描与之一致。

**证明**：由引理 1，题目条件的否定恰为「"ba" 出现」，而子串查找正确判定此事，故前者正确。对 flag 扫描：`seenB` 在处理 $s[0..i]$ 后为真 ⇔ 前 $i+1$ 个字符中存在 'b'；遇 'a' 且 `seenB` 为真 ⇔ 该 'a' 之前存在 'b' ⇔ 存在违规对，返回 `false` 与判据一致；扫描全程未返回 `false` ⇔ 任意 'a' 之前都无 'b' ⇔ 条件成立，返回 `true`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。子串查找与单遍扫描都只对每个字符做常数次访问，$n \le 100$ 下等同常数级。
- **空间复杂度**：$O(1)$。flag 扫描只用一个布尔变量，库函数的子串查找也只需常数额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkString(string s) {
        return s.find("ba") == string::npos;
    }
};
```

### Python

```python
class Solution:
    def checkString(self, s: str) -> bool:
        return "ba" not in s
```

## 8. 边界情况与易错点

1. **空段语义（本题最大的坑）**：全 'a'（"aaa"）与全 'b'（"bbb"，即示例 3）都返回 `true`——「每个 a 在每个 b 之前」在某一侧缺席时是**空真**。相邻判据与 flag 扫描天然覆盖，无需特判；位置判据则必须显式处理「字符不存在」的分支，否则必错（下条）。
2. **`find`/`rfind` 的 -1 陷阱**：Python 中裸写 `s.rfind('a') < s.find('b')`，在 "aaa" 上算得 $2 < -1$ 为 `false`，**直接判反**（正确为 `true`）；换成 `s.find('b') < s.rfind('a')`，在 "bbb" 上算得 $0 < -1$ 亦判反。两种写法各自只在「另一字符缺席」的半个边界上碰巧正确——失败返回的 -1 参与比较时语义已失真。C++ 的 `npos` 则是 `size_t`，与 `-1` 混比会触发整型转换问题。这正是推荐相邻判据的原因。
3. **不要枚举所有对**：$O(n^2)$ 在 $n \le 100$ 下能过，但引理 1 说明一次子串查找就足够——把定义读成形状，是本题想考察的能力。
4. **单字符输入**：$n = 1$ 时 "a" 与 "b" 均合法，所有判据天然覆盖。
5. **字符集假设**：判据依赖「s 只含 'a' 与 'b'」。若放宽为任意字符集（如要求所有 'a' 在所有 'c' 之前、无视其它字符），相邻判据失效，需改用位置判据并跳过无关字符。
