# LeetCode 参加会议的最多员工数 题解

## 1. 题目概述

- **标题 / 题号**：参加会议的最多员工数（#2127，hard）
- **链接**：https://leetcode.cn/problems/maximum-employees-to-be-invited-to-a-meeting/
- **来源**：LeetCode 第 274 场周赛 Q4
- **难度**：困难
- **标签**：图、拓扑排序、内向基环森林、树形动态规划

**题意**：公司准备了一张**圆桌**（只有一张，可坐任意多人），邀请名单上有 $n$ 位员工，编号 $0 \sim n-1$。每位员工恰有一位喜欢的员工 `favorite[i]`（保证不是自己）。员工 $i$ 愿意参会，**当且仅当**他被安排坐在 `favorite[i]` 的**旁边**（左邻或右邻之一）。邀请子集与圆桌座次都由你安排，求**最多**多少人能同时参会。

**约束**：

- $2 \le n \le 10^5$
- $0 \le \text{favorite}[i] \le n-1$，且 $\text{favorite}[i] \ne i$

> 💡 本题在本仓库另有[每日题解 2127](../../solution/2101-2200/2127_参加会议的最多员工数.md)：主线同为「内向基环森林 + 环长分类」。本篇按**周赛复盘视角**展开：补全「封闭性 → 长环锁死 → 二元环上界 → 单元拼接」的**引理-定理证明链**，给出拓扑剥链的流程图与双示例走查图，并沉淀赛场上最容易翻车的 8 个坑（depth 误累加、两类答案误合并、递归找环爆栈等）。至此第 274 场四题（Q1 #2124、Q2 #2125、Q3 #2126、Q4 #2127）复盘完整。

> 💡 题眼在「**每人恰有一个喜欢对象**」——出度恒为 1，输入天然是一张**内向基环森林**；而圆桌的「相邻」约束恰好把所有可行方案锁死在**环结构**上。赛场上先画出 ρ 形分量，答案公式几乎是看图直接读出来的。

## 3. 解题思路

### 3.1 暴力思路

枚举员工子集 $S$，再枚举 $S$ 的圆桌排列逐一验证「每人 favorite 在邻位」——这是子集枚举版的哈密顿回路判定，$2^n \cdot |S|!$ 在 $n \le 10^5$ 下毫无希望。暴力的浪费在于：合法座次的**形状**其实被 favorite 的结构完全支配，根本不需要搜索——直接分析函数图就能同时读出答案的**上界**与**构造**。

### 3.2 核心观察：内向基环森林 + 环长分类

![内向基环森林：每个分量恰有一个环，环上挂树](images/meeting_invites_functional_graph.svg)

每人出度恰为 1，整张图是若干 **ρ 形分量**的并：一个**环** + 挂在环上节点处的**树**（注意树可以分叉——多人可以喜欢同一个人）。两条硬事实支配所有可行座次：

1. **封闭性**：$i$ 参会 ⇒ `favorite[i]` 必须坐在 $i$ 旁边 ⇒ `favorite[i]` 也参会。参会集合对 favorite **封闭**，于是从任何参会者沿 favorite 走必然落进一个**完整的环**。
2. **邻位只有两个**：每人恰需 1 个邻位留给 favorite，另一个「自由邻位」能否利用，完全取决于**环长**。

![两类组桌方式：长环双邻位锁死 vs 二元环自由拼接](images/meeting_invites_two_table_cases.svg)

按环长分两类，组桌能力天差地别：

- **环长 $\ge 3$（长环）**：按环序围坐时，每个环上节点的两个邻位分别是**前驱**（他的 favorite 是我）与**后继**（我的 favorite）——**双邻位锁死**。挂链插不进、别的环拼不上，只能**整环独占一桌**，贡献 $= k$；又因为只有一张桌子，多个长环只能取最大的那个。示例 3 的员工 2 正是被锁死挡在门外的典型。
- **环长 $= 2$（二元环）**：$a \leftrightarrow b$ 互为 favorite，$a$ 的一个邻位给 $b$，还剩**一个自由邻位**可以挂「指向 $a$ 的最长链」$L_a$；$b$ 同理挂 $L_b$。每个二元环形成一个「**链–对–链**」单元，单元两端的人 favorite 都在自己单元内部且已相邻，所以**任意多个单元可以首尾相接拼满一张圆桌**，贡献**全部相加**。

两类方案互斥（长环锁死，无法与任何单元共桌），答案取两者较大：

$$\text{ans} = \max\Big(\underbrace{\max_{\text{长环}} k}_{\text{独占桌}},\ \ \underbrace{\sum_{\text{二元环}(a,b)} \big(2 + L_a + L_b\big)}_{\text{拼桌总和}}\Big)$$

### 3.3 算法流程：Kahn 剥叶子 + 环分类

![算法流程：拓扑剥叶子求挂链深度，再对环分类统计](images/meeting_invites_kahn_peel_flow.svg)

关键在于**一次拓扑剥离同时拿到两样东西**：

1. **哪些节点在环上**：入度（被喜欢的人数）归零的节点被逐层剥掉——它们是挂树的叶子（没人喜欢的人，即链的最远端）；剥不动的恰是环上节点，因为环上节点的入度永远有**环内前驱保底 $\ge 1$**。
2. **环上节点挂的链有多长**：剥叶子时沿 favorite 方向传递 `depth[u]`（$u$ 处挂链长度，**不含 $u$ 自身**，初值 0）。每剥一个 $u$，就松弛 `depth[favorite[u]] = max(depth[favorite[u]], depth[u] + 1)`。由于环上节点永远不会被剥，`depth[环上节点]` 天然只统计**环外挂链**——二元环的另一端是环上节点、不会入队，无需手工排除（细节见 §4）。

统计阶段对每个环沿 `favorite` 走一圈得长度 $L$：$L = 2$ 则把 $2 + \text{depth}[a] + \text{depth}[b]$ 累加进 `sum2`；$L \ge 3$ 则用 $L$ 更新 `maxCycle`。最终答案 `max(maxCycle, sum2)`。

### 3.4 示例演算

![示例演算：长环案与二元环案的 Kahn 走查](images/meeting_invites_walkthrough.svg)

**示例 3**（favorite = [3,0,1,4,1]，长环案）：

| 步骤 | 动作 | 状态 |
|------|------|------|
| 初始 | 统计入度 | `indeg = [1,2,0,1,1]`，队列 `[2]` |
| 剥 2 | 2→1，`depth[1] = 1` | `indeg[1]` 由 2 减为 1，队列空 |
| 找环 | 剩余 0,1,3,4 | 环 `0→3→4→1→0`，$L = 4$ |

`maxCycle = 4`，无二元环，答案 `max(4, 0) = 4` ✓（座次 0-3-4-1 即环序）。

**示例 1**（favorite = [2,2,1,2]，二元环案）：

| 步骤 | 动作 | 状态 |
|------|------|------|
| 初始 | 统计入度 | `indeg = [0,1,3,0]`，队列 `[0, 3]` |
| 剥 0 | 0→2，`depth[2] = 1` | `indeg[2]` 由 3 减为 2 |
| 剥 3 | 3→2，`depth[2] = max(1, 0+1) = 1` | **取 max 不累加**：0、3 都喜欢 2，自由邻位只挂一条链 |
| 找环 | 剩余 1,2 | 二元环 `1↔2`，$L = 2$ |

`sum2 = 2 + depth[1] + depth[2] = 2 + 0 + 1 = 3`，答案 `max(0, 3) = 3` ✓。

## 4. 算法细节

1. **剥的方向**：入度 = 「被多少人喜欢」。入度为 0 的节点是挂树**叶子**（链的最远端），从它们开始剥，剥离方向恰好从链尾推向环——与「链上每人喜欢链中下一个」的方向一致。
2. **depth 语义**：`depth[u]` = 以 $u$ 为**链头**（最靠近环的一端）的挂链长度，**不含 $u$ 自身**，初值 0；贡献公式 $2 + \text{depth}[a] + \text{depth}[b]$ 中的 2 正是二元环二人。
3. **松弛取 max**：挂树可以分叉（多人喜欢同一人），但二元环节点的自由邻位只有 1 个、只能挂**一条**链，故取最长而非求和——示例 1 中 0、3 都喜欢 2，`depth[2]` 仍是 1。
4. **环上节点不会被剥**：环上每个节点的入度至少有环内前驱贡献 1（长环的前驱是环上前一节点；二元环 $a$ 的保底来自 $b$），因此 Kahn 结束后 `indeg[i] > 0` **当且仅当** $i$ 在环上——入度数组本身就是「环标记」。
5. **二元环无污染**：`depth[a]` 只会被**已剥掉**的节点 $u$（且 `favorite[u] = a`）松弛；$b$ 是环上节点永不入队，不会把 $b$ 侧的信息算进 `depth[a]`，两侧链天然隔离。
6. **环遍历**：从每个 `indeg > 0` 且未访问的节点沿 `favorite` 走一圈计数即可；visited 可直接复用 `indeg`（走过后置 0），也可用独立数组，均 $O(n)$。
7. **无需建图**：`favorite` 数组本身就是出边表（出度 = 1），`v = favorite[u]` 一步取到唯一目标，连反图都不用建——这是函数图带来的实质简化。

## 5. 正确性证明

记 $f(i) = \text{favorite}[i]$。设某方案的参会集合为 $S$，$m = |S|$，圆桌座次是 $S$ 的一个环形排列；约束为 $\forall i \in S$：$f(i)$ 与 $i$ 在桌上相邻。记 $L_x$ 为挂树中以环上节点 $x$ 为链头、逐级「favorite 指向链头」方向的最长链长度（不含 $x$）。

**引理 1（封闭性）**：$i \in S \Rightarrow f(i) \in S$；且 $S$ 非空时必含至少一个完整的环。

**证明**：$i$ 的约束要求 $f(i)$ 坐在 $i$ 的邻位，故 $f(i) \in S$。对 $t$ 归纳得 $f^t(i) \in S$ 对一切 $t \ge 0$ 成立；$S$ 有限，序列必重现，设 $f^p(i) = f^q(i)$（$p < q$）为首次重现，则 $f^p(i), \dots, f^{q-1}(i)$ 两两不同且构成 $S$ 内一个完整的环。∎

**引理 2（长环锁死）**：若 $S$ 含长为 $k \ge 3$ 的环 $C$，则 $S = C$，且座次即环序。

**证明**：对 $v \in C$：$v$ 自身的约束要求后继 $f(v)$ 与 $v$ 相邻；前驱 $p$（$f(p) = v$）的约束要求 $v$ 与 $p$ 相邻。故 $v$ 的两个邻位都被环上节点占据（$k \ge 3$ 时前驱 $\ne$ 后继，两个邻位恰好用满）。于是 $k$ 条相邻关系 $\{v, f(v)\}$（$k \ge 3$ 时两两不同）构成圆桌邻接图（一个 $m$ 阶圈）中长为 $k$ 的**子圈**；而 $m$ 阶圈的任何子圈必是自身（去掉任何一条边就断成链），故 $k = m$，即 $S = C$，且相邻关系强制座次沿环序。∎

**推论**：长环既不能接纳挂链（示例 3 的员工 2），也不能与任何其他环或二元环单元共桌。

**引理 3（二元环上界）**：设二元环 $(a, b) \subseteq S$，则 $S$ 中 favorite 轨道终于 $(a,b)$ 的成员数不超过 $2 + L_a + L_b$。

**证明**：$a$ 的约束要求 $f(a) = b$ 相邻，故 $a$ 的一个邻位是 $b$；另一个邻位记为 $x_a$（若 $m \ge 3$，两邻位不同；$m = 2$ 时结论显然）。轨道终于 $(a,b)$ 且异于 $a, b$ 的成员 $u$，其 $f(u)$ 也在该成员组中（引理 1，且轨道是后缀）。其中 $f(u) = a$ 者必须坐在 $a$ 旁，而 $a$ 的邻位仅 $b$ 与 $x_a$，故**至多 1 人**，只能是 $x_a$（且要求 $f(x_a) = a$）。同理 $f(u) = b$ 者至多 1 人（$b$ 的另一邻位 $x_b$）。设 $f(x_a) = a$，则 $f(\cdot) = x_a$ 者必须坐在 $x_a$ 旁：$x_a$ 的邻位是 $a$（但 $f(a) = b \ne x_a$）与更外侧的 $y$，故又至多 1 人。归纳可知 $a$ 侧成员构成一条**从 $x_a$ 起、逐个 favorite 指向内侧**的连续链，它是挂树中以 $a$ 为链头的某条链的（子）链，长度 $\le L_a$；$b$ 侧同理 $\le L_b$。两侧分属不同的挂子树、互不相交，合计 $\le 2 + L_a + L_b$。∎

**引理 4（拼接可行性）**：任意 $r$ 个二元环单元（环 $(a_t, b_t)$，$a_t$ 侧挂一条长 $l_t \le L_{a_t}$ 的链、$b_t$ 侧挂一条长 $l'_t \le L_{b_t}$ 的链）可以拼成一张合法圆桌，人数 $= \sum_t \big(2 + l_t + l'_t\big)$。

**证明**：构造座次：每个单元排成「链尾–…–链头–$a_t$–$b_t$–链头–…–链尾」，再把 $r$ 个单元首尾相接成环。单元内部：链上每人的 favorite 是朝向环的下一个、$a_t$ 与 $b_t$ 互相相邻 ✓。拼接处相邻的两人分属不同单元，各自的 favorite 均在自己单元内部且已相邻——约束只要求「favorite 在邻位」，**不禁止**邻位再有别人，故拼接边不破坏任何约束。∎

**定理**：最大参会人数 $= \max\big(\max_{\text{长环}} k,\ \sum_{\text{二元环}} (2 + L_a + L_b)\big)$。

**证明**：（可达性）最长长环按环序围坐即合法——每人邻位恰为前驱与后继，favorite（后继）在邻位 ✓；全部二元环按引理 4 各挂最长链拼成一桌即达到求和值。（上界）设 $S$ 为任一合法方案。若 $S$ 含长环，由引理 2 得 $|S| = $ 该环长 $\le \max k$。否则 $S$ 中所有环均为二元环（$S$ 非空则必含环，引理 1），把 $S$ 按轨道终点划分给各二元环，由引理 3 逐组放缩再求和：$|S| \le \sum_{S \text{所含二元环}} (2 + L_a + L_b) \le$ 全图二元环总和。两种情形均不超过公式右端。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。入度统计 $O(n)$；Kahn 中每个节点至多入队出队一次、每条 favorite 边（恰 $n$ 条）松弛一次；环遍历每个环上节点恰好访问一次。$n \le 10^5$ 轻松通过。
- **空间复杂度**：$O(n)$。`indeg`、`depth`、队列各 $O(n)$；**无需邻接表 / 反图**——`favorite` 数组本身即出边表，这是「出度 = 1」带来的节省。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumInvitations(vector<int>& favorite) {
        int n = favorite.size();
        vector<int> indeg(n);
        for (int f : favorite) indeg[f]++;

        queue<int> q;
        for (int i = 0; i < n; ++i)
            if (indeg[i] == 0) q.push(i);

        vector<int> depth(n, 0);                 // 挂链长度（不含自身）
        while (!q.empty()) {
            int u = q.front(); q.pop();
            int v = favorite[u];
            depth[v] = max(depth[v], depth[u] + 1);
            if (--indeg[v] == 0) q.push(v);
        }

        int maxCycle = 0, sum2 = 0;
        for (int i = 0; i < n; ++i) {
            if (indeg[i] == 0) continue;         // 已剥掉的非环节点
            int len = 0, j = i;
            while (indeg[j] > 0) {               // 沿 favorite 走一圈
                indeg[j] = 0;                    // 兼作 visited
                j = favorite[j];
                ++len;
            }
            if (len == 2) sum2 += 2 + depth[i] + depth[favorite[i]];
            else maxCycle = max(maxCycle, len);
        }
        return max(maxCycle, sum2);
    }
};
```

### Python

```python
class Solution:
    def maximumInvitations(self, favorite: List[int]) -> int:
        n = len(favorite)
        indeg = [0] * n
        for f in favorite:
            indeg[f] += 1

        q = deque(i for i in range(n) if indeg[i] == 0)
        depth = [0] * n                          # 挂链长度（不含自身）
        while q:
            u = q.popleft()
            v = favorite[u]
            if depth[u] + 1 > depth[v]:
                depth[v] = depth[u] + 1
            indeg[v] -= 1
            if indeg[v] == 0:
                q.append(v)

        max_cycle = 0
        sum2 = 0
        for i in range(n):
            if indeg[i] == 0:
                continue
            u, length = i, 0
            while indeg[u] > 0:                  # 沿 favorite 走一圈
                indeg[u] = 0                     # 兼作 visited
                u = favorite[u]
                length += 1
            if length == 2:
                sum2 += 2 + depth[i] + depth[favorite[i]]
            else:
                max_cycle = max(max_cycle, length)
        return max(max_cycle, sum2)
```

## 8. 边界情况与易错点

1. **两类答案取 max 而非相加**：长环独占一桌（引理 2），不能与二元环单元共桌；最终必须 `max(maxCycle, sum2)`。误写成 `maxCycle + sum2` 是本题最经典的错误。
2. **二元环贡献是求和不是取 max**：多个二元环单元可以拼桌（引理 4），每个都要累加；只取最大的一个二元环会大幅漏算。
3. **depth 松弛取 max 不累加**：多人喜欢同一人时自由邻位只能挂一条链（示例 1 的 0 与 3）；写成 `depth[v] += ...` 或累加计数都会错。
4. **长环上的 depth 是废数据**：长环独占，挂链再长也上不了桌；只取环长，别把 `depth` 混入长环分支。
5. **判定条件是 `len == 2`**：环长 2 才能拼桌；写成 `len >= 2` 会把长环错误并入求和分支。
6. **别用递归找环 / DFS**：$n = 10^5$ 时链长可达 $10^5$，Python 默认递归深度 1000 必爆栈；Kahn + 迭代走环最稳。
7. **环遍历要做 visited**：外层循环会再次扫到同一环上的节点，不标记会重复统计（用 `indeg` 置 0 复用即可）。
8. **无「单人桌 / 空桌」特判**：`favorite[i] != i` 保证 1 人无法成桌；图中必有环，公式右端至少为 2，`maxCycle` 初值 0 不会误胜出。

**延伸思考**：① 若把圆桌改成**一排**（非环形）：环 $\ge 3$ 无法首尾相接被自然排除，答案退化为所有二元环单元之和 $\sum (2 + L_a + L_b)$；② 若公司备了 $k$ 张圆桌：长环可一环占一桌，二元环单元仍可任意拼桌，答案变为「最大的 $t$ 个长环之和 $+$（若还剩空桌）二元环总和」关于 $t \le \min(k, \text{长环数})$ 的最大值，一次扫描即可求解；③ 若每人可有**至多两个** favorite（至少一个在邻位即可），可行座次的刻画将复杂得多——这正说明「出度 = 1」是本题能线性求解的根基。
