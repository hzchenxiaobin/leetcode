# LeetCode 银行中的激光束数量 题解

## 1. 题目概述

- **标题 / 题号**：银行中的激光束数量（#2125，medium）
- **链接**：https://leetcode.cn/problems/number-of-laser-beams-in-a-bank/
- **来源**：LeetCode 第 274 场周赛 Q2
- **难度**：中等
- **标签**：数组、数学、字符串、矩阵

**题意**：给定一个 $m \times n$ 的二进制矩阵 `bank`（以字符串数组给出），`'1'` 表示该格有安全设备。两个位于**不同行**的设备之间存在一条激光束，当且仅当这两行**之间的所有行都没有设备**。激光束彼此独立。求激光束总数。

**约束**：

- $1 \le m, n \le 500$
- `bank[i][j]` 为 `'0'` 或 `'1'`

> 💡 本题在本仓库另有[每日题解 2125](../../solution/2101-2200/2125_银行中的激光束数量.md)：主线同为「相邻非空行乘法计数」。本篇按**周赛复盘视角**展开：给出「阻挡判据 → 相邻化 → 乘法定和」的完整引理-定理证明链、`prev` 状态机的流程推演、以示例 1/2 为对照的逐行走查，以及「空行清零 `prev`」这一赛场最高频翻车点的清单。同场 Q1（#2124 检查是否所有 A 都在 B 之前）已成文，Q3（#2126 摧毁小行星）、Q4（#2127 邀请参加开会所需的最少员工数）待补。

> 💡 本题的关键不是「怎么数」，而是「谁和谁配对」：一旦看清激光束只在**相邻的非空行**之间产生，计数就塌缩成一行乘法。

## 2. 示例

**示例 1**

```text
输入：bank = ["011001","000000","010100","001000"]
输出：8
解释：第 0 行（3 个设备）与第 2 行（2 个设备）之间：3 × 2 = 6 条；
      第 2 行与第 3 行（1 个设备）之间：2 × 1 = 2 条；合计 8 条。
      第 0 行与第 3 行之间不产生激光束——中间的第 2 行有设备，发生阻挡。
```

**示例 2**

```text
输入：bank = ["000","111","000"]
输出：0
解释：非空行只有第 1 行，不存在两个位于不同行的设备，没有激光束。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有设备对，逐对检查中间行是否全空。设备总数最坏 $500 \times 500 = 250000$，对数约 $3 \times 10^{10}$，必然超时。即使只枚举「行对」再对每对做 $O(m)$ 的中间行检查、配合行内设备数乘积计数，也是 $O(m^2)$ 的行对枚举——$m \le 500$ 勉强能过但完全不必要：条件里「中间所有行无设备」的结构远比这强。

### 3.2 核心观察：激光束只存在于相邻的非空行之间

![核心观察：空行穿透与非空行阻挡](images/laser_beams_block_model.svg)

把所有**非空行**（至少含一个设备的行）按行号从小到大列为 $r_1 < r_2 < \dots < r_k$，记 $\mathrm{cnt}(r)$ 为第 $r$ 行的设备数。那么：

1. **空行不阻挡**：中间隔的全是空行，激光束照样形成——两个设备分属 $r_i$ 与 $r_{i+1}$ 时，$r_i < j < r_{i+1}$ 的每个 $j$ 都不在非空行序列里，即为空行；
2. **非空行阻挡**：若两设备分属 $r_a$ 与 $r_b$ 且 $b \ge a + 2$，则非空行 $r_{a+1}$ 夹在中间，激光束被挡住。

于是**只有紧挨着的非空行对 $(r_i, r_{i+1})$ 之间才有激光束**，且这一对之间的激光束数是 $\mathrm{cnt}(r_i) \times \mathrm{cnt}(r_{i+1})$——每个「上行设备 × 下行设备」的组合各成一条，共 $k - 1$ 对（等价性证明见 §5）。

### 3.3 算法流程：单遍扫描 + prev 乘法累加

![算法流程：逐行扫描状态机](images/laser_beams_scan_flow.svg)

只需维护一个变量 `prev`——**最近一个非空行**的设备数，从上到下扫描：

```text
1. prev = 0, ans = 0
2. 对每一行 row（从第 0 行到第 m-1 行）：
      cnt = row 中 '1' 的个数
      若 cnt > 0：
          ans += prev * cnt     ← 与上一个非空行配对
          prev = cnt            ← 更新为当前非空行
      否则：跳过（prev 保持不变！）
3. 返回 ans
```

注意流程图里那条最关键的边：**空行什么都不做**——它既不贡献乘积，也不清空 `prev`。空行的语义本来就是「不阻挡」，跳过它正是「上一个非空行还能继续和下面配对」的体现。

### 3.4 示例演算

![示例演算：逐行走查表](images/laser_beams_walkthrough.svg)

| 行 | bank[i] | cnt | prev（进行前） | 本行操作 | ans |
|----|---------|-----|------|----------|-----|
| 0 | `"011001"` | 3 | 0 | `ans += 0×3`（无贡献），`prev = 3` | 0 |
| 1 | `"000000"` | 0 | 3 | 空行跳过，`prev` 保持 3 | 0 |
| 2 | `"010100"` | 2 | 3 | `ans += 3×2 = 6`，`prev = 2` | 6 |
| 3 | `"001000"` | 1 | 2 | `ans += 2×1 = 2`，`prev = 1` | 8 |

扫描结束返回 $8$，与示例 1 一致。示例 2 中非空行只有 1 行，没有相邻对，返回 $0$。

## 4. 算法细节

1. **行内计数**：`cnt` 直接用 `row.count('1')`（Python）或 `count(row.begin(), row.end(), '1')`（C++）统计，每行 $O(n)$。
2. **状态极简**：整个算法只维护 `prev` 与 `ans` 两个标量，无需显式存下每行的 $\mathrm{cnt}$ 数组——非空行序列是流式消费的，遇到新的非空行就把旧的「用掉」。
3. **乘法计数的来历**：固定一对相邻非空行 $(r_i, r_{i+1})$，上行任选一个设备、下行任选一个设备，二者之间都有一条激光束，且不同选法给出不同的激光束（设备对不同），故贡献恰为乘积 $\mathrm{cnt}(r_i) \times \mathrm{cnt}(r_{i+1})$，一步代替了设备层面的双重枚举。
4. **溢出估算**：非空行最多 $500$ 行、每行最多 $500$ 个设备，答案上界约 $499 \times 500 \times 500 \approx 1.25 \times 10^8$，在 `int` 范围内；但 C++ 中用 `long long` 更稳妥（见 §8 第 3 条）。

## 5. 正确性证明

**引理 1（阻挡判据）**：设备 $u$ 位于第 $r_1$ 行、设备 $v$ 位于第 $r_2$ 行（$r_1 < r_2$），则 $u, v$ 之间存在激光束 $\Leftrightarrow$ 所有满足 $r_1 < j < r_2$ 的行 $j$ 均为空行。

**证明**：这就是题目定义的直接复述：激光束条件二要求 $r_1 < i < r_2$ 的**所有**行 $i$ 无设备，即这些行全为空行。∎

**引理 2（相邻化）**：设非空行序列为 $r_1 < r_2 < \dots < r_k$。设备 $u, v$（所在行 $r_a < r_b$）之间存在激光束 $\Leftrightarrow$ $b = a + 1$。

**证明**：（⇐）若 $b = a + 1$，任意 $j$ 满足 $r_a < j < r_{a+1}$，则 $j$ 不等于任何 $r_t$（由序列严格递增，$r_a < j < r_{a+1}$ 之间没有序列中的行），故第 $j$ 行为空行，由引理 1 知激光束存在。（⇒）若 $b \ge a + 2$，则 $r_a < r_{a+1} < r_b$，非空行 $r_{a+1}$ 是中间行且含设备，违反引理 1，激光束不存在。∎

**定理**：激光束总数 $= \sum_{i=1}^{k-1} \mathrm{cnt}(r_i) \times \mathrm{cnt}(r_{i+1})$，且单遍扫描算法返回该值。

**证明**：按「设备对所在非空行」给所有激光束分类。由引理 2，激光束仅在行对 $(r_i, r_{i+1})$（$1 \le i \le k-1$）之间产生；对每个这样的行对，上行设备与下行设备的每个组合都形成一条激光束且互不相同，共 $\mathrm{cnt}(r_i) \times \mathrm{cnt}(r_{i+1})$ 条，不同行对的激光束显然不重合，故总数为所述乘积和。对扫描算法归纳：处理到非空行 $r_i$ 时，`prev` 恰为 $\mathrm{cnt}(r_{i-1})$（初值 $0$ 对应 $i=1$ 时无前驱、乘积为 $0$；中间的空行不修改 `prev`），`ans += prev * cnt` 累加的正是第 $i$ 项乘积，扫描结束后 `ans` 等于全部 $k-1$ 项之和。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \times n)$。每个格子只在统计所在行的 `cnt` 时被访问一次，乘法累加每行 $O(1)$；在 $m, n \le 500$ 下约 $2.5 \times 10^5$ 次字符访问。
- **空间复杂度**：$O(1)$。只使用 `prev`、`ans`、`cnt` 三个标量，不随输入规模增长（不计输入本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfBeams(vector<string>& bank) {
        int prev = 0;
        int ans = 0;
        for (const string& row : bank) {
            int cnt = count(row.begin(), row.end(), '1');
            if (cnt > 0) {
                ans += prev * cnt;
                prev = cnt;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfBeams(self, bank: List[str]) -> int:
        prev = 0
        ans = 0
        for row in bank:
            cnt = row.count('1')
            if cnt > 0:
                ans += prev * cnt
                prev = cnt
        return ans
```

## 8. 边界情况与易错点

1. **空行不清零 prev（本题最大的坑）**：如果把「空行」当成「断开连接」而写 `prev = 0`，示例 1 会在第 1 行后丢失第 0 行的状态，返回 $2$ 而非 $8$。空行的作用是**被穿过**，唯一正确的处理是跳过、什么都不做。
2. **全空矩阵 / 只有一个非空行**：`bank = ["000","111","000"]`（示例 2）或 `["0000"]`，非空行数 $\le 1$，无相邻对，返回 $0$；初值 `prev = 0` 天然覆盖首个非空行无前驱的情形，无需特判。
3. **C++ 溢出习惯**：本题上界约 $1.25 \times 10^8$ 未超 `int`，但 `prev * cnt` 这类中间乘积在更宽约束下是经典溢出点，周赛里顺手用 `long long` 是低成本保险。
4. **别数错 '1'**：`count` 统计的是字符 `'1'` 而非数字 `1`；Python 中 `row.count('1')` 正确，若误写成 `row.count(1)` 会得到 `0`。
5. **不要枚举设备对或行对**：$O\big((mn)^2\big)$ 的设备对枚举必然超时；即便优化到行对枚举也是浪费——引理 2 说明只有相邻非空行对有贡献，一遍扫描足够。
6. **「紧挨着的非空行」可以隔很多空行**：`prev` 与当前行之间允许隔任意多个空行（甚至一个都不隔），两种情况贡献同样成立，代码无需区分。
