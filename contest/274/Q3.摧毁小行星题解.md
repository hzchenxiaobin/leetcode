# LeetCode 摧毁小行星 题解

## 1. 题目概述

- **标题 / 题号**：摧毁小行星（#2126，medium）
- **链接**：https://leetcode.cn/problems/destroying-asteroids/
- **来源**：LeetCode 第 274 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：一颗行星初始质量为 `mass`，另有 $n$ 颗小行星，`asteroids[i]` 为第 $i$ 颗的质量。碰撞顺序**由你任意安排**：每次碰撞时，若行星当前质量**大于等于**小行星质量，小行星被摧毁，行星**获得**其质量；否则行星被摧毁、游戏失败。判断是否存在一种顺序把**所有**小行星都摧毁，能则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{mass} \le 10^5$
- $1 \le \text{asteroids.length} \le 10^5$
- $1 \le \text{asteroids[i]} \le 10^5$

> 💡 本题在本仓库另有[每日题解 2126](../../solution/2101-2200/2126_摧毁小行星.md)：主线同为「升序贪心 + 交换论证」。本篇按**周赛复盘视角**展开：给出「交换不劣 → 冒泡归约 → 主定理」的三段式证明链、排序贪心的流程图与双示例走查图，以及 **C++ 溢出**这一赛场最高频翻车点的清单。同场 Q1（#2124 检查是否所有 A 都在 B 之前）、Q2（#2125 银行中的激光束数量）已成文，Q4（#2127 参加会议的最多员工数）待补。

> 💡 题眼在「**任意顺序**」四个字——顺序是自由度，也是陷阱：直觉上「先吃小的攒质量」显然有利，但赛场上要快速确认**这条路走不通时也不会漏解**，靠的是交换论证，而不是感觉。

## 2. 示例

**示例 1**

```text
输入：mass = 10, asteroids = [3,9,19,5,21]
输出：true
解释：题面给出的可行顺序是 [9,19,5,3,21]：
      10+9=19 → 19+19=38 → 38+5=43 → 43+3=46 → 46+21=67，全部摧毁。
      换成升序 [3,5,9,19,21] 同样成功：10→13→18→27→46→67。
```

**示例 2**

```text
输入：mass = 5, asteroids = [4,9,23,4]
输出：false
解释：摧毁 23 之前能吞的至多是另外三颗，质量至多 5+4+9+4 = 22 < 23，
      无论如何安排顺序都轮不到摧毁 23，返回 false。
```

**示例 3（边界：恰好相等）**

```text
输入：mass = 5, asteroids = [5]
输出：true
解释：判定条件是「大于等于」，质量恰好相等也能摧毁，5 → 10。
```

## 3. 解题思路

### 3.1 暴力思路

枚举小行星的全排列，对每种排列模拟一遍碰撞过程：$n!$ 种顺序 × 每次 $O(n)$ 检查。$n \le 10^5$ 时 $n!$ 是天文数字，完全不可行。暴力的浪费在于：我们并不需要知道**哪种**顺序可行，只需要知道**是否存在**——于是思路转为「直接构造一种最有利的顺序，再判定它是否可行」，而最有利的顺序就是**升序**。

### 3.2 核心观察：质量单调不减，先吞小的永不亏

![核心观察：先吞小的攒质量，先撞大的当场暴毙](images/destroying_asteroids_greedy_model.svg)

两个事实叠出贪心方向：

1. **质量只增不减**：每次成功碰撞后行星质量严格增大，吞下的小行星全是纯增益；
2. **门槛由对方决定**：能不能吞，只看「当前质量 $\ge$ 对方质量」这一道门槛。

于是「先吞门槛最低的」永远不会让后续处境变差——小的先吃，攒够质量再啃大的。反过来，如果**升序**都在某颗小行星上卡壳，任何顺序都救不了（这一步并不显然，§5 用交换论证补全）。

注意示例 1 中题面给的顺序 $[9,19,5,3,21]$ 并不是升序，也能成功——可行顺序不唯一，但**升序是万能试金石**：升序可行 $\Leftrightarrow$ 存在可行顺序。

### 3.3 算法流程：排序 + 单遍吞噬

![算法流程：升序排序后单遍吞噬](images/destroying_asteroids_flow.svg)

流程只有三步：

```text
1. 将 asteroids 升序排序
2. m = mass（用足够宽的类型！）
3. 从左到右逐颗吞噬：
       若 m ≥ 当前小行星 a：m += a，继续下一颗
       否则：立即 return false
4. 全部吞完，return true
```

### 3.4 示例演算

![示例演算：两个示例的升序吞噬走查表](images/destroying_asteroids_walkthrough.svg)

**示例 1**（mass = 10，排序后 `[3, 5, 9, 19, 21]`）：

| 小行星 a | 3 | 5 | 9 | 19 | 21 |
|----------|----|----|----|----|----|
| 碰前质量 m | 10 | 13 | 18 | 27 | 46 |
| 碰后质量 m | 13 | 18 | 27 | 46 | 67 |

每一步都满足 $m \ge a$，全部吞噬，返回 `true`。

**示例 2**（mass = 5，排序后 `[4, 4, 9, 23]`）：

| 小行星 a | 4 | 4 | 9 | 23 |
|----------|---|---|---|----|
| 碰前质量 m | 5 | 9 | 13 | **22** |
| 碰后质量 m | 9 | 13 | 22 | **✗** |

在 23 处卡壳：$22 < 23$，返回 `false`。此时另外三颗已全部吞光，而**任何顺序**在轮到 23 之前能吞的都只是这三颗的子集，质量至多 22——换顺序也无力回天。

## 4. 算法细节

1. **排序方向**：必须**升序**。降序是典型笔误——先撞最大的最容易开局暴毙（见 §8 第 2 条的反例）。
2. **累加类型**：答案为 `true` 时最终质量上界为 $10^5 + 10^5 \times 10^5 \approx 1.0 \times 10^{10}$，超过 32 位 `int` 上限（约 $2.1 \times 10^9$），C++ 必须用 `long long`。
3. **判定符号**：题目要求「大于等于」，代码里写 `m < a` 才判失败，恰好相等时能摧毁。
4. **提前退出**：一旦 `m < a` 立即返回 `false`——由 §5 定理，升序失败意味着任何顺序都失败，无需（也不能）枚举其它排列补救。
5. **可选小优化**：排序后若 `m` 已不小于末尾元素（全局最大值），剩余全部可直接吞，可提前 `return true`；不做也不影响正确性与复杂度。

## 5. 正确性证明

**引理 1（交换不劣）**：设 $a_1, a_2, \dots, a_n$ 是一个可行顺序（能摧毁全部小行星），其中相邻两项满足 $a_i > a_{i+1}$。记撞 $a_i$ 之前行星质量为 $M$。则把这两项交换为「小在前、大在后」后，得到的顺序仍可行。

**证明**：原顺序可行给出两个条件：$M \ge a_i$ 且 $M + a_i \ge a_{i+1}$。交换后需重新验证两步碰撞：

- 先撞 $a_{i+1}$：需 $M \ge a_{i+1}$。由 $M \ge a_i > a_{i+1}$，成立。
- 再撞 $a_i$：需 $M + a_{i+1} \ge a_i$。由 $M \ge a_i$ 且 $a_{i+1} \ge 1 > 0$，得 $M + a_{i+1} > a_i$，成立。

两步之后行星质量均为 $M + a_i + a_{i+1}$，与原顺序完全一致，之后的碰撞过程不受影响，仍可行。∎

**引理 2（归约到升序）**：若存在可行顺序，则升序顺序也可行。

**证明**：对排列的逆序对数归纳。若可行顺序不是升序，则存在相邻逆序对 $a_i > a_{i+1}$，由引理 1 交换后仍可行；交换相邻的这对元素使全局逆序对数严格减一（其余元素与这两项的相对大小关系不受相邻交换影响）。逆序对数非负且每步严格递减，有限步后归零，得到升序排列，且每一步都保持可行。∎

**定理**：所有小行星能被摧毁 $\Leftrightarrow$ 将 `asteroids` 升序排序后从左到右逐个吞噬，全程无失败。

**证明**：（⇐）升序吞噬全程无失败，升序本身就是一种可行安排。（⇒）若存在可行安排，由引理 2，升序也可行，即升序逐个吞噬全程无失败。∎

**推论（提前退出的正确性）**：升序扫描首次遇到 $m < a_i$ 时可直接返回 `false`——由定理的逆否命题，升序失败 $\Leftrightarrow$ 不存在可行顺序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导；吞噬扫描为 $O(n)$。$n \le 10^5$ 时排序约 $10^5 \times 17$ 次比较，轻松通过。
- **空间复杂度**：$O(1)$ 额外空间（原地排序，不计排序内部栈空间）。Python 若用 `sorted(asteroids)` 会额外生成 $O(n)$ 列表，改用 `asteroids.sort()` 可保持原地。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool asteroidsDestroyed(int mass, vector<int>& asteroids) {
        sort(asteroids.begin(), asteroids.end());
        long long m = mass;
        for (int a : asteroids) {
            if (m < a) return false;
            m += a;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def asteroidsDestroyed(self, mass: int, asteroids: List[int]) -> bool:
        asteroids.sort()
        m = mass
        for a in asteroids:
            if m < a:
                return False
            m += a
        return True
```

## 8. 边界情况与易错点

1. **C++ 溢出（本题头号坑）**：全部摧毁时 $m$ 最终可达 $10^5 + \sum \text{asteroids} \le 10^5 + 10^{10}$，远超 `int`；用 `int` 累加会在大样例上溢出为负数，把本应 `true` 的案子误判成 `false`。必须 `long long`；Python 无此虑。
2. **排反方向**：升序写成降序。反例：mass = 10、asteroids = [21, 3]，降序第一步 $10 < 21$ 直接失败；升序却能 $10 \to 31 \to 34$ 全吞。
3. **判定边界**：是「大于等于」不是「严格大于」。mass = 5、asteroids = [5] 应返回 `true`；误写成 `m <= a` 判失败会错。
4. **不要往搜索 / DP 想**：题面像「顺序决策」问题，比赛时容易往回溯、状压方向绕远；交换论证已保证贪心完备，一次排序 + 扫描就够。
5. **提前退出是安全的**：升序首次失败即返回 `false`，不必再尝试其它顺序补救——这正是定理的价值所在。
6. **初始质量碾压**：mass 不小于全局最大值时任何顺序都可行，通用流程自然覆盖，无需特判。
7. **全相同元素**：如 asteroids = [4,4,4,4]，只要 mass ≥ 4 即 `true`，走通用流程即可。
