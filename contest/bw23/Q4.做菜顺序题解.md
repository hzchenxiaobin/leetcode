# LeetCode 做菜顺序 题解

## 1. 题目概述

- **标题 / 题号**：做菜顺序（#1402，hard）
- **链接**：https://leetcode.cn/problems/reducing-dishes/
- **来源**：LeetCode 第 23 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、动态规划、排序

**题意**：厨师有 $n$ 道菜，满意程度为 $satisfaction[i]$（可为负）。每道菜耗时 $1$ 单位，第 $i$ 个**被做**的菜的「like-time 系数」是「做完它的时刻 $time[i]$」乘以其满意度，即 $time[i] \times satisfaction[i]$，其中 $time$ 从 $1$ 开始按做菜顺序递增。可以放弃任意道菜、按任意顺序做剩下的菜，求 like-time 系数总和的**最大值**（一道不做则为 $0$）。

**约束**：

- $1 \le n \le 500$
- $-1000 \le satisfaction[i] \le 1000$

**约束解读**：$n \le 500$ 允许 $O(n^2)$ 的 DP，但 $n$ 若放大到 $10^5$ 就必须依赖排序 + 前缀和的线性贪心；本题作为困难题，值得把两种做法和证明都吃透。

## 2. 示例

**示例 1**

```text
输入：satisfaction = [-1,-8,0,5,-9]
输出：14
解释：放弃 -8 与 -9 两道菜，按 (-1, 0, 5) 的顺序做：(-1)×1 + 0×2 + 5×3 = 14。
（官方缓存用例为 [-1,-8,0,5,-7]，答案同样为 14。）
```

**示例 2**

```text
输入：satisfaction = [4,3,2]
输出：20
解释：三道全做，按 (2, 3, 4) 升序：(2)×1 + 3×2 + 4×3 = 20。
```

**示例 3**

```text
输入：satisfaction = [-1,-4,-5]
输出：0
解释：全部为负，一道不做，总和为 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举做哪些菜（$2^n$ 个子集）、再枚举做菜顺序（子集内排列），$O(2^n \cdot n!)$ 直接爆炸；即便意识到「固定子集后顺序可以优化」，也要 $O(2^n \cdot n)$，$n = 500$ 不可行。$n \le 500$ 下的正路之一是 $O(n^2)$ DP：按某顺序逐个决策「做不做、排第几位」；但更漂亮的是把问题转写成**前缀和**结构，一步得到 $O(n \log n)$ 贪心。

### 3.2 核心观察一：固定菜谱，按满意度升序做最优

![核心观察一：相邻两道菜交换顺序，满意度高者应靠后](images/bw23_q4_swap_argument.svg)

若选定了 $m$ 道菜，其做菜时刻为 $1, 2, \dots, m$，贡献为 $\sum_{t=1}^{m} t \cdot s_t$（$s_t$ 为第 $t$ 个做的菜的满意度）。考察相邻两道菜（第 $t$、$t+1$ 位，满意度 $p$、$q$，$p > q$）：交换前后贡献差

$$\big(qt + p(t+1)\big) - \big(pt + q(t+1)\big) = p - q > 0,$$

即**把满意度高的换到更靠后的位置，总和变大**。反复消去相邻逆序，最优顺序必为**满意度升序**——大的系数配大的满意度（排序不等式的直观形式）。

### 3.3 核心观察二：总收益 = 降序前缀和之和

设全数组**降序**排序为 $g_1 \ge g_2 \ge \cdots \ge g_n$，记降序前缀和 $G_v = g_1 + g_2 + \cdots + g_v$。若做升序排列的 $m$ 道菜 $s_1 \le \cdots \le s_m$，把系数按**后缀和**展开：

$$\sum_{t=1}^{m} t\, s_t = \sum_{v=1}^{m} \underbrace{\big(s_v + s_{v+1} + \cdots + s_m\big)}_{R_v} = \sum_{v=1}^{m} R_v,$$

（$s_t$ 恰出现在 $v \le t$ 的那些 $R_v$ 里，被计入 $t$ 次——系数正是 $t$；用 $(-1, 0, 5)$ 验算：$R = 4, 5, 5$，和恰为 $14$。）

![核心观察二：总收益为后缀和之和，倒序恰为降序前缀和 G](images/bw23_q4_prefix_sum_identity.svg)

再看 $R_v$：它是「所选 $m$ 道菜中最大的 $m-v+1$ 道之和」，而 $m$ 个不同元素中最大的 $m-v+1$ 个之和，不超过**全体**元素中最大的 $m-v+1$ 个之和，即 $R_v \le G_{m-v+1}$。令 $u = m-v+1$ 换序：

$$\sum_{v=1}^{m} R_v \;\le\; \sum_{u=1}^{m} G_u =: F(m).$$

于是「选 $m$ 道菜」的总收益上界是 $F(m)$；且**取降序数组的前 $m$ 道菜、按升序做**时每个不等式都取等（此时 $s_v = g_{m+1-v}$，逐项有 $R_v = G_{m+1-v}$），故「选 $m$ 道菜」能取得的最大总收益恰为

$$F(m) = \sum_{v=1}^{m} G_v,$$

最优方案就是**降序数组的前 $m$ 道菜**（按升序做）。

### 3.4 算法流程与示例演算

![示例演算：降序扫描累加前缀和，到第 3 道达到最大 14 后转负停止](images/bw23_q4_example_walkthrough.svg)

由 $F(m) - F(m-1) = G_m$：每多做一道（当前最大的未选）菜，总收益**增加** $G_m$（当前前缀和）。而 $G_m$ 一旦 $\le 0$ 便永远 $\le 0$（见引理 4），因此贪心流程为：

```text
1. 将 satisfaction 降序排序
2. pre = 0, ans = 0
3. 依次取 x = g_1, g_2, …：
       pre += x          # G_v
       若 pre ≤ 0：终止   # 之后增量只会更小，不再扩展
       ans += pre        # F(m) − F(m−1) = G_m
4. 返回 ans
```

**演算**（示例 1，$s = [-1,-8,0,5,-7]$）：降序得 $5, 0, -1, -7, -8$。

| $v$ | $g_v$ | $G_v$（前缀和） | $G_v > 0$? | $F(v)$ |
|-----|-------|------------------|------------|--------|
| 1 | 5 | 5 | ✓ | 5 |
| 2 | 0 | 5 | ✓ | 10 |
| 3 | $-1$ | 4 | ✓ | 14 |
| 4 | $-7$ | $-3$ | ✗ 终止 | — |

返回 $14$，对应做 $\{-1, 0, 5\}$ 三道、升序 $(-1, 0, 5)$：$-1 \times 1 + 0 \times 2 + 5 \times 3 = 14$ ✓。

## 4. 算法细节

1. **排序方向**：降序排序后「依次尝试扩展」，每一步的增量恰是当前前缀和 $G_v$。等价写法是升序排序后倒着累加，两种写法对拍结果一致，降序版更贴近证明。
2. **终止条件的两种等价表述**：`pre <= 0 时 break`（增量非正）与「取 $F(m)$ 最大的 $m$」完全一致，原因见引理 4——正增量区是前缀，不会出现「先亏后赚」。
3. **0 的处理**：$G_v = 0$ 时扩展与否不影响答案（增量为 0）；写 `pre <= 0` 提前终止与继续扫描等价，测试已覆盖。
4. **不做任何菜**：全负数组时第一步 $G_1 < 0$ 直接终止，`ans = 0`，与题意「可以不做」一致。
5. **DP 备选**（$n \le 500$ 时的稳妥写法）：降序排序后 $dp[i][j]$ 表示前 $i$ 道菜做 $j$ 道的最大收益，转移 $dp[i][j] = \max(dp[i-1][j],\ dp[i-1][j-1] + j \cdot g_i)$，答案 $\max_j dp[n][j]$，$O(n^2)$。它不依赖引理 4，可作为对拍基准与「不敢证明时的退路」。
6. **溢出核算**：上界 $\sum_t t \cdot 1000 \le 1000 \times \frac{500 \times 501}{2} \approx 1.25 \times 10^8$，`int` 足够；用 `long long` 累加是习惯性稳妥。

## 5. 正确性证明

**引理 1（顺序最优）**：固定 $m$ 道菜的集合，按满意度**升序**做时 like-time 总和最大。

**证明**：设某排列中存在相邻两位满意度 $p > q$（$p$ 在前），由 §3.2 的交换差 $p - q > 0$ 知交换后总和不减；每消去一个相邻逆序，排列的逆序数严格减小，有限步后得到升序排列且总和不减。故升序最优。∎

**引理 2（后缀和恒等式）**：升序做 $s_1 \le \cdots \le s_m$ 时，$\sum_{t=1}^m t\, s_t = \sum_{v=1}^m R_v$，其中 $R_v = s_v + s_{v+1} + \cdots + s_m$。

**证明**：$s_t$ 在 $R_v$ 中出现当且仅当 $v \le t$，故 $s_t$ 在 $\sum_{v=1}^m R_v$ 中被累加恰好 $t$ 次（对应 $v = 1, 2, \dots, t$），两边逐项对应相等。∎

**引理 3（占优）**：设全局降序为 $g_1 \ge \cdots \ge g_n$、$G_u = g_1 + \cdots + g_u$，则任意 $m$ 元子集升序排列 $s_1 \le \cdots \le s_m$ 满足 $R_v \le G_{m-v+1}$ 对所有 $1 \le v \le m$ 成立。

**证明**：$R_v = s_v + \cdots + s_m$ 是所选 $m$ 个互不相同元素中**最大的 $m-v+1$ 个之和**；$m$ 个不同元素中最大 $m-v+1$ 个之和，不超过全体 $n$ 个元素中最大 $m-v+1$ 个之和 $G_{m-v+1}$。∎

**引理 4（正增量是前缀）**：若 $G_v \le 0$，则对所有 $v' > v$ 有 $G_{v'} \le 0$。

**证明**：$G_v \le 0$ 时分两种情形。若 $g_1, \dots, g_v$ 全为非负，则 $G_v = 0$ 且全为 $0$，于是 $g_w \le 0\ (w > v)$，$G_{v'} = \sum_{w \le v'} g_w = \sum_{v < w \le v'} g_w \le 0$。否则存在某个 $u \le v$ 使 $g_u < 0$，由降序性对一切 $w > u$ 有 $g_w \le g_u < 0$，于是 $G_{v'} = G_v + \sum_{w=v+1}^{v'} g_w \le G_v + (v'-v)\, g_u < G_v \le 0$。∎

**定理（贪心正确性）**：设 $F(m) = \sum_{v=1}^m G_v$（$F(0) = 0$）。全数组可达到的最大 like-time 总和为 $\max_{0 \le m \le n} F(m)$，且该最大值由「降序扫描、前缀和 $\le 0$ 即停」的贪心取得。

**证明**：先证可达上界：任取一个「做 $m$ 道菜」的方案，由引理 1 可设其按升序做，由引理 2 其收益为 $\sum_{v=1}^m R_v$，再由引理 3 并令 $u = m - v + 1$ 换序，不超过 $\sum_{u=1}^m G_u = F(m) \le \max_m F(m)$；而「取降序前 $m$ 道菜、升序做」的方案满足 $s_v = g_{m+1-v}$，逐项 $R_v = G_{m+1-v}$，收益恰为 $F(m)$，故最大值 $= \max_m F(m)$。再证贪心取到该最大值：$F(m) - F(m-1) = G_m$，故 $F$ 的增量序列即 $G_1, G_2, \dots$；由引理 4，$\{v : G_v > 0\}$ 是一段前缀，取全部正增量（再加零增量与否不影响）即得 $\max_m F(m)$，这正是贪心流程的行为。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序主导；随后单趟扫描，每个元素做常数次加减比较。
- **空间**：$O(1)$ 额外（原地排序，C++ `sort`），Python 的 `sort` 亦为原地。若保留原数组需要 $O(n)$ 拷贝。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxSatisfaction(vector<int>& satisfaction) {
        sort(satisfaction.begin(), satisfaction.end(), greater<int>());  // 降序
        long long total = 0, pre = 0;
        for (int x : satisfaction) {
            pre += x;                            // pre = 降序前缀和 G_v
            if (pre <= 0) break;                 // 之后前缀和只会更小
            total += pre;                       // Total(m) = G_1 + G_2 + ... + G_m
        }
        return (int)total;
    }
};
```

### Python

```python
class Solution:
    def maxSatisfaction(self, satisfaction: list[int]) -> int:
        satisfaction.sort(reverse=True)          # 满意度降序
        total = pre = 0
        for x in satisfaction:
            pre += x                            # pre = 降序前缀和 G_v
            if pre <= 0:
                break                           # 之后前缀和只会更小
            total += pre                        # Total(m) = Σ G_v
        return total
```

> 💡 两份代码均通过官方示例（`14`、`20`、`0`，含题面文本版 $[-1,-8,0,5,-9]$ 用例）；另与 **bitmask 枚举全部子集+最优排列**的暴力对拍 $3000$ 组随机（$n \le 10$、数值含 $\pm 1000$ 大数与全负、全零定向用例），`mismatch = 0`；C++ 与 Python 在 $n = 500$ 随机数据上交叉 $50$ 组一致。

## 8. 边界情况与易错点

1. **全负数组**：答案为 $0$（一道不做）。贪心第一步 $G_1 < 0$ 即停，天然正确；DP 写法需显式允许 $j = 0$。
2. **含 0 满意度**：$0$ 菜加进菜谱「不亏不赚」，贪心在 $G_v = 0$ 处提前终止会跳过它——答案不受影响，但若题目改成「要求恰好做 $k$ 道」就必须 DP。
3. **别把终止条件写反**：`pre <= 0` 停止（增量非正），不是 `x <= 0` 停止——遇到第一个负数就停会错过「后面还有大正数」的情形吗？不会：降序下正数都在前面。但直接对单个 $x$ 判断的写法在「$0$ 后跟负数」等边角上与正确终止不同步，保持用**前缀和**判断最稳。
4. **升序还是降序**：升序排序 + 从大到小累加同样可行，但循环下标、终止条件容易绕晕；建议固定「降序 + 从头扩展」一种写法并与证明对应。
5. **溢出**：极值约 $1.25 \times 10^8$ 未超 `int`，但 $n$ 或值域放大后首选 `long long`。
6. **输出类型**：C++ 累加器 `long long` 返回前转 `int`，注意显式转换避免告警。
7. **忘记「可以不做菜」**：题目允许放弃全部菜，初始 `ans = 0` 即隐含该选择；若错误地强制至少做一道，全负样例（示例 3）会输出负数。
