# LeetCode 最近时刻 题解

## 1. 题目概述

- **标题 / 题号**：最近时刻（#681，medium）
- **链接**：https://leetcode.cn/problems/next-closest-time/
- **来源**：LeetCode 第 51 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、回溯、枚举

**题意**：给定一个形如 `"HH:MM"` 的合法时刻，取出它出现的 4 个数字（`':'` 不算），每个数字可以**无限次复用**，用它们重新拼出一个时刻。要求返回**严格晚于**输入、且距离输入最近的那个时刻；若当天之后再无合法时刻，就绕到次日（返回值在数值上可能比输入小）。

**约束**：

- `time.length == 5`，格式固定为 `"HH:MM"`
- 输入保证是合法时刻，取值范围 `"00:00"` 到 `"23:59"`，即 $0 \le HH < 24$、$0 \le MM < 60$
- 只允许复用输入中出现的这 4 个数位，每个数字使用次数不限
- 返回值必须是 `"HH:MM"` 两位补零格式

## 2. 示例

**示例 1**

```text
输入：time = "19:34"
输出："19:39"
解释：可用数字是 {1, 9, 3, 4}。19:35、19:36、19:37、19:38 分别用到 5、6、7、8，
      都不合法；19:39 的四个数位全在集合里，只比原来晚 5 分钟。
      19:33 也合法，但它比 19:34 小，只能算次日 19:33，晚了 1439 分钟。
```

**示例 2**

```text
输入：time = "23:59"
输出："22:22"
解释：可用数字 {2, 3, 5, 9}。当天 23:59 之后再没有合法时刻，
      于是绕到次日，最近的合法时刻是 22:22（晚 1343 分钟）。
```

**示例 3（补充，非官方）**

```text
输入：time = "00:00"
输出："00:00"
解释：可用数字只有 {0}，唯一合法时刻就是 00:00 本身，
      它的「下一个」出现是次日同一时刻，故答案为 "00:00"。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：从 `start + 1` 开始逐分钟往后试，最多试 1440 次，每次检查该时刻的 4 个数位是否都来自可用数字，第一个命中的就是答案。时间为 $O(1440)$、空间 $O(1)$，本身就能通过。

但它枚举的是「**所有时刻**」，而候选其实只有「4 个数字填 4 个数位」这一种结构：1440 个时刻里绝大多数根本拼不出来。所以更贴合题目标签（枚举 / 回溯）的做法，是直接在**数字组合域**上枚举，顺带把「最近」与「跨天回绕」统一成一个取模运算。

### 3.2 核心观察：时间是一个 1440 分钟的环

![时间环与最小正差](images/wc51_q2_time_ring.svg)

两个关键事实：

1. **候选集合很小**：设可用数字去重后为 $D$，$|D| = k \le 4$。一个候选由 4 个数位组成、每个数位取自 $D$，故候选至多 $k^4 \le 256$ 个；再按 `HH < 24`、`MM < 60` 过滤，通常只剩几十个。
2. **「最近」= 环上最小正差**：把时刻看成集合 $\{0, 1, \dots, 1439\}$ 上的一个环。候选 $t$ 相对起点 $s$ 的下一次出现要等

$$\Delta(t) = \bigl(t - s + 1440\bigr) \bmod 1440, \qquad \Delta(t) = 0 \text{ 时记作 } 1440$$

于是答案就是 $\arg\min_{t \in C} \Delta(t)$。$\Delta = 0$ 只会发生在 $t = s$（输入本身必在候选集中，它的数位当然都在 $D$ 里），此时「下一个」是次日同一时刻，故记作 1440。

> 💡 这一步把「跨天回绕」从 if-else 特判变成了一个取模，同时解释了示例 1 为什么不能选 19:33：它要绕一整圈，$\Delta = 1439$。

### 3.3 算法流程

![回溯枚举与取最小正差](images/wc51_q2_backtrack_flow.svg)

1. 解析出 `s = HH * 60 + MM`，用哈希集合收集 4 个数位（跳过下标 2 的 `':'`）得到 $D$。
2. 回溯枚举 4 个数位：小时十位、小时个位、分钟十位、分钟个位，每层从 $D$ 中挑一个。
3. 拼出 `hh`、`mm` 后过滤：`hh < 24` 且 `mm < 60`，否则剪掉该分支。
4. 对合法候选计算 $\Delta = (t - s + 1440) \bmod 1440$，遇 0 记作 1440。
5. 维护最小的 `bestDelta` 与对应的 `best`，最后按 `%02d:%02d` 格式化输出。

### 3.4 示例演算

![示例演算表](images/wc51_q2_walkthrough.svg)

示例 1（$s = 1174$，$D = \{1,3,4,9\}$）：

| 候选 $t$ | 时刻 | $\Delta$ | 说明 |
| --- | --- | --- | --- |
| 1173 | 19:33 | 1439 | 比 $s$ 小，只能次日，绕一整圈 |
| 1179 | 19:39 | 5 | 最小，输出 |
| 1181 | 19:41 | 7 | 比 19:39 还晚 2 分钟 |

示例 2（$s = 1439$，$D = \{2,3,5,9\}$）：当天最大的合法候选就是 23:59 本身（$\Delta = 1440$），其余候选全部 $< s$，取 $\Delta$ 最小者得到 22:22（$\Delta = 1343$）。

## 4. 算法细节

1. **用集合去重**：`"19:34"` 的 4 个数字是 $\{1,9,3,4\}$；`"11:11"` 只有 1 个不同数字，回溯规模自动缩到 $1^4 = 1$，不需要特判。
2. **必须按「两位」拼数字**：十位可以是 0（如 `"05:23"` 的 `0`），所以小时十位、分钟十位也要在 $D$ 里枚举，不能把小时当整数直接跑 `0..23`。
3. **过滤前置**：`hh` 只依赖前两层的选择，先判 `hh < 24` 再进入分钟层，可以少一层无效循环；分钟层再判 `mm < 60`。
4. **$\Delta$ 的写法**：C++ 中 `t - s` 可能为负，`+ 1440` 后取模一定落在 $[0, 2878]$，不会出现负数取模；Python 的 `%` 天然返回非负，直接写 `(t - s) % 1440`。
5. **$\Delta = 0$ 不能丢**：`"00:00"`、`"11:11"` 这类输入的唯一候选就是自己，正确答案正是次日同一时刻，所以要把 0 映射成 1440，而不是 `continue` 掉。
6. **格式化补零**：用 `%02d:%02d`（Python 用 `f"{h:02d}:{m:02d}"`），否则会拼出 `"9:5"` 这种非法输出。
7. **可选剪枝**：把 $D$ 升序排列后回溯，一旦小时前缀已超过 23 就 `break` 掉该层剩余分支。256 个候选下不必优化，但面试时是加分项。

## 5. 正确性证明

**引理 1（候选枚举完备）**：回溯生成并通过过滤的集合 $C$，恰好等于「所有由 $D$ 中数字拼成的合法时刻」。

**证明**：任取 $t \in C$，它的 4 个数位都取自 $D$，且满足 $hh < 24$、$mm < 60$，故 $t$ 是合法候选，得 $C \subseteq$ 合法候选集。反之，任取一个合法候选，其 4 个数位都在 $D$ 中，而回溯枚举穷尽了 $D^4$ 的全部取值（每层遍历 $D$ 中每个数字），必有一支对应它，且它通过过滤，得合法候选集 $\subseteq C$。∎

**引理 2（$\Delta$ 即下一次出现的等待时间）**：对候选 $t$，它在 $s$ 之后最近一次出现需要等待 $\Delta(t)$ 分钟，其中 $\Delta(t) = (t - s + 1440) \bmod 1440$，且 $\Delta = 0$ 时取 1440；也就是说，下一次出现的时刻为 $s + \Delta(t)$（可能已跨到次日）。

**证明**：候选每天出现一次，出现时刻集合为 $\{\,t + 1440k \mid k \in \mathbb{Z}\,\}$。令 $d = (t - s) \bmod 1440 \in [0, 1439]$。若 $d > 0$，则使 $t + 1440k > s$ 的最小整数 $k$ 满足 $t + 1440k - s = d$，等待 $d$ 分钟；若 $d = 0$，则 $t \equiv s$，下一次出现需 $k = 1$，即 1440 分钟。两种情况都与定义一致。∎

**引理 3（$C$ 非空）**：输入时刻 $s$ 本身属于 $C$。

**证明**：$s$ 的 4 个数位正是构造 $D$ 的来源，且 $s$ 合法，由引理 1 得 $s \in C$，故 $C \ne \varnothing$。∎

**定理**：算法返回的字符串，就是「复用输入数字、严格晚于输入的下一个最近时刻」。

**证明**：由引理 1，$C$ 覆盖全部合法候选；由引理 3，$C$ 非空，故循环结束后 `best` 一定被赋值。由引理 2，任意候选 $t$ 的下一次出现距 $s$ 为 $\Delta(t)$ 分钟，因此「时间上最近」等价于「$\Delta$ 最小」。算法遍历 $C$ 中每个元素取 $\Delta$ 最小者，返回的时刻即是最近的下一个合法时刻。若最小值对应 $\Delta = 1440$，说明 $(s, s + 1440)$ 内没有任何候选，最近的就是次日同一时刻，输出本身仍然正确。∎

## 6. 复杂度分析

- **时间**：$O(k^4)$，其中 $k = |D| \le 4$，最坏 $4^4 = 256$ 次组合，每次 $O(1)$；相对逐分钟扫描的 1440 次，常数约小 5 倍，二者都是常数复杂度。
- **空间**：$O(k) \le O(4)$ 存放数字集合；回溯栈深度固定为 4（写成四重循环时为 0），不计输出字符串。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
#include <cstdio>
using namespace std;

class Solution {
public:
    string nextClosestTime(string time) {
        // ① 起点分钟数 + 可用数字集合（跳过 ':'）
        int start = stoi(time.substr(0, 2)) * 60 + stoi(time.substr(3, 2));
        vector<int> d;
        for (int i = 0; i < 5; ++i) {
            if (time[i] == ':') continue;
            int x = time[i] - '0';
            if (find(d.begin(), d.end(), x) == d.end()) d.push_back(x);
        }

        // ② 四层枚举 HHMM，等价于对 d 做 4 位回溯
        int best = -1, bestDelta = 1441;
        for (int h1 : d) {
            for (int h2 : d) {
                int hh = h1 * 10 + h2;
                if (hh >= 24) continue;                  // 剪枝
                for (int m1 : d) {
                    for (int m2 : d) {
                        int mm = m1 * 10 + m2;
                        if (mm >= 60) continue;          // 剪枝
                        int t = hh * 60 + mm;
                        int delta = (t - start + 1440) % 1440;
                        if (delta == 0) delta = 1440;    // 自己 -> 次日同一时刻
                        if (delta < bestDelta) {
                            bestDelta = delta;
                            best = t;
                        }
                    }
                }
            }
        }

        // ③ 格式化输出
        char buf[8];
        snprintf(buf, sizeof(buf), "%02d:%02d", best / 60, best % 60);
        return string(buf);
    }
};
```

### Python

```python
class Solution:
    def nextClosestTime(self, time: str) -> str:
        # ① 起点分钟数 + 可用数字集合（跳过 ':'）
        start = int(time[:2]) * 60 + int(time[3:])
        digits = sorted({time[0], time[1], time[3], time[4]})

        # ② 四层枚举 HHMM，等价于对 digits 做 4 位回溯
        best, best_delta = -1, 1441
        for h1 in digits:
            for h2 in digits:
                hh = int(h1 + h2)
                if hh >= 24:                             # 剪枝
                    continue
                for m1 in digits:
                    for m2 in digits:
                        mm = int(m1 + m2)
                        if mm >= 60:                     # 剪枝
                            continue
                        cur = hh * 60 + mm
                        delta = (cur - start) % 1440 or 1440   # 0 -> 1440
                        if delta < best_delta:
                            best_delta, best = delta, cur

        # ③ 格式化输出
        return f"{best // 60:02d}:{best % 60:02d}"
```

## 8. 边界情况与易错点

1. **答案是次日同一时刻**：`"00:00"`、`"11:11"`、`"22:22"` 这类只有一种数字的输入，$\Delta$ 唯一取值 1440，输出与输入相同。若把 $\Delta = 0$ 直接 `continue`，`best` 会保持初值导致输出 `00:00` 或越界。
2. **不能选「更早」的时刻**：示例 1 里 19:33 合法但比 19:34 小，$\Delta = 1439$。本题的「最近」是**时间上向后**最近，不是数值上最接近。
3. **小时十位的 0**：`"05:23"` 的可用数字含 `0`，但 `"5:23"` 不是合法格式；必须按两位枚举，`hh = 5` 的十位就是 `0`。反过来 `"12:34"` 的 $D$ 不含 `0`，就不会生成任何以 0 开头的时刻。
4. **合法性过滤不能省**：组合域里存在 `"99:99"`、`"25:30"` 这类非法值，必须显式判 `hh < 24 && mm < 60`。这一点与逐分钟扫描不同——扫描靠分钟数范围天然规避，枚举组合则必须自查。
5. **`bestDelta` 初值**：取 1441（比最大可能值 1440 大 1）。若初值写成 1440，遇到「唯一候选是自己」（$\Delta = 1440$）时 `<` 判断不成立，`best` 永远不会被赋值，务必用 1441 或改用 `<=`。
6. **格式化补零**：`"9:5"` 是非法输出，必须 `%02d:%02d`；Python 的 `f"{0:02d}"` 得到 `"00"`，正好覆盖 `"00:00"` 这类答案。
