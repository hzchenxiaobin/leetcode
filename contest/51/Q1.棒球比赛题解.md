# LeetCode 棒球比赛 题解

## 1. 题目概述

- **标题 / 题号**：棒球比赛（#682，easy）
- **链接**：https://leetcode.cn/problems/baseball-game/
- **来源**：LeetCode 第 51 场周赛 Q1
- **难度**：简单
- **标签**：栈、数组、模拟

**题意**：维护一条得分「记录」，初始为空，按顺序处理每个操作：

- 整数 $x$：本回合新得 $x$ 分，追加到记录末尾；
- `"+"`：本回合得分为记录末两项之和，追加到末尾；
- `"D"`：本回合得分为末项的两倍，追加到末尾；
- `"C"`：末项作废，从记录中删除。

处理完全部操作后，返回记录中所有得分之和。数据保证 `"+"` 出现时记录至少有两项，`"C"` / `"D"` 出现时至少有一项，因此**无需做空栈判断**。

**约束**：

- $1 \le \lvert \text{operations} \rvert \le 1000$
- `operations[i]` 是 `"C"`、`"D"`、`"+"`，或一个表示 $[-3 \times 10^4,\, 3 \times 10^4]$ 内整数的字符串
- `"+"` 出现时记录中至少有两个有效分数；`"C"` / `"D"` 出现时至少有一个

## 2. 示例

**示例 1**

```text
输入：operations = ["5","2","C","D","+"]
输出：30
解释："5" → [5]
       "2" → [5, 2]
       "C" → [5]                （撤销 2）
       "D" → [5, 10]            （2 * 5）
       "+" → [5, 10, 15]        （5 + 10）
     总和 5 + 10 + 15 = 30
```

**示例 2**

```text
输入：operations = ["5","-2","4","C","D","9","+","+"]
输出：27
解释：记录依次为 [5] → [5,-2] → [5,-2,4] → [5,-2] → [5,-2,-4]
      → [5,-2,-4,9] → [5,-2,-4,9,5] → [5,-2,-4,9,5,14]
     总和 5 + (-2) + (-4) + 9 + 5 + 14 = 27
```

**示例 3**

```text
输入：operations = ["1"]
输出：1
解释：只有一个数字操作。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是把「记录」放在一个动态数组里，逐条执行四种操作，最后遍历数组求和。每一步要么追加、要么删除末尾元素，天然就是 $O(1)$ —— 这已经是正解，**本题没有需要优化的算法瓶颈**。

真正低效的写法是「每步都重建整条记录」：用 `vector::erase` 删中间元素、或每次 `"+"` 都从头重算前缀和，单步 $O(n)$、总体 $O(n^2)$。$n \le 1000$ 时 $10^6$ 次操作在 C++ 里也能勉强通过，但 Python 的列表中间删除是 $O(n)$ 的搬移，写起来还容易踩下标错误。

所以本题的「优化」不在于复杂度，而在于**选对容器**：既然四种操作只碰记录的**末尾 1～2 项**，那就该用**栈**（数组尾部当栈顶）来建模。

### 3.2 核心观察：记录天然是后进先出的

![四种操作只读写记录尾部，对应栈的 push/pop](images/wc51_q1_stack_model.svg)

把「记录」竖起来当栈看，四种操作全部落在栈顶一侧：

| 操作 | 语义 | 栈上的等价动作 |
|------|------|----------------|
| 整数 $x$ | 追加 $x$ | `push(x)` |
| `"+"` | 末两项之和 | `t1 = top`，`t2 = second`，`push(t1 + t2)` |
| `"D"` | 末项的两倍 | `push(2 * top)` |
| `"C"` | 末项作废 | `pop()` |

关键点有两处：

1. **`"C"` 撤销的永远是「最近一次」有效得分**——它不会去删中间某个分数。这正是栈「后进先出」的定义。
2. **`"D"` 与 `"+"` 只依赖最近的分数**——`"D"` 读栈顶，`"+"` 读栈顶与次栈顶，都不会访问更深处。

> 💡 一句话记忆：`C` 是撤销（undo），`D` 与 `+` 是「基于最近的得分派生新得分」。撤销只能撤销最近的一步，派生也只能派生最近的几步 —— 这两条性质一起把「记录」锁死成了栈。

### 3.3 算法流程

![一次遍历 + 四路分发的流程图](images/wc51_q1_branch_flow.svg)

```
st ← 空栈
for op in operations:
    if op == "C":   st.pop()                    # 撤销末项
    elif op == "D": st.push(2 * st.top())       # 先读栈顶，再压入
    elif op == "+": st.push(st.top1 + st.top2)  # 先读两个，再压入
    else:           st.push(int(op))            # 整数（可为负）
return sum(st)
```

分支判定顺序不影响正确性，因为四个 token 互不相同；但**「先读后压」的顺序很关键**：`"D"` 与 `"+"` 必须先把旧值读到临时变量里，再 `push` 新值，否则会把刚压入的新元素当成操作数。

### 3.4 示例演算

以示例 2 的 `operations = ["5","-2","4","C","D","9","+","+"]` 为例：

![示例 2 的逐步走查表](images/wc51_q1_walkthrough.svg)

| 步 | op | 动作 | 操作后的记录（栈底 → 栈顶） | 总和 |
|----|----|------|------------------------------|------|
| 1 | `5` | push 5 | $[5]$ | 5 |
| 2 | `-2` | push -2 | $[5, -2]$ | 3 |
| 3 | `4` | push 4 | $[5, -2, 4]$ | 7 |
| 4 | `C` | pop 4 | $[5, -2]$ | 3 |
| 5 | `D` | push $2 \times (-2) = -4$ | $[5, -2, -4]$ | -1 |
| 6 | `9` | push 9 | $[5, -2, -4, 9]$ | 8 |
| 7 | `+` | push $-4 + 9 = 5$ | $[5, -2, -4, 9, 5]$ | 13 |
| 8 | `+` | push $9 + 5 = 14$ | $[5, -2, -4, 9, 5, 14]$ | 27 |

第 4 步的 `"C"` 把第 3 步的 $4$ 撤掉，总和从 $7$ 回落到 $3$；第 5 步的 `"D"` 于是作用在 $-2$ 上得到 $-4$。若忘记撤销，第 5 步会算成 $2 \times 4 = 8$，最终结果完全错位 —— 这正是「必须真的删掉」而不是「打个标记跳过」的原因。

## 4. 算法细节

1. **token 分发方式**：`"C"`、`"D"`、`"+"` 三者都是长度为 1 的字符串，其余一律是整数（可能带负号，如 `"-2"`、长度 2）。因此正确的分发是「先与三个特殊串比较，剩下的都交给 `stoi` / `int()`」，**不要用 `isdigit(op[0])` 判断是否为数字**——`"-2"` 的首字符是 `-`，会被误判成特殊 token。
2. **`"D"` 的求值顺序**：必须写 `int t = st.back(); st.push_back(2 * t);`，或直接用右值 `st.push_back(2 * st.back())`（右侧先求值，安全）；若先 `push_back` 再改栈顶，读到的是新值，结果指数级跑飞。
3. **`"+"` 的求值顺序**：`st[st.size() - 1]` 是栈顶、`st[st.size() - 2]` 是次栈顶，两者之和 `push` 到末尾。**不要写成两个参数顺序颠倒后又在原地累加**，因为 `push_back` 可能触发扩容，任何指向旧缓冲区的引用/指针都会失效。
4. **负数与 `stoi`**：`std::stoi` 与 Python 的 `int()` 都能解析前导负号，无需自己处理符号；`"0"` 也是合法整数，不能被当成「空 token」跳过。
5. **总和可以边算边维护**：`push x` 时 `sum += x`，`"C"` 时先从栈顶取回被删的值再 `sum -= x`。这样最终不必再遍历一次栈；不过本题 $n \le 1000$，两种写法都是 $O(n)$，结尾 `sum(st)` 更不容易出错。
6. **数据保证合法，但防御性写法更好**：题面保证 `"C"` / `"D"` / `"+"` 出现时栈深足够，所以不必判空；如果要做防御，先判断 `st.size() >= 1`（或 `>= 2`）再操作。
7. **溢出风险**：连续 `"+"` 的得分是 Fibonacci 式增长（$\approx \varphi^n$），$n = 1000$ 时理论上会远远超过 `int` 甚至 `long long`。题面以 `int` 为返回值，意味着数据保证结果落在 `int` 范围内；实现时仍建议用 `long long` 累加总和，避免中间量的边界问题。Python 的整数无溢出问题。

## 5. 正确性证明

**引理 1（不变量：栈即记录）**：处理完第 $i$ 个操作后，栈 `st` 从底到顶的内容与题意中的「记录」逐项相同。

**证明**：对 $i$ 归纳。$i = 0$ 时记录为空、`st` 为空，成立。设处理完前 $i$ 个操作后二者相同，考察第 $i+1$ 个操作：

- 若为整数 $x$，题意为「追加 $x$」，算法 `push(x)`，两侧仍在末尾追加同一元素；
- 若为 `"D"`，题意为「追加末项的两倍」。因两侧末项相同（记为 $t$），算法压入 $2t$，与题意一致；
- 若为 `"+"`，题意为「追加末两项之和」。两侧末项、次末项分别相同（记为 $t_1, t_2$），算法压入 $t_1 + t_2$，一致；
- 若为 `"C"`，题意为「删除末项」。两侧非空且末项相同，算法 `pop()` 后两侧同步少一项。

四种情形下不变量均保持。∎

**引理 2（操作数取值正确）**：算法在 `"D"` / `"+"` 中读到的栈顶与次栈顶，正是「新得分压入之前」的记录末项与次末项。

**证明**：由引理 1，此刻栈与记录完全相同，故 `st.back()` 是记录末项、`st[size-2]` 是次末项。算法先读取这两个值、再执行 `push`，读取发生在修改之前，因此取值就是旧记录的值。∎

> 若把顺序写反（先 `push` 再读栈顶），读到的是刚压入的新值，引理 2 即失效——这也是唯一一处「顺序敏感」的地方。

**定理**：算法返回的值等于所有操作处理完后记录中所有得分之和。

**证明**：由引理 1，算法结束时栈与最终记录逐项相同；算法返回 `sum(st)`。由于相同的整数序列求和结果相同，返回值即记录中所有得分之和。∎

## 6. 复杂度分析

- **时间**：$O(n)$，$n = \lvert \text{operations} \rvert$。每个操作只做常数次栈操作（`push` / `pop` / 读栈顶两项）与一次整数解析；`push` 的均摊代价为 $O(1)$（`vector` 扩容按倍数增长，总额外搬移是线性的）。最后求和再花 $O(n)$，总量仍为 $O(n)$。
- **空间**：$O(n)$。栈最多保存 $n$ 个分数；`"C"` 只会让栈变浅，不会增加需求。若用「边算边维护总和」的写法，额外辅助空间是 $O(1)$，但栈本身仍是 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int calPoints(vector<string>& operations) {
        vector<int> st;
        st.reserve(operations.size());          // 最多 n 个分数，避免中途扩容
        for (const string& op : operations) {
            if (op == "C") {
                st.pop_back();                  // 撤销末项
            } else if (op == "D") {
                st.push_back(st.back() * 2);    // 先读旧栈顶，再压入
            } else if (op == "+") {
                int n = st.size();
                st.push_back(st[n - 1] + st[n - 2]);
            } else {
                st.push_back(stoi(op));         // 整数，可带负号
            }
        }
        long long sum = 0;
        for (int v : st) sum += v;
        return (int)sum;
    }
};
```

### Python

```python
class Solution:
    def calPoints(self, operations: list[str]) -> int:
        st: list[int] = []
        for op in operations:
            if op == "C":
                st.pop()                        # 撤销末项
            elif op == "D":
                st.append(2 * st[-1])           # 先读栈顶，再压入
            elif op == "+":
                st.append(st[-1] + st[-2])
            else:
                st.append(int(op))              # 整数，可带负号
        return sum(st)
```

## 8. 边界情况与易错点

1. **只有数字**：`["1"]` → `1`；`["5","2"]` → `7`。不要把「记录为空」当成非法输入提前报错。
2. **`"C"` 把记录清空**：`["5","C"]` → `0`；`["1","C"]` → `0`（官方 `exampleTestcases` 里就有这一组）。此时栈为空，返回 `sum([]) = 0`，不是 $-1$ 也不是空值。
3. **`"D"` 作用在负数上**：`["-3","D"]` → 记录 $[-3, -6]$，总和 $-9$。不能用 `abs`，也不能用左移 `<< 1`（对负数左移是未定义行为，且语义不同）。
4. **连续 `"+"`**：`["1","2","+","+"]` → $[1,2,3,5]$，总和 $11$。第二个 `"+"` 用的是刚压入的 $3$ 和 $2$，所以必须是真的压栈而不是「记住上一个和」。
5. **token 判定陷阱**：`"+"` / `"C"` / `"D"` 都是长度 1，但 `"-2"` 长度 2、`"0"` 是数字。判据必须是「与三个特殊串比较」，不能靠长度，也不能只看首字符是否 `isdigit`。
6. **`push` 后失效的引用**：C++ 中 `int& top = st.back(); st.push_back(...)` 之后 `top` 可能因扩容而悬空。要么先拷贝值，要么每条语句里重新 `st.back()`。
7. **总和类型**：极端构造下得分会 Fibonacci 式增长，用 `long long` 累加更稳妥；返回时再转 `int`（题目保证结果在 `int` 范围内）。

**延伸思考**：

1. 若把 `"+"` 改成「前三项之和」，单栈就不够了，需要额外维护最近 $k$ 项的滑动窗口或前缀和；$k$ 固定时仍可用「栈 + 环形缓冲」做到 $O(1)$ 每步。
2. 若 `"C"` 允许带下标（作废任意历史得分），撤销就不再是「后进先出」，单栈失效，需要双向链表 / 有序集合并配合树状数组维护总和 —— 这条思路与 [683. K 个关闭的灯泡](https://leetcode.cn/problems/k-empty-slots/) 里「按时间点亮 + 维护连续区间」的技巧同源。
3. 若要求返回「任意时刻的最大总和」而不仅是最终总和，只需在每次 `push` 后更新一个 `best` 变量，复杂度不变。
