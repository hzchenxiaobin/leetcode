# LeetCode 冗余连接 题解

## 1. 题目概述

- **标题 / 题号**：冗余连接（#684，medium）
- **链接**：https://leetcode.cn/problems/redundant-connection/
- **来源**：LeetCode 第 51 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、并查集、图

**题意**：树是连通且无环的无向图。现在有一棵 $n$ 个节点（编号 $1\sim n$）的树，被人**多加了一条边**，这条边的两个端点不同、都在 $1\sim n$ 之间，也不与原树中的任何一条边重复。图的信息按**加边顺序**记录在长度 $n$ 的 `edges` 中，`edges[i] = [ai, bi]`。请找出**一条**删掉之后剩下的图仍是 $n$ 节点树的边；如果有多条可选，返回在 `edges` 中**最后出现**的那一条。

**约束**：

- $n = \text{edges.length}$，$3 \le n \le 1000$
- $1 \le a_i < b_i \le n$，`ai != bi`
- `edges` 中没有重复的边，且给定的图连通

> 💡 关键词是**「最后出现」**：答案不是随便挑一条环边，而是所有合法答案里下标最大的那条。

## 2. 示例

**示例 1**

```text
输入：edges = [[1,2],[1,3],[2,3]]
输出：[2,3]
解释：三条边构成三角形 1-2-3-1。
      删 [2,3] 后剩 1-2、1-3，是 3 节点树；
      删 [1,2] 或 [1,3] 同样得到树，但 [2,3] 在输入中最后出现。
```

**示例 2**

```text
输入：edges = [[1,2],[2,3],[3,4],[1,4],[1,5]]
输出：[1,4]
解释：唯一环是 1-2-3-4-1，环边为 [1,2]、[2,3]、[3,4]、[1,4]，其中 [1,4] 最后出现；
      [1,5] 是挂在环外的树枝，删掉它图就不连通，不是答案。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**逐条试删**：对每个下标 $i$，把除 `edges[i]` 之外的 $n-1$ 条边建成邻接表，从节点 1 出发做一次 BFS/DFS 统计可达点数；若 $n$ 个点全部可达，则剩余的「$n$ 点、$n-1$ 边、连通」正是树。从后往前枚举，第一个成功的 $i$ 就是答案。

- 时间 $O(n^2)$：$n$ 次建图 + 遍历，每次 $O(n)$；空间 $O(n)$。
- 本题 $n \le 1000$，$10^6$ 量级其实能过，但它是「删完再验证」，完全没有利用「$n$ 点 $n$ 边只多一条」的结构。

另一种暴力是**增量 DFS**：依次把边加入邻接表，加入 $(u,v)$ 之前先判断 $u$ 能否到达 $v$，若能到达就说明这条边闭合了环。时间同样是 $O(n^2)$。

真正的关键是：不必「删完再检查」，而要在**加边的瞬间**判断这条边是不是多余的那条。

### 3.2 核心观察：唯一环上最后加入的边

![唯一环与冗余边](images/wc51_q3_cycle_concept.svg)

$n$ 个点、$n$ 条边且连通，由环空间维数（等价于欧拉公式的推论）

$$m - n + 1 = n - n + 1 = 1$$

可知图里**恰好有一个简单环**。取一棵生成树（$n-1$ 条边），剩下的那条边连接树上两个已连通的点，它把树上唯一的一条路径「补」成了环——这就是全部的环。

于是有两条互补的结论：

- **可删的边 = 环上的边**：删环边后图仍连通、边数为 $n-1$，必是树；删非环边（树枝）则图断开，不是树。
- **答案 = 环上最晚出现的那条边**：题目要求返回输入中最后出现的一条。

而「最晚出现」正好可以用**边加边判**实现：按输入顺序把边并进并查集，当某条边的两个端点**已经在同一个集合**里时，说明这条边闭合了环；它的下标大于环上其余所有边，所以它就是环上最晚的那条——立刻返回即可。

### 3.3 算法流程：并查集

![并查集流程](images/wc51_q3_dsu_flow.svg)

1. 初始化并查集 `parent[x] = x`（$x = 1..n$；节点编号从 1 开始，数组要开 $n+1$）。
2. 按输入顺序遍历 `edges` 中的每条边 $(a,b)$：
   - 求根 $r_a = \operatorname{find}(a)$、$r_b = \operatorname{find}(b)$；
   - 若 $r_a = r_b$：两端已连通，这条边闭合了唯一环，**返回** $[a,b]$；
   - 否则合并 $\text{parent}[r_a] = r_b$，继续下一条。
3. 题目保证输入合法，循环中一定会返回；函数末尾的空返回只是为了满足语言要求。

`find` 使用**路径压缩**（迭代写法 `parent[x] = parent[parent[x]]`，即隔代压缩）；`union` 直接挂根即可，若同时维护 `size` 按秩合并，可把树高严格压到 $O(\log n)$。

### 3.4 示例演算

![示例 1 演算表](images/wc51_q3_walkthrough.svg)

对示例 1 `edges = [[1,2],[1,3],[2,3]]`：

| 步骤 | 边 | 求根结果 | 动作 |
|------|----|----------|------|
| ① | [1,2] | 1、2 | 根不同，合并成 $\{1,2\}$ |
| ② | [1,3] | 1、3 | 根不同，合并成 $\{1,2,3\}$ |
| ③ | [2,3] | 1、1 | **根相同**，闭环 → 返回 [2,3] |

再看示例 2：前三条 [1,2]、[2,3]、[3,4] 依次合并成 $\{1,2,3,4\}$；第 4 条 [1,4] 两端已同根，直接返回 [1,4]；第 5 条 [1,5] 根本轮不到处理——这也说明「最后一条边」不一定是答案。

## 4. 算法细节

1. **下标从 1 开始**：`parent` 必须开 $n+1$ 并初始化 `parent[i] = i`；写成 $n$ 会导致 `parent[n]` 越界（尤其节点编号恰好是 $n$ 时）。
2. **先比较根、再合并**：必须取两个根后先判等，再决定合并；顺序颠倒会把闭环边当成普通合并，最终返回空数组。
3. **路径压缩用迭代**：$n \le 1000$ 递归不会爆栈，但迭代模板更通用：`while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }`。
4. **按秩合并可选**：本题规模小，直接 `parent[ra] = rb` 也能过；加上 `size` 数组后最坏树高 $O(\log n)$，与路径压缩叠加后均摊近似常数。
5. **返回原始边而不是根**：答案是 `[a, b]`，不是 `[ra, rb]`；题目保证 $a < b$，原样返回即与输入顺序一致。
6. **不要在循环里重建图**：每条边只做两次 `find`，整体 $O(n\,\alpha(n))$；若在循环里做 BFS 判定，复杂度会退化到 $O(n^2)$。

## 5. 正确性证明

**引理 1（图恰有一个环）**：$n$ 个节点、$n$ 条边的连通无向图恰好含一个简单环。

**证明**：取一棵生成树 $T$，它有 $n-1$ 条边，故恰有 1 条边 $e = (u,v) \notin T$。任何环不能全由 $T$ 的边组成（$T$ 无环），因此必含 $e$；而 $T$ 中 $u$ 到 $v$ 的路径唯一，去掉 $e$ 后环的其余部分只能是这条路径。故唯一环为「$T$ 上 $u$–$v$ 路径 $\cup\ \{e\}$」。∎

**引理 2（并查集不变量）**：处理完前 $i$ 条边后，$\operatorname{find}(x) = \operatorname{find}(y)$ 当且仅当 $x,y$ 仅用这 $i$ 条边就连通。

**证明**：对 $i$ 归纳。$i = 0$ 时每点自成一个集合，成立。设第 $i$ 条边为 $(a,b)$：若 $a,b$ 已同根则不合并，连通关系不变；否则把两个连通分量并成一个，恰好补上这条边带来的全部新连通关系。两种情形都保持不变量。∎

**引理 3（命中即环上最晚边）**：若第 $k$ 条边 $(a,b)$ 使 $\operatorname{find}(a) = \operatorname{find}(b)$，则 $(a,b)$ 是唯一环上在输入中下标最大的边。

**证明**：由引理 2，此时存在仅用前 $k-1$ 条边的 $a$–$b$ 路径 $P$，故 $P \cup \{(a,b)\}$ 是环，其所有边的下标 $\le k$，且只有 $(a,b)$ 达到 $k$、其余均 $< k$。由引理 1 环唯一，故 $(a,b)$ 正是该环上下标最大的边。∎

**定理**：算法返回的边删去后，剩余图是一棵 $n$ 节点树，且它是所有合法答案中在 `edges` 里最后出现的一条。

**证明**：设算法返回 `edges[k]`。由引理 3，它是唯一环上下标最大的边。删去它后图仍连通：任何用到该边的路径都可用引理 2 给出的、只含前 $k-1$ 条边的 $a$–$b$ 路径 $P$ 替代。于是剩余图有 $n$ 个点、$n-1$ 条边且连通，必是树，合法性成立。

反之，若删去的是非环边，由「唯一环」知它不属于任何环，是桥，删后图断开，不可能得到树；所以合法答案恰为环上各边，其中下标最大者就是 `edges[k]`。∎

## 6. 复杂度分析

- **时间**：$O(n\,\alpha(n))$。每条边执行两次 `find` 和至多一次合并，路径压缩下并查集操作均摊 $O(\alpha(n))$，共处理至多 $n$ 条边。
- **空间**：$O(n)$。`parent` 数组占 $n+1$ 个整数；若加上按秩合并的 `size` 数组，仍是 $O(n)$，与边数同阶。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <numeric>
#include <functional>
using namespace std;

class Solution {
public:
    vector<int> findRedundantConnection(vector<vector<int>>& edges) {
        int n = (int)edges.size();
        vector<int> parent(n + 1);
        iota(parent.begin(), parent.end(), 0);   // 节点 1..n，各自成集合

        function<int(int)> find = [&](int x) -> int {
            while (parent[x] != x) {
                parent[x] = parent[parent[x]];   // 路径压缩（隔代）
                x = parent[x];
            }
            return x;
        };

        for (auto& e : edges) {
            int ra = find(e[0]), rb = find(e[1]);
            if (ra == rb) return e;              // 两端已连通：这条边闭合了唯一环
            parent[ra] = rb;                     // 合并两个集合
        }
        return {};                               // 合法输入不会走到这里
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findRedundantConnection(self, edges: List[List[int]]) -> List[int]:
        n = len(edges)
        parent = list(range(n + 1))               # 节点 1..n，各自成集合

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]     # 路径压缩（隔代）
                x = parent[x]
            return x

        for a, b in edges:
            ra, rb = find(a), find(b)
            if ra == rb:
                return [a, b]                     # 根相同 → 冗余边
            parent[ra] = rb                       # 合并两个集合
        return []
```

## 8. 边界情况与易错点

1. **不能直接返回最后一条边**：示例 2 的最后一条 [1,5] 是树枝，删掉图就断开；必须返回「闭合环」的那条。
2. **节点编号是 1-based**：`parent` 开 $n+1$、初始化 `range(n+1)`；写成 $n$ 且用 `parent[b]` 会越界。
3. **最小规模 $n=3$**：三角形 `[[1,2],[2,3],[1,3]]` 应返回 `[1,3]`（最后一条），而不是 `[1,2]`。
4. **`a < b` 已由输入保证**：不要自行排序或交换，原样返回 `[a, b]` 才与输入顺序一致。
5. **必须「先比较根、后合并」**：顺序写反会把闭环边当普通边合并掉，循环结束后只能返回空。
6. **合并要挂在根上**：`parent[ra] = rb` 而不是 `parent[a] = b`，否则多级树上的节点会脱离集合，`find` 结果失真。
