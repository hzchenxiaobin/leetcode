# LeetCode K 个关闭的灯泡 题解

## 1. 题目概述

- **标题 / 题号**：K 个关闭的灯泡（#683，hard）
- **链接**：https://leetcode.cn/problems/k-empty-slots/
- **来源**：LeetCode 第 51 场周赛 Q4
- **难度**：困难
- **标签**：数组、滑动窗口、单调队列、有序集合、树状数组、线段树、堆（优先队列）

**题意**：一行 $N$ 个灯泡，编号 $1 \sim N$，初始全灭。`bulbs[i] = x` 表示第 $i+1$ 天点亮位置 $x$（`bulbs` 是 $1 \sim N$ 的排列，即每天恰好点亮一盏）。求**最小**的天数 $d$，使得第 $d$ 天结束时存在两盏亮着的灯泡，它们之间**恰好**有 $K$ 个位置、且这些位置全灭；若不存在则返回 $-1$。

**约束**：

- $1 \le N \le 20000$
- $1 \le \text{bulbs}[i] \le N$，且 `bulbs` 是 $1 \sim N$ 的全排列
- $0 \le K \le 20000$，因此 $K + 1 \ge N$ 时必须返回 $-1$

## 2. 示例

**示例 1**

```text
输入：bulbs = [1,3,2]，K = 1
输出：2
解释：第 1 天点亮位置 1 → [1,0,0]
      第 2 天点亮位置 3 → [1,0,1]，位置 1 与 3 之间恰有 1 个灭灯 ✓
      第 3 天点亮位置 2 → [1,1,1]
      故答案为 2。
```

**示例 2**

```text
输入：bulbs = [1,2,3]，K = 1
输出：-1
解释：第 2 天亮起的位置 1、2 相邻（0 个间隔）；
      第 3 天全部亮起，中间已不存在「全灭」的位置，无解。
```

**示例 3（自测补充，$K = 0$）**

```text
输入：bulbs = [2,3,1]，K = 0
输出：2
解释：第 1 天只有位置 2 亮；第 2 天位置 3 也亮，二者相邻、中间 0 个灭灯，满足 K = 0。
```

## 3. 解题思路

### 3.1 暴力思路

按天模拟：维护布尔数组 `on[x]`，第 $d$ 天点亮 `bulbs[d-1]`，然后枚举所有窗口 $[i,\ i+K+1]$，检查两端是否都亮、中间是否全灭。

估算一下：若每天都重算前缀和判断区间和，单次 $O(n)$、总计 $O(n^2) \approx 4 \times 10^8$；若逐格检查中间 $K$ 个位置，最坏 $O(nK)$，同样是 $4 \times 10^8$ 量级且常数更大——C++ 勉强，Python 必然超时。

瓶颈在于「按天」这个维度被浪费了：每天只改变一盏灯，我们却每天重扫一遍数组。

### 3.2 核心观察：时间与位置对偶

![时间与位置对偶](images/wc51_q4_days_dual.svg)

把「第几天亮」这个信息记录到位置上，定义

$$\text{days}[x] = \text{位置 } x \text{ 被点亮的天数（1-indexed）}$$

一次 $O(n)$ 扫描即可建好：`days[bulbs[t] - 1] = t + 1`。

接着把「第 $d$ 天存在合法灯泡对」翻译成 `days` 上的条件。设候选窗口为 $(i, j)$，其中 $j = i + K + 1$：

- 两端在第 $d$ 天都亮 $\iff d \ge \max(\text{days}[i],\ \text{days}[j])$；
- 中间位置 $m$（$i < m < j$）在第 $d$ 天仍灭 $\iff \text{days}[m] > d$。

所以窗口 $(i,j)$ **首次合法**的天数只能是 $d_0 = \max(\text{days}[i], \text{days}[j])$（更早则端点没亮），而它合法的充要条件正是

$$\min_{i < m < j} \text{days}[m] > \max(\text{days}[i],\ \text{days}[j])$$

于是原问题变成一句纯静态查询：

> 在 `days` 的全部长度 $K+2$ 的连续窗口里，挑出满足上式的窗口，最小化 $\max(\text{days}[i],\text{days}[j])$。

「滑动窗口求最小值」是单调队列的模板场景，于是得到 $O(n)$ 解法。

### 3.3 算法流程：单调队列滑窗

![滑动窗口与单调队列](images/wc51_q4_window_scan.svg)

1. 由 `bulbs` 构造 `days`（0-indexed 位置）。
2. **$K = 0$ 特判**：内部为空，任意相邻两盏亮灯即合法，答案 $=\min_i \max(\text{days}[i], \text{days}[i+1])$。
3. **$K \ge 1$**：令 $j$ 从 $1$ 扫到 $n-1$，用单调递增队列（存下标）维护窗口 $[j-K,\ j-1]$ 的最小值：
   - 入队 $x = j-1$：先从队尾弹出所有 $\text{days}[\cdot] \ge \text{days}[x]$ 的下标，再把 $x$ 压入；
   - 从队首弹出 $< j-K$ 的过期下标；
   - 令 $i = j-K-1$，若 $i \ge 0$ 且 $\text{days}[\text{队首}] > \max(\text{days}[i],\text{days}[j])$，则用 $\max(\text{days}[i],\text{days}[j])$ 更新答案。
4. 全程未更新答案则返回 $-1$。

### 3.4 示例演算

取 `bulbs = [3,1,5,2,4,6]`、$K = 1$：$\text{days} = [2,4,1,5,3,6]$，窗口长度 $K+2 = 3$。

![示例演算走查表](images/wc51_q4_walkthrough.svg)

| 窗口 $(i \to j)$ | 内部 $\min$ | 两端 $\max$ | 判定 | 答案 |
|---|---|---|---|---|
| $1 \to 3$ | $4$ | $2$ | $4 > 2$ ✓ | $2$ |
| $2 \to 4$ | $1$ | $5$ | $1 \le 5$ ✗ | $2$ |
| $3 \to 5$ | $5$ | $3$ | $5 > 3$ ✓ | $\min(2,3)=2$ |
| $4 \to 6$ | $3$ | $6$ | $3 \le 6$ ✗ | $2$ |

答案为 $2$：第 2 天位置 $1$、$3$ 已亮（$\text{days}[1]=2,\ \text{days}[3]=1$），而位置 $2$ 要到第 4 天才亮，中间恰好 $1$ 个关闭灯泡。

官方示例 1 的 $\text{days} = [1,3,2]$ 只有唯一窗口 $(1,3)$：$\min(3)=3>\max(1,2)=2$，答案同样是 $2$。

## 4. 算法细节

1. **下标换算**：`days` 用 0-indexed 位置，`days[bulbs[t]-1] = t+1`；窗口端点 $i, j$ 是位置下标，而「天数」始终从 $1$ 开始。
2. **循环起点必须是 $j = 1$**：窗口 $[j-K,\ j-1]$ 需要逐个元素「长满」，若直接从 $j = K+1$ 开始，队里只有下标 $K$ 一个元素，窗口左半部分从未进队，队首就成了假最小值。本文验证阶段正是这个 bug 在 600 组随机对拍里被翻了出来；$i < 0$ 时跳过判定即可。
3. **$K = 0$ 必须单独处理**：内部窗口为空，队列会在「弹出 $< j-K$」这一步把刚压入的元素弹空，`队首` 无定义，单独走「相邻两灯」分支最稳妥。
4. **严格性无关正确性**：弹尾用 `>=` 或 `>` 结果相同；用 `>=` 时等值保留更靠后的下标，滑出更晚，队列更短，是常用写法。
5. **哨兵值**：答案最大为 $n$（最后一盏灯才凑成一对），用 $n+1$ 或 `INT_MAX` 均可，但要保证「从未更新」能被识别为无解。
6. **窗口放不下**：$K+2 > n$ 时 $i = j-K-1 < 0$ 恒成立，循环自然不会更新答案；显式写 `if (n < K + 2) return -1;` 可以省去无意义的循环。
7. **等价的替代做法**：
   - **有序集合**（`TreeSet` / `SortedList` / 手写平衡树）：按天插入位置，每次检查新位置的**前驱**与**后继**是否恰好相距 $K+1$；若相等则中间必全灭，第一次命中的天即答案，$O(n \log n)$。
   - **树状数组 / 线段树**维护「亮 / 灭」，二分定位可行窗口，$O(n \log^2 n)$；$n \le 2\times 10^4$ 时上述做法都能通过，但只有单调队列是 $O(n)$。

## 5. 正确性证明

**引理 1（窗口判定）**：对固定窗口 $(i, j)$（$j = i + K + 1$），记 $d^*(i,j) = \max(\text{days}[i], \text{days}[j])$，则

$$(i,j) \text{ 在第 } d \text{ 天合法} \iff d \ge d^* \ \text{且}\ \min_{i<m<j}\text{days}[m] > d$$

从而它首次合法的天数就是 $d^*$，且其合法的充要条件为 $\min_{i<m<j}\text{days}[m] > d^*$。

**证明**：位置 $x$ 在第 $d$ 天亮 $\iff \text{days}[x] \le d$。故两端都亮 $\iff d \ge \max(\text{days}[i],\text{days}[j]) = d^*$；中间位置 $m$ 仍灭 $\iff \text{days}[m] > d$，对全部 $m$ 成立即 $\min > d$，即 $d < \min$。于是最小的可行 $d$ 为 $d^*$：若 $\min > d^*$ 则 $d^*$ 自身合法；若 $\min \le d^*$，则任意 $d \ge d^*$ 都有 $\min \le d$，中间至少一盏已亮，永不合法。∎

**引理 2（不重不漏）**：题面要求的每一对合法亮灯位置，与长度 $K+2$ 的窗口一一对应。

**证明**：设第 $d$ 天位置 $a < b$ 都亮且中间恰有 $K$ 个位置全灭，则中间位置数为 $b-a-1 = K$，即 $b = a+K+1$，窗口 $(a,b)$ 唯一确定；反之任一窗口的两端就是一对相距 $K+1$ 的位置。∎

**引理 3（单调队列不变量）**：第 $j$ 轮判定时，队首下标等于 $\arg\min\limits_{j-K \le t \le j-1}\text{days}[t]$。

**证明**：队内下标严格递增、`days` 值严格递增。压入 $x$ 前弹掉所有 $\text{days} \ge \text{days}[x]$ 的尾部元素：这些下标既不会更小、又更早过期，被 $x$ 完全支配，删去不影响任何一轮的最小值，且保持单调性；弹出 $< j-K$ 的下标正好删去滑出窗口者。故队首即窗口内最小者。∎

**定理**：算法输出等于题目所求的最小天数；若不存在合法灯泡对，输出 $-1$。

**证明**：由引理 2，候选窗口与合法灯泡对一一对应；由引理 1，每个窗口的代价为 $d^*$，且合法性与 $\min > d^*$ 等价；由引理 3，算法判定时使用的正是窗口内真实最小值，因此每个窗口被精确判定恰好一次，`ans` 取遍所有合法窗口的代价后即为最小值。若没有任何窗口合法，`ans` 保持哨兵，返回 $-1$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。构造 `days` 为 $O(n)$；单调队列中每个下标至多入队一次、出队一次，均摊 $O(1)$；$K=0$ 分支是一次线性扫描。总计 $O(n)$，$n = 2\times10^4$ 时仅数万次操作（实测 Python 单次调用约 8 ms）。
- **空间**：$O(n)$。`days` 数组占 $n$ 个整数；单调队列最多同时保存 $K$ 个下标（$K < n$）。除此之外没有额外分配。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <deque>
#include <algorithm>
using namespace std;

class Solution {
public:
    int kEmptySlots(vector<int>& bulbs, int k) {
        int n = bulbs.size();
        vector<int> days(n);
        for (int t = 0; t < n; ++t) days[bulbs[t] - 1] = t + 1;   // 位置 -> 点亮天数

        const int INF = 1e9;
        int ans = INF;

        if (k == 0) {                       // 内部为空：任意相邻两盏亮灯即可
            for (int i = 0; i + 1 < n; ++i) ans = min(ans, max(days[i], days[i + 1]));
            return ans == INF ? -1 : ans;
        }
        if (n < k + 2) return -1;           // 窗口都放不下

        deque<int> dq;                      // 单调递增队列，队首为窗口最小值的下标
        for (int j = 1; j < n; ++j) {
            int x = j - 1;                  // 新元素进入内部窗口
            while (!dq.empty() && days[dq.back()] >= days[x]) dq.pop_back();
            dq.push_back(x);
            while (dq.front() < j - k) dq.pop_front();   // 滑出窗口的下标

            int i = j - k - 1;              // 候选窗口左端
            if (i < 0) continue;
            int need = max(days[i], days[j]);
            if (days[dq.front()] > need) ans = min(ans, need);
        }
        return ans == INF ? -1 : ans;
    }
};
```

### Python

```python
from typing import List
from collections import deque


class Solution:
    def kEmptySlots(self, bulbs: List[int], k: int) -> int:
        n = len(bulbs)
        days = [0] * n
        for t, x in enumerate(bulbs):
            days[x - 1] = t + 1             # 位置 x 在第 t+1 天亮

        INF = float('inf')
        ans = INF

        if k == 0:                          # 内部为空：相邻两盏亮灯即可
            for i in range(n - 1):
                ans = min(ans, max(days[i], days[i + 1]))
            return -1 if ans == INF else ans

        if n < k + 2:                       # 窗口都放不下
            return -1

        dq = deque()                        # 单调递增队列，队首为窗口最小值的下标
        for j in range(1, n):
            x = j - 1
            while dq and days[dq[-1]] >= days[x]:
                dq.pop()
            dq.append(x)
            while dq[0] < j - k:            # 滑出窗口的下标
                dq.popleft()

            i = j - k - 1                   # 候选窗口左端
            if i < 0:
                continue
            need = max(days[i], days[j])
            if days[dq[0]] > need:
                ans = min(ans, need)

        return -1 if ans == INF else ans
```

## 8. 边界情况与易错点

1. **$K = 0$**：内部窗口为空，`min` 应视为 $+\infty$，任意相邻两盏亮灯都合法。若走统一的单调队列分支，刚入队就被「弹出过期下标」清空，`dq[0]` 直接越界——必须单独处理。
2. **$N = 1$**：只有一盏灯，永远凑不出一对，返回 $-1$；$K=0$ 分支中 `range(n-1)` 为空，`ans` 保持哨兵，同样返回 $-1$。
3. **$K + 1 \ge N$**：例如 $N = 3,\ K = 5$，窗口长度 $K+2 = 7 > N$，无候选窗口，返回 $-1$。
4. **循环起点写成 $j = K+1$**：最隐蔽的错误。此时队列尚未收纳 $[j-K,\ j-1]$ 的全部元素，队首是「假最小值」，会给出偏小的错误答案（本文验证阶段实现复现过，600 组随机对拍立刻抓出）。
5. **`days` 与位置下标的 1-indexed / 0-indexed 混用**：`days[x-1] = 天`，而判定中的 $i, j$ 都是 0-indexed 位置，二者只差一次平移；混淆会得到错开一格、语义完全不同的窗口。
6. **答案是 $n$ 的情形**：最后一盏灯在第 $n$ 天点亮，`ans` 可能取到 $n$，哨兵要用 $n+1$ 或 `INT_MAX`，不能用 $0$ / $-1$ 初始化。
7. **`bulbs` 是排列**：因此可以放心用「位置 → 天数」的数组映射，不必担心重复点亮或漏点；若题目改成可能重复，这个映射立刻失效。

**延伸思考**：

- 若把「恰好 $K$ 个关闭灯泡」改成「**至少** $K$ 个」，两端距离不再固定，窗口假设失效；此时应维护「亮灯位置」的有序集合，在每次插入时检查与左右邻居的距离是否 $\ge K+1$，第一次出现即为答案——本质仍是引理 2 的推广。
- 若同一天可以点亮多盏灯（按批给出、允许重复位置），「按位置预处理天数」不再成立，必须回到「按时间插入 + 有序集合查前驱后继」，$O(n\log n)$ 成为自然选择。
- 若要求返回**所有**满足条件的天数，则不能只保留最小值，而要枚举全部窗口并按代价去重；若 $N$ 放大到 $10^6$，$O(n)$ 时间仍可接受，但 `days` 与队列合计约 $2n$ 个整数，需要留意内存预算。
