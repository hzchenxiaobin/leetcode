# LeetCode 负二进制转换 题解

## 1. 题目概述

- **标题 / 题号**：负二进制转换（#1017，medium）
- **链接**：https://leetcode.cn/problems/convert-to-base-2/
- **来源**：LeetCode 第 130 场周赛 Q2
- **难度**：中等
- **标签**：数学、进制转换

**题意**：给定非负整数 $n$，返回它的**负二进制**（基为 $-2$）表示字符串，要求：

- 字符串只含 `0` 与 `1`；
- 除 $n = 0$ 时返回 `"0"` 外，不能有前导零；
- 若把字符串从低位到高位记为 $d_0, d_1, \dots, d_{m}$，则

$$n = \sum_{k=0}^{m} d_k \cdot (-2)^{k}$$

**约束**：

- $0 \le n \le 10^9$

> 💡 与普通二进制最大的区别：**基数带负号**，所以「按位取余、右移」这套流程不再直接成立，取余必须取**数学意义上的非负余数**。

## 2. 示例

**示例 1**

```text
输入：n = 2
输出："110"
解释：1*(-2)^2 + 1*(-2)^1 + 0*(-2)^0 = 4 - 2 + 0 = 2。
```

**示例 2**

```text
输入：n = 3
输出："111"
解释：4 - 2 + 1 = 3。
```

**示例 3**

```text
输入：n = 4
输出："100"
解释：(-2)^2 = 4，其余位为 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的是枚举：按长度从小到大枚举所有 `01` 串，逐个用 $(-2)$ 的多项式求值，找到等于 $n$ 的最短串。

长度上限约 $31$（$2^{30} > 10^9$），候选串有 $\sum_{k \le 31} 2^k \approx 2^{32}$ 个，完全不可行。即使剪枝，也无法在时限内完成。

### 3.2 核心观察：带余除法在负基数下依然成立

![负基数的逐位取余：n = q·(-2) + r，r ∈ {0,1}](images/wc130_q2_division_concept.svg)

**带余除法定理**对任意基数 $b \ne 0$ 都成立：存在唯一的一对 $(q, r)$ 使

$$n = q \cdot b + r, \qquad 0 \le r < |b|$$

取 $b = -2$、$|b| = 2$，则 $r \in \{0, 1\}$ 正好是一个合法的负二进制**最低位**，而商 $q$ 是「剩下的高位部分」在负二进制下的值。于是有恒等式

$$n = q \cdot (-2) + r \iff q = \frac{n - r}{-2}$$

它把规模为 $n$ 的问题**缩小**为规模为 $q$ 的同一个问题——典型的递归/迭代结构。

两个必须注意的点：

1. **余数必须非负**。C++ 的 `%` 对负数向零取整，例如 `(-1) % 2 == -1`，此时 $r \notin \{0,1\}$，必须修正为 `r += 2`，同时商也要跟着变成 $(n - r) / (-2)$。
2. **$q$ 的绝对值严格小于 $|n|$（$|n| \ge 2$ 时）**，因此过程必然终止。验证：$|q| = |n - r| / 2$，当 $|n| \ge 2$ 时 $|n - r| \le |n| + 1 \le \tfrac{3}{2}|n|$，故 $|q| \le \tfrac{3}{4}|n| < |n|$；边界 $n = \pm 1$ 时 $q \in \{0, 1\}$，下一轮即归零。

> 💡 直觉：负基数下，高位权值在正负之间交替，但**带余除法的代数结构不受影响**。我们不是在「移位」，而是在做「除以 $-2$ 取余」。

### 3.3 算法流程

![算法流程：反复取非负余数、除以 -2](images/wc130_q2_flow.svg)

```text
1. 若 n == 0: 返回 "0"
2. digits = []
3. while n != 0:
       r = n mod 2            # 数学意义上的非负余数，r ∈ {0,1}
       digits 追加 r
       n = (n - r) / (-2)     # 精确整除，新商
4. 反转 digits，拼成字符串返回
```

### 3.4 示例演算

![示例演算：n = 2 的两次取余](images/wc130_q2_walkthrough.svg)

以 $n = 2$ 为例：

| 轮次 | 当前 $n$ | $r = n \bmod 2$ | 新 $q = (n-r)/(-2)$ | 已得低位（从低到高） |
|---|---|---|---|---|
| 1 | 2 | 0 | $(2-0)/(-2) = -1$ | `0` |
| 2 | -1 | 1 | $(-1-1)/(-2) = 1$ | `0`,`1` |
| 3 | 1 | 1 | $(1-1)/(-2) = 0$ | `0`,`1`,`1` |

第 3 轮后 $n = 0$，反转得到 `"110"`，验证 $4 - 2 = 2$ ✓。

再以 $n = 3$：$3 \to r=1, q=-1$；$-1 \to r=1, q=1$；$1 \to r=1, q=0$，反转得 `"111"` ✓。

## 4. 算法细节

1. **C++ 的负数取模**：`n % 2` 在 `n < 0` 时可能为 $-1$，必须 `if (r < 0) r += 2;`。也可以直接用位运算 `r = n & 1`（补码下对负数同样给出 $0/1$），但为了可读性，显式修正更稳妥。
2. **商的精确性**：$(n - r)$ 一定是 $-2$ 的倍数（因为 $r \equiv n \pmod 2$ 且 $-2$ 与 $2$ 只差符号），所以整数除法不会丢精度；C++ 的 `/` 与 Python 的 `//` 在此都等于精确商。
3. **Python 的 `%` 已经满足要求**：Python 的取模结果与除数同号，$n \bmod 2 \in \{0,1\}$ 天然成立，直接写 `n % 2` 即可；商用 `(n - r) // -2` 或等价写法。
4. **数字位数**：$n \le 10^9 < 2^{30}$，负二进制位数不超过 $31$，字符拼接开销极小。
5. **前导零**：由于我们用「先收集低位、最后反转」，最高位一定是最后一次循环得到的 $r$，它对应当前 $n \ne 0$，故首位必为 1（除非 $n=0$ 的特判），天然无前导零。
6. **不要试图用 `bitset` 或原码技巧**：负基数没有「取反对应」的简单形式，老老实实做除法最稳。

## 5. 正确性证明

**引理 1（带余除法的存在唯一性）**：对任意整数 $n$ 与 $b = -2$，存在唯一的整数对 $(q, r)$ 满足 $n = qb + r$ 且 $0 \le r < 2$。

**证明**：存在性：取 $r = n \bmod 2$（非负最小剩余，$r \in \{0,1\}$），则 $r \equiv n \pmod 2$，故 $n - r$ 可被 2 整除，令 $q = (n-r)/(-2)$ 为整数，即得 $n = qb + r$。唯一性：若 $n = q_1 b + r_1 = q_2 b + r_2$ 且 $r_1, r_2 \in \{0,1\}$，则 $(q_1 - q_2)b = r_2 - r_1$。右边绝对值 $\le 1 < |b| = 2$，故只能是 $r_1 = r_2$，进而 $q_1 = q_2$。∎

**引理 2（终止性）**：算法至多经过 $O(\log |n|)$ 轮循环后 $n = 0$。

**证明**：每轮把 $n$ 更新为 $q = (n-r)/(-2)$。当 $|n| \ge 2$ 时

$$|q| = \frac{|n - r|}{2} \le \frac{|n| + 1}{2} \le \frac{3}{4}|n| < |n|$$

（第二个不等号用到 $|n| \ge 2 \Rightarrow |n| + 1 \le \tfrac{3}{2}|n|$）。当 $n = \pm 1$ 时：$n = 1 \Rightarrow r = 1, q = 0$；$n = -1 \Rightarrow r = 1, q = 1$，下一轮 $n = 1 \Rightarrow q = 0$。因此每两轮 $|n|$ 至少缩小到 $\tfrac{3}{4}$，循环必然终止。∎

**引理 3（结果正确）**：若算法输出串为 $d_m d_{m-1} \cdots d_0$（$d_m$ 为最高位），则 $\sum_{k=0}^{m} d_k (-2)^k = n$ 成立。

**证明**：设循环第 $t$ 轮开始时的值为 $n_t$，产生余数 $r_t = d_t$，并令 $n_{t+1} = (n_t - r_t)/(-2)$，即 $n_t = n_{t+1} \cdot (-2) + d_t$。设共 $L$ 轮，$n_L = 0$。对 $t$ 从 $L-1$ 递推回 $0$：

$$n_0 = n_1(-2) + d_0 = \bigl(n_2(-2) + d_1\bigr)(-2) + d_0 = \cdots = \sum_{t=0}^{L-1} d_t (-2)^t + n_L (-2)^L = \sum_{t=0}^{L-1} d_t (-2)^t$$

而输出串反转后第 $t$ 位（从低位数）正是 $d_t$。∎

**定理**：算法输出 $n$ 的合法负二进制表示（无前导零，$n = 0$ 时输出 `"0"`）。

**证明**：数值正确性由引理 3；终止性由引理 2；由引理 1，$r_t \in \{0,1\}$，故串只含 `0`/`1`；最高位 $d_{L-1}$ 是最后一次循环的余数，此时 $n_{L-1} \ne 0$，若 $d_{L-1} = 0$ 则 $n_{L-1}$ 为偶数、$n_L = n_{L-1}/(-2) \ne 0$，与「最后一轮」矛盾，故 $d_{L-1} = 1$，无前导零。$n = 0$ 由特判直接返回 `"0"`。∎

## 6. 复杂度分析

- **时间**：$O(\log |n|)$。每轮 $O(1)$，轮数不超过 $31$（$n \le 10^9$），最后反转字符串也是 $O(\log |n|)$。
- **空间**：$O(\log |n|)$，用于存位数列表；若直接头插或用 `reverse` 复用同一容器，额外空间仍是位数级别。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string baseNeg2(int n) {
        if (n == 0) return "0";
        string s;
        while (n != 0) {
            int r = n % 2;              // C++ 负数取模可能为 -1
            if (r < 0) r += 2;          // 修正为数学意义上的非负余数
            s.push_back(char('0' + r));
            n = (n - r) / -2;           // 精确整除
        }
        reverse(s.begin(), s.end());
        return s;
    }
};
```

### Python

```python
class Solution:
    def baseNeg2(self, n: int) -> str:
        if n == 0:
            return "0"
        digits = []
        while n != 0:
            r = n % 2                   # Python 取模结果非负，天然在 {0,1}
            digits.append(str(r))
            n = (n - r) // -2           # 精确整除，等价于 n // -2
        return "".join(reversed(digits))
```

## 8. 边界情况与易错点

1. **$n = 0$**：必须返回 `"0"`，不能返回空串——循环一次都不执行，忘特判就出错。
2. **C++ 负数取模**：`-1 % 2 == -1`，直接当余数用会得到非法字符（`'0' + (-1)`）。这是本题最常见的 WA。
3. **商的写法**：必须写 `(n - r) / -2`，不能写 `n / -2` 再单独算余数——后者在负数上会导致 商与余数不自洽。
4. **Python 的 `//` 与 C++ 的 `/`**：两者对负数向下/向零取整不同，但这里 `n - r` 恰为 $-2$ 的整数倍，除法无余数，二者结果一致，可以放心使用。
5. **前导零**：不要用 `string(32, '0')` 之类的定长缓冲后裁零，容易漏裁；用「收集 + 反转」天然无前导零。
6. **上界**：$n$ 最大 $10^9$，位数约 $31$，`int` 在迭代中可能变成负数，注意 `while (n != 0)` 而不是 `while (n > 0)`。
