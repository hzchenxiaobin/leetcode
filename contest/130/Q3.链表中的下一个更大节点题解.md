# LeetCode 链表中的下一个更大节点 题解

## 1. 题目概述

- **标题 / 题号**：链表中的下一个更大节点（#1019，medium）
- **链接**：https://leetcode.cn/problems/next-greater-node-in-linked-list/
- **来源**：LeetCode 第 130 场周赛 Q3
- **难度**：中等
- **标签**：链表、单调栈、数组

**题意**：给定一个长度为 $n$ 的单链表 `head`。对每个节点 $i$（从 1 开始编号），找到它**右边第一个严格大于**它自身值的节点，把该节点的值写入 `answer[i-1]`；若不存在这样的节点，则写 0。

形式化地，设链表值序列为 $a_0, a_1, \dots, a_{n-1}$，则

$$answer[i] = \begin{cases} a_j, & j = \min\{\, j > i : a_j > a_i \,\} \text{ 存在} \\ 0, & \text{否则} \end{cases}$$

**约束**：

- 节点数 $1 \le n \le 10^4$
- $1 \le Node.val \le 10^9$

> 💡 输入是**链表**而不是数组：不能随机访问，但可以花 $O(n)$ 先把它读成数组，再套用数组上的单调栈模板。

## 2. 示例

**示例 1**

```text
输入：head = [2,1,5]
输出：[5,5,0]
解释：2 的下一个更大值是 5；1 的下一个更大值是 5；5 右侧没有更大的节点，记 0。
```

**示例 2**

```text
输入：head = [2,7,4,3,5]
输出：[7,0,5,5,0]
解释：2 → 7；7 右侧没有更大的；4 → 5；3 → 5；5 后面没有节点。
```

**示例 3（自造，覆盖相等值）**

```text
输入：head = [3,3,4]
输出：[4,4,0]
解释：题目要求「严格大于」，第一个 3 的下一个更大值是 4（跳过相等的第二个 3）。
```

## 3. 解题思路

### 3.1 暴力思路

对每个节点，从它的后继开始一路向后扫，找到第一个更大的值。

最坏情况（链表严格递减，如 `[5,4,3,2,1]`）每个节点都要扫到末尾，总比较次数 $\sum_{i} (n-i) = O(n^2)$。$n = 10^4$ 时约 $5 \times 10^7$ 次比较，勉强能过但很浪费；若 $n$ 提升到 $10^5$ 就必然超时。

### 3.2 核心观察：单调栈保存「等待答案」的下标

![单调栈：栈内值单调不增，遇到更大值时连环结算](images/wc130_q3_monotonic_stack.svg)

换一个视角：不要「每个节点向后找」，而是「**每个值向前结算**」。

从左到右扫描，维护一个栈，栈里存的是**尚未找到答案的下标**。可以验证（见 §5 引理 1）：栈内下标对应的值**单调不增**。

当扫描到 $a_i$ 时：

- 栈顶元素的值若 $< a_i$，那么 $a_i$ 就是它**右边第一个更大的值**——因为栈顶之后的所有元素都已经被更早的值结算过了，而栈顶一直没被结算，说明中间没有比它大的。于是弹栈、写答案。
- 重复上述过程，直到栈空或栈顶值 $\ge a_i$。
- 把 $i$ 压栈（它成为新的「等待者」）。

扫描结束后仍在栈里的下标，右侧确实没有更大的值，答案保持 0。

> 💡 为什么栈内**不增**？因为一旦出现更大的值，比它小的栈内元素会被全部弹出；能留在栈里的都是「没有被当前值打败」的元素，它们的值沿栈底到栈顶单调不增。

### 3.3 算法流程

![算法流程：先读链表成数组，再一次扫描结算](images/wc130_q3_algorithm_flow.svg)

```text
1. 遍历链表，把值依次放进数组 a[0..n-1]        # 链表不支持随机访问，先落地
2. ans = 长度 n 的全 0 数组
3. st = 空栈（存下标）
4. for i = 0 .. n-1:
        while st 非空 且 a[st.top()] < a[i]:
            ans[st.top()] = a[i]
            st.pop()
        st.push(i)
5. 返回 ans
```

每个下标**入栈一次、出栈至多一次**，所以内层 `while` 的总执行次数不超过 $n$，整体线性。

### 3.4 示例演算

![示例演算：head = [2,7,4,3,5] 的五步结算](images/wc130_q3_walkthrough.svg)

对 `head = [2,7,4,3,5]`（$a = [2,7,4,3,5]$）：

| $i$ | $a_i$ | 弹栈动作 | 栈（自底向顶） | `ans` 变化 |
|---|---|---|---|---|
| 0 | 2 | — | [0] | [0,0,0,0,0] |
| 1 | 7 | 弹 0，`ans[0]=7` | [1] | [7,0,0,0,0] |
| 2 | 4 | —（7 > 4） | [1,2] | [7,0,0,0,0] |
| 3 | 3 | —（4 > 3） | [1,2,3] | [7,0,0,0,0] |
| 4 | 5 | 弹 3 → `ans[3]=5`；弹 2 → `ans[2]=5` | [1,4] | [7,0,5,5,0] |

扫描结束，栈中剩 `[1,4]`（值 7、5），右侧无更大值，答案保持 0，最终 `[7,0,5,5,0]` ✓。

## 4. 算法细节

1. **链表先转数组**：单调栈需要「跳过已结算元素」，而链表没有下标、也不能回头，必须先把值读进 `vector`/`list`。转换本身 $O(n)$，不影响总复杂度。
2. **栈存下标而不是值**：写答案时需要知道「是哪个位置的节点被结算」，所以存下标，值通过 `a[st.back()]` 取。
3. **严格大于**：弹栈条件是 `a[st.back()] < a[i]`，**不能**写成 `<=`。相等时不弹栈，否则会把「相等的值」误当作更大值（示例 3）。
4. **答案初值为 0**：正好对应「不存在下一个更大值」的情况，无需再补写。
5. **一次入栈一次出栈**：这是均摊 $O(n)$ 的关键；不要在循环里遍历栈。
6. **值域 $10^9$**：`int` 足够（$10^9 < 2^{31}-1$），答案数组用 `vector<int>`。

## 5. 正确性证明

设链表值序列为 $a_0, \dots, a_{n-1}$，$nxt(i) = \min\{j > i : a_j > a_i\}$（不存在则为 $+\infty$）。

**引理 1（栈内单调）**：任意时刻，栈内下标自底向顶严格递增，且对应的值 $a_{st_0} \ge a_{st_1} \ge \cdots \ge a_{st_k}$（单调不增）。

**证明**：对扫描步数归纳。初始空栈成立。扫描到 $a_i$ 时，算法先不断弹出栈顶中值 $< a_i$ 的元素，弹出结束后栈顶（若存在）满足 $a_{top} \ge a_i$，此时压入 $i$，$i$ 是最大下标且值不大于原栈顶，单调性保持。∎

**引理 2（弹栈即结算）**：扫描到 $a_i$ 时，若 $a_{st_{top}} < a_i$，则 $nxt(st_{top}) = i$。

**证明**：只需证明对任意 $st_{top} < j < i$ 都有 $a_j \le a_{st_{top}}$。反证：设存在这样的 $j$ 使 $a_j > a_{st_{top}}$。由于 $st_{top}$ 在 $i$ 时刻仍在栈中，它在 $j$ 时刻也必然在栈中（下标只会被弹出一次，且弹出后不再入栈）。由引理 1，$st_{top}$ 之上所有元素的值都不超过 $a_{st_{top}} < a_j$。于是扫描到 $j$ 时，内层 `while` 会把 $st_{top}$ 上方的元素逐个弹出，随后因 $a_{st_{top}} < a_j$ 把 $st_{top}$ 本身也弹出，与「$st_{top}$ 在 $i$ 时刻仍在栈中」矛盾。故 $a_i$ 是 $st_{top}$ 右侧第一个更大的值。∎

**引理 3（残留即无解）**：扫描结束后仍在栈中的下标 $i$，满足 $nxt(i) = +\infty$。

**证明**：若 $nxt(i) = j$ 存在，则在扫描到 $j$ 时，$a_j > a_i$；由引理 1，此时栈中 $i$ 及其上方元素的值均 $\le a_i < a_j$，故 $i$ 会在第 $j$ 步被弹出，与「仍在栈中」矛盾。∎

**定理**：算法返回的 `ans` 与题面定义一致。

**证明**：每个下标 $i$ 恰好经历一种命运：在某个 $j$ 时刻被弹出，或在扫描结束时残留。前者由引理 2 得 `ans[i] = a_{nxt(i)}`；后者由引理 3 得 $nxt(i)$ 不存在，`ans[i]` 保持 0。两类都符合定义，且每个下标只被写入一次。∎

## 6. 复杂度分析

- **时间**：$O(n)$。链表转数组 $O(n)$；主扫描中每个下标入栈恰好一次、出栈至多一次，内层 `while` 的总迭代次数 $\le n$，故总 $O(n)$。
- **空间**：$O(n)$。值数组 $O(n)$、答案数组 $O(n)$、栈 $O(n)$；若把答案数组与栈合并使用，可省到 $O(n)$ 常数更小，但渐近不变。
- **对比**：暴力 $O(n^2)$，本题 $n \le 10^4$ 时暴力约 $5 \times 10^7$ 次比较，恰好卡在边界；单调栈把最坏情况也压到线性。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> nextLargerNodes(ListNode* head) {
        vector<int> a;
        for (ListNode* p = head; p != nullptr; p = p->next) a.push_back(p->val);

        int n = (int)a.size();
        vector<int> ans(n, 0);
        vector<int> st;                       // 存下标，栈内值单调不增
        for (int i = 0; i < n; i++) {
            while (!st.empty() && a[st.back()] < a[i]) {
                ans[st.back()] = a[i];        // a[i] 是它右边第一个更大值
                st.pop_back();
            }
            st.push_back(i);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def nextLargerNodes(self, head) -> list[int]:
        a = []
        p = head
        while p is not None:
            a.append(p.val)
            p = p.next

        ans = [0] * len(a)
        st = []                               # 存下标，栈内值单调不增
        for i, v in enumerate(a):
            while st and a[st[-1]] < v:
                ans[st.pop()] = v
            st.append(i)
        return ans
```

## 8. 边界情况与易错点

1. **严格大于**：弹栈必须用 `<`，写成 `<=` 会把相等值当成更大值。例如 `[3,3,4]`，正确答案 `[4,4,0]`；若写成 `<=`，第一个 3 会被第二个 3 结算成 3，答案错为 `[3,4,0]`。
2. **单节点**：直接返回 `[0]`，栈里留一个下标，自然正确。
3. **严格递减**：如 `[5,4,3,2,1]`，全程不弹栈，返回值全 0——这是暴力最坏、单调栈最省的情况。
4. **链表读取**：`for (ListNode* p = head; p; p = p->next)`，不要漏 `p->next` 或写成 `p++`。
5. **空链表**：题面保证 $n \ge 1$，但代码对空链表也能返回空数组。
6. **答案补 0**：栈中残留的下标不需要额外处理，因为 `ans` 初始化为 0。
7. **值域**：$a_i \le 10^9$ 用 `int` 安全；若值域升到 $10^{18}$ 需改 `long long`。
