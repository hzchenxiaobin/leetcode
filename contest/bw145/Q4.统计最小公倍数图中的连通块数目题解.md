# LeetCode 统计最小公倍数图中的连通块数目 题解

## 1. 题目概述

- **标题 / 题号**：统计最小公倍数图中的连通块数目（#3378，hard）
- **链接**：https://leetcode.cn/problems/count-connected-components-in-lcm-graph/
- **来源**：LeetCode 第 145 场双周赛 Q4
- **难度**：困难
- **标签**：并查集、数组、哈希表、数学、数论、最大公约数、最小公倍数

**题意**：给定长度为 $n$ 的整数数组 `nums`（元素互不相同）与正整数 `threshold`。建有 $n$ 个节点的无向图，第 $i$ 个节点的值为 $\text{nums}[i]$，当且仅当

$$\text{lcm}(\text{nums}[i], \text{nums}[j]) \le \text{threshold}$$

时两节点之间有一条边。求这张图的**连通块**个数。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- `nums` 中所有元素**互不相同**
- $1 \le \text{threshold} \le 2 \times 10^5$

> 💡 量级对比是本题的题眼：**值域巨大（$10^9$）而阈值很小（$2 \times 10^5$）**。所有「值超过阈值」的元素都注定是孤点，真正需要处理的值只有不超过 $\text{threshold}$ 的那一小撮，而且可以用「倍数枚举」把它们之间的边压缩成 $O(T \log T)$ 次操作。

## 2. 示例

**示例 1**

```text
输入：nums = [2,4,8,3,9], threshold = 5
输出：4
解释：lcm(2,4) = 4 ≤ 5，连边；lcm(2,8) = 8 > 5，不连；lcm(4,8) = 8 > 5，不连。
      lcm(3,9) = 9 > 5，不连。8、9 都大于阈值，自身孤立。
      连通块为 (2,4)、(3)、(8)、(9)，共 4 个。
```

**示例 2**

```text
输入：nums = [2,4,8,3,9,12], threshold = 10
输出：2
解释：lcm(2,3) = 6 ≤ 10，所以 2 与 3 直接相连；
      2-4、2-8、3-9 也都有边，于是 {2,3,4,8,9} 连成一块。
      12 > 10，是孤点。共 2 块。
```

**示例 3（自造，考察「共同倍数」这条隐藏边）**

```text
输入：nums = [2,3], threshold = 6
输出：1
解释：lcm(2,3) = 6 ≤ 6，两节点直接相连。注意此时「6」并不在 nums 里，
      但仍能通过它把 2 和 3 连起来——这正是本题解法要用到的枢纽思想。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有点对 $(i, j)$，用 $\gcd$ 求 $\text{lcm}$ 判边，再做并查集，复杂度

$$O(n^2 \log \max(\text{nums}))$$

$n = 10^5$ 时是 $5 \times 10^9$ 次 $\gcd$，完全不可能。必须利用「阈值只有 $2\times 10^5$」这个不对称条件。

### 3.2 核心观察一：超过阈值的值是孤点

![lcm 不小于两数中的较大者，因此超过阈值的大值一定孤立](images/bw145_q4_observation.svg)

对任意两个正整数 $a, b$，因为 $a \mid \text{lcm}(a,b)$，所以

$$\text{lcm}(a,b) \ge \max(a, b)$$

于是若 $\text{nums}[i] > \text{threshold}$，则对任意 $j$ 都有 $\text{lcm} \ge \text{nums}[i] > \text{threshold}$，第 $i$ 个节点**没有任何边**，单独成一个连通块。

> 结论 1：答案为「值 $> \text{threshold}$ 的元素个数」加上「值 $\le \text{threshold}$ 的那些元素构成的连通块数」。

后者至多涉及 $\min(n, \text{threshold})$ 个**互不相同**的值，且这些值都 $\le T$（记 $T = \text{threshold}$）。

### 3.3 核心观察二：用「共同倍数」当枢纽，边可以被压缩

![2 与 3 没有整除关系，但它们的 lcm 6 是共同的倍数，可作枢纽把两者连起来](images/bw145_q4_steiner.svg)

直接在 $\le T$ 的值之间两两判 $\gcd$ 仍是 $O(T^2)$。关键等价改写：

$$\text{lcm}(a,b) \le T \iff \exists\, L \le T \text{ 使得 } a \mid L \text{ 且 } b \mid L$$

（$\Leftarrow$ 显然，因为 $L$ 是公共倍数则 $\text{lcm} \mid L \le T$；$\Rightarrow$ 取 $L = \text{lcm}(a,b)$ 即可。）

所以不要「两两连边」，而是**建一个以【数值】为下标的并查集（下标 $1 \sim T$）**，对每个出现在 `nums` 中且 $\le T$ 的值 $v$，枚举它的所有倍数 $mul = v, 2v, 3v, \dots \le T$，把 $v$ 与 $mul$ **合并**。

- $mul$ 不必出现在 `nums` 里：它就是上面那个「枢纽 $L$」。示例 3 中 $v = 2$ 会与 $6$ 合并，$v = 3$ 也会与 $6$ 合并，于是 2 与 3 落进同一块。
- 合并没有方向性：`union(v, mul)` 是无向的。

**为什么不会算错**（详见 §5）：任何一次合并都对应一条真实边（$v \mid mul$ 且 $mul \le T$，故 $\text{lcm}(v, mul) = mul \le T$）；反过来任何一条真实边 $(a,b)$ 都会通过枢纽 $L = \text{lcm}(a,b) \le T$ 被间接合并。于是「并查集里同块」与「原图中连通」完全等价。

**代价估算**：对每个出现过的 $v$ 枚举倍数，代价为 $\sum_{v \in P} \lfloor T / v \rfloor \le T \sum_{v=1}^{T} \frac{1}{v} = T H_T$。$T = 2 \times 10^5$ 时 $H_T \approx 12.2$，总量约 $2.4 \times 10^6$ 次合并，非常轻。

### 3.4 算法流程

![算法流程：孤点计数 + 倍数枚举建并查集 + 统计不同根](images/bw145_q4_flow.svg)

```text
1. T = threshold
2. 并查集初始化 parent[1..T]（每个值自成一类）
3. 把 nums 中所有 ≤ T 的值标记为 present
4. for v = 1 .. T:
       if not present[v]: continue
       for mul = v, 2v, 3v, ... (≤ T):
           union(v, mul)                       // v 与它的每个倍数合并
5. ans = 0；roots = 空集合
6. for x in nums:
       if x > T: ans += 1                  // 孤点，各自一块
       else: roots.add(find(x))            // 按根去重
7. return ans + len(roots)
```

### 3.5 示例演算

以示例 2 的 `nums = [2,4,8,3,9,12]`、`threshold = 10` 为例（$T = 10$）：

| 出现的值 $v$ | 枚举到的倍数 $mul \le 10$ | 产生的合并 |
|--------------|---------------------------|------------|
| 2 | 2, 4, 6, 8, 10 | $2 \sim 2$（自环，忽略）、$2 \sim 4$、$2 \sim 6$、$2 \sim 8$、$2 \sim 10$ |
| 3 | 3, 6, 9 | $3 \sim 6$、$3 \sim 9$ |
| 4 | 4, 8 | $4 \sim 8$（已同块） |
| 8 | 8 | 无 |
| 9 | 9 | 无 |

关键一步是 $2 \sim 6$ 与 $3 \sim 6$：通过枢纽 $6$，2 与 3 落进同一块，于是 $\{2,3,4,8,9\}$ 全部连通。而 $12 > 10$ 是孤点。

统计：孤点 1 个（12），$\le 10$ 的值只有 1 个不同的根，总计 $1 + 1 = 2$，与输出一致。

## 4. 算法细节

1. **并查集下标是「值」而不是「数组下标」**：这是本题最关键的实现决策。若按数组下标建并查集，就必须真的把每对边找出来（$\Omega(n^2)$）；按值建、把倍数当枢纽，才能把边压缩到 $O(T \log T)$。
2. **值的去重**：题目保证 `nums` 互不相同，但仍建议用 `present[]` 布尔数组或集合标记，避免对重复值重复枚举倍数（若数据不保证互异，重复值会重复合并，虽然结果不变，但白花时间）。
3. **`union` 只做一次方向**：`union(v, mul)` 内部用按秩/路径压缩即可；不需要双向调用。
4. **孤点单独统计**：值 $> T$ 的元素不能塞进大小为 $T+1$ 的并查集，直接计数更省内存。
5. **根的去重**：`find(x)` 之后放进集合（C++ 用 `unordered_set`，Python 用 `set`），因为不同值可能已经被合并成同一块。
6. **路径压缩写法**：迭代式 `while (parent[x] != x) parent[x] = parent[parent[x]], x = parent[x];` 避免递归深度问题（虽然链长很短）。
7. **$T$ 很小时的边界**：$T = 1$ 时只有值 1 可能被合并；`nums[i] = 1` 的节点与任何值 $x$ 的 $\text{lcm}$ 都是 $x$，所以 1 会与所有 $\le T$ 的值连通——代码中 $v = 1$ 会枚举全部倍数，正确覆盖。

## 5. 正确性证明

设 $P = \{\, x : x \in \text{nums},\ x \le T \,\}$（互不相同），$\mathcal{G}$ 为原图在 $P$ 对应节点上的诱导子图，$\mathcal{D}$ 为本题并查集（下标 $1 \sim T$）。

**引理 1（孤点）**：若 $x \in \text{nums}$ 且 $x > T$，则 $x$ 对应节点在图中度数为 $0$，自成一个连通块。

**证明**：对任意 $y$，$\text{lcm}(x,y) \ge \max(x,y) \ge x > T$，故无边。∎

**引理 2（每条合并都是真边）**：算法中的每次合并 `union(v, mul)` 都满足 $v, mul \le T$ 且 $v \mid mul$，因而 $\text{lcm}(v, mul) = mul \le T$；若 $v, mul$ 都在 `nums` 中，则它们之间确实有边。

**证明**：`mul` 取遍 $v$ 的不超过 $T$ 的倍数，故 $v \mid mul$、$mul \le T$；此时 $\text{lcm}(v,mul) = mul$（因为 $v \mid mul$）。若两者都出现在 `nums` 中，由题目定义即连边。∎

**引理 3（真实边不会被漏掉）**：若 $a, b \in P$ 在 $\mathcal{G}$ 中有边，则 $a, b$ 在 $\mathcal{D}$ 中属于同一集合。

**证明**：有边意味着 $L = \text{lcm}(a,b) \le T$。又 $a \mid L$ 且 $b \mid L$，且 $a, b$ 都被标记为 present、$L \le T$。算法中 $v = a$ 时会枚举到倍数 $L$，执行 `union(a, L)`；$v = b$ 时同理执行 `union(b, L)`。两次合并后 $a, b, L$ 同属一个集合，故 $a, b$ 同集合。∎

**引理 4（不会误连）**：若 $a, b \in P$ 在 $\mathcal{D}$ 中属于同一集合，则它们在 $\mathcal{G}$ 中连通。

**证明**：取 $\mathcal{D}$ 中连接 $a$ 与 $b$ 的一条**最短**路径 $a = z_0, z_1, \dots, z_k = b$。对路径做如下「折叠」：把路径中极大的连续非 $P$ 段 $z_i, \dots, z_j$（$z_{i-1}, z_j \in P$，中间都不在 $P$）替换掉。考察这样一段：由于每一步合并形如 `union(v, mul)` 且 $v$ 必然 present（只有 present 的值才会发起枚举），路径上相邻两点总有一个是 present 且整除另一个。于是对两个相邻的 present 端点，存在一条「整除链」连接它们；由整除的传递性，段两端满足 $p \mid q$ 或 $q \mid p$，从而 $\text{lcm}(p,q) = \max(p,q) \le T$，即 $p, q$ 在 $\mathcal{G}$ 中**直接相邻**。把每一段都换成这条直接边，就得到 $\mathcal{G}$ 中一条 $a \to b$ 的路径，故二者连通。∎

**定理**：算法返回值等于原图的连通块数。

**证明**：由引理 1，所有 $> T$ 的值各贡献恰好一个连通块，算法用 `ans` 逐一计数。对 $P$ 中的值，引理 3 与引理 4 说明「$\mathcal{D}$ 同集合」$\iff$「$\mathcal{G}$ 连通」，即并查集恰好刻画了 $\mathcal{G}$ 的连通块划分；算法对 $P$ 中每个值取一次 `find` 并按根去重，正好数出 $\mathcal{G}$ 的连通块个数。两者相加即为原图连通块总数。∎

## 6. 复杂度分析

- **筛/标记**：$O(n)$ 标记 present，$O(T)$ 分配并查集。
- **倍数枚举**：$\sum_{v \in P} \lfloor T/v \rfloor \le T \cdot H_T = O(T \log T)$。$T = 2 \times 10^5$ 时约 $2.4 \times 10^6$ 次 `union`，每次均摊 $O(\alpha(T))$。
- **统计答案**：$O(n \alpha(T))$。
- **总时间**：$O\big((n + T \log T)\,\alpha(T)\big)$，主导项是 $T \log T$。
- **空间**：$O(T)$ 的 `parent` 与 `present` 数组，加上 $O(T)$ 的根集合；与 $n$、$\text{nums}[i]$ 的大小无关。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
#include <numeric>

using namespace std;

class Solution {
    int find(vector<int>& parent, int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }

    void unite(vector<int>& parent, int a, int b) {
        a = find(parent, a);
        b = find(parent, b);
        if (a != b) parent[a] = b;
    }

public:
    int countComponents(vector<int>& nums, int threshold) {
        int limit = threshold;
        vector<int> parent(limit + 1);
        iota(parent.begin(), parent.end(), 0);

        vector<char> present(limit + 1, 0);
        for (int v : nums)
            if (v <= limit) present[v] = 1;

        for (int v = 1; v <= limit; v++) {
            if (!present[v]) continue;
            for (int mul = v; mul <= limit; mul += v) unite(parent, v, mul);
        }

        int ans = 0;
        unordered_set<int> roots;
        for (int v : nums) {
            if (v > limit) ans++;
            else roots.insert(find(parent, v));
        }
        return ans + (int)roots.size();
    }
};
```

### Python

```python
class Solution:
    def countComponents(self, nums: list[int], threshold: int) -> int:
        limit = threshold
        parent = list(range(limit + 1))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            ra, rb = find(a), find(b)
            if ra != rb:
                parent[ra] = rb

        present = set()
        for v in nums:
            if v <= limit:
                present.add(v)

        for v in present:
            for mul in range(v, limit + 1, v):
                union(v, mul)

        ans = sum(1 for v in nums if v > limit)
        roots = set()
        for v in present:
            roots.add(find(v))
        return ans + len(roots)
```

## 8. 边界情况与易错点

1. **只按「倍数」连边是不够的**：只连 $v$ 与 `nums` 中出现的倍数会漏掉无整除关系的边（示例 3：2 与 3 的边只能通过不在 `nums` 里的枢纽 6 体现）。必须让并查集覆盖 $1 \sim T$ 的所有值，而不是只覆盖 `nums` 中的值。
2. **$>T$ 的值不能进并查集**：数组大小按 $T+1$ 开，遇到大值直接计数，否则下标越界。
3. **答案是「不同根」而不是「值的个数」**：合并后多个值共享同一根，必须用集合去重。
4. **`lcm` 溢出**：若用 $\frac{a \cdot b}{\gcd(a,b)}$ 直接算，$a, b \le 10^9$ 时乘积会爆 `int`（甚至爆 `long long` 的中间值）。本题解法**完全不需要算 lcm**，只用整除关系，正好规避这一风险。
5. **$T$ 小时的特例**：$T = 1$ 时只有值 1 可能存在；值 1 与任何值的 lcm 都等于对方，若数组含 1 且另有 $\le 1$ 的值则连通——代码的倍数枚举自然处理。
6. **单个元素**：$n = 1$ 时答案恒为 1（孤点或自成一类），代码两条分支都给出 1。
7. **全部大于阈值**：每个元素都孤立，答案为 $n$；此时并查集循环一次都不执行，注意不要因为 `present` 全空而误返回 0。
8. **路径压缩的迭代写法**：递归版在极端链上可能爆栈（虽然本题链很短，仍建议迭代）。
