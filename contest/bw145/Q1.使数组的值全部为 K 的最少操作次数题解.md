# LeetCode 使数组的值全部为 K 的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组的值全部为 K 的最少操作次数（#3375，easy）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-array-values-equal-to-k/
- **来源**：LeetCode 第 145 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定整数数组 `nums` 与整数 `k`。称整数 $h$ 是**合法**的，当且仅当**所有严格大于 $h$ 的元素都相等**（没有元素大于 $h$ 也算合法）。一次操作是：

1. 选一个对**当前**数组合法的 $h$；
2. 把所有满足 $\text{nums}[i] > h$ 的位置一起改成 $h$。

求把数组所有元素都变成 $k$ 的**最少**操作次数；做不到则返回 $-1$。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$
- $1 \le k \le 100$

> 💡 一句话抓住本质：操作**只会把大值压小**，且一次操作只能抹掉「最大值这一层」。所以答案要么是 $-1$，要么就等于「数组中严格大于 $k$ 的**不同**取值个数」。

## 2. 示例

**示例 1**

```text
输入：nums = [5,2,5,4,5], k = 2
输出：2
解释：先选 h = 4（此时大于 4 的只有 5，全相等，合法），数组变 [4,2,4,4,4]；
     再选 h = 2（此时大于 2 的只有 4，全相等，合法），数组变 [2,2,2,2,2]。
     大于 2 的不同取值是 {5, 4}，共 2 个。
```

**示例 2**

```text
输入：nums = [2,1,2], k = 2
输出：-1
解释：数组中存在比 k 小的 1。操作只会让元素变小或不动，1 永远无法变成 2。
```

**示例 3**

```text
输入：nums = [9,7,5,3], k = 1
输出：4
解释：依次选 h = 7、5、3、1，每次把当前最大的一层压到下一层（最后一次直接压到 k）。
     大于 1 的不同取值是 {9,7,5,3}，共 4 个。
```

**示例 4（自造，考察「k 不在数组中」）**

```text
输入：nums = [5,5], k = 3
输出：1
解释：大于 3 的不同取值只有 {5}。选 h = 3 一次性把 5 压成 3，虽然数组里原本没有 3。
```

## 3. 解题思路

### 3.1 暴力思路

题意里 $h$ 的取值看似连续（$0 \sim 100$），可以暴力搜索：状态是「当前数组」，从初始状态出发 BFS，每次枚举所有合法 $h$ 生成后继状态，直到全为 $k$。

- 状态数上界约 $101^{100}$（每个位置独立取值），虽然实际可达状态远少于此，但**没有任何可证明的多项式上界**；
- 即使只在 $[0,100]$ 里枚举 $h$，单步枚举也要 $O(100n)$，而层数未知。

暴力在这个题上不仅慢，而且完全掩盖了真正的结构——操作对「不同取值的层数」是一层层削的。下面直接找这个结构。

### 3.2 核心观察：合法 $h$ 允许「跨越式下压」，但每次只消灭一层

![把数组看成若干层取值，操作一次只能削掉最高的一层](images/bw145_q1_levels.svg)

设当前数组中严格大于 $k$ 的**不同取值**从大到小为

$$v_1 > v_2 > \cdots > v_m > k$$

（$k$ 本身可能出现在数组里，也可能不出现，这不影响结论。）

- **合法性等价于「只看最高的那一层」**：取 $h \in [v_2, v_1 - 1]$ 时，大于 $h$ 的元素恰好是全部等于 $v_1$ 的元素，彼此相等，故 $h$ 合法；若取 $h < v_2$，则大于 $h$ 的元素里同时有 $v_1$ 与 $v_2$ 两种值，不合法。
- **取 $h = v_2$（或 $h = k$）最划算**：这一步把 $v_1$ 全部压成 $v_2$，不同取值从 $m$ 个减为 $m-1$ 个（若 $v_2$ 不存在，即只剩 $v_1$ 一层，则取 $h = k$ 直接收尾）。**每次操作恰好消灭一层。**
- **下界**：任意一次操作把「大于 $h$ 的所有值」统一改成 $h$，因此 $> k$ 的不同取值个数在一次操作里最多减少 $1$。要从 $m$ 层减到 $0$ 层，至少 $m$ 次。

两者合起来：能完成时**最少操作次数恰为 $m$**，即「数组中严格大于 $k$ 的不同取值个数」。

再看无解条件：操作只会把元素改成 $h \le \text{原值}$，任何元素都**不会变大**。所以只要存在 $\text{nums}[i] < k$，它永远到不了 $k$，答案 $-1$。反之若 $\min(\text{nums}) \ge k$，每条元素都能被压到 $k$（最后一步取 $h = k$，此时大于 $k$ 的只剩一层，合法），一定能完成。

### 3.3 算法流程

![算法流程：一次扫描判定无解并统计大于 k 的不同取值](images/bw145_q1_flow.svg)

```text
1. higher = 空集合
2. for x in nums:
       if x < k:  return -1          // 无法变大，永远到不了 k
       if x > k:  higher.add(x)      // 按值去重，只关心"有几层"
3. return len(higher)
```

用哈希集合的理由：只关心「有哪些不同的层」，重复元素对答案没有任何影响（示例 1 里三个 5 只算一层）。

### 3.4 示例演算

以示例 1 的 `nums = [5,2,5,4,5]`、`k = 2` 为例：

| 步骤 | 当前数组 | 大于 $k$ 的不同取值 | 选 $h$ | 结果 |
|------|----------|--------------------|--------|------|
| 初始 | $[5,2,5,4,5]$ | $\{5,4\}$ | — | — |
| 1 | $[4,2,4,4,4]$ | $\{4\}$ | $4$ | 5 这一层被压成 4，层数 2→1 |
| 2 | $[2,2,2,2,2]$ | $\varnothing$ | $2$ | 4 这一层被压成 2，层数 1→0 |

共 2 次，等于「大于 2 的不同取值个数」$=2$。示例 3 同理：$\{9,7,5,3\}$ 共 4 层，逐层下压 4 次。

## 4. 算法细节

1. **判定顺序**：先判 `x < k`（直接返回 $-1$，可提前退出），再判 `x > k` 去重。等于 $k$ 的元素不影响任何事。
2. **去重是核心**：答案统计的是「不同取值的层数」而非「元素个数」。用 `set` / `unordered_set` 天然去重，也可用值域 $\le 100$ 的布尔数组。
3. **不需要排序**：只统计层数，与顺序、与每层有多少个元素都无关。排序成 $O(n \log n)$ 是多余开销。
4. **$k$ 是否在数组中不参与判定**：示例 4 说明即使原数组没有 $k$，最后一次取 $h = k$ 依然合法（此时只剩一层大于 $k$ 的值），能一步收尾。
5. **合法性只需检查最强的约束**：本题不需要真的模拟「选 $h$ 后数组变成什么」，因为可以证明「每步恰好消一层」的构造总是存在（见 §5 的定理）。

## 5. 正确性证明

**引理 1（单调不增）**：任意一次操作后，每个元素的值都不大于操作前的值。

**证明**：操作把 $\text{nums}[i] > h$ 的位置改成 $h$，其余位置不动，故每位置新值 $= \min(\text{nums}[i], h) \le \text{nums}[i]$。∎

**引理 2（无解判定）**：若存在 $\text{nums}[i] < k$，则无论如何操作都无法让所有元素等于 $k$。

**证明**：由引理 1，该元素的值单调不增，始终 $< k$，永远不可能等于 $k$。∎

**引理 3（层数下界）**：设当前 $> k$ 的不同取值有 $m$ 个，则再经过一次任意合法操作，$> k$ 的不同取值个数至少为 $m - 1$；特别地，$m \ge 1$ 时无法用零次操作结束。

**证明**：一次操作把「所有 $> h$ 的值」统一替换为同一个值 $h$。设操作前 $>k$ 的不同取值为 $S$，操作后为 $S'$。$S$ 中所有 $\le h$ 的值保持不变，仍是 $S'$ 的元素；$S$ 中所有 $> h$ 的值（它们必须彼此相等，合法性要求）全部塌缩成一个值 $h$，在 $S'$ 中最多贡献 1 个新元素。因此 $|S'| \ge |S| - 1$。∎

**引理 4（构造上界）**：若 $\min(\text{nums}) \ge k$，设当前 $> k$ 的不同取值从大到小为 $v_1 > \cdots > v_m > k$，则存在合法操作使层数恰好减少 1。

**证明**：分两种情形。

- $m \ge 2$：取 $h = v_2$。此时 $> h$ 的元素恰为所有等于 $v_1$ 的元素，它们彼此相等，故 $h$ 合法。操作后 $v_1$ 全部变成 $v_2$，不同取值集合变为 $\{v_2, \dots, v_m\}$，层数 $m \to m-1$。
- $m = 1$：取 $h = k$。此时 $> h$ 的元素恰为所有等于 $v_1$ 的元素（因为 $\min \ge k$，其余元素都 $\le k$），彼此相等，合法。操作后它们全部变成 $k$，层数 $1 \to 0$。

两种情形都只改变 $>h$ 的那一层，其余层原样保留，故层数恰减 1。∎

**定理**：若 $\min(\text{nums}) < k$，答案为 $-1$；否则答案为「数组中严格大于 $k$ 的不同取值个数」，即算法返回值。

**证明**：无解情形由引理 2 得 $-1$。有解情形：由引理 4，可构造出恰好 $m$ 次操作的方案，故最优值 $\le m$；由引理 3，每次操作至多让层数减 1，从 $m$ 减到 $0$ 至少需要 $m$ 次，故最优值 $\ge m$。两者相等，而算法统计的正是 $m$（`higher` 是「$>k$ 的值」构成的集合，基数即层数）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，哈希集合的插入与查询均摊 $O(1)$；若用值域 $\le 100$ 的布尔数组，则为严格 $O(n + V)$。
- **空间**：$O(n)$（哈希集合最多存 $n$ 个不同值）；布尔数组写法为 $O(V)$，$V \le 100$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>

using namespace std;

class Solution {
public:
    int minOperations(vector<int>& nums, int k) {
        unordered_set<int> higher;
        for (int x : nums) {
            if (x < k) return -1;
            if (x > k) higher.insert(x);
        }
        return (int)higher.size();
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int], k: int) -> int:
        higher = set()
        for x in nums:
            if x < k:
                return -1
            if x > k:
                higher.add(x)
        return len(higher)
```

## 8. 边界情况与易错点

1. **只看不同值，不看出现次数**：示例 1 中 5 出现 3 次，但只算一层；重复元素不能累加。
2. **无解条件是「小于 $k$」而不是「不等于 $k$」**：等于 $k$ 的元素本来就满足目标，不需要操作。
3. **不要漏掉 `-1` 的提前返回**：若先统计完再判 $-1$，逻辑上没错，但漏判会直接 WA（示例 2）。
4. **`h` 不必是数组中出现过的值**：示例 4 说明可以直接选 $h = k$ 收尾。
5. **单元素数组**：$n = 1$ 时，若 $nums[0] \ge k$，答案为 $0$ 或 $1$（等于 $k$ 为 $0$，大于 $k$ 为 $1$），代码自然覆盖。
6. **全部等于 $k$**：`higher` 为空，返回 $0$，不要误判成 $-1$。
7. **整数范围**：$nums[i], k \le 100$，无溢出风险，无需 `long long`。
