# LeetCode 破解锁的最少时间 I 题解

## 1. 题目概述

- **标题 / 题号**：破解锁的最少时间 I（#3376，medium）
- **链接**：https://leetcode.cn/problems/minimum-time-to-break-locks-i/
- **来源**：LeetCode 第 145 场双周赛 Q2
- **难度**：中等
- **标签**：位掩码、动态规划、数组、回溯、位运算

**题意**：有 $n$ 把锁，第 $i$ 把需要能量 $\text{strength}[i]$ 才能打开。Bob 的剑有两个量：

- 当前能量 $E$，初始为 $0$；
- 能量**增量因子** $x$，初始为 $1$。

每分钟能量增加当前的 $x$，即「充能」阶段 $E \leftarrow E + x$。当 $E \ge \text{strength}[i]$ 时可以打开第 $i$ 把锁；**开锁瞬间** $E$ 归零，并且 $x \leftarrow x + k$（$k$ 为给定常数）。

求打开全部 $n$ 把锁所需的最少分钟数（充能按整分钟计，开锁本身不耗时间）。

**约束**：

- $n = \text{strength.length}$，$1 \le n \le 8$
- $1 \le k \le 10$
- $1 \le \text{strength}[i] \le 10^6$

> 💡 关键量级：$n \le 8$。$8! = 40320$，枚举全排列在浮点意义上都够用；而 $2^n = 256$ 的**子集 DP** 更稳、更好写，复杂度 $O(2^n \cdot n)$。

## 2. 示例

**示例 1**

```text
输入：strength = [3,4,1], k = 1
输出：4
解释：实际最优顺序是「先破 1，再破 4，最后破 3」：
      第 1 分钟 x = 1，E = 1 ≥ 1，破 strength[2] = 1，x 变 2；
      第 2-3 分钟 x = 2，E = 4 ≥ 4，破 strength[1] = 4，x 变 3；
      第 4 分钟 x = 3，E = 3 ≥ 3，破 strength[0] = 3，x 变 4。
      共 4 分钟。
```

**示例 2**

```text
输入：strength = [2,5,4], k = 2
输出：5
解释：顺序「2 → 5 → 4」：
      x = 1 时充 2 分钟（2/1 = 2）破 strength[0] = 2，x 变 3；
      x = 3 时充 2 分钟（5/3 上取整）破 strength[1] = 5，x 变 5；
      x = 5 时充 1 分钟（4/5 上取整）破 strength[2] = 4。
      合计 2 + 2 + 1 = 5。
```

**示例 3（自造，对比「强锁优先」的陷阱）**

```text
输入：strength = [4,3,1], k = 1
输出：4
解释：按「最强优先」的顺序 4 → 3 → 1 需要 ceil(4/1) + ceil(3/2) + ceil(1/3) = 4 + 2 + 1 = 7；
      而 1 → 4 → 3 只需 1 + 2 + 1 = 4。可见贪心把最强的锁排在最前面是错的方向。
```

## 3. 解题思路

### 3.1 暴力思路

顺序决定一切：一旦确定「以什么顺序开锁」，每把锁的耗时就被唯一确定。于是最朴素的暴力是**枚举全部 $n!$ 种顺序**，逐种累加时间取最小，复杂度 $O(n! \cdot n)$。

$n = 8$ 时 $8! \cdot 8 \approx 3.2 \times 10^5$，其实能过。但全排列枚举有两个明显短板：

1. 大量重复子问题被反复计算（「已经开了集合 $S$ 的锁」这个状态被 $|S|!$ 条排列重复走到）；
2. 一旦本题的 II 版把 $n$ 放大，$n!$ 立刻爆炸，而子集 DP 可以平滑升级。

所以这里用**状压 DP**：以「已开锁的集合」为状态，把 $O(n!)$ 压到 $O(2^n n)$。

### 3.2 核心观察：耗时只由「这是第几把」决定

![第 t 把锁的耗时是上取整 strength/x，x 随破锁次数线性增长](images/bw145_q2_formula.svg)

**观察 1（状态压缩的合法性）**：$x$ 只由「已经开了几把锁」决定，与开了哪几把无关。开了 $t$ 把后 $x = 1 + t \cdot k$，所以状态里不需要记录 $x$，只需记录集合。

**观察 2（单把锁的耗时）**：在因子为 $x$ 的阶段，充能是线性的，$m$ 分钟后能量为 $m x$。要让 $m x \ge s$，最少需要

$$m = \left\lceil \frac{s}{x} \right\rceil = \left\lfloor \frac{s + x - 1}{x} \right\rfloor$$

分钟。**不会多等**：早开锁能让 $x$ 更早变大，对后续只有好处，所以最优策略里每把锁都恰好在能量首次足够时打开。

**观察 3（贪心为什么不行）**：直觉上「因子小的时候先啃硬锁」很自然，但**上取整破坏了单调性**。示例 1 中把 $s = 1$ 放到因子 $x = 1$ 的位置只要 $1$ 分钟，而把 $s = 4$ 放到 $x = 2$ 只要 $2$ 分钟；反过来把 $s = 4$ 放在最前要 $4$ 分钟。交换论证通常依赖

$$\left\lceil \frac{a}{x} \right\rceil + \left\lceil \frac{b}{y} \right\rceil \le \left\lceil \frac{b}{x} \right\rceil + \left\lceil \frac{a}{y} \right\rceil \quad (a \ge b,\ y \ge x)$$

而这个不等式在取整下**不成立**：取 $a = 4, b = 1, x = 1, y = 3$，左边 $4 + 1 = 5$，右边 $1 + 2 = 3$，反而是「小的在前」更优。因此不能排序贪心，必须搜索顺序——但可以搜得聪明。

### 3.3 算法流程：子集 DP

![子集 DP：状态是已破锁集合，转移是"下一把破哪把"](images/bw145_q2_dp_states.svg)

定义

$$dp[S] = \text{恰好破掉集合 } S \text{ 中所有锁所需的最少分钟数}$$

初始 $dp[\varnothing] = 0$，其余 $+\infty$。转移时令 $t = |S|$（$S$ 中元素个数），则下一个要破的锁 $i \notin S$ 处于因子 $x = 1 + t k$ 的阶段：

$$dp[S \cup \{i\}] = \min\Big(dp[S \cup \{i\}],\ dp[S] + \left\lceil \frac{\text{strength}[i]}{1 + t k} \right\rceil\Big)$$

按 $S$ 的二进制数值从小到大遍历即可（$S \cup \{i\} > S$，天然满足拓扑序）。答案 $dp[2^n - 1]$。

```text
1. full = 2^n - 1，dp[0] = 0，其余 INF
2. for S = 0 .. full:
       if dp[S] == INF: continue
       t = popcount(S)，x = 1 + t*k
       for i in 0 .. n-1:
           if S 含 i: continue
           cost = ceil(strength[i] / x)
           dp[S | (1<<i)] = min(dp[S | (1<<i)], dp[S] + cost)
3. return dp[full]
```

### 3.4 示例演算

![示例 1 的 DP 走查：1 → 4 → 3 顺序总耗时 4](images/bw145_q2_walkthrough.svg)

对 `strength = [3,4,1]`、`k = 1`，$x$ 依次为 $1, 2, 3$：

| 顺序 | 各步耗时 | 总耗时 |
|------|----------|--------|
| $1 \to 4 \to 3$ | $\lceil 1/1 \rceil = 1$，$\lceil 4/2 \rceil = 2$，$\lceil 3/3 \rceil = 1$ | $\mathbf{4}$ |
| $3 \to 1 \to 4$ | $3$，$1$，$\lceil 4/3 \rceil = 2$ | $6$ |
| $4 \to 3 \to 1$ | $4$，$2$，$1$ | $7$ |
| $4 \to 1 \to 3$ | $4$，$1$，$1$ | $6$ |

DP 中的关键转移：

- $dp[\{2\}] = \lceil 1/1 \rceil = 1$（先破 strength[2] = 1，$x$ 变 2）；
- $dp[\{1,2\}] = 1 + \lceil 4/2 \rceil = 3$（再破 strength[1] = 4，$x$ 变 3）；
- $dp[\{0,1,2\}] = 3 + \lceil 3/3 \rceil = 4$。

最小值 4，与题面输出一致。

## 4. 算法细节

1. **上取整写法**：整数用 `(s + x - 1) / x`，Python 用 `(s + x - 1) // x`。**不要**用浮点 `math.ceil(s / x)`：$s \le 10^6$ 时虽不溢出双精度，但除法与取整的边界（如 $s = 3, x = 3$）在浮点下容易出偏差，整数写法是零风险。
2. **$x$ 的取值**：$t \in [0, n-1]$，故 $x \le 1 + 7 \times 10 = 71$，全程 $x \ge 1$，分母安全。
3. **状态遍历顺序**：直接 `for S in 0..full` 即可，因为转移总是把某一位从 $0$ 变 $1$，$S$ 单调增大，无需 BFS 或记忆化递归。
4. **`popcount`**：C++ 用 `__builtin_popcount`，Python 用 `bin(S).count("1")`（或 `int.bit_count()`）；也可预处理 `cnt[mask]` 数组避免重复计算。
5. **答案上界**：最坏 $\sum_i \lceil 10^6 / 1 \rceil = 8 \times 10^6$，`int` 足够；但为了和通式一致，Python 用无限大哨兵、C++ 用 `0x3f3f3f3f` 都行。
6. **不变量**：$dp[S]$ 中集合 $S$ 的大小固定，所以「$dp[S]$ 只会在 $|S|$ 层之间互相转移」，这也是可以按 $|S|$ 分层 BFS 的原因（本题直接按数值序遍历更省事）。

## 5. 正确性证明

**引理 1（单锁耗时）**：若第 $t$ 次开锁（从 $0$ 计数）时因子为 $x = 1 + tk$、目标能量为 $s$，则这次开锁最少需要 $\lceil s/x \rceil$ 分钟，且多等不会更优。

**证明**：充能阶段每分钟 $E \leftarrow E + x$，$E$ 从 $0$ 开始，$m$ 分钟后 $E = mx$。故能开锁的最小整数 $m$ 满足 $mx \ge s$，即 $m = \lceil s/x \rceil$。多等只会让本次耗时增加，且不改变 $x$（$x$ 只在开锁后变化），对后续状态没有任何收益，故最优解中每把锁都在首次可开时立刻打开。∎

**引理 2（顺序决定总耗时）**：给定开锁顺序 $\pi = (\pi_0, \pi_1, \dots, \pi_{n-1})$，总耗时为

$$T(\pi) = \sum_{t=0}^{n-1} \left\lceil \frac{\text{strength}[\pi_t]}{1 + tk} \right\rceil$$

**证明**：由题意，$x$ 初值 $1$，每开一把锁后加 $k$，故第 $t$ 把锁的因子必为 $1 + tk$，与具体开了哪些锁无关。由引理 1，第 $t$ 把锁耗时 $\lceil \text{strength}[\pi_t] / (1 + tk) \rceil$，求和即得。∎

**引理 3（DP 不变式）**：对任意集合 $S$，DP 结束后 $dp[S]$ 等于「恰好在 $S$ 上完成开锁、按某种顺序开完 $S$ 中所有锁」的最小总耗时；$dp[S] = +\infty$ 表示不可能（此处不会发生）。

**证明**：对 $|S|$ 归纳。$|S| = 0$ 时 $dp[\varnothing] = 0$，显然。设 $|S| = t \ge 1$，考虑 $S$ 中最优顺序的**最后一把**锁 $i$（必有 $i \in S$），则前缀 $S \setminus \{i\}$ 也必须是其自身的最优顺序（否则替换前缀得到更小的 $T(S)$，与最优性矛盾）。而 $i$ 的因子为 $1 + (t-1)k$，由引理 1 耗时为 $\lceil \text{strength}[i] / (1 + (t-1)k) \rceil$。因此

$$dp[S] = \min_{i \in S} \Big( dp[S \setminus \{i\}] + \left\lceil \frac{\text{strength}[i]}{1 + (t-1)k} \right\rceil \Big)$$

这与算法中「从 $S \setminus \{i\}$ 转移到 $S$」的式子完全一致（算法里写成 $t' = |S \setminus \{i\}|$、$x = 1 + t'k$，正是同一个公式），且所有可能的 $i$ 都被枚举。∎

**定理**：算法返回的值等于打开全部 $n$ 把锁所需的最少分钟数。

**证明**：任何合法的开锁方案都对应某一个顺序 $\pi$，其总耗时由引理 2 给出为 $T(\pi)$；由引理 3，$dp[2^n - 1]$ 是所有顺序总耗时中的最小值，故等于最优值。∎

> 💡 顺带说明：引理 2 表明「方案」与「顺序」一一对应，所以本题本质上是**排列最优化**问题，状压 DP 之所以可行，是因为代价函数只依赖「已开锁数量」（引理 1 的因子公式）。

## 6. 复杂度分析

- **状态数**：$2^n$ 个；每个状态枚举 $n$ 个候选锁做转移，转移 $O(1)$。
- **时间**：$O(2^n \cdot n)$。$n = 8$ 时为 $256 \times 8 = 2048$ 次转移，可忽略不计。相比枚举全排列的 $O(n! \cdot n) \approx 3.2 \times 10^5$，快了约两个数量级。
- **空间**：$O(2^n)$ 的 `dp` 数组（外加 $O(1)$ 的辅助变量）；$n = 8$ 时仅 256 个 `int`。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    int findMinimumTime(vector<int>& strength, int k) {
        int n = (int)strength.size();
        int full = 1 << n;
        const int INF = 0x3f3f3f3f;
        vector<int> dp(full, INF);
        dp[0] = 0;
        for (int mask = 0; mask < full; mask++) {
            if (dp[mask] == INF) continue;
            int broken = __builtin_popcount(mask);
            int x = 1 + broken * k;
            for (int i = 0; i < n; i++) {
                if (mask >> i & 1) continue;
                int cost = (strength[i] + x - 1) / x;
                int nxt = mask | (1 << i);
                dp[nxt] = min(dp[nxt], dp[mask] + cost);
            }
        }
        return dp[full - 1];
    }
};
```

### Python

```python
class Solution:
    def findMinimumTime(self, strength: list[int], k: int) -> int:
        n = len(strength)
        INF = float("inf")
        dp = [INF] * (1 << n)
        dp[0] = 0
        for mask in range(1 << n):
            if dp[mask] == INF:
                continue
            broken = bin(mask).count("1")
            x = 1 + broken * k
            for i in range(n):
                if mask >> i & 1:
                    continue
                cost = (strength[i] + x - 1) // x
                nxt = mask | (1 << i)
                if dp[mask] + cost < dp[nxt]:
                    dp[nxt] = dp[mask] + cost
        return dp[(1 << n) - 1]
```

## 8. 边界情况与易错点

1. **上取整的边界**：`strength[i]` 恰好是 $x$ 的倍数时，`(s + x - 1) / x` 与 `s / x` 相同，不要写成 `s / x + 1`（那样会多算一分钟）。
2. **舍入写法**：不要用浮点 `ceil`，也不要先算除法再判余数时漏掉「余数为 0」这一支；整数上取整公式最稳。
3. **贪心的诱惑**：示例 1 就是「强锁优先」的反例（贪心得 7，最优 4）。**必须搜索顺序**，不要写 `sort + 累加`。
4. **状态次序**：$S$ 的数值序遍历已经满足转移方向（只增位），不要用「按集合大小」而写错下标。
5. **$t$ 的取法**：$t$ 是**当前**已破锁数量，不是「正在破第几把」的 1-indexed；写成 $1 + (t+1)k$ 会让第一步的因子变成 $1+k$。
6. **$n = 1$**：答案为 $\lceil \text{strength}[0] / 1 \rceil = \text{strength}[0]$，代码应自动给出。
7. **答案范围**：最大约 $8 \times 10^6$，`int` 足够；但若把 II 版的 $n$ 放大，记得同步扩大类型。
