# LeetCode 最小化数组中的最大值 题解

## 1. 题目概述

- **标题 / 题号**：最小化数组中的最大值（#2439，medium）
- **链接**：https://leetcode.cn/problems/minimize-maximum-of-array/
- **来源**：LeetCode 第 89 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、二分查找、动态规划、前缀和

**题意**：给定长度为 $n$ 的非负整数数组 `nums`。一次操作是：选择某个 $i$（$1 \le i < n$）且 $\text{nums}[i] > 0$，把 $\text{nums}[i]$ 减 1、$\text{nums}[i-1]$ 加 1——即**把一个单位的值向左搬一格**。可以执行任意次操作，求最终数组中**最大值最小**能是多少。

**约束**：

- $n = \text{nums.length}$，$2 \le n \le 10^5$
- $0 \le \text{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [3,7,1,6]
输出：5
解释：i=1: [4,6,1,6] → i=3: [4,6,2,5] → i=1: [5,5,2,5]，
      最大值 5。可以证明无法更小。
```

**示例 2**

```text
输入：nums = [10,1]
输出：10
解释：值只能向左搬，位置 0 的 10 只会更大，不动是最优，最大值 10。
```

**补充示例**

```text
输入：nums = [1,1,10]
输出：4
解释：从右往左级联搬运：10 中的 6 个单位经位置 1 流向位置 0，
      得到 [4,4,4]，最大值 4 = ⌈12/3⌉。
```

## 3. 解题思路

### 3.1 暴力思路

操作可以把任意多个单位向左搬任意远，状态空间极大，直接 BFS 不现实。一个可靠的暴力框架是**二分答案 + 贪心检查**：猜测最大值上限 $m$，从右往左扫一遍，把每个位置的超出部分往左推（§3.3），检查位置 0 是否被压垮，$O(n)$ 判定可行性，$O(n \log V)$ 出答案。这是本题的正解之一；但若注意到「前缀和」的单调结构，还能再省一个 $\log$。

### 3.2 核心观察：值只向左流，瓶颈是每个前缀的平均值

![核心观察：前缀均值是瓶颈](images/bw89_q3_prefix_avg_ceiling.svg)

操作只把值从 $i$ 搬到 $i-1$，方向**永远向左**。于是对任何 $k$（$1 \le k \le n$），**前 $k$ 个位置的总和只增不减**（搬进前缀的比搬出的多，见 §5 引理 1）。若最终最大值为 $M$，则前 $k$ 个位置的最终总和 $\le k \cdot M$，于是

$$k \cdot M \ \ge\ P_k \triangleq \sum_{j=0}^{k-1} \text{nums}[j] \quad\Longrightarrow\quad M \ \ge\ \left\lceil \frac{P_k}{k} \right\rceil$$

对所有 $k$ 取最大，得到答案下界 $m^\* = \max_k \lceil P_k / k \rceil$。奇妙的是这个下界**总能取到**（§5 定理给出构造性证明），所以答案就是

$$\boxed{\ \text{answer} = \max_{1 \le k \le n} \left\lceil \frac{\text{nums}[0] + \cdots + \text{nums}[k-1]}{k} \right\rceil\ }$$

一遍扫描维护前缀和即可，$O(n)$、无需二分。

### 3.3 算法流程（两种等价实现）

![二分答案 + 右到左贪心 check 的流程](images/bw89_q3_binary_check_flow.svg)

**一遍扫描版（推荐）**

```text
pre = 0, ans = 0
for i = 0 .. n-1:
    pre += nums[i]
    ans = max(ans, ⌈pre / (i+1)⌉)     # (pre + i) / (i+1) 整数向上取整
返回 ans
```

**二分答案版（备用）**

```text
在 [max ⌈P_k/k⌉ ... 也可直接 [0, max(nums)] 上二分 m：
check(m)：carry = 0；for i = n-1 downto 1：
    cur = nums[i] + carry
    carry = max(0, cur - m)      # 超出部分必须继续向左推
若 nums[0] + carry <= m 则 m 可行
```

### 3.4 示例演算

![示例 nums 为 3,7,1,6 的前缀均值演算表](images/bw89_q3_example_walkthrough.svg)

对 `nums = [3,7,1,6]`，前缀和 $P = [3, 10, 11, 17]$：

| $k$ | 前缀和 $P_k$ | $\lceil P_k / k \rceil$ |
|-----|-------------|------------------------|
| 1 | 3 | 3 |
| 2 | 10 | 5 |
| 3 | 11 | 4 |
| 4 | 17 | 5 |

最大值为 $m^\* = 5$。相应构造：位置 1 的 7 搬 2 个单位到位置 0 得 `[5,5,1,6]`，再把位置 3 的 6 搬 1 个单位到位置 2 得 `[5,5,2,5]`——最大值恰 5。而 `[10,1]`：$P = [10, 11]$，$\lceil 10/1 \rceil = 10$ 已无法逾越，答案 10；`[1,1,10]`：$\lceil 12/3 \rceil = 4$ 支配一切，答案 4。

## 4. 算法细节

1. **整数向上取整**：$\lceil a/b \rceil = \lfloor (a + b - 1) / b \rfloor$；这里 $b = i+1$，故写成 `(pre + i) / (i + 1)`，全程整数运算，避开浮点。
2. **前缀和用 64 位**：$P_k$ 最大 $10^5 \times 10^9 = 10^{14}$，超出 `int`/`int32` 范围，C++ 必须用 `long long` 累加（答案本身 $\le 10^9$ 可以转回 `int`）。
3. **不需要真正执行操作**：公式直接给出最优值；构造性证明（§5）说明对应的操作序列存在，代码无需模拟。
4. **二分版 check 的方向**：必须**从右往左**检查——超出的值只能往左推，右边的超载会一路传给位置 0；从左往右则无法处理尚未见到的右侧入流。check 内 `carry` 记录「从右边推过来的量」。
5. **两版互为对拍**：一遍扫描公式与二分 check 在数学上等价（§5 引理 2），实现后用随机数据互相验证最稳。
6. **动态规划视角**：官方标签含 DP，本质是把「前 $i$ 个位置的最小可能最大值」作为子问题，转移恰是前缀均值取 max 的滚动形式，两种视角殊途同归。

## 5. 正确性证明

**引理 1（前缀和单调不减）**：任意一次操作（$i \to i-1$ 搬 1 个单位）对每个前缀和 $P_k$（前 $k$ 个位置之和）的影响是「不变或 +1」，故任意操作序列后仍有 $P_k \ge P_k^{(0)}$（初始值）。

**证明**：操作影响位置 $i-1$（+1）与 $i$（−1）。若 $i \le k - 1$，两个位置都在前 $k$ 内，$P_k$ 不变；若 $i = k$，+1 落在前缀内而 −1 在外，$P_k$ 增加 1；若 $i > k$，两者都在前缀外，$P_k$ 不变。不存在使 $P_k$ 减小的情形。∎

**引理 2（贪心 check 的等价刻画）**：右到左检查 `check(m)` 返回可行，当且仅当对所有 $1 \le k \le n$ 有 $P_k^{(0)} \le k \cdot m$。

**证明**：记从位置 $i$ 推向 $i-1$ 的总量为 $d(i)$（$i \ge 1$），约束为 $d(i) \ge 0$（只能左推）且非负值保证操作可实现。可行性「存在操作序列使最终每个位置 $\le m$」等价于存在 $d(\cdot)$ 满足最终值 $\text{nums}[i] + d(i+1) - d(i) \le m$（位置 0 无出流：$\text{nums}[0] + d(1) \le m$）。从右往左取最小可行 $d$：$d(i) = \max(0,\ \text{nums}[i] + d(i+1) - m)$（$d(n) = 0$），逐层展开得 $d(1) = \max_{j \ge 1}\big(0,\ \sum_{t=1}^{j} \text{nums}[t] - j \cdot m\big)$，从而位置 0 条件为 $\text{nums}[0] + d(1) \le m$，即对一切 $j$：$\sum_{t=0}^{j} \text{nums}[t] \le (j+1) m$——恰是 $P_{j+1}^{(0)} \le (j+1)m$。反之若该条件成立，上述 $d$ 即合法方案（每步推走的部分不超过现存值，操作可实现）。∎

**定理（答案公式）**：最优最大值恰为 $m^\* = \max_{1 \le k \le n} \lceil P_k^{(0)} / k \rceil$。

**证明**：下界：设最终最大值为 $M$。由引理 1，$P_k^{(0)} \le P_k^{\text{final}} \le k \cdot M$，故 $M \ge \lceil P_k^{(0)} / k \rceil$ 对每个 $k$ 成立，$M \ge m^\*$。上界：取 $m = m^\*$，则对每个 $k$，$P_k^{(0)} \le k \cdot m^\*$，由引理 2 知 check 可行，即存在合法操作序列使最大值 $\le m^\*$。两个方向合并即 $M_{\min} = m^\*$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一遍扫描，每个位置做一次加法、一次整数除法、一次比较。
- **空间**：$O(1)$。只维护前缀和、答案两个变量（二分版同阶：$O(n \log V)$ 时间、$O(1)$ 空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimizeArrayValue(vector<int>& nums) {
        long long pre = 0, ans = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            pre += nums[i];
            ans = max(ans, (pre + i) / (i + 1));   // 前缀平均值向上取整
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minimizeArrayValue(self, nums: list) -> int:
        pre = ans = 0
        for i, x in enumerate(nums):
            pre += x
            ans = max(ans, (pre + i) // (i + 1))   # 前缀平均值向上取整
        return ans
```

> 💡 两份代码均通过官方示例（`5`、`10`）；与「二分答案 + 右到左贪心 check」的独立实现在 5000 组随机数组（$n \le 60$、值 $\le 10^9$）上逐组一致，另与「穷举所有可达状态的 BFS」在 803 组小规模数组（$n \le 4$、值 $\le 3$）上逐组一致；$n = 10^5$ 极端规模 C++ 用时约 0.15s。

## 8. 边界情况与易错点

1. **溢出是头号陷阱**：前缀和可达 $10^{14}$，C++ `int` 直接爆；必须 `long long`（或 Python 天然大整数无碍）。
2. **向上取整别用浮点**：`(pre + i) / (i + 1)` 是整数写法；`ceil(pre * 1.0 / (i+1))` 在 $10^{14}$ 量级会有浮点误差，随机对拍能暴露。
3. **方向感**：值只能**向左**搬，所以 `[10,1]` 答案是 10 而不是 5——不要对称地幻想「向右也行」；反之 `[1,1,10]` 能降到 4，因为右侧的富余可以流过来。
4. **答案不必小于 max(nums)**：`[10,1]` 提醒你 $m^\*$ 可等于初始最大值；但也可小于它（`[1,1,10]`），不要拿 max(nums) 当下界。
5. **二分版 check 方向**：从左往右 check 是常见错法——右侧超载还未流入时左边看似安全，判可行会误判。必须从右往左，把 carry 传到位置 0。
6. **0 值**：`nums[i] = 0` 合法（非负数组），公式天然兼容；操作要求 `nums[i] > 0` 只限制「不能从空位置搬」，不影响公式推导（$d(i)$ 的构造不会从 0 位置搬出）。
