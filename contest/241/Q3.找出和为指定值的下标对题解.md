# LeetCode 找出和为指定值的下标对 题解

## 1. 题目概述

- **标题 / 题号**：找出和为指定值的下标对（#1865，medium）
- **链接**：https://leetcode.cn/problems/finding-pairs-with-a-certain-sum/
- **来源**：LeetCode 第 241 场周赛 Q3
- **难度**：中等
- **标签**：设计、数组、哈希表

**题意**：给定两个整数数组 `nums1` 与 `nums2`，实现数据结构 `FindSumPairs`，支持两类操作：

- `add(index, val)`：**单点更新**，执行 `nums2[index] += val`；
- `count(tot)`：**在线查询**，统计满足 `nums1[i] + nums2[j] == tot` 的下标对 `(i, j)` 数目（按下标计，重复值重复数）。

`nums1` 全程只读；`nums2` 只会被 `add` 单点修改。

**约束**：

- $1 \le \text{nums1.length} \le 1000$
- $1 \le \text{nums2.length} \le 10^5$
- $1 \le \text{nums1}[i] \le 10^9$，$1 \le \text{nums2}[i] \le 10^5$
- $1 \le \text{val} \le 10^5$，$1 \le \text{tot} \le 10^9$
- `add` 与 `count` 各最多调用 $1000$ 次

> 💡 本题在本仓库另有[每日题解 1865](../../solution/1801-1900/1865_找出和为指定值的下标对.md)：以「面试视角」展开——建表方向的权衡问答、C++ `operator[]` 与 `find` 的细节、排序 + 双指针为何不适合在线场景，以及面试问答。本篇按**周赛复盘视角**重写：侧重**赛时 30 秒读约束定方向**的设计题套路（三个数字 $1000 / 10^5 / 1000$ 一读，解法唯一）、**建表方向的三档复杂度算账**（$10^{11} / 10^8 / 10^6$）、**freq 不变式的归纳证明**，以及**值域膨胀、负数键**两个赛时隐蔽坑，两篇互为印证。

[null, 8, null, 2, 1, null, null, 11]

解释：
FindSumPairs([1, 1, 2, 2, 2, 3], [1, 4, 5, 2, 5, 4])

count(4) → 1     // 3 配 1 个 1

add(1, 1)         // nums2 = [2,5,5,4,5,4]

## 3. 解题思路

### 3.1 暴力思路：每次 count 双重遍历

`count(tot)` 时枚举全部 $(i, j)$ 判 `nums1[i] + nums2[j] == tot`：单次 $O(n_1 \cdot n_2) = 1000 \times 10^5 = 10^8$，而 `count` 最多 $1000$ 次，总量 $10^{11}$，必死。瓶颈在于**每次查询都把两个数组重新扫一遍**，而「哪些值出现了多少次」这一信息在操作之间几乎不变——本该被预处理复用。

### 3.2 核心观察：一短一长、一静一动，方向唯一

![核心观察：一短一长一静一动，频率表建在 nums2、count 枚举 nums1](images/findsumpairs_asymmetry_concept.svg)

设计题的赛时套路是**读约束定方向**。本题三个关键数字：$n_1 \le 1000$（短）、$n_2 \le 10^5$（长）、操作各 $\le 1000$ 次（查询量小）。两数组的不对称性直接给出分工：

- `nums1` **短且只读** → `count` 时逐个枚举它，单次 $O(n_1) = 10^3$；
- `nums2` **长且被 `add` 单点修改** → 对它维护一张**值频率哈希表** `freq`，`add` 只需两次计数器更新，$O(1)$。

于是查询公式为：

$$\text{count}(tot) = \sum_{x \,\in\, \text{nums1（按下标）}} \text{freq}[\,tot - x\,]$$

**建表方向的三档算账**（赛时在心里过一遍）：

| 方案 | 单次 `count` | 单次 `add` | 总量（各 1000 次） | 判定 |
|------|-------------|-----------|-------------------|------|
| 暴力双循环 | $O(n_1 n_2) = 10^8$ | $O(1)$ | $10^{11}$ | 必 TLE |
| 频率表建在 `nums1`，枚举 `nums2` | $O(n_2) = 10^5$ | $O(1)$（表不受 `add` 影响） | $10^8$ 次哈希查询 | C++ 赌常数，Python 必死 |
| **频率表建在 `nums2`，枚举 `nums1`** | $O(n_1) = 10^3$ | $O(1)$（两次计数器） | $\approx 10^6$ | 稳过 |

两个方向都能把双循环拆成「枚举一侧 + 查另一侧的表」，差别只在**枚举谁**：短的一侧是 $10^3$、长的一侧是 $10^5$，相差 100 倍。又因为 `add` 恰好只修改 `nums2`（即建表的那侧），频率表的维护天然是 $O(1)$ 增删——**两个不对称性指向同一个方向**，这就是本题 30 秒内该锁定的结论。

> 💡 「枚举一半 + 哈希查另一半」是两数之和家族的通用骨架（[1. 两数之和](https://leetcode.cn/problems/two-sum/)、[454. 四数相加 II](https://leetcode.cn/problems/4sum-ii/)）；本题加上「**在线 + 单点更新**」约束后，骨架升级为「可增量维护的频率表 + 枚举短的一侧」。

### 3.3 算法流程：三个操作各司其职

![算法流程：init 建表、add 三步 O(1) 维护、count 枚举查表](images/findsumpairs_ops_flow.svg)

- **构造**：保存两个数组引用，遍历 `nums2` 建 `freq`。$O(n_2)$，一次性。
- **`add(index, val)`**：**记旧 → 减旧 → 改数组 → 加新** 四步，$O(1)$。顺序是硬约束：先改了 `nums2[index]` 就永远找不回旧值，`freq` 从此与数组脱节。
- **`count(tot)`**：`ans` 清零，枚举 `nums1` 每个 $x$ 累加 `freq[tot - x]`（查不到按 0 计），$O(n_1)$。

### 3.4 示例演算

![示例演算：操作序列下 freq 快照与 count 分解](images/findsumpairs_walkthrough.svg)

对示例 1 逐步走查，重点看两件事：`add` 每次只动 `freq` 的两个键；`count(7)` 前后两次的分解对比：

- 初始 `freq = {1:1, 2:1, 4:2, 5:2}`，`count(7) = 3 \times \text{freq}[5] + 1 \times \text{freq}[4] = 6 + 2 = 8`（`x=1` 的两项查 `freq[6] = 0`，贡献 0）；
- 三次 `add` 后 `freq = {2:1, 4:2, 5:3}`，同一公式得 `3 \times 3 + 2 = 11`。

## 4. 算法细节

1. **必须哈希表，不能值域数组**。想用 `freq[10^5+1]` 的数组换常数是个陷阱：`add` 可以全部砸在同一下标上，$1000 \times 10^5$ 的累计增量能把单值推到 $10^8$ 量级，值域数组要数百 MB，直接 MLE。而哈希表的键数有天然上界——任一时刻计数非零的键不超过 $n_2$ 个（每键至少对应一个位置），即使从不清理归零键，也只多出至多 1000 个 `add` 产生的新值，空间仍是 $O(n_2 + q)$（$q$ 为 `add` 次数）。
2. **`add` 四步顺序**：`old = nums2[index]` → `freq[old] -= 1` → `nums2[index] += val` → `freq[nums2[index]] += 1`。核心是**先把旧值握在手里再改数组**。
3. **查询键可以为零或负**：$\text{tot} - x$ 在 $x > \text{tot}$ 时为负（$\text{nums1}[i]$ 可达 $10^9 > \text{tot}$）。哈希表查不到返回默认 0，天然正确；若误用数组下标且无偏移，直接越界。
4. **重复元素按下标计数**：`count` 枚举的是 `nums1` 的全部 $n_1$ 个位置（`x=2` 出现 3 次就贡献 $3 \times \text{freq}[5]$），`freq` 数的也是 `nums2` 的位置。若想「优化」成枚举 `nums1` 的**去重值**，必须聚合成（值, 出现次数）对、查询时乘上次数——只去重不乘次数，示例 1 的 `count(7)` 会算成 $0 + 2 + 2 = 4$ 而不是 8。
5. **C++ 查表用 `find`**：`freq[tot - x]` 的 `operator[]` 会在键缺失时**插入 0**，1000 次 `count` × 1000 个元素最多插入 $10^6$ 个垃圾键，表被撑大、后续操作变慢；`find` 只读不插。

## 5. 正确性证明

**引理 1（不变式）**：任一操作序列执行完毕后，对任意整数 $v$，

$$\text{freq}[v] = \#\{\, j \in [0, n_2) : \text{nums2}[j] = v \,\}$$

**证明**：对已执行的操作数归纳。**基础**：构造函数逐个执行 `freq[nums2[j]]++`，结束时每个 $v$ 的计数恰为其在 `nums2` 中的出现次数，不变式成立。**归纳步**：设某次 `add(index, val)` 执行前不变式成立，记旧值 $u = \text{nums2}[\text{index}]$。该操作仅改变这一个位置的值 $u \to u + \text{val}$：执行 `freq[u] -= 1` 使值 $u$ 的计数减一（该位置不再贡献 $u$），执行 `freq[u + \text{val}] += 1` 使新值计数加一（该位置改为贡献新值），其余值的计数不变——恰为更新后 `nums2` 的分布。`count` 不修改 `freq` 与 `nums2`，保持不变式。∎

**定理**：`count(tot)` 返回 $\#\{(i, j) : \text{nums1}[i] + \text{nums2}[j] = \text{tot}\}$。

**证明**：对每个固定下标 $i$，由引理 1，

$$\text{freq}[\text{tot} - \text{nums1}[i]] = \#\{\, j : \text{nums2}[j] = \text{tot} - \text{nums1}[i] \,\} = \#\{\, j : \text{nums1}[i] + \text{nums2}[j] = \text{tot} \,\}$$

（键不存在时 `freq` 按 0 计，与计数为 0 一致。）对 $i = 0, 1, \dots, n_1 - 1$ 求和：每个满足条件的对 $(i, j)$ 恰在第 $i$ 项被计入一次（第 $i$ 项数的就是「与固定的 $\text{nums1}[i]$ 配对的 $j$」），不同项计入的是不同 $i$ 的对，**不重不漏**，故总和即为所求对数。∎

## 6. 复杂度分析

- **时间**：构造 $O(n_2) = 10^5$；每次 `add` $O(1)$，共 $\le 10^3$；每次 `count` $O(n_1) = 10^3$ 次哈希查询，共 $\le 10^6$。总计约 $1.1 \times 10^6$ 次基本操作，远低于时限。
- **空间**：`freq` 的键数 $\le n_2 + q \approx 10^5$，即 $O(n_2)$；数组本体按引用保存即可（C++ 值拷贝也仅 $O(n_1 + n_2)$）。
- **对比**：方向选反（表建 `nums1`）时总量为 $10^8$ 次哈希查询——同为「哈希查一半」，枚举长侧还是短侧的差别，就是 TLE 与稳过的差别。

## 7. 参考代码

### C++

```cpp
class FindSumPairs {
    vector<int> nums1, nums2;
    unordered_map<int, int> freq;               // nums2 的值频率表
public:
    FindSumPairs(vector<int>& nums1, vector<int>& nums2)
        : nums1(nums1), nums2(nums2) {
        for (int x : this->nums2) freq[x]++;    // O(n2) 建表
    }

    void add(int index, int val) {
        int old = nums2[index];
        if (--freq[old] == 0) freq.erase(old);  // 旧值减一（归零删键，可省略）
        nums2[index] += val;                    // 再改数组
        freq[nums2[index]]++;                   // 新值加一
    }

    int count(int tot) {
        int ans = 0;
        for (int x : nums1) {                   // 枚举短的 nums1
            auto it = freq.find(tot - x);       // find 只读，不插垃圾键
            if (it != freq.end()) ans += it->second;
        }
        return ans;
    }
};
```

### Python

```python
from collections import Counter


class FindSumPairs:

    def __init__(self, nums1: List[int], nums2: List[int]):
        self.nums1 = nums1
        self.nums2 = nums2
        self.freq = Counter(nums2)              # O(n2) 建表

    def add(self, index: int, val: int) -> None:
        old = self.nums2[index]
        self.freq[old] -= 1                     # 先减旧
        self.nums2[index] += val                # 再改数组
        self.freq[self.nums2[index]] += 1       # 后加新

    def count(self, tot: int) -> int:
        ans = 0
        for x in self.nums1:                    # 枚举短的 nums1
            ans += self.freq.get(tot - x, 0)    # 缺键按 0 计（tot-x 可为负/零）
        return ans
```

## 8. 边界情况与易错点

1. **`add` 四步顺序**：先改数组会丢旧值，`freq` 从此脱节、后续 `count` 静默出错。以官方样例实测：错序版在 `add(3,2)` 后 `freq[2]` 残留为 1，`count(8)` 碰巧仍输出 2（查不到脏键 `2` 和 `4`），但 `count(4)` 会算出 $3 \times 1 + 1 = 4 \ne 1$，第三个输出即暴露——**中途碰巧正确不等于没错**，务必跑完整样例。
2. **建表方向**：表建 `nums1` 在逻辑上完全自洽（`add` 甚至不用动表），但 `count` 枚举 $10^5$ 的长侧，$10^8$ 次哈希查询连 C++ 都要赌常数——「过样例、提交 TLE」的典型，读约束时就该把方向定死。
3. **值域数组 MLE 陷阱**：见 §4 第 1 点。$10^5$ 的初始值域是**假上界**，1000 次 `add` 能把单值推到 $10^8$ 量级。
4. **负数 / 零键**：`tot - x` 可为负（$x$ 最大 $10^9$），哈希表无碍，数组下标必炸。
5. **C++ `operator[]` 污染**：见 §4 第 5 点。正确性不受影响（插入的是 0），但表膨胀拖慢后续查询。
6. **去重必须带次数**：只去重不乘出现次数，示例 1 的 `count(7)` 得 4 而非 8。
7. **构造时建表对象是 `nums2`**：手滑写成 `Counter(nums1)` 会让 `add` 的维护逻辑与表对不上——第一次 `add` 之后 `freq` 就不再反映任何数组的真实分布。
