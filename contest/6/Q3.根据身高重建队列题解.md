# LeetCode 根据身高重建队列 题解

## 1. 题目概述

- **标题 / 题号**：根据身高重建队列（#406，medium）
- **链接**：https://leetcode.cn/problems/queue-reconstruction-by-height/
- **来源**：LeetCode 第 6 场周赛 Q3
- **难度**：中等
- **标签**：数组、排序、树状数组、线段树

**题意**：$n$ 个人被打乱顺序，每人给出二元组 $(h_i, k_i)$，表示他的身高为 $h_i$，且在**最终队列**中排在他前面、身高**大于或等于** $h_i$ 的人恰好有 $k_i$ 个。要求把这些二元组排成一个满足所有人约束的队列，返回任意一个合法队列（数据保证至少存在一个）。

**约束**：

- $1 \le n \le 2000$
- $0 \le h_i \le 10^6$
- $0 \le k_i < n$
- 题目数据确保队列可以被重建

> 💡 「大于等于」而非「大于」是本题的关键字：等高的人**互相可见**，所以同身高的人之间有严格的前后顺序限制（见引理 1）。

## 2. 示例

**示例 1**

```text
输入：people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]
输出：[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]
解释：逐位核对输出队列（「身前」指排在前面的人）
  (5,0) 身前无人            → 身高 ≥5 的 0 个 ✓
  (7,0) 身前 [5]            → 身高 ≥7 的 0 个 ✓
  (5,2) 身前 [5,7]          → 身高 ≥5 的 2 个 ✓
  (6,1) 身前 [5,7,5]        → 身高 ≥6 的 1 个 ✓
  (4,4) 身前 [5,7,5,6]      → 这 4 人全都 ≥4 ✓
  (7,1) 身前 [5,7,5,6,4]    → 身高 ≥7 的 1 个 ✓
```

**示例 2**

```text
输入：people = [[6,0],[5,0],[4,0],[3,2],[2,2],[1,4]]
输出：[[4,0],[5,0],[2,2],[3,2],[1,4],[6,0]]
解释：身高 6 最高且 k = 0（没有比他更高的人），可以站在最后；
      身高 1 最矮，前面 4 人身高全都 ≥1，故 k = 4 把他钉在下标 4。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `people` 的全部 $n!$ 种排列，对每个排列用 $O(n^2)$ 逐人统计 $k$ 是否吻合：总复杂度 $O(n! \cdot n^2)$。$n = 2000$ 时连一个排列都检查不完。

暴力里藏着正确解法的线索：约束**只和「身高 $\ge h$ 的人」有关**，而身高更矮的人对高个子完全不可见。既然如此，能不能从最高的人开始，一个一个把人钉死在最终位置上？

### 3.2 核心观察：高个子看不见矮个子（降序插入）

![核心观察：高个子看不见矮个子](images/wc6_q3_greedy_insert_model.svg)

把 `people` 按身高**从高到低**排序，依次处理每个人 $(h,k)$。此时「已经就位的人」恰好就是「身高 $\ge h$ 的人」，于是：

- 当前队列长度为 $t$（合法数据保证 $k \le t$），把 $(h,k)$ 插到下标 $k$，前面正好有 $k$ 个身高 $\ge h$ 的人 —— **$k$ 直接就是插入下标**，一步到位；
- 之后插入的人身高 $h' \le h$。若 $h' < h$，即使插在他前面也不计入「$\ge h$」，不影响他；若 $h' = h$，则 $h'$ 的 $k$ 更大（同身高的 $k$ 互不相同且递增），落点在更靠后的下标，同样不影响他。

剩下一个必须交代的细节：**同身高要按 $k$ 升序**。等高的两个人里 $k$ 小的必须先落位，否则后插的人会把先落位者往后挤，二者会同时错位。

### 3.3 算法流程

![算法流程：排序一次 + 逐个插入](images/wc6_q3_algorithm_flow.svg)

```text
1. people.sort(key = (-h, k))          # 身高降序，同身高 k 升序
2. res ← []
3. for (h, k) in people:
4.     res.insert(k, (h, k))           # 下标从 0 开始，等价于「插到第 k 位」
5. return res
```

整个算法只有一个动作：**插到第 $k$ 位**。因为处理顺序是身高降序，res 里的每个人都满足自己的 $k$，而新插入者的身高不高于在场的每个人，所以插入不会破坏任何已有约束；等高的情形由排序键兜底。每一步都是终态，不需要回溯。

### 3.4 示例演算

![示例 1 演算：6 步插入](images/wc6_q3_example_walkthrough.svg)

对示例 1 排序得到 $(7,0),(7,1),(6,1),(5,0),(5,2),(4,4)$，逐步插入：

| 步骤 | 处理的人 | 插入位置 | 插入后的队列 |
|------|----------|----------|--------------|
| 1 | (7,0) | 0 | (7,0) |
| 2 | (7,1) | 1 | (7,0) (7,1) |
| 3 | (6,1) | 1 | (7,0) (6,1) (7,1) |
| 4 | (5,0) | 0 | (5,0) (7,0) (6,1) (7,1) |
| 5 | (5,2) | 2 | (5,0) (7,0) (5,2) (6,1) (7,1) |
| 6 | (4,4) | 4 | (5,0) (7,0) (5,2) (6,1) (4,4) (7,1) |

第 5 步值得单看：$(5,2)$ 之前已经站着 $(5,0)$ 与 $(7,0)$ 两个身高 $\ge 5$ 的人，插入下标 2 正好落在他们之后、$(6,1)$ 之前。第 6 步的 $(4,4)$ 身高最低，前面 4 人全部比他高，插到下标 4 即满足。最后一行与示例输出完全一致。

## 4. 算法细节

1. **排序键不能写反**：键是 $(-h, k)$，即身高降序、$k$ 升序。若把 $k$ 也写成降序，最高那一组的第一个人 $k > 0$，而此刻数组还是空的，下标 $k$ 就会越界（C++ `vector::insert` 是未定义行为；Python 的 `list.insert` 则把越界下标悄悄夹到末尾，给出一个错得很安静的答案）。
2. **插入下标必然合法**：设身高 $\ge h$ 的人共 $m$ 个（含自己），轮到他时 res 长度恰为 $m-1$；合法队列里他前面全是身高 $\ge h$ 的人，数量不超过 $m-1$，故 $k \le m-1 = \text{res.size()}$。「数据保证可重建」正是这条不等式成立的前提。
3. **数据结构**：动态数组即可（C++ `vector`、Python `list`）。`insert` 需要把插入点之后的元素整体后移，单次 $O(t)$，$n$ 次共 $O(n^2)$；$n = 2000$ 时总搬移量约 $\sum_{t=1}^{n} t \approx 2\times10^6$，实测 $n = 2000$ 时 Python 约 1 ms、C++ 约 0.1 ms。
4. **不要为本题上树状数组**：$O(n^2)$ 的常数极小，硬换成「树状数组求第 $k$ 个空位」既多写几十行，又要把同身高的落点补偿算清楚（见「延伸思考」），性价比不高；只有当 $n$ 升到 $10^5$ 量级时才值得。
5. **原地排序的副作用**：LeetCode 传入的是引用/可变列表，原地排序不影响判题；但本地对拍、多次调用同一数组时需要先拷贝一份，否则第二次调用拿到的是已排好序的输入。
6. **同身高的 $k$ 互不相同**：这是数据可重建的必要条件（引理 1），也是「同身高按 $k$ 升序」不会出现两个相等插入位置、从而不会互相挤位的原因。
7. **不需要额外校验**：题目保证可重建，构造完直接返回；若数据不保证，最后扫一遍 $O(n^2)$ 核对即可，不必在插入过程中做判断。

## 5. 正确性证明

**引理 1（同身高者的先后）**：若两人身高同为 $h$ 且 $k_i < k_j$，则任何合法队列中 $i$ 必在 $j$ 之前。特别地，同一身高的 $k$ 两两不同。

**证明**：反设 $j$ 排在 $i$ 之前。那么 $j$ 之前的每个人都排在 $i$ 之前；又因为两人身高同为 $h$，$j$ 本人也计入 $i$ 的 $k$。于是

$$k_i=\#\{q \text{ 在 } i \text{ 之前} : h_q \ge h\} \ge \#\{q \text{ 在 } j \text{ 之前} : h_q \ge h\} + 1 = k_j + 1 > k_j,$$

与 $k_i < k_j$ 矛盾。∎

**引理 2（插入不越界）**：排序后处理 $(h,k)$ 时，$k \le \text{res.size()}$。

**证明**：记身高 $\ge h$ 的人数为 $m$，则此刻 `res` 恰好装了这 $m$ 人中的 $m-1$ 个。合法队列中该人身前只有身高 $\ge h$ 的人，故 $k \le m-1$。∎

**引理 3（不变量）**：设身高为 $h$ 的一组刚刚处理完。则 `res` 中所有身高 $\ge h$ 的人，其「身前身高 $\ge$ 自身身高的人数」都等于各自的 $k$。

**证明**：对身高从大到小归纳。设当前组身高为 $h$，组内已按 $k$ 升序排列（引理 1 保证互不相同）。

- 处理前（归纳假设）：`res` 中身高 $> h$ 的人已满足约束；且 `res` 中每个元素的身高都 $> h$。
- 组内第 $r$ 个元素 $(h,k_r)$ 插入时，队内身高全都 $\ge h$；它被插到下标 $k_r$，于是身前的 $k_r$ 个元素身高都 $\ge h$，计数恰为 $k_r$（满足本人约束），且它自己的下标就是 $k_r$。
- 由于 $k_1 < k_2 < \cdots$，第 $r$ 个元素的下标 $k_r$ 大于此前所有同组元素的下标，插入不会把它们后移；同时新元素身高 $h$ 不大于任何已就位者的身高，对身高 $> h$ 的人来说，即使被后移，身前计数也不变（新元素更矮，不计数）。
- 归纳成立。∎

**定理**：算法返回的 `res` 是满足全部约束的合法队列。

**证明**：每个人恰好被插入一次，故 `res` 是 `people` 的一个排列。取最后一个身高组（最矮的一组）处理完毕的时刻，此时全部 $n$ 人都已插入，由引理 3，每个人身前身高 $\ge$ 自身的人数等于其 $k$。故 `res` 合法。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。排序 $O(n \log n)$；插入 $n$ 次，第 $t$ 次插入搬移 $O(t)$ 个元素，合计 $\sum_{t=1}^{n} O(t) = O(n^2)$。$n = 2000$ 时约 $2 \times 10^6$ 次元素搬移。
- **空间**：$O(n)$。结果数组存 $n$ 个二元组；排序为原地排序，额外栈空间 $O(\log n)$（不计入输入）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<vector<int>> reconstructQueue(vector<vector<int>>& people) {
        // 身高降序；同身高时 k 升序
        sort(people.begin(), people.end(), [](const vector<int>& a, const vector<int>& b) {
            if (a[0] != b[0]) return a[0] > b[0];
            return a[1] < b[1];
        });
        vector<vector<int>> res;
        res.reserve(people.size());
        for (const auto& p : people) {
            res.insert(res.begin() + p[1], p);   // 插到下标 k，等价于「插到第 k 位」
        }
        return res;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def reconstructQueue(self, people: List[List[int]]) -> List[List[int]]:
        people.sort(key=lambda p: (-p[0], p[1]))   # 身高降序，同身高 k 升序
        res = []
        for p in people:
            res.insert(p[1], p)                    # 插到下标 k
        return res
```

## 8. 边界情况与易错点

1. **$n = 1$**：`people = [[h,0]]`，插到下标 0 后直接返回；此时 $k$ 必须是 0，数据可重建保证这一点。
2. **$k$ 恰等于当前长度**：此时 `insert` 等价于追加到末尾，属于合法情形。例如 `[[2,0],[1,1]]`：先放 $(2,0)$，再处理 $(1,1)$ 时 $k = 1 = \text{res.size()}$，追加得 `[[2,0],[1,1]]`。
3. **排序键符号写错**：`(-h, k)` 写成 `(h, k)` 会变成从矮到高插入，$k$ 不再等于插入下标；写成 `(-h, -k)` 则会在空数组上越界（C++ UB，Python 静默夹到末尾）。这两个错法都很难通过样例自查发现。
4. **误把 $k$ 当下标以外的含义**：$k$ 是「身前 $\ge$ 他的人数」，能直接当插入下标用，靠的是「已插入的人恰好就是身高 $\ge$ 他的人」这一降序性质，不能脱离处理顺序单看。
5. **不要用 map/集合去重**：同身高的人可能有不同的 $k$，每个人都是一条独立记录，必须全部插入，否则长度都不对。
6. **不要边插入边改 $k$**：本题不需要维护「已插入几人」之类的补偿量，插第 $k$ 位即可；一旦引入补偿反而容易与同身高的顺序规则打架。
7. **Python 的 `people.sort` 原地改写入参**：对拍/多次调用时记得传副本，否则第二次拿到的是排序后的输入（本题结果不变，但不利于排查）。

**延伸思考**

1. **$O(n \log n)$ 版本**：把「插到第 $k$ 位」换成「坐到第 $k$ 个空位」，用树状数组上二分定位空位。注意方向要反过来：**升序**处理身高、同身高仍按 $k$ 升序，且落点是第 $k-e$ 个空位（空位从 0 开始数），$e$ 为该身高已经落座的人数 —— 同身高的人彼此可见，他们贡献了 $e$ 个「身前 $\ge$ 自己」的人，余下 $k-e$ 个空位由随后落座的高个子填充。
2. **逆问题**：给一个队列反求 `people`，只需统计每个人身前 $\ge$ 他的人数，$O(n^2)$ 暴力即可；按身高分组后用树状数组可以做到 $O(n \log n)$，正是 315 的做法。
3. **为什么必须从高到低**：从矮到高处理时，已就位的人对当前人「不可见」的部分变多，插入下标不再等于 $k$，必须额外记录空位与同身高人数（即上面 $O(n \log n)$ 版本里的 $e$）。「降序」才是让「$k$ 就是插入下标」成立的根本原因。
