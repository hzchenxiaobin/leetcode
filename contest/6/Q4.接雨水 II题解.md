# LeetCode 接雨水 II 题解

## 1. 题目概述

- **标题 / 题号**：接雨水 II（#407，hard）
- **链接**：https://leetcode.cn/problems/trapping-rain-water-ii/
- **来源**：LeetCode 第 6 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、优先队列（堆）、数组、矩阵

**题意**：给定 $m \times n$ 的非负整数矩阵 `heightMap` 表示每根柱子的高度，问下雨后这个二维地形**最多**能接住多少单位体积的水。水只能沿上下左右四个方向流动；贴着矩阵四条外边的格子无法存水，水会直接流走。

**约束**：

- $1 \le m, n \le 200$（$m$ 行 $n$ 列），格子总数 $mn \le 4 \times 10^4$
- $0 \le \text{heightMap}[i][j] \le 2 \times 10^4$（高度非负，可以是 0）

## 2. 示例

**示例 1**

```text
输入：heightMap = [[1,4,3,1,3,2],
                  [3,2,1,3,2,4],
                  [2,3,3,2,3,1]]
输出：4
解释：只有中间一行的 4 个格子可能存水，积水分别为 1、2、0、1，总和 = 4。
```

**示例 2**

```text
输入：heightMap = [[3,3,3,3,3],
                  [3,2,2,2,3],
                  [3,2,1,2,3],
                  [3,2,2,2,3],
                  [3,3,3,3,3]]
输出：10
解释：中心格高度 1，水位 3，积水 2；它外面一圈 8 个高 2 的格子各积水 1，共 2 + 8 = 10。
```

**示例 3（补充：最小的能存水的 3×3 案例，用于手推验证）**

```text
输入：heightMap = [[5,3,4],[4,1,3],[2,5,2]]
输出：2
解释：中心格高度 1，四周最矮的「出口山脊」是 3（上边 3 或右边 3），故水位 3，积水 3 - 1 = 2。
```

## 3. 解题思路

### 3.1 暴力思路

一维接雨水只需知道「左边最高」和「右边最高」，二维却没有这种简单的方向性——水可以绕着走。最朴素的做法是**模拟注水**：枚举水位 $T$ 从 $0$ 到 $2\times10^4$，每轮做一次 BFS，把「高度 $\le T$ 且能从边界连通到外部」的格子标记为"已流出"，剩下的高度 $\lt T$ 的格子记一层水。

单轮 BFS 是 $O(mn)$，总复杂度 $O(H \cdot mn)$，其中 $H = 2\times10^4$，乘积高达 $8\times 10^8$，而且每层只增加极少量水，绝大多数轮次是纯浪费。另一条暴力是「对每个格子二分水位」，每次判定都要 BFS，总计 $O(m^2n^2\log H)$，更慢。

### 3.2 核心观察：水位 = 到边界的最「矮」瓶颈

![水位由路径上最矮的山脊决定](images/wc6_q4_water_level_concept.svg)

把「水往外流」这件事抽出来看：从格子 $c$ 任意选一条四连通的路径走到矩阵外，这条路径上最高的那个格子记为 $B(P)$。水想沿 $P$ 流出去，就必须翻过 $B(P)$，所以

$$\text{水位}(c) \le \min_{P:\,c \to \text{边界}} B(P)$$

反过来，取达到这个最小值的路径 $P^{\ast}$，把水灌到 $\text{水位} = B(P^{\ast})$ 时，$P^{\ast}$ 上恰好有一个高度为 $B(P^{\ast})$ 的格子把水拦住，再高就会溢出。于是

$$\text{level}(c) = \min_{P:\,c \to \text{边界}} \max_{v \in P} \text{height}[v], \qquad \text{water}(c) = \max\bigl(0,\ \text{level}(c) - \text{height}[c]\bigr)$$

这就是图论里的**最小瓶颈路**（minimax path）：每条边 $(u,v)$ 的权取 $\max(h[u], h[v])$，再引一个超级源点连向所有边界格（边权为该格高度），则 $\text{level}(c)$ 就是从源点到 $c$ 的瓶颈最短路。**瓶颈最短路可以用 Dijkstra 求**，于是问题变成一次从边界出发的多源优先队列 BFS。

> 💡 一维的「左右两侧最大值取 min」其实正是这条式子在链状图上的特例：只有两条路径，瓶颈就是各自的最大值。

### 3.3 算法流程：优先队列 BFS（从边界向内注水）

![优先队列 BFS 流程](images/wc6_q4_heap_bfs_flow.svg)

把边界想象成一圈已知水位的"海岸线"，从最低处开始向内一格一格地淹没：

1. **初始化**：把所有边界格 $(h, r, c)$ 压入**小顶堆**并标记 `visited`。边界格的水位就是它自己的高度（水会直接流走）。
2. **取最低**：弹出堆顶 $(level, r, c)$，`level` 就是该格最终的水位（后面用引理 2 证明）。
3. **向内扩散**：对每个未访问的四邻居 $nb$：记 $h' = \text{height}[nb]$，新水位 $L' = \max(level, h')$；该格积水 $\max(0, level - h')$ 累加到答案；把 $(L', nb)$ 压入堆并标记已访问。
4. 堆空时返回累加值。

**为什么"先弹出最低的"就对了**：堆中元素的水位是"某条已知路径的瓶颈"，弹出最小者 $level$ 时，任何尚未发现的路径瓶颈都不可能更小——因为继续向内走只会遇到水位 $\ge level$ 的格子。这与 Dijkstra 的贪心选择完全同构，只是把"边权相加"换成了"路径取 max"。

### 3.4 示例演算

![示例 1 走查](images/wc6_q4_example_walkthrough.svg)

对示例 1 的 $3 \times 6$ 矩阵（只有中间一行是内部格，边界 14 格）：

| 步骤 | 弹出水位 | 新格子 | 高度 | 该格积水 | 推入水位 |
|------|----------|--------|------|----------|----------|
| 1 | 1（来自 (0,3)） | (1,3) | 3 | 0 | 3 |
| 2 | 3（来自 (0,2)） | (1,2) | 1 | 2 | 3 |
| 3 | 3（来自 (0,4)） | (1,4) | 2 | 1 | 3 |
| 4 | 3（来自 (1,0)） | (1,1) | 2 | 1 | 3 |

四个内部格的水位都收敛到 3，总积水 $0+2+1+1 = 4$。注意第 1 步弹出的水位 1 并没有让 (1,3) 存水——它被自身的 3 挡住，推入堆里的是 $\max(1,3)=3$，这正是"取路径瓶颈"的实现细节。

## 4. 算法细节

1. **堆元素设计**：用三元组 $(\text{level}, r, c)$，C++ 里 `priority_queue<tuple<int,int,int>, vector<...>, greater<>>` 天然按字典序取最小；Python 的 `heapq` 是裸小顶堆，元组比较同样按字典序。水位相同时谁先弹出不影响结果。
2. **必须先看水位再看坐标**：把 `level` 放在元组第一位，若把坐标放前面就变成了"按行优先"扫描，算法失效。
3. **`visited` 在入堆时标记，而不是出堆时标记**：一个格子会被最多 4 个邻居看到，若出堆才标记，同一个格子会被重复入堆（堆规模膨胀、答案可能重复累加）。入堆即标记保证**每格恰好入堆、出堆各一次**。
4. **边界去重**：四条边的两个角会被"上下边"和"左右边"重复加入，初始化时用 `visited` 判重（否则四角被算两次，虽然不影响答案，但会破坏"每格一次"的复杂度论证）。
5. **推入值只能是 `max(level, height[nb])`**：不要写成 `level`（水位会倒退，算出负积水）或 `height[nb]`（丢掉外侧更高水位的约束，答案偏小）。
6. **答案范围**：内部格至多 $198 \times 198 \approx 3.9\times10^4$ 个，每格水位差至多 $2\times10^4$，故答案 $\le 7.9\times10^8 \lt 2^{31}-1$，`int` 足够，无需 `long long`。
8. **不要用「按高度分桶」替代堆**：桶版本仍须按水位有序出队，写成 $H$ 轮 BFS 就退化回 $O(H \cdot mn)$。

## 5. 正确性证明

先形式化。构造带权图 $G$：顶点为所有格子，另加超级源 $s$；$s$ 与每个边界格 $b$ 连边，权为 $h[b]$；相邻格 $u,v$ 连边，权为 $\max(h[u], h[v])$。定义 $\text{dist}(c)$ 为 $s \to c$ 的**瓶颈最短路**，即所有路径上"最大边权"的最小值。

**引理 1（水位刻画）**：对任意格子 $c$，其最终水位恰为 $\text{level}(c) = \text{dist}(c)$，且边界格 $\text{level}(b) = h[b]$。

**证明**：

- 上界：任取一条 $s \to c$ 的路径，对应格子序列 $b = v_0, v_1, \dots, v_k = c$；该路径最大边权为 $\max_i h[v_i] = B$。若 $c$ 处的水位超过 $B$，这条路径上每一格的高度都低于水位，水会顺着它一路漫到边界流出，矛盾。故 $\text{level}(c) \le B$，对所有路径取下确界得 $\text{level}(c) \le \text{dist}(c)$。
- 下界：取达到 $\text{dist}(c)$ 的路径，其最大高度为 $L = \text{dist}(c)$。把水灌到高度 $L$：路径上高度为 $L$ 的格子恰好与水面齐平，不会溢出，故 $c$ 处至少能存到 $L$，即 $\text{level}(c) \ge L$。
- 边界格只有它自己这一格路径，故 $\text{level}(b) = h[b]$。∎

**引理 2（弹出即定型）**：算法每次弹出 $(k, r, c)$ 时，$k = \text{dist}(c)$。

**证明**：记 $c$ 弹出时的键值为 $k$，分两个方向。

- $\text{dist}(c) \le k$：对"入堆"归纳。边界格 $b$ 入堆时键为 $h[b] = \text{dist}(b)$；若格 $u$ 的键 $k_u$ 对应一条瓶颈为 $k_u$ 的真实路径，则从 $u$ 推给邻居 $v$ 的键 $\max(k_u, h[v])$ 正是"沿这条路再走一步"的瓶颈，仍对应真实路径。故任何入堆键都不小于该格的真实瓶颈。
- $k \le \text{dist}(c)$：取一条瓶颈为 $L = \text{dist}(c)$ 的最优路径 $s = v_0, v_1, \dots, v_t = c$。在 $c$ 被弹出的瞬间，设 $v_j$ 是这条路径上最后一个**已定型**（已弹出）的顶点；因 $c$ 本身尚未定型，$j \lt t$。当 $v_j$ 弹出时 $v_{j+1}$ 被压入，键为 $\max(\text{dist}(v_j), h[v_{j+1}]) \le L$（路径上所有高度 $\le L$，且 $\text{dist}(v_j) \le L$）。$v_{j+1}$ 此刻仍在堆中，而 $c$ 是当前最小键，故 $k \le \max(\text{dist}(v_j), h[v_{j+1}]) \le L$。

于是 $k = \text{dist}(c)$。这与 Dijkstra 的割论证同构，只是把"边权之和"换成了"路径取 max"。∎

**定理**：算法返回的累加值等于矩阵能接住的雨水总量。

**证明**：由引理 2，内部格 $c$ 的键值 $k = \text{dist}(c)$，且它只入堆一次，故弹出时的键仍是这个 $k$。算法在发现 $c$ 时累加 $\max(0, \text{level}(u) - h[c])$（$u$ 为触发它的已定型邻居），而推入键 $k = \max(\text{level}(u), h[c])$：

- 若 $\text{level}(u) \gt h[c]$，则 $k = \text{level}(u)$，累加值 $= k - h[c]$；
- 若 $\text{level}(u) \le h[c]$，则 $k = h[c]$，累加值 $= 0 = \max(0, k - h[c])$。

两种情形都等于 $\max(0, \text{dist}(c) - h[c])$，由引理 1 即该格真实积水量。边界格不入堆、不贡献水量，符合"水从边界流走"；各格水量互不重叠，求和即总量。∎

## 6. 复杂度分析

- **时间**：$O(mn \log(mn))$。初始化压入 $O(m+n)$ 个边界格；每个格子至多入堆一次、出堆一次，每次堆操作 $O(\log(mn))$；每格出堆时检查 4 个邻居，共 $O(mn)$ 次常数操作。合计 $O(mn\log(mn))$：$mn = 4\times10^4$ 时堆操作约 $8\times10^4$ 次、比较次数在 $10^6$ 量级，远低于时限。
- **空间**：$O(mn)$。`visited` 是个 $m \times n$ 的布尔矩阵；堆中最多同时存在 $O(mn)$ 个三元组（C++ 中每个约 12 字节），实际峰值远小于此，但上界取 $O(mn)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <tuple>
using namespace std;

class Solution {
public:
    int trapRainWater(vector<vector<int>>& heightMap) {
        int m = heightMap.size(), n = heightMap[0].size();
        if (m < 3 || n < 3) return 0;      // 没有内部格，一滴也存不住

        vector<vector<bool>> visited(m, vector<bool>(n, false));
        // 小顶堆，元素为 (水位, 行, 列)
        priority_queue<tuple<int, int, int>, vector<tuple<int, int, int>>,
                       greater<tuple<int, int, int>>> pq;

        // 1. 四条边界入堆，边界格水位 = 自身高度
        for (int i = 0; i < m; ++i)
            for (int j : {0, n - 1}) {
                visited[i][j] = true;
                pq.emplace(heightMap[i][j], i, j);
            }
        for (int j = 0; j < n; ++j)
            for (int i : {0, m - 1}) {
                if (!visited[i][j]) {       // 去掉四个角上的重复
                    visited[i][j] = true;
                    pq.emplace(heightMap[i][j], i, j);
                }
            }

        int ans = 0;
        const int dirs[4][2] = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

        // 2. 每次弹出当前水位最低的格子，向未访问邻居扩散
        while (!pq.empty()) {
            auto [level, r, c] = pq.top();
            pq.pop();
            for (const auto& d : dirs) {
                int nr = r + d[0], nc = c + d[1];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n || visited[nr][nc]) continue;
                visited[nr][nc] = true;     // 入堆即标记，保证每格只入堆一次
                if (level > heightMap[nr][nc]) ans += level - heightMap[nr][nc];
                pq.emplace(max(level, heightMap[nr][nc]), nr, nc);  // 路径瓶颈
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List
import heapq


class Solution:
    def trapRainWater(self, heightMap: List[List[int]]) -> int:
        m, n = len(heightMap), len(heightMap[0])
        if m < 3 or n < 3:
            return 0

        visited = [[False] * n for _ in range(m)]
        heap = []

        # 1. 四条边界入堆（visited 判重，避免四角重复）
        for i in range(m):
            for j in (0, n - 1):
                visited[i][j] = True
                heap.append((heightMap[i][j], i, j))
        for j in range(n):
            for i in (0, m - 1):
                if not visited[i][j]:
                    visited[i][j] = True
                    heap.append((heightMap[i][j], i, j))
        heapq.heapify(heap)

        ans = 0
        dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))

        # 2. 弹出水位最低者，向未访问邻居扩散
        while heap:
            level, r, c = heapq.heappop(heap)
            for dr, dc in dirs:
                nr, nc = r + dr, c + dc
                if 0 <= nr < m and 0 <= nc < n and not visited[nr][nc]:
                    visited[nr][nc] = True
                    if level > heightMap[nr][nc]:
                        ans += level - heightMap[nr][nc]
                    heapq.heappush(heap, (max(level, heightMap[nr][nc]), nr, nc))
        return ans
```

## 8. 边界情况与易错点

1. **只有一行或一列**：`m < 3` 或 `n < 3` 时任何格子都贴着边界，答案必为 0。例如 `[[1,2,1]]` 与 `[[5],[5],[5]]` 都返回 0，不提前返回也只会得到 0，但显式处理更清晰。
2. **入堆时就标记 `visited`**：若改成出堆时标记，中间一格的 4 个邻居会各自把它压进堆一次，答案可能被累加多次（也可能只是变慢），这是本题最高频的 WA 来源。
3. **推入值写成 `level` 而不是 `max(level, height[nb])`**：水位会沿着路径一路"降级"，示例 2 那种"外面一圈比中心高"的结构会算出过多积水。
4. **四角重复入堆**：上下边用 `for j in {0, n-1}`、左右边用 `for i in {0, m-1}` 时必然重叠 4 个角，必须用 `visited` 去重；否则虽然答案不变，但"每格只入堆一次"的复杂度论证被破坏。
5. **水位相等时的顺序**：堆里 `(level, r, c)` 字典序比较，水位相同就按坐标排，先弹谁都正确，不要为此加额外逻辑。
6. **答案类型**：C++ 用 `int` 即可（上界约 $7.9\times10^8$），若把水位与格数都乘错会溢出；Python 无此问题。
