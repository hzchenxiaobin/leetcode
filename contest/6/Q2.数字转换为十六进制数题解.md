# LeetCode 数字转换为十六进制数 题解

## 1. 题目概述

- **标题 / 题号**：数字转换为十六进制数（#405，easy）
- **链接**：https://leetcode.cn/problems/convert-a-number-to-hexadecimal/
- **来源**：LeetCode 第 6 场周赛 Q2
- **难度**：简单
- **标签**：位运算、数学、字符串

**题意**：给定一个 32 位有符号整数 `num`，返回它的十六进制字符串。字母一律小写，不带 `0x` 前缀，除 `0` 本身外不允许前导零；**负整数按 32 位补码解释**（所以 `-1` 的答案是 8 个 `f`，而不是带负号的 `-1`）。题面禁止调用库函数直接把数字格式化/转换成十六进制。

**约束**：

- $-2^{31} \le num \le 2^{31} - 1$，即标准 32 位有符号整数范围
- 答案长度不超过 8 个字符（负数恰好 8 位，非负数按需截断）
- 输出必须全小写，且除 `0` 外不得有前导零

## 2. 示例

**示例 1**

```text
输入：num = 26
输出："1a"
解释：26 = 1 × 16 + 10，最低位 10 对应字符 'a'，高位是 1，故为 "1a"。
```

**示例 2**

```text
输入：num = -1
输出："ffffffff"
解释：-1 的 32 位补码是 0xFFFFFFFF，即 8 个 f。注意这里没有负号，
      长度正好用满 8 位——这是补码解释的直接结果。
```

**补充示例**（官方仅给两组，这里补一组边界）

```text
输入：num = -2147483648        （即 −2^31）
输出："80000000"
解释：补码 0x80000000，最高位为 1、其余全 0，说明负数区间「恰好 8 位」是硬约束。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的写法是「不断取模、整除」：`res += digit(num % 16); num /= 16`。这套逻辑只对**非负整数**成立：

- 对负数，C++ 的 `%` 符号跟随被除数（`-1 % 16 == -1`），除法向零取整（`-1 / 16 == 0`），循环立刻结束，什么也得不到；
- 想先取绝对值再补符号，不仅会遇到 `-INT_MIN` 溢出（未定义行为），而且题意要的是**补码**（`-1 → "ffffffff"`），不是 `"-1"`；
- 直接调用 `std::hex` / `sprintf("%x")` / Python 的 `hex()` 属于被题面禁止的「库格式化」。

时间复杂度本身没问题（最多 8 轮），真正的难点是**负数的解释方式**。

### 3.2 核心观察：补码就是模 $2^{32}$ 的无符号数

![32 位补码示意图](images/wc6_q2_twos_complement_model.svg)

32 位补码的定义是：负数 `num` 的机器表示等于 $2^{32} + num$。而「把有符号数转成无符号数」这一操作，恰好就是**模 $2^{32}$ 取余**：

$$x = num \bmod 2^{32} = \begin{cases} num, & num \ge 0 \\ 2^{32} + num, & num < 0 \end{cases}$$

于是负数被搬到了 $[0, 2^{32})$ 这个普通无符号区间里，后面就可以用「取最低 4 位、右移 4 位」的同一套逻辑处理，**完全不需要分支讨论符号**。两种语言各有一行等价写法：

- C++：`unsigned int x = num;`（标准规定负数转无符号等于模 $2^{32}$，行为良定义，不是未定义行为）
- Python：`x = num & 0xFFFFFFFF`（`int` 是任意精度，按位与掩码等价于取低 32 位，即取模）

关键副产品：负数转成无符号后最高位必为 1，所以 $x \ge 2^{31}$，**一定跑满 8 轮**；非负数高位是 0，循环在 $x$ 归零时自然停下，**天然没有前导零**。

### 3.3 算法流程

![逐位取 4 位并右移的流程图](images/wc6_q2_nibble_flow.svg)

1. 若 `num == 0`，直接返回 `"0"`（否则后面的循环一次都不进，会返回空串）。
2. `x = num & 0xFFFFFFFF`（C++ 写成 `unsigned int x = num;`）。
3. 只要 `x > 0`：`d = x & 15`，把查表字符 `"0123456789abcdef"[d]` 追加到结果末尾，然后 `x >>= 4`。
4. 循环结束时结果是**低位在前**的，整体反转即得答案。

由于每一轮都取走最低 4 位，循环次数等于 $x$ 非零的十六进制位数：

$$\text{轮数} = \max\Bigl(1,\ \bigl\lceil \log_{16}(x+1) \bigr\rceil\Bigr) \le 8$$

### 3.4 示例演算

![两个例子的走查表](images/wc6_q2_walkthrough.svg)

以 `num = 26` 为例，$26 = \texttt{0x1a}$：

| 轮次 | $x$ | $x \bmod 16$ | 字符 | $x \gg 4$ |
|:---:|:---:|:---:|:---:|:---:|
| 1 | 26（`0x1a`） | 10 | `'a'` | 1 |
| 2 | 1（`0x1`） | 1 | `'1'` | 0，停止 |

收集到 `['a','1']`，反转得 `"1a"`。而 `num = -1` 时 $x = 4294967295 = \texttt{0xffffffff}$，8 轮每轮 `x & 15` 都是 15，全部输出 `'f'`，反转后仍是 `"ffffffff"`。

## 4. 算法细节

1. **负数只做一次转换**：C++ 用 `static_cast<unsigned int>(num)`，Python 用 `num & 0xFFFFFFFF`。不要写 `num = -num`——`-INT_MIN` 是有符号溢出（UB），而且在补码语义下本来就是错的。
2. **必须用无符号类型右移**：对负的 `int` 做 `>>` 会做符号扩展（C++20 起明确为算术右移），`-1 >> 4` 永远是 `-1`，`while (x)` 会死循环。转成 `unsigned int` 后右移才是逻辑右移，高位补 0。
3. **查表代替条件分支**：`"0123456789abcdef"` 下标取值比 `d < 10 ? '0' + d : 'a' + d - 10` 更短，也不会写错大小写；把这张表声明为 `const char*` / 模块级常量，避免每轮构造字符串。
4. **`num == 0` 必须特判**：循环条件是 `x > 0`（或 `while (x)`），`0` 进去一次都不循环，返回空串就错了。若改用固定 8 轮的写法（`for i in 0..7` 取 `(x >> 4i) & 15`），则需要在最后 `strip` 前导零，且要注意 `"0"` 别被 strip 成空串。
5. **逆序的两种写法**：先 `push_back` 再 `reverse`，或者用 `res = ch + res`（Python 里 `digits[::-1]`）。前者是 $O(1)$ 摊还的追加，后者是 $O(n^2)$ 的字符串拼接——本题 $n \le 8$ 无所谓，但习惯上应选前者。
6. **终止条件与上界**：$x < 2^{32} = 16^8$，所以循环最多 8 轮，答案缓冲区给 8 字节就够；C++ 里可以 `res.reserve(8)`。
7. **位运算优先级**：`&` 的优先级低于 `==`、高于赋值，因此 `x & 15 == 0` 会被解析成 `x & (15 == 0)`，`x >> 4 + 1` 会被解析成 `x >> (4 + 1)`。凡是把按位运算和比较、加减混写，**一律加括号**写成 `(x & 0xF)`、`(x >> 4)`。

## 5. 正确性证明

**引理 1（掩码等价于补码）**：设 $x = num \bmod 2^{32}$（即 C++ 的 `unsigned int x = num` 或 Python 的 `num & 0xFFFFFFFF`），则 $x$ 的 32 位二进制表示恰好是 `num` 的补码表示。

**证明**：若 $num \ge 0$，则 $num < 2^{31} < 2^{32}$，故 $x = num$，其 32 位二进制即 `num` 的二进制，非负数的原码与补码相同。若 $num < 0$，由补码定义，`num` 的补码为 $2^{32} + num$，而 $num \bmod 2^{32} = 2^{32} + num$（因为 $-2^{31} \le num < 0$，故 $2^{31} \le num + 2^{32} < 2^{32}$），两者相等。C++ 把负数转成无符号数的结果定义为「对 $2^{32}$ 取模后的唯一值」，Python 的 `& 0xFFFFFFFF` 取低 32 位，同样等于模 $2^{32}$ 的余数。∎

**引理 2（每一轮取出一位十六进制数字）**：设 $x > 0$，记 $r = x \bmod 16$、$q = \lfloor x / 16 \rfloor$，则 $r$ 是 $x$ 的十六进制表示的最低位数字，$q$ 的十六进制表示是删去该位后的前缀，且 $q = x \gg 4$。

**证明**：由带余除法 $x = 16q + r$，$0 \le r < 16$。十六进制是按权 $16^k$ 展开，故 $x$ 的最低位数字就是 $r$，其余部分为 $q$。又 $x \ge 0$ 时逻辑右移与整除 $16$ 一致，故 $x \gg 4 = \lfloor x/16 \rfloor = q$。∎

**引理 3（循环不变量与终止）**：循环执行 $k$ 轮后，$x_k = \lfloor x/16^k \rfloor$，结果数组中依次存放 $x$ 的最低 $k$ 位十六进制数字（低位在前）。循环最多执行 8 轮，且推入的最后一个字符非 `'0'`。

**证明**：对 $k$ 归纳。$k=0$ 时 $x_0 = x$，数组为空，成立。若第 $k$ 轮开始时不变量的前半部分成立，由引理 2 推入的正是 $x_k$ 的最低位，随后 $x_{k+1} = x_k \gg 4 = \lfloor x_k/16 \rfloor = \lfloor x/16^{k+1} \rfloor$，不变量保持。由于 $x < 2^{32} = 16^8$，有 $\lfloor x/16^8 \rfloor = 0$，故最多 8 轮后循环必然终止。设最后一轮开始时 $x_k > 0$ 而此后归零，则该轮推入的是 $x_k \in [1,15]$ 对应的字符，不是 `'0'`。∎

**定理**：算法返回的字符串恰为 `num` 的 32 位补码十六进制表示（小写、无 `0x` 前缀、除 `num = 0` 外无前导零）。

**证明**：由引理 1，$x$ 的位模式就是 `num` 的补码，因此只要输出 $x$ 的十六进制表示即符合题意。由引理 3，循环结束后数组里是 $x$ 的十六进制数字自低位到高位的排列，反转后即为标准的高位在前表示，字符取自 `"0123456789abcdef"` 故全小写。由引理 3 末句，反转后首位不是 `'0'`，故无前导零；`num = 0` 由特判直接返回 `"0"`，同样满足「唯一允许的零」这一约定。∎

## 6. 复杂度分析

- **时间**：$O(1)$，更精确地说是 $O(\log_{16} x) \le 8$ 轮。每轮做一次按位与、一次查表、一次右移，共 $O(1)$ 操作；把结果反转（或 `join`）也是 $O(8)$。相对于 32 位定长输入，整体是常数时间。
- **空间**：$O(1)$。结果数组最多 8 个字符，查表字符串长度 16，除此之外只有若干整型临时变量，与 `num` 的取值无关（不随输入规模增长）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    string toHex(int num) {
        if (num == 0) return "0";                        // 唯一的零
        const char* HEX = "0123456789abcdef";
        unsigned int x = static_cast<unsigned int>(num);  // 负数 → 模 2^32 的无符号数（补码）
        string res;
        res.reserve(8);
        while (x) {
            res.push_back(HEX[x & 0xF]);                 // 取最低 4 位
            x >>= 4;                                     // 逻辑右移，丢掉这 4 位
        }
        reverse(res.begin(), res.end());                 // 低位先出，整体反转
        return res;
    }
};
```

### Python

```python
class Solution:
    def toHex(self, num: int) -> str:
        HEX = "0123456789abcdef"
        if num == 0:
            return "0"
        x = num & 0xFFFFFFFF          # 负数按 32 位补码转成无符号，等价于 num % 2**32
        digits = []
        while x:
            digits.append(HEX[x & 0xF])
            x >>= 4
        return "".join(reversed(digits))
```

## 8. 边界情况与易错点

1. **`num == 0` 返回空串**：`while (x)` 循环体一次都不执行，若不特判就返回 `""`，而正确答案是 `"0"`。
2. **对负 `int` 直接右移导致死循环**：`-1 >> 4` 仍是 `-1`（算术右移补符号位），`while (x)` 永远为真。必须先转 `unsigned int`，这是本题最容易踩的坑。
3. **$-2^{31}$ 不能取绝对值**：`-INT_MIN` 是有符号溢出（UB），在补码语义下也没有意义；本题不需要取反，只要转无符号即可，答案 `"80000000"` 恰好 8 位。
4. **前导零**：`26` 应返回 `"1a"` 而不是 `"0000001a"`。固定 8 轮 + `strip('0')` 的写法要额外注意 `num = 0` 会被 strip 成空串。
5. **大小写**：`"1A"` 是错的，LeetCode 判题区分大小写；查表字符串写成全小写即可一劳永逸。
6. **不要用库格式化**：`std::hex`、`sprintf("%x")`、`hex()`、`format(num, 'x')` 都违反题面约定，即使输入输出正确也会被判为不合规的思路（面试中尤其要注意）。
7. **`&` 与 `>>` 混用漏括号**：`x & 15` 本身没问题，但 `x & 15 == 0`、`x >> 4 + 1` 这类连写会按优先级「意外结合」，统一加括号最稳。
