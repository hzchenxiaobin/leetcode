# LeetCode 最大字符串配对数目 题解

## 1. 题目概述

- **标题 / 题号**：最大字符串配对数目（#2744，easy）
- **链接**：https://leetcode.cn/problems/find-maximum-number-of-string-pairs/
- **来源**：LeetCode 第 107 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串、模拟

**题意**：给定一个字符串数组 `words`，其中所有字符串**互不相同**且长度均为 $2$。若 $0 \le i < j < n$ 且 $words[i]$ 恰好是 $words[j]$ 的反转字符串，则称这一对可以**匹配**。每个字符串最多匹配一次，返回数组中最大的匹配对数。

**约束**：

- $1 \le words.length \le 50$
- $words[i].length = 2$
- `words` 中的字符串**互不相同**
- `words[i]` 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：words = ["cd","ac","dc","ca","zz"]
输出：2
解释："cd" 与 "dc" 互为反转，"ac" 与 "ca" 互为反转，共 2 对；
      "zz" 是回文，数组里没有第二个 "zz" 与它配对。
```

**示例 2**

```text
输入：words = ["ab","ba","cc"]
输出：1
解释："ab" 与 "ba" 互为反转；"cc" 无配对。
```

**示例 3（边界补充）**

```text
输入：words = ["aa","ab"]
输出：0
解释：不存在任何互为反转的二元组，返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有下标对 $(i, j)$（$i < j$），把 $words[j]$ 反转后与 $words[i]$ 比较，统计可配对的对数。由于每个字符串**互不相同**且反转关系是对合的（反转的反转是自己），任意两个下标对之间不会共享字符串，直接计数即可，复杂度 $O(n^2 \cdot L)$（$L = 2$）。$n \le 50$，这个做法完全能过，比赛中用它签到毫无问题。不过本题只需要"每个字符串查询一次自己的反转是否出现过"，可以用哈希表一次遍历做到 $O(n)$。

### 3.2 核心观察：反转关系是对合，哈希一次遍历即可

![核心观察：反转后到已见集合里查命中](images/bw107_q1_reverse_match.svg)

两个关键性质让一次遍历成为可能：

1. **互不相同 + 反转是「对合」**：$\mathrm{reverse}(\mathrm{reverse}(w)) = w$，因此每个字符串 $w$ 的配对对象**至多一个**——就是字符串 $\mathrm{reverse}(w)$。不存在 $w$ 同时和两个不同字符串配对的可能（那要求两个字符串都等于 $\mathrm{reverse}(w)$，与互不相同矛盾）。
2. **回文串自动出局**：形如 `"zz"` 的回文串满足 $\mathrm{reverse}(w) = w$。若要它参与配对，需要**另一个下标**的字符串等于 $w$，但数组中字符串互不相同，不可能出现第二个 `"zz"`。

于是采用「两数之和」式的经典套路：维护一个**已见过的字符串集合**，遍历到 $w$ 时先查询 $\mathrm{reverse}(w)$ 是否在集合中——命中说明前面某个串与 $w$ 恰好构成一对，计数加一；无论命中与否，把 $w$ 插入集合。由于每个串的配对对象唯一，这里**甚至不需要删除**已配对的串：同一个键不会被命中第二次。

### 3.3 算法流程

```text
1. seen = 空哈希集合，ans = 0
2. 依次遍历每个 w ∈ words：
        r = reverse(w)
        若 r ∈ seen：ans += 1        # 命中：r 与 w 构成一对
        seen.insert(w)                # 先查后插！
3. 返回 ans
```

### 3.4 示例演算

![示例演算：五个字符串的一次遍历配对过程](images/bw107_q1_walkthrough.svg)

以示例 1（$words = [\text{"cd"},\text{"ac"},\text{"dc"},\text{"ca"},\text{"zz"}]$）为例：

| 步骤 | $w$ | $\mathrm{reverse}(w)$ | 在 `seen` 中？ | 动作 | `ans` |
|------|------|------|------|------|------|
| 1 | "cd" | "dc" | 否 | 插入 "cd" | 0 |
| 2 | "ac" | "ca" | 否 | 插入 "ac" | 0 |
| 3 | "dc" | "cd" | **是** ✅ | 配对 +1，插入 "dc" | 1 |
| 4 | "ca" | "ac" | **是** ✅ | 配对 +1，插入 "ca" | 2 |
| 5 | "zz" | "zz" | 否（回文不自配） | 插入 "zz" | 2 |

返回 $2$。注意第 5 步：如果先插入再查询，"zz" 会查询到自己而多算一对——**先查后插**的顺序在此处是正确性的一部分。

## 4. 算法细节

1. **先查后插**：处理 $w$ 时集合里只放**之前**的字符串，天然排除 $w$ 与自己（回文）配对的情况，也保证配对总是 $i < j$。
2. **长度恒为 2，反转即交换两字符**：可以直接用 `w[1] + w[0]` 拼出新串比较，不必调用库函数；用 `string r(w.rbegin(), w.rend())` 或 Python 的 `w[::-1]` 同样简单。
3. **无需删除已配对的键**：由对合性质，一个键至多被命中一次（两个不同字符串的 $\mathrm{reverse}$ 不可能相等）。写删除逻辑也不算错，但纯属多余。
4. **答案即「二元分量」个数**：把每个字符串与它的反转连边，图上只有孤立点（回文）和大小为 2 的分量，匹配数就是后者个数。
5. **数据结构选择**：$n \le 50$，`unordered_set` 与 `set` 都绰绰有余；哈希均摊 $O(1)$ 略快。

## 5. 正确性证明

**引理 1（对合性）**：对任意字符串 $w$，$\mathrm{reverse}(\mathrm{reverse}(w)) = w$。

**证明**：反转操作交换位置 $i$ 与 $L-1-i$ 的字符，执行两次每个字符回到原位。∎

**引理 2（配对结构）**：设互不相同的字符串集合 $S = \{words[0], \dots, words[n-1]\}$。定义无向图 $G$：$w$ 与 $w'$ 相邻当且仅当 $w' = \mathrm{reverse}(w)$。则 $G$ 的每个连通分量大小不超过 $2$；大小为 $1$ 的分量必为回文串。

**证明**：若 $w$ 有邻居 $w' = \mathrm{reverse}(w)$，则 $w'$ 的邻居由引理 1 只能是 $\mathrm{reverse}(w') = w$，即 $\{w, w'\}$ 构成封闭的二元分量。若 $w$ 无邻居，则 $\mathrm{reverse}(w) \notin S$；特别地当 $w$ 为回文串时 $\mathrm{reverse}(w) = w \in S$ 但题目要求两个**不同下标** $i < j$，而互不相同保证 $w$ 只出现一次，故回文串必为孤立点。∎

**定理**：算法返回的 `ans` 等于最大匹配数目，即 $G$ 中二元分量的个数。

**证明**：对遍历位置 $k$ 归纳：处理完 $words[0..k]$ 后，`seen` $= \{words[0], \dots, words[k]\}$（集合大小 $k+1$，因互不相同），且 `ans` 等于前 $k+1$ 个字符串中二元分量的个数。基础：$k=0$ 时无配对，成立。归纳步：处理 $w = words[k+1]$ 时查询 $r = \mathrm{reverse}(w)$。若命中，则 $r = words[i]$（某 $i \le k$），由引理 1 二者构成一个二元分量，且这是**新**出现的分量——若该分量已被统计过，需要存在 $j \le k$ 使 $\mathrm{reverse}(words[j]) = r$，由对合性 $words[j] = w$，与互不相同矛盾；故 `ans` 恰加一。若未命中，则由引理 2，$w$ 与之前任何串都不相邻，不产生新分量。归纳完成，算法终止时 `ans` 即全部二元分量的个数，也就是最大匹配数（每个二元分量贡献恰好一对，孤立点不贡献）。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot L)$，其中 $L = 2$ 是字符串长度，即 $O(n)$。每个字符串构造一次反转、一次哈希查询、一次哈希插入。$n \le 50$ 毫无压力。
- **空间**：$O(n \cdot L)$，哈希集合最多存 $n$ 个长度为 $L$ 的字符串。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumNumberOfStringPairs(vector<string>& words) {
        unordered_set<string> seen;
        int ans = 0;
        for (const string& w : words) {
            string r(w.rbegin(), w.rend());   // w 的反转
            if (seen.count(r)) ++ans;          // 先查：命中即成一对
            seen.insert(w);                    // 后插：回文串不会自配对
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumNumberOfStringPairs(self, words: list[str]) -> int:
        seen = set()
        ans = 0
        for w in words:
            r = w[::-1]                 # w 的反转
            if r in seen:               # 先查：命中即成一对
                ans += 1
            seen.add(w)                 # 后插：回文串不会自配对
        return ans
```

> 💡 两份代码均通过官方示例（`2`、`1`、`0`），并与「枚举全部下标对 + 已用标记」的 $O(n^2)$ 暴力对拍：C++ 侧 20000 组、Python 侧 4000 组随机数据（小字母表制造大量反转对与回文），`mismatch = 0`。

## 8. 边界情况与易错点

1. **先查后插的顺序**：若先插入再查询，回文串 `"zz"` 会在集合中查到自己而多算一对。这是本题最隐蔽的一分陷阱。
2. **回文串不可能配对**：需要 $i < j$ 且两串相等，而数组保证字符串互不相同——不要想当然地给回文串计数。
3. **答案下界是 0**：全部无法匹配时返回 0；单个字符串的数组也返回 0。
4. **不要套用「配对后删除」的惯性**：由于互不相同 + 对合性，删除是多余的；若误删（比如命中后把 $r$ 也删掉）在本题恰好不致错，但在允许重复的变体中要重新设计（见延伸）。
5. **反转长度为 2 的串**：直接交换两个字符即可，构造新字符串或调用库函数均可，注意不要把反转写成排序。
