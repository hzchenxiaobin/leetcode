# LeetCode 反转偶数长度组的节点 题解

## 1. 题目概述

- **标题 / 题号**：反转偶数长度组的节点（#2074，medium）
- **链接**：https://leetcode.cn/problems/reverse-nodes-in-even-length-groups/
- **来源**：LeetCode 第 267 场周赛 Q2
- **难度**：中等
- **标签**：链表、分段处理、翻转、指针操作

**题意**：给定单链表的头节点 `head`。链表节点**按顺序**依次分入长度为 `1, 2, 3, 4, …` 的组（第 $i$ 组预期长度为 $i$）。**最后一组可能不满**——剩余节点数可能小于其预期长度。请将**实际长度为偶数**的组整组反转，返回修改后链表的头节点。只能改指针，不能改节点内部的值。

**约束**：

- 链表中节点数目范围 $[1, 10^5]$
- $0 \leq \text{Node.val} \leq 10^5$

> 💡 **审题关键**：① 组大小**递增**（1, 2, 3, …），不是固定 $k$；② 判据是**实际长度**的奇偶而非预期长度——不满的最后一组仍可能反转；③ 奇数长度的组保持原序，一个节点都不用动；④ 只改指针不改值，暗示期望 $O(1)$ 空间的原位做法。

## 2. 示例

**示例 1**

```text
输入：head = [5,2,6,3,9,1,7,3,8,4]
输出：[5,6,2,3,9,1,4,8,3,7]
解释：
  组1 (len=1): [5]        → 奇，保留
  组2 (len=2): [2,6]      → 偶，反转 → [6,2]
  组3 (len=3): [3,9,1]    → 奇，保留
  组4 (len=4): [7,3,8,4]  → 偶，反转 → [4,8,3,7]
  拼接：5 → 6 → 2 → 3 → 9 → 1 → 4 → 8 → 3 → 7
```

**示例 2**

```text
输入：head = [1,1,0,6]
输出：[1,0,1,6]
解释：
  组1 (len=1): [1]    → 奇，保留
  组2 (len=2): [1,0]  → 偶，反转 → [0,1]
  组3 (预期3，实际1): [6]  → 奇，保留
  拼接：1 → 0 → 1 → 6
```

**示例 3**（覆盖「最后一组不满且为偶数」的关键情况）

```text
输入：head = [1,1,0,6,5]
输出：[1,0,1,5,6]
解释：
  组1 (len=1): [1]         → 奇，保留
  组2 (len=2): [1,0]       → 偶，反转 → [0,1]
  组3 (预期3，实际2): [6,5] → 偶（按实际长度！）→ 反转 → [5,6]
  拼接：1 → 0 → 1 → 5 → 6
```

## 3. 解题思路

### 3.1 暴力思路：转数组分组反转再重建

把链表节点全部搬进数组，按 `1, 2, 3, …` 切分各组，对实际长度为偶数的组反转数组片段，最后重建链表。

- **正确性**：显然正确。
- **复杂度**：时间 $O(n)$，但**空间 $O(n)$**，且「重建」本质上绕开了指针操作——比赛能过，但作为链表题的训练价值为零。

> ⚠️ 比赛视角：这题是 [25. K 个一组翻转链表](https://leetcode.cn/problems/reverse-nodes-in-k-group/) 的直系变体，直接套「dummy + 分组 + 局部翻转 + 串接」模板，多加一层「先探测实际长度再决策」即可，纯指针 $O(1)$ 空间并不比数组做法慢多少，现场值得写。

### 3.2 核心观察：递增分组 + 按实际长度判奇偶 + 两阶段处理

![递增分组与偶数长度组反转](images/wc267_q2_groups_concept.svg)

本题在 K 个一组翻转链表的骨架上有两个变化：

**变化一：组大小递增而非固定。** 外层循环不再用固定 `k`，而是维护一个递增变量 `expected`（第 1 组为 1，第 2 组为 2，……），每处理完一组 `expected++`。

**变化二：先探测实际长度，再决定是否翻转。** 25 题中不足 $k$ 个的尾巴组直接保持原序终止；本题的最后一组可能不满，**且不满的组仍可能要翻转**——判据是它的**实际长度** `actual` 的奇偶（示例 3：组 3 预期 3 实际 2，为偶，仍反转）。因此每组处理拆成两个阶段：

1. **探测阶段**：从前驱 `prev` 出发走 `expected` 步（遇 `null` 提前停），统计实际长度 `actual` 并定位组尾 `node`；
2. **决策阶段**：`actual` 为偶则整组翻转，为奇则原序跳过。

> 💡 **为什么不像 25 题那样「先翻转再判长度」？** 奇数长度的组不需要翻转，先翻再翻回是双倍无用功，还要重新定位边界。先探测再决策，奇数组完全不碰指针，偶数组只翻一次。

**翻转与串接技巧**（复用 25 题模板）：翻转区间 $[\text{groupHead}, \text{node}]$ 时，把累积指针 `p` 初始化为 `nextGroup`（下一组起点）而非 `nullptr`——翻转结束后原组头（已变新尾）的 `next` **自动**指向下一组，无需额外串接。翻转后：

- `prev->next = node`：原组尾变新头，接回前驱；
- `prev = groupHead`：原组头变新尾，充当下一组的前驱。

不翻转时：`prev = node`，组尾直接充当下一组前驱。

> ⚠️ **循环不变式**：无论翻转与否，处理完一组后 `prev` 始终指向**下一组的前驱节点**。这是全算法正确性的基石，两种分支殊途同归。

### 3.3 算法流程：dummy + prev 前驱推进

![算法流程：探测实际长度，按奇偶决策翻转](images/wc267_q2_probe_decide_flow.svg)

| 步骤 | 操作 | 作用 |
|------|------|------|
| ① 初始化 | `dummy.next = head; prev = dummy; expected = 1` | dummy 统一处理表头，`prev` 为当前组前驱 |
| ② 探测 | 从 `prev` 走至多 `expected` 步，统计 `actual`，定位组尾 `node` | 拿到**实际长度**（可能小于 `expected`） |
| ③ 记录 | `nextGroup = node->next` | 下一组起点，兼作翻转的终止边界 |
| ④ 决策 | `actual % 2 == 0`？ | 偶 → 翻转；奇 → 跳过 |
| ⑤a 翻转 | `p = nextGroup` 起逐节点掉头；`prev->next = node; prev = groupHead` | 原尾变新头接前驱，原头变新尾作下组前驱 |
| ⑤b 跳过 | `prev = node` | 组尾直接作下组前驱 |
| ⑥ 递增 | `expected++` | 下一组预期长度 +1 |
| ⑦ 循环 | `prev->next == nullptr` 时退出，返回 `dummy.next` | 所有组处理完毕 |

> 💡 **终止条件**是 `prev->next == nullptr` 而非「走到链表尾」——`prev` 恒为下一组前驱，它后面没有节点就说明没有下一组了。这与探测阶段「遇 `null` 提前停」配合，自然消化最后一组不满的情况，无需任何特判。

### 3.4 示例演算

![示例 1 的四组逐步处理](images/wc267_q2_walkthrough.svg)

以示例 1 `head = [5,2,6,3,9,1,7,3,8,4]` 走完整流程（`d` 为 dummy）：

| 组 | expected | 探测到的组 | actual | 奇偶 | 动作 | 处理后链表 | prev 指向 |
|----|----------|-----------|--------|------|------|-----------|-----------|
| 1 | 1 | [5] | 1 | 奇 | 保留 | d→5→2→6→3→9→1→7→3→8→4 | 5 |
| 2 | 2 | [2,6] | 2 | 偶 | 反转 → [6,2] | d→5→6→2→3→9→1→7→3→8→4 | 2（原组头） |
| 3 | 3 | [3,9,1] | 3 | 奇 | 保留 | 同上 | 1 |
| 4 | 4 | [7,3,8,4] | 4 | 偶 | 反转 → [4,8,3,7] | d→5→6→2→3→9→1→4→8→3→7 | 7（原组头） |

第 4 组处理后 `prev = 7`，`prev->next == nullptr`，循环退出，返回 `dummy.next`，即 `5 → 6 → 2 → 3 → 9 → 1 → 4 → 8 → 3 → 7` ✓。

对照示例 3 `[1,1,0,6,5]`：第 3 组探测时只走 2 步就遇 `null`，`actual = 2 < expected = 3`，按 **2** 判偶 → 反转 $[6,5] \to [5,6]$，验证「实际长度」判据。

## 4. 算法细节

1. **dummy 哨兵**：第一组长度恒为 1（奇、不翻转），`prev` 从 dummy 自然推进到原 head，全程无需对表头特判。
2. **探测循环**：`for (i = 0; i < expected && node->next; ++i)`——两个条件缺一不可：`i < expected` 封顶满组，`node->next` 为空时提前停，`actual` 恰为真实走过的节点数。
3. **`nextGroup` 的双重身份**：既是下一组的起点（供 `prev` 语义衔接），又是翻转的**终止哨兵**（翻转循环 `while (c != nextGroup)`）。
4. **翻转时 `p = nextGroup`** 而非 `nullptr`：普通反转链表翻完尾节点指向 `null`；分段翻转中翻转循环把每个节点的 `next` 指向前驱累积指针，初始为 `nextGroup` 就让原组头（新尾）的 `next` 直接落在下一组头上，省掉翻转后的串接语句。
5. **`prev` 的两种更新**：翻转时 `prev = groupHead`（原头已变新尾），跳过时 `prev = node`（组尾），两者都满足不变式「`prev` = 下一组前驱」。
6. **组间顺序天然保持**：算法从不跨组搬动节点，组内翻转也以 `nextGroup` 为界，因此不需要任何「拼接」步骤。

## 5. 正确性证明

**引理 1（不变式）**：每轮循环开始时，`prev` 指向「下一组第一个节点」的前驱，且 `expected` 等于该组在递增序列 $1,2,3,\dots$ 中的预期长度；此外，`prev` 及其之前的所有节点已构成最终答案的前缀。

**证明**：归纳。首轮 `prev = dummy`、`expected = 1`，前缀为空，成立。设某轮开始时命题成立。探测从 `prev` 出发走至多 `expected` 步：若中途遇 `null`，则本组是最后一组（其后无节点）；否则恰好取满 `expected` 个。两种情形中 `actual` 都等于本组的真实节点数，组尾 `node` 是链表中紧邻 `nextGroup`（`node->next`）之前的节点。

- 若 `actual` 为奇：不翻转，本组原序并入前缀（与最终答案一致——最终答案中奇数组本就原序），`prev = node` 指向 `node->next = nextGroup` 的前驱，`expected + 1` 恰为下一组的预期长度（若 `nextGroup` 为 `null` 则无下一组）。
- 若 `actual` 为偶：翻转 $[\text{groupHead}, node]$。翻转循环将组内每个节点的 `next` 依次指向前一个节点、组头指向 `nextGroup`，故翻转后组内顺序恰为原序的反向，且新尾（原组头）的 `next` 指向 `nextGroup`——链表整体无断裂。偶数组在最终答案中要求反转，故前缀仍与答案一致；`prev = groupHead`（新尾）指向下一组前驱，`expected` 同理加一。

无论哪种分支，下一轮开始时命题重新成立。∎

**引理 2（翻转的局部性）**：翻转区间 $[\text{groupHead}, node]$ 且累积指针初始为 `nextGroup` 时，区间外任何节点的 `next` 均不变，链表无环、无断裂。

**证明**：翻转循环只写 `c->next`，其中 `c` 始终取遍 $[\text{groupHead}, node]$ 内的节点，不触碰区间外节点；组头（区间内）的新 `next` 为 `nextGroup`，与原链表中 `node` 的指向一致，故从 `prev` 出发仍可沿 `next` 遍历所有 $n$ 个节点后到达 `null`——链表保持连通且无环。∎

**定理**：算法返回的链表恰为「将每个实际长度为偶数的组整组反转、奇数组保持原序、组间相对顺序不变」的结果，且时间 $O(n)$、额外空间 $O(1)$。

**证明**：分组由探测阶段的步数唯一确定——第 $i$ 组取到的是前缀之后的前 $\min(i, \text{剩余节点数})$ 个节点，与题意划分一致。由引理 1，每轮把一个组按其**实际长度**奇偶正确地固化进答案前缀；由引理 2，每轮之后链表完整。循环在 `prev->next == nullptr` 时终止，此时全部节点已处理且每组恰好处理一次。探测阶段每节点被访问一次（各组 `actual` 之和为 $n$），翻转阶段仅偶数组节点再各访问一次，总量 $\leq 2n$，故时间 $O(n)$；全程只用 `prev/node/nextGroup/p/c/groupHead/expected/actual` 等常数个标量与指针，故空间 $O(1)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。外层按组循环、内层按 `expected` 步走，看似嵌套，实则**每组的探测 + 翻转开销为 $O(\text{actual})$，而各组 `actual` 之和恰为 $n$**——每个节点属于且仅属于一个组。偶数组的节点最多再被翻转访问一次，总访问量 $\leq 2n$，不是 $O(n^2)$。
- **空间复杂度**：$O(1)$。仅常数个指针与计数器（数组暴力法需 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    ListNode* reverseEvenLengthGroups(ListNode* head) {
        ListNode dummy(0);
        dummy.next = head;
        ListNode* prev = &dummy;
        int expected = 1;

        while (prev->next != nullptr) {
            // ① 探测：从 prev 走至多 expected 步，统计实际长度
            ListNode* node = prev;
            int actual = 0;
            for (int i = 0; i < expected && node->next != nullptr; ++i) {
                node = node->next;
                ++actual;
            }
            // ② 下一组起点 = 组尾的下一个，兼作翻转终止哨兵
            ListNode* nextGroup = node->next;

            if (actual % 2 == 0) {
                // ③ 偶数长度 → 反转 [prev->next, node]
                ListNode* groupHead = prev->next;
                ListNode* p = nextGroup;      // 关键：初始为 nextGroup
                ListNode* c = groupHead;
                while (c != nextGroup) {
                    ListNode* nxt = c->next;
                    c->next = p;
                    p = c;
                    c = nxt;
                }
                prev->next = p;    // 原组尾(新头)接回前驱
                prev = groupHead;  // 原组头(新尾)作下一组前驱
            } else {
                // ④ 奇数长度 → 原序跳过
                prev = node;
            }
            ++expected;
        }
        return dummy.next;
    }
};
```

### Python

```python
class Solution:
    def reverseEvenLengthGroups(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        prev = dummy
        expected = 1

        while prev.next:
            # ① 探测：从 prev 走至多 expected 步，统计实际长度
            node = prev
            actual = 0
            for _ in range(expected):
                if not node.next:
                    break
                node = node.next
                actual += 1
            # ② 下一组起点，兼作翻转终止哨兵
            next_group = node.next

            if actual % 2 == 0:
                # ③ 偶数长度 → 反转 [prev.next, node]
                group_head = prev.next
                p, c = next_group, group_head
                while c != next_group:
                    c.next, p, c = p, c, c.next
                prev.next = p       # 原组尾(新头)接回前驱
                prev = group_head   # 原组头(新尾)作下一组前驱
            else:
                # ④ 奇数长度 → 原序跳过
                prev = node

            expected += 1

        return dummy.next
```

> 💡 Python 版翻转循环用元组赋值 `c.next, p, c = p, c, c.next` 一行完成三指针轮转；注意求值顺序是从右到左，`c.next` 的右侧新值取的是**旧的** `p`，与 C++ 版逐行等价。

## 8. 边界情况与易错点

1. **用 `expected` 判奇偶（最经典的 WA）**：示例 3 的组 3 预期 3 实际 2。若按 `expected % 2` 决策会跳过本该反转的组；必须先探测 `actual` 再判 `actual % 2`。
2. **翻转终止条件写成 `c != nullptr`**：普通反转链表的写法，会把本组之后的所有节点一并翻掉。正确哨兵是 `nextGroup`。
3. **翻转时 `p` 初始化为 `nullptr`**：翻完后原组头的 `next` 指向 `null`，链表在此断裂；必须初始化为 `nextGroup`（或翻转后补一句 `groupHead->next = nextGroup`）。
4. **翻转后 `prev` 更新错成 `prev = node`**：翻转后 `node` 已不是组尾而是组头方向的第一个……不对——翻转后 `node` 是新头、`groupHead` 是新尾；`prev` 必须指向新尾 `groupHead`，否则下一轮探测会从错误位置重复处理本组。
5. **`n = 1`**：唯一一组长度 1（奇），不翻转，`dummy` 直接兜住，无需特判。
6. **恰好取满到链表尾**：如 $n = 3$（组 1 + 组 2）或 $n = 6$（1+2+3），最后一组探测走满 `expected` 步后 `nextGroup == nullptr`；翻转以 `null` 为哨兵依然成立（新尾指向 `null`），无需特判。
7. **溢出 / 性能**：$n \leq 10^5$，指针操作无溢出问题；但若把「探测」写成每次从头数节点，会退化 $O(n^2)$——保证探测只从 `prev` 出发走一步数一组。
