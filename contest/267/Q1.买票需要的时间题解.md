# LeetCode 买票需要的时间 题解

## 1. 题目概述

- **标题 / 题号**：买票需要的时间（#2073，easy）
- **链接**：https://leetcode.cn/problems/time-needed-to-buy-tickets/
- **来源**：LeetCode 第 267 场周赛 Q1
- **难度**：简单
- **标签**：队列、数组、模拟

**题意**：`n` 个人排成一队买票，第 `i` 人要买 `tickets[i]` 张。每人每次只能买 1 张、耗时**恰好 1 秒**；没买完就**瞬间**走到队尾重新排队，买完则离开队伍。求下标为 `k` 的人买完所有票所需的总秒数。

**约束**：

- $n == \text{tickets.length}$
- $1 \leq n \leq 100$
- $1 \leq \text{tickets}[i] \leq 100$
- $0 \leq k < n$

## 2. 示例

**示例 1**

```text
输入：tickets = [2,3,2], k = 2
输出：6
解释：队伍按剩余张数依次变化：
  [2,3,2] → [3,2,1] → [2,1,2] → [1,2,1] → [2,1] → [1,1] → [1]
第 6 秒 k 买下最后一张票，返回 6。
```

**示例 2**

```text
输入：tickets = [5,1,1,1], k = 0
输出：8
解释：k 在队头，要买 5 张；其余 3 人各买 1 张就离开。
  5 + 1 + 1 + 1 = 8。
```

**示例 3**（覆盖「k 很早完成、后面的人没轮到」的情况）

```text
输入：tickets = [2,1,1], k = 1
输出：2
解释：第 1 秒 0 号买 1 张（剩 1，回队尾），第 2 秒 k 买完自己的 1 张，立即返回 2。
排在 k 后面的 2 号一次都没轮到。
```

## 3. 解题思路

### 3.1 暴力思路：队列逐秒模拟

签到题最稳的打法：用队列 `(下标, 剩余张数)` 真实模拟——每秒队头买一张，`k` 的剩余归零立即返回：

```text
queue ← (0,t[0]), (1,t[1]), ..., (n-1,t[n-1])
time ← 0
while queue 非空:
    (i, left) ← queue 队头出队
    time += 1; left -= 1
    若 i == k 且 left == 0: 返回 time
    若 left > 0: (i, left) 重新入队尾
```

- **时间**：$O\big(\sum \text{tickets}[i]\big) \leq 100 \times 100 = 10^4$，本题必过。
- **空间**：$O(n)$。

> ⚠️ 比赛视角：模拟代码约 10 行、3 分钟写完，作为 Q1 完全够用。但若数据放大到 $\sum \text{tickets}[i] \sim 10^9$，逐秒模拟会超时，需要下面的 $O(n)$ 做法。

### 3.2 核心观察：每秒恰好一人买一张 → 总时间 = 购票总张数

![循环队列规则与目标](images/ticket_time_queue_concept.svg)

两个观察把模拟压缩成一次遍历：

**观察 1（计数的桥梁）**：`k` 完成前队伍**永不为空**（`k` 自己始终在队），所以每一秒都恰好有一人买一张票。于是

$$\text{答案} = \text{k 完成前所有人买票的总张数}$$

**观察 2（每人买几张由位置决定）**：队伍是循环轮转的，**相对顺序不变**。`k` 要买 $T = \text{tickets}[k]$ 张，即经历 $T$ 轮：

- $i < k$（初始在 `k` 前面）：每一轮都在 `k` **之前**轮到，最多买 $\min(\text{tickets}[i],\ T)$ 张；
- $i = k$：贡献 $T$；
- $i > k$（初始在 `k` 后面）：最后一轮 `k` 买完即停，**这一轮轮不到他**，最多买 $\min(\text{tickets}[i],\ T-1)$ 张。

$$\boxed{\ \text{ans} = T \;+\; \sum_{i<k} \min\big(\text{tickets}[i],\ T\big) \;+\; \sum_{i>k} \min\big(\text{tickets}[i],\ T-1\big)\ }$$

### 3.3 算法流程：一次遍历按位置累加

![贡献法流程](images/ticket_time_contribution_flow.svg)

1. 取 $T = \text{tickets}[k]$，`ans = 0`。
2. 遍历 $i$ 从 $0$ 到 $n-1$：
   - $i < k$：`ans += min(tickets[i], T)`；
   - $i = k$：`ans += T`；
   - $i > k$：`ans += min(tickets[i], T - 1)`。
3. 返回 `ans`。

实现上常把 $i \leq k$ 合并成同一分支（`k` 自己的贡献 $\min(T, T) = T$，天然归入前面一类）。

### 3.4 示例演算

![示例演算](images/ticket_time_walkthrough.svg)

以 `tickets = [2,3,2], k = 2`（$T = 2$）走一遍：

| 位置 $i$ | $\text{tickets}[i]$ | 与 $k$ 的关系 | 贡献 | 累计 |
|---------|-----|------|------|------|
| 0 | 2 | $i < k$ | $\min(2, 2) = 2$ | 2 |
| 1 | 3 | $i < k$ | $\min(3, 2) = 2$ | 4 |
| 2 | 2 | $i = k$ | $T = 2$ | 6 |

答案 `6` ✓。对照示例 2：`tickets=[5,1,1,1], k=0`，$T=5$，$i>0$ 的三人各贡献 $\min(1,4)=1$，合计 $5+3=8$ ✓。

## 4. 算法细节

1. **计数桥梁**：「每秒恰好一人买一张」成立的前提是队伍非空——`k` 完成前它自己必在队中，因此时间与购票张数一一对应，这是把「求时刻」转成「求计数」的关键。
2. **前/后分界的由来**：轮转过程中离开者被移除、其余人相对顺序不变；`k` 第 $T$ 轮买到最后一张的**那一瞬间**过程终止，故初始在 `k` 后面的人只有前 $T-1$ 轮的机会。
3. **取 min 的含义**：某人可能中途买完离开（$\text{tickets}[i]$ 较小），也可能全程都在（达到轮数上界），两者取小。
4. **分支合并**：代码中 `i <= k` 统一取 $\min(\text{tickets}[i], T)$，`k` 自身贡献自动为 $T$，无需单独分支。

## 5. 正确性证明

**引理 1**：在 `k` 完成买票前的每一秒，恰好发生一次「某人买一张票」的动作；因此 `k` 的完成时刻等于该时刻前所有购票动作的总次数。

**证明**：动作只在队伍非空时发生。`k` 从开始到完成始终在队伍中（每次没买完都回到队尾），故队伍始终非空，每秒队头各买一张，动作与秒一一对应。∎

**引理 2**：设 $T = \text{tickets}[k]$。`k` 完成前，初始位于 `k` 前面的第 $i$ 人恰买 $\min(\text{tickets}[i], T)$ 张；初始位于 `k` 后面的第 $i$ 人恰买 $\min(\text{tickets}[i], T-1)$ 张。

**证明**：队伍每「转一圈」每人各轮到一次，且离队者被移除后其余人相对顺序不变。将 `k` 的 $T$ 次购票切分为 $T$ 轮（第 $j$ 轮指 `k` 第 $j$ 次购票前后的区间）。在每一轮内，仍在队中且位于 `k` 前面的每个人恰在 `k` 之前轮到一次；位于 `k` 后面的人在 `k` 之后轮到一次。第 $T$ 轮中 `k` 购票后过程立即终止，其后方者在该轮未被计入。故 $i<k$ 者至多轮到 $T$ 次、$i>k$ 者至多轮到 $T-1$ 次；又每人至多买光自己的 $\text{tickets}[i]$ 张，两者取 $\min$ 即为实际购票数。∎

**定理**：$\text{ans} = T + \sum_{i<k} \min(\text{tickets}[i], T) + \sum_{i>k} \min(\text{tickets}[i], T-1)$。

**证明**：由引理 1，答案 = `k` 完成前所有购票动作总数；每人购票数由引理 2 给出，`k` 自身为 $T$；逐人求和即得。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一次遍历，每个位置做一次 $\min$ 与累加。相比模拟的 $O(\sum \text{tickets}[i])$，把「逐秒」压缩为「按人求和」。
- **空间复杂度**：$O(1)$。仅用 `T`、`ans` 两个标量（模拟法需 $O(n)$ 队列）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int timeRequiredToBuy(vector<int>& tickets, int k) {
        int T = tickets[k], ans = 0;
        for (int i = 0; i < (int)tickets.size(); ++i) {
            ans += (i <= k) ? min(tickets[i], T) : min(tickets[i], T - 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def timeRequiredToBuy(self, tickets: List[int], k: int) -> int:
        T = tickets[k]
        return sum(min(t, T) if i <= k else min(t, T - 1)
                   for i, t in enumerate(tickets))
```

> 💡 `i <= k` 用 `<=` 把 `k` 归入「前面」一类，贡献恰为 $\min(T, T) = T$；`i > k` 必须 `T - 1`，这是本题唯一的新颖点。

## 8. 边界情况与易错点

1. **`i > k` 少一轮**：误写成 `min(tickets[i], T)` 会把 `k` 后面的人多算一轮，仅在 $\text{tickets}[i] \geq T$ 时暴露（如 `tickets=[3,5], k=0`：正确 $3+\min(5,2)=5$，误用得 $6$）。
2. **`n = 1`（`k = 0`）**：答案就是 $\text{tickets}[0]$，公式自动成立（无其他人贡献）。
3. **`k = 0`**：没有「前面」的人，全员按 `T - 1` 封顶，见示例 2。
4. **所有人票数相同**：如 `[2,2,2], k=1` → $2+2+\min(2,1)=5$，可用小样例快速验证。
5. **模拟法的坑**：若用 `i = (i + 1) % n` 的循环指针模拟，必须**跳过已买完（剩余 0）的人**，否则会把离开的人再算一秒。
6. **溢出**：$n \cdot \max \leq 10^4$，`int` 足够，无需 `long long`。
