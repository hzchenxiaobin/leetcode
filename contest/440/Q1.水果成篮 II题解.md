# LeetCode 水果成篮 II 题解

## 1. 题目概述

- **标题 / 题号**：水果成篮 II（#3477，easy）
- **链接**：https://leetcode.cn/problems/fruits-into-baskets-ii/
- **来源**：LeetCode 第 440 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定长度均为 $n$ 的数组 `fruits` 与 `baskets`，`fruits[i]` 表示第 $i$ 种水果的数量，`baskets[j]` 表示第 $j$ 个篮子的容量。从左到右逐个放置水果：每种水果必须放入**最左侧**那个容量**大于等于**该水果数量且**未被占用**的篮子；每个篮子只能装一种水果；放不进任何篮子的水果保持未放置。返回最终未放置的水果种类数。

**约束**：

- `n == fruits.length == baskets.length`
- `1 <= n <= 100`
- `1 <= fruits[i], baskets[i] <= 1000`

## 2. 示例

**示例 1**

```text
输入：fruits = [4,2,5], baskets = [3,5,4]
输出：1
解释：
- fruits[0] = 4：篮 0 容量 3 不足，放入篮 1（容量 5 ≥ 4）。
- fruits[1] = 2：篮 0 空闲且容量 3 ≥ 2，放入篮 0。
- fruits[2] = 5：只剩篮 2（容量 4 < 5），无法放置。
有 1 种水果未放置，返回 1。
```

**示例 2**

```text
输入：fruits = [3,6,1], baskets = [6,4,7]
输出：0
解释：
- fruits[0] = 3 放入篮 0（6 ≥ 3）。
- fruits[1] = 6：篮 1 容量 4 不足，放入篮 2（7 ≥ 6）。
- fruits[2] = 1 放入篮 1（4 ≥ 1）。
所有水果均已放置，返回 0。
```

**示例 3**（自造，验证"每个水果从下标 0 重新扫描"）

```text
输入：fruits = [3,1], baskets = [1,3]
输出：0
解释：
- fruits[0] = 3：篮 0 容量 1 不足，放入篮 1。
- fruits[1] = 1：从下标 0 重新扫，篮 0 空闲且 1 ≥ 1，放入篮 0。
后处理的水果可以落在比前一个水果更靠左的篮子里。
```

## 3. 解题思路

### 3.1 暴力思路

签到题。$n \le 100$ 意味着最朴素的 $O(n^2)$ 双重循环（每个水果从头扫一遍所有篮子）也只有 $10^4$ 量级的比较，完全在时限内——**模拟本身就是正解**。比赛时要做的是快速切入、一次写对，而不是优化。

### 3.2 核心观察：过程完全确定，逐字模拟即可

![核心规则：放入最左侧容量足够的可用篮子](images/fruits_baskets_ii_concept.svg)

本题的关键观察是：**放置过程没有任何决策自由度**。水果的处理顺序固定（从左到右），每个水果的归宿也由规则唯一确定（最左侧容量足够的可用篮子，或未放置）。因此不存在"策略是否最优"的问题——不存在策略，按题意逐字模拟即得到唯一答案。

真正决定 AC 与 WA 的是把题面三个词看准：

1. **最左侧**：按下标从小到大找**第一个**满足条件的篮子，而不是任意一个能装下的。
2. **可用**：已被占用的篮子必须跳过，且篮子一经占用**永不释放**。
3. **大于等于**：容量恰好等于数量时可以放入，即判断条件是 `baskets[j] >= fruits[i]`。

### 3.3 算法流程

1. 维护 `used[j]` 表示篮 $j$ 是否已被占用，初始全为 `false`；`unplaced = 0`。
2. 按 $i = 0 \to n-1$ 依次处理每个水果 `fruits[i]`：
   - 从 `j = 0` 向右找第一个满足 `used[j] == false` 且 `baskets[j] >= fruits[i]` 的下标 $j$；
   - 找到：置 `used[j] = true`；
   - 找不到：`unplaced += 1`，继续处理下一个水果（**不中断、不回退**）。
3. 返回 `unplaced`。

### 3.4 示例演算

对示例 1 `fruits = [4,2,5]`，`baskets = [3,5,4]` 逐步走查：

| 步骤 | 当前水果 | 扫描过程 | 结果 |
|------|----------|----------|------|
| 1 | fruits[0] = 4 | 篮 0：容量 3 < 4 ✗ → 篮 1：容量 5 ≥ 4 ✓ | 放入篮 1 |
| 2 | fruits[1] = 2 | 篮 0：空闲且 3 ≥ 2 ✓ | 放入篮 0 |
| 3 | fruits[2] = 5 | 篮 0 已占 → 篮 1 已占 → 篮 2：容量 4 < 5 ✗ | 未放置 |

最终只有 `fruits[2]` 未放置，答案为 **1**。

![示例 1 逐步演算](images/fruits_baskets_ii_walkthrough.svg)

## 4. 算法细节

1. **占用状态**：用 `bool used[n]` 记录占用；扫描时先判 `used[j]` 再判容量（也可就地把 `baskets[j]` 改成 0 以省空间，但可读性稍差）。
2. **每个水果独立扫描**：无论上一个水果落在哪，当前水果都从下标 0 重新找"最左侧"，各次扫描互不影响。
3. **判断条件**：`!used[j] && baskets[j] >= fruits[i]`，注意是 `>=` 不是 `>`。
4. **计数**：内层扫描走到 $j = n$ 仍未命中才计入未放置；随后继续外层循环，失败不阻塞后续水果。

## 5. 正确性证明

**引理 1（归宿唯一确定）**：对任意时刻的篮子占用状态与当前水果 `fruits[i]`，题面规则唯一确定该水果的归宿：若存在未占用且容量大于等于 `fruits[i]` 的篮子，则归宿为其中**下标最小**的一个；否则该水果未放置。

**证明**：题面规定水果"必须放入第一个容量大于等于该水果数量的最左侧可用篮子"，即未占用且容量足够的篮子中下标最小者；若这样的篮子不存在，题面规定其保持未放置。两种情况均无选择余地，归宿是当前状态的确定性函数。∎

**引理 2（模拟不变量）**：算法处理完前 $i$ 个水果后，`used` 数组恰好等于按题面规则放置前 $i$ 个水果后的篮子占用状态，且 `unplaced` 等于前 $i$ 个水果中放不下的个数。

**证明**：对 $i$ 归纳。$i = 0$ 时两者均为初始状态，成立。假设结论对 $i$ 成立。处理第 $i+1$ 个水果时，算法从下标 0 起查找第一个 `!used[j] && baskets[j] >= fruits[i]` 的篮子：由归纳假设，`used` 与规则执行 $i$ 步后的占用状态一致；由引理 1，算法命中的篮子（或"不存在"的判定）正是规则为该水果指定的归宿。更新 `used[j]`（或 `unplaced += 1`）后，状态与规则执行 $i+1$ 步后仍一致。∎

**定理**：算法返回值等于按题面规则完成全部放置后未放置的水果种类数。

**证明**：在引理 2 中取 $i = n$ 即得。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。每个水果最坏从头扫一遍全部 $n$ 个篮子；$n \le 100$ 时至多 $10^4$ 次比较，远低于时限。
- **空间复杂度**：$O(n)$，即 `used` 数组；若就地修改 `baskets` 标记占用，可降为 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numOfUnplacedFruits(vector<int>& fruits, vector<int>& baskets) {
        int n = fruits.size();
        vector<bool> used(n, false);
        int unplaced = 0;
        for (int i = 0; i < n; i++) {
            int j = 0;
            while (j < n && (used[j] || baskets[j] < fruits[i])) j++;
            if (j < n) used[j] = true;
            else unplaced++;
        }
        return unplaced;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def numOfUnplacedFruits(self, fruits: List[int], baskets: List[int]) -> int:
        n = len(fruits)
        used = [False] * n
        unplaced = 0
        for f in fruits:
            j = 0
            while j < n and (used[j] or baskets[j] < f):
                j += 1
            if j < n:
                used[j] = True
            else:
                unplaced += 1
        return unplaced
```

## 8. 边界情况与易错点

1. **漏判 `used`**：只比较容量会让同一个篮子装下多种水果，是最常见的 WA 点。
2. **没从下标 0 重新扫**：不能从上一个水果的落点继续向后找——后处理的水果可能落进更靠左的篮子（见示例 3）。
3. **`>` 与 `>=`**：容量恰好等于数量（如 `baskets[j] = fruits[i] = 3`）时可以放入。
4. **放不下不中断**：某水果放置失败后，后续水果照常处理，不要提前退出或回退调整。
5. **不要排序**："最左侧"按原始下标定义，对 `baskets` 按容量排序会得到完全错误的放置结果。
6. **极端规模**：$n = 1$ 且 `baskets[0] < fruits[0]`（答案 1）；全部放得下（答案 0）；全部放不下（答案 $n$）。
