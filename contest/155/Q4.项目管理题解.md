# LeetCode 项目管理 题解

## 1. 题目概述

- **标题 / 题号**：项目管理（#1203，hard）
- **链接**：https://leetcode.cn/problems/sort-items-by-groups-respecting-dependencies/
- **来源**：LeetCode 第 155 场周赛 Q4
- **难度**：困难
- **标签**：图、拓扑排序、广度优先搜索、深度优先搜索、有向无环图

**题意**：有 $n$ 个项目，`group[i]` 是第 $i$ 个项目所属的组（`-1` 表示不属于任何组），`beforeItems[i]` 列出**必须排在 $i$ 左边**的所有项目。要求返回一个项目排列，同时满足两点：① 同组项目在排列中占据一段连续位置（组与组不交叉穿插）；② 对每个 $u \in \text{beforeItems}[i]$，$u$ 出现在 $i$ 左边。多解时返回任意一个，无解返回空列表 `[]`。允许存在没有任何项目的空组，也允许项目不带组号。

**约束**：

- $1 \le m \le n \le 3 \times 10^4$，注意 $m$ 可以等于 $n$，组的编号空间要按「重编号之后」计算；
- `group.length == beforeItems.length == n`，`-1 <= group[i] <= m - 1`；
- `0 <= beforeItems[i].length <= n - 1`，`i != beforeItems[i][j]`，同一 `beforeItems[i]` 内无重复元素；
- 记依赖边总数 $E = \sum_{i} \lvert \text{beforeItems}[i] \rvert$，各层开销都应写成 $O(n + m + E)$ 而不是 $O(nm)$。

## 2. 示例

**示例 1**

```text
输入：n = 8, m = 2, group = [-1,-1,1,0,0,1,0,-1]
      beforeItems = [[],[6],[5],[6],[3,6],[],[],[]]
输出：[6,3,4,1,5,2,0,7]
解释：组 0 = {3,4,6}、组 1 = {2,5} 各自连成一段；6 在 1、3、4 之前，5 在 2 之前，3 在 4 之前。
```

**示例 2**

```text
输入：n = 8, m = 2, group = [-1,-1,1,0,0,1,0,-1]
      beforeItems = [[],[6],[5],[6],[3],[],[4],[]]
输出：[]
解释：与示例 1 只差第 4、6 个项目的依赖，但此时 6→3→4→6 形成环（全在组 0 内部），无解。
```

**补充示例（非官方，用来说明无组项目的处理）**

```text
输入：n = 6, m = 2, group = [0,0,1,1,-1,-1], beforeItems = [[],[],[3],[],[],[0]]
输出：[0,1,3,2,4,5]
解释：项目 4、5 无组号，各自成为大小为 1 的独立块；唯一跨组依赖 0→5 让 5 的块排在组 0 之后。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `0..n-1` 的全排列并逐个校验「同组相邻」与「依赖有序」，复杂度 $O(n! \cdot n)$，$n = 3\times10^4$ 时连 $n=10$ 都吃力。

能不能只做一次拓扑排序？不能。「依赖有序」可以表达成边，「同组相邻」却不能：两个项目 $a_1, a_2$ 同组、另有别组的 $b_1$、三者毫无依赖时，`[a1, b1, a2]` 是合法拓扑序，却把同组项目劈成两段。若改为枚举组的先后顺序再拼组内拓扑序，状态数是 $m!$，同样不可行。**卡点在于：两类约束分别作用在「组之间」与「组内部」两个层级，而单张图只能刻画其中一层。**

### 3.2 核心观察：两级图 —— 组间定顺序，组内定顺序

![两级建模：项目图投影成群组图](images/wc155_q4_two_level_projection.svg)

**带块的结构**：合法排列里同组项目必然连续，把这段区间叫该组的**块**，整个排列就是若干块的拼接（空组对应长度为 0 的块）。

**投影**：把每块收缩成一个点。一条依赖边 $u \to v$ 若满足 $g[u] = g[v]$（同组边），它只约束块**内部**的先后，收缩后不产生块间约束；若 $g[u] \ne g[v]$（跨组边），则要求 $u$ 的块整体排在 $v$ 的块之前，收缩后就是群组图上的边 $g[u] \to g[v]$。于是任务被拆成两层：先用**群组图**拓扑排序确定块的先后，再在每个块内用**项目图的组内诱导子图**拓扑排序确定块内顺序。

**无组项目**：给每个 `group[i] == -1` 的项目分配一个全新组号（依次取 $m, m+1, \dots$），它就变成大小为 1 的块。这样 `-1` 不再需要特判，而单元素块必然连续，不会破坏任何约束。

**为什么两层都无环就一定有解**：块间顺序只由跨组边决定，块内顺序只由同组边决定，两类边互不干扰；拼接后每条依赖边要么落在块内被块内拓扑序满足，要么落在块间被块间拓扑序满足。反过来，群组图有环意味着某个块必须排在自己前面，某组内部有环意味着块内排不出合法顺序——两者都是充分的否决条件。

### 3.3 算法流程

![两级拓扑排序的完整流程](images/wc155_q4_algorithm_flow.svg)

1. **重编号**：把 `group[i] == -1` 的项目依次分配到新组号 $m, m+1, \dots$，得到 `total` 个组。
2. **建项目图**：对每个 $i$ 与每个 $u \in \text{beforeItems}[i]$ 加边 $u \to i$。
3. **建群组图**：遍历同样的依赖边，仅当 $g[u] \ne g[i]$ 时加边 $g[u] \to g[i]$ 并统计组入度；**同组边不要加**，否则会变成自环。
4. **群组拓扑排序**（Kahn）：入度为 0 的组入队，逐个出队松弛后继；若出队组数 $\ne$ `total`，群组图有环，返回 `[]`。
5. **分组 + 组内拓扑排序**：项目按所属组装桶，再按第 4 步的组拓扑序逐块处理；块内只统计**同组前驱**的入度做局部 Kahn，出队数小于块大小则返回 `[]`。
6. **拼接**：把各块的组内拓扑序依次接到答案末尾。

### 3.4 示例演算

![示例 1 走查：重编号 → 群组拓扑 → 组内拓扑](images/wc155_q4_example_walkthrough.svg)

| 环节 | 示例 1 的结果 |
|------|----------------|
| 原始 `group` | `[-1,-1,1,0,0,1,0,-1]`，无组项目是 0、1、7 |
| 重编号后 `g` | `[2,3,1,0,0,1,0,4]`，组总数 `total = 5` |
| 组内边 | 组 0：$6\to3$、$3\to4$、$6\to4$；组 1：$5\to2$ |
| 跨组边 | 只有 $6\to1$ ⇒ 群组边 $0\to3$ |
| 群组拓扑序 | 由 $0\to3$ 得组 0 先于组 3，可取 `0, 1, 2, 4, 3` |
| 块与拼接 | `[6,3,4]`、`[5,2]`、`[0]`、`[7]`、`[1]` ⇒ `[6,3,4,5,2,0,7,1]` |

（输出任意合法解即可，官方给出的是 `[6,3,4,1,5,2,0,7]`。）

示例 2 的区别只在依赖：`beforeItems[6] = [4]` 添了 $4\to6$，与原有的 $6\to3$、$3\to4$ 在组 0 内部形成 $6\to3\to4\to6$ 的环，而跨组层面一条边都没有。**这正是本算法必须在第 5 步再查一次组内环的原因：只检查群组图会漏判。**

## 4. 算法细节

1. **组号空间**：`total = m + 无组项目个数`，最坏 $2n$。`adj_g`、`indeg_g`、`members` 都按 `total` 开，按 `m` 开必越界。
2. **边的方向**：`beforeItems[i]` 是「必须排在 $i$ 前的项目」，故边为 $u \to i$；写反会把整个拓扑序倒过来。
3. **群组图只收跨组边**：同组边入图会生成 `g[u] -> g[u]` 自环，让有解样例直接返回 `[]`。
4. **判环看出队数**：Kahn 结束后比较 `len(order) == total` 或块内 `cnt == len(ids)`；不要比较「出现过几个入度为 0 的点」，因为入度 0 可能在松弛后才出现。
5. **组内入度必须重算**：全局入度含跨组前驱，而这些前驱已由块间顺序保证；若直接复用，块内会一个都出不了队，被误判成环。只统计「前驱与本项目同组」的边。
6. **重复边无害**：不同项目之间可能产生相同的组间边，入度与松弛次数同步增加，计数自洽，不必去重。
7. **块内入度表用 `dict` / `unordered_map`**：只对块内项目建表，避免每组开长度 $n$ 的数组导致 $O(n \cdot \text{组数})$ 退化；空组直接 `continue`。

## 5. 正确性证明

**引理 1（必要性）**：若存在满足条件的排列，则群组图无环，且每个组诱导出的项目子图无环。

**证明**：设 $P$ 是合法排列。由同组相邻，每组 $c$ 的项目在 $P$ 中占据连续区间 $B_c$（空组为空区间）。对群组图的任一条边 $a \to b$，它来自某条跨组依赖 $u \to v$（$g[u]=a$、$g[v]=b$）；$P$ 中 $u$ 在 $v$ 左边，同组连续故整块 $B_a$ 都在 $B_b$ 左边。按块左端点给组编号即得群组图的一个拓扑序，故群组图无环。再固定组 $c$，把 $P$ 限制在 $B_c$ 上，每条两端都在 $c$ 内的依赖边仍保持先后（继承自 $P$），故它是该组诱导子图的拓扑序，无环。∎

**引理 2（构造正确）**：若群组图无环、每个组的诱导子图无环，则「群组拓扑序 × 块内拓扑序」的拼接序列合法。

**证明**：设群组拓扑序为 $c_1, \dots, c_k$，第 $t$ 块内部按组内拓扑序排列，拼接序列记为 $R$。*同组相邻*：$R$ 是各块首尾相接，块 $c_t$ 的项目在 $R$ 中连续且不同块不相交。*依赖有序*：任取依赖边 $u \to v$；若 $g[u] = g[v] = c$，$u, v$ 同在块 $c$ 内，组内拓扑序保证 $u$ 在 $v$ 前；若 $g[u] \ne g[v]$，群组图有边 $g[u] \to g[v]$，群组拓扑序保证块 $g[u]$ 整体先于块 $g[v]$，故 $u$ 在 $v$ 前。∎

**引理 3（Kahn 判环）**：对有向图跑 Kahn，出队顶点数等于顶点总数 $\iff$ 图无环。

**证明**：若图无环，取拓扑序中最靠前的未出队顶点，它不可能有未出队的前驱，故入度已为 0 会被入队，归纳可知全部出队。若有环，环上顶点在环内总有前驱，其入度永不为 0（入度只被环外边减少），故环上顶点永不出队。∎

**定理**：算法返回的序列是合法排列；无解时返回 `[]`。

**证明**：情形一，群组图有环：第 4 步出队数不足而返回 `[]`，由引理 1 此时无合法排列。情形二，群组图无环但某组内部有环：第 5 步该块出队数小于块大小而返回 `[]`，同样由引理 1 知无解。情形三，两层都无环：两步都不中断，引理 2 保证拼接结果满足同组相邻与依赖有序，且每个项目恰属于一个块，故 $R$ 是 $0..n-1$ 的排列，返回正确。∎

## 6. 复杂度分析

- **时间**：$O(n + m + E)$。重编号 $O(n)$；建两张图各扫一遍依赖边 $O(E)$；群组图 Kahn $O(\text{total} + E)$，其中 $\text{total} \le m + n$；块内 Kahn 对每条组内边只处理一次，合计 $O(n + E)$。**没有**按组数乘 $n$ 的开销。
- **空间**：$O(n + m + E)$。项目图邻接表 $O(n + E)$，群组图邻接表与入度 $O(\text{total} + E)$，分桶数组共 $n$ 个元素，块内入度表最大为一个块的大小，答案数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<int> sortItems(int n, int m, vector<int>& group, vector<vector<int>>& beforeItems) {
        vector<int> g = group;
        int total = m;
        for (int i = 0; i < n; i++) if (g[i] == -1) g[i] = total++;

        vector<vector<int>> adjItem(n);
        vector<int> indegG(total, 0);
        vector<vector<int>> adjG(total);
        for (int v = 0; v < n; v++) {
            for (int u : beforeItems[v]) {
                adjItem[u].push_back(v);              // 项目图：u 排在 v 之前
                if (g[u] != g[v]) {                   // 群组图只收跨组边
                    adjG[g[u]].push_back(g[v]);
                    indegG[g[v]]++;
                }
            }
        }
        queue<int> q;
        for (int x = 0; x < total; x++) if (indegG[x] == 0) q.push(x);
        vector<int> order;
        while (!q.empty()) {
            int x = q.front(); q.pop();
            order.push_back(x);
            for (int y : adjG[x]) if (--indegG[y] == 0) q.push(y);
        }
        if ((int)order.size() != total) return {};    // 群组图有环

        vector<vector<int>> members(total);
        for (int i = 0; i < n; i++) members[g[i]].push_back(i);

        vector<int> res;
        for (int grp : order) {
            const vector<int>& ids = members[grp];
            if (ids.empty()) continue;
            unordered_map<int, int> indeg;            // 只统计同组前驱
            for (int v : ids) indeg[v] = 0;
            for (int v : ids)
                for (int u : beforeItems[v])
                    if (g[u] == grp) indeg[v]++;
            queue<int> q2;
            for (int v : ids) if (indeg[v] == 0) q2.push(v);
            int cnt = 0;
            while (!q2.empty()) {
                int v = q2.front(); q2.pop();
                res.push_back(v); cnt++;
                for (int w : adjItem[v])
                    if (g[w] == grp && --indeg[w] == 0) q2.push(w);
            }
            if (cnt != (int)ids.size()) return {};    // 组内有环
        }
        return res;
    }
};
```

### Python

```python
from typing import List
from collections import deque

class Solution:
    def sortItems(self, n: int, m: int, group: List[int], beforeItems: List[List[int]]) -> List[int]:
        g, total = group[:], m
        for i in range(n):
            if g[i] == -1:
                g[i] = total
                total += 1

        adj_item = [[] for _ in range(n)]
        indeg_g = [0] * total
        adj_g = [[] for _ in range(total)]
        for v in range(n):
            for u in beforeItems[v]:
                adj_item[u].append(v)          # 项目图：u 排在 v 之前
                if g[u] != g[v]:               # 群组图只收跨组边
                    adj_g[g[u]].append(g[v])
                    indeg_g[g[v]] += 1
        dq = deque(x for x in range(total) if indeg_g[x] == 0)
        group_order = []
        while dq:
            x = dq.popleft()
            group_order.append(x)
            for y in adj_g[x]:
                indeg_g[y] -= 1
                if indeg_g[y] == 0:
                    dq.append(y)
        if len(group_order) != total:          # 群组图有环
            return []

        members = [[] for _ in range(total)]
        for i in range(n):
            members[g[i]].append(i)
        res = []
        for grp in group_order:
            ids = members[grp]
            if not ids:
                continue
            indeg = {v: 0 for v in ids}        # 只统计同组前驱
            for v in ids:
                for u in beforeItems[v]:
                    if g[u] == grp:
                        indeg[v] += 1
            q = deque(v for v in ids if indeg[v] == 0)
            cnt = 0
            while q:
                v = q.popleft()
                res.append(v)
                cnt += 1
                for w in adj_item[v]:
                    if g[w] == grp:
                        indeg[w] -= 1
                        if indeg[w] == 0:
                            q.append(w)
            if cnt != len(ids):                # 组内有环
                return []
        return res
```

## 8. 边界情况与易错点

1. **全部项目都无组号 / $m = n$**：前者让 $n$ 个项目变成 $n$ 个大小为 1 的块（任意顺序都合法），两者的 `total` 上界都是 $2n$，按 `m` 开数组必越界。
2. **同组边写进群组图**：造出自环 $g[u] \to g[u]$，示例 1 这类有解样例会被错误地判成无解。
3. **块内复用全局入度**：跨组前驱的入度没扣掉，块内队列一开始就空，示例 1 的组 0 会「假死」。
4. **只检查群组图不检查组内**：示例 2 的环完全在组 0 内部，跨组图是没有任何边的 DAG，漏掉第二次判环就会输出违反依赖的排列。
5. **用「入度为 0 的点个数」判环**：入度 0 可能是松弛后新产生的，必须在 Kahn 结束后比较**出队数**。
6. **`beforeItems` 整体为空**：项目图无边，块内顺序退化为任意顺序，结果应等于按群组拓扑序依次列出各组项目，检查实现是否仍输出完整排列。
