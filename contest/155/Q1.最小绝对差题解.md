# LeetCode 最小绝对差 题解

## 1. 题目概述

- **标题 / 题号**：最小绝对差（#1200，easy）
- **链接**：https://leetcode.cn/problems/minimum-absolute-difference/
- **来源**：LeetCode 第 155 场周赛 Q1
- **难度**：简单
- **标签**：数组、排序

**题意**：给定一个元素**互不相同**的整数数组 `arr`，先求出任意两个元素之间的最小绝对差 $d_{\min}$，再把**所有**绝对差恰好等于 $d_{\min}$ 的元素对找出来。每对写成 $[a, b]$ 且要求 $a < b$，最终答案按 $[a, b]$ 的升序（字典序）返回。

换一种说法：在数轴上标出所有点，找最近的一对（或几对）点，把它们的坐标按从左到右、每对内部小值在前的顺序输出。

**约束**：

- $2 \le \text{arr.length} \le 10^5$
- $-10^6 \le \text{arr}[i] \le 10^6$
- `arr` 中所有元素**互不相同**

> 💡 Q1 的定位是签到题：思路一眼可见，但「为什么排序后只看相邻元素」这一步值得写清楚，它是后面一堆「最近点对 / 最小间隔」问题的公共引理。真正容易翻车的不是算法，而是**结果的有序性**与**边界取值**。

## 2. 示例

**示例 1**

```text
输入：arr = [4,2,1,3]
输出：[[1,2],[2,3],[3,4]]
解释：最小绝对差为 1，差为 1 的对有 (1,2)、(2,3)、(3,4)，按升序返回。
```

**示例 2**

```text
输入：arr = [1,3,6,10,15]
输出：[[1,3]]
解释：最小绝对差为 2，只有 (1,3) 这一对的差为 2；
      其余相邻差为 3、4、5，都更大。
```

**示例 3**

```text
输入：arr = [3,8,-10,23,19,-4,-14,27]
输出：[[-14,-10],[19,23],[23,27]]
解释：升序后为 [-14,-10,-4,3,8,19,23,27]，相邻间隔 4、6、7、5、11、4、4，
      最小值为 4，出现在第 0、5、6 个间隔上，共三对。
```

三个示例的区别值得注意：示例 1 的最小差出现了 3 次，示例 2 只出现 1 次，示例 3 的元素含负数且最小差在中间位置也出现——**答案对的数量没有上界**，最坏情况下（等差数组）$n-1$ 对全部入选。

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $\binom{n}{2}$ 个元素对，逐个算 $|a - b|$ 求最小值，再枚举一遍把等于最小值的对收集起来。时间 $O(n^2)$，$n = 10^5$ 时约 $5 \times 10^9$ 次比较，**必然超时**；空间还要额外存放结果。

问题出在「无序数组里找最近的两点」没有利用任何顺序信息：任意一对都要单独算一次距离，而其中绝大多数对相隔很远，注定不可能是答案。

### 3.2 核心观察：最小差必在某对相邻元素之间

![排序后非相邻对的距离等于跨过的相邻间隔之和](images/wc155_q1_adjacent_lemma.svg)

先把 `arr` **升序排序**。排序后，任意一对 $i < j$ 的距离可以拆成一段「相邻间隔之和」：

$$\text{arr}[j] - \text{arr}[i] = \sum_{k=i}^{j-1} \bigl(\text{arr}[k+1] - \text{arr}[k]\bigr) = \sum_{k=i}^{j-1} \text{gap}[k]$$

其中 $\text{gap}[k] = \text{arr}[k+1] - \text{arr}[k] > 0$（元素互不相同保证严格大于 0）。

这个恒等式立刻给出两条结论：

1. **筛掉非相邻对**：上式是若干**正数**之和，故它不小于其中任意一项，特别是不小于 $\min_k \text{gap}[k]$。也就是说非相邻对的距离永远不可能**严格小于**当前最小相邻间隔。
2. **相邻对足够**：把上式取遍所有 $i < j$，全局最小值一定在 $j = i+1$ 时取到（相邻对本身就是合法元素对）。

于是问题从「在 $O(n^2)$ 个对里找最小」塌缩成「在 $n-1$ 个相邻间隔里找最小」，这就是本题的全部魔法。

### 3.3 算法流程

![两遍扫描：先定 best 再收集](images/wc155_q1_two_pass_flow.svg)

1. **排序**：`sort(arr)`，$O(n \log n)$。
2. **第一遍求最小间隔**：`best = min(arr[i+1] - arr[i])`，$i \in [0, n-2]$，共 $n-1$ 项，$O(n)$。
3. **第二遍收集**：从 $i = 0$ 递增到 $n-2$，若 `arr[i+1] - arr[i] == best`，把 `{arr[i], arr[i+1]}` 追加到结果，$O(n)$。
4. **直接返回**：因为 $i$ 递增且数组升序，结果天然按升序排列，无需再排一次。

第 3 步要特别注意「别提前 break」：`best` 是最小值，可能被多对同时达到，必须扫完全部 $n-1$ 个间隔。

### 3.4 示例演算

![示例 3 的排序、间隔与收集过程](images/wc155_q1_walkthrough.svg)

以示例 3 的 `arr = [3,8,-10,23,19,-4,-14,27]` 为例：

| 步骤 | 内容 |
|------|------|
| 排序后 | $-14,\ -10,\ -4,\ 3,\ 8,\ 19,\ 23,\ 27$ |
| 相邻间隔 | $4,\ 6,\ 7,\ 5,\ 11,\ 4,\ 4$（共 7 个） |
| 第一遍 | $\text{best} = \min(4,6,7,5,11,4,4) = 4$ |
| 第二遍 | 间隔下标 $0, 5, 6$ 处等于 4，收集三对 |
| 输出 | $[-14,-10],\ [19,23],\ [23,27]$ |

再核对示例 1：排序得 $1,2,3,4$，间隔 $1,1,1$，$\text{best} = 1$，三处全中，输出 $[1,2],[2,3],[3,4]$；示例 2 排序后间隔为 $2,3,4,5$，$\text{best} = 2$ 只出现一次，输出 $[1,3]$。三个示例的答案都与「只看相邻间隔」的预测一致。

## 4. 算法细节

1. **排序是唯一的重活**：总时间 $O(n \log n)$ 全部压在排序上；两遍扫描各 $O(n)$，常数极小。不要写「排序后对每个 $i$ 再向两侧扩展」那种写法，那会退化回 $O(n^2)$。
2. **`best` 的初值**：直接取 `arr[1] - arr[0]`（$n \ge 2$ 由约束保证），比用 `INT_MAX` 更省一次判断，也避免了「万一忘了更新就返回 INF」的隐患。
3. **`a` 与 `b` 的顺序**：排序后 `arr[i] < arr[i+1]` 恒成立，所以 `{arr[i], arr[i+1]}` 自动满足 $a < b$；不要在收集时再写一次 `min/max`，更不要把这一对写成 `{arr[i+1], arr[i]}`。
4. **结果的有序性来自排序**：循环下标 $i$ 递增，收集到的对首元素 $a$ 严格递增，故输出天然是字典序升序；额外调用一次 `sort` 是多余且容易写错的（比较器写反就全乱）。
5. **同一个 $a$ 只能配一个 $b$**：元素互不相同，所以对固定的 $a$，满足 $b - a = \text{best}$ 的 $b = a + \text{best}$ 最多一个，结果里不会出现「首元素相同、次元素不同」的对，字典序与「按 $a$ 升序」等价。
6. **值域很小，可以计数排序**：$\text{arr}[i] \in [-10^6, 10^6]$，理论上可用桶排做到 $O(n + 2 \times 10^6)$，但常数与内存都远大于 `std::sort`，周赛现场没有理由这么做；提一句是为了说明「排序不是瓶颈」。
7. **整数范围**：任何两个元素之差都落在 $[1, 2 \times 10^6]$ 内，`int` 完全够，不必开 `long long`；但不要写 `unsigned`，它会把负数卷成极大的正数，比较结果全错。
8. **允许重复的退化情况**：本题保证互不相同，故 `best >= 1`；若题目不保证，必须先处理「差为 0」的对（把所有相同值两两成对），逻辑要单独加一层，不能直接套用本节结论。

## 5. 正确性证明

**引理 1（非相邻对的距离不小于某个相邻间隔）**：设 `arr` 升序，对任意 $0 \le i < j \le n-1$，有

$$\text{arr}[j] - \text{arr}[i] \ge \text{gap}[k_0], \quad \text{其中 } \text{gap}[k_0] = \min_{k=i}^{j-1} \text{gap}[k]$$

**证明**：由裂项求和 $\text{arr}[j] - \text{arr}[i] = \sum_{k=i}^{j-1} \text{gap}[k]$，区间 $[i, j-1]$ 非空（因 $i < j$）。所有 $\text{gap}[k] \ge \text{gap}[k_0]$，于是该和 $\ge (j-i) \cdot \text{gap}[k_0] \ge \text{gap}[k_0]$，其中最后一个不等号用到 $j - i \ge 1$ 与 $\text{gap}[k_0] > 0$。∎

**引理 2（全局最小差 = 最小相邻间隔）**：令 $\text{best} = \min_{0 \le k \le n-2} \text{gap}[k]$，则

$$\min_{i<j} \bigl(\text{arr}[j] - \text{arr}[i]\bigr) = \text{best}$$

**证明**：

- $(\le)$：相邻对 $(k, k+1)$ 本身就是合法的元素对，故对每个 $k$ 都有左边 $\le \text{gap}[k]$；对 $k$ 取最小即得左边 $\le \text{best}$。
- $(\ge)$：任取 $i < j$，由引理 1 得 $\text{arr}[j] - \text{arr}[i] \ge \text{gap}[k_0] \ge \text{best}$，故左边 $\ge \text{best}$。

两者夹逼，等号成立。∎

**引理 3（收集到的对恰好是答案集）**：第二遍扫描收集的所有对，组成的集合恰好是 $\{(x, y) : x, y \in \text{arr},\ y - x = \text{best}\}$。

**证明**：

- **不漏**：设 $x = \text{arr}[i] < y = \text{arr}[j]$ 且 $y - x = \text{best}$。由裂项求和 $\sum_{k=i}^{j-1} \text{gap}[k] = \text{best}$，而每项 $\text{gap}[k] \ge \text{best}$，若 $j - i \ge 2$ 则和 $\ge 2\,\text{best} > \text{best}$，矛盾；故 $j = i + 1$ 且 $\text{gap}[i] = \text{best}$，第二遍扫描到 $i$ 时必然收集到该对。
- **不多**：被收集的对都满足 `arr[i+1] - arr[i] == best`，显然属于答案集。

∎

**定理**：算法返回的列表恰好包含所有最小绝对差的元素对，且按 $[a,b]$ 升序排列。

**证明**：由引理 2，算法求出的 `best` 就是题目要求的最小绝对差；由引理 3，结果集合正确且完整。关于顺序：设收集序列为 $(a_1, b_1), (a_2, b_2), \dots$，对应下标 $i_1 < i_2 < \dots$，则 $a_t = \text{arr}[i_t]$ 随 $t$ 严格递增（数组严格升序），故按首元素升序；又由细节 5，同一首元素不会对应两个次元素，所以按首元素升序即按 $[a,b]$ 字典序升序。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $\Theta(n \log n)$ 为唯一非线性的部分；第一遍扫描 $n-1$ 次减法与比较，第二遍扫描 $n-1$ 次比较与至多 $n-1$ 次追加，均为 $O(n)$。总时间 $O(n \log n)$，$n = 10^5$ 时约 $1.7 \times 10^6$ 次基本操作，远快于 $O(n^2)$ 的 $5 \times 10^9$。
- **空间**：$O(n)$。C++ 的 `std::sort` 需要 $O(\log n)$ 的栈空间；Python 的 `sorted` 会复制一份长度 $n$ 的列表，故额外空间 $O(n)$。结果数组最坏 $n-1$ 个对、每对 2 个整数，同样 $O(n)$。若把两遍扫描合并，空间不变。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> minimumAbsDifference(vector<int>& arr) {
        sort(arr.begin(), arr.end());                       // ① 升序排序

        int n = arr.size();
        int best = arr[1] - arr[0];                         // ② best 初值取第一个间隔
        for (int i = 1; i + 1 < n; ++i) {
            best = min(best, arr[i + 1] - arr[i]);          // 第一遍：求最小相邻间隔
        }

        vector<vector<int>> res;
        for (int i = 0; i + 1 < n; ++i) {
            if (arr[i + 1] - arr[i] == best) {
                res.push_back({arr[i], arr[i + 1]});        // ③ 第二遍：按 i 递增收集，天然升序
            }
        }
        return res;                                         // ④ 不需要再排序
    }
};
```

### Python

```python
from typing import List


class Solution:
    def minimumAbsDifference(self, arr: List[int]) -> List[List[int]]:
        arr = sorted(arr)                                    # ① 升序排序（不修改入参）

        best = min(arr[i + 1] - arr[i] for i in range(len(arr) - 1))   # ② 最小相邻间隔

        # ③ 按 i 递增收集，结果天然升序；列表推导保证顺序与下标一致
        return [[arr[i], arr[i + 1]] for i in range(len(arr) - 1)
                if arr[i + 1] - arr[i] == best]
```

> 💡 若担心把两遍扫描写重，也可以在第一遍里同时维护 `best` 与「当前等于 `best` 的对」：一旦遇到更小的间隔就清空结果再重新收集。但这种写法每次刷新 `best` 都要清空列表，边界多、易漏，周赛现场不划算。

## 8. 边界情况与易错点

1. **$n = 2$**：只有一个间隔，`best` 就是它，结果恰好一对。此时 `best` 的初值（`arr[1] - arr[0]`）与最终答案相同，第一遍循环一次也不执行，代码仍然正确——这是最容易被忽略的「循环不进入」边界。
2. **负数元素不影响比较**：数组含负数（如示例 3 的 $-14$）不会影响任何逻辑，因为排序后 `arr[i+1] - arr[i]` 恒为正，直接相减就是绝对差；若习惯性写成 `abs(arr[i+1] - arr[i])`，结果一样但多一次无谓调用，还会让人误以为必须处理符号。
3. **答案不会为空**：$n \ge 2$ 时至少有一个间隔，`best` 必然被某个间隔取到，所以结果至少一对。若代码里出现「返回空列表」，通常是 `best` 初值写成了 `INT_MAX` 却忘了在第一遍里更新，或把循环条件写成 `i < n - 2` 漏掉了最后一项。
4. **漏掉「最小值重复出现」**：只找到第一个等于 `best` 的间隔就 `return`，会在示例 1、示例 3 上直接错。必须收集完整后再返回。
5. **误把结果再排序**：结果已经升序，多写一次排序不会错，但若自定义比较器只比较 `a` 而比较器不满足严格弱序（例如写成 `<=`），`std::sort` 可能越界崩溃。最省事的做法就是**别排**。
6. **原地排序改变入参**：C++ 传的是 `vector<int>&`，`sort(arr.begin(), arr.end())` 会修改调用方数组。本题允许，但若后续还要用原顺序（例如需要返回下标），必须复制一份再排序。
7. **`i + 1 < n` 与 `i < n - 1` 等价但类型不同**：`n` 若是 `int`，`i < n - 1` 在 $n = 0$ 时会下溢成极大值；本题 $n \ge 2$ 不会触发，但写成 `i + 1 < n` 是更稳的习惯。
8. **输出格式**：返回值是「对的列表」，不是「元素列表」。每对必须是长度 2 的数组且满足 $a < b$；`[[1,2],[2,3]]` 与 `[[2,1],[3,2]]` 在判题时**不等价**。
9. **Python 的生成器为空**：`min(gen)` 在空序列上抛 `ValueError`。这里被 $n \ge 2$ 的约束保护，但如果把函数改造成可接受 $n < 2$ 的版本，必须显式特判。

**延伸思考**：

1. **允许重复元素**时，最小差可能为 0，答案变成「所有相同值的两两组合」，规模可达 $O(n^2)$，此时应先判 0 再按本题逻辑处理正差情形。
2. 若要求的是**第 $k$ 小的差值**，就不能只看相邻对：合法差值集合是 $\{\text{arr}[j]-\text{arr}[i]\}$，可用「二分答案 + 双指针计数」在 $O(n \log V)$ 内完成，本题的相邻结论在这里只是 $k=1$ 的特例。
3. 若要求输出**所有差值不超过 $T$ 的对**，排序后用双指针滑动即可，每个右端点对应的左端点区间连续，总复杂度 $O(n)$（不计排序）。
4. 把一维数轴换成平面上的点集，「最近点对」需要分治（$O(n \log n)$）；本题的「只看相邻」之所以成立，本质是**一维全序**让每一对的距离都能被单个相邻间隔下界控制，二维里这个性质不复存在。
