# LeetCode 电网维护 题解

## 1. 题目概述

- **标题 / 题号**：电网维护（#3607，medium）
- **链接**：https://leetcode.cn/problems/power-grid-maintenance/
- **来源**：LeetCode 第 457 场周赛 Q2
- **难度**：中等
- **标签**：并查集、有序集合、堆、图、模拟

**题意**：$c$ 个电站编号 $1..c$，$n$ 条双向电缆把电站划分成若干连通块（**电网**）。初始全部在线。给定 $q$ 条查询，按序处理：

- `[1, x]` 维护检查：若电站 $x$ **在线**，由 $x$ **自身**解决（答案为 $x$）；若 $x$ 已离线，由同一电网中**编号最小**的在线电站解决；若该电网已无在线电站，答案为 $-1$。
- `[2, x]` 电站 $x$ 离线。

返回所有 `[1, x]` 查询的答案构成的数组。注意电网结构固定：**离线不改变连接性**，离线电站仍属于其电网。

**约束**：

- $1 \le c \le 10^5$
- $0 \le n \le \min(10^5, \frac{c(c-1)}{2})$，无自环、无重边影响
- $1 \le q \le 2 \times 10^5$
- 电站一旦离线**永不恢复**（题目没有"重新上线"操作）

## 2. 示例

**示例 1**

```text
输入：c = 5, connections = [[1,2],[2,3],[3,4],[4,5]],
     queries = [[1,3],[2,1],[1,1],[2,2],[1,2]]
输出：[3,2,3]
解释：5 个电站连成一条链，属于同一电网 A。
     [1,3]：3 在线 → 自身解决，答案 3（注意：不是 1！）
     [2,1]：1 离线，在线集合 {2,3,4,5}
     [1,1]：1 离线 → 最小在线电站 2
     [2,2]：2 离线，在线集合 {3,4,5}
     [1,2]：2 离线 → 最小在线电站 3
```

**示例 2**

```text
输入：c = 3, connections = [], queries = [[1,1],[2,1],[1,1]]
输出：[1,-1]
解释：无连接，每个电站独立成电网。
     [1,1]：1 在线 → 答案 1；[2,1] 后其电网再无在线电站 → [1,1] 答案 -1。
```

**示例 3（自拟，覆盖"x 在线但非最小"与全离线）**

```text
输入：c = 4, connections = [[1,2],[3,4]],
     queries = [[1,4],[2,1],[1,2],[2,2],[1,2],[1,1]]
输出：[4,2,-1,-1]
解释：电网 A={1,2}，电网 B={3,4}。
     [1,4]：4 在线 → 答案 4（同电网 3 编号更小，但在线时由自身解决！）
     [2,1] → [1,2]：2 在线 → 答案 2
     [2,2] 后电网 A 全离线 → 后续 [1,2]、[1,1] 均为 -1
```

## 3. 解题思路

### 3.1 暴力思路

对每条 `[1, x]` 查询，遍历 $x$ 所在电网的全部电站，找出在线电站中的最小编号。最坏 $q \cdot c = 2\times10^5 \times 10^5 = 2\times10^{10}$ 次操作，必然超时。瓶颈在于**每次查询都重新扫描整组**——需要一个能动态维护"某组在线电站最小值"的数据结构。

### 3.2 核心观察：静态分组 + 每组一个在线集合

![核心观察概念图](images/power_grid_concept.svg)

三个关键性质决定了做法：

1. **连通性静态**：电网划分只由 `connections` 决定，离线操作不改变连接 → 开局用**并查集**把每个电站映射到所在电网的 root，之后 `find(x)` 就是 $O(\alpha)$ 的分组查询。
2. **离线不可逆**：没有"重新上线"操作 → 每个电站至多从在线集合中**删除一次**，全部删除操作总量 $\le c$。
3. **询问是"最小在线编号"**：给每个电网配一个按电站 id 升序的**有序集合**（C++ `std::set`），最小在线电站就是 `*begin()`。

> 💡 一句话套路：**静态结构用并查集预处理，动态成员用有序集合维护**。两个维度各自用最便宜的结构，互不干扰。

### 3.3 算法流程

![查询处理流程图](images/power_grid_query_flow.svg)

**预处理**（一次）：

1. 并查集合并所有 `connections`，得到每个电站的 root。
2. 对每个电网 root 建 `S[root]`，初始放入该电网**全部**电站 id（全部在线）。

**逐条处理查询**：

- `[2, x]`：标记 `offline[x] = true`，从 `S[find(x)]` 中 `erase(x)`（重复离线天然幂等）。
- `[1, x]`：
  - 若 `!offline[x]` → 答案就是 $x$ **自身**（哪怕同电网有编号更小的在线电站）；
  - 否则若 `S[find(x)]` 非空 → 答案 `*S[find(x)].begin()`；
  - 否则 → 答案 $-1$。

### 3.4 示例演算

![示例1演算图](images/power_grid_walkthrough.svg)

对示例 1 逐步走查（全部电站同属电网 A，$S$ 初始为 `{1,2,3,4,5}`）：

| i | 查询 | 动作 | S[A] | 答案 |
|---|------|------|------|------|
| 0 | [1,3] | 3 在线 → 自身 | {1,2,3,4,5} | 3 |
| 1 | [2,1] | 1 离线，erase(1) | {2,3,4,5} | — |
| 2 | [1,1] | 1 离线 → *begin() | {2,3,4,5} | 2 |
| 3 | [2,2] | 2 离线，erase(2) | {3,4,5} | — |
| 4 | [1,2] | 2 离线 → *begin() | {3,4,5} | 3 |

最终输出 `[3,2,3]` ✓

## 4. 算法细节

1. **并查集实现**：路径压缩（迭代写法防爆栈，$c$ 达 $10^5$ 时递归可能栈溢出）+ 按秩/大小合并均可，单次 `find` 近似 $O(1)$。
2. **集合挂在 root 上**：`vector<set<int>> s(c+1)`，只有 `s[find(x)]` 是有效的；孤立场站自成一组，其集合初始只含自己。
3. **在线判定 O(1)**：单独维护 `offline[x]` 布尔数组，避免每次 `[1,x]` 都去集合里 `count(x)`（省一个 $\log$，也更易读）。
4. **重复 `[2,x]` 幂等**：对已离线电站再离线，`erase` 一个不存在的元素是 no-op，`offline[x]` 重复置 true 无副作用，无需特判。
5. **Python 方案——逆序 + 小根堆**：Python 标准库没有有序集合（LeetCode 环境虽有 `sortedcontainers`，但面试/跨平台更稳妥的是标准库做法）。利用**离线不可逆**，把查询**倒过来处理**：删除全部变成插入，"最小在线"就是小根堆堆顶：
   - `off_time[x]` = 第一次 `[2,x]` 出现的下标 $i$（从未离线记 $\infty$）；
   - 初始把所有 `off_time[x] == ∞` 的电站按电网分组各自 `heapify`；
   - $i$ 从 $q-1$ 倒序扫：遇到 `[2,x]` 且 `off_time[x] == i` → `heappush(x)`（$x$ 在 $i$ 之前是"复活"的）；遇到 `[1,x]` → 若 `off_time[x] > i` 则 $x$ 在线答案为 $x$，否则答案为堆顶（堆空为 $-1$）。

   ![逆序堆技巧图](images/power_grid_reverse_heap.svg)

   每个电站**至多入堆一次**（永不离线者初始入堆一次，其余在 `off_time` 位置入堆一次），堆只增不减，无需懒惰删除，均摊 $O(\log c)$。

6. **答案顺序**：逆序法收集到的答案是反的，最后 `reverse()` 一次。

## 5. 正确性证明

**引理 1（离线单调性）**：电站状态只从"在线"变为"离线"，且一旦离线永不恢复；每个电站真正改变状态的时刻唯一——其**第一个** `[2,x]` 查询处（若无 `[2,x]` 则永不离线）。

**证明**：查询只有两类，`[1,x]` 只读不写；`[2,x]` 只把状态置为离线，题目不存在任何恢复操作，故状态序列单调。对同一电站的多次 `[2,x]`，第一次之后状态已是离线，后续操作不改变任何状态。∎

**引理 2（在线集合不变量）**：正向算法中，任意时刻 $i$（处理完 `queries[0..i]` 后），对任意电网 root $r$，集合 $S[r]$ 恰等于该电网当前在线电站的全体。

**证明**：对 $i$ 归纳。$i = -1$（初始）：全部电站在线，$S[r]$ 装入了组内全部 id，成立。归纳步：设处理前不变量成立，第 $i$ 条查询只有 `[2,x]` 改变真实状态——若 $x$ 原本在线，真实状态变为离线，同时算法执行 `S[find(x)].erase(x)`，两边同步删除 $x$；若 $x$ 已离线（重复 `[2,x]`），由引理 1 真实状态不变，且由归纳假设 $x \notin S$，`erase` 为 no-op。`[1,x]` 不改变任何状态。故不变量对 $i$ 仍成立。∎

**定理 1（正向算法正确性）**：对每条 `[1,x]` 查询，算法输出符合题意。

**证明**：由引理 2，处理 `[1,x]` 时 $S[\mathrm{find}(x)]$ 即该电网的在线电站集合。分三种情形：(a) `!offline[x]`：$x$ 在线，题意规定由 $x$ 自身解决，算法输出 $x$；(b) $x$ 离线且 $S$ 非空：`std::set` 按 id 升序维护，`*begin()` 恰为编号最小的在线电站；(c) $x$ 离线且 $S$ 为空：由引理 2 该电网已无在线电站，输出 $-1$。∎

**引理 3（逆序不变量）**：逆序算法处理到位置 $i$（完成该位置的入堆动作后），电网 $r$ 的堆恰含集合 $\{y \in r : \mathrm{off\_time}[y] \ge i\}$，即"时刻 $i-1$ 仍在线"的电站全体。

**证明**：对 $i$ 从 $q-1$ 到 $0$ 逆向归纳。初始（即将处理 $i = q-1$）：堆含所有 $\mathrm{off\_time}[y] = \infty$ 的电站；而位置 $q-1$ 的入堆动作只会放入 $\mathrm{off\_time}[y] = q-1$ 的电站（若有，必为 `queries[q-1] = [2,y]` 且首次），两者并集恰为 $\{y : \mathrm{off\_time}[y] \ge q-1\}$。归纳步：从位置 $i+1$ 推进到 $i$，集合应增加 $\{y : \mathrm{off\_time}[y] = i\}$，算法恰在扫到 `[2,x]` 且 `off_time[x] == i` 时 push（首次判重保证每个 $y$ 只在此刻入堆一次）；堆中元素从不移出，且由归纳假设此前堆含所有 $\mathrm{off\_time}[y] \ge i+1$ 者。故不变量成立。∎

**定理 2（逆序算法正确性）**：逆序算法对每条 `[1,x]` 输出与正向算法一致。

**证明**：`[1,x]` 位于 $i$ 时看到的是执行 `queries[0..i-1]` 后的状态，$x$ 在线当且仅当 $\mathrm{off\_time}[x] \ge i$；因位置 $i$ 是类型 1 查询，$\mathrm{off\_time}[x] \ne i$，故等价于 $\mathrm{off\_time}[x] > i$，算法此时输出 $x$，与正向情形 (a) 一致。若 $x$ 离线，由引理 3，堆恰为该电网时刻 $i-1$ 的在线集合，堆顶即其最小元；堆空即全离线，输出 $-1$，与正向情形 (b)(c) 一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big((c+n)\alpha(c) + (c+q)\log c\big)$。
  - 并查集建组：$O((c+n)\alpha(c))$；
  - 初始建集合 / 初始 `heapify`：$c$ 次插入 $O(c \log c)$（Python 的 `heapify` 更是 $O(c)$）；
  - 每条 `[2,x]`：一次 `erase` / 至多一次 `heappush`，$O(\log c)$；由引理 1，删除与入堆总量均 $\le c$；
  - 每条 `[1,x]`：`offline[x]` 判定 $O(1)$，`*begin()` / 堆顶 $O(1)$。
  - 本题 $c, n \le 10^5$、$q \le 2\times10^5$，总操作约 $10^6$ 量级，轻松通过。
- **空间复杂度**：$O(c + n)$——并查集数组、每组的集合/堆（合计恰容纳 $c$ 个电站 id）与 `offline` / `off_time` 数组。

## 7. 参考代码

### C++（正向 + `std::set`）

```cpp
class Solution {
public:
    vector<int> processQueries(int c, vector<vector<int>>& connections, vector<vector<int>>& queries) {
        vector<int> parent(c + 1);
        iota(parent.begin(), parent.end(), 0);
        auto find = [&](int x) {
            while (parent[x] != x) x = parent[x] = parent[parent[x]];
            return x;
        };
        for (auto& e : connections) parent[find(e[0])] = find(e[1]);

        vector<set<int>> s(c + 1);
        for (int x = 1; x <= c; x++) s[find(x)].insert(x);

        vector<bool> offline(c + 1, false);
        vector<int> ans;
        for (auto& q : queries) {
            int x = q[1], r = find(x);
            if (q[0] == 2) {
                offline[x] = true;
                s[r].erase(x);
            } else if (!offline[x]) {
                ans.push_back(x);
            } else {
                ans.push_back(s[r].empty() ? -1 : *s[r].begin());
            }
        }
        return ans;
    }
};
```

### Python（逆序 + 小根堆，纯标准库）

```python
class Solution:
    def processQueries(self, c: int, connections: List[List[int]], queries: List[List[int]]) -> List[int]:
        parent = list(range(c + 1))

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        for u, v in connections:
            parent[find(u)] = find(v)

        INF = float('inf')
        off_time = [INF] * (c + 1)
        for i, (t, x) in enumerate(queries):
            if t == 2 and off_time[x] == INF:
                off_time[x] = i

        heaps = {}
        for x in range(1, c + 1):
            if off_time[x] == INF:
                heaps.setdefault(find(x), []).append(x)
        for h in heaps.values():
            heapq.heapify(h)

        ans = []
        for i in range(len(queries) - 1, -1, -1):
            t, x = queries[i]
            r = find(x)
            if t == 2:
                if off_time[x] == i:
                    heapq.heappush(heaps.setdefault(r, []), x)
            elif off_time[x] > i:
                ans.append(x)
            else:
                h = heaps.get(r)
                ans.append(h[0] if h else -1)
        ans.reverse()
        return ans
```

## 8. 边界情况与易错点

1. **最大陷阱：`x` 在线时答案是 `x` 本身**，不是集合最小元！示例 1 的 `[1,3]` 答案是 3 而非 1。漏判此规则会让"全部在线"的用例全军覆没（我在本地对拍时第一版逆序代码就栽在这里）。
2. **重复 `[2,x]`**：对已离线电站再执行离线。正向 `set::erase` 天然幂等；**逆序堆法必须用 `off_time[x] == i` 判重**，只认第一次 `[2,x]`——若每次都 push，$x$ 会在第二次 `[2,x]` 之前被错误地"提前复活"。
3. **`n = 0` 无连接**：每个电站独立成电网，`[2,x]` 之后同组无在线 → `-1`（示例 2）。
4. **整组全离线** → 输出 `-1`，别输出 0 或抛异常；注意答案数组只收集 `[1,x]` 查询，`[2,x]` 不占位。
5. **电站编号从 1 开始**：数组开 `c + 1`，下标 0 空置；孤立场站的 root 是它自己，`S[root] = {x}`。
6. **并查集递归爆栈**：$c = 10^5$ 深链时递归 `find` 可能栈溢出，用迭代 + 路径压缩（`parent[x] = parent[parent[x]]`）。
7. **性能误区**：Python 若用 `list` 存在线电站、每次 `[1,x]` 前 `min()` 或重排序，单次 $O(c)$、总 $O(qc) = 2\times10^{10}$ 必然 TLE；必须有序集合（`SortedList`）或逆序 + 堆。
8. **`off_time[x] > i` 的等号**：位置 $i$ 是 `[1,x]` 时 `off_time[x] == i` 不可能发生（同一下标不能既是类型 1 又是类型 2），故 `>` 与 `>=` 此处等价，但写 `>` 语义更明确。
