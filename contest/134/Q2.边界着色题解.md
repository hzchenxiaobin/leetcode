# LeetCode 边界着色 题解

## 1. 题目概述

- **标题 / 题号**：边界着色（#1034，medium）
- **链接**：https://leetcode.cn/problems/coloring-a-border/
- **来源**：LeetCode 第 134 场周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、数组、矩阵

**题意**：给定 $m \times n$ 的整数矩阵 `grid`（每个值代表该格的颜色）以及 $(row, col)$ 与 `color`。把与 `grid[row][col]` **同色且 4-连通**的格子组成一个**连通分量**，只把该分量的**边界格子**染成 `color`，其余格子保持原样，返回最终矩阵。

其中「边界格子」指分量中满足下列条件之一的格子：

1. 位于网格最外圈（第 0 行 / 第 0 列 / 第 $m-1$ 行 / 第 $n-1$ 列）；
2. 上、下、左、右某个相邻格子**不属于同一连通分量**（越界也算不属于）。

**约束**：

- $m = \text{grid.length}$，$n = \text{grid}[i].\text{length}$
- $1 \le m, n \le 50$
- $1 \le \text{grid}[i][j], \text{color} \le 1000$
- $0 \le row < m$，$0 \le col < n$

## 2. 示例

**示例 1**

```text
输入：grid = [[1,1],[1,2]], row = 0, col = 0, color = 3
输出：[[3,3],[3,2]]
解释：颜色 1 的分量是 (0,0),(0,1),(1,0)，三个格子都在最外圈 → 全部染成 3；
      (1,1) 颜色为 2，不属于该分量，保持 2。
```

**示例 2**

```text
输入：grid = [[1,2,2],[2,3,2]], row = 0, col = 1, color = 3
输出：[[1,3,3],[2,3,3]]
解释：颜色 2 在这个分量里的格子是 (0,1),(0,2),(1,2)；
      (1,0) 虽然也是 2，但被 1 和 3 隔开，属于另一个分量，保持 2。
```

**示例 3**

```text
输入：grid = [[1,1,1],[1,1,1],[1,1,1]], row = 1, col = 1, color = 2
输出：[[2,2,2],[2,1,2],[2,2,2]]
解释：整个网格是一个分量，外圈 8 个格子是边界 → 染色；(1,1) 四邻全在分量内 → 保持 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的办法：对每个格子单独做一次 BFS，判断它是否与 $(row, col)$ 连通，再判它是不是边界。这样做要跑 $mn$ 次泛洪，复杂度 $O(m^2n^2) = 6.25 \times 10^6$，数据范围很小，也能过。但完全没有必要——一次泛洪就能把整个分量收集下来。

### 3.2 核心观察：一次泛洪收集分量，再判边界

![连通分量与边界格子](images/wc134_q2_component.svg)

要点只有三条：

- **分量靠颜色 + 4-邻接**：只从同色邻居扩散，且只看上下左右（对角相邻不算连通）。
- **边界 = 贴边或贴着异色**：判据是「在网格最外圈」或「某个 4-邻格颜色 $\ne$ 原色」。注意这里用**原色** `old` 判断，而不是「邻格是否在分量里」——两者等价，因为分量内所有格子的颜色都等于 `old`。
- **必须两阶段**：先把所有边界格子判完、存起来，最后统一涂色。如果边判边涂，已经涂成 `color` 的邻居会让后面的格子误以为「邻格异色」，从而把本该保留的内部格也染掉。这是一个非常隐蔽的坑。

### 3.3 算法流程

![算法流程：收集 → 判边界 → 统一染色](images/wc134_q2_border_flow.svg)

```text
1. old = grid[row][col]；visited 全 false，显式栈压入 (row, col)
2. 泛洪：弹出 (x, y) 记入 comp；对 4 个邻居 (nx, ny)：
       越界 → 跳过；已访问 → 跳过；grid[nx][ny] != old → 跳过
       否则标记已访问并压栈
3. 对 comp 中每个 (x, y) 判边界：
       在网格最外圈 → 边界
       否则逐个看 4 个邻居，若有 grid[nx][ny] != old → 边界
       是边界则加入 border_cells
4. 遍历 border_cells，执行 grid[x][y] = color
5. 返回 grid
```

### 3.4 示例演算

![示例 2 的分量划分](images/wc134_q2_example_walkthrough.svg)

以示例 2 的 `grid = [[1,2,2],[2,3,2]]`、$(row, col) = (0,1)$、`color = 3` 为例：

| 格子 | 颜色 | 与 (0,1) 连通？ | 边界理由 | 结果 |
|------|------|----------------|----------|------|
| (0,1) | 2 | 起点 | 第 0 行 | 染 3 |
| (0,2) | 2 | 连通 | 第 0 行 / 末列 | 染 3 |
| (1,2) | 2 | 连通 | 末列 | 染 3 |
| (1,0) | 2 | **不连通**（邻格为 1、3） | — | 保持 2 |
| (1,1) | 3 | 不连通 | — | 保持 3 |

最终得到 `[[1,3,3],[2,3,3]]`，与示例输出一致。

## 4. 算法细节

1. **显式栈而非递归**：$m, n \le 50$ 时递归深度最多 2500 层，多数语言可以接受，但显式栈更稳妥，也避免某些环境下的栈溢出。
2. **`old` 只在入口取一次**：泛洪、判边界都基于 `old`，不要在染色后重新读 `grid[row][col]`。
3. **越界即异色**：判边界时，若邻居越界，按题意「不属于同一连通分量」处理——但因为最外圈格子已经先被判为边界，越界分支实际上永远不会走到（可以先判圈，再判四邻，代码更短）。
4. **两阶段存储**：`border_cells`（或 `comp` 加标记数组）长度不超过 $mn$，代价可忽略。
5. **颜色恰好相同的退化情形**：当 `color == old` 时，染色不改变任何东西，两阶段写法自然正确；若在泛洪过程中改色则会死循环或误判，这也是必须两阶段的另一个理由。

## 5. 正确性证明

**引理 1（泛洪得到的正是连通分量）**：算法得到的 `comp` 恰为「与 $(row, col)$ 同色且 4-连通」的格子集合。

**证明**：记该集合为 $C$。

- $comp \subseteq C$：泛洪只从 $(row,col)$ 出发，每次只在「界内、同色、未访问」的 4-邻格上扩散，故任何进入 `comp` 的格子都能通过一条同色 4-邻接路径回到起点，即属于 $C$。
- $C \subseteq comp$：对 $C$ 中格子按到起点的最短同色路径长度归纳。长度 0 即起点，已入 `comp`；若 $u \in C$ 的最短路径长 $d$，其前驱 $v$ 路径长 $d-1$，由归纳假设 $v$ 会被入栈，而 $u$ 与 $v$ 同色、在界内且未访问（$u$ 尚未入栈时），故 $u$ 必被压栈。∎

**引理 2（边界判定与定义等价）**：对 `comp` 中格子 $(x,y)$，算法判其为边界 $\iff$ 它满足题面两条判据之一。

**证明**：算法第一个条件「在网格最外圈」与题面判据 2 完全相同。第二个条件在非最外圈时执行，此时四个邻居都在界内，算法检查是否存在 $grid[nx][ny] \ne old$ 的邻居；由引理 1，$grid[nx][ny] = old$ 等价于该邻居属于同一分量，故该条件等价于题面判据 1。∎

**定理**：算法返回的矩阵等于「把（含 $(row,col)$ 的连通分量的）全部边界格子染成 `color`」后的矩阵。

**证明**：由引理 1、2，`border_cells` 恰为需要染色的格子集合；第 4 步只对这些格子写入 `color`，其余格子从不被写（因为染色在全部判定之后统一进行，判定阶段读到的始终是原始颜色）。故结果与定义一致。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个格子至多入栈一次，出栈时做 4 次常数检查；判边界阶段对 `comp` 中每个格子再做 4 次常数检查。
- **空间**：$O(mn)$。`visited` 为 $mn$ 个布尔值，栈与 `comp` / `border_cells` 最坏各存 $mn$ 个坐标；递归写法还会额外引入 $O(mn)$ 的调用栈。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> colorBorder(vector<vector<int>>& grid, int row, int col, int color) {
        int m = grid.size(), n = grid[0].size();
        int old = grid[row][col];
        const int dx[4] = {1, -1, 0, 0};
        const int dy[4] = {0, 0, 1, -1};
        vector<vector<bool>> seen(m, vector<bool>(n, false));
        vector<pair<int, int>> comp, stack;
        seen[row][col] = true;
        stack.push_back({row, col});
        while (!stack.empty()) {
            auto [x, y] = stack.back();
            stack.pop_back();
            comp.push_back({x, y});
            for (int d = 0; d < 4; d++) {
                int nx = x + dx[d], ny = y + dy[d];
                if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                if (seen[nx][ny] || grid[nx][ny] != old) continue;
                seen[nx][ny] = true;
                stack.push_back({nx, ny});
            }
        }
        vector<pair<int, int>> borderCells;
        for (auto& p : comp) {
            int x = p.first, y = p.second;
            bool border = (x == 0 || y == 0 || x == m - 1 || y == n - 1);
            if (!border) {
                for (int d = 0; d < 4; d++) {
                    if (grid[x + dx[d]][y + dy[d]] != old) { border = true; break; }
                }
            }
            if (border) borderCells.push_back(p);
        }
        for (auto& p : borderCells) grid[p.first][p.second] = color;
        return grid;
    }
};
```

### Python

```python
class Solution:
    def colorBorder(self, grid: list[list[int]], row: int, col: int, color: int) -> list[list[int]]:
        m, n = len(grid), len(grid[0])
        old = grid[row][col]
        dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))
        seen = [[False] * n for _ in range(m)]
        seen[row][col] = True
        stack = [(row, col)]
        comp = []
        while stack:
            x, y = stack.pop()
            comp.append((x, y))
            for dx, dy in dirs:
                nx, ny = x + dx, y + dy
                if 0 <= nx < m and 0 <= ny < n and not seen[nx][ny] and grid[nx][ny] == old:
                    seen[nx][ny] = True
                    stack.append((nx, ny))
        border_cells = []
        for x, y in comp:
            border = x == 0 or y == 0 or x == m - 1 or y == n - 1
            if not border:
                for dx, dy in dirs:
                    if grid[x + dx][y + dy] != old:
                        border = True
                        break
            if border:
                border_cells.append((x, y))
        for x, y in border_cells:
            grid[x][y] = color
        return grid
```

## 8. 边界情况与易错点

1. **边判边染（高频错误）**：染色必须等全部判定结束。否则被染过的邻居会以「异色」身份污染其他格子的判定，把分量内部格也染上色。例如 `grid = [[3,1,1],[1,1,1],[2,1,2]]`、$(1,0)$、`color = 2`——(1,1) 本应保持 1，若边判边染就会被误染成 2。
2. **同色但不连通**：示例 2 的 (1,0) 与分量同为颜色 2，却被 1 和 3 隔开，属于另一分量，不能染色。
3. **`color` 与原色相同**：两阶段写法天然正确；若在泛洪中改色，可能出现「改完再判断」的自指错误。
4. **对角不算连通**：只检查上下左右四个方向，题目明确是 4-邻接。
5. **单行 / 单列**：$m = 1$ 或 $n = 1$ 时所有格子都在最外圈，全部染成 `color`——代码里「行号是 0 或 $m-1$」的条件会自动覆盖。
6. **1×1 网格**：起点既是首行又是末列，直接染色，返回单元素矩阵。
