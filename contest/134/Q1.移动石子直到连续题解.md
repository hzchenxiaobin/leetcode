# LeetCode 移动石子直到连续 题解

## 1. 题目概述

- **标题 / 题号**：移动石子直到连续（#1033，medium）
- **链接**：https://leetcode.cn/problems/moving-stones-until-consecutive/
- **来源**：LeetCode 第 134 场周赛 Q1
- **难度**：中等
- **标签**：脑筋急转弯、数学

**题意**：数轴上放着三颗石子，位置分别为 $a, b, c$（互不相同）。每一回合，你可以拿起**位置最小或最大**的那颗石子，把它放到另外两颗石子**之间**的任意空位（整数位置 $k$ 满足 $x < k < z$ 且 $k \ne y$）。当三颗石子占据**连续**的三个整数位置时游戏结束。求结束游戏所需的**最少**与**最多**移动次数，返回长度为 2 的数组。

**约束**：

- $1 \le a, b, c \le 100$
- $a \ne b$，$b \ne c$，$c \ne a$（三颗石子位置两两不同）

**关键概念**：把三颗石子排序成 $x < y < z$，则**空隙**（相邻两颗石子之间未被占据的整数位置个数）为 $g_1 = y - x - 1$ 与 $g_2 = z - y - 1$。全部答案只由这两个空隙决定。

## 2. 示例

**示例 1**

```text
输入：a = 1, b = 2, c = 5
输出：[1, 2]
解释：最少 1 步——把 5 直接挪到 3，得到 1,2,3；
      最多 2 步——先把 5 挪到 4，再把 4 挪到 3。
```

**示例 2**

```text
输入：a = 4, b = 3, c = 2
输出：[0, 0]
解释：排序后为 2,3,4，已经连续，一步都动不了。
```

**示例 3**

```text
输入：a = 3, b = 5, c = 1
输出：[1, 2]
解释：排序后为 1,3,5，两个空隙都是 1（即各差 2）：
      把 1 挪到 4 得 3,4,5，1 步结束；最多则是逐步挪、共 2 步。
```

## 3. 解题思路

### 3.1 暴力思路

把三颗石子的位置看成状态，直接 BFS 求最短步数、记忆化搜索求最长步数。状态数不大（位置 $\le 100$ 时最多约 $10^6$ 个有序三元组），可以过题，但完全没有利用「只有两个空隙」这个结构。真正的解法是常数时间的分类讨论。

### 3.2 核心观察：答案只由两个空隙决定

![两个空隙决定最小步数与最大步数](images/wc134_q1_gaps.svg)

排序后记 $x < y < z$，则：

- **最大步数**：每次移动都会把一颗端点石子塞进内部空位，内部空位总数 $h = (z - x + 1) - 3 = z - x - 2$。每移动一次，跨度 $z - x$ **严格变小**，而内部空位数**至少减 1**；只要还有内部空位，总能把某一端的端点石子挪到紧贴 $y$ 的空位上，使内部空位恰好减少 1。因此游戏能持续恰好 $h$ 步，即 $\text{max} = z - x - 2$。
- **最小步数**：一步就能结束，当且仅当**没被移动的那两颗石子间距不超过 2**——因为一步只改动一个端点，剩下两颗的相对位置不变，最终三颗连续要求它们之间最多隔一个空位。于是
  - 已经连续（两个空隙都为 0）→ $0$；
  - 存在一侧空隙 $\le 1$（即间距 $\le 2$）→ 只需把另一侧的端点石子在紧邻处补上 → $1$；
  - 两侧间距都 $\ge 3$ → 一步无解，但两步一定够：先让一侧变成间距 2，再补中间 → $2$。

### 3.3 算法流程

![算法流程：排序 + 三档判定](images/wc134_q1_algorithm_flow.svg)

```text
1. 把 a, b, c 排序为 x < y < z
2. 若 y - x == 1 且 z - y == 1:      min_moves = 0
   否则若 min(y - x, z - y) <= 2:   min_moves = 1
   否则:                            min_moves = 2
3. max_moves = z - x - 2
4. 返回 [min_moves, max_moves]
```

### 3.4 示例演算

![示例 1 的两种打法](images/wc134_q1_moves.svg)

以示例 1（$1, 2, 5$）为例：

| 目标 | 操作序列 | 步数 |
|------|----------|------|
| 最少 | $5 \to 3$，得到 $\{1,2,3\}$ | 1 |
| 最多 | $5 \to 4$，得到 $\{1,2,4\}$；$4 \to 3$，得到 $\{1,2,3\}$ | 2 |

公式核对：$g_1 = 1$、$g_2 = 3$，$\min(y-x, z-y) = \min(1,3) = 1 \le 2$ → $\text{min} = 1$；$\text{max} = z - x - 2 = 5 - 1 - 2 = 2$。与答案 $[1,2]$ 一致。

## 4. 算法细节

1. **先排序**：题目给的三颗石子是乱序的（示例 2 就是 $4,3,2$ 的降序），必须先 `sort` 再讨论。
2. **判定顺序不能换**：必须先判「两个空隙都是 0」（连续，0 步），再判「某一侧间距 $\le 2$」。否则示例 2 会被错误地判成 1 步。
3. **间距 vs 空隙**：代码里直接比较间距 `y - x`、`z - y`，等价于比较空隙 $g_1 + 1$、$g_2 + 1$；用间距可以省掉一次减法，但阈值是 2 而不是 1。
4. **最大步数不用模拟**：$\text{max} = z - x - 2$ 就是内部空位总数，不需要真的去走；$z - x \le 99$，结果远在 `int` 范围内。
5. **不会出现负值**：三颗石子互不相同且有序，故 $z - x \ge 2$，$\text{max} \ge 0$。

## 5. 正确性证明

**引理 1（跨度严格递减）**：设当前有序位置为 $x < y < z$，任取一次合法移动，移动后的跨度严格小于 $z - x$。

**证明**：合法移动只能拿起 $x$ 或 $z$。设拿起 $x$ 放到 $k$，由题设 $x < k < z$ 且 $k \ne y$。新集合为 $\{k, y, z\}$，其最小值为 $\min(k, y)$。若 $k < y$，则新最小值 $k > x$；若 $k > y$，则新最小值 $y > x$。两种情形下新最小值都严格大于 $x$，而最大值不超过 $z$，故新跨度 $< z - x$。拿起 $z$ 的情形对称。∎

**引理 2（最大步数）**：从有序位置 $x < y < z$ 出发，最多恰好能走 $z - x - 2$ 步。

**证明**：记内部空位数 $h = (z - x + 1) - 3 = z - x - 2$。由引理 1，跨度严格递减，故步数有限；又每次移动只能把端点的石子放进原来位于 $(x,z)$ 内的空位，因此每步至多消耗一个内部空位，故步数不超过 $h$——上界成立。

再证可达性：只要 $h \ge 1$，就存在内部空位。若 $y - 1 > x$，则 $y - 1$ 是空位，把 $x$ 挪到 $y - 1$，此步恰好填掉一个内部空位，$h$ 减 1；否则 $y - 1 = x$，此时 $x, y$ 相邻，若 $h \ge 1$ 则必有 $z - 1 > y$，把 $z$ 挪到 $y + 1$，同样使 $h$ 减 1。每步都严格消耗一个内部空位，$h$ 从初值降到 0 时三颗石子恰好连续。故恰好可以走 $h$ 步，上界可达。∎

**引理 3（最小步数）**：$\text{min} = 0$ 当且仅当已连续；否则 $\text{min} = 1$ 当且仅当 $\min(y - x,\, z - y) \le 2$；其余情形 $\text{min} = 2$。

**证明**：

- 已连续时无法移动（端点石子放到 $(x,z)$ 内的空位不存在），故为 0。
- 一步移动只改动一个端点，未被移动的两颗石子间距保持不变。最终三颗连续 $\Rightarrow$ 任意两颗间距 $\le 2$，因此必有 $\min(y-x, z-y) \le 2$，这证明了「$\min \ge 2$ 当 $\min(y-x,z-y) \ge 3$」这一侧。
- 反之若 $y - x \le 2$：$y - x = 1$ 时把 $z$ 挪到 $y + 1$（$y+1 < z$，因未连续）、$y - x = 2$ 时把 $x$ 挪到 $x + 1 = y - 1$，均一步连续；$z - y \le 2$ 对称。故 $\text{min} \le 1$。
- 两侧都 $\ge 3$ 时 $\text{min} \ge 2$；而两步方案存在：先把 $z$ 挪到 $y + 1$（合法，因 $y < y+1 < z$），此时 $x, y, y+1$ 满足 $y - x \ge 3$，再把 $x$ 挪到 $y - 1$ 即得连续的 $y-1, y, y+1$。故 $\text{min} = 2$。∎

**定理**：算法返回的 `[min_moves, max_moves]` 恰为游戏结束所需的最小与最大移动次数。

**证明**：由引理 2 得最大值为 $z - x - 2$，由引理 3 得最小值的三档判定，二者与算法的两次赋值逐条对应。∎

## 6. 复杂度分析

- **时间**：$O(1)$。排序 3 个数（比较次数为常数）加常数次算术运算。
- **空间**：$O(1)$。只用三个临时变量。即使换成 BFS 暴力，状态数也是 $O(V^3)$（$V \le 100$），本题的意义正在于用结构换掉搜索。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> numMovesStones(int a, int b, int c) {
        int p[3] = {a, b, c};
        sort(p, p + 3);
        int x = p[0], y = p[1], z = p[2];
        int minMoves;
        if (y - x == 1 && z - y == 1) minMoves = 0;          // 已经连续
        else if (min(y - x, z - y) <= 2) minMoves = 1;        // 一个空隙 <= 2
        else minMoves = 2;                                   // 两个空隙都 >= 3
        int maxMoves = z - x - 2;                            // 内部空位数
        return {minMoves, maxMoves};
    }
};
```

### Python

```python
class Solution:
    def numMovesStones(self, a: int, b: int, c: int) -> list[int]:
        x, y, z = sorted((a, b, c))
        if y - x == 1 and z - y == 1:
            min_moves = 0
        elif min(y - x, z - y) <= 2:
            min_moves = 1
        else:
            min_moves = 2
        return [min_moves, z - x - 2]
```

## 8. 边界情况与易错点

1. **输入乱序**：`a, b, c` 并不保证递增（示例 2 是 $4,3,2$），不排序直接算会得到负的最大步数。
2. **「连续」必须先判**：间距全为 1 时 $\min(y-x, z-y) \le 2$ 也成立，若把 0 步的分支写在后面就会错判成 1 步。
3. **阈值是 2 不是 1**：判据用的是**间距** `y - x`，一个空位对应间距 2，所以是 `<= 2`；若换成空隙 $g = y - x - 1$，阈值才变成 `<= 1`。
4. **最大步数不是空位总数**：只有 $x$ 与 $z$ **之间**的空位算数，网格外（$x$ 左边、$z$ 右边）的位置与答案无关。
5. **单步移动的合法性**：本题要求 $x < k < z$（不能越过另一端），这与同系列 1040 题「移动后不能成为端点」的规则不同，两题的公式不能混用。
