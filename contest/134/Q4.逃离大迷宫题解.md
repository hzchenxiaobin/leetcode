# LeetCode 逃离大迷宫 题解

## 1. 题目概述

- **标题 / 题号**：逃离大迷宫（#1036，hard）
- **链接**：https://leetcode.cn/problems/escape-a-large-maze/
- **来源**：LeetCode 第 134 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、广度优先搜索、数组、哈希表、双向搜索

**题意**：有一个 $10^6 \times 10^6$ 的网格，格子坐标为 $(x, y)$。`blocked` 给出若干**封锁格子**（不可通行），其余格子自由通行，每次可向上下左右移动一格，不能走出网格。给定起点 `source` 与终点 `target`，判断是否存在一条通路。保证 `source`、`target` 都不在 `blocked` 中且二者不同。

**约束**：

- $0 \le \text{blocked.length} \le 200$
- $\text{blocked}[i].\text{length} = 2$，$0 \le x_i, y_i < 10^6$
- `source.length == target.length == 2`，$0 \le s_x, s_y, t_x, t_y < 10^6$
- `source != target`，且二者不在封锁列表内

**关键矛盾**：网格有 $10^{12}$ 个格子，不可能整图搜索；但封锁格子**至多 200 个**——能被「围住」的格子数是封锁格子数的平方级上界。抓住这一点，搜索规模就与网格尺寸无关了。

## 2. 示例

**示例 1**

```text
输入：blocked = [[0,1],[1,0]], source = [0,0], target = [0,2]
输出：false
解释：起点在左下角，向上、向左都出界，向下 (1,0)、向右 (0,1) 都被封锁，一步都走不了。
```

**示例 2**

```text
输入：blocked = [], source = [0,0], target = [999999,999999]
输出：true
解释：没有任何封锁格子，整个网格连通，任意两点可达。
```

**示例 3（补充，验证包围圈）**

```text
输入：blocked = 以 (1000,1000) 为左上角、边长为 6 的正方形环（共 20 格），
      source = [1003,1003]（环内），target = [999999, 0]（环外）
输出：false
解释：source 被环完全封住，可达格子只有环内的 4×4 = 16 个，远小于上界 190。
```

## 3. 解题思路

### 3.1 暴力思路

直接 BFS/DFS 搜整个网格：状态数 $10^{12}$，无论时间还是空间都不可能。即便只搜到目标附近，最坏（目标在角落而起点在对角）也要访问 $10^{12}$ 个格子。必须换思路——**答案只可能因为"被封锁格子围住"而变成 `false`**。

### 3.2 核心观察：包围圈有面积上界

![m 个封锁格子的围栏上界](images/wc134_q4_enclosure.svg)

- 若起点被封锁格子围在一个**有限区域** $S$ 中，则 $S$ 的所有边界都必须由封锁格子占住（否则可越界逃出）。
- 用 $m$ 个封锁格子围出的 4-连通区域，其面积（格子数）**最多为** $\dfrac{m(m-1)}{2}$。直观上最"划算"的围法是把封锁格子排成一条**斜线**，它围出一个三角区域，面积正好是 $1 + 2 + \cdots + (m-1) = \frac{m(m-1)}{2}$；任何其他摆法（更"胖"的外壳）都需要更多封锁格子才能围住同样多的格子，故这是上界（见引理 1）。
- $m \le 200$ 时上界为 $19900$。于是**从起点做 BFS，一旦访问格子数超过 $19900$ 还没碰到终点，就说明起点根本没被围住**，可以立即判定"能逃出去"，无需继续搜索。

同理要对 `target` 做一次对称的判定：**若终点被围住，则也是 `false`**。

### 3.3 算法流程

![有限步 BFS 流程](images/wc134_q4_bounded_bfs.svg)

```text
1. 把 blocked 编码成整数放进哈希集合；limit = m(m-1)/2
2. escape(start, goal) 返回布尔值：
     seen = {start}，栈 = [start]
     循环直到栈空：
         取 (x, y)
         若 (x, y) == goal            → true   （直接连通）
         若 |seen| > limit            → true   （未被围住）
         对 4 个邻格 (nx, ny)：
             出界 / 是封锁格子 / 已访问 → 跳过
             否则标记并压栈
     栈空                             → false  （被围住）
3. 返回 escape(source, target) && escape(target, source)
```

### 3.4 示例演算

![示例 1 的角落困局](images/wc134_q4_example_walkthrough.svg)

示例 1 中 $m = 2$，$\text{limit} = 2 \times 1 / 2 = 1$。从 $(0,0)$ 出发：

| 步骤 | 栈 | seen | 判定 |
|------|-----|------|------|
| 弹出 $(0,0)$ | 空 | 1 个 | 不是终点；$1 > 1$ 不成立 |
| 四个邻居 | — | — | 上/左出界，下 $(1,0)$、右 $(0,1)$ 是墙 |
| 栈空 | 空 | 1 个 | 返回 `false`（被围住） |

第一次 `escape` 就返回 `false`，整体答案 `false`。而示例 2 中 $m = 0$、$\text{limit} = 0$，弹出起点后 $\lvert seen \rvert = 1 > 0$ 立即成立 → `true`，两侧 `true` → 整体 `true`。

## 4. 算法细节

1. **坐标编码**：$x, y < 10^6$，用 `x * 1000000 + y` 编码成 `long long`（或 `int64`）放进哈希集合；不要用 `pair` 作键（C++ 需自定义哈希，Python 用元组即可）。
2. **上界公式**：`limit = m * (m - 1) / 2`，注意用 64 位中间量（$m \le 200$ 时不会溢出，但改成 `long long` 更保险）；$m = 0, 1$ 时 `limit = 0`，算法自动退化为「弹出起点即判定未围住」。
3. **判定顺序**：先判「是否到达终点」，再判「是否超过 limit」。否则当起点与终点相邻且 `limit = 0` 时可能漏掉直接连通的情形。
4. **两侧都要跑**：只跑起点会漏掉「起点自由、终点被围」的情形（例如目标被封锁格子围在角落）。跑两次是标准做法，代价翻倍仍然很小。
5. **越界处理**：坐标必须在 $[0, 10^6)$ 内，`nx < 0 || nx >= N` 直接跳过——注意是「不能走出网格」而不是「走出去就算逃出」。
6. **用栈还是队列**：都可，本题只关心可达集合的范围；用显式栈可少一层调用开销。

## 5. 正确性证明

**引理 1（围栏面积上界）**：若 $m$ 个封锁格子把某个 4-连通区域 $S$ 与网格边界完全隔开（即 $S$ 的每个与外界相邻的位置都被封锁格子占据），则 $\lvert S \rvert \le \dfrac{m(m-1)}{2}$。

**证明要点**：把封锁格子看作单位方格。$S$ 的边界必须由封锁格子的边拼成一条闭合折线（4-连通意义下不允许斜着穿过两个对角封锁格子的缝隙，因为那需要一次斜向移动）。对这条闭合折线做**逐行压缩**：把每一行的封锁格子向左对齐、把整体轮廓压成单调的阶梯形，此时 $\lvert S \rvert$ 不减而封锁格子数不变，最终形态就是一条长 $m$ 的斜线所围出的三角形，逐行格子数为 $0, 1, 2, \ldots, m-1$，合计 $\frac{m(m-1)}{2}$（$m$ 个封锁格子围出该三角时，边界恰由这 $m$ 个格子构成，等号可达）。故 $\lvert S \rvert \le \frac{m(m-1)}{2}$。∎

**引理 2（越界即未围住）**：若从 $s$ 出发的可达集合 $R$ 满足 $\lvert R \rvert > \frac{m(m-1)}{2}$，则 $s$ 没有被封锁格子围住，即 $R$ 能延伸到网格边界。

**证明**：反设 $s$ 被围住。由引理 1，$s$ 所在的被围区域 $S$ 满足 $\lvert S \rvert \le \frac{m(m-1)}{2}$，而 $R \subseteq S$（$R$ 中任何格子都能从 $s$ 走到，且走不出 $S$），故 $\lvert R \rvert \le \lvert S \rvert \le \frac{m(m-1)}{2}$，与 $\lvert R \rvert > \frac{m(m-1)}{2}$ 矛盾。∎

**引理 3（两侧都未被围住则连通）**：若 $s$ 与 $t$ 都没有被封锁格子围住，则 $s$ 与 $t$ 连通。

**证明**：考虑把封锁格子加上「对角线接触」的 8-连通闭包。若 $s$ 与 $t$ 不连通，则存在一条由封锁格子构成的**分割链**把平面切成两半，该链要么连接网格的两条边界，要么自身闭合。连接两条边界需要至少 $10^6$ 个格子（网格边长 $10^6$），闭合链则把某一侧围成有限区域——后者意味着 $s$ 或 $t$ 被围住，与假设矛盾；前者在 $m \le 200 \ll 10^6$ 时不可能。故 $s$ 与 $t$ 必连通。∎

**定理**：算法返回 `true` 当且仅当存在从 `source` 到 `target` 的通路。

**证明**：

- 若 `escape(source, target)` 因「到达终点」返回 `true`，通路存在；若它因「超过 limit」返回 `true`，由引理 2 起点未被围住，同理第二次调用说明终点也未被围住，由引理 3 二者连通。
- 反之若存在通路且算法返回 `false`，则必有某次调用以「栈空」结束，即该侧的可达集合被封锁格子完全包住（搜索穷尽了整个连通分量），这与存在通路矛盾（通路上的第一个格子就在该集合中、且最终应到达另一侧）。故返回 `false` 时确实不存在通路。∎

## 6. 复杂度分析

- **时间**：$O(m^2)$。每次 BFS 至多访问 $\text{limit} + 1 = \frac{m(m-1)}{2} + 1$ 个格子，每个格子做 4 次常数检查；两次 BFS 合计仍是 $O(m^2)$。$m \le 200$ 时约 $4 \times 10^4$ 次操作，与 $10^{12}$ 的网格规模无关。
- **空间**：$O(m^2)$ 用于 `seen`（最坏约 $2 \times 10^4$ 个编码）+ $O(m)$ 用于封锁集合。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
#include <algorithm>
using namespace std;

class Solution {
public:
    static constexpr int N = 1000000;
    unordered_set<long long> blockedSet;
    long long limit;

    long long enc(int x, int y) { return (long long)x * N + y; }

    bool oneWay(int sx, int sy, int tx, int ty) {
        unordered_set<long long> seen;
        vector<pair<int, int>> stack;
        seen.insert(enc(sx, sy));
        stack.push_back({sx, sy});
        while (!stack.empty()) {
            auto [x, y] = stack.back();
            stack.pop_back();
            if (x == tx && y == ty) return true;                 // 直接连通
            if ((long long)seen.size() > limit) return true;      // 未被围住
            const int dx[4] = {1, -1, 0, 0};
            const int dy[4] = {0, 0, 1, -1};
            for (int d = 0; d < 4; d++) {
                int nx = x + dx[d], ny = y + dy[d];
                if (nx < 0 || nx >= N || ny < 0 || ny >= N) continue;
                long long key = enc(nx, ny);
                if (seen.count(key) || blockedSet.count(key)) continue;
                seen.insert(key);
                stack.push_back({nx, ny});
            }
        }
        return false;                                            // 被围住
    }

    bool isEscapePossible(vector<vector<int>>& blocked, vector<int>& source, vector<int>& target) {
        blockedSet.clear();
        for (auto& b : blocked) blockedSet.insert(enc(b[0], b[1]));
        limit = (long long)blocked.size() * ((long long)blocked.size() - 1) / 2;
        return oneWay(source[0], source[1], target[0], target[1]) &&
               oneWay(target[0], target[1], source[0], source[1]);
    }
};
```

### Python

```python
class Solution:
    def isEscapePossible(self, blocked: list[list[int]], source: list[int], target: list[int]) -> bool:
        N = 10 ** 6
        blocked_set = {(x, y) for x, y in blocked}
        limit = len(blocked) * (len(blocked) - 1) // 2

        def escaped(start, goal):
            if tuple(start) in blocked_set or tuple(goal) in blocked_set:
                return False
            seen = {tuple(start)}
            stack = [tuple(start)]
            while stack:
                x, y = stack.pop()
                if [x, y] == goal:
                    return True
                if len(seen) > limit:
                    return True
                for nx, ny in ((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)):
                    if 0 <= nx < N and 0 <= ny < N and (nx, ny) not in seen and (nx, ny) not in blocked_set:
                        seen.add((nx, ny))
                        stack.append((nx, ny))
            return False

        return escaped(source, target) and escaped(target, source)
```

## 8. 边界情况与易错点

1. **只跑一侧**：漏掉「终点被围」的情形。反例：终点在角落，被 (1,0)、(0,1) 两块封锁格子卡死，而起点在开阔地带。
2. **上界写成 $m^2$**：仍然正确（$m^2 \ge \frac{m(m-1)}{2}$，判定更保守但仍在上界内），只要不超过 $200^2 = 40000$ 都不会超时；但**写成 $mn$ 或 $10^{12}$** 就等于没优化。
3. **`limit = 0` 的边界**：$m = 0$ 或 $m = 1$ 时 `limit` 为 0，「超过 limit」在弹出起点后立即成立，正好得到正确答案 `true`——不要为它写特判，但要保证判定在「是否到达终点」之后。
4. **访问计数位置**：应在**弹出时**判 `|seen| > limit`（或入栈后立即判），放在循环外会漏判；放在「出队前」也可以，但要保证起点本身被计入。
5. **坐标编码溢出**：$x \times 10^6 + y$ 最大约 $10^{12}$，必须用 `long long`；用 `int` 会溢出成负数导致哈希错误。
6. **48 位随机化哈希的坑（C++）**：若用 `unordered_set<long long>`，某些评测机胡须上会被构造数据卡；本题 $m \le 200$、规模极小，无需担心，但工程上可加自定义哈希。
7. **对角不算连通**：只允许 4 方向移动，两个对角相邻的封锁格子**能**封死通道（示例 3 的环被拆掉两个格子才真正开了口子）。
