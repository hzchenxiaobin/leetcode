# LeetCode 二进制字符串前缀一致的次数 题解

## 1. 题目概述

- **标题 / 题号**：二进制字符串前缀一致的次数（#1375，medium）
- **链接**：https://leetcode.cn/problems/number-of-times-binary-string-is-prefix-aligned/
- **来源**：LeetCode 第 179 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀最大值、脑筋急转弯

**题意**：长度为 $n$、下标从 1 开始的二进制串初始**全为 0**。第 $i$ 步把下标为 `flips[i]` 的位翻转（$0 \to 1$）。若第 $i$ 步之后**闭区间 $[1, i]$ 内所有位都是 1**、其余位都是 0，则称此刻「**前缀一致**」。返回整个翻转过程中前缀一致的**次数**。

**约束**：

- $n = \mathrm{flips.length}$，$1 \le n \le 5 \times 10^4$
- `flips` 是 $[1, n]$ 内所有整数构成的**一个排列**（每步翻的位置两两不同）

> 💡 赛中读题 30 秒应抓到两个点：一是本题的孪生题面即「灯泡开关 III」，亮灯恰好构成前缀就「变蓝」，本质是同一道题；二是**「排列」这一约束是题眼**——前 $i$ 步翻动的 $i$ 个位置互不相同，「前缀一致」于是等价于一个极简判据「前缀最大值 $=$ 步数」，一趟遍历、两个标量变量即可满分。

## 3. 解题思路

### 3.1 暴力思路：每步重建字符串再校验

按题面直接模拟：维护长度 $n$ 的字符数组，每步翻转一位，然后检查「$[1,i]$ 全 1 且其余全 0」。单次校验要扫 $O(n)$ 个位置，共 $n$ 步，总计

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2} = O(n^2)
$$

$n = 5 \times 10^4$ 时约 $1.25 \times 10^9$ 次字符访问，赛场上 C++ 勉强、Python 必挂。更深层的问题是**信息利用率为零**：第 $i$ 步与第 $i-1$ 步的状态只差一位，逐位重扫把 $99\%$ 的旧结果全部丢掉。用有序集合维护「已亮位置集合」可压到 $O(n \log n)$，仍是把简单问题做重——本题的最优解连集合都不必存，**只需要一个数字**。

> ⚠️ 暴力的教训：题目白送了「`flips` 是排列」这个结构化约束，逐位校验却完全没用到它。看到排列 + 前缀类提问，第一反应应是「前 $i$ 步翻动的 $i$ 个**互不相同**的位置，什么时候恰好凑成 $\{1,\dots,i\}$」。

### 3.2 核心观察：前缀一致 ⟺ 前缀最大值追上步数

![核心观察：第 i 步后前缀一致 ⟺ 前缀最大值 curMax 恰好等于 i](images/wc179_q2_prefix_max_concept.svg)

记 $S_i = \{\mathrm{flips}[1], \dots, \mathrm{flips}[i]\}$ 为前 $i$ 步翻过的位置集合。推理链只有三步：

1. **每个位置至多被翻一次**（排列 ⟹ 元素互异），所以第 $i$ 步后位置 $j$ 为 $1 \iff j \in S_i$，且 $|S_i| = i$；
2. **前缀一致 $\iff S_i = \{1, \dots, i\}$**：$[1,i]$ 全亮且其余全灭，合起来就是「翻过的位置恰好是前 $i$ 个」；
3. **抽屉原理**：$S_i$ 是 $i$ 个互不相同的正整数，若 $\max(S_i) = i$，则这 $i$ 个数全都不超过 $i$、又要在 $\{1,\dots,i\}$ 里取满 $i$ 个互异值——只能是全集本身。反之集合恰为 $\{1,\dots,i\}$ 时最大值显然是 $i$。

把三步串起来，得到本题的「一行公式」：

$$
\text{第 } i \text{ 步后前缀一致} \;\Longleftrightarrow\; \max_{1 \le k \le i} \mathrm{flips}[k] = i
$$

以示例 1 验证：第 4 步时 $S_4 = \{3,2,4,1\}$，4 个互异值、最大值 $4$，恰是 $\{1,2,3,4\}$，前 4 位全亮 ✓；第 2 步时 $S_2 = \{3,2\}$，最大值 $3 > 2$，说明位置 3 已亮而位置 1 还有空洞 ✗。**$\max > i$ 就是「前缀内必有空洞」的直接信号**。

> ⚠️ 「排列」条件不可或缺：若无此保证，前 $i$ 步翻 $i$ 次 ≠ 翻动 $i$ 个不同位置，最大值判据即失效（见 §5 定理后的讨论）。本题能压到 $O(1)$ 空间，吃的全是这条约束的红利。

### 3.3 算法流程：一趟遍历维护 curMax

![算法流程：一趟遍历，维护前缀最大值并与步数比较，curMax == i 即计数](images/wc179_q2_one_pass_flow.svg)

1. 初始化 `ans = 0`（计数）、`curMax = 0`（前缀最大值）；
2. 依次处理每个 `flips[i]`（0-based 下标 $i$，对应第 $i+1$ 步）：
   - 更新 `curMax = max(curMax, flips[i])`；
   - 若 `curMax == i + 1`（前缀最大值追上步数），则 `ans += 1`；
3. 遍历结束返回 `ans`。

全程没有字符串、没有集合、没有树状数组——状态被压缩成一个标量 `curMax`，判定是整数相等比较。

### 3.4 示例演算

![示例演算：示例 1 与示例 2 的逐步 curMax 跟踪与判定](images/wc179_q2_walkthrough.svg)

**示例 1**（`flips = [3,2,4,1,5]`，$n=5$）：

| 步 $i$ | 翻转位 | 字符串 | $S_i$ | $\max S_i$ | 判定 |
|---|---|---|---|---|---|
| 1 | 3 | `00100` | $\{3\}$ | 3 | $3 \ne 1$ ✗ |
| 2 | 2 | `01100` | $\{2,3\}$ | 3 | $3 \ne 2$ ✗ |
| 3 | 4 | `01110` | $\{2,3,4\}$ | 4 | $4 \ne 3$ ✗ |
| 4 | 1 | `11110` | $\{1,2,3,4\}$ | 4 | $4 = 4$ ✓ |
| 5 | 5 | `11111` | $\{1,\dots,5\}$ | 5 | $5 = 5$ ✓ |

结果 `ans = 2` ✓。注意第 4 步翻的是下标 1（很小的值），但 `curMax` 保持第 3 步的 4 不变——**判定看的是累计最大值，不是本步翻的值**：累计最大值卡在 4，恰好说明前 4 个位置已凑齐。

**示例 2**（`flips = [4,1,2,3]`，$n=4$）：

| 步 $i$ | 翻转位 | 字符串 | $S_i$ | $\max S_i$ | 判定 |
|---|---|---|---|---|---|
| 1 | 4 | `0001` | $\{4\}$ | 4 | $4 \ne 1$ ✗ |
| 2 | 1 | `1001` | $\{1,4\}$ | 4 | $4 \ne 2$ ✗ |
| 3 | 2 | `1101` | $\{1,2,4\}$ | 4 | $4 \ne 3$ ✗ |
| 4 | 3 | `1111` | $\{1,2,3,4\}$ | 4 | $4 = 4$ ✓ |

结果 `ans = 1` ✓。第 1 步就把 4 顶成 `curMax`，此后 `curMax = 4` 一直「跑在步数前面」，直到最后一步步数追平——这正是「大值早出现 ⟹ 前缀留空洞」的典型形态。

## 4. 算法细节

1. **两个标量打天下**：`ans` 与 `curMax`，一趟遍历，每步一次 `max`、一次比较、可能一次自增。
2. **下标换算是最高频 bug 点**：判据是「`curMax` == 步数」，步数是 1-based；用 0-based 数组下标 `i` 遍历时必须写 `curMax == i + 1`。Python 可用 `enumerate(flips, 1)` 直接拿 1-based 步号，让判据写成与题意完全同构的 `curMax == i`。
3. **`curMax` 初始为 0**：小于一切 `flips` 值（$1 \le \mathrm{flips}[i] \le n$），进循环统一更新即可，无需为第一步特判。
4. **隐含的恒等式**：$i$ 个互异正整数的最大值**至少**是 $i$（最小集合 $\{1,\dots,i\}$ 的 $\max$ 就是 $i$），故第 $i$ 步后恒有 $\mathrm{curMax} \ge i$——判据 `== i` 与 `<= i` 等价，但写 `==` 语义最清晰，不要依赖这个性质耍小聪明。
5. **为什么不维护字符串**：字符串状态由 $S_i$ 完全决定，而判定只需要 $S_i$ 的「上界」信息；排列性质保证 $|S_i| = i$，「上界 = 个数」即「恰为 $\{1..i\}$」，集合信息被无损压缩成一个 `max`。
6. **若去掉排列约束**：同一位置可能被翻多次，「翻 $i$ 次」不再等于「翻 $i$ 个不同位置」，`max` 判据失效，需退回维护翻转奇偶性（异或计数 / 树状数组）的做法，复杂度上升到 $O(n \log n)$——本题不涉及，但要知道最优解的边界在哪里。

## 5. 正确性证明

记 $S_i = \{\mathrm{flips}[1], \dots, \mathrm{flips}[i]\}$（前 $i$ 步翻动的位置集合），$1 \le i \le n$。

**引理 1（一次翻转即恒亮）**：`flips` 是 $[1,n]$ 的排列，故任意位置在全程中**至多被翻转一次**；第 $i$ 步后，位置 $j$ 为 $1 \iff j \in S_i$。

**证明**：排列元素互异 ⟹ 任意 $j$ 至多出现于 `flips` 的一个下标；若其出现的下标 $\le i$，则恰被翻转一次（$0 \to 1$），否则从未被翻转（保持 $0$）。∎

**引理 2（抽屉判据）**：$S_i$ 含 $i$ 个互异正整数，则 $S_i = \{1, \dots, i\} \iff \max(S_i) = i$。

**证明**：（⇒）$\max\{1, \dots, i\} = i$，显然。（⇐）设 $\max(S_i) = i$，则 $S_i$ 的 $i$ 个互异元素均取自 $\{1, \dots, i\}$（不能超过 $\max$），而候选值恰有 $i$ 个、取的也恰是 $i$ 个互异值，故取满全集，$S_i = \{1, \dots, i\}$。∎

**定理（计数判据）**：第 $i$ 步后前缀一致 $\iff \max(\mathrm{flips}[1..i]) = i$。

**证明**：前缀一致即「$\forall j \le i$ 位 $j = 1$ 且 $\forall j > i$ 位 $j = 0$」。由引理 1，前者 $\iff [1, i] \subseteq S_i$，后者 $\iff S_i \cap (i, n] = \varnothing$，二者合并即 $S_i = \{1, \dots, i\}$。又排列互异给出 $|S_i| = i$，由引理 2，$S_i = \{1, \dots, i\} \iff \max(S_i) = i$。∎

**推论 1**：答案 $\ge 1$——取 $i = n$，$S_n = \{1, \dots, n\}$（排列全体），$\max = n$ 恒成立，最后一步必然一致。

**推论 2**：计入答案的恰是那些满足「$\mathrm{flips}[1..i]$ 是 $\{1, \dots, i\}$ 的排列」的步号 $i$；由于互补段 $\mathrm{flips}[i{+}1..n]$ 此时也恰是 $\{i{+}1, \dots, n\}$ 的排列，答案即 `flips` 的「左联前缀块」个数（与 [769. 最多能完成排序的块](https://leetcode.cn/problems/max-chunks-to-make-sorted/) 的分块计数完全同构）。

> ⚠️ 两条引理都依赖排列约束：引理 1 用「互异 ⟹ 至多翻一次」，引理 2 用「互异 ⟹ $|S_i| = i$」。若允许重复翻转，两处同时崩塌——例如 `flips = [1, 1]`（非法输入，仅作思想实验）在第 2 步后字符串是 `"00"`，而 $\max = 1$，任何基于 `max` 的判定都不再描述真实状态。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素一次 `max` 更新 + 一次比较，共 $n$ 轮；读取全部输入是必要开销，$O(n)$ 已达下界。
- **空间复杂度**：$O(1)$。只有 `ans` 与 `curMax` 两个标量，不随 $n$ 增长（不计输入数组）。
- **对比**：暴力模拟 $O(n^2)$（$n = 5 \times 10^4$ 时约 $1.25 \times 10^9$ 次操作，超时）；有序集合 $O(n \log n)$；前缀最大值法 $O(n)$ / $O(1)$——是排列约束下能 squeeze 出的最优形态。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numTimesAllBlue(vector<int>& flips) {
        int ans = 0, curMax = 0;
        for (int i = 0; i < (int)flips.size(); ++i) {
            curMax = max(curMax, flips[i]);   // 前 i+1 步翻动位置的最大值
            if (curMax == i + 1) ++ans;       // 追上步数 ⟺ 前缀 [1, i+1] 恰好凑齐
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numTimesAllBlue(self, flips: List[int]) -> int:
        ans = cur_max = 0
        for i, p in enumerate(flips, 1):   # i 为步号（1-based）
            cur_max = max(cur_max, p)
            if cur_max == i:               # 与题意完全同构的判据
                ans += 1
        return ans
```

> 💡 Python 版 `enumerate(flips, 1)` 把步号直接从 1 数起，判据 `cur_max == i` 与定理一字不差，是可读性最高的写法。注意 `cur_max` 比较的是 `flips` 的**值**（位置下标），`i` 是**步号**——两个不同维度被排列性质绑定：「已翻位置的最大下标」与「已翻次数」相等时，前缀恰好归位。

## 8. 边界情况与易错点

1. **0/1-based 错位（本题最高频 WA）**：判据是与**步数**比较；0-based 遍历时漏写 `+ 1`（`curMax == i`）必错，且示例 1 的第 3 步恰好掩盖问题（$S_3$ 的 $\max=4$、下标 $i=2$ 时 $4 \ne 2$ 侥幸不误判，但整体计数必偏小），本地要跑双示例对拍。
2. **别真的维护字符串**：每步重建 + 校验是 $O(n^2)$，$n = 5 \times 10^4$ 时 Python 稳挂、C++ 也悬；同理别上树状数组/有序集合，杀鸡用牛刀且代码量翻倍。
3. **把「前缀一致」记成「$[1,i]$ 全亮就算」**：还要求 $i$ 之后全灭；两者由 $|S_i| = i$ 自动绑定（引理 2 正是绑定的桥梁），但如果自造测试数据且元素可重复，判定就会假阳性。
4. **答案至少为 1**（推论 1）：本地测试若得 0 必有 bug；反之答案上界是 $n$（示例 3 的正序排列）。
5. **$n = 1$**：`flips = [1]`，第 1 步即一致，输出 1；`curMax = 0` 初值不会让首步误判。
6. **`curMax` 初始值取 0** 而非 `flips[0]`：进循环统一更新，免掉第一步特判；取负数也可但没必要。
7. **无溢出风险**：值域 $\le 5 \times 10^4$，`int` 绰绰有余；无空输入（$n \ge 1$）。
8. **读清孪生题面**：本题在部分版本题面里叫「灯泡开关 III」（亮灯构成前缀则「变蓝」），变量名与叙述不同但算法完全一致，赛场上别被换皮题面带偏。
