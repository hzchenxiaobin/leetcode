# LeetCode 通知所有员工所需的时间 题解

## 1. 题目概述

- **标题 / 题号**：通知所有员工所需的时间（#1376，medium）
- **链接**：https://leetcode.cn/problems/time-needed-to-inform-all-employees/
- **来源**：LeetCode 第 179 场周赛 Q3
- **难度**：中等
- **标签**：树、广度优先搜索、深度优先搜索、记忆化

**题意**：公司 $n$ 名员工构成一棵**树**：`manager[i]` 是员工 $i$ 的直属上司，根是 `headID`（`manager[headID] = -1`）。紧急消息从根开始向下传播：员工 $i$ **同时**通知其**所有**直属下属，耗时 $\mathrm{informTime}[i]$ 分钟（这 $informTime[i]$ 分钟结束后，这些下属**同时**开始继续向下传播）。返回从根发出消息到**所有**员工都收到的最少分钟数。

**约束**：

- $1 \le n \le 10^5$
- $0 \le \mathrm{informTime}[i] \le 1000$；没有下属的员工其 `informTime` 必为 0
- 题目保证从属关系构成树、所有员工都能收到消息

> 💡 赛中 30 秒定位：这是「**并行广播**」而不是「调度」——每个节点的所有孩子**同一时刻**收到消息，兄弟子树之间零干扰。于是「某人何时收到」只由根到他的**路径**决定，总时间就是**最长根到叶路径的权值和**（边权 = 上司的 `informTime`），一次 BFS/DFS 扫全树即可。同场 Q4（T 秒后青蛙的位置）也是树上 DFS，本题相当于其热身。

## 3. 解题思路

### 3.1 暴力思路：模拟时间轴 / 逐点无记忆上溯

两种朴素做法都会撞墙：

1. **逐分钟模拟**：维护「已收到」集合，按分钟推进、检查谁的计时归零。总时长 $T$ 最高可达 $\sum \mathrm{informTime} \approx 10^5 \times 10^3 = 10^8$ 分钟，逐分钟循环连 C++ 都跑不动（每分钟再扫全体员工更是 $O(T \cdot n)$ 天方夜谭）；换成事件堆模拟倒是可以 $O(n \log n)$ 过，但属于杀鸡用牛刀。
2. **逐点上溯求路径和**：对每个员工 $v$ 沿 `manager` 链走到根，累加路径上祖先的 `informTime`，全体取最大。单次上溯 $O(\mathrm{depth})$，链状树下合计 $O(n^2) \approx 10^{10}$，稳超时。

> ⚠️ 两者共同的问题：把「并行广播」误当「串行流程」逐帧重放，没有提炼出「到达时刻只依赖路径」这一结构。其实第 2 种做法离正解只差一步——上溯时**同一批祖先被反复走过**，把 $f(v)$ 存下来即记忆化，就是 $O(n)$（见 §4 备选写法）。

### 3.2 核心观察：到达时刻 = 根到该点路径的边权之和

![核心观察：把 manager 数组还原成树，边权 = 上司的 informTime，答案是最长根到叶加权路径](images/wc179_q3_weighted_path_concept.svg)

推理链只有三步：

1. **广播语义**：$u$ 的**所有**直属下属在 $f(u) + \mathrm{informTime}[u]$ **同一时刻**收到消息——兄弟子树之间零干扰，「何时收到」与别人的进度无关；
2. **递推公式**：$f(\mathrm{head}) = 0$，且
   $$f(v) = f(\mathrm{manager}[v]) + \mathrm{informTime}[\mathrm{manager}[v])]$$
   展开即 $f(v) = \sum_{u \in \mathrm{anc}(v)} \mathrm{informTime}[u]$（$v$ 的全部**严格祖先**的权值和，即根到 $v$ 路径的边权之和）；
3. **答案取最大**：全员收到 $\iff$ 最晚的那个人收到 $\iff$ $T \ge \max_v f(v)$，故答案 $= \max_v f(v)$，即**最长根到叶加权路径**。

> ⚠️ 第 3 步里的「叶」只是直觉说法：$\mathrm{informTime} \ge 0$ 保证 $f$ 沿路径单调不减，最大值必然能在某个叶子处取到；但实现中在**所有**节点上取 max 同样正确，完全不需要判叶子。另外注意「最长」指的是**权值和**而非边数——示例 5 里 4 条边的路径（和 12）输给了 3 条边的路径（和 14）。

### 3.3 算法流程：建反图 + BFS 传时刻

![算法流程：建孩子表 → 队列存 (员工, 到达时刻) → 出队刷新 max、孩子按递推式入队](images/wc179_q3_bfs_flow.svg)

1. **建孩子表**：题目给的是「孩子 → 父亲」方向的 `manager` 数组，而遍历需要「父亲 → 孩子」方向，一次线性扫描建出 `children` 邻接表（**必须跳过 headID**，因为 `manager[headID] = -1`，直接索引会越界）；
2. **BFS**：队列存二元组 $(u, t)$，$t$ 即 $f(u)$（$u$ 收到消息的时刻）。出队时用 $t$ 刷新全局最大值 `ans`，再把 $u$ 的每个孩子 $v$ 以 $(v,\; t + \mathrm{informTime}[u])$ 入队——入队时刻一次算清，无需回看；
3. 队列清空时的 `ans` 即答案。

### 3.4 示例演算

![示例演算：n=9 逐轮 BFS 的出队、入队、队列快照与 ans 跟踪](images/wc179_q3_bfs_walkthrough.svg)

对示例 5（$n=9$）逐轮跟踪（`q` 列为该轮出队后的队列快照）：

| 轮 | 出队 $(u,\,t)$ | 新入队 $(v,\ t+\mathrm{informTime}[u])$ | 队列（之后） | $ans$ |
|---|---|---|---|---|
| 0 | $(4,\,0)$ | $(0,4)\;(2,4)\;(5,4)$ | $(0,4)(2,4)(5,4)$ | 0 |
| 1 | $(0,\,4)$ | $(1,7)$ | $(2,4)(5,4)(1,7)$ | 4 |
| 2 | $(2,\,4)$ | $(6,6)$ | $(5,4)(1,7)(6,6)$ | 4 |
| 3 | $(5,\,4)$ | —（叶子） | $(1,7)(6,6)$ | 4 |
| 4 | $(1,\,7)$ | $(3,12)$ | $(6,6)(3,12)$ | 7 |
| 5 | $(6,\,6)$ | $(8,14)$ | $(3,12)(8,14)$ | 7 |
| 6 | $(3,\,12)$ | $(7,12)$ | $(8,14)(7,12)$ | 12 |
| 7 | $(8,\,14)$ | —（叶子） | $(7,12)$ | **14** |
| 8 | $(7,\,12)$ | —（叶子） | $\varnothing$ | **14** |

结果 $ans = 14$ ✓。三个值得咀嚼的细节：

- 轮 7 出队的 $(8,14)$ **早于**轮 8 的 $(7,12)$，但到达时刻上 $12 < 14$——**出队顺序 ≠ 到达时刻顺序**，`max` 必须全程维护，不能只看最后出队的元素；
- 员工 7（深度 4，时刻 12）比员工 8（深度 3，时刻 14）**更早**收到——「最深的叶子」不等于「最晚的叶子」，因为边权不均匀；
- 「出队」列中每个员工恰好出现一次、每条父子边只在「新入队」列出现一次——这就是 $O(n)$ 的直观来源。

## 4. 算法细节

1. **建图必须跳过 headID**：`manager[headID] = -1`。C++ 里 `children[-1]` 是**未定义行为**；Python 里 `children[-1]` **静默**索引到末尾元素，树里悄悄多出一条假边——样例甚至可能侥幸通过，是本题第一 WA 点。
2. **队列状态设计 $(u, t)$**：把「到达时刻」直接背在节点上进队，出队即用，无需另开数组存 $f$；$t$ 在入队时由递推式一次算清。
3. **max 更新点**：出队时更新即可，不必区分叶子/内部节点（§5 引理 3 的单调性兜底）；只在 `children[u]` 为空时更新也能对，但纯属锦上添花。
4. **显式栈/队列，不写递归**：链状树深度可达 $10^5$，Python 递归深度默认 1000 直接 `RecursionError`；C++ 深递归也在赌栈空间。BFS 用 `queue`、DFS 用显式 `stack`，都安全。
5. **备选：不建树的上溯记忆化**（Python 见 §7）：对每个 $v$ 沿 `manager` 上溯到第一个已算出 $f$ 的祖先，再回填整条路径。每条边至多被走两次，总复杂度仍 $O(n)$，省下整张邻接表，代价是代码略绕。
6. **备选：自底向上树形 DP**：$g(u) = \mathrm{informTime}[u] + \max_c g(c)$，答案 $g(\mathrm{head})$，与每日一题版（`solution/1301-1400/1376_通知所有员工所需的时间.md`）的写法一致。两者等价，BFS 版天然规避递归深度。

## 5. 正确性证明

**引理 1（到达时刻公式）**：记 $\mathrm{anc}(v)$ 为根到 $v$ 路径上 $v$ 的全部严格祖先，则员工 $v$ **恰在**时刻
$$f(v) = \sum_{u \in \mathrm{anc}(v)} \mathrm{informTime}[u]$$
收到消息（$f(\mathrm{head}) = 0$，空和）。

**证明**：对 $v$ 的深度作归纳。深度 0 即根，其本人在时刻 0 已知消息，$f = 0$ 成立。设 $v \ne \mathrm{head}$，令 $u = \mathrm{manager}[v]$，深度比 $v$ 小，归纳假设 $u$ 恰在 $f(u)$ 收到。题面保证 $u$ 从收到消息起经 $\mathrm{informTime}[u]$ 分钟**同时**通知所有直属下属——不含任何排队或次序——故 $v$ 恰在 $f(u) + \mathrm{informTime}[u]$ 收到；而 $\mathrm{anc}(v) = \mathrm{anc}(u) \cup \{u\}$，于是
$$f(u) + \mathrm{informTime}[u] = \sum_{w \in \mathrm{anc}(v)} \mathrm{informTime}[w] = f(v). \;\blacksquare$$

**引理 2（下界）**：答案 $\ge \max_v f(v)$。

**证明**：取 $v^*$ 使 $f(v^*) = \max_v f(v)$，由引理 1，$v^*$ 恰在时刻 $f(v^*)$ 才收到消息，故任何 $T < \max_v f(v)$ 都有人未收到。∎

**定理**：答案 $= \max_{0 \le v < n} f(v)$，即最长根到叶路径的 `informTime` 边权之和。

**证明**：「≤」由引理 1，每个 $v$ 在 $f(v) \le \max_v f$ 时刻已收到，故时刻 $\max_v f$ 全员收到，答案不超过它；「≥」即引理 2。∎

**引理 3（单调性）**：$\mathrm{informTime} \ge 0$ ⟹ $f$ 沿根到叶方向单调不减，故 $\max_v f(v)$ 必可在某叶子处取得。

**证明**：$v$ 是 $u$ 的孩子时 $f(v) = f(u) + \mathrm{informTime}[u] \ge f(u)$，沿路径逐边传递即得。∎

**推论（算法正确性）**：BFS 中入队的二元组恰为 $(v, f(v))$——初始 $(\mathrm{head}, 0)$ 成立；出队 $(u, f(u))$ 后按引理 1 的递推式把孩子以 $(v,\; f(u) + \mathrm{informTime}[u]) = (v, f(v))$ 入队，归纳知全体正确，故返回值 $\max t = \max_v f(v)$ 即答案。∎

> ⚠️ 广播语义是全部证明的地基：若题面改成「上司需**逐个**通知下属、每人耗时不同」，引理 1 的递推不再成立（同一父亲的不同孩子到达时刻互相依赖通知次序），问题升级为排序/调度类题目（对照 [LeetCode 1723. 完成所有工作的最短时间](https://leetcode.cn/problems/find-minimum-time-to-finish-all-jobs/) 一族）。本题明确写着「$informTime[i]$ 分钟后，他的**所有**直属下属都**可以开始**传播」——读题时务必咬死这半句。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。建 `children` 邻接表一趟线性扫描；BFS 中每个节点恰进出队各一次、每条父子边恰被遍历一次。$n = 10^5$ 下毫秒级。
- **空间复杂度**：$O(n)$。`children` 邻接表共 $n - 1$ 条边，加队列峰值（最深一层的节点数）。记忆化备选写法省去邻接表、只需 `memo` 数组，仍 $O(n)$。
- **对比**：逐分钟模拟 $O(T \cdot n)$、$T$ 可达 $10^8$，不可行；事件堆模拟 $O(n \log n)$，能过但无必要；逐点无记忆上溯 $O(n \cdot h)$，链上 $O(n^2) \approx 10^{10}$，超时；BFS / 记忆化上溯均为 $O(n)$ / $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numOfMinutes(int n, int headID, vector<int>& manager, vector<int>& informTime) {
        // 1. 建反图：children[manager[i]] 收集孩子；跳过 headID（其 manager 值为 -1）
        vector<vector<int>> children(n);
        for (int i = 0; i < n; ++i)
            if (i != headID) children[manager[i]].push_back(i);

        // 2. BFS：二元组 (u, t)，t 即 u 收到消息的时刻 f(u)
        int ans = 0;
        queue<pair<int, int>> q;
        q.emplace(headID, 0);
        while (!q.empty()) {
            auto [u, t] = q.front(); q.pop();
            ans = max(ans, t);
            for (int v : children[u])
                q.emplace(v, t + informTime[u]);   // 引理 1 的递推式
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numOfMinutes(self, n: int, headID: int, manager: List[int], informTime: List[int]) -> int:
        children = [[] for _ in range(n)]
        for i, m in enumerate(manager):
            if i != headID:                    # manager[headID] == -1，跳过防假边
                children[m].append(i)

        ans = 0
        stack = [(headID, 0)]                  # (员工, 到达时刻)
        while stack:
            u, t = stack.pop()
            ans = max(ans, t)
            for v in children[u]:
                stack.append((v, t + informTime[u]))
        return ans
```

### Python 备选：不建树的记忆化上溯

```python
class Solution:
    def numOfMinutes(self, n: int, headID: int, manager: List[int], informTime: List[int]) -> int:
        memo = [-1] * n
        memo[headID] = 0                       # f(head) = 0
        for v in range(n):
            if memo[v] != -1:
                continue
            path = []
            u = v
            while memo[u] == -1:               # 上溯到第一个已算出的祖先
                path.append(u)
                u = manager[u]
            t = memo[u]
            for w in reversed(path):           # 回填整条路径的 f 值
                t += informTime[manager[w]]
                memo[w] = t
        return max(memo)
```

> 💡 备选版的循环不变量：外层每轮结束后，$v$ 到根的整条链上所有节点的 $f$ 都已写入 `memo`，因此 `while` 循环每条边至多被走两次（一次上溯、一次回填），总代价 $O(n)$。它省掉了 `children` 邻接表，代价是需要想清楚回填方向——面试里两个版本都会写，赛场求稳用第一个。

## 8. 边界情况与易错点

1. **`manager[headID] = -1` 越界**（本题最高频 WA）：C++ `children[-1]` 是 UB；Python 会静默挂到 `children[n-1]` 上形成假边，且可能侥幸过样例。建图循环必须 `if (i != headID)`。
2. **递归爆栈**：链状树深 $10^5$，Python 递归默认上限 1000 必抛 `RecursionError`，C++ 递归也在赌默认栈大小——用队列/显式栈迭代写。
3. **`int` 够用但要有账**：答案上界 $\approx 10^5 \times 1000 = 10^8 < 2^{31} - 1$，C++ `int` 安全；若范围再放大一个量级就要换 `long long`。
4. **$n = 1$**：队列只有 $(\mathrm{head}, 0)$，出队后无孩子，返回 0，无需特判。
5. **别只看「最后一层」或「最后出队」**：边权不均匀时深度与到达时刻脱钩（员工 7 深 4 却早于员工 8 深 3 到达），出队顺序也与时刻顺序无关——`ans` 必须全程维护。
6. **叶子 `informTime = 0` 是约束不是依赖**：算法不依赖它；即便叶子时间非零，也只是「没有孩子继承这条边」，正确性不受影响（引理 3 仍成立）。
7. **别上 Dijkstra/优先队列**：树结构 + 非负权 + 唯一路径，时刻可直接算术传递，普通队列一趟即可；优先队列是给「一般图 + 需按最早时刻处理」的场景准备的，本题用了反而多一个 $\log$ 因子。
8. **入队时算清时刻，不要存「剩余时间」倒计时**：把状态设计成 $(u, f(u))$ 而非 $(u, \mathrm{remains})$，就没有计时轮询，也就没有 $T$ 那一圈循环。

**延伸思考**：其一，若上司必须**逐个**通知下属（同一时刻只能通知一人），求全员知晓的最短时间变为调度问题——子树内应优先通知「整体完成更晚」的分支（经典交换论证可证），复杂度仍线性但思路完全不同；其二，若公司结构是一般**有向无环图**（一人可有多个上司、消息取最早到达），则变为按拓扑序取最长/最短路式的 DP；其三，若问「最后一个收到消息的员工是谁」，只需在维护 `ans` 的同时多存一个 argmax——本题的最长路径终点。
