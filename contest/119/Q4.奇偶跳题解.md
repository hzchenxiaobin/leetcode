# LeetCode 奇偶跳 题解

## 1. 题目概述

- **标题 / 题号**：奇偶跳（#975，hard）
- **链接**：https://leetcode.cn/problems/odd-even-jump/
- **来源**：LeetCode 第 119 场周赛 Q4
- **难度**：困难
- **标签**：栈、数组、动态规划、有序集合、排序、单调栈

**题意**：给定整数数组 `arr`。从某个下标出发，第 $1, 3, 5, \dots$ 次跳跃是**奇数跳**，第 $2, 4, 6, \dots$ 次是**偶数跳**。每次从 $i$ 跳到 $j > i$：

- **奇数跳**：在满足 $arr[j] \ge arr[i]$ 的 $j$ 中，取 $arr[j]$ **最小**者；若并列，取**下标最小**者。
- **偶数跳**：在满足 $arr[j] \le arr[i]$ 的 $j$ 中，取 $arr[j]$ **最大**者；若并列，取**下标最小**者。

若从某下标出发、经过若干次（$0$ 次或多次）跳跃能到达 `arr.length - 1`，该下标是**好**的。返回好下标个数。

**约束**：

- $1 \le arr.length \le 20000$
- $0 \le arr[i] < 100000$

> 💡 关键事实：**每个位置的下一步落点是唯一的**——跳转规则与「这是第几次跳」无关，只与当前下标和奇偶性有关。这让问题从「路径搜索」变成「函数迭代」。

## 2. 示例

**示例 1**

```text
输入：arr = [10,13,12,14,15]
输出：2
解释：从 0 出发，奇数跳要求 arr[j] >= 10 且最小 → arr[2] = 12（下标 2），
      之后偶数跳要求 <= 12 且最大 → 右侧只有 14、15，都不满足 → 卡死；
      从 3 出发：奇数跳到 4（15）→ 到达末尾 ✓；
      从 4 出发：已在末尾 ✓。好下标为 {3,4}，共 2 个。
```

**示例 2**

```text
输入：arr = [2,3,1,1,4]
输出：3
解释：好下标为 {1,3,4}。从 0 出发：奇跳到 1（3），偶跳到 2（1，值并列取小下标），
      奇跳本应找 >= 1 的最小值 → 下标 3（值 1），到达 3 后偶跳找不到 <= 1 的更大值 → 卡死。
```

**示例 3**

```text
输入：arr = [5,1,3,4,2]
输出：3
解释：好下标为 {1,2,4}。
```

## 3. 解题思路

### 3.1 暴力思路

对每个起点 $i$ 模拟跳跃：每次从当前位置向后扫描找落点（$O(n)$），最多跳 $n$ 步，总 $O(n^3)$；$n = 2 \times 10^4$ 时是 $8 \times 10^{12}$，不可行。即便用有序集合把「找落点」压到 $O(\log n)$，对每个起点各跑一次仍是 $O(n^2 \log n)$。

### 3.2 核心观察：落点是位置的函数，可以一次算完所有落点

![两状态 DAG：canOdd 与 canEven 互为后继](images/wc119_q4_dp_states.svg)

记 `nxtOdd[i]`、`nxtEven[i]` 分别为从 $i$ 做一次奇数跳 / 偶数跳的落点（不存在记 $-1$）。由于「跳到哪个 $j$」只取决于 $i$ 与奇偶性，**与之前怎么走到 $i$ 无关**，于是：

- 好路径 = 在两条确定的「后继边」上不断前进直到 $n-1$；
- 状态只需记录「当前在哪个位置、下一步是奇还是偶」，共 $2n$ 个状态，且**后继位置一定大于当前位置**，天然是 DAG，可以**从右往左**做 DP。

状态与转移：

$$canOdd[i] = \big(nxtOdd[i] \neq -1\big) \wedge canEven\big[nxtOdd[i]\big]$$
$$canEven[i] = \big(nxtEven[i] \neq -1\big) \wedge canOdd\big[nxtEven[i]\big]$$

边界：$canOdd[n-1] = canEven[n-1] = \text{true}$（已在末尾，$0$ 次跳跃也算到达）。答案 $= \sum_i canOdd[i]$（起点第一步必是奇数跳）。

剩下的问题变成：**如何在 $O(n \log n)$ 内一次算出全部 $nxtOdd$ 与 $nxtEven$**。

### 3.3 算法流程

![排序 + 单调栈：按值从小到大处理，一次确定所有落点](images/wc119_q4_next_jump_table.svg)

```text
1. 求 nxtOdd：
   把下标按 (arr[i], i) 升序排序，得到处理序列 P
   维护一个栈 st（存「落点尚未确定」的下标，栈顶是其中下标最小的）
   for k in P:
       while st 非空 且 st.top() < k:
            nxtOdd[st.top()] = k;  st.pop()
       st.push(k)
2. 求 nxtEven：把排序键改成 (arr[i] 降序, i 升序)，重复同样的过程
3. canOdd[n-1] = canEven[n-1] = true
   for i = n-2 down to 0:
       canOdd[i]  = nxtOdd[i]  != -1 且 canEven[nxtOdd[i]]
       canEven[i] = nxtEven[i] != -1 且 canOdd[nxtEven[i]]
4. 返回 canOdd 中 true 的个数
```

**为什么栈能行**：按值升序处理时，先被处理的值更小。对某个未确定的位置 $i$，第一个被处理且下标 $> i$ 的位置 $k$，其值就是「$\ge arr[i]$ 中的最小值」（比它小的值都在它之前处理完了，且都没能完成配对），同一值组内按下标升序处理，故 $k$ 也是并列中下标最小的。栈恰好维护「未确定集合」，且栈顶是最小下标：若栈顶下标都 $\ge k$，则集合里没有 $< k$ 的位置需要配对，直接停；否则逐个弹出并赋值。

### 3.4 示例演算

![演算：先填 nxt 表，再从右往左推 canOdd / canEven](images/wc119_q4_walkthrough.svg)

对示例 1 的 `arr = [10,13,12,14,15]`，按下标 0~4：

| $i$ | $arr[i]$ | $nxtOdd[i]$ | $nxtEven[i]$ | $canOdd[i]$ | $canEven[i]$ |
|---|---|---|---|---|---|
| 4 | 15 | — | — | **true** | **true** |
| 3 | 14 | 4（15） | —（右侧无比 14 更小的） | **true** | false |
| 2 | 12 | 3（14） | — | false | false |
| 1 | 13 | 3（14） | 2（12） | false | false |
| 0 | 10 | 2（12） | — | false | false |

逐行解释：$i=3$ 的奇数跳找「$\ge 14$ 的最小值」→ 只有 15（下标 4）→ `canOdd[3] = canEven[4] = true` ✓。$i=2$：奇跳到 3，`canEven[3] = false`，故 `canOdd[2] = false`。$i=1$：奇跳到 3，`canEven[3] = false` → false；偶跳找「$\le 13$ 的最大值」→ 12（下标 2），`canOdd[2] = false` → false。$i=0$：奇跳到 2，`canEven[2] = false` → false。

`canOdd` 中为 true 的下标是 $\{3, 4\}$，答案 2 ✓。

## 4. 算法细节

1. **排序键要带下标**：值相等的元素必须按下标升序处理，否则「并列取最小下标」会被破坏。C++ 的比较器写成 `arr[a] != arr[b] ? arr[a] < arr[b] : a < b`。
2. **偶数跳的排序方向**：把 `<` 换成 `>`、并列仍按下标升序，就能复用同一段栈代码；也可以把值取负后复用升序逻辑。
3. **栈里存下标，不存值**：赋值时需要把值写回 `nxt` 数组，必须知道原始下标。
4. **初始 `nxt` 全为 $-1$**：栈里剩下的元素就是「找不到落点」的位置，天然对应 $-1$，不要再赋别的值。
5. **DP 必须从右往左**：$nxtOdd[i], nxtEven[i] > i$，所以计算 $i$ 时它们的状态已经算好；从左往右会用到未定义值。
6. **`n = 1` 特判**：答案是 1（起点即终点），直接初始化 `ans = 1` 可以自动覆盖，注意别访问 `n-1` 之外的下标。
7. **`char` 存布尔**：用 `vector<char>` 比 `vector<bool>` 快（后者是位压缩代理）。

## 5. 正确性证明

**引理 1（落点唯一）**：对每个 $i$，若存在 $j > i$ 满足 $arr[j] \ge arr[i]$，则满足条件的、使 $arr[j]$ 最小且下标最小的 $j$ 唯一；$nxtOdd[i]$ 与 $nxtEven[i]$ 由 $arr$ 唯一确定，与路径无关。

**证明**：候选集合 $S = \{j > i : arr[j] \ge arr[i]\}$ 有限且非空。取 $m = \min_{j \in S} arr[j]$，再取 $S' = \{j \in S : arr[j] = m\}$ 中的最小下标，二者都由 $arr$ 唯一确定。偶数跳同理（把 $\ge$ 换成 $\le$、$\min$ 换成 $\max$）。∎

**引理 2（栈正确地算出 $nxtOdd$）**：设下标按 $(arr[i], i)$ 升序排列为 $k_1, k_2, \dots, k_n$。则对每个 $i$，第一个满足 $k_t > i$ 的下标 $k_t$ 就是 $nxtOdd[i]$。

**证明**：设 $t$ 是使 $k_t > i$ 的最小下标。
（1）$k_t$ 是合法候选：$k_t$ 在排序中位于 $i$ 之后，故 $(arr[k_t], k_t) > (arr[i], i)$。若 $arr[k_t] < arr[i]$ 会矛盾（那它应排在 $i$ 之前），故 $arr[k_t] \ge arr[i]$，且 $k_t > i$，即 $k_t \in S$。
（2）$arr[k_t]$ 最小：任何 $j \in S$ 若满足 $arr[j] < arr[k_t]$，则 $j$ 排在 $k_t$ 之前；又 $j > i$，与 $t$ 的最小性矛盾。故 $arr[k_t] = \min_{j\in S} arr[j]$。
（3）并列时下标最小：若 $arr[j] = arr[k_t]$ 且 $j > i$、$j < k_t$，则 $(arr[j], j) < (arr[k_t], k_t)$，$j$ 排在 $k_t$ 前，同样矛盾。∎

**引理 3（栈的实现正确）**：栈中始终保存「$nxtOdd$ 尚未确定」的下标，且自底向顶严格递减（栈顶最小）。

**证明**：初始为空。处理 $k$ 时循环弹出所有 $< k$ 的栈顶并赋值——由引理 2，这些位置的最小合法后继正是 $k$，赋值正确，且它们此后不再需要确定，故可移出。循环结束时要么栈空、要么栈顶 $> k$，因此把 $k$ 压栈后仍保持「自底向顶递减」；同时栈内元素都是未确定的位置。∎

**引理 4（DP 转移正确）**：对 $i < n-1$，`canOdd[i]` 为真 $\iff$ 从 $i$ 出发（下一步奇数跳）能到达 $n-1$。

**证明**：对 $n-1-i$ 归纳。$i = n-1$ 时已在终点，为真。设 $i < n-1$：从 $i$ 出发的第一次跳跃（奇数跳）落点唯一，为 $nxtOdd[i]$。若 $nxtOdd[i] = -1$，则无法跳，为假，与转移一致；否则此后从 $nxtOdd[i]$ 出发、下一步是偶数跳，由归纳假设（$nxtOdd[i] > i$）`canEven[nxtOdd[i]]` 正确刻画可达性，转移即为二者的合取。`canEven` 对称同理。∎

**定理**：算法返回好下标的个数。

**证明**：由引理 1、2、3，`nxtOdd`、`nxtEven` 与题目规则完全一致；由引理 4，`canOdd[i]` 恰表示「从 $i$ 开始能到达末尾」。起点必为奇数跳，故好下标集合恰为 $\{i : canOdd[i]\}$，计数即答案。$n = 1$ 时 `ans` 初值为 1，也正确。∎

## 6. 复杂度分析

- **时间**：两次排序 $O(n \log n)$；两次栈扫描各 $O(n)$（每个下标进出栈一次）；DP 一遍 $O(n)$。合计 $O(n \log n)$，$n = 2 \times 10^4$ 时非常宽松。
- **空间**：`order`、`nxtOdd`、`nxtEven`、`canOdd`、`canEven`、栈各 $O(n)$，合计 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int oddEvenJumps(vector<int>& arr) {
        int n = (int)arr.size();
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);

        vector<int> nxtOdd(n, -1), nxtEven(n, -1);
        vector<int> st;

        // 奇数跳：按 (值升序, 下标升序) 处理，第一个右侧更大值即落点
        sort(order.begin(), order.end(), [&](int a, int b) {
            if (arr[a] != arr[b]) return arr[a] < arr[b];
            return a < b;
        });
        for (int k : order) {
            while (!st.empty() && st.back() < k) {
                nxtOdd[st.back()] = k;
                st.pop_back();
            }
            st.push_back(k);
        }

        // 偶数跳：按 (值降序, 下标升序) 处理
        sort(order.begin(), order.end(), [&](int a, int b) {
            if (arr[a] != arr[b]) return arr[a] > arr[b];
            return a < b;
        });
        st.clear();
        for (int k : order) {
            while (!st.empty() && st.back() < k) {
                nxtEven[st.back()] = k;
                st.pop_back();
            }
            st.push_back(k);
        }

        vector<char> canOdd(n, 0), canEven(n, 0);
        canOdd[n - 1] = canEven[n - 1] = 1;
        int ans = 1;
        for (int i = n - 2; i >= 0; i--) {
            if (nxtOdd[i] != -1 && canEven[nxtOdd[i]]) canOdd[i] = 1;
            if (nxtEven[i] != -1 && canOdd[nxtEven[i]]) canEven[i] = 1;
            if (canOdd[i]) ans++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def oddEvenJumps(self, arr: list[int]) -> int:
        n = len(arr)
        nxt_odd = [-1] * n
        nxt_even = [-1] * n

        # 奇数跳：值升序、下标升序
        st = []
        for k in sorted(range(n), key=lambda i: (arr[i], i)):
            while st and st[-1] < k:
                nxt_odd[st.pop()] = k
            st.append(k)

        # 偶数跳：值降序、下标升序
        st = []
        for k in sorted(range(n), key=lambda i: (-arr[i], i)):
            while st and st[-1] < k:
                nxt_even[st.pop()] = k
            st.append(k)

        can_odd = [False] * n
        can_even = [False] * n
        can_odd[-1] = can_even[-1] = True
        ans = 1
        for i in range(n - 2, -1, -1):
            if nxt_odd[i] != -1 and can_even[nxt_odd[i]]:
                can_odd[i] = True
            if nxt_even[i] != -1 and can_odd[nxt_even[i]]:
                can_even[i] = True
            if can_odd[i]:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **值相等时的 tie-break**：必须取**最小下标**，排序键漏掉下标会让并列情形取到错误落点（示例 2 的下标 2/3 都是 1，只能落到 2）。
2. **`arr[i]` 自己不算候选**：落点必须 $j > i$，排序后靠栈的 `st.back() < k` 条件天然排除自身与左侧元素。
3. **`n = 1`**：答案 1，直接返回；C++ 里 `canOdd[0] = canEven[0] = 1` 且循环不执行，`ans` 初值 1 正好。
4. **DP 方向**：必须从右往左；从左往右会读到尚未计算的状态。
5. **奇数跳 / 偶数跳的语义别搞反**：起点是**奇数**跳（第 1 次），答案统计 `canOdd` 而不是 `canEven`。
6. **`nxt` 初值**：栈里剩下的位置表示「无落点」，必须是 $-1$，不能用 0 之类的哨兵（下标 0 是合法落点的值域）。
7. **无序集合替代方案**：用 `TreeMap`/有序集合做「最近的不小于/不大于」也能 $O(n \log n)$，但常数更大且易写错边界，排序 + 栈更简洁。
8. **`arr` 被修改**：算法只排序下标数组，不改 `arr`，可以安全复用输入。
