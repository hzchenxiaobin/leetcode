# LeetCode 最接近原点的 K 个点 题解

## 1. 题目概述

- **标题 / 题号**：最接近原点的 K 个点（#973，medium）
- **链接**：https://leetcode.cn/problems/k-closest-points-to-origin/
- **来源**：LeetCode 第 119 场周赛 Q1
- **难度**：中等
- **标签**：几何、数组、数学、分治、快速选择、排序、堆（优先队列）

**题意**：给定平面上的点集 `points`，其中 `points[i] = [x_i, y_i]`，再给整数 $k$。返回距离原点 $(0,0)$ **最近**的 $k$ 个点，顺序任意。

两点距离是欧几里得距离 $\sqrt{(x_1-x_2)^2 + (y_1-y_2)^2}$。因为只比较远近，**平方距离** $x^2 + y^2$ 与距离同序，可以省掉开方。

**约束**：

- $1 \le k \le points.length \le 10^4$
- $-10^4 < x_i, y_i < 10^4$

> 💡 题目保证「除坐标顺序外答案唯一」，即不存在恰好等距的第 $k$、$k+1$ 名之争。

## 2. 示例

**示例 1**

```text
输入：points = [[1,3],[-2,2]], k = 1
输出：[[-2,2]]
解释：(1,3) 距原点 √10，(-2,2) 距原点 √8；√8 < √10，取最近的 1 个。
```

**示例 2**

```text
输入：points = [[3,3],[5,-1],[-2,4]], k = 2
输出：[[3,3],[-2,4]]        （[[-2,4],[3,3]] 也接受）
解释：平方距离分别为 18、26、20 → 最近的两个是 (3,3) 与 (-2,4)。
```

**示例 3**

```text
输入：points = [[0,0]], k = 1
输出：[[0,0]]
解释：只有一个点，直接返回。
```

## 3. 解题思路

### 3.1 暴力思路

对每个点算一次平方距离，然后**全排序**取前 $k$ 个：$O(n \log n)$。$n \le 10^4$ 时这已经能过，是最省心的写法。但题目明说「只取前 $k$ 个」，那 $n \log n$ 的完整排序就浪费了——我们并不需要后 $n-k$ 个元素之间的顺序。

### 3.2 核心观察：只需要「前 $k$ 名」，不需要「全序」

![只关心前 k 名：三种做法的比较](images/wc119_q1_distance_order.svg)

三档做法，复杂度递减：

| 做法 | 时间 | 说明 |
|---|---|---|
| 全排序 | $O(n \log n)$ | 简单，$10^4$ 足够 |
| 大顶堆（容量 $k$） | $O(n \log k)$ | 流式处理，适合 $n$ 很大、$k$ 较小 |
| **快速选择**（`nth_element`） | 平均 $O(n)$ | 只把前 $k$ 个元素划分到左边，不排序 |

快速选择的原理与快速排序的分区一致：随机/三数取中选枢轴，把「距离小于枢轴」的元素换到左边，然后只看第 $k$ 个位置落在哪一侧，递归处理一侧即可，期望 $O(n)$。

### 3.3 算法流程

![快速选择：一次分区就能砍掉一半搜索空间](images/wc119_q1_heap_selection.svg)

```text
1. 把每个点映射成它的平方距离 d(p) = x² + y²（比较键，不必真存）
2. 用 nth_element(points.begin(), points.begin()+k, points.end(), cmp)
       cmp(a,b) = d(a) < d(b)
   执行后：前 k 个位置恰好是距离最小的 k 个点（内部无序）
3. 返回 points[0 .. k-1]
```

Python 侧用 `heapq.nsmallest(k, ...)`：内部维护一个大小 $k$ 的堆，$O(n \log k)$，同样是「不必全排序」的思路。

### 3.4 示例演算

对示例 2 的 `points = [[3,3],[5,-1],[-2,4]]`，$k = 2$：

| 点 | $x^2+y^2$ | 排名 |
|---|---|---|
| (3,3) | $9+9=18$ | 1 |
| (-2,4) | $4+16=20$ | 2 |
| (5,-1) | $25+1=26$ | 3 |

`nth_element` 把前两个位置填成距离 18 与 20 的点（顺序可能是 `[[-2,4],[3,3]]`，题目接受任意顺序）；堆做法同理保留最小的两个。

## 4. 算法细节

1. **比较平方距离而不是开方**：$\sqrt{\cdot}$ 单调递增，且开方引入浮点误差；坐标绝对值 $<10^4$ 时 $x^2+y^2 < 2 \times 10^8$，`int` 足够，无需 `long long`。
2. **`nth_element` 的语义**：它保证 `[begin, begin+k)` 中的所有元素都**不大于** `[begin+k, end)` 中的元素，但两段内部都无序——这正好满足「顺序任意」。
3. **`k == n` 的边界**：`begin + k` 等于 `end` 合法，`nth_element` 直接返回，结果就是整个数组。
4. **Python 用 `heapq.nsmallest`**：它返回按序的前 $k$ 个（题目不要求顺序，多这一点排序开销可忽略）；若坚持 $O(n)$，可以手写快速选择。
5. **不要原地改动输入以外的副作用**：C++ 的 `nth_element` 会重排 `points`，本题允许（返回值取自 `points` 本身）；若不允许修改输入，应先拷贝。
6. **等距点**：题目保证答案唯一，因此不需要处理「距离相同如何取舍」的 tie-break。

## 5. 正确性证明

**引理 1（平方距离保序）**：对任意两点 $p, q$，$\lVert p\rVert < \lVert q\rVert \iff x_p^2 + y_p^2 < x_q^2 + y_q^2$。

**证明**：$\lVert p \rVert = \sqrt{x_p^2+y_p^2} \ge 0$，平方函数 $t \mapsto t^2$ 在 $[0, +\infty)$ 上严格递增，故两边平方不改变大小关系。∎

**引理 2（`nth_element` 的分区性质）**：执行 `nth_element(first, first+k, last, cmp)` 后，对任意 $i < k \le j$ 都有 $\mathrm{cmp}(a_j, a_i)$ 为假（左侧元素都不大于右侧元素）；等价地，前 $k$ 个元素恰为按 `cmp` 排序后的前 $k$ 个（多重集意义下）。

**证明**：这是 `nth_element` 的标准语义（selection 后第 $k$ 个元素处于其排序后应在的位置，且左侧元素都不大于它、右侧都不小于它）。因此前 $k$ 个位置的键集合就是全数组中最小的 $k$ 个键。∎

**定理**：算法返回的点集恰为距原点最近的 $k$ 个点。

**证明**：由引理 2，返回的 `points[0..k-1]` 是平方距离最小的 $k$ 个点。由引理 1，平方距离最小等价于欧氏距离最小，故返回集合正是最近的 $k$ 个点。答案唯一性保证不存在「等距导致两种合法解」的歧义。∎

## 6. 复杂度分析

- **时间**：C++ 平均 $O(n)$（`nth_element` 的期望复杂度，最坏 $O(n^2)$ 但实践中极罕见）；Python 的 `heapq.nsmallest` 为 $O(n \log k)$。全排序版本为 $O(n \log n)$。
- **空间**：$O(1)$ 额外空间（`nth_element` 原地分区）；`nsmallest` 为 $O(k)$；结果数组 $O(k)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> kClosest(vector<vector<int>>& points, int k) {
        auto dist2 = [](const vector<int>& p) { return p[0] * p[0] + p[1] * p[1]; };
        nth_element(points.begin(), points.begin() + k, points.end(),
                    [&](const vector<int>& a, const vector<int>& b) {
                        return dist2(a) < dist2(b);
                    });
        return vector<vector<int>>(points.begin(), points.begin() + k);
    }
};
```

### Python

```python
import heapq


class Solution:
    def kClosest(self, points: list[list[int]], k: int) -> list[list[int]]:
        return heapq.nsmallest(k, points, key=lambda p: p[0] * p[0] + p[1] * p[1])
```

## 8. 边界情况与易错点

1. **开方比较**：用 `sqrt` 比较既慢又可能因浮点误差把「几乎等距」判反，直接比平方距离。
2. **坐标范围与溢出**：$|x|, |y| < 10^4$ → 平方和 $< 2 \times 10^8$，`int` 安全；若坐标放大到 $10^5$，需换 `long long`。
3. **`k == n`**：`begin + k == end`，`nth_element` 合法；Python 的 `nsmallest(n, ...)` 也合法。
4. **`nth_element` 之后不能假设有序**：若后续需要按距离升序输出，必须再排一次前 $k$ 个。
5. **重复点**：`points` 中可能出现相同坐标（例如 `[[0,0],[0,0]]`），题目允许多次出现，按独立元素计数，不需要去重。
6. **原地修改输入**：`nth_element` 会打乱 `points`；有些评测环境会复用输入，必要时先 `auto a = points;`。
7. **Python 的 `key` 只算一次**：`nsmallest` 会对每个元素求一次 key，别把 `x*x+y*y` 写成会抛异常的形式（如坐标维度不足）。
