# LeetCode 单调递增的数字 题解

## 1. 题目概述

- **标题 / 题号**：单调递增的数字（#738，medium）
- **链接**：https://leetcode.cn/problems/monotone-increasing-digits/
- **来源**：LeetCode 第 61 场周赛 Q2
- **难度**：中等
- **标签**：贪心，数学

**题意**：若整数 $n$ 的十进制表示中，任意相邻两位 $x$（高位）与 $y$（低位）都满足 $x \le y$，则称 $n$ 的数字**单调递增**。给定 $n$，求**不超过** $n$ 且数字单调递增的**最大**整数。

**约束**：

- $0 \le n \le 10^9$

## 2. 示例

**示例 1**

```text
输入：n = 10
输出：9
解释：9 ≤ 10 且单调；10 本身是 1 > 0，不合法。
```

**示例 2**

```text
输入：n = 1234
输出：1234
解释：各位 1 ≤ 2 ≤ 3 ≤ 4，本身已经单调，原样返回。
```

**示例 3**

```text
输入：n = 332
输出：299
解释：332（3 > 2）、330、329、328 … 都不单调；
      而 299 的各位 2 ≤ 9 ≤ 9 满足单调，且是 ≤ 332 的最大者。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是从 $n$ 开始向下逐个枚举，检查数字是否单调：单次检查 $O(m)$（$m \le 10$ 为位数）。但相邻两个单调数之间可能相距很远——$n = 987654321$ 的答案是 $899999999$，中间要跳过近 $9 \times 10^7$ 个数；最坏情况下枚举量是 $10^8$ 量级，乘上每次 $O(m)$ 的检查，必然超时。

另一条朴素路线是「枚举所有单调数再取最大」：$m$ 位单调数等价于从 $0..9$ 中**可重复**地选 $m$ 个数，共 $\binom{m+8}{8}$ 个，$m = 10$ 时约 $4.4 \times 10^4$ 个，还能对每个位数区间分别处理。它正确（可以拿来对拍），但需要生成组合 + 分组比较，代码量和常数都不划算。真正的最优解只需要**一次线性扫描**。

### 3.2 核心观察：第一处「下降」就是切分点

![第一处下降决定切分点](images/wc61_q2_greedy_descent.svg)

把 $n$ 写成数位数组 $d[0..m-1]$（$d[0]$ 是最高位）。

- 若 $d$ 本身**非降**（如 $1234$），答案就是 $n$。
- 否则设 $i$ 是第一处下降的**右端下标**，即 $d[i-1] > d[i]$ 且 $d[0..i-1]$ 非降。

关键观察：任何单调数 $y \le n$、$y \ne n$，设 $p$ 是 $y$ 与 $n$ **首个不同**的位置。因为 $y < n$，必有 $y[p] < d[p]$；而为了让 $y$ 最大，$y[p]$ 就取 $d[p]-1$（它比 $d[p]$ 小、又尽量大），并且 $p$ 之后的位**全部填 9**（在不超上界的前提下尾数取到最大）。于是答案必然长成

$$\underbrace{d[0]\cdots d[p-1]}_{\text{与 } n \text{ 相同的前缀}}\ \bigl(d[p]-1\bigr)\ \underbrace{99\cdots 9}_{m-p-1 \text{ 个}}$$

这个形态**能成立**还要求两点：前缀 $d[0..p-1]$ 非降，并且借位后的 $d[p]-1$ 不小于前一位，即 $d[p-1] < d[p]$。

再看「$p$ 取多大最好」：若两个可行位置 $p < p'$，它们的值在第 $p$ 位就分出大小——候选 $p'$ 保留 $d[p]$，候选 $p$ 已经减成 $d[p]-1$，所以 $p'$ 的答案更大。**因此只需找最大的可行 $p$**。

而「$d[p]-1$ 顶掉前一位」这种情况必须处理：$n = 332$ 时第一处下降是 $3 > 2$（下标 $1 \to 2$），若只把下标 1 的 $3$ 减 1 得 $322$，仍然 $3 > 2$ 不合法；必须继续向左跨过与它**相同**的数字块，一直退到下标 0，才得到 $299$。

### 3.3 算法流程

![算法流程图](images/wc61_q2_algorithm_flow.svg)

1. **拆位**：把 $n$ 转成字符串（数位数组 $d$），长度为 $m$。
2. **向右扫描找下降**：令 $i = 1$，只要 $d[i-1] \le d[i]$ 就 $i \leftarrow i + 1$；循环结束后若 $i = m$，说明整串非降，直接返回 $n$。
3. **向左收缩**：令 $p = i - 1$，只要 $p > 0$ 且 $d[p-1] == d[p]$ 就 $p \leftarrow p - 1$。此时 $p$ 就是最左侧那个需要借位的位置。
4. **借位**：$d[p] \leftarrow d[p] - 1$。
5. **填 9**：把 $d[p+1..m-1]$ 全部置为 `'9'`，再转回整数返回。

Step 2 与 Step 3 合起来，每条数位最多被访问常数次，整体 $O(m)$。

### 3.4 示例演算

![三组走查](images/wc61_q2_walkthrough.svg)

| $n$ | 第一处下降 | 收缩后的 $p$ | 结果 |
|--------|----------------|----------------|--------|
| $332$ | $3 > 2$（下标 $1 \to 2$） | $1 \to 0$，因 $d[0] == d[1]$ | $299$ |
| $1130$ | $3 > 0$（下标 $2 \to 3$） | $p = 2$，因 $d[1]=1 < d[2]=3$ | $1129$ |
| $10$ | $1 > 0$（下标 $0 \to 1$） | $p = 0$（最高位借位） | `"09"` → $9$ |
| $1234$ | 无下降 | 不进入修改分支 | $1234$ |

以 $n = 1130$ 为例：$d = [1,1,3,0]$，第一处下降在 $3 > 0$，$p$ 初值为 $2$；检查 $d[1] = 1 \ne d[2] = 3$，不需要左移；于是 $d[2] \leftarrow 2$、$d[3] \leftarrow 9$，得到 $1129$。验算：$1129 \le 1130$ 且 $1 \le 1 \le 2 \le 9$；而任何 $1,1,3,x$ 形式的数都 $\ge 1130$，且 $1130$ 自身不单调，所以 $1131 \sim 1139$ 不能选，$1129$ 就是最优。

## 4. 算法细节

1. **用字符串而不是取模**：`to_string(n)` 后可以随机访问任意一位，也天然避开前导零问题；取模拆位需要额外反转数组，且末尾补 9 时要重新做幂运算。
2. **$i$ 的语义**：$i$ 是「第一处下降区间」的**右端**下标，完成 Step 2 后必有 $d[0..i-1]$ 非降、$d[i-1] > d[i]$，所以借位位置必然落在 $[0, i-1]$。
3. **左移条件用 `==` 而不是 `<=`**：进入 Step 3 时前缀 $d[0..i-1]$ 已非降，所以 $d[p-1]$ 只可能等于或小于 $d[p]$；小于时无需左移，等于时才需要继续借位。写成 `d[p-1] >= d[p]` 在同值情况下等价，但语义不如 `==` 清晰。
4. **借位不会下溢**：若 $p = 0$，由 $d[0..i-1]$ 非降且 $d[i-1] > d[i] \ge 0$ 可知 $d[0] \ge 1$；若 $p > 0$，同理 $d[p] \ge d[0] \ge 1$。因此 $d[p] \ge \text{'1'}$，减 1 后最小是 `'0'`，不会出现负数字符。
5. **前导零交给 `stoi` / `int()`**：$n = 10$ 时结果是 `"09"`，$n = 100$ 时是 `"099"`，转整数后自然丢掉前导零，位数随之减少——这正是正确答案（$9$、$99$）。
6. **结果范围**：$n \le 10^9$ 时 $m \le 10$，答案最大为 $999999999$，仍在 32 位 `int` 范围内；`stoi` 不会溢出，无需 `long long`。
7. **只需要处理一次借位链**：借位只会发生在一个数字块的最左端，且之后不再需要回看（前缀被证明非降）。因此「向左收缩」只要用 `while` 走一遍相同数字块即可，不必反复扫描整个数组。

## 5. 正确性证明

设 $n$ 的数位为 $d[0..m-1]$，记 $m$ 位数字串 $s$ 对应的数值为 $\mathrm{val}(s)$。

**引理 1（形态引理）**：若 $y \le n$ 且 $y$ 单调递增，$y \ne n$，则存在 $p \in [0, m-1]$ 使 $y$ 与 $n$ 的前 $p$ 位相同、$y[p] < d[p]$，且把 $y[p+1..m-1]$ 全部改成 $9$ 后得到的 $y'$ 仍满足 $y' \le n$、$y'$ 单调、$y' \ge y$。

**证明**：取 $p$ 为 $y$ 与 $n$ 首个不同的位置（$y \ne n$ 且位数相同时必存在；若 $y$ 位数更少，可高位补 0 后同样处理）。由 $y \le n$ 与首位不同处的比较得 $y[p] < d[p]$，前缀相同。

构造 $y'$：前 $p$ 位与 $y$ 相同，第 $p$ 位仍为 $y[p]$，其后全为 $9$。与 $n$ 比较时前 $p$ 位相同、第 $p$ 位 $y[p] < d[p]$，故 $y' < n$，即 $y' \le n$。单调性：前缀已是 $y$ 的前缀，故非降；$y[p] \le 9$ 且后面全是 $9$，故整体非降。又因为 $y$ 的第 $p$ 位之后每一位都 $\le 9$，逐位比较得 $y' \ge y$。∎

**引理 2（可行判据）**：位置 $p$ 上存在「前 $p$ 位同 $n$、第 $p$ 位小于 $d[p]$、其后全 9」的单调数 $\iff$ $d[0..p-1]$ 非降且（$p = 0$ 或 $d[p-1] < d[p]$）。

**证明**：

- ($\Leftarrow$) 令 $y'$ 为 $d[0..p-1]$、$d[p]-1$、$9\cdots9$。前缀非降；$d[p]-1 \ge d[p-1]$ 保证第 $p-1$ 到第 $p$ 位不降；后面全 9 显然不降，故单调。又第 $p$ 位 $d[p]-1 < d[p]$，故 $y' < n$。
- ($\Rightarrow$) 设这样的单调数 $y'$ 存在，$y'[p] \le d[p]-1$。前缀与 $n$ 相同故非降；单调性给出 $d[p-1] = y'[p-1] \le y'[p] \le d[p]-1 < d[p]$（$p = 0$ 时无此要求）。∎

**引理 3（最优位置单调）**：设 $p < p'$ 都是可行位置，则 $V(p') > V(p)$，其中 $V(p)$ 表示引理 2 中构造的数值。

**证明**：两者前 $p$ 位都与 $d$ 相同，第 $p$ 位上 $V(p)$ 的 digit 是 $d[p]-1$，而 $V(p')$ 保持 $d[p]$（因 $p' > p$），故 $V(p') > V(p)$。∎

**引理 4（算法求出的 $p$ 是最右可行位置）**：设 $i$ 为第一处下降的右端下标，则算法输出的 $p$ 等于 $\max\{q \in [0, i-1] : q = 0 \text{ 或 } d[q-1] < d[q]\}$。

**证明**：由引理 2，可行位置都满足前缀 $d[0..q-1]$ 非降；而第一处下降是 $d[i-1] > d[i]$，故前缀非降只可能对 $q \le i$ 成立。$q = i$ 又被引理 2 的第二个条件排除（$d[i-1] > d[i]$，不满足 $d[i-1] < d[i]$），所以可行集合含于 $[0, i-1]$。在 $[0, i-1]$ 上前缀都非降，因此「$q$ 不可行」（$q \ge 1$）$\iff d[q-1] = d[q]$。算法从 $q = i-1$ 起，只要 $d[q-1] = d[q]$ 就左移，停在第一个满足 $q = 0$ 或 $d[q-1] < d[q]$ 的位置：停下的 $q$ 可行，而被跨过的每个 $q' \in (q, i-1]$ 都满足 $d[q'-1] = d[q']$、不可行，故 $q$ 是最大可行位置。∎

**定理**：算法返回的整数是「不超过 $n$ 的最大单调递增数」。

**证明**：若 $d$ 非降，$n$ 本身单调且不超过 $n$，算法返回 $n$，正确。否则设第一处下降的右端为 $i$。由引理 2，$p = 0$ 是可行位置（$d[0] \ge 1$，否则 $d[0..i-1]$ 全为 0 与 $d[i-1] > d[i]$ 矛盾），故可行集非空；由引理 4 算法取到其中最大者 $p^{*}$，输出 $V(p^{*})$。

任取单调数 $y \le n$：若 $y = n$ 则 $d$ 非降，不符合本分支；于是由引理 1 可把 $y$ 放大到形态 $\mathrm{val}(d[0..p-1]\,(d[p]-1)\,9\cdots)$ 且仍 $\le n$、单调，其中 $p$ 由引理 2 可行，故 $y$ 不超过这一族的最大值。由引理 3，该族最大值即 $V(p^{*})$。因此 $y \le V(p^{*})$，算法输出最优。∎

## 6. 复杂度分析

- **时间**：$O(m)$，其中 $m = \lfloor \log_{10} n \rfloor + 1 \le 10$ 为位数。Step 2 的指针 $i$ 单调右移，Step 3 的指针 $p$ 单调左移，两趟合计每条数位最多访问常数次；填 9 一趟 $O(m)$。总计 $O(\log n)$，常数极小。
- **空间**：$O(m)$，仅一个长度 $m$ 的字符串（数位数组），无额外数组或递归栈。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int monotoneIncreasingDigits(int n) {
        string s = to_string(n);
        int m = (int)s.size();

        // Step 1: 找到第一处下降 d[i-1] > d[i] 的右端下标 i
        int i = 1;
        while (i < m && s[i - 1] <= s[i]) ++i;
        if (i == m) return n;                  // 本身就是单调递增

        // Step 2: 向左跨过与 s[p] 相同的数字块
        int p = i - 1;
        while (p > 0 && s[p - 1] == s[p]) --p;

        // Step 3: 该位借 1，其后全部填 9
        --s[p];
        for (int k = p + 1; k < m; ++k) s[k] = '9';

        return stoi(s);                        // "09" 之类的前导零自动丢掉
    }
};
```

### Python

```python
class Solution:
    def monotoneIncreasingDigits(self, n: int) -> int:
        d = list(str(n))
        m = len(d)

        # Step 1: 第一处下降 d[i-1] > d[i] 的右端下标
        i = 1
        while i < m and d[i - 1] <= d[i]:
            i += 1
        if i == m:                      # 已经单调递增
            return n

        # Step 2: 向左跨过与 d[p] 相同的数字块
        p = i - 1
        while p > 0 and d[p - 1] == d[p]:
            p -= 1

        # Step 3: 该位借 1，其后全部填 9
        d[p] = str(int(d[p]) - 1)
        for k in range(p + 1, m):
            d[k] = '9'

        return int(''.join(d))          # 前导零在这里被丢掉
```

## 8. 边界情况与易错点

1. **本身已单调**（$1234$、$999$）：必须原样返回，任何借位都会让答案变小。忘记 `if (i == m) return n` 会得到 $1233$ 之类的错误结果。
2. **一位数**（$0 \sim 9$）：$m = 1$，Step 1 的循环不执行、$i = m$，直接返回 $n$，不能因为「没有下降对」而误判。
3. **借位后出现前导零**：$10 \to$ `"09"`、$100 \to$ `"099"`，必须转成整数（$\to 9$、$\to 99$），若按字符串比较或直接返回字符串会得到答案位数错误的结果。
4. **上界是 $10^9$ 而不是 $10^9-1$**：$n = 10^9$（$10$ 位数）的答案是 $999999999$，结果仍在 `int` 范围内；但若把上界写成 $10^{18}$ 就必须用 `long long` / `int64`。
5. **相等的数字块**（$332$、$221$、$1110$）：只减第一处下降的左邻位会留下新的下降（$332 \to 322$），必须一路左移到相同数字块的最左端；这里的判断是 `==`，不是 `<=`。
6. **不能对每处下降都减 1**：如果简单地「从右往左，遇到 $d[i-1] > d[i]$ 就把 $d[i-1]$ 减 1」，$332$ 会被一路减成 $222$（正确答案是 $299$）——多借的高位白白损失了数值。真正的解只在最左端借**一次**位，其后全部填 9。
7. **Python 的 `d[p - 1] == d[p]` 与 `p > 0` 顺序**：`and` 短路必须把 `p > 0` 放在前面，否则 $p = 0$ 时会访问 `d[-1]` 形成环形下标，逻辑静默出错（不报错，更难查）。
