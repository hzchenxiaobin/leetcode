# LeetCode 每日温度 题解

## 1. 题目概述

- **标题 / 题号**：每日温度（#739，medium）
- **链接**：https://leetcode.cn/problems/daily-temperatures/
- **来源**：LeetCode 第 61 场周赛 Q1
- **难度**：中等
- **标签**：栈、数组、单调栈

**题意**：给定长度为 $n$ 的温度数组 `temperatures`，对每一天 $i$ 求「还要等几天才会更暖」，即

$$\text{answer}[i] = \min\{\,j - i \mid j > i,\ \text{temperatures}[j] > \text{temperatures}[i]\,\}$$

若右侧不存在更高的温度，则 $\text{answer}[i] = 0$。返回整个 `answer` 数组。

**约束**：

- $1 \le \text{temperatures.length} \le 10^5$
- $30 \le \text{temperatures}[i] \le 100$

数据规模决定了 $O(n^2)$ 不可行；而温度值域只有 $71$ 个整数，这个「小值域」也正是第二条思路（按温度记最近位置）的入口。

## 2. 示例

**示例 1**

```text
输入：temperatures = [73,74,75,71,69,72,76,73]
输出：[1,1,4,2,1,1,0,0]
解释：第 0 天 73°，第 1 天 74° 更暖 → 1；
      第 2 天 75°，要等到第 6 天 76° → 4；
      第 6 天 76° 是最大值，第 7 天 73° 之后再无日子 → 分别是 0、0。
```

**示例 2**

```text
输入：temperatures = [30,40,50,60]
输出：[1,1,1,0]
解释：温度严格递增，每天都由紧接着的下一天回答；最后一天无处可等 → 0。
```

**示例 3**

```text
输入：temperatures = [30,60,90]
输出：[1,1,0]
解释：与示例 2 同理，跨度变大但不影响「相邻即答案」。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 向右线性扫描，找到第一个大于 `temperatures[i]` 的位置。单次最坏 $O(n)$，总计 $O(n^2)$。

$n = 10^5$ 时最坏约 $5 \times 10^9$ 次比较，必然超时。退化的输入很容易构造：温度**单调不增**（如 `[100, 99, 98, ...]`）时每个 $i$ 都要扫到末尾才发现「没有更暖的日子」。

一个能过大测试但不够通用的改进：因为 $T[i] \in [30,100]$，可从右往左扫描，维护 `nxt[v]` = 值恰好为 $v$ 的温度**最近一次出现的下标**，则

$$\text{answer}[i] = \min_{v > T[i]} \text{nxt}[v] - i$$

时间 $O(71n) \approx 7 \times 10^6$，能过。但它依赖「值域很小」这个额外条件；下面给出不依赖值域、且更本质的 $O(n)$ 解法。

### 3.2 核心观察：一条递减栈就够了

![递减栈：栈里只留还没等到更暖日子的下标](images/wc61_q1_monotonic_stack.svg)

关键转换视角：与其「为每一天向右找答案」，不如「让每一天去回答它左边那些**还在等**的日子」。

维护一个栈，里面只存**下标**，含义是「这些天还没等到更暖的日子」。它满足两条不变式：

1. 下标自底向顶**严格递增**（因为按下标顺序入栈）；
2. 温度自底向顶**非递增**（新下标入栈前会把所有比它冷的栈顶弹走，剩下的栈顶必然不比它冷）。

当扫描到第 $i$ 天、温度为 $t$ 时：

- 若栈顶的温度 $< t$，那么**今天就是栈顶那一天等待的终点**——而且是最早的终点（栈顶下标最大，且此前每一天都没能弹走它）。于是弹出栈顶 $j$，写 $\text{answer}[j] = i - j$；
- 弹完一层后新的栈顶温度可能仍 $< t$，说明今天同时是它的答案，于是**继续弹**，形成级联结算；
- 直到栈空或栈顶温度 $\ge t$，把 $i$ 压栈，它开始等待。

一句话：**栈维护一条「温度递减的待办清单」，今天能结算多少就结算多少**。

### 3.3 算法流程

![算法流程：一次线性扫描加一个递减栈](images/wc61_q1_algorithm_flow.svg)

```text
ans ← 长度 n 的全 0 数组
stack ← 空栈（存下标）
for i = 0 to n-1:
    t ← temperatures[i]
    while stack 非空 且 temperatures[stack.top] < t:
        j ← stack.pop()
        ans[j] ← i - j          # 弹出即结算，i 是 j 右侧第一个更暖的日子
    stack.push(i)
return ans
```

注意 `while` 与 `push` 的次序：**先把能结算的都结算完，再把 i 自己入栈**。若先 `push(i)`，自己会被自己弹出（$\text{temperatures}[i] < \text{temperatures}[i]$ 为假时侥幸不死，但循环条件一旦写成 $\le$ 就会自弹），逻辑立刻错乱。

### 3.4 示例演算

![示例 1 的逐步演算表](images/wc61_q1_walkthrough.svg)

以示例 1 为例，逐日走查（表中「弹出 j」列即该步结算的下标）：

| $i$ | $T[i]$ | 动作 | 结算 | 栈（底→顶） |
|-----|--------|------|------|-------------|
| 0 | 73 | 压栈 | — | `[0]` |
| 1 | 74 | 弹 0 后压栈 | `ans[0]=1` | `[1]` |
| 2 | 75 | 弹 1 后压栈 | `ans[1]=1` | `[2]` |
| 3 | 71 | 压栈 | — | `[2,3]` |
| 4 | 69 | 压栈 | — | `[2,3,4]` |
| 5 | 72 | 弹 4、弹 3，压 5 | `ans[4]=1`、`ans[3]=2` | `[2,5]` |
| 6 | 76 | 弹 5、弹 2，压 6 | `ans[5]=1`、`ans[2]=4` | `[6]` |
| 7 | 73 | 压栈 | — | `[6,7]` |

遍历结束时栈中残留 `6`、`7`，它们右侧没有更暖的日子，`ans` 保持初值 0，得到 `[1,1,4,2,1,1,0,0]`，与官方输出一致。

值得单独看 $i = 5$：栈里同时积压了下标 2、3、4（温度 75°、71°、69°）三天的「待办」，72° 一天之内结算了其中两个（69° 等 1 天、71° 等 2 天），而 75° 比 72° 高，只能继续等待——这正是级联弹出与提前停止的组合。

## 4. 算法细节

1. **栈里存下标，不存温度**。答案要的是天数差 `i - j`，只存温度就丢掉了位置信息；若同时存二元组，反而多一次打包开销。
2. **弹出条件是严格小于** $\text{temperatures}[\text{top}] < t$。题目要求「更高」的温度，相等不算。写成 $\le$ 会让 `[60,60,60]` 这类输入全部错误地互相结算。
3. **`ans` 初始化为全 0**，于是「右侧没有更暖的日子」这一情形**天然被覆盖**，无需在循环后再扫一遍栈补 0。
4. **每个下标恰好入栈一次、出栈至多一次**，`while` 的总执行次数被入栈次数所限，因此均摊 $O(n)$——虽然代码是双层循环，但总代价是线性的。
5. **顺序：先 while 后 push**。这是本题唯一的顺序陷阱，写成 `push` 在前会引入自比较问题。
6. **`stack` 用数组/`vector` 实现**即可（只需 `push_back`/`pop_back`/`back`），不要用 `std::stack`——它默认基于 `deque`，常数更大且不能 `reserve`。
7. **值域小时可换桶**：若面试官追问「不用栈怎么做」，可答 3.1 中按温度维护「最近出现下标」的数组法，时间 $O((\max T - \min T)\,n)$，空间 $O(\max T)$。

## 5. 正确性证明

**引理 1（栈不变式）**：在任意时刻（每轮 `push` 之后），栈中下标自底向顶严格递增，且对应温度自底向顶非递增。

**证明**：对轮数归纳。初始空栈成立。设第 $i$ 轮开始前不变式成立；`while` 循环只从栈顶删除元素，剩余部分的下标递增性与温度非递增性都保持。循环终止时或栈空，或 $\text{temperatures}[\text{top}] \ge t$，此时把 $i$ 压栈：$i$ 大于栈中所有下标（它们都 $< i$），且 $\text{temperatures}[i] = t \le \text{temperatures}[\text{top}]$，两条性质均延续。∎

**引理 2（弹出即最近）**：若下标 $j$ 在第 $i$ 轮被弹出，则 $i$ 是 $j$ 右侧**第一个**温度更高的日子。

**证明**：由弹出条件 $\text{temperatures}[j] < \text{temperatures}[i]$ 且 $j < i$，$i$ 是一个合法候选。反设存在 $k$ 使 $j < k < i$ 且 $\text{temperatures}[k] > \text{temperatures}[j]$。$j$ 直到第 $i$ 轮才被弹出，说明它在第 $k$ 轮结束时仍在栈中；由引理 1，栈顶是栈内温度最小者，故

$$\text{temperatures}[j] \ge \text{temperatures}[\text{top}] \ge \text{temperatures}[k]$$

（第二个不等号来自第 $k$ 轮 `while` 的终止条件），与 $\text{temperatures}[k] > \text{temperatures}[j]$ 矛盾。∎

**引理 3（残留即无解）**：若下标 $j$ 在遍历结束时仍留在栈中，则 $j$ 右侧不存在更暖的日子。

**证明**：反设存在 $k > j$ 且 $\text{temperatures}[k] > \text{temperatures}[j]$，取其中最小的 $k$。对任意 $j < m < k$，由 $k$ 的最小性有 $\text{temperatures}[m] \le \text{temperatures}[j] < \text{temperatures}[k]$。第 $k$ 轮开始时栈中位于 $j$ 之上的元素，其下标都在 $(j, k)$ 内（它们晚于 $j$ 入栈且尚未弹出），温度都 $\le \text{temperatures}[j] < \text{temperatures}[k]$，于是 `while` 循环会先把它们逐个弹出，再弹出 $j$，与「$j$ 仍在栈中」矛盾。∎

**定理**：算法输出的 `answer` 与定义一致。

**证明**：对每个下标 $j$ 分两种情形。若 $j$ 被弹出，由引理 2 弹它的那一刻 $i$ 恰是 $j$ 右侧第一个更暖的日子，$\text{answer}[j] = i - j$ 正确；由引理 1 的递增性，每个下标至多被弹出一次，答案不会被覆盖。若 $j$ 未被弹出，由引理 3 右侧无更暖日子，$\text{answer}[j]$ 保持 0，正确。故全部位置正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层循环 $n$ 次；内层 `while` 每次弹出一个下标，而每个下标最多入栈一次、出栈一次，故 `while` 体总执行次数 $\le n$。均摊到外层，单次操作 $O(1)$。
- **空间**：$O(n)$。`ans` 数组 $n$ 个整数；栈最坏情形（温度单调不增）压入全部 $n$ 个下标，同为 $O(n)$。除输入输出外无其他与 $n$ 相关的辅助空间。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n, 0);
        vector<int> st;                       // 存下标，温度自底向顶非递增
        st.reserve(n);
        for (int i = 0; i < n; i++) {
            while (!st.empty() && temperatures[st.back()] < temperatures[i]) {
                int j = st.back();
                st.pop_back();
                ans[j] = i - j;               // i 是 j 右侧第一个更暖的日子
            }
            st.push_back(i);                  // 结算完才把自己入栈
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def dailyTemperatures(self, temperatures: list[int]) -> list[int]:
        n = len(temperatures)
        ans = [0] * n
        stack = []                       # 存下标，温度自底向顶非递增
        for i, t in enumerate(temperatures):
            while stack and temperatures[stack[-1]] < t:
                j = stack.pop()
                ans[j] = i - j           # i 是 j 右侧第一个更暖的日子
            stack.append(i)              # 结算完才把自己入栈
        return ans
```

## 8. 边界情况与易错点

1. **相等温度不算更暖**：`[60,60,60]` 应输出 `[0,0,0]`。把判定写成 `<=` 是本题最常见的 WA。
2. **没有更暖的日子**：`[76,73,72]` 输出 `[0,0,0]`。依赖 `ans` 初值为 0 即可，切勿忘记初始化。
3. **$n = 1$**：`[50]` 输出 `[0]`，循环正常走完、栈中残留一个下标，无需特判。
4. **严格单调递增**：`[30,40,50,60]` 每一步都弹空栈，栈的最大深度为 1，答案全为 1（末位 0）。
5. **严格单调递减**：`[100,99,98]` 全程只压不弹，栈深度达到 $n$，是空间与「残留即无解」逻辑的极端用例。
6. **空栈判断必须先于取栈顶**：`stack and temperatures[stack[-1]] < t` 中两条件的顺序不能交换，否则空列表 `stack[-1]` 抛 `IndexError`。
7. **多个下标在同一天结算**：如示例 1 的 $i = 6$ 一次弹掉两个下标，`ans` 必须逐个写入，不能「只弹一个」或「只记天数不记下标」。

**延伸思考**：若把问题改成「求所有 `answer[i]` 之和」，$O(n)$ 的单调栈依旧适用，但按温度桶的 $O(71n)$ 做法同样能求和——对照两者在「值域极大」（如 $10^{18}$）时的表现：桶法直接失效，单调栈不受影响，这正是「复杂度与值域解耦」的价值。

一个**看似自然却错误**的推广：若要求「下一个比 `temperatures[i]` 至少高 $k$ 度」的日子，把弹出条件改成 `temperatures[top] + k < t` 是**行不通**的。反例取 $k = 3$、`[10, 12, 14]`：第 2 天 14° 到来时，栈内为 `[10, 12]`，栈顶 $12 + 3 = 15 \ge 14$，循环提前停下，下标 0 永远得不到本应属于它的答案 2；根因是改判定后栈内温度**不再非递增**，$12$ 挡住了本应结算的 $10$，引理 1 与引理 2 同时失效。正确做法是离线：把所有下标按 `temperatures` 从高到低加入一棵「位置线段树」（叶存下标本身，内部取 $\min$），对每个 $i$ 先加入所有温度 $> \text{temperatures}[i] + k$ 的位置，再查询区间 $(i, n)$ 的最小下标，总复杂度 $O(n \log n)$。
