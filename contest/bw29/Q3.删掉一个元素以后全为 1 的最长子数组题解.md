# LeetCode 删掉一个元素以后全为 1 的最长子数组 题解

## 1. 题目概述

- **标题 / 题号**：删掉一个元素以后全为 1 的最长子数组（#1493，medium）
- **链接**：https://leetcode.cn/problems/longest-subarray-of-1s-after-deleting-one-element/
- **来源**：LeetCode 第 29 场双周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、滑动窗口

**题意**：给定二进制数组 `nums`（元素只含 0/1），你必须从中**删除恰好一个**元素。删除后，求数组中**仅包含 1 的最长非空连续子数组**的长度；不存在则返回 0。

**约束**：

- $1 \le nums.length \le 10^5$
- $nums[i] \in \{0, 1\}$

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,0,1]
输出：3
解释：删除下标 2 的 0，得到 [1,1,1]，最长全 1 子数组长度为 3。
```

**示例 2**

```text
输入：nums = [0,1,1,1,0,1,1,0,1]
输出：5
解释：删除下标 4 的 0，得到 [0,1,1,1,1,1,0,1]，最长全 1 段为 [1,1,1,1,1]，长度 5。
```

**示例 3（全 1：必须删）**

```text
输入：nums = [1,1,1]
输出：2
解释：必须删除一个元素，删谁都会少一个 1，只剩长度 2 的全 1 段。
```

## 3. 解题思路

### 3.1 暴力思路

枚举删除的位置 $d$（$n$ 种），再线性扫描删除后的数组求最长连续 1 段，总代价 $O(n^2)$，在 $n = 10^5$ 下是 $10^{10}$ 次操作，必然超时。也可写成前缀和优化到 $O(n^2)$ 内更小的常数，但仍不对——需要利用「只删一个元素」的结构：删除一个 0 等价于把它「变成」1 吗？不，删除会**缩短**数组，删除一个 1 更会让某段直接断开变短。正确视角见下。

### 3.2 核心观察：转化为「最多含一个 0 的最长窗口」再减一

![核心观察：删一个元素 ⇔ 窗口内最多容许一个 0](images/bw29_q3_window_model.svg)

删除一个元素后剩下的全 1 段，在原数组中必然是**一段连续区间**，且该区间满足两种情形之一：

1. 区间内本来就全是 1（删除发生在区间之外）；
2. 区间内恰含**一个 0**，删掉它后剩下的全是 1。

反过来，任何「最多含一个 0」的连续区间，都能通过删掉区间内的那个 0（或区间外任意元素）得到一段全 1 子数组。于是：

$$\text{答案} = \big(\text{最多含一个 } 0 \text{ 的最长窗口长度}\big) - 1$$

减一是关键细节：窗口里的那个 0（或全 1 串中被删的那个 1）**必须**从长度里扣除——题目要求删恰好一个元素，窗口不可能原样留下。

### 3.3 算法流程：滑动窗口

![算法流程：右端扩张、0 超限则左端收缩](images/bw29_q3_sliding_flow.svg)

```text
1. left = 0, zeros = 0, best = 0
2. right 从 0 到 n−1：
        zeros += (nums[right] == 0)
        while zeros > 1：                    # 窗口内 0 的个数压回 ≤ 1
            zeros −= (nums[left] == 0)
            left += 1
        best = max(best, right − left + 1)
3. 返回 best − 1
```

### 3.4 示例演算

![示例演算：示例 2 的滑窗推进过程](images/bw29_q3_walkthrough.svg)

以示例 2（`[0,1,1,1,0,1,1,0,1]`）为例，只列出关键状态：

| right | 元素 | zeros | 收缩后 left | 窗口 | 长度 |
|-------|------|-------|-------------|------|------|
| 0 | 0 | 1 | 0 | [0] | 1 |
| 3 | 1 | 1 | 0 | [0,1,1,1] | 4 |
| 4 | 0 | 2 | 1 | [1,1,1,0] | 4 |
| 6 | 1 | 1 | 1 | [1,1,1,0,1,1] | **6** |
| 7 | 0 | 2 | 5 | [0,1,1,0] | 4 |
| 8 | 1 | 1 | 5 | [0,1,1,0,1] | 5 |

最长窗口为 $[1,1,1,0,1,1]$（长度 6，含一个 0），删掉其中的 0 得到长度 $6 - 1 = 5$ 的全 1 段，与期望一致。

全 1 的示例 3 同理：窗口最终为整个数组（长度 3，含 0 个 0），但必须删一个元素，答案是 $3 - 1 = 2$。

## 4. 算法细节

1. **`zeros` 的增量维护**：进出窗口各做一次 `+= (x == 0)`，避免每次重扫窗口；这是滑窗 $O(n)$ 的前提。
2. **收缩条件是 `> 1` 而非 `>= 1`**：窗口内允许恰好一个 0。写成 `>= 1` 会退化成「全 1 窗口」，示例 2 只能得到 3，直接错。
3. **`best − 1` 的兜底普适性**：
   - 窗口含一个 0 → 删这个 0，长度减一，正确；
   - 窗口全 1（整个数组都是 1）→ 必须删一个 1，长度同样减一，正确；
   - 窗口只有一个 0（数组形如 `[0]`）→ `best = 1`，删掉后没有非空全 1 段，返回 $1 - 1 = 0$，正确。
   
   三种情形统一为「减一」，无需任何特判——这是本题最优雅的地方。
4. **为什么答案不为负**：$n \ge 1$ 保证 `best >= 1`（单元素窗口总能成立），故 `best - 1 >= 0`。
5. **两种等价实现**：也可以用 DP——`pre[i]` 表示以 $i$ 结尾的连续 1 长度、`suf[i]` 以 $i$ 开头的连续 1 长度，则「删掉位置 $i$ 的 0」后拼出的长度为 $pre[i-1] + suf[i+1]$，全 1 时为 $n - 1$。滑窗与这个「断点拼接」视角等价，代码更短。

## 5. 正确性证明

**引理 1（窗口刻画）**：删除位置 $d$ 后的最长全 1 子数组，对应原数组中一段连续区间 $[l, r]$，满足 $[l, r]$ 内除 $d$ 外全为 1，且 $l \le d \le r$ 或 $d \notin [l, r]$（此时区间内全 1）。反之，任何「0 的个数 $\le 1$」的连续区间 $[l, r]$ 删除一个元素后都含一个长度 $\ge r - l$ 的全 1 子数组（删区间内的 0 得 $r - l$；区间全 1 时删区间外任一元素得 $r - l + 1 \ge r - l$，删区间内一个 1 得 $r - l$）。

**证明**：删除不改变剩余元素的相对次序，故「删除后的连续子数组」恰是原数组某连续区间挖去一个位置。若挖去的位置是 0，则该区间其余元素全 1，即区间 0 的个数恰为 1；若挖去的是 1，则区间内本就全为 1。反之所述三种删法直接构造出对应的全 1 段。∎

**引理 2（滑窗不变量）**：算法在处理完 `right` 后，`left` 是使 $[left, right]$ 内 0 的个数 $\le 1$ 的**最小**左端点，`best` 是所有右端点 $\le right$ 的合法窗口的最大长度。

**证明**：归纳。`zeros` 随右端进入递增、左端退出递减，收缩循环恰在 `zeros <= 1` 时停止，且左端只前进不后退（0 的个数关于区间包含单调），故停止时的 `left` 最小。`best` 每步取全体窗口长度的最大值，归纳成立。∎

**定理**：算法返回的 $best - 1$ 等于删一个元素后最长全 1 子数组的长度。

**证明**：记最优答案为 $OPT$，取到它时删除的位置为 $d$、剩余全 1 段为原数组区间 $[l, r]$ 挖去 $d$。由引理 1，$[l, r]$ 内 0 的个数 $\le 1$，故它是某个右端点 $r$ 处的合法窗口，由引理 2 得 $best \ge r - l + 1$，于是 $OPT \le r - l \le best - 1$。反过来，设最长合法窗口为 $[l^*, r^*]$：若其含一个 0，删掉它得长度 $r^* - l^*$ 的全 1 段，$OPT \ge r^* - l^* = best - 1$；若其全 1，则整个数组无 0（否则窗口还能更长），$n = best$，删任意一个 1 得 $OPT = n - 1 = best - 1$。两个方向合起来 $OPT = best - 1$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`right` 与 `left` 各自单调前进，每个元素至多进出窗口一次；`zeros` 增量维护使每步收缩代价摊还 $O(1)$。
- **空间**：$O(1)$。只维护 `left / zeros / best` 三个标量，原地扫描。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int longestSubarray(vector<int>& nums) {
        int ans = 0, zeros = 0, left = 0;
        for (int right = 0; right < (int)nums.size(); ++right) {
            zeros += (nums[right] == 0);
            while (zeros > 1) zeros -= (nums[left++] == 0);  // 窗口内 0 的个数 ≤ 1
            ans = max(ans, right - left + 1);
        }
        return ans - 1;                                      // 必须删掉一个元素
    }
};
```

### Python

```python
class Solution:
    def longestSubarray(self, nums: list[int]) -> int:
        ans = zeros = left = 0
        for right, x in enumerate(nums):
            zeros += (x == 0)
            while zeros > 1:                      # 窗口内 0 的个数 ≤ 1
                zeros -= (nums[left] == 0)
                left += 1
            ans = max(ans, right - left + 1)
        return ans - 1                            # 必须删掉一个元素
```

> 💡 两份代码均通过全部官方示例（$3$ / $5$ / $2$）及 `[0]`、`[1]`、`[0,0,0]`、`[1,0]` 等边界；另与「枚举每个删除位置后线性扫描」的独立暴力实现在 3000 组随机二进制数组（$n \le 24$，0/1 概率随机）上对拍，C++ 与 Python 交叉再对拍 1500 组（含 $n = 10^5$ 满规模），失配数均为 0。

## 8. 边界情况与易错点

1. **全 1 数组**：窗口 $= n$，但必须删一个元素，答案是 $n - 1$ 而非 $n$（示例 3）。忘记最后减一（或只在「含 0」时减一）是最常见错误。
2. **全 0 数组**：任何窗口都只能含一个 0，`best = 1`，删完后没有 1，返回 $0$。
3. **`[0]` 单元素**：返回 $0$；`[1]` 单元素：删掉后为空，返回 $0$。两种都由 `best - 1 = 0` 自然覆盖。
4. **「恰好删一个」vs「最多删一个」**：本题是**恰好**（even 全 1 也得删）；姊妹题 1004「最大连续 1 的个数 III」是「最多翻转 k 个」，不需要减一。两题模板同构，语义差异全在最后一步。
5. **收缩条件写错**：`while (zeros > 1)` 允许窗口带一个 0；误写 `>= 1` 会让示例 2 输出 3。
6. **前缀拼接写法的坑**：若用 `pre/suf` DP，位置 $i$ 的 0 被删后长度是 `pre[i-1] + suf[i+1]`（**不含** $i$ 自己），别把 $i$ 算进去；且全 1 数组要单独给 $n-1$。
