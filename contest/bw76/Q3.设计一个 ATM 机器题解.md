# LeetCode 设计一个 ATM 机器 题解

## 1. 题目概述

- **标题 / 题号**：设计一个 ATM 机器（#2241，medium）
- **链接**：https://leetcode.cn/problems/design-an-atm-machine/
- **来源**：LeetCode 第 76 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、设计、数组

**题意**：ATM 机器存有 $20, 50, 100, 200, 500$ 五种面值的钞票，初始为空。支持两种操作：

- `deposit(banknotesCount)`：按面值顺序（20 → 500）存入对应数量的钞票；
- `withdraw(amount)`：按**优先取较大面额**的规则取款。若能恰好取出 `amount`，返回长度 5 的取款张数数组并**扣减库存**；否则返回 `[-1]` 且**不取出任何钞票**（机器状态不变）。

**约束**：

- $banknotesCount.length == 5$，$0 \le banknotesCount[i] \le 10^9$
- $1 \le amount \le 10^9$
- 最多 5000 次 `withdraw` / `deposit` 调用，两操作各至少一次

**注意**：单次存款张数可达 $10^9$，5 种面额库存总值可达 $5 \times 10^9 \times$ 面值，**必须用 64 位整数存库存**。

## 2. 示例

**示例 1**

```text
输入：
["ATM", "deposit", "withdraw", "deposit", "withdraw", "withdraw"]
[[], [[0,0,1,2,1]], [600], [[0,1,0,1,1]], [600], [550]]
输出：[null, null, [0,0,1,0,1], null, [-1], [0,1,0,0,1]]

解释：
- deposit([0,0,1,2,1]) 后库存 [0,0,1,2,1]；
- withdraw(600)：贪心取 500×1（余 100）+ 200×0 + 100×1（余 0）→ [0,0,1,0,1]，库存变 [0,0,0,2,0]；
- deposit([0,1,0,1,1]) 后库存 [0,1,0,3,1]；
- withdraw(600)：贪心取 500×1（余 100），但 200/100 无货、50 只有 1 张、20 无货 → 余 50 ≠ 0，返回 [-1]，库存不变；
- withdraw(550)：500×1（余 50）+ 50×1（余 0）→ [0,1,0,0,1]。
```

**示例 2（边界补充）**

[[], [[10,10,10,10,10]], [1370]]
输出：[null, null, [1,1,1,1,2]]
解释：贪心先取 500×2（余 370），再 200×1（余 170）、100×1（余 70）、

## 3. 解题思路

### 3.1 暴力思路

每次取款枚举钞票组合（5 维张数循环）或逐张模拟取出——取款额 $10^9$、单面额张数 $10^9$，逐张模拟最坏 $5 \times 10^9$ 步，组合枚举更不可行。正确做法是**贪心**：题目明确规定「优先取较大数额」，取法是唯一确定的，不存在搜索空间。

### 3.2 核心观察：贪心取法唯一，关键是「先试算、后扣账」

![贪心找零流程](images/bw76_q3_greedy_flow.svg)

从 $500$ 到 $20$ 依次处理：每个面额取

$$take_i = \min\left(cnt_i,\; \left\lfloor \frac{rest}{val_i} \right\rfloor\right), \qquad rest \leftarrow rest - take_i \times val_i$$

五个面额处理完后，若 $rest = 0$ 则成功，否则失败返回 $[-1]$。

> ⚠️ **本题贪心 ≠ 可行性判定**。示例 1 的第二次 `withdraw(600)` 中，库存里明明有 $200 \times 3 = 600$ 可以凑出，但机器规定先取 500；贪心取走 500 后剩余 100 无法凑出，**必须拒绝**，不允许「回退改用 3 张 200」。这正是题面示例特意强调的行为，读题时务必注意。

**失败时的回滚**：题目要求拒绝请求时「不取出任何钞票」。最稳的实现是**先用临时数组 `take` 试算、验证 `rest == 0` 后才真正扣减库存**——先算后扣，天然满足回滚语义，不用写「失败加回去」的逆向代码。

### 3.3 算法流程

```text
ATM()：
    cnt = [0, 0, 0, 0, 0]              # 20, 50, 100, 200, 500 的张数

deposit(banknotesCount)：
    for i in 0..4: cnt[i] += banknotesCount[i]

withdraw(amount)：
    take = [0]*5; rest = amount
    for i = 4 downto 0:                # 从大到小
        take[i] = min(cnt[i], rest / VAL[i])
        rest -= take[i] * VAL[i]
    if rest != 0: return [-1]          # 拒绝：cnt 未被改动
    for i in 0..4: cnt[i] -= take[i]
    return take
```

### 3.4 示例演算

![withdraw(550) 逐步演算](images/bw76_q3_walkthrough_steps.svg)

以库存 $[0,1,0,3,1]$、`withdraw(550)` 为例：

| 面额 | 库存 | $rest$ 计算 | $take$ | $rest$ 余 |
|------|------|-------------|--------|-----------|
| 500 | 1 | $\lfloor 550/500 \rfloor = 1$，$\min(1,1)=1$ | 1 | $550 - 500 = 50$ |
| 200 | 3 | $\lfloor 50/200 \rfloor = 0$ | 0 | 50 |
| 100 | 0 | $\lfloor 50/100 \rfloor = 0$ | 0 | 50 |
| 50 | 1 | $\lfloor 50/50 \rfloor = 1$，$\min(1,1)=1$ | 1 | $50 - 50 = 0$ |
| 20 | 0 | 0 | 0 | 0 |

$rest = 0$ → 成功，返回 $[0,1,0,0,1]$，库存扣减为 $[0,0,0,3,0]$ ✓。

![两次 withdraw(600) 命运对比](images/bw76_q3_walkthrough.svg)（见 §2 示例 1 的图解：同一金额，库存不同，一次成功一次拒绝。）

## 4. 算法细节

1. **库存类型**：`banknotesCount[i]` 最高 $10^9$，多次存款累加后远超 `int`；用 `long long`（C++）或 Python int。`amount` 也达 $10^9$，$rest$ 与 $take_i \times val_i$（最高 $10^9 \times 500$）同样需要 64 位。
2. **返回数组类型**：`withdraw` 返回 `int[]`（单面额取的张数 $\le rest/val \le 5 \times 10^7$，`int` 装得下），但内部计算全程 64 位，最后转型。
3. **「先试算后扣账」的顺序**：`take[i] = min(cnt[i], rest / VAL[i])` 全部算完并检查 `rest == 0`，再统一 `cnt[i] -= take[i]`。若边贪心边直接扣 `cnt`，失败时需要手动恢复，代码路径多、易错。
4. **贪心为什么不需要回溯**：因为「优先取较大面额」是题面**规定**的机器行为（不是我们的优化策略）。机器没有「智能凑款」的义务，贪心失败即拒绝——理解这一点就明白为什么不需要 DFS 或 DP。
5. **面值顺序与数组下标**：题面规定数组顺序为 $[20, 50, 100, 200, 500]$（**升序**），贪心从下标 4 往 0 扫；别把顺序记反。
6. **构造函数**：C++ 里 `ATM()` 需要显式清零成员数组（成员数组不会自动初始化）；Python `__init__` 里 `self.cnt = [0] * 5`。

## 5. 正确性证明

**引理 1（贪心取法唯一确定）**：对固定库存 $cnt$ 与金额 $amount$，按「从大到小、每面额取 $\min(cnt_i, \lfloor rest/val_i \rfloor)$」得到的结果唯一。

**证明**：算法每一步只依赖当前 $rest$ 与 $cnt_i$，无分支选择；五个面额按固定顺序处理，输出是确定性函数。∎

**引理 2（题意符合性）**：该取法正是题面描述的机器行为——「优先取较大数额的钱」。

**证明**：题面示例说明（取 300 时先取 100 与 200 中面额大的组合、取 600 时先取 500）表明机器总是先尽力用最大面额填充。形式化：处理面额 $val_i$ 时，可取的最大张数为 $\min(cnt_i, \lfloor rest/val_i \rfloor)$（受库存与「不超额」双重约束），机器取满该数量后才考虑更小面额——这正是贪心的逐面额定义。∎

**定理（withdraw 的正确性）**：算法在 `rest == 0` 时返回的 `take` 满足 (a) $\sum_i take_i \cdot val_i = amount$；(b) $take_i \le cnt_i$；(c) 与题面机器行为一致；在 `rest != 0` 时返回 `[-1]` 且库存不变。

**证明**：(a) 终止时 $rest = amount - \sum_i take_i \cdot val_i = 0$，即取款总额恰为 `amount`。(b) $take_i = \min(cnt_i, \cdot) \le cnt_i$，扣减后 $cnt_i - take_i \ge 0$，库存不越界。(c) 由引理 1、2，取法即机器行为。(d) 失败路径：`rest != 0` 说明贪心无法凑出 `amount`，由引理 2 机器必须拒绝；算法此时未触碰 `cnt`（扣减语句在 `rest == 0` 判定之后），机器状态与调用前一致。∎

**定理（deposit 的正确性）**：显然——按面值下标累加即可，无任何约束。

**证明**：`cnt[i] += banknotesCount[i]` 保持 `cnt` 的不变式「cnt[i] 是面额 VAL[i] 的当前库存」。∎

## 6. 复杂度分析

- **时间**：每次操作 $O(5) = O(1)$——deposit 是 5 次加法，withdraw 是 5 次除法/取 min/乘法，总共 5000 次操作即 $2.5 \times 10^4$ 次基本运算。
- **空间**：$O(5) = O(1)$，一个 5 元素数组存库存。

## 7. 参考代码

### C++

```cpp
class ATM {
private:
    long long cnt[5];                                   // 20,50,100,200,500 的张数
    static const int VAL[5];
public:
    ATM() { for (int i = 0; i < 5; ++i) cnt[i] = 0; }
    void deposit(vector<int> banknotesCount) {
        for (int i = 0; i < 5; ++i) cnt[i] += banknotesCount[i];
    }
    vector<int> withdraw(int amount) {
        long long take[5] = {0, 0, 0, 0, 0};
        long long rest = amount;
        for (int i = 4; i >= 0; --i) {                  // 从大面额往小贪心
            take[i] = min(cnt[i], rest / VAL[i]);
            rest -= take[i] * VAL[i];
        }
        if (rest != 0) return {-1};                     // 无法恰好取款 → 拒绝且不改动
        for (int i = 0; i < 5; ++i) cnt[i] -= take[i];
        return {(int)take[0], (int)take[1], (int)take[2], (int)take[3], (int)take[4]};
    }
};
const int ATM::VAL[5] = {20, 50, 100, 200, 500};
```

### Python

```python
class ATM:
    VAL = (20, 50, 100, 200, 500)

    def __init__(self):
        self.cnt = [0] * 5

    def deposit(self, banknotesCount: List[int]) -> None:
        for i in range(5):
            self.cnt[i] += banknotesCount[i]

    def withdraw(self, amount: int) -> List[int]:
        take = [0] * 5
        rest = amount
        for i in range(4, -1, -1):                     # 从大面额往小贪心
            take[i] = min(self.cnt[i], rest // self.VAL[i])
            rest -= take[i] * self.VAL[i]
        if rest != 0:
            return [-1]                                # 无法恰好取款 → 拒绝且不改动
        for i in range(5):
            self.cnt[i] -= take[i]
        return take
```

> 💡 两份代码均按**官方调用序列回放**通过示例 1（输出逐项一致 `[null, null, [0,0,1,0,1], null, [-1], [0,1,0,0,1]]`），并与独立参考实现（「逐张扣减」而非「除法+min」的贪心）进行 4000+ 组随机混合操作序列对拍（金额 $\le 1600$，存款张数 $0 \sim 3$），逐次比对返回值与余额，`mismatch = 0`。

## 8. 边界情况与易错点

1. **64 位库存**：`banknotesCount[i] \le 10^9` 且可多次存款，`int` 累加必溢出。C++ 用 `long long cnt[5]`；`rest`、`take[i] * VAL[i]` 同样 64 位。**这是本题最大的失分点**。
2. **拒绝时不能动库存**：先试算后扣账（或失败时逐项加回）。对拍时若混合序列后半段出现分叉，九成是拒绝路径污染了状态。
3. **贪心失败 ≠ 无解**：库存 $[0,1,0,3,1]$ 取 600 时存在 $200 \times 3$ 的凑法，但机器规定先取 500 导致失败——必须返回 `[-1]`。若自己「好心」写了个可行性判定（DFS/DP），反而与题意不符。
4. **面值数组顺序**：下标 0 是 20、下标 4 是 500（升序）；贪心循环 `for i = 4 downto 0`。写反了小数据可能侥幸，遇到 50/20 混合的用例必错。
5. **返回值格式**：成功返回长度恰为 5 的数组（面值顺序），失败返回单元素 `[-1]`；别把 `{-1,-1,-1,-1,-1}` 当失败返回。
6. **构造函数清零**：C++ 成员数组默认未初始化（值不确定），构造函数里显式清零；本地测试多组用例时也要每轮新建对象。
7. **`amount` 为 1~19 或 41 等无法被任何面额组合凑出的值**：贪心后 $rest \ne 0$，返回 `[-1]`，无需特判小金额。
