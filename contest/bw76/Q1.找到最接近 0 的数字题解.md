# LeetCode 找到最接近 0 的数字 题解

## 1. 题目概述

- **标题 / 题号**：找到最接近 0 的数字（#2239，easy）
- **链接**：https://leetcode.cn/problems/find-closest-number-to-zero/
- **来源**：LeetCode 第 76 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定整数数组 `nums`，返回其中**绝对值最小**的元素；若有多个绝对值相同的候选（必然是 $-x$ 与 $x$），返回其中**较大**的那个（即正数）。

**约束**：

- $1 \le n \le 1000$
- $-10^5 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [-4,-2,1,4,8]
输出：1
解释：各数到 0 的距离为 4, 2, 1, 4, 8，最小者是 1 对应的 1。
```

**示例 2**

```text
输入：nums = [2,-1,1]
输出：1
解释：1 与 -1 距离都是 1，返回较大值 1。
```

**示例 3（边界补充）**

```text
输入：nums = [0]
输出：0
解释：0 自身就是最近的，且没有并列问题。
```

## 3. 解题思路

### 3.1 暴力思路

排序：按 $|x|$ 升序、$x$ 降序的双关键字排序后取第一个元素，$O(n \log n)$。或者用 `min(a, key=lambda x: (abs(x), -x))` 一行解决。数据规模下都绰绰有余，但一遍扫描 $O(n)$ 更能体现「维护极值」的基本功。

### 3.2 核心观察：比较键是 $(|x| \text{ 升序},\; x \text{ 降序})$

![数轴视角：距离相同取正数](images/bw76_q1_numberline.svg)

把候选放到数轴上，「离 0 最近」就是按 $|x|$ 比；平局规则「取较大值」意味着当 $|x| = |best|$ 时**只有更靠右（更大）的才替换**。综合成单一比较：

$$x \text{ 优于 } best \iff |x| < |best| \;\text{ 或 }\; (|x| = |best| \text{ 且 } x > best)$$

注意平局时若 $x < best$（例如 $best = 1$、$x = -1$）则**不替换**——这就是「取正数」的实现方式。

### 3.3 算法流程

```text
1. best = nums[0]
2. for x in nums[1..]:
       if |x| < |best| 或 (|x| == |best| 且 x > best):
           best = x
3. 返回 best
```

一遍扫描，$O(n)$ 时间、$O(1)$ 空间。初始化用第一个元素而非哨兵值（如 `INT_MAX`），可避开「哨兵绝对值恰好并列」之类的边角思考。

### 3.4 示例演算

![示例走查](images/bw76_q1_walkthrough.svg)

对 `nums = [-4,-2,1,4,8]` 逐步维护 `best`：

| 读入 | 比较 | best |
|------|------|------|
| −4 | 初始化 | −4 |
| −2 | $\lvert-2\rvert = 2 < 4$ | −2 |
| 1 | $\lvert1\rvert = 1 < 2$ | 1 |
| 4 | $4 \ge 1$，不变 | 1 |
| 8 | $8 \ge 1$，不变 | 1 |

返回 $1$ ✓。若数组中还出现 $-1$：$\lvert-1\rvert = \lvert1\rvert$ 且 $-1 < 1$，不替换，仍返回 $1$。

## 4. 算法细节

1. **比较顺序**：先判绝对值严格更小，再判「相等且更大」，两个条件用 `||` 连接——注意第二个条件里 `abs(x) == abs(best)` 不能写成 `<=`（那会让距离更远的大数也通过）。
2. **初始化**：`best = nums[0]` 保证 `best` 永远是某个真实元素，不需要哨兵。若用 `INT_MAX` 做哨兵，空数组与全并列时容易出错（本题 $n \ge 1$ 无空数组，但习惯上从首元素初始化更稳）。
3. **返回值是元素本身而非距离**：题目要求数字，不是 $|x|$，读题别看漏。
4. **多种等价写法**：
   - `min(nums, key=lambda x: (abs(x), -x))`（Python，元组键）；
   - `*min_element(nums.begin(), nums.end(), [](a,b){ return abs(a)<abs(b) || (abs(a)==abs(b) && a>b); })`（C++，比较器表达「a 比 b 优」）。
   一遍扫描版与这些写法语义完全一致，写成哪个都可以。
5. **无溢出风险**：$|nums[i]| \le 10^5$，`abs` 与比较都在 `int` 范围内。

## 5. 正确性证明

**引理 1（平局结构）**：绝对值等于 $d > 0$ 的候选至多两个：$-d$ 与 $d$；按题意应取 $d$。绝对值为 0 的候选只有 0 自身。

**证明**：$|x| = d$ 的整数解恰为 $x = \pm d$。当 $d = 0$ 时 $-0 = 0$，仅一个值。题面规定「多个答案返回最大值」，$d > 0$ 时最大值为 $d > -d$。∎

**定理（扫描算法正确）**：一遍扫描按上述比较规则维护的 `best` 终值等于 $\arg\min_{x \in nums} (|x|, -x)$（字典序），即题意所求。

**证明**：记比较键 $key(x) = (|x|, -x)$，题意即求字典序最小的 $key$ 对应元素（引理 1 将「取较大值」编码进第二关键字 $-x$ 的升序）。归纳不变式：处理完前 $k$ 个元素后，`best` 是它们中 $key$ 最小者。$k = 1$ 平凡。设 $k$ 时成立，处理第 $k+1$ 个元素 $x$：若 $key(x) < key(best)$，即 $|x| < |best|$ 或（$|x| = |best|$ 且 $-x < -best$，即 $x > best$），恰好是替换条件，替换后 `best` 是前 $k+1$ 个中 $key$ 最小者；否则 $key(x) \ge key(best)$，`best` 不变仍最优。归纳完成，终值即全局最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$，一次遍历，每个元素 $O(1)$ 比较。
- **空间**：$O(1)$，只维护一个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findClosestNumber(vector<int>& nums) {
        int best = nums[0];
        for (int x : nums) {
            if (abs(x) < abs(best) || (abs(x) == abs(best) && x > best)) {
                best = x;               // 距离更近，或距离相同取更大值
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def findClosestNumber(self, nums: list[int]) -> int:
        best = nums[0]
        for x in nums:
            if abs(x) < abs(best) or (abs(x) == abs(best) and x > best):
                best = x                # 距离更近，或距离相同取更大值
        return best
```

> 💡 两份代码均通过官方示例（`1`、`1`），并与按 $(|x|, -x)$ 字典序排序的独立实现进行 5 万组（C++）/ 2 万组（Python）随机对拍（含 0、人为平手对 $\pm v$ 等边界），`mismatch = 0`。

## 8. 边界情况与易错点

1. **平手取正**：`[2,-1,1]` 必须返回 `1` 而非 `-1`。实现上「距离相同且 x 更大才替换」天然取到正数；若写成「距离相同就替换」，遍历顺序不同会时对时错，属于隐藏 bug。
2. **含 0**：0 是绝对值最小的可能值，任何含 0 的数组答案必为 0，算法自然处理。
3. **负数取绝对值**：C++ 的 `abs` 对 `int` 重载正确（`<cstdlib>`）；Python 的 `abs` 内置。别手写 `x > 0 ? x : -x` 时漏了 `INT_MIN`（本题范围不会触雷，但意识要有）。
4. **单元素数组**：循环从首元素出发（C++ 版 `for (int x : nums)` 首次比较自身不满足任何分支），直接返回该元素。
5. **不要排序**：$O(n \log n)$ 虽然也能过，但排序会把「维护极值」这个 $O(n)$ 基本动作掩盖掉，面试与比赛中都应默认一遍扫描。
