# LeetCode 高度互不相同的最大塔高和 题解

## 1. 题目概述

- **标题 / 题号**：高度互不相同的最大塔高和（#3301，medium）
- **链接**：https://leetcode.cn/problems/maximize-the-total-height-of-unique-towers/
- **来源**：LeetCode 第 140 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：给定数组 `maximumHeight`，其中 `maximumHeight[i]` 是第 $i$ 座塔的**高度上限**。要为每座塔指定一个高度，使得

1. 每座塔的高度都是**正整数**且不超过它自己的上限；
2. **所有塔的高度互不相同**。

求所有塔高度之和的最大值；若不存在合法方案，返回 $-1$。

**约束**：

- $1 \le maximumHeight.length \le 10^5$
- $1 \le maximumHeight[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：maximumHeight = [2,3,4,3]
输出：10
解释：可以设为 [1,2,4,3]（各塔都 ≤ 自己的上限且互不相同），
     总和 1 + 2 + 4 + 3 = 10，这是最大值。
```

**示例 2**

```text
输入：maximumHeight = [15,10]
输出：25
解释：直接取 [15,10]，两个高度不同，总和 25。
```

**示例 3**

```text
输入：maximumHeight = [2,2,1]
输出：-1
解释：三座塔需要三个互不相同的正整数，但高度上界只有 2、2、1，
     可选高度最多只有 {1, 2} 两个，无法安排，返回 -1。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的想法是枚举每座塔的高度：每座塔有 `maximumHeight[i]` 种选择，总组合数可达 $(10^9)^{10^5}$，完全没有可行域。即使把范围缩到小数据，组合数也是阶乘级。

另一种直觉是「**每座塔都尽量高**」：先给第一座塔取上限，再给第二座取「不与已用高度冲突的最大值」……但**顺序**会极大影响结果——先让上限小的塔取高值，可能把上限大的塔挤到很低。因此需要先确定顺序。

### 3.2 核心观察：降序排序后「顶格」赋值

![降序排序后「顶格」赋值](images/bw140_q2_greedy_chain.svg)

把上限**降序**排序，记为 $b_1 \ge b_2 \ge \cdots \ge b_n$。然后按这个顺序依次赋值，每次都取「当前还能取到的最大值」：

$$h_1 = b_1, \qquad h_i = \min\left(b_i,\; h_{i-1} - 1\right)$$

- **为什么降序**：上限大的塔先占高位，后面的塔上限只会更小，留给它们的空间也就更清楚；绝不会出现「小塔先占了高位、把大塔挤下去」的浪费。
- **为什么是 $h_{i-1}-1$**：高度必须互不相同。既然前面的塔按降序依次取了递减的高度，第 $i$ 座塔最多只能比前一座矮 $1$。
- **「顶格」最优**：每座塔都在合法前提下取最大值，单点最优不会伤害后面——因为把某座塔调低只会让后面的塔更容易安排，不会让结果变好。

一旦某一步算出 $h_i \le 0$，说明连「正整数」都保不住，直接返回 $-1$。

### 3.3 算法流程

![示例演算：三组输入，一次扫描定成败](images/bw140_q2_example_walkthrough.svg)

```text
1. 把 maximumHeight 降序排序
2. ans = 0，prev = +∞
3. for b in 排序后的数组:
       h = min(b, prev - 1)
       若 h <= 0: 返回 -1
       ans += h
       prev = h
4. 返回 ans
```

时间复杂度 $O(n \log n)$（排序），随后 $O(n)$ 一遍扫描。

### 3.4 示例演算

示例 1：`maximumHeight = [2,3,4,3]` → 降序 $[4,3,3,2]$：

| 次序 | 上限 $b_i$ | $h_{i-1}-1$ | 赋值 $h_i$ | 累计和 |
|---|---|---|---|---|
| 1 | 4 | $+\infty$ | 4 | 4 |
| 2 | 3 | 3 | 3 | 7 |
| 3 | 3 | 2 | 2 | 9 |
| 4 | 2 | 1 | 1 | 10 |

答案为 $10$。注意第 3 座塔的上限也是 $3$，但前一座已经用了 $3$，只能退到 $2$——这正是「互不相同」约束的代价。

示例 2：$[15,10]$ → 降序 $[15,10]$，赋值 $15$、$\min(10,14)=10$，和 $25$。
示例 3：$[2,2,1]$ → 降序 $[2,2,1]$，赋值 $2$、$\min(2,1)=1$、$\min(1,0)=0$ → 出现 $0$，返回 $-1$。

## 4. 算法细节

1. **排序方向**：必须**降序**。升序会让小上限先占低位，之后的塔只能更矮，和更小（例如 $[4,3,3,2]$ 升序会得到 $2,3,3,4$ 冲突后被迫 $2,3,1,?$，很快失败）。
2. **`prev` 的初值**：取 $+\infty$（C++ 可用 `LLONG_MAX/4`，Python 用 `float('inf')`），保证第一座塔不受「前一座」限制。
3. **`h ≤ 0` 立即返回 −1**：高度必须是正整数，$0$ 与负数都不合法；一旦某步不合法，后续只会更小（因为 `prev-1` 继续减小），不必尝试补救。
4. **`long long`**：$n \le 10^5$、高度可达 $10^9$，最大总和约 $10^{14}$，远超 `int` 上限。
5. **高度可以远小于上限**：不必执着于「每座都贴着上限」，被前一座压下来时取 `prev - 1` 才是最大可行值。
6. **排序会打乱下标**：题目只要求和，不要求还原到原下标顺序，故排序是安全的；若题目改为「返回具体方案」，则需要额外记录映射。

## 5. 正确性证明

把上限降序排列为 $b_1 \ge \cdots \ge b_n$。设任一合法方案的高度集合按降序排列为 $c_1 > c_2 > \cdots > c_n$（互不相同），贪心赋值为 $g_1, \dots, g_n$。

**引理 1（上限约束）**：任意合法方案中，$c_i \le b_i$。

**证明**：反设 $c_i > b_i$。由于 $c_1 > \cdots > c_i$，这 $i$ 个高度都 $\ge c_i > b_i$；它们被分配给 $n$ 座塔，每座被分配高度 $h$ 的塔必须满足上限 $\ge h > b_i$。而上限降序排列后，严格大于 $b_i$ 的塔至多只有前 $i-1$ 座（第 $i$ 座及其后上限都 $\le b_i$）。$i$ 个高度要塞进 $i-1$ 个可容纳的塔，矛盾（鸽巢原理）。∎

**引理 2（贪心值的闭式）**：对每个 $i$，$g_i = \min_{1 \le j \le i}\left(b_j - (i - j)\right)$。

**证明**：对 $i$ 归纳。$i=1$：$g_1 = b_1$，右端为 $b_1$。设对 $i-1$ 成立，则

$$g_i = \min(b_i,\; g_{i-1} - 1) = \min\left(b_i,\; \min_{j \le i-1}\left(b_j - (i-1-j)\right) - 1\right) = \min_{j \le i}\left(b_j - (i-j)\right)$$

其中第二项整体减 $1$ 恰好把 $b_j-(i-1-j)$ 变成 $b_j-(i-j)$。∎

**引理 3（贪心值是上界）**：任意合法方案的降序高度满足 $c_i \le g_i$。

**证明**：对 $i$ 归纳。$i=1$：由引理 1，$c_1 \le b_1 = g_1$。设 $c_{i-1} \le g_{i-1}$，则 $c_i \le c_{i-1} - 1 \le g_{i-1} - 1$（高度互不相同且降序），又由引理 1 有 $c_i \le b_i$，于是 $c_i \le \min(b_i, g_{i-1}-1) = g_i$。∎

**引理 4（贪心方案可行）**：若所有 $g_i \ge 1$，则把 $g_i$ 赋给第 $i$ 座塔（即上限为 $b_i$ 的那座）是一个合法方案。

**证明**：$g_i \le b_i$ 由定义成立；$g_i = \min(b_i, g_{i-1}-1) \le g_{i-1}-1 < g_{i-1}$，故 $g_1 > g_2 > \cdots > g_n$ 两两不同；又 $g_i \ge 1$ 为正整数。三条要求全部满足。∎

**定理**：若存在合法方案，则最大总高度为 $\sum_i g_i$；若某个 $g_i \le 0$，则不存在合法方案。

**证明**：存在性方向：由引理 4，全 $g_i \ge 1$ 时贪心方案合法，其总和为 $\sum g_i$；由引理 3，任何合法方案的总和 $\sum c_i \le \sum g_i$，故 $\sum g_i$ 最大。无解方向：若某 $g_i \le 0$，由引理 3 任何合法方案的 $c_i \le g_i \le 0$，但高度是正整数，矛盾，故无合法方案，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n\log n)$。排序是主导项；随后一遍扫描 $O(n)$，每步常数次比较与加法。
- **空间**：$O(1)$ 额外空间（除排序自身开销）。不构造新数组，也不做二分或堆操作。
- **数值规模**：总和上界 $\sum_{i} (10^9 - i) \approx n\cdot 10^9 = 10^{14}$，需 64 位整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maximumTotalSum(vector<int>& maximumHeight) {
        sort(maximumHeight.begin(), maximumHeight.end(), greater<int>());
        long long ans = 0;
        long long prev = (long long)4e18;
        for (int x : maximumHeight) {
            long long h = min<long long>(x, prev - 1);
            if (h <= 0) return -1;
            ans += h;
            prev = h;
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maximumTotalSum(self, maximumHeight: List[int]) -> int:
        ans = 0
        prev = float('inf')
        for x in sorted(maximumHeight, reverse=True):
            h = min(x, prev - 1)
            if h <= 0:
                return -1
            ans += h
            prev = h
        return ans
```

## 8. 边界情况与易错点

1. **排序方向写反**：降序是贪心正确性的前提。升序会让小上限塔先占高位，之后的塔被压到很低，甚至误判为无解。
2. **忘记 `h ≤ 0` 检查**：不检查会把 $0$ 或负数计入总和，返回一个看似合理的正数（示例 3 就会错）。
3. **用 `int` 存总和**：$10^{14}$ 溢出后结果变成随机数，必须 `long long`；Python 无此问题。
4. **`prev` 初值取 0**：会让第一座塔的 `min(b, -1)` 变成 $-1$，直接误判无解。
5. **把「上限」当成「高度」直接相加**：当上限有重复时必须下压，示例 1 的答案 $10 < 4+3+3+2 = 12$。
6. **$n = 1$**：答案就是 `maximumHeight[0]`（它一定是正整数），不要因「互不相同」而做额外处理。
7. **全相同的上限**：如 $[5,5,5]$，贪心得 $5,4,3$，和 $12$；若直接返回 $-1$ 就错了——只要排序后每个 $b_i \ge n-i+1$（例如所有上限都 $\ge n$）就一定有解。
