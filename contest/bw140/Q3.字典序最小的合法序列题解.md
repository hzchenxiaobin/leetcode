# LeetCode 字典序最小的合法序列 题解

## 1. 题目概述

- **标题 / 题号**：字典序最小的合法序列（#3302，medium）
- **链接**：https://leetcode.cn/problems/find-the-lexicographically-smallest-valid-sequence/
- **来源**：LeetCode 第 140 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、双指针、字符串、动态规划

**题意**：给定字符串 `word1`、`word2`。若下标序列 $seq$ 满足

1. $seq$ 严格递增；
2. 把 `word1` 中这些下标上的字符按顺序连起来，得到的字符串与 `word2` **几乎相等**（即**至多修改一个字符**就能变成 `word2`），

则称 $seq$ 是**合法**的。要求返回一个长度恰为 `word2.length` 的**字典序最小**的合法下标序列；若不存在，返回空数组。

注意：比较的是**下标数组**的字典序，而不是拼出的字符串的字典序。

**约束**：

- $1 \le word2.length < word1.length \le 3 \times 10^5$
- 两个字符串均只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：word1 = "vbcca", word2 = "abc"
输出：[0,1,2]
解释：word1[0]='v' 改成 'a'，word1[1]='b'、word1[2]='c' 原样对上，
     拼出 "abc"，只改了 1 个字符；且 [0,1,2] 是字典序最小的选择。
```

**示例 2**

```text
输入：word1 = "bacdc", word2 = "abc"
输出：[1,2,4]
解释：word1[1]='a' 对上 'a'；把 word1[2]='c' 改成 'b'；
     word1[4]='c' 对上 'c'。下标 [0,1,2] 不行（'bac' 与 'abc' 差两位）。
```

**示例 3**

```text
输入：word1 = "aaaaaa", word2 = "aaabc"
输出：[]
解释：word1 里没有 'b'、'c'，任何长度为 5 的下标序列都会差至少 2 位。
```

**示例 4**

```text
输入：word1 = "abc", word2 = "ab"
输出：[0,1]
解释：可以直接取前两个字符，完全相等（差别 0 ≤ 1）。
```

## 3. 解题思路

### 3.1 暴力思路

**方案一**：枚举所有长度为 $m$ 的下标组合，检查差异数。组合数是 $\binom{n}{m}$，$n = 3\times 10^5$ 时不可行。

**方案二**：按字典序贪心——第 1 位试最小下标、第 2 位试最小下标……每一步用一次 $O(n)$ 的可行性检查（从左往右贪心匹配）。但每位都可能试 $O(n)$ 个候选项，总计 $O(n^2)$ 甚至 $O(n^2 m)$，仍然超时。

瓶颈很清楚：**每换一个候选下标，都要重新判断「后面还能不能凑齐」**。只要把「从某个位置开始、还剩多少预算时能匹配多长」预先算成表，可行性判断就能降到 $O(1)$。

### 3.2 核心观察：唯一容错 = 两张后缀表

![两张后缀表：还剩几个字符能匹配？](images/bw140_q3_suffix_tables.svg)

由于「至多一处不同」，任何一个位置的决策只需要回答两个问题：**从 `word1[i]` 开始，`word2` 的后缀最多还能匹配多少个字符**——预算为 $0$（必须全等）和预算为 $1$（允许一处不同）各一张表：

- $S_0[i]$：`word2` 的**最长后缀**，使它是 `word1[i..]` 的子序列（要求逐字相等）；
- $S_1[i]$：同上，但允许**至多一处不同**。

显然 $S_1[i] \ge S_0[i]$，且都 $\le m$。有了它们，「在位置 $i$、还要匹配 `word2[j..m-1]`、剩余预算 $b$」是否可行，就等价于

$$S_b[i] \ge m - j$$

（因为 `word2[j..]` 的长度正是 $m-j$，而 $S_b[i]$ 是按「后缀长度」定义的。）

### 3.3 算法流程

**第一步：从右往左递推两张表。** 设 `word1` 长度 $n$、`word2` 长度 $m$。

$$S_0[i] = \begin{cases} S_0[i+1] + 1, & S_0[i+1] < m \ \wedge\ word1[i] = word2[m - S_0[i+1] - 1] \\ S_0[i+1], & \text{否则} \end{cases}$$

$S_1$ 则三选一取最大：

- **跳过 $i$**：$S_1[i+1]$；
- **用 $i$ 精确匹配**当前待配字符（即 $word2[m - S_1[i+1] - 1]$）：匹配上则 $S_1[i+1] + 1$；
- **把 $i$ 当作唯一的「不同」字符**：此后必须全等，故为 $S_0[i+1] + 1$。

**第二步：从左往右贪心构造下标。** 维护 `pos`（下一个可用下标）、`j`（`word2` 的位置）、`used`（容错是否已用掉）：

![贪心构造：给 word2 的当前字符找最小下标](images/bw140_q3_greedy_flow.svg)

```text
1. 递推 S0、S1
2. pos = 0, j = 0, used = false, ans = []
3. while j < m:
       若 used:                        # 预算已用尽，只能逐字相等
           跳过 word1[pos..] 中所有 != word2[j] 的字符，取第一个相等的下标
       否则:                          # 还有一次容错
           从 i = pos 开始扫描，取第一个满足下面之一的 i：
             (a) word1[i] == word2[j] 且 S1[i+1] >= m-j-1     # 精确用 i，预算留着
             (b) S0[i+1] >= m-j-1                              # 在 i 上花掉容错，之后全等
           若扫描不到任何 i: 返回 []
4. 返回 ans
```

**为什么同一位置先试 (a) 再试 (b)**：两者都能让「第 $j$ 位取 $i$」，但 (a) 保留了容错预算，后续可选集合更大，绝不会更差；只有当 (a) 不可行时才需要立刻花掉预算。

### 3.4 示例演算

![示例 2：word1 = "bacdc"，word2 = "abc"](images/bw140_q3_example_walkthrough.svg)

以示例 2（`word1 = "bacdc"`、`word2 = "abc"`）为例，先算两张表：

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| `word1[i]` | b | a | c | d | c | — |
| $S_0[i]$ | 2 | 1 | 1 | 1 | 1 | 0 |
| $S_1[i]$ | 3 | 3 | 2 | 2 | 1 | 0 |

逐步构造：

| 步骤 | 目标字符 | 候选 | 判定 | 结果 |
|---|---|---|---|---|
| $j=0$ | `'a'` | $i=0$：`'b'` ≠ `'a'`，(b) 需 $S_0[1]=1 \ge 2$ ✗ | 不可行 | — |
| $j=0$ | `'a'` | $i=1$：`'a'` = `'a'`，(a) 需 $S_1[2]=2 \ge 2$ ✓ | 可行 | 取 1，预算保留 |
| $j=1$ | `'b'` | $i=2$：`'c'` ≠ `'b'`，(b) 需 $S_0[3]=1 \ge 1$ ✓ | 可行 | 取 2，预算花掉 |
| $j=2$ | `'c'` | 预算已用，从 $i=3$ 起找 `'c'`：`'d'` 跳过，$i=4$ 命中 | — | 取 4 |

得到 $[1,2,4]$，与题面一致。若 $j=1$ 时硬取 $i=3$（`'d'`），后面只剩 1 个字符，凑不出 `'c'`，所以 (b) 的 $S_0$ 条件正是「花掉预算后必须全等」的精确表达。

## 4. 算法细节

1. **预算语义**：`used = false` 表示还剩一次容错；一旦用掉，后续必须逐字相等，此时用 $S_0$ 而非 $S_1$ 判定。
2. **表的边界**：$S_0[n] = S_1[n] = 0$；递推时用 `S0[i+1] < m` 防止访问 `word2[-1]`（C++ 中会越界）。
3. **`(a)` 的字符条件**：只有 `word1[i] == word2[j]` 时才能「精确用 $i$」，否则第 $j$ 位就已经不同，必须走 (b)。
4. **`(b)` 不需要字符条件**：无论 `word1[i]` 是什么字符，都可以把它当作被修改的那一位；即使恰好相等也无妨（「至多」一处）。
5. **`pos` 单调**：无论哪个分支，`pos` 只会增大，且每次扫描的区间首尾相接，故全部构造过程总计 $O(n)$ 次检查。
6. **扫描不到即无解**：此时说明以当前前缀为基础没有任何合法完成方案，而当前前缀是字典序最小的可行前缀，故整体无解，返回 `[]`。
7. **返回长度**：成功时长度必然恰为 $m$（循环条件是 `j < m`），无需额外截断。

## 5. 正确性证明

**引理 1（$S_0$ 的语义）**：对所有 $0 \le i \le n$，$S_0[i]$ 等于使 `word2[m-t..m-1]` 为 `word1[i..n-1]` 子序列的最大 $t$。

**证明**：对 $i$ 逆归纳。$i=n$ 时只能取 $t=0$，成立。设 $S_0[i+1]$ 正确。任何匹配 `word2` 后缀的选取若不含下标 $i$，长度 $\le S_0[i+1]$；若含 $i$，则 $i$ 必须匹配后缀的**首**个字符，即 `word2[m-t]`，且后 $t-1$ 个字符在 `word1[i+1..]` 中精确匹配，故 $t-1 \le S_0[i+1]$。要取最大 $t$ 就取 $t-1 = S_0[i+1]$，此时 $t = S_0[i+1]+1$ 可行当且仅当 `word1[i] == word2[m-S_0[i+1]-1]`——正是递推式；否则最大仍为 $S_0[i+1]$（含 $i$ 的方案也不会更优，因为 $t \le S_0[i+1]$）。∎

**引理 2（$S_1$ 的语义）**：对所有 $i$，$S_1[i]$ 等于「在 `word1[i..n-1]` 中匹配 `word2` 的某个后缀、允许至多一处不同」所能匹配的最大后缀长度。

**证明**：记最优匹配长度为 $t$。（i）若下标 $i$ 未使用，则 $t \le S_1[i+1]$。（ii）若 $i$ 用于匹配后缀首字符 `word2[m-t]`：若两字符相同，则余下 $t-1$ 个字符仍需在 `word1[i+1..]` 中以最多一处不同匹配，即 $t-1 \le S_1[i+1]$，最大只能取 $t = S_1[i+1]+1$（当且仅当该字符相等可取到），否则 $t \le S_1[i+1]$ 被「跳过」项覆盖；若两字符不同，则容错已用尽，余下必须全等，$t-1 \le S_0[i+1]$，即 $t \le S_0[i+1]+1$。三种情形分别对应递推式的三项，且每一项都可由构造达到，故取最大即为 $S_1[i]$。∎

**引理 3（可行性判定）**：给定剩余预算 $b \in \{0,1\}$，能在 `word1[i..]` 中用至多 $b$ 处不同匹配 `word2[j..m-1]` 当且仅当 $S_b[i] \ge m-j$。

**证明**：`word2[j..m-1]` 的长度为 $m-j$，即 $t = m-j$ 的「后缀」正是 `word2[j..]`。由引理 1、2，$S_b[i]$ 是这样能匹配的最长后缀长度，故可匹配长度 $m-j$ 的后缀 $\iff m-j \le S_b[i]$。∎

**定理（贪心正确）**：若合法序列存在，算法返回其中字典序最小者；否则返回空数组。

**证明**：设算法在第 $j$ 步已构造前缀 $A = (a_0,\dots,a_{j-1})$。归纳证明两条不变量：（甲）存在以 $A$ 为前缀的合法序列；（乙）对任何合法序列 $V$，$V$ 的前 $j$ 项按字典序 $\ge A$。

基础 $j=0$ 显然。归纳步：由（甲），存在从 $A$ 延伸的合法序列，其第 $j$ 项 $i'$ 满足引理 3 的可行性条件（预算状态由 $A$ 决定），故扫描必然找到某个可行 $i \le i'$，算法不会在这步失败——（甲）保持。对（乙）：任何合法 $V$ 的前 $j$ 项 $\ge A$（归纳假设）；若严格大于 $A$，则 $V$ 的前 $j+1$ 项也 $> (A,i)$；若等于 $A$，则 $V_j$ 是一个可行候选，故 $i \le V_j$，于是 $V$ 的前 $j+1$ 项 $\ge (A,i)$——（乙）保持。

当 $j = m$ 时，$A$ 本身就是合法序列，且由（乙）它不大于任何合法序列，即字典序最小。反之，若某一步扫描不到可行下标，注意（甲）保证当前前缀 $A$ 有合法完成，取该完成序列第 $j$ 项 $i'$：若 `word1[i'] == word2[j]`，则剩余 $m-j-1$ 个字符由该完成序列带预算 $1$ 匹配，即 $S_1[i'+1] \ge m-j-1$，检查 (a) 通过；否则该完成序列正是在此用掉了唯一容错，剩余 $m-j-1$ 个字符必须全等，即 $S_0[i'+1] \ge m-j-1$，检查 (b) 通过。所以只要存在合法序列，扫描就不会为空；「扫描为空」只能出现在 $j=0$ 且根本没有合法序列时，此时返回 `[]` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。两张后缀表各 $O(n)$ 次常数操作；贪心构造中 `pos` 单调右移，每个下标至多被检查一次，总计 $O(n)$；其余为 $O(m)$。
- **空间**：$O(n)$，两个长度 $n+1$ 的整型数组，$n = 3\times10^5$ 时约 $2.4$ MB。
- **对比**：逐位枚举 + 每次 $O(n)$ 判定的写法是 $O(n^2)$，在 $3\times10^5$ 规模下约 $9\times10^{10}$，不可行。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> validSequence(string word1, string word2) {
        int n = word1.size(), m = word2.size();
        vector<int> s0(n + 1, 0), s1(n + 1, 0);
        for (int i = n - 1; i >= 0; i--) {
            s0[i] = s0[i + 1];
            if (s0[i + 1] < m && word1[i] == word2[m - s0[i + 1] - 1]) s0[i] = s0[i + 1] + 1;
            int best = s1[i + 1];
            if (s1[i + 1] < m && word1[i] == word2[m - s1[i + 1] - 1]) best = max(best, s1[i + 1] + 1);
            if (s0[i + 1] < m) best = max(best, s0[i + 1] + 1);
            s1[i] = best;
        }
        vector<int> ans;
        int pos = 0, j = 0;
        bool used = false;
        while (j < m) {
            if (used) {
                while (pos < n && word1[pos] != word2[j]) pos++;
                if (pos == n) return {};
                ans.push_back(pos);
                pos++;
                j++;
            } else {
                int i = pos;
                for (; i < n; i++) {
                    if (word1[i] == word2[j] && s1[i + 1] >= m - j - 1) {
                        ans.push_back(i);
                        pos = i + 1;
                        j++;
                        break;
                    }
                    if (s0[i + 1] >= m - j - 1) {
                        ans.push_back(i);
                        pos = i + 1;
                        j++;
                        used = true;
                        break;
                    }
                }
                if (i == n) return {};
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def validSequence(self, word1: str, word2: str) -> List[int]:
        n, m = len(word1), len(word2)
        s0 = [0] * (n + 1)   # 预算 0：word2 的后缀最长能精确匹配多长
        s1 = [0] * (n + 1)   # 预算 1：word2 的后缀最长能匹配多长（至多一处不同）
        for i in range(n - 1, -1, -1):
            s0[i] = s0[i + 1]
            if s0[i + 1] < m and word1[i] == word2[m - s0[i + 1] - 1]:
                s0[i] = s0[i + 1] + 1
            best = s1[i + 1]
            if s1[i + 1] < m and word1[i] == word2[m - s1[i + 1] - 1]:
                best = max(best, s1[i + 1] + 1)
            if s0[i + 1] < m:
                best = max(best, s0[i + 1] + 1)
            s1[i] = best

        ans = []
        pos, j, used = 0, 0, False
        while j < m:
            if used:
                while pos < n and word1[pos] != word2[j]:
                    pos += 1
                if pos == n:
                    return []
                ans.append(pos)
                pos += 1
                j += 1
            else:
                i = pos
                while i < n:
                    if word1[i] == word2[j] and s1[i + 1] >= m - j - 1:
                        ans.append(i)
                        pos = i + 1
                        j += 1
                        break
                    if s0[i + 1] >= m - j - 1:
                        ans.append(i)
                        pos = i + 1
                        j += 1
                        used = True
                        break
                    i += 1
                if i == n:
                    return []
        return ans
```

## 8. 边界情况与易错点

1. **预算用完仍用 $S_1$ 判定**：`used` 之后必须用 $S_0$，否则会允许第二处不同，构造出非法答案。
2. **`m - j - 1` 写成 `m - j`**：第 $j$ 位已经占掉一个位置，剩下的长度是 $m-j-1$；差一位会多花/少花预算。
3. **`(a)` 漏掉字符相等条件**：若 `word1[i] != word2[j]` 却按 (a) 处理，会以为预算还在，实际已经用掉。
4. **`(b)` 加了字符不等条件**：`(b)` 描述的是「在 $i$ 上花掉容错」，字符相等也可以花（至多一处），加上条件会漏掉合法解。
5. **扫描越界**：$S_0[i+1]$、$S_1[i+1]$ 的下标最大到 $n$，数组要开 $n+1$；C++ 中 `word2[m - S - 1]` 在 $S = m$ 时为负，必须先判 `S < m`。
6. **`word2` 长度为 1**：此时 $m-j-1 = 0$，条件恒成立，答案必然是某个单下标，不应报无解。
7. **返回空数组的两种含义**：题面要求无解时返回 `[]`，而长度 $m \ge 1$ 的合法序列至少有一个元素，两者不会混淆。
8. **字典序是下标序列的字典序**：不要按「拼出字符串最小」去选；示例 1 的 `[0,1,2]` 在字符串层面反而是最差的选择（`"vbc"`），但下标最小。
