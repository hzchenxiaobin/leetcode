# LeetCode 第一个几乎相等子字符串的下标 题解

## 1. 题目概述

- **标题 / 题号**：第一个几乎相等子字符串的下标（#3303，hard）
- **链接**：https://leetcode.cn/problems/find-the-occurrence-of-first-almost-equal-substring/
- **来源**：LeetCode 第 140 场双周赛 Q4
- **难度**：困难
- **标签**：字符串、字符串匹配、KMP 算法

**题意**：给定两个字符串 `s` 和 `pattern`。若字符串 $x$ 修改**至多一个**字符就能变成 $y$，则称 $x$ 与 $y$ **几乎相等**。要求返回 `s` 中下标**最小**的子串（连续、非空），它满足：

1. 长度恰为 `pattern.length`；
2. 与 `pattern` 几乎相等。

若不存在，返回 $-1$。

**约束**：

- $1 \le pattern.length < s.length \le 10^5$
- 两个字符串均只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "abcdefg", pattern = "bcdffg"
输出：1
解释：s[1..6] = "bcdefg"，把 s[4] 的 'e' 改成 'f' 就得到 "bcdffg"，
     只改了一处。下标 0 的窗口 "abcdef" 与 "bcdffg" 差了 6 处，不合法。
```

**示例 2**

```text
输入：s = "ababbababa", pattern = "bacaba"
输出：4
解释：s[4..9] = "bababa"，把 s[6] 的 'b' 改成 'c'，得到 "bacaba"。
```

**示例 3**

```text
输入：s = "abcd", pattern = "dba"
输出：-1
解释：三个窗口 "abc"、"bcd" 与 "dba" 的差异都超过 1 处。
```

**示例 4**

```text
输入：s = "dde", pattern = "d"
输出：0
解释：pattern 只有一个字符，任何窗口至多差 1 处，下标 0 的窗口 "d" 完全相等。
```

## 3. 解题思路

### 3.1 暴力思路

对每个起点 $i \in [0, n-m]$，逐位比较 `s[i..i+m-1]` 与 `pattern`，统计不同字符数，遇到第二个不同就提前退出，第一个合法窗口即答案。

单窗口最坏 $O(m)$（前面全相同、最后一位才不同），总复杂度 $O(nm)$。$n = 10^5$、$m \approx n/2$ 时是 $5\times 10^9$ 次比较，必定超时。

瓶颈在于**重复比较**：下标 0 的窗口已经知道 `s[1..m-1]` 与 `pattern[1..m-1]` 是否相同，但这些信息在下标 1 的窗口里被完全丢弃、从头再比。字符串匹配的经典解法（KMP、Z 函数、哈希）正是为了复用这类信息。

### 3.2 核心观察：前缀命中 + 后缀命中把窗口盖满

![「至多一处不同」⟺ 前缀匹配 + 后缀匹配盖满窗口](images/bw140_q4_cover_condition.svg)

固定起点 $i$，定义

$$p_i = \operatorname{LCP}\bigl(s[i..],\; pattern\bigr) \quad (\text{截断到 } m),\qquad q_i = \operatorname{LCS}\bigl(s[..i+m-1],\; pattern\bigr)$$

即窗口与 `pattern` 的**公共前缀长度** $p_i$ 和**公共后缀长度** $q_i$。

- 前缀命中的是窗口的前 $p_i$ 个位置；
- 后缀命中的是窗口的后 $q_i$ 个位置；
- 中间没有被覆盖的位置有 $m - p_i - q_i$ 个。

**关键等价**：窗口与 `pattern` 至多一处不同 $\iff$

$$p_i + q_i \ge m - 1$$

理由很直观：若 $p_i + q_i \ge m-1$，未被覆盖的中间部分至多 $1$ 个位置，把那个位置改成 `pattern` 对应字符即可（若 $p_i + q_i \ge m$ 则两段重叠、完全相等，更合法）。反之，若窗口至多一处不同，设不同处在窗口内偏移 $t$（或不存在），则前 $t$ 个位置全等、后 $m-1-t$ 个位置全等，$p_i \ge t$、$q_i \ge m-1-t$，相加即得 $m-1$。

**重叠为何无害**：前缀匹配要求 $s[i + u] = pattern[u]$（$u < p_i$），后缀匹配要求 $s[i + v] = pattern[v]$（$v \ge m - q_i$）。两者对同一位置的要求是**同一个等式**，不会互相矛盾，所以直接相加即可，不必担心 $p_i + q_i > m$。

于是问题化为：对每个起点快速求出 $p_i$、$q_i$。所有 $p_i$ 恰好是「`pattern` 在 `s` 的每个后缀中的最长公共前缀」，用一次 Z 函数即可全部得到；$q_i$ 同理，把两个串都反转再做一次 Z。

### 3.3 算法流程

![两次 Z 函数：一次算前缀 LCP，一次算后缀 LCS](images/bw140_q4_z_pipeline.svg)

```text
1. lcp = 对每个 i 求 LCP(s[i..], pattern)       # Z 函数：pattern + '#' + s
2. 令 rs = reverse(s)，rp = reverse(pattern)
   lcsRev = 对每个 j 求 LCP(rs[j..], rp)         # 再跑一次 Z 函数
3. for i = 0 .. n-m:
       若 lcp[i] + lcsRev[n-1-(i+m-1)] >= m-1:  返回 i
4. 返回 -1
```

**Z 函数怎么给 LCP**：把串拼成 $t = pattern + \texttt{\#} + s$，其中 `#` 是不出现在字母表中的分隔符。$t$ 的 Z 数组满足 $z[k] = \operatorname{LCP}(t, t[k..])$。对 $k = m+1+i$（即 $t$ 中对应 `s[i]` 的位置），$z[k]$ 就是 `s[i..]` 与 `pattern` 的公共前缀长度；又因为匹配到底会撞上分隔符 `#`，$z[k]$ 天然不超过 $m$，不需要额外截断（代码里仍取 `min(z[k], m)` 更稳妥）。

**索引换算**：$q_i$ 是 `s[..i+m-1]` 与 `pattern` 的公共**后缀**长度。反转后，这个后缀对应 `rs` 中从 $n-1-(i+m-1)$ 开始的前缀，其与 `rp` 的公共前缀长度正是 $q_i$。

**为什么第一个满足条件的就是答案**：$i$ 从小到大枚举，第一个合法窗口的下标自然最小。

### 3.4 示例演算

![示例 1：前后缀在同一个窗口里「接上」](images/bw140_q4_example_walkthrough.svg)

以示例 1（`s = "abcdefg"`、`pattern = "bcdffg"`）为例：

$n = 7$、$m = 6$，合法起点只有 $i \in [0, n-m] = [0,1]$ 两个窗口：

| 起点 $i$ | 窗口 | $p_i$（前缀命中） | $q_i$（后缀命中） | $p_i + q_i \ge 5$？ |
|---|---|---|---|---|
| 0 | `abcdef` | 0（`'a'` ≠ `'b'`） | 0（`'f'` ≠ `'g'`） | 否，继续 |
| 1 | `bcdefg` | 3（`"bcd"`） | 2（`"fg"`） | $3+2 = 5$ ✓，返回 1 |

$i=1$ 时，前缀覆盖窗口前 3 位、后缀覆盖后 2 位，中间正好空出 1 位（`s[4]='e'` 对 `pattern[3]='f'`），改这一处即可，答案 $1$。

## 4. 算法细节

1. **分隔符选择**：`#`（或任何非小写字母）插在中间，保证 Z 值不会跨过 `pattern` 继续匹配，从而使 $z$ 值不超过 $m$。
2. **只枚举 $n-m+1$ 个窗口**：$i$ 从 $0$ 到 $n-m$，再往后长度不足 $m$。
3. **反向索引**：$q_i$ 对应 `lcsRev` 的下标 $n-1-(i+m-1) = n-i-m$。这个式子写成 `n - 1 - (i + m - 1)` 更不容易错。
4. **$m = 1$ 的退化**：$m-1 = 0$，条件 $p_i + q_i \ge 0$ 恒真，直接返回 $0$（示例 4）。
5. **Z 的线性实现**：维护当前最右的匹配区间 $[l, r]$，若 $i \le r$ 则从 $\min(r-i+1, z[i-l])$ 起继续扩展，否则从 $0$ 开始。这是保证 $O(n+m)$ 的关键，写成「对每个位置暴力扩展」会退化为 $O(n^2)$。
6. **两次 Z 的空间**：拼接串长度分别约 $n+m$，Z 数组同样大小；$10^5$ 量级下约数百 KB，可接受。
7. **不要用 `memcmp`/切片比较**：Python 中 `s[i:i+m] == pattern` 每次是 $O(m)$，整体仍是 $O(nm)$。

## 5. 正确性证明

**引理 1（Z 函数给出 LCP）**：对任意 $k \ge 1$，$z[k] = \operatorname{LCP}(t, t[k..])$，且 Z 算法在 $O(|t|)$ 内算出全部 $z[k]$。

**证明**：定义本身即 $z[k]$ 的语义，Z 算法只是加速计算：维护区间 $[l, r]$ 使 $t[l..r] = t[0..r-l]$，即当前最靠右的、与串前缀相等的区间。当 $k \le r$ 时，由 $t[k..r] = t[k-l..r-l]$ 可知 $z[k] \ge \min(r-k+1, z[k-l])$；取这个下界作为起点继续逐字符扩展，不会遗漏。所有扩展的右端点 $r$ 单调不减且总增幅不超过 $|t|$，故总复杂度线性。∎

**引理 2（覆盖判定的等价性）**：固定起点 $i$，窗口与 `pattern` 至多一处不同 $\iff p_i + q_i \ge m-1$。

**证明**：
（$\Leftarrow$）令 $U = \{0,1,\dots,m-1\}$ 为窗口内偏移集合。前缀命中保证对所有 $u < p_i$ 有 $s[i+u] = pattern[u]$；后缀命中保证对所有 $v \ge m - q_i$ 有 $s[i+v] = pattern[v]$。未被覆盖的偏移至多 $\max(0, m - p_i - q_i) \le 1$ 个。对至多一个未覆盖偏移改字符、其余不动，即可让窗口等于 `pattern`，改动数 $\le 1$；若两段重叠（$p_i+q_i \ge m$）则窗口本就完全相等，改动数为 $0$。注意两段对重叠位置的要求一致，不存在冲突。
（$\Rightarrow$）若窗口与 `pattern` 至多一处不同，设不同处的偏移为 $t$（若完全相同则不存在这样的 $t$）。则偏移 $0..t-1$ 全等，故 $p_i \ge t$；偏移 $t+1..m-1$ 全等，即窗口的后 $m-1-t$ 个字符与 `pattern` 的对应后缀相同，故 $q_i \ge m-1-t$。相加得 $p_i + q_i \ge m-1$。若完全相同，则 $p_i = m \ge m-1$，同样成立。∎

**引理 3（反向索引正确）**：设 `rs = reverse(s)`、`rp = reverse(pattern)`，$z_{rp}$ 为 `rp + '#' + rs` 的 Z 数组，则对任意起点 $i$，

$$q_i = \operatorname{LCP}\bigl(rs[n-1-(i+m-1)..],\; rp\bigr) = z_{rp}[m + 1 + n - 1 - (i+m-1)]$$

**证明**：`s[..i+m-1]` 的末尾 $k$ 个字符与 `pattern` 的末尾 $k$ 个字符相同，当且仅当反转后 `rs` 从 $n-1-(i+m-1)$ 起的第 $j$ 个字符等于 `rp` 的第 $j$ 个字符（$j < k$）。反转是一一对应的双射且保持前后顺序，故「公共后缀长度」等于「反转串的公共前缀长度」，即 LCP。∎

**定理**：算法返回 `s` 中下标最小的、与 `pattern` 几乎相等的长度为 $m$ 的子串起点；不存在时返回 $-1$。

**证明**：由引理 1、3，算法算出的 $p_i$、$q_i$ 正是窗口与 `pattern` 的公共前缀/后缀长度；由引理 2，判定式与「至多一处不同」等价。算法按 $i$ 递增顺序检查，返回第一个合法 $i$，它显然是最小下标；若所有 $i \in [0, n-m]$ 都不合法，则不存在合法窗口，返回 $-1$ 正确。又长度不小于 $m$ 的子串只有这些起点，没有遗漏。∎

## 6. 复杂度分析

- **时间**：两次 Z 函数各 $O(n+m)$（拼接串长度 $n+m+1$）；枚举窗口 $O(n-m+1)$，每次 $O(1)$ 判定。总计 $O(n+m)$，$n = 10^5$ 时约线性。
- **空间**：两次 Z 数组与拼接串，$O(n+m)$；实际约 $(n+m) \times 3$ 个整数，$10^5$ 量级下几 MB。
- **对比**：逐窗口逐字符比较是 $O(nm)$；即使加「第二个不同就退出」的剪枝，最坏仍是 $O(nm)$（例如所有窗口都在最后一位才出现第二个不同）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minStartingIndex(string s, string pattern) {
        int n = s.size(), m = pattern.size();
        if (m > n) return -1;
        vector<int> lcp = lcpWith(s, pattern);
        string rs(s.rbegin(), s.rend());
        string rp(pattern.rbegin(), pattern.rend());
        vector<int> lcsRev = lcpWith(rs, rp);
        for (int i = 0; i + m <= n; i++) {
            if (lcp[i] + lcsRev[n - 1 - (i + m - 1)] >= m - 1) return i;
        }
        return -1;
    }

private:
    static vector<int> lcpWith(const string& text, const string& pat) {
        int p = pat.size();
        string t = pat + "#" + text;
        int L = t.size();
        vector<int> z(L, 0);
        int l = 0, r = 0;
        for (int i = 1; i < L; i++) {
            if (i <= r) z[i] = min(r - i + 1, z[i - l]);
            while (i + z[i] < L && t[z[i]] == t[i + z[i]]) z[i]++;
            if (i + z[i] - 1 > r) {
                l = i;
                r = i + z[i] - 1;
            }
        }
        vector<int> res(text.size(), 0);
        for (int i = 0; i < (int)text.size(); i++) res[i] = min(z[p + 1 + i], p);
        return res;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def minStartingIndex(self, s: str, pattern: str) -> int:
        n, m = len(s), len(pattern)
        if m > n:
            return -1

        def lcp_with(text: str, pat: str) -> List[int]:
            t = pat + '#' + text
            p = len(pat)
            z = [0] * len(t)
            l = r = 0
            for i in range(1, len(t)):
                if i <= r:
                    z[i] = min(r - i + 1, z[i - l])
                while i + z[i] < len(t) and t[z[i]] == t[i + z[i]]:
                    z[i] += 1
                if i + z[i] - 1 > r:
                    l, r = i, i + z[i] - 1
            return [min(z[p + 1 + i], p) for i in range(len(text))]

        lcp = lcp_with(s, pattern)
        lcs_rev = lcp_with(s[::-1], pattern[::-1])
        for i in range(n - m + 1):
            if lcp[i] + lcs_rev[n - 1 - (i + m - 1)] >= m - 1:
                return i
        return -1
```

## 8. 边界情况与易错点

1. **`m = 1`**：$m-1 = 0$，任何窗口都合法，答案恒为 $0$；代码里 $+1$ 索引与 `n-1-(i+m-1)` 在 $i=0$ 时得到 $n-1-m+1 = n-1$，恰好是 `rs` 的末位，不会越界。
2. **条件写成 $p_i + q_i \ge m$**：会漏掉「恰好一处不同」的窗口（示例 1 的 $3+2 = 5 = m-1$ 就过不了）。
3. **重叠区间担心冲突**：前缀与后缀对同一位置的要求完全一致，直接相加即可；不要在代码里刻意跳过重叠部分，否则反而会漏判。
4. **忘记分隔符**：不插 `#` 直接拼接 `pattern + s`，$z$ 值可能超过 $m$，导致 $p_i$ 虚高、误判。
5. **索引换算写错**：`n - 1 - (i + m - 1)` 少一个 $-1$ 就整体错位一格；用「窗口末位在 `rs` 中的位置」这个语义记忆更可靠。
6. **Z 的 `z[0]`**：`z[0]` 按定义为 $|t|$，代码从 $i=1$ 开始循环，`z[0]` 保持 $0$，不影响结果；但若把 `z[0]` 拿去当 LCP 用会出错。
7. **空串/长度不足**：题面保证 $pattern$ 非空且严格短于 $s$；若 $m > n$ 应直接返回 $-1$（代码已处理）。
8. **用切片比较图省事**：Python 里 `if s[i:i+m] == pattern` 是 $O(m)$，在 $10^5$ 规模下会 TLE；必须用线性匹配。
