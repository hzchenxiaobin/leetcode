# LeetCode 替换为数位和以后的最小元素 题解

## 1. 题目概述

- **标题 / 题号**：替换为数位和以后的最小元素（#3300，easy）
- **链接**：https://leetcode.cn/problems/minimum-element-after-replacement-with-digit-sum/
- **来源**：LeetCode 第 140 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 `nums`。把其中**每一个**元素都替换成它的**各个数位之和**（例如 $199 \to 1+9+9 = 19$），返回替换后数组中的**最小元素**。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 10^4$

## 2. 示例

**示例 1**

```text
输入：nums = [10,12,13,14]
输出：1
解释：替换后为 [1, 3, 4, 5]，最小元素是 1。
```

**示例 2**

```text
输入：nums = [1,2,3,4]
输出：1
解释：都是单位数，替换后不变，最小元素是 1。
```

**示例 3**

```text
输入：nums = [999,19,199]
输出：10
解释：替换后为 [27, 10, 19]，最小元素是 10。
```

示例 3 提醒我们：**位数多不代表数位和大**。$999$ 的三位全是 $9$，数位和 $27$；$19$ 只有两位，数位和却只有 $10$。所以不能靠位数或原数值大小来猜答案。

## 3. 解题思路

### 3.1 暴力思路

最直接的做法分两步：先新开一个数组，把每个元素替换成数位和；再对新数组求最小值。这是 $O(n)$ 的额外空间与两遍扫描。

更「笨」一点的做法是对每个元素都从 $1$ 开始数位、甚至用字符串反复切分，虽然也能过（$n \le 100$、$nums[i] \le 10^4$，量级极小），但完全没有必要——**数位和可以边算边比较**，连新数组都不用开。

### 3.2 核心观察：每个数的数位和彼此独立

![每个数独立换血：数位和只由它自己决定](images/bw140_q1_digit_sum.svg)

- **无耦合**：第 $i$ 个元素的数位和只取决于 `nums[i]` 本身，与其它元素、与替换顺序都无关。因此可以**就地**求和、边求边更新最小值，不必构造新数组。
- **上界很小**：$nums[i] \le 10^4$ 最多 $5$ 位，数位和 $\le 9 \times 5 = 45$，实际上 $9999 \to 36$。这保证了「数位和」的计算是常数级开销。
- **求最小值的顺序无关**：无论先替换再取 min，还是先取 min 再替换，结果一样（因为替换是逐元素的映射）。这就是可以「边算边更新」的依据。

数位和的算法是十进制拆位：

$$\text{digitSum}(x) = \sum_{t \ge 0} \left\lfloor \frac{x}{10^t} \right\rfloor \bmod 10$$

### 3.3 算法流程

```text
1. ans = +∞
2. for x in nums:
       s = 0
       while x > 0:
           s += x mod 10
           x = x // 10
       ans = min(ans, s)
3. 返回 ans
```

### 3.4 示例演算

![示例 3：三个数的数位和演算](images/bw140_q1_example_walkthrough.svg)

以示例 3 为例：

| 原元素 | 数位拆解 | 数位和 | 当前最小值 |
|---|---|---|---|
| 999 | $9+9+9$ | 27 | 27 |
| 19 | $1+9$ | 10 | 10 |
| 199 | $1+9+9$ | 19 | 10 |

答案为 $10$。示例 1（$[10,12,13,14] \to [1,3,4,5]$）与示例 2（单位数不变）同理，答案都是 $1$。

## 4. 算法细节

1. **取模 + 整除**：`s += x % 10; x /= 10`，循环直到 `x == 0`，天然处理任意位数，不需要知道长度。
2. **不要漏掉最高位**：循环条件是 `x > 0`，当 `x` 只剩一位时仍会执行一次，最高位不会丢。
3. **`ans` 的初值**：取一个足够大的数（如 `INT_MAX` / `10**9`）。注意不能取 $0$：数位和恒 $\ge 1$，取 $0$ 会永远得到错误答案。
4. **原地修改参数**：C++ 中若写 `for (int &x : nums)` 并修改 `x`，会破坏入参；用值拷贝 `for (int x : nums)` 或临时变量。
5. **字符串写法**：Python 可以直接 `sum(int(c) for c in str(x))`，语义清晰；C++ 里取模更快，二者都对。
6. **数值范围**：`nums[i] \le 10^4`，数位和 $\le 36$，用 `int` 足够，无溢出风险。

## 5. 正确性证明

**引理 1（拆位求和正确）**：对任意正整数 $x$，上述循环结束时 $s$ 恰为 $x$ 的十进制各位数字之和。

**证明**：设 $x$ 的十进制表示为 $d_{L-1}d_{L-2}\cdots d_0$（$d_0$ 是个位）。每轮 `x % 10` 取出当前最低位并累加，随后 `x / 10` 抹掉这一位。对位数 $L$ 归纳：$L=1$ 时一轮取出 $d_0$，$s = d_0$ 正确；$L>1$ 时第一轮取出 $d_0$，问题化为对 $\lfloor x/10 \rfloor = d_{L-1}\cdots d_1$ 求和，由归纳假设余下各轮恰好累加 $d_1+\cdots+d_{L-1}$，故总和为 $\sum d_i$。∎

**引理 2（最小值覆盖全部元素）**：算法结束时 `ans` 等于集合 $\{\text{digitSum}(nums[i])\}$ 的最小值。

**证明**：`ans` 初始为 $+\infty$，每轮执行 `ans = min(ans, s_i)`，其中 $s_i$ 是第 $i$ 个元素的数位和。由 `min` 的结合律与交换律，循环结束后 `ans = min(s_1, \dots, s_n)`；又 $n \ge 1$ 保证至少更新过一次，`ans` 不会是 $+\infty$。∎

**定理**：算法返回值等于「把所有元素替换为数位和之后数组的最小元素」。

**证明**：替换后的数组第 $i$ 个元素正是 $\text{digitSum}(nums[i])$（引理 1），其最小元素由引理 2 给出。∎

## 6. 复杂度分析

- **时间**：$O(n \log_{10} M)$，其中 $M = \max nums[i] \le 10^4$，即每个元素 $O(\text{位数}) \le 5$ 次取模与整除；总计不超过 $500$ 次基本运算。
- **空间**：$O(1)$，只用一个累加变量与一个答案变量，不构造新数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minElement(vector<int>& nums) {
        int ans = 100000;
        for (int x : nums) {
            int s = 0;
            while (x > 0) {
                s += x % 10;
                x /= 10;
            }
            ans = min(ans, s);
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def minElement(self, nums: List[int]) -> int:
        return min(sum(int(c) for c in str(x)) for x in nums)
```

## 8. 边界情况与易错点

1. **`ans` 初值取 0**：数位和最小也是 $1$（$nums[i] \ge 1$），初值取 $0$ 会让答案永远是 $0$。
2. **循环写成 `while (x)` 但漏了最高位**：只要条件写对（`x > 0`），最高位自然被处理；把条件写成 `x >= 10` 会漏掉最高位，`10` 会变成 `0`。
3. **原地改写入参**：C++ 中用引用遍历并无所谓（不影响结果），但如果后续还要用原值就会出错；用值遍历更安全。
4. **单位数**：示例 2 说明单位数的数位和是它自己，不能因为「只有一位」就特判成 $0$ 或跳过。
5. **`nums[i] = 10000`**：数位和是 $1$，不是 $10$ 或 $10000$，`10^4` 这个上界处最容易被写死位数的代码坑到。
6. **「最小元素」不是「最小数位和对应的原数」**：题目要的是替换后的最小值；不要返回原数组中数位和最小的那个元素的值。
