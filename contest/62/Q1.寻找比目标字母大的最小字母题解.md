# LeetCode 寻找比目标字母大的最小字母 题解

## 1. 题目概述

- **标题 / 题号**：寻找比目标字母大的最小字母（#744，easy）
- **链接**：https://leetcode.cn/problems/find-smallest-letter-greater-than-target/
- **来源**：LeetCode 第 62 场周赛 Q1
- **难度**：简单
- **标签**：数组, 二分查找

**题意**：给定一个按**非递减顺序**排列的字符数组 `letters`（至少含两个不同字符）和一个字符 `target`，返回 `letters` 中**字典序严格大于** `target` 的最小字符；如果不存在这样的字符（即所有元素都 $\le$ `target`），则返回 `letters[0]`——相当于把数组首尾相接成一个环，从 `target` 的下一格继续找。

**约束**：

- $2 \le \text{letters.length} \le 10^4$
- `letters[i]` 与 `target` 都是小写英文字母
- `letters` 按非递减顺序排列（允许重复元素）
- `letters` 至少包含两个不同的字母，故 `letters[0] < letters[n-1]`

> 💡 官方提示只提了「枚举 26 个字母看谁出现过」，那是 $O(26n)$ 的取巧写法；本题真正的落点是 **`upper_bound`（第一个严格大于的位置）** 这一最常用的二分原语。

## 2. 示例

**示例 1**

```text
输入：letters = ['c', 'f', 'j'], target = 'a'
输出：'c'
解释：数组中比 'a' 大的字母有 c、f、j，字典序最小的是 'c'。
```

**示例 2**

```text
输入：letters = ['c', 'f', 'j'], target = 'c'
输出：'f'
解释：'c' 与 target 相等，不算「大于」；比 'c' 大的最小字母是 'f'。
```

**示例 3**

```text
输入：letters = ['x', 'x', 'y', 'y'], target = 'z'
输出：'x'
解释：没有任何字母大于 'z'，触发回绕，返回首元素 letters[0] = 'x'。
```

## 3. 解题思路

### 3.1 暴力思路

从左到右扫描，遇到第一个 $> \texttt{target}$ 的字符就返回，扫完没找到就返回 `letters[0]`：$O(n)$。$n \le 10^4$ 时这一万次比较当然能过，但它把「数组已经有序」这条信息整条丢掉了；换成本题的推广版本（长度上亿、或者数组换成有序流）就立刻失效。另一个常见做法是照抄提示：把 26 个字母全枚举一遍，判某个字母是否在 `letters` 里，$O(26n)$ 或 $O(26\log n)$，既慢又没抓住单调性。

正解只需一次二分：$O(\log n)$。下面先给出「为什么能二分」的观察。

### 3.2 核心观察：判定函数单调 → 二分上界

![非递减数组被 target 切成两段](images/wc62_q1_upper_bound_partition.svg)

定义判定函数

$$P(i) = \bigl[\texttt{letters}[i] > \texttt{target}\bigr].$$

因为 `letters` 非递减，若 $P(i)$ 为真，则对任意 $j > i$ 有 $\texttt{letters}[j] \ge \texttt{letters}[i] > \texttt{target}$，故 $P(j)$ 也为真。也就是说 $P$ 的值形如

$$\underbrace{\texttt{false},\ \dots,\ \texttt{false}}_{\le \texttt{target}\ \text{的前缀}},\ \underbrace{\texttt{true},\ \dots,\ \texttt{true}}_{> \texttt{target}\ \text{的后缀}}$$

——**一段「假」接一段「真」**。答案就是这个真后缀的第一个位置：

$$\text{ans} = \min\{\, i \mid \texttt{letters}[i] > \texttt{target} \,\},$$

集合为空时令 $\text{ans} = n$（哨兵），此时返回 `letters[0]`。

> ⚠️ 注意是**严格大于**。等于 `target` 的那些重复元素必须全部跳过，所以这里要的是**上界**（`upper_bound` / `bisect_right`），而不是下界（`lower_bound` / `bisect_left`）。示例 2 就是专门用来区分这两种写法的：对 `'c'` 取下界会得到下标 0，返回 `'c'`，直接错。

### 3.3 算法流程

![二分收缩与出口判定](images/wc62_q1_binary_search_flow.svg)

```text
1. lo = 0, hi = n − 1, ans = n          // ans = n 是「暂时无解」的哨兵
2. while lo ≤ hi:
       mid = lo + (hi − lo) / 2
       if letters[mid] > target:
           ans = mid                  // 命中：记下，再向左找有没有更小的
           hi  = mid − 1
       else:                          // letters[mid] ≤ target
           lo  = mid + 1              // mid 及其左侧全部不可能是答案
3. return ans < n ? letters[ans] : letters[0]
```

两个分支的收缩方向是**刻意不对称**的：命中时 `hi = mid - 1` 是「记录后继续向左」，不命中时 `lo = mid + 1` 是「连同 mid 一起排除」。这正是「找最左满足条件的位置」的标准模板。

### 3.4 示例演算

![两个示例的逐步走查](images/wc62_q1_example_walkthrough.svg)

以示例 2（`letters = ['c','f','j']`，`target = 'c'`）为例：

| 轮次 | $[lo, hi]$ | $mid$ | `letters[mid]` | 比较 | 动作 |
|------|-----------|-------|----------------|------|------|
| 1 | $[0, 2]$ | 1 | `'f'` | `'f' > 'c'` ✓ | `ans = 1, hi = 0` |
| 2 | $[0, 0]$ | 0 | `'c'` | `'c' ≤ 'c'` ✗ | `lo = 1` |
| 结束 | $1 > 0$ | — | — | 区间为空 | `ans = 1 < n` → `'f'` |

再以示例 3（`letters = ['x','x','y','y']`，`target = 'z'`）为例：三轮判定 `'x' ≤ 'z'`、`'y' ≤ 'z'`、`'y' ≤ 'z'` 全部为假，`lo` 一路涨到 $4$ 越界，`ans` 保持初值 $n = 4$，于是走回绕分支返回 `letters[0] = 'x'`。

## 4. 算法细节

1. **上界而非下界**：判定必须写 `letters[mid] > target`（严格）。写成 `>=` 时，只要 `letters` 中出现与 `target` 相同的字母就会返回它本身，示例 2 立刻暴露。Python 对应 `bisect_right`，C++ 对应 `upper_bound`。
2. **哨兵 `ans = n`**：把「还没有解」和「解在下标 $n-1$」区分开。若不用哨兵而用 `ans = -1`，返回前要判 `ans == -1`，且下标类型容易出错；用 $n$ 作哨兵可以少一个分支。
3. **循环结束后 `lo == hi + 1`**：由不变式 (a)，此时 `lo` 恰好等于「$\le$ target 的元素个数」，也就是第一个 $>$ target 的下标（找不到时等于 $n$）。它本身就是答案，`ans` 只是把这个值顺手记下来的中间变量。
4. **`mid` 的写法**：`lo + (hi - lo) / 2` 与 `(lo + hi) / 2` 在本题（$n \le 10^4$）完全等价，但模板化时保持前者，避免大区间时 `lo + hi` 溢出。C++ 对正整数除法向零取整、Python 的 `//` 向下取整，在 $lo \le hi$ 时结果一致，因此两种语言不会出现「一个死循环、一个正常退出」的差异。
5. **区间收缩的完备性**：`hi = mid - 1` 不丢答案，因为 `mid` 已经被 `ans` 记录；`lo = mid + 1` 不丢答案，因为 `mid` 处判定为假。两条都保证区间严格变短，循环必然终止。
6. **字符比较**：小写字母 ASCII 码为 $97 \sim 122$，全部小于 $128$，C++ 中即使是 `signed char` 也不会出现负数比较问题；Python 的 `str` 按 Unicode 码位比较，对小写字母与字典序一致。直接把字符当整数比即可。
7. **不必去重**：输入可能有大量重复（如示例 3 的 `x, x, y, y`），二分天然跳过重复区间，不需要预处理。

## 5. 正确性证明

**引理 1（判定单调）**：对任意 $0 \le i < j < n$，若 $\texttt{letters}[i] > \texttt{target}$，则 $\texttt{letters}[j] > \texttt{target}$。

**证明**：由非递减性 $\texttt{letters}[j] \ge \texttt{letters}[i]$，而 $\texttt{letters}[i] > \texttt{target}$，故 $\texttt{letters}[j] \ge \texttt{letters}[i] > \texttt{target}$。∎

**引理 2（二分不变式）**：在循环的每一次迭代开始前，以下四条同时成立：

- (a) 对任意 $i < lo$，$\texttt{letters}[i] \le \texttt{target}$；
- (b) 对任意 $i > hi$，或者 $\texttt{letters}[i] \le \texttt{target}$，或者 $i \ge ans$；
- (c) `ans` 要么等于 $n$，要么 $\texttt{letters}[ans] > \texttt{target}$；
- (d) 若 $ans < n$，则 $hi < ans$。

**证明**：对迭代次数归纳。初始 $lo = 0$、$hi = n-1$、$ans = n$：条件 (a)(b) 的下标集合为空（空真），(c) 由 $ans = n$ 成立，(d) 的前提 $ans < n$ 为假。

设某轮迭代前四条成立，取 $mid = \lfloor (lo+hi)/2 \rfloor$，则 $lo \le mid \le hi$。

**情形一：$\texttt{letters}[mid] > \texttt{target}$**，令 $ans' = mid$、$hi' = mid - 1$。

- (a)：$lo$ 未变，仍成立。
- (b)：新的「$i > hi'$」即 $i \ge mid$，只比原来多出 $i = mid$ 一个。对 $i = mid$，其判定为真且 $mid = ans'$，故 $i \ge ans'$ 成立；对原本就满足 $i > hi$ 的 $i$，由旧 (b) 要么 $\le \texttt{target}$，要么 $i \ge ans$，而由旧 (d) 有 $hi < ans$（$ans = n$ 时也成立），于是 $i > hi$ 且 $i \ge ans > hi \ge mid$，故 $i > mid = ans'$，仍满足。
- (c)：$ans' = mid$ 刚被判为真。(d)：$hi' = mid - 1 < mid = ans'$，成立。

**情形二：$\texttt{letters}[mid] \le \texttt{target}$**，令 $lo' = mid + 1$。

- (b)(c)(d)：$hi$、`ans` 均未变，仍成立。
- (a)：新增的「$i < lo'$」只多出 $i = mid$，而它满足 $\le \texttt{target}$；其余 $i < lo$ 由旧 (a) 成立。∎

**引理 3（终止时 ans 最优）**：循环终止时，若存在 $i$ 使 $\texttt{letters}[i] > \texttt{target}$，则 `ans` 等于其中最小的那个；否则 $ans = n$。

**证明**：终止条件是 $lo = hi + 1$。由引理 2(a)，所有 $i \le hi$ 都满足 $\texttt{letters}[i] \le \texttt{target}$，故任何真下标都落在 $i > hi$ 中；再由 2(b)，这些真下标都满足 $i \ge ans$。若 $ans < n$，由 2(c) 它本身是真下标，于是它就是全体真下标中最小的一个。若 $ans = n$，则任何真下标 $i$ 都满足 $i \ge n$，而 $i \le n-1$，矛盾，故不存在真下标。∎

**定理**：算法返回 `letters` 中严格大于 `target` 的最小字符；若不存在则返回 `letters[0]`。

**证明**：若存在真下标，由引理 3 得 `ans` 是最小真下标，返回值 `letters[ans]` 即所求最小字符。若不存在真下标，引理 3 给出 $ans = n$，算法返回 `letters[0]`，与题面要求的回绕规则一致。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。每轮迭代把区间长度从 $hi - lo + 1$ 缩小到不超过其一半，最多 $\lceil \log_2 n \rceil + 1$ 轮，每轮 $O(1)$ 的取中、比较与赋值。$n = 10^4$ 时不超过 15 轮，相当于把一万次比较压成十几次。
- **空间**：$O(1)$。只用了 `lo`、`hi`、`ans`、`mid` 四个整型变量，不复制数组、不建额外索引。
- **对照**：线性扫描 $O(n)$、时间可接受但未利用有序性；26 字母枚举 $O(26n)$ 或 $O(26\log n)$，常数大一个量级；哈希集合预处理 $O(n)$ 空间换 $O(1)$ 查询，对本题属于过度设计。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    char nextGreatestLetter(vector<char>& letters, char target) {
        int n = (int)letters.size();
        int lo = 0, hi = n - 1;
        int ans = n;                       // 哨兵：n 表示「暂时没找到」
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (letters[mid] > target) {   // 命中：记录，并继续向左找更小的
                ans = mid;
                hi = mid - 1;
            } else {                       // letters[mid] <= target：连同 mid 一起排除
                lo = mid + 1;
            }
        }
        return ans < n ? letters[ans] : letters[0];
    }
};
```

### Python

```python
class Solution:
    def nextGreatestLetter(self, letters: list[str], target: str) -> str:
        n = len(letters)
        lo, hi, ans = 0, n - 1, n
        while lo <= hi:
            mid = (lo + hi) // 2
            if letters[mid] > target:   # 命中：记录，并继续向左找更小的
                ans = mid
                hi = mid - 1
            else:                       # letters[mid] <= target：连同 mid 一起排除
                lo = mid + 1
        return letters[ans] if ans < n else letters[0]
```

> 💡 竞赛里更短的写法是直接调用库函数（`from bisect import bisect_right`）：`i = bisect_right(letters, target)`，再 `return letters[i] if i < len(letters) else letters[0]`。它与上面的手写二分完全等价，`bisect_right` 的语义就是「第一个 $>$ target 的下标」。

## 8. 边界情况与易错点

1. **`target` 不小于全部元素**（含 `target = 'z'`）：`ans` 保持 $n$，必须回绕返回 `letters[0]`。示例 3 就是这一支，忘写回绕会数组越界或返回错误字符。
2. **答案恰为最后一个元素**：`letters = ['a','y']`、`target = 'x'` 时 `ans = 1 = n - 1 < n`，返回 `'y'`。回绕的唯一条件是 `ans == n`，写成 `ans >= n - 1` 或 `ans + 1 >= n` 都会把正确答案误判成回绕。
3. **与 `target` 相等的重复元素**：`['c','f','j']` + `'c'` 必须跳到 `'f'`；`['a','a','a','b']` + `'a'` 必须跳到 `'b'`。用了 `>=` 或者 `bisect_left` 的写法在这里全线崩。
4. **最小规模输入**：`n = 2`，如 `['a','b']` + `'a'` → `'b'`；二分只跑 1~2 轮，`lo`、`hi` 的边界更新若有偏差就表现为死循环或越界。
5. **全同字符被题目排除**：题面保证至少两个不同字母，所以 `letters[0] < letters[n-1]`；如果自己写测试用例造出 `['a','a']`，回绕时返回 `'a'`，本代码依然正确（返回 `letters[0]`），但这类输入不在题面范围内。
6. **Python 下标越界**：一行流 `letters[bisect_right(letters, target)]` 在 `i == n` 时抛 `IndexError`，必须补 `if i < len(letters)` 判断。
7. **循环条件写成 `lo < hi`**：那样区间只剩一个元素时会直接退出，漏掉最后一次判定。例如 `['a','b']` + `'a'`，正确路径要看一眼 `letters[1] = 'b'`；用 `lo <= hi` 才能保证每个候选都被判定过。
8. **`char` 的符号性**：本题只有小写字母，若不慎传入高位字符，`signed char` 的负数会让比较结果反直觉——把参数当无符号字节（`unsigned char`）或用 Python 的 `str` 就不会有这个问题。
