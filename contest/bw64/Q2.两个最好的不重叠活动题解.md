# LeetCode 两个最好的不重叠活动 题解

## 1. 题目概述

- **标题 / 题号**：两个最好的不重叠活动（#2054，medium）
- **链接**：https://leetcode.cn/problems/two-best-non-overlapping-events/
- **来源**：LeetCode 第 64 场双周赛 Q2
- **难度**：中等
- **标签**：数组、二分查找、动态规划、排序、堆（优先队列）

**题意**：活动数组 `events[i] = [startTime_i, endTime_i, value_i]`。参加一个活动可获得其价值，**最多**选两个**时间不重叠**的活动使价值之和最大。时间闭区间意义上的不重叠：若先参加结束于 $t$ 的活动，下一个活动必须从 $t + 1$ 或之后开始。只参加一个活动（或不参加，价值 0——不过 $value \ge 1$，至少选一个）也可以。返回最大价值和。

**约束**：

- $2 \le events.length \le 10^5$
- $1 \le startTime_i \le endTime_i \le 10^9$
- $1 \le value_i \le 10^6$

## 2. 示例

**示例 1**

```text
输入：events = [[1,3,2],[4,5,2],[2,4,3]]
输出：4
解释：选活动 0（[1,3]，价值 2）与活动 1（[4,5]，价值 2），
3 < 4 不重叠，总价值 4。活动 2 与活动 0、1 都重叠（[2,4] 与 [1,3] 共享 2,3；
[2,4] 与 [4,5] 共享 4），不能同选。
```

**示例 2**

```text
输入：events = [[1,3,2],[4,5,2],[1,5,5]]
输出：5
解释：任何两个活动都重叠，只能选一个，取价值最大的活动 2，价值 5。
```

**示例 3**

```text
输入：events = [[1,5,3],[1,5,1],[6,6,5]]
输出：8
解释：选活动 0（[1,5]）与活动 2（[6,6]），5 < 6 不重叠，价值 3 + 5 = 8。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有活动对 $(i, j)$ 与"只选一个"的方案，判定不重叠后取最大价值，$O(n^2)$。$n = 10^5$ 时 $10^{10}$ 次判定，不可行。DP 暴力是另一条路：按结束时间排序后 $dp[i][j]$（前 $i$ 个活动、已选 $j$ 个的最大价值），转移要找"结束时间严格小于当前开始时间的最近前驱"，朴素找是 $O(n)$，总 $O(n^2)$——同样需要优化，而优化后它正是下面的堆解法。

### 3.2 核心观察：枚举"靠后的活动"，用堆维护"已结束活动的最大价值"

![核心观察：按开始时间扫描，小根堆里的活动按结束时间出堆](images/bw64_q2_sweep_heap.svg)

关键视角转换：**枚举两个活动中的后者**。设当前活动 $e$ 从 $s$ 开始，那么与它兼容的伙伴是所有满足 $end < s$ 的活动中价值最大者。于是：

1. 把活动按**开始时间**升序排序，顺序扫描；
2. 维护一个小根堆（按结束时间），存放"开始时间已过、但尚未越过当前活动开始时刻"的活动；
3. 扫到活动 $s$ 时，把堆顶所有 $end < s$ 的活动弹出，弹过的活动都是 $e$ 的潜在伙伴——用变量 $best$ 记录它们的最大价值；
4. 答案候选为 $value_e + best$（只选 $e$ 对应 $best = 0$ 的初始情形）。

由于扫描按开始时间单调推进、堆顶结束时间单调，每个活动最多进堆一次、出堆一次，整体 $O(n \log n)$。

> 💡 等价的 DP 视角：$best$ 就是"结束时间早于当前开始时间的活动前缀"的最大价值，堆只是把"哪些活动已可用"这一事件流组织了起来。

### 3.3 算法流程

![算法流程：排序、弹堆更新 best、更新答案、入堆](images/bw64_q2_flow.svg)

```text
1. events 按开始时间升序排序（开始时间相同任意序）
2. pq ← 空小根堆（键：结束时间），best = 0，ans = 0
3. for e = (s, t, v) in events（按开始时间）:
       while pq 非空且 pq 顶的结束时间 < s:
           best = max(best, 弹出活动的价值)
       ans = max(ans, v + best)
       pq.push((t, v))
4. 返回 ans
```

正确性的两个要点：**先弹后算**——必须把所有 $end < s$ 的活动并入 $best$ 之后再计算 $v + best$，顺序颠倒会把尚未结束的活动错误计入；**共享端点算重叠**——弹堆条件是严格小于，$end = s$ 的活动此刻仍在堆中，不作为伙伴。

### 3.4 示例演算（示例 1）

`events = [[1,3,2],[4,5,2],[2,4,3]]`，按开始时间排序后为 `[1,3,2], [2,4,3], [4,5,2]`：

| 步骤 | 当前活动 $(s,t,v)$ | 弹堆（$end < s$） | $best$ | 候选 $v + best$ | $ans$ | 堆内容 |
|------|--------------------|-------------------|--------|------------------|-------|--------|
| 1 | $(1,3,2)$ | 无 | 0 | 2 | 2 | (3,2) |
| 2 | $(2,4,3)$ | 无（$3 \ge 2$ 不弹） | 0 | 3 | 3 | (3,2),(4,3) |
| 3 | $(4,5,2)$ | 弹 $(3,2)$ | 2 | 4 | **4** | (4,3),(5,2) |

返回 $4$，与官方答案一致。注意第 2 步中 $end = 3 \ge start = 2$，活动 0 尚不可用；第 3 步 $end = 3 < 4$ 弹出后活动 0 才成为伙伴。

## 4. 算法细节

1. **排序键**：按开始时间升序。开始时间相同的活动顺序无所谓——它们两两必不兼容吗？不一定（$[1,3]$ 与 $[3,5]$ 开始时间不同；$[1,3]$ 与 $[1,3]$ 相同且重叠），但同开始时间的活动互不兼容（$s_1 = s_2$ 时 $end_1 \ge s_1 = s_2 > end_2$ 不可能成立，即谁也不满足 $end < s$），扫描中后处理的那个不会把先处理的当作伙伴（先入堆者的 $end \ge s$，不会被弹出），逻辑自洽。
2. **弹堆条件是严格小于**：`pq.top().end < s`。写成 `<=` 会把 $end = s$ 的活动误当作兼容——按题意 $end = s$ 重叠。
3. **$best$ 单调不减**：只被 `max` 更新，天然满足"前缀最大"语义，无需回退。
4. **只选一个 / 空堆情形**：$best$ 初始为 0，第一次循环或堆一直未弹出时候选退化为 $v$，覆盖"只参加一个活动"。全重叠时答案就是最大单价值（示例 2 的 5）。
5. **溢出**：两个价值之和 $\le 2 \times 10^6$，`int` 安全。
6. **C++ 堆的写法**：`priority_queue<pair<int,int>, vector<...>, greater<>>` 以 `first`（结束时间）为小根；也可以排结束时间 + 二分写法：按结束时间排序后前缀最大值数组 `pre[i]`，对每个活动二分最后一个 $end < s$ 的位置取 `pre`——两版等价，堆版无需二分边界调试。

## 5. 正确性证明

**引理 1（伙伴刻画）**：活动 $a$ 与 $b$（$s_a \le s_b$）不重叠当且仅当 $end_a < s_b$。

**证明**：闭区间 $[s_a, end_a]$ 与 $[s_b, end_b]$ 不相交（$s_a \le s_b$ 时即 $end_a < s_b$）恰是题目"先参加结束于 $t$ 的活动则下一个须从 $t+1$ 或之后开始"的形式化。∎

**引理 2（弹堆时机正确）**：扫描到活动 $e$（开始时间 $s$）时，堆中恰存放所有"已处理且结束时间 $\ge$ 此前已处理活动的开始时刻"的活动（即尚未被任何扫描步弹出的活动）；且此刻的 $best$ 等于所有满足 $end' < s$ 的已处理活动的最大价值。

**证明**：归纳。初始堆空、$best = 0$ 成立。设处理开始时间 $s$ 的活动前不变量成立。本步先弹出全部 $end < s$ 的堆内元素并更新 $best$；由于弹出条件只与 $s$ 有关且堆以 $end$ 为小根，弹出的恰是堆中全部 $end < s$ 者（其余 $end \ge s$ 留在堆中）。被弹出者都是此前入堆的活动（开始时间 $\le s$），故弹出后 $best$ = 已处理活动中 $end < s$ 者的最大价值。未弹出者 $end \ge s$，留在堆中等待更晚的扫描时刻。随后当前活动入堆，不变量对下一次扫描（开始时间 $s'' \ge s$）依然成立。∎

**定理（算法返回最优值）**：设最优方案选了 $m \le 2$ 个不重叠活动，价值和 $OPT$，则算法返回值 $ans = OPT$。

**证明**：算法的每个候选值 $v + best$ 都对应一个合法方案（活动 $e$ 加上一个 $end < s_e$ 的活动，或 $best = 0$ 时仅 $e$），故 $ans \le OPT$。反之对最优方案分类：（i）$m \le 1$：该活动价值 $\le$ 全局最大价值，会在其扫描步以 $v + 0 \ge v$ 被 $ans$ 覆盖；（ii）$m = 2$：设两活动为 $a$（靠前，$end_a < s_b$）与 $b$（靠后）。扫描到 $b$ 时，$a$ 已处理（$s_a \le s_b$）且 $end_a < s_b$，由引理 2，$best \ge value_a$，候选 $value_b + best \ge value_b + value_a = OPT$，被 $ans$ 覆盖。故 $ans \ge OPT$，结合得 $ans = OPT$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；每个活动入堆一次、至多出堆一次，堆操作 $O(\log n)$，总计 $O(n \log n)$。
- **空间**：$O(n)$。堆最坏同时存放全部活动（全部互相重叠时）；排序额外 $O(\log n)$（C++ 原地）或 $O(n)$（Python）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxTwoEvents(vector<vector<int>>& events) {
        sort(events.begin(), events.end());          // 按开始时间升序
        priority_queue<pair<int, int>, vector<pair<int, int>>, greater<pair<int, int>>> pq; // (end, value)
        int best = 0, ans = 0;                       // best：所有已结束活动中的最大价值
        for (auto& e : events) {
            while (!pq.empty() && pq.top().first < e[0]) {   // end < start ⇒ 不重叠
                best = max(best, pq.top().second);
                pq.pop();
            }
            ans = max(ans, e[2] + best);             // 当前活动 + 之前结束的最佳活动
            pq.emplace(e[1], e[2]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxTwoEvents(self, events: List[List[int]]) -> int:
        events.sort()                              # 按开始时间升序
        pq = []                                    # 小顶堆：(end, value)
        best = 0                                   # 已结束活动中的最大价值
        ans = 0
        for st, en, val in events:
            while pq and pq[0][0] < st:            # end < start ⇒ 不重叠
                best = max(best, heapq.heappop(pq)[1])
            ans = max(ans, val + best)
            heapq.heappush(pq, (en, val))
        return ans
```

> 💡 两份代码均通过官方全部 3 组示例，并与"枚举全体活动对 + 单活动取最大"的暴力实现做了 500 组随机对拍（含完全重叠、共享端点 $end = start$、单活动最优等情形），结果完全一致；另在 $n = 10^5$ 随机规模实测（C++ 0.22s / Python 0.44s）。

## 8. 边界情况与易错点

1. **共享端点算重叠**：兼容条件是 $end < start$（严格）。$[1,3]$ 与 $[3,5]$ 不能同选。弹堆条件误写成 `<=` 是最高频错误。
2. **只选一个活动**：$best = 0$ 的初始值天然覆盖；不要把 `ans` 初始化成 $-\infty$ 后忘记单活动候选。
3. **先弹堆再计算答案**：顺序颠倒会把"此刻仍重叠"的活动错误计入 $best$。
4. **同开始时间的活动**：互不兼容，任意顺序处理都不影响正确性（见 §4.1），无需特意按结束时间二次排序。
5. **大数据下别用 $O(n^2)$**：$n = 10^5$ 时双重循环必然超时；DP 朴素版（线性找前驱）同样超时，必须堆或二分。
6. **堆里存什么**：存 $(end, value)$，键是结束时间；只存结束时间会丢价值，存价值做键则弹堆顺序错误。
7. **价值全为正**（$value \ge 1$），"不选任何活动"（价值 0）永远不优；若题目变体允许负价值，需把候选改成显式的三者比较（0、单活动、双活动）。
