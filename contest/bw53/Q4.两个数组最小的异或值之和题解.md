# LeetCode 两个数组最小的异或值之和 题解

## 1. 题目概述

- **标题 / 题号**：两个数组最小的异或值之和（#1879，hard）
- **链接**：https://leetcode.cn/problems/minimum-xor-sum-of-two-arrays/
- **来源**：LeetCode 第 53 场双周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、动态规划、位掩码、状态压缩

**题意**：给定长度均为 $n$ 的两个数组 `nums1` 与 `nums2`。可以**重排 `nums2`**，求 $\sum_{i=0}^{n-1} (nums1[i] \oplus nums2[\sigma(i)])$ 的最小值，其中 $\sigma$ 是一个排列。返回该最小值。

**约束**：

- $n = nums1.length = nums2.length$
- $1 \le n \le 14$
- $0 \le nums1[i], nums2[i] \le 10^7$

## 2. 示例

**示例 1**

```text
输入：nums1 = [1,2], nums2 = [2,3]
输出：2
解释：重排 nums2 为 [3,2]，(1 XOR 3) + (2 XOR 2) = 2 + 0 = 2。
```

**示例 2**

```text
输入：nums1 = [1,0,3], nums2 = [5,3,4]
输出：8
解释：重排 nums2 为 [5,4,3]，(1 XOR 5) + (0 XOR 4) + (3 XOR 3) = 4 + 4 + 0 = 8。
```

**示例 3（边界补充）**

```text
输入：nums1 = [7], nums2 = [7]
输出：0
解释：n = 1 只有一种配对，7 XOR 7 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `nums2` 的全部 $n!$ 个排列，逐个求异或和取最小。$n = 14$ 时 $14! \approx 8.7 \times 10^{10}$，彻底不可行。搜索树中存在大量重叠子问题（前 $k$ 个位置配了相同的 `nums2` 下标集合，代价只与集合有关、与配对顺序无关），提示用**状态压缩 DP** 压掉排列内部的顺序冗余。

### 3.2 核心观察：配对 = 完全二分图最小权匹配 → 状压 DP

![状态设计：配对问题与 dp 掩码](images/bw53_q4_bitmask_model.svg)

把 `nums1` 的每个下标与 `nums2` 的每个下标连一条权为 $nums1[i] \oplus nums2[j]$ 的边，问题即**完全二分图最小权完美匹配**。$n \le 14$ 的关键意义是：`nums2` 下标集合可用 $2^{14} = 16384$ 个位掩码表示。定义

$$dp[mask] = \text{「前 } popcount(mask) \text{ 个 nums1 元素已与 mask 所示的 nums2 下标配对」的最小异或和}$$

「前 $k$ 个」的设计消除了顺序冗余：**不需要记录具体是哪 $k$ 个 `nums1`**（固定按前缀推进），也不需要记录配对顺序（代价与顺序无关）。

### 3.3 状态转移：枚举最后配对的 nums2 下标

![状态转移：枚举最后配对位](images/bw53_q4_dp_transition.svg)

设 $mask$ 含 $k$ 个 1 位，则已配 $nums1[0..k-1]$，正在决策第 $k$ 个（下标 $i = k - 1$）与谁配对。枚举 $mask$ 中每个 1 位 $j$（作为「最后一个被配对」的下标）：

$$dp[mask] = \min_{j \in mask} \left\{ dp[mask \setminus \{j\}] + \big(nums1[k-1] \oplus nums2[j]\big) \right\}$$

初始 $dp[\varnothing] = 0$，答案 $dp[\text{全 1 掩码}]$。每个状态转移 $O(n)$，总复杂度 $O(2^n \cdot n)$。

### 3.4 示例演算

![示例演算：n=3 的 dp 表](images/bw53_q4_example_walkthrough.svg)

以示例 2（$nums1 = [1,0,3]$、$nums2 = [5,3,4]$）为例，8 个状态的 $dp$ 值依次为 $0, 4, 2, 7, 5, 8, 6, 8$（见上图逐层展开），最终 $dp[111_2] = 8$，对应重排 $nums2 = [5,4,3]$。

## 4. 算法细节

1. **下标含义统一**：约定 `mask` 的第 $j$ 位为 1 表示 `nums2[j]` 已被占用；`popcount(mask)` 恰等于已配对的 `nums1` 前缀长度，于是「当前待配的 nums1 下标」$i = popcount(mask) - 1$ 在转移时现场计算。
2. **正向填表**：按 `mask` 从 $1$ 到 $2^n - 1$ 升序枚举，保证转移来源 `mask ^ (1 << j)`（数值更小）已就绪；也可记忆化搜索，但正向循环无递归开销、常数更小。
3. **初始值与不可达**：`dp[0] = 0`，其余初始化为 $\infty$；由于每个非空 `mask` 的转移来源都非空且可达，实际上不会残留 $\infty$（可不写可达性判断）。
4. **溢出**：单对异或值 $< 2^{24}$（$nums \le 10^7 < 2^{24}$），总和 $< 14 \times 2^{24} \approx 2.3 \times 10^8$，`int` 够用；`INT_MAX/2` 作 $\infty$ 可防加法溢出。
5. **位运算加速转移**（可选）：`for (int j = 0; j < n; ++j) if (mask >> j & 1)` 直接逐位测试即可；$2^{14} \times 14 \approx 2.3 \times 10^5$ 次内层操作，无需进一步优化。
6. **为什么不按 `nums1` 的集合做状态**：对称做法（`mask` 表示 `nums1` 已配下标）同样正确；习惯上固定一侧按前缀推进、另一侧用掩码，代码最短。
7. **更优算法的存在性**：本题等价于最小权完美匹配，可用 **KM 算法**（$O(n^3)$）或 SSP + Dijkstra（$O(n^3)$）解决，$n \le 14$ 时状压 DP 已绰绰有余，且实现短、不易错。

## 5. 正确性证明

**引理 1（代价与配对顺序无关）**：设 $\sigma$ 为排列，则 $\sum_i (nums1[i] \oplus nums2[\sigma(i)])$ 只依赖配对关系 $\{(i, \sigma(i))\}$ 本身，与「配对的先后次序」无关。

**证明**：求和是交换的，每一项只由二元关系 $(i, \sigma(i))$ 决定。∎

**引理 2（DP 值良定义且有限）**：对每个 `mask`，$dp[mask]$ 的定义域非空（至少存在一种把前 $k$ 个 `nums1` 与 `mask` 的双射），且 $dp[mask]$ 是这些方案代价的最小值。

**证明**：归纳于 $|mask|$。$|mask| = 0$ 时唯一空方案代价 $0$。设 $|mask| = k \ge 1$、$j_1 < \dots < j_k$ 为 `mask` 的位。任何「前 $k$ 个 `nums1` 与 $\{j_1, \dots, j_k\}$ 双射」的方案 $\pi$（$nums1[i] \leftrightarrow j_{\pi(i)}$）可唯一分解为「前 $k-1$ 个与某 $(k-1)$ 子集 $S$ 双射」+「$nums1[k-1]$ 配 $mask \setminus S$ 中唯一的 $j$」。反之任取 $j \in mask$ 与一个 $(k-1)$ 子集方案复合得到完整方案。故方案集合恰为 $\bigcup_{j \in mask} \{$「$nums1[k-1]$ 配 $j$」$\times$「前 $k-1$ 个配 $mask \setminus \{j\}$ 的方案」$\}$，两两不相交（由 $j$ 区分），每个都有有限代价，最小值存在。∎

**定理（转移方程的正确性）**：对 $|mask| = k \ge 1$，

$$dp[mask] = \min_{j \in mask} \left\{ dp[mask \setminus \{j\}] + \big(nums1[k-1] \oplus nums2[j]\big) \right\}$$

**证明**：由引理 2 的分解，`mask` 的最优方案必然属于某个 $j$ 分支。固定 $j$：该分支内的总代价 = （$nums1[k-1]$ 配 $j$ 的代价）+（前 $k-1$ 个配 $mask \setminus \{j\}$ 的最优代价 $dp[mask \setminus \{j\}]$），后者由归纳假设正确计算（$|mask \setminus \{j\}| = k - 1$ 更小，且其 $dp$ 值不依赖「之后 $nums1[k-1]$ 配谁」——因为前 $k-1$ 个的代价只由自身配对决定，两部分代价可分离）。对 $j$ 取 min 即覆盖所有分支且每分支取到最优，故等式成立。∎

**定理（算法正确性）**：算法返回 $dp[2^n - 1]$，即所有 $n!$ 个排列代价的最小值。

**证明**：$|mask| = n$ 时 `mask` 为全 1 掩码，「前 $n$ 个 `nums1` 与全部 `nums2` 下标配对」恰是全部完美匹配（排列）。由引理 1 代价与顺序无关，由引理 2 与转移定理，$dp[\text{全 1}]$ 逐层归纳地等于这些匹配代价的最小值。∎

## 6. 复杂度分析

- **时间**：$O(2^n \cdot n)$。状态 $2^n \le 16384$ 个，每个转移至多 $n = 14$ 次；总计约 $2.3 \times 10^5$ 次基本操作，远低于 1 秒。
- **空间**：$O(2^n)$。一维 `dp` 数组（`int` 时 64 KB）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumXORSum(vector<int>& nums1, vector<int>& nums2) {
        int n = (int)nums1.size();
        int FULL = 1 << n;
        const int INF = INT_MAX / 2;
        vector<int> dp(FULL, INF);
        dp[0] = 0;
        for (int mask = 1; mask < FULL; ++mask) {
            int i = __builtin_popcount(mask) - 1;   // 正在配 nums1[i]
            int& best = dp[mask];
            for (int j = 0; j < n; ++j)
                if (mask >> j & 1) {
                    int cand = dp[mask ^ (1 << j)] + (nums1[i] ^ nums2[j]);
                    if (cand < best) best = cand;
                }
        }
        return dp[FULL - 1];
    }
};
```

### Python

```python
class Solution:
    def minimumXORSum(self, nums1: list[int], nums2: list[int]) -> int:
        n = len(nums1)
        FULL = 1 << n
        INF = float("inf")
        dp = [INF] * FULL
        dp[0] = 0
        for mask in range(1, FULL):
            i = bin(mask).count("1") - 1             # 正在配 nums1[i]
            best = INF
            rest, j = mask, 0
            while rest:                               # 只扫 1 位，稍快
                if rest & 1:
                    cand = dp[mask ^ (1 << j)] + (nums1[i] ^ nums2[j])
                    if cand < best:
                        best = cand
                rest >>= 1
                j += 1
            dp[mask] = best
        return dp[FULL - 1]
```

> 💡 两份代码均通过官方示例（`2`、`8`）；并与「枚举全部 $n!$ 排列」的暴力实现大规模对拍：C++ 侧 3 万组（$n \le 7$，值域含 $[0, 127]$ 与 $[0, 10^7]$ 两档）+ $n = 14$ 满规模性能冒烟，Python 侧 4200 组（含 $n = 8$ 全排列 40320 种），全部 `mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：`dp[1] = nums1[0] ^ nums2[0]`，直接返回；无需特判。
2. **`popcount` 的下标对应**：`i = popcount(mask) - 1` 容易写错成 `popcount(mask)`；前者表示「mask 含 $i+1$ 个已用下标，第 $i$ 个（0 基）nums1 正在配」。
3. **C++ `__builtin_popcount`**：GCC/Clang 内建函数，MSVC 需换 `__popcnt` 或手写循环；`INT_MAX / 2` 作 $\infty$ 防止 `INF + cost` 溢出为负。
4. **转移方向**：只能「去掉一个 1 位」向更小 `mask` 转移；若误写成「加上一个 1 位」（`dp[mask | 1<<j]`）会漏掉/重复计数，且需保证遍历顺序按位单调。
5. **两数组角色不可混**：状态掩码固定套在 `nums2` 上、前缀推进固定套在 `nums1` 上；写反（用 `nums2` 的下标做 $i$）在非对称输入下会得到错误答案——对拍时用不对称数组即可抓出。
6. **大值域**：$10^7 < 2^{24}$，单次异或无溢出；但若题目改成 $10^{18}$ 需换 `long long`。
7. **「重排 nums2」而非「重排 nums1」**：两者等价（取 $\sigma^{-1}$），但按题面固定重排 `nums2` 可避免歧义。
