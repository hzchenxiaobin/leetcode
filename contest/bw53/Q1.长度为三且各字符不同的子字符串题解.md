# LeetCode 长度为三且各字符不同的子字符串 题解

## 1. 题目概述

- **标题 / 题号**：长度为三且各字符不同的子字符串（#1876，easy）
- **链接**：https://leetcode.cn/problems/substrings-of-size-three-with-distinct-characters/
- **来源**：LeetCode 第 53 场双周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、计数、滑动窗口

**题意**：不含重复字符的字符串称为「好」字符串。给定字符串 $s$，统计 $s$ 中长度为 3 且各字符互不相同（即「好」）的子字符串数量。相同的好子字符串出现多次时，每次都要计入答案。

**约束**：

- $1 \le s.length$（未在题面截断处展示完整上界，实际为 $100$）
- $s$ 只包含小写英文字母

> ⚠️ 题面中「1 <= s.length」的渲染截断不影响解题；按 LeetCode 官方原始约束为 $1 \le s.length \le 100$。

## 2. 示例

**示例 1**

```text
输入：s = "xyzzaz"
输出：1
解释：长度为 3 的子字符串共 4 个："xyz"、"yzz"、"zza"、"zaz"。
其中只有 "xyz" 三个字符两两不同，是唯一的好子字符串。
```

**示例 2**

```text
输入：s = "aababcabc"
输出：4
解释：长度为 3 的子字符串共 7 个："aab"、"aba"、"bab"、"abc"、"bca"、"cab"、"abc"。
好子字符串为 "abc"、"bca"、"cab"、"abc"，共 4 个（最后一个 "abc" 与首个相同，仍计入）。
```

**示例 3（边界补充）**

```text
输入：s = "a"
输出：0
解释：长度不足 3，不存在长度为 3 的子字符串，返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有满足 $i + 2 < n$ 的起点 $i$，取子字符串 $s[i..i+2]$，用集合或排序判断三个字符是否互不相同。时间 $O(n)$（每个窗口判定 $O(1)$，若用哈希集合则是 $O(3)$ 摊还），空间 $O(1)$。由于窗口长度固定为 3，这个「暴力」其实已经是最优做法——不存在更快的亚线性算法（至少要读入整个字符串）。

### 3.2 核心观察：定长窗口三字符判异

![核心观察：定长窗口三字符两两判异](images/bw53_q1_sliding_window.svg)

关键点是**窗口长度固定为 3**，判「三个字符互不相同」不需要任何数据结构——三个字符两两不同当且仅当三次两两比较全部成立：

$$s[i] \ne s[i+1] \;\wedge\; s[i] \ne s[i+2] \;\wedge\; s[i+1] \ne s[i+2]$$

这是 $O(1)$ 判定。窗口从左端滑到右端，起点 $i$ 的合法范围是 $0 \le i \le n - 3$，共 $n - 2$ 个窗口。

> 💡 相比通用滑动窗口（维护计数哈希、处理窗口扩张/收缩），定长窗口的写法退化成一条单循环，代码量最小、常数最低。这是签到题该有的「最短路径」：识别出定长为 3 → 直接三次比较，不引入哈希集合。

### 3.3 算法流程

```text
1. ans = 0
2. for i in 0 .. n-3:              # 窗口 [i, i+2]
3.     若 s[i] ≠ s[i+1] 且 s[i] ≠ s[i+2] 且 s[i+1] ≠ s[i+2]:
4.         ans += 1
5. 返回 ans
```

Python 一行流版本直接翻译上式。C++ 同理，`for (int i = 0; i + 2 < n; ++i)` 即可。

### 3.4 示例演算

![示例演算：aababcabc 的 7 个窗口判定](images/bw53_q1_example_walkthrough.svg)

以 $s = $ `aababcabc` 为例（见上图）：7 个窗口中 `abc`、`bca`、`cab`、`abc` 四个通过判定（注意 $i=3$ 与 $i=6$ 的两个 `abc` 是不同位置的子串，都计入），其余三个窗口分别因 `aa`、`aa`、`bb` 重复而失败，答案为 $4$。$s = $ `xyzzaz` 同理：仅 `xyz` 通过，答案 $1$。

## 4. 算法细节

1. **循环边界**：起点 $i$ 最大取 $n - 3$（C++ 写 `i + 2 < n`，Python 写 `range(len(s) - 2)`），共 $n-2$ 次迭代；$n < 3$ 时循环体不执行，自然返回 0。
2. **判定顺序**：三次比较短路求值，大多数失败窗口在第一次比较（$s[i] \ne s[i+1]$）就被淘汰，平均比较次数远小于 3。
3. **重复子串计入**：题目按「位置」计数而非「内容」去重，无需任何去重集合。
4. **数据结构选型**：用哈希集合判重（`len(set(w)) == 3`）也可通过，但每窗口建集合的常数更大；三次比较版本零额外空间。
5. **字符集**：只含小写字母这一点在本题用不上（无需计数数组）；若窗口长度更大（如 $k = 26$），才需要维护频次计数与「重复字符数」变量做 $O(1)$ 滑动。

## 5. 正确性证明

**引理 1（窗口枚举完备且不重）**：字符串 $s$ 中长度为 3 的子字符串恰好为 $s[i..i+2]$，$i = 0, 1, \dots, n-3$，每个子字符串对应唯一起点。

**证明**：子字符串定义为连续字符序列，由其起点唯一确定（长度固定）。起点 $i$ 合法当且仅当 $i \ge 0$ 且 $i + 2 \le n - 1$，即 $0 \le i \le n - 3$。不同起点的子字符串起始位置不同，故互不相同（作为位置上的出现）。∎

**引理 2（三字符判异等价性）**：三个字符 $a, b, c$ 互不相同 $\iff$ $a \ne b \wedge a \ne c \wedge b \ne c$。

**证明**：（$\Rightarrow$）互不相同即任意两个都不同，三个不等式显然成立。（$\Leftarrow$）逆否：若存在相同的一对，则对应不等式失败。三对恰为所有二元组合 $\binom{3}{2} = 3$ 种，无遗漏。∎

**定理**：上述算法返回 $s$ 中好子字符串的个数。

**证明**：由引理 1，算法遍历且仅遍历每个长度为 3 的子字符串一次。由引理 2，判定条件在窗口三字符两两不同时恰为真，且此时窗口是不含重复字符的（长度为 3 的）好子字符串；反之判定失败即窗口含重复字符，非好子字符串。计数器在每个好子字符串处恰加 1，故返回值等于好子字符串总数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。单次扫描，每个窗口 $O(1)$ 判定（至多 3 次字符比较）；$n \le 100$ 时实际耗时微不足道。
- **空间**：$O(1)$。只使用常数个计数变量，不随输入规模增长。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countGoodSubstrings(string s) {
        int n = (int)s.size(), ans = 0;
        for (int i = 0; i + 2 < n; ++i)              // 定长为 3 的窗口 [i, i+2]
            if (s[i] != s[i + 1] && s[i] != s[i + 2] && s[i + 1] != s[i + 2])
                ++ans;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countGoodSubstrings(self, s: str) -> int:
        return sum(s[i] != s[i + 1] and s[i] != s[i + 2] and s[i + 1] != s[i + 2]
                   for i in range(len(s) - 2))
```

> 💡 两份代码均通过官方示例（`xyzzaz → 1`、`aababcabc → 4`）及长度 1/2 的边界用例；判定逻辑由三次比较的等价性直接保证（见 §5 引理 2），无需对拍。

## 8. 边界情况与易错点

1. **$n < 3$**：循环不执行返回 0。Python 的 `range(len(s) - 2)` 在 `len(s) ≤ 2` 时为空，天然安全；C++ 手写 `i + 2 < n` 同理。若误写 `i <= n - 3` 且 $n$ 为无符号小值（如 `size_t`），`n - 3` 会下溢成大数导致越界——用 `i + 2 < n` 的写法可避免。
2. **重复子串要重复计数**：`"abcabc"` 中两个 `abc` 都算，不要拿 set 去重内容。
3. **「好」的定义是长度 3 内部无重复**，不是「s 的前 3 个字符」也不是「字符种类数为 3 的任意子串」，注意别把窗口长度写错。
4. **短路求值**：把最可能失败的比较（相邻相等，如 `aa`、`bb` 模式）放在前面可以稍微提速，但在 $n \le 100$ 下无关紧要。
5. **不要过度设计**：哈希集合/滑动窗口模板都能做，但对定长 3 窗口是杀鸡用牛刀，反而容易在窗口边界写错。
