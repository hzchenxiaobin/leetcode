# LeetCode 数组中最大数对和的最小值 题解

## 1. 题目概述

- **标题 / 题号**：数组中最大数对和的最小值（#1877，medium）
- **链接**：https://leetcode.cn/problems/minimize-maximum-pair-sum-in-array/
- **来源**：LeetCode 第 53 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、双指针、排序

**题意**：给定长度为偶数 $n$ 的数组 `nums`，将其分成 $n/2$ 个数对（每个元素恰好属于一个数对），数对和为数对内两元素之和。最大化「最小」：在所有配对方案中，使**最大数对和**尽可能小，返回该最小可能值。

**约束**：

- $n = nums.length$
- $2 \le n \le 10^5$
- $n$ 是偶数
- $1 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [3,5,2,3]
输出：7
解释：分成数对 (3,3) 和 (5,2)，数对和分别为 6 与 7，最大数对和 = 7。
```

**示例 2**

```text
输入：nums = [3,5,4,2,4,6]
输出：8
解释：分成数对 (3,5)、(4,4)、(6,2)，数对和分别为 8、8、8，最大数对和 = 8。
```

**示例 3（边界补充）**

```text
输入：nums = [1, 100000]
输出：100001
解释：n = 2 只有一种配对，两数必须同队，最大数对和 = 1 + 100000。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有配对方案：第 1 个未配对元素任意挑一个搭档，递归展开，共 $(n-1)!! = (n-1)(n-3)\cdots 3 \cdot 1$ 种（$n = 10$ 时 945 种，$n = 14$ 时已超百万）。$n \le 10^5$ 完全不可行，且状态空间没有明显的记忆化结构（本质是完全匹配枚举）。

### 3.2 核心观察：排序后首尾配对

![核心观察：排序后首尾配对](images/bw53_q2_two_pointer_pairing.svg)

直觉：**最大数对和被「大数」主导**。若两个大数同队，它们的和直接顶到上限；若把最大数与最小数配对，最大数「拖着一个垫底的」，数对和被压下来。正式表述：将数组升序排序后，第 $i$ 小的数与第 $i$ 大的数配对（$i = 0, \dots, n/2 - 1$）：

$$\text{ans} = \max_{0 \le i < n/2} \left( nums[i] + nums[n - 1 - i] \right)$$

反例对照（见上图右半）：「小配小、大配大」让 5、6 同队，和为 11，明显劣于首尾配对的 8。

### 3.3 交换论证：为什么首尾配对最优

![交换论证：拆开大×大同队](images/bw53_q2_exchange_argument.svg)

排序后任取最优方案中的两对 $(a, b)$ 与 $(c, d)$，不妨设 $a \le b \le c \le d$（即两对是「嵌套」或「交错」关系）。关键事实：**最优方案中不会出现两个较大数同队而较小数被拆开的情况**，因为交叉重配后最大值不增：

$$\max(a + d, \; b + c) \;\le\; c + d \;\le\; \max(a + b, \; c + d)$$

详细推导见 §5 定理证明。反复应用该交换，任何方案都可被改造成「首尾配对」且最大数对和不增——所以首尾配对就是最优的。

### 3.4 示例演算

![示例演算：两个官方例子的排序与首尾配对](images/bw53_q2_example_walkthrough.svg)

例 1：`[3,5,2,3]` 排序为 `[2,3,3,5]`，配对 $(2,5) \to 7$、$(3,3) \to 6$，答案 $7$。
例 2：`[3,5,4,2,4,6]` 排序为 `[2,3,4,4,5,6]`，配对 $(2,6) \to 8$、$(3,5) \to 8$、$(4,4) \to 8$，答案 $8$。

## 4. 算法细节

1. **排序**：升序排序是整个贪心的前提；`sort` 为 $O(n \log n)$，主导总复杂度。
2. **双指针形态**：实现上等价于双指针 `l = 0, r = n - 1`，每轮计算 `nums[l] + nums[r]` 后 `l++, r--`，直到相遇。与排序配合即「首尾配对」。
3. **配对数恰为 $n/2$**：循环 $i$ 从 0 到 $n/2 - 1$，共 $n/2$ 对，元素全部各用一次。
4. **溢出**：$nums[i] \le 10^5$，两数之和 $\le 2 \times 10^5$，`int` 完全够用，无需 `long long`。
5. **为什么与「总和守恒」无关**：所有数对和的总和恒为 $\sum nums$（每个元素恰好计入一次），但这只说明平均值固定——本题要压的是**最大值**，与「平均分配」直觉不同，排序贪心才是正确抓手。

## 5. 正确性证明

**引理 1（交叉重配不等式）**：设 $a \le b \le c \le d$ 为四个数，则

$$\max(a + d, \; b + c) \;\le\; \max(a + b, \; c + d)$$

**证明**：由 $b \le d$ 得 $a + d \le a + d + (d - b)$ 不直接可用，改证逐项控制：$b + c \le c + d$（因 $b \le d$）；$a + d \le c + d$（因 $a \le c$）。于是两个「交叉和」都不超过 $c + d$，而 $c + d \le \max(a + b, c + d)$。故交叉配对的最大值 $\max(a+d, b+c) \le \max(a+b, c+d)$，即不超过原配对的最大值。∎

**引理 2（首尾配对的下界刻画）**：设排序后为 $x_0 \le x_1 \le \dots \le x_{n-1}$。任何配对方案 $P$ 的最大数对和 $M(P)$ 满足 $M(P) \ge x_{n-1} + x_0$ 不一定成立（这不是引理内容）；但必有 $M(P) \ge \max_i (x_i + x_{n-1-i})$ **不**成立——正确刻画是：**首尾配对方案 $P^*$ 的最大值 $M^* = \max_i (x_i + x_{n-1-i})$，且 $M^*$ 是「最大数对和」在所有方案中的最小值**。证明见定理。

**定理（排序首尾配对的最优性）**：对任意配对方案 $P$，存在有限次「交换」将 $P$ 变换为首尾配对方案 $P^*$，且每次交换不增大最大数对和。从而 $M(P^*) \le M(P)$ 对一切 $P$ 成立，首尾配对最优。

**证明**：对 $P$ 中任意两对 $(x_i, x_j)$、$(x_p, x_q)$（下标为排序后位置），若它们「非交叉」（即 $\max(i,j) < \min(p,q)$ 或互不交错），不动。设存在两对 $(x_i, x_j)$ 与 $(x_p, x_q)$ 满足 $i \le p \le q \le j$（嵌套）或 $i \le p \le j \le q$（半交叉），统称「可交叉化」：将其重配为 $(x_i, x_q)$ 与 $(x_p, x_j)$（保持 $i \le p$、$q \ge j$ 的配对端点位置关系——即较小下标配较大下标）。由排序单调性，这四数满足 $x_i \le x_p \le x_j \le x_q$（嵌套情形）或 $x_i \le x_p \le x_j \le x_q$（半交叉同理重排后适用），由引理 1，新两对的最大和不超过原来两对的最大和，且不影响其他数对，故 $M$ 不增。定义势函数 $\Phi(P) = \sum_{\text{对 }(u,v)} |u - v|$（下标距离之和）：每次上述交换严格使配对更「交叉」（$\Phi$ 严格增），而 $\Phi$ 有上界 $\binom{n}{2}$，故交换在有限步后终止；终止时不存在任何可交叉化的两对——这恰意味着每对都是「第 $i$ 小配第 $i$ 大」的形态：若某对 $(x_i, x_j)$ 不满足 $j = n - 1 - i$，取与 $x_{n-1-i}$ 同队的元素 $x_k$，则 $(x_i, x_j)$ 与 $(x_k, x_{n-1-i})$ 可交叉化（因 $k, n-1-i$ 中必有一个落在开区间 $(i, j)$ 或另一侧），矛盾。故终止态即首尾配对 $P^*$。由于每次交换 $M$ 不增，$M(P^*) \le M(P)$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序主导；随后一趟 $n/2$ 次迭代的求最大值为 $O(n)$。
- **空间**：$O(1)$ 额外（C++ 原地排序）至 $O(n)$（Python `sort` 的辅助数组）。不计输入，仅常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minPairSum(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = (int)nums.size(), ans = 0;
        for (int i = 0; i < n / 2; ++i)              // 第 i 小配第 i 大
            ans = max(ans, nums[i] + nums[n - 1 - i]);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minPairSum(self, nums: list[int]) -> int:
        nums.sort()
        n = len(nums)
        return max(nums[i] + nums[n - 1 - i] for i in range(n // 2))
```

> 💡 两份代码均通过官方示例（`7`、`8`）；并与「枚举全部 $(n-1)!!$ 种配对」的暴力实现做了大规模对拍——C++ 侧 30 万组随机偶数长度数组（$n \le 10$），Python 侧 2 万组，另含 $n = 10^5$ 的性能冒烟测试，全部 `mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 2$**：唯一一对即答案 $nums[0] + nums[1]$；排序后 `nums[0] + nums[1]` 正确。
2. **全部相同元素**（如 `[7,7,7,7]`）：首尾配对答案 $14$，任何方案都是 $14$，排序贪心不劣。
3. **负数/零不在本题范围**（$1 \le nums[i]$），但算法本身对含负数数组同样成立（证明只用了排序单调性）。
4. **别把「最大数对和最小」误做成「数对和总和最小」**：总和恒定等于 $\sum nums$，任何方案都一样——若按「总和最小」写贪心会得到错误的目标。
5. **双指针写法**：`l` 与 `r` 必须同步推进、循环 $n/2$ 次；只推进一侧会漏配或多配。
6. **排序方向**：降序排序时公式对称（第 $i$ 大配第 $i$ 小），但写公式时容易把下标搞反，建议统一升序 + `nums[i] + nums[n-1-i]`。
