# LeetCode 判断连接可整除性 题解

## 1. 题目概述

- **标题 / 题号**：判断连接可整除性（#3533，hard）
- **链接**：https://leetcode.cn/problems/concatenated-divisibility/
- **来源**：LeetCode 第 447 场周赛 Q3
- **难度**：困难
- **标签**：状态压缩、动态规划、位运算、数组

**题意**：给定正整数数组 $nums$ 与正整数 $k$。取 $nums$ 的某个**排列**，把所有数字的十进制表示**按顺序首尾拼接**成一个大数；若该大数能被 $k$ 整除，则称此排列形成「可整除连接」。返回可形成可整除连接的排列中**字典序最小**的那个（以整数列表返回），不存在则返回空列表。

**约束**：

- $1 \le nums.length \le 13$
- $1 \le nums[i] \le 10^5$
- $1 \le k \le 100$

> 💡 **审题关键**：其一，$n \le 13$ 是**状压 DP** 的标准信号灯（$2^{13} = 8192$），且 $k \le 100$ 把「余数」维压到两位数；其二，拼接出的数最长 $13 \times 6 = 78$ 位（约 $10^{78}$），**不可能真的构造出来判整除**，整除信息必须压缩进 $\bmod\ k$ 的余数里；其三，**字典序按整数列表逐元素比较**——示例 2 中 $[5,10]$ 优先于 $[10,5]$，说明比较的是「整数值」而**不是**拼接字符串的字典序（否则 $"105" < "510"$，结论恰好相反）；其四，是「排列」——**每个数字都必须用上且恰好用一次**。

## 2. 示例

**示例 1**

```text
输入：nums = [3,12,45], k = 5
输出：[3,12,45]
解释：排列 [3,12,45] 拼接得 31245，能被 5 整除；
      [12,3,45] 拼接得 12345 也可行，但 3 < 12，[3,12,45] 字典序更小。
```

**示例 2**

```text
输入：nums = [10,5], k = 10
输出：[5,10]
解释：[5,10] 拼接得 510，能被 10 整除；[10,5] 拼接得 105，不能。
      5 < 10，故 [5,10] 更小 —— 整数比较，而非字符串比较（"105" < "510"）。
```

**示例 3**

```text
输入：nums = [1,2,3], k = 5
输出：[]
解释：任何排列的拼接末位只能是 1、2 或 3，均不被 5 整除，无解。
```

## 3. 解题思路

本题是「排列 + 整除 + 字典序最小」三合一：整除性靠**余数 DP**，字典序最小靠**逐位贪心**，两者用状压状态 $(mask,\ r)$ 串起来。

### 3.1 暴力思路：按字典序枚举全排列

一个正确的朴素做法：`next_permutation` 按**字典序**从小到大枚举全部排列，逐个拼接判整除，**遇到的第一个可行解即答案**。判整除不必真做大数除法——从左到右扫，维护「当前已拼部分 $\bmod\ k$」即可，单次判定 $O(n)$。

但 $13! \approx 6.2 \times 10^9$，总操作约 $8 \times 10^{10}$，超时是定局。更糟的是答案靠后或无解时（示例 3）要枚举到底。

> ⚠️ 浪费的根源：不同的拼放顺序会反复落到「**同一批已用数字 + 同一个余数**」的子问题上——后续能拼成的余数集合完全一样，但朴素 DFS 不记得它曾经来过，把同构子树搜了一遍又一遍。

### 3.2 核心观察：拼接 = 余数转移，整除信息压缩进 (mask, r)

![核心观察：拼接不构造大数，A′ = A·10^L + x 的整除性只取决于 (r, x)，压缩成 (mask, r) 两把钥匙](images/wc447_q3_remainder_transfer.svg)

**观察 1（余数转移）**：拼接只是把旧数「左移 $L$ 位再加上新数」：$A' = A \cdot 10^L + x$。由模运算对乘法、加法的封闭性，

$$A' \bmod k = \big(r \cdot (10^L \bmod k) + x\big) \bmod k,$$

其中 $r = A \bmod k$。**78 位大数从头到尾不需要出现**，整除信息全程只用小于 $k$ 的小数传递。

**观察 2（信息压缩）**：拼接进行到一半时，能决定「未来」的全部信息只有两样——**用了哪些数字**（下标集合 $mask$）与**当前余数** $r \in [0, k)$。这就是经典状压 DP 状态 $(mask,\ r)$，规模 $2^{13} \times 100 \approx 8.2 \times 10^5$。

**观察 3（整数序贪心）**：字典序按**整数值**逐元素比较（见示例 2），因此「构造字典序最小」= 每一步在「未用且**后继可行**」的候选中选**值最小**的那个，而不是选「拼接串」意义下最小的。

### 3.3 算法流程：可行性 DP + 逐位贪心

![算法流程：排列森林按 (mask, r) 折叠，f(mask, r) 记忆化搜索 + 从 (0,0) 出发逐位贪心](images/wc447_q3_bitmask_dp_state.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 预处理 | $pw[L] = 10^L \bmod k$（$L \le 6$）；每个数的位数 $L_i$ 与余数 $md_i = nums_i \bmod k$ | $nums_i \le 10^5$ 是 6 位数，幂表只需 7 项 |
| ② 可行性 DP | 记忆化搜索 $f(mask,\ r)$：已用集合 $mask$、当前余数 $r$，能否把剩余数字**全部拼完**且最终余数为 $0$ | 终态 $f(full,\ r) = [r = 0]$；转移见上图公式 |
| ③ 逐位贪心 | 从 $(mask,\ r) = (0,\ 0)$ 出发走 $n$ 步；每步把未用数字**按值升序**试探，第一个满足 $f$ 为真的立即选中并更新状态 | $f$ 是 $O(1)$ 的「先知」，保证每步选的都是可行最小值 |

整体框架一句话：**把「按字典序枚举排列」改造成「逐位贪心 + 可行性 oracle」，再用状压 DP 把 oracle 做到 $O(1)$**。

### 3.4 示例演算

![示例 1 演算：三步贪心，每步选中值最小的可行候选，余数 0→3→2→0](images/wc447_q3_greedy_trace.svg)

以示例 1（$nums = [3,12,45]$，$k=5$）走一遍。$pw = [1, 0, 0, 0, 0, 0, 0]$（$10^L \bmod 5$ 对 $L \ge 1$ 全为 $0$）。

- **第 1 步**（$mask = \varnothing$，$r = 0$）：候选按值升序为 $3, 12, 45$。试 $3$：新余数 $(0 \cdot 10 + 3) \bmod 5 = 3$，$f(\{3\},\ 3) = \text{true}$（后继 $3 \to 12 \to 45$ 余数 $3 \to 2 \to 0$ 可行）→ **选中 3**，后面的候选不必再看。
- **第 2 步**（$mask = \{3\}$，$r = 3$）：候选 $12, 45$。试 $12$：$(3 \cdot 100 + 12) \bmod 5 = 2$，$f(\{3,12\},\ 2) = \text{true}$ → **选中 12**。
- **第 3 步**（$mask = \{3,12\}$，$r = 2$）：候选只剩 $45$：$(2 \cdot 100 + 45) \bmod 5 = 0$，到达终态 $(full,\ 0)$ → **选中 45**。

输出 $[3, 12, 45]$，连接值 $31245 \equiv 0 \pmod 5$。对照：$12$ 开头的 $[12,3,45]$（拼接 $12345$）也可行，但 $3 < 12$，整数比较下落选——这正是「整数序」与「字符串序」的分水岭。

## 4. 算法细节

1. **幂表边界**：$pw[0] = 1 \bmod k$（$k = 1$ 时全表为 $0$）。转移只用 $pw[L_i]$，$L_i \ge 1$，但递推初值必须按 $1 \bmod k$ 写，否则 $k=1$ 会错。
2. **$f$ 的视角**：定义为「已用 $mask$、余数 $r$，能否拼完剩余并归零」。查询入口 $f(0,\ 0)$ 自然对应「空拼接」（空串余数按 $0$ 起步，拼第一个数后余数恰为 $nums_i \bmod k$，与公式 $r' = (0 \cdot 10^{L} + x) \bmod k$ 自洽）。
3. **贪心的候选枚举**：线性扫一遍未用下标，维护「当前值最小的可行候选」：若已有候选且新值 $\ge$ 它则跳过。重复值天然只选中一个——**值相同则位数、余数、转移、后继可行性完全相同**，选哪个下标输出的值序列都一样。
4. **贪心不会走进死胡同**：第 ③ 步开始前已确认 $f(mask,\ r) = \text{true}$，而 $f$ 为真保证存在可行后继，故每步必能选中一个候选，无需再判空。
5. **记忆化实现**：C++ 用三态 `signed char`（$-1$ 未算 / $0$ 否 / $1$ 是），不能用 `bool`——两态会把「未计算」与「不可行」混为一谈；Python 直接 `@lru_cache`。
6. **递归深度**：至多 $n + 1 = 14$ 层，无爆栈风险。若想避免递归，也可按 $mask$ **数值降序**迭代递推（$mask \cup \{i\} > mask$ 恒成立），复杂度不变。

## 5. 正确性证明

**引理 1（拼接的余数转移）**：设已拼数为 $A \ge 0$，$r = A \bmod k$，新拼数 $x$ 的十进制位数为 $L$，则拼接结果 $A' = A \cdot 10^L + x$ 满足

$$A' \equiv r \cdot 10^L + x \pmod{k}.$$

**证明**：由 $A \equiv r \pmod k$ 与模对乘法、加法封闭：$A \cdot 10^L + x \equiv r \cdot 10^L + x \pmod k$。∎

**定理 1（可行性 DP 的刻画）**：对任意已用集合 $mask$ 与 $r \in [0, k)$：$f(mask,\ r) = \text{true}$ 当且仅当存在剩余元素的一个排列 $x_{i_1}, \cdots, x_{i_m}$，使从当前余数 $r$ 出发依次拼接后最终余数为 $0$。此外 $f$ 的真值只取决于**剩余元素的多重集**与 $r$，与 $mask$ 的具体编码无关。

**证明**：对剩余元素个数 $m$ 归纳。$m = 0$（$mask = full$）：无元素可拼，拼接结果就是当前余数对应的大数，可整除 $\iff r = 0$，与边界定义一致。$m \ge 1$：无论下一个拼谁，由引理 1，拼上 $x_i$ 后新余数**确定地**变为 $(r \cdot 10^{L_i} + x_i) \bmod k$，不依赖 $A$ 的具体取值；转移式对一切 $i \notin mask$ 取「或」，恰好枚举「下一个拼谁」的全部选择，而每种选择留下的子问题（剩余多重集去掉 $x_i$、新余数）由归纳假设正确刻画。最后，交换「已用集合中两个同值元素的下标」不改变剩余多重集，由上述归纳结构知 $f$ 真值不变。∎

**定理 2（贪心输出字典序最小）**：若可行排列存在，则 ③ 的贪心构造输出恰为字典序最小的可行排列 $P^*$。

**证明**：对步数 $p$ 归纳：**贪心的前 $p$ 个输出值与 $P^*$ 的前 $p$ 个元素相同**，且当前 $(mask,\ r)$ 是拼出该前缀后唯一确定的状态（$mask$ = 前缀用到的下标集合，$r$ 由引理 1 唯一确定）。$p = 0$ 平凡。归纳步：设 $y$ 为 $P^*$ 的第 $p+1$ 个元素值。

- $P^*$ 本身是从当前状态出发的可行完成，故至少一个候选可行，贪心必选出某个候选。
- 若贪心选中了值 $v < y$ 的候选，说明 $v$ 可行，则可构造可行排列 $Q$：前 $p$ 位与 $P^*$ 相同、第 $p+1$ 位为 $v$。于是 $Q$ 与 $P^*$ 首次差异在第 $p+1$ 位且 $v < y$，得 $Q <_{\text{lex}} P^*$，与 $P^*$ 最小性矛盾。故所有 $v < y$ 的候选均不可行，贪心按值升序试探必在值 $y$ 处**首次**成功。
- 若值为 $y$ 的元素有多个，由定理 1 的「多重集刻画」，任选其一可行性相同，输出值序列也与 $P^*$ 的前 $p+1$ 位一致。

归纳至 $p = n$，构造输出即 $P^*$。∎

由定理 1，② 中 $f(0,\ 0)$ 的判定无遗漏无虚报；由定理 2，③ 输出的排列字典序最小。算法正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(2^n \cdot k \cdot n)$。状态 $2^{13} \times 100 \approx 8.2 \times 10^5$ 个，每个至多 $n = 13$ 次转移，总计约 $1.1 \times 10^7$；贪心构造 $n$ 步、每步 $n$ 次记忆化查询，$O(n^2)$ 可忽略。
- **空间复杂度**：$O(2^n \cdot k)$。三态记忆化数组约 $8.2 \times 10^5$ 字节（`signed char`），外加 $O(n)$ 递归栈。
- **对照**：按字典序枚举全排列为 $O(n! \cdot n) \approx 8 \times 10^{10}$，不可行；状压把「$n!$ 种拼放历史」折叠成「$2^n \cdot k$ 个等价类」，是本题的全部收益来源。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> concatenatedDivisibility(vector<int>& nums, int k) {
        int n = nums.size();
        int full = (1 << n) - 1;

        vector<int> pw(7);                          // ① 幂表：10^L mod k
        pw[0] = 1 % k;                              //    k = 1 时全为 0，任何排列都可行
        for (int i = 1; i <= 6; i++) pw[i] = pw[i - 1] * 10 % k;

        vector<int> len(n), md(n);                  //    nums[i] <= 10^5，最多 6 位
        for (int i = 0; i < n; i++) {
            len[i] = to_string(nums[i]).size();
            md[i] = nums[i] % k;
        }

        // ② f[mask][r]：已用 mask、余数 r，能否拼完剩余并使最终余数为 0
        //    -1 未算 / 0 否 / 1 是
        vector<vector<signed char>> f(1 << n, vector<signed char>(k, -1));
        function<bool(int, int)> can = [&](int mask, int r) -> bool {
            if (mask == full) return r == 0;
            signed char& res = f[mask][r];
            if (res != -1) return res;
            for (int i = 0; i < n; i++) {
                if (mask & (1 << i)) continue;
                if (can(mask | (1 << i), (r * pw[len[i]] + md[i]) % k))
                    return res = 1;
            }
            return res = 0;
        };

        if (!can(0, 0)) return {};                  // 无解（如示例 3）

        vector<int> ans;                            // ③ 贪心：每步选「可行后继」的最小值
        int mask = 0, r = 0;
        for (int step = 0; step < n; step++) {
            int pick = -1;
            for (int i = 0; i < n; i++) {
                if (mask & (1 << i)) continue;
                if (pick != -1 && nums[i] >= nums[pick]) continue;
                if (can(mask | (1 << i), (r * pw[len[i]] + md[i]) % k)) pick = i;
            }
            ans.push_back(nums[pick]);
            mask |= 1 << pick;
            r = (r * pw[len[pick]] + md[pick]) % k;
        }
        return ans;
    }
};
```

### Python

```python
from functools import lru_cache

class Solution:
    def concatenatedDivisibility(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        full = (1 << n) - 1

        pw = [1 % k] * 7                            # ① 幂表：10^L mod k
        for i in range(1, 7):
            pw[i] = pw[i - 1] * 10 % k
        length = [len(str(x)) for x in nums]
        md = [x % k for x in nums]

        @lru_cache(None)                            # ② 可行性 DP
        def can(mask: int, r: int) -> bool:
            if mask == full:
                return r == 0
            return any(can(mask | 1 << i, (r * pw[length[i]] + md[i]) % k)
                       for i in range(n) if not mask >> i & 1)

        if not can(0, 0):
            return []

        ans, mask, r = [], 0, 0                     # ③ 贪心：每步选「可行后继」的最小值
        for _ in range(n):
            pick = -1
            for i in range(n):
                if mask >> i & 1:
                    continue
                if pick != -1 and nums[i] >= nums[pick]:
                    continue
                if can(mask | 1 << i, (r * pw[length[i]] + md[i]) % k):
                    pick = i
            ans.append(nums[pick])
            mask |= 1 << pick
            r = (r * pw[length[pick]] + md[pick]) % k
        return ans
```

## 8. 边界情况与易错点

1. **整数序 ≠ 字符串序**：字典序按**整数值**逐元素比较——示例 2（$[5,10]$ 优于 $[10,5]$）是试金石。若按拼接字符串比较，$"105" < "510"$ 会把顺序整个选反。
2. **$pw[0] = 1 \bmod k$ 而非 $1$**：$k = 1$ 时全表为 $0$、一切余数为 $0$，任何排列都可行，答案就是排序后的 $nums$——按 $1 \bmod k$ 写初值即可**零特判**自然得出。
3. **位数上限**：$10^5$ 本身是 6 位数，幂表预处理到 $10^6 \bmod k$ 即可，别只算到 $10^5$ 的「5 位」。
4. **重复元素**：值相同则转移与后继完全等价（定理 1），「$\ge$ 当前候选则跳过」的写法天然只选一个，输出值序列不受影响。
5. **三态记忆化**：C++ 用 `signed char` 存 $-1/0/1$；用 `bool` 会把「未计算」误当「不可行」，DP 直接失灵。
6. **乘法溢出**：$r,\ pw < k \le 100$，乘积 $\le 9801$，`int` 安全。若 $k$ 放大到 $10^9$，此处需 `long long`（但那时状态数也爆炸，见延伸思考）。
7. **无前导零坑**：$nums_i \ge 1$，不存在把 $0$ 放排首产生「05」之类歧义的可能——这是本题友好之处。
8. **先判无解再构造**：$f(0,0)$ 为假直接返回 `[]`（示例 3），贪心循环只在可行性确认后进行，不会出现选到一半无路可走。
