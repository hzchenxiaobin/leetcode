# LeetCode 统计被覆盖的建筑 题解

## 1. 题目概述

- **标题 / 题号**：统计被覆盖的建筑（#3531，medium）
- **链接**：https://leetcode.cn/problems/count-covered-buildings/
- **来源**：LeetCode 第 447 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、排序

**题意**：一个 $n \times n$ 的城市里有 $m$ 栋建筑，$buildings[i] = [x, y]$ 表示坐标 $(x, y)$ 处有一栋建筑，所有坐标**互不相同**。若某栋建筑在**左、右、上、下四个方向上各自存在至少一栋建筑**（不要求相邻，同在一条直线上即可），则称该建筑**被覆盖**。返回被覆盖的建筑数量。

**约束**：

- $2 \le n \le 10^5$
- $1 \le buildings.length \le 10^5$
- $buildings[i] = [x, y]$，$1 \le x, y \le n$，坐标两两不同

> 💡 **审题关键**：其一，「某方向上存在建筑」**不要求相邻**——示例 3 中 $(3,3)$ 的上方建筑 $(1,3)$ 与它相距 2 格，只要同线即可；其二，方向语义由示例 1 读出：**$y$ 相同而 $x$ 更小者为「上方」，$x$ 相同而 $y$ 更小者为「左方」**。于是自然得到分组方式：同 $x$ 的建筑连成一条**水平线**（决定左右），同 $y$ 的建筑连成一条**竖直线**（决定上下）。

## 2. 示例

**示例 1**

```text
输入：n = 3, buildings = [[1,2],[2,2],[3,2],[2,1],[2,3]]
输出：1
解释：只有 (2,2) 被覆盖——上方 (1,2)、下方 (3,2)、左方 (2,1)、右方 (2,3)。
```

**示例 2**

```text
输入：n = 3, buildings = [[1,1],[1,2],[2,1],[2,2]]
输出：0
解释：2×2 方块中，每栋建筑既是所在水平线的端点、又是所在竖直线的端点，四方向永不齐备。
```

**示例 3**

```text
输入：n = 5, buildings = [[1,3],[3,2],[3,3],[3,5],[5,3]]
输出：1
解释：只有 (3,3) 被覆盖——上方 (1,3)（相距 2 格）、下方 (5,3)、左方 (3,2)、右方 (3,5)。
```

## 3. 解题思路

本题虽是 Q1，官方难度却标了**中等**——门槛在于把「四个方向的存在性判定」坍缩成「两组极值的严格夹逼」这一步观察。

### 3.1 暴力思路：逐栋全量扫描

对每栋建筑 $(x, y)$，再完整扫一遍 $buildings$，用四个标记分别记录左、右、上、下是否出现过同线建筑：

```text
for (x, y) in buildings:
    hasL = hasR = hasU = hasD = false
    for (x2, y2) in buildings:
        if x2 == x and y2 < y: hasL = true   # 同 x，y 更小 → 左
        if x2 == x and y2 > y: hasR = true   # 同 x，y 更大 → 右
        if y2 == y and x2 < x: hasU = true   # 同 y，x 更小 → 上
        if y2 == y and x2 > x: hasD = true   # 同 y，x 更大 → 下
    if hasL and hasR and hasU and hasD: ans++
```

时间复杂度 $O(m^2)$，$m = 10^5$ 时约 $10^{10}$ 次比较，必然超时。另一个要避开的坑是把城市当成 $n \times n$ 网格遍历——$n = 10^5$ 同样是 $10^{10}$；建筑只有 $m$ 栋，答案只由它们的相对位置决定，**$n$ 仅仅是坐标上界（烟雾弹）**。

> ⚠️ 暴力的浪费在于：判定「该侧有没有建筑」时把同线上的**所有**建筑都比了一遍，但答案只取决于该侧**是否存在**建筑——是谁、有几栋、距离多远都无关紧要。这个存在性判定可以被每组里的两个数——$\min$ 与 $\max$——完全吸收。

### 3.2 核心观察：分组极值 + 严格夹逼

![核心观察：同 x 组的 y 极值管左右，同 y 组的 x 极值管上下，双重严格夹逼同时成立即被覆盖](images/wc447_q1_covered_concept.svg)

把建筑按坐标分成两组十字交叉的桶：

- **同 $x$ 组**（$x$ 相同的建筑连成一条水平线）：决定**左右**。$(x, y)$ 有左邻居 $\iff$ 组内存在 $y' < y$；有右邻居 $\iff$ 组内存在 $y' > y$；两者同时成立 $\iff \text{rowMin}[x] < y < \text{rowMax}[x]$。
- **同 $y$ 组**（$y$ 相同的建筑连成一条竖直线）：决定**上下**。$(x, y)$ 同时有上、下邻居 $\iff \text{colMin}[y] < x < \text{colMax}[y]$。

| 观察 | 内容 | 带来的做法 |
|------|------|-----------|
| **方向判定坍缩成极值** | 「左方有建筑」= 同 $x$ 组内存在更小的 $y$，至于是谁、有几栋都无所谓 | 每组只维护 $\min / \max$ 两个数，一趟扫描即可建好 |
| **两组条件正交** | 左右只看同 $x$ 组的 $y$ 极值，上下只看同 $y$ 组的 $x$ 极值，互不干扰 | 覆盖 $\iff$ 两个严格夹逼**同时**成立，逐栋 AND 判定 |
| **端点永不合格** | 组内取到 $\min$ 或 $\max$ 的建筑必然缺一侧（自己就是该方向上最远的） | 不等式必须**严格**；单栋成组时 $\min = \max =$ 自己，天然落选 |
| **$n$ 是烟雾弹** | 算法只依赖 $m$ 栋建筑的相对位置，$n$ 仅给出坐标范围 | 坐标有界 ⇒ 长度 $n+1$ 的数组当桶；换哈希表连 $n$ 都不需要 |

两遍扫描即得答案：第一遍为每个 $x$ 维护 $y$ 的极值、为每个 $y$ 维护 $x$ 的极值；第二遍对每栋建筑检查「双重严格夹逼」是否同时成立。

> 💡 官方标签里的 **Sorting** 来自等价做法——把每组坐标排序后，「不在首尾」的建筑即在该轴向两侧都有邻居（$O(m \log m)$）。极值法是它的进一步坍缩：判「是否存在更小 / 更大」根本不需要顺序信息，连排序都省了。

### 3.3 算法流程：两遍扫描

![算法流程：初始化四张极值表，第一遍扫描建表，第二遍扫描逐栋双重夹逼判定并计数](images/wc447_q1_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | $\text{rowMin}, \text{colMin} \leftarrow +\infty$，$\text{rowMax}, \text{colMax} \leftarrow -\infty$ | 长度 $n+1$ 的数组，下标即坐标，$O(n)$ |
| ② 第一遍扫描 | 对每栋 $(x, y)$：用 $y$ 刷新 $\text{rowMin}[x], \text{rowMax}[x]$，用 $x$ 刷新 $\text{colMin}[y], \text{colMax}[y]$ | 一栋建筑同时喂给「行桶」与「列桶」 |
| ③ 第二遍扫描 | 检查 $\text{rowMin}[x] < y < \text{rowMax}[x]$ **且** $\text{colMin}[y] < x < \text{colMax}[y]$ | 四个严格不等式同时成立才计数 |
| ④ 返回 | 累计计数即答案 | — |

### 3.4 示例演算

![示例演算：十字五栋建筑先建极值表，再逐栋判定，只有中心 (2,2) 通过双重严格夹逼](images/wc447_q1_example_walkthrough.svg)

以示例 1（$n = 3$，五栋建筑摆成十字）走一遍。

**第一遍扫描建立极值表**（同 $x$ 组记录 $y$ 的极值，同 $y$ 组记录 $x$ 的极值）：

| 分组 | 组内取值 | min | max |
|------|----------|-----|-----|
| 同 $x$：$x=1$ | $\{2\}$ | 2 | 2 |
| 同 $x$：$x=2$ | $\{1,2,3\}$ | **1** | **3** |
| 同 $x$：$x=3$ | $\{2\}$ | 2 | 2 |
| 同 $y$：$y=1$ | $\{2\}$ | 2 | 2 |
| 同 $y$：$y=2$ | $\{1,2,3\}$ | **1** | **3** |
| 同 $y$：$y=3$ | $\{2\}$ | 2 | 2 |

**第二遍扫描逐栋判定**：

| 建筑 $(x,y)$ | 左右：$\text{rowMin}[x] < y < \text{rowMax}[x]$ | 上下：$\text{colMin}[y] < x < \text{colMax}[y]$ | 被覆盖？ |
|------|------|------|------|
| (1,2) | $2 < 2$ ✗（$x{=}1$ 组只有自己） | $1 < 1$ ✗（$y{=}2$ 组端点） | ✗ |
| **(2,2)** | $1 < 2 < 3$ ✓ | $1 < 2 < 3$ ✓ | **✓** |
| (3,2) | $2 < 2$ ✗ | $3 < 3$ ✗（$y{=}2$ 组另一端） | ✗ |
| (2,1) | $1 < 1$ ✗（$x{=}2$ 组 $\min$ 端点） | $2 < 2$ ✗ | ✗ |
| (2,3) | $3 < 3$ ✗（$x{=}2$ 组 $\max$ 端点） | $2 < 2$ ✗ | ✗ |

答案 = **1**，与示例一致。示例 2 同理：$2 \times 2$ 方块中每栋建筑既是所在 $x$ 组的端点、又是所在 $y$ 组的端点，全部落选，答案 0。

## 4. 算法细节

1. **方向语义先对表**：同 $x$ 且 $y$ 更小 → 左；同 $y$ 且 $x$ 更小 → 上。这层语义只能从示例 1 读出，写代码前先拿样例人工核对一遍，避免把两组桶的**比较坐标**接反（详见 §8 第 4 点）。
2. **数组当哈希表**：由 $1 \le x, y \le n$，四张表开成长度 $n+1$ 的数组，下标即坐标，缓存友好、常数小。被查询的下标（每栋建筑的 $x$ 与 $y$）必然在建表时出现过，所以 $\pm\infty$ 哨兵永远不会被真正读到。若坐标无上界，换成 `unordered_map` / `dict`，复杂度变为与 $n$ 无关的 $O(m)$。
3. **为什么必须两遍扫描**：判定某栋建筑需要它所在行桶、列桶的**最终**极值，而极值在扫完之前不确定——后面的建筑随时可能刷新。若坚持单遍，需要在线维护每组的次小 / 次大值并在极值被刷新时回溯修正计数，得不偿失。「先全局建表、后逐栋判定」是需要全局信息的题目的标准两遍式写法。
4. **与排序版对照**：官方标签 Sorting 的来源是「每组排序，非首尾即通过」，$O(m \log m)$。它与极值版完全等价——「非首尾」就是「严格介于 $\min$ 与 $\max$ 之间」，而判定存在性根本不需要全序，两个数就够。
5. **赛场快速验算**：每栋被覆盖的建筑所在行组、列组都至少 3 栋（自己 + 两侧各一），因此答案上界为 $\sum_{\text{组}} (\text{size} - 2)^+$；十字形（5 栋）是用最少建筑凑出 1 栋覆盖的典型形态——每条线恰好 3 栋，端点 4 栋全部报废，只剩中心。

## 5. 正确性证明

**引理 1（方向邻居与组极值的等价）**：对建筑 $(x, y)$：

- 有左邻居 $\iff \text{rowMin}[x] < y$；有右邻居 $\iff y < \text{rowMax}[x]$；
- 有上邻居 $\iff \text{colMin}[y] < x$；有下邻居 $\iff x < \text{colMax}[y]$。

**证明**：左邻居存在 $\iff$ 存在建筑 $(x, y')$ 且 $y' < y$ $\iff$ 集合 $\{ y' : (x, y') \in B \}$ 中存在小于 $y$ 的元素 $\iff$ 该集合的最小值 $\text{rowMin}[x] < y$。其余三个方向同理（右对 $\max$，上 / 下对列组的 $\min / \max$）。∎

**定理（覆盖判定）**：建筑 $(x, y)$ 被覆盖 $\iff \text{rowMin}[x] < y < \text{rowMax}[x]$ 且 $\text{colMin}[y] < x < \text{colMax}[y]$。

**证明**：按定义，被覆盖 $\iff$ 左、右、上、下邻居同时存在。由引理 1 逐方向代入：左且右 $\iff \text{rowMin}[x] < y < \text{rowMax}[x]$；上且下 $\iff \text{colMin}[y] < x < \text{colMax}[y]$。两个条件取 AND 即得。∎

**推论（端点必落选）**：若 $y = \text{rowMin}[x]$ 或 $y = \text{rowMax}[x]$（对列组同理），则 $(x, y)$ 不被覆盖。特别地，组大小为 1 或 2 时，组内**所有**建筑都无法通过该轴向的判定。

**证明**：若 $y = \text{rowMin}[x]$，则 $\text{rowMin}[x] < y$ 不成立，由定理其不被覆盖。组大小为 1 时 $\min = \max =$ 自己；大小为 2 时两成员分别取到 $\min$ 与 $\max$，均触端点。∎

**引理 2（建表不变式）**：第一遍扫描结束后，$\text{rowMin}[x]$ 恰等于 $\{ y : (x, y) \in B \}$ 的最小值（其余三张表同理）。

**证明**：对扫描步数归纳。初始 $\text{rowMin}[x] = +\infty$ 大于一切实坐标，可视作空集的最小值。每处理一栋 $(x, y)$，$\text{rowMin}[x] \leftarrow \min(\text{rowMin}[x],\ y)$ 恰好是把 $y$ 并入集合后重新取最小，归纳保持「$\text{rowMin}[x]$ = 已见同 $x$ 建筑的 $y$ 最小值」。扫描遍历全部建筑后即得全集的最小值。∎

由引理 2，第二遍扫描中查到的极值就是真实极值；再由定理，计数恰好等于被覆盖的建筑数，算法正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。$O(n)$ 初始化四张长度 $n+1$ 的数组；两遍扫描各 $O(m)$，每栋建筑仅做常数次比较与赋值。换成哈希表后为 $O(m)$，与 $n$ 无关。
- **空间复杂度**：$O(n)$，即四张极值表（不计返回值）。哈希表版为 $O(m)$。
- **对照**：暴力 $O(m^2)$ 在 $m = 10^5$ 时约 $10^{10}$ 次比较，超时；排序版 $O(m \log m)$ 能过但不是必需——存在性判定不需要全序。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countCoveredBuildings(int n, vector<vector<int>>& buildings) {
        // 同 x 组的 y 极值（管左右），同 y 组的 x 极值（管上下）
        vector<int> rowMin(n + 1, INT_MAX), rowMax(n + 1, INT_MIN);
        vector<int> colMin(n + 1, INT_MAX), colMax(n + 1, INT_MIN);

        for (auto& b : buildings) {            // ① 建表
            int x = b[0], y = b[1];
            rowMin[x] = min(rowMin[x], y);
            rowMax[x] = max(rowMax[x], y);
            colMin[y] = min(colMin[y], x);
            colMax[y] = max(colMax[y], x);
        }

        int ans = 0;
        for (auto& b : buildings) {            // ② 双重严格夹逼
            int x = b[0], y = b[1];
            if (rowMin[x] < y && y < rowMax[x] &&
                colMin[y] < x && x < colMax[y]) {
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countCoveredBuildings(self, n: int, buildings: List[List[int]]) -> int:
        INF = float("inf")
        row_min = [INF] * (n + 1)      # 同 x 组的 y 极值 → 左右
        row_max = [-1] * (n + 1)
        col_min = [INF] * (n + 1)      # 同 y 组的 x 极值 → 上下
        col_max = [-1] * (n + 1)

        for x, y in buildings:         # ① 建表
            if y < row_min[x]: row_min[x] = y
            if y > row_max[x]: row_max[x] = y
            if x < col_min[y]: col_min[y] = x
            if x > col_max[y]: col_max[y] = x

        ans = 0
        for x, y in buildings:         # ② 双重严格夹逼
            if row_min[x] < y < row_max[x] and col_min[y] < x < col_max[y]:
                ans += 1
        return ans
```

> 💡 Python 版哨兵用 `-1` 代替 $-\infty$ 是安全的：坐标 $\ge 1$，任何真实极值都大于 $-1$，且被查询的桶必非空，哨兵不会被读到。

## 8. 边界情况与易错点

1. **不等式必须严格**：写成 $\le$ 会把组端点误判为覆盖——样例 1 会从 1 错成 5。端点建筑自己就是该方向上最远的建筑，那一侧必然空无一人。
2. **单栋成组无需特判**：$\min = \max =$ 自己，严格夹逼天然为假，代码零分支处理。
3. **别开 $n \times n$ 网格**：$n$ 只用于给数组定长（坐标 $1 \sim n$）；把它当网格遍历是 $10^{10}$，比暴力还惨。
4. **两组桶的比较坐标别写反**：行桶（键 $x$）里存的是 $y$ 的极值，列桶（键 $y$）里存的是 $x$ 的极值。本题三个官方样例在 $x \leftrightarrow y$ 互换下都对称，把比较对象写反（拿 $x$ 去和 $y$ 极值比）照样全过——自造非对称数据核对，如 `n = 13, buildings = [[10,2],[10,5],[10,8],[7,5],[13,5]]`：正确答案 1（$(10,5)$ 被覆盖），写反则得 0。
5. **两遍顺序不能颠倒**：先判定后建表会读到 $\pm\infty$ 哨兵，全部落选，答案恒 0。
6. **溢出**：无。坐标、计数都 $\le 10^5$，`int` 足够。
7. **想一遍扫完？** 判定需要最终极值，而后面的建筑随时可能刷新它；在线版要维护次极值并回溯修正，得不偿失（见 §4 第 3 点）。
