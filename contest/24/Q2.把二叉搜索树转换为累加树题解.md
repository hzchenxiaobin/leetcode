# LeetCode 把二叉搜索树转换为累加树 题解

## 1. 题目概述

- **标题 / 题号**：把二叉搜索树转换为累加树（#538，medium）
- **链接**：https://leetcode.cn/problems/convert-bst-to-greater-tree/
- **来源**：LeetCode 第 24 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、二叉搜索树、二叉树

**题意**：给定一棵**结点值互不相同**的二叉搜索树的根 `root`，把每个结点的值 $x$ 改成 $x + (\text{原树中所有大于 } x \text{ 的值之和})$，返回改造后的根。树的结构（`left` / `right` 指针）不能变，可以原地修改。本题与 [#1038](https://leetcode.cn/problems/binary-search-tree-to-greater-sum-tree/) 完全相同。

**约束**：

- 结点数 $0 \le n \le 10^4$
- 结点值 $-10^4 \le val \le 10^4$（**可以为负**）
- 所有结点值互不相同，且输入保证是一棵合法的 BST

## 2. 示例

**示例 1**

```text
输入：[4,1,6,0,2,5,7,null,null,null,3,null,null,null,8]
输出：[30,36,21,36,35,26,15,null,null,null,33,null,null,null,8]
解释：结点 4 的新值 = 4 + (5+6+7+8) = 30；结点 1 的新值 = 1 + (2+3+4+5+6+7+8) = 36；
      最大值结点 8 没有更大的值，新值仍是 8。
```

**示例 2**

```text
输入：root = [0,null,1]
输出：[1,null,1]
解释：结点 0 的新值 = 0 + 1 = 1；结点 1 保持 1。
```

**示例 3**

```text
输入：root = [1,0,2]
输出：[3,3,2]
解释：中序升序为 0,1,2；0 加 (1+2)=3，1 加 2 得 3，2 没有更大的值。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对**每个**结点，重新遍历整棵树，把所有比它大的值加起来再写回。单次遍历 $O(n)$，共 $n$ 个结点，总时间 $O(n^2)$；$n = 10^4$ 时约 $10^8$ 次比较，Python 必然超时。

稍好一点的暴力：先中序遍历把全部值排成升序数组，再用一个后缀和数组，对每个结点二分出「第一个严格大于自己的位置」，直接读出答案。时间 $O(n\log n)$、空间 $O(n)$。这能过，但完全没有利用「输入是 BST」这一结构信息——而利用它可以把时间做到严格 $O(n)$、额外空间只是递归栈。

### 3.2 核心观察：逆中序就是降序，前缀和就是答案

![逆中序得到降序序列](images/wc24_q2_reverse_inorder.svg)

BST 的中序遍历（左 → 根 → 右）输出**升序**序列；把它反过来，即**逆中序**（右 → 根 → 左），输出的就是**严格降序**序列。设降序序列为

$$v_1 > v_2 > \cdots > v_n$$

那么对第 $i$ 个被访问的结点：

$$\text{新值}(v_i) = v_i + \sum_{j<i} v_j = \sum_{j\le i} v_j$$

也就是说：**把降序序列的前缀和写回对应结点即可**。而前缀和可以在遍历过程中用一个变量 $s$ 在线维护，每访问一个结点就执行

$$s \leftarrow s + v_i,\qquad val_i \leftarrow s$$

一次遍历、一个计数器，$O(1)$ 额外开销就替代了「对每个结点再求和」的 $O(n)$。

> 💡 关键点在于「所有更大的值」在逆中序里恰好排在前面，因此它们是**已经累加过的**，不需要回看、也不需要查找。

### 3.3 算法流程

![逆中序递归流程](images/wc24_q2_flow.svg)

递归写法（`acc` 为全局累加和）：

```text
dfs(node):
    if node == null: return
    dfs(node.right)      # ① 先处理所有更大的值
    acc += node.val      # ② 累加原值
    node.val = acc       # ③ 写回前缀和
    dfs(node.left)       # ④ 最后处理更小的值
```

若不想依赖递归，可以改成显式栈的**迭代逆中序**：从当前结点一路向右压栈，弹栈时累加并写回，然后转向左子树。两者遍历次序完全一致，只是把「调用栈」换成了「手写栈」，额外空间仍是树高 $O(h)$。

以示例 1 为例，逆中序把 9 个结点按降序逐个访问：

![降序序列的前缀和](images/wc24_q2_prefix_sum.svg)

| 次序 $i$ | 结点原值 $v_i$ | 累加和 $s_i$ | 写回的新值 |
| --- | --- | --- | --- |
| 1 | 8 | 8 | 8 |
| 2 | 7 | 15 | 15 |
| 3 | 6 | 21 | 21 |
| 4 | 5 | 26 | 26 |
| 5 | 4 | 30 | 30 |
| 6 | 3 | 33 | 33 |
| 7 | 2 | 35 | 35 |
| 8 | 1 | 36 | 36 |
| 9 | 0 | 36 | 36 |

每个结点的「更大值之和」都被前几行的累加吸收掉了，于是整棵树变成：

![改造前后的树](images/wc24_q2_before_after.svg)

对照输出 `[30,36,21,36,35,26,15,null,null,null,33,null,null,null,8]`：根 4→30、左子 1→36、右子 6→21、0→36、2→35、5→26、7→15、3→33、8→8，与表中结果完全一致。另一个小例子 `[3,2,4,1]` 的降序为 4,3,2,1，前缀和 4,7,9,10，得到 `[7,9,4,10]`。

## 4. 算法细节

1. **访问顺序必须是「右 → 根 → 左」**。只有先走完右子树，累加和里才集齐了「所有更大的值」；先左或先根都会漏加。
2. **两行代码的先后不能换**：必须 `acc += node.val` 再 `node.val = acc`。若写成 `node.val = acc; acc += node.val`，第二步累加的是刚写入的 `acc`（即 $s$）而不是原值 $v$：于是该结点写回的只有 $s$（漏掉自己），`acc` 却变成 $2s$（$s$ 被算了两遍），后续结点全部跟着错。这里 $s$ 表示该结点之前已累加的「更大值之和」，$v$ 是它的原值。
3. **原地修改**：题目允许直接改原树，因此不需要拷贝结构，最后返回 `root` 即可；DFS 里也不必回写左右指针。
4. **负数与零**：结点值可以为负，`acc` 可能为负，降序序列严格递减这一性质与正负无关，但**前缀和 $s_i$ 本身并不单调**（$v_i < 0$ 时 $s_i < s_{i-1}$），不要拿 $s$ 的大小关系做任何判断。也不要用 `acc == 0` 当「尚未开始」的哨兵，初值 0 只表示「空的前缀和」。
5. **递归深度**：最坏情况是 $10^4$ 个结点退化成一条右斜链，Python 默认递归上限约 1000，会抛 `RecursionError`，需要 `sys.setrecursionlimit(100000)` 或改用迭代；C++ 的 $10^4$ 层递归大约只占几百 KB 栈空间，安全。
6. **迭代写法**：内层 `while (node) { push(node); node = node->right; }` 完成「一路向右」，弹栈后累加、写回、再令 `node = node->left`，与递归的次序逐位等价。
7. **数值范围**：$\lvert acc\rvert \le n \times 10^4 = 10^8 < 2^{31}-1$，C++ 用 `int` 即安全；若担心以后数据加强，用 `long long` 也无额外代价（Python 整数天然无溢出）。
8. **不要破坏指针**：遍历期间任何对 `left` / `right` 的改写都会让逆中序走错（Morris 遍历正是「故意改写再复原」，见文末延伸）。

## 5. 正确性证明

**引理 1**：逆中序（右 → 根 → 左）遍历依次输出的结点值构成严格递减序列，且每个结点恰好输出一次。

**证明**：对子树规模归纳。空树平凡。设当前结点为 $u$，左、右子树为 $L, R$。由 BST 性质，$R$ 中任意值都 $> u.val$，$u.val$ 又大于 $L$ 中任意值。由归纳假设，$\text{rev}(R)$ 与 $\text{rev}(L)$ 各自严格递减；把 $\text{rev}(R)$、$u$、$\text{rev}(L)$ 依次拼接：第一段的值全部大于 $u.val$，$u.val$ 又大于第三段的值，而三段内部各自严格递减，故整体严格递减。三部分互不相交且并集为整棵子树，每个结点恰好输出一次。∎

**引理 2**：算法访问到第 $i$ 个结点时，执行 `acc += node.val` 之后 $acc = \sum_{j \le i} v_j$，于是写回的值恰为 $v_i + \sum_{j<i} v_j$。

**证明**：`acc` 只在一个结点被「累加」时改变，而按逆中序的次序，第 $i$ 个结点之前恰好有 $i-1$ 个结点完成过累加。对 $i$ 归纳：$i = 1$ 时初值 0，累加 $v_1$ 得 $acc = v_1$；设第 $i-1$ 次累加后 $acc = \sum_{j \le i-1} v_j$，此后到第 $i$ 次累加之间没有别的累加操作，故累加 $v_i$ 后 $acc = \sum_{j \le i} v_j$。∎

**引理 3**：对任意 $i$，集合 $\{v_1, \dots, v_{i-1}\}$ 恰好是原树中所有大于 $v_i$ 的结点值。

**证明**：由引理 1，降序序列的前 $i-1$ 项是树中值最大的 $i-1$ 个结点，而第 $i$ 项之后的值都小于 $v_i$，故「前 $i-1$ 项」与「所有大于 $v_i$ 的值」是同一集合。∎

**定理**：算法结束时，每个结点的新值都等于「原值 + 原树中所有更大值之和」，且树的结构不变。

**证明**：设结点 $u$ 的原值为 $v_i$，即它在逆中序中第 $i$ 个被访问（引理 1 保证其存在且唯一）。由引理 2、3，写回给 $u$ 的值是 $v_i + \sum_{j<i} v_j = v_i + \sum_{v > v_i} v$，正是题目要求的新值。算法全程只读取 `left` / `right` 用于遍历、只写 `val` 字段，因此树形不变；每个结点恰好被访问一次，所有结点都被正确更新。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个结点恰好进入一次 `dfs`，每次只做一次加法、一次赋值和常数次指针判断；不存在任何按结点重复扫描的开销。
- **空间**：$O(h)$，$h$ 为树高。递归写法使用调用栈，迭代写法使用显式栈，二者深度都不超过 $h$；平衡树 $h = O(\log n)$，退化成链时 $h = O(n)$。除栈外只多一个整型累加变量，$O(1)$。
- **Morris 逆中序**（扩展做法）：利用叶子空指针做临时线索，空间可降到 $O(1)$，时间仍是 $O(n)$。

## 7. 参考代码

### C++

```cpp
/**
 * Definition for a binary tree node.
 * struct TreeNode {
 *     int val;
 *     TreeNode *left;
 *     TreeNode *right;
 *     TreeNode() : val(0), left(nullptr), right(nullptr) {}
 *     TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
 *     TreeNode(int x, TreeNode *left, TreeNode *right) : val(x), left(left), right(right) {}
 * };
 */
class Solution {
    int acc = 0;                       // 当前前缀和：所有已访问（更大）结点原值之和
    void dfs(TreeNode* node) {
        if (!node) return;
        dfs(node->right);              // 右：所有更大的值
        acc += node->val;              // 累加原值
        node->val = acc;               // 写回前缀和
        dfs(node->left);               // 左：更小的值
    }
public:
    TreeNode* convertBST(TreeNode* root) {
        dfs(root);
        return root;
    }
};
```

### Python

```python
# Definition for a binary tree node.
# class TreeNode:
#     def __init__(self, val=0, left=None, right=None):
#         self.val = val
#         self.left = left
#         self.right = right
import sys


class Solution:
    def convertBST(self, root: "TreeNode") -> "TreeNode":
        sys.setrecursionlimit(100000)      # 链状树深度可达 1e4，先抬高递归上限
        self.acc = 0

        def dfs(node: "TreeNode") -> None:
            if node is None:
                return
            dfs(node.right)                # 先处理所有更大的值
            self.acc += node.val           # 累加原值
            node.val = self.acc            # 写回前缀和
            dfs(node.left)                 # 最后处理更小的值

        dfs(root)
        return root


class SolutionIterative:
    """迭代版逆中序：不依赖递归上限，空间同样是 O(h)。"""

    def convertBST(self, root: "TreeNode") -> "TreeNode":
        acc = 0
        stack, node = [], root
        while stack or node:
            while node:                    # 一路向右，压栈
                stack.append(node)
                node = node.right
            node = stack.pop()             # 当前最大的未访问结点
            acc += node.val
            node.val = acc
            node = node.left               # 转向左子树
        return root
```

## 8. 边界情况与易错点

1. **空树**：`root = null`（结点数可以为 0）→ 直接返回 `null`，递归写法天然满足，不要假定非空。
2. **单结点**：没有更大的值，`acc` 从 0 变为 `val`，写回后仍是 `val`，树不变。
3. **赋值顺序写反**：`node.val = acc; acc += node.val` 会把 `acc` 变成原来的两倍、同时漏加当前结点的原值，从该结点起答案整体错乱，是最常见的手误（务必先在纸上跑一遍示例 1 的根）。
4. **遍历方向写反**：写成中序（左 → 根 → 右）得到升序，累加的是「不大于自己的和」，答案整体错误且不易察觉。
5. **Python 深递归**：$10^4$ 个结点退化成右斜链时，默认递归上限约 1000 会导致 `RecursionError`（表现为 RE 而不是 WA），务必 `setrecursionlimit` 或改用迭代版。
6. **负数**：结点值可为负，`acc` 可能为负甚至从负数开始增长，不要做「`acc > 0` 才累加」之类的额外判断。
7. **遍历中改指针**：只在遍历结束后树形才应保持不变；遍历期间若顺手改写 `left` / `right`，逆中序会走错分支甚至死循环。
8. **返回值**：返回的是原 `root` 指针（原地修改），若用「返回新结点、在父层重新挂接」的写法，注意别把左右孩子挂反、也别丢掉 `null` 分支。

**延伸思考**：

1. **值有重复怎么办？** 题目保证互不相同，所以「所有更大的值」等价于「逆中序中排在前面」。若允许重复且要求**严格大于**，同值的结点不能互相累加，需要先按值分组统计频次，再对每组统一 `acc += 值 × 频次` 后才能写入——这也是 1038 的常见变体陷阱。
2. **Morris 逆中序**：把每个结点左子树中的最右结点的 `right` 临时指向自己，就能在不使用栈的情况下完成逆中序，空间降到 $O(1)$；代价是代码更绕，且必须在访问后把线索还原。
3. **树不是 BST**：失去有序性后只能先 $O(n\log n)$ 排序、再用哈希表或二分求「更大值之和」，或者按值域用后缀和（值域 $[-10^4, 10^4]$ 时可以直接开桶做到 $O(n + V)$）。
4. **要求不修改原树**：先按原结构克隆一棵，再在新树上做逆中序；或者一边遍历一边构造新结点，把前缀和写进新结点。
