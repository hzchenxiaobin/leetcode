# LeetCode 输出比赛匹配对 题解

## 1. 题目概述

- **标题 / 题号**：输出比赛匹配对（#544，medium）
- **链接**：https://leetcode.cn/problems/output-contest-matches/
- **来源**：LeetCode 第 24 场周赛 Q4
- **难度**：中等
- **标签**：递归、字符串、模拟

**题意**：$n$ 支队伍按实力编号 $1 \sim n$（1 最强、$n$ 最弱）。每一轮把**当前序列的首尾两两配对**——最强的碰最弱的——然后用 `(`、`)` 与 `,` 把这一对包成一个新的"比赛对"。下一轮把这 $n/2$ 个比赛对再按同样规则配对，直到只剩一项。要求输出最终这一项的字符串表示。

**约束**：

- $2 \le n \le 2^{12} = 4096$
- 输入保证 $n$ 可以写成 $2^k$（$k$ 为正整数），即队伍数一定是 2 的幂，**不会出现轮空**

## 2. 示例

**示例 1**

```text
输入：n = 2
输出："(1,2)"
解释：初始序列 1,2，只有一轮配对，直接包起来即可。
```

**示例 2**

```text
输入：n = 4
输出："((1,4),(2,3))"
解释：第 1 轮 1 打 4、2 打 3，得到 (1,4),(2,3)；
      第 2 轮两场胜者再打一场，整体再包一层。
```

**示例 3**

```text
输入：n = 8
输出："(((1,8),(4,5)),((2,7),(3,6)))"
解释：第 1 轮： (1,8),(2,7),(3,6),(4,5)
      第 2 轮： ((1,8),(4,5)),((2,7),(3,6))   ← 首尾再配，(1,8) 碰 (4,5)
      第 3 轮： 整体包一层，得到最终答案
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是严格"翻译"题面：维护一个当前"队伍 / 比赛对"的列表，每一轮先按强度把列表**排序**，再让第 1 名碰最后 1 名、第 2 名碰倒数第 2 名……

排序需要给每个比赛对维护一个"队内最强 rank"字段，每轮 $O(m \log m)$，总比较量 $O(n \log n)$。它当然能过（$n \le 4096$），但**排序完全是多余的**：只要配对方式不破坏顺序，列表天然就是有序的。

另一个更常见的"暴力"陷阱是**相邻配对**：先把 $1$ 与 $n$、$2$ 与 $n-1$ 配好，再把这 $n/2$ 个串按位置相邻两两配对。对 $n = 8$ 会得到

$$((1,8),(2,7)),\;((3,6),(4,5)) \;\Longrightarrow\; (((1,8),(2,7)),((3,6),(4,5)))$$

而正确答案是 $(((1,8),(4,5)),((2,7),(3,6)))$——错误根源在于把「新一轮的首尾」误当成了「上一轮的相邻」。记住：**每一轮的配对对象都是当前序列的首尾**。

### 3.2 核心观察：当前序列永远按「队内最强」升序

![首尾配对：每一轮把当前序列的最强与最弱配在一起](images/wc24_q4_pair_fold.svg)

对任意一个比赛对串 $t$，记 $\min(t)$ 为它**队内最强的 rank**（即串中出现的最小数字）。对 $n = 8$ 的第 1 轮：

$$
\begin{aligned}
\text{序列} &= [1,\,2,\,3,\,4,\,5,\,6,\,7,\,8]\\
\text{配对} &= [(1,8),\,(2,7),\,(3,6),\,(4,5)]
\end{aligned}
$$

新序列的 $\min$ 依次是 $1,2,3,4$——**仍然是严格升序**。原因是：新序列第 $k$ 项取的是旧序列第 $k$ 项与第 $m-1-k$ 项，而旧序列升序保证 $\min(\text{左}) < \min(\text{右})$，所以新项的 $\min$ 就等于旧第 $k$ 项的 $\min$，即 $k+1$。

> 💡 **一句话**：首尾配对**不会打乱顺序**，所以「按强度排序」这一步从头到尾都不需要，每轮直接取下标 $i$ 与 $m-1-i$。

### 3.3 算法流程：序列长度逐轮减半

![算法流程：循环首尾配对，直到只剩一个匹配串](images/wc24_q4_merge_flow.svg)

1. 把 $1 \sim n$ 转成字符串数组 `teams`。
2. 当 `teams` 长度 $m > 1$：对 $i = 0,1,\dots,\frac{m}{2}-1$ 生成 `"(" + teams[i] + "," + teams[m-1-i] + ")"`，组成 `next`。
3. `teams = next`，回到第 2 步；只剩一项时返回 `teams[0]`。

$m$ 每轮减半，所以循环 $k = \log_2 n$ 轮，最多 $12$ 轮。

**等价递归写法**（不做逐轮数组，直接按「下标路径」展开）：记 $T(m,i)$ 为长度 $m$ 的列表里第 $i$ 项的字符串，则

$$
T(m,i)=
\begin{cases}
i+1, & m=n\\[2pt]
\bigl(T(2m,\,i),\;T(2m,\,2m-1-i)\bigr), & m<n
\end{cases}
$$

答案为 $T(1,0)$。每个叶子只展开一次，时间 $O(n)$、栈深 $O(\log n)$，是本迭代写法的常数级优化版本。

### 3.4 示例演算（n = 8）

![n = 8 的三轮配对演算](images/wc24_q4_walkthrough.svg)

| 轮次 | 当前序列（每一项是一个"队伍"或"比赛对"） | 说明 |
|------|------------------------------------------|------|
| 0 | $1,\ 2,\ 3,\ 4,\ 5,\ 6,\ 7,\ 8$ | 初始 rank，升序 |
| 1 | $(1,8),\ (2,7),\ (3,6),\ (4,5)$ | $i$ 与 $8-1-i$ 配对 |
| 2 | $((1,8),(4,5)),\ ((2,7),(3,6))$ | 首尾再配：$(1,8)$ 碰 $(4,5)$ |
| 3 | $(((1,8),(4,5)),((2,7),(3,6)))$ | 只剩两项，包一层即答案 |

对照官方示例 3，第 2 轮的两个串与题面完全一致，最终结果也逐字符相同。

## 4. 算法细节

1. **序列元素是字符串**：第 $k$ 轮的元素是一整个比赛对串，不要试图用数字或下标表示，否则外层括号无处安放。
2. **双指针首尾配对**：用 $i$ 与 $j = m-1-i$ 向中间收缩，循环条件写 $i < j$；更简洁的是直接 `for i in range(m // 2)`，因为 $m$ 一定是偶数。
3. **顺序不能写反**：必须是 `"(" + teams[i] + "," + teams[j] + ")"`。写成 `teams[j]` 在前会得到 `((4,1),(3,2))` 这类"弱队在前"的错误输出，而 LeetCode 是**精确字符串比较**，一字符不同即 WA。
4. **每轮整体替换**：C++ 用 `teams.swap(next)` 交换指针，避免把 `next` 拷回 `teams` 的 $O(n)$ 开销；`next.reserve(m / 2)` 免去扩容。
5. **轮数上界**：$\log_2 4096 = 12$，循环次数极少，不需要任何剪枝或提前终止。
6. **字符总量**：最终串长度为 $3(n-1) + \sum \text{各位数字的位数}$，即 $n = 4096$ 时 $12285 + 15277 = 27562$ 个字符；Python 用列表推导一次性生成下一轮列表，避免在循环里 `append` 与 `+=` 拼串的额外开销。
7. **递归写法**：$T(m,i)$ 每层把区间折半展开，深度 $\log_2 n \le 12$，不存在爆栈风险；它对 $m$ 的判断是"$m = n$ 时到底层"，注意别写成"$m = 1$ 时到底层"。
8. **无需特判 $n$ 为奇数**：由约束 $n = 2^k$，每轮长度必为偶数，不会出现无人可配的情况。

## 5. 正确性证明

**定义**：对字符串 $t$，$\min(t)$ 表示 $t$ 中出现的**最小队伍编号**（即该比赛对里最强的队伍）。记第 $r$ 轮的序列为 $S_r$，长度 $m_r = n/2^r$，$S_0 = [1,2,\dots,n]$。

**引理 1（顺序不变式）**：对每个 $r \ge 0$，$S_r$ 满足 $\min(S_r[0]) < \min(S_r[1]) < \cdots < \min(S_r[m_r-1])$，且 $\min(S_r[k]) = k+1$。

**证明**：对 $r$ 归纳。$r = 0$ 时 $S_0[k] = k+1$，$\min = k+1$，成立。设 $S_r$ 成立，算法生成

$$S_{r+1}[k] = \bigl(S_r[k],\, S_r[m_r-1-k]\bigr),\quad 0 \le k < m_r/2$$

因为 $k < m_r - 1 - k$，由归纳假设 $\min(S_r[k]) = k+1 < \min(S_r[m_r-1-k])$，故

$$\min(S_{r+1}[k]) = \min(S_r[k]) = k+1$$

于是 $\min(S_{r+1}[0..]) = 1,2,\dots,m_r/2$ 严格递增，$S_{r+1}$ 满足不变式。∎

**引理 2（配对对象正确）**：题面要求每一轮把"最强的剩余项"与"最弱的剩余项"配对，即把 $S_r$ 的第 $k$ 项与第 $m_r-1-k$ 项配对。

**证明**：由引理 1，$S_r$ 按 $\min$ 严格升序，故第 $k$ 项恰是"第 $k+1$ 强"的比赛对，第 $m_r-1-k$ 项恰是"第 $k+1$ 弱"的比赛对。"强碰弱"就是这两项配对。∎

**引理 3（结构唯一）**：给定每轮的配对关系，最终字符串被唯一确定。

**证明**：每一轮把若干个已确定的子串用 `"(" + 左 + "," + 右 + ")"` 组合成一个新串；叶子是 $1\sim n$ 的字面量。组合方式与配对关系一一对应，且拼接顺序（左子在先）固定，因此最终串唯一。∎

**定理**：算法返回的字符串与题面定义的答案完全一致。

**证明**：归纳证明第 $r$ 轮算法得到的序列 $S_r$ 与题面定义的第 $r$ 轮序列相同。$r = 0$ 时两者都是 $[1,\dots,n]$。设第 $r$ 轮相同，由引理 2 两者在第 $r$ 轮的配对关系相同，故各自生成的第 $r+1$ 轮序列也相同。循环共执行 $\log_2 n$ 轮，结束时长度恰为 1，由引理 3 该唯一串就是答案。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。共 $\log_2 n$ 轮；第 $r$ 轮对 $n/2^r$ 个元素各拼接一个长度 $O(2^r)$ 的子串，单轮字符总量 $O(n)$，累计 $O(n\log n)$。$n = 4096$ 时约 $5 \times 10^4$ 次字符操作，实际运行在毫秒级。
- **空间**：$O(n)$。同一轮的各个元素串互不包含、叶子各出现一次，故 `teams`（或 `next`）所有元素长度之和为 $O(n)$；最终返回串长度同样是 $O(n)$。若改用 §3.3 的递归写法，额外空间只有 $O(\log n)$ 的递归栈，时间降到 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    string findContestMatch(int n) {
        vector<string> teams;
        teams.reserve(n);
        for (int i = 1; i <= n; ++i) teams.push_back(to_string(i));

        while (teams.size() > 1) {
            int m = (int)teams.size();
            vector<string> next;
            next.reserve(m / 2);
            for (int i = 0; i < m / 2; ++i)          // 首尾配对：i 与 m-1-i
                next.push_back("(" + teams[i] + "," + teams[m - 1 - i] + ")");
            teams.swap(next);                        // 指针交换，避免整表拷贝
        }
        return teams[0];
    }
};
```

### Python

```python
class Solution:
    def findContestMatch(self, n: int) -> str:
        teams = [str(i) for i in range(1, n + 1)]
        while len(teams) > 1:
            m = len(teams)
            teams = ["(" + teams[i] + "," + teams[m - 1 - i] + ")"
                     for i in range(m // 2)]
        return teams[0]
```

## 8. 边界情况与易错点

1. **$n = 2$（最小规模）**：循环只跑一轮，返回 `"(1,2)"`；若循环条件写成 `while len(teams) > 0` 会在长度 1 时继续配对而越界。
2. **左右顺序写反**：`teams[m-1-i]` 在前、`teams[i]` 在后，会输出 `"(4,1)"` 这类弱队在前的串——LeetCode 精确比对，必然 WA。
3. **相邻配对的经典错误**：第二轮把上一轮结果按相邻两项组合，得到 `(((1,8),(2,7)),((3,6),(4,5)))`，与答案差之千里；务必坚持「当前序列首尾」。
4. **逗号后加空格**：`"(1, 2)"` 看起来更美观，但与标准答案不匹配；题面格式里逗号两侧**没有空格**，括号也没有。
5. **括号层数算错**：答案的括号层数恰好是 $\log_2 n$，少包一层或多包一层都会导致结构错误；$n=8$ 时外层有 3 层括号，可用来快速自检。
6. **把 `for i in range(m//2)` 写成 `range(m)`**：会重复配对（同一个对被生成两次），长度不再减半，甚至进入死循环。
7. **Python 中 `teams[i] + "," + teams[j]` 少写括号**：只拼了逗号没拼左右括号，长度虽然也是 $O(n)$，但输出不是合法结构。
8. **误以为要处理奇数队轮空**：约束保证 $n = 2^k$；若题目改成任意 $n$，则需要先补一个"轮空"占位再按同样规则配对。

**延伸思考**：

1. **直接递归构造**：用 §3.3 的 $T(m,i)$，每个节点只算一次，时间 $O(n)$，比逐轮复制字符串渐进更优；$n$ 很大时（如 $2^{20}$）差距会体现出来。
