# LeetCode 二叉树的直径 题解

## 1. 题目概述

- **标题 / 题号**：二叉树的直径（#543，easy）
- **链接**：https://leetcode.cn/problems/diameter-of-binary-tree/
- **来源**：LeetCode 第 24 场周赛 Q1
- **难度**：简单
- **标签**：树、深度优先搜索、二叉树、树形 DP

**题意**：给一棵二叉树的根节点，返回它的**直径**——树中任意两个节点之间最长路径的**边数**。这条路径可以经过根节点，也可以整条都躲在某棵子树里。

**约束**：

- 节点数 $1 \le n \le 10^4$
- $-100 \le \text{Node.val} \le 100$，但节点值不参与任何运算，只看树的形状

## 2. 示例

**示例 1**

```text
输入：root = [1,2,3,4,5]
输出：3
解释：树为 1 的孩子 2、3，2 的孩子 4、5。
      最长路径是 4 → 2 → 1 → 3（或 5 → 2 → 1 → 3），共 3 条边。
```

**示例 2**

```text
输入：root = [1,2]
输出：1
解释：只有一条边 2 → 1，路径长度即 1。
```

**示例 3（补充：直径不经过根）**

```text
输入：root = [1,2,null,3,4,5,null,6]
输出：4
解释：1 只有左孩子 2；2 的孩子是 3、4；3 的左孩子 5，4 的左孩子 6。
      最长路径 5 → 3 → 2 → 4 → 6 共 4 条边，整条都待在根的左子树里；
      经过根的路径最长只有 3（5 → 3 → 2 → 1）。所以「只算根」会答错。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举所有节点对 $(u,v)$，再求它们的距离。点对有 $O(n^2)$ 个，每次求距离要么从 $u$ 出发 DFS 一遍（$O(n)$），要么算 LCA（$O(n)$ 预处理 + $O(\log n)$ 询问），总复杂度 $O(n^3)$ 或 $O(n^2 \log n)$。换一种暴力：以每个点为起点跑一次 DFS 求最远距离，也要 $O(n^2)$，$n = 10^4$ 时约 $10^8$ 次邻居遍历，常数大、Python 里必然超时。

瓶颈在于「每条路径都要重新走一遍」。但这些路径之间有大量共享结构：同一条从某节点向下的链，会被很多条路径复用。

### 3.2 核心观察：路径的「最高点」+ 两条下行链

![以最高点结算：候选长度 = 左高 + 右高](images/wc24_q1_diameter_gain_concept.svg)

任取一条路径，把它上面**离根最近**的那个节点 $u$ 叫作这条路径的**最高点**。在 $u$ 处把路径切开，剩下的部分至多两段，每一段都是从 $u$ 的某个孩子一路向下走到某个后代的**下行链**（若 $u$ 本身就是端点，则只有一段）。

于是以 $u$ 为最高点的最长路径，长度恰好等于「左子树中最长下行链的边数」加上「右子树中最长下行链的边数」，即

$$\text{cand}(u) = h(l) + h(r)$$

其中 $h(l)$、$h(r)$ 分别是左、右子树中**向下最长链的边数**（下一节给出精确定义）。

**为什么是加法**：路径要穿过 $u$，就只能从左边下去、从右边下去，两侧各挑最深的一条，互不影响；如果两边都挑不到（$u$ 是叶子），两条链都记 0。

于是整棵树的直径就是

$$ans = \max_{u}\bigl(h(l) + h(r)\bigr)$$

**关键转变**：不再枚举「点对」，而是枚举「路径的最高点」。每个节点的 $h$ 只依赖两个孩子，自底向上算一遍即可，信息不再重复计算。

### 3.3 算法流程 / 状态转移

![后序 DFS：返回一条链，本地结算答案](images/wc24_q1_postorder_flow.svg)

定义 $h(u)$ 为**按节点数计**的子树高度：空树 0，叶子 1，一般地

$$h(u) = \max\bigl(h(l),\, h(r)\bigr) + 1$$

（选节点数口径而不是边数口径，好处是空树直接写 0，不用引入 $-1$；此时「从 $u$ 经过左孩子向下的边数」恰好就是 $h(l)$，候选值可以直接写 $h(l)+h(r)$。）

一次**后序** DFS 完成两件事：

1. 递归得到 $L = h(l)$、$R = h(r)$；
2. 用 $L + R$ 更新全局答案，然后向上返回 $\max(L,R)+1$。

注意返回值和答案值是**两个不同的量**：答案 $L+R$ 在本地结算，返回值只能是一条链。

### 3.4 示例演算

![示例 [1,2,3,4,5] 的后序演算表](images/wc24_q1_walkthrough.svg)

对 `root = [1,2,3,4,5]`，后序访问顺序是 4、5、2、3、1：

| 访问顺序 | 节点 | $h(l)$ | $h(r)$ | 候选 $L+R$ | 返回 $h(u)$ |
|---------|------|--------|--------|-----------|------------|
| 1 | 4 | 0 | 0 | 0 | 1 |
| 2 | 5 | 0 | 0 | 0 | 1 |
| 3 | 2 | 1 | 1 | **2** | 2 |
| 4 | 3 | 0 | 0 | 0 | 1 |
| 5 | 1 | 2 | 1 | **3** | 3 |

答案为 $\max(0,0,2,0,3) = 3$，对应路径 4 → 2 → 1 → 3（3 条边）。注意节点 2 处的候选 2 也很大，如果树的右子树更矮，它就会成为答案——这正是「直径可能不经过根」的来源。

## 4. 算法细节

1. **高度口径统一**：空节点返回 0、叶子返回 1（节点数口径）。此时从 $u$ 经左孩子向下的最长边数就是 $h(l)$，候选直接写 `left + right`；若改用「空 = −1」的边数口径，叶子为 0，候选要写成 `left + right + 2`，极容易差 1。
2. **严格后序**：先递归求 $L, R$，再更新答案，最后返回。顺序颠倒会用上还没算好的子树信息。
3. **返回值与答案分离**：返回给父节点的必须是 $\max(L,R)+1$（一条链）。若返回 $L+R$，父节点会把这当成一条链继续和兄弟链相加，等价于允许路径在子树里折返；而且叶子会返回 0 而不是 1，整棵树的高度定义直接塌缩（对 `[1,2,3]` 会得到 0）。
4. **答案的承载方式**：C++ 用 `int&` 引用传入，Python 用 `nonlocal` 或 `self.ans`；也可以让 `dfs` 返回 `(高度, 答案)` 二元组，但多一层打包开销。
5. **递归深度 = 树高**：链状树可达 $10^4$ 层。C++ 默认栈足够；Python 默认递归上限 1000，必须 `sys.setrecursionlimit(20000)`（或改写成显式栈的后序迭代）。
6. **只依赖形状**：节点值允许为负、为 0，判断空节点只能用 `node is None` / `!node`，绝不能用 `if node.val` 之类的真假值判断。
7. **答案单位是边数**：一棵 $n$ 个节点的链，直径是 $n-1$ 而不是 $n$。本口径天然正确（叶子 $h=1$ 但候选 $0+0=0$），无需额外减一。

## 5. 正确性证明

**引理 1（返回值即高度）**：对任意节点 $u$，`dfs(u)` 的返回值等于 $h(u)$（节点数口径的子树高度）。

**证明**：对子树规模归纳。$u$ 为空时返回 0，等于 $h(\varnothing)=0$。$u$ 非空时，由归纳假设两个递归调用分别返回 $h(l)$、$h(r)$，函数返回 $\max(h(l),h(r))+1$，与定义一致。∎

**引理 2（单点最优性）**：对任意节点 $u$，以 $u$ 为最高点的最长路径，其边数恰为 $h(l)+h(r)$。

**证明**：设 $P$ 是以 $u$ 为最高点的任一路径。去掉 $u$ 后 $P$ 分成至多两段，分别落在左、右子树中（某一侧可以为空，长度记 0）。每一段都是从 $u$ 的孩子出发向下的链，长度不超过该子树的最长下行链，即 $h(l)$ 或 $h(r)$，故 $\lvert P\rvert \le h(l)+h(r)$，上界成立。

再证可达：设 $a$ 为左子树中最深叶子（取到 $h(l)$ 的那条链的末端），$b$ 为右子树中最深叶子；若某侧为空，就用 $u$ 自己充当该侧端点。则 $a \to u \to b$ 是一条合法路径，长度正好是 $h(l)+h(r)$。∎

**引理 3（最高点唯一）**：树中任意一条路径都有唯一的最高点，且该路径是以它为最高点的路径。

**证明**：路径上的节点按深度排序，取深度最小者。若有两个不同的节点深度同为最小，路径在它们之间的部分必须先向下再向上，中间节点深度更大，矛盾。故深度最小者唯一，记作 $u$；路径上其余节点都在 $u$ 的子树内，$u$ 到两端各走一棵子树（或 $u$ 本身就是端点），符合引理 2 的前提。∎

**定理**：算法输出的 `ans` 等于树的直径。

**证明**：DFS 后序遍历了所有节点，由引理 1 每个节点拿到的 $L,R$ 都是真实高度，因此 `ans` 是 $\max_u \bigl(h(l)+h(r)\bigr)$。由引理 2，每个候选值都是某条合法路径的长度且可达，所以 `ans` 不超过直径；由引理 3，每条路径（包括直径）都被某个最高点的候选覆盖，所以 `ans` 不小于直径。两者夹逼，`ans` 恰为直径。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点被 `dfs` 访问一次，函数体内只有两次加法、一次比较和一次取最大值，常数时间；不存在重复遍历整棵子树的操作。
- **空间**：$O(H)$，$H$ 为树高。开销全部来自递归栈，最好（平衡树）$O(\log n)$，最坏（链）$O(n)$；除栈以外只用了常数个变量，没有额外数组或哈希表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int diameterOfBinaryTree(TreeNode* root) {
        int ans = 0;
        dfs(root, ans);
        return ans;
    }

private:
    // 返回子树高度（节点数口径：空树 0，叶子 1），同时用引用带回答案
    int dfs(TreeNode* node, int& ans) {
        if (!node) return 0;
        int left = dfs(node->left, ans);
        int right = dfs(node->right, ans);
        ans = max(ans, left + right);    // 以 node 为最高点结算候选
        return max(left, right) + 1;     // 只向父节点交一条下行链
    }
};
```

### Python

```python
import sys
from typing import Optional

sys.setrecursionlimit(20000)   # 链状树深度可达 10^4


class Solution:
    def diameterOfBinaryTree(self, root: Optional[TreeNode]) -> int:
        self.ans = 0

        def dfs(node: Optional[TreeNode]) -> int:
            if node is None:
                return 0
            left = dfs(node.left)
            right = dfs(node.right)
            self.ans = max(self.ans, left + right)   # 以 node 为最高点结算
            return max(left, right) + 1              # 只向父节点交一条下行链

        dfs(root)
        return self.ans
```

## 8. 边界情况与易错点

1. **单节点**：`[1]` → `0`。答案初值取 0（不能取 $-1$），因为叶子处候选就是 $0+0=0$。
2. **两个节点**：`[1,2]` → `1`，不要因为「节点数是 2」就返回 2，题目要的是**边数**。
3. **链状树**：$10^4$ 个节点排成一条链，答案是 $9999$，同时递归深度 $10^4$。C++ 无压力；Python 不加 `setrecursionlimit` 会直接 `RecursionError`。
4. **直径不经过根**：`[1,2,null,3,4,5,null,6]` → `4`。只在根处算「左高 + 右高」会得 3，必须对每个节点都结算一次。
5. **节点值为 0 或负数**：值域是 $[-100,100]$，`0` 是完全合法的节点值；序列化里的 `null` 才表示空。用 `if not node` 判空是对的（`None`/`nullptr`），但不要用 `if not node.val`。
6. **返回值写成 `L + R`**：最常见的错误。父节点会把它当成一条链继续累加兄弟链，路径在子树内折返；同时叶子返回 0 而非 1，高度整体塌缩。
7. **忘记在空节点处返回**：`dfs` 开头必须有 `if (!node) return 0;`，否则访问空指针；同时这也保证了 `left + right = 0` 在叶子处成立。

## 相关题目与扩展

- [LeetCode 124. 二叉树中的最大路径和](https://leetcode.cn/problems/binary-tree-maximum-path-sum/)：同款「最高点 + 两条下行链」模型，区别是权值在节点上且可为负，向上返回时要和 0 取 $\max$ 剪掉负贡献。
- [LeetCode 687. 最长同值路径](https://leetcode.cn/problems/longest-univalue-path/)：仍然是最高点结算，但两条下行链要求与父节点同值，不满足就把对应一侧高度清零。
- [LeetCode 1522. N 叉树的直径](https://leetcode.cn/problems/diameter-of-n-ary-tree/)：把「左高 + 右高」推广为「所有孩子深度的前两大之和」，并不再固定两个分支。
- [LeetCode 1245. 树的直径](https://leetcode.cn/problems/tree-diameter/)：无向树版本，可用两次 BFS（从任意点找最远点，再从该点找最远点）或同样的树形 DP。

**延伸思考**：若要返回**具体路径**而不只是长度，可在每个节点结算时记录取到最大值的那个 $u$ 以及左右两条链的末端叶子，之后从 $u$ 分别向两侧回溯即可，时间复杂度不变。若边上带权（权可负），「最高点 + 两条链」的框架仍成立，但要把「高度」换成「最大路径和」，并在负权时把贡献截断到 0；而「两次 BFS」的做法在负权下会失效，因为 BFS 求的是边数最远而非权值最远，此时必须改用树形 DP。
