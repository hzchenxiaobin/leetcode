# LeetCode 滑动谜题 题解

## 1. 题目概述

- **标题 / 题号**：滑动谜题（#773，hard）
- **链接**：https://leetcode.cn/problems/sliding-puzzle/
- **来源**：LeetCode 第 69 场周赛 Q3
- **难度**：困难
- **标签**：广度优先搜索、双向搜索、A\* 搜索、启发式搜索、数组、矩阵、状态压缩

**题意**：一块固定的 $2\times 3$ 板子上摆着数字 $1\sim 5$ 和一块空格 $0$。一次「移动」指把 $0$ 与它**上下左右相邻**的数字交换。当板子恰好变成 $\begin{bmatrix}1&2&3\\4&5&0\end{bmatrix}$ 时谜题解开。给定初始板 `board`，返回**最少**移动次数；永远解不开则返回 `-1`。

注意板子的**形状是固定的**：只有一块 $2\times 3$ 的板、只有 $5$ 块砖，不存在更小或更大的子问题——所以整题的搜索空间是一个只有几百个点的图，而不是一个无限棋盘。

**约束**：

- `board.length == 2`，`board[i].length == 3`
- $0 \le \text{board}[i][j] \le 5$，六个格子里的值**互不相同**（即 $0\sim 5$ 的一个排列）

这条约束等价于「`board` 是 $0\sim5$ 的一个排列」，于是状态总数被钉死在 $6! = 720$ 以内——这是本题一切优化的源头。

## 2. 示例

**示例 1**

```text
输入：board = [[1,2,3],[4,0,5]]
输出：1
解释：0 在下行中间，与右边的 5 交换一次即得 [[1,2,3],[4,5,0]]。
```

**示例 2**

```text
输入：board = [[1,2,3],[5,4,0]]
输出：-1
解释：无论怎么滑都到不了目标态。直观原因：4 与 5 的相对顺序反了，
      而本题所有合法移动都无法改变「去掉 0 之后 1..5 的相对顺序的奇偶性」。
```

**示例 3**

```text
输入：board = [[4,1,2],[5,0,3]]
输出：5
解释：最少 5 步，官方给出的一条最优路径：
      0: [[4,1,2],[5,0,3]]   1: [[4,1,2],[0,5,3]]   2: [[0,1,2],[4,5,3]]
      3: [[1,0,2],[4,5,3]]   4: [[1,2,0],[4,5,3]]   5: [[1,2,3],[4,5,0]]
```

## 3. 解题思路

### 3.1 暴力思路

把「移动」写成递归：每一步枚举 $0$ 能换的所有邻居，一路试下去，直到板子等于目标态。

这条路有两个致命问题：

1. **分支因子与深度都不可控**。四个角上的 $0$ 只有 2 个邻居、中间两格的 $0$ 有 3 个，六个位置平均出度是 $14/6 = 7/3$；本题最长答案是 21 步（把 $6!$ 个排列全部跑一遍可以验证）。于是一棵深度 21、平均分支 $7/3$ 的搜索树约有 $(7/3)^{21}\approx 5\times10^{7}$ 条路径，无解时（示例 2）必须把这棵树**全部穷尽**才能回答 `-1`。
2. **先到的不一定最优**。DFS 找到的第一条可行路径未必最短，而题目要的是**最少**步数。

即使改成「带 visited 的 DFS」，也只是能判断可达性，还是拿不到最短距离。真正的浪费在于：**同一条路径之外的重排会被反复访问**——鸟瞰整棵树时会发现，能到达的棋盘其实只有 360 种，却被搜索了数千万次。

### 3.2 核心观察：状态图只有 720 个点，最短路就是答案

![状态空间与奇偶不变量](images/wc69_q3_state_space_parity.svg)

把每个棋盘看成一个**状态**，两个状态之间连边当且仅当一次移动能把它们互相转换。于是：

- **点数**：$0\sim5$ 的排列共 $6! = 720$ 个，所以图最多 720 个点；
- **边数**：每个点最多 3 条出边（中间的 $0$），所以最多约 $720\times 3/2 \approx 1080$ 条边；
- **边权**：每次移动代价都是 1，是无权图。

题目问的「最少移动次数」于是就是**无权图上起点到目标态的最短路边数**，标准解法是 BFS。搜索的对象从「移动序列」换成了「棋盘状态」，这是本题的核心跳跃：状态数只有 720，BFS 一定在几百次扩展内结束。

进一步的观察有两条，都能省事：

**观察 A（反向建表）**：BFS 可以从**目标态**出发而不是从起点出发。目标态只有 $\begin{bmatrix}1&2&3\\4&5&0\end{bmatrix}$ 一个，从它出发做一遍 BFS 就得到「任意棋盘到目标的距离」整张表，之后对任意输入只是一次查表。

**观察 B（只有一半状态可达）**：把 $0$ 去掉，把剩下的 $1\sim5$ 按它在扁平序列里出现的顺序排成一列，记这一列的**逆序数奇偶性**。

- $0$ 左右移动：它只是和一个相邻数字换位，$1\sim5$ 的相对顺序**完全没有变**；
- $0$ 上下移动：在 $2\times3$ 的扁平序列里两个位置相差 3，被换的数字**跨过 2 个数字**，等于做了 2 次交换，奇偶性也**不变**。

所以奇偶性是移动下的**不变量**，$720$ 个排列被劈成两半，只有与目标态同奇偶的那 360 个可达。示例 3 的起点去掉 $0$ 得 $4,1,2,5,3$，逆序数是 4（偶），与目标态的 $1,2,3,4,5$（逆序数 0）同侧，故可解；示例 2 的起点得 $1,2,3,5,4$，逆序数 1（奇），故必为 `-1`。

不过实现上**不需要真的写奇偶判定**：从目标态 BFS 时，走不到的状态在表里就是缺省值 `-1`，判断自然正确。奇偶性在这里的价值是让我们事先知道「表里只会填 360 项」。

### 3.3 算法流程

![算法流程：编码、邻接表、反向 BFS](images/wc69_q3_algorithm_flow.svg)

1. **扁平化**：把 $2\times3$ 的板按行主序摊成 6 元序列 $(d_0,d_1,\dots,d_5)$。
2. **编码**：用 base-6 把它压成一个整数

$$\text{state} = \sum_{i=0}^{5} d_i \cdot 6^{i}, \qquad d_i \in \{0,1,\dots,5\}$$

   $\text{state}$ 的取值范围是 $[0, 6^6) = [0, 46656)$，恰好一对一（见引理 1）。
3. **预计算邻接表**：板子形状固定，所以「$0$ 在位置 $p$ 时能换到哪些位置」是一张写死的表：

$$nxt = \bigl[(1,3),\ (0,2,4),\ (1,5),\ (0,4),\ (1,3,5),\ (2,4)\bigr]$$

4. **从目标态反向 BFS**：$\text{dist}[\,\text{goal}\,] = 0$，队列初始只放目标态。每次弹出一个状态，解码出 $0$ 的位置 $p$，对 $nxt[p]$ 里的每个 $np$ 生成后继：

$$\text{next} = \text{state} + (d_{np} - d_p)\bigl(6^{p} - 6^{np}\bigr)$$

   若该状态尚未赋值，则 $\text{dist}[\text{next}] = \text{dist}[\text{state}] + 1$ 并入队。$d_p$ 恒为 0，这一步是 $O(1)$。
5. **查表**：`dist[start]` 就是答案；若从未被赋值则为 `-1`。

### 3.4 示例演算

![示例 3 的逐步演算](images/wc69_q3_walkthrough.svg)

以示例 3 的 $\begin{bmatrix}4&1&2\\5&0&3\end{bmatrix}$ 为例，沿官方最优路径逐格看 $0$ 的走位（最后一列是该状态在反向 BFS 表中的距离）：

| 步数 | 板面 | 扁平序列 | $0$ 的位置 | $\text{dist}$ |
|:-:|------|----------|:-:|:-:|
| 0 | $\begin{bmatrix}4&1&2\\5&0&3\end{bmatrix}$ | $(4,1,2,5,0,3)$ | 4 | **5** |
| 1 | $\begin{bmatrix}4&1&2\\0&5&3\end{bmatrix}$ | $(4,1,2,0,5,3)$ | 3 | 4 |
| 2 | $\begin{bmatrix}0&1&2\\4&5&3\end{bmatrix}$ | $(0,1,2,4,5,3)$ | 0 | 3 |
| 3 | $\begin{bmatrix}1&0&2\\4&5&3\end{bmatrix}$ | $(1,0,2,4,5,3)$ | 1 | 2 |
| 4 | $\begin{bmatrix}1&2&0\\4&5&3\end{bmatrix}$ | $(1,2,0,4,5,3)$ | 2 | 1 |
| 5 | $\begin{bmatrix}1&2&3\\4&5&0\end{bmatrix}$ | $(1,2,3,4,5,0)$ | 5 | 0 |

每一步的距离都恰好减 1，说明这条路径**逐层**下降，是最优的。反向 BFS 的各层大小（从目标态往外数）为 $1,2,3,5,6,7,10,12,12,16,23,25,\dots$，最远一层是 21 层；把 22 层全部加起来正好 360，与「只有一半状态可达」吻合。

## 4. 算法细节

1. **为什么用 base-6 而不是 base-10 或字符串**：$6^6 = 46656$ 只比 $720$ 大两个数量级，可以直接开一个长度 46656 的 `int` 数组当 `dist`（每项 4 字节，约 182 KB），比哈希表省掉全部哈希开销；若用 `"123450"` 这样的字符串做 key，Python 里也能过（状态少），但 C++ 里每次 `unordered_map` 查找的常数会明显变大。
2. **位权顺序必须自洽**：编码时用 $d_i \cdot 6^i$（第 $i$ 位权重 $6^i$），解码时就用 `state % 6, state /= 6` 逐位取出——两者必须都是「低位对应下标 0」。写混了不会报错，只会得到一张全错的距离表。
3. **后继用增量公式而不是重新编码**：$\text{next} = \text{state} + (d_{np}-d_p)(6^p - 6^{np})$ 只做一次乘加，比「解码 6 位 → 交换 → 重新编码 6 位」快一个数量级；而解码本身只需要一次循环就能顺便拿到 $p$。
4. **邻居表写死**：$2\times3$ 的板只可能出现在这 6 个位置，`nxt` 是常量，不必在 BFS 里用行列坐标判断越界。若把题解推广到 $n\times m$，就在初始化时按行列生成这张表。
5. **反向建表 + 缓存**：本题每次调用只问一个棋盘，建表 $O(720)$ 完全够；但如果判题机在同一个进程里连问 $10^4$ 次（面试里常见这种追问），就把 `dist` 提成 `static` 局部变量或类成员，只建一次表，单次查询退化成 $O(1)$。
6. **双向 BFS**（可选优化）：从起点与目标态同时扩展、每次扩层数较少的一侧，遇到对方已访问的状态就合并距离。实测最坏情况（距离 21）单向 BFS 访问 360 个状态、双向只需 200 个；示例 3 从 37 个降到 15 个。本题状态数太小，收益有限，但这个模板在 $3\times3$ 八数码（181440 个可达状态）上是数量级的差别。
7. **A\* 的思路**（可选）：启发函数取五个数字到各自目标格的**曼哈顿距离之和**（忽略 $0$）。它在每次移动下最多变化 1，因此既不高估也可采纳，配合优先队列可以显著减少扩展；但要把「一致（consistent）」这一点也论证清楚，否则会退化成不保证最优的贪心。
8. **Python 实现的取舍**：直接拿 `tuple` 当状态、用 `dict` 存距离，代码最短（360 个状态，实测不到 1 ms）；唯一要小心的是原地交换后必须换回来，或者干脆 `list(cur)` 复制一份再交换，避免污染队列里的状态。
9. **`-1` 不必特判**：目标态 BFS 覆盖不到的状态在表里查不到，返回 `-1` 即可。若想 O(1) 判定，可以用引理 3 的逆序数奇偶性，但那只是「早知道答案」，不能替代求距离。

## 5. 正确性证明

**引理 1（编码是双射）**：映射 $\phi(d_0,\dots,d_5) = \sum_i d_i 6^i$ 是 $\{0,\dots,5\}^6 \to [0,46656)$ 的双射；且对任意相邻位置 $p,np$，把 $d_p$ 与 $d_{np}$ 交换后得到的状态恰为 $\text{state} + (d_{np}-d_p)(6^p - 6^{np})$。

**证明**：这就是 base-6 表示的唯一性：每个 $\text{state} \in [0,6^6)$ 有唯一的 6 位 6 进制展开，各位数字恰在 $\{0,\dots,5\}$ 中，故 $\phi$ 是双射。记 $\text{state} = \sum_i d_i 6^i$，交换前两项之和为 $d_p 6^p + d_{np} 6^{np}$，交换后为 $d_{np}6^p + d_p 6^{np}$，差值即 $(d_{np}-d_p)(6^p-6^{np})$，其余位不变。∎

**引理 2（反向 BFS 求出到目标的距离）**：设 $\text{dist}$ 由从目标态出发的 BFS 填写，则 BFS 结束后对每个状态 $s$，$\text{dist}[s]$ 等于 $s$ 到目标态的最少移动次数；不可达的状态保持缺省值。

**证明**：对 BFS 的层数 $k$ 归纳。$k=0$ 时表中只有目标态，距离为 0，正确。设所有距离 $\le k$ 的状态取值正确。任取一个距离为 $k+1$ 的状态 $s$，它必由某个距离为 $k$ 的状态 $u$ 经一次移动得到（最短路的前缀），由引理 1 的增量公式，BFS 在处理 $u$ 时生成的 $\text{next}$ 正是 $s$；此时 $s$ 尚未被赋更小的值（否则 $s$ 的距离 $\le k$，矛盾），故被赋为 $k+1$。反之，任何被赋值为 $k+1$ 的状态都由距离 $k$ 的状态一步可达，故其真实距离不超过 $k+1$；结合上一句即等于 $k+1$。不可达状态永远不会进入队列，保持缺省值。∎

**引理 3（奇偶不变量）**：记 $\pi(s)$ 为状态 $s$ 去掉 $0$ 后 $1\sim5$ 的排列，$\text{inv}(\pi)$ 为其逆序数。一次移动不改变 $\text{inv}(\pi) \bmod 2$。

**证明**：分两类。左右移动：$0$ 与同行相邻格交换。$0$ 不在 $\pi$ 中，去掉它之后 $1\sim5$ 的相对次序原封不动，逆序数不变。上下移动：在行主序下两个位置的下标相差 3，设被换的数字为 $x$，交换后 $x$ 在扁平序列中向前（或向后）跨过 2 个数字，每跨过一个就是一个逆序对的变化，因此逆序数恰好改变 $\pm 2$ 或 $0$，奇偶性不变。∎

**定理**：算法返回的值等于把 `board` 解成 $\begin{bmatrix}1&2&3\\4&5&0\end{bmatrix}$ 的最少移动次数，无解时返回 `-1`。

**证明**：由引理 1，`board` 的编码与 BFS 中的状态一一对应，且 BFS 生成的每个后继都是真实可达的一次移动。由引理 2，查表得到的 $\text{dist}[\text{start}]$ 正是起点到目标态的最少移动次数；起点不可达时表中无值，函数返回 `-1`，与题意一致。引理 3 只是解释了「为什么恰好有一半状态不可达」，不参与正确性论证。∎

## 6. 复杂度分析

- **时间**：$O(6! \cdot 3)$，即 $O(1)$ 级别的常数。BFS 最多弹出 720 个状态（实际 360 个），每个状态解码 6 位、最多生成 3 个后继，全部是常数次运算；总操作数约 $360 \times (6+3) \approx 3\times10^3$。查表 $O(1)$。
- **空间**：`dist` 数组 $6^6 = 46656$ 个 `int`，约 182 KB；BFS 队列最多同时驻留一层状态（最宽一层 25 个）。若改存哈希表，则是 $O(360)$ 项，但常数更大。递归写法不可取——需要显式的队列。
- **推广到 $n\times m$**：状态数为 $(nm)!$，$3\times3$ 八数码是 $9! = 362880$（可达 181440），此时编码要换成「康托展开」把排列压到 $[0, 9!)$，空间约 1.4 MB，仍然可做；再大就得上 IDA\* 或双向 BFS。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    int slidingPuzzle(vector<vector<int>>& board) {
        // 2x3 棋盘中每个位置（扁平下标）的相邻位置，-1 表示没有
        static const int nxt[6][3] = {
            {1, 3, -1}, {0, 2, 4}, {1, 5, -1},
            {0, 4, -1}, {1, 3, 5}, {2, 4, -1}
        };
        const int POW6[6] = {1, 6, 36, 216, 1296, 7776};
        const int N = 46656;                    // 6^6 个编码槽位

        int goal = 0, start = 0;
        for (int i = 0; i < 6; ++i) {
            goal  += ((i + 1) % 6) * POW6[i];   // 1,2,3,4,5,0
            start += board[i / 3][i % 3] * POW6[i];
        }
        if (start == goal) return 0;

        vector<int> dist(N, -1);
        queue<int> q;
        dist[goal] = 0;
        q.push(goal);
        while (!q.empty()) {
            int cur = q.front(); q.pop();
            int digit[6], p = -1, t = cur;
            for (int i = 0; i < 6; ++i) {       // 解码，同时定位 0
                digit[i] = t % 6;
                t /= 6;
                if (digit[i] == 0) p = i;
            }
            int nd = dist[cur] + 1;
            for (int k = 0; k < 3; ++k) {
                int np = nxt[p][k];
                if (np < 0) continue;
                int ns = cur + (digit[np] - digit[p]) * (POW6[p] - POW6[np]);
                if (dist[ns] == -1) {           // 首次到达即最短路
                    dist[ns] = nd;
                    q.push(ns);
                }
            }
        }
        return dist[start];                     // 不可达时为 -1
    }
};
```

### Python

```python
class Solution:
    def slidingPuzzle(self, board: list[list[int]]) -> int:
        # 每个空格位置可以与之交换的邻居位置（2x3 扁平化后的下标）
        nxt = ((1, 3), (0, 2, 4), (1, 5), (0, 4), (1, 3, 5), (2, 4))
        goal = (1, 2, 3, 4, 5, 0)

        # 从目标态反向 BFS，一次建表，之后 O(1) 查询
        dist = {goal: 0}
        q = [goal]
        head = 0
        while head < len(q):
            cur = q[head]
            head += 1
            p = cur.index(0)
            d = dist[cur] + 1
            for np in nxt[p]:
                lst = list(cur)
                lst[p], lst[np] = lst[np], lst[p]
                st = tuple(lst)
                if st not in dist:
                    dist[st] = d
                    q.append(st)

        start = tuple(board[0]) + tuple(board[1])
        return dist.get(start, -1)
```

## 8. 边界情况与易错点

1. **起点就是目标态**：如 `[[1,2,3],[4,5,0]]`，答案应为 0。Python 版靠 `dist.get(start)` 自然得到 0；C++ 版若不写 `start == goal` 提前返回也无所谓（表里就是 0），但提前返回能省一次建表。
2. **`-1` 的两种来源要分清**：一是奇偶性不对（示例 2），二是理论上更一般的「图不连通」。本题恰好只有奇偶性一种，但代码不要只依赖奇偶判定——BFS 覆盖不到才是判 `-1` 的正确依据。
3. **行列与扁平下标混淆**：$p=4$ 表示「第 1 行第 1 列」，不是「第 4 行」。`nxt` 表、`board[i/3][i%3]`、$6^p$ 三处必须用同一套下标约定，否则表能建出来但答案全错。
4. **位权方向写反**：编码用 $6^i$ 而解码用 $6^{5-i}$，会让「解码得到的 0 位置」与「增量公式里的 $p$」对不上，整张表错位。C++ 里甚至不会越界（各位权重之和仍小于 46656），错误是完全静默的——所以务必用示例 1、3 核对一下答案。
5. **原地交换忘了换回来**：Python 里 `cur` 是 tuple 无所谓，但若把状态存成 list 并在循环里原地交换，忘记还原会让后续分支全错；用 `list(cur)` 复制是最省心的写法。
6. **用 DFS 求最短距离**：DFS 只能判断可达。哪怕加 visited 剪枝，第一个到达目标的深度也不保证最小——这类错误在示例 1、3 上可能侥幸通过（路径短），在距离 21 的用例上必错。
7. **漏写 visited**：只有一层 `if` 忘了判 `dist`，BFS 会反复把已访问状态入队，在 $2\times3$ 上都可能死循环；代码里必须「赋距离」和「入队」同时发生。
8. **误以为要按行列建图搜索**：本题的搜索空间是**棋盘状态的排列**，不是格子坐标；在格子上做 BFS 或最短路（比如把数字当成可自由移动的粒子）会得到错误答案，因为数字之间会互相占位。

**延伸思考**：把 $2\times3$ 换成 $3\times3$ 就是经典**八数码**，可达状态 181440 个，此时需要康托展开做状态编码（把排列映射到 $[0,9!)$），并可配合双向 BFS 或 IDA\*（启发函数用曼哈顿距离）。再加一层难度：如果允许**任意**两块砖交换（不限相邻），答案就退化成 $5 - \text{已就位的砖数}$ 之类的贪心；如果板子允许旋转或翻转，则要先对状态做规范化（取 8 种对称形态里字典序最小的那个），这其实就是「状态去重前先归一化」的通用套路。再往深一层，$n$ 数码的可解性有通用判据：**宽度为奇数**时只看「去掉 $0$ 后逆序数为偶数」，**宽度为偶数**时还要叠加空白所在行的奇偶性。本题宽度是 3（奇数），恰好落在前一种，与引理 3 的结论一致——但**推导时仍要按自己的移动规则重新算一遍，不要背公式**，因为「行主序扁平化」的偏移量会随矩形形状变化。
