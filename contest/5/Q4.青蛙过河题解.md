# LeetCode 青蛙过河 题解

## 1. 题目概述

- **标题 / 题号**：青蛙过河（#403，hard）
- **链接**：https://leetcode.cn/problems/frog-jump/
- **来源**：LeetCode 第 5 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、哈希表

**题意**：河被切成若干单元格，`stones` 按升序给出所有有石子的位置。青蛙从 `stones[0] = 0` 出发，只能踩着石子向前跳：

- 第一步**固定跳 1 格**；
- 若上一跳长度为 $k$，下一次只能跳 $k-1$、$k$、$k+1$ 格（其中 $k-1=0$ 等于原地，不允许）；
- 每一跳都必须落在石子上，不能落水，也不能后退。

问能否最终落在最后一块石子上。注意**允许越过中间的石子**，并不要求一块块挨着跳。

**约束**：

- $2 \le n \le 2000$，其中 $n = \lvert \text{stones} \rvert$
- $0 \le \text{stones}[i] \le 2^{31}-1$
- $\text{stones}[0] = 0$，且 `stones` 严格递增

## 2. 示例

**示例 1**

```text
输入：stones = [0,1,3,5,6,8,12,17]
输出：true
解释：跳跃长度依次为 1, 2, 2, 3, 4, 5，落点位置 0 →1 →3 →5 →8 →12 →17，
      对应下标 0 →1 →2 →3 →5 →6 →7；下标 4（位置 6）的石子被直接越过。
```

**示例 2**

```text
输入：stones = [0,1,2,3,4,8,9,11]
输出：false
解释：前 5 块石子连成 0..4，青蛙最远跳到位置 4，此处上一跳至多为 2，
      下一步最多到 7；8 号石子与 4 相距 4 格，跳不过去。
```

**补充（非官方）**

```text
输入：stones = [0,2]
输出：false
解释：第一步只能跳 1 格，而位置 1 没有石子，无处落脚。
```

## 3. 解题思路

### 3.1 暴力思路

从 0 出发 DFS 枚举所有合法跳跃序列：每步至多 3 个分支、最多 $n-1$ 步，复杂度 $O(3^n)$，$n = 2000$ 时完全不可行。

另一种常见的错误想法是「状态就是位置 $p$，记 `reachable[p]`」。可它连转移都写不出来：不知道导致当前位置的上一跳 $k$，就无从判断下一步能跳多远。所以这里缺的是**信息**，不是算力——必须把 $k$ 一起放进状态。

### 3.2 核心观察：(i,k) 二元状态 + 位置哈希

![同一块石子可能由不同 k 到达，后续可跳距离随之不同](images/wc5_q4_state_design.svg)

定义状态 $(i,k)$：**站在第 $i$ 块石子上，且上一跳长度为 $k$**。一条转移就是

$$(i,k) \longrightarrow \Bigl(\operatorname{idx}\bigl(\text{stones}[i]+d\bigr),\; d\Bigr),\qquad d \in \{k-1,\,k,\,k+1\},\ d > 0$$

其中 $\operatorname{idx}(x)$ 是「位置 $x$ 上的石子下标」，用哈希表实现，单次 $O(1)$；查不到说明落水，丢弃。四个关键点：

1. **起点语义**：把起点记成 $(0,0)$，即「上一跳长度为 0」。它的候选距离是 $-1,0,1$，前两个非法，只剩 $1$——于是「第一步必须跳 1」不需要任何特判，它是转移规则的**自然推论**。
2. **无环**：每次落点位置严格增大，所以「按下标 $i$ 从小到大处理」就是这张 DAG 的拓扑序，既不用递归也不用队列。
3. **状态上界**：落到下标 $i$ 至少跳了 $i$ 次（每次至少推进一块石子），而第 $t$ 次跳跃长度不超过 $t$，故 $k \le i$。集合 $dp[i]$ 只需容纳 $1 \le k \le i$，状态总数上界 $\sum_{i=0}^{n-1}(i+1) = O(n^2)$。
4. **同一位置、不同 $k$**：示例 1 中位置 6 的石子（下标 4）既能由 $(3,2)$ 跳 1 格到达、也能由 $(2,2)$ 跳 3 格到达，于是 $dp[4] = \{1,3\}$。这正是必须把 $k$ 写进状态的原因。

### 3.3 算法流程

![算法流程：按石子下标逐层推进，三种距离各查一次表](images/wc5_q4_algo_flow.svg)

1. 若 $n = 1$ 返回 true（数据保证 $n \ge 2$，防御性写法）。
2. 若 `stones[1] != 1` 直接返回 false：第一步只能跳 1 格，位置 1 没有石子就无从起跳。这只是剪枝，DP 本身也会得出 false。
3. 建立哈希表 `idx`：位置 $\to$ 下标。
4. `dp[0] = {0}`，其余 $dp[i] = \varnothing$。
5. 对 $i = 0,1,\dots,n-2$：若 $dp[i]$ 为空就整层跳过；否则对每个 $k \in dp[i]$、每个 $d \in \{k-1,k,k+1\}$ 且 $d > 0$：
   - 令 $j = \operatorname{idx}(\text{stones}[i]+d)$，不存在则丢弃这一跳；
   - 若 $j = n-1$，立即返回 true；
   - 否则把 $d$ 并入 $dp[j]$。
6. 所有层扫完仍未命中末石，返回 false。

层与层之间只依赖更小的下标，所以枚举顺序不影响结果；集合自带去重，同一个 $(j,d)$ 不会被重复展开。

### 3.4 示例演算

![示例 1 的逐层 dp 集合，以及示例 2 的死路](images/wc5_q4_walkthrough.svg)

示例 1（`stones = [0,1,3,5,6,8,12,17]`）逐层推进，得到

$$\bigl(dp[0],\dots,dp[7]\bigr) = \bigl(\{0\},\{1\},\{2\},\{2\},\{1,3\},\{2,3\},\{4\},\{5\}\bigr)$$

其中 $dp[7]$ 非空，答案 true。取其中一条路径（长度 1,2,2,3,4,5）：

$$0 \xrightarrow{1} 1 \xrightarrow{2} 3 \xrightarrow{2} 5 \xrightarrow{3} 8 \xrightarrow{4} 12 \xrightarrow{5} 17$$

注意这一跳 $5 \xrightarrow{3} 8$ 越过了位置 6 上的石子（下标 4）——**允许跳过石子**，这正是示例 1 解释里「第 4 块直接到第 6 块」的含义。

示例 2（`stones = [0,1,2,3,4,8,9,11]`）在位置 4 上 $dp = \{1,2\}$：下一步最远跳 $2+1 = 3$ 格，只能摸到 7；8 号石子相距 4 格，因此 $dp[5],dp[6],dp[7]$ 全为空集，返回 false。

## 4. 算法细节

1. **状态容器**：C++ 用 `vector<unordered_set<int>> dp(n)`，Python 用 `[set() for _ in range(n)]`。也可以把状态编码成整数 `i*(n+1)+k` 塞进单个哈希集合，或开一张 $n \times (n+1)$ 的 `char` 表（约 4 MB，常数最小但内存最大）。三者复杂度同阶，集合写法内存最省。
2. **位置表**：C++ 用 `unordered_map<int,int>` 并 `reserve(2*n)` 减少 rehash；Python 用 `dict`。查询时要区分「不存在」和「下标 0」，写成 `it == idx.end()` / `is None`，不要用默认值 0。
3. **$d \le 0$ 必须过滤**：$k = 1$ 时 $k-1 = 0$ 表示原地不动，题目不允许；$k = 0$（起点）时 $k-1 = -1$ 更是非法距离。漏掉这一步，换成 BFS 写法就会在同一块石子上自循环。
4. **$k \le i$ 的上界**：由 3.2 第 3 点，$dp[i] \subseteq [1,i]$。这条上界既说明布尔表只需 $n \times (n+1)$，也直接给出 $O(n^2)$ 的状态总数上界。
5. **越界与溢出**：`stones[i] + d` 形式上最坏可达 $2^{31}-1+2000$，会越过 `int`；但可达坐标至多 $1+2+\dots+(n-1) \approx 2\times10^{6}$，实际不会溢出。稳妥起见仍用 `long long` 累加，并利用 $d$ 单调递增：一旦 `stones[i]+d > stones.back()` 就 `break`，既省一次查表也彻底避开溢出。
6. **末石提前返回**：命中 `j == n-1` 立刻返回 true，不必再把末石入队展开——省一层，也避免给 $dp[n-1]$ 分配条目。
7. **按层推进的不变量**：小下标只会跳向大下标，因此 $i$ 递增扫描时 $dp[i]$ 已完整，之后不会被改写（所有写入目标下标都更大）。这条不变量是正确性证明里归纳法能成立的前提。
8. **Python 的常数**：内层 `for k in dp[i]` 遍历期间只写 $dp[j]$（$j > i$），不会修改正在遍历的集合；不要在内层构造临时列表或切片。

## 5. 正确性证明

**引理 1（状态语义）**：若算法尚未提前返回，则对任意 $i \ge 1$、$k \ge 1$，在按下标递增把 $dp[0],\dots,dp[i]$ 全部算完之后有

$$k \in dp[i] \iff \text{存在合法跳跃序列 } 0 = p_0 < p_1 < \cdots < p_m = \text{stones}[i],\ \text{其最后一跳长为 } k$$

并约定 $dp[0] = \{0\}$ 表示「起点，上一跳长 0」。

**证明**：对 $i$ 归纳。

- $i = 0$：约定即定义。
- 设所有 $j < i$ 成立。若 $k \in dp[i]$，则它只能由某次 `dp[j].add(d)` 写入，且 $j < i$、$d = k$、$\text{stones}[i]-\text{stones}[j] = d$，同时存在 $k' \in dp[j]$ 使 $d \in \{k'-1,k',k'+1\}$。由归纳假设有合法序列到达 $j$、最后一跳 $k'$；追加长度 $d > 0$ 的一跳（符合规则且落在石子上）即得合法序列到达 $i$、最后一跳 $d = k$。
- 反之，设存在合法序列到达 $i$、最后一跳 $k$，其前驱为 $j < i$、前一跳 $k'$，则 $k \in \{k'-1,k',k'+1\}$ 且 $k > 0$。由归纳假设 $k' \in dp[j]$；处理第 $j$ 层时枚举 $d$ 会取到 $d = k$，查表得 $\operatorname{idx}(\text{stones}[j]+k) = i$，故 $k$ 被写入 $dp[i]$。∎

**引理 2（$k \le i$）**：若 $k \in dp[i]$ 且 $k \ge 1$，则 $k \le i$。

**证明**：落到下标 $i$ 至少需要 $i$ 次跳跃（落点下标严格递增，从 0 走到 $i$）。第一次跳跃长度固定为 1，此后每次至多比上次多 1，故第 $t$ 次跳跃长度 $\le t$。最后一跳是第 $m$ 次跳跃且 $m \le i$，于是 $k \le m \le i$。∎

**引理 3（提前返回可靠）**：算法返回 true 时必存在合法序列落到最后一块石子。

**证明**：返回 true 只发生在「$d$ 使 $\operatorname{idx}(\text{stones}[i]+d) = n-1$」时，即 $\text{stones}[i]+d = \text{stones}[n-1]$。由引理 1，$k \in dp[i]$ 对应一条合法序列到达 $i$；追加这一跳（长度 $d$、符合 $k \pm 1$ 规则、落在石子 $n-1$ 上）即得合法序列到达末石。∎

**定理**：`canCross` 返回 true 当且仅当青蛙能落到最后一块石子上。

**证明**：

- （$\Rightarrow$）即引理 3。
- （$\Leftarrow$）设存在合法序列到达末石，其最后一跳前的状态为 $(i',k')$，显然 $i' \le n-2$。由引理 1，$k' \in dp[i']$，故第 $i'$ 层非空、一定会被处理；处理时枚举的 $d$ 必然覆盖末跳长度 $d^{*} > 0$，于是 $\operatorname{idx}(\text{stones}[i']+d^{*}) = n-1$，算法返回 true。∎

（若 `stones[1] != 1`，第一步无处落脚，$dp[1]$ 及其后全为空，循环自然返回 false，与 3.3 的预检一致。）

## 6. 复杂度分析

- **时间**：$O(n^2)$。状态数上界 $\sum_{i=0}^{n-1}(i+1) = n(n+1)/2$（引理 2），每个状态枚举 3 个距离、各做一次 $O(1)$ 哈希查表；$n = 2000$ 时上界约 $2\times10^{6}$ 个状态、$6\times10^{6}$ 次查表。
- **空间**：$O(n^2)$ 最坏。所有 $dp$ 集合合计至多 $n(n+1)/2$ 个整数，位置表 $O(n)$；若换成 $n \times (n+1)$ 的 `char` 表则固定约 4 MB。
- **实测**：最稠密的输入（位置 $0,1,2,\dots,1999$）实际只出现约 $8.2\times10^{4}$ 个状态，Python 约 0.04 s、C++ 约 0.004 s，远小于上界。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <unordered_set>
using namespace std;

class Solution {
public:
    bool canCross(vector<int>& stones) {
        int n = stones.size();
        if (n == 1) return true;
        if (stones[1] != 1) return false;          // 第一步必须跳 1 格

        unordered_map<int, int> idx;               // 位置 -> 石子下标
        idx.reserve(n * 2);
        for (int i = 0; i < n; ++i) idx[stones[i]] = i;

        vector<unordered_set<int>> dp(n);          // dp[i]：到达第 i 块石子时可能的上一跳长度
        dp[0].insert(0);                           // 起点：上一跳长度记作 0
        for (int i = 0; i + 1 < n; ++i) {
            if (dp[i].empty()) continue;           // 这一层到不了，整层跳过
            long long p = stones[i];
            for (int k : dp[i]) {
                for (int d = k - 1; d <= k + 1; ++d) {
                    if (d <= 0) continue;          // 不能后退，也不能原地
                    long long np = p + d;
                    if (np > stones.back()) break; // d 递增，再往后只会更远；同时避开 int 上溢
                    auto it = idx.find((int)np);
                    if (it == idx.end()) continue; // 落水
                    int j = it->second;
                    if (j == n - 1) return true;   // 落到最后一块石子
                    dp[j].insert(d);
                }
            }
        }
        return false;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def canCross(self, stones: List[int]) -> bool:
        n = len(stones)
        if n == 1:
            return True
        if stones[1] != 1:                  # 第一步只能跳 1 格
            return False

        idx = {v: i for i, v in enumerate(stones)}   # 位置 -> 石子下标
        last = stones[-1]
        dp = [set() for _ in range(n)]      # dp[i]：到达第 i 块石子时可能的上一跳长度
        dp[0].add(0)                        # 起点：上一跳长度记作 0

        for i in range(n - 1):
            if not dp[i]:                   # 这一层到不了，整层跳过
                continue
            p = stones[i]
            for k in dp[i]:
                for d in (k - 1, k, k + 1):
                    if d <= 0:              # 不能后退，也不能原地
                        continue
                    if p + d > last:        # d 递增，再往后只会更远
                        break
                    j = idx.get(p + d)
                    if j is None:           # 落水
                        continue
                    if j == n - 1:          # 落到最后一块石子
                        return True
                    dp[j].add(d)
        return False
```

## 8. 边界情况与易错点

1. **`stones[1] != 1`**：如 `[0,2]`，第一步只能跳 1 格，直接 false。别把规则读成「第一步可跳 1 或 2 格」。
2. **原地跳的错觉**：$k = 1$ 时 $k-1 = 0$；若不过滤 $d \le 0$，状态会在同一块石子上自循环，BFS 写法会死循环。
3. **必须允许跳过石子**：示例 1 中 $5 \to 8$ 越过了位置 6 的石子；若强行要求落在「下一块」石子上，会误判 false。
4. **末石判定的位置**：只有命中 `j == n-1` 才算成功；仅检查 `dp[n-2]` 非空是错的——那里的 $k$ 未必够得到末石。
5. **`idx` 的默认值**：`idx.get(x, 0)` 会把「不存在」误判成下标 0，把起点当落点，导致几乎恒真。
6. **坐标上溢**：`stones[i] + d` 用 `long long` 计算，先与 `stones.back()` 比较，再做 `(int)` 强转；顺序颠倒就可能得到一个被截断的「假位置」。
7. **`n == 2`**：只有 `[0,1]` 能过河——`dp[0] = {0}` 一跳命中末石返回 true，`[0,x]`（$x \ge 2$）返回 false。
8. **别用「相邻间距」做贪心**：间距大不等于无解（长跳可以越过），间距小也不等于有解（上一跳长度不够）。判定必须依赖每块石子上的 $k$ 集合。
