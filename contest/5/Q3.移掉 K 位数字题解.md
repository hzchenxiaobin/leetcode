# LeetCode 移掉 K 位数字 题解

## 1. 题目概述

- **标题 / 题号**：移掉 K 位数字（#402，medium）
- **链接**：https://leetcode.cn/problems/remove-k-digits/
- **来源**：LeetCode 第 5 场周赛 Q3
- **难度**：中等
- **标签**：栈、贪心、字符串、单调栈

**题意**：给定数字串 `num` 与整数 `k`（$1 \le k \le \lvert num \rvert$），从 `num` 中删掉**恰好** `k` 个字符，让剩下的字符保持原相对顺序拼成整数，要求这个整数**最小**，以字符串形式返回。返回值不允许有前导零；若所有字符都被删掉，返回 `"0"`。

**约束**：

- $1 \le k \le \lvert num \rvert \le 10^5$
- `num` 仅由 `0`–`9` 组成
- 除 `"0"` 本身外，`num` 不含前导零

## 2. 示例

**示例 1**

```text
输入：num = "1432219", k = 3
输出："1219"
解释：删掉 4、3、2 三位得到 1219，是全部 C(7,3) = 35 种删法中最小的。
```

**示例 2**

```text
输入：num = "10200", k = 1
输出："200"
解释：删掉首位的 1 得到 "0200"，去掉前导零即 200；输出不允许前导零。
```

**示例 3**

```text
输入：num = "10", k = 2
输出："0"
解释：2 位全部删掉，剩余为空，按题意返回 "0"。
```

## 3. 解题思路

### 3.1 暴力思路

**枚举删法**：从 $n$ 位里挑 $k$ 位删掉，共 $\binom{n}{k}$ 种。$k=5\times10^4$、$n=10^5$ 时这个数有上万位十进制长度，连枚举都写不出来，更别说比较。

**逐位确定（窗口最小值）**：答案有 $n-k$ 位。第 1 位只能在 `num[0..k]` 里选（否则后面不够 $n-k-1$ 位），为了让整数最小，应当选窗口里**最小的数字**（并列取最靠左的），把它之前的字符全部删掉；再对剩余后缀重复。这个贪心是对的，但每一步都要重新扫描长度为 $k+1$ 的窗口，最坏 $O(nk)$。当 $k\approx n/2$ 时是 $10^{10}$ 量级，必然超时。

**正解的切入点**：上面每一步的「窗口最小值」并不需要重新扫描——随着窗口左端右移，被淘汰的候选恰好满足「比后来的字符大」，用一个**单调栈**就能均摊到 $O(1)$。

### 3.2 核心观察：删掉「第一个下降点」的左侧那一位

![第一个下降点：删 4 还是删 3](images/wc5_q3_descent_observation.svg)

先明确两个前提：

1. 删除 $k$ 位后长度固定为 $n-k$，「整数最小」等价于「字典序最小」（引理 1）。
2. 只删**一位**时，最优删法总能取「**删掉第一个下降点左侧的那一位**」；若整串单调不降（没有下降点），就删末位（引理 2）。

以 `num = "1432219"` 为例，第一个下降点是 $4>3$：

- 删 4 得 `132219`，删 3 得 `142219`。两串第 1 位都是 `1`，第 2 位一边是 `3`、一边是 `4`，前者更小。
- 删 4 与删其后的 2 号位、3 号位……同理，第 2 位始终是 `4`，全都比 `3` 大。

> ⚠️ **别按「删掉最大数字」下手**：`num` 里最大的是末位 9，删 9 得 `143221`，而删 4 得 `132219`，后者第 2 位 `3 < 4`，明显更小。**位置**比**大小**更重要——要尽早把高位压小。

于是解法有了形状：把「删一位」重复 $k$ 次。再看一眼「反复删第一个下降点」会发生什么——每次删的都是左边那个较大的数字，剩下的序列**单调不降**。这正是单调栈的形态：从左往右扫，遇到比栈顶小的字符，就不断把更大的栈顶挤掉。

### 3.3 算法流程

![单调栈流程](images/wc5_q3_monotonic_stack_flow.svg)

1. 维护一个字符栈 `st`，初值为空；`k` 就地递减。
2. 依次取 `num` 的每一位 `c`：**只要** `k > 0` 且栈非空且栈顶 `> c`，就弹出栈顶并 `k -= 1`；循环结束后把 `c` 压栈。
3. 遍历结束后若 `k > 0`，说明剩下的串单调不降，只能从末尾删：丢掉栈尾 `k` 位。
4. 去掉前导零；若结果为空，返回 `"0"`。

**两条不变量**（证明见引理 4）：

- 栈内字符始终**单调不降**；
- 每次弹出都恰好是「当前保留串的第一个下降点左邻」，即恰好执行一次引理 2 的最优单删。

### 3.4 示例演算

![示例 1 的单调栈走查](images/wc5_q3_walkthrough.svg)

`num = "1432219"`，`k = 3`：

| 读入 `c` | 栈（底 → 顶） | 弹出 | `k` 剩余 |
|----------|----------------|------|-----------|
| 1 | `1` | — | 3 |
| 4 | `1 4` | — | 3 |
| 3 | `1 3` | 4 | 2 |
| 2 | `1 2` | 3 | 1 |
| 2 | `1 2 2` | — | 1 |
| 1 | `1 2 1` | 2 | 0 |
| 9 | `1 2 1 9` | — | 0 |

恰好弹出 3 次，`k` 归零，收尾无需再删，拼接得 `"1219"`。

另外两个官方示例暴露了收尾细节：

- `num = "10200"`，`k = 1`：读入 0 时把 1 弹掉，`k` 归零，栈为 `0 2 0 0`，拼接 `"0200"`，去前导零得 `"200"`。**前导零必须处理**。
- `num = "10"`，`k = 2`：两个字符先后被弹出，栈空；即使没弹完，收尾删除也会清空，最终统一返回 `"0"`。

## 4. 算法细节

1. **栈的物理实现**：C++ 用 `string`（`push_back` / `pop_back` / `back`，还可 `reserve(num.size())` 一次分配）；Python 用 `list` 存单字符。不要用 `deque`，本题只在尾部操作。
2. **`k` 就地递减**：弹出时 `--k`，收尾时按剩余 `k` 删，最后无需再校验总数；两种删除次数之和恒为 $k$。
3. **收尾删除的前提**：遍历结束时若 `k > 0`，说明每次压栈前都有「栈顶 ≤ 新字符」，否则弹出会继续，故栈单调不降，只能删末尾（引理 2 的「无下降点删末位」）。C++ 用 `while (k > 0 && !st.empty())`，Python 必须先 `if k > 0` 再 `del stack[-k:]`——因为 `stack[:-0]` 是**空列表**。
4. **前导零**：C++ 用 `st.find_first_not_of('0')`，找不到（`npos`）就返回 `"0"`；Python 用 `''.join(stack).lstrip('0')`，空串兜底成 `"0"`。注意 `"1000", k=1` 也会删出全零串。
5. **比较符用 `>` 而非 `>=`**：相等的字符弹出去再压回来，字符序列不变，却白扔一次删除额度。`num = "112", k = 1` 用 `>=` 会得到 `"12"`，正确答案是 `"11"`。
6. **不要转成整数**：答案最长 $10^5$ 位，C++ 的 `stoll` 直接抛 `out_of_range`，Python 的大整数转换既慢又受位数限制；全程按字符串操作。
7. **循环里别改 `num`**：早期写法常用 `num = num[:i] + num[i+1:]` 模拟删除，字符串不可变，这样是 $O(n^2)$ 拷贝，$10^5$ 必然超时。
8. **弹出次数上界**：每个字符至多入栈一次、出栈一次，所以 `while` 的总执行次数 $\le n$，均摊 $O(1)$。

## 5. 正确性证明

**引理 1（等长数字串比较）**：设 $A,B$ 是长度同为 $L$ 的数字串，$p$ 是第一个 $A[p]\ne B[p]$ 的下标。若 $A[p]<B[p]$ 则 $A<B$；若 $A[p]>B[p]$ 则 $A>B$；若这样的 $p$ 不存在则 $A=B$。

**证明**：记数值函数 $\mathrm{val}(\cdot)$，则

$$\mathrm{val}(A)-\mathrm{val}(B)=\sum_{i=p}^{L-1}\bigl(A[i]-B[i]\bigr)10^{L-1-i}$$

当 $A[p]<B[p]$ 时首项 $\le -10^{L-1-p}$，其余项之和至多 $\sum_{j=0}^{L-2-p}9\cdot10^{j}=10^{L-1-p}-1$，故差值 $<0$；$A[p]>B[p]$ 时对称。∎

**引理 2（单次删除的最优位置）**：设 $d$ 是最小的满足 $s[d]>s[d+1]$ 的下标；若不存在这样的下标，令 $d=n-1$。则在所有「删掉一位」得到的 $n-1$ 位串中，删掉 $s[d]$ 得到的串字典序最小。

**证明**：记删掉 $j$ 所得串为 $T_j$。$d$ 的定义保证 $s[0..d]$ 单调不降。

- 若 $j<d$：$T_d$ 与 $T_j$ 的前 $j$ 位都是 $s[0..j)$，第 $j$ 位分别为 $s[j]$ 与 $s[j+1]$；由 $s[j]\le s[j+1]$ 与引理 1 得 $T_d\le T_j$。
- 若 $j>d$：两者前 $d$ 位相同，第 $d$ 位分别为 $s[d+1]$ 与 $s[d]$，而 $s[d+1]<s[d]$，故 $T_d<T_j$。
- 若无下降点（$d=n-1$）：任意 $j<n-1$ 都有 $s[j]\le s[j+1]$，同第一种情形得 $T_{n-1}\le T_j$。

三种情形合起来即 $T_d$ 最小。∎

**引理 3（贪心首步可嵌入最优解）**：设 $d$ 如引理 2，$D$ 是任一最优的「删 $k$ 位」方案（$D$ 为被删下标集合）。则存在最优方案 $D'$ 使 $d\in D'$。

**证明**：若 $d\in D$ 取 $D'=D$。否则分三种情况：

1. $d+1\in D$：令 $D'=D\setminus\{d+1\}\cup\{d\}$。两者保留的位置只有「$s[d]$ 还是 $s[d+1]$」这一处不同，其余完全相同；在这个位置上 $D$ 给出 $s[d]$、$D'$ 给出 $s[d+1]<s[d]$，由引理 1，$D'$ 严格更小，与 $D$ 最优矛盾。
2. 存在被删下标 $>d$：取 $j=\min\{i\in D:i>d\}$，令 $D'=D\setminus\{j\}\cup\{d\}$。由于 $(d,j)$ 内没有删除位，两串前 $d$ 位相同，第 $d$ 位分别为 $s[d+1]$ 与 $s[d]$，$D'$ 严格更小，矛盾。
3. 所有被删下标都 $<d$：取 $j=\max D$，令 $D'=D\setminus\{j\}\cup\{d\}$。此时 $D$ 保留了 $s[d..n)$ 全部，$D'$ 保留了 $s[j]$ 与 $s[d+1..n)$。把两者的保留位按升序排开：公共部分 $C=[0,d)\setminus D$ 完全一致，$D'$ 在 $C$ 的有序序列中插入 $j$，$D$ 则在 $C$ 之后接 $d$。首次出现差异的位置正是 $j$ 的插入处：那里 $D'$ 是 $s[j]$，$D$ 是 $C$ 中的下一个元素或 $d$，其下标落在 $(j,d]$ 内，由 $s[0..d]$ 单调不降得该字符 $\ge s[j]$，故 $D'\le D$；$D'$ 的删除位数同为 $k$，于是也是最优。

∎

**引理 4（栈的不变量）**：处理完 $s[0..i]$ 后，栈中恰为保留下来的字符，且

- (i) 栈内字符单调不降；
- (ii) 若 $i<n-1$ 且栈顶 $>s[i+1]$、$k>0$，则栈顶就是当前保留串（栈 + 未处理后缀）第一个下降点的左邻。

**证明**：(i) 对压栈次数归纳：压入 $c$ 之前，循环已把所有 $>c$ 的栈顶弹出，故压入后仍单调不降。(ii) 由 (i)，栈这一段没有下降点，第一个下降点只可能在栈顶与 $s[i+1]$ 的交界处或更靠后；若栈顶 $>s[i+1]$，交界处就是下降点，且它是所有下降点中最靠前的一个。∎

**定理**：算法返回的串是删掉恰好 $k$ 位后能得到的最小整数（并按题意去掉了前导零）。

**证明**：对 $k$ 归纳，同时证明「算法 = 反复执行引理 2 的最优单删」。$k=0$ 时无需删除，结论显然。设 $k>0$，当前串为 $S$、第一个下降点为 $d$（无下降点取末位）。

由引理 3，存在最优方案删除 $d$；删掉后问题变成「从 $T_d$ 中再删 $k-1$ 位」，且 $T_d$ 上该子问题的最优解与 $d$ 合起来必然是 $S$ 的最优解（否则替换成更好的子方案会得到比原最优更小的串，矛盾）。由归纳假设，继续对 $T_d$ 执行引理 2 的删除即可。

再由引理 4，栈实现的每一次弹出都恰好等于对当前保留串按引理 2 删一位，且弹出至多 $k$ 次；若遍历结束时仍有 $k>0$，说明栈单调不降，引理 2 给出的最优删法就是从末尾删，收尾删除与之一致。两次删除次数之和恰为 $k$，故最终串是全部删 $k$ 位方案中的字典序最小者；这些串长度都是 $n-k$，由引理 1 它也是数值最小者。

最后，去掉前导零不改变数值；$n-k=0$ 或剩余全为 0 时输出 `"0"`，与题意一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符入栈一次、出栈至多一次（`while` 的总弹出次数 $\le k\le n$），收尾删除至多 $n$ 次，去前导零与拼接各 $O(n)$。
- **空间**：$O(n)$。栈最多容纳 $n$ 个字符，C++ 用 `string` 原地增长，Python 的 list 存单字符引用；除此之外只用了若干整型变量。不计输入输出。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string removeKdigits(string num, int k) {
        string st;
        st.reserve(num.size());              // 一次分配，避免扩容拷贝
        for (char c : num) {
            while (k > 0 && !st.empty() && st.back() > c) {
                st.pop_back();               // 栈顶更大且还有删除额度：删掉它
                --k;
            }
            st.push_back(c);
        }
        while (k > 0 && !st.empty()) {       // 剩余串单调不降，只能从末尾删
            st.pop_back();
            --k;
        }
        size_t pos = st.find_first_not_of('0');   // 去前导零
        if (pos == string::npos) return "0";      // 全零或已删空
        return st.substr(pos);
    }
};
```

### Python

```python
class Solution:
    def removeKdigits(self, num: str, k: int) -> str:
        stack = []
        for ch in num:
            while k > 0 and stack and stack[-1] > ch:
                stack.pop()          # 栈顶更大且还有额度：删掉它
                k -= 1
            stack.append(ch)

        if k > 0:                    # 必须有这个判断：stack[:-0] 会清空整个列表
            del stack[-k:]           # 剩余串单调不降，从末尾删

        res = ''.join(stack).lstrip('0')
        return res if res else '0'   # 全零或删空都返回 "0"
```

## 8. 边界情况与易错点

1. **`k == n`（全删）**：`"10", k = 2`、`"0", k = 1` 都应返回 `"0"`。C++ 走 `find_first_not_of` 的 `npos` 分支，Python 走 `res` 为空的分支，两条路径都必须存在。
2. **前导零**：`"10200", k = 1` → `"200"`；`"1000", k = 1` → `"0"`（删完 1 剩全零）。不能只 `lstrip('0')` 而不判空。
3. **`>` 写成 `>=`**：`"112", k = 1` 会输出 `"12"`，正确是 `"11"`。相等时弹出只是原地换一个相同字符，白白消耗一次删除额度。
4. **单调不降串**：`"12345", k = 2` 循环内一次都不弹，必须靠收尾删末两位得到 `"123"`；漏写收尾删除会返回整串。
5. **Python 的负零切片**：`stack[:-k]` 在 `k == 0` 时是 `stack[:0]`，即空列表，会把答案清空。必须 `if k > 0` 保护（或写 `stack = stack[:len(stack) - k]`）。
6. **收尾删除不会越界**：弹出次数 $p\le k$，剩余长度 $n-p\ge n-k\ge k$（用 $k\le n$），故 `del stack[-k:]` / `while` 删除都不会越界；但若题目放宽到 $k>n$ 就需要额外判断。
7. **不要返回整数**：答案可达 $10^5$ 位，`stoi` / `stoll` 必然溢出，Python 转 `int` 再转回字符串也既慢又有位数上限，全程字符串最稳。

**延伸思考**：

- 若要求删除 $k$ 位后得到的数**最大**，把栈的比较符反过来（维护单调递减栈，弹掉更小的栈顶），收尾同样从末尾删。

- 若要求「删 $k$ 位后必须是 $m$ 的倍数」或「恰好 $L$ 位且无前导零」，贪心不再充分，需要按位 DP 或枚举首位数字后接最优化后缀，复杂度升到 $O(n\cdot m)$ 级别。
- 本题的证明套路（单步最优 + 首步可嵌入最优解 + 归纳）适用于一大类「按位比较的字典序贪心」问题，例如拼接最小数（按 `a+b` 与 `b+a` 排序）也用同一套交换论证。
