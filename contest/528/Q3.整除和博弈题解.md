# LeetCode 整除和博弈 题解

## 1. 题目概述

- **标题 / 题号**：整除和博弈（#4113，medium）
- **链接**：https://leetcode.cn/problems/game-of-divisible-sums/
- **来源**：LeetCode 第 528 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、博弈论、前缀和

**题意**：Alice 与 Bob 轮流从**剩余数组的最左端**取元素，Alice 先手。每一回合当前玩家可以取走 1 个元素，也可以在至少还剩 2 个元素时取走最左边的 2 个元素。记本回合取走元素之和为 $s$：若 $s$ 能被 3 整除，则**换手**；否则**当前玩家继续行动**。玩家的得分是自己取走的全部元素之和，双方都采取最优策略（各自最大化自己的得分），直到元素取完。返回 Alice 得分减去 Bob 得分。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- 答案的量级可达 $\sum \text{nums} \le 10^{14}$，必须用 64 位整数

## 2. 示例

**示例 1**

```text
输入：nums = [3,6,4]
输出：5
解释：Alice 取最左两个，和 9 能被 3 整除，换手；Bob 取走 4。
      Alice 得 9，Bob 得 4，差 5。
```

**示例 2**

```text
输入：nums = [6,1,2,1,2]
输出：12
解释：Alice 取 6+1=7（不整除 3，继续），再取 2（继续），再取 1+2=3，得 12；
      Bob 没有回合，得 0，差 12。
```

**示例 3**

```text
输入：nums = [3,3,4,5]
输出：-3
解释：Alice 取 3+3=6（能被 3 整除，换手），Bob 取走剩下的 4+5=9。
      Alice 得 6，Bob 得 9，差 6-9 = -3。
```

## 3. 解题思路

### 3.1 暴力思路

每一步只有「取 1 个」或「取 2 个」两种选择，朴素枚举所有取法最多 $2^{n}$ 条路径（每条路径上还要维护分差），指数级，$n = 10^5$ 时完全不可行。

即便改成记忆化搜索，状态写成「后缀起点 $i$ + 轮到谁」也有 $2n$ 个状态，而且枚举下一步还要算区间和。真正的困难是：**取几个会让「谁行动」发生变化**，看起来必须把身份记进状态。事实上这一维可以消掉。

### 3.2 核心观察：把「身份」换成「净胜分」

![状态压缩：后缀起点 + 净胜分](images/wc528_q3_state_rule.svg)

**总和是固定的**。记全体元素之和为 $S$，任意时刻都有

$$\text{Alice 得分} + \text{Bob 得分} = S$$

所以「最大化自己的得分」与「最大化自己得分减对手得分」是同一件事，博弈是**零和**的，可以只跟踪分差。

于是定义 $dp[i]$ 为**轮到行动的那个人**从后缀 $\text{nums}[i..n-1]$ 中能取得的**最大净胜分**（自己得分减对手得分）。

这里**不区分这个人是 Alice 还是 Bob**——规则对双方完全对称，谁站在这个位置上，能拿到的净胜分都一样。

一次行动取走 $\text{nums}[i..j-1]$，和为 $s$，剩下后缀从 $j$ 开始：

- $s \bmod 3 = 0$：换手，接下来由**对手**在 $j$ 上行动。$dp[j]$ 是**对手**的净胜分，折算到我的账上要取负号，贡献为 $s - dp[j]$；
- $s \bmod 3 \ne 0$：还是我行动，$dp[j]$ 仍记在**我**的账上，贡献为 $s + dp[j]$。

于是

$$dp[i] = \max_{j \in \{i+1,\, i+2\},\; j \le n} \left( s(i,j) + \begin{cases} -dp[j], & s(i,j) \bmod 3 = 0 \\ +dp[j], & s(i,j) \bmod 3 \ne 0 \end{cases} \right)$$

其中 $s(i,j) = \sum_{k=i}^{j-1} \text{nums}[k]$，边界 $dp[n] = 0$。答案就是 $dp[0]$。

### 3.3 算法流程

![从右往左递推的流程](images/wc528_q3_dp_flow.svg)

1. 令 $dp[n] = 0$，从 $i = n-1$ 逆序推到 $i = 0$。
2. 取 1 个的候选：$s_1 = \text{nums}[i]$，$j = i+1$，按 $s_1 \bmod 3$ 决定加减，得 $c_1$。
3. 取 2 个的候选（仅当 $i+1 < n$）：$s_2 = \text{nums}[i] + \text{nums}[i+1]$，$j = i+2$，同理得 $c_2$。
4. $dp[i] = \max(c_1, c_2)$。
5. 由于转移只依赖 $dp[i+1]$ 与 $dp[i+2]$，用两个滚动变量即可，空间 $O(1)$。

### 3.4 示例演算

![示例演算表](images/wc528_q3_walkthrough.svg)

对 $\text{nums} = [6,1,2,1,2]$ 倒序填表：

| $i$ | 后缀 | 取 1 个 | 取 2 个 | $dp[i]$ |
|-----|------|---------|---------|---------|
| 4 | $[2]$ | $s=2$，$2+dp[5]=2$ | 不合法 | 2 |
| 3 | $[1,2]$ | $s=1$，$1+dp[4]=3$ | $s=3$，$3-dp[5]=3$ | 3 |
| 2 | $[2,1,2]$ | $s=2$，$2+dp[3]=5$ | $s=3$，$3-dp[4]=1$ | 5 |
| 1 | $[1,2,1,2]$ | $s=1$，$1+dp[2]=6$ | $s=3$，$3-dp[3]=0$ | 6 |
| 0 | $[6,1,2,1,2]$ | $s=6$，$6-dp[1]=0$ | $s=7$，$7+dp[2]=12$ | 12 |

第 0 行是整题的关键对比：取 1 个虽然让 Alice 立刻拿 6 分，但和能被 3 整除会把局面交给对手（对手净胜 6，净效果 0）；取 2 个拿 7 分且**保住行动权**，最终净胜 12。

再看示例 1 的 $\text{nums} = [3,6,4]$：$dp[2] = 4$，$dp[1] = \max(6 - dp[2],\, 10 + dp[3]) = \max(2, 10) = 10$，$dp[0] = \max(3 - dp[1],\, 9 - dp[2]) = \max(-7, 5) = 5$，与官方输出一致。

## 4. 算法细节

1. **用净胜分消掉身份维度**：$dp$ 只定义「轮到行动者」的视角，状态数从 $2n$ 降到 $n$，且不需要知道 Alice/Bob 谁在行动——这是本题唯一的思维门槛。
2. **一次转移只看两个 $j$**：每回合最多取 2 个元素，所以 $j$ 只可能是 $i+1$ 或 $i+2$，转移 $O(1)$，无需前缀和数组。
3. **滚动变量代替数组**：逆序推进时 $dp[i]$ 只用到 $dp[i+1]$、$dp[i+2]$，用 `dp1`、`dp2` 两个变量即可，空间 $O(1)$。
4. **更新顺序**：必须先把 $c_1, c_2$ 都算完，再执行 `dp2 = dp1; dp1 = best`；若先覆盖 `dp1`，取 2 个的候选就会用到错误的 $dp[i+1]$。
5. **64 位整数**：$n$ 个 $10^9$ 相加达到 $10^{14}$，C++ 必须用 `long long`，`int` 会静默溢出；Python 整数天然无上限。
6. **取模判断**：这里 $s$ 恒为正，直接用 `s % 3 == 0` 即可；若题目允许负数元素，应写成 `((s % 3) + 3) % 3 == 0`。
7. **边界不需要哨兵**：逆序 DP 从 $dp[n]=0$ 出发，每一格都会被真实计算，不必用 `-INF` 标记「未计算」；同时 $dp[i]$ 允许为负（Alice 可能输），不能把 0 当成下界。
8. **合法性检查**：取 2 个要求 $i + 1 < n$（即至少剩 2 个元素），$i = n-1$ 时只有取 1 个这一条路。

## 5. 正确性证明

**引理 1（零和性）**：任意时刻，Alice 得分与 Bob 得分之和恒等于全体元素之和 $S$。

**证明**：每个元素恰好被某一方取走一次，取走时其值计入该方得分，因此任意时刻两人得分之和等于已取走元素之和。元素只从最左端取走，已取走部分是一个前缀，故这个和是 $S$ 的前缀和；游戏结束时前缀覆盖整个数组，和恰为 $S$。∎

**引理 2（状态充分性）**：后缀 $\text{nums}[i..n-1]$ 上的子博弈，其最优净胜分只依赖 $i$，与历史、与当前行动者的身份无关；记这个值为 $V(i)$。

**证明**：对 $n-i$ 归纳。$i=n$ 时无元素可取，净胜分 0。设 $i$ 之后成立，则当前行动者的可行行动集合只由 $\text{nums}[i]$、$\text{nums}[i+1]$ 决定（规则不区分身份），行动后的局面是某个从 $j > i$ 开始的同构子博弈，由归纳假设其值为 $V(j)$，且与谁行动无关。故 $V(i)$ 由 $i$ 唯一确定。∎

**引理 3（递推式）**：对 $0 \le i < n$，

$$V(i) = \max_{j \in \{i+1,\,i+2\},\; j \le n} \begin{cases} s(i,j) - V(j), & s(i,j) \bmod 3 = 0 \\ s(i,j) + V(j), & s(i,j) \bmod 3 \ne 0 \end{cases}$$

且 $V(n) = 0$。

**证明**：当前行动者取走 $\text{nums}[i..j-1]$ 得 $s = s(i,j)$ 分。若 $s \bmod 3 = 0$，接下来轮到对手，由引理 2 对手在 $j$ 上的净胜分为 $V(j)$，即对手得分减我方得分为 $V(j)$，故我方净胜为 $s - V(j)$；若 $s \bmod 3 \ne 0$，仍是我方行动，$j$ 上的净胜分 $V(j)$ 属于我方，故为 $s + V(j)$。当前行动者取最优行动，即在所有合法 $j$ 上取最大值；由引理 1，最大化自己的得分等价于最大化这个净胜分，因此取 $\max$ 不损失最优性。∎

**定理**：设算法输出的 $dp[0]$ 为 $A$，则 $A = V(0)$，且 $A$ 等于双方最优策略下 Alice 得分减 Bob 得分。

**证明**：对 $i$ 从 $n$ 到 $0$ 归纳证明算法算出的 $dp[i] = V(i)$。$i=n$ 时 $dp[n] = 0$，与边界一致。设 $i+1$、$i+2$ 处成立，算法算出的 $c_1, c_2$ 正是引理 3 中 $j=i+1$、$j=i+2$ 的两个候选（$j=i+2$ 仅在 $i+1 < n$ 时存在，与合法性一致），取 $\max$ 后即为 $V(i)$，归纳成立。于是 $dp[0] = V(0)$。由引理 1、2，$V(0)$ 是 Alice 在最优策略下的净胜分；零和博弈的最优策略值唯一，故它就是所求的 Alice 得分减 Bob 得分。∎

## 6. 复杂度分析

- **时间**：$O(n)$。逆序扫描一遍，每个 $i$ 只做常数次比较、加法与取模。
- **空间**：$O(1)$。只维护 `dp1`、`dp2` 与两个临时和，不申请与 $n$ 相关的数组。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    long long maxDifference(vector<int>& nums) {
        int n = (int)nums.size();
        long long dp1 = 0, dp2 = 0;              // dp[i+1] 与 dp[i+2]
        for (int i = n - 1; i >= 0; --i) {
            long long s1 = nums[i];
            long long best = (s1 % 3 == 0) ? s1 - dp1 : s1 + dp1;
            if (i + 1 < n) {
                long long s2 = s1 + nums[i + 1];
                long long cand = (s2 % 3 == 0) ? s2 - dp2 : s2 + dp2;
                if (cand > best) best = cand;
            }
            dp2 = dp1;
            dp1 = best;
        }
        return dp1;
    }
};
```

### Python

```python
class Solution:
    def maxDifference(self, nums: list[int]) -> int:
        n = len(nums)
        dp1 = dp2 = 0                      # dp[i+1] 与 dp[i+2]
        for i in range(n - 1, -1, -1):
            s1 = nums[i]
            best = s1 - dp1 if s1 % 3 == 0 else s1 + dp1
            if i + 1 < n:
                s2 = s1 + nums[i + 1]
                cand = s2 - dp2 if s2 % 3 == 0 else s2 + dp2
                if cand > best:
                    best = cand
            dp2, dp1 = dp1, best
        return dp1
```

## 8. 边界情况与易错点

1. **只有一个元素**：$n=1$ 时只能取 1 个，$dp[0] = \text{nums}[0] - dp[1] = \text{nums}[0]$。即使元素能被 3 整除「本该换手」，也没有剩余元素，结果仍然是正分，不要额外特判成 0。
2. **取 2 个的越界**：条件必须是 $i+1 < n$（而不是 $i+1 \le n$），否则会读到 `nums[n]`；$i = n-1$ 时 $dp[2]$ 这个滚动变量是旧值，绝不能参与计算。
3. **`int` 溢出**：$\sum \text{nums}$ 可达 $10^{14}$，C++ 用 `int` 会在样例之外的极大用例上错得很隐蔽；累加、`dp` 一律用 `long long`。
4. **答案是负数也合法**：示例 3 输出 $-3$。不要把结果与 0 取最大值，也不要用 0 作为 `dp` 的初值哨兵。
5. **加减号写反**：能被 3 整除时给的是 $-dp[j]$（换手了，$dp[j]$ 是对手的领先量）；很多错误写法会在这里丢掉符号，导致同一玩家被连算两次。
6. **滚动变量更新次序**：先算完两个候选，再 `dp2 = dp1; dp1 = best`；顺序颠倒会破坏 $dp[i+2]$ 的含义。
7. **取模与整除的区分**：判断条件是「和能被 3 整除」，看的是**区间和** $s$，而不是单个元素或元素个数。
8. **前缀和不是必须的**：本题转移窗口长度恒为 2，逆序扫描时用 `nums[i]`、`nums[i] + nums[i+1]` 现算即可，多开一个前缀和数组只是浪费空间（也容易在下标上写错）。
