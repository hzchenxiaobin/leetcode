# LeetCode 座位预约管理系统 题解

## 1. 题目概述

- **标题 / 题号**：座位预约管理系统（#1845，medium）
- **链接**：https://leetcode.cn/problems/seat-reservation-manager/
- **来源**：LeetCode 第 51 场双周赛 Q2
- **难度**：中等
- **标签**：设计、堆（优先队列）

**题意**：设计管理 $n$ 个座位（编号 $1 \sim n$）的 `SeatManager` 类，初始所有座位都可预约：

- `SeatManager(int n)`：初始化；
- `int reserve()`：返回可以预约座位的**最小编号**，并将该座位变为不可预约；
- `void unreserve(int seatNumber)`：将给定编号的座位（保证当前处于被预约状态）变为可以预约。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \mathit{seatNumber} \le n$
- 每次调用 `reserve` 时保证至少存在一个可预约座位；每次调用 `unreserve` 时保证该座位处于被预约状态
- `reserve` 与 `unreserve` 的调用**总共**不超过 $10^5$ 次

## 2. 示例

**示例 1**

```text
输入：
["SeatManager", "reserve", "reserve", "unreserve", "reserve", "reserve",
 "reserve", "reserve", "unreserve"]
[[5], [], [], [2], [], [], [], [], [5]]
输出：[null, 1, 2, null, 2, 3, 4, 5, null]
解释：reserve 依次取 1、2；unreserve(2) 后再 reserve 拿回 2；
     之后 reserve 依次取 3、4、5；最后 unreserve(5)。
```

**示例 2（边界补充）**

```text
输入：["SeatManager", "reserve", "unreserve", "reserve", "unreserve", "reserve"]
     [[1], [], [1], [], [1], []]
输出：[null, 1, null, 1, null, 1]
解释：n = 1 时反复"占用—释放"：堆空走 smallest 指针，堆非空弹堆顶，两个来源交替供位。
```

## 3. 解题思路

### 3.1 暴力思路

布尔数组 `free[1..n]`：`unreserve` 把 `free[x]` 置 true（$O(1)$）；`reserve` 从 1 开始线性扫到第一个 `true`（最坏 $O(n)$）。操作总数 $10^5$、每次 $O(n) = 10^5$，最坏 $10^{10}$ 次操作，不可行。瓶颈很清楚：`reserve` 需要的是"**当前最小可预约编号**"这个查询，线性扫描把每次查询做成了全表扫。

### 3.2 核心观察：「取最小 + 删最小 + 插入」正是小根堆的接口

![模型：下一空位指针 smallest ＋ 回收小根堆 freed](images/bw51_q2_pointer_heap_model.svg)

可预约座位集合的动态变化只有两种：`reserve` **取走最小元素**、`unreserve` **插回一个元素**——这是小根堆的原生操作集，每次 $O(\log m)$。

再进一步观察：**编号总是按 $1, 2, 3, \dots$ 的顺序"发出"**，只有被 `unreserve` 过的编号才可能"复活"。于是构造时完全不必把 $1 \sim n$ 全塞进堆（那是 $O(n)$ 的时间与空间）；只需维护两个轻量部件：

- 指针 `smallest`：**从未发出过**的最小编号；
- 小根堆 `freed`：被 `unreserve` 回收的编号集合。

构造函数 $O(1)$，空间只与"回收过多少个座位"有关。由于回收的编号总是小于 `smallest`（见 §5 引理 1），`reserve` 的判定顺序天然是"堆优先、指针兜底"。

### 3.3 算法流程

![reserve 与 unreserve 的判定流程图](images/bw51_q2_operations_flow.svg)

```text
reserve():
    若 freed 非空：弹出堆顶并返回（它就是当前最小可预约编号）
    否则：返回 smallest，并 smallest ← smallest + 1

unreserve(x):
    freed.push(x)
```

### 3.4 示例演算

![官方示例 9 步调用回放](images/bw51_q2_walkthrough.svg)

官方示例（$n = 5$）逐行回放：前两次 `reserve` 走指针拿到 1、2；`unreserve(2)` 把 2 压入堆；第 5 步 `reserve` 时堆非空，弹堆顶得到 2——**压过了指针值 3**；随后三次 `reserve` 继续走指针取 3、4、5；最后 `unreserve(5)` 入堆。输出序列与官方逐项一致。

## 4. 算法细节

1. **堆顶一定小于 `smallest`**：`freed` 中的编号都是历史 `reserve` 返回过的，发出时 `smallest` 已越过它们，而 `smallest` 单调不减。因此"堆非空就弹堆顶"不需要再与 `smallest` 比较大小，两个来源的编号区间天然不重叠。
2. **构造 $O(1)$ 的意义**：$n$ 可达 $10^5$ 但操作总数只有 $10^5$；全量入堆（`for i in 1..n: push(i)`）也能通过（初始化 $O(n)$、总 $O(q \log n)$），指针版把空间压到 $O(\min(q, n))$ 且省去初始化开销，是更优雅的写法，也是面试官想听的那一层。
3. **C++ 小根堆写法**：`priority_queue<int, vector<int>, greater<int>>`；默认的 `priority_queue<int>` 是**大根堆**，漏写比较器是最常见 bug（会让 `reserve` 返回最大可预约座位）。
4. **Python 用 `heapq`**：`heappush` / `heappop` 直接操作列表，空列表即空堆，判断用 `if self.freed:`。
5. **无重复元素保证**：题目保证 `unreserve` 只作用于"当前被预约"的座位，所以同一编号不会二次入堆、堆中无重复；若没有这条保证，就要换成"惰性删除"方案（弹出时校验有效性，见延伸思考）。
6. **`smallest` 初值为 1**：座位从 1 开始编号；指针只在堆空时前进。

## 5. 正确性证明

**引理 1（三态划分）**：任意时刻，每个编号 $x \in [1, n]$ 恰处于三种状态之一：(a) 被预约；(b) 在 `freed` 堆中；(c) 从未发出（$x \ge \mathit{smallest}$）。且 `freed` 中元素恒小于 `smallest`。

**证明**：对操作序列长度归纳。初始 `smallest` = 1，无编号被发出，(c) 成立。设某时刻命题成立，考察下一步操作：`reserve` 取 $r$ = 堆顶（状态 (b) 转为 (a)，且 $r < \mathit{smallest}$ 不变）或 $r = \mathit{smallest}_{\text{旧}}$（状态 (c) 转为 (a)，新 $\mathit{smallest} = \mathit{smallest}_{\text{旧}} + 1$，(c) 的下界右移一格）；`unreserve(x)` 把 $x$ 从 (a) 转入 (b)，其余状态不变。两种操作后 `freed` 中元素（旧元素或新入的 $x$，后者是历史发出的编号、小于当前 `smallest`）仍全部小于 `smallest`。∎

**定理（`reserve` 正确性）**：每次 `reserve` 返回当前最小可预约编号，并将其置为被预约状态。

**证明**：由引理 1，可预约编号集合恰为 $\mathit{freed} \cup \{\mathit{smallest}, \mathit{smallest}+1, \dots, n\}$。若 `freed` 非空，其最小元素（堆顶）小于 `smallest`，从而小于集合中其余一切元素，是全局最小可预约编号——算法弹出并返回它；若 `freed` 为空，最小可预约编号即 `smallest`——算法返回它并右移指针。两种情况返回值都从"可预约"转入"被预约"。∎

## 6. 复杂度分析

- **时间**：每次 `reserve` / `unreserve` 均 $O(\log m)$，$m$ 为堆大小（$m \le \min(q, n)$，$q$ 为操作数）；总计 $O(q \log n)$。构造函数 $O(1)$（指针版）。
- **空间**：$O(\min(q, n))$——堆中只存被回收过的编号；外加 $O(1)$ 的指针。全量入堆版本则为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class SeatManager {
public:
    SeatManager(int n) {}                        // 无需真的初始化 n 个座位
    int reserve() {
        if (!freed.empty()) {                    // 有回收的空位 → 取最小编号
            int seat = freed.top();
            freed.pop();
            return seat;
        }
        return smallest++;                       // 否则发出下一个全新编号
    }
    void unreserve(int seatNumber) {
        freed.push(seatNumber);                  // 回收入小根堆
    }
private:
    priority_queue<int, vector<int>, greater<int>> freed;  // 已回收座位的小根堆
    int smallest = 1;                            // 从未发出过的最小编号
};
```

### Python

```python
import heapq

class SeatManager:
    def __init__(self, n: int):
        self.smallest = 1                        # 从未发出过的最小编号
        self.freed = []                          # 已回收座位的小根堆

    def reserve(self) -> int:
        if self.freed:                           # 有回收的空位 → 取最小编号
            return heapq.heappop(self.freed)
        self.smallest += 1                       # 否则发出下一个全新编号
        return self.smallest - 1

    def unreserve(self, seatNumber: int) -> None:
        heapq.heappush(self.freed, seatNumber)   # 回收入堆
```

> 💡 两份代码均通过官方 9 步调用序列回放；另与「布尔数组线性扫描」的暴力实现在 2500 组随机操作序列（$n \le 20$、序列长 $\le 60$、保证调用合法）上对拍一致；$n = 10^5$、$2 \times 10^5$ 次混合操作实测 C++ 约 170ms、Python 约 150ms。

## 8. 边界情况与易错点

1. **回收后立刻预约**：回收编号可能小于指针，判空顺序必须"堆优先、指针兜底"；先动指针再查堆会漏掉刚回收的座位。
2. **`smallest++` 的返回值**：C++ `return smallest++;` 返回旧值恰好正确；Python 没有这种表达式，先自增再返回 `self.smallest - 1`（或拆两行），容易差一。
3. **大根堆陷阱**：C++ 漏写 `greater<int>` 会让 `reserve` 返回最大空位，官方示例第 2 步（应返 2 而非 5）立刻露馅。
4. **重复 unreserve**：题目保证不发生；若允许（或防御式编程），需在弹出时校验编号当前确实空闲（惰性删除），否则会重复发出同一编号。
5. **构造函数别做多余的事**：指针版完全不需要遍历 $1 \sim n$，把 `n` 存下来或预填充堆都是画蛇添足。
6. **数据规模感**：$q \le 10^5$ 下 $O(q \log n)$ 双语言都很宽裕；若操作数升到 $10^7$，Python 建议把 `heapq.heappop` 局部化或直接换 C++。
