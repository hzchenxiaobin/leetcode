# LeetCode 查询后的偶数和 题解

## 1. 题目概述

- **标题 / 题号**：查询后的偶数和（#985，medium）
- **链接**：https://leetcode.cn/problems/sum-of-even-numbers-after-queries/
- **来源**：LeetCode 第 122 场周赛 Q1
- **难度**：中等
- **标签**：数组、模拟

**题意**：给出整数数组 $A$ 和查询数组 `queries`。第 $i$ 次查询取 $val = queries[i][0]$、$index = queries[i][1]$，把 $val$ **加**到 $A[index]$ 上（永久修改），随后统计此刻 $A$ 中**所有偶数值之和**作为 `answer[i]`。返回全部查询的答案数组。

**约束**：

- $1 \le A.length \le 10000$
- $-10000 \le A[i] \le 10000$
- $1 \le queries.length \le 10000$
- $-10000 \le queries[i][0] \le 10000$
- $0 \le queries[i][1] < A.length$

> 💡 关键点：一次查询只改变**一个位置**，其余元素纹丝不动。能否复用上一次的答案，就决定了 $O(nq)$ 与 $O(n+q)$ 的差别。

## 2. 示例

**示例 1**

```text
输入：A = [1,2,3,4], queries = [[1,0],[-3,1],[-4,0],[2,3]]
输出：[8,6,2,4]
解释：
初始 [1,2,3,4]，偶数之和 2 + 4 = 6。
+1 到 A[0] → [2,2,3,4]，偶数和 2 + 2 + 4 = 8
−3 到 A[1] → [2,-1,3,4]，偶数和 2 + 4 = 6
−4 到 A[0] → [-2,-1,3,4]，偶数和 −2 + 4 = 2
+2 到 A[3] → [-2,-1,3,6]，偶数和 −2 + 6 = 4
```

**示例 2**

```text
输入：A = [1], queries = [[4,0]]
输出：[0]
解释：1 + 4 = 5 是奇数，唯一元素不是偶数，偶数和为 0。
```

示例 2 说明：**偶数之和可以是 0，也可以为负**（如示例 1 第 3 步的 $-2+4=2$），不能用 0 当作「无解」标记。

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：每条查询先更新 $A[index]$，再遍历整个数组求和，复杂度 $O(nq)$。取 $n = q = 10^4$ 时约 $10^8$ 次加法，C++ 勉强能过，Python 必然超时；而且它完全忽略了「只改一个元素」这个结构性事实。

### 3.2 核心观察：增量维护偶数之和

![只维护偶数之和这一个数，按增量更新](images/wc122_q1_delta_update.svg)

设 $S$ 表示**当前数组所有偶数元素之和**。查询只会改动 $A[index]$ 这一个位置，于是：

- 旧值 $old$ 若是偶数，它原本被计入 $S$，更新前应先把这份贡献**撤回**；
- 新值 $nw = old + val$ 若是偶数，它应当被计入 $S$，更新后**加上**。

两者相抵即得

$$S' = S - [old \text{ 为偶数}] \cdot old + [nw \text{ 为偶数}] \cdot nw$$

其中 $[\cdot]$ 为指示函数。整个过程只做两次奇偶判断和两次加减，与 $n$ 无关。

### 3.3 算法流程

![算法流程：先减旧值再加新值](images/wc122_q1_delta_update.svg)

```text
1. S = sum(x for x in A if x 是偶数)
2. for (val, index) in queries:
       old = A[index]
       若 old 是偶数: S -= old
       nw = old + val;  A[index] = nw
       若 nw 是偶数: S += nw
       answer 追加 S
3. 返回 answer
```

注意「先减旧、再加新」的顺序：如果写成「先加新、再减旧」，当新旧值都是偶数时仍然等价，但当代码被改写成别种形式（例如把 $A[index]$ 提前更新）就极易把同一个值算两遍。保持「撤回旧贡献 → 写入新值 → 结算新贡献」三段式最稳。

### 3.4 示例演算

![示例 1 走查](images/wc122_q1_walkthrough.svg)

对示例 1，$S$ 的初值为 $2+4=6$：

| 查询 | $A$ 变为 | $S$ 的更新 | answer |
|------|----------|------------|--------|
| $(+1, 0)$ | $[2,2,3,4]$ | $1$ 是奇数不减；$2$ 是偶数加 $2$，$S=8$ | 8 |
| $(-3, 1)$ | $[2,-1,3,4]$ | $2$ 是偶数减 $2$；$-1$ 是奇数不加，$S=6$ | 6 |
| $(-4, 0)$ | $[-2,-1,3,4]$ | 减 $2$ 再加 $-2$，$S=2$ | 2 |
| $(+2, 3)$ | $[-2,-1,3,6]$ | 减 $4$ 再加 $6$，$S=4$ | 4 |

最终答案 $[8,6,2,4]$，与题面一致。

## 4. 算法细节

1. **初值扫描**：先 $O(n)$ 求一次偶数之和，之后不再需要遍历数组。
2. **奇偶判定**：C++/Python 中 `x % 2 == 0` 对负数同样成立（$-4 \bmod 2 = 0$、$-3 \bmod 2 = 1$），不必先取绝对值。
3. **答案范围**：数组长度与元素绝对值都不超过 $10^4$，偶数之和不超过 $10^8$，`int` 足够；但用 `long long` 维护中间和更保险，最后再窄化。
4. **原地修改**：题面要求查询永久生效，直接在 `nums` 上累加即可，不需要复制数组。
5. **一次一条查询**：`answer` 与 `queries` 等长，按顺序追加，天然对位。

## 5. 正确性证明

**引理 1（初值正确）**：算法开始时 $S = \sum_{x \in A,\, x \text{ 为偶数}} x$。

**证明**：初始化时对每个元素判一次 `x % 2 == 0`，为真则累加，遍历完整数组后 $S$ 恰为全部偶数元素之和。∎

**引理 2（单步更新正确）**：若更新前 $S$ 等于当前数组的偶数之和，则按增量公式更新后 $S'$ 等于更新后数组的偶数之和。

**证明**：设被修改位置的下标为 $index$。更新只影响 $A[index]$，其余元素不变，因此

$$S' = S - \bigl(\text{若 } old \text{ 为偶数则 } old \text{ 否则 } 0\bigr) + \bigl(\text{若 } nw \text{ 为偶数则 } nw \text{ 否则 } 0\bigr).$$

分四种情形：若 $old$ 偶、$nw$ 偶，则 $S' = S - old + nw$，正是把旧贡献换成新贡献；若 $old$ 偶、$nw$ 奇，则 $S' = S - old$，该位置退出偶数集合；若 $old$ 奇、$nw$ 偶，则 $S' = S + nw$，该位置新加入偶数集合；若两者皆奇，$S' = S$，而偶数集合确实没变。四种情形结论一致。∎

**定理**：算法返回的 `answer` 恰为每次查询后的偶数之和。

**证明**：对查询次数归纳。第 $0$ 次查询前，由引理 1，$S$ 是初始偶数之和。设第 $k-1$ 次查询后 $S$ 正确，第 $k$ 次查询只修改一个位置，由引理 2，更新后 $S$ 仍是当前数组的偶数之和，于是 `answer[k]` 正确，归纳成立。∎

## 6. 复杂度分析

- **时间**：$O(n + q)$。初值扫描 $O(n)$；每条查询做常数次判断与加减，共 $q$ 条。相比暴力的 $O(nq)$ 是本题的降维点。
- **空间**：$O(1)$ 额外空间（不计 `answer` 本身与输入数组）。只维护一个累加变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> sumEvenAfterQueries(vector<int>& nums, vector<vector<int>>& queries) {
        long long total = 0;
        for (int x : nums) {
            if (x % 2 == 0) total += x;
        }
        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            int val = q[0], idx = q[1];
            if (nums[idx] % 2 == 0) total -= nums[idx];
            nums[idx] += val;
            if (nums[idx] % 2 == 0) total += nums[idx];
            ans.push_back(static_cast<int>(total));
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def sumEvenAfterQueries(self, nums: list[int], queries: list[list[int]]) -> list[int]:
        total = 0
        for x in nums:
            if x % 2 == 0:
                total += x
        ans = []
        for val, idx in queries:
            if nums[idx] % 2 == 0:
                total -= nums[idx]
            nums[idx] += val
            if nums[idx] % 2 == 0:
                total += nums[idx]
            ans.append(total)
        return ans
```

## 8. 边界情况与易错点

1. **全奇数组**：初始 $S = 0$，查询后仍可能是 0，不能把 0 当作「尚未初始化」而漏答。
2. **负数取模**：C++ 中 `-3 % 2 == -1`、`-4 % 2 == 0`，用 `== 0` 判断偶数没有问题；若写成 `x % 2 == 1` 判奇数，负数会漏判（$-3 \bmod 2 = -1$），应写 `!= 0` 或 `x & 1`。
3. **新值等于旧值**：必须先减后加，两次判断各自独立，结果正确；若只判一次就可能算错。
4. **单元素数组**：示例 2 的情形，逻辑无需特判。
5. **查询下标合法**：题面保证 $0 \le queries[i][1] < A.length$，无需越界检查。
6. **输出类型**：和为整数，即使数组全为奇数也要返回与 $q$ 等长的数组（全 0），不能返回空。
7. **大输入**：$n = q = 10^4$ 时暴力约 $10^8$ 次加法，Python 会 TLE；增量法只有 $2 \times 10^4$ 次操作。

**延伸思考**：如果每次查询是「把区间 $[l, r]$ 内所有元素加 $val$」，并同样要求回答偶数之和，增量法就退化为 $O(\text{区间长度})$。此时需要**线段树**：每个区间维护「偶数个数」与「偶数之和」，整体加一个值会使奇偶性翻转（加奇数时偶数变奇数、奇数变偶数），于是懒标记只需记录待加值，节点内两个量在翻转时互相交换角色（偶数个数变成奇数个数，偶数之和变成区间总和减偶数和）。这是本题从「签到题」升级为「数据结构题」的自然方向。
