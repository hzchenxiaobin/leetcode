# LeetCode 区间列表的交集 题解

## 1. 题目概述

- **标题 / 题号**：区间列表的交集（#986，medium）
- **链接**：https://leetcode.cn/problems/interval-list-intersections/
- **来源**：LeetCode 第 122 场周赛 Q3
- **难度**：中等
- **标签**：数组、双指针、扫描线

**题意**：给定两个**闭区间**列表 `firstList` 与 `secondList`，每个列表内部**互不相交**且**已按起点升序排列**。返回这两个列表中所有区间的**交集**（按起点升序）。两个闭区间的交集要么为空，要么仍是闭区间，例如 $[1,3] \cap [2,4] = [2,3]$。

**约束**：

- $0 \le firstList.length, secondList.length \le 1000$
- $firstList.length + secondList.length \ge 1$
- $0 \le start_i \le end_i \le 10^9$，且列表内 $end_i < start_{i+1}$
- 同理 $0 \le start_j \le end_j \le 10^9$，且 $end_j < start_{j+1}$

> 💡 「闭区间 + 列表内不相交」这两个条件缺一不可：闭区间意味着 $[5,5]$ 这样的**单点**交集必须保留；列表内不相交保证了「按右端点推进指针」的安全性。

## 2. 示例

**示例 1**

```text
输入：firstList  = [[0,2],[5,10],[13,23],[24,25]]
      secondList = [[1,5],[8,12],[15,24],[25,26]]
输出：[[1,2],[5,5],[8,10],[15,23],[24,24],[25,25]]
```

**示例 2**

```text
输入：firstList = [[1,3],[5,9]], secondList = []
输出：[]
解释：空列表与任何列表的交集都是空。
```

**示例 3**

```text
输入：firstList = [], secondList = [[4,8],[10,12]]
输出：[]
```

**示例 4**

```text
输入：firstList = [[1,7]], secondList = [[3,10]]
输出：[[3,7]]
解释：两个区间各取一端：$[1,7] \cap [3,10] = [3,7]$。
```

## 3. 解题思路

### 3.1 暴力思路

两两枚举：对每个 $i, j$ 计算 $[\max(start_i, start_j), \min(end_i, end_j)]$，非空则收集。复杂度 $O(nm)$，$n = m = 1000$ 时是 $10^6$ 次比较，本身还能过，但**完全没有利用「已排序」**这一结构性信息；而且结果需要额外排序才能保证输出顺序。如果区间规模升到 $10^5$，就必然超时。

### 3.2 核心观察：谁先结束，谁就可以被淘汰

![双指针：交集右端点由更早结束的区间决定](images/wc122_q3_pointer_advance.svg)

设当前考察 `firstList[i] = [a1, b1]` 与 `secondList[j] = [a2, b2]`。它们的交集为

$$\bigl[\max(a_1, a_2),\; \min(b_1, b_2)\bigr],$$

当且仅当 $\max(a_1,a_2) \le \min(b_1,b_2)$ 时非空。

接下来该移动哪个指针？看谁**先结束**：

- 若 $b_1 < b_2$：`firstList[i]` 结束得更早。由于 `secondList` 内区间互不相交且有序，`secondList[j]` 之后的所有区间起点都 $> b_2 > b_1$，不可能再与 `firstList[i]` 相交；而 `firstList` 中后面的区间起点 $> b_1$，还有可能与 `secondList[j]` 相交。所以可以**永久丢弃** `firstList[i]`，令 $i \gets i+1$。
- 若 $b_1 \ge b_2$：对称地丢弃 `secondList[j]`，令 $j \gets j+1$。

每一步至少有一个区间被淘汰，两个列表各被扫一遍，总步数 $O(n+m)$。

### 3.3 算法流程

```text
1. ans = []，i = j = 0
2. while i < len(firstList) 且 j < len(secondList):
       lo = max(firstList[i][0], secondList[j][0])
       hi = min(firstList[i][1], secondList[j][1])
       若 lo <= hi: ans 追加 [lo, hi]
       若 firstList[i][1] < secondList[j][1]: i += 1
       否则: j += 1
3. 返回 ans
```

注意两件事：**先记录交集再移动指针**（否则会漏掉当前这对）；比较用的是**右端点** $b_1$ 与 $b_2$，而不是左端点。

### 3.4 示例演算

![示例 1 的 7 步走查](images/wc122_q3_walkthrough.svg)

对示例 1 逐步走查：

| 步 | `firstList[i]` | `secondList[j]` | 交集 | 前进 |
|----|----------------|-----------------|------|------|
| 1 | $[0,2]$ | $[1,5]$ | $[1,2]$ | $2<5$，$i{+}{+}$ |
| 2 | $[5,10]$ | $[1,5]$ | $[5,5]$ | $10>5$，$j{+}{+}$ |
| 3 | $[5,10]$ | $[8,12]$ | $[8,10]$ | $10<12$，$i{+}{+}$ |
| 4 | $[13,23]$ | $[8,12]$ | 空（$13>12$） | $23>12$，$j{+}{+}$ |
| 5 | $[13,23]$ | $[15,24]$ | $[15,23]$ | $23<24$，$i{+}{+}$ |
| 6 | $[24,25]$ | $[15,24]$ | $[24,24]$ | $25>24$，$j{+}{+}$ |
| 7 | $[24,25]$ | $[25,26]$ | $[25,25]$ | $25<26$，$i{+}{+}$ |

共 7 步、6 段交集，与题面输出一致。第 4 步是「空交集」的典型：$lo = 13 > hi = 12$，只前进不记录。

## 4. 算法细节

1. **交集公式**：下界取两个起点的 $\max$，上界取两个终点的 $\min$；用 `lo <= hi`（含等号）判非空。
2. **指针推进条件**：严格小于 `<` 时推进 `i`，否则推进 `j`。相等时推进哪一个都可以（另一个下一步会因 `lo > hi` 被淘汰），本实现选择推进 `j`。
3. **空列表**：任一侧为空时 `while` 直接不进入，返回空数组，无需特判。
4. **输出顺序**：由于两个列表都升序且指针单调，产出的交集起点天然非降，无需再排序。
5. **越界安全**：`lo`/`hi` 只取当前合法元素，指针推进后立即回到循环条件检查。
6. **数值范围**：端点最大 $10^9$，落在 `int` 范围内，无需 `long long`。

## 5. 正确性证明

**引理 1（当前对计算正确）**：对任意 $i, j$，$[a_1,b_1] \cap [a_2,b_2] = [\max(a_1,a_2), \min(b_1,b_2)]$，且非空当且仅当 $\max(a_1,a_2) \le \min(b_1,b_2)$。

**证明**：$x$ 同时属于两个闭区间 $\iff \max(a_1,a_2) \le x \le \min(b_1,b_2)$，这正是闭区间 $[\max(a_1,a_2), \min(b_1,b_2)]$ 的定义；该区间非空当且仅当下界不超过上界。∎

**引理 2（淘汰安全性）**：若 $b_1 < b_2$，则 `firstList[i]` 与 `secondList[j], secondList[j+1], \dots` 中任何一个都不相交。

**证明**：对 $k > j$，由列表内不相交且有序，有 $a_{2}^{(k)} > b_2$（严格大于当前区间终点）。于是

$$\max(a_1, a_2^{(k)}) \ge a_2^{(k)} > b_2 > b_1 \ge \min(b_1, b_2^{(k)}),$$

即交集为空。故 `firstList[i]` 与后续所有第二列表区间都无交集，可以永久丢弃。对称地，$b_1 \ge b_2$ 时 `secondList[j]` 与第一列表后续区间全部无交集。∎

**引理 3（不遗漏）**：算法的每一轮恰好检查「尚未被淘汰的第一个」组合 $(i, j)$，且任何一对可能相交的区间都会在某一轮被检查。

**证明**：指针只会单调前进，且只在引理 2 的条件下前进；被跳过的组合都已由引理 2 证明交集为空。对于任意一对 $(i', j')$，在其之前被跳过的组合均为空，故当 $i = i'$、$j = j'$ 时二者尚未被淘汰，必然被某一轮检查到。∎

**定理**：算法输出恰为两个区间列表的全部交集，且按起点升序。

**证明**：由引理 1，每次记录的都是真实交集；由引理 2、3，跳过的不产生交集、可能相交的组合一个不漏，故输出集合正确。排序性：每轮产出的交集起点为 $\max(a_{1}, a_{2})$，而指针单调前进使两个 $a$ 都非降，故产出序列起点非降。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。每轮循环至少推进一个指针，$i$ 至多推进 $n$ 次、$j$ 至多推进 $m$ 次，因此循环至多执行 $n + m$ 次，每次 $O(1)$。
- **空间**：$O(1)$ 额外空间（不计输出数组）。输出数组长度不超过 $n + m$，因为每轮至多产出一段交集。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> intervalIntersection(vector<vector<int>>& firstList, vector<vector<int>>& secondList) {
        vector<vector<int>> ans;
        int i = 0, j = 0;
        int n = firstList.size(), m = secondList.size();
        while (i < n && j < m) {
            int lo = max(firstList[i][0], secondList[j][0]);
            int hi = min(firstList[i][1], secondList[j][1]);
            if (lo <= hi) ans.push_back({lo, hi});
            if (firstList[i][1] < secondList[j][1]) i++;
            else j++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def intervalIntersection(self, firstList: list[list[int]], secondList: list[list[int]]) -> list[list[int]]:
        ans = []
        i = j = 0
        while i < len(firstList) and j < len(secondList):
            lo = max(firstList[i][0], secondList[j][0])
            hi = min(firstList[i][1], secondList[j][1])
            if lo <= hi:
                ans.append([lo, hi])
            if firstList[i][1] < secondList[j][1]:
                i += 1
            else:
                j += 1
        return ans
```

## 8. 边界情况与易错点

1. **单点交集**：$[5,5]$、$[24,24]$、$[25,25]$ 都必须保留，判断写成 `lo <= hi`；写成 `lo < hi` 会漏掉一半答案。
2. **空列表**：示例 2、3 里有一侧为空，`while` 自然不进入，不要额外返回 `[[0,0]]` 之类的占位。
3. **端点相等时的指针**：$b_1 = b_2$ 时推进任意一侧都正确，但**只能推进一个**；同时推进会漏掉与另一侧后续区间的组合。
4. **忘了先记录再推进**：把 `push_back` 放到 `if/else` 之后、指针推进之后，会读到已换掉的下标。
5. **误用左端点推进**：推进条件必须是右端点的比较，用起点比较会破坏引理 2 的前提。
6. **输出排序**：不要自作聪明再 `sort` 一遍；顺序由指针单调性保证，额外排序纯属多余（且若真需要排序说明逻辑有 bug）。
7. **大端点**：$10^9$ 仍在 `int` 内，但若题面把范围改到 $10^{18}$ 就要换 `long long`。

**延伸思考**：若列表内部**允许相交**（不再保证互不相交），双指针的淘汰论证就失效了，需要退化为「扫描线 + 事件排序」：把所有端点按坐标排序，遇到起点计数加一、终点计数减一，计数 $\ge 2$ 的区间即为交集，复杂度 $O((n+m)\log(n+m))$。另一种变体是求**多个**列表的交集：可以把当前结果与下一个列表反复做双指针求交，结果规模单调不增，总复杂度为各列表长度之和的线性倍数。
