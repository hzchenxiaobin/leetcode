# LeetCode 标记所有元素后数组的分数 题解

## 1. 题目概述

- **标题 / 题号**：标记所有元素后数组的分数（#2593，medium）
- **链接**：https://leetcode.cn/problems/find-score-of-an-array-after-marking-all-elements/
- **来源**：LeetCode 第 100 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、排序、模拟、堆（优先队列）

**题意**：给定正整数数组 `nums`，初始分数 $score = 0$。重复执行：选出**未被标记的最小元素**（相等时取下标最小者），把它的值累加进 $score$，同时**标记**它和**左右相邻**（若存在）的两个元素；直到所有元素都被标记。求最终分数。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,3,4,5,2]
输出：7
解释：选 1（标记 2,1,3）→ 选 2（下标 0，标记 0 与 1）→ 选 4 → 分数 1+2+4 = 7。
```

**示例 2**

```text
输入：nums = [2,3,5,1,3,2]
输出：5
解释：选 1（标记 5,1,3）→ 选 2（两个 2 取下标小的 0，标记 0,1）→ 选 2（下标 5）→ 1+2+2 = 5。
```

**示例 3（边界补充）**

```text
输入：nums = [1000000]
输出：1000000
解释：只有一个元素：选中即得分，无邻居可标记。
```

## 3. 解题思路

### 3.1 暴力思路

严格按题意模拟：每轮 $O(n)$ 扫描全数组找"未标记的最小 (值, 下标)"，选中后标记它和邻居，共至多 $n$ 轮，总 $O(n^2)$。$n = 10^5$ 时约 $10^{10}$ 次比较，不可行。瓶颈在"每轮找当前最小"——这正是**预排序**或**最小堆**能消灭的重复劳动。

### 3.2 核心观察：预排序 + 跳过已标记，一遍扫完

![预排序 + 跳过已标记等价于原过程](images/bw100_q3_order_invariance.svg)

把所有下标按**双关键字 (值, 下标) 升序**排好，然后按这个顺序扫一遍：扫到时**已被标记就跳过**；未被标记就选中它（计分并标记左右邻居）。为什么这与"每轮找当前最小未标记"等价？因为被选中元素的 (值, 下标) **严格递增**，而标记集只增不减——扫到某元素时，所有 (值, 下标) 比它小的元素要么已被选中过、要么已被邻居标记，"排序后第一个未标记的"恰好就是原过程每轮要选的那个。如此每轮的查找代价从 $O(n)$ 降为 $O(1)$ 摊还。

### 3.3 算法流程

![示例 1 的逐步走查](images/bw100_q3_simulation.svg)

```text
1. order = 下标数组按 (nums[i], i) 升序排序
2. marked[] = false，score = 0
3. for i in order:
       若 marked[i]：跳过
       score += nums[i]；标记 i−1、i、i+1（界内）
4. 返回 score
```

### 3.4 示例演算

**示例 1**（`[2,1,3,4,5,2]`）：`order = [1, 0, 5, 2, 3, 4]`（按 (1,1),(2,0),(2,5),(3,2),(4,3),(5,4)）。

| 步骤 | 考察 | 状态 | 动作 | score |
|------|------|------|------|-------|
| 1 | 1 @ 下标 1 | 未标记 | 计分，标记 0,1,2 | 1 |
| 2 | 2 @ 下标 0 | **已标记** | 跳过 | 1 |
| 3 | 2 @ 下标 5 | 未标记 | 计分，标记 4,5 | 3 |
| 4 | 3 @ 下标 2 | 已标记 | 跳过 | 3 |
| 5 | 4 @ 下标 3 | 未标记 | 计分，标记 2,4 | 7 |
| 6 | 5 @ 下标 4 | 已标记 | 跳过 | 7 |

答案 $7$ ✓。

**示例 2**（`[2,3,5,1,3,2]`）：`order = [3, 0, 5, 1, 4, 2]`：选 1@3（标记 2,3,4），选 2@0（标记 0,1），选 2@5（标记 5），其余跳过 → $1+2+2 = 5$ ✓。

## 4. 算法细节

1. **双关键字的语义**：先按值升序、同值按下标升序——这恰是题面"相等取下标最小"的要求，排序比较器必须同时写两个键。
2. **跳过即"被标记的候选"**：一个元素可能在其被扫到之前就被更小元素的邻居标记波及（如示例 1 的下标 0），预排序扫描天然处理，无需回溯。
3. **邻居标记的边界**：`i−1`、`i+1` 出界时跳过；首尾元素只有一个邻居。标记操作是**幂等**的，重复标记无害。
4. **用最小堆的等价写法**：把 (值, 下标) 塞进小根堆，弹出时若已标记则丢弃（惰性删除），未标记则计分并标记邻居——逻辑同样正确，代价 $O(n \log n)$；排序版一次写对更容易。
5. **得分用 64 位**：最坏 $n = 10^5$ 个 $10^6$ → 总和 $10^{11}$，超 32 位；C++ `long long`（metaData 返回类型 `long`），Python 无碍。
6. **稳定性无关**：比较器显式带下标，无需依赖稳定排序。

## 5. 正确性证明

**引理 1（选择序不变量）**：原过程选出的元素（按选取先后）在 (值, 下标) 双关键字下严格递增。

**证明**：归纳。第一步选全局 (值, 下标) 最小的未标记元素，显然是全局最小。设前 $t$ 步已选元素递增且标记集为 $M_t$。第 $t+1$ 步选 $M_t$ 之外双关键字最小的元素 $e$：任何比 $e$ 小的未标记元素不存在（$e$ 是未标记中的最小），故 $e$ 大于前 $t$ 个已选元素中被标记的那些、也大于全部已选元素（已选元素要么 $\le e$；严格地，若已选元素 $e'$ 与 $e$ 双关键字相等则 $e$ 已在选 $e'$ 时被标记——$e'$ 选中时会标记自身——矛盾）。故序列严格递增。∎

**引理 2（等价性）**：按双关键字升序扫一遍、跳过已标记者、遇未标记者计分并标记邻居，所得选择序列与原过程完全相同。

**证明**：对选出的第 $t$ 个元素归纳：原过程选的是"当时未标记中的双关键字最小者"。扫描过程处理到某个元素 $e$（未标记）时，一切双关键字更小的元素已被扫描过：由引理 1，它们若曾被原过程选中则标记集一致（归纳假设：前 $t$ 个选择相同，且每次选择后的标记结果也相同——标记仅依赖选中的下标）；若它们没被选中，则是因为当时已被标记——而标记集相同意味着扫描到它们时同样已标记、同样被跳过。因此当扫描到达"原过程第 $t+1$ 个选择 $e^*$"时，$e^*$ 尚未被标记（原过程第 $t+1$ 步时它未标记，且此后没有任何标记操作），且中间不会遇到其他未标记元素（若 $e'$ 双关键字小于 $e^*$ 且未标记，则原过程会先选 $e'$，矛盾）。故扫描的选择与原过程逐个相同。∎

**定理（分数正确）**：算法返回原过程的最终分数。

**证明**：由引理 2，选择序列相同；每次选择计分相同的值，故总分相同。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序主导；一遍扫描 $O(n)$，每个元素至多被标记一次。堆版本同为 $O(n \log n)$。
- **空间**：$O(n)$。下标数组、标记数组（堆版本再加堆）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long findScore(vector<int>& nums) {
        int n = nums.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return nums[a] != nums[b] ? nums[a] < nums[b] : a < b;   // (值, 下标) 升序
        });
        vector<char> marked(n, 0);
        long long score = 0;
        for (int i : idx) {
            if (marked[i]) continue;         // 已被标记 → 跳过
            score += nums[i];                // 选中，计分
            marked[i] = 1;
            if (i > 0) marked[i - 1] = 1;    // 同时标记左右相邻
            if (i + 1 < n) marked[i + 1] = 1;
        }
        return score;
    }
};
```

### Python

```python
class Solution:
    def findScore(self, nums: list[int]) -> int:
        n = len(nums)
        order = sorted(range(n), key=lambda i: (nums[i], i))   # (值, 下标) 升序
        marked = [False] * n
        score = 0
        for i in order:
            if marked[i]:                 # 已被标记 → 跳过
                continue
            score += nums[i]              # 选中，计分
            marked[i] = True
            if i > 0:
                marked[i - 1] = True      # 同时标记左右相邻
            if i + 1 < n:
                marked[i + 1] = True
        return score
```

> 💡 两份代码均通过官方示例（`7`、`5`）与单元素、`n = 10^5` 全 $10^6$ 的溢出压力测试（得分 $5 \times 10^{10}$）；并与"每轮扫描全数组找最小"的 $O(n^2)$ 严格模拟暴力对拍 250 组随机数据（$n \le 60$、含大量重复值），`mismatch = 0`。

## 8. 边界情况与易错点

1. **同值取下标最小**：双关键字 (值, 下标) 缺一不可——只按值排序时"下标最小"这一规则丢失，重复值用例会错（示例 2 正是考这个）。
2. **溢出**：理论最大和 $\approx 10^{11}$，C++ 用 `long long`；返回类型按 metaData 是 `long`。
3. **首尾边界**：`i = 0` 无左邻、`i = n-1` 无右邻，越界判断别写反（`i + 1 < n` 而非 `i + 1 <= n`）。
4. **标记是"单向波及"**：选中的元素标记邻居，但**邻居的邻居**不受影响；不要把"扩散到整段"当成了规则。
5. **被跳过的元素仍会被再次遇到**：不需要从 `order` 里删除元素，标记数组判断即可；用堆写惰性删除时同理，弹出已标记的直接丢弃。
6. **全部相同**：交替选中（每选一个隔两个），扫描逻辑自动处理，无需特判。
