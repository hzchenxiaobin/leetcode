# LeetCode 无需开会的工作日 题解

## 1. 题目概述

- **标题 / 题号**：无需开会的工作日（#3169，medium）
- **链接**：https://leetcode.cn/problems/count-days-without-meetings/
- **来源**：LeetCode 第 400 场周赛 Q2
- **难度**：中等
- **标签**：数组、排序、区间合并

**题意**：给定总工作天数 `days`（从第 1 天开始）和会议列表 `meetings`，其中 `meetings[i] = [start_i, end_i]` 表示第 `i` 场会议覆盖的闭区间（首尾两天都开会）。会议时间可能重叠，返回没有任何会议的**空闲工作日**天数。

**约束**：

- $1 \le days \le 10^9$
- $1 \le meetings.length \le 10^5$
- $meetings[i].length == 2$
- $1 \le meetings[i][0] \le meetings[i][1] \le days$

> 💡 **审题关键**：值域高达 $10^9$，而会议最多只有 $10^5$ 场——**值域巨大、区间稀疏**。这组约束直接判死刑给「开 `days` 大小的数组逐天打标记」，必须把「哪些天被占用」压缩成区间来处理。

## 2. 示例

**示例 1**

```text
输入：days = 10, meetings = [[5,7],[1,3],[9,10]]
输出：2
解释：第 4 天和第 8 天没有安排会议。
```

**示例 2**

```text
输入：days = 5, meetings = [[2,4],[1,3]]
输出：1
解释：第 5 天没有安排会议（[1,3] 与 [2,4] 重叠部分只算一次）。
```

**示例 3**

```text
输入：days = 6, meetings = [[1,6]]
输出：0
解释：所有工作日都安排了会议。
```

## 3. 解题思路

### 3.1 暴力思路：值域打标记（被 $10^9$ 卡死）

最直观的做法：开一个 `days + 1` 的布尔数组 `busy`，对每场会议把 $busy[start \dots end]$ 全置 `true`，最后统计 `false` 的天数。时间 $O(days + n)$、空间 $O(days)$。

问题出在 $days \le 10^9$：这个数组约 1 GB，开不出来；就算改成差分数组，值域大小不变，照样爆空间。**瓶颈在值域而不是区间个数**，必须换视角——不逐天看，改看「区间与区间之间的空隙」。

### 3.2 核心观察：排序 + 区间合并，空闲 = 总天数 − 覆盖天数

把会议按**左端点升序**排序后，相交（含共享端点、互相包含）的会议一定在扫描中**连续出现**。维护当前合并段 $[S, E]$：遇到不相交的区间就「封存」当前段（长度 $E - S + 1$ 累加进 `covered`），遇到相交的区间就把 $E$ 扩展为 $\max(E, e)$。所有段封存完毕后：

$$\text{空闲天数} = days - \text{covered}$$

![核心观察：重叠会议先「粘」成整块，空闲天数 = days − 覆盖天数](images/count_days_merge_concept.svg)

> 💡 **一句话总结**：这是 [56. 合并区间](https://leetcode.cn/problems/merge-intervals/) 的计数版——重叠会议先「粘」成两两不相交的整块，块内是开会天、块外是空闲天，答案就是「总天数 − 各块长度之和」。

### 3.3 算法流程

排序后一次线性扫描，只有「封存旧段、开新段」与「并入当前段」两个分支：

![算法流程：排序 → 线性扫描合并 → 返回 days − covered](images/count_days_merge_flow.svg)

```text
1. 按左端点升序排序 meetings
2. 初始化 covered = 0；curS = 0, curE = −1（哨兵，保证第一个区间必开新段）
3. 依次扫描每个会议 [s, e]：
   若 s > curE：与当前段不相交 → 封存旧段 covered += curE − curS + 1，开新段 curS = s, curE = e
   否则：相交/被包含 → 并入当前段 curE = max(curE, e)
4. 扫描结束，补最后一段：covered += curE − curS + 1
5. 返回 days − covered
```

## 4. 算法细节

1. **排序键**：`vector<vector<int>>` 的默认字典序先比左端点、再比右端点；本题只需要左端点有序，左端点相同的顺序无关紧要（相交判定与 `max` 兜底）。
2. **相交判定的闭区间口径**：会议是闭区间，$s \le E$ 即相交——共享端点的 $[1,3]$ 与 $[3,5]$ 走「并入」分支，第 3 天不会被重复计数；日历紧挨的 $[1,3]$ 与 $[4,6]$ 满足 $s = E + 1$，走「开新段」分支，两段长度之和 $3 + 3 = 6$ 恰好等于合并长度 $[1,6]$，**无需把「相邻」误当「相交」做特判**。
3. **哨兵设计**：`curS = 0, curE = −1` 表示一段「不存在的空段」——第 0 天不存在，天然保证第一个会议必然触发开新段；且封存空段时累加 $(−1) − 0 + 1 = 0$，不会污染 `covered`。
4. **循环外补最后一段**：循环体内只在「开新段」时封存旧段，最后一段（以及只有一段的情形）必须在循环结束后补加——与哨兵配对，所有段共用同一条封存语句，分支最少。
5. **等价简化——数空隙版**：不显式计算 `covered`，维护 `cur_end = 0`（同样的哨兵），遇 $s > cur\_end$ 时 `free += s − cur_end − 1`，末尾 `free += days − cur_end`。两版完全等价（任意时刻 $\text{free} + \text{covered} = days$ 恒成立），数空隙版少一次「封存」动作、代码更短，计数版与 56 合并区间模板一脉相承、更好迁移。

## 5. 正确性证明

**引理 1（相交区间的连续性）**：将所有会议区间按左端点升序排序后，设当前合并段为 $[S, E]$。若下一个区间 $[s, e]$ 满足 $s > E$，则其后所有区间均与 $[S, E]$ 不相交。

**证明**：排序保证对任意后续区间 $[s_j, e_j]$ 有 $s_j \ge s > E$，而 $[S, E]$ 的右端点固定为 $E$，故 $[s_j, e_j] \cap [S, E] = \emptyset$。即「封存当前段」是安全的，不会漏掉后续可能的相交区间。∎

**引理 2（不重不漏）**：算法产生的段序列 $[S_1, E_1], \dots, [S_m, E_m]$ 两两不相交，且 $\bigcup_{i=1}^{m} [S_i, E_i] = \bigcup_{j=1}^{n} [s_j, e_j]$。

**证明**：对扫描步数归纳。归纳假设：已处理区间生成的段两两不相交，且并集等于已处理区间之并。初始时仅有哨兵空段，结论平凡。处理新区间 $[s, e]$：

- 若 $s \le E$：并入当前段得 $[S, \max(E, e)]$，新段与旧并集之差恰为 $[s, e]$ 的贡献，其余段不受影响，不相交性与并集等价性均保持；
- 若 $s > E$：由引理 1，$[s, e]$ 及其后所有区间均与当前段不相交；又因为更早封存的段满足 $E_i \le E < s$（封存按左端点推进，段右端点随扫描单调不减），$[s, e]$ 与它们也不相交。封存 $[S, E]$、开启新段 $[s, e]$ 后归纳假设依然成立。∎

**定理**：算法返回的 $days - \sum_{i=1}^{m} (E_i - S_i + 1)$ 即没有会议的工作日数。

**证明**：由约束 $1 \le s_j \le e_j \le days$，所有会议都在 $[1, days]$ 内。对任意一天 $d \in [1, days]$：$d$ 空闲 $\iff d \notin \bigcup_j [s_j, e_j] \iff d \notin \bigcup_i [S_i, E_i]$（引理 2）。由引理 2 诸段两两不相交，故 $\left| \bigcup_i [S_i, E_i] \right| = \sum_i (E_i - S_i + 1) = \text{covered}$，空闲天数 $= days - \text{covered}$，与算法返回值一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序占主导；线性扫描每个会议 $O(1)$ 处理。与值域 $days$ 的大小完全解耦——这正是暴力被 $10^9$ 卡死后正确的出路。
- **空间复杂度**：$O(1)$（不计原地排序的递归栈 $O(\log n)$）。只使用 `covered / curS / curE` 三个变量，无需保存合并结果。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int countDays(int days, vector<vector<int>>& meetings) {
        sort(meetings.begin(), meetings.end());   // 按左端点升序
        long long covered = 0;
        int curS = 0, curE = -1;                   // 哨兵：curE = -1 保证首区间必开新段
        for (auto& m : meetings) {
            if (m[0] > curE) {                     // 不相交 → 封存旧段，开新段
                covered += (long long)curE - curS + 1;
                curS = m[0];
                curE = m[1];
            } else {                               // 相交/被包含 → 并入，取 max 防回退
                curE = max(curE, m[1]);
            }
        }
        covered += (long long)curE - curS + 1;     // 别忘最后一段
        return (int)(days - covered);
    }
};
```

### Python

```python
class Solution:
    def countDays(self, days: int, meetings: List[List[int]]) -> int:
        meetings.sort()                    # 按左端点升序
        covered = 0
        cur_s, cur_e = 0, -1              # 哨兵：cur_e = -1 保证首区间必开新段
        for s, e in meetings:
            if s > cur_e:                 # 不相交 → 封存旧段，开新段
                covered += cur_e - cur_s + 1
                cur_s, cur_e = s, e
            else:                         # 相交/被包含 → 并入，取 max 防回退
                cur_e = max(cur_e, e)
        covered += cur_e - cur_s + 1      # 别忘最后一段
        return days - covered
```

## 8. 边界情况与易错点

1. **值域与溢出**：$days \le 10^9$，开数组逐天打标记必然爆空间。合并后的段两两不相交且都在 $[1, days]$ 内，故 $covered \le days \le 10^9$，`int` 装得下；但「不合并直接累加每场会议长度」的写法上限 $10^5 \times 10^9 = 10^{14}$ 会爆 `int`——C++ 建议直接用 `long long` 防御。
2. **被包含区间导致回退**：`meetings = [[1,10],[2,3]]`，处理 `[2,3]` 时若写 `curE = e` 而不是 `max`，$E$ 会从 10 回退到 3，凭空多算第 $4 \sim 10$ 天的空隙。**排序只保证左端点有序，右端点完全可能乱序**。
3. **共享端点算相交**：$[1,3]$ 与 $[3,5]$ 共享第 3 天，满足 $s \le E$ 走「并入」分支，第 3 天恰好只计一次。
4. **日历紧挨不算相交**：$[1,3]$ 与 $[4,6]$ 之间空闲天数为 $4 - 3 - 1 = 0$，走「开新段」分支后两段长度相加恰好正确，无需特判。
5. **最后一段 / 尾部空隙**：循环内只封存旧段，最后一段必须循环外补加；数空隙写法对应「尾部空隙 $days - cur\_end$」，漏掉就少算一段。
6. **空输入天然正确**：题面保证 $n \ge 1$，但哨兵设计使代码对空数组也直接返回 `days`，无需特判。
7. **原地排序修改入参**：`meetings` 被原地排序，LeetCode 判题不检查入参可变性，可放心使用；若需保持原序，先拷贝一份 $O(n)$。

**延伸思考**：

- **在线化**：若会议支持动态增删、随时查询空闲天数，排序扫描的离线做法失效——需要离散化 + 动态开点线段树（或平衡树）维护「覆盖总长度」，查询 $O(\log)$。
- **区间越界**：若允许 $start_i, end_i$ 落在 $[1, days]$ 之外（甚至 $start > end$），需先把每场会议与 $[1, days]$ 求交，再套用本题流程。
- **变体提问**：把「空闲天数总数」改成「最长连续空闲天数」，只需在合并后扫描相邻段间隙取最大值；改成「空闲天数 ≥ k 的最早时刻」则可再叠加二分。
