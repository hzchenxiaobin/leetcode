# LeetCode 找到按位或最接近 K 的子数组 题解

## 1. 题目概述

- **标题 / 题号**：找到按位或最接近 K 的子数组（#3171，hard）
- **链接**：https://leetcode.cn/problems/find-subarray-with-bitwise-or-closest-to-k/
- **来源**：LeetCode 第 400 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、动态规划、前缀思想

**题意**：给定数组 `nums` 和整数 `k`，找一个**连续非空**子数组 `nums[l..r]`，使其所有元素的按位或 $OR(l..r) = nums[l] \lor nums[l+1] \lor \cdots \lor nums[r]$ 与 $k$ 的绝对差 $|k - OR(l..r)|$ 尽可能小，返回这个最小绝对差。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$
- $1 \le k \le 10^9$

> 💡 **审题关键**：$10^9 < 2^{30}$，所以所有数（包括任意子数组的 OR 值和 $k$）都落在 30 个比特位之内——这个「30」正是全题复杂度的来源。另外注意 OR 值**可以越过 $k$**：答案可能在 $k$ 的上方，也可能在下方，两侧都要检查。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4,5], k = 3
输出：0
解释：子数组 nums[0..1] 的 OR 值为 1 | 2 = 3，|3 - 3| = 0。
```

**示例 2**

```text
输入：nums = [1,3,1,3], k = 2
输出：1
解释：所有子数组的 OR 值都在 {1, 3} 中，最接近 2 的是 3，差为 1。
```

**示例 3**

```text
输入：nums = [1], k = 10
输出：9
解释：唯一的子数组 OR 值为 1，|10 - 1| = 9。
```

## 3. 解题思路

### 3.1 暴力思路：$O(n^2)$ 枚举被卡死

朴素做法是双重循环：固定左端点 $l$，向右扩张 $r$，用变量 $v$ 增量维护 $OR(l..r)$，每次更新答案。内层是 $O(1)$ 的，但总循环次数 $n(n+1)/2 \approx 5 \times 10^9$，在 $n = 10^5$ 下必然超时。

更致命的是，**两条经典优化路线全部失效**：

- **前缀和路线**：前缀 OR 无法相减——OR 没有「逆运算」，就算知道 $OR(0..r)$ 和 $OR(0..l-1)$ 也推不出 $OR(l..r)$，「区间 = 前缀差」的性质只属于 XOR（和、按位异或）。
- **滑动窗口路线**：右端点右移时窗口 OR 只增不减没问题，但**左端点右移时无法撤销**已经 OR 进窗口的比特位，窗口收缩不是 $O(1)$ 的，双指针的单调可控性断了。

> 💡 一句话：**「不可逆」是本题一切困难的根源**。破解它的钥匙不是硬造可逆性，而是发现候选值根本没有那么多。

### 3.2 核心观察：固定右端点，OR 值是一条长度 $\le 31$ 的「位集链」

固定右端点 $r$，让左端点 $l$ 从 $r$ 向 $0$ 移动。每左移一格，子数组多吞一个数，OR 结果**只会添位、不会减位**：

$$OR(l-1..r) = OR(l..r) \lor nums[l-1] \supseteq OR(l..r)$$

于是这 $r+1$ 个左端点对应的 OR 值构成一条**按位集合单调包含的链**。关键结论：

- 值沿链**单调不减**，且**每严格增大一次，至少新添 1 个比特位**；
- 本题所有值 $< 2^{30}$，只有 30 个比特位；
- 所以严格增大至多发生 **30 次**，**互异 OR 值至多 $30 + 1 = 31$ 个**。

也就是说，尽管以 $r$ 结尾的子数组有 $r+1$ 个，它们的产品（OR 值）**只有不超过 31 种**。$n$ 个右端点，总共只有 $O(30n)$ 个有意义的候选值——把它们全部枚举一遍也才 $3 \times 10^6$ 量级。

![核心观察：固定右端点，子数组 OR 值构成位集链](images/wc400_q4_or_chain_concept.svg)

### 3.3 算法流程：逐右端点维护「升序链」

用一个列表 `dp` 维护**以当前元素结尾的所有子数组的互异 OR 值**（按升序排列）。处理新元素 $x = nums[i]$ 时：

1. **前插**：把 $x$ 放到链头——它对应单元素子数组 $[i..i]$，是新的最小值；
2. **整体 OR**：旧链每个值 $v$ 更新为 $v \lor x$（对应左端点不变、右端点扩张到 $i$）；
3. **相邻去重**：链仍保持升序（位集链 + 同一批新位），相等值必然相邻，一遍扫描去掉重复——链长回到 $\le 31$；
4. **更新答案**：对链上每个值 $v$，用 $|v - k|$ 更新 `ans`。

![算法流程：前插 x、整体 OR、相邻去重、逐值更新答案](images/wc400_q4_dp_transition_flow.svg)

```text
1. dp = []（空链），ans = +∞
2. 对每个 x = nums[i]：
   a. ndp = [x]                    # 前插：单元素子数组
   b. 对 dp 中每个 v（升序）：
        w = v | x
        若 w != ndp 末尾元素：追加 w   # 升序 ⇒ 重复必相邻
   c. dp = ndp                      # 新链，长度 ≤ 31
   d. 对 dp 中每个 v：ans = min(ans, |v − k|)
3. 返回 ans
```

以 `nums = [1,2,4,5], k = 3` 走查全程：

## 4. 算法细节

1. **链的表示**：用普通数组按升序存互异值即可，无需哈希集合。升序是「相邻去重」正确性的前提，而它由位集链结构天然保证。
2. **前插位置是正确性关键**：新元素 $x$ 必须放在链头（最小端）。因为 $\mathrm{bits}(x) \subseteq \mathrm{bits}(v \lor x)$ 对旧链一切 $v$ 成立，$x$ 一定是新链最小值；反之若把 $x$ 接到链尾，升序被破坏，相邻去重失效，链长失控退化到 $O(n)$。
3. **只存值、不存端点**：本题只关心 $|v - k|$，无需记录每个值对应哪些左端点。若题目改为计数（有多少个子数组的 OR 值满足某条件），则每个链节点需附带「覆盖的左端点区间长度」，套路不变。
4. **等价的另一种写法**（官方标签里的线段树 / 二分思路）：固定**左端点** $l$，用 ST 表 $O(1)$ 查询区间 OR，配合「每个比特位的下一次出现位置」$nxt[i][b]$，可以 $O(30)$ 找出 $r$ 增大过程中 OR 值发生跳变的至多 31 个断点逐一检查——与右端点链法互为镜像，复杂度同为 $O(30n)$，但代码量和常数都更大。
5. **可选剪枝**：一旦 `ans == 0` 即达到理论下界，可直接返回。

## 5. 正确性证明

**引理 1（位集链）**：固定 $r$，记 $f_r(l) = OR(l..r)$。则对 $0 \le l \le r-1$ 有 $\mathrm{bits}(f_r(l)) \supseteq \mathrm{bits}(f_r(l+1))$，从而 $f_r(l)$ 关于 $l$ 单调不减。

**证明**：$f_r(l) = f_r(l+1) \lor nums[l]$，而 OR 运算只会把 $nums[l]$ 的位并入、不会清除任何已有位，故位集合单调包含，数值随之单调不减。∎

**引理 2（链长界）**：集合 $\{f_r(l) : 0 \le l \le r\}$ 的互异值个数至多为 $\min(r, 30) + 1$。

**证明**：把互异值按 $l$ 从大到小排成严格递增序列 $w_0 < w_1 < \cdots < w_{m-1}$（$w_0 = nums[r]$）。由引理 1，$w_{j}$ 的位集合真包含 $w_{j-1}$ 的位集合，即每次严格增大至少新添 1 个位。又因 $nums[i] \le 10^9 < 2^{30}$，一切 $f_r(l) < 2^{30}$，位集合大小至多 30，故 $m - 1 \le 30$。∎

**引理 3（循环不变量）**：处理完 $nums[0..i]$ 后，列表 `dp` 恰为 $\{OR(l..i) : 0 \le l \le i\}$ 的互异值集合，且升序。

**证明**：对 $i$ 归纳。$i = 0$ 时 `dp = [nums[0]]` 成立。设第 $i$ 轮结论成立，第 $i+1$ 轮处理 $x = nums[i+1]$：以 $i+1$ 结尾的子数组按左端点分为两类——单元素子数组 $[i+1..i+1]$，OR 值为 $x$；一般子数组 $[l..i+1]$（$l \le i$），OR 值为 $OR(l..i) \lor x$。由引理 1，旧链升序，且 $\mathrm{bits}(x) \subseteq \mathrm{bits}(v \lor x)$ 对一切 $v$ 成立，故 $[x, v_1 \lor x, \cdots, v_m \lor x]$ 仍升序；升序序列中相等值必相邻，故算法的相邻去重恰好去掉全部重复，得到新互异集。∎

**定理**：算法返回值 $= \min_{0 \le l \le r \le n-1} |OR(l..r) - k|$。

**证明**：算法输出是若干个 $|v - k|$ 的最小值，其中每个 $v$ 都来自某一轮 `dp`，由引理 3 每个这样的 $v$ 等于某个真实子数组的 $OR(l..r)$，故输出 $\ge$ 所求最小值。反之，对任意子数组 $[l..r]$，其 OR 值 $v$ 属于第 $r$ 轮结束时的 `dp`（引理 3），在第 $r$ 轮的检查中被用于更新 `ans`，故输出 $\le |v - k|$；取遍所有子数组即得输出 $\le$ 所求最小值。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(n \cdot (B+1)\big)$，其中 $B = 30$。每个元素触发一次链转移，链长由引理 2 界定为 $\le 31$，每次转移与答案检查均为链长线性。$n = 10^5$ 时约 $3.1 \times 10^6$ 次基本操作，远低于时限。
- **空间复杂度**：$O(B+1) = O(31)$。只维护当前一条链，旧链在转移后被替换，无需额外结构。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumDifference(vector<int>& nums, int k) {
        int ans = INT_MAX;
        vector<int> dp;                        // 以当前元素结尾的互异 OR 值（升序）
        for (int x : nums) {
            vector<int> ndp;
            ndp.push_back(x);                  // ① 前插：单元素子数组
            for (int v : dp) {                 // ② 旧链整体 OR x
                int w = v | x;
                if (w != ndp.back())           // ③ 升序 ⇒ 重复必相邻
                    ndp.push_back(w);
            }
            dp = move(ndp);
            for (int v : dp)                   // ④ 逐值更新答案
                ans = min(ans, abs(v - k));
            if (ans == 0) break;               // 可选剪枝：已达理论下界
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumDifference(self, nums: List[int], k: int) -> int:
        ans = inf
        dp = []                                # 以当前元素结尾的互异 OR 值（升序）
        for x in nums:
            ndp = [x]                          # ① 前插：单元素子数组
            for v in dp:                       # ② 旧链整体 OR x
                w = v | x
                if w != ndp[-1]:               # ③ 升序 ⇒ 重复必相邻
                    ndp.append(w)
            dp = ndp
            for v in dp:                       # ④ 逐值更新答案
                d = abs(v - k)
                if d < ans:
                    ans = d
            if ans == 0:
                break                          # 可选剪枝：已达理论下界
        return ans
```

## 8. 边界情况与易错点

1. **OR 值可能越过 $k$，最优解在 $k$ 上方**：如 `nums = [1, 6], k = 5`，候选 OR 值为 $\{1, 6, 7\}$，最优是 6（差 1）；若只维护「$\le k$ 的最大 OR」会误答 4（值 1 的差）。链上每个值都要检查，不能只看单侧。
2. **前插位置错 → 隐性 $O(n^2)$ 超时**：若把 $x$ 接到链尾，升序被破坏，相邻去重失效，链长失控。同理，**忘记去重**也会让链每轮长一格，总复杂度退化平方级。
3. **`ans` 初始化**：必须是 $+\infty$（C++ 用 `INT_MAX`），不要初始化为 0；首个元素（单元素子数组）一定会被检查，循环至少执行一次，答案必定被正确更新。
4. **溢出检查**：$|v - k| \le \max(2^{30} - 1, 10^9) < 2^{31} - 1$，C++ `int` 安全；若值域升到 $10^{18}$ 需换 `long long`，同时链长界变为 61，算法其余部分不变。
5. **$k$ 大于一切可达 OR 值**：如 `nums = [1], k = 10`，OR 永远到不了 10，答案是「最接近的下方值」的差 9；算法天然处理，无需特判。
6. **不要误用滑动窗口**：见 §3.1——OR 不可逆，左端点收缩无法撤销比特；本题的正确姿势是「每个右端点全存 $\le 31$ 个候选值」。
7. **提前返回剪枝**：`ans == 0` 即理论下界，可立即返回；不剪枝也不影响正确性。
