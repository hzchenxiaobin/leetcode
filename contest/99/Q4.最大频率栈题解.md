# LeetCode 最大频率栈 题解

## 1. 题目概述

- **标题 / 题号**：最大频率栈（#895，hard）
- **链接**：https://leetcode.cn/problems/maximum-frequency-stack/
- **来源**：LeetCode 第 99 场周赛 Q4
- **难度**：困难
- **标签**：栈、设计、哈希表、有序集合

**题意**：设计一个类似栈的数据结构，支持：

- `push(int val)`：把 `val` 压入栈顶；
- `pop()`：删除并返回**出现频率最高**的元素。若有多个元素频率并列最高，则返回**最接近栈顶**的那个。

**约束**：

- $0 \le \text{val} \le 10^9$
- `push` 与 `pop` 的总操作数不超过 $2 \times 10^4$
- 调用 `pop` 时保证栈非空

> 💡 两个维度同时最优：**频率最高**、频率并列时**最靠近栈顶**。前者要求能快速定位最大频率，后者要求同频率内按入栈顺序取「最新」。

**示例 1**

解释：

pop()    → 7（5 与 7 都是 2 次，7 更靠近栈顶）
pop()    → 5（此时 5 出现 2 次、7 只剩 1 次，5 频率最高）
pop()    → 4（5、7、4 各 1 次，4 最靠近栈顶）
```

```

## 3. 解题思路

### 3.1 暴力思路

用一个数组/链表模拟栈，`push` 直接追加 $O(1)$；`pop` 时先统计每个值的出现次数，再找出最大频率，然后**从栈顶向下**找到第一个频率等于最大值的元素并删除。单次 `pop` 需要 $O(n)$ 统计 + $O(n)$ 查找，总复杂度 $O(n^2)$；$2\times10^4$ 次操作约 $4\times10^8$，勉强但很危险，且违背了「设计题要 O(1)」的意图。

### 3.2 核心观察：按频率分层，每层都是一个栈

![按频率分层的结构](images/wc99_q4_freq_layers_concept.svg)

注意到「频率」这个维度是**离散且单调**的：一个值每被 `push` 一次，它的频率就 $+1$，于是它从第 $f-1$ 层「升」到第 $f$ 层。我们可以维护：

- `freq[val]`：值 `val` 当前的出现次数；
- `group[f]`：一个**栈**，存放「第 $f$ 次出现」的元素，按入栈时间排序；
- `maxFreq`：当前全局最大频率。

**关键性质**：`group[f]` 的栈顶，恰好是所有「当前频率 $= f$ 且第 $f$ 次出现最晚」的值，也就是频率并列时**最靠近栈顶**的元素。因此 `pop` 只需从 `group[maxFreq]` 弹栈顶即可，$O(1)$。

当 `group[maxFreq]` 被弹空时，说明当前已没有频率为 `maxFreq` 的元素，最大频率整体降为 `maxFreq - 1`。

### 3.3 算法流程

![push / pop 的维护](images/wc99_q4_push_pop_flow.svg)

```text
push(val):
    f = ++freq[val]
    maxFreq = max(maxFreq, f)
    group[f].push(val)            # 第 f 次出现，进入第 f 层栈顶

pop():
    v = group[maxFreq].pop()      # 最高层、最靠栈顶
    freq[v]--
    if group[maxFreq] 为空:
        maxFreq--
    return v
```

### 3.4 示例演算

![示例演算：push 5,7,5,7,4,5 后四次 pop](images/wc99_q4_walkthrough.svg)

按示例 1 的 6 次 `push` 维护分层：

| 操作 | 值 | `freq` | `group[1]` | `group[2]` | `group[3]` | `maxFreq` |
|------|----|--------|------------|------------|------------|-----------|
| push | 5 | 5:1 | [5] | — | — | 1 |
| push | 7 | 7:1 | [5,7] | — | — | 1 |
| push | 5 | 5:2 | [5,7] | [5] | — | 2 |
| push | 7 | 7:2 | [5,7] | [5,7] | — | 2 |
| push | 4 | 4:1 | [5,7,4] | [5,7] | — | 2 |
| push | 5 | 5:3 | [5,7,4] | [5,7] | [5] | 3 |

随后 4 次 `pop`：

| 调用 | 取 | 说明 | 返回 |
|------|-----|------|------|
| pop 1 | `group[3]` 顶 | 5 频率 3 最高 | 5 |
| pop 2 | `group[2]` 顶 | 7 比 5 更靠近栈顶 | 7 |
| pop 3 | `group[2]` 顶 | 5 的第二次出现 | 5 |
| pop 4 | `group[1]` 顶 | 4 是频率 1 中入栈最晚的 | 4 |

输出 `[5,7,5,4]`，与题面一致。

## 4. 算法细节

1. **`group` 用哈希表而非数组**：$f$ 最大等于操作次数（$2\times10^4$），开数组也可以，但用 `unordered_map<int, vector<int>>` 更省内存且无需预估上界。
2. **`maxFreq` 只 ±1**：`push` 最多让它 $+1$，`pop` 最多让它 $-1$，不需要重新扫描所有频率，这是 $O(1)$ 的关键。
3. **`group[f]` 一定是栈而不是集合**：同频率内要「最靠近栈顶」，必须保留入栈顺序；用 `vector` 的 `push_back/pop_back` 即可。
4. **弹出后只减 `freq[v]`**：`v` 的旧副本仍留在 `group[1..f-1]` 中，它们的语义是「第 $k$ 次出现」，与 `freq[v]` 的减少天然对应，不需要移动。
5. **`group[maxFreq]` 为空时立刻降层**：这一步只在弹空时发生一次，均摊 $O(1)$；降层后新的 `maxFreq` 层一定非空（否则继续降——但由于每次 `push` 只 $+1$，实际上只需降一次）。
6. **值域 $10^9$**：必须用哈希表，不能开值域数组。
7. **空栈**：题目保证 `pop` 前栈非空，无需返回哨兵值；若自行加保护，可返回 $-1$。

## 5. 正确性证明

记 $f_v$ 为值 $v$ 的当前出现次数，$\text{last}(v)$ 为 $v$ 最近一次被 `push` 的时刻（全局单调递增的时间戳）。

**引理 1（分层不变式）**：任意时刻，对每个值 $v$，它在 `group[1], \dots, group[f_v]` 中各恰有一个条目；且对任意 $g$，`group[g]` 中的条目按入栈时间递增排列。进一步，`group[g]` 中出现的值集合恰为 $\{v : f_v \ge g\}$。

**证明**：对操作次数归纳。初始为空，成立。`push(v)`：$f_v$ 变为 $f_v+1$，把 $v$ 追加到 `group[f_v]` 末尾，恰好补上「每个 $g \le f_v$ 一个条目」的新要求，且追加在末尾保持时间递增；其他值的条目不变。`pop()`：从 `group[maxFreq]` 弹出栈顶条目（值 $v$，且 $f_v = \text{maxFreq}$，否则由值集合描述它会出现在更高层，矛盾于 `maxFreq` 最大），$f_v$ 减一后它恰好应从 `group[f_v+1]` 中消失，被弹出的正是该条目；其余层不受影响。∎

**引理 2（并列最靠栈顶）**：设 $M = \text{maxFreq}$，则 `group[M]` 的栈顶元素就是「频率等于 $M$ 的值中，$\text{last}(v)$ 最大者」。

**证明**：由引理 1，`group[M]` 含且仅含所有 $f_v \ge M$ 的值，而 $M$ 是最大频率，故恰为 $f_v = M$ 的值；每个这样的值在 `group[M]` 中的条目正是它「第 $M$ 次出现」的时刻，即 $\text{last}(v)$（因为 $f_v = M$ 时最近一次出现就是第 $M$ 次）。`group[M]` 按时间递增排列，故栈顶元素时间戳最大，即最靠近栈顶。∎

**定理**：`pop()` 返回的元素恰好是「频率最高的元素中最接近栈顶者」。

**证明**：由引理 1，`maxFreq` 等于当前所有 $f_v$ 的最大值（每层非空性由值集合描述保证），故 `group[maxFreq]` 非空且其元素频率都等于最大值；由引理 2，其栈顶是其中 $\text{last}$ 最大者，即最接近栈顶。弹出后按流程更新 `freq` 与 `maxFreq`（引理 1 的归纳步骤保证更新正确），不变式继续成立。∎

## 6. 复杂度分析

- **时间**：`push` 为 $O(1)$（哈希表自增 + 一次追加）；`pop` 为 $O(1)$（一次弹栈 + 若干 $O(1)$ 更新）。均摊到每次操作都是常数，总 $O(q)$，$q \le 2\times10^4$。
- **空间**：`freq` 存不同值的计数 $O(d)$；`group` 中每个条目对应一次 `push`，共 $O(q)$；总计 $O(q)$。

## 7. 参考代码

### C++

```cpp
class FreqStack {
    unordered_map<int, int> freq;                 // 值 -> 出现次数
    unordered_map<int, vector<int>> group;        // 频率 -> 该频率的元素栈（按入栈顺序）
    int maxFreq = 0;                              // 当前最大频率

public:
    FreqStack() {}

    void push(int val) {
        int f = ++freq[val];
        maxFreq = max(maxFreq, f);
        group[f].push_back(val);                  // 入栈时立刻放进"新频率"组
    }

    int pop() {
        int val = group[maxFreq].back();          // 频率最高且最靠近栈顶
        group[maxFreq].pop_back();
        freq[val]--;
        if (group[maxFreq].empty()) maxFreq--;    // 该频率层耗尽，整体下降一层
        return val;
    }
};
```

### Python

```python
class FreqStack:
    def __init__(self):
        self.freq = {}                  # 值 -> 出现次数
        self.group = {}                 # 频率 -> 该频率的元素栈（按入栈顺序）
        self.max_freq = 0               # 当前最大频率

    def push(self, val: int) -> None:
        f = self.freq.get(val, 0) + 1
        self.freq[val] = f
        self.max_freq = max(self.max_freq, f)
        self.group.setdefault(f, []).append(val)   # 入栈时立刻放进"新频率"组

    def pop(self) -> int:
        val = self.group[self.max_freq].pop()      # 频率最高且最靠近栈顶
        self.freq[val] -= 1
        if not self.group[self.max_freq]:          # 该频率层耗尽，整体下降一层
            self.max_freq -= 1
        return val
```

## 8. 边界情况与易错点

1. **并列时取「最靠栈顶」而非「最小/最大值」**：必须依赖 `group[f]` 的入栈顺序；若用 `set` 或堆，会丢掉顺序信息。
2. **降层条件**：只在 `group[maxFreq]` **弹空**时才降层；不能每次 `pop` 都降，否则会漏掉同层其他元素。
3. **`maxFreq` 不能重新计算**：每次 `pop` 都重扫所有频率会退化为 $O(n)$，失去设计题意义。
4. **`freq[val]--` 的位置**：先弹出再自减，顺序无关但两个都必须做；漏减会导致后续频率判断错误。
5. **`group` 用哈希而非数组**：值域是 $10^9$，频率上界是操作数，二者性质不同，不要开错维度的大数组。
6. **空栈保护**：题目保证非空；若自己封装，`pop` 空栈时 `group[0]` 不存在会抛异常（Python）或未定义行为（C++），需要额外判断。
7. **重复值的大量 `push`**：如示例 2，`group[f]` 会有很多层，每层只有一个元素；这是正常的，`pop` 逐层下降即可。
8. **不要用「频率 + 全局时间戳」的堆**：优先级是二元组（频率, 时间戳），堆能做到 $O(\log n)$，但本题用分层栈可以做到 $O(1)$，是更优解。
