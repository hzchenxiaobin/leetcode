# LeetCode 连接非零数字并乘以其数字和 I 题解

## 1. 题目概述

- **标题 / 题号**：连接非零数字并乘以其数字和 I（#3754，easy）
- **链接**：https://leetcode.cn/problems/concatenate-non-zero-digits-and-multiply-by-sum-i/
- **来源**：LeetCode 第 477 场周赛 Q1
- **难度**：简单
- **标签**：数学、字符串、模拟

**题意**：给定整数 $n$，把 $n$ 中所有**非零数字**按原始顺序连接成新整数 $x$（不存在非零数字则 $x = 0$）；记 $sum$ 为 $x$ 的**数位和**，返回 $x \times sum$。

**约束**：

- $0 \le n \le 10^9$

> 💡 **审题三件事**：① $sum$ 藏着一条免费捷径——零对数位和**零贡献**，$sum$ 不必等 $x$ 拼好再算，滤零循环里顺手累加即可；② **溢出账**是最隐蔽的坑——$x \le 999999999$ 恰好塞得进 32 位 `int`，但 $x \cdot sum$ 最大约 $8.1 \times 10^{10}$，超 `INT32_MAX` 近 38 倍，官方签名返回 `long long` 正是为此；③ 本题允许 $n = 0$——「不存在非零数字则 $x = 0$」只对 $n = 0$ 生效，字符串解法在这里埋着一颗**空串雷**。另外，本场 Q3（[3756](https://leetcode.cn/problems/concatenate-non-zero-digits-and-multiply-by-sum-ii/)）正是本题的区间查询加强版，Q1 沉淀的两条观察到 Q3 直接复用。

## 2. 示例

**示例 1**

```text
输入：n = 10203004
输出：12340
解释：非零数字是 1、2、3、4，因此 x = 1234；
     数字和 sum = 1 + 2 + 3 + 4 = 10；
     答案 = x * sum = 1234 * 10 = 12340。
```

**示例 2**

```text
输入：n = 1000
输出：1
解释：非零数字只有 1，因此 x = 1 且 sum = 1，答案 = 1 * 1 = 1。
```

**边界示例 3**

```text
输入：n = 0
输出：0
解释：不存在非零数字，x = 0，sum = 0，答案 = 0 * 0 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

签到题。最直觉的三步：转字符串 → 滤掉 `'0'` 拼成 $x$ → 对 $x$ 求数位和 → 相乘：

```python
def sumAndMultiply(n):
    t = str(n).replace('0', '')
    x = int(t or '0')          # n = 0 时 t 是空串，必须兜底！
    return x * sum(map(int, t))
```

这已经是对的、$O(d)$ 的做法（$d$ 为 $n$ 的位数，至多 10）。比赛时写到这里就能 AC，但值得琢磨的是三件事：`or '0'` 兜底**为什么不能省**——$n = 0$ 滤完是空串，`int('')` 直接抛异常；乘法**为什么必须 64 位**——见 3.2 的溢出账；以及能不能**免特判、免二次遍历**，一趟循环同时收齐 $x$ 与 $sum$——这是从「会做」到「理解深」的分水岭。

### 3.2 核心观察：零既不占位、也不进和，一趟收两个量

![核心观察：零划掉压实成 x，零不进和白拿 sum](images/w477_q1_nonzero_concept.svg)

**观察一（$x$ 的构造——Horner 拼接）**：从左到右扫描 $n$ 的数字，遇到非零数字 $d$ 就执行 $x \leftarrow 10x + d$：把已拼好的数整体左移一位，让新数字落入个位。零字符直接跳过——**不乘 10、不追加**。全部扫完，$x$ 恰是非零数字按序连接的结果；一个非零数字都没有时 $x$ 保持 0，**天然无特判**。

**观察二（$sum$ 的免费捷径）**：$x$ 的数位恰好是 $n$ 的全部非零位，而 $0$ 加进数位和等于没加，所以

$$\text{sum}(x) = \sum_{d_i \ne 0} d_i = \text{sum}(n)$$

即 **$sum$ 就是 $n$ 的数位和**——滤零循环里顺手 `sum += d` 即可，不必先拼好 $x$ 再遍历一遍。省掉的不是一轮 10 次的循环，而是「两个量必须分两趟算」的思维定势；它也是本场 Q3 把区间查询摊成 $O(1)$ 的种子。

**观察三（两笔账）**：

- **溢出账**：$n \le 10^9$ 中数字全非零的最大者是 $999999999$（9 位），故 $x \le 999999999$、$sum \le 81$，乘积上界 $999999999 \times 81 = 80\,999\,999\,919 \approx 8.1 \times 10^{10}$，必须 `long long`；而 $x$ 本身塞得进 `int`——**中间量合法、最终乘积爆表**，这个烟雾弹让 `int` 版 `x * sum` 悄悄溢出。
- **边界账**：$n = 0$ 时无非零数字，$x = sum = 0$，答案 0。Horner 循环一次都不更新、天然返回 0；字符串版滤出空串则需兜底。

### 3.3 算法流程

![算法流程：一趟扫描，零走旁路，非零同时更新 x 与 sum](images/w477_q1_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `x = 0, sum = 0` | 空结果天然表示 $x = 0$ |
| ② 取字符 | 遍历 `s = to_string(n)` | 从最高位扫到最低位 |
| ③ 零走旁路 | `c == '0'` 则跳过 | 零既不占位也不进和 |
| ④ 非零更新 | `x = 10*x + d; sum += d`（$d = c - '0'$） | 拼位与求和一趟完成 |
| ⑤ 返回 | `x * sum`（64 位） | C++ 全程 `long long` |

### 3.4 示例演算

![示例演算：n = 10203004 逐字符走查](images/w477_q1_example_walkthrough.svg)

**示例 1**：`n = 10203004`（从左到右逐字符推进）：

| 轮次 | 字符 $c$ | 动作 | `x` | `sum` |
|------|----------|------|-----|-------|
| 1 | 1 | 保留 | 1 | 1 |
| 2 | 0 | 跳过 | 1 | 1 |
| 3 | 2 | 保留 | 12 | 3 |
| 4 | 0 | 跳过 | 12 | 3 |
| 5 | 3 | 保留 | 123 | 6 |
| 6 | 0 | 跳过 | 123 | 6 |
| 7 | 0 | 跳过 | 123 | 6 |
| 8 | 4 | 保留 | **1234** | **10** |

扫完 8 个字符，返回 $1234 \times 10 = 12340$ ✓。注意 $x$ 的生长轨迹 $1 \to 12 \to 123 \to 1234$：每收一个非零数字，旧的 $x$ 整体左移一位、新数字落入个位；`sum` 同步长到 $10 = 1+2+3+4$，恰是 $n$ 的数位和。

**示例 2**：`n = 1000`：仅字符 `'1'` 触发更新（`x = 1, sum = 1`），三个 `'0'` 全走旁路，返回 $1 \times 1 = 1$ ✓。

**边界**：`n = 0`：`to_string(0)` 只含一个 `'0'`，走旁路，返回 $0 \times 0 = 0$ ✓。

## 4. 算法细节

1. **一趟收两量的关键在 `'0'` 分支什么都不做**：不乘 10、不追加、不加和。若把零也统一执行 $x \leftarrow 10x + 0$，数值上等于把 $x$ 白白乘 10——位权没压实，$x$ 恰好原样拼回 $n$，等于什么都没删。
2. **Horner 拼接优于库函数转换**：`x = 10*x + d` 循环结束时若无非零数字则 $x = 0$，天然覆盖题目的特判分支；而 `stoll("")` 抛 `invalid_argument`、Python `int('')` 抛 `ValueError`，用库函数就必须先判空串。
3. **溢出账要算到每一步**：$x \le 999999999 < 2^{31}-1$（注意 $n = 10^9$ 本身是 `1000000000`，只含一个非零数字 1；全非零的最大 $n$ 是 9 位的 $999999999$），$sum \le 9 \times 9 = 81$，乘积上界 $8.1 \times 10^{10}$。C++ 中 `x`、`sum` **从声明起就要 `long long`**——两个 `int` 相乘在最后一步静默溢出（有符号溢出是 UB），且无任何报错。
4. **替代路线（算术剥位版）**：不转字符串，从低位 `n % 10` 剥、`n /= 10` 前进，维护「下一个保留位的位权」`pw`：遇零丢弃、`pw` 不动，遇非零 `x += d * pw` 后 `pw *= 10`。两个版本循环体同构，算术版 $O(1)$ 空间、免字符串分配，且与 Q3 的前缀化推导一脉相承。
5. **Python 免溢出但账要会算**：大整数自动扩位，同样代码直接过；换 C++/Java 就要命——比赛中养成先算上界再选类型的习惯。

## 5. 正确性证明

**引理 1（Horner 拼接正确性）**：设 $n$ 的十进制表示中非零数字从高位到低位依次为 $d_1, d_2, \ldots, d_k$，则算法结束时 $x = \overline{d_1 d_2 \cdots d_k}$（这些数字按序拼接成的整数），$k = 0$ 时 $x = 0$。

**证明**：对已处理的非零数字个数 $j$ 归纳。$j = 0$ 时 $x = 0$，结论平凡。设处理完前 $j-1$ 个非零数字后 $x_{j-1} = \overline{d_1 \cdots d_{j-1}}$。第 $j$ 个非零数字 $d_j$ 到来时执行 $x_j = 10 x_{j-1} + d_j$，由十进制按位展开，$10 \cdot \overline{d_1 \cdots d_{j-1}} + d_j = \overline{d_1 \cdots d_j}$，即旧数整体左移一位、新数字落入个位。字符 `'0'` 不触发任何更新，被原样丢弃；$n = 0$ 时字符串只含一个 `'0'`，$k = 0$，$x = 0$。∎

**引理 2（和的等价性）**：算法结束时 $\text{sum} = \sum_{j=1}^{k} d_j$，且该值同时等于 $x$ 的数位和与 $n$ 的数位和。

**证明**：`sum += d` 仅对非零数字执行，累加结果即 $\sum_j d_j$。由引理 1，$x$ 的十进制表示恰为 $d_1 \cdots d_k$，其数位和为 $\sum_j d_j$；而 $n$ 的数位和 = 非零数字之和 + 零数字的贡献 = $\sum_j d_j + 0$。三者相等。∎

**定理**：算法返回题目所求的 $x \times \text{sum}$。

**证明**：题目定义 $x$ 为非零数字按原始顺序连接的结果（无非零数字则 $x = 0$），$\text{sum}$ 为 $x$ 的数位和。由引理 1、2，循环维护的 $x$、$\text{sum}$ 与题目定义完全一致，故返回值即 $x \times \text{sum}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(d)$，$d$ 为 $n$ 的十进制位数；$n \le 10^9$ 时 $d \le 10$，一趟扫描至多 10 轮。
- **空间复杂度**：$O(d)$，`to_string(n)` 的字符串开销；改用算术剥位版（`n % 10` / `n / 10`）可降到 $O(1)$。
- **对比**：「拼好 $x$ 再二次遍历求和」同为 $O(d)$，一趟版少一轮循环，更重要的是把「零不进和」这条不变量显式化——它是 Q3 中 $sum$ 可以前缀减的地基。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long sumAndMultiply(int n) {
        long long x = 0, sum = 0;
        for (char c : to_string(n)) {
            if (c != '0') {
                x = x * 10 + (c - '0');   // Horner 拼接，空结果天然为 0
                sum += c - '0';            // 一趟顺手收 sum
            }
        }
        return x * sum;
    }
};
```

> 💡 `x`、`sum` **从声明起就是 `long long`**：若图省事写成 `int`，中间全程合法（$x \le 999999999$），偏偏最后一步 `x * sum` 静默溢出——$n = 999999999$ 时返回错误值且无任何报错，全题最阴的坑。

### Python

```python
class Solution:
    def sumAndMultiply(self, n: int) -> int:
        x = s = 0
        for c in str(n):
            if c != '0':
                x = x * 10 + int(c)
                s += int(c)
        return x * s
```

> 💡 比赛速写一行流 `t = str(n).replace('0', ''); return int(t or '0') * sum(map(int, t))` 同样正确，`or '0'` 兜的是 $n = 0$ 的空串；循环版胜在零特判、零雷区，且骨架可直接平移到 C++。

## 8. 边界情况与易错点

1. **乘积溢出（最阴的坑）**：$x \le 999999999$ 恰在 `int` 内，`int` 版 `x * sum` 在 $n = 999999999$ 时溢出（$999999999 \times 81 \approx 8.1 \times 10^{10}$，超 `INT32_MAX` 近 38 倍）且**无任何报错**。C++ 全程 `long long`。
2. **$n = 0$ 的空串雷**：字符串滤零后为空——`int('')` 抛 `ValueError`、`stoll("")` 抛 `invalid_argument`。Horner 循环天然返回 0；一行流必须 `or '0'` 兜底。任何 $n \ge 1$ 的最高位都是 $1 \sim 9$，滤后必非空——这颗雷**只**在 $n = 0$ 踩响，容易漏测。
3. **零不能走 Horner 更新**：若把 `'0'` 也执行 `x = 10*x + 0`，$x$ 会被白白乘 10，恰好拼回 $n$ 本身——位权没压实，等于什么都没删。跳过必须是真的跳过。
4. **$sum$ 的口径**：是 $x$ 的**数位和**，不是 $x$ 的位数、也不是 $n$ 的位数。好在 $\text{sum}(x) = \text{sum}(n)$，从哪个角度理解都收敛到同一趟累加。
5. **$x$ 至多 9 位**：$n \le 10^9$，而 $10^9$ 写作 `1000000000` 只含一个非零数字；全非零的最大 $n$ 是 $999999999$。算溢出账时别把 $x$ 的位数当成 10。
