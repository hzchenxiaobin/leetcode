# LeetCode 有向图中最大颜色值 题解

## 1. 题目概述

- **标题 / 题号**：有向图中最大颜色值（#1857，hard）
- **链接**：https://leetcode.cn/problems/largest-color-value-in-a-directed-graph/
- **来源**：LeetCode 第 240 场周赛 Q4
- **难度**：困难
- **标签**：图、拓扑排序、动态规划、计数、DAG

**题意**：

给定一个含 $n$ 个节点、$m$ 条有向边的**有向图**（不保证无环）。字符串 `colors` 中 `colors[i]` 是节点 $i$ 的颜色（小写字母）；`edges[j] = [a_j, b_j]` 表示有一条有向边 $a_j \to b_j$。一条**有效路径**是点序列 $x_1 \to x_2 \to \dots \to x_k$（相邻两点间有有向边），其**颜色值**是路径中出现次数最多的那种颜色的节点数。求所有有效路径中的**最大颜色值**；**图中有环则返回 $-1$**。

> 💡 一句话审题：在「所有路径」上统计「26 种颜色各自最多能攒多少个」。路径数是指数级的，但计数具有**最优子结构**：以 $v$ 结尾的最优计数可以由前驱的最优计数拼出来，这是典型的 **DAG 上路径 DP**；而「有环返回 $-1$」恰好可以和求拓扑序合并成同一趟 Kahn 扫描。

**约束**：

- $1 \le n \le 10^5$，$0 \le m \le 10^5$
- `colors` 只含小写英文字母
- $0 \le a_j, b_j < n$（**不保证无自环、无重边**）

## 2. 示例

**示例 1**（官方示例 1）

```text
输入：colors = "abaca", edges = [[0,1],[0,2],[2,3],[3,4]]
输出：3
解释：路径 0 → 2 → 3 → 4 上有 3 个颜色为 "a" 的节点（节点 0、2、4）。
```

**示例 2**（官方示例 2：自环）

```text
输入：colors = "a", edges = [[0,0]]
输出：-1
解释：节点 0 到自己有一条边，构成环。
```

**示例 3**（补充：无边退化）

```text
输入：colors = "abc", edges = []
输出：1
解释：没有任何边时，每个节点自成一条路径，最大颜色值为 1。
```

**示例 4**（补充：换色陷阱）

```text
输入：colors = "abb", edges = [[0,1],[1,2]]
输出：2
解释：路径 0 → 1 → 2 上 "b" 出现 2 次（节点 1、2）。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有路径

从每个节点出发 DFS 枚举全部路径，逐条统计 26 色频次取最大。两条死路：

- **路径数指数级**：$k$ 级「二选一」并联的钻石链拥有 $2^k$ 条路径，节点数 $n \approx 2k$ 时路径数达 $\Theta(2^{n/2})$，$n = 10^5$ 完全不可枚举；
- **有环直接死循环**：环上可以绕任意多圈，枚举根本停不下来。

> ⚠️ 瓶颈的根源：把「统计」绑定在「每条路径」上。实际上以 $v$ 结尾的众多路径共享大量前缀，**「以 $v$ 结尾、颜色 $c$ 的最大计数」才是不重复的子问题**——这是换 DP 视角的第一信号。

### 3.2 核心观察：拓扑序 + 每节点 26 维颜色计数 DP

![核心观察：每个节点携带 26 维颜色计数向量，沿拓扑序传播](images/wc240_q4_color_dp_concept.svg)

定义 $M(v, c)$ = **以 $v$ 结尾的所有路径中，颜色 $c$ 出现次数的最大值**。任何路径都以某个节点结尾，所以答案就是 $\max_{v,c} M(v,c)$。

**最优子结构**：以 $v$ 结尾的路径要么是单点 $[v]$，要么是「一条以前驱 $p$ 结尾的路径，再走一步边 $p \to v$」。后者的 $c$ 计数 $= \mathrm{cnt}_c(\text{前段}) + [\mathrm{col}(v) = c] \le M(p, c) + [\mathrm{col}(v) = c]$。两情形合并取最大：

$$M(v, c) \;=\; \big[\mathrm{col}(v) = c\big] \;+\; \max\Big(0,\ \max_{p \to v} M(p, c)\Big)$$

依赖方向是「前驱 → 后继」，恰好是**拓扑序**——按拓扑序逐点计算，每个 $M(v,c)$ 只算一次。状态是 26 维向量 `dp[v][0..25]`，转移是逐维取 max 再加自身色。

> ⚠️ **为什么必须带全 26 维，不能只记「当前最大色」？** 最大色会随路径延伸「换人」：`colors = "abb"`、链 $0 \to 1 \to 2$，节点 1 处 $\{a{:}1,\ b{:}1\}$ 并列最大；若贪图省事只留 $a{:}1$ 丢掉 $b{:}1$，节点 2 只能算出 $b{:}1$，而真实答案 $b{:}2$（见插图下方反例）。**没当过第一名的颜色也可能在后半程反超**，26 维计数必须整体随路径传播。

> 💡 **判环与 DP 一趟完成**：$M$ 的递推只在拓扑序下成立；反过来，Kahn 算法剥零入度点的过程中，环上节点的入度永远降不到 0（环内边互相支撑），出队计数 `processed < n` 即有环——求拓扑序、判环、DP 三件事共用同一趟 BFS。

### 3.3 算法流程：Kahn 一趟两得

![算法流程：Kahn 建图入队出队传播，一趟完成判环与 DP](images/wc240_q4_kahn_flow.svg)

1. **建图**：邻接表 `adj[u]` 存后继，`indeg[v]` 统计前驱数，$O(n+m)$。
2. **初始化**：`dp[v][0..25]` 全 0；**所有** `indeg[v] == 0` 的源点入队——图可不连通，漏掉任何源点都会把无环图误判成有环。
3. **出队 $u$**：`processed += 1`。此刻 $u$ 的全部前驱都已出队并传播完毕，`dp[u]` 已收齐前驱信息。
4. **加自身色**：`dp[u][colors[u]] += 1`。
5. **更新答案**：`ans = max(ans, max(dp[u]))`。
6. **传播**：对每个后继 $v$，逐维 `dp[v][c] = max(dp[v][c], dp[u][c])`（$c = 0..25$）；`indeg[v] -= 1`，减到 0 则 $v$ 入队。
7. **收尾**：队列空后，`processed < n` 返回 $-1$（有环），否则返回 `ans`。

关键机制：**入度归零 ⇔ 前驱全部传完 ⇔ `dp[v]` 冻结**，出队时再加上自身色即为终态——此后 $u$ 只会去写别人的 `dp`，自身不再变化。

### 3.4 示例演算

![示例 1 演算：Kahn 出队逐步传播 26 维计数](images/wc240_q4_walkthrough.svg)

以示例 1 为例（完整表格见插图）：初始 `indeg = [0,1,1,1,1]`，队列 `[0]`。步 ③ 节点 2（颜色 a）继承源点 0 传来的 `{a:1}`，加自身 a 得 `{a:2}`；步 ⑤ 节点 4 得到 `{a:3, c:1}`，全局答案 3。`processed = 5 = n`，无环，返回 3。

> ⚠️ `ans` 在每个节点**出队加完自身色后**立刻用 `max(dp[u])` 刷新：节点 1 出队时最大值只有 1 不碍事，后来者（节点 4）会再次刷新；有环时 `ans` 中途的值没有意义，但最终被 $-1$ 短路，不会被读到。

## 4. 算法细节

1. **邻接方向**：存「前驱 → 后继」。若存反向（后继 → 前驱）则要配记忆化 DFS，递归深度可达链长 $10^5$，Python 默认递归上限 1000 必崩（见 §8 第 8 条）。
2. **出队时做三件事**：加自身色、更新 `ans`、传播后继。三件事都依赖「前驱已全部传完」这一前提，而 Kahn 的入度归零恰好保证它——把三件事全部放在出队时刻，逻辑最内聚。
3. **传播是逐维取 max，不是覆盖**：节点 $v$ 可能有多个前驱，各前驱对不同颜色各有所长（A 路径 a 多、B 路径 b 多），必须逐维取 max；$v$ 等自己的入度归零后，`dp[v]` 才聚合了所有前驱的最优。
4. **判环零成本**：一个 `processed` 计数即可，不必显式找出环的位置。自环 `[[0,0]]` 使 `indeg[0] = 1`，初始队列为空，`processed = 0 < 1` 自动返回 $-1$。
5. **重边无害**：`edges` 未保证互不相同。重复边 $u \to v$ 让 `indeg[v]` 多计一次，但 $u$ 出队时也会多传播一次，一加一减恰好抵消，结果不变（C++ 极端用例已实测，见 §7）。
6. **内存与值域**：`dp` 共 $26n$ 个 int，$n = 10^5$ 时约 10 MB（C++ `vector<array<int,26>>`），顺序扫描下毫无压力；单维计数 $\le n = 10^5$，`int` 无溢出风险。
7. **Python 提速**：把 `dp[u]`、`dp[v]` 提为局部引用再跑内层 26 循环，`colors[u]` 的下标出队时只算一次。实测 $n, m = 10^5$ 规模轻松通过。

## 5. 正确性证明

**引理 1（入队条件与冻结）**：Kahn 过程中，节点 $v$ 入队当且仅当其全部前驱都已出队并完成传播；$v$ 出队处理前，`dp[v]` 逐维等于 $\max\big(0,\ \max_{p \to v} \text{dp}[p]\big)$，且此后不再被修改。

**证明**：`indeg[v]` 初值为前驱数，每个前驱 $p$ 出队时恰传播一次并使 `indeg[v]` 减 1，故归零 ⇔ 全部前驱已传播 ⇔ $v$ 入队。此后能写 `dp[v]` 的只有前驱（传播语句），而它们都已处理完，故 `dp[v]` 冻结。∎

**引理 2（DP 值 = 定义值）**：节点 $u$ 出队、加完自身色后，对所有 $c$ 有 $\text{dp}[u][c] = M(u, c)$。

**证明**：出队序列构成拓扑序（前驱总在后继之前出队），对出队序归纳：处理 $u$ 时其全部前驱已加过自身色，由归纳假设其 dp 值等于各 $M(p, c)$。结合引理 1：

$$\text{dp}[u][c] \;=\; \big[\mathrm{col}(u) = c\big] + \max\Big(0,\ \max_{p \to u} M(p, c)\Big)$$

另一方面，以 $u$ 结尾的路径全体 = 单点路径 $[u]$（$c$ 计数为 $[\mathrm{col}(u)=c]$）∪ { $P' + u$ : $P'$ 以某个前驱 $p$ 结尾 }，后者的 $c$ 计数 $= \mathrm{cnt}_c(P') + [\mathrm{col}(u)=c] \le M(p,c) + [\mathrm{col}(u)=c]$，且对每个 $p$ 取 $P'$ 为达到 $M(p,c)$ 的路径时取等。两情形合并取最大，恰为上式右端。∎

**定理 1（无环时正确）**：图无环时，算法返回 $\displaystyle\max_{v,\,c} M(v, c)$，即全图最大颜色值。

**证明**：DAG 中恒存在入度 0 的节点（否则从任一点沿入边回走 $n+1$ 步，由抽屉原理必重复成环）；出队一个源点后剩余图仍是 DAG，归纳知全部节点终将出队，`processed = n`。由引理 2，每次出队时 `ans ← max(ans, max(dp[u]))` 把全体 $M(u,c)$ 纳入比较，故 `ans = max M`。而任一路径按其结尾节点 $v$ 分类，其颜色值 $\le \max_c M(v,c)$；反之每个 $M(v,c)$ 都被某条真实路径达到（$M$ 是非空有限集上的最大值，单点路径保证集合非空）。故 $\max M$ 恰为所求。∎

**定理 2（判环正确）**：算法返回 $-1$ 当且仅当图中有环（含自环）。

**证明**：（有环 ⇒ `processed < n`）设 $C$ 是一个环。$C$ 上每个节点有一条入边来自环内前驱，该入边只有环内前驱出队时才被删除。反设 $C$ 中某节点最先出队，此刻其环内入边尚未删除、入度 $\ge 1$，与「入度归零才入队」矛盾。故 $C$ 上节点永不出队，`processed < n`，返回 $-1$。（无环 ⇒ `processed = n`）见定理 1 中的归纳。∎

> 💡 有环时 `dp` 可能已被环外节点更新出「看似合法」的值，但返回值被 $-1$ 短路，不受污染——这是把判环放在**最后统一裁决**而不是边跑边判的好处。

## 6. 复杂度分析

- **时间复杂度**：$O\big(26\,(n+m)\big) = O(n+m)$。建图 $O(n+m)$；每个节点进出队各一次，出队时加自身色 $O(1)$、更新答案 $\le 26$ 次比较；每条边恰传播一次、每次 26 维。$n, m \le 10^5$，总量约 $5 \times 10^6$ 次整数操作，远在时限内。
- **空间复杂度**：$O(26n + n + m)$。`dp` 占 $26n$；邻接表 $n + m$；入度数组与队列各 $O(n)$。C++ 实现约 10 MB。
- **关于 26**：它是字母表大小 $|\Sigma|$，与输入规模无关，渐近意义下是常数。若颜色扩展为任意字符集，复杂度变为 $O\big((n+m)\,|\Sigma|\big)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int largestPathValue(string colors, vector<vector<int>>& edges) {
        int n = colors.size();
        vector<vector<int>> adj(n);
        vector<int> indeg(n, 0);
        for (const auto& e : edges) {
            adj[e[0]].push_back(e[1]);
            ++indeg[e[1]];
        }

        vector<array<int, 26>> dp(n);            // 每节点 26 维计数，默认全 0
        queue<int> q;
        for (int i = 0; i < n; ++i)
            if (indeg[i] == 0) q.push(i);        // 全部源点入队（图可不连通）

        int processed = 0, ans = 0;
        while (!q.empty()) {
            int u = q.front(); q.pop();
            ++processed;
            ++dp[u][colors[u] - 'a'];            // 出队时才加自身色
            for (int c = 0; c < 26; ++c)
                ans = max(ans, dp[u][c]);
            for (int v : adj[u]) {
                for (int c = 0; c < 26; ++c)     // 26 维逐维传播
                    dp[v][c] = max(dp[v][c], dp[u][c]);
                if (--indeg[v] == 0) q.push(v);
            }
        }
        return processed < n ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def largestPathValue(self, colors: str, edges: List[List[int]]) -> int:
        n = len(colors)
        adj = [[] for _ in range(n)]
        indeg = [0] * n
        for u, v in edges:
            adj[u].append(v)
            indeg[v] += 1

        dp = [[0] * 26 for _ in range(n)]        # 每节点 26 维计数
        q = deque(i for i in range(n) if indeg[i] == 0)
        processed, ans = 0, 0

        while q:
            u = q.popleft()
            processed += 1
            du = dp[u]
            du[ord(colors[u]) - 97] += 1         # 出队时才加自身色
            ans = max(ans, max(du))
            for v in adj[u]:
                dv = dp[v]
                for c in range(26):              # 26 维逐维传播
                    if du[c] > dv[c]:
                        dv[c] = du[c]
                indeg[v] -= 1
                if indeg[v] == 0:
                    q.append(v)

        return -1 if processed < n else ans
```

> 💡 两份实现均已验证：官方示例 1 / 2、无边退化（`"abc"`, `[]` → 1）、换色陷阱（`"abb"` → 2）、三点大环（→ $-1$）全部通过；另与「枚举全部路径取最大颜色计数」的暴力在 3000 张随机图（$n \le 7$，含环 / 自环 / 重边）上逐一对拍一致；C++ 版另通过 $n = 10^5$ 全 `a` 链 + 全部重边复制的极端用例（答案恰 $10^5$，重边不干扰）。

## 8. 边界情况与易错点

1. **只记「当前最大色」（头号坑）**：26 维砍成一维，换色场景立刻翻车（§3.2 的 `"abb"` 反例）。识别信号：题目问「最多颜色的个数」≠「某个固定颜色的个数」——第一名会换人，榜单要全带。
2. **加自身色的时机**：必须在「前驱全部传完」之后（Kahn 出队时刻）再加。若在入队甚至建图时加，多前驱节点会把没收齐的状态定格，后续传播全错。
3. **多源点漏入队**：图不连通时入度 0 的节点不止一个，必须全部入队；漏一个就会 `processed < n`，把无环图误判成有环返回 $-1$。
4. **判环判据用 `processed` 计数**：不要用「DFS 访问到已访问节点」判有向图的环——那是无向图的套路；有向图需要三色标记（灰 = 在递归栈上）才可靠，而 Kahn 里 `processed < n` 一个计数就够。
5. **自环无需特判**：`[[0,0]]` 就是「环内前驱是自己」的最简环，入度永不归零，自动走到 $-1$ 分支。
6. **重边**：不保证互不相同，但入度多计一次、传播多做一次，效果抵消，无需去重。
7. **`ans` 初值 0 是安全的**：无环时每个节点都出队，单点路径颜色值 $\ge 1$，`ans` 必然被抬到 $\ge 1$；有环时直接 $-1$，`ans` 的中间值不被使用。
8. **别用 DFS + 记忆化硬闯**：链长 $10^5$ 的递归深度在 Python（默认上限 1000）必爆、C++ 也有爆栈风险；且判环要三色标记，时序远不如 Kahn 直观。
9. **溢出核算**：单维计数 $\le n = 10^5$，`int` 绰绰有余；真正要留意的是 `dp` 的内存（$26n$ 个 int ≈ 10 MB），别再叠加无谓的 $O(n^2)$ 结构。

**延伸思考**：

1. **环不再判死，而是允许计数**：若把「路径」放宽为「可行走的通道（walk）」，环上节点可全部收编——Tarjan 缩点后每个 SCC 内部各色计数取全集，再在缩点 DAG 上做同样的 26 维 DP。本题的 $-1$ 分支就是这个变体的「直接弃疗」版。
2. **输出取得最大颜色值的具体路径**：传播时逐维记录 argmax 前驱，结束时从取得全局 max 的 $(v, c)$ 回溯，即得一条具体的最优路径。
3. **字母表变大**：颜色改为任意字符集时复杂度为 $O\big((n+m)\,|\Sigma|\big)$；$|\Sigma|$ 很大时可改用哈希表只存出现过的颜色，稀疏时更省。
4. **图保证无环时**：可省去 `processed` 计数；但保留它没有任何额外开销，判环健壮性白拿。
