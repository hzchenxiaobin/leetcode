# LeetCode 子数组最小乘积的最大值 题解

## 1. 题目概述

- **标题 / 题号**：子数组最小乘积的最大值（#1856，medium）
- **链接**：https://leetcode.cn/problems/maximum-subarray-min-product/
- **来源**：LeetCode 第 240 场周赛 Q3
- **难度**：中等
- **标签**：单调栈、数组、前缀和、笛卡尔树

**题意**：

一个数组的**最小乘积**定义为：数组中**最小值 × 数组的和**。例如 `[3,2,5]` 的最小值是 2，和是 10，最小乘积为 $2 \times 10 = 20$。给定正整数数组 `nums`，返回其**任意非空子数组**的最小乘积的**最大值**。由于答案可能很大，返回对 $10^9 + 7$ 取余的结果。

两个关键细节：

1. 最小乘积的最大值考虑的是**取余之前**的结果——先在原始值域上取 max，最后一步才取模；
2. 题目保证取余前的最大值可以用 **64 位有符号整数**存下。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^7$（**全为正整数**，是解题的关键前提）

> 💡 **一句话审题**：「任意子数组」+「最小值参与运算」是**贡献法**的经典信号——与其枚举 $O(n^2)$ 个子数组，不如换视角：**枚举每个元素当最小值**，问「以它为最小值的子数组中，哪个最优」。再配上「取余前比较、最后取模」，就是完整的审题。

## 2. 示例

输出：14
解释：最优子数组是 [2,3,2]（最小值 2），
最小乘积 = 2 * (2+3+2) = 2 * 7 = 14。
```

最小乘积 = 3 * (3+3) = 3 * 6 = 18。
```

```text
输入：nums = [3,1,5,6,4,2]
输出：60
解释：最优子数组是 [5,6,4]（最小值 4），
最小乘积 = 4 * (5+6+4) = 4 * 15 = 60。
```

两个相等的最小值由谁「接管」这个子数组，正是本题最容易写错的地方（见 §8 第 2 条）。

## 3. 解题思路

### 3.1 暴力思路：枚举全部子数组

枚举每个左端点 $l$，向右扩张右端点 $r$，过程中同步维护当前区间的最小值 $\text{mn}$ 与和 $s$（均为增量更新，$O(1)$），每步用 $\text{mn} \times s$ 刷新答案。

- 时间 $O(n^2)$、空间 $O(1)$：$n = 10^5$ 时约 $5 \times 10^9$ 次运算，远超时限；
- 但暴力给出了正确的搜索空间，且暗含一个重要结构：**固定左端点向右扩张时，min 单调不增、sum 单调不减**。乘积在「min 尚未跌落」的扩张段里只会变大——这提示最优子数组在「min 不变」的意义下应当**扩到不能再扩**。

> ⚠️ 瓶颈的根源：把枚举对象绑定在「子数组」上（$O(n^2)$ 个）。而最小乘积由**最小值**主导，每个子数组都唯一对应「它的最小值」——把枚举对象换成**最小值的出现位置**（只有 $n$ 个），搜索空间立刻塌缩到线性。

### 3.2 核心观察：每个元素当一次「最小值」，配一个极大窗口

![核心观察：固定最小值位置 i，最优子数组是向两侧扩张到极限的极大窗口](images/wc240_q3_minproduct_concept.svg)

对每个下标 $i$，问：**如果子数组的最小值恰好由 $\text{nums}[i]$ 决定**，最优子数组是哪个？

**扩张只会更好**：只要新扩入的元素 $\ge \text{nums}[i]$，区间最小值不变，而**正整数**数组的区间和严格变大，乘积 $=$ min $\times$ sum 随之变大。因此最优子数组一定是**极大窗口**——向两侧扩张到再扩一格就会破坏「$\text{nums}[i]$ 是最小值」为止：

- **左边界 $L_i$**：$i$ 左侧第一个**严格小于** $\text{nums}[i]$ 的下标（不存在则 $-1$）；
- **右边界 $R_i$**：$i$ 右侧第一个**小于等于** $\text{nums}[i]$ 的下标（不存在则 $n$）；
- 极大窗口 $W_i = [L_i + 1,\ R_i - 1]$（必含 $i$，非空）。

于是每个 $i$ 贡献一个候选值，用前缀和 $O(1)$ 算区间和：

$$\text{cand}(i) \;=\; \text{nums}[i] \times \Big(\text{pre}[R_i] - \text{pre}[L_i + 1]\Big)$$

答案就是 $\max_i \text{cand}(i)$（取模前）。

> ⚠️ **两侧边界为何不对称（左严格、右非严格）？** 全是处理**重复元素**的讲究。以 `[2,2]` 为例：右边界用「$\le$」，下标 0 的窗口被右侧相等的 2 截断为 `[2]`（候选 4），下标 1 的窗口是整个数组（候选 8）——**相等的最小值由最右出现接管整个区间**，每个子数组恰好被覆盖一次。若两侧都用「$\le$」，两个 2 的窗口都只剩自己，答案错误地变成 4；若两侧都用「$<$」，同一个子数组会被重复覆盖，对取 max 无害（详见 §5 的证明与 §8 的坑点对照）。

### 3.3 算法流程：两趟单调栈 + 一趟前缀和 + 一趟统计

![算法流程：前缀和、正向反向两趟单调栈求边界、逐 i 统计候选、最后取模](images/wc240_q3_minproduct_flow.svg)

1. **前缀和**：$\text{pre}[j] = \sum_{k < j} \text{nums}[k]$，$\text{pre}[0] = 0$，使任意区间和化为两次查询相减。
2. **正向单调栈**（$i$ 从左到右）：维护**值严格递增**的下标栈。弹掉所有栈顶值 $\ge \text{nums}[i]$ 的下标后，栈顶即 $L_i$（栈空则 $-1$），再把 $i$ 入栈。
3. **反向单调栈**（$i$ 从右到左）：弹掉所有栈顶值 $> \text{nums}[i]$ 的下标后，栈顶即 $R_i$（栈空则 $n$），再把 $i$ 入栈。
4. **统计**：$\text{ans} = \max_i \text{nums}[i] \times (\text{pre}[R_i] - \text{pre}[L_i + 1])$。
5. **收尾**：返回 $\text{ans} \bmod (10^9 + 7)$。

关键机制：单调栈每步「弹出即淘汰」——被弹出的下标**永远不会成为后续任何 $i$ 的边界**（它比当前元素大或相等，挡在中间必然先被弹掉），因此每个下标进出栈各一次，总代价均摊 $O(1)$。

### 3.4 示例演算

![示例 1 演算：逐个 i 求左右边界与极大窗口，统计候选取最大](images/wc240_q3_minproduct_walkthrough.svg)

以示例 1 `nums = [1,2,3,2]` 为例（完整表格见插图），前缀和 $\text{pre} = [0,1,3,6,8]$：

| $i$ | $\text{nums}[i]$ | $L_i$ | $R_i$ | 窗口 $W_i$ | 区间和 | 候选值 |
|---|---|---|---|---|---|---|
| 0 | 1 | $-1$ | $4$ | $[0,3]$ | $8$ | $1 \times 8 = 8$ |
| 1 | 2 | $0$ | $3$ | $[1,2]$ | $5$ | $2 \times 5 = 10$ |
| 2 | 3 | $1$ | $3$ | $[2,2]$ | $3$ | $3 \times 3 = 9$ |
| 3 | 2 | $0$ | $4$ | $[1,3]$ | $7$ | $2 \times 7 = \mathbf{14}$ |

两个值为 2 的元素中，$i = 1$ 的窗口被右侧相等的 $i=3$ 截断为 $[1,2]$；$i = 3$ 作为**最右出现**接管了完整的 $[1,3]$，贡献最大候选 14。最小值 1 虽然拥有最长的窗口 $[0,3]$，但乘积只有 8——「窗口长」不等于「乘积大」，必须逐个比较。

> 💡 也可用**一次遍历**完成：从左到右维护单调栈，当 $\text{nums}[i]$ 把栈顶 $j$ 弹出时，$j$ 的右边界即 $i$、左边界即弹出 $j$ 后的新栈顶——边界在弹出时刻「定格」。本文选两趟写法，边界定义与 §3.2 一一对应，更不易写错。

## 4. 算法细节

1. **边界定义必须配套**：左严格小（弹栈条件 $\ge$）对应 $L_i$，右小于等于（弹栈条件 $>$）对应 $R_i$。两趟弹栈条件恰好互为镜像的严格/非严格，写反一处就会串味（§8 第 7 条）。
2. **前缀和下标约定**：$\text{pre}[j]$ 存前 $j$ 个元素之和，则 $\sum_{l \le k \le r} = \text{pre}[r+1] - \text{pre}[l]$；代入窗口 $[L_i+1, R_i-1]$ 得 $\text{pre}[R_i] - \text{pre}[L_i+1]$，边界 $-1$ / $n$ 无需特判，自动落在合法下标 $0$ / $n$ 上。
3. **取模时机**：全程用原始 64 位值比较，**最后一步**才 `ans % MOD`。中途取模会把大小关系打乱（模后小的可能原本大）。
4. **溢出核算**：区间和至多 $10^5 \times 10^7 = 10^{12}$，`long long` 安全；乘积理论上界 $10^{19}$ 超出 `int64`，但每个候选值都是**真实子数组的最小乘积**，都被题目「最大值 64 位可存」的保证覆盖，故 `long long` 全程安全；Python 原生大整数则完全无此顾虑。
5. **哨兵写法**（备选）：在数组两端拼接 $-\infty$ 哨兵可把「栈空」分支消掉；本文直接用 $-1$ / $n$ 哨兵值配前缀和，效果相同。
6. **正整数前提**：固定 min 后「窗口越大乘积越大」依赖**元素为正**（sum 严格随扩张不减）。若允许负数，sum 可能随扩张变小、乘积反而增大，极大窗口不再必然最优（见延伸思考 1）。
7. **Python 提速**：三趟循环全部用局部变量（`pre`、`left`、`right`、`nums`），弹栈用 `while st and nums[st[-1]] >= x` 短路写法；$n = 10^5$ 规模毫无压力。

## 5. 正确性证明

**引理 1（候选可达）**：对每个 $i$，窗口 $W_i = [L_i+1,\ R_i-1]$ 非空，且 $\min(W_i) = \text{nums}[i]$；从而 $\text{cand}(i)$ 是子数组 $W_i$ 的最小乘积。

**证明**：$i \in W_i$，非空。若 $j \in (L_i, i)$ 且 $\text{nums}[j] < \text{nums}[i]$，则 $j$ 是比 $L_i$ 更近的「左侧严格小」，与 $L_i$ 的定义矛盾，故 $(L_i, i)$ 内元素全 $\ge \text{nums}[i]$；若 $j \in (i, R_i)$ 且 $\text{nums}[j] \le \text{nums}[i]$，与 $R_i$ 是右侧第一个「$\le$」矛盾，故 $(i, R_i)$ 内元素全 $> \text{nums}[i]$。两段拼起来：$W_i$ 内元素全 $\ge \text{nums}[i]$ 且至少含 $\text{nums}[i]$ 本身，故 $\min(W_i) = \text{nums}[i]$，$\text{cand}(i) = \text{nums}[i] \times \text{sum}(W_i)$ 恰为 $W_i$ 的最小乘积。∎

**引理 2（覆盖性）**：任取非空子数组 $[a, b]$，设 $m = \min([a,b])$，$i$ 为 $m$ 在 $[a,b]$ 中的**最右出现位置**。则 $[a,b] \subseteq W_i$，且 $\text{minprod}([a,b]) \le \text{cand}(i)$。

**证明**：$[a,b]$ 内元素全 $\ge m = \text{nums}[i]$。**左侧**：反设 $L_i \ge a$，则 $L_i \in [a, i)$ 且 $\text{nums}[L_i] < m$，与 $[a,b]$ 最小值为 $m$ 矛盾，故 $L_i < a$，即 $a \ge L_i + 1$。**右侧**：反设 $R_i \le b$，则 $R_i \in (i, b]$ 且 $\text{nums}[R_i] \le m$；但 $i$ 已是 $m$ 在 $[a,b]$ 中的最右出现，$(i, b]$ 内元素应全 $> m$，矛盾，故 $R_i > b$，即 $b \le R_i - 1$。于是 $[a,b] \subseteq W_i$；元素全为正整数，故 $\text{sum}([a,b]) \le \text{sum}(W_i)$，从而

$$\text{minprod}([a,b]) = m \times \text{sum}([a,b]) \;\le\; \text{nums}[i] \times \text{sum}(W_i) = \text{cand}(i). \quad \blacksquare$$

**定理（算法正确）**：$\displaystyle\max_{0 \le i < n} \text{cand}(i)$ 等于所有非空子数组最小乘积的最大值（取模前）。

**证明**：一方面，每个 $\text{cand}(i)$ 都是某个真实子数组的最小乘积（引理 1），故 $\max_i \text{cand}(i)$ 不超过全局最大值。另一方面，任意子数组的最小乘积都被某个候选值超过（引理 2），故全局最大值不超过 $\max_i \text{cand}(i)$。两向夹逼即得相等；最后对最大值取模输出。∎

> 💡 证明里「最右出现」与「右边界取 $\le$」是**配套选择**：右边界非严格才能把 $(i, b]$ 中潜在的等值元素挡在 $R_i$ 之外，覆盖性才成立。若两侧都取严格小，引理 2 改取「任一出现位置」仍可证（子数组会被多个候选重复覆盖），max 不受影响——所以两侧严格小是**安全的等价写法**；而两侧都取 $\le$ 则覆盖性失效，是真 bug。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。前缀和一趟；两趟单调栈中每个下标至多入栈、出栈各一次（总弹出次数 $\le$ 总入栈次数 $= n$），均摊每步 $O(1)$；统计一趟。$n = 10^5$ 时总操作量约 $5 \times 10^5$ 次整数运算。
- **空间复杂度**：$O(n)$。前缀和数组 $n+1$、左右边界数组各 $n$、单调栈最坏 $n$（数组严格递增时）。C++ 下约 3 MB。
- **与暴力对比**：搜索对象从「子数组」（$O(n^2)$ 个）换为「最小值出现位置」（$n$ 个），每个对象的窗口边界由单调栈均摊 $O(1)$ 求出——这是贡献法题的标准复杂度画像。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxSumMinProduct(vector<int>& nums) {
        const long long MOD = 1e9 + 7;
        int n = nums.size();
        vector<long long> pre(n + 1, 0);
        for (int i = 0; i < n; ++i) pre[i + 1] = pre[i] + nums[i];

        vector<int> left(n, -1), right(n, n);
        stack<int> st;
        for (int i = 0; i < n; ++i) {                 // 左侧第一个严格小于
            while (!st.empty() && nums[st.top()] >= nums[i]) st.pop();
            left[i] = st.empty() ? -1 : st.top();
            st.push(i);
        }
        st = stack<int>();
        for (int i = n - 1; i >= 0; --i) {            // 右侧第一个小于等于
            while (!st.empty() && nums[st.top()] > nums[i]) st.pop();
            right[i] = st.empty() ? n : st.top();
            st.push(i);
        }

        long long ans = 0;
        for (int i = 0; i < n; ++i)
            ans = max(ans, (long long)nums[i] * (pre[right[i]] - pre[left[i] + 1]));
        return ans % MOD;                             // 先取 max 后取模
    }
};
```

### Python

```python
class Solution:
    def maxSumMinProduct(self, nums: List[int]) -> int:
        MOD = 10 ** 9 + 7
        n = len(nums)
        pre = [0] * (n + 1)
        for i, x in enumerate(nums):
            pre[i + 1] = pre[i] + x

        left = [-1] * n
        st = []
        for i, x in enumerate(nums):              # 左侧第一个严格小于
            while st and nums[st[-1]] >= x:
                st.pop()
            left[i] = st[-1] if st else -1
            st.append(i)

        right = [n] * n
        st = []
        for i in range(n - 1, -1, -1):            # 右侧第一个小于等于
            x = nums[i]
            while st and nums[st[-1]] > x:
                st.pop()
            right[i] = st[-1] if st else n
            st.append(i)

        ans = 0
        for i, x in enumerate(nums):
            cand = x * (pre[right[i]] - pre[left[i] + 1])
            if cand > ans:
                ans = cand
        return ans % MOD                          # 先取 max 后取模
```

> 💡 两份实现均已验证：官方示例 1 / 2 / 3、重复元素（`[2,2]` → 8、`[2,2,3]` → 14）、单元素（`[7]` → 49）全部通过；另与「枚举全部子数组」的 $O(n^2)$ 暴力在 3000 组随机数组（$n \le 12$，含大量重复值）上逐一对拍一致。

## 8. 边界情况与易错点

1. **取模时机（头号坑）**：中途对候选值取模再比较，会把大小关系彻底打乱。正确姿势：全程 64 位（Python 大整数）裸值比较，`return ans % MOD` 收尾。
2. **重复元素的边界不对称（次号坑）**：右侧必须用「$\le$」（或两侧都用「$<$」）。两侧都用「$\le$」时 `[2,2]` 的两个候选窗口都只剩单元素，答案错成 4 而非 8。识别信号：凡是「以 $i$ 为最小值」的题，写边界前先拿 `[2,2]` 手推一遍。
3. **栈空即边界哨兵**：`left[i] = -1`、`right[i] = n`，配合前缀和公式 $\text{pre}[R_i] - \text{pre}[L_i+1]$ 自动归位（$-1+1=0$、$R_i=n$ 都是 `pre` 的合法下标），不要额外 if 特判，反而易错。
4. **$n = 1$**：唯一候选 $W_0 = [0,0]$，返回 $\text{nums}[0]^2 \bmod \text{MOD}$（如 `[7]` → 49）。
5. **全相同元素**：`[5,5,5]` 中最右一个 5 接管全数组，答案 $5 \times 15 = 75$——验证边界实现是否正确的最小用例。
6. **溢出**：`pre` 必须 `long long`（最大 $10^{12}$）；乘积由题面保证 64 位可存。C++ 中 `nums[i] * (...)` 记得至少一侧转 `long long`。
7. **弹栈条件与边界定义写反**：正向栈弹「$\ge$」求严格小边界、反向栈弹「$>$」求非严格边界，两处条件互换是差一个等号的隐性 bug，肉眼难查——建议写完立刻用 `[2,2]`、`[2,3,3,1,2]` 两个用例自测（后者含 `3,3` 相邻重复与截断）。
8. **「窗口最长」不等于「乘积最大」**：示例 1 中最小值 1 的窗口最长（候选 8），最优却是最小值 2 的窗口（候选 14）。逐个 $i$ 比较不可省略，不能只看全局最小值或贪单个指标。

**延伸思考**：

1. **若数组含负数**：固定 min 后区间和不再随扩张单调不减，「极大窗口最优」失效，需在笛卡尔树 / 分治框架下对「min 固定时 sum 的最大前缀贡献」做更细致的 DP，不能再无脑取极大窗口。
2. **若改求「所有子数组最小乘积之和」**：贡献法变为 $\sum_i \text{nums}[i] \times \sum(\text{以}~i~\text{为最右最小值的子数组的区间和})$，后者需要「区间和的前缀和」技巧——正是 2281 巫师的总力量和的做法。
3. **笛卡尔树视角**：按最小值递归建笛卡尔树（小根），每个节点的子树恰好是它的极大窗口；本题等价于树上「节点值 × 子树内权和」取最大。该视角能自然推广到区间查询（可持久化笛卡尔树）。
4. **在线区间询问**：若要多次询问「任意区间 $[l,r]$ 内的最小乘积最大值」，单调栈离线失效，可转笛卡尔树上启发式合并或分治（$O(n \log n)$ 预处理、$O(\log n)$ 或 $O(1)$ 查询），是本题的竞赛级扩展。
