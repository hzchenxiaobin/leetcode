# LeetCode K 次操作转变字符串 题解

## 1. 题目概述

- **标题 / 题号**：K 次操作转变字符串（#1540，medium）
- **链接**：https://leetcode.cn/problems/can-convert-string-in-k-moves/
- **来源**：LeetCode 第 32 场双周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串

**题意**：给定字符串 $s$、$t$ 与整数 $k$。第 $i$ 次（$1 \le i \le k$）操作可以选择一个**之前未被选过**的下标 $j$，把 $s[j]$ 在字母环上**前移 $i$ 次**（'z' 之后回到 'a'），也可以不操作。每个下标至多被操作一次。问能否在 $k$ 次操作内把 $s$ 变成 $t$。

**约束**：

- $1 \le |s|, |t| \le 10^5$
- $0 \le k \le 10^9$
- $s$、$t$ 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "input", t = "ouput", k = 9
输出：true
解释：第 6 次操作把 'i' 切换 6 次得 'o'；第 7 次操作把 'n' 切换 7 次得 'u'。
```

**示例 2**

```text
输入：s = "abc", t = "bcd", k = 10
输出：false
解释：三个位置都需要移位 1 次，但彼此不同的操作序号中，与 1 同余（mod 26）的只有 1、27、53…，
      第二个 27 已经超过 k = 10。
```

**示例 3**

```text
输入：s = "aab", t = "bbb", k = 27
输出：true
解释：第 1 次操作把第一个 'a' 移位 1 次；第 27 次操作把第二个 'a' 移位 27 次（27 mod 26 = 1）。
```

**示例 4（边界补充）**

```text
输入：s = "abc", t = "abc", k = 0
输出：true
解释：两串相同，无需任何操作。
```

## 3. 解题思路

### 3.1 暴力思路

逐位计算需要的移位量 $d_i = (t[i] - s[i]) \bmod 26$，然后尝试给每个位置分配一个互不相同且 $\le k$ 的操作序号，使序号 $\equiv d_i \pmod{26}$。若直接搜索所有分配方式是指数级的；贪心模拟（每次给「还需移位且序号可用」的位置中挑一个）正确但实现繁琐、复杂度 $O(26n)$ 且容易写错。观察到「同余的序号天然排队」，可以一步到位。

### 3.2 核心观察：同余移位排队，各余数独立判定

![同余移位排队](images/bw32_q2_shift_remainder_queue.svg)

第 $i$ 次操作把字符前移 $i$ 次，而字母环长 26，**前移 $i$ 次与前移 $i \bmod 26$ 次效果相同**。因此位置 $j$ 能被「序号 $i$」修复，当且仅当

$$i \equiv d_j \pmod{26},\quad i \le k,$$

其中 $d_j = (t[j] - s[j]) \bmod 26$。同一个位置只能用一次操作，而**不同的位置可以使用同一个序号吗**？不能——每次操作只能选一个下标，但**不同次操作的序号互不相同**，$1..k$ 每个序号最多用一次。于是：

- 余数 $d$（$1 \le d \le 25$）对应的序号是 $d,\ d+26,\ d+52,\ \dots$，即 $d + 26c$（$c \ge 0$）；
- 若有 $\textit{cnt}[d]$ 个位置需要余数 $d$ 的移位，它们必须**依次占用**这列序号的前 $\textit{cnt}[d]$ 个，最晚用到 $d + 26(\textit{cnt}[d] - 1)$；
- 不同余数 $d \ne d'$ 的序号集合**互不相交**（模 26 不同），彼此绝不冲突。

所以可行 ⟺ 对每个 $d \in [1, 25]$ 都有 $d + 26(\textit{cnt}[d] - 1) \le k$（$\textit{cnt}[d] = 0$ 时跳过）。$d = 0$（字符相同）不需要操作。

### 3.3 算法流程

```text
1. 若 len(s) != len(t)：返回 false
2. cnt[26] 清零；对每个 i：d = (t[i] - s[i] + 26) % 26，若 d > 0 则 cnt[d] += 1
3. 对 d = 1..25：
       若 cnt[d] > 0 且 d + 26 * (cnt[d] - 1) > k：返回 false
4. 返回 true
```

### 3.4 示例演算

![差值分桶演算](images/bw32_q2_diff_bucket_table.svg)

**示例 1**（`input → ouput`）：差值为 $6$（i→o）与 $7$（n→u），$\textit{cnt}[6] = \textit{cnt}[7] = 1$，最大序号 $\max(6, 7) = 7 \le 9$，返回 `true`。

**示例 3**（`aab → bbb`，$k = 27$）：前两个位置 `a→b` 差值都是 $1$，$\textit{cnt}[1] = 2$，需要的序号为 $1, 27$，最大 $27 \le 27$，返回 `true`。第三个位置 `b→b` 差值为 $0$，**不占序号**——若误把它也计入，$\textit{cnt}[1] = 3$ 会需要序号 $53 > 27$，把答案错判为 `false`。这正是「$d = 0$ 必须跳过」的关键样例。

**示例 2**（`abc → bcd`，$k = 10$）：$\textit{cnt}[1] = 3$，最大序号 $53 > 10$，返回 `false`。

## 4. 算法细节

1. **先比长度**：$|s| \ne |t|$ 直接 `false`，绝无可能转换。
2. **差值取模**：$(t[i] - s[i] + 26) \% 26$ 保证非负；C++ 中 `char` 相减可能为负，`+26` 不可省。
3. **$\textit{cnt}[d] - 1$ 而非 $\textit{cnt}[d]$**：第 $c$ 个（从 0 数）同余位置用序号 $d + 26c$；$\textit{cnt}$ 个位置里最大的序号是 $d + 26(\textit{cnt}-1)$。差一错误是最常见的提交杀手。
4. **溢出**：$\textit{cnt}[d] \le 10^5$，$26 \times (\textit{cnt}-1) \approx 2.6 \times 10^6$，加上 $d$、与 $k \le 10^9$ 比较——`int` 恰好够，但用 `long long` 更稳（Python 无此问题）。
5. **为什么各余数独立**：序号 $i$ 的余数 $i \bmod 26$ 唯一确定它属于哪一列；两列序号集合不相交，一列「排满」不影响另一列。这正是「分配论证」的核心（见 §5）。
6. **$k = 0$**：只有 $s = t$（所有 $d = 0$）才可行，循环里 $\textit{cnt}$ 全 0，自然返回 `true`。

## 5. 正确性证明

**引理 1（移位的模不变性）**：把字符 $x$ 前移 $i$ 次的结果只依赖 $i \bmod 26$；特别地，位置 $j$ 可由「序号 $i$ 的一次操作」变为目标字符，当且仅当 $i \equiv d_j \pmod{26}$。

**证明**：字母表是长 26 的循环群 $\mathbb{Z}_{26}$，前移 $i$ 次即加 $i$（模 26）。加法的结果由 $i \bmod 26$ 唯一决定：$i = 26q + r$ 时，加 $i$ 等于加 $26q$（恒等）再加 $r$。位置 $j$ 需要从 $s[j]$ 变到 $t[j]$，即需要加 $d_j = (t[j] - s[j]) \bmod 26$；一次操作加的量是 $i \bmod 26$，两者相等 ⟺ $i \equiv d_j \pmod{26}$。∎

**引理 2（互异性）**：一次合法操作序列中，所有被使用的操作序号互不相同，且每个位置至多被操作一次。

**证明**：由题意，第 $i$ 次操作若选择下标 $j$，则 $j$ 被标记「之前未被选过」；故每个下标至多出现一次。不同操作天生序号不同（$i$ 各不相同）。反过来，任何「互不相同的序号集合 + 每序号指派一个互不相同下标」的方案都对应唯一合法操作序列（把操作按序号升序执行，不用的序号选择「不操作」）。∎

**定理（判定准则）**：转换可行当且仅当对每个 $d \in [1, 25]$，$\textit{cnt}[d] = 0$ 或 $d + 26(\textit{cnt}[d]-1) \le k$。

**证明**：

（必要性）设可行。需要余数 $d$ 的 $\textit{cnt}[d]$ 个位置各被分配一个序号 $i \equiv d \pmod{26}$（引理 1），由引理 2 这些序号互不相同。模 26 同余且互不相同的正整数至多是等差数列 $d, d+26, d+52, \dots$ 中互异的前若干项，其中第 $\textit{cnt}$ 小者 $\ge d + 26(\textit{cnt}-1)$。故最大的被用序号 $\ge d + 26(\textit{cnt}[d]-1)$，而所有被用序号 $\le k$，必要性得证。

（充分性）设条件成立。构造分配：对每个 $d$，把需要余数 $d$ 的位置（任意顺序）依次指派序号 $d, d+26, \dots, d+26(\textit{cnt}[d]-1)$，由条件这些序号都 $\le k$。不同 $d$ 的序号模 26 不同故互不相同；同一 $d$ 内序号严格递增亦互不相同；每个位置恰得一个序号。由引理 2，这是一组合法操作序列；由引理 1，每个位置被自己的序号恰好移位到目标字符。故可行。∎

> 💡 **分配论证**的要点：把「序号」看作资源，按模 26 分成 26 列互不重叠的队列；每列的需求只能由本列从头开始依次满足（互异性禁止跳号——跳号只会让后面更挤，交换论证可知「最小的需求配最小的号」不劣）。各列独立判定，正是计数式贪心的标准形态。

## 6. 复杂度分析

- **时间**：$O(n + 26)$。一遍扫差值计数，再常数轮检查 26 个桶。
- **空间**：$O(26)$。只差值计数数组（哈希表亦可，但定长数组更快）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canConvertString(string s, string t, long long k) {
        if (s.size() != t.size()) return false;
        long long cnt[26] = {0};
        for (size_t i = 0; i < s.size(); ++i) {
            int d = (t[i] - s[i] + 26) % 26;
            if (d) cnt[d]++;
        }
        for (int d = 1; d < 26; ++d) {
            if (cnt[d] == 0) continue;
            // 同余 d 的第 c 个位移必须用第 d + 26(c-1) 次操作
            if (d + 26LL * (cnt[d] - 1) > k) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canConvertString(self, s: str, t: str, k: int) -> bool:
        if len(s) != len(t):
            return False
        cnt = [0] * 26
        for a, b in zip(s, t):
            d = (ord(b) - ord(a)) % 26
            if d:
                cnt[d] += 1
        for d in range(1, 26):
            if cnt[d] and d + 26 * (cnt[d] - 1) > k:
                return False
        return True
```

> 💡 两份代码均通过官方全部示例（`true`、`false`、`true`）与边界用例（`s = t, k = 0` → `true`；`k = 0` 但存在差值 → `false`），另与 400 组随机数据（$k$ 取 0/1/5/25/26/27/50/100 等关键值附近）上的「逐位置依次分配序号」模拟对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **长度不等**：第一时间返回 `false`，别让后面的循环越界。
2. **$d = 0$ 不占序号**：字符相同的位置**不需要也不能**消耗操作（给它分配序号纯属浪费）。示例 3（`aab → bbb`）正是考这一点：把 $d=0$ 也计入会把答案错判为 `false`。
3. **差一错误**：最大序号是 $d + 26 \times (\textit{cnt}-1)$，不是 $d + 26 \times \textit{cnt}$。用 $\textit{cnt} = 1$ 自检：此时只需要序号 $d$ 本身。
4. **`(t[i] - s[i] + 26) % 26` 的 `+26`**：C++ 负数取模向零截断，不加 26 会得到负余数；Python 的 `%` 恒非负可省，但统一写上无害。
5. **`k` 用 `long long`**：虽然 $k \le 10^9$ 在 `int` 内，但 $26 \times (\textit{cnt}-1)$ 与比较式在 `int` 下贴边；函数签名按题目是 `int`，内部转 `long long` 计算最稳。
6. **极端 $\textit{cnt}[d] = |s|$**：如 $s = $ "za…" 全部需要 $d = 1$，$\textit{cnt}[1] = 10^5$，最大序号 $\approx 2.6 \times 10^6$；此时 $k$ 必须 $\ge$ 该值，注意题目 $k$ 可达 $10^9$，判定范围充分。
