# LeetCode 独特的电子邮件地址 题解

## 1. 题目概述

- **标题 / 题号**：独特的电子邮件地址（#929，easy）
- **链接**：https://leetcode.cn/problems/unique-email-addresses/
- **来源**：LeetCode 第 108 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：每个有效邮件地址由「本地名 `@` 域名」组成。对**本地名**有两条归一化规则（域名不受影响）：

1. 本地名中的所有 `.` 被忽略：`alice.z@x.com` 与 `alicez@x.com` 是同一地址；
2. 本地名中第一个 `+` 及其之后的内容被忽略：`m.y+name@x.com` 归一化为 `my@x.com`。

两条规则可以同时使用。给定邮件数组 `emails`，返回归一化后**不同**地址的个数。

**约束**：

- $1 \le \text{emails.length} \le 100$
- $1 \le \text{emails}[i].\text{length} \le 100$
- 仅含小写字母、`+`、`.`、`@`；每个地址恰有一个 `@`
- 本地名与域名均非空；本地名不以 `+` 开头；域名以 `.com` 结尾

## 2. 示例

**示例 1**

```text
输入：emails = ["test.email+alex@leetcode.com",
                "test.e.mail+bob.cathy@leetcode.com",
                "testemail+david@lee.tcode.com"]
输出：2
解释：前两条都归一化为 "testemail@leetcode.com"；第三条为 "testemail@lee.tcode.com"。
```

**示例 2**

```text
输入：emails = ["a@leetcode.com","b@leetcode.com","c@leetcode.com"]
输出：3
解释：本地名不同且没有可归一化的内容，三条互不相同。
```

**示例 3（补充）**

```text
输入：emails = ["a.b+c@x.com", "ab@x.com", "a+b@x.com"]
输出：1
解释：三条都归一化为 "ab@x.com"。
```

## 3. 解题思路

### 3.1 暴力思路

对每封邮件，与其他邮件**两两比较**是否「归一化后相同」：先写一个 `normalize(e)`，再 $O(n^2)$ 去重。$n \le 100$ 时 $10^4$ 次比较绰绰有余，正确性也没问题——只是把「去重」这件哈希表最擅长的事写成了手动两两比较，属于「能做但不该这么做」。

更差的是「枚举所有可能的点/加号组合」：每条邮件有 $O(2^{|local|})$ 种写法，完全没必要。

### 3.2 核心观察：归一化只依赖本地名，直接拼出规范形式

![归一化：本地名去点、截断加号，域名原样保留](images/wc108_q1_normalize_concept.svg)

对一封邮件 `e`：

1. 找到唯一的 `@`，把它切成 `local` 与 `domain`；
2. 从 `local` 中**删除所有 `.`**；
3. 若 `local` 中出现 `+`，**从该位置起全部丢弃**；
4. 规范地址 = 「处理后的 local」+ `@` + 原样的 `domain`。

把规范地址放进 `set`，最后返回集合大小即可。

**为什么本地名的处理与域名的处理必须分开**：题面明确「此规则不适用于域名」。例如 `test@lee.tcode.com` 中的 `lee.tcode.com` 里的点是有意义的，删掉就变成另一个域了。所以切分必须先做，之后只对左半部分套规则。

> 💡 关键点：**归一化是幂等的**（对规范形式再归一化结果不变），因此「先把每条邮件变成唯一代表，再对代表去重」与「按等价类计数」等价——这正是可以放心用集合的原因。

### 3.3 算法流程

```text
1. seen = 空集合
2. for e in emails:
       at = e.find('@')
       local = e[0..at)，domain = e[at+1..]
       clean = ""
       for ch in local:
           if ch == '+': break
           if ch == '.': continue
           clean += ch
       seen.insert(clean + "@" + domain)
3. 返回 |seen|
```

### 3.4 示例演算

![示例 1 演算](images/wc108_q1_walkthrough.svg)

| 原始邮件 | 本地名（处理后） | 域名 | 归一化结果 |
|----------|-----------------|------|-----------|
| `test.email+alex@leetcode.com` | `testemail` | `leetcode.com` | `testemail@leetcode.com` |
| `test.e.mail+bob.cathy@leetcode.com` | `testemail` | `leetcode.com` | `testemail@leetcode.com` |
| `testemail+david@lee.tcode.com` | `testemail` | `lee.tcode.com` | `testemail@lee.tcode.com` |

前两条归一化后相同（只算 1 个），第三条域名不同（另算 1 个），答案 2。

## 4. 算法细节

1. **`@` 的位置只找一次**：题目保证恰有一个 `@`，用 `find('@')` 即可；不要用 `split('@')` 之后忘记域名可能含 `.`。
2. **先截断 `+` 再去点，还是先去点再截断？** 两者等价：`.` 与 `+` 是不同字符，删除点不会改变第一个 `+` 的位置；代码里用「一次遍历 + `break`」最省事。
3. **不要对域名做任何处理**：`lee.tcode.com` 必须原样保留。
4. **`+` 出现在末尾**（如 `ab+@x.com`）：`break` 后 `clean = "ab"`，正确。
5. **集合去重**：C++ 用 `unordered_set<string>`，Python 用 `set`；总规模 $\le 100 \times 100$ 字符，开销可忽略。
6. **返回值是「不同地址数」而不是「重复次数」**：直接返回集合大小。

## 5. 正确性证明

**引理 1（归一化函数良定义）**：对任意合法邮件 `e = L@D`，`normalize(e)` 由 $L$ 与 $D$ 唯一确定，且结果仍是「本地名@域名」形式。

**证明**：算法对 $L$ 做「删除所有 `.`、在首个 `+` 处截断」，两步都是确定性的字符级操作，输出唯一；域名 $D$ 原样保留。处理后的 $L'$ 非空（题目保证本地名不以 `+` 开头，故首个字符不是 `+`，且它不是 `.`，所以 $L'$ 至少保留该字符），因此 `L'@D` 形式合法。∎

**引理 2（等价性）**：两封邮件 `e1 = L1@D1`、`e2 = L2@D2` 转发到同一地址，当且仅当 `normalize(e1) == normalize(e2)`。

**证明**：

*（⇒）* 若二者转发到同一地址，则它们的域名必须相同（转发不跨域），即 $D_1 = D_2$；本地名在「去点 + 截断加号」后必须相同，即 $L_1' = L_2'$。于是 `normalize(e1) = L1'@D1 = L2'@D2 = normalize(e2)`。

*（⇐）* 若 `normalize(e1) == normalize(e2)`，则两者字符串完全相同，特别地 `@` 之后的部分相同（$D_1 = D_2$）、`@` 之前的部分相同（$L_1' = L_2'$）。而题面的两条规则恰好说明「$L$ 与 $L'$ 指向同一邮箱」，故二者转发到同一地址。∎

**引理 3（集合大小 = 等价类个数）**：`set` 中的元素两两不同，且每个等价类恰有一个代表进入集合。

**证明**：由引理 2，`normalize` 是等价关系的**代表元**；对同一等价类中的任意两封邮件，`normalize` 给出同一字符串，故该类在集合中只占一个元素。不同等价类的代表元由引理 2 的（⇒）知其必不相同（否则会被判为同类），故不同类在集合中占不同元素。∎

**定理**：算法返回的集合大小等于实际收到邮件的不同地址数。

**证明**：由引理 3，集合大小 = 邮件集合按「转发到同一地址」划分的等价类个数，而后者正是「实际收到邮件的不同地址数目」。∎

## 6. 复杂度分析

- **时间**：$O(\sum |e_i|)$。每条邮件只做一次线性扫描（切分 + 逐字符处理）。上界为 $100 \times 100 = 10^4$ 个字符。
- **空间**：$O(\sum |e_i|)$，用于存放去重后的规范地址（至多 100 条、每条至多 100 字符）。
- **哈希开销**：`unordered_set` 插入均摊 $O(1)$，总代价与字符数同阶。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numUniqueEmails(vector<string>& emails) {
        unordered_set<string> seen;
        for (const string& e : emails) {
            size_t at = e.find('@');
            string local, domain = e.substr(at + 1);   // 域名原样保留
            for (size_t i = 0; i < at; ++i) {
                if (e[i] == '+') break;                // '+' 之后全部忽略
                if (e[i] == '.') continue;             // 本地名中的 '.' 直接删掉
                local.push_back(e[i]);
            }
            seen.insert(local + "@" + domain);
        }
        return (int)seen.size();
    }
};
```

### Python

```python
class Solution:
    def numUniqueEmails(self, emails: list[str]) -> int:
        seen = set()
        for e in emails:
            local, domain = e.split('@')          # 题目保证只有一个 '@'
            local = local.split('+')[0].replace('.', '')
            seen.add(local + '@' + domain)
        return len(seen)
```

## 8. 边界情况与易错点

1. **对域名也去点**：`lee.tcode.com` 被错误改成 `leetcode.com`，会与 `leetcode.com` 混淆。规则只作用于本地名。
2. **忘记截断 `+`**：`test.email+alex@x.com` 与 `test.e.mail+bob@x.com` 会被当成不同地址，答案偏大。
3. **本地名只剩空串**：题目保证本地名不以 `+` 开头，因此 `local` 处理后至少一个字符；但若自己造用例（如 `"+a@x.com"`）需注意，本题不会出现。
4. **`split('@')` 的坑**：Python 的 `split('@')` 若域名中还有 `@`（本题不会）会拆出多个部分；C++ 用 `find` 更稳。
5. **大小写**：题目只含小写字母，不需要 `lower()`；若误加 `lower()` 在变体题里可能反而错（真实邮件规范中本地名大小写敏感）。
6. **返回类型**：返回的是「不同地址数」，不是「去掉了几个重复」。
7. **单元素输入**：`["a@b.com"]` → 1，注意别在循环外多算。
