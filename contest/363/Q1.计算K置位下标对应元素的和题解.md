# LeetCode 计算 K 置位下标对应元素的和 题解

## 1. 题目概述

- **标题 / 题号**：计算 K 置位下标对应元素的和（#2859，easy）
- **链接**：https://leetcode.cn/problems/sum-of-values-at-indices-with-k-set-bits/
- **来源**：LeetCode 第 363 场周赛 Q1
- **难度**：简单
- **标签**：位运算、数组

**题意**：给你一个下标从 0 开始的整数数组 `nums` 和整数 `k`。把每个**下标** `i` 写成二进制，数其中 `1`（置位）的个数；把所有恰好有 `k` 个置位的下标对应的 `nums[i]` 加起来，返回这个和。

**约束**：

- `1 <= nums.length <= 1000`
- `1 <= nums[i] <= 10^5`
- `0 <= k <= 10`

## 2. 示例

**示例 1**

```text
输入：nums = [5,10,1,5,2], k = 1
输出：13
解释：下标 1(001)、2(010)、4(100) 都恰有 1 个置位，
      答案 = nums[1] + nums[2] + nums[4] = 10 + 1 + 2 = 13。
```

**示例 2**

```text
输入：nums = [4,3,2,1], k = 2
输出：1
解释：只有下标 3(11) 恰有 2 个置位，答案 = nums[3] = 1。
```

**示例 3（k = 0 边界）**

```text
输入：nums = [10,20,30], k = 0
输出：10
解释：只有下标 0(0) 有 0 个置位，答案 = nums[0] = 10。
```

## 3. 解题思路

### 3.1 快速切入：数据范围决定"暴力即正解"

签到题的最短路径：`n <= 1000`，下标最大 999，二进制最多 10 位。对每个下标数一遍置位、与 `k` 比较、累加，总操作量约 $1000 \times 10 = 10^4$，怎么写都能过，**不需要任何优化**，比赛时直接枚举提交。

唯一值得花 10 秒确认的是：**数的是「下标」的二进制，不是「元素值」的二进制**——Q1 最常见的 WA 就出在看错这一点。

### 3.2 核心观察：怎么数一个整数的置位数

![数置位数的三种方式与 Kernighan 过程](images/k_set_bits_kernighan.svg)

数置位数（popcount）有三种常用姿势：

1. **逐位判断**：`while (i) { cnt += i & 1; i >>= 1; }`，每一位看一次，$O(\log n)$。
2. **Brian Kernighan 技巧**：`i &= i - 1` 恰好消去最低位的 `1`，循环次数恰为置位数。
3. **内置函数**：C++ 的 `__builtin_popcount(i)`（C++20 还有 `std::popcount`）、Python 3.10+ 的 `i.bit_count()`，底层映射为单条 CPU 指令。

周赛中**优先用内置函数**：写得快、不会写错，这正是签到题要的"从题面到代码的最短路径"。

### 3.3 算法流程

```text
1. ans = 0
2. 枚举下标 i = 0 .. n-1：
   a. c = popcount(i)        # i 的二进制中 1 的个数
   b. 若 c == k：ans += nums[i]
3. 返回 ans
```

### 3.4 示例演算

![示例 1 的逐下标筛选过程](images/k_set_bits_sum_concept.svg)

以示例 1（`nums = [5,10,1,5,2]`，`k = 1`）走一遍：下标 `1(001)`、`2(010)`、`4(100)` 恰有 1 个置位被选中；`0(000)` 置位数为 0、`3(011)` 置位数为 2，被跳过。最终 `ans = 10 + 1 + 2 = 13`。

## 4. 算法细节

1. **枚举对象是下标**：判断 `popcount(i) == k`，而非 `popcount(nums[i]) == k`。
2. **popcount 实现选择**：
   - C++：`__builtin_popcount(i)`，参数按 `unsigned int` 解释，`i` 非负直接传即可；C++20 可用 `<bit>` 头的 `std::popcount`。
   - Python：`i.bit_count()`（3.10+）；低版本用 `bin(i).count('1')`。
3. **求和变量**：最大和 $1000 \times 10^5 = 10^8 < 2^{31} - 1$，C++ `int` 不会溢出，但用 `long long` 更稳。

若面试要求不用内置函数，手写 Kernighan 版只需三行：

```text
cnt = 0
while i != 0:
    i &= i - 1     # 每次消去最低位的 1
    cnt += 1
```

## 5. 正确性证明

**引理 1**：对任意正整数 `n`，`n & (n - 1)` 恰等于 `n` 去掉**最低**一个置位后的值。

**证明**：设 `n` 的最低置位在第 `t` 位，则 `n` 的第 $0..t-1$ 位全为 0、第 $t$ 位为 1。计算 `n - 1` 时向第 `t` 位借位：第 $t$ 位变 0，第 $0..t-1$ 位全变 1，高于 $t$ 的位不变。两者按位与后，高于 $t$ 的位保留，第 $t$ 位为 $1 \& 0 = 0$，低于 $t$ 的位为 $0 \& 1 = 0$。故结果恰为 `n` 去掉第 $t$ 位的那个 `1` ∎

**引理 2**：`cnt = 0; while (n) { n &= n - 1; cnt++; }` 结束后，`cnt` 等于 `n` 初始值的置位数。

**证明**：由引理 1，每轮循环 `n` 的置位数恰减 1 且 `n` 严格减小，故循环恰在 `popcount(n)` 轮后以 `n = 0` 终止，而 `cnt` 每轮加 1 ∎

**定理**：枚举 $0 \le i < n$，累加所有满足 `popcount(i) = k` 的 `nums[i]`，所得即题目所求。

**证明**：题目所求集合恰为 $\{\, i : 0 \le i < n,\ \operatorname{popcount}(i) = k \,\}$；枚举区间覆盖全部下标且每个恰好访问一次，无重无漏；结合引理 2，判定条件与题意一致 ∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$——每个下标数一次置位，$n \le 1000$、下标最多 10 个二进制位，总量约 $10^4$；用内置 popcount 则近似 $O(n)$。
- **空间复杂度**：$O(1)$——只用常数个累加变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int sumIndicesWithKSetBits(vector<int>& nums, int k) {
        long long ans = 0;
        for (int i = 0; i < (int)nums.size(); i++) {
            if (__builtin_popcount(i) == k) {
                ans += nums[i];
            }
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def sumIndicesWithKSetBits(self, nums: List[int], k: int) -> int:
        return sum(x for i, x in enumerate(nums) if i.bit_count() == k)
```

## 8. 边界情况与易错点

1. **数的是下标不是元素值**：`popcount(i)` 而非 `popcount(nums[i])`，Q1 最易 WA 的点。
2. **k = 0**：只有下标 `0`（二进制 `0`）有 0 个置位，答案 = `nums[0]`。别把"0 个置位"误解成"没有元素入选"。
3. **k = 10 必然为 0**：`n <= 1000` 时下标最大 999，置位数至多 9（要 $1023 = 1111111111_2$ 才有 10 个置位）。代码无需特判，自然返回 0。
4. **溢出**：最大和 $10^8 < 2^{31} - 1$，C++ `int` 可过，`long long` 更稳。
5. **Python 版本**：`int.bit_count()` 需 3.10+，老环境改用 `bin(i).count('1')`。
6. **`__builtin_popcount` 参数**：按无符号解释；本题下标非负直接传。若操作数可能为负，先转无符号或用 `__builtin_popcountll`。
