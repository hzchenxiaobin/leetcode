# LeetCode 修改后子树的大小 题解

## 1. 题目概述

- **标题 / 题号**：修改后子树的大小（#3331，medium）
- **链接**：https://leetcode.cn/problems/find-subtree-sizes-after-changes/
- **来源**：LeetCode 第 142 场双周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、数组、哈希表、字符串

**题意**：给定一棵以 $0$ 为根、节点编号 $0 \sim n-1$ 的树（`parent[0] = -1`），以及每个节点上的字符 `s[i]`。对**所有** $x = 1 \sim n-1$ **同时**执行一次操作：

1. 在原树上找 $x$ 的**最近祖先** $y$，满足 `s[y] == s[x]`；
2. 若 $y$ 不存在则什么都不做；否则断开 $x$ 与原父节点的边，把 $x$ 挂到 $y$ 下。

求最终树中每个节点为根的**子树大小**。

**约束**：

- $n = \text{parent.length} = \text{s.length}$，$1 \le n \le 10^5$
- $0 \le \text{parent}[i] \le n-1$（$i \ge 1$），`parent[0] = -1`，`parent` 表示一棵合法树
- `s` 只含小写英文字母

> **注意**：题面没有「Create the variable …」这类注入指令。「同时」二字是关键约束，不能按编号顺序边改边算。

## 2. 示例

**示例 1**

```text
输入：parent = [-1,0,0,1,1,1], s = "abaabc"
输出：[6,3,1,1,1,1]
解释：节点 3 的父节点从 1 变为 0（0 是它最近的 'a' 祖先）；其余节点找不到同字符祖先或保持原样。
```

**示例 2**

```text
输入：parent = [-1,0,4,0,1], s = "abbba"
输出：[5,2,1,1,1]
解释：节点 4 ('a') 挂到 0 下；节点 2 ('b') 的最近 'b' 祖先是 1，于是挂到 1 下。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $x$，沿 `parent` 指针一路向上爬，找到第一个字符相同的祖先，复杂度 $O(\text{depth})$。最坏情况（链）每次都要爬到根，总复杂度 $O(n^2) = 10^{10}$，$n = 10^5$ 时必然超时。

但「向上爬找最近的同字符祖先」这件事有一个天然的加速方式：**DFS 时维护当前路径上每个字符最新的节点**。路径长度是深度，但每进入一个节点只需要 $O(1)$ 更新一个位置，整棵树走一遍即可处理所有节点。

### 3.2 核心观察：路径上「每个字符的最后一个节点」

![DFS 路径栈 + last[26]：进入节点时查表，退出时回溯](images/bw142_q2_nearest_ancestor.svg)

在从根出发的 DFS 中，任何时刻的**递归栈**恰好就是「当前节点到根的路径」。维护一个长度 $26$ 的数组

$$\text{last}[c] = \text{当前路径上字符为 } c \text{ 的最深节点（没有则为 } -1\text{）}$$

那么当 DFS **进入**节点 $x$ 时：

- 此时的 `last[s[x]]` 正是 $x$ 的**最近同字符祖先**（若为 $-1$ 表示不存在）；
- 记录 `newParent[x] = last[s[x]]`；
- 再令 `last[s[x]] = x`，供子树里的节点使用；
- **退出** $x$ 时要把 `last[s[x]]` 恢复成进入前的值（即 `newParent[x]`），否则兄弟子树会看到不属于自己路径的节点。

**为什么要恢复**：`last` 描述的是「当前路径」，而 DFS 换到另一棵子树后，之前的节点已经不在路径上，必须回溯撤销。

**为什么可以「同时」**：题目规定所有重连同时发生，等价于「每个 $x$ 都按**原树**的祖先关系找 $y$」。DFS 全程都在原树上走，`last` 记录的也一直是原树路径上的节点，因此天然满足「同时」的语义。

### 3.3 算法流程

![三遍扫描：找新父节点、建新树、反序累加子树大小](images/bw142_q2_algorithm_flow.svg)

```text
1. 建原树 children；last[26] 全 -1；newParent[] 全 -1
2. 迭代 DFS（enter / exit 事件）：
      进入 u：newParent[u] = last[s[u]]；last[s[u]] = u；压入 exit 事件与所有子节点的 enter 事件
      退出 u：last[s[u]] = newParent[u]          # 恢复
3. 建新树：对 u = 1..n-1，p = newParent[u] 若存在否则 parent[u]，把 u 挂到 p 下
4. 从 0 出发求新树的先序 order[]
5. size[] 全 1，倒序扫 order[1..]：size[父(u)] += size[u]
6. 返回 size[]
```

第 $4$、$5$ 步的思想是：**先序序列中父节点一定排在子节点之前**，把它倒过来扫，就能保证处理某个节点时它的所有孩子都已经累加完毕。

### 3.4 示例演算

![示例 2 的新旧树对照：4 挂到 0，2 挂到 1，各子树大小](images/bw142_q2_example_walkthrough.svg)

以示例 2（`parent = [-1,0,4,0,1]`、`s = "abbba"`）为例：

| 节点 $x$ | 字符 | 原树上的祖先（由近到远） | `last[字符]` | 新父节点 |
|----------|------|--------------------------|---------------|----------|
| 1 | b | 0(a) | -1 | 0（不变） |
| 4 | a | 1(b), 0(a) | 0 | **0** |
| 2 | b | 4(a), 1(b), 0(a) | 1 | **1** |
| 3 | b | 0(a) | -1 | 0（不变） |

新树的边为 $0\to1$、$0\to3$、$0\to4$、$1\to2$，子树大小从叶子往根累加：$2,3,4$ 都是 $1$，$1 = 1+1 = 2$，$0 = 1+2+1+1 = 5$，得到 `[5,2,1,1,1]`，与示例一致。

## 4. 算法细节

1. **迭代 DFS**：$n = 10^5$ 且可能是链状树，C++ 递归深度 $10^5$ 有爆栈风险，Python 默认递归上限只有 $1000$。用 `(节点, 阶段)` 的显式栈最稳。
2. **退出事件的顺序**：把 `exit` 事件压栈后再压子节点的 `enter` 事件，LIFO 保证子树全部处理完才弹到 `exit`。
3. **字符下标**：`s[u] - 'a'`（C++）或 `ord(s[u]) - 97`（Python），数组大小 $26$。
4. **恢复写法**：退出时 `last[c] = newParent[u]`，因为 `newParent[u]` 恰好就是进入前的 `last[c]`，不必另开数组保存。
5. **新父节点的兜底**：`p = (newParent[u] == -1) ? parent[u] : newParent[u]`。注意根节点 $0$ 不需要处理。
6. **新树仍是一棵树**：`newParent[u]` 是原树上 $u$ 的**真祖先**，故新边的方向严格「向上」、深度减小，不可能成环，根仍是 $0$。
7. **先序 + 反序累加**：比递归后序更简单，也避免递归。`size` 初值全 $1$（自身）。
8. **结果顺序**：按节点编号 $0 \sim n-1$ 返回。

## 5. 正确性证明

**引理 1（`last` 的语义）**：在迭代 DFS 中，每当算法正处于「刚进入节点 $x$、尚未更新 `last`」的时刻，对任意字符 $c$，`last[c]` 等于当前路径（$x$ 及其祖先）上字符为 $c$ 的**最深**节点，若路径上没有该字符则为 $-1$。

**证明**：对 DFS 的步数归纳。初始路径为空（处理根之前），所有 `last[c] = -1`，成立。进入节点 $u$ 时，路径由「父路径 + $u$」组成，父路径的结论成立；此时先读取 `last[s[u]]`，再把 `last[s[u]]` 置为 $u$：对 $c = s[u]$，路径上最深节点变成 $u$；对 $c \ne s[u]$，仍由父路径决定，未被改动。退出 $u$ 时用 `newParent[u]`（即进入前的 `last[s[u]]`）恢复，路径回到父路径，结论保持。归纳完成。∎

**引理 2（最近同字符祖先）**：算法写入的 `newParent[x]` 等于原树上距 $x$ 最近的、字符与 `s[x]` 相同的祖先；若不存在则为 $-1$。

**证明**：由引理 1，进入 $x$ 时 `last[s[x]]` 是路径（$x$ 的全部祖先）上字符为 `s[x]` 的最深节点。「最深」等价于「距 $x$ 最近」，故取值正确。路径上没有该字符时引理 1 给出 $-1$，与「不存在」一致。∎

**引理 3（新树良构）**：新树的边集 $\{(p(u), u)\}$（$p(u)$ 为 `newParent[u]` 或原父节点）构成一棵以 $0$ 为根的树。

**证明**：由引理 2，`newParent[u]` 是原树上 $u$ 的真祖先，因此在原树中的深度严格小于 $u$ 的深度；未重连的节点仍指向原父节点，深度同样更小。于是沿新边向上走，深度严格递减，最终必然停在 $0$（$0$ 没有父节点），不可能出现环，且每个节点都有唯一父节点。故构成以 $0$ 为根的树。∎

**引理 4（反序累加）**：设 `order` 是新树的先序序列，则对任意 $k \ge 1$，在处理 `order[k]` 之前，`order[k]` 的所有后代都已被处理过。

**证明**：先序遍历中，$u$ 的整棵子树在 `order` 里是紧随 $u$ 的一段连续区间，且 $u$ 排在这段区间的第一个位置。因此 `order` 的反序中，$u$ 的所有后代都排在 $u$ 之前。又 `order[0] = 0` 是根，被排除在循环之外，故循环只处理非根节点，处理顺序与「深度从大到小」相容。∎

**定理**：算法返回的数组中，第 $i$ 项等于最终树中以 $i$ 为根的子树大小。

**证明**：引理 2 保证每个节点的新父节点与题面「同时重连」的规则一致，引理 3 保证最终结构确实是一棵树。引理 4 说明反序累加时每个节点的孩子都已完成，于是 `size[u]` 在累加结束时等于 $1 + \sum_{v \text{ 是 } u \text{ 的孩子}} \text{size}[v]$，正是子树大小的递归定义。对根节点同样成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建原树 $O(n)$；迭代 DFS 每个节点进/出各一次，$O(1)$ 操作，共 $O(n)$；建新树 $O(n)$；先序遍历 $O(n)$；反序累加 $O(n)$。
- **空间**：$O(n)$。原树与新树的邻接表各 $O(n)$，外加 `order`、`size`、`newParent` 各 $O(n)$，`last` 为 $O(26)$ 常数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findSubtreeSizes(vector<int>& parent, string s) {
        int n = (int)s.size();
        vector<vector<int>> children(n);
        for (int i = 1; i < n; i++) children[parent[i]].push_back(i);

        // 第一遍：原树 DFS（迭代），找每个节点的「最近同字符祖先」
        vector<int> newParent(n, -1);
        vector<int> last(26, -1);
        vector<pair<int, int>> st;          // (node, phase) 0=进入 1=退出
        st.push_back({0, 0});
        while (!st.empty()) {
            auto [u, phase] = st.back();
            st.pop_back();
            int c = s[u] - 'a';
            if (phase == 0) {
                newParent[u] = last[c];      // -1 表示没有同字符祖先
                st.push_back({u, 1});
                last[c] = u;                 // 本节点成为路径上最新的同字符节点
                for (int v : children[u]) st.push_back({v, 0});
            } else {
                last[c] = newParent[u];      // 回溯：恢复进入前的状态
            }
        }

        // 第二遍：建新树
        vector<vector<int>> nxt(n);
        for (int i = 1; i < n; i++) {
            int p = (newParent[i] == -1) ? parent[i] : newParent[i];
            nxt[p].push_back(i);
        }

        // 第三遍：新树先序，再反序累加子树大小
        vector<int> size(n, 1), order;
        order.reserve(n);
        vector<int> stack2{0};
        while (!stack2.empty()) {
            int u = stack2.back();
            stack2.pop_back();
            order.push_back(u);
            for (int v : nxt[u]) stack2.push_back(v);
        }
        for (int k = (int)order.size() - 1; k >= 1; k--) {
            int u = order[k];
            int p = (newParent[u] == -1) ? parent[u] : newParent[u];
            size[p] += size[u];
        }
        return size;
    }
};
```

### Python

```python
class Solution:
    def findSubtreeSizes(self, parent: list[int], s: str) -> list[int]:
        n = len(s)
        children = [[] for _ in range(n)]
        for i in range(1, n):
            children[parent[i]].append(i)

        # 第一遍：原树 DFS（迭代），记录最近同字符祖先
        new_parent = [-1] * n
        last = [-1] * 26
        stack = [(0, 0)]                      # (节点, 阶段) 0=进入 1=退出
        while stack:
            u, phase = stack.pop()
            c = ord(s[u]) - 97
            if phase == 0:
                new_parent[u] = last[c]
                stack.append((u, 1))
                last[c] = u
                for v in children[u]:
                    stack.append((v, 0))
            else:
                last[c] = new_parent[u]       # 回溯恢复

        # 第二遍：建新树
        nxt = [[] for _ in range(n)]
        for i in range(1, n):
            p = parent[i] if new_parent[i] == -1 else new_parent[i]
            nxt[p].append(i)

        # 第三遍：新树先序，再反序累加
        size = [1] * n
        order, st = [], [0]
        while st:
            u = st.pop()
            order.append(u)
            st.extend(nxt[u])
        for u in reversed(order[1:]):
            p = parent[u] if new_parent[u] == -1 else new_parent[u]
            size[p] += size[u]
        return size
```

## 8. 边界情况与易错点

1. **「同时」与「按编号顺序」的区别**：若按 $1,2,\dots$ 顺序边改边找，节点 $2$ 可能会把已被重连的 $4$ 当成新的祖先，结果就错了。必须在**原树**上一次性求 `newParent`。
2. **忘记回溯恢复 `last`**：不恢复会让右兄弟子树「看到」左子树的节点，`newParent` 可能指向根本不是祖先的节点，导致成环或答案错乱。
3. **递归爆栈**：$n = 10^5$ 的链，C++ 递归深度 $10^5$ 可能栈溢出，Python 会直接 `RecursionError`。务必写迭代版。
4. **根节点**：`parent[0] = -1`，循环处理时从 $1$ 开始，避免访问 `parent[0]` 的父。
5. **`newParent` 为 $-1$ 表示「不重连」**：此时必须回退到原父节点 `parent[u]`，不能当成挂到根。
6. **先序不唯一**：孩子顺序不同会得到不同先序，但只要「父在子前」，反序累加就正确。
7. **`size` 初值**：每个节点至少包含自己，初值必须是 $1$（不是 $0$）。
8. **新树正向性**：`newParent[u]` 必为真祖先，深度严格减小，因此不会出现自环或环；若实现把「兄弟」「后代」误当祖先（比如 `last` 未回溯），就会成环——这也是第 2 条的另一个后果。
