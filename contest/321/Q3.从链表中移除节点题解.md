# LeetCode 从链表中移除节点 题解

## 1. 题目概述

- **标题 / 题号**：从链表中移除节点（#2487，medium）
- **链接**：https://leetcode.cn/problems/remove-nodes-from-linked-list/
- **来源**：LeetCode 第 321 场周赛 Q3
- **难度**：中等
- **标签**：链表、单调栈、递归、翻转

**题意**：给定单链表的头节点 `head`，把**右侧存在一个值严格更大的节点**全部移除，返回处理后的链表头。注意判定是**单向**的——只看右边，左边多小都无所谓。

**约束**：

- 节点数目 $n \in [1, 10^5]$
- $1 \le \text{Node.val} \le 10^5$

> 💡 读题先抓两个信号：①「右侧有更大就删」是**后缀信息依赖**——一个节点的命运取决于它右边的最大值，而单链表只能从头往右走，「看不到右边」正是本题唯一的机关；② $n \le 10^5$ 排除 $O(n^2)$ 的逐点向右扫描。

## 2. 示例

**示例 1**

```text
输入：head = [5, 2, 13, 3, 8]
输出：[13, 8]
解释：5 的右侧有 13，删；2 的右侧有 13，删；3 的右侧有 8，删。
      13 与 8 的右侧都没有比自己大的，保留。
```

**示例 2**

```text
输入：head = [1, 1, 1, 1]
输出：[1, 1, 1, 1]
解释：相等不算「更大」，没有任何节点需要移除。
```

**补充示例 3**

```text
输入：head = [2, 3]
输出：[3]
解释：2 的右侧有 3，被删——注意头节点可能被删，返回的是新头。
```

## 3. 解题思路

### 3.1 暴力思路：逐点向右扫，$O(n^2)$ 超时

最直接的做法：对每个节点 $u$，向右扫一遍检查是否存在值 $> u.val$ 的节点。$n = 10^5$ 时最坏 $O(n^2) = 10^{10}$ 次操作，必然超时。

问题出在**重复劳动**：每个节点都把自己的右侧重新扫了一遍，而「右侧最大值」本可以从右往左用前缀最大值 $O(n)$ 一趟摊销出来——只是单链表不给从右往左走。

### 3.2 核心观察：把「保留条件」翻译成从右往左的一句话

![核心观察：栈里只留右侧没见过更大值的节点](images/wc321_q3_stack_concept.svg)

**保留条件**：节点 $u$ 被保留 ⟺ $\max(\text{右侧所有值}) \le u.val$。也就是说，**保留集合恰好是「从右往左看的前缀最大值链」**，结果链表从左到右**非严格递减**（示例 1 剩下 `[13, 8]`；示例 2 剩下 `[1,1,1,1]`，相等不算更大）。

于是有两条等价的线性化路线：

- **单调栈（从左往右记账）**：维护一个栈存放「目前还活着」的节点，保证栈底到栈顶非严格递减。读到新节点 $x$ 时，把栈顶所有值 $< x.val$ 的节点弹出——它们右侧出现了更大的 $x$，必死；相等不弹。遍历完，栈内节点自底到顶串起来就是答案。**栈替我们记住了「右边暂时没出事」的账**。
- **反转链表（换个方向走）**：既然单链表走不了回头路，就**把路反过来**——先反转链表，从原链表尾向头扫，维护已扫部分的最大值 $maxv$，值 $< maxv$ 的删掉；最后再反转回来。两趟反转 + 一趟过滤，全程 $O(1)$ 额外空间。

### 3.3 算法流程：两次反转 + 一趟过滤

![算法流程：反转、过滤、再反转](images/wc321_q3_reverse_flow.svg)

1. **反转链表**（迭代三指针 `prev/cur/nxt`，$O(1)$ 空间）；
2. **过滤**：$p$ 从新头出发，$maxv$ 初始为 $0$（值域 $\ge 1$，故首个节点必保留）；
   - 若 $p.val < maxv$：删 $p$（跳过，`prev->next = p->next`）；
   - 否则保留 $p$，更新 $maxv = p.val$（此时必有 $p.val \ge maxv$，直接赋值即可）；
   - $p$ 前进一步；
3. **再反转一次**，恢复原有的从左到右顺序，返回新头。

### 3.4 示例演算

![示例演算：给每个节点算右侧最大值 R](images/wc321_q3_walkthrough.svg)

- **示例 1**：右侧最大值 $R$ 依次为 $[13, 13, 8, 8, -]$，判定「$val \ge R$？」得到保留 `[13, 8]`。从右往左算 $R$ 只需一趟前缀最大：$R_i = \max(v_{i+1}, R_{i+1})$；
- **示例 2**：每个 $R = 1$，$1 \ge 1$ 成立，**相等不算更大**，全保留；
- **补充示例**：`[2, 3]` 删头变 `[3]`——过滤后头节点变化，最终返回值必须取第二次反转后的新头。

## 4. 算法细节

1. **弹栈 / 删除条件必须是严格小于**：`top->val < p->val` 才弹，相等保留（示例 2 的考点）。若写成 `<=`，`[1,1,1,1]` 会只剩一个 `1`。
2. **重建链表要切断尾巴**：单调栈版把栈内节点串联后，**最后一个保留节点的 `next` 必须置 `nullptr`**——它原来的 `next` 可能指向被删节点，不切断则答案尾部带脏数据。反转版用 `prev` 指针边走边摘除，天然无此问题。
3. **递归版的妙处**：`dfs(head)` 处理完后缀并返回新头 `nxt`。由「结果非严格递减」可知 **`nxt->val` 就是后缀最大值**，于是判定压缩成一行：`head->val < nxt->val` 则删 `head`，否则接上。代码极短，但 $n = 10^5$ 的递归深度在 Python 必爆（`RecursionError`），C++ 也逼近默认栈上限，**比赛慎用**，优先迭代。
4. **反转链表写法**：`prev/cur/nxt` 三指针迭代，别背错顺序——先存 `nxt`，再改向，再平移。两次反转后节点顺序完全复原，不会破坏「原地」性质。
5. **虚拟头节点**：过滤循环里删的是「当前头」也可能发生（反转后的头对应原链表尾，原链表尾必保留，所以其实第一次删除不会落在头——但用 `dummy` 统一写法更稳，不必特判）。
6. **无溢出**：全程只比较 `int` 值（$\le 10^5$），无累加无乘法，不涉及溢出。

## 5. 正确性证明

**引理 1（保留判定）**：节点 $u$ 出现在最终链表中 ⟺ $u$ 的右侧不存在值 $> u.val$ 的节点（右侧为空时视为条件成立）。

**证明**：这是题意的直接翻译：移除条件恰为其否定。∎

**引理 2（结果形态）**：最终链表的值序列从左到右非严格递减；反之，把所有违反引理 1 的节点删掉后，剩余序列必然非严格递减。

**证明**：设结果中 $a$ 与 $b$ 相邻且 $a$ 在 $b$ 左。若 $a.val < b.val$，则 $a$ 右侧存在更大值 $b$，由引理 1 $a$ 应被删，矛盾；故 $a.val \ge b.val$，相邻非严格递减推出整体非严格递减。反向同理逐对验证即可。∎

**引理 3（单调栈刻画）**：从左到右遍历、遇新节点 $x$ 时弹出所有值 $< x.val$ 的栈顶。则节点 $u$ 被弹出 ⟺ $u$ 右侧存在值严格更大的节点。

**证明**：（⇒）$u$ 被弹出当且仅当某时刻新节点 $x$ 满足 $x.val > u.val$，而 $x$ 晚于 $u$ 入栈、位于 $u$ 右侧。（⇐）设 $v$ 是 $u$ 右侧**第一个**值 $> u.val$ 的节点，则 $u$ 与 $v$ 之间（链表上）的所有节点值都 $\le u.val$。$v$ 到来时，栈中在 $u$ 之上的元素全是这类节点（值 $\le u.val < v.val$，且 $v$ 到来前任何弹它们的动作都会先暴露 $u$，与 $v$ 的「第一」性矛盾——因为弹出意味着遇到更大者），于是它们被 $v$ 依次弹出，紧接着 $u.val < v.val$ 也被弹出。∎

**定理（单调栈算法正确性）**：遍历结束后将栈内节点自底到顶串联，即为答案。

**证明**：栈内元素 = 从未弹出的节点。由引理 3，从未弹出 ⟺ 右侧无严格更大值 ⟺（引理 1）应保留；串联顺序即原链表顺序（入栈序），值非严格递减与引理 2 一致。∎

**推论（反转法正确性）**：反转后从新头扫描、维护 $maxv$、删除 $val < maxv$ 的节点、再反转，结果亦为答案。

**证明**：反转后第 $i$ 个被访问的节点恰是原链表倒数第 $i$ 个，访问到 $u$ 时 $maxv = \max$（$u$ 原右侧全体值，若非空）。故 $u$ 被删 ⟺ $u.val < maxv$ ⟺ 右侧最大值 $> u.val$ ⟺（引理 1）$u$ 应被删；相等时 $u.val = maxv$ 不满足严格不等式，正确保留。第二次反转仅恢复保留节点间的原相对顺序，不改变集合。∎

> 💡 **一句话**：三种解法（单调栈 / 反转 / 递归）都是同一个定理的三种实现——先把「右侧有更大」翻译成单向可判定的一句话，再选一种「从右往左拿信息」的手段。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。栈版每节点至多入栈、出栈各一次，摊还线性；反转版 = 两次反转 $O(n)$ + 一趟过滤 $O(n)$。
- **空间复杂度**：栈版 $O(n)$（栈与重建用数组）；反转版 $O(1)$（仅指针与 $maxv$）；递归版 $O(n)$ 调用栈，且有爆栈风险。
- **对比**：暴力 $O(n^2) = 10^{10}$ 不可行；三种线性解法中以反转版空间最优、最稳。

## 7. 参考代码

### C++（反转版：$O(n)$ 时间 / $O(1)$ 空间，推荐）

```cpp
class Solution {
    ListNode* reverse(ListNode* head) {
        ListNode *prev = nullptr, *cur = head;
        while (cur) {
            ListNode* nxt = cur->next;
            cur->next = prev;
            prev = cur;
            cur = nxt;
        }
        return prev;
    }
public:
    ListNode* removeNodes(ListNode* head) {
        head = reverse(head);                 // 变成从原链表尾往头走
        int maxv = 0;                         // 值域 >= 1，0 保证首节点必留
        ListNode dummy(0, head);
        ListNode *prev = &dummy, *cur = head;
        while (cur) {
            if (cur->val < maxv) {
                prev->next = cur->next;       // 右侧有更大值，删
            } else {
                maxv = cur->val;              // 保留，更新已扫最大值
                prev = cur;
            }
            cur = prev->next;
        }
        return reverse(dummy.next);
    }
};
```

### C++（单调栈版）

```cpp
class Solution {
public:
    ListNode* removeNodes(ListNode* head) {
        vector<ListNode*> stk;
        for (ListNode* p = head; p; p = p->next) {
            while (!stk.empty() && stk.back()->val < p->val)
                stk.pop_back();               // 严格小于才弹，相等保留
            stk.push_back(p);
        }
        ListNode dummy(0);
        ListNode* tail = &dummy;
        for (ListNode* node : stk) {
            tail->next = node;
            tail = node;
        }
        tail->next = nullptr;                  // 切断指向已删节点的旧尾巴
        return dummy.next;
    }
};
```

### Python（反转版）

```python
class Solution:
    def removeNodes(self, head: Optional[ListNode]) -> Optional[ListNode]:
        def reverse(h: Optional[ListNode]) -> Optional[ListNode]:
            prev = None
            while h:
                h.next, prev, h = prev, h, h.next
            return prev

        head = reverse(head)
        maxv = 0
        dummy = prev = ListNode(0, head)
        cur = head
        while cur:
            if cur.val < maxv:
                prev.next = cur.next          # 删
            else:
                maxv = cur.val                # 留，更新右侧最大值
                prev = cur
            cur = prev.next
        return reverse(dummy.next)
```

### C++（递归版：优雅但有爆栈风险）

```cpp
class Solution {
public:
    ListNode* removeNodes(ListNode* head) {
        if (!head->next) return head;
        ListNode* nxt = removeNodes(head->next);  // 处理后的后缀，头即后缀最大值
        if (head->val < nxt->val) return nxt;      // 删 head
        head->next = nxt;
        return head;
    }
};
```

## 8. 边界情况与易错点

1. **相等不算更大**：弹栈与删除都要求**严格** `$<$`。`[1,1,1,1]` 输出原链表；写成 `$\le$` 就只剩一个 `1`——本题最经典的 WA 点。
2. **头节点会被删**：`[5,2,...]` 删完头变成 `13`；返回值必须是过滤 + 二次反转后的**新头**，不能想当然返回原 `head`。
3. **栈版忘记切断尾巴**：串完栈后最后节点 `next` 仍指向原链表的被删节点，务必置空，否则走查输出时带出脏节点。
4. **递归深度**：$n = 10^5$ 时递归版在 Python 触发 `RecursionError`（默认上限 1000），C++ 亦可能爆系统栈；比赛用迭代版兜底。
5. **单节点链表**：右侧为空直接保留，反转版天然正确，栈版栈中只有它自己，均无需特判。
6. **不要重算右侧最大值**：暴力对每个节点向右扫一遍是 $O(n^2)$；一旦意识到「右侧最大值 = 从右往左的 running max」，一趟就够——单调栈与反转只是「拿到这个 running max」的两种手段。
