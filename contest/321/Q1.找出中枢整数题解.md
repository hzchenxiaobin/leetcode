# LeetCode 找出中枢整数 题解

## 1. 题目概述

- **标题 / 题号**：找出中枢整数（#2485，easy）
- **链接**：https://leetcode.cn/problems/find-the-pivot-integer/
- **来源**：LeetCode 第 321 场周赛 Q1
- **难度**：简单
- **标签**：数学、前缀和

**题意**：给定正整数 $n$，寻找**中枢整数** $x$，使得 $1$ 到 $x$ 的所有整数之和等于 $x$ 到 $n$ 的所有整数之和，即 $\displaystyle\sum_{i=1}^{x} i = \sum_{i=x}^{n} i$。返回 $x$；若不存在，返回 $-1$。题目保证对于给定输入至多存在一个中枢整数。

**约束**：

- $1 \le n \le 1000$

> 💡 签到题抓两个信号：① $n \le 1000$ 极小，任何 $O(n)$ 做法都瞬秒，比拼的是**从题面到代码的最短路径**；② **$x$ 同时计入左右两段**——左和是 $\sum_{i=1}^{x} i$、右和是 $\sum_{i=x}^{n} i$，这个「重叠端点」是本题的灵魂细节，读错端点归属则全盘皆错。

## 2. 示例

**示例 1**

```text
输入：n = 8
输出：6
解释：6 是中枢整数，因为 1 + 2 + 3 + 4 + 5 + 6 = 6 + 7 + 8 = 21。
```

**示例 2**

```text
输入：n = 1
输出：1
解释：1 是中枢整数，因为 1 = 1。
```

**示例 3**

```text
输入：n = 4
输出：-1
解释：可以证明不存在满足题目要求的整数。
```

## 3. 解题思路

### 3.1 暴力思路：枚举 x，前缀和一趟扫描

朴素做法：枚举 $x \in [1, n]$，分别计算左和与右和再比较。若对每个 $x$ 都从零累加两段，是 $O(n^2)$（$n=1000$ 时约 $10^6$ 次加法，仍能过但浪费）；套等差数列求和公式则是 $O(n)$。

周赛现场最稳的保底写法是**一趟扫描**：预先算出总和 $\text{total} = \frac{n(n+1)}{2}$，从 $x=1$ 起维护左和 $\text{left}$（每步自增 $x$），右和无需单独维护——$\sum_{i=x}^{n} i = \text{total} - \sum_{i=1}^{x-1} i = \text{total} - (\text{left} - x)$，命中条件即：

$$\text{left} = \text{total} - \text{left} + x$$

一趟 $O(n)$、常数极小、无任何边界坑，是签到的标准出手。

### 3.2 核心观察：单调性 + 代数化简，$x^2 = \frac{n(n+1)}{2}$

![核心观察：中枢 x 是支点，左段 1..x 与右段 x..n 等和，化简得 x² = n(n+1)/2](images/wc321_q1_pivot_balance.svg)

两段和都能写成闭式：左和 $S_L = \frac{x(x+1)}{2}$，右和 $S_R = \frac{n(n+1)}{2} - \frac{x(x-1)}{2}$（总和减去 $1..x-1$ 的和）。令 $S_L = S_R$ 并移项：

$$\frac{x(x+1)}{2} + \frac{x(x-1)}{2} = \frac{n(n+1)}{2}$$

左式中 $(x+1)$ 与 $(x-1)$ 的 $\pm 1$ 恰好抵消，$S_L$ 贡献 $+\frac{x}{2}$、移项后的 $\frac{x(x-1)}{2}$ 贡献 $-\frac{x}{2}$，线性项消失，只剩：

$$\boxed{\,x^2 = \frac{n(n+1)}{2}\,} \quad\Longrightarrow\quad x = \sqrt{\frac{n(n+1)}{2}}$$

> 💡 **为什么线性项会抵消？** 因为 $x$ 同时是左段的右端点与右段的左端点（重叠端点）。若误读成右段从 $x+1$ 开始，方程变为 $x(x+1) = \frac{n(n+1)}{2}$，无法消成 $x^2$，答案全错——审题时务必确认端点归属。

于是：**中枢存在 $\Leftrightarrow$ $t = \frac{n(n+1)}{2}$ 是完全平方数，且 $x = \sqrt{t}$**。验证：$n=8$ 时 $t=36=6^2$ ✓；$n=1$ 时 $t=1=1^2$ ✓；$n=4$ 时 $t=10$ 非完全平方 → $-1$ ✓。

另一视角：$S_L(x)$ 随 $x$ **严格递增**，$S_R(x)$ 随 $x$ **严格递减**，一增一减至多一个交点——这正是题面「至多存在一个中枢整数」的结构由来。

### 3.3 算法流程

![算法流程：保底 O(n) 扫描与 O(1) 公式判定](images/wc321_q1_algorithm_flow.svg)

公式法三步：

1. 计算 $t = \frac{n(n+1)}{2}$；
2. 取 $s = \lfloor\sqrt{t}\rfloor$（整数开方），**回验** $s \cdot s = t$；
3. 相等返回 $s$，否则返回 $-1$。

保底方案（§3.1 一趟扫描）与公式方案并列于上图，现场任选其一。

### 3.4 示例演算

![示例演算：n=8 交于 x=6，n=4 跨过未相等](images/wc321_q1_walkthrough.svg)

- **$n=8$**：$S_L$ 从 $1$ 一路递增、$S_R$ 从 $36$ 一路递减，在 $x=6$ 处 $21 = 21$ 相遇，返回 $6$。
- **$n=4$**：$x=3$ 时 $6 < 7$、$x=4$ 时 $10 > 4$，两条序列**跨过而未相等**；公式视角 $t=10$ 非完全平方数，返回 $-1$。

## 4. 算法细节

1. **右和的增量维护**：$\sum_{i=x}^{n} i = \text{total} - (\text{left} - x)$，故一趟扫描只需一个变量 `left`，命中条件写作 `left == total - left + x`，无需第二个累加器。
2. **整数开方**：C++ 用 `(int)sqrt(t)` 后必须回验 `s * s == t`；Python 用 `math.isqrt(t)`（精确整数开方，无浮点误差，天然免疫回验问题）。
3. **回验的必要性**：`sqrt` 是浮点运算，本应为 $s$ 的结果可能被算成 $s - 10^{-7}$，截断取整后错得 $s-1$；纯整数乘法回验杜绝此类误判。
4. **解的范围**：$1 \le t = \frac{n(n+1)}{2} < (n+1)^2$，故 $s \le n$，返回值必然落在 $[1, n]$ 内，无需额外校验合法性。
5. **溢出**：$n \le 1000$ 时 $t \le 500500$，`int` 安全；若推广到 $n \sim 10^9$，C++ 需 `long long`，Python 天然大整数无虞。

## 5. 正确性证明

**引理 1（唯一性）**：至多存在一个 $x \in [1, n]$ 满足 $S_L(x) = S_R(x)$。

**证明**：$S_L(x) = \frac{x(x+1)}{2}$ 关于 $x$ 严格递增（每步增加 $x+1 > 0$）；$S_R(x) = \frac{n(n+1)}{2} - \frac{x(x-1)}{2}$ 关于 $x$ 递减，且当 $x \ge 2$ 时每步严格减少 $x - 1 > 0$。令 $f(x) = S_L(x) - S_R(x)$，则 $f$ 在 $x \ge 2$ 上严格递增，至多一次为零；$x=1$ 处单独验证不影响「至多一个」的结论。∎

**引理 2（闭式等价）**：$S_L(x) = S_R(x) \Leftrightarrow x^2 = \frac{n(n+1)}{2}$。

**证明**：
$$S_L(x) = S_R(x) \Leftrightarrow \frac{x(x+1)}{2} = \frac{n(n+1)}{2} - \frac{x(x-1)}{2} \Leftrightarrow \frac{x\bigl[(x+1)+(x-1)\bigr]}{2} = \frac{n(n+1)}{2} \Leftrightarrow x^2 = \frac{n(n+1)}{2}$$
每步均为恒等变形（移项、合并同类项），可逆。∎

**定理（算法正确性）**：设 $t = \frac{n(n+1)}{2}$。算法返回 $s$ 当且仅当 $s$ 是中枢整数；$t$ 非完全平方数时算法返回 $-1$，且此时确无中枢。

**证明**：若 $t = s^2$（$s$ 为正整数），由 $t \ge 1$ 知 $s \ge 1$，由 $t < (n+1)^2$ 知 $s \le n$，故 $s \in [1, n]$ 合法；由引理 2，$s^2 = t$ 即 $S_L(s) = S_R(s)$，$s$ 是中枢；回验 $s \cdot s = t$ 保证浮点开方不会漏判或错判。反之，若中枢 $x$ 存在，由引理 2 得 $t = x^2$ 是完全平方数，正平方根唯一，故 $s = x$，算法必返回它；若 $t$ 非完全平方数，由引理 2 无任何 $x$ 使等式成立，返回 $-1$ 正确。∎

> 💡 引理 1 的单调性同时解释了题面「至多存在一个中枢整数」的保证从何而来——不是人为限定，而是结构必然。

## 6. 复杂度分析

- **时间复杂度**：公式法 $O(1)$——一次乘除、一次开方、一次回验；保底扫描法 $O(n)$，$n \le 1000$ 时约 $10^3$ 步，同样瞬秒。
- **空间复杂度**：两法均为 $O(1)$，仅常数个变量。
- **实战取舍**：签到题以「最快写对」为先——一趟扫描逻辑最直白、零风险；公式法展示结构观察能力，且在 $n$ 放大到 $10^{18}$（本题约束之外）时是唯一可行解。

## 7. 参考代码

### C++（公式判定，O(1)）

```cpp
class Solution {
public:
    int pivotInteger(int n) {
        int t = n * (n + 1) / 2;
        int s = sqrt(t);              // 浮点开方，向下截断
        return s * s == t ? s : -1;   // 整数回验，防浮点误差
    }
};
```

### Python（保底扫描，O(n)）

```python
class Solution:
    def pivotInteger(self, n: int) -> int:
        total = n * (n + 1) // 2
        left = 0
        for x in range(1, n + 1):
            left += x
            if left == total - left + x:
                return x
        return -1
```

> 💡 Python 公式版可用 `math.isqrt`（精确整数开方）：`t = n * (n + 1) // 2; s = math.isqrt(t); return s if s * s == t else -1`。

## 8. 边界情况与易错点

1. **$n = 1$**：$x = 1$ 即中枢（$1 = 1$），扫描与公式都直接命中，切勿手滑特判成 $-1$。
2. **端点归属读错（最高频 WA）**：两段**都含** $x$。误读成「左 $\sum_{i=1}^{x}$、右 $\sum_{i=x+1}^{n}$」会得到 $x(x+1) = \frac{n(n+1)}{2}$，消不成 $x^2$，答案全错（如 $n=8$ 会错答 $-1$）。
3. **浮点开方不回验**：`(int)sqrt(t)` 可能因浮点误差截成 $s-1$，必须 `s*s==t` 回验；Python 直接用 `math.isqrt` 根治。
4. **无解返回 $-1$**：不是 $0$、不是 $n$，$n=4$ 即无解样例。
5. **溢出**：本题 $t \le 500500$，`int` 安全；推广大 $n$ 时 C++ 记得换 `long long`。
6. **别过度设计**：$n \le 1000$ 无需二分（单调性虽支持 $O(\log n)$），更无需哈希表；签到题多写一行多一分出错机会。
