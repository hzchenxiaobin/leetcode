# LeetCode 追加字符以获得子序列 题解

## 1. 题目概述

- **标题 / 题号**：追加字符以获得子序列（#2486，medium）
- **链接**：https://leetcode.cn/problems/append-characters-to-string-to-make-subsequence/
- **来源**：LeetCode 第 321 场周赛 Q2
- **难度**：中等
- **标签**：贪心、双指针、字符串

**题意**：给定仅由小写字母组成的字符串 $s$ 和 $t$，只允许**向 $s$ 末尾追加**字符，使得 $t$ 成为 $s$ 的**子序列**（子序列 = 删掉部分字符、不改变剩余字符顺序得到的字符串）。返回最少需要追加的字符数。

**约束**：

- $1 \le |s|, |t| \le 10^5$
- $s$、$t$ 仅由小写英文字母组成

> 💡 读题先抓两个信号：① 操作被限定为**尾部追加**——不能改、不能删、不能往中间插，这个「单向阀门」正是题目的全部机关；② $10^5 \times 10^5$ 的规模直接排除 $O(nm)$ 的 DP，要往**线性扫描**想。

## 2. 示例

**示例 1**

```text
输入：s = "coaching", t = "coding"
输出：4
解释：向 s 末尾追加 "ding"，s = "coachingding"，此时 t 是 s 的子序列。
     可以证明追加任何 3 个字符都无法使 t 成为 s 的子序列。
```

**示例 2**

```text
输入：s = "abcde", t = "a"
输出：0
解释：t 已经是 s 的子序列，无需追加。
```

**示例 3**

```text
输入：s = "z", t = "abcde"
输出：5
解释：s 与 t 没有任何公共字符，需把 t 整个接上去。
```

## 3. 解题思路

### 3.1 暴力思路：DP 超时，而且方向就错了

第一反应容易联想到**最长公共子序列（LCS）**式的二维 DP，但 $n, m \le 10^5$，$O(nm) = 10^{10}$ 直接超时。

更根本的问题是**方向错了**：若允许在 $s$ 的**任意位置**插入字符，答案才是 $m - \mathrm{LCS}(s, t)$；本题只允许**尾部追加**，追加段在顺序上排在所有原字符之后，只能服务 $t$ 的一个后缀——结构远比 LCS 简单，根本不需要 DP。

另一个「半暴力」是**二分答案**：「$t$ 的前 $k$ 个字符是 $s$ 的子序列」关于 $k$ 单调，可以二分 $k$、每次贪心验证 $O(n + m)$，总计 $O((n+m)\log m)$。可行，但对单次查询的题纯属绕远。

### 3.2 核心观察：答案 = $m - k^*$，$k^*$ 是最长可匹配前缀

![核心观察：只能尾部追加，答案 = m − k*](images/wc321_q2_append_concept.svg)

设 $k^*$ 为**最大的** $k$，使得 $t[0..k)$ 是 $s$ 的子序列，则：

$$\text{ans} = m - k^*$$

直觉：追加段接在 $s$ 末尾，**顺序上排在所有原字符之后**，因此匹配中落到追加段的字符只能是 $t$ 的一个后缀；$t$ 的前缀必须完全由原 $s$ 消化。把前缀「吃」得越长（$k^*$ 越大），需要追加的就越少。

求 $k^*$ 用**贪心双指针**：$i$ 扫 $s$，$j$ 指向 $t$ 中下一个待匹配位置；$s[i] = t[j]$ 则 $j{+}{+}$（**能匹配就立刻匹配**），$i$ 每轮都 $+1$。循环结束时 $j$ 就是 $k^*$——每一步都匹配在最左可能位置，给后面留下最大空间（§5 引理 1 保证这是最优的）。

> 💡 本题 = [392. 判断子序列](https://leetcode.cn/problems/is-subsequence/) 的「半程版」：392 判断 $k^* = m$ 是否成立，本题直接问「配到第几个停」。

### 3.3 算法流程

![算法流程：一趟双指针，能匹配就匹配](images/wc321_q2_greedy_flow.svg)

核心只有一个循环、两个判断：

1. 初始化 $i = 0$、$j = 0$；
2. 当 $i < n$ 且 $j < m$：若 $s[i] = t[j]$ 则 $j{+}{+}$；无论是否匹配，$i{+}{+}$；
3. 返回 $m - j$。

$i$、$j$ 都**只前进不回退**，整趟至多 $n + m$ 步。

### 3.4 示例演算

![示例演算：三个样例的双指针走查](images/wc321_q2_walkthrough.svg)

- **示例 1**：$t$ 的 `c`、`o` 依次匹配 $s[0]$、$s[1]$；$t[2] = $ `d` 从 $i = 2$ 扫到末尾都找不到 ⇒ 匹配终止，$k^* = 2$，追加 $6 - 2 = 4$ 个（`ding`）。
- **示例 2**：`a` 首位命中，$t$ 全部消费完，$k^* = 1 = m$，追加 $0$ 个。
- **示例 3**：`a` 在 `z` 里就找不到，$k^* = 0$，追加全部 $5$ 个。

## 4. 算法细节

1. **贪心方向**：「能匹配就立刻匹配」（earliest match）。$s$ 只能被**从左到右顺序消费**，把每次匹配按到最左，剩余部分最长、后续选择最多——不存在「留着好位置等更好字符」的收益。
2. **$j < m$ 的防御**：`while (i < n && j < m)` 版本在 $t$ 配完后自然终止；写成 `for (char c : s)` 内层判断则必须带 `j < m`，否则访问 $t[j]$ 越界（C++ 未定义行为 / Python `IndexError`）。
3. **不是 LCS**：LCS 允许「删 $s$ 中间字符再拼」，本题只能尾部接龙。若把题意误读成任意位置插入，会错误地往 $O(nm)$ DP 上撞。
4. **单次查询无需子序列自动机**：预处理 `nxt[i][c]`（位置 $i$ 之后字符 $c$ 首次出现处）是**多查询**套路（如 792 题），代价 $O(26n)$；本题单次查询，裸双指针 $O(n + m)$ 即是最优。
5. **无溢出**：答案范围 $[0, m] \le 10^5$，下标与计数全程 `int` 安全。

## 5. 正确性证明

**引理 1（贪心领先性）**：设贪心算法第 $j$ 个匹配位置为 $g_j$（即 $s$ 中 $g_{j-1}$ 之后第一个等于 $t[j-1]$ 的位置，约定 $g_0 = -1$）。对任何长度为 $k$ 的合法匹配 $p_1 < p_2 < \cdots < p_k$（$s[p_j] = t[j-1]$），有 $p_j \ge g_j$ 对所有 $1 \le j \le k$ 成立。

**证明**：对 $j$ 归纳。$j = 1$：$g_1$ 是 $s$ 中第一个 $t[0]$，任何匹配位置都不早于它，$p_1 \ge g_1$。设 $p_{j-1} \ge g_{j-1}$。由合法性 $p_j > p_{j-1} \ge g_{j-1}$ 且 $s[p_j] = t[j-1]$，即 $p_j$ 是 $g_{j-1}$ 之后一个等于 $t[j-1]$ 的位置；而 $g_j$ 是这样的**第一个**位置，故 $p_j \ge g_j$。∎

**推论**：贪心算法的匹配长度恰为 $k^*$。

**证明**：若存在长度为 $k$ 的匹配，由引理 1 得 $g_k \le p_k \le n-1$，即贪心也完成了 $k$ 次匹配，故贪心匹配长度 $\ge k$；取 $k = k^*$ 即得。∎

**引理 2（答案刻画）**：最少追加字符数 $= m - k^*$。

**证明**：

- **上界（$m - k^*$ 个足够）**：把 $t[k^*..m)$ 原样接到 $s$ 末尾。匹配方案：前缀 $t[0..k^*)$ 由 $k^*$ 的定义在原 $s$ 中按序匹配；后缀 $t[k^*..m)$ 与追加段逐位相等、逐位匹配。故 $t$ 成为子序列。
- **下界（更少不够）**：设追加 $q$ 个字符后 $t$ 是 $s' = s + a_1 \cdots a_q$ 的子序列。由顺序性，匹配中落在追加段的字符对应 $t$ 的一个**后缀** $t[m-r..m)$（$r \le q$）——若 $t[i]$ 匹配在追加段，则 $i$ 之后的所有字符也只能匹配在追加段。于是 $t[0..m-r)$ 完全由原 $s$ 匹配，故 $m - r \le k^*$，即 $r \ge m - k^*$，从而 $q \ge r \ge m - k^*$。∎

**定理（算法正确性）**：双指针算法返回 $m - j$，且该值是最少追加字符数。

**证明**：算法是贪心的直接实现，终止时 $j$ 为其匹配长度，由推论 $j = k^*$；由引理 2，返回值 $m - j = m - k^*$ 正确。∎

> 💡 **一句话**：尾部追加把「双向自由」压成「单向接龙」——$t$ 必须先用前缀消费 $s$，剩下的才轮到追加段；贪心把前缀吃满，答案自动最小。

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。循环每轮 $i$ 至少前进 $1$，共 $\le n$ 轮；$j$ 只在匹配时前进且 $\le m$。
- **空间复杂度**：$O(1)$，仅两个下标变量。
- **对比**：DP $O(nm) = 10^{10}$ 不可行；二分 + 验证 $O((n+m)\log m)$ 可行但无谓地多了 $\log$ 因子。

## 7. 参考代码

### C++（双指针 while 版）

```cpp
class Solution {
public:
    int appendCharacters(string s, string t) {
        int n = s.size(), m = t.size();
        int i = 0, j = 0;
        while (i < n && j < m) {
            if (s[i] == t[j]) ++j;   // 能匹配就立刻匹配
            ++i;                     // s 前进，永不回退
        }
        return m - j;                // j = k*，剩余全靠追加
    }
};
```

### Python（for 扫描版）

```python
class Solution:
    def appendCharacters(self, s: str, t: str) -> int:
        j = 0
        for c in s:
            if j < len(t) and c == t[j]:   # j < len(t) 防越界
                j += 1
        return len(t) - j
```

> 💡 Python 还有一个利用**迭代器消耗**的行家写法：`it = iter(s); return len(t) - sum(c in it for c in t)`——`c in it` 会把迭代器一路吃到下一个 `c` 为止，天然实现「从当前位置向右找首次出现」。

## 8. 边界情况与易错点

1. **$t$ 已是 $s$ 的子序列**：返回 $0$（示例 2）。`while` 版本在 $j = m$ 时自然退出；`for` 版本务必带 `j < len(t)` 判断，否则越界。
2. **首字符即失配**：$k^* = 0$，返回整个 $m$（示例 3）。
3. **别套 LCS**：$O(nm)$ 超时只是表层；深层原因是本题只允许尾部追加，结构上是「前缀匹配」而非「双删对齐」。
4. **贪心别拧巴**：不存在「这次先不匹配、留给后面更优」的方案——交换论证（引理 1）说明早匹配严格不劣。
5. **答案与匹配位置无关**：$s$ 里 $t$ 出现多少次、出现在哪都无关紧要，唯一的信息是**最长可匹配前缀长度**。
6. **双重循环幻觉**：内层「找下一个 $t[j]$」若每次从当前位置重新扫甚至从头扫，会退化到 $O(nm)$；正确姿势是 $i$ 只进不退（外层单循环）。
