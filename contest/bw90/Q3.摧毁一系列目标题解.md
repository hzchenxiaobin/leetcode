# LeetCode 摧毁一系列目标 题解

## 1. 题目概述

- **标题 / 题号**：摧毁一系列目标（#2453，medium）
- **链接**：https://leetcode.cn/problems/destroy-sequential-targets/
- **来源**：LeetCode 第 90 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：数组 `nums` 给出数轴上若干目标的位置（可能有重复），另给正整数 `space`。给机器输入种子 `nums[i]` 后，它会摧毁所有位于 `nums[i] + c·space`（$c$ 为任意非负整数）位置的目标。希望摧毁**尽可能多**的目标；在摧毁数最多的前提下，返回**最小**的种子值 `nums[i]`。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- $1 \le \text{space} \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [3,7,8,1,1,5], space = 2
输出：1
解释：输入 1 可摧毁位置 1,3,5,7,9,… 上的所有目标，
      共 5 个（除了位置 8）；输入 7 只能摧毁 7 这 1 个……
      最多只能摧毁 5 个，能达成该数的最小种子是 1。
```

**示例 2**

```text
输入：nums = [1,3,5,2,4,6], space = 2
输出：1
解释：奇数组 {1,3,5} 与偶数组 {2,4,6} 各含 3 个目标，
      并列最多；最小种子取 1。
```

**示例 3**

```text
输入：nums = [6,2,5], space = 100
输出：2
解释：三者两两不同余，谁做种子都只能摧毁自己那 1 个；
      并列时取最小种子值 2。
```

## 3. 解题思路

### 3.1 暴力思路

对每个候选种子 `nums[i]`，扫一遍数组数「有多少 `nums[j]` 满足 $\text{nums}[j] \ge \text{nums}[i]$ 且 $(\text{nums}[j] - \text{nums}[i]) \bmod \text{space} = 0$」——$O(n^2)$，$n = 10^5$ 时 $10^{10}$ 步，不可行。也可对每个种子真去模拟「沿数轴一步一个 space 走过去」，更慢。两者都指向同一个被浪费的事实：**摧毁集合只由「余数」决定**，与具体走到哪无关——同一余数的所有目标对彼此互达。

### 3.2 核心观察：同余即同生共死

![核心观察：同一余数的目标构成一个「同余组」](images/bw90_q3_residue_groups.svg)

位置 $y$ 被种子 $x$ 摧毁，条件是 $y = x + c \cdot s$（$c \ge 0$），即：

1. $y \ge x$（机器只能向上打，$c$ 非负）；
2. $y \equiv x \pmod{s}$（同余）。

条件 2 说明**余数相同的所有目标互为「可摧毁关系」**——只要选组内最小的那个做种子（条件 1 也满足），整组全灭。于是问题坍缩为：

- 按 $x \bmod s$ 把 `nums` 分组（保留重复计数）；
- 找**组内出现次数最多**的余数；
- 答案是该组内的**最小值**；并列时取各组最小值中的更小者。

数轴直觉：以 `space` 为步长的「机关枪」对准哪个余数档位，就会横扫那一档的全部目标；要打得多就选人最多的档，档里挑最小的位置开火。

### 3.3 算法流程

![算法流程：余数哈希计数 + 最小种子](images/bw90_q3_min_seed_concept.svg)

```text
1. cnt = 哈希表：余数 r -> (组大小, 组内最小值)
2. for x in nums:
       r = x mod space
       cnt[r].count += 1
       cnt[r].min = min(cnt[r].min, x)
3. 在所有余数中选 (count 最大) 者；count 并列时选 min 更小的
4. 返回该组的 min
```

一趟哈希 $O(n)$，再用 $O(\text{不同余数数})$ 收尾。

### 3.4 示例演算

![示例 1 与 2 的分组演算](images/bw90_q3_example_walkthrough.svg)

示例 1（$s = 2$）：余数 $1$ 组 $\{3,7,1,1,5\}$：大小 5、最小值 1；余数 $0$ 组 $\{8\}$：大小 1。最大组是余数 1，答案 1。

示例 2（$s = 2$）：奇数组 $\{1,3,5\}$ 大小 3 最小 1；偶数组 $\{2,4,6\}$ 大小 3 最小 2。并列大小 3，取更小最小值 → 1。

示例 3（$s = 100$）：三个互不同余的组大小全为 1，并列时取组内最小 → 2。

## 4. 算法细节

1. **`space` 高达 $10^9$，必须哈希**：不能用长度 `space` 的数组做桶（内存爆炸）；`unordered_map` / `dict` 即可，至多 $n$ 个键。
2. **组内最优种子是组内最小值**：种子只需打掉「位置 ≥ 自己」的同余目标，组内最小值覆盖全组；选更大的种子反而可能漏掉比它小的同组成员。因此每组只记 `(count, min)` 两个量。
3. **并列规则是「种子值最小」**：不是「下标最前」。先比组大小，再比组内最小值。实现时可以按 `(count, -min)` 取最大，或直接双条件遍历。
4. **重复目标要计数**：示例 1 中两个位置 1 是两个目标，同余组的大小按出现次数计（种子 1 能同时摧毁它们）。
5. **取余无坑**：`nums[i]`、`space` 皆正，`x % space` 非负，无需修正负余数。
6. **答案必是 `nums` 中的元素**：种子必须取自 `nums`（题目要求输入 `nums[i]`），组内最小值自然满足。

## 5. 正确性证明

**引理 1（摧毁集合的刻画）**：种子 $x$ 摧毁目标 $y$，当且仅当 $y \ge x$ 且 $y \equiv x \pmod{s}$。

**证明**：机器摧毁位置集合 $\{x + c s : c \ge 0\}$。$y$ 属于它 ⟺ 存在整数 $c \ge 0$ 使 $y = x + cs$ ⟺（$y - x$ 是 $s$ 的非负倍数）$y \ge x$ 且 $s \mid (y - x)$，后者即 $y \equiv x \pmod s$。∎

**引理 2（组内最优种子）**：固定余数 $r$，设组 $G_r = \{x \in \text{nums} : x \bmod s = r\}$。则选 $m = \min G_r$ 做种子可摧毁全部 $|G_r|$ 个目标，且组内任何种子至多摧毁 $|G_r|$ 个。

**证明**：上界：任何种子 $x \in G_r$ 摧毁的目标必属 $G_r$（引理 1 的同余条件），故至多 $|G_r|$。可达：对任意 $y \in G_r$，由 $y \ge m$ 与 $y \equiv m \pmod s$ 及引理 1，$y$ 被 $m$ 摧毁。∎

**定理（算法正确性）**：可摧毁的最多目标数 $M = \max_r |G_r|$；在其达成条件下最小种子为 $\min\{\min G_r : |G_r| = M\}$。

**证明**：由引理 2，每个种子能摧毁的数量等于「其所在组的大小」（选组内最小种子时取满），故全局最大值 $M = \max_r |G_r|$。要达成 $M$，只能选大小为 $M$ 的组中某元素做种子；同组内能达到组大小的是且仅是组内最小值（更小的种子覆盖更全——严格地：组内种子 $x \ne \min G_r$ 时，目标 $\min G_r < x$ 且同余，由引理 1 不可被 $x$ 摧毁，故摧毁数 $< |G_r|$）。于是候选答案集是 $\{\min G_r : |G_r| = M\}$，取最小即所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟遍历做哈希插入与最小值维护（均摊 $O(1)$ 每个元素），收尾扫哈希表 $O(\text{键数}) \le O(n)$。
- **空间**：$O(n)$。哈希表至多存 $\min(n, \text{space})$ 个余数键。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int destroyTargets(vector<int>& nums, int space) {
        unordered_map<int, pair<int, int>> cnt;     // 余数 -> (出现次数, 组内最小种子)
        for (int x : nums) {
            auto it = cnt.find(x % space);
            if (it == cnt.end()) cnt[x % space] = {1, x};
            else {
                ++it->second.first;
                it->second.second = min(it->second.second, x);
            }
        }
        int bestCnt = 0, bestSeed = INT_MAX;
        for (auto& [r, p] : cnt)                    // 次数优先，并列取最小种子
            if (p.first > bestCnt || (p.first == bestCnt && p.second < bestSeed)) {
                bestCnt = p.first;
                bestSeed = p.second;
            }
        return bestSeed;
    }
};
```

### Python

```python
class Solution:
    def destroyTargets(self, nums: list, space: int) -> int:
        cnt = {}                                    # 余数 -> (出现次数, 组内最小种子)
        for x in nums:
            r = x % space
            c, m = cnt.get(r, (0, x))
            cnt[r] = (c + 1, min(m, x))
        best_cnt, best_seed = 0, float('inf')
        for c, m in cnt.values():                   # 次数优先，并列取最小种子
            if c > best_cnt or (c == best_cnt and m < best_seed):
                best_cnt, best_seed = c, m
        return best_seed
```

> 💡 两份代码均通过官方示例（`1`、`1`、`2`），并与 $O(n^2)$ 逐种子模拟的暴力在 5000 组随机数据（$n \le 40$、含重复、$s \le 200$）下逐组一致；$n = 10^5$、$s = 10^9$ 极端规模 C++ 约 0.2 s、Python 约 0.04 s。

## 8. 边界情况与易错点

1. **重复目标按次数计**：示例 1 的两个 `1` 各算一个目标，组大小是 5 而不是 4；若去重会导致并列判断错误。
2. **种子只能打到「比自己大」的同余目标**：这正是组内必须选最小值的原因；只按同余计数、忘了 $c \ge 0$ 的方向性，会误以为组内任何元素都行——在「组最小值重复出现」或并列组比较时会翻车。
3. **并列比较键**：`(count 最大, 组内最小值最小)`，与「返回下标最前的元素」无关；直接对 `nums` 排序后扫一遍也可以，但要小心先按余数分组再比较。
4. **`space` 可能大于所有值**：如示例 3，每数自成一组，答案是最小元素——代码自然覆盖，但手推容易把「最大组」想成「最靠前的组」。
5. **别开数组桶**：`space = 10^9` 时 `vector<int> bucket(space)` 直接内存爆炸，必须哈希表。
6. **取余与溢出**：值域 $\le 10^9$，`int` 足够；无负数故不需要 `(x % s + s) % s` 防御写法。
