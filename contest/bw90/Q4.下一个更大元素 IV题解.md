# LeetCode 下一个更大元素 IV 题解

## 1. 题目概述

- **标题 / 题号**：下一个更大元素 IV（#2454，hard）
- **链接**：https://leetcode.cn/problems/next-greater-element-iv/
- **来源**：LeetCode 第 90 场双周赛 Q4
- **难度**：困难
- **标签**：栈、数组、单调栈、排序、二分查找、堆（优先队列）

**题意**：给定非负整数数组 `nums`。对每个 `nums[i]`，找它的**第二大整数** `answer[i]`：即满足 $j > i$、$\text{nums}[j] > \text{nums}[i]$，且开区间 $(i, j)$ 中**恰好存在一个** $k$ 使 $\text{nums}[k] > \text{nums}[i]$ 的元素 $\text{nums}[j]$。不存在则为 $-1$。直观说：从 $i$ 往右看，把所有比 $\text{nums}[i]$ 大的元素按位置排好，**第二个**就是答案。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $0 \le \text{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,4,0,9,6]
输出：[9,6,6,-1,-1]
解释：2 的右边比它大的是 4、9、6，第二个是 9；
      4 的右边比它大的是 9、6，第二个是 6；
      0 的右边比它大的是 9、6，第二个是 6；
      9、6 右边没有更大的数，为 -1。
```

**示例 2**

```text
输入：nums = [3,3]
输出：[-1,-1]
解释：相等不算「更大」，两个 3 的第二大整数都不存在。
```

**补充：被夹住的第二栈陷阱**

```text
输入：nums = [4,2,5,3]
输出：[-1,3,-1,-1]
解释：2 的右边比它大的是 5（第一个）与 3（第二个）→ 3；
      4 的更大元素只有 5，凑不齐两个 → -1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 从右往右线性扫，计数「比 $\text{nums}[i]$ 大」的元素，取第二个——$O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 步不可行，但它是完美的对拍基准（§7 的验证就用它）。沿「单调栈找 next greater」的成熟套路改进：第一大用一条单调栈即可 $O(n)$ 找齐；第二大需要**在第一大的基础上再找一次 next greater**——难点在于「第二大」**不是**第一大的 next greater（$k$ 只需大于 $\text{nums}[i]$，不必大于第一大），不能简单串两次单栈。

### 3.2 核心观察：两条单调栈接力——「等第一大」与「等第二大」

![双栈模型：栈 1 等第一大，栈 2 等第二大，当前值 x 依次结算](images/bw90_q4_two_stack_model.svg)

把元素想成在两条栈上「排队升级」：

- **栈 1**：还没遇到第一大的元素，按值**从底到顶非递增**排好；
- **栈 2**：已经见过第一大、正在等第二大的元素，同样按值非递增排好。

扫描到新元素 $x = \text{nums}[i]$ 时，按顺序做三件事：

1. **结算栈 2**：把栈顶所有值 $< x$ 的元素弹出——$x$ 正是它们的第二大（它们的第一大早就来过了）；
2. **转移栈 1**：把栈顶所有值 $< x$ 的元素弹出、**逆序**压入栈 2——$x$ 是它们的第一大，从现在起它们改等第二大；
3. **入栈 1**：$x$ 自己入栈 1 开始排队。

为什么恰好「第二个更大的元素」会在第 1 步被结算？关键在两条栈的**单调不变量**（§5 引理 2、引理 3）：栈 2 中压在 $u$ 上面的元素值都 $\le \text{nums}[u]$，因此一旦来了 $x > \text{nums}[u]$，上面的会先被弹光，$u$ 必然轮到——$u$ 进入栈 2 之后遇到的第一个比它大的数，就是它位置意义上的「第二个更大」。

### 3.3 算法流程

```text
ans 全部初始化为 -1，s1、s2 为空
for i = 0 .. n-1:
    x = nums[i]
    while s2 非空 且 nums[s2.top] < x:      # ① 结算：x 是它们的第二大
        ans[s2.pop()] = x
    tmp = []
    while s1 非空 且 nums[s1.top] < x:      # ② 转移：x 是它们的第一大
        tmp.push(s1.pop())
    for j = tmp.size-1 downto 0:            #    逆序压入，维持栈 2 单调
        s2.push(tmp[j])
    s1.push(i)                              # ③ 自己排队
返回 ans（仍在栈中的元素无第二大，保持 -1）
```

### 3.4 示例演算

![示例 nums 为 2,4,0,9,6 的双栈走查](images/bw90_q4_example_walkthrough.svg)

以 `nums = [2,4,0,9,6]` 为例（栈底在左）：

| $i$ | $x$ | 结算栈 2 | 转移栈 1 → 栈 2 | 栈 1（底→顶） | 栈 2（底→顶） |
|-----|-----|-----------|----------------|---------------|---------------|
| 0 | 2 | — | — | `[0]` | `[]` |
| 1 | 4 | — | 弹 0，压入 | `[1]` | `[0]` |
| 2 | 0 | — | — | `[1,2]` | `[0]` |
| 3 | 9 | 弹 0 → `ans[0]=9` | 弹 2、1，逆序压入 | `[3]` | `[1,2]` |
| 4 | 6 | 弹 2 → `ans[2]=6`；弹 1 → `ans[1]=6` | — | `[3,4]` | `[]` |

扫描结束，`ans = [9,6,6,-1,-1]` ✓。注意第 3 步的**逆序压入**：栈 1 弹出的顺序是 $0, 2, 1$（值 $0 < 2 < 4$ 递增），压入栈 2 后必须变成 `[…,1,2]`（值递减）才能在第 4 步被 $6$ 依次正确弹出（§5 引理 4 详述）。

## 4. 算法细节

1. **先结算栈 2、再转移栈 1，顺序不能反**：若先把栈 1 的元素转移进栈 2 再结算，当前 $x$ 会被错误地当作「刚入队者」的第二大——它们的第一大恰是 $x$ 自己。
2. **转移必须逆序压入**：栈 1 弹出序列的值**递增**（栈 1 从底到顶非递增，弹从顶开始），而栈 2 要求从底到顶非递增；直接顺序压入会破坏栈 2 的单调不变量。反例正是 §2 的补充示例 `[4,2,5,3]`：`5` 把 `2、4` 弹出栈 1 后若顺序压入，`3` 到达时会被栈顶的 `4` 挡住，`ans[1]` 漏掉本应的 `3`（详见 §8 第 2 条）。
3. **相等元素不弹**：弹出条件用严格小于 `<`，与「更大」的定义一致——`[3,3]` 中谁也不挤走谁，都停在栈里最后输出 $-1$。同理 `0` 值不影响（非负约束与严格比较无冲突）。
4. **栈存下标而非值**：结算时要写下标 `ans[下标] = x`；比存值多一步寻址，但语义清晰、避免值重复时的歧义。
5. **临时数组可复用**：`tmp` 在循环外声明、每轮 `clear()`，避免反复分配；总体空间仍是 $O(n)$（每个下标至多经历「入栈 1 → 转移到栈 2 → 出栈」各一次）。
6. **堆/有序集合替代法**：官方提示给的是「栈 1 弹出的元素放进有序结构（如 multiset / 单调栈）」，与双栈等价；双栈版本免掉平衡树 $\log$ 因子，是常数最小的写法。

## 5. 正确性证明

**引理 1（栈 1 的经典性质）**：扫描过程中，栈 1 从底到顶的值非严格递减；元素 $u$ 从栈 1 被弹出的时刻，恰是扫描到首个满足 $x > \text{nums}[u]$ 的位置时，且弹出者是它的第一大。

**证明**：归纳维护单调性：入栈前所有值 $< x$ 的都已弹出，余下栈顶值 $\ge x$，压入后仍非严格递减。弹出时刻：归纳易见 $u$ 在栈 1 期间，位于它上面的元素值都 $\le \text{nums}[u]$；当 $x > \text{nums}[u]$ 到来时，栈顶这些更小（或相等但更靠上）的元素全部先被弹光，$u$ 随之出栈，故出栈者遇到的 $x$ 是 $u$ 右侧第一个比 $\text{nums}[u]$ 大的元素，即第一大。∎

**引理 2（两栈值域的隔离）**：每一轮结算（第 ① 步）结束后、转移（第 ② 步）之前，栈 2 中幸存者的值都 $\ge x$；本轮转移压入的值都 $< x$。

**证明**：结算弹出所有值 $< x$ 的栈 2 元素，幸存者自然 $\ge x$；转移弹出的是栈 1 中值 $< x$ 的元素。∎

**引理 3（栈 2 的单调不变量）**：若进入某轮时栈 2 从底到顶非递增，则本轮结算+逆序转移结束后仍非递增。

**证明**：结算只删不改，仍非递增（引理 2，剩余段值 $\ge x$）。转移批的值是 $< x$ 的，且按逆序压入后从底到顶递减：栈 1 弹出序列 $u_1, u_2, \dots, u_m$ 的值非递减（引理 1：从顶弹出，值递增），逆序压入后栈 2 新增段自底为 $u_m, \dots, u_1$，值非递增；且新增段全部 $< x \le$ 原幸存段的最小值。两段拼接整体非递增。∎

**引理 4（结算的正确性）**：元素 $u$ 被压入栈 2 后（设其第一大出现在 $f$），栈 2 中位于 $u$ 之上的元素值都 $\le \text{nums}[u]$；因此 $u$ 在栈 2 期间遇到的第一个值 $x > \text{nums}[u]$ 的元素——它必然把 $u$ 之上的元素先弹光再弹出 $u$——出现在 $f$ 之后，且是 $u$ 右侧第二个比 $\text{nums}[u]$ 大的元素。

**证明**：由引理 3 的不变量，任何时刻栈 2 从底到顶非递增，$u$ 之上的值 $\le \text{nums}[u]$。设 $u$ 入栈 2 后，位置 $g > f$ 处首次出现 $x_g = \text{nums}[g] > \text{nums}[u]$。该轮到达时：栈 2 顶部所有值 $< x_g$ 的元素依次被弹出——$u$ 之上的值都 $\le \text{nums}[u] < x_g$，先被弹光；轮到 $u$ 时 $\text{nums}[u] < x_g$，$u$ 被弹出并记 `ans[u] = x_g`。反之，任何更早位置 $g' \in (f, g)$ 有 $\text{nums}[g'] \le \text{nums}[u]$，那一轮弹不到 $u$（且即便 $u$ 之上有更小元素被弹走，也与 $u$ 无关）。于是弹出 $u$ 的时刻恰是「$f$ 之后第一个更大元素」的位置 $g$。而 $u$ 的第二大按定义正是：右侧所有更大元素中按位置的第二个 = $f$ 处的第一个之后的下一个 = $x_g$。两者一致。∎

**定理（算法正确性）**：算法终止时，每个 `ans[u]` 等于 $\text{nums}[u]$ 的第二大整数，不存在则保持 $-1$。

**证明**：每个下标 $u$ 的轨迹是：入栈 1 →（遇到第一大时）被转移到栈 2 →（遇到第二大时）被结算出栈。由引理 1，转移到栈 2 的时刻是第一大出现之时；由引理 4，结算写入的值恰为第二大整数。若 $u$ 终止时仍在栈 1 或栈 2 中，说明其右侧更大元素不足两个（不足一个 → 栈 1；恰一个 → 栈 2），`ans[u]` 保持初始化的 $-1$。所有下标各经历至多一次入栈与出栈，算法必然终止。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标入栈 1 一次、转移至栈 2 一次、出栈至多一次，均摊每轮 $O(1)$；总操作数为 $3n$ 级别。$n = 10^5$ 的实测用时 C++ 约 0.16 s、Python 约 0.06 s。
- **空间**：$O(n)$。栈 1、栈 2、临时数组 `tmp` 合计不超过 $n + n$ 个下标（转移瞬间 `tmp` 与栈 2 的和不超过当时的栈深度），答案数组不计入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> secondGreaterElement(vector<int>& nums) {
        int n = (int)nums.size();
        vector<int> ans(n, -1), s1, s2, tmp;         // s1 等第一大，s2 等第二大
        for (int i = 0; i < n; ++i) {
            while (!s2.empty() && nums[s2.back()] < nums[i]) {  // 先结算栈 2
                ans[s2.back()] = nums[i];
                s2.pop_back();
            }
            tmp.clear();                            // 栈 1 中被当前值压过的，第一大是它
            while (!s1.empty() && nums[s1.back()] < nums[i]) {
                tmp.push_back(s1.back());
                s1.pop_back();
            }
            for (int j = (int)tmp.size() - 1; j >= 0; --j)      // 逆序压入保住栈 2 单调
                s2.push_back(tmp[j]);
            s1.push_back(i);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def secondGreaterElement(self, nums: list) -> list:
        n = len(nums)
        ans = [-1] * n
        s1, s2 = [], []                             # s1 等第一大，s2 等第二大
        for i, x in enumerate(nums):
            while s2 and nums[s2[-1]] < x:          # 先结算栈 2
                ans[s2.pop()] = x
            tmp = []
            while s1 and nums[s1[-1]] < x:          # 栈 1 中被压过的，第一大是 x
                tmp.append(s1.pop())
            s2.extend(reversed(tmp))                # 逆序压入保住栈 2 单调
            s1.append(i)
        return ans
```

> 💡 两份代码均通过官方示例（`[9,6,6,-1,-1]`、`[-1,-1]`），并与 $O(n^2)$ 逐位计数暴力的在 5003 组随机数据（一半集中小值域 0~5 制造大量相等，一半全值域 $0 \sim 10^9$）下逐组一致。

## 8. 边界情况与易错点

1. **相等元素**：弹出条件必须是严格 `<`。`[3,3]` 若写成 `<=`，第二个 3 会把第一个挤去「等第二大」，`ans` 全错；相等元素谁也不算谁的更大。
2. **逆序压入是正确性的命门**：顺序压入在 `[4,2,5,3]` 上立即翻车——`5` 从栈 1 弹出 `2、4` 顺序进栈 2 成 `[2,4]`（底小顶大），随后 `3 < 4` 被挡在栈外，`2` 的第二大 `3` 被漏掉。逆序压入成 `[4,2]`，`3` 先弹值小的 `2` ✓。引理 3 给出了一般性保证。
3. **结算与转移的先后**：必须先弹栈 2 再转栈 1。反着写会把刚转移进来的元素用同一个 $x$ 立刻结算（$x$ 既是它们的第一大又被记成第二大），`ans` 系统性偏小。
4. **单个元素 / 全体递减**：$n = 1$ 或整体非递增时两栈从不弹人，全部输出 $-1$；初始化 `-1` 即答案，无需特判。
5. **存值还是存下标**：结算要定位 `ans[u]`，必须存下标；若图省事存值，值重复时无法回填。
6. **不要递归或额外扫尾巴**：终止时栈里残留的下标维持 `-1` 即可，切勿画蛇添足地把「栈 2 剩余元素的答案设为栈 1 对应值」之类的错误修补。
