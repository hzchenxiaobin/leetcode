# LeetCode 最多单词数的发件人 题解

## 1. 题目概述

- **标题 / 题号**：最多单词数的发件人（#2284，medium）
- **链接**：https://leetcode.cn/problems/sender-with-largest-word-count/
- **来源**：LeetCode 第 79 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、计数

**题意**：聊天记录共 $n$ 条消息，`messages[i]` 由发件人 `senders[i]` 发出，消息是若干以**单个空格**连接的单词（无前后空格）。一个发件人的**单词计数**是其所有消息的单词数**总和**。返回单词数最多的发件人；若有多个并列最多，返回**字典序最大**的名字。

**约束**：

- $n = \text{messages.length} = \text{senders.length}$，$1 \le n \le 10^4$
- $1 \le \text{messages[i].length} \le 100$，单词以单个空格分隔、无前后空格
- $1 \le \text{senders[i].length} \le 10$，只含大小写字母
- 字典序中**大写字母小于小写字母**；`"Alice"` 与 `"alice"` 是不同名字

## 2. 示例

**示例 1**

```text
输入：messages = ["Hello userTwooo","Hi userThree","Wonderful day Alice","Nice day userThree"],
      senders = ["Alice","userTwo","userThree","Alice"]
输出："Alice"
解释：Alice 共发出 2 + 3 = 5 个单词；userTwo 2 个；userThree 3 个。
     Alice 最多，返回 "Alice"。
```

**示例 2**

```text
输入：messages = ["How is leetcode for everyone","Leetcode is useful for practice"],
      senders = ["Bob","Charlie"]
输出："Charlie"
解释：Bob 与 Charlie 都是 5 个单词，打平。
     返回字典序最大的名字 "Charlie"（'C' > 'B'）。
```

**示例 3（边界补充）**

```text
输入：messages = ["a b", "c d"], senders = ["X", "x"]
输出："x"
解释：两人都是 2 词打平；'x'(0x78) > 'X'(0x58)，按 ASCII 序 "x" 更大。
```

## 3. 解题思路

### 3.1 暴力思路

对每个出现的发件人，重新遍历全部消息、把属于他的消息单词数加起来，再在名字之间比较。时间 $O(n^2 \cdot L)$（$L$ 为消息平均长度），$n = 10^4$ 时约 $10^{10}$ 次字符操作，不可行。瓶颈在于「每个发件人的单词总数」被重复计算——它显然可以在**一次遍历**中同时统计。

### 3.2 核心观察：哈希表一次遍历累计 + 平局取字典序最大

![哈希计数：按发件人累计单词数](images/bw79_q2_hash_count_model.svg)

两个关键化简：

1. **单词数 $=$ 空格数 $+ 1$**：题目保证单词间是单个空格、无前后空格，因此无需 `split`，数一遍空格即可，单条消息的统计从 $O(L)$ 次字符串操作降为一次扫描。
2. **发件人 $\to$ 单词总数**是一张哈希表：遍历 $(\text{message}, \text{sender})$ 对，向 `cnt[sender]` 累加空格数 $+1$。同一发件人的多条消息**累加**而非分别比较。

### 3.3 算法流程

```text
1. cnt ← 空哈希表
2. 对每条 (messages[i], senders[i])：
       cnt[senders[i]] += (messages[i] 的空格数 + 1)
3. 在 cnt 中找 (计数最大, 名字字典序最大) 的条目：
       best_cnt = −1, best = ""
       对每个 (name, c)：
           若 c > best_cnt 或 (c == best_cnt 且 name > best)：
               best_cnt = c, best = name
4. 返回 best
```

### 3.4 示例演算

![平局规则：返回字典序最大的名字](images/bw79_q2_tie_break.svg)

以示例 2 走查：`cnt = {"Bob": 5, "Charlie": 5}`。`Bob` 先被遍历时成为候选；`Charlie` 计数相同但名字更大（首字符 'C' > 'B'），替换候选。最终返回 `"Charlie"`。

再看示例 1：第 1、4 条消息都来自 `Alice`，分别累加 2 与 3 得 5；`userTwo` 与 `userThree` 各只有 2 与 3。最大者 `Alice` 直接胜出，无平局。

## 4. 算法细节

1. **数空格而非切分**：`messages[i]` 的单词数 $=\text{count}(\text{' '}) + 1$。C++ 手写循环或 `count(msg.begin(), msg.end(), ' ')`；Python 直接 `msg.count(' ')`。
2. **平局规则是「字典序最大」，不是最小**：与许多题目相反，容易条件反射写错。C++ 的 `std::string` 比较与 Python 的 `str` 比较都按 ASCII 码逐字符进行，天然满足「大写 < 小写」的题设，直接用 `>` 比较名字即可，无需自定义比较器。
3. **打平判定与计数判定的优先级**：先比计数，计数相同再比名字；两个条件合并写成 `c > best_cnt || (c == best_cnt && name > best)`。
4. **哈希表实现**：C++ 用 `unordered_map<string, int>`；Python 用 `dict` 或 `collections.defaultdict(int)`。
5. **名字比较与大小写**：题目明确 `Alice` 与 `alice` 不同、且大写字母小于小写字母——即普通字节序比较，**不要**做大小写归一化。

## 5. 正确性证明

**引理 1（单词数公式）**：若消息由 $w \ge 1$ 个单词以单个空格连接、无前后空格，则其长度中的空格数为 $w - 1$。

**证明**：$w$ 个单词之间恰有 $w - 1$ 个间隔，每个间隔恰一个空格；前后无空格。故空格数 $= w - 1$，即 $w = \text{空格数} + 1$。∎

**定理**：算法返回的名字 $b$ 满足：$\text{cnt}(b) = \max_x \text{cnt}(x)$，且在计数最大的名字中 $b$ 的字典序最大。

**证明**：由引理 1，步骤 2 中每次累加的正是该条消息的单词数，故哈希表最终存有每个发件人的单词总数。步骤 3 扫描全部条目维护 $(\text{cnt}, \text{name})$ 的字典序最大候选（先比较计数，再比较名字），这是在一个有限集合上求「二元组 $(\text{cnt}, \text{name})$ 按字典序」的最大元。因此返回者的计数是全局最大；而在计数相同者中，它拥有最大名字。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot L + S)$，其中 $L \le 100$ 为消息平均长度（数空格的扫描），$S$ 为哈希表中名字总数（不超过 $n$，且名字长度 $\le 10$）。总量约 $10^4 \times 100 = 10^6$，轻松通过。
- **空间**：$O(S)$，哈希表最多存 $\min(n, \text{不同名字数})$ 个条目。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string largestWordCount(vector<string>& messages, vector<string>& senders) {
        unordered_map<string, int> cnt;
        for (int i = 0; i < (int)messages.size(); ++i) {
            int words = 1;                          // 单词数 = 空格数 + 1
            for (char c : messages[i]) words += (c == ' ');
            cnt[senders[i]] += words;
        }
        string best;
        int bestCnt = -1;
        for (const auto& [name, c] : cnt)
            if (c > bestCnt || (c == bestCnt && name > best)) {
                bestCnt = c;
                best = name;
            }
        return best;
    }
};
```

### Python

```python
class Solution:
    def largestWordCount(self, messages: list[str], senders: list[str]) -> str:
        cnt = {}
        for msg, name in zip(messages, senders):
            cnt[name] = cnt.get(name, 0) + msg.count(' ') + 1          # 单词数 = 空格数 + 1
        best, best_cnt = "", -1
        for name, c in cnt.items():
            if c > best_cnt or (c == best_cnt and name > best):
                best, best_cnt = name, c
        return best
```

> 💡 两份代码均通过官方示例（`"Alice"`、`"Charlie"`）与边界用例（单条单词消息、大小写平局 `"X"` vs `"x"`、长度不同的平局名 `"Ab"` vs `"Abc"`）的本地验证，全部一致。

## 8. 边界情况与易错点

1. **平局取字典序「最大」**：本题最容易翻车的点——很多相似题要求最小。务必用题目示例 2 自测（`Bob`/`Charlie` → `Charlie`）。
2. **同一发件人多次发消息要累加**：哈希表的值是总和；若误把「覆盖」当「累加」，示例 1 会错答 `"userThree"`。
3. **大小写敏感**：`"Alice"` 与 `"alice"` 是不同的人，且比较遵循 ASCII 序（大写 < 小写）。不要 `lower()` 或 `tolower()`。
4. **空串消息不存在**：$1 \le \text{messages[i].length}$ 保证每条至少 1 个单词，`空格数 + 1` 不会算出 0。
5. **返回类型**：一定有答案（$n \ge 1$），`best` 不会为空，无需处理「无人发消息」。
6. **$n = 10^4$、消息长度 100**：纯字符串扫描总量约 $10^6$，注意别写成 $O(n^2)$ 的重复统计。
