# LeetCode 公交路线 题解

## 1. 题目概述

- **标题 / 题号**：公交路线（#815，hard）
- **链接**：https://leetcode.cn/problems/bus-routes/
- **来源**：LeetCode 第 79 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、数组、哈希表

**题意**：`routes[i]` 是第 `i` 辆公交车的循环线路，它会按该序列不停地绕圈（`1 -> 5 -> 7 -> 1 -> 5 -> 7 -> ...`）。你从 `source` 站出发，初始不在任何车上，目标是 `target` 站，只允许乘公交移动。求**最少乘坐多少辆公交车**（换乘一次算多坐一辆）；到不了返回 `-1`。

关键转述：因为车是**无限循环**行驶的，「第几站、什么顺序」都不重要，一条线路真正携带的信息只有**它经过哪些站点**；而在同一条线路上随便坐多少站，都只花「一辆车」。

**约束**：

- $1 \le \text{routes.length} \le 500$
- $1 \le \lvert \text{routes}[i] \rvert \le 10^5$，且 $\sum_i \lvert \text{routes}[i] \rvert \le 10^5$
- 同一条线路内的站点互不相同
- $0 \le \text{routes}[i][j] < 10^6$，$0 \le \text{source}, \text{target} < 10^6$

> 💡 站点总数只有 $10^5$ 量级，而站点编号最大到 $10^6$：说明**编号是稀疏的**，用哈希表或「按编号开数组 + 访问标记」都可以，但绝不能假设编号连续且稠密。

## 2. 示例

**示例 1**

```text
输入：routes = [[1,2,7],[3,6,7]], source = 1, target = 6
输出：2
解释：先坐 0 号线到 7 站（1 -> 2 -> 7），再换乘 1 号线到 6 站。
      两条线路在站点 7 相交，换乘只能发生在「多线共站」处。
```

**示例 2**

```text
输入：routes = [[7,12],[4,5,15],[6],[15,19],[9,12,13]], source = 15, target = 12
输出：-1
解释：{15,19} 与 {4,5,15} 自成一组，{7,12} 与 {9,12,13} 自成一组；
      两组没有任何公共站点，无法换乘，故不可达。
```

**示例 3（补充：起点即终点）**

```text
输入：routes = [[1,2,7],[3,6,7]], source = 2, target = 2
输出：0
解释：已经在终点站，一辆车都不用坐。
```

## 3. 解题思路

### 3.1 暴力思路

把问题看成「站点图」上的最短路：对每条线路，把它经过的站点**两两连边**，边权记为该线路，然后在这个图上 BFS/最短路。问题是边数：一条线路有 $L$ 个站就会产生 $\Theta(L^2)$ 条边，$L = 10^5$ 时是 $10^{10}$ 条边，建图直接爆炸。

换成「同一线路内相邻两站连边、边权 1」也不行：那样 BFS 得到的是**坐了几站**，而题目要的是**换了几辆车**——同一条线路上坐 50 站仍然只花 1 辆。**度量对象错了**，这是本题真正的坑。

即使给边标上线路编号，最短路也变成「最小化不同线路的数量」，普通的边权最短路无法表达这种「同色边只计一次」的代价。

### 3.2 核心观察：站点–线路二分图上的 BFS

![站点–线路二分图：层数就是乘车数](images/wc79_q4_bipartite_model.svg)

把站点和线路分别当作两类节点，建成**二分图**：

- 站点节点 $s$ 与线路节点 $r$ 之间有边 $\iff$ 线路 $r$ 经过站点 $s$。
- 在站点上移动是**免费的**（只要还在这辆车上），上一条新线路才需要 +1。

于是「坐 $k$ 辆车从 `source` 到 `target`」正好对应二分图中一条从 `source` 出发、经过 $k$ 个线路节点的路径。BFS 的层号天然就是「已经坐了几辆车」：

- 第 0 层：`source` 本身（0 辆）；
- 从某站点 $u$（$k$ 辆）出发，凡经过 $u$ 的线路都可「上车」，其上的所有站点都变成 $k+1$ 辆可达。

**最关键的剪枝**：**每条线路只需要展开一次**。设线路 $r$ 第一次被展开时是在站点 $u$ 处、$dist[u] = d$，它把 $r$ 上所有站点的距离压到 $\le d+1$。此后若再从某个 $dist[u'] = d' \ge d$ 的站点尝试展开 $r$，得到的候选值是 $d'+1 \ge d+1$，不可能更优。所以用一个 `usedRoute[r]` 布尔标记就够了——这和普通 BFS 里「每个点只入队一次」是同一个思想，只不过被搬到了线路一侧。

> ⚠️ 注意：不能只按「站点是否访问过」来剪枝。一个站点可能属于多条线路，先访问它不代表它的所有线路都被展开过；反过来，**线路的 `used` 标记才是复杂度的保证**。

### 3.3 算法流程

![按线路扩展的 BFS 流程](images/wc79_q4_bfs_flow.svg)

1. **特判**：`source == target` 直接返回 `0`。
2. **建表**：一次扫描所有线路，得到 `stopToRoutes`：站点 → 经过它的线路编号列表。总规模 $O(\sum_i \lvert \text{routes}[i] \rvert)$。
3. **初始化**：`dist[source] = 0`，`source` 入队；所有 `usedRoute[i] = false`。
4. **BFS**：每次弹出站点 $u$（当前已坐 `dist[u]` 辆），枚举 $u$ 所属的每条**未用过**的线路 $r$：
   - 置 `usedRoute[r] = true`；
   - 遍历 $r$ 上的每个站点 $v$：若 $v = \text{target}$，立即返回 `dist[u] + 1`；若 $v$ 尚未访问，则 `dist[v] = dist[u] + 1` 并让 $v$ 入队。
5. 队列耗尽仍未命中，返回 `-1`。

注意第 4 步里「命中 target 立即返回」是安全的：BFS 按层推进，第一次扫到 target 时用的车辆数就是最小的。

### 3.4 示例演算

![示例 1 的逐步走查](images/wc79_q4_walkthrough.svg)

以 `routes = [[1,2,7],[3,6,7]]`、`source = 1`、`target = 6` 为例，按层推进：

| 层（已坐车辆数） | 站点集合 | 可展开的线路 |
|------------------|----------|--------------|
| 0 | $\{1\}$ | 线路 0（含 1） |
| 1 | $\{2, 7\}$ | 线路 0 已用；线路 1（含 7） |
| 2 | $\{3, 6\}$ | 扫到 6 = target，返回 $1 + 1 = 2$ |

站 2 出队时，它只属于线路 0，而线路 0 已经被站点 1 展开过，直接跳过——这就是「每条线路只展开一次」在起作用。示例 2 中，从 15 出发只能到达 $\{4,5,19\}$，它们的线路都已用尽，队列耗尽得到 `-1`。

## 4. 算法细节

1. **线路当集合**：因为车循环行驶，`routes[i]` 的顺序无关紧要，判断「$u$ 能否上线路 $r$」就是判断 $u \in \text{routes}[r]$；提前建 `stopToRoutes` 反查表即可 $O(1)$ 取到。
2. **两层访问标记缺一不可**：`dist`（或 `visitedStop`）保证站点不重复入队，`usedRoute` 保证线路不重复展开。只留 `dist` 时，同一条线路会被不同站点反复扫描，$O(\sum L)$ 退化成 $O(\sum L^2)$；只留 `usedRoute` 时，同一个站点会被多条线路反复入队，队列规模失控，还可能重复出队。
3. **标记时机**：从 $u$ 枚举到线路 $r$ 时**先置 `usedRoute[r] = true` 再遍历 $r$ 的站点**，否则同一线路可能被同层的多个站点重复展开。
4. **返回时机**：命中 target 时返回 `dist[u] + 1`，而不是 `dist[target]`——此刻 target 还没有被赋距离，因为它就是在这次展开中被发现的。
5. **反查表的选型**：`stopToRoutes` 用 `unordered_map<int, vector<int>>`（编号稀疏，$10^6$ 开数组约 24 MB，也可以但没必要）；`dist` 同样用哈希表即可，站数 $\le 10^5$。
6. **复杂度只与 $\sum \lvert \text{routes}[i] \rvert$ 有关**：每条线路恰好展开一次，展开时扫描它的站点；每个站点出队一次，出队时枚举它所属的线路。两者相加是 $O(\sum L)$，与「站点编号最大值 $10^6$」无关。
7. **不要建稠密站点图**：任何 $O(L^2)$ 的建边/两两枚举都会在单条 $10^5$ 站的线路上超时或超内存。

## 5. 正确性证明

**引理 1（层序性）**：BFS 中站点出队的 `dist` 单调不减，且入队时写入的 `dist[v] = dist[u] + 1` 是当时能给出的最小值。

**证明**：队列是 FIFO，且每次只在队尾压入 `dist[u] + 1`，由归纳可知队列中 `dist` 非降，出队顺序亦然。又因为一个站点一旦被赋 `dist` 就不再改动，它的值来自某个 $dist[u]+1$。∎

**引理 2（线路只展开一次不丢最优解）**：设线路 $r$ 第一次展开发生在站点 $u$、$dist[u] = d$。则对 $r$ 上任意站点 $v$，最终 $dist[v] \le d+1$；任何更晚的展开（从 $dist[u'] = d' \ge d$ 的站点）给出的候选 $d' + 1 \ge d + 1$ 不可能改进它。

**证明**：第一次展开时遍历了 $r$ 的全部站点，对每个尚未赋值的 $v$ 写入 $d+1$，已赋值的更小；故 $dist[v] \le d+1$。由引理 1，后来的展开发生在 $d' \ge d$ 的层，候选值 $d'+1 \ge d+1$，不优于已写入的值。∎

**引理 3（分层可达性）**：记 $R_k$ 为「用至多 $k$ 辆车可达的站点集合」，则 BFS 处理完所有 $dist = k$ 的站点后，距离表中小于等于 $k+1$ 的站点集合恰为 $R_{k+1}$。

**证明**：对 $k$ 归纳。

- 归纳基础：$R_0 = \{\text{source}\}$，与 $dist = 0$ 的集合一致。
- 归纳步：设 $R_k$ 与 $dist \le k$ 的集合一致。任何 $v \in R_{k+1} \setminus R_k$ 必须由某条「经过 $u \in R_k$ 的线路 $r$」到达（第 $k+1$ 辆车只能在 $R_k$ 的站点上换乘）。若 $r$ 未展开过，$u$ 出队时必然展开它并给 $v$ 赋值 $k+1$；若 $r$ 已在更早的 $d \le k$ 展开，则由引理 2 得 $dist[v] \le d+1 \le k+1$。故 $R_{k+1}$ 中站点都有 $dist \le k+1$。反之，每次赋值 `dist[v] = dist[u] + 1` 都对应「在 $u$ 换乘线路 $r$ 到 $v$」，是合法方案，故 $dist \le k+1$ 的站点都在 $R_{k+1}$ 中。∎

**定理**：算法返回值等于最少乘车数；若不可达返回 `-1`。

**证明**：若 target 可达，设最少需要 $k^{\ast}$ 辆，则 $\text{target} \in R_{k^{\ast}}$、$\text{target} \notin R_{k^{\ast}-1}$。由引理 3，target 第一次被扫到时所在的展开来自某个 $dist[u] = k^{\ast}-1$ 的站点，算法返回 $dist[u] + 1 = k^{\ast}$，正是最小值；且由引理 1 的层序性，不可能更早以更大的值返回。若不可达，队列耗尽后 `dist` 不再增长，即 $R_k$ 稳定且不含 target，由引理 3 得 target 不可达，返回 `-1` 正确。∎

## 6. 复杂度分析

- **时间**：$O(\sum_i \lvert \text{routes}[i] \rvert)$。建 `stopToRoutes` 扫描所有站点一次；BFS 中每个站点至多出队一次，出队时枚举它所属的全部线路（所有站点的「所属线路数」之和恰为 $\sum L$）；每条线路至多被展开一次，展开时扫描它的站点（总和也是 $\sum L$）。因此总操作数是线性的，与线路数的平方、站点编号上界都无关。
- **空间**：$O(\sum_i \lvert \text{routes}[i] \rvert)$。`stopToRoutes` 存了每个「站点–线路」关系一份，`dist` 最多存全部站点，`usedRoute` 为 $O(\text{routes.length})$；队列最坏 $O(\sum L)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int numBusesToDestination(vector<vector<int>>& routes, int source, int target) {
        if (source == target) return 0;

        int n = (int)routes.size();
        // stopToRoutes[s] = 经过站点 s 的所有线路编号
        unordered_map<int, vector<int>> stopToRoutes;
        for (int i = 0; i < n; i++)
            for (int s : routes[i])
                stopToRoutes[s].push_back(i);

        if (!stopToRoutes.count(source) || !stopToRoutes.count(target)) return -1;

        unordered_map<int, int> dist;          // 站点 -> 已乘车辆数
        dist[source] = 0;
        vector<char> usedRoute(n, 0);          // 线路是否已展开
        queue<int> q;
        q.push(source);

        while (!q.empty()) {
            int u = q.front();
            q.pop();
            int du = dist[u];
            for (int r : stopToRoutes[u]) {
                if (usedRoute[r]) continue;    // 每条线路只展开一次
                usedRoute[r] = 1;              // 先标记，再遍历
                for (int v : routes[r]) {
                    if (v == target) return du + 1;   // 第一次扫到即最优
                    if (!dist.count(v)) {
                        dist[v] = du + 1;
                        q.push(v);
                    }
                }
            }
        }
        return -1;
    }
};
```

### Python

```python
from collections import defaultdict, deque


class Solution:
    def numBusesToDestination(self, routes: list[list[int]], source: int, target: int) -> int:
        if source == target:
            return 0

        # 站点 -> 经过它的线路编号
        stop_to_routes = defaultdict(list)
        for i, stops in enumerate(routes):
            for s in stops:
                stop_to_routes[s].append(i)

        if source not in stop_to_routes or target not in stop_to_routes:
            return -1

        dist = {source: 0}                      # 站点 -> 已乘车辆数
        used_route = [False] * len(routes)      # 线路是否已展开
        q = deque([source])

        while q:
            u = q.popleft()
            du = dist[u]
            for r in stop_to_routes[u]:
                if used_route[r]:
                    continue
                used_route[r] = True            # 先标记，再遍历
                for v in routes[r]:
                    if v == target:
                        return du + 1           # 第一次扫到即最优
                    if v not in dist:
                        dist[v] = du + 1
                        q.append(v)
        return -1
```

## 8. 边界情况与易错点

1. **`source == target`**：答案 `0`（一辆车都不用坐），必须放在最前面特判；否则会一路 BFS 到尽头返回 `-1`，或错误地返回 `1`。
2. **起点/终点不在任何线路上**：`stopToRoutes` 里查不到，直接 `-1`；若省略这步，BFS 也会自然走到 `-1`，但显式判断更省时间也更清晰。
3. **同一站点属于多条线路**：`stop_to_routes[u]` 里可能有多条线路，必须全部枚举，不能「取第一条就走」。
4. **标记顺序**：`usedRoute[r] = true` 必须在遍历 `routes[r]` **之前**；否则同层多个站点可能把同一条线路重复展开，虽然结果仍然正确，但复杂度会退化。
5. **返回的是 `dist[u] + 1`**：不能写 `dist[target]`（此时还没赋值），也不能写 `dist[u]`。
6. **站点编号稀疏**（最大 $10^6$）：用哈希表或「数组 + 显式访问标记」，不要拿编号直接当下标去做 `1..maxStop` 的循环。
7. **超长单线路**：单条线路可达 $10^5$ 站，任何 $O(L^2)$ 的建边、去重、两两比较都会超时；必须依赖「展开一次 + 线性扫描」。

**延伸思考**：

1. 若线路有**行驶耗时**（每条线路给一个时间），要求「车辆数最少的前提下总时间最小」，就变成分层最短路：先 BFS 求最小车辆数 $k^{\ast}$，再在 $k^{\ast}$ 层内按时间做第二关键字（或者在二分图上跑 Dijkstra，代价放在线路边上）。这类题可以对比 [LeetCode 1928. 规定时间内到达终点的最小花费](https://leetcode.cn/problems/minimum-cost-to-reach-destination-in-time/)。
2. 若线路会被**动态增删**，`usedRoute` 的「一次性展开」就不再成立，需要维护连通块 + 每块的线路活跃度（类似并查集维护「块内可用线路数」），这就从 BFS 变成了动态连通性问题。
3. 一个常见的错误直觉是把 `source`、`target` 直接看成一端，然后求「最少换乘」——注意换乘次数 $= k-1$，而题目问的是乘坐车辆数 $k$，两者差 1，且 `source == target` 时 $k = 0$ 也不满足这个公式。
