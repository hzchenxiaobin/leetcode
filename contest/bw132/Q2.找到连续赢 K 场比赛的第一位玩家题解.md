# LeetCode 找到连续赢 K 场比赛的第一位玩家 题解

## 1. 题目概述

- **标题 / 题号**：找到连续赢 K 场比赛的第一位玩家（#3175，medium）
- **链接**：https://leetcode.cn/problems/find-the-first-player-to-win-k-games-in-a-row/
- **来源**：LeetCode 第 132 场双周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：$n$ 位玩家排成一列，编号 $0 \sim n-1$，技能值 `skills[i]` **互不相同**。每场比赛由队首两人对战，技能高者获胜并**留在队首**，败者排到队尾。求**第一位**连续赢下 $k$ 场比赛的玩家编号。

**约束**：

- $n = |\text{skills}|$，$2 \le n \le 10^5$
- $1 \le k \le 10^9$
- $1 \le \text{skills}[i] \le 10^6$
- `skills` 中的整数互不相同

> ⚠️ $k$ 可以到 $10^9$，**绝不能**真的模拟 $k$ 场比赛。

## 2. 示例

**示例 1**

```text
输入：skills = [4,2,6,3,9], k = 2
输出：2
解释：队列 [0,1,2,3,4]
      玩家 0 胜 1 → [0,2,3,4,1]
      玩家 2 胜 0 → [2,3,4,1,0]
      玩家 2 胜 3 → [2,4,1,0,3]，连胜 2 场，返回 2。
```

**示例 2**

```text
输入：skills = [2,5,4], k = 3
输出：1
解释：玩家 1（技能 5）先胜 0，再胜 2，再胜 0，连胜 3 场。
```

**示例 3（边界补充）**

```text
输入：skills = [3,1,2], k = 1
输出：0
解释：k = 1 时答案就是第一场比赛的胜者，玩家 0 技能最高，直接返回 0。
```

```text
输入：skills = [1,2,3], k = 10
输出：2
解释：k 远大于 n，玩家 2（技能 3）成为擂主后无人能敌，最终连胜 10 场。
```

## 3. 解题思路

### 3.1 暴力思路

用双端队列严格模拟：每场弹出队首两人、比较技能、胜者放回队首、败者放队尾，同时维护「当前连胜者」与「连胜数」，达到 $k$ 就返回。每场 $O(1)$，但可能要打 $k$ 场，$k = 10^9$、$n = 10^5$ 时是 $10^9$ 次操作，超时。

### 3.2 核心观察：挑战者的出场顺序是固定的

![核心：一轮扫描维护擂主与连胜数](images/bw132_q2_champion_model.svg)

仔细观察队列的演化：胜者始终留在队首，所以**队首永远是当前擂主**。而擂主的挑战者按什么顺序登场？一开始是 $1, 2, 3, \dots$；当某个挑战者 $i$ 击败擂主后，它成为新擂主，接下来的挑战者是 $i+1, i+2, \dots$。

也就是说：**挑战者严格按编号 $1, 2, \dots, n-1$ 的顺序各登场一次**，中间不会插入别人。这带来两个结论：

1. 只需一次 $O(n)$ 扫描就能还原前 $n-1$ 场比赛：维护 `champion`（擂主）与 `wins`（其当前连胜数）。若 `skills[i] > skills[champion]`，则挑战者接管，`champion = i`、`wins = 1`；否则擂主卫冕，`wins += 1`。任一时刻 `wins >= k` 就立即返回。
2. 一旦**全局最大值**成为擂主，它再也不会输（技能互不相同，没人比它高），于是它会一直连胜下去。

由此分两种情形：

- $k$ 较小：扫描过程中必然命中，直接返回当时的擂主；
- $k$ 较大（例如 $k \ge n$）：扫描完 $n-1$ 场仍未达到 $k$，此时擂主已是全局最大值的持有者，之后它每场都赢，答案就是它的下标。

两种情况被同一段代码覆盖：**循环结束后若还没返回，就返回当前的 `champion`**。

### 3.3 算法流程

![算法流程：一轮线性扫描，命中即返回](images/bw132_q2_algorithm_flow.svg)

```text
1. champion = 0, wins = 0
2. 对 i = 1 .. n-1：
       若 skills[champion] > skills[i]：wins += 1
       否则：champion = i, wins = 1
       若 wins >= k：返回 champion
3. 返回 champion          # 擂主已是全局最大值，之后必达 k 连胜
```

注意第 2 步「否则」分支里 `wins` 赋值为 **1** 而不是 0：挑战者赢下了当前这一场，它的连胜已经开始了。

### 3.4 示例演算

以示例 1（`skills = [4,2,6,3,9]`，$k = 2$）为例：

| 比赛 | 挑战者 $i$ | 比较 | 动作 | `champion` | `wins` |
|------|-----------|------|------|-----------|--------|
| 1 | 1（技能 2） | $4 > 2$ | 卫冕 | 0 | 1 |
| 2 | 2（技能 6） | $4 < 6$ | 易位 | 2 | 1 |
| 3 | 3（技能 3） | $6 > 3$ | 卫冕 | 2 | 2 = k → 返回 2 |

第 4 位玩家（技能 9）根本没被访问：答案在扫描途中就已确定。再看示例 2（`[2,5,4]`，$k = 3$）：$i=1$ 时 5 击败 2，易位后 `wins = 1`；$i=2$ 时 5 击败 4，`wins = 2`；扫描结束仍未到 3，返回 `champion = 1`——因为技能 5 是全局最大值，第 3 场它必赢。

## 4. 算法细节

1. **`champion` 与 `wins` 的语义**：`champion` 是「已登场玩家中的最大值持有者」，`wins` 是它自上次易位以来的连胜场数（易位时重置为 1）。
2. **`k` 的类型**：$k \le 10^9$ 在 32 位 `int` 范围内，但读入时用 `long long` 更稳妥，比较时转回即可；Python 无此顾虑。
3. **循环上界是 $n-1$ 而不是 $n$**：玩家 0 是初始擂主，不需要和自己比。$n-1$ 场之后擂主必为全局最大值。
4. **提前返回**：命中 `wins >= k` 立即 `return`，避免无谓扫描。
5. **不要真的维护队列**：队列轮转是「表象」，真正影响胜负的只有「谁在擂主位」与「下一个挑战者是谁」，而后者就是下标递增。
6. **技能互不相同**：这是「全局最大值一旦登顶就永不落败」的前提；若有并列，需要额外定义平局规则。
7. **答案一定存在**：全局最大值的持有者最终会赢下任意多场，所以函数不会无解。

## 5. 正确性证明

**引理 1（挑战者顺序）**：在任意时刻，若擂主为 $c$，则下一个挑战者是「尚未登场的最小下标」，且所有挑战者按 $1, 2, \dots, n-1$ 的顺序各出现一次。

**证明**：初始队列为 $0, 1, \dots, n-1$，队首为 0，故第一个挑战者是 1。每场比赛后，胜者留在队首，败者移到队尾；其余玩家相对顺序不变。因此队首之后的第一位始终是「下一个尚未交手的下标」——若擂主一直卫冕，则依次是 $2, 3, \dots$；若挑战者 $i$ 获胜，它成为擂主，队首之后第一位变为 $i+1$。无论哪种情况，下一次登场的都是当前未登场的最小下标，故挑战者序列恰为 $1, 2, \dots, n-1$。∎

**引理 2（擂主 = 已登场者的最大值）**：打完前 $t$ 场（即下标 $1..t$ 都已登场）后，擂主的技能值等于 $\max\{\text{skills}[0..t]\}$。

**证明**：对 $t$ 归纳。$t = 0$ 时擂主是 0，成立。设打完前 $t-1$ 场后擂主为 $c$ 且技能为前缀最大值。第 $t$ 场的挑战者是 $t$（引理 1），若 $\text{skills}[t] > \text{skills}[c]$ 则新擂主为 $t$，其技能是新的前缀最大值；否则擂主不变，仍是前缀最大值。∎

**推论**：打完 $n-1$ 场后，擂主是全局最大值的持有者，且此后每场都获胜。

**引理 3（首次命中）**：若算法在某个 $i$ 处返回 `champion`，则它是第一位连续赢下 $k$ 场的玩家。

**证明**：算法按时间顺序处理比赛，`wins` 精确等于当前擂主此刻的连胜场数（易位时重置为 1，卫冕时加 1）。第一次出现 `wins >= k` 的时刻，就是某位玩家首次达成 $k$ 连胜的时刻，而此时擂主正是该玩家。∎

**定理**：算法返回第一位连续赢下 $k$ 场比赛的玩家编号。

**证明**：分两种情形。
情形一：循环中命中 `wins >= k`。由引理 3，返回值正确。
情形二：循环结束仍未命中。由引理 2 的推论，擂主是全局最大值持有者 $m$，它在第 $n-1$ 场之后每场必赢；设此时 `wins = w < k`，则再打 $k - w$ 场后 $m$ 达成 $k$ 连胜。因为 $m$ 之后不会再输，它是**第一位**达成 $k$ 连胜的玩家（在它之前登场的玩家都至少输给过它一次，其连胜已被终结，且扫描已确认它们都没有达到 $k$）。故返回 $m$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个玩家最多被比较一次，命中即提前返回；与 $k$ 的大小无关。
- **空间**：$O(1)$。只维护 `champion` 与 `wins` 两个变量，不复制队列。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findWinningPlayer(std::vector<int>& skills, int k) {
        int n = (int)skills.size();
        int champion = 0, wins = 0;
        for (int i = 1; i < n; ++i) {
            if (skills[champion] > skills[i]) {
                ++wins;                       // 擂主卫冕
            } else {
                champion = i;                 // 挑战者接管，连胜数重置为 1
                wins = 1;
            }
            if (wins >= k) return champion;
        }
        return champion;                      // 一轮后擂主必为全局最大值
    }
};
```

### Python

```python
class Solution:
    def findWinningPlayer(self, skills: list[int], k: int) -> int:
        n = len(skills)
        champion, wins = 0, 0
        for i in range(1, n):
            if skills[champion] > skills[i]:
                wins += 1                     # 擂主卫冕
            else:
                champion, wins = i, 1         # 挑战者接管，连胜数重置为 1
            if wins >= k:
                return champion
        return champion                       # 一轮后擂主必为全局最大值
```

> 💡 两份代码通过题面 2 个示例与补充示例（$k = 1$、$k \gg n$），并与「双端队列严格模拟」的参考实现做了 300 组随机对拍（$n \le 7$、$k \le 12$，覆盖 $k > n$ 的情形），`mismatch = 0`；$n = 10^5$、$k = 10^9$ 时 C++ 约 0.01 s、Python 约 0.04 s。

## 8. 边界情况与易错点

1. **$k = 1$**：答案是第一场（玩家 0 与 1）的胜者；循环第一轮就会命中，注意易位分支里 `wins` 必须是 1。
2. **$k \ge n$**：答案一定是全局最大值的下标；循环会自然结束并返回 `champion`，不要额外写特判（写了也无害）。
3. **易位时把 `wins` 置 0**：这是最常见的错误——挑战者刚赢了一场，连胜数应当是 1，置 0 会少算一场，$k = 1$ 时直接错。
4. **最大值在 0 号位**：擂主从头卫冕到尾，`wins` 一路累加到 $n-1$；若 $k > n-1$，循环结束返回 0，正确。
5. **递减数组**：如 `[5,4,3,2,1]`，擂主一直是 0，答案为 0（$k$ 任意）。
6. **`k` 溢出**：$10^9$ 用 `int` 尚可，但若乘积或自增接近上界，建议直接用 `long long`。
7. **真的去模拟队列**：$k = 10^9$ 时会 TLE；即便用 `deque` 每场 $O(1)$，常数也远大于本题的 $O(n)$ 扫描。
8. **误以为要处理「平局」**：题面保证技能互不相同，无需考虑相等。
