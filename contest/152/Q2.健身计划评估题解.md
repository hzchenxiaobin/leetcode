# LeetCode 健身计划评估 题解

## 1. 题目概述

- **标题 / 题号**：健身计划评估（#1176，easy）
- **链接**：https://leetcode.cn/problems/diet-plan-performance/
- **来源**：LeetCode 第 152 场周赛 Q2
- **难度**：简单
- **标签**：数组、滑动窗口、前缀和

**题意**：第 $i$ 天摄入 `calories[i]` 千卡。对**每个长度为 $k$ 的连续区间**（下标 $0 \le i \le n-k$）求和得到 $T$：若 $T < \text{lower}$ 扣 1 分；若 $T > \text{upper}$ 加 1 分；否则分数不变。初始 0 分，返回吃完 $n$ 天后的**总分**（可能为负）。

**约束**：

- $1 \le k \le \text{calories.length} \le 10^5$
- $0 \le \text{calories}[i] \le 20000$
- $0 \le \text{lower} \le \text{upper}$

## 2. 示例

**示例 1**

```text
输入：calories = [1,2,3,4,5], k = 1, lower = 3, upper = 3
输出：0
解释：k = 1，逐个元素比较：
      calories[0]=1、calories[1]=2 小于 lower → 扣 2 分；
      calories[3]=4、calories[4]=5 大于 upper → 加 2 分；
      calories[2]=3 落在 [3,3] → 不变。总分 −2 + 2 = 0。
```

**示例 2**

```text
输入：calories = [3,2], k = 2, lower = 0, upper = 1
输出：1
解释：唯一的窗口 [0,1]，T = 3 + 2 = 5 > upper = 1 → 加 1 分。
```

**示例 3**

```text
输入：calories = [6,5,0,0], k = 2, lower = 1, upper = 5
输出：0
解释：窗口 [0,1]：T = 11 > 5 → 加 1 分；
      窗口 [1,2]：T = 5，满足 1 ≤ 5 ≤ 5 → 不变；
      窗口 [2,3]：T = 0 < 1 → 扣 1 分。总分 +1 + 0 − 1 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个起点 $i \in [0, n-k]$，再内层循环把 `calories[i..i+k-1]` 重新累加一次：

$$O\bigl((n-k+1)\cdot k\bigr)$$

最坏情况 $k \approx n/2$，运算量约 $2.5 \times 10^{9}$，在 $n = 10^5$ 时必然超时。而相邻窗口之间有 $k-1$ 个元素是**重叠**的，重复求和做了大量无用功。

### 3.2 核心观察：相邻窗口只差一头一尾

![滑动窗口与三段判定](images/wc152_q2_window_model.svg)

设当前窗口为 `[left, left+k-1]`，和为 $S$。把它右移一格后，窗口变成 `[left+1, left+k]`：

$$S' = S - \text{calories}[left] + \text{calories}[left+k]$$

即**减掉移出的左端、加上新进的右端**，一次加法和一次减法就是 $O(1)$。于是我们只需在开始时花 $O(k)$ 算出第一个窗口的和，之后每个窗口 $O(1)$ 更新、$O(1)$ 判定，总计 $O(n)$。

判分规则本身是**三段互斥完备**的划分，用一个 `if / else if` 即可，不存在「既小于 lower 又大于 upper」的歧义（因为 $\text{lower} \le \text{upper}$）。

### 3.3 算法流程

![算法流程图](images/wc152_q2_flow.svg)

1. `window = calories[0] + … + calories[k-1]`，`ans = 0`；
2. `left` 从 $0$ 遍历到 $n-k$：
   - 若 `left > 0`，先用「减左加右」把 `window` 平移到新窗口（第一个窗口已经算好，不能重复加减）；
   - 若 `window < lower`，`ans -= 1`；
   - 否则若 `window > upper`，`ans += 1`；
   - 否则不变；
3. 循环结束返回 `ans`。

> 💡 关键点：**先滑动、再判定**，且第一个窗口要跳过滑动这一步。若写成「先判定、再滑动」，则循环要看住 `left+k < n` 的右边界，容易多算一个越界窗口。

### 3.4 示例演算

![示例 3 走查](images/wc152_q2_walkthrough.svg)

以示例 3（`calories = [6,5,0,0]`，$k=2$，$\text{lower}=1$，$\text{upper}=5$）为例，共 $n-k+1 = 3$ 个窗口：

| 窗口 | left | 求 $T$ 的方式 | $T$ | 与 $[\text{lower},\text{upper}]$ 比较 | 本窗口得分 | ans |
|------|------|----------------|-----|----------------------------------------|-----------|-----|
| `[0,1]` | 0 | $6+5$（初始累加） | 11 | $11 > 5$ | $+1$ | 1 |
| `[1,2]` | 1 | $11-6+0 = 5$ | 5 | $1 \le 5 \le 5$ | $0$ | 1 |
| `[2,3]` | 2 | $5-5+0 = 0$ | 0 | $0 < 1$ | $-1$ | 0 |

返回 `ans = 0`，与官方输出一致。注意第 2、3 个窗口的和都是从**上一个窗口的和**推出来的，全程没有重新累加两个元素。

## 4. 算法细节

1. **初始化窗口**：用 `sum(calories[:k])` / 循环累加前 $k$ 个元素，$O(k)$。此时 `left = 0` 的窗口已就绪。
2. **滑动顺序**：循环从 `left = 0` 开始，`left > 0` 时才做 `window += calories[left+k-1] - calories[left-1]`。`left-1` 是移出的下标，`left+k-1` 是移入的下标，二者恰好一进一出。
3. **循环上界**：`left + k <= n`，即 `left <= n - k`，共有 $n-k+1$ 个窗口。写成 `left + k - 1 < n` 或 `range(n - k + 1)` 等价，但别写成 `< n`，否则最后一次会越界访问 `calories[left+k-1]`。
4. **三段判定的写法**：`if (T < lower) --ans; else if (T > upper) ++ans;`。因为 `lower <= upper`，两段不会同时成立；当 `lower == upper` 时中间段退化为单点 $T = \text{lower}$，`if / else if` 依然正确。
5. **累加变量用 64 位**：单个元素最大 $20000$，窗口长度最大 $10^5$，窗口和上界 $2 \times 10^{9}$，虽然勉强落在 `int` 内（$2.147\times10^9$），但为了不依赖这个巧合，C++ 里用 `long long` 存窗口和；Python 整数无溢出。
6. **答案可以为负**：`ans` 初值 0，最后直接返回，**不要**在过程中取 `max(ans, 0)` 或把它当初值上界使用。
7. **不要用前缀和数组**：前缀和也能 $O(1)$ 求任意区间和，但要额外 $O(n)$ 空间；本题窗口定长且单调右移，滚动变量更省。

## 5. 正确性证明

**引理 1（窗口和正确）**：循环中变量 `window` 在第 $i$ 轮开始时（滑动之后）等于 $\sum_{j=i}^{i+k-1}\text{calories}[j]$。

**证明**：对 `left` 归纳。`left = 0` 时由初始化直接成立。设 `left = i-1` 时成立，即 `window` $= \sum_{j=i-1}^{i+k-2}\text{calories}[j]$。第 $i$ 轮执行

$$\text{window} \leftarrow \text{window} - \text{calories}[i-1] + \text{calories}[i+k-1] = \sum_{j=i}^{i+k-1}\text{calories}[j]$$

减去的正是上一窗口独有的左端，加入的正是新窗口独有的右端，中间 $k-1$ 项不变，故第 $i$ 轮成立。∎

**引理 2（判分正确）**：对任意实数 $T$ 与 $0 \le \text{lower} \le \text{upper}$，三段 `T < lower`、`lower <= T <= upper`、`T > upper` 恰好覆盖全部情况且两两不交，`if / else if` 给出的增减分与题面规则一致。

**证明**：若 $T < \text{lower}$，第一分支命中，扣 1 分，与题面「perform poorly」一致；此时 $T > \text{upper}$ 不可能成立（否则 $\text{lower} > T > \text{upper} \ge \text{lower}$，矛盾），故不会误加。若 $T \ge \text{lower}$ 且 $T > \text{upper}$，第二分支命中，加 1 分；否则 $T \le \text{upper}$，三段条件给出 $\text{lower} \le T \le \text{upper}$，分数不变，与题面「perform normally」一致。∎

**定理**：算法返回的值等于按题面规则统计出的总分。

**证明**：由引理 1，每个 `left` 判定时 `window` 就是该窗口的真实和；由引理 2，每轮对 `ans` 的改动恰好是该窗口应得的分值；循环恰好遍历 $n-k+1$ 个合法窗口各一次（第 3 节的上界分析），没有遗漏也没有重复，故累加结果即总分。∎

## 6. 复杂度分析

- **时间**：$O(n)$。初始化窗口 $O(k)$；主循环 $n-k+1$ 轮，每轮常数次加法比较；总计 $O(n + k) = O(n)$。
- **空间**：$O(1)$。只用了 `window`、`ans`、循环变量；不申请前缀和数组、不拷贝切片（Python 的 `sum(calories[:k])` 会临时拷贝 $k$ 个元素，若想避免可写成 `sum(calories[i] for i in range(k))`，但通常无必要）。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int dietPlanPerformance(vector<int>& calories, int k, int lower, int upper) {
        int n = calories.size();
        long long window = 0;
        for (int i = 0; i < k; ++i) window += calories[i];   // 第一个窗口
        int ans = 0;
        for (int left = 0; left + k <= n; ++left) {
            if (left > 0) {                                   // 先滑动，再判定
                window += calories[left + k - 1] - calories[left - 1];
            }
            if (window < lower) {
                --ans;
            } else if (window > upper) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def dietPlanPerformance(self, calories: List[int], k: int, lower: int, upper: int) -> int:
        window = sum(calories[:k])       # 第一个长度为 k 的窗口
        ans = 0
        for left in range(len(calories) - k + 1):
            if left > 0:                 # 右移一格：减左端、加右端
                window += calories[left + k - 1] - calories[left - 1]
            if window < lower:
                ans -= 1
            elif window > upper:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **$k = n$**：只有一个窗口，主循环只跑 `left = 0` 一轮且不进入滑动分支，答案只能是 $-1$、$0$ 或 $1$。若把滑动放在判定之前，就会访问 `calories[left-1]` 越界。
2. **$k = 1$**：每个元素自成一个窗口，退化成逐元素与 `lower / upper` 比较，例 1 即此情形。
3. **$\text{lower} = \text{upper}$**：中间段只剩单点 $T = \text{lower}$，`if / else if` 仍正确；但若写成两个独立的 `if`，$T$ 同时等于上下界时可能被误加减分。
4. **答案可为负**：例如 `calories = [1], k = 1, lower = 5, upper = 9` 返回 $-1$。因此最终答案不能用「非负」假设，中途也不要做 `max(ans, 0)`。
5. **越界下标**：滑入位置是 `left + k - 1`（不是 `left + k`），滑出位置是 `left - 1`；这两处是最常见的差一错误，建议先手算 $k = 2$、$n = 4$ 的最后一轮确认。
6. **溢出**：窗口和上界 $2\times10^9$ 贴近 `int` 上限，C++ 用 `long long` 更稳妥；Python 无需考虑。
7. **空数组**：题目保证 $k \ge 1$ 且 $k \le n$，不会出现 $n = 0$，但把代码复用到其他题时应自行判空。
