# LeetCode 合并若干三元组以形成目标三元组 题解

## 1. 题目概述

- **标题 / 题号**：合并若干三元组以形成目标三元组（#1899，medium）
- **链接**：https://leetcode.cn/problems/merge-triplets-to-form-target-triplet/
- **来源**：LeetCode 第 245 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定二维整数数组 `triplets`（$triplets[i] = [a_i, b_i, c_i]$）与目标 $target = [x, y, z]$。可执行**任意多次**（含 0 次）如下操作：选两个**不同**下标 $i \ne j$，把 $triplets[j]$ 原地更新为 $[\max(a_i, a_j), \max(b_i, b_j), \max(c_i, c_j)]$（$triplets[i]$ 保持不变）。判断经过若干操作后，$target$ 能否成为 `triplets` 的一个元素，能则返回 `true`。

**约束**：

- $1 \le n = \text{triplets.length} \le 10^5$
- $triplets[i].\text{length} = \text{target.length} = 3$
- $1 \le a_i, b_i, c_i, x, y, z \le 1000$

> 💡 **切入信号**：操作是「逐维取 $\max$」⇒ 天然携带两条代数性质：**单调性**（$\max$ 只增不减，某维一旦超过 $target$ 对应维就永久无法回退）与**交换律 + 结合律**（合并结果只取决于参与合并的**集合**，与顺序无关）。字面是「过程模拟」题，实质是「集合聚合」题——遇到运算具有良好代数性质的题，正确动作是先把过程塌缩掉，再谈算法。

> 💡 本题在本仓库另有[每日题解 1899](../../solution/1801-1900/1899_合并若干三元组以形成目标三元组.md)：侧重面试问答与「filter + 逐维 max」的写法对照。本篇按周赛复盘视角，聚焦**可达性的完整刻画（§5 引理-定理）**、「中间产物不提供新信息」的论证与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：triplets = [[2,5,3],[1,8,4],[1,7,5]], target = [2,7,5]
输出：true
解释：合并第 1 个和第 3 个：[max(2,1), max(5,7), max(3,5)] = [2,7,5]，
      target 成为 triplets 的元素。
```

**示例 2**

```text
输入：triplets = [[1,3,4],[2,5,8]], target = [2,5,8]
输出：true
解释：target 本来就是 triplets 的元素（0 次操作即可）。
```

**示例 3**

```text
输入：triplets = [[2,5,3],[2,3,4],[1,2,5],[5,2,3]], target = [5,5,5]
输出：true
解释：[2,5,3] ⊕ [1,2,5] = [2,5,5]，再 ⊕ [5,2,3] = [5,5,5]。
```

**示例 4**

```text
输入：triplets = [[3,4,5],[4,5,6]], target = [3,2,5]
输出：false
解释：[3,4,5] 因 4 > 2 无法参与，[4,5,6] 因 4 > 3（且 6 > 5）无法参与，
      没有任何三元组能提供第二维的 2。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是**模拟**：枚举所有可能的合并序列——每一步有 $\Theta(n^2)$ 种 $(i, j)$ 选择，序列长度可达 $n - 1$，组合数是天文数字。退一步，即便想到「合并顺序无关，只需枚举子集」，也要枚举 $2^n$ 个子集 $S$、对每个求逐维 $\max$ 再与 $target$ 比对，$n \le 10^5$ 下同样不可行。

> ⚠️ 暴力卡在**过程爆炸与子集爆炸**。但「枚举子集 + 求逐维 max」这个视角已经暴露了关键：每个子集的合并结果是**平凡可计算**的确定值 $M(S)$——爆炸的只是子集数量。这强烈暗示存在一个**代表性子集**，查它一个就够（§3.2 第三步）。

### 3.2 核心观察：越界即弃 + 全集聚合

![核心观察：max 单调 ⇒ 越界即弃，结合律 ⇒ 顺序无关，全集 max 是唯一代表](images/wc245_q3_max_monotone_concept.svg)

**第一步（可用性）：一维越界，整体弃用。**

$\max$ 只增不减。若某三元组 $t = [a, b, c]$ 有某一维超过 $target$ 对应维（如 $a > x$），则 $t$ 参与的任何合并，其产物第一维 $\ge a > x$，**永久无法等于** $x$。又因合并是**逐维同时**进行的，无法「只借它好的维度、避开坏的维度」。故：

$$t \text{ 可用} \iff a \le x \;\land\; b \le y \;\land\; c \le z$$

记全体可用三元组的下标集为 $U$。

**第二步（聚合）：合并顺序无关，结果是集合的逐维 max。**

$\max$ 满足交换律、结合律与幂等律，故把集合 $S$ 中的三元组按**任意**顺序两两合并（含用中间产物继续合并），结果恒为

$$M(S) = \left[\max_{i \in S} a_i,\; \max_{i \in S} b_i,\; \max_{i \in S} c_i\right]$$

于是「$target$ 可达」$\iff$「存在非空 $S$ 使 $M(S) = target$」。

**第三步（代表元）：只查 $M(U)$ 一个。**

由第一步，可行的 $S$ 必满足 $S \subseteq U$；由 $M$ 关于集合包含的单调性，$M(U)$ 的每一维既不低于任何候选子集的聚合，又不超过 $target$（$U$ 的定义保证）。双向夹逼：

$$\exists\, S:\ M(S) = \text{target} \iff M(U) = \text{target}$$

**一遍扫描**即可判定：过滤越界、对可用者累积逐维 $\max$、最后与 $target$ 比对。

> 💡 **同类范式**：这是「单调聚合 + 目标封闭 ⇒ 检查最大候选」的极值论证，与[每日题解 2505. 所有子序列和的按位或](../../solution/2501-2600/2505_所有子序列和的按位或.md)中「按位 OR 只置位不清位」的位聚合思想同源：都用运算的代数性质把指数级的子集枚举塌缩成一次线性扫描。

### 3.3 算法流程

![算法流程：过滤越界 → 逐维聚合 max → 比对 target](images/wc245_q3_filter_max_flow.svg)

1. **初始化**：三个标量 $ra = rb = rc = 0$（累积逐维最大值）。
2. **单遍扫描**每个三元组 $t = [a, b, c]$：若 $a \le x$ 且 $b \le y$ 且 $c \le z$（三维全不越界），更新 $ra = \max(ra, a)$、$rb = \max(rb, b)$、$rc = \max(rc, c)$；否则跳过。
3. **比对**：返回 $[ra, rb, rc] = [x, y, z]$ 是否成立。

### 3.4 示例演算

![示例演算：例 1 过滤 + 累积 max 达标，例 4 全军覆没](images/wc245_q3_example_walkthrough.svg)

**例 1**（`target = [2,7,5]`，返回 `true`）：

| 步骤 | 三元组 $t$ | 越界判定 | 操作 | res |
|------|-----------|----------|------|-----|
| 0 | — | — | 初始化 | $[0,0,0]$ |
| 1 | $[2,5,3]$ | 否 | 并入 | $[2,5,3]$ |
| 2 | $[1,8,4]$ | **是**（$8 > 7$） | 跳过 | $[2,5,3]$ |
| 3 | $[1,7,5]$ | 否 | 并入 | $[2,7,5]$ |
| 4 | — | — | 比对 | $[2,7,5] = target$ ✓ |

**例 4**（`target = [3,2,5]`，返回 `false`）：$[3,4,5]$ 因 $4 > 2$ 弃、$[4,5,6]$ 因 $4 > 3$（且 $6 > 5$）弃，可用集为空，`res` 保持 $[0,0,0] \ne target$。

**例 3**（`target = [5,5,5]`，返回 `true`）：四个三元组全部可用，`res` 依次演进 $[2,5,3] \to [2,5,4] \to [2,5,5] \to [5,5,5]$，与官方两步合并的操作序列一一对应。

## 4. 算法细节

1. **过滤条件一次判定**：`t[0] <= x && t[1] <= y && t[2] <= z` 是「一票否决」式的合取——三维**同时**不越界才可用。注意是 $\le$ 而非 $<$：某维**恰好等于** $target$ 对应维的三元组不仅可用，而且恰恰是「有贡献」的（示例 2 中 `target` 本身已在数组里）。
2. **累积变量初值取 $[0,0,0]$ 安全**：值域下界为 $1$，而 $target$ 每维 $\ge 1$，故空可用集时 $[0,0,0]$ 必不等于 $target$，**无需特判**。若值域允许 $0$，应改用 $-\infty$ 哨兵或换用下面的布尔变体。
3. **等价变体（三维独立布尔）**：由可用性知每个可用三元组各维 $\le target$ 对应维，故「该维的 $\max$ 恰为 $target$ 对应维」$\iff$「存在某个可用三元组在该维**恰好取到** $target$ 值」。于是可用三个布尔 $f_x, f_y, f_z$ 替代三个数值累积（§7 Python 版二）。这把问题拆成三个**完全独立**的「精确达到」判定，推广到 $k$ 维时更自然。
4. **中间产物不提供新信息**：操作把 `triplets[j]` **原地**更新，合并产物可以继续作为原料参与后续合并。但由 §5 引理 1，任何时刻每个位置上的值都是某个「原始下标集合」的 $M$——把产物再并入，等价于直接并入它背后的整个集合。产物不会产生 $U$ 之外的值，更不可能「绕开」越界（$\max$ 只会更大不会更小）。
5. **不要排序、不要堆、不要 DP**：「合并」的字面语义是过程，容易诱导排序 / 贪心选对 / 区间合并式的思路；本题的代数性质把过程彻底塌缩，正确形态就是一遍聚合。赛场上若发现自己在模拟合并过程，应立即回头审视 $\max$ 的代数性质。
6. **值域 $\le 1000$ 与复杂度无关**：无需计数数组或桶，判定与值域无关；$n \le 10^5$ 下 $O(n)$ 单遍扫描绰绰有余。

## 5. 正确性证明

**引理 1（集合表示 / 顺序无关）**：对任意操作序列，任意时刻每个位置 $j$ 上的值等于 $M(S_j)$，其中 $S_j \subseteq [n]$ 是「已并入位置 $j$」的原始三元组下标集合（初始 $S_j = \{j\}$）；每次操作 $(i, j)$ 恰使 $S_j \leftarrow S_j \cup S_i$，其余不变。因此操作结束后 `triplets` 中出现的值都属于 $\{M(S) : \varnothing \ne S \subseteq [n]\}$；反之，任意非空 $S$ 的 $M(S)$ 都可经 $|S| - 1$ 步操作出现在 `triplets` 中。

**证明**：对操作步数归纳。基础：0 步时 $S_j = \{j\}$，$v_j$ 即原始三元组 $= M(\{j\})$。归纳步：操作 $(i, j)$ 后

$$v_j' = \text{逐维}\max(v_i, v_j) = \text{逐维}\max(M(S_i), M(S_j)) = M(S_i \cup S_j)$$

（逐维运用 $\max$ 的交换律、结合律与幂等律 $\max(u, u) = u$），且 $S_i$ 侧不变，不变量保持。可达性方向：对 $S = \{i_1, \dots, i_k\}$，依次执行以 $i_1$ 为被更新方的操作 $(i_t, i_1)$，$t = 2, \dots, k$，经 $k - 1$ 步后位置 $i_1$ 上的值即 $M(S)$。∎

**引理 2（越界即弃）**：若非空 $S \subseteq [n]$ 满足 $M(S) = target$，则 $S$ 中每个三元组的每一维都 $\le target$ 对应维（即 $S \subseteq U$）。

**证明**：$M(S)$ 的每一维是 $S$ 中该维的最大值，不小于 $S$ 中**任何**成员在该维的取值；而 $M(S) = target$，故每个成员每维 $\le target$ 对应维。∎

**定理**：$target$ 可成为 `triplets` 的一个元素 $\iff M(U) = target$（$U$ 为可用下标全集，约定 $M(\varnothing) = [0, 0, 0]$，与代码初值一致）。

**证明**：

（⇒）若可行，由引理 1 存在非空 $S$ 使 $M(S) = target$；由引理 2，$S \subseteq U$。逐维地，

$$\max_{i \in U}(\cdot) \;\ge\; \max_{i \in S}(\cdot) = \text{target 对应维}，\qquad \text{又由 } U \text{ 的定义}，\;\max_{i \in U}(\cdot) \le \text{target 对应维}$$

二者夹逼得 $M(U)$ 每维 $= target$ 对应维。

（⇐）若 $M(U) = target$，则 $U$ 非空（$target$ 每维 $\ge 1 > 0$）。由引理 1 的可达性方向，把 $U$ 中元素逐一并入同一位置，$|U| - 1$ 步后 $target$ 出现在 `triplets` 中。∎

> 💡 论证骨架是「**单调聚合下的夹逼论证**」：候选全体（$U$）对并入封闭、聚合结果被 $target$ 封闭在上，最大候选 $M(U)$ 被「$\ge$ 任一子集」与「$\le target$」双向夹住——「存在子集恰好达标」于是等价于「最大候选恰好达标」。与子序列贪心中「最早匹配不亏」同属「把搜索空间压缩到唯一代表元」的范式，只不过这里是**代数压缩**，那边是**贪心压缩**。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单遍扫描，每个三元组做 $O(1)$ 的越界判定（三次比较）与至多三次 $\max$ 更新。$n \le 10^5$，一遍即出。
- **空间复杂度**：$O(1)$。仅三个标量 $ra, rb, rc$（或三个布尔），与输入规模无关；过滤与聚合在同一循环内完成，不产生可用集的副本。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool mergeTriplets(vector<vector<int>>& triplets, vector<int>& target) {
        int x = target[0], y = target[1], z = target[2];
        int ra = 0, rb = 0, rc = 0;
        for (auto& t : triplets) {
            if (t[0] <= x && t[1] <= y && t[2] <= z) {  // 三维全不越界才可用
                ra = max(ra, t[0]);
                rb = max(rb, t[1]);
                rc = max(rc, t[2]);
            }
        }
        return ra == x && rb == y && rc == z;
    }
};
```

### Python

```python
class Solution:
    def mergeTriplets(self, triplets: List[List[int]], target: List[int]) -> bool:
        x, y, z = target
        ra = rb = rc = 0
        for a, b, c in triplets:
            if a <= x and b <= y and c <= z:
                ra = max(ra, a)
                rb = max(rb, b)
                rc = max(rc, c)
        return (ra, rb, rc) == (x, y, z)
```

### Python（三维独立布尔变体）

```python
class Solution:
    def mergeTriplets(self, triplets: List[List[int]], target: List[int]) -> bool:
        x, y, z = target
        fx = fy = fz = False
        for a, b, c in triplets:
            if a <= x and b <= y and c <= z:  # 必须先过滤，越界者无置位资格
                fx |= (a == x)
                fy |= (b == y)
                fz |= (c == z)
        return fx and fy and fz
```

> 💡 两版等价（§4.3）：数值版累积「最接近上界的 max」，布尔版记录「每维是否被精确达到」——由可用性 $\le target$，max 达到上界 $\iff$ 某个可用三元组恰好取到上界。布尔版的置位**必须**放在可用性判定内部，否则越界三元组会凭「碰巧相等」的维度污染结果（§8.8）。

## 8. 边界情况与易错点

1. **过滤必须三维同时判定**：合并逐维同时进行，只要一维越界整个三元组作废，**不存在**「部分使用」。典型诱惑：看到 $[1, 8, 4]$ 的第一、三维都「很有用」就想保留——但它一旦参与，第二维永久 $> 7$。
2. **是 $\le$ 不是 $<$**：恰好等于 $target$ 某维的三元组是最有用的参与者；把过滤写成严格小于会把示例 2（`target` 已在数组中）判成 `false`。
3. **不要模拟合并过程**：排序、堆、逐对合并、枚举顺序都是过程思维陷阱；也不要把本题类比成「区间合并」——同名「合并」，语义毫无交集。
4. **初值 $[0,0,0]$ 的安全性依赖值域 $\ge 1$**：空可用集时 `res` 保持初值，因 $target$ 每维 $\ge 1$ 而 $[0,0,0] \ne target$，天然返回 `false`。若值域含 $0$（如 $target = [0, y, z]$），数值版会把「空集」误判成可行，须换 $-\infty$ 哨兵或布尔版。
5. **「中间产物绕开越界」是幻觉**：产物每维已是某子集的 $\max$，只会更大不会更小；指望「先合并出中间三元组再稀释回去」违背 $\max$ 的单调性（§4.4、§5 引理 1）。
6. **$n = 1$**：仅当该三元组恰为 $target$（0 次操作）时可行；算法自然涵盖——可用时 `res` 即其本身，判等即所求。
7. **target 含「无处取到的值」**（示例 4 第二维的 $2$）：该维 `res` 达不到 $target$，返回 `false`，代码自动涵盖，无需预判值域。
8. **布尔变体的置位资格**：置位必须在可用性判定**内部**。反例：$triplets = [[3,4,7],[1,1,6]]$，$target = [3,4,6]$——正确答案 `false`（$[3,4,7]$ 越界弃用，$[1,1,6]$ 撑不起前两维）；若不过滤直接查相等，$[3,4,7]$ 会误置 $f_x, f_y$，叠加 $[1,1,6]$ 的 $f_z$ 后错误地返回 `true`。
9. **读题别丢「任意次（含 0 次）」**：0 次操作合法对应「$target$ 已在数组中」的平凡情形，由 $|S| = 1$ 的单元素集合覆盖（引理 1），算法无需分支。

**延伸思考**：① **改问最少操作次数**：由引理 1，$k$ 个三元组聚到一处恰需 $k - 1$ 步，故答案 = 「覆盖三维所需的最少可用三元组数」$- 1$。每个可用三元组覆盖「它与 $target$ 相等的那些维」，这是 3 个元素上的集合覆盖：单个全覆盖（$t = target$）→ 0 步；两个拼满 → 1 步；每维各一个 → 2 步；否则不可行，仍是 $O(n)$ 分类讨论。② **操作改为逐维取 $\min$**：完全对称——低于 $target$ 对应维的三元组「越下界即弃」，对剩余取逐维 $\min$ 判等。③ **推广到 $k$ 维 $k$ 元组**：算法不变，$O(nk)$；维数大时可换布尔版，把「每维是否被可用元素精确达到」拆成 $k$ 个独立判定。
