# LeetCode 重新分配字符使所有字符串都相等 题解

## 1. 题目概述

- **标题 / 题号**：重新分配字符使所有字符串都相等（#1897，easy）
- **链接**：https://leetcode.cn/problems/redistribute-characters-to-make-all-strings-equal/
- **来源**：LeetCode 第 245 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、计数

**题意**：给定字符串数组 `words`（下标从 0 开始）。每步操作需选出两个**不同**下标 $i \ne j$（$words[i]$ 非空），把 $words[i]$ 中的**任一**字符移动到 $words[j]$ 中的**任一**位置上。可以执行任意步操作，问能否使 `words` 中的每个字符串都相等，能则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \text{words[i].length} \le 100$
- `words[i]` 由小写英文字母组成

> 💡 **签到题切入**：题面三个条件直接决定解法形态——① 操作可执行**任意步**、每步只搬一个字符 ⇒ 字符在串之间几乎**自由流动**；② 目标位置**任选** ⇒ 串内字符顺序无关紧要，每个串只剩「字符多重集合」这一信息量；③ 问的是「能否」而非「最少几步」 ⇒ 判定性问题，应去找**不变量 + 充要条件**，而不是模拟过程。三点合起来：只需统计**每个字母在所有串中的总数**，看能否被 $n$ 整除。

> 💡 本题在本仓库另有[每日题解 1897](../../solution/1801-1900/1897_重新分配字符使所有字符串都相等.md)：侧重「枚举目标模板的暴力为何多余」的推导与面试问答。本篇按周赛复盘视角，聚焦签到题从题面到 AC 的最短路径——**识别守恒量 → 整除性判定**，并补齐引理-定理化的完整正确性证明（含「多重集配平之后，为何还能把各串排成同一顺序」这一常被一笔带过的环节，§5 引理 3）与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：words = ["abc","aabc","bc"]
输出：true
解释：将 words[1] 中的第一个 'a' 移动到 words[2] 的最前面，
      使 words[1] = "abc" 且 words[2] = "abc"，所有字符串都等于 "abc"。
```

**示例 2**

```text
输入：words = ["ab","a"]
输出：false
解释：执行操作无法使所有字符串都相等。
```

**示例 3（自拟，验证「顺序无关」）**

```text
输入：words = ["ba","ab"]
输出：true
解释：两个串的多重集合已经相同（各含 1a 1b），仅顺序不同：
      total(a) = 2, total(b) = 2, n = 2，均可整除。
      例如：从 "ba" 移出 'b' 插入 "ab" 得 "bab" → 再从 "bab" 移出 'b' 插回 "a" 尾部，
      得 ["ab","ab"]。
```

## 3. 解题思路

### 3.1 暴力思路

思维上的第一反应是把「所有串的当前内容」当作状态节点、每次搬运当作一条边，用 BFS 搜索判可达。但状态空间是 $n$ 个串内容的组合，随搬运步数近乎无界，彻底不可行。

现实一点的做法是**枚举目标模板**：既然要全等，总得有一个目标串 $T$，不妨枚举 `words` 中每个串充当 $T$，验证对每个字母 $c$ 都有

$$\text{total}(c) = n \times T.\text{count}(c)$$

这个验证 $O(n \cdot 26)$，在本题数据规模下也能 AC。但它做了多余的功：`total(c) = n · T.count(c)` 等价于 `total(c)` 能被 $n$ 整除——**与 $T$ 具体取哪个串无关**，枚举 $n$ 个候选纯属浪费。

> ⚠️ 暴力的瓶颈在于「绕道构造」：先猜一个目标，再验证。而目标的存在性其实被整除性**自动保证**——$k_c = \text{total}(c) / n$ 一旦确定，任意「$k_a$ 个 a、$k_b$ 个 b、……」的串都是合法目标。绕开构造，判定退化为纯数值条件。

### 3.2 核心观察：总数守恒 + 整除判定

![核心观察：字符可自由搬运，只看各字母总数能否被 n 整除](images/wc245_q1_count_divisibility_concept.svg)

关键观察分两层：

**第一层——守恒量**。操作只在串之间搬运字符，不增也不减任何字符，因此每个字母 $c$ 在**所有串中的总数** $\text{total}(c)$ 是操作前后的**不变量**。判定可行性时，它是唯一需要关心的全局量。

**第二层——充要条件**。$n$ 个串最终全相等，等价于每个串的字符多重集合相同，等价于每串恰含 $k_c = \text{total}(c) / n$ 个 $c$，等价于

$$\forall c \in \Sigma:\quad \text{total}(c) \bmod n = 0$$

- **不整除即无解**（必要性）：$n$ 串全等时 $\text{total}(c) = n \cdot k_c$ 必是 $n$ 的倍数；而 $\text{total}(c)$ 又是守恒量，初始时就必须满足整除——如示例 2 中唯一的 `b`，无论怎么搬，总有一个串含 `b` 而另一个不含，永远不可能相等。
- **整除即有解**（充分性）：令 $k_c = \text{total}(c)/n$，目标串 $T$（「$k_c$ 个各字母」的任意排列）自动存在；「多的搬到少的」总能把每串配平成 $T$ 的字母异位词，再把各串排成同一顺序（完整构造见 §5 引理 3，周赛时可直接跳过这步——判定并不依赖它）。

> ⚠️ **易被一笔带过的「顺序」环节**：配平后各串只是 $T$ 的**字母异位词**（anagram），未必逐位相等（如示例 3 的 `"ba"` 与 `"ab"`）。好在「可插入任意位置」允许借助另一串作中转完成排序，完整证明必须补上这一环，否则充分性是残缺的。

### 3.3 算法流程：计数 + 逐字母取余

![算法流程：一次计数 + 26 次取余判定](images/wc245_q1_algorithm_flow.svg)

1. **初始化**：$n = \text{len(words)}$，计数数组 `cnt[26] = {0}`。
2. **计数**：双层遍历所有串的所有字符，`cnt[c - 'a']++`，一次线性扫描汇总每个字母的总数。
3. **判定**：遍历 26 个字母，遇到 `cnt[i] % n != 0` 立即 `return false`（提前终止）；26 个全部整除则 `return true`。

> 💡 全程与「搬运」「顺序」无关——判定是纯数值条件，这也是签到题的**最短提交路径**：计数、取余、返回，三步成码。

### 3.4 示例演算

![示例演算：逐字母计数与整除性判定走查](images/wc245_q1_example_walkthrough.svg)

按「每串 × 每字母」展开成计数矩阵，逐列求和得总数，再对每个总数验整除性：

| 示例 | `words` | $n$ | 各字母总数 | 判定 | 结果 |
|------|---------|-----|-----------|------|------|
| 1 | `["abc","aabc","bc"]` | 3 | a:3, b:3, c:3 | $3\%3=0$ ✓（全部） | `true` |
| 2 | `["ab","a"]` | 2 | a:2, b:1 | $2\%2=0$ ✓，$1\%2=1$ ✗ | `false` |
| 3 | `["ba","ab"]` | 2 | a:2, b:2 | $2\%2=0$ ✓（全部） | `true` |

> 💡 示例 3 值得一读：两个串的初始计数完全相同、顺序却不同——它说明判定**只看列和**（总数），与行分布（各串内部）无关；也说明「多重集合相同但顺序不齐」是可行状态，佐证 §5 引理 3 中排序环节的必要性。

## 4. 算法细节

1. **计数容器**：字符集是小写字母，$|\Sigma| = 26$ 为常数——C++ 用定长数组 `int cnt[26]`，Python 用 `Counter`（或拼接后 `Counter("".join(words))`，等价于双层循环）。若字符集扩大到 Unicode，改用哈希表，判定逻辑不变。
2. **除数是 $n$ 而非 $S$**：整除性的分母是**串数** $n = \text{words.size()}$——每个字母要被均分成 $n$ 份。约束保证 $n \ge 1$，无除零风险。
3. **提前终止**：判定循环中第一个不整除的字母即可返回 `false`，平均而言不必扫满 26 个字母。
4. **`Counter` 只含出现过的字母**：未出现的字母 `total = 0`，而 $0 \bmod n = 0$ 恒成立，`all(v % n == 0 for v in cnt.values())` 不会漏判，逻辑等价于显式遍历 26 个字母。
5. **溢出评估**：总数上界 $100 \times 100 = 10^4$，任何整型都绰绰有余，无需 `long long`。

## 5. 正确性证明

**引理 1（总数守恒）**：任意有限步操作之后，每个字母 $c$ 在所有串中的总数 $\text{total}(c)$ 与初始时相同。

**证明**：一步操作把 $words[i]$ 的某个字符 $x$ 移入 $words[j]$，则字母 $x$ 的总数变化为 $(-1) + (+1) = 0$，其余字母不受影响。对步数归纳即得。∎

**引理 2（必要性）**：若存在操作序列使所有串相等，则对每个字母 $c$，初始的 $\text{total}(c) \equiv 0 \pmod n$。

**证明**：设终态所有串均为 $T$，则终态 $\text{total}(c) = n \cdot \text{count}_T(c)$ 是 $n$ 的倍数；由引理 1，初始总数等于终态总数，故初始 $\text{total}(c) \equiv 0 \pmod n$。∎

**引理 3（充分性）**：若对每个字母 $c$ 都有 $\text{total}(c) \equiv 0 \pmod n$，则存在有限步操作序列使所有串相等。

**证明**（构造性，两阶段；$n = 1$ 时单串自等，显然成立，下设 $n \ge 2$）：记 $k_c = \text{total}(c) / n$，$M$ 为「$k_a$ 个 a、…、$k_z$ 个 z」的多重集合，$\text{count}_i(c)$ 为当前第 $i$ 串中 $c$ 的个数。

- **阶段一（配平多重集）**：只要存在串 $i$ 与字母 $c$ 使 $\text{count}_i(c) > k_c$，由 $\sum_i \text{count}_i(c) = n k_c$ 知必存在串 $j$ 使 $\text{count}_j(c) < k_c$；从 $i$ 移一个 $c$ 到 $j$（操作合法：$i$ 含富余字符故非空）。定义势函数 $\Phi = \sum_i \sum_c \lvert \text{count}_i(c) - k_c \rvert$，该移动使 $i$、$j$ 两项各减 1，$\Phi$ 恰减 2。$\Phi$ 是非负整数且每步严格减 2，故有限步后不再存在富余，从而 $\Phi = 0$——每串的多重集合恰为 $M$，所有串互为字母异位词。
- **阶段二（统一顺序）**：借助**任一**其他串 $t$ 作中转，可以把任何串 $s$ 排成非降序：第 $p$ 轮在 $s$ 尚未就位的字符中取一个最小者 $x$，先移到 $t$，再立即移回并**插入 $s$ 的第 $p$ 位**（紧随已排好的前缀之后）。每轮该轮最小者不小于前几轮的最小者，前缀保持非降；每字符恰 2 步，$t$ 先收后还同一字符、其余不动，$t$ 自身不被破坏。对每个串分别执行后，所有串都是 $M$ 的非降序排列，而多重集合唯一确定非降序排列——故所有串相等。∎

**定理**：`words` 可经若干步操作变得全等，当且仅当对每个字母 $c$，$\text{total}(c) \bmod n = 0$。

**证明**：引理 2 给出必要性，引理 3 给出充分性，二者合并即得。∎

## 6. 复杂度分析

- **时间复杂度**：$O(S + |\Sigma|) = O(S + 26)$，其中 $S = \sum_i \text{len}(\text{words}[i]) \le 10^4$ 为一次计数遍历的开销；取余判定至多 26 次，是常数项。
- **空间复杂度**：$O(|\Sigma|) = O(1)$，定长 26 的计数数组（或 `Counter`，至多 26 个键），与输入规模无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool makeStringsEqual(vector<string>& words) {
        int n = words.size();
        int cnt[26] = {0};
        for (const string& w : words) {
            for (char c : w) {
                cnt[c - 'a']++;
            }
        }
        for (int i = 0; i < 26; ++i) {
            if (cnt[i] % n != 0) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def makeStringsEqual(self, words: List[str]) -> bool:
        n = len(words)
        cnt = Counter("".join(words))
        return all(v % n == 0 for v in cnt.values())
```

> 💡 `Counter` 版只遍历**出现过的**字母，但由于未出现字母 $\text{total} = 0$、$0 \bmod n = 0$ 恒成立，与显式遍历 26 个字母完全等价（§4.4）。赛场先写显式版求稳，再压成一行皆可。

## 8. 边界情况与易错点

1. **$n = 1$**：任意整数 $\bmod\ 1 = 0$，恒返回 `true`——单串天然自等，代码自动覆盖，**无需特判**。
2. **判据写成「每串各自计数是否相同」必错**：初始各串的计数**不必**相同（如示例 1 的 `"aabc"` 与 `"bc"`），因为字符可搬运。必须先求**跨串总数**，再验整除。
3. **哈希表 / `Counter` 漏零键**：未出现的字母不在 `.values()` 中，但 $0 \bmod n = 0$ 自动满足——本题恰好无此坑；若判据是与某目标比对而非取余，漏掉零计数字母就会错。
4. **「总长度 $S$ 能否被 $n$ 整除」只是必要条件**：`["aa","ab"]` 总长 4 被 2 整除，但 `b` 只有 1 个 → `false`。必须**逐字母**判定，不能用总长走捷径。
5. **不要模拟搬运过程**：任何贪心搬运、逐步调整的写法都是无用功——判定是纯数值条件，模拟既容易写错也毫无收益。
6. **C++ 细节**：下标转换 `c - 'a'`；`int cnt[26] = {0}` 整体零初始化勿忘；`words.size()` 返回无符号数，`% n` 时先存入 `int n` 更稳。
7. **数据规模小**：总数上界 $10^4$，`int` 足够，无溢出；题面保证每串非空、$n \ge 1$，无需防御空串与除零。
