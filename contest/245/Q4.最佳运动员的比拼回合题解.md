# LeetCode 最佳运动员的比拼回合 题解

## 1. 题目概述

- **标题 / 题号**：最佳运动员的比拼回合（#1900，hard）
- **链接**：https://leetcode.cn/problems/the-earliest-and-latest-rounds-where-players-compete/
- **来源**：LeetCode 第 245 场周赛 Q4
- **难度**：困难
- **标签**：记忆化搜索、动态规划、状态压缩、博弈

**题意**：$n$ 名运动员站成一排，按初始站位从 $1$ 到 $n$ 编号。锦标赛由多个回合组成（从回合 $1$ 开始）：每一回合中，从前数的第 $i$ 名与从后数的第 $i$ 名配对比拼，胜者晋级；当前人数为奇数时，中间那位轮空。每回合结束后，晋级者按**原始编号升序**重新排成一排。编号为 `firstPlayer` 和 `secondPlayer` 的两位是最佳运动员，与其他任何人比拼都必胜；其余任意两人对决时**任一方都可能获胜**——由你裁定胜负。返回两位最佳运动员相遇的**最早**和**最晚**回合数。

**约束**：

- $2 \le n \le 28$
- $1 \le \text{firstPlayer} < \text{secondPlayer} \le n$

> 💡 **切入信号**：$n \le 28$ 暗示允许「指数级枚举 + 记忆化」甚至「多项式高维状态」；「你可以裁定胜负」说明这不是对抗博弈——**最早**与**最晚**是两个独立的最优化问题；配对规则是「第 $i$ 个 ↔ 倒数第 $i$ 个」的**折叠**配对，只依赖行中**位置**而与编号细节无关——这正是压缩状态的入口。

> 💡 本题在本仓库另有[每日题解 1900](../../solution/1801-1900/1900_最佳运动员的比拼回合.md)：以**完整存活集合**（位掩码 / 元组）为状态做记忆化搜索，侧重实现细节与面试问答。本篇按周赛复盘视角，聚焦把状态进一步压缩为**三段计数 $(l, m, r)$** 的做法与完整正确性证明；两篇做法已在 $n = 2 \sim 28$ 全部 $3654$ 组输入上交叉验证一致。

## 3. 解题思路

### 3.1 暴力思路：枚举裁定 + 记忆化的两级铺垫

**第一级（纯枚举模拟）**：每回合中不含两位明星的对决胜负自由——最坏时回合 1 就有 $12$ 场自由对决、$2^{12} = 4096$ 种裁定。逐回合模拟到底并记录相遇回合，实测 $n = 28$ 最坏（如 `firstPlayer = 15, secondPlayer = 18`）约需遍历 $2.9 \times 10^5$ 条完整裁定路径：C++ 可以承受，Python 秒级非常吃力。浪费显而易见——**不同的裁定序列经常汇聚到完全相同的局面**，重复子树被一遍遍重算。

**第二级（存活集合记忆化）**：把「局面」定义为当前存活选手的集合，以其为记忆化键（Python 元组 / C++ 28 位位掩码）。实测 $n = 28$ 最坏约 $2.3 \times 10^4$ 个不同状态，已经轻松通过——这正是[每日题解 1900](../../solution/1801-1900/1900_最佳运动员的比拼回合.md) 的做法。

**本篇的追问**：集合状态里的信息真的用满了吗？下一回合的局面由什么决定？——由**配对结构**决定，而折叠配对只看「第 $i$ 个 ↔ 倒数第 $i$ 个」的位置。两位明星把队列切成三段，每个位置落在哪一段、离两位明星多远，才是配对的全部依据。**具体编号是冗余信息**。

### 3.2 核心观察：三段计数状态 $(l, m, r)$

![核心观察：三段划分 + 折叠配对 + 相遇判定](images/wc245_q4_lmr_concept.svg)

两位明星把每一回合的存活队列切成三段：

- **左段** $l$：编号小于 `firstPlayer` 的存活人数；
- **中段** $m$：编号介于两位明星之间的存活人数；
- **右段** $r$：编号大于 `secondPlayer` 的存活人数。

三个关键事实：

1. **段别是选手的固有属性**：编号与两位明星的大小关系永不变，且行始终按编号升序排列——故左段永远连续排在 `firstPlayer` 左侧，中段夹在两位明星之间，右段连续排在右侧。
2. **位置只由计数决定**：总人数 $T = l + m + r + 2$，`firstPlayer` 位于第 $f = l + 1$ 位，`secondPlayer` 位于第 $s = l + m + 2$ 位。
3. **相遇判定**：折叠配对把第 $i$ 位与第 $T + 1 - i$ 位配对，两位明星配对 $\iff f + s = T + 1$，代入化简：

$$f + s = T + 1 \iff (l+1) + (l+m+2) = (l+m+r+2) + 1 \iff l = r$$

即**左右两段人数相等（局面关于中点对称）时，两位明星恰好被折叠配到一起**。

于是状态压缩为 $(l, m, r)$：与具体编号无关，状态数上界 $\binom{29}{3} = 3654$（$l, m, r \ge 0$ 且 $l + m + r \le 26$），用三维数组即可记忆化，连哈希都不需要。

> 💡 **最早 / 最晚的直觉**：最早相遇 = 让 $l$ 与 $r$ **尽快**削到相等（中段与外侧选手快速出局）；最晚相遇 = 尽久保持 $l \ne r$（在中段养人，拖住对称时刻的到来）。

### 3.3 算法流程：逐对分类 + 枚举跨段对决

![算法流程：配对分类与记忆化搜索](images/wc245_q4_pair_classify_flow.svg)

定义 $\text{dfs}(l, m, r)$ 返回「从当前回合起两位明星相遇还需的（最早, 最晚）回合数」：

1. **判相遇**：若 $l = r$，返回 $(1, 1)$（本回合就打）。
2. **生成配对**：$T = l + m + r + 2$ 人排成一行，第 $i$ 位与第 $T + 1 - i$ 位配对（$i \le \lfloor T/2 \rfloor$）；$T$ 为奇数时第 $(T+1)/2$ 位轮空。
3. **逐对分类**（按对决两端位置的段别）：

| 对决类型 | 例子 | 对下一状态的贡献 | 分支？ |
|---|---|---|---|
| 含明星 | $(L,F), (F,M), (F,R), (L,S), (M,S), (S,R)$ | 明星晋级，**计数不变** | 否 |
| 同段 | $(L,L), (M,M), (R,R)$ | 该段 $+1$（谁胜都一样） | 否 |
| 跨段 | $(L,M), (L,R), (M,R)$ | 胜者所在段 $+1$，两种选择 | **是** |

   轮空的中位：段别为 $L/M/R$ 时该段 $+1$；中位恰是明星时轮空晋级、计数不变。

4. **枚举与合并**：$k$ 场跨段对决产生 $2^k$ 种选择，每种选择确定下一状态 $(l', m', r')$，递归后合并：

$$\text{earliest} = 1 + \min_{\text{分支}} e, \qquad \text{latest} = 1 + \max_{\text{分支}} w$$

5. **记忆化**：以 $(l, m, r)$ 为键缓存结果。

> ⚠️ **为什么 min 与 max 能在同一棵枚举树上同时取？**「你可以裁定每场胜负」意味着最早、最晚是**两次独立**的查询，各自选各自最优的裁定序列即可，不存在对抗——这不是 minimax。若胜负由对手参与决策（见延伸思考②），就不能这样共用一棵树。

### 3.4 示例演算：$n = 11$ 的状态树

![示例演算：n=11 的 (l,m,r) 状态转移树](images/wc245_q4_state_tree_walkthrough.svg)

初始 $(l, m, r) = (1, 1, 7)$（$T = 11$）。回合 1 的配对：$(1,11)$ 跨段、$(2,10)$ 明星、$(3,9)$ 跨段、$(4,8)$ 明星、$(5,7)$ 同段、$6$ 号轮空——同段与轮空贡献基数 $R' \ge 2$，两场跨段对决产生四个分支：

| 分支（$1{\leftrightarrow}11$、$3{\leftrightarrow}9$ 的胜者） | 下一状态 | 对应存活行 | 递归值 |
|---|---|---|---|
| $1$ 胜, $3$ 胜 | $(1, 1, 2)$ | `1,2,3,4,5,6`（官方最晚路径） | $(3, 3)$ |
| $1$ 胜, $9$ 胜 | $(1, 0, 3)$ | `1,2,4,5,6,9` | $(3, 3)$ |
| $11$ 胜, $3$ 胜 | $(0, 1, 3)$ | `2,3,4,5,6,11`（官方最早路径） | $(2, 3)$ |
| $11$ 胜, $9$ 胜 | $(0, 0, 4)$ | `2,4,5,6,9,11` | $(3, 3)$ |

汇总：earliest $= \min(3,3,2,3) + 1 = 3$，latest $= \max(3,3,3,3) + 1 = 4$，即 $[3, 4]$ ✓。

官方两条路径在状态树上的落点：

- **最早**：$(0,1,3) \to (0,1,0)$（$3$ 胜 $6$，存活 `2,3,4`）$\to$ $l = r = 0$，回合 3 相遇。
- **最晚**：$(1,1,2) \to (1,0,0)$（$4$ 胜 $3$，存活 `1,2,4`）$\to (0,0,0)$（存活 `2,4`）$\to$ 回合 4 相遇。

另可注意 $(0,0,1)$、$(1,0,0)$ 等状态被多个分支共享——这正是记忆化生效的位置：状态树远小于裁定路径树。

## 4. 算法细节

1. **初始状态**：$l_0 = \text{firstPlayer} - 1$，$m_0 = \text{secondPlayer} - \text{firstPlayer} - 1$，$r_0 = n - \text{secondPlayer}$。初始即可能 $l_0 = r_0$（示例 2 是 $(0, 3, 0)$）。
2. **段判定 $O(1)$**：位置 $p$ 的段别只需与 $f = l+1$、$s = l+m+2$ 做两次比较。前半位置的段别只可能是 $L/F/M$，后半只可能是 $L/M/S/R$，故跨段组合只有 $(L,M), (L,R), (M,R)$ 三种——$(M,L)$ 之类的排列不可能出现（$L$ 段永远在最前）。
3. **$(F, S)$ 不会进入枚举**：两位明星配对 $\iff l = r$，已被第 1 步提前返回；枚举中遇到的对决至多含一位明星。
4. **终止性**：$l \ne r$ 时 $T \ge 3$，且下一回合人数 $T' \le 2 + \lfloor T/2 \rfloor < T$——总人数每回合严格递减，递归深度 $\le \lceil \log_2 28 \rceil = 5$。
5. **记忆化键**：Python 直接对 $(l, m, r)$ 元组用 `lru_cache`；C++ 用 `memo[29][29][29]` 三维数组（$l, m, r \le 27$），以 `first == 0` 作「未计算」哨兵——合法返回值的 `first` 恒 $\ge 1$，无冲突。
6. **返回值语义**：dfs 返回「距相遇还差几个回合」，故每回归一层 $+1$；对初始状态调用的返回值就是答案，无需再调整。

## 5. 正确性证明

**引理 1（段别不变性）**：每个非明星选手属于 $L/M/R$ 哪一段是其固有属性；且在每一回合的存活行中，左段选手连续占据第 $1 \sim l$ 位、`firstPlayer` 在第 $l+1$ 位、中段在第 $l+2 \sim l+m+1$ 位、`secondPlayer` 在第 $l+m+2$ 位、右段在最后 $r$ 位。

**证明**：选手编号是固有标签；行始终按原始编号升序排列，故行中位置次序 = 编号大小次序。$L$ 段编号 $<$ `firstPlayer` $<$ 中段编号 $<$ `secondPlayer` $<$ $R$ 段编号，这一链关系与回合无关；又两位明星相遇前逢对手必胜、轮空亦晋级，始终存活，故段结构与位置公式逐回合成立。∎

**引理 2（相遇判定）**：当前回合两位明星配对 $\iff l = r$。

**证明**：由引理 1，$f = l+1$，$s = l+m+2$，$T = l+m+r+2$。折叠配对将位置 $i$ 与 $T+1-i$ 配对，故两位明星配对 $\iff f + s = T + 1$（$f < s$）。代入得 $(l+1)+(l+m+2) = (l+m+r+2)+1 \iff 2l+m+3 = l+m+r+3 \iff l = r$。∎

**引理 3（状态等价）**：两个局面若 $(l, m, r)$ 相同，则从当前回合起「两位明星可能的相遇回合数」的集合完全相同。

**证明**：对存活总人数 $T$ 强归纳。由引理 1，相同 $(l,m,r)$ 的两个局面段结构相同，进而配对结构逐一相同：每场对决两端的段别、轮空者的段别都对应相等。于是两局的合法裁定集合之间存在保结构双射（按逐场胜负一一对应），且对应裁定产生的下一局面有相同的 $(l', m', r')$。$l = r$ 时两局都在本回合相遇（引理 2），集合同为 $\{1\}$；否则每个对应分支递归到相同的 $(l', m', r')$，由归纳假设其相遇回合数集合相同，逐分支平移 $+1$ 后取并仍相同。∎

**引理 4（转移完备且无伪）**：$l \ne r$ 时，算法枚举产生的下一状态集合，恰等于该回合所有合法裁定产生的 $(l', m', r')$ 集合。

**证明**：下一回合存活者 = 两位明星 + 各场胜者 + 轮空者。逐类核对对 $(l', m', r')$ 的贡献：含明星对决——明星晋级不计入，对手出局；同段对决——无论谁胜，该段恰 $+1$；跨段对决——胜者恰属两端之一，对应枚举的一个分支方向；轮空者——段别为 $L/M/R$ 时该段 $+1$，是明星时不计入。因此 $(l', m', r')$ 仅由「每场跨段对决选了哪一段的选手」决定，与同段对决的胜负、与选手的具体编号均无关。算法枚举了跨段对决的全部 $2^k$ 种选择：每种选择都可扩充为合法裁定（**无伪**），每种合法裁定都被某种选择覆盖（**完备**）。∎

**定理**：$\text{dfs}(l, m, r)$ 返回从当前回合起到相遇的最早与最晚回合数。

**证明**：对 $T$ 强归纳（终止性见 §4.4）。$l = r$ 时由引理 2 本回合相遇，返回 $(1,1)$ 正确。$l \ne r$ 时由引理 4，可能的下一状态恰为枚举集合；由引理 3，各分支的递归返回值与具体局面无关，由归纳假设保证正确。相遇回合数的可能值集合为 $\bigcup_{\text{分支}} \{v + 1\}$（$v$ 遍历该分支的相遇回合数），故最早 $= 1 + \min$ 各分支 $e$、最晚 $= 1 + \max$ 各分支 $w$；又因最早、最晚是两次独立裁定（无对抗），$\min$ 与 $\max$ 可在同一棵枚举树上分别维护。∎

> 💡 **论证骨架**：引理 1、2 锁定「**何时相遇**」（$l = r$）；引理 3 论证「**状态压缩无损**」（编号是冗余信息）；引理 4 论证「**转移不漏不虚**」（枚举 = 全部合法裁定）。三者合起来正是所有「状态压缩 DP / 记忆化」题的标准证明模板，值得作为范式沉淀。

## 6. 复杂度分析

- **时间复杂度**：状态数上界 $\binom{n+2}{3} = O(n^3)$；单个状态至多枚举 $2^{\lfloor T/2 \rfloor - 1}$ 种跨段组合（$k \le 13$），宽松上界 $O(n^3 \cdot 2^{n/2})$。实测远低于上界：$n = 2 \sim 28$ **全部 3654 组输入**合计，C++ 仅 63 ms、Python 约 2.7 s；最坏单输入 `n=28, firstPlayer=6, secondPlayer=14`（答案 $[2,5]$）也只有 68 个状态、4873 次分支枚举、约 6 ms。上界虚高的三个原因：① 每回合人数约减半，可达状态远少于组合数；② 含明星对与同段对占多数，真正分支的跨段对决很少；③ 跨段对决数随深度递减。作为对比：无记忆化纯枚举最坏约 $2.9 \times 10^5$ 条路径，存活集合记忆化最坏约 $2.3 \times 10^4$ 个状态，计数压缩再降约两个数量级至 $\le 68$。
- **空间复杂度**：$O(n^3)$ 记忆化数组（实测仅用到几十项）+ $O(\log n)$ 递归栈。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    pair<int, int> memo[29][29][29];

    pair<int, int> dfs(int l, int m, int r) {
        if (l == r) return {1, 1};              // 左右段人数相等：本回合折叠配对相遇
        auto &res = memo[l][m][r];
        if (res.first) return res;              // 0 是「未计算」哨兵（合法值 >= 1）

        int T = l + m + r + 2, f = l + 1, s = l + m + 2;
        auto seg = [&](int p) {                 // 位置 p 的段别：0=L 1=F 2=M 3=S 4=R
            if (p < f) return 0;
            if (p == f) return 1;
            if (p < s) return 2;
            if (p == s) return 3;
            return 4;
        };
        vector<pair<int, int>> pairs;           // 折叠配对：第 i 位 <-> 第 T+1-i 位
        for (int i = 1; i <= T / 2; i++) pairs.push_back({i, T + 1 - i});
        int midSeg = (T % 2) ? seg((T + 1) / 2) : -1;

        int bestE = INT_MAX, bestL = 0;
        function<void(int, int, int, int)> go = [&](int idx, int L, int M, int R) {
            if (idx == (int)pairs.size()) {
                if (midSeg == 0) L++;           // 轮空者计入其段；中位是明星则不计
                else if (midSeg == 2) M++;
                else if (midSeg == 4) R++;
                auto [e, w] = dfs(L, M, R);
                bestE = min(bestE, e);
                bestL = max(bestL, w);
                return;
            }
            auto [a, b] = pairs[idx];
            int sa = seg(a), sb = seg(b);
            if (sa == 1 || sa == 3 || sb == 1 || sb == 3) {
                go(idx + 1, L, M, R);           // 含明星：明星胜，计数不变
            } else if (sa == sb) {
                go(idx + 1, L + (sa == 0), M + (sa == 2), R + (sa == 4));  // 同段
            } else {
                go(idx + 1, L + (sa == 0), M + (sa == 2), R + (sa == 4));  // 跨段
                go(idx + 1, L + (sb == 0), M + (sb == 2), R + (sb == 4));  // 二选一
            }
        };
        go(0, 0, 0, 0);
        res = {bestE + 1, bestL + 1};
        return res;
    }

    vector<int> earliestAndLatest(int n, int firstPlayer, int secondPlayer) {
        memset(memo, 0, sizeof(memo));
        auto [e, w] = dfs(firstPlayer - 1, secondPlayer - firstPlayer - 1, n - secondPlayer);
        return {e, w};
    }
};
```

```python
            if l == r:                          # 左右段人数相等：本回合相遇
                return (1, 1)
            T = l + m + r + 2
            f, s = l + 1, l + m + 2

            def seg(p):                         # 0=L 1=F 2=M 3=S 4=R
                if p < f: return 0
                if p == f: return 1
                if p < s: return 2
                if p == s: return 3
                return 4

            pairs = [(i, T + 1 - i) for i in range(1, T // 2 + 1)]
            mid_seg = seg((T + 1) // 2) if T % 2 else -1
            best_e, best_w = float('inf'), 0

            def go(idx, L, M, R):
                nonlocal best_e, best_w
                if idx == len(pairs):
                    if mid_seg == 0: L += 1     # 轮空者计入其段；是明星则不计
                    elif mid_seg == 2: M += 1
                    elif mid_seg == 4: R += 1
                    e, w = dfs(L, M, R)
                    best_e, best_w = min(best_e, e), max(best_w, w)
                    return
                a, b = pairs[idx]
                sa, sb = seg(a), seg(b)
                if sa in (1, 3) or sb in (1, 3):
                    go(idx + 1, L, M, R)        # 含明星：计数不变
                elif sa == sb:
                    go(idx + 1, L + (sa == 0), M + (sa == 2), R + (sa == 4))
                else:
                    go(idx + 1, L + (sa == 0), M + (sa == 2), R + (sa == 4))
                    go(idx + 1, L + (sb == 0), M + (sb == 2), R + (sb == 4))

            go(0, 0, 0, 0)
            return (best_e + 1, best_w + 1)

        return list(dfs(firstPlayer - 1,
                        secondPlayer - firstPlayer - 1,
                        n - secondPlayer))
```

> 💡 **实现要点**：① 段判定 `seg(p)` 只与 $f, s$ 两次比较；② 枚举用「逐对递归 + 累积计数」的 `go`，把「含明星 / 同段 / 跨段」三类处理天然统一；③ 跨段分支的两个方向对应两端各自的段；④ Python 的 `lru_cache` 挂在内层闭包上，每个输入独立一份缓存，等价于按用例重置。

## 8. 边界情况与易错点

1. **先判 $l = r$，再枚举**：初始状态就可能相遇（示例 2 是 $(0,3,0)$；`firstPlayer=1, secondPlayer=n`、$n=28$ 时的 `(14,15)` 等都是 $l_0 = r_0$）。若漏判，$(F,S)$ 这场对决会落进「含明星」类被无声跳过，答案整体多 $+1$。
2. **中位可能是明星**：$T$ 为奇数且正中恰是 `firstPlayer` / `secondPlayer` 时，明星轮空——**不计入三段计数**。例如 $(l,m,r)=(1,0,0)$：行 `L,F,S`，中位是 F。这是手写分类时最容易漏的一条。
3. **明星可能在配对的后半位置**：如 $(L,S)$、$(M,F)$——照样是「明星胜、对手出局、计数不变」。代码用「两端任一为明星」统一判定；只考虑前半端的手写分类会漏。
4. **$(1,1)$ 基例与 $+1$ 的配合**：dfs 语义是「距相遇还差几回合」，从初始状态调用的返回值就是答案，不要再多加一轮（对照 §4.6）。
5. **别写成 minimax**：最早、最晚是两次独立裁定，可在同一棵枚举树上同时维护 $\min$ 与 $\max$；若误写成「对手也想赢」的对抗搜索，最晚值会算错。
6. **C++ 哨兵与重置**：`memo` 初始化为 0、以 `res.first != 0` 判「已计算」，前提是合法值 `first ≥ 1`；`Solution` 实例可能被连续调用，入口处必须 `memset` 重置。
7. **无分支的退化输入**：`firstPlayer=1, secondPlayer=2`（$l = m = 0$）时所有对决要么同段要么含明星，全程无任何分支，最早 = 最晚 = $\lceil \log_2 n \rceil$（$n = 28$ 时为 $[5,5]$）——可当作对拍基准。
8. **枚举重复无害**：两场同类跨段对决交换选择会得到相同的 $(l', m', r')$，$\min / \max$ 幂等不受影响，仅少量冗余；延伸思考①给出按计数分组的去重优化。
