# LeetCode 可移除字符的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：可移除字符的最大数目（#1898，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-removable-characters/
- **来源**：LeetCode 第 245 场周赛 Q2
- **难度**：中等
- **标签**：数组、字符串、二分查找、双指针

**题意**：给定字符串 `s` 与其子序列 `p`，以及一个下标**互不相同**的数组 `removable`（`s` 中下标的子集）。对整数 $k$，先把 `s` 中位于 $removable[0..k-1]$ 的字符**标记**，再全部移除，问 $p$ 仍然是 `s` 的子序列的**最大** $k$。注意移除的是 `removable` 的**前缀**——按数组给定的顺序取前 $k$ 个，不是任意挑选。

**约束**：

- $1 \le |p| \le |s| \le 10^5$
- $0 \le m = |removable| < |s|$
- $0 \le removable[i] < |s|$，且元素**互不相同**
- `p` 是 `s` 的一个子序列（初始保证，即 $k=0$ 必可行）
- `s`、`p` 都由小写英文字母组成

> 💡 **切入信号**：题面求「最大的 $k$ 使某条件成立」+ 条件能 $O(|s|)$ 验证 + 「删得越多越难保持子序列」的直觉 ⇒ 典型**二分答案**。本题是「二分答案 + 双指针判子序列」的拼装题，单独看两个组件都是模板，难点全在把它们正确焊在一起——尤其是「按前缀移除」的实现细节（§4）。

> 💡 本题在本仓库另有[每日题解 1898](../../solution/1801-1900/1898_可移除字符的最大数目.md)：侧重「朴素布尔数组 vs 移除时刻表」的工程对比与面试问答。本篇按周赛复盘视角，聚焦**二段性的来源（嵌套的移除集合族）**、双指针贪心的完整证明（§5 引理 2）与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：s = "abcacb", p = "ab", removable = [3,1,0]
输出：2
解释：移除前 2 个下标 {3,1} 后，s 剩 "accb"，"ab" 仍是子序列（a@0, b@5）。
      若再移除下标 0，s 剩 "ccb"，'a' 消失，"ab" 不再是子序列。
```

**示例 2**

```text
输入：s = "abcbddddd", p = "abcd", removable = [3,2,1,4,5,6]
输出：1
解释：仅移除下标 3 后 s = "abcddddd"，"abcd" 仍是子序列；
      再移除下标 2（唯一的 'c'）即失败。
```

**示例 3**

```text
输入：s = "abcab", p = "abc", removable = [0,1,2,3,4]
输出：0
解释：k=1 时移除下标 0，剩 "bcab"：'a' 只在原下标 3，其后的 'b' 只在原下标 4，
      'c' 再无落点，"abc" 不再是子序列——k=1 即失败，最大 k = 0。
```

**示例 4（自拟，验证答案可达上界 $m$）**

```text
输入：s = "aabb", p = "ab", removable = [0,2]
输出：2
解释：移除全部 2 个下标后 s 剩 "ab"（原下标 1、3），恰为 p 本身。
      说明答案可以等于 m，二分上界必须取 m 而非 m-1（§8.1）。
```

## 3. 解题思路

### 3.1 暴力思路

从 $k=0$ 到 $k=m$ 逐个尝试：每次把 `removable` 前 $k$ 个下标的字符删掉，双指针 $O(|s|)$ 判定 `p` 是否仍是子序列，返回最后一个可行的 $k$。

单次验证 $O(|s|)$，整体 $O(|s| \cdot m)$。本题 $|s|, m \le 10^5$，总量达 $10^{10}$，**必然超时**。即便用「相邻两个 $k$ 只差一次删除」做增量维护，被删字符可能迫使贪心嵌入整体右移，单次退化仍达 $O(|s|)$，无济于事。

> ⚠️ 暴力的浪费在于**线性扫描了 $m+1$ 个候选 $k$**，而这些候选的可行性不是孤立的——它们之间有单调结构，值得用二分一次性跳过大片区间。

### 3.2 核心观察：移除集合族是嵌套的 ⇒ 二段性

![核心观察：前缀移除集合嵌套，可行 k 构成前缀区间](images/wc245_q2_monotonicity_concept.svg)

固定移除顺序 `removable`，令 $D_k = \{removable[0], \dots, removable[k-1]\}$ 为移除前 $k$ 个下标得到的集合，则

$$D_0 \subset D_1 \subset \cdots \subset D_m$$

是**严格递增的嵌套族**，保留集合 $R_k = [0, |s|) \setminus D_k$ 相应**递减**。于是：

- 若 $k$ 可行（$p$ 是 $s|_{R_k}$ 的子序列），则任意 $k' \le k$ 也可行——$R_{k'} \supseteq R_k$，$k$ 情形下那个保序嵌入用到的字符在 $k'$ 情形下**全部保留**，且相对顺序不变，嵌入原样有效；
- 反之，若 $k$ 不可行，任意 $k' \ge k$ 也不可行。

所以可行 $k$ 恰构成前缀 $\{0, 1, \dots, k^*\}$（$k=0$ 由题设保证可行），存在唯一分界点 $k^*$。**求 $k^*$ ⇒ 在 $[0, m]$ 上二分**：每次取 $mid$，$O(|s|)$ 验证，可行则答案 $\ge mid$，向右收缩；不可行则向左收缩。

> 💡 **二分答案的识别范式**：「求最大的满足某条件的值」+「条件可快速验证」+「可行性单调」。与 [1011. 在 D 天内送达包裹的能力](../../solution/1001-1100/1011_在D天内送达包裹的能力.md)、[875. 爱吃香蕉的珂珂](../../solution/0801-0900/875_爱吃香蕉的珂珂.md) 同一套模板，区别只在 `check()` 内部。本题 `check` 是双指针判子序列，母题即 [392. 判断子序列](../../solution/0301-0400/392_判断子序列.md)。

> ⚠️ **二段性的来源要认准**：单调性来自「移除集合按**前缀**嵌套」这一结构。若题目改成「任选 `removable` 的子集移除」，嵌套性消失（虽然「固定某个子集族内取前缀」仍在，但候选族不再是链），就不能这样二分了（§延伸思考②）。

### 3.3 算法流程：移除时刻表 + 双指针 check

![算法流程：预处理 removeTime，二分 mid，双指针判定子序列](images/wc245_q2_binary_search_flow.svg)

**第一步：预处理移除时刻表**。`check(k)` 需要知道每个下标是否在 $D_k$ 中。朴素做法每轮重建布尔数组，$O(k)$ 建表。更好的做法是一次预处理：

$$\text{removeTime}[i] = \begin{cases} t, & \text{若 } removable[t] = i \\ -1, & \text{若 } i \notin removable \end{cases}$$

由于 `removable` 元素互不相同，该定义良定。于是「$i \in D_k$」$\iff 0 \le \text{removeTime}[i] < k$，$O(1)$ 判定，无需每轮建表。

**第二步：二分**。闭区间 $[0, m]$，`check(mid)` 可行则记 `ans = mid` 并右移，否则左移。

**第三步：check(k) 内部——双指针判子序列**。`i` 扫 `s`，`j` 指向 `p` 中待匹配字符：跳过已移除下标（$\text{removeTime}[i] < k$），若 $s[i] = p[j]$ 则 $j$ 右移；`j` 走完 `p` 即可行。

### 3.4 示例演算

![示例演算：removeTime 构造与二分三轮走查](images/wc245_q2_example_walkthrough.svg)

以示例 1 为例：$s = $ `"abcacb"`，$p = $ `"ab"`，`removable = [3,1,0]`，$m = 3$。

**预处理**：`removable[0]=3`（第 0 步删下标 3）、`removable[1]=1`、`removable[2]=0`，故

| 下标 $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|---|
| $s[i]$ | a | b | c | a | c | b |
| removeTime | **2** | **1** | -1 | **0** | -1 | -1 |

**二分**（`lo=0, hi=3, ans=0`；匹配位置用原串 `s` 的下标记）：

| 轮次 | 区间 | mid | 被删下标（$D_{mid}$） | 剩余串 | "ab" 匹配 | 结论 |
|------|------|-----|----------------------|--------|-----------|------|
| 1 | [0,3] | 1 | {3} | "abccb" | a@0, b@1 ✓ | 可行，ans=1，lo=2 |
| 2 | [2,3] | 2 | {1,3} | "accb" | a@0, b@5 ✓ | 可行，ans=2，lo=3 |
| 3 | [3,3] | 3 | {0,1,3} | "ccb" | 无 'a' ✗ | 不可行，hi=2 |

循环结束（`lo=3 > hi=2`），返回 $ans = 2$。

## 4. 算法细节

1. **移除时刻表的构造**：`removeTime` 初始化为 $-1$，再遍历 `removable` 置 `removeTime[removable[t]] = t`。元素互不相同保证每个下标至多被赋值一次，无覆盖风险（若可能重复，见 §8.8）。
2. **「前 $k$ 个」的判定是严格小于**：`removable` 前 $k$ 项对应的时刻恰为 $\{0, 1, \dots, k-1\}$，故 $i \in D_k \iff \text{removeTime}[i] \ne -1 \wedge \text{removeTime}[i] < k$。写成 $\le k$ 会多删第 $k+1$ 个字符（当 $i = removable[k]$ 时）。
3. **哨兵技巧**：若把初值从 $-1$ 改为 $m$（「正无穷」语义），判定可简化为 $\text{removeTime}[i] < k$ 一条——因 $k \le m$，永不被移除的下标自动不满足。代价是丢失「是否在 removable 中」的信息，若后续要用该信息则保留 $-1$ 版本。两版等价，赛场选一个写对即可。
4. **check 的扫描**：`i` 从左到右扫整个 `s`；`j == |p|` 时可提前退出。判定「已移除」必须放在「字符相等」判断之前——被移除的字符即使相等也不能参与匹配。
5. **二分边界**：区间 $[0, m]$ 闭区间，`ans` 初值 $0$（$k=0$ 必可行，由题设「p 是 s 的子序列」保证）。`mid = lo + (hi - lo) / 2` 防溢出（本题数值小，纯习惯）。
6. **不要真的构造删除后的字符串**：每轮拼接新串是 $O(|s|)$ 的额外分配与拷贝，C++ 中直接按下标扫描 + 标记判定即可，把「删除」退化为「逻辑跳过」。
7. **为什么不用 `p` 的自动机（如 392 题的后续状态数组）**：那是对**多次询问不同 `p`** 的优化；本题 `p` 固定、变化的是移除集合，双指针已是每个 `check` 的最优形态。

## 5. 正确性证明

**引理 1（前缀单调性）**：设 $0 \le k' \le k \le m$。若移除 $D_k$ 后 $p$ 仍是 $s$ 的子序列，则移除 $D_{k'}$ 后亦然。

**证明**：$D_{k'} \subseteq D_k$，故 $R_{k'} \supseteq R_k$。设移除 $D_k$ 后 $p$ 是 $s$ 的子序列，即存在严格递增映射 $\varphi: [0, |p|) \to R_k$ 使 $s[\varphi(j)] = p[j]$。由 $R_{k'} \supseteq R_k$ 知 $\varphi$ 的像落在 $R_{k'}$ 中，且 $\varphi$ 的严格递增性与取值只依赖 `s` 的原始下标，不依赖哪些字符被移除。故 $\varphi$ 也是「移除 $D_{k'}$ 后」的一个合法嵌入，$p$ 仍是子序列。∎

**引理 2（双指针贪心判定的正确性）**：对任意保留集合 $R \subseteq [0, |s|)$，双指针算法（`i` 升序扫 `s`，遇到 $i \in R$ 且 $s[i] = p[j]$ 则 $j{+}{+}$）返回 true，当且仅当 $p$ 是 $s|_R$ 的子序列。

**证明**：

（⇒）若返回 true，算法实际选出下标 $i_0 < i_1 < \dots < i_{|p|-1}$，均属于 $R$ 且 $s[i_j] = p[j]$，这本身就是保序嵌入，故 $p$ 是子序列。

（⇐）设 $p$ 是 $s|_R$ 的子序列，任取一个保序嵌入 $\varphi$。对 $j$ 归纳证明算法为 $p[j]$ 匹配的下标 $i_j \le \varphi(j)$：

- **基础**：算法为 $p[0]$ 选取 $R$ 中第一个字符等于 $p[0]$ 的下标；$\varphi(0)$ 是一个候选，故 $i_0 \le \varphi(0)$。
- **归纳**：设 $i_{j-1} \le \varphi(j-1)$。由嵌入的严格递增性，$\varphi(j) > \varphi(j-1) \ge i_{j-1}$，且 $\varphi(j) \in R$、$s[\varphi(j)] = p[j]$，即 $\varphi(j)$ 是算法自 $i_{j-1}$ 之后会扫到的一个合法候选，故算法选中的 $i_j \le \varphi(j)$。

于是每个 $p[j]$ 都在扫完 `s` 前成功匹配，算法返回 true。∎

> 💡 引理 2 的 (⇐) 方向即「**贪心匹配最早出现位置不会吃亏**」：最早的合法选择永远把最多的后续余地留给后面的字符。这是子序列/匹配类贪心的通用论证模式（交换论证的归纳形式）。

**定理**：上述二分算法返回 $k^* = \max\{\, k \in [0, m] : \text{移除 } D_k \text{ 后 } p \text{ 仍是 } s \text{ 的子序列}\,\}$。

**证明**：由题设 $k=0$ 可行，可行集非空；由引理 1，可行集向下封闭，故恰为 $\{0, 1, \dots, k^*\}$。二分维护不变量：「所有 $< lo$ 的 $k$ 可行，所有 $> hi$ 的 $k$ 不可行，且 $ans = lo - 1$」。初始 $lo=0, hi=m, ans=0$，不变量成立（定义域外为空）。每轮取 $mid \in [lo, hi]$：若 `check(mid)` 为真，由引理 1 一切 $\le mid$ 可行，置 $ans = mid,\ lo = mid + 1$，不变量保持；若为假，由引理 1 的逆否一切 $\ge mid$ 不可行，置 $hi = mid - 1$，不变量保持。又 `check` 由引理 2 正确判定可行性（其中「$i \in D_{mid}$」由 §4.2 的时刻表等价刻画保证）。循环每轮区间严格缩小，终止时 $lo = hi + 1$，不变量给出：$lo - 1 = ans$ 可行且 $lo$ 不可行，即 $ans = k^*$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(|s| \log m)$。预处理时刻表 $O(m)$；二分 $O(\log m)$ 轮，每轮双指针扫描至多走完 `s`（`j` 的移动不超过 $|p| \le |s|$ 次），单轮 $O(|s|)$。本题 $|s| \le 10^5$、$\log m \approx 17$，总量约 $1.7 \times 10^6$，轻松通过。
- **空间复杂度**：$O(|s|)$，即 `removeTime` 数组。若用朴素布尔数组版，同为 $O(|s|)$，只是把建表开销摊进了每轮 `check`。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maximumRemovals(string s, string p, vector<int>& removable) {
        int n = s.size(), m = removable.size();
        // removeTime[i]：s[i] 在 removable 中是第几个（0 起）被移除的，-1 表示永不移除
        vector<int> removeTime(n, -1);
        for (int t = 0; t < m; ++t) {
            removeTime[removable[t]] = t;
        }

        int lo = 0, hi = m, ans = 0;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (check(s, p, removeTime, mid)) {
                ans = mid;      // 可行，尝试移除更多
                lo = mid + 1;
            } else {
                hi = mid - 1;   // 不可行，少移除一些
            }
        }
        return ans;
    }

  private:
    // 移除 removable 前 k 个下标后，p 是否仍是 s 的子序列
    bool check(const string& s, const string& p,
               const vector<int>& removeTime, int k) {
        int j = 0, np = p.size();
        for (int i = 0; i < (int) s.size() && j < np; ++i) {
            if (removeTime[i] != -1 && removeTime[i] < k) continue; // 已移除，跳过
            if (s[i] == p[j]) ++j;
        }
        return j == np;
    }
};
```

### Python

```python
class Solution:
    def maximumRemovals(self, s: str, p: str, removable: List[int]) -> int:
        n, m = len(s), len(removable)
        remove_time = [-1] * n
        for t, idx in enumerate(removable):
            remove_time[idx] = t

        def check(k: int) -> bool:
            j = 0
            for i, c in enumerate(s):
                if j == len(p):
                    break
                if -1 < remove_time[i] < k:  # 前 k 步内被移除
                    continue
                if c == p[j]:
                    j += 1
            return j == len(p)

        lo, hi, ans = 0, m, 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                ans = mid
                lo = mid + 1
            else:
                hi = mid - 1
        return ans
```

> 💡 Python 版判定写作 `-1 < remove_time[i] < k`，把「非哨兵」与「严格小于」合并成一条链式比较；C++ 版拆成两个条件更直观。二者语义一致（§4.3）。

## 8. 边界情况与易错点

1. **二分上界是 $m$ 而非 $m-1$**：$k = m$（全部移除）可能是答案——示例 4 的 `s="aabb", p="ab", removable=[0,2]` 返回 2。约束 $m < |s|$ 保证全删后 `s` 仍剩字符，但剩余部分仍可能包含 `p`。
2. **`removeTime[i] < k` 必须严格小于**：前 $k$ 个的时刻是 $0..k-1$。写成 `<=` 会在恰有 $removable[k]$ 处多删一个，可能把本来可行的 `mid` 误判为不可行，答案偏小。
3. **哨兵 $-1$ 的处理是最大坑点**：若判定漏掉 `removeTime[i] != -1`，则 $-1 < k$ 对一切 $k \ge 1$ 成立，**所有不在 removable 里的字符都会被误删**，几乎必然 WA。要么补上非 $-1$ 判断，要么把初值设为 $m$（§4.3 的哨兵技巧）从根上规避。
4. **绝对不能对 `removable` 排序**：「前 $k$ 个」是按**给定顺序**的前缀，顺序本身就是信息。反例：$s = $ `"ba"`，$p = $ `"b"`，`removable = [1,0]` 正确答案是 1（先删 1，剩 `"b"` 仍含 `b`）；排序成 `[0,1]` 后答案变成 0。
5. **「先标记、后统一移除」的语义**：$k$ 的定义是先标记 $removable[0..k-1]$ 再全部移除，等价于直接删集合 $D_k$——顺序在集合语义下无影响，因此 `check` 只需判「是否属于前 $k$ 个下标集合」，无需模拟删除时序。
6. **跳过判断先于相等判断**：`continue` 掉已移除下标必须在 `s[i] == p[j]` 之前，否则被删字符会被错误地用于匹配。
7. **提前退出的位置**：`j == |p|` 即可返回 true（C++ 循环条件已含），Python 在循环内 break——扫完整串才判 `j` 也能对，只是白走。
8. **`removable` 若含重复**：题面保证互不相同；若取消该保证，`removeTime` 会被靠后的出现覆盖，「前 $k$ 个」语义被破坏，应改回「每轮重建布尔标记」或先去重（保留最早出现时刻）。
9. **不要用 `while (i < n && s[i] != p[j]) i++` 的裸指针风格硬扫**：漏判「已移除」条件的方式五花八门，统一写成「先跳过已移除，再看相等」的三行结构最不易错。

**延伸思考**：① **若允许任选 `removable` 的子集移除**（不限定前缀），求最大移除数：问题变为「选一个 `p` 的保序嵌入，使其与 `removable` 集合的交集尽量小」，可用 DP $O(26 \cdot |s|)$ 求「从位置 $i$ 起匹配 $p[j..]$ 的最小代价嵌入」，答案是 $m - \min_{\text{嵌入 } \varphi} |\varphi \cap removable|$——嵌套性消失，二分不再适用，需换成最优化视角。② **若把判定改为「$p$ 是剩余串的子串（连续）」**：可行性不再具有前缀单调性（删字符可能反而拼出新子串），甚至可能「删得越多越可行」，二分彻底失效——对照体会本题单调性对「子序列 + 只删不增」结构的依赖。③ **在线版本**（逐个给出 `removable` 元素、每步询问当前最大 $k$）：可用树状数组维护「贪心嵌入最远匹配位置」的单调栈式重构，每步删除后从受影响位置重新贪心，均摊复杂度可做到 $O((|s| + q)\log |s|)$，感兴趣的读者可自行推敲。
