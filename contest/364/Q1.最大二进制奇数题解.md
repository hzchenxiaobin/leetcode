# LeetCode 最大二进制奇数 题解

## 1. 题目概述

- **标题 / 题号**：最大二进制奇数（#2864，easy）
- **链接**：https://leetcode.cn/problems/maximum-odd-binary-number/
- **来源**：LeetCode 第 364 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数学、字符串

**题意**：给定一个**二进制**字符串 `s`（至少含一个 `'1'`），要求**重排**其中的字符，使结果是能由这组字符拼出的**最大二进制奇数**，以字符串形式返回。注意返回结果**允许含前导零**。

**约束**：

- $1 \le s.length \le 100$
- `s` 仅由 `'0'` 和 `'1'` 组成
- `s` 中至少包含一个 `'1'`

> 💡 读题关键：两个约束拆开看——「**奇数**」只由**末位**决定（末位是 1 即奇）；「**最大**」由**高位**决定（'1' 越靠左数值越大）。二者互不抢位：扣下一个 '1' 看守末位，其余 '1' 全部冲向最高位，'0' 只能垫中间。签到题的最短路径：一趟计数 + 三段拼接，两行代码。

## 2. 示例

**示例 1**

```text
输入：s = "010"
输出："001"

解释：s 中只有一个 '1'，它必须出现在末位上，其余位置只能是 '0'，
      所以答案是 "001"（允许前导零）。
```

**示例 2**

```text
输入：s = "0101"
输出："1001"

解释：一个 '1' 必须出现在末位上，剩下 "010" 能拼出的最大数是 "100"，
      所以答案是 "1001"。
```

**示例 3（补充：全 '1' 边界）**

```text
输入：s = "111"
输出："111"

解释：末位征用一个 '1' 后，其余 k-1 = 2 个 '1' 全部前置，中段 '0' 为空，
      答案仍是 "111"。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是**枚举全部重排**：生成长度 $n$ 的字符串的所有排列，过滤出末位为 `'1'` 者，再取数值最大。排列数高达 $O(n!)$，$n = 100$ 时是天文数字，直接爆炸。

退一步可以**排序**：把 `s` 降序排序得到 `1…10…0`（这已是「最大」的架势），但末位是 `'0'`，不满足奇数约束，还得把最后一个 '1' 挪到末尾。$O(n \log n)$ 能过，但绕了弯路——**答案只依赖 '1' 和 '0' 各有几个，原串的顺序信息全是冗余**，问题可以降维成一次计数。

### 3.2 核心观察：守末位 + 冲高位

![核心概念：一个 1 守末位保证奇数，其余 1 全冲最高位，0 垫中间](images/max_odd_binary_concept.svg)

- **观察 1（奇数约束 ⟺ 末位是 '1'）**：二进制数 $\sum_i b_i 2^i$ 中，$i \ge 1$ 的项全是 2 的倍数，奇偶性完全由最低位 $b_0$ 独占。所以答案的末位必须是一个 '1'——从 $k$ 个 '1' 里扣下一个看守末位。
- **观察 2（最大化 ⟺ '1' 冲高位）**：位权 $2^i$ 随位置升高严格增大，任何「高位 0 压着低位 1」的安排，交换两者都严格变大（且不动末位、不破坏奇偶性）。所以剩下的 $k-1$ 个 '1' 应**全部堆到最前**。
- **观察 3（'0' 的归宿）**：剩下的 $n-k$ 个 '0' 只能垫在中间，而题目明确允许前导零，连「开头不能是 0」的最后一条美学约束也被豁免。

三个观察合起来，答案形态唯一：

$$\text{答案} = \underbrace{11\cdots1}_{k-1\ \text{个}} \; \underbrace{00\cdots0}_{n-k\ \text{个}} \; 1$$

### 3.3 算法流程

![算法流程：一趟统计 1 的个数，然后三段拼接直接输出](images/max_odd_binary_flow.svg)

整个算法只有「一趟计数 + 三段拼接」：

1. 扫描 `s`，统计 `'1'` 的个数 $k$（$n$ 为串长）；
2. 依次拼接：$(k-1)$ 个 `'1'` → $(n-k)$ 个 `'0'` → 末位一个 `'1'`；
3. 返回拼接结果。

题目保证 $k \ge 1$，因此 $k-1 \ge 0$ 恒成立，**无需任何特判**——连「全 0」这种边界都被约束排除掉了。

### 3.4 示例演算

![示例演算：四个输入的三段拼接过程](images/max_odd_binary_walkthrough.svg)

| 输入 `s` | $n$ | $k$ | 第 1 段（$k{-}1$ 个 '1'） | 第 2 段（$n{-}k$ 个 '0'） | 第 3 段 | 结果 |
|---------|-----|-----|--------------------------|--------------------------|---------|------|
| `"010"` | 3 | 1 | `""`（空串） | `"00"` | `"1"` | `"001"` |
| `"0101"` | 4 | 2 | `"1"` | `"00"` | `"1"` | `"1001"` |
| `"110"` | 3 | 2 | `"1"` | `"0"` | `"1"` | `"101"` |
| `"111"` | 3 | 3 | `"11"` | `""`（空串） | `"1"` | `"111"` |

四个输入恰好覆盖两端边界：$k=1$ 时前缀为空串（答案全是前导零），$k=n$ 时中段为空串（答案全 '1'）。

## 4. 算法细节

1. **计数而非排序**：答案只依赖字符多重集 $\{1^k,\ 0^{n-k}\}$，与原串顺序无关。识别出「顺序信息冗余」、把问题降维到计数，是本题唯一的思维含量；一趟 $O(n)$ 计数优于 $O(n \log n)$ 排序。
2. **三段拼接用构造 API**：C++ 用 `string(cnt, ch)` 串联，Python 用 `ch * cnt`，三段各自直接生成，连循环都不用手写。两个段长 $k-1$ 与 $n-k$ 都可能为 0，构造 0 个字符得到空串，天然合法。
3. **替代写法（原地重排）**：如果想体现「重排」的操作感，可在原串上双指针交换——第一步征用一个 '1' 守末位，第二步把其余 '1' 冒泡到前部。两步恰好对应「先满足约束、再贪心优化」，额外空间 $O(1)$，见 §7 的第二份代码。
4. **排序思路的正确落地**：降序排序得 `1…10…0` 后，把下标 $k-1$ 处的 '1' 与末位 '0' 交换即可，$O(n \log n)$，能过但绕路。

## 5. 正确性证明

**引理 1（奇偶由末位独占）**：二进制数 $v = \sum_{i=0}^{n-1} b_i 2^i$ 为奇数，当且仅当 $b_0 = 1$。

**证明**：当 $i \ge 1$ 时 $2^i \equiv 0 \pmod 2$，故 $v \equiv b_0 \pmod 2$，奇偶性完全由最低位给出。∎

**引理 2（交换升值）**：设重排 $b$ 的末位为 '1'。若存在位置 $a > b \ge 1$ 满足 $b_a = \texttt{'0'}$、$b_b = \texttt{'1'}$（即非末位区域中「高位 0 压着低位 1」），交换两处后数值严格增大，且仍为奇数。

**证明**：交换前后其余位不变，数值变化量为 $2^a - 2^b > 0$，严格增大；末位 $b_0$ 未参与交换，由引理 1 奇偶性不变。∎

**引理 3（前缀形态唯一）**：固定末位为 '1' 后，前 $n-1$ 位由 $k-1$ 个 '1' 与 $n-k$ 个 '0' 组成，其中数值最大的排列唯一：前 $k-1$ 位全 '1'、后 $n-k$ 位全 '0'。

**证明**：若前 $n-1$ 位不满足「'1' 全在 '0' 前」，则存在位置 $a > b \ge 1$ 使得 $b_a = \texttt{'0'}$、$b_b = \texttt{'1'}$，由引理 2 交换后严格变大，故该排列不是最大。反之，满足该形态的排列唯一，且其前 $n-1$ 位中不存在任何逆置对（所有 '1' 权重大的位置都取满了 1），无法再通过引理 2 改进。∎

**定理**：$\texttt{'1'} \times (k-1) + \texttt{'0'} \times (n-k) + \texttt{'1'}$ 是 `s` 能重排出的最大二进制奇数。

**证明**：由引理 1，奇数重排的末位必为 '1'，故可行解集合恰为「末位 '1' 的全部重排」。在这类解中扣去末位后，前缀是 $k-1$ 个 '1' 与 $n-k$ 个 '0' 的排列，由引理 3 其最大且唯一者为全 '1' 前缀 + 全 '0' 中段。该串与 `s` 拥有相同的字符多重集（可由重排得到）、末位为 '1'（是奇数）、且前缀已取到最大，故它是最大的二进制奇数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描统计 $k$ 为 $O(n)$，三段拼接共构造 $n$ 个字符为 $O(n)$。
- **空间复杂度**：$O(n)$。存放返回的答案字符串（输出本身不可避免）；除输出外仅用 $O(1)$ 计数变量，原地双指针写法可在原串上完成。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string maximumOddBinaryNumber(string s) {
        int n = s.size();
        int k = count(s.begin(), s.end(), '1');   // 一趟计数
        return string(k - 1, '1') + string(n - k, '0') + '1';
    }
};
```

### C++（原地双指针版）

```cpp
class Solution {
  public:
    string maximumOddBinaryNumber(string s) {
        int n = s.size();
        if (s[n - 1] != '1') {                    // 第一步：征用一个 '1' 守末位
            for (int i = 0; i < n; i++) {
                if (s[i] == '1') { swap(s[i], s[n - 1]); break; }
            }
        }
        int j = 0;                                // 第二步：其余 '1' 全部冒到最前
        for (int i = 0; i < n - 1; i++) {
            if (s[i] == '1') swap(s[i], s[j++]);
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def maximumOddBinaryNumber(self, s: str) -> str:
        k = s.count('1')                          # 一趟计数
        return '1' * (k - 1) + '0' * (len(s) - k) + '1'
```

## 8. 边界情况与易错点

1. **只有一个 '1'（$k=1$）**：唯一的 '1' 被末位征用，前缀段为空串，答案是 $(n-1)$ 个前导零 + 末位 '1'（示例 1 的 `"010"` → `"001"`）。$k-1 = 0$ 时 `string(0, '1')` / `'1' * 0` 合法返回空串，无需特判。
2. **全 '1'（$k=n$）**：中段为空串，答案就是 `s` 本身（如 `"111"` → `"111"`），注意不要误判为「无解」或额外交换。
3. **单字符输入**：`s = "1"`，$n = k = 1$，答案 `"1"`。
4. **陷阱：忘挪末位**：直接降序排序输出 `"110"` 是**偶数**；排序后必须把一个 '1' 换到末位。
5. **陷阱：转数值处理**：$n = 100$ 的二进制数约 $2^{100}$，超出 64 位整数范围，C++ 转 `long long` 直接溢出；应全程在字符串层面构造。Python 大整数虽不会溢出，但转数值再比较纯属多余。
6. **陷阱：去前导零**：题目明确**允许**前导零，且 $k=1$ 时前导零不可避免；擅自去除会改变长度甚至导致答案错误。
7. **进制误判**：全程按二进制位权思考（'1' 冲高位），不要按十进制数字的直觉处理。
