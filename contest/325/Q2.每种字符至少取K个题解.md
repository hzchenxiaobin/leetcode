# LeetCode 每种字符至少取 K 个 题解

## 1. 题目概述

- **标题 / 题号**：每种字符至少取 K 个（#2516，medium）
- **链接**：https://leetcode.cn/problems/take-k-of-each-character-from-left-and-right/
- **来源**：LeetCode 第 325 场周赛 Q2
- **难度**：中等
- **标签**：字符串、滑动窗口、双指针

**题意**：给定仅由 `'a'`、`'b'`、`'c'` 组成的字符串 `s` 和非负整数 $k$。每分钟取走 `s` 当前**最左侧**或**最右侧**的一个字符（取走后从串中移除）。要求取走的 `'a'`、`'b'`、`'c'` 每种**至少** $k$ 个，求最少分钟数；无解返回 $-1$。

**约束**：

- $1 \le \text{s.length} \le 10^5$
- `s` 仅由字母 `'a'`、`'b'`、`'c'` 组成
- $0 \le k \le \text{s.length}$

> 💡 关键不变式：每步只能取「最左」或「最右」⇒ 取走的部分永远是**一个前缀 + 一个后缀**，留下的必然是**中间一段连续子串**。于是「最少取走多少」$\Leftrightarrow$「中间最长能保留多少」——典型的**正难则反**。

## 2. 示例

**示例 1**

```text
输入：s = "aabaaaacaabc", k = 2
输出：8
解释：
从左侧取 3 个字符（"aab"）：a×2、b×1；
从右侧取 5 个字符（"caabc"）：a×4、b×2、c×2。
合计 a:4、b:2、c:2，均 ≥ 2，共 3 + 5 = 8 分钟，为最少值。
```

**示例 2**

```text
输入：s = "a", k = 1
输出：-1
解释：串中不存在 'b' 和 'c'，即使全取走也不够，无解。
```

**示例 3**（$k=0$ 的退化）

```text
输入：s = "abc", k = 0
输出：0
解释：每种字符至少取 0 个，一步不取即满足。
```

## 3. 解题思路

### 3.1 暴力思路：枚举「左取 i 个 + 右取 j 个」

操作序列只由两个数字刻画：左取 $i$ 个、右取 $j$ 个（$i + j \le n$），取走集合恰为前缀 `s[0:i]` 并上后缀 `s[n-j:n]`。暴力枚举所有 $(i, j)$，用前缀计数表与后缀计数表 $O(1)$ 判断三类计数是否都 $\ge k$，取最小的 $i + j$。

枚举对数 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次，严重超时。根病在于：**同一个「中间保留段」被反复表达成不同的 $(i, j)$ 对**——固定中间段长度后，$i + j = n - (\text{中间段长度})$ 是定值，二维枚举全是冗余。

### 3.2 核心观察：正难则反，求「最长可保留的中间子串」

![核心观察：取走=前缀+后缀，保留=中间连续子串](images/2516_prefix_suffix_concept.svg)

三个层层递进的观察：

1. **结构**：每步取最左或最右，$t$ 步后取走的是前缀 `s[0:l]` 与后缀 `s[r:n]`（$l + n - r = t$），**保留部分是连续子串 `s[l+1 .. r-1]`**（§5 引理 1 有严格证明）。因此最少取走数 $= n - \text{最长合法保留子串长度}$。
2. **约束翻转**：设全串中字符 $c$ 总数为 $\text{cnt}[c]$，保留窗口内为 $\text{win}[c]$。取走部分中 $c$ 的个数 $= \text{cnt}[c] - \text{win}[c]$，故「取走 $\ge k$」$\iff$ 「$\text{win}[c] \le \text{cnt}[c] - k$」。记上界 $\text{limit}[c] = \text{cnt}[c] - k$。
3. **可行性**：若某 $\text{cnt}[c] < k$，全取走也不够，返回 $-1$；否则 $\text{limit}[c] \ge 0$，空窗口天然合法。

问题转化为：**求最长子串，使 `'a'`、`'b'`、`'c'` 每类出现次数都不超过各自 `limit`**——经典的上界型单调滑窗。

> ⚠️ 本题是**上界型**窗口（扩张易越界、收缩易修复），与 76 最小覆盖子串的**下界型**（扩张易满足、收缩易破坏）方向相反：口诀「下界求最短、上界求最长」。

### 3.3 算法流程：上界型滑动窗口

![算法流程：滑动窗口求最长合法保留子串](images/2516_sliding_window_flow.svg)

1. 一趟扫描统计 $\text{cnt}[a/b/c]$；任一 $< k$ 则返回 $-1$；否则算 $\text{limit}[c] = \text{cnt}[c] - k$。
2. 双指针 $l = 0$，窗口计数 $\text{win} = \{0,0,0\}$，$\text{maxWin} = 0$。
3. 右端 $r$ 从 $0$ 到 $n-1$：先 $\text{win}[s[r]] \mathrel{+}= 1$；只要 $\text{win}[s[r]] > \text{limit}[s[r]]$ 就左缩（$\text{win}[s[l]] \mathrel{-}= 1$，$l \mathrel{+}= 1$）。
4. 用 $r - l + 1$ 更新 $\text{maxWin}$；最终返回 $n - \text{maxWin}$。

> 💡 内层 `while` 只判 $s[r]$ 一类就够：加入 $s[r]$ 前窗口已合法，这一步只让 $\text{win}[s[r]]$ 加一，只它可能越界；左缩只会让各类计数减小，不会制造新越界。$l$ 全程单调不退、至多右移 $n$ 次，故整体仍是 $\Theta(n)$。

### 3.4 示例演算

以示例 1 为例：$s = $ `aabaaaacaabc`（$n=12$），$k=2$。统计 $\text{cnt} = \{a{:}8,\ b{:}2,\ c{:}2\}$，均 $\ge 2$，故 $\text{limit} = \{a{:}6,\ b{:}0,\ c{:}0\}$——**窗口里不得含任何 $b$ 或 $c$**，只能装纯 $a$ 段且 $a \le 6$。

| $r$ | 新入字符 | 动作 | 窗口 | $\text{win}(a,b,c)$ | $\text{maxWin}$ |
|---|---|---|---|---|---|
| $0,1$ | `a,a` | 扩张 | $[0,1]$ | $(2,0,0)$ | $2$ |
| $2$ | `b` | $b$ 越界 → 左缩清空 | $\varnothing$（$l=3$） | — | $2$ |
| $3..6$ | `a,a,a,a` | 扩张 | $[3,6]$ | $(4,0,0)$ | $\mathbf{4}$ |
| $7$ | `c` | $c$ 越界 → 左缩清空 | $\varnothing$（$l=8$） | — | $4$ |
| $8,9$ | `a,a` | 扩张 | $[8,9]$ | $(2,0,0)$ | $4$ |
| $10$ | `b` | 左缩清空 | $\varnothing$（$l=11$） | — | $4$ |
| $11$ | `c` | 左缩清空 | $\varnothing$（$l=12$） | — | $4$ |

最长合法保留段为 $[3,6]=$ `aaaa`（4 个），返回 $12 - 4 = 8$ ✓。恰好对应官方解释：左取 `"aab"` 3 个 + 右取 `"caabc"` 5 个。

## 4. 算法细节

1. **为什么要先做总数检查**：既给出无解判定（任一 $\text{cnt}[c] < k \Rightarrow -1$），又保证 $\text{limit}[c] = \text{cnt}[c] - k \ge 0$ 非负——空窗口（各类计数 $0$）因此天然合法，滑窗的收缩循环必有终点（最多收缩到空）。
2. **`while` 的判定只看 $s[r]$**：合法窗口加入 $s[r]$ 后仅 $\text{win}[s[r]]$ 增一，唯一可能越界的就是这一类；左缩只减不增，不会引入新越界，故收缩到 $\text{win}[s[r]] \le \text{limit}[s[r]]$ 即整体合法，无需逐类复查。
3. **`maxWin` 初值为 0**：对应空窗口这一「平凡合法」的保留方案（取走全部）。$k = 0$ 时 $\text{limit} = \text{cnt}$，全串合法，$\text{maxWin} = n$，返回 $0$，正确退化，无需特判。
4. **字符集只有 3 类**：用长度 3 的数组按 $s[r] - \text{'a'}$ 索引，避免哈希开销；若字符集扩大到 $26$ 类甚至更多，骨架不变，只换数组长度或 `dict`。
5. **等价写法（前缀 + 后缀双指针）**：预处理后 $j$ 个字符的计数 $\text{suf}[j]$；枚举左取个数 $i$（前缀计数逐字符递推），「补足 $k$」所需的最小 $j$ 随 $i$ 增大单调不增，再扫一遍即 $O(n)$。与滑窗反转法同阶，但代码更长；滑窗版把两端统一成一个「保留窗口」，更简洁。

## 5. 正确性证明

**引理 1（结构）**：任意操作序列执行 $t$ 步后，已取走的字符恰为某个前缀 `s[0:l]` 与某个后缀 `s[r:n]`（$l \le r$，$t = l + n - r$），剩余部分为连续子串 `s[l .. r-1]`。

**证明**：对 $t$ 归纳。$t=0$ 时 $l=0, r=n$，取走为空、剩余为全串，成立。设 $t$ 步后剩余 `s[l..r-1]`（仍按原下标）：下一步取最左即取 $s[l]$，剩余变为 `s[l+1..r-1]`；取最右即取 $s[r-1]$，剩余变为 `s[l..r-2]`。两种情况取走部分都保持「前缀 + 后缀」形态。∎

**引理 2（约束翻转）**：对引理 1 中的形态，取走部分每类字符个数 $\ge k$ $\iff$ 剩余窗口满足 $\text{win}[c] \le \text{cnt}[c] - k$（对所有 $c \in \{a,b,c\}$）。

**证明**：取走部分与剩余窗口在原串上互补，故 $\text{taken}[c] + \text{win}[c] = \text{cnt}[c]$。于是 $\text{taken}[c] \ge k \iff \text{win}[c] \le \text{cnt}[c] - k$。∎

**推论**：存在可行操作序列 $\iff$ 每类 $\text{cnt}[c] \ge k$（充分性：把整串取完即可；必要性：取走部分是全串的子集）。这正是算法开头的 $-1$ 检查。

**引理 3（子窗口封闭性）**：合法窗口的任意子窗口也合法。

**证明**：子窗口内每类字符的计数不超过原窗口对应计数。∎

**引理 4（双指针不漏）**：算法处理完每个 $r$ 后，$[l, r]$ 是以 $r$ 为右端点的最长合法窗口（允许收缩到空，即长度 $0$）。

**证明**：归纳假设处理 $r-1$ 后窗口 $[l, r-1]$ 合法。处理 $r$：仅 $\text{win}[s[r]]$ 增一，故只有 $s[r]$ 这一类可能越界，`while` 条件恰指向它；左缩只让计数减小，所以循环终止时该类达标、其余类原本达标且只减不增，窗口整体合法。最短性：`while` 只要 $s[r]$ 类越界就继续收缩，停在**最小**的合法 $l$。不漏性：本轮起点继承上一轮的 $l$，若某个 $l' < l$，则 $[l', r-1]$ 包含上一轮已越过阈值之前的非法窗口（由引理 3 的逆否：非法窗口的超集仍非法，因计数只增），故 $[l', r]$ 必非法，不会被错过。∎

**定理**：算法返回最少分钟数；无解时返回 $-1$。

**证明**：由引理 1，任意策略取走 $t$ 个对应「前缀 + 后缀」形态；由引理 2，该形态可行 $\iff$ 对应保留窗口合法，且 $t = n - \text{窗口长度}$。故最优值 $= n - \max\{\text{合法窗口长度}\}$。由引理 4，算法对每个右端点求出以其结尾的最长合法窗口；任意非空窗口均有右端点，故取 `max` 恰为全局最长合法窗口。无解情形由推论在开头拦截返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。右指针 $r$ 恰走 $n$ 步；左指针 $l$ 单调不退、全程至多右移 $n$ 步（每个字符至多进窗、出窗各一次），两个指针合计 $\Theta(n)$；计数与检查均为常数。
- **空间复杂度**：$O(1)$。仅 `cnt`、`limit`、`win` 三个长度 3 的数组与常数个整型变量，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int takeCharacters(string s, int k) {
        int n = s.size();
        array<int, 3> cnt{};
        for (char c : s) cnt[c - 'a']++;

        for (int i = 0; i < 3; i++)
            if (cnt[i] < k) return -1;          // 全取也不够，无解

        array<int, 3> limit{cnt[0] - k, cnt[1] - k, cnt[2] - k};
        array<int, 3> win{};
        int l = 0, maxWin = 0;
        for (int r = 0; r < n; r++) {
            int idx = s[r] - 'a';
            win[idx]++;                          // 右端纳入保留窗口
            while (win[idx] > limit[idx]) {      // 仅 s[r] 这类可能越界
                win[s[l] - 'a']--;
                l++;
            }
            maxWin = max(maxWin, r - l + 1);
        }
        return n - maxWin;
    }
};
```

### Python

```python
class Solution:
    def takeCharacters(self, s: str, k: int) -> int:
        n = len(s)
        cnt = [0, 0, 0]
        for ch in s:
            cnt[ord(ch) - 97] += 1
        if min(cnt) < k:
            return -1                            # 全取也不够，无解

        limit = [c - k for c in cnt]
        win = [0, 0, 0]
        l = 0
        max_win = 0
        for r, ch in enumerate(s):
            idx = ord(ch) - 97
            win[idx] += 1                        # 右端纳入保留窗口
            while win[idx] > limit[idx]:         # 仅 s[r] 这类可能越界
                win[ord(s[l]) - 97] -= 1
                l += 1
            max_win = max(max_win, r - l + 1)
        return n - max_win
```

## 8. 边界情况与易错点

1. **无解判定要前置**：任一 $\text{cnt}[c] < k$ 直接返回 $-1$（示例 2 中 `'b'`、`'c'` 计数为 0）。漏掉的话，负的 `limit` 会让 `while` 收缩到 $l > r$ 仍在死循环或逻辑错乱。
2. **$k = 0$ 不需特判**：$\text{limit} = \text{cnt}$，全串即最长合法窗口，返回 $0$（示例 3）。
3. **`while` 只判 $s[r]$ 一类**：多判无害但多余；判错类（如判全部三类用 `or` 连接反而不收缩）才是 bug 源头。
4. **`maxWin` 必须初始化为 0**：初始空窗口对应「全部取走」的保底方案；若初始化为 $-\infty$ 或 1，遇到整串无任何合法非空窗口时会算错。
5. **返回的是 $n - \text{maxWin}$**：窗口越长取走越少，方向别写反（返回 `maxWin` 是最长保留段长度，不是分钟数）。
6. **收缩可以把窗口清空**：$l$ 可以走到 $r + 1$（长度 0），不是不变式错误；`r - l + 1` 此时为 0，不更新 `maxWin`。
7. **同场次对照**：Q1（#2515）是「环形数组上两个方向走」，本题是「线性串两端取」，都靠「把过程坍缩成少数几个参数 + 一次线性扫描」解决。
