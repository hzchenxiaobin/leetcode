# LeetCode 礼盒的最大甜蜜度 题解

## 1. 题目概述

- **标题 / 题号**：礼盒的最大甜蜜度（#2517，medium）
- **链接**：https://leetcode.cn/problems/maximum-tastiness-of-candy-basket/
- **来源**：LeetCode 第 325 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、二分查找、排序、二分答案

**题意**：给定正整数数组 `price`（`price[i]` 为第 $i$ 类糖果的价格）和正整数 $k$。商店把 $k$ 类**不同**糖果打包成礼盒出售，礼盒的**甜蜜度**定义为盒中**任意两种**糖果价格绝对差的最小值。返回礼盒能达到的**最大**甜蜜度。

**约束**：

- $2 \le k \le \text{price.length} \le 10^5$
- $1 \le \text{price[i]} \le 10^9$

> 💡 **读题关键**：①「最大化最小值」是**二分答案**的标准信号；② 甜蜜度只关心「选了哪些价格」而与原始下标顺序无关 ⇒ 可以先排序；③ $k$ 类「不同」指**下标不同**，价格可以相等（此时甜蜜度可以为 0），**不能去重**。

## 2. 示例

**示例 1**

```text
输入：price = [13,5,1,8,21,2], k = 3
输出：8
解释：选出价格 [13,5,21]（排序后 [5,13,21]）。
      甜蜜度 = min(|13−5|, |13−21|, |5−21|) = min(8, 8, 16) = 8。
      可以证明 8 是能取得的最大甜蜜度。
```

**示例 2**

```text
输入：price = [1,3,1], k = 2
输出：2
解释：选 [1,3]。甜蜜度 = min(|1−3|) = 2。
      两颗价格 1 的糖不能提供更大的差，选 1 和 3 最优。
```

**示例 3**（价格全相同，答案为 0 的退化）

```text
输入：price = [7,7,7,7], k = 2
输出：0
解释：任选两类，价格差都是 0，甜蜜度 = 0。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有组合

枚举从 $n$ 类中选 $k$ 类的全部 $\binom{n}{k}$ 种组合，对每种组合求两两价格差的最小值，再取所有组合中的最大值。$n = 10^5$ 时组合数是天文数字，完全不可行。

> ⚠️ 暴力的根病在于把「选 $k$ 颗」当成**组合搜索**。但甜蜜度只依赖「选中值的分布」，一旦意识到「排序后只有相邻差重要」，问题就从指数级组合搜索塌缩为**对答案域的二分**。

### 3.2 核心观察：排序 + 二分答案

![核心观察：排序后选 k 颗，甜蜜度 = 最小相邻差](images/2517_adjacent_gap_concept.svg)

三个观察层层递进：

1. **排序后只需看相邻差**：把任意选出的 $k$ 颗按价格排序为 $a_1 \le a_2 \le \cdots \le a_k$。任意 $a_j - a_i\ (j > i)$ 都可以拆成中间各相邻差之和 $\sum_{t=i}^{j-1}(a_{t+1}-a_t)$，其中每一项都 $\ge$ 全局最小相邻差，故**任意两两差 $\ge$ 最小相邻差**。而相邻差本身也是两两差之一，所以**甜蜜度恰好等于选中序列的最小相邻差**——与原数组顺序无关，先整体排序。

2. **答案域单调（二段性）**：设 $f(d) =$ 「能否选出 $k$ 颗使**相邻差都 $\ge d$**」。若 $f(d_0)$ 为真，则同一选法对一切 $d \le d_0$ 也真。于是可行域必形如 $[0, d^*]$，答案即最大可行值 $d^*$——这正是二分所需的二段性。

3. **check 贪心 $O(n)$**：给定 $d$ 判定 $f(d)$：从最小的开始选，每次选「下一个价格 $\ge$ 上一个 $+\ d$」的糖果。直觉是**选越靠前的越给后面留空间**（§5 引理 3 用交换论证严格化）。

> 💡 **识别信号**：题面出现「最大化最小值」且能 $O(n)$ 验证候选答案 ⇒ 想「二分答案」。与「最小化最大值」类（875 珂珂吃香蕉、1011 送包裹、410 分割数组）互为镜像：那类可行时向左收缩，本题可行时向右扩张。

### 3.3 算法流程：二分 + 贪心 check

![算法流程：排序 + 二分答案 + 贪心 check](images/2517_binary_search_flow.svg)

1. `price` 升序排序，记 $M = \text{price[n-1]} - \text{price[0]}$（值域跨度）。
2. 闭区间二分 $d \in [0, M]$：`mid = (lo + hi) / 2`，跑 `check(mid)`。
3. `check(d)`：`cnt = 1, last = price[0]`；遍历 `i = 1..n-1`，若 `price[i] - last >= d` 则 `cnt++, last = price[i]`（`cnt >= k` 立即返回真）；最终返回 `cnt >= k`。
4. 可行 ⇒ `ans = mid, lo = mid + 1`（向右找更大）；不可行 ⇒ `hi = mid - 1`（向左收紧）。循环结束返回 `ans`。

### 3.4 示例演算

![示例演算：二分 5 轮，check 与区间收缩全过程](images/2517_binary_search_walkthrough.svg)

以示例 1 为例：`price = [13,5,1,8,21,2]`，$k=3$。排序后 `[1,2,5,8,13,21]`，$M = 21 - 1 = 20$，`lo=0, hi=20`。五轮二分的 `check(mid)` 贪心选取与区间收缩如上图：第 1 轮 `mid=10` 只能选出 2 颗（不可行）；第 2~4 轮 `mid=4,7,8` 均可行，`ans` 依次升到 8；第 5 轮 `mid=9` 不可行，区间缩空，返回 `ans = 8`。

> ⚠️ **贪心选取的细节**：以 `mid=8` 为例，`last=1`：`2−1=1<8` 跳过、`5−1=4<8` 跳过、`8−1=7<8` 跳过、`13−1=12≥8` 选中（`last=13`）、`21−13=8≥8` 选中 ⇒ 选中 `[1,13,21]`，`cnt=3` ✓。注意「相邻差都 $\ge d$」是对**选中序列的相邻**而言，不是对原数组相邻下标而言。

## 4. 算法细节

1. **为什么先排序**：引理 1 表明甜蜜度只由「选中值集合的相邻差」决定，与输入顺序无关；排序后贪心 check 才能用「下一个 $\ge$ last $+\ d$」的一趟扫描实现。
2. **二分上下界**：下界 `lo = 0`——价格可以重复，答案可能为 0（示例 3），且 `check(0)` 恒真。上界 `hi = M`：$k \ge 2$ 时选中的 $k$ 个值全落在 $[\text{price[0]},\ \text{price[n-1]}]$ 内，最小差不超过总跨度 $M$，是合法上界。
3. **上界可收紧到 $\lfloor M/(k-1) \rfloor$**：鸽巢原理，$k$ 个点把跨度 $M$ 分成 $k-1$ 段相邻差，最小段 $\le M/(k-1)$。这只省常数（约 $\log_2 k$ 轮二分），不改变复杂度；主解用朴素的 $M$ 便于理解。
4. **check 的提前终止**：`cnt` 一到 $k$ 立即返回真，不必扫完全数组，实测常数明显更小。
5. **二分方向**：本题求「最大可行下界」，可行时 `ans = mid; lo = mid + 1` 向右扩张——写反（可行时缩左）会返回 0，是二分答案最常见的方向错误。

## 5. 正确性证明

**引理 1（相邻差支配）**：选中 $k$ 颗按价格升序为 $a_1 \le \cdots \le a_k$，则
$$\min_{i<j}\ (a_j - a_i) \;=\; \min_{1 \le i < k}\ (a_{i+1} - a_i).$$

**证明**：记右边为 $m$（最小相邻差）。任取 $j > i$，$a_j - a_i = \sum_{t=i}^{j-1}(a_{t+1}-a_t)$，和中每一项非负且都 $\ge m$（$m$ 是所有相邻差的最小值），故 $a_j - a_i \ge m$，从而左边 $\ge m$。反过来，每个相邻差 $a_{i+1}-a_i$ 本身就是某个两两差，故左边 $\le m$。两边夹逼即得等号。∎

**推论**：「甜蜜度 $\ge d$」$\iff$「存在选法使排序后相邻差都 $\ge d$」（即 $f(d)$）：由引理 1，甜蜜度 $=$ 最小相邻差，而最小相邻差 $\ge d \iff$ 所有相邻差 $\ge d$。

**引理 2（二段性）**：若 $f(d_0)$ 为真且 $0 \le d \le d_0$，则 $f(d)$ 为真。

**证明**：$f(d_0)$ 的那一选法满足所有相邻差 $\ge d_0 \ge d$，即它也是 $f(d)$ 的 witness。∎

**推论**：可行 $d$ 的集合是形如 $[0, d^*]$ 的前缀区间，$d^*$ 即所求最大甜蜜度。

**引理 3（贪心判定等价）**：`check(d)` 返回真 $\iff$ $f(d)$ 为真。

**证明**：（⇐）设存在合法选法 $b_1 < b_2 < \cdots < b_k$（相邻差都 $\ge d$），贪心依次选出 $g_1, g_2, \cdots$。对 $i$ 归纳证明 $g_i \le b_i$：基座 $g_1 = \text{price[0]} \le b_1$（$b_1$ 是某颗糖果的价格，必 $\ge$ 全局最小价）。归纳步：若 $g_i \le b_i$，则 $b_{i+1} \ge b_i + d \ge g_i + d$，即 $b_{i+1}$ 是「价格 $\ge g_i + d$」的候选之一，而贪心取的是**首个**满足该条件的糖果，故 $g_{i+1} \le b_{i+1}$。于是贪心至少能选出 $k$ 颗，`check(d)` 为真。（⇒）贪心的选取本身就是一种合法选法。∎

**定理**：算法返回礼盒的最大甜蜜度。

**证明**：由引理 2 的推论，可行域为 $[0, d^*]$；由引理 3，二分中每次 `check(mid)` 恰好判定 $f(\text{mid})$。闭区间二分 `while (lo <= hi)` 在可行时记录 `ans = mid` 并 `lo = mid + 1`、不可行时 `hi = mid - 1`，终止时 `ans` 为判过可行的最大 `mid`。初始区间 $[0, M]$ 覆盖 $[0, d^*]$（上界合法性见 §4 第 2 点），且 `check(0)` 恒真保证 `ans` 至少被更新为 0。故 `ans = d^*`，即最大甜蜜度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n\log n + n\log M)$。排序 $O(n\log n)$；二分 $O(\log M)$ 轮（$M \le 10^9$，约 30 轮），每轮 `check` 至多一趟 $O(n)$ 扫描（提前终止往往远小于 $n$）。$n = 10^5$ 时总量约 $3\times 10^6$ 次比较，远低于时限。
- **空间复杂度**：$O(\log n)$。仅排序的递归栈（原地排序不开额外数组）与常数个变量；Python 的 `check` 闭包同样只用常数空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumTastiness(vector<int>& price, int k) {
        sort(price.begin(), price.end());
        int lo = 0, hi = price.back() - price.front(), ans = 0;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (check(price, mid, k)) {
                ans = mid;          // 可行，向右找更大
                lo = mid + 1;
            } else {
                hi = mid - 1;       // 不可行，向左收紧
            }
        }
        return ans;
    }
private:
    bool check(const vector<int>& price, int d, int k) {
        int cnt = 1, last = price[0];
        for (int i = 1; i < (int)price.size(); ++i) {
            if (price[i] - last >= d) {
                if (++cnt >= k) return true;   // 提前终止
                last = price[i];
            }
        }
        return cnt >= k;
    }
};
```

### Python

```python
class Solution:
    def maximumTastiness(self, price: List[int], k: int) -> int:
        price.sort()

        def check(d: int) -> bool:
            cnt, last = 1, price[0]
            for p in price[1:]:
                if p - last >= d:
                    cnt += 1
                    if cnt >= k:
                        return True        # 提前终止
                    last = p
            return cnt >= k

        lo, hi, ans = 0, price[-1] - price[0], 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if check(mid):
                ans = mid                 # 可行，向右找更大
                lo = mid + 1
            else:
                hi = mid - 1              # 不可行，向左收紧
        return ans
```

## 8. 边界情况与易错点

1. **不要对 `price` 去重**：$k$ 类「不同」糖果指下标不同、价格可以重复（示例 3 全是 7）。去重后 `[7]` 连 $k=2$ 颗都选不出，或错误地抬高答案，是本题最阴的坑。
2. **`lo` 必须从 0 开始**：价格重复时答案为 0（示例 3），`check(0)` 恒真（任意差 $\ge 0$）；若从 1 开始会漏掉 0 答案。
3. **「相邻」指选中序列相邻**：`check` 里 `last` 是**上一颗选中**的价格，不是原数组前一个下标；写成 `price[i] - price[i-1] >= d` 是典型 bug。
4. **二分方向别写反**：可行时 `ans = mid; lo = mid + 1`（找更大），不可行时 `hi = mid - 1`。写反后恒返回 0。
5. **溢出检查**：$1 \le \text{price[i]} \le 10^9$，差值与 $M$ 至多约 $10^9$，32 位 `int`（上限约 $2.1\times10^9$）安全；若值域升到更大需换 `long long`。
6. **$k = n$（全选）**：二分同样正确，答案退化为排序后全数组的最小相邻差。
7. **同场次对照**：Q1（#2515）环形距离、Q2（#2516）两端取字符，加上本题，三题的共同套路是「先把问题坍缩成有序/线性结构，再一次线性扫描或二分判定」。
