# LeetCode 移除子树后的二叉树高度 题解

## 1. 题目概述

- **标题 / 题号**：移除子树后的二叉树高度（#2458，hard）
- **链接**：https://leetcode.cn/problems/height-of-binary-tree-after-subtree-removal-queries/
- **来源**：LeetCode 第 317 场周赛 Q4
- **难度**：困难
- **标签**：树、二叉树、广度优先搜索、深度优先搜索、预处理、查询

**题意**：给定一棵含 $n$ 个节点的二叉树 `root`（节点值互不相同且恰为 $1..n$）与长度为 $m$ 的查询数组 `queries`。每个查询**相互独立**：移除以 `queries[i]` 为根的整棵子树后，求剩余树的高度（根到节点最长路径的**边数**），返回所有查询的答案数组。

**约束**：

- $2 \le n \le 10^5$
- $1 \le \text{Node.val} \le n$，值互不相同
- $1 \le m \le \min(n,\, 10^4)$
- $\text{queries[i]} \ne \text{root.val}$（根永不被移除）

> 💡 本题在本仓库另有[每日题解 2458](../../solution/2401-2500/2458_移除子树后的二叉树高度.md)：侧重「脊柱 + 姐妹子树」的递归两遍 DFS 模板与面试问答。本篇按**周赛复盘视角**展开，侧重**赛场三级优化阶梯**（$O(nm) \to O(m\cdot\mathrm{depth}) \to O(n+m)$ 的识别路径）、**BFS 序全迭代实现**（链状树下 $10^5$ 递归深度的爆栈规避，Python 必须迭代）与**引理—定理式的严格证明**，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：逐查询重算——以及沿链聚合为什么还不够

**暴力一（逐查询重算整树）**：对每个查询 $q$，DFS 时跳过子树 $q$ 重算剩余高度，单次 $O(n)$，总计 $O(nm) \approx 10^5 \times 10^4 = 10^9$，必超时。

**暴力二（逐查询沿祖先链聚合）**：稍有经验的选手会发现「移除 $v$ 后，剩余的最深叶子只可能出现在 $v$ 的各级祖先的**姐妹子树**里」，于是对每个查询从 $v$ 沿祖先链走到根，逐层取姐妹子树的最深叶深度做 $\max$，单次 $O(\mathrm{depth}(v))$。但树退化成**链**时 $\mathrm{depth}$ 可达 $10^5$，$m \cdot \mathrm{depth}$ 最坏仍是 $10^9$ 量级——而且不同查询共享大量祖先前缀，**重复劳动**严重。

> ⚠️ 赛场分水岭：能否把「沿祖先链的逐层 $\max$」变成**一次自顶向下的累积传递**——父节点把已聚合好的最大值直接传给孩子，孩子只增量比较本层的一个新候选。做到这一点，复杂度立刻从「每查询一条链」降为「每个节点 $O(1)$」。

### 3.2 核心观察：幸存者 = 非后代，最深幸存叶决定剩余高度

![核心观察：移除子树 v 后，幸存者 = 祖先 + 各层姐妹子树](images/subtree_height_survivors_concept.svg)

先建立两个方向相反的基本量（各需一趟遍历）：

- $\mathrm{depth}(u)$：根到 $u$ 的边数（根为 $0$）——**自顶向下**传；
- $\mathrm{height}(u)$：子树 $u$ 的高度（叶子为 $0$）——**自底向上**汇。

两者相加得到关键的**复合量**：

$$f(u) = \mathrm{depth}(u) + \mathrm{height}(u) = \text{子树 } u \text{ 内最深叶子的深度}$$

**关键洞察**：移除 $\mathrm{subtree}(v)$ 后，剩余树仍以原根为根，节点集恰为 $v$ 的所有**非后代**。于是：

$$\text{剩余高度} = G(v) := \max\{\, \mathrm{depth}(u) : u \notin \mathrm{subtree}(v) \,\}$$

而非后代恰好来自三个来源（设 $a = \mathrm{parent}(v)$）：

1. $a$ 之外的一切（更高层的幸存者，**递归结构**）；
2. $a$ 本身（若 $v$ 是独子，$a$ 失去所有孩子变成叶子，深度 $\mathrm{depth}(a)$）；
3. 姐妹 $s$ 的整棵子树（**二叉树**里 $v$ 至多一个姐妹），其最深叶深度为 $f(s)$。

### 3.3 算法流程：自顶向下累积 + 三趟迭代遍历

![递推与流程：ans 沿脊柱累积传递，三趟 BFS 序遍历](images/subtree_height_recurrence_flow.svg)

把 §3.2 的三分来源写成**自顶向下递推**：

$$\mathrm{ans}[c] = \max\big(\mathrm{ans}[a],\ \mathrm{depth}(a)\ (\text{无姐妹时}),\ f(s)\ (\text{有姐妹时})\big)$$

两条互斥分支的取舍：有姐妹时 $f(s) \ge \mathrm{depth}(s) = \mathrm{depth}(a) + 1 > \mathrm{depth}(a)$，$\mathrm{depth}(a)$ 被**支配**，无需加入；无姐妹时 $a$ 变叶，$\mathrm{depth}(a)$ 是唯一新候选。根的哨兵取 $\mathrm{ans}[\mathrm{root}] = -1$（根外无幸存者，且根永不被查询）。

**实现采用三趟迭代遍历，全程无递归**：

1. **Pass 0（BFS 建序）**：队列一遍扫出访问序（父必先于子），同时下传 $\mathrm{depth}$、记录 $\mathrm{parent}$；
2. **Pass 1（逆 BFS 序求 height）**：BFS 序中孩子必排在父之后，**倒序遍历即是合法后序**——处理 $x$ 时其所有孩子已处理完，执行 $\mathrm{hgt}[\mathrm{par}(x)] \gets \max(\,\cdot,\ \mathrm{hgt}[x] + 1)$；
3. **Pass 2（正 BFS 序下传 ans）**：处理 $x$ 时 $\mathrm{ans}[x]$ 已由父算好，对 $x$ 的每个孩子按互斥分支算出其 $\mathrm{ans}$。

最后每个查询 $O(1)$ 查表：$\mathrm{answer}(q) = \mathrm{ans}[q]$。

### 3.4 示例演算

![示例演算：示例 2 的 depth/height/ans 全表与递推链](images/subtree_height_walkthrough.svg)

以示例 2 走查（完整表格见上图）：BFS 序为 $5, 8, 9, 2, 1, 3, 7, 4, 6$。关键递推链——

- $\mathrm{ans}[8] = \max(-1,\ \mathrm{depth}(5)=0,\ f(9)=1+1=2) = 2$；
- $\mathrm{ans}[2] = \max(\mathrm{ans}[8]=2,\ f(1)=2+0=2) = 2$；
- $\mathrm{ans}[4] = \max(\mathrm{ans}[2]=2,\ f(6)=3+0=3) = 3$ ✓。

查询 $[3,2,4,8]$ 依次得 $[3,2,3,2]$，与官方输出一致。注意 $\mathrm{ans}[2]=2$ 已把「根层姐妹 $9$ 的 $f=2$」吸收进来，$\mathrm{ans}[4]$ 只需增量比较本层姐妹 $6$——这正是「累积传递」取代「逐链重算」的体现。

## 4. 算法细节

1. **BFS 序的两用**：正序是合法前序（父先于子，Pass 0/2 用），逆序是合法后序（孩子先于父，Pass 1 用）。一棵序列两种遍历，省去显式栈的入出序管理。
2. **逆序求 height 的正确性**：处理 $x$ 时需 $\mathrm{hgt}[x]$ 已终态。$x$ 的孩子深度比 $x$ 大 $1$，在 BFS 序中必排在 $x$ 之后，逆序中必先于 $x$ 处理，届时已把 $\mathrm{hgt}[x]$ 更新完毕；叶子初始化为 $0$ 即终态。
3. **值即下标**：值域恰为 $1..n$ 且互不相同，用定长数组 `dep/hgt/ans/par` 替代哈希表，免去 `unordered_map` 的常数。`par` 数组只需存**父的值**。
4. **互斥分支**：有姐妹 → 候选 $f(s) = \mathrm{dep}[s] + \mathrm{hgt}[s]$；无姐妹 → 候选 $\mathrm{dep}[a]$（父变叶）。两分支写反或漏写是无姐妹分支的头号错误（单链树上全军覆没）。
5. **根哨兵 $-1$**：语义是「根之外无幸存者」。根的任何孩子的递推式里恒有 $\ge 0$ 的项（两孩子分支 $f(s) \ge 1$，独子分支 $\mathrm{depth}(\mathrm{root})=0$），哨兵不会泄漏进答案。
6. **爆栈规避**：$n \le 10^5$ 且树可退化为链，递归深度最坏 $10^5$——Python 默认递归上限 1000 直接 `RecursionError`；C++ 递归深度 $10^5$ 在部分判题环境也处于爆栈边缘。三趟 BFS 迭代是**工程上更稳**的选择，这是本实现相对递归版（见每日题解）的核心差异。
7. **另一等价解法**：部分题解对每个深度层把该层节点的 $f$ 值建**前缀/后缀最大值**，查询时沿祖先逐层取「祖先位置两侧」的最大。它与本解法本质同源（都是「排除脊柱、取各层最大 $f$」），但本解法把逐层 $\max$ 折叠成一次下传，代码量与常数都更优。

## 5. 正确性证明

约定 $\mathrm{subtree}(v)$ 含 $v$ 自身；$R(v) = \{u : u \notin \mathrm{subtree}(v)\}$ 为幸存者集；$D(S) = \max\{\mathrm{depth}(u) : u \in S\}$（空集取 $-\infty$）。

**引理 1**（幸存者刻画）：移除 $\mathrm{subtree}(v)$ 后，剩余树仍以原根为根且节点集恰为 $R(v)$，故剩余高度 $= D(R(v)) = G(v)$。

**证明**：删除一棵完整子树不影响其余节点与根的连通性与父子关系，剩余树是原树的子树且以原根为根。高度 $=$ 根到剩余节点的最长路边数 $= \max_{u \in R(v)} \mathrm{depth}(u) = G(v)$（$v \ne$ 根时根 $\in R(v)$，最大值良定义且 $\ge 0$）。∎

**引理 2**（$f$ 的含义）：对任意节点 $x$，$f(x) = \mathrm{depth}(x) + \mathrm{height}(x) = D(\mathrm{subtree}(x))$。

**证明**：对子树大小归纳。$x$ 为叶子时 $\mathrm{height}=0$，$f = \mathrm{depth}(x) = D(\{x\})$。否则最深叶子必落在某个孩子 $y$ 的子树内，$\mathrm{height}(x) = 1 + \max_y \mathrm{height}(y)$，且该孩子子树内最深叶深度为 $\mathrm{depth}(x) + 1 + \mathrm{height}(y)$，取 $\max_y$ 即 $D(\mathrm{subtree}(x)) = \mathrm{depth}(x) + \mathrm{height}(x)$。∎

**引理 3**（三分划分）：设 $c \ne \mathrm{root}$，$a = \mathrm{parent}(c)$，则

$$R(c) = R(a)\ \cup\ \{a\}\ \cup\ \big(\mathrm{subtree}(s)\ \text{若姐妹}\ s\ \text{存在}\big)$$

且三部分两两不交（$R(c) \cap \{a\} = \varnothing$，因为 $a \in R(c)$ 而 $a \notin R(a)$ 等按定义直接验证）。

**证明**：任取 $u \in R(c)$。若 $u \notin \mathrm{subtree}(a)$ 则 $u \in R(a)$；若 $u \in \mathrm{subtree}(a)$，则 $u = a$，或 $u$ 属于 $a$ 的某个孩子 $y \ne c$ 的子树——二叉树中这样的 $y$ 至多一个即姐妹 $s$，故 $u \in \mathrm{subtree}(s)$。反向包含：$R(a) \subseteq R(c)$（$\mathrm{subtree}(c) \subseteq \mathrm{subtree}(a)$）、$a \notin \mathrm{subtree}(c)$、$\mathrm{subtree}(s) \cap \mathrm{subtree}(c) = \varnothing$（不同孩子的子树不相交）。∎

**定理**（递推正确性）：对 $c \ne \mathrm{root}$、$a = \mathrm{parent}(c)$，

$$G(c) = \begin{cases} \max\big(G(a),\ \mathrm{depth}(a),\ f(s)\big) & \text{姐妹 } s \text{ 存在} \\[4pt] \max\big(G(a),\ \mathrm{depth}(a)\big) & \text{不存在} \end{cases}$$

**证明**：由引理 1，$G(c) = D(R(c))$；由引理 3 三分取 $\max$：$D(R(a)) = G(a)$，$D(\{a\}) = \mathrm{depth}(a)$，$D(\mathrm{subtree}(s)) = f(s)$（引理 2）；无姐妹时第三部分为空。∎

**推论**（算法正确性）：按 BFS 正序用上述递推计算的 `ans` 满足 `ans`$[v] = G(v)$（$v \ne \mathrm{root}$），从而每个查询输出正确。

**证明**：对 BFS 序归纳。基础：根置哨兵 $-1$；对根的孩子 $c$，真值 $G(c) = \max(-\infty, \mathrm{depth}(\mathrm{root}) = 0, \cdots)$，而算法算 $\max(-1, \ge 0 \text{ 的项})$——两孩子分支中 $f(s) \ge \mathrm{depth}(s) = 1 > -1$，独子分支中 $\mathrm{depth}(\mathrm{root}) = 0 > -1$，故哨兵 $-1$ 与 $-\infty$ 在 $\max$ 下产生相同结果。归纳步：处理节点 $x$ 时其 $\mathrm{ans}[x]$ 已由父在更早的 BFS 位置算出且等于 $G(x)$（归纳假设），Pass 1 又已保证全树 $\mathrm{hgt}$ 终态，故按定理计算的孩子值 $= G(\cdot)$。每个非根节点恰被父计算一次，查询 $v \ne \mathrm{root}$ 查表即得 $G(v)$，由引理 1 即剩余高度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。三趟遍历各 $O(n)$（每节点 $O(1)$：Pass 1 一次比较，Pass 2 每个孩子一次 $\max$），$m$ 次查询各 $O(1)$ 查表。
- **空间复杂度**：$O(n)$。四张值域数组（`dep/hgt/ans/par`）与 BFS 序数组；无递归栈开销（显式队列 $O(n)$ 最坏）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> treeQueries(TreeNode* root, vector<int>& queries) {
        const int N = 100001;
        vector<int> dep(N), hgt(N), ans(N), par(N);
        vector<TreeNode*> order;                        // BFS 序：父先于子
        order.push_back(root);
        for (int i = 0; i < (int)order.size(); ++i) {   // 边扫边追加 = 队列
            TreeNode* x = order[i];
            for (TreeNode* c : {x->left, x->right}) {
                if (c) {
                    par[c->val] = x->val;
                    dep[c->val] = dep[x->val] + 1;
                    order.push_back(c);
                }
            }
        }
        for (int i = (int)order.size() - 1; i >= 0; --i) { // 逆序 = 合法后序
            TreeNode* x = order[i];
            hgt[par[x->val]] = max(hgt[par[x->val]], hgt[x->val] + 1);
        }
        ans[root->val] = -1;                            // 根哨兵：根外无幸存者
        for (TreeNode* x : order) {                     // 正序：ans 自顶向下传
            int a = ans[x->val];
            TreeNode* l = x->left, *r = x->right;
            if (l && r) {
                ans[l->val] = max(a, dep[r->val] + hgt[r->val]); // f(姐妹)
                ans[r->val] = max(a, dep[l->val] + hgt[l->val]);
            } else if (l) {
                ans[l->val] = max(a, dep[x->val]);      // 独子：父变叶
            } else if (r) {
                ans[r->val] = max(a, dep[x->val]);
            }
        }
        vector<int> res;
        res.reserve(queries.size());
        for (int q : queries) res.push_back(ans[q]);    // O(1) 查表
        return res;
    }
};
```

> 💡 逆序循环处理根时 `par[root] = 0`，写入哑元 `hgt[0]`，无人读取、无害。全程无递归，链状树不爆栈。

### Python

```python
class Solution:
    def treeQueries(self, root: Optional[TreeNode], queries: List[int]) -> List[int]:
        N = 100001
        dep, hgt, ans, par = [0] * N, [0] * N, [0] * N, [0] * N
        order = [root]
        for x in order:                        # 边遍历边追加 = BFS
            for c in (x.left, x.right):
                if c:
                    par[c.val] = x.val
                    dep[c.val] = dep[x.val] + 1
                    order.append(c)
        for x in reversed(order):              # 逆序 = 合法后序，自底向上求 height
            p = par[x.val]
            hgt[p] = max(hgt[p], hgt[x.val] + 1)
        ans[root.val] = -1                     # 根哨兵
        for x in order:                        # 正序：ans 自顶向下传
            a = ans[x.val]
            l, r = x.left, x.right
            if l and r:
                ans[l.val] = max(a, dep[r.val] + hgt[r.val])  # f(姐妹)
                ans[r.val] = max(a, dep[l.val] + hgt[l.val])
            elif l or r:
                c = l or r
                ans[c.val] = max(a, dep[x.val])               # 独子：父变叶
        return [ans[q] for q in queries]      # O(1) 查表
```

> 💡 `for x in order: ... order.append(c)` 是 Python 的经典 BFS 惯用法（列表迭代器会跟随追加）。链深度 $10^5$ 下若用递归，默认上限 1000 必抛 `RecursionError`——迭代不是优化项而是**必需品**。

## 8. 边界情况与易错点

1. **递归爆栈（Python 必炸）**：树退化成 $10^5$ 长的链时递归深度 $= n$。Python 默认上限 1000；C++ 深递归在栈空间紧张的环境同样危险。BFS 迭代彻底规避（§4.6）。
2. **漏写「无姐妹 → $\mathrm{depth}[a]$」分支（头号 WA）**：单链树 `1→2→3→…` 上查询中部的 $v$，正确答案是 $\mathrm{depth}(v) - 1$（父变叶）；只写有姐妹分支会得到偏小的值。自构造示例 3 的 `n=2` 是最小反例：答案 0 恰来自 $\mathrm{depth}(\mathrm{root}) = 0$。
3. **高度按边数计**：叶子 $\mathrm{height} = 0$、根 $\mathrm{depth} = 0$。若误按点数计数，所有答案整体 $+1$。
4. **哨兵 $-1$ 而非 $0$**：语义上根之外无幸存者。写 $0$ 在本题**凑巧**不出错（根的每个孩子的候选中恒有 $\ge 0$ 项把哨兵吸收），但 $-1$ 才是可推广的正确语义。
5. **逆序求 height 时依赖「孩子后于父」**：这是 BFS 序的性质，DFS 前序**不**满足（前序中孩子紧随父，但兄弟子树穿插），不能随手换成前序逆扫。
6. **`par[root]` 哨兵**：逆序循环里根的父写作 $0$（哑元下标），须确认 `hgt[0]` 无人读取；若用 `n+1` 大小数组则更需留意越界。
7. **重复查询与任意查询点**：`ans` 表覆盖全部 $n$ 个点，`queries` 含重复值、含 `height=0` 的叶节点均无碍——叶节点查询的答案常等于原树高度（若最深叶不在其子树内），别对「叶子查询返回大值」感到意外。
8. **别被 $m \le 10^4$ 诱惑走「逐查询沿链」**：$m \cdot \mathrm{depth}$ 在链状树下仍达 $10^9$ 量级（§3.1），且与 $O(n)$ 预处理相比毫无优势。

**延伸思考**：

- **多叉树推广**：姐妹不再唯一，$\max$ 需排除查询点所在分支——对每个父节点维护孩子 $f$ 值的**最大与次大**（top-2），查询分支若是最大者取次大、否则取最大，仍能做到 $O(1)$ 每节点。这与「按层前缀/后缀最大值」解法（§4.7）同源，都是「排除一个元素的整体 $\max$」的经典手法。
- **允许查询根**：需约定空树高度（一般 $-1$ 或 $0$），并给 `ans[root]` 赋实际哨兵。
- **强制在线 / 树动态变化**：静态两趟遍历失效，需要树剖 / LCT 级别的数据结构维护「删子树求最深叶」，复杂度上升一个量级——这也是本题定为 Hard 但仍属「套路困难」的原因。
