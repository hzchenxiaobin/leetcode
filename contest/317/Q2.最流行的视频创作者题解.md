# LeetCode 最流行的视频创作者 题解

## 1. 题目概述

- **标题 / 题号**：最流行的视频创作者（#2456，medium）
- **链接**：https://leetcode.cn/problems/most-popular-video-creator/
- **来源**：LeetCode 第 317 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序、堆（优先队列）

**题意**：给定三个长度均为 $n$ 的数组 `creators`、`ids`、`views`：第 $i$ 个视频的创作者是 `creators[i]`、id 是 `ids[i]`、播放量是 `views[i]`。创作者的**流行度** = 其**所有**视频播放量之**和**。求流行度**最高**的创作者及其播放量**最大**的视频 id：

- 多个创作者流行度并列最高时**全部**返回；
- 某创作者有多个播放量并列最大的视频时，返回其中**字典序最小**的 `id`。

返回二维字符串数组 `answer`，`answer[i] = [creator_i, id_i]`，顺序任意。

**约束**：

- $n = \text{creators.length} = \text{ids.length} = \text{views.length}$
- $1 \le n \le 10^5$
- $1 \le \text{creators}[i].\text{length},\ \text{ids}[i].\text{length} \le 5$
- `creators[i]`、`ids[i]` 仅由小写英文字母组成
- $0 \le \text{views}[i] \le 10^5$

> 💡 本题在本仓库另有[每日题解 2456](../../solution/2401-2500/2456_最流行的视频创作者.md)：侧重「哈希双聚合」方法论、Top-K 扩展与面试问答。本篇按**周赛复盘视角**展开，侧重**模板识别**（分组聚合是 Q2 手速题）、赛场两处 **WA 高发点**（64 位溢出、$0$ 播放量哨兵）与**更新与顺序无关**的严格证明，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：creators = ["alice","bob","alice","chris"], ids = ["one","two","three","four"], views = [5,10,5,4]
输出：[["alice","one"],["bob","two"]]
解释：alice 流行度 = 5 + 5 = 10；bob = 10；chris = 4。alice、bob 并列最高。
alice 播放量最高的视频是 "one"(5) 与 "three"(5)，"one" 字典序更小 → 取 "one"。
```

**示例 2**

```text
输入：creators = ["alice","alice","alice"], ids = ["a","b","c"], views = [1,2,2]
输出：[["alice","b"]]
解释："b"(2) 与 "c"(2) 并列最大，"b" 字典序更小 → 取 "b"。
```

**示例 3**（自构造，覆盖「全零并列 + $0$ 播放量平票」分支）

```text
输入：creators = ["a","b","a","b"], ids = ["x","y","z","w"], views = [0,0,0,0]
输出：[["a","x"],["b","w"]]
解释：所有创作者流行度均为 0，全部并列最高。a 的 "x"、"z" 播放量平票（均为 0），字典序取 "x"；
b 的 "y"、"w" 平票，"w" 字典序更小 → 取 "w"。
```

## 3. 解题思路

### 3.1 暴力思路：每个创作者独立扫描两遍

先收集所有**不同**创作者（设共 $m$ 个），再对每个创作者 $c$ 扫两遍数组：一遍累加流行度，一遍找其播放量最大的视频（平票比字典序）。时间 $O(m \cdot n)$，最坏 $m = n$ 时 $O(n^2) = 10^{10}$，必然超时。问题出在**同一份输入被按创作者反复线性扫描**——而「分组」关系本可一次遍历建立。

> ⚠️ 介于两者之间的做法是先按创作者**排序**再分组聚合，$O(n \log n)$ 能过但排序非必要——题面标签里的 Sorting / Heap 都是迷惑项，见 3.2。

### 3.2 核心观察：哈希分组 + 组内「双聚合」

![核心观察：按创作者哈希分组，组内同步维护流行度与最热视频](images/popular_creator_group_aggregate.svg)

把题目拆成「**分组聚合 + 取最大**」两段流水线：

1. **一趟遍历建聚合表**：用哈希表把每个创作者映射到一条聚合记录 $\{\text{tot},\ \text{mx},\ \text{id}\}$。对每个三元组 $(c, \text{id}, v)$：
   - $\text{tot}[c] \mathrel{+}= v$（流行度累加）；
   - 双关键字更新最热视频：若 $v > \text{mx}$，**或** $v = \text{mx}$ 且 $\text{id}$ 字典序小于当前 $\text{id}$，则 $(\text{mx}, \text{id}) \leftarrow (v, \text{id})$。
2. **末尾取最大流行度**：遍历中顺手维护 $\text{maxPop}$，结束时收集所有 $\text{tot}[c] = \text{maxPop}$ 的创作者，各带上其最热 id。

两个聚合量都**只随新数据单调更新**：求和天然可增量；「播放量取大、平票 id 取字典序小」构成全序（§5 引理 1），新视频只会把记录推向更优或保持不变，**与到达顺序无关**——故无需保存任何创作者的视频列表，每行只留两个标量加一个字符串。又因为只取**最大**（Top-1 含并列）而非前 $K$，末尾一次「等于」过滤即可，**不需要排序也不需要堆**。

### 3.3 算法流程

![算法流程：单表双聚合 + 末尾等于过滤，红色标注两处 WA 高发点](images/popular_creator_tiebreak_flow.svg)

线性流水线：初始化聚合表（哨兵 $\text{mx} = -1$）→ 一趟遍历（累加流行度并同步维护 $\text{maxPop}$，再按双关键字刷新最热视频）→ 循环结束对聚合表做一次 $O(m)$「等于」过滤收集答案。

### 3.4 示例演算

![示例 1 演算：一趟遍历建聚合表，第 2 步平票比字典序](images/popular_creator_walkthrough.svg)

以示例 1 演算（完整表格见上图）：

| $i$ | 三元组 $(c, \text{id}, v)$ | `tot[c]`（后） | `best[c]`（后） | `maxPop` |
|-----|---------------------------|----------------|-----------------|----------|
| 0 | (alice, one, 5) | alice = 5 | (5, "one") | 5 |
| 1 | (bob, two, 10) | bob = 10 | (10, "two") | 10 |
| 2 | (alice, three, 5) | alice = 10 | (5, "one") 保持 | 10 |
| 3 | (chris, four, 4) | chris = 4 | (4, "four") | 10 |

第 $i = 2$ 步是关键：alice 新增 "three"(5) 与历史最热 "one"(5) **平票**，但 "three" 字典序**大于** "one"（首字母 't' > 'o'），`best[alice]` 保持 "one"——平票判定只拿当前记录的两个标量参与比较，**无需回看** alice 的全部视频。遍历结束 $\text{maxPop} = 10$，alice、bob 并列，答案 $[["alice","one"], ["bob","two"]]$ ✓。

**示例 3** 演算要点：四条记录的 $v$ 全为 $0$，哨兵 $\text{mx} = -1$ 保证每个创作者的**第一条**视频必然写入（$0 > -1$）；随后的平票比较恰好走向两个方向——a 的 $"z" < "x"$ 为**假**，最热保持 "x"；b 的 $"w" < "y"$ 为**真**，最热更新为 "w"。最终全员流行度为 $0$ 并列，输出 $[["a","x"],["b","w"]]$ ✓——若哨兵误取 $0$，此处会输出空 id（见 §8.2）。

## 4. 算法细节

1. **单表聚合**：`unordered_map<string, Info>` 一张表三个字段（`tot` 流行度、`mx` 组内最大播放量、`id` 最热视频 id），比「两张表分别维护总表与最热表」每步少一次哈希查找，赛场写法越紧凑越不易错。
2. **哨兵 $\text{mx} = -1$**：$views[i] \ge 0$，哨兵必须**严格小于一切合法播放量**。C++ 用默认成员初始化 `int mx = -1`；Python 用 `setdefault(c, [0, -1, ""])`，保证创作者的第一条视频无条件写入。
3. **64 位流行度**：$n \le 10^5$、$views[i] \le 10^5$，单创作者流行度上界 $10^5 \times 10^5 = 10^{10}$，超过 32 位 `int`（约 $2.1 \times 10^9$）；`tot` 与 `maxPop` 都必须开 `long long`。`mx` 是单个视频的播放量，`int` 即可。
4. **双关键字更新条件**：`v > mx || (v == mx && id < mi)`——播放量**严格更大**直接覆盖（无需看 id）；**相等**时才比字典序。两个分支缺一不可（§8.3）。
5. **`maxPop` 循环内顺手维护**：每次 `tot` 更新后立即比较刷新，末尾收集只做一次「等于」过滤，省掉一次独立的 $O(m)$ 求 $\max$ 扫描。
6. **字符串比较 $O(1)$**：`id` 长度 $\le 5$ 且全小写，直接用语言内置字符串比较；输出顺序题面允许任意，无需对答案排序。

## 5. 正确性证明

**引理 1**（双关键字构成全序）：在固定创作者的视频上定义「更优」关系 $\prec$：$(v_1, \text{id}_1) \prec (v_2, \text{id}_2)$ 当且仅当 $v_1 > v_2$，或 $v_1 = v_2$ 且 $\text{id}_1$ 的字典序小于 $\text{id}_2$。则 $\prec$ 在互不相等的 $(v, \text{id})$ 对之间是严格全序（完全、传递、反对称）。

**证明**：$\prec$ 是「播放量降序」与「id 字典序升序」的**字典序复合**。整数上的 $>$ 与字符串上的 $<$ 都是全序，而两个全序的字典序复合仍是全序（先比第一关键字，平局比第二关键字；完全性与传递性逐情形验证即得）。若两条记录的 $(v, \text{id})$ 完全相同，则二者在 $\prec$ 下并列，且任取其一输出的 id 字符串相同。∎

**引理 2**（增量收敛、与顺序无关）：对任一创作者 $c$，设其视频按**任意**顺序到达。算法维护的 $(\text{mx}, \text{id})$ 在处理完任意前缀后，都等于该前缀中按 $\prec$ 的最优视频；特别地，处理完全部视频后结果与到达顺序无关。

**证明**：对已处理视频数归纳。**基础**：初始哨兵 $(\text{mx}, \text{id}) = (-1, \cdot)$，因一切合法 $v \ge 0 > -1$，哨兵劣于任何真实视频，首个视频必然触发写入。**归纳步**：设处理前记录为已见集合 $S$ 的 $\prec$-最优元；新来 $(v, \text{id})$ 时，若 $(v, \text{id}) \prec$ 当前记录则替换，否则保留——由 $\prec$ 的全序性，$S \cup \{(v, \text{id})\}$ 的最优元要么仍是原记录、要么恰是新元素，两种情况算法都正确维护。由引理 1，最优 $(v, \text{id})$ 对唯一（或并列且 id 相同），故最终结果与顺序无关。∎

**引理 3**（流行度与最大值正确）：遍历结束后 $\text{tot}[c] = \sum_{i:\ \text{creators}[i] = c} \text{views}[i]$，且 $\text{maxPop} = \max_{c} \text{tot}[c]$。

**证明**：`tot[c] += v` 是纯累加，加法可交换可结合，与处理顺序无关，归纳即得第一式。`maxPop` 每步与**刚更新后**的 `tot[c]` 比较取大，归纳知其始终等于已出现的所有 `tot` 值之最大，遍历结束即全局最大。∎

**定理**：算法输出恰为 $\{\, [c, \text{id}_c] : \text{tot}(c) = \text{maxPop} \,\}$，其中 $\text{id}_c$ 是创作者 $c$ 播放量最大（平票取字典序最小）的视频 id——即题目所求的完整答案。

**证明**：由引理 3，收集条件 `tot == maxPop` 恰好选出**全部**流行度并列最高的创作者（等于者全收、小于者全弃），无遗漏亦无多余；由引理 2，每个入选创作者带出的 $\text{id}_c$ 是其组内双关键字最优视频的 id。二者合并即题意所求。∎

## 6. 复杂度分析

- **时间复杂度**：期望 $O(n)$。一趟遍历，每步均摊 $O(1)$ 哈希操作 + $O(1)$ 字符串比较（长度 $\le 5$）+ $O(1)$ 算术；末尾收集 $O(m) \le O(n)$。对照：按创作者排序再分组为 $O(n \log n)$，能过但多余。
- **空间复杂度**：$O(m)$，$m$ 为不同创作者数（最坏 $m = n$），存储聚合表与答案。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<string>> mostPopularCreator(vector<string>& creators,
                                              vector<string>& ids,
                                              vector<int>& views) {
        struct Info { long long tot = 0; int mx = -1; string id; };
        unordered_map<string, Info> mp;   // creator -> {流行度, 最热播放量, 最热 id}
        long long maxPop = 0;

        for (int i = 0; i < (int)creators.size(); ++i) {
            Info& t = mp[creators[i]];              // 默认构造: tot=0, mx=-1, id=""
            t.tot += views[i];
            maxPop = max(maxPop, t.tot);
            if (views[i] > t.mx || (views[i] == t.mx && ids[i] < t.id)) {
                t.mx = views[i];
                t.id = ids[i];
            }
        }

        vector<vector<string>> ans;
        for (auto& [c, t] : mp)
            if (t.tot == maxPop) ans.push_back({c, t.id});
        return ans;
    }
};
```

> 💡 `mp[creators[i]]` 默认构造的哨兵 `mx = -1` 保证首条视频必写入（覆盖 $v = 0$）；`tot`/`maxPop` 用 `long long` 防 $10^{10}$ 溢出；`mx` 保持 `int`。

### Python

```python
class Solution:
    def mostPopularCreator(self, creators: List[str], ids: List[str], views: List[int]) -> List[List[str]]:
        info = {}   # creator -> [流行度, 最热播放量, 最热 id]
        max_pop = 0
        for c, vid, v in zip(creators, ids, views):
            rec = info.setdefault(c, [0, -1, ""])   # 哨兵 mx = -1
            rec[0] += v
            if rec[0] > max_pop:
                max_pop = rec[0]
            if v > rec[1] or (v == rec[1] and vid < rec[2]):
                rec[1], rec[2] = v, vid
        return [[c, rec[2]] for c, rec in info.items() if rec[0] == max_pop]
```

> 💡 Python 整数无界，无溢出顾虑；哨兵同样取 $-1$；末尾列表推导一次完成「等于过滤 + 取最热 id」。

## 8. 边界情况与易错点

1. **32 位溢出（本场最大 WA 点）**：单创作者流行度可达 $10^5 \times 10^5 = 10^{10}$，`tot` 与 `maxPop` 必须 `long long`。示例里播放量都是个位数，溢出**不报错只 WA**，肉眼极难发现——C++ 选手提交前先做值域核算。
2. **哨兵误取 $0$**：$views[i]$ 可为 $0$。若 `mx` 哨兵取 $0$ 且更新条件是严格大于，则全零视频的创作者最热 id 永远是空串，输出 `["a", ""]` 直接 WA。哨兵取 $-1$（或以「键不存在」判定首条），自构造示例 3 覆盖此分支。
3. **平票判定写一半**：只写 `v > mx`（平票时保留先到者，违反字典序要求）或只比字典序（$v$ 更小但 id 更小时误更新）都错，两个分支缺一不可。示例 1 的第 $i=2$ 步与示例 2 的 "b"/"c" 各拦一个方向。
4. **全零并列**：所有 `views = 0` 时 `maxPop = 0`，**所有**创作者并列最高，答案含全部 $m$ 项——这是正确行为不是 bug，输出本身 $O(n)$。
5. **`maxPop` 初值 $0$ 安全**：因 $\text{tot} \ge 0$ 恒成立，「等于过滤」在全员为零时仍收全；若推广到流行度可为负的变体，才需要用首个值初始化。
6. **单视频 / 单创作者**：$n = 1$ 时 $\text{maxPop} = \text{views}[0]$，答案 $[\text{creator}, \text{id}]$，同一套逻辑自然覆盖。
7. **完全重复的 $(v, \text{id})$ 记录**：$\prec$ 意义下并列且输出相同，算法天然正确，无需去重。
