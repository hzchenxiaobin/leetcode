# LeetCode 具有给定数值的最小字符串 题解

## 1. 题目概述

- **标题 / 题号**：具有给定数值的最小字符串（#1663，medium）
- **链接**：https://leetcode.cn/problems/smallest-string-with-a-given-numeric-value/
- **来源**：LeetCode 第 216 场周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串

**题意**：小写字母的**数值**是它在字母表中的位置（a=1, b=2, …, z=26），字符串的数值是各字符数值之和。给定整数 `n` 与 `k`，返回**长度恰好为 n、数值恰好为 k** 的**字典序最小**字符串。

**约束**：

- `1 <= n <= 10^5`
- `n <= k <= 26 * n`

> 💡 约束本身就保证有解：下界 `n` 对应全 a，上界 `26n` 对应全 z，本题不需要判无解。

## 2. 示例

**示例 1**

```text
输入：n = 3, k = 27
输出："aay"
解释：1 + 1 + 25 = 27。首两位必须尽可能小：任何第二位 > 'a' 的串都比 "aay" 大，
     而前缀为 "aa" 时第三位必须恰好凑出 25 点，即 'y'。
```

**示例 2**

```text
输入：n = 5, k = 73
输出："aaszz"
解释：1 + 1 + 19 + 26 + 26 = 73。
```

**示例 3**

```text
输入：n = 1, k = 26
输出："z"
解释：只有 1 个字符，26 点数值只能由 'z' 承担。
```

## 3. 解题思路

### 3.1 暴力思路：枚举与 DP 都不可行

- **无脑枚举**：长度为 n 的小写串共 $26^n$ 个，$n \le 10^5$ 下是天文数字。
- **可行性 DP**：设 `dp[i][j]` =「用 i 个字符能否凑出数值 j」，状态数 $O(n \cdot 26n)$（$k \le 26n \approx 2.6 \times 10^6$），转移还要乘 26，彻底爆炸。
- 两者共同的浪费：把「可行性」当成黑盒反复询问。而本题的可行性有 $O(1)$ 判定式，顺着它一步步走，就是贪心。

### 3.2 核心观察：可行性有公式，答案有固定形态

**观察 1（可行性判定）**：m 个字符能凑出数值 k，当且仅当

$$m \le k \le 26m$$

下界对应全 a、上界对应全 z；夹在中间的任何 k 都能凑出来（把超额 $k - m$ 逐位撒到字符上，每位至多 +25）。

**观察 2（字典序 = 前面尽量小 = 数值往后挤）**：字典序由**最左边的不同位**决定，所以要让答案小，应当**前缀尽量放 a**。但前面每放一个 a（只花 1 点），多出的数值就必须由后面的位置扛起来——后面的字符上限是 26，所以**后缀要尽量放 z**。

两个方向夹逼，答案必然长成：

$$\underbrace{a\cdots a}_{j\ \text{个}}\;\;x\;\;\underbrace{z\cdots z}_{q\ \text{个}}$$

—— **一串 a、至多一个"过渡字符" x、一串 z**。

![核心观察：数值往后挤，前缀全是 a](images/1663_value_distribution_concept.svg)

> 💡 **一句话总结**：字典序最小 ⟺ 前导 a 尽量多 ⟺ 后缀 z 尽量多；两侧贪心只在中点碰头一次，只留下至多一个过渡字符。

### 3.3 算法流程：从右往左，能扛就扛

从最右位开始**从右往左**填，每一步在位置 i（0 编号，左边还有 i 个空位）填**当前能扛的最大值**：

$$c = \min(26,\; k - i)$$

- `k - i`：左边 i 位每位的下限是 1，共需保底 i 点，所以本位至多分到 `k - i`；
- 再被单字符上限 26 截断；
- 填完后 `k -= c`，继续左移一位。

不变量 `k >= i+1`（见 §4）保证 `c >= 1` 永不越界，循环天然覆盖"a 块 → 过渡 → z 块"三个阶段。

![算法流程：从右往左贪心填最大可行字符](images/1663_fill_from_right_flow.svg)

对称写法是**从左往右**，每位取"不压垮后缀的最小值"：$c = \max(1,\ k - 26 \times (\text{剩余位数} - 1))$。两种写法输出同一个串（见 §4、§5 推论）。

### 3.4 示例演算

以 `n = 5, k = 73` 为例：

| 步 | 位置 i | 剩余 k | k − i | c = min(26, k−i) | 填入 | 当前串（_ 为未填） |
|----|--------|--------|-------|------------------|------|--------------------|
| 1 | 4 | 73 | 69 | **26** | z | `____z` |
| 2 | 3 | 47 | 44 | **26** | z | `___zz` |
| 3 | 2 | 21 | 19 | **19** | s | `__szz` |
| 4 | 1 | 2 | 1 | 1 | a | `_aszz` |
| 5 | 0 | 1 | 1 | 1 | a | `aaszz` |

第 3 步是**过渡字符**：右边两个 z 已扛满 52 点，再放 z 前面就凑不齐；左边每位的预算只剩 1 点，剩余的 19 点恰好由位置 2 的一个字符接住。验证：$1+1+19+26+26 = 73$ ✓。

![示例演算：n=5, k=73 的填表过程](images/1663_example_walkthrough.svg)

## 4. 算法细节

1. **公式推导（从右往左）**：处理位置 i 时，左边还有 i 个空位，各至少需要 1 点，故本位至多 `k - i`；单字符上限 26。取**最大值**是为了给左边留下最小的预算——右端每多扛 1 点，前缀就多 1 点"省"的空间。
2. **循环不变量**：进入位置 i 时恒有 $i+1 \le k \le 26(i+1)$。放 $c = \min(26,\ k-i)$ 后剩余 $k' = k - c$：
   - 若 $c = k-i$（前缀保底优先），则 $k' = i$，恰好够左边每位 1 点；
   - 若 $c = 26$（扛满优先），则 $k' = k - 26 \le 26(i+1) - 26 = 26i$。
   两种情况都维持 $i \le k' \le 26i$，故 `c` 永远落在 `[1, 26]`，无需任何特判。
3. **对称写法（从左往右）**：位置 i（右边还有 rest 位）取 $c = \max(1,\ k - 26 \cdot \text{rest})$——后缀至多扛 $26 \cdot \text{rest}$，扛不动的部分必须由本位先付。
4. **O(1) 闭式构造**：记超额 $d = k - n$（在"全 a 保底"基础上还需撒掉的数值）。每个 z 比保底多扛 25，过渡字符多扛 $x - 1$，于是
   - $q = \lfloor d/25 \rfloor$ 个 z，$x = d \bmod 25 + 1$（第 x 个字母），前导 a 共 $n - q - 1$ 个；
   - 特判 $k = 26n$（即 $d = 25n$）时答案就是全 z；
   - 这是 §3.2 形态观察的定量化，可直接三段拼串输出。
5. **实现小技巧**：C++ 可先把串预填为全 'a' 再从右往左覆盖（所有位置都会被覆盖，预填只是省去左段赋值）；Python 用列表 + `join`，避免循环内字符串拼接的 $O(n^2)$ 开销。

## 5. 正确性证明

**引理 1（可行性判定）**：存在长度为 m、数值为 k 的字符串 $\iff$ $m \le k \le 26m$。

**证明**：（必要性）每个字符的数值落在 $[1,26]$，m 个字符之和落在 $[m, 26m]$。（充分性）取全 a（数值 m），把超额 $d = k - m$ 从左到右逐位分配、每位至多加 25；由 $0 \le d \le 25m$，贪心分配必能在 m 位内分完。∎

**引理 2（前导 a 的上限）**：任何可行串的前导连续 'a' 至多 $j^* = n - \lceil d/25 \rceil$ 个，其中 $d = k - n$。

**证明**：设某可行串前 j 位全为 'a'，则后 $n - j$ 位需凑出 $k - j$，由引理 1 需 $k - j \le 26(n-j)$，即 $25j \ge 25n - d$，即 $j \le n - d/25$。j 为整数，而 $\lfloor n - d/25 \rfloor = n - \lceil d/25 \rceil$，故 $j \le n - \lceil d/25 \rceil$。∎

**定理（从右往左贪心的正确性）**：从右往左、每位取 $c = \min(26,\ k-i)$ 的贪心输出的串 S 是字典序最小的可行串。

**证明**：记 $d = k - n$，$q = \lfloor d/25 \rfloor$，$r = d \bmod 25$。

（i）**贪心输出的形态**：设已放 $q'$ 个 z（剩余预算 $k' = k - 26q'$，当前位置 $i = n - q' - 1$），则本步放 z 当且仅当

$$k' - i = d - 25q' + 1 \ge 26 \iff d \ge 25(q'+1).$$

由 $q = \lfloor d/25 \rfloor$，该条件对 $q' \le q-1$ 成立、对 $q' \ge q$ 不成立，故恰好放 q 个 z（$q = n$ 即 $k = 26n$ 时串就是 $z^n$，结论仍成立）。随后在位置 $n-q-1$：$k' - i = r + 1 \in [1, 25]$，放过渡字符 $x = r+1$，放完后剩余预算**恰好等于** $n-q-1$；此后每个位置满足 $k - i = 1$，全放 'a'。于是

$$S = a^{\,n-q-1}\, x\, z^{\,q}.$$

（ii）**S 的前导 a 数恰为上限 $j^*$**：$r > 0$ 时 $\lceil d/25 \rceil = q+1$，S 的前导 a 数 $= n-q-1 = j^*$；$r = 0$ 时 $x = $ 'a' 并入前导块，前导 a 数 $= n-q = n - \lceil d/25 \rceil = j^*$。

（iii）**任何可行串 $T$ 都有 $T \ge S$**（字典序）：

- 若 T 的前导 a 数 $< j^*$：设 T 的首个非 'a' 位置为 p，则 $p < j^*$，且 T 的前 p 位与 S 相同（全是 'a'），而 $T[p] >$ 'a' $= S[p]$，故 $T > S$；
- 若 T 的前导 a 数 $= j^*$（更多由引理 2 不可能）：
  - $r = 0$ 时：位置 $j^*$ 起还剩 $n - j^* = q$ 位，需凑 $k - j^* = 26q$，每字符上限 26，故每位恰为 'z'，$T = S$；
  - $r > 0$ 时：设 $T[j^*] = c$（$c \ge 2$），后续 q 位可行要求（引理 1）$q \le k - j^* - c \le 26q$，故 $c \ge k - j^* - 26q = (n+d) - (n-q-1) - 26q = r + 1 = x$。若 $c > x$，则 T 与 S 前 $j^*$ 位相同、位置 $j^*$ 处 T 更大，故 $T > S$；若 $c = x$，则后续 q 位需凑 $k - j^* - x = 26q$，每位恰为 'z'，$T = S$。

综上，一切可行串 $T \ge S$，S 为字典序最小的可行串。∎

**推论（从左往右贪心的正确性）**：从左往右、每位取 $c = \max(1,\ k - 26(m-1))$（m 为当前剩余位数）的贪心输出同一个串 S。

**证明**：对 m 归纳。m = 1 时唯一可行字符就是 $c = k$，成立。设对 m−1 成立。由引理 1，当前位可行的最小值为 $c_{\min} = \max(1,\ k - 26(m-1))$（后缀至多扛 $26(m-1)$，扛不动的本位先付；且取 $c_{\min}$ 后剩余预算仍在 $[m-1,\ 26(m-1)]$ 内，可行）。任何首位 $> c_{\min}$ 的可行串，字典序都大于所有以 $c_{\min}$ 开头的可行串（首位即分胜负）；而首位取定后，后缀可行性与首位无关，其最优解由归纳假设给出。故该贪心输出长度 m 的字典序最小串——由唯一性即 S。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。从右往左（或从左往右）单遍扫描，每个位置 $O(1)$ 算出 `c`；闭式构造只需 $O(1)$ 计算 + $O(n)$ 拼串。
- **空间复杂度**：$O(1)$ 额外空间（答案串本身 $O(n)$ 属于输出，不计）。

## 7. 参考代码

### C++（从右往左贪心）

```cpp
class Solution {
public:
    string getSmallestString(int n, int k) {
        string s(n, 'a');                    // 预填占位，循环会覆盖每一位
        for (int i = n - 1; i >= 0; --i) {
            int c = min(26, k - i);          // 左边 i 位各留 1 点后，本位能扛的最大值
            s[i] = 'a' + c - 1;
            k -= c;
        }
        return s;
    }
};
```

### C++（从左往右贪心）

```cpp
class Solution {
public:
    string getSmallestString(int n, int k) {
        string s;
        for (int i = 0; i < n; ++i) {
            int rest = n - i - 1;            // 当前位之后还剩多少位
            int c = max(1, k - 26 * rest);   // 后缀扛不动的部分，由本位先付
            s.push_back('a' + c - 1);
            k -= c;
        }
        return s;
    }
};
```

### Python（从右往左贪心）

```python
class Solution:
    def getSmallestString(self, n: int, k: int) -> str:
        s = [''] * n
        for i in range(n - 1, -1, -1):
            c = min(26, k - i)
            s[i] = chr(ord('a') + c - 1)
            k -= c
        return ''.join(s)
```

### Python（O(1) 闭式构造）

```python
class Solution:
    def getSmallestString(self, n: int, k: int) -> str:
        q, r = divmod(k - n, 25)            # q 个 z；剩余超额 r 由过渡字符承担
        if q == n:                           # k = 26n，全是 z
            return 'z' * n
        return 'a' * (n - q - 1) + chr(ord('a') + r) + 'z' * q
```

## 8. 边界情况与易错点

1. **min/max 方向别写反**：从右往左是 $\min(26,\ k-i)$（"能扛就扛"，单字符扛不了更多）；从左往右是 $\max(1,\ k - 26 \cdot \text{rest})$（"能省就省"，后缀背不动的自己先付）。两式分属同一枚硬币的两面。
2. **off-by-one**：第 c 个字母是 `'a' + c - 1`（'a' 对应 c=1），写成 `'a' + c` 会整体右移一位。
3. **`k - i` 永不为 0 或负**：由不变量 $k \ge i+1$ 保证；若手推时发现想放 0，说明某一步没有取满 $\min$。
4. **全 z 边界**：$k = 26n$ 时闭式解的前导 a 块长度会算成 $-1$，必须特判 `q == n`；循环写法天然覆盖（每步都是 $\min(26, 26 \cdot \text{剩余位})$）。
5. **全 a 边界**：$k = n$ 时 $d = 0$、$q = 0$、过渡字符即 'a'，退化为纯 a 块，闭式解无需特判。
6. **溢出**：$k \le 26 \times 10^5 = 2.6 \times 10^6$，`26 * rest` 同量级，`int` 完全够用。
7. **Python 拼串**：循环内 `s += ch` 均摊尚可，但用列表 + `''.join`（或闭式解三段拼接）更稳。
