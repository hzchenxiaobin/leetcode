# LeetCode 完成所有任务的最少初始能量 题解

## 1. 题目概述

- **标题 / 题号**：完成所有任务的最少初始能量（#1665，hard）
- **链接**：https://leetcode.cn/problems/minimum-initial-energy-to-finish-tasks/
- **来源**：LeetCode 第 216 场周赛 Q4
- **难度**：困难
- **标签**：贪心、排序、数组

**题意**：给定任务数组 $tasks$，其中 $tasks[i] = [actual_i, minimum_i]$：完成第 $i$ 个任务要**实际消耗** $actual_i$ 点能量，而**开始这个任务之前**当前能量必须**不低于** $minimum_i$（开始后只扣 $actual_i$，门槛本身不扣钱）。任务可以按**任意顺序**完成，求能完成全部任务的最少初始能量。

**约束**：

- $1 \le tasks.length \le 10^5$
- $1 \le actual_i \le minimum_i \le 10^4$

## 2. 示例

**示例 1**

```text
输入：tasks = [[1,2],[2,4],[4,8]]
输出：8
解释：按 [4,8] → [2,4] → [1,2] 的顺序执行：
  初始 8 ≥ 8，开工 [4,8]，剩 4；
  4 ≥ 4，开工 [2,4]，剩 2；
  2 ≥ 2，开工 [1,2]，剩 1。
若初始只有 7：先做 [4,8] 剩 3 < 4，无法开工 [2,4]；先做 [2,4] 剩 5 < 8，
无法开工 [4,8]。7 不够。
```

**示例 2**

```text
输入：tasks = [[1,3],[2,4],[10,11],[10,12],[8,9]]
输出：32
```

**示例 3**

```text
输入：tasks = [[1,7],[2,8],[3,9],[4,10],[5,11],[6,12]]
输出：27
解释：六个任务的 m − a 都等于 6，任何顺序需求相同：
E = max(0+7, 1+8, 3+9, 6+10, 10+11, 15+12) = 27。
```

## 3. 解题思路

### 3.1 暴力思路：枚举执行顺序

最朴素的做法是枚举 $n$ 个任务的全排列，对每个排列模拟一遍求出所需初始能量，取最小值，时间 $O(n \cdot n!)$，$n = 10^5$ 下完全不可行。

> 💡 顺序正是本题唯一的自由度：每个任务"扣多少"是定死的，"什么时候扣"由我们决定。尝试二分答案 $E$ 也绕不开它——判定"$E$ 够不够"仍需在所有顺序里找一个可行序。所以必须直接回答：**什么顺序最优？**

### 3.2 核心观察：能量只降不升，"押金差"大的先做

![核心观察：能量只降不升，初始能量由最紧的门槛决定](images/1665_concept.svg)

把初始能量看作**水位**：每执行一个任务水位下降 $a_i$，而每个任务的门槛 $m_i$ 是横在执行序列上的一道**闸门**，开工瞬间水位必须不低于闸门高度。

- **固定顺序的需求公式**：若某顺序中前 $k-1$ 个任务已耗 $S_{k-1}$，则开工第 $k$ 个任务要求 $E \ge S_{k-1} + m_k$。整个顺序的需求就是

$$E(\pi) = \max_{1 \le k \le n} \left( S_{k-1}(\pi) + m_{\pi_k} \right)$$

- **押金差** $d_i = m_i - a_i$：门槛里**超出实际消耗**的部分，相当于开工要交的"押金"。水位只降不升（$a_i \ge 1$），押金差大的任务对"高水位"依赖最强——**必须趁早做**；押金差小（接近 0）的任务几乎只"付账"不"要押金"，放在低水位时也无所谓。

直觉的反例验证：

![交换论证：押金差大的先做，所需初始能量更低](images/1665_exchange.svg)

任务 $A = [1, 100]$（押金差 99）与 $B = [99, 100]$（押金差 1）：先 $B$ 后 $A$ 需要 $199$，先 $A$ 后 $B$ 只需要 $101$——**同样两个任务，顺序不同需求天差地别**。一般地，对相邻两任务 $i \to j$（$i$ 之前已耗 $S$）：

$$\text{先 } i \text{ 后 } j：\ S + \max(m_i,\ m_j + a_i) \qquad \text{先 } j \text{ 后 } i：\ S + \max(m_j,\ m_i + a_j)$$

当 $d_i \ge d_j$ 时前者 $\le$ 后者（证明见 §5 引理 2），即**把押金差大的放前面永不吃亏**。

### 3.3 算法流程：按 d 降序排序 + 一遍扫描

![算法流程：排序后一遍扫描，随时把水位补到门槛](images/1665_algorithm_flow.svg)

1. 将所有任务按 $d = m - a$ **从大到小**排序；
2. 维护两个量：`cur`（当前水位，初始 0）与 `ans`（累计补水量，初始 0）；
3. 依次处理每个任务 $[a, m]$：若 `cur < m`，补水 $m - cur$（计入 `ans`）并把 `cur` 抬到 $m$；然后 `cur -= a`；
4. 全部处理完，`ans` 即最少初始能量。

### 3.4 示例演算

以示例 2 `tasks = [[1,3],[2,4],[10,11],[10,12],[8,9]]` 为例。按 $d = m - a$ 降序（稳定排序）得 $[1,3], [2,4], [10,12], [10,11], [8,9]$：

![示例演算：逐任务补水位与扣款过程](images/1665_example_walkthrough.svg)

| 步骤 | 任务 $[a, m]$ | $d = m - a$ | 执行前 `cur` | 补水 $m - cur$ | `ans` 累计 | 执行后 `cur` |
|---|---|---|---|---|---|---|
| 1 | $[1, 3]$ | 2 | 0 | 3 | 3 | 2 |
| 2 | $[2, 4]$ | 2 | 2 | 2 | 5 | 2 |
| 3 | $[10, 12]$ | 2 | 2 | 10 | 15 | 2 |
| 4 | $[10, 11]$ | 1 | 2 | 9 | 24 | 1 |
| 5 | $[8, 9]$ | 1 | 1 | 8 | **32** | 1 |

返回 **32**。用公式交叉验证：$\max(0+3,\ 1+4,\ 3+12,\ 13+11,\ 23+9) = \max(3, 5, 15, 24, 32) = 32$ ✓

## 4. 算法细节

1. **排序键**：$m - a$ 降序。C++ 写比较器 `x[1] - x[0] > y[1] - y[0]`；Python 写 `key=lambda t: t[1] - t[0], reverse=True`。由 §5 推论，键值相同的任务**顺序无关**，不必加二级排序键。
2. **增量法与公式法等价**：循环不变量为 $ans_k = \max_{i \le k}(S_{i-1} + m_i)$ 且 $cur_k = ans_k - S_k$（证明见 §5 引理 3）。也可以直接一遍扫公式：遍历到任务 $k$ 时先 `ans = max(ans, S + m_k)`、再 `S += a_k`，两种写法结果一致。
3. **`cur` 永不为负**：每轮先保证 $cur \ge m \ge a$ 再扣 $a$，归纳可知全程 $cur \ge 0$，无需与 0 取 max。
4. **单一维度排序都是错的**：只按 $m$ 排——$[1,100]$ 与 $[99,100]$ 门槛相同，但先做后者要多花 98；只按 $a$ 排——$[3,100]$（$d=97$）与 $[2,51]$（$d=49$），按 $a$ 升序先做 $[2,51]$ 需求 102，先做 $[3,100]$ 只需 100。必须用**差值** $m - a$。
5. **"能开工就能完工"**：题目保证 $m \ge a$，开工瞬间能量 $\ge m \ge a$，扣完不透支，因此需求公式只需覆盖"开工门槛"约束，无需再管过程非负。

## 5. 正确性证明

**引理 1（固定顺序的需求公式）**：对固定执行顺序 $\pi = (\pi_1, \dots, \pi_n)$，初始能量 $E$ 能按此顺序完成全部任务，当且仅当

$$E \ge \max_{1 \le k \le n} \left( S_{k-1}(\pi) + m_{\pi_k} \right), \qquad S_{k-1}(\pi) = \sum_{j < k} a_{\pi_j}$$

**证明**：开工第 $k$ 个任务前的能量为 $E - S_{k-1}(\pi)$（之前的任务各实扣 $a$，门槛不扣钱），可开工当且仅当 $E - S_{k-1}(\pi) \ge m_{\pi_k}$，即 $E \ge S_{k-1}(\pi) + m_{\pi_k}$。全部可开工 $\iff$ $E$ 不小于这 $n$ 个数的最大值。又 $m_{\pi_n} \ge a_{\pi_n}$，故该最大值 $\ge S_{n-1} + m_{\pi_n} \ge \sum_i a_i$，即"全部可开工"自动蕴含过程能量非负、全部可完成。∎

**引理 2（相邻交换）**：设顺序中相邻两任务依次为 $x \to y$，$x$ 之前的消耗和为 $S$。两种局部顺序的需求分别为

$$R(x \to y) = S + \max(m_x,\ m_y + a_x), \qquad R(y \to x) = S + \max(m_y,\ m_x + a_y)$$

若 $d_x \ge d_y$，则 $R(x \to y) \le R(y \to x)$。

**证明**：由 $d_x \ge d_y$ 得 $m_x + a_y \ge m_y + a_x$。又 $a_x, a_y \ge 1$，故 $m_x < m_x + a_y$ 且 $m_y + a_x \le m_x + a_y$，于是左边 $\max$ 的两个分量均不超过 $m_x + a_y$，从而

$$\max(m_x,\ m_y + a_x) \le m_x + a_y \le \max(m_y,\ m_x + a_y)$$

（后一个不等号源于 $m_x + a_y$ 本身是右边 $\max$ 的参数之一。）而交换相邻两项**不影响其余位置的约束**：$x$ 之前各位置的前缀和不变；$y$ 之后各位置的前缀和都含 $a_x + a_y$，亦不变。故整条顺序的需求由这两位上的局部需求决定，$d_x \ge d_y$ 时 $x \to y$ 不劣于 $y \to x$。∎

**推论（并列无关）**：$d_x = d_y$ 时记 $T = m_x + a_y = m_y + a_x$。由 $a_x, a_y \ge 1$ 知 $m_x, m_y < T$，故两个 $\max$ 都等于 $T$，两种顺序需求相等。因此 $d$ 相同的任务相对顺序无关紧要。

**引理 3（循环不变量）**：增量法处理完前 $k$ 个任务后，$ans = \max_{i \le k}(S_{i-1} + m_i)$ 且 $cur = ans - S_k$。

**证明**：对 $k$ 归纳。$k = 0$ 时 $ans = cur = 0$，成立。设第 $k$ 轮开始前命题成立：

- 若 $cur \ge m_k$：由归纳假设 $ans - S_{k-1} \ge m_k$，即 $ans \ge S_{k-1} + m_k$，最大值不变，`ans` 不更新；扣款后 $cur = ans - S_{k-1} - a_k = ans - S_k$。
- 若 $cur < m_k$：补水后 $ans' = ans + (m_k - cur) = m_k + S_{k-1} \ge$ 原最大值，恰为新最大值；`cur` 抬到 $m_k$ 再扣 $a_k$ 得 $cur' = m_k - a_k$，而 $ans' - S_k = S_{k-1} + m_k - S_{k-1} - a_k = m_k - a_k$，一致。∎

**定理**：按 $d = m - a$ 从大到小排序后依次执行，所得初始能量是全局最少。

**证明**：任取顺序 $\pi$。若其中存在相邻对 $x \to y$ 满足 $d_x < d_y$（"押金差逆序"），由引理 2（交换为 $y \to x$，即大者在前）需求不增。每次这样的交换使序列的逆序数严格减一，有限次交换后得到按 $d$ 降序的顺序 $\pi^\*$，且 $E(\pi^\*) \le E(\pi)$。故降序序的需求不超过任何顺序，为全局最小；由引理 1 与引理 3，算法输出的 `ans` 恰等于该最小值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序占主导；一遍扫描每个任务 $O(1)$，共 $O(n)$。
- **空间复杂度**：$O(1)$ 额外空间（原地排序，仅 `cur` / `ans` 两个变量；不计排序自身的 $O(\log n)$ 递归栈）。

## 7. 参考代码

### C++（排序 + 增量扫描）

```cpp
class Solution {
public:
    int minimumEffort(vector<vector<int>>& tasks) {
        sort(tasks.begin(), tasks.end(), [](const vector<int>& x, const vector<int>& y) {
            return x[1] - x[0] > y[1] - y[0];
        });
        long long cur = 0, ans = 0;
        for (auto& t : tasks) {
            if (cur < t[1]) {
                ans += t[1] - cur;
                cur = t[1];
            }
            cur -= t[0];
        }
        return (int)ans;
    }
};
```

### Python（排序 + 增量扫描）

```python
class Solution:
    def minimumEffort(self, tasks: List[List[int]]) -> int:
        tasks.sort(key=lambda t: t[1] - t[0], reverse=True)
        cur = ans = 0
        for a, m in tasks:
            if cur < m:
                ans += m - cur
                cur = m
            cur -= a
        return ans
```

## 8. 边界情况与易错点

1. **单任务**：答案就是 $m_1$，公式 $\max(0 + m_1)$ 自动给出，无需特判。
2. **全部 $m_i = a_i$**（$d$ 全 0）：任何顺序需求都是 $\sum a_i$，排序退化为无操作，公式自动正确。
3. **排序方向写反**（按 $d$ 升序）是最典型 WA：结果仍可行但偏大，样例 1 会输出 11、样例 2 会输出 33，本地样例即可拦截。
4. **增量法更新顺序**：先补水（`ans += m - cur; cur = m`）再扣款（`cur -= a`）；写反会漏掉"把水位抬到门槛"，从低水位直接扣款。
5. **单一维度排序**：只按 $m$ 或只按 $a$ 排序都有反例（见 §4 第 4 点），必须用差值 $m - a$。
6. **溢出**：$ans \le (n-1) \cdot 10^4 + 10^4 < 10^9$，`int`（上限约 $2.1 \times 10^9$）勉强够用，C++ 建议用 `long long` 稳妥；Python 无此顾虑。
7. **别担心 `cur` 变负**：由 §5 引理 3 的不变量，全程 $cur \ge 0$，无需额外防护。
