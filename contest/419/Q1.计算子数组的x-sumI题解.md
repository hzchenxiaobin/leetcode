# LeetCode 计算子数组的 x-sum I 题解

## 1. 题目概述

- **标题 / 题号**：计算子数组的 x-sum I（#3318，easy）
- **链接**：https://leetcode.cn/problems/find-x-sum-of-all-k-long-subarrays-i/
- **来源**：LeetCode 第 419 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、滑动窗口、排序

**题意**：给定长度为 $n$ 的数组 `nums` 与整数 $k$、$x$。数组的 **x-sum** 按三步计算：① 统计每种元素的出现次数；② 仅保留**出现频率最高的前 $x$ 种**元素——若两种元素频次相同，**数值较大**者被认为「出现次数更多」；③ 求保留元素的总和（保留即计入其**全部出现**）。若不同元素不足 $x$ 种，x-sum 就是数组的元素总和。返回长度为 $n-k+1$ 的数组 `answer`，其中 `answer[i]` 为子数组 `nums[i..i+k-1]` 的 x-sum。

**约束**：

- $1 \le n = \text{nums.length} \le 50$
- $1 \le \text{nums}[i] \le 50$
- $1 \le x \le k \le n$

> 💡 **读题关键**：三个决定成败的细节——① 平局时取**数值大**者（不是小者）；② 保留元素要把它的**每一次出现**都计入求和（值 × 频次）；③ 不足 $x$ 种时取总和。而 $n \le 50$ 的数据范围宣告了本题 intended 解就是**暴力枚举窗口**——签到题的正确姿势是先看范围、再估暴力。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,2,3,4,2,3], k = 6, x = 2
输出：[6,10,12]
解释：
  子数组 [1,1,2,2,3,4]：频次 1×2、2×2 并列最高 → 保留 1、2 → 1+1+2+2 = 6
  子数组 [1,2,2,3,4,2]：频次 2×3 一骑绝尘；1、3、4 频次并列 1，
                        平局取数值大者 → 保留 2、4 → 2+2+2+4 = 10
  子数组 [2,2,3,4,2,3]：频次 2×3、3×2 最高 → 保留 2、3 → 2+2+2+3+3 = 12
```

**示例 2**

```text
输入：nums = [3,8,7,8,7,5], k = 2, x = 2
输出：[11,15,15,15,12]
解释：k == x，每个窗口至多 k = x 种不同元素，必然全部保留，
      x-sum 退化为窗口和。
```

**边界用例（自造）**

```text
输入：nums = [1,1,1], k = 3, x = 2
输出：[3]
解释：窗口内只有 1 种元素 < x = 2 种 → 按总和条款，x-sum = 1+1+1 = 3。
      若代码统一为「取前 min(x, 种数) 个」，此用例自动被覆盖，无需特判。

输入：nums = [1,2], k = 2, x = 1
输出：[2]
解释：1 与 2 频次并列，数值大者 2 入选；保留即只保留 2 的一次出现 → 2。
      注意不是 1+2 = 3！
```

## 3. 解题思路

### 3.1 先看数据范围：签到题的暴力就是正解

不动脑子的做法：枚举全部 $n-k+1 \le 50$ 个窗口，每个窗口重扫 $k \le 50$ 个元素建频次表（哈希表），再把不同元素按频次排序取前 $x$ 种。单窗口开销 $O(k + m \log m)$（$m$ 为窗口内不同元素数 $\le \min(k, 50)$），总时间约 $50 \times (50 + 50 \cdot 6) \approx 1.6 \times 10^4$——**比一次快排的常数还小**。甚至每个窗口写 $O(k^2)$ 双重循环现数频次（$50^3 = 1.25 \times 10^5$）都能过。

> ⚠️ **别被标签骗去过度设计**。本题官方标签挂着「滑动窗口 / 堆」，但那套增量维护是给同场 Q4（#3321，$n \le 10^5$）准备的。Q1 的 $n \le 50$ 下，重扫频次 + 排序既最短、又最难写错——**先把模拟写对，再谈优化**。

### 3.2 核心观察：x-sum = 按 (频次, 值) 双关键字排序取前 min(x, 种数) 个

![x-sum 三步曲：统计频次 → 排序取前 x 种 → 求和](images/xsum_i_definition.svg)

三条观察环环相扣：

**观察一：x-sum 只由频次表决定。** 三步定义的输入只有「值 → 出现次数」映射，与元素在窗口内的排列次序无关——统计完频次，窗口就可以丢掉了。

**观察二：题面的比较规则是一个严格全序，直接翻译成排序键。** 「频次高者优先；频次相同数值大者优先」即字典序 $(\text{频次降序}, \text{值降序})$，排序键一行写出：`(-频次, -值)`。任何两种不同元素要么频次不同、要么频次相同而值不同，全序无歧义，「前 $x$ 种」唯一确定。

**观察三：「不足 $x$ 种取总和」不需要特判。** 设窗口有 $m$ 种不同元素，取排序后的前 $\min(x, m)$ 个：$m \ge x$ 时恰好取 $x$ 种；$m < x$ 时取全部 $m$ 种，值 × 频次之和恰为窗口总和——两条条款被同一行代码覆盖。**这也是最容易被忽略的简化点**：很多人读完题先写 `if m < x: return 总和` 的分支，其实排序截断天然等价。

![平局规则：频次相同 → 数值大者优先](images/xsum_i_tiebreak_rule.svg)

平局规则是最容易 WA 的点：示例 1 的 `answer[1] = 10` 中，频次并列 1 的候选 $\{1, 3, 4\}$ 只有数值最大的 4 入选；若排序键漏了第二关键字、或方向写反（误取数值小者），会算出 $2+2+2+1 = 7$。

### 3.3 算法流程

![算法流程：枚举窗口 → 建频次表 → 双关键字排序 → 取前 min(x, 种数) → 累加值×频次](images/xsum_i_algorithm_flow.svg)

外层枚举左端点 $i \in [0, n-k]$，内层四步：建频次表 → 取出 (值, 频次) 对 → 按 $(-\text{频次}, -\text{值})$ 排序 → 取前 $\min(x, m)$ 个累加「值 × 频次」。

### 3.4 示例演算

![示例 1 完整演算：三个窗口各自的频次表、top-2 与 x-sum](images/xsum_i_windows_walkthrough.svg)

以示例 1 完整走一遍三个窗口：窗 0 频次 $\{1{\times}2, 2{\times}2, 3{\times}1, 4{\times}1\}$，top-2 为 1、2，和为 6；窗 1 的 4 靠平局规则挤掉 1 和 3，和为 10；窗 2 频次 $\{2{\times}3, 3{\times}2, 4{\times}1\}$，top-2 为 2、3，和为 12——与题面输出 $[6, 10, 12]$ 逐项一致。

## 4. 算法细节

1. **频次表**：Python 用 `collections.Counter`（切片 `nums[i:i+k]` 一步建表）；C++ 用 `unordered_map<int,int>`。因 $1 \le \text{nums}[i] \le 50$，也可开长度 51 的数组做桶，省去哈希开销。
2. **排序键**：`(-频次, -值)`——两个关键字都取负实现降序。C++ 用自定义比较器 `if (a.second != b.second) return a.second > b.second; return a.first > b.first;`。
3. **取前 x**：`[:x]` / 循环条件 `t < x && t < items.size()` 自然截断，覆盖「不足 $x$ 种」条款（观察三），无需 if 分支。
4. **求和口径**：累加 `值 × 频次`——保留的是该元素的**全部出现**，不是每种计一次。示例 1 窗 0 中保留 1（频次 2）贡献 $1 \times 2 = 2$。
5. **窗口滑动**：本题每个窗口独立重扫即可；若要省掉重扫，可维护增量频次表（右移一格 = 一个元素进、一个元素出，$O(1)$ 更新）——这是同场 Q4 的入场券，Q1 无此必要。

## 5. 正确性证明

**引理 1**：子数组 $W$ 的 x-sum 仅由其频次表 $f_W: v \mapsto c_v$ 决定，与元素排列次序无关。

**证明**：x-sum 的三步中，第一步产出频次表；第二步的元素间比较只引用 $c_u, c_v, u, v$；第三步求和只对被保留元素的 $c_v \cdot v$ 求和。三步均不读取位置信息。∎

**引理 2**：设窗口有 $m$ 种不同元素。将 (值, 频次) 对按 (频次降序, 值降序) 的字典序排列，取前 $\min(x, m)$ 项，所得保留集合与题面「出现频率最高的前 $x$ 种元素（频次相同时数值较大者优先）」一致。

**证明**：题面对「元素 $u$ 比 $v$ 出现次数更多」的定义为：$c_u > c_v$，或 $c_u = c_v \wedge u > v$。该关系在 $m$ 种元素上严格、反对称且传递（任意两种不同元素频次不同则比频次，相同则值必不同），构成严格全序。「频次最高的前 $x$ 种」即此全序下的前 $x$ 大，恰为按 $(\text{频次降序}, \text{值降序})$ 排序的前 $x$ 项；不足 $x$ 种时前 $\min(x, m) = m$ 项即全部。∎

**引理 3**：当 $m < x$ 时，前 $\min(x, m)$ 项的 $\sum v \cdot c_v$ 等于窗口元素总和，与「不足 $x$ 种则取总和」条款一致。

**证明**：$m < x$ 时保留全部 $m$ 种元素，每个元素的每次出现恰好计入一次，故 $\sum_{v} c_v \cdot v = \sum_{i} \text{nums}[i]$，即窗口总和。∎

**定理**：对每个 $i \in [0, n-k]$，算法输出的 `ans[i]` 等于 `nums[i..i+k-1]` 的 x-sum。

**证明**：算法对窗口建频次表（由引理 1，这是计算 x-sum 的充分信息），按 $(-\text{频次}, -\text{值})$ 排序后取前 $\min(x, m)$ 项并累加 $v \cdot c_v$。由引理 2，保留集合与定义一致；由引理 3，$m < x$ 的条款被同一逻辑覆盖；累加 $v \cdot c_v$ 恰为「保留元素的所有出现之和」。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big((n-k+1) \cdot (k + m \log m)\big)$，其中 $m \le \min(k, 50)$。粗略上界 $O(n k \log k)$，代入 $n = 50$ 约 $1.6 \times 10^4$ 次基本操作。
- **空间复杂度**：$O(m)$ 为频次表与排序数组（$\le 50$ 项），不计输出；输出数组占 $O(n-k+1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> findXSum(vector<int>& nums, int k, int x) {
        int n = nums.size();
        vector<int> ans;
        for (int i = 0; i + k <= n; ++i) {
            unordered_map<int, int> cnt;
            for (int j = i; j < i + k; ++j) ++cnt[nums[j]];   // ① 频次表
            vector<pair<int, int>> items;                      // (值, 频次)
            for (auto& [v, c] : cnt) items.emplace_back(v, c);
            sort(items.begin(), items.end(), [](const auto& a, const auto& b) {
                if (a.second != b.second) return a.second > b.second;  // ② 频次降序
                return a.first > b.first;                              // ③ 平局值大优先
            });
            int s = 0;
            for (int t = 0; t < x && t < (int)items.size(); ++t)       // ④ min(x, m) 截断
                s += items[t].first * items[t].second;                // ⑤ 值 × 频次
            ans.push_back(s);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findXSum(self, nums: List[int], k: int, x: int) -> List[int]:
        n = len(nums)
        ans = []
        for i in range(n - k + 1):
            cnt = Counter(nums[i:i + k])                     # ① 频次表
            top = sorted(cnt.items(), key=lambda p: (-p[1], -p[0]))[:x]  # ②③④ 排序 + 截断
            ans.append(sum(v * c for v, c in top))           # ⑤ 值 × 频次
        return ans
```

## 8. 边界情况与易错点

1. **平局方向**：频次相同时取**数值大**者，排序键 `(-频次, -值)`。方向写反或漏掉第二关键字，示例 1 的 `answer[1]` 就从 10 变 7。
2. **求和口径**：保留元素计入**全部出现**（值 × 频次），不是每种计一次。窗口 `[1,2]`、`x=1` 的 x-sum 是 2 而非 3。
3. **不足 $x$ 种**：`min(x, m)` 截断天然覆盖「取总和」条款，不必写 if 特判；但 C++ 手写循环若忘 `t < items.size()` 会越界。
4. **`x == k` 的快速自检**：每个窗口至多 $k = x$ 种元素，答案退化为窗口和（示例 2），可用来对拍。
5. **窗口个数是 $n-k+1$**：循环边界写 `i + k <= n`，别漏最后一个窗口。
6. **别误解平局条款**：「数值较大者被认为出现次数更多」只是**排序的平局打破规则**，频次数据本身不变，不改写频次表。
7. **本题无溢出风险**：窗口和 $\le 50 \times 50 = 2500$，`int` 足够；但同场 Q4 的 II 版 $k \le 10^5$、$\text{nums}[i] \le 10^9$，累加必须 `long long`。
