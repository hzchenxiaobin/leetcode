# LeetCode 点菜展示表 题解

## 1. 题目概述

- **标题 / 题号**：点菜展示表（#1418，medium）
- **链接**：https://leetcode.cn/problems/display-table-of-food-orders-in-a-restaurant/
- **来源**：LeetCode 第 185 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序、模拟

**题意**：给你订单数组 `orders[i] = [customerName, tableNumber, foodItem]`，分别是客户姓名、所在桌号、点的餐品。请返回「点菜展示表」：

- **第一行为表头**：第一列为 `"Table"`，其后每列是按**字母顺序**排列的餐品名；
- **每个数据行对应一张餐桌**：第一列为桌号（行间按**桌号升序**），其后为该桌点各餐品的**数量**，没点过的填 `"0"`；
- 客户姓名不出现在表中。

**约束**：

- $1 \le orders.length \le 5 \times 10^4$
- $orders[i].length = 3$；姓名与餐品名长度 $1 \sim 20$，由大小写字母和空格组成
- 桌号是 $1 \sim 500$ 的整数，但**以字符串形式**给出

> 💡 一句话定位：答案是一张「桌号 × 餐品」的**计数矩阵**——列按餐品字典序、行按桌号数值序、缺失补零，姓名是纯粹的干扰字段。本题的全部难度浓缩在**两种排序规则**与**字符串数字的类型转换**上。

## 2. 示例

**示例 1**

```text
输入：orders = [["David","3","Ceviche"],["Corina","10","Beef Burrito"],["David","3","Fried Chicken"],
               ["Carla","5","Water"],["Carla","5","Ceviche"],["Rous","3","Ceviche"]]
输出：[["Table","Beef Burrito","Ceviche","Fried Chicken","Water"],
       ["3","0","2","1","0"],["5","0","1","0","1"],["10","1","0","0","0"]]
解释：桌 3：David 点 Ceviche + Fried Chicken，Rous 点 Ceviche → Ceviche×2、Fried Chicken×1；
      桌 5：Carla 点 Water + Ceviche → 各 ×1；桌 10：Corina 点 Beef Burrito → ×1。
```

**示例 2**

```text

               ["Amadeus","12","Fried Chicken"],["Adam","1","Canadian Waffles"],["Brianna","1","Canadian Waffles"]]
输出：[["Table","Canadian Waffles","Fried Chicken"],["1","2","0"],["12","0","3"]]
解释：桌 1 两人各点一份 Canadian Waffles → ×2；桌 12 三人各点 Fried Chicken → ×3。注意行序 "1" 在 "12" 前。
```

**示例 3**

```text
输入：orders = [["Laura","2","Bean Burrito"],["Jhon","2","Beef Burrito"],["Melissa","2","Soda"]]
输出：[["Table","Bean Burrito","Beef Burrito","Soda"],["2","1","1","1"]]
解释：单桌三样餐品各一份。
```

## 3. 解题思路

### 3.1 朴素思路：逐格扫描计数

输出表有 $T$ 行 $F$ 列（$T$ = 出现过的桌号数，$F$ = 出现过的餐品数）。最直接的想法是把每个格子当独立问题：枚举每张桌 $t$、每个餐品 $f$，再扫一遍 `orders` 统计 $(t, f)$ 出现次数——$O(T \cdot F \cdot n)$。以 $T \le 500$、$F \le n = 5 \times 10^4$ 计，最坏约 $1.25 \times 10^{12}$ 次比较，必然超时。

> ⚠️ 朴素做法失败的原因：**每条订单只含一个 (桌, 餐品) 信息，却被重复读取了 $T \cdot F$ 次**。它对绝大多数格子而言是无关数据——重复扫描纯属浪费。

### 3.2 核心观察：订单 = (桌号, 餐品) 计数键，一趟哈希搞定

![核心观察：订单拆成 (桌号, 餐品) 二元组，嵌套哈希计数后拼成稠密展示表](images/wc185_q2_orders_to_table_concept.svg)

- **姓名是烟雾弹**：题面明说姓名不进展示表。一条订单对答案的全部贡献就是「桌 $t$ 的餐品 $f$ 计数 $+1$」，与谁点的无关；
- **答案是一张计数矩阵**：行集合 = 出现过的桌号，列集合 = 出现过的餐品，格值 = 对应二元组的出现次数，**缺失格 = 0**（稠密输出）；
- 于是一趟扫描把每条订单 $O(1)$ 累加进嵌套哈希，再把行、列各自排序、按序拼表即可。

> 💡 把「统计什么」看穿后，本题从 $O(T \cdot F \cdot n)$ 的模拟降维成 $O(n)$ 的计数。这是所有「报表类」模拟题的通用套路：**先找计数键，再定行列序，最后补零拼表**。

### 3.3 算法流程：计数 → 定列序 → 定行序 → 拼表补零

![算法流程：一趟计数、两种排序、拼表补零，附桌号排序陷阱](images/wc185_q2_algorithm_flow.svg)

```text
输入：orders
① 一趟扫描：foods ← 餐品去重；cnt[int(桌号)][餐品] += 1        O(n)
② 定列序：foods 按字典序排序，表头 = ["Table"] + foods           O(F log F)
③ 定行序：桌号转 int，按数值升序排列                            O(T log T)
④ 拼表：每桌一行 [str(桌号)] + 各餐品计数，未点的格子填 "0"      O(T·F)
输出：点菜展示表
```

> ⚠️ ③ 是本题头号 WA 点：桌号以**字符串**给出，按字典序排会得到 `"10" < "3" < "5"`（首字符 `'1' < '3'`），必须转 `int` 按数值排，输出时再转回字符串。

### 3.4 示例演算

![示例演算：6 条订单逐条计数，两种排序后拼成 4×5 展示表](images/wc185_q2_example_walkthrough.svg)

以示例 1 为例，一趟扫描的计数过程：

| 订单 | 二元组 | 计数表变化 |
|------|--------|-----------|
| David, 3, Ceviche | (3, Ceviche) | `cnt[3][Ceviche] = 1` |
| Corina, 10, Beef Burrito | (10, Beef Burrito) | `cnt[10][Beef Burrito] = 1` |
| David, 3, Fried Chicken | (3, Fried Chicken) | `cnt[3][Fried Chicken] = 1` |
| Carla, 5, Water | (5, Water) | `cnt[5][Water] = 1` |
| Carla, 5, Ceviche | (5, Ceviche) | `cnt[5][Ceviche] = 1` |
| Rous, 3, Ceviche | (3, Ceviche) | `cnt[3][Ceviche] = 2`（与第 1 行同格累加） |

排序：`foods = [Beef Burrito, Ceviche, Fried Chicken, Water]`（字典序），桌号 `[3, 5, 10]`（数值序）。拼表：

| Table | Beef Burrito | Ceviche | Fried Chicken | Water |
|-------|-------------|---------|---------------|-------|
| 3     | 0           | 2       | 1             | 0     |
| 5     | 0           | 1       | 0             | 1     |
| 10    | 1           | 0       | 0             | 0     |

> 💡 两处值得盯紧：桌 3 的 Ceviche 由 David 与 Rous 各点一次**同格累加**为 2；桌 10 没点 Ceviche，但该列照样存在并填 `"0"`。六条订单的姓名全程未参与任何计算。

## 4. 算法细节

1. **桌号的类型链**：`"10"`（输入）→ `int 10`（排序键）→ `"10"`（输出）。C++ 用 `stoi` + `to_string`，Python 用 `int()` + `str()`。这条链断在任何一环都会 WA：按字符串排序则行序错，直接输出 `int` 则类型错。
2. **两个有序容器分管两种序**：餐品侧 `set<string>`（C++）或 `sorted({...})`（Python）天然字典序，管**列**；桌号侧 `map<int, ...>`（C++）或 int 键 + `sorted`（Python）天然数值序，管**行**。C++ 一把 `map<int, map<string, int>>` 连内层餐品都是有序的，拼表时顺序遍历即可，连显式排序调用都省了。
3. **嵌套哈希 vs 元组键**：`cnt[桌][餐品]` 两级定位等价于 `Counter[(桌, 餐品)]` 元组键。Python 的 `Counter` 查缺失键返回 `0`，与「补零」语义天然契合（普通 `dict` 需 `.get((t, f), 0)`）。
4. **补零放在拼表时做**：计数阶段只记出现过的二元组；拼表时按 `foods` 全列扫一遍 `find → 0` 生成零格子。不要在计数阶段预填全零矩阵——既浪费空间也没必要。
5. **数据范围**：单格计数 $\le n \le 5 \times 10^4$，`int` 足够；桌号 $1 \sim 500$、餐品名 $\le 20$ 字符，哈希键都很短，单次操作 $O(1)$。

## 5. 正确性证明

**引理 1（计数正确性）**：一趟扫描结束后，$cnt[t][f]$ 等于 `orders` 中桌号为 $t$ 且餐品为 $f$ 的订单条数。

**证明**：对已处理的订单条数归纳。初始（0 条）所有计数为 0。设处理完前 $k$ 条时结论成立；第 $k+1$ 条订单 $(name, t', f')$ 使且仅使 $cnt[\mathrm{int}(t')][f']$ 自增 1，且每条订单恰好被处理一次，故处理完 $k+1$ 条后结论仍成立。∎

**引理 2（行序是数值序）**：题意「数据行按桌号升序排列」指的是**数值大小**序，而非字符串字典序。

**证明**：桌号是 $1 \sim 500$ 的正整数，仅以字符串形式存放。位数相同的桌号，逐位比较与数值比较一致；位数不同时两种序必然分歧：$5 < 10$（数值），但 $"5" > "10"$（首字符 `'5' > '1'`）。若按字典序输出，桌 10 会排到桌 3、5 之前，与「小桌号在前」的语义矛盾。故必须按数值排序（转 `int`），输出时再转回字符串。∎

**定理**：算法返回的表与「点菜展示表」逐格相同。

**证明**：点菜展示表由三要素唯一确定：(a) 表头 = `["Table"]` + 全部出现过的餐品按字典序；(b) 数据行 = 全部出现过的桌号按数值升序，每桌一行；(c) 格 $(t, f)$ 的值 = 桌 $t$ 点餐品 $f$ 的次数，未点为 0。算法中：表头由 `foods` 排序后构造，(a) 成立；数据行由 int 桌号升序遍历构造，由引理 2 行序正确，(b) 成立；由引理 1，`cnt[t][f]` 恰为该次数，查不到的键取 0，与「未点」的应填值一致，(c) 成立。三要素唯一确定输出，故逐格相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + F \log F + T \cdot F)$。扫描计数 $O(n)$（每条订单 $O(1)$ 哈希操作）；餐品排序 $O(F \log F)$；桌号排序 $O(T \log T)$（$T \le 500$，可忽略）；拼表 $O(T \cdot F)$，每个格子 $O(1)$ 字符串化。
- **空间复杂度**：$O(n + T \cdot F)$。计数哈希最多存 $n$ 个键，输出表 $(T+1) \times (F+1)$ 个格子。
- 其中 $n$ 为订单数（$\le 5 \times 10^4$）、$T$ 为不同桌号数（$\le 500$）、$F$ 为不同餐品数（$\le n$）。**$T \cdot F$ 是输出规模下界**——输出本身就有 $(T+1) \times (F+1)$ 个格子，拼表阶段不可能低于输出规模，故该复杂度已是最优。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<string>> displayTable(vector<vector<string>>& orders) {
        set<string> foods;                     // 列序：餐品字典序
        map<int, map<string, int>> cnt;        // 行序：桌号（int）数值序
        for (auto& o : orders) {
            foods.insert(o[2]);
            cnt[stoi(o[1])][o[2]]++;           // 桌号转 int：排序按数值
        }

        vector<vector<string>> res;
        res.push_back({"Table"});
        for (auto& f : foods) res[0].push_back(f);

        for (auto& [t, dish] : cnt) {          // map 按桌号数值升序
            vector<string> row{to_string(t)};
            for (auto& f : foods) {
                auto it = dish.find(f);
                row.push_back(it != dish.end() ? to_string(it->second) : "0");
            }
            res.push_back(move(row));
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def displayTable(self, orders: List[List[str]]) -> List[List[str]]:
        foods = sorted({o[2] for o in orders})          # 列序：餐品字典序
        cnt = defaultdict(lambda: defaultdict(int))     # 桌号(int) → 餐品 → 数量
        for _, table, food in orders:                   # 姓名直接丢弃
            cnt[int(table)][food] += 1                  # 桌号转 int：行按数值序

        res = [["Table"] + foods]
        for t in sorted(cnt):                           # int 键 → 数值升序
            res.append([str(t)] + [str(cnt[t][f]) for f in foods])
        return res
```

> 💡 两份代码同一骨架：**计数 → 双排序 → 拼表补零**。C++ 靠 `map<int, map<string, int>>` 的双重有序性免掉显式排序；Python 用 `sorted` 两次显式排序，`defaultdict` 查缺失键自动得 0。

## 8. 边界情况与易错点

1. **桌号字符串排序陷阱（头号 WA）**：字典序下 `"10" < "3" < "5"`，行序整体错乱。示例 1 恰好同时给出 3、5、10 三张桌，专门照出这个坑。必须转 `int` 排序、输出再转回 `str`。
2. **姓名是干扰字段**：既不进表头也不进统计；但同一桌不同客户点同一餐品要**累加**（示例 2 桌 12 三人各点一份 → 3）。
3. **稠密输出**：每个数据行必须填齐**全部**餐品列，未点的补 `"0"`；只输出「点过的」餐品会整行缺列。
4. **输出全为字符串**：桌号与数量都要 `to_string` / `str`，直接放 `int` 会类型错误。
5. **餐品名含空格**：`"Beef Burrito"`、`"Canadian Waffles"` 是单个餐品名，整体作哈希键，不能按空格拆词。
6. **排序比较器**：直接用语言默认的字符串比较（按码点）即与判题的「字母顺序」一致，无需手写大小写归一。
7. **$n = 1$**：输出 2×2 的表（表头 + 唯一桌 × 唯一餐品），不存在空表或空行。

**延伸思考**：

- 若桌号改为任意字符串（如 `"VIP-1"`、`"A3"`），行序退化为纯字典序，坑反而消失——本题的难度本质是「**字符串数字的语义歧义**」，而不是排序本身。
- 流式版本：订单不断到达、随时查询某桌某餐品数量 → 只需维护 `cnt` 哈希（$O(1)$ 更新 / $O(1)$ 点查）；全表重建 $O(T \cdot F)$，写操作后置脏、按需重算即可。
- 若要求餐品列按「点单总量降序」而非字典序：只把 `foods` 的排序键换成 $-\sum_t cnt[t][f]$（并列时字典序），计数与拼表完全不变——**报表题的三个组成部分里，只有排序键在变**。
