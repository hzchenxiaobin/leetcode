# LeetCode 生成数组 题解

## 1. 题目概述

- **标题 / 题号**：生成数组（#1420，hard）
- **链接**：https://leetcode.cn/problems/build-array-where-you-can-find-the-maximum-exactly-k-comparisons/
- **来源**：LeetCode 第 185 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、前缀和、计数

**题意**：题面内置了一个「找最大值」算法：从左到右扫描数组，维护当前最大值 `curmax` 与计数器 `search_cost`（均初始为 0）；一旦 `arr[i] > curmax` 就更新 `curmax = arr[i]` 并令 `search_cost += 1`。给定 `n`、`m`、`k`，统计有多少个长度恰为 `n`、元素都取自 `[1, m]` 的数组 `arr`，能使算法跑完后 `search_cost` 恰好等于 `k`。答案对 $10^9+7$ 取模。

**约束**：

- $1 \le n \le 50$
- $1 \le m \le 100$
- $0 \le k \le n$

> 💡 一句话定位：`search_cost` 就是**严格前缀最大值的刷新次数**——某位元素比它前面所有元素都**严格**大时才 +1（首位必 +1）。于是问题变为：值域 $[1,m]$、长度 $n$ 的数组中，恰有 $k$ 个「从左到右的记录」的有多少个？经典**计数 DP**：状态携带「当前最大值」，用**前缀和**把一段刷新转移压成 $O(1)$，总复杂度 $O(nkm)$。

## 2. 示例

输入：n = 2, m = 3, k = 1
输出：6
解释：[1,1], [2,1], [2,2], [3,1], [3,2], [3,3]。
      首元素为 v 时，第二位必须 ≤ v 才不再刷新：1 + 2 + 3 = 6。
```

**示例 2**

输出：0
解释：每次刷新都产生一个严格更大的新最大值，3 次刷新需要 3 个严格递增的值，
      而值域只有 {1, 2}，无解。
```

**示例 3**

```text

输出：1
解释：唯一可能的数组是 [1,1,1,1,1,1,1,1,1]，首位刷新一次后再无更大值。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $m^n$ 个数组，对每个数组模拟一遍算法统计 `search_cost`。$n=50, m=100$ 时约 $10^{100}$ 个数组，天文数字；即便 $m=2$、$n=50$ 也有 $2^{50}$ 个，完全不可行。

浪费在于：无数数组共享「相同的已填位数、相同的当前最大值、相同的已花代价」——**此后还能怎么填，与前面的具体排布完全无关**。把这三个量提取成状态逐位转移，就是计数 DP。

### 3.2 核心观察：search_cost = 严格前缀最大值的刷新次数

![核心观察：search_cost 是严格前缀最大值的刷新次数，未来只由当前最大值决定](images/wc185_q4_concept.svg)

对算法逐位归纳（引理 1，证明见 §5）：扫完前 $i$ 位后 `curmax` 恰为 $\max(arr[0..i])$，`search_cost` 恰等于「该位严格大于前缀最大」的位置个数。由此读出三个事实：

1. **首元素必刷新**：$arr[0] \ge 1 > 0 =$ 初始 `curmax`，故代价至少为 1，$k = 0$ 恒为 0；
2. **记录值严格递增**：第 $t$ 次刷新后的最大值严格大于第 $t-1$ 次的，$k$ 个记录需要 $k$ 个严格递增的值 → $k \le \min(n, m)$（示例 2 为 0 的原因）；
3. **未来只由当前最大值 $v$ 决定**：设当前最大值为 $v$，下一位填 $x \in [1, v]$ 有 $v$ 种「安全」选择（不刷新）；填 $x \in [v+1, m]$ 则必刷新且新最大值恰为 $x$。**全部历史被压缩进 $(i, j, v)$ 三个量**——这正是 DP 的状态。

### 3.3 状态设计与转移：一段刷新用前缀和聚合

![状态转移：不刷新乘 v，刷新用行前缀和聚合成 O(1) 查表](images/wc185_q4_algorithm_flow.svg)

**状态**：$f[i][j][v]$ = 长度 $i$、代价恰为 $j$、**前缀最大值恰为 $v$** 的数组个数。

**初始化**：$f[1][1][v] = 1$（$v = 1, \dots, m$）——单元素数组 $[v]$ 的代价必为 1。

**转移**：从 $(i, j, v)$ 考虑第 $i+1$ 位填什么，按与 $v$ 的大小关系二分：

- **安全**（$x \le v$）：$v$ 种选择都停在 $(i+1, j, v)$：

  $$f[i+1][j][v] \mathrel{+}= f[i][j][v] \cdot v$$

- **刷新**（$x > v$）：新最大恰为 $x$、代价 $+1$。目标格 $(i+1, j+1, x)$ 汇聚**所有** $v' < x$ 的来源：

  $$f[i+1][j+1][x] \mathrel{+}= \sum_{v'=1}^{x-1} f[i][j][v']$$

刷新转移若逐项求和，每个目标格 $O(m)$，总 $O(nkm^2) \approx 1.25 \times 10^7$，本题范围尚能通过但不够优雅。注意到来源恰是一段**值域前缀**，预处理行前缀和

$$P[i][j][x] = \sum_{v'=1}^{x} f[i][j][v']$$

即可 $O(1)$ 查表。两支转移于是合并为一条**逐格递推**——新表的每个格子由两个 $O(1)$ 量合成：

$$f[i+1][j][v] = f[i][j][v]\cdot v + P[i][j-1][v-1]$$

第二项的直觉：上一时刻代价为 $j-1$、最大值 $< v$ 的所有状态，这一位恰好刷新到 $v$。

**答案**：$\sum_{v=1}^{m} f[n][k][v]$（$k=0$ 或 $k > \min(n,m)$ 时自然为 0）。

```text
输入：n, m, k
① f[j][v] ← 0；f[1][v] ← 1（v = 1..m）          // 单元素数组，代价必为 1
② 重复 n−1 次（滚动推进 i）：
   a. 对每个 j 计算行前缀和 P[j][x] = P[j][x−1] + f[j][x]
   b. 新表逐格：nf[j][v] = f[j][v]·v + P[j−1][v−1]（取模）
   c. f ← nf
③ 返回 Σ_v f[k][v] mod 1e9+7
```

### 3.4 示例演算

![示例演算：n=3, m=2, k=2 三层 DP 表，答案格 3 的两路来源](images/wc185_q4_example_walkthrough.svg)

取 $n=3, m=2, k=2$（表按「行 = 代价 $j$、列 = 最大值 $v$」组织，每个格子写 $(v{=}1,\ v{=}2)$ 两个值）：

| 长度 $i$ | $f[\cdot][1][\cdot]$ | $f[\cdot][2][\cdot]$ | $f[\cdot][3][\cdot]$ |
|---|---|---|---|
| $i=1$ | 1, 1 | 0, 0 | 0, 0 |
| $i=2$ | 1, 2 | 0, 1 | 0, 0 |
| $i=3$ | 1, 4 | 0, **3** | 0, 0 |

关键一格：$f[3][2][2] = \underbrace{f[2][2][2] \cdot 2}_{\text{安全} = 2} + \underbrace{P[2][1][1]}_{\text{刷新} = f[2][1][1] = 1} = 3$，正对应三个数组 $[1,2,1]$、$[1,2,2]$（$[1,2]$ 末位安全补 1 或 2）与 $[1,1,2]$（$[1,1]$ 末位刷新到 2）。答案 $f[3][2][1] + f[3][2][2] = 0 + 3 = 3$ ✓。而 $j=3$ 一行全为 0——值域 $\{1,2\}$ 撑不起 3 个严格递增的记录值（同示例 2）。

顺带验证示例 1（$n=2, m=3, k=1$）：$f[2][1][v] = f[1][1][v] \cdot v = v$，答案 $1+2+3 = 6$ ✓。

## 4. 算法细节

1. **「恰为 $v$」而非「至多为 $v$」**：状态定义为前缀最大**恰好**等于 $v$——安全选择的个数恰为 $v$（$x \in [1,v]$ **含 $x=v$**，因刷新条件是严格大于），转移乘数干净；若用「至多」语义还得做差还原，平添出错面。
2. **前缀和必须取自旧表**：每层先用旧表算行前缀和 $P[j][\cdot]$，再逐格生成新表；若边生成新表边读 $f$，会把「刷新来源」污染成新旧混合值（经典 WA 点）。
3. **滚动数组**：$i$ 维每次只依赖上一层，两张 $(k+2) \times (m+1)$ 的表交替即可，空间 $O(km)$；行数开 $k+2$ 是为了让 $j-1$ 与 $j=k$ 都不越界。
4. **$j$ 的循环范围**：每层只需 $j \in [1, k]$；$j=0$ 恒为 0（首元素必刷新），从 1 开始即可，$P[0][\cdot]$ 自然全 0，递推式无需特判。
5. **无解边界不特判**：$k=0$（代价至少 1）与 $k > \min(n, m)$（记录值严格递增）都会被 DP 自然算出 0；也可作输入快速剪枝。
6. **取模与溢出**：$f[j][v] \cdot v$ 最大约 $(10^9) \times 100 = 10^{11}$，C++ 必须 `long long` 乘完再取模；前缀和累加与最终求和同样逐级取模。Python 无溢出问题，逐级取模只为控制大数规模。

## 5. 正确性证明

**引理 1（代价刻画）**：对元素取自 $[1,m]$ 的任意数组，算法处理完前缀 $arr[0..i]$ 后 `curmax` $= \max(arr[0..i])$，且最终

$$\text{search\_cost} = \#\{\, i : arr[i] > \max(arr[0..i-1]) \,\}$$

（约定空前缀最大值为 $0$）。特别地，$n \ge 1$ 时 $\text{search\_cost} \ge 1$。

**证明**：对 $i$ 归纳。空前缀时 `curmax` $= 0$、代价为 0，成立。设处理完 $arr[0..i-1]$ 后不变量成立。处理 $arr[i]$：若 $arr[i] \le$ `curmax` $= \max(arr[0..i-1])$，则前缀最大不变、分支不执行；否则 $arr[i]$ 恰为新的前缀最大，`curmax` 被更新为它且代价 $+1$。两种情形均维护不变量，且代价恰在「严格超过此前所有元素」时递增。∎

**引理 2（记录值严格递增）**：若算法代价为 $k$，则历次刷新后的 `curmax` 取值 $r_1 < r_2 < \dots < r_k$ 严格递增；特别地 $k \le \min(n, m)$。

**证明**：每次刷新把 `curmax` 赋为一个严格更大的值，此后只增不减；这 $k$ 个记录值互不相同、均取自 $[1,m]$，且发生在互异下标上（每个下标至多贡献一次刷新）。∎

**引理 3（不重不漏）**：按 §3.3 的初始化与转移迭代所得的 $f[i][j][v]$，恰好等于「长度 $i$、代价 $j$、前缀最大恰为 $v$」的数组个数。

**证明**：对 $i$ 归纳。
$i=1$：单元素数组仅有 $[v]$（$v \in [1,m]$），代价为 1、前缀最大为 $v$，各恰 1 个，与初始化一致；其余格子为 0，正确。
$i \to i+1$：把长度 $i+1$、代价 $j$、前缀最大恰为 $v$ 的数组 $arr$ 按**末位是否为记录**分为两类（互斥且完备）：
- **末位不刷新**（$arr[i] \le \max(arr[0..i-1])$）：由最终最大为 $v$ 且末位不超过它，知前 $i$ 位的最大恰为 $v$、代价不变为 $j$。前 $i$ 位是「长 $i$、代价 $j$、最大 $v$」的任意数组，末位可取 $[1, v]$ 中任意值（$v$ 种），共 $f[i][j][v] \cdot v$ 个；
- **末位刷新**（$arr[i] > \max(arr[0..i-1])$）：末位必为 $v$（它是新最大），前 $i$ 位的最大 $v' < v$、代价为 $j-1$。前 $i$ 位是「长 $i$、代价 $j-1$、最大 $v' \in [1, v-1]$」的任意数组，末位唯一确定，共 $\sum_{v'=1}^{v-1} f[i][j-1][v'] = P[i][j-1][v-1]$ 个。

两类中「前缀 $\times$ 末位」的分解均为双射，相加即得逐格递推式。∎

**定理**：算法返回值 $= \#\{\, arr \in [1,m]^n : \text{search\_cost}(arr) = k \,\} \bmod (10^9+7)$。

**证明**：所计集合按「代价 $k$、前缀最大 $v$」分桶，桶大小由引理 3 为 $f[n][k][v]$，故总数为 $\sum_{v=1}^{m} f[n][k][v]$。算法每步只做模意义下的加法与乘法，而 $\mathbb{Z} \to \mathbb{Z}_{10^9+7}$ 是环同态，返回值与真实计数在模 $10^9+7$ 下相等。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot k \cdot m)$。每层先 $O(km)$ 算行前缀和，再 $O(km)$ 逐格生成新表，共 $n-1$ 层；本题上限 $50 \times 50 \times 100 = 2.5 \times 10^5$ 次转移，毫秒级。朴素逐项求和版为 $O(nkm^2) \approx 1.25 \times 10^7$，虽也能过，前缀和却是零成本的优雅。
- **空间复杂度**：$O(k \cdot m)$。滚动两张 $(k+2) \times (m+1)$ 的表，约 $5 \times 10^3$ 个数；若保留全部层则为 $O(nkm)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numOfArrays(int n, int m, int k) {
        const long long MOD = 1000000007;
        // f[j][v]: 已填 i 位、代价 j、前缀最大恰为 v 的方案数（沿 i 滚动）
        vector<vector<long long>> f(k + 2, vector<long long>(m + 1, 0));
        for (int v = 1; v <= m; ++v) f[1][v] = 1;   // 单元素数组，代价必为 1
        for (int i = 1; i < n; ++i) {
            // 行前缀和 P[j][x] = Σ_{v≤x} f[j][v]（取自旧表）
            vector<vector<long long>> P(k + 1, vector<long long>(m + 1, 0));
            for (int j = 1; j <= k; ++j)
                for (int v = 1; v <= m; ++v)
                    P[j][v] = (P[j][v - 1] + f[j][v]) % MOD;
            vector<vector<long long>> nf(k + 2, vector<long long>(m + 1, 0));
            for (int j = 1; j <= k; ++j)
                for (int v = 1; v <= m; ++v)
                    nf[j][v] = (f[j][v] * v + P[j - 1][v - 1]) % MOD;
            f.swap(nf);
        }
        long long ans = 0;
        for (int v = 1; v <= m; ++v) ans = (ans + f[k][v]) % MOD;
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def numOfArrays(self, n: int, m: int, k: int) -> int:
        MOD = 10 ** 9 + 7
        # f[j][v]: 已填 i 位、代价 j、前缀最大恰为 v 的方案数（沿 i 滚动）
        f = [[0] * (m + 1) for _ in range(k + 2)]
        for v in range(1, m + 1):
            f[1][v] = 1                             # 单元素数组，代价必为 1
        for _ in range(n - 1):
            P = [[0] * (m + 1) for _ in range(k + 1)]
            for j in range(1, k + 1):               # 行前缀和（取自旧表）
                for v in range(1, m + 1):
                    P[j][v] = (P[j][v - 1] + f[j][v]) % MOD
            nf = [[0] * (m + 1) for _ in range(k + 2)]
            for j in range(1, k + 1):               # 逐格递推
                for v in range(1, m + 1):
                    nf[j][v] = (f[j][v] * v + P[j - 1][v - 1]) % MOD
            f = nf
        return sum(f[k]) % MOD
```

> 💡 两版都把「安全乘 $v$」与「刷新查前缀和」合并在同一行递推里。若想先写朴素 $O(nkm^2)$ 版（内层显式枚举下一取值 $x$）便于调试，再换前缀和，可参考每日题解的三维写法与 `j=0` 哨兵消除特判技巧（见文末链接）。

## 8. 边界情况与易错点

1. **k = 0 直接 0**：$n \ge 1$ 时首元素必刷新（引理 1），代价至少为 1；DP 从 $j=1$ 起算，$f[k=0]$ 行自然全 0。
2. **k > min(n, m) 为 0**：记录值严格递增（引理 2），位置或值域不够就无解——示例 2（$n=5, m=2, k=3$）即值域不够。可作输入剪枝。
3. **n = 1**：主循环不执行，答案为 $m$（$k=1$）或 0（$k \ne 1$）——单元素数组 $[1..m]$ 各代价 1。
4. **m = 1**：全部元素为 1，代价恒为 1；仅 $k=1$ 有解且方案数为 1（示例 3）。
5. **前缀和取自新表（头号 WA）**：必须先算 $P$ 再生成新表；边算边覆盖 $f$ 会让刷新来源混入本层新值。
6. **安全乘数是 v 不是 v−1**：刷新条件是**严格**大于（`arr[i] > curmax`），相等不刷新；$x = v$ 属于安全选择，共 $v$ 种。误用 $v-1$ 会在示例 1 错算成 $0+1+2=3$。
7. **C++ 溢出**：$f[j][v] \cdot v \approx 10^{11}$ 超 `int` 范围；用 `long long` 乘完取模，前缀和累加处同样防溢。
8. **递推第二项查的是 j−1 行**：$P[i][j-1][v-1]$ 是**代价减一**那一行的前缀和；写错行号会把安全与刷新的来源加错层。

**延伸思考**：

- **排列版（Stirling 数）**：若额外要求 `arr` 是 $1..n$ 的排列（$m = n$ 且互异），恰有 $k$ 个前缀最大值的排列数恰为无符号第一类 Stirling 数 $\begin{bmatrix} n \\ k \end{bmatrix}$——本题是其「值域受限、可重复」的推广。
- **恰 k → 至多 k**：答案改为 $\sum_{j \le k} \sum_v f[n][j][v]$，即对 $j$ 维再做一次前缀和；「至少 k」可类似容斥。
- **输出任一方案**：DP 倒序回溯——从答案非零的 $(n, k, v)$ 出发，每步判断当前格子由「安全」还是「刷新」分支贡献，即可构造一个满足条件的数组。
- **k 上界剪枝**：$k > \min(n, m)$ 时跳过全部计算直接返回 0。
