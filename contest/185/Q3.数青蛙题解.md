# LeetCode 数青蛙 题解

## 1. 题目概述

- **标题 / 题号**：数青蛙（#1419，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-frogs-croaking/
- **来源**：LeetCode 第 185 场周赛 Q3
- **难度**：中等
- **标签**：字符串、计数、贪心、模拟

**题意**：给定字符串 `croakOfFrogs`，它是若干只青蛙发出的蛙鸣 `"croak"` 的交错混合。每只青蛙发出一声蛙鸣必须**依序**输出 `'c' → 'r' → 'o' → 'a' → 'k'` 五个字母；多只青蛙可以同时鸣叫，叫完一声的青蛙可以**立刻**开始下一声。求模拟整个字符串**最少**需要多少只青蛙；若字符串无法由若干完整的 `"croak"` 交错组成，返回 `-1`。

**约束**：

- $1 \le \text{croakOfFrogs.length} \le 10^5$
- 字符串只含 `'c'`、`'r'`、`'o'`、`'a'`、`'k'` 五种字符

> 💡 一句话定位：把每声 `"croak"` 看成时间轴上的一个**区间**，青蛙是可以复用的资源——这正是经典的「最少会议室」模型：**最少青蛙数 = 同时在叫的蛙鸣数的峰值**，一趟计数即可求出。

## 3. 解题思路

### 3.1 暴力思路：显式维护每只青蛙

维护一个青蛙列表，每只记录「下一个要说的字母」。逐字符扫描，对当前字符 `ch` 线性查找一只恰好等着说 `ch` 的青蛙并推进它；找不到且 `ch == 'c'` 就新建一只，否则返回 `-1`。最终列表大小即答案。

问题：每个字符都要扫一遍全部青蛙，时间 $O(n \cdot m)$（$m$ 为青蛙数）。合唱型输入如 `"ccrroo…"` 中 $m = n/5 = 2 \times 10^4$，总比较约 $2 \times 10^9$ 次，$n = 10^5$ 规模下必然超时。

> ⚠️ 暴力的浪费在于**追踪了不该追踪的信息**：判定合法性与计数只依赖「每个状态下有几只青蛙」，与「具体是哪只」无关。5 种状态用 5 个计数器就够。

### 3.2 核心观察：蛙鸣是区间，青蛙是资源，答案 = 峰值并发

![核心观察：蛙鸣是区间，青蛙是可复用资源，答案等于峰值并发](images/wc185_q3_concept.svg)

- **每声 `"croak"` 是一个区间**：从它的 `'c'` 所在位置开始，到配对的 `'k'` 结束。示例 2 中青蛙 A 占据位置 $[0,5]$、青蛙 B 占据 $[2,9]$，两区间重叠；
- **青蛙串行发音**：一只青蛙的一声蛙鸣未说完（还没到 `'k'`）不能再开下一声，所以**重叠的蛙鸣区间必须占用不同的青蛙**；
- **答案 = 峰值并发**：在飞蛙鸣数 $cur$ 只在 `'c'` 时 $+1$、`'k'` 时 $-1$，即任意前缀的 $\#c - \#k$。这个量**与蛙鸣的具体配对方式无关**——每声蛙鸣必然由一个 `'c'` 开启、一个 `'k'` 闭合，于是

$$\text{最少青蛙数} = \max_{\text{前缀}} (\#c - \#k)$$

这正是 [253. 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/) 的「区间划分：最少资源数 = 最大重叠数」结论（严格证明见 §5）。

> 💡 关键的减负推论：既然答案有闭式（峰值），我们**根本不需要显式分配青蛙**，也不需要维护「空闲青蛙池」——只需验证字符串合法（扫描不断供、结尾无在飞）并记录 $cur$ 的峰值。

### 3.3 算法流程：5 个计数器 + 1 个峰值变量

![算法流程：一趟扫描，计数器流转，'c' 刷新峰值，'k' 收尾，两处 -1 判定](images/wc185_q3_algorithm_flow.svg)

```text
输入：croakOfFrogs
① 初始化：cnt[5] = {0}（c/r/o/a/k 各状态在飞青蛙数），cur = ans = 0
② 对每个字符 ch，i ← ch 在 "croak" 中的下标：
   - i = 0（'c'）：开启一声新蛙鸣 → cur++；ans = max(ans, cur)
   - i > 0：若 cnt[i-1] = 0 → 返回 -1（没有青蛙能发出这个音）
             否则 cnt[i-1]--（一只青蛙从前驱音推进到 ch）
   - cnt[i]++；若 i = 4（'k'）→ cur--（一声完整收尾）
③ 扫描结束：cur = 0 → 返回 ans；cur > 0 → 返回 -1（有蛙鸣没收尾）
输出：最少青蛙数 或 -1
```

> ⚠️ 两处 `-1` 缺一不可：**中途断供**（如 `"co"`，`'o'` 到来时 $cnt[r]=0$）与**末尾在飞**（如 `"croakcr"`，扫描全程合法但最后一幕停在 `'r'`）。贯穿全程的不变量是 $cur = cnt[c]+cnt[r]+cnt[o]+cnt[a] = \#c-\#k$（前缀）。

### 3.4 示例演算

![示例演算：crcoakroak 十步扫描，计数器流转与峰值刷新](images/wc185_q3_example_walkthrough.svg)

以示例 2 `"crcoakroak"` 为例（cnt 按 c/r/o/a/k 顺序）：

| 步 | 字符 | 动作 | cnt (c/r/o/a/k) | cur | ans |
|----|------|------|-----------------|-----|-----|
| 1 | c | 开启蛙鸣 A | 1/0/0/0/0 | 1 | 1 |
| 2 | r | A：c→r | 0/1/0/0/0 | 1 | 1 |
| 3 | c | 开启蛙鸣 B，**峰值刷新** | 1/1/0/0/0 | 2 | **2** |
| 4 | o | A：r→o | 1/0/1/0/0 | 2 | 2 |
| 5 | a | A：o→a | 1/0/0/1/0 | 2 | 2 |
| 6 | k | A 收尾 | 1/0/0/0/1 | 1 | 2 |
| 7 | r | B：c→r | 0/1/0/0/1 | 1 | 2 |
| 8 | o | B：r→o | 0/0/1/0/1 | 1 | 2 |
| 9 | a | B：o→a | 0/0/0/1/1 | 1 | 2 |
| 10 | k | B 收尾 | 0/0/0/0/2 | 0 | 2 |

扫描结束 $cur = 0$，返回 $ans = 2$ ✓。第 3 步是胜负手：A 正停在 `'r'`，第二个 `'c'` 只能开启第二声蛙鸣，并发冲上 2——这一瞬间**必须**有两只青蛙同时在场。

> 💡 对照示例 1 `"croakcroak"`：前 5 步后 $cur$ 回到 0，第 6 个 `'c'` 复用同一只青蛙，全程峰值 1。对照示例 3 `"croakcrook"`：第 8 个字符 `'o'` 到来时 $cnt[r] = 0$，立即返回 `-1`。

## 4. 算法细节

1. **下标映射**：`"croak".find(ch)`（C++）或 `"croak".index(ch)`（Python）把字符映成 $0\sim4$；作用在长度 5 的常量串上，单次 $O(1)$，也可换成 `switch` / 字典直查。
2. **为什么不需要空闲青蛙池**：`'c'` 到来时「复用还是新开」不影响任何计数——两种情况都是 $cur$ 加一，而答案只取 $cur$ 的峰值。青蛙分配是「存在即可」的论证对象（见 §5 定理的上界证明），不必落实到代码。这比让 `cnt[k]` 兼任空闲池、加复用判断的写法少一个分支。
3. **cur 与 cnt 的恒等关系**：$cur \equiv cnt[0]+cnt[1]+cnt[2]+cnt[3] \equiv \#c-\#k$（当前前缀）。维护增量变量免去每步求和；`cnt[4]` 只增不减，语义是「已完成蛙鸣总数」，不参与任何判定，留作调试观察。
4. **峰值只在 `'c'` 处刷新**：$cur$ 只在 `'c'` 时上升，`ans = max(ans, cur)` 写在 `'c'` 分支内即可，且必须在 `cur++` 之后（放前面会永远慢一拍）。
5. **合法性 = 两道闸门**：扫描中的「前驱断供」检查交错结构是否成立，结尾的 $cur = 0$ 检查每声蛙鸣是否完整。二者合并覆盖「字符串是若干完整 croak 的交错」的全部否定情形（引理 2）。
6. **数据范围**：合法串中五字符计数相等，故 $ans \le \lfloor n/5 \rfloor \le 2 \times 10^4$，`int` 足够；$n = 10^5$，单趟 $O(n)$ 无压力。

## 5. 正确性证明

**引理 1（前缀不变量）**：扫描任意前缀后，$cur = \#c - \#k$（该前缀中两字符的个数差），且 $cnt[0]+cnt[1]+cnt[2]+cnt[3] = cur$。

**证明**：对前缀长度归纳。空前缀两者均为 0。设长度为 $k$ 时成立，考察第 $k+1$ 个字符：若为 `'c'`，则 $cur$ 与四态计数和各加 1，$\#c$ 加 1；若为 `'k'`，则 $cnt[3]$ 减 1、$cnt[4]$ 加 1，四态计数和与 $cur$ 各减 1，$\#k$ 加 1；其余字符只在四态之间挪动 1（$cnt[i-1]$ 减、$cnt[i]$ 加），$cur$ 与字符计数均不变。故长度 $k+1$ 时仍成立。∎

**引理 2（合法性判定）**：`croakOfFrogs` 是若干完整 `"croak"` 的交错 $\iff$ 扫描中每个 $i>0$ 的字符都有 $cnt[i-1]>0$，且结束时 $cur=0$。

**证明**：
（⇒）设字符串按某种方式分解为若干完整的 `"croak"`。对任意前缀，处于「已说字母 $s$、未说 $s$ 的下一字母 $s^+$」（$s \in \{c,r,o,a\}$）状态的蛙鸣实例数恰为 $\#s-\#s^+$；而由计数规则，$cnt[s]$ 正是这个差值（$s$ 出现时加 1，$s^+$ 出现时减 1）。当字符 $x \ne c$ 到来时，它所属的实例正处于其前驱状态，故 $cnt[\text{前驱}] \ge 1$，扫描不会断供。结束时每个实例都完整，五字符总计数相等，四态计数之和为 0，即 $cur=0$。
（⇐）构造性证明：维护真实青蛙集合，保持归纳不变式「各状态在飞青蛙的多重集 $\equiv$ $cnt[0..3]$」。非 `'c'` 字符由 $cnt[i-1]>0$ 保证存在处于前驱态的青蛙，任取一只推进；`'c'` 则取一只空闲青蛙（若有）否则新建一只开启新蛙鸣。结束时 $cur=0$ 说明没有半途的蛙鸣，每只青蛙的发音序列都被完整切分成若干 `"croak"`。∎

**定理（最优性）**：若串合法，最少青蛙数 $p^\* = \max\limits_{\text{前缀}}(\#c-\#k)$，算法返回的 $ans$ 恰为 $p^\*$。

**证明**：
下界：取达到最大值的前缀，记 $p = \#c-\#k$。该时刻有 $p$ 声蛙鸣已开始未结束（在飞）。一只青蛙的两声蛙鸣在字符串上必然完全先后（必须说完前一声的 `'k'` 才能开始后一声的 `'c'`），故两声在飞的蛙鸣不能共享同一只青蛙——这 $p$ 声在飞蛙鸣占用 $p$ 只**互不相同**的青蛙，任何可行方案的青蛙数 $\ge p$。
上界：采用引理 2（⇐）中的贪心分配——`'c'` 到来时空闲则复用、无空闲才新建。新建仅发生在「现有青蛙全部在飞」的时刻，此刻青蛙总数等于在飞数；新建并处理完该 `'c'` 后，总数 $=$ 在飞数 $= cur \le p$。故任何时刻青蛙总数 $\le p$，即 $p$ 只青蛙足以完成整个模拟。
两边夹逼得 $p^\* = p$。由引理 1，算法维护的 $ans = \max cur = p$，即返回最优值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个字符一次 $O(1)$ 下标查询与常数次计数器增减。
- **空间复杂度**：$O(1)$。`cnt[5]` 加 `cur`、`ans` 共 7 个变量，与输入规模无关。
- 相比暴力 $O(n \cdot m)$ 的逐青蛙扫描，把「找一只可用的青蛙」从 $O(m)$ 降为 $O(1)$——只需知道前驱状态的计数是否为正，无需知道是哪一只。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minNumberOfFrogs(string croakOfFrogs) {
        int cnt[5] = {0};              // cnt[i]: 处于 "croak"[i] 状态的在飞青蛙数
        int cur = 0, ans = 0;          // 当前在飞蛙鸣数 / 历史峰值
        const string t = "croak";
        for (char ch : croakOfFrogs) {
            int i = t.find(ch);
            if (i == 0) {              // 'c'：开启一声新蛙鸣
                cur++;
                ans = max(ans, cur);   // 峰值只在 'c' 处刷新
            } else {
                if (cnt[i - 1] == 0) return -1;   // 没有青蛙能发出这个音
                cnt[i - 1]--;          // 一只青蛙从前驱音推进到 ch
            }
            cnt[i]++;
            if (i == 4) cur--;         // 'k'：一声 croak 完整收尾
        }
        return cur == 0 ? ans : -1;    // 末尾仍有蛙鸣未收尾 → 非法
    }
};
```

### Python

```python
class Solution:
    def minNumberOfFrogs(self, croakOfFrogs: str) -> int:
        s = "croak"
        cnt = [0] * 5                  # 各状态的在飞青蛙数
        cur = ans = 0                  # 当前在飞蛙鸣数 / 历史峰值
        for ch in croakOfFrogs:
            i = s.index(ch)
            if i == 0:                 # 'c'：开启一声新蛙鸣
                cur += 1
                ans = max(ans, cur)    # 峰值只在 'c' 处刷新
            else:
                if cnt[i - 1] == 0:
                    return -1          # 没有青蛙能发出这个音
                cnt[i - 1] -= 1
            cnt[i] += 1
            if i == 4:
                cur -= 1               # 'k'：一声完整收尾
        return ans if cur == 0 else -1
```

> 💡 另有一种等价的「前驱映射」写法：把 `'c'` 的前驱设为 `'k'`，让复用与新建统一成同一套 `cnt[prev]--` / `cnt[idx]++` 转移——那版需要 `cnt[k]` 兼任空闲池。本版利用 §5 的峰值定理省掉了复用判断，分支更少。

## 8. 边界情况与易错点

1. **漏掉末尾 `cur == 0` 检查（头号 WA）**：`"croakcr"` 扫描全程无断供，但没有青蛙说完整第二声，应返回 `-1` 而非 `1`。由引理 1，`cur` 就是「在飞蛙鸣数」，结尾非零即非法。
2. **只校验五字符计数相等不够**：`"croakkroa"` 中 $\#c=\#r=\#o=\#a=\#k=2$，但第 6 个字符 `'k'` 到来时 $cnt[a]=0$，断供返回 `-1`。计数相等只是合法的必要条件。
3. **峰值更新位置**：`ans = max(ans, cur)` 必须写在 `'c'` 分支内、且在 `cur++` 之后。若放在 `cur++` 之前会永远慢一拍：`"ccrrooaakk"` 会错算成 1（正确为 2）。
4. **首个字符不是 'c'**：如 `"roak"`，`'r'` 到来时 $cnt[c]=0$ 直接 `-1`——前驱检查天然覆盖，无需特判首字符。
5. **单字符输入**：`"c"` 结尾 $cur=1$ 返回 `-1`；`"k"` 断供返回 `-1`。不存在长度小于 5 的合法输入。
6. **合唱串**：`"ccrrooaakk"` 合法且答案为 2——不要误以为相同字符连排就非法，断供检查只看**前驱**计数，不看后续。
7. **`find` / `index` 未命中**：约束保证字符只有五种；若不放心可先校验（本题可省）。Python 的 `str.index` 对非法字符会抛异常，C++ 的 `find` 返回 `string::npos`。
