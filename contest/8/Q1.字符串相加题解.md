# LeetCode 字符串相加 题解

## 1. 题目概述

- **标题 / 题号**：字符串相加（#415，easy）
- **链接**：https://leetcode.cn/problems/add-strings/
- **来源**：LeetCode 第 8 场周赛 Q1
- **难度**：简单
- **标签**：数学、字符串、模拟

**题意**：给定两个用字符串表示的非负整数 `num1` 和 `num2`，返回它们的和，结果同样用字符串表示。禁止使用 `BigInteger` 之类处理大整数的库，也禁止把输入的字符串**整体**转成整数——换句话说，要求手写一次十进制竖式加法，只允许逐字符取数位。

**约束**：

- $1 \le \lvert\text{num1}\rvert, \lvert\text{num2}\rvert \le 10^4$
- `num1`、`num2` 只包含数字 `0-9`
- 两串都不含前导零（单独一个 `"0"` 除外）

> 💡 这是一道签到题，考点不在算法而在**边界**：最高位的进位、两串长度不等、以及「不能用整型偷懒」这三件事。

## 2. 示例

**示例 1**

```text
输入：num1 = "11", num2 = "123"
输出："134"
解释：11 + 123 = 134，两串长度不同，短的那个在高位没有数字。
```

**示例 2**

```text
输入：num1 = "456", num2 = "77"
输出："533"
解释：个位 6+7=13 写 3 进 1；十位 5+7+1=13 写 3 进 1；百位 4+0+1=5。
```

**示例 3**

```text
输入：num1 = "0", num2 = "0"
输出："0"
解释：两个零相加仍是 "0"，不能输出空串，也不能输出 "00"。
```

## 3. 解题思路

### 3.1 暴力思路

最省事的写法是把两串转成整数相加再转回字符串：C++ 的 `long long` 只有约 19 位十进制，$10^4$ 位必然溢出，`stoll` 会抛异常；Python 的 `int` 虽然没有溢出问题，但题面白纸黑字禁止「把输入字符串直接转成整数」，这样写属于**违规解法**。

另一条路是用大整数数组自己做 $O(n^2)$ 的「乘 10 的幂再累加」，或调 `boost::multiprecision`——代码量、常数、依赖都远大于竖式，完全没必要。

结论：唯一自然且合规的做法是**逐位模拟竖式加法**，一遍 $O(n)$ 扫描完成。

### 3.2 核心观察：竖式模拟（逐位进位）

![竖式加法的列对齐与单列规则](images/wc8_q1_vertical_addition_concept.svg)

把两个串**右对齐**，指针 `i`、`j` 分别从 `num1`、`num2` 的末尾出发，向左同步推进。每一列只做三件事：

$$s = a + b + c,\qquad \text{digit} = s \bmod 10,\qquad c' = \left\lfloor \frac{s}{10} \right\rfloor$$

其中 $a,b$ 是当前位数字（**越界按 0**），$c$ 是上一位留下的进位，$c'$ 是要传给左边的进位。

关键量级观察：$a,b \le 9$、$c \le 1$，于是 $s \le 19$，所以

$$c' = \left\lfloor \frac{s}{10} \right\rfloor \in \{0, 1\}$$

**进位永不超过 1**，用一个 `int` 即可携带，不需要任何大整数结构。这就是「字符串长度 $10^4$ 但计算本身是 $O(1)$ 状态」的原因。

### 3.3 算法流程

![逐位模拟加法的流程图](images/wc8_q1_simulation_flow.svg)

```text
i = len(num1) - 1, j = len(num2) - 1, carry = 0, buf = []
while i >= 0 or j >= 0 or carry:
    s = carry
    if i >= 0: s += num1[i] - '0'; i--
    if j >= 0: s += num2[j] - '0'; j--
    buf.append(s % 10)        # 低位先写
    carry = s // 10
return reverse(buf) 拼成字符串
```

循环条件里的 `carry` 是关键：它保证「两串都读完后，如果还有进位，就再补一位」（如 `"9" + "9" = "18"`）。

### 3.4 示例演算

![456 + 77 的逐列走查](images/wc8_q1_walkthrough.svg)

对 `num1 = "456"`、`num2 = "77"` 走一遍：

| 轮次 | 位 | num1 位 | num2 位 | 进位入 | $s$ | 写入 / 进位出 |
|------|----|---------|---------|--------|-----|----------------|
| 1 | 个位 | 6 | 7 | 0 | 13 | 写 `3`，进 1 |
| 2 | 十位 | 5 | 7 | 1 | 13 | 写 `3`，进 1 |
| 3 | 百位 | 4 | 越界→0 | 1 | 5 | 写 `5`，进 0 |

此时 `i`、`j` 都已小于 0 且 `carry = 0`，循环结束；`buf = ['3','3','5']` 是**低位在前**，反转得 `"533"`。

## 4. 算法细节

1. **双指针右对齐**：`i`、`j` 从两串尾部独立左移，长度不等时短串自然「越界」，越界的位取 0 即可，千万不要在短串前面真的补 `'0'`（会破坏「无前导零」的假设，也浪费 $O(n)$ 空间）。
2. **循环条件三选一**：`i >= 0 || j >= 0 || carry`。少写 `carry` 会让 `"1" + "9"` 输出 `"0"`、`"9" + "9"` 输出 `"8"`。
3. **字符取值**：C++ 用 `num1[i] - '0'`，Python 用 `ord(num1[i]) - ord('0')`。直接 `(int)num1[i]` 得到的是 ASCII 码 48~57，会算错。
4. **逆序拼接**：先 `push_back` 低位、最后整体 `reverse`，是 $O(n)$。C++ 里 `res = c + res` 或 `insert(0, 1, c)` 每次搬移整串，退化成 $O(n^2)$。
5. **预分配容量**：C++ 用 `res.reserve(max(m, n) + 1)`，长度最多比长串多 1（进位），避免反复扩容。
6. **不进整型**：整个过程中最大的数是 $19$，任何中间变量都不会超过 `int`；这正是竖式相对「转整型」的优势——与输入长度无关。
7. **Python 的 `reversed`**：返回的是迭代器，必须 `"".join(reversed(buf))` 才能得到 `str`；直接返回会类型错误。
8. **不要依赖前导零**：题面保证输入无前导零，但若把代码复用到「可能带前导零」的变体（如 LintCode 版），需要最后 `lstrip('0')` 并兜底 `"0"`。

## 5. 正确性证明

**引理 1（不变量）**：设两数最低 $t$ 位（不足补 0）组成的整数为 $A_t$、$B_t$，已写入的 $t$ 个数字按低位在前拼成的整数为 $S_t$，第 $t$ 轮结束后的进位为 $c_t$，则

$$A_t + B_t = S_t + c_t \cdot 10^t$$

**证明**：对 $t$ 归纳。

- $t = 0$：$A_0 = B_0 = S_0 = 0$，$c_0 = 0$，等式成立。
- 设 $t$ 时成立，第 $t+1$ 轮取出第 $t$ 位数字 $a_t$、$b_t$，有 $A_{t+1} = A_t + a_t 10^t$、$B_{t+1} = B_t + b_t 10^t$。令 $s = c_t + a_t + b_t$、$d = s \bmod 10$、$c_{t+1} = \lfloor s/10 \rfloor$，则

$$A_{t+1} + B_{t+1} = S_t + (c_t + a_t + b_t)10^t = S_t + d \cdot 10^t + c_{t+1}10^{t+1} = S_{t+1} + c_{t+1}10^{t+1}$$

其中最后一步用到 $S_{t+1} = S_t + d \cdot 10^t$（新数字被放在第 $t$ 位）与 $s = d + 10c_{t+1}$。归纳完成。∎

**引理 2（进位有界）**：对任意轮次，$c_t \in \{0, 1\}$。

**证明**：$c_0 = 0$。若 $c_t \le 1$，则 $s = c_t + a_t + b_t \le 1 + 9 + 9 = 19$，故 $c_{t+1} = \lfloor s/10 \rfloor \le 1$，且显然非负。由归纳得证。∎

**引理 3（终止与无冗余前导零）**：设 $m = \lvert\text{num1}\rvert$、$n = \lvert\text{num2}\rvert$。循环在 $t = \max(m, n)$ 且 $c_t = 0$ 时结束（若 $c_t = 1$ 则再多一轮写入 `'1'` 后结束）。结束时 $buf$ 反转即为 $A + B$ 的十进制表示，且不含多余前导零。

**证明**：当 $t \ge \max(m, n)$ 时两指针均已越界，循环的唯一继续理由是 `carry`，而由引理 2 只需再走一轮就把进位清空，故必然终止。终止时由引理 1 得 $A_t + B_t = S_t$，即写入的数字恰好是和的十进制各位。

再看前导零：反转后首位即**最后一轮**写入的数字。若最后一轮来自进位，该位是 `'1'`；否则它是最长串的最高位数字，题面保证该位非零且加上进位后 $s \in [1, 19]$，若 $s \ge 10$ 会再触发一轮写 `'1'`，故写入值仍非零。唯一例外是两数都为 `"0"`：此时 $s = 0$，只写入一个 `'0'`，恰好是正确结果。∎

**定理**：算法返回的字符串等于 `num1` 与 `num2` 所表示整数之和的十进制表示。

**证明**：由引理 3，返回串是精确和 $A + B$ 的十进制表示且无冗余前导零；十进制表示（无前导零）对每个非负整数唯一，故返回串正是题目要求的结果。∎

## 6. 复杂度分析

- **时间**：$O(\max(m, n))$。每轮循环把两个指针各推进至多一次，共 $\max(m, n)$ 轮，每轮常数次算术与一次 `push_back`/`append`，最后反转 $O(\max(m, n))$。
- **空间**：$O(\max(m, n))$，用于存放结果字符（最多 $\max(m, n) + 1$ 位）。除输出外只用了 `i`、`j`、`carry` 三个变量，辅助空间 $O(1)$。
- 与「转整型」对比：后者要么溢出，要么需要 $O(n)$ 甚至 $O(n \log n)$ 的大整数位运算，竖式是严格最优的量级。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    string addStrings(string num1, string num2) {
        int i = (int)num1.size() - 1, j = (int)num2.size() - 1;
        int carry = 0;
        string res;
        res.reserve(max(num1.size(), num2.size()) + 1);   // 最多多一位进位

        while (i >= 0 || j >= 0 || carry) {               // carry 必须进条件
            int sum = carry;
            if (i >= 0) sum += num1[i--] - '0';           // 越界位不参与
            if (j >= 0) sum += num2[j--] - '0';
            res.push_back(char('0' + sum % 10));          // 低位先入
            carry = sum / 10;                             // 只可能是 0 或 1
        }

        reverse(res.begin(), res.end());                  // 低位在前 → 反转
        return res;
    }
};
```

### Python

```python
class Solution:
    def addStrings(self, num1: str, num2: str) -> str:
        i, j = len(num1) - 1, len(num2) - 1
        carry = 0
        buf = []
        while i >= 0 or j >= 0 or carry:                 # carry 必须进条件
            s = carry
            if i >= 0:
                s += ord(num1[i]) - ord('0')             # 越界位不参与
                i -= 1
            if j >= 0:
                s += ord(num2[j]) - ord('0')
                j -= 1
            buf.append(chr(s % 10 + ord('0')))           # 低位先入
            carry = s // 10                              # 只可能是 0 或 1
        return ''.join(reversed(buf))                    # 低位在前 → 反转
```

## 8. 边界情况与易错点

1. **最高位进位**：`"1" + "9" = "10"`、`"9" + "9" = "18"`。循环条件漏掉 `carry` 会输出 `"0"` / `"8"`，是本场最集中的错误。
2. **长度悬殊**：`"1000" + "1" = "1001"`、`"1" + "9999999" = "10000000"`。短的串走完后指针越界，必须靠 `if` 判断而不是靠长度对齐。
3. **零加零**：`"0" + "0"`。循环至少执行一轮（因为 `i >= 0`），写入 `'0'`，输出 `"0"`；不会输出空串，也不会输出 `"00"`。
4. **大数溢出**：$10^4$ 位十进制远超 `unsigned long long`（约 $1.8 \times 10^{19}$）。任何「转整数」的尝试都会溢出或违反题意，别用 `stoll` / `atoi`。
5. **字符与数字混淆**：`'0'` 是 48。C++ 若写 `sum += num1[i]` 会得到 100 多；正确写法是 `num1[i] - '0'`。
6. **字符串拼接性能**：C++ 用头插构造会退化成 $O(n^2)$，$10^4$ 位虽不至于超时，但这是坏习惯；统一 `push_back` + `reverse`。
7. **返回值类型**：Python 里 `reversed()` 是迭代器，必须 `''.join(...)`；C++ 里 `reverse` 是原地修改且返回 `void`，不要写成 `return reverse(...)`。
8. **前导零的「隐性假设」**：本题输入保证无前导零，所以百位「越界按 0」与「补 `'0'`」等价；若复用到不保证的题面，结果需 `lstrip('0')`，并把空串兜底成 `"0"`。
