# LeetCode 太平洋大西洋水流问题 题解

## 1. 题目概述

- **标题 / 题号**：太平洋大西洋水流问题（#417，medium）
- **链接**：https://leetcode.cn/problems/pacific-atlantic-water-flow/
- **来源**：LeetCode 第 8 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、数组、矩阵

**题意**：给定 $m \times n$ 的高度矩阵 `heights`，上边界与左边界外是太平洋，下边界与右边界外是大西洋。水从某个格子可以流向上下左右四个相邻格子，前提是**相邻格子的高度不高于当前格子**（即 $h_{\text{next}} \le h_{\text{cur}}$，等高也可以流）。问哪些格子里的水**既能流入太平洋、又能流入大西洋**，返回这些格子的坐标列表。

**约束**：

- $m = \text{heights.length}$，$n = \text{heights}[i]\text{.length}$
- $1 \le m, n \le 200$
- $0 \le \text{heights}[r][c] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：heights = [[1,2,2,3,5],[3,2,3,4,4],[2,4,5,3,1],[6,7,1,4,5],[5,1,1,2,4]]
输出：[[0,4],[1,3],[1,4],[2,2],[3,0],[3,1],[4,0]]
解释：例如 (2,2)=5 有多条下坡路径分别通往左上角与右下角；
      (4,1)=1 虽然紧贴下边界、雨水直接进大西洋，但相邻的
      (4,0)=5 与 (3,1)=7 都比它高，水爬不上去，到不了太平洋。
```

**示例 2**

```text
输入：heights = [[2,1],[1,2]]
输出：[[0,0],[0,1],[1,0],[1,1]]
解释：四个格子都至少有一条路径流向两个海洋。
```

**示例 3**

```text
输入：heights = [[1]]
输出：[[0,0]]
解释：唯一的格子同时贴着上边界（太平洋）和下边界（大西洋）。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每个格子 $(r,c)$ 各做一次 DFS/BFS，顺流而下（只允许走向高度 $\le$ 当前格的邻居），看能否碰到上/左边界（太平洋）与下/右边界（大西洋）。

单次搜索 $O(mn)$，共 $mn$ 个格子，总时间 $O(m^2n^2)$。$m=n=200$ 时是 $1.6 \times 10^9$ 量级，Python 必然超时；而且这种写法把**同一片区域反复搜索了成千上万次**——如果两个格子共享一段下游路径，这段路径被走了两遍，信息完全浪费。

### 3.2 核心观察：把水流方向反过来

![核心观察：从海洋往高处爬](images/wc8_q3_reverse_climb_concept.svg)

水只能流向**不高于**自己的邻居。把每条相邻边看成一条有向边：$u \to v$ 存在当且仅当 $h_v \le h_u$。于是「从 $u$ 出发能否到达海洋」就是一个有向图可达性问题。

关键的一步是**反转视角**：把 $u \to v$ 反过来记为 $v \rightsquigarrow u$，条件是 $h_u \ge h_v$。同一条相邻关系，正着看是「下坡」，反着看就是「爬坡」，**存在性完全等价**。

> 💡 **一句话**：「$u$ 的水能流到海洋」$\iff$「从海洋出发、沿着 $h_{\text{next}} \ge h_{\text{cur}}$ 往上爬，能爬到 $u$」。

这样一来，「$mn$ 个起点各搜一次」就变成「**两条海岸线各搜一次**」：把上边界与左边界的所有格子作为太平洋侧的**多源起点**一起入队，反向扩展一次，就能标记出所有能流入太平洋的格子。大西洋侧同理。两个海洋各做一次，总时间降到 $O(mn)$。

### 3.3 算法流程

![算法流程：两次多源 BFS 取交集](images/wc8_q3_bfs_pipeline.svg)

1. 建立两个布尔矩阵 `seenP`、`seenA`（分别表示能流入太平洋 / 大西洋）。
2. 太平洋侧：把第 $0$ 行、第 $0$ 列的格子全部标记并入队；大西洋侧：把第 $m-1$ 行、第 $n-1$ 列的格子全部标记并入队。
3. 对每个队列做多源 BFS：取出 $(r,c)$，遍历四个邻居 $(nr,nc)$，若越界则跳过；若 `heights[nr][nc] >= heights[r][c]` 且该侧尚未标记，则标记并入队（**标记在入队时完成**，不是出队时）。
4. 两个 BFS 都结束后，扫描全图，把 `seenP[r][c] && seenA[r][c]` 的格子按行优先顺序收集起来即为答案。

### 3.4 示例演算

![示例演算：两个可达集合取交集](images/wc8_q3_example_walkthrough.svg)

以示例 1 的 $5\times5$ 矩阵为例，两个方向标记出的集合如下：

| 集合 | 大小 | 具体范围 |
|------|------|----------|
| `seenP` | 16 | 第 $0$ 行与第 $0$ 列共 9 格；再向高处爬出 $(1,1)(1,2)(1,3)(1,4)$、$(2,1)(2,2)$、$(3,1)$ |
| `seenA` | 16 | 第 $4$ 行与第 $4$ 列共 9 格；再向上爬出 $(3,0)(3,1)(3,2)(3,3)$、$(2,3)$、$(2,2)$、$(1,3)$ |
| 交集 | 7 | `[0,4] [1,3] [1,4] [2,2] [3,0] [3,1] [4,0]` |

注意 $16 + 16 - 7 = 25$ 恰好是格子总数：本例中**每个格子至少能流入一个海洋**，所以两个集合的并集覆盖全图，交集自然就是答案。

## 4. 算法细节

1. **起点集合去重**：角落格子同时属于两条边界（如 $(0,0)$ 既在第 $0$ 行又在第 $0$ 列）。入队前必须判 `seen`（或直接按「第 $0$ 行 + 第 $0$ 列从 $r=1$ 开始」构造），否则同一格会被压入队列两次，虽然不影响正确性，但会破坏「每格至多入队一次」的复杂度论证。
2. **单行 / 单列的退化写法**：$m=1$ 时第 $0$ 行既是上边界也是下边界，用 `range(1, m)` 构造左边界起点、`range(m-1)` 构造右边界起点可以自然处理这种情况，不需要额外特判。
3. **扩展条件必须是 $\ge$**：等高时水也能流过去，写成 `>` 会漏掉台地、平原这类数据（例如整片全为 $1$ 的矩阵会错误地返回空答案）。
4. **入队即标记**：如果等出队时再标记，同一格子会被多个邻居重复入队，最坏情况下队列规模退化为 $O(4mn)$ 个重复元素，虽然仍是常数因子，但白白浪费内存与时间。
5. **BFS 优于递归 DFS**：两者复杂度相同，但 $200\times200=40000$ 个格子的递归 DFS 在 Python 里会触发递归深度限制（默认 1000），C++ 里也要靠栈空间硬扛。多源 BFS 用显式队列，天然没有这个问题。
6. **两份标记表可压缩成一份**：用一个 `int` 矩阵记录位掩码（$1$ 表示太平洋、$2$ 表示大西洋），或者两次 BFS 共用一个 `visited` 数组并在结束时归零，空间从 $2mn$ 降到 $mn$。
7. **输出顺序无关**：题目接受任意顺序的答案；按行优先（$r$ 升序、$c$ 升序）输出最直观，也便于与暴力解对拍。

## 5. 正确性证明

**引理 1（反向边等价）**：对任意两个相邻格子 $u,v$，原图中的有向边 $u \to v$ 存在，当且仅当反向搜索中的边 $v \rightsquigarrow u$ 存在。

**证明**：$u \to v$ 存在 $\iff h_v \le h_u$；反向搜索允许从 $v$ 走向 $u$ $\iff h_u \ge h_v$。两个不等式互为同一条件，故等价。∎

**引理 2（可达性镜像）**：设 $S$ 为某个海洋边界上的格子集合。格子 $u$ 的水能沿合法下坡路径流入该海洋，当且仅当在反向搜索中从 $S$ 出发能到达 $u$。

**证明**：设原图路径 $u = x_0 \to x_1 \to \cdots \to x_k \in S$，则每步满足 $h_{x_{i+1}} \le h_{x_i}$。由引理 1，把这条路径反向即 $S \ni x_k \rightsquigarrow \cdots \rightsquigarrow x_0 = u$，反向搜索的每一步都合法，故可达。反之，若反向搜索给出 $x_k \rightsquigarrow \cdots \rightsquigarrow x_0 = u$，同样由引理 1 逐边翻转，就得到一条从 $u$ 到 $S$ 的合法下坡路径。∎

**引理 3（BFS 标记精确）**：一次多源 BFS 结束后，`seen[r][c]` 为真当且仅当 $(r,c)$ 在反向图中可从起点集合 $S$ 到达。

**证明**：起点全部被标记，对应距离 $0$ 的可达集。归纳假设第 $k$ 层处理完时，所有反向距离 $\le k$ 的格子都已被标记。出队一个距离为 $k$ 的格子时，算法遍历它所有满足 $h_{\text{next}} \ge h_{\text{cur}}$ 且未标记的邻居，正好把它们标记为距离 $k+1$，而距离 $\le k$ 的格子已标记，不会被重复计数。由 BFS 的正确性，队列清空时标记集合恰为可达集合。∎

**定理**：算法输出的坐标集合，恰好是所有「既能流入太平洋、又能流入大西洋」的格子。

**证明**：设 $(r,c)$ 是算法输出的一格，则 `seenP[r][c]` 与 `seenA[r][c]` 同为真。由引理 3，$(r,c)$ 在反向图中分别可从太平洋边界与大西洋边界到达；再由引理 2，$(r,c)$ 的水能流入两个海洋，故它确实属于答案。反之，若 $(r,c)$ 的水能流入两个海洋，由引理 2 它在反向图中可从两个边界集合到达，由引理 3 两个标记矩阵在该位置都为真，算法会把它收集进答案。两边互相包含，故输出集合与答案集合相等。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个格子最多入队一次，每次出队只检查 4 个邻居，两次多源 BFS 合计 $O(mn)$；最后的交集扫描再花 $O(mn)$。总计 $O(mn)$，常数约为 $8$ 次邻居访问。
- **空间**：$O(mn)$。两个布尔标记矩阵各占 $mn$，BFS 队列最坏同时存 $O(mn)$ 个坐标；若用位掩码合并标记表可降到 $mn$ 个整数。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <utility>
using namespace std;

class Solution {
public:
    vector<vector<int>> pacificAtlantic(vector<vector<int>>& heights) {
        int m = heights.size(), n = heights[0].size();
        const int dr[4] = {1, -1, 0, 0}, dc[4] = {0, 0, 1, -1};

        // 反向多源 BFS：从 starts 出发，只走向高度 >= 当前格的邻居
        auto bfs = [&](const vector<pair<int, int>>& starts) {
            vector<vector<char>> seen(m, vector<char>(n, 0));
            queue<pair<int, int>> q;
            for (auto& s : starts) {
                if (!seen[s.first][s.second]) {
                    seen[s.first][s.second] = 1;   // 入队即标记
                    q.push(s);
                }
            }
            while (!q.empty()) {
                auto [r, c] = q.front();
                q.pop();
                for (int d = 0; d < 4; d++) {
                    int nr = r + dr[d], nc = c + dc[d];
                    if (nr >= 0 && nr < m && nc >= 0 && nc < n && !seen[nr][nc]
                        && heights[nr][nc] >= heights[r][c]) {
                        seen[nr][nc] = 1;
                        q.push({nr, nc});
                    }
                }
            }
            return seen;
        };

        vector<pair<int, int>> pStart, aStart;
        for (int c = 0; c < n; c++) { pStart.push_back({0, c}); aStart.push_back({m - 1, c}); }
        for (int r = 1; r < m; r++) pStart.push_back({r, 0});
        for (int r = 0; r + 1 < m; r++) aStart.push_back({r, n - 1});

        auto pac = bfs(pStart), atl = bfs(aStart);
        vector<vector<int>> ans;
        for (int r = 0; r < m; r++)
            for (int c = 0; c < n; c++)
                if (pac[r][c] && atl[r][c]) ans.push_back({r, c});
        return ans;
    }
};
```

### Python

```python
from typing import List
from collections import deque


class Solution:
    def pacificAtlantic(self, heights: List[List[int]]) -> List[List[int]]:
        m, n = len(heights), len(heights[0])
        dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))

        def bfs(starts):
            seen = [[False] * n for _ in range(m)]
            q = deque()
            for r, c in starts:
                if not seen[r][c]:
                    seen[r][c] = True      # 入队即标记
                    q.append((r, c))
            while q:
                r, c = q.popleft()
                for dr, dc in dirs:
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < m and 0 <= nc < n and not seen[nr][nc] \
                            and heights[nr][nc] >= heights[r][c]:
                        seen[nr][nc] = True
                        q.append((nr, nc))
            return seen

        pac = bfs([(0, c) for c in range(n)] + [(r, 0) for r in range(1, m)])
        atl = bfs([(m - 1, c) for c in range(n)] + [(r, n - 1) for r in range(m - 1)])
        return [[r, c] for r in range(m) for c in range(n) if pac[r][c] and atl[r][c]]
```

## 8. 边界情况与易错点

1. **$1\times1$ 矩阵**：唯一的格子同时邻接两个海洋，必须返回 `[[0,0]]`；如果起点集合写成「第 0 行 + 第 0 列从 $r=1$ 开始」就不会重复入队，两个标记矩阵也都为真。
2. **单行 / 单列**：$m=1$ 时上边界与下边界重合，每个格子都能直接流入两个海洋，答案应为全部格子；$n=1$ 同理。这类数据能立刻暴露「起点集合构造错误」。
3. **全部等高**：整片区域连成一体，水在任意相邻格之间都能流，答案同样是全部格子；扩展条件写成 `>` 会误判成空集。
4. **低洼盆地**：如示例 1 的 $(4,1)=1$，贴着底边能入大西洋，但左右两侧都比它高，只能与 $(3,2)$、$(4,2)$ 互相连通，永远到不了太平洋——这是「贴边但不等于答案」的典型反例。
5. **递归 DFS 的栈深度**：$200\times200=40000$ 个等高格子会形成一条 40000 深的路径，Python 默认递归上限 1000 会直接 `RecursionError`，C++ 也可能爆栈；用 BFS 或显式栈。
6. **`pop(0)` 的隐性代价**：Python 里用 `list` 当队列、每次 `pop(0)` 是 $O(n)$ 搬移，整体会退化到 $O((mn)^2)$，必须用 `collections.deque`。
7. **越界判断的位置**：先判越界再判高度，否则会读到非法下标；四个方向用常量数组展开比四段 `if` 更不容易写错。
