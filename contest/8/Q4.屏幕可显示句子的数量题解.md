# LeetCode 屏幕可显示句子的数量 题解

## 1. 题目概述

- **标题 / 题号**：屏幕可显示句子的数量（#418，中等）
- **链接**：https://leetcode.cn/problems/sentence-screen-fitting/
- **来源**：LeetCode 第 8 场周赛 Q4
- **难度**：中等
- **标签**：数组、字符串、动态规划

**题意**：给定一块 $rows \times cols$ 的屏幕和一个非空单词表 `sentence`。从 `sentence` 的第一个单词开始，**按原顺序循环反复**地把单词铺到屏幕上：单词不能拆成两行；同一行里相邻两个单词之间恰好一个空格；当前行放不下下一个单词就换行，行尾剩余的格子留空。问整块屏幕最多能完整容纳多少遍 `sentence`。

**约束**：

- $1 \le rows, cols \le 20000$
- $1 \le \text{sentence.length} \le 100$，即 $n \le 100$
- $1 \le \text{sentence}[i].\text{length} \le 10$，单词非空

## 2. 示例

**示例 1**

```text
输入：rows = 2, cols = 8, sentence = ["hello", "world"]
输出：1
解释："hello world" 需要 5 + 1 + 5 = 11 列，一行放不下：
      hello---
      world---
      两行各放 1 个单词，共 2 个 = 恰好 1 遍句子。
```

**示例 2**

```text
输入：rows = 3, cols = 6, sentence = ["a", "bcd", "e"]
输出：2
解释：'-' 表示空格子：
      a-bcd-
      e-a---
      bcd-e-
      3 行共放下 6 个单词（a, bcd, e, a, bcd, e），6 / 3 = 2 遍。
```

**示例 3**

```text
输入：rows = 4, cols = 5, sentence = ["i", "had", "apple", "pie"]
输出：1
解释：
      i-had
      apple
      pie-i
      had--
      4 行共放下 6 个单词，只有前 4 个凑成 1 遍；
      末尾的 i、had 是第 2 遍的开头，不完整，所以答案是 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是维护「当前行已用列数」和「下一个要放的单词下标」，逐词尝试：放得下就放并加上空格，放不下就换行。这样做是对的，但代价有多大？单词长度至少为 1，且非行首的单词前面还要占 1 个空格，所以每行最多放约 $(cols+1)/2$ 个单词，整块屏幕要处理的单词总数最多约

$$rows \cdot \frac{cols+1}{2} \approx 2 \times 10^8$$

C++ 里 2 亿次简单判断勉强卡在时间线附近，Python 必然超时。另一条常见弯路是把句子拼成 $rows \cdot cols$ 那么长的字符串再扫描——字符数达 $4 \times 10^8$，空间直接爆掉。

### 3.2 核心观察：一行 = 一次由「行首下标」决定的状态转移

![核心观察：行首单词下标唯一决定这一行的放置结果](images/wc8_q4_row_state.svg)

固定行宽 `cols` 之后，**一行能放什么，只取决于这一行从句子第几个单词开始**：

1. 行内从空行开始，依次试放当前单词，放得下就放，直到下一个单词放不下为止；设这一行放下了 $k$ 个单词。
2. 下一个单词的下标是 $i + k$（句子循环，对 $n$ 取模），它就是下一行的行首。

于是每一行都被压缩成一次状态转移 $i \to (i + k_i) \bmod n$，并对总词数贡献 $k_i$。状态只有 $n \le 100$ 种，$k_i$ 与 `rows` 无关，可以一次性预处理成跳表 `jump[i]`。

由此得到两个直接结论：

- **总词数**：走完 `rows` 行后累计 $T = \sum k_{i_r}$；
- **答案**：铺出来的单词序列就是无限周期串 $W^\infty$ 的前缀，长度 $T$ 的前缀里完整包含 $W$ 的次数恰为 $\lfloor T / n \rfloor$。

> 💡 这一步把「按字符铺满 $4 \times 10^8$ 个格子」换成了「按单词跳跃 $2 \times 10^4$ 行」，规模下降四个数量级。

### 3.3 算法流程

![算法流程：预处理跳表 + 逐行 O(1) 跳跃](images/wc8_q4_flow.svg)

1. **前置检查**：若存在 `len(word) > cols`，这个单词永远放不进任何一行，直接返回 0（否则后面的模拟会原地打转）。
2. **预处理跳表**：对每个 $i \in [0, n)$，用滚动列指针 `used` 在行内贪心塞词，得到 `jump[i]` 与下一行行首 `(i + jump[i]) % n`。
3. **逐行跳跃**：`cur = 0, T = 0`，重复 `rows` 次：`k = jump[cur]; T += k; cur = (cur + k) % n`。
4. **输出**：$\lfloor T/n \rfloor$。

### 3.4 示例演算

![示例演算：sentence = [i, had, apple, pie]，rows = 4，cols = 5](images/wc8_q4_walkthrough.svg)

以示例 3 为例（$cols = 5$，$n = 4$），先预处理出跳表：

| 行首 $i$ | 这一行放下的内容 | 用掉列数 | $jump[i]$ | 下一行行首 |
|----------|------------------|----------|-----------|------------|
| 0 | `i had` | 5 | 2 | 2 |
| 1 | `had` | 3 | 1 | 2 |
| 2 | `apple` | 5 | 1 | 3 |
| 3 | `pie i` | 5 | 2 | 1 |

再跑 4 行：行首 0 放 `i had`（$k=2$），行首 2 放 `apple`（$k=1$），行首 3 放 `pie i`（$k=2$），行首 1 放 `had`（$k=1$），累计 $T = 2+1+2+1 = 6$。

最终 $\lfloor T/n \rfloor = \lfloor 6/4 \rfloor = 1$，与官方输出一致；末尾的 `i`、`had` 是第 2 遍的开头，凑不满一句。

## 4. 算法细节

1. **单词是原子**：不要用「每行能装多少字符」去近似，因为行尾的空格浪费、词间空格都不可预知；必须逐个单词判断，`need = len(w)`（行首）或 `len(w) + 1`（非行首）。
2. **前置检查不能省**：若某个 `len(word) > cols`，行内贪心一个词也放不下，`jump[i] = 0`，`cur = (cur + 0) % n` 会永远停在同一行 —— 死循环。必须先返回 0。
3. **累加总词数，而不是分段数句子**：句子会被行边界切断（示例 2 的第 2 遍是跨行拼起来的），用「放进去的单词总数」累加再做整数除法，比分段计数简单且不会漏。
4. **预处理只做一次**：`jump` 只与 `cols` 和词表有关，与 `rows` 无关。若把预处理写进 `rows` 循环，复杂度立刻退化回 $O(rows \cdot cols)$。
5. **下标取模**：`cur + k` 可能超过 $n-1$，必须 `% n`；Python 里写成 `sentence[(cur + k) % n]`，不要依赖负下标（负下标会静默取到列表尾部，错误极难发现）。
6. **整数范围**：$T \le rows \cdot \lceil (cols+1)/2 \rceil \approx 2 \times 10^8$，`int` 够用，但 C++ 用 `long long` 更稳；`T` 与 `n` 的除法是向下取整，正好是完整句子数。
7. **跳表的计算量**：对每个起点从头扫描，$O(n \cdot W)$，其中 $W \le (cols+1)/2 \le 10000$，$n \le 100$，最坏约 $10^6$ 次内循环，Python 也在百毫秒级。

## 5. 正确性证明

**引理 1（行内放置是唯一的贪心前缀）**：给定行首单词下标 $i$ 与列宽 `cols`，按「顺序、不拆词、相邻词一个空格、放不下就换行」的规则，本行放下的单词序列唯一，且就是从 $i$ 开始能放下的最长连续前缀，长度为 $jump[i]$。

**证明**：对该行中第 $m$ 个待放单词做归纳。前 $m-1$ 个单词放好后，已用列数是确定值（各词长度之和 + 词间空格数），于是第 $m$ 个词放不放只取决于它的长度与剩余列数，结果唯一。规则既不允许跳词也不允许拆词，所以放下的必然是连续前缀；一旦某个词放不下，后面的词只会更靠右、更放不下，故本行到此结束，长度为最长可行前缀。∎

**引理 2（状态转移正确）**：若某行以单词 $i$ 开头，则这一行放下 $jump[i]$ 个单词，且下一行以 $(i + jump[i]) \bmod n$ 开头。

**证明**：由引理 1，本行恰好放下 $i, i+1, \dots, i+jump[i]-1$ 这些单词；紧随其后的待放单词下标为 $i + jump[i]$，句子循环意味着对 $n$ 取模。∎

**引理 3（前缀计数）**：设屏幕上共放下 $T$ 个单词，则其中完整包含 `sentence` 的次数为 $\lfloor T/n \rfloor$。

**证明**：由引理 1、2，放下的单词序列严格等于无限周期串 $W^\infty$ 的前 $T$ 项（$W$ 为 `sentence`）。该前缀中第 $m$ 遍完整出现要求前 $mn$ 项都在其中，即 $mn \le T$，故完整遍数正是满足条件的最大 $m = \lfloor T/n \rfloor$。∎

**引理 4（模拟不变式）**：处理完 $r$ 行后，`T` 等于前 $r$ 行放下的单词总数，`cur` 等于第 $r+1$ 行的行首下标。

**证明**：$r = 0$ 时 `T = 0`、`cur = 0`，第 1 行确实从单词 0 开始，成立。设对 $r-1$ 成立，处理第 $r$ 行时 `k = jump[cur]`，由引理 2 这行放下 $k$ 个词、下一行行首为 `(cur + k) % n`；更新 `T += k`、`cur = (cur + k) % n` 后两条性质同时保持。∎

**定理**：算法返回的 $\lfloor T/n \rfloor$ 是屏幕能完整显示 `sentence` 的最大次数。

**证明**：由引理 4，`rows` 行走完后 `T` 就是按规则铺排放下的单词总数，再由引理 3 得完整遍数为 $\lfloor T/n \rfloor$。

还需说明「提前换行」不会得到更大的 $T$：若某行在还能放下一个词时提前换行，就相当于让下一行的行首提前 1 个单词。设从 $i-1$ 起放，放了首词后留给后缀可用列数不超过 $cols-2$，而列数更少能放下的单词数不会更多，故有

$$jump[i-1] \le jump[i] + 1$$

即「少放 1 个词」换来的后续每行收益至多 1 个词，与损失相抵，不会超过贪心的总词数。因此贪心铺排的 $T$ 已是最大值，答案正确。∎

## 6. 复杂度分析

- **时间**：预处理 $O(n \cdot W)$，其中 $W \le \lfloor (cols+1)/2 \rfloor$ 是一行最多能放的单词数（每个词至少 1 列，非行首还要 1 个空格）；模拟 $O(rows)$，每行 $O(1)$。合计 $O(n \cdot cols + rows)$，最坏约 $10^6 + 2\times10^4$ 次操作。
- **空间**：$O(n)$，只存 $n$ 个跳跃长度，与 `rows`、`cols` 无关；不需要构造屏幕或长字符串。

## 7. 参考代码

### C++

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int wordsTyping(vector<string>& sentence, int rows, int cols) {
        int n = (int)sentence.size();
        for (const string& w : sentence)
            if ((int)w.size() > cols) return 0;   // 永远放不进一行

        // jump[i]：从第 i 个单词开始，单独一行能放下多少个单词
        vector<int> jump(n, 0);
        for (int i = 0; i < n; ++i) {
            int used = 0, k = 0, idx = i;
            while (true) {
                int w = (int)sentence[idx % n].size();
                int need = (used == 0) ? w : w + 1;  // 行首不带前导空格
                if (used + need > cols) break;
                used += need;
                ++idx;
                ++k;
            }
            jump[i] = k;
        }

        long long total = 0;   // 已放下的单词总数
        int cur = 0;           // 下一行的行首单词下标
        for (int r = 0; r < rows; ++r) {
            int k = jump[cur];
            total += k;
            cur = (cur + k) % n;
        }
        return (int)(total / n);
    }
};
```

### Python

```python
from typing import List


class Solution:
    def wordsTyping(self, sentence: List[str], rows: int, cols: int) -> int:
        n = len(sentence)
        # 有单词比整行还长，它永远放不进去 -> 一句也放不完
        for w in sentence:
            if len(w) > cols:
                return 0

        # jump[i]：从句子第 i 个单词开始，单独一行能放下多少个单词
        jump = [0] * n
        for i in range(n):
            used = 0          # 当前行已占用列数（0 表示空行）
            k = 0
            idx = i
            while True:
                w = len(sentence[idx % n])
                need = w if used == 0 else w + 1   # 非行首单词前需要一个空格
                if used + need > cols:
                    break
                used += need
                idx += 1
                k += 1
            jump[i] = k

        total = 0                          # 已放下的单词总数
        cur = 0                            # 下一行的行首单词下标
        for _ in range(rows):
            k = jump[cur]
            total += k
            cur = (cur + k) % n
        return total // n
```

## 8. 边界情况与易错点

1. **单词比行宽还长**：如 `sentence = ["abcdef"]`、`cols = 4`，任何行都放不下，答案 0。必须先特判，否则模拟死循环。
2. **单列屏幕**：`cols = 1` 且所有单词长度都是 1 时，每行恰好 1 个词，答案 $rows / n$（向下取整）；若某个词长大于 1，答案直接是 0。
3. **单个单词的句子**：$n = 1$ 时 `cur` 永远为 0，$jump[0] = \lfloor (cols+1)/2 \rfloor$，答案即 $rows \cdot jump[0]$。
4. **空格也占列**：`"hello world"` 需要 11 列而不是 10 列；行尾多余格子既不能跨行复用，也不能拿来补词间空格。
5. **累加用整数除法**：$T$ 可能不是 $n$ 的倍数（示例 3 的 $T = 6$、$n = 4$），必须取 $\lfloor T/n \rfloor$ 向下取整，不能四舍五入或向上取整。
6. **下标越界**：C++ 里 `sentence[idx % n]` 的取模别写成 `sentence[idx]`；Python 的负下标不会报错，反而更隐蔽。
7. **大 `rows` 的极限**：`rows`、`cols` 都取 $20000$ 且词表全为 `"a"` 时 $T = 2 \times 10^8$，用 `int` 恰好够，但 `long long` 更保险；此时 `jump` 的值可达 $10000$，不要用 `char`、`short` 之类小类型存。

**延伸思考**：本题的 `rows` 只有 $2\times10^4$，所以逐行模拟就够。若 `rows` 放大到 $10^{18}$，状态转移 $i \to (i + jump[i]) \bmod n$ 是一张每个点出度为 1 的**函数图**，从 0 出发至多 $n$ 步就会进入一个长度 $\le n$ 的环；先把进入环前的词数与环内一圈的词数、环长算出来，就可以用除法把剩余行数 $O(1)$ 一次性跳完，整体变成 $O(n)$。另一种变形是「屏幕可以从任意单词开始铺」，此时要对每个起点各做一次预处理，或直接求每个状态沿转移走 `rows` 步的加权和——那就是标准的「路径加和 + 倍增」套路了。
