# LeetCode 等差三元组的数目 题解

## 1. 题目概述

- **标题 / 题号**：等差三元组的数目（#2367，easy）
- **链接**：https://leetcode.cn/problems/number-of-arithmetic-triplets/
- **来源**：LeetCode 第 305 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、枚举、双指针

**题意**：给定下标从 0 开始、**严格递增** 的整数数组 `nums` 和一个正整数 `diff`。若三元组 $(i, j, k)$ 满足 $i < j < k$ 且 $\text{nums}[j] - \text{nums}[i] = \text{diff}$、$\text{nums}[k] - \text{nums}[j] = \text{diff}$，则称其为 **等差三元组**。返回不同等差三元组的数目。

**约束**：

- $3 \le \text{nums.length} \le 200$
- $0 \le \text{nums}[i] \le 200$
- $1 \le \text{diff} \le 50$
- `nums` **严格**递增

> 💡 本题在本仓库另有[每日题解 2367](../../solution/2301-2400/2367_等差三元组的数目.md)：侧重「中项为锚」的直觉展开与面试问答。本篇按周赛复盘视角，侧重**赛场最短路径**、**正确性证明**与**边界清单**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,4,6,7,10], diff = 3
输出：2
解释：
(1, 2, 4) 是等差三元组：nums[2]−nums[1] = 4−1 = 3，nums[4]−nums[2] = 7−4 = 3
(2, 4, 5) 是等差三元组：nums[4]−nums[2] = 7−4 = 3，nums[5]−nums[4] = 10−7 = 3
```

**示例 2**

```text

输出：2
解释：
(0, 2, 4)：nums[2]−nums[0] = 6−4 = 2，nums[4]−nums[2] = 8−6 = 2
(1, 3, 5)：nums[3]−nums[1] = 7−5 = 2，nums[5]−nums[3] = 9−7 = 2
```

**示例 3**（自构造：最小规模恰一组）

```text
输入：nums = [0,3,6], diff = 3
输出：1
解释：n = 3 时唯一候选 (0,1,2)，公差恰为 3，计入。
```

**示例 4**（自构造：值对在场但凑不齐两端）

```text
输入：nums = [0,1,2,3,4], diff = 3
输出：0
解释：数组里有相距 3 的值对（0 与 3、1 与 4），但任何 x 的左右邻
从未同时在场（如 x=3 左邻 0 在、右邻 6 缺），输出 0。
```

## 3. 解题思路

### 3.1 暴力思路：三重循环

忠实枚举所有 $(i, j, k)$ 组合并逐个判定。$n \le 200$ 时约 $\binom{200}{3} \approx 1.3 \times 10^6$ 次比较，赛场直接交也能 AC。

但它把「值的存在性」拆成下标层面的逐对比较——明明只关心三个值 $x - \text{diff}$、$x$、$x + \text{diff}$ 在不在数组里，却遍历了所有下标组合，重复劳动。

### 3.2 核心观察：两个等式 = 一个三项等差数列，中项为锚

![核心观察：中项 x 一旦确定，两端值唯一确定](images/2367_mid_anchor_concept.svg)

两个等式合起来看，恰是「$\text{nums}[i], \text{nums}[j], \text{nums}[k]$ 构成公差为 $\text{diff}$ 的三项等差数列」。于是以**中项** $x = \text{nums}[j]$ 为锚：

$$\text{nums}[i] = x - \text{diff}, \qquad \text{nums}[k] = x + \text{diff}$$

中项一旦确定，两端值**唯一确定**——判定一组三元组从「两步搜索」压成**两次 $O(1)$ 哈希集合查询**：

$$\text{ans} = \sum_{x \in \text{nums}} \mathbb{1}\big[\, (x - \text{diff}) \in S \ \land\ (x + \text{diff}) \in S \,\big]$$

> 💡 **为什么「查到值」就等于「存在合法下标」？** 数组严格递增且 $\text{diff} \ge 1$，故 $x - \text{diff} < x < x + \text{diff}$；三个值若都在数组中，出现顺序必然是 $i < j < k$。且严格递增 ⇒ 值互异 ⇒ 每个中项 $x$ 至多贡献一组，**计数天然不重不漏**。

> ⚠️ 「严格递增」不是废话：它同时送出「值互异」（不重不漏）与「值序即下标序」（查到即合法）两个性质。若数组允许重复或乱序，存在性不再蕴含下标顺序，需改用三指针或「值 → 下标」映射。

### 3.3 算法流程

![算法流程：建集合 → 逐中项查两端 → 两端都在则计数](images/2367_hashset_flow.svg)

两阶段：① 一次遍历把所有值入集合 $S$（$O(n)$）；② 遍历每个 $x$ 作中项，$x - \text{diff}$ 与 $x + \text{diff}$ 都在 $S$ 则 `ans++`。建集合与查询分离，循环体里只有 $O(1)$ 操作。

### 3.4 示例演算

![示例演算：nums=[0,1,4,6,7,10]，diff=3，逐中项查两端](images/2367_example_walkthrough.svg)

对示例 1 逐中项核对（$S = \{0,1,4,6,7,10\}$，$\text{diff} = 3$）：

| 中项 $x$ | $x-3 \in S?$ | $x+3 \in S?$ | 贡献 |
|----------|--------------|--------------|------|
| 0 | $-3$ ✗ | $3$ ✗ | 0 |
| 1 | $-2$ ✗ | $4$ ✓ | 0（缺左邻） |
| **4** | $1$ ✓ | $7$ ✓ | **+1 → (1,2,4)** |
| 6 | $3$ ✗ | $9$ ✗ | 0 |
| **7** | $4$ ✓ | $10$ ✓ | **+1 → (2,4,5)** |
| 10 | $7$ ✓ | $13$ ✗ | 0（缺右邻） |

合计 $2$ 组 ✓。注意 $x=1$ 右邻在场但左邻缺失，$x=10$ 左邻在场但右邻缺失——**两端必须齐备，缺一不可**。

## 4. 算法细节

1. **建集合与查询分离**：先 `S = set(nums)` 建全再查，避免「边插边查」时漏掉位于 $x$ 之后的 $x + \text{diff}$。查询只与值相关、与下标无关，一次建全最稳。
2. **锚定中项而非端点**：枚举 $i$ 还需再搜 $j, k$ 两步；枚举中项 $x$ 一次定下两个伙伴值，且左右对称，代码最短。
3. **短路求值**：`x - diff in S and x + diff in S`——左邻不在时直接跳过右邻查询。
4. **值域小可换定长数组**：$0 \le \text{nums}[i] \le 200$，可用 `bool present[201]` 代替哈希集合，查询严格 $O(1)$、无哈希常数。但注意 $x - \text{diff}$ 可能为负（最小 $-50$）、$x + \text{diff}$ 可能超过 200（最大 250），**取下标前必须判越界**；哈希集合写法则天然安全。
5. **替代方案（三指针）**：数组有序，对每个 $i$ 维护 $j, k$ 单调不退同样 $O(n)$，但写法繁琐，签到题不值得。

## 5. 正确性证明

**引理 1**（值互异）：`nums` 严格递增 ⇒ 数组中任意两个值互不相同。

**证明**：若存在 $i < j$ 使 $\text{nums}[i] = \text{nums}[j]$，与严格递增（$i < j \Rightarrow \text{nums}[i] < \text{nums}[j]$）矛盾。∎

**引理 2**（存在即有序）：若 $x \in \text{nums}$ 且 $x - \text{diff}, x + \text{diff} \in \text{nums}$，则三者的下标 $i, j, k$ 满足 $i < j < k$。

**证明**：$\text{diff} \ge 1 > 0$，故 $x - \text{diff} < x < x + \text{diff}$。严格递增数组中值更小者下标更小，三个互异的值按下标排列的顺序与按值排列的顺序一致，即 $i < j < k$。∎

**定理**：设 $S$ 为 `nums` 的值集合，则等差三元组的数目恰为

$$\text{ans} = \#\{\, x \in \text{nums} : (x - \text{diff}) \in S \ \land\ (x + \text{diff}) \in S \,\}$$

**证明**：

- **不漏**：任取合法三元组 $(i, j, k)$，令 $x = \text{nums}[j]$。由两个等式知 $\text{nums}[i] = x - \text{diff}$、$\text{nums}[k] = x + \text{diff}$，故遍历到 $x$ 时必然计数。
- **不重**：由引理 1 值互异，中项值 $x$ 唯一对应下标 $j$，且 $x - \text{diff}$、$x + \text{diff}$ 各只出现一次，故对 $x$ 的计数唯一对应三元组 $(i, j, k)$；由引理 2 该三元组合法。不同合法三元组的中项值不同（$j$ 不同且值互异），不会重复计数。
- 反之，每次计数都由引理 2 对应一个合法三元组。

计数与目标一一对应，算法正确。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n)`。建集合一次 `O(n)`；遍历 $n$ 个中项，每次两次均摊 `O(1)` 哈希查询。
- **空间复杂度**：`O(n)`。哈希集合存全部 $n$ 个值；换 `bool present[201]` 则为 `O(V)`，$V = 201$，本题下可视作常数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int arithmeticTriplets(vector<int>& nums, int diff) {
        unordered_set<int> s(nums.begin(), nums.end());
        int ans = 0;
        for (int x : nums) {
            if (s.count(x - diff) && s.count(x + diff)) {
                ++ans;
            }
        }
        return ans;
    }
};
```

值域版（`bool` 数组替代哈希，注意越界防护）：

```cpp
class Solution {
public:
    int arithmeticTriplets(vector<int>& nums, int diff) {
        bool present[201] = {false};
        for (int v : nums) present[v] = true;
        int ans = 0;
        for (int x : nums) {
            int lo = x - diff, hi = x + diff;
            if (lo >= 0 && hi <= 200 && present[lo] && present[hi]) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def arithmeticTriplets(self, nums: List[int], diff: int) -> int:
        s = set(nums)
        return sum((x - diff in s) and (x + diff in s) for x in nums)
```

## 8. 边界情况与易错点

1. **最小规模**：`n = 3` 时恰有一个候选。如 `[0,3,6], diff=3` 输出 1；`[0,1,2], diff=3` 输出 0。
2. **越界值**：$x - \text{diff}$ 可为负（最小 $0 - 50 = -50$），$x + \text{diff}$ 可超过 200（最大 $250$）。哈希集合写法天然安全；`bool` 数组写法必须先判 `lo >= 0 && hi <= 200` 再取下标，否则未定义行为。
3. **「严格递增」要用足**：它同时提供「值互异」（计数不重不漏）与「值序即下标序」（查到即合法）。若允许重复，同一中项值可对应多个三元组，需改为三指针或「值 → 下标列表」。
4. **无需预处理**：数组已严格递增，不要画蛇添足地排序或去重；也无溢出风险（值域 $\le 200$，计数 $\le 200$）。
5. **暴力也能过，别恋战**：签到题目标是 30 秒内从题面到代码，`O(n)` 哈希写法与三重循环代码量相当，直接写干净版。
