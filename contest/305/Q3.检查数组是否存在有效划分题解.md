# LeetCode 检查数组是否存在有效划分 题解

## 1. 题目概述

- **标题 / 题号**：检查数组是否存在有效划分（#2369，medium）
- **链接**：https://leetcode.cn/problems/check-if-there-is-a-valid-partition-for-the-array/
- **来源**：LeetCode 第 305 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划

**题意**：给定下标从 0 开始的整数数组 `nums`，必须将其划分为一个或多个**连续**子数组，且每个子数组满足以下三条之一：

1. 恰由 **2 个相等**元素组成，如 `[2,2]`；
2. 恰由 **3 个相等**元素组成，如 `[4,4,4]`；
3. 恰由 **3 个连续递增**元素组成（相邻差**恰为 1**），如 `[3,4,5]`（`[1,3,5]` 不合法）。

若整个数组**至少存在一种**这样的划分，返回 `true`，否则返回 `false`。

**约束**：

- $2 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums[i]} \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums = [4,4,4,5,6]
输出：true
解释：划分为 [4,4] 和 [4,5,6]。
     [4,4]：2 个相等（条件①）
     [4,5,6]：3 连续递增差 1（条件③）
```

**示例 2**

```text
输入：nums = [1,1,1,2]
输出：false
解释：枚举所有切法——
     [1,1] + [1,2]：[1,2] 不等、长度又不足 3，非法
     [1,1,1] + [2]：剩单元素无法成段
     整段 [1,1,1,2]：长度 4，单段非法
```

**示例 3**（自构造：两种"顺切"贪心各翻一次车）

```text
输入：nums = [1,1,1,2,3]
输出：true
解释：唯一可行划分是 [1,1] + [1,2,3]（长度组合 2+3）。
     若贪心地"见三相等先切"：切出 [1,1,1] 后剩 [2,3]，无法成段 → 误判 false。

输入：nums = [1,1,1,1,2,3]
输出：true
解释：唯一可行划分是 [1,1,1] + [1,2,3]（长度组合 3+3）。
     若贪心地"见二相等先切"：切出 [1,1]、[1,1] 后剩 [2,3] → 误判 false。
```

## 3. 解题思路

### 3.1 暴力思路：回溯枚举每一刀，贪心救不了场

「划分 = 依次下刀」。最朴素的做法是**从左到右回溯**：每一刀只可能切出长度 2 或 3 的段（题面三类形态的长度分别为 2、3、3，别无其他），切出合法段就递归剩余后缀，任一分支走通即返回 `true`：

```text
dfs(i)：从下标 i 起的后缀能否有效划分
  i == n                                          → true
  i+2 ≤ n 且 nums[i]==nums[i+1] 且 dfs(i+2)       → true   // ①
  i+3 ≤ n 且 nums[i]==nums[i+1]==nums[i+2] 且 dfs(i+3) → true   // ②
  i+3 ≤ n 且 nums[i]+1==nums[i+1] 且 nums[i+1]+1==nums[i+2] 且 dfs(i+3) → true   // ③
  否则                                            → false
```

同一后缀 `dfs(i)` 会被不同切分路径反复调用，递归树规模按"长度 2/3 组合数"指数增长（最坏约 $2^{n/2}$ 量级），$n = 10^5$ 必然超时。

赛场上更诱人的捷径是**贪心**——从左往右"能切就切"。但示例 3 的两个自构造用例说明，**两个方向的贪心都有反例**：

| 策略 | 反例 | 贪心走法 | 正确划分 |
|------|------|----------|----------|
| 优先切 3 元段 | `[1,1,1,2,3]` | 切 `[1,1,1]` → 剩 `[2,3]` 死路 → 误判 false | `[1,1] + [1,2,3]` |
| 优先切 2 元段 | `[1,1,1,1,2,3]` | 切 `[1,1]`、`[1,1]` → 剩 `[2,3]` 死路 → 误判 false | `[1,1,1] + [1,2,3]` |

根子在于：**某一刀怎么切，要传导到几格之后才能看出生死**——局部信息不足以当场裁决，必须两条分支都保留。而保留全部分支又撞上大量**重复子问题**（同一个后缀被反复求解），这正是**动态规划**的入场信号。

### 3.2 核心观察：前缀可行性 DP——dp[i] 只回看 2 / 3 格

![核心观察：三类合法段与 dp[i] 的三条转移边，dp[i-1] 无边可走](images/2369_dp_transition_concept.svg)

把视角从「在哪里下刀」换到「**前 `i` 个元素整体能否被有效划分**」。定义：

$$\text{dp}[i] = \text{true} \iff \text{nums}[0..i)\ \text{存在有效划分}$$

由于任何有效划分的**末段长度只能是 2 或 3**，末段之前的剩余部分（长度为 $i-2$ 或 $i-3$ 的前缀）自身也必须是一个有效划分。于是 `dp[i]` 恰好由三条转移边决定：

$$\text{dp}[i] = \big(\text{dp}[i-2] \wedge \text{①}\big) \;\lor\; \big(\text{dp}[i-3] \wedge \text{②}\big) \;\lor\; \big(\text{dp}[i-3] \wedge \text{③}\big)$$

其中 ①②③ 表示末段 `nums[i-2..i)` / `nums[i-3..i)` 是否是对应类型的合法段。基准 $\text{dp}[0] = \text{true}$（空前缀 = 零个段的划分，条件对空集**空真**），答案即 $\text{dp}[n]$。

> 💡 **为什么不回看 dp[i−1]**：合法段最短长度为 2，长度 1 的末段永远非法，`dp[i-1]` 与 `dp[i]` 之间**不存在转移边**。窗口形状完全由「合法段长集合 $\{2,3\}$」决定——与 [139. 单词拆分](https://leetcode.cn/problems/word-break/) 的「字典词长有限」、[91. 解码方法](https://leetcode.cn/problems/decode-ways/) 的「末 1/2 位编码」同属「末段有限长度的前缀可行性 DP」家族。

### 3.3 算法流程：自底向上递推

![算法流程：初始化、主循环三连查、返回 dp[n]](images/2369_algorithm_flow.svg)

1. **初始化**：`dp[0] = true`，其余位置待填；
2. **主循环** `i` 从 $1$ 到 $n$，每步"三连查"：
   - 末 2 元素相等且 `dp[i-2]` 为真 → `dp[i] = true`；
   - 末 3 元素全相等且 `dp[i-3]` 为真 → `dp[i] = true`；
   - 末 3 元素差 1 递增且 `dp[i-3]` 为真 → `dp[i] = true`；
3. **返回** `dp[n]`。

每步至多 3 组 $O(1)$ 检查，全程一遍线性扫描，**一刀都不用真的试**。

### 3.4 示例演算

![示例演算：[4,4,4,5,6] 逐格填 dp，i=4 断档后 i=5 越过断档接力成功](images/2369_example_walkthrough.svg)

以示例 1 `nums = [4,4,4,5,6]` 逐格填表：

| i | 末段候选 | 三连查 | dp[i] |
|---|----------|--------|-------|
| 0 | —（空前缀） | 基准 | **T** |
| 1 | — | 长度不足 2，无段可成 | F |
| 2 | `[4,4]` | ① 4=4 ✓ ∧ dp[0]=T ✓ | **T** |
| 3 | `[4,4,4]` | ② 三相等 ✓ ∧ dp[0]=T ✓（① 路 dp[1]=F 不通） | **T** |
| 4 | `[4,5]` / `[4,4,5]` | ① 4≠5 ✗；② 不全等 ✗；③ 4,4,5 非连续递增 ✗ | F |
| 5 | `[4,5,6]` | ③ 连续递增 ✓ ∧ dp[2]=T ✓ | **T** |

回溯可行链：`dp[5]` ←(③ `[4,5,6]`) `dp[2]` ←(① `[4,4]`) `dp[0]`，得划分 `[4,4] + [4,5,6]`，返回 `true` ✓。

> 💡 注意 `i=4` 处 dp 一度**断档**（F），但最终答案仍为 true——`i=5` 经 ③ 接力到**两格之外**的 `dp[2]`。这正是 DP 对贪心的本质优势：**不要求每个前缀都可行，只要存在一条从 dp[0] 到 dp[n] 的可行链**。

## 4. 算法细节

1. **状态语义与下标差一**：`dp[i]` 对应**前 `i` 个元素**（`nums[0..i)`），末元素是 `nums[i-1]`。建议转移里的下标全部从 `i` 出发**倒着数**（`nums[i-2]`、`nums[i-3]`），不要一会儿正数一会儿倒数——这是本题最容易 off-by-one 的地方。
2. **空基准 dp[0] = true**：空前缀对应「零个段」的退化划分，「每个子数组都满足条件」对空集**空真**。它既是递归的出口，也是递推唯一的种子，漏掉则全表皆 F。
3. **越界防护**：条件① 需 `i ≥ 2`，条件②③ 需 `i ≥ 3`。主循环从 `i = 1` 起跑、在转移内加 guard，比"先特判 `i = 1, 2` 再开主循环"的写法更不易漏。
4. **条件③ 的两个相邻差**：必须判 `nums[i-3]+1 == nums[i-2]` **且** `nums[i-2]+1 == nums[i-1]`。只判首尾 `nums[i-3]+2 == nums[i-1]` 会被 `[1,3,3]` 这类"首尾凑巧、中间断裂"的段骗过。
5. **三类条件的逻辑关系**：对同一末段是「或」，命中任一即可；`else if` 短路只为省常数、不影响正确性。②③ 对同一段**互斥**（全相等的段不可能同时严格递增）。
6. **滚动数组**：`dp[i]` 只依赖 `dp[i-2]`、`dp[i-3]`（**不依赖 `dp[i-1]`**），但 `dp[i-1]` 会被下一轮 `dp[i+1]` 用到，故需滚动保留最近 3 个值：用 `(r, q, p) = (dp[i-3], dp[i-2], dp[i-1])`，每轮算出 `cur` 后整体左移，空间压到 $O(1)$。
7. **自顶向下备选**：记忆化 DFS 与递推等价、更贴近「切分」直觉，但 $n = 10^5$ 的输入会让递归深度达 $10^5$——Python 默认上限 1000 直接 `RecursionError`，C++ 也有栈溢出风险。赛场上**自底向上递推最稳**。

## 5. 正确性证明

**引理 1**（段长约束）：任何有效划分中，每段的长度属于 $\{2, 3\}$。

**证明**：有效划分要求每段满足题面三类形态之一，三类形态的长度分别为 2、3、3，故段长只能取自 $\{2,3\}$。∎

**引理 2**（末段切除与拼接）：对 $2 \le i \le n$、$k \in \{2,3\}$：

- (a) 若 `nums[0..i)` 存在有效划分且其末段长度为 $k$，则 `nums[0..i-k)` 存在有效划分（约定 $i = k$ 时的空前缀视为有效）；
- (b) 若 `nums[0..i-k)` 存在有效划分（含空前缀）且 `nums[i-k..i)` 是三类合法段之一，则 `nums[0..i)` 存在有效划分。

**证明**：(a) 去掉末段后，剩余各段仍是原划分中的段、依然各自满足条件，且连续无缝地覆盖 `nums[0..i-k)`；剩余为空时按约定有效（条件对空集空真）。(b) 把新段接在原划分末尾：各段仍满足条件之一，且段与段首尾相接、不重不漏地覆盖 `nums[0..i)`，是有效划分。∎

**定理**：对一切 $0 \le i \le n$，递推得到的 $\text{dp}[i] = \text{true}$ 当且仅当 `nums[0..i)` 存在有效划分。

**证明**：对 $i$ 强归纳。

- $i = 0$：`dp[0] = true`，对应空划分（空真），成立。
- 设结论对一切 $j < i$ 成立，考虑 $i \ge 1$：
  - **充分性**（转移命中 ⇒ 可划分）：设 `dp[i] = true` 由某条转移推得。若经①：`nums[i-2] == nums[i-1]` 且 `dp[i-2] = true`，由归纳假设 `nums[0..i-2)` 可有效划分，而末段 `nums[i-2..i)` 是 ① 类合法段，由引理 2(b)（$k=2$）得 `nums[0..i)` 可有效划分。经②③同理（$k=3$）。
  - **必要性**（可划分 ⇒ 转移命中）：设 `nums[0..i)` 存在有效划分。由引理 1 其末段长 $k \in \{2,3\}$，且该末段满足三类条件之一；由引理 2(a)，`nums[0..i-k)` 可有效划分（含空前缀情形），由归纳假设 `dp[i-k] = true`。于是对应转移的条件在末段上成立，`dp[i] = true`。∎

**推论**：算法返回 `dp[n]`，恰为整个数组是否存在有效划分的真值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。主循环 $n$ 步，每步至多 3 组比较 + 2 次布尔读表，单步转移 $O(1)$。对比暴力回溯的指数级（$n = 10^5$ 时天文数字）与记忆化 DFS 的 $O(n)$（但附带 $10^5$ 深递归栈的溢出风险）。
- **空间复杂度**：$O(n)$（`dp` 数组长 $n+1$）。注意到 `dp[i]` 只回看 2/3 格，用 3 个布尔变量滚动可压至 $O(1)$（见 §7 滚动版）。

## 7. 参考代码

### C++（线性 DP）

```cpp
class Solution {
public:
    bool validPartition(vector<int>& nums) {
        int n = nums.size();
        vector<char> dp(n + 1, 0);
        dp[0] = 1;  // 空前缀：零个段的退化划分
        for (int i = 1; i <= n; ++i) {
            if (i >= 2 && nums[i - 2] == nums[i - 1] && dp[i - 2])
                dp[i] = 1;  // ① 末 2 相等
            else if (i >= 3 && nums[i - 3] == nums[i - 2] && nums[i - 2] == nums[i - 1] && dp[i - 3])
                dp[i] = 1;  // ② 末 3 全等
            else if (i >= 3 && nums[i - 3] + 1 == nums[i - 2] && nums[i - 2] + 1 == nums[i - 1] && dp[i - 3])
                dp[i] = 1;  // ③ 末 3 差 1 递增
        }
        return dp[n];
    }
};
```

### C++（滚动变量，O(1) 空间）

```cpp
class Solution {
public:
    bool validPartition(vector<int>& nums) {
        int n = nums.size();
        bool r = false, q = false, p = true;  // dp[i-3], dp[i-2], dp[i-1]，p 即 dp[0]
        for (int i = 1; i <= n; ++i) {
            bool cur = false;
            if (i >= 2 && nums[i - 2] == nums[i - 1] && q)
                cur = true;  // ①
            else if (i >= 3 && nums[i - 3] == nums[i - 2] && nums[i - 2] == nums[i - 1] && r)
                cur = true;  // ②
            else if (i >= 3 && nums[i - 3] + 1 == nums[i - 2] && nums[i - 2] + 1 == nums[i - 1] && r)
                cur = true;  // ③
            r = q; q = p; p = cur;  // 整体左移一格
        }
        return p;  // 处理完 i=n 后 p 即 dp[n]
    }
};
```

> ⚠️ 滚动版的初始占位：`r`、`q` 的 `false` 是 `dp[-2]` / `dp[-1]` 的占位值，它们只在 `i ≥ 3` 的分支被读取，而那时已通过两轮左移把 `dp[0] = true` 送进 `r`——**垃圾值必须在其被读取前已被真实值覆盖**，这是滚动 DP 的通用校验点。

### Python

```python
class Solution:
    def validPartition(self, nums: List[int]) -> bool:
        n = len(nums)
        dp = [False] * (n + 1)
        dp[0] = True
        for i in range(1, n + 1):
            if i >= 2 and nums[i - 2] == nums[i - 1] and dp[i - 2]:
                dp[i] = True
            elif i >= 3 and nums[i - 3] == nums[i - 2] == nums[i - 1] and dp[i - 3]:
                dp[i] = True
            elif i >= 3 and nums[i - 3] + 1 == nums[i - 2] and nums[i - 2] + 1 == nums[i - 1] and dp[i - 3]:
                dp[i] = True
        return dp[n]
```

> 💡 Python 的链式比较 `a == b == c` 等价于 `a == b and b == c`。若偏好自顶向下，可写 `@lru_cache` 记忆化 DFS，但 $n = 10^5$ 会触发 `RecursionError`（默认上限 1000），需 `sys.setrecursionlimit` 且仍有栈风险——递推更稳。

## 8. 边界情况与易错点

1. **dp[0] = true 别漏**：空基准是唯一的种子，漏了全表皆 false，连示例 1 都过不了。
2. **越界 guard**：`i = 1, 2` 时不能读 `nums[i-3]`（`i = 2` 时是 `nums[-1]`）。主循环统一从 `i = 1` 起、转移内判 `i >= 2` / `i >= 3` 最不易漏。
3. **条件③的双差判定**：只判 `nums[i-3] + 2 == nums[i-1]` 会被 `[1,3,3]` 骗过（首尾差 2 但中间断裂）；两个相邻差必须都判。
4. **n = 2 的最小输入**：只有 `[x,x]` 返回 true，`[1,2]` 返回 false——验证代码没有依赖 `n ≥ 3` 的隐含假设。
5. **贪心冲动**：两个方向的"顺切"贪心都有反例（§3.1 的表）；赛场上凡是「当前刀法影响远处生死」的题，直接上 DP。
6. **记忆化爆栈**：$n = 10^5$ 的输入递归深 $10^5$，Python `RecursionError`（上限 1000）、C++ 逼近默认栈深；自底向上递推无此忧。
7. **滚动版占位值**：`r/q` 的初始 `false` 在 `i ≥ 3` 分支被读取前，已被两轮左移换成真实 dp 值；若改动段长集合（窗口变化），需重新核对覆盖时机。
8. **dp 与 nums 的下标差一**：`dp[i]` 的末元素是 `nums[i-1]`。推荐全部倒着数下标（`nums[i-2]`、`nums[i-3]`），混用两种数法最易写错。

**延伸思考**：

- 若要求**输出任一具体划分**：`dp` 之外加一张 `from[i]` 表记录「由哪类条件、来自哪个前缀」，从 `dp[n]` 反向跳回 `dp[0]` 即得各段边界，仍为 $O(n)$。
- 若合法段长集合改为 $\{2, 3, \dots, k\}$ 或「任意回文段」：转移边变多、回看窗口变长（回文情形需先预处理 `isPal[i][j]`，即 132 的做法），框架不变。
- 若把「每个子数组都满足条件」放宽为「至多一个子数组不满足」：加一维状态 `dp[i][j]`（前 `i` 个元素、已有 `j` 个坏段），从纯可行性升级为带计数的二维 DP。
