# LeetCode 超级回文数 题解

## 1. 题目概述

- **标题 / 题号**：超级回文数（#906，hard）
- **链接**：https://leetcode.cn/problems/super-palindromes/
- **来源**：LeetCode 第 102 场周赛 Q4
- **难度**：困难
- **标签**：数学、字符串、枚举

**题意**：若正整数 $x$ 本身是**回文数**，且 $x$ 还是某个**回文数**的平方，则称 $x$ 为**超级回文数**。给定两个以字符串表示的正整数 `left`、`right`，统计闭区间 $[left, right]$ 中超级回文数的个数。

**约束**：

- $1 \le left.length, right.length \le 18$
- `left`、`right` 只含数字，无前导零，表示的整数在 $[1, 10^{18}-1]$ 内
- $left \le right$

区间上界高达 $10^{18}$，暴力逐个判定不可能通过，必须反向思考：**超级回文数的根最多只有 $10^9$，而回文根更稀疏**。

## 2. 示例

**示例 1**

```text
输入：left = "4", right = "1000"
输出：4
解释：4 = 2²、9 = 3²、121 = 11²、484 = 22²，四个都满足「回文数」且「根也是回文数」。
      676 = 26² 是回文数，但 26 不是回文数，因此不算。
```

**示例 2**

```text
输入：left = "1", right = "2"
输出：1
解释：区间内只有 1 = 1² 是超级回文数。
```

**示例 3（上界压力）**

```text
输入：left = "1", right = "1000000000000000000"
输出：70
解释：整个 64 位范围内一共只有 70 个超级回文数，可见其稀疏程度。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：枚举 $x \in [left, right]$，判定 $x$ 是否回文，再开方判断根是否整数且回文。区间长度可达 $10^{18}$，即便每秒处理 $10^9$ 个数也要跑几十年，彻底不可行。

退一步：枚举**根** $p$，只需 $p \le \sqrt{right} \le 10^9$，再检查 $p$ 是回文、$p^2$ 是回文、$p^2$ 落在区间内。这已经把 $10^{18}$ 降到 $10^9$，但 $10^9$ 次「转字符串 + 反转比较」仍然太慢（约几十秒到几分钟），依然过不了。

### 3.2 核心观察：不回文直接跳过，只枚举回文根

![枚举「回文根」，反查它的平方](images/wc102_q4_root_enumeration_concept.svg)

关键观察是：**根 $p$ 必须是回文数**，而 $10^9$ 以内的回文数只有约 $1.1 \times 10^5$ 个（$1$ 位 $\sim$ $9$ 位各 $9, 9, 90, 90, 900, 900, \dots$ 个）。如果能**直接生成**这些回文数，而不是逐个判定，复杂度就降到 $10^5$ 量级。

生成方法：回文数由它的**前半部分**唯一确定。

- 取 `half` 的十进制串 $s$；
- **奇数位回文**：$s + \text{reverse}(s[0..|s|-2])$，例如 $s = \texttt{"12"}$ → `"121"`；
- **偶数位回文**：$s + \text{reverse}(s)$，例如 $s = \texttt{"12"}$ → `"1221"`。

$p \le 10^9$ 意味着回文长度不超过 9 位，即 `half` 不超过 5 位，所以 `half` 只需枚举到 $10^5$；每个 `half` 生成 2 个回文根，共约 $2\times 10^5$ 次「生成 + 平方 + 回文判定」，每次 $O(18)$，总量约 $4\times 10^6$ 次基本操作，毫秒级完成。

### 3.3 算法流程

![枚举回文根的流程](images/wc102_q4_algorithm_flow.svg)

```text
1. L = int(left), R = int(right)
2. ans = 0
3. for half = 1 .. 10^5:
4.     s = str(half)
5.     for p in { int(s + reverse(s[0..-2])), int(s + reverse(s)) }:
6.         若 p > 10^9: 跳过                     # p² 会超出 64 位
7.         sq = p * p
8.         若 sq < L 或 sq > R: 跳过
9.         若 sq 的十进制表示是回文: ans += 1
10. 返回 ans
```

第 5 行两种拼接分别覆盖**奇数位**与**偶数位**回文，长度不同，因此不会重复。

### 3.4 示例演算

![示例演算：left = 4，right = 1000](images/wc102_q4_walkthrough.svg)

对 $left = 4$、$right = 1000$：

| 回文根 $p$ | $p^2$ | $p^2$ 回文 | 落在 $[4,1000]$ | 计入 |
|------------|-------|------------|-----------------|------|
| 1 | 1 | ✓ | 否（$1 < 4$） | |
| 2 | 4 | ✓ | 是 | ✓ |
| 3 | 9 | ✓ | 是 | ✓ |
| 11 | 121 | ✓ | 是 | ✓ |
| 22 | 484 | ✓ | 是 | ✓ |
| 33 | 1089 | — | 否（$>1000$） | |

统计得 4。作为对照，$26^2 = 676$ 虽然是回文，但 26 本身不是回文，根本不会出现在我们的枚举序列里——这正是「只枚举回文根」的威力。

## 4. 算法细节

1. **枚举上界**：$p \le \sqrt{10^{18}-1} < 10^9$，对应 `half` 最多 5 位；循环写到 $10^5$ 即可，写 $10^9$ 会超时。
2. **整数范围**：$p \le 10^9$ 时 $p^2 \le 10^{18} < 2^{63}-1$，`long long` / Python `int` 都安全；但若把 `half` 上界写成 $10^6$，某些 $p$ 的平方会达到 $10^{22}$，C++ 会溢出。因此第 6 行的 `p > 1e9` 保护必须保留。
3. **两种拼接的分工**：`s + reverse(s[0..|s|-2])` 生成 $2|s|-1$ 位（奇数位），`s + reverse(s)` 生成 $2|s|$ 位（偶数位）。两者长度奇偶不同，天然不重复；`half = 1` 时奇数位得到 `"1"`、偶数位得到 `"11"`，都合法。
4. **字符串转整数**：C++ 用 `stoll`（$10^{18}$ 不会越界），Python 直接 `int()`。区间端点本身就是字符串，必须先转换再比较。
5. **回文判定**：统一转成十进制字符串后与反转串比较，比逐位取模更短、更不易错；本题数字最多 19 位，字符串开销可忽略。
6. **不需要 sqrt**：从根出发做平方是精确整数运算，避免了浮点 `sqrt` 的精度陷阱（$10^{18}$ 附近 `double` 只有约 15 位有效数字，`sqrt` 后取整容易错一位）。

## 5. 正确性证明

**引理 1（拼接的完备性与唯一性）**：对每个正整数 $p$，$p$ 是回文数当且仅当存在唯一的 `half` 与唯一的奇偶模式，使 $p$ 等于上述拼接结果。

**证明**：设 $p$ 的十进制串为 $t$，长度 $m$。

- 若 $m = 2k-1$ 为奇数，则回文条件等价于「后 $k-1$ 位是前 $k-1$ 位的逆序」，即 $t$ 由前 $k$ 位 $s$ 与 $\text{reverse}(s[0..k-2])$ 拼成，且 $s = t[0..k-1]$ 唯一。
- 若 $m = 2k$ 为偶数，同理 $t$ 由前 $k$ 位 $s$ 与 $\text{reverse}(s)$ 拼成，$s$ 唯一。

长度决定了奇偶模式，模式决定拼接公式，公式中的 $s$ 又被 $t$ 的前半唯一确定，故表示唯一。反过来，按任一公式拼出的串首尾对称，必是回文。∎

**引理 2（枚举范围充分）**：若 $x \in [left, right]$ 是超级回文数，则存在回文根 $p$ 满足 $p \le 10^9$ 且 $p^2 = x$，且该 $p$ 会被算法枚举到。

**证明**：由定义，$x = p^2$ 且 $p$ 回文。因 $x \le right < 10^{18}$，有 $p < 10^9$。$p$ 的十进制长度不超过 9 位，其前半 `half` 不超过 5 位即 `half < 10^5`，落在循环范围内；由引理 1，$p$ 必由该 `half` 的某一种拼接产生。∎

**引理 3（不重复计数）**：算法中同一个超级回文数不会被统计两次。

**证明**：由引理 1，每个回文根 $p$ 只对应一对 `(half, 模式)`；算法对每个 `(half, 模式)` 恰好生成一次 $p$、判定一次 $p^2$，因此每个 $p$ 至多被统计一次。又 $p^2$ 是单射，不同的 $p$ 给出不同的 $x$，故每个超级回文数至多计数一次。∎

**定理**：算法返回值等于 $[left, right]$ 中超级回文数的个数。

**证明**：由引理 2，区间内每个超级回文数都会被某个枚举项覆盖；由引理 3，每个至多被计数一次。另一方面，算法只在 $sq \in [left, right]$ 且 $sq$ 回文时计数，而 $sq = p^2$ 且 $p$ 由回文拼接得到（故 $p$ 回文），所以被计数的每个数都满足超级回文数的定义。两个方向合起来即为「恰好一次」，故计数等于区间内超级回文数个数。∎

## 6. 复杂度分析

- **时间**：$O(H \log R)$，其中 $H = 10^5$ 是 `half` 的枚举上界，$\log R \le 19$ 是回文判定的字符数。具体约 $2 \times 10^5$ 次「拼接 + 平方 + 判回文」，即 $4 \times 10^6$ 级别的基本操作，与区间大小无关——即使查询 $[1, 10^{18}]$ 也是同样的耗时。
- **空间**：$O(\log R)$。只用了若干个长度不超过 19 的字符串和常数个整数，与输入规模无关（输入是两个字符串，读取本身 $O(18)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int superpalindromesInRange(string left, string right) {
        long long L = stoll(left), R = stoll(right);
        int ans = 0;
        for (long long half = 1; half <= 100000; half++) {
            string s = to_string(half);
            for (int odd = 0; odd < 2; odd++) {
                string t = s;
                // odd = 1 生成奇数位回文：跳过 reverse 的第一个字符（即 s 的末位）
                string rev = s;
                reverse(rev.begin(), rev.end());
                t += rev.substr(odd ? 1 : 0);
                long long p = stoll(t);
                if (p > 1000000000LL) continue;       // p^2 会超出 long long 的可用范围
                long long sq = p * p;
                if (sq < L || sq > R) continue;
                string u = to_string(sq);
                string v = u;
                reverse(v.begin(), v.end());
                if (u == v) ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def superpalindromesInRange(self, left: str, right: str) -> int:
        L, R = int(left), int(right)
        ans = 0
        for half in range(1, 100001):
            s = str(half)
            for t in (s + s[-2::-1], s + s[::-1]):
                p = int(t)
                if p > 10 ** 9:
                    continue
                sq = p * p
                if sq < L or sq > R:
                    continue
                u = str(sq)
                if u == u[::-1]:
                    ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **`half` 上界写成 $10^9$**：等价于退化为枚举 $10^9$ 个整数，必然超时；正确上界是 $10^5$（5 位前缀）。
2. **`p > 1e9` 的保护**：`half` 取到 $10^5$ 时，奇数位拼接会得到 $10$ 位的 `1000000001`，其平方约为 $10^{18}$ 数量级偏大；虽然本题 `half ≤ 100000` 尚不至于溢出 `long long`，但保护语句能让代码对「把上界调大」的改动保持安全。
3. **`int` 溢出**：C++ 若把 `p` 或 `sq` 声明成 `int`，$p^2$ 在 $p > 46340$ 时立刻溢出，答案会莫名其妙变小。
4. **奇偶拼接写混**：奇数位是「跳过 reverse 的首字符」（`rev.substr(1)`），偶数位是「完整拼接」；写反会漏掉一半回文根。
5. **浮点开方**：不要用 `sqrt` 判根，$10^{18}$ 附近精度不够；本题从根出发平方，完全不需要开方。
6. **`left`/`right` 是字符串**：区间端点必须转成整数再比较，直接字符串比较会得到字典序（`"9" > "1000"`）。
7. **`676` 这类陷阱**：$676 = 26^2$，平方是回文但根不是，我们的枚举集合里不含 26，所以天然不会被误计——若改用「枚举区间内回文数再开方」的写法，就必须显式检查根的回文性。
8. **区间端点包含性**：题目是闭区间 $[left, right]$，判定用 `sq < L || sq > R` 跳过，等号必须算在内。
