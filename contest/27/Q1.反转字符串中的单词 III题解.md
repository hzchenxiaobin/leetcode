# LeetCode 反转字符串中的单词 III 题解

## 1. 题目概述

- **标题 / 题号**：反转字符串中的单词 III（#557，easy）
- **链接**：https://leetcode.cn/problems/reverse-words-in-a-string-iii/
- **来源**：LeetCode 第 27 场周赛 Q1
- **难度**：简单
- **标签**：双指针、字符串

**题意**：给定一个由若干个单词组成的句子 `s`（单词之间恰好一个空格、无首尾空格），**只把每个单词内部的字符顺序反转**，空格的数量与位置、以及单词的先后顺序都保持不变，返回处理后的字符串。

**约束**：

- $1 \le \lvert s \rvert \le 5 \times 10^4$
- `s` 只含可打印的 ASCII 字符
- `s` 不含任何开头或结尾空格，且至少含 1 个单词
- 所有单词之间用**单个空格**分隔

> 💡 签到题的胜负手在于「从题面到代码的最短路径」。本题的题眼是：**空格是不可移动的分界线**——它把整串切成若干互不干扰的区间，于是「整句处理」退化成「对每个区间各做一次反转」。

## 2. 示例

**示例 1**

```text
输入：s = "Let's take LeetCode contest"
输出："s'teL ekat edoCteeL tsetnoc"
解释：4 个单词各自反转：Let's→s'teL、take→ekat、LeetCode→edoCteeL、contest→tsetnoc；
      3 个空格仍在下标 5、10、19，单词顺序不变。
```

**示例 2**

```text
输入：s = "Mr Ding"
输出："rM gniD"
解释：Mr→rM、Ding→gniD，两个单词分别翻转一次。
```

**补充边界示例（非官方）**

```text
输入：s = "a"
输出："a"
解释：只有一个单字符单词，区间长度为奇数且为 1，一次交换都不做。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是借助语言内置的切分：`' '.join(w[::-1] for w in s.split(' '))`。它确实 $O(n)$ 且能过题，但它把「找到每个单词」这个核心步骤交给了库函数，还额外开辟了单词列表；一旦题目要求**原地**修改（如第 186 题的 $O(1)$ 额外空间版本），这套写法立刻失效。

另一种「真正的暴力」是逐字符构造答案：对输出位置 $k$ 回溯它来自原串的哪个字符，每个位置都要重新定位所在单词并数偏移，整体 $O(n^2)$。$n = 5\times 10^4$ 时约 $2.5\times 10^9$ 次操作，会超时；而且它没有利用「单词之间完全独立」这一结构。

### 3.2 核心观察：空格把整串切成互不干扰的区间

![核心观察：空格是天然分界，每个单词区间独立翻转](images/wc27_q1_word_interval_concept.svg)

设空格所在下标集合为 $P = \{p_1 < p_2 < \dots < p_m\}$，则 `s` 被切成 $m+1$ 个**极大非空格区间**（单词）：

$$[0, p_1),\quad [p_1+1, p_2),\quad \dots,\quad [p_m+1, n)$$

由于题目只要求「单词内部字符逆序」，而这个操作**只重排区间内部的字符**、绝不跨越区间边界，于是：

- 非空格字符始终留在原下标上，空格字符从不被交换 $\Rightarrow$ 输出长度、空格位置集合 $P$ 自动不变；
- 每个区间独立处理，互不影响 $\Rightarrow$ 单词的先后顺序自动保留。

换句话说，整题等价于 $m+1$ 个互相独立的「区间反转」子问题，可以单遍扫描顺次解决。区间反转的标准手法是**双指针对撞**：左指针 `l` 指向区间左端、右指针 `r` 指向右端，交换后各自内收一格，直到 `l >= r`，恰好做 $\lfloor L/2 \rfloor$ 次交换（$L$ 为单词长度）。

### 3.3 算法流程：单遍扫描 + 区间内对撞

![算法流程：先定单词右边界，再在区间内双指针翻转](images/wc27_q1_two_pointer_flow.svg)

```text
1. i ← 0
2. while i < n:
3.     j ← i
4.     while j < n 且 s[j] ≠ ' ':  j ← j + 1      # 现在 [i, j) 恰是一个单词
5.     l ← i, r ← j − 1
6.     while l < r:  swap(s[l], s[r]);  l ← l + 1;  r ← r − 1
7.     i ← j + 1                                  # 跳过这个单词后面的空格
8. 返回 s
```

- 第 4 行是「定右边界」：`j` 从 `i` 一路向右，遇到空格或越过末尾才停；
- 第 6 行是「区间内对撞」：只在 $[i, j)$ 内交换，绝不碰空格；
- 第 7 行让 `i` **单调递增**地跳到下一个单词的首字符，保证每轮互不重叠。

### 3.4 示例演算

![逐轮扫描走查：每轮只改动一个单词区间](images/wc27_q1_walkthrough.svg)

对 `s = "Let's take LeetCode contest"`（$n = 27$）逐轮走查：

| 轮次 | `i` | `j` | 翻转区间 | 翻转前 | 翻转后 | 交换次数 |
|------|-----|-----|----------|--------|--------|----------|
| 1 | 0 | 5 | $[0,5)$ | `Let's` | `s'teL` | 2 |
| 2 | 6 | 10 | $[6,10)$ | `take` | `ekat` | 2 |
| 3 | 11 | 19 | $[11,19)$ | `LeetCode` | `edoCteeL` | 4 |
| 4 | 20 | 27 | $[20,27)$ | `contest` | `tsetnoc` | 3 |

四轮结束后得到 `"s'teL ekat edoCteeL tsetnoc"`，与示例 1 一致；累计交换 11 次，恰好等于 $\sum_i \lfloor L_i/2 \rfloor$，每个成对位置只被处理一次，没有冗余交换。空格下标 5、10、19 在每一行都落在同一列，可直观确认「空格与单词顺序不变」。

示例 2 `"Mr Ding"` 同理：区间 $[0,2)$ 交换 1 次得 `rM`，区间 $[3,7)$ 交换 2 次得 `gniD`，输出 `"rM gniD"`。

## 4. 算法细节

1. **统一用半开区间 $[i, j)$**：`j` 的含义是「第一个空格的下标或 $n$」，它永远不是单词的一部分。翻转时用闭端点 `r = j - 1`，这样单字符单词会自然得到 `l == r`、循环零次，不需要额外特判。
2. **内层扫描必须带边界检查**：`while (j < n && s[j] != ' ')`。末尾单词后面没有空格，若漏写 `j < n` 就会越界读（C++ 中可能读到 `'\0'` 之后的内存）。
3. **`i` 必须跳到 `j + 1`**：写成 `i = j` 时，`j` 停在同一位置不动，单空格场景会死循环；写成 `i = j + 1` 时即使 `j == n`，`i` 也会变成 $n+1$ 让外层条件失败而安全退出（$n \le 5\times10^4$，`int` 不会溢出）。
4. **交换不含冗余**：对撞法对长度 $L$ 的单词恰好执行 $\lfloor L/2 \rfloor$ 次交换，每个成对位置 $(\text{原 } l,\ \text{原 } r)$ 只被处理一次，不会出现「换完再换回来」。严格意义上的最少交换数是「逆序后位置确实改变的成对位置个数」，回文单词（如 `"aba"`）可以 0 次；若追求这个更紧的最优，只需在交换前加一句 `if (a[l] != a[r])` 判断即可。
5. **空间策略分语言**：C++ 的签名是 `string s`（按值传入副本），可以直接在副本上原地交换，除返回值外零额外空间；Python 的 `str` 不可变，必须先 `list(s)` 再交换，最后 `''.join`，额外空间 $O(n)$。
6. **分隔符只认 `' '`**：撇号、数字、标点都属于单词的一部分（`Let's` 整体是一个单词），用 `isalpha()` 或按 `\w+` 切分会把 `Let's` 拆错，得到 `s'teL` 之外的结果。
7. **鲁棒性**：本题保证单词间恰好一个空格，但若出现连续空格，`i` 会落在空格上，此时区间为空、循环零次、`i` 前进 1，代码依然正确不崩——这是「用区间视角写代码」的附带好处。

## 5. 正确性证明

**引理 1（区间划分唯一）**：设空格下标为 $p_1 < \dots < p_m$，则 $[0,p_1), [p_1+1,p_2), \dots, [p_m+1,n)$ 两两不交，且其并集恰为 `s` 的全部非空格下标。

**证明**：相邻区间之间恰好隔着下标 $p_t$（空格），故不交；任取非空格下标 $k$，它必落在某个空格之间或首尾，即属于其中一个区间；空格下标 $p_t$ 不属于任何区间。∎

**引理 2（区间反转正确）**：对任意 $l \le r$，执行「`swap(a[l], a[r])` 后 `l++, r--`，直到 `l >= r`」后，子数组 `a[l..r]` 变为其原内容的逆序，区间外字符不变。

**证明**：对交换次数 $k$ 归纳。第 $k$ 次交换时指针为 $l+k$ 与 $r-k$，交换后这两个位置的值分别是原 `a[r-k]` 与 `a[l+k]`，正是逆序所需的取值；交换只涉及区间内下标，故区间外不变。循环终止时 $l+k \ge r-k$，即所有成对位置（共 $\lfloor L/2 \rfloor$ 对）都已就位；若 $L$ 为奇数，剩下的中心位置 $l+k = r-k$ 与自身配对，取值不变。∎

**引理 3（扫描不重不漏）**：外层每轮处理的下标区间恰好是一个单词；同一单词不会被两次处理；外层循环有限步终止。

**证明**：`i` 初值为 0，由约束「无开头空格」，下标 0 必为非空格，故第 1 轮 `[i, j)` 从非空格开始、到第一个空格或 $n$ 结束，正是首个单词。归纳：每轮结束时 `i = j + 1`；若 `j < n`，则 `j` 是空格，由「单词间恰一个空格」，`j+1` 要么是 $n$（末尾，循环结束）要么是非空格，于是下一轮同样得到一个完整单词。由于 `i` 每轮严格增大且上界为 $n+1$，外层至多 $m+1$ 轮后终止，故每个单词恰被处理一次。∎

**定理**：算法返回的字符串等于题目要求的答案。

**证明**：由引理 3，算法恰好对每个单词区间执行一次处理动作；由引理 2，该动作把区间内字符逆序、且不改变区间外任何位置；由引理 1，单词区间与空格位置构成整个字符串的不交划分，因此相邻单词之间的空格既未被读取为单词字符、也从未被交换，仍留在原下标。于是输出中每个单词是其原文的逆序、空格的数量与位置不变、单词顺序不变，且输出长度仍为 $n$——正是题目要求的唯一字符串。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`j` 在内层只向右移动、总计前进 $n$ 次；`i` 在外层单调递增、总计 $n$ 次；区间内交换总数为 $\sum \lfloor L_i/2 \rfloor \le n/2$。三者相加仍是 $O(n)$，平均到每个字符是常数次操作。
- **空间**：C++ 版 $O(1)$ 额外空间（输入按值传入，原地交换，只多两个下标变量）；Python 版 $O(n)$（`list(s)` 与 `join` 的缓冲区）。输出字符串本身占 $O(n)$，任何实现都无法避免。
- **对照 `split` 写法**：时间复杂度同为 $O(n)$，但要额外存 $O(n)$ 的单词列表与切片副本，且无法回答「要求原地」的追问。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string reverseWords(string s) {
        int n = (int)s.size();
        int i = 0;
        while (i < n) {
            int j = i;
            while (j < n && s[j] != ' ') j++;   // 单词右边界（开区间）
            int l = i, r = j - 1;               // 闭区间 [l, r] 对撞翻转
            while (l < r) {
                swap(s[l], s[r]);
                l++;
                r--;
            }
            i = j + 1;                          // 跳过单词后的空格
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def reverseWords(self, s: str) -> str:
        a = list(s)                      # str 不可变，先转成可写序列
        n = len(a)
        i = 0
        while i < n:
            j = i
            while j < n and a[j] != ' ':  # 扫描出当前单词的右边界
                j += 1
            l, r = i, j - 1               # 区间 [l, r] 双指针对撞
            while l < r:
                a[l], a[r] = a[r], a[l]
                l += 1
                r -= 1
            i = j + 1                     # 跳到下一个单词首字符
        return ''.join(a)
```

## 8. 边界情况与易错点

1. **单字符单词**：`"a"`、`"a b c"`。此时 `l == r`，交换循环必须零次；若误用 `do-while` 或先 `swap` 再判断，会把字符换没或越界。
2. **末尾单词没有空格收尾**：`"abc"`、`"hi there"` 的最后一个单词，`j` 只能停在 `n`。内层条件漏掉 `j < n` 是最常见的越界来源（C++ 中 `s[n]` 是 `'\0'`，再往后是未定义行为）。
3. **撇号与标点属于单词**：`"Let's"` 必须整体处理成 `"s'teL"`。用 `isalpha()`、`\w+` 或「非字母即分隔」的写法会把撇号当分隔符，答案错误。
4. **`i` 的推进方式**：必须 `i = j + 1`。写成 `i = j` 会在单空格情形下原地打转（`j` 恰好停在空格上），直接死循环超时。
5. **连续空格（题面外的输入）**：`"a  b"` 若被喂进来，`i` 落在第二个空格上时区间为空、循环零次，`i` 前进 1 后继续，结果仍是 `"a  b"`——不崩且空格保留，这是半开区间写法的额外鲁棒性。
6. **多字节字符**：约束限定可打印 ASCII，按字节交换才安全。若放开到 UTF-8（如中文），一个汉字占 3 字节，按字节对撞会把编码拆坏，必须按码点（`wstring` / Python 的字符）处理。
7. **长度合法但无单词**：约束保证至少 1 个单词且无首尾空格，故 `i` 首次一定落在字符上；若自行放宽到空串，外层循环不进入、返回空串，不会崩。
8. **不要额外写去空格逻辑**：本题空格必须原样保留，若顺手套用第 151 题的「压缩空格」步骤，`"a  b"` 类输入的空格数会被改写，反而是画蛇添足。
