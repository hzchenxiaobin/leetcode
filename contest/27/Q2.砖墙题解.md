# LeetCode 砖墙 题解

## 1. 题目概述

- **标题 / 题号**：砖墙（#554，medium）
- **链接**：https://leetcode.cn/problems/brick-wall/
- **来源**：LeetCode 第 27 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、前缀和

**题意**：给出 $n$ 行砖块，每行砖块高度相同、宽度不同，但**各行总宽度相等**（记总宽为 $W$）。要画一条**自顶向下贯穿整面墙**的竖线，求这条线**最少穿过多少块砖**。线若恰好沿两块砖之间的缝隙走，就不算穿过该行；但**不允许**沿墙的两条竖直边缘（$x=0$ 与 $x=W$）画线。

**约束**：

- $1 \le n \le 10^4$
- $1 \le \text{wall}[i].\text{length} \le 10^4$，且 $\sum_i \text{wall}[i].\text{length} \le 2 \times 10^4$
- 每行宽度之和相同
- $1 \le \text{wall}[i][j] \le 2^{31}-1$

> ⚠️ 注意：$O(n \cdot W)$ 的「按坐标开数组 / 逐格涂色」做法不可行——$W$ 可达 $2\times10^4 \times (2^{31}-1) \approx 4.3\times10^{13}$，只能对**出现过的缝隙坐标**做哈希统计。

## 2. 示例

**示例 1**

```text
输入：wall = [[1,2,2,1],[3,1,2],[1,3,2],[2,4],[3,1,2],[1,3,1,1]]
输出：2
解释：在 x = 4 处画线，只有第 1 行（砖宽 1,2,2,1）和第 4 行（砖宽 2,4）被穿过，
      其余 4 行都恰好在缝隙上，所以只穿过 2 块砖。
```

**示例 2**

```text
输入：wall = [[1],[1],[1]]
输出：3
解释：每行只有一块砖，墙内部没有任何缝隙，任何竖线都必然穿过全部 3 块砖。
```

**示例 3（补充，答案为 0）**

```text
输入：wall = [[1,2,3],[1,2,3]]
输出：0
解释：两行砖缝都落在 x = 1 与 x = 3，沿任一缝隙画线都不穿砖。
```

## 3. 解题思路

### 3.1 暴力思路

枚举竖线的横坐标 $x$，对每一行从左到右累加砖宽，判断 $x$ 落在哪块砖内部，统计穿过的砖数。

- 若枚举所有整数坐标：$O(W \cdot \sum_i m_i)$，$W$ 可到 $4.3\times10^{13}$，直接超时；
- 即使只枚举「缝隙坐标」（数量 $\le \sum_i m_i \le 2\times10^4$），逐行模拟仍是 $O\big((\sum m_i)^2\big) \approx 4\times10^8$，在 Python 下也不安全。

关键在于：**同一个缝隙坐标会被很多行共享**，逐行重复统计是浪费。

### 3.2 核心观察：把「缝隙」当成键做计数

![裂缝计数：最优竖线落在缝隙最密的坐标上](images/wc27_q2_gap_concept.svg)

每行砖的**右边界**就是该行砖宽的**前缀和**。设第 $i$ 行的前缀和集合为

$$P_i = \Bigl\{\,\sum_{k=0}^{j} \text{wall}[i][k] \;:\; 0 \le j < m_i \,\Bigr\}$$

其中 $j = m_i - 1$ 那一项等于 $W$，属于墙的边缘，**不能画线，必须排除**。于是定义

$$\mathrm{cnt}[x] = \#\{\, i : x \in P_i,\ x < W \,\}$$

表示「在 $x$ 处恰好有缝隙」的行数。因为竖线在 $x$ 处要么贴缝滑过某行、要么从砖心穿过某行，二者必居其一，所以

$$\text{在 } x \text{ 处穿过的砖数} = n - \mathrm{cnt}[x]$$

要让穿过的砖数最少，就要让 $\mathrm{cnt}[x]$ 最大：

$$\boxed{\;\text{答案} = n - \max_{1 \le x \le W-1} \mathrm{cnt}[x]\;}\qquad(\mathrm{cnt} \text{ 为空时约定 } \max = 0)$$

于是问题从「枚举线 × 遍历行」降维成「遍历每行的每个前缀和，丢进哈希表加一」，一次扫描即可。

> 💡 **为什么只需要考虑整数坐标**：砖宽都是正整数，所有缝隙坐标都是整数。若 $x$ 不是整数，它在每一行都严格落在某块砖内部，必然穿过全部 $n$ 行；而任何整数缝隙坐标处的穿过数都 $\le n$，故最小值一定在整数坐标处取得。

### 3.3 算法流程

![算法流程：一次扫描累计缝隙频次](images/wc27_q2_algorithm_flow.svg)

1. 记 $n = \text{wall.length}$，哈希表 `cnt` 置空；
2. 对每一行 `row`：令 `pos = 0`，只遍历**前 $m_i - 1$ 块**砖（跳过最后一块，因为它的右边界是墙边），累加得 `pos`，执行 `cnt[pos] += 1`；
3. 取 `cnt` 中的最大频次 `maxc`（`cnt` 为空时 `maxc = 0`）；
4. 返回 `n - maxc`。

整个过程对每块砖做 $O(1)$ 次哈希表操作，没有任何嵌套枚举。

### 3.4 示例演算

![示例演算：逐列统计 6 行的缝隙数](images/wc27_q2_walkthrough.svg)

以示例 1 为例，各行的内部缝隙坐标：

| 行 | 砖宽 | 内部缝隙 |
|----|------|----------|
| 1 | 1,2,2,1 | 1, 3, 5 |
| 2 | 3,1,2 | 3, 4 |
| 3 | 1,3,2 | 1, 4 |
| 4 | 2,4 | 2 |
| 5 | 3,1,2 | 3, 4 |
| 6 | 1,3,1,1 | 1, 4, 5 |

按坐标汇总：$\mathrm{cnt}[1]=3$、$\mathrm{cnt}[2]=1$、$\mathrm{cnt}[3]=3$、$\mathrm{cnt}[4]=4$、$\mathrm{cnt}[5]=2$。

最大频次是 $\mathrm{cnt}[4]=4$，故答案 $= 6 - 4 = 2$：在 $x=4$ 处画线，只穿过第 1、4 两行。

## 4. 算法细节

1. **只累计到倒数第二块砖**：写成 `for j in range(len(row) - 1)` / `for (size_t j = 0; j + 1 < row.size(); ++j)`，把最后一块砖的右边界（$=W$）排除掉。这是本题最容易写错的一点——若把 $W$ 也计入，会有 $n$ 行都「贴缝」，`maxc` 变成 $n$，答案错成 0。
2. **坐标类型用 64 位**：单块砖宽可达 $2^{31}-1$，前缀和可达 $4.3\times10^{13}$，C++ 必须用 `long long` 存 `pos` 与哈希键；用 `int` 会静默溢出，得到错误的缝隙坐标并互相覆盖。
3. **必须用哈希表而非数组**：坐标值域是 $10^{13}$ 级，但**不同坐标的个数**只有 $O(\sum_i m_i) \le 2\times10^4$ 个，正好是哈希表的规模。C++ 可 `reserve(20000)` 减少 rehash。
4. **空表取 max 要兜底**：Python 用 `max(cnt.values(), default=0)`（否则空序列抛 `ValueError`）；C++ 用一个初值为 0 的 `best` 变量边遍历边取 `max`。
5. **一行内的前缀和天然互不相同**：砖宽 $\ge 1$，前缀和严格递增，所以同一行不会对同一坐标重复计数，无需去重。
6. **累加顺序即全部代价**：每行只需一次线性扫描，不需要排序、二分或任何预处理；总操作数等于砖块总数 $2\times10^4$。

## 5. 正确性证明

**引理 1（穿砖数公式）**：对任意 $1 \le x \le W-1$，记 $c(x) = \#\{\,i : x \in P_i\,\}$，则「在 $x$ 处画线穿过的砖数」恰为 $n - c(x)$。

**证明**：固定一行 $i$，其 $m_i$ 块砖把 $[0, W]$ 划成左闭右开区间 $[p_{j-1}, p_j)$，其中 $p_0 = 0 < p_1 < \cdots < p_{m_i} = W$。由 $0 < x < W$，$x$ 落在唯一一个区间 $[p_{j-1}, p_j)$ 内。

- 若 $x = p_{j-1}$ 且 $j \ge 2$，则 $x$ 是该行的一条内部缝隙，竖线只擦过砖的边界，**不穿过**这一行的砖；
- 否则 $x \in (p_{j-1}, p_j)$ 严格位于砖内部（$x = p_0 = 0$ 不可能，因为 $x \ge 1$），线**穿过**这一行的这块砖。

两种情况互斥且穷尽，故第 $i$ 行被穿过 $\iff x \notin P_i$。对所有行求和，穿过的行数 $= n - c(x)$。∎

**引理 2（只需考虑整数坐标）**：若 $x \notin \mathbb{Z}$，则线穿过全部 $n$ 块砖；故最优解可在整数坐标处取得。

**证明**：每行的前缀和都是整数，故内部缝隙坐标都是整数。非整数 $x$ 不等于任何 $p_j$，于是对每一行都有 $x \in (p_{j-1}, p_j)$，由引理 1 的第二种情况该行必被穿过，合计 $n$ 块。另一方面，取 $x = 1$，由引理 1 穿过数为 $n - c(1) \le n$，故最小值不超过 $n$，不可能由非整数坐标取得。∎

**引理 3（无内部缝隙时答案为 $n$）**：若每行都只有一块砖，则答案为 $n$；此时 `cnt` 为空、`maxc = 0`，公式仍给出 $n$。

**证明**：每行只有一块砖时 $P_i = \{W\}$，对任意 $1 \le x \le W-1$ 都有 $x \notin P_i$，由引理 1 每一行都被穿过，共 $n$ 块；恰好没有竖线能贴缝，故 $n$ 即最小值。公式侧：`cnt` 中没有键，`maxc` 兜底为 0，返回值 $n - 0 = n$，两者一致。∎

**定理（算法正确）**：设 $\textit{maxc} = \max_{1 \le x \le W-1} c(x)$（无内部缝隙时取 0），则算法返回的 $n - \textit{maxc}$ 等于画一条合法竖线所能穿过的**最少**砖块数。

**证明**：由引理 2，最优线可在整数坐标处取得；题面禁止沿 $x=0$、$x=W$ 画线，故合法候选正是整数 $x \in [1, W-1]$。由引理 1，这些位置上的穿过数为 $n - c(x)$，最小化它等价于最大化 $c(x)$，最大值即 $\textit{maxc}$。算法对每行的每块砖（最后一块的右边界 $W$ 除外）累加前缀和并 `cnt[pos] += 1`，恰好统计了所有 $c(x)$ 的非零取值，因此 $\textit{maxc}$ 计算无误，返回值就是 $\min_x \bigl(n - c(x)\bigr)$。若不存在内部缝隙，引理 3 保证返回值仍为 $n$。∎

## 6. 复杂度分析

- **时间**：$O\!\left(\sum_i m_i\right)$。每行的每块砖（最后一块除外）做一次加法与一次哈希表自增，平均 $O(1)$；总计不超过 $2\times10^4$ 次操作，取最大值再扫描一遍哈希表同样不超过 $2\times10^4$ 次。
- **空间**：$O\!\left(\sum_i m_i\right)$。哈希表中最多存入「所有行所有内部前缀和」的去重结果，不超过 $\sum_i (m_i - 1) \le 2\times10^4$ 个键；除此之外只有常数个变量。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int leastBricks(vector<vector<int>>& wall) {
        unordered_map<long long, int> cnt;      // 缝隙坐标 -> 该处有缝隙的行数
        cnt.reserve(20000);                     // 不同坐标数 <= 2*10^4，避免 rehash
        for (const auto& row : wall) {
            long long pos = 0;                  // 前缀和可达 4.3e13，必须 64 位
            for (size_t j = 0; j + 1 < row.size(); ++j) {
                pos += row[j];                  // 跳过最后一块砖：其右边界是墙边
                ++cnt[pos];
            }
        }
        int best = 0;                           // cnt 为空（每行只有一块砖）时保持 0
        for (const auto& kv : cnt) best = max(best, kv.second);
        return static_cast<int>(wall.size()) - best;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def leastBricks(self, wall: List[List[int]]) -> int:
        cnt = {}
        for row in wall:
            pos = 0
            # row[:-1]：最后一块砖的右边界就是墙的边缘，不能画线，直接跳过
            for w in row[:-1]:
                pos += w
                cnt[pos] = cnt.get(pos, 0) + 1
        # 每行只有一块砖时 cnt 为空，max 兜底为 0
        return len(wall) - max(cnt.values(), default=0)
```

## 8. 边界情况与易错点

1. **每行只有一块砖**（示例 2）：内部缝隙集合为空，`cnt` 为空表，必须让最大值兜底为 0，答案是 $n$；直接调 `max(cnt.values())` 会崩，或用数组实现会误判成 0。
2. **把墙边缘算进缝隙**：只写 `for w in row:` 会把 $W$ 也统计进去，所有行都「贴缝」，答案恒为 0。必须显式跳过最后一块砖（或在循环里判 `pos < W`）。
3. **前缀和溢出**：`int` 存 `pos` 在极端数据（砖宽 $2^{31}-1$、行内多块砖）下溢出，导致不同坐标被折叠成同一个键、答案偏小。C++ 用 `long long`（Python 无此问题）。
4. **按坐标开数组**：$W$ 最高约 $4.3\times10^{13}$，`vector<int>(W+1)` 立刻 MLE/无法分配；只能用哈希表，规模由上界 $\sum_i m_i$ 控制。
5. **答案下界为 0**：若所有行砖缝完全重合（如 `[[1,2,3],[1,2,3]]`），返回 0 是合法结果，不要画蛇添足地 `max(1, ...)`。
6. **不要排序后再统计**：把 $\sum_i m_i$ 个前缀和收集起来排序也能算频次，但要多付 $O(k\log k)$ 的代价；直接哈希计数即可，且天然无需去重（行内前缀和严格递增）。

**延伸思考**：

1. 若允许沿墙的边缘画线，答案直接是 0，题目就退化了——**正是「禁止沿边缘」这条限制**让「边缘必须排除」成为本题的核心陷阱。
2. 若砖块高度不等（每行起点错开），竖线穿过的砖块数不再等于 $n - \mathrm{cnt}[x]$，而要按行区间做「区间覆盖计数」，需要扫描线或差分数组。
3. 若把竖线放宽为**任意斜线**，问题就变成「用一条直线穿过最少矩形」，通常只能靠几何对偶 + 枚举拐点，复杂度远高于本题——这也是本题被设计成「自顶向下的竖线」的原因：把二维几何压成一维计数。
