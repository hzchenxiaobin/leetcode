# LeetCode 将字符串拆分为若干长度为 k 的组 题解

## 1. 题目概述

- **标题 / 题号**：将字符串拆分为若干长度为 k 的组（#2138，easy）
- **链接**：https://leetcode.cn/problems/divide-a-string-into-groups-of-size-k/
- **来源**：LeetCode 第 276 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定字符串 `s`、组长 `k` 与填充字符 `fill`，把 `s` **自左向右**切成若干长度为 `k` 的组：第 $i$ 组取第 $ik$ 到第 $(i+1)k$ 个字符；**仅末组**可能不足 $k$ 个，用 `fill` 补在**尾部**凑满。返回所有组组成的字符串数组。约束「去掉末组填充后按序连接应还原 `s`」意味着：填充只发生在末组、且只补在尾部。

**约束**：

- $1 \leq n = \text{s.length} \leq 100$
- `s` 仅由小写英文字母组成
- $1 \leq k \leq 100$
- `fill` 是一个小写英文字母

> 💡 本题在本仓库另有[每日题解 2138](../../solution/2101-2200/2138_将字符串拆分为若干长度为k的组.md)：主线同为「步长切片 + 末组填充」。本篇按**周赛复盘视角**展开：给出组数 $\lceil n/k \rceil$ 的引理-定理完整证明、填充量 $(k - n \bmod k) \bmod k$ 与负取模 $-n \bmod k$ 的两套写法、`ljust` 语义级 API 的最短代码，以及「整除时多补一整组」等赛场高频翻车点。同场 Q3（#2140 解决智力问题，倒序线性 DP）与 Q4（#2141 同时运行 N 台电脑的最长时间，二分答案 + 贪心验证）才是本场主菜。

## 2. 示例

**示例 1**

```text
输入：s = "abcdefghi", k = 3, fill = 'x'
输出：["abc","def","ghi"]
解释：n = 9 恰为 3 的整倍数，3 组各 3 字符，填充量 (3 − 9 mod 3) mod 3 = 0，零填充。
```

**示例 2**

```text
输入：s = "abcdefghij", k = 3, fill = 'x'
输出：["abc","def","ghi","jxx"]
解释：n = 10，组数 ⌈10/3⌉ = 4；末组只剩 r = 10 mod 3 = 1 个字符 'j'，
      补 k − r = 2 个 'x' 凑成 "jxx"。
```

**示例 3（k > n，单组退化）**

```text
输入：s = "abc", k = 5, fill = 'x'
输出：["abcxx"]
解释：n = 3 < k，只切出一组：3 个原字符 + (k − n) = 2 个填充，无需任何特判。
```

**示例 4（k = 1）**

```text
输入：s = "x", k = 1, fill = 'x'
输出：["x"]
解释：n mod 1 = 0 恒成立，每组恰好 1 字符，永不填充。
```

## 3. 解题思路

### 3.1 暴力思路：逐字符累加缓冲区

维护缓冲区 `buf` 与计数器，逐字符塞入 `buf`，凑满 $k$ 个就输出一组并清空；扫完后若 `buf` 非空，补 `fill` 再输出。

- **正确性**：与题意逐句对应，完全正确，$O(n)$ 也能过。
- **不足**：引入了「计数器 + 清空时机 + 末尾补齐分支」三处状态，签到题里多一处状态就多一分 WA 风险。定长分组的本质是**等间距切片**——起点就是 $0, k, 2k, \dots$，根本不需要逐字符累积。

> ⚠️ 周赛 Q1 比的不是复杂度（$n \leq 100$ 怎么写都过），而是**从题面到无 bug 代码的最短路径**：状态越少、分支越少，交得越快越稳。识别出「等间距」结构，一步就从字符级状态机跳到组级循环。

### 3.2 核心观察：等间距切片，末组是唯一的「短组」

![核心观察：等间距切片，末组是唯一的短组](images/2138_groups_concept.svg)

第 $i$ 组（从 0 起）对应原串下标区间 $[ik,\ \min((i+1)k,\ n))$。于是三件事全部公式化：

- **组数** $m = \lceil n/k \rceil$；
- **前 $\lfloor n/k \rfloor$ 组**长度恰为 $k$，切片越界截断对它们不生效；
- **填充量** $(k - n \bmod k) \bmod k$——整除时为 $0$，否则为 $k - r$（$r = n \bmod k$）。数学上这正是最小非负剩余 $(-n) \bmod k$。

> 💡 **负取模技巧**：Python 的 `%` 恒返回非负结果，`fill * (-n % k)` 一行算出填充量且整除时自动为 $0$；C++/Java 的 `%` 向零取整，`-n % k` 会得到**非正数**，照抄即错，必须写 `(k - n % k) % k`。同一个数学式在两门语言里长相不同，这是本题最值得沉淀的语言细节。

### 3.3 算法流程

![算法流程：步长 k 切片与末组按需填充](images/2138_groups_flow.svg)

1. `res = []`，起点 `i = 0`。
2. 循环（步长 `k`）：当 `i < n` 时——
   - `g = s[i : i+k]`（Python 切片 / C++ `substr(i, k)` 越界自动截断）；
   - 若 `len(g) < k`，在 `g` **尾部**补 `fill × (k − len(g))`；
   - `res.append(g)`，`i += k`。
3. 返回 `res`。

两版实现等价：**按需填充版**（循环内一个判定）与**预补齐版**（先把整串补成 $k$ 的整倍数 `s += fill × (−n mod k)`，循环内零分支）。后者把「末组特判」前移为一次预处理，是「用预处理消灭特例」的常用手法。

### 3.4 示例演算

![示例走查：四组切片与两个边界对照](images/2138_groups_walkthrough.svg)

以示例 2 `s = "abcdefghij", k = 3, fill = 'x'`（$n = 10$）走查：

| 步 | `i` | `s[i:i+3]` | 长度 | 补 fill | 组结果 | res 累积 |
|----|-----|------------|------|---------|--------|----------|
| 1 | 0 | `"abc"` | 3 | — | `"abc"` | `["abc"]` |
| 2 | 3 | `"def"` | 3 | — | `"def"` | `["abc","def"]` |
| 3 | 6 | `"ghi"` | 3 | — | `"ghi"` | `["abc","def","ghi"]` |
| 4 | 9 | `"j"`（截断） | 1 | `+"xx"` | `"jxx"` | `["abc","def","ghi","jxx"]` |
| — | 12 | `i ≥ n` 停止 | | | | 返回 `res` |

- 步 1–3：`i` 每轮 +3，`i + k ≤ n` 截断不生效，长度恰 3，零填充。
- 步 4：`s[9:12]` 自动截成 `"j"`，`len = 1 < 3`，尾部补 2 个 `fill`。
- **对照 1**（$n = 9$ 整除）：$i = 9 \geq n$ 直接停，末组 `"ghi"` 恰满——若此时还补 `k − n mod k = 3` 个 `fill`，就多出 `"ghixxx"` 一整组。
- **对照 2**（$k > n$）：单组 `"abc" + "xx" = "abcxx"`，公式自然覆盖，无需特判。

## 4. 算法细节

1. **上取整的整数写法**：$m = \lceil n/k \rceil = \lfloor (n+k-1)/k \rfloor = \lfloor (n-1)/k \rfloor + 1$（$n \geq 1$）。避免浮点 `ceil((double)n/k)`——本题 $n \leq 100$ 无所谓，但大数下浮点有精度风险，整数式是习惯。循环写法其实**不需要显式算组数**（`i < n` 自然终止），只有预补齐 / 列表推导版才用得上。
2. **切片越界的跨语言差异**：Python `s[i:i+k]` 与 C++ `s.substr(i, k)`（第二参数是**长度**）都自动夹取到串尾；Java `s.substring(i, i+k)` 越界**抛异常**，须手动 `Math.min(i+k, n)`。签到题拼手速时最容易栽在语言语义而非算法上。
3. **尾部对齐的语义级 API**：Python `str.ljust(k, fill)` 恰是「右补齐到宽度 $k$」，与本题主推写法天作之合，一行完成切片 + 填充；C++ 对应 `g.append(count, ch)`。
4. **负取模的语言差异**：数学填充量 $= (-n) \bmod k \in [0, k)$。Python `-n % k` 直接给出该值；C++ 里 `-n % k` 得非正数，拿去构造 `string(负数, fill)` 会抛 `length_error`，正确写法是 `(k - n % k) % k`。
5. **结果规模**：组数 $m$，输出总字符数 $mk \leq n + k - 1 < 200$；预补齐版会复制整串（$O(n + k)$），本题可忽略。

## 5. 正确性证明

**引理 1（划分唯一性与组数公式）**：设 $n = |s| \geq 1$，$k \geq 1$。自左向右把 $[0, n)$ 首尾相接地切成 $m$ 段，除末段外每段长度恰为 $k$、末段长度在 $[1, k]$ 内，则该划分唯一，且 $m = \lceil n/k \rceil$。

**证明**：对段序归纳：第 0 段为 $[0, k)$；若第 $i$ 段起点为 $ik$ 且非末段，则其长度恰 $k$，故第 $i+1$ 段起点为 $(i+1)k$——切分由规则唯一确定。覆盖且末段非空等价于 $(m-1)k < n \leq mk$，即 $n/k \leq m < n/k + 1$；任意实数 $x$ 的半开区间 $[x, x+1)$ 恰含一个整数，故 $m$ 唯一且 $m = \lceil n/k \rceil$（验证：$k \mid n$ 时 $m = n/k$，$(m-1)k = n - k < n$ 成立；$k \nmid n$ 时 $m = \lfloor n/k \rfloor + 1$，$(m-1)k = \lfloor n/k \rfloor k < n$ 成立）。∎

**引理 2（满组引理）**：当 $i < \lfloor n/k \rfloor$ 时，第 $i$ 组对应的区间 $[ik, \min((i+1)k, n))$ 长度恰为 $k$。

**证明**：$i < \lfloor n/k \rfloor \Rightarrow (i+1)k \leq \lfloor n/k \rfloor k \leq n$，故 $\min$ 取 $(i+1)k$，区间长度 $(i+1)k - ik = k$。∎

**推论（填充量）**：末组长度 $r' = n - (m-1)k \in [1, k]$；当 $k \mid n$ 时 $r' = k$、填充量为 $0$；否则 $r' = n \bmod k$、填充量为 $k - (n \bmod k)$。统一写成 $(k - n \bmod k) \bmod k = (-n) \bmod k$（最小非负剩余）。

**证明**：由引理 1 的两种情形直接代入：$k \mid n$ 时 $m = n/k$，$r' = n - (n/k - 1)k = k$；$k \nmid n$ 时 $m = \lfloor n/k \rfloor + 1$，$r' = n - \lfloor n/k \rfloor k = n \bmod k \in [1, k-1]$。填充量 $k - r'$ 在两种情形下分别为 $0$ 与 $k - (n \bmod k)$；而 $(-n) \bmod k$ 恰给出同一结果：$n \bmod k = 0$ 时为 $0$，否则为 $k - (n \bmod k)$，故三者统一为 $(k - n \bmod k) \bmod k$。∎

**定理（算法正确性）**：步长循环（`g = s[i:i+k]`，`g` 尾补 `fill` 至长度 $k$，`i += k`）恰执行 $m = \lceil n/k \rceil$ 轮，输出即题意划分：每组长度恰 $k$，前 $m-1$ 组逐位等于 $s$ 的对应切片，末组前 $r'$ 个字符为 $s$ 的尾部。

**证明**：每轮 $i$ 增加 $k \geq 1$，且循环在 $i \geq n$ 时终止，故轮数为满足 $ik < n$ 的 $i \in \{0, k, 2k, \dots\}$ 的个数，恰为 $m$（引理 1）。语言切片 / `substr` 从 $ik$ 起逐位复制并夹取到 $n$：由引理 2，前 $\lfloor n/k \rfloor$ 组夹取不生效、得恰 $k$ 个原字符；末组得 $r'$ 个。补 `fill` 发生在尾部且补足到 $k$（`append` / `ljust` 的语义），故每组长度恰 $k$ 且原字符全部位于填充之前。由引理 1，满足题意的划分唯一，算法输出即它。∎

**定理 2（还原性）**：去掉末组尾部 $(k - r') \bmod k$ 个 `fill` 后按序连接所有组，恰得原串 $s$；即使 `fill` 本就出现在 $s$ 中亦然。

**证明**：连接结果中，位置 $p < (m-1)k + r'$ 的字符来自切片的逐位复制，等于 $s_p$；其后是填充字符。剥离按**数量**进行：填充数量由 $n, k$ 唯一确定（推论），与字符取值无关——`fill` 出现在原串中时属于「原字符」，按位置不会被误删。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k)$。$m = \lceil n/k \rceil$ 轮切片共复制 $n$ 个原字符，末组填充至多 $k - 1$ 个（预补齐版为一次性补齐 + 整串重切，同为 $O(n + k)$）。本题 $n, k \leq 100$，操作数百次，签到题一轮内完成。
- **空间复杂度**：$O(n + k)$ 为输出本身（$\lceil n/k \rceil$ 个组共 $mk$ 个字符）。不计输出，按需填充版仅 $O(1)$ 额外变量（C++ 可 `move` 进结果避免拷贝）；预补齐版多复制一份长为 $mk$ 的串。
- **对照**：逐字符缓冲版同为 $O(n)$ 时间——差异在**代码状态数**而非复杂度；签到题的胜负手是「状态最少、分支最少」的无 bug 实现。

## 7. 参考代码

### C++（按需填充，主推）

```cpp
class Solution {
public:
    vector<string> divideString(string s, int k, char fill) {
        vector<string> res;
        for (int i = 0; i < (int)s.size(); i += k) {
            string g = s.substr(i, k);          // 越界自动截断，至多取 k 个
            g.append(k - g.size(), fill);       // 整除时补 0 个，无分支特判
            res.push_back(move(g));
        }
        return res;
    }
};
```

### C++（预补齐版）

```cpp
class Solution {
public:
    vector<string> divideString(string s, int k, char fill) {
        s.append((k - s.size() % k) % k, fill); // 补成 k 的整倍数，整除时补 0 个
        vector<string> res;
        for (int i = 0; i < (int)s.size(); i += k)
            res.push_back(s.substr(i, k));      // 循环内零分支
        return res;
    }
};
```

> 💡 注意 C++ 不能照抄 Python 的 `-n % k`：C++ 的 `%` 向零取整，`-10 % 3 = -1`，拿负数当填充长度会抛 `length_error`；`(k - n % k) % k` 才是等价写法。

### Python（ljust 语义级一行，主推）

```python
class Solution:
    def divideString(self, s: str, k: int, fill: str) -> List[str]:
        return [s[i:i + k].ljust(k, fill) for i in range(0, len(s), k)]
```

> 💡 `str.ljust(k, fill)` 的语义就是「右补齐到宽度 $k$、不足补指定字符」，与本题填充规则逐字对应；越短的代码越难藏 bug，这是周赛 Q1 的理想形态。

### Python（预补齐 + 负取模版）

```python
class Solution:
    def divideString(self, s: str, k: int, fill: str) -> List[str]:
        s += fill * (-len(s) % k)               # 整除时补 0 个
        return [s[i:i + k] for i in range(0, len(s), k)]
```

## 8. 边界情况与易错点

1. **整除陷阱（最高频）**：$n \bmod k = 0$ 时填充量必须为 $0$。把填充量写死成 `k - n % k`，整除时会算出 $k$，末组凭空多补一整组（`n=9, k=3` → `"ghixxx"` ✗）。修正：`(k - n % k) % k` 或 Python 的 `-n % k`。走查 `n=9` 这个用例即可拦截。
2. **k > n**：只剩一组，$n$ 个原字符 + $(k - n)$ 个 `fill`（`"abc", k=5 → "abcxx"`），公式自然覆盖，无需特判。
3. **k = 1 / n = 1**：$n \bmod 1 = 0$ 恒成立，永不填充；`s="x", k=1` 输出 `["x"]`。
4. **C++ `substr` 参数手滑**：`s.substr(i, i+k)` 把「长度」当「终点」——`n=9, k=3, i=3` 时取到 `"defghi"`（6 字符），组长度失控。正确是 `s.substr(i, k)`。
5. **Java 切片越界抛异常**：`s.substring(i, i+k)` 在末组越界直接 `StringIndexOutOfBoundsException`，须 `Math.min(i+k, n)`；Python / C++ 的截断语义是「恰好安全」的巧合福利。
6. **只补末组、只补尾部**：给每组都补、或补在头部，都会破坏「去填充连接还原 = s」的约束（定理 2 的前提是填充全部位于末组尾部）。
7. **fill 重复出现在 s 中无害**：还原按**数量**剥离填充，不按「删掉所有 fill 字符」——后者会误删原字符。
8. **返回类型与参数类型**：返回 `vector<string>` / `List[str]` 而非拼接后的整串；`fill` 在 C++ 接口里是 `char`、Python 里是 `str`，别在 C++ 里写 `string(k, fill)` 之外的臆造重载。
9. **溢出审计**：$n, k \leq 100$，$(n + k - 1) \leq 199$，`int` 毫无压力，无溢出风险。
