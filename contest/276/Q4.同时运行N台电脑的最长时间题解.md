# LeetCode 同时运行 N 台电脑的最长时间 题解

## 1. 题目概述

- **标题 / 题号**：同时运行 N 台电脑的最长时间（#2141，hard）
- **链接**：https://leetcode.cn/problems/maximum-running-time-of-n-computers/
- **来源**：LeetCode 第 276 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、二分查找、排序

**题意**：有 $n$ 台电脑与 $m$ 节电池，第 $i$ 节电池可让一台电脑运行 $b_i$ 分钟。一台电脑同一时刻至多接一节电池；任意整数时刻可零耗时换电池（新电池或别的电脑用过的都行），但电池不可充电、同一时刻也不可同时供两台电脑。求让**全部** $n$ 台电脑**同时**连续运行的最长分钟数。

**约束**：

- $1 \le n \le m \le 10^5$
- $1 \le b_i \le 10^9$

> 💡 约束的「甜区」读法：$m \le 10^5$ 期望 $O(m \log m)$ 以内；总能量 $\sum b_i$ 可达 $10^{14}$——答案与判定中的和都**远超 32 位 int**，C++ 全程 `long long`。「求最长时间 + 调度难以直接构造」是二分答案的招牌信号。

> 💡 本题在本仓库另有[每日题解 2141](../../solution/2101-2200/2141_同时运行N台电脑的最长时间.md)：主线同为「二分答案 + $\sum \min(b_i, t) \ge n \cdot t$ 判定」。本篇按**周赛复盘视角**展开：模拟调度为何无从下手、$\min$ 截断如何被反例逼出来（$n=2,\ b=[10,1,1]$）、可行性 ⇔ 不等式的三引理一定理完整证明（能量上界 / 能量条构造 / 前缀性）、贪心「削峰拉平」$O(m \log m)$ 的水位直觉，以及 $10^{14}$ 溢出与二分方向两类高频翻车点。同场 Q1（#2138 定长切片）、Q2（#2139 反向贪心）、Q3（#2140 倒序线性 DP）均已成文，本题是本场收官。

## 3. 解题思路

### 3.1 暴力思路：两层「无从下手」

**模拟调度**：最直接的想法是离散事件模拟——但「何时换哪节电池」本身就是决策变量，搜索空间是随时间指数膨胀的组合；题目问的是**最优调度**能撑多久，而不是评估某个给定调度，模拟没有下手处。

**逐 $t$ 枚举**：退一步，若能 $O(m)$ 判定「能否同时运行 $t$ 分钟」，从 $t = 1$ 逐个试到能量上界 $\lfloor \sum b_i / n \rfloor$ 即可。但该上界可达 $10^{5} \times 10^{9} = 10^{14}$——即使判定是 $O(1)$ 也跑不完。

> 💡 卡点即提示：判定难直接构造 + 值域巨大 +「求最大可行」——**二分答案**的标准画像。剩下的问题只有一个：$O(m)$ 的判定函数长什么样？

### 3.2 核心观察：能量守恒 + $\min(b_i, t)$ 截断

![核心观察：截断与二段性](images/2141_runtime_concept.svg)

**第一层（能量上界）**：$n$ 台各跑 $t$ 分钟共耗能 $n \cdot t$，电池总能量 $\sum b_i$，故 $t \le \lfloor \sum b_i / n \rfloor$。但示例 3 表明这只是必要条件——$n=2,\ b=[10,1,1]$ 时上界为 6，实际只有 2。

**第二层（单节贡献封顶）**：一节电池**同一时刻只能供一台电脑**，而每台电脑只活 $[0, t]$ 这 $t$ 分钟。于是容量 $b_i > t$ 的电池即使全程在线，也至多供电 $t$ 分钟——**超出 $t$ 的能量没有时间窗口安放**。单节有效贡献 $\le \min(b_i, t)$，判定式收紧为：

$$\boxed{\;\sum_i \min(b_i,\, t) \;\ge\; n \cdot t\;}$$

**第三层（二段性）**：若 $t$ 可行，把它的可行调度截断在 $t' < t$，就是 $t'$ 的可行调度——可行集合是 $\{0, 1, \ldots, t^*\}$ 的**前缀**（引理 3）。也可看 $f(t) = \sum_i \min(b_i, t) - n \cdot t$ 的形状：起步斜率 $m - n \ge 0$，随电池陆续触顶斜率递减，一旦活跃电池数跌破 $n$ 便恒负——分段线性凹函数，正负只跨越一次。

三件事凑齐：**一行求和的判定 + 前缀性 + 巨大值域** ⇒ 上界型二分，可行往右。

> ⚠️ 对照家族题的差异：[875. 爱吃香蕉的珂珂](../../solution/0801-0900/875_爱吃香蕉的珂珂.md) / [2064](../../solution/2001-2100/2064_分配给商店的最多商品的最小值.md) 的判定是**向上取整求和** $\lceil q/x \rceil$（一份货物可拆到多家店），本题是**向下截断求和** $\min(b_i, t)$（电池不可同时分身）——方向与截断方式都不同，模板别整套照搬。

### 3.3 算法流程：上界型二分

![算法流程：上界型二分](images/2141_runtime_flow.svg)

1. **初始化**：`total = Σb`，`lo = 1`，`hi = total / n`（物理天花板），`ans = 0`；
2. **循环** `lo ≤ hi`：取 `mid`，累加 `s = Σ min(b_i, mid)`，一旦 `s ≥ n·mid` 立即返回可行（提前剪枝，兼提速与防溢出）；
3. **判定**：`s ≥ n·mid` → 可行，记 `ans = mid`，`lo = mid + 1`（往右试更长）；否则 `hi = mid − 1`；
4. **返回** `ans`。

### 3.4 示例演算

![示例演算：二分与构造](images/2141_runtime_walkthrough.svg)

以示例 1 `n = 2, batteries = [3,3,3]` 演算：`total = 9`，`hi = 9 / 2 = 4`：

| 轮次 | 区间 $[\text{lo}, \text{hi}]$ | mid | $\sum \min(b_i, \text{mid})$ | 判定 | 动作 |
|----|----|----|----|----|----|
| 1 | $[1,4]$ | 2 | $3 \times 2 = 6$ | $6 \ge 4$ ✓ | `ans=2`, `lo=3` |
| 2 | $[3,4]$ | 3 | $3 \times 3 = 9$ | $9 \ge 6$ ✓ | `ans=3`, `lo=4` |
| 3 | $[4,4]$ | 4 | $3 \times 3 = 9$ | $9 \ge 8$ ✓ | `ans=4`, `lo=5 > hi` |

返回 `ans = 4`。**验证 4 确实可调度**（引理 2 的构造）：把三节电池接成能量条 $[0,9]$，按 $t=4$ 切成电脑 0 的 $[0,4]$ 与电脑 1 的 $[4,8]$（尾部 $[8,9]$ 舍弃）。电池 1 的条 $[3,6]$ 跨过切口 4：$[3,4]$ 段给电脑 0 的第 3 分钟、$[4,6]$ 段给电脑 1 的前 2 分钟——**同一节电池先后服务两台电脑，但时段不重叠**。展开正是官方解释给出的调度。

### 3.5 进阶：贪心「削峰拉平」$O(m \log m)$

二分是对谓词的通用搜索，本题还有**显式解出交点 $t^*$** 的贪心：

1. 降序排序，前 $n$ 节（最大）各对接一台电脑当**主力**，其余电池总能量记 `spare`；
2. 主力中最矮的是 $b[n-1]$。「拉平」到 $b[n-2]$ 需给 $1$ 台补差额；再拉到 $b[n-3]$ 需 $2$ 台各补差额……第 $k$ 级共需 $k \cdot \text{diff}$；
3. 某级 `spare` 付不起 ⇒ 答案 = 当前级 $b[i] + \lfloor \text{spare} / k \rfloor$（剩余备用均摊给这 $k$ 台）；
4. 一路拉平到 $b[0]$ 仍有余 ⇒ 答案 = $b[0] + \lfloor \text{spare} / n \rfloor$（全部均摊）。

以 `n=3, batteries=[10,1,1,1]` 验证：降序后前 3 节 `[10,1,1]`，`spare=1`；`i=2`：`k=1, diff=0` 不花钱；`i=1`：`k=2, diff=9, need=18 > 1` → 返回 $1 + \lfloor 1/2 \rfloor = 1$ ✓（三台中两台只有 1 分钟能量，主力 10 被短板拖死）。

> 💡 直觉：把前 $n$ 节画成 $n$ 根高低不齐的水柱，`spare` 是待注入的水——**注水拉平后的水位就是 $t^*$**。二分在值域上对分搜索交点，贪心沿水位直接走到交点。正确性可对输出 $\hat t$ 验证 $f(\hat t) \ge 0 > f(\hat t + 1)$ 逐级分类讨论得证，此处从略；赛场求稳，二分优先。

## 4. 算法细节

1. **判定函数**：`s = Σ min(b_i, t)`，累加中一旦 `s ≥ n·t` 立即返回 `true`——既提前剪枝（$t$ 小时往往几节电池就够），又把 `s` 的上界收紧在 $n \cdot t$ 附近，彻底杜绝累加溢出的可能。
2. **上下界**：上界 `hi = total / n` 是能量天花板（超过它时 $\sum \min(b_i, t) \le \sum b_i < n \cdot t$ 恒假）；下界取 1（$b_i \ge 1$ 且 $m \ge n$ ⇒ $\sum \min(b_i, 1) = m \ge n$，$t=1$ 恒可行，答案必 $\ge 1$）。
3. **溢出审计**：`total` 达 $10^{14}$，`n * mid` 因 `mid ≤ total/n` 也 $\le 10^{14}$，C++ 全程 `long long`；`min((long long)b, t)` 必须先把 `b` 提升类型再比较。Python 整数任意精度，无此虞。
4. **二分方向**：本题找**最后一个可行值**（最大化可行值），可行时 `ans = mid; lo = mid + 1`；与 875/2064 的「第一个可行值」（可行时 `hi = mid - 1`）方向相反。
5. **贪心实现**：降序排序后从 `i = n-1` 往回扫，`k = n - i` 是「需要补给的主力台数」；除法向下取整（剩余 `spare` 拆不出半分钟）；循环走完必须落到「全拉平 + 均摊」的收尾分支。

## 5. 正确性证明

先把「调度」形式化：给每台电脑 $c \in \{0, \ldots, n-1\}$ 一条供电记录——把 $[0, t]$ 划分为若干整数区间、每个区间标注一节电池；合法性约束为 (a) 任一时刻一节电池至多出现在一台电脑的记录中（不可分身），(b) 每节电池 $i$ 被标注区间总长 $\le b_i$（容量）。$t$ **可行** ⇔ 存在这样的 $n$ 条记录。

**引理 1（必要性：能量不等式）**：$t$ 可行 $\Rightarrow \sum_i \min(b_i, t) \ge n \cdot t$。

**证明**：设电池 $i$ 实际供电 $x_i$ 分钟，则 $n \cdot t = \sum_i x_i$。由 (b)，$x_i \le b_i$；由 (a)，电池 $i$ 的供电区间互不重叠且都落在 $[0, t]$ 内，故 $x_i \le t$。于是 $x_i \le \min(b_i, t)$，求和即得。∎

**引理 2（充分性：能量条构造）**：$\sum_i \min(b_i, t) \ge n \cdot t \Rightarrow t$ 可行。

**证明**：令 $c_i = \min(b_i, t) \le t$，均为整数。把每节电池画成一条长 $c_i$ 的能量条，任意顺序首尾相接成总长 $L \ge n \cdot t$ 的长条；取前 $n \cdot t$ 按 $t$ 切成 $n$ 段，第 $k$ 段 $[kt, (k{+}1)t]$ 分给电脑 $k$，条上位置 $p$ 对应电脑 $k$ 的时刻 $p - kt$。每条长 $\le t$，故一节电池至多跨越一条切口，至多出现在**相邻两台**电脑的记录中。设某条占 $[x, y]$（$y - x \le t$）且跨过切口 $kt$：电脑 $k{-}1$ 在时段 $[x-(k{-}1)t,\; t]$ 使用它，电脑 $k$ 在时段 $[0,\; y-kt]$ 使用它；由 $y - x \le t$ 得 $y - kt \le x - (k{-}1)t$，两时段不相交。切口与条端均为整数，切换发生在整数时刻，与题面一致。故构造给出合法调度。∎

**引理 3（前缀性）**：$t$ 可行且 $0 \le t' < t$ $\Rightarrow t'$ 可行。

**证明**：取 $t$ 的可行调度，把所有供电记录截断到 $[0, t']$（跨越 $t'$ 的区间右端点改为 $t'$）。每台电脑在 $[0, t']$ 全程有电；约束 (a)(b) 在子区间上自然继承。∎

**定理**：以 $\text{check}(t) \equiv [\sum_i \min(b_i, t) \ge n \cdot t]$ 为谓词、在 $[1, \lfloor \sum b_i / n \rfloor]$ 上的上界型二分，返回值恰为最大可行时间 $t^*$。

**证明**：由引理 1、2，check 与「可行」等价。由引理 3，可行集合形如 $\{0, 1, \ldots, t^*\}$；它非空（$t = 1$ 恒可行，见 §4.2）。当 $t > \lfloor \sum b_i / n \rfloor$ 时 $\sum \min(b_i, t) \le \sum b_i < n \cdot t$，check 恒假，故 $t^*$ 落在二分区间内。上界型二分（可行则记录并右移）在「真前缀 + 假后缀」谓词上恰好收敛到最后一个真值 $t^*$。∎

**推论**：每轮判定 $O(m)$，共 $O(\log S)$ 轮（$S = \sum b_i / n \le 10^{14}$，$\log S \approx 47$），总时间 $O(m \log S)$。∎

> 💡 证明的枢纽在**引理 2 的构造**：它把「换电池的艺术」具象成「能量条首尾相接再切段」，而 $c_i = \min(b_i, t) \le t$ 恰好保证每条不跨两个切口——截断不是拍脑袋的收紧，而是构造成立的充分条件。引理 3 则便宜得出奇：无需分析 $f(t)$ 的斜率，「把调度截短」一句就拿到二段性。

## 6. 复杂度分析

- **时间复杂度**：$O(m \log S)$，$m$ 为电池数，$S = \lfloor \sum b_i / n \rfloor \le 10^{14}$，$\log S \approx 47$；总运算量约 $4.7 \times 10^6$，远低于时限。提前剪枝在 $t$ 较小时通常几节电池即返回，实测更快。
- **空间复杂度**：$O(1)$ 额外空间（贪心版需原地排序，栈深 $O(\log m)$）。
- **对照**：贪心削峰 $O(m \log m)$——省掉值域搜索的 $\log$ 因子，代价是额外的洞察与证明负担。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long maxRunTime(int n, vector<int>& batteries) {
        long long total = 0;
        for (int b : batteries) total += b;

        long long lo = 1, hi = total / n, ans = 0;
        while (lo <= hi) {
            long long mid = lo + (hi - lo) / 2;
            if (canRun(batteries, n, mid)) {
                ans = mid;          // 可行：往右试更长
                lo = mid + 1;
            } else {
                hi = mid - 1;       // 不够：缩短时间
            }
        }
        return ans;
    }

  private:
    // 验证：n 台电脑同时运行 t 分钟是否可行
    bool canRun(const vector<int>& batteries, int n, long long t) {
        long long target = n * t;               // 总耗能
        long long s = 0;
        for (int b : batteries) {
            s += min((long long)b, t);          // 每节电池截断在 t
            if (s >= target) return true;       // 提前剪枝，兼防溢出
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def maxRunTime(self, n: int, batteries: List[int]) -> int:
        total = sum(batteries)

        lo, hi = 1, total // n
        ans = 0
        while lo <= hi:
            mid = (lo + hi) // 2
            if self._can_run(batteries, n, mid):
                ans = mid          # 可行：往右试更长
                lo = mid + 1
            else:
                hi = mid - 1       # 不够：缩短时间
        return ans

    def _can_run(self, batteries: List[int], n: int, t: int) -> bool:
        target = n * t                       # 总耗能
        s = 0
        for b in batteries:
            s += min(b, t)                   # 每节电池截断在 t
            if s >= target:
                return True                  # 提前剪枝
        return False
```

### Python（进阶：贪心削峰 $O(m \log m)$）

```python
class Solution:
    def maxRunTime(self, n: int, batteries: List[int]) -> int:
        batteries.sort(reverse=True)
        spare = sum(batteries[n:])              # 备用电池总能量
        for i in range(n - 1, 0, -1):
            k = n - i                           # 需补给 k 台升到 b[i-1]
            need = k * (batteries[i - 1] - batteries[i])
            if spare >= need:
                spare -= need
            else:
                return batteries[i] + spare // k
        return batteries[0] + spare // n        # 全拉平再均摊
```

> 💡 三版共同要点：① 判定的 $\min(b, t)$ 截断不可省（示例 3 即反例）；② C++ 全程 `long long`，`min((long long)b, t)` 先提类型；③ 二分方向是「可行往右」；贪心版注意 `spare // k` 向下取整与收尾分支。

## 8. 边界情况与易错点

1. **C++ 溢出（最高频 WA）**：`total` 可达 $10^{14}$、`n * mid` 同量级，`int` 必炸；`min((long long)b, t)` 的类型提升别漏。
2. **忘写 $\min$ 截断**：把判定写成 $\sum b_i \ge n \cdot t$、答案直接返回 `total / n`——示例 3（$n=2,\ b=[10,1,1]$）会答 6，正确答案 2。大电池的多余能量**没有时间窗口**。
3. **二分方向套反**：照搬 875/2064 的「可行往左」模板，会收敛到 1（$t=1$ 恒可行），连样例都过不去。本题求**最大**可行值：可行 `ans = mid; lo = mid + 1`。
4. **上界取错**：`hi = total` 不会错答案但白跑几十轮；`hi = total / n` 是物理天花板。不要取 `max(batteries)`——$n=1$ 时真上界是 $\sum b_i$，$n = m$ 时是 $\min b_i$，两个方向都能错。
5. **$n = m$（无备用电池）**：答案即 $\min(b_i)$——每台恰好分到一节、无替换余地；判定式自然给出（$t > \min b$ 时最矮电池的贡献被钉死在 $\min b$）。可作小样例自测。
6. **大电池独大**：如 $[10,1,1,1],\ n=3$ → 1。此时 $t^*$ 低于全部「主力」高度，贪心在第一个付费级就断裂；二分写法对此无感，稳。
7. **贪心版两处坑**：`k = n - i` 别写成 `i`（台数与下标互为倒数关系，写反则付费级全错）；循环正常走完必须落到 `batteries[0] + spare // n` 的收尾分支，漏掉会把「恰好全拉平」的情形答小。
8. **提前剪枝的位置**：在累加循环**内部**判断 `s >= target` 即返回，而不是累加完再比——后者在大 $m$ 下多做无效功，且失去对 `s` 的溢出保护。
9. **答案下界**：$b_i \ge 1$ 且 $m \ge n$ 保证答案 $\ge 1$，无需特判 0；`ans` 初值取 0 只是防御性写法。
