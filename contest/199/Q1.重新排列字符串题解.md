# LeetCode 重新排列字符串 题解

## 1. 题目概述

- **标题 / 题号**：重新排列字符串（#1528，easy）
- **链接**：https://leetcode.cn/problems/shuffle-string/
- **来源**：LeetCode 第 199 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、模拟、排列（置换）

**题意**：给定字符串 `s` 和**长度相同**的整数数组 `indices`。请重新排列 `s`：第 $i$ 个字符需要移动到下标 $\text{indices}[i]$ 指示的位置。返回重新排列后的字符串。

**约束**：

- $1 \le n \le 100$ → 签到量级，任何单趟扫描做法都绰绰有余，重点在「不写错」而非「跑得快」
- $0 \le \text{indices}[i] < n$ 且**所有值互不相同** → `indices` 是 $[0, n-1]$ 的**排列**（双射），这是本题唯一的结构性信息
- `s` 仅含小写英文字母 → 字符取什么值无关紧要，重排逻辑只看下标

> 💡 一眼定性：`indices` 是一张「源位置 → 目标位置」的**置换表**，照着把字符搬运到位即可——纯模拟，无任何最优化决策。本题在本仓库另有[每日题解 1528](../../solution/1501-1600/1528_重新排列字符串.md)，本篇按**周赛复盘视角**重写：签到题的切入节奏、映射方向感与完整证明。

## 2. 示例

**示例 1**

```text
输入：s = "codeleet", indices = [4,5,6,7,0,2,1,3]
输出："leetcode"
解释：第 0 个字符 'c' 去下标 4，第 4 个字符 'l' 去下标 0……
     8 个字符各自归位后拼成 "leetcode"。
```

**示例 2**

```text
输入：s = "abc", indices = [0,1,2]
输出："abc"
解释：恒等映射，每个字符留在原位。
```

**示例 3（自造，覆盖整体轮换的单循环情形）**

```text
输入：s = "abc", indices = [1,2,0]
输出："cab"
解释：'a'→位置 1，'b'→位置 2，'c'→位置 0，整串恰好构成一个 3-循环。
```

## 3. 解题思路

### 3.1 朴素思路与三个高频坑

- **按目标找源（$O(n^2)$）**：要填 `result[j]`，就扫描一遍 `indices` 找满足 `indices[i] == j` 的 `i`。信息方向用反了——题目白给「源 → 目标」的映射，偏要现场求逆，每个目标都把数组重扫一遍。$n \le 100$ 侥幸能过，但完全没必要。
- **写反方向（直接 WA）**：`res[i] = s[indices[i]]` 把 `indices` 当成「从哪儿取」，而题意是「送到哪儿」。用示例 1 一测便知：得到 `"leetcdoe"`（'o' 与 'd' 放错了位）而非 `"leetcode"`。
- **原地写回（数据丢失）**：`s[indices[i]] = s[i]` 会覆盖尚未读取的源字符——处理 $i=0$ 时写 `s[4]`，可 `'l'` 还没被读走就没了。

签到题翻车基本都翻在这三处：两个方向坑 + 一个覆盖坑。

### 3.2 核心观察：indices 是排列，顺着映射方向直达放置

![核心观察：indices 是排列，顺着映射方向直达放置](images/wc199_q1_place_concept.svg)

把三个坑翻过来看，正解自然浮出：**对每个源下标 $i$，把 `s[i]` 直接写到 `res[indices[i]]`**：

$$\text{res}[\text{indices}[i]] = s[i], \quad i = 0, 1, \dots, n-1$$

由于 `indices` 是 $[0, n-1]$ 的排列——**双射**——每个目标位置恰好被一个源命中：**不冲突**（同一格子不会被写两次）、**不遗漏**（每个格子都会被写一次）。一趟循环，每个字符 $O(1)$ 直达。

> 💡 **方向感是本题唯一的考点**：顺着给定的映射方向走（源 → 目标），永远比求逆（目标 → 源）省力；「顺着走」落在代码里就是 `res[indices[i]] = s[i]` 这一行。

### 3.3 算法流程

![算法流程：一趟放置](images/wc199_q1_algorithm_flow.svg)

```text
输入：s（长度 n），indices
1. res ← 长度为 n 的空数组
2. 对 i = 0 … n-1：res[indices[i]] ← s[i]
3. 返回 res（拼成字符串）
```

流程里藏着一个**循环不变量**：处理完前 $i$ 个源后，`res` 中 `indices[0..i-1]` 对应的位置已**最终就位**——后续放置写到的是别的位置，永远不会覆盖它们（放置目标互异）。这正是 §5 正确性证明的直观骨架。

### 3.4 示例演算

![示例演算：codeleet 逐步填入结果数组](images/wc199_q1_example_walkthrough.svg)

对 `s = "codeleet", indices = [4,5,6,7,0,2,1,3]` 逐步走查（`_` 为尚未填入）：

- **i=0**：`'c'` → 位置 4：`____c___`
- **i=1**：`'o'` → 位置 5：`____co__`
- **i=2**：`'d'` → 位置 6：`____cod_`
- **i=3**：`'e'` → 位置 7：`____code`
- **i=4**：`'l'` → 位置 0：`l___code`
- **i=5**：`'e'` → 位置 2：`le_ecode`
- **i=6**：`'e'` → 位置 1：`lee_code`
- **i=7**：`'t'` → 位置 3：`leetcode` ⭐

8 次放置恰好填满 8 个格子，与示例输出一致——每个格子只被写一次、也没有格子漏写，正是双射的直接体现。

## 4. 算法细节

1. **必须用独立结果数组**：原地写回有覆盖未读字符的风险（坑 ③）；`res` 与源 `s` 分离后，整个遍历期间源数据不被破坏。
2. **核心公式只有一行**：`res[indices[i]] = s[i]`。把题面的「第 $i$ 个字符**移动到** $\text{indices}[i]$」翻译成这一行，签到即完成。
3. **语言落地**：
   - C++：`string res(n, '\0')` 预分配后逐位写入，最后直接返回；
   - Python：`res = [''] * n` 逐位放置后 `join`；亦可一行 `"".join(c for _, c in sorted(zip(indices, s)))`——按 `indices` 排序再拼接，$O(n \log n)$，比赛同样可用，只是不如直接放置直白。
4. **合法性别操心**：题面已保证 `indices` 是排列，无需校验越界或重复；若题面不保证，须先校验（见 §8 第 6 条）。
5. **签到节奏**：认出「置换搬运」模型 → 写下那一行公式 → 用示例 1 自测方向 → 提交。全程控制在 2 分钟内，把时间留给后面的 Q2/Q3。

## 5. 正确性证明

**引理 1（indices 是双射）**：`indices` 的 $n$ 个值互不相同且都落在 $[0, n-1]$ 内，故它是 $[0, n-1]$ 到自身的双射（即排列）。

**证明**：互异 → 单射；$n$ 个不同值装入大小为 $n$ 的集合，由鸽笼原理每个值都被取到 → 满射。∎

**引理 2（恰写一次）**：执行一轮 `res[indices[i]] = s[i]`（$i = 0, \dots, n-1$）后，`res` 的每个位置**恰好**被写入一次。

**证明**：位置 $j$ 被写当且仅当存在 $i$ 使 $\text{indices}[i] = j$；由引理 1，这样的 $i$ 存在（满射 ⇒ 不遗漏）且唯一（单射 ⇒ 不冲突）。∎

**定理**：算法输出是唯一满足题意的字符串，即 $t[j] = s[\text{indices}^{-1}(j)]$ 对一切 $j$ 成立。

**证明**：题意要求每个合法输出 $t$ 满足 $t[\text{indices}[i]] = s[i]$（对所有 $i$）。位置 $j$ 的取值由 $i = \text{indices}^{-1}(j)$ 唯一确定，故合法输出至多一个；又由引理 2，算法把每个 $j$ 恰写成 $s[\text{indices}^{-1}(j)]$ 且填满全部位置，故合法输出存在且恰为算法的输出。∎

> 💡 Q1 的证明一句话：**双射 ⇒ 放置既无冲突也无遗漏 ⇒ 一趟填完的数组就是唯一答案**。置换类模拟题（如 1920）都可以套这个骨架。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟循环，每个字符一次寻址写入；$n \le 100$ 毫无压力。
- **空间复杂度**：$O(n)$。长度为 $n$ 的结果数组；返回值本身就要占 $O(n)$，这部分不可避免。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string restoreString(string s, vector<int>& indices) {
        int n = s.size();
        string res(n, '\0');          // 独立结果数组，源 s 全程不被破坏
        for (int i = 0; i < n; i++) {
            res[indices[i]] = s[i];   // 顺着映射方向：源 i 的字符直达目标
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def restoreString(self, s: str, indices: list[int]) -> str:
        res = [''] * len(s)            # 独立结果数组
        for i, ch in enumerate(s):
            res[indices[i]] = ch       # 顺着映射方向放置
        return ''.join(res)
```

> 💡 Python 一行版：`return ''.join(c for _, c in sorted(zip(indices, s)))`——按 `indices` 排序后拼接，$O(n \log n)$，仅作语言趣味。

## 8. 边界情况与易错点

1. **方向写反**：`res[i] = s[indices[i]]` 在示例 1 上得到 `"leetcdoe"`——交卷前务必**用示例 1 自测**，方向坑当场现形。

2. **原地写回覆盖**：`s[indices[i]] = s[i]` 会抹掉尚未读取的字符，必须用独立结果数组。

3. **$n = 1$**：`"a"`、`[0]` → `"a"`，单字符路径天然覆盖，无需特判。

4. **恒等映射**（示例 2）：`indices = [0, 1, ..., n-1]` 时输出即输入，放置写法自然成立。

5. **重复字符不添乱**：`"codeleet"` 有三个 `'e'`，但双射由**下标**保证、与字符值无关——重复字符各去各的位置，不会产生歧义。

6. **若题面不保证排列**（防错意识延伸）：`indices` 出现重复 → 目标冲突；出现缺失 → 有格子无人写。需先校验值域与互异性，或改用稳定排序口径处理冲突。
