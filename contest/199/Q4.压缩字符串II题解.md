# LeetCode 压缩字符串 II 题解

## 1. 题目概述

- **标题 / 题号**：压缩字符串 II（#1531，hard）
- **链接**：https://leetcode.cn/problems/string-compression-ii/
- **来源**：LeetCode 第 199 场周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划、线性 DP

**题意**：行程长度编码（RLE）把连续 $\ge 2$ 个相同字符替换为「字符 + 计数」，**单个字符后不附加 `'1'`**，例如 `"aabccc"` → `"a2bc3"`。给定字符串 `s` 和整数 $k$，允许从 `s` 中**删除至多 $k$ 个字符**，求剩余字符串 RLE 编码长度的最小值。

**约束**：

- $1 \le n \le 100$ → 数据范围是明示的「DP 甜区」，$O(n^2 k)$ 级别可行
- $0 \le k \le n$ → $k \ge n$ 时可全部删空，答案为 0
- `s` 仅含小写字母 → 任一段长 $\le 100$，单段编码贡献封顶 4

## 2. 示例

**示例 1**

```text
输入：s = "aaabcccd", k = 2
输出：4
解释：不删除时 RLE 为 "a3bc3d"，长度 6。
删去 'b' 和 'd' 后剩 "aaaccc" → "a3c3"，长度 4。
```

**示例 2**

```text
输入：s = "aabbaa", k = 2
输出：2
解释：删去两个 'b'，剩 "aaaa" → "a4"，长度 2。
```

**示例 3**

```text
输入：s = "aaaaaaaaaaa", k = 0
输出：3
解释：一个 'a' 都不能删，11 个 'a' 编码为 "a11"——计数占 2 位，总长 3。
```

**示例 4（自造，覆盖跨阈值删除）**

```text
输入：s = "aaaaaaaaaa", k = 1
输出：2
解释：10 个 'a' 编码 "a10" 长度 3；删 1 个剩 9 个 'a' 编码 "a9" 长度 2。
删除的收益来自「把段长压过计数位数阈值 10」。
```

## 3. 解题思路

### 3.1 暴力思路：枚举删除集合

最直接的做法是枚举所有大小 $\le k$ 的删除位置子集，对每个剩余子序列现场算一遍 RLE 长度。方案数为 $\sum_{t=0}^{k}\binom{n}{t}$，$n = 100$、$k = 50$ 时是 $10^{28}$ 量级，完全不可行。

贪心也不可靠：删除的两种收益——**删段间异字符促合并**（`"aabaa"` 删 `'b'`）与**删段内字符压阈值**（10 个 `a` 删 1 个）——互相依赖，没有局部最优的贪心序。

> 💡 关键转换：不枚举「删哪些位置」，而是**从左到右决策每个字符的去留**，把「已删几个」编进状态。删除次数最多 $k \le n \le 100$，天然是 DP 的第二维。

### 3.2 核心观察：一段的编码贡献只由段长决定

![RLE 计费规则、合并收益与阈值收益](images/wc199_q4_rle_merge_concept.svg)

RLE 长度等于**各极大同字符段贡献之和**，而一段的贡献只看段长：

$$\text{encLen}(c) = \begin{cases} c & c \le 1 \quad(\text{单字符不附计数})\\ 1 + \text{十进制位数}(c) & 2 \le c \le 100 \end{cases}$$

即 $1 \mapsto 1$、$2 \sim 9 \mapsto 2$、$10 \sim 99 \mapsto 3$、$100 \mapsto 4$。由此得到两个结构性收益：

- **合并收益**：删除段间的异字符，可把两侧同字符段拼成一段，`"a2ba2"`（5）删 `'b'` → `"a4"`（2）；
- **阈值收益**：段长从 10 压回 9、从 100 压回 99，各恰好省 1 位。

> ⚠️ 段的边界在删除后会**动态合并**，所以不能按原始串的段做静态规划——段数与段长都是决策的结果，不是输入。这就是为什么状态要逐字符定义。

### 3.3 状态设计与转移

![dp 状态转移：决策 A 删除与决策 B 保留拼段](images/wc199_q4_dp_transition.svg)

定义 $dp[i][j]$ = 只考虑前 $i$ 个字符 $s[0..i-1]$、**至多删除 $j$ 个**时的最短 RLE 长度。边界 $dp[0][j] = 0$，答案 $dp[n][k]$。对 $dp[i][j]$ 有两个决策：

**决策 A —— 删除 $s[i-1]$**：消耗 1 次删除预算，问题规模减一：

$$dp[i][j] \leftarrow dp[i-1][j-1] \qquad (j \ge 1)$$

**决策 B —— 保留 $s[i-1]$**，让它作为最终串某个「以 $s[i-1]$ 结尾的同字符段」的成员。枚举段覆盖的原串区间 $[p-1,\, i-1]$（$p$ 从 $i$ 向左递减），区间内：

- 与 $s[i-1]$ **相同**的字符全部保留，共 $\text{kept}$ 个，拼接成一段，贡献 $\text{encLen}(\text{kept})$；
- 与 $s[i-1]$ **不同**的字符必须全部删除，共 $\text{del}$ 个（保留任意一个都会把这段切断，而那等价于枚举更靠右的区间左端，已被其他 $p$ 覆盖）。

$$dp[i][j] \leftarrow \min_{\text{del} \le j} \Bigl( dp[p-1][\,j-\text{del}\,] + \text{encLen}(\text{kept}) \Bigr)$$

前缀 $s[0..p-2]$ 用剩余预算 $j - \text{del}$ 独立求解，两段贡献直接相加——因为前缀方案的串**不以** $s[i-1]$ 结尾时两段互不干扰，即便恰好以它结尾，真实拼接只会因合并而**更短**（见 §5 引理 1），$\min$ 聚合下不吃亏。

### 3.4 示例演算

![示例 aaabcccd k=2 的最优路径走查](images/wc199_q4_example_walkthrough.svg)

以 $s = $ `"aaabcccd"`、$k = 2$ 走查最优路径：

1. **顶层 $dp[8][2]$**：走决策 A，删掉末尾孤立的 `'d'$，转入 $dp[7][1]$；
2. **$dp[7][1]$**：末字符是 `'c'`，走决策 B，区间左端扫到 $[3, 6] = $ `"bccc"`：删 `'b'`（$\text{del} = 1$）、保留 `'ccc'`（$\text{kept} = 3$，贡献 $\text{encLen}(3) = 2$），转入 $dp[3][0] + 2$；
3. **$dp[3][0]$**：前缀 `"aaa"` 无预算可用，整段保留，$\text{encLen}(3) = 2$。

合计 $dp[8][2] = 2 + 2 = 4$，对应删除集 $\{s_4= $ `'b'`$,\ s_7= $ `'d'`$\}$，剩余 `"aaaccc"` → `"a3c3"`。对比：不删长度 6，只删 `'b'` 或只删 `'d'$ 都是 5——两次删除分别来自「促合并消孤段」与「删段尾孤立字符」两种动机。

## 4. 算法细节

1. **encLen 的实现**：按阈值三分支（`c <= 1` / `c <= 9` / `c <= 99` / 其余）最直白；等价闭式为 $c \le 1$ 时取 $c$、否则 $1 + $ 十进制位数。注意 $\text{encLen}(0) = 0$（空段无贡献）。

2. **决策 B 的单调剪枝**：区间左端 $p$ 向左移动时只会**扩大**区间，$\text{del}$ 单调不减。一旦 $\text{del} > j$，更左的 $p$ 只会更贵，直接 `break`。这使内层循环远快于最坏 $O(n)$。

3. **状态语义取「至多 $j$」而非「恰好 $j$」**：由引理 2（删多不劣），两者最优值相同；「至多」语义让转移无需关心预算是否用完，$dp[n][k]$ 直接就是答案。

4. **决策 B 的记账是真实长度的上界**：若前缀方案的串恰好以 $s[i-1]$ 结尾，拼接后两段合并、真实长度**小于**记账值。由引理 1 保证记账值不低估任何真实方案（可行性方向），而 $\min$ 聚合使上界不影响最优性——这正是 §5 证明的枢纽。

5. **为什么必须逐字符 DP**：段的边界随删除动态变化（`"aabaa"` 删 `'b'` 后两段 `a` 合并），无法预先固定段结构；「位置 × 预算」的状态把合并隐式交给区间枚举表达。

## 5. 正确性证明

记 $\text{OPT}(i, j)$ 为前 $i$ 个字符、至多删 $j$ 个的最短 RLE 长度。

**引理 1（子可加性）**：对非负整数 $a, b$，$\text{encLen}(a+b) \le \text{encLen}(a) + \text{encLen}(b)$。

**证明**：$a = 0$ 或 $b = 0$ 时取等。设 $a, b \ge 1$，按 $a + b$ 所在档位讨论：

- $2 \le a+b \le 9$：左边 $\le 2$，右边 $\ge 1 + 1 = 2$；
- $10 \le a+b \le 99$：左边 $= 3$。若 $\min(a,b) \ge 2$，右边 $\ge 4$；若 $\min(a,b) = 1$，另一数 $\ge 9$，其贡献 $\ge 2$，右边 $\ge 3$；
- $a + b = 100$：左边 $= 4$。若 $\min(a,b) = 1$，另一数 $= 99$ 贡献 $3$，右边 $= 4$；否则两边均 $\ge 4$。∎

**引理 2（删多不劣）**：$\text{encLen}$ 关于段长单调不减；从任一保留子序列中再多删一个字符，RLE 长度不增。从而 $\text{OPT}(i, j)$ 关于 $j$ 单调不增。

**证明**：多删一个字符，或使某段长减一（贡献不增），或使相邻两个同字符段合并（新段贡献由引理 1 不超过原两段之和），其余段不变。又 $j$ 增大时可行解集合只扩不缩，故 OPT 单调不增。∎

**定理**：对所有 $0 \le i \le n$、$0 \le j \le k$，$dp[i][j] = \text{OPT}(i, j)$。

**证明**：对 $i$ 强归纳，$i = 0$ 时空串 RLE 为 0，两边相等。设 $i \ge 1$。

**（一）$dp[i][j] \ge \text{OPT}(i, j)$**（每个 dp 值都不低估真实可达长度）：归纳证明每个转移值都被某个可行方案的长度不超过。

- 决策 A：归纳取出 $(i-1, j-1)$ 的最优方案（长度 $dp[i-1][j-1]$），再删 $s[i-1]$ 即得 $(i, j)$ 的可行方案，长度不变；
- 决策 B：归纳取出 $(p-1,\, j - \text{del})$ 的最优方案，设其串为 $T$（长度 $dp[p-1][j-\text{del}]$）。保留区间内全部 $\text{kept}$ 个同类字符、删除全部 $\text{del}$ 个异类字符，得 $(i, j)$ 的可行方案，串为 $T \cdot c^{\text{kept}}$（$c = s[i-1]$），总删除数 $\le (j - \text{del}) + \text{del} = j$。若 $T$ 不以 $c$ 结尾则 $\text{RLE}(T \cdot c^{\text{kept}}) = \text{RLE}(T) + \text{encLen}(\text{kept})$；若 $T$ 以 $c^u$ 结尾，则由引理 1，$\text{encLen}(u + \text{kept}) \le \text{encLen}(u) + \text{encLen}(\text{kept})$，拼接后长度仍然 $\le dp[p-1][j-\text{del}] + \text{encLen}(\text{kept})$。

**（二）$dp[i][j] \le \text{OPT}(i, j)$**（每个最优解都被某个转移覆盖）：取 $(i, j)$ 的一个最优方案 $S$，$D$ 为其删除集，$\text{RLE}(S) = \text{OPT}(i, j)$。

- **情形 1（$S$ 删除 $s[i-1]$）**：把 $S$ 限制在前 $i-1$ 个字符上，是 $(i-1, j-1)$ 的可行方案且串不变，故 $\text{OPT}(i-1, j-1) \le \text{OPT}(i, j)$。由归纳与决策 A，$dp[i][j] \le dp[i-1][j-1] = \text{OPT}(i-1, j-1) \le \text{OPT}(i, j)$。

- **情形 2（$S$ 保留 $s[i-1]$）**：记 $c = s[i-1]$，$t$ 为 $S$ 的剩余串。$t$ 的最后一个字符是 $s[i-1]$，故 $t$ 的**末段**为 $c^m$（$m \ge 1$）。设段成员（保留位置）为 $r_1 < \cdots < r_m = i-1$，$P$ 为 $r_1$ 之前最后一个保留位置（无则记 $-1$）。则：

  （i）区间 $(P,\, i-1]$ 内的**非 $c$ 字符全部被 $S$ 删除**——否则它会出现在 $t$ 中把末段切断，与末段从 $r_1$ 开始矛盾；
  （ii）区间 $(P,\, i-1]$ 内**保留**的字符恰为段成员、均为 $c$（由 $P$ 的极大性与 (i)）。

  记区间内被删除的 $c$ 字符有 $d''$ 个，分两种子情形：

  - **2a（$d'' = 0$）**：取决策 B、区间 $[r_1,\, i-1]$：区间内恰有 $\text{kept} = m$ 个 $c$、$\text{del} = \Delta$ 个非 $c$（全删）。$S$ 在前缀 $[0, r_1-1]$ 上的删除数 $d_{\text{pre}}$ 满足 $d_{\text{pre}} + \Delta \le j$；其前缀串 $A$（为空或以 $\ne c$ 结尾，后者因 $P$ 若保留则 $s[P] \ne c$，否则 $P$ 应属末段）满足 $\text{RLE}(S) = \text{RLE}(A) + \text{encLen}(m)$。由归纳，$dp[r_1][j - \Delta] = \text{OPT}(r_1, j - \Delta) \le \text{RLE}(A)$，故
    $$dp[i][j] \le dp[r_1][j-\Delta] + \text{encLen}(m) \le \text{RLE}(A) + \text{encLen}(m) = \text{OPT}(i, j).$$

  - **2b（$d'' \ge 1$，交换论证）**：取区间内最后一个被删除的 $c$ 字符位置 $q$（$q < i-1$，因 $S$ 保留 $i-1$）。构造 $S'$：**把 $q$ 改为保留、把 $i-1$ 改为删除**，删除次数不变。由 (i)(ii)，$(P,\, i-1)$ 内 $S'$ 保留的字符是「原段成员去掉 $i-1$、加上 $q$」，共 $m$ 个且均为 $c$、中间无其他保留字符，故 $S'$ 的串为 $A \cdot c^m$，$\text{RLE}(S') = \text{RLE}(S) = \text{OPT}(i, j)$。但 $S'$ 删除了 $s[i-1]$，由情形 1 的论证即得 $dp[i][j] \le \text{OPT}(i, j)$。∎

> 💡 **情形 2b 的直觉**：在段**内部**删一个 $c$，等价于删**段尾**的 $c$——段长不变、编码不变。因此任何最优解都能转化为「若干次决策 A（删尾 / 删段内同类）+ 每段恰好一次决策 B」的形态，这正是转移全集所覆盖的方案空间。

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 k)$。状态数 $O(nk)$；决策 A $O(1)$，决策 B 每状态向左扫描至多 $O(n)$，且 $\text{del} > j$ 时提前 break，实际常数远小于最坏值。$n = 100$、$k \le 100$ 时约 $10^6$ 次基本运算，轻松通过。
- **空间复杂度**：$O(nk)$，即约 $10^4$ 个整数的二维表。决策 B 依赖任意更小的行 $dp[p-1][\cdot]$（$p-1 < i$），无法滚动压缩到一维；本题规模下无需优化。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int getLengthOfOptimalCompression(string s, int k) {
        int n = s.size();
        const int INF = 1e9;
        // dp[i][j] = 前 i 个字符、至多删 j 个的最短 RLE 长度
        vector<vector<int>> dp(n + 1, vector<int>(k + 1, INF));
        for (int j = 0; j <= k; ++j) dp[0][j] = 0;

        for (int i = 1; i <= n; ++i) {
            for (int j = 0; j <= k; ++j) {
                // 决策 A：删除 s[i-1]
                if (j > 0) dp[i][j] = min(dp[i][j], dp[i - 1][j - 1]);
                // 决策 B：保留 s[i-1]，向左合并同字符段
                int kept = 0, del = 0;
                for (int p = i; p >= 1; --p) {          // 区间 [p-1, i-1]
                    if (s[p - 1] == s[i - 1]) ++kept;
                    else                          ++del;
                    if (del > j) break;                  // 更左只会更贵
                    dp[i][j] = min(dp[i][j], dp[p - 1][j - del] + encLen(kept));
                }
            }
        }
        return dp[n][k];
    }
  private:
    static int encLen(int c) {
        if (c <= 1)  return c;   // 0 -> 0, 1 -> 1（单字符不附计数）
        if (c <= 9)  return 2;   // "a9"
        if (c <= 99) return 3;   // "a99"
        return 4;                // "a100"（n <= 100 封顶）
    }
};
```

### Python

```python
class Solution:
    def getLengthOfOptimalCompression(self, s: str, k: int) -> int:
        n = len(s)

        def enc_len(c: int) -> int:
            if c <= 1:
                return c
            if c <= 9:
                return 2
            if c <= 99:
                return 3
            return 4

        INF = float('inf')
        # dp[i][j] = 前 i 个字符、至多删 j 个的最短 RLE 长度
        dp = [[INF] * (k + 1) for _ in range(n + 1)]
        for j in range(k + 1):
            dp[0][j] = 0

        for i in range(1, n + 1):
            for j in range(k + 1):
                # 决策 A：删除 s[i-1]
                if j > 0:
                    dp[i][j] = min(dp[i][j], dp[i - 1][j - 1])
                # 决策 B：保留 s[i-1]，向左合并同字符段
                kept = del_cnt = 0
                for p in range(i, 0, -1):        # 区间 [p-1, i-1]
                    if s[p - 1] == s[i - 1]:
                        kept += 1
                    else:
                        del_cnt += 1
                    if del_cnt > j:
                        break                    # 更左只会更贵
                    dp[i][j] = min(dp[i][j], dp[p - 1][j - del_cnt] + enc_len(kept))
        return dp[n][k]
```

## 8. 边界情况与易错点

1. **encLen 阈值表**：$1 \mapsto 1$（单字符**不**附加 `'1'`）、$2 \sim 9 \mapsto 2$、$10 \sim 99 \mapsto 3$、$100 \mapsto 4$。最容易错的是把单字符记成 2 位，或忘掉 100 这一档（$n \le 100$ 时恰好可能出现 `a100`）。

2. **多位数计数**：11 个 `a` 编码 `"a11"` 长度 3（示例 3），计数不是一位数；同理删 1 个把段长 10 压到 9、100 压到 99 各省 1 位（示例 4），DP 会自动捕捉，手写贪心却容易漏。

3. **$k \ge n$**：全删空，答案 0。DP 经决策 A 链自动覆盖，无需特判。

4. **$n = 1$**：$k = 0$ 时答案 1，$k \ge 1$ 时答案 0。

5. **决策 B 区间必须包含 $s[i-1]$ 自身**：内层 $p$ 从 $i$ 开始（而非 $i-1$），保证末字符被计入 $\text{kept}$。

6. **break 条件是 $\text{del} > j$ 而非 $\ge j$**：$\text{del} = j$ 时区间仍可行，只是前缀预算归零；用错会漏解。

7. **不要按原始段贪心**：`"aabaa"`、$k=1$，删中间 `'b'` 得 `"a4"`（2），优于删任何 `'a'`（长度 4）。合并与阈值两种收益互相依赖，必须交给 DP 统一权衡。

8. **「至多」语义**：转移用 $dp[p-1][j - \text{del}]$ 把剩余预算**全部**交给前缀，不要求恰好用完；由引理 2 这不损失最优性。

**延伸思考**：

- 把「删除」改成「修改为任意小写字母」，最优结构如何变化？段字符可以改写，状态需要额外携带段字符信息，复杂度显著上升，值得一试。
- 若要求输出达到最短长度的**具体删除方案**，在 DP 表上记录每个状态的转移来源回溯即可。
- 若 $n$ 放大到 $10^5$：$O(n^2 k)$ 不再可行，需要利用「encLen 只有 4 档」的结构做更紧的建模（例如按段长档位合并决策），目前没有已知的线性解法，是很好的开放练习。
