# LeetCode 子树中标签相同的节点数 题解

## 1. 题目概述

- **标题 / 题号**：子树中标签相同的节点数（#1519，medium）
- **链接**：https://leetcode.cn/problems/number-of-nodes-in-the-sub-tree-with-the-same-label/
- **来源**：LeetCode 第 198 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、计数

**题意**：给一棵 $n$ 个节点的**无向无环树**（`edges` 只给边，不定向），节点编号 $0$ 到 $n-1$，以节点 $0$ 为根。每个节点 $i$ 有一个小写字母标签 $\text{labels}[i]$。要求返回长度为 $n$ 的数组 $\text{ans}$，其中 $\text{ans}[i]$ 为节点 $i$ 的**子树**（$i$ 自己加上它的全部后代）中标签与 $\text{labels}[i]$ 相同的节点个数。

**约束**：

- $1 \le n \le 10^5$
- $\text{edges.length} = n - 1$，边互不相同、无自环，构成有效树
- $\text{labels}$ 仅由小写英文字母组成

> 💡 **审题关键**：① 边是**无向**的，需要先「定向」成以 $0$ 为根的有根树；② 子树**包含节点自身**，所以答案至少是 1（示例 2 里叶子的答案都是 1 正是提示）；③ 一次遍历要同时回答**所有**节点的统计问题，这决定了做法必须是「信息上传」而非逐点查询。

## 2. 示例

**示例 1**

```text
输入：n = 7, edges = [[0,1],[0,2],[1,4],[1,5],[2,3],[2,6]], labels = "abaedcd"
输出：[2,1,1,1,1,1,1]
解释：节点 0 标签 'a'，其子树是整棵树，标签序列 a,b,a,e,d,c,d，
      'a' 恰出现 2 次（节点 0 和 2），故 ans[0] = 2；
      其余节点子树里自己的标签都只出现 1 次。
```

**示例 2**

```text
输入：n = 4, edges = [[0,1],[1,2],[0,3]], labels = "bbbb"
输出：[4,2,1,1]
解释：全部标签相同：根 0 的子树 4 个节点全为 'b'；节点 1 的子树 {1,2} 共 2 个。
```

**示例 3**

```text
输入：n = 5, edges = [[0,1],[0,2],[1,3],[0,4]], labels = "aabab"
输出：[3,2,1,1,1]
解释：节点 1 的子树 {1,3} 标签都是 'a'，ans[1] = 2；
      根 0 的子树标签序列 a,a,b,a,b，'a' 出现 3 次。
```

## 3. 解题思路

### 3.1 暴力思路：逐节点独立搜索

最直接的做法：枚举每个节点 $i$，从 $i$ 出发 DFS/BFS 它的子树，数一遍标签等于 $\text{labels}[i]$ 的节点数。每个节点最多花 $O(n)$，总计 $O(n^2)$；$n = 10^5$ 时约 $10^{10}$ 次操作，**必然超时**。

> 💡 浪费在于**父子子树高度重叠**：父节点的子树 = 自身 + 各子节点的子树。逐点独立统计，同一棵子树被反复扫描了很多遍。正确姿势是让子节点把「子树信息」**向上传递**一次，父节点只做汇总。

### 3.2 核心观察：子树频次向量，自底向上合并

![核心观察：子树频次向量按位相加自底向上合并](images/wc198_q2_subtree_merge.svg)

给每个节点 $u$ 定义一个**长度 26 的频次向量** $\text{cnt}[u]$，表示 $u$ 的子树中每个小写字母出现的次数。由子树的递归结构直接得到递推式：

$$\text{cnt}[u] \;=\; \mathbf{e}_{\text{labels}[u]} \;+\; \sum_{v \in \mathrm{children}(u)} \text{cnt}[v],$$

其中 $\mathbf{e}_c$ 表示字母 $c$ 那一位为 1、其余位为 0 的单位向量。向量加法是**逐位相加**，而答案就是

$$\text{ans}[u] = \text{cnt}[u]\big[\text{labels}[u]\big].$$

> 💡 **为什么这是本质优化**：每个节点只把自己算一次、把每个子节点的向量合并一次——每条树边恰好承担一次 $O(26)$ 的合并工作量，总代价从 $O(n^2)$ 降到 $O(26n)$。频次向量的合并是**可结合**的（全是加法），所以「先子后父」的任何顺序都正确，这正是后序 DFS 能工作的原因。

### 3.3 算法流程：BFS 定序 + 逆序合并（迭代写法）

![算法流程：BFS 定序与逆序合并两阶段流程](images/wc198_q2_bfs_reverse_flow.svg)

「先子后父」理论上用后序递归即可，但本题 $n \le 10^5$，**链形树的递归深度可达 $10^5$**：Python 默认递归上限只有 1000，即便调大 `setrecursionlimit` 也有 CPython 栈溢出风险；C++ 默认栈空间下十万层递归同样可能 RE。周赛实战中对 $10^5$ 规模的树题，建议**默认写迭代版**：

1. **建邻接表**：无向边两端都存。
2. **BFS 定序**：从根 $0$ 出发，记录访问序列 `order` 与每个节点的 `parent`（访问邻居时跳过来时的父节点，即完成定向）。树无环，每个节点恰好入队一次。
3. **初始化**：$\text{cnt}[u][\text{labels}[u]] = 1$（把自己先记上）。
4. **逆序遍历 `order`**：BFS 序天然「父先于子」，倒过来就保证处理 $u$ 时其所有子节点都已处理完——先取 $\text{ans}[u] = \text{cnt}[u][\text{labels}[u]]$，再把 $\text{cnt}[u]$ 整行逐位加进 $\text{cnt}[\text{parent}[u]]$（根节点无父，跳过合并）。

### 3.4 示例演算

![示例演算：逆 BFS 序逐步合并频次向量](images/wc198_q2_example_walkthrough.svg)

以示例 1 为例（树形与标签见 §3.2 插图，节点 $0{:}a$，子女 $1{:}b$、$2{:}a$，孙辈 $4{:}d$、$5{:}c$、$3{:}e$、$6{:}d$）。BFS 序为 $0,1,2,4,5,3,6$，逆序遍历过程如下（只列非零位）：

| 步 | 处理节点 | 此刻 $\text{cnt}[u]$ | $\text{ans}[u]$ | 合并去向 |
|----|---------|----------------------|-----------------|----------|
| 1 | $6\ (d)$ | d:1 | 1 | → cnt[2] |
| 2 | $3\ (e)$ | e:1 | 1 | → cnt[2] |
| 3 | $5\ (c)$ | c:1 | 1 | → cnt[1] |
| 4 | $4\ (d)$ | d:1 | 1 | → cnt[1] |
| 5 | $2\ (a)$ | a:1, d:1, e:1 | 1 | → cnt[0] |
| 6 | $1\ (b)$ | b:1, c:1, d:1 | 1 | → cnt[0] |
| 7 | $0\ (a)$ | a:2, b:1, c:1, d:2, e:1 | **2** | 根，无合并 |

最终 $\text{ans} = [2,1,1,1,1,1,1]$，与预期一致 ✓。

## 4. 算法细节

1. **无向边定向**：BFS 时为每个节点记录 `parent`，扩展邻居时跳过 `v == parent[u]`。树中无环，每个节点只会被访问一次，**无需 visited 数组**。
2. **「队列只增不减」写法**：`order` 数组同时充当队列与最终 BFS 序——用下标 `i` 当队头指针向后扫，扫到哪补到哪，一次遍历完成 BFS，省去真正的双端队列。
3. **先自报到再合并**：初始化就让 $\text{cnt}[u]$ 在自身标签位为 1，之后逆序处理时无需再单独「+1 自身」，取答案、整行上交，逻辑最短。
4. **合并顺序**：「取 $\text{ans}[u]$ → 合并进父」的固定顺序。合并进父不会修改 $\text{cnt}[u]$ 本身，两者其实互不干扰，但固定顺序能避免「先上交再取数」的心智负担。
5. **字母表常数 26**：频次向量长度取标签种类数（26）。若标签换成任意字符串，需换哈希表逐键合并，复杂度变为 $O(\sum \text{子树不同标签数})$。

## 5. 正确性证明

**引理 1（先子后父）**：逆 BFS 序中，任意节点 $u$ 的所有子节点都排在 $u$ 之前。

**证明**：BFS 中节点 $u$ 出队时才把其子节点入队，故对任意父子对 $(p, c)$，BFS 序中 $p$ 严格排在 $c$ 之前。逆序遍历反转全部位置关系，子节点先于父节点。∎

**引理 2（频次向量聚合正确）**：轮到逆序遍历处理节点 $u$ 时，$\text{cnt}[u]$ 恰等于 $u$ 子树内各标签的频次向量。

**证明**：对 $u$ 在逆序中的位置归纳。

- **基础**：逆序第一个节点是 BFS 序的最后一个。若它有子节点，子节点必然在它之后入队，与「最后一个」矛盾，故它是叶子，$\text{cnt}[v] = \mathbf{e}_{\text{labels}[v]}$ 正确。
- **归纳**：设结论对所有排在 $u$ 之前的节点成立。$u$ 的每个子节点 $c$ 由引理 1 排在 $u$ 前，且处理 $c$ 时算法已把彼时等于 $\text{freq}(\text{subtree}(c))$ 的 $\text{cnt}[c]$（归纳假设）逐位加进了 $\text{cnt}[u]$。这些加法均发生在处理 $u$ 之前，故此刻
$$\text{cnt}[u] = \mathbf{e}_{\text{labels}[u]} + \sum_{c \in \mathrm{children}(u)} \text{freq}(\text{subtree}(c)) = \text{freq}(\{u\} \cup \textstyle\bigcup_{c} \text{subtree}(c)) = \text{freq}(\text{subtree}(u)).$$
∎

**定理**：算法输出的 $\text{ans}[u]$ 等于 $u$ 的子树中标签与 $\text{labels}[u]$ 相同的节点数（含自身）。

**证明**：算法在处理 $u$ 时取 $\text{ans}[u] = \text{cnt}[u][\text{labels}[u]]$。由引理 2，此刻 $\text{cnt}[u]$ 是 $\text{subtree}(u)$ 的频次向量，其第 $\text{labels}[u]$ 位即子树中该标签的节点个数，且初始自报到保证了自身被计入。∎

## 6. 复杂度分析

- **时间复杂度**：$O(26n)$。建邻接表与 BFS 各 $O(n)$；初始化 $n$ 个频次向量 $O(n)$；逆序遍历中每条树边恰好触发一次 26 位合并，共 $26(n-1)$ 次加法。$n = 10^5$ 时约 $2.6 \times 10^6$ 次操作，轻松通过。
- **空间复杂度**：$O(26n)$。频次矩阵 $\text{cnt}$ 是大头（$n = 10^5$ 约占 $2.6 \times 10^6$ 个整数）；邻接表、`order`、`parent` 各 $O(n)$。若极端卡内存，可改为「欧拉序 + 离线区间计数」或递归栈上复用数组（见延伸思考），本题无此必要。

## 7. 参考代码

### C++（BFS 定序 + 逆序合并，全程迭代）

```cpp
class Solution {
  public:
    vector<int> countSubTrees(int n, vector<vector<int>>& edges, string labels) {
        vector<vector<int>> adj(n);
        for (auto& e : edges) {
            adj[e[0]].push_back(e[1]);
            adj[e[1]].push_back(e[0]);
        }

        vector<int> parent(n, -1), order;
        order.reserve(n);
        order.push_back(0);
        for (int i = 0; i < n; ++i) {          // order 只增不减，下标即队头
            int u = order[i];
            for (int v : adj[u]) {
                if (v != parent[u]) {          // 跳过来时的父节点 = 无向边定向
                    parent[v] = u;
                    order.push_back(v);
                }
            }
        }

        vector<array<int, 26>> cnt(n);
        for (int i = 0; i < n; ++i) cnt[i][labels[i] - 'a'] = 1;   // 先把自己算上

        vector<int> ans(n);
        for (int i = n - 1; i >= 0; --i) {      // 逆 BFS 序：先子后父
            int u = order[i];
            ans[u] = cnt[u][labels[u] - 'a'];   // 此刻 cnt[u] 已聚合整棵子树
            if (parent[u] != -1) {
                for (int c = 0; c < 26; ++c)   // 整行逐位上交
                    cnt[parent[u]][c] += cnt[u][c];
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countSubTrees(self, n: int, edges: List[List[int]], labels: str) -> List[int]:
        adj = [[] for _ in range(n)]
        for a, b in edges:
            adj[a].append(b)
            adj[b].append(a)

        parent = [-1] * n
        order = [0]
        for i in range(n):                      # order 只增不减，下标即队头
            u = order[i]
            for v in adj[u]:
                if v != parent[u]:              # 无向边定向
                    parent[v] = u
                    order.append(v)

        cnt = [[0] * 26 for _ in range(n)]
        for i, ch in enumerate(labels):
            cnt[i][ord(ch) - 97] = 1            # 先把自己算上

        ans = [0] * n
        for u in reversed(order):               # 逆 BFS 序：先子后父
            ans[u] = cnt[u][ord(labels[u]) - 97]
            p = parent[u]
            if p != -1:
                row = cnt[p]
                for c in range(26):
                    row[c] += cnt[u][c]
        return ans
```

> 💡 递归后序版（每个节点 `dfs` 返回 26 维数组）同样正确，但链形树下有爆栈风险，周赛中 $n \ge 10^5$ 的树题建议直接落笔迭代版。递归版与「全局单数组 + 差分还原」的空间优化讨论见[站内每日题解 1519](../../solution/1501-1600/1519_带给定标签的二叉树中的节点数.md)。

## 8. 边界情况与易错点

1. **链形树递归爆栈**：$n = 10^5$ 且边为 $[0,1],[1,2],\dots$ 时树深 $10^5$，Python 默认递归上限 1000（调大后仍有段错误风险），C++ 默认栈空间也悬。BFS 定序 + 逆序合并彻底规避递归，是本题最值得沉淀的工程习惯。
2. **无向边必须跳父**：比较的是 `v != parent[u]`（当前节点 $u$ 的父），而不是 `v != u`；跳错对象会沿无向边走回头路，轻则重复统计、重则死循环。
3. **别忘了「+1 自身」**：若初始化时不在自身标签位记 1，所有答案会统一少 1（叶子答案变 0，与「子树包含自身」的题意直接矛盾）。
4. **合并必须整行逐位**：只把自身标签那一位传给父是错的——父节点可能同时需要其他字母的计数（示例 1 根节点聚合出 a,b,c,d,e 五种字母）。
5. **$n = 1$（最小输入）**：`edges` 为空，`order = [0]`，逆序处理根时 `parent[0] = -1` 跳过合并，输出 `[1]`，无需特判。
6. **全同标签对拍**：`labels` 全为同一字母时 $\text{ans}[0] = n$、其余按子树大小，是检验合并方向是否写反的最短测试。
7. **数组下标取整**：`labels[i] - 'a'` 只对**小写字母**合法，题面保证成立；若自行扩展字符集，先统一做偏移映射。

**延伸思考**：

- **欧拉序离线解法**：迭代 DFS 求出每个节点的进出时间戳 $\text{in}[u] \le \text{out}[u]$，则「$v$ 在 $u$ 子树中」等价于 $\text{in}[u] \le \text{in}[v] \le \text{out}[u]$。按字母分组、组内按 $\text{in}$ 排序后二分，即得 $\text{ans}[u]$——把树形统计转成区间计数，$O(n \log n)$，空间 $O(n)$，是标签种类极多时（哈希合并退化）的替代方案。
- **值域扩展**：标签换成任意字符串或大字符集时，26 维数组换成哈希表逐键合并；此时「小到合并」（DSU on tree / 启发式合并，轻儿子向重儿子合并）能把总复杂度压到 $O(n \log n)$ 级。
- **动态变体**：若要求支持「修改某节点标签 + 实时查询任一节点的 $\text{ans}$」，单次上传不再够用，需要树链剖分或欧拉序 + 树状数组维护 26 棵计数树，把「子树修改/查询」落到区间上。
