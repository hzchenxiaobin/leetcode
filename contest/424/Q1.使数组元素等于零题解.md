# LeetCode 使数组元素等于零 题解

## 1. 题目概述

- **标题 / 题号**：使数组元素等于零（#3354，easy）
- **链接**：https://leetcode.cn/problems/make-array-elements-equal-to-zero/
- **来源**：LeetCode 第 424 场周赛 Q1
- **难度**：简单
- **标签**：数组、前缀和、模拟

**题意**：给定整数数组 `nums`，选择一个满足 `nums[curr] == 0` 的起点 `curr` 和一个移动方向（左或右），然后反复执行：若 `curr` 越界则过程结束；若 `nums[curr] == 0` 沿当前方向走一步；若 `nums[curr] > 0` 则将其减 1、**反转方向**、沿新方向走一步。若过程结束后数组**全部元素变为 0**，则该「起点 + 方向」组合有效。求有效组合数。

**约束**：

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`
- 至少存在一个元素满足 `nums[i] == 0`

## 2. 示例

**示例 1**

```text
输入：nums = [1,0,2,0,3]
输出：2
解释：选 curr = 3 向左移动、或选 curr = 3 向右移动，均能把所有元素清零。
```

**示例 2**

```text
输入：nums = [2,3,4,0,4,1,0]
输出：0
解释：不存在有效的选择方案。
```

**示例 3**

```text
输入：nums = [2,0,1]
输出：1
解释：只有「curr = 1 向左移动」有效：(2,0,1) → 撞 2 变 (1,0,1) → 撞 1 变 (1,0,0)
      → 撞 2 变 (0,0,0) → 向右越界。向右出发则会在左侧清零后从左侧越界，右侧剩 1。
```

## 3. 解题思路

### 3.1 暴力思路：直接模拟

签到题最直接的写法：枚举每个零位置 `i` 和两个方向，按题意逐格模拟，结束后检查是否全零。

```cpp
class Solution {
public:
    int countValidSelections(vector<int>& nums) {
        int n = nums.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            if (nums[i] != 0) continue;
            for (int dir : {1, -1}) {
                vector<int> a = nums;
                int curr = i, step = dir;
                while (curr >= 0 && curr < n) {
                    if (a[curr] == 0) {
                        curr += step;
                    } else {
                        a[curr] -= 1;
                        step = -step;
                        curr += step;
                    }
                }
                if (all_of(a.begin(), a.end(), [](int v) { return v == 0; })) ++ans;
            }
        }
        return ans;
    }
};
```

复杂度：至多 $2n$ 个「起点 + 方向」组合；每次模拟中，每次碰撞使总和减 1，故碰撞次数不超过 $S+1$（$S = \sum nums \le 10^4$），相邻两次碰撞之间至多移动 $n$ 步，单次模拟为 $O(n \cdot S)$，整体最坏约 $10^8$ 步。C++ 足够通过（实际数据远达不到最坏界），但 **Python 有超时风险**，且没有沉淀任何观察。下面把它优化到 $O(n)$。

### 3.2 核心观察：弹跳模型 —— 碰撞左右交替

![小球在两侧最近正数之间往复弹跳](images/wc424_q1_bounce_model.svg)

把小球想成**弹球**：正数是会被消耗的「挡板」。关键在于确认小球究竟在哪里碰撞：

- 任意时刻，小球总是在「起点左侧最近的未清零正数 `q`」和「起点右侧最近的未清零正数 `p`」之间往复——因为**两个碰撞点之间全是 0**（初始时由 `q`、`p` 的最近性保证；某个挡板被撞成 0 后，外侧下一个正数顶替，区间内依然全是 0）。
- 于是每次碰撞后小球反向，穿过中间的零区间，**必然撞向另一侧的最近挡板**：碰撞严格按「右、左、右、左、⋯」交替（向右出发则首撞在右）。
- 每次碰撞恰使**所在侧的剩余和减 1**。设起点左侧和为 $SL$、右侧和为 $SR$，过程就是把 $(SR, SL)$ 交替地减一，直到某侧变 0 时小球正走向该侧而**越界结束**。

### 3.3 判定条件：前缀和 O(1) 判定每个起点

![前缀和判定条件：SR 与 SL 只差 0 或 1](images/wc424_q1_prefix_condition.svg)

由交替性数一数碰撞次数即可得到判定条件。向右出发时碰撞序列为 $R, L, R, L, \dots$：

- 若**向右越界**结束：末次碰撞在左侧（或从未碰撞），右侧碰撞数 $=$ 左侧碰撞数，全部清零要求 $SR = SL$；
- 若**向左越界**结束：末次碰撞在右侧，右侧碰撞数 $=$ 左侧碰撞数 $+ 1$，全部清零要求 $SR = SL + 1$。

因此：

$$\text{向右出发有效} \iff SR - SL \in \{0, 1\}, \qquad \text{向左出发有效} \iff SL - SR \in \{0, 1\}$$

**算法流程**：

1. 预处理 $total = \sum nums$；
2. 从左到右扫描，维护已遍历元素之和 $pre$（即前缀和）；
3. 遇到 `nums[i] == 0` 时：$SL = pre$，$SR = total - pre$（因 `nums[i] = 0` 无需再减），令 $d = SR - SL = total - 2 \cdot pre$；
4. $d \in \{0, 1\}$ 则向右方案数加一，$d \in \{0, -1\}$ 则向左方案数加一（$d = 0$ 时两个方向都有效，贡献 2）。

### 3.4 示例演算

![示例演算：两个零位置的碰撞链](images/wc424_q1_example_walkthrough.svg)

对 `nums = [1,0,2,0,3]`（$total = 6$）：

| 起点/i | $SL$ | $SR$ | $d = SR - SL$ | 向右 | 向左 | 贡献 |
|--------|------|------|---------------|------|------|------|
| 1 | 1 | 5 | 4 | ✗ | ✗ | 0 |
| 3 | 3 | 3 | 0 | ✓ | ✓ | 2 |

碰撞链（以 $i=3$ 向右为例）：$(3,3) \to (2,3) \to (2,2) \to (1,2) \to (1,1) \to (0,1) \to (0,0)$，右侧清零后小球向右越界，全零 ✓。答案 $= 0 + 2 = 2$，与示例一致。

## 4. 算法细节

1. **前缀和维护**：一遍扫描，`pre` 在处理完下标 `i` 后才累加 `nums[i]`；处理 `i` 时 `pre` 恰为左半和 $SL$。
2. **右半和免计算**：因起点处 `nums[i] == 0`，$SR = total - pre$，不需要「减去 `nums[i]`」的特判。
3. **统一差值**：$d = SR - SL = total - 2 \cdot pre$，只与前缀和有关，判定只看 $d$ 是否落在 $\{0, \pm 1\}$。
4. **方向分别计数**：$d = 0$ 贡献 2（两个方向），$d = \pm 1$ 贡献 1，其余贡献 0；不要合并成「$|d| \le 1$ 计一次」。

## 5. 正确性证明

**引理 1（交替性）**：从零位置 $i$ 出发后，碰撞严格按左右交替发生（向右出发首撞在右），且每次碰撞恰使所在侧剩余和减 1。

**证明**：记某时刻左侧、右侧距起点最近的未清零正数分别为 $q$、$p$。先证开区间 $(q, p)$ 内全是 0：初始时由 $q$、$p$ 的最近性与 $nums[i]=0$ 成立。归纳步：设碰撞前成立，小球撞 $p$ 使其减 1；若 $nums[p]$ 变 0，新的右侧最近正数 $p'$ 在 $p$ 右侧且 $(p, p')$ 全 0，故 $(q, p')$ 仍全 0；左侧同理。于是每次碰撞后小球反向，穿过的区域全是 0，必然走到另一侧最近正数处才再次碰撞，碰撞左右交替；每次碰撞使被撞元素减 1，即该侧剩余和减 1。∎

**引理 2（出口与计数）**：向右出发时，过程结束当且仅当小球「向右移动且右侧剩余和为 0」（向右越界）或「向左移动且左侧剩余和为 0」（向左越界）。前者末次碰撞在左侧（或从未碰撞），此刻右侧碰撞数 $=$ 左侧碰撞数；后者末次碰撞在右侧，右侧碰撞数 $=$ 左侧碰撞数 $+ 1$。方案有效 $\iff$ 结束时两侧剩余和均为 0。

**证明**：由引理 1，碰撞序列为 $R,L,R,L,\dots$，故任意时刻 $\#R \in \{\#L, \#L+1\}$；「向右移动」的时刻（出发时或某次 $L$ 碰撞后）恰有 $\#R = \#L$，「向左移动」的时刻（某次 $R$ 碰撞后）恰有 $\#R = \#L + 1$。小球只在「正走向某侧而该侧已无正数」（即该侧剩余和为 0）时越界。全部清零 $\iff \#R = SR$ 且 $\#L = SL$：若向右越界结束，则 $\#R = \#L$，联立得 $SR = SL$；若向左越界结束，则 $\#R = \#L + 1$，联立得 $SR = SL + 1$。反之，当 $SR = SL$ 时，由 $\#R - \#L \in \{0,1\}$ 与两侧消耗速率对称，两侧同时清零，小球随即向右越界；当 $SR = SL + 1$ 时，右侧恰比左侧多一次碰撞，左侧清零的同一时刻右侧清零且末撞在右，小球向左越界；两种情况均有效。∎

**定理**：起点 $i$ 向右出发有效 $\iff SR - SL \in \{0, 1\}$；向左出发有效 $\iff SL - SR \in \{0, 1\}$。用前缀和对每个零位置 $O(1)$ 判定并计数，即得答案。

**证明**：向右情形由引理 1、2 直接得出。向左情形将数组左右镜像后碰撞过程完全对称，条件相应变为 $SL - SR \in \{0, 1\}$。算法遍历全部零位置并按条件计数，与「枚举所有 (起点, 方向) 判定有效性」的暴力完全等价，故正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一次遍历维护前缀和，每个零位置 $O(1)$ 判定。
- **空间复杂度**：$O(1)$。仅 `total`、`pre`、`ans` 等常数个变量（不计输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countValidSelections(vector<int>& nums) {
        int total = accumulate(nums.begin(), nums.end(), 0);
        int pre = 0, ans = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (nums[i] == 0) {
                int d = total - 2 * pre;
                if (d == 0 || d == 1) ++ans;
                if (d == 0 || d == -1) ++ans;
            }
            pre += nums[i];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countValidSelections(self, nums: List[int]) -> int:
        total = sum(nums)
        pre = 0
        ans = 0
        for x in nums:
            if x == 0:
                d = total - 2 * pre
                if d in (0, 1):
                    ans += 1
                if d in (0, -1):
                    ans += 1
            pre += x
        return ans
```

## 8. 边界情况与易错点

1. **全零数组**（如 `[0]`、`[0,0,0]`）：两侧和均为 0，每个零位置的两个方向都有效，答案是零位置数的两倍（`[0]` 为 2），不要漏掉「方向」也是方案的一部分。
2. **$d = 0$ 贡献 2 不是 1**：左右两侧和相等时向右、向左都有效；若把条件误写成「$|total - 2 \cdot pre| \le 1$ 计一次」会少算一半。
3. **前缀和时机**：处理下标 `i` 时 `pre` 必须尚未加入 `nums[i]`；由于 `nums[i] = 0` 加不加数值一样，但代码顺序不要颠倒，避免在有非零判断的变体里出错。
4. **碰撞点会外移**：挡板被撞成 0 后碰撞点换为外侧下一个正数，交替性不变——推导时不要假设碰撞点固定不动。
5. **暴力模拟的顺序**：每步先判越界，再判当前格是否为 0，否则「减 1、反向、走一步」；顺序写反会差一步。
6. **起点只能选零位置**：题目要求 `nums[curr] == 0`，非零位置不能作为起点（那会立即触发减 1 与反弹，不属于本题定义）。
