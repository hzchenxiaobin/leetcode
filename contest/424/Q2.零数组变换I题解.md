# LeetCode 零数组变换 I 题解

## 1. 题目概述

- **标题 / 题号**：零数组变换 I（#3355，medium）
- **链接**：https://leetcode.cn/problems/zero-array-transformation-i/
- **来源**：LeetCode 第 424 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和、差分数组

**题意**：给定长度为 $n$ 的数组 `nums` 与查询数组 `queries`，其中 `queries[i] = [li, ri]`。对每个查询：在 `nums` 的下标范围 $[l_i, r_i]$ 内**选择一个下标子集**，把选中下标的元素各减 1。**零数组**是所有元素都为 0 的数组。若按顺序处理完所有查询后，能把 `nums` 变成零数组，返回 `true`，否则 `false`。

**约束**：

- $1 \le nums.length \le 10^5$
- $0 \le nums[i] \le 10^5$
- $1 \le queries.length \le 10^5$
- $queries[i].length = 2$，$0 \le l_i \le r_i < n$

## 2. 示例

**示例 1**

```text
输入：nums = [1,0,1], queries = [[0,2]]
输出：true
解释：查询 [0,2] 选下标子集 {0, 2}（下标 1 已是 0 不选），两个元素各减 1
      → [0,0,0]，是零数组。
```

**示例 2**

```text
输入：nums = [4,3,2,1], queries = [[1,3],[0,2]]
输出：false
解释：查询 [1,3] 选 {1,2,3} → [4,2,1,0]；查询 [0,2] 选 {0,1,2} → [3,1,0,0]，
      无论怎么选子集都无法全零。
```

**示例 3**

```text
输入：nums = [2,2,2], queries = [[0,2],[0,1],[1,2]]
输出：true
解释：cover = [2,3,2] ≥ nums，贪心即可：[0,2] 全减 → [1,1,1]；[0,1] 减 → [0,0,1]；
      [1,2] 只减下标 2 → [0,0,0]。
```

## 3. 解题思路

### 3.1 暴力思路：逐查询扫区间

「选子集」有 $2^{r-l+1}$ 种方案无法枚举，但可以直接想一个自然的贪心：**每个查询把区间内当前值大于 0 的下标全部减 1**（已经为 0 的位置不动，避免减成负数）。逐查询扫区间更新，最后检查是否全零。

```cpp
class Solution {
public:
    bool isZeroArray(vector<int>& nums, vector<vector<int>>& queries) {
        for (auto& q : queries)
            for (int j = q[0]; j <= q[1]; ++j)
                if (nums[j] > 0) --nums[j];
        return all_of(nums.begin(), nums.end(), [](int v) { return v == 0; });
    }
};
```

这个贪心本身是**正确**的（下文引理 2 会证明），但复杂度 $O(nq)$ 最高 $10^{10}$，必然超时。瓶颈在于：同一位置被反复扫过，而它真正需要的只是「**总共被覆盖了多少次**」这一个数字。

### 3.2 核心观察：判定只看每个下标的「覆盖次数」

![每个查询对每个下标至多贡献一次减1](images/wc424_q2_diff_coverage.svg)

把「选择子集」翻译成逐下标的语言：

- 每个查询对区间内**每个下标独立地**决定「减 1 / 不减」，即**单个查询对某个下标至多贡献 1 次减 1**；
- 顺序、子集怎么选都只是幌子——查询之间互不干扰，下标 $j$ 能获得的总减量上界恰是**覆盖它的查询个数** $cover(j) = \#\{i : l_i \le j \le r_i\}$；
- 减到负数毫无意义（零数组要求恰好为 0），所以每个下标的命运只由一个不等式决定：

$$\boxed{\;nums[j] \le cover(j)\;}$$

满足则该位可在自己的覆盖次数内恰好清零，否则无论怎么安排都不可能清零。于是问题从「模拟操作」退化为「统计每个下标被多少个区间覆盖」——**区间加减 → 差分数组**。

### 3.3 算法流程：差分数组统计覆盖次数

![算法流程：差分打标记、前缀和还原、逐位判定](images/wc424_q2_algorithm_flow.svg)

1. 建长度 $n+1$ 的差分数组 `diff`，初始全 0；
2. 对每个查询 $[l_i, r_i]$：`diff[l_i] += 1`，`diff[r_i + 1] -= 1`（$r_i+1$ 最大为 $n$，故开 $n+1$ 位）；
3. 从左到右对 `diff` 做前缀和，逐位得到 `cover`，同时比较：一旦 `nums[j] > cover` 立即返回 `false`；
4. 全部通过返回 `true`。

### 3.4 示例演算

![示例演算：diff 数组、cover 还原与逐位判定](images/wc424_q2_example_walkthrough.svg)

对示例 2 `nums = [4,3,2,1]`，`queries = [[1,3],[0,2]]`：

| 下标 $j$ | 0 | 1 | 2 | 3 |
|----------|---|---|---|---|
| `diff` 打标记 | $+1$（$[0,2]$） | $+1$（$[1,3]$） | | $-1$（$[0,2]$），$-1$（$[1,3]$，记在 $j=4$） |
| `cover`（前缀和） | 1 | 2 | 2 | 1 |
| `nums[j]` | **4** | 3 | 2 | 1 |
| 判定 | $4 > 1$ ✗ | $3 > 2$ ✗ | $2 \le 2$ ✓ | $1 \le 1$ ✓ |

下标 0 只被 $[0,2]$ 一个查询覆盖，最多减 1，而它需要减 4，不可能清零 → `false`。对示例 1 `nums = [1,0,1]`：`cover = [1,1,1]`，逐位 $1\le1, 0\le1, 1\le1$ 全部通过 → `true`。

## 4. 算法细节

1. **差分数组长度开 $n+1$**：`diff[r+1] -= 1` 中 $r+1$ 可以等于 $n$，若只开 $n$ 位会越界写。
2. **打标记 $O(1)$**：每个查询只动两个位置， $q$ 个查询共 $O(q)$ 次，与区间长度无关。
3. **前缀和边还原边判定**：`cover` 不需要显式数组，用滚动变量累加 `diff[j]`，顺便与 `nums[j]` 比较，可提前退出。
4. **减量与需要量分开理解**：`cover[j]` 是「至多可用的减量」，实际使用时取 $\min(nums[j], cover[j])$ 即恰好清零；判定只需上界比较。
5. **参数取引用**：`queries` 达 $10^5 \times 2$ 规模，C++ 按值传递会整体拷贝，务必 `vector<vector<int>>&`。

## 5. 正确性证明

**引理 1（上界）**：任意合法操作方案中，下标 $j$ 的总减量不超过 $cover(j)$。

**证明**：单个查询在 $[l_i, r_i]$ 内选一个子集，对任意下标至多贡献 1 次减 1；且只有满足 $l_i \le j \le r_i$ 的查询才可能选中 $j$。故总减量 $\le$ 覆盖 $j$ 的查询数 $cover(j)$。∎

**引理 2（贪心可达）**：按任意顺序处理查询，每个查询把「区间内当前值 $> 0$ 的下标」全部减 1，则最终 $nums[j] = \max(0,\; nums_0[j] - cover(j))$，且过程中任何位置不会变负。

**证明**：对位置 $j$，除覆盖它的查询外，其余查询不触碰 $j$。对覆盖 $j$ 的查询按处理顺序编号 $1, 2, \dots, cover(j)$，归纳证明「处理完第 $k$ 个后 $nums[j] = \max(0, nums_0[j] - k)$」：若当前值为正，本查询选中它，值减 1，与 $k$ 的递增同步；若当前值已为 0，本查询不再选中它（子集可不含 $j$），值保持 0。两种情况均维持归纳不变式，且值始终 $\ge 0$。$k$ 取到 $cover(j)$ 时结论成立。∎

**定理**：`nums` 能被转换为零数组 $\iff$ 对所有 $j$ 都有 $nums[j] \le cover(j)$。其中 $cover$ 可用差分数组在 $O(n + q)$ 内求出。

**证明**：（$\Rightarrow$）若某位 $nums[j] > cover(j)$，由引理 1 该位总减量 $\le cover(j) < nums[j]$，终值必为正，矛盾。（$\Leftarrow$）当所有位满足不等式时，由引理 2，贪心方案下每位终值 $= \max(0, nums[j] - cover(j)) = 0$，即零数组。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + q)$。打标记 $q$ 次、每次 $O(1)$；前缀和还原与判定一遍 $O(n)$。
- **空间复杂度**：$O(n)$。差分数组 $n+1$ 位（滚动前缀和不再需要额外数组，判定也可提前返回）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isZeroArray(vector<int>& nums, vector<vector<int>>& queries) {
        int n = nums.size();
        vector<int> diff(n + 1, 0);
        for (auto& q : queries) {
            ++diff[q[0]];
            --diff[q[1] + 1];
        }
        int cover = 0;
        for (int j = 0; j < n; ++j) {
            cover += diff[j];
            if (nums[j] > cover) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def isZeroArray(self, nums: List[int], queries: List[List[int]]) -> bool:
        n = len(nums)
        diff = [0] * (n + 1)
        for l, r in queries:
            diff[l] += 1
            diff[r + 1] -= 1
        cover = 0
        for j, x in enumerate(nums):
            cover += diff[j]
            if x > cover:
                return False
        return True
```

## 8. 边界情况与易错点

1. **`diff` 越界**：$r_i + 1 = n$ 时要在下标 $n$ 处减 1，数组长度必须是 $n+1$；开成 $n$ 是最常见的一发 WA/RE。
2. **「按顺序处理」是幌子**：每个查询的子集选择相互独立、操作可交换，判定与顺序无关，不要被题面带偏去设计顺序相关策略。
3. **减成负数不算成功**：零数组要求恰好为 0；判定条件是 `nums[j] <= cover[j]` 的**逐位上界比较**，不是「覆盖总和 ≥ 需求总和」。例如 `nums = [3,0]`，`queries = [[0,1],[0,1]]`：覆盖总和 $4 \ge 3$，但 $cover[0] = 2 < 3$，答案仍是 `false`——**分布错配**光看总和发现不了。
4. **`nums[j] = 0` 不需要覆盖**：该位天然满足 $0 \le cover(j)$，哪怕没有任何查询覆盖它。
5. **子集可以为空**：全部清零后剩余的查询选空子集即可，无需担心「必须操作」的误解。
6. **C++ 引用传参**：`queries` 按值传递带来无谓拷贝（$10^5$ 个 `vector`），按引用传递是基本功。
