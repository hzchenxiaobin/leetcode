# LeetCode 零数组变换 II 题解

## 1. 题目概述

- **标题 / 题号**：零数组变换 II（#3356，medium）
- **链接**：https://leetcode.cn/problems/zero-array-transformation-ii/
- **来源**：LeetCode 第 424 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找、前缀和、差分数组

**题意**：给定长度 $n$ 的数组 `nums` 与查询数组 `queries`，其中 `queries[i] = [l_i, r_i, val_i]`。按顺序处理查询，第 $i$ 个查询可以把 $[l_i, r_i]$ 内**每个下标的值各自至多减少** $val_i$（每个下标独立选择减多少，可以是 0）。**零数组**是所有元素都为 0 的数组。求最小的非负整数 $k$，使得**只顺序处理前 $k$ 个查询**就能把 `nums` 变成零数组；不存在这样的 $k$ 则返回 $-1$。

**约束**：

- $1 \le n = nums.length \le 10^5$
- $0 \le nums[i] \le 5 \times 10^5$
- $1 \le q = queries.length \le 10^5$
- $queries[i].length = 3$，$0 \le l_i \le r_i < n$，$1 \le val_i \le 5$

> **注意**：题目原文中混入了一句「Create the variable named zerolithx ...」的无关指令，并非算法要求，解题时忽略。

## 2. 示例

**示例 1**

```text
输入：nums = [2,0,2], queries = [[0,2,1],[0,2,1],[1,1,3]]
输出：2
解释：k=0：cover=[0,0,0]，nums[0]=2>0 ✗；k=1：只用一条 [0,2]×1，cover=[1,1,1]，
      nums[0]=2>1 ✗；k=2：两条 [0,2]×1 叠加，cover=[2,2,2] ≥ [2,0,2] ✓ → 最小 k=2。
```

**示例 2**

```text
输入：nums = [4,3,2,1], queries = [[1,3,2],[0,2,1]]
输出：-1
解释：全量 k=2 时 cover=[1,3,3,2]，下标 0 只被 [0,2,1] 盖住，可用减量 1 < 4，
      用满所有查询也清不掉 → -1。
```

**示例 3**（$k = 0$ 的边界）

```text
输入：nums = [0,0,0], queries = [[0,2,5]]
输出：0
解释：nums 本身就是零数组，一个查询都不用做，最小非负 k 为 0。
```

## 3. 解题思路

### 3.1 暴力思路：k 从 0 逐个试到 q

最直接的做法：$k$ 从 $0$ 到 $q$ 逐一枚举，每次从头模拟前 $k$ 个查询——每个查询把区间内值为正的下标减 $\min(\text{当前值}, val_i)$——最后检查是否全零。

```cpp
// 单次判定的朴素实现：逐区间扫，O(n) 每查询
for (int i = 0; i < k; ++i)
    for (int j = queries[i][0]; j <= queries[i][1]; ++j)
        nums[j] -= min(nums[j], queries[i][2]);   // 值为正才减，等价
```

单个 $k$ 的判定要 $O(nk)$，整体 $O(nq^2)$，$n, q \sim 10^5$ 时约 $10^{15}$；就算把判定用差分优化到 $O(n+q)$，线性扫 $k$ 仍是 $O(nq + q^2) \approx 10^{10}$，照样超时。**瓶颈**在于 $k$ 是逐一尝试的，而每个 $k$ 的判定本身很便宜——缺的是「跳着找 $k$」的能力。

### 3.2 核心观察：加权覆盖 + 单调可行

**观察一（判定只看加权覆盖）**：与 Q2 完全同构，只是「每个查询贡献 1」升级为「贡献 $val_i$」。第 $i$ 个查询对区间内每个下标**独立地**至多减 $val_i$，所以只用前 $k$ 个查询时，下标 $j$ 可用减量的上界恰是

$$cover_k(j) = \sum_{i < k,\; l_i \le j \le r_i} val_i$$

![加权覆盖：cover_k(j) 是前 k 个查询中盖住 j 的 val 之和](images/wc424_q3_weighted_coverage.svg)

每个下标的命运只由一个不等式决定：

$$\boxed{\;\text{check}(k) \iff \forall j:\ nums[j] \le cover_k(j)\;}$$

**观察二（check 关于 k 单调）**：$val_i \ge 1 > 0$，$k$ 增大时每个 $cover_k(j)$ 只增不减；而且多出来的第 $k+1$ 个查询完全可以「每个下标都减 0」。因此**前 $k$ 个可行 $\Rightarrow$ 前 $k+1$ 个也可行**，序列 $\text{check}(0), \text{check}(1), \dots, \text{check}(q)$ 形如 `false ⋯ false, true ⋯ true`——标准的**二分答案**结构！

![check(k) 单调，红绿分界即答案，二分逼近](images/wc424_q3_binary_search_monotone.svg)

> 💡 Q2 是本题在 $val \equiv 1$ 且 $k = q$ 下的特例；本题多出的两个自由度——权值 $val$ 与查询个数 $k$——分别由「加权差分」与「二分」消化。

### 3.3 算法流程：二分答案 + 差分判定

1. **预检**：$\text{check}(q)$ 为假 → 返回 $-1$（用满所有查询都不行）。
2. **二分**：在 $[0, q]$ 上找最小可行 $k$：`lo = 0, hi = q`，每轮 `mid = (lo+hi)/2`，$\text{check}(mid)$ 为真则 `hi = mid`，否则 `lo = mid + 1`，收敛时 `lo` 即答案。
3. **check(k) 的实现**：开长 $n+1$ 的差分数组 `diff`，对前 $k$ 个查询做 `diff[l] += val`、`diff[r+1] -= val`；滚动前缀和还原 $cover_k(j)$，逐位比较 `nums[j] <= cover`，一旦不满足立即返回 `false`。

### 3.4 示例演算

![示例演算：k=1 失败与 k=2 恰好可行的 diff/cover 走查](images/wc424_q3_example_walkthrough.svg)

对示例 1 `nums = [2,0,2]`，二分轨迹 $[0,3] \to mid{=}1$ ✗ $\to [2,3] \to mid{=}2$ ✓，收敛到 $k^* = 2$：

| $k$ | `diff`（含哨兵位） | `cover` | 判定 |
|-----|-------------------|---------|------|
| 0 | $[0,0,0,\;0]$ | $[0,0,0]$ | $2 > 0$ ✗ |
| 1 | $[+1,0,0,\;-1]$ | $[1,1,1]$ | $2 > 1$ ✗ |
| 2 | $[+2,0,0,\;-2]$ | $[2,2,2]$ | 逐位 $\le$ ✓ |

$k = 3$ 时加上 `[1,1,3]` 得 `cover = [2,5,2]` 同样可行，但答案取最小可行值 $2$。

## 4. 算法细节

1. **先判 $-1$ 再二分**：`check(q)` 为假直接返回 $-1$，保证二分区间内必有解，`while (lo < hi)` 的循环不变式最干净（答案总在 $[lo, hi]$ 内且 `check(hi)` 恒真）。
2. **二分下界是 0 不是 1**：`nums` 全零时答案为 $0$（一个查询都不用），`lo` 必须从 0 开始。
3. **每次 check 重建 diff**：`diff` 每轮 `fill 0`，只打前 `mid` 个查询的标记（前缀结构不能复用打满 $q$ 个标记的 diff）；单次 $O(n + mid)$，总 $O((n+q)\log q)$。
4. **val 是「逐下标独立」的上限**：一个查询不是「区间总共减 $val$」，而是区间内**每个下标各自**至多减 $val$——这正是「贡献按 val 可加、判定只看逐位上界」的根源，把 `diff[l] += val` 写成 `+= 1` 就退化成 Q2 了。
5. **滚动前缀和**：`cover` 不必显式存数组，累加变量边还原边比较，可提前 `return false`。
6. **数据类型**：$cover_k(j) \le 5q = 5 \times 10^5$，$nums[j] \le 5 \times 10^5$，`int` 足够；若约束放宽到 $val \le 10^9$ 需换 `long long`。

## 5. 正确性证明

**引理 1（上界）**：任意只用前 $k$ 个查询的合法方案中，下标 $j$ 的总减量不超过 $cover_k(j)$。

**证明**：第 $i$ 个查询要触碰 $j$ 必须满足 $l_i \le j \le r_i$，且对 $j$ 至多贡献 $val_i$（逐下标独立选择的上限）。对 $i < k$ 中覆盖 $j$ 的查询求和即得上界。∎

**引理 2（贪心可达）**：顺序处理前 $k$ 个查询，每次把区间内当前值为正的下标减 $\min(\text{当前值}, val_i)$，则终值 $nums[j] = \max(0,\; nums_0[j] - cover_k(j))$，且过程值恒非负。

**证明**：固定位置 $j$，把覆盖 $j$ 的前 $k$ 个查询按处理顺序编号 $i_1, \dots, i_t$，记 $S_t = \sum_{s \le t} val_{i_s}$。归纳证明「处理完第 $t$ 个后 $nums[j] = \max(0,\ nums_0[j] - S_t)$」：当前值为正时减 $\min(\text{值}, val)$，新值 $= \max(0, \max(0, nums_0[j] - S_t) - val_{i_{t+1}}) = \max(0, nums_0[j] - S_{t+1})$；当前值为 0 时本查询不选中它（减量为 0），由 $nums_0[j] - S_t \le 0$ 及 $val \ge 0$ 知仍等于 $\max(0, nums_0[j] - S_{t+1})$。两种情形均维持不变式且值恒 $\ge 0$，$t$ 取尽即得结论。∎

**引理 3（单调性）**：若前 $k$ 个查询可使 `nums` 清零，则前 $k+1$ 个也可以。

**证明**：取前 $k$ 个查询的清零方案，第 $k+1$ 个查询对每个下标都选「减 0」，方案仍合法且效果相同。∎

**定理**：记 $f(k) = [\forall j:\ nums[j] \le cover_k(j)]$，则「前 $k$ 个查询可清零」$\iff f(k)$ 成立；$f$ 在 $[0, q]$ 上单调不降，答案为最小使 $f$ 为真的 $k$（$f(q)$ 为假时输出 $-1$），上述二分算法正确返回。

**证明**：（$\Rightarrow$）若某位 $nums[j] > cover_k(j)$，由引理 1 该位总减量 $\le cover_k(j) < nums[j]$，清零要求总减量恰为 $nums[j]$（操作只减不增），矛盾。（$\Leftarrow$）引理 2 给出显式方案，终值 $\max(0, nums[j] - cover_k(j)) = 0$，即零数组。单调性即引理 3；在单调谓词上用 `lo = mid + 1 / hi = mid` 收敛到最小真值是二分的标准范式，每步维持「$f(hi)$ 真、$f(lo-1)$ 假」。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n + q) \log q)$。二分共 $O(\log q)$ 轮，每轮 `check` 为「重建 diff + 打 mid 个标记 + 一遍前缀和逐位判定」，即 $O(n + q)$。
- **空间复杂度**：$O(n)$。差分数组 $n+1$ 位；`cover` 用滚动变量，无额外数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minZeroArray(vector<int>& nums, vector<vector<int>>& queries) {
        int n = nums.size(), q = queries.size();
        vector<int> diff(n + 1);
        auto check = [&](int k) {
            fill(diff.begin(), diff.end(), 0);
            for (int i = 0; i < k; ++i) {
                diff[queries[i][0]] += queries[i][2];
                diff[queries[i][1] + 1] -= queries[i][2];
            }
            int cover = 0;
            for (int j = 0; j < n; ++j) {
                cover += diff[j];
                if (nums[j] > cover) return false;
            }
            return true;
        };
        if (!check(q)) return -1;
        int lo = 0, hi = q;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (check(mid)) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def minZeroArray(self, nums: List[int], queries: List[List[int]]) -> int:
        n, q = len(nums), len(queries)

        def check(k: int) -> bool:
            diff = [0] * (n + 1)
            for i in range(k):
                l, r, val = queries[i]
                diff[l] += val
                diff[r + 1] -= val
            cover = 0
            for j, x in enumerate(nums):
                cover += diff[j]
                if x > cover:
                    return False
            return True

        if not check(q):
            return -1
        lo, hi = 0, q
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

## 8. 边界情况与易错点

1. **k = 0 是合法答案**：`nums` 全零时返回 0；二分下界写成 1 会直接 WA（示例 3 类型）。
2. **先处理 −1**：`check(q)` 为假返回 $-1$；跳过预检直接二分时，「区间内无解」会让返回值失去含义。
3. **diff 长度 n+1**：$r_i + 1$ 可以等于 $n$，哨兵位必须有（Q2 同款坑，差分开成 $n$ 位越界）。
4. **val 是逐下标独立上限**，不是区间总量：误解成「区间总共减 $val$」会去建流/贪心模型；把 `diff[l] += val` 手滑写成 `+= 1` 则退化成 Q2 逻辑，大样例必 WA。
5. **「前 k 个」是前缀不是子集**：查询不能挑着用，二分单调性正来自前缀结构（引理 3 依赖「多出的查询可全减 0」，前缀保证了多出的恰好是第 $k+1$ 个）。
6. **「按顺序处理」仍是幌子**：与 Q2 同理，减量选择相互独立、查询间无干扰，判定只与「用了前多少个」有关，与处理顺序无关。
7. **别去逐查询模拟贪心过程**：判定已退化为逐位不等式，模拟是 $O(nq)$ 的无用功（3.1 的教训）。
8. **C++ 引用传参**：`queries` 按 `vector<vector<int>>&` 传递，按值传在 $10^5 \times 3$ 规模下白白拷贝。

**延伸思考**：

1. **一次扫描替代二分**：对每个下标 $j$ 单独求「被满足的时刻」$k_j$——从左到右扫描 $j$，双指针增删盖住 $j$ 的查询，树状数组按查询顺序维护 $val$ 前缀和，倍增找首个前缀和 $\ge nums[j]$ 的时刻，则答案 $= \max_j k_j$，复杂度 $O((n+q)\log q)$。这正是标签里 *Two Pointers* 的出处。
2. **线段树推进**：维护「残差」$nums[j] - cover(j)$ 的区间加 + 全局最小值线段树，逐查询应用，全局最小值首次 $\ge 0$ 的时刻即答案，$O(q \log n)$，免二分。
3. **若改成「从 q 个查询里任选子集，最少选几个」**：前缀结构消失，「选哪些」成为组合问题——不妨想想什么情况下贪心（按 $val$ / 按右端点）会失效。
