# LeetCode 你能在你最喜欢的那天吃到你最喜欢的糖果吗？ 题解

## 1. 题目概述

- **标题 / 题号**：你能在你最喜欢的那天吃到你最喜欢的糖果吗？（#1744，medium）
- **链接**：https://leetcode.cn/problems/can-you-eat-your-favorite-candy-on-your-favorite-day/
- **来源**：LeetCode 第 226 场周赛 Q3
- **难度**：中等
- **标签**：数组、前缀和

**题意**：给定正整数数组 `candiesCount`，`candiesCount[i]` 是第 $i$ 类糖果的颗数。吃糖规则：从第 $0$ 天开始；必须先吃完**所有**第 $i-1$ 类糖果才能吃第 $i$ 类（同一天内可以跨类型，只要当天先吃前一类、后吃后一类即可）；在吃完所有糖果之前，每天**至少吃 1 颗**。再给 $q$ 个**相互独立**的查询 `queries[i] = [favoriteType, favoriteDay, dailyCap]`：若存在一种吃糖方案，使你在**第 `favoriteDay` 天**（从 0 计）吃到一颗第 `favoriteType` 类糖果，且每天吃的颗数不超过 `dailyCap`，则 `answer[i] = true`；否则为 `false`。

**约束**：

- $1 \le \text{candiesCount.length} \le 10^5$，$1 \le \text{candiesCount}[i] \le 10^5$
- $1 \le \text{queries.length} \le 10^5$，$\text{queries}[i].\text{length} = 3$
- $0 \le \text{favoriteType}_i < \text{candiesCount.length}$
- $0 \le \text{favoriteDay}_i \le 10^9$，$1 \le \text{dailyCap}_i \le 10^9$

> 💡 **一句话建模**：规则把吃糖顺序钉死 → 全部糖果排成一条「总队列」，每天的进食只是把队列切成连续段。第 $t$ 类糖对应队列上一段连续的**全局序号区间**，从而占据一段**可达天区间**——查询即判断 $d$ 是否落在这个区间里。

```text
1. 第 0、1 天各吃 2 颗类型 0，第 2 天仍在吃类型 0（共 7 颗）→ true
```


## 3. 解题思路

### 3.1 暴力思路

最直观的做法是逐天模拟一场游戏：每天吃的颗数可取 $1 \sim \text{cap}$（$\text{cap}$ 可达 $10^9$ 种选择），方案空间指数级；若退化为按颗推进，糖果总数 $N$ 可达 $10^5 \times 10^5 = 10^{10}$；若按天推进，天数可达 $10^9$；再乘上 $q \le 10^5$ 个查询，任何「逐天 / 逐颗」的模拟都不可行。

> ⚠️ 瓶颈剖析：查询问的是「**是否存在**一种安排」，候选安排有天文数字种。突破口在于：合法安排的自由度只有「每天吃几颗」，而极端安排只有两种——**吃得最快**（每天吃满）与**吃得最慢**（每天 1 颗）。答案只由这两个极端决定。

### 3.2 核心观察：第 t 类糖占据一段「可达天区间」

![核心观察：吃糖顺序固定，第t类糖占据可达天区间](images/wc226_q3_candy_interval_concept.svg)

规则「先吃完 $i-1$ 类才能吃 $i$ 类」把进食顺序完全钉死：所有糖果等价于排成一条**总队列**，第 $k$ 颗被吃掉的糖全局序号就是 $k$；同类糖彼此无差别，同一天可以吃队列上任意长度的连续一段（允许跨类型边界）。记**前缀和**

$$s[t] = \sum_{i=0}^{t-1} \text{candiesCount}[i],\qquad s[0]=0,$$

则第 $t$ 类糖占据全局序号区间 $[\,s[t]+1,\ s[t+1]\,]$，而它能被吃到的**天**恰好铺满一段区间：

| 端点 | 进度 | 含义 |
|------|------|------|
| **最早天** $\bigl\lfloor s[t]/\text{cap} \bigr\rfloor$ | 每天吃满 $\text{cap}$ 颗 | 第 $s[t]+1$ 颗（类型 $t$ 第一颗）最早入口的天 |
| **最晚天** $s[t+1]-1$ | 每天只吃 $1$ 颗 | 第 $s[t+1]$ 颗（类型 $t$ 最后一颗）最晚入口的天 |

> 💡 **关键洞察**：每天的进食量在 $[1,\text{cap}]$ 内连续可调，「最快」与「最慢」之间的任何中间进度都可实现，因此类型 $t$ 的可达天**没有空洞**，恰为区间 $[\,\lfloor s[t]/\text{cap}\rfloor,\ s[t+1]-1\,]$（严格证明见 §5）。于是每个查询只是一次**区间包含判断**。

### 3.3 算法流程：前缀和 + O(1) 区间判定

![算法流程：前缀和预处理，每查询O(1)区间判定](images/wc226_q3_prefix_query_flow.svg)

1. **预处理**：$s[0]=0$，$s[i+1]=s[i]+\text{candiesCount}[i]$，得到长度 $n+1$ 的前缀和数组。⚠️ 用 64 位整数：总和可达 $10^{10}$，溢出 32 位。
2. **逐查询判定**：对 $[t, d, \text{cap}]$，计算最早天 $\bigl\lfloor s[t]/\text{cap} \bigr\rfloor$ 与最晚天 $s[t+1]-1$，答案即
   $$\Bigl\lfloor \frac{s[t]}{\text{cap}} \Bigr\rfloor \le d \le s[t+1]-1.$$
3. **等价的乘法形式**（免整除、两条件对称）：
   $$(d+1)\cdot\text{cap} > s[t] \quad\land\quad d+1 \le s[t+1].$$

> ⚠️ **溢出**：$(d+1)\cdot\text{cap}$ 可达 $(10^9+1)\times 10^9 \approx 10^{18}$，C++ 必须写 `1LL * (day + 1) * cap` 先提升再乘；Python 原生大整数无此问题。

### 3.4 示例演算

![示例演算：三个查询的区间判定与示例2验证](images/wc226_q3_example_walkthrough.svg)

以示例 1 为例，`candiesCount = [7,4,5,3,8]`，前缀和 $s=[0,7,11,16,19,27]$：

| 查询 | 最早天 | 最晚天 | 判定 | 结果 |
|------|--------|--------|------|------|
| $[0,2,2]$ | $\lfloor 0/2 \rfloor = 0$ | $7-1=6$ | $0 \le 2 \le 6$ ✓ | true |
| $[4,2,4]$ | $\lfloor 19/4 \rfloor = 4$ | $27-1=26$ | $2 < 4$，太早 ✗ | false |
| $[2,13,10^9]$ | $\lfloor 16/10^9 \rfloor = 0$ | $16-1=15$ | $0 \le 13 \le 15$ ✓ | true |

- **查询 2 直观**（吃太慢）：每天吃满 4 颗，到第 2 天结束共吃 $12$ 颗，够不到第 $20$ 颗（类型 4 起点）。
- **查询 3 直观**（节奏可调）：每天吃 1 颗时，类型 2（第 $12\sim16$ 颗）落在第 $11\sim15$ 天，第 13 天正在其中。

示例 2 同法：$s=[0,5,7,13,17,18]$，五个查询依次判定为 $6>1$ ✗、$5\le 10\le 17$ ✓、$0\le 10\le 16$ ✓、$100>17$ ✗、$5>3$ ✗，输出 `[false,true,true,false,false]` ✓。

## 4. 算法细节

1. **前缀和下标约定**：$s$ 长 $n+1$，$s[t]$ = 前 $t$ 类总颗数，$s[0]=0$；第 $t$ 类糖 = 全局第 $s[t]+1 \sim s[t+1]$ 颗。查询访问 $s[t]$ 与 $s[t+1]$，因此必须多留一位。
2. **两个条件的语义**：$(d+1)\cdot\text{cap} > s[t]$ ——「**吃得够快**」：到第 $d$ 天结束时最多吃了 $(d+1)\cdot\text{cap}$ 颗，必须越过 $s[t]$ 才摸得到类型 $t$ 的第一颗；$d+1 \le s[t+1]$ ——「**吃得够慢**」：到第 $d$ 天开始前最少已吃 $d$ 颗（每天至少 1 颗），若 $d \ge s[t+1]$，则即使全程每天 1 颗也早把类型 $t$ 吃完了。
3. **除法形式 vs 乘法形式**：对非负整数有 $\lfloor s[t]/\text{cap} \rfloor \le d \iff s[t] < (d+1)\cdot\text{cap}$，两种写法等价。乘法形式与第二条件对称、没有整除细节，C++ 里两处都需 64 位。
4. **边界自动覆盖**：$t=0$ 时 $s[0]=0$，「够快」条件 $(d+1)\cdot\text{cap} > 0$ 恒成立（$d \ge 0,\ \text{cap} \ge 1$）；$d=0$、$\text{cap}=1$、单类糖果等极端均无需特判。
5. **同一天跨类型**：规则只约束「先吃完 $i-1$ 类再吃 $i$ 类」，允许同一天先吃前类尾部、再吃后类头部。总队列模型中每天的进食段是**连续序号段**，天然允许跨过类型边界，无需任何额外处理。

## 5. 正确性证明

**约定**：将 $N=s[n]$ 颗糖按类型顺序编号 $1..N$（同类糖无差别）。合法**计划**指把 $1..N$ 按序吃完的逐日安排；第 $k$ 颗糖被吃掉的天记为 $D(k)$（从 0 计）。

**引理 1（总队列模型）**：任何合法计划中，糖按序号 $1,2,\dots,N$ 依次被吃；每天吃掉一段**连续**的序号区间，颗数介于 $1$ 与 $\text{cap}$ 之间。

**证明**：规则 2 要求全部 $0$ 类先于任何 $1$ 类、全部 $1$ 类先于任何 $2$ 类……故进食顺序按类型分段递增；同类糖彼此无差别，段内顺序任取不影响合法性，可设段内按固定顺序，整体即 $1..N$。于是第 $j$ 天吃掉的是该序列中一段连续区间；由规则 3 其长度 $\ge 1$，由查询限制其长度 $\le \text{cap}$。∎

**引理 2（单颗糖的可达天区间）**：固定 $\text{cap}$，第 $k$ 颗糖可被安排在第 $d$ 天吃，当且仅当

$$\Bigl\lfloor \frac{k-1}{\text{cap}} \Bigr\rfloor \le d \le k-1,$$

且该区间内每个 $d$ 都有对应方案。

**证明**：（**必要性**）设 $D(k)=d$。第 $0 \sim d-1$ 天共 $d$ 天且每天 $\ge 1$ 颗，须容纳前 $k-1$ 颗，故 $k-1 \ge d$；第 $0 \sim d$ 天共 $d+1$ 天且每天 $\le \text{cap}$ 颗，须容纳前 $k$ 颗，故 $k \le (d+1)\cdot\text{cap}$，即 $d \ge \lceil k/\text{cap} \rceil - 1 = \lfloor (k-1)/\text{cap} \rfloor$。
（**充分性**）设 $d$ 满足两不等式。取 $j=\min(d\cdot\text{cap},\ k-1)$，则 $\max(d,\ k-\text{cap}) \le j \le \min(d\cdot\text{cap},\ k-1)$（依次由 $\text{cap}\ge 1$、$d \le k-1$、$k \le (d+1)\text{cap}$、$j$ 的定义推得）。构造：第 $0 \sim d-1$ 天吃序号 $1 \sim j$，由 $d \le j \le d\cdot\text{cap}$，把 $j$ 颗均衡切成 $d$ 段，每段 $\lfloor j/d \rfloor$ 或 $\lceil j/d \rceil$ 颗，均落在 $[1,\text{cap}]$ 内；第 $d$ 天吃序号 $j+1 \sim k$，颗数 $k-j$ 满足 $1 \le k-j \le \text{cap}$（由 $j \le k-1$ 与 $j \ge k-\text{cap}$）；其后的糖任意按天切段消化（每段 $\le \text{cap}$、$\ge 1$ 即可）。该计划合法且 $D(k)=d$。∎

**引理 3（类型区间的可达天并起来无空洞）**：第 $t$ 类糖（$k \in [s[t]+1,\ s[t+1]]$）可被吃到的天的集合为区间 $[\,\lfloor s[t]/\text{cap} \rfloor,\ s[t+1]-1\,]$。

**证明**：由引理 2，第 $k$ 颗糖的可达天为区间 $I_k=[\lfloor (k-1)/\text{cap} \rfloor,\ k-1]$，故所求集合为 $\bigcup_{k=s[t]+1}^{s[t+1]} I_k$。左端点在 $k=s[t]+1$ 处最小，为 $\lfloor s[t]/\text{cap} \rfloor$；右端点在 $k=s[t+1]$ 处最大，为 $s[t+1]-1$。对相邻两颗糖 $k$、$k+1$：$I_k$ 右端为 $k-1$，$I_{k+1}$ 左端为 $\lfloor k/\text{cap} \rfloor \le k$，即 $I_{k+1}$ 的起点至多比 $I_k$ 的终点大 $1$，两区间相接或相交，故并集连续。因此并集恰为 $[\,\lfloor s[t]/\text{cap} \rfloor,\ s[t+1]-1\,]$。∎

**定理（判定条件）**：`answer = true` 当且仅当

$$\Bigl\lfloor \frac{s[t]}{\text{cap}} \Bigr\rfloor \le d \le s[t+1]-1 \quad\iff\quad (d+1)\cdot\text{cap} > s[t] \ \land\ d+1 \le s[t+1].$$

**证明**：由引理 1，「第 $d$ 天吃到类型 $t$」当且仅当存在 $k \in [s[t]+1, s[t+1]]$ 使 $D(k)=d$；由引理 2 与引理 3，这样的 $d$ 全体为 $[\lfloor s[t]/\text{cap} \rfloor,\ s[t+1]-1]$。再证代数等价：对非负整数 $s[t]$，$\lfloor s[t]/\text{cap} \rfloor \le d \iff s[t] \le (d+1)\text{cap}-1 \iff s[t] < (d+1)\cdot\text{cap}$；而 $d \le s[t+1]-1 \iff d+1 \le s[t+1]$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n+q)$。预处理前缀和 $O(n)$；每个查询只做一次除法 / 乘法加两次比较，$q$ 个查询共 $O(q)$。$n=q=10^5$ 时约 $2\times10^5$ 步，毫秒级。
- **空间复杂度**：$O(n)$。前缀和数组长 $n+1$（64 位约 0.8MB）；答案数组 $O(q)$ 为输出不计。

## 7. 参考代码

### C++

```cpp
using ll = long long;

class Solution {
public:
    vector<bool> canEat(vector<int>& candiesCount, vector<vector<int>>& queries) {
        int n = candiesCount.size();
        vector<ll> s(n + 1, 0);                  // s[t] = 前 t 类糖果总数
        for (int i = 0; i < n; ++i) s[i + 1] = s[i] + candiesCount[i];

        vector<bool> ans;
        ans.reserve(queries.size());
        for (auto& q : queries) {
            int t = q[0], day = q[1], cap = q[2];
            ll earliest = s[t] / cap;           // 每天吃满 cap 颗
            ll latest = s[t + 1] - 1;            // 每天只吃 1 颗
            ans.push_back(earliest <= day && day <= latest);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def canEat(self, candiesCount: List[int], queries: List[List[int]]) -> List[bool]:
        s = [0]
        for c in candiesCount:
            s.append(s[-1] + c)
        ans = []
        for t, day, cap in queries:
            earliest = s[t] // cap              # 每天吃满 cap 颗
            latest = s[t + 1] - 1               # 每天只吃 1 颗
            ans.append(earliest <= day <= latest)
        return ans
```

> 💡 乘法形式 `(day + 1) * cap > s[t] and day + 1 <= s[t + 1]` 与上述除法形式完全等价（§5 定理），C++ 写法需 `1LL * (day + 1) * cap` 防溢出。

## 8. 边界情况与易错点

1. **天数从 0 计**：`favoriteDay = 0` 是第一天，「到第 $d$ 天结束」经历了 $d+1$ 天，因此上界是 $(d+1)\cdot\text{cap}$ 而非 $d\cdot\text{cap}$——本题最高频的 off-by-one。
2. **C++ 溢出两处**：① 前缀和 $s$：总和可达 $10^{10}$，必须 `vector<long long>`；② 乘法形式 $(d+1)\cdot\text{cap} \approx 10^{18}$，必须 `1LL *` 先提升再乘。除法形式 `s[t] / cap` 中 `s[t]` 已是 64 位，天然安全。
3. **$t = 0$ 无需特判**：$s[0]=0$ 使「够快」条件恒真，答案退化为 $d+1 \le \text{candiesCount}[0]$。
4. **$d$ 巨大而糖很少**：如 `candiesCount = [1]`、`d = 10^9`，判 $d+1 \le s[1]$ 即 false（吃太快），别被 $10^9$ 吓到去模拟天数。
5. **条件对象别写错**：是 $(d+1)\cdot\text{cap} > s[t]$（越过类型 $t$ 的**起点**，摸到第一颗即可），不是 $\ge s[t+1]$（无需吃完整个类型 $t$，也无需当天全部吃类型 $t$——同天混类型是允许的）。
6. **「每天至少一颗」是根基**：最晚天 $s[t+1]-1$ 完全依赖该规则；若允许空窗日，可以无限拖延，只剩「够快」条件（见延伸思考①）。
7. **查询相互独立**：每个查询都是一场从头开始的新游戏，进度不共享、不累计。
8. **Python 整除**：`//` 对非负数即下取整，与 $\lfloor\cdot\rfloor$ 一致；`(day+1)*cap` 原生大整数无溢出。
