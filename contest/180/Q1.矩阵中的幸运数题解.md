# LeetCode 矩阵中的幸运数 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中的幸运数（#1380，easy）
- **链接**：https://leetcode.cn/problems/lucky-numbers-in-a-matrix/
- **来源**：LeetCode 第 180 场周赛 Q1
- **难度**：简单
- **标签**：数组、矩阵

**题意**：给定一个 $m \times n$ 且**元素互不相同**的矩阵，「**幸运数**」指同时满足两个条件的元素：在**所在行**的所有元素中最小，且在**所在列**的所有元素中最大。按任意顺序返回矩阵中的所有幸运数。

**约束**：

- $1 \le m, n \le 50$
- $1 \le \text{matrix}[i][j] \le 10^5$
- 所有元素互不相同

> 💡 签到题先读约束定基调：$mn \le 2500$，连 $O(mn(m+n))$ 的逐格暴力都能毫秒级通过，比赛时**求稳**即可；但「行最小」「列最大」是两个典型的**可预计算全局统计量**，把逐格现算升级为「建表 + 等值双判」，才是这道题值得沉淀的模板。

```text
解释：15 是第 2 行的最小值，也是第 0 列的最大值。
```

**示例 2**


**示例 3**

```text
输出：[7]
解释：7 是第 0 行的最小值、第 0 列的最大值。
```

**示例 4**（自拟：$1 \times 1$ 矩阵）

```text
输入：matrix = [[5]]
输出：[5]
解释：唯一元素既是行最小又是列最大，必为幸运数。
```

**示例 5**（自拟：无幸运数）

```text
输入：matrix = [[1,5,9],[6,4,3]]
输出：[]

```

## 3. 解题思路

### 3.1 暴力思路：每格现扫行与列

最直接的做法：对每个格子 $(i,j)$，现场扫第 $i$ 行求最小、扫第 $j$ 列求最大，再判定该格是否同时取到两个极值。每格 $O(m+n)$，总计 $O(mn(m+n))$；$m = n = 50$ 时约 $2.5 \times 10^5$ 次比较——**能过，但结构差**：同一行的最小值被重复计算 $n$ 遍、同一列的最大值被重复计算 $m$ 遍，是典型的「可预计算消除的重复劳动」。

> ⚠️ 签到题的正确姿势不是发明新算法，而是识别「判定条件由哪些全局量组成」，把它们的计算提到外层一次做完。

### 3.2 核心观察：预计算两张极值表，判定退化为双判

![核心观察：幸运数 = 行最小 ∩ 列最大，预计算后每格只需两次等值比较](images/wc180_q1_minmax_concept.svg)

幸运数的两个条件**各只依赖一个维度**，是两条独立的谓词：

- **行最小**：$a[i][j] = \text{minRow}[i]$，其中 $\text{minRow}[i]$ 是第 $i$ 行的最小值；
- **列最大**：$a[i][j] = \text{maxCol}[j]$，其中 $\text{maxCol}[j]$ 是第 $j$ 列的最大值。

两个量都是**一次遍历即可求出的全局统计量**：在同一个双循环里同时更新 $m$ 个行最小与 $n$ 个列最大，此后每格的判定就退化为两次 $O(1)$ 等值比较。用集合语言：答案 $= \{\text{minRow}[i]\} \cap \{\text{maxCol}[j]\}$——元素互异保证「值 ↔ 位置」一一对应，交集中的每个值恰对应一个格子。

### 3.3 算法流程：一趟建表 + 逐格双判

![算法流程：一趟预计算 minRow 与 maxCol，再逐格双判收集](images/wc180_q1_scan_flow.svg)

1. **预计算**：一趟双循环，`minRow[i]` 与 `maxCol[j]` 同时更新；
2. **判定**：再扫一遍矩阵，`a[i][j] == minRow[i] && a[i][j] == maxCol[j]` 者收入 `ans`；
3. **返回** `ans`（可为空列表）。

### 3.4 示例演算：增广矩阵 + 候选验收

![示例演算：示例 2 的增广矩阵与三个行最小候选的验收过程](images/wc180_q1_walkthrough.svg)

把每行最小拼成附加列、每列最大拼成附加行，得到「**增广矩阵**」，幸运数一眼可见——它就是**同时被绿色（行最小）与橙色（列最大）标记**的格子。以示例 2 为例：

| 行最小候选 | 所在列 $j$ | $\text{maxCol}[j]$ | 相等？ |
|-----------|-----------|--------------------|--------|
| $(0,0)=1$ | 0 | 15 | ✗ |
| $(1,1)=3$ | 1 | 16 | ✗ |
| $(2,3)=12$ | 3 | 12 | ✓ 幸运数 |

> 💡 幸运数**必先是行最小**（定义的第一个条件），所以只需对 $m$ 个行最小候选验收，不必对全部 $mn$ 格逐一双判——判定次数从 $mn$ 降到 $m$（§4 第 2 点、§5 引理 2）。示例 3 更快：$\text{minRow} = [7, 1]$、$\text{maxCol} = [7, 8]$，候选 $(0,0)=7$ 一击命中，`ans = [7]`。

## 4. 算法细节

1. **一趟双更新**：`minRow` 与 `maxCol` 在**同一个** $(i,j)$ 双循环里更新——处理格子 $(i,j)$ 时顺手执行 `minRow[i] = min(minRow[i], a)`、`maxCol[j] = max(maxCol[j], a)`，预计算只需扫一遍矩阵，无需「扫行一趟 + 扫列一趟」两趟。
2. **两个版本按需选**：
   - **全格双判版**（本文 C++）：对 $mn$ 格逐一双判，**不依赖互异性**——哪怕题目允许重复元素也正确，是最稳的底稿；
   - **argmin 候选版**（本文 Python）：每行用 `min` / `index` 定位行最小所在列 $j_i$（互异 ⇒ 位置唯一），只验 $m$ 次等值 `a[i][j_i] == maxCol[j_i]`，判定次数从 $mn$ 降到 $m$。
3. **鞍点一行式**：由 §5 定理 2，幸运数存在 $\iff \max(\text{minRow}) = \min(\text{maxCol})$，相等则返回 `[该值]`，否则返回 `[]`——把整道题压成一次比较；`zip(*matrix)` 转置后逐列取 `max` 最顺手。
4. **互异性用在哪**：候选版靠它保证 argmin 唯一；鞍点版靠它保证「值相等 ⇒ 位置相同」；定理 2 靠它保证答案至多一个。全格双判版**不依赖**它。
5. **哨兵初值**：`minRow` 初始化 `INT_MAX`、`maxCol` 初始化 `INT_MIN`（或直接用首元素初始化）。别用 0 当初值——本题元素 $\ge 1$ 时碰巧不越界，换成含负数的题就错，属于应当戒掉的「侥幸正确」。

## 5. 正确性证明

记 $a[i][j]$ 为矩阵元素，$L$ 为全部幸运数的集合。

**引理 1（预计算正确性）**：双循环结束后，$\text{minRow}[i] = \min_j a[i][j]$，$\text{maxCol}[j] = \max_i a[i][j]$。

**证明**：按行主序对已处理格子个数 $k$ 归纳。断言：处理完行主序前缀 $P_k$ 后，$\text{minRow}[r]$ 等于第 $r$ 行限制在 $P_k$ 内的最小值（该行在 $P_k$ 中无格子时为 $+\infty$），$\text{maxCol}[c]$ 同理。$k=0$ 时两表为 $\pm\infty$，成立。设 $k$ 时断言成立；第 $k+1$ 个格子为 $(i,j)$：$P_{k+1}$ 只比 $P_k$ 多含 $(i,j)$，故只有第 $i$ 行与第 $j$ 列的「已见集合」变化，而循环体恰好只对 $\text{minRow}[i]$、$\text{maxCol}[j]$ 各做一次 min/max 更新，更新后仍为对应集合的极值，断言保持。循环终止时 $P_k$ 为整个矩阵。∎

**引理 2（候选缩减）**：幸运数必为所在行的行最小；且元素互异时每行的行最小位置唯一，故 $m$ 个行最小候选覆盖全部幸运数。

**证明**：前一断言是定义的直接推论（幸运数的条件一即「行最小」）。后一断言：若第 $i$ 行有两个位置都取到行最小值，则两格数值相同，与互异矛盾。∎

**定理 1（全格双判版正确）**：算法返回的集合恰为 $L$。

**证明**：格子 $(i,j)$ 被收入 $\iff a[i][j] = \text{minRow}[i]$ 且 $a[i][j] = \text{maxCol}[j]$。由引理 1，$\text{minRow}[i]$ 是全行最小值：若 $a[i][j] = \text{minRow}[i]$，则该格取到第 $i$ 行的最小值；反之行最小格的值即 $\text{minRow}[i]$，等式成立。故第一条件 $\iff$ 该格是行最小，同理第二条件 $\iff$ 该格是列最大。两者同时成立 $\iff$ 该格是幸运数。又每格恰被判定一次，无重无漏。∎

**定理 2（鞍点定理：至多一个）**：元素互异时幸运数至多一个；且存在时其值 $= \max_i \text{minRow}[i] = \min_j \text{maxCol}[j]$。反之若 $\max_i \text{minRow}[i] = \min_j \text{maxCol}[j] = v$，则 $v$ 是唯一的幸运数。

**证明**：先证唯一性。设有幸运数 $a$ 位于 $(r_1, c_1)$、$b$ 位于 $(r_2, c_2)$。若 $r_1 = r_2$，与引理 2 的「每行行最小位置唯一」矛盾，故 $r_1 \ne r_2$；同理 $c_1 \ne c_2$。考察交叉格 $a[r_1][c_2]$：它在第 $r_1$ 行，$\ge$ 行最小 $= a$；又在第 $c_2$ 列，$\le$ 列最大 $= b$。故 $a \le b$。对称考察 $a[r_2][c_1]$ 得 $b \le a$，于是 $a = b$，与不同位置元素互异矛盾。

再证值等式。对任意 $i, j$ 有 $\text{minRow}[i] \le a[i][j] \le \text{maxCol}[j]$，取 $i$ 为 $\max(\text{minRow})$ 的取到者、$j$ 为 $\min(\text{maxCol})$ 的取到者，得 $\max(\text{minRow}) \le \min(\text{maxCol})$。设幸运数 $a$ 位于 $(r, c)$，则
$$a = \text{minRow}[r] \le \max(\text{minRow}) \le \min(\text{maxCol}) \le \text{maxCol}[c] = a$$
全链取等，故 $a = \max(\text{minRow}) = \min(\text{maxCol})$。

最后证反向：若公共值为 $v$，则 $v$ 作为 $\max(\text{minRow})$ 是某行 $r$ 的行最小、作为 $\min(\text{maxCol})$ 是某列 $c$ 的列最大；互异性保证值 $v$ 在矩阵中只出现一次，于是「$r$ 行最小格」与「$c$ 列最大格」必为同一格，该格既是行最小又是列最大，即幸运数。∎

**推论**：鞍点一行式正确——比较 $\max(\text{minRow})$ 与 $\min(\text{maxCol})$ 即可判定存在性并给出唯一解。∎

## 6. 复杂度分析

- **时间复杂度**：$O(mn)$。预计算一趟 $2mn$ 次 min/max 更新；判定一趟至多 $mn$ 次双判（候选版仅 $m$ 次）。$m, n \le 50$ 时总运算量约 $7.5 \times 10^3$，签到题余量充足；对照暴力 $O(mn(m+n)) \approx 2.5 \times 10^5$，快 30 倍以上。
- **空间复杂度**：$O(m+n)$——`minRow` 长 $m$、`maxCol` 长 $n$；输出列表由定理 2 至多含 1 个元素，$O(1)$。
- **工程取舍**：鞍点一行式代码最短（一次比较）；候选版判定次数最少（$m$ 次）；全格双判版最稳（不依赖互异）。比赛签到按「最快写对」的原则，全格双判版或候选版任选其一即可。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> luckyNumbers(vector<vector<int>>& matrix) {
        int m = matrix.size(), n = matrix[0].size();
        vector<int> minRow(m, INT_MAX), maxCol(n, INT_MIN);
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j) {          // 一趟同时更新两张表
                minRow[i] = min(minRow[i], matrix[i][j]);
                maxCol[j] = max(maxCol[j], matrix[i][j]);
            }

        vector<int> ans;
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                if (matrix[i][j] == minRow[i] && matrix[i][j] == maxCol[j])
                    ans.push_back(matrix[i][j]);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def luckyNumbers(self, matrix: List[List[int]]) -> List[int]:
        max_col = [max(col) for col in zip(*matrix)]   # 每列最大：转置取 max
        ans = []
        for row in matrix:
            j = row.index(min(row))                    # 行最小所在列（互异 ⇒ 唯一）
            if row[j] == max_col[j]:                   # 只验 m 个候选
                ans.append(row[j])
        return ans
```

> 💡 **鞍点一行式**（互异条件下的最短形态）：`v = max(min(r) for r in matrix)`，若 `v == min(max(c) for c in zip(*matrix))` 返回 `[v]`，否则 `[]`——一次比较代替整趟判定，正确性见 §5 定理 2。

## 8. 边界情况与易错点

1. **$1 \times 1$ 矩阵**：唯一元素既是行最小又是列最大，必为幸运数（示例 4）——不要对单格矩阵特判返回空。
2. **无幸运数返回 `[]`**：不是 `-1` 也不是 `null`。对照 1394「找出数组中的幸运数」返回 `-1`——两题同名「幸运数」但定义与输出协议都不同，别串味。
3. **行列别读反**：`m = matrix.size()` 是行数、`n = matrix[0].size()` 是列数；`minRow` 长 $m$、`maxCol` 长 $n$。方阵里下标混用侥幸不崩，长方矩阵（$m \ne n$）必越界——自测请用非方阵。
4. **互异性是隐含前提**：候选版与鞍点一行式都依赖它；若去掉互异（如 `[[2,2],[2,2]]` 每格皆幸运），唯一性失效，必须回到全格双判版。
5. **哨兵初值**：`minRow` 用 `INT_MAX` 而非 0（元素全 $\ge 1$ 时 0 恰好不越界，换成含负数的题即错）；`maxCol` 用 `INT_MIN` 或首元素初始化。
6. **输出超过 1 个元素必有 bug**：互异前提下由定理 2 答案长度 $\in \{0, 1\}$——这是现成的自检断言。
7. **`row.index(min(row))` 扫两遍行**：$n \le 50$ 无所谓，但需知道它是两次 $O(n)$；介意时可写 `min(range(n), key=row.__getitem__)` 一趟取 argmin。
