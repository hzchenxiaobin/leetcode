# LeetCode 最大的团队表现值 题解

## 1. 题目概述

- **标题 / 题号**：最大的团队表现值（#1383，hard）
- **链接**：https://leetcode.cn/problems/maximum-performance-of-a-team/
- **来源**：LeetCode 第 180 场周赛 Q4
- **难度**：困难
- **标签**：贪心、排序、堆（优先队列）、数组

**题意**：给定 $n$ 名工程师的速度数组 `speed` 与效率数组 `efficiency`，从中**至多选 $k$ 名**组成团队。**团队表现值** = 成员**速度之和** × 成员**效率的最小值**。求最大团队表现值，答案对 $10^9 + 7$ 取余后返回。

**约束**：

- $1 \leq k \leq n \leq 10^5$
- $1 \leq \text{speed}[i] \leq 10^5$
- $1 \leq \text{efficiency}[i] \leq 10^8$

> 💡 「和 × 最小值」的结构里两个维度互相牵制：高速度的人可能拉低效率，高效率的人可能速度平平。这类题的通用解法是**枚举卡脖子的维度（min），用堆最优化求和的维度**——本题正是该套路最标准的模板。

## 2. 示例

**示例 1**

```text
输入：n = 6, speed = [2,10,3,1,5,8], efficiency = [5,4,3,9,7,2], k = 2
输出：60
解释：选工程师 2（speed=10, eff=4）与工程师 5（speed=5, eff=7），
      表现值 = (10 + 5) × min(4, 7) = 60。
```

**示例 2**

```text
输出：68
解释：选工程师 1、2、5，表现值 = (2 + 10 + 5) × min(5, 4, 7) = 68。
```

**示例 3**

```text
输入：n = 6, speed = [2,10,3,1,5,8], efficiency = [5,4,3,9,7,2], k = 4

```

```text
输出：20
解释：只能选唯一的工程师，5 × 4 = 20；堆中自始至终只有 1 个元素，永不触发弹出。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有大小不超过 $k$ 的子集并逐一计算表现值：组合数 $\sum_{i=1}^{k}\binom{n}{i}$ 在 $n = 10^5$ 时是天文数字，不可行。

退一步利用结构：表现值被**效率最小值**卡住，那么**枚举「效率最小值的承担者」**，子问题变为——在效率 $\geq e_i$ 的工程师中选至多 $k$ 个，使速度和最大（即候选池的**速度 top-k 之和**）。但若每个子问题独立求解（每次对前缀做一次选择），总代价 $O(n^2)$ 起步，$n = 10^5$ 时约 $10^{10}$ 次操作，仍然超时。

> ⚠️ 瓶颈在于 $n$ 个子问题被「各自为政」地重复求解。但相邻子问题只差一个人：效率 $\geq e_{i-1}$ 的池子加入第 $i$ 个人就是效率 $\geq e_i$ 的池子，**top-k 集合每步至多换出一个元素**——这种增量性正是堆的用武之地。

### 3.2 核心观察：按效率降序扫描 + 小顶堆维护速度 top-k

![核心观察：按效率降序排序后扫描，当前工程师的效率即团队效率下界，小顶堆维护前缀速度 top-k](images/wc180_q4_sort_heap_concept.svg)

分三步拆解：

1. **锚定卡脖子的维度**。固定「效率最小值是谁」，问题立刻坍缩为：在效率不低于它的人里选至多 $k$ 个速度，使**速度和最大**——答案显然是候选池的**速度 top-k 之和**。
2. **排序把 min 变成已知量**。按效率**降序**排列后扫描到第 $i$ 位时：(a) 已扫描前缀 $[0..i]$ 恰好是「效率 $\geq e_i$ 的候选池」；(b) $e_i$ 就是池中最低效率。以 $i$ 为短板的团队，其速度和上界 = 前缀 top-k 速度和，候选表现值 = $\text{sum} \times e_i$——全程无需任何求 min 操作。
3. **小顶堆增量维护 top-k**。每个新速度 push 进堆；堆超过 $k$ 个时弹出**堆顶**（当前最小速度）。不变式：堆中永远是「已见速度中最大的 $\min(\text{已见数}, k)$ 个」（证明见 §5 引理 2）。

每一步用 $\text{sum} \times e_i$ 更新答案，扫描完毕取最大值即为最优。

> 💡 这是「**枚举限制维度、堆最优化另一维度**」的经典套路，与 502 IPO、857 雇佣 K 名工人、630 课程表 III 同族：两维牵制时，用排序消掉 min/max，用堆维护受约束集合的最优选取。

### 3.3 算法流程

![算法流程：排序后逐个入堆、超员踢堆顶、每步更新答案、最后取模](images/wc180_q4_algorithm_flow.svg)

1. 将 $n$ 名工程师按效率 $e$ **降序**排序；
2. 初始化空小顶堆、速度和 `sum = 0`、答案 `ans = 0`；
3. 依序处理每位工程师 $(e, s)$：
   - 将 $s$ 入堆，`sum += s`；
   - 若堆大小超过 $k$：`sum -= 堆顶`，弹出堆顶——踢掉最小速度；
   - `ans = max(ans, sum * e)`——$e$ 即当前团队的效率下界；
4. 返回 `ans % (10^9 + 7)`。

> ⚠️ **两个工程陷阱**：其一，`sum` 可达 $10^{10}$、`sum * e` 可达 $10^{18}$，C++ 必须全程 `long long`；其二，**中途不能取模**——模运算不保序，`max` 比较会失真，只能在返回前一次性取模。

### 3.4 示例演算

![示例演算：k=2 的六步扫描过程，第 4 步取得最优值 60](images/wc180_q4_walkthrough.svg)

以示例 1（$k=2$）为例，排序后依次为 $(9,1),\ (7,5),\ (5,2),\ (4,10),\ (3,3),\ (2,8)$：

| 步骤 | $(e, s)$ | 小顶堆（速度） | sum | perf = sum × e | ans |
|------|----------|----------------|-----|----------------|-----|
| 1 | (9, 1) | 推入 1 → {1} | 1 | 9 | 9 |
| 2 | (7, 5) | 推入 5 → {1, 5} | 6 | 42 | 42 |
| 3 | (5, 2) | 推入 2，踢 1 → {2, 5} | 7 | 35 | 42 |
| 4 | (4, 10) | 推入 10，踢 2 → {5, 10} | 15 | **60** | **60** |
| 5 | (3, 3) | 推入 3，踢 3 → {5, 10} | 15 | 45 | 60 |
| 6 | (2, 8) | 推入 8，踢 5 → {8, 10} | 18 | 36 | 60 |

- **第 4 步登顶**：效率 $e=4$ 处于「不算低」的甜区，且堆中已攒下 top-2 速度 $\{5, 10\}$（工程师 5 与工程师 2），乘积 $15 \times 4 = 60$。
- **第 6 步是反面教材**：速度和达到全程最大的 18，但效率下界已跌到 2，$18 \times 2 = 36 < 60$——两维牵制的直观体现。

换 $k$ 复用同一扫描：$k=3$ 时第 4 步堆为 $\{2,5,10\}$，$17 \times 4 = 68$（示例 2）；$k=4$ 时第 4 步堆为 $\{1,2,5,10\}$，$18 \times 4 = 72$（示例 3）——「至多 $k$ 名」的语义由堆的大小控制自动处理，代码无需分支。

## 4. 算法细节

1. **排序键**：按效率降序；效率并列时先后随意——正确性只依赖「扫描到 $i$ 时，前缀 $[0..i]$ 包含所有已见的效率 $\geq e_i$ 者」。C++ 排 `pair<int,int>`（`{efficiency, speed}`）加自定义比较器；Python 直接 `sorted(zip(efficiency, speed), reverse=True)`。
2. **堆的方向**：保留速度 top-$k$ ⇒ **小顶堆**，堆顶永远是「最该被踢的人」。对比 502 IPO 用大顶堆「每次取最大利润」——方向取决于「要保留什么」：留最大用小顶堆踢最小，取最大用大顶堆直接取顶。
3. **溢出分析**：$\text{sum} \leq k \times 10^5 \leq 10^{10}$，$\text{sum} \times e \leq 10^{10} \times 10^8 = 10^{18} < 2^{63} - 1 \approx 9.2 \times 10^{18}$——`long long` 恰好安全，`int` 连 `sum` 本身都装不下。C++ 中 `sum` 声明为 `long long` 后，`sum * e` 自动按 64 位运算。
4. **取模时机**：全程用 `long long` 比较大小，**返回前一次性** `% MOD`。中途取模是本题最高频的 WA 原因。
5. **「至多 $k$ 名」**：每一步都更新 `ans`（哪怕堆里只有 1 人）——高效小团队可能就是最优；堆不满 $k$ 时绝不弹出。
6. **操作次数**：每人恰好一次 push、至多一次 pop，堆操作总量 $O(n \log k)$，无隐藏的重复计算。

## 5. 正确性证明

设工程师已按效率降序重排为 $(e_0, s_0), \dots, (e_{n-1}, s_{n-1})$，即 $e_0 \geq e_1 \geq \cdots \geq e_{n-1}$。团队为下标集合 $T$（$|T| \leq k$），表现值 $\mathrm{perf}(T) = \big(\sum_{t \in T} s_t\big) \cdot \min_{t \in T} e_t$，最优值记为 $\mathrm{OPT}$。

**引理 1（下界锚点）**：对任意非空团队 $T$，取 $j = \max T$（$T$ 中下标最大者），则 $T \subseteq \{0, 1, \dots, j\}$ 且 $\min_{t \in T} e_t = e_j$。

**证明**：降序排列中下标越大效率不增，故 $j$ 的效率是 $T$ 中最小者；又 $j$ 是最大下标，全体成员落于前缀 $\{0..j\}$。∎

**引理 2（堆不变式）**：处理完第 $i$ 位工程师（push 及可能的 pop 之后），堆中元素恰为 $\{s_0, \dots, s_i\}$ 中最大的 $\min(i+1, k)$ 个，`sum` 为其和。

**证明**：对 $i$ 归纳。$i = 0$ 时堆为 $\{s_0\}$，平凡。设第 $i-1$ 步成立，记当前堆 $M$（前 $i$ 个速度的 top-$m$，$m = \min(i, k)$），堆顶 $x = \min M$。第 $i$ 步 push $s_i$：

- 若 $i + 1 \leq k$：堆大小 $\leq k$ 不弹出，堆含全部前 $i+1$ 个速度，即其 top-$\min(i+1, k)$。
- 若 $i + 1 > k$（此时 $m = k$）：堆为 $M \cup \{s_i\}$ 共 $k+1$ 个，弹出其中最小者。
  - $s_i \leq x$：最小者是 $s_i$，弹出后堆还原为 $M$；而 $s_i$ 不超过 $M$ 中任何元素，前 $i+1$ 个速度的 top-$k$ 仍为 $M$。
  - $s_i > x$：最小者是 $x$，弹出后堆为 $(M \setminus \{x\}) \cup \{s_i\}$；$M$ 之外的元素都 $\leq x < s_i$，故 $s_i$ 必属 top-$k$，且恰好挤掉最小的 $x$。

两种情形堆均为前 $i+1$ 个速度的 top-$\min(i+1, k)$。∎

**定理**：$\mathrm{OPT} = \max_{0 \leq i < n} \big(\text{sum}_i \times e_i\big)$，即算法返回正确答案。

**证明**：记候选值 $c_i = \text{sum}_i \times e_i$。

（每个候选不超过最优）固定 $i$，堆中成员构成合法团队 $H_i$：大小 $\min(i+1, k) \leq k$，全部来自前缀。由引理 2，$H_i$ 的速度和为 $\text{sum}_i$；成员效率均 $\geq e_i$，故 $c_i = \text{sum}_i \times e_i \leq \text{sum}_i \times \min_{t \in H_i} e_t = \mathrm{perf}(H_i) \leq \mathrm{OPT}$。

（最优被某个候选覆盖）设 $T^*$ 为最优团队，取 $j = \max T^*$。由引理 1，$T^* \subseteq \{0..j\}$ 且 $\min_{t \in T^*} e_t = e_j$。由引理 2，$\text{sum}_j$ 是 $\{s_0, \dots, s_j\}$ 中最大的 $\min(j+1, k)$ 个之和：若 $j + 1 \leq k$，候选池全部入堆，自然不小于 $\sum_{t \in T^*} s_t$；否则 top-$k$ 和是一切大小 $\leq k$ 的子集速度和的最大者，亦有 $\text{sum}_j \geq \sum_{t \in T^*} s_t$。于是 $c_j = \text{sum}_j \times e_j \geq \big(\sum_{t \in T^*} s_t\big) \times e_j = \mathrm{perf}(T^*) = \mathrm{OPT}$。

两个方向合起来 $\max_i c_i = \mathrm{OPT}$；先求最大再取模不影响正确性。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n + n \log k)$。排序 $O(n \log n)$；主循环中每人恰一次 push、至多一次 pop，各 $O(\log k)$。由 $k \leq n$，总量 $O(n \log n)$，$n = 10^5$ 时仅数百万次堆操作，轻松通过。
- **空间复杂度**：$O(n)$。排序后的 $(e, s)$ 数组占大头；堆仅 $O(k)$。C++ 可原地排序 pair 数组，Python 的 `sorted` 会生成新列表，渐进不变。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxPerformance(int n, vector<int>& speed, vector<int>& efficiency, int k) {
        const long long MOD = 1e9 + 7;
        vector<pair<int, int>> eng(n);                    // (效率, 速度)
        for (int i = 0; i < n; i++) eng[i] = {efficiency[i], speed[i]};
        sort(eng.begin(), eng.end(), [](const auto& a, const auto& b) {
            return a.first > b.first;                     // 效率降序
        });

        priority_queue<int, vector<int>, greater<int>> heap;  // 小顶堆存速度
        long long sum = 0, ans = 0;
        for (auto& [e, s] : eng) {
            heap.push(s);
            sum += s;
            if ((int)heap.size() > k) {                   // 超员：踢最小速度
                sum -= heap.top();
                heap.pop();
            }
            ans = max(ans, sum * e);                      // e 即团队效率下界
        }
        return ans % MOD;                                 // 最后才取模
    }
};
```

### Python

```python
class Solution:
    def maxPerformance(self, n: int, speed: List[int],
                       efficiency: List[int], k: int) -> int:
        MOD = 10**9 + 7
        eng = sorted(zip(efficiency, speed), reverse=True)  # 效率降序
        heap = []              # 小顶堆，存已选工程师的速度
        sum_speed = 0
        ans = 0
        for e, s in eng:
            heapq.heappush(heap, s)
            sum_speed += s
            if len(heap) > k:                     # 超员：踢最小速度
                sum_speed -= heapq.heappop(heap)
            ans = max(ans, sum_speed * e)         # e 即团队效率下界
        return ans % MOD                          # 最后才取模
```

## 8. 边界情况与易错点

1. **中途取模（最高频 WA）**：`ans = max(ans, sum * e % MOD)` 是错的——模运算不保序，小值取模后可能反而更大。必须全程 `long long` 参与比较，返回前一次性取模。
2. **`int` 溢出**：`sum` 上界 $10^{10}$ 已远超 `int`（约 $2.1 \times 10^9$）；`sum * e` 上界 $10^{18}$ 仍在 `long long` 内。返回时 `ans % MOD < 10^9 + 7`，转 `int` 安全。
3. **「至多 $k$」不是「恰好 $k$」**：每步都要更新答案。反例：`speed = [100000, 1]`，`efficiency = [100000000, 1]`，`k = 2`——最优是只选第一个人得 $10^{13}$；若只在堆满 $k$ 时更新，只能得 $(100000 + 1) \times 1$。
4. **堆方向反了**：C++ 默认 `priority_queue` 是大顶堆——会踢掉最大速度，示例 1 直接错（只得 42）。保留 top-$k$ **大**值要用**小**顶堆。
5. **排序键选错**：必须按效率排。按速度排序会破坏「当前效率是前缀下界」的前提，证明全部失效。
6. **效率并列**：无需特判，任意先后都不影响前缀性质。
7. **$k \geq n$ 或 $k = 1$**：前者堆永不超员（等价于前缀全选），后者退化为 $\max(s_i \times e_i)$，代码无需分支。
8. **空团队**：题目保证 $k \geq 1$ 且速度、效率 $\geq 1$，任何团队表现值 $\geq 1$，`ans` 初值 0 安全，不存在「不选更优」的退化。
