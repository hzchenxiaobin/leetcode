# LeetCode 设计一个支持增量操作的栈 题解

## 1. 题目概述

- **标题 / 题号**：设计一个支持增量操作的栈（#1381，medium）
- **链接**：https://leetcode.cn/problems/design-a-stack-with-increment-operation/
- **来源**：LeetCode 第 180 场周赛 Q2
- **难度**：中等
- **标签**：栈、设计、数组

**题意**：实现容量为 `maxSize` 的 `CustomStack`。`push(x)` 在栈未满时把 `x` 压入**栈顶**，已满则**丢弃**；`pop()` 弹出并返回**栈顶**元素，栈空返回 `-1`；`increment(k, val)` 把**栈底**的 $k$ 个元素各加 `val`，若栈中元素不足 $k$ 则**全部**加上 `val`。

**约束**：$1 \le \text{maxSize}, x, k \le 1000$，$0 \le \text{val} \le 100$，且 `push`、`pop`、`increment` 三种方法**各自**最多被调用 $1000$ 次。

> 💡 先读约束定基调：$O(k)$ 的朴素 `increment` 在本题也能过（总代价 $\le 10^3 \times 10^3$）。但这道 Q2 真正值得带走的是「延迟更新」模板——怎样把一次 $O(k)$ 的前缀加值压成 $O(1)$。

## 2. 示例

**示例 1**（官方示例）

```text
输入：
["CustomStack","push","push","pop","push","push","push",
 "increment","increment","pop","pop","pop","pop"]
[[3],[1],[2],[],[2],[3],[4],[5,100],[2,100],[],[],[],[]]
输出：[null,null,null,2,null,null,null,null,null,103,202,201,-1]
解释：
CustomStack stk = new CustomStack(3);   // 栈 []
stk.push(1);                            // 栈 [1]
stk.push(2);                            // 栈 [1, 2]
stk.pop();                              // 返回 2，栈 [1]
stk.push(2);                            // 栈 [1, 2]
stk.push(3);                            // 栈 [1, 2, 3]
stk.push(4);                            // 已满，栈仍是 [1, 2, 3]
stk.increment(5, 100);                  // k 被截到 3，栈 [101, 102, 103]
stk.increment(2, 100);                  // 栈 [201, 202, 103]
stk.pop();                              // 返回 103，栈 [201, 202]
stk.pop();                              // 返回 202，栈 [201]
stk.pop();                              // 返回 201，栈 []
stk.pop();                              // 栈空 → 返回 -1
```

## 3. 解题思路

### 3.1 暴力思路：每次 `increment` 扫一遍前缀

用数组（`vector`）当栈：`push` / `pop` 都是尾部操作，$O(1)$；`increment(k, val)` 老老实实 `for (i = 0; i < min(k, size); i++) a[i] += val`，$O(k)$。它的**结构缺陷**很明显：一次 `increment` 触碰一整段前缀，而这段时间被 `pop` 掉的元素可能只有栈顶一两个——大量加法是「加完马上被丢掉」的白工；若 `maxSize` 与调用次数都放大到 $10^5$，最坏就是 $10^{10}$ 量级。

> 关键问题：**能不能让一次 `increment` 只做常数次修改，把「加」推迟到元素真正被弹出时再结算？**

### 3.2 核心观察：前缀互相嵌套，所以可以只记一格账

![延迟账：真实值 = 原始值 + add 的后缀和](images/wc180_q2_lazy_increment_model.svg)

两个操作的方向恰好**相反**：`increment(k, val)` 只作用于**栈底**的一段前缀 $\{0, 1, \dots, m-1\}$（$m = \min(k, \text{size})$），而 `pop()` 只移除**栈顶**的一个元素。也就是说「被加值的集合」永远是下标的**前缀**、「被删除的元素」永远是**后缀**；所有前缀都从下标 0 出发、彼此**嵌套**，于是任意多次 `increment` 叠加后，每个元素受到的增量恰好等于**包含它的那些前缀的 `val` 之和**。

于是引入与 `st` 等长的数组 `add`，规定真实值取 `add` 的**后缀和**：

$$\text{value}(i) \;=\; st[i] + \sum_{j=i}^{\text{top}} add[j]$$

这样一次 `increment(k, val)` 只需执行 $add[\min(k, \text{size}) - 1] \mathrel{+}= val$：下标 $i^{*} = m-1$ 的后缀 $\{i^{*}, \dots, \text{top}\}$ 恰好出现在所有 $i \le i^{*}$ 的求和中，而不出现在任何 $i > i^{*}$ 的求和里——正是「栈底 $m$ 个元素各加 `val`、其余不变」。一次加法，$O(1)$。

`pop()` 时栈顶 $i$ 的后缀只剩它自己，真实值即 $st[i] + add[i]$；取出后把这一格账**下推**一格（`add[i-1] += add[i]`），剩余元素的真实值就保持不变。

### 3.3 算法流程

![三个操作：push 追加 0，pop 结算并下推，increment 记一格账](images/wc180_q2_ops_flow.svg)

```text
数据结构：st[]（原始值）、add[]（每格的延迟账），两者等长，长度 ≤ maxSize

push(x):
    若 len(st) == maxSize: 直接丢弃 x
    否则: st.append(x); add.append(0)          # 新元素不欠账

pop():
    若 st 为空: 返回 -1
    i = len(st) - 1
    res = st[i] + add[i]                       # 栈顶的真实值
    若 i > 0: add[i-1] += add[i]               # 把账下推给剩余元素
    弹出 st[i] 与 add[i]
    返回 res

increment(k, val):
    若 st 为空: 直接返回                       # 没有元素可加
    add[min(k, len(st)) - 1] += val            # 一格账覆盖栈底 min(k,size) 个元素
```

三条规则都只读写**常数个**格子，所以三个操作的最坏时间都是 $O(1)$（不是均摊，是真正的每步常数）。

### 3.4 示例演算

![示例 1 的 12 步走查：记账、真实值与返回值](images/wc180_q2_walkthrough.svg)

走到示例 1 第 8 步：`st = [1, 2, 3]`，`add = [0, 100, 100]`（第 7 步记 `add[2] = 100`，第 8 步记 `add[1] += 100`）。按后缀和还原：下标 2 是 $3 + 100 = 103$，下标 1 是 $2 + 100 + 100 = 202$，下标 0 是 $1 + 0 + 100 + 100 = 201$，与官方解释的 `[201, 202, 103]` 完全一致，而我们**一次都没有真正把 100 加进 `st`**。

接着三次 `pop` 就是「结算 + 搬运」：先取 $103$，把 `add[2]` 并给 `add[1]`（变 200）；再取 $202$，把 `add[1]` 并给 `add[0]`（变 200）；最后取 $201$，无人可推。第四次 `pop` 时栈空，返回 $-1$。

## 4. 算法细节

1. **两个数组必须等长且同步**：`push` 时同时 `append`，`pop` 时同时弹出。若只维护 `st` 而让 `add` 落后半拍，下标就整体错位——这是本设计最典型的 bug 形态。
2. **`add` 的语义是「前缀隶属」而非元素自身属性**：`add[i]` 表示「后缀覆盖到 $i$ 的那些元素都该加的量」，所以真实值要靠**后缀和**还原。若误读成「`st[i]` 自己的增量」，示例 1 的下标 0 会算出 $1 + 0 = 1$，全错。
3. **`pop` 的三步顺序不能换**：先取 `res = st[i] + add[i]`（此时账还在），再 `add[i-1] += add[i]`，最后才 `pop_back` 两个数组。顺序颠倒要么丢账，要么栈顶值少一截。
4. **`increment` 的下标是 `min(k, size) - 1`**：`k ≥ size` 时都落到栈顶 `size - 1`（等价于全体加值），共用一条路径无需特判；但 `st` 为空时必须提前 `return`，否则 `size - 1 = -1` 在 C++ 里是越界 UB、在 Python 里会静默写到栈顶那一格（`add[-1]`）。
5. **满栈 `push` 要「真丢弃」**：被丢的 `x` 不能留下任何 `add` 格子，也不能把增量挂到旧栈顶，否则后续 `pop` 会把本该消失的值算进去。
6. **数值范围与「不摊平」**：$val \le 100$、`increment` 至多 $10^3$ 次，单元素最多累加 $10^5$，加 $x \le 1000$ 上限约 $1.01 \times 10^5$，`int` 足够；任何「定期把 `add` 并进 `st`」的优化都会把总代价抬回 $O(k)$，`add` 只在 `pop` 时被动下推一格才是 $O(1)$ 的来源。

## 5. 正确性证明

**引理 1（不变量）**：任意操作结束后，对栈中每个下标 $i \in [0, \text{top}]$，有

$$\text{value}(i) = st[i] + \sum_{j=i}^{\text{top}} add[j]$$

且该值等于题面定义下第 $i$ 个（自栈底数起）元素应持有的值。

**证明**：对操作次数归纳，初始空栈命题平凡成立。

- `push(x)`（未满）：新元素下标 $\text{top}' = \text{top}+1$，真实值 $= st[\text{top}'] + add[\text{top}'] = x + 0 = x$，符合定义；旧元素的下标与所有 `add` 均未变，而「后缀 $\{i, \dots, \text{top}'\}$」只比原来多出 `add[top'] = 0`，和不变。
- `increment(k, val)`：令 $m = \min(k, \text{size})$、$i^{*} = m-1$ 并执行 `add[i*] += val`。对任意 $i \le i^{*}$，后缀含 $i^{*}$，和恰增加 `val`；对任意 $i > i^{*}$，后缀不含 $i^{*}$，和不变——正是「栈底 $m$ 个元素各加 `val`，其余不变」。
- `pop()`：栈顶 $\text{top}$ 的后缀只有 $\{top\}$，故 $st[\text{top}] + add[\text{top}]$ 就是它应持有的值。随后 `add[top-1] += add[top]` 使每个剩余 $i \le \text{top}-1$ 的新后缀和 $\sum_{j=i}^{\text{top}-1} add[j] + add[\text{top}]$ 与旧后缀和相等，真实值不变。∎

**引理 2（容量与空栈语义）**：`push` 在 `size == maxSize` 时不改变任何状态；`pop` 在空栈时返回 $-1$ 且不改变状态；`increment` 在空栈时是空操作。

**证明**：三个分支都在进入修改逻辑前 `return`，状态未被触碰，返回值依次为「无」「$-1$」「无」，与题面逐条对应（空栈上「全部元素加 `val`」是空集上的操作）。∎

**定理**：本实现下三个操作的对外行为与题面定义完全一致，且每个操作最坏 $O(1)$ 时间。

**证明**：由引理 1，任意时刻每个元素的真实值都等于它应持有的值，因此 `pop` 返回正确；由引理 2，边界语义正确；三个操作各自只做常数次数组读写与一次比较，故最坏 $O(1)$。∎

## 6. 复杂度分析

- **时间**：`push`、`pop`、`increment` 均为**最坏** $O(1)$（非均摊），每次 1–3 次数组读写；总时间 $O(q)$，$q$ 为操作总数（本题 $\le 3 \times 10^3$），对比朴素实现的 $O(q \cdot k)$。
- **空间**：$O(\text{maxSize})$，`st` 与 `add` 各至多 `maxSize` 个 `int`，无哈希表、无递归栈。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class CustomStack {
    int maxSize;
    vector<int> st;    // 原始值
    vector<int> add;   // 每格的延迟账（真实值 = st[i] + add[i..top] 的后缀和）
public:
    CustomStack(int maxSize) : maxSize(maxSize) {}

    void push(int x) {
        if ((int)st.size() < maxSize) {
            st.push_back(x);
            add.push_back(0);          // 新元素不欠账
        }
    }

    int pop() {
        if (st.empty()) return -1;
        int i = (int)st.size() - 1;
        int res = st[i] + add[i];          // 栈顶的后缀只有自己
        if (i > 0) add[i - 1] += add[i];   // 账下推给剩余元素
        st.pop_back();
        add.pop_back();
        return res;
    }

    void increment(int k, int val) {
        if (st.empty()) return;            // 空栈：无元素可加，也避免下标 -1
        int i = min(k, (int)st.size()) - 1;
        add[i] += val;                     // 一格账覆盖栈底 min(k, size) 个元素
    }
};
```

### Python

```python
class CustomStack:
    def __init__(self, maxSize: int):
        self.maxSize = maxSize
        self.st = []    # 原始值
        self.add = []   # 延迟账：真实值 = st[i] + add[i..top] 的后缀和

    def push(self, x: int) -> None:
        if len(self.st) < self.maxSize:
            self.st.append(x)
            self.add.append(0)

    def pop(self) -> int:
        if not self.st:
            return -1
        i = len(self.st) - 1
        res = self.st[i] + self.add[i]
        if i > 0:
            self.add[i - 1] += self.add[i]   # 账向栈底挪一格
        self.st.pop()
        self.add.pop()
        return res

    def increment(self, k: int, val: int) -> None:
        if not self.st:
            return                           # 空栈直接返回，绝不能写 add[-1]
        i = min(k, len(self.st)) - 1
        self.add[i] += val
```

## 8. 边界情况与易错点

1. **空栈上的 `increment`**：题面允许调用（「若栈中元素总数小于 k，则栈中所有元素增加 val」，空集也满足），必须**直接返回**。C++ 里 `(int)add.size() - 1` 为 $-1$，写入即越界 UB；Python 里 `add[-1] += val` 会静默写到**栈顶那一格**，把未来的返回值改坏，小样例极难暴露。
2. **空栈 `pop` 返回 $-1$**，不是 $0$、也不是异常；约束保证 $x \ge 1, val \ge 0$，所以 $-1$ 不会与真实元素值混淆。
3. **容量为 1**：`push` 只能存一个；`increment` 无论 $k$ 多大都只作用于这一个元素（$i$ 恒为 0），示例 2 就在考这一点。
4. **`pop` 的下推必须在 `pop_back` 之前完成**：`res` 的取值与下推先后无所谓（两者读的都是原 `add[i]`），但账一旦随数组弹出就再也找不回来，剩余元素会凭空少一截增量。
5. **`k` 与 `size` 的截断方向**：必须用 `min(k, size)`；`k > size` 时若不截断就会写到下标 $k-1 \ge \text{size}$ 的越界位置。
6. **`push` 用 `< maxSize` 而非 `<=`**：多存一个元素会让示例 1 第 6 步的「丢弃 4」变成「入栈 4」，之后所有 `pop` 的返回值全错；同时注意被丢弃的 `x` 不参与任何后续运算。

**延伸思考**：「延迟账」成立的前提是「加值作用域为嵌套前缀、删除位置在后缀」。若改成「对任意区间 $[l, r]$ 加 `val`」，前缀嵌套性消失，后缀和无法还原任意区间，此时要用**差分数组 + 弹出结算**或 **Fenwick（树状数组）** 支持区间加 / 单点查，代价升到 $O(\log n)$；若还要求「随时查询第 $i$ 个元素的真实值」（而非只在弹出时），同样只能用 Fenwick 维护。反过来，若 `increment` 改为作用于**栈顶** $k$ 个元素，影响集合变成后缀、`pop` 恰好逐个消掉，直接在弹出时扣减即可，反而比本题更简单。
