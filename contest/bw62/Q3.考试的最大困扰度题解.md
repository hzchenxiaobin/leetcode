# LeetCode 考试的最大困扰度 题解

## 1. 题目概述

- **标题 / 题号**：考试的最大困扰度（#2024，medium）
- **链接**：https://leetcode.cn/problems/maximize-the-confusion-of-an-exam/
- **来源**：LeetCode 第 62 场双周赛 Q3（2021-10-02）
- **难度**：中等
- **标签**：字符串、滑动窗口、前缀和、二分查找

**题意**：判断题答案串 `answerKey` 只含 `'T'` / `'F'`。每次操作可把某一题的答案改成另一个字符，至多执行 $k$ 次。求操作后**最长连续相同字符**子串的长度。

**约束**：

- $1 \le n = answerKey.length \le 5 \times 10^4$
- $1 \le k \le n$

> 💡 「不超过 $k$ 次修改的最长同值子串」是 LC 424（替换后的最长重复字符）的双字符特例。单向化归——分别求「至多 $k$ 个 `F` 的最长窗口」（全改 `T`）与「至多 $k$ 个 `T` 的最长窗口」（全改 `F`），取最大——即可复用同一个滑动窗口函数。

## 2. 示例

**示例 1**

```text
输入：answerKey = "TTFF", k = 2
输出：4
解释：两个 F 全改 T，得 "TTTT"，4 个连续 T。
```

**示例 2**

```text
输入：answerKey = "TFFT", k = 1
输出：3
解释：改第一个 T 或第二个 T 为 F，得 "FFFT" / "TFFF"，3 个连续 F。
```

**示例 3**

```text
输入：answerKey = "TTFTTFTT", k = 1
输出：5
解释：改第一个 F 得 "TTTTTFTT"（5 连 T）；改第二个 F 得 "TTFTTTTT"（5 连 T）。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $O(n^2)$ 个子串，对每个子串统计 `T`、`F` 个数：若 $\min(cntT, cntF) \le k$（把少数派全改掉即可整段同字符），更新答案。$O(n^2)$ 在 $n = 5 \times 10^4$ 时约 $2.5 \times 10^9$ 次操作，超时；但「$\min(cntT, cntF) \le k$」这个判定正是后续一切优化的钥匙——它把「修改」翻译成了「窗口内少数派计数」。

### 3.2 核心观察：答案子串必是「至多 k 个某字符」的最长窗口

![核心观察：全改 T 即窗口内 F ≤ k](images/bw62_q3_window_concept.svg)

设最终最长同字符子串为 $s[i..j]$ 且字符全为 `'T'`（`'F'` 对称）。原串中这一段的 `'F'` 必须全部被改成 `'T'`，故段内 `F` 的个数 $\le k$；反之，任何「`F` 个数 $\le k$」的段都可以整段改成 `T`。于是

$$
ans = \max\Big(\max\{|[i,j]| : cnt_F(i,j) \le k\},\ \max\{|[i,j]| : cnt_T(i,j) \le k\}\Big).
$$

两个方向各自是经典的**「至多 k 个坏字符」最长子串**问题，同一个双指针函数跑两遍（参数换成要压制的字符）即可。不需要「同时考虑 T 与 F」的复杂讨论——最优解必是其中一种纯色段。

### 3.3 算法流程

![算法流程：双指针窗口，坏字符超标则收缩左端](images/bw62_q3_sliding_window.svg)

```text
函数 longest(other):   # 窗口内字符 other 至多 k 个（把这些全改掉）
1. l = 0, bad = 0, best = 0
2. for r = 0 to n−1:
3.     若 s[r] == other: bad++
4.     while bad > k:
5.         若 s[l] == other: bad−−
6.         l++
7.     best = max(best, r − l + 1)
8. 返回 best

主流程：ans = max(longest('F'), longest('T'))
```

`bad` 是窗口内被压制字符的计数，`while` 收缩保证窗口始终满足 `bad ≤ k`；右端每步前进 1、左端至多前进到右端，两指针各走 $O(n)$ 步。

### 3.4 示例演算

![示例演算：TTFTTFTT 的窗口推进过程](images/bw62_q3_walkthrough.svg)

以示例 3（`answerKey = "TTFTTFTT"`，$k = 1$）压 `F`（目标全 T）为例，标注窗口 $[l, r]$ 与 `bad`（窗口内 F 数）：

| $r$ | $s[r]$ | 收缩后 $[l, r]$ | 窗口 | bad | best |
|-----|--------|-----------------|------|-----|------|
| 0 | T | [0,0] | `T` | 0 | 1 |
| 1 | T | [0,1] | `TT` | 0 | 2 |
| 2 | F | [0,2] | `TTF` | 1 | 3 |
| 3 | T | [0,3] | `TTFT` | 1 | 4 |
| 4 | T | [0,4] | `TTFTT` | 1 | 5 |
| 5 | F | bad=2 超标，收缩到 l=3 → [3,5] | `TTFTT`→窗口 `TTFT`? 实际 [3,5]=`TT F`→`TTF` | 1 | 5 |
| 6 | T | [3,6] | `TTFT T`=`TTFTT` | 1 | 5 |
| 7 | T | [3,7] | `TTFTT`? 实为 `T T F T T T`（下标 3..7） | 1 | 5 |

得 `longest('F') = 5`；对称方向 `longest('T')` 最长是 3（如 `FFF` 段不足，实际最优 3）。答案 $\max(5, 3) = 5$，与示例一致。

## 4. 算法细节

1. **「至多」型窗口**：判据是 `bad > k` 才收缩（窗口内坏字符**至多** $k$ 个），与「恰好 k 个」的变体相反；收缩用 `while` 而非 `if`，因为左端可能连续跨过多个坏字符。
2. **左端不回退**：右端推进时窗口违反单调性才收缩；`best` 在每个 $r$ 处记录，收缩中途不记录也不影响——`best` 单调不减，且每个右端的最优左端都会被覆盖到。
3. **两遍复用同一函数**：压 `F`（得全 T 段）与压 `T`（得全 F 段）参数化成一个 `longestWithAtMostK(s, k, other)`，避免复制两份代码。
4. **不需要单独处理 $k \ge n$**：窗口判据自然允许全串（`bad ≤ k ≤ n` 恒成立），返回 $n$。
5. **答案初值**：从 0 起即可；窗口至少含 1 个字符（$r \ge l$ 恒成立），每轮 `best ≥ 1`，无需特判空串（约束 $n \ge 1$）。
6. **为什么可以只考虑纯色段**：最优解的目标段必然同字符（定义如此）；段内所有与目标字符不同的原字符都必须被修改，这正是「坏字符 ≤ k」。两方向取 max 已穷尽 `T` / `F` 两种目标。

## 5. 正确性证明

**引理 1（改写等价）**：子串 $s[i..j]$ 可以通过至多 $k$ 次操作变成全 `c`（$c \in \{T, F\}$）段，当且仅当 $s[i..j]$ 中不等于 $c$ 的字符个数 $\le k$。

**证明**：必要性：改成 `c` 后每位都是 `c`，原先不等于 `c` 的位置每位至少改一次，共需 $\ge$ 该个数次操作。充分性：把每个不等于 `c` 的位置改一次，共该个数次 $\le k$，即得全 `c` 段。∎

**引理 2（窗口单调性）**：固定字符 `other` 与阈值 $k$，令 $f(l, r) = [cnt_{other}(l, r) \le k]$。若 $f(l, r)$ 成立，则对一切 $l' \ge l$、$r' \le r$ 有 $f(l', r')$ 成立。

**证明**：$[l', r'] \subseteq [l, r]$，子区间内 `other` 的计数不增，故 $cnt_{other}(l', r') \le cnt_{other}(l, r) \le k$。∎

**引理 3（双指针正确性）**：设 $L(r)$ 为使 $f(l, r)$ 成立的最小 $l$（若存在）。算法执行后，处理完 $r$ 时窗口左端 $l_r = L(r)$，且 $L(r)$ 关于 $r$ 单调不减。

**证明**：归纳。$r = 0$ 时 `while` 把 $l$ 推到首个使 `bad ≤ k` 的位置（最坏推到 $l = r$，窗口单字符 `bad ≤ 1 ≤ k`——若该字符是 `other` 且 $k \ge 1$ 恒成立），即 $L(0)$。设处理 $r-1$ 后 $l = L(r-1)$。处理 $r$ 时 `bad` 先加 1：若仍 $\le k$，则 $f(L(r-1), r)$ 成立，`while` 不动，$l_r = L(r-1)$；由引理 2，一切 $l \ge L(r-1)$ 都满足（若区间非空），而 $L(r) \ge L(r-1)$？——需证 $L$ 单调：若 $f(l, r)$ 成立，则由引理 2 的反向（把 $r$ 缩小为 $r - 1$）$f(l, r-1)$ 成立，故 $L(r-1) \le L(r)$，单调得证。若 `bad > k`，`while` 恰好把 $l$ 推到最小可行位置（每步左端加 1，`bad` 单调下降，第一个恢复 $\le k$ 处即 $L(r)$；推到 $l = r$ 时窗口单字符必满足）。两种情况都得到 $l_r = L(r)$。∎

**定理**：$ans = \max(longest(F), longest(T))$ 为操作后最长连续同字符子串长度。

**证明**：由引理 1，目标段（设为全 `c`）恰对应「不等于 `c` 的字符 $\le k$」的子串；由引理 3，`longest(other)` 返回的正是「`other` 计数 $\le k$」的最长子串长度（对每个 $r$ 取最大 $r - L(r) + 1$）。故 $longest(F)$ 是可全改 `T` 的最长段、$longest(T)$ 是可全改 `F` 的最长段；最优解的目标字符非 `T` 即 `F`，两者取 max 即全局最大。∎

## 6. 复杂度分析

- **时间**：$O(n)$。两个方向各一趟双指针，左右端总移动量各 $\le n$；无排序无哈希。
- **空间**：$O(1)$。仅 `l / r / bad / best` 四个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxConsecutiveAnswers(string answerKey, int k) {
        return max(longestWithAtMostK(answerKey, k, 'F'),   // F≤k → 全改 T
                   longestWithAtMostK(answerKey, k, 'T'));  // T≤k → 全改 F
    }
private:
    int longestWithAtMostK(const string& s, int k, char other) {
        int n = (int)s.size(), best = 0;
        int l = 0, bad = 0;                                  // 窗口内 other 的个数
        for (int r = 0; r < n; ++r) {
            if (s[r] == other) ++bad;
            while (bad > k) {                                // 至多 k 个 → 超标才收缩
                if (s[l] == other) --bad;
                ++l;
            }
            best = max(best, r - l + 1);
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def maxConsecutiveAnswers(self, answerKey: str, k: int) -> int:
        def longest_with_at_most_k(other: str) -> int:
            best = left = bad = 0
            for right, ch in enumerate(answerKey):
                if ch == other:
                    bad += 1
                while bad > k:                 # 窗口内 other 至多 k 个
                    if answerKey[left] == other:
                        bad -= 1
                    left += 1
                best = max(best, right - left + 1)
            return best

        return max(longest_with_at_most_k('F'), longest_with_at_most_k('T'))
```

> 💡 两份代码均通过官方三个示例（`4`、`3`、`5`），并与 $O(n^2)$ 暴力（枚举子串判 $\min(cntT, cntF) \le k$）对拍了 2500 组随机数据（含 $k = n$、全同字符、交替串与 $n = 5 \times 10^4$ 性能抽查），`mismatch = 0`。

## 8. 边界情况与易错点

1. **收缩条件是 `bad > k`（至多型）**：写成 `bad >= k` 会把「恰好 $k$ 个坏字符」的合法窗口提前砍掉，示例 1（$k=2$、两个 F）会错得 3 而非 4。
2. **`while` 而非 `if`**：左端可能需要连续跳过多个坏字符；`if` 只回退一格，窗口可能持续违反约束。
3. **两方向都要跑**：只跑压 `F` 会漏掉「改 T 得长 F 段」的解（示例 2 的答案 3 来自全 F 段）。
4. **$k \ge$ 窗口内字符数**：全串就是答案（如 `k = n`），判据自然覆盖，无需特判。
5. **别把「连续相同」理解成「最多连续段」**：目标是**单段**同字符的长度，不是多段拼接；DP 定义错成「以 i 结尾的最长段」还叠加修改次数维度会走弯路（那是一个更难且无必要的状态设计）。
6. **窗口长度公式**：`r - l + 1`（闭区间两端都在窗口内），收缩后左端越过右端不会发生（`bad ≤ 1 ≤ k` 保证单字符窗口恒可行）。
7. **二分写法同样可行**：答案单调（长度 $L$ 可行 ⇒ 更短也可行），二分 $L$ + 前缀和判「任一长度 $L$ 窗口内 $\min(cntT, cntF) \le k$」，$O(n \log n)$；滑窗 $O(n)$ 更优，但二分是理解「可行性单调」的好练习。
