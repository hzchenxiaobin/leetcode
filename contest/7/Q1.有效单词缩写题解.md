# LeetCode 有效单词缩写 题解

## 1. 题目概述

- **标题 / 题号**：有效单词缩写（#408，easy）
- **链接**：https://leetcode.cn/problems/valid-word-abbreviation/
- **来源**：LeetCode 第 7 场周赛 Q1
- **难度**：简单
- **标签**：双指针、字符串、模拟

**题意**：给定非空字符串 `word` 与缩写 `abbr`，判断 `abbr` 是否是 `word` 的合法缩写。「缩写」的构造方式是：把 `word` 中**任意若干段互不相邻的非空子串**替换成它们的长度（十进制数字），其余字符原样保留。

换成"读"的视角，把 `abbr` 切成 token 序列后：

- **字母 token**：必须与 `word` 当前位置的字符相同，消耗 1 个字符；
- **数字 token** $k$：消耗**恰好** $k$ 个字符，内容不看。

`abbr` 合法，当且仅当存在这样一条消费路径，使两个串**同时**走到末尾。

**约束**：

- $1 \le \lvert word \rvert \le 20$，`word` 仅由小写英文字母组成
- $1 \le \lvert abbr \rvert \le 10$，`abbr` 由小写字母与数字组成
- 数字 token 必须满足 $k \ge 1$ 且无前导零（题面枚举的 16 个合法缩写里没有 `0ord`、`01rd`）

> 💡 **审题关键**：数字不是"匹配 $k$ 个字符"，而是"**跳过** $k$ 个字符"；而且 $k$ 由 `abbr` **单方面**决定。匹配因此没有分支——这是本题一切简洁性的来源。

## 2. 示例

**示例 1**

```text
输入：word = "internationalization", abbr = "i12iz4n"
输出：true
解释：i + 跳过 12 个字符 (nternational) + i + z + 跳过 4 个字符 (atio) + n
      消耗 1 + 12 + 1 + 1 + 4 + 1 = 20 = len(word)，两串同时走到末尾。
```

**示例 2**

```text
输入：word = "apple", abbr = "a2e"
输出：false
解释：a 匹配 word[0]，i = 1；数字 2 跳过 "pp"，i = 3；
      此时 abbr 要求 'e'，而 word[3] = 'l'，字母不等 → false。
```

**示例 3**（补充示例：题面未给，用来钉住"整段数字一次读完"）

```text
输入：word = "substitution", abbr = "s10n"
输出：true
解释：s 消耗 1 格；10 消耗 10 格（覆盖 "ubstitutio"）；n 恰为 word[11]。
      总消耗 1 + 10 + 1 = 12 = len(word)。
```

## 3. 解题思路

### 3.1 暴力思路

按定义生成 `word` 的全部合法缩写：每个位置选择"保留字母"或"并入一段长度 $\ge 1$ 的数字"，再把 `abbr` 丢进集合里查。

方案数是指数级的：长度为 $n$ 的词恰好有 $2^{n}$ 个合法缩写（`"word"` 正好 16 个，与题面列出的清单一致），$n = 20$ 时约 $10^6$，还要带上"数字段不相邻""无前导零"的约束与字符串去重，代码又长又慢。

更关键的是，"生成再比对"浪费了题目的结构：**`abbr` 已经把每一段消耗多少字符写死了**。字母 token 消耗 1，数字 token 消耗 $k$——没有"选择"，也就没有搜索空间，更不需要回溯。

### 3.2 核心观察：token 消耗长度固定 → 双指针唯一路径

![核心观察：token 消耗长度固定，匹配路径唯一](images/wc7_q1_token_concept.svg)

把 `abbr` 做**唯一**的 token 切分：字母各自成 token，**连续数字字符合并成一个**数字 token（`"12"` 是 12，不是 1 和 2）。

| token | 消耗的 `word` 字符数 | 校验条件 |
|-------|---------------------|----------|
| 字母 $c$ | 1 | `word[i] == c`，且 $i < n$ |
| 数字 $k$ | $k$（不看内容） | 首字符非 `'0'`，且 $i + k \le n$ |

于是"是否匹配"退化成一维走格子：从 $(i, j) = (0, 0)$ 出发，每步按 `abbr[j]` 的类型唯一确定后继，$i$ 只增不减、$j$ 只增不减。**路径唯一，所以不需要 DFS、不需要 DP、也不需要记忆化**。

失败情形同样只有四类，全部能在走的过程中当场判掉：

1. 字母 token 与 `word[i]` 不等，或 $i$ 已经等于 $n$；
2. 数字 token 首字符是 `'0'`（$k = 0$ 或带前导零）；
3. 跳过之后 $i + k > n$；
4. 走完所有 token 后 $i \ne n$ 或 $j \ne m$。

### 3.3 算法流程 / 状态转移

![算法流程：一次扫描，四类失败立即返回](images/wc7_q1_two_pointer_flow.svg)

| 步骤 | 条件 | 动作 |
|------|------|------|
| ① | $j = m$ | 退出循环，返回 $i = n \wedge j = m$ |
| ② | `abbr[j]` 是数字 | 若 `abbr[j] == '0'` → `false`；否则整段读出 $k$，$i \leftarrow i + k$、$j$ 移到数字段之后 |
| ③ | `abbr[j]` 是字母 | 若 $i = n$ 或 `word[i] != abbr[j]` → `false`；否则 $i{+}{+}$、$j{+}{+}$ |
| ④ | 每步之后（不变式） | 保证 $0 \le i \le n$；越界已在②③里当场返回 |

状态转移可以写成一句话：$(i, j) \to (i+1,\, j+1)$（字母），或 $(i, j) \to (i+k,\, j+\text{数字段长度})$（数字）。两个坐标都严格增加，循环必然终止。

### 3.4 示例演算

![示例演算：i12iz4n 的六步推进](images/wc7_q1_example_walkthrough.svg)

对 `word = "internationalization"`（$n = 20$）、`abbr = "i12iz4n"`（$m = 7$）逐步推进：

| 步 | token | `word` 区间 | 动作 | 校验 | $i$ 之后 |
|----|-------|-------------|------|------|----------|
| 1 | `i` | $[0, 1)$ | 字母比对 | `word[0] = 'i'` ✓ | 1 |
| 2 | `12` | $[1, 13)$ | 跳过 12 格 | $1 + 12 = 13 \le 20$ | 13 |
| 3 | `i` | $[13, 14)$ | 字母比对 | `word[13] = 'i'` ✓ | 14 |
| 4 | `z` | $[14, 15)$ | 字母比对 | `word[14] = 'z'` ✓ | 15 |
| 5 | `4` | $[15, 19)$ | 跳过 4 格 | $15 + 4 = 19 \le 20$ | 19 |
| 6 | `n` | $[19, 20)$ | 字母比对 | `word[19] = 'n'` ✓ | 20 |

结束时 $i = 20 = n$、$j = 7 = m$，返回 `true`。

反例 `word = "apple"`、`abbr = "a2e"`：`'a'` 比对通过（$i = 1$），数字 2 跳到 $i = 3$，此时 `abbr` 要求 `'e'` 而 `word[3] = 'l'`，落入第 1 类失败，当场返回 `false`。

## 4. 算法细节

1. **数字必须整段读完**：遇到数字后用内层 `while` 一直读到非数字，累加 $k = 10k + d$。若只读一位就跳，`"i12iz4n"` 会被误解成"跳 1 格、跳 2 格、再比对 `i`"，结果全错。
2. **前导零只需看首字符**：token 首字符是 `'0'` 就非法——它同时覆盖单独的 `"0"`（被替换子串非空）与 `"01"`、`"007"`（前导零）。解析完再判长度是多余动作。
3. **防溢出**：$m \le 10$ 时数字最大约 $10^{10}$，超过 32 位 `int`。本文在累加过程中就判 $k > n$ 直接返回——因为 $k$ 一旦超过 $n$，无论 $i$ 取值如何都必然越界；于是每次累加前 $k \le n$，累加后最多 $10n + 9$（$n \le 20$ 时不超过 209），`int` 都不可能溢出（用 `long long` 同样安全）。
4. **越界比较用 `>` 而不是 `>=`**：$i + k = n$ 是合法终态（`"word"` 对 `"4"`），只有 $i + k > n$ 才失败。
5. **收尾必须两侧都查**：循环条件只保证 `abbr` 走完，`word` 可能还剩字符（`"abc"` 对 `"a1"`），也可能 `word` 走完而 `abbr` 还有 token（`"hi"` 对 `"hi1"`）。故返回 $i = n \wedge j = m$。
6. **字符分类**：C++ 用 `isdigit((unsigned char)c)`（先转无符号，避免负值 UB），Python 用 `c.isdigit()`；也可直接判断 `'0' <= c && c <= '9'`。输入保证只含字母与数字，两种写法等价。
7. **不要构造子串**：判定只要计数，$O(1)$ 空间足够；若改用 `abbr.substr(...)` 再 `stoi`，既有额外拷贝，又要单独处理 `"01"` 与溢出。

## 5. 正确性证明

**引理 1（token 分解唯一）**：`abbr` 的 token 切分唯一：每个字母单独成 token，每段极长连续数字构成一个数字 token；且每个 token 消耗的 `word` 字符数是固定的（字母 1 个，数字 $k$ 个）。

**证明**：切分规则由字符类别直接决定，相邻数字必属同一 token（否则会凭空拆出一个不存在的边界），故切分唯一。消耗长度由 token 语义给出：字母对应"保留的 1 个字符"，数字对应"被替换子串的长度 $k$"，与出现位置无关。∎

**引理 2（匹配不变量）**：循环每轮开始时，已处理 token 消耗的字符数恰为 $i$，且这些字符与 `word` 的前 $i$ 个字符逐位相同（数字 token 只计数、不比对内容）；$j$ 指向下一个 token 的首字符。

**证明**：对已处理 token 的个数归纳。初始 $(i, j) = (0, 0)$，空前缀成立。字母 token：先校验 $i < n$ 且 `word[i] == abbr[j]`，再 $i{+}{+}$、$j{+}{+}$，新增的那 1 个字符已确认相符，消耗量 $+1$。数字 token：解析出 $k$ 并校验 $k \le n - i$，令 $i \leftarrow i + k$、$j$ 移到 token 末尾；按语义它消耗 $k$ 个字符且不比对内容，不变量保持。∎

**引理 3（拒绝必真）**：算法返回 `false` 的每一种情形，都确实说明 `abbr` 不是 `word` 的合法缩写。

**证明**：按四个出口分类。
（a）数字 token 首字符为 `'0'`：该 token 的数值为 0 或带前导零，而合法缩写要求被替换子串非空（长度 $\ge 1$）且数字无前导零，故非法。
（b）$i + k > n$：所有 token 的消耗量之和已超过 $n$，不可能恰好覆盖 `word`。
（c）字母 token 失配或 $i = n$：合法缩写在保留字母的位置必须与该位置字符相同，且该位置必须存在。
（d）结束时 $i \ne n$ 或 $j \ne m$：前者说明消耗总量不等于 $n$，后者说明还有 token 未被处理。∎

**定理**：算法返回 `true` 当且仅当 `abbr` 是 `word` 的合法缩写。

**证明**：

（$\Leftarrow$）设 `abbr` 是合法缩写，则存在某个切分与消耗序列，使各保留字母与 `word` 对应位置相同，且数字段长度与字母个数之和恰为 $n$。由引理 1 切分唯一，算法处理的正是这串 token；由引理 2 的推进方式，$i$ 始终等于前缀消耗和。合法缩写的数字 token 满足 $k \ge 1$、无前导零，且 $k \le n - i$（总消耗为 $n$，其余 token 消耗量非负）；字母 token 处必有 $i < n$ 且字符相同。因此四个 `false` 出口都不会触发。循环结束时 $j = m$ 且 $i = n$，返回 `true`。

（$\Rightarrow$）设算法返回 `true`，则循环完整走完且 $i = n$、$j = m$。由引理 2，每个字母 token 都与 `word` 对应位置相同，每个数字 token 消耗了 $k$ 个字符且未越界；把这些 token 还原成"字母保留 / 数字段替换"的切分，即得 `word` 的一个合法缩写，且字面正是 `abbr`。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。$j$ 单调扫过 `abbr` 一次，共 $m$ 个字符；$i$ 单调推进且不超过 $n$，数字 token 的跳跃是一次加法而非逐字符访问；内层数字解析读到的总位数不超过 $m$。没有任何回退或重复扫描。
- **空间**：$O(1)$。只用 $i, j, k$ 三个整型变量，不构造子串、不开数组。
- **下界**：判定必须读到失配点或两个串的末尾，$\Omega(n + m)$ 已是最优；实现常数也极小（每字符一次比较）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool validWordAbbreviation(string word, string abbr) {
        int n = word.size(), m = abbr.size();
        int i = 0, j = 0;
        while (j < m) {
            if (isdigit((unsigned char)abbr[j])) {
                if (abbr[j] == '0') return false;        // 0 与前导零都非法
                long long k = 0;
                while (j < m && isdigit((unsigned char)abbr[j])) {
                    k = k * 10 + (abbr[j] - '0');
                    if (k > n) return false;             // 边解析边截断，顺带防溢出
                    ++j;
                }
                if (i + k > n) return false;             // 跳过越界
                i += (int)k;
            } else {
                if (i >= n || word[i] != abbr[j]) return false;
                ++i; ++j;                                // 字母 token：消耗 1 格
            }
        }
        return i == n && j == m;                         // 两侧都要到末尾
    }
};
```

### Python

```python
class Solution:
    def validWordAbbreviation(self, word: str, abbr: str) -> bool:
        n, m = len(word), len(abbr)
        i = j = 0
        while j < m:
            c = abbr[j]
            if c.isdigit():
                if c == '0':                 # 0 与前导零都非法
                    return False
                k = 0
                while j < m and abbr[j].isdigit():
                    k = k * 10 + int(abbr[j])
                    if k > n:                # 边解析边截断，顺带防溢出
                        return False
                    j += 1
                if i + k > n:                # 跳过越界
                    return False
                i += k
            else:
                if i >= n or word[i] != c:
                    return False
                i += 1                       # 字母 token：消耗 1 格
                j += 1
        return i == n and j == m             # 两侧都要到末尾
```

## 8. 边界情况与易错点

1. **`"0"` 与前导零**：`word = "word", abbr = "w0rd"` → `false`；`"01rd"`、`"w01d"` 同理。题面列出的 16 个合法缩写里没有它们。只判 token 首字符即可，不必再判长度。
2. **收尾只判一侧**：`word = "hi", abbr = "hi1"` → $i = 2 = n$ 但 $j = 2 < m$，必须 `false`；`word = "abc", abbr = "a1"` → $i = 2 \ne 3$，同样 `false`。
3. **越界的边界值**：`word = "a", abbr = "2"` → $i + k = 2 > 1$，`false`；但 `word = "word", abbr = "4"` → $i + k = 4 = n$ 且 `abbr` 恰好吃完，为 `true`。比较必须是 `>`。
4. **数字后接字母但词已耗尽**：`word = "word", abbr = "4d"` → 跳过 4 格后 $i = n$，再遇字母 token 时 $i \ge n$ → `false`。
5. **大数字溢出**：`abbr = "9999999999"`（10 位）在 C++ 里用 `int` 累加会溢出（UB）。本文"边解析边判 $k > n$"从根上避免了这个问题。
6. **相邻数字要合并**：`"1o1d"` 合法，但 `"11"` 表示 11 而不是两个 1；数字 token 必须整段读完，不能读一位就处理。
7. **`char` 传给 `isdigit` 的符号性**：`abbr` 只含 ASCII，通常无害，但严格写法是 `isdigit((unsigned char)c)`。
