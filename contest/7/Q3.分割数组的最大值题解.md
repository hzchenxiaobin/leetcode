# LeetCode 分割数组的最大值 题解

## 1. 题目概述

- **标题 / 题号**：分割数组的最大值（#410，hard）
- **链接**：https://leetcode.cn/problems/split-array-largest-sum/
- **来源**：LeetCode 第 7 场周赛 Q3
- **难度**：困难
- **标签**：贪心、数组、二分查找、动态规划、前缀和

**题意**：给定非负整数数组 `nums` 和整数 $k$，把数组切成 $k$ 段**非空连续**子数组。设第 $i$ 段的和为 $S_i$，令 $M=\max_i S_i$，求所有切法中 $M$ 的最小值。

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $0 \le \text{nums}[i] \le 10^6$
- $1 \le k \le \min(50,\ \text{nums.length})$

**题意里的关键前提**：元素全部**非负**。它同时决定了两件事——贪心能「只进不退」地切段，以及二分所需的单调性；第五节会看到它出现在证明的哪一步。

## 2. 示例

**示例 1**

```text
输入：nums = [7,2,5,10,8]，k = 2
输出：18
解释：一共四种切法，各自的「最大段和」为
      [7] | [2,5,10,8]    → max(7, 25)  = 25
      [7,2] | [5,10,8]    → max(9, 23)  = 23
      [7,2,5] | [10,8]    → max(14, 18) = 18
      [7,2,5,10] | [8]    → max(24, 8)  = 24
      最优是 [7,2,5] | [10,8]，最大段和 18。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5]，k = 2
输出：9
解释：四种切法的最大段和依次为 14、12、9、10，
      [1,2,3] | [4,5] 的 9 最小。
```

**示例 3**

```text
输入：nums = [1,4,4]，k = 3
输出：4
解释：k 等于长度，只能每段一个元素，段和是 1、4、4，最大值为 4。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举切法：在 $n-1$ 个空隙里放 $k-1$ 块隔板，共 $\binom{n-1}{k-1}$ 种，每种花 $O(n)$ 求最大段和。$n=1000$、$k=50$ 时这是天文数字，完全不可行。

退一步，有一个多项式解法是 DP：令 $dp[j][i]$ 表示「把前 $i$ 个元素切成 $j$ 段」的最小最大段和，$pre$ 为前缀和，则

$$dp[j][i]=\min_{j-1\le m<i}\ \max\bigl(dp[j-1][m],\ pre[i]-pre[m]\bigr)$$

状态数 $O(kn)$、转移 $O(n)$，总 $O(k n^2)$，按 $k n^2/2$ 估算约 $2.5\times10^7$ 次「取 $\max$ 再取 $\min$」。C++ 勉强能压过去，Python 基本超时；而且它把答案当成「求出来的值」，没有利用答案自身的结构。

### 3.2 核心观察：二分答案 + 贪心判定

![把最小化最大段和转成可行性判定](images/wc7_q3_answer_bisection.svg)

关键有三点：

1. **答案落在一个有限区间里**。最大元素 $L=\max(\text{nums})$ 所在的那一段，段和至少是 $L$，所以答案 $\ge L$；把所有元素塞进一段只需 1 段（$\le k$），故 $\text{check}(S)$ 恒真，答案 $\le S=\sum\text{nums}$。于是答案在 $[L,S]$ 中，而 $S\le 10^9$。
2. **判定远易于求解**。给定阈值 $x$，问「能否切成 $\le k$ 段、每段和 $\le x$」——从左往右扫一遍就够。
3. **可行性对 $x$ 单调**。若阈值 $x$ 可行，把同一个切法的阈值放宽到任意 $y>x$ 仍然可行；反过来，若 $x$ 不可行，任何更小的 $y$ 也不可能可行。于是存在一个翻转点，它就是**最小的可行值**，正是题目要的答案。

这就是「**二分答案**」：二分的对象不是下标，而是答案的取值。

### 3.3 算法流程：贪心判定 check(x)

![贪心判定 check(x)](images/wc7_q3_greedy_check.svg)

判定只有一句话：**能塞就塞，塞不下才另起一段**。

```text
cnt ← 1，cur ← 0
for v in nums:
    if cur + v > x:        # 当前段装不下 v
        cnt ← cnt + 1      # 另起一段
        cur ← v
    else:
        cur ← cur + v
return cnt ≤ k
```

为什么这样切出的段数最少？因为每一段都「吃到撑」：在「每段和 $\le x$」的约束下，贪心的第一段能覆盖的长度不短于任何合法切法的第一段，之后逐段归纳，贪心永远不落后（严格论证见引理 1）。所以

$$\text{check}(x)\ \text{为真}\iff g(x)\le k$$

其中 $g(x)$ 是满足「每段和 $\le x$」所需的最少段数。又因为 $k\le n$：若贪心只用了 $g(x)<k$ 段，就把任意一段继续拆开凑到恰好 $k$ 段，而拆分只会让段和变小，依旧合法——所以「至多 $k$ 段」与「恰好 $k$ 段」等价。

二分主流程（值域二分）：

```text
lo ← max(nums)，hi ← sum(nums)
while lo < hi:
    mid ← ⌊(lo + hi) / 2⌋
    if check(mid): hi ← mid        # mid 可行，答案不超过 mid
    else:          lo ← mid + 1    # mid 不可行，答案至少 mid + 1
return lo
```

每轮区间至少减半：$[10,32]$ 这 23 个候选值只需 4 轮就收敛（$23\to12\to6\to3\to1$），最坏情况下 $\log_2 10^9\approx 30$ 轮。

### 3.4 示例演算

![示例 1 的二分走查](images/wc7_q3_example_walkthrough.svg)

以 `nums = [7,2,5,10,8]`、$k=2$ 为例，$L=10$、$S=32$：

| 轮 | lo | hi | mid | 贪心切段 | 段数 | check | 更新 |
|----|----|----|-----|----------|------|-------|------|
| 1 | 10 | 32 | 21 | `[7,2,5]` \| `[10,8]` | 2 | ✓ | hi ← 21 |
| 2 | 10 | 21 | 15 | `[7,2,5]` \| `[10]` \| `[8]` | 3 | ✗ | lo ← 16 |
| 3 | 16 | 21 | 18 | `[7,2,5]` \| `[10,8]` | 2 | ✓ | hi ← 18 |
| 4 | 16 | 18 | 17 | `[7,2,5]` \| `[10]` \| `[8]` | 3 | ✗ | lo ← 18 |

第 4 轮之后 $lo=hi=18$，循环结束返回 18。第 2、4 轮不可行的原因相同：$7+2+5=14$ 之后，$10$ 与 $8$ 之和 18 超过阈值，只能各占一段，总共 3 段；而 $x=18$ 恰好能把它们合成 `[10,8]`，段数降到 2。

另外注意 `[7,2,5,10] | [8]` 也是 2 段，但最大段和是 24。**贪心只负责判断「这个 $x$ 能不能用 $\le k$ 段装下」，最小化最大值这件事由二分来完成**——两件事分工明确，不要混为一谈。

## 4. 算法细节

1. **下界必须是 $\max(\text{nums})$，这是正确性要求而非剪枝**。`check` 里没有「单个元素就超过 $x$」的检查：若 $x<\max(\text{nums})$，超限元素会被贪心单独切出来，但这段的和仍 $>x$，而判定只数段数。例如 `nums=[1,100], k=2, x=50`：贪心给出 `[1] | [100]`，`cnt=2 ≤ k` 返回 `true`，可 `[100]` 一段就对不上阈值。取 $lo=\max$ 保证二分中所有 $mid\ge\max$，从根上规避。
2. **二分写法**：`mid = lo + (hi - lo) / 2` 向下取整，配合 `while (lo < hi)`、可行侧 `hi = mid`、不可行侧 `lo = mid + 1`。若可行侧误写成 `lo = mid`，当 `hi - lo == 1` 时 `mid == lo`，会原地死循环。
3. **段数初值为 1**（数组非空），`cur` 存当前段和。`cnt` 只增不减，一旦 `cnt > k` 立即返回 `false`，省掉后半段扫描。
4. **不需要前缀和**：判定只需一次线性扫描，额外空间 $O(1)$。前缀和只在 3.1 的 DP 里才用得上。
5. **溢出**：$S\le 1000\times10^6=10^9$ 在 `int` 范围内（上限约 $2.1\times10^9$），但 `hi`、`cur` 用 `long long` 更稳妥，日后把数据范围改大也不用回头检查。
6. **零元素**：`nums[i] = 0` 时 `cur + 0 <= x` 恒成立，直接并入当前段；非负性与单调性都不受影响。
7. **提前退出的依据**：`cnt > k` 说明「至少需要 $k+1$ 段」，而后面的元素只会让段数更多，所以立刻返回 `false` 是安全的；但不要反过来在 `cnt == k` 时就返回 `true`，剩余元素还没扫。

## 5. 正确性证明

**引理 1（贪心段数最少）**：设 $x\ge\max(\text{nums})$，贪心切出的段数为 $g(x)$，则任何满足「每段和 $\le x$」的切法都至少有 $g(x)$ 段。

**证明**：记贪心各段右端点（不含）为 $p_1<p_2<\cdots<p_g$，任一合法切法的右端点为 $q_1<\cdots<q_m$。对 $t$ 归纳证明 $p_t\ge q_t$：

- $t=1$：贪心第一段是所有满足「前缀和 $\le x$」的最长前缀，而 $[0,q_1)$ 的和 $\le x$，故 $p_1\ge q_1$。
- 设 $p_{t-1}\ge q_{t-1}$。贪心从 $p_{t-1}$ 出发尽量向右延伸；区间 $[p_{t-1},q_t)$ 是合法切法第 $t$ 段 $[q_{t-1},q_t)$ 的子区间，由元素非负，其和不超过后者之和，故也 $\le x$，于是贪心至少能延伸到 $q_t$，即 $p_t\ge q_t$。∎

由 $p_t\ge q_t$ 可知贪心覆盖到数组末尾的时刻不晚于任何合法切法，故 $g(x)\le m$。

**引理 2（可行性单调）**：若 $\text{check}(x)$ 为真，则对任意 $y\ge x$，$\text{check}(y)$ 也为真；等价地，若 $\text{check}(x)$ 为假，则任意 $y\le x$ 都不可行。

**证明**：取 $x$ 可行时的切法，每段和 $\le x\le y$，同一分法对 $y$ 也合法。后一句是其逆否命题。∎

（也可由引理 1 直接得到：约束放宽后贪心能塞进更多元素，$g(y)\le g(x)\le k$。）

**引理 3（与「恰好 $k$ 段」等价）**：$\text{check}(x)$ 为真 $\iff$ 存在把数组切成恰好 $k$ 段、每段和 $\le x$ 的切法。

**证明**：

- ($\Leftarrow$) 恰好 $k$ 段的合法切法也是「至多 $k$ 段」的合法切法，由引理 1 得 $g(x)\le k$，故 $\text{check}(x)$ 为真。
- ($\Rightarrow$) 贪心给出 $g(x)\le k$ 段的合法切法。每段非空且 $k\le n$，故只要段数不足 $k$，就必有一段长度 $\ge 2$，把它拆成两段（两段之和都不超过原段和，因为元素非负），重复 $k-g(x)$ 次即得恰好 $k$ 段且仍合法。∎

**定理**：二分结束时返回的 $lo$ 就是答案，即所有切法中「最大段和」的最小值。

**证明**：维护不变量 $lo\le x^*\le hi$，其中 $x^*$ 为最小的可行阈值（答案）。

- 初始 $lo=\max(\text{nums})\le x^*$：任何切法都包含最大元素，它所在段的和 $\ge\max(\text{nums})$，故更小的阈值都不可行；又 $hi=S$ 是可行值（整段装下只需 1 段），故 $x^*\le S$。
- 每轮取 $mid$：若 $\text{check}(mid)$ 为真，由 $x^*$ 的最小性得 $x^*\le mid$，令 $hi=mid$，不变量保持；若为假，由引理 2 所有 $\le mid$ 的阈值都不可行，故 $x^*>mid$，令 $lo=mid+1$，不变量保持。
- 循环在 $lo=hi$ 时终止，此时 $lo=hi=x^*$。∎

结合引理 3，该阈值在「恰好 $k$ 段」的意义下也最优，与题面要求一致。

## 6. 复杂度分析

- **时间**：$O(n\log S)$，$S=\sum\text{nums}\le 10^9$，故 $\log_2 S\le 30$。每轮 `check` 一次线性扫描 $O(n)$，最坏约 $1000\times30=3\times10^4$ 次加法与比较，C++ 与 Python 都在毫秒级。
- **空间**：$O(1)$ 额外空间，只用 `lo`、`hi`、`cur`、`cnt` 四个变量，不建前缀和数组、不建 DP 表。作为对照，3.1 的 DP 需要 $O(kn^2)$ 时间与 $O(n)$ 空间（滚动掉 $j$ 维后）。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int splitArray(vector<int>& nums, int k) {
        long long lo = 0, hi = 0;
        for (int v : nums) {
            lo = max(lo, (long long)v);   // 下界：最大单元素
            hi += v;                      // 上界：全部装进一段
        }

        auto feasible = [&](long long limit) -> bool {
            int cnt = 1;                  // 至少一段
            long long cur = 0;
            for (int v : nums) {
                if (cur + v > limit) {    // 装不下，另起一段
                    if (++cnt > k) return false;
                    cur = v;
                } else {
                    cur += v;             // 能塞就塞
                }
            }
            return true;
        };

        while (lo < hi) {                 // 值域二分：找最小可行值
            long long mid = lo + (hi - lo) / 2;
            if (feasible(mid)) hi = mid;
            else lo = mid + 1;
        }
        return (int)lo;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def feasible(limit: int) -> bool:
            cnt, cur = 1, 0              # 至少一段
            for v in nums:
                if cur + v > limit:      # 装不下，另起一段
                    cnt += 1
                    if cnt > k:          # 段数只增不减，可提前退出
                        return False
                    cur = v
                else:
                    cur += v             # 能塞就塞
            return True

        lo, hi = max(nums), sum(nums)    # 下界：最大单元素；上界：一段装完
        while lo < hi:
            mid = (lo + hi) // 2
            if feasible(mid):
                hi = mid                 # mid 可行，答案不超过 mid
            else:
                lo = mid + 1             # mid 不可行，答案至少 mid+1
        return lo
```

## 8. 边界情况与易错点

1. **$k=1$** 时答案是 $\sum\text{nums}$，**$k=n$** 时答案是 $\max(\text{nums})$。二分本身不需要特判，但前提是 $lo$ 取 $\max$；把 $lo$ 写成 0 时 $k=n$ 会算错。
2. **下界取 0 的误判**（见 4.1）：`nums=[1,100], k=2`，若从 $lo=0$ 起二分，`check(50)` 会返回真（做成 `[1] | [100]` 两段），最终答案偏小。下界取 $\max$ 才能同时保证「$\ge$ 答案」和「判定有效」。
3. **二分方向写反**：本题求「最小的可行值」，可行时应收缩上界（`hi = mid`）；写成 `lo = mid` 既死循环又可能停在最大不可行值上。
4. **全零数组**：`nums=[0,0,0], k=2` 时 $lo=hi=0$，循环一次都不进，直接返回 0；`while (lo < hi)` 不会死循环，而 `while (lo <= hi)` 配合 `lo = mid + 1` 则需要额外的答案变量。
5. **`cnt` 初值必须为 1**：数组非空（$n\ge1$），不存在「零段」。若写成 0，恰好用满 $k$ 段的切法会被误判为 $k-1$ 段，答案偏小。
6. **不要在 `cnt == k` 时提前返回真**：剩余元素尚未扫描，后面每遇到一处超限都意味着需要第 $k+1$ 段，答案应当为假。
7. **求和范围**：$n=1000$、$\text{nums}[i]=10^6$ 时 $S=10^9$ 仍在 `int` 内，但如果题目范围放宽到 $10^{10}$ 级别，`int` 会溢出，统一用 `long long` 可以免去复查。

**延伸思考**：

- 如果 `nums` 允许**负数**：可行性对 $x$ 的单调性仍然成立（放宽阈值永远不劣），但**贪心失效**——多塞一个负数可能让段和变小，段数最少的切法不再是「能吃就吃」，只能退回 $O(kn^2)$ 的 DP。这正是本题把「非负」写进约束的原因。
- 如果要求「段和互不相同」「最大段和最小且段数最少」这类双目标，贪心判定不再充分，需要在 DP 里多加一维状态来记录附加约束。
- 若 $n$ 大到 $10^6$，$O(n\log S)$ 依然可行，而 $O(kn^2)$ 完全不可行——这正是二分答案相对 DP 的价值：把「多阶段决策」换成「一轮判定 + 值域搜索」。
