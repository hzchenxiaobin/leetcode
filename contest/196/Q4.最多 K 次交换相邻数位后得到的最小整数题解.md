# LeetCode 最多 K 次交换相邻数位后得到的最小整数 题解

## 1. 题目概述

- **标题 / 题号**：最多 K 次交换相邻数位后得到的最小整数（#1505，hard）
- **链接**：https://leetcode.cn/problems/minimum-possible-integer-after-at-most-k-adjacent-swaps-on-digits/
- **来源**：LeetCode 第 196 场周赛 Q4
- **难度**：困难
- **标签**：贪心、树状数组、字符串、逆序对

**题意**：给定表示大整数的字符串 `num` 和整数 $k$。每次可以交换**相邻两个数位**上的数字，最多执行 $k$ 次。返回能得到的**最小**整数（以字符串返回，**输出允许前导 0**，输入保证无前导 0）。

**约束**：

- $1 \le \text{num.length} \le 3 \times 10^4$
- `num` 只包含数字且不含前导 0
- $1 \le k \le 10^9$

> 💡 注意规模的错位：$n \le 3\times10^4$ 而 $k \le 10^9$——最大可能的逆序对数不过 $\binom{n}{2} \approx 4.5 \times 10^8$，$k$ 可能大到足以**完全排序**（示例 3）。所以瓶颈根本不在「模拟多少次交换」，而在于**不能一步步模拟**，必须直接**计算**把某个数字提前的代价，并快速判断「预算内能负担的最小数字」是谁。

## 2. 示例

**示例 1**

```text
输入：num = "4321", k = 4
输出："1342"

解释：4321 → 4312 → 4132 → 1432 → 1342，共 4 次相邻交换得到最小整数。
完全排序成 "1234" 需要 6 次交换（4321 的逆序对总数），"1243" 也需要 5 次，
预算 k = 4 都不够，"1342"（4 次）才是能负担的最小整数。
```

**示例 2**

```text
输入：num = "100", k = 1
输出："010"

解释：把下标 1 的 '0' 交换到首位即可。输出可以包含前导 0，无需特殊处理。
```

**示例 3**

```text
输入：num = "36789", k = 1000
输出："36789"

解释：已经升序，无需任何交换；k 再大也不会被「强行用掉」。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**逐步模拟**：每轮扫描当前串，找到一处能让字典序变小的相邻对交换之，重复至多 $k$ 轮。时间 $O(nk)$，$n = 3\times10^4$、$k = 10^9$ 时约 $3 \times 10^{13}$ 次操作，彻底不可行。

退一步的「正确但太慢」做法：逐位贪心——确定第 $t$ 位时，向右扫一段窗口找预算内能提取的最小数字，然后**真实搬移**数组元素模拟提取，再进入下一位。单次提取 $O(\text{窗口长})$，总计 $O(n \cdot \min(n, k)) \approx 9 \times 10^8$，仍然超时，而且朴素代价计算本身就是错的（见 3.2 的反例）。

**两个必须砍掉的开销**：

1. **不能执行交换，只能计算代价**——把某个数字提前的交换次数可以 $O(\log n)$ 算出，无需搬移。
2. **候选数字只有 10 种**——按数字值分桶维护出现位置，第 $t$ 位的候选只需检查 $\le 10$ 个「队首」。

### 3.2 核心观察：逐位提取，代价 = 前方剩余数字个数

![逐位提取模型](images/1505_greedy_extract_concept.svg)

**模型转换**：把「最终排列」看作逐位**提取**——每一步从**剩余序列**（原串删去已选位置、保持原相对顺序）中挑一个数字接到结果末尾。挑选的物理实现就是连续的相邻交换：要提取的数字每越过**一个**挡在它前面的剩余数字，恰好消耗**一次**相邻交换，且不改变其余元素的相对顺序。

于是第 $t$ 位的问题变成：**在剩余序列中，哪个数字是「预算能负担」的最小数字？**

贪心策略：从小到大枚举数字 $d \in [0,9]$，取 $d$ 的**最左未删除位置** $j$，若提取代价 $\text{cost}(j) \le k$ 就选它。

**代价公式**：设 $D$ 为已删除（已提取）位置集合，则

$$\text{cost}(j) = j - \text{del\_lt}(j), \qquad \text{del\_lt}(j) = \lvert\{\, d \in D : d < j \,\}\rvert$$

即 $j$ 前方**尚未被取走**的数字个数。妙处在于：**公式里根本没有步数 $t$**——已删除位置无论在 $j$ 左边还是右边，都只影响 $j$ 的「当前坐标」，而提取只与「前方剩余」有关。

> ⚠️ **为什么朴素「$j - t$」是错的？** $t = \text{del\_lt}(j) + \text{del\_ge}(j)$（左侧幽灵 + 右侧幽灵），用 $j - t$ 等于让**右侧的幽灵**错误地抵扣了**前方真实挡路者**，代价被**低估**，贪心会「以为能负担」，最终输出一个实际需要超过 $k$ 次交换、根本不可达的串。

![代价公式与幽灵位置修正](images/1505_bit_cost_correction.svg)

反例（图中 Panel B）：`num = "921", k = 2`。选走 '1'（位置 2，cost 2）后，'2' 在原下标 1、前方真实的 '9' 还在挡路，正确代价是 $\text{cost}(1) = 1 - \text{del\_lt}(1) = 1 - 0 = 1 > k_{\text{剩}} = 0$，必须拒选；朴素公式却给出 $1 - 1 = 0$ 误判可负担，拼出 "129"——实际需要 3 次交换，不可达。正确答案是 "192"（恰好 2 次）。

而 $\text{del\_lt}(j)$ 是「单点标记 + 前缀和查询」，正是**树状数组（BIT）**的标准场景：初始全 0，选中 $j$ 后在 BIT 位置 $j+1$ 加 1，查询 $\text{query}(j)$ 即原下标 $[0, j-1]$ 内的已删除个数，$O(\log n)$。

### 3.3 算法流程

![算法流程图](images/1505_greedy_bit_flow.svg)

```text
1. 预处理：pos[0..9] ← 各数字出现的原下标（升序队列）；BIT 置 0
2. for t = 0 .. n-1:                    # 逐位确定结果
       for d = 0 .. 9:                  # 从小到大枚举数字
           若 pos[d] 空：跳过
           j   = pos[d] 队首            # 同数字最左未删位置
           cost = j - BIT.query(j)      # 前方剩余数字个数
           若 cost <= k:
               ans += d；k -= cost
               BIT.add(j+1, 1)          # 标记 j 已删除
               pos[d] 出队；break        # 本位敲定
3. 返回 ans
```

两个内建的正确性保障：

- **兜底不卡死**：剩余序列的首元素是某个 $d$ 的队首且前方剩余为 0（cost = 0 恒可负担），所以内层枚举必有命中。
- **队首最优**：同一数字的多个位置中，$j$ 越小 $\text{cost}(j)$ 越小（$\text{cost}$ 关于 $j$ 单调不减），且删除更靠左的 $j$ 会让**后续**更大 $j'$ 的 $\text{del\_lt}$ 计数更多、代价更小——当前最省、后续受益，双重最优。

### 3.4 示例演算

![示例演算 4321](images/1505_walkthrough_4321.svg)

以 `num = "4321", k = 4` 完整走查（逐步解读见插图）：

| $t$ | 尝试的候选（$d$: $j$, cost） | 选中 | $k$ 剩余 | 已删 $D$ | 结果 |
|---|---|---|---|---|---|
| 0 | $d{=}1$: $j{=}3$, cost $= 3 \le 4$ ✓ | '1' | 4 → 1 | $\{3\}$ | "1" |
| 1 | $d{=}2$: $j{=}2$, cost $= 2 > 1$ ✗ → $d{=}3$: $j{=}1$, cost $= 1$ ✓ | '3' | 1 → 0 | $\{3,1\}$ | "13" |
| 2 | $d{=}2$: $j{=}2$, cost $= 2{-}1 = 1 > 0$ ✗ → $d{=}4$: $j{=}0$, cost $= 0$ ✓ | '4' | 0 | $\{3,1,0\}$ | "134" |
| 3 | $d{=}2$: $j{=}2$, cost $= 2{-}2 = 0$ ✓ | '2' | 0 | $\{3,1,0,2\}$ | "1342" |

- **$t = 1$ 是胜负手**：'2' 的 cost 是 2 而预算只剩 1，拒选——这正是 "1243"（需 5 次交换）不可达的瞬间，贪心退而选 '3'。
- **$t = 3$ 见证幽灵修正**：'2' 名义在原下标 2，但前方 $\{0,1\}$ 全是已删幽灵，cost $= 2 - 2 = 0$。
- 总代价 $3+1+0+0 = 4 = k$ ✓，输出 "1342"。

## 4. 算法细节

1. **位置桶 + 队首游标**：`pos[d]` 存数字 $d$ 的全部原下标（升序），配一个头指针 `head[d]`（或直接用队列）。选中即 `head[d]++`，天然保证队首永远是「该数字最左的未删除位置」，无需真删除。
2. **BIT 的 1-based 偏移**：原下标 $j$（0-based）对应 BIT 位置 $j+1$。$\text{del\_lt}(j) = \text{query}(j)$（BIT 位置 $1..j$ = 原下标 $0..j-1$，恰好是「严格小于 $j$」）；删除标记是 `add(j+1, 1)`。**偏移搞反是本题最常见的 bug**。
3. **cost 与 $t$ 无关**：公式里只有 $j$ 和删除集合，实现时不需要维护「当前结果长度」参与代价计算；$t$ 只控制循环次数。
4. **同数字必取队首**：$\text{cost}(j) = j - \text{del\_lt}(j)$ 关于 $j$ 单调不减（$j$ 每加 1，$\text{del\_lt}$ 至多加 1），队首代价最小；且删除队首（更靠左的位置）对后续候选的 $\text{del\_lt}$ 补益最大。
5. **预算不会透支**：只有 `cost <= k` 才扣减，$k$ 始终非负；输出串的总交换次数恰为累计扣减额，必然 $\le k$，可达性免费保证。
6. **`k` 的类型**：$k \le 10^9$ 在 `int` 范围内；cost $\le n \le 3\times10^4$，无溢出风险（Python 天然无虞，C++ 亦无需 `long long`）。

## 5. 正确性证明

**引理 1（提取代价）**：设剩余序列 $R$（保持原相对顺序），将 $R$ 中下标 $p$ 的元素移到 $R$ 开头，恰好需要 $p$ 次相邻交换，且 $R$ 中其余元素相对顺序不变。

**证明**：相邻交换每次让该元素位置减 1，从 $p$ 到 $0$ 恰需 $p$ 次；每一步只与紧邻的前一个元素互换，其余元素间的相对顺序保持不变。∎

**引理 2（代价公式）**：设已删除位置集 $D$，候选位置 $j \notin D$，则其在剩余序列中的下标为 $j - \text{del\_lt}(j)$，提取代价 $\text{cost}(j) = j - \text{del\_lt}(j)$，与步数 $t$ 无关。

**证明**：剩余序列 = 原序列删去 $D$ 中位置后按原序拼接。$j$ 前面的剩余元素恰为原下标 $< j$ 且 $\notin D$ 的位置，共 $j - \text{del\_lt}(j)$ 个，此即其剩余序列下标，由引理 1 即得。$t$ 未出现在式中。∎

**引理 3（总代价 = 最小交换次数）**：对 `num` 的任意目标排列 $T$，逐位提取构造 $T$ 的总代价 $C(T) = \sum_t \text{cost}_t$ 恰等于把 `num` 变成 $T$ 的**最小**相邻交换次数，且 $C(T)$ 等于二者之间的逆序对数。

**证明**：分三步。

- *（$C(T)$ = 逆序对数）* 把 `num` 每个元素映射为它在 $T$ 中的位置得序列 $\pi$。由引理 2，$\text{cost}_t$ 数的是「原下标小于 $j_{T[t]}$、且尚未被提取（即排在 $T$ 中更后）」的元素个数。对 $t$ 求和，恰好每个「原下标小却排位靠后」的点对被计数一次，故 $C(T) = \text{inv}(\pi)$。
- *（上界）* 逐位提取是一段合法的相邻交换序列，总长 $C(T)$，故最小交换次数 $\le C(T)$。
- *（下界）* 任何相邻交换只改变相邻两元素的相对顺序，$\text{inv}(\pi)$ 每次至多变化 1；结束时 $\text{inv} = 0$，故交换次数 $\ge \text{inv}(\pi) = C(T)$。∎

**引理 4（前缀可行性刻画）**：设前缀 $P = T[0..t-1]$，$C(P)$ 为逐位提取 $P$ 的代价（由 $P$ 唯一决定）。则：**存在以 $P$ 为前缀的、$\le k$ 次交换可达的排列 $\iff C(P) \le k$**。

**证明**：（⇐）把剩余序列按原相对顺序直接续接在 $P$ 之后——后续每步提取的都是剩余序列首元素，cost 全为 0，总代价 $= C(P) \le k$，可达。（⇒）设 $T$ 以 $P$ 为前缀且最小交换次数 $\le k$，由引理 3 得 $C(T) \le k$；又 $C(T) = C(P) + (\text{后续各项代价})$，各项非负，故 $C(P) \le k$。∎

**定理（贪心正确性）**：算法输出的是所有 $\le k$ 次交换可达的排列中**字典序最小**者。

**证明**：对 $t$ 归纳：贪心产生的前缀 $P_t$ 可行（$C(P_t) \le k$），且是所有可行排列的字典序最小前缀。

- *归纳基础* $t = 0$：空前缀平凡可行。
- *归纳步*：设 $P_{t-1}$ 成立，其删除集 $D$ 与剩余预算 $k' = k - C(P_{t-1}) \ge 0$ 随之确定。任何以 $P_{t-1}$ 为前缀的可行排列，其第 $t$ 位数字 $d'$（取其某个未删位置 $j'$）由引理 4 必须满足 $C(P_{t-1}) + \text{cost}(j') \le k$，即 $\text{cost}(j') \le k'$——注意 $D$ 相同，故 cost 公式与贪心所用**完全一致**；同一数字取队首时 cost 最小（引理 2 的单调性）。贪心选取的 $g$ 是**最小的**满足 $\text{cost} \le k'$ 的数字，且 $C(P_t) = C(P_{t-1}) + \text{cost}(g) \le k$ 使 $P_t$ 可行。于是任何字典序更小的第 $t$ 位选择（$< g$ 的数字）其前缀不可行，由引理 4 不存在以其为前缀的可行排列。∎

**推论（可达性）**：算法输出串的实际最小交换次数 $= \sum$ 各步扣减的 cost $\le k$，输出必然合法。∎

## 6. 复杂度分析

- **时间复杂度**：$O(10 \cdot n \log n)$
  - 外层 $n$ 位，每位置多枚举 10 个数字候选；
  - 每个候选一次 BIT 前缀和查询 $O(\log n)$，命中时额外一次 BIT 更新 $O(\log n)$；
  - $n = 3\times10^4$ 时约 $10 \times 3\times10^4 \times 15 \approx 4.5\times10^6$ 次基本操作，轻松通过。$k$ 只参与比较，不影响复杂度。
- **空间复杂度**：$O(n)$
  - BIT 数组 $n+1$；`pos` 桶合计存储 $n$ 个下标；结果串 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string minInteger(string num, int k) {
        int n = num.size();
        vector<int> tree(n + 1, 0);            // BIT：删除标记，1-based
        auto add = [&](int i) {
            for (; i <= n; i += i & -i) tree[i]++;
        };
        auto query = [&](int i) {              // 原下标 [0, i-1] 内已删除个数
            int s = 0;
            for (; i > 0; i -= i & -i) s += tree[i];
            return s;
        };

        vector<vector<int>> pos(10);            // 各数字的原下标（升序）
        for (int i = 0; i < n; ++i) pos[num[i] - '0'].push_back(i);
        int head[10] = {0};

        string ans;
        ans.reserve(n);
        for (int t = 0; t < n; ++t) {
            for (int d = 0; d <= 9; ++d) {
                if (head[d] >= (int)pos[d].size()) continue;
                int j = pos[d][head[d]];
                int cost = j - query(j);        // cost = j - del_lt(j)，与 t 无关
                if (cost <= k) {
                    k -= cost;
                    add(j + 1);                 // 标记原下标 j 已删除
                    ++head[d];
                    ans.push_back('0' + d);
                    break;
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minInteger(self, num: str, k: int) -> str:
        n = len(num)
        tree = [0] * (n + 1)                    # BIT：删除标记，1-based

        def add(i: int) -> None:
            while i <= n:
                tree[i] += 1
                i += i & -i

        def query(i: int) -> int:               # 原下标 [0, i-1] 内已删除个数
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & -i
            return s

        pos = [[] for _ in range(10)]           # 各数字的原下标（升序）
        for i, ch in enumerate(num):
            pos[ord(ch) - 48].append(i)
        head = [0] * 10

        ans = []
        for _ in range(n):
            for d in range(10):
                if head[d] >= len(pos[d]):
                    continue
                j = pos[d][head[d]]
                cost = j - query(j)             # cost = j - del_lt(j)，与 t 无关
                if cost <= k:
                    k -= cost
                    add(j + 1)                  # 标记原下标 j 已删除
                    head[d] += 1
                    ans.append(chr(48 + d))
                    break
        return ''.join(ans)
```

## 8. 边界情况与易错点

1. **朴素「$j - t$」是致命 bug**：右侧幽灵不能抵扣前方挡路者，代价被低估会输出**不可达**的串（反例 `"921", k = 2` → 错输出 "129"，正确 "192"）。必须用 BIT 查 $\text{del\_lt}(j)$ 修正。
2. **BIT 偏移**：查询用 `query(j)`（原下标 $< j$），更新用 `add(j + 1)`。两者搞混（比如 `query(j+1)` 把 $j$ 自身也算进挡路者）会系统性高估代价、输出次优。
3. **同数字必须取队首**：跳过队首选更靠后的同数字，当前多花代价，后续也少一份 $\text{del\_lt}$ 补益，双重劣化。
4. **前导零**：输出允许（示例 2 的 "010"），不要画蛇添足地去掉。
5. **$k$ 巨大**：无需特判——预算充足时贪心自然每次都取全场最小，等价于稳定排序（示例 3 直接原样返回）。
6. **$n = 1$**：单字符，枚举首个候选 cost = 0，原样返回。
7. **不卡死**：不要给内层枚举加「全军覆没就 break」的假设——剩余序列首元素 cost = 0 必命中，`if cost <= k` 分支必然触发（写成防御性 break 反而掩盖逻辑错误）。
8. **Python 性能**：用 `list + 头指针` 或 `deque` 消费桶、`ans` 列表 + `join` 拼接，避免 $O(n^2)$ 的字符串累加。

**延伸思考**：

- 若允许交换**任意**两位（而非相邻）：每步代价变为常数 1，贪心仍成立但退化成「k 次内逐步选择排序」，$k \ge n-1$ 时即可完全排序——对比凸显「相邻交换的代价 = 逆序」这一本质。
- 若 $k < 10$：只有前 $k+1$ 位可能被改变，窗口极小，甚至可以直接暴力；这也解释了为什么本题必须用「代价计算」而非「逐步模拟」才能吃下 $k = 10^9$。
- 更深一层的沉淀：**「逐位提取 + 代价前缀和维护」是相邻交换类问题的通用框架**——把「能动性预算」转化为每一步的精确代价，再配上字典序贪心，正确性由「前缀可行性刻画」（引理 4）一锤定音。
