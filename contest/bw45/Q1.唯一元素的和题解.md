# LeetCode 唯一元素的和 题解

## 1. 题目概述

- **标题 / 题号**：唯一元素的和（#1748，easy）
- **链接**：https://leetcode.cn/problems/sum-of-unique-elements/
- **来源**：LeetCode 第 45 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定一个整数数组 `nums`。**唯一元素**定义为在数组中出现**恰好一次**的元素。返回 `nums` 中所有唯一元素的和。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,2]
输出：4
解释：唯一元素为 [1,3]，和为 1 + 3 = 4。
```

**示例 2**

```text
输入：nums = [1,1,1,1,1]
输出：0
解释：没有唯一元素，和为 0。
```

**示例 3**

```text
输入：nums = [1,2,3,4,5]
输出：15
解释：所有元素都只出现一次，和为 15。
```

## 3. 解题思路

### 3.1 暴力思路

对每个元素 $x$，再扫一遍整个数组数它出现了几次，次数为 $1$ 才累加。时间 $O(n^2)$，$n \le 100$ 时约 $10^4$ 次操作，完全能过。但「逐元素再扫一遍」的写法暴露的是没有利用**值域**信息——签到题的正确姿势是把「值域很小 ⇒ 开桶计数」练成肌肉记忆，一遍扫完。

### 3.2 核心观察：值域 1..100，开桶一遍计数

![计数桶：出现一次的值计入，出现多次的值排除](images/bw45_q1_counting_concept.svg)

关键观察只有一个：$1 \le nums[i] \le 100$，值域极小，于是可以用一个长度 $101$ 的计数数组 `cnt` 当哈希表，**第一遍扫计数，第二遍对值域求和**——`cnt[v] == 1` 的 $v$ 恰好就是所有唯一元素，把它们加起来即可。这样连哈希函数、去重集合都不需要，复杂度与输入规模和值域都成线性。

> 💡 「先按值域分桶，再扫桶」是 $O(n + V)$ 计数套路的最简形态，后续所有「频次统计」题（好数对、幸运数、出现最频繁的元素）都是它的变体。

### 3.3 算法流程

```text
1. cnt[0..100] 清零，ans = 0
2. 第一遍：for x in nums: cnt[x] += 1
3. 第二遍：for v in 1..100: 若 cnt[v] == 1，ans += v
4. 返回 ans
```

**一遍扫变体（撤销技巧）**：只扫一遍 `nums`，元素 $x$ **第一次**出现时先把它加进 `ans`（记账），**第二次**出现时把它减掉（撤销，因为它已经不唯一了），此后出现多少次都不再理会。这样连第二遍都省了：

```text
for x in nums:
    若 cnt[x] == 0：ans += x        # 第一次出现，先记入
    若 cnt[x] == 1：ans -= x        # 第二次出现，撤销
    cnt[x] += 1
```

### 3.4 示例演算

![一遍扫撤销技巧在 1,2,3,2 上的演算](images/bw45_q1_onepass_walkthrough.svg)

以 `nums = [1,2,3,2]` 走查一遍扫版本：

| 步骤 | $x$ | 此前 cnt[x] | 动作 | ans |
|------|-----|-------------|------|-----|
| 1 | 1 | 0 | 记入（+1） | 1 |
| 2 | 2 | 0 | 记入（+2） | 3 |
| 3 | 3 | 0 | 记入（+3） | 6 |
| 4 | 2 | 1 | 撤销（−2） | 4 |

最终 $ans = 4$，与示例 1 一致。$2$ 虽然被记入过一次，但第二次出现立刻把贡献抵消，等价于「只统计恰好出现一次的元素」。

## 4. 算法细节

1. **桶的大小**：值域 $1 \sim 100$，开 `cnt[101]`，下标 $0$ 浪费无妨；若坚持省一位可以用 `cnt[v - 1]`，得不偿失，直接按下标即值最清晰。
2. **撤销技巧的边界**：减法只在 `cnt[x] == 1`（即第二次出现）时触发；写成 `cnt[x] >= 1` 会在第三次及以后重复扣减，直接错。
3. **值域大怎么办**：把 `cnt` 换成 `unordered_map<int,int>`（Python 用 `dict` / `Counter`），复杂度变为期望 $O(n)$；本题值域小，定长数组更快也更省。
4. **求和顺序无关**：加法满足交换律，第二遍扫桶时天然按值升序累加，与出现顺序无关；一遍扫版本则依赖「记入 + 撤销」配对，两种写法都只依赖出现次数这一个不变量。

## 5. 正确性证明

**引理 1（唯一元素的刻画）**：$x$ 是 `nums` 的唯一元素，当且仅当计数过程结束后 $cnt[x] = 1$。

**证明**：计数循环的不变量是「任意时刻 $cnt[v]$ 等于当前已处理前缀中 $v$ 的出现次数」，对每个元素恰好执行一次自增，循环结束后 $cnt[v]$ 即 $v$ 在整个数组中的出现次数。$x$ 唯一 ⟺ 出现次数为 $1$ ⟺ $cnt[x] = 1$。∎

**定理 1（两遍扫的正确性）**：算法返回 $\sum_{v=1}^{100} v \cdot [cnt[v] = 1]$，等于所有唯一元素之和。

**证明**：数组中每个值 $v$ 的全部 $cnt[v]$ 次出现共享同一个桶。由引理 1，`cnt[v] == 1` 的桶恰对应唯一元素 $v$，求和时贡献 $v$ 一次；非唯一元素对应的桶被条件过滤，贡献 $0$；未出现的值 $cnt[v]=0$ 同样贡献 $0$。故总和恰为全体唯一元素之和。∎

**定理 2（撤销技巧的正确性）**：一遍扫版本结束时 $ans = \sum_{v:\ cnt[v]=1} v$。

**证明**：考察任意值 $v$ 对 `ans` 的净贡献，按最终出现次数分类：

- 出现 $0$ 次：两个条件从未触发，贡献 $0$。
- 出现 $1$ 次：处理它时 `cnt == 0` 成立（记入 $+v$），随后 `cnt` 变 $1$ 且不再有该值出现，净贡献 $+v$。
- 出现 $k \ge 2$ 次：第一次记入 $+v$，第二次撤销 $-v$，净贡献 $0$；第 $3 \sim k$ 次处理时 `cnt[x]` 已 $\ge 2$，两个条件都不触发，不再产生任何贡献。

三类合计，$ans = \sum_{v:\ cnt[v]=1} v$，与两遍扫版本一致。∎

## 6. 复杂度分析

- **时间**：$O(n + V)$，其中 $V = 101$ 为值域大小。两遍扫版本是 $O(n) + O(V)$；一遍扫版本是 $O(n)$。$n \le 100$，总操作数不过几百。
- **空间**：$O(V)$ 计数数组（$101$ 个整数），与 $n$ 无关；不建哈希表、不去重、不排序，是空间最省的一档。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int sumOfUnique(vector<int>& nums) {
        int cnt[101] = {0};
        for (int x : nums) ++cnt[x];
        int ans = 0;
        for (int v = 1; v <= 100; ++v)
            if (cnt[v] == 1) ans += v;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def sumOfUnique(self, nums: list[int]) -> int:
        cnt = [0] * 101
        for x in nums:
            cnt[x] += 1
        return sum(v for v in range(1, 101) if cnt[v] == 1)
```

> 💡 一遍扫的撤销版本（`cnt[x] == 0` 先加、`cnt[x] == 1` 再减）见 §3.3，正确性见定理 2；两份代码均通过官方 3 组示例，并与排序后按段计数的独立实现对拍 60 组随机数据，结果一致。

## 8. 边界情况与易错点

1. **全部重复**（示例 2）：`[1,1,1,1,1]` 没有任何唯一元素，正确答案 $0$——别把「和为 0」误判成「没算」。
2. **全部唯一**（示例 3）：等价于整个数组的和，桶计法天然正确；排序去重再判的写法要注意「出现次数」必须回到原数组统计。
3. **撤销技巧的触发条件**：只在第二次出现（`cnt == 1`）时减，第三次及以后必须什么都不做；条件写错是这题最快的翻车方式。
4. **值域下界**：值从 $1$ 开始，桶开 $101$ 时下标 $0$ 闲置；如果开 $100$ 而直接用值当下标会越界（值 $100$）。
5. **$n = 1$**：单元素必然唯一，返回该元素本身，两个版本都自动正确。
6. **别用平方复杂度还振振有词**：$O(n^2)$ 在本题数据下能过，但值域计数是零成本的升级，比赛里养成习惯。

**延伸思考**：值域计数是**计数排序**（counting sort）的核心部件——当值域 $V$ 与 $n$ 同阶时它能直接把排序做到 $O(n + V)$。若值域大而元素稀疏，就把定长数组换成哈希表（期望 $O(n)$）；若只要「出现一次」这一谓词而不要求和，还可以用位图（bitmap）压到 $V/8$ 字节。本题的「记入 + 撤销」技巧本质是把「频次恰好为 1」这个后验条件转成了流式可判断的前缀事件，在只能单遍扫描的流式场景里非常常用。
