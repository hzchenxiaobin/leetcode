# LeetCode 执行操作后的最大 MEX 题解

## 1. 题目概述

- **标题 / 题号**：执行操作后的最大 MEX（#2598，medium）
- **链接**：https://leetcode.cn/problems/smallest-missing-non-negative-integer-after-operations/
- **来源**：LeetCode 第 337 场周赛 Q4
- **难度**：中等
- **标签**：贪心、数组、哈希表、数学

**题意**：给定整数数组 `nums` 与整数 `value`。一步操作可对**任一**元素加上或减去 `value`，操作可执行**任意多次**（同一元素可反复加减，也可不动）。数组的 **MEX** 是其中缺失的最小非负整数（如 `[-1,2,3]` 的 MEX 是 0，`[1,0,3]` 的 MEX 是 2）。返回执行任意次操作后 `nums` 能达到的**最大 MEX**。

**约束**：

- $1 \le \text{nums.length},\ \text{value} \le 10^5$
- $-10^9 \le \text{nums[i]} \le 10^9$

> 💡 **两个信号**：① 「加减 `value` 任意多次」= 给元素加上 `value` 的任意整数倍——每个元素的可达集合是一条**同余等差数列**，$10^5$ 个元素可以压缩成按 $x \bmod \text{value}$ 的 `value` 个桶；② MEX 只由 $0..k-1$ 是否**全部出现**决定，是典型的「前缀覆盖」型目标——从小到大逐靶贪心，卡在哪里答案就是哪里。

## 2. 示例

**示例 1**

```text
输入：nums = [1,-10,7,13,6,8], value = 5
输出：4
解释：-10 + 2×5 = 0；7 − 1×5 = 2；13 − 2×5 = 3；1、6、8 原地不动
      得到 [1,0,2,3,6,8]，MEX = 4。
```

**示例 2**

```text
输入：nums = [1,-10,7,13,6,8], value = 7
输出：2
解释：7 − 1×7 = 0，得到 [1,-10,0,13,6,8]，MEX = 2。
      想凑 2 需要余 2 的元素，而 1≡1、-10≡4、7≡0、13≡6、6≡6、8≡1，余 2 的桶是空的。
```

**示例 3**（自造，覆盖「同类元素错开占用 r 与 r+value」的关键情况）

```text
输入：nums = [0,5,1,2,3,4], value = 5
输出：6
解释：0 与 5 同余（余 0），让 0 原地担任靶点 0、5 原地担任靶点 5；
      1,2,3,4 各自原地，于是 0..5 全覆盖。
      若把每个元素缩成最小非负余数得 [0,0,1,2,3,4]，MEX 只有 5——这是错误做法（§8）。
```

## 3. 解题思路

### 3.1 暴力思路：逐靶扫描 + 线性配对

要让 MEX 尽量大，直觉是依次凑出 $0,1,2,\dots$：对每个靶点 $t$ 从 $0$ 起递增，在**尚未使用**的元素里找一个能变成 $t$ 的元素并占用之；找不到则返回 $t$。单次匹配需 $O(n)$ 线性扫描，答案至多 $n$，总计 $O(n^2) \approx 10^{10}$，$n = 10^5$ 下不可行。

暴力虽超时，却暴露了本题最关键的事实：**元素 $x$ 能否变成 $t$，只取决于 $x \bmod \text{value}$ 是否等于 $t \bmod \text{value}$**，与 $x$ 的具体数值、正负都无关。既然匹配条件只看余数，就该把逐元素匹配压缩为**按余数分桶计数**，查询降为 $O(1)$。

### 3.2 核心观察：余数不变量 + 同余分桶

![核心观察：加减 value 不改变余数，元素只能在同余类内移动](images/wc337_q4_residue_invariant.svg)

**观察一（不变量）**：每次操作 $\pm\,\text{value}$ 不改变 $x \bmod \text{value}$；反之，与 $x$ 同余的任何数都可达（加/减足够多次）。于是余数为 $r$ 的元素可以变成**任何**非负的、$\equiv r \pmod{\text{value}}$ 的数，即可担任靶点 $r,\ r+\text{value},\ r+2\,\text{value},\ \dots$ 中的任意一个（§5 引理 1）。

**观察二（分桶）**：数组里每个元素的「能力」完全由其余数决定。设 $\text{cnt}[r]$ 为余数为 $r$ 的元素个数（$0 \le r < \text{value}$），整个问题被压缩为一个长度为 `value` 的计数向量。

**观察三（同类错开）**：桶内元素**不可分辨，但每个只能用一次**。$\text{cnt}[r] = c$ 的桶恰好能把类内靶点 $r,\ r+v,\ \dots,\ r+(c-1)v$ **全部**占据、再多一个也不行——这与示例 3 中两个余 0 元素错开担任 $0$ 和 $5$ 一致，也是「缩余数」错法的病灶所在。

### 3.3 算法流程：贪心消耗扫描 / 闭式取 min

![算法流程：从 x=0 起贪心扫描，余类耗尽即停](images/wc337_q4_greedy_scan_flow.svg)

赛场写法（贪心扫描）：

```text
cnt[0..value−1] ← 统计每个元素的余数
x ← 0
循环：r = x mod value
      若 cnt[r] > 0：cnt[r] −= 1（安排一个类 r 元素变成 x），x += 1，继续
      否则：停止，答案 = x
```

每成功一步就消耗一个元素，故循环至多 $n+1$ 步、答案 $\le n$（§5 引理 5），扫描版总复杂度 $O(n + \text{value})$。

赛后复盘可得**一步到位的闭式**：类 $r$ 恰能占据前 $\text{cnt}[r]$ 个类内靶点，第 $\text{cnt}[r]+1$ 个类内靶点（即 $r + \text{cnt}[r]\cdot\text{value}$）起无从补起。取所有类中**最早失守**的靶点即答案：

$$\text{ans} \;=\; \min_{0 \,\le\, r\, <\, \text{value}} \bigl(\, r + \text{cnt}[r]\cdot\text{value} \,\bigr)$$

> 💡 **与每日题解的网格视角等价**。`solution/2501-2600/2598_执行操作后的最大MEX.md` 把靶点排成「行 = 层 $j$、列 = 余数 $r$」的网格，读出 $\text{ans} = j^*\cdot v + \min\{r : \text{cnt}[r] = j^*\}$（$j^* = \min_r \text{cnt}[r]$：最矮柱决定断层层号，最左断柱决定列号）。两个闭式恒相等：记 $r^*$ 为最左断柱，则 $r^* + j^* v$ 显然是一个候选；对任何 $r \ge r^*$ 有 $r + \text{cnt}[r]v \ge r^* + j^* v$；对任何 $r < r^*$ 必有 $\text{cnt}[r] \ge j^*+1$，于是 $r + \text{cnt}[r]v \ge r + (j^*{+}1)v > r^* + j^* v$（因 $r - r^* > -v$）。故 $\min_r (r + \text{cnt}[r]v) = r^* + j^* v$。

### 3.4 示例演算

![示例演算：分桶、逐类候选与贪心扫描，第一处空洞在 x=4](images/wc337_q4_walkthrough.svg)

以示例 1（`value = 5`）为例。分桶：$1{\to}1$，$-10{\to}0$，$7{\to}2$，$13{\to}3$，$6{\to}1$，$8{\to}3$，得 $\text{cnt} = [1,2,1,2,0]$（$r = 0..4$）。贪心扫描：

| 靶点 $x$ | $r = x \bmod 5$ | 桶变化 | 结果 |
|---|---|---|---|
| 0 | 0 | $1 \to 0$ | ✓（−10 加两个 5 变 0）|
| 1 | 1 | $2 \to 1$ | ✓（元素 1 原地）|
| 2 | 2 | $1 \to 0$ | ✓（7 减一个 5 变 2）|
| 3 | 3 | $2 \to 1$ | ✓（13 减两个 5 变 3）|
| 4 | 4 | 桶空 | ✗ 停止——**答案 4** |

闭式逐类候选：$0{+}1{\times}5{=}5$，$1{+}2{\times}5{=}11$，$2{+}1{\times}5{=}7$，$3{+}2{\times}5{=}13$，$4{+}0{\times}5{=}4$，最小值 4，与扫描一致。最终数组正是官方解释的 $[1,0,2,3,6,8]$：6、8 原地不动即可（未被指派的元素**无需处理**，MEX 只看 $0..k-1$ 是否出现）。

## 4. 算法细节

1. **非负余数规范化**：C++ 的 `%` 可能返回负值（如 $-10 \bmod 7 = -3$），必须写 `((x % value) + value) % value` 归一到 $[0, \text{value})$；Python 对正模数天然返回非负余数，直接 `x % value` 即可。
2. **计数数组开 `value` 大小**：$1 \le \text{value} \le 10^5$，定长数组代替哈希表更快。若 $\text{value} \gg n$，多数桶为空，最小空桶的下标 $r$ 直接令 $\text{ans} \le r$——闭式与扫描都自然处理，无需特判。
3. **闭式候选用 64 位**：$r + \text{cnt}[r]\cdot\text{value}$ 可达 $(\text{value}-1) + n\cdot\text{value} \approx 10^{10}$，超出 `int`；C++ 用 `long long` 取 min。最终答案 $\le n \le 10^5$，返回 `int` 安全。
4. **扫描版不需要显式循环上界**：每成功一步消耗一个元素（§5 引理 5），循环至多 $n+1$ 步必然终止；防御性写法可加 `x < n` 断言。
5. **指派自由**：桶内哪个元素担任哪个类内靶点无所谓——同余即互达，不需要真正的二分图匹配。这正是能把 $10^5$ 个元素压缩成 `value` 个计数的原因。
6. **两种实现的取舍**：闭式一次遍历取 min、与 §5 定理直译对应；扫描版是赛场直觉（逐靶消耗），也更好改成「只加不减」之类的变体（见延伸思考）。两者复杂度同为 $O(n + \text{value})$。

## 5. 正确性证明

**引理 1**（可达性）：元素 $x$ 经若干次操作能变成 $y$ $\iff$ $x \equiv y \pmod{\text{value}}$。

**证明**：（⇒）每次操作使元素变化 $\pm\text{value}$，即加上 $\text{value}$ 的整数倍，余数不变；对操作次数归纳知终值与初值同余。（⇐）设 $y - x = k\cdot\text{value}$：$k \ge 0$ 时执行 $k$ 次「加」，$k < 0$ 时执行 $-k$ 次「减」。特别地，余 $r$ 的元素可变成**任何**非负的 $y \equiv r \pmod v$。∎

**引理 2**（前缀可覆盖判定）：能把 $0,1,\dots,k-1$ 全部同时凑出 $\iff$ 对每个 $r \in [0, v)$ 都有 $c_r(k) \le \text{cnt}[r]$，其中 $c_r(k) = \bigl|\{\,t \in [0,k) : t \equiv r \ (\mathrm{mod}\ v)\}\bigr|$。

**证明**：（⇒）靶点 $t$ 须由某个**终值恰为 $t$** 的元素承担；不同靶点的承担元素互不相同（一个元素只有一个终值）；又由引理 1 的逆否，终值 $t \equiv r$ 的元素初值必 $\equiv r$。故余 $r$ 的元素至少被占用 $c_r(k)$ 个，$c_r(k) \le \text{cnt}[r]$。（⇐）对每个类 $r$，将其 $c_r(k)$ 个类内靶点 $r, r+v, \dots$ 与该类中任选的 $c_r(k)$ 个元素一一配对，由引理 1 各自可达，未被指派的元素保持原值。∎

**引理 3**（计数化简）：对 $0 \le r < v$：若 $r \ge k$ 则 $c_r(k) = 0$；若 $r < k$ 则 $c_r(k) = \bigl\lceil (k-r)/v \bigr\rceil$，且

$$c_r(k) \le \text{cnt}[r] \iff k \le r + \text{cnt}[r]\cdot v .$$

**证明**：类内小于 $k$ 的靶点为 $r,\ r+v,\ \dots,\ r+(j-1)v$ 共 $j$ 个 $\iff r+(j-1)v < k \le r + jv \iff j = \lceil (k-r)/v \rceil$；而 $j \le \text{cnt}[r] \iff k \le r + \text{cnt}[r] \cdot v$（对上取整定义移项即得）。∎

**引理 4**（前缀封闭）：若 $[0,k)$ 可覆盖，则 $[0,k')\ (k' < k)$ 可覆盖。

**证明**：$c_r(k') \le c_r(k) \le \text{cnt}[r]$，引理 2 的条件在 $k'$ 下仍全部成立。∎

**引理 5**（答案上界）：任何方案中 $\mathrm{MEX} \le n$；且贪心扫描至多 $n+1$ 步内必然停在某个空桶上。

**证明**：$\mathrm{MEX} \ge k+1$ 要求 $0..k$ 全部出现，即 $k+1$ 个互不相同的终值，需要 $k+1$ 个元素，故 $k \le n-1$、$\mathrm{MEX} \le n$。扫描中每个成功靶点消耗一个桶内元素，至多消耗 $n$ 个，故至多 $n+1$ 步内必遇空桶。∎

**定理**：最大 MEX $= \displaystyle\min_{0 \le r < v} \bigl( r + \text{cnt}[r]\cdot v \bigr)$。

**证明**：记 $k^* = \min_r (r + \text{cnt}[r]v)$，取达到最小的 $r^*$。

（可达下界）对任意 $k \le k^*$ 与任意 $r \in [0,v)$：若 $r \ge k$ 则 $c_r(k) = 0 \le \text{cnt}[r]$；否则由 $k \le k^* \le r + \text{cnt}[r]v$ 与引理 3 得 $c_r(k) = \lceil (k-r)/v \rceil \le \text{cnt}[r]$。由引理 2，$[0,k)$ 可覆盖，故最大 MEX $\ge k^*$。

（不可达上界）取 $k = k^* + 1$。由 $k^* + 1 > r^* + \text{cnt}[r^*]v \ge r^*$ 知 $r^* < k$，且 $(k^*+1) - r^* > \text{cnt}[r^*]\cdot v$，故 $c_{r^*}(k^*+1) = \lceil ((k^*{+}1)-r^*)/v \rceil \ge \text{cnt}[r^*] + 1 > \text{cnt}[r^*]$，引理 2 不满足，$[0,k^*+1)$ 不可覆盖。若某方案 $\mathrm{MEX} \ge k^*+1$，则该方案中 $0..k^*$ 全部出现，是 $[0,k^*+1)$ 可覆盖的见证，矛盾。故最大 MEX $= k^*$。∎

**推论 1**（$\text{value} = 1$）：答案 $= n$——所有元素同余于唯一的桶 $r=0$，恰能凑出 $0..n-1$。

**推论 2**（最小空桶封顶）：若存在空桶，设最小的空桶为 $r_0$，则 $\text{ans} \le r_0$；再由 $r_0 + 0 \cdot v = r_0$ 本身就是候选，$\text{ans} = \min\bigl(r_0,\ \min_{\text{cnt}[r]>0}(r + \text{cnt}[r]v)\bigr)$。示例 1 中 $r_0 = 4$ 即答案。

## 6. 复杂度分析

- **时间复杂度**：$O(n + \text{value})$——一次遍历建桶 $O(n)$；闭式对 $\text{value}$ 个桶各算一次候选取 min，或贪心扫描至多 $n+1$ 步（引理 5 保证 $\text{ans} \le n$）。相比暴力的 $O(n^2) \approx 10^{10}$ 快了五个数量级。
- **空间复杂度**：$O(\text{value})$——计数数组。$\text{value} \le 10^5$ 无压力；若 $\text{value} \gg n$ 想省空间，可换哈希表只存非空桶：鸽笼保证 $n$ 个元素填不满前 $n+1$ 个桶，最小空桶必落在 $[0, \min(\text{value}, n+1)]$ 内，对该范围逐个检查非空即可补上空桶信息。
- **数值范围**：闭式中间值 $r + \text{cnt}[r]\cdot\text{value}$ 最大约 $10^{10}$，C++ 需 `long long`；最终答案 $\le n \le 10^5$，`int` 收尾安全。

## 7. 参考代码

### C++（主解：闭式取 min，§5 定理直译）

```cpp
class Solution {
public:
    int findSmallestInteger(vector<int>& nums, int value) {
        int n = nums.size();
        vector<int> cnt(value);
        for (int x : nums) ++cnt[((x % value) + value) % value]; // 负余数规范化
        long long ans = LLONG_MAX;
        for (long long r = 0; r < value; ++r)
            ans = min(ans, r + (long long)cnt[r] * value);       // 候选可达 ~1e10
        return (int)ans;                                          // 答案 ≤ n，int 安全
    }
};
```

### C++（贪心消耗扫描，赛场直觉版）

```cpp
class Solution {
public:
    int findSmallestInteger(vector<int>& nums, int value) {
        vector<int> cnt(value);
        for (int x : nums) ++cnt[((x % value) + value) % value];
        int x = 0;
        while (cnt[x % value] > 0) {  // 每成功一步消耗一个元素，至多 n 步
            --cnt[x % value];
            ++x;
        }
        return x;
    }
};
```

### Python（主解：闭式取 min）

```python
class Solution:
    def findSmallestInteger(self, nums: List[int], value: int) -> int:
        cnt = [0] * value
        for x in nums:
            cnt[x % value] += 1          # Python 的 % 天然非负
        return min(r + c * value for r, c in enumerate(cnt))
```

### Python（贪心消耗扫描）

```python
class Solution:
    def findSmallestInteger(self, nums: List[int], value: int) -> int:
        cnt = [0] * value
        for x in nums:
            cnt[x % value] += 1
        x = 0
        while cnt[x % value]:            # 类空即停，至多 n 步
            cnt[x % value] -= 1
            x += 1
        return x
```

## 8. 边界情况与易错点

1. **C++ 负数取余**（本题 WA 之首）：$-10 \bmod 7$ 在 C++ 里是 $-3$ 而非 $4$，直接当下标会越界或分错桶；必须 `((x % value) + value) % value`。Python 对正模数返回非负余数，免疫此坑。
2. **「缩到最小非负余数再求 MEX」是错法**：示例 3 的 `[0,5,1,2,3,4]`、`value = 5` 缩成 `[0,0,1,2,3,4]` 后 MEX 只有 5；但两个余 0 元素可**错开**担任 0 与 5，正确答案 6。同类元素的靶点要沿 $r, r+v, r+2v, \dots$ 错开排布，不能都挤在 $r$。
3. **闭式中间值溢出**：$r + \text{cnt}[r]\cdot\text{value}$ 可达约 $10^{10}$，C++ 用 `long long` 参与取 min；答案本身 $\le n$，返回前再转 `int`。
4. **`value = 1` 退化**：唯一桶 $r=0$ 装下全部 $n$ 个元素，答案恰为 $n$（推论 1），可用于对拍断言。
5. **全部元素同余**（如全是 `value` 的倍数）：$\text{cnt}[0] = n$、其余桶空，答案为 1——0 能凑、1 缺，与「元素很多」无关。
6. **未被指派的元素无需处理**：MEX 只看 $0..k-1$ 是否出现，其余元素放哪都不影响；官方示例里 6、8 原地不动。反过来说，**扫描停在第一个空洞就该停**——后面的空洞（5、7）不用管。
7. **空桶封顶直觉**：最小空桶下标 $r_0$ 直接给出上界 $\text{ans} \le r_0$（推论 2），可当快速心算/对拍手段。
8. **扫描版循环上界**：不写上界也安全（每步消耗一个元素，至多 $n+1$ 步）；若担心实现笔误，加 `x < n` 防御性条件不会改变正确性。

**延伸思考**：① 若每步**只能加不能减** `value`：元素 $x$ 只能变成 $\ge x$ 的同余数，类内需按元素值升序与靶点 $r, r+v, \dots$ 顺序配对，配对条件变为 $x_j \le r + (j-1)v$，首个失败处即答案——排序后仍是线性判定，但初始值过大的元素（如 $x = r + 10v$）够不到类内的小靶点。② 若**每个元素至多操作一次**（$\pm v$ 各一次）：可达集缩为 $\{x-v,\ x,\ x+v\}$，计数论证失效，需二分图匹配 / Hall 条件判定前缀可覆盖性。③ 若**操作总次数受限 $m$**：靶点应优先由搬运代价 $|t - x|$ 最小的类内元素承担，退化为类内的代价贪心甚至费用流问题。本题在 `solution/2501-2600/2598_执行操作后的最大MEX.md` 另有一篇每日题解（主推「层×余数网格」与最矮柱闭式的视角，另附哈希表版贪心模拟），可对照阅读。
