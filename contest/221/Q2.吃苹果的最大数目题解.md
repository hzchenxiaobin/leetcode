# LeetCode 吃苹果的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：吃苹果的最大数目（#1705，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-eaten-apples/
- **来源**：LeetCode 第 221 场周赛 Q2
- **难度**：中等
- **标签**：贪心、堆（优先队列）、模拟

**题意**：有一棵特殊的苹果树，在连续 $n$ 天里每天都会长出若干苹果：第 $i$ 天长出 `apples[i]` 个，它们将在 $\text{days}[i]$ 天后**腐烂**（从第 $i + \text{days}[i]$ 天起无法食用）。`apples[i] == 0` 且 `days[i] == 0` 表示当天不长苹果。你**每天最多吃一个**苹果，且 `n` 天结束后树上的存量苹果仍可继续吃。求最多能吃掉的苹果总数。

**约束**：

- $\text{apples.length} == \text{days.length} == n$
- $1 \le n \le 2 \times 10^4$
- $0 \le \text{apples}[i],\ \text{days}[i] \le 2 \times 10^4$
- 只有在 $\text{apples}[i] = 0$ 时，$\text{days}[i] = 0$ 才成立（长出正数苹果的批次，保质期至少为 1 天）

> 💡 **一句话抽象**：每批苹果是一组「带截止期的任务」——截止期是腐烂日，每天至多完成一个，求最大完成数。这是单机 **EDF 调度**（Earliest Deadline First）的教科书场景，招牌解法是**贪心 + 小顶堆（按腐烂日）**。

## 2. 示例

输出：7
解释：第 1 天吃第 1 天长的；第 2、3 天各吃一个第 2 天长的
     （第 3 天后第 3 天长的批次已腐烂）；第 4~7 天吃第 4 天长的。
```

     第 6、7 天吃第 6 天长的 2 个。注意 n=6 天结束后第 7 天仍在吃。
```

**示例 3**（中间空窗期吃存量）

## 3. 解题思路

### 3.1 暴力思路：每天线性扫描找最快腐烂

直觉贪心：**每天在所有尚未腐烂的批次里，挑腐烂日最近的那批吃一个**。朴素实现是每天对「可用列表」做一遍线性扫描：

```text
for d = 0, 1, 2, ... 直到无苹果可吃:
    把第 d 天新长出的批次加入可用列表
    从可用列表删除所有腐烂日 ≤ d 的批次（已腐烂）
    线性扫描找"腐烂日最小"的批次，吃 1 个
```

找最小腐烂日单次 $O(B)$（$B$ 为可用批次数，最坏 $O(n)$），时间轴最长到 $T \approx n + \max(\text{days}) \le 4 \times 10^4$ 天，整体 $O(T \cdot n) \approx 8 \times 10^8$，逼近超时边界。

> ⚠️ **症结**：每天的可用集合只发生**增量变化**（新增一批、腐烂若干），却在无序列表里日复一日重复找最小值。这正是**优先队列**的用武之地。

### 3.2 核心观察：每天吃最快腐烂的 + 小顶堆维护

![核心观察：每天吃最快腐烂的苹果（EDF 贪心 + 小顶堆）](images/wc221_q2_edf_concept.svg)

**观察一（贪心选择）**：每天吃「腐烂日最近」的苹果不会更差。直观理解：快烂的苹果「时间预算」最紧张，把它留到以后最容易白白烂掉；慢烂的苹果今天不吃，明天后天大概率还在。严格的交换论证见第 5 节。

**观察二（数据结构）**：把「找最小腐烂日」从 $O(n)$ 扫描降为 $O(\log n)$ 堆操作。维护一个**小顶堆**，键为**腐烂日**，值为**剩余数量**：

- **入堆**：第 $d$ 天长出苹果时，push `(d + days[d], apples[d])`；
- **清腐烂**：每天先弹出堆顶所有腐烂日 $\le d$ 的批次（从腐烂日起不可食用）；
- **吃**：吃堆顶一个，数量 $-1$，归零则弹出。

> 💡 **腐烂日语义**（按 0-indexed 记）：下标 $i$ 的批次在第 $i$ 天长出，腐烂日 $r = i + \text{days}[i]$，第 $r$ 天**已不可吃**，最后可吃日是 $r-1$。故清除条件是 `rot <= d`。

### 3.3 算法流程

![算法流程：逐天推进，入堆 → 清腐烂 → 吃堆顶](images/wc221_q2_daily_flow.svg)

**步骤**：

1. **初始化**：空小顶堆 `heap`、`ans = 0`、当前日 `d = 0`。
2. **主循环**：只要 `d < n` 或 `heap` 非空：
   - **入堆**：若 `d < n` 且 `apples[d] > 0`，push `(d + days[d], apples[d])`；
   - **清腐烂**：`while heap` 且堆顶腐烂日 $\le d$：`pop`；
   - **吃**：若堆非空，`ans += 1`，堆顶数量 $-1$，归零则 `pop`；
   - **推进**：`d += 1`。
3. **返回** `ans`。

三步**顺序固定**：先入堆（新批次当天就能吃）、再清腐烂（保证后面只吃新鲜的）、最后吃。`n` 天之后不再有新批次，但堆里的存货还能继续吃，所以循环条件不能只写 `d < n`。

### 3.4 示例演算

以示例 1 `apples = [1,2,3,5,2], days = [3,2,1,4,2]`（腐烂日 `[3,3,3,7,6]`）为例，堆用 `{腐烂日:数量}` 表示（同键合并显示）：

![示例演算：逐天入堆、清腐烂、吃堆顶，共 7 个](images/wc221_q2_walkthrough.svg)

| Day | 新入堆 | 清腐烂 | 吃堆顶 | 吃后的堆 | ans |
|-----|--------|--------|--------|----------|-----|
| 0 | (3,1) | — | 吃 (3) | {} | 1 |
| 1 | (3,2) | — | 吃 (3) | {3:1} | 2 |
| 2 | (3,3) | — | 吃 (3) | {3:3} | 3 |
| 3 | (7,5) | 清 3:3 | 吃 (7) | {7:4} | 4 |
| 4 | (6,2) | — | 吃 (6) | {6:1, 7:4} | 5 |
| 5 | — | — | 吃 (6) | {7:4} | 6 |
| 6 | — | — | 吃 (7) | {7:3} | 7 |
| 7 | — | 清 7:3 | 堆空 | {} | 7 |

**关键转折**：

- **Day 3**：堆里存量 `{3:3}` 的腐烂日 $3 \le d = 3$，必须**先全部清掉**再吃——否则会把腐烂当天的苹果吃进肚。
- **Day 4**：新批 `(6,2)` 比存量 `(7:4)` 腐烂日更近，堆顶自动切换成 `6`，保证每天吃的都是「最快腐烂」——这正是小顶堆的核心价值。
- **Day 5~7**：$d \ge n$ 已无新果，但堆非空就继续推进，直到 Day 7 存量 `7:3` 全部腐烂、堆空终止。这解释了为什么循环条件是「$d < n$ 或堆非空」。

最终 `ans = 7` ✓。

## 4. 算法细节

1. **堆元素**：二元组 `(rot, cnt)`——`rot = d + days[d]` 是该批次的腐烂日，`cnt` 是剩余数量。**键是 rot**，小顶堆保证堆顶是存活批次中腐烂日最小者。
2. **腐烂日语义与清除条件**：第 $i$ 批苹果在第 $i + \text{days}[i]$ 天（0-indexed）**当天已不可吃**，所以清除条件必须是 `rot <= d`；写成 `< d` 会在腐烂当天误吃一个。
3. **循环终止**：条件 `d < n or heap`。上界 $T \le n + \max(\text{days}) \le 4 \times 10^4$，天数有限必终止。
4. **空批次跳过**：`apples[d] == 0` 时（约束保证此时 `days[d] == 0`）不入堆，避免无意义条目。
5. **语言差异——吃堆顶**：
   - Python `heapq` 以首元素为键，`h[0][1] -= 1` **原地减数量**不破坏堆序（键未变），归零再 `heappop`，省一次 push；
   - C++ `priority_queue::top()` 返回 `const` 引用，不能原地改，须 **pop → 改值 → 若仍 >0 再 push**，多一次 $O(\log n)$ 但不影响渐近复杂度。
6. **小顶堆声明**：C++ 默认 `priority_queue` 是**大顶堆**，必须写 `priority_queue<pair<int,int>, vector<...>, greater<...>>`；写反会每天吃最晚腐烂的批次，快的全烂掉，结果严重偏小。

## 5. 正确性证明

**引理 1（交换不劣）**：设 $S$ 是任意合法解，其在前 $d$ 天的吃法与贪心 $G$ 相同，但第 $d$ 天不同：$G$ 吃批次 $A$（当天可用批次中腐烂日最小，腐烂日 $r_A$），$S$ 吃批次 $B \ne A$（腐烂日 $r_B > r_A$）或什么都不吃。则存在合法解 $S'$，前 $d$ 天与 $G$ 完全一致，且总进食数 $|S'| \ge |S|$。

**证明**：分三种情形。

- **$S$ 第 $d$ 天不吃**：令 $S' = S$ 加上「第 $d$ 天吃 $A$ 的一个」。$A$ 在第 $d$ 天可用（$G$ 正是这么吃的），合法，且 $|S'| = |S| + 1 > |S|$。
- **$S$ 吃 $B$，且此后某天 $d'$（$d < d' \le r_A - 1$）也吃 $A$**：构造 $S'$ 在 $d$ 吃 $A$、在 $d'$ 吃 $B$，其余与 $S$ 相同。$A$ 在 $d$ 天可用；$B$ 在 $d'$ 天可用，因为 $S$ 在 $d'$ 吃 $A$ 要求 $d' \le r_A - 1 < r_A < r_B$，即 $d'$ 未到 $B$ 的腐烂日。$|S'| = |S|$。
- **$S$ 吃 $B$，此后再也不吃 $A$**：令 $S'$ 在 $d$ 天把吃的对象从 $B$ 换成 $A$，其余与 $S$ 相同。$A$ 在 $d$ 天可用，$|S'| = |S|$。

三种情形下 $S'$ 都合法且不劣，且第 $d$ 天与 $G$ 一致。∎

**引理 2（堆维护等价）**：在任意天 $d$，算法「清腐烂后取堆顶吃一个」等价于「在所有腐烂日 $> d$ 的存活批次中，吃腐烂日最小批次的一个苹果」。

**证明**：对天数归纳维护不变式「堆中恰为当前所有未吃完且腐烂日 $> d$ 的批次」。初始堆空成立。第 $d$ 天：入堆恰好加入当天新批次；随后不断弹出堆顶腐烂日 $\le d$ 者——由小顶堆性质，若堆顶腐烂日 $> d$ 则堆中所有元素均如此，若 $\le d$ 则该批次必在第 $d$ 天不可吃、该被丢弃。清空后堆中元素全部满足腐烂日 $> d$，且堆顶是其中键最小者。∎

**定理**：算法返回的 `ans` 是可吃苹果的最大数目。

**证明**：算法由引理 2 恰好实现了「每天吃存活批次中腐烂日最小者」的贪心解 $G$，故只需证 $G$ 最优。对天数归纳：设 $O$ 是最优解，由引理 1，存在最优解 $O_1$ 与 $G$ 在第 0 天一致；将 $O_1$ 截去第 0 天后是剩余子问题的最优解（否则用更优替换可改进 $O_1$，与 $O_1$ 最优矛盾），对其再次应用引理 1 得到与 $G$ 前两天一致的最优解。逐日推进，最终得到与 $G$ 每一天完全一致的最优解，故 $|G| = |O|$。∎

> 💡 **本质**：这正是单机实时调度中 **EDF（Earliest Deadline First）** 的离散版本——任务带截止期、单位时间执行一个、按截止期升序执行可最大化完成任务数。记住「**堆键 = 截止期**」这一抽象，可迁移到一大批题目（见文末）。

## 6. 复杂度分析

- **时间复杂度**：$O(T + n \log n)$，其中 $T \le n + \max(\text{days}) \le 4 \times 10^4$ 是最后一批苹果的腐烂日。
  - 主循环逐天推进，每天除堆操作外是 $O(1)$，共 $O(T)$；
  - 每天至多**入堆一次**（一批），全程入堆 $\le n$ 次；每次入堆、出堆 $O(\log n)$，且出堆总数 $\le$ 入堆总数，故堆操作总计 $O(n \log n)$。
- **空间复杂度**：$O(n)$。堆中至多同时存放 $n$ 个批次条目（每天至多入堆一批）。

> 💡 **循环由「天」驱动而非「苹果个数」驱动**：即使 $d \ge n$ 没有新苹果，只要堆里还有存货就得继续推进。本题 $T \le 4 \times 10^4$ 规模可控；若把 $\text{days}[i]$ 放大到 $10^9$，逐天模拟会超时，需改用「事件驱动」按堆顶跳天（见文末延伸思考）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int eatenApples(vector<int>& apples, vector<int>& days) {
        int n = apples.size(), ans = 0;
        priority_queue<pair<int,int>, vector<pair<int,int>>,
                       greater<pair<int,int>>> pq;   // 小顶堆：(腐烂日, 剩余数量)
        for (int d = 0; d < n || !pq.empty(); ++d) {
            if (d < n && apples[d] > 0) {
                pq.emplace(d + days[d], apples[d]);  // 今天的批次入堆
            }
            while (!pq.empty() && pq.top().first <= d) {
                pq.pop();                            // 清掉今天已腐烂的批次
            }
            if (!pq.empty()) {                       // 吃腐烂日最近的一个
                ++ans;
                auto [rot, cnt] = pq.top();
                pq.pop();
                if (cnt > 1) {
                    pq.emplace(rot, cnt - 1);
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from heapq import heappush, heappop

class Solution:
    def eatenApples(self, apples: List[int], days: List[int]) -> int:
        h = []                              # 小顶堆：[腐烂日, 剩余数量]
        n, ans, d = len(apples), 0, 0
        while d < n or h:                   # n 天后堆里有存货就继续吃
            if d < n and apples[d] > 0:
                heappush(h, [d + days[d], apples[d]])
            while h and h[0][0] <= d:       # 清掉今天已腐烂的批次
                heappop(h)
            if h:                           # 吃腐烂日最近的一个
                ans += 1
                h[0][1] -= 1                 # 键未变，原地减数量不破坏堆序
                if h[0][1] == 0:
                    heappop(h)
            d += 1
        return ans
```

## 8. 边界情况与易错点

1. **清除条件是 `rot <= d` 而非 `< d`**：腐烂日语义是「第 $r$ 天**起**不可吃」，最后可吃日为 $r-1$。示例 1 的 Day 3 若写成 `<`，会在腐烂当天多吃存量 `3:3` 一个，输出错误的 8。
2. **「清腐烂」必须在「吃」之前**：先吃后清会把腐烂日恰等于当天的苹果吃掉。Day 3 是现成的反例测试点。
3. **循环条件 `d < n or heap`**：示例 1 中 Day 5~7（$d \ge n$）贡献了 3 个苹果，示例 2 的第 7 天同理。循环只写 `d < n` 会大量少算。
4. **`apples[d] == 0` 不入堆**：约束保证此时 `days[d] == 0`；顺手判掉可避免无意义条目（即便误入堆也会因 `rot = d` 立即被清，但依赖巧合的写法不可取）。
5. **不存在「当天长当天烂」**：约束「只有 `apples[i]=0` 时 `days[i]=0` 才成立」排除了 `apples[i]>0, days[i]=0`，无需特判 `rot == d` 的新批次。
6. **C++ 小顶堆写法**：`priority_queue` 默认大顶堆，必须加 `greater<pair<int,int>>`；写反不报错、只 WA，是本题最隐蔽的坑。
7. **无溢出风险**：`ans` 每天至多 +1，上界 $T \le 4 \times 10^4$；腐烂日上界同量级，`int` 足够。
8. **同一天多批同腐烂日**：示例 1 的 Day 0/1/2 三批腐烂日均为 3，堆中同键条目顺序无要求，先吃哪个都等价（同一刻腐烂），不影响正确性。
