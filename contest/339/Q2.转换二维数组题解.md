# LeetCode 转换二维数组 题解

## 1. 题目概述

- **标题 / 题号**：转换二维数组（#2610，medium）
- **链接**：https://leetcode.cn/problems/convert-an-array-into-a-2d-array-with-conditions/
- **来源**：LeetCode 第 339 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数、构造

**题意**：给定整数数组 `nums`，把它的**全部**元素划分进若干行，构造一个二维数组，满足三个条件：

- 只用 `nums` 中的元素，且每个元素都要用上（`nums` 作为**多重集被完整划分**）；
- 每一行内的元素**互不相同**；
- 行数**尽可能少**。

返回任一合法方案，各行长度可以不同。

**约束**：

- $1 \le nums.length \le 200$
- $1 \le nums[i] \le nums.length$

> 💡 关键信号：约束「同值不能同行」意味着行数的瓶颈只卡在**最高频的值**身上——谁的副本多，谁就决定下界。而 $nums[i] \le n$ 的值域限制则提示计数表用普通数组即可。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,4,1,2,3,1]
输出：[[1,3,4,2],[1,3],[1]]
解释：1 出现 3 次，每行至多放一个 1，故至少需要 3 行。
      三行分别为 [1,3,4,2]、[1,3]、[1]，恰好用完全部 7 个元素。
```

**示例 2**

```text
输入：nums = [1,2,3,4]
输出：[[4,3,2,1]]
解释：所有元素互异，一行就够了。
```

**示例 3（补充：全相同元素）**

```text
输入：nums = [2,2,2,2]
输出：[[2],[2],[2],[2]]
解释：每个 2 都必须单独占一行，行数 = n = 最大频次 4。
```

## 3. 解题思路

### 3.1 暴力思路：逐元素找「第一个能放的行」

最直接的模拟：从左到右扫 `nums`，对每个 `x` 依次检查第 0 行、第 1 行……找到第一个**尚未包含** `x` 的行放进去；全都包含就新开一行。若行内查重用线性扫描，最坏（全相同元素）为 $O(n^2) \approx 4 \times 10^4$，$n \le 200$ 完全能过；「枚举所有划分」则是指数级，不可行。

但这个模拟要为每行维护一个「已含哪些值」的集合，代码重、细节多。比赛时应直接抓住结构：**行数的答案与投放顺序无关，只由频次决定**。

### 3.2 核心观察：最少行数 = 最大频次

![频次即下界+第k次进第k行的构造](images/wc339_q2_freq_lower_bound.svg)

**下界（必须这么多行）**：设值 $x$ 出现 $f_x$ 次。「每行内元素互不相同」⇒ 同一个 $x$ 在任一行至多出现 1 次 ⇒ $x$ 的 $f_x$ 份副本必须散进 $f_x$ 个**不同**的行。于是行数

$$
R \;\ge\; \max_{x}\, f_x \;=\; \text{maxFreq}.
$$

**上界（这么多行够用）**：取 $R = \text{maxFreq}$ 行，把每个值的**第 $k$ 次出现**（$k$ 从 0 计）放进**第 $k$ 行**。同值副本的 $k$ 互不相同 ⇒ 落进不同行 ⇒ 行内不重复；不同值之间天然无冲突。构造合法。

**结论**：最少行数恰为 $\text{maxFreq}$，「第 $k$ 次进第 $k$ 行」就是现成的合法方案。

> ⚠️ 区分两类「装箱」问题：这里最小化的是**桶的数量**、约束是「同值不同桶」，桶数由最大需求（最大频次）决定；不要与「桶容量固定、最小化桶数」的经典装箱混为一谈——后者是 NP-hard，本题不是。

### 3.3 算法流程：一遍扫描，按需开行

![算法流程：seen 计数 + 按需 append 新行](images/wc339_q2_algorithm_flow.svg)

不必先扫一遍算 `maxFreq` 再预建行，一遍扫描即可：维护 `seen[x]` 表示 `x` **已投放的份数**——它恰好就是 `x` 下一步该去的**行号**。当 `seen[x]` 追上当前行数时，说明现有每一行都已被 `x` 占了一个位置，必须新开一行；行数就这样在「某值的第 $R$ 份副本」处 $+1$，最终自然收敛到 $\text{maxFreq}$。

### 3.4 示例演算

![示例 [1,3,4,1,2,3,1] 的逐元素投放演算](images/wc339_q2_example_walkthrough.svg)

以 `nums = [1,3,4,1,2,3,1]` 为例（值 `1` 的频次为 3，即答案行数为 3）：

| 步 | $x$ | `seen[x]`（投放前） | 动作 | 第0行 | 第1行 | 第2行 |
|:--:|:---:|:------------------:|------|-------|-------|-------|
| ① | 1 | 0 | 投入第 0 行 | `[1]` | | |
| ② | 3 | 0 | 投入第 0 行 | `[1,3]` | | |
| ③ | 4 | 0 | 投入第 0 行 | `[1,3,4]` | | |
| ④ | 1 | 1 | **新开第 1 行** | `[1,3,4]` | `[1]` | |
| ⑤ | 2 | 0 | 投入第 0 行 | `[1,3,4,2]` | `[1]` | |
| ⑥ | 3 | 1 | 投入第 1 行 | `[1,3,4,2]` | `[1,3]` | |
| ⑦ | 1 | 2 | **新开第 2 行** | `[1,3,4,2]` | `[1,3]` | `[1]` |

最终 `[[1,3,4,2],[1,3],[1]]`，共 3 行 $= \text{maxFreq}$。两次「新开行」都发生在值 `1` 的副本上——它正是频次最高的值 ⭐。

## 4. 算法细节

1. **`seen[x]` 的双重语义**：既是「`x` 已投放的份数」，又是「`x` 下一个副本的目标行号」——因为第 $k$ 次出现进第 $k$ 行，投放次数与行号天然同步，一张计数表同时承担查重与定位。
2. **按需开行的判据**：`seen[x] == len(ans)` 时 `append` 新行。此时 `x` 已在现有 $0..len(ans)-1$ 每行各占一份（每份进不同行），第 `seen[x]` 份只能去新行——判据与「第 $k$ 次进第 $k$ 行」严格一致。
3. **计数表选型**：值域 $[1, n]$ 用 `vector<int>(n+1)` / 长度 $n+1$ 的数组即可，无哈希常数；值域无界时换 `unordered_map` / `defaultdict`，均摊仍是 $O(n)$。
4. **行内顺序无关**：题目只检查三个条件，返回任一合法解即可；一遍扫描天然按出现顺序追加，无需刻意构造特定顺序。
5. **与「先算 maxFreq 再预建行」的等价性**：两趟写法（先统计 `maxFreq`、预建 `R` 行再投放）与按需开行在正确性上等价，后者省一趟扫描、也无需提前知道 `maxFreq`，比赛时更顺手。

## 5. 正确性证明

**引理 1（下界）**：任何合法方案的行数 $R \ge \max_x f_x$，其中 $f_x$ 为值 $x$ 的出现次数。

**证明**：取频次最大的值 $x^\ast$，$f_{x^\ast} = \max_x f_x$。「行内互不相同」⇒ $x^\ast$ 在每行至多出现 1 次。要把 $f_{x^\ast}$ 份副本全部放进行中且每行至多 1 份，至少需要 $f_{x^\ast}$ 个不同的行，故 $R \ge f_{x^\ast}$。∎

**引理 2（构造合法）**：按「值 $x$ 的第 $k$ 次出现（$k$ 从 0 计）放入第 $k$ 行」构造，则每行内元素互不相同。

**证明**：反设某行 $r$ 内有两个位置的值相同，均为 $x$。它们是 $x$ 的第 $k_1$、$k_2$ 次出现且 $k_1 \ne k_2$；但由投放规则二者都应在第 $k_1$（与 $k_2$）行，即 $k_1 = r = k_2$，矛盾。故同行任意两位置的值不同。∎

**定理**：一遍扫描 + 按需开行算法返回的 `ans` 是合法解，且行数恰为 $\max_x f_x$，即最少。

**证明**：投放规则与引理 2 相同（`seen[x]` 投放前恰为该副本的出现序号），合法性得证。对循环步数归纳证明不变量「每步处理后 $len(ans) = \max_{x}\, seen[x]$」：初始两者均为 0；处理 $x$ 时设 $k = seen[x]$，若 $k = len(ans)$ 则新开行后行数变为 $k+1$，随后 $seen[x]$ 增至 $k+1$，不变量两侧同步达到新最大值；若 $k < len(ans)$，行数不变，$seen[x]$ 增至 $k+1 \le len(ans)$，不变量保持。终止时 $seen[x] = f_x$ 对所有 $x$ 成立，故行数 $= \max_x f_x$，结合引理 1 即为最少。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个元素仅一次计数自增、一次判等、一次追加，均为 $O(1)$。
- **空间复杂度**：$O(n)$。计数表 `seen` 占 $O(n)$（值域 $[1,n]$）；输出数组存全部 $n$ 个元素，亦为 $O(n)$。

$n \le 200$ 时任意 $O(n^2)$ 写法都能通过，本题考点在「下界观察」而非常数优化。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<vector<int>> findMatrix(vector<int>& nums) {
        int n = nums.size();
        vector<int> seen(n + 1, 0);        // seen[x] = x 已投放的份数 = 下一个目标行号
        vector<vector<int>> ans;
        for (int x : nums) {
            int k = seen[x]++;
            if (k == (int)ans.size())      // 现有每行都已被 x 占位
                ans.push_back({});         // 新开第 k 行
            ans[k].push_back(x);           // 第 k 次出现 → 第 k 行
        }
        return ans;
    }
};
```

### Python

```python
from collections import defaultdict

class Solution:
    def findMatrix(self, nums: List[int]) -> List[List[int]]:
        ans = []
        seen = defaultdict(int)            # seen[x] = 已投放的 x 份数
        for x in nums:
            k = seen[x]
            if k == len(ans):             # 现有每行都已有 x
                ans.append([])            # 新开第 k 行
            ans[k].append(x)              # 第 k 次出现 → 第 k 行
            seen[x] += 1
        return ans
```

## 8. 边界情况与易错点

1. **全相同元素**（如 `[2,2,2,2]`）：答案为 $n$ 行、每行 1 个元素。按需开行自动处理，无需特判——这正是行数达到 $\text{maxFreq} = n$ 的极端情形。
2. **全互异**：一行装下，`seen[x]` 恒为 0，永不触发开新行。
3. **行数下界的直觉错误**：既不是「去重后的元素个数」（把行当列看齐），也不是 $\lceil n / R \rceil$ 之类的均分——就是 $\max_x f_x$。拿示例 1 自测：去重数 4、均分 $\lceil 7/4 \rceil = 2$ 都不对，只有频次 3 对。
4. **元素必须全部用上**：题面说「只包含 `nums` 中的元素」，示例 1 的解释明确「所有元素都有用到」——这是对多重集的**完整划分**，不能丢弃元素来减少行数（否则 1 行甚至 0 行就是「最优」了）。
5. **返回任一合法解即可**：行内顺序、行间顺序都不影响判定，别浪费比赛时间构造特定顺序。
6. **C++ 有符号 / 无符号比较**：`k == ans.size()` 是 int 与 size_t 比较，部分编译器开 `-Wsign-compare` 会告警，加 `(int)` 转换更稳。
7. **别写「逐行线性查重」的模拟**：$O(n \cdot R)$ 在 $n \le 200$ 虽能过，但要维护每行的集合、代码更长；`seen` 计数一遍扫描更短更不易错，是最该沉淀的模板。
8. **值域提示别浪费**：$1 \le nums[i] \le n$ 明示了数组计数；面试或加强版中若值域放大到 $10^9$，换哈希表即可，思路不变。
