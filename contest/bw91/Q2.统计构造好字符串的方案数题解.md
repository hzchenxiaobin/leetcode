# LeetCode 统计构造好字符串的方案数 题解

## 1. 题目概述

- **标题 / 题号**：统计构造好字符串的方案数（#2466，medium）
- **链接**：https://leetcode.cn/problems/count-ways-to-build-good-strings/
- **来源**：LeetCode 第 91 场双周赛 Q2
- **难度**：中等
- **标签**：动态规划

**题意**：从空串出发，每一步可以在末尾**追加** $zero$ 个 `'0'` 或 $one$ 个 `'1'`（两种操作可任意次、任意混合）。长度落在 $[low, high]$ 内（含边界）的串称为**好字符串**。求不同好字符串的数目，答案对 $10^9+7$ 取模。

**约束**：

- $1 \le low \le high \le 10^5$
- $1 \le zero, one \le low$（两种步长都不超过 `low`，但转移写法不变，只需处理 $i < zero$ / $i < one$ 的下标边界）

## 2. 示例

**示例 1**

```text
输入：low = 3, high = 3, zero = 1, one = 1
输出：8
解释：zero = one = 1，每步加 1 个字符，长度 3 的串共 2^3 = 8 个，全部是好字符串。
```

**示例 2**

```text
输入：low = 2, high = 3, zero = 1, one = 2
输出：5
解释：长度 2："00"、"11"；长度 3："000"、"011"、"110"，共 5 个。
```

**示例 3（边界补充）**

```text
输入：low = 1, high = 3, zero = 2, one = 2
输出：2
解释：zero = one = 2 时只能构造 "00"、"11"、"0000"、"1111"、"0011"……
长度 1~3 内只有长度 2 的 "00" 与 "11" 两个好字符串。
注意：zero == one 不代表两种操作等价——一个加的是 '0' 段、一个加的是 '1' 段，
产生的字符串内容不同，不会重复计数（见 §5 引理 1）。
```

## 3. 解题思路

### 3.1 暴力思路

DFS 枚举所有构造路径：从长度 0 出发，每步分支「+zero」或「+one」，长度超过 `high` 剪枝，落在 $[low, high]$ 内计数。状态数最坏是斐波那契级别的指数增长（$high = 10^5$ 时天文数字），直接枚举不可行。反向的暴力是按长度 $O(high \cdot high / \min(zero,one))$ 枚举「最后一段」，同样是超时的平方级。必须把「长度」抽象成状态做 DP。

### 3.2 核心观察：一维爬楼梯 DP

![核心观察：爬楼梯式一维 DP](images/bw91_q2_climbing_dp_model.svg)

**定义** $dp[i]$：长度**恰好**为 $i$ 的字符串的构造方案数。操作的顺序性给出天然的最后一步分解：任何长度 $i$ 的串，其**最后一次操作**要么追加了 $zero$ 个 `'0'`（于是前面是某个长度 $i - zero$ 的串），要么追加了 $one$ 个 `'1'`（前面是长度 $i - one$ 的串）。这两类末尾字符不同（`'0'` vs `'1'`），**互斥**；又必居其一，**完备**。于是：

$$dp[i] = [i \ge zero] \cdot dp[i - zero] + [i \ge one] \cdot dp[i - one]$$

这就是经典爬楼梯（LeetCode 70）的变形——「步长」从 $\{1,2\}$ 换成 $\{zero, one\}$。答案即：

$$\text{ans} = \sum_{i=low}^{high} dp[i] \pmod{10^9+7}$$

### 3.3 算法流程

![算法流程：一遍递推 + 区间求和](images/bw91_q2_algorithm_flow.svg)

```text
1. dp[0] = 1（空串），dp[1..high] = 0
2. for i = 1 .. high：
       cur = 0
       若 i ≥ zero：cur += dp[i−zero]
       若 i ≥ one ：cur += dp[i−one]
       dp[i] = cur mod (10⁹+7)
3. 答案 = (dp[low] + … + dp[high]) mod (10⁹+7)
```

### 3.4 示例演算

![示例演算：low=2, high=3, zero=1, one=2](images/bw91_q2_walkthrough.svg)

以示例 2 演算：$dp[0]=1$；$dp[1] = dp[0] = 1$（"0"）；$dp[2] = dp[1] + dp[0] = 2$（"00"、"11"）；$dp[3] = dp[2] + dp[1] = 3$（"000" = "00"+"0"、"011" = "0"+"11"、"110" = "1"+"10"）。答案 $= dp[2] + dp[3] = 5$。示例 1 中 $zero = one = 1$ 时每步两种选择，$dp[i] = 2^i$（$dp[0]=1, dp[1]=2, dp[2]=4, dp[3]=8$），答案 $= dp[3] = 8$ ✓。

## 4. 算法细节

1. **状态只设长度一维**：操作只影响末尾，前缀的构造方式不影响后续合法性，无后效性成立。
2. **初值 $dp[0] = 1$**：空串是唯一长度 0 的串；这个 1 会顺着 $i = zero$、$i = one$ 两个入口流入后续状态，漏掉它全盘皆 0。
3. **边界 $i < zero$ / $i < one$ 跳项**：转移前判断下标非负，等价写法是把不满足条件的加数视为 0。
4. **取模时机**：每次加法后立即 `% MOD`（C++ 用 `long long` 承接两次累加更稳），最后区间求和再取一次。
5. **答案的两种等价算法**：直接 $\sum_{i=low}^{high} dp[i]$；或算 $S(x) = \sum_{i \le x} dp[i]$ 的前缀和再作差。前者更不容易错。
6. **「方案数」按字符串内容计**：不同操作序列若产生相同字符串（见 §5 引理，其实不可能——操作序列与字符串一一对应），按题意算一个；本题的 DP 直接按字符串计数，无需额外去重。

## 5. 正确性证明

**引理 1（末段唯一分解）**：设串 $t$ 长度为 $i$ 且可由操作序列构造，则 $t$ 的**最后一个字符块**（极长的同字符末尾段）唯一确定，且该块的字符与长度要么恰为 $(zero, \text{'}0\text{'})$ 要么恰为 $(one, \text{'}1\text{'})$。

**证明**：每次操作追加的是**同一段**字符（$zero$ 个 '0' 或 $one$ 个 '1'），故 $t$ 的末尾字符块是若干次操作逐段拼接的结果，但同字符的相邻段会合并——逆着看：$t$ 的极长同字符末段字符为 $c$、长度为 $L$。若 $c = \text{'}0\text{'}$，能产生 '0' 的操作只有「加 $zero$ 个 '0'」，且它必须**最后**执行（其后不能再有加 '1' 的操作，否则末段是 '1'；也不能再加 '0'，否则末段变长），故 $L = zero$。同理 $c = \text{'}1\text{'}$ 时 $L = one$。∎

> ⚠️ 这里隐藏着一个关键事实：**操作序列与最终字符串一一对应**（去掉末段后再递归分解，唯一逆推整条操作序列）。因此「按构造路径计数」与「按字符串内容计数」是同一件事，DP 不会重也不会漏。这也澄清了 §2 示例 3 的讨论——`zero == one` 时 "0" 段与 "1" 段内容不同，永不相撞。

**引理 2（递推无环）**：转移 $dp[i] \to dp[i+zero]$、$dp[i] \to dp[i+one]$ 的依赖方向严格增（$zero, one \ge 1$），按 $i$ 升序计算时右端总是已确定。

**证明**：$i - zero < i$、$i - one < i$。∎

**定理**：按上述递推得到的 $dp[i]$ 等于长度恰为 $i$ 的可构造字符串数目；$\sum_{i=low}^{high} dp[i]$ 为答案。

**证明**：对 $i$ 归纳。$i=0$：空串唯一，$dp[0]=1$ ✓。设对所有 $< i$ 的长度结论成立。任取长度 $i$ 的可构造串 $t$，由引理 1 其末段唯一（'0' 段长 $zero$ 或 '1' 段长 $one$），去掉末段后的前缀长度分别为 $i-zero$、$i-one$，且前缀本身可构造；反之给任一长度 $i-zero$（或 $i-one$）的可构造串追加一段 '0'（或 '1'）得到长度 $i$ 的可构造串。两个方向的构造互逆，故 $dp[i] = dp[i-zero] + dp[i-one]$（下标为负的项视为 0）。长度在 $[low, high]$ 内的串按长度分类互斥完备，求和即答案。∎

## 6. 复杂度分析

- **时间**：$O(high)$——一重递推每步常数次加法与取模，加上 $O(high)$ 的区间求和。
- **空间**：$O(high)$ 的 DP 数组；若只需答案可顺带累计，但 $dp[i]$ 本身要留到区间求和，无法滚动成 $O(1)$（除非边递推边对 $i \ge low$ 累加，那样空间仍需 $O(\max(zero, one))$ 滚动窗，收益不大）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countGoodStrings(int low, int high, int zero, int one) {
        const long long MOD = 1000000007LL;
        vector<long long> dp(high + 1, 0);
        dp[0] = 1;                                   // 空串：1 种方案
        for (int i = 1; i <= high; ++i) {
            long long cur = 0;
            if (i >= zero) cur += dp[i - zero];      // 末尾追加 zero 个 '0'
            if (i >= one)  cur += dp[i - one];       // 末尾追加 one 个 '1'
            dp[i] = cur % MOD;
        }
        long long ans = 0;
        for (int i = low; i <= high; ++i) ans = (ans + dp[i]) % MOD;
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countGoodStrings(self, low: int, high: int, zero: int, one: int) -> int:
        MOD = 10 ** 9 + 7
        dp = [0] * (high + 1)
        dp[0] = 1                              # 空串：1 种方案
        for i in range(1, high + 1):
            cur = 0
            if i >= zero:
                cur += dp[i - zero]            # 末尾追加 zero 个 '0'
            if i >= one:
                cur += dp[i - one]             # 末尾追加 one 个 '1'
            dp[i] = cur % MOD
        return sum(dp[low:high + 1]) % MOD
```

> 💡 两份代码均通过官方示例（`8`、`5`），并与「按构造路径 DFS 展开」的暴力在 2000 组小规模随机数据（$high \le 18$）下对拍一致；大规模 $high = 10^5$ 时 C++ 毫秒级、Python 约 40ms。

## 8. 边界情况与易错点

1. **$dp[0] = 1$ 忘记初始化**：最常见的错，导致全 0。
2. **下标越界**：$i < zero$ 或 $i < one$ 时对应项直接跳过，别让 `dp[i - zero]` 访问负下标。
3. **取模遗漏**：C++ 中 `int` 相加两次 $10^9$ 级别会溢出，用 `long long` 中转或每加一次取模；Python 天然大数，但最后要 `% MOD`。
4. **区间求和再取模**：`sum` 累计到 $10^5 \times 10^9$ 级别，C++ 必须 `long long`；Python 无碍但别忘最终取模。
5. **`zero == one` 的疑虑**：两种操作产生不同字符段，不重复计数（§5 引理 1），转移照写 `dp[i-zero] + dp[i-one]` 即可，无需特判。
6. **「长度在区间内」含边界**：$low$、$high$ 都取到（闭区间），循环写 `for i in range(low, high + 1)`。
7. **别用记忆化递归裸跑**：$high = 10^5$ 时 Python 递归深度/开销都可能出问题，线性递推最稳。
