# LeetCode 顺次数 题解

## 1. 题目概述

- **标题 / 题号**：顺次数（#1291，medium）
- **链接**：https://leetcode.cn/problems/sequential-digits/
- **来源**：LeetCode 第 167 场周赛 Q2
- **难度**：中等
- **标签**：枚举、数学

**题意**：一个整数的每一位都比前一位大 1，就称它为**顺次数**（如 `123`、`2345`、`789`）。给定闭区间 $[low, high]$，返回区间内**所有**顺次数组成的**升序**列表。

关键点在于「反向思考」：题目问的是「区间里有哪些数满足条件」，最容易写成「把区间里的数挨个查一遍」；但满足条件的数**极少**，因此应当**直接把答案造出来**。

**约束**：

- $10 \le low \le high \le 10^9$
- 返回值长度没有单独限制，因为答案总数不超过 36 个
- 顺次数各位严格递增 1，所以**天然没有重复数字**，不存在重复答案

## 2. 示例

**示例 1**

```text
输入：low = 100, high = 300
输出：[123, 234]
解释：区间内只有 123（1,2,3）和 234（2,3,4）两个顺次数；
      两位顺次数最大是 89 < 100，所以全部不入答案。
```

**示例 2**

```text
输入：low = 1000, high = 13000
输出：[1234, 2345, 3456, 4567, 5678, 6789, 12345]
解释：四位顺次数 1234 … 6789 共 6 个全部落在区间内；
      五位顺次数中只有 12345 ≤ 13000，23456 已经超出上界；
      三位及以下的顺次数都小于 1000。
```

**示例 3**（补充，覆盖「跨位数」与「下界切掉一半」）

```text
输入：low = 58, high = 155
输出：[67, 78, 89, 123]
解释：两位里只有 67、78、89 不小于 58；三位里只有 123 不超过 155。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法：`for x in range(low, high + 1)`，对每个 $x$ 逐位检查「后一位是否比前一位大 1」。检查一个数需要 $O(\log x)$ 时间，总复杂度

$$O\bigl((high - low) \cdot \log high\bigr)$$

当 $low = 10$、$high = 10^9$ 时是约 $10^{10}$ 次基本操作，必然超时。暴力的问题不在「检查」太慢，而在**枚举对象选错了**：区间里有十亿个数，其中满足条件的只有几十个。命中率约为 $10^{-7}$，等于用十亿次检查去捞 36 个答案。

### 3.2 核心观察：答案由「位数 + 首位」唯一确定

![答案空间只有 36 个数](images/wc167_q2_answer_space.svg)

一个顺次数只由两个参数决定：

- **位数** $L$：这个数一共有几位；
- **首位** $d$：最高位上的数字是几。

因为「每位比前一位大 1」，第 $k$ 位（从 0 开始数）必然是 $d + k$，整个数被完全钉死：

$$x(L, d) = \sum_{k=0}^{L-1} (d+k) \cdot 10^{L-1-k}$$

于是**候选总数**可以直接数出来：

- 位数 $L$ 位时，首位必须满足 $1 \le d$ 且末位 $d + L - 1 \le 9$，即 $1 \le d \le 10 - L$，共 $10 - L$ 个；
- $L$ 最多到 9：若 $L \ge 10$，末位至少是 $1 + 9 = 10$，不是合法数字位；
- 本题 $low \ge 10$，所以一位数 $1 \sim 9$ 全部出局，只需 $L = 2 \dots 9$。

$$\sum_{L=2}^{9} (10-L) = 8+7+6+5+4+3+2+1 = 36$$

**整个值域内只有 36 个顺次数**。与其在十亿个数里找它们，不如直接把这 36 个造出来，逐个判断是否落在 $[low, high]$。

### 3.3 算法流程

![双层枚举 + 递推拼接](images/wc167_q2_enumeration_flow.svg)

两层循环 + 一个递推：

1. 外层枚举位数 $L = 1 \dots 9$（$L = 1$ 的 $1 \sim 9$ 恒小于 $low$，等价于从 2 开始）；
2. 内层枚举首位 $d = 1 \dots 10 - L$；
3. 从 $x = 0$ 出发，对 $k = 0 \dots L-1$ 反复执行 $x \leftarrow 10x + (d+k)$，第 $k$ 次循环就把第 $k$ 位「接」到末尾；
4. 若 $low \le x \le high$，把 $x$ 追加进 `ans`。

**为什么不用排序**：$L$ 位数的取值范围是 $[10^{L-1}, 10^L)$，位数不同的数区间互不重叠且随 $L$ 单调右移；位数相同时，首位越大数越大。而枚举顺序正是「$L$ 升序、$d$ 升序」，所以**生成顺序天然就是数值升序**，直接返回即可。

**可选剪枝**：内层先看最小的候选（$d = 1$，即 $12\cdots$ 共 $L$ 位）。若它已经 $> high$，那么位数更大的顺次数只会更大，可以直接 `break` 跳出外层。本题 36 次枚举本就极快，剪枝属于锦上添花。

### 3.4 示例演算

![示例走查](images/wc167_q2_walkthrough.svg)

以 `low = 1000, high = 13000` 为例：

| 位数 $L$ | 生成的候选 | 判定结果 |
|----------|-----------|----------|
| 2 | 12, 23, 34, 45, 56, 67, 78, 89（8 个） | 全部 $< 1000$，丢弃 |
| 3 | 123, 234, 345, 456, 567, 678, 789（7 个） | 全部 $< 1000$，丢弃 |
| 4 | 1234, 2345, 3456, 4567, 5678, 6789（6 个） | 6 个全部命中 |
| 5 | 12345, 23456, 34567, 45678, 56789（5 个） | 只有 12345 命中 |
| 6 | 123456 已 $>$ 13000 | 之后全部超出，可提前终止 |

最终 `ans = [1234, 2345, 3456, 4567, 5678, 6789, 12345]`。注意 $6789 < 12345$：位数少的数哪怕每一位都大，也一定更小——这正是「按位数优先枚举即得升序」的原因。

## 4. 算法细节

1. **位数的上界是 9，不是 10**。顺次数每位递增 1，长度 10 需要数字 $d, d+1, \dots, d+9$，其中 $d \ge 1$ 必然导致末位 $\ge 10$，非法。把循环写成 `L <= 10`，末位就会取到 $9+1=10$，把 `10` 当成一位拼进去，得到 `1234567890` 这种非法值。
2. **首位上界是 $10 - L$**。这一条与上一条是同一件事的两种说法：$d + L - 1 \le 9$。若只让 $d$ 取 $1 \dots 9$ 而不加这个约束，$L = 2,\ d = 9$ 会拼出 `910`，位数和合法性都错了。
3. **用递推拼接而不是 `pow` 或字符串**。$x \leftarrow 10x + (d+k)$ 各一次乘法加法，既避免 `pow(10, L-1-k)` 的浮点隐患，也避免字符串转换的开销。另一种等价写法是在常量串 `"123456789"` 上取长度为 $L$ 的窗口后 `int()`，注意起点范围必须是 $0 \dots 9-L$（含端点），写成 `range(10)` 会取到长度不足的残缺子串。
4. **不要用 `set` + 排序**。有人担心重复或乱序，于是把结果塞进 `set` 再 `sorted()`。这虽然不会错，但掩盖了「生成即有序」这个关键性质，也让复杂度从 $O(1)$ 变成 $O(k \log k)$；面试/复盘时更应该讲清顺序从何而来。
5. **一位数要不要枚举**。题面保证 $low \ge 10$，所以 $L = 1$ 的 $1 \sim 9$ 永远进不了答案。为通用性从 $L = 1$ 开始写也无妨（多 9 次构造，且这 9 个数必然被区间过滤掉），但必须知道它们**不会**成为答案。
6. **数值范围安全**。最大的顺次数是 `123456789`，远小于 `int` 上限 $2^{31}-1$；即便上界给到 $10^9$ 也不会构造出第 10 位，因此 `int` 足够，无需 `long long`。
7. **过滤用闭区间**。判断条件写 `low <= x && x <= high`，两端都要能取到：示例 1 的 `100..300` 里，`123` 就是靠下界判断保留的。

## 5. 正确性证明

**引理 1（生成的数合法）**：对任意 $1 \le L \le 9$、$1 \le d \le 10-L$，第 3.3 节递推得到的 $x$ 是一个 $L$ 位顺次数。

**证明**：递推每次执行 $x \leftarrow 10x + (d+k)$，等价于在十进制末尾追加数字 $d+k$。归纳可得 $x$ 的十进制表示恰为 $d,\ d+1,\ \dots,\ d+L-1$ 共 $L$ 位。首位 $d \ge 1$，故无前导零、恰为 $L$ 位；末位 $d+L-1 \le 9$，每位都是合法数字；相邻两位之差恒为 1，满足顺次数定义。∎

**引理 2（完备，无遗漏）**：区间 $[10, 10^9]$ 内任意顺次数 $y$ 都会被某一组 $(L, d)$ 生成。

**证明**：设 $y$ 有 $L$ 位、首位为 $d$。由约束 $y \le 10^9$ 且 $y \ge 10$，得 $2 \le L \le 9$，在枚举范围内。又 $y$ 是顺次数，第 $k$ 位必为 $d+k$，故 $y = x(L,d)$；且末位 $d+L-1 \le 9$，即 $d \le 10-L$，落在内层枚举范围内。由引理 1 的构造唯一性，算法生成的值与 $y$ 完全相同。∎

**引理 3（生成顺序升序）**：按 $L$ 升序、$d$ 升序枚举时，被收录进 `ans` 的数值严格递增。

**证明**：设 $L$ 位的顺次数 $y$，则 $10^{L-1} \le y < 10^{L}$，故 $L$ 位数的全体都小于任何 $(L+1)$ 位数，位数分组之间严格有序。同一 $L$ 内，

$$x(L, d+1) - x(L, d) = \sum_{k=0}^{L-1} 10^{L-1-k} = \underbrace{11\cdots1}_{L \text{ 位}} > 0$$

即 $x(L,d)$ 关于 $d$ 严格递增。枚举顺序是字典序 $(L, d)$，映射到数值上严格递增；`ans` 是其子序列，故 `ans` 严格递增。∎

**定理**：算法返回的 `ans` 恰好是区间 $[low, high]$ 内全部顺次数，且按升序排列。

**证明**：

- *不重不漏*：由引理 1，`ans` 中每个元素都是顺次数；且只有满足 $low \le x \le high$ 才被追加，故 `ans` 中元素都在区间内，无非法项。反之，设 $y \in [low, high]$ 是顺次数，由引理 2 它必在某次迭代被构造出来，且过滤条件成立（$y$ 在区间内），故被追加，无遗漏。
- *升序*：由引理 3，枚举顺序即数值严格递增顺序，`ans` 作为子序列保持升序。∎

## 6. 复杂度分析

- **时间**：$O(1)$，与输入规模无关。外层至多 9 位、内层至多 9 个首位，构造第 $L$ 位数需 $L$ 次乘加，总运算量
  $$\sum_{L=2}^{9} (10-L)\cdot L = 156$$
  次乘加（若从 $L = 1$ 起枚举则为 $165$），外加 36 次区间判断与至多 36 次追加。属于常数级开销（约 $10^2$ 量级），比 $O(high - low)$ 的暴力快约 $10^7$ 倍。
- **空间**：$O(1)$ 额外空间（不计返回值）。循环只用 $L$、$d$、$x$ 三个整型变量；返回值本身最多 36 个整数，即 $O(36)$，可视作常数。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> sequentialDigits(int low, int high) {
        vector<int> ans;
        // 顺次数最多 9 位；L = 1 的一位顺次数恒小于 low，写进来只为覆盖面更广
        for (int L = 1; L <= 9; ++L) {
            // 首位 d 的上界是 10 - L，保证末位 d + L - 1 <= 9
            for (int d = 1; d + L - 1 <= 9; ++d) {
                int x = 0;
                for (int k = 0; k < L; ++k) {
                    x = x * 10 + (d + k);   // 逐位拼接，等价于在末尾追加数字
                }
                if (x >= low && x <= high) {
                    ans.push_back(x);       // 生成顺序即升序，无需排序
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def sequentialDigits(self, low: int, high: int) -> list[int]:
        ans = []
        for length in range(1, 10):              # 顺次数最多 9 位
            for first in range(1, 11 - length):  # 末位 first + length - 1 <= 9
                x = 0
                for k in range(length):
                    x = x * 10 + (first + k)     # 逐位拼接
                if low <= x <= high:
                    ans.append(x)                # 生成顺序天然升序
        return ans
```

## 8. 边界情况与易错点

1. **无解要返回空列表**。例如 `low = high = 10`，区间内没有顺次数（最小的两位顺次数是 12），必须返回 `[]` 而不是 `[0]` 或 `[-1]`；C++ 中直接返回空 `vector` 即可。
2. **抽象成闭区间判断**。`low <= x <= high` 两端都要能取等：若把下界写成 `x > low`，示例中 `low = 123` 时会漏掉 123；若把上界写成 `x < high`，`high = 1234` 时会漏掉 1234。
3. **首位上界漏约束**。只写 `for d in range(1, 10)` 而不加 $d + L - 1 \le 9$ 的判断，会拼出 `910`（$L=2,\ d=9$）、`8910` 之类的非法数，且可能把非法值误放进答案（如果它恰好落在区间内）。
4. **位数上界写成 10**。10 位顺次数不存在：继续枚举时末位会取到 $9+1=10$，递推把 `10` 当成一位拼进去，得到 `1234567890` 这种非法值（若再放开到 11 位，`x` 还会突破 `int`），属于典型的「多算反而错」。
5. **字符串切片窗口的边界**。若改用常量串 `"123456789"` 取窗口，`range` 上界必须是 `10 - length`。写成 `range(10)` 时，`len(table[i:i+length])` 会缩短但仍能 `int()` 成功，静默产出错误的短数字。
6. **别为了「保险」而排序**。先 `set` 再 `sorted` 逻辑上不错，但会掩盖「$L$ 升序 + $d$ 升序 = 数值升序」这一核心性质；如果枚举顺序被改成先 $d$ 后 $L$，忘记排序就会直接 WA——所以顺序的性质必须在证明里讲清楚，而不是靠排序兜底。
7. **上界 $10^9$ 与答案规模**。$high$ 取 $10^9$ 时区间内只有 36 个答案；不要因为「上界很大」就误以为需要二分开销或离线预处理，本算法的开销与 $high$ 完全无关。

## 相关题目与扩展

- [LeetCode 1291. 顺次数](https://leetcode.cn/problems/sequential-digits/)：本题，官方提示「先生成全部顺次数再筛选」或「固定首位后递归追加合法数字」。
- [LeetCode 1215. 步进数](https://leetcode.cn/problems/stepping-numbers/)（会员题）：把「比前一位大 1」放宽为「差的绝对值为 1」，同一位可以变小，需从 $0 \sim 9$ 各起点做 BFS/DFS 扩展，是本题的直接变体。
- [LeetCode 788. 旋转数字](https://leetcode.cn/problems/rotated-digits/)：同样是「逐位判定合法性」的枚举题，可与本题的「逐位构造」对照。
- [LeetCode 357. 统计各位数字都不同的数字个数](https://leetcode.cn/problems/count-numbers-with-unique-digits/)：按位数做组合计数，$10 - L$ 这个「首位取值范围」的推导方式与本题一脉相承。

**延伸思考**：若把上界从 $10^9$ 提高到 $10^{18}$，只需把位数上界从 9 改成 18（或按 `high` 的位数截断），枚举量线性增长到约 150 个数，仍然是 $O(1)$ 级别；若要求「返回区间内第 $k$ 个顺次数」，由于候选总数只有 36，可以先 $O(1)$ 生成全表再取下标，也可以用「按位数分组计数 + 组内偏移」直接定位到 $(L, d)$，连生成都省掉。真正需要小心的是把「差为 1」换成「差为任意定值 $c$」的情形——此时首位上界变成 $d + c(L-1) \le 9$，计数公式要相应修改。
