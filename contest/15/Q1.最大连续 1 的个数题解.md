# LeetCode 最大连续 1 的个数 题解

## 1. 题目概述

- **标题 / 题号**：最大连续 1 的个数（#485，easy）
- **链接**：https://leetcode.cn/problems/max-consecutive-ones/
- **来源**：LeetCode 第 15 场周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定一个只由 $0$ 和 $1$ 组成的数组 `nums`，求其中**最长的一段连续 $1$** 的长度；数组里没有 $1$ 时返回 $0$。「连续」指下标相邻，这一段不要求贴住数组边界。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $\text{nums}[i] \in \{0, 1\}$

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,0,1,1,1]
输出：3
解释：开头的两位和最后的三位都是连续 1，其中最长的一段长度为 3。
```

**示例 2**

```text
输入：nums = [1,0,1,1,0,1]
输出：2
解释：三段连续 1 的长度分别为 1、2、1，最大值为 2。
```

**示例 3（补充边界）**

```text
输入：nums = [0,0,0]
输出：0
解释：数组中不存在 1，按题意返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有子数组 $[l, r]$，判定其中是否全为 $1$ 并取最长：枚举 $O(n^2)$ 组区间、每组判定 $O(n)$，总 $O(n^3)$；用前缀和把判定降到 $O(1)$ 后仍有 $O(n^2)$。$n = 10^5$ 时 $n^2 = 10^{10}$，远超一秒能完成的 $10^8$ 量级，必然超时。

> 💡 暴力的浪费在于反复枚举「同一个连续段」内部的每个子区间——而它们的共同答案，一次扫描就能顺手记下来。

### 3.2 核心观察：答案 = 被 0 分隔的各段长度的最大值

![0 把数组切成若干段连续 1](images/wc15_q1_segments.svg)

数组里的 $0$ 是天然的分隔符。把每个 $0$ 当成切点，整个数组被切成若干**互不相邻**的块：块内元素全是 $1$，块外紧邻的元素一定是 $0$ 或者数组边界。于是

$$\text{最长连续 1 的长度} = \max_{\text{块}} \text{块长}$$

因为任何一个连续 $1$ 的区间都不可能跨越某个 $0$，它必须完整落在某一个块内；反之每个块本身就是一个合法的连续 $1$ 区间。

这条观察把「求最优区间」降级成了「求极值统计」：不需要记录区间的左右端点，只需要一个计数器 `cur` 记住**当前块已经延伸了多长**，再用 `best` 记住**历史最大值**。

### 3.3 算法流程

![扫描流程：cur 与 best 的更新规则](images/wc15_q1_flow.svg)

1. 初始化 `cur = 0`、`best = 0`。
2. 从左到右遍历 `nums` 的每个元素 $x$：
   - 若 $x = 1$：`cur += 1`，并 `best = max(best, cur)`——段在延伸，答案可能就在此刻刷新；
   - 若 $x = 0$：`cur = 0`——段被打断，此前的长度已经记进 `best`，直接清零。
3. 遍历结束返回 `best`。

**关键点**：`best` 的更新放在「读入 $1$」的分支里，而不是「读入 $0$」的分支里。这样即使数组以 $1$ 结尾（最后一段后面没有 $0$ 触发结算），它的长度也已经在增长的那一刻与 `best` 比较过，**不需要循环之外的收尾补算**。

另一种等价写法是「遇 $0$ 时结算」：

```text
if x == 1: cur += 1
else:      best = max(best, cur); cur = 0
```

它必须在**循环结束之后再补一次** `best = max(best, cur)`，否则示例 1 会错误地返回 2——这是本题最高频的错误。

### 3.4 示例演算

![逐元素走查 cur 与 best](images/wc15_q1_walkthrough.svg)

对 `nums = [1,1,0,1,1,1]`：

| 下标 $i$ | `nums[i]` | `cur` | `best` | 说明 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 1 | 1 | 新段开始，`best` 更新为 1 |
| 1 | 1 | 2 | 2 | 段内继续，`best` 更新为 2 |
| 2 | 0 | 0 | 2 | 段结束，第一段长 2 |
| 3 | 1 | 1 | 2 | 新段开始，`best` 保持 2 |
| 4 | 1 | 2 | 2 | 段内继续，与 `best` 相同 |
| 5 | 1 | 3 | 3 | 段内继续，`best` 刷新为 3 |

返回 `best = 3`，对应下标 $3..5$ 的 `1,1,1`。

## 4. 算法细节

1. **两个计数器足够**：`cur` 是「以当前下标结尾的连续 $1$ 长度」，`best` 是「已扫描部分中连续 $1$ 长度的最大值」，状态总量 $O(1)$，无需数组或栈。
2. **更新位置决定要不要收尾**：`best` 在 $x = 1$ 分支内更新 → 免收尾；在 $x = 0$ 分支内更新 → 必须收尾。选前一种写法，等于用「更新时机」换掉一个易错点。
3. **哨兵法**：在数组末尾想像追加一个 $0$，让最后一段必然被结算。若真去 `nums.push_back(0)` 需要 $O(n)$ 拷贝或 $O(1)$ 摊还但会改动入参；想清楚「补 $0$」只是思维模型即可。
4. **别为了写「一行」构造新对象**：`max(map(len, ''.join(map(str, nums)).split('0')))` 也能 AC，但它构造了 $O(n)$ 的字符串与 $n$ 个小整数对象，Python 在 $10^5$ 规模上比纯循环慢数倍。
5. **传参方式**：C++ 用 `vector<int>&`（或 `const vector<int>&`）避免拷贝；本题只读不写，签名给出的引用形式可直接使用。
6. **可选剪枝**：若 `best` 已等于「`cur` + 剩余元素个数」，后续不可能更长，可提前 `return`。本题 $n \le 10^5$ 不需要，但这是同类扫描题的通用加速手段。

## 5. 正确性证明

**引理 1（`cur` 的语义）**：处理完下标 $i$ 之后，`cur` 恰好等于「以 $i$ 结尾的连续 $1$ 的个数」；特别地，当 $\text{nums}[i] = 0$ 时 `cur = 0`。

**证明**：对 $i$ 归纳，初始 $i = -1$ 时长度视为 $0$，成立。

- 若 $\text{nums}[i] = 1$：以 $i$ 结尾的连续 $1$ 段 = 以 $i-1$ 结尾的连续 $1$ 段再接上 $\text{nums}[i]$，长度 $\text{cur} + 1$，与更新一致；
- 若 $\text{nums}[i] = 0$：以 $i$ 结尾的连续 $1$ 段不含任何元素，长度 $0$，与更新一致。∎

**引理 2（`best` 的上界）**：任意时刻 `best` 的取值都不超过某个连续 $1$ 块的长度（从而不超过最优值 $L^\ast$）。

**证明**：`best` 初值为 $0$，对应空块。此后 `best` 只在 $x = 1$ 分支被赋成 `cur`，由引理 1，`cur` 是以当前位置结尾的连续 $1$ 个数，它所在的块长度一定 $\ge$ `cur`，故该次赋值不超过某个块的长度；而 `max` 只会取两者中的较大值，归纳可知整个过程中 `best` 都不超过某个块长，故 `best ≤ L^\ast`。∎

**引理 3（最优块会被计入）**：设最长块的下标区间为 $[s, e]$、长度 $L$，则算法处理到下标 $e$ 时已有 `best ≥ L`。

**证明**：$s-1$ 处为 $0$ 或 $s = 0$，且 $s..e$ 全为 $1$，由引理 1 处理到 $e$ 时 `cur = e - s + 1 = L`。此时 $x = \text{nums}[e] = 1$，进入 $x = 1$ 分支执行 `best = max(best, cur) ≥ L`。∎

**定理**：算法返回的 `best` 等于数组中最长连续 $1$ 的个数 $L^\ast$。

**证明**：由引理 2 得 `best ≤ L^\ast`；由引理 3，最长块在其右端点处把 `best` 抬到 $L^\ast$，且 `best` 全程单调不减，故结束时 `best ≥ L^\ast`。两式合并得 `best = L^\ast`。若数组中不含 $1$，所有块长为 $0$（$L^\ast = 0$），`best` 保持初值 $0$，同样成立。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，每个元素常数次比较与加法，没有嵌套循环、排序或哈希表操作。
- **空间**：$O(1)$ 额外空间。只用 `cur`、`best` 两个整型变量（不计输入本身占用的内存）。

> 这已经是理论下界：读一遍输入就要 $O(n)$，因此本题不存在更优的渐进算法。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findMaxConsecutiveOnes(vector<int>& nums) {
        int best = 0, cur = 0;
        for (int x : nums) {
            if (x == 1) {
                ++cur;                        // 段在延伸
                if (cur > best) best = cur;   // 顺手刷新历史最大值
            } else {
                cur = 0;                      // 段被打断，长度已入账
            }
        }
        return best;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:
        best = cur = 0
        for x in nums:
            if x == 1:
                cur += 1
                if cur > best:      # 段延伸的同时刷新答案
                    best = cur
            else:
                cur = 0             # 遇到 0，段结束
        return best
```

## 8. 边界情况与易错点

1. **数组以 1 结尾**：如示例 1、`[1,1]`。若 `best` 只在遇 $0$ 时结算且循环外不收尾，示例 1 会返回 2 而不是 3，这是本题最高频的 WA。
2. **全 1 数组**：$10^5$ 个 $1$ → 返回 $10^5$。`cur` 一路增长，用 `int` 足够（$10^5 < 2^{31}-1$），但别把计数器声明成 `char`/`short` 之类窄类型。
3. **全 0 数组**：返回 $0$。`best` 初值必须是 $0$ 而非 $-1$，否则会在无解输入上返回负数。
4. **单个元素**：`[1]` → 1，`[0]` → 0。「先找第一个 1 再向后扩展」的写法容易在 $n = 1$ 且末尾为 $1$ 时越界，本文写法天然安全。
5. **收尾语句的幂等性**：`[1,0]` 中遇 $0$ 时 `best` 已为 1，再算一次 `max(best, cur = 0)` 仍是 1；`max` 幂等，所以「遇 $0$ 结算 + 收尾」两者同时存在也不会算错，只是多余。
6. **不要用字符串/排序技巧**：转成字符串 `split('0')` 会引入 $O(n)$ 额外空间与大量临时对象，在 Python 上常数更差，也失去了 $O(1)$ 空间的优点。
