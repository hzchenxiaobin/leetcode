# LeetCode 最大连续1的个数 II 题解

## 1. 题目概述

- **标题 / 题号**：最大连续1的个数 II（#487，medium）
- **链接**：https://leetcode.cn/problems/max-consecutive-ones-ii/
- **来源**：LeetCode 第 15 场周赛 Q2
- **难度**：中等
- **标签**：数组、动态规划、滑动窗口

**题意**：给定只含 `0` 和 `1` 的数组 `nums`，**最多**允许把其中一个 `0` 翻成 `1`（也可以一次都不翻），求操作之后数组里**连续 `1` 的最长长度**。

**约束**：

- $1 \le \lvert nums \rvert \le 10^4$（长度为正整数，不超过 10000）
- $nums[i] \in \{0, 1\}$
- 翻转次数上限为 1，"至多一次"意味着不翻也是合法方案

> 💡 与 [485. 最大连续1的个数](https://leetcode.cn/problems/max-consecutive-ones/) 的唯一差别就是这条"至多翻一次"。它把"数一段 1"变成"用中间那个 0 把左右两段 1 粘起来"，于是所有候选答案都能用**一个至多含一个 0 的区间**来描述。

## 2. 示例

**示例 1**

```text
输入：nums = [1,0,1,1,0]
输出：4
解释：翻转下标 1 的 0，数组变为 [1,1,1,1,0]，最长连续 1 的长度为 4（只翻下标 4 的 0 只能得到 3）。
```

**示例 2**

```text
输入：nums = [1,0,1,1,0,1]
输出：4
解释：翻转下标 4 的 0，数组变为 [1,0,1,1,1,1]，末尾 4 个 1 连成一段；翻转下标 1 的 0 同样得到长度 4。
```

## 3. 解题思路

### 3.1 暴力思路

枚举"被翻转的那个 `0`"，再向左右两侧扩展数连续 `1`，每个翻点 $O(n)$，共 $O(n^2)$；等价地枚举所有区间 $[i,j]$ 并统计其中 `0` 的个数（三重循环 $O(n^3)$，加前缀和可降到 $O(n^2)$）。

$n = 10^4$ 时 $O(n^2) = 10^8$，Python 必然超时。更关键的是：暴力的浪费在于**同一段连续的 1 被反复扫描**——相邻两个 `0` 之间的那段 `1`，在枚举左右两侧时会被反复数一遍。

### 3.2 核心观察：答案 = 最长"至多含一个 0"的区间

![核心观察：窗口内 0 的个数不超过 1](images/wc15_q2_window_concept.svg)

把"翻转一个 `0`"翻译成区间语言，两个方向都成立：

- **合法 $\Rightarrow$ 可翻**：若区间 $[l,r]$ 内 `0` 的个数 $\le 1$，那么（需要时）把其中那个 `0` 翻成 `1`，整个区间就全是 `1`，贡献长度 $r-l+1$。
- **可翻 $\Rightarrow$ 合法**：任何"翻转一个 `0` 之后得到的连续 `1` 段"，在翻转前只可能比它多一个 `0`（被翻的那个），所以对应原数组的区间内 `0` 的个数 $\le 1$。

两个方向合起来：**答案就是所有"至多含一个 `0`"的区间的最大长度**。这就从"枚举翻哪个 `0`"变成了"维护一个满足约束的最长窗口"——标准滑动窗口。

### 3.3 算法流程

![算法流程：右指针扩张，0 超过 1 个就收缩左指针](images/wc15_q2_window_flow.svg)

维护窗口 $[left, right]$ 与窗口内 `0` 的个数 `zeros`，不变式为 `zeros <= 1`。

1. `right` 从左到右扩张，把 $nums[right]$ 纳入窗口；若它为 `0`，`zeros += 1`。
2. 若 `zeros > 1`（窗口非法），移动 `left` 收缩：当 $nums[left] == 0$ 时先 `zeros -= 1`，再 `left += 1`；重复直到 `zeros <= 1`。
3. 收缩结束后窗口必合法，用 $right - left + 1$ 更新 `ans`。
4. `right` 遍历完毕后返回 `ans`。

关键点是**两层循环的均摊**：`right` 至多右移 $n$ 次，`left` 全程也只右移 $n$ 次且从不回退（因为对固定的 `right`，窗口越短越容易合法，**不需要**把 `left` 往回挪），所以内层 `while` 的总执行次数是 $O(n)$。

### 3.4 示例演算

![示例演算：nums = [1,0,1,1,0,1] 的逐步扩张与收缩](images/wc15_q2_walkthrough.svg)

以 `nums = [1,0,1,1,0,1]`（$n = 6$，预期答案 4）为例：

| right | $nums[right]$ | zeros | left | 窗口 | 长度 | ans |
|-------|---------------|-------|------|------|------|-----|
| 0 | 1 | 0 | 0 | $[0,0]$ | 1 | 1 |
| 1 | 0 | 1 | 0 | $[0,1]$ | 2 | 2 |
| 2 | 1 | 1 | 0 | $[0,2]$ | 3 | 3 |
| 3 | 1 | 1 | 0 | $[0,3]$ | 4 | **4** |
| 4 | 0 | 2 → 1 | 0 → 2 | $[2,4]$ | 3 | 4 |
| 5 | 1 | 1 | 2 | $[2,5]$ | 4 | 4 |

`right = 4` 时窗口 $[0,4]$ 内出现两个 `0`（下标 1 和 4），`left` 必须连走两步跨过下标 1 的 `0`，窗口缩成 $[2,4]$。长度从 4 回落到 3，但 `ans` 仍是 4。最后 `right = 5` 把窗口补到 $[2,5]$，长度再次达到 4，返回 4 —— 对应翻转下标 4 的 `0`。

## 4. 算法细节

1. **不变式先立住**：任何时刻（收缩结束后）`[left, right]` 内 `0` 的个数 $\le 1$。这是"能用一次翻转解决"的充要条件，也是后面证明的基石。
2. **`zeros` 与 `left` 的更新顺序**：必须**先**判断 $nums[left]$ 是否为 `0` 并减计数，**再** `left += 1`。写成 `left += 1` 在前会跳过窗口最左端元素，计数漏减、`zeros` 只增不减，窗口再也收不回去（C++ 里还可能让 `left` 越过右端造成越界）。
3. **为什么用 `while` 而不是 `if`**：一次扩张可能让 `zeros` 从 1 跳到 2，而被跨过的这段里可能夹着好几个 `1`（例如 `[1,1,0,1,1,1,0]` 在 `right = 6` 时 `left` 要从 0 连走到 3），只收缩一步恢复不了"窗口内 `0` 的个数 $\le 1$"的不变式。把 `while` 改成 `if` 是常见的"不收缩"技巧：窗口长度只在合法的那一步才增长，非法时 `left` 的同一步右移抵消了 `right` 的扩张，长度不涨，`ans` 早已记下历史最优，所以答案依然正确——但此时窗口内可能残留两个 `0`，`right - left + 1` 不再等于"合法长度"，语义被破坏。本题 `while` 的均摊开销极小，建议保留 `while`，让不变式始终成立。
4. **等价的状态机（DP）视角**：设 $a_i$ 为"以 $i$ 结尾、**没有**用过翻转的最长连续 `1`"，$b_i$ 为"以 $i$ 结尾、**至多**用过一次翻转的最长连续 `1`"，则

   $$a_i = \begin{cases} a_{i-1} + 1, & nums[i] = 1 \\ 0, & nums[i] = 0 \end{cases} \qquad b_i = \begin{cases} b_{i-1} + 1, & nums[i] = 1 \\ a_{i-1} + 1, & nums[i] = 0 \end{cases}$$

   答案 $= \max_i b_i$（约定 $a_{-1} = b_{-1} = 0$）。$b_i$ 天然 $\ge a_i$，且全 `1` 数组不会多算，**无需任何 `min` 兜底**。
5. **为什么这个 DP 值得写**：它只需要 $a, b$ 两个滚动变量，空间 $O(1)$ 且**不依赖 `nums[left]` 的历史元素**，正好回答题目的 Follow-up ——输入是无限流时滑动窗口无法回看 `left` 处元素，而状态机可以边走边算。
6. **答案更新时机**：必须在收缩循环**之后**更新 `ans`。若在扩张后立刻更新，会拿非法窗口的长度（如 `right = 4` 时的 5）去比较，直接算错。
7. **C++ 传参**：按官方签名 `int findMaxConsecutiveOnes(vector<int>& nums)` 用引用，避免 $10^4$ 个元素的无谓拷贝；`ans` 初值取 0 即可，因为"至少一个元素"保证答案 $\ge 1$。

## 5. 正确性证明

**引理 1（合法窗口可一次翻转成全 1）**：若区间 $[l,r]$ 内 `0` 的个数 $\le 1$，则只需翻转其中至多一个 `0`，$[l,r]$ 内所有元素都能变成 `1`。

**证明**：设区间内 `0` 的个数为 $c \le 1$。若 $c = 0$，无需翻转；若 $c = 1$，翻转该唯一 `0`，翻转次数恰为 1，区间内不再有 `0`。两种情形翻转次数都不超过 1，故可行。∎

**引理 2（可翻成的连续 1 段必来自合法窗口）**：若翻转至多一个 `0` 后存在长度为 $L$ 的连续 `1` 段，则该段在翻转前对应的原数组区间内 `0` 的个数 $\le 1$。

**证明**：翻转操作只改变一个位置。设翻转后该连续 `1` 段占据原数组区间 $[l,r]$。区间内翻转后全是 `1`，说明翻转前这些位置只能是 `1`，或恰好是那一个被翻的 `0`；翻转次数 $\le 1$ 意味着这样的位置至多一个。故区间内原值中 `0` 的个数 $\le 1$。∎

**引理 3（贪婪收缩不漏解）**：对每个 `right`，收缩循环结束后 `left` 是使 $[left, right]$ 内 `0` 的个数 $\le 1$ 的**最小**下标。

**证明**：循环仅在 `zeros > 1` 时右移 `left`，退出时 `zeros <= 1`，故 $[left, right]$ 合法。若 `left > 0`，则说明上一次移动前窗口为 $[left-1, right]$ 且其中 `0` 的个数 $\ge 2$；而任何 $l' < left$ 都满足 $[l', right] \supseteq [left-1, right]$，其 `0` 的个数只会更多，同样 $\ge 2$，均不合法。因此 `left` 是最小合法左端点。∎

**定理**：算法返回的 `ans` 等于"至多翻转一个 `0` 后最长连续 `1` 的长度"。

**证明**：记最优值为 $OPT$。由引理 3，每个 `right` 处算法考察的窗口都是合法窗口，其长度由引理 1 可通过至多一次翻转变成全 `1`，故 `ans` $\le OPT$。另一方面，设最优方案对应的区间为 $[l^*, r^*]$，长度 $OPT$；由引理 2 该区间合法。考察 $right = r^*$ 这一轮：由引理 3，算法的 `left` 是此时最小的合法左端点，故 `left` $\le l^*$，从而本轮窗口长度 $r^* - left + 1 \ge OPT$；又长度不可能超过 $OPT$（否则该窗口本身就给出更优解），所以本轮长度恰为 $OPT$，`ans` $\ge OPT$。两个方向合起来 `ans` $= OPT$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`right` 从左到右各访问一次，共 $n$ 次；`left` 单调右移，全程总移动次数不超过 $n$，内层 `while` 的累计开销因此是 $O(n)$；每次迭代的计数与比较都是 $O(1)$。总计 $O(n)$，均摊到每个元素是常数次操作。
- **空间**：$O(1)$。只用了 `left`、`zeros`、`ans` 三个整型变量，没有额外数组或哈希表；输入本身不计入空间。状态机写法同样只用 $a, b, ans$ 三个变量。
- **对比**：暴力 $O(n^2)$ 在 $n = 10^4$ 时就已是 $10^8$ 次操作，Python 基本跑不完；滑窗把常数压到"每元素两次判断"，本机实测 $n = 10^6$ 的随机输入：C++ 约 0.1 s、Python 约 0.3 s（含解释器启动），比题目上限 $10^4$ 还大两个数量级，仍远在时限之内。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findMaxConsecutiveOnes(vector<int>& nums) {
        int n = (int)nums.size();
        int left = 0, zeros = 0, ans = 0;
        for (int right = 0; right < n; ++right) {
            if (nums[right] == 0) ++zeros;      // 右端纳入窗口
            while (zeros > 1) {                 // 窗口非法：收缩
                if (nums[left] == 0) --zeros;   // 先减计数
                ++left;                         // 再移动左指针
            }
            ans = max(ans, right - left + 1);   // 收缩后才能取长度
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findMaxConsecutiveOnes(self, nums: List[int]) -> int:
        left = 0
        zeros = 0
        ans = 0
        for right, x in enumerate(nums):
            if x == 0:
                zeros += 1          # 右端纳入窗口
            while zeros > 1:        # 窗口非法：收缩
                if nums[left] == 0:
                    zeros -= 1      # 先减计数
                left += 1           # 再移动左指针
            ans = max(ans, right - left + 1)  # 收缩后才能取长度
        return ans
```

## 8. 边界情况与易错点

1. **全为 `1`**：`zeros` 恒为 0，从不收缩，`ans = n`。注意此时"翻转"是空操作，不要画蛇添足地写 `ans = min(ans, n)` 之类的补丁（滑窗写法本来就不会多算；只有 `prev/cur + 1` 的写法才需要那个 `min`）。
2. **全为 `0`**：扩张后窗口内至多出现 2 个 `0`，收缩一次即回到 1，窗口长度恒为 1，答案 1 —— 即翻转其中一个 `0`。
3. **长度为 1**：`[1]` 返回 1（不翻），`[0]` 返回 1（翻它），都无需特判。
4. **计数与移动顺序**：`if (nums[left] == 0) --zeros; ++left;` 顺序不能反。写成先 `++left` 再减计数，窗口最左端那个 `0` 就被永久跳过，`zeros` 只增不减；在 400 余组随机小数据（长度 $\le 12$）上有 144 组直接算错。
5. **更新 `ans` 的位置**：只能在收缩循环之后。放在扩张后会把 `zeros = 2` 的非法窗口计入答案，例如 `[0,0]` 会输出 2（正确为 1）。
6. **"至多"还是"恰好"**：本题是至多。若改成"恰好翻一次"，全 `1` 数组就无解（没有 `0` 可翻），必须单独返回 0 或按题意约定处理——这正是"至多"与"恰好"的分水岭。
7. **输入是流（Follow-up）**：滑动窗口需要回看 $nums[left]$，流式输入下不可行；此时应换成第 4 节的状态机写法，只保留 $a, b, ans$ 三个变量。

**延伸思考**：

1. **流式输入**（题目 Follow-up）：由于无法存储整个数组，也无法回看 `left`，滑窗失效；而第 4 节的状态机只需 $O(1)$ 空间，代码就是

   ```python
   def stream_answer(nums):      # 输入可以是生成器，无法索引
       a = b = ans = 0           # a：未用翻转；b：至多翻一次
       for x in nums:
           if x == 1:
               a += 1
               b += 1
           else:
               b = a + 1         # 把翻转机会用在这个 0 上
               a = 0
           ans = max(ans, b)
       return ans
   ```

2. **恰好翻转一次**：额外维护 $c_i$ ——"以 $i$ 结尾、**恰好**用掉一次翻转的长度"：$x_i = 1$ 且 $c_{i-1} > 0$ 时 $c_i = c_{i-1} + 1$，$x_i = 0$ 时 $c_i = a_{i-1} + 1$，答案取 $\max_i c_i$；全 `1` 数组没有 `0` 可翻，此时需特判。
3. **同时统计方案数**：把 `max` 换成"记录最优窗口的左端点"，可以顺便数出有多少个不同的 `0` 能作为翻点达成最优长度（本题示例 2 的两个 `0` 都能把长度凑到 4）。
