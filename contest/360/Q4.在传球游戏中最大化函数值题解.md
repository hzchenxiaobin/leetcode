# LeetCode 在传球游戏中最大化函数值 题解

## 1. 题目概述

- **标题 / 题号**：在传球游戏中最大化函数值（#2836，hard）
- **链接**：https://leetcode.cn/problems/maximize-value-of-function-in-a-ball-passing-game/
- **来源**：LeetCode 第 360 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、动态规划（倍增）

**题意**：给定长度为 $n$ 的数组 $\text{receiver}$ 与整数 $k$。$n$ 名玩家玩传球：编号 $i$ 的玩家永远把球传给编号 $\text{receiver}[i]$ 的玩家（可以传给自己）。你选择一名起点玩家 $x$，球被传**恰好** $k$ 次，定义

$$f(x) = x + \text{receiver}[x] + \text{receiver}[\text{receiver}[x]] + \cdots + \text{receiver}^{(k)}[x]，$$

即从 $x$ 出发共 $k+1$ 个持球人的编号之和（同一玩家多次触球则**累加多次**）。返回 $\max\limits_{x} f(x)$。

**约束**：

- $1 \le n \le 10^5$
- $0 \le \text{receiver}[i] \le n - 1$
- $1 \le k \le 10^{10}$

> ⚠️ $k$ 高达 $10^{10}$：逐次模拟单条路线就要 $10^{10}$ 步，对 $n$ 个起点更是 $O(nk) = 10^{15}$——必须把「走 $k$ 步」压缩成「跳若干个 $2^j$ 步」。

## 2. 示例

**示例 1**

```text
输入：receiver = [2,0,1], k = 4
输出：6
解释：从 x = 2 出发，持球人依次为 2 → 1 → 0 → 2 → 1（含起点共 5 个落脚点），
      f(2) = 2 + 1 + 0 + 2 + 1 = 6，为所有起点中的最大值。
```

**示例 2**

```text
输入：receiver = [1,1,1,2,3], k = 3
输出：10
解释：从 x = 4 出发，持球人依次为 4 → 3 → 2 → 1，
      f(4) = 4 + 3 + 2 + 1 = 10。注意最优起点 4 不在任何环上。
```

## 3. 解题思路

### 3.1 暴力思路

对每个起点 $x$ 直接模拟 $k$ 次传球并累加：时间 $O(nk)$。$n = 10^5$、$k = 10^{10}$ 时约 $10^{15}$ 次操作，哪怕只算**一个**起点也要 $10^{10}$ 步，必然超时。

路线确实很快进环、之后周期性重复——「尾巴 + 整圈等差 + 余数前缀」的基环分解做法可以做到 $O(n)$，但要按「尾巴长度、环长、余数」分三种情况讨论，分支多、易写错（见「相关题目与扩展」）。这里选择更统一的武器：**倍增**。

### 3.2 核心观察：出度恒为 1 的路线唯一 + 倍增跳表

![内向基环森林的尾巴加环结构](images/wc360_q4_functional_graph.svg)

每个玩家恰有一个传球目标，即图中每个点**出度恰为 1**——这是一张**内向基环森林**：从任意 $x$ 出发的传球路线唯一，形如希腊字母 $\rho$（先走一段尾巴，再绕某个环不停转圈）。因此 $f(x)$ 完全由「这条唯一路线上 $k+1$ 个落脚点的编号」决定，与从哪个 $x$ 出发无关的干扰不存在——问题只剩「如何快速算出一条 $\rho$ 路径上 $k+1$ 个落脚点之和」。

$k$ 巨大但**二进制只有约 34 位**：若能一步跳 $2^j$ 步并顺便拿到沿途编号和，$k$ 步就能拆成至多 34 次大跳。为此预处理两张表（$L = \lceil \log_2(k+1) \rceil \le 34$ 层，下标 $j = 0 \ldots L-1$）：

- $\text{nxt}[j][i]$：从 $i$ 出发连跳 $2^j$ 步后的**落点**；
- $\text{sum}[j][i]$：从 $i$ 出发的 $2^j$ 个落脚点（**含 $i$ 自己**，即时刻 $t = 0 \ldots 2^j-1$）的**编号和**。

![倍增表的递推结构](images/wc360_q4_binary_lifting.svg)

递推口诀「**两段拼接，和相加，落点接力**」：

$$\text{nxt}[0][i] = \text{receiver}[i], \qquad \text{sum}[0][i] = i,$$

$$\text{nxt}[j][i] = \text{nxt}[j-1][\text{nxt}[j-1][i]], \qquad \text{sum}[j][i] = \text{sum}[j-1][i] + \text{sum}[j-1][\text{nxt}[j-1][i]].$$

> 💡 **一句话总结**：路线唯一（基环森林）+ $k$ 的二进制只有 34 位（倍增）——一张 $O(n \log k)$ 的跳表把「逐步传球」变成「至多 34 次查询」。

### 3.3 算法流程：按 $k$ 的二进制位拼接路径

![按二进制位查询的流程](images/wc360_q4_query_decomposition.svg)

1. **建表**：如上递推出 $j = 0 \ldots L-1$ 的 $\text{nxt}$、$\text{sum}$，其中 $L$ 取满足 $2^L > k$ 的最小值（$k \le 10^{10} < 2^{34}$，故 $L \le 34$）。
2. **查询**：对每个起点 $x$，令 $\text{cur} = x$、$\text{ans} = 0$，从低位到高位枚举 $k$ 的二进制位 $j$：若该位为 1，则 $\text{ans} \mathrel{+}= \text{sum}[j][\text{cur}]$、$\text{cur} = \text{nxt}[j][\text{cur}]$；处理完全部位后 $\text{ans} \mathrel{+}= \text{cur}$（补上第 $k$ 次传球后的落点）。此时 $\text{ans} = f(x)$。
3. **汇总**：答案为所有 $x$ 中 $f(x)$ 的最大值。

### 3.4 示例演算

![示例一的完整演算](images/wc360_q4_example_walkthrough.svg)

以示例 1（$\text{receiver} = [2,0,1]$，$k = 4$，$x = 2$）为例。三张表（$n=3$）：

| $j$ | $\text{sum}[j]$ | $\text{nxt}[j]$ |
|-----|-----------------|-----------------|
| 0 | $[0, 1, 2]$ | $[2, 0, 1]$ |
| 1 | $[2, 1, 3]$ | $[1, 2, 0]$ |
| 2 | $[3, 4, 5]$ | $[2, 0, 1]$ |

$k = 4 = 100_2$：只有第 2 位是 1，故 $\text{ans} \mathrel{+}= \text{sum}[2][2] = 5$（覆盖时刻 $0 \ldots 3$，即 $2+1+0+2$），$\text{cur} = \text{nxt}[2][2] = 1$；最后 $\text{ans} \mathrel{+}= \text{cur} = 1$（时刻 4 的落点），得 $f(2) = 6$ ✓。

示例 2（$k = 3 = 11_2$，$x = 4$）：第 0 位 → $\text{ans} \mathrel{+}= \text{sum}[0][4] = 4$，$\text{cur} = 3$；第 1 位 → $\text{ans} \mathrel{+}= \text{sum}[1][3] = 3 + 2 = 5$，$\text{cur} = \text{nxt}[0][\text{nxt}[0][3]] = 1$；最后 $\text{ans} \mathrel{+}= 1$，$f(4) = 10$ ✓。

## 4. 算法细节

1. **层数 $L$ 的求法**：需覆盖 $k$ 的最高位，即 $2^{L-1} \le k < 2^L$。C++ 写 `while ((1LL << L) <= k) L++;`——**必须 `1LL`**，`1 << 33` 在 32 位 `int` 上是未定义行为。Python 直接 `k.bit_length()`。
2. **两张表的类型**：落点值 $< n \le 10^5$，$\text{nxt}$ 用 `int`（$34 \times 10^5 \times 4\text{B} \approx 13.6\text{MB}$）；和最大约 $10^{15}$，$\text{sum}$ 用 `long long`（约 $27.2\text{MB}$）。合计约 $41\text{MB}$，内存无忧。
3. **「含起点」的约定**：$\text{sum}[j][i]$ 从 $i$ 自己数起（$\text{sum}[0][i] = i$），因此查询时被跳过的时段恰好从「当前落点」开始无缝衔接；循环结束后**必须补 $\text{ans} + \mathrel{+} \text{cur}$**——它是第 $k$ 次传球后的持球人，只出现在落点表里、不在任何 $\text{sum}$ 时段内。
4. **位处理顺序无关紧要**：从低位或高位开始都对——各位对应的时段 $[0,2^j)$ 平移后不重不漏地铺满 $[0, k)$，与拼接顺序无关（证明见 §5 定理 1）。从低位写循环最短。
5. **溢出界**：$f(x) \le (k+1)(n-1) < (10^{10}+1) \times 10^5 \approx 1.0 \times 10^{15} \ll 2^{63}-1 \approx 9.2 \times 10^{18}$，`long long` 全程安全，但 `int` 必然溢出。
6. **Python 实现按位向量化**：对每个二进制位用列表推导同时推进全部 $n$ 个起点，避免 $n \times 34$ 次 Python 级循环；C++ 则直接逐起点查询。

## 5. 正确性证明

约定 $p(i, 0) = i$、$p(i, t+1) = \text{receiver}[p(i, t)]$，则 $f(x) = \sum_{t=0}^{k} p(x, t)$。

**引理 1**（复合结合律）：对任意非负整数 $a, b$，$p(p(i, a), b) = p(i, a+b)$。

**证明**：对 $b$ 归纳。$b = 0$ 时两侧均为 $p(i, a)$。设对 $b$ 成立，则
$$p(p(i,a),\, b+1) = \text{receiver}\big[p(p(i,a),\, b)\big] = \text{receiver}\big[p(i,\, a+b)\big] = p(i,\, a+b+1). \; ∎$$

**引理 2**（倍增表刻画）：对一切 $j \ge 0$ 与 $i \in [0, n)$，$\text{nxt}[j][i] = p(i, 2^j)$，$\text{sum}[j][i] = \sum_{t=0}^{2^j - 1} p(i, t)$。

**证明**：对 $j$ 归纳。$j = 0$：$\text{nxt}[0][i] = \text{receiver}[i] = p(i, 1) = p(i, 2^0)$，$\text{sum}[0][i] = i = p(i, 0)$。设对 $j-1$ 成立，记 $\text{mid} = \text{nxt}[j-1][i]$，由归纳假设 $\text{mid} = p(i, 2^{j-1})$，则

$$\text{nxt}[j][i] = \text{nxt}[j-1][\text{mid}] \overset{\text{IH}}{=} p(\text{mid},\, 2^{j-1}) \overset{\text{引理1}}{=} p(i,\, 2^{j-1} + 2^{j-1}) = p(i, 2^j),$$

$$\text{sum}[j][i] = \text{sum}[j-1][i] + \text{sum}[j-1][\text{mid}] \overset{\text{IH}}{=} \sum_{t=0}^{2^{j-1}-1} p(i,t) + \sum_{t=0}^{2^{j-1}-1} p(\text{mid}, t) \overset{\text{引理1}}{=} \sum_{t=0}^{2^{j-1}-1} p(i,t) + \sum_{t=2^{j-1}}^{2^j-1} p(i,t) = \sum_{t=0}^{2^j-1} p(i,t). \; ∎$$

**定理 1**（查询正确性）：查询循环结束时 $\text{ans} = \sum_{t=0}^{k-1} p(x, t)$ 且 $\text{cur} = p(x, k)$，从而 $\text{ans} + \text{cur} = f(x)$。

**证明**：对已处理位数 $d$ 归纳，断言「处理完第 $0 \ldots d-1$ 位后，$\text{cur} = p(x,\, k \bmod 2^d)$，$\text{ans} = \sum_{t=0}^{(k \bmod 2^d) - 1} p(x, t)$」。

- $d = 0$：$k \bmod 1 = 0$，$\text{cur} = x = p(x, 0)$，$\text{ans} = 0$（空和）。
- 设对 $d$ 成立，处理第 $d$ 位。记 $c = k \bmod 2^d$。若该位为 0，则 $k \bmod 2^{d+1} = c$，状态不变。若该位为 1，则 $k \bmod 2^{d+1} = c + 2^d$，且由引理 2：

$$\text{ans}' = \text{ans} + \text{sum}[d][\text{cur}] = \sum_{t=0}^{c-1} p(x,t) + \sum_{t=0}^{2^d-1} p(\text{cur}, t) \overset{\text{引理1}}{=} \sum_{t=0}^{c-1} p(x,t) + \sum_{t=c}^{c+2^d-1} p(x,t) = \sum_{t=0}^{c+2^d-1} p(x,t),$$

$$\text{cur}' = \text{nxt}[d][\text{cur}] \overset{\text{引理2}}{=} p(\text{cur},\, 2^d) \overset{\text{引理1}}{=} p(x,\, c + 2^d).$$

循环在 $d = L$ 时结束（$k < 2^L$），故 $k \bmod 2^L = k$：$\text{ans} = \sum_{t=0}^{k-1} p(x, t)$、$\text{cur} = p(x, k)$，相加即 $f(x)$。∎

**定理 2**（整体正确性）：算法返回 $\max_{x \in [0, n)} f(x)$。

**证明**：由定理 1，对每个起点 $x$ 算得的恰是题面定义的 $f(x)$；算法遍历全部 $n$ 个候选并取最大值，而最优起点由定义必在 $[0, n)$ 中。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log k)$。建表 $L$ 层、每层 $O(n)$；$n$ 个起点各查询 $O(L)$；$L \le 34$，总计约 $2 \times 3.4 \times 10^6$ 次基本操作。
- **空间复杂度**：$O(n \log k)$。$\text{nxt}$（`int`）约 $13.6\text{MB}$ + $\text{sum}$（`long long`）约 $27.2\text{MB} \approx 41\text{MB}$。

（对比：暴力 $O(nk) = 10^{15}$；基环分解可到 $O(n)$，但以三倍代码量与大量分支为代价——倍增用乘一个 $\log$ 换来了「建一张表、查 34 位」的极简实现。）

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long getMaxFunctionValue(vector<int>& receiver, long long k) {
        int n = receiver.size();
        int L = 0;
        while ((1LL << L) <= k) L++;   // 2^(L-1) <= k < 2^L，L <= 34

        vector<vector<int>> nxt(L, vector<int>(n));
        vector<vector<long long>> sum(L, vector<long long>(n));
        for (int i = 0; i < n; i++) {
            nxt[0][i] = receiver[i];
            sum[0][i] = i;             // 含起点自己
        }
        for (int j = 1; j < L; j++) {
            for (int i = 0; i < n; i++) {
                int mid = nxt[j - 1][i];
                nxt[j][i] = nxt[j - 1][mid];
                sum[j][i] = sum[j - 1][i] + sum[j - 1][mid];
            }
        }

        long long ans = 0;
        for (int x = 0; x < n; x++) {
            long long f = 0;
            int cur = x;
            long long rest = k;
            for (int j = 0; rest > 0; j++, rest >>= 1) {
                if (rest & 1) {
                    f += sum[j][cur];
                    cur = nxt[j][cur];
                }
            }
            f += cur;                  // 补上第 k 次传球后的落点
            ans = max(ans, f);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getMaxFunctionValue(self, receiver: List[int], k: int) -> int:
        n = len(receiver)
        L = k.bit_length()

        nxt = [receiver]
        s = [list(range(n))]
        for j in range(1, L):
            p, sp = nxt[-1], s[-1]
            nxt.append([p[p[i]] for i in range(n)])
            s.append([sp[i] + sp[p[i]] for i in range(n)])

        # 按位向量化：同时推进全部 n 个起点，f 为已覆盖时段的和，cur 为当前落点
        f = [0] * n
        cur = list(range(n))
        for j in range(L):
            if (k >> j) & 1:
                sj, pj = s[j], nxt[j]
                f = [fv + sj[c] for fv, c in zip(f, cur)]
                cur = [pj[c] for c in cur]
        return max(fv + c for fv, c in zip(f, cur))
```

## 8. 边界情况与易错点

1. **末尾漏加落点**（最高频错误）：循环结束只累计了时刻 $0 \ldots k-1$，第 $k$ 次传球后的持球人 $\text{cur}$ 必须单独加上，否则 $f(x)$ 少一项。
2. **`sum` 的约定别混用**：本文 $\text{sum}[j][i]$ **含起点**（$\text{sum}[0][i] = i$）；若改用「不含起点、含末点」的约定，则开头要 $f \mathrel{+}= x$ 而结尾不补——两种写法都对，混搭必错。
3. **层数计算用 `1LL`**：`1 << 33` 在 32 位 `int` 上溢出（UB）；$k \le 10^{10}$ 需要 $j$ 覆盖到 33，共 34 层。
4. **`long long` 全程**：$f$ 最大约 $1.0 \times 10^{15}$，C++ 返回值、累加器、`sum` 表都必须 64 位；Python 天然安全。
5. **枚举所有起点**：最优 $x$ 可能在尾巴上（示例 2 的 $x = 4$ 不在任何环上），不能只试环上的点或入度为 0 的点。
6. **自环与重复值**：$\text{receiver}[i] = i$（示例 2 的玩家 1）与重复元素被倍增递推天然覆盖，无需特判。
7. **内存**：两张表合计约 41MB；$\text{nxt}$ 用 `int` 即可（落点 $< 10^5$），全部用 `long long` 则翻倍到 68MB，虽能过但浪费。
8. **$k = 1$ 最小情形**：$L = 1$，只有第 0 层表，$f(x) = x + \text{receiver}[x]$，公式自然退化正确。

**延伸思考**：

- **基环分解 $O(n)$ 做法**：显式找环、环上做前缀和，整圈贡献用等差数列、余数段用前缀和——省掉一个 $\log$，但要分「$k$ 小于尾巴长」「整圈数」「余数」三种情况，细节远多于倍增；周赛场景下倍增的性价比更高。
- **$k$ 放大到 $10^{18}$**：$L \le 60$，模板原样适用，时间仍是 $O(n \log k)$。
- **在线多次询问** $(x, k)$：倍增表建一次，每次询问 $O(\log k)$——这正是倍增相对基环分解的额外优势（后者需另设计前缀和查询）。
- **改为最小化 $f(x)$**：编号非负，把 `max` 换成 `min` 即可，正确性证明逐字不变。
