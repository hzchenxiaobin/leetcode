# LeetCode 使子序列的和等于目标的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使子序列的和等于目标的最少操作次数（#2835，hard）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-form-subsequence-with-target-sum/
- **来源**：LeetCode 第 360 场周赛 Q3
- **难度**：困难
- **标签**：贪心、位运算、数组

**题意**：给定数组 $\text{nums}$，其中每个元素都是 **2 的幂**，再给定整数 $\text{target}$。一次操作可以选择某个 $\text{nums}[i] > 1$，将其删除，并在数组**末尾**追加**两个** $\text{nums}[i] / 2$。目标是让 $\text{nums}$ 的某个**子序列**的元素和恰好等于 $\text{target}$，求最少操作次数；无法达成返回 $-1$。

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $1 \le \text{nums}[i] \le 2^{30}$，且均为 2 的幂
- $1 \le \text{target} < 2^{31}$

> ⚠️ 总和最大约 $1000 \times 2^{30} \approx 1.07 \times 10^{12}$：若真把元素一路拆成 $1$，数组长度会膨胀到 $2^{40}$ 量级——**绝不能显式模拟数组**，必须把整个问题搬到「二进制位」的账本上做。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,8], target = 7
输出：1
解释：拆 8 → [1,2,4,4]，取子序列 [1,2,4]，和为 7。
```

**示例 2**

```text
输入：nums = [1,32,1,2], target = 12
输出：2
解释：拆 32 → 16+16，再拆 16 → 8+8，数组变为 [1,1,2,16,8,8]，
      取子序列 [1,1,2,8]，和为 12。
```

**示例 3**

```text
输入：nums = [1,32,1], target = 35
输出：-1
解释：总和 34 < 35，无论怎么拆都不可能凑出 35。
```

## 3. 解题思路

### 3.1 暴力思路

把「拆分过程」当状态空间搜索：状态是当前数组的多重集，每次操作把一片 $2^t$ 换成两片 $2^{t-1}$，终态判定为「存在和为 target 的子序列」。但状态数是总和 $S$ 的**二进制拆分数**，$S$ 可达 $2^{40}$，状态空间指数爆炸；反向枚举 target 的全部二进制拆分同样是指数级。必须利用「元素全是 2 的幂、只能大拆小」的结构。

### 3.2 核心观察：层级货架 + 低位优先的「竖式借位」

![核心观察：层级计数与链式借位](images/wc360_q3_concept_model.svg)

**观察 1（可行性一步判出）**：操作把一片 $2^t$ 换成两片 $2^{t-1}$，**数组总和不变**；而子序列和不超过总和。故 $\sum \text{nums} < \text{target}$ 当且仅当无解（引理 1）。反之只要总和够，一定有解。

**观察 2（按层级记账）**：所有元素都是 2 的幂，天然按「层级」分桶：$cnt[b]$ 记值为 $2^b$ 的元素个数。整个问题与元素顺序无关，只与 $cnt[\cdot]$ 有关。

**观察 3（借位 = 链式拆分）**：要从一片 $2^j$ 中拆出一片 $2^b$，最省的做法是**只沿一条链往下拆**（每次只继续拆包含目标的那一半），代价恰为层级差 $j - b$；且沿途每层都白送一片副产物 $2^t$（$t = b, \ldots, j-1$），这些副产物回账本后还能被更高位继续白嫖（引理 2）。

**观察 4（免费配对）**：子序列里同时选中两片 $2^b$，效果等同一片 $2^{b+1}$，**零操作**。于是账本上每层剩下的片可两两配对「虚拟升级」到上一层；奇数片多余的单片对高位毫无用处（引理 3）。

> 💡 **一句话总结**：把需求（target 的二进制位）与供给（层级货架）做**竖式对齐**，从低位到高位逐位结算——**能白嫖就白嫖，不能就向最近的高层借，借的代价只是层级差，副产物还全额退款**。

### 3.3 算法流程：逐位扫描（白嫖 → 借位 → 配对进位）

![贪心算法流程：逐位白嫖、借位与配对进位](images/wc360_q3_greedy_flow.svg)

1. **特判**：若 $\sum \text{nums} < \text{target}$，返回 $-1$。
2. **建账**：统计 $cnt[b]$（值为 $2^b$ 的元素个数）。
3. **逐位结算**：对 $b = 0, 1, \ldots, 31$：
   - 若 target 第 $b$ 位为 $1$：
     - **白嫖**：若 $cnt[b] > 0$（含配对出的虚拟片），直接 $cnt[b] \mathrel{-}= 1$；
     - **借位**：否则找最小的 $j > b$ 使 $cnt[j] > 0$，令 $\text{ans} \mathrel{+}= j - b$，$cnt[j] \mathrel{-}= 1$，并给 $cnt[b], cnt[b+1], \ldots, cnt[j-1]$ 各 $+1$（链式副产物入账），再 $cnt[b] \mathrel{-}= 1$。
   - **配对进位**：$cnt[b+1] \mathrel{+}= \lfloor cnt[b] / 2 \rfloor$（两片剩余 $2^b$ 顶一片虚拟 $2^{b+1}$；奇数片弃账）。
4. 输出 $\text{ans}$。

### 3.4 示例演算

![示例二的逐位演算](images/wc360_q3_example_walkthrough.svg)

以示例 2（$\text{nums} = [1,32,1,2]$，$\text{target} = 12 = 1100_2$）为例，初始账本 $cnt[0]=2$、$cnt[1]=1$、$cnt[5]=1$：

| 位 $b$ | target 位 | 决策前 $cnt[b]$ | 动作 | 代价 | 配对进位 |
|-------|-----------|----------------|------|------|----------|
| 0 | 0 | 2 | 不动用 | 0 | 两个 $1$ → 虚拟 $2$ 入层 1 |
| 1 | 0 | 2（1 真 + 1 虚） | 不动用 | 0 | 虚拟 $2$ + 真实 $2$ → 虚拟 $4$ 入层 2 |
| 2 | 1 | 1（虚拟 $4$） | 白嫖 $= 1+1+2$ | 0 | 层 2 清零 |
| 3 | 1 | 0 | 向层 5 借：$32 \to 16+16 \to 8+8$ | $+2$ | 副产物 $16$、$8$ 入账，$8$ 被拿走 |

总代价 $2$，最终子序列 $\{1, 1, 2, 8\}$，和恰为 $12$ ✓——与官方解释完全一致。注意两个精妙之处：位 2 的需求被「三片小元素免费拼出」，位 3 借位时拆出的第二片 $8$ 与 $16$ 全部入账不浪费。

## 4. 算法细节

1. **$-1$ 判据前置**：`total` 必须用 64 位（C++ `long long`）：$1000 \times 2^{30} \approx 1.07 \times 10^{12}$，32 位 `int` 必溢出。
2. **层级编号**：$x$ 是 2 的幂，层级 = 末尾 0 的个数：C++ 用 `__builtin_ctz(x)`，Python 用 `x.bit_length() - 1`。
3. **副产物按「每层一片」入账（最大易错点）**：借位时应执行 `cnt[t] += 1 (t = b … j−1)`，而**不是** `cnt[b] += 2^(j−b)`。后者对应「整棵拆光」，代价是 $2^{j-b} - 1$，远大于链式的 $j - b$。例如 $[16], \text{target}=15$：链式拆 $16 \to 8 \to 4 \to 2 \to 1$ 花 $4$ 次，沿途副产物 $8+4+2$ 连同 $1$ 恰好凑出 $15$；若拆成 $16$ 个 $1$ 再挑 $15$ 个，要花 $15$ 次。
4. **配对进位每层都做**：无论该位是否置位，结算完都要 `cnt[b+1] += cnt[b] / 2`。它建模的是「两片小元素在子序列里同时被选中」这一零成本组合，漏掉会凭空多付借位费（示例 2 的位 2 正是靠它白嫖）。
5. **借位的 $j$ 一定存在（质量不变式）**：处理完位 $b$ 后，剩余可用总质量仍 $\ge$ 剩余需求，且剩余需求是 $2^{b+1}$ 的倍数、账面质量对齐后也满足同样的整除性（引理 3），故向上扫描必然命中非空层。理论上 $j \le 30$（元素最大 $2^{30}$），`cnt` 仍建议开 $40$ 格做防御。
6. **循环上界 32**：$\text{target} < 2^{31}$，位 $0 \ldots 30$ 覆盖全部需求；跑满 $b < 32$ 是为了统一处理。

## 5. 正确性证明

**引理 1（可行性判据）**：存在方案使某子序列和为 $\text{target}$ $\iff$ $\sum \text{nums} \ge \text{target}$。

**证明**：（$\Rightarrow$）每次操作把一片 $2^t$ 换成两片 $2^{t-1}$，数组总和不变；子序列和不超过数组总和，故总和 $\ge \text{target}$ 是必要条件。（$\Leftarrow$）把所有元素完全拆成 $1$，得到 $\sum \text{nums} \ge \text{target}$ 个 $1$，任取 $\text{target}$ 个即得和为 $\text{target}$ 的子序列。∎

**引理 2（链式拆分的最小代价）**：设 $j > b \ge 0$。要从一片 $2^j$ 中拆出一片 $2^b$，至少需要 $j - b$ 次操作；且 $j-b$ 次可以做到——沿一条链每次只继续拆「包含目标的那一半」。此时副产物恰为 $t = b, b+1, \ldots, j-1$ **每层一片** $2^t$。

**证明**：把 $2^j$ 的拆分过程看成二叉树：根为 $2^j$，每次操作把一个叶 $2^t$ 替换为两个 $2^{t-1}$ 叶。一片值为 $2^b$ 的叶深度为 $j-b$，而根到该叶路径上的 $j-b$ 条边由 $j-b$ 次**互不相同**的操作产生（一次操作只在一个结点下方新增两条边），故操作数 $\ge j - b$。链式拆分逐层推进目标链，恰用 $j-b$ 次完成，且每层在链旁留下一个兄弟叶，即每层一片副产物。∎

**引理 3（对齐性与免费配对）**：任何和为 $\text{target}$ 的选用片集合中，值 $\le 2^b$ 的片之和 $L$ 满足 $L \equiv \text{target} \pmod{2^{b+1}}$。因此「两片 $2^b$」与「一片 $2^{b+1}$」在满足需求上完全等价（可互换、且互换不改变操作代价）；反之，单独一片 $2^b$ 无法参与任何「$2^{b+1}$ 的倍数」需求的满足。

**证明**：设选用片中值 $\ge 2^{b+1}$ 的片之和为 $H$，则 $H$ 是 $2^{b+1}$ 的倍数且 $L + H = \text{target}$，故 $L \equiv \text{target} \pmod{2^{b+1}}$。把一对 $2^b$ 换成一片 $2^{b+1}$（或反之）时 $L$ 的变化是 $2^{b+1}$ 的倍数，同余关系与总和均不变，且「两片 $2^b$ 同时存在」与「一片 $2^{b+1}$ 存在」互为对方的免费拆分 / 免费组合，操作代价不增。而奇数片 $2^b$ 之和 $\equiv 2^b \pmod{2^{b+1}}$，不可能构成 $2^{b+1}$ 的倍数。∎

**定理（贪心最优性）**：算法返回的 $\text{ans}$ 是最少操作次数。

**证明**：先证贪心可行：账本上每次「借位」对应一条真实的链式拆分（引理 2 构造），每次「白嫖 / 配对」对应子序列里直接选中相应元素（引理 3），逐位拼出的选用集之和恰为 $\text{target}$，且 $\text{ans}$ 恰为所执行的操作数。再证最优性（交换论证）：将任一最优解 OPT 写成「拆分森林 + 选用叶集」，对 target 的二进制位从低到高归纳，证明 OPT 可被逐步改写成与贪心逐位同决策、且代价不增：

- **改写一（白嫖优先）**：设位 $b$ 置位、账本 $cnt[b] > 0$，但 OPT 为凑该位付出了拆分。把 OPT 归因于位 $b$ 的选用片换成现成片（虚拟片即两片小的），并把原先供养它的拆分链剪短到「不再供养任何选用叶」为止——链每剪掉一层省 $1$ 次操作，代价不增。
- **改写二（就近借位）**：设位 $b$ 置位、$cnt[b] = 0$，最小可用层为 $j$，而 OPT 从更高层 $j' > j$ 借（归纳保证层 $b+1 \ldots j-1$ 账面为空，OPT 的借源层级 $\ge j$）。设 OPT 的 $j'$-链在层 $\ge j$ 处仍被占用的最小层为 $t$（若无则视 $t = j'$）：改写为「从 $2^j$ 链拆到位 $b$、从 $2^{j'}$ 链拆到层 $t$」。两条新链完全覆盖原链供养的全部选用叶（低于 $j$ 的兄弟由前者按层供给，$t$ 及以上由后者供给），总代价从 $j' - b$ 变为 $(j-b) + (j'-t) \le (j-b) + (j'-j) = j' - b$，代价不增；当 OPT 在层 $\ge j$ 无占用时严格下降。多次应用后 OPT 位 $b$ 的借源变为层 $j$，与贪心一致。

归纳完成时 OPT 与贪心全部决策一致且代价不增，故贪心代价 $\le$ 最优代价；结合可行性即取等。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + B^2)$，其中 $B = 32$ 为位数。统计 $cnt$ 为 $O(n)$；每个二进制位至多触发一次借位，每次借位的「找 $j$ + 副产物入账」共 $O(B)$，总计 $O(B^2) \approx 10^3$，与 $n$ 相比可忽略。
- **空间复杂度**：$O(B)$，即长度 $40$ 的计数数组。

（对比：显式模拟数组需要 $\Theta(2^{40})$ 片；按位账本把整个拆分过程压缩成 $32$ 层竖式。）

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int target) {
        long long total = 0;
        for (int x : nums) total += x;
        if (total < target) return -1;          // 操作不改变总和

        long long cnt[40] = {};
        for (int x : nums) cnt[__builtin_ctz(x)]++;   // 2 的幂：层级 = 末尾 0 的个数

        int ans = 0;
        for (int b = 0; b < 32; b++) {
            if (target >> b & 1) {
                if (cnt[b] == 0) {
                    int j = b + 1;
                    while (cnt[j] == 0) j++;          // 质量不变式保证 j 存在
                    ans += j - b;                     // 链式拆分的代价 = 层级差
                    cnt[j]--;
                    for (int t = b; t < j; t++) cnt[t]++;  // 副产物每层一片入账
                }
                cnt[b]--;                             // 用掉一片 2^b（白嫖或借来的）
            }
            cnt[b + 1] += cnt[b] / 2;                 // 剩余两两配对，免费升级
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: List[int], target: int) -> int:
        if sum(nums) < target:
            return -1
        cnt = [0] * 40
        for x in nums:
            cnt[x.bit_length() - 1] += 1
        ans = 0
        for b in range(32):
            if target >> b & 1:
                if cnt[b] == 0:
                    j = b + 1
                    while cnt[j] == 0:
                        j += 1
                    ans += j - b
                    cnt[j] -= 1
                    for t in range(b, j):        # 链式副产物，每层一片
                        cnt[t] += 1
                cnt[b] -= 1
            cnt[b + 1] += cnt[b] // 2            # 配对进位
        return ans
```

## 8. 边界情况与易错点

1. **总和溢出**：C++ 中 `total` 必须 `long long`（最大约 $1.07 \times 10^{12}$）；Python 天然安全。
2. **副产物入账方式**：借位是 `cnt[b..j-1] 各 +1`（链式），不是 `cnt[b] += 2^(j-b)`（拆光）。写成后者会把代价暗中放大到 $2^{j-b}-1$，在 $[16], \text{target}=15$ 这类用例上输出 $15$ 而非 $4$。
3. **配对进位不能漏**：对「该位为 0」的层同样要做 `cnt[b+1] += cnt[b]/2`；它是零成本组合的建模，漏掉会多付借位费（见示例 2 位 2）。
4. **$-1$ 判据放最前**：先比总和再进循环，避免在无解情形下借位扫描越界。
5. **数组防御性开大**：`cnt` 开 $40$ 格。不变式保证借位 $j \le 30$，但若实现有细微差错，开大能避免越界读触发未定义行为，便于暴露逻辑问题。
6. **别显式模拟数组**：拆分后数组长度可达 $n + \text{ans} \sim 2^{40}$，只能用账本。
7. **大数位宽**：$\text{target} < 2^{31}$、$\text{nums}[i] \le 2^{30}$，位循环写满 $b < 32$ 即可全覆盖，无需特判最高位。
8. **「子序列」陷阱**：操作追加到末尾不影响子序列可选性（子序列可跳任意元素），故顺序无关、多重集视角成立——这是能按 $cnt$ 记账的前提。
