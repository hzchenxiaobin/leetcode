# LeetCode 工作计划的最低难度 题解

## 1. 题目概述

- **标题 / 题号**：工作计划的最低难度（#1335，hard）
- **链接**：https://leetcode.cn/problems/minimum-difficulty-of-a-job-schedule/
- **来源**：LeetCode 第 173 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划

**题意**：有 $n$ 项工作排成一行，工作之间有依赖——做第 $i$ 项之前必须做完所有 $j < i$ 的工作，所以整个计划就是把这个数组切成 $d$ 段**连续非空**的区间，依次分给第 $1$ 到第 $d$ 天。一天的难度等于当天所有工作的**最大**难度，计划的总难度是 $d$ 天难度之和。求总难度的最小值；若无法安排（工作数少于天数）返回 $-1$。

**约束**：

- $1 \le n = \lvert \text{jobDifficulty} \rvert \le 300$
- $0 \le \text{jobDifficulty}[i] \le 1000$
- $1 \le d \le 10$

> 💡 本题的关键在于把「依赖关系」翻译成「**连续区间划分**」：只要每天做的是连续一段，依赖就自动满足。

## 2. 示例

**示例 1**

```text
输入：jobDifficulty = [6,5,4,3,2,1], d = 2
输出：7
解释：第一天完成前 5 项，当天难度 = max(6,5,4,3,2) = 6；
      第二天完成最后 1 项，当天难度 = 1；
      总难度 = 6 + 1 = 7。其他切法都会更大（6+5=11、6+4=10、6+3=9、6+2=8）。
```

**示例 2**

```text
输入：jobDifficulty = [7,1,7,1,7,1], d = 3
输出：15
解释：切成 [7,1,7] / [1,7] / [1]，三天难度分别为 7、7、1，总和 15。
```

**示例 3**

```text
输入：jobDifficulty = [9,9,9], d = 4
输出：-1
解释：只有 3 项工作却要排 4 天，必然有一天无事可做，无法制定计划。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有把数组切成 $d$ 段的方案：切点有 $\binom{n-1}{d-1}$ 种，$n = 300$、$d = 10$ 时是天文数字。即使用「枚举每种划分再求每段最大」的写法，单次枚举也要 $O(n)$，总复杂度 $O\bigl(\binom{n-1}{d-1} \cdot n\bigr)$，完全不可行。

暴力枚举之所以慢，是因为它把「切点组合」当成互相独立的整体来搜索，重复计算了大量相同的**前缀子问题**。注意到「前 $k$ 项工作分给前 $j-1$ 天」这个子问题会被无数种切法复用——这正是动态规划的入口。

### 3.2 核心观察：连续区间划分与分段 DP

![把数组切成 d 段连续非空区间](images/wc173_q4_partition_model.svg)

**观察 1（连续性）**：由于依赖关系 $0 \to 1 \to \cdots \to n-1$，第 $k$ 天做的工作必须是下标连续的一段，且各天的区间首尾相接、从左到右排列。于是**任何一个合法计划都等价于在 $n-1$ 个空隙中选择 $d-1$ 个切点**。

**观察 2（段代价只与段内最大值有关）**：一天做完一段后，这一天的贡献就是这段的最大值，和段内顺序、长度都无关。

**观察 3（最优子结构）**：设 $dp[j][i]$ 表示「把前 $i$ 项工作恰好分给前 $j$ 天」的最小总难度。若第 $j$ 天负责的是区间 $[k, i-1]$，那么前 $k$ 项必须由前 $j-1$ 天以最优方式完成，且第 $j$ 天的代价固定为 $\max(\text{jobDifficulty}[k..i-1])$。于是

$$dp[j][i] = \min_{j-1 \le k \le i-1} \Bigl( dp[j-1][k] + \max_{k \le t \le i-1} \text{jobDifficulty}[t] \Bigr)$$

其中 $k \ge j-1$ 保证前 $j-1$ 天每天至少有一项，$k \le i-1$ 保证第 $j$ 天至少有一项。

**边界**：$dp[0][0] = 0$，$dp[0][i>0] = +\infty$；答案 $dp[d][n]$。若 $n < d$，答案为 $-1$。

### 3.3 算法流程 / 状态转移

![状态设计与转移](images/wc173_q4_dp_transition.svg)

朴素地按上式转移，每个状态要枚举 $k$ 并各自求一次区间最大值，单次转移 $O(n^2)$，总 $O(d\,n^3)$，对 $n=300$ 偏大（虽然常数小、实际也能过，但没必要）。

**关键技巧：边枚举边维护最大值**。固定 $i$，让 $k$ 从 $i-1$ **递减**到 $j-1$：

- 初始 $mx = \text{jobDifficulty}[i-1]$，此时区间是 $[i-1, i-1]$；
- 每把 $k$ 减 $1$，区间左端点左移一格，只需 $mx \leftarrow \max(mx, \text{jobDifficulty}[k])$；
- 同时用 $dp[j-1][k] + mx$ 更新当前最优值。

这样每个状态 $O(n)$ 完成，总复杂度降到 $O(d\,n^2) \le 10 \times 300^2 = 9\times 10^5$ 次运算。

```text
for j = 1 .. d:                       # 逐天推进
    cur[*] = +∞
    for i = j .. n:                   # 前 i 项分给 j 天，至少 j 项
        mx = 0, best = +∞
        for k = i-1 downto j-1:       # 枚举最后一天的起点
            mx = max(mx, a[k])
            best = min(best, prev[k] + mx)
        cur[i] = best
    prev = cur
return (n < d ? -1 : prev[n])
```

### 3.4 示例演算

![示例演算：a=[6,5,4,3,2,1]，d=2](images/wc173_q4_walkthrough.svg)

以 $a = [6,5,4,3,2,1]$、$d = 2$ 为例（下标从 $1$ 计）：

| 状态 | $i=1$ | $i=2$ | $i=3$ | $i=4$ | $i=5$ | $i=6$ |
|------|-------|-------|-------|-------|-------|-------|
| $dp[1][i]$ | 6 | 6 | 6 | 6 | 6 | 6 |
| $dp[2][i]$ | $\infty$ | 11 | 10 | 9 | 8 | **7** |

$dp[1][i]$ 就是把前 $i$ 项全放在第一天，代价等于前缀最大值，恒为 $6$。

$dp[2][6]$ 枚举 $k=5 \to 1$：$6+1=7$、$6+2=8$、$6+3=9$、$6+4=10$、$6+5=11$，取最小得 $7$。这个 $7$ 正是答案，对应的切点是 $k=5$（第一天做前 5 项，第二天做最后 1 项）。

再看示例 2 的 $a=[7,1,7,1,7,1]$、$d=3$：$dp[1][\cdot] = 7$，$dp[2][2..6] = 8,14,8,14,8$，$dp[3][3..6] = 15,15,15,15$，答案为 $15$。最优切法是 $[7,1,7] \mid [1,7] \mid [1]$：第一天同时承担两个 $7$，代价依然只是 $7$；反过来，若为了「摊平」而把三个 $7$ 各放一天，$7+7+7=21$ 反而更差——**局部摊平最大值并不更优**，必须交给 DP 做全局决策。

## 4. 算法细节

1. **状态维度与顺序**：$dp[j][i]$ 只依赖上一行 $dp[j-1][\cdot]$，因此只需两个长度为 $n+1$ 的数组（`prev` / `cur`）滚动，空间从 $O(dn)$ 降到 $O(n)$。
2. **枚举方向决定复杂度**：$k$ 必须从 $i-1$ **往小**枚举，才能让 $mx$ 只增不减地增量维护；若从 $j-1$ 往大枚举，区间右端点在变，$mx$ 无法增量更新，就只能退化成 $O(n^2)$ 的区间最大值查询。
3. **非法状态用哨兵值**：$i < j$ 的状态不合法，填 $+\infty$（C++ 用 `1e9`，Python 用 `float('inf')`）。内层循环下界取 $j-1$ 时，`prev[k]` 一定有限，所以 $+\infty$ 不会被加到答案里；只有第 1 天会用到 $dp[0][k>0] = +\infty$，此时 $k=0$ 这一项必然给出有限值。
4. **提前判无解**：$n < d$ 时直接返回 $-1$，否则 DP 里所有状态都是 $+\infty$，还要额外判断一次。
5. **下标的两种边界含义**：$k = j-1$ 表示前 $j-1$ 天「每天恰好一项」；$k = i-1$ 表示第 $j$ 天「只做一项」。两者都必须被枚举到，否则会漏掉最优解。
6. **值为 0 的工作**：$\text{jobDifficulty}[i]$ 可以为 $0$，$mx$ 的初值取 $0$ 即可（区间非空，不会留下空区间）；答案也可能是 $0$，所以不要拿 `-1` 表示「状态不可达」，否则与 $n<d$ 的返回值混淆。
7. **可选优化**：用单调栈把 $k$ 的候选值按「$dp[j-1][k] +$ 后缀最大值」分段维护，可把单次转移压到均摊 $O(1)$，整体 $O(dn)$；本题 $O(dn^2)$ 已足够，写单调栈反而增加出错概率。

## 5. 正确性证明

**引理 1（连续性）**：任一合法计划中，第 $j$ 天完成的工作在数组中构成一段连续区间 $[s_j, e_j)$，且 $0 = s_1 < e_1 = s_2 < \cdots < e_d = n$，每段非空。

**证明**：设第 $j$ 天做了工作 $b$。由依赖关系，所有下标 $< b$ 的工作必须在第 $j$ 天或更早完成。设第 $j$ 天还做了 $a < b$，取任意 $a < c < b$：若 $c$ 安排在第 $j$ 天之后，则做 $b$（$c < b$）时 $c$ 尚未完成，违反依赖；若 $c$ 安排在第 $j$ 天之前，则做 $c$ 时 $a$（$a < c$）尚未完成，同样违反依赖。故 $c$ 也只能安排在第 $j$ 天，第 $j$ 天的下标集合连续。又因依赖关系要求各天按时间先后覆盖从左到右的区间，这些区间首尾相接，且「每天至少一项」保证每段非空。∎

**引理 2（转移完备）**：对任意 $1 \le j \le i \le n$，有
$$dp[j][i] = \min_{j-1 \le k \le i-1} \bigl( dp[j-1][k] + \max(\text{jobDifficulty}[k..i-1]) \bigr).$$

**证明**：任取一个把前 $i$ 项分给 $j$ 天的合法计划。由引理 1，前 $j-1$ 天覆盖 $[0,k)$、第 $j$ 天覆盖 $[k,i)$，其中 $j-1 \le k \le i-1$。该计划的总难度为（前 $j-1$ 天的难度和）$+ \max(\text{jobDifficulty}[k..i-1])$，而前者不小于 $dp[j-1][k]$，故总难度不小于右侧第 $k$ 个候选值，进而不小于右侧的 $\min$。

反之，任取 $k \in [j-1, i-1]$，把 $dp[j-1][k]$ 的最优计划与「第 $j$ 天做 $[k,i)$」拼接，得到一个合法计划（每天非空、依赖满足），其总难度恰为候选值。因此右侧每个候选值都是可达的，$\min$ 不超过真实最优值。

两个方向合起来得到等式。∎

**引理 3（增量最大值的正确性）**：固定 $i$，令 $k$ 从 $i-1$ 递减到 $j-1$，循环变量 $mx$ 在第 $k$ 轮恰好等于 $\max(\text{jobDifficulty}[k..i-1])$。

**证明**：对 $i-1-k$ 归纳。$k = i-1$ 时 $mx = \text{jobDifficulty}[i-1]$，即单元素最大值。若第 $k+1$ 轮 $mx = \max(\text{jobDifficulty}[k+1..i-1])$，则第 $k$ 轮更新 $mx \leftarrow \max(mx, \text{jobDifficulty}[k]) = \max(\text{jobDifficulty}[k..i-1])$。∎

**定理**：算法返回 $n < d$ 时的 $-1$，否则返回 $dp[d][n]$，即最小总难度。

**证明**：$n < d$ 时由引理 1（每天非空）不可能划分，返回 $-1$ 正确。否则按天数递增计算：第 $j$ 行由引理 2 的等式、引理 3 的增量最大值逐项填出，故每个 $dp[j][i]$ 都是对应子问题的最优值（对 $j$ 归纳：$j=1$ 时 $dp[1][i]$ 就是前缀最大值，正确；若第 $j-1$ 行正确，则第 $j$ 行由引理 2 正确）。$j=d$、$i=n$ 时 $dp[d][n]$ 即原问题最优值。∎

## 6. 复杂度分析

- **时间**：$O(d\,n^2)$。外层 $d$ 天，内层对每个 $i$（共 $O(n)$ 个）扫描 $O(n)$ 个切点 $k$，每个 $k$ 只做一次比较与一次加法。$d \le 10$、$n \le 300$ 时约 $9\times10^5$ 次基本运算。
- **空间**：$O(n)$。只保留上一行与当前行两个长度为 $n+1$ 的数组；输入数组不计入额外空间。若保留完整 $dp$ 表则为 $O(dn)$。
- **常数说明**：内层是纯顺序内存访问 + 整数比较，无哈希、无递归，C++ 为毫秒级；Python 在本机 $n=300, d=10$ 下实测约 $2.6\times10^{-2}$ 秒。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minDifficulty(vector<int>& jobDifficulty, int d) {
        int n = jobDifficulty.size();
        if (n < d) return -1;
        const int INF = 1e9;
        vector<int> prev(n + 1, INF), cur(n + 1, INF);
        prev[0] = 0;                       // dp[0][0] = 0
        for (int day = 1; day <= d; day++) {
            fill(cur.begin(), cur.end(), INF);
            for (int i = day; i <= n; i++) {          // 前 i 项分给 day 天
                int mx = 0, best = INF;
                for (int k = i - 1; k >= day - 1; k--) {   // 最后一天做 [k, i-1]
                    mx = max(mx, jobDifficulty[k]);       // 增量维护区间最大值
                    best = min(best, prev[k] + mx);
                }
                cur[i] = best;
            }
            prev.swap(cur);
        }
        return prev[n];
    }
};
```

### Python

```python
class Solution:
    def minDifficulty(self, jobDifficulty: list[int], d: int) -> int:
        n = len(jobDifficulty)
        if n < d:
            return -1
        INF = float('inf')
        prev = [INF] * (n + 1)
        prev[0] = 0                                   # dp[0][0] = 0
        for day in range(1, d + 1):
            cur = [INF] * (n + 1)
            for i in range(day, n + 1):               # 前 i 项分给 day 天
                mx = 0
                best = INF
                for k in range(i - 1, day - 2, -1):   # 最后一天做 [k, i-1]
                    if jobDifficulty[k] > mx:
                        mx = jobDifficulty[k]         # 增量维护区间最大值
                    if prev[k] + mx < best:
                        best = prev[k] + mx
                cur[i] = best
            prev = cur
        return prev[n]
```

## 8. 边界情况与易错点

1. **$d > n$**：直接返回 $-1$（示例 3）。若不特判，DP 中 $i$ 从 $d$ 开始、$i \le n$ 无点可算，最终返回 $+\infty$，会得到错误答案甚至溢出。
2. **$d = 1$**：只能一天做完所有工作，答案就是整个数组的最大值。循环上界 $i \le n$、下界 $k \ge 0$，恰好只留下 $k=0$ 一个候选，代码无需特判。
3. **$d = n$**：每天一项，答案是数组元素之和。此时内层只有 $k = i-1$ 一个候选，验证了「$k = i-1$ 表示当天只做一项」这一边界。
4. **$\text{jobDifficulty}[i] = 0$**：允许出现，$mx$ 初值取 $0$ 即可；答案也可能是 $0$，切勿把 $0$ 当成「无解」的哨兵；$-1$ 只用于 $n < d$ 这一种情况。
5. **哨兵值溢出**：C++ 的 `INF` 取 `1e9` 而不是 `INT_MAX`，否则 `prev[k] + mx` 会整数溢出成负数，被误当成更优解。
6. **下标越界**：内层 `k` 的下界是 `day - 1`（不是 `day - 2`），上界是 `i - 1`（不是 `i`）。写成 `i` 会把第 $i$ 项（$0$ 基下越界）算进去，写成 `day-2` 会漏掉「前面每天恰好一项」的情形。
7. **滚动数组的初始化**：每轮都要把 `cur` 重置为 $+\infty$，只在 `day == 1` 时初始化一次会读到上一轮的残留值。
8. **Python 的 `INF` 与整数混用**：`float('inf') + int` 得到 `inf`，与真实值比较不会出错，但如果需要返回整数，记得结果一定来自有限候选（本题 $n \ge 1$ 时必然有限），不会返回 `inf`。

- [LeetCode 813. 最大平均值和的分组](https://leetcode.cn/problems/largest-sum-of-averages/)：把「段最大值」换成「段平均值」，其余结构与本篇完全一致，可用前缀和 + 同样的 $O(dn^2)$ DP。
- [LeetCode 1959. K 次调整数组大小浪费的最小总空间](https://leetcode.cn/problems/minimum-total-space-wasted-with-k-resizing-operations/)：段代价是「段长 $\times$ 段最大值 $-$ 段和」，仍是 $O(kn^2)$ 的分段 DP，可对照练习。

**延伸思考**：

1. **能否做到 $O(dn)$？** 可以。固定 $i$ 从 $i-1$ 向左扫时，$\max(\text{jobDifficulty}[k..i-1])$ 是随 $k$ 递减的**阶梯函数**，用**单调栈**把 $k$ 分成若干段，每段内最大值相同，再用每段内 $dp[j-1][k]$ 的最小值（前缀 min 或与栈同步维护）$O(1)$ 合并，单次转移均摊 $O(1)$。$n$ 增大到 $10^5$ 级别时这是标准做法。
2. **若一天的代价改成段和**：$\max$ 换成 $\text{sum}$ 后，转移里的区间和可用前缀和 $O(1)$ 求出，「边扫边维护」的技巧失效，但只需 $O(dn^2)$ 枚举；若目标改为「最小化最大段和」，则退化成 410 题的二分答案。
3. **若允许「某天可以不工作」**（段可以为空）：由于 $\max(A \cup B) \le \max A + \max B$（元素非负），任意两段合并都不会让总难度变大，故最优解就是把全部工作塞进一天，答案为整个数组的最大值——这个变体因此退化成一趟求最大值。
4. **段长有上下界的情形**：若第 $j$ 天必须恰好承担一段、且段长被限制在 $[L_j, R_j]$ 内，转移的枚举范围就从 $[j-1, i-1]$ 收紧为 $[i-R_j,\, i-L_j]$，增量维护最大值的技巧依然可用；若 $\sum_j L_j > n$ 则无解，若 $\sum_j R_j < n$ 同样无解。
