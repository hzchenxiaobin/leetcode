# LeetCode 餐厅过滤器 题解

## 1. 题目概述

- **标题 / 题号**：餐厅过滤器（#1333，medium）
- **链接**：https://leetcode.cn/problems/filter-restaurants-by-vegan-friendly-price-and-distance/
- **来源**：LeetCode 第 173 场周赛 Q2
- **难度**：中等
- **标签**：数组，排序

**题意**：每家餐厅是一个五元组 $[\text{id},\ \text{rating},\ \text{vegan},\ \text{price},\ \text{distance}]$。要求按三条规则筛选：若 `veganFriendly = 1`，只保留 $\text{vegan} = 1$ 的餐厅（为 0 时素食与非素食都要）；价格不超过 `maxPrice`；距离不超过 `maxDistance`。把通过筛选的餐厅按 **`rating` 从高到低**排序，`rating` 相同则按 **`id` 从高到低**排序，返回排序后的 `id` 列表。

**约束**：

- $1 \le n \le 10^4$
- $1 \le \text{id},\ \text{rating},\ \text{price},\ \text{distance} \le 10^5$，且所有 `id` 互不相同
- $1 \le \text{maxPrice},\ \text{maxDistance} \le 10^5$
- `vegan` 与 `veganFriendly` 的取值只有 0 或 1

> 💡 官方提示原话是 *the id may not be the index in the array*——**不要把数组下标当 id**，排序与输出都要用 `restaurants[i][0]`。

## 2. 示例

**示例 1**

```text
输入：restaurants = [[1,4,1,40,10],[2,8,0,50,5],[3,8,1,30,4],[4,10,0,10,3],[5,1,1,15,1]]
      veganFriendly = 1, maxPrice = 50, maxDistance = 10
输出：[3,1,5]
解释：① 素食过滤剔除 id=2、id=4（vegan=0）；
      ② 价格与距离都未超上限，剩下的 {1,3,5} 全部保留；
      ③ 按 rating 降序：id=3(8) > id=1(4) > id=5(1)。
```

      veganFriendly = 0, maxPrice = 50, maxDistance = 10
输出：[4,3,2,1,5]
解释：veganFriendly = 0 时素食过滤形同不存在，五家全保留；

      veganFriendly = 0, maxPrice = 30, maxDistance = 3

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**每轮线性扫描**：先扫一遍收集合法餐厅，然后重复 $k$ 次「在尚未输出的餐厅里找 $(rating, id)$ 最大的那家」，找到就输出并标记。

- 时间复杂度 $O(n + k^2) = O(n^2)$。$n = 10^4$ 时最坏约 $5 \times 10^7$ 次比较，C++ 也许能蹭过去，Python 则要几秒到十几秒，属于典型「思路对但写法亏」。
- 另一种常见写法是**两趟稳定排序**：先按 `id` 降序排一遍，再按 `rating` 降序**稳定**排一遍。它确实能得到正确顺序（稳定排序保留了同 `rating` 内部的 `id` 降序），但代价是两次 $O(n \log n)$，而且**方向极易写反**——第二趟必须稳定、且第一趟要按次关键字降序，稍不留神就变成 `id` 升序。既然 C++/Python 的比较器天然支持多关键字，就没必要绕这一圈。
- 更差的还有「边过滤边插入有序表」（插入排序思想），同样是 $O(n^2)$。

可见瓶颈不在过滤（那必然是 $O(n)$），而在**如何一次排序就表达二维顺序**。

### 3.2 核心观察：过滤与排序解耦 + 键唯一

![三段过滤与全序键](images/wc173_q2_filter_and_order.svg)

**观察 1：过滤和排序互不干扰。** 过滤是逐行独立的谓词 $P(r)$，删掉一行不会改变剩下任意两行的相对顺序；排序只依赖 $(\text{rating}, \text{id})$，与 `price`、`distance` 无关。所以可以先把合法行收进一个临时集合 $K$，再对 $K$ 排序，两件事各做一次即可。

**观察 2：$(\text{rating}, \text{id})$ 是严格全序。** 题目保证所有 `id` 互不相同，于是键 $(\text{rating}, \text{id})$ 也互不相同——任意两家餐厅的键要么一个大一个小，绝不会相等。这意味着：

- 排序结果是**唯一**的，不依赖排序算法的稳定性；
- 比较器只需回答「严格大于」，不需要处理相等分支之外的兜底。

**观察 3：二维键可以打包成一维整数。** 因为 $\text{id} \le 10^5$，取 $B = 100001 > \max \text{id}$，令

$$\text{key} = \text{rating} \times B + \text{id}$$

则 $\text{key}$ 的大小关系与 $(\text{rating}, \text{id})$ 的字典序**完全一致**：低位放 `id`、高位放 `rating`，`id` 的值域被 $B$ 卡住，永远不会向高位进位。于是「先比 `rating`、再比 `id`」退化成「比一个 64 位整数」，在需要手写排序或使用计数/基数排序时特别方便。

### 3.3 算法流程

![一次扫描加一次排序](images/wc173_q2_scan_flow.svg)

1. 准备空数组 `kept`，元素类型为 `(rating, id)`。
2. 顺序遍历 `restaurants` 的每一行 $r$：
   - 若 `veganFriendly == 1` 且 $r[2] == 0$，跳过；
   - 若 $r[3] > \text{maxPrice}$ 或 $r[4] > \text{maxDistance}$，跳过；
   - 否则把 $(r[1], r[0])$ 压入 `kept`。
3. 对 `kept` 按 `(rating, id)` 字典序**降序**排序。
4. 依次取出每个二元组里的 `id`，即为答案。

第 2 步是 $O(n)$，第 3 步是 $O(k \log k)$（$k = |K| \le n$），第 4 步 $O(k)$。全程只需一次排序，没有额外的稳定排序或反复扫描。

### 3.4 示例演算

![示例 1 逐行判定](images/wc173_q2_walkthrough.svg)

以示例 1（`veganFriendly = 1`、`maxPrice = 50`、`maxDistance = 10`）为例：

| id | rating | vegan | price | distance | 判定 | 保留 |
|----|--------|-------|-------|----------|------|------|
| 1 | 4 | 1 | 40 | 10 | 三项均通过 | ✓ |
| 2 | 8 | 0 | 50 | 5 | `vegan=0` 被剔除 | ✗ |
| 3 | 8 | 1 | 30 | 4 | 三项均通过 | ✓ |
| 4 | 10 | 0 | 10 | 3 | `vegan=0` 被剔除 | ✗ |
| 5 | 1 | 1 | 15 | 1 | 三项均通过 | ✓ |

$K = \{(4,1),\ (8,3),\ (1,5)\}$。按键降序比较：$(8,3) > (4,1) > (1,5)$，取 `id` 得 $[3,1,5]$，与官方输出一致。

注意 id=2 的 `price = 50` 恰好**等于**上限仍然通过——过滤用的是 $\le$ 而不是 $<$；它被剔除纯粹是因为 `vegan = 0`。若换成示例 2（`veganFriendly = 0`），id=2 与 id=4 都会被保留，此时 $(8,3) > (8,2)$ 正是「同分比 `id`」的那一步。

## 4. 算法细节

1. **过滤写成「保留条件」的合取**：`(veganFriendly == 0 or r[2] == 1) and r[3] <= maxPrice and r[4] <= maxDistance`。这样 `veganFriendly = 0` 的分支自然短路，不需要写两份循环。
2. **C++ 比较器必须是严格弱序**：写成 `if (a.first != b.first) return a.first > b.first; return a.second > b.second;`。若图省事写 `a.first >= b.first`，比较器对相等元素返回 `true`，`std::sort` 会陷入未定义行为——小数据可能「看起来对」，数据一大就越界崩溃。
3. **Python 直接用元组的 `reverse=True`**：`kept.sort(reverse=True)` 对 `(rating, id)` 元组做整体降序字典序，恰好是所需顺序；不要写成 `key=lambda x: -x[0]`，那样会丢掉 `id` 这个次关键字。
4. **打包键要注意位数**：`key = rating * 100001 + id` 最大约 $1.00002 \times 10^{10}$，**必须用 64 位整数**（C++ `long long`，Python 无此问题）。若把 $B$ 写成 $100000$，`id = 100000` 就会与「`rating` 大 1、`id` 为 0」撞在同一个键上。
5. **只存 `(rating, id)` 而不是整行**：排序时的元素更小、缓存更友好；也避免比较器里再去访问原数组、写得又长又慢。
6. **输出阶段再取 `id`**：排序只负责顺序，最后统一 `map` 出 `id`，逻辑分层清晰，也方便复用（比如题目改问「返回前 $m$ 个 `id`」，只需在输出阶段截断或换成堆）。
7. **不要用下标代替 `id`**：官方提示专门强调了这一点。排序后位置早已打乱，任何「返回下标」的写法都会错。

## 5. 正确性证明

**引理 1（过滤集合正确）**：算法得到的集合 $K$ 恰好等于满足三条过滤条件的餐厅集合 $S$。

**证明**：对任意一行 $r$，算法保留它当且仅当三个子句同时为真。当 `veganFriendly = 1` 时，第一个子句化为 $r[2] == 1$，与题意一致；当 `veganFriendly = 0` 时该子句恒真，即素食属性不参与筛选，也与题意一致。另两个子句分别等价于 $\text{price} \le \text{maxPrice}$ 与 $\text{distance} \le \text{maxDistance}$。故 $r \in K \iff r \in S$。∎

**引理 2（键构成严格全序）**：映射 $\varphi(r) = (\text{rating}, \text{id})$ 在 $K$ 上是单射，且字典序比较给出严格全序，因此按它降序排列的结果唯一。

**证明**：若两家餐厅的键相同，则 `rating` 与 `id` 都相同；而所有 `id` 互不相同，故键相同的两家必是同一家，$\varphi$ 单射。字典序在任意集合上都是全序，单射又排除了相等，故为严格全序，任意两个正确排序的结果逐位相同。∎

**引理 3（打包键保序）**：取 $B = 100001$，对任意两家餐厅 $r_1, r_2$，

$$\text{key}_1 > \text{key}_2 \iff (\text{rating}_1, \text{id}_1) > (\text{rating}_2, \text{id}_2)$$

**证明**：记 $\Delta_r = \text{rating}_1 - \text{rating}_2$，$\Delta_i = \text{id}_1 - \text{id}_2$，则 $\text{key}_1 - \text{key}_2 = \Delta_r B + \Delta_i$。

- 若 $\Delta_r > 0$：由 $1 \le \text{id} \le 10^5$ 及 $B = 10^5 + 1$ 得 $\Delta_i \ge 1 - (B-1) = 2 - B$，于是 $\text{key}_1 - \text{key}_2 \ge B + (2 - B) = 2 > 0$。
- 若 $\Delta_r < 0$：对称地 $\Delta_i \le B - 2$，$\text{key}_1 - \text{key}_2 \le -B + (B-2) = -2 < 0$。
- 若 $\Delta_r = 0$：$\text{key}_1 - \text{key}_2 = \Delta_i$，符号与 `id` 比较一致。

三种情形下键的比较都与字典序比较同号。∎

**定理**：算法输出的 `id` 序列恰为题目要求的序列。

**证明**：由引理 1，参与排序的集合就是合法餐厅集合；由引理 2，排序结果唯一且为键的降序；由引理 3，键降序等价于 $(\text{rating}, \text{id})$ 降序，即「`rating` 高者在前，同分则 `id` 大者在前」；最后一步按序取 `id`，保持顺序不变。三点合起来即为题目要求的输出。∎

## 6. 复杂度分析

- **时间**：$O(n + k \log k) \subseteq O(n \log n)$。过滤逐行做常数次比较，$O(n)$；对 $k$ 个键排序 $O(k \log k)$；输出 $O(k)$。最坏 $k = n = 10^4$ 时排序约 $1.3 \times 10^5$ 次比较，任意语言都在毫秒级。
- **空间**：$O(k) \subseteq O(n)$。只存通过过滤的 $(rating, id)$；C++ 里是 `vector<pair<int,int>>`，Python 里是元组列表。若允许原地重排原数组（把合法行换到前 $k$ 位），额外空间可压到 $O(1)$，但对 $n = 10^4$ 来说没有必要，可读性更重要。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> filterRestaurants(vector<vector<int>>& restaurants, int veganFriendly,
                                  int maxPrice, int maxDistance) {
        vector<pair<int, int>> kept;              // (rating, id)
        for (const auto& r : restaurants) {
            if (veganFriendly == 1 && r[2] == 0) continue;   // 素食过滤
            if (r[3] > maxPrice || r[4] > maxDistance) continue;
            kept.push_back({r[1], r[0]});
        }
        sort(kept.begin(), kept.end(), [](const pair<int, int>& a, const pair<int, int>& b) {
            if (a.first != b.first) return a.first > b.first;  // 严格弱序，不能写 >=
            return a.second > b.second;
        });
        vector<int> ans;
        ans.reserve(kept.size());
        for (const auto& p : kept) ans.push_back(p.second);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def filterRestaurants(self, restaurants: list[list[int]], veganFriendly: int,
                          maxPrice: int, maxDistance: int) -> list[int]:
        kept = [
            (r[1], r[0])                              # (rating, id)
            for r in restaurants
            if (veganFriendly == 0 or r[2] == 1)      # 素食过滤
            and r[3] <= maxPrice
            and r[4] <= maxDistance
        ]
        kept.sort(reverse=True)                       # 先 rating 降序，再 id 降序
        return [rid for _, rid in kept]
```

## 8. 边界情况与易错点

1. **全部被过滤**：如 `restaurants = [[7,3,1,5,5]]`、`maxPrice = 4`，应返回 `[]`。C++ 返回空 `vector` 即可，不要误返回 `{-1}` 之类的哨兵；Python 不要返回 `None`。
2. **`veganFriendly = 0` 不等于「只留非素食」**：它是「不筛素食属性」，示例 2 的输出包含 1、3、5 三家素食餐厅就是反例。常见错误是写成 `if r[2] != veganFriendly: continue`。
3. **上界含等于**：价格、距离都用 `<=`。示例 2 中 id=2 的 `price = 50` 恰好等于 `maxPrice` 仍被保留；若写成 `<` 会漏掉它。
4. **同分要比 `id` 降序**：示例 2 里 id=3 与 id=2 都是 `rating = 8`，正确顺序是 3 在 2 前。只按 `rating` 排序会让输出顺序依赖排序算法的稳定性，属于「能过样例、换语言就挂」的写法。
5. **C++ 比较器不能用 `>=`**：非严格弱序会触发 `std::sort` 的未定义行为（越界读写甚至死循环），且往往只在 $n$ 较大时暴露。
6. **打包键必须 64 位**：$\text{rating} \times 100001$ 约 $10^{10}$，用 `int` 直接溢出成负数，排序结果会莫名其妙地反掉；$B$ 也必须严格大于 $10^5$。
7. **`id` 不是下标**：任何 `restaurants[i]` 与 `i` 混用的地方都要检查，尤其是「按数量建桶」「按下标回填答案」这类写法。
8. **单元素与空集合**：$n = 1$ 且通过过滤时返回单元素列表，不通过时返回空列表；代码无需特判，但不要把「排序后取第一个」写成会越界的 `kept[0]`（应先判空或直接遍历）。

**延伸思考**：

1. **值域只有 $10^5$，能否线性？** 可以。`rating` 与 `id` 都在 $[1, 10^5]$ 内，用「以 `rating` 为桶下标」的桶排序，桶内再按 `id` 从大到小收集（或者先按 `id` 升序扫一遍再对每个桶反转），时间做到 $O(n + V)$、空间 $O(V)$，$V = 10^5$。这比 $O(n \log n)$ 更快，但常数与内存更大：只有当 $n$ 远大于值域（例如 $10^6$ 量级）时才明显划算。
2. **如果查询是流式的？** 若过滤参数固定、但餐厅不断到来，维护一个按 `key` 有序的结构（C++ `set`、Python 的 `sortedcontainers.SortedList`）即可边插入边保持顺序，插入 $O(\log n)$；若只关心前 $m$ 家，用小顶堆把空间压到 $O(m)$。
3. **如果同一 `id` 出现多条记录？** 键不再唯一，必须补第三关键字（如时间戳或价格）才能保证输出确定；或者先按 `id` 去重（保留最新一条）再走本流程。
4. **如果过滤条件是区间查询？** 例如「价格在 $[a,b]$、距离不超过 $d$」的多次询问，可以按 `price` 排序后配合二维偏序（离线排序 + 树状数组）或 k-d 树，把单次 $O(n)$ 的过滤降到 $O(\log^2 n)$ 级。
