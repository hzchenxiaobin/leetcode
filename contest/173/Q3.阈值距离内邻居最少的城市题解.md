# LeetCode 阈值距离内邻居最少的城市 题解

## 1. 题目概述

- **标题 / 题号**：阈值距离内邻居最少的城市（#1334，medium）
- **链接**：https://leetcode.cn/problems/find-the-city-with-the-smallest-number-of-neighbors-at-a-threshold-distance/
- **来源**：LeetCode 第 173 场周赛 Q3
- **难度**：中等
- **标签**：图、动态规划、最短路、Dijkstra 算法、Floyd 算法、Bellman–Ford 算法

**题意**：有 $n$ 个城市，编号 $0 \sim n-1$，`edges` 给出无向带权边 $(u, v, w)$，路径距离定义为沿途边权之和。对每个城市 $i$，统计**最短路径距离不超过** `distanceThreshold` 的其它城市个数 $c_i$（自己不算）。返回 $c_i$ 最小的城市；若有多个并列最小，返回**编号最大**的那个。

**约束**：

- $2 \le n \le 100$
- $1 \le \lvert \text{edges} \rvert \le \dfrac{n(n-1)}{2}$，所有 $(u, v)$ 互不相同（无重边）
- $0 \le \text{from} < \text{to} < n$，$1 \le w \le 10^4$，$1 \le D \le 10^4$
- 任意两点最短路至多 $99 \times 10^4 < 10^6$，32 位整数足以容纳

## 2. 示例

**示例 1**

```text
输入：n = 4, edges = [[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold = 4
输出：3
解释：各城市在阈值 4 内的邻居为
      城市 0 -> [1, 2]
      城市 1 -> [0, 2, 3]
      城市 2 -> [0, 1, 3]
      城市 3 -> [1, 2]
      城市 0 与城市 3 都有 2 个邻居，并列最少，取编号更大的 3。
```

**示例 2**

```text
输入：n = 5, edges = [[0,1,2],[0,4,8],[1,2,3],[1,4,2],[2,3,1],[3,4,1]], distanceThreshold = 2
输出：0
解释：城市 0 的邻居只有 {1}，城市 1 有 {0, 4}，城市 2 有 {3, 4}，
      城市 3 有 {2, 4}，城市 4 有 {1, 2, 3}；
      城市 0 只有 1 个邻居，最少，返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「把路径枚举出来」：从城市 $i$ 出发做 DFS，枚举所有简单路径并记录到每个城市的最小距离。带权图上这一条路可能绕很远，剪枝写不好就指数爆炸；更本质的是，题目只要**距离值**，根本不需要知道路径长什么样，枚举具体路径属于用错了工具。

退一步看「单源最短路」：Dijkstra 一次 $O(m \log n)$，对 $n$ 个城市各跑一次是 $O(n m \log n) \approx 100 \times 4950 \times 7 \approx 3.5 \times 10^6$，能过，但要写堆、邻接表、每轮重置 `dist`；每点跑一遍 Bellman–Ford 则是 $O(n^2 m) \approx 5 \times 10^7$，C++ 勉强、Python 偏悬。而本题的甜点区在于：$n \le 100$ 小得离谱，$n^3 = 10^6$ 的三重循环完全够用，Floyd 只要十行代码。

### 3.2 核心观察：一次 Floyd 得到全源最短路，答案只是逐行计数

![以城市 i 为中心、半径 D 的球里有几个城市](images/wc173_q3_threshold_ball.svg)

两件事同时成立，才有了这个解法：

1. **所有城市问的是同一个问题**——「离我最近的那些城市里，有多少个在我 $D$ 半径内」。它们共用同一张距离矩阵，所以只需求一次**全源最短路**，不要对每个城市分别搜索。
2. **带权图看的是最短路长度，不是边权或边数**。示例 1 中 $d(3,1) = 2$（走 3-2-1），比 3-1 的直达边权 4 更短：若把阈值调成 3，只看直达边会把城市 1 判在阈值外，而它其实在阈值内。

Floyd 的 DP 定义是「阶段」而非「起点」：令 $d^{(k)}_{ij}$ 表示只允许经过编号小于 $k$ 的城市作中转时 $i \to j$ 的最短距离，转移为

$$d^{(k+1)}_{ij} = \min\left(d^{(k)}_{ij},\ d^{(k)}_{ik} + d^{(k)}_{kj}\right)$$

即「不经过 $k$」与「经过 $k$」两者取小。跑完 $k = 0 \sim n-1$ 后 $d_{ij}$ 就是真实最短路，计数与选择一步到位：

$$c_i = \#\{\, j \ne i : d_{ij} \le D \,\}, \qquad \text{ans} = \max\{\, i : c_i = \min_{k} c_k \,\}$$

### 3.3 算法流程

![Floyd 流程与两个实现要点](images/wc173_q3_floyd_flow.svg)

1. **建矩阵**：`d[i][i] = 0`，对每条边 $(u, v, w)$ 置 `d[u][v] = d[v][u] = w`，其余为 `INF`。
2. **最外层枚举中转城市 `k`**，内两层枚举 `(i, j)`：若 `d[i][k] + d[k][j] < d[i][j]` 则更新。
3. **逐行计数**：对每个 `i`，数 `j != i` 且 `d[i][j] <= D` 的 `j` 的个数 `cnt`。
4. **更新答案**：若 `cnt <= bestCnt`，则 `bestCnt = cnt, ans = i`。用 `<=` 而不是 `<`，正是「同分取更大编号」的实现。
5. 返回 `ans`。

```text
d[i][i] = 0，其余 INF；对每条边 (u,v,w)：d[u][v] = d[v][u] = min(..., w)
for k in 0 .. n-1:
    for i in 0 .. n-1:
        for j in 0 .. n-1:
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])
best = n;  ans = -1
for i in 0 .. n-1:
    cnt = count{ j != i and d[i][j] <= D }
    if cnt <= best:  best = cnt;  ans = i
return ans
```

### 3.4 示例演算

![示例 1 的距离矩阵与计数](images/wc173_q3_walkthrough.svg)

以示例 1 为例（$n = 4$，$D = 4$），跑完 Floyd 得到的距离矩阵与逐行计数如下：

| $d_{ij}$ | 0 | 1 | 2 | 3 | $c_i$ |
| --- | --- | --- | --- | --- | --- |
| **0** | 0 | 3 | 4 | 5 | **2** |
| **1** | 3 | 0 | 1 | 2 | 3 |
| **2** | 4 | 1 | 0 | 1 | 3 |
| **3** | 5 | 2 | 1 | 0 | **2** |

几个值得留意的值：$d_{02} = 3 + 1 = 4$（而不是绕 0-1-3-2 的 8）；$d_{13} = 2$（走 1-2-3，而不是直达的 4）；$d_{03} = 3 + 1 + 1 = 5$，它**超过**阈值，所以城市 0 与城市 3 互相看不见。于是城市 0 这一行只有 1（3）与 2（4）计入，$c_0 = 2$；城市 1 计入 0、2、3 三个；城市 2 计入 0、1、3 三个；城市 3 计入 1（2）与 2（1），$c_3 = 2$。最小计数为 2，城市 0 与城市 3 并列，按规则取编号更大的 **3**。

示例 2（$n = 5$，$D = 2$）走同一条流水线：$d_{04} = \min(8,\ 2+2,\ 2+3+1+1) = 4$（直达边权 8，绕 0-1-4 只要 4），计数得 $c = [1, 2, 2, 2, 3]$，城市 0 的 1 最小，返回 0。

## 4. 算法细节

1. **`INF` 取 $10^9$，不要用 `INT_MAX`**。`d[i][k] + d[k][j]` 可能把两个 `INF` 相加，`INT_MAX + INT_MAX` 在 `int` 上溢出成负数，反而在比较中「变小」；$10^9 + 10^9 = 2 \times 10^9 < 2^{31} - 1$ 则安全。更稳的写法是内层先判 `if (d[i][k] == INF) continue;`，顺带省掉一半无效松弛。
2. **`k` 必须是最外层循环**。它代表 DP 的阶段（允许经过哪些中转城市）；写成 `i` 最外层会用到「本阶段尚未算好」的值，可能漏掉合法的最短路。
3. **无向边要写两个方向**：`d[u][v] = d[v][u] = w`。本题保证 $(u, v)$ 不重复，但仍建议写成 `min`，对重边与自环都友好。
4. **阈值比较用 $\le$**。示例 1 中 $d_{02} = 4$ 恰好等于 $D$，它是邻居；若写成 `<`，计数变成 $c = [1, 3, 2, 2]$（$d_{02}$ 被漏掉），最小值落到城市 0，答案会从 3 错成 0。
5. **计数时排除自己**（`j != i`）。自身距离 0 永远 $\le D$，漏掉这一条会让每个城市的计数同时 +1 —— 对本题的 argmin 没有影响（同时 +1 不改变排序与并列集合），但口径就错了，换到「输出计数」的变体上立刻翻车。
6. **同分取大编号**：顺序扫描用 `cnt <= bestCnt` 更新；若改为倒序扫描（$n-1 \to 0$）则要用 `cnt < bestCnt`。两种写法等价，别混着用。
7. **Python 的内层优化**：把 `d[k]`、`d[i]` 绑成局部变量，并跳过 `d[i][k] == INF` 的行，$n = 100$ 时 $10^6$ 次内层迭代在 0.1 s 量级。注意 $i = k$ 时 `d[i]` 与 `d[k]` 是同一行，此时 `d[i][k] = 0`，松弛不会写入，别名是安全的。
8. **`bestCnt` 初值取 $n$**：因为 $c_i \le n-1 < n$，第一个城市必定触发更新，`ans` 不会停留在 `-1`；也无需额外判「答案存在」。

## 5. 正确性证明

**引理 1（Floyd 的 DP 语义）**：第 $k$ 阶段（$k$ 从 0 数起）结束后，$d_{ij}$ 等于「只允许经过中转城市 $\{0, \ldots, k-1\}$」时 $i$ 到 $j$ 的最短距离。

**证明**：对 $k$ 归纳。$k = 0$ 时允许的中转集合为空，最短路只能是直达边（或 $i = j$ 的 0），与矩阵初值一致。设第 $k$ 阶段成立，考察第 $k+1$ 阶段：任取一条允许中转 $\{0, \ldots, k\}$ 的最短路。若它不经过 $k$，由归纳假设其长度不小于 $d^{(k)}_{ij}$；若它经过 $k$，沿路径第一次与最后一次经过 $k$ 把它切成两段，每段只经过 $\{0, \ldots, k-1\}$，于是总长度不小于 $d^{(k)}_{ik} + d^{(k)}_{kj}$。故真实最短路 $\ge \min\left(d^{(k)}_{ij},\ d^{(k)}_{ik} + d^{(k)}_{kj}\right)$；另一方面转移式取到的两个候选都对应合法路径，故该下界可以取到，等式成立。∎

**引理 2（计数正确）**：全部阶段结束后，$c_i$ 恰为最短距离不超过 $D$ 的其它城市个数。

**证明**：由引理 1 取 $k = n$，此时允许经过全部城市，$d_{ij}$ 即真实最短路长度。计数循环枚举所有 $j \ne i$，当且仅当 $d_{ij} \le D$ 时把 $j$ 计入，因此 $c_i$ 与题面定义完全一致。∎

**引理 3（并列取大编号）**：按 $i = 0, 1, \ldots, n-1$ 顺序扫描并用 `cnt <= bestCnt` 更新，结束时 `ans` 是计数最小的城市中编号最大的那个。

**证明**：设已经扫描到 $i$，记 $\text{bestCnt}$ 为前缀 $\{0, \ldots, i\}$ 的最小计数，$\text{ans}$ 为该前缀中取到这个最小值的最大编号。归纳：初始 $i = 0$ 时 $c_0 < n = \text{bestCnt}$，更新后恰为 $\{0\}$ 的情形。扫描 $i+1$ 时，若 $c_{i+1} < \text{bestCnt}$，最小值被刷新，$\text{ans} = i+1$ 是唯一取到它的编号；若 $c_{i+1} = \text{bestCnt}$，`<=` 使 $\text{ans}$ 覆盖为 $i+1$，正是「同分取更大编号」；若 $c_{i+1} > \text{bestCnt}$ 则不更新。扫描结束前缀为全集，结论成立。∎

**定理**：算法返回的正是题目要求的城市。

**证明**：由引理 2，计数口径与题面一致；由引理 3，返回值是计数最小者中编号最大的城市。二者合起来即题面「返回阈值距离内可达城市最少的城市，若有多个则返回编号最大的」，故算法正确。∎

## 6. 复杂度分析

- **时间**：$O(n^3)$ 预处理最短路，三重循环内层只有一次加法与一次比较，$n = 100$ 时约 $10^6$ 次；逐行计数 $O(n^2)$；总计 $O(n^3)$，常数极小。
- **空间**：$O(n^2)$ 的距离矩阵，$n = 100$ 时为 $10^4$ 个 `int`，约 40 KB；除此之外只有常数个标量。
- **对比**：$n$ 次 Dijkstra 的 $O(n m \log n)$ 在稠密图上约 $3.5 \times 10^6$，常数与代码量都更大；只有在稀疏大图（$n$ 大、$m$ 小）时才反过来占优，而本题 $n \le 100$ 恰好落在 Floyd 的舒适区。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int findTheCity(int n, vector<vector<int>>& edges, int distanceThreshold) {
        const int INF = 1000000000;                 // 1e9：两个相加也不会溢出 int
        vector<vector<int>> d(n, vector<int>(n, INF));
        for (int i = 0; i < n; ++i) d[i][i] = 0;

        for (const auto& e : edges) {
            int u = e[0], v = e[1], w = e[2];
            if (w < d[u][v]) d[u][v] = d[v][u] = w;  // 无向边，两个方向都写
        }

        for (int k = 0; k < n; ++k) {               // 中转城市必须是最外层
            for (int i = 0; i < n; ++i) {
                if (d[i][k] == INF) continue;        // 不可达，跳过整行
                int dik = d[i][k];
                for (int j = 0; j < n; ++j)
                    if (d[k][j] != INF && dik + d[k][j] < d[i][j])
                        d[i][j] = dik + d[k][j];
            }
        }

        int bestCnt = n, ans = -1;
        for (int i = 0; i < n; ++i) {
            int cnt = 0;
            for (int j = 0; j < n; ++j)
                if (j != i && d[i][j] <= distanceThreshold) ++cnt;
            if (cnt <= bestCnt) {                   // <= 保证同分时取更大编号
                bestCnt = cnt;
                ans = i;
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findTheCity(self, n: int, edges: List[List[int]], distanceThreshold: int) -> int:
        INF = 10 ** 9
        d = [[INF] * n for _ in range(n)]
        for i in range(n):
            d[i][i] = 0
        for u, v, w in edges:
            if w < d[u][v]:                          # 无向边，两个方向都写
                d[u][v] = d[v][u] = w

        for k in range(n):                           # 中转城市必须是最外层
            dk = d[k]
            for i in range(n):
                dik = d[i][k]
                if dik == INF:                       # 不可达，跳过整行
                    continue
                di = d[i]
                for j in range(n):
                    nd = dik + dk[j]
                    if nd < di[j]:
                        di[j] = nd

        best_cnt, ans = n, -1
        for i in range(n):
            cnt = 0
            di = d[i]
            for j in range(n):
                if j != i and di[j] <= distanceThreshold:
                    cnt += 1
            if cnt <= best_cnt:                      # <= 保证同分时取更大编号
                best_cnt, ans = cnt, i
        return ans
```

## 8. 边界情况与易错点

1. **孤立城市**：没有任何边的城市 $c_i = 0$，必然是最小值；若有多个孤立城市，取编号最大的那个。例如 `n = 3, edges = [[0,1,5]], D = 10000` 应返回 2——代码天然正确，不需要特判。
2. **图不连通**：不相通的两点 $d_{ij} = \text{INF} > D$，不会被计入。前提是 `INF` 足够大且没有溢出，见第 4 节第 1 条。
3. **并列取大编号**：示例 1 就是 $c_0 = c_3 = 2$，答案是 3 而不是 0。顺序扫描写成 `cnt < bestCnt` 会返回 0，是最常见的 WA。
4. **$\le$ 与 $<$**：$d_{ij} = D$ 算邻居。示例 1 的 $d_{02} = 4$ 正好卡在边界，写成 `<` 会把答案从 3 变成 0。
5. **`k` 循环的位置**：把 `k` 放进最内层是初学 Floyd 的经典错误，小数据偶尔也能碰对，但一般会漏掉更短的路径。
6. **`INF` 相加溢出**：C++ 中 `INF = INT_MAX` 时 `INF + INF` 溢出为负，会让「不可达」在比较中胜出；Python 无此问题。
7. **`edges` 只有一条边**：$n \ge 2$ 时图必然不连通。除这条边的两个端点 $c = 1$ 外，其余城市 $c = 0$，所以答案落在「编号最大的孤立城市」上（$n = 2$ 时没有孤立城市，两个端点并列，返回 1）。
8. **返回值范围**：`ans` 一定落在 $[0, n-1]$，因为每个城市都被扫描且第一个城市必定更新；不需要 `return -1` 之类的兜底。

**延伸思考**：

1. **阈值有大量询问**：若要对同一个图回答 $q$ 组不同的 $D$，可以把每个城市的距离行排序，$O(n^2 \log n)$ 预处理后每组询问二分出「$\le D$ 的个数」，$O(\log n)$ 回答，比每次重跑 $O(n^2)$ 计数更快。
2. **稀疏大图**：$n = 10^5$、$m = 10^5$ 时 Floyd 不可行。若阈值 $D$ 很小，可以从每个点做「距离超过 $D$ 立即停止」的受限 Dijkstra，总代价取决于 $D$ 半径内的边数。
3. **$D$ 超过图直径**：此时 $c_i$ 退化为「$i$ 所在连通块的大小 $- 1$」，答案就是连通块最小的那一类里编号最大的点，用并查集 $O(n + m)$ 即可，完全不需要最短路。
4. **要输出邻居列表**：计数循环里顺手把满足条件的 $j$ 收集起来即可，总空间 $O(n^2)$，与距离矩阵同阶，不改变复杂度。
