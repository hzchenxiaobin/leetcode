# LeetCode 从双倍数组中还原原数组 题解

## 1. 题目概述

- **标题 / 题号**：从双倍数组中还原原数组（#2007，medium）
- **链接**：https://leetcode.cn/problems/find-original-array-from-doubled-array/
- **来源**：LeetCode 第 61 场双周赛 Q2（2021-09-18）
- **难度**：中等
- **标签**：贪心、数组、哈希表、排序

**题意**：一个整数数组 `original` 可以按如下方式变成「双倍数组」`changed`：把 `original` 中每个元素乘 2 后加入数组，再把所有元素**随机打乱**。给定 `changed`，若它确实是某个双倍数组，返回对应的 `original`（任意顺序）；否则返回空数组。

**约束**：

- $1 \le changed.length \le 10^5$
- $0 \le changed[i] \le 10^5$

> 💡 本题与 LC 954「二倍数对数组」同源：都是「多重集合 $S$ 与 $2S$ 精确配对」的判定问题，是排好贪心匹配 + 计数判定的经典模板。

## 2. 示例

**示例 1**

```text
输入：changed = [1,3,4,2,6,8]
输出：[1,3,4]
解释：1→2、3→6、4→8，加上原数 1、3、4 打乱后即为输入。
```

**示例 2**

```text
输入：changed = [6,3,0,1]
输出：[]
解释：无论怎么划分都无法两两配成 (x, 2x)。
```

**示例 3**

```text
输入：changed = [1]
输出：[]
解释：长度为奇数，必然无法由「原数 + 二倍数」组成。
```

**示例 4（边界补充）**

```text
输入：changed = [0,0,0,0]
输出：[0,0]
解释：0 的二倍仍是 0，四个 0 两两配对，原数组是两个 0。
```

## 3. 解题思路

### 3.1 暴力思路

若 `changed` 是双倍数组，其长度必为偶数，且可以划分成 $\frac{n}{2}$ 对 $(x, 2x)$。最直接的暴力是枚举所有大小为 $\frac{n}{2}$ 的子集当作 `original`，检验多重集合 $original \cup 2 \cdot original$ 是否等于 $changed$——$O(2^n)$ 指数爆炸，$n \le 10^5$ 完全不可行。退一步的「正确暴力」是排序后逐个配对，但朴素实现每次找 $2x$ 都要线性扫描，$O(n^2)$ 依然超时。必须利用值域或哈希把「找配对」降到 $O(1)$。

### 3.2 核心观察：从小到大贪心，最小剩余值必为原数

![核心观察：从小到大配对，最小值必为原数](images/bw61_q2_greedy_match.svg)

把 `changed` 按值排序（或直接按值域桶计数）后，观察**当前最小的、还未配对的正数 $x$**：它的二分之一 $x/2 < x$ 已经全部处理完毕，不可能再有「多余的 $x/2$」充当它的原数；而 $x$ 若是二倍数，其原数只能是 $x/2$。因此剩下的 $x$ **只能全部当原数**，每个 $x$ 必须消耗一个 $2x$ 作为其二倍数。这就把配对过程完全锁死：从小到大扫描，遇到 $cnt[v] > 0$ 就把 $v$ 全部输出为原数，并检查 $cnt[2v]$ 是否够用。

唯一的例外是 $0$：$2 \times 0 = 0$，0 的二倍数就是 0 自己，因此 0 只能和 0 配对，$cnt[0]$ 必须是偶数，其中一半进 `original`。

![零的自配对特判](images/bw61_q2_zero_pairs.svg)

### 3.3 算法流程

```text
1. 若 changed 长度为奇数 → 返回 []
2. 值域计数 cnt[0..200000]（changed[i] ≤ 1e5，2x ≤ 2e5）
3. 若 cnt[0] 为奇数 → 返回 []；否则输出 cnt[0]/2 个 0 到 original
4. for v = 1 to 100000:
5.     若 cnt[v] == 0：跳过
6.     若 cnt[2v] < cnt[v]：二倍数不够配 → 返回 []
7.     输出 cnt[v] 个 v 到 original；cnt[2v] -= cnt[v]   # 这些 2v 被消耗为二倍数
8. 返回 original
```

第 7 步是关键：被消耗掉的 $cnt[2v]$ 个 $2v$ 是「二倍数」身份，轮到值 $2v$ 自己被扫描时，剩余的 $cnt[2v]$ 才是它作为原数的个数——消耗必须发生在扫描到它之前，这正是「从小到大」顺序保证的。

### 3.4 示例演算

![示例演算：[1,3,4,2,6,8] 的逐步配对](images/bw61_q2_walkthrough.svg)

以示例 1（$changed = [1,3,4,2,6,8]$）为例，$cnt$ 非零项为 $\{1{:}1, 2{:}1, 3{:}1, 4{:}1, 6{:}1, 8{:}1\}$：

| 步骤 | 扫描值 $v$ | $cnt[v]$（剩余） | 动作 | $original$ | 消耗后 $cnt$ 变化 |
|------|-----------|------------------|------|------------|-------------------|
| 1 | 1 | 1 | 原数 1，消耗一个 2 | [1] | $cnt[2]: 1 \to 0$ |
| 2 | 2 | 0 | 跳过 | [1] | — |
| 3 | 3 | 1 | 原数 3，消耗一个 6 | [1,3] | $cnt[6]: 1 \to 0$ |
| 4 | 4 | 1 | 原数 4，消耗一个 8 | [1,3,4] | $cnt[8]: 1 \to 0$ |
| 5 | 6, 8 | 0 | 跳过 | [1,3,4] | — |

所有桶清零，返回 $[1,3,4]$。反例 $[6,3,0,1]$：$cnt[0] = 1$ 为奇数，立即返回 $[]$。

## 4. 算法细节

1. **先判长度奇偶**：双倍数组长度必为偶数，奇数直接返回空，能省掉后续一切工作。
2. **0 是唯一的自环值**：$2x = x$ 仅当 $x = 0$。0 必须单独处理——它不能套用「消耗 $cnt[2 \cdot 0] = cnt[0]$」的通式（那会把全部 0 同时当作原数和二倍数，逻辑上自相矛盾）。偶数个 0 中恰有一半是原数。
3. **计数数组开到 $2 \times 10^5 + 1$**：$changed[i] \le 10^5$，但 $cnt[2v]$ 的下标最大到 $2 \times 10^5$；数组开小会在第 6 步越界。
4. **消耗方向**：总是「小值消耗大值」。扫描到 $v$ 时，$cnt[v]$ 里可能已经被更小的 $v/2$（若 $v$ 是偶数）消耗过一部分，剩余值才是 $v$ 作为原数的个数；因此判定与消耗都必须读**当前**的 $cnt$。
5. **返回顺序任意**：题目允许任意顺序，我们的实现天然按值升序输出（0 在最前），省去一次排序。
6. **复杂度选择**：值域计数版 $O(n + V)$；若值域无界，改用 `map`/排序 + 哈希计数，$O(n \log n)$。本题值域小，计数版最优。
7. **不要用「排序 + 双指针」的朴素版本**：双指针无法正确处理 $[2, 1, 2, 4]$ 这类「同一个值既是某数的二倍又是待配原数」的重叠情况，计数消耗才能表达「身份抢占」。

## 5. 正确性证明

**引理 1（原数组唯一性）**：若 `changed` 是双倍数组，则 `original` 的多重集合唯一。

**证明**：对 `changed` 的最小值 $v_1$ 分类。若 $v_1 > 0$：$original$ 中若有元素 $y$ 满足 $2y = v_1$，则 $y = v_1 / 2 < v_1$，而 $y$ 必须出现在 `changed` 中（$original \subseteq changed$），与 $v_1$ 最小矛盾。故 $v_1$ 的全部 $cnt[v_1]$ 次出现都必须属于 `original`，且每个需要一个 $2v_1$ 出现（属于二倍数部分）。若 $v_1 = 0$：0 的二倍数仍是 0，$cnt[0]$ 个 0 中恰有 $cnt[0]/2$ 个属于 `original`（二倍数部分的 0 与原数部分的 0 一一对应，两者个数相等）。于是第一层配对被唯一确定；从 `changed` 中删去这些原数与二倍数后，剩余多重集合仍是双倍数组（对应 `original` 去掉已确定元素），对其归纳即得整体唯一。∎

**引理 2（贪心可行性判定）**：从小到大扫描值 $v \ge 1$，设 $r_v$ 为扫描到 $v$ 时 $cnt[v]$ 的剩余值（已被更小值的消耗扣减过）。`changed` 是双倍数组当且仅当每个 $r_v \le$ 当前 $cnt[2v]$，且 $cnt[0]$ 为偶数，且每步消耗后不出现负数。

**证明**：由引理 1 的归纳论证，任何合法方案中值 $v$ 的「原数个数」恰为 $r_v$（更小值 $v/2$ 的原数个数已唯一确定并消耗了等量 $v$），且这 $r_v$ 个原数各自需要一个 $2v$，故必须 $cnt[2v] \ge r_v$；反之，若每步条件都满足，按「$r_v$ 个 $v$ 为原数 + 消耗 $r_v$ 个 $2v$」构造的划分恰好把所有计数清零（每个值要么全部作为原数被输出，要么全部作为二倍数被消耗，或两者兼有但身份不重叠），得到合法 `original`。∎

**定理**：算法返回的 `original` 正确，且当且仅当 `changed` 是双倍数组时非空。

**证明**：长度为奇数时 $original$ 与 $2 \cdot original$ 的并集大小必为偶数，返回空正确。长度为偶数时，由引理 2，算法的逐步判定与唯一合法方案完全一致：判定失败任意一步即无解，返回空；全部通过则输出的多重集恰为引理 1 唯一确定的 `original`。∎

## 6. 复杂度分析

- **时间**：$O(n + V)$，其中 $V = 2 \times 10^5 + 1$ 为值域规模。一次计数 $O(n)$，一趟值域扫描 $O(V)$，与 $n$ 无关的常数开销。
- **空间**：$O(V)$。计数数组 $200001$ 个 `int`（约 0.8 MB）；输出数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findOriginalArray(vector<int>& changed) {
        int n = (int)changed.size();
        if (n % 2 == 1) return {};                 // 双倍数组长度必为偶数
        const int V = 200001;
        vector<int> cnt(V, 0);
        for (int x : changed) ++cnt[x];
        vector<int> original;
        original.reserve(n / 2);
        if (cnt[0] % 2 == 1) return {};            // 0 只能与 0 配对，必须成偶数
        for (int i = 0; i < cnt[0] / 2; ++i) original.push_back(0);
        for (int v = 1; v <= 100000; ++v) {
            if (cnt[v] == 0) continue;
            if (cnt[2 * v] < cnt[v]) return {};    // 二倍数不够配 → 无解
            for (int i = 0; i < cnt[v]; ++i) original.push_back(v);
            cnt[2 * v] -= cnt[v];                  // 消耗：这些 2v 是二倍数
        }
        return original;
    }
};
```

### Python

```python
class Solution:
    def findOriginalArray(self, changed: list[int]) -> list[int]:
        n = len(changed)
        if n % 2:
            return []
        cnt = Counter(changed)
        if cnt[0] % 2:
            return []
        original = [0] * (cnt[0] // 2)             # 0 的一半进原数组
        for v in sorted(cnt):
            if v == 0:
                continue
            need = cnt[v]                           # 剩余的 v 全部是原数
            if need > cnt[2 * v]:
                return []
            original.extend([v] * need)
            cnt[2 * v] -= need
        return original
```

> 💡 两份代码均通过官方示例（`[1,3,4]`、`[]`、`[]`）与 0 特判用例，并与「枚举 $\binom{n}{n/2}$ 子集 + 多重集合精确比对」的暴力对拍了 4000 组随机数据（含半构造的有解数据与 $n = 10^5$ 大规模用例），`mismatch = 0`。

## 8. 边界情况与易错点

1. **长度为奇数**：第一时间返回空数组，不要带着奇数长度进入配对逻辑。
2. **0 的特判**：忘记 0 自环是本题最高频的 WA 点。把 0 当普通正数处理会得到「$cnt[0]$ 个 0 全是原数、消耗 $cnt[0]$ 个 0」的悖论式代码；正确做法是偶偶配对、输出一半。
3. **计数数组大小**：`cnt` 必须开到 $2 \times 10^5$，因为要访问 $cnt[2v]$；只开 $10^5$ 会在 $v > 50000$ 时越界。
4. **消耗时机**：必须**先判定后消耗**，且消耗发生在扫描到 $2v$ 之前。「排序后用双指针跳过已消耗元素」的写法极易在重复值上错乱，计数消耗是最不易错的形态。
5. **同一个值的双重身份**：如 $[2, 1, 2, 4]$ 中值 2 既是 1 的二倍数又是原数，只有「计数扣减」能正确表达这种身份流转。
6. **输出顺序**：题目允许任意顺序，不必对结果排序；但若用哈希表（如 `Counter`）实现，注意按 key 升序遍历，保证 $v$ 的原数消耗发生在 $2v$ 之前。
7. **`Counter` 的读零副作用**：Python 中 `cnt[2 * v]` 读取不存在的 key 返回 0 且不插入，安全；但 `cnt[2 * v] -= need` 若 key 不存在会从 0 起减成负数——先做大小判定即可避免。
