# LeetCode 查找包含给定字符的单词 题解

## 1. 题目概述

- **标题 / 题号**：查找包含给定字符的单词（#2942，easy）
- **链接**：https://leetcode.cn/problems/find-words-containing-character/
- **来源**：LeetCode 第 118 场双周赛 Q1
- **难度**：简单
- **标签**：数组、字符串

**题意**：给定字符串数组 `words` 与字符 `x`，返回一个下标数组，包含所有「含字符 $x$」的单词的下标。返回顺序任意。

**约束**：

- $1 \le \mathrm{words.length} \le 50$
- $1 \le \mathrm{words[i].length} \le 50$
- `x` 为小写字母，`words[i]` 只含小写字母

## 2. 示例

**示例 1**

```text
输入：words = ["leet","code"], x = "e"
输出：[0,1]
解释："e" 同时出现在 "l(e)et" 与 "cod(e)" 中。
```

**示例 2**

```text
输入：words = ["abc","bcd","aaaa","cbc"], x = "a"
输出：[0,2]
解释："a" 出现在 "a bc" 与 "a aaa" 中，不在 "bcd"、"cbc" 中。
```

**示例 3**

```text
输入：words = ["abc","bcd","aaaa","cbc"], x = "z"
输出：[]
解释：没有任何单词含 "z"，返回空数组。
```

## 3. 解题思路

### 3.1 暴力思路

对每个单词逐字符扫描，遇到 $x$ 记录下标并立刻跳出内层循环（后面再出现也不影响结果）。总字符数 $\le 50 \times 50 = 2500$，$O(|\Sigma|)$ 之外毫无优化空间——这就是签到题的定位：考察「遍历 + 收集」的基本功与**提前跳出**的小习惯。

### 3.2 核心观察：一次线性过滤

![核心观察：过滤式收集下标](images/bw118_q1_filter_indices.svg)

把问题看成一条**过滤流水线**：数组下标依次流过「单词是否含 $x$」的判定器，通过者进入结果列表。判定用语言内建的子串搜索即可：C++ `string::find(x) != npos`、Python `x in word`，它们内部就是一次线性扫描（CPython 对短串用的是混合算法，等价于线性）。**不需要**正则、不需要建哈希集合——单词长度只有 50，任何预处理都是负优化。

### 3.3 算法流程

![算法流程：两重循环与短路跳出](images/bw118_q1_algorithm_flow.svg)

```text
1. ans = []
2. for i in 0..len(words)-1:
3.     if x in words[i]:        # 内部线性扫描，找到即可短路
4.         ans.append(i)
5. 返回 ans
```

### 3.4 示例演算

以示例 2（`["abc","bcd","aaaa","cbc"]`，`x = "a"`）走查：

| i | words[i] | 首次出现位置 | 是否收录 |
|---|----------|--------------|----------|
| 0 | `"abc"` | 0 | ✓ |
| 1 | `"bcd"` | 无 | ✗ |
| 2 | `"aaaa"` | 0 | ✓ |
| 3 | `"cbc"` | 无 | ✗ |

结果 `[0, 2]` ✓。注意 `"aaaa"` 虽然出现 4 次，但只需判定「出现过」，收录一次即可。

## 4. 算法细节

1. **短路跳出**：内层扫描找到第一个 $x$ 就 `break`。对 `"aaaa"` 这类单词能省 3 次比较——本量级无感，但避免无意义的重复判定是好习惯。
2. **内建搜索的语义**：`find` 返回 `npos` 表示未找到；Python 的 `in` 返回布尔。两者都是**大小写敏感**的精确字符匹配，题面保证全小写，无需归一化。
3. **返回顺序任意**：题目明说「任意顺序」，正序收集最自然；若用倒序遍历也正确，不必排序。
4. **空结果**：所有单词都不含 $x$ 时返回空列表，不是 `null`。
5. **复杂度下界**：必须至少读完每个单词的最长前缀（直到首个 $x$），故 $O(\sum |\mathrm{words}[i]|)$ 是信息论下界，本解法已最优。

## 5. 正确性证明

**引理 1**：`x in words[i]` 为真，当且仅当存在下标 $k$ 使 $\mathrm{words}[i][k] = x$。

**证明**：`in` / `find` 的语义即线性搜索：逐位比较，任一位相等返回真，全部不等返回假。∎

**定理**：算法返回的集合恰为 $\{\, i \mid \exists k:\ \mathrm{words}[i][k] = x \,\}$。

**证明**：循环对每个 $i \in [0, n)$ 恰好判定一次条件。由引理 1，条件为真当且仅当第 $i$ 个单词含 $x$；条件为真时 $i$ 被加入 `ans` 且仅加一次（外层循环每个 $i$ 只执行一次 `append`），为假时不加。故 `ans` 中的元素与目标集合一一对应，又因 `append` 顺序即 $i$ 递增序，无重复。∎

## 6. 复杂度分析

- **时间**：$O\!\left(\sum_i |\mathrm{words}[i]|\right) \le O(50 \times 50) = O(2500)$，即总字符数的线性扫描；每个字符至多比较一次。
- **空间**：$O(1)$ 额外空间（不计返回列表；返回列表至多 $n$ 个下标）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findWordsContaining(vector<string>& words, char x) {
        vector<int> ans;
        for (int i = 0; i < (int)words.size(); ++i)
            if (words[i].find(x) != string::npos)   // 线性搜索，命中即短路
                ans.push_back(i);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findWordsContaining(self, words: list[str], x: str) -> list[int]:
        return [i for i, w in enumerate(words) if x in w]
```

> 💡 两份代码均通过官方示例（`[0,1]`、`[0,2]`、`[]`）与 2 万组随机数据（字母表限定 `abc` 以高频命中）和逐字符暴力判定的对拍（`mismatch = 0`）。

## 8. 边界情况与易错点

1. **全部命中 / 全不命中**：前者返回 $[0, 1, \dots, n-1]$，后者返回 `[]`。两种极端都不要特判，循环天然覆盖。
2. **单词内多次出现**：只收录一次下标；若误把「出现次数」当「下标数」会返回重复下标。
3. **`char` vs `string`**：C++ 中 `x` 是 `char`，`find(x)` 用字符重载；误写成 `find("x")` 会构造临时 `string`，功能相同但多余开销，语义上也要保持类型一致。
4. **下标类型**：`words.size()` 是无符号数，`i < words.size()` 与 `int i` 混用时若数组为空会有告警；本题 $n \ge 1$ 无碍，但建议 `(int)words.size()` 显式转换。
5. **大小写**：题面保证全小写。若去 `tolower` 反而画蛇添足且可能改变语义。
6. **不要过度设计**：建 26 叉 trie、哈希表缓存每个单词的字符集，在本规模下都是负优化；签到题的正解就是最短路径。
