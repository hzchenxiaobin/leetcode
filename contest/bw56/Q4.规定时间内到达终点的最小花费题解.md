# LeetCode 规定时间内到达终点的最小花费 题解

## 1. 题目概述

- **标题 / 题号**：规定时间内到达终点的最小花费（#1928，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-reach-destination-in-time/
- **来源**：LeetCode 第 56 场双周赛 Q4
- **难度**：困难
- **标签**：图、动态规划、最短路

**题意**：$n$ 座城市（编号 $0 \sim n-1$）由双向道路连接成连通图，`edges[i] = [x, y, time]` 表示 $x, y$ 之间耗时 $\mathit{time}$ 分钟（两点间可能有多条道路，无自环）。**每经过一座城市**（含起点与终点、重复经过每次都算）需付该城通行费 $\mathit{passingFees}[j]$。从城市 $0$ 出发，要在 **$\mathit{maxTime}$ 分钟以内（含）**到达城市 $n-1$，求最小总通行费；不可达返回 $-1$。

**约束**：

- $1 \le \mathit{maxTime} \le 100$
- $n = \mathit{passingFees.length}$，$2 \le n \le 1000$
- $1 \le \mathit{edges.length} \le 2000$，$0 \le x_i, y_i \le n - 1$，$1 \le \mathit{time}_i \le 100$
- $1 \le \mathit{passingFees}[j] \le 1000$；图连通、可能有重边、无自环

## 2. 示例

**示例 1**

```text
输入：maxTime = 30, edges = [[0,1,10],[1,2,10],[2,5,10],[0,3,1],[3,4,10],[4,5,15]],
      passingFees = [5,1,2,20,20,3]
输出：11
解释：0 → 1 → 2 → 5，耗时 30 分钟（恰好不超），费用 5 + 1 + 2 + 3 = 11。
```

**示例 2**

```text
输入：maxTime = 29, （其余同上）
输出：48
解释：时间预算缩到 29，路径 0 → 1 → 2 → 5 超时；改走 0 → 3 → 4 → 5，
      耗时 1 + 10 + 15 = 26 ≤ 29，费用 5 + 20 + 20 + 3 = 48。
```

**示例 3**

```text
输入：maxTime = 25, （其余同上）
输出：-1
解释：两条路分别要 30 与 26 分钟，均超时，无法到达。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有时间预算内的途径（walk）逐条算费用——分支随步数指数增长，显然不可行。那么最短路算法呢？**普通 Dijkstra 在这里直接失效**：把「费用」当最短路的键，先按费用贪心扩展，第一条到达 $n-1$ 的路径未必满足时间限制；把「时间」当键，时间最省的路径可能贵得离谱。费用与时间**互相牵制**（示例 1 与 2 正是两组解互相不可比较的活例子），单一键值的贪心序不存在。这正是本题「困难」的根源：**两个优化目标必须同时进入状态**。

### 3.2 核心观察：把「到达时刻」并进状态，得到沿时间维严格前进的分层图

![分层图模型：状态 (city, time)，所有转移沿时间维向前](images/bw56_q4_layered_graph.svg)

由于每条边的耗时 $\ge 1$，**时间只进不退**——把状态定义为「**到达时刻 $t$ 时身处城市 $u$**」（记为状态 $(u, t)$），则每条原图的边 $(u, v, w)$ 对应分层图中 $t \to t + w$ 的转移，所有转移**严格沿时间维向前**。这张分层图是一个 **DAG**（无环），于是不必动用任何最短路算法：按 $t$ 从小到大做一遍 DP 即可。

$$
\mathit{dp}[t][u] \;=\; \text{在时刻 } t \text{ 恰好位于城市 } u \text{ 的最小总费用（含起点费与沿途各城费用）}
$$

规模恰好卡进约束的缝隙：$\mathit{maxTime} \le 100$、$\mathit{edges.length} \le 2000$，状态转移总量 $100 \times 2000 \times 2 = 4 \times 10^5$。

答案不是 $\mathit{dp}[\mathit{maxTime}][n-1]$，而是 $\min_{0 \le t \le \mathit{maxTime}} \mathit{dp}[t][n-1]$——**途径在任何时刻抵达终点都算成功**，不必消磨到时间上限（也不能「原地等待」，但多走几步浪不浪费时间无所谓，取最小即可）。

### 3.3 状态转移

![转移流程：按 t 升序扫每条边，双向松弛 dp[t+w][v]](images/bw56_q4_dp_flow.svg)

初值：$\mathit{dp}[0][0] = \mathit{passingFees}[0]$（出发即缴起点费），其余 $\infty$。按 $t = 0, 1, \dots, \mathit{maxTime} - 1$ 升序填表，对每条边 $(u, v, w)$（双向）：

$$
\mathit{dp}[t + w][v] \gets \min(\mathit{dp}[t + w][v],\ \mathit{dp}[t][u] + \mathit{passingFees}[v])
$$

（同时做 $u \leftrightarrow v$ 对称的另一个方向；$t + w > \mathit{maxTime}$ 的转移丢弃。）

### 3.4 示例演算

![示例演算：maxTime 30/29/25 三种预算下的最优途径对比](images/bw56_q4_example_walkthrough.svg)

以官方用例（6 城、6 边、费率 $[5,1,2,20,20,3]$）为：

| 途径 | 耗时 | 费用 | maxTime=30 | maxTime=29 | maxTime=25 |
|------|------|------|------|------|------|
| $0 \to 1 \to 2 \to 5$ | $10+10+10=30$ | $5+1+2+3=11$ | ✓ 最优 | 超时 | 超时 |
| $0 \to 3 \to 4 \to 5$ | $1+10+15=26$ | $5+20+20+3=48$ | 可行但贵 | ✓ 最优 | 超时 |
| （其他绕路） | $> 26$ | 更贵 | — | — | — |

DP 会在 $t = 26$ 层把状态 $(5, 26)$ 填成 48、在 $t = 30$ 层填成 11，随后对 $t \le \mathit{maxTime}$ 的 $\mathit{dp}[t][5]$ 取最小：预算 30 时两者都可见取 11；预算 29 时只剩 26 层的 48；预算 25 时 $(5, t)$ 全为 $\infty$ 返回 $-1$。这个例子同时演示了「更贵但更快的路径为何必须保留在状态里」——若只留每个城市费用最小的途径，26 分钟的备份路线早被 11 的假象挤掉了。

## 4. 算法细节

1. **「恰好时刻」的合法性**：费用在到达城市时缴纳，每到达一次缴一次；$\mathit{dp}[t][u]$ 的语义是「**恰在**时刻 $t$ 位于 $u$」的最小费用，同一城市不同时刻各存一份，互不覆盖——这是两条优劣互换的途径能共存的原因。
2. **起点费**：$\mathit{dp}[0][0] = \mathit{passingFees}[0]$，别在转移时对 $0$ 再收一次；若途中折返城市 $0$，按到达正常再缴（DP 转移自然处理）。
3. **重边零成本处理**：两点间多条时间不同的边各自独立参与转移，谁快谁慢交给 DP 竞争，无需预处理去重。
4. **无用的层跳过**：某层全部 $\infty$ 时内层循环照样空转，直接让 `dp[t][u] < INF` 的判断短路即可，无需显式特判。
5. **溢出**：途径最多 $\mathit{maxTime}$ 条边 + 起点，总费用 $\le 101 \times 1000 \approx 10^5$，`int` 无压力；但 `INF` 取 `INT_MAX/2` 防止 `INF + fee` 加法溢出。
6. **答案对 $t$ 取 min**：$n \ge 2$ 保证 $t = 0$ 不可能是答案层；遍历全部 $t \le \mathit{maxTime}$ 的 $\mathit{dp}[t][n-1]$。
7. **为什么不用带支配剪枝的 Dijkstra**：把状态 $(u, t)$ 建成优先队列按费用弹出、首弹即定值的做法同样正确且同阶，但分层 DP 的实现只有三重循环、无堆无 visited，比赛里更短更稳；两者复杂度都是 $O(\mathit{maxTime} \cdot E)$（Dijkstra 版多一个 $\log$）。

## 5. 正确性证明

**引理 1（分层图是 DAG）**：所有转移 $(u, t) \to (v, t + w)$ 满足 $w \ge 1$，即转移严格增大 $t$；故状态图无环，按 $t$ 升序处理即可让每个状态在被使用前已获得最终值。

**证明**：设存在环 $(u_1, t_1) \to \cdots \to (u_k, t_k) \to (u_1, t_1)$，环上每条转移 $t$ 至少增 1，绕环一周 $t_1 > t_1$，矛盾。∎

**引理 2（状态刻画）**：按算法填表后，$\mathit{dp}[t][u]$ 等于「从城市 0 出发、恰在时刻 $t$ 到达城市 $u$、且每经一城缴费（含起点、重复经过重复缴）」的所有途径的最小费用；不可达时为 $\infty$。

**证明**：对 $t$ 归纳。$t = 0$：只有「原地待在 0」一种途径，费用即起点费，与初值一致（其他城市不可达）。设时刻 $< t$ 的层均正确。任取时刻 $t$ 到达 $u$ 的途径 $P$，其最后一步是沿某条边 $(u', u, w)$ 于时刻 $t - w$ 从 $u'$ 出发，前缀 $P'$ 是「时刻 $t - w$ 到达 $u'$」的途径，费用 $\mathit{fee}(P) = \mathit{fee}(P') + \mathit{passingFees}[u]$。由归纳假设 $\mathit{fee}(P') \ge \mathit{dp}[t - w][u']$，故 $\mathit{fee}(P) \ge \mathit{dp}[t - w][u'] + \mathit{passingFees}[u] \ge \mathit{dp}[t][u]$（该转移被算法枚举）。反之，$\mathit{dp}[t][u]$ 的每个候选都对应一条真实途径（$\infty$ 除外），由归纳可构造。故 $\mathit{dp}[t][u]$ 恰为最小值。∎

**定理（主结果）**：$\min_{0 \le t \le \mathit{maxTime}} \mathit{dp}[t][n-1]$ 即题目所求的最小费用；全为 $\infty$ 时无可行途径，返回 $-1$ 正确。

**证明**：一条途径合法当且仅当它从城市 0 出发、终于城市 $n-1$、总耗时 $t \le \mathit{maxTime}$。由引理 2，每个时刻 $t$ 的最优费用都在 $\mathit{dp}[t][n-1]$ 中，且合法途径与其 DP 值一一对应；对 $t \le \mathit{maxTime}$ 取 min 恰好枚举了所有「到达时刻不超预算」的情形。耗时恰为某 $t$ 的途径不会在取 min 时遗漏（它就落在那一层），耗时相同 $t$ 越大不占优也不影响正确性。若所有层均为 $\infty$，说明预算内无任何途径抵达 $n-1$，图虽连通但边权 $\ge 1$ 使时间约束可能不可满足，返回 $-1$。∎

## 6. 复杂度分析

- **时间**：$O(\mathit{maxTime} \cdot E)$。外层 $t$ 共 $\mathit{maxTime} \le 100$ 层，每层扫全部 $E \le 2000$ 条边、每条边做两个方向的松弛，共约 $4 \times 10^5$ 次转移。
- **空间**：$O(\mathit{maxTime} \cdot n)$。DP 表 $100 \times 1000 = 10^5$ 个整数（约 400KB）；无需邻接表以外的高维结构（直接扫边表甚至省去邻接表）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(int maxTime, vector<vector<int>>& edges, vector<int>& passingFees) {
        int n = passingFees.size();
        const int INF = INT_MAX / 2;
        vector<vector<int>> dp(maxTime + 1, vector<int>(n, INF));
        dp[0][0] = passingFees[0];                     // 出发即缴起点费
        for (int t = 0; t < maxTime; ++t) {             // 按到达时刻升序填表
            for (auto& e : edges) {
                int u = e[0], v = e[1], w = e[2];
                if (t + w > maxTime) continue;
                if (dp[t][u] < INF)
                    dp[t + w][v] = min(dp[t + w][v], dp[t][u] + passingFees[v]);
                if (dp[t][v] < INF)
                    dp[t + w][u] = min(dp[t + w][u], dp[t][v] + passingFees[u]);
            }
        }
        int ans = INF;
        for (int t = 0; t <= maxTime; ++t) ans = min(ans, dp[t][n - 1]);
        return ans >= INF ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minCost(self, maxTime: int, edges: list[list[int]], passingFees: list[int]) -> int:
        n = len(passingFees)
        INF = float('inf')
        # dp[t][u]：恰在时刻 t 位于城市 u 的最小总费用
        dp = [[INF] * n for _ in range(maxTime + 1)]
        dp[0][0] = passingFees[0]                      # 出发即缴起点费
        for t in range(maxTime):                       # 按到达时刻升序填表
            for u, v, w in edges:
                if t + w > maxTime:
                    continue
                if dp[t][u] < INF:
                    c = dp[t][u] + passingFees[v]
                    if c < dp[t + w][v]:
                        dp[t + w][v] = c
                if dp[t][v] < INF:
                    c = dp[t][v] + passingFees[u]
                    if c < dp[t + w][u]:
                        dp[t + w][u] = c
        best = min(dp[t][n - 1] for t in range(maxTime + 1))
        return -1 if best == INF else best
```

> 💡 两份代码均通过全部官方示例（`11`、`48`、`-1`）；另与**两条独立参照**对拍——(a) 全途径穷举 DFS（无任何剪枝，指数枚举每条时间预算内的途径）在 2000 组小图上逐组比对；(b) 堆优化 Dijkstra（按 `(费用, 时刻)` 弹出、`dist[time][city]` 首弹即定）在 300 组（C++）/ 200 组（Python）随机连通图（$n \le 50$，含重边）上比对，`mismatch = 0`；$n = 1000$、$E = 2000$ 大图性能冒烟通过。

## 8. 边界情况与易错点

1. **答案是「所有时刻」的 min，不是 $\mathit{dp}[\mathit{maxTime}][n-1]$**：到达后行程即结束，不需要也不能原地消磨时间；漏掉对 $t$ 的遍历会在「快而贵到得早」的用例上出错。
2. **起点费**：$\mathit{dp}[0][0]$ 必须预置 $\mathit{passingFees}[0]$；漏掉会把所有费用少算一笔。
3. **单键 Dijkstra 的诱惑**：只按费用跑 Dijkstra、给每个城市打 visited 的做法在示例 2/3 上直接翻车——先到 $n-1$ 的可能超时；只按时间同理。**两个维度都必须进状态**。
4. **`INF` 防溢出**：C++ 用 `INT_MAX / 2`，转移前判 `dp[t][u] < INF`；直接 `INT_MAX + fee` 是未定义行为。
5. **重边与回环**：图允许重边（不同耗时），也允许途经城市折返（重复缴费）；DP 对每条边独立松弛天然兼容，千万不要「去重」或「禁止回头」。
6. **时间上限恰好的途径**：示例 1 耗时恰为 $\mathit{maxTime} = 30$，`t + w > maxTime` 用**严格大于**判丢弃，边界别写成 $\ge$。
7. **层内顺序无关紧要**：因为转移只写「未来层」$t + w \ge t + 1$，当前层 $t$ 只读不写，内层先做 $u \to v$ 还是 $v \to u$ 都不影响结果。
8. **`-1` 的语义**：图保证连通，但时间预算可能不足（示例 3）；`dp` 全 $\infty$ 才返回 $-1$，别把「$\mathit{dp}[\mathit{maxTime}][n-1] = \infty$」当成不可达。

**延伸思考**：本题的方法学名称是「**分层图 / 扩维最短路**」：当一个资源约束（时间、剩余体力、可消除障碍数、免费升级次数）不能被贪心键吸收时，就把它并入状态、把原图的边沿约束维展开。判别式很简单——**两个方案互相支配不了（一个便宜超时、一个贵但准时），单键贪心就失效**。进一步：若 $\mathit{maxTime}$ 大到 $10^9$，分层不可行，需转用「支配对剪枝」的 Dijkstra（状态 $(u, t)$ 只保留费用-时间**互不支配**的方案集合，`dist[u]` 维护一个 Pareto 前沿，配合松弛每个状态至多被更新 $O(\log)$ 次的势能论证）；若边权只有 0/1，可用双端队列 BFS 把每层代价压到线性。分层 DP 还有一个反向应用——「恰好 $k$ 条边」的约束把**下界**也变成维度（LC 787 的 $k$ 站中转即「边数 $\le k+1$」），上下界约束统称**资源约束最短路**，是状态空间设计的万能模板。
