# LeetCode 完成旅途的最少时间 题解

## 1. 题目概述

- **标题 / 题号**：完成旅途的最少时间（#2187，medium）
- **链接**：https://leetcode.cn/problems/minimum-time-to-complete-trips/
- **来源**：LeetCode 第 282 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找

**题意**：给定数组 `time`，`time[i]` 表示第 $i$ 辆公交车跑**一趟**旅途所需的时间。每辆车跑完一趟**立即**开始下一趟、连续运转，各车**独立并行**、互不影响。给定整数 `totalTrips`，表示所有公交车**合计**需要完成的旅途趟数，求完成**至少** `totalTrips` 趟所需的最少时间。

**约束**：

- $1 \le \text{time.length} \le 10^5$
- $1 \le \text{time}[i], \text{totalTrips} \le 10^7$

> 💡 **读题定位**：直接问「最少时间」，且时间越大越容易完成任务——答案是**单调**的，而判断「给定时间 $t$ 能否完成」只需 $O(n)$ 一次求和。这两个信号合起来就是「**二分答案**」的标准面孔：不构造方案，而是把「求最优值」转化为「在有序值域上找第一个满足条件的值」。本题是 875/1011 一族的模板题，赛场上应在 1~2 分钟内完成识别；真正的分差在于**边界与溢出细节**（见 §8）。

## 2. 示例

**示例 1**（官方）

```text
输入：time = [1,2,3], totalTrips = 5
输出：3
解释：
- t=1 时各车完成 [1,0,0]，合计 1 趟；
- t=2 时各车完成 [2,1,0]，合计 3 趟；
- t=3 时各车完成 [3,1,1]，合计 5 趟 ≥ 5。
所以最少时间为 3。
```

**示例 2**（官方）

```text
输入：time = [2], totalTrips = 1
输出：2
解释：只有一辆公交车，它在时刻 t = 2 完成第一趟旅途。
```

**示例 3**（自造：隔离「上界很松」这一变量）

```text
输入：time = [5,7], totalTrips = 6
输出：20
解释：trips(t) = ⌊t/5⌋ + ⌊t/7⌋：
- t = 19：3 + 2 = 5 < 6；
- t = 20：4 + 2 = 6 ≥ 6 ✓。
而上界 min(time) × totalTrips = 5 × 6 = 30 —— 远松于答案 20。
注意答案 20 恰是 5 的倍数（见 §4 第 3 条的观察）。
```

## 3. 解题思路

### 3.1 暴力思路

从 $t = 1$ 起逐时刻检查：每个 $t$ 用 $O(n)$ 算出所有车在 $t$ 时刻的完成趟数之和

$$\text{trips}(t) = \sum_{i} \left\lfloor \frac{t}{\text{time}[i]} \right\rfloor,$$

第一个满足 $\text{trips}(t) \ge \text{totalTrips}$ 的 $t$ 即答案。但答案上界可达 $\min(\text{time}) \times \text{totalTrips} \le 10^{14}$，逐时刻模拟是 $O(n \cdot 10^{14})$，完全不可行。数据范围（$10^5$ 辆车、$10^7$ 的值）本身就是提示：$O(n \log M)$ 的对数复杂度才能过。

### 3.2 核心观察：trips(t) 单调不减 → 二段性 → 二分答案

![核心观察：trips(t) 单调不减，可行与不可行构成二段性](images/wc282_q3_monotone_concept.svg)

关键在于 $\text{trips}(t)$ 关于 $t$ **单调不减**：

- $t$ 变大时，每辆车的 $\lfloor t / \text{time}[i] \rfloor$ 只增不减——时间多给一点，任何车都不可能「跑出负数趟」；
- 于是值域被切成**一红一绿两段**：存在最小可行时刻 $t^*$，使 $t < t^*$ 时跑不完、$t \ge t^*$ 时跑得完。

这正是二分查找所需的**二段性**。与「在有序数组里二分下标」不同，这里**二分的对象是答案本身**：直接在候选时间区间 $[1, \min(\text{time}) \times \text{totalTrips}]$ 上定位 $t^*$。

- **下界 $lo = 1$**：$\text{time}[i] \ge 1$，跑完一趟至少 1 单位时间；且 $\text{trips}(0) = 0 < T$ 必不可行。
- **上界 $hi = \min(\text{time}) \times \text{totalTrips}$**：让**最快的**一辆车独跑完全部 $T$ 趟，此刻它自己就完成了 $T$ 趟，必然可行。注意该乘积可达 $10^7 \times 10^7 = 10^{14}$，超出 32 位 `int`，C++ 中必须用 `long long`。

> 💡 **识别信号**：题目求「最小的满足某条件的值」+ 该条件随值增大**只会从假变真**（单调）+ 单次验证 $O(n)$ → 二分答案。周赛里这类题通常作为 Q2/Q3 的「签到套路题」出现，比拼的是模板熟练度与边界处理。

### 3.3 算法流程

![算法流程：闭区间二分，可行向左收缩，不可行向右扩张](images/wc282_q3_binary_search_flow.svg)

采用**闭区间二分**，不维护 `ans` 变量，靠不变式保证结束时 `lo` 就是答案：

1. 初始化 $lo = 1$，$hi = \min(\text{time}) \times \text{totalTrips}$；
2. 循环不变式：**$lo - 1$ 及其左侧全部不可行，$hi + 1$ 及其右侧全部可行**（初始由上下界的取法保证）；
3. 每轮取 $mid = lo + (hi - lo) / 2$，用 $O(n)$ 检查 $\text{trips}(mid) \ge T$ 是否成立：
   - **可行**：说明 $t^* \le mid$，向左收缩，$hi = mid - 1$；
   - **不可行**：说明 $t^* > mid$，向右扩张，$lo = mid + 1$；
4. 当 $lo > hi$ 时区间为空，由不变式，$lo = hi + 1$ 恰好是第一个可行位置，**返回 $lo$**。

`check()` 内部累加 $\lfloor mid / \text{time}[i] \rfloor$ 时，**一旦累计 $\ge \text{totalTrips}$ 就立即返回**——既是实践加速，更是防溢出的关键（见 §8 第 2 条）。

### 3.4 示例演算

![示例演算：三轮二分收敛到答案 3](images/wc282_q3_walkthrough.svg)

以 `time = [1,2,3]`、`totalTrips = 5` 为例，$hi = \min(\text{time}) \times T = 1 \times 5 = 5$，二分区间 $[1, 5]$：

- **第 1 轮** $[1,5]$，$mid=3$，$\text{trips}(3) = 3+1+1 = 5 \ge 5$ ✓ → 可行，$hi = 2$；
- **第 2 轮** $[1,2]$，$mid=1$，$\text{trips}(1) = 1+0+0 = 1 < 5$ ✗ → 不可行，$lo = 2$；
- **第 3 轮** $[2,2]$，$mid=2$，$\text{trips}(2) = 2+1+0 = 3 < 5$ ✗ → 不可行，$lo = 3$；
- 此时 $lo = 3 > hi = 2$，循环结束，返回 $lo = 3$ ✓。

验证：$\text{trips}(2) = 3 < 5$、$\text{trips}(3) = 5 \ge 5$，$3$ 恰为分界点。

## 4. 算法细节

1. **`check(t)` 的写法**：遍历一遍累加 $\lfloor t / \text{time}[i] \rfloor$ 即可，整数除法天然向下取整（一趟没跑完的时间不计入）。**提前退出**：一旦累计值达到 `totalTrips` 立即返回 `true`。这不仅省时间，更是防溢出——见第 2 条。

2. **两处必须防范的溢出**（C++）：
   - **上界乘法**：`min(time) × totalTrips` 可达 $10^{14}$，`int × int` 在乘法阶段就已溢出，必须**先强转再乘**：`(long long)mn * totalTrips`；
   - **`check` 累加**：$mid$ 可达 $10^{14}$，若某辆车 $\text{time}[i] = 1$，单项即 $10^{14}$；$n = 10^5$ 辆车全加总可达 $10^{19}$，超过 `long long` 上限 $\approx 9.2 \times 10^{18}$。提前退出保证累计值始终 $\le (T - 1) + mid \le 2 \times 10^{14}$，安全。

3. **答案必为某个 `time[i]` 的倍数**（有趣的性质，本题用不上）：$\text{trips}(t)$ 是阶梯函数，取值只在 $t$ 跨过某个 $\text{time}[i]$ 的倍数时跳变。若 $t^*$ 可行而 $t^* - 1$ 不可行，则 $\text{trips}$ 在 $t^*$ 处必然跳变，即**恰有一辆车在 $t^*$ 时刻完成一趟**，故 $t^* \equiv 0 \pmod{\text{time}[i]}$（对某辆 $i$）。这解释了示例 3 中答案 $20 = 4 \times 5$。可作为提交后的 sanity check，但不必写进算法。

4. **二分模板的选择**：本文用「闭区间 + 结束返回 $lo$」——不变式清晰（§5），少一个变量。等价写法还有「可行时记 `ans = mid`」「左边界模板 `while lo < hi`」等，赛场用最不容易写错的那套。切忌混搭：`while (lo <= hi)` 必须配 `hi = mid - 1` / `lo = mid + 1`，写成 `hi = mid` 会在 $lo = mid$ 时死循环。

5. **上下界都可以取松**：下界取 $0$、上界取 $\max(\text{time}) \times T$ 甚至 $10^{18}$ 都不影响正确性（不变式同样成立），只是多几轮二分（$\log$ 级，可忽略）。取紧上下界是好习惯，但本题不必强求「恰好紧」——上界只需**保证可行**即可。

## 5. 正确性证明

记 $T = \text{totalTrips}$，$P(t)$ 表示谓词「$\text{trips}(t) \ge T$」（时刻 $t$ 足够完成全部旅途），$t^* = \min \{\, t \ge 1 : P(t) \,\}$ 为所求答案。

**引理 1（单调性）**：对任意 $t_1 \le t_2$，有 $\text{trips}(t_1) \le \text{trips}(t_2)$。特别地，$P$ 单调：$P(t_2) \Rightarrow P(t_1)$ 不一定，但 $\neg P(t_1) \Rightarrow \neg P(t_2 \text{ 以下})$——准确地说，若 $P(t_1)$ 真则对一切 $t \ge t_1$，$P(t)$ 真；若 $P(t_2)$ 假则对一切 $t \le t_2$，$P(t)$ 假。

**证明**：对每辆固定的车 $i$，$t_1 \le t_2 \Rightarrow \lfloor t_1 / \text{time}[i] \rfloor \le \lfloor t_2 / \text{time}[i] \rfloor$（分母为正时商随被除数不减）。对 $i$ 求和即得 $\text{trips}$ 单调不减，两个推论随之成立。∎

**引理 2（存在性与边界）**：$t^*$ 存在，且 $1 \le t^* \le M$，其中 $M = \min(\text{time}) \times T$。

**证明**：$\text{trips}(0) = 0 < T$（因 $T \ge 1$），故 $P(0)$ 假；取最快的车 $j$（$\text{time}[j] = \min(\text{time})$），在时刻 $M$ 它独自完成 $\lfloor M / \text{time}[j] \rfloor = T$ 趟，故 $\text{trips}(M) \ge T$，$P(M)$ 真。由引理 1，集合 $\{\, t : P(t) \,\}$ 非空（含 $M$）且为一段连续整数后缀，其最小元即 $t^*$，落在 $[1, M]$ 内。∎

**引理 3（区间不变式）**：算法每轮循环条件判断时，恒有：(a) 对一切 $t < lo$，$P(t)$ 假；(b) 对一切 $t > hi$，$P(t)$ 真。

**证明**：对迭代轮数归纳。

- **初始**：$lo = 1$，$t < 1$ 即 $t = 0$，$P(0)$ 假，(a) 成立；$hi = M$，由引理 2 $P(M)$ 真，再由引理 1 右推论，一切 $t \ge M$（更强地，$t > M$）皆真，(b) 成立。
- **保持**：设本轮 (a)(b) 成立，$lo \le hi$，取 $mid = \lfloor (lo + hi)/2 \rfloor \in [lo, hi]$。
  - 若 $P(mid)$ 假：由引理 1 右推论，一切 $t \le mid$ 皆假，故新 $lo = mid + 1$ 使 (a) 保持；(b) 未涉及 $hi$，不变。
  - 若 $P(mid)$ 真：由引理 1 左推论，一切 $t \ge mid$ 皆真，故新 $hi = mid - 1$ 使 (b) 保持（$t > mid - 1 \Leftrightarrow t \ge mid$）；(a) 未涉及 $lo$，不变。∎

**定理**：算法终止并返回 $t^*$。

**证明**：每轮迭代后区间长度至少减半（$mid$ 被排除后新区间严格变小），故循环必终止。终止时 $lo = hi + 1$。由引理 3：(a) 一切 $t \le hi = lo - 1$ 皆假，(b) 一切 $t \ge lo$ 皆真。于是 $lo$ 是第一个使 $P$ 为真的整数，即 $t^*$。∎

> 💡 **证明结构复盘**：引理 1 是二分答案类题目的「发动机」——单调性把连续的可行性判断折叠成一个分界点；引理 2 确认分界点落在二分区间内（上下界取值的正确性依据）；引理 3 是标准的「不变式收缩」论证，是所有闭区间二分正确性的通用骨架。把这三步背熟，任何二分答案题的证明都能现场套写。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log M)$，其中 $M = \min(\text{time}) \times \text{totalTrips} \le 10^{14}$，$\log_2 M \approx 47$。二分共 $O(\log M)$ 轮，每轮 `check` 遍历一遍 $O(n)$（提前退出只会更快）。本题 $n \le 10^5$，总运算量约 $4.7 \times 10^6$ 次整数除法，远低于时限。
- **空间复杂度**：$O(1)$，仅使用常数个额外变量（`lo`/`hi`/`mid`/累加器），不随输入规模增长。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long minimumTime(vector<int>& time, int totalTrips) {
        long long lo = 1;
        long long hi = (long long)(*min_element(time.begin(), time.end())) * totalTrips;
        while (lo <= hi) {
            long long mid = lo + (hi - lo) / 2;
            if (canFinish(time, mid, totalTrips)) {
                hi = mid - 1;   // mid 可行：t* <= mid，向左收缩
            } else {
                lo = mid + 1;   // mid 不可行：t* > mid，向右扩张
            }
        }
        return lo;              // 循环结束时 lo = hi + 1 = 最小可行 t*
    }

  private:
    // 时刻 t 内所有车完成的旅途总数是否 >= totalTrips
    bool canFinish(const vector<int>& time, long long t, int totalTrips) {
        long long total = 0;
        for (int ti : time) {
            total += t / ti;
            if (total >= totalTrips) return true;   // 提前退出，防溢出
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def minimumTime(self, time: List[int], totalTrips: int) -> int:
        lo, hi = 1, min(time) * totalTrips
        while lo <= hi:
            mid = (lo + hi) // 2
            if self._can_finish(time, mid, totalTrips):
                hi = mid - 1     # 可行：向左找更小
            else:
                lo = mid + 1     # 不可行：加大时间
        return lo                 # lo = hi + 1 即最小可行时间

    def _can_finish(self, time: List[int], t: int, totalTrips: int) -> bool:
        total = 0
        for ti in time:
            total += t // ti
            if total >= totalTrips:   # 提前退出
                return True
        return False
```

> ⚠️ Python 的整数无上限，两处溢出问题都不存在；但 `min(time) * totalTrips` 仍建议照抄——它在 C++ 里是致命错误，保持两种语言写法一致能减少赛场切换的心智负担。

## 8. 边界情况与易错点

1. **上界乘法溢出**（最高频 WA 点）：`min(time) * totalTrips` 最大 $10^7 \times 10^7 = 10^{14}$，超出 `int`（约 $2.1 \times 10^9$）。C++ 必须写成 `(long long)mn * totalTrips`——**先强转再乘**；只把结果赋给 `long long` 变量而在 `int` 上做乘法，溢出已经发生。

2. **`check` 累加溢出**：$mid$ 可达 $10^{14}$、$\text{time}[i]$ 可为 $1$，$n \le 10^5$ 辆车的和理论上可达 $10^{19} > 9.2 \times 10^{18}$（`long long` 上限）。一旦累计 $\ge \text{totalTrips}$ 立即返回 `true`，把累计值压在 $2 \times 10^{14}$ 以内。不写提前退出，在极端数据下**可能 RE 或返回错误值**。

3. **`n = 1`**：答案就是 $\text{time}[0] \times T$，恰等于上界，二分照常工作，无需特判。

4. **二分模板混搭死循环**：`while (lo <= hi)` 必须配 `hi = mid - 1`；若误写 `hi = mid`，当区间收缩到 $lo = mid = hi$ 且判定可行时会原地打转。反过来，左边界模板 `while (lo < hi)` 配 `hi = mid` 也是对的——关键是整套一致。

5. **下界从 1 还是 0 开始**：两者都对（$P(0)$ 假，从 0 开始只是多一轮无效迭代）；但上界**必须可行**（引理 2），取 $T - 1$ 或 $\min(\text{time})$ 当上界是错的——它们不一定能跑完全部趟数。

6. **`(lo + hi) / 2` 的写法**：本题 $lo + hi \le 2 \times 10^{14}$，`long long` 下直接相加不会溢出；但 `lo + (hi - lo) / 2` 是普适的安全写法，养成习惯可避免在值域 $10^{18}$ 级的题上翻车。

7. **快速手算校验**：$T = 1$ 时答案应为 $\min(\text{time})$（最快车跑一趟）；`time` 全相同且 $n$ 辆车时，答案应为 $\lceil T/n \rceil \times \text{time}[0]$。提交前用这两个特例心算一遍能拦截大部分模板错误。

8. **「至少」而非「恰好」**：题目要求完成**至少** $T$ 趟，`check` 用 $\ge$；若误用 $==$，会因 $\text{trips}$ 的阶梯跳变漏掉大量可行时刻（如示例 1 中 $t = 4$ 时完成 7 趟，同样合法但被跳过）。

**延伸思考**：

- **若改问「恰好 $T$ 趟」的最少时间**？答案可能**不存在**：$\text{trips}$ 是阶梯函数，会整段跳过某些取值。例如 `time = [2,3]`：$t=5$ 时 3 趟、$t=6$ 时 5 趟，「恰好 4 趟」永远无法实现。判定需检查 $t^*$ 邻域内 $\text{trips}$ 的取值是否恰好等于 $T$。
- **若要求输出每辆车的具体趟数安排**？在求得 $t^*$ 后，任意满足 $\sum \lfloor t^*/\text{time}[i] \rfloor \ge T$ 的分配都合法——前 $n-1$ 辆车各跑 $\lfloor t^*/\text{time}[i] \rfloor$ 趟，最后一辆车补足剩余趟数即可（补的趟数 $\le \lfloor t^*/\text{time}[i] \rfloor$，由可行性和单调性保证放得下）。
- **若 `time[i]` 可以为 0**？零耗时的车一瞬间完成无穷多趟，答案退化为 $\min_{\text{time}[i] > 0}$ 相关的常数或直接 $0$——单调性与二分框架不变，但上下界需要重新推导。
