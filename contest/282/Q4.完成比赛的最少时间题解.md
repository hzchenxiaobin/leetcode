# LeetCode 完成比赛的最少时间 题解

## 1. 题目概述

- **标题 / 题号**：完成比赛的最少时间（#2188，hard）
- **链接**：https://leetcode.cn/problems/minimum-time-to-finish-the-race/
- **来源**：LeetCode 第 282 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划

**题意**：给定若干款轮胎，第 $i$ 款参数 $(f_i, r_i)$：**同一条**轮胎连续使用时，第 $x$ 圈耗时 $f_i \cdot r_i^{x-1}$ 秒——计费对象是「这一条」轮胎，换上另一条（哪怕同款新胎）就从 $f$ 重新计起。每圈结束后可以花 `changeTime` 秒换上**任意一款的新胎**。要跑完 `numLaps` 圈，求最少总耗时。

**约束**：

- $1 \le \text{tires.length} \le 10^5$
- $1 \le f_i, \text{changeTime} \le 10^5$
- $2 \le r_i \le 10^5$
- $1 \le \text{numLaps} \le 1000$

> 💡 **读题定位**：本题与同场 Q3（#2187 完成旅途的最少时间）是精心设计的一对：Q3 问「最少时间」但答案**单调**、验证 $O(n)$，于是二分；Q4 同样问「最少时间」，但它是**组合优化**——如何在「换胎」与「连跑」之间取舍，没有可以直接二分的单调谓词（判断「$t$ 秒内能否完赛」本身就是同规模的背包问题，验证不比求解便宜），只能 DP。再抓住两个信号：① $r \ge 2$ 且换胎代价固定 $\Rightarrow$ 单胎连跑呈**指数增长**，「连续段长」存在**常数上界**；② $\text{numLaps} \le 1000$ 很小 $\Rightarrow$ 段长有界后 DP 规模是 $O(1000 \times 18)$ 的玩具。困难题的台阶就搭在这两个信号上。

## 2. 示例

**示例 1**（官方）

```text
输入：tires = [[2,3],[3,4]], changeTime = 5, numLaps = 4
输出：21
解释：
第 1-2 圈：轮胎 0 连跑，2 + 6 = 8；换胎 5 秒；第 3-4 圈：再换一条轮胎 0 连跑，2 + 6 = 8。
总耗时 = 8 + 5 + 8 = 21。硬跑 4 圈需 2+6+18+54 = 80 秒；取胜关键在第 3 圈：
继续旧胎要 2×3² = 18 秒，远贵于「换胎 + 新跑一圈」= 5 + 2 = 7 秒——指数尾巴就该掐掉。
```

**示例 2**（官方）

```text
输入：tires = [[1,10],[2,2],[3,4]], changeTime = 6, numLaps = 5
输出：25
解释：
第 1-2 圈：轮胎 1（2+4=6）→ 换胎 6 → 第 3-4 圈：轮胎 1（2+4=6）→ 换胎 6 → 第 5 圈：轮胎 0（1）。
总耗时 = 6 + 6 + 6 + 6 + 1 = 25。
```

**示例 3**（自造：隔离「换胎极贵」这一变量）

```text
输入：tires = [[1,2]], changeTime = 100000, numLaps = 16
输出：65535
解释：换一次胎 10^5 秒，而单胎每圈只是温和翻倍：连跑 16 圈 = 2^16 − 1 = 65535。
任何含换胎的方案 ≥ 100000 + 16 > 65535，所以最优解是一整段 16 圈。
这个例子说明「段长上界」不能拍脑袋取小（见 §8 第 3 条）。
```

## 3. 解题思路

### 3.1 暴力思路

三个朴素方向全部撞墙：

- **枚举分段**：把 `numLaps` 圈切成若干段、每段选一款轮胎，方案数是 $2^{\text{numLaps}-1}$ 量级，天文数字。
- **带轮胎身份的逐圈 DP**：状态得记「已完成圈数 + 当前哪款胎 + 已连续跑了几圈」，状态数至少 $O(n \cdot \text{numLaps}^2)$，在 $n = 10^5$ 下完全不可存。
- **逐圈贪心**：「这一圈继续跑如果比换胎+新跑一圈便宜就继续」也不行——段内成本是**耦合**的几何级数，同一连续段必须锁定同一条轮胎，第 $x$ 圈的成本取决于前面跑了几圈，局部比较无法保证全局最优（示例 3 的构造思路正是反例温床）。

数据范围的提示也很明确：$n$ 高达 $10^5$（只能线性扫描），`numLaps` 却小到 $10^3$（留给 DP 的空间），中间一定存在一步「把 $10^5$ 款轮胎压缩成常数个候选」的预处理。

### 3.2 核心观察：指数增长给「段长」封顶

![核心观察：单胎圈耗时指数增长，第 19 圈必越过换胎成本线](images/wc282_q4_exponential_cap_concept.svg)

**观察 A（换胎语义）**：换胎可以换**同款新胎**，等价于「指数计时清零」。于是任何合法方案天然具有**分段结构**：若干段，每段 = 某条全新轮胎连续跑 $\ell$ 圈，段与段之间付一次 `changeTime`（首段之前不用付）。段内耗时只由「轮胎 × 段长」决定：

$$T_{(f,r)}(\ell) = f + fr + \cdots + fr^{\ell-1} = f \cdot \frac{r^\ell - 1}{r - 1}.$$

**观察 B（指数封顶）**：$r \ge 2$ 意味着第 $x$ 圈耗时 $f \cdot r^{x-1} \ge 2^{x-1}$，**每圈至少翻倍**；而「换条同款新胎再跑它的第 1 圈」只需 $\text{changeTime} + f \le 2 \times 10^5$。连续第 19 圈耗时 $\ge 2^{18} = 262144 > 2 \times 10^5 \ge \text{changeTime} + f$——**必不划算**。于是最优解中每段长度 $\le 18$。

**观察 C（压缩 $10^5$ 款轮胎）**：段长有了常数上界，只需预计算 $18$ 个数：

$$\text{best}[x] = \min_{\text{轮胎 } (f,r)} T_{(f,r)}(x), \quad x = 1, \dots, \min(\text{numLaps}, 18),$$

即「单胎连跑 $x$ 圈」的最少耗时。计算时对每款轮胎从 $f$ 起累乘，一旦当前圈耗时 $> \text{changeTime} + f$ 就提前截断（§3.3）。

**观察 D（DP 规模）**：段长 $\le 18$、`numLaps` $\le 1000$，一个「分段 DP」（完全背包式转移）只需 $O(\text{numLaps} \times 18) \le 1.8 \times 10^4$ 次转移。

### 3.3 算法流程

![解的结构：分段与换胎，压缩为段长不超过 18 的分段 DP](images/wc282_q4_segment_dp_model.svg)

1. 令 $\text{CAP} = \min(\text{numLaps}, 18)$，初始化 $\text{best}[1..\text{CAP}] = +\infty$。
2. **预处理 best[]**：对每款 $(f, r)$，令 `lap = f`、`total = 0`，对 $x = 1, \dots, \text{CAP}$：`total += lap`，用 `total` 更新 $\text{best}[x]$；若 `lap > changeTime + f` 则 **break**（该胎再连跑必然劣于换新胎，且天然避免 $r^{x}$ 爆炸溢出），否则 `lap *= r`。
3. **分段 DP**：$dp[0] = 0$，对 $i = 1, \dots, \text{numLaps}$：

$$dp[i] = \min_{1 \le j \le \min(i, \text{CAP})} \Big( dp[i-j] + [i > j] \cdot \text{changeTime} + \text{best}[j] \Big),$$

   其中 $\text{best}[j] = \infty$ 的转移直接跳过（该长度没有任何轮胎记录过，见 §4 第 2 条）；$i = j$ 时首段之前不换胎、不加 `changeTime`。
4. 返回 $dp[\text{numLaps}]$。

### 3.4 示例演算

![示例 2 演算：best 表、dp 表与最优方案回溯](images/wc282_q4_example_walkthrough.svg)

以示例 2（`tires = [[1,10],[2,2],[3,4]]`，`changeTime = 6`，`numLaps = 5`）走一遍全程，CAP = 5：

- **best[]**：轮胎 $(1,10)$ 贡献 $1, 11$ 后在 $10 > 6+1$ 处截断；轮胎 $(2,2)$ 贡献 $2, 6, 14, 30$ 后在 $16 > 6+2$ 处截断；轮胎 $(3,4)$ 贡献 $3, 15$ 后在 $12 > 6+3$ 处截断。取逐列最小得 $\text{best} = [1, 6, 14, 30, \infty]$——第 5 列没有任何轮胎能活到，$\infty$ 转移会被跳过。
- **dp[]**：$dp[1] = \text{best}[1] = 1$；$dp[2] = \text{best}[2] = 6$（首段两圈，免换胎）；$dp[3] = dp[2] + 6 + 1 = 13$；$dp[4] = dp[2] + 6 + 6 = 18$；$dp[5] = dp[4] + 6 + 1 = 25$。
- **回溯**：$dp[5] \xleftarrow{j=1} dp[4] \xleftarrow{j=2} dp[2] = \text{best}[2]$，对应方案「轮胎 (2,2) 跑 2 圈 → 换 → 轮胎 (2,2) 跑 2 圈 → 换 → 轮胎 (1,10) 跑 1 圈」，$6 + 6 + 6 + 6 + 1 = 25$ ✓，与官方解释一致。

## 4. 算法细节

1. **截断 break 的双重身份**：`lap > changeTime + f` 时停止该轮胎的累乘，既是**正确性剪枝**（更长的连续段必然劣于拆开，见 §5 引理 3），又是**溢出防护**——只有 `lap ≤ changeTime + f ≤ 2×10^5` 时才执行 `lap *= r`，乘后至多 $2 \times 10^{10}$；`total` 累加 18 个这样的值约 $3.6 \times 10^{11}$，`long long` 稳稳放下。若不截断，$r = 10^5$ 时第 4 圈的 `lap` 就达 $10^{20}$，直接溢出。

2. **best[j] 可能为 $+\infty$**：例如 `tires = [[1,100000]]`、`changeTime = 1`，所有轮胎在第 2 圈后截断，$\text{best}[3..18] = \infty$。DP 转移必须跳过 $\infty$ 项，否则 C++ 里 `LLONG_MAX + changeTime` 是未定义行为。尽管如此 $dp[i]$ 永远有限：每款轮胎至少能记录 $x = 1$（$f \le \text{changeTime} + f$ 恒成立），故 $\text{best}[1] = \min f$ 总存在，$j = 1$ 的链路保证 $dp[i] \le dp[i-1] + \text{changeTime} + \text{best}[1] < \infty$。

3. **「多记无害，漏记才害」**：break 发生在「记录完第 $x$ 圈之后」，即触发截断的那一圈仍会写入 $\text{best}[x]$。这个值是一个真实可行的耗时，参与 min 不会破坏正确性；相反，若把该截的也记上（不 break），才会溢出、才会把永远不该用的长段塞给 DP。同理，转移里「首段免换胎」也可以写成对称的等价形式 $dp[0] = -\text{changeTime}$、每段一律加 `changeTime`——两种写法结果相同，本文选显式分支、每日题解版选负初值，按赛场习惯取一种即可。

4. **CAP 的取值**：18 来自「第 19 圈 $\ge 2^{18} = 262144 > 2 \times 10^5 \ge \text{changeTime} + f$」这一行不等式，证明最省事。更精细的交换分析还能把界压得更低（紧界其实是 16，见「延伸思考」），但压界纯属锦上添花；反之把 CAP 取小（如 15）会直接 WA——示例 3 里答案必须靠 16 圈的长段构成。赛场上取 18~20 都安全，关键是有 §5 那样的论证兜底。

5. **为什么不能像 Q3 那样二分答案**：二分答案需要「给定 $t$，用明显低于求解成本的谓词判断可行性」。本题的可行性判断（「$t$ 秒内是否存在一种分段方式跑完」）本身就是同等规模的组合优化，没有单向单调、可 $O(n)$ 验证的谓词。**「求最少时间」的长相相同，可用工具完全不同**——先判单调可验证、再判组合结构，是两题放在一起的最大收获。

## 5. 正确性证明

设 $T_{(f,r)}(\ell) = f \cdot \frac{r^\ell - 1}{r - 1}$。称一个方案是**规范的**，若它由若干段组成：第 $k$ 段使用一条全新轮胎连续跑 $\ell_k$ 圈（第 $k \ge 2$ 段前付一次 `changeTime`），且不含多余动作（开赛前换胎、完赛后换胎、连续两次换胎均可删去而不增耗时）。

**引理 1（分段范式）**：任何规范方案的总耗时为 $\sum_k T_{A_k}(\ell_k) + (m-1) \cdot \text{changeTime}$（$m$ 为段数）；反之任何段序列都对应一个合法方案。

**证明**：换胎动作天然把时间线切成段；换胎后装上的必然是一条新胎（轮胎无限供给），段内不换则计时连续，第 $j$ 圈耗时 $f \cdot r^{j-1}$，求和即几何级数 $T$。首段之前没有换胎动作。多余动作删除后耗时不变或减少，且任何「连续两次换胎」可合并为一次，故规范方案不失一般性。∎

**引理 2（段长 $\le 18$）**：任何包含长度 $\ge 19$ 的段的方案都不是最优的。

**证明**：设该段用轮胎 $A = (f, r)$。对 $j \ge 19$，该段第 $j$ 圈耗时 $f \cdot r^{j-1} \ge 2^{18} = 262144 > 2 \times 10^5 \ge \text{changeTime} + f$。把第 $19, \dots, \ell$ 圈**逐圈**替换为「换一条同款新胎并跑它的第 1 圈」（耗时 $\text{changeTime} + f$），每替换一圈严格减少耗时，得到的新方案仍合法（引理 1），与最优性矛盾。∎

**引理 3（单胎截断覆盖）**：设轮胎 $A = (f, r)$ 的截断点 $x_A$ 为使 $f \cdot r^{x-1} > \text{changeTime} + f$ 的最小 $x$（算法即在此 break）。任何包含「$A$ 连跑 $y > x_A$ 圈的段」的方案都不是最优的；且 $\text{best}[x]$ 恰好取遍了所有「未在 $x$ 前截断的轮胎」的 $T_A(x)$。

**证明**：$A$ 的第 $x_A + 1, \dots, y$ 圈每圈耗时 $\ge f \cdot r^{x_A} \ge 2 f \cdot r^{x_A - 1} > \text{changeTime} + f$（比值 $r \ge 2$），逐圈替换为换新胎跑一圈严格变优，同引理 2。由 break 的位置，算法完整记录了每款轮胎在 $1, \dots, x_A$ 处的耗时，故 $\text{best}[x]$ 的取值集合恰为所述。∎

**定理**：算法返回的 $dp[\text{numLaps}]$ 等于最优耗时。

**证明**：两个方向夹逼。

*($\ge$，每个 dp 值都可行)* 对 $i$ 归纳：$dp[i]$ 的每个被 min 保留的取值来自 $dp[i-j] + [\,i>j\,]\text{changeTime} + \text{best}[j]$，其中 $\text{best}[j] < \infty$ 等于某条具体轮胎 $A$ 的真实耗时 $T_A(j)$（$j \le \text{CAP} \le 18$ 且 $A$ 未在 $j$ 前截断，由引理 3 确实被记录）。归纳假设 $dp[i-j]$ 对应合法方案；在其后接一次换胎（若 $i > j$）与 $A$ 连跑 $j$ 圈，仍是合法方案。故 $dp[\text{numLaps}] \ge \mathrm{OPT}$。

*($\le$，某个最优方案被覆盖)* 取最优方案并规范化（引理 1），由引理 2、3 可设其每段长度 $\ell_k \le 18$ 且不超过所用轮胎的截断点（否则可严格改进，矛盾）。记段长为 $\ell_1, \dots, \ell_m$，前缀和 $i_t = \ell_1 + \cdots + \ell_t$。对 $t$ 归纳证明 $dp[i_t] \le \sum_{k \le t} T_{A_k}(\ell_k) + (t-1)\text{changeTime}$：转移时取 $j = \ell_t$，由 $\ell_t \le \min(18, x_{A_t})$ 知 $\text{best}[\ell_t] \le T_{A_t}(\ell_t) < \infty$（该转移不被跳过），$t = 1$ 时 $i_1 = \ell_1$ 恰有免换胎转移 $dp[\ell_1] \le \text{best}[\ell_1]$。于是 $dp[\text{numLaps}] \le \mathrm{OPT}$。∎

> 💡 **证明结构复盘**：引理 1 是「结构引理」——把自由的操作序列规范成可枚举的组合对象（分段）；引理 2、3 是「交换引理」——证明最优解可假定满足规范形式（段长受限、不超过截断点），从而 $10^5$ 款轮胎被压成 18 个 best 值；最后的双向夹逼（每个 dp 值可行 / 某个最优方案被 dp 覆盖）是「DP + 规范化」类题目的通用收尾。它与 Q3 的「不变式收缩」并列为周赛两大证明骨架：一个证明**过程**收敛到答案，一个证明**空间**覆盖了答案。

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot \text{CAP} + \text{numLaps} \cdot \text{CAP})$。预处理每款轮胎至多累乘 $\text{CAP} \le 18$ 圈（触发截断通常更早），$10^5 \times 18 \approx 1.8 \times 10^6$ 次加乘；DP 至多 $1000 \times 18 = 1.8 \times 10^4$ 次转移。总量约 $2 \times 10^6$，远低于时限。
- **空间复杂度**：$O(\text{numLaps} + \text{CAP})$，即 `best` 与 `dp` 两个一维数组。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumFinishTime(vector<vector<int>>& tires, int changeTime, int numLaps) {
        const long long INF = LLONG_MAX;
        int cap = min(numLaps, 18);
        vector<long long> best(cap + 1, INF);

        // best[x]：单条新胎连跑 x 圈的最少耗时
        for (auto& t : tires) {
            long long f = t[0], r = t[1];
            long long lap = f, total = 0;
            for (int x = 1; x <= cap; ++x) {
                total += lap;
                best[x] = min(best[x], total);
                if (lap > changeTime + f) break;   // 再连跑必劣于换新胎，兼防溢出
                lap *= r;
            }
        }

        // dp[i]：跑完前 i 圈的最少时间
        vector<long long> dp(numLaps + 1, INF);
        dp[0] = 0;
        for (int i = 1; i <= numLaps; ++i) {
            int hi = min(i, cap);
            for (int j = 1; j <= hi; ++j) {
                if (best[j] == INF) continue;              // 无轮胎记录过该长度
                long long add = (i == j) ? 0 : changeTime; // 首段之前不换胎
                dp[i] = min(dp[i], dp[i - j] + add + best[j]);
            }
        }
        return (int)dp[numLaps];   // 答案 ≤ 1000 × 2×10⁵ = 2×10⁸，int 放得下
    }
};
```

### Python

```python
class Solution:
    def minimumFinishTime(self, tires: List[List[int]], changeTime: int, numLaps: int) -> int:
        cap = min(numLaps, 18)
        INF = float('inf')
        best = [INF] * (cap + 1)

        for f, r in tires:
            lap, total = f, 0
            for x in range(1, cap + 1):
                total += lap
                if total < best[x]:
                    best[x] = total
                if lap > changeTime + f:      # 再连跑必劣于换新胎
                    break
                lap *= r

        dp = [INF] * (numLaps + 1)
        dp[0] = 0
        for i in range(1, numLaps + 1):
            for j in range(1, min(i, cap) + 1):
                if best[j] == INF:
                    continue
                add = 0 if i == j else changeTime   # 首段之前不换胎
                dp[i] = min(dp[i], dp[i - j] + add + best[j])
        return dp[numLaps]
```

> ⚠️ Python 整数无上限，溢出问题不存在，`inf` 参与比较也无害；但 break 与「跳过 $\infty$」两处建议照抄——它们在 C++ 里分别是溢出防线和 UB 防线，保持两语言写法一致能减少赛场切换的心智负担。

## 8. 边界情况与易错点

1. **累乘溢出（C++ 最高频 RE/WA 点）**：不做截断直接累乘，$r = 10^5$ 时第 3 圈 `lap = 10^15` 尚可，第 4 圈 `10^20` 溢出 `long long`（UB，常表现为负数把 `best` 拉到荒谬的小值）。截断保证乘法只发生在 `lap ≤ 2×10^5` 时。此外 `lap`、`total`、`best`、`dp` 全线用 `long long`——`int` 在 `total` 处就到 $2 \times 10^{10}$ 了。官方接口返回 `int`（最优答案 $\le 1000 \times (10^5 + 10^5) = 2 \times 10^8$，放得下），末尾一次强转即可，**中间值千万别跟着用 `int`**。

2. **$\infty$ 参与加法**：`best[j] == INF` 必须跳过再相加。`tires = [[1,100000]]`、`changeTime = 1` 时 $\text{best}[3..18]$ 全是 $\infty$，不跳过则 C++ 直接 UB、Python 得到 `inf` 后 `min` 虽无害但掩盖逻辑。同时记住 `dp[i]` 永远有限（$j=1$ 链路，§4 第 2 条），无需对 `dp` 侧再设防。

3. **CAP 取太小**：示例 3（`tires = [[1,2]]`、`changeTime = 10^5`、`numLaps = 16`）的答案是整段 16 圈 = 65535，任何含换胎的方案都超过 $10^5$。CAP ≤ 15 时最优段长被禁止，直接 WA。取 18 有 §5 引理 2 兜底，取 20 更保险也无害（多算几个永不入选的候选）。

4. **换胎语义读漏**：「也可以换成当前种类的新轮胎」这句是全题题眼——换同款新胎 = 指数清零，最优解几乎总是反复用最划算的那一款胎。漏读的话会误以为换胎只在换「更便宜的款」时有意义。另外：**首段之前不换胎**（转移中 $i = j$ 时 `add = 0`），完赛后也不付换胎时间。

5. **段内不能混用轮胎**：「每圈独立挑最便宜的轮胎」是错的——连续段的成本是几何级数，第 $x$ 圈依赖前面的圈数。这正是要按「段」整体转移、预计算 `best[]` 的原因，也是本题标 Hard 的理解门槛。

6. **$r \ge 2$ 是全部上界论证的地基**：观察 B、引理 2、3 处处用到 $r \ge 2$（每圈至少翻倍）。题面保证 $2 \le r_i$，分析时别无意识地当成「$r$ 可以是 1」——$r = 1$ 时每圈恒为 $f$，长段线性增长，整个封顶论证失效（好在那时问题退化成平凡：一次都不换，答案 = $\text{numLaps} \cdot \min f$）。

7. **`numLaps = 1`**：答案就是 $\min f$，DP 自然覆盖；连同「全同款胎」「`changeTime` 极小」两种极端，可作为提交前的手算校验。

8. **j 的上界是 $\min(i, \text{cap})$ 不是 cap**：$i < \text{cap}$ 时若仍取 $j$ 到 cap，会读 `dp[i - j]` 负下标——C++ 中是 UB，Python 中是负索引错值。顺手检查转移方向：$dp[i]$ 只依赖更小下标，正序遍历即可。

**延伸思考**：

- **段长上界到底能压多紧？** §5 给出 18；更强的交换分析：18 圈的段把末圈换成「换新胎跑一圈」必然严格变优（末圈 $\ge 131072 f > 10^5 + f \ge \text{changeTime} + f$）；17 圈的段拆成 $8+9$ 也必然严格变优（增量 $f \cdot \frac{r^{17} - r^9 - r^8 + 1}{r-1} \ge 130305 > 10^5 \ge \text{changeTime}$，$r = 2$ 时已最小，$r$ 更大只会更悬殊）。所以**任何最优解的段长其实 $\le 16$，且 16 是紧的**——示例 3 正是被迫整段 16 圈的情形；同参数 `numLaps = 17` 时答案是 $100766$（拆 $8+9$：$255 + 10^5 + 511$），恰好印证 17 圈长段不必需。CAP 取 18 只是「证明一行写完」的工程选择。
- **方案回溯**：在转移时记录 $dp[i]$ 的 argmin $j$（必要时再记 $\text{best}[j]$ 的取值轮胎），即可还原完整的换胎时刻表——哪一圈换、换成哪款，面试追问时是现成的加分项。
- **若 `numLaps` 大到 $10^9$**：CAP 仍 $\le 18$，但 $O(\text{numLaps})$ 的数组不行。远圈部分是否趋于「均摊代价最小的固定段长循环」($\min_j (\text{best}[j] + \text{changeTime})/j$)？可先用小规模 DP 与该猜测对拍，再用「远端结构周期性」尝试证明——背包类 DP 的经典进阶方向。
