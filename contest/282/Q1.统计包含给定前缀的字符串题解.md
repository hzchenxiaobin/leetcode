# LeetCode 统计包含给定前缀的字符串 题解

## 1. 题目概述

- **标题 / 题号**：统计包含给定前缀的字符串（#2185，easy）
- **链接**：https://leetcode.cn/problems/counting-words-with-a-given-prefix/
- **来源**：LeetCode 第 282 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、字符串匹配

**题意**：给定字符串数组 `words` 和字符串 `pref`，返回 `words` 中以 `pref` 作为**前缀**的字符串数目。字符串 `s` 的前缀指 `s` 的任一**前导连续子串**（必须从首字符开始）。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \text{words[i].length}, \text{pref.length} \le 100$
- `words[i]` 和 `pref` 仅由小写英文字母组成

> 💡 **读题定位**：签到题的标准面孔——「**逐词判定 + 计数**」，判定谓词是前缀相等。赛场的最短路径是直接调内置：Python 一行 `sum(w.startswith(pref) for w in words)`，C++ 用 `w.compare(0, m, pref) == 0` 配长度守卫，3 分钟内 AC 把时间留给后面的题。复盘要沉淀的是两件事：①「前缀」与「子串」的区别——从首字符开始，**长度是硬前提**；②避开 `substr` / 切片这类「先拷贝再比较」的隐性浪费。

## 2. 示例

**示例 1**（官方）

```text
输入：words = ["pay","attention","practice","attend"], pref = "at"
输出：2
解释：以 "at" 作为前缀的字符串有 2 个："attention" 和 "attend"。
```

**示例 2**（官方）

```text
输入：words = ["leetcode","win","loops","success"], pref = "code"
输出：0
解释：不存在以 "code" 作为前缀的字符串。
```

**示例 3**（自造：覆盖「词等于前缀」与「词比前缀短」两个边界）

```text
输入：words = ["at","a","atlas","bat"], pref = "at"
输出：2
解释："at" 本身就是自己的前缀（前缀可以是整个字符串）；
"a" 长度 1 < 2，被长度守卫淘汰；"atlas" 前 2 位恰为 "at"；"bat" 首位失配。
```

## 3. 解题思路

### 3.1 暴力思路：切片比较

最直白的做法：对每个词切出前 $m$ 位子串，与 `pref` 整体比较——Python 写 `w[:m] == pref`，C++ 写 `w.substr(0, m) == pref`。正确性显然，$O(N \cdot m)$ 的复杂度也完全够用（$N, m \le 100$，至多 $10^4$ 次字符比较）。

问题在**隐性浪费**：切片会创建长度为 $m$ 的**子串副本**——即使首位就不相等，$m$ 个字符也已经拷完了；对 $\text{len}(w) < m$ 的短词，这次拷贝注定白做（切出来的子串比 `pref` 短，必然不等）。签到题不影响 AC，但「只问是否相等、不需要子串本身」的判定，本就不该为它付出副本。

### 3.2 核心观察：前缀 = 长度守卫 + 首 m 位逐一相等

![核心观察：前缀判定 = 长度守卫 + 首 m 位逐一相等，失配即止](images/wc282_q1_prefix_concept.svg)

**观察一（长度是硬前提）**：`pref` 是 `w` 的前缀，当且仅当 `w` 的前 $m$ 个字符与 `pref` 逐一相等。这蕴含 $\text{len}(w) \ge m$——**长度不足的词一次字符比较都不用做**，$O(1)$ 直接淘汰。

**观察二（失配即止）**：长度足够时，从 $j = 0$ 逐位比较，**首个失配立即终止**。不匹配的词往往在前几位（甚至首位）就被拒绝，实际比较次数远小于 $m$。

**观察三（词等于前缀也算）**：$\text{len}(w) = m$ 且逐位相等时，`w` 以 `pref` 为前缀（前缀可以是整个串）——逐位比较天然覆盖，**无需特判**。

### 3.3 算法流程

![算法流程：一次遍历 —— 长度守卫 → 逐位比较 → 计数](images/wc282_q1_scan_flow.svg)

1. 记 $m = \text{len(pref)}$，`ans = 0`；
2. 遍历每个词 `w`：
   - **长度守卫**：$\text{len}(w) < m$ → 跳过（0 次比较）；
   - **逐位比较**：$j$ 从 $0$ 到 $m-1$，遇 `w[j] != pref[j]` 立即 break；
   - 全部相等 → `ans += 1`；
3. 词表取尽，返回 `ans`。

### 3.4 示例演算

![示例演算：4 个词共 6 次字符比较，提前终止省掉 2 次](images/wc282_q1_walkthrough.svg)

以示例 1 演算（`pref = "at"`，$m = 2$）：

| # | word | 长度守卫 | 逐位比较 | 比较次数 | 判定 |
|---|------|----------|----------|----------|------|
| 1 | `pay` | $3 \ge 2$ ✓ | `p ≠ a` 首位失配 | 1 | ✗ |
| 2 | `attention` | $9 \ge 2$ ✓ | `a = a`、`t = t` | 2 | ✓ |
| 3 | `practice` | $8 \ge 2$ ✓ | `p ≠ a` 首位失配 | 1 | ✗ |
| 4 | `attend` | $6 \ge 2$ ✓ | `a = a`、`t = t` | 2 | ✓ |

共 $1+2+1+2 = 6$ 次字符比较（切片法固定 $4 \times 2 = 8$ 次比较，另加 4 次子串拷贝），`ans = 2` ✓。

## 4. 算法细节

1. **判定一谓词三写法**（按赛场推荐度排序）：
   - **内置零副本**：Python `w.startswith(pref)`；C++ `w.compare(0, m, pref) == 0`。不创建子串副本、底层常量极小，是签到题的「最短路径」；
   - **手撕守卫版**：长度守卫 + 逐位比较 + 失配 break。$O(1)$ 额外空间，逻辑透明，用于讲清原理（本节与证明均以它为对象）；
   - **切片版**：`w.substr(0, m) == pref` / `w[:m] == pref`。先拷贝 $m$ 个字符再整体比较，即使首位不等也白拷——能过但不推荐，要能说清它差在哪。
2. **`compare` 的语义与守卫的配合**：`w.compare(0, m, pref)` 把 `w` 从下标 0 起、长度至多 $m$ 的子串与 `pref` 比较（长度不足时取到串尾），返回 0 即相等，全程**无副本**。注意 `len(w) < m` 时它「碰巧」也返回非 0（拿短串跟长串比必然不等）——但这是多做了无谓比较后的碰巧正确，把 `w.size() >= m` 短路在前才是清醒的写法。
3. **C 风格捷径**：`strncmp(w.c_str(), pref.c_str(), m) == 0` 同样零副本；$|w| < m$ 时会在 `w` 结尾的 `\0` 处自然失配（`pref` 在该位置是字母，$> 0$），语义正确。仍建议配长度守卫，意图更明显。
4. **计数器与类型**：答案上界 $N \le 100$，`int` 绰绰有余；本题不存在任何溢出问题，别把时间花在伪优化上。

## 5. 正确性证明

**引理 1（前缀的逐位刻画）**：设 $m = |\text{pref}| \ge 1$。字符串 $w$ 以 `pref` 为前缀，当且仅当 $|w| \ge m$ 且对一切 $0 \le j < m$ 有 $w[j] = \text{pref}[j]$。

**证明**：（⇒）设 `pref` 是 `w` 的前缀，按定义存在 `w` 的某个前导连续子串等于 `pref`；该子串长度为 $m$，故 $|w| \ge m$，且其第 $j$ 位即 $w[j]$ 与 $\text{pref}[j]$ 相等。（⇐）若 $|w| \ge m$ 且前 $m$ 位逐一相等，则 `w` 的长度为 $m$ 的前导连续子串就是 `pref`，按定义 `pref` 是 `w` 的前缀。∎

**定理**：算法返回的 `ans` 等于 `words` 中以 `pref` 为前缀的字符串数目。

**证明**：算法对每个词**恰好判定一次**引理 1 的右侧条件：长度守卫仅拒绝 $|w| < m$ 的词，此时右侧条件不成立，判「非前缀」正确；$|w| \ge m$ 时逐位比较精确检查全部 $m$ 个等式，`break` 仅在已发现失配后提前退出，不改变判定结果。`ans` 恰在判定为真时自增一次，故遍历终止时 `ans` 即满足条件的词数。∎

> 💡 证明虽朴素，但「**计数算法的正确性 = 谓词判定的正确性 + 每元素恰判定一次**」这一分解适用于所有「过滤计数」型题目（如 #2942 查找包含给定字符的单词），是比本题本身更值钱的模板。

## 6. 复杂度分析

- **时间复杂度**：$O(N \cdot m)$，其中 $N = \text{words.length}$、$m = |\text{pref}|$。每个词至多比较 $m$ 位；长度守卫让短词零比较，失配即止让不匹配的词通常只比常数次，实际开销远小于上界。本题 $N, m \le 100$，最坏 $10^4$ 次比较，瞬时完成。
- **空间复杂度**：$O(1)$。仅 `ans`、`m`、下标等常数个变量；全程不创建任何子串副本（这是相对切片法的实质改进）。

## 7. 参考代码

### C++（手撕守卫版：长度守卫 + 逐位比较）

```cpp
class Solution {
  public:
    int prefixCount(vector<string>& words, string pref) {
        int m = pref.size();
        int ans = 0;
        for (const string& w : words) {
            if ((int)w.size() < m) continue;                 // 长度守卫：0 次比较
            bool ok = true;
            for (int j = 0; j < m; ++j) {
                if (w[j] != pref[j]) { ok = false; break; }  // 失配即止
            }
            if (ok) ++ans;
        }
        return ans;
    }
};
```

### C++（compare 零副本版：赛场最短路径）

```cpp
class Solution {
  public:
    int prefixCount(vector<string>& words, string pref) {
        int m = pref.size();
        int ans = 0;
        for (const string& w : words) {
            if ((int)w.size() >= m && w.compare(0, m, pref) == 0) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python（startswith 一行流：赛场最短路径）

```python
class Solution:
    def prefixCount(self, words: List[str], pref: str) -> int:
        return sum(w.startswith(pref) for w in words)
```

### Python（手撕守卫版：对照原理）

```python
class Solution:
    def prefixCount(self, words: List[str], pref: str) -> int:
        m = len(pref)
        ans = 0
        for w in words:
            if len(w) < m:
                continue
            match = True
            for j in range(m):
                if w[j] != pref[j]:
                    match = False
                    break
            if match:
                ans += 1
        return ans
```

> ⚠️ `startswith` / `compare` / `strncmp` 都是零副本实现；唯一要避开的是 `w[:m] == pref` 与 `w.substr(0, m) == pref` 的「先拷贝后比较」。赛场写内置版求快，复盘讲手撕版求懂，两套都过一遍才算吃透这道签到题。

## 8. 边界情况与易错点

1. **手撕版漏掉长度守卫 = 真越界**：`len(w) < m` 时循环里 `w[j]` 会越界——C++ 是未定义行为，Python 直接 `IndexError`。这是本题手撕版**唯一**的致命坑（内置的 `startswith` / `compare` / `substr` 都自行处理了短串）。
2. **切片法「碰巧正确」要心里有数**：`w[:m]`（Python）在 `m > len(w)` 时切出 `w` 本身，与 `pref` 必不等；`w.substr(0, m)`（C++）会把长度截断到串尾、**不抛异常**，同样必不等。能过，但属于「碰巧」——换成手撕循环就原形毕露。
3. **词等于前缀**：`w == pref` 是合法前缀（前缀可为整个串），逐位比较天然覆盖；若顺手写成严格大于 `len(w) > m`，会漏掉这种情况（示例 3 的 `"at"`）。
4. **`w.size() < m` 的有符号比较警告**：`size()` 是无符号数，与 `int` 混比在 `-Wall` 下有警告；`(int)w.size() < m` 消除之。本题 $m \ge 1$ 不会真出错，但这是 C++ 习惯问题。
5. **全不匹配返回 0**：`ans` 从 0 起累计，示例 2 即返回 0；不要假设至少一个匹配，也不要把「找不到」误当成特殊错误值。
6. **`pref` 为空串**（超纲但值得知道）：本题约束 $m \ge 1$ 不出现；工程语境下任何串都以空串为前缀（`startswith("")` 恒真），答案恒为 $N$。
7. **别过度设计**：$100 \times 100$ 的规模，任何 Trie / AC 自动机的念头都是负优化——签到题的目标是最快 AC，把盘算数据结构的时间省下来投给 Q3/Q4。

**延伸思考**：

- **多次前缀查询**：若要在同一批 `words` 上回答 $Q$ 次前缀计数，逐次扫描是 $O(Q \cdot N \cdot m)$；用 **Trie** 预处理（节点存经过的词数 `cnt`），单次查询沿 `pref` 走 $m$ 步取终点 `cnt`，代价 $O(m)$，总代价 $O(\sum |w| + Q \cdot m)$。本题 $Q = 1$，直接扫描即最优——先写对，再优化。
- **排序 + 二分的另一条路**：把所有词按字典序排序后，以 `pref` 为前缀的词恰构成一段**连续区间**——查询等价于两次二分定位（`pref` 的插入位置与其「末位字符 +1」版本的插入位置之差）。这也是后缀数组、有序索引上做前缀统计的基础想法，规模大、查询多时 worth 考虑。
