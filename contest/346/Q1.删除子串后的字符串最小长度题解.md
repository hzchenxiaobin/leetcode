# LeetCode 删除子串后的字符串最小长度 题解

## 1. 题目概述

- **标题 / 题号**：删除子串后的字符串最小长度（#2696，easy）
- **链接**：https://leetcode.cn/problems/minimum-string-length-after-removing-substrings/
- **来源**：LeetCode 第 346 场周赛 Q1
- **难度**：简单
- **标签**：栈、字符串、模拟

**题意**：给定仅由**大写**字母组成的字符串 `s`，每一步可以从中删除**任意一个**相邻的 `"AB"` 或 `"CD"` 子串；删除后左右两段拼接，可能拼出新的 `"AB"` / `"CD"`。求把能删的都删掉后，最终字符串的**最小**可能长度。

**约束**：

- `1 <= s.length <= 100`
- `s` 仅由大写英文字母组成

> 💡 **签到题关键点**只有两个：① 删除单位是**相邻两位**的子串，隔着别的字符的 `A`、`B` 不能直接删；② 删除会「拼出」新对（级联），所以「一次扫描找完所有对」不够——**消除顺序是否影响结果**是本题唯一的思维考点（答案：不影响，§5 给出完整证明）。本题另有[每日题解 2696](../../solution/2601-2700/2696_删除子串后的字符串最小长度.md)，与本文互为印证；本文按周赛复盘主线，重点补齐「为什么一趟栈扫描就是最优」。

## 2. 示例

**示例 1**

```text
输入：s = "ABFCACDB"
输出：2
解释：你可以执行下述操作：
- 从 "ABFCACDB" 中删除子串 "AB"，得到 s = "FCACDB"。
- 从 "FCACDB" 中删除子串 "CD"，得到 s = "FCAB"。
- 从 "FCAB" 中删除子串 "AB"，得到 s = "FC"。
最终字符串的长度为 2。可以证明 2 是可获得的最小长度。
```

**示例 2**

```text
输入：s = "ACBBD"
输出：5
解释：无法执行操作，字符串长度不变。
```

**示例 3（自拟，覆盖「级联删除」）**

```text
输入：s = "CABD"
输出：0
解释：原串中 C、D 并不相邻：
- 删除 "AB"（下标 1-2），两段拼成 "CD"；
- 再删除 "CD"，得到空串。
第一刀删掉 AB，才把原本隔开的 C、D 拼到一起。
```

**示例 4（自拟，覆盖「有字母但配不成对」）**

```text
输入：s = "ACBD"
输出：4
解释：A、B、C、D 四个字母都在，但相邻两位依次是
"AC"、"CB"、"BD"，都不是 "AB" / "CD"，一个也删不掉。
```

## 3. 解题思路

### 3.1 暴力思路：反复扫描，删到不能删

反复扫 `s`，每找到一个相邻的 `"AB"` / `"CD"` 就删掉，直到某一轮一处也找不到。每轮扫描 $O(n)$，每轮至少删掉一对，最坏 $\lceil n/2 \rceil$ 轮，总计 $O(n^2)$。

$n \le 100$，$O(n^2)$ 稳过，签到题这么做并没有错（Python 一行 `while` + `replace` 最顺手）。但周赛应该沉淀**通用套路**：这类「删除后拼出新对」的问题有 $O(n)$ 的标准姿势——**栈**。

### 3.2 核心观察：新对只出现在「删除点左侧末位 × 后续字符」→ 栈

![核心观察：删除后新相邻关系只出现在左侧末位与后续字符之间](images/wc346_q1_stack_concept.svg)

删掉某个 `"AB"` 后，被拼到一起的是**左侧剩下部分的末位 X** 和**右侧开头 Y**。关键在于：

- X 在删除发生时**已经确定**，但它的去留要等**后面才来**的 Y 拍板；
- 右侧字符按先后顺序依次到达，于是「**最靠近删除点的左侧字符最先接受检验**」——**后进的左半先配对**，这正是 LIFO，天然是**栈**。

于是得到一趟扫描算法：字符逐个进栈，**每个新字符只和栈顶比较**——栈顶拼上它恰好是 `"AB"` / `"CD"` 就双双消失，否则入栈等待以后。

换个视角：把 `A` 看作 `(`、`B` 看作 `)`，`C` 看作 `[`、`D` 看作 `]`，本题与 [20. 有效的括号](https://leetcode.cn/problems/valid-parentheses/) 完全同构，只是从「判定合法」退化为「数还剩几个」。

### 3.3 算法流程

![算法流程：一趟扫描，每个字符只与栈顶比较一次](images/wc346_q1_algorithm_flow.svg)

```text
stk ← 空栈
for c in s:
    if stk 非空 且 (栈顶 + c) ∈ {"AB", "CD"}:
        stk.pop()          # 这对一起消失，c 不入栈
    else:
        stk.push(c)        # 左半就位，等右半来配
return len(stk)
```

**不变式**：任何时刻栈内不存在相邻可删对。新字符 `c` 只可能与栈顶成对（成对则双双消失，栈顶退回更早的字符；不成对则入栈且不打扰更深的字符），所以不变式始终成立；扫描结束时的栈就是「删不动」的终态。

### 3.4 示例演算

![示例演算：ABFCACDB 的栈逐步变化](images/wc346_q1_example_walkthrough.svg)

以 `s = "ABFCACDB"` 为例（栈底 → 栈顶）：

| 步骤 | 读入 | 判定 | 动作 | 栈（底 → 顶） |
|------|------|------|------|---------------|
| 1 | A | 栈空 | 入栈 | `A` |
| 2 | B | A+B = "AB" | 弹出 A | （空） |
| 3 | F | 谁也配不上 | 入栈 | `F` |
| 4 | C | F+C 不成对 | 入栈 | `F C` |
| 5 | A | C+A 不成对 | 入栈 | `F C A` |
| 6 | C | A+C 不成对 | 入栈 | `F C A C` |
| 7 | D | C+D = "CD" | 弹出 C | `F C A` |
| 8 | B | A+B = "AB" | 弹出 A | `F C` |

扫描结束，栈 = `F C`，长度 **2** ✓。

注意第 7、8 步的级联：原串中下标 4 的 `A` 与下标 7 的 `B` **并不相邻**（中间隔着下标 5、6 的 `C`、`D`），是第 7 步删掉 `C D` 之后它们才在栈顶相遇——这正是「删除后拼出新对」的体现，栈把它自动处理了。

对照示例 2 `s = "ACBBD"`：`AC`、`CB`、`BB`、`BD` 均不成对，5 个字符全部入栈，答案 **5** ✓。

## 4. 算法细节

1. **判定条件**：`!stk.empty() && ((stk.back()=='A' && c=='B') || (stk.back()=='C' && c=='D'))`。只查「栈顶 + 当前字符」拼出的两位串，**方向固定**（`A` 在左、`B` 在右），`"BA"`、`"DC"` 不算。
2. **单次 `if` 即可，不需要 `while`**：当前字符 `c` 至多与栈顶成一次对——成对则 `c` 与栈顶一起消失、`c` 根本不入栈，本次处理即告结束；下一个字符自然会与新的栈顶比较。这与「消连续 k 个相同字符」的题（如 1209）不同，那类题才需要循环弹出。
3. **检查时机在「右半」到来时**：`A`、`C` 是对的左半，入栈时不做任何事；`B`、`D` 是右半，到来时主动查栈顶。左半永远「等着」，右半永远「主动查」。
4. **泛化**：若删除模式扩成多组**不相交**字母对（如再加 `"EF"`），判定改成集合查表 `stk.back()+c ∈ {"AB","CD","EF"}` 即可，栈逻辑一字不改（正确性依赖各组字母集两两不相交，见 §5 引理 1 与 §8 易错点第 2 条）。
5. **返回的是长度**：`len(stk)`。栈内容本身就是「删不动的终态串」，但题目只要长度。

## 5. 正确性证明

本题真正的考点藏在「**最小**长度」三个字里：如果不同删除顺序能删出不同长度，一趟贪心扫描就可能错过最优。所以必须证明：**删到不能再删时，结果与顺序无关**。

**引理 1（不重叠）**：任一字符串中，任意两个可删子串不共享任何位置。

**证明**：反设两个可删对共享位置 $i$。若是 `"AB"` 与 `"CD"` 共享，则 $s_i \in \{A,B\} \cap \{C,D\} = \varnothing$，矛盾；若是两个 `"AB"` 共享，则 $s_i$ 须同时为 `A` 与 `B`（共享位既当左半又当右半），矛盾；两个 `"CD"` 同理 □

**引理 2（合流性）**：从同一串出发，任意两条「删到不能再删」的路径，终点串**完全相同**。

**证明**：把「每步删一个 `AB`/`CD`」看作字符串重写系统，每步长度严格减 2，故**终止**。再证**局部合流**：设当前串有两个不同的可删对 $p$、$q$，由引理 1 二者位置不相交，于是先删 $p$ 后 $q$ 的两个字符原封不动、仍然相邻，可再删 $q$；先删 $q$ 同理可再删 $p$；两条一步分支 $s_p$、$s_q$ 均可延伸到同一个串（同时删掉 $p$、$q$ 的结果）。由 **Newman 引理**（终止 + 局部合流 ⇒ 全局合流），任意极大删除路径的终态唯一 ∎

**引理 3（栈模拟 = 真实删除序列）**：栈算法终止时的栈内容，等于 `s` 经某个合法删除序列删到不能再删的结果。

**证明**：对已扫描前缀 $P$ 归纳，证明更强的命题：**任意时刻栈内容 = $R(P)$**，其中 $R(\cdot)$ 是 $P$ 的唯一终态（由引理 2 良定义）。初始栈空 = $R(\epsilon)$。设当前栈 = $R(P)$，读入 $c$：由引理 2，$R(Pc) = R(R(P) \cdot c)$（先在前缀内部删，是 $Pc$ 上一条合法的部分路径）。$R(P)$ 已不可再删，故 $R(P) \cdot c$ 中若还有可删对，只能跨在最后一个字符 $c$ 上，即「$R(P)$ 的末位 + $c$」这一处。若它恰为 `"AB"`/`"CD"`，删掉后剩下 $R(P)$ 去掉末位——它不可再删（否则 $R(P)$ 自身含可删对），得 $R(Pc) = R(P)$ 去掉末位，对应**弹栈**；否则 $R(P) \cdot c$ 整体不可删，$R(Pc) = R(P) \cdot c$，对应**入栈**。两种情况与栈操作完全一致 ∎

**定理**：栈算法返回 `s` 可达的最小长度，且该值就是任何「删到不能再删」结果的长度。

**证明**：由引理 3，栈算法产出 `s` 的一个终态 $R(s)$；由引理 2，所有删除路径终态唯一，故**无论怎么删**，能到达的不可删串只有 $R(s)$，其长度即所求最小值。又每删一步长度严格减 2，任何可达状态的长度都不会小于 $|R(s)|$——若某个可达状态长度更小，把它延伸到删不动时得到长度 $\le$ 该状态长度的终态，与终态唯一性矛盾 ∎

> 💡 一句话：**「最小长度」在这题里是幌子**——终态唯一，怎么删都一样，一趟栈扫描就是最优。合流性的根源是引理 1 的「两组字母集不相交」；一旦模式共享字母（如同时允许删 `"AB"` 与 `"BC"`），顺序就可能影响长度（见 §8 易错点第 2 条）。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个字符恰好处理一次：要么入栈一次（此后不再移动），要么与栈顶一起消失；判定是两次 $O(1)$ 比较。$n \le 100$，瞬间完成。
- **空间复杂度**：$O(n)$。最坏没有任何可删对（如 `"EF"`、`"AAAA"`），全部字符入栈。若允许原地修改，可用写指针把 `s` 自身当栈，额外空间 $O(1)$（见 §7）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minLength(string s) {
        string stk;
        for (char c : s) {
            if (!stk.empty() &&
                ((stk.back() == 'A' && c == 'B') ||
                 (stk.back() == 'C' && c == 'D'))) {
                stk.pop_back();    // 栈顶 + c 成对，一起消失
            } else {
                stk.push_back(c);  // 左半就位，等右半来配
            }
        }
        return stk.size();
    }
};
```

原地写指针版（把 `s` 自己当栈，额外空间 $O(1)$）：

```cpp
class Solution {
public:
    int minLength(string s) {
        int top = 0;  // s[0..top-1] 是栈
        for (char c : s) {
            if (top > 0 &&
                ((s[top - 1] == 'A' && c == 'B') ||
                 (s[top - 1] == 'C' && c == 'D'))) {
                top--;          // 弹栈：c 不写入
            } else {
                s[top++] = c;   // 入栈
            }
        }
        return top;
    }
};
```

### Python

```python
class Solution:
    def minLength(self, s: str) -> int:
        stk = []
        for c in s:
            if stk and stk[-1] + c in ("AB", "CD"):
                stk.pop()       # 成对：栈顶与 c 一起消失
            else:
                stk.append(c)   # 左半就位，等右半来配
        return len(stk)
```

> 💡 Python 用元组查表 `stk[-1] + c in ("AB", "CD")` 比写两个 `and` 更短；C++ 同理可以查 `string`，但显式比较最直白。周赛 Q1 的目标是零调试一次过，按手感选即可。

## 8. 边界情况与易错点

1. **不能只数 A、B、C、D 的个数**。本题的删除条件是「**模式型**」（固定字母对），不是「**数量型**」：`"ACBD"` 四个字母各有一个，却一个也删不掉。这与 [3746. 等量移除后的字符串最小长度](https://leetcode.cn/problems/minimum-length-of-balanced-removals/)（[周赛 476 Q2 题解](../476/Q2.等量移除后的字符串最小长度题解.md)）形成鲜明对照——那题是数量条件，纯计数 $O(1)$ 就够；本题必须栈模拟。
2. **顺序无关依赖「字母集不相交」，别把栈套路乱搬到共享字母的变体**。若规则改为可删 `"AB"` 与 `"BC"`（共享 `B`），`"ABCB"` 先删 `AB` 得 `"CB"`（长 2）、先删 `BC` 再删 `AB` 得空串（长 0）——终态不唯一，一趟贪心栈不再保证最优。
3. **「子串」= 相邻两位**。`s = "ACBD"` 里 `A`、`B` 中间隔着 `C`，不能直接删；只有中间的字符也被删空（级联）之后它们才可能配对——示例 3 的 `CABD` 演示了这一点。
4. **单次 `if` 判定即可**，不要顺手写 `while` 多次弹栈：`c` 是右半，与栈顶成对即消失、不入栈，至多消一次。
5. **`n = 1`**：单字符无对可删，入栈返回 1。取栈顶前必须判栈空（C++ 对空串 `back()` 是未定义行为）。
6. **题目要长度**：不要返回栈内容或下标；每删一对长度减 2，答案与 $n$ 同奇偶，可用作快速自检。

**延伸思考**：

- 删除模式扩成 $k$ 组**两两不相交**的字母对（如 `"AB"`、`"CD"`、`"EF"`……）：引理 1 依然成立（任意两组字母集不相交），栈解法与整套证明原样照搬，只是查表集合变大。

- 若模式**共享字母**（如 `"AB"` 与 `"BC"`），合流性被破坏：`"ABCB"` 的两种顺序分别得到长 2 与长 0。此时问题升格为需要更细致分析的消除类问题，可联想 [390. 消除游戏](https://leetcode.cn/problems/elimination-game/) 这类「操作顺序影响结果」的题。
