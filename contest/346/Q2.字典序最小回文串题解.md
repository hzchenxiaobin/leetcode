# LeetCode 字典序最小回文串 题解

## 1. 题目概述

- **标题 / 题号**：字典序最小回文串（#2697，easy）
- **链接**：https://leetcode.cn/problems/lexicographically-smallest-palindrome/
- **来源**：LeetCode 第 346 场周赛 Q2
- **难度**：简单
- **标签**：贪心、双指针、字符串

**题意**：给定仅由**小写字母**组成的字符串 `s`，一步操作可以把 `s` 中**一个**字符替换成另一个小写字母。要求用**尽可能少**的操作把 `s` 变成**回文串**；若最少操作数的方案不止一种，取**字典序最小**的方案，返回最终的回文串。

**约束**：

- $1 \le s.\text{length} \le 1000$
- `s` 仅由小写英文字母组成

> 💡 本场是「双简单」开局（Q1 #2696、Q2 #2697 均为 easy），Q2 的唯一思维考点是**双目标的优先级**——「最少操作」是硬约束，「字典序最小」只在操作数并列时才生效。本题另有[每日题解 2697](../../solution/2601-2700/2697_字典序最小回文串.md)，与本文互为印证；本文按周赛复盘主线，重点补齐「为什么取 $\min$ 恰好同时拿下两个目标」的形式化证明（§5），并与 Q1 的「终态唯一」证明对照。

## 3. 解题思路

### 3.1 暴力思路

每个对称对都有「不改 / 改左 / 改右 / 两侧改成 26 种字母之一」等选择，暴力做法是枚举所有组合，按「操作数、字典序」双关键字取最小——组合数指数级；把每步替换看作状态转移做 BFS，状态空间高达 $26^n$，$n \le 1000$ 时完全不可行。

但这题根本不需要搜索：两个目标都能**逐对独立**判定（见 3.2），一趟双指针直接构造出唯一的最优解。

### 3.2 核心观察：对称对独立 + 一次操作的可达集

![核心观察：对称配对独立决策，失配对一次操作只有两种归宿](images/wc346_q2_pair_min_concept.svg)

三个观察层层递进：

1. **替换不改变长度与下标对齐**。回文条件只耦合对称对 $P_i = (i,\ n-1-i)$ 内部的两个位置，而各对占用的位置互不重叠 ⇒ **每个对称对独立决策**，操作数与字典序都不会跨对传播。
2. **失配对 $(a, b)$ 在「恰好 1 次」下只有两种归宿**：只改一侧就必须向另一侧看齐，得 $(a,a)$ 或 $(b,b)$；想让两侧同改成更小的第三字母至少要 2 次，被「最少操作」直接淘汰。
3. **相等对被冻结**：0 次已是最少；只改一个反而失配，两个都改要 +2 次。所以「字典序最小」管不到相等对头上——它只能在失配对的两种 1 次方案里挑。

字典序方向：位置 $i$ 比 $n-1-i$ **先**参与比较，所以两种方案里选 $c = \min(a, b)$，让靠前位置拿到更小的字符。

**结论：相等对跳过，失配对两侧同写 $\min$。**

### 3.3 算法流程

![算法流程：双指针对撞，失配双写 min](images/wc346_q2_algorithm_flow.svg)

```text
i ← 0, j ← n − 1
while i < j:
    if s[i] ≠ s[j]:
        c ← min(s[i], s[j])   # 较小字符
        s[i] ← c, s[j] ← c    # 两侧同写（较小侧赋值幂等）
    i ← i + 1, j ← j − 1
return s
```

奇数长度的中心位在 $i = j$ 相遇时自然跳过，无需特判。

### 3.4 示例演算

![示例演算：三个官方示例与一个自拟反例](images/wc346_q2_example_walkthrough.svg)

| 示例 | 对 $(0, n{-}1)$ | 对 $(1, n{-}2)$ | 中心位 | 结果 | 操作数 |
|------|----------------|----------------|--------|------|--------|
| `"egcfe"` | (e,e) 不动 | (g,f)→(f,f) | c 免检 | `"efcfe"` | 1 |
| `"abcd"` | (a,d)→(a,a) | (b,c)→(b,b) | — | `"abba"` | 2 |
| `"seven"` | (s,n)→(n,n) | (e,e) 不动 | v 免检 | `"neven"` | 1 |
| `"bb"` | (b,b) 不动 | — | — | `"bb"` | 0 |

注意 `"seven"`：被改小的是**靠前**的 `s`。若惯性地「保住左边字符」，会得到 1 次操作的回文 `"seves"`，操作数达标但字典序输给 `"neven"`——这是本题最典型的 WA 来源。

## 4. 算法细节

1. **双指针循环条件 `i < j`**：共处理 $\lfloor n/2 \rfloor$ 对；奇数长度时 $i = j$ 的中心位与自己配对，天然免检，不用特判。
2. **`min` 直接用于字符**：小写字母的比较就是字母序比较（ASCII 连续），C++ `min(s[i], s[j])`、Python `min(a[i], a[j])` 都合法，无需 `s[i]-'a'` 换算。
3. **「两侧同写 c」≠「改两次」**：较小那侧本来就是 $c$，对它赋值是**幂等**的，实际改动的只有较大一侧——恰好 1 次操作。代码上统一赋值比写分支更短、更不易错。
4. **语言差异**：C++ `std::string` 可变，原地改完直接返回，额外空间 $O(1)$；Python `str` 不可变，必须 `list(s)` 改完再 `join` 回去。
5. **若顺手统计操作数**：答案就是失配对的个数（每对恰 1 次）；本题只要求返回串。
6. 也可以不显式维护 `j`：`for i in range(n // 2)`，镜像位是 $n-1-i$（Python 里 `a[-1-i]` 更顺手）。

## 5. 正确性证明

记 $n = |s|$，对称对 $P_i = (i,\ n-1-i)$，$0 \le i < \lfloor n/2 \rfloor$；失配对（$s[i] \neq s[n-1-i]$）的个数记为 $k$。

**引理 1（操作数下界）**：任何把 $s$ 改成回文串的方案，操作数 $\ge k$；且 $k$ 次可行。

**证明**：替换不改变下标。设结果 $t$ 为回文，则每对 $P_i$ 上 $t[i] = t[n-1-i]$。若 $s$ 在 $P_i$ 上失配，则 $i$ 与 $n-1-i$ 至少一个位置被改过，该对贡献 $\ge 1$ 次操作；各对位置互不相交，操作数按对可加，总计 $\ge k$。另一方面，「每个失配对把较大者改成较小者」恰用 $k$ 次并得到回文，下界可达 ∎

**引理 2（相等对冻结）**：任何恰好 $k$ 次操作的方案中，每个相等对的两位置都未被修改。

**证明**：反设某相等对 $(c,c)$ 上有位置被改。只改一个，则该对两字符不同，与结果是回文矛盾；两个都改，则该对贡献 $\ge 2$ 次，而每个失配对仍需 $\ge 1$ 次（引理 1 的逐对计数），总计 $\ge k+2 > k$，矛盾 ∎

**引理 3（一次操作的可达集）**：失配对 $(a,b)$（$a \neq b$）若只允许 1 次替换且要求改后两侧相等，结果只能是 $(a,a)$ 或 $(b,b)$。

**证明**：1 次替换只碰一个位置；把某一侧改成 $x$ 后，相等性迫使 $x$ 等于另一侧的原字符，故结果为 $(b,b)$（改左）或 $(a,a)$（改右）。任何其他结果（如两侧同改成第三字母）至少需 2 次 ∎

**定理**：算法输出是所有 $k$ 次操作的回文化方案中字典序最小的结果，且该结果唯一。

**证明**：由引理 2，候选方案在相等对上与 $s$ 相同；由引理 3，每个失配对 $P_i$ 独立地二选一：落字符 $a_i$ 或 $b_i$（记 $s[i] = a_i$，$s[n-1-i] = b_i$）。于是每个候选串由选择序列 $(c_0, c_1, \dots)$ 唯一决定。对两个不同候选 $t \neq t'$，取选择不同的编号最小的对 $P_i$：编号更小的对选择相同、相等对冻结，故两串在位置 $0..i-1$ 上完全相同；而位置 $i$ 上 $t[i] = c_i \neq c'_i = t'[i]$，即**首个不同位置恰是 $P_i$ 的靠前位置**。所以串的字典序 = 选择序列（按对编号升序）的字典序，逐位最小化即每对取 $c_i = \min(a_i, b_i)$，每个选择位都取到独立最小，最优且唯一 ∎

> 💡 一句话：**「最少操作」把解空间压缩成「每对二选一」（相等对冻结、失配对 1 次），「字典序」再让每个二选一取 $\min$**——两个目标逐对独立、互不打架，局部贪心就是全局最优。对照 [本场 Q1](Q1.删除子串后的字符串最小长度题解.md)：那边的「顺序无关」靠重写系统**合流性**，这边的「逐对独立」靠**位置互不重叠**——两种典型的「局部决策 = 全局最优」论证。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。双指针共处理 $\lfloor n/2 \rfloor$ 对，每对一次比较、至多两次赋值，均为 $O(1)$；$n \le 1000$，瞬间完成。
- **空间复杂度**：C++ 原地修改 `std::string`，额外 $O(1)$；Python 因 `str` 不可变需 $O(n)$ 工作数组（输出本身占 $O(n)$，按惯例不计入额外空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string makeSmallestPalindrome(string s) {
        for (int i = 0, j = (int)s.size() - 1; i < j; ++i, --j) {
            if (s[i] != s[j]) {
                char c = min(s[i], s[j]);  // 较小字符
                s[i] = s[j] = c;           // 较大者改小，较小者幂等
            }
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def makeSmallestPalindrome(self, s: str) -> str:
        a = list(s)                              # str 不可变，转 list 原地改
        i, j = 0, len(a) - 1
        while i < j:
            if a[i] != a[j]:
                a[i] = a[j] = min(a[i], a[j])    # 两侧同写较小字符
            i, j = i + 1, j - 1
        return "".join(a)
```

下标遍历版（不显式维护 `j`，Python 更顺手）：

```python
class Solution:
    def makeSmallestPalindrome(self, s: str) -> str:
        a = list(s)
        for i in range(len(a) // 2):
            a[i] = a[-1 - i] = min(a[i], a[-1 - i])
        return "".join(a)
```

> 💡 `a[i] = a[-1-i] = min(...)`：Python 先求右侧 `min`（用的还是旧值），再从左到右赋值，两个位置互不干扰，一行完成「双写 min」。

## 8. 边界情况与易错点

1. **别把「字典序最小」读成「不限次数」**：`"bb"` 的答案是 `"bb"` 而非 `"aa"`——操作数优先是硬约束，0 次已是下界的串一个字符都不能动（引理 2）。
2. **别惯性「保住左边字符」**：`"seven"` 保左得 `"seves"`（1 次、回文、但字典序更大）；必须取 $\min$，被改小的可能是靠前的 `s`。
3. **相等对不能顺手改小**：把 `(e,e)` 改成 `(a,a)` 花 2 次，直接出局。
4. **失配对别改成第三字母**：`(g,f)` 改成 `(e,e)` 要 2 次；1 次的可达集只有 `(g,g)`、`(f,f)`（引理 3）。
5. **奇数长度中心位无需特判**：`i < j` 相遇即止；`n = 1` 时循环一次都不进，原样返回。
6. **Python 直接 `s[i] = c` 会抛 `TypeError`**：`str` 不可变，先 `list(s)` 再 `join`。
7. **返回的是串，不是操作数**：本题接口 `makeSmallestPalindrome`，别串到「求最少操作次数」的变体上。
8. **「两侧同写」不会多花操作**：较小侧赋值是幂等的，担心理由不成立；反过来若写成「两侧都 `+1` 步」计数就会把 1 算成 2，统计操作数时会翻车。

**延伸思考**：

- **变体一（预算放宽）**：若改成「至多 $k$ 次操作、字典序最小」，多出的预算该怎么花？把一个对称对改造成 `(a,a)` 的代价是 0 / 1 / 2 次（取决于两字符现状），仍是逐对独立决策 + 字典序高位优先——从最靠前的对开始，把预算花在能让靠前位置变小的改造上，直到预算耗尽。
