# LeetCode 所有球里面不同颜色的数目 题解

## 1. 题目概述

- **标题 / 题号**：所有球里面不同颜色的数目（#3160，medium）
- **链接**：https://leetcode.cn/problems/find-the-number-of-distinct-colors-among-the-balls/
- **来源**：LeetCode 第 131 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：共有 $\text{limit}+1$ 个球，编号 $0 \sim \text{limit}$，初始都没有颜色。依次执行 `queries[i] = [x, y]`：把球 $x$ **染成**颜色 $y$（覆盖它原来的颜色，可能原本无色，也可能本来就是 $y$）。每次操作后，输出「当前所有球中不同颜色的数目」——没有染色的球不计入任何一种颜色。

**约束**：

- $1 \le \text{limit} \le 10^9$
- $1 \le n = |\text{queries}| \le 10^5$
- `queries[i].length == 2`
- $0 \le \text{queries}[i][0] \le \text{limit}$
- $1 \le \text{queries}[i][1] \le 10^9$

> ⚠️ 两个值域都到 $10^9$，**不能**用「球编号 / 颜色编号」直接开数组，必须用哈希表。

## 2. 示例

**示例 1**

```text
输入：limit = 4, queries = [[1,4],[2,5],[1,3],[3,4]]
输出：[1,2,2,3]
解释：
  操作 0 后：球 1 颜色 4                      → 1 种颜色
  操作 1 后：球 1 颜色 4、球 2 颜色 5           → 2 种
  操作 2 后：球 1 颜色 3、球 2 颜色 5（4 消失）  → 仍是 2 种
  操作 3 后：球 1 颜色 3、球 2 颜色 5、球 3 颜色 4 → 3 种
```

**示例 2**

```text
输入：limit = 4, queries = [[0,1],[1,2],[2,2],[3,4],[4,5]]
输出：[1,2,2,3,4]
解释：球 1 与球 2 同为颜色 2，颜色种类只算一次，所以第 3 步仍是 2 种。
```

**示例 3（边界补充）**

```text
输入：limit = 0, queries = [[0,7],[0,7],[0,8]]
输出：[1,1,1]
解释：只有球 0；反复染同一颜色不改变颜色数，换色时旧颜色消失、新颜色出现，总数仍为 1。
```

## 3. 解题思路

### 3.1 暴力思路

每次操作后遍历所有已染色的球，把它们的颜色塞进一个集合再取大小。单次 $O(n)$，总时间 $O(n^2)$；$n = 10^5$ 时是 $10^{10}$ 量级，超时。而且每次重新统计等于把「只有一个球改色」的局部变化放大成全局扫描。

**关键点**：一次改色只可能让**至多两种颜色**的球数发生变化——旧颜色少一个球、新颜色多一个球，其余颜色不受影响。所以「不同颜色数」也应该可以增量维护。

### 3.2 核心观察：两张互逆的哈希表 + 一个计数器

![核心：ballColor 与 colorCnt 两张表 + distinct 计数器](images/bw131_q3_two_hashmaps.svg)

维护三样东西：

- `ballColor`：球编号 → 当前颜色（允许球不在表中 = 未染色）；
- `colorCnt`：颜色 → 当前染成该颜色的**球数**（计数为 0 时**必须删除键**）；
- `distinct`：当前不同颜色的数目。

改色 `[ball, color]` 时：

1. 若球 `ball` 已有旧颜色 `old`：`colorCnt[old] -= 1`；若减到 0，说明这种颜色彻底消失，删除该键并 `distinct -= 1`。
2. 给新颜色加计数：若 `colorCnt[color]` 在加之前为 0（或键不存在），说明这是该颜色的**首次出现**，`distinct += 1`；随后 `colorCnt[color] += 1`。
3. `ballColor[ball] = color`，把 `distinct` 记入答案。

这样每次操作只做 $O(1)$（期望）次哈希读写，`distinct` 永远等于 `colorCnt` 中键的个数。

### 3.3 算法流程

![单次操作：先撤旧颜色，再上新颜色](images/bw131_q3_algorithm_flow.svg)

```text
1. distinct = 0
2. 对每个 [ball, color]：
       若 ball 有旧颜色 old：
              colorCnt[old] -= 1
              若 colorCnt[old] == 0：删除 old，distinct -= 1
       若 colorCnt[color] 为 0（或不存在）：distinct += 1
       colorCnt[color] += 1
       ballColor[ball] = color
       答案追加 distinct
3. 返回答案数组
```

> 💡 顺序很重要：**先撤旧、再上新**。即使旧颜色与新颜色相同（球被重复染成同一色），这套顺序也能得到正确的净效果：先减到 0 再删除并 `distinct -= 1`，接着又因「首次出现」而 `distinct += 1`，`distinct` 净不变。

### 3.4 示例演算

![示例演算：四次操作后的球状态与颜色数](images/bw131_q3_example_walkthrough.svg)

以示例 1 为例，`limit = 4`，`queries = [[1,4],[2,5],[1,3],[3,4]]`：

| 操作 | `ballColor` | `colorCnt` | `distinct` |
|------|-------------|------------|------------|
| 初始 | 空 | 空 | 0 |
| [1,4] | 1→4 | {4:1} | 1 |
| [2,5] | 1→4, 2→5 | {4:1, 5:1} | 2 |
| [1,3] | 1→3, 2→5 | {4:1 被删, 5:1, 3:1} | 2 |
| [3,4] | 1→3, 2→5, 3→4 | {5:1, 3:1, 4:1} | 3 |

第 3 步是本题的关键：球 1 从颜色 4 改成颜色 3，颜色 4 的球数归零被删除（`distinct - 1`），颜色 3 首次出现（`distinct + 1`），所以总数**仍是 2**。输出 `[1,2,2,3]`。

## 4. 算法细节

1. **`colorCnt` 归零必须删键**：如果只把计数减到 0 却保留键，`distinct` 就不能简单地用「键的个数」解释；即便你另外维护 `distinct`，也要保证判断「新颜色是否首次出现」时看的是**加一之前**的计数。
2. **`distinct` 的两次改动互不干扰**：旧颜色与新颜色是两个不同的键（若相同，见下条），所以两次判断可以顺序写。
3. **旧色 == 新色的情形**：先减后加，中间可能出现「该颜色计数暂为 0」的瞬时状态，但因为紧接着会加回来，`distinct` 会先减后加，最终正确。不要为了「优化」而跳过旧色处理，否则当球是唯一持有该颜色的球时会算错。
4. **`limit` 只是上界**：真正被染色的球最多 $n$ 个，所以两张表的大小都是 $O(n)$，与 `limit` 无关。
5. **颜色值域 $10^9$**：必须哈希；若用 `vector` 会直接爆内存（$10^9$ 个 `int` 约 4 GB）。
6. **哈希表的最坏情况**：`unordered_map` 理论上可被构造数据卡到 $O(n)$ 单次，但本题数据随机分布，期望 $O(1)$；若担心可换 `std::map`（$O(\log n)$）或自行加随机种子。
7. **答案数组长度**：恰好等于 `queries` 的长度，每个操作都要记录一次，包括那些没有改变颜色数的操作。

## 5. 正确性证明

**引理 1（不变式）**：每次操作处理完毕、且尚未进入下一次操作时，下列三条同时成立：
(a) `ballColor[b] = c` 当且仅当球 $b$ 当前颜色为 $c$，未染色的球不在表中；
(b) `colorCnt[c]` 等于当前颜色为 $c$ 的球数，且当该数为 0 时键 $c$ 不存在；
(c) `distinct` 等于当前不同颜色的数目。

**证明**：对操作次数归纳。初始时三张表为空、`distinct = 0`，与「所有球未染色」一致。
设处理 `[ball, color]` 前三条件成立，记旧颜色为 `old`（若存在）。
- 对 (a)：操作只把 `ballColor[ball]` 改为 `color`，其余球不变，故 (a) 成立。
- 对 (b)：若球有旧颜色 `old`，其颜色变为 `color`，于是颜色 `old` 的球数减 1、颜色 `color` 的球数加 1；代码正是 `colorCnt[old] -= 1` 与 `colorCnt[color] += 1`。若 `colorCnt[old]` 减为 0，代码删除该键，满足「为 0 则不存在」。若球原本未染色，则只有 `color` 加 1。其余颜色计数不变，且它们本来就满足 (b)。
- 对 (c)：只有 `old` 与 `color` 两种颜色的球数变化。`old` 的计数由正变 0 时（删键）颜色种类减 1，代码执行 `distinct -= 1`；`color` 的计数由 0 变正时颜色种类加 1，代码在加一前判断为 0 并执行 `distinct += 1`。其他颜色种类不变。故 (c) 成立。∎

**定理**：算法输出的第 $i$ 项等于第 $i$ 次操作后所有球中不同颜色的数目。

**证明**：由引理 1(c)，每次操作结束时 `distinct` 正是当时的颜色种类数，而代码恰在此时把 `distinct` 追加进答案，且第 $i$ 次追加对应第 $i$ 次操作。故输出序列逐项正确。∎

## 6. 复杂度分析

- **时间**：每次操作常数次哈希查找/插入/删除，期望 $O(1)$，共 $n$ 次操作，总时间 $O(n)$（期望）。最坏情况（哈希退化）为 $O(n^2)$，可用平衡树替换保证 $O(n \log n)$。
- **空间**：`ballColor` 至多 $n$ 项、`colorCnt` 至多 $n$ 项、答案数组 $n$ 项，合计 $O(n)$，与 `limit`、颜色值域无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    std::vector<int> queryResults(int limit, std::vector<std::vector<int>>& queries) {
        std::unordered_map<int, int> ballColor;   // 球 -> 颜色
        std::unordered_map<int, int> colorCnt;    // 颜色 -> 球数（为 0 即删除）
        std::vector<int> ans;
        ans.reserve(queries.size());
        int distinct = 0;
        for (const auto& q : queries) {
            int ball = q[0], color = q[1];
            auto it = ballColor.find(ball);
            if (it != ballColor.end()) {          // 先撤销旧颜色
                int old = it->second;
                if (--colorCnt[old] == 0) {
                    colorCnt.erase(old);
                    --distinct;
                }
            }
            if (colorCnt[color]++ == 0) ++distinct;  // 加一之前为 0 ⇒ 新颜色
            ballColor[ball] = color;
            ans.push_back(distinct);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def queryResults(self, limit: int, queries: list[list[int]]) -> list[int]:
        ball_color = {}       # 球 -> 颜色
        color_cnt = {}        # 颜色 -> 球数
        ans = []
        distinct = 0
        for ball, color in queries:
            old = ball_color.get(ball)
            if old is not None:                 # 先撤销旧颜色
                color_cnt[old] -= 1
                if color_cnt[old] == 0:
                    del color_cnt[old]
                    distinct -= 1
            if color_cnt.get(color, 0) == 0:    # 加一之前为 0 ⇒ 新颜色
                distinct += 1
            color_cnt[color] = color_cnt.get(color, 0) + 1
            ball_color[ball] = color
            ans.append(distinct)
        return ans
```

> 💡 两份代码通过题面 2 个示例、`limit = 0`、同一球反复染同一颜色、颜色被反复清空/重建等边界，并与「每步重算颜色集合」的暴力实现做了 300 组随机对拍（`mismatch = 0`）；$n = 10^5$、颜色值域 $10^9$ 时 C++ 约 0.04 s、Python 约 0.11 s。

## 8. 边界情况与易错点

1. **计数归零不删键**：`colorCnt[old]` 减到 0 后若保留键，任何「用 `size()` 当 distinct」的写法都会高估颜色数。
2. **旧色 == 新色**：必须走完「先减后加」的流程，`distinct` 才能自动抵平；跳过旧色处理会在「该球是此色唯一持有者」时少算或多算。
3. **`limit` 极大**：$10^9$ 时不能用数组，必须哈希；同时注意球编号可能为 0（示例 2），不要用 0 当「未染色」哨兵，应使用「键是否存在」。
4. **颜色值域极大**：$y \le 10^9$，与球编号同理，只能哈希。
5. **首次操作**：`ballColor` 中查不到球，直接进入「上新颜色」分支，不能访问空迭代器。
6. **未染色的球不算颜色**：只有 `colorCnt` 中存在的键才计数，不要用 `limit + 1` 之类的总数参与计算。
7. **答案必须与操作一一对应**：即使某次操作后颜色数没变，也要追加当前值。

**延伸思考**：本题的 `distinct` 之所以能 $O(1)$ 增量维护，是因为一次操作只影响两种颜色的计数，而「不同颜色数」是可加性的一阶统计量。若改问「出现次数最多的颜色的球数」，一阶可加性就失效了，需要再维护一个「球数 → 颜色个数」的桶并对最大值做指针移动（类似 LFU 的结构）；若改问「颜色数 × 球数的加权和」之类，则需要同时维护多个统计量。这类「局部修改 + 全局聚合」的题目，通用套路是：选一个**对单点修改敏感度低**的聚合量，并让每个修改只触碰 $O(1)$ 个桶。
