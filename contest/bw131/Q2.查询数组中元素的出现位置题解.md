# LeetCode 查询数组中元素的出现位置 题解

## 1. 题目概述

- **标题 / 题号**：查询数组中元素的出现位置（#3159，medium）
- **链接**：https://leetcode.cn/problems/find-occurrences-of-an-element-in-an-array/
- **来源**：LeetCode 第 131 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表

**题意**：给定数组 `nums`、查询数组 `queries` 和目标值 `x`。对每个 `queries[i] = q`，求 `nums` 中**第 $q$ 个** `x` 出现的**下标**；若 `x` 的出现次数不足 $q$，答案为 $-1$。返回与 `queries` 等长的答案数组。

这里要特别区分两个容易混淆的量：查询里的 $q$ 是「**第几个** `x`」（从 1 开始计数），而要返回的是该元素在 `nums` 中的**下标**（从 0 开始）。

**约束**：

- $1 \le \text{nums.length}, \text{queries.length} \le 10^5$
- $1 \le \text{queries}[i] \le 10^5$
- $1 \le \text{nums}[i], x \le 10^4$

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,1,7], queries = [1,3,2,4], x = 1
输出：[0,-1,2,-1]
解释：值为 1 的下标依次是 [0, 2]。
      第 1 个 → 下标 0；第 3 个不存在（只有 2 个 1）→ -1；
      第 2 个 → 下标 2；第 4 个不存在 → -1。
```

**示例 2**

```text
输入：nums = [1,2,3], queries = [10], x = 5
输出：[-1]
解释：nums 中没有 5，任何查询都返回 -1。
```

**示例 3（边界补充）**

```text
输入：nums = [2,2], queries = [1,2], x = 2
输出：[0,1]
解释：每个 2 都按下标顺序被编号，第 1 个在下标 0、第 2 个在下标 1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询 $q$，从头扫描 `nums`，数到第 $q$ 个等于 $x$ 的元素就返回其下标，扫完不够就返回 $-1$。单次 $O(n)$，总时间 $O(n \cdot |\text{queries}|)$，最坏 $10^{10}$ 量级，必然超时。

问题在于**大量查询反复做同一件事**：它们问的都是同一个 $x$，只是「第几个」不同。因此把所有答案**预处理**出来，让每次查询变成一次数组访问。

### 3.2 核心观察：把 $x$ 的所有下标按顺序串成一张表

![核心观察：一次扫描建出 x 的下标列表](images/bw131_q2_position_lists.svg)

从左到右扫描 `nums`，遇到等于 $x$ 的位置就把下标 `i` 追加到列表 `pos` 尾部。由于扫描顺序就是下标递增顺序，`pos` 天然**升序**，且 `pos[k]` 恰好是「第 $k+1$ 个 $x$ 的下标」。

于是查询 $q$（1-based）直接映射为 `pos[q-1]`；若 `q` 超过 `pos` 的长度，说明出现次数不足，返回 $-1$。**单次查询 $O(1)$**。

> 💡 如果查询针对的是多个不同的目标值，则应建立 `值 → 下标列表` 的哈希表；本题 `x` 只有一个，所以只收集 `x` 的位置即可，空间最省。

### 3.3 算法流程

![算法流程：预处理一次，查询逐条 O(1)](images/bw131_q2_algorithm_flow.svg)

```text
1. pos = []，一次扫描 nums：
       若 nums[i] == x：pos.push_back(i)
2. 对每个查询 q：
       q <= len(pos) ? answer.push_back(pos[q-1])
                     : answer.push_back(-1)
3. 返回 answer
```

### 3.4 示例演算

![查询映射：1-based 的 q 与 0-based 的下标](images/bw131_q2_query_mapping.svg)

`nums = [1,3,1,7]`、`x = 1` 时，`pos = [0, 2]`，长度 2。四个查询的处理：

| $i$ | `queries[i]` | 比较 | 取值 | 答案 |
|-----|--------------|------|------|------|
| 0 | 1 | $1 \le 2$ | `pos[0]` | 0 |
| 1 | 3 | $3 > 2$ | 越界 | -1 |
| 2 | 2 | $2 \le 2$ | `pos[1]` | 2 |
| 3 | 4 | $4 > 2$ | 越界 | -1 |

输出 `[0,-1,2,-1]`，与示例 1 一致。

## 4. 算法细节

1. **下标基准转换**：`pos` 的下标从 0 开始，而 $q$ 从 1 开始，所以取 `pos[q-1]`。这是本题最容易写错的地方——写成 `pos[q]` 会让所有答案右移一位，并在 $q = |pos|$ 时越界。
2. **越界判定用「长度」而不是「是否等于 0」**：$-1$ 是「不存在」的标记，而答案里确实可能出现下标 0，不能用 0 当哨兵。
3. **只需收集 $x$**：题面只有单一目标值，不必为每个值都建列表；若建全量映射，时间与空间都要乘以值域。
4. **`pos` 天然有序**：因为按 $i$ 递增扫描并尾部追加，无需再排序，这也是「下标」定义的直接推论。
5. **答案数组长度必须等于 `queries` 长度**：查询之间有重复（如 `[1,1,1]`）时要重复输出同一个下标，不能用集合去重。
6. **输入规模与常数**：$10^5$ 级别下 `vector::reserve` 能省掉多次扩容；Python 用列表推导预分配亦可。
7. **值域无关性**：`nums[i] \le 10^4` 只影响「能否用桶数组」，本题只用单链表，$O(n)$ 空间与值域无关。

## 5. 正确性证明

**引理 1（`pos` 的语义）**：扫描结束后，`pos` 的长度等于 `x` 在 `nums` 中的出现次数，且对任意 $k \in [0, |\text{pos}|)$，`pos[k]` 是 `nums` 中第 $k+1$ 个等于 $x$ 的元素下标；`pos` 严格递增。

**证明**：按 $i = 0, 1, \dots, n-1$ 顺序扫描，每遇到一个 $x$ 就追加当前下标，故第 $k+1$ 次追加的值正是第 $k+1$ 个 $x$ 的下标，长度即出现次数。又追加顺序与 $i$ 的递增顺序一致，故严格递增。∎

**引理 2（查询映射）**：对任意 $q \ge 1$，若 $q \le |\text{pos}|$，则 `nums` 中第 $q$ 个 $x$ 的下标是 `pos[q-1]`；若 $q > |\text{pos}|$，则不存在第 $q$ 个 $x$。

**证明**：前半由引理 1 取 $k = q-1$ 立得。后半由引理 1 中「长度等于出现次数」：出现次数不足 $q$，自然不存在第 $q$ 个。∎

**定理**：算法输出的答案数组与题目要求逐项一致。

**证明**：对每个查询 $q$，算法分两种情况：
- $q \le |\text{pos}|$：输出 `pos[q-1]`，由引理 2 它正是第 $q$ 个 $x$ 的下标，正确；
- $q > |\text{pos}|$：输出 $-1$，由引理 2 第 $q$ 个 $x$ 不存在，正确。

所有查询独立处理且顺序保持，故整个数组正确。∎

## 6. 复杂度分析

- **时间**：预处理 $O(n)$；每个查询 $O(1)$，共 $O(m)$，其中 $m = |\text{queries}|$；总计 $O(n + m)$。
- **空间**：`pos` 最坏存 $n$ 个下标，答案数组 $O(m)$，合计 $O(n + m)$；除输入输出外无额外结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    std::vector<int> occurrencesOfElement(std::vector<int>& nums,
                                          std::vector<int>& queries, int x) {
        std::vector<int> pos;
        for (int i = 0; i < (int)nums.size(); ++i)
            if (nums[i] == x) pos.push_back(i);      // 下标递增，天然有序

        std::vector<int> ans;
        ans.reserve(queries.size());
        for (int q : queries)
            ans.push_back((q >= 1 && q <= (int)pos.size()) ? pos[q - 1] : -1);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def occurrencesOfElement(self, nums: list[int], queries: list[int], x: int) -> list[int]:
        pos = [i for i, v in enumerate(nums) if v == x]   # 天然升序
        return [pos[q - 1] if 1 <= q <= len(pos) else -1 for q in queries]
```

> 💡 两份代码通过题面 2 个示例与补充示例，并与「逐查询暴力扫描」的参考实现做了 300 组随机对拍（含 $x$ 不存在、$q$ 超过出现次数、重复查询），`mismatch = 0`；$n = m = 10^5$ 的规模下 C++ 约 0.02 s、Python 约 0.07 s。

## 8. 边界情况与易错点

1. **`pos[q-1]` 的差一错误**：最典型的失分点。记忆口诀：$q$ 是「第几个」，从 1 数；列表下标从 0 数，所以减 1。
2. **$x$ 完全不存在**：`pos` 为空，任何 $q \ge 1$ 都返回 $-1$，示例 2 覆盖。此时不要访问 `pos[0]`。
3. **$q$ 恰好等于出现次数**：`pos[q-1]` 是最后一个合法元素，条件必须是 $\le$ 而不是 $<$。
4. **答案含下标 0**：不能用 0 作为「不存在」的标记，必须显式用 $-1$。
5. **`queries` 中有重复值**：逐条输出即可，不要因为重复而跳过。
6. **返回值长度**：必须与 `queries` 等长，返回 `pos` 或去重后的结果都是错的。
7. **$q$ 的上界**：$q$ 可达 $10^5$，而 `x` 的出现次数不超过 $n$，因此大多数查询会落到越界分支，判定顺序要正确。
