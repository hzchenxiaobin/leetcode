# LeetCode 求出最多标记下标 题解

## 1. 题目概述

- **标题 / 题号**：求出最多标记下标（#2576，medium）
- **链接**：https://leetcode.cn/problems/find-the-maximum-number-of-marked-indices/
- **来源**：LeetCode 第 334 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、双指针、二分查找、排序

**题意**：给定下标从 $0$ 开始的整数数组 `nums`，初始所有下标未标记。可以执行以下操作**任意次**：选择两个**互不相同且未标记**的下标 $i$ 和 $j$，满足 $2 \times \text{nums}[i] \le \text{nums}[j]$，则将 $i$ 和 $j$ **都标记**。返回最多能标记的下标数目。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [3,5,2,4]
输出：2
解释：选 i = 2、j = 1：2×nums[2] = 4 ≤ nums[1] = 5，标记下标 2 和 1。没有更多可执行的操作。
```

**示例 2**

```text
输入：nums = [9,2,5,4]
输出：4
解释：先选 (i=3, j=0)：2×4 = 8 ≤ 9；再选 (i=1, j=2)：2×2 = 4 ≤ 5。四个下标全部标记。
```

**示例 3**

```text
输入：nums = [7,6,8]
输出：0
解释：2×6 = 12 > 8，任何两个元素都凑不出合法操作。
```

**示例 4**（自造，覆盖奇数长度）

```text
输入：nums = [1,2,100,200,300]
输出：4
解释：例如 (1,100)、(2,200) 配成两对，标记 4 个下标；5 个元素至多配 ⌊5/2⌋ = 2 对。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是回溯枚举所有配对方案：每次挑一个未标记的 $i$、再挑一个满足条件的 $j$，标记二者并递归。配对方案数随 $n$ 指数级爆炸（最坏 $(n-1)!!$ 量级），即使状压 DP $O(2^n)$ 在 $n = 10^5$ 下也毫无希望。问题本质是「在值满足 $2a \le b$ 的元素间求最大配对数」，必须挖掘**单调结构**把搜索降为贪心。

注意到：标记条件只依赖**值**的大小关系，与下标位置无关——任何配对方案在排序前后同样可行。**排序不改变答案，却能暴露结构**。

### 3.2 核心观察：排序切半，小值池 × 大值池

![核心观察：排序后切成小值池与大值池，小值从小到大配大值从小到大，配成几对标记 2 倍个](images/mark334_concept.svg)

**观察 1（一对消耗一小一大）**：每对中 $i$ 是被翻倍的「**小值**」、$j$ 是作上界的「**大值**」。由 $a \ge 1$ 得 $b \ge 2a > a$，即**小值严格小于大值**。因此答案 $= 2 \times$ 配对数 $k$（恒为偶数），且 $k \le \lfloor n/2 \rfloor$。

**观察 2（交换论证）**：最优解中，小值可以换成**最小的 $k$ 个**、大值换成**最大的 $k$ 个**——把某个偏大的小值换成更小的值，条件 $2 \times \text{小} \le \text{大}$ 只松不紧；把某个偏小的大值换成更大的值同理。反复交换即可把任何最优解规范化为「小值全在左半、大值全在右半」（严格证明见 §5 引理 2）。

**观察 3（判据与单调性）**：于是「能标记 $2k$ 个下标」$\iff$「排序后前 $k$ 小与后 $k$ 大**按序**配对全部成立」，即对所有 $t \in [0,k)$ 有 $2 v_t \le v_{n-k+t}$。又 $k$ 对可行 $\Rightarrow k-1$ 对也可行（丢掉一对），判定关于 $k$ **单调**——既可**二分答案**，也可用**双指针一趟**直接求出最大 $k$。

### 3.3 算法流程

![算法流程：排序，i=0、j=n−⌊n/2⌋ 起，判 2·nums[i]≤nums[j]：是则 i++，否则只 j++；j 扫完返回 2×i](images/mark334_flow.svg)

1. **排序**：`nums` 升序排序；
2. **初始化**：`i = 0`（小值指针）；`j` 从 $n - \lfloor n/2 \rfloor$（顶半起点，即 $\lceil n/2 \rceil$）出发；
3. **扫描**：`j` 逐轮右移，每轮判断 $2 \times \text{nums}[i] \le \text{nums}[j]$：成立则**配对**，`i++`（`j` 下一轮自然右移）；不成立则只右移 `j`（当前大值不够格，换更大的）；
4. **返回** $2 \times i$。

顶半恰好含 $\lfloor n/2 \rfloor$ 个候选大值——正是配对数上界，因此小值至多消耗前 $\lfloor n/2 \rfloor$ 个，**两池永不相交**；循环轮数自动钳制 `i`，无需手写上界。

### 3.4 示例演算

![示例演算：[9,2,5,4] 排序后全配成两对得 4；[3,5,2,4] 排序后第二对 6&gt;5 配不动得 2](images/mark334_walkthrough.svg)

**示例 2**：`nums = [9,2,5,4]` → 排序 $[2,4,5,9]$，$n=4$，`j` 从 $4-2=2$ 起：

| 轮 | $j$ | $\text{nums}[j]$ | $i$ | $\text{nums}[i]$ | 判断 | 动作 |
|----|-----|------------------|-----|------------------|------|------|
| ① | 2 | 5 | 0 | 2 | $4 \le 5$ ✓ | 配对 $(2,5)$，`i→1` |
| ② | 3 | 9 | 1 | 4 | $8 \le 9$ ✓ | 配对 $(4,9)$，`i→2` |

`j` 扫完，返回 $2 \times 2 = 4$（全部标记）。

**示例 1**：`nums = [3,5,2,4]` → 排序 $[2,3,4,5]$：

| 轮 | $j$ | $\text{nums}[j]$ | $i$ | $\text{nums}[i]$ | 判断 | 动作 |
|----|-----|------------------|-----|------------------|------|------|
| ① | 2 | 4 | 0 | 2 | $4 \le 4$ ✓ | 配对 $(2,4)$，`i→1` |
| ② | 3 | 5 | 1 | 3 | $6 > 5$ ✗ | 大值耗尽，停 |

返回 $2 \times 1 = 2$。

**示例 3**：$[7,6,8] \to [6,7,8]$，`j` 从 $3-1=2$ 起：$2 \times 6 = 12 > 8$，一对都配不成，返回 $0$。

## 4. 算法细节

1. **排序为何无损**：条件 $2 \times \text{nums}[i] \le \text{nums}[j]$ 只依赖值的大小关系，与下标位置无关，故答案只由值的多重集合决定，排序仅用于暴露「小 / 大」结构。
2. **切点为何是 $\lceil n/2 \rceil$**：大值池取顶半（位置 $\lceil n/2 \rceil$ 起），恰好 $\lfloor n/2 \rfloor$ 个 = 配对数上界；小值至多用前 $\lfloor n/2 \rfloor$ 个，两池不相交，`i` 被「每轮至多 +1」自动钳制（循环共 $\lfloor n/2 \rfloor$ 轮）。若写 `while` 版本，可显式加 `i < n/2` 作保险。
3. **贪心方向**：小值从小到大、大值也从小到大——用「最小的够格大值」配「最小的未配小值」，把更大的大值留给后面更难配的小值，与 [455. 分发饼干](https://leetcode.cn/problems/assign-cookies/) 同款。
4. **溢出**：$2 \times \text{nums}[i]$ 上界 $2 \times 10^9$，恰好未超 `INT_MAX`（约 $2.147 \times 10^9$）但极度贴脸，C++ 中用 `2LL * nums[i]` 提升中间量类型。
5. **返回值**：$2 \times i$——答案必为偶数。

## 5. 正确性证明

记排序后 $v_0 \le v_1 \le \cdots \le v_{n-1}$。注意 $k$ 对配对占用 $2k$ 个互异位置，故 $2k \le n$，前缀 $[0,k)$ 与后缀 $[n-k,n)$ 不相交。

**引理 1（每对必是一小一大）**：合法配对 $(a, b)$ 满足 $2a \le b$，由 $a \ge 1$ 得 $b \ge 2a > a$，即 $a < b$ **严格**。故排序后任一方案中，每对小值的位置必排在大值的位置之前。

**引理 2（规范化）**：若可标记 $2k$ 个下标，则存在同样标记 $2k$ 个下标的方案，使小值恰为排序后**前 $k$ 个位置**、大值恰为**后 $k$ 个位置**。

**证明**（两阶段交换，每步保持「$k$ 对、条件成立、位置互异」）：

**阶段一（大值赶往后缀）**：只要后缀 $[n-k, n)$ 存在不是大值的位置 $u$：由鸽笼，必有某大值 $l$ 位于位置 $< n-k$，设其搭档小值为 $p$。
- 若 $u$ 未标记：把 $(p,l)$ 换成 $(p,u)$。由位置 $l < u$ 得 $v_l \le v_u$，故 $2v_p \le v_l \le v_u$ ✓；
- 若 $u$ 是小值（搭档大值 $w$）：把 $(p,l)$、$(u,w)$ 换成 $(p,u)$、$(l,w)$。前者 $2v_p \le v_l \le v_u$ ✓；后者由原对 $2v_u \le v_w$ 与 $v_l \le v_u$ 得 $2v_l \le v_w$ ✓。

每步使「后缀中的大值数」严格 +1 且不减少，至多 $k$ 步后后缀全部为大值。

**阶段二（小值赶进前缀）**：只要前缀 $[0,k)$ 存在不是小值的位置 $t$：由鸽笼，必有某小值 $s$ 位于位置 $\ge k$；又后缀已全为大值，故 $s$ 落在中间区。设 $s$ 的搭档大值为 $b$。
- 若 $t$ 未标记：把 $(s,b)$ 换成 $(t,b)$。由 $t < k \le s$ 得 $v_t \le v_s$，故 $2v_t \le 2v_s \le v_b$ ✓；
- 若 $t$ 是大值（搭档小值 $q$）：把 $(s,b)$、$(q,t)$ 换成 $(t,b)$、$(q,s)$。前者 $2v_t \le 2v_s \le v_b$ ✓；后者由原对 $2v_q \le v_t$ 及 $v_t \le v_s$ 得 $2v_q \le v_s$ ✓。

每步使「前缀中的小值数」严格 +1，且不会把后缀大值改成小值（$s$ 只会改成大值或弃标），阶段一成果保持。至多 $k$ 步后前缀全为小值、后缀全为大值。∎

**定理 1（按序配对判据）**：可标记 $2k$ 个下标 $\iff$ 对所有 $t \in [0,k)$ 有 $2 v_t \le v_{n-k+t}$。

![check(k)：前 k 小与后 k 大按序配对，谓词随 k 单调，可二分也可双指针](images/mark334_check_k.svg)

**证明**：

（$\Leftarrow$）令第 $t$ 对为 $(v_t,\ v_{n-k+t})$：前缀与后缀不相交（$2k \le n$），是 $k$ 对合法配对。

（$\Rightarrow$）由引理 2，存在「小值 = 前缀、大值 = 后缀」的方案，即前缀与后缀之间的完美匹配。反设存在 $t$ 使 $2v_t > v_{n-k+t}$：考察后缀最小的 $t+1$ 个大值 $v_{n-k}, \ldots, v_{n-k+t}$，其中每个 $q \le v_{n-k+t} < 2v_t$，与它配对的小值 $p$ 须满足 $2p \le q < 2v_t$，即 $p < v_t$；而值严格小于 $v_t$ 的小值只可能位于位置 $0..t-1$，至多 $t$ 个。$t+1$ 个大值需要 $t+1$ 个互异的小值，鸽笼矛盾。∎

**推论（单调性）**：check$(k)$ 为真 $\Rightarrow$ check$(k-1)$ 为真。

**证明**：设 $2v_t \le v_{n-k+t}$ 对 $t < k$ 成立，则对 $t < k-1$：$2v_t \le v_{n-k+t} \le v_{n-(k-1)+t}$（位置更大则值不减）。∎

> 💡 推论意味着谓词呈「✓✓…✓✗✗…✗」，可二分 $k \in [0, \lfloor n/2 \rfloor]$，单次 check $O(k)$。

**定理 2（双指针贪心正确性）**：贪心配出的对数恰等于最大配对数 $k^*$。

**证明**：（$\le$）贪心产出的每对都合法，且由「$i <$ 循环轮数 $\le \lfloor n/2 \rfloor$、$j \ge \lceil n/2 \rceil$」知两位置互异，故贪心对数 $\le k^*$。

（$\ge$）设最大对数为 $k$，由定理 1 位置 $n-k+t$ 满足 $2v_t \le v_{n-k+t}$（$t < k$）。归纳证明贪心配第 $t$ 对所用大值位置 $j_t \le n-k+t$：
- $t=0$：顶半起点 $n-\lfloor n/2 \rfloor \le n-k$，且扫到位置 $n-k$ 时条件必成立，故 $j_0 \le n-k$；
- $t \to t+1$：下一轮 $j$ 从 $j_t + 1 \le n-k+t+1$ 起逐位右移，而位置 $n-k+t+1 \le n-1$ 必满足 $2v_{t+1} \le v_{n-k+t+1}$，故在越界前必配上。

于是小值 $v_0, \ldots, v_{k-1}$ 全部配上，贪心对数 $\ge k$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序主导 $O(n \log n)$；双指针扫描顶半 $\lfloor n/2 \rfloor$ 轮、每轮 $O(1)$，合计 $O(n)$。二分版本为排序 $O(n \log n)$ + $\log n$ 轮 × $O(n)$ check，同阶但常数更大。
- **空间复杂度**：$O(\log n)$ 额外空间（`std::sort` 内省排序递归栈；Python Timsort 最坏需 $O(n)$ 临时空间），双指针本身仅 $O(1)$ 标量。

排序的 $\Omega(n \log n)$ 是本题模板的固有开销；判定部分已被压到线性，整体已最优到常数因子。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxNumOfMarkedIndices(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = nums.size();
        int i = 0;                          // 小值指针：只在前 ⌊n/2⌋ 个里走
        for (int j = n - n / 2; j < n; ++j) { // 大值指针：扫顶半 ⌊n/2⌋ 个候选
            if (2LL * nums[i] <= nums[j]) {  // 2×10^9 贴近 INT_MAX，用 2LL 稳妥
                ++i;                         // 配对成功；j 随循环自然右移
            }
        }
        return 2 * i;                        // 答案必为偶数
    }
};
```

### Python

```python
class Solution:
    def maxNumOfMarkedIndices(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)
        i = 0
        for j in range(n - n // 2, n):      # 顶半 ⌊n//2⌋ 个候选大值
            if 2 * nums[i] <= nums[j]:
                i += 1
        return i * 2
```

### Python（二分答案变体，对应定理 1）

```python
class Solution:
    def maxNumOfMarkedIndices(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)

        def check(k: int) -> bool:          # 前 k 小 与 后 k 大按序配对
            return all(2 * nums[t] <= nums[n - k + t] for t in range(k))

        lo, hi = 0, n // 2                  # hi 必须 ≤ ⌊n/2⌋，两池才不相交
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if check(mid):
                lo = mid
            else:
                hi = mid - 1
        return 2 * lo
```

## 8. 边界情况与易错点

1. **$n = 1$**：选不出两个互异下标，返回 $0$；顶半为空，循环不进入，代码自然覆盖。
2. **奇数长度的「中间元素」陷阱**：若大值池从 $\lfloor n/2 \rfloor$ 起且 `i` 无上界，$n=5$ 时 `for j in range(n//2, n)` 会让正中间元素先当大值、又被 `i` 回吃当小值。以 $[1,2,100,200,300]$ 为例：$j=2$ 配 $(1,100)$、$j=3$ 配 $(2,200)$、$j=4$ 又配 $(100,300)$，误返回 $6$（真实答案 $4$）。**修复**：大值池从 $\lceil n/2 \rceil$ 起跳过中间元素（本文实现），或给 `i` 加 `< n//2` 上界。
3. **反向贪心是错的**：「用最大的大值配最小的小值」浪费大值——$[2,4,5,9]$ 中先配 $(2,9)$，剩下 $4$ 配不上 $5$，只得 $2$；正确答案是 $4$（$(2,5),(4,9)$）。大值必须**从小到大**供给。
4. **溢出临界**：$2 \times 10^9$ 距 `INT_MAX` 仅约 $1.5 \times 10^8$，看似不溢实则贴脸，约束微调即翻车且属未定义行为，C++ 一律 `2LL`。
5. **相等元素不能互配**：$2a \le a \Rightarrow a \le 0$ 与 $a \ge 1$ 矛盾，故排序后相同值的元素之间天然无法配对；两池不相交已保证 $i \ne j$，无需特判。
6. **答案必为偶数**：调试时若返回奇数，必是重复计数或漏乘 2 的 bug。
7. **二分上界**：`hi` 必须取 $\lfloor n/2 \rfloor$，否则前缀后缀重叠，check 语义失效。
