# LeetCode 左右元素和的差值 题解

## 1. 题目概述

- **标题 / 题号**：左右元素和的差值（#2574，easy）
- **链接**：https://leetcode.cn/problems/left-and-right-sum-differences/
- **来源**：LeetCode 第 334 场周赛 Q1
- **难度**：简单
- **标签**：数组、前缀和、前后缀分解

**题意**：给定下标从 $0$ 开始、长度为 $n$ 的正整数数组 `nums`。定义 $\text{leftSum}[i]$ 为 $i$ **左侧**元素之和（左侧为空则取 $0$），$\text{rightSum}[i]$ 为 $i$ **右侧**元素之和（右侧为空则取 $0$）。返回长度为 $n$ 的数组 `answer`，其中 $\text{answer}[i] = \bigl|\text{leftSum}[i] - \text{rightSum}[i]\bigr|$。

**约束**：

- $1 \le n \le 1000$
- $1 \le \text{nums}[i] \le 10^5$

> 📚 本题在本仓库另有[每日题解 2574](../../solution/2501-2600/2574_左侧右侧求和差值.md)：含展开式写法、前缀/后缀两数组对照版与面试问答；本篇侧重赛时签到最短路径与「三段守恒」模板的复盘。

## 2. 示例

**示例 1**

```text
输入：nums = [10,4,8,3]
输出：[15,1,11,22]
解释：leftSum = [0,10,14,22]，rightSum = [15,11,3,0]，
answer = [|0-15|, |10-11|, |14-3|, |22-0|] = [15,1,11,22]。
```

**示例 2**

```text
输入：nums = [1]
输出：[0]
解释：唯一元素左右两侧均为空，leftSum = rightSum = 0，差为 0。
```

**示例 3**（自造，覆盖 answer 为 0 的情况）

```text
输入：nums = [5,5,5]
输出：[10,0,10]
解释：T = 15。i=0：|0-10|=10；i=1：|5-5|=0（左右和恰好相等）；
i=2：|10-0|=10。
```

## 3. 解题思路

### 3.1 赛时最短路：逐位切片求和

签到题的第一目标是**用最短时间写出一定对的代码**。最直接的做法是按定义逐位重算：

```python
class Solution:
    def leftRightDifference(self, nums: List[int]) -> List[int]:
        n = len(nums)
        return [abs(sum(nums[:i]) - sum(nums[i+1:])) for i in range(n)]
```

时间 $O(n^2)$（每个 $i$ 把左右两段各扫一遍）、空间 $O(n)$（切片临时对象）。$n \le 1000$ 时总计约 $10^6$ 次加法，赛时可直接 AC。但它完全无视了「相邻位置的左右和只差一个元素」的增量结构——每个位置都从头重算，数据范围放大到 $10^5$ 即超时。复盘时应把线性模板沉淀下来，这也是本场 Q2（前缀余数滚动）同一个「前缀信息增量维护」套路的入门形态。

### 3.2 核心观察：三段守恒 + 前缀滚动

![核心观察：leftSum[i] + nums[i] + rightSum[i] = 总和 T，rightSum 可由两个减法扣出；leftSum 相邻下标只差一个元素可滚动维护](images/lrsum334_concept.svg)

两个观察把 $O(n^2)$ 压成 $O(n)$：

- **三段守恒**：对任意 $i$，左侧 $[0, i-1]$、自身 $\{i\}$、右侧 $[i+1, n-1]$ 三段区间不重不漏地拼成整个数组，故
  $$
  \text{leftSum}[i] + \text{nums}[i] + \text{rightSum}[i] = T, \qquad T = \sum_{k=0}^{n-1}\text{nums}[k].
  $$
  手握总和 $T$ 与左侧和，右侧和就是**两个减法**的事：$\text{rightSum}[i] = T - \text{leftSum}[i] - \text{nums}[i]$，无需为每个 $i$ 重扫右侧。
- **前缀滚动**：$\text{leftSum}[i+1] = \text{leftSum}[i] + \text{nums}[i]$，相邻下标的前缀和只差一个元素，从左到右一趟即可 $O(1)$ 转移。

于是一次求和（得 $T$）加一趟滚动（维护 `leftSum`）就得到所有位置的答案。

> ⚠️ **先用后加**：处理 $i$ 时 `leftSum` 必须恰好是 $i$ 左侧之和（**不含** $\text{nums}[i]$）；写完 $\text{answer}[i]$ 之后才执行 `leftSum += nums[i]` 把自己并入，为下一个下标备好左侧和。顺序颠倒则每个位置都错用 $\text{leftSum}[i+1]$，全盘错位一个元素。

### 3.3 算法流程

![算法流程：求 T → leftSum=0 → 循环：rightSum=T−leftSum−nums[i]，answer[i]=|leftSum−rightSum|，leftSum+=nums[i] → 返回](images/lrsum334_flow.svg)

1. **求总和**：一趟遍历得 $T = \sum \text{nums}$；
2. **滚动扫描**：`leftSum = 0`，对 $i = 0, \dots, n-1$：
   - $\text{rightSum} = T - \text{leftSum} - \text{nums}[i]$；
   - $\text{answer}[i] = |\text{leftSum} - \text{rightSum}|$；
   - $\text{leftSum} \mathrel{+}= \text{nums}[i]$（**先用后加**）；
3. **返回** `answer`。

### 3.4 示例演算

![示例演算：nums=[10,4,8,3]，T=25，逐步滚动 leftSum 并扣出 rightSum，得到 [15,1,11,22]](images/lrsum334_walkthrough.svg)

以示例 1 `nums = [10,4,8,3]` 为例，$T = 10+4+8+3 = 25$：

| $i$ | $\text{nums}[i]$ | leftSum（用前） | rightSum $=T-\text{leftSum}-\text{nums}[i]$ | $\text{answer}[i]$ | 更新后 leftSum |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 10 | $0$  | $25-0-10=15$  | $\|0-15\|=\mathbf{15}$  | $0+10=10$ |
| 1 | 4  | $10$ | $25-10-4=11$  | $\|10-11\|=\mathbf{1}$  | $10+4=14$ |
| 2 | 8  | $14$ | $25-14-8=3$   | $\|14-3\|=\mathbf{11}$  | $14+8=22$ |
| 3 | 3  | $22$ | $25-22-3=0$   | $\|22-0\|=\mathbf{22}$  | $22+3=25$ |

输出 `[15,1,11,22]`。注意末步更新后 `leftSum = 25 = T`——前缀和追平总和，正是「扫完整段」的标志；这次冗余写入换来了循环体的统一。示例 2 中 $n = 1$：$i=0$ 时 `leftSum = 0`、`rightSum = 1-0-1 = 0`，输出 `[0]`，无需任何特判。

## 4. 算法细节

1. **唯一公式**：$\text{rightSum}[i] = T - \text{leftSum}[i] - \text{nums}[i]$。也可代入展开为 $\text{answer}[i] = \bigl|\,2\cdot\text{leftSum}[i] + \text{nums}[i] - T\,\bigr|$，省一次减法，但可读性略降，赛时以「先扣 rightSum 再作差」更贴题意。
2. **先用后加**：`rightSum` 与 `answer[i]` 都算完之后才 `leftSum += nums[i]`，保证处理 $i$ 时 `leftSum` 的语义是「$i$ 左侧之和」。
3. **数值范围**：$T \le 1000 \times 10^5 = 10^8 < 2^{31}-1 \approx 2.1\times 10^9$，且 $\text{answer}[i] \le T$，全程 `int` 安全——对照本场 Q2 必须开 `long long`，签到题也应花五秒核一遍范围再提交。
4. **结果数组定长**：`vector<int> answer(n)` 一次分配，避免 `push_back` 反复扩容。
5. **两数组对照版**：也可预处理前缀和数组与后缀和数组再逐位作差，$O(n)$ 额外空间。仅当之后要**反复查询**各位置的左右和时才值得；单次取差场景被恒等式版碾平为 $O(1)$ 额外空间。

## 5. 正确性证明

**引理 1（滚动不变量）**：进入处理下标 $i$ 的循环体时，变量 `leftSum` $= \sum_{k=0}^{i-1}\text{nums}[k] = \text{leftSum}[i]$。

**证明**：对 $i$ 归纳。基例 $i = 0$：进入循环前 `leftSum` 初始化为 $0$，而空和 $\text{leftSum}[0] = 0$，成立。归纳步：设处理 $i$ 时 `leftSum` $= \text{leftSum}[i]$；循环体末尾执行 `leftSum += nums[i]`，故进入 $i+1$ 时 `leftSum` $= \text{leftSum}[i] + \text{nums}[i] = \sum_{k=0}^{i}\text{nums}[k] = \text{leftSum}[i+1]$。∎

**引理 2（三段守恒）**：对任意 $0 \le i < n$，$\text{leftSum}[i] + \text{nums}[i] + \text{rightSum}[i] = T$。

**证明**：区间 $[0, i-1]$、$\{i\}$、$[i+1, n-1]$ 两两不交且并集为 $[0, n-1]$（$i = 0$ 或 $i = n-1$ 时对应区间为空，和约定为 $0$）。由求和的交换律与结合律，三段之和等于全体元素之和 $T$。∎

**定理**：算法返回的 `answer` 满足对每个 $0 \le i < n$：$\text{answer}[i] = \bigl|\text{leftSum}[i] - \text{rightSum}[i]\bigr|$。

**证明**：由引理 1，处理 $i$ 时循环体内的 `leftSum` 恰为 $\text{leftSum}[i]$；由引理 2，变量 `rightSum` $= T - \text{leftSum}[i] - \text{nums}[i] = \text{rightSum}[i]$（先用后加保证此刻尚未并入 $\text{nums}[i]$）。故写入的 $\text{answer}[i] = \bigl|\text{leftSum}[i] - \text{rightSum}[i]\bigr|$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。第一趟求 $T$ 做 $n$ 次加法；第二趟每步两次减法、一次绝对值、一次加法，共 $n$ 步，均为 $O(1)$。读入必须访问每个元素，$\Omega(n)$ 不可破，已最优。
- **空间复杂度**：$O(1)$ 额外空间。仅 `total` / `leftSum` / `rightSum` 三个标量；结果数组不计入。相比两数组对照版的 $O(n)$ 辅助空间，恒等式把「存右侧和」压成「算右侧和」。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> leftRightDifference(vector<int>& nums) {
        int total = 0;
        for (int x : nums) total += x;                 // T ≤ 1e8，int 安全
        int n = nums.size();
        vector<int> answer(n);
        int leftSum = 0;
        for (int i = 0; i < n; ++i) {
            int rightSum = total - leftSum - nums[i];  // 先用
            answer[i] = abs(leftSum - rightSum);
            leftSum += nums[i];                        // 后加
        }
        return answer;
    }
};
```

### Python

```python
class Solution:
    def leftRightDifference(self, nums: List[int]) -> List[int]:
        total = sum(nums)
        left_sum = 0
        answer = []
        for x in nums:
            right_sum = total - left_sum - x            # 先用
            answer.append(abs(left_sum - right_sum))
            left_sum += x                              # 后加
        return answer
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一元素左右两侧均为空，`answer = [0]`；循环里 `rightSum = T - 0 - nums[0] = 0` 自然覆盖，无需特判。
2. **先用后加搞反**：若先 `leftSum += nums[i]` 再计算，`leftSum` 变成 $\text{leftSum}[i+1]$，把 $\text{nums}[i]$ 错算进左侧和，所有位置错位一个元素——本题最高频的 WA 点。
3. **忘取绝对值**：`answer` 恒非负；不加 `abs` 会输出负数（如示例 1 的 $i=0$ 得 $-15$）。
4. **两侧多算自己**：$\text{leftSum}[i]$ 与 $\text{rightSum}[i]$ 都**不含** $\text{nums}[i]$——同 344 场 Q1 的 `suf[i+1]` 差一警惕，扣 `rightSum` 时别忘减去 `nums[i]`。
5. **溢出评估**：本题 $T \le 10^8$、`int` 足够；但若范围放宽（如 $n = 10^5$、$\text{nums}[i] = 10^9$），$T$ 与展开式中间量 $2\cdot\text{leftSum} + \text{nums}[i]$ 都会超 `int`，稳妥换 `long long`。
6. **末步冗余写入**：$i = n-1$ 的 `leftSum += nums[i]` 更新后无下一轮，属冗余；保留它换取循环体统一，仅多一次加法。
