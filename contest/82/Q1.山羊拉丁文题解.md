# LeetCode 山羊拉丁文 题解

## 1. 题目概述

- **标题 / 题号**：山羊拉丁文（#824，easy）
- **链接**：https://leetcode.cn/problems/goat-latin/
- **来源**：LeetCode 第 82 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定一个由单词组成的句子 `sentence`（单词之间、且仅用一个空格分隔），把每个词按下面三条规则改写成山羊拉丁文，再把结果按原顺序用单个空格拼回：

1. 若 $w[0]$ 是元音（`a`、`e`、`i`、`o`、`u`，大写也算），词尾追加 `"ma"`；
2. 若 $w[0]$ 是辅音，把首字母**移到词尾**，再追加 `"ma"`；
3. 设该词在句中的序号为 $k$（从 $1$ 开始），在词尾再追加 $k$ 个 `"a"`。

即第 $k$ 个词的输出形如 $\text{core}(w_k) + \text{"ma"} + \underbrace{\text{"a…a"}}_{k\ \text{个}}$。

**约束**：

- $1 \le \lvert \text{sentence} \rvert \le 150$
- `sentence` 只含英文字母与空格
- 无前导、尾随空格；单词之间**恰好一个**空格

> 💡 数据规模小到 $O(N^2)$ 都能过，所以本题的胜负手不在复杂度，而在**把三条规则拆成三个互不干扰的步骤**、把 $k$ 的边界（从 1 起）与大小写处理写对。

## 2. 示例

**示例 1**

```text
输入：sentence = "I speak Goat Latin"
输出："Imaa peaksmaaa oatGmaaaa atinLmaaaaa"
解释：I（元音）→ Ima + a        = Imaa
      speak（辅音）→ peaksma + aa  = peaksmaaa
      Goat（辅音）→ oatGma + aaa   = oatGmaaaa
      Latin（辅音）→ atinLma + aaaa = atinLmaaaaa
```

**示例 2**

```text
输入：sentence = "The quick brown fox jumped over the lazy dog"
输出："heTmaa uickqmaaa rownbmaaaa oxfmaaaaa umpedjmaaaaaa overmaaaaaaa hetmaaaaaaaa azylmaaaaaaaaa ogdmaaaaaaaaaa"
解释：9 个词全是辅音开头；第 k 个词尾部有 k 个 a，最长的是第 9 个词（9 个 a）。
```

**示例 3**（补充用例：单词数最少、单词最短的边界）

```text
输入：sentence = "a"
输出："amaa"
解释：唯一的词是元音开头 → "a" + "ma" = "ama"，追加 1 个 a → "amaa"。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是：先 `split` 出词表，再对每个词依次做「定位首字母 → 改写 → 拼 `ma` → 拼 $k$ 个 `a`」，最后 `join`。这在 $N \le 150$ 下当然能过，真正的问题在于**它把三个正交的子问题缠在一起**，于是四处都是 off-by-one 的入口：

- 尾部用 `for` 循环现场拼 $k$ 个 `a`：第 $k$ 个词就要写内层循环 $k$ 次，累计 $\Theta(W^2)$ 次字符追加（`append` 调用 $W$ 次、每次写 $k$ 个字符），与输出规模同阶但常数翻倍；
- 若不用 `split`、改成「对每个词都从头扫一遍句子定位」，切词退化成 $O(N \cdot W)$；
- 更常见的错误是**先整句补 `ma` 再整句补 `a`**：两个后缀长度不同，一步全局替换就会错位，因为 $a$ 的个数随词变化。

所以本题不需要「更快的算法」，而需要**把规则拆成一条流水线**，让每个环节只干一件事。

### 3.2 核心观察：三条规则对应流水线的三个工位

![两条分支与统一的组装顺序](images/wc82_q1_two_branches.svg)

把规则逐条对照，会发现后两条对**所有词完全一样**，只有第一条分叉：

$$
\text{core}(w) =
\begin{cases}
w, & w[0] \in V\\
w[1:] + w[0], & w[0] \notin V
\end{cases}
\qquad V = \{a, e, i, o, u\}
$$

于是第 $k$ 个词的输出可写成一个统一的式子：

$$
\text{ans}_k = \text{core}(w_k) + \text{"ma"} + \text{"a"}^k
$$

三个工位分别是「取核心」「补常量 `ma`」「补变长尾部 $\text{a}^k$」。前两个是 $O(\lvert w_k \rvert)$ 的字符串复制，第三个只与序号 $k$ 有关——它**不需要重新构造**：

$$\text{tail}_k = \text{tail}_{k-1} + \text{"a"}, \qquad \text{tail}_0 = \text{""}$$

第 $k$ 轮开始时先让 `tail` 多一个 `a`，它自然就长到 $k$ 个。这样尾部只在**增量**上花时间，累计 $\Theta(W^2)$ 次字符追加，正好等于必须写出的那部分输出，没有任何多余开销。

> ⚠️ 注意「元音」是题面钦定的封闭集合 $\{a,e,i,o,u\}$：`y` 按题意是辅音；大写 `A`、`E`、`I`、`O`、`U` 同样是元音。

### 3.3 算法流程

![算法流程图：切词、判元音、组装、推进](images/wc82_q1_algorithm_flow.svg)

1. 按空格切出词表 $w_1, w_2, \dots, w_W$；令 $k=1$，`tail = ""`，`ans = ""`。
2. `tail += 'a'`，此时 `tail` 恰有 $k$ 个 `a`。
3. 判 $w_k[0]$ 是否属于 $V$：属于则 `core = w`，否则 `core = w[1:] + w[0]`。
4. 若 $k > 1$ 先往 `ans` 追加一个空格（词间分隔），再追加 `core`、`"ma"`、`tail`。
5. $k \leftarrow k+1$；若 $k \le W$ 回到第 2 步。
6. 返回 `ans`。

第 2 步放在第 3、4 步之前是刻意安排的：**先增长尾部、再使用它**，这样「$k$ 从 1 开始」的约定被编码进循环结构里，循环体内不再出现任何 $k-1$。

### 3.4 示例演算

![示例 1 的逐词走查表](images/wc82_q1_walkthrough.svg)

对 `sentence = "I speak Goat Latin"`：

| $k$ | $w$ | $w[0] \in V$ | core | core + `ma` | 结果（+ $k$ 个 a） |
|-----|-----|--------------|------|-------------|--------------------|
| 1 | `I` | 是（大写 I） | `I` | `Ima` | `Imaa` |
| 2 | `speak` | 否 | `peaks` | `peaksma` | `peaksmaaa` |
| 3 | `Goat` | 否 | `oatG` | `oatGma` | `oatGmaaaa` |
| 4 | `Latin` | 否 | `atinL` | `atinLma` | `atinLmaaaaa` |

四个结果用单个空格拼接，得到 `"Imaa peaksmaaa oatGmaaaa atinLmaaaaa"`，与官方输出一致。注意第 1 行：`I` 是大写元音，**core 就等于原词**，不做任何移位——把 `I` 误判成辅音是最常见的翻车点。

## 4. 算法细节

1. **元音判据用封闭字符集**：`"aeiouAEIOU"` 一次列出大小写两套，`find` / `in` 是 $O(5)$ 的常数操作。不要用 `isalpha`、`islower` 之类的「近似」判断，`y` 不属于元音。
2. **先 `tail += 'a'` 再用**：把「第 $k$ 个词加 $k$ 个 a」变成「每轮无条件加一个 a」，循环体里不出现 $k-1$ 这种表达式，从结构上消灭 off-by-one。
3. **`tail` 增量维护，而不是 `"a" * k` 每次重建**：后者第 $k$ 轮要复制 $k$ 个字符，累计仍是 $\Theta(W^2)$，但每次重建会让尾部在内存里被反复分配；增量版让同一块缓冲区一直复用。
4. **空格只在 $k>1$ 时补**：句子无前导空格、无尾随空格，因此分词后的拼接必须是「第一个词前不补、其余词前补一个」。用 `join`（Python）或 `if (k>1)`（C++）都行，但不要写成「每个词后补空格再 `strip`」，那会多做一次 $O(N)$ 复制。
5. **`core` 的构造对任意长度都合法**：$w$ 至少 1 个字母，所以 $w[0]$ 一定存在、$w[1:]$ 可能为空串；长度为 1 的辅音词 `"b"` 会得到 `core = "b"`，这不是 bug。
6. **大小写原样保留**：`"The"` 的 `T` 跟着左移变成 `"heT"`，输出 `"heTmaa"`；绝不能顺手转成小写（`"hetmaa"` 会被判错）。
7. **切词用「跳过所有空白」的语义**：Python 用无参 `split()`，C++ 用 `istringstream >>`，它们都会跳过连续空白、不产生空串。用 `split(' ')` 虽然本题（单空格分隔）也对，但对多空格输入会产生空词，属于把题面约束当成实现依赖。
8. **流式写法更省内存**：可以不存词表，边读词边往 `ans` 追加；词表版本额外占 $O(W)$，本题 $W \le 75$，影响可以忽略，但流式写法与第 3.3 节流程完全同构。
9. **`ans` 预留容量**：输出长度 $\le \sum_k (\lvert w_k \rvert + 2 + k)$，C++ 里 `ans.reserve(sentence.size() + 3 * W)` 量级即可避免多次扩容。

## 5. 正确性证明

**引理 1（切词不重不漏）**：`sentence.split()` 得到的第 $k$ 段恰好是题面所定义的第 $k$ 个单词，且词表长度等于单词个数。

**证明**：题面保证单词之间**恰好一个**空格、且首尾无空格。以空格为分隔符切分，每个分隔符两侧都非空，故不会切出空串，得到的段数等于空格数加一，正好是单词个数；按出现顺序编号即第 $k$ 个词。∎

**引理 2（core 正确）**：对任意词 $w$，第 3.2 节定义的 $\text{core}(w)$ 满足：$w[0] \in V$ 时 $\text{core}(w)=w$，此时 $w + \text{"ma"}$ 正是规则 1 要求的形态；$w[0] \notin V$ 时 $\text{core}(w) = w[1:] + w[0]$，此时 $\text{core}(w) + \text{"ma"}$ 正是规则 2 所要求的「删去首字母、追加到末尾、再加 `ma`」的结果。

**证明**：两种情况都只是把规则中的「删去首字母再放到末尾」写成 $w[1:] + w[0]$ 的拼接（长度 $\lvert w \rvert$，首字符为 $w[1]$、末字符为 $w[0]$），删除与追加两步合成一次循环左移；元音情形不移位，直接保留。∎

**引理 3（尾部长度）**：第 $k$ 轮执行第 2 步后，`tail` 恰由 $k$ 个 `a` 组成。

**证明**：对 $k$ 归纳。$k=1$ 时 `tail` 由空串加一个 `a` 得到，长度 1。设第 $k-1$ 轮结束时 `tail` 有 $k-1$ 个 `a`，则第 $k$ 轮第 2 步追加一个 `a` 后长度变为 $k$，且字符仍全为 `a`。∎

**定理（算法正确）**：算法返回的字符串，就是把 $w_1,\dots,w_W$ 逐词改写为 $\text{core}(w_k)+\text{"ma"}+\text{"a"}^k$ 后按原顺序用单个空格连接的结果，即题面要求的山羊拉丁文句子。

**证明**：由引理 1，循环恰好遍历 $w_1,\dots,w_W$ 各一次；由引理 2、3，第 $k$ 轮追加的 `core + "ma" + tail` 逐字符等于规则 1/2 与规则 3 共同确定的第 $k$ 个词输出；由第 4 步的空格条件，词与词之间恰有一个空格，且首词前、末词后都没有空格。各轮输出按 $k$ 递增顺序追加，故最终 `ans` 就是唯一的山羊拉丁文句子。∎

## 6. 复杂度分析

- **时间**：$O(N + W^2)$。切词扫描 $O(N)$；每轮的 `core` 复制与 `"ma"` 追加合计 $O(\lvert w_k \rvert)$，累计 $O(N)$；`tail` 每轮增长 1、拼接进 `ans` 时复制 $k$ 个字符，累计 $\sum_{k=1}^{W} k = O(W^2)$。由于 $W \le (N+1)/2 \le 75$，$W^2$ 最多约 $2.8 \times 10^3$，与输出规模同阶，属最优。
- **空间**：$O(N + W^2)$ 用于返回的字符串（这是输出本身，不可省），外加 $O(W)$ 的词表或 $O(L)$ 的单词缓冲（$L$ 为最长单词长度）。若采用流式写法，额外空间只有词缓冲。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <sstream>
using namespace std;

class Solution {
public:
    string toGoatLatin(string sentence) {
        const string vowels = "aeiouAEIOU";
        istringstream in(sentence);
        string w, ans, tail;
        int k = 0;

        while (in >> w) {                                  // 自动跳过连续空白
            ++k;
            string core = w;
            if (vowels.find(w[0]) == string::npos) {        // 辅音：首字母搬到末尾
                core = w.substr(1) + w[0];
            }
            tail += 'a';                                    // 第 k 个词的尾部：k 个 a
            if (k > 1) ans += ' ';                          // 词间恰好一个空格
            ans += core;
            ans += "ma";
            ans += tail;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def toGoatLatin(self, sentence: str) -> str:
        vowels = set("aeiouAEIOU")
        out = []
        tail = ""
        for k, w in enumerate(sentence.split(), 1):
            core = w if w[0] in vowels else w[1:] + w[0]
            tail += "a"                    # 第 k 个词的尾部：k 个 a
            out.append(core + "ma" + tail)
        return " ".join(out)
```

## 8. 边界情况与易错点

1. **句子只有一个词、没有空格**。`split()` / `>>` 仍返回 1 个词；代码里不能假设「至少有两个词」，也不要靠「找第一个空格来切」实现。
2. **长度为 1 的辅音词**。`"b"` 的 `core` 是 `w[1:] + w[0]`，即空串加 `"b"`，结果是 `"bmaa"`；`w.substr(1)` 在长度 1 时返回空串，合法。
3. **大写元音**。`"I"`、`"Apple"`、`"Owl"` 的首字母都是元音，必须原样保留；用 `find(vowels)` 或 `w[0].lower() in "aeiou"` 才能覆盖大小写。
4. **$k$ 从 1 开始**。第 1 个词只加 **1** 个 `a`：`"I"` → `"Imaa"`。若把循环变量当 $k-1$ 用，会得到 `"Ima"`；若从 0 开始，会出现词尾没有 `a`。
5. **尾部只加 `a`，不加 `k`**。常见笔误是 `tail += str(k)`，输出变成 `"Ima1"` 之类。
6. **词间空格的数量**。必须是「词与词之间恰好一个」，首尾不能多出空格；用 `join` 或 `if (k>1)` 是最稳的写法，`ans += core + " "` 之后整体 `strip` 也正确但多一次复制。
7. **不要把 `ma` 追加在移位之前**。顺序是 `core`（已左移）→ `"ma"` → $\text{a}^k$；写成 `w + "ma" + w[0]` 会得到 `"goatma g"` 这类错误形态。
8. **`y` 不是元音**。`"y"` 开头的词按辅音处理（`"y"` → `"ymaa"`）；若把元音集合写成「所有小写字母中的 aeiou 加 y」就会错。
9. **Python 的 `split(' ')` 与 `split()` 之别**。本题单空格分隔，两者等价；但 `split(' ')` 对多空格输入会产生空串，进而在 `w[0]` 处抛 `IndexError`，无参 `split()` 没有这个隐患。
