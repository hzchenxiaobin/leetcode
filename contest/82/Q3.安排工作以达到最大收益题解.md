# LeetCode 安排工作以达到最大收益 题解

## 1. 题目概述

- **标题 / 题号**：安排工作以达到最大收益（#826，medium）
- **链接**：https://leetcode.cn/problems/most-profit-assigning-work/
- **来源**：LeetCode 第 82 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、排序、双指针、二分查找

**题意**：有 $n$ 个工作，第 $i$ 个工作有难度 `difficulty[i]` 与收益 `profit[i]`；有 $m$ 个工人，第 $i$ 个工人的能力为 `worker[i]`，他只能做难度不超过自己能力的工作。每个工人**至多**分配**一个**工作，但同一个工作可以被**任意多个**工人重复完成。求所有工人收益之和的最大值；做不了任何工作的工人收益记 $0$。

**约束**：

- $n = \lvert \text{difficulty} \rvert = \lvert \text{profit} \rvert$，$m = \lvert \text{worker} \rvert$
- $1 \le n, m \le 10^4$
- $1 \le \text{difficulty}[i], \text{profit}[i], \text{worker}[i] \le 10^5$

> 💡 本题的陷阱全在一句话上：**难度高不等于收益高**。工人要的不是「难度最接近自己的能力」的那份工作，而是「自己够得着的所有工作里收益最高」的那份。

## 2. 示例

**示例 1**

```text
输入：difficulty = [2,4,6,8,10], profit = [10,20,30,40,50], worker = [4,5,6,7]
输出：100
解释：分配难度为 [4,4,6,6]，收益分别为 [20,20,30,30]，合计 20 + 20 + 30 + 30 = 100。
```

**示例 2**

```text
输入：difficulty = [85,47,57], profit = [24,66,99], worker = [40,25,25]
输出：0
解释：最低难度为 47，三个工人的能力都更小，谁也做不了工作，收益为 0。
```

**补充示例**（用于演示「同难度取高收益」与「无法工作者取 0」）

```text
输入：difficulty = [4,4,7], profit = [8,20,5], worker = [3,4,5,7]
输出：60
解释：能力 3 做不了任何工作得 0；能力 4、5 都取难度 4 中收益更高的那份（20）；能力 7 仍取 20（难度 7 的收益只有 5）。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：对每个工人遍历全部 $n$ 个工作，在 `difficulty[i] <= worker` 中取 `profit[i]` 的最大值累加。时间 $O(nm)$，$n = m = 10^4$ 时是 $10^8$ 次比较，必然超时。

穷举所有分配方案更不可行：单个工人有 $n+1$ 种合法选择（含「不做」），总方案数 $(n+1)^m$，天文数字。

瓶颈在于「每个工人各自重扫一遍工作」。注意一个单调性：**工人能力越大，他能做的工作集合只会更大**（包含关系，不是相交关系）。因此把工人按能力升序排列后，扫描工作的指针可以一路向右、永不回头。

### 3.2 核心观察：把工作压成「能力 → 最高收益」的台阶表

![把难度到收益的关系折叠成前缀最大收益台阶](images/wc82_q3_prefix_max_model.svg)

单个工人的问题可以独立求解：设

$$f(w) = \max\{\, \text{profit}[k] : \text{difficulty}[k] \le w \,\}$$

若集合为空则 $f(w) = 0$。这个工人最多只能做一份工作，所以他的最大收益**恰好**是 $f(w)$：选收益最高的那份即可，选不到更高的。

把工作按难度升序排成 $(d_1, p_1), \dots, (d_n, p_n)$，$d_1 \le \dots \le d_n$，再做一趟前缀最大：

$$B_i = \max_{1 \le k \le i} p_k, \qquad B_0 = 0$$

那么 $f(w) = B_{j}$，其中 $j$ 是满足 $d_j \le w$ 的最大下标（没有则 $j = 0$）。$w$ 落在 $[d_j, d_{j+1})$ 内时答案都是 $B_j$，所以 $f$ 是一条**只升不降的台阶**——这正是「能力提升但没解锁新工作，收益不变」的来源。

> ⚠️ 前缀最大这一趟**不能省**。若收益随难度下降（例如难度 4 收益 30、难度 6 收益 20），那么能力 6 的工人应当拿 30 而不是 20。省掉这一趟，就只能对每个工人重新求最大值。

### 3.3 算法流程

![双指针流程：排序、前缀最大、单趟累加](images/wc82_q3_two_pointer_flow.svg)

1. 把 `difficulty` 与 `profit` 配对成 $n$ 个二元组，按难度升序排序（**成对排**，绝不能两个数组分开排）；
2. 从 $i = 1$ 到 $n-1$ 做前缀最大：$\text{profit}[i] \leftarrow \max(\text{profit}[i], \text{profit}[i-1])$；
3. 把 `worker` 升序排序；
4. 指针 $j = 0$、$best = 0$、$ans = 0$；按能力从小到大处理每个工人 $w$：
   - `while j < n && difficulty[j] <= w`：$best \leftarrow \max(best, \text{profit}[j])$，$j \leftarrow j+1$；
   - $ans \leftarrow ans + best$；
5. 返回 $ans$。

第 4 步的 `while` 不能写成 `if`：一个能力较强的工人可能一次解锁好几份工作，必须把 $d_j \le w$ 的全部推完，$best$ 才是真正的 $f(w)$。

**替代实现（二分）**：不排序工人，直接在难度数组上 `upper_bound(w)` 找到第一个难度 $> w$ 的位置再减 1 得到 $j$；若结果越界说明没有任何工作可做，$j = 0$。答案累加 $B_j$，总时间 $O(n \log n + m \log n)$，$m \gg n$ 时更省。

### 3.4 示例演算

![示例 1 的逐步走查表](images/wc82_q3_walkthrough.svg)

以示例 1 为例，排序后的工作为 $(2,10),(4,20),(6,30),(8,40),(10,50)$，收益本身递增，前缀最大后不变。工人排序后为 $4,5,6,7$：

| 工人能力 $w$ | 本轮解锁 | 指针 $j$ | 当前 $best$ | 贡献 |
|---|---|---|---|---|
| 4 | 难度 2、4 | 2 | 20 | +20 |
| 5 | 无（下一份难度 6） | 2 | 20 | +20 |
| 6 | 难度 6 | 3 | 30 | +30 |
| 7 | 无（下一份难度 8） | 3 | 30 | +30 |

合计 $20 + 20 + 30 + 30 = 100$，与官方输出一致。

两处值得单独核对：

- **能力 5、7 没有解锁任何新工作**，$best$ 保持上一轮的值，仍各自贡献 20、30。这意味着它们在做「当前最划算的那份」工作——而工作可以重复做，不存在抢占。
- 若换成「按难度就近匹配」的错误贪心，能力 5 会找不到难度 5 的工作而记 0，能力 7 同理，答案只有 60。示例 1 的收益恰好随难度递增，所以两种贪心结果相同，**这是本题最容易自我欺骗的地方**：用示例 1 验证不出正确性。

再看补充示例：工作排序为 $(4,8),(4,20),(7,5)$，前缀最大后变成 $(4,20),(4,20),(7,20)$。能力 3 时 $j=0$、$best=0$，贡献 0；能力 4 与 5 都取 20；能力 7 解锁了难度 7 的工作，但它的原始收益只有 5，在压台阶表时已被前缀最大改写为 20，$best$ 不变，仍贡献 20。合计 $0 + 20 + 20 + 20 = 60$。

## 4. 算法细节

1. **成对排序**：把 `(difficulty[i], profit[i])` 绑在一起排序。若分别对两个数组 `sort`，难度与收益的对应关系就被打乱，答案会随机错。
2. **前缀最大从下标 1 开始**：`for (int i = 1; i < n; ++i) p[i] = max(p[i], p[i-1]);`；从 0 开始会访问 `p[-1]`，属于越界访问（未定义行为，可能直接崩溃）。
3. **`while` 而非 `if`**：工人能力可能一次跨过好几个难度档位，循环必须一直推进到 `difficulty[j] > w` 为止。
4. **`best` 初值为 0**：既覆盖「一个工作也做不了」，也保证第一次解锁时 `max(0, p[j])` 不会把正收益吃掉。收益下界为 1，取 0 不会出错，但初值必须代表「还没有任何收益」。
5. **两个指针各自只走一趟**：外层 $m$ 个工人，内层 $j$ 总共前进 $n$ 次，所以回答阶段是 $O(n+m)$ 而不是 $O(nm)$。
6. **答案用 64 位整数**：本题上界 $10^4 \times 10^5 = 10^9 < 2^{31}-1$，理论上 `int` 装得下；但同一份代码若被改到 $m \le 10^6$ 就会溢出，C++ 中直接用 `long long` 累加更稳妥，返回时再转 `int`。
7. **不必给工人去重**：重复能力直接各自累加即可，处理一个工人是 $O(1)$（摊销），去重反而多一次哈希开销。
8. **`std::sort` 对二元组默认按第一关键字升序**，第一关键字相同时按收益升序；这与「同难度取高收益」并不冲突——前缀最大会把低收益覆盖掉，无需自定义比较器。

## 5. 正确性证明

记排序后的工作为 $(d_1,p_1),\dots,(d_n,p_n)$，$d_1 \le \dots \le d_n$；$B_i = \max_{1 \le k \le i} p_k$ 且 $B_0 = 0$；$f(w) = \max\{p_k : d_k \le w\}$（空集取 0）。

**引理 1（单工人最优值）**：对任意能力 $w$，一个工人能获得的最大收益恰为 $f(w)$。

**证明**：工人至多做一个工作，可行集合 $S(w) = \{k : d_k \le w\}$。若 $S(w)$ 非空，收益为某个 $p_k$（$k \in S(w)$），其上界是 $\max_{k \in S(w)} p_k = f(w)$，且取到该最大值的那份工作合法，故可达；若 $S(w)$ 为空，收益只能是 0 = $f(w)$。∎

**引理 2（双指针不变式）**：设工人能力升序为 $w_1 \le \dots \le w_m$。在第 $t$ 轮循环结束时，指针 $j$ 满足
$$j = \bigl\lvert \{k : d_k \le w_t\}\bigr\rvert, \qquad best = f(w_t).$$

**证明**：对 $t$ 归纳。$t=1$ 时 $j$ 从 0 出发，`while` 恰好把所有 $d_k \le w_1$ 的工作推入，结束后 $j$ 等于该集合大小，$best = \max\{p_k : d_k \le w_1\} = f(w_1)$。

归纳步：设第 $t-1$ 轮结束后不变式成立。因为 $w_{t-1} \le w_t$，集合 $\{k : d_k \le w_{t-1}\} \subseteq \{k : d_k \le w_t\}$ 是包含关系，故新的目标下标不小于旧的 $j$，指针无需回退；`while` 从旧 $j$ 继续推进到新集合的大小，恰好把新解锁的工作的收益并入 $best$。于是 $best = \max\bigl(f(w_{t-1}), \max\{p_k : d_k \le w_t,\ k > j_{\text{旧}}\}\bigr) = f(w_t)$。∎

**引理 3（可分性）**：各工人的选择互不冲突，且总收益上界为 $\sum_{t=1}^{m} f(w_t)$。

**证明**：同一个工作可被任意多个工人重复完成，因此任何工人取用某工作都不会减少他人的可行集合，分配问题按工人分解。对每个工人用引理 1 得上界 $f(w_t)$，求和得上界；让第 $t$ 个工人取使其达到 $f(w_t)$ 的那份工作即同时达到每个上界，故上界可达。∎

**定理**：算法返回的值等于最大总收益。

**证明**：由引理 2，第 $t$ 轮累加的 `best` 恰为 $f(w_t)$；算法返回 $\sum_{t} f(w_t)$。由引理 3，该值既是上界又可达到，故即为最大总收益。∎

> 💡 证明里没有出现「收益随难度单调」的假设——前缀最大把任意收益序列折叠成单调序列后，引理 2 的归纳才成立。这解释了为什么错误贪心在示例 1 上也能通过：那里收益恰好单调。

## 6. 复杂度分析

- **时间**：工作排序 $O(n \log n)$；前缀最大一趟 $O(n)$；工人排序 $O(m \log m)$；双指针回答阶段，外层 $m$ 个工人、内层 $j$ 至多前进 $n$ 次，共 $O(n+m)$。总计 $O(n \log n + m \log m)$，瓶颈是两次排序。
- **空间**：存放配对后的工作数组需要 $O(n)$；对 `worker` 原地排序只需 $O(\log m)$ 的递归栈。除输入输出外不额外开表，二分实现同样只需 $O(n)$。
- **对比暴力**：$O(nm)$ 在 $n=m=10^4$ 时约 $10^8$ 次操作，而 $O(n \log n + m \log m)$ 约 $3 \times 10^5$ 量级，差三个数量级。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxProfitAssignment(vector<int>& difficulty, vector<int>& profit, vector<int>& worker) {
        int n = (int)difficulty.size();
        vector<pair<int, int>> jobs(n);
        for (int i = 0; i < n; ++i) jobs[i] = {difficulty[i], profit[i]};
        sort(jobs.begin(), jobs.end());                 // 按难度升序

        for (int i = 1; i < n; ++i)                     // 前缀最大收益
            jobs[i].second = max(jobs[i].second, jobs[i - 1].second);

        sort(worker.begin(), worker.end());             // 能力升序

        long long ans = 0;
        int j = 0, best = 0;
        for (int w : worker) {
            while (j < n && jobs[j].first <= w) {       // 解锁所有做得了的工作
                best = max(best, jobs[j].second);
                ++j;
            }
            ans += best;                                // 每人取当前最优，工作可重复
        }
        return (int)ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxProfitAssignment(self, difficulty: List[int], profit: List[int], worker: List[int]) -> int:
        jobs = sorted(zip(difficulty, profit))      # 成对排序，按难度升序

        best = 0
        for i in range(len(jobs)):                  # 压成前缀最大收益
            best = max(best, jobs[i][1])
            jobs[i] = (jobs[i][0], best)

        worker.sort()                               # 能力升序
        ans = 0
        j = 0
        best = 0
        for w in worker:
            while j < len(jobs) and jobs[j][0] <= w:
                best = max(best, jobs[j][1])
                j += 1
            ans += best
        return ans
```

## 8. 边界情况与易错点

1. **全部工人都够不着最低难度**：如示例 2，`while` 一次也不执行、`best` 始终为 0，答案自然返回 0；不要在这种情况下特判成 `-1`，也不要「跳过该工人不累加」——跳过的效果与加 0 相同，但会漏掉后续能力更强的工人。
2. **只有一个工作**：所有人要么拿 `profit[0]`，要么拿 0；前缀最大循环 `i` 从 1 开始，`n = 1` 时根本不执行，务必确认不会越界。
3. **同难度、不同收益**：必须取较高的那个。排序后它们相邻，前缀最大逐个覆盖，天然正确；若自己写「用哈希把难度映射到收益」则会互相覆盖出错。
4. **收益非单调**：这是本题的核心陷阱。`difficulty = [2,4,6], profit = [30,10,20], worker = [4]` 的答案是 30，而不是「难度 4 对应收益 10」。任何「按难度就近匹配」的写法都会错。
5. **`while` 写成 `if`**：若一个工人一次解锁多份工作（如能力 10、难度 2/4/6），`if` 只会记录其中一份，后续 `best` 偏小，答案系统性偏低。
6. **整数溢出**：本题上界 $10^9$ 尚在 `int` 范围内，但累加过程用 `long long` 更安全；Python 无此问题。
7. **C++ 传引用排序**：`sort(worker.begin(), worker.end())` 会修改调用方的数组。LeetCode 判题无影响，若在其他场合复用该函数，应先拷贝一份。
