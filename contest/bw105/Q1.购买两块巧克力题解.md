# LeetCode 购买两块巧克力 题解

## 1. 题目概述

- **标题 / 题号**：购买两块巧克力（#2706，easy）
- **链接**：https://leetcode.cn/problems/buy-two-chocolates/
- **来源**：LeetCode 第 105 场双周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、排序

**题意**：商店里有若干块巧克力，价格为数组 `prices`，你身上有 `money` 块钱。必须**恰好购买两块**巧克力，且花掉的钱不能超过 `money`（剩余非负）。在满足条件的前提下，你希望花得尽量少，这样剩下的钱最多。返回**最多能剩下多少钱**；若无论怎么挑两块都会超支，则一块也不买，返回 `money` 本身。

**约束**：

- $2 \le prices.length \le 50$
- $1 \le prices[i] \le 100$
- $1 \le money \le 100$

## 2. 示例

**示例 1**

```text
输入：prices = [1,2,2], money = 3
输出：0
解释：买价格 1 和 2 的两块，花费 3，剩余 3 − 3 = 0。
```

**示例 2**

```text
输入：prices = [3,2,3], money = 3
输出：3
解释：最便宜的两块是 2 和 3，共 5 > 3，任何两块都买不起，返回 3。
```

**示例 3（边界补充）**

```text
输入：prices = [9,9], money = 18
输出：0
解释：只有一种选择，恰好花光，剩余 0——"非负"包含恰好等于 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $\binom{n}{2}$ 个数对 $(i, j)$，对每个和不超过 `money` 的数对计算剩余 `money − prices[i] − prices[j]`，取最大值；若没有可负担的数对则返回 `money`。$n \le 50$ 时数对至多 $1225$ 个，完全可行，但显然没必要——**决定答案的只有"两个最小值"**。

### 3.2 核心观察：最省花费 = 两个最便宜的价格之和

![核心观察：只关心全局最小 m1 与次小 m2](images/bw105_q1_two_smallest.svg)

"恰好买两块"且"剩余非负"意味着：**可行的购买方案的花费下界，就是数组中最小值与次小值之和**。记两者为 $m_1 \le m_2$：

- 若 $m_1 + m_2 \le money$：花掉 $m_1 + m_2$ 就是全局最省的方案，答案为 $money - m_1 - m_2$。任何其他两块组合只会更贵，剩余更少。
- 若 $m_1 + m_2 > money$：连最便宜的两块都买不起，其余组合更不可能，一块也不买，答案就是 $money$。

于是问题从"选哪两块"坍缩成"求前两小"，一次遍历即可，连排序都不需要。

### 3.3 算法流程

![算法流程：一次遍历维护 (m1, m2)，再比较与 money 的大小](images/bw105_q1_decision_flow.svg)

```text
1. m1 = m2 = +∞（用 101 充当，因 prices[i] ≤ 100）
2. 遍历每个价格 p：
       若 p < m1：m2 ← m1，m1 ← p      # 出现新的最小，原最小滑为次小
       否则若 p < m2：m2 ← p           # 只能竞争次小
3. 若 m1 + m2 ≤ money：返回 money − m1 − m2
   否则：返回 money
```

### 3.4 示例演算

![示例演算：买得起的示例 1 与买不起的示例 2](images/bw105_q1_walkthrough.svg)

以两个官方示例走一遍：

| 示例 | prices | $m_1$ | $m_2$ | $m_1+m_2$ | 与 money 比较 | 返回 |
|------|--------|-------|-------|-----------|---------------|------|
| 1 | [1,2,2] | 1 | 2 | 3 | $3 \le 3$ ✓ | $3-3=0$ |
| 2 | [3,2,3] | 2 | 3 | 5 | $5 > 3$ ✗ | $3$（原封不动） |

示例 1 中另一个价格 2 与被选中的 $m_2$ 并列，选哪一块花费都相同，答案不受影响——并列最小值无需任何特殊处理。

## 4. 算法细节

1. **一次遍历维护两个最小值**：遇 `p < m1` 时必须先把 `m1` 挪给 `m2` 再更新 `m1`，顺序写反会把次小覆盖掉；`p == m1` 的并列情形落入 `else if` 分支竞争次小，天然正确。
2. **初值取 101**：约束 $prices[i] \le 100$，用 101 当 $+\infty$ 保证任何真实价格都能把它顶下去，且不会误当作价格参与加法（$n \ge 2$ 时两轮更新后 `m1`、`m2` 必为真实价格）。
3. **比较用 ≤ 而非 <**：恰好花光（$m_1+m_2 = money$）是合法的，剩余 0 也是"非负"。
4. **无需排序**：排序是 $O(n \log n)$，一次遍历是 $O(n)$；$n \le 50$ 两者都行，但遍历版少一行、零额外空间，是签到题的"最短路径"写法。
5. **返回语义**：题目要求的是"剩余的钱"，不是"花费"；买不起时剩余即 `money` 本身，别错写成 0 或 −1。

## 5. 正确性证明

**引理 1（花费下界）**：对任意两个下标 $i \ne j$，有 $prices[i] + prices[j] \ge m_1 + m_2$，其中 $m_1, m_2$ 为数组中最小与次小的值。

**证明**：设 $m_1$ 出现在下标 $a$。若 $\{i, j\}$ 包含 $a$，不妨设 $i = a$，则 $prices[j]$ 是除 $m_1$ 外某个元素，按定义 $prices[j] \ge m_2$（$m_2$ 是"去掉一个最小值后"的最小值），故和 $\ge m_1 + m_2$；若 $\{i, j\}$ 不含 $a$，则两个元素都 $\ge m_2 \ge m_1$，和 $\ge 2m_2 \ge m_1 + m_2$。∎

**定理**：算法返回值等于"买恰好两块后（剩余非负）的最大剩余钱数"。

**证明**：分两种情形。若 $m_1 + m_2 \le money$：任何可行方案的花费 $c$ 都 $\ge m_1 + m_2$（引理 1），故剩余 $money - c \le money - (m_1+m_2)$；而取 $m_1, m_2$ 所在的两块恰好花费 $m_1+m_2 \le money$，剩余非负且达到该上界，算法返回 $money - m_1 - m_2$ 正确。若 $m_1 + m_2 > money$：由引理 1 任何两块的花费都 $> money$，不存在可行购买，题面规定此时返回 $money$，算法亦然。∎

## 6. 复杂度分析

- **时间**：$O(n)$，单趟扫描，每个价格常数次比较。
- **空间**：$O(1)$，只维护两个标量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int buyChoco(vector<int>& prices, int money) {
        int m1 = 101, m2 = 101;                 // prices[i] <= 100，101 充当 +inf
        for (int p : prices) {
            if (p < m1) { m2 = m1; m1 = p; }    // 出现更小值：原最小滑到次小
            else if (p < m2) m2 = p;
        }
        return m1 + m2 <= money ? money - m1 - m2 : money;
    }
};
```

### Python

```python
class Solution:
    def buyChoco(self, prices: List[int], money: int) -> int:
        m1 = m2 = 101                     # prices[i] <= 100，101 充当 +inf
        for p in prices:
            if p < m1:
                m1, m2 = p, m1
            elif p < m2:
                m2 = p
        return money - m1 - m2 if m1 + m2 <= money else money
```

> 💡 两份代码均通过官方示例（`0`、`3`）与"恰好花光""并列最小"边界，并与"枚举全部数对取最优剩余"的暴力对拍 3305 组随机数据（含 $n=2$ 最小规模、大量重复价格、$money$ 贴边界），`mismatch = 0`。

## 8. 边界情况与易错点

1. **恰好买得起**：$m_1 + m_2 = money$ 时返回 0，判定必须用 `<=`，写成 `<` 会错误地放弃合法购买。
2. **$n = 2$**：只有一种组合，两个"最小值"就是这两个元素本身，一次遍历逻辑自动覆盖。
3. **并列最小值**：如 `[2,2,9]`，第二个 2 走 `else if` 分支成为 $m_2$，花费 $4$；不会出现把同一个元素取两次的错误——$m_1$ 与 $m_2$ 由**不同轮次**的更新产生，天然对应两个不同下标。
4. **初值不要用 0 或 −1**：价格全为正，用 0 当 $+\infty$ 会导致全 1 数组出错（$m_2$ 永远是 0）；用 101 这种"大于值域上界的哨兵"最稳。
5. **买不起时返回 money**：不是 0，更不是负数；题面原话"返回 money"。
6. **更新顺序**：`m2 = m1; m1 = p;` 两句顺序不能反，否则新最小直接覆盖而丢失次小。
