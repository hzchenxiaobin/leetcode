# LeetCode 字符串中的额外字符 题解

## 1. 题目概述

- **标题 / 题号**：字符串中的额外字符（#2707，medium）
- **链接**：https://leetcode.cn/problems/extra-characters-in-a-string/
- **来源**：LeetCode 第 105 场双周赛 Q2
- **难度**：中等
- **标签**：字典树、数组、哈希表、字符串、动态规划

**题意**：给定字符串 `s` 与单词字典 `dictionary`。把 `s` 分割成若干**互不重叠**的子字符串，每个子字符串都必须是字典中出现过的单词；没被任何子字符串覆盖的字符称为**额外字符**。求在最优分割下，额外字符的**最少**个数。

**约束**：

- $1 \le s.length \le 50$
- $1 \le dictionary.length \le 50$
- $1 \le dictionary[i].length \le 50$
- `dictionary[i]` 与 `s` 只含小写英文字母，字典内单词互不相同

## 2. 示例

**示例 1**

```text
输入：s = "leetscode", dictionary = ["leet","code","leetcode"]
输出：1
解释：切成 "leet"（下标 0..3）与 "code"（下标 5..8），只有下标 4 的 's' 是额外字符。
```

**示例 2**

```text
输入：s = "sayhelloworld", dictionary = ["hello","world"]
输出：3
解释：切成 "hello"（下标 3..7）与 "world"（下标 8..12），前三个字符 "say" 全部额外。
```

**示例 3（边界补充）**

```text
输入：s = "abcd", dictionary = ["ab","bc"]
输出：2
解释：两个词在 s 中重叠（"ab" 用掉 0..1，"bc" 用掉 1..2），只能二选一：
      选 "ab" 剩 "cd" 两个额外字符；选 "bc" 剩 "ad" 同样两个。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个位置"保留/作废"的 $2^n$ 种组合，再检查保留位置能否切成字典词——指数级，$n = 50$ 直接爆炸。退一步的正确暴力是记忆化搜索：在位置 $i$ 处，要么把 $s[i]$ 记作额外字符走到 $i+1$，要么枚举一个能在 $i$ 处匹配的词整体跳过——这其实已经就是 DP 的递归形态。本题真正的考点是把"分割 + 容忍废字符"翻译成**线性 DP**。

### 3.2 核心观察：额外字符可以"逐个计费"，最后一段要么是单词要么是废字符

![状态设计：dp[i] = 前 i 个字符的最少额外字符数](images/bw105_q2_dp_model.svg)

关键是设计状态 **$dp[i]$ = 只考虑前 $i$ 个字符（前缀 $s[0..i)$）时，最少额外字符数**。考察前缀的"最后一截"只有两种形态：

1. **$s[i-1]$ 是额外字符**：它单独计费一次，前 $i-1$ 个字符的问题不变，即 $dp[i] = dp[i-1] + 1$；
2. **$s[j..i)$ 恰是字典单词**：这 $i - j$ 个字符零额外，剩下前 $j$ 个字符独立求解，即 $dp[i] = dp[j]$。

两类转移取最小即可。"分割方案 = 若干互不重叠单词 + 散落的废字符"这一结构，保证了**任意最优解的最后一个字符**必然落入上述两种情形之一，转移不重不漏。$dp[0] = 0$（空前缀无字符），答案为 $dp[n]$。

### 3.3 算法流程

![算法流程：从左到右填 dp 表，每个 i 先取下界再枚举单词起点](images/bw105_q2_dp_flow.svg)

```text
1. 把 dictionary 放入哈希集合 words
2. dp[0] = 0
3. for i = 1 .. n:
       dp[i] = dp[i-1] + 1                  # 情形一：s[i-1] 记额外
       for j = 0 .. i-1:
           若 s[j..i) ∈ words：             # 情形二：整段是单词
               dp[i] = min(dp[i], dp[j])
4. 返回 dp[n]
```

### 3.4 示例演算

![示例演算：leetscode 的 dp 表逐步填出 1](images/bw105_q2_walkthrough.svg)

以示例 1（`s = "leetscode"`，词典 `{leet, code, leetcode}`）填表：

| $i$ | 前缀 | $dp[i]$ | 依据 |
|-----|------|---------|------|
| 0 | "" | 0 | 边界 |
| 1 | "l" | 1 | 无词，+1 |
| 2 | "le" | 2 | +1 |
| 3 | "lee" | 3 | +1 |
| 4 | "leet" | **0** | "leet" 是单词 → $dp[0]$ |
| 5 | "leets" | 1 | $dp[4]+1$（'s' 额外） |
| 6 | "leetsc" | 2 | +1 |
| 7 | "leetsco" | 3 | +1 |
| 8 | "leetscod" | 4 | +1 |
| 9 | "leetscode" | **1** | "code"（$j=5$）→ $dp[5]=1$ |

注意 $i=9$ 时还有候选 "leetcode"，但 $s[0..9)=$ "leetscode" ≠ "leetcode"，不命中；最终 $dp[9] = 1$ ✓。

## 4. 算法细节

1. **哈希集合判词**：`unordered_set<string>` / Python `set` 存词典，单次查询 $O(L)$（$L$ 为串长）。总转移 $O(n^2)$ 次查询、每次子串构造 $O(n)$，总计 $O(n^3) \le 1.25 \times 10^5$ 字符操作，$n = 50$ 下绰绰有余。
2. **先赋下界再放松**：`dp[i] = dp[i-1] + 1` 必须写在枚举 $j$ **之前**，它既是合法转移也是初始上界，避免用哨兵无穷大初始化。
3. **两处等价优化（非必需）**：其一，$j$ 只需枚举到 $i - \text{maxLen}$（`maxLen` 为最长单词长度），更短的 $j$ 不可能拼出词；其二，用**字典树**存词典、固定右端 $i$ 向左逐字符走，走到断枝即停，省去每次子串的构造与哈希开销，复杂度降为 $O(n \cdot \text{maxLen})$。$n \le 50$ 时两者都属"锦上添花"。
4. **重叠词无需特殊处理**：示例 3 中 "ab"、"bc" 共享下标 1——DP 按"前缀最后一截"分类，任何方案里下标 1 只会被一个词用掉，重叠的词会在不同转移路径里自然竞争，不会重复计数。
5. **dp 含义锚定"前缀"而非"子串"**：子串型状态（$dp[l][r]$）会把问题做成 $O(n^2)$ 状态 + 区间合并，纯属绕路；额外字符是"前缀消费"结构，线性状态就够。

## 5. 正确性证明

**引理 1（可行解的结构）**：任意一种分割方案可写为不重叠区间集合 $\{[l_t, r_t)\}$（每个 $s[l_t..r_t)$ 是词典单词）与额外字符集 $E$ 的并，且互不相交、覆盖 $[0, n)$。反之，任意这样的结构都对应一个合法方案，其额外字符数为 $|E|$。

**证明**：题面定义的"分割成互不重叠子字符串 + 额外字符"即逐字符指派：每个下标要么属于某个单词区间、要么额外。区间由单词端点确定且互不重叠，故结构成立；反向，给定该结构按区间切分即得合法分割。∎

**引理 2（转移完全性）**：设 $OPT(i)$ 为前缀 $s[0..i)$ 的最少额外字符数，则 $OPT(0) = 0$，且对 $i \ge 1$：

$$OPT(i) = \min\Big(\, OPT(i-1) + 1,\ \min_{j:\ s[j..i) \in D} OPT(j) \Big)$$

**证明**：取前 $i$ 个字符的一个最优结构。若下标 $i-1 \notin E$，它属于某单词区间 $[l, i)$，该区间是词典单词且其余区间与额外字符都落在 $[0, l)$ 内，故 $OPT(i) \le OPT(l)$，且去掉该区间后前 $l$ 个字符的结构给出 $OPT(l)$ 个额外字符（若更少则替换得更好方案，矛盾）；若 $i-1 \in E$，同理 $OPT(i) \le OPT(i-1) + 1$ 且 $OPT(i-1) \ge OPT(i) - 1$。于是 $OPT(i)$ 不小于右端两选项之最小值；又两个选项各自都对应可构造的方案（$OPT(i-1)$ 的结构追加一个额外字符 $i-1$；$OPT(j)$ 的结构追加单词区间 $[j, i)$），故取等。对 $i$ 归纳即得递推。∎

**定理**：算法返回 $dp[n] = OPT(n)$，即最少额外字符数。

**证明**：$dp$ 按 $i$ 从小到大计算，归纳基础 $dp[0] = OPT(0) = 0$；归纳步骤中 $dp[i-1]$ 与各 $dp[j]$（$j < i$）均已等于对应 $OPT$，由引理 2 的递推，$dp[i] = OPT(i)$。终止时 $dp[n] = OPT(n)$。∎

## 6. 复杂度分析

- **时间**：$O(n^2 \cdot L)$，$L \le 50$ 为子串平均长度上限——枚举 $O(n^2)$ 个 $(j, i)$ 对，每对构造/哈希子串 $O(L)$；$n = 50$ 时约 $1.25 \times 10^5$ 字符操作。改用字典树后为 $O\big(n \cdot \text{maxLen} + \sum |w|\big)$。
- **空间**：$O(n + \sum |w|)$：dp 数组 $O(n)$，哈希集合存词典共 $O(\sum |w|)$ 字符（字典树同阶）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minExtraChar(string s, vector<string>& dictionary) {
        int n = s.size();
        unordered_set<string> dict(dictionary.begin(), dictionary.end());
        vector<int> dp(n + 1, 0);                  // dp[i]：前 i 个字符的最少额外字符数
        for (int i = 1; i <= n; ++i) {
            dp[i] = dp[i - 1] + 1;                 // 情形一：s[i-1] 记作额外字符
            for (int j = 0; j < i; ++j)
                if (dict.count(s.substr(j, i - j)))// 情形二：s[j..i) 恰是词典单词
                    dp[i] = min(dp[i], dp[j]);
        }
        return dp[n];
    }
};
```

### Python

```python
class Solution:
    def minExtraChar(self, s: str, dictionary: List[str]) -> int:
        n = len(s)
        words = set(dictionary)
        dp = [0] * (n + 1)                   # dp[i]：前 i 个字符的最少额外字符数
        for i in range(1, n + 1):
            dp[i] = dp[i - 1] + 1            # 情形一：s[i-1] 记作额外字符
            for j in range(i):
                if s[j:i] in words:          # 情形二：s[j..i) 恰是词典单词
                    dp[i] = min(dp[i], dp[j])
        return dp[n]
```

> 💡 两份代码均通过官方示例（`1`、`3`）与"重叠词""全额外"边界，并与"枚举保留位置子集 + 独立 word-break 校验"的暴力对拍 2506 组随机数据（$n \le 12$，词典随机、含重叠/嵌套词），`mismatch = 0`。

## 8. 边界情况与易错点

1. **整个 `s` 没有任何词能匹配**：一路 `+1`，答案为 $n$；`dp[i] = dp[i-1] + 1` 的兜底转移保证了这条路永远存在，无需特判。
2. **重叠词**（示例 3 的 "ab"/"bc"）：贪心匹配（如"能配就配"）会错——必须靠 DP 让两种选择在 $dp$ 值上竞争。千万不要写成区间覆盖贪心。
3. **子串方向**：转移枚举的是**右端固定为 $i$** 的词 $s[j..i)$；若误写成 $s[i..j)$（左端固定），状态就不闭合，需要另一套从右往左的 $dp$ 才能自洽。
4. **`dp[0] = 0` 别忘**：它是所有"整段恰是一个词"转移（$j = 0$）的来源。
5. **词典去重无关紧要**：题面保证单词互不相同；即便有重复，放入哈希集合也自动去重。
6. **单词可长于 `s`**：`dictionary[i].length ≤ 50` 与 `s.length` 无约束关系，超长词在枚举中永远不会被 $s[j..i)$ 命中，无需过滤（过滤 `maxLen` 只是把它们挡在 $j$ 的枚举范围外，属于优化而非正确性）。
