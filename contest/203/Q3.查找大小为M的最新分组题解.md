# LeetCode 查找大小为 M 的最新分组 题解

## 1. 题目概述

- **标题 / 题号**：查找大小为 M 的最新分组（#1562，medium）
- **链接**：https://leetcode.cn/problems/find-latest-group-of-size-m/
- **来源**：LeetCode 第 203 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：长度为 $n$ 的二进制串初始全 0，`arr` 是 $1 \sim n$ 的一个排列。第 $i$ 步把位置 `arr[i]` 上的位设为 1。**一组 1** 定义为极大的连续 1 段（左右两边不再有可延伸的 1）。求**最后一个**使串中存在长度**恰好**为 $m$ 的组的步骤编号；若这样的步骤不存在，返回 $-1$。

**约束**：

- $n = \mathrm{arr.length}$，$1 \le n \le 10^5$
- `arr` 中的整数互不相同（即 $1 \sim n$ 的排列）
- $1 \le m \le n$

> 💡 本题的题眼是「位置只从 0 变 1」——这意味着 **组只会合并、永不分裂**。抓住这一点，每一步都是一次 $O(1)$ 的局部维护；再配上「端点存长度」和「按长度计数」两个技巧，就能从朴素 $O(n^2)$ 一路优化到 $O(n)$，连平衡树的 $\log$ 都省掉。

## 2. 示例

**示例 1**

```text
输入：arr = [3,5,1,2,4], m = 1
输出：4
解释：
步骤 1："00100"，组：["1"]
步骤 2："00101"，组：["1", "1"]
步骤 3："10101"，组：["1", "1", "1"]
步骤 4："11101"，组：["111", "1"]   ← 最后一个含长度 1 组的步骤
步骤 5："11111"，组：["11111"]
```

**示例 2**

```text
输入：arr = [3,1,5,4,2], m = 2
输出：-1
解释：任何一步都没有出现长度恰为 2 的组。
```

**示例 3**

```text
输入：arr = [2,1], m = 2
输出：2
解释：第 2 步后串为 "11"，恰好构成长度为 2 的一组。
```

## 3. 解题思路

### 3.1 暴力思路：逐步重扫全串

最直接的做法：每步置 1 之后，从头到尾扫描一遍串，统计所有极大连续 1 段的长度，看是否出现 $m$。单步 $O(n)$，总计 $O(n^2)$；$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时。

稍加改进可以想到：组的变化只发生在新置位位置的附近，用一个**有序集合维护所有组的区间**，每步二分找到左右邻区间、合并、更新计数，即可做到 $O(n \log n)$（本文方法二，赛时完全够用）。但本题还能更彻底——$O(n)$。

### 3.2 核心观察：只合不分 + 端点存长度 + 按长度计数

![核心观察：置位只合并相邻组，端点存组长即可](images/wc203_q3_merge_concept.svg)

三个层层递进的观察：

1. **只合不分**。位置只从 0 变 1，永不回头。第 $i$ 步置位 $p$ 时，新的 1 只可能与**左右紧邻**的两组（若存在）粘成一组，其余组纹丝不动。每步是一次局部合并：左组长 $L$、右组长 $R$、新组长 $L + R + 1$，其中 $+1$ 正是新置位的 $p$ 本身。
2. **端点存长度**。想知道 $p$ 左侧的组多长，只需看 $p-1$ 处存的值：$p$ 置位前是 0，左侧组（若存在）的右端点必然恰是 $p-1$。于是只需开一个数组 `len`，把每个组的长度记在它的**两个端点**上，合并后回写新组的两个端点即可。内部位置的旧值从此永不再被读——因为读取只发生在「新置位位置的邻点」处，而邻点若是 1，必是它所在组的当前端点。这一步直接干掉了平衡树。
3. **按长度计数**。题目不关心组在哪，只关心**有没有**长度为 $m$ 的组。维护计数数组 $\mathrm{cnt}[\ell]$ = 当前长度为 $\ell$ 的组的个数，每步做三次加减（$-L$、$-R$、$+(L+R+1)$），则 $\mathrm{cnt}[m] > 0 \iff$ 当前存在长 $m$ 的组。这一步干掉了我对组集合的遍历。

### 3.3 算法流程

![算法流程：读邻点、改计数、回写端点、查 cnt[m]](images/wc203_q3_algorithm_flow.svg)

```text
1. len[0..n+1] 清零（下标 0 与 n+1 是哨兵），cnt[0..n] 清零，ans = -1
2. 对每一步 i = 1..n，p = arr[i]：
   a. L = len[p-1]，R = len[p+1]              （0 表示该侧没有组）
   b. 若 L > 0 则 cnt[L] 减一；若 R > 0 则 cnt[R] 减一；cnt[L+R+1] 加一
   c. 回写新组两端点：len[p-L] = len[p+R] = L+R+1
   d. 若 cnt[m] > 0：ans = i
3. n 步全部结束后返回 ans（可能仍为 -1）
```

### 3.4 示例演算

![示例演算：arr=[3,5,1,2,4], m=1 的五步状态](images/wc203_q3_example_walkthrough.svg)

以示例 1（`arr = [3,5,1,2,4]`，$m = 1$）完整走一遍：

| 步骤 | 置位 $p$ | 串状态 | 组 | $\mathrm{cnt}[1]$ | ans |
|------|---------|--------|-----|---------|-----|
| 1 | 3 | `00100` | `[1]` | 1 | 1 |
| 2 | 5 | `00101` | `[1]`,`[1]` | 2 | 2 |
| 3 | 1 | `10101` | `[1]`,`[1]`,`[1]` | 3 | 3 |
| 4 | 2 | `11101` | `[111]`,`[1]` | 1 | **4** |
| 5 | 4 | `11111` | `[11111]` | 0 | 4 |

- 步骤 4：置位 $p=2$，左邻组 `[1]`（$L=1$）与右邻组 `[1]`（$R=1$）合并成 `[111]`，长度 1 的组还剩位置 5 上那一个，$\mathrm{cnt}[1] > 0$，ans 更新为 4；
- 步骤 5：置位 $p=4$，把 `[111]`（$L=3$）与 `[1]`（$R=1$）并成全串 `[11111]`，$\mathrm{cnt}[1]$ 归零，ans 停在 4。输出 **4**。

再看示例 2（`arr = [3,1,5,4,2]`，$m = 2$）：五步串状态依次为 `00100` → `10100` → `10101` → `10111` → `11111`，组长始终在 $\{1, 3, 5\}$ 里打转，长度 2 的组从未出现，返回 $-1$。

## 4. 算法细节

1. **1-indexed + 哨兵**：`len` 开到 $n+2$，`len[0]` 与 `len[n+1]` 恒为 0，$p=1$ 或 $p=n$ 时无需任何越界分支。
2. **先读后写**：同一步必须先取出 $L=\mathrm{len}[p-1]$、$R=\mathrm{len}[p+1]$，再回写端点。$L=1$ 时 $p-L=p-1$（$R=1$ 时 $p+R=p+1$），回写会覆盖刚读过的位置，顺序颠倒就会读错。
3. **内部旧值不清理**：`len` 只在「当前端点」处有意义。某位置一旦成为组的内部点，它的左右邻都已是 1，不会再有新置位发生在它旁边，其旧值永不再被读——这也是 $L, R \ge 1$ 时 `len[p]` 保持 0 也无妨的原因。
4. **cnt 与 len 各司其职**：`len` 负责「相邻组多长」（步 a），`cnt` 负责「有没有长 $m$ 的组」（步 b、d），两者都必须每步同步更新。
5. **$m = n$ 的捷径**：全串并成一组只可能发生在第 $n$ 步，`if (m == n) return n;` 可短路；不写也正确，循环天然覆盖（示例 3 即此情形）。
6. **必须扫完全程**：$\mathrm{cnt}[m]$ 归零后仍可能再次变正（其它组之后合并恰好拼出新的长 $m$ 组），既不能首次命中就返回（题目要**最后**一步），也不能在归零后提前退出。

## 5. 正确性证明

**引理 1（只合不分 / 局部合并）**：设第 $i$ 步置位 $p$。置位前若 $p-1$ 为 1，记左侧极大组 $A=[p-L,\,p-1]$；若 $p+1$ 为 1，记右侧极大组 $B=[p+1,\,p+R]$；否则对应长度视为 0。则置位后，$A$、$B$ 被替换为唯一的组 $[p-L,\,p+R]$，长度为 $L+R+1$，其余所有组不变。

**证明**：极大连续 1 段由相邻位置的取值决定。对任何 $q \le p-2$，$q$ 与 $q+1$ 的取值都未随置位 $p$ 改变，故不与 $p-1$ 相邻的左侧组边界完全不动；右侧同理。若 $A$ 存在，由其极大性及 $p$ 原为 0，知 $A$ 的右端点恰为 $p-1$，且 $p-L-1$ 为 0 或越界；$B$ 同理，$p+R+1$ 为 0 或越界；若 $A$ 不在（$L=0$），则 $p-1$ 本身为 0。于是置位后 $[p-L,\,p+R]$ 全为 1，两端外侧均为 0 或越界，是极大组；且它吸纳了 $p$ 左右两侧原有的全部相邻 1。∎

**引理 2（端点不变式）**：以 $S_i$ 记第 $i$ 步后的串状态。算法维护的数组 `len` 满足：

（i）$S_i$ 中为 0 的位置 $q$ 上 $\mathrm{len}[q] = 0$；

（ii）$S_i$ 中每个组 $[l, r]$ 满足 $\mathrm{len}[l] = \mathrm{len}[r] = r - l + 1$。

**证明**：对 $i$ 归纳。$i = 0$ 时空串、`len` 全 0，两条成立。设第 $i-1$ 步后成立，考察第 $i$ 步置位 $p$。

先证**读取正确**：若 $p-1$ 在 $S_{i-1}$ 中为 0，由（i）得 $L = \mathrm{len}[p-1] = 0$；若 $p-1$ 为 1，由 $p$ 在 $S_{i-1}$ 中为 0 知它是左侧组的右端点，由（ii）得 $\mathrm{len}[p-1]$ 等于该组长度，即真实的 $L$。$R$ 同理。故算法读到的 $L$、$R$ 与引理 1 中的左右组长一致。

再证**不变式保持**：本步只写 $\mathrm{len}[p-L]$ 与 $\mathrm{len}[p+R]$ 两处（$L=R=0$ 时重合于 $p$）。由引理 1，$S_i$ 中唯一的新组是 $[p-L,\,p+R]$，算法写入的值 $L+R+1$ 恰为其长度，且两写入位置恰为其两端点——（ii）对新组成立；其余组的端点未被触碰，（ii）延续。（i）的保持：$S_i$ 中为 0 的位置在 $S_{i-1}$ 中也为 0 且不是 $p$，本步未写它们，由归纳假设其 `len` 仍为 0。∎

**引理 3（计数正确）**：每步之后，$\mathrm{cnt}[\ell]$ 等于 $S_i$ 中长度为 $\ell$ 的组的个数。

**证明**：对 $i$ 归纳。初始无组、`cnt` 全 0。第 $i$ 步由引理 1，组长多重集的净变化是：移除长 $L$ 与长 $R$ 的组各一个（长度为 0 者不存在、跳过），加入长 $L+R+1$ 的组一个。算法恰执行与之完全同步的三次计数加减。∎

**定理**：算法返回 $\max\{\,i : S_i \text{ 中存在长度恰为 } m \text{ 的组}\,\}$（该集合为空时返回 $-1$），即题目所求的最后步骤。

**证明**：由引理 3，第 $i$ 步后 $\mathrm{cnt}[m] > 0 \iff S_i$ 中存在长 $m$ 的组。算法在第 $i$ 步末检查该条件并令 $\mathrm{ans} = i$，遍历全部 $n$ 步后 `ans` 即为满足条件的最大 $i$；若从未满足则保持初值 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每步只做常数次数组操作——两次读、两次写、至多三次计数加减、一次查询，共 $n$ 步。
- **空间复杂度**：$O(n)$。`len` 开 $n+2$、`cnt` 开 $n+1$。方法二的有序区间集合同为 $O(n)$ 空间，但每步多一次 $O(\log n)$ 的查找与删除。

## 7. 参考代码

### 方法一：端点存长度 + 按长度计数，$O(n)$

#### C++

```cpp
class Solution {
public:
    int findLatestStep(vector<int>& arr, int m) {
        int n = arr.size();
        vector<int> len(n + 2, 0), cnt(n + 1, 0);
        int ans = -1;
        for (int i = 0; i < n; ++i) {
            int p = arr[i];
            int L = len[p - 1], R = len[p + 1];
            int cur = L + R + 1;
            if (L) --cnt[L];
            if (R) --cnt[R];
            ++cnt[cur];
            len[p - L] = cur;
            len[p + R] = cur;
            if (cnt[m] > 0) ans = i + 1;
        }
        return ans;
    }
};
```

#### Python

```python
class Solution:
    def findLatestStep(self, arr: List[int], m: int) -> int:
        n = len(arr)
        length = [0] * (n + 2)
        cnt = [0] * (n + 1)
        ans = -1
        for i, p in enumerate(arr, 1):
            L, R = length[p - 1], length[p + 1]
            cur = L + R + 1
            if L:
                cnt[L] -= 1
            if R:
                cnt[R] -= 1
            cnt[cur] += 1
            length[p - L] = cur
            length[p + R] = cur
            if cnt[m] > 0:
                ans = i
        return ans
```

### 方法二：有序区间集，$O(n \log n)$（赛时稳妥版）

不想推端点不变式时，用平衡树直接维护「组的区间集合」也能过：每步二分找到 $p$ 的左右邻区间，合并后插回。思路直白，代价是每步 $O(\log n)$。

#### C++

```cpp
class Solution {
public:
    int findLatestStep(vector<int>& arr, int m) {
        int n = arr.size();
        set<pair<int, int>> s;
        vector<int> cnt(n + 1, 0);
        int ans = -1;
        for (int i = 0; i < n; ++i) {
            int p = arr[i];
            int lo = p, hi = p;
            auto it = s.upper_bound({p, n + 1});
            if (it != s.begin()) {
                auto l = prev(it);
                if (l->second == p - 1) {
                    lo = l->first;
                    --cnt[l->second - l->first + 1];
                    s.erase(l);
                }
            }
            if (it != s.end() && it->first == p + 1) {
                hi = it->second;
                --cnt[it->second - it->first + 1];
                s.erase(it);
            }
            s.insert({lo, hi});
            ++cnt[hi - lo + 1];
            if (cnt[m] > 0) ans = i + 1;
        }
        return ans;
    }
};
```

#### Python

```python
from sortedcontainers import SortedList

class Solution:
    def findLatestStep(self, arr: List[int], m: int) -> int:
        n = len(arr)
        starts = SortedList()
        end_of = {}
        cnt = [0] * (n + 1)
        ans = -1
        for i, p in enumerate(arr, 1):
            lo, hi = p, p
            j = starts.bisect_left(p)
            if j < len(starts) and starts[j] == p + 1:
                s = starts.pop(j)
                cnt[end_of[s] - s + 1] -= 1
                hi = end_of.pop(s)
            if j > 0 and end_of[starts[j - 1]] == p - 1:
                s = starts.pop(j - 1)
                cnt[p - s] -= 1
                lo = s
            end_of[lo] = hi
            cnt[hi - lo + 1] += 1
            starts.add(lo)
            if cnt[m] > 0:
                ans = i
        return ans
```

## 8. 边界情况与易错点

1. **下标与哨兵**：题目 1-indexed，`len` 必须开 $n+2$，让 `len[0]`、`len[n+1]` 作哨兵；否则 $p=1$ 或 $p=n$ 时 `len[p-1]` / `len[p+1]` 越界。
2. **先读后写**：$L=1$ 时 $p-L=p-1$，回写端点会覆盖刚读过的位置；读、写顺序颠倒会把 $L$ 错读成新组长。
3. **首次命中不能返回**：题目要的是「最后」一步；同理 $\mathrm{cnt}[m]$ 归零后也不能 break——别的组之后仍可能合并出新的长 $m$ 组。
4. **$m = n$**：答案恒为 $n$（只有最后一步全为 1 才有长 $n$ 的组），循环天然正确，短路判断只是加速（示例 3 即此情形）。
5. **$+1$ 别丢**：新组长是 $L+R+1$，那个 1 是刚置位的 $p$ 本身；漏掉后 $m=1$ 的用例全错。
6. **返回 $-1$**：全程未出现长 $m$ 的组（示例 2），`ans` 保持初值直接返回。
7. **方法二的小坑**：弹出右侧区间后有序集合的索引会前移，务必先处理右侧（用定位一次的索引 $j$ 判断 `starts[j] == p+1`）再处理左侧（`starts[j-1]`），或每次重新定位。
