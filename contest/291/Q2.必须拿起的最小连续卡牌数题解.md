# LeetCode 必须拿起的最小连续卡牌数 题解

## 1. 题目概述

- **标题 / 题号**：必须拿起的最小连续卡牌数（#2260，medium）
- **链接**：https://leetcode.cn/problems/minimum-consecutive-cards-to-pick-up/
- **来源**：LeetCode 第 291 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：给定整数数组 `cards`（`cards[i]` 为第 `i` 张卡牌的值），值相同的两张卡牌称为一对**匹配**卡牌。要求拿起一段**连续下标**的卡牌，使其中含有一对匹配卡牌，返回这段卡牌的**最小长度**；若无论怎么拿都不含匹配对（所有值互异），返回 `-1`。

**约束**：

- $1 \le \text{cards.length} \le 10^5$
- $0 \le \text{cards[i]} \le 10^6$

> 💡 本题在本仓库另有[每日题解 2260](../../solution/2201-2300/2260_必须拿起的最小连续卡牌数.md)：以「哈希表存最近下标 + 与 219 的判定/最值对照」为主线，附面试问答。本篇按**周赛复盘视角**展开，补齐**引理-定理化的严格证明**（答案归约到相邻同值对、覆盖更新的安全性）与**赛场易错清单**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：cards = [3,4,2,3,4,7]
输出：4
解释：拿起 [3,4,2,3]（下标 0..3）含一对值为 3 的匹配卡牌；
      拿起 [4,2,3,4]（下标 1..4）同样最优。
```

**示例 2**

```text
输入：cards = [1,0,5,3]
输出：-1
解释：所有值互异，任何连续段都不含匹配对。
```

**示例 3**（体现「覆盖更新」的收益）

```text
输入：cards = [3,4,2,3,3]
输出：2
解释：值 3 出现在下标 0、3、4。相邻对 (3,4) 夹出段 [3,4]，
      长度 2，比用第一次出现 (0,3) 算出的 4 更短。
```

**示例 4**（最小可能答案）

```text
输入：cards = [1,1]
输出：2
解释：两张卡牌值相同且相邻，必须两张都拿起。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有同值下标对

照搬题意：枚举所有下标对 $(i, j)$（$i < j$），若 `cards[i] == cards[j]`，则它们夹出的连续段长度为 $j - i + 1$，对所有同值对取最小：

```text
ans = ∞
for i in 0 .. n-1:
    for j in i+1 .. n-1:
        if cards[i] == cards[j]:
            ans = min(ans, j - i + 1)
return ans == ∞ ? -1 : ans
```

时间 $O(n^2)$。当 $n = 10^5$ 时约 $10^{10}$ 次比较，**超时**。

> ⚠️ 浪费在于：对每个 `cards[i]`，「之后第一个同值」靠线性回头扫。其实每个元素只关心一件事——**同值的上一次出现在哪**。这正是哈希表 $O(1)$ 能回答的问题。

### 3.2 核心观察：最短匹配段必由「相邻同值对」夹成

![核心观察：最小跨度落在相邻同值对，哈希表只存最近下标](images/2260_card_pickup_concept.svg)

两个事实把问题化简到一次线性扫描：

> 💡 **观察 1（段由对夹成）**：一段连续卡牌含匹配对，当且仅当其中存在一对同值下标 $(p, q)$（$p < q$）。段长 $r - l + 1 \ge q - p + 1$，所以**最短的合法段一定恰好由某对同值下标夹住**（端点即该对本身）。答案就是
> $$\text{ans} = \min_{\text{同值对 } (p,q)} (q - p + 1)$$

> 💡 **观察 2（相邻对支配）**：设值 $v$ 依次出现在 $p_1 < p_2 < \dots < p_m$。任何**非相邻**对 $(p_a, p_c)$（中间还夹着 $p_b$）满足
> $$p_c - p_a = (p_c - p_b) + (p_b - p_a) \;\ge\; \max(p_c - p_b,\; p_b - p_a)$$
> 即非相邻对的跨度不小于其中某个相邻对的跨度。所以**全局最小跨度必落在某个「相邻两次出现」上**。

两式合并：只需对每个值 $v$、每个相邻出现对 $(p_k, p_{k+1})$ 计算 $p_{k+1} - p_k + 1$ 取最小。而「扫描到 $p_{k+1}$ 时，$v$ 的上一次出现恰是 $p_k$」——用哈希表 `last` 维护「值 → 最近下标」即可，每步一次查表、一次覆盖写入。

**覆盖为什么安全**：更近的历史下标算出的跨度只会更小。当前位置 $i$，若 $v$ 在 $p_1 < p_2 < i$ 出现过，用 $p_2$ 算得 $i - p_2 + 1$，比用被覆盖的 $p_1$ 算出的 $i - p_1 + 1$ 更小、更优，丢掉 $p_1$ 不损失任何候选（详见 §5 引理 3）。

### 3.3 算法流程

![算法流程：单层循环查表算跨度，覆盖更新，末尾判哨兵](images/2260_card_pickup_flow.svg)

1. 初始化 `ans = ∞`，`last = {}`（空哈希表）；
2. 从左到右扫描 `cards[i]`：
   - **查**：若 `cards[i]` 在 `last` 中，计算 $\text{dist} = i - \text{last}[\text{cards[i]}] + 1$，更新 $\text{ans} = \min(\text{ans}, \text{dist})$；
   - **写**：无论是否命中，覆盖 `last[cards[i]] = i`；
3. 扫描结束：`ans` 仍为 $\infty$ 返回 `-1`，否则返回 `ans`。

**必须先查后写**：先写会把「当前元素自己」写进表里，查出来的跨度恒为 $i - i + 1 = 1$，完全失效。

### 3.4 示例演算

以 `cards = [3,4,2,3,4,7]` 为例，关键在第 4 步（$i=3$）第二个 `3` 命中已存的最近下标 $0$：

![示例演算：cards = [3,4,2,3,4,7] 逐张扫描算跨度](images/2260_card_pickup_walkthrough.svg)

| 步 | $i$ | cards[i] | last 中同值下标 | 距离 $i-\text{last}+1$ | 动作 | ans |
|----|-----|----------|-----------------|------------------------|------|-----|
| 1 | 0 | 3 | —（首现） | — | last[3]=0 | ∞ |
| 2 | 1 | 4 | —（首现） | — | last[4]=1 | ∞ |
| 3 | 2 | 2 | —（首现） | — | last[2]=2 | ∞ |
| 4 | 3 | 3 | 0 | $3-0+1=$ **4** | last[3]=3（覆盖） | 4 |
| 5 | 4 | 4 | 1 | $4-1+1=4$ | last[4]=4（覆盖） | 4（不变） |
| 6 | 5 | 7 | —（首现） | — | last[7]=5 | 4 |

**答案 = 4** ✓（对应拿起 `[3,4,2,3]` 或 `[4,2,3,4]`）

> ⚠️ 步 4 覆盖后，若后面再出 `3`（如示例 3 的 `[3,4,2,3,3]`），将用新的 `last[3]=3` 算出 $4-3+1=2$，正是覆盖带来的「更近 → 更小 → 更优」收益；若不覆盖、仍用 `last[3]=0`，会算出 $4-0+1=5$，错过真正的最小值。

## 4. 算法细节

1. **答案公式**：连续卡牌数 = 跨度 $+\ 1$，即 $i - \text{last}[v] + 1$。把「下标差」当「段长」是最常见的 WA 原因。
2. **先查后写**：`find` 必须在 `last[cards[i]] = i` 之前，理由见 3.3。
3. **覆盖更新**：`last[cards[i]] = i` 无条件执行（命中与否都写），保证表里永远是「最近下标」。
4. **哨兵判无解**：`ans` 初始化 `INT_MAX` / `float('inf')`，扫完仍为哨兵说明无任何同值对，返回 `-1`；避免额外维护「是否命中过」标志。
5. **数据结构选择**：
   - 通用做法 `unordered_map` / `dict`，均摊 $O(1)$；
   - 本题值域 $0 \le \text{cards[i]} \le 10^6$，赛场求快可用**值域数组** `vector<int> last(1e6 + 1, -1)`（约 4 MB），`last[v] >= 0` 即出现过，省掉哈希常数（$n$ 只有 $10^5$，两版都能过，数组版是常数优化而非必需）。
6. **C++ 查表习惯**：用 `find` 拿迭代器一次查找，命中直接读 `it->second`；`count` 再 `[]` 是两次哈希查找。

## 5. 正确性证明

**引理 1（答案归约到同值对）**：设 $P$ 为所有同值下标对构成的集合，则合法答案为

$$\text{ans} = \begin{cases} \min_{(p,q) \in P} (q - p + 1), & P \ne \varnothing \\ -1, & P = \varnothing \end{cases}$$

**证明**：若 $P = \varnothing$，任何段都不含同值元素，无解返回 $-1$。否则：任取 $(p, q) \in P$，段 $[p, q]$ 含匹配对，是合法方案，故 $\text{ans} \le q - p + 1$ 对每对成立，$\text{ans} \le \min_P$；反之任何合法段 $[l, r]$ 必含某对 $(p, q) \in P$ 且 $l \le p < q \le r$，于是 $r - l + 1 \ge q - p + 1 \ge \min_P$，故 $\text{ans} \ge \min_P$。∎

**引理 2（相邻对支配）**：对每个值 $v$，设其出现下标为 $p_1 < p_2 < \dots < p_m$（$m \ge 2$），则

$$\min_{1 \le a < b \le m} (p_b - p_a) = \min_{1 \le k < m} (p_{k+1} - p_k)$$

**证明**：相邻对是全体对的子集，故左端 $\le$ 右端。反之对任意非相邻对 $(p_a, p_c)$，取 $b = a + 1$（$a < b < c$），有 $p_c - p_a = (p_c - p_b) + (p_b - p_a) \ge p_b - p_a \ge$ 右端；对相邻对自身显然 $\ge$ 右端。故左端 $\ge$ 右端，等号成立。∎

**引理 3（覆盖安全性）**：设当前位置为 $i$，值 $v = \text{cards}[i]$ 在 $i$ 之前出现过至少两次，最近两次为 $p_{m-1} < p_m < i$，则丢弃 $p_{m-1}$ 只保留 $p_m$ 不影响答案。

**证明**：由 $v$ 内部的下标对看，$i$ 与 $p_{m-1}$ 配对不是相邻对（中间隔着 $p_m$），由引理 2 其跨度 $i - p_{m-1} + 1 > i - p_m + 1$，且被 $p_m$ 相关的相邻对支配。故只记录最近下标，所有相邻对仍会被逐一计算，最小值不变。∎

**定理**：上述算法返回正确答案。

**证明**：用循环不变式：处理完下标 $i$ 后，对每个出现过的值 $v$，$\text{last}[v]$ 恰为 $v$ 在 $[0, i]$ 内的最后一次出现下标。归纳：初始表空成立；处理 $i$ 时，若 $\text{cards}[i] = v$ 已在表中，查得的 $\text{last}[v]$ 即 $v$ 的上次出现 $p_k$（归纳假设），计算 $i - p_k + 1$ 正是相邻对 $(p_k, p_{k+1}=i)$ 的候选值；随后 `last[v] = i` 维持不变式。因此扫描过程恰好对**每个值的每个相邻出现对**各计算一次跨度，由引理 2 与引理 3，这些候选的最小值等于引理 1 的 $\text{ans}$。若全程未命中，$P = \varnothing$，返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素一次哈希查 + 一次哈希写，均摊 $O(1)$，共 $n$ 次；值域数组版每次为严格 $O(1)$。
- **空间复杂度**：$O(\min(n, V))$，其中 $V = 10^6$ 为值域上界。哈希表条目数不超过不同值的个数；值域数组版为 $O(V)$（约 $10^6$ 个 `int`，4 MB）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumCardPickup(vector<int>& cards) {
        unordered_map<int, int> last;          // val -> 最近下标
        int ans = INT_MAX;
        for (int i = 0; i < (int)cards.size(); ++i) {
            auto it = last.find(cards[i]);
            if (it != last.end()) {
                ans = min(ans, i - it->second + 1);  // 段长 = 跨度 + 1
            }
            last[cards[i]] = i;                // 覆盖：只留最近下标
        }
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minimumCardPickup(self, cards: List[int]) -> int:
        last = {}                               # val -> 最近下标
        ans = float('inf')
        for i, card in enumerate(cards):
            if card in last:
                ans = min(ans, i - last[card] + 1)   # 段长 = 跨度 + 1
            last[card] = i                      # 覆盖：只留最近下标
        return -1 if ans == float('inf') else ans
```

> 💡 赛场加速版（C++）：值域 $0 \sim 10^6$，用 `vector<int> last(1000001, -1);` 替代 `unordered_map`，判断 `last[v] >= 0` 即命中，写法同样三行，省哈希常数。

## 8. 边界情况与易错点

1. **跨度忘加一**：`i - last` 是下标差，答案是 `i - last + 1`（两端的卡牌都要拿起）。
2. **先查后写**：若先执行 `last[cards[i]] = i` 再查，查到的是自己，跨度恒为 $1$，样例都过不了。
3. **不覆盖会 WA**：反例 `[3,4,2,3,3]`——不覆盖的话第二个 `3` 之后再用首个下标 $0$ 计算，得 $5$；正确答案 $2$。必须无条件 `last[v] = i`。
4. **无解返回 -1**：所有值互异（含 $n = 1$）时全程无命中，靠哨兵 `INT_MAX` / `inf` 判断；别忘了这个分支。
5. **$n = 1$**：不可能有匹配对，直接 `-1`。
6. **相邻重复是最小答案**：`[1,1]` 类输入答案为 $2$，可当小样例心算校验。
7. **C++ 两次哈希查找的常数**：`count` + `[]` 各查一次；`find` 一次拿迭代器更快。$n = 10^5$ 时无碍，但值得养成习惯。
8. **别上滑动窗口的当**：本题虽然官方标了滑动窗口标签，但「最小窗口含重复」用定长窗口判重（219 的做法）要对每个长度试探或二分，绕远路；直接对同值对取最小跨度一步到位。
