# LeetCode 含最多 K 个可整除元素的子数组 题解

## 1. 题目概述

- **标题 / 题号**：含最多 K 个可整除元素的子数组（#2261，medium）
- **链接**：https://leetcode.cn/problems/k-divisible-elements-subarrays/
- **来源**：LeetCode 第 291 场周赛 Q3
- **难度**：中等
- **标签**：字典树（Trie）、数组、哈希表、枚举

**题意**：给定整数数组 `nums` 与整数 `k`、`p`。统计**不同的子数组**中，满足「可被 `p` 整除的元素个数 $\le k$」的有多少个。两个子数组**不同**指二者长度不同，或存在某下标处元素不同。子数组是连续非空序列。

**约束**：

- $1 \le \text{nums.length} \le 200$
- $1 \le \text{nums[i]},\; p \le 200$
- $1 \le k \le \text{nums.length}$

> 💡 本题在本仓库另有[每日题解 2261](../../solution/2201-2300/2261_含最多K个可整除元素的子数组.md)：以「`set` 序列化去重」为主线，Trie 仅作扩展一节。本篇按**周赛复盘视角**展开，直接以 **Trie 沿链下行的 $O(n^2)$ 进阶解**为主线（本题进阶要求 $O(n^2)$），并补齐**引理-定理化的严格证明**（合法前缀性、路径-内容一一对应、计数一致性）与**赛场易错清单**，两篇互为印证。

```text
      [2]、[2,3]、[2,3,3]、[2,3,3,2]、[3]、[3,3]、[3,3,2]、[3,3,2,2]、
```


## 3. 解题思路

### 3.1 暴力思路：枚举全部合法子数组 + 序列化去重

照搬题意：外层枚举左端点 $l$，内层向右扩 $r$，顺带维护窗口内可整除元素计数 `cnt`，一旦 `cnt > k` 立即 `break`（右侧必然更非法）；每个合法子数组序列化成元组丢进 `set` 去重：

```python
seen = set()
for l in range(n):
    cnt = 0
    for r in range(l, n):
        cnt += (nums[r] % p == 0)
        if cnt > k:
            break
        seen.add(tuple(nums[l:r+1]))   # 序列化：O(len)
return len(seen)
```

合法子数组至多 $\frac{n(n+1)}{2}$ 个，每个序列化要 $O(\text{len})$，总计 $O(n^3)$。$n = 200$ 时约 $8 \times 10^6$ 量级，**能过**（这也是每日题解的主线），但题目进阶要求 $O(n^2)$，且重复内容多时 `set` 里堆着大量长元组，空间同样 $O(n^3)$。

> ⚠️ 浪费在于：**去重靠「把整个子数组搬进哈希」**。其实相邻两个子数组只差一个元素——去重本可以像查找树一样只「多走一步」。

### 3.2 核心观察：固定左端点沿 Trie 链下行，去重每步 O(1)

![核心观察：固定左端点沿 Trie 链下行，新节点 ⟺ 新子数组](images/2261_kdivisible_trie_concept.svg)

把「子数组内容」看作字符串，则**去重 = 统计不同路径**，天然归 Trie：

> 💡 **观察 1（合法前缀性 → 枚举免费）**：固定左端点 $l$ 向右扩 $r$，可整除元素个数单调不减，所以合法的 $r$ 恰是一段**连续前缀** $[l,\; R(l)]$——`cnt > k` 时 `break` 不漏不重。枚举所有合法 $(l, r)$ 只花 $O(n^2)$ 步。

> 💡 **观察 2（Trie 链式下行 → 去重免费）**：固定 $l$、$r$ 递增时，$[l..r]$ 与 $[l..r-1]$ 只差结尾一个元素。让游标 `node` 从 `root` 出发、每扩一个元素就沿标为 `nums[r]` 的边**下行一格**：若该边不存在，说明当前内容**首次出现**——新建节点并 `ans++`；若已存在，只是重复内容，**下行不计数**。于是**每一步 $(l, r)$ 的去重只花均摊 $O(1)$**。

两个观察合并：**枚举合法子数组 $O(n^2)$ 步 + 每步 $O(1)$ 精确去重 = 总 $O(n^2)$**，且 Trie 是确定性结构，没有哈希冲突风险。这就是本题进阶解，也对应官方标签里的 Trie。

### 3.3 算法流程

![算法流程：外层枚举左端点 l，内层沿 Trie 链向右扩展 r](images/2261_kdivisible_flow.svg)

1. 建只含根节点的 Trie，`ans = 0`；
2. 外层 `for l = 0 … n−1`：`node = root`，`cnt = 0`；
3. 内层 `for r = l … n−1`：
   - 若 `p | nums[r]`：`cnt++`；若 `cnt > k`：**break**（右侧全非法）；
   - 在 `node` 的 `children` 里查 `nums[r]`：
     - **无** → 新建子节点（`ans++`），`node = 新节点`；
     - **有** → `node = child`（沿链下行，不计数）；
4. 外层结束，返回 `ans`。

> ⚠️ 循环方向是灵魂：**必须固定左端点、让 `node` 沿链逐格下行**。若改成「枚举右端点、每个子数组都从 root 重新走一遍」，单次插入退回 $O(\text{len})$，整体退回 $O(n^3)$——这正是 3.1 暴力的本质。（固定右端点、`l` 递减、沿反向链下行也可，内容按反转存储，双射不影响不同性。）

### 3.4 示例演算

![示例演算：nums = [2,3,3,2,2] 逐轮统计新节点](images/2261_kdivisible_walkthrough.svg)

以示例 1 `nums = [2,3,3,2,2], k = 2, p = 2` 走查（蓝格下标 0、3、4 可整除）：

| $l$ | 合法 $r$ | 触发 break | 本轮新建 | 新增 | ans |
|----|---------|------------|---------|------|-----|
| 0 | 0 → 3 | $r=4$：第 3 个可整除 | [2]、[2,3]、[2,3,3]、[2,3,3,2] | +4 | 4 |
| 1 | 1 → 4 | 无（恰 2 个可整除） | [3]、[3,3]、[3,3,2]、[3,3,2,2] | +4 | 8 |
| 2 | 2 → 4 | 无 | [3,2]、[3,2,2]（[3] 重复） | +2 | 10 |
| 3 | 3 → 4 | 无 | [2,2]（[2] 重复） | +1 | 11 |
| 4 | 4 | 无 | —（[2] 重复） | +0 | 11 |

**答案 = 11** ✓。注意 $l=2$ 轮里 `[3]` 走到 $l=1$ 轮已建的节点、$l=3$ 轮里 `[2]` 走到 $l=0$ 轮已建的节点——只下行、不计数，这正是 Trie 去重的工作方式（完整树结构见 3.2 插图）。

## 4. 算法细节

1. **双循环序与游标复用**：`node` 在外层初始化为 `root`，内层随 `r` 逐步下行；一次 `find/[]` 就是全部去重开销。`cnt` 同样在外层清零、内层累加。
2. **break 的语义**：`cnt > k` 时当前 $r$ 已非法，且由单调性右侧全部非法——直接跳出内层，避免把非法子数组插入 Trie（否则会**多数**非法内容）。
3. **Trie 的存储**：
   - Python：嵌套 `dict` 即节点（`node[x]` 不存在就新建 `{}`）；
   - C++：`vector<unordered_map<int,int>>`，下标即节点编号，`trie[node][x] = 新编号`。$n \le 200$ 时节点数 $\le \frac{200 \times 201}{2} \approx 2 \times 10^4$，内存无压力。
   - 值域只有 $[1, 200]$，若嫌哈希慢也可每节点开 `vector<int>(201, -1)`，但 $2 \times 10^4$ 节点 × 201 × 4B ≈ 16 MB 不划算；`unordered_map` 均摊 $O(1)$ 足够。
4. **计数与去重合一**：`ans` 只在「新建节点」时增加——无需先收集所有子数组再去重，也无需另设 `set`。
5. **为什么不用滚动哈希**（官方标签里的 Rolling Hash / Hash Function）：单模多项式哈希存在构造性反例，比赛用需双哈希保险；哈希一个长为 $L$ 的子数组 $O(L)$，若每次重算同样退回 $O(n^3)$，须配合前缀哈希 $O(1)$ 查询——而 Trie 无冲突、无需取模、每步均摊 $O(1)$，是本题最稳的 $O(n^2)$。
6. **达到进阶 $O(n^2)$ 的记账**：内层总步数 = 合法 $(l, r)$ 对数 $\le \frac{n(n+1)}{2}$，每步均摊 $O(1)$。

## 5. 正确性证明

**引理 1（合法前缀性）**：固定 $l$，记 $f(r) = \#\{\, i \in [l, r] : p \mid \text{nums}[i] \,\}$，则合法右端点集 $\{\, r \in [l, n-1] : f(r) \le k \,\}$ 是一段连续前缀 $[l,\; R(l)]$（非空，因 $k \ge 1$ 使 $f(l) \le 1 \le k$）。从而「`cnt > k` 即 break」恰好枚举全部合法 $(l, r)$、不枚举任何非法者。

**证明**：$[l, r] \subseteq [l, r']$（$r \le r'$）使 $f(r) \le f(r')$，即 $f$ 关于 $r$ 单调不减。若 $r$ 合法，则一切 $r' \le r$ 有 $f(r') \le f(r) \le k$ 亦合法；若 $r$ 非法，则一切 $r' \ge r$ 有 $f(r') \ge f(r) > k$ 亦非法。故合法集形如 $[l, R(l)]$。break 发生在首个 $f$ 超限的 $r$ 处，恰为 $R(l)+1$。∎

**引理 2（路径-内容一一对应）**：Trie 是树，故从 `root` 出发的任一路径唯一确定其边标序列，反之任一有限序列对应至多一条从 `root` 出发的路径。固定 $l$ 归纳可知：内层处理 $(l, r)$ 时游标 `node` 的路径边标恰为 $(\text{nums}[l], \dots, \text{nums}[r])$（初始为空路径；每步沿标 `nums[r]` 的边下行一格）。

**引理 3（计数一致性）**：按算法处理顺序（$l$ 升序，同 $l$ 内 $r$ 升序），处理完全部已遍历的 $(l, r)$ 后：Trie 中从 `root` 出发的路径集合 = 至今处理过的合法子数组内容集合，且 `ans` = 该集合大小。

**证明**：归纳。初始 Trie 仅空路径，集合为空，`ans = 0`，成立。处理 $(l, r)$ 时其内容路径由引理 2 确定：若路径已存在（更早处理过同内容子数组），`find` 命中，`ans` 不变，路径集合不变；若不存在，则新建终止节点使路径从无到有，`ans` 与集合大小同步 +1。且因同 $l$ 的更小 $r$ 已插入该内容的全部真前缀，路径的中间节点均存在，新建只需一个节点。不变式始终成立。∎

**定理**：算法返回的 `ans` 等于不同合法子数组的个数。

**证明**：由引理 1，算法恰好逐一处理每个合法 $(l, r)$；由引理 3，结束时 `ans` = 全体合法子数组内容集合的大小；又由题意，子数组「不同」当且仅当内容序列不同，故该集合大小即所求答案。∎

**复杂度注记**：内层总步数为合法 $(l, r)$ 对数 $\le \frac{n(n+1)}{2}$，每步一次均摊 $O(1)$ 的字典查找/插入，故时间为 $O(n^2)$；Trie 节点数 = 不同合法子数组数 $\le \frac{n(n+1)}{2}$，故空间为 $O(n^2)$（元素全相同时仅 $O(n)$）。

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。合法 $(l, r)$ 对至多 $\frac{n(n+1)}{2} \approx 2 \times 10^4$（$n = 200$），每对一次均摊 $O(1)$ 的 `find`/`insert`；`cnt` 维护与整除判断 $O(1)$。满足题目进阶要求。
- **空间复杂度**：$O(D)$，$D$ 为不同合法子数组个数（$\le \frac{n(n+1)}{2}$）。每个 Trie 节点一个字典/哈希表；元素大量重复时 $D = O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int countDistinct(vector<int>& nums, int k, int p) {
        int n = nums.size();
        vector<unordered_map<int, int>> trie(1);   // trie[0] 为根
        int ans = 0;
        for (int l = 0; l < n; ++l) {
            int node = 0, cnt = 0;                 // 游标回到根，计数清零
            for (int r = l; r < n; ++r) {
                if (nums[r] % p == 0 && ++cnt > k)
                    break;                         // 引理 1：右侧全部非法
                auto it = trie[node].find(nums[r]);
                if (it == trie[node].end()) {      // 内容首次出现：新子数组
                    int child = trie.size();       // 先取新编号，再扩容
                    trie[node].emplace(nums[r], child);
                    trie.emplace_back();
                    node = child;
                    ++ans;
                } else {
                    node = it->second;             // 重复内容：沿链下行
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countDistinct(self, nums: List[int], k: int, p: int) -> int:
        root = {}
        ans = 0
        for l in range(len(nums)):
            node, cnt = root, 0                 # 游标回到根，计数清零
            for r in range(l, len(nums)):
                if nums[r] % p == 0:
                    cnt += 1
                    if cnt > k:                # 引理 1：右侧全部非法
                        break
                nxt = node.get(nums[r])
                if nxt is None:                # 内容首次出现：新子数组
                    nxt = {}
                    node[nums[r]] = nxt
                    ans += 1
                node = nxt                     # 沿链下行
        return ans
```

## 8. 边界情况与易错点

1. **忘 break 会多数**：`cnt > k` 后继续循环会把非法子数组也插入 Trie，答案偏大；break 由引理 1 的单调性保证不漏。
2. **游标忘记回根**：新一轮 $l$ 必须 `node = root`、`cnt = 0` 重置；漏掉会把上一轮的链续接到本轮，结果彻底错乱。
3. **序列化去重的定界陷阱**（若写暴力版）：直接拼接字符串会把 `[1,2]` 与 `[12]` 混淆，`nums[i] \le 200` 是三位数，必须用 `tuple` 或加 `,` 分隔。
4. **循环方向陷阱**：固定左端点正向沿链下行是 $O(n^2)$ 的关键；「枚举右端点、每个子数组从根重走」单次 $O(\text{len})$，整体退回 $O(n^3)$。
5. **单元素恒合法**：$k \ge 1$ 保证每个 $[i..i]$ 至多含 1 个可整除元素，合法集永不空，答案 $\ge 1$，无需特判空返回。
6. **大量重复元素**：如 `[7,7,...,7]` 且 $k$ 很大——合法子数组 $O(n^2)$ 个但内容只有 $O(n)$ 个；Trie 版照旧 $O(n^2)$ 时间、$O(n)$ 空间，而暴力 `set` 版存 $O(n^2)$ 个长元组、空间 $O(n^3)$，重复越多差距越大。
7. **滚动哈希的冲突风险**：单模哈希可能被构造数据卡（WA 而非 TLE），要用双模/随机基数；Trie 无冲突，是赛场上更稳的选择。
8. **`p = 1` 整除一切**：此时合法子数组长度 $\le k$，break 把每条链长限制在 $k$，可作心算校验（如示例 2 中 $k = 4 \ge n$ 则不受限）。
9. **C++ 节点扩容细节**：先记录新节点编号再 `emplace_back`（或扩容后回填），避免引用/迭代器因 `vector` 扩容而失效。
