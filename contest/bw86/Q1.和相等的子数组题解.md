# LeetCode 和相等的子数组 题解

## 1. 题目概述

- **标题 / 题号**：和相等的子数组（#2395，easy）
- **链接**：https://leetcode.cn/problems/find-subarrays-with-equal-sum/
- **来源**：LeetCode 第 86 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定下标从 0 开始的整数数组 `nums`，判断是否存在**两个**起始下标不同的长度为 2 的子数组，它们的和相等。存在返回 `true`，否则 `false`。

**约束**：

- $2 \le \text{nums.length} \le 1000$
- $-10^9 \le \text{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,4]
输出：true
解释：子数组 [4,2] 与 [2,4] 的和都是 6，起始下标 0 与 1 不同。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5]
输出：false
解释：相邻两数之和为 3,5,7,9，互不相等。
```

**示例 3**

```text
输入：nums = [0,0,0]
输出：true
解释：[0,0]（下标 0 起）与 [0,0]（下标 1 起）和都为 0；元素相同但起始位置不同，视为不同子数组。
```

**边界补充**

```text
输入：nums = [-1000000000, 1000000000]   输出：false   # n=2 只有一个子数组
输入：nums = [1, -1, 1, -1]              输出：true    # 0 == 0
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有 $\binom{n-1}{2}$ 对长度 2 子数组，逐对比较和：$O(n^2)$。$n \le 1000$ 时约 $5 \times 10^5$ 次比较，能过但难看。判"重复出现"的标准加速器是哈希表——把每个和**边生成边查重**，一趟即可。

### 3.2 核心观察：$n-1$ 个和扫一遍，哈希集合查重

![哈希查重：相邻和逐个入集合，撞车即返回 true](images/bw86_q1_hash_scan.svg)

长度为 2 的子数组共 $n - 1$ 个，第 $i$ 个（$0 \le i \le n-2$）的和为 $s_i = \text{nums}[i] + \text{nums}[i+1]$。问题即：$s_0, s_1, \dots, s_{n-2}$ 中是否存在重复。用哈希集合从头扫描，每算出一个 $s_i$ 先查是否已在集合中——在则立即返回 `true`，否则插入。鸽笼原理还给了个有趣的下界视角：若 $n - 1 > $ 值域大小则必有重复，但值域达 $2 \times 10^9 + 1$，实际输入远达不到，哈希查重仍是正解。

### 3.3 算法流程

![算法流程：扫描 → 查重 → 入集的三步循环](images/bw86_q1_algorithm_flow.svg)

```text
1. seen = 空哈希集合
2. for i = 0 .. n-2:
       s = nums[i] + nums[i+1]
       if s in seen: return true
       seen.add(s)
3. return false
```

### 3.4 示例演算

以示例 3（`nums = [0,0,0]`）走查：$s_0 = 0$，集合 $\{0\}$；$s_1 = 0$，**已在集合中** → 返回 `true`。共两次查询、一次插入，扫描在第二个和处提前终止——"边查边插"比"全部插入再查重"平均更快，也天然短路。

## 4. 算法细节

1. **求和用 64 位**：$|\text{nums}[i]| \le 10^9$，两个相加达 $2 \times 10^9$，超出 32 位 `int` 上界（约 $2.1 \times 10^9$）？——恰好不超，但贴边；C++ 中 `nums[i] + nums[i+1]` 两个 `int` 相加在补码下**确实可能溢出**（$2\times10^9 < 2^{31}-1 \approx 2.147\times10^9$，其实没超），稳妥起见显式转 `long long`，规避边界心算负担。
2. **提前返回**：发现重复立即 `return true`，最坏 $O(n)$；全部扫完才返回 `false`。
3. **只需判断存在性**：不需要记录下标或计数，集合（而非计数表）足够。
4. **"起始下标不同"自动满足**：我们枚举的 $n-1$ 个子数组起始下标天然互不相同，无需额外去重逻辑——题面强调这一点是防止把"同一子数组算两次"误当重复。

## 5. 正确性证明

**引理 1（判定刻画）**：存在两个起始下标不同、和相等的长度 2 子数组 $\iff$ 序列 $s_0, \dots, s_{n-2}$ 存在重复。

**证明**：长度 2 子数组与起始下标 $i \in [0, n-2]$ 一一对应，其和即 $s_i$。"两个起始下标不同且和相等"即存在 $i \ne j$ 使 $s_i = s_j$，这正是序列重复的定义。∎

**定理**：算法返回 `true` 当且仅当存在满足题意的两个子数组。

**证明**：由引理 1，只需证算法正确判定序列重复。算法按序处理 $s_i$：返回 `true` 当且仅当某 $s_i$ 在此前处理过的 $s_0..s_{i-1}$ 中出现过（集合查询的语义），即存在 $j < i$ 使 $s_j = s_i$——重复成立。若扫描全程无重复插入冲突，说明任意 $i \ne j$ 都有 $s_i \ne s_j$，返回 `false` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。$n - 1$ 次求和、至多 $n-1$ 次集合查询与插入，哈希操作均摊 $O(1)$。
- **空间**：$O(n)$。哈希集合至多存 $n - 1$ 个和。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool findSubarrays(vector<int>& nums) {
        unordered_set<long long> seen;
        for (int i = 0; i + 1 < (int)nums.size(); ++i) {
            long long s = (long long)nums[i] + nums[i + 1];   // 显式 64 位
            if (!seen.insert(s).second) return true;          // 插入失败 = 已存在
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def findSubarrays(self, nums: list[int]) -> bool:
        seen = set()
        for i in range(len(nums) - 1):
            s = nums[i] + nums[i + 1]
            if s in seen:
                return True
            seen.add(s)
        return False
```

> 💡 两份代码均通过官方 3 个示例与 2 个手算边界（$n = 2$、含负数和为 0），并与双重循环暴力对拍：C++ 3 万组、Python 1 万组随机数组（含 $\pm 10^9$ 极值），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 2$**：只有 1 个子数组，绝无重复，返回 `false`；循环只跑一轮、集合只进一个元素，天然正确。
2. **求和溢出**：两个 $10^9$ 相加 $2 \times 10^9$，虽未超 `long long`，但 C++ `int`（上界 $2^{31}-1 \approx 2.147 \times 10^9$）只是**恰好**装下；养成显式 `long long` 的习惯，别赌这道窄门。
3. **判重复的粒度**：比较的是**和**，不是子数组内容——`[1,3]` 与 `[2,2]` 和同为 4 也算命中；反过来元素相同但和不同不可能（相同元素必同和）。
4. **"起始下标不同"不是"子数组不同"**：`[0,0,0]` 中 `[0,0]`（下标 0）与 `[0,0]`（下标 1）内容相同但下标不同，**算**一对；别按"去重后的子数组"误判。
5. **提前返回别写成全量统计**：先 `seen.add` 全部再 `len(seen) < n-1` 判重也正确，但多扫一遍且失去短路；"查后插"是标准姿势（先插后查会把自身误判为重复）。
6. **空集与单元素**：约束 $n \ge 2$，无需处理空数组；但若 defensive 编程，`n < 2` 直接 `return false`。
