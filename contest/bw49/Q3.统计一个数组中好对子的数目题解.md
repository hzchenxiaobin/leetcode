# LeetCode 统计一个数组中好对子的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计一个数组中好对子的数目（#1814，medium）
- **链接**：https://leetcode.cn/problems/count-nice-pairs-in-an-array/
- **来源**：LeetCode 第 49 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、数学、计数

**题意**：定义 $\mathrm{rev}(x)$ 为把非负整数 $x$ 的十进制位反转后的数（如 $\mathrm{rev}(123)=321$，$\mathrm{rev}(120)=21$）。称下标对 $(i,j)$（$0 \le i < j < n$）是**好的**，当且仅当

$$nums[i] + \mathrm{rev}(nums[j]) = nums[j] + \mathrm{rev}(nums[i]).$$

返回好下标对的数目，对 $10^9+7$ 取模。

**约束**：

- $1 \le n \le 10^5$
- $0 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [42,11,1,97]
输出：2
解释：(0,3)：42 + rev(97) = 42 + 79 = 121，97 + rev(42) = 97 + 24 = 121；
     (1,2)：11 + rev(1) = 11 + 1 = 12，1 + rev(11) = 1 + 11 = 12。
```

**示例 2**

```text
输入：nums = [13,10,35,24,76]
输出：4
解释：13/35/24 的 key 相同（-18），10/76 的 key 相同（9），共 C(3,2)+C(2,2)=3+1=4 对。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有 $(i,j)$ 对，对每对现场计算两个 $\mathrm{rev}$ 并判断等式：$O(n^2 \cdot \log_{10} V)$，$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时。观察等式的形状：四个量分居等号两侧，各含一个 $nums$ 与一个 $\mathrm{rev}$——这是典型的**可以移项把 $i$ 与 $j$ 解耦**的对称条件。

### 3.2 核心观察：移项变形，配对条件与 $j$ 无关地刻画 $i$

![关键变形：等式移项后按 x - rev(x) 归组](images/bw49_q3_key_grouping.svg)

把 $nums[j] + \mathrm{rev}(nums[i])$ 移到左边、$nums[i]$ 归到一边：

$$nums[i] - \mathrm{rev}(nums[i]) = nums[j] - \mathrm{rev}(nums[j]).$$

定义**指纹** $f(x) = x - \mathrm{rev}(x)$，则好对条件就是 $f(nums[i]) = f(nums[j])$——与"两数之和"类问题完全同构：**把每个数映射成指纹，同指纹的元素两两成对**。

⚠️ 注意变形方向是**减法**而不是加法：$x+\mathrm{rev}(x)$ 相等既不必要也不充分（反例：$42$ 与 $97$ 满足 $f(42)=f(97)=18$ 是好对，但 $42+\mathrm{rev}(42)=66$ 与 $97+\mathrm{rev}(97)=176$ 并不相等）。

### 3.3 算法流程：一趟哈希计数

![同指纹桶内两两配对，桶大小 n 贡献 C(n,2)](images/bw49_q3_pair_counting.svg)

```text
1. cnt ← 空哈希表（指纹 → 出现次数），ans = 0
2. 对每个 x ∈ nums：
       计算 rev(x)（按位反转）
       key = x - rev(x)
       ans += cnt[key]        # 之前每个同 key 的元素都与 x 构成好对
       cnt[key] += 1
3. 返回 ans mod (10^9 + 7)
```

每个桶内若有 $m$ 个同指纹元素，两两组合贡献 $\binom{m}{2}$ 对；逐元素累加"先看之前有多少个同 key"恰好等价于对每个桶累加 $\binom{m}{2}$（第 $k$ 个进桶的元素贡献 $k-1$，求和 $0+1+\dots+m-1 = \binom{m}{2}$），无需显式组合数。

### 3.4 示例演算

**示例 1**：$nums = [42, 11, 1, 97]$：

| $x$ | $\mathrm{rev}(x)$ | $f(x)=x-\mathrm{rev}(x)$ | 进桶前该桶已有 | 累计答案 |
|-----|------------------|--------------------------|----------------|----------|
| 42 | 24 | 18 | 0 | 0 |
| 11 | 11 | 0 | 0 | 0 |
| 1 | 1 | 0 | 1 | 1 |
| 97 | 79 | 18 | 1 | 2 |

桶 $\{18: 2,\; 0: 2\}$，$\binom{2}{2}+\binom{2}{2} = 1+1 = 2$ ✓。

**示例 2**：$nums = [13,10,35,24,76]$ 的指纹依次为 $-18, 9, -18, -18, 9$，桶 $\{-18: 3,\; 9: 2\}$，答案 $\binom{3}{2}+\binom{2}{2} = 3+1 = 4$ ✓。

## 4. 算法细节

1. **按位反转**：`while (y) { r = r * 10 + y % 10; y /= 10; }`。$x=0$ 时循环不执行、$\mathrm{rev}(0)=0$，天然正确；尾零自动丢弃（$\mathrm{rev}(120)=21$），无需特判。
2. **指纹用带符号整数**：$f(x)$ 的取值范围是 $(-10^9, 10^9)$，`int` 放得下，但 C++ 哈希键建议直接 `long long` 以免隐式转换踩坑。
3. **取模时机**：答案上界 $\binom{10^5}{2} \approx 5 \times 10^9$，超过 `int`；C++ 中累加变量用 `long long` 且每步 `% MOD`，Python 原生大整数无溢出但仍应按题意取模。
4. **先累加后计数**：`ans += cnt[key]` 必须发生在 `cnt[key] += 1` 之前，保证 $(i,j)$ 只按 $i<j$ 数一次。
5. **一遍扫描**：不需要先建完哈希表再二次遍历求 $\sum \binom{m}{2}$，边扫边加的单趟写法更短且省一次遍历。

## 5. 正确性证明

**引理 1（等价变形）**：对任意非负整数 $a, b$，

$$a + \mathrm{rev}(b) = b + \mathrm{rev}(a) \iff a - \mathrm{rev}(a) = b - \mathrm{rev}(b).$$

**证明**：原式移项（两边同减 $b + \mathrm{rev}(a)$）得 $a - \mathrm{rev}(a) = b - \mathrm{rev}(b)$，每一步都是可逆的整数加减法，故为等价变形。∎

**引理 2（桶计数）**：设多重集 $\{f(nums[i])\}$ 中值为 $v$ 的元素出现 $m_v$ 次，则好对总数 $= \sum_v \binom{m_v}{2}$。

**证明**：由引理 1，$(i,j)$ 是好对 ⟺ $f(nums[i]) = f(nums[j])$。对每个指纹值 $v$，$m_v$ 个元素中无序选取两个（对应 $i<j$ 的唯一排列）恰有 $\binom{m_v}{2}$ 种；不同指纹值之间不构成好对。各桶独立求和即得。∎

**定理**：算法返回的 `ans` 等于好对数模 $10^9+7$。

**证明**：按扫描顺序归纳：处理完前 $k$ 个元素后，`ans` 等于这 $k$ 个元素内部的好对数，`cnt[v]` 等于前 $k$ 个元素中指纹为 $v$ 的个数。第 $k{+}1$ 个元素进桶时新增的好对数恰为"之前同指纹个数"，即 `cnt[key]`，与引理 2 中按桶累计 $\binom{m}{2}$ 的分解一致（第 $t$ 个进入桶 $v$ 的元素贡献 $t-1$）。全程每步对 `ans` 取模，由同余运算对加法的封闭性，返回值是好对数模 $10^9+7$。∎

## 6. 复杂度分析

- **时间**：$O(n \log_{10} V)$。每个元素一次按位反转（$V \le 10^9$，至多 10 位）加一次哈希表操作；$n = 10^5$ 时约 $10^6$ 量级基本操作。
- **空间**：$O(n)$。哈希表至多存 $n$ 个不同指纹。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countNicePairs(vector<int>& nums) {
        const long long MOD = 1000000007LL;
        unordered_map<long long, long long> cnt;
        long long ans = 0;
        for (int x : nums) {
            long long r = 0;
            for (long long y = x; y > 0; y /= 10) r = r * 10 + y % 10;
            long long key = (long long)x - r;                 // 指纹 x - rev(x)
            auto it = cnt.find(key);
            long long c = (it == cnt.end()) ? 0 : it->second;
            ans = (ans + c) % MOD;
            cnt[key] = c + 1;
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countNicePairs(self, nums: list[int]) -> int:
        MOD = 10 ** 9 + 7
        cnt = {}
        ans = 0
        for x in nums:
            r, y = 0, x
            while y:                              # 按位反转
                r = r * 10 + y % 10
                y //= 10
            key = x - r                           # 指纹 x - rev(x)
            ans = (ans + cnt.get(key, 0)) % MOD   # 与之前同指纹的元素两两配对
            cnt[key] = cnt.get(key, 0) + 1
        return ans
```

> 💡 两份代码通过官方 2 个示例（`2 / 4`），与"双重循环 + 现场计算 rev"的暴力在 2000 组随机数组（含 $10^9$ 大数、尾零、$0$）上对拍（`mismatch = 0`），$n = 10^5$ 随机数组 Python 0.08s / C++ 瞬时完成；C++ 与 Python 在 300 组随机输入上交叉一致。

## 8. 边界情况与易错点

1. **变形方向写错**：最常见的翻车是把指纹写成 $x + \mathrm{rev}(x)$——那既不充分也不必要（见 §3.2 的反例）。移项时盯紧每一项挪到哪一侧。
2. **$\mathrm{rev}$ 的尾零与 0**：$\mathrm{rev}(120)=21$、$\mathrm{rev}(0)=0$，按位循环自动处理；若用"转字符串反转再转回"的写法，注意前导零同样自动消失，两种写法等价。
3. **溢出**：指纹范围 $(-10^9, 10^9)$ 在 `int` 边缘，而计数上界 $\binom{10^5}{2} \approx 5 \times 10^9$ **必然**超出 `int`；C++ 必须用 `long long` 累加并取模。
4. **取模只对答案**：指纹本身是精确等值判断，**不能**对指纹取模（不同指纹模后相撞会多算），只对最终计数取模。
5. **先加后更**：`ans += cnt[key]` 在 `cnt[key] += 1` 之前，否则会把元素和自己配成一对。
6. **哈希键支持负数**：指纹可以是负数（如 $13-31=-18$），`unordered_map<long long, ...>` 与 Python `dict` 都原生支持，无需偏移。
