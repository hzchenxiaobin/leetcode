# LeetCode 得到新鲜甜甜圈的最多组数 题解

## 1. 题目概述

- **标题 / 题号**：得到新鲜甜甜圈的最多组数（#1815，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-groups-getting-fresh-donuts/
- **来源**：LeetCode 第 49 场双周赛 Q4
- **难度**：困难
- **标签**：位运算、记忆化、数组、动态规划、位掩码

**题意**：甜甜圈商店每批烤 $\textit{batchSize}$ 个甜甜圈，规则是上一批必须全部卖完才能烤下一批。给定一批批顾客，每组 `groups[i]` 人，每人恰好买一个。一组顾客感到**开心**当且仅当该组第一位顾客拿到的甜甜圈**不是上一组剩下的**（即轮到该组时恰好开新批）。可以任意安排各组到来的顺序，求最多能让多少组开心。

**约束**：

- $1 \le \textit{batchSize} \le 9$
- $1 \le \textit{groups.length} \le 30$
- $1 \le \textit{groups[i]} \le 10^9$

## 2. 示例

**示例 1**

```text
输入：batchSize = 3, groups = [1,2,3,4,5,6]
输出：4
解释：按 [6,2,4,5,1,3] 的顺序安排，第 1、2、4、6 组（该顺序下的位置）会开心。
```

**示例 2**

```text
输入：batchSize = 4, groups = [1,3,2,5,2,2,1,6]
输出：4
解释：按 [1,3,2,2,2,2,1,1] 的顺序，1、3、5、7 位置上的组开心。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是穷举所有 $30!$ 个排列，对每个排列模拟一遍统计开心组数——天文数字，不可行。退一步，把"还没安排的组集合"压成 30 位二进制掩码做记忆化搜索，状态数 $2^{30} \approx 10^9$，同样爆炸。

暴力路线的启示是：**决定后续命运的只有"还剩哪些组"和"当前累计人数的余数"**。而"还剩哪些组"中，同余数的组彼此完全可互换—— $1{,}000{,}000{,}000$ 人的组和 $1{,}000{,}000{,}003$ 人的组对后续毫无区别。这提示我们按**余数计数**而不是按**组的身份**来压缩状态。

### 3.2 核心观察：取模不变性、余 0 贪心、计数状态压缩

![三个关键观察：取模、余 0 贪心、按余数计数压状态](images/bw49_q4_state_packing.svg)

**观察 1（取模不变性）**：一组是否开心只取决于"它之前的人数总和是否是 $\textit{batchSize}$ 的倍数"。设当前位置的前缀和为 $S$，则买 $1$ 个人和买 $\textit{batchSize}+1$ 个人对后续的影响完全相同。于是每组只需保留 $r = \textit{groups}[i] \bmod \textit{batchSize}$，余数落在 $[0, B-1]$（记 $B = \textit{batchSize}$）。

**观察 2（余 0 组贪心拿满）**：余数为 $0$ 的组每买完一批恰好清空、不改变前缀余数。把它们**全部排到最前**：每组的开局余数都是 $0$，于是**全部开心**，而且它们不会干扰任何其他组的前缀余数（可证明交换后其余组的开心情况不变，见 §5 引理 2）。答案先加上 $\textit{cnt}[0]$，DFS 只需处理余数 $1 \dots B-1$ 的组。

**观察 3（计数状态压缩）**：剩余组只由"每种余数还剩几组"这个计数向量决定。$B \le 9$，非零余数至多 $8$ 种；每组数不超过 $30 < 2^5$，用 **5 个二进制位**存一种余数的个数，$8 \times 5 = 40$ 位打包进一个 64 位整数 `state`。这样状态数从 $2^{30}$ 骤减为 $\prod_r (\textit{cnt}[r]+1)$——最坏情况（$B=9$、30 组均摊到 8 种余数，即四个 4、四个 3）也只有 $5^4 \times 4^4 = 160000$ 个。

> ⚠️ 一个隐蔽但关键的性质：**当前前缀余数由 state 唯一确定**。所有非零余数之和 $\textit{total}$ 是定值，剩余部分的余数和 $\textit{rest} = \sum_r r \cdot \textit{cnt}[r]$，于是已安排部分的余数和恰为 $(\textit{total} - \textit{rest}) \bmod B$。因此记忆化哈希表的键**只需 state 一个数**，无需把前缀余数一起塞进键。

### 3.3 算法流程：记忆化 DFS

![DFS 决策树：每个状态枚举下一组放哪种余数，开局余数为 0 时得分](images/bw49_q4_dfs_tree.svg)

定义 $\text{dfs}(\text{state})$：剩余计数状态为 state（其对应开局余数 $\text{used}$ 可反推）时，还能获得的最多开心组数。

```text
1. 统计 cnt[r]，ans = cnt[0]；把 cnt[1..B-1] 打包成 state，total = Σ r·cnt[r] mod B
2. dfs(state)：
       若 state == 0：返回 0
       rest = Σ r · cnt_r(state)，used = (total − rest) mod B     # 反推开局余数
       happy = (used == 0) ? 1 : 0                                  # 现在放的这组是否开心
       res = max over 余数 r（cnt_r(state) > 0）:
                 dfs(state − e_r) + happy
       记忆化返回 res
3. 返回 ans + dfs(state)
```

转移的含义：枚举"下一组放哪种余数 $r$"。放下去的这组若开局余数为 0 就得 1 分，之后问题变成更小的 state。**得分挂在"开局余数为 0"的组上**，而不是"放完后余数变 0"的组——后者只是恰好清空一批，并不开心。

### 3.4 示例演算

![示例 1 的最优排列：前缀和 mod 3 的时间线](images/bw49_q4_example_prefix.svg)

**示例 1**（$B=3$，余数 $[1,2,0,1,2,0]$，$\textit{cnt}[1]=\textit{cnt}[2]=2$）：$\textit{cnt}[0]=2$ 直接计入；打包 $\text{state} = 2 \ll 5 \;|\; 2 \ll 10 = 2112$，$\textit{total} = (1 \cdot 2 + 2 \cdot 2) \bmod 3 = 0$。最优排列 $[6,2,4,5,1,3]$ 的逐组走查：

| 位置 | 组人数 | 该组开局的累计人数 | mod 3 | 开心 |
|------|--------|--------------------|-------|------|
| 1 | 6 | 0 | 0 | ✓ |
| 2 | 2 | 6 | 0 | ✓ |
| 3 | 4 | 8 | 2 | ✗ |
| 4 | 5 | 12 | 0 | ✓ |
| 5 | 1 | 17 | 2 | ✗ |
| 6 | 3 | 18 | 0 | ✓ |

加上前置的余 0 组，共 $2 + 2 = 4$ 组开心 ✓。**示例 2**（$B=4$，余数 $[1,3,2,1,2,2,1,2]$）同理：排列 $[1,3,2,2,2,2,1,1]$ 中位置 1、3、5、7 开局余数为 0，得 4 分 ✓。

## 4. 算法细节

1. **打包位运算**：余数 $r$ 的个数放在从第 $r \times 5$ 位开始的 5 个二进制位里。读取个数用 `(state >> (r * 5)) & 31`（$31 = 2^5-1$）；"拿走一个余数 $r$ 的组"用 `state - (1LL << (r * 5))`。5 位上限 31，容纳 $\le 30$ 的计数绰绰有余。
2. **前缀余数反推**：`used = (total - rest) mod B`，其中 `rest = Σ r·cnt_r(state) mod B`。C++ 中 `total - rest` 可能为负，需 `((total - rest) % B + B) % B`；Python 的 `%` 天然非负。
3. **余 0 组不进 DFS**：它们已被贪心拿满。若放进状态里，反而要在余数非 0 的开局处理"不开心"分支，既费状态又容易写错。
4. **记忆化容器**：C++ 用 `unordered_map<long long, int>`（state 是 40 位整数，键去重后即唯一局面）；Python 用 `dict` 或 `functools.lru_cache`。键只有 state 一个数（观察 3 保证了合法性）。
5. **得分时机**：`happy` 由**当前 state 的开局余数**决定，对本 state 的所有转移是同一个值，放在循环外计算一次即可。
6. **多次调用**：C++ 中把哈希表作为成员时，入口处要 `clear()`，防止同一 `Solution` 实例被多次调用时残留旧状态（LeetCode 单次调用无碍，但这是好习惯）。

## 5. 正确性证明

记 $B = \textit{batchSize}$，某排列的前缀和 $S_0=0, S_k = \sum_{t \le k} g_{\pi(t)}$。

**引理 1（开心的前缀刻画）**：排列 $\pi$ 中第 $k$ 组开心 $\iff$ $S_{k-1} \equiv 0 \pmod B$。

**证明**：店方规则是"上一批卖完才烤下一批"。第 $k$ 组第一位顾客拿到的甜甜圈是第 $\lceil S_{k-1}/B \rceil$ 批的剩余 $S_{k-1} \bmod B$ 个中的第一个：若 $S_{k-1} \bmod B = 0$，说明之前的批恰好卖空、该顾客拿到新批的第一个——新鲜，全组开心；否则拿到上一组剩下的——不开心。$k=1$ 时 $S_0 = 0$，第一组总开心，与规则一致。∎

**引理 2（余 0 组前置不劣）**：存在最优排列，使所有余 0 组都排在最前且全部开心。

**证明**：任取最优排列，把所有余 0 组抽出、按原相对顺序放到最前。抽出后各非零组的相对顺序不变。对任一非零组，其新开局余数 = （所有余 0 组之和 $\equiv 0$）+（原排列中它前面的非零组之和），而原开局余数 = （原排列中它前面的余 0 组之和 $\equiv 0$）+（同样的非零前缀），两者模 $B$ 相等，故非零组的开心情况逐一保持不变。而余 0 组现在每组的开局余数都是 0（前缀全为余 0 组之和），全部开心，不劣于原来。∎

**引理 3（无后效性）**：给定剩余组的余数多重集 $M$ 与开局余数 $u$，后续可获得的最多开心组数与到达该局面的历史无关；且 $u$ 由 $M$ 唯一确定：$u = (\textit{total} - \sum_{r \in M} r) \bmod B$，其中 $\textit{total}$ 为初始非零余数总和。

**证明**：后续任何排列产生的开心数由引理 1 只依赖 $u$ 与 $M$ 的一个排列顺序，历史中已固定的组不再参与。又因为全程所有组（余 0 组已被剥离）的余数总和守恒为 $\textit{total}$，已安排部分的余数和为 $\textit{total} - \sum_{r \in M} r$，其模 $B$ 即为 $u$，故 $u$ 是 $M$ 的函数。∎

**定理（DFS 正确性）**：`dfs(state)` 返回剩余局面 state 下的最多开心组数，从而 `cnt[0] + dfs(state_init)` 即全局最优。

**证明**：对剩余组数 $m$ 归纳。$m = 0$：state 为 0，返回 0 ✓。$m \ge 1$：最优排列的第一组设余数为 $r$（$cnt_r > 0$），由引理 1 该组贡献 $\left[ u = 0 \right]$ 分（$u$ 为 state 反推出的开局余数），剩余部分是 $M - \{r\}$ 的子问题且新开局余数 $(u + r) \bmod B$ 恰为子状态的反推值（引理 3），由归纳假设其最优值即 $\text{dfs}(\text{state} - e_r)$。对所有可选 $r$ 取最大即得转移方程；由引理 3，$u$ 是 state 的函数，故以 state 为键记忆化不损失正确性。结合引理 2 把余 0 组剥离到最前，总答案为 $\textit{cnt}[0] + \text{dfs}(\text{state}_{\text{init}})$。∎

## 6. 复杂度分析

- **时间**：状态数为各余数计数的乘积 $\prod_{r=1}^{B-1} (\textit{cnt}[r]+1)$（从初始计数只减不增，可达状态是初始计数的全部"子向量"）。$\sum_r \textit{cnt}[r] \le 30$ 固定时，乘积在计数均摊时最大：$B=9$ 时为 $5^4 \times 4^4 = 160000$。每个状态转移枚举至多 $B-1 = 8$ 种余数、反推余数和也是 $O(B)$，总操作约 $160000 \times 16 \approx 2.6 \times 10^6$，远低于题目限制。
- **空间**：哈希表 $O(\text{状态数}) \le 1.6 \times 10^5$ 个键值对，另有 $O(1)$ 的打包状态与计数数组。递归深度 $\le 30$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxHappyGroups(int batchSize, vector<int>& groups) {
        long long state = 0;
        int ans = 0;
        for (int g : groups) {
            int r = g % batchSize;
            if (r == 0) ++ans;                    // 余 0 的组任意时刻都开心，贪心先拿满
            else state += 1LL << (r * 5);         // 余数 r 的个数放在第 r*5 位起的 5 个二进制位
        }
        int total = 0;
        for (int r = 1; r < batchSize; ++r)
            total = (total + r * (int)((state >> (r * 5)) & 31)) % batchSize;
        memo.clear();
        return ans + dfs(state, total, batchSize);
    }
private:
    unordered_map<long long, int> memo;
    int dfs(long long state, int total, int B) {
        if (state == 0) return 0;
        auto it = memo.find(state);
        if (it != memo.end()) return it->second;
        int rest = 0;
        for (int r = 1; r < B; ++r)
            rest = (rest + r * (int)((state >> (r * 5)) & 31)) % B;
        int used = ((total - rest) % B + B) % B;   // 当前前缀余数，由 state 唯一确定
        int happy = (used == 0) ? 1 : 0;           // 余数为 0 → 接下来这组开心
        int res = 0;
        for (int r = 1; r < B; ++r)
            if ((state >> (r * 5)) & 31)
                res = max(res, dfs(state - (1LL << (r * 5)), total, B) + happy);
        memo[state] = res;
        return res;
    }
};
```

### Python

```python
class Solution:
    def maxHappyGroups(self, batchSize: int, groups: list[int]) -> int:
        freq = [0] * batchSize
        ans = 0
        for g in groups:
            r = g % batchSize
            if r == 0:
                ans += 1                        # 余 0 的组任意时刻都开心，贪心先拿满
            else:
                freq[r] += 1
        state = 0
        total = 0
        for r in range(1, batchSize):           # 余数 r 的个数放在第 r*5 位起的 5 个二进制位
            state += freq[r] << (r * 5)
            total = (total + r * freq[r]) % batchSize

        memo = {}

        def dfs(state):
            if state == 0:
                return 0
            if state in memo:
                return memo[state]
            rest = 0
            for r in range(1, batchSize):
                rest = (rest + r * ((state >> (r * 5)) & 31)) % batchSize
            used = (total - rest) % batchSize   # 当前前缀余数，由 state 唯一确定
            happy = 1 if used == 0 else 0       # 余数为 0 → 接下来这组开心
            res = 0
            for r in range(1, batchSize):
                if (state >> (r * 5)) & 31:
                    res = max(res, dfs(state - (1 << (r * 5))) + happy)
            memo[state] = res
            return res

        return ans + dfs(state)
```

> 💡 两份代码通过官方 2 个示例（`4 / 4`），与"穷举全部排列逐一模拟"的暴力在 2500 组随机小规模数据（$n \le 7$、$B \le 6$、人数含 $10^9$ 大数）上对拍（`mismatch = 0`），并在最坏状态规模（$B=9$、30 组均摊 8 种余数，状态数 $5^4 \times 4^4 = 160000$）下实测 Python 0.5s / C++ 0.02s；C++ 与 Python 在 300 组随机输入上交叉一致。

## 8. 边界情况与易错点

1. **$B = 1$**：所有组余数都是 0，答案就是组数；代码中 `state` 保持 0，`dfs(0)` 返回 0，`ans = n` 自动正确。
2. **得分挂错位置**：开心的是"开局余数为 0"的那组，不是"买完后清空"的那组。写成 `happy = ((used + r) % B == 0)` 是最典型的错——那样把收尾组当成了开心组，示例 1 会算出错误答案。
3. **state 必须用 64 位**：最大占用 $8 \times 5 = 40$ 位，C++ 中 `1 << (r * 5)` 在 $r \ge 7$ 时已是移位 35 位，**必须写 `1LL`**，`int` 移位越界是未定义行为。
4. **5 位计数不是随便选的**：$30 < 2^5 = 32$ 恰好封住组数上限；若题面放宽组数，位宽与状态数都要重算。用 `(state >> (r*5)) & 31` 读取时掩码别忘了写成 $2^5 - 1$。
5. **负数取模**：C++ 反推 `used` 时 `total - rest` 可为负，先 `% B` 再 `+ B` 再 `% B`；Python 的 `%` 对负数返回非负，无此坑。
6. **记忆化键只放 state**：这是利用"前缀余数由计数向量唯一确定"的性质；若实现时对 `(state, used)` 二元组做键，虽然也不算错，但状态会被无谓地分裂讨论，而且必须想清楚 used 是否真被 state 决定（本实现里由 state 反推，天然安全）。
7. **余 0 组别忘加**：先统计 `cnt[0]` 直接入答案，再进入 DFS；漏掉的话示例 1（含两个整除组）会输出 2 而非 4。
8. **`groups[i]` 高达 $10^9$**：只参与一次 `g % batchSize`，`int` 足够；不要试图用人数本身做状态。
