# LeetCode 句子相似性 III 题解

## 1. 题目概述

- **标题 / 题号**：句子相似性 III（#1813，medium）
- **链接**：https://leetcode.cn/problems/sentence-similarity-iii/
- **来源**：LeetCode 第 49 场双周赛 Q2
- **难度**：中等
- **标签**：数组、双指针、字符串

**题意**：两个句子 `sentence1`、`sentence2` 由单个空格分隔的单词构成，首尾无多余空格。若可以**往其中一个句子的某个位置插入一个任意句子**（可以是空句子，插入内容须与已有单词用空格隔开）从而得到另一个句子，则称两句子**相似**。判断给定两句子是否相似。

**约束**：

- $1 \le \text{sentence1.length}, \text{sentence2.length} \le 100$
- 两句子只含大小写英文字母和空格，单词都由单个空格分隔

## 2. 示例

**示例 1**

```text
输入：sentence1 = "My name is Haley", sentence2 = "My Haley"
输出：true
解释：往 sentence2 的 "My" 与 "Haley" 之间插入 "name is"，得到 sentence1。
```

**示例 2**

```text
输入：sentence1 = "of", sentence2 = "A lot of words"
输出：false
解释：无法只插入一个句子使其中一个变成另一个。
```

**示例 3**

```text
输入：sentence1 = "Eating right now", sentence2 = "Eating"
输出：true
解释：往 sentence2 结尾插入 "right now"，得到 sentence1。
```

**示例 4（词对齐反例）**

```text
输入：sentence1 = "Frog cool", sentence2 = "Frogs are cool"
输出：false
解释："s are" 不是一个完整的单词序列，插入必须发生在单词边界上。
```

## 3. 解题思路

### 3.1 暴力思路

把插入操作反过来理解：**相似 ⟺ 较短句子的单词序列能由较长句子的单词序列删去一个连续单词块（可为空）得到**。于是暴力做法是枚举被删块的起点 $i$ 与终点 $j$（$0 \le i \le j \le |w_2|$），检查 $w_2[:i] + w_2[j:]$ 是否等于 $w_1$，复杂度 $O(L^3)$（$L$ 为单词数，$|L| \le 50$），能过但完全没有必要——删去**一个连续块**这件事有很强的结构性，可以被两端匹配一次判定。

### 3.2 核心观察：双端匹配——短句 = 长句的前缀 + 后缀

![双端匹配模型：短句由长句的公共前缀和公共后缀拼成](images/bw49_q2_prefix_suffix_model.svg)

设 $w_1$ 是较短的单词序列。若 $w_1$ 能由 $w_2$ 删去一个连续块得到，那么 $w_1$ 必然拆成"**一部分接在 $w_2$ 开头、一部分接在 $w_2$ 结尾**"：

$$w_1 = \underbrace{w_2[0 \dots L)}_{\text{公共前缀}} \;+\; \underbrace{w_2[|w_2|-R \dots |w_2|)}_{\text{公共后缀}}$$

反过来，只要**最长公共前缀**长度 $L$ 与**最长公共后缀**长度 $R$（各自至多 $\min(|w_1|,|w_2|)$）满足

$$L + R \;\ge\; |w_1|,$$

就一定相似：被删掉的块是 $w_2[L \dots |w_2|-R)$ 中的一段（长度恰为 $|w_2|-|w_1|$，且夹在前缀与后缀之间，天然合法）。注意**两边同时匹配**是必须的——只匹配前缀或只匹配后缀都会漏掉"插在句中"的情况（如示例 1）。

### 3.3 算法流程：两端双指针

![算法流程：切分取短、前缀匹配、后缀匹配、判定](images/bw49_q2_match_flow.svg)

```text
1. w1, w2 ← 两句子按空格切分成的单词序列
2. 若 |w1| > |w2|：交换，保证 w1 是较短（或等长）的一方
3. i = 0；while i < |w1| 且 w1[i] == w2[i]：i++      # 最长公共前缀 L
4. j = 0；while j < |w1| 且 w1 末尾第 j 个 == w2 末尾第 j 个：j++   # 最长公共后缀 R
5. 返回 i + j >= |w1|
```

### 3.4 示例演算

| 用例 | $w_1$（短） | $w_2$（长） | $L$ | $R$ | $L+R$ vs $|w_1|$ | 结论 |
|------|-------------|-------------|-----|-----|------------------|------|
| 示例 1 | My Haley | My name is Haley | 1 | 1 | $2 \ge 2$ | true |
| 示例 2 | of | A lot of words | 0 | 0 | $0 < 1$ | false |
| 示例 3 | Eating | Eating right now | 1 | 0 | $1 \ge 1$ | true |
| 示例 4 | Frog cool | Frogs are cool | 0 | 1 | $1 < 2$ | false |

以示例 1 为例：前缀 `My` 匹配上（$L=1$），后缀 `Haley` 匹配上（$R=1$），中间被"删去"的块是 `name is`，恰好是插入的内容；短句 2 个单词全部被两端覆盖，故相似。

## 4. 算法细节

1. **先切分再比较**：相似性是**词级**的概念，必须 `split()` 成单词序列后比较，绝不能在原字符串上直接比较字符——示例 4 中 `"Frog"` 与 `"Frogs"` 前缀只差一个字母，但词级上根本不匹配。
2. **交换保证短方为 $w_1$**：插入是双向的（往任一句插入都可以），统一成"从长删到短"一个方向，判定条件才唯一。
3. **$L$、$R$ 都要封顶在 $|w_1|$**：两个 `while` 的条件里都带 `i < n` / `j < n`，否则等长且相同的两句会把 $L+R$ 数到 $2n$，虽然结论恰好仍对，但语义上"前缀覆盖了整个短句"就该停。
4. **中间块长度自动合法**：当 $L+R \ge |w_1|$ 且 $|w_1| \le |w_2|$ 时，取删除起点 $i^\* = \max(|w_1|-R,\; 0) \le L$，块为 $w_2[i^\* \dots i^\*+|w_2|-|w_1|)$，可以验证其夹在前缀与后缀之间且不越界（详见 §5 引理 2 的证明）。
5. **空插入对应两句相同**：$|w_1|=|w_2|$ 时条件退化为 $w_1 = w_2$（见 §8 第 3 条），与"插入空句子"的语义一致。

## 5. 正确性证明

**引理 1（插入与删块等价）**：两句子相似 ⟺ 把较短单词序列记为 $w_1$、较长的记为 $w_2$ 后，存在 $0 \le i \le j \le |w_2|$ 使得 $w_1 = w_2[0..i) + w_2[j..|w_2|)$。

**证明**："往 $w_1$ 的第 $i$ 个单词前插入句子 $t$" 得到 $w_2$，等价于 $w_2 = w_1[0..i) + t + w_1[i..)$；取 $j = i + |t|$，则 $w_2[0..i) = w_1[0..i)$、$w_2[j..) = w_1[i..)$，即 $w_1 = w_2[0..i) + w_2[j..)$。反向把恒等式改写即得插入方式。空句子对应 $i = j$（空块）。双向插入由"较短方"的选取统一：若原方向是往长句插，等价于从长句里删块得到短句。∎

**引理 2（双端判定）**：记 $L$ 为 $w_1,w_2$ 的最长公共前缀长度（封顶 $|w_1|$），$R$ 为最长公共后缀长度（封顶 $|w_1|$），则引理 1 中的删块存在 ⟺ $L + R \ge |w_1|$。

**证明**：（⇐）设 $L+R \ge |w_1|$，令 $d = |w_2|-|w_1| \ge 0$，取 $i^\* = \max(|w_1|-R,\,0)$。由 $|w_1|-R \le L$ 知 $i^\* \le L$，且 $i^\* \le |w_1| \le |w_2| - d$，故块 $[i^\*,\, i^\*+d)$ 落在 $[0,|w_2|]$ 内。验证 $w_2$ 删去该块后：前 $i^\*$ 个单词与 $w_1$ 前 $i^\*$ 个相同（$i^\* \le L$），后 $|w_1|-i^\*$ 个单词与 $w_1$ 后 $|w_1|-i^\*$ 个相同（因 $|w_1|-i^\* \le R$），两段合计恰覆盖 $w_1$ 的全部 $|w_1|$ 个单词且互不冲突，故相等。
（⇒）若存在删块 $[i, i+d)$，则 $w_1[0..i) = w_2[0..i)$ 说明 $L \ge i$；$w_1[i..) = w_2[i+d..)$ 说明 $w_1$ 的最后 $|w_1|-i$ 个单词与 $w_2$ 的最后 $|w_1|-i$ 个相同，即 $R \ge |w_1|-i$。两式相加得 $L+R \ge |w_1|$。∎

**定理**：算法返回 `true` 当且仅当两句子相似。

**证明**：算法按引理 2 的条件 $L+R \ge |w_1|$ 判定，其中 $L,R$ 由两次线性扫描按定义求出（循环在首个不匹配处停止，保证"最长"）。由引理 1、引理 2 传递即得正确性。∎

## 6. 复杂度分析

- **时间**：$O(|s_1| + |s_2|)$。切分是一次线性扫描；两个双指针合计至多推进 $2|w_1|$ 个单词，每个单词比较是长度成比例的字符比较，总量仍是线性的。
- **空间**：$O(|s_1| + |s_2|)$。存放切分出的单词序列。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool areSentencesSimilar(string sentence1, string sentence2) {
        vector<string> w1 = split(sentence1), w2 = split(sentence2);
        if (w1.size() > w2.size()) swap(w1, w2);          // 保证 w1 是较短一方
        int n = (int)w1.size();
        int i = 0;
        while (i < n && w1[i] == w2[i]) ++i;              // 最长公共前缀 L
        int j = 0;
        while (j < n && w1[n - 1 - j] == w2[(int)w2.size() - 1 - j]) ++j;  // 最长公共后缀 R
        return i + j >= n;
    }
private:
    static vector<string> split(const string& s) {
        vector<string> res;
        string cur;
        for (char c : s) {
            if (c == ' ') {
                if (!cur.empty()) { res.push_back(cur); cur.clear(); }
            } else {
                cur += c;
            }
        }
        if (!cur.empty()) res.push_back(cur);
        return res;
    }
};
```

### Python

```python
class Solution:
    def areSentencesSimilar(self, sentence1: str, sentence2: str) -> bool:
        w1, w2 = sentence1.split(), sentence2.split()
        if len(w1) > len(w2):
            w1, w2 = w2, w1                      # 保证 w1 是较短（或等长）的一方
        n = len(w1)
        i = 0
        while i < n and w1[i] == w2[i]:           # 最长公共前缀
            i += 1
        j = 0
        while j < n and w1[n - 1 - j] == w2[len(w2) - 1 - j]:   # 最长公共后缀
            j += 1
        return i + j >= n
```

> 💡 两份代码通过官方 3 个示例（`true / false / true`），并与"枚举所有连续删块"的暴力实现在 2000 组随机句子上对拍（`mismatch = 0`）；C++ 与 Python 在 300 组随机输入上交叉一致。

## 8. 边界情况与易错点

1. **两句完全相同**：`"My name"` vs `"My name"`，$L = n$，条件成立返回 `true`（插入空句子是允许的）。反过来若题面禁止空插入，等长情形就要改为严格相等以外的判断——本题不涉及。
2. **只在字符层面比较**：示例 4 的 `"Frog cool"` vs `"Frogs are cool"` 在字符前缀上只差一个 `'s'`，容易诱导人写"字符双指针"；正确模型是**单词序列**。
3. **等长但不相同**：如 `a b c` vs `a x c`，$L=1, R=1$，$L+R = 2 < 3$ 判 `false` ✓。可以证明等长时 $L+R \ge n$ 必然推出两串相等（若 $L < n$，由 $L$ 的最大性 $w_1[L] \ne w_2[L]$，而 $R \ge n - L$ 又要求 $w_1[L] = w_2[L]$，矛盾）。
4. **只匹配一端**：只查前缀会漏掉"插在尾部"（示例 3 反过来放），只查后缀会漏掉"插在头部"；两端必须**同时**匹配且允许中间留空。
5. **交换方向**：插入是双向的，忘记把短句换到 $w_1$ 会让"删块长度 $d = |w_2|-|w_1|$"出现负数，逻辑崩坏。
6. **split 的健壮性**：题面保证单词间单个空格、首尾无空格；C++ 手写 `split` 时仍要注意空串过滤，防止末尾单词丢失。
