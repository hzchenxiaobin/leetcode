# LeetCode 统计范围内的好整数 题解

## 1. 题目概述

- **标题 / 题号**：统计范围内的好整数（#3966，hard）
- **链接**：https://leetcode.cn/problems/count-good-integers-in-a-range/
- **来源**：LeetCode 第 185 场双周赛 Q4
- **难度**：困难
- **标签**：数学、动态规划、数位 DP

**题意**：若一个整数**任意一对相邻数位**之间的绝对差都**至多为** $k$，则称它为**好数**。给定 $l, r, k$，返回区间 $[l, r]$ 内好整数的个数。

**约束**：

- $10 \le l \le r \le 10^{15}$
- $0 \le k \le 9$
- 答案需要用 64 位整数保存（$r$ 最大 $10^{15}$，区间长度可达 $10^{15}$ 量级）

## 2. 示例

**示例 1**

```text
输入：l = 10, r = 15, k = 1
输出：3
解释：10 (|1-0|=1)、11 (0)、12 (1) 满足；13 (2)、14 (3)、15 (4) 不满足。
```

**示例 2**

```text
输入：l = 201, r = 204, k = 2
输出：2
解释：201：|2-0|=2, |0-1|=1 ✓；202：2, 2 ✓；
     203：|0-3|=3 ✗；204：4 ✗。
```

**示例 3**

```text
输入：l = 10, r = 10, k = 0
输出：0
解释：|1-0| = 1 > 0，所以 10 不是好数。
```

## 3. 解题思路

### 3.1 暴力思路

逐个数检查：对每个 $x \in [l, r]$ 转成字符串，判断相邻数位差。单次判定 $O(D)$（$D \le 16$），整体 $O\big((r-l)\cdot D\big)$。当 $l = 10$、$r = 10^{15}$ 时是 $10^{16}$ 次判定，完全不可行。

暴力唯一的价值是**确认判定条件本身**没写错：`abs(int(s[i]) - int(s[i+1])) <= k`。真正要换掉的是「逐个枚举」这个框架。

### 3.2 核心观察：前缀差分 + 数位 DP

![数位 DP 的四个状态维度](images/bw185_q4_digitdp.svg)

两个关键点：

1. **区间转前缀**：令 $F(x)$ 表示 $[1, x]$ 中好数的个数，由容斥

$$\text{answer} = F(r) - F(l-1)$$

于是只需解决「统计 $\le x$ 的好数」。

2. **按数位而不是按数值枚举**：好数的约束只发生在**相邻数位**之间，是一个典型的「沿数位从左到右做决策、只需记住上一位」的问题。定义 DP 状态

$$dp(\textit{pos},\ \textit{prev},\ \textit{tight},\ \textit{started})$$

- `pos`：当前填到第几位（从高位起，$0 \le \textit{pos} \le D$）；
- `prev`：上一位填的数字，用 $10$ 表示「还没有上一位」；
- `tight`：前缀是否与 $x$ 的对应前缀完全相等（相等时当前位只能取 $0 \sim s[\textit{pos}]$）；
- `started`：是否已经开始填非零数字（用于跳过前导零）。

转移时枚举当前位 $d$：若 `started` 为真且 $|d - \textit{prev}| > k$ 则剪掉；否则递归到下一位。走到 `pos == D` 时，`started` 为真则贡献 $1$（否则是数字 $0$，本题范围 $l \ge 10$ 不影响结果，但严谨起见不计入）。

### 3.3 算法流程

```text
F(x):
    if x <= 0: return 0
    s = 十进制串(x);  D = len(s)
    memo 初始化为未访问
    dfs(pos, prev, tight, started):
        if pos == D: return started ? 1 : 0
        if 已记忆: return memo
        up = tight ? s[pos] : 9
        res = 0
        for d = 0 .. up:
            nt = tight and (d == up)
            if not started and d == 0:
                res += dfs(pos+1, 10, nt, false)      // 仍是前导零
            else:
                if started and abs(d - prev) > k: continue
                res += dfs(pos+1, d, nt, true)
        memo = res;  return res
    return dfs(0, 10, true, false)

answer = F(r) - F(l-1)
```

### 3.4 示例演算

以示例 1（$l = 10, r = 15, k = 1$）为例：

- $F(15)$：一位数 $1 \sim 9$ 全部合格，共 $9$ 个；两位数中 $10, 11, 12$ 合格，$13, 14, 15$ 不合格。故 $F(15) = 9 + 3 = 12$。
- $F(9) = 9$。
- 答案 $= F(15) - F(9) = 3$，与示例一致。

DP 在 $F(15)$ 上的走位（$D = 2$，第二位受 `tight` 限制最多填 $5$）：

| pos | prev | tight | 可选 d | 说明 |
|-----|------|-------|--------|------|
| 0 | 10 | true | 0,1 | `d=0` 继续前导零；`d=1` 开始 |
| 1（前导零分支）| 10 | false | 0..9 | 得到 $1\sim9$ 共 9 个数 |
| 1（`d=1` 分支）| 1 | true | 0..5 | 保留 $\lvert d-1\rvert \le 1$ 即 $d \in \{0,1,2\}$，共 3 个 |

合计 $12$，与手算吻合。

## 4. 算法细节

1. **`prev` 用 $10$ 表示空**：数组维度开 $11$，这样 `started = false` 时无需特判 `prev` 的合法性。
2. **前导零的处理**：只有 `!started && d == 0` 时保留 `started = false` 且 `prev` 不变，绝不能把前导零当成真实的「上一位 $0$」，否则 $5$ 会被误判成 $05$（差 $|0-5| = 5$）。
3. **`tight` 的传递**：`nt = tight && (d == up)`。注意 `up` 在 `tight = false` 时是 $9$，此时 `d == up` 不代表贴住上界，所以必须写 `tight &&`。
4. **记忆化的键**：`(pos, prev, tight, started)` 四元组；只记忆 `tight = false` 的状态能省一点空间，但本题状态数极小，全记忆更省心。
5. **$x \le 0$ 的短路**：$l \ge 10$ 时 $l - 1 \ge 9$，其实不会触发；但写成通用函数更安全（若 $l = 1$，$F(0)$ 必须返回 $0$）。
6. **`long long` 返回**：$[10, 10^{15}]$ 内好数数量可达 $10^{15}$ 量级（如 $k = 9$ 时全部合格），`int` 必然溢出。

## 5. 正确性证明

**引理 1（数位串与整数一一对应）**：不计前导零时，每个十进制数位串唯一对应一个非负整数；`started` 机制恰好跳过所有前导零，因此 DP 枚举的每个「已完成」数位串与 $[0, x]$ 中的整数一一对应。

**证明**：十进制表示在不计前导零时唯一，这是进制表示的基本性质。DP 中 `started = false` 时只允许继续填 $0$（并保持 `started = false`）或填非零数字（转为 `started = true`）；一旦 `started = true`，后续每一位都进入数位串。故最终被计数的串恰是「首位非零、长度 $1 \sim D$」的串，与 $1 \sim x$ 的整数一一对应；`started = false` 到底的情况对应数字 $0$，被 `started ? 1 : 0` 排除。∎

**引理 2（`tight` 精确刻画上界）**：在状态 `(pos, prev, tight, started)` 下，DP 枚举的补全方案恰好是所有「前 `pos` 位与 $x$ 的前 `pos` 位相同时取值不超过 $x$」的合法补全。

**证明**：对 `pos` 归纳。`pos = 0` 时 `tight = true`，前缀为空自然与 $x$ 相同。设当前状态正确，枚举 $d \le up$：若 `tight = true`，则 `up = s[pos]`，$d \le s[pos]$ 保证新前缀不超过 $x$ 的同长度前缀；`nt = (d == s[pos])` 精确表示「新前缀是否仍与 $x$ 相同」。若 `tight = false`，则 `up = 9`，$d$ 可任意取，且新前缀已严格小于 $x$ 的同长度前缀，`nt` 必为 `false`。两种情况都与定义一致。∎

**引理 3（相邻约束被完整检查）**：DP 计入的方案恰好是「每一对相邻数位差的绝对值 $\le k$」的方案。

**证明**：每次从 `started = true` 的状态填 $d$ 时都检查 $|d - \textit{prev}| \le k$，而 `prev` 恰为真实的前一位数字（引理 1 保证前导零不写入 `prev`）。故所有相邻对都被检查且仅被检查一次。∎

**定理（算法正确）**：`F(x)` 返回 $[1, x]$ 中好数的个数，`goodIntegers` 返回 $[l, r]$ 中好数的个数。

**证明**：由引理 1、2、3，DP 的每个终止路径对应且仅对应一个 $\le x$ 的好数，故 `F(x)` 计数正确。又 $[l, r] = [1, r] \setminus [1, l-1]$，两个区间不相交，故 `F(r) - F(l-1)` 恰为 $[l, r]$ 中好数个数。∎

## 6. 复杂度分析

- **时间**：单次 `F(x)` 的状态数为 $D \times 11 \times 2 \times 2 \le 16 \times 44 = 704$，每个状态枚举至多 $10$ 个数字，故 $O(10 \cdot D \cdot 11 \cdot 4) = O(D)$（常数约 $7000$ 次转移）。两次前缀查询，总计仍是常数级，远小于 $1$ 毫秒。
- **空间**：记忆化表 $O(D \cdot 11 \cdot 4)$，递归深度 $O(D)$，均为常数级。

## 7. 参考代码

### C++

```cpp
#include <cstdlib>
#include <cstring>
#include <functional>
#include <string>
#include <vector>

using namespace std;

class Solution {
public:
    long long goodIntegers(long long l, long long r, int k) {
        return countUpTo(r, k) - countUpTo(l - 1, k);
    }

private:
    // 统计 [1, x] 中「相邻数位绝对差 <= k」的整数个数
    long long countUpTo(long long x, int k) {
        if (x <= 0) {
            return 0;
        }
        string s = to_string(x);
        int n = (int)s.size();
        long long memo[17][11][2][2];
        bool seen[17][11][2][2];
        memset(seen, 0, sizeof(seen));
        function<long long(int, int, bool, bool)> dfs = [&](int pos, int prev, bool tight, bool started) -> long long {
            if (pos == n) {
                return started ? 1 : 0;
            }
            if (seen[pos][prev][tight][started]) {
                return memo[pos][prev][tight][started];
            }
            seen[pos][prev][tight][started] = true;
            int up = tight ? (s[pos] - '0') : 9;
            long long res = 0;
            for (int d = 0; d <= up; d++) {
                bool ntight = tight && (d == up);
                if (!started && d == 0) {
                    res += dfs(pos + 1, 10, ntight, false);  // 前导零，尚未开始
                } else {
                    if (started && abs(d - prev) > k) {
                        continue;
                    }
                    res += dfs(pos + 1, d, ntight, true);
                }
            }
            return memo[pos][prev][tight][started] = res;
        };
        return dfs(0, 10, true, false);
    }
};
```

### Python

```python
from functools import lru_cache

class Solution:
    def goodIntegers(self, l: int, r: int, k: int) -> int:
        return self._countUpTo(r, k) - self._countUpTo(l - 1, k)

    def _countUpTo(self, x: int, k: int) -> int:
        if x <= 0:
            return 0
        s = str(x)
        n = len(s)

        @lru_cache(maxsize=None)
        def dfs(pos: int, prev: int, tight: bool, started: bool) -> int:
            if pos == n:
                return 1 if started else 0
            up = int(s[pos]) if tight else 9
            total = 0
            for d in range(up + 1):
                ntight = tight and d == up
                if not started and d == 0:
                    total += dfs(pos + 1, 10, ntight, False)
                else:
                    if started and abs(d - prev) > k:
                        continue
                    total += dfs(pos + 1, d, ntight, True)
            return total

        return dfs(0, 10, True, False)
```

## 8. 边界情况与易错点

1. **$k = 0$**：只有「所有数位都相同」的数合格（如 $11, 222, 3333$）。注意一位数天然合格。
2. **$k = 9$**：任意相邻差都 $\le 9$，所以区间内**所有**数都是好数，答案应为 $r - l + 1$；可用它作为自检用例。
3. **$l = 10$**：$l - 1 = 9$ 是一位数，$F(9) = 9$，不要漏掉这一段而直接从 $10$ 开始算。
4. **前导零不能写入 `prev`**：否则 $5$ 会按 $05$ 检查 $|0-5| = 5$，在 $k < 5$ 时被错误排除。这是本题最常见的错误来源。
5. **`tight` 更新写错**：若写成 `nt = (d == up)`，在 `tight = false` 时 `up = 9`，填 $9$ 会错误地保持「贴住上界」，导致少算。
6. **`abs(d - prev)` 在 `started = false` 时不能算**：此时 `prev = 10`，$|d - 10|$ 没有意义，必须先判断 `started`。
7. **返回值类型**：`long long` / Python `int`。样例 `l = 10, r = 10^15, k = 9` 的答案是 $999999999999991$，`int` 装不下。
8. **记忆化与 `tight` 的关系**：`tight = true` 的状态同样可以记忆（因为 `x` 固定），不必特意只记 `tight = false`，但若在多次查询间复用记忆表就会出错——每次 `F(x)` 必须重建。

**延伸思考**：本题的 `prev` 只需一位，因为约束只涉及相邻数位。若约束改为「任意两位之差都不超过 $k$」，`prev` 就必须升级为「已用数位的集合」（用位掩码表示），状态数变成 $2^{10}$，与 [2376](https://leetcode.cn/problems/count-special-integers/) 同构；若约束改为「数位和不超过 $S$」，则需把 `prev` 换成「当前数位和」。数位 DP 的通用套路是：**把「需要记住的历史信息」压成状态，把「还没决定的位」交给递归**。
