# LeetCode 任务完成时间 I 题解

## 1. 题目概述

- **标题 / 题号**：任务完成时间 I（#3965，medium）
- **链接**：https://leetcode.cn/problems/finish-time-of-tasks-i/
- **来源**：LeetCode 第 185 场双周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、数组、动态规划

**题意**：有 $n$ 个任务构成一棵以任务 $0$ 为根的树，`edges[i] = [u, v]` 表示 $u$ 是 $v$ 的父任务。每个任务耗时 `baseTime[i]`。

任务 $i$ 的**完成时间** $f(i)$ 递归定义：

- 若 $i$ 是叶子：$f(i) = \textit{baseTime}[i]$；
- 否则令 $\textit{earliest} = \min_{c \in \text{child}(i)} f(c)$、$\textit{latest} = \max_{c \in \text{child}(i)} f(c)$，则

$$f(i) = \textit{latest} + \big[(\textit{latest} - \textit{earliest}) + \textit{baseTime}[i]\big]$$

求根任务 $0$ 的完成时间。

**约束**：

- $1 \le n \le 10^5$，$\textit{edges}$ 长度 $n-1$，保证是一棵合法的以 $0$ 为根的树
- $1 \le \textit{baseTime}[i] \le 10^5$
- 每个任务的完成时间保证小于 $2^{53}$（但仍建议用 `long long`）

## 2. 示例

**示例 1**

```text
输入：n = 3, edges = [[0,1],[1,2]], baseTime = [9,5,3]
输出：17
解释：f(2)=3；f(1)=3+(3-3)+5=8；f(0)=8+(8-8)+9=17。
```

**示例 2**

```text
输入：n = 3, edges = [[0,1],[0,2]], baseTime = [4,7,6]
输出：12
解释：f(1)=7, f(2)=6；earliest=6, latest=7；
     f(0)=7+(7-6)+4=12。
```

**示例 3**

```text
输入：n = 4, edges = [[0,1],[0,2],[2,3]], baseTime = [5,8,2,1]
输出：18
解释：f(3)=1；f(2)=1+0+2=3；f(1)=8；
     f(0)=8+(8-3)+5=18。
```

## 3. 解题思路

### 3.1 暴力思路

按定义直接写递归：

```text
f(u):
    if u 是叶子: return baseTime[u]
    times = [f(c) for c in children[u]]
    earliest, latest = min(times), max(times)
    return latest + (latest - earliest) + baseTime[u]
```

这**已经是最优复杂度**了：每个节点被访问常数次，$O(n)$。但它有两个工程问题：

1. 树是一条 $10^5$ 长链时递归深度达到 $10^5$，Python 默认递归上限 $1000$ 会直接 `RecursionError`，C++ 也可能爆栈；
2. 反复调用 `min/max`、临时列表在 Python 里常数偏大。

所以真正的解法就是**把这段递归改成显式栈的迭代后序遍历**，逻辑一模一样。

### 3.2 核心观察：每个任务只需要两个数

![示例 3 的树与自底向上的完成时间](images/bw185_q3_tree.svg)

观察递推式：

$$f(i) = 2\cdot\textit{latest} - \textit{earliest} + \textit{baseTime}[i]$$

也就是说，父任务**只需要子任务完成时间的最小值与最大值**，完全不需要保存全部子任务的明细。这让「动态规划」的形态非常轻：每个节点只需一个 `long long` 的 $f$ 值。

另一个关键观察是**依赖方向**：$f(u)$ 只依赖子孙，所以只要保证「所有子节点先于父节点被计算」即可。任意一个合法的后序（子树全部处理完再处理根）都满足要求，且不必真的按「左→右」顺序。

### 3.3 算法流程

![算法流程：一次迭代后序遍历](images/bw185_q3_flow.svg)

```text
1. 由 edges 建 children（边已经是父→子的方向，直接 push 即可）
2. 用栈做一次先序遍历，得到 order（根在前）
3. 逆序枚举 order —— 这就是一个合法后序（子节点必然排在父节点之前）
4. 对每个 u：
     叶子  → f[u] = baseTime[u]
     非叶子 → earliest = min f[c], latest = max f[c]
              f[u] = latest + (latest - earliest) + baseTime[u]
5. 返回 f[0]
```

为什么「先序的逆序」一定是合法后序？因为先序中父节点一定出现在其所有子孙之前，逆序后父节点就出现在所有子孙之后，正好满足「子孙先算」。

### 3.4 示例演算

对示例 3（`edges = [[0,1],[0,2],[2,3]]`，`baseTime = [5,8,2,1]`）：

| 处理顺序 | 节点 | 类型 | 子节点完成时间 | earliest / latest | 完成时间 |
|---------|------|------|---------------|-------------------|---------|
| 1 | 3 | 叶子 | — | — | 1 |
| 2 | 2 | 内部 | {1} | 1 / 1 | $1 + 0 + 2 = 3$ |
| 3 | 1 | 叶子 | — | — | 8 |
| 4 | 0 | 内部 | {8, 3} | 3 / 8 | $8 + (8-3) + 5 = 18$ |

答案为 $18$，与示例一致。注意节点 2 的 `ownDuration` 为 $0 + 2 = 2$，而节点 0 的 `ownDuration` 为 $5 + 5 = 10$——**跨度越大，父任务自己的耗时越长**，这是本题的直观含义：等待子任务陆续完成的时间也要计入自己的工期。

## 4. 算法细节

1. **不用建图再 BFS**：边方向已经是父→子，直接 `children[u].push_back(v)`，无需建立双向邻接表，也无需 `visited`。
2. **迭代后序的最省写法**：先序遍历入栈时顺序无所谓（本题不要求子节点顺序），把先序序列整体 `reverse` 后逆序扫描即可；也可以显式模拟「访问标记」，但代码更长。
3. **`long long` 必开**：`baseTime` 最大 $10^5$，链上累加会超过 $2^{31}$（题目保证小于 $2^{53}$ 就是在提示这一点）。
4. **`earliest` / `latest` 初值**：用 `LLONG_MAX` / `LLONG_MIN`，或在进入循环前用第一个子节点初始化，避免对空集合取 `min/max`。
5. **不用额外存储 `earliest`**：`finish` 数组一次算完即可；也可以只保留「子节点 min/max」两个数组，但没必要。
6. **叶子判定**：`children[u].empty()`；$n = 1$ 时根就是叶子。

## 5. 正确性证明

设树的节点集合为 $V$，$\text{child}(u)$ 为 $u$ 的子节点集合。

**引理 1（逆先序是合法后序）**：在先序遍历得到的序列 `order` 中，若 $v$ 是 $u$ 的真子孙，则 $v$ 排在 $u$ 之后；因此逆序扫描时，$v$ 一定先于 $u$ 被处理。

**证明**：先序遍历先访问 $u$，再递归访问 $u$ 的每棵子树；$u$ 的所有真子孙都在这些子树中，故全部排在 $u$ 之后。逆序后先后关系翻转，$v$ 在 $u$ 之前。∎

**引理 2（完成时间唯一）**：对每个节点 $u$，满足题面递推式的 $f(u)$ 唯一存在，且只由 $u$ 的子树决定。

**证明**：对子树高度归纳。叶子由 $f(u) = \textit{baseTime}[u]$ 唯一确定。内部节点的每个子节点 $c$ 的 $f(c)$ 由归纳假设唯一确定，于是 $\textit{earliest}$、$\textit{latest}$ 唯一确定，进而 $f(u) = \textit{latest} + (\textit{latest} - \textit{earliest}) + \textit{baseTime}[u]$ 唯一确定。∎

**定理（算法输出等于定义值）**：算法返回的 `f[0]` 等于按题面定义计算的根任务完成时间。

**证明**：对 $u$ 在树中的深度做归纳，证明算法写入的 `f[u]` 等于定义值 $f_0(u)$。

- 若 $u$ 是叶子：算法执行 `f[u] = baseTime[u]`，与定义一致。
- 若 $u$ 是内部节点：由引理 1，算法在处理 $u$ 之前已经处理完 $u$ 的所有子节点，且写入的 `f[c]` 由归纳假设等于 $f_0(c)$。于是算法计算的 `earliest`、`latest` 正是定义中的 $\min_c f_0(c)$ 与 $\max_c f_0(c)$，从而 `f[u]` 等于 $f_0(u)$。

特别地 $u = 0$ 时成立，故返回值正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建 `children` 一次遍历 $n-1$ 条边；先序遍历每个节点入栈出栈一次；逆序扫描时每个节点把子节点列表遍历一次，所有 `children` 合计长度 $n-1$，总计 $O(n)$。
- **空间**：$O(n)$。`children` 存 $n-1$ 条边、`finish` 存 $n$ 个 `long long`、`order` 与栈各 $O(n)$，均为线性；没有递归栈。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>

using namespace std;

class Solution {
public:
    long long finishTime(int n, vector<vector<int>>& edges, vector<int>& baseTime) {
        vector<vector<int>> children(n);
        for (auto& e : edges) {
            children[e[0]].push_back(e[1]);
        }
        vector<long long> finish(n, 0);
        // 先求一个先序序列，再逆序即为「子节点先于父节点」的合法后序
        vector<int> order;
        order.reserve(n);
        vector<int> stack;
        stack.push_back(0);
        while (!stack.empty()) {
            int u = stack.back();
            stack.pop_back();
            order.push_back(u);
            for (int v : children[u]) {
                stack.push_back(v);
            }
        }
        for (int idx = n - 1; idx >= 0; idx--) {
            int u = order[idx];
            if (children[u].empty()) {
                finish[u] = baseTime[u];
                continue;
            }
            long long earliest = LLONG_MAX, latest = LLONG_MIN;
            for (int v : children[u]) {
                earliest = min(earliest, finish[v]);
                latest = max(latest, finish[v]);
            }
            long long ownDuration = (latest - earliest) + baseTime[u];
            finish[u] = latest + ownDuration;
        }
        return finish[0];
    }
};
```

### Python

```python
from typing import List

class Solution:
    def finishTime(self, n: int, edges: List[List[int]], baseTime: List[int]) -> int:
        children = [[] for _ in range(n)]
        for u, v in edges:
            children[u].append(v)
        finish = [0] * n
        order = []
        stack = [0]
        while stack:
            u = stack.pop()
            order.append(u)
            for v in children[u]:
                stack.append(v)
        for u in reversed(order):
            if not children[u]:
                finish[u] = baseTime[u]
            else:
                times = [finish[v] for v in children[u]]
                earliest, latest = min(times), max(times)
                finish[u] = latest + (latest - earliest) + baseTime[u]
        return finish[0]
```

## 8. 边界情况与易错点

1. **$n = 1$**：根即叶子，返回 `baseTime[0]`。迭代写法天然正确，但若写成「根一定有两个以上子节点」就会错。
2. **一条长链**：必须用迭代（或用 `sys.setrecursionlimit` 的递归），否则 Python 会 `RecursionError`、C++ 可能栈溢出。
3. **溢出**：链长 $10^5$、每层 $10^5$，累计可达 $10^{10}$，`int` 会溢出，必须 `long long`。
4. **`earliest`/`latest` 初值写反**：`earliest` 要用 `LLONG_MAX` 初始化（取 min），`latest` 用 `LLONG_MIN` 初始化（取 max），写反会让所有结果变成极端值。
5. **order 的下标假设**：代码里用 `for idx = n-1 downto 0` 遍历 `order`，依赖「每个节点恰好入列一次」。因为输入保证是一棵树且从 0 可达所有节点，`order.size() == n` 成立；若担心输入异常，可用 `order.size()` 代替 `n`。
6. **把 `ownDuration` 当成 `baseTime`**：还要加上 $\textit{latest} - \textit{earliest}$，这一项正是「等子任务陆续完成」的代价，漏掉会系统性偏小。
7. **子任务顺序无关**：只取 min/max，不要试图按某种顺序累加子任务完成时间（那不是本题定义）。
