# LeetCode 照亮道路的最少灯泡数 题解

## 1. 题目概述

- **标题 / 题号**：照亮道路的最少灯泡数（#3964，medium）
- **链接**：https://leetcode.cn/problems/minimum-lights-to-illuminate-a-road/
- **来源**：LeetCode 第 185 场双周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和、贪心、区间覆盖

**题意**：路上有 $n$ 个位置 $0 \sim n-1$，`lights[i] = v > 0` 表示位置 $i$ 有一盏**已工作**的灯泡，照亮 $[\max(0, i-v),\ \min(n-1, i+v)]$；`lights[i] = 0` 表示没有灯泡。

我们还可以在**任意位置** $j$ 安装**额外灯泡**，它照亮 $[\max(0, j-1),\ \min(n-1, j+1)]$。求让每个位置都「至少被一盏灯照亮」所需安装的**最少额外灯泡数**。

**约束**：

- $1 \le n \le 10^5$
- $0 \le lights[i] \le n$
- 额外灯泡没有数量上限，且可以装在已有灯泡的位置上

## 2. 示例

**示例 1**

```text
输入：lights = [0,0,0,0]
输出：2
解释：在位置 1 装灯照亮 [0,1,2]，在位置 3 装灯照亮 [2,3]，共 2 盏。
```

**示例 2**

```text
输入：lights = [0,0,0,2,0]
输出：1
解释：lights[3]=2 的灯泡照亮 [1,2,3,4]，只差位置 0；
     在位置 1 装一盏，照亮 [0,1,2]，全部可见。
```

**示例 3**

```text
输入：lights = [3]
输出：0
解释：唯一的灯泡亮度 3，覆盖 [max(0,-3), min(0,3)] = [0,0]，本身已照亮全部。
```

## 3. 解题思路

### 3.1 暴力思路

设「额外灯泡落在哪些位置」是一个集合 $S$。一个朴素做法是从小到大枚举 $|S| = 0,1,2,\dots$，对每个 $k$ 检查所有 $\binom{n}{k}$ 种放法是否覆盖全程。当 $n = 10^5$ 时，光是 $|S|$ 就可能达到 $\lceil n/3 \rceil \approx 3.3\times 10^4$，组合数完全爆炸。

即便只考虑「区间覆盖」的标准做法——对每个位置枚举所有能覆盖它的灯——也会退化到 $O(n^2)$。这条路走不通，必须利用本题的**特殊结构**：每盏额外灯泡的覆盖半径恒为 $1$。

### 3.2 核心观察：先标记已有覆盖，再从左往右贪心

![第一步：差分数组标记已有灯泡的照亮区间](images/bw185_q2_cover.svg)

第一步是**把「已有灯泡」和「额外灯泡」解耦**：先用差分数组在 $O(n)$ 时间内求出每个位置是否已被已有灯泡照亮，得到一个布尔数组 `vis`。

第二步是核心观察：

> 设 $i$ 是**最左边**的未被照亮位置。任何能照亮 $i$ 的额外灯泡必须装在 $[i-1, i+1] \cap [0, n-1]$ 内。为了让这盏灯「向右」尽可能多覆盖，应把它的位置取到最右端 $p = \min(i+1, n-1)$。

安装后它覆盖 $[p-1, p+1]$，其中左端已经生效（因为 $i$ 左侧全部已可见，且 $p-1 \le i$），右端最多推进到 $i+2$。于是可以直接把扫描指针跳到 $\min(n-1, p+1) + 1$，一个灯泡的循环开销是 $O(1)$。

![第二步：最左未覆盖点 → 装在 i+1 → 跳过覆盖范围](images/bw185_q2_greedy.svg)

为什么「装在 $i+1$」是安全的？因为**任何装得比 $i+1$ 更靠左的灯泡**，其右端也不超过 $i+2$，覆盖范围被 $i+1$ 处完全包含，替换成 $i+1$ 只会让右端更远或不变，绝不会让已覆盖的位置重新变暗。

### 3.3 算法流程

```text
1. diff[0..n] 全 0
2. for i = 0 .. n-1:
3.     if lights[i] > 0:
4.         l = max(0, i - lights[i]);  r = min(n - 1, i + lights[i])
5.         diff[l] += 1;  diff[r + 1] -= 1
6. cur = 0;  vis[i] = (前缀和 cur > 0)       // 一次扫描
7. ans = 0;  i = 0
8. while i < n:
9.     if vis[i]:  i += 1;  continue
10.    p = min(i + 1, n - 1);  ans += 1
11.    i = min(n - 1, p + 1) + 1              // 跳过新灯泡的覆盖区间
12. return ans
```

### 3.4 示例演算

**示例 1**：`lights = [0,0,0,0]`，没有任何已有灯泡，`vis` 全为假。

| 步骤 | 最左未覆盖 $i$ | 放置位置 $p$ | 新增覆盖 | 跳转到 |
|------|---------------|-------------|---------|--------|
| 1 | 0 | 1 | [0,2] | 3 |
| 2 | 3 | 3 | [2,3] | — |

共 $2$ 盏，与答案一致。

**示例 2**：`lights = [0,0,0,2,0]`。位置 3 的亮度 2 覆盖 $[1,4]$，`vis = [F,T,T,T,T]`。

| 步骤 | 最左未覆盖 $i$ | 放置位置 $p$ | 新增覆盖 | 跳转到 |
|------|---------------|-------------|---------|--------|
| 1 | 0 | 1 | [0,2] | 3 |

此时 $i = 3 \ge n$，答案为 $1$，与示例一致。

## 4. 算法细节

1. **小数组合并到一个差分数组**：`diff[l] += 1, diff[r+1] -= 1`，因为 $r+1$ 可能等于 $n$，数组长度取 $n+1$。
2. **判断「可见」不用开 `bool` 数组也能做**：把 `diff` 原地做成前缀和，`diff[i] > 0` 即可见；多开一个 `vector<char>` 更直观，空间仍是 $O(n)$。
3. **指针跳跃的边界**：$p = n-1$ 时右端被裁到 $n-1$，跳转目标应为 $\min(n-1, p+1)+1 = n$，循环自然结束，不会越界。
4. **`lights[i] = v` 的区间要裁剪**：$i - v$ 可能为负、$i + v$ 可能超过 $n-1$，必须 `max(0, ...)`、`min(n-1, ...)`。
5. **不要真的去「涂色」**：对每盏灯暴力涂色最坏是 $O(n^2)$（例如全路段一盏中心灯、亮度 $n$ 时每个位置都被涂一次，仍是 $O(n^2)$）。
6. **额外灯泡与已有灯泡互不干扰**：题目允许在已有灯泡的位置装灯，也允许新灯覆盖已被照亮的位置，因此贪心只需关心「未覆盖的最左点」。

## 5. 正确性证明

记 $U$ 为当前未被已有灯泡照亮的最左位置，$R(x)$ 表示在位置 $x$ 装灯后照亮的区间 $\{\max(0,x-1), x, \min(n-1,x+1)\}$。

**引理 1（同时覆盖 $U$ 的灯必须落在 $[U-1, U+1]$）**：若某盏灯装在 $x$ 且能照亮 $U$，则 $x \in \{U-1, U, U+1\}$。

**证明**：灯装在 $x$ 时只照亮与 $x$ 距离不超过 $1$ 的位置，$U$ 被照亮即 $|U - x| \le 1$。∎

**引理 2（替换不劣）**：设 $p = \min(U+1, n-1)$。任取 $x \in [U-1, U+1]$ 且 $x \ne p$，则 $R(x) \subseteq R(p)$。

**证明**：分两种情形。

- 若 $U+1 \le n-1$，则 $p = U+1$，即 $x \le U$，于是 $x+1 \le U+1 = p+1$，而 $R(x)$ 的右端为 $\min(n-1, x+1) \le \min(n-1, p+1)$，左端 $x - 1 \le p - 1$。又 $R(p)$ 的左端为 $p-1 = U$，而 $U$ 左侧的位置在本轮开始前已全部可见（$U$ 是最左未覆盖点），故把左端截到 $U$ 不损失任何「新覆盖」。
- 若 $U+1 > n-1$，即 $U = n-1$，则 $p = n-1$，此时唯一能覆盖 $U$ 的可行位置就是 $n-1$ 本身（$n-1+1$ 越界），$x = p$，集合相等。

两种情形下用 $p$ 替换 $x$ 都不会让已覆盖集合变小。∎

**定理（贪心最优）**：设 $G$ 为贪心算法安装的额外灯泡数，$O^{*}$ 为任意可行方案的最小灯泡数，则 $G = O^{*}$。

**证明**：对贪心轮数归纳。设第 $k$ 轮（$k = 1,2,\dots$）处理的最左未覆盖点为 $U_k$。由引理 1，任何可行方案都必须有一盏灯装在 $U_k$ 附近（$[U_k-1, U_k+1]$ 内）才能照亮它；由引理 2，把这盏灯换成 $p_k = \min(U_k+1, n-1)$ 不会减少覆盖。故存在一个最优方案，其第 $1$ 盏灯恰好装在 $p_1$，且安装后剩余待覆盖位置恰是贪心第 2 轮开始时的状态；对该状态重复上述论证，可逐个把最优方案的灯对齐到 $p_1, p_2, \dots$。若最优方案灯数少于 $G$，则对齐到第 $G$ 轮时它已无灯可用，但 $U_G$ 仍未被覆盖，矛盾。因此 $O^{*} \ge G$；又贪心过程中每轮都让被覆盖集合严格增大且最终覆盖全程，其本身可行，故 $G \le O^{*}$。综上 $G = O^{*}$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。差分打标记 $O(n)$，前缀和扫描 $O(n)$；贪心循环中 `i` 严格递增且每次跳过至少 $1$ 个位置，至多执行 $n$ 轮，每轮 $O(1)$。合计 $O(n)$。
- **空间**：$O(n)$。一个长度 $n+1$ 的差分数组、一个长度 $n$ 的可见标记（可复用 `diff` 原地做成前缀和，做到 $O(n)$ 且常数极小）。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>

using namespace std;

class Solution {
public:
    int minLights(vector<int>& lights) {
        int n = (int)lights.size();
        vector<int> diff(n + 1, 0);
        for (int i = 0; i < n; i++) {
            if (lights[i] > 0) {
                int l = max(0, i - lights[i]);
                int r = min(n - 1, i + lights[i]);
                diff[l] += 1;
                diff[r + 1] -= 1;
            }
        }
        vector<char> vis(n, 0);
        int cur = 0;
        for (int i = 0; i < n; i++) {
            cur += diff[i];
            vis[i] = (cur > 0);
        }
        int ans = 0;
        int i = 0;
        while (i < n) {
            if (vis[i]) {
                i++;
                continue;
            }
            int p = min(i + 1, n - 1);  // 在 i 的最右侧可覆盖位置放新灯泡
            ans++;
            i = min(n - 1, p + 1) + 1;  // 新灯泡覆盖 [p-1, p+1]，整体跳过
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def minLights(self, lights: List[int]) -> int:
        n = len(lights)
        diff = [0] * (n + 1)
        for i, v in enumerate(lights):
            if v > 0:
                l = max(0, i - v)
                r = min(n - 1, i + v)
                diff[l] += 1
                diff[r + 1] -= 1
        vis = [False] * n
        cur = 0
        for i in range(n):
            cur += diff[i]
            vis[i] = cur > 0
        ans = 0
        i = 0
        while i < n:
            if vis[i]:
                i += 1
                continue
            p = min(i + 1, n - 1)
            ans += 1
            i = min(n - 1, p + 1) + 1
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一位置。若 `lights[0] > 0` 则答案 $0$，否则在位置 $0$ 装一盏，答案 $1$。$p = \min(1, 0) = 0$，跳转到 $\min(0, 1) + 1 = 1$，逻辑自洽。
2. **已有灯泡的区间越界**：$i - v$ 可能为负、$i + v$ 可能超过 $n-1$，不裁剪会访问非法下标。
3. **差分数组长度**：`r + 1` 最大取到 $n$，数组至少要 $n+1$ 长，否则最后一个 `-= 1` 越界（在 C++ 中是未定义行为）。
4. **全路段已被照亮**：贪心循环只做 `i++`，返回 $0$，不要漏掉这个分支。
5. **亮度 $v = 0$**：表示无灯泡，必须用 `lights[i] > 0` 判断，不能用「非零」以外的含义；若写成 `>= 0` 会把无灯位置当作覆盖 $[i,i]$。
6. **误以为新灯必须装在最左未覆盖点上**：装在最左点只能向右延伸 $1$ 格，而装在 $i+1$ 能延伸到 $i+2$，贪心务必取 $i+1$。
7. **把额外灯泡数量当 $n/3$ 直接算**：已有灯泡造成的「整段覆盖」会显著减少答案，必须按实际未覆盖段贪心。
