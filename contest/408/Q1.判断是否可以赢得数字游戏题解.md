# LeetCode 判断是否可以赢得数字游戏 题解

## 1. 题目概述

- **标题 / 题号**：判断是否可以赢得数字游戏（#3232，easy）
- **链接**：https://leetcode.cn/problems/find-if-digit-game-can-be-won/
- **来源**：LeetCode 第 408 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学、脑筋急转弯

**题意**：给定一个正整数数组 `nums`。Alice 和 Bob 玩游戏：Alice 可以选择 `nums` 中**所有个位数**或**所有两位数**，剩余数字全部归 Bob。若 Alice 所选数字之和**严格大于** Bob 的数字之和，Alice 获胜。判断 Alice 能否赢得游戏。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 99$

> 💡 **审题关键**：三个要点决定本题难度。(1) Alice 的选项只有**两个**——「全拿个位数」或「全拿两位数」，不能只挑其中一部分；(2) 值域 $[1, 99]$ 保证每个数**非个位即两位**，不存在第三类；(3) Bob 全程**没有任何决策**，只是被动接盘。这不是博弈题，是披着博弈外衣的**求和判定题**——签到题的切入速度就体现在识破外壳的快慢上。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,10]
输出：false
解释：Alice 不管选个位数还是两位数都无法赢得比赛。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5,14]
输出：true
解释：Alice 选择个位数可以赢得比赛，所选数字之和为 15。
```

**示例 3**

```text
输入：nums = [5,5,5,25]
输出：true
解释：Alice 选择两位数可以赢得比赛，所选数字之和为 25。
```

**补充示例（覆盖「某一类为空」的边界）**

```text
输入：nums = [8,2]
输出：true
解释：数组中没有两位数，s₂ = 0；Alice 选个位数，8 + 2 = 10 > 0。
```

## 3. 解题思路

### 3.1 暴力思路：老老实实模拟两种选择

最直接的做法是把 Alice 仅有的两个选项逐一模拟：先求「个位数之和 $s_1$」与「两位数之和 $s_2$」，再分别核对——选个位数时 Alice 得 $s_1$、Bob 得 $s_2$，胜当且仅当 $s_1 > s_2$；选两位数时对称，胜当且仅当 $s_2 > s_1$。两个条件取「或」即为答案。

这个做法已经是 $O(n)$，复杂度上无可指摘——签到题不必优化复杂度，但仍有两个**冗余**值得消除：Bob 的和根本不用单独算（两类互补，Bob 的和就是另一桶）；两个胜负条件其实是同一个比较的镜像。消除冗余后代码只剩一行判据，比赛中读题到提交可以压到一分钟内。

### 3.2 核心观察：两类互补，胜负塌缩为 $s_1 \ne s_2$

![核心观察：两个选择互为镜像，胜负塌缩为 s₁ ≠ s₂](images/wc408_q1_two_choices_insight.svg)

三个环环相扣的观察：

- **观察 1（分桶唯一且完备）**：由 $1 \le nums[i] \le 99$，每个数要么是个位数（$1 \sim 9$）要么是两位数（$10 \sim 99$），两桶**不重不漏**。于是每桶的和是**确定的**，与 Alice 怎么选无关。
- **观察 2（两种选择互为镜像）**：Alice 选个位桶，Bob 拿两位桶；Alice 选两位桶，Bob 拿个位桶。Alice 两种可能的得分恰好是 $s_1$ 与 $s_2$ 各取一次，Bob 永远接盘另一桶。
- **观察 3（两个条件合一）**：Alice 获胜 $\iff s_1 > s_2$ **或** $s_2 > s_1$。两个不等式方向相反、不能同时成立，合起来恰是**一个**判据：

$$\text{Alice 获胜} \iff s_1 \ne s_2$$

两桶和不相等时，较大的那桶必然存在，Alice 选它、把较小的桶甩给 Bob 即稳赢；两桶和相等时，无论怎么选双方都打平，「严格大于」不成立，Alice 必输。**false 的唯一来源是 $s_1 = s_2$**——示例 1 正是这个陷阱：$1+2+3+4 = 10$，恰好与两位数 $10$ 打平。

> ⚠️ 顺带一提：如果把规则的「严格大于」改成「大于等于」，两个数中必有一个不小于另一个，答案将**恒为 true**。比较条件里的一个词决定了整题的输出空间。

### 3.3 算法流程：一趟分桶累加

![算法流程：一趟遍历、两个累加器、一次比较](images/wc408_q1_one_pass_flow.svg)

1. 初始化两个累加器 `single = 0`、`dbl = 0`；
2. 遍历 `nums`：`x < 10` 则 `single += x`，否则 `dbl += x`；
3. 返回 `single != dbl`。

分界线 `x < 10` 一条比较搞定：$9$ 是最大个位数、$10$ 是最小两位数。值域下界 $1$ 使我们无需讨论 $0$（即便允许 $0$，它也归个位数且贡献为 $0$，结论不变）。

### 3.4 示例演算

![示例演算：分桶、求和、比较，三个样例一图看尽](images/wc408_q1_example_walkthrough.svg)

以示例 2 `nums = [1,2,3,4,5,14]` 为例，走一遍累加过程：

| $x$ | 位数 | `single` | `dbl` |
|:---:|:---:|:---:|:---:|
| 1 | 个位 | 1 | 0 |
| 2 | 个位 | 3 | 0 |
| 3 | 个位 | 6 | 0 |
| 4 | 个位 | 10 | 0 |
| 5 | 个位 | 15 | 0 |
| 14 | 两位 | 15 | 14 |

最终 `single = 15 ≠ dbl = 14` → `true`，Alice 选个位数。三个示例全景对账：

| 输入 | $s_1$ | $s_2$ | 关系 | 输出 | Alice 的选择 |
|------|:---:|:---:|:---:|:---:|--------------|
| `[1,2,3,4,10]` | 10 | 10 | 相等 | `false` | 两种选择都平手，「严格大于」不成立 |
| `[1,2,3,4,5,14]` | 15 | 14 | $15 > 14$ | `true` | 拿个位桶，Bob 只剩 14 |
| `[5,5,5,25]` | 15 | 25 | $25 > 15$ | `true` | 反手拿两位桶，Bob 只剩 15 |

示例 3 最值得回味：个位桶元素个数占优（3 个 vs 1 个），却**输在和值**上——桶的胜负只看**和**，与元素个数无关。

## 4. 算法细节

1. **分类判据 `x < 10`**：`10` 是两位数，误写 `x <= 10` 会把 10 划进个位桶——示例 1 会从 `false` 错成 `true`，恰好被官方样例抓住。
2. **两个累加器足够**：无需数组、无需排序、无需哈希。更省的写法是只维护 `single` 与 `total`，返回 $2 \cdot single \ne total$（利用 $single + dbl = total$）——少一个变量，但两桶写法语义更直白，签到题优先可读性。
3. **和的量级**：$n \le 100$、$nums[i] \le 99$，总和 $\le 9900$，`int` 绰绰有余，无溢出之虞。
4. **别引入不存在的复杂度**：不需要排序（和与顺序无关）、不需要去重、不需要博弈 DP（Bob 无决策）。签到题的最短路径就是「分桶 → 求和 → 比较」，多写任何一行都是在给罚时加码。

## 5. 正确性证明

**引理 1（划分完备且不交）**：数组 `nums` 按位数分成个位数集合 $S_1 = \{x : 1 \le x \le 9\}$ 与两位数集合 $S_2 = \{x : 10 \le x \le 99\}$，则 $S_1 \cup S_2$ 覆盖全部元素且 $S_1 \cap S_2 = \varnothing$。

**证明**：$S_1 \cup S_2 = [1, 99]$ 恰为值域约束的全体；$[1,9]$ 与 $[10,99]$ 是相邻且不交的整数区间。故每个元素恰属一类。∎

**引理 2（两种选择的得分）**：记 $s_1 = \sum_{x \in S_1} x$，$s_2 = \sum_{x \in S_2} x$。若 Alice 选个位数，则 Alice 得 $s_1$、Bob 得 $s_2$；若 Alice 选两位数，则 Alice 得 $s_2$、Bob 得 $s_1$。

**证明**：Alice 的选择只能是整桶取走，由引理 1 两桶覆盖全部元素，「剩余的数字」即另一桶的全体，其和为另一侧。∎

**定理**：Alice 有获胜策略 $\iff s_1 \ne s_2$。

**证明**：Alice 有获胜策略 $\iff$（选个位数获胜）$\lor$（选两位数获胜）$\iff s_1 > s_2 \lor s_2 > s_1$（引理 2）。对整数 $s_1, s_2$，三分律给出 $s_1 > s_2$、$s_1 = s_2$、$s_1 < s_2$ 三者恰居其一：前两种情形分别使两个析取支为真，析取为真；第三种情形（$s_1 = s_2$）使两支均为假，析取为假。故 Alice 有获胜策略 $\iff s_1 > s_2 \lor s_2 > s_1 \iff s_1 \ne s_2$。∎

**推论**：`false` 当且仅当 $s_1 = s_2$；若规则改为「大于等于」，则答案恒为 `true`（两个析取支必有其一成立）。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟遍历，每个元素一次比较一次加法，最后一次判等。相对「模拟两种选择」的朴素写法，省掉的不是渐进量级，而是把两次条件核对压缩成一次比较——签到题拼的是代码最短、出错面最小。
- **空间复杂度**：$O(1)$。仅两个整型累加器（或 `single + total` 一个半）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool canAliceWin(vector<int>& nums) {
        int single = 0, dbl = 0;
        for (int x : nums) {
            if (x < 10) single += x;   // 9 是最大个位数
            else        dbl   += x;   // 10 是最小两位数
        }
        return single != dbl;          // 平局即失败，判据是「不等于」
    }
};
```

### Python

```python
class Solution:
    def canAliceWin(self, nums: List[int]) -> bool:
        single = dbl = 0
        for x in nums:
            if x < 10:
                single += x          # 9 是最大个位数
            else:
                dbl += x             # 10 是最小两位数
        return single != dbl         # 平局即失败，判据是「不等于」
```

## 8. 边界情况与易错点

1. **平局判负**：判据是「严格大于」，$s_1 = s_2$ 时返回 `false`。示例 1 正是此坑（$1+2+3+4 = 10$ 恰与两位数 $10$ 打平）；误写 `>=` 会把平局误判为胜。
2. **分界线 `x < 10`**：`10` 归两位数，误写 `x <= 10` 会改变示例 1 的答案，提交前用样例 1 自测可直接抓出。
3. **某一类为空**：如 `[8, 2]`（无两位数，$s_2 = 0$）或 `[42]`（无个位数）。此时另一桶和 $\ge 1 > 0$ 必胜；空桶以 $0$ 参与比较，代码无需特判。
4. **$n = 1$**：单个元素归哪类，Alice 就选哪类，$x \ge 1 > 0$ 必胜，返回 `true`。
5. **别脑补成「任选子集」或博弈 DP**：把题面里「所有」两个字圈出来——Alice 只有两种**整类**选法，Bob 无决策。签到题的罚时差距往往就在敢不敢直接写最短代码。
6. **别单独算 Bob 的和**：两类互补，Bob 的和就是另一桶，无需第三个变量，更无需二次遍历。
7. **返回值语义**：题目问「Alice 能否赢」，即「**存在一种**选择获胜」——是析取，不是「两种都赢」。
