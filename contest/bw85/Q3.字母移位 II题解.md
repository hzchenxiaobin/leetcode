# LeetCode 字母移位 II 题解

## 1. 题目概述

- **标题 / 题号**：字母移位 II（#2381，medium）
- **链接**：https://leetcode.cn/problems/shifting-letters-ii/
- **来源**：LeetCode 第 85 场双周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、前缀和

**题意**：给定小写字母串 $s$ 与操作数组 `shifts[i] = [start_i, end_i, direction_i]`。每个操作把闭区间 $[\text{start}_i, \text{end}_i]$ 内所有字符整体移位：`direction = 1` 向后（字母表下一个，`z` 绕回 `a`），`direction = 0` 向前（`a` 绕回 `z`）。返回所有操作依次执行后的最终串。

**约束**：

- $1 \le s.length,\ shifts.length \le 5 \times 10^4$
- `shifts[i].length == 3`，$0 \le \text{start}_i \le \text{end}_i < s.length$
- $0 \le \text{direction}_i \le 1$
- $s$ 只含小写字母

## 2. 示例

**示例 1**

```text
输入：s = "abc", shifts = [[0,1,0],[1,2,1],[0,2,1]]
输出："ace"
解释：[0,1] 前移 → "zac"；[1,2] 后移 → "zbd"；[0,2] 后移 → "ace"。
```

**示例 2**

```text
输入：s = "dztz", shifts = [[0,0,0],[1,1,1]]
输出："catz"
解释：下标 0 前移 → "cztz"；下标 1 后移 → "catz"。
```

**边界补充**

```text
输入：s = "z", shifts = [[0,0,1]]   输出："a"   # z 向后绕回 a
输入：s = "a", shifts = [[0,0,0]]   输出："z"   # a 向前绕回 z
输入：s = "abcd", shifts = [[0,3,1],[0,3,0],[0,3,1]]
输出："bcde"                          # 净位移 +1+(-1)+1 = +1
输入：s = "zzzz", shifts = [[0,3,1],[0,3,1],[0,3,0],[0,3,0]]
输出："zzzz"                          # 净位移 0
```

## 3. 解题思路

### 3.1 暴力思路

对每个操作，遍历 $[\text{start}, \text{end}]$ 逐字符移位：$O(mn)$，$m, n \le 5\times10^4$ 时最坏 $2.5 \times 10^9$ 次字符运算，必然超时。瓶颈在于：**区间整体移动相同偏移量**这一结构被完全忽略，同一个字符被反复"就地"搬运 $m$ 次。

### 3.2 核心观察：位移可加，先攒后算——差分数组

![差分模型：每个操作只在两端打标记，一次前缀和还原每个位置的净位移](images/bw85_q3_diff_model.svg)

移位运算是**可加**的：一个字符先 $+3$ 再 $-5$ 等价于净移 $-2$（模 26）。于是不必逐操作搬运字符，只需统计每个下标的**净位移** $\delta_i$，最后统一应用：

$$\text{res}_i = \texttt{'}a\texttt{'} + \big((s_i - \texttt{'}a\texttt{'} + \delta_i) \bmod 26\big)$$

净位移是"若干区间各 ±1 叠加"的结果——这正是**差分数组**的标准场景。对区间 $[l, r]$ 加 $d$：

```text
diff[l] += d;  diff[r+1] -= d;
```

$m$ 个操作只打 $2m$ 个标记；随后一遍前缀和把 `diff` 还原成每位的 $\delta_i$。总代价 $O(n + m)$，区间长度不再影响复杂度。

### 3.3 算法流程

```text
1. diff = [0] * (n + 1)
2. for (l, r, dir) in shifts:
       d = dir == 1 ? +1 : -1
       diff[l] += d;  diff[r+1] -= d        # 区间加 d 的差分标记
3. cur = 0; res = []
   for i in 0..n-1:
       cur += diff[i]                        # cur 即 δ_i
       res.append('a' + (s[i]-'a'+cur) mod 26)
4. 返回 res
```

### 3.4 示例演算

![示例演算：abc 三段操作的差分标记与前缀和还原](images/bw85_q3_example_walkthrough.svg)

以示例 1（$s = \texttt{abc}$）为例，三个操作 $[0,1,-1]$、$[1,2,+1]$、$[0,2,+1]$ 打标记后：

| 下标 $i$ | 0 | 1 | 2 | 3（哨兵） |
|---|---|---|---|---|
| diff | $-1 + 1 = 0$ | $+1 + 1 = 2$ | $+1$ | $-1 - 1 = -2$ |
| 前缀和 $\delta_i$ | $0$ | $2$ | $3$ | — |

应用：$\texttt{a} + 0 = \texttt{a}$，$\texttt{b} + 2 = \texttt{d}$？——不对，注意第三个操作是 $[0, 2]$ **含下标 0**，diff$[0]$ 应为 $-1 + 1 = 0$、diff$[3]$ 为 $-1 - 1 - 1$？让我们逐个操作重算（**这正说明差分标记要逐操作打，不能口算合并时想当然**）：

- 操作 1 $[0,1,-1]$：diff$[0] -= 1$，diff$[2] += 1$
- 操作 2 $[1,2,+1]$：diff$[1] += 1$，diff$[3] -= 1$
- 操作 3 $[0,2,+1]$：diff$[0] += 1$，diff$[3] -= 1$

汇总：diff $= [0, 1, 1, -2]$，前缀和 $\delta = [0, 1, 2, 0]$。应用：$\texttt{a}\!\to\!\texttt{a}$、$\texttt{b}\!\to\!\texttt{c}$、$\texttt{c}\!\to\!\texttt{e}$，得 `"ace"`，与官方一致。

## 4. 算法细节

1. **方向映射**：`direction = 1` → $+1$，`direction = 0` → $-1$。与直觉的"0/1 = 前/后"对应关系别接反（题目定义 0 是向前、1 是向后）。
2. **哨兵位 `diff[n]`**：区间右端点可能取 $n-1$，`r+1 = n` 越出串长，差分数组必须开 $n + 1$ 长。
3. **模运算统一处理负数**：净位移 $\delta_i \in [-m, m]$ 可正可负。C++ 中 `(x % 26 + 26) % 26` 双重取模把负余数折回 $[0, 26)$；Python 的 `%` 天然返回非负，`% 26` 一步到位。也可全程把 $-1$ 写作 $+25$（模 26 同余），彻底避开负数。
4. **位移规模**：$|\delta_i| \le m \le 5\times10^4$，`int` 足够；但若把它与字符码直接相加再取模，注意 C++ 负数取模的截断行为（上一点已处理）。
5. **为什么可以"先攒后算"**：字符集是**循环群** $\mathbb{Z}_{26}$，移位是群上的加法，加法交换结合，与操作顺序无关——这是本题能用差分的前提。若操作是"替换为指定字符"这类不可交换运算，就必须按序模拟。
6. **返回新串而非原地修改**：$O(n)$ 构造新串即可；原地修改也可（先算完所有 $\delta$ 再统一改），但边扫 diff 边改 $s$ 会破坏尚未处理的字符信息吗？不会——$s[i]$ 只在第 $i$ 轮被读一次，读后即改，安全。

## 5. 正确性证明

**引理 1（移位的可加性）**：设 $\sigma_d(c)$ 表示把字符 $c$ 移位 $d$（$d \in \mathbb{Z}$，正为向后）的结果，则对任意 $c$ 与 $d_1, d_2$：$\sigma_{d_1}(\sigma_{d_2}(c)) = \sigma_{d_1 + d_2}(c)$。

**证明**：把字符编码为 $\mathbb{Z}_{26}$ 中的元素 $x = c - \texttt{a}$。一次移位即 $x \mapsto (x + d) \bmod 26$，这是 $\mathbb{Z}_{26}$ 上的平移映射。两次复合：$(x + d_2 + d_1) \bmod 26 = (x + (d_1 + d_2)) \bmod 26$，由模加法结合律成立。∎

**引理 2（差分还原）**：设 `diff` 初始为零，对每个操作 $[l_j, r_j, d_j]$ 执行 `diff[l_j] += d_j; diff[r_j+1] -= d_j`，则前缀和 $\delta_i = \sum_{t \le i} \text{diff}[t]$ 满足 $\delta_i = \sum_{j:\ l_j \le i \le r_j} d_j$，即恰好是覆盖下标 $i$ 的所有操作位移之和。

**证明**：对每个操作 $j$ 单独考察其对 $\delta_i$ 的贡献：它使所有 $i \ge l_j$ 的前缀和加上 $d_j$，又使所有 $i \ge r_j + 1$ 的前缀和减回 $d_j$，净效果恰为"在 $[l_j, r_j]$ 内贡献 $d_j$，区间外贡献 0"。前缀和是线性的，各操作贡献相加即得结论。∎

**定理**：算法输出的串等于按题意依次执行全部移位后的串。

**证明**：由引理 1 归纳，依次执行操作序列等价于对每个下标 $i$ 一次性施加总位移 $D_i = \sum_{j:\ l_j \le i \le r_j} d_j$（顺序无关）。由引理 2，算法中前缀和算出的 $\delta_i = D_i$；最后一步 $(s_i - \texttt{a} + \delta_i) \bmod 26$ 即施加总位移（引理 1 的 $d$ 取 $\delta_i$），故每个字符与逐操作模拟的结果一致。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。打标记 $2m$ 次 $O(m)$；前缀和与应用各扫一遍 $O(n)$。相比暴力的 $O(nm)$（最坏 $2.5 \times 10^9$），快了近五个数量级。
- **空间**：$O(n)$。差分数组 $n + 1$ 个整数与结果串；不计输出则差分数组为 $O(n)$ 额外空间（Python 需要显式构建，C++ 可复用结果缓冲）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string shiftingLetters(string s, vector<vector<int>>& shifts) {
        int n = s.size();
        vector<long long> diff(n + 1, 0);
        for (auto& sh : shifts) {
            int d = sh[2] == 1 ? 1 : -1;     // 1 → 向后 +1，0 → 向前 −1
            diff[sh[0]] += d;
            diff[sh[1] + 1] -= d;            // 哨兵：右端 +1 可能等于 n
        }
        string res;
        res.reserve(n);
        long long cur = 0;
        for (int i = 0; i < n; ++i) {
            cur += diff[i];                  // cur = 覆盖 i 的净位移 δ_i
            long long v = (s[i] - 'a' + cur % 26 + 26) % 26;
            res.push_back('a' + v);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def shiftingLetters(self, s: str, shifts: list[list[int]]) -> str:
        n = len(s)
        diff = [0] * (n + 1)
        for start, end, d in shifts:
            delta = 1 if d == 1 else -1
            diff[start] += delta
            diff[end + 1] -= delta           # 哨兵：右端 +1 可能等于 n
        res = []
        cur = 0
        for i, ch in enumerate(s):
            cur += diff[i]                   # cur = 覆盖 i 的净位移 δ_i
            res.append(chr((ord(ch) - 97 + cur) % 26 + 97))
        return ''.join(res)
```

> 💡 两份代码均通过官方 2 个示例与 4 个手算边界（z/a 环绕、净位移 $\pm1$ 与 0），并与逐操作暴力对拍：C++ 2 万组、Python 5 千组随机（$n \le 60$、$m \le 40$），`mismatch = 0`；另通过 $n = m = 5 \times 10^4$ 大规模性能与跨语言一致性校验（首 1000 字符与字符码总和逐位一致）。

## 8. 边界情况与易错点

1. **哨兵越界**：`end = n - 1` 时 `diff[n]` 被写，数组长度必须是 $n + 1$；开成长度 $n$ 是最经典的越界事故。
2. **方向 0/1 的语义**：题目定义 `direction = 0` 向**前**（减 1）、`1` 向**后**（加 1）。写成 `d == 0 ? 1 : -1` 全盘皆错。
3. **C++ 负数取模**：`(-3) % 26 == -3` 而非 23，必须 `(x % 26 + 26) % 26` 双重取模；或把 $-1$ 直接记为 $+25$。
4. **环绕双向都要测**：`z` 向后应得 `a`，`a` 向前应得 `z`；只测一个方向容易漏掉取模符号 bug。
5. **区间是闭区间**：$[\text{start}, \text{end}]$ 两端都含，差分标记是 `diff[l] += d, diff[r+1] -= d`；把 `r+1` 写成 `r` 会把右端点多算一次。
6. **m 可以为 0 吗**：约束 $m \ge 1$，但代码天然兼容空操作集（返回原串），无需特判。
7. **别在打标记阶段就取模**：`diff` 累加到 $\pm 5 \times 10^4$ 远未溢出，前缀和同理；提前取模虽不影响正确性（模加法封闭）但毫无必要，徒增心智负担。

**延伸思考**：本题的本质是「**循环群上的区间加法**」：字符集 $\mathbb{Z}_{26}$ + 平移运算构成交换群，因此 $m$ 个区间操作可以**任意重排、合并、抵消**，差分只是把这种自由度压缩成 $O(n + m)$ 的实现。沿着这条线：若移位量不是 $\pm 1$ 而是任意 $d_j$，差分标记改为 `±d_j` 即可，完全同构；若字符集不循环（移出边界报错），可加性在边界处断裂，必须按序模拟；若查询是"某时刻某位置的字符"（在线问题），则要上**树状数组/线段树**（单点查询 + 区间加），把"离线攒齐再算"换成"在线维护"。差分、前缀和、树状数组由此构成同一件事的三档实现强度。
