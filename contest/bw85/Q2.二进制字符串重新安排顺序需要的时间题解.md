# LeetCode 二进制字符串重新安排顺序需要的时间 题解

## 1. 题目概述

- **标题 / 题号**：二进制字符串重新安排顺序需要的时间（#2380，medium）
- **链接**：https://leetcode.cn/problems/time-needed-to-rearrange-a-binary-string/
- **来源**：LeetCode 第 85 场双周赛 Q2
- **难度**：中等
- **标签**：字符串、动态规划、模拟

**题意**：给定二进制字符串 $s$。每一秒，**所有**子串 `"01"` **同时**被替换成 `"10"`（即每个 1 与紧邻其左的 0 交换，且同一秒内每个字符至多参与一次交换）。过程持续到串中不再出现 `"01"`。求总秒数。

**约束**：

- $1 \le s.length \le 1000$
- $s[i]$ 为 `'0'` 或 `'1'`

**进阶**：能否 $O(n)$ 解决？

## 2. 示例

**示例 1**

```text
输入：s = "0110101"
输出：4
解释：0110101 → 1011010 → 1101100 → 1110100 → 1111000，共 4 秒。
```

**示例 2**

```text
输入：s = "11100"
输出：0
解释：不含 "01"，0 秒。
```

**边界补充**（均已用逐秒模拟器核实）

```text
输入：s = "01"      输出：1   # 一个 1 越过一个 0
输入：s = "00111"   输出：4   # 最左的 1 要穿过 2 个 0，但它被后面的 1 "排队"阻塞
输入：s = "0101"    输出：2
输入：s = "11011"   输出：2   # 中间的 1 要越过中间的 0：z=1，f=2
输入：s = "0110001" 输出：4
```

## 3. 解题思路

### 3.1 暴力思路

直接逐秒模拟：每秒从左到右扫描，把所有不重叠的 `"01"` 同时换成 `"10"`，直到没有 `"01"`。单轮 $O(n)$；最坏情形（如 `"000...01"` 形如全 0 后跟一个 1）需要 $n - 1$ 秒，总计 $O(n^2)$。$n = 1000$ 时约 $10^6$ 次字符操作，能过，但题面进阶要求 $O(n)$——模拟没有利用"每个 1 独立向左沉降"的结构。

### 3.2 核心观察：每个 1 独立计算"穿过 0 的受阻时间"

![逆向视角：每个 1 要穿过它左侧的全部 0，耗时 = 前面 1 的完成时间 + 1 与前方 0 数的较大值](images/bw85_q2_bubble_model.svg)

把过程看成**稳定冒泡排序**：1 是气泡，向左上浮穿过 0。最终形态是全部 1 排在左边（形如 `1^a 0^b`）。**从左到右**看每个 1：

- 设 $z_i$ 为第 $i$ 个 1 左侧 0 的个数——这个 1 最终必须**穿过这 $z_i$ 个 0**，每穿过一个花 1 秒；若 $z_i = 0$ 它从头到尾不动。
- 但它不能"抄近道"：同一秒每个字符只参与一次交换，且它左边若还有未就位的 1，就要**排队**。

设 $f_i$ 为第 $i$ 个 1（从左数）**完全就位**的时刻，则答案 $= \max_i f_i$（串结束当且仅当所有 1 就位）。转移为：

$$f_i = \begin{cases} 0 & z_i = 0 \\ \max(f_{i-1} + 1,\ z_i) & z_i > 0 \end{cases}$$

两项含义：

- $z_i$（下界）：**无阻塞**时它只需依次穿过前方 $z_i$ 个 0，最早在第 $z_i$ 秒完成——即使它前面没有别的 1 挡路。
- $f_{i-1} + 1$（阻塞项）：左边的 1 在 $f_{i-1}$ 秒才穿过某个 0，此刻那个 0 刚落到位置上、成为我们面前的**新障碍**，再花 1 秒穿过它。更妙的是：**阻塞只来自"前一个 1"而非"前面所有 1"**——前一个 1 穿过的 0 会挡住我，但更早的 1 穿过的 0 会先挡住前一个 1（被它消耗掉），轮到我时那些 0 早已在我左侧更远处，与本 1 无关。

两个下界都不可少，取 $\max$ 恰好是精确值（§5 证明）。

### 3.3 算法流程

```text
zeros = 0, ans = 0
for c in s:
    if c == '0': zeros += 1
    elif zeros > 0: ans = max(ans + 1, zeros)   # 该 1 就位时刻
返回 ans
```

一行状态、一次扫描：`ans` 即"最近一个需要移动的 1"的就位时刻 $f_i$（$z_i = 0$ 的 1 不更新 `ans`，因为它们不动、且 $f$ 序列中它们等于前值——详见 §4 第 3 点）。

### 3.4 示例演算

![示例演算：s = 00111 逐秒交换与逐 1 计算](images/bw85_q2_example_walkthrough.svg)

以 $s = \texttt{00111}$ 为例（这是"阻塞项"压过 "$z_i$" 的典型）：

**逐秒模拟**：`00111` → `01011` → `01101` → `11001` → `11100`，共 **4** 秒。

**逐 1 计算**：3 个 1 的 $z$ 均为 2。

| 第 $i$ 个 1 | $z_i$ | $f_i = \max(f_{i-1}+1,\ z_i)$ |
|---|---|---|
| 1 | 2 | $\max(0+1, 2) = 2$ |
| 2 | 2 | $\max(2+1, 2) = 3$ |
| 3 | 2 | $\max(3+1, 2) = 4$ |

答案 4。直觉：三个 1 排成一列依次穿过同两个 0，像**单车道跟车**——每个 1 要等前车挪开才能前进，所以总时间被"队列 + 瓶颈"共同决定，而非各自独立。

再看 $s = \texttt{0110001}$：前 3 个 1 的 $z = 1, 1, 1$，$f = 1, 2, 3$；最后一个 1 的 $z = 4$，$f = \max(3+1, 4) = 4$。答案 4——此时 $z$ 项与阻塞项相等，两种瓶颈同时咬合。

## 4. 算法细节

1. **为什么从左往右扫**：$f_i$ 只依赖 $f_{i-1}$ 与左侧 0 计数 $z_i$，二者都在扫描中顺路维护，一次遍历完成。
2. **$z_i = 0$ 的 1 跳过更新**：它不需要移动，就位时刻是 0；若套用公式会得到 $\max(ans+1, 0) = ans + 1$，凭空多 1 秒。更准确地说，这样的 1 的"就位时刻"应继承 $f_{i-1}$（它右侧的 0 不会挡它），但由于它**不可能是最慢的**（$f_{i-1}$ 已由前一个 1 贡献给 `ans`），跳过即可。
3. **`ans` 即 $f_{i-1}$**：因为 $f$ 关于 $i$ 单调不减（$f_i \ge f_{i-1} + 1 > f_{i-1}$，当 $z_i > 0$；其余情形 $f_i \ge f_{i-1}$），维护中的 `ans` 恰是最近一次更新处的 $f$ 值，可直接充当 $f_{i-1}$。
4. **不要把同一秒的交换写错**：若写暴力对拍，注意"同时替换"必须**从左到右扫描且跳过已交换位置**（`i += 2`），从右到左扫或允许重叠都会产生不同结果。
5. **答案上界**：$n - 1$（形如 `0^(n-1) 1`），`int` 足够，无溢出风险。

## 5. 正确性证明

先固定记号：把 $s$ 中的 1 从左到右记为 $1^{(1)}, 1^{(2)}, \dots, 1^{(a)}$，$z_i$ 是 $1^{(i)}$ 左侧 0 的个数。称一个 1 **就位**当且仅当它左侧不再有 0（此后永不再移动，因为交换只发生在 `01` 上）。过程终止 $\iff$ 所有 1 就位。

**引理 1（就位时刻递推）**：按上述规则，第 $i$ 个 1 的就位时刻 $f_i = \max(f_{i-1} + 1,\ z_i)$（$z_i > 0$；约定 $f_0 = 0$），且 $f_i \ge f_{i-1} + 1$。

**证明**：对 $i$ 归纳。$i = 1$：唯一的阻塞是其左 $z_1$ 个 0。注意同一秒内 `01` 的替换互不重叠，故同一秒内多个 0 向右移一格不影响本 1 每秒至多穿一个 0；第 1 秒它穿过**最右**的那个 0（若有），第 $t$ 秒穿过倒数第 $t$ 个，第 $z_1$ 秒穿完全部，且不可能更快（每秒至多一次交换），故 $f_1 = z_1 = \max(0 + 1, z_1)$。

归纳步：$1^{(i)}$ 面前的 0 分两类——(A) 初始就在它左侧的 $z_i$ 个；(B) $1^{(i-1)}$ 在左移途中"吐"到它右侧的 0。任一时刻 $1^{(i)}$ 与 $1^{(i-1)}$ 之间至多隔着**一个** 0（两个 0 相邻且左边是 1 的状态 `100` 稳定，说明中间的 0 已被前一个 1 穿过；中间不会积压第二个 0）。$1^{(i-1)}$ 在第 $f_{i-1}$ 秒完成最后一次交换，把最后一个 0 放到 $1^{(i)}$ 紧右侧（若该 0 存在），于是 $1^{(i)}$ 最早在第 $f_{i-1} + 1$ 秒穿过它。类 (B) 的 0 恰好是 $1^{(i-1)}$ 穿过的那些且逐个延迟到达，它们不叠加（前一个被穿完后下一个才到面前），故阻塞时间为 $f_{i-1} + 1$。类 (A) 的 $z_i$ 个 0 提供独立下界 $z_i$（每秒至多穿一个）。两个下界可**同时**满足：$1^{(i)}$ 在等待 $1^{(i-1)}$ 挪窝的每一秒里，都在同步消耗自己原生的 0（若有）；到第 $\max(f_{i-1} + 1, z_i)$ 秒时两类障碍恰好都耗尽，故 $f_i$ 等于该值。∎

**引理 2（终止刻画）**：过程在第 $T$ 秒结束 $\iff$ $T = \max_i f_i$。

**证明**：过程结束当且仅当串中无 `01`，即每个 1 左侧无 0，即所有 1 就位；最晚就位时刻为 $\max_i f_i$，此后每秒都无交换。∎

**定理**：一次扫描的算法返回正确秒数。

**证明**：由引理 1、2，答案为 $\max_i f_i$。算法按从左到右顺序维护 `ans`：遇到 $z_i > 0$ 的 1 时 `ans = max(ans + 1, zeros)` 恰是 $f_i = \max(f_{i-1} + 1, z_i)$（归纳地 `ans` 保存 $\max_{j \le i-1} f_j = f_{i-1}$，因 $f$ 单调不减）；遇到 $z_i = 0$ 的 1 不更新——其 $f_i = 0$，不影响最大值（只要存在 $z_j > 0$ 的 $j$，则 $f_j \ge 1 > 0$；若所有 $z_i = 0$，串初始即无 `01`，`ans` 保持 0 正确）。扫描结束时 `ans` $= \max_i f_i$。∎

> ⚠️ 注意引理 1 中"两类 0 不叠加"是关键一步：直觉上容易误以为总时间应把"前方 1 吐出的 0"与"自己的 0"相加，但实际上等待前车的时间里本车可以同步穿自己的 0，两条时间线**并行**，故取 $\max$ 而非求和。这也是为什么 $s = \texttt{00111}$ 的答案是 4 而不是 $2 + 3 = 5$。

## 6. 复杂度分析

- **时间**：$O(n)$。单趟扫描，每字符 $O(1)$。相比模拟的 $O(n^2)$，省去了"逐秒重扫整串"的冗余。
- **空间**：$O(1)$。仅 `zeros`、`ans` 两个计数器。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int secondsToRemoveOccurrences(string s) {
        int zeros = 0, ans = 0;
        for (char c : s) {
            if (c == '0') ++zeros;
            else if (zeros > 0) ans = max(ans + 1, zeros);   // f_i = max(f_{i-1}+1, z_i)
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def secondsToRemoveOccurrences(self, s: str) -> int:
        zeros = ans = 0
        for c in s:
            if c == '0':
                zeros += 1
            elif zeros > 0:
                ans = max(ans + 1, zeros)   # f_i = max(f_{i-1}+1, z_i)
        return ans
```

> 💡 两份代码均通过官方 2 个示例与 6 个手算边界，并与逐秒模拟对拍：C++ 穷举全部 $n \le 16$ 的 $2^{16}$ 个串 + 5000 组随机（共 13.6 万组）、Python 穷举 $n \le 14$ + 600 组随机，`mismatch = 0`；另通过 $n = 10^5$ 级大串性能校验。

## 8. 边界情况与易错点

1. **首字符是 1**：$z_1 = 0$，该 1 不动；别在它身上误触发 `ans + 1`——这正是 `elif zeros > 0` 分支存在的意义。
2. **全 0 / 全 1 串**：两者都无 `01`，答案 0；全 0 时循环只累计 `zeros`，`ans` 不动，正确。
3. **最易错点——把两项写成求和**：正确转移是 $\max(f_{i-1} + 1,\ z_i)$。若误用 $f_{i-1} + 1 + z_i$ 或 $z_i + \text{前方 0 总数}$，在 `00111` 这类"排队"样例上必错（会得 5 而非 4）。
4. **写暴力时"同时替换"的实现**：必须从左到右扫、遇到 `01` 交换后**跳过两个位置**（`i += 2`），否则同一字符在一秒内被交换两次，对拍基准本身就是错的。
5. **方向别搞反**：交换规则是 `01 → 10`，即 1 向**左**移动；把"左侧 0 计数"写成"右侧 0 计数"方向全反。
6. **别用 `pair`/队列模拟每个 1 的位置**：$O(n)$ 公式已足够，多余数据结构只会引入边界 bug。

**延伸思考**：本题的普适框架是「**受限并行冒泡**」：$k$ 个粒子沿同一条单车道向左穿行，每个粒子有独立行程 $z_i$ 与跟车约束 $f_i \ge f_{i-1} + 1$，总完成时间 $= \max_i \max(z_i, f_{i-1} + 1)$。把它抽象出来：若每秒允许每个字符参与 $c$ 次交换（$c$ 车道），转移变为 $f_i \ge f_{i-1} + \lceil 1/c \rceil$ 型；若交换规则改为 `10 → 01`（1 向右），只需把串反转后套同一公式。更远的亲戚是"稳定排序下相邻交换次数"（逆序对计数）：本题问的不是**次数**（那恰是 $\sum_i z_i$，即逆序对数）而是**并行完成时间**——次数与时间的分离正是并行调度问题的精髓。
