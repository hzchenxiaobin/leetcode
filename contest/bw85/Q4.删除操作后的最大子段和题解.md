# LeetCode 删除操作后的最大子段和 题解

## 1. 题目概述

- **标题 / 题号**：删除操作后的最大子段和（#2382，hard）
- **链接**：https://leetcode.cn/problems/maximum-segment-sum-after-removals/
- **来源**：LeetCode 第 85 场双周赛 Q4
- **难度**：困难
- **标签**：并查集、数组、有序集合、前缀和

**题意**：给定长度为 $n$ 的正整数数组 `nums` 与删除下标序列 `removeQueries`（互不相同）。第 $i$ 次删除 `removeQueries[i]` 处的元素，数组被切成若干**连续非空子段**。返回长度为 $n$ 的数组 `answer`，`answer[i]` 为第 $i$ 次删除后所有现存子段中和的最大值（无任何元素时为 0）。

**约束**：

- $n = \text{nums.length} = \text{removeQueries.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- $0 \le \text{removeQueries}[i] < n$，且互不相同

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,5,6,1], removeQueries = [0,3,2,4,1]
输出：[14,7,2,2,0]
解释：依次删除后数组（0 表示已删）为
  [0,2,5,6,1] → 最大子段 [2,5,6,1] = 14
  [0,2,5,0,1] → [2,5] = 7
  [0,2,0,0,1] → [2] = 2
  [0,2,0,0,0] → [2] = 2
  [0,0,0,0,0] → 0
```

**示例 2**

```text
输入：nums = [3,2,11,1], removeQueries = [3,2,1,0]
输出：[16,5,3,0]
解释：[3,2,11,0] → 16；[3,2,0,0] → 5；[3,0,0,0] → 3；全删 → 0。
```

**边界补充**

```text
输入：nums = [7], removeQueries = [0]        输出：[0]      # 删完即空
输入：nums = [5,5], removeQueries = [0,1]    输出：[5,0]
```

## 3. 解题思路

### 3.1 暴力思路

每次删除后线性扫一遍数组，维护"当前连续段和"取最大：$O(n^2)$。$n = 10^5$ 时 $10^{10}$ 次操作，不可行。更糟的是，即使借助有序集合维护"存活区间"（插入删除 $O(\log n)$），"当前所有段和的最大值"也要一个**支持删除的多重集**或延迟堆来维护，实现细节多、易错。正解的关键一步是**把时间倒流**，让所有操作统一成"添加"。

### 3.2 核心观察：时间倒流——删除序列逆转成添加序列

![时间倒流：删除序列从后往前看是逐个“点亮”元素，段只会合并不会分裂](images/bw85_q4_reverse_time.svg)

正向删除时，一个段可能被**劈成两半**（分裂），段的演化难以增量维护；但把 `removeQueries` 从后往前看：初始时**所有元素都已被删**，第 $i$ 步（$i$ 从 $n-1$ 倒序到 0）相当于把 `removeQueries[i]` 处的元素**添加回来**。添加只会发生两件事：

- 该位置自成一段（长 1）；
- 与左右相邻的**已存活段**合并——左右各自至多一段，合并方式唯一。

也就是说倒流视角里**段只合不分**，这恰好是并查集的舒适区：每个段是一个集合，添加一个元素即至多三次 `union`。而 `answer[i]`（第 $i$ 次删除后的最大段和）等于倒流中**第 $i$ 步添加之前**的最大段和——倒着算，先记录再合并。

### 3.3 算法流程

```text
1. answer[n-1] = 0                      # 全删光
2. best = 0                             # 当前最大段和（初始无段）
   alive[i] = false, fa[i] = i, sum/size 按根维护
3. for i = n-1 downto 1:                # 注意：最后一步（i=0）不合并，只填 answer[0]
       answer[i] = best                 # 第 i 次删除后的答案 = 本次添加前的最大段和
       p = removeQueries[i]
       激活 p：alive[p] = true, sum[p] = nums[p]
       若 p+1 存活 → union(段含 p, 段含 p+1)，段和相加
       若 p-1 存活 → union(段含 p, 段含 p-1)，段和相加
       best = max(best, 合并后新段和)
4. 返回 answer
```

> ⚠️ 顺序陷阱：`answer[i]` 是"第 $i$ 次**删除后**"的状态，而倒流中该状态对应"第 $i$ 步**添加前**"——所以必须**先取 `best` 再执行本步添加**。最后一步（$i = 0$，添加 `removeQueries[0]`）之后数组恢复完整，不再有删除，故循环只到 $i = 1$，`answer[0]` 在进入循环前……不对——`answer[0]` 是**第一次删除后**（即只剩 $n-1$ 个元素时）的最大段和，它对应倒流中"完成第 1 步添加（$i = 1$）之后、第 0 步添加之前"的 `best`，恰好由循环 $i = 1$ 那轮的**合并后** `best` 充当：因此循环体里"先记录 answer[i] 再合并"覆盖了 $i = n-1 \dots 1$ 的全部答案，$i = 0$ 这轮添加其实无需执行。实现上让循环跑到 $i = 0$、只在 $i \ge 1$ 时记录亦可，见参考代码。

### 3.4 示例演算

![示例演算：nums=[1,2,5,6,1] 的倒流添加与并查集合并过程](images/bw85_q4_example_walkthrough.svg)

以示例 1 倒流为例（`removeQueries = [0,3,2,4,1]`，倒序添加 $1, 4, 2, 3, 0$）：

| 倒流步 | 添加 | 存活段（下标） | 段和 | best（记录为 answer[i]） |
|---|---|---|---|---|
| — | — | ∅ | — | 0 → answer[4] = 0 |
| $i=4$ | 1 | {1} | 2 | 2 → answer[3] = 2 |
| $i=3$ | 4 | {1}, {4} | 2, 1 | 2 → answer[2] = 2 |
| $i=2$ | 2 | {1}, {2,4} | 2, 6 | 6 → answer[1] = 7？ |

慢着——添加 4 之后 $\{2,4\}$ 不相邻不合并，添加 2 时与 $\{4\}$ 合并成 $\{2,4\}$ 和 $6$，`best` 此时应为 $\max(2, 6) = 6$，但 `answer[1]` 应是 7。哪里差了？添加 2 后还要继续倒流……

| 倒流步 | 添加 | 存活段 | 段和 | best |
|---|---|---|---|---|
| $i=1$ | 3 | {1}, {2,3,4} | 2, 12 | 12 → answer[0] = 12？ |

这与期望 `answer = [14, 7, 2, 2, 0]` 仍不符。问题出在**错位一格**：`answer[i]` 对应的倒流状态应是"第 $i$ 步添加**完成后**再倒数 $n-1-i$ 步"——精确地说，倒流第 $i$ 步添加 `removeQueries[i]` 后的状态 = 正向完成 $i+1$ 次删除（再无更多）……不对，正反向步数对应是：正向做完前 $i+1$ 次删除的数组 = 倒流做完后 $n-1-i$ 步添加的数组。因此 **answer[i] = 倒流完成 $n-1-i$ 步添加后的 best**。上表补齐：倒流 $n-1-i$ 步后——$i=4$：0 步，best=0 ✓；$i=3$：1 步（添加 1），best=2 ✓；$i=2$：2 步（再添加 4），段 $\{1\},\{4\}$，best=2 ✓；$i=1$：3 步（再添加 2），段 $\{1\},\{2,4\}$，best=6 ✗（期望 7）？

再核对正向：`answer[1]` 是删除 0、3 两次后 `[0,2,5,0,1]` 的最大段和 = $2+5 = 7$，即段 $\{1,2\}$。而倒流 3 步添加的是 $\{1, 4, 2\}$，段为 $\{1\}, \{2, 4\}$——**下标 3 尚未添加**（它是第 $i=1$ 步添加的 `removeQueries[1] = 3`）。矛盾说明我的对照表把 `removeQueries` 的下标角色弄混了：倒流第 $j$ 步添加的是 `removeQueries[j]`，正向"完成 $i+1$ 次删除"删掉的恰好是 `removeQueries[0..i]`，**还活着的正是 `removeQueries[i+1..n-1]`**，即倒流要添加的前 $n-1-i$ 个（倒序）是 `removeQueries[n-1], ..., removeQueries[i+1]`。重列（倒序依次添加 1, 4, 2, 3, 0）：

| 倒流步 | 添加 | 存活段 | 段和 | best = answer[?] |
|---|---|---|---|---|
| 0 | — | ∅ | — | 0 = answer[4] ✓ |
| 1 | 1 | {1} | 2 | 2 = answer[3] ✓ |
| 2 | 4 | {1},{4} | 2,1 | 2 = answer[2] ✓ |
| 3 | 2 | {1},{2,4} | 2,6 | 6 = answer[?] |

倒流 3 步后存活 $\{1,2,4\}$，对应正向删了 $\{0,3\}$（answer[1] 状态）——但正向该状态的最大段是 $\{1,2\}$ 和 7，而 $\{2,4\}$ 在正向里**不相邻**（下标 3 已删）！症结找到了：**倒流时下标 4 与 2 之间隔着已添加的下标 3 吗？** 倒流 3 步只添加了 $\{1,4,2\}$，下标 3 未添加，段 $\{2,4\}$ 因中间 3 缺失**不应合并**——但我的并查集只查 $p\pm1$ 是否存活，$p=2$ 时 $p+1=3$ 未存活不合并，正确！那 $\{2,4\}$ 是怎么来的？——是添加 4 时它自成一段 $\{4\}$，添加 2 时 $p+1=3$ 未存活、$p-1=1$ 未存活（1 属于另一段但**下标 1 存活**！）。啊，$p=2$ 时 $p-1=1$ **是存活的**（第 1 步添加），所以 $\{1,2\}$ 合并成段和 7，另有 $\{4\}$ 段和 1，best = 7 = answer[1] ✓。之前表里的 $\{2,4\}$ 是我手算时的笔误。修正后完整过程：

| 倒流步 | 添加 | 存活段 | 段和 | best |
|---|---|---|---|---|
| 0 | — | ∅ | — | 0 = answer[4] |
| 1 | 1 | {1} | 2 | 2 = answer[3] |
| 2 | 4 | {1},{4} | 2,1 | 2 = answer[2] |
| 3 | 2 | {1,2},{4} | 7,1 | 7 = answer[1] |
| 4 | 3 | {1,2,3,4} | 14 | 14（= answer[0] 前一步？） |

倒流 4 步后存活 $\{1,2,3,4\}$，即正向只删了下标 0（answer[0] 状态），最大段和 14 ✓。最后一步（添加 0）恢复全数组，不需要记录。全部吻合——**这段反复纠错正体现了"先记录后合并"与"相邻存活判定"两个最易错点，值得在写代码前亲手推一遍**。

## 4. 算法细节

1. **答案的取值时机**：倒流循环里 `answer[i] = best` 必须发生在**激活 `removeQueries[i]` 之前**（该步添加对应正向第 $i+1$ 次删除的逆操作）。等价口诀："倒流 $n-1-i$ 步后的 best 即 answer[i]"。
2. **合并判据是"下标相邻且都存活"**：激活 $p$ 时只检查 $p-1$ 与 $p+1$。段与段之间必然隔着**已删除**（未激活）的下标，不可能出现"跳过空位误合并"——被删的下标永远不激活，天然是墙。
3. **并查集只存段，不存已删点**：初始所有点自成一集合但都"未激活"；激活时才赋予段和。也可以给并查集加"惰性激活"标记（`alive` 数组），`find` 不经过未激活点（它们从未被 union 过，天然自成根）。
4. **段和挂在根上**：`sum[find(x)]` 即 $x$ 所在段之和；合并时把两根的 `sum` 相加写到新根。由于只与**紧邻**段合并，不需要维护区间端点（本实现省去了 `left/right` 数组；若题目询问段的具体区间才需要）。
5. **最大值的维护**：段只会**新增与合并**，段和单调不减？不——合并后旧段消失，但新段和 = 两段之和 ≥ 各自旧值，且全局 `best` 只被 `max(best, 新段和)` 更新，**从不减小**。因此无需"删除旧段和"的多重集，一个变量即可（这正是倒流带来的红利；正向做必须支持删除）。
6. **前缀和备选**：段和也可用前缀和 `pre[r+1] - pre[l]` 计算，合并时维护段的左右端点。两者等价，直接累加更省一个数组与一次减法。
7. **数据类型**：$n \le 10^5$、$\text{nums}[i] \le 10^9$，总和控制 $\le 10^{14}$，必须 `long long`。

## 5. 正确性证明

**记号**：正向状态 $S_i$（$0 \le i \le n-1$）表示完成前 $i+1$ 次删除后的数组；$A_i$ 为 $S_i$ 中最大子段和（$A_{n-1} = 0$，因全删空）。倒流状态 $R_j$ 表示依次激活 `removeQueries[n-1], ..., removeQueries[n-j]` 共 $j$ 个下标后的"存活集合"。

**引理 1（状态对偶）**：$R_{n-1-i}$ 的存活集合 $= S_i$ 的存活集合 $= \{0..n-1\} \setminus \{\text{removeQueries}[0..i]\}$。

**证明**：$R_{n-1-i}$ 激活的是 `removeQueries` 的后 $n-1-i$ 个元素 `removeQueries[n-1..i+1]`；由于 `removeQueries` 是 $0..n-1$ 的排列，未激活的恰为前 $i+1$ 个 `removeQueries[0..i]`，即 $S_i$ 中被删除的集合。∎

**引理 2（倒流的段演化）**：设 $R_j$ 的存活集划分为极大连续段。激活下标 $p = \text{removeQueries}[n-1-j]$ 得 $R_{j+1}$，则 $R_{j+1}$ 的段 = $R_j$ 的段 ∪ $\{p\}$ 中，含 $p$ 的新段恰为 $\{p\} \cup (\text{含 } p+1 \text{ 的段}) \cup (\text{含 } p-1 \text{ 的段})$（存在才并），其余段不变。

**证明**：$p$ 原本不存活，其左右邻居（若存活）分别属于 $R_j$ 的某段 $T_r, T_l$。存活集中相邻下标属于同一段（极大连续性），故 $p$ 并入后与 $T_r, T_l$ 连成一体；除此之外不改变任何其他相邻关系。$T_r, T_l$（若都存在）原本被 $p$ 隔开、互不相邻，合并没有歧义。∎

**引理 3（单调性）**：倒流过程中 `best`（按算法维护的最大段和）单调不减，且恒等于当前 $R_j$ 的最大段和。

**证明**：归纳。$R_0$ 无段，best = 0 成立。设 $R_j$ 时成立。由引理 2，$R_{j+1}$ 相对 $R_j$ 只有"含 $p$ 的新段"是新的，其余段原样保留；新段和 $= \text{nums}[p] + \sum(\text{并入的段和}) \ge$ 每个被并入段的旧和（$\text{nums}[p] \ge 1 > 0$）。故消失的段和被新段和**覆盖或超过**，$R_{j+1}$ 的最大段和 $= \max(R_j \text{ 的最大段和}, \text{新段和}) = \max(\text{best}, \text{新段和})$，与算法更新式一致。∎

**定理**：算法返回的 `answer` 满足 `answer[i]` $= A_i$。

**证明**：由引理 1，$S_i = R_{n-1-i}$，故 $A_i$ = $R_{n-1-i}$ 的最大段和。算法倒流循环在第 $j$ 步**激活前**记录 `answer[?]`，激活对应 $p = \text{removeQueries}[n-1-j]$；倒流 $j$ 步完成后的状态是 $R_j$，其中 $j = n-1-i \iff i = n-1-j$，即循环变量 $i = n-1-j$ 时"激活前"的 best 恰是 $R_j = R_{n-1-i}$ 的最大段和（引理 3）$= A_i$。循环覆盖 $i = n-1$（$j=0$，answer[n-1]=0）至 $i = 1$（$j = n-2$）；$i = 0$ 时 $j = n-1$，$R_{n-1}$ 的最大段和由最后一轮合并后的 best 给出，算法在循环中先记录 answer[0] 于激活 `removeQueries[0]` 之前——即 $i=0$ 轮也执行"先记录后激活"，故 answer[0] $= R_{n-1}$ 的最大段和 $= A_0$。∎

> ⚠️ 引理 3 中"段和被新段和覆盖"依赖 $\text{nums}[i] \ge 1$（正数）。若允许负数，新段和可能**小于**被并入的段和，`best` 单调性破灭，需要改用支持删除的有序多重集维护——这是本题"正数约束"的隐藏作用，值得注意。

## 6. 复杂度分析

- **时间**：$O(n \alpha(n))$。倒流 $n$ 轮，每轮至多两次 `union` 与常数次 `find`，路径压缩下并查集单操作均摊 $O(\alpha(n))$（近似常数）。总计算量约 $4n$ 次找根。
- **空间**：$O(n)$。并查集父指针、段和、存活标记各 $n$ 长度，答案数组 $n$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<long long> maximumSegmentSum(vector<int>& nums, vector<int>& removeQueries) {
        int n = nums.size();
        vector<int> fa(n);
        for (int i = 0; i < n; ++i) fa[i] = i;
        vector<bool> alive(n, false);          // 该下标是否已“添加”回来
        vector<long long> sum(n, 0);           // 段和，挂在段根上
        vector<long long> ans(n);
        long long best = 0;
        auto find = [&](int x) {               // 路径压缩
            while (fa[x] != x) { fa[x] = fa[fa[x]]; x = fa[x]; }
            return x;
        };
        for (int i = n - 1; i >= 0; --i) {
            ans[i] = best;                     // 先记录：删除后 = 添加前
            int p = removeQueries[i];
            alive[p] = true;
            long long tot = nums[p];
            if (p + 1 < n && alive[p + 1]) {   // 与右邻段合并
                int r = find(p + 1);
                fa[r] = p;
                tot += sum[r];
            }
            if (p > 0 && alive[p - 1]) {       // 与左邻段合并
                int l = find(p - 1);
                fa[l] = p;
                tot += sum[l];
            }
            sum[p] = tot;
            best = max(best, tot);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maximumSegmentSum(self, nums: list[int], removeQueries: list[int]) -> list[int]:
        n = len(nums)
        fa = list(range(n))
        alive = [False] * n
        seg_sum = [0] * n            # 段和，挂在段根上

        def find(x):
            while fa[x] != x:
                fa[x] = fa[fa[x]]    # 路径减半
                x = fa[x]
            return x

        ans = [0] * n
        best = 0
        for i in range(n - 1, -1, -1):
            ans[i] = best            # 先记录：删除后 = 添加前
            p = removeQueries[i]
            alive[p] = True
            tot = nums[p]
            if p + 1 < n and alive[p + 1]:     # 与右邻段合并
                r = find(p + 1)
                fa[r] = p
                tot += seg_sum[r]
            if p > 0 and alive[p - 1]:         # 与左邻段合并
                l = find(p - 1)
                fa[l] = p
                tot += seg_sum[l]
            seg_sum[p] = tot
            best = max(best, tot)
        return ans
```

## 8. 边界情况与易错点

1. **answer 的取值时机错一格**：必须"先记录 `ans[i] = best`，再激活 `removeQueries[i]`"。若先激活后记录，所有答案右移一位，样例 1 会得到 `[14,14,7,2,2]` 之类的错误序列。
2. **全删空的最后一步**：`answer[n-1] = 0` 由初始 `best = 0` 天然给出，无需特判；但循环务必从 $i = n-1$ 开始（第一轮记录的就是它）。
3. **合并判据只看紧邻下标**：激活 $p$ 时只探测 $p \pm 1$ 的 `alive` 状态。错误地探测 `find(p±1)` 是否存在（而不看 alive）会把**未激活**的点也拉进段——未激活点从未被合并过、自成一根，只查并查集无法区分"独立段"与"孤魂未激活点"。
4. **段和累加方向**：合并时新段和 $=$ 自身 + 左段 + 右段，三处来源一次算清；漏加任何一处会在"左右同时合并"（如倒流添加正好填补两段之间）时出错。
5. **溢出**：最大段和可达 $10^5 \times 10^9 = 10^{14}$，C++ 必须 `long long`（题目返回类型即 `long[]`），Python 无虞。
6. **正数假设**：`best` 的单调维护依赖 $\text{nums}[i] > 0$。若值可为负/零，合并出的新段和可能小于旧段，须改用有序多重集（`multiset` / `SortedList`）支持"删旧插新"。
7. **`find` 的路径压缩别忘**：$n = 10^5$ 且链式合并（顺序添加 $0,1,2,\dots$）会把并查集拉成链，无压缩时最坏 $O(n^2)$。

**延伸思考**：本题是「**离线倒流**」家族的典型成员：当在线操作是"破坏"（删除、断边、熄灭）而结构只对"生长"（合并、连接、点亮）友好时，把操作序列**整体逆转**，配合并查集的只增不删特性，即可把动态维护难题变成一串 `union`。判断一道题是否适用只需两问：(1) 查询能否与操作一起离线按"倒序时间"处理？(2) 逆转后结构是否只合不分？本题两问皆肯定。若查询必须**在线**（边删边答），倒流失效，退而求其次的武器是"按大小合并的分裂并查集"（离线重建）或直接上线段树维护最大子段和（经典 `sum/lsum/rsum/ans` 四元组上传，支持单点改 0/恢复）。把本题改造成"允许负数"或"在线查询"，就得到两个绝佳的进阶练习。
