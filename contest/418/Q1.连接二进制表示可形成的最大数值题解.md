# LeetCode 连接二进制表示可形成的最大数值 题解

## 1. 题目概述

- **标题 / 题号**：连接二进制表示可形成的最大数值（#3309，medium）
- **链接**：https://leetcode.cn/problems/maximum-possible-number-by-binary-concatenation/
- **来源**：LeetCode 第 418 场周赛 Q1
- **难度**：中等
- **标签**：位运算、数组、枚举、排序

**题意**：给定长度为 3 的正整数数组 `nums`，将三个数的**二进制表示**（无前导零）按某种顺序首尾拼接成一个二进制串，返回能拼出的**最大数值**。

**约束**：

- `nums.length == 3`
- $1 \le \text{nums}[i] \le 127$

> 💡 **读题三秒抓关键**：① 长度恒为 3 → 候选顺序只有 $3! = 6$ 种，**枚举就是正解**；② $127 = 2^7 - 1$ → 每段二进制至多 7 位、且首字符必为 `1`，拼接结果至多 21 位，`int` 毫无压力；③ 无论什么顺序，拼接串总长恒为 $L_a + L_b + L_c$（$L_x$ 表示 $x$ 的二进制位数）→ **所有候选等长**，「数值最大」等价于「拼接串字典序最大」。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]
输出：30
解释：按 [3,1,2] 顺序拼接 "11"+"1"+"10" = "11110"，即 30 的二进制表示。
```

**示例 2**

```text
输入：nums = [2,8,16]
输出：1296
解释：按 [2,8,16] 顺序拼接 "10"+"1000"+"10000" = "10100010000"，即 1296 的二进制表示。
```

**示例 3（自造，验证「与输入顺序无关」）**

```text
输入：nums = [16,8,2]
输出：1296
解释：与示例 2 相同——拼接结果只取决于「选择的连接顺序」，与输入给出顺序无关；
     顺带一提，按输入原样（数值降序）拼接只得 1058，恰是 6 个候选中最小的。
```

## 3. 解题思路

### 3.1 朴素贪心的陷阱

最诱人的做法是按直觉排序——**数值大的放前面**或**位数多的放前面**。两个直觉都是错的：

![直觉贪心失效：按数值排序拼出最差解](images/bin_concat_greedy_fail.svg)

示例 2 中数值降序 $[16, 8, 2]$ 只拼出 $1058$（6 个候选中**最小**），最优顺序 $[2, 8, 16]$ 恰好是数值**升**序，拼出 $1296$。直觉失效的原因：一个数对拼接串的贡献取决于其**二进制串作为前缀的「统治力」**，而非数值本身——高位快还是低位慢，数值大小说了不算。

正确的切入只有两条路：**枚举**（本题 $n=3$，6 个候选全算一遍）与**拼接比较器排序**（可推广到任意 $n$）。

### 3.2 核心观察：拼接 = 左移腾位 + 按位或，6 种排列直接枚举

签到最短路径：候选顺序只有 $3! = 6$ 种，全部算出来取 $\max$，不需要任何贪心假设。

拼接本身用位运算一步完成。顺序 $(a, b)$ 的拼接值为

$$
(a \ll L_b) \mid b \;=\; a \cdot 2^{L_b} + b
$$

其中 $L_x$ 为 $x$ 的二进制位数（`bit_length`）。直觉：$a$ 排在前面，就要给 $b$ **腾出** $L_b$ 个低位 `0`——这正是「左移」；腾出的低位全为 0，与 $b$ 按位**或**等价于直接**加**上它（1 位无重叠、无进位）。

![拼接的位运算本质：左移腾位 + 按位或](images/bin_concat_shift_or.svg)

三个数同理嵌套：

$$
V(a,b,c) = \big((a \ll L_b) \mid b\big) \ll L_c \mid c
$$

于是 `v = (v << L) | x` 一个表达式就把一个数拼了进去，全程不碰字符串。

### 3.3 算法流程

![算法流程图：枚举 6 种排列](images/bin_concat_algorithm_flow.svg)

主循环就是「枚举排列 → 三步移位拼接 → 更新最大值」：

- **C++** 用 `next_permutation` 枚举，**必须先 `sort` 升序**：do-while 会从起点一路走到字典序最大的排列停住，起点不是最小排列就会漏掉前面一段。
- **Python** 用 `itertools.permutations` 直接生成全部 6 个排列，无此坑。

若 $n$ 更大（$n!$ 爆炸），换**拼接比较器**排序：定义「$a$ 排在 $b$ 前」当且仅当 $(a \ll L_b) \mid b > (b \ll L_a) \mid a$（谁在前拼出来更大，谁排前面），排序后依次拼接，$O(n \log n)$。比较器的正确性与合法性见第 5 节证明。

### 3.4 示例演算

![示例演算表：[2,8,16] 的 6 种排列](images/bin_concat_permutation_table.svg)

以示例 2（`nums = [2,8,16]`，bin：$2 \to 10$、$8 \to 1000$、$16 \to 10000$）列出全部 6 种排列：

| 顺序 | 分段拼接 | 拼接串 | 数值 |
|------|----------|--------|------|
| $[2,8,16]$ | "10"+"1000"+"10000" | 10100010000 | **1296** ★ |
| $[2,16,8]$ | "10"+"10000"+"1000" | 10100001000 | 1288 |
| $[8,2,16]$ | "1000"+"10"+"10000" | 10001010000 | 1104 |
| $[8,16,2]$ | "1000"+"10000"+"10" | 10001000010 | 1090 |
| $[16,2,8]$ | "10000"+"10"+"1000" | 10000101000 | 1064 |

## 4. 算法细节

1. **位长计算**：Python `x.bit_length()`、C++ 手写循环（或 C++20 `bit_width`），恰好返回「无前导零的二进制位数」，与题意无缝对接；本题 $x \ge 1$，无需处理 $0$。
2. **拼接公式**：`v = (v << L) | x`。$v$ 左移 $L$ 位后低 $L$ 位全 0，$x < 2^L$ 只占低 $L$ 位，1 位无重叠 → `|` 与 `+` 完全等价。
3. **`next_permutation` 的坑**：do-while 从当前排列走到字典序最大者停止，必须先 `sort` 升序，否则漏掉起点之前的排列（例如从 `[2,1,3]` 出发只会枚举到 4 个排列）。
4. **拼接比较器（推广版）**：「$a$ 前 $b$ 后」优于反向 $\iff a\,(2^{L_b}-1) > b\,(2^{L_a}-1) \iff \dfrac{a}{2^{L_a}-1} > \dfrac{b}{2^{L_b}-1}$。排序时用实数键 $\text{key}(x) = x / (2^{L_x} - 1)$ 保证严格弱序，避免手写比较器破坏传递性。

## 5. 正确性证明

**引理 1（候选全集）**：任何拼接方案对应且仅对应三个元素的一个排列；枚举全部 $3! = 6$ 个排列后取最大值即为答案。

**证明**：拼接按顺序消耗三个元素各恰好一次，方案与 $[0,1,2]$ 的排列一一对应。6 个排列覆盖全部方案，取 $\max$ 正确。∎

**引理 2（拼接公式）**：对正整数 $a, b$（位长 $L_a, L_b$），「$a$ 前 $b$ 后」的拼接值为 $a \cdot 2^{L_b} + b$。

**证明**：$a$ 无前导零，故 $a < 2^{L_a}$。$a \ll L_b$ 后低 $L_b$ 位全 0；$b < 2^{L_b}$ 只占低 $L_b$ 位。两者二进制 1 位不重叠，按位或等于算术相加。∎

**引理 3（比较器的全序性）**：定义 $a \prec b \iff a \cdot 2^{L_b} + b > b \cdot 2^{L_a} + a$（$a$ 在前拼出来更大）。该关系等价于比较实数键 $k(x) = \dfrac{x}{2^{L_x} - 1}$ 的大小，故满足传递性，是严格弱序。

**证明**：移项 $a \cdot 2^{L_b} + b > b \cdot 2^{L_a} + a \iff a\,(2^{L_b} - 1) > b\,(2^{L_a} - 1) \iff \dfrac{a}{2^{L_a}-1} > \dfrac{b}{2^{L_b}-1}$（最后一步两边同除正数 $(2^{L_a}-1)(2^{L_b}-1)$）。右端是实数比较，实数上 $>$ 传递，故 $\prec$ 传递。∎

**定理**：按 $k(x)$ 降序排列后依次拼接，得到最大数值。

**证明（交换论证）**：设排列 $\pi = (\ldots, a, b, \ldots)$ 最优，其中 $a, b$ 相邻且 $a$ 在 $b$ 前，但 $k(b) > k(a)$（即 $b$ 放前更优）。交换 $a, b$：两段覆盖的连续区间长度 $L_a + L_b$ 不变，故前缀的移位量与后缀的数值均不变，仅该区间贡献由 $a \cdot 2^{L_b} + b$ 变为 $b \cdot 2^{L_a} + a$，由引理 3 的等价变形严格增大——与 $\pi$ 最优矛盾。因此最优排列中每对相邻段都满足 $k(\text{前}) \ge k(\text{后})$；再由引理 3 的传递性，整个排列按 $k$ 降序（平局时两种顺序拼接值相等，随意打破）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。$3! = 6$ 种排列 × 每种 3 次移位拼接 = 18 次位运算。一般化为 $O(n \cdot n!)$；排序版 $O(n \log n)$。
- **空间复杂度**：$O(1)$。仅常数个变量；Python `permutations` 惰性生成，不物化全排列表。

## 7. 参考代码

### C++（枚举版）

```cpp
class Solution {
    int blen(int x) {                    // x 的二进制位数（本题 x ≥ 1）
        int n = 0;
        while (x) ++n, x >>= 1;
        return n;
    }
  public:
    int maxGoodNumber(vector<int>& nums) {
        sort(nums.begin(), nums.end());  // next_permutation 要从最小排列出发才不漏
        int ans = 0;
        do {
            int v = 0;
            for (int x : nums) v = (v << blen(x)) | x;   // 左移腾位 + 按位或 = 拼接
            ans = max(ans, v);
        } while (next_permutation(nums.begin(), nums.end()));
        return ans;
    }
};
```

### Python（枚举版）

```python
class Solution:
    def maxGoodNumber(self, nums: List[int]) -> int:
        ans = 0
        for a, b, c in permutations(nums):          # 3! = 6 种顺序
            v = (a << b.bit_length() | b) << c.bit_length() | c
            ans = max(ans, v)
        return ans
```

### Python（排序版，可推广到任意 n）

```python
class Solution:
    def maxGoodNumber(self, nums: List[int]) -> int:
        key = lambda x: x / ((1 << x.bit_length()) - 1)   # 拼接统治力键，见引理 3
        ans = 0
        for x in sorted(nums, key=key, reverse=True):
            ans = (ans << x.bit_length()) | x
        return ans
```

> 💡 三个版本对两组官方示例分别输出 `30` / `1296`；位运算版与字符串版（`int(f"{a:b}{b:b}{c:b}", 2)`）在 $[1,127]$ 内随机三元组上对拍一致。

## 8. 边界情况与易错点

1. **直觉排序陷阱**：按数值（或位数）降序拼接是错的——$[2,8,16]$ 中数值降序 $[16,8,2]$ 恰拼出最小的 $1058$，最优反而是数值升序的 $1296$。
2. **`next_permutation` 忘记先 `sort`**：do-while 只走「当前 → 字典序最大」这一段，会漏排列；Python `permutations` 无此坑。
3. **溢出**：$\text{nums}[i] \le 127 = 2^7 - 1$ → 总位数 $\le 21$，拼接值 $< 2^{21} \approx 2.1 \times 10^6$，`int32` 余量三个数量级；一般化到大 $n$ 才需 `long long` / 大数。
4. **位长与前导零**：`bit_length()` 恰返回无前导零位数，与题意天然吻合；若题目允许 $x = 0$（位长为 0），移位公式与比较器分母 $2^{L_x} - 1$ 都会出问题，需特判——本题 $x \ge 1$ 无此坑。
5. **殊途同归**：$[1,2,3]$ 的 $[1,3,2]$ 与 $[3,1,2]$ 同拼出 $30$，取 $\max$ 天然覆盖，无需去重。
6. **比较器传递性**：拼接类比较器若随手定义（如直接比数值、比位长）不满足严格弱序，喂给 `sort` 是未定义行为；必须用引理 3 的实数键。
