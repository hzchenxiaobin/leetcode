# LeetCode 移除可疑的方法 题解

## 1. 题目概述

- **标题 / 题号**：移除可疑的方法（#3310，medium）
- **链接**：https://leetcode.cn/problems/remove-methods-from-project/
- **来源**：LeetCode 第 418 场周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、图

**题意**：项目有 $n$ 个方法（编号 $0 \sim n-1$），`invocations[i] = [a, b]` 表示方法 $a$ 调用方法 $b$。已知方法 $k$ 有 bug：$k$ 及其**直接或间接调用**的所有方法都是「可疑方法」，需要从项目中移除。但一组方法只有在**没有被这组之外的任何方法调用**时才能被移除；若无法移除**所有**可疑方法，则一个都不删。返回移除后剩下的方法编号，顺序任意。

**约束**：

- $1 \le n \le 10^5$，$0 \le k \le n - 1$
- $0 \le \text{invocations.length} \le 2 \times 10^5$
- $a_i \ne b_i$ 且无重边（调用关系**允许成环**）

> 💡 **读题三秒抓关键**：① 「直接或间接调用」= 调用图上从 $k$ 出发的**正向可达性**——方向别想反，调用可疑方法的人**不会**被传染；② 移除条件看的是**从圈外指向圈内**的入边；③ 语义是 all-or-nothing：删就删光、删不动就全保留，不存在中间态。本题标中等，卡人的几乎全是①②的方向语义，图算法部分只是模板级 BFS。

## 2. 示例

**示例 1**

```text
输入：n = 4, k = 1, invocations = [[1,2],[0,1],[3,2]]
输出：[0,1,2,3]
解释：可疑集合 S = {1, 2}（1 调用 2）。但 0→1、3→2 都是圈外指向圈内的「入侵边」，
      无法整组移除 → 一个不删，返回全部方法。
```

**示例 2**

```text
输入：n = 5, k = 0, invocations = [[1,2],[0,2],[0,1],[3,4]]
输出：[3,4]
解释：可疑集合 S = {0, 1, 2}；四条边里三条在圈内、(3,4) 两端都在圈外，
      没有入侵边 → 删光 S，剩下 [3,4]。
```

**示例 3**

```text
输入：n = 3, k = 2, invocations = [[1,2],[0,1],[2,0]]
输出：[]
解释：2→0→1→2 成环，从 2 出发全部可达，S = 全体方法；没有「圈外」可言，自然全删。
```

**示例 4（自造，验证「无边」情形）**

```text
输入：n = 3, k = 1, invocations = []
输出：[0,2]
解释：S = {1}，没有任何边（自然没有入侵边）→ 删掉 1，返回 [0,2]。
      「invocations 为空」不是失败，照常走流程。
```

## 3. 解题思路

### 3.1 暴力思路与真正的坑

「直接或间接调用」最朴素的翻译：对每个方法 $i$ 独立跑一次 BFS，判断 $k$ 是否可达 $i$：

```cpp
for (int i = 0; i < n; ++i)
    susp[i] = (i == k) || reach(k, i);   // reach：一次完整遍历
```

每次 `reach` 花费 $O(n + m)$，总计 $O\big(n(n+m)\big)$，在 $n = 10^5$、$m = 2 \times 10^5$ 下约 $3 \times 10^{10}$ 步，超时约两个数量级。浪费显而易见：**$n$ 次遍历走的是同一张图、同一个起点**——可达性本来就是「一次遍历顺带标记全体」的场景，从 $k$ 走一遍，踩到谁标记谁，走完时标记数组就是答案。

但比赛时这题真正的 WA 来源往往不是复杂度，而是**方向**：

- 把「可疑」理解成 $k$ 的**祖先**（谁调用了 $k$ 谁可疑）——示例 1 里 $0$ 调用 $1$，按这个理解 $0$ 也该删，答案直接错；
- 把移除判定写成「$S$ 中有方法调用圈外就放弃」——反着判同样错。

删除的受害者是**被调用者**：只有「外部调用内部」的边会让圈外方法在删除后悬空，这才是唯一的否决条件。

### 3.2 核心观察：传染闭包 + 入边一票否决

**观察一：可疑集合 $S$ = 从 $k$ 出发的可达集合（传染闭包）。**

bug 是一种**只顺流、不逆流**的传染：$k$ 本身可疑；$a$ 可疑且 $a$ 调用 $b$ $\Rightarrow$ $b$ 可疑；反过来 $a$ 调用了可疑的 $b$，$a$ 不受影响（示例 1 的 $0$ 调用 $1$，$0$ 干净）。于是求 $S$ 就是最朴素的图论模板——从 $k$ 出发一次 BFS/DFS，环无需特判（已标记的点直接跳过）。

![传染闭包与 BFS 扩张轨迹](images/remove_methods_bug_closure.svg)

**观察二：移除资格只由「圈外 → 圈内」的边一票否决。**

把题目条件翻译成边语言：

$$S \text{ 可移除} \iff \neg\,\exists\ \text{边 } (a, b) \in E:\ a \notin S \ \wedge\ b \in S$$

把所有边按两端归属分类，逐类裁决：

| 边 $(a \to b)$ | 会出现吗 | 能否否决删除 | 原因 |
|----------------|----------|--------------|------|
| 圈外 → 圈内 | **会** | ✗ **一票否决** | 外部方法还依赖圈内方法，删了它就悬空 |
| 圈外 → 圈外 | 会 | ✓ 放行 | 与 $S$ 无关 |
| 圈内 → 圈内（含环） | 会 | ✓ 放行 | 整组一起消失，组内调用关系随之蒸发 |
| 圈内 → 圈外 | **永远不会** | （空集） | $a \in S$ 且 $a \to b$ ⇒ 路径拼接得 $b \in S$ |

第四行是个值得单独点出的**结构性事实**：$S$ 是从 $k$ 出发的可达集合，对出边封闭——可疑方法调用的对象必然也可疑。所以「删掉 $S$ 会让某个圈外方法失去它调用的方法」这件事，**当且仅当**存在入侵边时发生，恰好就是被否决的那种情形。判定因此干净利落：

![三类边判定：只有入侵边能否决删除](images/remove_methods_edge_verdict.svg)

配合 all-or-nothing 语义：扫一遍 `invocations`，**发现一条** `susp[a] = 0 且 susp[b] = 1` 的边就立刻返回全体；一条都没有，才删光 $S$。

### 3.3 算法流程

两趟线性扫描，没有第三个步骤：

![算法流程图：建图、BFS 标记、扫边判定](images/remove_methods_algorithm_flow.svg)

1. 建正向邻接表（$a \to b$），$O(m)$；
2. 从 $k$ 出发**迭代** BFS，标记 `susp[]`（传染闭包 $S$），$O(n + m)$；
3. 扫一遍 `invocations`：发现 `susp[a] = 0` 且 `susp[b] = 1` 的边 → 返回 $[0, 1, \dots, n-1]$，$O(m)$；
4. 否则收集所有 `susp[i] = 0` 的下标返回，$O(n)$。

> ⚠️ 第 2 步必须用**迭代**队列/显式栈：$n$ 可达 $10^5$，一条 $0 \to 1 \to \cdots \to n-1$ 的长链就有 $10^5$ 层递归深度——Python 默认递归上限 1000 直接爆栈，C++ 也受栈大小约束。

### 3.4 示例演算

示例 1 与示例 2 并排走一遍，看「入侵边」如何一票否决：

![示例演算：入侵边决定两种命运](images/remove_methods_example_walkthrough.svg)

- **示例 1**（$k=1$）：BFS 从 1 出发只能走到 2，$S=\{1,2\}$；扫边发现 $(0,1)$、$(3,2)$ 两条都是圈外指向圈内 → 否决，返回 $[0,1,2,3]$。
- **示例 2**（$k=0$）：BFS 出队顺序 $0 \to 2 \to 1$，$S=\{0,1,2\}$；四条边里 $(1,2),(0,2),(0,1)$ 在圈内、$(3,4)$ 在圈外，无入侵边 → 删光 $S$，返回 $[3,4]$。
- **示例 3**（$k=2$）：环 $2 \to 0 \to 1 \to 2$ 全部可达，$S$ = 全体；没有圈外可言，连入侵边都不可能出现 → 返回 $[\,]$。

## 4. 算法细节

1. **只建正向邻接表**：标记要顺流走（$a \to b$），但判定可以直接扫原始 `invocations` 数组读两端标记，**不必建反向图**——少一份 $O(n + m)$ 内存，也少一步建图。
2. **入队即标记**：BFS 的不变式是「入队时立刻置 `susp[v] = 1`」，而不是出队时——后者会让同一个点被重复入队，环上直接死循环。这个不变式同时保证每点至多入队一次、每条边至多查看一次。
3. **迭代代替递归**：Python `deque` + `while`；C++ `queue`。$10^5$ 长链是本题的隐形压力用例。
4. **标记数组选型**：C++ 用 `vector<char>`（`vector<bool>` 是位压缩特化，逐元素访问更慢且取不了引用）；Python 直接用 `list[bool]`，$O(1)$ 判定且缓存友好。
5. **一票否决的早退**：扫边发现第一条入侵边就 `iota` / `list(range(n))` 构造全体返回，不必继续扫完。
6. **答案顺序任意**：收集幸存者按下标升序即可，无需排序。

## 5. 正确性证明

**引理 1（可疑集合的刻画）**：记调用图为 $G = (V, E)$，$E$ 中边 $(a,b)$ 表示 $a$ 调用 $b$。方法 $v$ 可疑 $\iff$ $G$ 中存在从 $k$ 到 $v$ 的有向路径（长度可以为 0，即 $v = k$）。

**证明**：题意中「$k$ 直接或间接调用的方法」展开后即「存在调用序列 $k = u_0 \to u_1 \to \cdots \to u_\ell = v$」，这正是有向路径的定义。对 $\ell$ 归纳：$\ell = 0$ 时 $v = k$ 本身可疑；$\ell \ge 1$ 时前缀 $u_0 \to \cdots \to u_{\ell-1}$ 是「$k$ 直接或间接调用 $u_{\ell-1}$」的序列，归纳假设下 $u_{\ell-1}$ 可疑，再经边 $(u_{\ell-1}, v)$，$v$ 被 $u_{\ell-1}$ 直接调用，故 $v$ 可疑。反向：可疑方法只能由「$k$ 本身 + 逐条调用边扩张」生成，扩张的每一步都对应路径长度加一，故可疑者必可达。∎

**推论（$S$ 对出边封闭）**：若 $a \in S$ 且 $(a, b) \in E$，则 $b \in S$。

**证明**：$k$ 到 $a$ 的路径拼接边 $(a,b)$ 即得 $k$ 到 $b$ 的路径，由引理 1，$b \in S$。∎（这正是 3.2 节表格第四行「圈内 → 圈外不会出现」的依据。）

**引理 2（BFS 标记的正确性）**：「入队即标记」的迭代 BFS 终止时，标记集合恰为从 $k$ 出发的可达集合 $R$。

**证明**：（$\subseteq$）对出队次序归纳：$k$ 有长度 0 的路径；某点 $u$ 已标记且存在边 $(u, v)$，则 $k \to \cdots \to u \to v$ 是 $k$ 到 $v$ 的路径，故每个入队的点都在 $R$ 中。（$\supseteq$）对 $k$ 到 $v$ 的最短路长度 $\ell$ 归纳：$\ell = 0$ 时 $v = k$ 已预标记；$\ell \ge 1$ 时最短路上前一个点 $u$ 的最短路长度 $\le \ell - 1$，归纳假设 $u$ 已标记，于是 $u$ 出队时扫描其邻接表必会把 $v$ 标记（若尚未标记）。两个包含合并即得标记集 $= R$。∎

**引理 3（判定条件）**：$S$ 可整组移除 $\iff$ 不存在边 $(a,b) \in E$ 满足 $a \notin S$ 且 $b \in S$。

**证明**：题设规则「一组方法没有被这组之外的任何方法调用时才能被移除」中，「方法 $x$ 调用方法 $y$」恰对应边 $(x, y)$；「$S$ 外的方法调用 $S$ 中的方法」即 $\exists (a,b) \in E: a \notin S \wedge b \in S$。对该存在命题取否定，即得等价式。∎

**定理（主定理）**：算法输出正确——(i) 若扫边发现入侵边，输出 $[0, 1, \dots, n-1]$；(ii) 否则输出 $V \setminus S$。两种情况互斥且完备。

**证明**：由题意 all-or-nothing 语义，答案 $= S$ 可移除 ? $V \setminus S$ : $V$。由引理 2，算法的 `susp` 标记集 $= R$，再由引理 1 即可疑集合 $S$；由引理 3，第 3 步扫边判定的真假恰对应「$S$ 不可移除 / 可移除」。分情况代入即得 (i)、(ii)；判定结果非真即假，故两情况互斥完备。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。建图 $O(m)$；BFS 每点至多入队一次、每条边至多查看一次，合计 $O(n + m)$；扫边判定 $O(m)$（早退只会更快）；收集答案 $O(n)$。$n = 10^5$、$m = 2 \times 10^5$ 时总量约 $5 \times 10^5$ 次基本操作，远低于限制。
- **空间复杂度**：$O(n + m)$。正向邻接表 $O(n + m)$ + 标记数组与队列 $O(n)$（输出数组不计入）。
- **暴力对照**：逐点独立判可达为 $O\big(n(n+m)\big) \approx 3 \times 10^{10}$，超时约两个数量级。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> remainingMethods(int n, int k, vector<vector<int>>& invocations) {
        vector<vector<int>> g(n);
        for (auto& e : invocations) g[e[0]].push_back(e[1]);

        vector<char> susp(n, 0);                   // susp[i]=1 ⇔ i 可疑
        susp[k] = 1;
        queue<int> q;
        q.push(k);
        while (!q.empty()) {                       // BFS：从 k 顺流标记传染闭包（迭代防爆栈）
            int u = q.front(); q.pop();
            for (int v : g[u])
                if (!susp[v]) { susp[v] = 1; q.push(v); }
        }

        for (auto& e : invocations)                // 扫边：外部调用内部 → 一票否决
            if (!susp[e[0]] && susp[e[1]]) {
                vector<int> ans(n);
                iota(ans.begin(), ans.end(), 0);
                return ans;
            }

        vector<int> ans;                           // 无入侵边 → 删光 S，收集幸存者
        for (int i = 0; i < n; ++i)
            if (!susp[i]) ans.push_back(i);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def remainingMethods(self, n: int, k: int, invocations: List[List[int]]) -> List[int]:
        g = [[] for _ in range(n)]
        for a, b in invocations:
            g[a].append(b)

        susp = [False] * n                         # susp[i]=True ⇔ i 可疑
        susp[k] = True
        q = deque([k])
        while q:                                   # BFS：入队即标记，环自动终止
            u = q.popleft()
            for v in g[u]:
                if not susp[v]:
                    susp[v] = True
                    q.append(v)

        for a, b in invocations:                   # 扫边：外部调用内部 → 一票否决
            if not susp[a] and susp[b]:
                return list(range(n))

        return [i for i in range(n) if not susp[i]]
```

> 💡 两个版本对三组官方样例分别输出 `[0,1,2,3]` / `[3,4]` / `[]`；与「逐点独立 BFS」的暴力参照在随机数据（$n \le 9$）上对拍 3000 组全部一致；$n = 10^5$ 长链压力用例（递归版必爆栈）瞬时通过。

## 8. 边界情况与易错点

1. **方向陷阱（本题头号 WA 源）**：把「可疑」扩散到 $k$ 的祖先（谁调用 $k$ 谁可疑）——示例 1 的 $0$ 调用 $1$ 但 $0$ 干净；或把否决条件写成「圈内调用圈外」——反着判会错误地删掉示例 1 的 $\{1,2\}$。记住：删除的受害者是**被调用者**，只有外部指向内部的入边卡删除。
2. **递归爆栈**：$n = 10^5$ 的链状图递归深度同量级，Python 默认上限 1000 必爆，必须用迭代队列/显式栈。
3. **标记时机**：入队即标记。出队才标记会让环上的点被重复入队，直接死循环。
4. **别忘了 $k$ 本身可疑**：`susp[k]` 要预置（既是 BFS 种子，也覆盖「无边」时 $S = \{k\}$ 的情形）。
5. **`invocations` 为空**：不是失败——$S = \{k\}$，无边可扫，直接删 $k$ 返回其余。
6. **$S$ = 全体方法**：返回空数组，这是合法答案，别把「收集结果为空」误当成「失败返回全体」。
7. **一票否决后的返回值**：是**全体方法** $[0, \dots, n-1]$（一个不删），别返回空数组或 $V \setminus S$。
8. **C++ 容器选型**：`vector<bool>` 是位压缩特化，用 `vector<char>` 更稳更快；返回全体时用 `iota` 一行生成。
