# LeetCode 最短且字典序最小的美丽子字符串 题解

## 1. 题目概述

- **标题 / 题号**：最短且字典序最小的美丽子字符串（#2904，medium）
- **链接**：https://leetcode.cn/problems/shortest-and-lexicographically-smallest-beautiful-string/
- **来源**：LeetCode 第 367 场周赛 Q2
- **难度**：中等
- **标签**：字符串、枚举、滑动窗口

**题意**：给定一个二进制字符串 `s` 和正整数 `k`。若 `s` 的某个子串中 `1` 的个数恰好等于 $k$，则称其为**美丽子字符串**。设 $\text{len}$ 为**最短**美丽子串的长度，要求返回**长度恰为 $\text{len}$ 且字典序最小**的美丽子串；若不存在美丽子串，返回空串。

**约束**：

- $1 \le s.length \le 100$
- $1 \le k \le s.length$

> 💡 本题数据范围极小（$n \le 100$），暴力也能通过；但其结构非常经典——「删 0 不改变 1 的个数」直接把候选集合从 $O(n^2)$ 个子串压缩到「1 的位置」上的 $m-k+1$ 个窗口，值得作为套路沉淀。

## 2. 示例

**示例 1**

```text
输入：s = "100011001", k = 3
输出："11001"
解释：s 中 1 的位置为 0, 4, 5, 8，共 7 个美丽子串：
      [0,5]、[0,6]、[0,7]、[1,8]、[2,8]、[3,8]、[4,8]。
      最短美丽子串长度为 5，长度为 5 的只有 "11001"。
```

**示例 2**

```text
输入：s = "1011", k = 2
输出："11"
解释：美丽子串为 "101"、"011"、"11"，最短长度为 2，
      长度为 2 的只有 "11"。
```

**示例 3**

```text
输入：s = "000", k = 1
输出：""
解释：s 中没有 1，不存在美丽子串。
```

## 3. 解题思路

### 3.1 暴力思路：枚举全部子串

$n \le 100$，子串共 $O(n^2) \approx 5000$ 个。对每个子串统计 `1` 的个数（可用前缀和 $O(1)$ 判断），把恰好含 $k$ 个 `1` 的子串全部收集，再按「长度、字典序」双关键字取最小，总体 $O(n^3) \approx 10^6$，本题完全能过。

但这样枚举了大量**带前导 `0` 或多余尾巴**的无效子串——例如示例 1 中 `[1,8]`、`[2,8]`、`[3,8]` 都只是 `[4,8]` 加了前导 `0`。如果 $n$ 放大到 $10^5$，三次方不可接受，思路必须收缩。

### 3.2 核心观察：最短候选首尾都贴着 1

![核心观察：最短美丽子串首尾都贴着 1](images/shortest_beautiful_ones_window.svg)

**关键性质**：删掉子串首部或尾部的 `0`，`1` 的个数不变。于是：

- 若美丽子串以 `'0'` 开头，去掉首字符后仍美丽且更短——所以**最短美丽子串必以 `'1'` 开头**；尾部 `'0'` 同理，必以 `'1'` 结尾。
- 左端点一旦确定为某个 `1` 的位置 $pos[i]$，要**恰好**含 $k$ 个 `1` 且长度最短，右端点唯一：从左端往右数的第 $k$ 个 `1`，即 $pos[i+k-1]$。

记 `1` 的位置数组为 $pos[0..m-1]$，候选只剩 $m-k+1$ 个：$s[pos[i]..pos[i+k-1]]$。在这 $m-k+1$ 个候选中按「长度、字典序」双关键字取最小即为答案。

### 3.3 算法流程

![pos 数组枚举 + 双关键字择优算法流程](images/shortest_beautiful_algorithm_flow.svg)

1. 线性扫描 `s`，收集所有 `1` 的下标到 `pos`，记 `m = pos.size()`
2. 若 $m < k$：`1` 的总数不足，无美丽子串，直接返回 `""`
3. 枚举 $i = 0, 1, \ldots, m-k$，取候选 $t = s[pos[i]..pos[i+k-1]]$（恰好含 $k$ 个 `1`）
4. 双关键字择优：$t$ 更短，或等长且 $t$ 字典序更小 → 更新 `ans`
5. 返回 `ans`

### 3.4 示例演算

![示例演算与同长候选比较陷阱](images/shortest_beautiful_example_walkthrough.svg)

以示例 1 为例，$s = \text{"100011001"}$，$k=3$，$pos = [0, 4, 5, 8]$：

| $i$ | 候选区间 $[pos[i], pos[i+2]]$ | 候选 $t$ | 长度 | 当前最优 |
|-----|------------------------------|----------|------|----------|
| 0 | $[0, 5]$ | `"100011"` | 6 | `"100011"` |
| 1 | $[4, 8]$ | `"11001"` | 5 ✓ | `"11001"` |

长度 5 胜出，返回 `"11001"`。注意两个候选**都首尾贴着 1**，这正是 3.2 性质的体现。

## 4. 算法细节

1. **候选恰好含 $k$ 个 1**：$pos$ 严格递增，下标落在 $[pos[i], pos[i+k-1]]$ 内的 `1` 恰好是 $pos[i], pos[i+1], \ldots, pos[i+k-1]$ 共 $k$ 个——不多不少。

2. **固定左端后右端为何唯一**：左端 $= pos[i]$ 时，子串 $s[pos[i]..r]$ 含 $k$ 个 `1` 要求 $pos[i+k-1] \le r < pos[i+k]$；其中最短的是 $r = pos[i+k-1]$，其余更长的候选不可能成为全局最短（它们都被同左端的更短候选压制）。

3. **双关键字择优**：比较规则是 $\big(\text{len}(t),\ t\big)$ 的字典序——先长度、同长再字典序。**顺序不能反**：`"1011" < "11"`（前缀更小），但题目要求最短优先，答案必须取 `"11"`。

4. **同长候选不能只比起点下标**：反例 $s = \text{"110110"}$，$k=3$，$pos=[0,1,3,4]$，候选 `"1101"`（起点 0）与 `"1011"`（起点 1）同长，逐字符比较知 `"1011"` 更小——起点更靠右反而字典序更小。**必须逐字符比较**。

5. **滑动窗口等价实现**：`right` 主循环 + 超 $k$ 收缩 + 命中 $k$ 后去前导 `0`，每个 `right` 至多产生一个候选，与 `pos` 枚举是同一枚举的两种写法（代码见第 7 节附加版）。

6. **实现取舍**：$n \le 100$ 时 `pos` 版最短最稳，比赛时优先写它；`min + key`（Python）或手写双关键字更新（C++）皆可。

## 5. 正确性证明

**引理 1**：最短美丽子串必以 `'1'` 开头且以 `'1'` 结尾。

**证明**：反证。设美丽子串 $t$ 长度为 $\text{len}$（最短）且以 `'0'` 开头，去掉首字符得 $t'$：长度 $\text{len}-1$，`1` 的个数不变仍为 $k$，故 $t'$ 仍美丽且更短，与 $\text{len}$ 最短矛盾。尾部 `'0'` 同理。∎

**引理 2**：（a）对任意 $0 \le i \le m-k$，子串 $s[pos[i]..pos[i+k-1]]$ 恰含 $k$ 个 `1`；（b）任何**首尾都是 `1`** 且恰含 $k$ 个 `1` 的子串必形如 $s[pos[i]..pos[i+k-1]]$。

**证明**：（a）$pos$ 严格递增，区间 $[pos[i], pos[i+k-1]]$ 内的 `1` 恰为 $pos[i], \ldots, pos[i+k-1]$ 这 $k$ 个。（b）设该子串为 $s[l..r]$，$s[l] = s[r] = \text{'1'}$。设 $l = pos[i]$（$l$ 处是 `1`，故对应 $pos$ 中某个下标 $i$）；子串内的 `1` 依次为 $pos[i], pos[i+1], \ldots, pos[i+k-1]$，其中最后一个是 $pos[i+k-1]$；又 $r$ 处是 `1` 且是子串最后一个字符，即 $r$ 是子串内最后一个 `1`，故 $r = pos[i+k-1]$。∎

**定理**：上述算法返回长度为 $\text{len}$ 的美丽子串中字典序最小者；不存在美丽子串时返回空串。

**证明**：若 $m < k$，`s` 中 `1` 的总数不足 $k$，任何子串都不美丽，算法返回 `""`，正确。否则，候选集合 $C = \{s[pos[i]..pos[i+k-1]] : 0 \le i \le m-k\}$：

- 由引理 2(a)，$C$ 中每个候选都是美丽子串；
- 反之，任何长度为 $\text{len}$（最短长度）的美丽子串，由引理 1 首尾都是 `1`，再由引理 2(b) 必属于 $C$。

于是「长度为 $\text{len}$ 的全部美丽子串」恰好是 $C$ 中长度为 $\text{len}$ 的那些候选。算法按 $(\text{长度}, \text{字典序})$ 双关键字取最小：第一关键字保证取到最短长度 $\text{len}$，第二关键字在等长候选中取字典序最小者，与题目要求一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。收集 `pos` 为 $O(n)$；候选至多 $m-k+1 \le n$ 个，每个候选的切片与字典序比较最坏 $O(n)$，总计 $O(n^2)$。$n \le 100$ 时约 $10^4$ 次字符操作，远低于限制。
- **空间复杂度**：$O(n)$。`pos` 数组与候选/答案串的存储。

> 💡 若 $n$ 放大到 $10^5$：滑动窗口的移动本身均摊 $O(n)$，瓶颈只剩同长候选的字典序比较——可用「二分 + 字符串哈希求 LCP」或后缀数组把每次比较降到 $O(\log n)$，总体 $O(n \log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string shortestBeautifulSubstring(string s, int k) {
        int n = s.size();
        vector<int> pos;
        for (int i = 0; i < n; i++)
            if (s[i] == '1')
                pos.push_back(i);
        if ((int)pos.size() < k)
            return "";

        string ans;
        for (int i = 0; i + k <= (int)pos.size(); i++) {
            string t = s.substr(pos[i], pos[i + k - 1] - pos[i] + 1);
            if (ans.empty() || t.size() < ans.size() ||
                (t.size() == ans.size() && t < ans))
                ans = t;
        }
        return ans;
    }
};
```

### C++（滑动窗口版，与 pos 枚举等价）

```cpp
class Solution {
  public:
    string shortestBeautifulSubstring(string s, int k) {
        string ans;
        int cnt = 0;
        for (int left = 0, right = 0; right < (int)s.size(); right++) {
            cnt += s[right] == '1';
            while (cnt > k)                    // 超载：左端弹出直到 1 的个数 ≤ k
                cnt -= s[left++] == '1';
            if (cnt == k) {
                while (s[left] == '0')         // 去前导 0：以 right 结尾的最短候选
                    left++;
                string t = s.substr(left, right - left + 1);
                if (ans.empty() || t.size() < ans.size() ||
                    (t.size() == ans.size() && t < ans))
                    ans = t;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def shortestBeautifulSubstring(self, s: str, k: int) -> str:
        pos = [i for i, c in enumerate(s) if c == '1']
        if len(pos) < k:
            return ""
        return min((s[pos[i]:pos[i + k - 1] + 1] for i in range(len(pos) - k + 1)),
                   key=lambda t: (len(t), t))
```

> 💡 Python 的元组比较 `(len(t), t)` 天然实现双关键字择优；C++ 需要手写「先长度、同长再字典序」的更新条件，或改用 `std::tie` / `pair` 组装。

## 8. 边界情况与易错点

1. **1 的总数不足**：$m < k$ 时无美丽子串，返回 `""`。`pos` 版**必须显式判断**（否则 `pos[i+k-1]` 越界）；滑窗版 `cnt == k` 永不触发，`ans` 自然保持空串。
2. **全 0 串**：$m = 0$，对任意 $k \ge 1$ 都返回 `""`（含于上一条）。
3. **k = 1**：候选退化为每个孤立的 `"1"`，全部等长（1）等值（`"1"`），答案为 `"1"`（存在 `1` 时）。
4. **双关键字顺序不能反**：只按字典序比较会错——`"1011" < "11"`，但题目要求最短优先，答案应取 `"11"`。
5. **同长候选不能只比起点下标**：反例 $s = \text{"110110"}$，$k=3$：`"1101"`（起点 0）与 `"1011"`（起点 1）同长，后者字典序更小。必须逐字符比较（见 3.4 演算图）。
6. **C++ 细节**：循环条件写成 `i + k <= (int)pos.size()`，避免有符号/无符号比较隐患；`substr(pos[i], pos[i+k-1] - pos[i] + 1)` 的第二参数是**长度**而非右端下标，容易误写为 `pos[i+k-1]`。
7. **空串兜底**：`ans` 初始为 `""`，用 `ans.empty()` 判定首候选；不要把空串混入字典序比较（空串比任何串都小，语义错误）。
8. **去前导 0 的收缩不回退**（滑窗版）：`left` 只在 `s[left]=='0'` 且 `cnt==k` 时右移，`cnt` 不变、不变式保持，`left` 全程单调，两处收缩合计最多 $n$ 次。
