# LeetCode 统计满足 K 约束的子字符串数量 I 题解

## 1. 题目概述

- **标题 / 题号**：统计满足 K 约束的子字符串数量 I（#3258，easy）
- **链接**：https://leetcode.cn/problems/count-substrings-that-satisfy-k-constraint-i/
- **来源**：LeetCode 第 411 场周赛 Q1
- **难度**：简单
- **标签**：字符串、滑动窗口

**题意**：给定一个**二进制**字符串 $s$ 和整数 $k$。若子串中 `0` 的数量最多为 $k$，**或** `1` 的数量最多为 $k$（任一成立即可），则称该子串满足 **k 约束**。返回 $s$ 的所有子串中满足 k 约束的数量。

**约束**：

- $1 \le s.length \le 50$
- $1 \le k \le s.length$
- $s[i]$ 是 `'0'` 或 `'1'`

> 💡 **签到定位**：$n \le 50$ 是白给的数据范围，$O(n^2)$ 暴力两分钟可写完；但本场 **Q4（3261. II 版）就是同一约束定义的强化版**（$n \le 10^5$ + 区间查询）。签到时直接按 Q4 的数据范围选算法、用线性滑窗过 Q1，等于提前把 Q4 的预处理写完——「I 版按 II 版的数据范围选算法」是性价比最高的签到姿势。

## 2. 示例

```text
输入：s = "10101", k = 1
输出：12
解释：除了 "1010"、"10101" 和 "0101" 外，其余子字符串都满足 k 约束。
```

**示例 2**

```text

输出：25
解释：除了长度大于 5 的子字符串（"101010"、"010101"、"1010101"）外，
     其余子字符串都满足 k 约束。
```

**示例 3**

```text
输入：s = "11111", k = 1
输出：15
解释：所有子字符串都满足 k 约束（0 的个数恒为 0 ≤ k）。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举子串 $[i, j]$，右端 $j$ 外扩时**增量**维护 `zeros` / `ones` 两个计数器，判定 `zeros ≤ k 或 ones ≤ k`。总复杂度 $O(n^2) \le 2500$ 次判定，本题可过。

问题在于**判定信息的浪费**：窗口已经「坏」了还继续逐个判定注定失败的超集；II 版把 $n$ 放大到 $10^5$ 后 $O(n^2) = 10^{10}$ 直接超时——需要让每次「坏」的判定直接推动左端点跳跃，而不是原地重复。

### 3.2 核心观察：取逆否——坏子串是「两边都超」

![k 约束的单调性与封闭性](images/kconstraint_window_concept.svg)

**第一步（取逆否）**：合法条件是「或」，直接照抄进收缩循环必错；取逆否后，违反约束 $\iff zeros > k$ **且** $ones > k$——两个计数**都超**才算坏。

**第二步（单调性）**：窗口扩大时 $zeros$ 与 $ones$ 都**单调不减**，因此：

- 坏子串的任何**超集**仍坏——坏对扩窗**封闭**；
- 好子串的任何**子集**仍好——好对缩窗**向下封闭**。

**第三步（按右端点计数）**：固定右端点 $right$，好子串的左端点构成**连续后缀段** $[L, right]$——收缩循环停下来时的 `left` 正是 $L$，以 $right$ 结尾的好子串共 $right - left + 1$ 个，逐右端点累加即可：

$$ans = \sum_{right=0}^{n-1} \bigl(right - left + 1\bigr)$$

### 3.3 算法流程：shrink-while-bad 计数滑窗

![shrink-while-bad 计数滑窗流程](images/kconstraint_algorithm_flow.svg)

标准计数滑窗骨架：$right$ 右移入窗（计数 +1）→ 若**两个计数都超**则左端出窗（计数 −1）→ 累加 $right - left + 1$。**最大易错点**：收缩条件是 `&&`（且），不是 `||`。

### 3.4 示例演算

![示例演算表](images/kconstraint_example_walkthrough.svg)

对 `s = "10101"`、$k = 1$ 走一遍（见上图）：5 步贡献 $1+2+3+3+3 = 12$ ✓。注意 $right = 2$ 时窗口 `"101"` 的 $ones = 2 > k$，但 $zeros = 1 \le k$——**只超一边仍是好窗口**，不收缩；$right = 3$ 时两个计数同时超界才触发收缩。对照总数验证：全部子串 $\frac{5 \times 6}{2} = 15$ 个，坏子串恰为 `"1010"`、`"10101"`、`"0101"` 共 3 个，$15 - 3 = 12$ ✓。

## 4. 算法细节

1. **逆否转换**：合法性「$zeros \le k$ 或 $ones \le k$」的逆否是「$zeros > k$ 且 $ones > k$」，收缩循环 `while (zeros > k && ones > k)` 照抄坏条件——把「或」题面直接搬进循环是第一大坑。
2. **计数器对称更新**：入窗 `(s[right]=='0' ? zeros : ones)++`，出窗 `(s[left++]=='0' ? zeros : ones)--`，同一分支结构一进一出，维护「窗口计数 = 窗口内实况」的不变式。
3. **按右端点归档**：`ans += right - left + 1` 数的是「以 $right$ 结尾」的好子串——左端点取遍 $[left, right]$，与后缀段一一对应。
4. **数据类型**：$n \le 50 \Rightarrow ans \le \frac{50 \times 51}{2} = 1275$，`int` 足够；II 版（$n \le 10^5$）上界约 $5 \times 10^9$，C++ 需换 `long long`。

## 5. 正确性证明

**引理 1（单调性）**：窗口扩大时 $zeros$ 与 $ones$ 均单调不减。

**证明**：$zeros([i, j])$ 是区间上字符指示函数的求和。扩大窗口加入一个字符时，$zeros$ 增量为 $[s = 0] \in \{0, 1\}$，非负；$ones$ 同理。故两个计数均不降。∎

**引理 2（封闭性）**：坏子串的任何超集仍坏；好子串的任何子集仍好。

**证明**：坏 $\iff zeros > k$ 且 $ones > k$。超集的两个计数均不低于原窗口（引理 1），两个严格不等式同时保持，故仍坏。好子串至少满足 $zeros \le k$ 或 $ones \le k$ 之一，其子集对应计数只减不增，同一个不等式继续成立，故仍好。∎

**引理 3（后缀段结构）**：固定 $right$，以 $right$ 为右端点的好子串左端点集合是连续后缀段 $[L, right]$，其中 $L$ 为最小合法左端点；$k \ge 1$ 时 $L$ 必存在且 $L \le right$。

**证明**：对 $L \le start \le right$，$[start, right] \subseteq [L, right]$，由引理 2 好；对 $start < L$，若 $[start, right]$ 好则与 $L$ 的最小性矛盾，故坏。又 $k \ge 1$ 时单字符窗口 $[right, right]$ 计数为 $(1, 0)$ 或 $(0, 1)$，均满足约束，故 $L \le right$，集合非空。∎

**定理**：滑窗算法的返回值等于好子串总数。

**证明（不重不漏）**：每轮累加的是以 $right$ 为右端点的好子串个数。**不重**：不同 $right$ 的类两两互斥，同类内每个左端点恰计一次；**不漏**：`while` 退出时窗口 $[left, right]$ 合法，由引理 3，该类恰含 $right - left + 1$ 个子串，与累加量一致。对全体右端点求和即覆盖全部好子串。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`left` 与 `right` 各自单调右移，全程合计至多 $2n$ 次指针移动（摊还分析），每次移动 $O(1)$。
- **空间复杂度**：$O(1)$。仅 `left`、两个计数器与答案累计变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countKConstraintSubstrings(string s, int k) {
        int n = s.size(), left = 0, zeros = 0, ones = 0, ans = 0;
        for (int right = 0; right < n; ++right) {
            (s[right] == '0' ? zeros : ones)++;
            while (zeros > k && ones > k) {
                (s[left++] == '0' ? zeros : ones)--;
            }
            ans += right - left + 1;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countKConstraintSubstrings(self, s: str, k: int) -> int:
        left = zeros = ones = ans = 0
        for right, ch in enumerate(s):
            if ch == '0':
                zeros += 1
            else:
                ones += 1
            while zeros > k and ones > k:
                if s[left] == '0':
                    zeros -= 1
                else:
                    ones -= 1
                left += 1
            ans += right - left + 1
        return ans
```

## 8. 边界情况与易错点

1. **收缩条件误写 `||`（本题第一大坑）**：会把「只超一边」的好窗口误判为坏、过度收缩而**漏计**。反例：$k = 1$ 的窗口 `"101"`，$ones = 2 > 1$ 但 $zeros = 1 \le 1$，本身合法、应贡献 3；误用 `||` 收缩成 `"01"` 后只贡献 2，漏掉子串 `"101"`。
2. **`left` 不会追过 `right`**：$k \ge 1$ 时单字符窗口恒好，`while` 最迟在 $left = right$ 时停止，无需防御性判空。反例是假想的 $k = 0$：全 `1` 串会缩成空窗（`left = right + 1`）——本题约束 $1 \le k$ 恰好挡住此坑。
3. **全同字符串**：如 `"11111"`，$zeros = 0 \le k$ 恒成立，窗口从不收缩，$ans = \frac{n(n+1)}{2}$（对应示例 3 的 15）。
4. **答案不溢出**：$n \le 50$ 时上界 1275，`int` 安全；II 版 $n \le 10^5$ 需 `long long`。
5. **入窗 / 出窗不对称**是滑窗经典 bug 来源：两个分支结构必须严格互逆，否则窗口计数不变式被破坏。
