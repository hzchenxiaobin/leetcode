# LeetCode 统计定界子数组的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计定界子数组的数目（#2444，hard）
- **链接**：https://leetcode.cn/problems/count-subarrays-with-fixed-bounds/
- **来源**：LeetCode 第 315 场周赛 Q4
- **难度**：困难
- **标签**：数组、滑动窗口、双指针、计数

**题意**：给定整数数组 `nums` 与两个整数 `minK`、`maxK`。子数组是**定界子数组**，当且仅当其**最小值恰好等于 `minK`** 且**最大值恰好等于 `maxK`**。返回定界子数组的数目（子数组为连续段）。

**约束**：

- $2 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i], \text{minK}, \text{maxK} \le 10^6$
- 约束**并未保证** $\text{minK} \le \text{maxK}$（见 §8 边界 3）

> 💡 本题在本仓库另有[每日题解 2444](../../solution/2401-2500/2444_统计定界子数组的数目.md)：侧重三指针的直觉解释、面试表达与同类题矩阵。本篇按周赛复盘视角展开，侧重**赛场识别路径**（如何从 795 一眼看穿）、**分段视角与三指针的等价性**、**引理-定理结构的完整正确性证明**与**边界清单**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,5,2,7,5], minK = 1, maxK = 5
输出：2
解释：定界子数组是 [1,3,5] 和 [1,3,5,2]。
```

**示例 2**

```text
输入：nums = [1,1,1,1], minK = 1, maxK = 1
输出：10
解释：nums 的每个子数组都是定界子数组，共 10 个。
```

**补充示例 3**（minK = maxK + 越界切段）

```text
输入：nums = [2,2,2,7,2], minK = 2, maxK = 2
输出：7
解释：7 把数组切成 [2,2,2] 与 [2] 两段，段间互不连通：
      前段全部 6 个子数组（3+2+1）定界，后段 1 个，共 7 个。
```

**补充示例 4**（minK > maxK，答案恒 0）

```text
输入：nums = [5,5], minK = 6, maxK = 3
输出：0
解释：任何子数组的最小值 ≤ 最大值，而 minK > maxK，不可能同时命中两个等式。
```

## 3. 解题思路

### 3.1 暴力思路：枚举左端点 + 增量极值

```text
ans = 0
for l in 0..n-1:
    mn = +inf, mx = -inf
    for r in l..n-1:
        mn = min(mn, nums[r]); mx = max(mx, nums[r])
        if mn == minK and mx == maxK: ans += 1
```

内层可提前 `break`：一旦 `mn < minK` 或 `mx > maxK`，继续向右延长只会更糟。但「全部元素恰好落在 $[\text{minK}, \text{maxK}]$」的最坏数据（如示例 2 的全 1 数组）一次都断不掉，仍要扫满 $O(n^2)$ 对 $(l, r)$——$n = 10^5$ 时约 $5 \times 10^9$ 步，TLE。

> ⚠️ 瓶颈在于「把极值当状态」：每个 $r$ 都从 $l$ 起重算 `mn/mx`，没有跨子数组的复用。突破口是**按右端点分桶**——对每个 $i$ 单独问「以 $i$ 结尾的定界子数组有几个」，把配对枚举变成 $n$ 个**单点计数**问题。

### 3.2 核心观察：定界 = 三个存在性条件 = 三个最近位置

![核心观察：三个「最近位置」钉死左端点合法区间](images/wc315_bounded_concept.svg)

**观察 1（条件拆解）**：子数组 $[l, i]$ 是定界子数组，当且仅当

1. **无越界元素**：每个元素都落在 $[\text{minK}, \text{maxK}]$ 内；
2. **含 minK**：至少一个元素等于 $\text{minK}$；
3. **含 maxK**：至少一个元素等于 $\text{maxK}$。

「全在界内」给出 $\min \ge \text{minK}$ 与 $\max \le \text{maxK}$，两个存在性条件再把不等号**夹成等号**（§5 引理 2 严格证明）。

**观察 2（存在性条件 → 最近位置）**：三条条件全是**存在性**的——只问「窗口里有没有」，不问「窗口极值是多少」。固定右端点 $i$，设

- $\text{lastInvalid}$：$\le i$ 中**最后一个**越界元素下标（无则 $-1$）；
- $\text{lastMin}$：$\le i$ 中最后一个等于 $\text{minK}$ 的下标（无则 $-1$）；
- $\text{lastMax}$：$\le i$ 中最后一个等于 $\text{maxK}$ 的下标（无则 $-1$）。

三条条件逐一翻译成对左端点 $l$ 的约束：

$$\text{无越界} \iff l > \text{lastInvalid}，\qquad \text{含 minK} \iff l \le \text{lastMin}，\qquad \text{含 maxK} \iff l \le \text{lastMax}$$

求交后合法左端点恰成一段**连续区间**：

$$l \in \bigl(\text{lastInvalid},\; \min(\text{lastMin}, \text{lastMax})\bigr]$$

其长度 $\max\bigl(0,\; \min(\text{lastMin}, \text{lastMax}) - \text{lastInvalid}\bigr)$ 即本步贡献。三个下标随 $i$ 单调滚动、每步 $O(1)$ 更新，全程一趟 $O(n)$。

**观察 3（分段视角：同一件事的另一副眼镜）**：越界元素像一堵「墙」，把数组切成若干**段**；墙不可跨，段与段完全独立。段内没有墙，问题化为「段内同时含 minK 与 maxK 的子数组数」。三指针代码中的 $\text{lastInvalid}$ 天然就是「当前这堵墙」——跨段时它自动前移，**无需显式分段**，两个视角共用同一份 $O(n)$ 代码。补充示例 3 的 $[2,2,2,7,2]$ 正是按墙分成两段各自计数后求和。

**赛场识别路径**：子数组计数 → 固定右端点问左端点合法集合；约束是「极值**等于定值**」而非「极值落在区间」→ 存在性条件 → 最近出现位置。[795. 区间子数组个数](../../solution/0701-0800/795_区间子数组个数.md) 只有条件 1（全在界内），2444 把条件 2、3 加进来，而存在性条件的答案永远写在「最近出现位置」上。识别出这一点，本题从 Hard 降维成一次套路复用。

### 3.3 算法流程

![算法流程：一趟扫描，三指针 O(1) 滚动更新](images/wc315_bounded_flow.svg)

1. 初始化 $\text{lastInvalid} = \text{lastMin} = \text{lastMax} = -1$，$\text{ans} = 0$；
2. 依次扫描右端点 $i = 0, 1, \dots, n-1$，**并列**执行三次判断更新：
   - $\text{nums}[i] < \text{minK}$ 或 $\text{nums}[i] > \text{maxK}$：$\text{lastInvalid} \gets i$；
   - $\text{nums}[i] = \text{minK}$：$\text{lastMin} \gets i$；
   - $\text{nums}[i] = \text{maxK}$：$\text{lastMax} \gets i$；
3. 累加贡献 $\text{ans} \mathrel{+}= \max\bigl(0,\; \min(\text{lastMin}, \text{lastMax}) - \text{lastInvalid}\bigr)$；
4. 扫描结束，返回 $\text{ans}$。

### 3.4 示例演算

![示例演算：nums=[1,3,5,2,7,5] 的六步指针表](images/wc315_bounded_walkthrough.svg)

以示例 1 逐行跟踪（完整指针表见上图）：

- $i = 2$：`5` 让 $\text{lastMax}$ 首次就位（$=2$），$\text{lastMin} = 0$，贡献 $\min(0, 2) - (-1) = 1$——左端点只能取 $l = 0$，即 $[1,3,5]$；
- $i = 3$：指针全部不动，贡献仍为 $1$——中间插入的 `2` 不影响极值命中，得 $[1,3,5,2]$；
- $i = 4$：`7` 越界，$\text{lastInvalid}$ 跳到 $4$。此后 $\min(\text{lastMin}, \text{lastMax}) - \text{lastInvalid} \le 0$，贡献恒 0——即便 $i = 5$ 重新出现 `5` 刷新了 $\text{lastMax}$，左墙 $4$ 也已越过所有 minK 位置，救不回来。

合计 $\text{ans} = 2$ ✓。

示例 2（$\text{minK} = \text{maxK} = 1$）：每步**双更新** $\text{lastMin} = \text{lastMax} = i$，贡献 $i - (-1) = i + 1$，合计 $1 + 2 + 3 + 4 = 10$ ✓。此时三指针退化为**等差求和**——这也是 §8 边界 2「必须并列 if」的最好例证：若写成 `elif`，示例 2 只会得 $6$。

## 4. 算法细节

1. **三指针语义钉死在「$\le i$ 的最近一次出现」**：初值全为 $-1$ 表示「尚未出现」。只记最近、不记全部出现位置——存在性条件只关心「最近的会不会被左端点甩出窗外」。
2. **三次更新必须并列 `if`，不能 `if/elif`**：$\text{minK} = \text{maxK}$ 时同一元素同时命中两个等值分支，漏更新一个指针就漏计一整片子数组。
3. **贡献公式的取零**：$\max(0, \cdot)$ 处理「墙越过锚点」的时段（示例 1 的 $i \ge 4$）。每步贡献 $\le n \le 10^5$，用 `int` 取零后累加进 `long long` 即可——**不要**写 `max(0LL, min(...) - lastInvalid)`：`0LL` 与 `int` 实参类型不一致，`std::max` 模板推导直接编译报错（这是不少题解里潜伏的暗坑）。
4. **答案必须 64 位**：全数组元素 $= \text{minK} = \text{maxK}$ 时答案 $\frac{n(n+1)}{2} \approx 5 \times 10^9$，超出 32 位 `int` 上限（$\approx 2.1 \times 10^9$）。返回值与累加器用 `long long`，Python 天然安全。
5. **为什么不用单调队列/单调栈**：本题约束是「窗口内**是否含有**某值」——存在性，最近位置即充分统计量；只有「窗口**极值**」类约束才需要单调结构。判别口诀：**存在性看最近，极值看单调**。
6. **分段写法与三指针是同一件事**：按墙切段、段内计数的显式两重循环版，等价于维护 $\text{lastInvalid}$ 的一趟版——段起点恰是 $\text{lastInvalid} + 1$。分段版多一层循环不多一分正确性，赛场上直接写指针版最短。

## 5. 正确性证明

固定右端点 $i$，记 $p$ 为 $\le i$ 中最大的越界元素下标、$q$ 为 $\le i$ 中最大的等于 $\text{minK}$ 的下标、$r$ 为 $\le i$ 中最大的等于 $\text{maxK}$ 的下标（三者均无则取 $-1$）。

**引理 1（越界即墙）**：若 $[l, i]$ 含越界元素（$< \text{minK}$ 或 $> \text{maxK}$），则 $[l, i]$ 不是定界子数组。

**证明**：设 $\text{nums}[k] \in [l, i]$ 越界。若 $\text{nums}[k] < \text{minK}$，则 $[l,i]$ 的最小值 $\le \text{nums}[k] < \text{minK}$；若 $\text{nums}[k] > \text{maxK}$，则 $[l,i]$ 的最大值 $\ge \text{nums}[k] > \text{maxK}$。两种情形极值均偏离目标。∎

**引理 2（三条件拆解）**：$[l, i]$ 是定界子数组 $\iff$ ①所有元素 $\in [\text{minK}, \text{maxK}]$；②至少一个元素 $= \text{minK}$；③至少一个元素 $= \text{maxK}$。

**证明**：（$\Leftarrow$）①给出最小值 $\ge \text{minK}$、最大值 $\le \text{maxK}$；②中的元素值恰为 $\text{minK}$，给出最小值 $\le \text{minK}$，夹逼得最小值 $= \text{minK}$；同理最大值 $= \text{maxK}$。（$\Rightarrow$）最小值在子数组中取得，故存在元素 $= \text{minK}$，②成立；同理③成立；又每个元素 $\ge$ 最小值 $= \text{minK}$、$\le$ 最大值 $= \text{maxK}$，①成立。∎

**引理 3（左端点区间刻画）**：对任意 $0 \le l \le i$：

$$[l, i] \text{ 是定界子数组} \iff p < l \le \min(q, r).$$

**证明**：先证「$[l, i]$ 含越界元素 $\iff l \le p$」。若 $l \le p$，由 $p \le i$ 得 $p \in [l, i]$，且 $\text{nums}[p]$ 越界；反之若某 $k \in [l, i]$ 越界，由 $p$ 的最大性 $l \le k \le p$。同理论证「$[l, i]$ 含 $\text{minK}$ $\iff l \le q$」与「含 $\text{maxK}$ $\iff l \le r$」（当 $q = -1$，即 $[0, i]$ 内无 $\text{minK}$ 时，左边恒假，而右边 $l \ge 0 > -1$ 亦假，等价仍成立；$r$ 同理）。将引理 2 的三条件按上述等价改写为 $l > p$、$l \le q$、$l \le r$，求交即得 $p < l \le \min(q, r)$。∎

**定理**：算法返回的 $\text{ans}$ 等于定界子数组总数，且每个右端点 $i$ 的贡献恰为 $\max\bigl(0, \min(q, r) - p\bigr)$。

**证明**：每个子数组由 $(l, i)$ 唯一确定，总数 $= \sum_{i=0}^{n-1} N(i)$，其中 $N(i)$ 是以 $i$ 为右端点的定界子数组个数。由引理 3，以 $i$ 为右端点的合法左端点集合是整数区间 $(p, \min(q, r)]$：当 $\min(q, r) > p$ 时其大小为 $\min(q, r) - p$，否则为空、大小 $0$——即 $N(i) = \max(0, \min(q, r) - p)$。算法在扫描 $i$ 时维护的三个指针正是 $p, q, r$（更新规则与定义一致），累加项正是 $N(i)$，故每个定界子数组按其唯一右端点被恰好计数一次，不重不漏。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。右端点 $i$ 单调前进一遍，每步三次比较、一次 $\min/\max$、一次累加，全为 $O(1)$；无回退、无重扫、无排序。
- **空间复杂度**：$O(1)$。仅三个下标变量与一个 64 位累加器，不需要显式分段数组、哈希表或任何辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long countSubarrays(vector<int>& nums, int minK, int maxK) {
        long long ans = 0;
        int lastInvalid = -1, lastMin = -1, lastMax = -1;
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (nums[i] < minK || nums[i] > maxK) lastInvalid = i;
            if (nums[i] == minK) lastMin = i;
            if (nums[i] == maxK) lastMax = i;
            ans += max(0, min(lastMin, lastMax) - lastInvalid);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countSubarrays(self, nums: List[int], minK: int, maxK: int) -> int:
        ans = 0
        last_invalid = last_min = last_max = -1
        for i, x in enumerate(nums):
            if not minK <= x <= maxK:
                last_invalid = i
            if x == minK:
                last_min = i
            if x == maxK:
                last_max = i
            ans += max(0, min(last_min, last_max) - last_invalid)
        return ans
```

## 8. 边界情况与易错点

1. **答案溢出 32 位**：全数组 $= \text{minK} = \text{maxK}$ 时答案 $\frac{n(n+1)}{2} \approx 5 \times 10^9$。返回值与累加器必须 `long long`——每步贡献 $\le n \le 10^5$ 在 `int` 内取零后 `ans +=` 即可，C++ 隐式转换安全；但 `max(0LL, <int表达式>)` 因两参类型不合**编译不过**，别照抄这行暗坑。
2. **minK = maxK**（示例 2）：同一元素要同时刷新 `lastMin` 与 `lastMax`。写成 `if/elif` 会让示例 2 输出 $6$ 而非 $10$——本题最高频 WA 点。
3. **minK > maxK**（约束未禁止）：任何元素都必然越界（$x \ge \text{minK} \Rightarrow x > \text{maxK}$），每步 $\text{lastInvalid} = i$ 把贡献压成 $0$，答案自然为 $0$，**无需特判**——前提是越界判断同时写了 `< minK` 与 `> maxK` 两个方向。
4. **数组中不含 minK 或 maxK**：对应指针停在 $-1$（或被甩出的旧位置），区间非正，全程贡献 $0$，同样无需特判。
5. **贡献的 $\max(0, \cdot)$ 不能省**：墙立起后 $\min(q, r) - p$ 是负数（示例 1 的 $i \ge 4$ 时为 $0 - 4$），漏掉取零会把负数加进答案。
6. **指针初值用 −1 而不是 0**：下标 $0$ 是合法位置；用 $0$ 初始化会在「首元素即 minK/maxK」时错误排除 $l = 0$。
7. **赛时自检数据**：`[1,1,1,1]`（期望 10，抓 `elif` 漏更新）；`[1,3,5,2,7,5]`（期望 2，抓墙逻辑）；`[2,2,2,7,2]`（期望 7，分段 + minK=maxK 复合）；`minK > maxK`（期望 0）。四个都过，本题基本稳。

**延伸思考**：其一，若想避开「最近位置」的灵感，可走**容斥**——答案 = （全在界内）−（全在界内且无 minK）−（全在界内且无 maxK）+（全在界内且两者皆无），四项各自是「元素全落在某区间」的 795 式滑窗，合计至多四趟 $O(n)$，长但稳。其二，把条件改成「最小值 $\ge \text{minK}$ 且最大值 $\le \text{maxK}$」，存在性条件消失，就回到 795 本身；改成「maxK 出现至少 K 次」则通向 2962。其三，若数组带在线修改，「最近位置」不可增量维护，需在线段树上做区间合并（每段记录最近的 minK/maxK/invalid 位置）——那是另一档难度的工程题。
