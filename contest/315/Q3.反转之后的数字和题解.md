# LeetCode 反转之后的数字和 题解

## 1. 题目概述

- **标题 / 题号**：反转之后的数字和（#2443，medium）
- **链接**：https://leetcode.cn/problems/sum-of-number-and-its-reverse/
- **来源**：LeetCode 第 315 场周赛 Q3
- **难度**：中等
- **标签**：数学、枚举、数位反转

**题意**：给定**非负**整数 `num`，判断是否存在**非负**整数 $k$ 使得 $k + \text{reverse}(k) = \text{num}$：存在返回 `true`，否则返回 `false`。其中 $\text{reverse}(k)$ 表示把 $k$ 的十进制数位整体倒序后得到的数，反转后**可能出现前导零**（如 $\text{reverse}(140) = 041 = 41$），前导零在数值意义下自然消去。

**约束**：

- $0 \le \text{num} \le 10^5$

> 💡 本题在本仓库另有[每日题解 2443](../../solution/2401-2500/2443_反转之后的数字和.md)：侧重枚举上界的直觉解释与「大 num 按位构造」的扩展。本篇按周赛复盘视角展开，侧重**赛场识别路径**（值域即枚举许可证）、**枚举完备性与反转正确性的完整证明**、**「砍半」对称剪枝为何是陷阱**与**边界清单**，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：枚举 k，逐一检验

题目只问**存在性**——这是最友好的问法：枚举到一个满足条件的 $k$ 就可以立刻返回 `true`，不必计数、不必构造所有解。剩下唯一的问题是：**$k$ 要枚举到哪为止？**

$k$ 与 $\text{reverse}(k)$ 都是非负整数，由 $k + \text{reverse}(k) = \text{num}$ 移项得

$$k = \text{num} - \text{reverse}(k) \le \text{num}$$

所以**解只可能出现在 $[0, \text{num}]$ 内**：

```text
for k in 0 .. num:
    if k + reverse(k) == num:
        return true        # 存在性判定，命中即停
return false
```

由约束 $\text{num} \le 10^5$，候选 $k$ 至多 $10^5 + 1$ 个；每个 $k$ 的反转是 $O(d)$ 的取模整除循环（$d \le 6$ 为 $k$ 的位数），总运算量约 $6 \times 10^5$ 次基本运算。**这个一次遍历就是本题的最优解**——不需要任何更深的数学。赛场上这道题的价值全在三分钟内把上界推导写对，而不是想出花活：按位构造、数论刻画在这里都是大材小用。

### 3.2 核心观察：解被「钉」死在 [0, num]

![核心观察：rev(k) ≥ 0 ⟹ k ∈ [0, num]，前导零与末尾零的两种待遇](images/2443_enumeration_concept.svg)

**观察 1（上界）**：$\text{reverse}(k) \ge 0$ 与 $k \ge 0$ 一起，把候选 $k$ 「钉」在数轴的 $[0, \text{num}]$ 段上。上界不是猜出来的，是一行不等式的产物——这也是「枚举-检验」范式的标准起手式：**先证枚举范围完备，再谈检验**。

**观察 2（前导零自动消去）**：$\text{reverse}(140) = 041 = 41$。数值反转 `rev = rev*10 + t%10` 遇到末尾的 $0$ 时只在 `rev = 0` 阶段原地踏步（$0 \times 10 + 0 = 0$），不贡献任何位值；字符串写法 `int("041")` 同样自动丢弃。两种写法行为一致，**无需任何特判**——示例 3 已经替我们把这条路趟平了。

**观察 3（砍半是陷阱）**：直觉上 $k$ 与 $\text{reverse}(k)$ 在和式中「地位对等」，似乎只需枚举 $k \le \text{num}/2$。但**末尾零打破对称性**：对 $k \ge 1$，$\text{reverse}(\text{reverse}(k)) = k$ 当且仅当 $k$ 不以 $0$ 结尾。$k = 140$ 命中 $\text{num} = 181$，而它的「对称伙伴」$41$ 满足的是 $41 + 14 = 55 \ne 181$——按对偶性跳过 $k = 140$ 就会把解跳丢。**老老实实扫满 $[0, \text{num}]$**，$O(\text{num})$ 本就够快。

### 3.3 算法流程

![算法流程：枚举 → 反转 → 检验，命中即提前返回](images/2443_algorithm_flow.svg)

1. $k \gets 0$；
2. 若 $k > \text{num}$：区间扫完仍无命中，返回 `false`；
3. 数值反转求 $\text{reverse}(k)$：`rev = 0`，每轮 `rev = rev*10 + t%10`、`t /= 10`，直到 `t = 0`；
4. 若 $k + \text{reverse}(k) = \text{num}$：返回 `true`；
5. 否则 $k \gets k + 1$，回到步骤 2。

整个循环体只有一个乘加循环与一次比较，是「枚举-检验」范式的最简形态。

### 3.4 示例演算

![示例演算：num=443 命中 k=172，附 63/181/0 三个判定](images/2443_example_walkthrough.svg)

以 `num = 443` 为例（下表仅列关键值，中间的 $k$ 同构检验）：

| $k$ | $\text{reverse}(k)$ | $k + \text{reverse}(k)$ | $= 443$？ |
|-----|--------------------|--------------------------|-----------|
| 0 | 0 | 0 | ✗ |
| 100 | 1（001，前导零消去）| 101 | ✗ |
| 140 | 41（041）| 181 | ✗（恰是示例 3 的解）|
| 170 | 71（071）| 241 | ✗ |
| 171 | 171 | 342 | ✗ |
| **172** | **271** | **443** | ✅ 命中，返回 `true` |

对照其余输入的判定依据：

- `num = 63`：一位数 $k$ 的和 $2k$ 是偶数；两位数 $k = 10a + b$ 的和是 $11(a+b)$，必为 $11$ 的倍数，而 $63$ 不是；三位数 $k$ 的和 $\ge 101 > 63$。三类全部落空，返回 `false`。
- `num = 181`：枚举到 $k = 140$ 命中，$140 + 041 = 181$，前导零不碍事。
- `num = 0`：$k = 0$ 即命中，$0 + 0 = 0$——**别把 $k = 0$ 漏在枚举范围外**。

## 4. 算法细节

1. **上界来自不等式而非猜测**：$k + \text{reverse}(k) = \text{num}$ 与 $\text{reverse}(k) \ge 0$ 联立得 $k \le \text{num}$。循环写成 `for (int k = 0; k <= num; ++k)`，两端闭区间，$k = 0$ 自然覆盖 $\text{num} = 0$ 的情形，无需特判。
2. **数值反转模板**：`rev` 从 $0$ 出发，每轮 `rev = rev*10 + t%10` 后 `t /= 10`，循环次数恰为 $k$ 的位数 $d$；$k = 0$ 时循环零轮、`rev = 0`，同样无需特判。
3. **存在性 → 提前返回**：命中即 `return true`，只有无解的最坏情形才扫满全区间。不要先收集全部解再判空——那是计数题的写法，存在性判定用不上。
4. **值域与溢出**：$k \le 10^5$，$\text{reverse}(k) \le 99999$，故 $k + \text{reverse}(k) \le 199998$，32 位 `int` 绰绰有余。与第 7 题「整数反转」不同，本题**没有任何溢出防护**的必要。
5. **两种反转写法**：C++ 数值循环零分配、最高效；Python 可用 `int(str(k)[::-1])` 一行搞定，`int("041") = 41` 自动消去前导零，`str(0)[::-1] = "0"` 亦得 $0$，与数值法行为完全一致。

## 5. 正确性证明

**引理 1**（解的范围）：若非负整数 $k$ 满足 $k + \text{reverse}(k) = \text{num}$，则 $0 \le k \le \text{num}$。

**证明**：$k \ge 0$ 是题设。$\text{reverse}(k)$ 是 $k$ 的数位倒排，作为整数非负，故 $k = \text{num} - \text{reverse}(k) \le \text{num}$。∎

**引理 2**（数值反转的正确性与前导零消去）：设 $k \ge 1$ 的十进制表示自高位到低位为 $b_1 b_2 \cdots b_d$（$b_1 \ne 0$，允许 $b_d = 0$），则循环 `rev = 0; t = k; while t > 0: rev = rev*10 + t%10; t /= 10` 结束时

$$\text{rev} = \sum_{i=1}^{d} b_i \cdot 10^{\,i-1} = b_d b_{d-1} \cdots b_1 \ \text{（作为整数）}，$$

特别地，$k$ 末尾的零对应项 $b_d \cdot 10^{d-1} = 0$，倒排后的前导零自动消去；$k = 0$ 时循环零轮，$\text{rev} = 0$。

**证明**：对循环轮数 $j$ 归纳：$j$ 轮后 $\text{rev}_j = \sum_{i=1}^{j} b_{d-i+1} \cdot 10^{\,j-i}$（先取出者居于高位）。$j = 0$ 时 $\text{rev}_0 = 0$ 平凡成立。归纳步骤：第 $j+1$ 轮取出 $t$ 的当前末位，此刻 $t$ 已被砍去 $j$ 位，末位即 $b_{d-j}$，于是

$$\text{rev}_{j+1} = \text{rev}_j \times 10 + b_{d-j} = \sum_{i=1}^{j} b_{d-i+1} \cdot 10^{\,j-i+1} + b_{d-j} \cdot 10^{0} = \sum_{i=1}^{j+1} b_{d-i+1} \cdot 10^{\,j+1-i}，$$

归纳完成。$j = d$ 时换元 $i' = d - i + 1$ 得 $\text{rev} = \sum_{i'=1}^{d} b_{i'} \cdot 10^{\,i'-1}$，即数位倒排构成的整数；末尾零的项系数为零、不贡献位值。∎

**定理**：算法返回 `true` 当且仅当存在非负整数 $k$ 使 $k + \text{reverse}(k) = \text{num}$。

**证明**：（$\Leftarrow$）设这样的 $k$ 存在。由引理 1，$k \in [0, \text{num}]$，必被循环枚举到；由引理 2，该轮计算的 `rev` 恰为 $\text{reverse}(k)$，检验 $k + \text{rev} = \text{num}$ 通过，返回 `true`。（$\Rightarrow$）算法仅在某个被枚举的 $k_0 \in [0, \text{num}]$ 上检验通过时返回 `true`，此时 $k_0$ 非负且 $k_0 + \text{reverse}(k_0) = \text{num}$，所求 $k$ 存在。若循环耗尽仍无命中，由引理 1 区间之外不存在解，返回 `false` 正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\text{num} \cdot d)$，其中 $d \le 6$ 是 $k$ 的位数（$k \le 10^5$），故等价于 $O(\text{num})$。最坏情形 $\text{num} = 10^5$ 无解时全区间扫描，约 $6 \times 10^5$ 次取模/整除；有解时提前返回，平均更少。
- **空间复杂度**：$O(1)$。仅 `k / t / rev` 三个整型变量，原地反转，无任何额外数据结构。

## 7. 参考代码

### C++（数值反转 + 枚举检验）

```cpp
class Solution {
public:
    bool sumOfNumberAndReverse(int num) {
        for (int k = 0; k <= num; ++k) {
            int rev = 0;
            for (int t = k; t > 0; t /= 10) {
                rev = rev * 10 + t % 10;
            }
            if (k + rev == num) {
                return true;
            }
        }
        return false;
    }
};
```

### Python（字符串反转 + 枚举检验）

```python
class Solution:
    def sumOfNumberAndReverse(self, num: int) -> bool:
        for k in range(num + 1):
            if k + int(str(k)[::-1]) == num:
                return True
        return False
```

## 8. 边界情况与易错点

1. **`num = 0` 必为 `true`**：$k = 0$ 命中（$0 + 0 = 0$）。若把循环从 $k = 1$ 起步、或把 $\text{reverse}(0)$ 误当 $1$，直接 WA；数值与字符串两种写法在 $k = 0$ 都得 $0$，无特判必要。
2. **前导零只认数值**：$181 = 140 + 041$，检验的是整数相等，`041` 与 `41` 是同一个数；若用字符串比较会引入假差异。
3. **砍半枚举是陷阱**：$k$ 与 $\text{reverse}(k)$ 的「对等」在 $k$ 含末尾零时失效（$\text{reverse}(\text{reverse}(140)) = 14 \ne 140$），跳过 $k > \text{num}/2$ 会漏掉 $k = 140$ 这类解。全区间扫描是安全下限，且 $O(\text{num})$ 本就足够快。
4. **无溢出风险**：$k + \text{reverse}(k) \le 199998 < 2^{31}$，不需要第 7 题那套溢出防护；反之若值域升到 $10^{18}$，`rev * 10` 的中间量需换 `__int128` 或字符串反转。
5. **存在性 ≠ 计数**：命中即 `return true`，别先统计解的个数再判非零——最坏情形会白白放弃提前返回的收益。
6. **赛时自检数据**：`num = 1` 是最小无解输入（$k \in \{0, 1\}$ 给出 $\{0, 2\}$）；`num = 63` 官方无解样例；`num = 181` 前导零样例；`num = 0` 下界样例。四个都过，本题基本稳。
