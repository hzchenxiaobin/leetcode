# LeetCode 反转之后不同整数的数目 题解

## 1. 题目概述

- **标题 / 题号**：反转之后不同整数的数目（#2442，medium）
- **链接**：https://leetcode.cn/problems/count-number-of-distinct-integers-after-reverse-operations/
- **来源**：LeetCode 第 315 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、数学、计数

**题意**：给定一个由**正整数**组成的数组 `nums`。必须取出数组中的**每个**整数，**反转其数位**，并将反转后得到的数字**添加到数组末尾**（只对原有整数执行一次）。返回结果数组中**不同整数**的数目。

**约束**：

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^6`

## 2. 示例

**示例 1**

```text
输入：nums = [1,13,10,12,31]
输出：6
解释：反转每个数字后，结果数组是 [1,13,10,12,31,1,31,1,21,13]。
      注意对于整数 10，反转之后会变成 01，即 1。
      数组中不同整数的数目为 6（数字 1、10、12、13、21 和 31）。
```

**示例 2**

```text
输入：nums = [2,2,2]
输出：1
解释：反转每个数字后，结果数组是 [2,2,2,2,2,2]，不同整数只有 2 这一个。
```

**补充示例 3**（前导零极端情形）

```text
输入：nums = [10]
输出：2
解释：结果数组是 [10, 1]，rev(10) = 01 = 1，不同整数为 10 和 1。
```

## 3. 解题思路

### 3.1 暴力思路：按题意字面模拟

最直白的做法是完全照题面执行：遍历 `nums` 求出每个反转数，把 `n` 个反转数**真的拼接**到数组末尾得到长度 `2n` 的结果数组，再统计其中不同整数的个数。

```text
result = nums + [rev(x) for x in nums]
return len(set(result))
```

时间 $O(n \cdot d)$（$d$ 为数位个数）、空间 $O(2n)$，在本题范围下可以通过。但**拼接这一步是纯浪费**——题目只问「不同整数的数目」，这 `2n` 个元素一个都不需要单独保存，边算边扔进集合即可。

### 3.2 核心观察：答案就是并集大小

![核心观察：原数与反转数一起倒入哈希集合](images/2442_reverse_set_concept.svg)

**关键观察**：结果数组的元素恰由两部分组成——`n` 个原数与 `n` 个反转数，因此

$$\text{答案} = \left| \{\, x : x \in nums \,\} \cup \{\, rev(x) : x \in nums \,\} \right|$$

而**哈希集合的插入天然幂等**（重复加入无副作用），把每个 $x$ 与 $rev(x)$ 都丢进集合，集合大小就是答案，一遍扫描解决。

第二个要点是**前导零**：`10` 反转得 `01`，作为整数就是 `1`。数值反转 `rev = rev * 10 + t % 10` 的过程中，开头的零只在 `rev = 0` 时原地踏步（$0 \times 10 + 0 = 0$），不会贡献任何位值，**天然丢弃前导零**，无需特判。

### 3.3 算法流程

![算法流程：遍历 + 反转 + 入集合](images/2442_digit_reverse_flow.svg)

一遍扫描，对每个 `num` 依次做三件事：

1. **原数入集**：`s.insert(num)`
2. **反转数位**：`rev = 0; while t > 0: rev = rev*10 + t%10; t /= 10`，循环次数为 `num` 的位数 $d \le 7$
3. **反转数入集**：`s.insert(rev)`

遍历结束返回 `s.size()`。

### 3.4 示例演算

![示例演算：nums = [1,13,10,12,31]](images/2442_example_walkthrough.svg)

以 `nums = [1,13,10,12,31]` 为例：

| 步骤 | `num` | `rev(num)` | 加入后集合 | 大小 |
|------|-------|-----------|-----------|------|
| 0 | 1 | 1 | {1} | 1 |
| 1 | 13 | 31 | {1, 13, 31} | 3 |
| 2 | 10 | **1**（前导零丢弃） | {1, 10, 13, 31} | 4 |
| 3 | 12 | 21 | {1, 10, 12, 13, 21, 31} | 6 |
| 4 | 31 | 13（均已存在） | 不变 | 6 |

注意两处：第 2 步 `rev(10) = 01 = 1` 与已入集的 `1` 撞车，本步只新增 `10` 一个元素；第 4 步 `31` 与 `rev(31) = 13` 全部已在集合中，集合原地不动。最终 $|S| = 6$。

## 4. 算法细节

1. **数值反转模板**：`rev` 从 `0` 出发，每轮把 `rev` 左移一位（乘 `10`）再拼上 `t` 的末位（`t % 10`），同时 `t` 砍掉末位（整除 `10`）。`t` 的位数就是循环次数。
2. **每个元素恰好两次插入**：$x$ 与 $rev(x)$ 各一次，缺一不可——只插 `rev` 会丢掉原数（如 `nums = [12]`，答案是 2 而非 1）。
3. **位数上界**：$nums[i] \le 10^6$，故 $d \le 7$，单次反转至多 7 轮乘加；反转值也不超过 $999999$，`int` 完全够用。
4. **两种反转写法**：C++ 用数值循环取模（无额外分配，最高效）；Python 可用 `int(str(x)[::-1])` 一行搞定，`int("01")` 同样自动丢弃前导零，行为与数值法一致。

## 5. 正确性证明

**引理 1**（问题等价于并集计数）：题面操作生成的结果数组，其不同整数构成的集合恰为 $S^* = \{\,x_i\,\} \cup \{\,rev(x_i)\,\}$，答案为 $|S^*|$。

**证明**：操作生成的 $2n$ 个元素依次为 $x_1, \dots, x_n, rev(x_1), \dots, rev(x_n)$，追加顺序不影响去重结果。一个整数出现在结果数组中，当且仅当它等于某个 $x_i$ 或某个 $rev(x_i)$，故不同整数的集合恰为 $S^*$。∎

**引理 2**（数值反转的正确性）：设 $x \ge 1$ 的十进制表示自高位到低位为 $b_1 b_2 \cdots b_d$（$b_1 \ne 0$），则循环结束后 $rev = \sum_{i=0}^{d-1} b_{d-i} \, 10^{i}$，即数位倒序后的整数；特别地，$x$ 末尾的零（倒序后位于最高位）不产生任何贡献。

**证明**：对循环轮数 $k$ 归纳。循环每轮取出 $t$ 的末位，第 $k$ 轮取出的恰是 $b_{d-k+1}$。归纳假设：$k$ 轮后 $rev_k = \sum_{i=0}^{k-1} b_{d-i} \, 10^{i}$。$k=0$ 时 $rev_0 = 0$ 平凡成立。若 $k-1$ 轮时成立，则第 $k$ 轮

$$rev_k = rev_{k-1} \times 10 + b_{d-k} = \sum_{i=0}^{k-2} b_{d-i} \, 10^{i+1} + b_{d-k} = \sum_{i=0}^{k-1} b_{d-i} \, 10^{i}$$

故 $d$ 轮后 $rev_d = b_d b_{d-1} \cdots b_1$（作为整数）。若 $b_d = 0$，其项 $b_d \cdot 10^{d-1} = 0$，不贡献位值——这正是前导零自动丢弃的原因。∎

**定理**：算法返回的 `s.size()` 等于结果数组中不同整数的数目。

**证明**：算法构造的集合 $S$ 满足 $S = S^*$。一方面，每次插入的元素是某个 $x_i$ 或某个 $rev(x_i)$，故 $S \subseteq S^*$；另一方面，每个 $x_i$ 被步骤②插入，每个 $rev(x_i)$ 被步骤③④插入，且由引理 2，计算出的 `rev` 确为数位反转值，故 $S^* \subseteq S$。由引理 1，返回值 $|S| = |S^*|$ 即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot d)$，其中 $d \le 7$ 为 $nums[i]$ 的数位个数，故等价于 $O(n)$。哈希集合单次插入平均 $O(1)$，共 $2n$ 次。
- **空间复杂度**：$O(n)$。最坏情况下 $2n$ 个插入值互不相同，集合存储至多 $2n$ 个整数。

## 7. 参考代码

### C++（数值反转 + 哈希集合）

```cpp
class Solution {
public:
    int countDistinctIntegers(vector<int>& nums) {
        unordered_set<int> s;
        for (int x : nums) {
            s.insert(x);
            int rev = 0;
            for (int t = x; t > 0; t /= 10) {
                rev = rev * 10 + t % 10;
            }
            s.insert(rev);
        }
        return (int)s.size();
    }
};
```

### Python（字符串反转 + 集合）

```python
class Solution:
    def countDistinctIntegers(self, nums: List[int]) -> int:
        s = set(nums)
        for x in nums:
            s.add(int(str(x)[::-1]))
        return len(s)
```

## 8. 边界情况与易错点

1. **前导零**：`10 → 01 = 1`，极端如 `1000000 → 1`（六个零全丢）。数值反转与 `int(str(...))` 都天然处理；但若用字符串形式去重，必须先转回整数或去掉前导零，否则 `"01"` 与 `"1"` 会被误判为两个不同元素。
2. **两次插入缺一不可**：只插 `rev(x)` 不插 `x` 是错的（`nums = [12]` 的答案是 2 不是 1）；反之只插 `x` 忘插 `rev` 更错。
3. **无需溢出防护**：$nums[i] \le 10^6$，反转值 $\le 999999$，与第 7 题「整数反转」不同，不需要任何溢出判断。
4. **别真拼接数组**：构造长度 $2n$ 的中间数组是多余的 $O(n)$ 空间，虽能过，但应养成「只问计数就不构造」的直觉。
5. **退化输入**：`n = 1`（`[7]` → 1）与全相同元素（`[2,2,2]` → 1）算法天然处理，无需特判。
6. **答案上界**：$|S| \le 2n$，可达吗？可达——如 `nums = [12, 13]` 时 `{12, 21, 13, 31}` 大小为 4，估算复杂度时可按 $2n$ 计。
