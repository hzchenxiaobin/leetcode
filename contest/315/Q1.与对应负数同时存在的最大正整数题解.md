# LeetCode 与对应负数同时存在的最大正整数 题解

## 1. 题目概述

- **标题 / 题号**：与对应负数同时存在的最大正整数（#2441，easy）
- **链接**：https://leetcode.cn/problems/largest-positive-integer-that-exists-with-its-negative/
- **来源**：LeetCode 第 315 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序、双指针

**题意**：给定一个**不含零**的整数数组 `nums`，返回最大的正整数 `k`，要求 `k` 与其相反数 `-k` **同时**出现在数组中；不存在这样的整数则返回 `-1`。

**约束**：

- `1 <= nums.length <= 1000`
- `-1000 <= nums[i] <= 1000`
- `nums[i] != 0`

## 2. 示例

**示例 1**

```text
输入：nums = [-1,2,-3,3]
输出：3
解释：3 是数组中唯一一个满足 k 与 -k 同时存在的正整数。
```

**示例 2**

```text
输入：nums = [-1,10,6,7,-7,1]
输出：7
解释：数组中 1 和 7 都存在对应的负数，7 的值更大。
```

**示例 3**

```text
输入：nums = [-10,8,6,7,-2,-3]
输出：-1
解释：不存在满足要求的正整数，返回 -1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个正数 `x`，再完整遍历一遍数组检查 `-x` 是否存在，配对成功者取最大。时间 $O(n^2)$，`n <= 1000` 时约 $10^6$ 次比较，虽可过，但"存在性查询"明显可以做到更快。

### 3.2 核心观察：存在性查询 → 哈希集合

![正负配对概念：k 与 -k 必须同时出现](images/2441_pair_match_concept.svg)

**关键观察**：整个问题由一次次**存在性查询**构成——"数组里有没有 `-x`？"。把所有元素一次性塞进**哈希集合** `S`，每次查询降为 $O(1)$：

- 对每个**正数** `x`：若 `-x ∈ S`，则 `x` 是候选答案
- 取所有候选的最大值；一个候选都没有则返回 `-1`

### 3.3 解法二：排序 + 双指针

![排序后双指针夹逼流程](images/2441_two_pointer_flow.svg)

排序后负数全在左侧、正数全在右侧。令 `l` 指向最左（最负）、`r` 指向最右（最大），根据两端之和移动指针：

- `nums[l] + nums[r] < 0`：负数绝对值太大，连最大的正数都配不上，`l++`
- `nums[l] + nums[r] > 0`：`nums[r]` 太大，数组里没有它的相反数，`r--`
- `nums[l] + nums[r] == 0`：配对成功，`nums[r]` 即最大配对正数，直接返回

由于 `r` 从最大端出发**只减不增**，第一次遇到和为 `0` 时，`nums[r]` 就是全局最大的配对正数。

### 3.4 示例演算

![双指针走查：成功与失败两条路径](images/2441_sorted_walkthrough.svg)

**示例 2**（成功路径）：排序后 `[-7,-1,1,6,7,10]`。`l→-7, r→10`，和为 `3 > 0`，`r--`；`l→-7, r→7`，和为 `0`，返回 **7**。仅两步。

**示例 3**（失败路径）：排序后 `[-10,-3,-2,6,7,8]`。指针按 `l++ / r--` 交替移动 5 次，`l` 与 `r` 相遇，说明没有任何配对，返回 **-1**。

## 4. 算法细节

1. **哈希集合做法**：`S = set(nums)` 一次建集合；遍历时只检查 `x > 0` 的元素，避免正负各查一遍做无用功；答案初始化为 `-1`，天然兼容"无配对"情形。
2. **双指针做法**：先升序排序；循环条件用 `l < r`——同一元素不可能与自身配对（题目保证无 `0`），`l == r` 时和不可能为 `0`；三分支严格对应 `<0`、`>0`、`==0`。
3. **终止性**：每次循环 `l` 或 `r` 必有一个向中间移动一步，最多 `n-1` 次后 `l >= r`，必然结束。
4. **值域技巧**：值域仅 `[-1000, 1000]`，也可用两个长度 `1001` 的布尔数组分别标记正数、负数（按绝对值索引）是否出现，再从 `1000` 到 `1` 倒序找第一个两边都出现的位置，时间 $O(n + V)$。

## 5. 正确性证明

**引理 1**（`sum > 0` 时丢弃 `r` 安全）：设 `nums[l] + nums[r] > 0`，则 `nums[r]` 在数组中不存在配对负数。

**证明**：若 `nums[l] < 0`，排序后所有负数均 `<= nums[l] < 0`，其相反数均 `>= -nums[l] > nums[r]`，故不存在值为 `-nums[r]` 的负数；若 `nums[l] >= 0`，说明区间内已无负数，更无配对。两种情况均可安全 `r--`。∎

**引理 2**（`sum < 0` 时丢弃 `l` 安全）：设 `nums[l] + nums[r] < 0`，则 `nums[l]` 不存在配对正数。

**证明**：排序后所有正数均 `<= nums[r] < -nums[l]`，故不存在值为 `-nums[l]` 的正数，可安全 `l++`。∎

**定理**：排序 + 双指针若遇到 `sum == 0`，返回的 `nums[r]` 是最大的配对正数；若以 `l >= r` 结束，数组无配对，返回 `-1` 正确。

**证明**：由引理 1、2，每次移动丢弃的都是**已被证明无配对**的元素，任何真实的配对 `(x, -x)` 的两端都不会被单独丢弃，故不遗漏。`r` 只减不增，第一个命中的 `sum == 0` 对应剩余区间中最右端的正数，即当前候选中的最大者；由无遗漏性，它就是全局最大配对正数。若循环以 `l >= r` 结束，则所有元素均已被证明无配对，返回 `-1`。∎

哈希集合做法的正确性是直接的：它逐一验证了每个正数的配对条件，候选集合与真实配对集合完全一致，取最大即答案。∎

## 6. 复杂度分析

**哈希集合**：

- **时间复杂度**：$O(n)$。建集合与遍历检查均为线性。
- **空间复杂度**：$O(n)$。集合存储全部元素。

**排序 + 双指针**：

- **时间复杂度**：$O(n \log n)$，排序主导；指针扫描本身仅 $O(n)$。
- **空间复杂度**：C++ 原地排序 $O(1)$（忽略排序递归栈）；Python `sorted` 需 $O(n)$。

## 7. 参考代码

### C++（哈希集合）

```cpp
class Solution {
public:
    int findMaxK(vector<int>& nums) {
        unordered_set<int> s(nums.begin(), nums.end());
        int ans = -1;
        for (int x : s) {
            if (x > 0 && s.count(-x)) {
                ans = max(ans, x);
            }
        }
        return ans;
    }
};
```

### C++（排序 + 双指针）

```cpp
class Solution {
public:
    int findMaxK(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int l = 0, r = (int)nums.size() - 1;
        while (l < r) {
            int sum = nums[l] + nums[r];
            if (sum == 0) return nums[r];
            if (sum < 0) ++l;
            else --r;
        }
        return -1;
    }
};
```

### Python（哈希集合）

```python
class Solution:
    def findMaxK(self, nums: List[int]) -> int:
        s = set(nums)
        return max((x for x in s if x > 0 and -x in s), default=-1)
```

## 8. 边界情况与易错点

1. **答案初值**：必须初始化为 `-1` 而非 `0`——无配对时题目要求返回 `-1`，且数组中不含 `0`，初值 `0` 会导致错误答案。
2. **循环条件**：双指针用 `l < r`，不能写成 `l <= r`——同一元素无法与自身配对（无 `0` 保证），`l == r` 时和不可能为 `0`。
3. **单侧缺失**：数组全正或全负时无解，两种做法都天然返回 `-1`，无需特判。
4. **只查正数**：哈希做法遍历时用 `x > 0` 过滤，否则每个配对被正负各检查一遍（不影响正确性，只影响常数）。
5. **值域陷阱**：若改用桶数组方案，负数要用**绝对值**索引，且正数、负数需要两个独立标记数组，不能共用。
