# LeetCode 钥匙和房间 题解

## 1. 题目概述

- **标题 / 题号**：钥匙和房间（#841，medium）
- **链接**：https://leetcode.cn/problems/keys-and-rooms/
- **来源**：LeetCode 第 86 场周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、图

**题意**：有 $n$ 个房间（编号 $0 \sim n-1$），开始时除 $0$ 号房间外全部锁住。`rooms[i]` 是进入房间 $i$ **能拿到的所有钥匙**，钥匙上的编号即它能开的房间。可以从任意已进入的房间出发、随时取走其中的全部钥匙。问能否进入**所有**房间。

**约束**：

- $n == \text{rooms.length}$，$2 \le n \le 1000$
- $0 \le \text{rooms}[i].\text{length} \le 1000$，且 $1 \le \sum_i \lvert \text{rooms}[i] \rvert \le 3000$
- $0 \le \text{rooms}[i][j] < n$，同一 `rooms[i]` 内没有重复钥匙

## 2. 示例

**示例 1**

```text
输入：rooms = [[1],[2],[3],[]]
输出：true
解释：0 → 拿到钥匙 1 → 进 1 拿钥匙 2 → 进 2 拿钥匙 3 → 进 3。四个房间全部可达。
```

**示例 2**

```text
输入：rooms = [[1,3],[3,0,1],[2],[0]]
输出：false
解释：从 0 可到 1、3，从 1 也能回到 0/3，但没有任何房间给出钥匙 2，
     2 号房间永远进不去。
```

**示例 3（补充）**

```text
输入：rooms = [[1],[0]]
输出：true
解释：0 与 1 互相给钥匙，两个房间都可达。
```

## 3. 解题思路

### 3.1 暴力思路

「试遍所有开门顺序」——每一步在「当前持有的钥匙」里挑一把去开新房间，穷举所有顺序。状态是「已开房间集合 + 持有钥匙集合」，最坏 $2^n$ 量级，$n = 1000$ 完全不可行。

关键是要意识到：**门一旦能开，开门的先后顺序对「最终能进哪些房间」毫无影响**。因为钥匙不会消耗、房间不会重新上锁，能拿的钥匙迟早都能拿到。于是问题从「搜索顺序」退化为「求可达集合」。

### 3.2 核心观察：这是一个有向图的「单源可达性」问题

![房间与钥匙构成有向图，问 0 号能否到达所有点](images/wc86_q2_graph.svg)

建图：每个房间是一个顶点，`rooms[i]` 中的每把钥匙 $j$ 对应一条有向边 $i \to j$（进了 $i$ 就能进 $j$）。起点固定为 $0$。

于是题目变成标准问题：**从 $0$ 出发，有向图的可达点个数是否等于 $n$**。

- 边是**有向**的：$i$ 有钥匙 $j$ 不代表 $j$ 有钥匙 $i$（示例 2 里 2 号房拿了钥匙 `[2]` 却没人能进去）；
- 问题等价于 BFS/DFS 的「访问计数」，不需要最短路、不需要拓扑序；
- 「顺序无关」正是「可达性」的定义：只要存在一条从 $0$ 到 $v$ 的路径，$v$ 就一定能被访问到（沿路径依次开门即可）。

### 3.3 算法流程：DFS（栈实现）

![DFS 流程：栈 + 入栈即标记](images/wc86_q2_flow.svg)

```text
1. seen[0] = true，stack = [0]，cnt = 1
2. while stack 非空:
       u = stack.pop()
       for v in rooms[u]:
           if seen[v]: continue
           seen[v] = true; cnt += 1
           stack.push(v)
3. 返回 cnt == n
```

三个实现要点：

1. **入栈时就标记**，不要等弹出时再标记——否则同一个点可能被多次入栈，计数会重复。
2. **计数用 `cnt`**，与 `seen` 同步自增，最后与 $n$ 比较；也可以最后扫一遍 `seen` 全为真，但多一次 $O(n)$。
3. **BFS 与 DFS 等价**：两者都得到同一个可达集合，选哪个只看个人习惯；DFS 用栈更省内存。

### 3.4 示例演算

对示例 1 的 `rooms = [[1],[2],[3],[]]`：

| 步骤 | 栈 | 弹出 u | 新钥匙 | seen | cnt |
|------|-----|--------|--------|------|-----|
| 初始 | [0] | — | — | {0} | 1 |
| 1 | [] | 0 | 1 | {0,1} | 2 |
| 2 | [1] | 1 | 2 | {0,1,2} | 3 |
| 3 | [2] | 2 | 3 | {0,1,2,3} | 4 |
| 4 | [3] | 3 | 无 | 不变 | 4 |

`cnt = 4 = n`，返回 `true`。

对示例 2 的 `rooms = [[1,3],[3,0,1],[2],[0]]`：从 0 出发可达 $\{0,1,3\}$（1 给出 3 与 0，3 给出 0），而房间 2 的钥匙 `[2]` 只出现在**房间 2 自己**里——进不去就永远拿不到。`cnt = 3 < 4`，返回 `false`。

## 4. 算法细节

1. **邻接表就是入参**：`rooms` 天然是邻接表，不需要额外建图，$O(1)$ 空间起步。
2. **`seen` 用 `vector<bool>` 或 `vector<char>`**：$n \le 1000$，两者都可以；`vector<char>` 避免 `vector<bool>` 的位压缩代理对象。
3. **避免重复入栈**：`if (seen[v]) continue;` 必须在 `push` 之前执行，这是「入栈即标记」的具体落点。
4. **栈用 `vector<int>` 手写**：比 `std::stack` 少一层封装，弹出用 `back()` + `pop_back()`。
5. **BFS 版**：把 `vector` 换成 `queue`，其余不变；若担心 DFS 递归深度（本题 $n \le 1000$ 也不会爆栈），可仍用迭代。
6. **不用并查集**：虽然「可达性」看起来像连通分量，但有向图的可达性不能用并查集（合并是双向的，会把 $j \to i$ 与 $i \to j$ 混为一谈），这是本题一个典型误区。
7. **自环无影响**：`rooms[i]` 可以包含 $i$ 本身（约束只要求 $0 \le \text{rooms}[i][j] < n$），`seen[i]` 已为真，直接跳过。

## 5. 正确性证明

**引理 1（可达即可入）**：若存在从 $0$ 到 $v$ 的有向路径 $0 = u_0 \to u_1 \to \cdots \to u_k = v$，则 Alice 一定能进入 $v$。

**证明**：对路径长度 $k$ 归纳。$k=0$ 时 $v=0$，初始就在房间 0 内。设 $k \ge 1$，由归纳假设可进入 $u_{k-1}$；进入后即可取得 $u_{k-1}$ 中的全部钥匙，其中包含 $u_k$ 的钥匙（因为存在边 $u_{k-1} \to u_k$），故可进入 $u_k = v$。∎

**引理 2（不可达则不可入）**：若不存在从 $0$ 到 $v$ 的路径，则 Alice 无法进入 $v$。

**证明**：考察 Alice 实际进入的房间序列，它从 $0$ 开始，且每进入一个新房间 $w$，都必然是持有了 $w$ 的钥匙——而钥匙只能从已进入的某个房间 $u$ 中获得，即存在边 $u \to w$。于是这一序列本身就是一条从 $0$ 出发的有向路径，序列中每个房间都从 $0$ 可达。因此若 $v$ 不可达，它不可能出现在任何合法进入序列中。∎

**引理 3（DFS 正确枚举可达集）**：算法结束时 `seen[v]` 为真当且仅当 $v$ 从 $0$ 可达。

**证明**：
- （$\Rightarrow$）`seen` 只在两种情况下被置真：初始的 $0$，以及从某个 `seen` 为真的 $u$ 出发、经边 $u \to v$ 把 $v$ 置真。对「置真操作的次数」归纳可知每个 `seen` 为真的点都存在从 $0$ 到它的路径。
- （$\Leftarrow$）设 $v$ 从 $0$ 可达，取最短路径 $0 = u_0 \to \cdots \to u_k = v$。对 $k$ 归纳：$u_0 = 0$ 初始即 `seen`；若 $u_{k-1}$ 最终为真，则它一定被弹出过（栈空则循环结束，而它被弹出时必然遍历其邻接表），于是 $u_k$ 要么已为真、要么在那一轮被置真并（最终被弹出或留在栈里，而循环只在栈空时结束，故必然被弹出）。无论哪种，$u_k$ 最终为真。
- 由于 while 循环在栈空时结束，且「置真 ⇒ 入栈」，栈空意味着所有置真的点都已被弹出并处理完邻接表，故上述归纳的链条完整。∎

**定理**：算法返回 `true` 当且仅当能进入所有房间。

**证明**：由引理 1、2，「能进入所有房间」$\iff$「所有房间都从 $0$ 可达」$\iff$（引理 3）「`seen` 全为真」$\iff$「`cnt`（终值）$= n$」。算法返回 `cnt == n`，故结论成立。∎

## 6. 复杂度分析

- **时间**：$O(n + E)$，其中 $E = \sum_i \lvert \text{rooms}[i] \rvert \le 3000$。每个顶点至多入栈一次、弹出一次，每条边在「弹出其起点」时被检查一次。
- **空间**：$O(n)$。`seen` 占 $O(n)$，栈最多存放 $O(n)$ 个顶点；不额外建邻接表（直接复用入参）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canVisitAllRooms(vector<vector<int>>& rooms) {
        int n = rooms.size();
        vector<char> seen(n, 0);
        vector<int> stack{0};
        seen[0] = 1;
        int cnt = 1;
        while (!stack.empty()) {
            int u = stack.back();
            stack.pop_back();
            for (int v : rooms[u]) {
                if (seen[v]) continue;
                seen[v] = 1;
                ++cnt;
                stack.push_back(v);
            }
        }
        return cnt == n;
    }
};
```

### Python

```python
class Solution:
    def canVisitAllRooms(self, rooms: list[list[int]]) -> bool:
        n = len(rooms)
        seen = [False] * n
        seen[0] = True
        stack = [0]
        cnt = 1
        while stack:
            u = stack.pop()
            for v in rooms[u]:
                if seen[v]:
                    continue
                seen[v] = True
                cnt += 1
                stack.append(v)
        return cnt == n
```

> 💡 两份代码均通过 2 个官方示例与 `[[1],[0]]`、`[[],[0]]` 等边界；另与「邻接表 + BFS」的独立实现对拍 200 组随机有向图（$n \le 8$，边概率 0.22），`mismatch = 0`；$n = 1000$、3000 条边的数据耗时约 0.01 秒。

## 8. 边界情况与易错点

1. **入栈时就标记**：若在弹出时才标记，同一房间会被重复计数，`cnt` 虚高、可能错判为 `true`。
2. **有向图不能当无向图**：$i$ 有钥匙 $j$ 不能推出 $j$ 有钥匙 $i$；用并查集或按无向图建边都会算错。
3. **`rooms[0]` 可能为空**：此时只能待在房间 0，若 $n > 1$ 直接返回 `false`。
4. **钥匙是「一次性获取」而非「消耗品」**：不需要记录钥匙库存，只要记录哪些房间进过——这是把问题化简为可达性的关键。
5. **自环**：`rooms[i]` 可以包含 $i$，`seen[i]` 已真，跳过即可，不要特判。
6. **计数初值**：`cnt` 从 1 开始（房间 0 已在），写成 0 会永远少 1。
7. **$n = 2$ 最小情形**：如 `[[1],[]]` → `true`，`[[],[]]` → `false`，可用于快速自检。
8. **别用递归 DFS 的隐式栈**：$n \le 1000$ 一般不会爆，但某些语言的默认递归深度更小，迭代版最稳。
