# LeetCode 矩阵中的幻方 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中的幻方（#840，medium）
- **链接**：https://leetcode.cn/problems/magic-squares-in-grid/
- **来源**：LeetCode 第 86 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、数学、矩阵

**题意**：$3 \times 3$ 的幻方指一个填满 **$1 \sim 9$ 这九个不同数字**的 $3 \times 3$ 矩阵，且每行、每列、两条对角线上的三个数之和都相等。给定 `row × col` 的整数矩阵 `grid`，统计其中有多少个 **$3 \times 3$ 的「幻方」子矩阵**（连续的三行三列）。

注意：`grid` 本身的元素可以取 $0 \sim 15$、可以重复，只有**子矩阵内部**必须恰为 $1 \sim 9$ 的一个排列。

**约束**：

- $1 \le \text{row}, \text{col} \le 10$
- $0 \le \text{grid}[i][j] \le 15$

## 2. 示例

**示例 1**

```text
输入：grid = [[4,3,8,4],[9,5,1,9],[2,7,6,2]]
输出：1
解释：3×4 的网格里只有两个 3×3 窗口。
     窗口 (0,0) = [[4,3,8],[9,5,1],[2,7,6]] 是幻方（八线和均为 15）；
     窗口 (0,1) = [[3,8,4],[5,1,9],[7,6,2]] 中心为 1、对角线 3+1+2 = 6，不是幻方。
```

**示例 2**

```text
输入：grid = [[8]]
输出：0
解释：不足 3 行 3 列，没有任何 3×3 子矩阵。
```

**示例 3（补充）**

```text
输入：grid = [[8,1,6],[3,5,7],[4,9,2]]
输出：1
解释：整个网格恰好是一个幻方，任何方向的和都是 15。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有可能的 $3 \times 3$ 窗口（左上角 $(i,j)$ 满足 $0 \le i \le R-3$、$0 \le j \le C-3$），对每个窗口做两件事：

1. 取出 9 个数，检查是否恰为 $1 \sim 9$（去重 + 范围）；
2. 检查 3 行、3 列、2 条对角线的和是否都等于 15。

窗口数最多 $(10-2) \times (10-2) = 64$ 个，单窗口检查是常数工作量，总复杂度 $O(RC)$，本来就是最优量级。所以这题的「暴力」其实不需要优化太多——真正的考点是**别把判定条件写漏、写错**，以及能不能看出那个 $O(1)$ 的强剪枝。

### 3.2 核心观察：中心必为 5，且三个条件可互相印证

![3×3 幻方的三个条件与「中心为 5」的推导](images/wc86_q1_checks.svg)

**引理（幻方中心）**：若 $3 \times 3$ 幻方填的是 $1 \sim 9$，则中心格必为 $5$，且每条线（8 条）之和必为 $15$。

推导只用两条事实：

- $1 + 2 + \cdots + 9 = 45$；若幻方每条线之和为 $S$，把 3 行相加得 $3S = 45$，故 $S = 15$。
- 过中心的**四条线**（中行、中列、两条对角线）之和为 $4 \times 15 = 60$。它们覆盖了全部 9 个格子，其中中心格被计入 4 次、其余 8 格各 1 次，于是

$$45 + 3 \cdot \text{center} = 60 \quad\Longrightarrow\quad \text{center} = 5$$

这是本题最好用的剪枝：**绝大多数格子中心不是 5，直接否掉**，连 9 个数的去重都不用做。

于是判定可以组织成「由快到慢」的三级：

| 级别 | 检查内容 | 代价 |
|------|----------|------|
| 1 | 中心是否等于 5 | $O(1)$ |
| 2 | 9 个数是否恰为 $1 \sim 9$ 的排列 | $O(9)$ |
| 3 | 8 条线的和是否都为 15 | $O(9)$ |

三级全过才是幻方。第 1 级能滤掉绝大部分窗口；第 2 级保证「数字合法」；第 3 级保证「线合相等」。三级都不能省——虽然理论上「$1\sim9$ 排列 + 中心 5 + 4 条线」就已蕴含其余（这是幻方的经典性质），但显式检查 8 条线更直白、也不慢。

### 3.3 算法流程

![枚举所有 3×3 窗口](images/wc86_q1_windows.svg)

```text
1. ans = 0
2. for i = 0 .. R-3:
       for j = 0 .. C-3:
           if isMagic(grid, i, j): ans += 1
3. 返回 ans

isMagic(g, r, c):
   1) 中心不为 5 → false
   2) 9 个数逐一检查：必须在 [1,9] 且互不重复（seen 数组）
   3) 3 行和、3 列和、2 条对角线和都为 15 → true
```

### 3.4 示例演算

![示例 1 的两个窗口](images/wc86_q1_walkthrough.svg)

**示例 1**（3 行 4 列，只有两个窗口）：

- 窗口 (0,0)：`[[4,3,8],[9,5,1],[2,7,6]]`。中心 5 ✓；九数为 $1\sim9$ ✓；行和 $15,15,15$、列和 $15,15,15$、对角线和 $4+5+6=15$、$8+5+2=15$ ✓ → **计入**。
- 窗口 (0,1)：`[[3,8,4],[5,1,9],[7,6,2]]`。中心是 1，第 1 级就被否 → 不计入。

答案 $= 1$。

**示例 3**：`[[8,1,6],[3,5,7],[4,9,2]]`，中心 5，九数齐全，行 $15/15/15$、列 $15/15/15$、对角 $8+5+2=15$、$6+5+4=15$ → 计入，答案 1。

## 4. 算法细节

1. **先判中心**：`if (g[r+1][c+1] != 5) return false;` 放在最前面，是最省的一条剪枝。注意中心下标是 `(r+1, c+1)`，别写成 `(r, c)`。
2. **`seen` 数组代替 `set`**：值域只有 $0 \sim 15$，开长度 10 的数组，遇到 $<1$ 或 $>9$ 或已出现即返回 `false`；比哈希表快且无分配。
3. **8 条线逐一检查**：3 行 + 3 列 + 2 对角，写完对着「八线和均为 15」核对一遍，漏掉对角线是最常见的错误。
4. **窗口下标边界**：`i + 2 < R`、`j + 2 < C`（等价于 `i <= R-3`），$R<3$ 或 $C<3$ 时循环体不执行，天然返回 0，无需特判。
5. **不要复用 `seen` 而不清空**：若把 `seen` 提到循环外，必须每次 memset；本文在 `isMagic` 内部定义，天然清零。
6. **`grid` 元素可为 15**：范围检查必须写 `v < 1 || v > 9`，只写 `v > 9` 会漏掉 0。
7. **Python 的 `sorted(vals) != list(range(1,10))`**：一行完成「范围 + 去重 + 齐全」的检查，比手写 `seen` 更短；代价是排序 9 个元素，可忽略。

## 5. 正确性证明

**引理 1（和与中心）**：若一个 $3 \times 3$ 矩阵填的是 $1 \sim 9$ 各一次，且 8 条线的和都相等为 $S$，则 $S = 15$，中心格 $= 5$。

**证明**：三条行和相加得 $3S = \sum_{k=1}^{9} k = 45$，故 $S = 15$。中行、中列、两对角线共 4 条线，和 $4S = 60$；这 4 条线覆盖全部 9 个格子，中心格出现在全部 4 条线中、其余 8 格各出现一次，故 $4S = 45 + 3 \cdot \text{center}$，代入 $4S = 60$ 得 center $= 5$。∎

**引理 2（判定等价）**：`isMagic` 返回 `true` 当且仅当该 $3 \times 3$ 子矩阵是幻方。

**证明**：
- （$\Rightarrow$）若返回 `true`，则 9 个数都落在 $[1,9]$ 且互不相同，共 9 个 → 恰为 $1\sim9$ 的排列；且 8 条线的和都为 15（相等），满足幻方定义。
- （$\Leftarrow$）若子矩阵是幻方，则 9 个数是 $1\sim9$ 的排列，`seen` 检查通过；由引理 1 中心为 5，第 1 级通过；由定义 8 条线的和都相等，而引理 1 给出该公共值为 15，第 3 级通过。故返回 `true`。∎

**定理**：算法返回值等于 `grid` 中幻方子矩阵的个数。

**证明**：所有 $3 \times 3$ 连续子矩阵与左上角 $(i,j)$（$0 \le i \le R-3$，$0 \le j \le C-3$）一一对应，双层循环恰好各枚举一次、不重不漏。由引理 2，`isMagic` 为真的窗口恰是幻方，`ans` 对其逐一计数，故 `ans` 等于幻方子矩阵总数。∎

## 6. 复杂度分析

- **时间**：$O(RC)$。窗口数 $(R-2)(C-2) \le 64$，每个窗口最多检查 9 个数字 + 8 条线，均为常数；故总时间 $O(RC)$，$R, C \le 10$ 时不超过几百次基本操作。
- **空间**：$O(1)$。`seen` 数组长度 10，Python 版临时列表长度 9。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numMagicSquaresInside(vector<vector<int>>& grid) {
        int R = grid.size(), C = grid[0].size(), ans = 0;
        for (int i = 0; i + 2 < R; ++i)
            for (int j = 0; j + 2 < C; ++j)
                if (isMagic(grid, i, j)) ++ans;
        return ans;
    }
private:
    bool isMagic(vector<vector<int>>& g, int r, int c) {
        if (g[r + 1][c + 1] != 5) return false;      // 幻方中心必为 5，先做 O(1) 剪枝
        int seen[10] = {0};
        for (int i = 0; i < 3; ++i)
            for (int j = 0; j < 3; ++j) {
                int v = g[r + i][c + j];
                if (v < 1 || v > 9 || seen[v]) return false;   // 必须恰为 1..9 的一个排列
                seen[v] = 1;
            }
        for (int i = 0; i < 3; ++i) {
            if (g[r + i][c] + g[r + i][c + 1] + g[r + i][c + 2] != 15) return false;  // 行
            if (g[r][c + i] + g[r + 1][c + i] + g[r + 2][c + i] != 15) return false;  // 列
        }
        if (g[r][c] + g[r + 1][c + 1] + g[r + 2][c + 2] != 15) return false;          // 主对角线
        if (g[r][c + 2] + g[r + 1][c + 1] + g[r + 2][c] != 15) return false;          // 副对角线
        return true;
    }
};
```

### Python

```python
class Solution:
    def numMagicSquaresInside(self, grid: list[list[int]]) -> int:
        R, C = len(grid), len(grid[0])

        def is_magic(r: int, c: int) -> bool:
            if grid[r + 1][c + 1] != 5:            # 幻方中心必为 5，先做 O(1) 剪枝
                return False
            vals = [grid[r + i][c + j] for i in range(3) for j in range(3)]
            if sorted(vals) != list(range(1, 10)):  # 必须恰为 1..9 的一个排列
                return False
            rows = [sum(grid[r + i][c + j] for j in range(3)) for i in range(3)]
            cols = [sum(grid[r + i][c + j] for i in range(3)) for j in range(3)]
            diag1 = grid[r][c] + grid[r + 1][c + 1] + grid[r + 2][c + 2]
            diag2 = grid[r][c + 2] + grid[r + 1][c + 1] + grid[r + 2][c]
            return rows + cols + [diag1, diag2] == [15] * 8

        return sum(
            1
            for i in range(R - 2)
            for j in range(C - 2)
            if is_magic(i, j)
        )
```

> 💡 两份代码均通过 2 个官方示例与 `[[8,1,6],[3,5,7],[4,9,2]]`、$1\times1$ 等边界；另与「不剪枝、直接检查 8 线和与 1..9 集合」的独立暴力对拍 300 组随机网格（$R,C \le 6$，含刻意嵌入的已知幻方），`mismatch = 0`。

## 8. 边界情况与易错点

1. **小于 $3 \times 3$**：`range(R-2)` 为空（或 `i + 2 < R` 不成立），返回 0，不需要特判。
2. **中心不是 5**：第 1 级剪枝就否掉；这正是示例 1 第二个窗口被淘汰的原因（中心为 1）。
3. **`grid` 元素可以大于 9**：题目说 `grid` 最多到 15，所以必须显式检查 $1 \le v \le 9$，不能因为「看起来像幻方」就跳过。
4. **`grid` 元素可以是 0**：范围检查必须同时卡下界，`if (v > 9) return false` 会漏掉 0。
5. **重复数字**：同一窗口内两次出现同一个数必须判否（用 `seen` 或排序后比较）。
6. **漏检查对角线**：只查行列会把「行列都对、对角线错」的假幻方算进去。
7. **窗口重叠**：相邻窗口共享两列/两行，必须逐个独立检查，不能用前缀和式的「滑动复用」而忘记重新判重。
8. **下标错位**：`g[r+i][c+j]` 中 `i` 对应行、`j` 对应列，转置写反在方阵上不容易暴露，但遇到 $R \ne C$ 就会错。
