# LeetCode 找出不同元素数目差数组 题解

## 1. 题目概述

- **标题 / 题号**：找出不同元素数目差数组（#2670，easy）
- **链接**：https://leetcode.cn/problems/find-the-distinct-difference-array/
- **来源**：LeetCode 第 344 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、前后缀分解

**题意**：给定下标从 **0** 开始、长度为 $n$ 的数组 `nums`，定义**不同元素数目差**数组 `diff`：$\text{diff}[i]$ 等于前缀 $\text{nums}[0, \dots, i]$ 中**不同元素**的数目**减去**后缀 $\text{nums}[i+1, \dots, n-1]$ 中不同元素的数目。返回 `diff`。

**约束**：

- $1 \le n = \text{nums.length} \le 50$
- $1 \le \text{nums}[i] \le 50$

> 📚 本题在本仓库另有[每日题解 2670](../../solution/2601-2700/2670_找出不同元素数目差数组.md)：含位掩码 + popcount 写法与面试问答；本篇侧重赛时最短路径与两趟扫描模板的复盘。

> 💡 两条关键信号：**值域只有 50** ⇒ 定长计数数组即可当集合，$O(1)$ 查改；**相邻前后缀只差一个元素** ⇒ 两个"不同元素数"都能增量维护，不必每个位置重建集合。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,5]
输出：[-3,-1,1,3,5]
解释：元素互不相同，前缀不同数 = i+1，后缀不同数 = n-i-1，
diff[i] = (i+1) - (n-i-1) = 2i+2-n，随 i 每步 +2。
```

**示例 2**

```text
输入：nums = [3,2,3,4,2]
输出：[-2,-1,0,2,3]
解释：
i=0：前缀 {3}→1，后缀 {2,3,4,2}→3，diff[0]=1-3=-2
i=1：前缀 {3,2}→2，后缀 {3,4,2}→3，diff[1]=2-3=-1
i=2：前缀 {3,2}（3 重复）→2，后缀 {4,2}→2，diff[2]=2-2=0
i=3：前缀 {3,2,4}→3，后缀 {2}→1，diff[3]=3-1=2
i=4：前缀 {3,2,4}（2 重复）→3，后缀 {}→0，diff[4]=3-0=3
```

## 3. 解题思路

### 3.1 赛时最短路：逐位重建集合

签到题的最优策略是**用最短时间写出一定对的代码**。最朴素的写法：对每个 $i$ 分别把前缀、后缀建成集合，取大小相减：

```python
class Solution:
    def distinctDifferenceArray(self, nums: List[int]) -> List[int]:
        n = len(nums)
        return [len(set(nums[:i+1])) - len(set(nums[i+1:])) for i in range(n)]
```

$n \le 50$ 时这是 $O(n^2)$（切片 + 建集合），完全够用，赛时几分钟即可写完提交。**但它浪费了两条可增量维护的性质**，复盘时应沉淀线性做法——Q2 之后还要抢时间，这类"前后缀分解"模板值得背熟。

> ⚠️ 若数据范围放大到 $n \le 10^5$，$O(n^2)$ 建集合即超时，线性做法从"锦上添花"变成"必须"。

### 3.2 核心观察：前缀增量 + 后缀预算

![核心概念：diff[i] = 前缀不同元素数 − 后缀不同元素数](images/distinct_diff_prefix_suffix.svg)

把 $\text{diff}[i]$ 拆成两个可独立线性维护的量：

- **前缀不同数 $\text{pre}$**：从左到右扫描，遇到**首次出现**的元素就加一——前缀 $\text{nums}[0..i]$ 与 $\text{nums}[0..i-1]$ 只差一个元素；
- **后缀不同数 $\text{suf}[i]$**：定义为 $\text{nums}[i..n-1]$ 的不同元素数。后缀随 $i$ 增大而**收缩**，但从右端看恰好是"逐个加入"——先从右向左扫一遍，$\text{suf}[i]$ 可由 $\text{suf}[i+1]$ 加一个 0/1 增量得到。

于是一个位置一个公式：$\text{diff}[i] = \text{pre} - \text{suf}[i+1]$，两趟线性扫描出答案。

> 💡 为什么后缀不能在从左到右的一趟里顺带算出？因为它依赖"未来"的元素；而从右向左看，"未来"恰好是已扫过的部分——所以**后缀必须先反向预算**。这也是一切"前后缀分解"题的通用套路：需要哪一侧的信息，就先反向把那一侧的表填好。

### 3.3 算法流程

![算法流程：第一趟反向预算 suf，第二趟正向写 diff](images/distinct_diff_two_pass_flow.svg)

1. 初始化 $\text{suf}[n] = 0$（空后缀哨兵），值域计数数组 $\text{cnt}[1..50] = 0$；
2. **第一趟**（$i$ 从 $n-1$ 递减到 $0$）：若 $\text{cnt}[\text{nums}[i]] == 0$（该值首次进后缀）则 $\text{suf}[i] = \text{suf}[i+1] + 1$，否则 $\text{suf}[i] = \text{suf}[i+1]$；随后标记 $\text{cnt}[\text{nums}[i]] = 1$；
3. **第二趟**（$i$ 从 $0$ 递增到 $n-1$）：用**另一张表** $\text{seen}$ 维护前缀出现情况，$\text{nums}[i]$ 首次出现则 $\text{pre} \mathrel{+}= 1$ 并标记；写 $\text{diff}[i] = \text{pre} - \text{suf}[i+1]$；
4. 返回 `diff`。

### 3.4 示例演算

![示例演算：nums=[3,2,3,4,2] 逐位追踪 suf、pre 与 diff](images/distinct_diff_walkthrough.svg)

以示例 2 走查。先反向预算 $\text{suf} = [3,3,3,2,1,0]$（如 $\text{suf}[2]$ 统计 $\{3,4,2\}$ 共 3 个），再正向维护 $\text{pre}$ 写出 `diff`：

| $i$ | $\text{nums}[i]$ | 前缀集合 | $\text{pre}$ | $\text{suf}[i+1]$ | $\text{diff}[i]$ |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 3 | {3} | 1 | 3 | $1-3=-2$ |
| 1 | 2 | {3,2} | 2 | 3 | $2-3=-1$ |
| 2 | 3 | {3,2}（3 重复） | 2 | 2 | $2-2=0$ |
| 3 | 4 | {3,2,4} | 3 | 1 | $3-1=2$ |
| 4 | 2 | {3,2,4}（2 重复） | 3 | 0 | $3-0=3$ |

得 $\text{diff} = [-2, -1, 0, 2, 3]$ ✓

> 💡 看点：$i=2$ 处 $\text{nums}[2]=3$ 与前缀重复，$\text{pre}$ 不增；同时它也不再给任何后缀"贡献新值"——**重复元素对前后缀计数都不起作用**，这正是 $\text{pre}$ 单调不减、$\text{suf}$ 单调不增的原因。

## 4. 算法细节

1. **值域计数数组当集合**：$\text{nums}[i] \le 50$，开 `int cnt[51]`，查、改都是 $O(1)$ 数组访问，比哈希集合更快更省。值域变大时换成 `unordered_set` / `set` 即可，框架不变。
2. **哨兵 $\text{suf}[n] = 0$**：`suf` 开 $n+1$ 长，$i = n-1$ 时取 $\text{suf}[i+1] = \text{suf}[n] = 0$，空后缀**无需特判**。这是"多开一位边界值消分支"的惯用法，与前缀和题里 `prefix[0] = 0` 同源。
3. **`cnt[nums[i]]++ == 0` 惯用法**：后置自增返回**旧值**，旧值为 0 即"该值此前未出现"——把"查 + 标记"压成一句。
4. **两趟必须用两张独立的表**：第一趟的 `cnt` 记录的是**后缀**出现情况，第二趟的 `seen` 记录**前缀**出现情况，语义不同；要么开两张表，要么第二趟前重置。
5. **差一警惕**：$\text{diff}[i]$ 的后缀项是 $\text{suf}[i+1]$ 而不是 $\text{suf}[i]$——后者把 $\text{nums}[i]$ 自己也算进去了。这是本题最容易写错的一个下标。

## 5. 正确性证明

**引理 1（后缀递推）**：第一趟扫描后，对每个 $0 \le i \le n-1$，$\text{suf}[i]$ 恰为 $\text{nums}[i..n-1]$ 中不同元素的数目。

**证明**：对 $i$ 从 $n$ 到 $0$ 归纳。基例 $i = n$：空集元素数为 $0$，与哨兵一致。归纳步：设 $\text{suf}[i+1]$ 已正确。$\text{nums}[i..n-1]$ 与 $\text{nums}[i+1..n-1]$ 只差 $\text{nums}[i]$ 一个元素，故前者的不同元素数比后者恰多 1 当且仅当 $\text{nums}[i]$ 不在 $\text{nums}[i+1..n-1]$ 中出现；而扫描顺序保证处理 $i$ 时 `cnt` 恰记录 $\text{nums}[i+1..n-1]$ 中出现过的值，故 `cnt[nums[i]] == 0` 与"$\text{nums}[i]$ 是新值"等价，递推式成立。∎

**引理 2（前缀增量）**：第二趟中，处理完下标 $i$ 后 $\text{pre}$ 恰等于 $\text{nums}[0..i]$ 中不同元素的数目。

**证明**：对 $i$ 归纳。基例 $i = -1$（尚未处理任何元素）时 $\text{pre} = 0$，空集成立。归纳步：处理 $i$ 时 `seen` 恰记录 $\text{nums}[0..i-1]$ 中出现过的值，$\text{nums}[i]$ 首次出现当且仅当 `seen[nums[i]] == 0`，此时不同元素数加一并标记，否则不变，与代码一致。∎

**定理**：算法返回的 `diff` 满足对每个 $0 \le i \le n-1$：$\text{diff}[i] = \bigl|\{\text{nums}[0..i]\}\bigr| - \bigl|\{\text{nums}[i+1..n-1]\}\bigr|$。

**证明**：由引理 2，写 $\text{diff}[i]$ 时 $\text{pre} = \bigl|\{\text{nums}[0..i]\}\bigr|$；由引理 1，$\text{suf}[i+1] = \bigl|\{\text{nums}[i+1..n-1]\}\bigr|$（$i+1 = n$ 时为空集，哨兵为 $0$）。两者相减恰为所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + V)$，其中 $V = 50$ 为值域大小。两趟扫描各 $n$ 步，每步 $O(1)$ 的数组查改与加减；$V$ 体现在计数数组初始化。相比逐位重建集合的 $O(n^2)$，把每个位置的两次集合构建压缩成了两趟线性扫描。
- **空间复杂度**：$O(n + V)$。`suf` 数组 $O(n)$ 加两张值域计数表 $O(V)$；输出数组不计额外空间。$n \le 50$ 时几乎零开销。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> distinctDifferenceArray(vector<int>& nums) {
        int n = nums.size();
        const int M = 51;
        // 第一趟：从右向左预算 suf[i] = nums[i..n-1] 不同元素数
        vector<int> suf(n + 1, 0), cnt(M, 0);
        for (int i = n - 1; i >= 0; --i)
            suf[i] = suf[i + 1] + (cnt[nums[i]]++ == 0);  // 首次进后缀才 +1
        // 第二趟：从左向右维护 pre，写出 diff
        vector<int> diff(n);
        int seen[M] = {}, pre = 0;   // 与第一趟的 cnt 语义不同，必须换表
        for (int i = 0; i < n; ++i) {
            pre += (seen[nums[i]]++ == 0);
            diff[i] = pre - suf[i + 1];   // 后缀项是 suf[i+1]，差一下标
        }
        return diff;
    }
};
```

### Python

```python
class Solution:
    def distinctDifferenceArray(self, nums: List[int]) -> List[int]:
        n = len(nums)
        # 第一趟：从右向左预算 suf[i] = nums[i..n-1] 不同元素数
        suf = [0] * (n + 1)
        cnt = [0] * 51
        for i in range(n - 1, -1, -1):
            if cnt[nums[i]] == 0:
                suf[i] = suf[i + 1] + 1
            else:
                suf[i] = suf[i + 1]
            cnt[nums[i]] = 1
        # 第二趟：从左向右维护 pre，写出 diff
        seen = [0] * 51          # 与第一趟的 cnt 语义不同，必须换表
        pre = 0
        diff = []
        for i in range(n):
            if seen[nums[i]] == 0:
                pre += 1
                seen[nums[i]] = 1
            diff.append(pre - suf[i + 1])
        return diff
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一位置前缀 1 个不同元素、后缀为空，`diff = [1]`；由哨兵 $\text{suf}[1] = 0$ 自动覆盖。
2. **空后缀**：$i = n-1$ 时后缀为空，后缀项为 0。若不开 $\text{suf}[n]$ 哨兵而只开 $n$，这里极易越界或漏特判。
3. **差一下标**：`diff[i]` 用 `suf[i+1]` 而非 `suf[i]`（后者多算了 $\text{nums}[i]$ 自己），本题最高频的 WA 点。
4. **两趟共用一张表**：第一趟的 `cnt` 是后缀出现标记，第二趟若不重置或换表，前缀"首次出现"判断全错。
5. **先查后标**：`seen[nums[i]]++ == 0` 的顺序不能反，先置 1 再判断会把每个元素都判成"重复"。
6. **全相同元素**：如 `nums = [7,7,7]`，`diff = [1,1,1]`（每个前缀恰 1 个不同元素，每个非空后缀也恰 1 个），可作快速手测用例。
7. **无溢出风险**：$|\text{diff}[i]| \le 50$，`int` 绰绰有余，本题无需考虑数值范围。
