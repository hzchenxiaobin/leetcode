# LeetCode 有相同颜色的相邻元素数目 题解

## 1. 题目概述

- **标题 / 题号**：有相同颜色的相邻元素数目（#2672，medium）
- **链接**：https://leetcode.cn/problems/number-of-adjacent-elements-with-the-same-color/
- **来源**：LeetCode 第 344 场周赛 Q3
- **难度**：中等
- **标签**：数组、增量维护、差量更新

**题意**：给定整数 $n$ 表示长度为 $n$ 的数组 `colors`，初始所有元素均为 `0`，表示**未染色**。再给定查询数组 `queries`，其中 `queries[i] = [index_i, color_i]`。对第 $i$ 个查询：先把 `colors[index_i]` 染成 `color_i`，再统计 `colors` 中**颜色相同的相邻对**的数量（不限本次染的颜色）。返回数组 `answer`，`answer[i]` 为前 $i+1$ 个操作后的答案。

**约束**：

- $1 \le n \le 10^5$
- $1 \le q = \text{queries.length} \le 10^5$
- `queries[i].length == 2`
- $0 \le \text{index}_i \le n - 1$
- $1 \le \text{color}_i \le 10^5$

> 📚 本题在本仓库另有[每日题解 2672](../../solution/2601-2700/2672_有相同颜色的相邻元素数目.md)：含面试问答与同类练习表；本篇侧重赛时切入路径、边集视角的正确性证明与边界复盘。

> 💡 **审题关键**：统计量是**全局**所有相邻位置对 $(j, j+1)$ 中"两端颜色相同且非零"的对数，与本次染的 `color_i` 无关；`0` 表示**未染色**，两条相邻的 `0` **不算**同色对——示例 1 第 1 次查询后 `colors = [2,0,0,0]` 答案为 `0` 即是佐证。

> ⚠️ **规模信号**：$n, q \le 10^5$ ⇒ 单条查询必须 $O(1)$。每次现数全数组是 $O(n \cdot q) = 10^{10}$，必超时——这直接宣告「维护计数器 + 差量更新」是唯一出路。


## 3. 解题思路

### 3.1 暴力思路

维护 `colors` 数组，每条查询先写入 `colors[index] = color`，再**从左到右扫描整个数组**，数出 `colors[j] == colors[j+1] != 0` 的对数。

单条查询 $O(n)$，总代价 $O(n \cdot q)$，最坏 $10^{10}$，超时。

> 💡 **瓶颈定位**：染色本身 $O(1)$，瓶颈全在"每次都从头重数全局"。但每次查询只改了**一个位置**——全局 $n-1$ 条邻接边里，只有包含该位置的两条边可能变，其余边两端颜色根本没动。抓住"单点改动只波及 $O(1)$ 条边"，就能把 $O(n)$ 统计压成 $O(1)$ 差量。

### 3.2 核心观察：答案 = "边的集合"的大小，单点改色只波及两条邻接边

![核心观察：单点改色，全局只有两条邻接边在变](images/wc344_q3_edge_locality_concept.svg)

把**相邻同色对**看成图里的边：定义时刻 $t$ 的边集

$$A_t = \{\, (j, j+1) \mid 0 \le j \le n-2,\ \text{colors}_t[j] = \text{colors}_t[j+1] \ne 0 \,\}$$

则第 $t$ 次查询的正确答案就是 $|A_t|$。把位置 $i$ 从 `old` 改成 `c` 时：

- **不含 $i$ 的边**：两端颜色都没动，属于 $A_t$ 的归属不变——贡献**冻结**；
- **含 $i$ 的边**（至多两条 $(i-1, i)$ 与 $(i, i+1)$）：各自独立重估，可能进出边集。

于是维护一个全局计数器 `ans`，每条查询只对**受影响的 ≤ 2 条边**做"撤旧 + 加新"。引入指示函数 $f(x, y) = [x \ne 0 \land x = y]$（越界的邻居视为永不匹配），单条查询的差量为：

$$\Delta = f(c, L) + f(c, R) - f(\text{old}, L) - f(\text{old}, R)$$

其中 $L$、$R$ 是 $i$ 左右邻居的当前颜色。**撤销用旧色、累加用新色**，两组比较互不干扰。

> ⚠️ **`old = 0` 为何天然不可撤**：$f(0, y) = [0 \ne 0 \land \ldots] = 0$ 恒成立——未染色的格子从未给任何边贡献过"同色对"（两条相邻的 `0` 不算），所以旧色为 `0` 时撤销项必为 0。代码里的 `if (old != 0)` 守卫正是这个公式的短路化简；若漏掉守卫、又把比较写成 `colors[nb] == old`，两条相邻 `0` 会被误判为"曾经贡献过"，`ans` 就被多扣了。

### 3.3 算法流程：撤旧 → 染新 → 加新

![算法流程：每条查询的差量三段](images/wc344_q3_delta_flow.svg)

每条查询固定四步：

1. 读出 `old = colors[i]`；
2. **撤旧**：`old != 0` 时，左邻 `== old` 则 `ans−−`，右邻 `== old` 则 `ans−−`；
3. **染新**：写入 `colors[i] = c`（$c \ge 1$ 恒非零，无需守卫）；
4. **加新**：左邻 `== c` 则 `ans++`，右邻 `== c` 则 `ans++`；随后把 `ans` 追加进结果。

> 💡 **`old == c` 的天然正确性**：撤销阶段按 `old` 扣、累加阶段按 `c` 加，两次用的是同一个值，每条匹配边各 −1 再 +1 净零，`ans` 不变——与"数组实际没变"一致，无需特判（见示例 3）。先撤后加的次序保证比较基准清晰，是防写错的纪律。

### 3.4 示例演算

![示例演算：n=4，ans 随查询差量滚动](images/wc344_q3_example_walkthrough.svg)

以示例 1 走查（高亮行对应两种关键形态）：

| 查询 | 染后 colors | 差量细节 | ans |
|------|-------------|----------|-----|
| `[0,2]` | `[2,0,0,0]` | `old=0` 不撤；左右邻 ≠ 2，+0 | 0 |
| `[1,2]` | `[2,2,0,0]` | `old=0`；左邻 2 == c → +1 | 1 |
| `[3,1]` | `[2,2,0,1]` | `old=0`；左右邻均 ≠ 1，+0 | 1 |
| `[1,1]` | `[2,1,0,1]` | **old=2：左邻 2 == old 撤 −1**；新色 1 无匹配 | 0 |
| `[2,1]` | `[2,1,1,1]` | **old=0：左邻 1 == c +1、右邻 1 == c 再 +1** | 2 |

第 4 行触发**撤销分支**（改色拆掉了原有的同色边），第 5 行**一条查询左右两条边同时命中**（+2）。两者恰好说明：受影响的两条边各自独立重估，一条查询的 $\Delta \in \{-2,-1,0,1,2\}$。

## 4. 算法细节

1. **只维护一个全局计数器**：不需要任何哈希表或前缀和——`ans` 本身就是被查询量。撤旧/加新各至多 2 次比较，单条查询至多 4 次邻居读取 + 1 次写入。
2. **守卫与公式合一**：统一差量公式 $\Delta = f(c,L)+f(c,R)-f(\text{old},L)-f(\text{old},R)$ 中，$f(0, \cdot) \equiv 0$ 与 $f(\cdot, 0) \equiv 0$（$c \ge 1$，old 侧由 $x \ne 0$ 保证）共同消化"未染色不计数"的语义；代码中 `if (old != 0)` 只是 `old = 0` 时两个撤销项必为 0 的短路，逻辑上不引入任何特例。
3. **比较基准要显式**：撤销比 `old`、累加比 `c`，都只读邻居 `colors[i±1]`，不读 `colors[i]`。一个常见变体是"与 `colors[i]` 直接比较"：先撤（此时 `colors[i]` 还是 `old`）→ 写入 → 再加（此时已是 `c`）。该写法**必须**把写入夹在中间，顺序错了就把新色当旧色撤；用显式 `old` / `c` 变量则对三步顺序天然免疫——推荐后者。
4. **越界即无邻居**：$i=0$ 无左邻、$i=n-1$ 无右邻，用 `i > 0` / `i + 1 < n` 守卫即可，公式里相当于 $f(x, \bot) = 0$。
5. **与前两题的共性**：本场 Q1（2670）是"相邻前后缀只差一个元素 ⇒ 增量维护两个计数"，Q3 是"单点改色只差两条邻接边 ⇒ 差量维护一个计数器"——同一思想（**只重算受影响的局部**）在线性序列上的两次运用，赛时若在 Q1 顺手写过增量，Q3 应当条件反射到差量。

## 5. 正确性证明

**引理 1（局部性）**：设第 $t+1$ 条查询为 $(i, c)$，改前 `colors[i] = old`。则对任意不含位置 $i$ 的边 $e = (j, j+1)$（即 $j \notin \{i-1, i\}$），有 $e \in A_t \iff e \in A_{t+1}$。

**证明**：$e$ 两端 $j, j+1$ 均未被本次操作修改，故 $\text{colors}_{t+1}[j] = \text{colors}_t[j]$ 且 $\text{colors}_{t+1}[j+1] = \text{colors}_t[j+1]$，两端相等的判定结果与非零性都相同。∎

**引理 2（差量公式）**：记 $L = \text{colors}_t[i-1]$（$i > 0$）、$R = \text{colors}_t[i+1]$（$i < n-1$），越界侧约定 $f(x, \bot) = 0$。则

$$|A_{t+1}| - |A_t| = f(c, L) + f(c, R) - f(\text{old}, L) - f(\text{old}, R)$$

**证明**：含 $i$ 的边至多两条：$e_L = (i-1, i)$ 与 $e_R = (i, i+1)$。对 $e_L$：$e_L \in A_t \iff \text{colors}_t[i-1] = \text{old} \ne 0 \iff f(\text{old}, L) = 1$（改前 `colors[i]` 即 `old`）；$e_L \in A_{t+1} \iff \text{colors}_{t+1}[i-1] = c \ne 0 \iff f(c, L) = 1$（改后 `colors[i]` 即 `c`，且邻居值不变）。故 $e_L$ 对 $|A_{t+1}| - |A_t|$ 的贡献为 $f(c, L) - f(\text{old}, L)$。对 $e_R$ 同理贡献 $f(c, R) - f(\text{old}, R)$。由引理 1，不含 $i$ 的边贡献均为 0，逐边求和即得。∎

**定理（算法正确性）**：对任意查询序列，算法输出的 `answer[t]` 等于第 $t+1$ 条查询执行后的真实相邻同色对数 $|A_{t+1}|$。

**证明**：对已执行查询数 $k$ 归纳。

- **基础**：$k = 0$ 时 `colors` 全零，任何边的两端相等但均为 0，不满足"非零"，故 $A_0 = \varnothing$，`ans = 0` 正确。
- **归纳**：设第 $k$ 条查询后 `ans` $= |A_k|$。第 $k+1$ 条查询时，算法先按 `old != 0` 守卫执行减去 $f(\text{old}, L) + f(\text{old}, R)$（`old = 0` 时守卫跳过，而 $f(0, L) + f(0, R) = 0$，两种行为等价），再写入 `c`，加上 $f(c, L) + f(c, R)$。由引理 2，更新后 `ans` $= |A_k| + \Delta = |A_{k+1}|$，算法随后记录的就是 $|A_{k+1}|$。∎

**推论（重复染色）**：`old == c` 时 $\Delta = 0$。由 $f(c, \cdot) \equiv f(\text{old}, \cdot)$（同一值）逐项相消即得，与"数组未变"一致。∎

## 6. 复杂度分析

- **时间**：$O(n + q)$。初始化 `colors` 为 $O(n)$；每条查询只做至多 4 次邻居比较 + 1 次写入，均摊 $O(1)$，共 $q$ 条。相比暴力的 $O(n \cdot q)$（$10^{10}$），降到 $2 \times 10^5$ 量级，快了 5 个数量级。
- **空间**：$O(n)$（不计返回值）。`colors` 数组 $O(n)$，计数器 `ans` 与循环变量 $O(1)$；若计入答案数组则为 $O(n + q)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> colorTheArray(int n, vector<vector<int>>& queries) {
        vector<int> colors(n);          // 全 0 表示未染色
        vector<int> res;
        res.reserve(queries.size());
        int ans = 0;                    // 全局相邻同色对计数器
        for (auto& q : queries) {
            int i = q[0], c = q[1], old = colors[i];
            if (old != 0) {             // 未染色从未贡献过，无可撤销
                if (i > 0 && colors[i - 1] == old) --ans;
                if (i + 1 < n && colors[i + 1] == old) --ans;
            }
            colors[i] = c;              // 染新（c >= 1 恒非零）
            if (i > 0 && colors[i - 1] == c) ++ans;
            if (i + 1 < n && colors[i + 1] == c) ++ans;
            res.push_back(ans);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def colorTheArray(self, n: int, queries: List[List[int]]) -> List[int]:
        colors = [0] * n
        ans = 0
        res = []
        for i, c in queries:
            old = colors[i]
            if old != 0:                # 未染色从未贡献过，无可撤销
                if i > 0 and colors[i - 1] == old:
                    ans -= 1
                if i < n - 1 and colors[i + 1] == old:
                    ans -= 1
            colors[i] = c               # 染新（c >= 1 恒非零）
            if i > 0 and colors[i - 1] == c:
                ans += 1
            if i < n - 1 and colors[i + 1] == c:
                ans += 1
            res.append(ans)
        return res
```

## 8. 边界情况与易错点

1. **`n = 1` 无邻边**：答案恒为 `0`，`i > 0` / `i + 1 < n` 守卫天然覆盖，无需特判（示例 2）。
2. **漏掉 `old != 0` 守卫**：两条相邻的 `0` 不算同色对，`old = 0` 时本就没有贡献可撤。漏守卫（且比较写成 `colors[nb] == old`）会撤掉不存在的贡献，`ans` 偏小甚至变负。**调试信号：`ans` 一旦为负，必然是撤销了从未记过的边**。
3. **重复染色 `old == c`**：先撤后加净零，`ans` 不变，切勿加"颜色相同就跳过"之类特判以外的多余分支——特判本身也正确，但不加更简洁。
4. **比较对象写错**：撤销必须比 `old`、加新必须比 `c`；若与 `colors[i]` 直接比较，写入必须夹在撤、加之间，否则把新色当旧色撤、旧色当新色加。用显式 `old` / `c` 变量可彻底免疫。
5. **数组越界**：`i = 0` 无左邻、`i = n-1` 无右邻，C++ 中漏守卫直接越界 RE；Python 不会崩但 `colors[-1]` 会静默取到**末尾元素**，产生更隐蔽的逻辑错——负下标比崩溃更危险。
6. **误把"本次颜色的对数"当答案**：统计的是全局所有颜色的相邻同色对，不是只数 `color_i` 的（审题偏差会把示例 1 第 3 步答成 0）。
7. **先写入后撤销的顺序洁癖**：用显式 `old` / `c` 时三步（撤、写、加）其实互不干扰（比较只读邻居），但保持"撤 → 写 → 加"的纪律可以在改写为多位置更新或与 `colors[i]` 比较的变体时不出错。
