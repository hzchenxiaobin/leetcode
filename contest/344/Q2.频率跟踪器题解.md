# LeetCode 频率跟踪器 题解

## 1. 题目概述

- **标题 / 题号**：频率跟踪器（#2671，medium）
- **链接**：https://leetcode.cn/problems/frequency-tracker/
- **来源**：LeetCode 第 344 场周赛 Q2
- **难度**：中等
- **标签**：设计、哈希表

**题意**：设计一个数据结构跟踪一组数字，支持三种操作：`add(number)` 加入一个数字；`deleteOne(number)` 删除一个数字（若不存在则什么都不做）；`hasFrequency(f)` 回答「是否存在某个数字**恰好**出现 $f$ 次」。

**约束**：

- $1 \le \text{number} \le 10^5$
- $1 \le \text{frequency} \le 10^5$
- `add`、`deleteOne`、`hasFrequency` 总调用次数 $\le 2 \times 10^5$

> 📚 本题在本仓库另有[每日题解 2671](../../solution/2601-2700/2671_频率跟踪器.md)：含值域数组优化与面试问答；本篇侧重赛时切入路径、正确性证明与边界复盘。

> 💡 **审题关键**：`hasFrequency(f)` 问的不是「某个指定数字出现了几次」，而是「**任意**数字是否恰好出现 $f$ 次」——被查询的量是「频率为 $f$ 的数字**有几个**」，这才是决定数据结构形态的根因。


## 3. 解题思路

### 3.1 暴力思路

用一张哈希表 `cnt` 维护每个数字的出现次数：`add` / `deleteOne` 都是 $O(1)$ 的计数增减；但 `hasFrequency(f)` 必须**遍历 `cnt` 的全部值**，看是否有值等于 $f$，单次 $O(n)$。总调用 $2 \times 10^5$ 次，最坏（大量查询、表很大）总代价 $O(q \cdot n)$，必然超时。

> 💡 **瓶颈定位**：瓶颈不在维护频率，而在「按频率反查数字」。查询时现算不可行，就必须把「每个频率桶里有几个数字」在**增删的同时**维护好——查询时直接读桶。

### 3.2 核心观察：双哈希表，「频率的频率」

![核心观察：cnt 的值恰好是 freq 的键](images/freq_tracker_dual_table_concept.svg)

关键洞察是**再加一张哈希表 `freq`，让 `cnt` 的「值」恰好充当 `freq` 的「键」**：

| 哈希表 | 键 | 值 | 语义 |
|--------|----|----|------|
| `cnt` | 数字 $x$ | 频率 $f$ | 数字 $x$ 当前出现 $f$ 次 |
| `freq` | 频率 $f$ | 个数 | **恰好出现 $f$ 次**的数字有几个 |

两表由一条不变量绑定（对所有 $f \ge 1$）：

$$\text{freq}[f] = \left| \{\, x \mid \text{cnt}[x] = f \,\} \right|$$

于是 `hasFrequency(f)` 蜕化为一次哈希读：$\text{freq}[f] > 0$，$O(1)$ 出结果。

### 3.3 算法流程：cnt 变一格，freq 搬一次桶

![算法流程：离旧桶、入新桶](images/freq_tracker_bucket_move_flow.svg)

每次 `add` / `deleteOne` 只让某个 `cnt[x]` 变动 $\pm 1$，对应 $x$ 在 `freq` 中**从旧桶搬进相邻新桶**：

**`add(number)`**：

1. `old = cnt[number]`
2. `cnt[number] = old + 1`
3. `freq[old] -= 1`（离旧桶）
4. `freq[old + 1] += 1`（入新桶）

**`deleteOne(number)`**：

1. `old = cnt[number]`
2. 若 `old == 0`：数字不存在，直接 `return`（题面允许删不存在的数）
3. `cnt[number] = old - 1`
4. `freq[old] -= 1`；`freq[old - 1] += 1`

**`hasFrequency(f)`**：`return freq[f] > 0`

> ⚠️ **`freq[0]` 为何可以放任不管**：约束保证 $f \ge 1$，`hasFrequency` 永不读 `freq[0]`。`old = 0`（新数字）时减的、`old = 1` 删空时加的，都是这个永不被查询的桶——代码因此保持对称，省去 `if` 分支，不影响任何查询的正确性。

### 3.4 示例演算

![示例演算：freq 桶随增删同步搬移](images/freq_tracker_walkthrough.svg)

在示例 1 的操作序列上继续删、继续查，观察 `freq` 的搬移：

| 操作 | cnt（数字→频率） | freq（频率→个数） | hasFrequency 结果 |
|------|------------------|------------------|-------------------|
| `add(3)` | `{3: 1}` | 桶 1 = 1 | — |
| `add(3)` | `{3: 2}` | 桶 1 = 0，桶 2 = 1 | — |
| `hasFrequency(2)` | `{3: 2}` | `freq[2]=1` | **true** |
| `deleteOne(3)` | `{3: 1}` | 桶 1 = 1，桶 2 = 0 | — |
| `hasFrequency(2)` | `{3: 1}` | `freq[2]=0` | **false** |
| `deleteOne(3)` | `{}` | 桶 1 = 0 | — |
| `deleteOne(3)` | `{}`（`old=0` 直接返回） | 不变 | — |

第二次 `add(3)` 把 3 从桶 1 搬进桶 2（`freq[1]` 减、`freq[2]` 加），查询读桶直接命中；`deleteOne` 反向搬回。全程没有一次遍历 `cnt`。

## 4. 算法细节

1. **两表缺一不可**：`cnt` 记录「每个数字的当前频率」，是搬桶的依据——不知道 `cnt[number]` 就不知道从哪个 `freq` 桶搬走；`freq` 是「被查询量」的索引，把 $O(n)$ 的按值反查压成 $O(1)$ 哈希读。
2. **搬移的统一视角**：`cnt[x]` 从 $a$ 变到 $b$（$|a - b| = 1$）时，规则恒为「`freq[a] -= 1`、`freq[b] += 1`」，`add` 与 `deleteOne` 只是方向不同。抓住这点即可对称成对地写代码，不易漏更新。
3. **哈希表的零值语义**：C++ `unordered_map` 与 Python `defaultdict(int)` 对缺失键的下标访问都会零初始化，`freq[old] -= 1` 在键不存在时先建 0 再减，行为统一；C++ 查询用 `find` 守卫避免把查询键插入表，Python 可用 `get(f, 0) > 0` 规避白建键。
4. **为何不用 `multiset` / 平衡树**：把所有频率塞进有序容器，单次查询 `count` 也要 $O(\log n)$ 起步且常数大；本题查询只是「桶非空」的二值判断，哈希表天然 $O(1)$，是最简也最快的形态。

## 5. 正确性证明

**引理 1（不变量）**：对任意操作序列，每次操作结束后，对所有 $f \ge 1$ 都有

$$\text{freq}[f] = \left| \{\, x \mid \text{cnt}[x] = f \,\} \right|$$

（约定 `cnt` 中值为 $0$ 的键视为不存在。）

**证明**：对已执行的操作次数 $k$ 作归纳。

- **基础**：$k = 0$，两表均为空，等式两边均为 $0$，成立。
- **归纳**：设第 $k$ 次操作后不变量成立，考察第 $k+1$ 次操作：
  - 若为 `hasFrequency`，两表不变，不变量保持。
  - 若为 `add(number)`：记 $\text{old} = \text{cnt}[\text{number}]$。操作后仅 `number` 的频率从 $\text{old}$ 变为 $\text{old}+1$，其余数字不变，故除 $f \in \{\text{old}, \text{old}+1\}$ 外等式两边均不变。对 $f = \text{old}$：若 $\text{old} \ge 1$，代码左减 1，右边的集合恰失去 `number` 也减 1；若 $\text{old} = 0$，左边减的是无约束的 `freq[0]`，右边频率为 $0$ 的数字不计入任何 $f \ge 1$ 的桶，等式不受影响。对 $f = \text{old}+1$：代码左加 1，右边的集合恰得到 `number` 也加 1。等式保持。
  - 若为 `deleteOne(number)`：$\text{old} = 0$ 时守卫直接返回，两表不变。$\text{old} \ge 1$ 时对称：`number` 从桶 $\text{old}$ 离开、进入桶 $\text{old}-1$，$f = \text{old}$ 两边同减 1；$f = \text{old}-1$ 时若 $\text{old}-1 \ge 1$ 两边同加 1，若 $\text{old}-1 = 0$ 则动的只是无约束的 `freq[0]`。等式保持。∎

**引理 2（非负性）**：任意时刻所有 $\text{cnt}[x] \ge 0$。

**证明**：归纳：`add` 只增；`deleteOne` 有 `old == 0` 守卫，仅当 $\text{old} \ge 1$ 时减 1，减后仍 $\ge 0$。∎

**定理（算法正确性）**：对任意 $1 \le f \le 10^5$，`hasFrequency(f)` 返回 `true` 当且仅当当前结构中存在恰好出现 $f$ 次的数字，且三个操作均摊 $O(1)$。

**证明**：由引理 1，$\text{freq}[f]$ 恰等于出现次数为 $f$ 的数字个数，故 `freq[f] > 0` 与「存在这样的数字」等价；引理 2 保证频率非负、搬移始终发生在相邻桶之间，归纳无例外。操作复杂度：`hasFrequency` 仅一次哈希查询与比较，`add`/`deleteOne` 为常数次哈希读写，均摊 $O(1)$。∎

## 6. 复杂度分析

- **时间**：`add` 均摊 $O(1)$（`cnt` 一次读写 + `freq` 两次读写）；`deleteOne` 均摊 $O(1)$（一次存在性判断 + 常数次双表读写）；`hasFrequency` $O(1)$（一次哈希查询）。三个操作均无遍历，总代价 $O(q)$，$q \le 2 \times 10^5$。
- **空间**：$O(n)$，$n$ 为出现过的不同数字个数。`cnt` 的大小 $\le n$；`freq` 的大小 $\le$ 不同频率数 $\le n + 1$。两张表用「空间换时间」换掉了查询里的 $O(n)$ 扫描。

## 7. 参考代码

### C++

```cpp
class FrequencyTracker {
    unordered_map<int, int> cnt;   // 数字 -> 出现频率
    unordered_map<int, int> freq;  // 频率 -> 恰好出现该次数的数字个数

public:
    FrequencyTracker() {}

    void add(int number) {
        int old = cnt[number];
        cnt[number] = old + 1;
        freq[old]--;        // 离开旧频率桶（old=0 时动 freq[0]，永不被查询）
        freq[old + 1]++;    // 进入新频率桶
    }

    void deleteOne(int number) {
        int old = cnt[number];
        if (old == 0) return;  // 不存在，不删除任何内容
        cnt[number] = old - 1;
        freq[old]--;        // 离开旧频率桶
        freq[old - 1]++;    // 进入新频率桶（old-1=0 时动 freq[0]，不被查询）
    }

    bool hasFrequency(int frequency) {
        auto it = freq.find(frequency);
        return it != freq.end() && it->second > 0;
    }
};
```

### Python

```python
from collections import defaultdict

class FrequencyTracker:
    def __init__(self):
        self.cnt = defaultdict(int)   # 数字 -> 出现频率
        self.freq = defaultdict(int)  # 频率 -> 恰好出现该次数的数字个数

    def add(self, number: int) -> None:
        old = self.cnt[number]
        self.cnt[number] = old + 1
        self.freq[old] -= 1        # 离开旧频率桶（old=0 时动 freq[0]，永不被查询）
        self.freq[old + 1] += 1    # 进入新频率桶

    def deleteOne(self, number: int) -> None:
        old = self.cnt[number]
        if old == 0:               # 不存在，不删除任何内容
            return
        self.cnt[number] = old - 1
        self.freq[old] -= 1        # 离开旧频率桶
        self.freq[old - 1] += 1    # 进入新频率桶

    def hasFrequency(self, frequency: int) -> bool:
        return self.freq[frequency] > 0
```

## 8. 边界情况与易错点

1. **删除不存在的数字**：题面明确允许 `deleteOne` 传入结构中不存在的 `number`，此时必须原样返回；漏掉 `old == 0` 守卫会让 `cnt[number]` 变成 $-1$，破坏引理 2 的非负性，后续 `freq[-1]` 的增减会进一步污染桶语义。
2. **`freq[0]` 被增减但永不查询**：新数字入桶（`old=0`）与删空归零（`old-1=0`）都会触碰 `freq[0]`，它可能变负、可能累积，但约束保证 `frequency >= 1`，任何查询都读不到它——不必修复，加 `if` 反而破坏代码对称性。
3. **查询键未入表**：`hasFrequency(f)` 查询的 $f$ 可能从未被触及，`freq` 中无此键。Python 的 `defaultdict` 访问会补 0（结果正确，只是白建键），可用 `get(f, 0) > 0` 规避；C++ 用 `find` 守卫避免向表中插入查询键。
4. **误答「指定数字的频率」**：审题走偏会把 `hasFrequency` 实现成返回某个数字的出现次数——本题问的是「**任意**数字是否恰好出现 $f$ 次」，答案在桶级别，不在单数字级别。
5. **只想一层哈希**：只维护 `cnt` 会让每次查询退化为全表扫描；反过来想省掉 `cnt` 只维护 `freq` 则无从知道搬桶起点。两表互为索引，缺一不可。
6. **极端调用形态**：$2 \times 10^5$ 次调用全部是 `hasFrequency`，或全部是对同一数字反复 `add` / `deleteOne`（频率在 0、1 间震荡），双表方案都保持均摊 $O(1)$；若改用 `multiset<int>` 存频率，每次增删 $O(\log n)$ 且查询 `count` 最坏与重数同阶，会翻车。
