# LeetCode 逐步求和得到正数的最小值 题解

## 1. 题目概述

- **标题 / 题号**：逐步求和得到正数的最小值（#1413，easy）
- **链接**：https://leetcode.cn/problems/minimum-value-to-get-positive-step-by-step-sum/
- **来源**：LeetCode 第 24 场双周赛 Q1
- **难度**：简单
- **标签**：数组、前缀和

**题意**：给定数组 $nums$，选定一个**正整数** $startValue$ 作为初值，从左到右依次累加 $nums$ 的每个元素。要求**每一步累加后（含中间每一步）的累加和始终 $\ge 1$**，求满足要求的最小 $startValue$。

**约束**：

- $1 \le nums.length \le 100$
- $-100 \le nums[i] \le 100$

**约束解读**：数据很小，怎么写都能过；本题的价值在于把「逐步约束」翻译成「前缀和的最小值」这一通用转化。

## 2. 示例

**示例 1**

```text
输入：nums = [-3,2,-3,4,2]
输出：5
解释：startValue = 4 时第三步累加和为 4−3+2−3 = 0 < 1，不合法；
startValue = 5 时各步累加和为 2, 4, 1, 5, 7，全程 ≥ 1。
```

**示例 2**

```text
输入：nums = [1,2]
输出：1
解释：任何正数 startValue 都合法，最小正数为 1。
```

**示例 3**

```text
输入：nums = [1,-2,-3]
输出：5
解释：前缀和为 1, −1, −4，最低点 −4 需要 startValue ≥ 5。
```

## 3. 解题思路

### 3.1 暴力思路

从 $startValue = 1$ 开始逐一尝试：模拟一遍累加，若中途累加和 $< 1$ 就 $startValue{+}{+}$ 重来。单次模拟 $O(n)$，$startValue$ 最多递增到 $1 + 100 \times 100 = 10^4$ 量级（最低前缀和 $\ge -10^4$），总代价 $O(10^4 \cdot n) \approx 10^6$，本题能过但写法笨重。更好的观察是：$startValue$ 的合法性对每个位置是**独立可算**的约束，直接解不等式即可。

### 3.2 核心观察：约束 = 前缀和整体抬升

![核心观察：前缀和折线的最低点决定需要抬升多少](images/bw24_q1_prefix_min_model.svg)

设 $P_i = nums[0] + nums[1] + \cdots + nums[i]$ 为**前缀和**（$P_{-1} = 0$ 视作累加前状态）。第 $i$ 步累加后的和为 $startValue + P_i$，约束即

$$startValue + P_i \ge 1 \quad \text{对所有 } i,$$

也就是 $startValue \ge 1 - P_i$ 对所有 $i$ 成立，即 $startValue \ge \max_i (1 - P_i) = 1 - \min_i P_i$。

再加上「$startValue$ 必须是正数」（$\ge 1$），答案为

$$\boxed{\ startValue = \max\big(1,\ 1 - \min_i P_i\big)\ }$$

直觉图像：把前缀和折线整体向上平移 $startValue$，要求整条折线不低于高度 $1$——**只需要看最低点**，最低点抬高到 $1$，其余位置自动满足。

### 3.3 算法流程

```text
1. pre = 0, minPre = 0        # minPre 记录前缀和最小值
2. for x in nums:
       pre += x
       minPre = min(minPre, pre)
3. 返回 max(1, 1 − minPre)
```

`minPre` 初值取 $0$（对应空前缀 $P_{-1} = 0$）也没关系：$1 - 0 = 1$ 恰是「正数下界」本身，与 $\max(1, \cdot)$ 天然融合。

### 3.4 示例演算

![示例演算：startValue=4 与 5 的两条累加轨迹对比](images/bw24_q1_example_walkthrough.svg)

**示例 1**（$nums = [-3, 2, -3, 4, 2]$）：

| 步骤 | $nums[i]$ | 前缀和 $P_i$ | $sv=4$ 时累计 | $sv=5$ 时累计 |
|------|-----------|--------------|----------------|----------------|
| 1 | $-3$ | $-3$ | $1$ | $2$ |
| 2 | $2$ | $-1$ | $3$ | $4$ |
| 3 | $-3$ | $-4$ | $0$ ✗ | $1$ ✓ |
| 4 | $4$ | $0$ | $4$ | $5$ |
| 5 | $2$ | $2$ | $6$ | $7$ |

最低前缀和 $\min P = -4$，$startValue = 1 - (-4) = 5$。$sv = 4$ 在第 3 步跌到 $0 < 1$ 被否决。

**示例 2**（$nums = [1, 2]$）：前缀和 $1, 3$ 全为正，$\min P = 1$（含初值 $0$ 后取 $0$），$1 - 0 = 1$，答案 $1$——「正数」约束主导。

**示例 3**（$nums = [1, -2, -3]$）：前缀和 $1, -1, -4$，$\min P = -4$，答案 $5$。

## 4. 算法细节

1. **minPre 初始化为 0**：把「未累加任何数」的状态也纳入约束体系，此时 $1 - P = 1$ 正是正数下界，逻辑自洽；初始化成正无穷再另外处理「至少为 1」则需要两步判断，容易漏。
2. **一遍扫描同时维护**：`pre` 与 `minPre` 在同一循环里更新，无需先存下所有前缀和再求最小。
3. **答案上限**：$n \le 100$、$|nums[i]| \le 100$，$startValue \le 1 + 10^4$，`int` 绰绰有余。
4. **「正数」的语义**：题面要求严格正整数，即 $\ge 1$；若把约束误写成「$\ge 0$」，示例 2 会错答 $0$。
5. **恒等式复查**：$startValue + P_i \ge 1$ 移项时别把不等号方向弄反（除以正数不变号，这里是加减法）。

## 5. 正确性证明

**引理 1（约束等价）**：$startValue = sv$ 合法（每步累加和 $\ge 1$）$\iff$ $sv \ge 1 - P_i$ 对所有 $i \in [0, n-1]$ 成立。

**证明**：第 $i$ 步累加后的和恰为 $sv + P_i$（初值加前缀和），约束「每步 $\ge 1$」逐条写开即 $sv + P_i \ge 1$，移项得 $sv \ge 1 - P_i$；二者逐条对应，故等价。∎

**引理 2（最小值刻画）**：$\max_i (1 - P_i) = 1 - \min_i P_i$。

**证明**：$1 - x$ 关于 $x$ 严格递减，在有限集 $\{P_i\}$ 上取最大等价于 $P_i$ 取最小。∎

**定理**：满足条件的最小正整数 $startValue = \max(1,\ 1 - \min_{0 \le i < n} P_i)$。

**证明**：合法性条件由引理 1、2 给出 $sv \ge 1 - \min P$，加上正数条件 $sv \ge 1$，故可行 $sv$ 恰为 $sv \ge \max(1, 1 - \min P)$ 的整数；最小可行值即右边本身（它是整数，且满足两个约束，由引理 1 知其合法）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟扫描维护前缀和与其最小值。
- **空间**：$O(1)$。仅两个标量，不需要前缀和数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minStartValue(vector<int>& nums) {
        int minPre = 0, pre = 0;
        for (int x : nums) {
            pre += x;
            minPre = min(minPre, pre);            // 前缀和的最小值
        }
        return max(1, 1 - minPre);                // startValue ≥ 1 且 ≥ 1 − minPre
    }
};
```

### Python

```python
class Solution:
    def minStartValue(self, nums: list[int]) -> int:
        min_pre = pre = 0
        for x in nums:
            pre += x
            min_pre = min(min_pre, pre)           # 前缀和的最小值
        return max(1, 1 - min_pre)                # startValue ≥ 1 且 ≥ 1 − minPre
```

> 💡 两份代码均通过官方示例（`5`、`1`、`5`）；另与「从 $1$ 起逐值模拟」的暴力对拍 $3000$ 组随机（含全负、$0$ 数组、$[-1] \times 100 + [1]$ 定向用例），`mismatch = 0`。

## 8. 边界情况与易错点

1. **全正数组**：前缀和最低点是 $0$（初值），答案由「正数约束」决定为 $1$，别输出 $0$ 或 $1 - \min P$ 的负值。
2. **最低点出现在最后一步**：如 $[1, -100]$，最低前缀和 $-99$ 在末尾，答案 $100$；扫描不必提前退出。
3. **前缀和最小值包含初值 0**：若 `minPre` 初值设为正无穷且忘记与 $0$ 比较，全正数组会得到 $1 - \min P$（可能是 $0$ 或负数）的错误答案。
4. **「每步」包括中间步骤**：不是只看最终总和，也不是只看负数位置——任何一个前缀和低点都可能卡约束。
5. **整数范围**：$|P| \le 10^4$，`int` 足够。
6. **别排序**：累加顺序固定为从左到右，排序后前缀和完全变了，这是典型的「手滑写成熟悉模板」型错误。
