# LeetCode 二叉树的坡度 题解

## 1. 题目概述

- **标题 / 题号**：二叉树的坡度（#563，easy）
- **链接**：https://leetcode.cn/problems/binary-tree-tilt/
- **来源**：LeetCode 第 29 场周赛 Q1
- **难度**：简单
- **标签**：树、深度优先搜索、二叉树、树形 DP

**题意**：定义节点 $v$ 的坡度为其**左子树所有节点值之和**与**右子树所有节点值之和**之差的绝对值；左（右）子树为空时该侧和为 $0$，空节点的坡度为 $0$。求**整棵树**的坡度，即所有节点坡度之和。

**约束**：

- 树中节点数目在 $[0, 10^4]$ 内
- $-1000 \le Node.val \le 1000$

> 💡 **签到题的关键不是递归，而是「返回值选什么」**：坡度要的是两个**子树和**，所以 DFS 必须把「子树和」交还给父节点，坡度只是顺路累加的副产物。记住这一点，代码十行内可收，也不会掉进「让 DFS 返回坡度」的坑。

## 2. 示例

**示例 1**

```text
输入：root = [1,2,3]
输出：1
解释：节点 2、3 是叶子，坡度均为 |0-0| = 0；
      根节点 1 的坡度 = |2-3| = 1；
      坡度总和 = 0 + 0 + 1 = 1。
```

**示例 2**

```text
输入：root = [4,2,9,3,5,null,7]
输出：15
解释：节点 2 的坡度 = |3-5| = 2，其子树和 = 2+3+5 = 10；
      节点 9 缺左子树，坡度 = |0-7| = 7，其子树和 = 9+7 = 16；
      根 4 的坡度 = |10-16| = 6；
      坡度总和 = 0+0+0+2+7+6 = 15（叶子 3、5、7 坡度均为 0）。
```

**示例 3**

```text
输入：root = [21,7,14,1,1,2,2,3,3]
输出：9
解释：节点 7 的左子树和 = 1+3+3 = 7，右子树和 = 1，坡度 = 6；
      节点 14 的两棵子树和都是 2，坡度 = 0；
      根 21 的左子树和 = 7+(7+1) = 15，右子树和 = 14+2+2 = 18，坡度 = 3；
      坡度总和 = 6 + 3 = 9，其余节点坡度均为 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是**对每个节点单独求两侧子树和**：写一个 `sum(node)` 递归函数，再写一个遍历访问每个节点 $v$，累加 $\lvert sum(v.left) - sum(v.right) \rvert$。正确性是显然的，但代价很高：

- 每求一次 `sum` 要遍历整棵子树，节点 $v$ 会被它**所有祖先**各重算一次；
- 链状树（$10^4$ 个节点排成一条）下总工作量退化成 $\sum_{k=1}^{n} k \approx 5 \times 10^7$，即 $O(n^2)$；
- 而这份重复计算**完全是多余的**——同一个子树和会被反复用到。

### 3.2 核心观察：后序 DFS 返回「子树和」

![坡度定义：节点坡度等于左右子树和之差的绝对值](images/wc29_q1_tilt_definition.svg)

关键事实就两条：

1. 节点 $v$ 的坡度**只需要**两个数——左子树和 $S(L)$、右子树和 $S(R)$，即
   $$tilt(v) = \bigl| S(L) - S(R) \bigr|;$$
2. 而 $S(L)$、$S(R)$ 恰好就是「以子节点为根的子树」这个**同类子问题**的答案：
   $$S(v) = S(L) + S(R) + val(v).$$

于是问题天然适合**自底向上**的树形 DP：让 DFS 返回 $S(v)$，趁手里同时握着 $S(L)$ 与 $S(R)$ 的空档，把 $tilt(v)$ 累加进全局答案。每个节点只被访问一次，$O(n)$ 收工。

> ⚠️ **最容易写错的方向**：让 DFS 返回「坡度」。父节点要算自己的坡度，需要的是两个**和**，拿到的却是两个坡度——信息不够。返回值必须是「和」，坡度只能作为副产物累加。

### 3.3 算法流程

![后序遍历流程：左右子树和先返回，再累加当前节点坡度](images/wc29_q1_postorder_flow.svg)

1. 维护一个全局（或成员）变量 $total$，初值 $0$，记录已结算的坡度总和。
2. 定义 `dfs(v)`，语义是「**结算整棵以 $v$ 为根的子树，并返回它的节点值之和**」。
3. 若 $v$ 为空：返回 $0$。这让「没有左子树」与「左子树和为 $0$」自然等价，无需特判。
4. 否则先递归得到 $L = \text{dfs}(v.left)$、$R = \text{dfs}(v.right)$，再把 $|L-R|$ 累加进 $total$。
5. 返回 $L + R + val(v)$ 交给父节点。

### 3.4 示例演算

![示例 2 的后序遍历走查表](images/wc29_q1_example_walkthrough.svg)

以 `[4,2,9,3,5,null,7]` 为例，访问顺序是**后序**：$3 \to 5 \to 2 \to 7 \to 9 \to 4$。

| 访问节点 | 左和 $L$ | 右和 $R$ | 坡度 $\lvert L-R \rvert$ | 返回 $S(v)$ | 累计 $total$ |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 3 | 0 | 0 | 0 | 3 | 0 |
| 5 | 0 | 0 | 0 | 5 | 0 |
| 2 | 3 | 5 | 2 | 10 | 2 |
| 7 | 0 | 0 | 0 | 7 | 2 |
| 9 | 0 | 7 | 7 | 16 | 9 |
| 4 | 10 | 16 | 6 | 26 | 15 |

可见 $S(v)$ 这一列正好就是父节点下一步要用的输入：节点 4 直接拿 $10$ 与 $16$ 算出坡度 $6$，全程**没有第二次遍历**。最终 $total = 2 + 7 + 6 = 15$。

## 4. 算法细节

1. **返回值语义固定为「子树和」**：`dfs` 的返回类型与 $S(v)$ 一致；坡度只写进 `total`，绝不出现在返回值里。这是本题唯一的设计决策，定错就会推倒重写。
2. **空指针返回 0**：`if (!node) return 0;` 一行同时解决「空树」「单侧子树缺失」「叶子」三种情形，后续无任何特判分支。
3. **累加时机在后序位置**：必须等两次递归都返回后再算 $|L-R|$，因为坡度依赖两个完整子树和；写在递归之前只能拿到未定义值。
4. **绝对值不能省**：$L-R$ 可能为负（子树和可为负、左右可失衡），直接累加 $L-R$ 会得到错误且可能为负的答案；$|L-R|$ 的顺序无关，取 `l > r ? l - r : r - l` 可省一次函数调用。
5. **返回值必须带上自身 `val`**：$S(v) = L + R + val(v)$。漏掉自身值会让所有祖先的子树和偏小——示例 3 里节点 7 的左子树和 $1+3+3=7$ 就常被写成 $6$。
6. **成员变量要重置**：`total` 若挂成成员/属性，LeetCode 复用同一个 `Solution` 实例多次调用时必须在新一次 `findTilt` 开头清零，否则结果会累加历史答案。
7. **递归深度要评估**：链状树深度可达 $10^4$。C++ 递归 $10^4$ 层完全安全；Python 默认递归上限 $1000$，直接递归会抛 `RecursionError`（本仓库验证脚本已真实复现），需 `sys.setrecursionlimit(30000)`，或改写为显式栈的后序遍历。
8. **数值范围要留余量**：单棵子树和至多 $10^4 \times 1000 = 10^7$，`int` 足够；但「全为正值的链」其坡度总和可达 $1000 \cdot \frac{n(n-1)}{2} \approx 5 \times 10^{10}$，超出 32 位有符号整数。官方签名是 `int`，内部用 `long long` 累加、最后按签名返回，是零成本的保险。

## 5. 正确性证明

**引理 1（返回值语义）**：对任意节点 $v$，`dfs(v)` 返回 $S(v)$，即子树 $v$ 中所有节点值之和；且调用 `dfs(v)` 期间，$total$ 恰好增加了子树 $v$ 内**所有**节点的坡度之和。

**证明**：对子树高度归纳。

- 空树：`dfs(null)` 返回 $0 = S(\varnothing)$，且 $total$ 不变（空子树坡度和为 $0$），成立。
- 非空：设 $v$ 的左右孩子为 $L, R$。由归纳假设，`dfs(v.left)` 返回 $S(L)$ 并累加了左子树内所有坡度，`dfs(v.right)` 同理。随后代码执行
  $$total \mathrel{+}= \lvert S(L) - S(R) \rvert = tilt(v),$$
  再返回 $S(L) + S(R) + val(v) = S(v)$。于是本次调用累加的恰是「左子树坡度 + 右子树坡度 + 自身坡度」= 子树 $v$ 的坡度总和，返回值也正确。∎

**引理 2（访问唯一性）**：后序 DFS 中每个非空节点被 `dfs` 调用恰好一次，且在调用该节点时其左右子树已全部结算完毕。

**证明**：对树结构归纳。根节点仅被 `findTilt` 调用一次；每个孩子只在父节点的调用体内被调用一次，且父亲在所有祖先中唯一，故任一节点至多被调用一次；又因树连通、根可达所有节点，每个节点至少被调用一次——合起来恰好一次。递归调用发生在父节点自身累加之前，故父节点被结算时子树已处理完。∎

**定理**：`findTilt(root)` 返回整棵树的坡度，即 $\sum_{v} tilt(v)$。

**证明**：若 `root` 为空，$total$ 保持 $0$，空树坡度和为 $0$，成立。否则由引理 2，树中每个节点都被 `dfs` 访问恰好一次；由引理 1，每次访问都把当前节点坡度（连同其子树）累加进 $total$，而 $total$ 初值为 $0$、除此之外无其他写入，故结束时
$$total = \sum_{v} tilt(v).$$
函数最后按签名返回该值，定理得证。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n$ 为节点数。递归式为 $T(n) = T(l) + T(r) + O(1)$，每个节点做常数次加法、一次绝对差、一次累加，无重复访问；比「逐节点求子树和」的 $O(n^2)$ 少一个因子。
- **空间复杂度**：$O(h)$，$h$ 为树高，开销只来自递归栈。最坏（链状）$h = n = 10^4$ 层；最好（完全平衡）$h = \lceil \log_2(n+1) \rceil$。除栈以外只用了 `total` 一个标量，没有额外数组、哈希表或辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long total = 0;          // 用 64 位累加，避免极端数据的溢出争议

    long long dfs(TreeNode* node) {
        if (node == nullptr) return 0;              // 空子树：和为 0
        long long l = dfs(node->left);
        long long r = dfs(node->right);
        total += (l > r ? l - r : r - l);           // 坡度 = |S(L) - S(R)|
        return l + r + node->val;                   // 返回子树和给父节点
    }

    int findTilt(TreeNode* root) {
        total = 0;                                  // 同一实例可能被复用，必须清零
        dfs(root);
        return (int)total;                          // 官方签名返回 int
    }
};
```

### Python

```python
import sys


class Solution:
    def findTilt(self, root) -> int:
        # 链状树深度可达 10^4，默认递归上限 1000 会 RecursionError
        sys.setrecursionlimit(30000)
        self.total = 0

        def dfs(node) -> int:
            if node is None:
                return 0
            left = dfs(node.left)
            right = dfs(node.right)
            self.total += abs(left - right)     # 后序位置：两侧和都已返回
            return left + right + node.val      # 返回子树和

        dfs(root)
        return self.total
```

> 💡 若不想依赖递归上限，可改用显式栈 + 「访问标记」做后序：第一次弹出节点时压回并压入两个子节点，第二次弹出时用哈希表里已存的左右子树和结算，再把自己的和写回。代码约 20 行，适合作为递归的安全替代。

## 8. 边界情况与易错点

1. **空树**：`root = null` → 返回 `0`。空指针在 `dfs` 里直接返回 $0$、`total` 保持 $0$，无需在 `findTilt` 里特判。
2. **单节点**：左右皆空，坡度 $|0-0| = 0$；注意此时返回值是 `val`，不是 $0$——别把「坡度」和「子树和」混为一谈。
3. **只有一侧子树**：缺失的一侧按 $0$ 计，而不是跳过该节点。如 `[1,null,2]` 答案为 $2$（$|0-2|$），`[1,2]` 答案为 $2$（$|2-0|$）。
4. **负数节点值**：子树和可能为负，绝对值必须保留。如 `[0,-2,-1]` 左和 $-2$、右和 $-1$，坡度 $1$；若误写 `total += l - r` 会得 $-1$ 这类荒谬结果。
5. **漏加自身 `val`**：`return l + r` 是最常见的 WA 之一。用示例 3 自检：节点 7 的 $S$ 应为 $7+7+1 = 15$，若返回 $8$，根节点坡度立刻错。
6. **`total` 未清零**：LeetCode 可能复用实例；成员变量形式必须在每次 `findTilt` 开头重置，否则第二次调用结果翻倍。
7. **Python 递归深度**：$10^4$ 层链在默认上限 $1000$ 下必崩（已实测），要么 `sys.setrecursionlimit`，要么改迭代；C++ 递归不受影响。
8. **溢出**：单个子树和 $\le 10^7$ 在 `int` 内；但全正链的坡度总和理论上约 $5 \times 10^{10}$，超出 `int`。官方签名是 `int`，用 `long long` 累加是零成本的保险。
