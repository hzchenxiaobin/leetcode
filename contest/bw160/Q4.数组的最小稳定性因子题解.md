# LeetCode 数组的最小稳定性因子 题解

## 1. 题目概述

- **标题 / 题号**：数组的最小稳定性因子（#3605，hard）
- **链接**：https://leetcode.cn/problems/minimum-stability-factor-of-array/
- **来源**：LeetCode 第 160 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、线段树、数组、数学、二分查找、数论

**题意**：给定整数数组 `nums` 与整数 `maxC`。若一个子数组所有元素的最大公因数 $\ge 2$，称它是**稳定的**。数组的**稳定性因子**为**最长**稳定子数组的长度。

你**最多**可以把 `maxC` 个元素改成**任意整数**，求修改后数组的**最小可能稳定性因子**；若没有稳定子数组则返回 $0$。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- $0 \le \text{maxC} \le n$

> 💡 「改成任意整数」是极强的能力：把某个位置改成 $1$（或任何与邻居互质的数），所有包含它的子数组立刻不再稳定。

## 2. 示例

**示例 1**

```text
输入：nums = [3,5,10], maxC = 1
输出：1
解释：原数组有稳定子数组 [5,10]（GCD 5，长度 2）。把 5 改成 7 后，没有长度 > 1 的稳定子数组，因子 1。
```

**示例 2**

```text
输入：nums = [2,6,8], maxC = 2
输出：1
解释：把 6 改成 3、8 改成 5，得 [2,3,5]，没有长度 > 1 的稳定子数组。
```

**示例 3**

```text
输入：nums = [2,4,9,6], maxC = 1
输出：2
解释：稳定子数组有 [2,4]（GCD 2）与 [9,6]（GCD 3），两段互不相邻，改 1 个数只能破坏其中一段，故因子仍为 2。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「改哪些位置」（$\binom{n}{\text{maxC}}$ 种）显然不可行。即使只枚举最终因子 $k$ 并检查，单次检查若用「枚举所有长度 $k+1$ 的窗口、每个窗口扫一遍求 GCD」，是 $O(nk)$，配上 $k$ 的遍历就是 $O(n^3)$ 量级。

### 3.2 核心观察：二分答案 + 「所有长度 $k+1$ 的窗口 GCD 必须为 1」

![二分答案 k：判定能否把稳定性因子压到 <= k](images/bw160_q4_binary_search.svg)

- **判定转化**：稳定性因子 $\le k$ $\iff$ 不存在长度 $> k$ 的稳定子数组。
- **只需查长度恰为 $k+1$ 的窗口**：若存在长度 $> k+1$ 的稳定子数组，它内部必然包含一个长度 $k+1$ 的子数组，其 GCD 是原 GCD 的倍数，仍然 $\ge 2$，也是稳定的。所以「所有长度 $k+1$ 的窗口 GCD 都为 1」是充要条件。
- **单调性**：$k$ 越大条件越弱（要检查的窗口更少、更长，而长窗口的 GCD 只会更小），因此可以**二分**最小的可行 $k$。
- **区间 GCD**：用**稀疏表**做 $O(1)$ 查询（$O(n\log n)$ 预处理）。

### 3.3 算法流程

![检查函数：稀疏表 O(1) 查 GCD + 贪心改窗口最右端](images/bw160_q4_window_hit.svg)

```text
check(k):                       # 能否让稳定性因子 <= k
    若 k >= n: 返回 true         # 没有长度 n+1 的窗口
    used = 0；last = -1
    for i = 0 .. n-k-1:         # 窗口 [i, i+k]
        若 last >= i: 跳过       # 该窗口已包含被改过的位置（last），必然已被打破
        若 rangeGcd(i, i+k) > 1:
            used++；若 used > maxC: 返回 false
            last = i + k        # 贪心：改窗口最右端
    返回 true

主流程：
    lo = 0, hi = n
    while lo < hi:
        mid = (lo+hi)/2
        若 check(mid): hi = mid
        否则: lo = mid + 1
    返回 lo
```

**为什么改最右端**：这是一个经典的「区间刺点」问题——每个 GCD $>1$ 的窗口都必须被至少一个修改位置「覆盖」。把所有需要覆盖的窗口按右端点排序，选择当前窗口的**最右端点**作为修改位置，可以覆盖最多的后续窗口（因为后续窗口的左端点只会更靠右），贪心最优。

**为什么可以跳过 `last >= i` 的窗口**：一旦某个位置 $p$ 被改成 $1$，所有包含 $p$ 的窗口 GCD 都变成 $1$（$\gcd(1,x)=1$），而 $p = \text{last}$ 且窗口 $[i, i+k]$ 满足 $i \le p$ 时必然包含 $p$（因为 $p \le i + k$ 由 $p$ 是某个更早窗口的右端点可得）。

### 3.4 示例演算

![示例 3 的逐 k 判定](images/bw160_q4_example_walk.svg)

`nums = [2,4,9,6]`、`maxC = 1`：

| $k$ | 窗口长度 | 被打破的窗口 | 需要次数 | 可行？ |
|-----|---------|-------------|---------|--------|
| 0 | 1 | 所有 $>1$ 的元素（4 个） | 4 | 否 |
| 1 | 2 | $[0,1]$（GCD 2）与 $[2,3]$（GCD 3） | 2 | 否（`maxC = 1`） |
| 2 | 3 | $[0,2]$ GCD $\gcd(2,4,9)=1$；$[1,3]$ GCD $\gcd(4,9,6)=1$ | 0 | 是 |

二分过程：`mid = 2` 可行 $\to hi = 2$；`mid = 1` 不可行 $\to lo = 2$；收敛到 $2$，与官方输出一致。

## 4. 算法细节

1. **稀疏表**：`st[k][i]` 表示 $\gcd(\text{nums}[i..i+2^k-1])$，预处理 $O(n\log n)$；查询用两个长度 $2^{\lfloor\log len\rfloor}$ 的块拼起来（GCD 满足幂等性，重叠不影响）。
2. **`check(0)`**：窗口长度为 1，要求每个元素都变成 $1$——需要修改的次数等于「$>1$ 的元素个数」，可能超过 `maxC`。
3. **`check(n)`**：不存在长度 $n+1$ 的窗口，恒真；二分上界取 $n$ 保证有解（$n=1$ 时答案 0 或 1 都不会越界）。
4. **贪心的 `last` 初值**：$-1$ 表示「还没改过任何位置」；用 `last >= i` 判断窗口是否已被覆盖。
5. **`k + 1` 与 `n` 的关系**：循环条件 `i + k < n`，即窗口右端点 $i + k \le n-1$。
6. **`__builtin_clz` 求 $\log$**：`31 - __builtin_clz(len)` 对 `len >= 1` 安全；Python 版用预处理 `logs` 数组更稳。
7. **复杂度**：预处理 $O(n\log n)$，单次 `check` 是 $O(n)$（每个窗口 $O(1)$ 查 GCD），二分 $O(\log n)$ 次，总 $O(n\log n\log n)$；$n = 10^5$ 时约 $3\times10^7$ 次操作。
8. **`maxC = 0`**：不能改任何元素，答案就是原数组的稳定性因子；二分仍正确（`check` 只在「需要改的次数 $\le 0$」时可行）。

## 5. 正确性证明

**引理 1（长度归约）**：稳定性因子 $\le k$ $\iff$ 所有长度恰为 $k+1$ 的子数组的 GCD 都为 $1$。

**证明**：若存在长度 $> k+1$ 的稳定子数组 $A$，取其任意长度 $k+1$ 的连续子段 $B \subseteq A$，则 $\gcd(B)$ 是 $\gcd(A)$ 的倍数，故 $\gcd(B) \ge \gcd(A) \ge 2$，$B$ 稳定，必要性得证（逆否）。反之若所有长度 $k+1$ 的子数组 GCD 都为 $1$，则任何长度 $>k+1$ 的子数组都包含某个长度 $k+1$ 的子段，其 GCD 为 $1$，从而整个子数组 GCD 为 $1$，不可能是稳定的，充分性成立。∎

**引理 2（贪心的最优覆盖）**：设需要被「覆盖」（即至少包含一个被修改位置）的窗口集合为 $\mathcal{W}$，按左端点升序扫描，每次遇到尚未被覆盖的窗口 $W$ 就选取其**右端点**，则所选位置数最少。

**证明**：设首个未被覆盖的窗口为 $W = [i, i+k]$（其左端点 $i$ 最小）。任何可行解都必须选一个位置 $p \in W$。把 $p$ 换成 $i+k$：对任何左端点 $\ge i$ 的窗口，若它包含 $p$，则因为其右端点 $\ge i+k$（窗口长度固定），它也包含 $i+k$。故替换不会减少覆盖数，重复替换即得「每次选当前窗口右端点」不劣于任何可行解，归纳得最少性。∎

**引理 3（`check` 的正确性）**：`check(k)` 返回真 $\iff$ 存在至多 `maxC` 个位置的修改，使所有长度 $k+1$ 的窗口 GCD 为 $1$。

**证明**：充分性：被选中的位置改成 $1$ 后，任何包含它的窗口 GCD 为 $1$；`check` 保证每个 GCD $>1$ 的窗口都包含某个选中位置（要么当次选中其右端点，要么之前已被 `last` 覆盖），故所有窗口 GCD 为 $1$。必要性：由引理 2，需要覆盖的窗口若至少需要 `maxC+1` 个位置，则任何 $\le \text{maxC}$ 的修改都无法覆盖全部，`check` 在 `used > maxC` 时返回假，正确。∎

**定理**：算法输出为最小可能的稳定性因子。

**证明**：由引理 1、3，`check(k)` 恰判定「能否使稳定性因子 $\le k$」；该判定关于 $k$ 单调（因子 $\le k$ 蕴含因子 $\le k+1$），故二分收敛到最小的可行 $k$。又 $k = n$ 恒可行（无长度 $n+1$ 的窗口），二分必有解。∎

## 6. 复杂度分析

- **时间**：$O(n\log n\log n)$。稀疏表预处理 $O(n\log n)$；每次 `check` 扫描 $O(n)$ 个窗口、每窗口 $O(1)$ GCD 查询；二分至多 $O(\log n)$ 次。$n = 10^5$ 时约 $10^5\times17\times17 \approx 3\times10^7$ 次基本运算。
- **空间**：$O(n\log n)$。稀疏表 $\text{LOG}\times n \approx 17\times10^5$ 个整数，约 7 MB；若用线段树可降到 $O(n)$ 但查询 $O(\log n)$（总复杂度变为 $O(n\log^2 n\log n)$，通常反而更慢）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minStable(vector<int>& nums, int maxC) {
        int n = (int)nums.size();
        int LOG = 1;
        while ((1 << LOG) <= n) LOG++;
        // 稀疏表：st[k][i] = gcd(nums[i .. i+2^k-1])
        vector<vector<int>> st(LOG, vector<int>(n, 0));
        st[0] = nums;
        for (int k = 1; k < LOG; k++) {
            for (int i = 0; i + (1 << k) <= n; i++) {
                st[k][i] = std::gcd(st[k - 1][i], st[k - 1][i + (1 << (k - 1))]);
            }
        }
        auto rangeGcd = [&](int l, int r) {
            int len = r - l + 1;
            int k = 31 - __builtin_clz((unsigned)len);
            return std::gcd(st[k][l], st[k][r - (1 << k) + 1]);
        };

        // 能否把稳定性因子压到 <= k：等价于所有长度 k+1 的窗口 GCD 都为 1
        auto feasible = [&](int k) {
            if (k >= n) return true;
            int used = 0, last = -1;
            for (int i = 0; i + k < n; i++) {
                if (last >= i) continue;                 // 该窗口已被改过的位置打破
                if (rangeGcd(i, i + k) > 1) {
                    if (++used > maxC) return false;
                    last = i + k;                        // 贪心：改窗口最右端
                }
            }
            return true;
        };

        int lo = 0, hi = n;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (feasible(mid)) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
};
```

### Python

```python
from math import gcd


class Solution:
    def minStable(self, nums: list[int], maxC: int) -> int:
        n = len(nums)
        LOG = max(1, n.bit_length())
        # 稀疏表：st[k][i] = gcd(nums[i .. i+2^k-1])
        st = [nums[:]]
        for k in range(1, LOG):
            half = 1 << (k - 1)
            span = 1 << k
            prev = st[k - 1]
            cur = [0] * (n - span + 1) if n - span + 1 > 0 else []
            for i in range(len(cur)):
                cur[i] = gcd(prev[i], prev[i + half])
            st.append(cur)
        logs = [0] * (n + 2)
        for i in range(2, n + 2):
            logs[i] = logs[i >> 1] + 1

        def range_gcd(l: int, r: int) -> int:
            length = r - l + 1
            k = logs[length]
            return gcd(st[k][l], st[k][r - (1 << k) + 1])

        def feasible(k: int) -> bool:
            """能否把稳定性因子压到 <= k"""
            if k >= n:
                return True
            used, last = 0, -1
            for i in range(n - k):          # 窗口 [i, i+k]
                if last >= i:               # 已被改过的位置打破
                    continue
                if range_gcd(i, i + k) > 1:
                    used += 1
                    if used > maxC:
                        return False
                    last = i + k            # 贪心：改窗口最右端
            return True

        lo, hi = 0, n
        while lo < hi:
            mid = (lo + hi) // 2
            if feasible(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

## 8. 边界情况与易错点

1. **只查长度 $k+1$ 的窗口**：不能只查「稳定子数组」是否存在，必须查**每个**长度 $k+1$ 的窗口；漏查会低估需要的修改数。
2. **`last >= i` 的跳过条件**：被改位置 $p$ 覆盖的窗口是「左端点 $\le p$ 且右端点 $\ge p$」的那些；由于窗口长度固定且按左端点递增扫描，判断 `last >= i` 即可。
3. **贪心改右端而非左端**：改左端会漏掉右侧紧邻的窗口，导致需要的修改数变多。
4. **`k = 0` 的语义**：要求所有元素 GCD $\ge 2$ 的子数组都不存在，即每个元素都必须是 $1$（或与所有邻居互质），需要改的次数 = 值 $>1$ 的元素个数。
5. **`k = n`**：没有长度 $n+1$ 的窗口，恒可行；二分上界必须取 $n$（而不是 $n-1$），否则 `maxC = 0` 且整个数组 GCD $>1$ 时会无解。
6. **`maxC = 0`**：一个都不能改，答案即原稳定性因子；代码无需特判。
7. **线段树 vs 稀疏表**：线段树单次查询 $O(\log n)$，会让 `check` 变成 $O(n\log n)$，二分后总 $O(n\log^2 n)$，比稀疏表多一个 $\log$。
8. **`__builtin_clz(0)` 未定义**：`len >= 1` 恒成立（窗口非空），安全；Python 版用预处理的 `logs` 数组避免了同类问题。
