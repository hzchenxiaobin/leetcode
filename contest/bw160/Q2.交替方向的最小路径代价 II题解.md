# LeetCode 交替方向的最小路径代价 II 题解

## 1. 题目概述

- **标题 / 题号**：交替方向的最小路径代价 II（#3603，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-path-with-alternating-directions-ii/
- **来源**：LeetCode 第 160 场双周赛 Q2
- **难度**：中等
- **标签**：数组、动态规划、矩阵

**题意**：给定 $m \times n$ 的网格。**进入**格子 $(i,j)$ 的代价为 $(i+1)(j+1)$。另有 `waitCost[i][j]` 表示在该格**等待**一秒的代价。

路径从第 1 秒进入 $(0,0)$ 并支付入场费开始，之后按交替节奏行动：

- **奇数秒**：必须向右或向下移动到相邻格，并支付该格的入场费；
- **偶数秒**：必须原地等待恰好 1 秒，支付 `waitCost[i][j]`。

求到达 $(m-1, n-1)$ 的最小总代价。

**约束**：

- $1 \le m, n \le 10^5$，$2 \le m\times n \le 10^5$
- $0 \le \text{waitCost}[i][j] \le 10^5$

> 💡 注意 $m$ 或 $n$ 可以到 $10^5$，但**乘积**只有 $10^5$——所以 $O(mn)$ 的 DP 完全可行，只要别开 $10^5\times10^5$ 的二维数组。

## 2. 示例

**示例 1**

```text
输入：m = 1, n = 2, waitCost = [[1,2]]
输出：3
解释：第 1 秒进入 (0,0) 付 1；第 1 秒向右到 (0,1) 付 (0+1)(1+1)=2。总 3（没有等待）。
```

**示例 2**

```text
输入：m = 2, n = 2, waitCost = [[3,5],[2,4]]
输出：9
解释：1（进入 (0,0)）+ 2（进入 (1,0)）+ 2（在 (1,0) 等待）+ 4（进入 (1,1)）= 9。
```

**示例 3**

```text
输入：m = 2, n = 3, waitCost = [[6,1,4],[3,2,5]]
输出：16
解释：1 + 2（进 (0,1)）+ 1（在 (0,1) 等）+ 4（进 (1,1)）+ 2（在 (1,1) 等）+ 6（进 (1,2)）= 16。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有「只向右/向下」的单调路径，共 $\binom{m+n-2}{m-1}$ 条，逐条按秒模拟累加代价。$m = n = 316$ 时路径数已是天文数字，不可行。需要 DP。

### 3.2 核心观察：等待发生在「除起点、终点外的每个路径格」

![时间轴：奇数秒移动、偶数秒等待](images/bw160_q2_seconds_model.svg)

把时间轴摊开看：第 1 秒进入 $(0,0)$ 并立即支付入场费；从第 1 秒起「移动 / 等待」交替。因此：

- 移动到终点共需 $(m-1)+(n-1)$ 次移动，耗时固定，与具体路径**无关**；
- 等待次数 $=$ 移动次数 $-1$，等待发生在**每次移动之后、下一次移动之前**所在的那个格子，也就是「路径上除起点与终点之外的每个格子」；
- 起点 $(0,0)$ 不需要等待（第 1 秒直接走），终点不需要等待（到了就结束，示例 1 只有 1 次移动、0 次等待）。

于是总代价可以写成与路径一一对应的式子：

$$\text{cost}(P) = \sum_{(i,j)\in P}(i+1)(j+1) + \sum_{(i,j)\in P,\ (i,j)\ne \text{起点},\ (i,j)\ne\text{终点}} \text{waitCost}[i][j]$$

第一项是入场费（**所有**经过的格子，含起点终点），第二项是途经格（**不含**起点终点）的等待费。

### 3.3 算法流程

![DP：到达每个格子的最小代价与上一格的等待费](images/bw160_q2_dp_grid.svg)

定义

$$\text{dp}[i][j] = \text{到达 }(i,j)\text{ 的最小代价（含 }(i,j)\text{ 的入场费，不含在此等待的费用）}$$

转移时，从上一格 $p$ 过来要先把「在 $p$ 等待一拍」的钱付掉：

$$\text{dp}[i][j] = (i+1)(j+1) + \min\big(g[i-1][j],\ g[i][j-1]\big),\qquad g[p] = \begin{cases}\text{dp}[0][0], & p = (0,0)\\ \text{dp}[p] + \text{waitCost}[p], & \text{否则}\end{cases}$$

$$ \text{dp}[0][0] = 1 $$

```text
for i = 0 .. m-1:
    for j = 0 .. n-1:
        enter = (i+1)*(j+1)
        if (i,j) == (0,0): dp = enter; continue
        best = +inf
        if i > 0: best = min(best, dp[i-1][j] + (i-1,j) == (0,0) ? 0 : waitCost[i-1][j])
        if j > 0: best = min(best, dp[i][j-1] + (i,j-1) == (0,0) ? 0 : waitCost[i][j-1])
        dp[i][j] = best + enter
返回 dp[m-1][n-1]
```

### 3.4 示例演算

![示例 2 的四步付费](images/bw160_q2_example_walk.svg)

示例 2：$m=n=2$，`waitCost = [[3,5],[2,4]]`。

| 步骤 | 位置 | 付费类型 | 金额 | 累计 |
|------|------|---------|------|------|
| 第 1 秒 | $(0,0)$ | 入场 | $(0+1)(0+1) = 1$ | 1 |
| 第 1 秒 | $(1,0)$ | 入场 | $(1+1)(0+1) = 2$ | 3 |
| 第 2 秒 | $(1,0)$ | 等待 | `waitCost[1][0] = 2` | 5 |
| 第 3 秒 | $(1,1)$ | 入场 | $(1+1)(1+1) = 4$ | 9 |

若改走「先右后下」：$1 + 2 + \text{waitCost}[0][0]=3 + 4 = 10 > 9$，DP 在 $(1,1)$ 处会比较两条来路并选小的那条。

**注意**：起点 $(0,0)$ 的 `waitCost[0][0] = 3` **不会**被支付——这是最容易多算的地方。

## 4. 算法细节

1. **$g[p]$ 的处理**：只有在 $p$ 不是起点时才加 `waitCost[p]`；代码里用 `(i-1 == 0 && j == 0)` 与 `(i == 0 && j-1 == 0)` 判断。
2. **`dp[0][0] = 1`**：起点入场费恰好是 $(0+1)(0+1) = 1$，不要漏。
3. **终点不加等待费**：返回 `dp[m-1][n-1]` 即可，因为 `dp` 的定义里本来就不含「在本格等待」的费用。
4. **空间**：`m*n <= 1e5`，二维 DP 数组 $10^5$ 个 `long long` 约 800 KB，完全够用；若想更省，可只保留上一行。
5. **遍历顺序**：按行优先（$i$ 外层、$j$ 内层）即可，转移只依赖上、左。
6. **`m = 1` 或 `n = 1`**：退化成一维，转移只剩一个方向；此时路径上除起点终点外没有中间格，等待费为 0（示例 1）。
7. **数值范围**：入场费最大 $(10^5)(10^5)$ 但 $m\times n \le 10^5$ 限制了一边的大小，实际单格入场费 $\le 10^5$；路径代价上界约 $10^{10}$，用 `long long`。
8. **`waitCost` 可以为 0**：不影响正确性，无需特判。

## 5. 正确性证明

**引理 1（等待位置的刻画）**：沿任一条单调路径 $P = (c_0, c_1, \dots, c_{L})$（$c_0$ 为起点、$c_L$ 为终点、$L = m+n-2$），等待恰好发生在 $c_1, c_2, \dots, c_{L-1}$ 这些格子上，每格恰好一次；起点与终点不等待。

**证明**：第 1 秒进入 $c_0$ 后，移动与等待交替：移动 $c_0\to c_1$、等待（在 $c_1$）、移动 $c_1\to c_2$、等待（在 $c_2$）……最后一次移动 $c_{L-1}\to c_L$ 之后到达终点，过程结束，不再等待。因此等待发生在 $c_1, \dots, c_{L-1}$，各一次。∎

**引理 2（代价分解）**：对路径 $P$，总代价 $= \sum_{k=0}^{L}(c_k^{(i)}+1)(c_k^{(j)}+1) + \sum_{k=1}^{L-1}\text{waitCost}[c_k]$。

**证明**：入场费在「进入每个格子」时支付一次，路径恰好进入 $c_0, \dots, c_L$ 各一次，故第一项。等待费由引理 1 恰在 $c_1..c_{L-1}$ 各付一次，故第二项。两项之外没有其他付费。∎

**引理 3（转移正确）**：设 $\text{dp}[p]$ 表示到达 $p$ 的最小代价（含入场费、不含在 $p$ 的等待费）。则对 $(i,j)\ne(0,0)$，

$$\text{dp}[i][j] = (i+1)(j+1) + \min_{p \in \{\text{上, 左}\}}\big(\text{dp}[p] + w(p)\big)$$

其中 $w(p) = 0$ 若 $p$ 是起点，否则 $w(p) = \text{waitCost}[p]$。

**证明**：到达 $(i,j)$ 的最后一步必然来自上方 $(i-1,j)$ 或左方 $(i,j-1)$（单调路径）。由引理 1，在这两个格子上都必须等待一拍（除非它是起点），因此到达 $(i,j)$ 的代价 $=$ 到达 $p$ 的最小代价 $+$ 在 $p$ 等待的代价 $+$ 进入 $(i,j)$ 的入场费。对两个来路取最小即为最优子结构；且子问题与原问题同构，故最优性成立。∎

**定理**：算法返回值为到达 $(m-1,n-1)$ 的最小总代价。

**证明**：由引理 2，任一单调路径的代价由引理 3 的递推式逐步累加得到；DP 按行列顺序计算，每个状态取所有前驱的最小值，属于标准的最短路/DP 最优子结构。因此 $\text{dp}[m-1][n-1]$ 是所有单调路径代价的最小值，即所求。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个格子做 $O(1)$ 次比较与加法，$m\times n \le 10^5$。
- **空间**：$O(mn)$。二维 `long long` 数组约 $800$ KB；若按行滚动可降到 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minCost(int m, int n, vector<vector<int>>& waitCost) {
        // dp[i][j]：到达 (i,j) 的最小总代价（含 (i,j) 的入场费，不含在 (i,j) 等待的费用）
        vector<vector<long long>> dp(m, vector<long long>(n, 0));
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                long long enter = 1LL * (i + 1) * (j + 1);
                if (i == 0 && j == 0) {
                    dp[i][j] = enter;          // 起点只有入场费，不需要等待
                    continue;
                }
                long long best = LLONG_MAX;
                if (i > 0) {
                    // 从上方进入：在 (i-1,j) 等待一拍（起点除外）
                    long long w = (i - 1 == 0 && j == 0) ? 0 : waitCost[i - 1][j];
                    best = min(best, dp[i - 1][j] + w);
                }
                if (j > 0) {
                    long long w = (i == 0 && j - 1 == 0) ? 0 : waitCost[i][j - 1];
                    best = min(best, dp[i][j - 1] + w);
                }
                dp[i][j] = best + enter;
            }
        }
        return dp[m - 1][n - 1];
    }
};
```

### Python

```python
class Solution:
    def minCost(self, m: int, n: int, waitCost: list[list[int]]) -> int:
        # dp[i][j]：到达 (i,j) 的最小总代价（含 (i,j) 入场费，不含在 (i,j) 等待的费用）
        dp = [[0] * n for _ in range(m)]
        for i in range(m):
            for j in range(n):
                enter = (i + 1) * (j + 1)
                if i == 0 and j == 0:
                    dp[i][j] = enter         # 起点只有入场费，不需要等待
                    continue
                best = None
                if i > 0:
                    w = 0 if (i - 1 == 0 and j == 0) else waitCost[i - 1][j]
                    best = dp[i - 1][j] + w
                if j > 0:
                    w = 0 if (i == 0 and j - 1 == 0) else waitCost[i][j - 1]
                    cand = dp[i][j - 1] + w
                    best = cand if best is None else min(best, cand)
                dp[i][j] = best + enter
        return dp[m - 1][n - 1]
```

## 8. 边界情况与易错点

1. **起点等待费不要付**：$m=1,n=2$ 时如果给起点加了 `waitCost[0][0]`，示例 1 会算成 $1+1+2=4$ 而不是 3。
2. **终点等待费不要付**：`dp` 的定义不含「在本格等待」，返回值直接用 `dp[m-1][n-1]`，不要再加 `waitCost[m-1][n-1]`。
3. **`dp[0][0]` 的初值**：入场费是 $(0+1)(0+1)=1$，不是 0。
4. **$m=1$ 或 $n=1$**：路径唯一，且没有中间格 → 等待费全为 0（示例 1）。
5. **`m*n` 很大但单边不大**：$1\le m,n\le 10^5$ 且 $m\times n\le 10^5$，所以二维数组不会爆内存；但不要用 $O(m^2)$ 或 $O(n^2)$ 的写法。
6. **`int` 溢出**：代价可达 $10^{10}$，必须 `long long`。
7. **`waitCost` 全 0**：答案就是单纯的最小入场费路径（贴着左上角走），无需特判。
8. **行列顺序**：转移只依赖「上」和「左」，行优先遍历即可，别写成列优先还漏掉依赖。
