# LeetCode 细分图中的可到达节点 题解

## 1. 题目概述

- **标题 / 题号**：细分图中的可到达节点（#882，hard）
- **链接**：https://leetcode.cn/problems/reachable-nodes-in-subdivided-graph/
- **来源**：LeetCode 第 96 场周赛 Q4
- **难度**：困难
- **标签**：图、最短路、Dijkstra 算法、堆（优先队列）

**题意**：一张 $n$ 个节点（编号 $0 \sim n-1$）的无向图，边由 `edges[i] = [u_i, v_i, cnt_i]` 给出。把每条边**细分**：在 $u_i$ 与 $v_i$ 之间插入 $cnt_i$ 个新节点，形成 $cnt_i + 1$ 条边。

在新图中从节点 $0$ 出发，若到某节点的最短距离 $\le maxMoves$，则称该节点**可到达**。求新图中可到达节点的总数（包含原始节点与新增的细分节点）。

**关键点**：

- 细分点数量可达 $10^4 \times 10^4 = 10^8$，**不能把新图真的建出来**。
- 原始节点之间的距离为 $cnt_i + 1$（穿过一条边要走 $cnt_i+1$ 步），所以先在**原图**上跑最短路。
- 细分节点只通过所在的那条边被到达，可以从边的两端分别「吃进一截」，再取并集。

**约束**：

- $1 \le n \le 3000$，$0 \le edges.length \le \min\!\left(\frac{n(n-1)}{2}, 10^4\right)$
- $0 \le cnt_i \le 10^4$，$0 \le maxMoves \le 10^9$
- 图中不存在平行边

## 2. 示例

**示例 1**

```text
输入：edges = [[0,1,10],[0,2,1],[1,2,2]], maxMoves = 6, n = 3
输出：13
解释：原图最短路 dist = [0, 5, 2]（0→2 花 2 步，2→1 再花 3 步）。
     3 个原始节点都可到达；
     边 0–1 内可达 min(10, 6 + 1) = 7 个；边 0–2 内 1 个；边 1–2 内 min(2, 1+4) = 2 个。
     合计 3 + 7 + 1 + 2 = 13。
```

输入：edges = [[0,1,4],[1,2,6],[0,2,8],[1,3,1]], maxMoves = 10, n = 4
输出：23
解释：4 个原始节点 + 各边内部可达的细分点，合计 23。
```

```

## 3. 解题思路

### 3.1 暴力思路

真的把新图建出来：每条边插入 $cnt_i$ 个节点，总节点数 $n + \sum cnt_i$，最坏 $3000 + 10^4 \times 10^4 = 10^8$，内存与时间都不可接受（BFS 也会 $10^8$ 级）。

即便建出来了，BFS 的复杂度是 $O(V + E) = O(10^8)$，在 $10^4$ 条边、每条 $10^4$ 个细分点的最坏数据下必然超时。

### 3.2 核心观察：压缩成「边权 $cnt+1$」的原图

![Dijkstra + 两端各吃一截](images/wc96_q4_dijkstra_count.svg)

**第一步：在原图上求最短路。** 细分边 $[u,v,cnt]$ 中，从 $u$ 走到 $v$ 必须经过 $cnt+1$ 条单位边，即 $cnt+1$ 步。所以把每条边压缩成「权重 $cnt+1$」的边，原图中 $0$ 到 $i$ 的最短距离 `dist[i]` 就等于新图中 $0$ 到原始节点 $i$ 的最短距离。用 Dijkstra（边权非负）求即可，复杂度 $O((n + m)\log n)$。

**第二步：数原始节点。** 满足 `dist[i] <= maxMoves` 的原始节点都可到达，共 $\#\{i : dist[i] \le maxMoves\}$。

**第三步：数每条边内部的细分点。** 对边 $[u, v, cnt]$，站在 $u$ 一侧最多能往里走

$$a = \max(0,\ maxMoves - dist[u])$$

步；站在 $v$ 一侧最多能往里走

$$b = \max(0,\ maxMoves - dist[v])$$

步。这条边上共有 $cnt$ 个细分点：

- 从 $u$ 侧能到达的是**最靠 $u$ 的 $a$ 个**（若 $a \ge cnt$ 则全都能到）；
- 从 $v$ 侧能到达的是**最靠 $v$ 的 $b$ 个**。

两者的并集大小就是这条边的贡献：

$$\text{contrib} = \min\big(cnt,\ a + b\big)$$

**为什么可以直接「相加再封顶」？** 因为两侧各吃进的是一个**前缀**与一个**后缀**：若 $a + b \le cnt$，两段不重叠，并集大小就是 $a+b$；若 $a + b > cnt$，两段必然覆盖整条边（前缀吃掉前 $a$ 个、后缀吃掉后 $b$ 个，$a + b \ge cnt$ 意味着没有漏掉的），并集大小就是 $cnt$。两种情况统一写作 $\min(cnt, a+b)$。

**第四步**：把三部分相加即为答案。

### 3.3 算法流程

```text
1. 建原图邻接表：对每条 [u,v,cnt]，加两条权重为 cnt+1 的边
2. Dijkstra 求 dist[]（起点 0）
3. ans = #{ i : dist[i] <= maxMoves }
4. for 每条边 [u, v, cnt]：
      a = dist[u] <= maxMoves ? maxMoves - dist[u] : 0
      b = dist[v] <= maxMoves ? maxMoves - dist[v] : 0
      ans += min(cnt, a + b)
5. 返回 ans
```

原图边权：$0\text{–}1$ 为 $11$、$0\text{–}2$ 为 $2$、$1\text{–}2$ 为 $3$。Dijkstra 结果 `dist = [0, 5, 2]`（$0 \to 2 \to 1$ 共 $2 + 3 = 5$ 步，优于直接的 $11$）。

| 对象 | 计算 | 贡献 |
|------|------|------|
| 原始节点 | `dist = [0,5,2]`，全部 $\le 6$ | $3$ |
| 边 0–1（$cnt=10$） | $\min(10, (6-0) + (6-5)) = \min(10, 7)$ | $7$ |
| 边 0–2（$cnt=1$） | $\min(1, (6-0) + (6-2)) = \min(1, 10)$ | $1$ |

## 4. 算法细节

1. **边权的含义**：$cnt+1$ 而不是 $cnt$。细分后 $u$ 与 $v$ 之间有 $cnt+1$ 条单位边，走完要 $cnt+1$ 步——这是最容易写错的一处。
2. **`dist` 用 `long long`**：$maxMoves$ 可达 $10^9$，$cnt+1$ 可达 $10^4 + 1$，路径长度累加可能超过 $2^{31}$，用 `long long` 更安全（实际上最短路不超过 $n \cdot 10^4$ 量级，但求稳）。
3. **不可达节点的处理**：`dist[i] > maxMoves`（或为 `INF`）时，它不能作为「进入该边」的入口，对应的 $a$ 或 $b$ 应取 $0$。用 `dist[i] <= maxMoves ? maxMoves - dist[i] : 0` 统一处理。
4. **孤立点**：示例 3 中节点 0 没有边，Dijkstra 只访问到它自己，`ans` 初始为 $1$（若 $0 \le maxMoves$），其余边两侧都不可达，贡献为 $0$。
5. **不需要建新图**：整个算法只在原图上跑 Dijkstra，边内部的计数是纯公式。
6. **`cnt = 0`**：该边没有细分点，贡献 $\min(0, \cdot) = 0$，公式自然成立。
7. **重边不可能存在**（题目保证），所以每条边只需处理一次。

## 5. 正确性证明

**引理 1（距离压缩）**：新图中从 $0$ 到一个**原始节点** $i$ 的最短距离，等于原图中以 $cnt_e + 1$ 为边权的最短距离 `dist[i]`。

**证明**：新图中任意一条从 $0$ 到 $i$ 的路径，按经过的原始节点切分成若干段；每段要么在原始节点间径直穿过某条细分边（长度恰为 $cnt_e + 1$，且中途没有其它原始节点），要么是细致的往返（不会更短）。把每段替换为原图中对应的边，得到原图中长度相同的路径，故 `dist[i]` $\le$ 新图距离。反之，原图中每条边都可展开成 $cnt_e+1$ 条单位边，故原图路径可展开为新图路径，新图距离 $\le$ `dist[i]`。两个方向结合即得相等。∎

**引理 2（边内可达集是前缀/后缀）**：对边 $e = [u,v,cnt]$，从 $u$ 沿该边向 $v$ 走，第 $t$ 个细分点（$1 \le t \le cnt$）在新图中的最短距离为 $\min(dist[u] + t,\ dist[v] + (cnt + 1 - t))$。

**证明**：到达该点只有两条途径——从 $u$ 侧进入（走 $t$ 步）或从 $v$ 侧进入（走 $cnt+1-t$ 步），而绕行其它边不可能更短（任何绕行都要回到 $u$ 或 $v$，而 `dist[u]`、`dist[v]` 已是各自的最短距离）。故距离为两者最小值。∎

**引理 3（贡献公式）**：边 $e$ 内部可到达的细分点个数为 $\min(cnt,\ a + b)$，其中 $a = \max(0, M - dist[u])$、$b = \max(0, M - dist[v])$、$M = maxMoves$。

**证明**：由引理 2，第 $t$ 个点可达 $\iff \min(dist[u] + t, dist[v] + cnt + 1 - t) \le M$，等价于 $t \le M - dist[u]$ 或 $t \ge cnt + 1 - (M - dist[v])$。即：可达集合是「前 $a$ 个」与「后 $b$ 个」的并集（长度不足时自然截断）。前缀与后缀的并集大小：若 $a + b \le cnt$ 则两段不重叠，大小为 $a+b$；若 $a+b > cnt$ 则覆盖全部 $cnt$ 个，大小为 $cnt$。统一为 $\min(cnt, a+b)$。∎

**定理**：算法返回值等于新图中从 $0$ 出发距离 $\le maxMoves$ 的节点总数。

**证明**：新图的节点分成两类：原始节点与细分节点。原始节点由引理 1 判定，算法累加 $\#\{i: dist[i] \le M\}$，正确；细分节点各自属于唯一的边，由引理 3 每条边的贡献被精确计数一次，且不同边的细分点互不相同。两类相加即为总数。∎

## 6. 复杂度分析

- **时间**：$O((n + m)\log n)$。建图 $O(m)$；Dijkstra 用二叉堆 $O((n+m)\log n)$；最后扫描 $m$ 条边 $O(m)$。$n \le 3000$、$m \le 10^4$，约 $10^5$ 级操作。
- **空间**：$O(n + m)$。邻接表与 `dist` 数组；**不需要**存储任何细分节点。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int reachableNodes(vector<vector<int>>& edges, int maxMoves, int n) {
        vector<vector<pair<int, int>>> adj(n);
        for (auto& e : edges) {
            int u = e[0], v = e[1], c = e[2];
            adj[u].push_back({v, c + 1});      // 穿过这条边要 c+1 步
            adj[v].push_back({u, c + 1});
        }
        const long long INF = (1LL << 60);
        vector<long long> dist(n, INF);
        priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> pq;
        dist[0] = 0;
        pq.push({0, 0});
        while (!pq.empty()) {
            auto [d, u] = pq.top(); pq.pop();
            if (d > dist[u]) continue;
            for (auto [v, w] : adj[u]) {
                if (d + w < dist[v]) { dist[v] = d + w; pq.push({dist[v], v}); }
            }
        }
        long long ans = 0;
        for (int i = 0; i < n; i++) if (dist[i] <= maxMoves) ans++;   // 原始节点
        for (auto& e : edges) {
            int u = e[0], v = e[1], c = e[2];
            long long a = (dist[u] <= maxMoves) ? maxMoves - dist[u] : 0;
            long long b = (dist[v] <= maxMoves) ? maxMoves - dist[v] : 0;
            ans += min<long long>(c, a + b);                          // 边内的细分节点
        }
        return (int)ans;
    }
};
```

### Python

```python
import heapq

class Solution:
    def reachableNodes(self, edges: list[list[int]], maxMoves: int, n: int) -> int:
        adj = [[] for _ in range(n)]
        for u, v, c in edges:
            adj[u].append((v, c + 1))       # 细分后 u→v 要 c+1 步
            adj[v].append((u, c + 1))

        INF = float('inf')
        dist = [INF] * n
        dist[0] = 0
        pq = [(0, 0)]
        while pq:
            d, u = heapq.heappop(pq)
            if d > dist[u]:
                continue
            for v, w in adj[u]:
                nd = d + w
                if nd < dist[v]:
                    dist[v] = nd
                    heapq.heappush(pq, (nd, v))

        ans = sum(1 for d in dist if d <= maxMoves)        # 原始节点
        for u, v, c in edges:
            a = maxMoves - dist[u] if dist[u] <= maxMoves else 0
            b = maxMoves - dist[v] if dist[v] <= maxMoves else 0
            ans += min(c, a + b)                            # 边内细分点
        return ans
```

## 8. 边界情况与易错点

1. **边权写成 `cnt` 而不是 `cnt+1`**：细分 $cnt$ 个点后有 $cnt+1$ 条边，走完要 $cnt+1$ 步。这是本题第一大坑。
2. **真的建新图**：最坏 $10^8$ 个点，必然超时/超内存。必须用「压缩 + 公式」。
3. **`min(cnt, a+b)` 的封顶**：不封顶会把同一条边上两端重叠的部分重复计数，答案偏大（示例 1 的边 0–2 会算成 $10$ 而不是 $1$）。
4. **不可达端点的 $a$/$b$**：`dist[u]` 为 `INF` 时不能直接相减（会溢出或得到负数），必须特判为 $0$。
5. **节点 0 孤立**：示例 3 中 `dist[0] = 0 \le 17`，答案为 $1$；若把「无边」当作不可达会错答 $0$。
6. **`cnt = 0`**：贡献为 $0$，公式 `min(0, ...) = 0` 自动正确。
7. **`maxMoves` 很大**（如 $10^9$）：所有原始节点与所有细分点都可到达，答案 $= n + \sum cnt_i$；公式自然给出这个值。
8. **`dist` 用 `int`**：$maxMoves$ 达到 $10^9$，$maxMoves - dist$ 仍在 `int` 内，但累加答案可能超过 `int`（$\sum cnt \le 10^8$，仍在范围内）——为稳妥用 `long long`。
