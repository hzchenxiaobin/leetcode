# LeetCode 救生艇 题解

## 1. 题目概述

- **标题 / 题号**：救生艇（#881，medium）
- **链接**：https://leetcode.cn/problems/boats-to-save-people/
- **来源**：LeetCode 第 96 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、双指针、排序

**题意**：第 $i$ 个人的体重是 `people[i]`。每艘船的载重上限为 `limit`，**每艘船最多载两人**，且同船两人的体重之和不得超过 `limit`。船的数量不限，求把所有人运走所需的**最少**船数。

**关键点**：

- 「每船最多两人」把问题从装箱（NP-hard）拉回了可贪心的范围。
- 题目保证 $people[i] \le limit$，所以人人至少能单独上船，一定有解。
- 船数最少 $\iff$ 让尽可能多的人**两两拼船**。

**约束**：

- $1 \le people.length \le 5\times 10^4$
- $1 \le people[i] \le limit \le 3\times 10^4$

## 2. 示例

**示例 1**

```text
输入：people = [1,2], limit = 3
输出：1
解释：1 + 2 = 3 ≤ 3，两人同船，只需 1 艘。
```

**示例 2**

```text
输入：people = [3,2,2,1], limit = 3
输出：3
解释：排序后 [1,2,2,3]。3 只能单走；1 与 2 同船；剩下一个 2 单走。共 3 艘。
```

**示例 3**

```text
输入：people = [3,5,3,4], limit = 5
输出：4
解释：5 必须单走；3+3 = 6 > 5、3+4 = 7 > 5，任意两人都无法同船，故 4 人 4 船。
```

## 3. 解题思路

### 3.1 暴力思路

「最少船数」等价于「最大化两人组数量」：求最多能组成多少个满足 $p_i + p_j \le limit$ 的配对，答案 $= n - \text{配对数}$。这是二分图最大匹配，匈牙利算法 $O(n^3)$，$n = 5\times10^4$ 时不可能通过。

也可以枚举所有配对方式，指数级，同样不可行。但本题有极强的结构：**配对只取决于体重之和，且每船至多两人**。把体重排序后，最重的人最难安置——这提示我们从最重的开始处理。

### 3.2 核心观察：最重者必上船，能带最轻的就带

![排序后双指针：最重的人必上船，再看最轻的能否同行](images/wc96_q2_boats_two_pointers.svg)

把 `people` 升序排序，用两个指针 `lo`（最轻）、`hi`（最重）：

1. **`people[hi]` 必须被安排**：它是当前最重的，无论和谁同船都占一个位置，所以每轮至少消耗一条船。
2. 既然要给它配一个人，就配**最轻的** `people[lo]`：
   - 若 `people[lo] + people[hi] <= limit`：两人同船，`lo++`、`hi--`，一条船解决两个人（「赚到」）。
   - 否则：连最轻的都配不上它，说明**剩余任何人也配不上它**（其余人都比 `people[lo]` 重），它只能独坐，`hi--`。
3. 两种情形下 `hi` 都减 $1$（最重者被处理掉），船数加 $1$。

**为什么配最轻的？** 最轻的人「最百搭」：把他用在最重者身上，剩下的中等体重者之间更容易配对；若拿一个中等体重的人去配最重者而配不上，反而浪费了一次机会，同时最轻的人还要另占一条船。严格论证见 §5 的交换引理。

### 3.3 算法流程

```text
1. people 升序排序
2. lo = 0，hi = n − 1，boats = 0
3. while lo <= hi：
   3.1 if people[lo] + people[hi] <= limit：lo += 1     // 最轻的能同行
   3.2 hi -= 1                                          // 最重的必被安排
   3.3 boats += 1
4. 返回 boats
```

**注意循环条件是 `lo <= hi`**：`lo == hi` 时还剩最后一人，必须再开一条船；写成 `lo < hi` 会让 `people = [1]` 返回 $0$。

### 3.4 示例演算

![示例 2 的三轮安排：3 独坐、1 与 2 同船、2 独坐](images/wc96_q2_walkthrough.svg)

对示例 2（`people = [3,2,2,1]`，`limit = 3`，排序后 `[1,2,2,3]`）：

| 轮次 | `lo`（体重） | `hi`（体重） | $p_{lo}+p_{hi}$ | 判定 | 动作 | `boats` |
|------|------------|------------|----------------|------|------|---------|
| 1 | 0（1） | 3（3） | 4 | $> 3$ | 3 独走，`hi--` | 1 |
| 2 | 0（1） | 2（2） | 3 | $\le 3$ | 1、2 同船，`lo++`、`hi--` | 2 |
| 3 | 1（2） | 1（2） | — | `lo == hi`，剩一人 | 2 独走 | 3 |

返回 $3$，与示例一致。示例 3（`[3,3,4,5]`、`limit = 5`）每轮 $p_{lo}+p_{hi} \ge 3+5 = 8 > 5$，始终走独走分支，返回 $4$。示例 1（`[1,2]`、`limit = 3`）一轮即同行，返回 $1$。

## 4. 算法细节

1. **必须先排序**：贪心依赖「最轻」「最重」两端；排序 $O(n \log n)$ 是整体瓶颈。
2. **`while (lo <= hi)`**：等号不能省，否则单人会漏算。每轮 `hi` 必减 $1$，循环最多 $n$ 轮，必然终止。
3. **`lo` 只在同船时前进**：不同船时 `lo` 不动——最轻的人还在等更轻的搭档（此时 `hi` 在左移，下一位更轻，仍有配对机会）。
4. **不需要记录分配方案**：题目只要船数；若要输出方案，在同船时记录 `(people[lo], people[hi])` 即可。
5. **答案上界是 $n$**：最坏人手一船，$n \le 5\times10^4$，`int` 足够。
6. **重复体重无碍**：排序后相同体重相邻，贪心不需要区分具体是哪个人。

## 5. 正确性证明

设排序后数组为 $p_0 \le p_1 \le \cdots \le p_{n-1}$。用「方案」表示把人群划分成若干组（每组 1 或 2 人，2 人组满足体重和 $\le limit$），船数即组数。

**引理 1（独坐判定）**：在当前剩余集合 $p_{lo},\ldots,p_{hi}$ 中，若 $p_{lo} + p_{hi} > limit$，则 $p_{hi}$ 无法与任何剩余者同船。

**证明**：对任意剩余 $p_j$（$lo \le j \le hi$）有 $p_j \ge p_{lo}$，故 $p_j + p_{hi} \ge p_{lo} + p_{hi} > limit$，即 $p_{hi}$ 与任何人都超载。∎

**引理 2（配最轻不劣）**：若 $p_{lo} + p_{hi} \le limit$，则存在最优方案使 $p_{lo}$ 与 $p_{hi}$ 同船。

**证明**：取任一最优方案 $O$，设 $p_{hi}$ 所在组为 $B_{hi}$、$p_{lo}$ 所在组为 $B_{lo}$。

- 若 $B_{hi} = B_{lo}$，结论直接成立。
- 否则 $B_{hi} = \{p_{hi}, p_j\}$ 或 $\{p_{hi}\}$，$B_{lo} = \{p_{lo}, p_k\}$ 或 $\{p_{lo}\}$。构造 $O'$：删去这两组，加入 $\{p_{lo}, p_{hi}\}$；若 $p_j, p_k$ 都存在则再加入 $\{p_j, p_k\}$，否则让落单者单独成组。
  - $\{p_{lo}, p_{hi}\}$ 合法：由前提 $p_{lo}+p_{hi}\le limit$。
  - $\{p_j,p_k\}$ 合法：$B_{hi}$ 合法给出 $p_j + p_{hi} \le limit$（$p_j$ 存在时），而 $p_k \le p_{hi}$（$p_{hi}$ 是最大者），故 $p_j + p_k \le p_j + p_{hi} \le limit$。
  - 组数：原来两组，现在至多两组；若原有一组是单人，新方案只会更少。故 $O'$ 的船数不超过 $O$，仍最优，且 $p_{lo}$、$p_{hi}$ 同船。∎

**定理**：贪心返回的船数是最少的。

**证明**：对剩余人数归纳。剩余为空时无需船，成立。设当前剩余 $p_{lo},\ldots,p_{hi}$：

- 若 $p_{lo} + p_{hi} > limit$：由引理 1，任何方案都必须让 $p_{hi}$ 独坐一船；贪心正是如此（`hi--`、船数 $+1$），删去该人后在剩余集合上归纳，贪心最优。
- 若 $p_{lo} + p_{hi} \le limit$：由引理 2，存在最优方案让两人同船；贪心正是如此（`lo++`、`hi--`、船数 $+1$），删去两人后在剩余集合上归纳，贪心最优。

两种情形下贪心本轮的安排都被某个最优方案包含，且剩余子问题同构，故贪心总体最优。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；双指针最多 $n$ 轮、每轮 $O(1)$。
- **空间**：$O(1)$ 额外空间（不计排序内部 $O(\log n)$ 的栈）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numRescueBoats(vector<int>& people, int limit) {
        sort(people.begin(), people.end());
        int lo = 0, hi = people.size() - 1, boats = 0;
        while (lo <= hi) {
            if (people[lo] + people[hi] <= limit) lo++;  // 最轻的能塞进去就拼船
            hi--;                                        // 最重的必定占一条船
            boats++;
        }
        return boats;
    }
};
```

### Python

```python
class Solution:
    def numRescueBoats(self, people: list[int], limit: int) -> int:
        people.sort()
        lo, hi = 0, len(people) - 1
        boats = 0
        while lo <= hi:
            if people[lo] + people[hi] <= limit:
                lo += 1          # 最轻的与最重的同船
            hi -= 1              # 最重的必被安排
            boats += 1
        return boats
```

## 8. 边界情况与易错点

1. **`while (lo < hi)` 漏掉最后一人**：`people = [1]` 会返回 $0$，必须用 `lo <= hi`。
2. **忘记排序**：不排序时「最轻/最重」无从谈起，贪心直接失效。
3. **不同船时也 `lo++`**：会把最轻的人白白消耗掉，答案偏大。
4. **误以为每船可载多人**：本题限定两人；若按「只看总重」的装箱思路写，会得到偏小的错误答案。
5. **`people[i] > limit`**：题目保证不会出现；若出现则无解，需要返回 $-1$。
6. **大体重扎堆**：`[4,4,4,4]`、`limit = 5` 每轮都走独坐分支，返回 $4$，正确。
