# LeetCode 找到所有好下标 题解

## 1. 题目概述

- **标题 / 题号**：找到所有好下标（#2420，medium）
- **链接**：https://leetcode.cn/problems/find-all-good-indices/
- **来源**：LeetCode 第 312 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、前缀和（预处理）

**题意**：给你大小为 $n$、下标从 $0$ 开始的整数数组 `nums` 和正整数 $k$。对于 $k \le i < n - k$ 的下标 $i$，若同时满足：

- 下标 $i$ **之前** 的 $k$ 个元素是**非递增的**（$\text{nums}[i-k] \ge \text{nums}[i-k+1] \ge \cdots \ge \text{nums}[i-1]$）；
- 下标 $i$ **之后** 的 $k$ 个元素是**非递减的**（$\text{nums}[i+1] \le \text{nums}[i+2] \le \cdots \le \text{nums}[i+k]$）；

则称 $i$ 为**好下标**。按**升序**返回所有好下标。

**约束**：

- $n = \text{nums.length}$，$3 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^6$
- $1 \le k \le n / 2$

> ⚠️ 「非递增」「非递减」都**含等号**（允许相邻相等，如 $[1,1]$ 既是非递增也是非递减）。这与 845 山脉、2100 适合打劫银行的日子里的「严格」单调（不含等号）口径不同，转移必须用 $\le$ 而非 $<$。

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,1,1,3,4,1], k = 2
输出：[2,3]
解释：
- 下标 2：前 2 格 [2,1] 非递增，后 2 格 [1,3] 非递减 → 好。
- 下标 3：前 2 格 [1,1] 非递增（含等号），后 2 格 [3,4] 非递减 → 好。
- 下标 4 不是好下标：前 2 格 [1,1] 非递增成立，
  但后 2 格 [4,1] 满足 4 ≤ 1 不成立，不是非递减。
```

**示例 2**

```text
输入：nums = [2,1,1,2], k = 2
输出：[]
解释：候选区间 i ∈ [2, n−k) = [2, 2) 为空，不存在好下标。
```

**示例 3**（k = 1 退化为全候选）

```text
输入：nums = [9,8,7,6,7,8], k = 1
输出：[1,2,3,4]
解释：k = 1 时前、后各 1 个格子的段是单元素段，
自动非递增且非递减，故所有候选 i ∈ [1, 5) 都是好下标。
```

**示例 4**（全等数组，等号双侧成立）

```text
输入：nums = [1,1,1,1,1], k = 2
输出：[2]
解释：唯一候选 i = 2：前 2 格 [1,1]、后 2 格 [1,1]
均为「相等段」，同时非递增、非递减。
```

## 3. 解题思路

### 3.1 暴力思路

对每个候选 $i \in [k,\, n-k)$，向左扫 $k$ 格判非递增、向右扫 $k$ 格判非递减：

```text
for i in range(k, n - k):
    left_ok  = all(nums[j-1] >= nums[j] for j in range(i-k+1, i+1))
    right_ok = all(nums[j] <= nums[j+1] for j in range(i+1, i+k))
    if left_ok and right_ok: ans.append(i)
```

每个候选 $O(k)$，共 $O(n)$ 个候选，总计 $O(n \cdot k)$。由 $k \le n/2$，最坏 $k = n/2$ 时约 $n^2/2$；$n = 10^5$ 即 $5 \times 10^9$ 次比较，必然 TLE。

> ⚠️ 瓶颈在于**重复扫描**：相邻候选 $i$ 与 $i+1$ 的「前 $k$ 格」重叠 $k-1$ 个元素、$k-2$ 对相邻关系，却在判定 $i+1$ 时从零重扫；「后 $k$ 格」同理。$O(nk)$ 里几乎全是重复功。

> 💡 赛场信号：$n \le 10^5$ 排除逐候选扫描；「每个位置左右各判一段单调性」+「相邻候选窗口大幅重叠」的组合，几乎总指向**双趟前后缀预处理 DP**——把每对相邻关系只算一次、缓存成段长，查询时 $O(1)$ 查表。同款骨架见 845 最长山脉（严格版）、2100 适合打劫银行的日子（严格版）。

### 3.2 核心观察：两个段长数组，把窗口判定压成查表

![核心观察：好下标判定等价为 inc[i−1]≥k 且 dec[i+1]≥k 的双段长查表](images/2420_prefix_suffix_dp_concept.svg)

定义两个一维数组：

- $\text{inc}[i]$：**以 $i$ 结尾**的连续**非递增**段长度（元素个数），正向一趟递推：

  $$
  \text{inc}[i] =
  \begin{cases}
  \text{inc}[i-1] + 1, & \text{nums}[i] \le \text{nums}[i-1] \\
  1, & \text{否则（含 } i = 0 \text{ 基准）}
  \end{cases}
  $$

- $\text{dec}[i]$：**以 $i$ 开头**的连续**非递减**段长度，反向一趟递推：

  $$
  \text{dec}[i] =
  \begin{cases}
  \text{dec}[i+1] + 1, & \text{nums}[i] \le \text{nums}[i+1] \\
  1, & \text{否则（含 } i = n-1 \text{ 基准）}
  \end{cases}
  $$

**为什么这两个量就够用？** 「前 $k$ 格非递增」说的是一段以 $i-1$ **结尾**、长为 $k$ 的非递增段，等价于「以 $i-1$ 结尾的最长非递增段长度 $\ge k$」，即 $\text{inc}[i-1] \ge k$；「后 $k$ 格非递减」说的是一段以 $i+1$ **开头**、长为 $k$ 的非递减段，等价于 $\text{dec}[i+1] \ge k$。于是

$$
i \text{ 是好下标} \iff \text{inc}[i-1] \ge k \;\;\text{且}\;\; \text{dec}[i+1] \ge k .
$$

> 💡 **结构对称性**：`inc` 向左看（依赖 $i-1$，正向扫），`dec` 向右看（依赖 $i+1$，反向扫），方向相反、形态镜像。这与 [845. 数组中的最长山脉](https://leetcode.cn/problems/longest-mountain-in-array/) 的 `up`/`down`、[238. 除自身以外数组的乘积](https://leetcode.cn/problems/product-of-array-except-self/) 的前缀积/后缀积是同一族「两趟预处理 + 逐点合并」范式。

### 3.3 算法流程

![算法流程：正向算 inc、反向算 dec、扫描 [k,n−k) 查表收集](images/2420_two_pass_dp_flow.svg)

三趟线性扫描：

1. **正向**：算 $\text{inc}[]$，$i$ 从 $1$ 到 $n-1$，比较 $\text{nums}[i]$ 与 $\text{nums}[i-1]$；
2. **反向**：算 $\text{dec}[]$，$i$ 从 $n-2$ 到 $0$，比较 $\text{nums}[i]$ 与 $\text{nums}[i+1]$；
3. **扫描**：$i$ 从 $k$ 到 $n-k-1$（半开区间 $[k,\, n-k)$），若 $\text{inc}[i-1] \ge k$ 且 $\text{dec}[i+1] \ge k$，把 $i$ 加入答案。

> ⚠️ **候选区间边界**：左端 $i \ge k$ 保证 $i - k \ge 0$（前 $k$ 格存在），右端 $i \le n-k-1$ 保证 $i + k \le n-1$（后 $k$ 格存在）。当 $n < 2k + 1$（如示例 2，$n = 4, k = 2$）时区间为空，`range(k, n-k)` 自然产出 `[]`，无需特判。区间还保证查表下标 $i-1 \ge 0$、$i+1 \le n-1$，不会越界。

### 3.4 示例演算

![示例演算：nums、inc、dec 三行与逐候选判定得 [2,3]](images/2420_example_walkthrough.svg)

以示例 1 `nums = [2,1,1,1,3,4,1]`，$k = 2$，$n = 7$。

**第一趟（正向算 inc，比较 nums[i] ≤ nums[i−1]）**：

| $i$ | nums[i] | 与前比较 | $\text{inc}[i]$ |
|-----|---------|----------|------------------|
| 0 | 2 | —（基准） | 1 |
| 1 | 1 | $1 \le 2$ ✓ | $\text{inc}[0]+1 = 2$ |
| 2 | 1 | $1 \le 1$ ✓ | $\text{inc}[1]+1 = 3$ |
| 3 | 1 | $1 \le 1$ ✓ | $\text{inc}[2]+1 = 4$ |
| 4 | 3 | $3 \le 1$ ✗ | 1 |
| 5 | 4 | $4 \le 3$ ✗ | 1 |
| 6 | 1 | $1 \le 4$ ✓ | $\text{inc}[5]+1 = 2$ |

$\text{inc} = [1,2,3,4,1,1,2]$。

**第二趟（反向算 dec，比较 nums[i] ≤ nums[i+1]）**：

| $i$ | nums[i] | 与后比较 | $\text{dec}[i]$ |
|-----|---------|----------|------------------|
| 6 | 1 | —（基准） | 1 |
| 5 | 4 | $4 \le 1$ ✗ | 1 |
| 4 | 3 | $3 \le 4$ ✓ | $\text{dec}[5]+1 = 2$ |
| 3 | 1 | $1 \le 3$ ✓ | $\text{dec}[4]+1 = 3$ |
| 2 | 1 | $1 \le 1$ ✓ | $\text{dec}[3]+1 = 4$ |
| 1 | 1 | $1 \le 1$ ✓ | $\text{dec}[2]+1 = 5$ |
| 0 | 2 | $2 \le 1$ ✗ | 1 |

$\text{dec} = [1,5,4,3,2,1,1]$。

**第三趟（扫描 $i \in [2, 5)$）**：

| $i$ | $\text{inc}[i-1]$ | $\text{dec}[i+1]$ | 判定 | 结果 |
|-----|--------------------|--------------------|------|------|
| 2 | $\text{inc}[1]=2 \ge 2$ ✓ | $\text{dec}[3]=3 \ge 2$ ✓ | 好 | 加入 2 |
| 3 | $\text{inc}[2]=3 \ge 2$ ✓ | $\text{dec}[4]=2 \ge 2$ ✓ | 好 | 加入 3 |
| 4 | $\text{inc}[3]=4 \ge 2$ ✓ | $\text{dec}[5]=1 < 2$ ✗ | 否 | 跳过 |

最终 `ans = [2, 3]` ✓。下标 4 的前 $k$ 格 `[1,1]` 完全合规（$\text{inc}[3] = 4$ 远超 $k$），却因后 $k$ 格 `[4,1]` 中 $4 \le 1$ 不成立而出局——对应的正是 $\text{dec}[5] = 1$，**一侧失守即全局淘汰**。

> 💡 扫描 $i$ 从小到大，答案天然升序，无需排序。

## 4. 算法细节

1. **两个 DP 的方向选择**：`inc[i]` 取「以 $i$ 结尾」是为了依赖左邻 $i-1$、正向递推；`dec[i]` 取「以 $i$ 开头」是为了依赖右邻 $i+1$、反向递推。若把 `dec` 也设计成「以 $i$ 结尾的非递减段长」，则须正向扫且判据改为查 $\text{dec}[i+k]$，语义绕一层——「开头版」与「后 $k$ 格」直接对应，可读性最好。
2. **转移的等号**：两处比较都是 $\text{nums}[i] \le \text{nums}[\text{邻居}]$——向左看 $\le$ 表非递增（$\text{nums}[i-1] \ge \text{nums}[i]$ 的镜像写法），向右看 $\le$ 表非递减。两趟只差「邻居是 $i-1$ 还是 $i+1$」与「扫的方向」，一个常量写反就全盘皆错。
3. **初始化**：两数组初始化全 `1`（单元素自成一段），边界 $i=0$ / $i=n-1$ 不进循环也持有正确值 1，省去显式基准分支。
4. **判定的短路顺序**：先查 $\text{inc}[i-1]$ 再查 $\text{dec}[i+1]$（`&&` 短路），统计意义上无差别，纯粹让「常见失败原因」尽早暴露。
5. **空间账**：两个 `int` 数组在 $n = 10^5$ 时约 $0.8\,\text{MB}$，远低于限制；滚动变量可省成 $O(1)$ 但需小心「先用旧值判定再更新」的错位（见 §8 第 7 条），**可读性优先，保留双数组**。

## 5. 正确性证明

**引理 1**（inc 的刻画）：对一切 $0 \le i < n$，$\text{inc}[i]$ 等于「以下标 $i$ 结尾的最长非递增连续段的元素个数」。

**证明**：对 $i$ 归纳。$i = 0$ 时仅存在段 $[0,0]$，长 $1$，$\text{inc}[0] = 1$ 成立。设对 $i-1$ 成立。若 $\text{nums}[i] \le \text{nums}[i-1]$：任何以 $i$ 结尾的非递增段若长度 $\ge 2$，必含 $i-1$，去掉 $\text{nums}[i]$ 后是以 $i-1$ 结尾的非递增段，由归纳假设其长 $\le \text{inc}[i-1]$，故以 $i$ 结尾的段长 $\le \text{inc}[i-1] + 1$；反之，取以 $i-1$ 结尾的最长非递增段（长 $\text{inc}[i-1]$）并接上 $\text{nums}[i]$，因 $\text{nums}[i] \le \text{nums}[i-1]$ 整段仍非递增，长恰 $\text{inc}[i-1] + 1$。两侧夹逼得 $\text{inc}[i] = \text{inc}[i-1] + 1$，与递推式一致。若 $\text{nums}[i] > \text{nums}[i-1]$：任何长 $\ge 2$ 的以 $i$ 结尾的非递增段必含相邻对 $(i-1, i)$，与 $\text{nums}[i-1] < \text{nums}[i]$ 矛盾，故最长段即 $[i, i]$ 自身，$\text{inc}[i] = 1$，与递推式一致。∎

**引理 2**（dec 的刻画）：对一切 $0 \le i < n$，$\text{dec}[i]$ 等于「以下标 $i$ 开头的最长非递减连续段的元素个数」。

**证明**：与引理 1 关于下标镜像对称（$i$ 从 $n-1$ 向 $0$ 归纳，比较对象换成 $\text{nums}[i+1]$），逐字对应成立。∎

**引理 3**（窗口判定等价）：对 $k \le i < n - k$：子数组 $\text{nums}[i-k..i-1]$ 非递增 $\iff \text{inc}[i-1] \ge k$；子数组 $\text{nums}[i+1..i+k]$ 非递减 $\iff \text{dec}[i+1] \ge k$。

**证明**：（⇒）若 $\text{nums}[i-k..i-1]$ 非递增，则它是以 $i-1$ 结尾、长为 $k$ 的非递增段，由引理 1「最长」性得 $\text{inc}[i-1] \ge k$。（⇐）若 $\text{inc}[i-1] \ge k$，取以 $i-1$ 结尾的最长非递增段 $[j,\, i-1]$（长 $\text{inc}[i-1] \ge k$），其最后 $k$ 个元素恰为下标 $i-k, \dots, i-1$，即 $\text{nums}[i-k..i-1]$ 是一个非递增段的子段，故非递增。$\text{dec}$ 一侧由引理 2 同理。∎

**定理**：算法返回的恰为全部好下标按升序组成的列表。

**证明**：对 $i \in [k,\, n-k)$，由好下标定义与引理 3：$i$ 是好下标 $\iff \text{inc}[i-1] \ge k$ 且 $\text{dec}[i+1] \ge k$；对区间外的 $i$，其前 $k$ 格或后 $k$ 格不完整，按定义不参与判定，而算法的扫描范围恰为 $[k, n-k)$，不重不漏。由引理 1、2，两趟递推算出的 `inc`、`dec` 与其定义值逐点相等，故每个候选的判定结果与定义一致。又扫描按 $i$ 递增进行，收集顺序即升序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。正向算 `inc` 一趟 $n-1$ 次比较、反向算 `dec` 一趟 $n-1$ 次比较、扫描候选至多 $n-2k$ 次查表，总计约 $3n$ 个 $O(1)$ 步骤；对照暴力 $O(n \cdot k)$（最坏 $\approx n^2/2 = 5 \times 10^9$）快了约 $k$ 倍。
- **空间复杂度**：$O(n)$。两个长度 $n$ 的 DP 数组（$n = 10^5$ 时约 $0.8\,\text{MB}$）；答案数组最坏 $O(n)$（如 $k = 1$ 时几乎所有候选入选）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> goodIndices(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> inc(n, 1);                    // 以 i 结尾的非递增段长
        for (int i = 1; i < n; ++i)
            if (nums[i] <= nums[i - 1]) inc[i] = inc[i - 1] + 1;

        vector<int> dec(n, 1);                    // 以 i 开头的非递减段长
        for (int i = n - 2; i >= 0; --i)
            if (nums[i] <= nums[i + 1]) dec[i] = dec[i + 1] + 1;

        vector<int> ans;
        for (int i = k; i < n - k; ++i)           // 候选区间 [k, n-k)
            if (inc[i - 1] >= k && dec[i + 1] >= k) ans.push_back(i);
        return ans;
    }
};
```

> 💡 两个 DP 数组初始化全 `1`（单个元素自成一段），转移只在该方向比较一次相邻元素；两处比较统一写 `nums[i] <= nums[邻居]`，差别仅在邻居取 $i-1$（向左，非递增）还是 $i+1$（向右，非递减）。

### Python

```python
class Solution:
    def goodIndices(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        inc = [1] * n                     # 以 i 结尾的非递增段长
        for i in range(1, n):
            if nums[i] <= nums[i - 1]:
                inc[i] = inc[i - 1] + 1

        dec = [1] * n                     # 以 i 开头的非递减段长
        for i in range(n - 2, -1, -1):
            if nums[i] <= nums[i + 1]:
                dec[i] = dec[i + 1] + 1

        return [i for i in range(k, n - k)
                if inc[i - 1] >= k and dec[i + 1] >= k]
```

> 💡 列表推导式直接产出答案；`range(k, n - k)` 在 $n < 2k + 1$ 时为空，`[]` 免特判。

## 8. 边界情况与易错点

1. **等号必须保留**：「非递增 / 非递减」都含等号，两趟比较都用 `<=`。误写成严格 `<` 会把 `[1,1]` 这类相等段判死，示例 1 的下标 3（前 $k$ 格 `[1,1]`）直接漏掉——对照 2100 打劫银行（严格版）与 845 山脉（严格版），三题仅一字之差，口径看错整题报废。
2. **候选区间是 $[k,\, n-k)$（左闭右开）**：写成 `[k, n-k-1]` 闭区间会漏 $i = n-k-1$，写成 `[k, n-k]` 会查 $\text{dec}[n-k+1]$ 越界或误收 $i = n-k$。
3. **$n = 2k$ 时区间恰为空**（示例 2）：`range(k, n-k)` 自然为空，别为「至少一个好下标」写特判硬造答案。
4. **$k = 1$ 时答案恒为 $[1, 2, \dots, n-2]$**：单元素段自动非递增且非递减，所有候选全好（示例 3）——可作对拍用例检验区间端点是否写对。
5. **数组命名别拧巴**：`inc`/`dec` 若定义为「非递减/非递增」的反向组合很容易自己绕进去；建议按本文口径——`inc[i]`（以 $i$ 结尾非递增）+ `dec[i]`（以 $i$ 开头非递减），查表恒为 `inc[i-1]`、`dec[i+1]`。
6. **全等数组**：所有段长都拉满，$\text{inc}[i-1] = i$、$\text{dec}[i+1] = n - 1 - i$，候选区间内全部入选（示例 4 只有一个候选 $i = k$ 当 $n = 2k+1$），流程天然覆盖。
7. **滚动变量版的空间优化陷阱**：若省掉 `inc` 数组用单变量滚动，须在推进 $i$ 时**先用旧值（以 $i-1$ 结尾的段长）判定、再更新为新值**，顺序颠倒会用错位段长。$n = 10^5$ 下双数组仅 $0.8\,\text{MB}$，不值得冒此险。
8. **别忘 `i` 自身不参与两侧判定**：题意只约束 $i$ **前**、**后**各 $k$ 格，$\text{nums}[i]$ 的值与好坏无关（示例 1 中 $i=3$ 的值 $1$ 夹在 $1$ 与 $3$ 之间毫无约束力），别在判定里把 $\text{nums}[i]$ 拉进来比较。
