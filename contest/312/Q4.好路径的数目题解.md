# LeetCode 好路径的数目 题解

## 1. 题目概述

- **标题 / 题号**：好路径的数目（#2421，hard）
- **链接**：https://leetcode.cn/problems/number-of-good-paths/
- **来源**：LeetCode 第 312 场周赛 Q4
- **难度**：困难
- **标签**：树、并查集、排序、图

**题意**：给定一棵 $n$ 个节点、$n-1$ 条无向边的树，节点 $i$ 的值为 $\text{vals}[i]$。一条**好路径**需满足：

- 开始节点与结束节点的值**相同**（设为 $v$）；
- 路径上其余节点的值都 $\le v$，即**端点值是整条路径上的最大值**。

单个节点自身也算一条好路径；一条路径与其反向视为同一条。求不同好路径的数目。

**约束**：

- $1 \le n \le 3 \times 10^4$
- $0 \le \text{vals}[i] \le 10^5$
- $\text{edges}$ 恰有 $n-1$ 条，构成一棵合法的树。

## 2. 示例

**示例 1**

```text
输入：vals = [1,3,2,1,3], edges = [[0,1],[0,2],[2,3],[2,4]]
输出：6
解释：5 条单节点好路径；另有 1 条好路径 1 → 0 → 2 → 4
（端点值均为 3，中间节点 0、2 的值 1、2 均 ≤ 3）。
注意 0 → 2 → 3 不是好路径：端点值同为 1，但中间 vals[2]=2 > 1。
```

```text
各自确定一条好路径（0→1、1→2、0→1→2），共 3 + 3 = 6。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法：好路径由**两个同值端点**决定，于是枚举所有同值无序点对 $(u, u')$，再验证树路径上是否全程 $\le \text{vals}[u]$。

- 朴素的点对枚举 + 每次走一遍路径：$O(n^3)$，不可行。
- 改进版：对每个值 $v$ 的节点组，从组内每个节点出发做**限制 BFS/DFS**——只经过值 $\le v$ 的节点，统计能到达的同值节点。最坏情形（例如值沿一条长链单调递增）下，每个组都要把「值 $\le v$ 的子图」整个重走一遍，总开销退化为 $O(n^2)$，$n = 3 \times 10^4$ 时约 $9 \times 10^8$ 步基本操作，C++ 勉强、Python 必然超时。

> 💡 赛场信号：树的连通性 + 「只经过不超过某个阈值的节点」+ 计数问题，是**按权值从小到大增量并入 + 并查集**的经典组合（Kruskal 系套路）。相邻两组之间的导出子图只差「一点点节点与边」，重复整图搜索就是在浪费——把增量维护交给并查集，每次合并摊销近乎 $O(1)$。

### 3.2 核心观察：按值从小到大「点亮」节点，并查集维护导出森林

![核心观察：好路径等价于同值端点在值不超过 v 的导出森林中连通](images/good_paths_union_concept.svg)

对每个阈值 $v$，定义**导出森林** $F_v$：只保留值 $\le v$ 的节点，以及两端值都 $\le v$ 的树边。

**关键等价**：设 $\text{vals}[u] = \text{vals}[u'] = v$，那么

$$
u,\ u' \text{ 之间存在好路径} \iff u,\ u' \text{ 在 } F_v \text{ 中连通}
$$

直观上：好路径全程值 $\le v$，整条路必然「躺在」$F_v$ 里；反过来，$F_v$ 里能连过去的两个点，其树上唯一路径也全程值 $\le v$，端点值 $v$ 恰是路径最大值。

于是流程呼之欲出：

1. 把节点按值**升序**排序，同值节点成组处理；
2. 处理到值 $v$ 的组时，把所有「两端值 $\le v$」的树边**恰好合并完**（新点亮的组内节点连向一切值 $\le v$ 的邻居）；
3. 此时并查集的连通块 = $F_v$ 的连通块，组内节点**同根的就配对**：一个根下有 $k$ 个值 $v$ 的节点，贡献 $\binom{k}{2}$ 条好路径；
4. 单节点路径在最开始用 $\text{ans} = n$ 一次性计入。

这本质上是 Kruskal 的「按边权（这里取两端点值的最大值）从小到大加点」，只是统计的对象从「最小生成树」换成了「同值点对计数」。

### 3.3 算法流程

![算法流程：排序分组后每组先合并后计数，累计组合数](images/good_paths_algorithm_flow.svg)

1. **初始化**：$\text{ans} = n$（单节点路径）；建立邻接表；节点下标按 $\text{vals}$ 升序排序；
2. **逐组处理**：取出值相同的连续段 $G = \{u_1, \dots, u_k\}$（组值为 $v$）；
3. **合并阶段**：对每个 $u \in G$，遍历其邻居 $w$，只要 $\text{vals}[w] \le v$ 就 $\text{union}(u, w)$（**等值邻居也在条件内**，同组点之间的边要在这阶段合并掉）；
4. **计数阶段**：对每个 $u \in G$ 求 $\text{find}(u)$，按根分桶；每个桶大小 $k$ 给 $\text{ans}$ 加上 $\binom{k}{2}$；
5. 重复直到所有组处理完，返回 $\text{ans}$。

### 3.4 示例演算

![示例1演算：按值1、2、3三步点亮并合并，最终ans等于6](images/good_paths_walkthrough.svg)

以示例 1（$\text{vals} = [1,3,2,1,3]$）走一遍，注意**每组先合并完、再计数**的顺序：

| 步骤 | 组 | 合并的边 | 组内分桶 | 本步贡献 | ans |
|------|----|----------|----------|----------|-----|
| 1 | 值 1：$\{0, 3\}$ | 无（邻居值都 $> 1$） | $\{0\}$、$\{3\}$ 各一桶 | 0 | 5 |
| 2 | 值 2：$\{2\}$ | $2\text{–}0$、$2\text{–}3$ → 连通块 $\{0,2,3\}$ | $\{2\}$ 一桶 | 0 | 5 |
| 3 | 值 3：$\{1, 4\}$ | $0\text{–}1$、$2\text{–}4$ → 全树连通 | $\{1,4\}$ 同根 $k=2$ | $\binom{2}{2}=1$ | 6 |

最终 $\text{ans} = 5 + 1 = 6$，与答案一致。图示见上演算图。

## 4. 算法细节

1. **排序分组**：对节点下标按 $\text{vals}$ 排序后用双指针切出同值连续段；一段一组，**绝不能**逐个节点边合并边计数（见 §8 第 2 条）。
2. **合并条件是 $\text{vals}[w] \le \text{vals}[u]$（带等号）**：处理组 $v$ 时，组内节点 $u$ 的邻居 $w$ 若值 $\le v$ 就合并。这样每条树边 $(a,b)$ 恰在 $\max(\text{vals}[a], \text{vals}[b])$ 对应的组里被合并一次——与 Kruskal 按「边权 = 两端值最大值」排序逐步加边完全等价。
3. **计数用临时哈希表**：组内每个节点查一次 $\text{find}$（此时合并已全部完成），按根聚合得桶大小 $k$，累加 $k(k-1)/2$。
4. **路径与反向路径同一**：正因为按**无序点对** $\binom{k}{2}$ 计数，天然不会把正反两条走法算成两条。
5. **实现细节**：并查集用路径压缩（可再加按大小合并）；无向图建邻接表；`find` 写成迭代避免深递归。

## 5. 正确性证明

**引理 1（点对刻画）**：好路径由其无序端点对唯一决定。因此好路径总数

$$
\text{ans} = n + \#\{(u, u') : u \ne u',\ \text{vals}[u] = \text{vals}[u'] = v,\ u, u' \text{ 间存在好路径}\}
$$

**证明**：树上任意两点间存在**唯一**简单路径，故给定端点对，路径本身唯一；反之一条（多节点）好路径给出无序端点对 $\{u, u'\}$（$u \ne u'$）。单节点路径对应平凡点对 $(u,u)$，共 $n$ 条。∎

**引理 2（导出森林等价）**：设 $\text{vals}[u] = \text{vals}[u'] = v$，则 $u, u'$ 之间存在好路径 $\iff$ $u, u'$ 在 $F_v$ 中连通。

**证明**：

（⇒）设好路径为 $u = x_0, x_1, \dots, x_m = u'$。路径上每个节点值 $\le v$（端点 $= v$，中间 $\le v$），且相邻 $x_i, x_{i+1}$ 之间是树边、两端值都 $\le v$，所以整条路径是 $F_v$ 中的一条链，$u, u'$ 在 $F_v$ 中连通。

（⇐）设 $u, u'$ 在 $F_v$ 中连通，取 $F_v$ 中连接二者的任意一条路。$F_v$ 是原树的子图，这条路也是原树中一条路，其中必含 $u$ 到 $u'$ 的**简单**路径 $P$；而树上 $u$ 到 $u'$ 的简单路径唯一，故 $P$ 就是那条唯一的树路径，且 $P$ 的节点全在 $F_v$ 中、值全 $\le v$。端点值为 $v$，是路径最大值，中间节点值 $\le v$，故 $P$ 是好路径。∎

**引理 3（并查集增量维护导出森林）**：在处理完值 $v$ 的组的**合并阶段**之后，并查集的连通块恰等于 $F_v$ 的连通块。

**证明**：对处理进度归纳。初始（未处理任何组）时并查集与 $F_{-\infty}$（空边集）同为全孤立点，成立。设处理完更小的值 $v^-$ 后成立。组 $v$ 的合并阶段执行 union 的边集合为

$$
\{(a, b) \in E : \max(\text{vals}[a], \text{vals}[b]) \le v \text{ 且 } \min(\text{vals}[a], \text{vals}[b]) \ge v^- \text{ 至少一端} = v\}
$$

即所有「一端值为 $v$、另一端值 $\le v$」的边（含两端同为 $v$ 的边，由组内节点遍历邻居时被合并）。另一方面

$$
E_v \setminus E_{v^-} = \{(a,b) \in E : \text{两端值} \le v \text{ 且} \max(\text{vals}[a], \text{vals}[b]) = v\}
$$

两者是同一个集合：一条边若两端值 $\le v$ 但最大端值 $< v$，则它已在处理值 $\max(\text{vals}[a],\text{vals}[b])$ 的组时被合并，属于 $E_{v^-}$（归纳假设）。又算法只 union 两端值都 $\le v$ 的边，不会引入 $E_v$ 之外的边。归纳完成。∎

**定理**：算法返回的恰是好路径总数。

**证明**：由引理 1，只需数对 $(u, u')$（$u \ne u'$，同值，有好路径）。设其值为 $v$。由引理 2，这样的点对 $\iff$ $u, u'$ 在 $F_v$ 中同一连通块；由引理 3，$\iff$ 在处理组 $v$ 的计数阶段时 $\text{find}(u) = \text{find}(u')$。算法把组 $v$ 的节点按根分桶，桶大小 $k$ 恰是该连通块内的同值点数，$\binom{k}{2}$ 恰是其中无序同值点对数。每个点对的值唯一，只会在它所属的组被统计一次，不重不漏；单节点路径由初值 $n$ 计入。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n + n\,\alpha(n))$，整体即 $O(n \log n)$。
  - 排序节点：$O(n \log n)$，是主导项；
  - 每条树边在「较大端点值」对应的组里恰好被 union 一次，共 $n-1$ 次；
  - 组内每个节点各做一次 $\text{find}$ 与一次邻居扫描，合并阶段全体邻居扫描总量为 $O(\sum \deg) = O(n)$，路径压缩下 find 摊销 $O(\alpha(n))$。
- **空间复杂度**：$O(n)$。
  - 邻接表、排序数组、并查集数组、临时计数哈希表均为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfGoodPaths(vector<int>& vals, vector<vector<int>>& edges) {
        int n = vals.size();
        vector<vector<int>> g(n);
        for (auto& e : edges) {
            g[e[0]].push_back(e[1]);
            g[e[1]].push_back(e[0]);
        }

        // 节点按值升序，同值相邻成组
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(),
             [&](int a, int b) { return vals[a] < vals[b]; });

        // 并查集（迭代 find + 路径压缩）
        vector<int> fa(n);
        iota(fa.begin(), fa.end(), 0);
        auto find = [&](int x) {
            while (fa[x] != x) {
                fa[x] = fa[fa[x]];
                x = fa[x];
            }
            return x;
        };

        long long ans = n;  // 单节点路径
        for (int i = 0, j; i < n; i = j) {
            for (j = i; j < n && vals[order[j]] == vals[order[i]]; ++j) {}

            // 合并阶段：组内每个节点连向一切值 <= v 的邻居
            for (int k = i; k < j; ++k) {
                int u = order[k];
                for (int w : g[u]) {
                    if (vals[w] <= vals[u]) {
                        int ru = find(u), rw = find(w);
                        if (ru != rw) fa[ru] = rw;
                    }
                }
            }

            // 计数阶段：组内按根分桶，桶大小 k 贡献 C(k,2)
            unordered_map<int, int> cnt;
            for (int k = i; k < j; ++k) ++cnt[find(order[k])];
            for (auto& [r, c] : cnt) ans += 1LL * c * (c - 1) / 2;
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfGoodPaths(self, vals: List[int], edges: List[List[int]]) -> int:
        n = len(vals)
        g = [[] for _ in range(n)]
        for a, b in edges:
            g[a].append(b)
            g[b].append(a)

        fa = list(range(n))

        def find(x: int) -> int:
            while fa[x] != x:
                fa[x] = fa[fa[x]]  # 路径压缩
                x = fa[x]
            return x

        order = sorted(range(n), key=lambda i: vals[i])

        ans = n  # 单节点路径
        i = 0
        while i < n:
            j = i
            while j < n and vals[order[j]] == vals[order[i]]:
                j += 1

            # 合并阶段：组内节点连向一切值 <= v 的邻居（含等值邻居）
            for k in range(i, j):
                u = order[k]
                for w in g[u]:
                    if vals[w] <= vals[u]:
                        ru, rw = find(u), find(w)
                        if ru != rw:
                            fa[ru] = rw

            # 计数阶段：按根分桶，桶大小 k 贡献 C(k,2)
            cnt = Counter(find(order[k]) for k in range(i, j))
            ans += sum(c * (c - 1) // 2 for c in cnt.values())
            i = j

        return ans
```

## 8. 边界情况与易错点

1. **初值 $\text{ans} = n$ 别忘**：单节点路径是合法好路径，全部同值时多节点部分约 $4.5 \times 10^8$，C++ 中累加用 `long long` 更稳。
2. **必须「整组合并完再计数」**：若逐个节点边合并边计数，同值邻居可能尚未并入同一连通块，导致漏数。例如示例 1 的组 $\{1,4\}$，若处理完节点 1 就立刻数桶，4 还未点亮，会漏掉那 1 条路径。
3. **合并条件带等号**：$\text{vals}[w] \le \text{vals}[u]$，同值邻居之间的边（两端都等于 $v$）也要合并，否则同组点经「等值桥」相连时会漏。
4. **计数时机在组内所有 union 之后**：桶的 key 必须是**合并完成后**查询的 $\text{find}$，提前查会拿到过期的根。
5. **$n = 1$、无边**：循环中不发生任何合并，直接返回初值 1，无需特判。
6. **值可为 0**：排序与比较不受影响，无需平移。
7. **重边/自环不存在**（题目保证是合法树），邻接表直接建即可。
8. **正反路径同一**：由无序点对 $\binom{k}{2}$ 计数天然保证，不要按有序对数成 $k(k-1)$。

**延伸思考**：

- 若要统计**所有好路径的长度和**或**最长好路径**，可以在 Kruskal 重构树上倍增 / DP，合并分量时把「同值点对的距离和」沿新边转移。
- 若图**不是树**（存在环），「点对之间存在全程 $\le v$ 的路」依然等价于「$F_v$ 中连通」，本算法与计数公式**原封不动照用**——树上路径唯一性只影响证明中「点对 ↔ 路径一一对应」这一步，计数对象本来就是不重不漏的无序点对。
- 若要求端点值**严格大于**所有中间节点（中间 $< v$ 而非 $\le v$），导出森林改为「值 $< v$ 的节点」，同值点之间的直达边需单独特判，等值链上的点对要精细拆分，难度再上一档。
