# LeetCode 按身高排序 题解

## 1. 题目概述

- **标题 / 题号**：按身高排序（#2418，easy）
- **链接**：https://leetcode.cn/problems/sort-the-people/
- **来源**：LeetCode 第 312 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串、排序

**题意**：给定长度均为 $n$ 的字符串数组 `names` 与**互不相同**的正整数数组 `heights`，其中 `names[i]`、`heights[i]` 表示第 $i$ 个人的名字和身高。请按身高**降序**顺序返回对应的名字数组。

**约束**：

- $n = \text{names.length} = \text{heights.length}$，$1 \le n \le 10^3$
- $1 \le \text{names}[i]\text{.length} \le 20$，`names[i]` 由大小写英文字母组成（**名字可以重复**）
- $1 \le \text{heights}[i] \le 10^5$，且**互不相同**

## 2. 示例

**示例 1**

```text
输入：names = ["Mary","John","Emma"], heights = [180,165,170]
输出：["Mary","Emma","John"]
解释：Mary(180) 最高，接着是 Emma(170) 和 John(165)。
```

**示例 2**

```text
输入：names = ["Alice","Bob","Bob"], heights = [155,185,150]
输出：["Bob","Alice","Bob"]
解释：第一个 Bob(185) 最高，然后是 Alice(155) 和第二个 Bob(150)。
```

**示例 3**（单元素）

```text
输入：names = ["Solo"], heights = [168]
输出：["Solo"]
```

## 3. 解题思路

### 3.1 暴力思路

输出有 $n$ 个位置，第 $k$ 个位置要填「尚未输出的人中身高最高者」的名字。最直接的实现是维护 `used` 标记，每轮完整扫一遍 `heights` 选出剩余最大——选择排序式 $O(n^2)$，$n \le 10^3$ 时约 $10^6$ 次比较可过，但每轮重扫把「同一个人的身高被反复比较」的浪费背在身上；且 `used` 数组、选人逻辑都是签到题里多余的出错点。

> 💡 关键观察：整个输出顺序由**一次排序**完全确定——不必逐位挑最大，先排好序再按序取名即可。

### 3.2 核心观察：平行数组，一次排序定全局

![核心观察：名字与身高按下标绑定，按身高降序一次排序即可得到答案](images/2418_bind_sort_concept.svg)

1. **平行数组**：`names[i]` 与 `heights[i]` 通过下标绑定，题目要重排的是**输出顺序**，绑定关系本身不动；
2. **heights 互不相同**：任意两人身高可比较且**无并列** ⟹ 降序序列唯一确定，不需要稳定排序、不需要副键打破并列。

于是问题化为标准的「**按键重排另一数组**」：以身高为键做一次降序排序，名字跟着走。落地方式三选一：

- **捆绑排序**：把 `(height, name)` 捆成对按身高降序排，再拆出名字；
- **哈希表**：建立 `height → name` 的映射（方向不能反，见 §8），排好 `heights` 后查表取名；
- **索引数组（argsort，推荐）**：只排下标 `idx`，排序中换位的只有整数，字符串全程只读。

### 3.3 算法流程

![算法流程：构造 idx → 以 heights[idx] 为键降序排序 → 收集 names → 返回](images/2418_algorithm_flow.svg)

以索引数组为例，流程线性无分支：

1. **构造**：`idx = [0, 1, …, n−1]`；
2. **排序**：以 $\text{heights}[\text{idx}[i]]$ 为键对 `idx` 降序排序；
3. **收集**：`ans[i] = names[idx[i]]`；
4. **返回** `ans`。

### 3.4 示例演算

![示例演算：Mary/John/Emma 经一次排序得到 Mary/Emma/John](images/2418_example_walkthrough.svg)

以示例 1 `names = ["Mary","John","Emma"]`、`heights = [180,165,170]` 演算：

| 步骤 | 内容 |
|------|------|
| ① 构造 | `idx = [0, 1, 2]`，对应身高 `[180, 165, 170]` |
| ② 排序 | 比较身高 $180 > 170 > 165$，降序排得 `idx = [0, 2, 1]` |
| ③ 收集 | `ans = [names[0], names[2], names[1]] = ["Mary","Emma","John"]` |

结果 `["Mary","Emma","John"]` ✓。示例 2 中两个 Bob 同名但身高不同（185 与 150），靠身高被区分到不同位置——名字重复不干扰排序。

## 4. 算法细节

1. **三种落地方式对比**：

| 方案 | 排序中搬动对象 | names 是否参与换位 | 备注 |
|------|----------------|--------------------|------|
| 捆绑 `(h, name)` 对 | 字符串 + 整数组成的对 | 是 | 最直白，Python 一行 |
| 哈希 `height → name` | 仅 `heights` | 否（查表取名） | 依赖 heights 互不相同 |
| 索引数组 `idx` | 仅整数下标 | 否（最后读一次） | argsort 范式，语义最干净 |

2. **比较键**：被排序的是 `idx`，比较器收到的参数就是**下标本身**，故 C++ 直接写 `heights[a] > heights[b]`（降序），不要再套一层 `heights[idx[a]]` 造成二重间接。
3. **哈希方向**：必须 `height → name`。`heights` 互不相同保证键唯一；反向 `name → height` 在示例 2 会因两个 Bob 同名而**同名覆盖**，丢失一人。
4. **降序实现**：C++ 用比较器 `heights[a] > heights[b]`；Python 用 `reverse=True`（或 `key=lambda i: -heights[i]`）。
5. **值域福利**（本题不必，但值得记住）：$1 \le \text{heights}[i] \le 10^5$ 且互不相同 ⟹ 可用长度 $10^5$ 的布尔桶做**计数排序**：从大到小扫值域，遇到出现过的身高查表取名，$O(n + V)$——当 $n$ 很大而值域不大时，这是绕过 $O(n \log n)$ 的出路。

## 5. 正确性证明

**引理 1**（降序唯一）：`heights` 两两互异 ⟹ 其降序排列唯一，且严格递减。

**证明**：对任意 $i \ne j$，$h_i \ne h_j$，故 $h_i > h_j$ 与 $h_i < h_j$ 恰有一者成立，$n$ 个元素的全序关系由输入完全确定；降序序列是该全序的唯一线性化，无并列故严格递减。∎

**定理**：将 `idx` 以 $\text{heights}[\text{idx}[i]]$ 为键降序排序后按 `ans[i] = names[idx[i]]` 收集，输出恰为按身高降序的名字序列。

**证明**：由引理 1，排序后有 $\text{heights}[\text{idx}[0]] > \text{heights}[\text{idx}[1]] > \dots > \text{heights}[\text{idx}[n-1]]$，即 `idx[i]` 恰为身高第 $i+1$ 大者的原始下标。`ans[i] = names[idx[i]]` 取的正是该人的名字，与题意要求的降序输出**逐位一致**。又 `idx` 是 $\{0, 1, \dots, n-1\}$ 的排列，收集过程对每个人恰好访问一次，无遗漏、无重复。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导；构造 `idx` 与收集结果均为线性 $O(n)$。对照：暴力选择式扫描 $O(n^2)$；计数排序 $O(n + V)$（$V = 10^5$，本题 $n \le 10^3$ 用不上）。
- **空间复杂度**：$O(n)$，`idx` 数组与答案数组各占 $O(n)$；不计输出空间，排序本身仅需 $O(\log n)$ 递归栈。

> 💡 $n \le 10^3$ 时三种做法（甚至暴力）都能 AC。签到题拼的是**写得快、写得对**——索引数组版代码短、无并列坑，是首选。

## 7. 参考代码

### C++（索引数组）

```cpp
class Solution {
public:
    vector<string> sortPeople(vector<string>& names, vector<int>& heights) {
        int n = names.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return heights[a] > heights[b];
        });
        vector<string> ans(n);
        for (int i = 0; i < n; ++i) ans[i] = names[idx[i]];
        return ans;
    }
};
```

### C++（哈希表 height→name）

```cpp
class Solution {
public:
    vector<string> sortPeople(vector<string>& names, vector<int>& heights) {
        unordered_map<int, string> who;
        for (int i = 0; i < (int)names.size(); ++i) who[heights[i]] = names[i];
        sort(heights.begin(), heights.end(), greater<int>());
        vector<string> ans;
        ans.reserve(names.size());
        for (int h : heights) ans.push_back(who[h]);
        return ans;
    }
};
```

### Python（捆绑排序，一行）

```python
class Solution:
    def sortPeople(self, names: List[str], heights: List[int]) -> List[str]:
        return [name for _, name in sorted(zip(heights, names), reverse=True)]
```

### Python（索引数组）

```python
class Solution:
    def sortPeople(self, names: List[str], heights: List[int]) -> List[str]:
        idx = sorted(range(len(names)), key=lambda i: heights[i], reverse=True)
        return [names[i] for i in idx]
```

## 8. 边界情况与易错点

1. **$n = 1$**：排序平凡，直接返回原数组，流程天然覆盖，无需特判。
2. **名字可重复（示例 2）**：两个 Bob 同名不同身高。哈希方向必须 `height → name`（heights 互不相同 ⟹ 键唯一）；写成 `name → height` 会同名覆盖、第二人直接丢失，WA。
3. **互不相同 ⟹ 无并列**：不需要稳定排序。若题目放宽为身高可相同且并列按输入序输出，需改用 `stable_sort` 或添加副键 $(-h_i,\ i)$。
4. **降序别写反**：比较器是 `heights[a] > heights[b]`，Python 是 `reverse=True`——排成升序是本题最常见的 WA。
5. **zip 的顺序**：Python 捆绑时键在前：`zip(heights, names)` 排的是身高；误写 `zip(names, heights)` 就变成按名字字典序排序。
6. **C++ lambda 捕获**：`[&]` 捕获 `heights`，漏捕获会编译失败（好在编译期即暴露，不至于 WA）。
