# LeetCode 三等分 题解

## 1. 题目概述

- **标题 / 题号**：三等分（#927，hard）
- **链接**：https://leetcode.cn/problems/three-equal-parts/
- **来源**：LeetCode 第 107 场周赛 Q3
- **难度**：困难
- **标签**：数组、数学、模拟

**题意**：给定只含 0 和 1 的数组 `arr`，把它切成**三个非空连续段**，要求三段作为二进制数**数值相等**（允许前导零，例如 `[0,1,1]` 与 `[1,1]` 都表示 3）。若可行，返回任意一组分割下标 $[i, j]$（$i + 1 < j$），其中

- 第一段 $= \text{arr}[0..i]$；
- 第二段 $= \text{arr}[i+1..j-1]$；
- 第三段 $= \text{arr}[j..n-1]$。

若不可行，返回 $[-1, -1]$。

**约束**：

- $3 \le n \le 3 \times 10^4$
- `arr[i]` 为 0 或 1

> 💡 难点不在「比较三个数」，而在于 $n$ 可达 $3 \times 10^4$——把每段当成大整数去比会溢出，必须**利用二进制串的结构**做逐位比较。

## 2. 示例

**示例 1**

```text
输入：arr = [1,0,1,0,1]
输出：[0,3]
解释：三段为 [1]、[0,1]、[0,1]，后两段虽有前导零，但数值都是 1。
```

**示例 2**

```text
输入：arr = [1,1,0,1,1]
输出：[-1,-1]
解释：1 的总数为 4，无法均分成三份（每份需要相同个数的 1）。
```

**示例 3**

```text
输入：arr = [1,1,0,0,1]
输出：[0,2]
解释：切成 [1]、[1]、[0,0,1]，后两段数值都是 1（第三段带前导零）。
```

**示例 4（补充）**

```text
输入：arr = [0,0,0]
输出：[0,2]（或任意合法切法）
解释：三段的数值都是 0，全 0 数组总是可行。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $i < j$：把三段分别转成整数（或逐位比较），取第一组可行解。方案数 $O(n^2)$，每次比较 $O(n)$，总 $O(n^3)$；即使优化到 $O(n^2)$ 前缀哈希，$n = 3\times10^4$ 时 $9 \times 10^8$ 也不现实。

关键是要发现：**可行解的切割点是唯一的**（在「每段 1 的个数」意义下被完全确定），因此不需要枚举。

### 3.2 核心观察：1 的个数必须三等分，且每段起点被唯一确定

![三段二进制值相等 ⇔ 1 的个数均分 + 逐位一致](images/wc107_q3_ones_split_concept.svg)

记数组中 1 的总数为 $K$，第三段第一个 1 的下标为 $p_3$，第二段第一个 1 的下标为 $p_2$，第一段第一个 1 的下标为 $p_1$。

**第一层：1 的个数必须均分。** 三段数值相等 $\Rightarrow$ 三段的**有效位数相同** $\Rightarrow$ 三段中 1 的个数相同，均为 $K/3$。所以 $K \bmod 3 \ne 0$ 直接无解。

**第二层：第三段的长度被唯一确定。** 第三段必须延伸到数组末尾（这就是切割的定义），因此它的长度是
$$\text{len} = n - p_3$$
而「数值相等」要求三段**从各自的第一个 1 到最后一位**的比特串完全相同。于是第一段必须占据 $[p_1, p_1 + \text{len})$、第二段必须占据 $[p_2, p_2 + \text{len})$——没有任何自由度。

**第三层：只需要逐位比对。** 确定了 $p_1, p_2, p_3, \text{len}$ 之后，验证
$$\text{arr}[p_1 + k] = \text{arr}[p_2 + k] = \text{arr}[p_3 + k] \quad (0 \le k < \text{len})$$
即可。全相等则返回 $[p_1 + \text{len} - 1,\ p_2 + \text{len}]$。

> 💡 注意「前导零被允许」这个条件**不会增加自由度**：它只影响切割点左侧的零点归属，而第三段的右端必须顶到数组末尾，长度已经被钉死。

### 3.3 算法流程

![算法流程：数 1 → 定位 → 逐位比对](images/wc107_q3_algorithm_flow.svg)

```text
1. 统计 ones（1 的总个数）
2. 若 ones == 0：返回 [0, n-1]        # 三段数值都是 0
3. 若 ones % 3 != 0：返回 [-1,-1]
4. part = ones / 3
5. 一次扫描求出：
       first  = 第 1 个 1 的下标
       second = 第 (part+1) 个 1 的下标
       third  = 第 (2*part+1) 个 1 的下标
6. len = n - third
7. for k = 0 .. len-1:
       若 arr[first+k] != arr[third+k] 或 arr[second+k] != arr[third+k]：返回 [-1,-1]
8. 返回 [first + len - 1, second + len]
```

### 3.4 示例演算

![示例演算：三个示例的定位与比对](images/wc107_q3_walkthrough.svg)

**示例 1** `arr = [1,0,1,0,1]`：$K = 3$，$part = 1$，$p_1 = 0$、$p_2 = 2$、$p_3 = 4$，$\text{len} = 5 - 4 = 1$。
比对 $k = 0$：`arr[0] = arr[2] = arr[4] = 1` ✓，返回 $[0 + 1 - 1,\ 2 + 1] = [0, 3]$。
校验：三段为 `[1]`、`[0,1]`、`[0,1]`，数值都是 1。

**示例 2** `arr = [1,1,0,1,1]`：$K = 4$，$4 \bmod 3 \ne 0$，返回 $[-1,-1]$。

**示例 3** `arr = [1,1,0,0,1]`：$K = 3$，$part = 1$，$p_1 = 0$、$p_2 = 1$、$p_3 = 4$，$\text{len} = 1$。
比对 $k = 0$：`arr[0] = arr[1] = arr[4] = 1` ✓，返回 $[0 + 1 - 1,\ 1 + 1] = [0, 2]$。
校验：三段为 `[1]`、`[1]`、`[0,0,1]`，数值都是 1（第三段有前导零）。

**示例 4** `arr = [0,0,0]`：$K = 0$，走特判返回 $[0, 2]$，三段 `[0]`、`[0]`、`[0]` 数值都为 0。

## 4. 算法细节

1. **$K = 0$ 的特判**：此时 `arr` 全为 0，任意满足 $i + 1 < j$ 的切法都可行。返回 $[0, n-1]$ 需要 $n \ge 3$，题目保证 $n \ge 3$，故 $i = 0, j = n-1$ 满足 $0 + 1 < n - 1$。
2. **$p_2, p_3$ 的取法**：`second` 是第 $part + 1$ 个 1 的下标（即「第二段的第一个 1」），`third` 是第 $2 \cdot part + 1$ 个 1 的下标（第三段的第一个 1）。这样三段各自恰好含 $part$ 个 1。
3. **`len = n - third` 的含义**：第三段从 $p_3$ 到末尾的长度。前两段必须「按同样的比特串长度」截取，因此第一段是 $[p_1, p_1 + \text{len})$、第二段是 $[p_2, p_2 + \text{len})$。
4. **比对的下标不会越界**：因 $p_1 < p_2 < p_3$ 且每段至少含一个 1，故 $p_1 + \text{len} \le p_2$、$p_2 + \text{len} \le p_3$（见引理 3），所以 `arr[first+k]`、`arr[second+k]`、`arr[third+k]` 都在范围内。
5. **切割点与返回值的换算**：第一段是 $[0, i]$ 且必须覆盖到 $p_1 + \text{len} - 1$，故 $i = p_1 + \text{len} - 1$；第二段是 $[i+1, j-1]$，故 $j - 1 = p_2 + \text{len} - 1$，即 $j = p_2 + \text{len}$。
6. **比较用字符而非整数**：把三段转成 `int`/`long long` 会在 $n = 3\times 10^4$ 时溢出，必须逐位比较。

## 5. 正确性证明

**引理 1（无 1 的情形）**：若 $K = 0$，则 `arr` 全为 0，$[0, n-1]$ 是合法切法。

**证明**：切点 $i = 0$、$j = n-1$，三段分别为 `arr[0..0]`、`arr[1..n-2]`、`arr[n-1..n-1]`，均非空（$n \ge 3$ 保证中间段非空）。三段全为 0，二进制数值都是 0，相等；且 $i + 1 = 1 < n - 1 = j$。∎

**引理 2（1 的个数必须均分）**：若存在合法切法，则三段的 1 的个数相等，从而 $K \bmod 3 = 0$。

**证明**：设三段表示的二进制数都为 $V$。二进制表示去掉前导零后是唯一的，因此三段去掉前导零后的串完全相同，其中 1 的个数相同。设每段含 $m$ 个 1，则 $K = 3m$，$K \bmod 3 = 0$。∎

**引理 3（切割点被唯一确定）**：若存在合法切法且 $K > 0$，则$K = 3m$，并且切割点必为
$$i = p_1 + \text{len} - 1, \qquad j = p_2 + \text{len}$$
其中 $p_1, p_2, p_3$ 分别是第 $1$、$m+1$、$2m+1$ 个 1 的下标，$\text{len} = n - p_3$。

**证明**：由引理 2，每段恰含 $m$ 个 1。第一段从下标 0 开始，其第一个 1 必须是全数组第 1 个 1，否则第一段全为 0、数值为 0，而另外两段含有 1（$K > 0$ 且均分），数值非零，矛盾。故第一段覆盖到 $p_1$。同理第二段从第一段结束后的第一个 1 开始，即 $p_2$（第 $m+1$ 个 1）——因为前 $m$ 个 1 已全部落在第一段内（第一段恰含 $m$ 个 1），第二段的第一个 1 就是第 $m+1$ 个。第三段同理从 $p_3$（第 $2m+1$ 个 1）开始。

又第三段必须覆盖到数组末尾（题目要求第三段是 `arr[j..n-1]`），故第三段长度恰为 $n - p_3$；而三段「从第一个 1 到段末」的比特串长度必须相同（数值相等 + 无前导零 + 末位可能为 0，长度由最高位与末位共同决定），故每段都从各自的第一个 1 起恰好取 $\text{len} = n - p_3$ 个字符。于是 $i = p_1 + \text{len} - 1$、$j-1 = p_2 + \text{len} - 1$，即 $j = p_2 + \text{len}$。

最后验证不重叠：第一段 $[p_1, p_1 + \text{len})$ 含 $m$ 个 1，其最后一个 1 是第 $m$ 个 1（下标 $p_2$ 之前的某处），之后第一段还有 $\text{len}$ 中的剩余零位，故 $p_1 + \text{len} \le p_2$；同理 $p_2 + \text{len} \le p_3$。因此 $i + 1 = p_1 + \text{len} \le p_2 \le j - 1$，满足 $i + 1 < j$。∎

**引理 4（比对判定正确）**：在引理 3 的切割点下，三段数值相等 $\iff$ 对一切 $0 \le k < \text{len}$ 有 `arr[p_1+k] = arr[p_2+k] = arr[p_3+k]`。

**证明**：三段都从各自第一个 1 开始（首位都是 1，无前导零），长度都是 $\text{len}$，故三段去掉前导零后的二进制串就是 `arr[p_1..p_1+len)`、`arr[p_2..p_2+len)`、`arr[p_3..p_3+len)`。两个等长二进制串数值相等当且仅当逐位相同。∎

**定理**：算法正确返回一组合法切割点或 $[-1,-1]$。

**证明**：

*有解时*：由引理 3，任何合法解的切割点都等于算法算出的 $(i, j)$，即解唯一。若比对全部通过，则由引理 4 三段数值相等，且由引理 3 已证 $i + 1 < j$、各段非空、第三段顶到末尾，故返回值为合法解。

*无解时*：若 $K = 0$，由引理 1 必有解，与前提矛盾。若 $K \bmod 3 \ne 0$，由引理 2 无解，算法返回 $[-1,-1]$，正确。若 $K \bmod 3 = 0$ 但比对失败，则引理 3 确定的**唯一**候选切割点不满足「三段数值相等」（引理 4 的逆否），而其他任何切割点都更不可能，故确实无解，返回 $[-1,-1]$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。统计 1 的个数一遍扫描；定位 $p_1, p_2, p_3$ 一遍扫描；比对至多 $\text{len} \le n$ 次。总计 $O(n)$，$n = 3 \times 10^4$ 时完全无压力。
- **空间**：$O(1)$，只用几个下标变量（不构造三段数组，也不做大整数运算）。
- **对比**：暴力枚举 $O(n^2)$、逐段转整数 $O(n)$ 但会溢出；本解法同时解决了时间与溢出问题。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> threeEqualParts(vector<int>& arr) {
        int n = (int)arr.size();
        int ones = 0;
        for (int x : arr) ones += x;

        if (ones == 0) return {0, n - 1};            // 全 0：任意三分都相等
        if (ones % 3 != 0) return {-1, -1};           // 1 的个数无法均分

        int part = ones / 3;                          // 每部分应有的 1 的个数
        int first = -1, second = -1, third = -1, seen = 0;
        for (int i = 0; i < n; ++i) {
            if (arr[i] == 1) {
                ++seen;
                if (seen == 1) first = i;             // 第一部分的最高位
                if (seen == part + 1) second = i;     // 第二部分第一个 1
                if (seen == 2 * part + 1) third = i;  // 第三部分第一个 1
            }
        }
        // 第三部分一定延伸到数组末尾，长度 len 固定；前两部分必须逐位相同
        int len = n - third;
        for (int k = 0; k < len; ++k) {
            if (arr[first + k] != arr[third + k]) return {-1, -1};
            if (arr[second + k] != arr[third + k]) return {-1, -1};
        }
        return {first + len - 1, second + len};
    }
};
```

### Python

```python
class Solution:
    def threeEqualParts(self, arr: list[int]) -> list[int]:
        n = len(arr)
        ones = sum(arr)
        if ones == 0:
            return [0, n - 1]
        if ones % 3 != 0:
            return [-1, -1]

        part = ones // 3
        first = second = third = -1
        seen = 0
        for i, x in enumerate(arr):
            if x == 1:
                seen += 1
                if seen == 1:
                    first = i
                if seen == part + 1:
                    second = i
                if seen == 2 * part + 1:
                    third = i

        length = n - third
        for k in range(length):
            if arr[first + k] != arr[third + k]:
                return [-1, -1]
            if arr[second + k] != arr[third + k]:
                return [-1, -1]
        return [first + length - 1, second + length]
```

## 8. 边界情况与易错点

1. **全 0 的数组**：$K = 0$ 时不能返回 $[-1,-1]$，必须返回合法切法（如 $[0, n-1]$）。这是最容易漏的特判。
2. **$K \bmod 3 \ne 0$**：如示例 2，必须先判模，否则后面的坐标会算错。
3. **把三段转成整数**：$n = 3 \times 10^4$ 时数值远超 `long long`，会溢出。必须逐位比较。
4. **切割点算错一位**：$i$ 是「第一段最后一个下标」、$j$ 是「第三段第一个下标」，因此 $i = p_1 + \text{len} - 1$（不是 $p_1 + \text{len}$）、$j = p_2 + \text{len}$。差一位会得到「第二段起点错位」的答案。
5. **中间段非空**：返回值必须满足 $i + 1 < j$。由引理 3 的 $p_1 + \text{len} \le p_2 \le p_2 + \text{len} - 1$ 保证，但如果误写成 $j = p_2 + \text{len} - 1$，就可能让第二段为空。
6. **前导零**：`[1]`、`[0,1]`、`[0,0,1]` 三者数值相同，所以第三段的「长度」由它自己决定（顶到末尾），不能假设三段等长。
7. **最长用例**：$n = 3\times 10^4$ 且全 1 时，$K = 3\times10^4$ 能被 3 整除，$p_1 = 0$、$p_2 = 10^4$、$p_3 = 2\times10^4$，$\text{len} = 10^4$，逐位比对 $10^4$ 次后返回 $[9999, 20000]$；务必保证不越界。
