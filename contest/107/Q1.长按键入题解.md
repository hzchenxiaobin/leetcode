# LeetCode 长按键入 题解

## 1. 题目概述

- **标题 / 题号**：长按键入（#925，easy）
- **链接**：https://leetcode.cn/problems/long-pressed-name/
- **来源**：LeetCode 第 107 场周赛 Q1
- **难度**：简单
- **标签**：双指针、字符串

**题意**：朋友用键盘输入名字 `name`。打字时某些按键可能被**长按**，于是某个字符会被输入 1 次或多次（但不能一次都不输入）。给定实际输入的字符串 `typed`，判断它是否**可能**是 `name` 的长按结果。

形式化地说：把 `name` 中每个字符 $c_i$ 各重复至少 1 次得到一串，是否可能恰好等于 `typed`。

**约束**：

- $1 \le \text{name.length}, \text{typed.length} \le 1000$
- 两者都只含小写字母

## 2. 示例

**示例 1**

```text
输入：name = "alex", typed = "aaleex"
输出：true
解释：'a' 被长按成 "aa"，'e' 被长按成 "ee"，其余正常。
```

**示例 2**

```text
输入：name = "saeed", typed = "ssaaedd"
输出：false
解释：name 需要 2 个 'e'，typed 里只有 1 个 'e' —— 长按只会多不会少。
```

**示例 3（补充）**

```text
输入：name = "alex", typed = "aaleexa"
输出：false
解释：末尾多出的 'a' 既不是前一个字符的长按，也对不上 name。
```

**示例 4（补充）**

```text
输入：name = "a", typed = "aaaaaaaaaa"
输出：true
解释：单字符被长按 10 次。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的暴力是「枚举每个字符重复几次」：`name` 长度 $n$、`typed` 长度 $m$，让每个字符重复 $1 \sim m$ 次，检查能否拼出 `typed`。方案数是 $O(m^n)$ 级别，$n = 1000$ 时完全不可行。

另一种常见误区是「压缩成 (字符, 次数) 组再比较」。这确实是**正确**的做法（见 3.2 的等价刻画），但它要额外存储两组压缩结果，且容易在「首字符不匹配」「末字符缺失」这类细节上写错。双指针能在**一次扫描、$O(1)$ 额外空间**内完成同样的判定。

### 3.2 核心观察：只有两种「合法解释」

![双指针：typed 的字符只有「对位」与「长按」两种解释](images/wc107_q1_two_pointer_concept.svg)

让 $i$ 指向 `name` 的待匹配位置、$j$ 指向 `typed` 的当前字符。读 `typed[j]` 时只有两种可能：

1. **对位**：`name[i] == typed[j]`。这次输入的是 `name` 的第 $i$ 个字符（可能还只是它重复的第一次），于是 $i$、$j$ 同进；
2. **长按**：`typed[j] == typed[j-1]`。这是上一个字符被按住产生的**额外**重复，只消耗 `typed`，于是 $j$ 单独前进。

除此之外的任何情况都只能判 `false`：`typed[j]` 既不是 `name` 的当前字符、又不是前一个字符的重复，说明它凭空多出来了。

扫描结束后还差一步——**`i` 必须也走到 `n`**，否则说明 `name` 的尾部字符一个都没打出来（如 `name = "ab"`、`typed = "a"`）。

> 💡 一句话总结：`typed` 里每一段连续相同字符，必须能对上 `name` 中同字符的那一段，且长度**不短于**它。

### 3.3 算法流程

![算法流程：两种合法解释，其余一律 false](images/wc107_q1_why_not_naive.svg)

```text
1. i = 0, j = 0
2. while j < m:
       if i < n 且 name[i] == typed[j]:   i++; j++      # 对位
       elif j > 0 且 typed[j] == typed[j-1]:  j++        # 长按
       else:  return false
3. return i == n
```

注意 `j > 0` 这个前置条件：`typed[0]` 没有「前一个字符」，不能被解释成长按。

### 3.4 示例演算

![示例演算：alex / aaleex 与 saeed / ssaaedd](images/wc107_q1_walkthrough.svg)

`name = "alex"`、`typed = "aaleex"`：

| j | typed[j] | 走哪条规则 | i |
|---|----------|------------|---|
| 0 | a | `name[0] == typed[0]` | 1 |
| 1 | a | `typed[1] == typed[0]`（长按） | 1 |
| 2 | l | `name[1] == typed[2]` | 2 |
| 3 | e | `name[2] == typed[3]` | 3 |
| 4 | e | `typed[4] == typed[3]`（长按） | 3 |
| 5 | x | `name[3] == typed[5]` | 4 = n |

循环结束时 $i = 4 = n$，返回 `true`。

反面例子 `name = "saeed"`、`typed = "ssaaedd"`：前 4 步都顺利（`s`、`a` 各被长按一次），到 $j = 5$ 时 `typed[5] = 'd'`，而 `name[3] = 'e'`——对位失败；再看长按：`typed[5]` 与 `typed[4] = 'e'` 不同，也不是重复。于是直接返回 `false`。真正的原因是 `name` 有两个 `e`，而 `typed` 只给了一个：长按只会让字符**变多**，不会变少。

## 4. 算法细节

1. **循环条件用 $j < m$**：以 `typed` 为主轴扫描；`name` 是否被完整消耗留到最后用 $i == n$ 检查。
2. **`i < n` 必须写在条件里**：`i` 可能先走到 `n`（`name` 已用完），此时后续字符只能靠长按解释；若不判 `i < n` 就会越界。
3. **`j > 0` 保护首字符**：`typed[0]` 不能被当成长按，否则像 `typed = "b"`、`name = "a"` 这种会误判（首字符直接走长按分支跳过）。
4. **不需要额外数据结构**：压缩分组法的逻辑被「在线的两个判断」等价替代，额外空间 $O(1)$。
5. **字符集无关**：小写字母的限制不影响算法，任意字符集都适用。

## 5. 正确性证明

**引理 1（匹配的单调性）**：算法中 $i$、$j$ 均单调不减，且 $i \le j$ 始终成立。

**证明**：两种分支都让 $j$ 增加 1；`i` 只在「对位」分支增加 1，且该分支同时让 $j$ 增加 1，故 $i \le j$ 的差不会变大。初始 $i = j = 0$，归纳即得。∎

**引理 2（不变量）**：设某时刻 $j$ 之前（不含 $j$）的 `typed` 前缀已被成功解释，则 $j > 0$ 时有「$i$ 之前的 `name` 前缀已全部被消耗，且 `typed[j-1]` 对应 `name[i-1]`」。

**证明**：对 $j$ 归纳。$j = 0$ 时前缀为空，成立。设当前不变量成立，处理 `typed[j]`：

- 若走对位分支，则 `typed[j]` 明确对应 `name[i]`，处理完后前缀延伸到 $j+1$，$i$ 也前进 1，不变量保持；
- 若走长按分支，则 `typed[j] == typed[j-1]` 且由不变量 `typed[j-1]` 对应 `name[i-1]`，故 `typed[j]` 是同一字符的额外重复，只延伸 `typed` 前缀而不推进 `name`，不变量保持（此时 `typed[j]` 对应 `name[i-1]`）。∎

**引理 3（false 的必要性）**：若算法返回 `false`，则 `typed` 不可能是 `name` 的长按结果。

**证明**：返回 `false` 只可能来自两处。

其一，某个 `typed[j]` 两个分支都不满足，即 `typed[j] != name[i]` 且 `typed[j] != typed[j-1]`。由引理 2，前 $j$ 个字符已被正确解释、`typed[j-1]` 对应 `name[i-1]`。若 `typed` 是长按结果，则 `typed[j]` 要么开始对应 `name[i]`（对位），要么是 `typed[j-1]` 所示字符的重复（长按），二者必居其一，矛盾。

其二，循环正常结束但 $i < n$，即 `name` 的尾部若干字符没有出现在解释中。长按只会让字符**变多**，不会让 `name` 的字符消失，故 `typed` 不可能是长按结果。∎

**定理**：算法返回 `true` 当且仅当 `typed` 是 `name` 的长按结果。

**证明**：

*必要性*（true ⇒ 合法）：若返回 `true`，则整个 `typed` 都被解释过，且由引理 2 每次解释都对应「`name` 中某字符的一次输入」，最终 $i = n$ 说明 `name` 的每个字符都至少被输入一次。于是每个字符被输入 1 次或多次，且顺序与 `name` 一致，`typed` 恰为 `name` 的长按结果。

*充分性*（合法 ⇒ true）：设 `typed` 由 `name` 每个字符重复 $\ge 1$ 次得到。对 `typed` 的每个位置，按上述「两种解释」处理：新字符首次出现时一定对位成功，重复出现时一定满足 `typed[j] == typed[j-1]`。因此扫描过程不会落入 `false` 分支，且 $i$ 恰在每个字符第一次出现时前进 1，最终 $i = n$，返回 `true`。∎

## 6. 复杂度分析

- **时间**：$O(m)$，其中 $m = \text{typed.length}$。$j$ 单调递增、最多走 $m$ 步，$i$ 的推进也包含在同样的循环里。
- **空间**：$O(1)$，只有两个下标。
- **上界**：$m \le 1000$，最坏 1000 次循环，远低于限制。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isLongPressedName(string name, string typed) {
        int n = (int)name.size(), m = (int)typed.size();
        int i = 0, j = 0;
        while (j < m) {
            if (i < n && name[i] == typed[j]) {
                i++; j++;                       // 正常键入 / 该字符的第 1 次长按
            } else if (j > 0 && typed[j] == typed[j - 1]) {
                j++;                            // 长按产生的多余重复字符
            } else {
                return false;                   // 多出既非长按、也对不上 name 的字符
            }
        }
        return i == n;                          // name 必须被完整消耗
    }
};
```

### Python

```python
class Solution:
    def isLongPressedName(self, name: str, typed: str) -> bool:
        i = j = 0
        n, m = len(name), len(typed)
        while j < m:
            if i < n and name[i] == typed[j]:
                i += 1
                j += 1
            elif j > 0 and typed[j] == typed[j - 1]:
                j += 1
            else:
                return False
        return i == n
```

## 8. 边界情况与易错点

1. **忘记 `return i == n`**：`name = "ab"`、`typed = "a"` 会被误判为 `true`，这是最常见的 WA。
2. **`j > 0` 漏判**：`typed` 首字符若与 `name` 首字符不同，会直接走长按分支跳过，导致 `name = "a"`、`typed = "b"` 误判为 `true`。
3. **`i < n` 漏判**：`name` 先耗尽后继续读 `typed` 会越界（C++ 未定义行为，Python 抛 `IndexError`）。
4. **长度方向搞反**：`typed` 一定不短于 `name`；若 `m < n` 必然 `false`，算法会自然返回 `false`（$i$ 到不了 $n$），无需特判。
5. **单字符长按**：`name = "a"`、`typed = "aaaa"` → `true`；注意 `typed` 全为同一字符且 `name` 也是该字符才成立。
6. **`name` 与 `typed` 完全相同**：全部走对位分支，`i` 到 `n`，返回 `true`。
7. **长按跨越字符边界**：`typed = "aabb"` 对 `name = "ab"` 成立，但 `typed = "abab"` 不成立——长按只能重复**当前**字符，不能重排。
