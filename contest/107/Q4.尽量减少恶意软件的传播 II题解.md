# LeetCode 尽量减少恶意软件的传播 II 题解

## 1. 题目概述

- **标题 / 题号**：尽量减少恶意软件的传播 II（#928，hard）
- **链接**：https://leetcode.cn/problems/minimize-malware-spread-ii/
- **来源**：LeetCode 第 107 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、广度优先搜索、并查集、图、数组、哈希表

**题意**：给定 $n$ 个节点的无向图（$n \times n$ 邻接矩阵 `graph`，主对角线为 1、矩阵对称）。`initial` 中的节点最初被感染，感染沿边无限扩散至稳定，记此时感染节点总数为 $M(\text{initial})$。

现在**从 `initial` 中删除恰好一个节点**，并**完全移除该节点以及它连接的所有边**。选择删除哪个节点能使 $M$ 最小；若有多个，返回**下标最小**者。

**约束**：

- $2 \le n \le 300$
- `graph[i][j]` 为 0 或 1，`graph[i][j] = graph[j][i]`，`graph[i][i] = 1`
- $1 \le \text{initial.length} < n$，`initial` 内元素互不相同
- $0 \le \text{initial}[i] \le n - 1$

> ⚠️ 与 #924（I 版）的关键差别：I 版只是**取消初始感染**，节点与边都保留；本题是**把节点从图上摘掉**。摘掉一个节点可能让原本连通的一大块裂成几块，因此 I 版「块内只有 1 个源 → 收益 = 块大小」的结论**完全不适用**。

## 2. 示例

**示例 1**

```text
输入：graph = [[1,1,0],[1,1,0],[0,0,1]], initial = [0,1]
输出：0
解释：删 0 后图剩 {1},{2}，感染 {1}，M = 1；删 1 同理 M = 1。并列取最小下标 0。
```

**示例 2**

```text
输入：graph = [[1,1,0],[1,1,1],[0,1,1]], initial = [0,1]
输出：1
解释：0—1—2 是一条链。
     删 0：剩源 {1} → 感染 {1,2}，M = 2；
     删 1：图断成 {0} 与 {2}，剩源 {0} → 感染 {0}，M = 1。
     M 更小的是删 1，故返回 1。
```

**示例 3**

```text
输入：graph = [[1,1,0,0],[1,1,1,0],[0,1,1,1],[0,0,1,1]], initial = [0,1]
输出：1
解释：0—1—2—3 是一条链。
     删 0：剩源 {1} → 感染 {1,2,3}，M = 3；
     删 1：图断成 {0} 与 {2,3}，剩源 {0} → 感染 {0}，M = 1。
     故返回 1。
```

## 3. 解题思路

### 3.1 暴力思路

本题的「暴力」其实已经是正解：按定义逐个枚举候选 $u \in \text{initial}$，在「删掉 $u$ 的图」上从剩余感染源做一次 DFS/BFS，统计最终感染数，取最小者。

单次扩散 $O(n^2)$（邻接矩阵），候选至多 $n$ 个，总复杂度 $O(n^3)$。$n = 300$ 时约 $2.7 \times 10^7$ 次操作，在 C++ 里 0.1 秒内完成，Python 也能过。所以**这题的关键不是找到更快的算法，而是准确理解「删除」的语义**。

相比 I 版，本题多了一个「图上没有更省的结构性优化」的事实：删点会让图的连通性任意改变，无法用一次块计数覆盖所有候选。

### 3.2 核心观察：删点会改变连通性，必须逐候选重算

![II 版的关键差异：删节点 = 连边一起删](images/wc107_q4_remove_concept.svg)

在 I 版里，「移除」只改变源集合，图本身不变，所以感染范围只由**原来的连通块**决定，一次染色即可回答所有候选。

II 版则不同：删掉 $u$ 后，原本经由 $u$ 相连的两部分会断开，感染可能因此被限制在更小的区域。示例 2 的链 $0-1-2$ 就是最好的例子：删掉中间的 $1$，图被切成 $\{0\}$ 与 $\{2\}$ 两半，感染数从 2 骤降到 1；而删掉端点 $0$ 时，剩余部分仍然连成一片，感染数是 2。

于是正确的做法只有一条：**对每个候选，真的在「去掉该点」的图上重算一次扩散范围**。

- 若从其余感染源出发的 DFS 已把 $u$ 之外的所有连通部分覆盖，则 $u$ 自己也「被删了」，不计入感染数——这正是题面「完全移除该节点」的含义。
- 遍历时把 $u$ 当作不可达（既不访问也不计入），其余节点照常扩展。

### 3.3 算法流程

![算法流程：枚举被删节点 × 一次 DFS](images/wc107_q4_algorithm_flow.svg)

```text
1. 将 initial 升序排序
2. best = initial[0], bestCnt = +∞
3. for ban in initial:
       vis[] = false，栈 = { u ∈ initial : u != ban }，并标记为已访问
       cnt = 0
       while 栈非空:
           弹出 u，cnt++
           for v in 0..n-1:
               if graph[u][v] == 1 且 !vis[v] 且 v != ban:
                   vis[v] = true; 入栈
       if cnt < bestCnt:  bestCnt = cnt; best = ban
4. 返回 best
```

两个细节决定了正确性：**（a）** 剩余感染源一开始全部入栈（多源 DFS）；**（b）** `v != ban` 时既不访问也不计数，等价于把 `ban` 从图中摘除。

### 3.4 示例演算

![示例 2 演算：链 0—1—2](images/wc107_q4_walkthrough.svg)

以示例 2 `graph = [[1,1,0],[1,1,1],[0,1,1]]`、`initial = [0,1]` 为例：

| ban | 删点后的图 | 剩余源 | 扩散结果 | cnt |
|-----|-----------|--------|----------|-----|
| 0 | 1—2 连通，0 被删除 | {1} | {1,2} | 2 |
| 1 | 0 孤立、2 孤立（1 的边全断） | {0} | {0} | 1 |

`cnt = 1 < 2`，故 `best = 1`，与官方输出一致。

再看示例 3 的链 $0-1-2-3$：删 1 后 $\{0\}$ 与 $\{2,3\}$ 断开，剩余源只有 0，感染 1 个节点；删 0 则 $\{1,2,3\}$ 全被感染，$M = 3$。同样返回 1。

## 4. 算法细节

1. **多源初始化**：把所有「非 ban 的初始感染源」一次性入栈，避免对每个源各跑一次 DFS 造成重复计数（用 `vis` 保证每个节点只计一次）。
2. **`ban` 的三重隔离**：不入栈、不被扩展、不被计数。三者缺一不可，否则会把它算进感染数或经由它传播。
3. **`initial` 升序 + 严格小于**：`best` 初值取 `initial[0]`，更新条件是 `cnt < bestCnt`（严格小于）。由于升序遍历，并列时先遇到的（下标更小）自然保留。
4. **复杂度可控**：每候选一次 $O(n^2)$ 的 DFS；递推时用显式栈（迭代），避免 $n = 300$ 时递归层数过深（C++ 通常没事，Python 需注意 `sys.setrecursionlimit`，迭代写法更稳）。
5. **`graph[u][u] = 1`**：自身边不影响传播，因为入栈时已标记 `vis`。
6. **不要用「块计数」优化**：删点后块结构随候选变化，若强行预计算会得到错误答案；若想优化，只能对「删点后连通性不变」的候选做剪枝，收益不稳定，不如直接算。

## 5. 正确性证明

固定候选 $u$，记 $G_u$ 为从 `graph` 中删除节点 $u$ 及其所有关联边后得到的图，$S_u = \text{initial} \setminus \{u\}$，$R_u$ 为在 $G_u$ 上从 $S_u$ 出发的可达节点集合。

**引理 1（删除语义的等价性）**：题面所述「删除 $u$ 并移除其所有边」之后的最终感染集合恰为 $R_u$，感染数 $M_u = |R_u|$。

**证明**：删点后图中不再有 $u$，故任何传播路径都不可能经过 $u$；其余顶点与其余边都与原图一致。感染在 $G_u$ 上按连通性扩散：从 $S_u$ 出发可达的点全被感染，不可达的点永不被感染（同 I 版引理：块内全染、块外不染）。$u$ 已不在 $G_u$ 中，自然不计入感染数。∎

**引理 2（DFS 计算的正是 $R_u$）**：算法对候选 $u$ 的 DFS 结束时，`cnt` $= |R_u|$。

**证明**：算法的遍历规则与在 $G_u$ 上做标准 DFS 完全一致：初始栈为 $S_u$ 且全部标记访问；从 $u'$ 扩展时只考虑 `graph[u'][v] = 1`、`v \ne ban`、未访问的 $v$，这与 $G_u$ 的邻接关系逐条对应。标准 DFS 的结论是：从 $S_u$ 可达的节点恰被访问一次、不可达的节点永不被访问。`cnt` 在每次出栈时自增，故 `cnt = |R_u|`。∎

**引理 3（枚举的完备性）**：算法对 `initial` 中每个元素都恰好计算了一次 $M_u$。

**证明**：外层循环遍历 `initial` 全部元素一次，由引理 1、2，每次得到的是 $M_u = |R_u|$。没有候选被跳过或重复计算。∎

**定理**：算法返回的节点 $u^*$ 满足 $M_{u^*} = \min_{u \in \text{initial}} M_u$，且在所有达到最小值的候选中下标最小。

**证明**：由引理 3，循环中每个候选的 $M_u$ 都被正确计算；更新规则是「`cnt < bestCnt` 时替换」，故循环结束时 `bestCnt` 恰为所有 $M_u$ 的最小值，`best` 是最小值对应的某个候选。由于遍历按升序进行、且只在**严格更小**时替换，任何并列的后来者都不会覆盖先到者，因此 `best` 是所有最小值候选中下标最小的那个。∎

## 6. 复杂度分析

- **时间**：$O(n^3)$。对每个候选（至多 $n$ 个）做一次 DFS，每次遍历邻接矩阵 $O(n^2)$；共 $O(n^3)$。$n = 300$ 时约 $2.7\times10^7$ 次基本操作。
- **空间**：$O(n)$。`vis` 数组与显式栈各 $O(n)$；邻接矩阵是输入本身。
- **常数优化**：内层只用「按行扫邻接矩阵」，没有哈希或动态分配，实际跑得很快；`initial` 很小时（如 $|initial| = 1$）退化为一次 DFS。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minMalwareSpread(vector<vector<int>>& graph, vector<int>& initial) {
        int n = (int)graph.size();
        sort(initial.begin(), initial.end());   // 升序遍历 → 并列时天然取最小下标

        int best = initial[0], bestCnt = INT_MAX;
        for (int ban : initial) {
            // 把 ban 从图中彻底删除后，从其余感染源出发做一次 DFS，统计最终感染数
            vector<char> vis(n, 0);
            vector<int> st;
            for (int u : initial) {
                if (u != ban) { vis[u] = 1; st.push_back(u); }
            }
            int cnt = 0;
            while (!st.empty()) {
                int u = st.back();
                st.pop_back();
                cnt++;
                for (int v = 0; v < n; ++v) {
                    if (graph[u][v] == 1 && !vis[v] && v != ban) {
                        vis[v] = 1;
                        st.push_back(v);
                    }
                }
            }
            if (cnt < bestCnt) { bestCnt = cnt; best = ban; }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def minMalwareSpread(self, graph: list[list[int]], initial: list[int]) -> int:
        n = len(graph)
        initial = sorted(initial)
        best, best_cnt = initial[0], None
        for ban in initial:
            vis = [False] * n
            st = []
            for u in initial:
                if u != ban:
                    vis[u] = True
                    st.append(u)
            cnt = 0
            while st:
                u = st.pop()
                cnt += 1
                for v in range(n):
                    if graph[u][v] == 1 and not vis[v] and v != ban:
                        vis[v] = True
                        st.append(v)
            if best_cnt is None or cnt < best_cnt:
                best_cnt, best = cnt, ban
        return best
```

## 8. 边界情况与易错点

1. **把「删点」写成「取消初始感染」**：这是把本题写回 I 版的最常见错误。区别在示例 2 就暴露了：I 版会输出 0，本题输出 1。
2. **`ban` 被自己的边「感染」**：若忘记了 `v != ban` 这个过滤，DFS 会经由其它节点回到 `ban`（因为边还在矩阵里），把它计入 `cnt`，结果偏大。
3. **多源未同时入栈**：只从 `initial[0]` 出发会漏掉其它源的扩散范围；必须把所有非 `ban` 的源一次性入栈并统一标记。
4. **`initial` 未排序就按输入顺序遍历**：并列规则会失效，可能返回较大的下标。
5. **用 `<=` 更新**：会保留最后一个并列候选（下标最大），与题意相反。
6. **$|initial| = 1$**：删掉它后没有感染源，$M = 0$，答案就是它本身；注意 `initial.length < n` 保证至少还有一个节点存在。
7. **$n = 2$**：`graph = [[1,1],[1,1]]`、`initial = [0]` → 删 0 后 $M = 0$，返回 0。
8. **递归写法爆栈**：$n = 300$ 的链式图递归深度可达 300，Python 默认递归限制 1000 通常够，但改成迭代更稳。
