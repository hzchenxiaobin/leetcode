# LeetCode 快照数组 题解

## 1. 题目概述

- **标题 / 题号**：快照数组（#1146，medium）
- **链接**：https://leetcode.cn/problems/snapshot-array/
- **来源**：LeetCode 第 148 场周赛 Q3
- **难度**：中等
- **标签**：设计、数组、哈希表、二分查找、可持久化数据结构

**题意**：实现 `SnapshotArray` 的四个操作——构造（长度 `length`，初始全为 $0$）、`set(index, val)` 改写某个位置、`snap()` 拍快照并返回快照编号（第 $k$ 次调用返回 $k-1$）、`get(index, snap_id)` 读出指定快照中指定位置的值。核心矛盾在于：数组长度与快照次数都可以到 $5\times10^4$，但**总调用次数只有 $5\times10^4$**，即「被改动的元素」是稀疏的。

**约束**：

- $1 \le \text{length} \le 5\times10^4$
- $0 \le \text{index} < \text{length}$，$0 \le \text{val} \le 10^9$
- `set`、`snap`、`get` 的总调用次数 $\le 5\times10^4$
- `get` 的 `snap_id` 保证严格小于已调用 `snap()` 的次数

## 2. 示例

**示例 1（官方）**

```text
输入：["SnapshotArray","set","snap","set","get"]
     [[3],[0,5],[],[0,6],[0,0]]
输出：[null,null,0,null,5]
解释：SnapshotArray arr = new SnapshotArray(3);
     arr.set(0, 5);   // array[0] = 5
     arr.snap();      // 取快照，返回 snap_id = 0
     arr.set(0, 6);   // 只影响之后的快照
     arr.get(0, 0);   // 快照 0 里 array[0] 仍是 5
```

**示例 2（补充：从未被写过的下标）**

```text
输入：["SnapshotArray","snap","get","get","set","snap","get","get"]
     [[2],[],[0,0],[1,0],[1,7],[],[1,0],[1,1]]
输出：[null,0,0,0,null,1,0,7]
解释：快照 0 里两个元素都还是 0；set(1,7) 只对快照 1 生效，
      get(1,0) 仍为 0，get(1,1) 才是 7。
```

**示例 3（补充：同一快照内反复改写）**

```text
输入：["SnapshotArray","set","set","snap","get","set","snap","get","get"]
     [[4],[2,1],[2,2],[],[2,0],[2,3],[],[2,0],[2,1]]
输出：[null,null,null,0,2,null,1,2,3]
解释：两次 set 落在同一个快照区间内，只有最后一次 (2,2) 进入快照 0；
      之后 set(2,3) 进入快照 1，快照 0 的历史值 2 不被覆盖。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的实现是「快照即整份复制」：`snap()` 时把整个数组 `copy` 一份压进 `vector<vector<int>>`，`get` 直接查下标。此时查询 $O(1)$，但每次 `snap` 要 $O(\text{length})$。最坏情况下 $\text{length} = 5\times10^4$、调用 $5\times10^4$ 次且几乎全是 `snap`，复制量约 $2.5\times10^9$ 个整数——超时且爆内存。

另一种暴力是「反过来记」：只在 `set` 时把 `(时刻, index, val)` 追加到一条日志里，`get` 时倒着扫日志找第一条 $t$ 满足「写入时刻不晚于该快照」且下标匹配的记录。单次 `get` 最坏 $O(q)$，$q = 5\times10^4$ 时同样是 $2.5\times10^9$ 次操作，过不去。

两者失败的原因相同：**查询时没有「按下标」索引，或者写入时复制了太多用不到的数据**。

### 3.2 核心观察：把「按下标的行」拆出来，每个下标只记自己的历史

![按下标拆分：版本链取代全量复制](images/wc148_q3_version_chain.svg)

关键观察：`get` 永远只查**一个下标**。既然总写入次数只有 $5\times10^4$，完全没必要为「没被写过的位置」保存任何东西。于是把二维的「快照 × 下标」表格按列切开：

- 每个下标 $i$ 维护一条链 `his[i]`，存放 `(stamp, val)`；
- `stamp` = 这次写入发生时**已经调用 `snap()` 的次数**，含义是「本记录从编号为 `stamp` 的快照开始生效」；
- `snap()` 只返回计数器 `snap_cnt` 再把它加一，**不触碰任何链**；
- `get(index, snap_id)` 在该下标的链上找 `stamp <= snap_id` 的**最后一个**版本；找不到说明这个位置从未被写过，返回初始值 $0$。

链上的 `stamp` 天然严格递增（时间只会往前走），所以「最后一个 `stamp <= snap_id`」可以用二分在 $O(\log m)$ 内定位，$m$ 是该下标被写过的次数。

### 3.3 算法流程

![三个接口的分工](images/wc148_q3_interface_flow.svg)

三个接口的职责被彻底分开：

1. **`set(index, val)`**：令 `stamp = snap_cnt`。若链尾的 `stamp` 与它相同（说明同一快照区间内重复写同一个位置），直接覆盖链尾；否则追加 `(stamp, val)`。两种分支都是 $O(1)$。
2. **`snap()`**：返回当前 `snap_cnt`，然后 `snap_cnt += 1`。题目定义「快照号 = 调用次数 − 1」，与这个计数器完全一致。
3. **`get(index, snap_id)`**：在 `his[index]` 上二分，找出最后一个 `stamp <= snap_id` 的记录并返回其 `val`；若不存在（链为空，或所有 `stamp` 都大于 `snap_id`，即这些写入都发生在取该快照之后），返回 $0$。

### 3.4 示例演算

![官方示例的逐步走查](images/wc148_q3_walkthrough.svg)

对示例 1 走一遍：`set(0,5)` 时 `snap_cnt = 0`，链变成 `[(0,5)]`；`snap()` 返回 $0$ 并把计数器推到 $1$；`set(0,6)` 追加 `(1,6)`，链变成 `[(0,5), (1,6)]`；最后 `get(0,0)` 在链上找 `stamp <= 0` 的最后一个版本，命中 `(0,5)`，返回 $5$——后写入的 `(1,6)` 因为 `stamp = 1 > 0` 被正确地排除在外。

## 4. 算法细节

1. **`stamp` 为什么用「已 snap 次数」而不是「刚返回的 `snap_id`」**：两次 `snap()` 之间的所有 `set` 都属于「下一个」快照，此时 `snap_cnt` 恰好等于那个快照的编号。于是「`stamp <= snap_id`」精确等价于「这次写入发生在取该快照之前」，语义没有歧义。
2. **同一区间内重复写同一位置**：`stamp` 相同，只保留最后一次即可。若选择全部追加，二分取最后一个 `<= snap_id` 依然正确，但链上会出现重复 `stamp`，浪费空间；覆盖写法还能让「`stamp` 严格递增」这个性质成立，二分边界更干净。
3. **二分的写法是「最后一个 $\le$ 目标」**，不是 `lower_bound`：

   ![二分定位最后一个 stamp ≤ snap_id 的版本](images/wc148_q3_upper_bound.svg)

   循环里用 `ans` 记住最后一次满足 `h[mid].first <= snap_id` 的下标，满足时向右收缩 `lo = mid + 1`，否则 `hi = mid - 1`；循环结束 `ans` 就是答案，`ans == -1` 表示没有可用版本。
4. **C++ 的 `pair` 比较**：`h` 是 `vector<pair<int,int>>`，可以直接 `upper_bound(h.begin(), h.end(), make_pair(snap_id, INT_MAX))`；**第二个字段必须取足够大的哨兵**（`val <= 10^9`，用 `INT_MAX` 安全），否则可能停在同 `stamp` 的记录之前。
5. **Python 的 `bisect_right`**：`bisect_right(h, (snap_id, INF)) - 1` 一行搞定，`INF = 1 << 60` 远大于任何 `val`，保证同 `stamp` 的记录被算进区间。
6. **查询里的 $0$ 是「初始值」而不是「未找到标记」**：`val` 可以为 $0$，所以不能靠值判断是否存在，必须靠「二分结果下标 `>= 0`」判断。
7. **空间上限**：最多 $5\times10^4$ 条记录，每条两个 `int`，约 $400$ KB；再加 `length` 个空 `vector`（约 $1.2$ MB）。不要用 `vector<vector<int>>` 存整份快照。

## 5. 正确性证明

**定义**：设第 $k$ 次调用 `snap()` 返回编号 $k-1$，且返回后 `snap_cnt` 变为 $k$。称一次 `set` 写入的 `stamp` 为它发生时 `snap_cnt` 的值。

**引理 1（链上有序）**：任意 `his[i]` 中 `stamp` 严格递增。

**证明**：只有当新 `stamp` 大于链尾 `stamp` 时才追加；`snap_cnt` 单调不减，且同一 `stamp` 的写入被覆盖而非追加，故不会出现相等或逆序的相邻元素。∎

**引理 2（版本语义）**：对任意下标 $i$ 与任意合法 `snap_id` $k$，`get(i, k)` 返回的正是「取快照 $k$ 时 $array[i]$ 的值」。

**证明**：`stamp = s` 的写入发生在 `snap_cnt = s` 的时刻，即快照 $0,1,\dots,s-1$ 已经创建、快照 $s$ 尚未创建。因此它属于快照 $s$ 及其之后的所有快照，对编号 $< s$ 的快照不可见。于是对固定快照 $k$，可见的写入集合恰为 $\{\text{stamp} \le k\}$；由引理 1 与「时间递增时后者覆盖前者」的事实，$array[i]$ 在快照 $k$ 的取值就是该集合中时间最晚（即 `stamp` 最大）那一条的 `val`。若集合为空，说明 $i$ 在取快照 $k$ 之前从未被写过，值保持初始值 $0$。∎

**引理 3（二分定位正确）**：在严格递增序列上用「最后一个 $\le$ 目标的二分」返回的下标 $ans$ 满足：$h[ans]$ 是唯一一个 `stamp <= snap_id` 且其后继要么不存在、要么 `stamp > snap_id` 的元素；若不存在这样的元素则 `ans = -1`。

**证明**：不变量为「$ans$ 始终是已知满足条件的最右下标，$lo$ 左侧全部 $\le$ 目标、$hi$ 右侧全部 $>$ 目标」。每次 `mid` 满足条件时更新 `ans = mid` 并令 `lo = mid + 1`（由单调性，$mid$ 左边的不可能是更右的解），否则令 `hi = mid - 1`。循环结束时 $lo > hi$，不变量两侧夹出的正是最后一个满足条件的位置。∎

**定理**：`set`、`snap`、`get` 三个接口的返回值与题目要求的语义完全一致。

**证明**：`snap()` 返回 `snap_cnt` 并自增，而 `snap_cnt` 的初值为 $0$、每次调用恰好加一，故第 $k$ 次调用返回 $k-1$，与「快照号 = 调用次数 − 1」一致。`set` 只改写当前状态，按定义它应对之后创建的快照生效，而 `stamp = snap_cnt` 正是下一个快照的编号，所以新值从快照 `snap_cnt` 起可见，符合语义。`get` 的正确性由引理 2（语义刻画）与引理 3（二分精确定位到该刻画所要求的记录）复合得到：返回值的来源是「`stamp` 最大且 $\le k$ 的那条记录」，恰为快照 $k$ 中的值；集合为空时返回 $0$，也与初始状态一致。∎

## 6. 复杂度分析

- **时间**：`set` 为 $O(1)$（尾插或覆盖，`vector` 尾插均摊 $O(1)$）；`snap` 为 $O(1)$；`get` 为 $O(\log m)$，其中 $m$ 是该下标被写入的次数，$m \le$ `set` 总次数 $\le 5\times10^4$。总计 $O(q\log q)$，$q$ 为调用总数，$5\times10^4$ 次调用完全够用。
- **空间**：$O(\text{length} + \#\text{set})$。`length` 个空链的容器开销，加上每条写入记录两个 `int`；没有整份快照副本，也没有哈希表。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <utility>
using namespace std;

class SnapshotArray {
public:
    SnapshotArray(int length) : snapCnt(0), his(length) {}

    void set(int index, int val) {
        vector<pair<int, int>>& h = his[index];
        if (!h.empty() && h.back().first == snapCnt) {
            h.back().second = val;              // 同一快照区间内重复写：只留最后一次
        } else {
            h.push_back({snapCnt, val});        // stamp = 下一个快照的编号
        }
    }

    int snap() { return snapCnt++; }

    int get(int index, int snap_id) {
        const vector<pair<int, int>>& h = his[index];
        int lo = 0, hi = (int)h.size() - 1, ans = -1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (h[mid].first <= snap_id) {
                ans = mid;                      // 先记下，再尝试更靠右的版本
                lo = mid + 1;
            } else {
                hi = mid - 1;
            }
        }
        return ans < 0 ? 0 : h[ans].second;     // 没有版本 ⇒ 初始值 0
    }

private:
    int snapCnt;                                 // 已调用 snap() 的次数
    vector<vector<pair<int, int>>> his;          // 每下标：(生效 stamp, 值)
};
```

### Python

```python
import bisect


class SnapshotArray:
    INF = 1 << 60

    def __init__(self, length: int):
        self.snap_cnt = 0                       # 已调用 snap() 的次数
        self.his = [[] for _ in range(length)]   # 每下标: [(stamp, val), ...]

    def set(self, index: int, val: int) -> None:
        h = self.his[index]
        stamp = self.snap_cnt                    # 对编号 >= stamp 的快照生效
        if h and h[-1][0] == stamp:
            h[-1] = (stamp, val)                 # 同一快照区间内覆盖
        else:
            h.append((stamp, val))

    def snap(self) -> int:
        sid = self.snap_cnt
        self.snap_cnt += 1
        return sid

    def get(self, index: int, snap_id: int) -> int:
        h = self.his[index]
        # 二分找最后一个 stamp <= snap_id 的版本
        i = bisect.bisect_right(h, (snap_id, self.INF)) - 1
        return h[i][1] if i >= 0 else 0
```

## 8. 边界情况与易错点

1. **`get` 一个从未被写过的下标**：必须返回 $0$，不能返回 $-1$ 或让二分的 `ans` 参与下标访问（`h[-1]` 在 Python 里会静默取到最后一个元素，是最阴的坑）。
2. **第一次 `snap()` 之前的 `set`**：`stamp = 0`，必须能被 `snap_id = 0` 查到。若把 `stamp` 记成「刚返回的 `snap_id`」或初始化为 $-1$，这条写入就会被漏掉。
3. **`stamp > snap_id` 的记录必须排除**：同一个下标在更晚的快照里被改写过时，链尾的 `stamp` 会大于查询的 `snap_id`，二分比较要用 `<=` 且只在满足时向右走。
4. **哨兵值**：`upper_bound` / `bisect_right` 的比较键要用足够大的第二个字段（`INT_MAX` / `1 << 60`），否则同 `stamp` 的那条记录可能被排除在区间外。
5. **`val = 0` 与「不存在」不可混淆**：不能把「查到 $0$」当成「没有历史」，必须用下标 `ans >= 0` / `i >= 0` 判定是否存在。
6. **同一快照区间内对同一位置的多次 `set`**：不覆盖而全部追加也能通过（取最后一个），但会白白放大链长；覆盖写法让单条链的长度不超过该下标的 `set` 次数，且保证 `stamp` 严格递增。
7. **不要为每次 `snap` 复制数组**：即使只想「省点时间」用 `vector::assign` 也存在 $O(\text{length})$ 的复制，$5\times10^4$ 次 `snap` 时必然超时。
