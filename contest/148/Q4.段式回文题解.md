# LeetCode 段式回文 题解

## 1. 题目概述

- **标题 / 题号**：段式回文（#1147，hard）
- **链接**：https://leetcode.cn/problems/longest-chunked-palindrome-decomposition/
- **来源**：LeetCode 第 148 场周赛 Q4
- **难度**：困难
- **标签**：贪心，双指针，字符串，动态规划，哈希函数，滚动哈希

**题意**：把字符串 `text` 切成 $k$ 个**非空连续块** $\text{subtext}_1,\dots,\text{subtext}_k$，要求块序列本身构成回文，即对每个 $1 \le i \le k$ 都有 $\text{subtext}_i = \text{subtext}_{k-i+1}$。求 $k$ 的最大值。

换句话说：从两端向中间「对拆」，第 $1$ 块与最后 $1$ 块完全相同、第 $2$ 块与倒数第 $2$ 块相同……一路对到底，最中间那一块（至多一块）不需要配对。

**约束**：

- $1 \le \lvert \text{text} \rvert \le 1000$
- `text` 仅由小写英文字符组成

## 2. 示例

**示例 1**

```text
输入：text = "ghiabcdefhelloadamhelloabcdefghi"
输出：7
解释：(ghi)(abcdef)(hello)(adam)(hello)(abcdef)(ghi)，首尾对称共 7 块。
```

**示例 2**

```text
输入：text = "merchant"
输出：1
解释：首字符 m 与末字符 t 不同，一次配对都做不出，只能整串一块。
```

**示例 3**

```text
输入：text = "antaprezatepzapreanta"
输出：11
解释：(a)(nt)(a)(pre)(za)(tep)(za)(pre)(a)(nt)(a) = 5 对 + 中间 1 块。
      注意 (anta)(pre)(za)(tep)(za)(pre)(anta) 也合法，但只有 7 块。
```

## 3. 解题思路

### 3.1 暴力思路

最直白地按定义搜索：枚举所有切分点，检查块序列是否回文。切点有 $n-1$ 个，枚举量 $2^{n-1}$，不可行。

稍微聪明一点做 DP。设 $f(l,r)$ 表示子串 `text[l..r]` 能切出的最大块数，则

$$f(l,r)=\max\Bigl(1,\ \max_{\substack{L \ge 1\\ 2L \le r-l+1\\ \text{text}[l..l+L)=\text{text}[r-L+1..r+1)}} \bigl(2+f(l+L,\ r-L)\bigr)\Bigr)$$

即先确定首尾两块的公共长度 $L$，再递归处理中间。状态是 $(l,r)$ 的二元组，共 $O(n^2)$ 个；每个状态要枚举 $O(n)$ 个 $L$、每次比较 $O(n)$ 个字符，最坏 $O(n^4)$——即使把比较换成 $O(1)$ 哈希也是 $O(n^3)$，$n=1000$ 时约 $10^9$ 次操作，必然超时。**瓶颈在于「每个状态都要试所有 $L$」，而这个枚举可以砍掉：最短的那个 $L$ 一定不劣。**

### 3.2 核心观察：贪心取「最短可配对前后缀」

![贪心每次配对最短的前后缀块](images/wc148_q4_greedy_shortest_match.svg)

设 $\ell$ 是最小的长度，使得

$$\text{text}[0..\ell) = \text{text}[n-\ell..n), \qquad 2\ell \le n$$

也就是「能配对的最短一对前后缀块」。断言：

> **每一步都取这个最短的 $\ell$，不会损失最优性。**

两条直觉支撑：

1. **块数 $= 2 \times$ 配对数 $+$（中间是否还剩字符）**。想多切块，就要多配对。
2. **外层块越短，留在中间的字符越多**，才有机会继续找出可配对的前后缀；先吃掉一大块（如示例 3 取 `(anta)` 打头），中间空间不足，最多只有 7 块。

在示例 3 里最短配对长度是 $\ell = 1$：`a` 与 `a` 配对后剩 `ntaprezatepzaprean`，继续 $1$ 不行、$2$ 可以（`nt` 与 `nt`），如此反复最终得到 11 块——远多于「先配长块 `(anta)`」的 7 块。严格论证见第 5 节：任何最优分块的首块长度都不会大于 $\ell$，否则可以把首尾块「再拆一层」得到更多块或直接矛盾。

### 3.3 算法流程：双指针 + 双哈希

![双指针与滚动哈希的算法流程](images/wc148_q4_two_pointers_flow.svg)

用两个指针夹住「尚未处理」的区间：$i$ 指向左端、$j$ 指向右端，答案累积在 `ans` 中。

1. 初始化 $i = 0$、$j = n-1$、`ans = 0`。
2. 若 $i > j$，结束，返回 `ans`。
3. 令 $L = 1, 2, \dots$ 递增，找**最小**的 $L$ 使 $2L \le j-i+1$ 且
   $$\text{text}[i..i+L) = \text{text}[j-L+1..j+1)$$
4. 找到这样的 $L$：`ans += 2`，$i \mathrel{+}= L$，$j \mathrel{-}= L$，回到第 2 步。
5. 试到 $2L > j-i+1$ 仍没配上：说明中间剩下的这一段无法再配对，`ans += 1`（它整体作为最中间那一块），结束。

**判等怎么做快**：每次判等都要比较两段长度不同的子串，直接逐字符比较是 $O(L)$。用**滚动哈希**可以把任意子串映射成整数，$O(1)$ 判定：

$$h[0]=0,\qquad h[k+1]=\bigl(h[k]\cdot B+\text{val}(\text{text}[k])\bigr) \bmod M$$

$$\text{hash}(l,r)=\bigl(h[r]-h[l]\cdot B^{\,r-l}\bigr)\bmod M$$

> 💡 左右两块都是 `text` 的**正序**子串（左块从 $i$ 往右读，右块从 $j-L+1$ 往右读），所以一套前缀哈希数组就够了，**不需要**反转串——这里很容易写错（见第 8 节第 5 条）。

为了彻底摆脱「哈希碰撞」的概率假设，采用**双模数**（$10^9+7$ 与 $10^9+9$，底数 $131$ 与 $137$）过滤，命中后再取切片 / `compare` 逐字符确认。哈希只当「快速否证器」，最终正确的等式一定被确认过。

## 4. 算法细节

1. **$L$ 的上界是剩余长度的一半**：剩余 $R = j-i+1$，只试 $L \le \lfloor R/2 \rfloor$；若把上界写成 $R$，同一段字符会被同时当作左块与右块，答案偏大。双指针推进也必须对称：$i \mathrel{+}= L$ 的同时 $j \mathrel{-}= L$。
2. **字符映射与取模**：用 `text[k] - 'a' + 1`（$1..26$）避免 $0$ 值歧义；C++ 里 `(h[r] - h[l] * p[L] % M + M) % M` 必须补 `+M`（负数取模仍为负），Python 的 `%` 天然非负。
3. **幂表要一起预处理**：$p[k] = B^k \bmod M$，否则每次判等都要现算幂，退化回 $O(L)$。
4. **双哈希 + 命中后确认**：单模数有被构造数据针对的风险，双模数后再逐字符确认，正确性完全不依赖哈希；确认只在命中时做，一次 $O(L)$，成功轮次的 $L$ 之和为 $n/2$，总开销仍 $O(n)$。
5. **可以完全不写哈希**：$n \le 1000$ 时，用 C++ 的 `compare` 或 Python 的切片比较，最坏 $O(n^2)$、约 $10^6$ 次字符比较，同样轻松通过。哈希版是为了匹配官方提示里「滚动哈希 + DP」的进阶写法。

## 5. 正确性证明

**引理 1（最短配对长度一定出现在某个最优解的首尾）**：设 $k = f(s) \ge 2$ 为最优块数，$\ell$ 为最小可配对长度。则存在 $k$ 块的合法分块，其首块与末块长度都等于 $\ell$。

**证明**：任取一个 $k$ 块的合法分块 $A\,C_2\cdots C_{k-1}\,B$，其中 $A = B$，$|A| = k_1$。由 $\ell$ 的最小性有 $k_1 \ge \ell$。记 $g = s[0..\ell) = s[n-\ell..n)$。

若 $k_1 = \ell$，已经得证。否则 $k_1 > \ell$。此时 $g$ 是 $A$ 的长度为 $\ell$ 的前缀（$A$ 从下标 $0$ 开始），又因 $g$ 是 $s$ 的后缀、$|g| = \ell \le |B| = k_1$，故 $g$ 也是 $B$ 的后缀，即 $A$ 的后缀。分两种情形：

- 情形 (a)：$2\ell \le k_1$，可写 $A = g\,y\,g$（$y$ 可以为空）。去掉首尾的 $g$ 后
  $$s[\ell..n-\ell) = y\,g\,C_2\cdots C_{k-1}\,g\,y$$
  按 $(y)(g)(C_2)\cdots(C_{k-1})(g)(y)$ 分组是一个**合法**的段式回文分块，块数至少为 $k$（$y$ 为空时恰为 $k$）。于是 $f(s) \ge 2 + k > k$，与 $k = f(s)$ 矛盾。
- 情形 (b)：$2\ell > k_1$，令 $p = k_1 - \ell > 0$。由 $A$ 同时以 $g$ 为前缀和后缀得 $A[t] = A[t+p]$（对所有 $t < \ell$），即 $A$ 以 $p$ 为周期。又 $2\ell > k_1 = \ell+p$ 给出 $\ell > p$，故对 $0 \le j < p$ 可反复使用周期性把下标一路减到 $j$，得 $A[\ell+j] = A[j]$，即 $A[\ell..k_1) = A[0..p)$。于是
  $$s[\ell..n-\ell) = A[\ell..k_1)\,C_2\cdots C_{k-1}\,A[0..p)$$
  是一个含 $k$ 块的合法分块，同样得到 $f(s) \ge 2 + k > k$，矛盾。

两种情形都与最优性矛盾，故 $k_1 = \ell$。∎

**引理 2（最优子结构）**：设 $\ell$ 为最小可配对长度且 $2\ell \le n$，记 $m = s[\ell..n-\ell)$，则 $f(s) = 2 + f(m)$；若不存在可配对长度，则 $f(s) = 1$。

**证明**：一方面，把 $m$ 的最优分块两侧各贴一块 $\text{text}[0..\ell)$，得到 $s$ 的合法分块，故 $f(s) \ge 2 + f(m)$。另一方面由引理 1，存在 $k = f(s)$ 块的合法分块且首末块长为 $\ell$，它的中间 $k-2$ 块正是 $m$ 的一个合法分块，故 $f(m) \ge k - 2$，即 $f(s) \le 2 + f(m)$，两向合并得 $f(s) = 2 + f(m)$。

若不存在可配对长度：假设存在 $k \ge 2$ 的合法分块，其首末两块等长且内容相等，则该长度 $\ell'$ 满足 $2\ell' \le n$ 且 $\text{text}[0..\ell') = \text{text}[n-\ell'..n)$，即存在可配对长度，矛盾；故 $f(s) = 1$。∎

**定理**：贪心算法输出的块数等于 $f(\text{text})$。

**证明**：对串长 $n$ 归纳。$n = 1$ 时不存在可配对长度，贪心输出 $1$，由引理 2 有 $f = 1$。

设 $n \ge 2$。若存在最小可配对长度 $\ell$（必有 $2\ell \le n$），贪心输出 $2 + \text{greedy}(m)$，其中 $|m| = n - 2\ell < n$，由归纳假设 $\text{greedy}(m) = f(m)$，再由引理 2 得贪心输出 $= 2 + f(m) = f(s)$。若不存在可配对长度，贪心输出 $1$，由引理 2 有 $f(s) = 1$。∎

## 6. 复杂度分析

- **时间（哈希版）**：预处理前缀哈希与幂表 $O(n)$。每轮 $L$ 从 $1$ 开始试：成功的一轮尝试 $L$ 次、消耗 $2L$ 个字符，故所有成功轮的尝试次数之和不超过 $n/2$；失败只可能发生在最后一轮，尝试次数不超过 $n/2$。每次判等 $O(1)$，逐字符确认的总开销不超过 $n/2$。整体 $O(n)$。
- **时间（朴素比较版）**：判等为 $O(L)$，最坏 $O(n^2)$；$n \le 1000$ 时上界约 $10^6$ 个字符比较，实测很快。
- **空间（哈希版）**：两套前缀哈希 + 两套幂表，共 $4(n+1)$ 个整数，$O(n)$；朴素比较版只需 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int longestDecomposition(string text) {
        int n = text.size();
        const long long M1 = 1000000007LL, M2 = 1000000009LL, B1 = 131, B2 = 137;
        vector<long long> h1(n + 1, 0), h2(n + 1, 0), p1(n + 1, 1), p2(n + 1, 1);
        for (int i = 0; i < n; i++) {
            long long v = text[i] - 'a' + 1;
            h1[i + 1] = (h1[i] * B1 + v) % M1;
            h2[i + 1] = (h2[i] * B2 + v) % M2;
            p1[i + 1] = p1[i] * B1 % M1;
            p2[i + 1] = p2[i] * B2 % M2;
        }
        // text[i..i+L) 与 text[j-L+1..j] 是否相等：双哈希过滤 + 逐字符确认
        auto eq = [&](int i, int j, int L) -> bool {
            long long a1 = (h1[i + L] - h1[i] * p1[L] % M1 + M1) % M1;
            long long a2 = (h2[i + L] - h2[i] * p2[L] % M2 + M2) % M2;
            long long b1 = (h1[j + 1] - h1[j - L + 1] * p1[L] % M1 + M1) % M1;
            long long b2 = (h2[j + 1] - h2[j - L + 1] * p2[L] % M2 + M2) % M2;
            if (a1 != b1 || a2 != b2) return false;
            return text.compare(i, L, text, j - L + 1, L) == 0;
        };

        int ans = 0, i = 0, j = n - 1;
        while (i <= j) {
            int L = 1;
            while (2 * L <= j - i + 1 && !eq(i, j, L)) L++;
            if (2 * L > j - i + 1) {   // 没有可配对的前后缀，剩余部分整体作为一块
                ans += 1;
                break;
            }
            ans += 2;
            i += L;
            j -= L;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def longestDecomposition(self, text: str) -> int:
        n = len(text)
        M1, M2, B1, B2 = 1000000007, 1000000009, 131, 137
        # 双模数前缀哈希（含幂表），任意子串 O(1) 取哈希
        h1, h2 = [0] * (n + 1), [0] * (n + 1)
        p1, p2 = [1] * (n + 1), [1] * (n + 1)
        for i in range(n):
            v = ord(text[i]) - 96
            h1[i + 1] = (h1[i] * B1 + v) % M1
            h2[i + 1] = (h2[i] * B2 + v) % M2
            p1[i + 1] = p1[i] * B1 % M1
            p2[i + 1] = p2[i] * B2 % M2

        def eq(i: int, j: int, L: int) -> bool:
            """text[i:i+L] 与 text[j-L+1:j+1] 是否相等：双哈希过滤，O(1)"""
            a1 = (h1[i + L] - h1[i] * p1[L]) % M1
            a2 = (h2[i + L] - h2[i] * p2[L]) % M2
            b1 = (h1[j + 1] - h1[j - L + 1] * p1[L]) % M1
            b2 = (h2[j + 1] - h2[j - L + 1] * p2[L]) % M2
            if a1 != b1 or a2 != b2:
                return False
            return text[i:i + L] == text[j - L + 1:j + 1]   # 逐字符确认

        ans, i, j = 0, 0, n - 1
        while i <= j:
            L = 1
            while 2 * L <= j - i + 1 and not eq(i, j, L):
                L += 1
            if 2 * L > j - i + 1:              # 找不到可配对的前后缀
                ans += 1                       # 中间剩余部分整体作为一块
                break
            ans += 2
            i += L
            j -= L
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：$i = j = 0$，`rem = 1`，$L$ 的上界 $\lfloor 1/2 \rfloor = 0$，一轮都配不上，直接 `ans = 1`。不要假设「至少能配一对」。
2. **奇数长度的中间块**：`"aaa"` 应为 3（`(a)(a)(a)`），最后一轮 `ans += 1` 不能漏；同时 `"aa"` 应为 2 而不是 3——中间为空时**不加**这一块，所以必须用「配不上才 +1」的写法，而不是「最后无条件 +1」。
3. **$L$ 的上界**：必须满足 $2L \le j-i+1$，否则同一段字符被当成左右两块，答案偏大（如 `"a"` 会错算成 2）。
4. **$L$ 必须从 $1$ 逐个往上试**：跳着试会漏掉最短匹配；从大往小试则会先吃掉长块，示例 3 只能得到 7 而不是 11。
5. **哈希方向**：两块都是正序子串，用同一套前缀哈希做区间查询即可；若引入反转串哈希，两边朝向必须一致——否则 `"abab"` 会把 `ab` 与 `ba` 判成不等，错答 1。
6. **别省逐字符确认**：省掉后正确性只剩概率意义，而一次确认才 $O(L)$，没有省的必要；另外 C++ 的负数取模必须 `+M`。
7. **全同字符串**（$1000$ 个 `a`）：每轮 $L = 1$，答案就是 $n$；哈希与幂表必须用 `long long`，`h[i] * p[L]` 最坏约 $10^{18}$，用 `int` 会溢出。
