# LeetCode 递减元素使数组呈锯齿状 题解

## 1. 题目概述

- **标题 / 题号**：递减元素使数组呈锯齿状（#1144，medium）
- **链接**：https://leetcode.cn/problems/decrease-elements-to-make-array-zigzag/
- **来源**：LeetCode 第 148 场周赛 Q1
- **难度**：中等
- **标签**：贪心，数组

**题意**：每次操作可以选一个元素把它**减 1**（不能加、不能一次减多）。称数组 $A$ 为锯齿数组，如果满足「偶数下标都是波峰」或「奇数下标都是波峰」之一，即

$$A[0] > A[1] < A[2] > A[3] < \cdots \quad\text{或}\quad A[0] < A[1] > A[2] < A[3] > \cdots$$

返回把 `nums` 变成锯齿数组所需的最小操作次数。

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $1 \le \text{nums}[i] \le 1000$
- 操作只能**减小**元素，且每次只减 1

> 💡 **关键约束带来强结构**：既然只能减，任何元素都不能变大；于是「让谁当波峰」比「把谁压低」更值得先决策。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]
输出：2
解释：把 2 递减到 0（2 次），得到 [1,0,3]，满足 A[0] > A[1] < A[2]；
      或者把 3 递减到 1（2 次），得到 [1,2,1]，同样满足。最少 2 次。
```

**示例 2**

```text
输入：nums = [9,6,1,6,2]
输出：4
解释：让奇数下标当波峰，只把 nums[0] 从 9 压到 5（4 次），得到 [5,6,1,6,2]：
      5 < 6 > 1 < 6 > 2，合法。
      若让偶数下标当波峰，则要把 nums[1]、nums[3] 都从 6 压到 0，共 12 次。
```

**补充示例（非官方样例）**

```text
输入：nums = [2,1]
输出：0
解释：2 > 1 已经是偶峰模式，无需操作。说明「两种模式」必须分别尝试，
      不能只看一种就下结论。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是对每个元素枚举它最终被减到多少，再做合法性检查。终态空间是 $\prod (\text{nums}[i]+1)$，指数级；改成 DP 后，状态为「前 $i$ 个元素的最后一个值 $v$」，转移要枚举相邻两个值：

$$dp[i][v] = \min_{u}\bigl(dp[i-1][u] + \text{nums}[i] - v\bigr),\quad \text{s.t. } (u, v) \text{ 满足相邻的大小关系}$$

状态数 $O(nV)$、转移 $O(V)$，取 $V = 1000$、$n = 1000$ 时约 $10^9$ 次操作，超时。这说明暴力「枚举终值」的粒度太细——很多枚举根本不可能出现在最优解里。

### 3.2 核心观察：只压低波谷，且各波谷代价独立

![锯齿数组的两种模式：偶峰与奇峰](images/wc148_q1_two_patterns.svg)

**观察一（模式互斥且穷尽）**：锯齿数组的定义就是「偶峰」或「奇峰」二者之一，因此只需分别求出两种模式下的最小成本再取 $\min$。两种模式覆盖了全部合法终态，答案不会被漏掉。

**观察二（波峰不动）**：在**固定模式**下，设波峰下标集合为 $P$、波谷下标集合为 $V$。约束只有「波谷严格小于两侧邻居」，而波峰之间从不比较。于是：

- 把波峰调小**只会让约束更紧**（波谷要更低），所以最优解中波峰保持原值；
- 波谷之间也从不比较，每个波谷只被它与相邻波峰的差约束，因此**各波谷的代价可以直接相加**。

**观察三（每个波谷的唯一最优目标值）**：波谷 $j$ 的邻居只有 $j-1$ 与 $j+1$（都存在时），它们都是波峰、都保持原值。令

$$m_j = \min\bigl(\text{nums}[j-1],\ \text{nums}[j+1]\bigr)$$

则必须把 $\text{nums}[j]$ 降到不超过 $m_j - 1$；降得刚好就够了（多降只增加成本）。单个波谷成本为

$$\text{cost}_j = \max\bigl(0,\ \text{nums}[j] - (m_j - 1)\bigr)$$

### 3.3 算法流程

![波谷的压低量与代价公式](images/wc148_q1_greedy_valley.svg)

对两种模式各扫一遍，每个模式只处理「奇偶性与波峰相反」的下标：

```text
ans ← +∞
for peak in {0, 1}:                       # 波峰的奇偶性
    cost ← 0
    for j from (1 - peak) step 2 while j < n:    # 枚举波谷
        m ← +∞
        if j > 0:        m ← min(m, nums[j-1])   # 左邻居（必为波峰）
        if j + 1 < n:    m ← min(m, nums[j+1])   # 右邻居（必为波峰）
        if nums[j] >= m: cost ← cost + nums[j] - m + 1
    ans ← min(ans, cost)
return ans
```

- **循环起点**：偶峰（`peak = 0`）时波谷是奇数下标，从 1 开始；奇峰时波谷是偶数下标，从 0 开始。步长恒为 2。
- **单邻居**：端点处的波谷只有一侧邻居，$m$ 就取那一个值；$n = 1$ 时没有任何波谷，成本为 0。
- **不做负贡献**：$\text{nums}[j] < m$ 时已经合法，成本记 0，绝不能把负数累加进去。

### 3.4 示例演算

![示例 nums = [9,6,1,6,2] 的两种模式代价对比](images/wc148_q1_walkthrough.svg)

对 `nums = [9,6,1,6,2]`（$n = 5$）逐波谷计算：

| 模式 | 波谷 $j$ | 邻居 | $m_j$ | 目标 $m_j-1$ | 成本 |
|------|----------|------|-------|--------------|------|
| 偶峰（0/2/4 是峰） | 1 | 9, 1 | 1 | 0 | 6 |
| 偶峰（0/2/4 是峰） | 3 | 1, 2 | 1 | 0 | 6 |
| 奇峰（1/3 是峰） | 0 | 6 | 6 | 5 | 4 |
| 奇峰（1/3 是峰） | 2 | 6, 6 | 6 | 5 | 0 |
| 奇峰（1/3 是峰） | 4 | 6 | 6 | 5 | 0 |

偶峰小计 $6 + 6 = 12$，奇峰小计 $4 + 0 + 0 = 4$，答案 $\min(12, 4) = 4$。终态为 `[5,6,1,6,2]`，确实满足 $5 < 6 > 1 < 6 > 2$。

再对 `nums = [1,2,3]`：偶峰时波谷只有 $j = 1$，$m = \min(1,3) = 1$，成本 $2$；奇峰时波谷为 $0$（$m = 2$，成本 $0$）与 $2$（$m = 2$，成本 $2$），小计 $2$。两种模式都得 2，答案 2，与官方解释一致（把 2 降到 0，或把 3 降到 1）。

## 4. 算法细节

1. **先定模式，再定数值**：模式 `peak ∈ {0, 1}` 只有两种。枚举它、把「波峰奇偶性」变成常量后，每个元素的角色（峰/谷）就被唯一确定，这是把搜索问题化为计数问题的关键一步。
2. **波谷下标用步长 2 枚举**：`for (j = 1 - peak; j < n; j += 2)`，一次到位，不需要额外的 `if (i % 2 == ...)` 判断，也避免了下标奇偶写反的常见错误。
3. **$m$ 的哨兵值只用于初始化**：C++ 用 `INT_MAX`、Python 用 `float('inf')` 表示「该侧没有邻居」；但它们绝不能参与 `nums[j] - m + 1` 的运算，因此在用之前要么先判断 `m != INT_MAX`，要么把 `nums[j] >= m` 作为守卫（$m = +\infty$ 时该条件恒假，天然跳过）。
4. **成本只累加正值**：$\text{cost} \mathrel{+}= \max(0, \text{nums}[j] - m + 1)$。写成 `cost += nums[j] - m + 1` 而漏掉守卫，会在「波谷本来就够小」时把负值加进答案，这是本题最高频的 WA 原因。
5. **不需要真的修改数组**：波谷的邻居全是波峰，而波峰永远不动，所以压低某个波谷不会改变别的波谷读到的 $m_j$。既省去写回，也避免「先改后读」导致 $m_j$ 被污染。
6. **成本量级**：$n \le 1000$、$\text{nums}[i] \le 1000$，单次压低最坏 $1000$，总数不超过约 $500 \times 1000 = 5\times10^5$，`int` 足够；但哨兵用了 `INT_MAX`，就不能对它做算术。
7. **两模式对称但不相等**：两种模式的波谷集合大小最多差 1，成本却可能相差数倍（示例 2 中 12 与 4），必须都算。
8. **零额外空间**：只需常数个计数器，天然 $O(1)$ 辅助空间。

## 5. 正确性证明

**引理 1（波谷的取值范围）**：固定模式后设 $P$ 为波峰集合、$V$ 为波谷集合。若终态 $B$ 是锯齿数组且 $B[i] \le \text{nums}[i]$，则对每个 $j \in V$ 有

$$B[j] \le m_j - 1,\qquad m_j = \min_{i \in \{j-1, j+1\},\, 0 \le i < n} \text{nums}[i].$$

**证明**：$j \in V$ 时其每个存在的邻居 $i$ 都属于 $P$（下标奇偶性相反），锯齿条件要求 $B[j] < B[i]$，而 $B[i] \le \text{nums}[i]$，故对每个邻居 $i$ 都有 $B[j] < \text{nums}[i]$。整数意义下 $B[j] \le \text{nums}[i] - 1$ 对每个邻居成立，对邻居取最小即得 $B[j] \le m_j - 1$。∎

**引理 2（成本下界）**：任何把 `nums` 变成该模式锯齿数组的方案，操作次数至少为 $\sum_{j \in V} \max\bigl(0,\ \text{nums}[j] - m_j + 1\bigr)$。

**证明**：设终态为 $B$，则总操作次数 $=\sum_{i}\bigl(\text{nums}[i] - B[i]\bigr)$（只能减，减了几次就是几）。由于 $B[i] \le \text{nums}[i]$，每项非负，故和式不小于只取波谷的那部分 $\sum_{j \in V}\bigl(\text{nums}[j] - B[j]\bigr)$。由引理 1，$B[j] \le m_j - 1$，于是 $\text{nums}[j] - B[j] \ge \text{nums}[j] - m_j + 1$；又 $\text{nums}[j] - B[j] \ge 0$，两者取大仍成立，即 $\text{nums}[j] - B[j] \ge \max(0, \text{nums}[j] - m_j + 1)$。对 $j \in V$ 求和即得下界。∎

**引理 3（下界可达）**：令 $T[i] = \text{nums}[i]\ (i \in P)$，$T[j] = \min\bigl(\text{nums}[j],\ m_j - 1\bigr)\ (j \in V)$，则 $T$ 是该模式的锯齿数组，且把 `nums` 变成 $T$ 恰好需要 $\sum_{j \in V}\max(0, \text{nums}[j] - m_j + 1)$ 次操作。

**证明**：对任意 $j \in V$ 及其存在的邻居 $i \in P$，有 $T[i] = \text{nums}[i] \ge m_j > m_j - 1 \ge T[j]$，即 $T[j] < T[i]$，锯齿条件成立。操作次数 $=\sum_i (\text{nums}[i] - T[i]) = \sum_{j \in V}(\text{nums}[j] - T[j])$（波峰不变），而 $\text{nums}[j] - \min(\text{nums}[j], m_j - 1) = \max(0, \text{nums}[j] - m_j + 1)$，故总次数恰为下界。∎

**定理**：算法返回的 `ans` 是题目要求的最小操作次数。

**证明**：锯齿数组的定义把合法终态分成偶峰、奇峰两类。对固定模式，引理 2 给出下界、引理 3 说明下界可达，因此该模式的最优值恰为算法算出的 `cost`；算法对两种模式都计算后取 $\min$，得到两类中的较小者。由于合法终态必属某一类（$n = 1$ 时两类都平凡成立、成本为 0），$\min$ 就是全局最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层只有 2 种模式；内层对每个模式各扫约 $n/2$ 个波谷，每个波谷只做常数次比较与加法，两次扫描合计 $\le n$ 次迭代。
- **空间**：$O(1)$ 辅助空间（`ans`、`cost`、`m` 三个标量），不计输入与返回值。
- **对比暴力 DP**：枚举终值的 DP 需 $O(nV^2) \approx 10^9$，而贪心把它降到 $O(n)$——差距来自「波峰不动 + 波谷互不干扰」这一结构。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>
using namespace std;

class Solution {
public:
    int movesToMakeZigzag(vector<int>& nums) {
        int n = nums.size();
        int ans = INT_MAX;
        for (int peak = 0; peak < 2; ++peak) {   // peak: 波峰下标的奇偶性
            int cost = 0;
            for (int j = 1 - peak; j < n; j += 2) {  // j 是波谷
                int m = INT_MAX;
                if (j > 0) m = min(m, nums[j - 1]);      // 左邻居（波峰）
                if (j + 1 < n) m = min(m, nums[j + 1]);  // 右邻居（波峰）
                if (m != INT_MAX && nums[j] >= m) {
                    cost += nums[j] - m + 1;             // 压到 m-1
                }
            }
            ans = min(ans, cost);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def movesToMakeZigzag(self, nums: list[int]) -> int:
        n = len(nums)
        INF = float('inf')
        ans = INF
        for peak in (0, 1):                    # 波峰下标的奇偶性
            cost = 0
            for j in range(1 - peak, n, 2):    # j 是波谷
                m = min(nums[j - 1] if j > 0 else INF,
                        nums[j + 1] if j + 1 < n else INF)
                if nums[j] >= m:               # m 为 INF 时条件自然为假
                    cost += nums[j] - m + 1
            ans = min(ans, cost)
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：没有任何相邻关系，两种模式都没有波谷，成本为 0。此时不能因为「波谷集合为空」就把 `ans` 留在无穷大——两种模式各贡献 0，`min` 自然得到 0，代码无需特判。
2. **$n = 2$**：例如 `[2,1]` 已是偶峰，答案 0；`[1,1]` 必须把某一个减 1 才能严格不等，答案 1。两元素数组的答案就是 $\min\bigl(\max(0, a-b+1),\ \max(0, b-a+1)\bigr)$，可用于手测。
3. **端点波谷只有一个邻居**：不要用 `0` 或 `nums[0]` 之类的默认值去补空邻居，否则 $m$ 会被错误地压小、成本虚高。正确做法是用 $+\infty$ 作哨兵并按守卫跳过。
4. **漏写 `nums[j] >= m` 守卫**：会累加负值，答案偏小。这是本题最常见的错误，务必写成 `cost += max(0, nums[j] - m + 1)`。
5. **哨兵参与算术**：C++ 中 `nums[j] - INT_MAX + 1` 会下溢成负数，必须先判 `m != INT_MAX`（或像 Python 版那样依赖 `nums[j] >= inf` 恒假）。
6. **只算一种模式**：`[9,6,1,6,2]` 两种模式成本 12 与 4，只算一种必错；必须两种都算再取小。
7. **误以为要修改数组**：本题不需要写回，也不该在遍历时修改 `nums`；一旦写回，若后续把被改过的值当邻居读取，$m_j$ 就被污染（本题恰好安全，但换成「差至少 $k$」的变体就会出错）。
8. **奇偶写反**：偶峰模式下**波谷**是奇数下标，别把「波峰奇偶性」直接当成「要枚举的下标奇偶性」；`j` 从 `1 - peak` 开始正是为此。

**延伸思考**：

1. 若把「差至少 1」改成「差至少 $k$」，只需把目标值 $m_j - 1$ 换成 $m_j - k$，成本公式变为 $\max(0, \text{nums}[j] - m_j + k)$，算法结构完全不变——说明本题的贪心对「阈值型」约束是稳健的。
2. 若允许**加**也允许减，波峰就可能被抬高而不是压低，成本变为两侧代价的权衡，逐项独立不再成立；此时需要枚举终态值域的 DP（$O(nV)$，用前缀最小值优化到 $O(nV)$ 甚至 $O(n)$）。
3. 若数组首尾相接（环形锯齿），相邻关系多了一条 $(n-1, 0)$，两种模式变成「首尾约束耦合」的情形：固定 $A[0]$ 的最终值后其余仍可贪心，于是需要枚举 $A[0]$ 的目标值，复杂度升到 $O(nV)$。
4. 若要求输出具体方案，按引理 3 的构造 $T[j] = \min(\text{nums}[j], m_j - 1)$ 直接改即可，无需第二遍搜索。
