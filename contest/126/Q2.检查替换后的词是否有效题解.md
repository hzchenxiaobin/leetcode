# LeetCode 检查替换后的词是否有效 题解

## 1. 题目概述

- **标题 / 题号**：检查替换后的词是否有效（#1003，medium）
- **链接**：https://leetcode.cn/problems/check-if-word-is-valid-after-substitutions/
- **来源**：LeetCode 第 126 场周赛 Q2
- **难度**：中等
- **标签**：栈、字符串

**题意**：从空串 `t = ""` 出发，可以**任意次**把 `"abc"` 插入到 `t` 的任意位置，得到新串。给定 `s`，判断它能否由这种方式生成。

等价地说：`s` 有效 $\iff$ 存在一个「**不断删除子串 `"abc"`**」的过程，能把 `s` 删成空串。

**约束**：

- $1 \le s.length \le 2 \times 10^4$
- `s` 只含 `'a'`、`'b'`、`'c'`

## 2. 示例

**示例 1**

```text
输入：s = "aabcbc"
输出：true
解释："" -> "abc" -> "a" + "abc" + "bc" = "aabcbc"
```

**示例 2**

```text
输入：s = "abcabcababcc"
输出：true
解释："" -> "abc" -> "abcabc" -> "abcabcabc" -> 在中间插入 -> "abcabcababcc"
```

**示例 3**

```text
输入：s = "abccba"
输出：false
解释：长度虽然是 6 的倍数，但无论怎么删 "abc" 都删不空。
```

**示例 4**

```text
输入：s = "abc"
输出：true
解释：只插入一次。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：反复在 `s` 中找一个子串 `"abc"` 删掉，直到删不动为止，再看是否为空。

- 每删除一次长度减少 3，最多删 $n/3$ 次；
- 每次查找 `"abc"` 若用 `std::string::find` 加 `erase`，单次 $O(n)$，总计 $O(n^2)$。

$n = 2 \times 10^4$ 时 $n^2 = 4 \times 10^8$，已经贴着时限甚至超时。而且这个暴力隐含了一个必须证明的假设：**删除顺序不影响最终是否为空**——如果不同删除顺序能得到不同结果，那「随便删」就是错的。

### 3.2 核心观察：删除 `"abc"` 的归约系统是合流的

![有效串的生成与删除：插入 abc 与删除 abc 互为逆操作](images/wc126_q2_stack_concept.svg)

把「插入 `"abc"`」倒过来看，就是「删除一个子串 `"abc"`」。生成与删除互为逆操作，因此：

$$s \text{ 有效} \iff s \text{ 能通过反复删除 } "abc" \text{ 变成空串}$$

这个等价本身很直观，但要支撑「随便删」的算法，需要两条性质：

1. **终止性**：每次删除长度减少 3，必然停机。
2. **合流性**：任意两个可删除的 `"abc"` 子串，起点不可能相邻，因此两个删除动作要么互不重叠、可以交换次序，要么就是同一处。于是**删除顺序不影响归约终态**（若某顺序能删空，任何顺序都能删空）。

既然顺序无关，就可以选最方便的顺序——**从左到右、见到 `"abc"` 就删**。而这恰好可以用一个**栈**在 $O(n)$ 内完成：边读边压栈，一旦栈顶三个字符是 `a`、`b`、`c`，立刻弹出，相当于「就地删除」。

为什么栈能替代「回退删除」？因为扫描到位置 $i$ 时，栈里保存的是**前缀 $s[0..i]$ 的归约终态（不含 `"abc"` 的规范形）**。若新字符恰好补在栈顶的 `a`、`b` 之后，这三个字符就构成一个此刻最靠左的可删除块，直接弹出即可；不会存在「先不删、等后面再删更优」的情况——合流性保证早晚都等价。

### 3.3 算法流程

![算法流程：压栈 + 检查栈顶三字符](images/wc126_q2_flow.svg)

```text
1. st = 空栈
2. for ch in s:
       st.push(ch)
       若 |st| >= 3 且 st[-3..] == "abc":
           st.pop() 三次
3. 返回 st 是否为空
```

栈用 `std::string` 充当即可：`push_back` / `pop_back` 都是 $O(1)$ 均摊。

### 3.4 示例演算

![示例演算：s = "abcabcababcc" 的栈变化过程](images/wc126_q2_walkthrough.svg)

以示例 2 的 `s = "abcabcababcc"` 为例（`|·|` 表示栈内容）：

| 读入 | 栈（弹栈后） | 说明 |
|---|---|---|
| a | a | |
| b | ab | |
| c | （空） | 栈顶凑成 abc，弹出 |
| a | a | |
| b | ab | |
| c | （空） | 再弹一次 |
| a | a | |
| b | ab | |
| a | aba | 不构成 abc |
| b | abab | |
| c | ab | 弹出末尾 abc，剩 ab |
| c | abc | |
| — | （空） | 最后三字符 abc 弹出 → 空 |

最终栈空，返回 `true` ✓。

再看示例 3 的 `"abccba"`：读到 `a`、`b`、`c` 后弹出，栈空；接着读 `c`、`b`、`a`，栈为 `cba`，永远凑不出 `abc`，返回 `false` ✓。

## 4. 算法细节

1. **用字符串当栈**：`string st` 的 `push_back` / `pop_back` 比 `vector<char>` 更省心，且可以直接用 `st.compare(st.size()-3, 3, "abc") == 0` 判断栈顶。
2. **先判长度再取栈顶**：`st.size() >= 3` 必须在访问 `st[size-3]` 之前判断，否则 `size()` 是无符号数，减法会下溢成巨大的值。
3. **只需判一次**：压入一个字符后，最多只能新形成一个可删除块（位置固定在栈顶），不必循环弹出。
4. **长度快速剪枝**：若 `s.size() % 3 != 0` 直接返回 `false`；这是 $O(1)$ 的早退，虽然栈算法本身也能得出同样结论。
5. **Python 用 list**：`st.append` / `st.pop` 均摊 $O(1)$；判断 `st[-3:] == ['a','b','c']`。
6. **不要用 `replace("abc","")` 反复替换**：每轮都要重建字符串，最坏 $O(n^2)$；`str::find` + `erase` 也是同样问题。

## 5. 正确性证明

先固定两个概念：称 `s` **可归约到空** 指存在删除序列把它删空；称串 `u` 是 **规范形** 指 `u` 中不含子串 `"abc"`。

**引理 1（删除不会制造新串）**：删除一个 `"abc"` 后得到的串，是原串的子序列；且原串长度为 3 的倍数当且仅当结果串长度也是 3 的倍数。

**证明**：删除只去掉三个连续字符，剩下的是原串的子序列。长度减少 3，故模 3 的余数不变。∎

**引理 2（两个可删除块互不重叠）**：若 `s` 中位置 $i$ 与位置 $j > i$ 都是 `"abc"` 的起点，则 $j - i \ge 3$。

**证明**：若 $j = i + 1$，则由 $s[i..i+2] = \text{"abc"}$ 得 $s[i+1] = \text{'b'}$，而由 $s[i+1..i+3] = \text{"abc"}$ 得 $s[i+1] = \text{'a'}$，矛盾。若 $j = i + 2$，则由前者得 $s[i+2] = \text{'c'}$，由后者得 $s[i+2] = \text{'a'}$，矛盾。故 $j - i \ge 3$。∎

**引理 3（合流性）**：若 `s` 中有两处可删除的 `"abc"`，先删任一处，两个结果再各自归约，最终得到同一个规范形。

**证明**：由引理 2，两处删除区间 $[i, i+2]$ 与 $[j, j+2]$ 不相交，两个删除动作作用在互不相交的位置上，交换次序结果相同（删除操作对区间外字符只做位置平移，不改变相对顺序）。因此任意删除序列都可以重排成任意其它顺序，归约终态唯一。∎

**引理 4（栈内容 = 前缀的规范形）**：处理完前缀 $s[0..i]$ 后，栈中内容等于该前缀反复删除 `"abc"` 后得到的规范形。

**证明**：对 $i$ 归纳。$i = -1$ 时栈空，规范形为空。设处理完 $s[0..i-1]$ 后栈内容 $T$ 是前缀的规范形。读入 $ch = s[i]$：

- 若 $T$ 末尾不是 `"ab"` 或 $ch$ 不是 `'c'`：新前缀的规范形就是 $T + ch$。因为 $T$ 不含 `"abc"`，唯一可能新出现的 `"abc"` 只能以 $ch$ 结尾，而该情况已被排除。
- 若 $T$ 以 `"ab"` 结尾且 $ch = \text{'c'}$：$T + ch$ 的末尾是 `"abc"`，删除它得到 $T' = T$ 去掉末尾两个字符。由于 $T$ 无 `"abc"`，$T'$ 也无 `"abc"`；并且由引理 3，先删这一处再归约与任何其它顺序等价，故 $T'$ 就是新前缀的规范形。

两种情形都与算法的弹栈行为一致，归纳成立。∎

**定理**：算法返回 `true` 当且仅当 `s` 有效。

**证明**：

- （$\Leftarrow$）若 `s` 有效，则存在插入序列把它从空串生成。对插入次数归纳可证 `s` 可归约到空：最后一次插入是在某个有效串 $t$ 中插入一块 `"abc"`，$s$ 中因此存在 `"abc"`，删掉它得到 $t$，由归纳假设 $t$ 可归约到空，故 `s` 也可。于是 `s` 的规范形为空；由引理 4 栈内容就是规范形，故最终栈空，返回 `true`。
- （$\Rightarrow$）若算法返回 `true`，则栈空，即 $s$ 的规范形为空，说明存在删除序列把 `s` 删空。把该删除序列倒序执行，就是把 `"abc"` 逐块插回的过程，从空串生成 `s`，故 `s` 有效。

（注意引理 3 保证「规范形」定义良好，否则「$s$ 的规范形」一语无意义。）∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符入栈一次、至多出栈一次；栈顶判断是 $O(1)$ 的常数次字符比较。`s.size() % 3` 的早退是 $O(1)$。
- **空间**：$O(n)$。栈最坏保存整个串（例如 `s = "aaaa...bbb...ccc"` 的前半段）。
- 若改用「反复 `find` + `erase`」：时间 $O(n^2)$、额外空间 $O(1)$，是本题的主要超时陷阱。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isValid(string s) {
        if (s.size() % 3 != 0) return false;
        string st;
        st.reserve(s.size());
        for (char ch : s) {
            st.push_back(ch);
            if (st.size() >= 3 && st[st.size() - 3] == 'a' &&
                st[st.size() - 2] == 'b' && st[st.size() - 1] == 'c') {
                st.pop_back();
                st.pop_back();
                st.pop_back();
            }
        }
        return st.empty();
    }
};
```

### Python

```python
class Solution:
    def isValid(self, s: str) -> bool:
        if len(s) % 3 != 0:
            return False
        st = []
        for ch in s:
            st.append(ch)
            if len(st) >= 3 and st[-3] == 'a' and st[-2] == 'b' and st[-1] == 'c':
                st.pop()
                st.pop()
                st.pop()
        return not st
```

## 8. 边界情况与易错点

1. **长度不是 3 的倍数**：如 `"ab"`、`"abca"`，必然无效，提前返回 `false` 可省一次扫描。
2. **空栈取栈顶**：`st.size() - 3` 在 `size_t` 下会下溢，务必先判 `st.size() >= 3`。
3. **`"abc"` 出现在开头/中间/结尾**：栈算法对三种位置一视同仁，因为它们都会在「读到该块最后一个字符」的瞬间被弹出。
4. **误以为「a、b、c 数量相等」就有效**：`"abccba"` 三类字符各 2 个，但无效。数量相等只是必要条件。
5. **误以为「任意前缀中 a 的个数 ≥ b 的个数 ≥ c 的个数」就充分**：`"aabbcc"` 满足该单调性，但它无法生成（`"abc"` 只能成块插入）。必须用栈/删除来判定。
6. **删除顺序的迷思**：不能想当然地「先删哪块都行」而不加证明——本题恰好奇妙地满足合流性；若把 `"abc"` 换成 `"aba"` 之类的模式，合流性就可能失效。
7. **递归写法爆栈**：用递归「找 `"abc"` → 删 → 递归」在 $n = 2\times10^4$、串形如 `"abcabcabc..."` 时递归深度可达 $n/3 \approx 6667$，虽然通常不爆，但没必要冒险。
