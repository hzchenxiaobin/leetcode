# LeetCode 合并石头的最低成本 题解

## 1. 题目概述

- **标题 / 题号**：合并石头的最低成本（#1000，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-merge-stones/
- **来源**：LeetCode 第 126 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、前缀和

**题意**：$n$ 堆石头排成一排，第 $i$ 堆有 `stones[i]` 块。每次移动必须把**连续的 $k$ 堆**合并成**一堆**，成本为这 $k$ 堆石头总数。求把所有石头合并成一堆的最小总成本；无法合并成一堆时返回 $-1$。

**约束**：

- $1 \le n \le 30$
- $1 \le stones[i] \le 100$
- $2 \le k \le 30$

> 💡 注意「连续 $k$ 堆」是硬约束：不是任意挑选 $k$ 堆（那就退化成 Huffman 编码）。这一条把问题从贪心拉到了区间 DP。

## 2. 示例

**示例 1**

```text
输入：stones = [3,2,4,1], k = 2
输出：20
解释：合并 [3,2] 成本 5 → [5,4,1]
      合并 [4,1] 成本 5 → [5,5]
      合并 [5,5] 成本 10 → [10]
      总成本 20，最小。
```

**示例 2**

```text
输入：stones = [3,2,4,1], k = 3
输出：-1
解释：4 堆每次减 2 堆，只能到 2 堆，无法变成 1 堆。
```

**示例 3**

```text
输入：stones = [3,5,1,2,6], k = 3
输出：25
解释：合并 [5,1,2] 成本 8 → [3,8,6]
      合并 [3,8,6] 成本 17 → [17]
      总成本 25。
```

**示例 4**

```text
输入：stones = [1], k = 2
输出：0
解释：本来就只有一堆，不需要任何操作。
```

## 3. 解题思路

### 3.1 暴力思路

直接搜索所有合并顺序：每一步枚举 $O(n)$ 个可合并的连续 $k$ 段，深度为 $(n-1)/(k-1)$，最坏复杂度是指数级的（$n=30$ 时完全不可行）。

一个自然的「改进」是枚举区间分割：把区间 $[i,j]$ 分成左右两半，分别合并后再合并——但如果**不做状态约束**，这种枚举会产生大量无用状态：

- 左右两半各自合并成几堆？如果不管，就要记录「合并成 $p$ 堆」的维度；
- 而最终要合成一堆，最后一次合并必须吃下恰好 $k$ 堆，这要求左半是 $1$ 堆、右半是 $k-1$ 堆（或其它拆分）。

关键洞察是：**一个区间能合并成的堆数并不是任意的**，它被长度模 $k-1$ 的余数完全钉死。抓住这一点，状态可以从「$p$ 堆」压缩掉。

### 3.2 核心观察：堆数由长度模 $k-1$ 唯一确定

![每次合并减少 k−1 堆，因此堆数由区间长度模 k−1 决定](images/wc126_q4_dp_state.svg)

一次合并把 $k$ 堆变成 $1$ 堆，**堆数净减 $k-1$**。设区间长度 $\ell = j - i + 1$，把它合并到若干堆，最终堆数 $p$ 必满足

$$p \equiv \ell \pmod{k-1}, \qquad 1 \le p \le \ell$$

而在所有可达到的堆数里，**最小**的那个是

$$p_{\min}(\ell) = (\ell - 1) \bmod (k-1) + 1$$

（$\ell \le k$ 时 $p_{\min} = \ell$，一堆都合不动；$\ell = k$ 时 $p_{\min} = 1$。）

于是定义状态：

$$dp[i][j] = \text{把 } stones[i..j] \text{ 合并成 } p_{\min}(j-i+1) \text{ 堆的最小成本}$$

这个状态是**自洽**的，因为「合并到最小堆数」的过程可以自顶向下分解：

- 最终若是 $1$ 堆（即 $(j-i) \bmod (k-1) = 0$），最后一次合并吃下 $k$ 堆，其中最左那一堆由某个前缀 $[i, m]$ 合并而成，且该前缀被合并成 **1 堆**（所以 $m - i$ 必是 $k-1$ 的倍数）；剩下的 $[m+1, j]$ 被合并成 **$k-1$ 堆**，而 $k-1$ 恰好就是 $[m+1,j]$ 的最小堆数（可由上面的同余关系验证）。
- 若最终不是 $1$ 堆，则不存在「最后一次合并」，$dp[i][j]$ 就是把区间拆成若干块、各自合并到最小堆数的最小成本，同样可以枚举第一块的分割点。

由此得到转移：

$$dp[i][j] = \min_{m \in \{i,\, i+(k-1),\, i+2(k-1),\, \dots,\, < j\}} \bigl(dp[i][m] + dp[m+1][j]\bigr)$$

若 $(j-i) \bmod (k-1) = 0$，再补上把当前 $k$ 堆合成一堆的成本：

$$dp[i][j] \mathrel{+}= \sum_{t=i}^{j} stones[t]$$

区间和用前缀和 $O(1)$ 取出。

**为什么分割点只能以 $k-1$ 为步长？** 因为左块 $[i,m]$ 必须恰好合并成 1 堆，而这只在 $(m-i) \bmod (k-1) = 0$ 时可能——这正是「堆数由长度模 $k-1$ 决定」的直接推论。

### 3.3 算法流程

![算法流程：可行性判定 + 按区间长度递增的区间 DP](images/wc126_q4_flow.svg)

```text
1. 若 n == 1：返回 0
2. 若 (n-1) % (k-1) != 0：返回 -1
3. 前缀和 pre[0..n]
4. dp[i][i] = 0
5. for len = 2 .. n:
       for i = 0 .. n-len:
           j = i + len - 1
           dp[i][j] = min over m = i, i+k-1, ... < j of (dp[i][m] + dp[m+1][j])
           若 (j - i) % (k-1) == 0：dp[i][j] += pre[j+1] - pre[i]
6. 返回 dp[0][n-1]
```

按区间长度**从小到大**枚举，保证转移时用到的子区间（长度更小）都已算好。

### 3.4 示例演算

![示例演算：k = 2 时的 dp 三角表](images/wc126_q4_walkthrough.svg)

对示例 1 的 `stones = [3,2,4,1]`、`k = 2`（此时 $k-1 = 1$，任何分割点都允许，且每个长度都满足 $(j-i) \bmod 1 = 0$，即每个区间都要合成 1 堆）：

| 区间 | 长度 | 候选分割 | 最小子代价 | 区间和 | $dp$ |
|---|---|---|---|---|---|
| [0,0] | 1 | — | — | — | 0 |
| [0,1] | 2 | m=0 | 0 | 3+2=5 | 5 |
| [1,2] | 2 | m=1 | 0 | 2+4=6 | 6 |
| [2,3] | 2 | m=2 | 0 | 4+1=5 | 5 |
| [0,2] | 3 | m=0: 0+6=6；m=1: 5+0=5 | 5 | 9 | 14 |
| [1,3] | 3 | m=1: 0+5=5；m=2: 6+0=6 | 5 | 7 | 12 |
| [0,3] | 4 | m=0: 0+12=12；m=1: 5+5=10；m=2: 14+0=14 | 10 | 10 | **20** |

$dp[0][3] = 20$ ✓，对应方案：先把 `[3,2]` 合成 5、`[4,1]` 合成 5，再把两个 5 合成 10，成本 $5+5+10 = 20$。

再看示例 3 的 `[3,5,1,2,6]`、`k = 3`：$(5-1) \bmod 2 = 0$，可行。最优先把 `[5,1,2]` 合成 8（成本 8），数组变 `[3,8,6]`，再合成 17，总成本 $8 + 17 = 25$ ✓。在 DP 里它对应 $dp[0][4] = \min(dp[0][0]+dp[1][4],\ dp[0][2]+dp[3][4]) + 15$，其中 $dp[1][4]$ 内部再拆出 $[1,3]$ 这一段。

## 4. 算法细节

1. **可行性先判**：$(n-1) \bmod (k-1) \neq 0$ 时直接 $-1$，避免 DP 里出现大量无穷大状态。$n = 1$ 是唯一 $(n-1) = 0$ 的特例，返回 0。
2. **前缀和**：`pre[t] = stones[0..t-1]` 之和，区间和 `pre[j+1] - pre[i]`，$O(1)$。
3. **分割步长**：`for (int m = i; m < j; m += k - 1)`。注意 `k = 2` 时步长为 1（退化成矩阵链的枚举）；`k` 很大时枚举量急剧下降。
4. **加成本的位置**：`sum` 只在「该区间最终合成 1 堆」时加一次，即 $(j-i) \bmod (k-1) = 0$。这一笔正是最后一次合并的成本。
5. **无穷大与溢出**：区间和上界 $30 \times 100 = 3000$，合并次数上界 $29$，答案不超过 $8.7 \times 10^4$，`int` 足够；但 `dp` 用 `long long` 与 `LLONG_MAX/4` 做哨兵更稳妥，避免加法溢出。
6. **循环顺序**：外层枚举长度、内层枚举起点。若外层枚举起点、内层枚举终点，会用到尚未计算的更长区间，必须改成「按长度」。
7. **Python 的 `float('inf')`**：与整数相加不报错，但返回时要转 `int`；本题可用大整数 `10**18` 代替。
8. **不要试图贪心**：每次合并「当前和最小的连续 $k$ 堆」在 $k = 2$ 时就是 Huffman，但在「必须连续」的约束下贪心不最优——示例 3 中先合并 `[5,1,2]`（和 8）而不是 `[3,5,1]`（和 9），说明局部选择会影响全局。

## 5. 正确性证明

记 $S(i,j) = \sum_{t=i}^{j} stones[t]$，$p_{\min}(\ell)$ 如上定义。

**引理 1（堆数同余）**：把长度 $\ell$ 的区间合并成 $p$ 堆（$p \ge 1$），则 $p \equiv \ell \pmod{k-1}$；反之该同余类中所有 $1 \le p \le \ell$ 的堆数都可达。

**证明**：每次合并把堆数从 $q$ 变成 $q - (k-1)$，故堆数模 $k-1$ 不变，初始为 $\ell$。反之，反复合并任意前 $k$ 堆即可把堆数一路降到 $\ell - t(k-1)$，直到小于 $k$ 为止；只需 $\ell \ge k$ 时才有操作可做，故可达集合恰为 $\{\ell, \ell-(k-1), \dots, p_{\min}(\ell)\}$。∎

**引理 2（可行性）**：能把 $n$ 堆合成 1 堆 $\iff n = 1$ 或 $(n-1) \bmod (k-1) = 0$。

**证明**：必要性由引理 1 取 $p = 1$ 得 $(n-1) \equiv 0$。充分性：若 $n > 1$ 且 $(n-1) = t(k-1)$，对 $t$ 归纳——合并最左边 $k$ 堆后堆数变为 $n - k + 1$，其减一为 $(t-1)(k-1)$，由归纳假设可继续合并成一堆。∎

**引理 3（分割完备性）**：设 $(j-i) \bmod (k-1) = 0$，则任一「把 $[i,j]$ 合并成 1 堆」的方案，其最后一次合并所吃的 $k$ 堆中，最左一堆必由某个 $[i,m]$ 合并而成，$m-i \equiv 0 \pmod{k-1}$，其余 $k-1$ 堆恰由 $[m+1,j]$ 合并而成，且该方案成本 $\ge dp[i][m] + dp[m+1][j] + S(i,j)$。

**证明**：合并操作的区间是连续的，且一旦合并，被合并的堆在后续过程中始终相邻；因此「最后一次合并的最左一堆」所覆盖的原始下标必然是 $[i, m]$ 形式的前缀（它包含 $i$，否则 $i$ 无法进入最终那一堆）。该前缀被合并成 1 堆，由引理 1 得 $m - i \equiv 0 \pmod{k-1}$。同理，剩余的 $k-1$ 堆是由后缀 $[m+1,j]$ 合并成 $k-1$ 堆得到的，而 $k-1 = p_{\min}(j-m)$（因为 $j-m \equiv 0$ 且 $j-m \ge k-1$）。子区间的操作互不干扰，成本可加，故总成本 $\ge$ 子区间各自的最优成本之和 $+ S(i,j)$。∎

**引理 4（无最终合并情形的分解）**：若 $(j-i) \bmod (k-1) \neq 0$，则把 $[i,j]$ 合并到最小堆数的方案可分解为「把 $[i,m]$ 合并成 1 堆」与「把 $[m+1,j]$ 合并到最小堆数」两段，成本 $\ge dp[i][m] + dp[m+1][j]$。

**证明**：由于目标是 $p_{\min} > 1$ 堆，方案中不存在把整个区间吃成 1 堆的合并。取最终各堆中**最左边那一堆**，它由某个前缀 $[i,m]$ 合并而成（$m < j$），该前缀被合并成 1 堆，余下后缀独立合并到最小堆数。∎

**引理 5（最优子结构）**：若某方案在子区间 $[a,b]$ 上的操作成本高于 $dp[a][b]$，则把该部分替换为 $dp[a][b]$ 对应的方案后整体仍合法且成本不增。

**证明**：替换只改动子区间内部的操作序列，子区间被合并成的堆数不变（都是 $p_{\min}$ 或 1），因此它与区间外部的合并顺序、堆的相邻关系完全兼容；成本严格不增。∎

**定理**：若 $(n-1) \bmod (k-1) = 0$，则 $dp[0][n-1]$ 等于最小总成本；否则不存在方案，返回 $-1$。

**证明**：由引理 2 得可行性的判定正确。可行时，对区间长度 $\ell$ 归纳证明 $dp[i][j]$ 等于对应区间的最小成本：$\ell = 1$ 时为 0。设所有更短区间成立。任一最优方案分两种情形：若 $(j-i) \bmod (k-1) = 0$，由引理 3 存在分割点 $m$ 使成本 $\ge dp[i][m] + dp[m+1][j] + S(i,j)$，而算法枚举了该 $m$ 并取最小，故 $dp[i][j] \le$ 最优；反过来每个候选 $m$ 都能构造出合法方案（分别合并两段后再合并），故 $dp[i][j] \ge$ 最优。若同余不为 0，用引理 4 同理。两种情形都得到等号，归纳完成。∎

## 6. 复杂度分析

- **时间**：$O\!\left(n^2 \cdot \frac{n}{k-1}\right) = O\!\left(\frac{n^3}{k-1}\right)$。区间个数 $O(n^2)$，每个区间的分割点个数约 $(j-i)/(k-1) \le n/(k-1)$。$n = 30$、$k = 2$ 时约 $30^3/2 \approx 1.35\times 10^4$ 次转移，远低于时限。
- **空间**：$O(n^2)$ 存 `dp`，$O(n)$ 存前缀和。
- 对比：朴素搜索是指数级；不做「堆数同余」压缩的状态要加一维 $p$，时空都放大 $n$ 倍。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int mergeStones(vector<int>& stones, int k) {
        int n = (int)stones.size();
        if (n == 1) return 0;
        if ((n - 1) % (k - 1) != 0) return -1;

        vector<long long> pre(n + 1, 0);
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + stones[i];

        const long long INF = LLONG_MAX / 4;
        vector<vector<long long>> dp(n, vector<long long>(n, INF));
        for (int i = 0; i < n; i++) dp[i][i] = 0;

        for (int len = 2; len <= n; len++) {
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                for (int m = i; m < j; m += k - 1) {
                    dp[i][j] = min(dp[i][j], dp[i][m] + dp[m + 1][j]);
                }
                if ((j - i) % (k - 1) == 0) dp[i][j] += pre[j + 1] - pre[i];
            }
        }
        return (int)dp[0][n - 1];
    }
};
```

### Python

```python
class Solution:
    def mergeStones(self, stones: list[int], k: int) -> int:
        n = len(stones)
        if n == 1:
            return 0
        if (n - 1) % (k - 1) != 0:
            return -1

        pre = [0] * (n + 1)
        for i, v in enumerate(stones):
            pre[i + 1] = pre[i] + v

        INF = 10 ** 18
        dp = [[0] * n for _ in range(n)]

        for length in range(2, n + 1):
            for i in range(n - length + 1):
                j = i + length - 1
                best = INF
                m = i
                while m < j:
                    cand = dp[i][m] + dp[m + 1][j]
                    if cand < best:
                        best = cand
                    m += k - 1
                if (j - i) % (k - 1) == 0:
                    best += pre[j + 1] - pre[i]
                dp[i][j] = best

        return dp[0][n - 1]
```

## 8. 边界情况与易错点

1. **`n = 1`**：不需要任何操作，答案是 0（不是 -1，也不是 `stones[0]`）。$(n-1) \bmod (k-1) = 0$ 恰好也通过，所以必须先单独处理或确认 DP 输出 0。
2. **`(n-1) % (k-1) != 0`**：直接 -1。示例 2 就是 $3 \bmod 2 = 1$。
3. **`k > n`**：一次都合不了，若 $n > 1$ 则 $(n-1) \bmod (k-1) = n-1 \ne 0$（因为 $n-1 < k-1$ 且 $n-1 > 0$），自然返回 -1。
4. **分割步长写错**：写成 `m++` 会允许「左块合并成非 1 堆」的非法分割，得到偏小的错误答案；必须 `m += k - 1`。
5. **漏加区间和**：忘掉 `if ((j-i) % (k-1) == 0) dp += sum` 会得到 0；反过来，对不需要合成的区间也加和会得到偏大的答案。
6. **循环顺序**：必须按长度递增。按起点递增会让 `dp[m+1][j]`（更长的区间）尚未计算。
7. **`k = 2` 的退化**：此时步长为 1、每个区间都要合成 1 堆，等价于「相邻合并的最小代价」，答案与 Huffman 一致但推导路径不同。
8. **重复元素的干扰**：本题不要求区分相同值的石头，DP 只依赖下标区间，不依赖数值大小关系，所以有重复值也不会出错。
