# LeetCode 查找共用字符 题解

## 1. 题目概述

- **标题 / 题号**：查找共用字符（#1002，easy）
- **链接**：https://leetcode.cn/problems/find-common-characters/
- **来源**：LeetCode 第 126 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：给定字符串数组 `words`，找出**在每个字符串中都出现过**的字符，并且**按重复次数**逐个列出：若字符 `c` 在某个串里出现 3 次、在另一个串里出现 5 次，那么答案里最多只能放 3 个 `c`。答案顺序任意。

**约束**：

- $1 \le words.length \le 100$
- $1 \le words[i].length \le 100$
- `words[i]` 只含小写英文字母

> 💡 关键词是「**包括重复字符**」与「**每个字符串中都出现**」：前者决定要按次数输出多个副本，后者决定次数取**最小值**。

## 2. 示例

**示例 1**

```text
输入：words = ["bella","label","roller"]
输出：["e","l","l"]
解释：e 在每个串里各出现 1 次；l 在三个串里分别出现 2、2、2 次，取最小值 2，因此输出两个 l。
```

**示例 2**

```text
输入：words = ["cool","lock","cook"]
输出：["c","o"]
解释：c 各出现 1 次；o 在三个串中出现 2、1、2 次，取最小值 1，所以只输出一个 o。
```

**示例 3**

```text
输入：words = ["abc"]
输出：["a","b","c"]
解释：只有一个串时，它的每个字符都是「共用字符」，出现几次输出几次。
```

## 3. 解题思路

### 3.1 暴力思路

枚举候选字符 `c`（26 个字母），再对 `words` 中每个串都数一遍 `c` 的出现次数，取最小值 $m$，把 `c` 追加 $m$ 次。复杂度 $O(26 \cdot \sum |words[i]|)$，在 $100 \times 100$ 的数据下毫无压力，而且**这个暴力其实就是最优解**——本题真正的考点不是复杂度，而是「按最小次数展开」这个细节别写错。

一个常见的错误写法是「收集每个串的字符集合，取交集」：这样只回答「出现过没有」，丢掉了次数信息，示例 1 会输出 `["e","l"]` 而不是 `["e","l","l"]`。

### 3.2 核心观察：每个字符独立，共用次数 = 各串出现次数的最小值

![共用字符：同一字符在各串中的出现次数取最小](images/wc126_q1_counts_min.svg)

关键在于把二维问题拆成一维：

- **字符之间互不影响**：`a` 能输出几个，与 `b` 能输出几个完全无关，所以可以逐字符独立求解。
- **单字符的答案是「最小值」**：设字符 `c` 在第 $i$ 个串中出现 $f_i(c)$ 次。要同时满足「每个串里都有」，最多只能取 $\min_i f_i(c)$ 个；取满这个数又确实在每个串里都能找到，所以答案就是

$$\text{cnt}(c) = \min_{0 \le i < n} f_i(c)$$

- **顺序无关**：题目允许任意顺序，因此不需要任何排序逻辑（想输出稳定顺序时按 `a`~`z` 遍历即可）。

于是问题变成：对 26 个字母各维护一个「当前最小频次」。初始化用第一个串的频次表，随后每个串的频次表与它**逐位取 min**。

### 3.3 算法流程

![算法流程：首串频次表作为初值，后续串逐位取 min](images/wc126_q1_flow.svg)

```text
1. cnt[26] = 第一个串的字符频次
2. for i = 1 .. n-1:
        freq[26] = words[i] 的字符频次
        cnt[c] = min(cnt[c], freq[c])  对每个 c
3. 结果 = 对 c 从 a 到 z，把 c 追加 cnt[c] 次
4. 返回结果
```

用「长度为 26 的数组」而不是哈希表，是因为字母表固定且很小：数组的 `min` 是一次连续的内存比较（C++ 里 `std::transform` 或一个 26 次循环），常数极小，也天然处理了「某字符从未出现」的情况。

### 3.4 示例演算

![示例演算：三个串的频次表逐位取 min](images/wc126_q1_walkthrough.svg)

对示例 1 的 `words = ["bella","label","roller"]`，只列出非零字母：

| 串 | 频次（非零） |
|---|---|
| `bella` | b:1, e:1, l:2, a:1 |
| `label` | l:2, a:1, b:1, e:1 |
| `roller` | r:2, o:1, l:2, e:1 |
| **逐位取 min** | **e:1, l:2**，其余字母至少有一个串缺失（0 次） |

输出 `["e","l","l"]` ✓。三个串的长度并不相同（5、5、6），但取 min 只看同一字母，与长度无关。

再看示例 2：`cool` → c:1,o:2,l:1；`lock` → l:1,o:1,c:1,k:1；`cook` → c:1,o:2,k:1。取 min 得 c:1、o:1、`l` 在 `cook` 中为 0 → 淘汰，`k` 在 `cool` 中为 0 → 淘汰，输出 `["c","o"]` ✓。

## 4. 算法细节

1. **初始化技巧**：把 `cnt` 初值设为第一个串的频次，再从第二个串开始取 min。若 `cnt` 全初始化为 `INT_MAX`，逻辑同样正确但要额外处理「空串」等边界；用首串初始化更直观。
2. **频次表复用**：每轮只申请一个长度 26 的 `freq`，遍历完当前串就与 `cnt` 合并，空间是 $O(26)$ 而非 $O(n \cdot 26)$。
3. **输出顺序**：按 `a`~`z` 遍历输出，结果稳定、便于对拍；题目不要求顺序，所以这纯属工程习惯。
4. **不要过早展开**：先把 26 个计数算完，最后一次性展开成字符串，避免在循环里反复 `push_back` 造成重复计数。
5. **C++ 字符下标**：`c - 'a'` 得到 $0 \sim 25$，注意 `char` 可能带符号，但小写字母范围内安全。

## 5. 正确性证明

**引理 1（单字符上界）**：对任意字符 $c$，答案中 $c$ 的个数不超过 $\min_i f_i(c)$。

**证明**：答案要求 $c$ 出现在每个串中。第 $i$ 个串中只有 $f_i(c)$ 个位置是 $c$，答案里有多少个 $c$ 就要求每个串至少有同样多的 $c$，故答案中 $c$ 的个数 $\le f_i(c)$ 对每个 $i$ 都成立，取最紧的一个得上界 $\min_i f_i(c)$。∎

**引理 2（上界可取到）**：把 $m = \min_i f_i(c)$ 个 $c$ 放进答案，仍然满足「在每个串中都出现」。

**证明**：对每个串 $i$ 都有 $f_i(c) \ge m$，即第 $i$ 个串里至少有 $m$ 个 $c$ 可用，因此这 $m$ 个 $c$ 都能在该串中找到对应位置。∎

**引理 3（独立性）**：不同字符的计数互不约束，可以分别取到各自的最小值。

**证明**：答案是一个多重集，某个字符放几个不消耗别的字符的位置，也不影响别的字符在各串中的出现次数，故各字符的计数约束彼此独立。∎

**定理**：算法输出的多重集恰为「每个字符取各串出现次数最小值」的结果，即答案正确。

**证明**：算法对每个字符 $c$ 输出 $\min_i f_i(c)$ 个副本（初始化 + 逐串取 min 正是求最小值），由引理 2 该数量可行、由引理 1 该数量最优、由引理 3 各字符可同时取到，故输出既可行又最优，且覆盖了所有共用字符（未通过 min 检验的字符在某个串中为 0，不可能出现在答案里）。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot L + 26n)$，其中 $L$ 为单串最大长度。统计每个串的频次是 $O(L)$；每次合并 26 个计数器是 $O(26)$；展开输出不超过 $26 \cdot L$ 个字符。因字母表固定，整体可视作 $O(\sum |words[i]|)$。
- **空间**：$O(26)$ 的频次数组 + $O(1)$ 额外变量（不计输出）。若用哈希表则退化为 $O(\min(26, L))$，没有收益。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> commonChars(vector<string>& words) {
        int cnt[26] = {0};
        for (char ch : words[0]) cnt[ch - 'a']++;

        for (size_t i = 1; i < words.size(); i++) {
            int freq[26] = {0};
            for (char ch : words[i]) freq[ch - 'a']++;
            for (int c = 0; c < 26; c++) cnt[c] = min(cnt[c], freq[c]);
        }

        vector<string> ans;
        for (int c = 0; c < 26; c++) {
            for (int t = 0; t < cnt[c]; t++) ans.push_back(string(1, char('a' + c)));
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def commonChars(self, words: list[str]) -> list[str]:
        cnt = [0] * 26
        for ch in words[0]:
            cnt[ord(ch) - ord('a')] += 1

        for w in words[1:]:
            freq = [0] * 26
            for ch in w:
                freq[ord(ch) - ord('a')] += 1
            for c in range(26):
                cnt[c] = min(cnt[c], freq[c])

        ans = []
        for c in range(26):
            ans.extend(chr(ord('a') + c) for _ in range(cnt[c]))
        return ans
```

## 8. 边界情况与易错点

1. **只数「是否出现」而丢掉次数**：示例 1 的 `l` 会被错误地只输出一次。必须用频次而不是布尔集合。
2. **误用「各串字符集求交」**：交集只能回答「有没有」，答案是 `["e","l"]`，与期望的 `["e","l","l"]` 不符。
3. **单串输入**：`words = ["abc"]` 应输出 `["a","b","c"]`，算法中「从第 2 个串开始合并」的循环不执行，`cnt` 保持首串频次，正确。
4. **某字符在某串中完全不出现**：`freq[c] = 0`，取 min 后 `cnt[c]` 归零，后续再怎么出现也输出 0 个——这正是「必须每个串都有」的语义。
5. **重复字符的输出**：必须是多个独立元素（`["l","l"]`），不能拼成 `"ll"` 一个元素。
6. **顺序要求**：题目任意顺序均可，判题会做多重集比较；不要为了「稳定」而额外排序增加复杂度。
7. **字符数组越界**：只保证小写字母，用 `ch - 'a'` 安全；若扩展到大写或数字，需把数组开到 128 或改用 `unordered_map`。
