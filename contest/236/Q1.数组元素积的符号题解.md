# LeetCode 数组元素积的符号 题解

## 1. 题目概述

- **标题 / 题号**：数组元素积的符号（#1822，easy）
- **链接**：https://leetcode.cn/problems/sign-of-the-product-of-an-array/
- **来源**：LeetCode 第 236 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学、一次遍历

**题意**：定义 $\operatorname{signFunc}(x)$：$x$ 为正返回 $1$，为负返回 $-1$，为零返回 $0$。给定整数数组 $\mathrm{nums}$，令 $\mathrm{product}$ 为全部元素之积，返回 $\operatorname{signFunc}(\mathrm{product})$——即**只问乘积的正负零，不问乘积本身**。

**约束**：

- $1 \le n \le 1000$，$-100 \le \mathrm{nums}[i] \le 100$ → 乘积绝对值上限 $100^{1000} = 10^{2000}$，远超 64 位整型上限（约 $9.2 \times 10^{18}$）——**直接累乘在 C++/Java 必然溢出**，本题考的正是「不求乘积、只求符号」
- 元素非零时绝对值 $\ge 1$ → 乘积非零当且仅当没有任何元素为零，零与奇偶是两条独立判定

## 2. 示例

**示例 1**

```text
输入：nums = [-1,-2,-3,-4,3,2,1]
输出：1
解释：数组中所有值的乘积是 144，且 signFunc(144) = 1
```

**示例 2**

```text
输入：nums = [1,5,0,2,-3]
输出：0
解释：数组中所有值的乘积是 0，且 signFunc(0) = 0
```

**示例 3**

```text
输入：nums = [-1,1,-1,1,-1]
输出：-1
解释：数组中所有值的乘积是 -1，且 signFunc(-1) = -1
```

## 3. 解题思路

### 3.1 朴素思路：直接累乘

按定义把所有元素乘起来得到 $\mathrm{product}$，再套 $\operatorname{signFunc}$。问题出在数值规模：$|\mathrm{product}|$ 可达 $10^{2000}$：

- **C++ / Java**：中途必然溢出，且**有符号整型溢出是未定义行为**——溢出后的符号毫无意义
- **Python**：任意精度大整数能「侥幸」算对，但中间数长达两千位，每次乘法的代价随位数增长，纯属浪费

而题目**只要符号**——绝对值信息从头到尾都是噪音。把「维护乘积」降级为「维护符号」，就是本题的全部优化空间。

### 3.2 核心观察：符号只由「零的存在 + 负数的奇偶」决定

![核心观察：乘积符号只看负数个数与零](images/wc236_q1_sign_parity_concept.svg)

由乘法符号法则 $\operatorname{sign}(x \cdot y) = \operatorname{sign}(x)\cdot\operatorname{sign}(y)$，乘积的符号可以**逐元素传递**地维护，绝对值大小从不参与。于是得到三条性质：

- **零一票否决**：只要有一个元素为 $0$，乘积必为 $0$，负数个数再多也无关；
- **正数无害**：乘正数不改变符号，$100$ 个正数与 $0$ 个正数效果完全相同；
- **负数翻转**：每乘一个负数，符号翻转一次，最终符号只依赖负数个数 $k$ 的奇偶性：$(-1)^k$。

> 💡 一句话：别把 $10^{2000}$ 位的乘积算出来再问正负——符号在每次乘法时就地更新，$O(1)$ 状态走完全程。

### 3.3 算法流程：一趟扫描 + 零短路

![算法流程：一趟扫描与两个短路判定](images/wc236_q1_sign_decision_flow.svg)

```text
输入：nums（长度 n）
1. sign ← ＋1（或 neg ← 0）
2. 对每个 x ∈ nums：
   a. 若 x ＝ 0：立即返回 0          # 零短路，后面元素无需再看
   b. 若 x ＜ 0：sign ← −sign        # （或 neg ← neg ＋ 1）
3. 遍历结束：sign 即答案              # （或按 neg 奇偶返回 ±1）
```

### 3.4 示例演算

![示例演算：符号随负数逐个翻转](images/wc236_q1_sign_parity_walkthrough.svg)

以示例 1（`nums = [-1,-2,-3,-4,3,2,1]`）走一遍，符号像开关一样被负数逐个拨动：

| 步 | $i$ | $\mathrm{nums}[i]$ | 判定 | neg | 当前符号 |
|---|---|---|---|---|---|
| 1 | 0 | $-1$ | 负数，翻转 | 1 | $-$ |
| 2 | 1 | $-2$ | 负数，翻转 | 2 | $+$ |
| 3 | 2 | $-3$ | 负数，翻转 | 3 | $-$ |
| 4 | 3 | $-4$ | 负数，翻转 | 4 | $+$ |
| 5 | 4 | $3$ | 正数，跳过 | 4 | $+$ |
| 6 | 5 | $2$ | 正数，跳过 | 4 | $+$ |
| 7 | 6 | $1$ | 正数，跳过 | 4 | $+$ |

遍历结束：$k = 4$ 为偶数 → 返回 $+1$，与示例输出一致。示例 2 在第 3 步就撞上 $0$ 短路返回；示例 3 无零、$k = 3$ 为奇数 → 返回 $-1$。

## 4. 算法细节

1. **两种等价写法**：`sign` 翻转法（遇负数 `sign = -sign`）与 `neg` 计数法（最后 `neg & 1` 判奇偶），由 $(-1)^k$ 的定义统一。计数法便于一行统计，翻转法省去收尾判断。
2. **零短路要「立即」返回**：不是置标记后继续扫——遇到 $0$ 后面元素对答案已无影响，提前退出是零成本收益。
3. **C++ 的无分支技巧**：`sign *= (x > 0) - (x < 0)`，该表达式的值域恰为 $\{-1, 0, +1\}$（正是 $\operatorname{sign}(x)$），状态永远停在三值之内不会溢出，且零被自动吸收（乘 $0$ 归 $0$），连 `if` 都省了。
4. **无需预处理**：不必统计正数个数、不必取绝对值；$-100$ 与 $-1$ 对符号的贡献完全一样。

## 5. 正确性证明

**引理 1（符号乘法法则）**：对任意实数 $x, y$，$\operatorname{sign}(x \cdot y) = \operatorname{sign}(x)\cdot\operatorname{sign}(y)$。

**证明**：若 $x = 0$ 或 $y = 0$，则 $xy = 0$，等式两边均为 $0$，成立。若二者均非零，按符号组合逐一验证：$(+)\times(+)$ 积为正；$(+)\times(-)$ 与 $(-)\times(+)$ 积为负，且 $\operatorname{sign}(x)\operatorname{sign}(y) = -1$；$(-)\times(-)$ 积为正，且 $(-1)\cdot(-1) = +1$。四种情形均吻合。∎

**引理 2（零吸收）**：$\prod_{i=0}^{n-1} \mathrm{nums}[i] = 0 \iff \exists\, i,\ \mathrm{nums}[i] = 0$。

**证明**：「⇐」对元素个数归纳：单个零元素之积为 $0$；设前 $i$ 个元素之积为 $P$，则 $P \cdot 0 = 0$，零一旦混入乘积恒为零。「⇒」证逆否命题：若所有元素非零，则每个 $|\mathrm{nums}[i]| \ge 1$，故 $\left|\prod_i \mathrm{nums}[i]\right| \ge 1$，乘积非零。∎

**定理**：设 $k = \#\{\, i : \mathrm{nums}[i] < 0 \,\}$，则

$$
\operatorname{sign}\!\left(\prod_{i=0}^{n-1} \mathrm{nums}[i]\right) =
\begin{cases}
0, & \exists\, i,\ \mathrm{nums}[i] = 0 \\
(-1)^k, & \text{否则}
\end{cases}
$$

**证明**：若含零，由引理 2 乘积为 $0$，符号为 $0$。若不含零，用引理 1 链式展开：

$$
\operatorname{sign}\!\left(\prod_i \mathrm{nums}[i]\right) = \prod_i \operatorname{sign}(\mathrm{nums}[i]) = \prod_{\mathrm{nums}[i] < 0} (-1) \cdot \prod_{\mathrm{nums}[i] > 0} (+1) = (-1)^k. \quad \blacksquare
$$

**推论（算法正确性）**：一趟扫描算法的返回值恰为 $\operatorname{sign}(\prod_i \mathrm{nums}[i])$。

**证明**：若途中遇到零，算法立即返回 $0$，由引理 2 这正是乘积的符号；若循环正常结束，说明全程无零，算法维护的 $k$（或翻转 $k$ 次后的 sign，即 $(-1)^k$）等于负数个数，由定理返回值即乘积的符号。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素至多经历「判零、判负」两次 $O(1)$ 比较；含零时在首个零处提前终止，实际访问更少。
- **空间复杂度**：$O(1)$。只维护一个 `sign`（或 `neg`）计数器。
- **与累乘法对比**：累乘法在固定宽度整型下直接不可行（溢出）；即便在 Python 中可行，中间数位数线性增长，单次大数乘法代价远超 $O(1)$，总代价远高于一趟比较。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int arraySign(vector<int>& nums) {
        int sign = 1;
        for (int x : nums) {
            if (x == 0) return 0;   // 零短路
            if (x < 0) sign = -sign; // 负数翻转
        }
        return sign;
    }
};
```

### Python

```python
class Solution:
    def arraySign(self, nums: list[int]) -> int:
        sign = 1
        for x in nums:
            if x == 0:
                return 0            # 零短路
            if x < 0:
                sign = -sign        # 负数翻转
        return sign
```

一行统计版（无零时）：`0 if 0 in nums else (-1 if sum(x < 0 for x in nums) & 1 else 1)`，与循环版等价，适合比赛末期抢时间。

## 8. 边界情况与易错点

1. **直接累乘溢出**（最经典的踩点）：$100^{1000} = 10^{2000}$，而 `long long` 上限约 $9.2 \times 10^{18}$——C++/Java 连乘必爆，且溢出后的符号可能「碰巧对、悄悄错」，样例都过不了。签到题的第一反应应当是：**要符号就只维护符号**。
2. **漏判 0**：只数负数奇偶、忘记零短路 → 示例 2 会被判成 $-1$（恰有奇数个负数），正确答案是 $0$。零的优先级**高于**奇偶判定。
3. **「全负 = 负」的直觉陷阱**：$1000$ 个 $-100$（偶数个负数）→ 答案是 $+1$；周赛手快时最容易在这种签到题上翻车。
4. **单元素数组**：$[-5]$ → $-1$、$[0]$ → $0$、$[7]$ → $1$，模板天然覆盖，无需特判。
5. **先判 0 还是先判负**：一个元素不可能同时是 $0$ 和负数，两种顺序对答案无影响；但先判 $0$ 能让含零输入提前退出，顺手放前面。
6. **Python 别依赖 `math.prod` 侥幸**：能过，但中间数长达两千位，养成习惯后迁移到 C++ 就会翻车；`(-100)` 这类边界也不需要任何特殊处理。
