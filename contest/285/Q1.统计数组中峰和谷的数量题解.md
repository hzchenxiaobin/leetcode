# LeetCode 统计数组中峰和谷的数量 题解

## 1. 题目概述

- **标题 / 题号**：统计数组中峰和谷的数量（#2210，easy）
- **链接**：https://leetcode.cn/problems/count-hills-and-valleys-in-an-array/
- **来源**：LeetCode 第 285 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、一次遍历、去重

**题意**：给定下标从 0 开始的整数数组 `nums`。下标 `i` 属于某个**峰**，当且仅当它左右两侧**最近的与 `nums[i]` 不相等的邻居**都存在且均小于 `nums[i]`；属于某个**谷**，当且仅当两个最近不等邻居均大于 `nums[i]`。相邻下标若值相等，则属于**同一个**峰或谷（一个"平台"整体只算一个）。返回峰和谷的总数。

**约束**：

- $3 \le \text{nums.length} \le 100$
- $1 \le \text{nums[i]} \le 100$

> 📚 本题在本仓库另有[每日题解 2210](../../solution/2201-2300/2210_统计数组中峰和谷的数量.md)：含乘积判别技巧、`groupby` 压缩写法、$O(1)$ 在线判定与面试问答；本篇侧重赛时切入路径、等值段视角的正确性证明与边界复盘，两篇刻意互补。

> ⚠️ **读题信号**：$n \le 100$ 说明任何合理做法都能过——签到题的胜负手不在复杂度，而在两条语义的精确落地：**「最近不相等邻居」要跨过相等值去找**，**「相邻相等属同一峰/谷」要去重**。把这两条合成一句话：判定对象不是下标，是**等值段**。

## 2. 示例

**示例 1**

```text
输入：nums = [2, 4, 1, 1, 6, 5]
输出：3
解释：
  下标 1（值 4）：最近不等邻居 2 与 1，均小于 4 → 峰
  下标 2、3（值 1）：最近不等邻居都是 4 与 6（右侧要跨过另一个 1），
                   均大于 1 → 谷；但两下标相邻且相等，属同一个谷，只计 1 个
  下标 4（值 6）：最近不等邻居 1 与 5 → 峰
  下标 0、5：缺一侧邻居，不计
  共 2 峰 + 1 谷 = 3。
```

**示例 2**

```text
输入：nums = [6, 6, 5, 5, 4, 1]
输出：0
解释：压缩为 [6, 5, 4, 1] 后单调递减，每个内部下标都一侧大一侧小，无峰无谷。
     注意下标 1（值 6）：左侧只有与它相等的 6，"最近不相等邻居"根本不存在，同样不计。
```

**示例 3（自造，覆盖长平台与峰谷相邻）**

```text
输入：nums = [1, 9, 9, 9, 1, 3, 3, 2]
输出：3
解释：三个 9 组成的平台是一个峰；中段的 1 是谷；两个 3 组成的平台是一个峰。
     压缩后 [1, 9, 1, 3, 2]，三个内部值依次为 峰、谷、峰 → 3。
```

## 3. 解题思路

### 3.1 暴力思路：逐下标找邻居

对每个 $i$（$1 \le i \le n-2$）向左、向右各扫一段，找到最近的不等邻居再判定，单点 $O(n)$、总计 $O(n^2)$。$n \le 100$ 下这个复杂度毫无压力，**真正的问题不是超时而是计数**：示例 1 中下标 2、3 都满足谷的定义，直接各计一次会答 4 而不是 3。补救办法是"每个等值段只计一次"——而这一步补救，本质上已经是在做压缩了。

### 3.2 核心观察：等值段整体同判

把 `nums` 切成若干**极大等值段**（段内值相同、相邻段值不同）。三个观察合起来直接给出最短解法：

- **观察一（段内同判）**：段内任一下标向左找最近不等邻居时，先跳过的恰好是本段的值，落点因此**固定**为前一段的末尾值；右侧对称。也就是说，段内**所有下标的两侧最近不等邻居完全相同**，峰/谷判定要么整段成立、要么整段不成立。
- **观察二（计数单位是段）**：题面"相邻相等属同一个峰/谷"，配合观察一，说明计数单位从下标坍缩为**段**——一段一票，天然去重。
- **观察三（压缩后无需再扫）**：把每段压缩成一个代表值得到序列 $b$，则 $b$ **相邻元素必不相等**——段 $t$ 的左右最近不等邻居恰好就是 $b[t-1]$ 与 $b[t+1]$，判定退化为一次比较：两侧同小是峰、两侧同大是谷。

![核心观察：等值段整体同判，压缩后数拐点](images/wc285_q1_segment_concept.svg)

### 3.3 算法流程

观察一~三有两种等价的落地方式：

- **写法 A（显式压缩）**：先一趟把相邻相等元素合并成 $b$，再对 $b$ 的每个内部下标判一次拐点。最清晰、最不容易写错。
- **写法 B（段首判定，一次遍历）**：不建辅助数组。遍历 $i \in [1, n-2]$：若 `nums[i] == nums[i-1]`，说明 $i$ 不是段首，直接跳过（本段已在段首判过）；否则左侧最近不等邻居就是 `nums[i-1]`，再向右跳过与 `nums[i]` 相等的值找右侧邻居，判一次。额外空间 $O(1)$。

两种写法的判定参数逐段一致（见 §5 推论），赛时写哪个都行——写法 B 是写法 A 的原地形态。

## 4. 算法细节

1. **压缩（写法 A）**：遍历 `nums`，仅当 `b` 为空或 `b[-1] != x` 时压入 `x`，得到无相邻重复的 $b$；判定遍历范围 $[1, m-2]$，$m < 3$ 时自然返回 0。
2. **段首判定（写法 B）**：跳过条件 `nums[i] == nums[i-1]` 一石二鸟——段内非段首的下标全部跳过；段首 $i$ 处 `nums[i-1]` 必是左侧最近不等邻居（段首与前一段值不同）。
3. **右侧邻居**：`r` 从 `i+1` 起向右跳过与 `nums[i]` 相等的值；`r == n` 说明本段是尾段（无右侧不等邻居），不计。首段则天然不会被判：其段首在 $i = 0$，不在循环范围内。
4. **判定表达式**：峰/谷可显式写两个布尔，也可合并为乘积 $(v-l)(v-r) > 0$（两差同号则积为正）。本文 C++ 用显式布尔便于阅读，Python 用乘积一行判定。
5. **内层 while 不破坏 $O(n)$**：内层扫描只跨过与 `nums[i]` 相等的下标，而每个下标至多被"某一次内层扫描"越过一次（它只属于一个段），总代价 $\le n$，整体仍是一次遍历。

## 5. 正确性证明

**引理 1（等值段同判性）**：设 $S_t = [l_t, r_t]$ 是值为 $v_t$ 的极大等值段（相邻段值不同）。对任意 $i \in S_t$：其左侧最近不相等邻居当且仅当 $t > 0$ 时存在，且恒为 $\text{nums}[l_t - 1] = v_{t-1}$；右侧最近不相等邻居当且仅当 $t < m-1$ 时存在，且恒为 $\text{nums}[r_t + 1] = v_{t+1}$。故段内所有下标的峰/谷判定结果一致。

**证明**：对 $i \in [l_t, r_t]$，向左扫描时下标 $l_t, \dots, i-1$ 的值均为 $v_t$，与 $\text{nums}[i]$ 相等而被全部跳过，第一个可能停下的位置是 $l_t - 1$；由段的极大性，$t > 0$ 时 $\text{nums}[l_t - 1] = v_{t-1} \ne v_t$，即为所求。该位置与 $i$ 在段内的选取无关。右侧对称。于是"两侧最近不等邻居均小于（大于）$v_t$"对整段同真或同假。∎

**引理 2（计数即合格段数）**：答案等于"判定为峰或谷、且 $1 \le t \le m-2$ 的极大等值段"的个数。

**证明**：题面把峰/谷定义为下标组：相邻相等的下标同组。由引理 1，若某段有下标属于某峰，则整段都属于该峰；又相邻两段值不同、不可能同组，故峰/谷与"判定为峰/谷的段"一一对应。首段（$t=0$）无左侧最近不等邻居、尾段（$t=m-1$）无右侧最近不等邻居（引理 1 的边界情形），依题意两侧邻居须都存在，故不计。峰与谷判定互斥（$v_t$ 不能同时严格大于、又严格小于同一对邻居），同段不重复贡献。∎

**定理**：设压缩序列 $b = [v_0, \dots, v_{m-1}]$，则

$$\text{ans} = \#\{\, t : 1 \le t \le m-2,\ (v_t - v_{t-1})(v_t - v_{t+1}) > 0 \,\}$$

**证明**：由引理 1，内部段 $S_t$ 的两侧最近不等邻居为 $v_{t-1}$ 与 $v_{t+1}$；$S_t$ 是峰的一部分当且仅当 $v_t > v_{t-1} \wedge v_t > v_{t+1}$（两差同正），是谷的一部分当且仅当两差同负；两者合并即差之乘积为正。由引理 2，答案即满足条件的内部段个数。∎

**推论（写法 B 的正确性）**：段首判定一次遍历输出与定理相同的计数。

**证明**：对 $t \ge 1$ 的段，段首 $l_t$ 满足 $\text{nums}[l_t] \ne \text{nums}[l_t - 1]$，循环恰在 $i = l_t$ 处判定一次（以 $v_{t-1}$ 为左邻；右邻经内层扫描得到 $v_{t+1}$，$t = m-1$ 时不存在、被跳过），段内其余下标全部命中 `nums[i] == nums[i-1]` 的跳过分支；$t = 0$ 的段，其段首 $i = 0$ 不在循环内、段内其余下标命中跳过分支，判定次数为 0。故每段判定次数至多 1 且判定参数与定理一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。写法 A 为压缩一趟 + 判定一趟；写法 B 的内层 `while` 只跨过相等值、每个下标至多被越过一次，均摊后仍是一趟。$n \le 100$ 下即使 $O(n^2)$ 暴力也能过，$O(n)$ 的意义在于模板正确性而非速度。
- **空间复杂度**：写法 A 为 $O(n)$（压缩数组最坏 $m = n$，无相邻重复时）；写法 B 只用常数个变量，$O(1)$。

## 7. 参考代码

### C++（写法 B：段首判定，$O(1)$ 额外空间）

```cpp
class Solution {
  public:
    int countHillValley(vector<int>& nums) {
        int n = nums.size(), ans = 0;
        for (int i = 1; i < n - 1; ++i) {
            if (nums[i] == nums[i - 1]) continue;  // 非段首：本段已在段首判过
            int r = i + 1;
            while (r < n && nums[r] == nums[i]) ++r;  // 右侧最近不相等邻居
            if (r == n) continue;                      // 尾段无右邻，不计
            bool hill = nums[i] > nums[i - 1] && nums[i] > nums[r];
            bool vale = nums[i] < nums[i - 1] && nums[i] < nums[r];
            if (hill || vale) ++ans;
        }
        return ans;
    }
};
```

### Python（写法 A：压缩 + 乘积判定）

```python
class Solution:
    def countHillValley(self, nums: List[int]) -> int:
        b = []
        for x in nums:
            if not b or b[-1] != x:
                b.append(x)
        return sum(
            (b[i] - b[i - 1]) * (b[i] - b[i + 1]) > 0
            for i in range(1, len(b) - 1)
        )
```

### Python（写法 B：与 C++ 同构，$O(1)$ 额外空间）

```python
class Solution:
    def countHillValley(self, nums: List[int]) -> int:
        n, ans = len(nums), 0
        for i in range(1, n - 1):
            if nums[i] == nums[i - 1]:
                continue
            r = i + 1
            while r < n and nums[r] == nums[i]:
                r += 1
            if r == n:
                continue
            if (nums[i] - nums[i - 1]) * (nums[i] - nums[r]) > 0:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **重复计数（本题第一大坑）**：逐下标判定而不合并相等段，示例 1 会把下标 2、3 各算一个谷，答 4 而非 3。写法 A 靠压缩解决，写法 B 靠 `nums[i] == nums[i-1]` 跳过——漏写这个跳过必错。

2. **"最近不相等邻居"≠ 相邻下标**：判定必须跨过相等值再取邻居。示例 1 中下标 2 的右侧邻居是 6（跨过下标 3 的 1），不是 `nums[3]`。若误用 `nums[i±1]`，会产生形如 `1 < 1` 的假比较，部分用例侥幸通过、另一部分错。

3. **首尾的两种不计**：一是下标 0 与 $n-1$ 天然缺一侧；二是**首段/尾段延伸出的平台**——如示例 2 的下标 1（值 6），左侧只有相等的 6，"最近不相等邻居"不存在。两种都依题意不计。

4. **全等数组**：`[5, 5, 5]` 压缩后长度 1，循环不执行，返回 0。

5. **压缩后长度恰为 3**：如 `[1, 2, 2, 1]` 压缩为 `[1, 2, 1]`，唯一内部下标是峰，答案 1——遍历范围 $[1, m-2]$ 是两端闭区间，别写成半开。

6. **相邻段可以相继成峰成谷**：`[1, 3, 2, 4]` 中 3 是峰、紧邻的 2 是谷，两段值不同、不合并——"同一个峰/谷"只合并**相等**的相邻下标。

7. **无溢出/性能风险**：$n \le 100$、值域 $[1, 100]$，全部 `int` 裸算即可，不需要任何数据结构。
