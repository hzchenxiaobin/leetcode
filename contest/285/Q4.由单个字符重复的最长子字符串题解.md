# LeetCode 由单个字符重复的最长子字符串 题解

## 1. 题目概述

- **标题 / 题号**：由单个字符重复的最长子字符串（#2213，hard）
- **链接**：https://leetcode.cn/problems/longest-substring-of-one-repeating-character/
- **来源**：LeetCode 第 285 场周赛 Q4
- **难度**：困难
- **标签**：线段树、数组、字符串、有序集合

**题意**：给定长度为 $n$ 的字符串 $s$ 和 $k$ 次查询。第 $i$ 次查询把 $s[\text{queryIndices}[i]]$ 改成 $\text{queryCharacters}[i]$，要求在**每次修改之后**回答：当前 $s$ 中「全部由同一字符重复组成的最长子串」的长度。返回长度为 $k$ 的答案数组。

**约束**：

- $1 \le n \le 10^5$，$s$ 仅由小写英文字母组成；
- $1 \le k \le 10^5$，$\text{queryCharacters}$ 仅由小写英文字母组成；
- $0 \le \text{queryIndices}[i] < n$。

> 💡 **一句话定位**：单点修改 × 全局最值查询 ×「最长重复段」信息**不可加但可合并**——维护**五元组（前缀 run、后缀 run、段内最长）的线段树**，与「区间最大子段和」同款骨架的字符版。

> 💡 本题在本仓库另有[每日题解 2213](../../solution/2201-2300/2213_由单个字符重复的最长子字符串.md)：主线同为「前缀 run / 后缀 run / 段内最长」合并的线段树，附「为什么必须用线段树」（对比树状数组、ST 表的选型论证）与面试问答。本篇按**周赛复盘视角**展开，补齐引理-定理化的合并正确性证明（跨界子串刻画 + 结构归纳不变式）、C++ 递归 / Python 迭代双实现与赛场易错清单，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路

每次修改后从头到尾线性扫描 $s$，维护「当前连续段长度」取最大：单次 $O(n)$，总计 $O(nk) = 10^{10}$，在 $n = k = 10^5$ 下必然超时。

瓶颈在于：一次**单点**修改最多影响**一个**位置的字符，却花了 $O(n)$ 重算全串。要让复杂度降到 $O(\log n)$ 级别，必须让「修改的影响」只沿着一条短路径传播——这正是线段树的甜区：**单点修改 + 全局信息查询**。

### 3.2 核心观察：run 信息虽不可加，但「五元组」可合并

![核心观察：节点维护前缀 run、后缀 run、段内最长三个字段](images/wc285_q4_node_fields_concept.svg)

记 **run** 为极长的同字符连续段。答案就是**最长 run 的长度**（任何单字符子串都能扩成包含它的 run，长度不减）。

直接把「区间最长 run」当作节点信息会卡在一点：它**不满足区间可加**——把左右两段拼起来，最长 run 不等于左右各自最长 run 的最大值，因为可能出现**横跨分界点的桥接**（左半的后缀 run 与右半的前缀 run 同字符时拼接变长）。解决办法是经典的**陪跑信息**设计：

每个线段树节点额外维护自己区间的**前缀 run**（从区间左端开始的最长同字符段，记字符与长度）和**后缀 run**（对称定义）。于是五元组 $(\text{prefC}, \text{prefL}, \text{sufC}, \text{sufL}, \text{mx})$ 加上由树结构隐含的段长 $\text{len}$，构成**合并封闭**的信息集：

1. **前缀合成**：若左儿子**整段同字符**且与右儿子的前缀 run 同字符，父亲的前缀 run 延伸进右儿子；
2. **后缀合成**：对称；
3. **最长合成**：$\text{mx} = \max(\text{左 mx},\ \text{右 mx},\ \text{桥})$，桥 = 左后缀 run 与右前缀 run 同字符时的长度和。

这与「区间最大子段和」（前缀和 / 后缀和 / 内部最优三字段）是同一套骨架——本题是它的「字符相等版」。

### 3.3 算法流程：merge 与单点更新

![算法流程：merge 的三条合成规则与单点更新上浮](images/wc285_q4_merge_flow.svg)

**建树 `build(o, lo, hi)`**：

1. 叶子（$lo = hi$）：五元组为 $(s[lo], 1, s[lo], 1, 1)$；
2. 内部节点：取 $\text{mid} = \lfloor (lo + hi) / 2 \rfloor$，递归建左右儿子，回溯时 `pushup` 合并五元组。

**更新 `update(pos, c)`**：

1. 从根下行到叶子 $pos$，把叶子的两个字符字段改成 $c$（三个长度字段恒为 1 不动）；
2. 自底向上沿**根→叶路径**逐层 `pushup` 重算，每层 $O(1)$。

**查询**：修改后根节点的 $\text{mx}$ 就是答案，$O(1)$ 读取——信息只上浮（pushup-only），全程**无懒标记、无 pushdown**（与 293 场 Q4 的「染色永久化」同属免下传形态）。

### 3.4 示例演算

![示例演算：babacc 的三次查询](images/wc285_q4_walkthrough.svg)

对示例 1（$s = $ `babacc`）：

| 步骤 | 操作 | 修改后 $s$ | run 划分 | 答案 |
|---|---|---|---|---|
| ① | $s[1] \leftarrow$ `b` | `bbbacc` | `bbb` · `a` · `cc` | 3 |
| ② | $s[3] \leftarrow$ `c` | `bbbccc` | `bbb` · `ccc` | 3 |
| ③ | $s[3] \leftarrow$ `b` | `bbbbcc` | `bbbb` · `cc` | 4 |

注意 ③：位置 3 一变，原来长 3 的 `ccc` run 消失，`bbb` 与新 `b` **桥接**成 `bbbb`——这个「桥」正是 3.2 中跨界合成规则要处理的情况；树里它发生在管辖 $[0,3]$ 与 $[4,5]$（或按分治结构划分）的祖先节点的一次 `pushup` 中。

## 4. 算法细节

1. **节点字段**：`prefC / prefL`（前缀 run 字符与长度）、`sufC / sufL`（后缀 run）、`mx`（段内最长 run）。段长 `len` 不必存储：递归版由递归参数 $(lo, hi)$ 随身携带；迭代版补齐到 2 的幂后各节点段长规整可预计算。

2. **merge 三公式**（$L$、$R$ 为左右儿子，$\text{len}(\cdot)$ 为段长）：

   $$\text{pref}(P) = \begin{cases} \big(\text{prefC}[L],\ \text{len}(L) + \text{prefL}[R]\big) & \text{prefL}[L] = \text{len}(L) \wedge \text{prefC}[L] = \text{prefC}[R] \\ \big(\text{prefC}[L],\ \text{prefL}[L]\big) & \text{否则} \end{cases}$$

   $$\text{suf}(P) = \begin{cases} \big(\text{sufC}[R],\ \text{len}(R) + \text{sufL}[L]\big) & \text{sufL}[R] = \text{len}(R) \wedge \text{sufC}[R] = \text{sufC}[L] \\ \big(\text{sufC}[R],\ \text{sufL}[R]\big) & \text{否则} \end{cases}$$

   $$\text{mx}(P) = \max\big(\text{mx}[L],\ \text{mx}[R],\ \text{sufC}[L] = \text{prefC}[R]\ ?\ \text{sufL}[L] + \text{prefL}[R] : 0\big)$$

3. **为什么只重算一条路径**：单点修改只改变位置 $pos$ 的字符，而线段树中**区间包含 $pos$ 的节点恰好是根→叶路径上的 $O(\log n)$ 个**（每层一个）；路径外节点的管辖区间不含 $pos$，五元组天然不变。

4. **答案的读取**：每次更新后整棵树实时正确，根的 `mx` 即 $M([0, n-1])$，无需任何额外扫描。

5. **实现形态**：C++ 给递归版（经典 $4n$ 数组，`pushup` 在回溯时调用）；Python 给迭代版（补齐 2 的幂、自底向上一层层 `pushup`），省去递归调用开销，跑满 $k = 10^5$ 次查询更稳。两版 merge 逻辑逐行同构。

## 5. 正确性证明

对当前串 $s$ 与区间 $I = [l, r]$，定义：

- $P(I)$：最大 $k$ 使 $s[l..l+k-1]$ 全同字符（**前缀 run** 长度），$\text{prefC}(I) = s[l]$；
- $S(I)$：对称的**后缀 run** 长度，$\text{sufC}(I) = s[r]$；
- $M(I)$：$I$ 内**最长单字符子串**的长度。

**引理 1（跨界子串的刻画）**：设 $I = I_L \uplus I_R$，$I_L = [l, m]$，$I_R = [m+1, r]$。$I$ 内任何单字符子串要么含于 $I_L$，要么含于 $I_R$，要么横跨分界点 $m$；横跨者存在当且仅当 $s[m] = s[m+1]$，且此时其长度不超过 $S(I_L) + P(I_R)$，并存在长度恰为 $S(I_L) + P(I_R)$ 的横跨者。

**证明**：按子串 $[a, b]$ 的位置三分，前两种情形显然。设 $[a,b]$ 均匀（字符 $c$）且 $a \le m < b$：则 $s[a..m]$ 是 $I_L$ 内以 $m$ 结尾的均匀段，故 $m - a + 1 \le S(I_L)$ 且 $c = s[m]$；同理 $b - m \le P(I_R)$ 且 $c = s[m+1]$。于是 $c = s[m] = s[m+1]$（必要性），且 $b - a + 1 \le S(I_L) + P(I_R)$。反之当 $s[m] = s[m+1] = c$ 时，$I_L$ 的后缀 run（长 $S(I_L) \ge 1$，字符 $s[m] = c$）与 $I_R$ 的前缀 run（长 $P(I_R) \ge 1$，字符 $s[m+1] = c$）相邻拼接，得到长恰为 $S(I_L) + P(I_R)$ 的均匀子串 ∎

**引理 2（前缀 run 的合成）**：$P(I) = \text{prefL}[L] = \text{len}(L) \wedge \text{prefC}[L] = \text{prefC}[R]$ 时取 $\text{len}(L) + P(I_R)$，否则取 $P(I_L)$。（后缀对称）

**证明**：设 $c = s[l]$，前缀 run 从 $l$ 向右延伸。

- 若 $P(I_L) < \text{len}(L)$：延伸在 $I_L$ 内部已断（$s[m] \ne s[l]$ 之前就出现异字符），故 $P(I) = P(I_L)$；
- 若 $P(I_L) = \text{len}(L)$（$I_L$ 整段同为 $c$）：
  - $s[m+1] = c$：run 无缝进入 $I_R$ 并恰好再延伸 $I_R$ 自身的前缀 run 长度，$P(I) = \text{len}(L) + P(I_R)$；
  - $s[m+1] \ne c$：run 止于 $m$，$P(I) = \text{len}(L) = P(I_L)$。

三种情况与公式的两个分支一一对应 ∎

**定理（五元组不变式与答案正确性）**：`build` 完成后，以及每次 `update` 之后，每个节点 $o$ 的五元组等于其管辖区间在当前串下的 $(\text{prefC}, P, \text{sufC}, S, M)$；从而根的 `mx` 即所求答案。

**证明**：对结构归纳。

1. **叶子**：区间为单点，$P = S = M = 1$、字符即该位置字符；`update` 到叶子时同步改字符，长度字段不变，叶子不变式保持。
2. **内部节点**：设儿子为 $L, R$。若二者不变式成立，则 `pushup` 中：前缀由引理 2 得正确值（后缀对称）；`mx` 取三候选之最大——$M(I_L)$、$M(I_R)$ 与横跨最大长度（引理 1），由引理 1 的三分覆盖 $I$ 内所有单字符子串的可能位置、且横跨候选在可行时取到上界，故 `mx` $= M(I_o)$。节点恢复不变式。
3. **单点修改**：只有位置 $pos$ 的字符变化。包含 $pos$ 的节点恰为根→叶路径（每层恰一个），路径外节点五元组不变仍正确；路径上自叶向根逐层 `pushup`，由第 2 条逐层恢复不变式。
4. **答案**：任何单字符子串可向两侧扩成包含它的极大 run 且长度不减，故全串最长单字符子串长度 $= M([0, n-1]) = $ 根的 `mx` ∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k \log n)$。建树每个节点 $O(1)$ 合并、共 $O(n)$ 个节点；每次查询是一次单点更新——路径长 $\lceil \log_2 n \rceil = 17$ 层、每层一次 $O(1)$ 的 `pushup`——加一次 $O(1)$ 的读根。总计约 $10^5 + 10^5 \times 17 \approx 1.9 \times 10^6$ 次合并。
- **空间复杂度**：$O(n)$。递归版 $4n$、迭代版 $2 \cdot 2^{\lceil \log_2 n \rceil}$ 个五元组槽位；字符仅 26 种小写字母，每字段一个 `char`/`int8` 加三个 `int` 足够。

> 💡 **对比有序集合路线**（标签里的 Ordered Set）：用平衡树维护 run 边界（如 `map<起点, 字符>`）+ `multiset` 维护所有 run 长度，每次修改做至多 $O(1)$ 次 run 的分裂与合并，同样 $O((n + k) \log n)$。它常数更小，但要小心「分裂/合并时把旧长度从 multiset 里删干净」这类簿记细节；线段树一套 `merge` 管所有字段，且天然支持更强的区间查询（见延伸思考）。

## 7. 参考代码

### C++

```cpp
class Solution {
    int n;
    string s;
    vector<char> pc, sc;    // 前缀 / 后缀 run 的字符
    vector<int> pl, sl, mx; // 前缀 / 后缀 run 长度、段内最长 run

    void pushup(int o, int lo, int hi) {
        int mid = (lo + hi) / 2;
        int llen = mid - lo + 1, rlen = hi - mid; // 左右儿子段长
        int L = 2 * o, R = 2 * o + 1;
        // ① 前缀：左儿子整段同字符且与右儿子前缀同字符，才延伸进右儿子
        if (pl[L] == llen && pc[L] == pc[R]) {
            pc[o] = pc[L];
            pl[o] = llen + pl[R];
        } else {
            pc[o] = pc[L];
            pl[o] = pl[L];
        }
        // ② 后缀：对称
        if (sl[R] == rlen && sc[R] == sc[L]) {
            sc[o] = sc[R];
            sl[o] = rlen + sl[L];
        } else {
            sc[o] = sc[R];
            sl[o] = sl[R];
        }
        // ③ 最长：左内、右内、跨界桥，三者取最大
        int bridge = (sc[L] == pc[R]) ? sl[L] + pl[R] : 0;
        mx[o] = max({mx[L], mx[R], bridge});
    }

    void build(int o, int lo, int hi) {
        if (lo == hi) {
            pc[o] = sc[o] = s[lo];
            pl[o] = sl[o] = mx[o] = 1;
            return;
        }
        int mid = (lo + hi) / 2;
        build(2 * o, lo, mid);
        build(2 * o + 1, mid + 1, hi);
        pushup(o, lo, hi);
    }

    void update(int o, int lo, int hi, int pos, char c) {
        if (lo == hi) {
            pc[o] = sc[o] = c; // 长度字段恒为 1，无需改动
            return;
        }
        int mid = (lo + hi) / 2;
        if (pos <= mid) update(2 * o, lo, mid, pos, c);
        else update(2 * o + 1, mid + 1, hi, pos, c);
        pushup(o, lo, hi);
    }

  public:
    vector<int> longestRepeating(string s, string queryCharacters, vector<int>& queryIndices) {
        n = s.size();
        this->s = move(s);
        pc.assign(4 * n, 0);
        sc.assign(4 * n, 0);
        pl.assign(4 * n, 0);
        sl.assign(4 * n, 0);
        mx.assign(4 * n, 0);
        build(1, 0, n - 1);
        vector<int> ans;
        ans.reserve(queryIndices.size());
        for (int i = 0; i < (int)queryIndices.size(); ++i) {
            update(1, 0, n - 1, queryIndices[i], queryCharacters[i]);
            ans.push_back(mx[1]); // 根的 mx 即答案
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def longestRepeating(self, s: str, queryCharacters: str, queryIndices: List[int]) -> List[int]:
        n = len(s)
        size = 1
        while size < n:      # 补齐到 2 的幂，叶子 i 落在 size + i
            size <<= 1
        pc = [''] * (2 * size)  # 前缀 run 字符
        pl = [0] * (2 * size)   # 前缀 run 长度
        sc = [''] * (2 * size)  # 后缀 run 字符
        sl = [0] * (2 * size)   # 后缀 run 长度
        mx = [0] * (2 * size)   # 段内最长 run
        ln = [0] * (2 * size)   # 节点段长（空叶子为 0）
        for i in range(size):
            if i < n:
                o = size + i
                ln[o] = 1
                pc[o] = sc[o] = s[i]
                pl[o] = sl[o] = mx[o] = 1
        for o in range(size - 1, 0, -1):
            ln[o] = ln[2 * o] + ln[2 * o + 1]

        def pushup(o):
            L, R = 2 * o, 2 * o + 1
            if ln[L] == 0:   # 空儿子：直接取另一侧
                pc[o], pl[o], sc[o], sl[o], mx[o] = pc[R], pl[R], sc[R], sl[R], mx[R]
                return
            if ln[R] == 0:
                pc[o], pl[o], sc[o], sl[o], mx[o] = pc[L], pl[L], sc[L], sl[L], mx[L]
                return
            if pl[L] == ln[L] and pc[L] == pc[R]:
                pc[o], pl[o] = pc[L], ln[L] + pl[R]
            else:
                pc[o], pl[o] = pc[L], pl[L]
            if sl[R] == ln[R] and sc[R] == sc[L]:
                sc[o], sl[o] = sc[R], ln[R] + sl[L]
            else:
                sc[o], sl[o] = sc[R], sl[R]
            bridge = sl[L] + pl[R] if sc[L] == pc[R] else 0
            mx[o] = max(mx[L], mx[R], bridge)

        for o in range(size - 1, 0, -1):
            pushup(o)

        ans = []
        for c, pos in zip(queryCharacters, queryIndices):
            o = size + pos
            pc[o] = sc[o] = c
            o >>= 1
            while o:          # 叶→根逐层 pushup
                pushup(o)
                o >>= 1
            ans.append(mx[1])
        return ans
```

> 💡 Python 版用**迭代自底向上**写法：叶子定在 $2 \cdot \text{size}$ 数组的 $\text{size} + i$，更新后 `o >>= 1` 一路向根 `pushup`。补齐 2 的幂引入的空叶子（段长 0）在 `pushup` 里做恒等元处理，占位字符用空串，绝不与真实小写字母判等。

## 8. 边界情况与易错点

1. **桥接忘判字符相等**（最高频 bug）：`sc[L] == pc[R]` 不成立时桥长必须记 0。反例：$L = $ `ab`、$R = $ `ab`，拼成 `abab` 最长 run 是 1；不判字符会桥出错误的 2。

2. **前缀延伸漏判「整段同字符」**：`pl[L] == len[L]` 是延伸的前提。反例：$L = $ `ab`（前缀 run 仅 `a`×1）、$R = $ `ac`，直接拼接会把父亲前缀算成 `a`×2，实际 `abac` 的前缀 run 只有 1。

3. **叶子初始化**：叶子的 `pl/sl/mx` 必须初始化为 1 而非 0（初始化成 0 会让所有桥长与 `mx` 系统性偏小）；`update` 命中叶子时只需改两个字符字段。

4. **更新为相同字符**：$s[pos] = c$ 时无需特判——照常走 $O(\log n)$ 路径重算恒正确；若想省这次重算，也必须照常输出当前答案（例如示例 3 的第 2 次查询），别把「跳过更新」误写成「跳过输出」。

5. **`n = 1`**：树退化成单个叶子。递归版 `4n` 数组下标安全（大小 4），迭代版 `size = 1` 时根即叶（节点 1），更新后 `o >>= 1` 直接为 0 跳过循环，`mx[1]` 恒为 1——两种写法都要专门过一遍这个 case。

6. **迭代版的空叶子**：补齐 2 的幂后 $[n, \text{size})$ 的叶子段长为 0，`pushup` 遇空儿子必须直接取另一侧；占位字符若用真实字母（如 `'a'`），会在桥接判等时污染结果，用空串或非字母哨兵最稳。

7. **别再扫一遍全串**：每次更新后根的 `mx` 就是答案，$O(1)$ 读走即可；任何「更新后重新遍历」都把复杂度打回 $O(nk)$。

8. **递归深度**：$\lceil \log_2 10^5 \rceil = 17$ 层，C++ / Python 均无栈风险（Python 默认上限 1000）。

**延伸思考**：

- **有序集合路线的实现细节**：`map<int, char>` 存每个 run 的起点与字符，`multiset<int>` 存所有 run 长度。单点修改 $pos$：定位 $pos$ 所在 run，至多拆成三段、再与左右邻居各至多合并一次；每次结构变动都要从 `multiset` 中删除旧长度、插入新长度（注意等长删除时 `multiset.erase(key)` 会把同键全删，应先 `find` 再删迭代器）。答案取 `*multiset.rbegin()`。
- **升级为区间查询**：若每次问「区间 $[l, r]$ 内最长单字符子串」，把查询也写成一次 $O(\log n)$ 的线段树递归——沿途把完整覆盖的节点五元组按同一套 `merge` 拼起来即可，这正是 SPOJ GSS 系列的经典形态；平衡树路线则要拆区间后手工拼接 run，边界繁琐得多。
- **升级为区间赋值**：若操作变成「把一段区间全改成字符 $c$」，需要真正的区间覆盖懒标记 + `pushdown`（整段覆盖时五元组可 $O(1)$ 直接算出：`pref = suf = mx = len`），本题的 pushup-only 骨架升级为完整线段树。
