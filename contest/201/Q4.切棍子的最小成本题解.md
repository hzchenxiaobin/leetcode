# LeetCode 切棍子的最小成本 题解

## 1. 题目概述

- **标题 / 题号**：切棍子的最小成本（#1547，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-cut-a-stick/
- **来源**：LeetCode 第 201 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、区间 DP、排序

**题意**：一根长为 $n$ 的木棍，按原坐标标记 $0 \sim n$。给定互不相同的整数数组 `cuts`，需要把棍子在这些位置上**各切一刀**。每次切割的成本 = **被切木棍当时的长度**，切开后得到两根短棍，切出的两段长度之和等于切割前的长度。切割顺序可以任意安排，求总成本的最小值。

**约束**：

- $2 \le n \le 10^6$
- $1 \le cuts.length \le \min(n-1, 100)$
- $1 \le cuts[i] \le n - 1$，且 `cuts` 中所有整数互不相同

> 💡 关键信号：$n$ 高达 $10^6$，但切割点**最多 100 个**——复杂度必须只依赖 $m = len(cuts)$，这强烈暗示要在「切割点构成的坐标体系」上做文章，而不是在原坐标 $0 \sim n$ 上。

## 2. 示例

**示例 1**

```text
输入：n = 7, cuts = [1,3,4,5]
输出：16
解释：按 [3, 5, 1, 4] 的顺序切割：7 + 4 + 3 + 2 = 16；
      按给定顺序 [1, 3, 4, 5] 切割：7 + 6 + 4 + 3 = 20。
```

**示例 2**

```text
输入：n = 9, cuts = [5,6,1,4,2]
输出：22
解释：按给定顺序切割为 25，重排顺序后可以降到 22。
```

## 3. 解题思路

### 3.1 暴力思路：枚举顺序

最直接的想法是枚举所有 $m!$ 种切割顺序并逐一模拟，$m = 100$ 时这是天文数字，毫无希望。

退一步用贪心：「每刀尽量切在最长段的中点附近」。以示例 1 为例（整根中点是 $3.5$，切 $3$ 和切 $4$ 「一样居中」），若第一刀切在 $4$，可以验证**无论后续怎么切，总成本最少是 $7 + 7 + 3 = 17$**（把 $[0,4]$ 内的 $1,3$ 切完最少 $7$，把 $[4,7]$ 内的 $5$ 切完 $3$），而先切 $3$ 能到 $16$——同样「居中」的两个位置，全局代价却不同。局部信息（哪刀更居中）分辨不出全局优劣，贪心失效。

### 3.2 核心观察：每刀成本只取决于「所在段」

![核心观察：每刀成本 = 所在段的原坐标长度](images/wc201_q4_interval_dp_concept.svg)

盯住任何一根「当前木棍」，它对应原坐标上的一个区间 $[l, r]$，有两个性质：

- **端点不变**：任意时刻每根现存木棍的端点都来自 $\{0, n\} \cup cuts$（初始为 $[0, n]$；每切一刀，切点成为新端点，而切点 $\in cuts$）。
- **成本局部**：在段 $[l, r]$ 内切一刀的成本恰为 $r - l$——**原坐标差**，与之前发生过什么完全无关。

于是「在段 $[l, r]$ 内切一刀」这个动作可以抽象成：**支付 $r - l$，把区间 $[l, r]$ 拆成 $[l, p]$ 与 $[p, r]$**。切完之后左右两段互不影响：后续在左段的任何切割不改变右段的任何成本。

问题天然变成**在「切割点 + 哨兵」构成的坐标序列上做区间 DP**：把 `cuts` 排序，首尾补上哨兵 $0$ 和 $n$，得到长度为 $m+2$ 的递增数组

$$c = [c_0, c_1, \dots, c_m, c_{m+1}] = [0, \text{排序后的 cuts}, n]$$

### 3.3 状态转移：枚举「第一刀」

![区间 DP 状态转移](images/wc201_q4_dp_transition.svg)

**状态**：$dp[i][j]$ = 把所有落在开区间 $(c_i, c_j)$ 内的切割点切完的最小成本（当前木棍是完整的 $[c_i, c_j]$ 段）。

**转移**：枚举这段木棍的**第一刀**切在 $c_k$（$i < k < j$）：

$$dp[i][j] = (c_j - c_i) + \min_{i < k < j} \big( dp[i][k] + dp[k][j] \big)$$

- 第一刀的成本是 $c_j - c_i$：切这一刀时木棍还完整；
- 之后左右两段独立，各自取最优子问题；
- 反过来，左右两边各自的任意合法方案拼接起来仍是合法方案，所以取 $\min$ 恰好不重不漏。

**边界**：$dp[i][i+1] = 0$（相邻两点之间没有切割点，无事可做）。

**答案**：$dp[0][m+1]$（整根木棍 $[0, n]$）。

**实现顺序**：自底向上按区间长度 $L = j - i$ 从 $2$ 到 $m+1$ 枚举；或自顶向下写记忆化递归，更贴近思路本身、不易错。

### 3.4 示例演算

![示例 1 的 dp 表演算](images/wc201_q4_example_walkthrough.svg)

以示例 1 为例：$c = [0, 1, 3, 4, 5, 7]$，按长度 $L$ 从小到大填表（只列 $j > i$ 的有效格）：

| $dp[i][j]$ | $j=1$ | $j=2$ | $j=3$ | $j=4$ | $j=5$ |
|--------|-----|-----|-----|-----|-----|
| $i=0$  | 0   | 3   | 7   | 10  | **16** |
| $i=1$  |     | 0   | 3   | 6   | 12  |
| $i=2$  |     |     | 0   | 2   | 6   |
| $i=3$  |     |     |     | 0   | 3   |
| $i=4$  |     |     |     |     | 0   |

关键看答案格：

$$dp[0][5] = 7 + \min\{0+12,\ 3+6,\ 7+3,\ 10+0\} = 7 + 9 = 16$$

最小值在 $k = 2$ 取得——**第一刀切在 $c_2 = 3$**。沿最优分割点回溯：$dp[2][5]$ 选 $k=4$（切 $5$），$dp[0][2]$ 选 $k=1$（切 $1$），$dp[2][4]$ 选 $k=3$（切 $4$），得到最优顺序 $[3, 5, 1, 4]$（或等价的 $[3, 1, 5, 4]$），成本 $7 + 4 + 3 + 2 = 16$。

## 4. 算法细节

1. **哨兵技巧**：`cuts` 排序后首尾补 `0` 和 `n`，得到长度 $m+2$ 的数组 $c$。这一步把「边界上没有切点的段」与普通段统一处理，并把规模从 $n$ 解耦到 $m$，是全题最重要的工程化一步。
2. **为什么「枚举第一刀」直接可行**：第一刀的成本恰是当前区间长度 $c_j - c_i$，**在转移时就已经确定**；切完后左右子问题完全独立。对比 [312. 戳气球](https://leetcode.cn/problems/burst-balloons/)：戳破气球的得分依赖**左右邻居**（区间外信息），「第一戳」的成本无法在转移时确定，必须改枚举「最后一戳」——这是区间 DP 两种经典建模的分水岭。
3. **枚举顺序**：自底向上必须按区间长度 $L = j - i$ 从小到大（$L$ 从 $2$ 起，$L=1$ 是边界 $0$）；若直接双重循环 $i, j$ 而不控制长度，转移会读到尚未计算的格子。
4. **记忆化递归**：自顶向下 `dp(i, j)` 遇到 $j - i \le 1$ 返回 $0$，最不容易写错；递归深度 $\le m + 2 \le 102$，无栈风险。
5. **规模解耦**：所有数组只开 $O(m^2)$，$n \le 10^6$ 只出现在 $c_j - c_i$ 的数值里，**千万不要**开任何 $O(n)$ 的数组。
6. **答案上界**：每刀成本 $\le n$、共 $m$ 刀，总成本 $\le n \cdot m \le 10^8$，`int` 恰好装得下（$< 2^{31} - 1 \approx 2.1 \times 10^9$），但 C++ 建议用 `long long` 留余量。

## 5. 正确性证明

**引理 1（区间不变式）**：切割过程中的任何时刻，所有现存木棍构成 $[0, n]$ 的一个划分，且每根木棍的两个端点都属于 $S = \{0, n\} \cup cuts$。

**证明**：对切割次数归纳。$0$ 次时划分为 $\{[0, n]\}$，端点 $0, n \in S$，成立。设某时刻命题成立，下一次切割在段 $[l, r]$ 内的位置 $p$ 进行（$p \in cuts$，$l < p < r$）：划分中 $[l, r]$ 被替换为 $[l, p]$ 与 $[p, r]$，新端点 $p \in S$，其余段不动，命题仍成立。∎

**推论 1.1（成本的区间表示）**：在段 $[l, r]$ 内切的一刀，成本恰为 $r - l$。即每刀成本只由这一刀**当时所在段**的两个端点决定，而段的端点自产生起不再变化。

**引理 2（独立分解）**：任一合法切割方案 $\sigma$ 中，设在完整段 $[c_i, c_j]$ 上的第一刀切在 $c_k$，则

$$cost(\sigma) = (c_j - c_i) + cost(\sigma_L) + cost(\sigma_R)$$

其中 $\sigma_L, \sigma_R$ 是 $\sigma$ 在左右两段上的限制；反之，左段的任一合法方案与右段的任一合法方案可以**自由拼接**成一个整体合法方案。

**证明**：第一刀时该段完整，由推论 1.1 成本为 $c_j - c_i$。此后每一刀都在某个小段内进行，成本由该小段自身的端点决定（推论 1.1），而左右两段的端点集合互不相交、各自不变，故两部分成本互不依赖、逐刀相加即总和。拼接方向：切割之间没有任何次序约束（每刀成本只看所在段），先执行完左段方案再执行右段方案（或任意交错）都是合法切割序列，成本相同。∎

**定理**：$dp[i][j]$ 等于「把 $(c_i, c_j)$ 内所有切割点切完」的最小成本，且转移方程正确。

**证明**：对区间长度 $L = j - i$ 归纳。

- $L = 1$：内部无切割点，无需切割，$dp[i][i+1] = 0$ 正确。
- $L \ge 2$：内部至少含一个切割点，最优方案存在且第一刀切在某 $c_k$（$i < k < j$）。由引理 2 与归纳假设（左右子区间长度严格更小），
  $cost(\sigma^*) = (c_j - c_i) + cost(\sigma_L^*) + cost(\sigma_R^*) \ge (c_j - c_i) + dp[i][k] + dp[k][j] \ge$ 方程右端；
  反之取达到 $\min$ 的 $k^*$，把左右两边的最优子方案按引理 2 拼接并先切 $c_{k^*}$，得到成本恰为方程右端的合法方案。两个方向夹逼，转移方程成立。∎

答案 $dp[0][m+1]$ 对应完整木棍 $[0, n]$，即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m^3)$。有效状态 $O(m^2)$ 个（$0 \le i < j \le m+1$），每个状态枚举第一刀的位置至多 $O(m)$ 次；$m \le 100$，总量 $\le 10^6$。
- **空间复杂度**：$O(m^2)$，即 $(m+2)^2$ 的 dp 表；记忆化写法同阶（递归栈 $O(m)$）。
- 与 $n$ **无关**：$n$ 只出现在 $c_j - c_i$ 的数值计算中——这正是排序 + 哨兵带来的规模解耦。

## 7. 参考代码

### C++（自底向上）

```cpp
class Solution {
public:
    int minCost(int n, vector<int>& cuts) {
        cuts.push_back(0);
        cuts.push_back(n);
        sort(cuts.begin(), cuts.end());
        int m = cuts.size();
        vector<vector<int>> dp(m, vector<int>(m, 0));
        for (int len = 2; len < m; len++) {
            for (int i = 0; i + len < m; i++) {
                int j = i + len;
                int best = INT_MAX;
                for (int k = i + 1; k < j; k++) {
                    best = min(best, dp[i][k] + dp[k][j]);
                }
                dp[i][j] = cuts[j] - cuts[i] + best;
            }
        }
        return dp[0][m - 1];
    }
};
```

### Python（记忆化）

```python
from functools import lru_cache
from typing import List


class Solution:
    def minCost(self, n: int, cuts: List[int]) -> int:
        c = sorted(cuts + [0, n])

        @lru_cache(None)
        def dp(i: int, j: int) -> int:
            if i + 1 >= j:
                return 0
            return c[j] - c[i] + min(dp(i, k) + dp(k, j) for k in range(i + 1, j))

        return dp(0, len(c) - 1)
```

## 8. 边界情况与易错点

1. **忘记排序**：`cuts` 不保证有序（示例 2 就是 `[5,6,1,4,2]`），不排序则 $c$ 非递增，所有转移作废。
2. **忘记哨兵**：不补 `0` 和 `n`，最左段（$[0, c_1]$）与最右段无法进入 dp，答案错。
3. **长度枚举从 2 开始**：$L=1$（相邻点对）内部无切割点，成本为 $0$；若误从 $L=1$ 进入转移，内层 `k` 循环为空，`min` 作用于空集（C++ 里 `INT_MAX` 再加长度直接溢出）。
4. **答案取 `dp[0][m+1]`**：即哨兵 $0$ 与 $n$ 之间那一格；误取 `dp[0][m]` 会漏掉最右段。
5. **别开 $O(n)$ 数组**：$n \le 10^6$，任何以 $n$ 为规模的数组或 DP 都会超时/超内存；规模全部按 $m \le 100$ 来。
6. **溢出**：总成本上界 $n \cdot m \le 10^8$，`int` 能装但不宽裕，C++ 建议 `long long`；Python 无此问题。
7. **哨兵与切割点重合**：题目保证 $1 \le cuts[i] \le n-1$，不会等于 $0$ 或 $n$，`cuts + [0, n]` 不会产生重复元素；若自己改造题面（允许 $cuts[i] = 0$），需要先去重。
8. **记忆化判空条件**：`i + 1 >= j`（相邻或交叉即无内部切割点）；写成 `i >= j` 会引入多余的非法状态，浪费但不致错，写成 `i == j` 则漏判相邻情形。

**延伸思考**：

- **能否降到 $O(m^2)$？** 转移形如 $dp[i][j] = w(i,j) + \min_k \{dp[i][k] + dp[k][j]\}$，且权 $w(i,j) = c_j - c_i$ 满足四边形不等式，可用 **Knuth–Yao（四边形不等式）优化**：为每格记录取得最优的分割点 $k$，下一层枚举范围被夹在相邻层的最优分割点之间，总时间降到 $O(m^2)$——与矩阵链乘法的优化完全同构。
- **和哈夫曼树为什么不同？** 哈夫曼/合并棒材类问题的「合并」成本结构满足贪心选择性质（最小的两堆一定在某最优解中最先合并）；而「拆分」成本（每刀 = 当前段长）里，切哪个点最划算取决于切完之后两侧的后续成本，局部比较无法闭环，只能交给 DP。
