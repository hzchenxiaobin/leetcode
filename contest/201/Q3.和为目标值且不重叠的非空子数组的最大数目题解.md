# LeetCode 和为目标值且不重叠的非空子数组的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：和为目标值且不重叠的非空子数组的最大数目（#1546，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-non-overlapping-subarrays-with-sum-equals-target/
- **来源**：LeetCode 第 201 场周赛 Q3
- **难度**：中等
- **标签**：贪心、前缀和、哈希表、数组

**题意**：给定整数数组 `nums` 与整数 `target`，从中选出尽可能多的子数组，要求：每个子数组**非空**、元素和恰为 $target$、且任意两个子数组**互不重叠**（不共用任何下标）。返回能选出的最大数目。

**约束**：

- $1 \le nums.length \le 10^5$
- $-10^4 \le nums[i] \le 10^4$
- $0 \le target \le 10^6$

> 💡 两个关键信号：其一，$nums[i]$ **可正可负**，窗口和随端点移动不再单调，**滑动窗口失效**——子数组定位必须回到「前缀和 + 哈希表」；其二，「不重叠」意味着每选中一个子数组，数组就在其右端点处被**剪断**，之后是同构的子问题——「按右端点贪心」的区间调度直觉呼之欲出。两个信号叠加，就是本题的完整骨架。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,1,1,1], target = 2
输出：2
解释：选下标 (0,1) 与 (2,3)（或 (3,4)）处的两个 [1,1]，
      互不重叠且各和为 2，最多选 2 个。
```

**示例 2**

```text
输入：nums = [-1,3,5,1,4,2,-9], target = 6
输出：2
解释：和为 6 的子数组共 3 个：[5,1]、[4,2]、[3,5,1,4,2,-9]，
      但只有前 2 个能互不重叠地共存。
```

**示例 3**

```text
输入：nums = [-2,6,6,3,5,4,1,2,8], target = 10
输出：3
```

**示例 4**

```text
输入：nums = [0,0,0], target = 0
输出：3
解释：三个单元素子数组 [0]、[0]、[0] 互不重叠，和均为 0。
      注意 target = 0 时「空子数组」的和也是 0，但题目要求非空。
```

## 3. 解题思路

### 3.1 暴力思路：先枚举区间，再做区间调度

子数组和可用前缀和 $O(1)$ 判定，于是可以枚举全部 $O(n^2)$ 个子数组，筛出和为 $target$ 的**候选区间**；再在这些区间上做经典的**区间调度**（按右端点排序，每步选结束最早且不与已选重叠的区间），得到答案。总复杂度 $O(n^2 \log n)$。

$n = 10^5$ 时候选数最坏达 $\binom{10^5}{2} \approx 5 \times 10^9$，光是枚举就已出局。问题出在「生成区间」与「挑选区间」两步割裂：我们其实不需要知道**所有**候选，只需要在每个位置回答一个比特——「有没有候选在这里结束」。

### 3.2 核心观察：命中即拿、拿完即剪

![核心观察：命中即拿、拿完即剪](images/wc201_q3_greedy_cut_concept.svg)

**观察一（$O(1)$ 定位）**：记前缀和 $pre[k] = nums[0] + \dots + nums[k-1]$（$pre[0] = 0$），则子数组 $nums[j..k-1]$ 的和为 $pre[k] - pre[j]$。于是「存在以元素 $k-1$ 为右端点的候选」$\iff pre[k] - target \in \{pre[0], \dots, pre[k-1]\}$——一个哈希集合就能 $O(1)$ 回答，负数完全不构成障碍。

**观察二（右端点决定一切）**：一个已被选中的子数组，对未来唯一的封锁是它的**右端点**：之后的子数组只能从右端点之后开始；至于选中区间自身多长、从哪里开始，未来毫不关心。因此「结束得越早，留给后面的余地越大」——扫描中一旦出现命中，**立即拿走**必然不亏（严格论证见 §5 的交换论证）。

**观察三（剪断重启）**：拿走一个以 $i$ 为右端点的子数组后，剩余问题就是**同一问题在 $nums[i+1..]$ 上的实例**。实现上不必真的切数组：把「自上次剪断起的元素和」记为 $cur$、见过的相对前缀集合记为 $seen$（初始 $\{0\}$），命中时 $cur \leftarrow 0$、$seen \leftarrow \{0\}$ 即完成重启。

### 3.3 算法流程：一次扫描，命中即剪断重启

![算法流程：单次扫描，命中即剪断重启](images/wc201_q3_scan_flow.svg)

1. 初始化 $ans = 0$、$cur = 0$、$seen = \{0\}$（$0$ 代表「空前缀」，保证从下标 0 开始的子数组能被匹配到）。
2. 从左到右扫描每个元素 $x$：$cur \leftarrow cur + x$。
3. **先查后插**：若 $cur - target \in seen$——命中，$ans \leftarrow ans + 1$，剪断重启（$cur \leftarrow 0$，$seen \leftarrow \{0\}$）；否则把 $cur$ 插入 $seen$。
4. 扫描结束，返回 $ans$。

> ⚠️ 「先查后插」是正确性的一部分：判断发生在插入 $cur$ **之前**，保证命中时匹配到的前缀严格早于当前位置，子数组**非空**——$target = 0$ 时这是生死线（见 §8）。

### 3.4 示例演算

![示例演算：nums = [-1,3,5,1,4,2,-9], target = 6](images/wc201_q3_example_walkthrough.svg)

以示例 2 走查（$target = 6$）：

| $i$ | $x$ | $cur$ | $cur-6$ | 命中？ | $seen$（检查后） | 动作 |
|-----|-----|-------|---------|--------|------------------|------|
| 0 | $-1$ | $-1$ | $-7$ | 否 | $\{0, -1\}$ | 累积 |
| 1 | $3$  | $2$  | $-4$ | 否 | $\{0, -1, 2\}$ | 累积 |
| 2 | $5$  | $7$  | $1$  | 否 | $\{0, -1, 2, 7\}$ | 累积 |
| 3 | $1$  | $8$  | $2$  | **是** | 重置为 $\{0\}$ | ✂ 选中 $[5,1]$，$ans=1$ |
| 4 | $4$  | $4$  | $-2$ | 否 | $\{0, 4\}$ | 累积 |
| 5 | $2$  | $6$  | $0$  | **是** | 重置为 $\{0\}$ | ✂ 选中 $[4,2]$，$ans=2$ |
| 6 | $-9$ | $-9$ | $-15$ | 否 | $\{0, -9\}$ | 累积 |

注意最后一步：候选 $[3,5,1,4,2,-9]$ 的和也是 6，若没有剪断清空，它会在 $i=6$ 被错误计入（跨越剪断点、与已选重叠）——**清空 $seen$ 正是「不重叠」约束的化身**。最终 $ans = 2$。

## 4. 算法细节

1. **相对前缀与全局前缀的换算**：设剪断后下一个可用起点为 $c$（初始视为数组开头），则 $cur = pre$ 在当前段的相对值，$seen = \{$剪断点之后所有历史相对前缀$\} \cup \{0\}$。两边同加剪断点处的全局前缀，检查式 $cur - target \in seen$ 与全局口径逐点等价——**「剪断重启」在状态上恰等于「把同一算法原封不动跑在后缀上」**，这正是 §5 归纳证明在实现上的落点。
2. **先查后插**：命中时匹配到的 $j$ 满足 $j <$ 当前位置，子数组非空。若先插后查，$target = 0$ 时每步 $cur - 0 = cur$ 必在 $seen$ 中，连空子数组都会被计数（$nums = [1,2], target = 0$ 会错答 2，正确为 0）。
3. **命中时不必区分匹配到哪个 $j$**：同一右端点可能对应多个候选（如 $nums = [0,0,6], target = 6$ 在末位同时有 $[0,0,6]$、$[0,6]$、$[6]$）。无论拿哪一个，未来可用信息完全相同（都只要求后续从当前位置之后开始），所以算法只需「命中/未命中」一比特，**无需记录具体区间**——这与区间调度中「同一右端点的多条区间任选其一」同构。
4. **两种等价的重置写法**：相对口径 $cur \leftarrow 0,\ seen \leftarrow \{0\}$，或全局口径 $seen \leftarrow \{sum\}$（$sum$ 为全局前缀和，不再清零 $sum$）。两者逐点等价（相差常数），本文采用前者，因为它让「重启 = 在后缀上重跑」一目了然。
5. **数值范围**：$|cur| \le 10^5 \times 10^4 = 10^9 < 2^{31} - 1 \approx 2.15 \times 10^9$，`int` 恰好装得下但没有余量；$cur - target$ 至多再偏 $10^6$，仍在范围内。C++ 建议直接用 `long long` 免去心智负担，Python 无此问题。
6. **等价的 DP 写法**（对照理解贪心）：$dp[k] = \max\big(dp[k-1],\ dp[j] + 1\big)$，其中 $j$ 为满足 $pre[j] = pre[k] - target$ 的**最后一个**下标（用哈希表维护前缀和最后出现位置；$dp$ 单调不减，故取最后出现即最优）。同为 $O(n)$；贪心可视为该 DP 的「立即兑现」版——一旦能 $+1$ 就落袋，并把检索范围重置到剪断点之后。

## 5. 正确性证明

**约定**：区间为元素下标的闭区间；称和为 $target$ 的非空子数组为**候选**；$pre[k]$ 定义同 §3.2。

**引理 1（前缀和刻画）**：对 $0 \le j < k \le n$，子数组 $nums[j..k-1]$ 是候选 $\iff pre[k] - pre[j] = target$。

**证明**：$pre[k] - pre[j] = nums[j] + \dots + nums[k-1]$，即该子数组之和。∎

**引理 2（最早右端点至多一个冲突）**：设 $b$ 是所有候选中最小的右端点，$G = [a, b]$ 是任一右端点为 $b$ 的候选。则任意一组两两不交的候选中，与 $G$ 相交的成员至多一个。

**证明**：反设组内两个不同候选 $[s_1, t_1]$、$[s_2, t_2]$ 都与 $G$ 相交。由 $b$ 的最小性，$t_1 \ge b$ 且 $t_2 \ge b$；由与 $[a, b]$ 相交（注意 $t_i \ge b \ge a$ 自动满足），得 $s_1 \le b$ 且 $s_2 \le b$。两者不交，不妨设 $t_1 < s_2$，则 $b \le t_1 < s_2 \le b$，矛盾。∎

**定理（贪心最优性）**：「从左到右扫描，一旦存在以当前位置为右端点的候选就立即选取并剪断，之后仅在剩余后缀上继续」的贪心，输出等于最优值。

**证明**：对 $n$ 归纳。$n = 0$ 时无候选，贪心与最优同为 $0$。

设 $n \ge 1$。若全数组无候选，两边同为 $0$；否则设 $b$ 为最小右端点。

**(1) 贪心首个命中恰在 $b$**。由引理 1，处理完元素 $k-1$ 后，「存在右端点为 $k-1$ 的候选」$\iff pre[k] - target \in \{pre[0], \dots, pre[k-1]\}$；首次剪断前，$cur$、$seen$ 与全局前缀逐点换算相等（§4.1），故首次命中发生在最小的这样的 $k$，即右端点 $b$。先查后插保证命中的候选非空。于是贪心选中某个右端点为 $b$ 的候选 $G$ 并剪断；由 §4.1，剪断后的状态恰是在后缀 $nums[b+1..]$ 上从头运行同一算法的状态，故贪心总值 $= 1 + \text{greedy}(nums[b+1..])$。

**(2) 交换**。任取最优解 $OPT$（一组两两不交的候选）。$OPT$ 中与 $G$ 相交的成员至多一个（引理 2），记为 $O^*$。$O^*$ 必存在：否则 $OPT \cup \{G\}$ 仍两两不交且更大，与最优性矛盾（$G$ 本身是候选，故 $|OPT| \ge 1$）。构造 $OPT' = (OPT \setminus \{O^*\}) \cup \{G\}$：$G$ 与 $OPT \setminus \{O^*\}$ 的每个成员不相交（引理 2），其余成员间原不相交，故 $OPT'$ 合法且 $|OPT'| = |OPT|$。

**(3) 归结为后缀**。$OPT' \setminus \{G\}$ 中每个成员 $[s, t]$ 与 $G$ 不交且 $t \ge b$（$b$ 最小性），故必有 $s > b$（若 $s \le b$，则由 $t \ge b \ge a$ 知其与 $[a, b]$ 相交，矛盾）——即它们全部落在 $nums[b+1..]$ 上，构成后缀问题的可行解，大小为 $|OPT| - 1$。由归纳假设（后缀长度 $< n$），$\text{greedy}(nums[b+1..]) \ge |OPT| - 1$。于是贪心总值 $\ge |OPT|$；又贪心结果是可行解，$\le |OPT|$。故相等。∎

**备注（实现与证明的同构）**：引理 2 成立的根源正是观察二——同右端点的候选对未来无差别，而更晚的右端点只会封锁更多；「清空 $seen$」丢弃剪断点之前的全部前缀，恰好禁止了任何跨剪断点的候选，使代码与上述归纳逐字对应。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单次线性扫描，每个元素触发一次均摊 $O(1)$ 的哈希集合查询/插入；命中时的重置所丢弃的元素也是先前逐个放入的，均摊仍为 $O(1)$。
- **空间复杂度**：$O(n)$。$seen$ 在两次剪断之间最多累积当前段长度个前缀，最坏（全程无命中）为 $n$ 个。
- 对比暴力 $O(n^2 \log n)$：把「生成全部候选 + 排序调度」折叠成了「边扫描边判定、命中即消费」，省下的正是那些永远不会被选中的候选。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxNonOverlapping(vector<int>& nums, int target) {
        int ans = 0;
        long long cur = 0;
        unordered_set<long long> seen{0};
        for (int x : nums) {
            cur += x;
            if (seen.count(cur - target)) {   // 先查
                ans++;
                cur = 0;                      // 命中：不插入，直接剪断重启
                seen = {0};
            } else {
                seen.insert(cur);             // 后插
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxNonOverlapping(self, nums: List[int], target: int) -> int:
        ans, cur, seen = 0, 0, {0}
        for x in nums:
            cur += x
            if cur - target in seen:      # 先查后插
                ans += 1
                cur, seen = 0, {0}         # 剪断重启
            else:
                seen.add(cur)
        return ans
```

## 8. 边界情况与易错点

1. **先查后插的顺序**：必须先判断 $cur - target \in seen$、再把 $cur$ 插入。若先插后查，$target = 0$ 时连空子数组都会被计数：$nums = [1,2], target = 0$ 会错答 2（正确 0）。
2. **$seen$ 必须含初始 $0$**：它代表「空前缀」。缺失时从下标 0 开始的候选永远匹配不到：$nums = [6], target = 6$ 会错答 0（正确 1）。
3. **剪断必须清空 $seen$**：若保留全局前缀不清（贪心却照做），示例 2 中 $i = 6$ 时 $5 - 6 = -1$ 命中旧前缀，把跨越剪断点的 $[3,5,1,4,2,-9]$ 计入，错答 3。清空的力度要彻底——只留新段自己的前缀。
4. **别用滑动窗口**：$nums[i]$ 可为负，窗口和随端点移动不单调，「收缩使和趋向 target」的推理失效。前缀和 + 哈希不受负数影响。
5. **溢出**：$|cur| \le 10^9$ 贴着 `int` 上限，C++ 用 `long long` 最稳；Python 无此问题。
6. **$target = 0$ 与全零数组**：$nums = [0,0,0], target = 0$ 答案为 3（三个单元素子数组）；「先查后插」口径下算法自然正确，无需特判。
7. **只计数，不构造**：命中时无需记录具体选中了哪段（§4.3），试图维护区间反而增加代码量与出错面；需要输出方案时再升级为哈希映射（见延伸思考）。
