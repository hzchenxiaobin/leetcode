# LeetCode 可以攻击国王的皇后 题解

## 1. 题目概述

- **标题 / 题号**：可以攻击国王的皇后（#1222，medium）
- **链接**：https://leetcode.cn/problems/queens-that-can-attack-the-king/
- **来源**：LeetCode 第 158 场周赛 Q2
- **难度**：中等
- **标签**：数组、矩阵、模拟

**题意**：在一个下标从 0 开始的 $8 \times 8$ 棋盘上放着若干黑皇后与一个白国王。皇后沿 8 个方向（上、下、左、右、四条对角）走任意格，但**不能越过其他棋子**。若皇后与国王同行、同列或同对角线，且两者之间没有任何别的皇后，该皇后就能**直接攻击**国王。返回所有这样的皇后坐标，顺序任意。

**约束**：

- $1 \le \text{queens.length} < 64$：皇后至多 63 枚，同一格不会有两枚皇后
- `queens[i].length == king.length == 2`，坐标为 `[x, y]`
- $0 \le x_{\text{Queen}}, y_{\text{Queen}}, x_{\text{King}}, y_{\text{King}} < 8$
- 所有给定位置互不相同（皇后之间、皇后与国王之间都不重合）

> 💡 Q2 的定位是「8 方向模拟」模板题。它真正考的不是搜索，而是**能不能把「攻击」翻译成「射线上第一枚」**：想清楚这一点，代码只有十几行，复杂度与皇后数量线性相关。

## 2. 示例

**示例 1**

```text
输入：queens = [[0,1],[1,0],[4,0],[0,4],[3,3],[2,4]], king = [0,0]
输出：[[0,1],[1,0],[3,3]]
解释：(0,1) 在正下方、(1,0) 在正右方、(3,3) 在右下对角线上，三枚都直接相邻无遮挡；
      (4,0) 与 (0,4) 分别在 (1,0)、(0,1) 的后面，被挡住；
      (2,4) 与国王既不同行同列，也不在对角线上。
```

**示例 2**

```text
输入：queens = [[0,0],[1,1],[2,2],[3,4],[3,5],[4,4],[4,5]], king = [3,3]
输出：[[2,2],[3,4],[4,4]]
解释：左上方 (2,2) 最近，它挡住了更远的 (1,1)、(0,0)；
      正右方 (3,4) 最近，它挡住了 (3,5)；右下方 (4,4) 最近，它挡住了 (4,5)。
```

两个示例给出同一个信号：**同一个方向上往往有多个皇后，但只有最靠前的那一枚算数**。

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举所有皇后 $q$，再枚举另一枚皇后 $r$，判断 $r$ 是否夹在国王与 $q$ 之间。判定共线可以用向量叉积，判断「夹在中间」还要比较投影长度：

$$ (x_q - x_k)(y_r - y_k) = (x_r - x_k)(y_q - y_k), \quad 0 < (x_r - x_k)(x_q - x_k) + (y_r - y_k)(y_q - y_k) < (x_q - x_k)^2 + (y_q - y_k)^2 $$

单次判定 $O(1)$，总体 $O(m^2)$。本题 $m < 64$，$m^2 < 4096$，**其实完全跑得过**。但这份代码要处理叉积、同向、距离三重条件，容易写错符号，也没有利用「答案至多 8 个」这一强结构。既然棋盘只有 $8 \times 8$，不如直接从国王出发做射线扫描。

### 3.2 核心观察：答案只可能来自 8 条射线

![8 条射线与遮挡关系](images/wc158_q2_attack_rays.svg)

行、列、两条对角线，从国王看出去正好是 **8 条射线**。把「攻击」拆成两个条件：

1. **共线**：皇后必须落在某条射线上，即 $(x_q - x_k, y_q - y_k)$ 与某个方向向量 $(dx, dy) \in \{-1,0,1\}^2 \setminus \{(0,0)\}$ 同向。
2. **无遮挡**：国王与该皇后之间不能有第三枚皇后。

由条件 2 立刻得到一个关键推论：**同一条射线上，只有离国王最近的那枚皇后可能攻击**。若射线上有 $q_1, q_2$（$q_1$ 更近），则 $q_1$ 严格夹在国王和 $q_2$ 之间，$q_2$ 必定被挡住。

于是答案规模天然 $\le 8$，问题退化为：**对 8 个方向，各找射线上第一枚皇后**。这正是官方提示 "Check 8 directions around the King / Find the nearest queen in each direction" 的含义。

### 3.3 算法流程

![射线扫描流程](images/wc158_q2_raycast_flow.svg)

1. 开一个 $8 \times 8$ 的布尔数组 `board`，把所有皇后所在格子标为 `true`（国王的位置不必特殊处理，它不会是皇后）。
2. 枚举 8 个方向：`dx, dy` 各自取 $-1, 0, 1$，跳过 `(0, 0)`。
3. 对每个方向，从 $(x_k + dx,\; y_k + dy)$ 起步，每步加上 $(dx, dy)$：
   - 坐标越界 → 该方向结束，没有皇后；
   - 当前格是皇后 → 记录坐标，**立即 `break`**，该方向结束；
   - 否则继续前进。
4. 8 个方向都走完，返回记录下来的坐标。

射线长度不超过 7，所以扫描本身最多 $8 \times 7 = 56$ 次判断。

> 💡 **等价解法（以皇后为中心）**：也可以反过来遍历皇后，对每枚皇后算 $dr = x_q - x_k$、$dc = y_q - y_k$；若 $dr = 0$ 或 $dc = 0$ 或 $|dr| = |dc|$，方向键取 $(\text{sign}(dr), \text{sign}(dc))$，并保留该方向上切比雪夫距离 $\max(|dr|, |dc|)$ 最小的那枚。复杂度 $O(m)$，不需要建棋盘，见 §4 第 7 条。

### 3.4 示例演算

![示例 1 逐方向走查](images/wc158_q2_walkthrough.svg)

以示例 1（`king = [0,0]`）为例，8 个方向的扫描结果：

| 方向 $(dx,dy)$ | 扫描序列 | 结果 |
|----------------|----------|------|
| $(1,0)$ 右 | $(1,0)$ 是皇后 | 记录 `[1,0]` |
| $(1,1)$ 右下 | $(1,1)$ 空 → $(2,2)$ 空 → $(3,3)$ 是皇后 | 记录 `[3,3]` |
| $(0,1)$ 下 | $(0,1)$ 是皇后 | 记录 `[0,1]` |
| 其余 5 向 | 第一步就越界 | 无 |

得到 `[[0,1],[1,0],[3,3]]`，与官方输出完全一致（`dx`、`dy` 从 $-1$ 枚举到 $1$，恰好也得到这个顺序）；即使顺序不同也不影响判题，题目允许任意顺序。

再看示例 2（`king = [3,3]`）：左上射线上依次是 $(2,2)$、$(1,1)$、$(0,0)$，扫到 $(2,2)$ 就停止，后两枚被挡；正右方先遇 $(3,4)$，$(3,5)$ 被挡；右下方先遇 $(4,4)$，$(4,5)$ 被挡；其余 5 个方向第一步越界。答案 `[[2,2],[3,4],[4,4]]`。

## 4. 算法细节

1. **方向枚举别手写 8 组常量**：两重循环 `for dx in (-1,0,1): for dy in (-1,0,1):`，跳过 `dx == 0 and dy == 0`，既短又不会漏掉对角方向 $(1,1)$、$(1,-1)$。
2. **用布尔棋盘而不是哈希集合**：坐标范围恒为 $[0,8)$，`bool board[8][8]` 查表 $O(1)$、常数极小；C++ 中必须写 `bool board[8][8] = {};` 完成零初始化，否则查表会读到未初始化的值。
3. **先判边界再查表**：`while (0 <= x && x < 8 && 0 <= y && y < 8)`，循环体内才能安全访问 `board[x][y]`；顺序颠倒会数组越界。
4. **命中即 `break`**：这是「只取最近一枚」的代码体现。若不 `break` 而是继续扫描，就会把被遮挡的皇后也加进答案（示例 1 会多出 `[4,0]`、`[0,4]`）。
5. **输出顺序无关**：判题按集合比较，不必排序；若要稳定复现官方顺序，对结果 `sort` 一次即可，$O(8 \log 8)$ 可忽略。
6. **$x$ 与 $y$ 的角色可以互换**：把 `queens[i] = [x, y]` 当 `(行, 列)` 或 `(列, 行)` 都不影响结果，因为 8 方向集合关于坐标轴、两条对角线都是对称的。但**不能只考虑正方向**（只查右、下、右下），反向射线上的皇后同样可能更近。
7. **以皇后为中心的 $O(m)$ 变体**：方向键 `(sign(dr), sign(dc))` 天然把 8 条射线编号；同一键下只保留 $\max(|dr|,|dc|)$ 最小者。因为同一射线上距离越小越靠前，这个「最近者」与射线扫描的结果完全一致。本题棋盘固定为 8，收益不明显，但当棋盘为 $n \times n$ 且 $m \ll n$ 时是更优写法。
8. **不要用浮点斜率判共线**：`dy/dx` 会引入精度问题且有除零风险；用整数条件 `dr == 0 or dc == 0 or abs(dr) == abs(dc)` 才是精确判据。

## 5. 正确性证明

**引理 1（共线判据）**：皇后 $q$ 与国王 $k$ 共线（同行、同列或同对角线）当且仅当 $(x_q-x_k,\, y_q-y_k)$ 与某个方向向量 $(dx,dy) \in \{-1,0,1\}^2 \setminus \{(0,0)\}$ 同向。

**证明**：同行即 $y_q-y_k = 0$，方向为 $(\pm 1, 0)$；同列即 $x_q-x_k = 0$，方向为 $(0, \pm 1)$；同对角线即 $|x_q-x_k| = |y_q-y_k| \ne 0$，方向为 $(\pm 1, \pm 1)$。三者合起来恰好是 8 个方向向量，且每个方向向量对应的点集就是一条射线。∎

**引理 2（每方向至多一枚）**：同一条射线上至多有一枚皇后能攻击国王，即离国王最近的那一枚。

**证明**：设射线上有两枚皇后 $q_1, q_2$，且 $q_1$ 更靠近国王。则 $q_1$ 位于国王与 $q_2$ 的连线段内部（严格在两者之间），由「不能越过其他棋子」的规则，$q_2$ 被 $q_1$ 遮挡，无法攻击。对射线上任意两枚皇后都成立，故能攻击的只能是最近的一枚。∎

**引理 3（扫描结果正确）**：沿某方向扫描，若遇到皇后则记录的是该射线最近的一枚且它确实能攻击；若越界结束，则该射线上没有皇后。

**证明**：扫描从距离 1 开始按距离递增访问格子，第一次遇到的皇后距离最小，即最近的一枚；它之前的所有格子都为空，故它与国王之间没有棋子，满足攻击条件。若一直走到越界，说明射线上所有格子都为空，该方向无皇后。∎

**定理**：算法输出的集合恰好等于所有能直接攻击国王的皇后集合。

**证明**：

- **可靠性（不多报）**：每个被加入答案的皇后都由引理 3 保证是某条射线最近的一枚、且与国王之间无棋子，故它确实能攻击国王。
- **完备性（不漏报）**：设皇后 $q$ 能攻击国王。由引理 1，$q$ 落在某条射线上。设该射线上离国王最近的皇后为 $q'$，由引理 3 扫描一定遇到 $q'$ 并记录。若 $q' \ne q$，则 $q'$ 严格位于国王与 $q$ 之间，$q$ 被遮挡，与 $q$ 能攻击矛盾；故 $q' = q$，$q$ 被记录。
- **无重复**：8 条射线两两不交（除国王所在格外），每条射线至多加入一枚，故答案中无重复坐标。

综上，输出集合与真实集合相等。∎

## 6. 复杂度分析

- **时间**：$O(m + 64)$，其中 $m$ 为皇后数量。标记棋盘遍历 $m$ 枚皇后；8 个方向每条射线至多走 7 步，共 $\le 56$ 次查表。由于棋盘固定为 $8 \times 8$，可写作 $O(m)$，且 $m < 64$ 使实际运算量不超过百次。
- **空间**：$O(64) = O(1)$。只需一个 $8 \times 8$ 布尔数组；答案数组至多 8 个坐标，也可视为常数。不计输入输出。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> queensAttacktheKing(vector<vector<int>>& queens, vector<int>& king) {
        bool board[8][8] = {};                  // 必须零初始化
        for (const auto& q : queens) board[q[0]][q[1]] = true;

        vector<vector<int>> res;
        for (int dx = -1; dx <= 1; ++dx) {
            for (int dy = -1; dy <= 1; ++dy) {
                if (dx == 0 && dy == 0) continue;
                int x = king[0] + dx, y = king[1] + dy;
                while (x >= 0 && x < 8 && y >= 0 && y < 8) {
                    if (board[x][y]) {          // 该方向最近的一枚皇后
                        res.push_back({x, y});
                        break;                  // 更远的都被它挡住
                    }
                    x += dx;
                    y += dy;
                }
            }
        }
        return res;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def queensAttacktheKing(self, queens: List[List[int]], king: List[int]) -> List[List[int]]:
        board = [[False] * 8 for _ in range(8)]
        for x, y in queens:
            board[x][y] = True

        res = []
        for dx in (-1, 0, 1):
            for dy in (-1, 0, 1):
                if dx == 0 and dy == 0:
                    continue
                x, y = king[0] + dx, king[1] + dy
                while 0 <= x < 8 and 0 <= y < 8:
                    if board[x][y]:
                        res.append([x, y])
                        break               # 该方向只取最近的一枚
                    x += dx
                    y += dy
        return res
```

## 8. 边界情况与易错点

1. **皇后紧贴国王**：如示例 1 的 `(1,0)`、`(0,1)`，距离为 1，第一步就命中，不要因为「太近」而做任何特判。
2. **同方向多枚皇后只取最近**：示例 1 的 `(4,0)`、`(0,4)`，示例 2 的 `(1,1)`、`(3,5)`、`(4,5)`，都**不能**出现在答案里；漏写 `break` 是最常见的 WA 原因。
3. **越界判断顺序**：必须先用 `0 <= x < 8` 挡住，再访问 `board[x][y]`；负下标是未定义行为，可能读到脏内存甚至直接崩溃，出错后极难排查。
4. **反向方向不能漏**：只枚举右、下、右下会漏掉左、上、左上三条射线上的皇后。用 `-1..1` 两重循环最稳妥。
5. **近而不共线的皇后**：示例 1 的 `(2,4)` 距国王很近，但既不同行同列也不在对角线上，不攻击；判定必须用 8 方向而不是「距离近」。
6. **棋盘恒为 8×8**：不要把它当成 $n \times n$ 去读输入里的边界，也不要写死 `while (true)`；步进循环必须有越界出口。
7. **只含一枚皇后 / 皇后全被挡**：可能返回空数组（如 `queens = [[7,7]], king = [0,0]`），`res` 初始为空即可，无需特判。
