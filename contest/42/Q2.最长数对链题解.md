# LeetCode 最长数对链 题解

## 1. 题目概述

- **标题 / 题号**：最长数对链（#646，medium）
- **链接**：https://leetcode.cn/problems/maximum-length-of-pair-chain/
- **来源**：LeetCode 第 42 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、动态规划、排序、最长上升子序列

**题意**：给定 $n$ 个数对，第 $i$ 对记为 $[left_i, right_i]$，满足 $left_i < right_i$（代码中即 `pairs[i] = [left, right]`）。定义**跟随**关系：数对 $[c,d]$ 可以跟在 $[a,b]$ 后面当且仅当 $b < c$。你可以按**任意顺序**挑选任意一些数对（不必全用）串成一条**数对链**，返回能形成的最长链的长度。

一句话：把每个数对看成一个闭区间，求「区间两两不相交（端点相接也不行）」时最多能选几个。

**约束**：

- $1 \le n \le 1000$
- $-1000 \le left_i < right_i \le 1000$
- 数对之间没有互不相同的保证，可能出现重复数对

> 💡 值域只有约 $2000$ 个整数，这个额外条件在 §3.3 会给出一个 $O(n + V)$ 的值域 DP 写法；不过本题 $n \le 1000$，贪心已经足够。

## 2. 示例

**示例 1**

```text
输入：pairs = [[1,2], [2,3], [3,4]]
输出：2
解释：最长的数对链是 [1,2] -> [3,4]。
      注意 [1,2] -> [2,3] 不合法：2 < 2 不成立，端点相接不算跟随。
```

**示例 2**

```text
输入：pairs = [[1,2], [7,8], [4,5]]
输出：3
解释：排序后为 [1,2] -> [4,5] -> [7,8]，三对全部可用。
```

**补充案例（非官方，用于覆盖边界）**

```text
输入：pairs = [[1,2], [1,2], [1,2]]
输出：1
解释：三对完全相同且互相重叠，只能选一个。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举所有子集：共 $2^n$ 个，对每个子集按右端点排好序再检查相邻两对是否满足 $b < c$。复杂度 $O(2^n \cdot n \log n)$，$n = 1000$ 时完全不可行。

退一步用动态规划：把数对按左端点排序，令 `dp[i]` 表示「以第 $i$ 对结尾的最长链长度」，则

$$dp[i] = 1 + \max\{\, dp[j] \mid j < i,\ right_j < left_i \,\}$$

这是标准的 $O(n^2)$ 做法（$n=1000$ 时约 $5 \times 10^5$ 次内层判断，能过），但它没利用题目结构，也不是本题想要的答案。真正的关键观察是：**这是一道区间调度问题**。

### 3.2 核心观察：按右端点排序的贪心

![数对即区间，按右端点升序贪心](images/wc42_q2_greedy_choice.svg)

把数对 $[a,b]$ 画成数轴上的闭区间。链要求 $b < c$，等价于**选中的区间两两不相交（端点相接也不行）**。于是问题变成：从若干个闭区间中挑出尽可能多、互不重叠的区间。

这就是经典的**区间调度 / 最早结束优先**贪心：

1. 把数对按**右端点 `b` 升序**排序；
2. 维护 `last` = 上一个被选中数对的右端点，初值 $-\infty$；
3. 从头扫一遍，若当前数对 `[a,b]` 满足 $a > last$，就选它并令 `last = b`；否则跳过。

**为什么按右端点而不是左端点？** 反例 `pairs = [[1,10],[2,3],[4,5]]`：按左端点排序会先取 $[1,10]$，把后面的全挡死，只能得 1；而最优是 $[2,3] \to [4,5]$，长度 2。右端点越小，留给后面的空间越大——这就是「最早结束优先」的直观含义。

**为什么 $a > last$ 就选不会有损失？** $a > last$ 时当前对与整条已选链兼容，直接接上即可。$a \le last$ 时它与链的末对 $[a', b']$ 冲突（$last = b'$），无法直接接上；而若想用它换掉末对，新链的末右端点从 $last$ 变成 $b \ge last$（按右端点排序），只会更靠右、对后续更不利，长度也不会增加。所以「保留末对、跳过当前对」不会更差。严格的归纳证明见 §5。

### 3.3 算法流程与等价的 DP

![排序后单次扫描的贪心流程](images/wc42_q2_dp_flow.svg)

**贪心流程**（$O(n \log n)$）：

1. 将 `pairs` 按 `[1]`（右端点）升序排序；
2. `cnt = 0`，`last = -∞`；
3. 顺序遍历每个 `[a, b]`：若 $a > last$，则 `cnt += 1`，`last = b`；
4. 遍历结束返回 `cnt`。

**等价的 DP 视角**：若不想依赖贪心的正确性直觉，可以先按**左端点**排序，再用 §3.1 的转移式

$$dp[i] = 1 + \max_{j:\,right_j < left_i} dp[j]$$

答案取 $\max_i dp[i]$。这是 $O(n^2)$ 时间、$O(n)$ 空间，与贪心结果必然相同（§5 的引理 1 正是说「贪心永远取到最长」）。

**值域优化**：利用 $left_i, right_i \in [-1000, 1000]$，把坐标整体平移 $+1000$ 到 $[0, 2000]$。令 $pre[v]$ 表示「只考虑右端点 $\le v$ 的数对时能取到的最长链长度」，它随 $v$ 单调不减。按**右端点升序**处理每对 $[a, b]$，先把 $pre$ 的前缀最大值推进到 $b$，再更新

$$pre[b] \leftarrow \max\bigl(pre[b],\ pre[a-1] + 1\bigr),\qquad \text{约定 } pre[-1] = 0$$

读 $pre[a-1]$ 时该位置已定稿（$a-1 < a < b$，右端点更小的数对都已处理完且前缀最大值已推进），同一右端点的多对互不干扰。推进指针单调右移，所以总时间 $O(n + V)$、空间 $O(V)$，$V = 2001$——这是「用值域换掉排序」的写法，思路与 LIS 的值域 DP / 树状数组解法一致。（已用随机数据与暴力对拍验证该写法。）

### 3.4 示例演算

![示例逐对扫描的演算表](images/wc42_q2_walkthrough.svg)

对 `pairs = [[1,2], [7,8], [4,5]]`，按右端点排序后为 `[1,2], [4,5], [7,8]`：

| 步 | 当前数对 | 判断 $a > last$ | 动作 | `cnt` | `last` |
|----|----------|------------------|------|-------|--------|
| 1 | $[1,2]$ | $1 > -\infty$ 成立 | 选中 | 1 | 2 |
| 2 | $[4,5]$ | $4 > 2$ 成立 | 选中 | 2 | 5 |
| 3 | $[7,8]$ | $7 > 5$ 成立 | 选中 | 3 | 8 |

返回 3，链为 $[1,2] \to [4,5] \to [7,8]$。

再看要小心严格性的例子 `pairs = [[1,2], [2,3], [3,4]]`：

| 步 | 当前数对 | 判断 $a > last$ | 动作 | `cnt` | `last` |
|----|----------|------------------|------|-------|--------|
| 1 | $[1,2]$ | $1 > -\infty$ 成立 | 选中 | 1 | 2 |
| 2 | $[2,3]$ | $2 > 2$ **不成立** | 跳过 | 1 | 2 |
| 3 | $[3,4]$ | $3 > 2$ 成立 | 选中 | 2 | 4 |

返回 2。若把判断写成 $a \ge last$，第 2 步会错误地选中 $[2,3]$，答案变成 3——这是本题最常见的 WA 点。

## 4. 算法细节

1. **排序键只取右端点**：`sort(key=lambda p: p[1])`，不要用 `(a, b)` 或左端点。右端点相同时顺序任意：两对右端点同为 $b$，选中任意一对后 `last` 都变成 $b$，另一对的左端点 $< b$，必然被跳过，因此最多取一个，结果不受影响。
2. **`last` 的初值必须表示 $-\infty$**：Python 用 `float('-inf')`，C++ 用 `INT_MIN`（或 `-1001`，因为 $left_i \ge -1000$）。**不要用 0 初始化**：`pairs = [[-5,-4]]` 时 $a = -5 > 0$ 不成立，会直接返回 0。
3. **判断用严格大于**：`a > last` 对应 $b' < a$，即题目要求的 `b < c`。写成 `>=` 会允许端点相接，示例 1 立刻出错。
4. **原地排序的副作用**：`pairs.sort()` 会修改入参。LeetCode 判题无影响，但若判题环境多次调用同一数组，或调用方还要用原顺序，需先 `copy`/`vector<int> p = pairs`。
5. **贪心是 $O(n \log n)$，DP 是 $O(n^2)$**：$n=1000$ 时两者都能过（贪心约 $10^4$ 次比较，DP 约 $5\times10^5$ 次内层判断），但贪心代码只有 5 行、常数更小，且能直接推广到 $n = 10^5$。
6. **不要被「最长上升子序列」标签带偏**：本题虽挂了 LIS 标签，但不需要套 $O(n \log n)$ 的二分 LIS 模板；按右端点贪心即可，DP 视角只用来帮助理解（§3.1、§3.3）。
7. **重复数对无需去重**：相同数对互相冲突，贪心只会取第一个，去重反而多一次 $O(n \log n)$。

## 5. 正确性证明

**引理 1（贪心不变式）**：把数对按右端点升序排列为 $P_1, \dots, P_n$，其中 $P_k = [a_k, b_k]$。扫描到第 $i$ 对后，设贪心链长度为 $g_i$、末对右端点为 $r_i$（空链取 $r_i = -\infty$）。则：

1. 只用前 $i$ 对，不存在长度大于 $g_i$ 的链；
2. 只用前 $i$ 对，任何长度为 $g_i$ 的链，其末对右端点都 $\ge r_i$。

**证明**：对 $i$ 归纳。$i = 0$ 时链长为 0，$r_0 = -\infty$，两条均成立。

设前 $i-1$ 对满足结论，加入 $P_i = [a_i, b_i]$。由于按右端点升序，$b_i$ 是前 $i$ 对中的**最大右端点**。关键观察：**任何包含 $P_i$ 的链都以 $P_i$ 结尾**——若 $P_i$ 后面还接着 $[c,d]$，则 $b_i < c < d$，右端点 $d > b_i$ 超出前缀范围，矛盾。

- **情形一 $a_i > r_{i-1}$**：贪心选中 $P_i$，故 $g_i = g_{i-1}+1$，$r_i = b_i$。
  - 若存在长度 $\ge g_{i-1}+2$ 的链，它必以 $P_i$ 结尾（否则整条落在前 $i-1$ 对中，与归纳第 1 条矛盾），删掉 $P_i$ 得到前 $i-1$ 对中长度 $\ge g_{i-1}+1$ 的链，仍与归纳第 1 条矛盾。故长度上界成立。
  - 长度为 $g_{i-1}+1$ 的链必以 $P_i$ 结尾，末对右端点 $= b_i = r_i$，第 2 条成立。
- **情形二 $a_i \le r_{i-1}$**：贪心跳过，$g_i = g_{i-1}$，$r_i = r_{i-1}$。
  - 若存在长度 $g_{i-1}+1$ 的链，它必以 $P_i$ 结尾（否则与归纳第 1 条矛盾），去掉 $P_i$ 得前 $i-1$ 对中长度 $g_{i-1}$ 的链，其末对右端点 $x < a_i \le r_{i-1}$，与归纳第 2 条（任何长度 $g_{i-1}$ 的链末对右端点 $\ge r_{i-1}$）矛盾。故长度上界成立。
  - 长度为 $g_i$ 的链：若含 $P_i$ 则必以 $P_i$ 结尾，末对右端点 $b_i \ge r_{i-1} = r_i$；若不含 $P_i$ 则由归纳第 2 条得末对右端点 $\ge r_{i-1} = r_i$。第 2 条成立。∎

**引理 2（贪心链合法）**：贪心选出的数对序列构成合法数对链。

**证明**：设依次选中 $[a_{k_1}, b_{k_1}], \dots, [a_{k_m}, b_{k_m}]$，下标递增。选中 $[a_{k_t}, b_{k_t}]$ 时 `last` 恰为上一个被选数对的右端点 $b_{k_{t-1}}$（$t=1$ 时为 $-\infty$），判断成立即 $a_{k_t} > b_{k_{t-1}}$，正是跟随关系的定义。∎

**定理**：贪心返回的 `cnt` 等于最长数对链的长度。

**证明**：由引理 2，贪心链合法，故 `cnt` 不超过最优值；由引理 1 第 1 条取 $i = n$，用全部数对也不存在长度 $> g_n = cnt$ 的链，故 `cnt` 不小于最优值。两者相等。∎

> 💡 也可以从 Dilworth 定理的视角看：把「可跟随」当作偏序，「链」就是偏序集里的链，最优解即最长链长度，与贪心的「最早结束优先」结论一致。

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序是唯一的非线性开销；随后一次线性扫描，每对 $O(1)$ 比较与赋值。若用 §3.3 的值域 DP，可降到 $O(n + V)$，$V = 2001$。
- **空间**：$O(1)$ 额外空间（除排序内部开销，C++ `std::sort` 为 $O(\log n)$ 栈深）；`cnt`、`last` 两个标量。若不允许修改入参，需要 $O(n)$ 拷贝。
- 对照：$O(n^2)$ DP 时间为 $O(n^2)$、空间 $O(n)$，$n = 1000$ 时约 $5 \times 10^5$ 次内层判断，仍可通过。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <climits>
#include <vector>
using namespace std;

class Solution {
public:
    int findLongestChain(vector<vector<int>>& pairs) {
        // 按右端点升序：最早结束优先
        sort(pairs.begin(), pairs.end(),
             [](const vector<int>& x, const vector<int>& y) { return x[1] < y[1]; });

        int cnt = 0;
        int last = INT_MIN;               // 上一被选数对的右端点，初值 -∞
        for (const auto& p : pairs) {
            if (p[0] > last) {            // 严格大于：b < c 而非 b <= c
                ++cnt;
                last = p[1];
            }
        }
        return cnt;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findLongestChain(self, pairs: List[List[int]]) -> int:
        pairs.sort(key=lambda p: p[1])      # 按右端点升序
        cnt, last = 0, float('-inf')        # last 表示上一被选数对的右端点
        for a, b in pairs:
            if a > last:                    # 严格大于才可跟随（b < c）
                cnt += 1
                last = b
        return cnt
```


## 8. 边界情况与易错点

1. **$n = 1$**：`last = -∞` 保证第一对必被选中，返回 1。若把 `last` 初始化为 0，遇到负数左端点（如 `[[-5,-4]]`）会返回 0。
2. **端点相接**：`[[1,2],[2,3]]` 返回 1，不是 2。判断必须严格 `>`；示例 1 的 `[1,2] -> [2,3]` 正是这个陷阱。
3. **全等/全重叠**：`[[1,2],[1,2],[1,2]]` 返回 1；`[[1,100],[2,3],[4,5]]` 返回 2（排序后 `[2,3]` 先于 `[1,100]`）。
4. **负数与 $-\infty$ 的表示**：因为 $left_i \ge -1000$，`INT_MIN`、`-1e9`、`-1001` 都能安全表示 $-\infty$；但**不能**用 0 或任何大于 $-1000$ 的数，否则左端点为负的数对会被误判为「不能选」。
5. **排序键写错**：按左端点排序会 WA，反例 `[[1,10],[2,3],[4,5]]`（左端点排序贪心得 1，最优 2）。按区间长度升序也不行：`[[0,4],[6,8]]` 会先取更短的 $[6,8]$，只能得 1，最优是 $[0,4] \to [6,8]$ 的 2。
6. **不要用 `>=` 代替 `>`，也不要在比较里混用 `b` 与 `last` 的含义**：`last` 始终是「已选链末对的右端点」，不是当前对的右端点。
7. **修改入参**：`pairs.sort()` 与 `std::sort` 均原地排序；若在同一测试里复用原数组，需先拷贝。

**延伸思考**：

1. 若每对带权重 $w_i$，要求权重和最大，则贪心不再正确（一个右端点小但权重极低的区间可能拖累全局），必须用**加权区间调度**的 DP + 二分。
2. 若把跟随条件放宽为 $b \le c$（端点可相接），只需把判断改成 `a >= last`，正确性证明的引理 1 依然成立，只是「任何含 $P_i$ 的链都以 $P_i$ 结尾」要改成 $b_i \le c$ 的相应版本。
3. 若要输出**具体的一条最长链**而非长度，贪心天然给出一个答案（记录选中的数对），DP 则需要记录前驱 `pre[i]` 再回溯。
4. 把维度升高——数对换成 $k$ 维盒子、要求每维严格小于——问题变成偏序集最长链，二维可用排序 + LIS，高维一般需要 CDQ 分治或树套树。
