# LeetCode 统计作战单位数 题解

## 1. 题目概述

- **标题 / 题号**：统计作战单位数（#1395，medium）
- **链接**：https://leetcode.cn/problems/count-number-of-teams/
- **来源**：LeetCode 第 182 场周赛 Q2
- **难度**：中等
- **标签**：数组、计数、动态规划、树状数组

**题意**：`n` 名士兵站成一排，每人有一个**独一无二**的评分。要选出下标 $0 \le i < j < k < n$ 的三名士兵组成「作战单位」，且评分**严格单调**：要么 $\text{rating}[i] < \text{rating}[j] < \text{rating}[k]$（递增），要么 $\text{rating}[i] > \text{rating}[j] > \text{rating}[k]$（递减）。返回可组建的作战单位**方案总数**。

**约束**：

- $n = \text{rating.length}$，$3 \le n \le 1000$
- $1 \le \text{rating}[i] \le 10^5$
- `rating` 中元素**互异**

> 💡 从约束读档位：$n \le 1000$ 说明 $O(n^2) \approx 10^6$ 稳过，而 $O(n^3)$（$\binom{1000}{3} \approx 1.7 \times 10^8$ 次判定）卡在超时边缘；「元素互异」说明任意两个士兵比大小**非小即大**——左侧「小于 / 大于」两类计数相加恰等于左侧总数。这两条约束直接圈定正解形态：**枚举中位 + 左右计数**。

## 2. 示例

**示例 1**

```text
输入：rating = [2,5,3,4,1]
输出：3
解释：可组建三个作战单位——(2,3,4) 严格递增；(5,4,1)、(5,3,1) 严格递减。
```

**示例 2**

```text
输入：rating = [2,1,3]
输出：0
解释：唯一的三元组 (2,1,3) 先降后升，两种单调条件都不满足。
```

**示例 3**

```text
输入：rating = [1,2,3,4]
输出：4
解释：全部 C(4,3) = 4 个三元组都严格递增：(1,2,3)、(1,2,4)、(1,3,4)、(2,3,4)。
```

**示例 4**（自拟：对称性自检）

```text
输入：rating = [4,3,2,1]
输出：4
解释：全递减排列与示例 3 互为镜像，答案同为 C(4,3) = 4——
把数组反转，递增队伍与递减队伍互换，总数不变。
```

## 3. 解题思路

### 3.1 暴力思路：三重循环逐个判定

枚举所有下标三元组 $i < j < k$，逐个判定两种单调性，命中则计数。三重循环的执行次数是 $\binom{n}{3} \approx 1.7 \times 10^8$（$n = 1000$），C++ 勉强能卡过、Python 必然超时。更要命的是**结构缺陷**：$i$、$j$、$k$ 三层循环互相耦合，「左侧有几个比 $\text{rating}[j]$ 小」这条信息被每个不同的 $i$ 重复计算了一遍，中间结果完全无法复用。

> ⚠️ 三元组计数题的通用破局点：找一个**枢纽下标**把三重循环拆成「枢纽一侧 × 枢纽另一侧」两个独立子问题。本题的枢纽就是**中间下标 $j$**——它左管 $i$、右管 $k$，天然把问题切成两半。

### 3.2 核心观察：枚举中位 j + 乘法原理

![核心观察：固定中位 j，左右各分大小，乘法原理定贡献](images/teams_middle_pivot_concept.svg)

三元组 $(i, j, k)$ 中 $j$ 是**中位**：$i$ 只能取自左侧 $[0, j)$、$k$ 只能取自右侧 $(j, n)$。固定 $j$ 后，由于元素**互异**，左侧每个元素与 $\text{rating}[j]$ 比较非小即大，右侧同理。于是四个计数浮出水面：

| 计数 | 定义 | 供给 |
|------|------|------|
| 左小 $\text{ls}(j)$ | $\#\{i < j : \text{rating}[i] < \text{rating}[j]\}$ | 递增队伍的 $i$ 候选 |
| 左大 $\text{lg}(j)$ | $\#\{i < j : \text{rating}[i] > \text{rating}[j]\}$ | 递减队伍的 $i$ 候选 |
| 右大 $\text{rg}(j)$ | $\#\{k > j : \text{rating}[k] > \text{rating}[j]\}$ | 递增队伍的 $k$ 候选 |
| 右小 $\text{rs}(j)$ | $\#\{k > j : \text{rating}[k] < \text{rating}[j]\}$ | 递减队伍的 $k$ 候选 |

固定 $j$ 后「选 $i$」与「选 $k$」**相互独立**——任取一个左候选配任取一个右候选都拼出一支合法队伍，**乘法原理**直接把配对数压成一次乘法：

$$\text{contribution}(j) = \text{ls}(j) \times \text{rg}(j) + \text{lg}(j) \times \text{rs}(j)$$

第一项数**递增**队伍（$i$ 取左小、$k$ 取右大），第二项数**递减**队伍（$i$ 取左大、$k$ 取右小）。对 $j = 1, \ldots, n-2$ 累加贡献即为答案。

以示例 1 的 $\text{rating} = [2,5,3,4,1]$、$j = 2$（$\text{rating}[j] = 3$）为例：左侧 $[2,5]$ 中 $2 < 3$、$5 > 3$，故 $\text{ls} = 1$、$\text{lg} = 1$；右侧 $[4,1]$ 中 $4 > 3$、$1 < 3$，故 $\text{rg} = 1$、$\text{rs} = 1$。贡献 $= 1 \times 1 + 1 \times 1 = 2$，恰对应递增队伍 $(2,3,4)$ 与递减队伍 $(5,3,1)$。

> ⚠️ **元素互异用在哪里**：互异 ⟹ 左侧非小即大，$\text{ls}(j) + \text{lg}(j) = j$、$\text{rg}(j) + \text{rs}(j) = n - 1 - j$ 恒成立。这条**守恒式**是「数一减一」实现技巧与运行时自检的依据。注意即便元素可重复，**乘法配对公式本身依然正确**（引理 2 的双射不依赖互异）——失效的只是守恒式，届时须把四个计数全部显式数出。

### 3.3 算法流程：外层枚举中位，内层左右各扫一趟

![算法流程：枚举 j → 扫左侧 → 扫右侧 → 乘法原理累加](images/teams_counting_flow.svg)

1. **初始化** `ans = 0`；
2. **枚举中位** $j = 1, \ldots, n-2$（$j = 0$ 左侧为空、$j = n-1$ 右侧为空，贡献必为 0，直接跳过）；
3. **扫左侧** $[0, j)$：数出 `leftSmaller`，由守恒式得 `leftLarger = j - leftSmaller`；
4. **扫右侧** $(j, n)$：数出 `rightLarger`，由守恒式得 `rightSmaller = n - 1 - j - rightLarger`；
5. **累加贡献**：`ans += leftSmaller * rightLarger + leftLarger * rightSmaller`；
6. 遍历完所有 $j$ 后**返回** `ans`。

每个 $j$ 左扫 $O(j)$、右扫 $O(n-1-j)$，单步合计恰为 $n - 1$；共 $n - 2$ 个 $j$，总计 $O(n^2)$。

### 3.4 示例演算

![示例演算：逐个中位 j 统计四量并累加贡献](images/teams_walkthrough.svg)

对示例 1 的 $\text{rating} = [2,5,3,4,1]$：

| $j$ | $\text{rating}[j]$ | 左小 | 左大 | 右大 | 右小 | 贡献 |
|-----|-------------------|------|------|------|------|------|
| 1 | 5 | 1 | 0 | 0 | 3 | $1 \times 0 + 0 \times 3 = 0$ |
| 2 | 3 | 1 | 1 | 1 | 1 | $1 \times 1 + 1 \times 1 = 2$ |
| 3 | 4 | 2 | 1 | 0 | 1 | $2 \times 0 + 1 \times 1 = 1$ |

**逐行详解**：

- **$j = 1$（rating 5）**：左侧 $[2]$ 中 $2 < 5$ → 左小 1、左大 0；右侧 $[3,4,1]$ 全部 $< 5$ → 右大 0、右小 3。5 是全局最大值——左侧无人比它大（递减选不出 $i$）、右侧无人比它大（递增选不出 $k$），贡献 0。
- **$j = 2$（rating 3）**：左侧 $[2,5]$ → 左小 1（$2 < 3$）、左大 1（$5 > 3$）；右侧 $[4,1]$ → 右大 1（$4 > 3$）、右小 1（$1 < 3$）。贡献 2：递增队伍 $(2,3,4)$、递减队伍 $(5,3,1)$。
- **$j = 3$（rating 4）**：左侧 $[2,5,3]$ → 左小 2（$2,3$）、左大 1（$5$）；右侧 $[1]$ → 右大 0、右小 1。贡献 1：递增 $2 \times 0 = 0$，递减队伍 $(5,4,1)$。

**总方案数** $= 0 + 2 + 1 = 3$ ✓，与示例 1 列出的三支队伍一一对应。

> 💡 **自检**：每行都应满足 左小 $+$ 左大 $= j$、右大 $+$ 右小 $= n - 1 - j$。如 $j = 3$：$2 + 1 = 3$ ✓、$0 + 1 = 1 = 5 - 1 - 3$ ✓。守恒式一旦破裂，说明漏判了「等于」或扫描区间写错——先查这里再查别处。

## 4. 算法细节

1. **枢纽选「中位」而非「首 / 尾」**：$i < j < k$ 的位置约束里，中位 $j$ 左右各管一边、两侧候选集不相交，一次乘法即可配对；若以首（或尾）为枢纽，另一侧内部还要再分两层（先数长度 2 的子序列、再合成），处理成两级 DP 才能落地——同为 $O(n^2)$ 但代码更绕。
2. **减法技巧**：由守恒式，一趟扫描只显式数「左小」「右大」两个量，`leftLarger = j - leftSmaller`、`rightSmaller = n - 1 - j - rightLarger` 由总数减得——比较次数减半，且数错即不守恒，天然便于自检。
3. **两种单调方向共享一趟扫描**：递增用「左小 × 右大」、递减用「左大 × 右小」，四个计数来自**同一组比较结果**，「方向」维度被完全折叠，不存在第二次分类扫描。
4. **DP 等价视角**（对应标签 Dynamic Programming）：定义 $\text{up2}[j]$ 为以 $j$ 结尾、长度为 2 的递增子序列个数（恰等于左小数），则递增队伍数 $= \sum_k \sum_{j < k,\ \text{rating}[j] < \text{rating}[k]} \text{up2}[j]$——与枚举中位等价，只是把枢纽从「中位」换成「末位」，同为 $O(n^2)$。
5. **累加与溢出**：答案上界 $\binom{n}{3} \approx 1.66 \times 10^8 < 2^{31} - 1$，$n \le 1000$ 时 `int` 承得住；若 $n$ 放大到 $10^4$ 量级须换 `long long`（Python 无此虑）。
6. **不要排序**：$i < j < k$ 是**位置**约束，排序会摧毁下标序；值的大小关系一次比较即可获得，无需任何预处理，也不动原数组。

## 5. 正确性证明

记 $L_s(j) = \{i < j : \text{rating}[i] < \text{rating}[j]\}$，$L_g(j) = \{i < j : \text{rating}[i] > \text{rating}[j]\}$，$R_g(j) = \{k > j : \text{rating}[k] > \text{rating}[j]\}$，$R_s(j) = \{k > j : \text{rating}[k] < \text{rating}[j]\}$；$T$ 为全体合法作战单位集合，$T_j$ 为以 $j$ 为中位者。

**引理 1（按中位分组不重不漏）**：映射 $(i, j, k) \mapsto j$ 把 $T$ 划分为两两不交的 $T_1, \ldots, T_{n-2}$ 之并。

**证明**：任一合法单位满足 $i < j < k$，中间下标 $j$ 由严格不等式唯一确定；$j \in [1, n-2]$ 时左右两侧各至少有一个可用下标。两个作战单位若中位不同则分属不同 $T_j$；同一单位的中位唯一，不会同时落入两组。故 $T = \bigsqcup_{j=1}^{n-2} T_j$。∎

**引理 2（组内计数恰为乘积）**：对每个 $j$，$T_j$ 中递增单位数 $= |L_s(j)| \cdot |R_g(j)|$，递减单位数 $= |L_g(j)| \cdot |R_s(j)|$。

**证明**：固定 $j$，则 $(i, j, k)$ 递增 $\iff \text{rating}[i] < \text{rating}[j] \wedge \text{rating}[k] > \text{rating}[j] \iff i \in L_s(j) \wedge k \in R_g(j)$。映射 $(i, j, k) \mapsto (i, k)$ 是「$T_j$ 中递增单位」到 $L_s(j) \times R_g(j)$ 的双射：不同 $(i, k)$ 给出不同单位，且每个 $(i, k) \in L_s(j) \times R_g(j)$ 反解出的 $(i, j, k)$ 都满足下标与单调约束。故递增数 $= |L_s(j)| \cdot |R_g(j)|$。递减情形将 $<$ 与 $>$ 全部对调，对称得证。∎

**引理 3（两方向互斥）**：同一作战单位不能既严格递增又严格递减。

**证明**：若同时成立，则 $\text{rating}[i] < \text{rating}[j]$ 与 $\text{rating}[i] > \text{rating}[j]$ 并立，矛盾。∎

**定理**：$\displaystyle \text{ans} = \sum_{j=1}^{n-2} \Big( |L_s(j)| \, |R_g(j)| + |L_g(j)| \, |R_s(j)| \Big)$。

**证明**：$|T| = \sum_{j=1}^{n-2} |T_j|$（引理 1）；$|T_j| = |T_j \cap \text{递增}| + |T_j \cap \text{递减}|$（引理 3 给出互斥二分）；对两项分别代入引理 2 的乘积公式，即得求和式。∎

> 💡 实现层面另依赖一条事实——**守恒式** $|L_s(j)| + |L_g(j)| = j$、$|R_g(j)| + |R_s(j)| = n-1-j$，由元素互异直接保证（非小即大，无第三类），支撑「数一减一」的减法技巧。

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。固定 $j$ 时左扫 $j$ 次、右扫 $n-1-j$ 次，单步合计恰 $n-1$ 次比较；$j$ 取 $1$ 到 $n-2$，总计 $(n-2)(n-1) = O(n^2)$。$n = 1000$ 时约 $10^6$ 次比较，毫秒级通过。
- **空间复杂度**：$O(1)$。只有常数个计数变量，不开辅助数组、不改原数组。
- **横向对比**：三重循环 $O(n^3)$，$\binom{1000}{3} \approx 1.7 \times 10^8$ 次判定，C++ 卡边缘、Python 必超时；树状数组优化到 $O(n \log m)$（见「相关题目与扩展」），$n = 1000$ 时约 $1.7 \times 10^4$ 次树状数组操作——本题 $n$ 太小，$O(n^2)$ 已是性价比最高的形态。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numTeams(vector<int>& rating) {
        int n = rating.size(), ans = 0;
        for (int j = 1; j < n - 1; ++j) {          // 枚举中位：j ∈ [1, n-2]
            int leftSmaller = 0, rightLarger = 0;
            for (int i = 0; i < j; ++i)            // 扫左侧：数「左小」
                if (rating[i] < rating[j]) ++leftSmaller;
            for (int k = j + 1; k < n; ++k)        // 扫右侧：数「右大」
                if (rating[k] > rating[j]) ++rightLarger;
            int leftLarger = j - leftSmaller;              // 互异 ⟹ 左侧其余皆更大
            int rightSmaller = n - 1 - j - rightLarger;    // 互异 ⟹ 右侧其余皆更小
            ans += leftSmaller * rightLarger       // 递增队伍
                 + leftLarger  * rightSmaller;     // 递减队伍
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numTeams(self, rating: List[int]) -> int:
        n = len(rating)
        ans = 0
        for j in range(1, n - 1):                              # 枚举中位
            left_smaller = sum(rating[i] < rating[j] for i in range(j))
            right_larger = sum(rating[k] > rating[j] for k in range(j + 1, n))
            left_larger = j - left_smaller                     # 互异 ⟹ 守恒式减法
            right_smaller = n - 1 - j - right_larger
            ans += left_smaller * right_larger + left_larger * right_smaller
        return ans
```

> 💡 两版都只显式数「左小」「右大」，另两个计数由守恒式减得——互异性在此从「题设约束」变成「实现资产」。若不放心守恒式，把四个计数全部显式数出来也完全正确，只是每步多一倍比较。

## 8. 边界情况与易错点

1. **$j$ 的遍历范围**：$[1, n-2]$。写成 $[0, n-1]$ 结果碰巧不变（空侧贡献为 0）但白扫两端；漏掉 $j = n-2$ 才是真正的错。C++ 写法 `for (int j = 1; j < n - 1; ++j)` 即 $[1, n-2]$。
2. **减法技巧的前提是互异**：若元素可重复，出现 $\text{rating}[i] = \text{rating}[j]$ 时「等于」既非小也非大，`leftLarger = j - leftSmaller` 会把「等于」错算进「更大」——乘法配对公式本身仍正确，但须把四个计数全部显式数出、不再用减法。
3. **两方向不会重复计数**：严格递增与严格递减互斥（$\text{rating}[i] < \text{rating}[j]$ 与 $\text{rating}[i] > \text{rating}[j]$ 不能并存），公式两项天然不交；题面要求严格单调，也不存在第三种合法方向被漏掉。
4. **全单调排列是最好的对拍用例**：$[1,2,\ldots,n]$ 或其镜像的答案恒为 $\binom{n}{3}$（$n = 4$ 即示例 3 与自拟示例 4）；乱序数据可用暴力三重循环对拍验证。
5. **$n = 3$ 最小规模**：循环体只执行一次（$j = 1$），答案非 0 即 1（示例 2 输出 0）。
6. **溢出**：$n \le 1000$ 时答案上界 $\binom{1000}{3} \approx 1.66 \times 10^8$，32 位 `int` 安全；若约束放大到 $n \le 10^4$，上界 $\binom{10^4}{3} \approx 1.7 \times 10^{11}$ 溢出 `int`，须 `long long`。
7. **别顺手排序**：位置序 $i < j < k$ 是题目约束的一部分，排序后「左侧 / 右侧」的位置语义消失；值比较随时可做，无需预处理。

**延伸思考**：其一，把「左小 / 右小」的查询从 $O(n)$ 线性扫描压成 $O(\log m)$ 值域前缀和——开一棵大小 $10^5$ 的树状数组，从左往右扫查询 $[1, \text{rating}[j]-1]$ 得左小，从右往左扫同理得右小，整体 $O(n \log m)$（题目标签中的 Binary Indexed Tree 即指此；值域无界时先离散化）。其二，把「长度恰为 3」推广为「长度恰为 $k$ 的单调子序列计数」：DP 状态 $f_t[j]$ = 以 $j$ 结尾、长度为 $t$ 的递增子序列个数，转移 $f_t[j] = \sum_{i < j,\ \text{rating}[i] < \text{rating}[j]} f_{t-1}[i]$，$k = 3$ 时与枚举中位法殊途同归。其三，若题面改为「非严格单调（允许相邻相等）」，相等的两侧也可配对，计数须按「$\le$ / $\ge$」重新分类推导，不能再直接套用本题的严格比较。
