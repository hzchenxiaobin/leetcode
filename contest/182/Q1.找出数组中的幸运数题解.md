# LeetCode 找出数组中的幸运数 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的幸运数（#1394，easy）
- **链接**：https://leetcode.cn/problems/find-lucky-integer-in-an-array/
- **来源**：LeetCode 第 182 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：在整数数组中，如果一个整数的**出现频次**和它的**数值大小**相等，就称其为「**幸运数**」。给定整数数组 `arr`，找出并返回一个幸运数：存在多个时返回**最大**的那个；不存在时返回 `-1`。

**约束**：

- $1 \le \text{arr.length} \le 500$
- $1 \le \text{arr}[i] \le 500$

> 💡 签到题的最短路径从约束读起：值域 $[1, 500]$ 是**常数**，值可以直接当数组下标——开一个长度 501 的计数数组（桶），一趟建表、一趟判定，连哈希函数都不用跑。

## 2. 示例

**示例 1**

```text
输入：arr = [2,2,3,4]
输出：2
解释：数组中唯一的幸运数是 2，因为数值 2 的出现频次也是 2。
```

**示例 2**

```text
输入：arr = [1,2,2,3,3,3]
输出：3
解释：1、2 以及 3 都是幸运数，返回其中最大的 3。
```

**示例 3**

```text
输入：arr = [2,2,2,3,3]
输出：-1
解释：数组中不存在幸运数。
```

**示例 4**

```text
输入：arr = [5]
输出：-1
解释：5 只出现 1 次，1 ≠ 5。
```

**示例 5**（自拟：最容易被漏判的幸运数）

```text
输入：arr = [1]
输出：1
解释：1 出现了 1 次，频次恰等于数值——单个 1 就是幸运数。
```

## 3. 解题思路

### 3.1 暴力思路：每个候选值现数一遍

先收集所有不同值，对每个候选 `v` 再扫一遍数组数它出现几次，等于 `v` 则纳入候选，最后取最大。设不同值有 $d$ 个，总代价 $O(n \cdot d)$，元素互异时退化为 $O(n^2) = 2.5 \times 10^5$——$n \le 500$ 暴力也能毫秒级通过，但每个值的频次都被「现数一遍」，重复劳动且完全不利用约束。

另一条中间路线是**排序 + 游程**：排序后相同值连成游程，游程长度恰等于值即为幸运数，$O(n \log n)$。也能过，但频次根本不需要顺序信息，排序属于「动了不该动的东西」。

### 3.2 核心观察：桶计数 + 等值判定

![核心观察：一趟建桶，频次与下标撞个正着才算幸运数](images/luckyint_bucket_concept.svg)

判定谓词是 $\text{cnt}[v] = v$，同时用到「值」和「值的频次」两个量。**频次是全数组的全局统计量**，把统计提到外层一趟做完，判定就退化为 $O(1)$ 查表：

1. **建桶**：开长度 501 的数组 `cnt`（下标即值，0 号位弃用），遍历 `arr` 执行 `cnt[v]++`；
2. **判定**：$v$ 是幸运数 $\iff \text{cnt}[v] == v$。值域 $[1,500]$ 保证所有候选 $v$ 都落在桶的下标范围内。

以示例 1 的 `arr = [2,2,3,4]` 为例：建桶得 $\text{cnt}[1]=0$、$\text{cnt}[2]=2$、$\text{cnt}[3]=1$、$\text{cnt}[4]=1$，只有 $v=2$ 满足 $\text{cnt}[v]=v$，答案 `2`。

> 💡 值域 $\le 500$ 是本题最有价值的约束：它把「哈希表」降级成「数组下标直访」，无哈希常数、无冲突处理，是「**用值域换实现简单度**」的第一反应。

### 3.3 算法流程：倒序扫描，首个命中即最大

![算法流程：建桶一趟，从 500 倒序找首个 cnt[v]=v](images/luckyint_scan_flow.svg)

题目要**最大**幸运数，而桶的下标天然有序——从 500 到 1 **倒序**扫描，第一个满足 `cnt[v] == v` 的 `v` 就是答案，直接 `return`。「取最大」由枚举顺序免费获得，不需要维护 `ans`、也不需要扫完全程：

1. **建桶**：遍历 `arr`，`cnt[v]++`；
2. **倒序判定**：`for v = 500 downto 1`，若 `cnt[v] == v`，立即 `return v`；
3. **落空**：循环走完仍未命中，`return -1`。

> ⚠️ 「首个命中即最大」依赖桶下标有序。若换成哈希表（键无序），必须显式维护 `ans = max(ans, v)` 或对键排序，不能套用「首个命中就返回」的写法。

### 3.4 示例演算

![示例演算：建桶后倒序一击命中；无幸运数时全程落空](images/luckyint_walkthrough.svg)

**示例 2**（`arr = [1,2,2,3,3,3]`）：建桶得 $\text{cnt} = \{1:1,\ 2:2,\ 3:3\}$，三个值全是幸运数。倒序扫描：$v = 500 \ldots 4$ 全为 0 ✗，$v=3$ 时 $\text{cnt}[3]=3$ ✓ 首个命中，`return 3`——$v=2$、$v=1$ 无需再看。

| $v$ | $\text{cnt}[v]$ | 命中？ | 说明 |
|-----|-----------------|--------|------|
| 500 … 4 | 0 | ✗ | 这些值都没出现 |
| 3 | 3 | ✓ 停 | 首个命中即最大幸运数 |
| 2、1 | 2、1 | （也是幸运数） | 已返回，不再扫描 |

**示例 3**（`arr = [2,2,2,3,3]`）：建桶得 $\text{cnt} = \{2:3,\ 3:2\}$——2 出现 3 次、3 出现 2 次，值与频次**交叉错位**，全程无命中，`return -1`。

| $v$ | $\text{cnt}[v]$ | 命中？ |
|-----|-----------------|--------|
| 2 | 3 | ✗（$2 \ne 3$） |
| 3 | 2 | ✗（$3 \ne 2$） |

## 4. 算法细节

1. **数据结构**：值域 $[1,500]$ 为常数 → 长度 501 的桶数组，下标即值、$O(1)$ 直访、零哈希开销；0 号下标弃用（值域从 1 起）。若值域发散（如 $\text{arr}[i] \le 10^9$），退回 `unordered_map` / `Counter`，骨架不变。
2. **倒序扫描**：从大到小枚举，谓词首次为真的 $v$ 即最大幸运数（§5 引理 2）。相比「正序扫完维护 `ans = max(ans, v)`」，倒序版平均提前终止，代码只有命中返回与落空返回两个出口。
3. **上界剪枝**（可选）：幸运数满足 $v = \text{cnt}[v] \le n$，扫描起点可从 500 压到 $n$，$n$ 很小时少扫空桶。主代码仍从 500 起扫——$U = 500$ 是常数，复杂度不变，少一个出错点。
4. **判定对象是桶不是原数组**：桶按下标天然去重，每个值只判一次；若误遍历原数组，同一值会被重复判定（结果碰巧不变，但属无用功）。
5. **哨兵 $-1$**：值域从 1 起，任何真幸运数 $v \ge 1 > -1$；「无解返回 $-1$」与「初值 $-1$」天然重合，无需 `found` 标志。

## 5. 正确性证明

设值域上界 $U = 500$，$L$ 为 `arr` 的幸运数集合（出现频次等于自身数值的整数）。

**引理 1（建桶的正确性）**：一趟扫描结束后，对每个 $v \in [1, U]$ 有 $\text{cnt}[v] = \left|\{ i : \text{arr}[i] = v \}\right|$。

**证明**：对已处理元素个数 $k$ 归纳。$k=0$ 时 `cnt` 全 0，成立。设处理前 $k$ 个后结论成立；第 $k+1$ 个元素为 $w$，循环体仅执行 `cnt[w] += 1`：等式两端只有 $w$ 对应的计数各增 1，其余值两端都不变，结论传递。∎

**引理 2（倒序枚举的首个命中即最大）**：设谓词 $P$ 定义在整数 $[1, U]$ 上，按 $v = U, U-1, \ldots, 1$ 的顺序枚举，则首个满足 $P(v)$ 的 $v$（若存在）等于 $\max\{ v \in [1,U] : P(v) \}$。

**证明**：设命中者为 $v_0$，则 $P(v_0)$ 成立，故 $v_0$ 属于该集合且 $v_0 \le \max$。若 $\max > v_0$，则 $\max \in (v_0, U]$ 且 $P(\max)$ 成立，而枚举自 $U$ 递减、先于 $v_0$ 到达 $\max$，与 $v_0$ 是「首个」矛盾。∎

**定理**：算法返回 $\max L$（$L$ 非空时），否则返回 $-1$。

**证明**：取谓词 $P(v) \equiv (\text{cnt}[v] = v)$。由引理 1，$\text{cnt}[v]$ 恰为 $v$ 的出现频次；又 `arr` 的取值全在 $[1,U]$ 内，且 $\text{cnt}[v] = v \ge 1$ 自动保证 $v$ 在数组中出现，故 $\{v \in [1,U] : P(v)\} = L$。由引理 2，倒序扫描的首个命中即 $\max L$，算法立即返回；若 $L = \emptyset$，循环完整走完落到 `return -1`。两种情形均符合题意。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + U)$。建桶一趟 $O(n)$；判定一趟至多检查 $U = 500$ 个桶，为常数，整体即 $O(n)$。倒序扫描在首个命中处提前返回，答案为 $-1$ 时才扫满全程。
- **空间复杂度**：$O(U) = O(1)$。桶长 501 固定，与 $n$ 无关；哈希表版为 $O(d)$（$d$ 为不同值个数，$d \le \min(n, U) = 500$，同为常数界）。
- **横向对比**：暴力现数 $O(n^2)$（$n=500$ 时 $2.5 \times 10^5$ 次比较，能过但结构最差）；排序游程 $O(n \log n)$ 且改动原数组；桶计数 $O(n)$ 是本题约束下的最优形态。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findLucky(vector<int>& arr) {
        int cnt[501] = {0};
        for (int v : arr) cnt[v]++;          // 建桶：下标即值

        for (int v = 500; v >= 1; --v)       // 倒序：首个命中即最大
            if (cnt[v] == v) return v;
        return -1;                           // 全程无命中
    }
};
```

### Python

```python
class Solution:
    def findLucky(self, arr: List[int]) -> int:
        cnt = [0] * 501
        for v in arr:
            cnt[v] += 1
        for v in range(500, 0, -1):          # 倒序：首个命中即最大
            if cnt[v] == v:
                return v
        return -1
```

> 💡 **哈希一行式**（不依赖值域）：`max((v for v, c in Counter(arr).items() if v == c), default=-1)`——遍历键值对判 `v == c`，`default=-1` 内建了落空语义。周赛两版任选：桶版零依赖、下标即语义；哈希版可迁移到任意值域。

## 8. 边界情况与易错点

1. **`[1]` 是幸运数**：$\text{cnt}[1] = 1$，频次与数值相等，返回 `1`。单元素数组别习惯性返回 `-1`（对照示例 4 的 `[5]`：$\text{cnt}[5] = 1 \ne 5$，才是 `-1`）。
2. **交叉错位**：`[2,2,2,3,3]` 中 $\text{cnt}[2]=3$、$\text{cnt}[3]=2$，互相错开一位、双双落选。判的是**等值** `cnt[v] == v`，不是「出现过」也不是「频次接近」。
3. **桶开 501 别开 500**：值域含 500，`cnt[500]` 必须合法；C++ 栈上 `int cnt[501]` 约 2 KB，无压力。
4. **扫描方向**：必须倒序才能「首个命中即最大」；正序则要扫完并维护 `max`。用「上界压到 $n$」的剪枝时，起点取 $\min(n, 500)$——值 $> n$ 的桶频次至多 $n < v$，跳过它们不影响正确性。
5. **返回值语义**：题目要「最大」不是「任意」也不是「所有」——示例 2 的幸运数有 $\{1,2,3\}$ 三个，只返回 `3`。
6. **桶的前提是值域有界**：若约束改成 $\text{arr}[i] \le 10^9$，定长数组不可行，换 `unordered_map` / `Counter`，其余逻辑不变。
