# LeetCode 检测相邻递增子数组 I 题解

## 1. 题目概述

- **标题 / 题号**：检测相邻递增子数组 I（#3349，easy）
- **链接**：https://leetcode.cn/problems/adjacent-increasing-subarrays-detection-i/
- **来源**：LeetCode 第 423 场周赛 Q1
- **难度**：简单
- **标签**：数组、递增游程、一次扫描

**题意**：给定长度为 $n$ 的整数数组 $\textit{nums}$ 和整数 $k$，判断是否存在两个**相邻**且长度均为 $k$ 的**严格递增**子数组。即是否存在下标 $a < b$，同时满足：

1. $\textit{nums}[a..a+k-1]$ 严格递增；
2. $\textit{nums}[b..b+k-1]$ 严格递增；
3. $b = a + k$（后一段恰好紧接在前一段后面）。

存在返回 `true`，否则返回 `false`。

**约束**：

- $2 \le n = \textit{nums.length} \le 100$
- $1 \le 2k \le n$
- $-1000 \le \textit{nums}[i] \le 1000$

> ⚠️ **读题关键**：题目只要求两段**各自**严格递增，**不要求**接缝处满足 $\textit{nums}[a+k-1] < \textit{nums}[a+k]$。示例 1 中 $[7,8,9]$ 与 $[2,3,4]$ 相邻（接缝处 $9 > 2$）照样返回 `true`。因此本题**不能**等价成"存在长度 $2k$ 的严格递增段"，这是最大的读题陷阱。

## 2. 示例

**示例 1**

```text
输入：nums = [2,5,7,8,9,2,3,4,3,1], k = 3
输出：true
解释：a = 2 的子数组 [7,8,9] 与 b = 5 的子数组 [2,3,4] 都严格递增，且 b = a + 3。
```

**示例 2**

```text
输入：nums = [1,2,3,4,4,4,4,5,6,7], k = 5
输出：false
解释：中间的 4,4,4 把数组截断，不存在任何长度为 5 的严格递增子数组，更凑不出两个相邻的。
```

**示例 3（自构造，体会接缝）**

```text
输入：nums = [5,6,7,1,2,3], k = 3
输出：true
解释：a = 0 的 [5,6,7] 与 b = 3 的 [1,2,3] 各自严格递增且相邻；接缝处 7 > 1 不影响答案。
```

## 3. 解题思路

### 3.1 暴力思路：枚举起点，逐段检查

枚举第一段起点 $a \in [0,\, n-2k]$，对每个 $a$ 扫描 $2k$ 个元素，分别验证前半段与后半段是否严格递增。

- 时间复杂度 $O(nk)$，本题 $n \le 100$，至多约 $10^4$ 次比较，完全可以通过；
- 但同场 Q2（检测 II）把 $n$ 提到 $2 \times 10^5$，还改问**最大的 $k$**，$O(nk)$ 的暴力既超时也答非所问。签到阶段就值得把 $O(n)$ 的"递增游程"写法练熟——它正是 Q2 的分析基础。

### 3.2 核心观察：递增游程预处理，让"区间递增"变成 O(1) 查询

![两段相邻的递增子数组与接缝示意](images/adjacent_inc_subarrays_concept.svg)

定义 $\text{inc}[i]$ 为**以 $i$ 结尾的最长严格递增连续段的长度**：

$$\text{inc}[i] = \begin{cases} \text{inc}[i-1] + 1, & \textit{nums}[i] > \textit{nums}[i-1] \\ 1, & \text{其他情况} \end{cases}$$

于是有：**任一区间 $\textit{nums}[l..r]$ 严格递增 $\iff \text{inc}[r] \ge r-l+1$**（证明见 §5 引理 1）。

两段相邻（$b = a+k$）意味着它们恰好拼成连续区间 $\textit{nums}[a..a+2k-1]$。记第二段右端点 $e = a + 2k - 1$，则第一段右端点为 $e - k$，判定条件收敛为：

$$\text{inc}[e] \ge k \ \text{且} \ \text{inc}[e-k] \ge k$$

两个条件各自独立，正好对应"两段各自递增、接缝不管"的题意。

### 3.3 算法流程

![O(n) 判定流程图](images/adjacent_inc_subarrays_flow.svg)

1. 一遍扫描求出 $\text{inc}$ 数组；
2. 枚举第二段右端点 $e \in [2k-1,\, n-1]$；
3. 若某个 $e$ 满足 $\text{inc}[e] \ge k$ 且 $\text{inc}[e-k] \ge k$，返回 `true`；
4. 枚举完都不满足，返回 `false`。

### 3.4 示例演算

![示例 1 的 inc 数组演算](images/adjacent_inc_subarrays_walkthrough.svg)

对示例 1，$\text{inc} = [1,2,3,4,5,1,2,3,1,1]$，$k = 3$：$e = 5, 6, 8, 9$ 时 $\text{inc}[e] < 3$ 被跳过；$e = 7$ 时 $\text{inc}[7] = 3 \ge 3$ 且 $\text{inc}[4] = 5 \ge 3$，对应 $a = e - 2k + 1 = 2$，返回 `true`。

## 4. 算法细节

1. **下标一一对应**：合法起点 $a \in [0, n-2k]$ 与第二段右端点 $e = a + 2k - 1 \in [2k-1, n-1]$ 一一对应，枚举 $e$ 不重不漏。
2. **为什么不能只判 $\text{inc}[e] \ge 2k$**：那等价于要求整段 $2k$ 个元素连成一条递增链（连接缝也递增），条件比题意更强。反例：$\textit{nums} = [5,6,7,1,2,3]$、$k=3$，答案为 `true`，但最长递增段只有 3。
3. **数据结构选择**：只需一个 $\text{inc}$ 数组；若用长度 $k+1$ 的滚动数组可把空间降到 $O(k)$，本题无必要。
4. **顺手剪枝**：求 $\text{inc}$ 时若发现 $\text{inc}[i] \ge 2k$，可立即返回 `true`（此时取 $e = i$，两个条件自动满足）。

## 5. 正确性证明

**引理 1**：区间 $\textit{nums}[l..r]$ 严格递增 $\iff \text{inc}[r] \ge r - l + 1$。

**证明**：
（必要性）若 $\textit{nums}[l..r]$ 严格递增，则对每个 $l < i \le r$ 都有 $\textit{nums}[i] > \textit{nums}[i-1]$。对 $i$ 从 $l$ 到 $r$ 归纳：$\text{inc}[l] \ge 1$，且每步 $\text{inc}[i] = \text{inc}[i-1] + 1$，故 $\text{inc}[r] \ge r - l + 1$。
（充分性）若 $\text{inc}[r] \ge r-l+1$，则以 $r$ 结尾的递增段向左至少延伸到下标 $r - \text{inc}[r] + 1 \le l$，即 $[l..r]$ 整段落在同一条递增链上，故严格递增。∎

**定理**：算法返回 `true` $\iff$ 存在满足题意的下标对 $(a,\ b = a+k)$。

**证明**：
（充分性）算法在某个 $e$ 处判定成功，即 $\text{inc}[e] \ge k$ 且 $\text{inc}[e-k] \ge k$。取 $a = e - 2k + 1$，$b = a + k = e - k + 1$。由 $e \ge 2k - 1$ 得 $a \ge 0$；由 $e \le n-1$ 得 $b + k - 1 = e \le n - 1$，两段均不越界。由引理 1，$\text{inc}[e-k] \ge k$ 说明 $\textit{nums}[a..a+k-1]$（右端点 $e-k$）严格递增，$\text{inc}[e] \ge k$ 说明 $\textit{nums}[b..b+k-1]$（右端点 $e$）严格递增，且 $b = a + k$，是合法解。
（必要性）若存在合法解 $(a, a+k)$，取 $e = a + 2k - 1 \in [2k-1, n-1]$。两段分别严格递增，由引理 1 得 $\text{inc}[e-k] \ge k$（第一段右端点 $a+k-1 = e-k$）且 $\text{inc}[e] \ge k$，故算法枚举到该 $e$ 时（或更早）返回 `true`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。求 $\text{inc}$ 数组一遍扫描 $O(n)$；枚举 $e$ 一遍 $O(n)$，每次判定 $O(1)$。
- **空间复杂度**：$O(n)$，即 $\text{inc}$ 数组。（滚动数组可降到 $O(k)$，本题无必要。）

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool hasIncreasingSubarrays(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> inc(n, 1);  // inc[i]：以 i 结尾的最长严格递增段长度
        for (int i = 1; i < n; i++) {
            if (nums[i] > nums[i - 1]) {
                inc[i] = inc[i - 1] + 1;
            }
        }
        // e 是第二段的右端点，对应起点 a = e - 2k + 1
        for (int e = 2 * k - 1; e < n; e++) {
            if (inc[e] >= k && inc[e - k] >= k) {
                return true;
            }
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def hasIncreasingSubarrays(self, nums: List[int], k: int) -> bool:
        n = len(nums)
        inc = [1] * n  # inc[i]：以 i 结尾的最长严格递增段长度
        for i in range(1, n):
            if nums[i] > nums[i - 1]:
                inc[i] = inc[i - 1] + 1
        # e 是第二段的右端点，对应起点 a = e - 2k + 1
        return any(
            inc[e] >= k and inc[e - k] >= k
            for e in range(2 * k - 1, n)
        )
```

## 8. 边界情况与易错点

1. **接缝陷阱（最大坑）**：题意不要求 $\textit{nums}[a+k-1] < \textit{nums}[a+k]$，示例 1 的 $9 > 2$ 就是刻意提醒。误把问题当"找长度 $2k$ 的递增段"会在 $\textit{nums} = [5,6,7,1,2,3]$ 这类数据上答错。

2. **"严格"递增**：相邻相等（示例 2 的 `4,4,4`）同样截断递增段，比较必须用 `>` 而非 `>=`。

3. **枚举边界**：$e \in [2k-1,\, n-1]$（等价于 $a \in [0,\, n-2k]$）。由约束 $2k \le n$，该区间至少含一个候选点。

4. **$k = 1$ 恒为 true**：长度 1 的子数组天然严格递增，只要 $n \ge 2$（约束保证）必有解；通用代码自动覆盖，无需特判。

5. **数值范围**：只做比较、无求和累积，不存在溢出问题，`int` 足够。

6. **迁移到 Q2**：#3350（检测 II）把 $n$ 放大到 $2 \times 10^5$，并改求满足条件的**最大 $k$**。沿用的正是本文的 $\text{inc}$ 游程预处理：枚举每个位置，用两侧段长推出可控的最大 $k$——这正是周赛签到题"沉淀模板"的价值。

**延伸思考**：

- 若额外要求接缝处也递增（即整段 $2k$ 递增），判定退化为"存在 $\text{inc}[e] \ge 2k$"，反而更简单；
