# LeetCode 转置矩阵 题解

## 1. 题目概述

- **标题 / 题号**：转置矩阵（#867，easy）
- **链接**：https://leetcode.cn/problems/transpose-matrix/
- **来源**：LeetCode 第 92 场周赛 Q1
- **难度**：简单
- **标签**：数组、矩阵、模拟

**题意**：给定 $m \times n$ 的二维整数数组 `matrix`，返回它的**转置矩阵**。转置就是把矩阵沿主对角线翻转，交换行索引与列索引：原矩阵 $(i, j)$ 位置的元素，在答案里位于 $(j, i)$。

注意转置后形状会变：$m \times n$ 的输入必然输出 $n \times m$ 的矩阵。

**约束**：

- $m = \text{matrix.length}$，$n = \text{matrix}[i].\text{length}$
- $1 \le m, n \le 1000$
- $-10^9 \le \text{matrix}[i][j] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：matrix = [[1,2,3],[4,5,6],[7,8,9]]
输出：[[1,4,7],[2,5,8],[3,6,9]]
解释：3 × 3 方阵沿主对角线翻折，(0,1) 的 2 与 (1,0) 的 4 互换位置。
```

**示例 2**

```text
输入：matrix = [[1,2,3],[4,5,6]]
输出：[[1,4],[2,5],[3,6]]
解释：2 行 3 列变成 3 行 2 列，形状改变，必须新建矩阵。
```

**示例 3（补充）**

```text
输入：matrix = [[1]]
输出：[[1]]
解释：1 × 1 矩阵转置后不变，是边界最小的情况。
```

## 3. 解题思路

### 3.1 暴力思路

按定义把每个元素搬到新位置，本身就是最优解法，$O(mn)$ 无可优化。真正容易出错的是「想省空间」的两种写法：

1. **试图原地转置**：只有方阵（$m = n$）才能原地交换 $(i,j)$ 与 $(j,i)$；本题允许 $m \ne n$，原地写法会覆盖未读取的数据或写出界。
2. **先按行压成一维数组再按列取**：多花 $O(mn)$ 额外空间与一次拷贝，还容易把列下标算错，没有任何收益。

所以正确的「暴力」就是老老实实新建一个 $n \times m$ 的矩阵，逐格赋值。

### 3.2 核心观察：转置是纯下标映射

![转置只是换一种下标写法：(i, j) → (j, i)](images/wc92_q1_index_mapping.svg)

转置不需要任何算术，只需要交换两个下标：

$$\text{res}[j][i] = \text{matrix}[i][j]$$

三个直接推论：

- 答案的行数 = 原矩阵列数 $n$，答案的列数 = 原矩阵行数 $m$；
- 原矩阵的「第 $i$ 行」变成答案的「第 $i$ 列」，原矩阵的「第 $j$ 列」变成答案的「第 $j$ 行」；
- 每个元素恰好被搬运一次，没有任何重复或遗漏。

### 3.3 算法流程

![形状决定写法：方阵可原地转置，长方形必须另开数组](images/wc92_q1_square_vs_rect.svg)

```text
1. m = 行数，n = 列数
2. 新建矩阵 res，大小为 n 行 m 列
3. for i = 0 .. m-1:
       for j = 0 .. n-1:
           res[j][i] = matrix[i][j]
4. 返回 res
```

外层也可以反过来枚举新行 $j$、内层枚举新列 $i$，两种写法等价；关键是**下标不要写反**。

### 3.4 示例演算

对示例 2 的 `matrix = [[1,2,3],[4,5,6]]`（$m=2$，$n=3$）：

| 原位置 $(i, j)$ | 值 | 新位置 $(j, i)$ |
|------------------|----|------------------|
| (0, 0) | 1 | (0, 0) |
| (0, 1) | 2 | (1, 0) |
| (0, 2) | 3 | (2, 0) |
| (1, 0) | 4 | (0, 1) |
| (1, 1) | 5 | (1, 1) |
| (1, 2) | 6 | (2, 1) |

按新位置排好即得 `[[1,4],[2,5],[3,6]]`，是一个 $3 \times 2$ 的矩阵。

## 4. 算法细节

1. **先取 $m$、$n$**：答案大小由两者共同决定，别习惯性地按 $m \times n$ 申请空间。
2. **C++ 初始化**：`vector<vector<int>> ans(n, vector<int>(m));`，行列顺序分别是 $n$ 与 $m$，写反会越界。
3. **Python 推导式**：`[[matrix[i][j] for i in range(m)] for j in range(n)]`——外层是 $j$（新行），内层是 $i$（新列）。
4. **不要原地修改**：除非题目额外要求（如 48 题），否则不必要地原地操作会引入大量边界判断。
5. **值域**：元素可达 $\pm 10^9$，需要 32 位有符号整型（`int` 足够），但搬运时不要做任何运算。
6. **规模**：$m, n \le 1000$ 时元素总数 $10^6$，$O(mn)$ 完全够用。

## 5. 正确性证明

**引理 1（赋值完备）**：算法对答案矩阵的每个位置 $(j, i)$（$0 \le j < n$，$0 \le i < m$）恰好执行一次赋值。

**证明**：外层循环 $i$ 取遍 $[0, m)$，内层循环 $j$ 取遍 $[0, n)$，组合 $(i, j)$ 与答案位置 $(j, i)$ 一一对应（双射），故每个答案位置恰好被写入一次，不存在遗漏或覆盖。∎

**引理 2（值正确）**：算法结束后，对任意 $0 \le j < n$、$0 \le i < m$ 有 $\text{res}[j][i] = \text{matrix}[i][j]$。

**证明**：由引理 1，位置 $(j,i)$ 的写入值为当次循环的 $\text{matrix}[i][j]$，且仅写一次，故成立。∎

**定理**：算法的返回值是 `matrix` 的转置矩阵。

**证明**：转置矩阵的定义为 $\text{res}[j][i] = \text{matrix}[i][j]$（$0 \le i < m$，$0 \le j < n$），其形状为 $n \times m$；算法返回值形状与之相同（第 3.3 步新建为 $n$ 行 $m$ 列），且逐元素满足该等式（引理 2），故两者相等。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个元素被读取一次、写入一次，无其他开销。
- **空间**：$O(mn)$，用于存放答案矩阵；除此之外只有常数个循环变量，辅助空间 $O(1)$（若题目要求原地转置，方阵情形可做到 $O(1)$ 辅助空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> transpose(vector<vector<int>>& matrix) {
        int m = matrix.size(), n = matrix[0].size();
        vector<vector<int>> ans(n, vector<int>(m));
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) ans[j][i] = matrix[i][j];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def transpose(self, matrix: list[list[int]]) -> list[list[int]]:
        m, n = len(matrix), len(matrix[0])
        return [[matrix[i][j] for i in range(m)] for j in range(n)]
```

## 8. 边界情况与易错点

1. **行列数写反**：把答案建成 $m \times n$ 而不是 $n \times m$，示例 2 会直接越界或输出形状错误。
2. **内层循环顺序写反**：写成 `res[i][j] = matrix[i][j]` 就等于什么都没做（原样返回）。
3. **$1 \times 1$ 矩阵**：答案就是原矩阵，注意不要写成空数组。
4. **单行矩阵**（$m = 1$）：结果是 $n \times 1$ 的列向量；**单列矩阵**（$n = 1$）反之，都是形状变化最容易被忽略的情形。
5. **误用原地交换**：$m \ne n$ 时原地交换会越界；即使是方阵，也只应处理 $i < j$ 的上三角，否则换两次等于没换。
6. **空矩阵**：本题约束 $m, n \ge 1$，无需处理，但写成通用代码时可先判空。
