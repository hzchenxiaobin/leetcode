# LeetCode 获取所有钥匙的最短路径 题解

## 1. 题目概述

- **标题 / 题号**：获取所有钥匙的最短路径（#864，hard）
- **链接**：https://leetcode.cn/problems/shortest-path-to-get-all-keys/
- **来源**：LeetCode 第 92 场周赛 Q4
- **难度**：困难
- **标签**：位运算、广度优先搜索、数组、矩阵

**题意**：给定二维网格 `grid`，格子含义为：`.` 空地、`#` 墙（不可通过）、`@` 起点、小写字母 `a`–`f` 钥匙、大写字母 `A`–`F` 对应的锁。每步可以向上下左右走一格，不能出界、不能穿墙；**钥匙一旦经过就自动拾取**；只有当手里有对应钥匙时才能通过某把锁（钥匙不会被消耗）。设钥匙总数为 $k$（$1 \le k \le 6$），求拿到**全部 $k$ 把钥匙**所需的最少移动次数，做不到则返回 $-1$。

注意目标只是**集齐钥匙**，不是打开所有锁——拿到最后一把钥匙的那一刻就结束。

**约束**：

- $m = \text{grid.length}$，$n = \text{grid}[i].\text{length}$，$1 \le m, n \le 30$
- 网格只含 `.`、`#`、`@`、`a`–`f`、`A`–`F`
- 钥匙数量在 $[1, 6]$ 内，每把钥匙与一把同字母的锁一一对应

## 2. 示例

**示例 1**

```text
输入：grid = ["@.a..","###.#","b.A.B"]
输出：8
解释：先向右两格拿 a（2 步），再绕到 (2,0) 拿 b（6 步），共 8 步。
     途中会经过锁 A，此时已有 a，可以通行。锁 B 始终没开也不影响。
```

**示例 2**

```text
输入：grid = ["@..aA","..B#.","....b"]
输出：6
解释：向右 3 步拿 a，此时可穿过 A；从 (0,4) 向下两格即到 b，共 3 + 3 = 6 步。
```

**示例 3**

```text
输入：grid = ["@Aa"]
输出：-1
解释：a 在锁 A 的右边，而通过 A 需要 a，形成死锁，永远拿不到钥匙。
```

**示例 4（补充）**

```text
输入：grid = ["@aA"]
输出：1
解释：走到 a 就已经集齐全部钥匙，答案是 1；不需要（也不必要）去开锁 A。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是在网格上做 BFS，状态只记 $(r, c)$。这会出错：如果某次到达 $(r,c)$ 时手里没有钥匙 $a$，而另一次到达同一格时已经拿到了 $a$，后者显然更有前途，但「已访问」标记会把后者直接挡掉，导致漏解。

补救方案各有各的坑：

- **只用 DFS 搜路径**：不剪枝时是指数级；剪枝又很难剪对。
- **枚举拿钥匙的顺序**：$k \le 6$ 时最多 $6! = 720$ 种顺序，对每种顺序依次 BFS 求「从当前点到下一个钥匙」的距离。但中途可能顺路捡到别的钥匙、某些门在拿到新钥匙后才开通，这些情况会让「按固定顺序分段求最短路」失效或需要额外修正。

问题的本质是：**「我在哪」不足以描述当前局面，「我有哪些钥匙」也是状态的一部分**。

### 3.2 核心观察：状态 = 位置 + 钥匙集合

![状态空间：位置 × 钥匙集合，把「记忆」压进 mask](images/wc92_q4_state_layers.svg)

把钥匙集合压缩进一个整数 `mask`：第 $i$ 位为 1 表示已拥有字母表中第 $i$ 把钥匙（`a`/`A` 对应 bit 0，`b`/`B` 对应 bit 1……）。于是状态定义为

$$\text{state} = (r,\, c,\, \text{mask})$$

在这个扩展状态图上：

- **普通移动**：$(r,c,\text{mask}) \to (r',c',\text{mask})$，四联通；
- **钥匙格**（小写 `ch`）：$\text{mask}' = \text{mask} \mid (1 \ll (ch - \text{'a'}))$，集合只增不减；
- **锁格**（大写 `ch`）：仅当 $\text{mask}$ 的第 $(ch - \text{'A'})$ 位为 1 时允许通过；
- **墙**：不可通过。

状态总数 $m \cdot n \cdot 2^k \le 30 \times 30 \times 64 = 57600$，边权全为 1，**直接 BFS**，第一次到达 $\text{mask} = 2^k - 1$（全部钥匙）时的步数就是答案。

![位运算细节：第 i 位代表第 i 把钥匙 / 锁](images/wc92_q4_key_mask.svg)

### 3.3 算法流程

```text
1. 扫描网格：找到起点 @，收集所有小写字母，allKeys = 所有钥匙位的并集
2. dist[r][c][mask] 全初始化为 -1；dist[sr][sc][0] = 0
3. 队列 q = [(sr, sc, 0)]
4. while q 非空：
       取出 (r, c, mask)
       若 mask == allKeys：返回 dist[r][c][mask]（入队时已保证是最短）
       对四个方向 (nr, nc)：
           越界或为 '#'：跳过
           nmask = mask
           若 grid[nr][nc] 是小写字母：nmask |= 1 << (ch - 'a')
           若 grid[nr][nc] 是大写字母：若 mask 缺少对应位则跳过
           若 dist[nr][nc][nmask] != -1：跳过
           dist[nr][nc][nmask] = dist[r][c][mask] + 1
           若 nmask == allKeys：立即返回该距离
           入队 (nr, nc, nmask)
5. 队列空仍未集齐 ⇒ 返回 -1
```

在「入队时判定并返回」与「出队时判定」都正确，前者更早结束；两者都要保证先判 `nmask` 再判重复访问。

### 3.4 示例演算

![示例走查：先拿 a、再穿过门 A 拿 b，共 8 步](images/wc92_q4_walkthrough.svg)

对示例 1 的网格：

```text
@ . a . .
# # # . #
b . A . B
```

| 步数 | 状态 (r, c, mask) | 事件 |
|------|--------------------|------|
| 0 | (0,0), 00 | 起点 |
| 1 | (0,1), 00 | 向右 |
| 2 | (0,2), 01 | 拿到 a，mask 变为 01 |
| 3 | (0,3), 01 | 落到列 3 的通道 |
| 4 | (1,3), 01 | 向下 |
| 5 | (2,3), 01 | 向下 |
| 6 | (2,2), 01 | 经过锁 A：检查 bit0 = 1，通过 |
| 7 | (2,1), 01 | 继续向左 |
| 8 | (2,0), 11 | 拿到 b，mask 集齐，返回 8 |

再对示例 2 验证一次「锁改变地形」的效果：$\text{grid} = [\texttt{"@..aA"}, \texttt{"..B\#."}, \texttt{"....b"}]$。拿到 a 之前 $(0,4)$ 是锁 A、不可通行；拿到 a 之后 A 变成可走格，于是 $(0,3) \to (0,4) \to (1,4) \to (2,4)$ 三步就到 b，总共 $3 + 3 = 6$。

## 4. 算法细节

1. **mask 的定义**：用 `1 << (ch - 'a')` 编钥匙位、`1 << (ch - 'A')` 编锁位，两套下标天然对齐。
2. **目标态**：`allKeys` 是**实际出现**的钥匙位并集，不是 `(1 << 6) - 1`；二者只有在恰好 6 把钥匙时才相同。
3. **距离数组**：三维 `dist[m][n][allKeys + 1]`，值为 -1 表示未访问；也可以只用 `visited` + 队列里存步数。
4. **不消耗钥匙**：通过锁时 `mask` 不变，这正是「状态足够刻画未来」的关键——门是否可通行只取决于 `mask`，没有「门被开过」这种额外记忆。
5. **起点不是钥匙**：`@` 格不改变 `mask`，所以初始状态是 $(sr, sc, 0)$。
6. **入队即判定**：BFS 的队列按步数非降序，第一次生成 `nmask == allKeys` 时就已最优，可立即返回。
7. **剪枝顺序**：先判墙、再判锁、再判是否已访问，可以少算几次 `mask`。

## 5. 正确性证明

把问题建模为状态图 $G$：顶点为所有 $(r, c, \text{mask})$，边为上文定义的合法转移。

**引理 1（转移合法）**：算法构造的每条边都对应一次合法的移动。

**证明**：边 $(r,c,m)\to(r',c',m')$ 要求 $(r',c')$ 在界内且不是墙；若为锁则要求 $m$ 的对应位为 1（即手里确有该钥匙），正符合题意；若为钥匙格则 $m' = m \mid \text{bit}$，模拟拾取；其余 $m' = m$。故每一步都是合法的一格移动，且 `mask` 的更新与钥匙拾取规则一致。∎

**引理 2（钥匙单调）**：沿任意路径，`mask` 的位数只增不减，且始终是 `allKeys` 的子集。

**证明**：只有钥匙格会修改 `mask`，且只做按位或，故已置的位不会清零；置的位都是网格中实际出现的钥匙位，故仍是 `allKeys` 子集。∎

**引理 3（状态充分性）**：若两条路径终止于同一状态 $(r,c,m)$，则它们后续可用的动作集合与能达到的最优终态完全相同。

**证明**：后续每一步的合法性只依赖三件事：当前位置 $(r,c)$、目标格是否墙/锁、以及锁对应的钥匙位是否在 $m$ 中；由引理 2，`mask` 只增不减且与历史无关地决定「哪些锁可通行」。题目规定钥匙不会被消耗、门也不需要有「已开」的状态，因此历史路径不提供任何额外信息。故从同一状态出发，后续可达路径集合相同，最优后续步数也相同。∎

**引理 4（BFS 最短性）**：$G$ 中所有边权为 1，BFS 中状态 $u$ 首次被访问时的层号等于 $s$ 到 $u$ 的最短距离。

**证明**：标准 BFS 结论。对层号归纳：第 $d$ 层恰好是所有距离为 $d$ 的状态（距离 $< d$ 的已被访问、距离 $= d$ 的由第 $d-1$ 层扩展得到、距离 $> d$ 的尚未被扩展），故首次访问即最短。∎

**定理**：算法返回值为集齐全部钥匙的最少移动次数；若不可达则返回 $-1$。

**证明**：由引理 1，算法中每条路径都对应一个合法的走法序列，故返回值不会小于真实最优；由引理 3，把任意合法走法序列映射到 $G$ 中的路径不会丢失信息，故 $G$ 中的最短路与真实最优走法一一对应；由引理 4，BFS 第一次生成 $\text{mask} = \text{allKeys}$ 的状态时步数最小，正是所求。若 BFS 遍历完所有可达状态仍未集齐，则真实最优不存在，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(m \cdot n \cdot 2^k)$。状态数上界 $30 \times 30 \times 64 = 57600$，每个状态最多扩展 4 条边，总转移数不超过 $4mn2^k$；扫描网格求起点与 `allKeys` 是 $O(mn)$。
- **空间**：$O(m \cdot n \cdot 2^k)$。`dist` 三维数组约 $230$ KB（`int`），BFS 队列最坏存下全部状态。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int shortestPathAllKeys(vector<string>& grid) {
        int m = grid.size(), n = grid[0].size();
        int sr = 0, sc = 0, allKeys = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                char ch = grid[i][j];
                if (ch == '@') { sr = i; sc = j; }
                else if (ch >= 'a' && ch <= 'f') allKeys |= 1 << (ch - 'a');
            }
        }
        if (allKeys == 0) return 0;

        vector<vector<vector<int>>> dist(m, vector<vector<int>>(n, vector<int>(allKeys + 1, -1)));
        dist[sr][sc][0] = 0;
        queue<array<int, 3>> q;
        q.push({sr, sc, 0});
        const int dr[4] = {1, -1, 0, 0};
        const int dc[4] = {0, 0, 1, -1};
        while (!q.empty()) {
            auto [r, c, mask] = q.front();
            q.pop();
            int step = dist[r][c][mask];
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
                char ch = grid[nr][nc];
                if (ch == '#') continue;
                int nmask = mask;
                if (ch >= 'a' && ch <= 'f') nmask |= 1 << (ch - 'a');
                else if (ch >= 'A' && ch <= 'F') {
                    if (!(mask >> (ch - 'A') & 1)) continue;
                }
                if (dist[nr][nc][nmask] != -1) continue;
                dist[nr][nc][nmask] = step + 1;
                if (nmask == allKeys) return step + 1;
                q.push({nr, nc, nmask});
            }
        }
        return -1;
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def shortestPathAllKeys(self, grid: list[str]) -> int:
        m, n = len(grid), len(grid[0])
        sr = sc = 0
        all_keys = 0
        for i in range(m):
            for j in range(n):
                ch = grid[i][j]
                if ch == '@':
                    sr, sc = i, j
                elif 'a' <= ch <= 'f':
                    all_keys |= 1 << (ord(ch) - ord('a'))
        if all_keys == 0:
            return 0

        dist = [[[-1] * (all_keys + 1) for _ in range(n)] for _ in range(m)]
        dist[sr][sc][0] = 0
        q = deque([(sr, sc, 0)])
        while q:
            r, c, mask = q.popleft()
            step = dist[r][c][mask]
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if not (0 <= nr < m and 0 <= nc < n):
                    continue
                ch = grid[nr][nc]
                if ch == '#':
                    continue
                nmask = mask
                if 'a' <= ch <= 'f':
                    nmask |= 1 << (ord(ch) - ord('a'))
                elif 'A' <= ch <= 'F':
                    if not (mask >> (ord(ch) - ord('A')) & 1):
                        continue
                if dist[nr][nc][nmask] != -1:
                    continue
                dist[nr][nc][nmask] = step + 1
                if nmask == all_keys:
                    return step + 1
                q.append((nr, nc, nmask))
        return -1
```

## 8. 边界情况与易错点

1. **只用 `visited[r][c]`**：本例最经典的错误。同一个格子在「有钥匙」和「没钥匙」时是不同状态，必须三维标记，否则会漏掉「回头拿钥匙再穿门」的路线（示例 2 依赖这一点）。
2. **`allKeys` 写死成 63**：若网格只有 2 把钥匙，目标应是 `0b11 = 3`；写死 63 会永远到不了，返回 -1。
3. **锁的判定用错下标**：钥匙用 `ch - 'a'`、锁用 `ch - 'A'`，混用会把 `A` 当成 `a` 之外的位。
4. **把目标当成「开所有锁」**：题面明确只要集齐钥匙；示例 4 中 `["@aA"]` 答案是 1 而不是 2。
5. **忘记 `@` 不改变 `mask`**：起点初始化应为 `dist[sr][sc][0] = 0`，不要试图去「拾取起点」。
6. **`-1` 与不可达**：示例 3 的死锁（a 在 A 后面）必须返回 -1，不要返回一个大数或 0。
7. **在入队处判定时漏掉初始状态**：若起点本身就是「全部钥匙已集齐」（本题不可能，因为没有钥匙在起点），需要额外判一次 `0 == allKeys`；代码里保留该分支更稳健。
