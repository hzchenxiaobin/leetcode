# LeetCode 商品折扣后的最终价格 题解

## 1. 题目概述

- **标题 / 题号**：商品折扣后的最终价格（#1475，easy）
- **链接**：https://leetcode.cn/problems/final-prices-with-a-special-discount-in-a-shop/
- **来源**：LeetCode 第 28 场双周赛 Q1
- **难度**：简单
- **标签**：栈、数组、单调栈

**题意**：数组 prices 中 prices[i] 是第 i 件商品的价格。购买第 i 件商品时，可享受折扣 prices[j]，其中 j 是满足 $j > i$ 且 $prices[j] \le prices[i]$ 的**最小下标**；不存在这样的 j 则无折扣。返回数组 ans，ans[i] 为购买第 i 件商品最终支付的价格（即 $prices[i] -$ 折扣）。

**约束**：

- $1 \le prices.length \le 500$
- $1 \le prices[i] \le 10^3$

## 2. 示例

**示例 1**

```text
输入：prices = [8,4,6,2,3]
输出：[4,2,4,2,3]
解释：商品 0 折扣为 prices[1]=4（8−4=4）；商品 1 折扣为 prices[3]=2（4−2=2）；
      商品 2 折扣为 prices[3]=2（6−2=4）；商品 3、4 无折扣。
```

**示例 2**

```text
输入：prices = [1,2,3,4,5]
输出：[1,2,3,4,5]
解释：严格递增，每件商品右侧都没有更小或相等的价格，全部无折扣。
```

**示例 3**

```text
输入：prices = [10,1,1,6]
输出：[9,0,1,6]
解释：商品 0 折扣为 prices[1]=1；商品 1 折扣为 prices[2]=1（相等也打折！）；商品 3 无折扣。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 向右线性扫描找到第一个满足 $prices[j] \le prices[i]$ 的下标 $j$，单次最坏 $O(n)$，总计 $O(n^2)$。$n = 500$ 时约 $2.5 \times 10^5$ 次操作，本题完全能过——但这是「下一个更小元素」的教科书场景，单调栈是必须沉淀的模板（$n$ 放大到 $10^5$ 时暴力就会超时）。

### 3.2 核心观察：折扣来源 = 「下一个小于等于自己」的元素 → 单调栈

![核心观察：下一更小或相等元素](images/bw28_q1_monotonic_stack.svg)

「右侧第一个 $prices[j] \le prices[i]$」正是经典的**下一更小（或相等）元素**问题。单调栈一次扫描解决：栈中存放「还没等到折扣」的商品下标，保持栈内价格自底向顶**严格递增**。新价格 $p$ 进栈前，把所有栈顶价格 $\ge p$ 的商品弹出——它们右边的第一个「不大于自己」的价格恰好就是当前的 $p$，当场结算 $ans = prices[j] - p$。

为什么弹出的商品折扣恰是 $p$？因为这些商品右侧比 $p$ 更早出现且 $\le$ 它们的价格早已在之前的弹栈中出现过了——栈的严格递增性保证了这一点（§5 严格证明）。

### 3.3 算法流程

![算法流程：入栈、弹栈结算、剩余原价](images/bw28_q1_algorithm_flow.svg)

```text
1. 栈 st 清空，ans 预填 0
2. for i = 0 .. n−1：
       while st 非空 且 prices[st.top()] >= prices[i]:
           j = st.pop()
           ans[j] = prices[j] − prices[i]      # i 就是 j 的折扣来源
       st.push(i)
3. 扫描结束仍在栈中的下标：右侧无人 ≤ 它 → ans[j] = prices[j]（原价）
```

弹栈条件是 $\ge$（而不是 $>$）：相等价格也能当折扣（示例 3 的两个 1）。

### 3.4 示例演算

![示例演算：[8,4,6,2,3] 的单调栈全过程](images/bw28_q1_example_walkthrough.svg)

以示例 1 为例：i=0 入 8；i=1 时 4 < 8 弹出 8（结算 8−4=4），入 4；i=2 时 6 > 4 直接入栈（栈 4,6）；i=3 时 2 ≤ 6、2 ≤ 4 **连弹两个**（结算 6−2=4、4−2=2），入 2；i=4 时 3 > 2 入栈（栈 2,3）。收尾：2 与 3 原价保留 → ans = [4,2,4,2,3]。

## 4. 算法细节

1. **栈存下标而非价格**：结算时需要知道「是谁被打折」（写下标），价格可随时经下标查询；只存价格会丢失目标位置。
2. **严格递增还是非严格**：弹栈用 $\ge$ 时，栈内剩下的必然 $< p$，即栈内价格**严格递增**。相等元素一旦出现就立即结算出栈，不会共存于栈中。
3. **逆序栈循环收尾**：扫描结束后栈内下标右侧无更小元素，直接原价；也可以在初始化时 `ans = prices` 然后只改被弹出的位置，等价且少一个循环。
4. **复杂度保证**：每个下标恰入栈一次、出栈至多一次，while 循环的总弹出次数以 $n$ 为上界，整体均摊 $O(1)$ 每步。
5. **方向变体**：本题求「右侧下一个 ≤」，从左到右扫、弹 ≥；若题目改成「左侧下一个更小」，则从右往左扫或倒序处理——套路完全对称。

## 5. 正确性证明

**引理 1（栈的递增性）**：任意时刻，栈内下标对应的价格从底到顶严格递增。

**证明**：只有「栈顶价格 $<$ 当前价格」时当前下标才入栈（否则栈顶在入栈前已被弹出），故每次入栈都保持严格递增。初始栈空，归纳成立。∎

**引理 2（结算正确）**：当下标 $j$ 因 $p = prices[i]$ 被弹出时，$i$ 正是满足 $i > j$ 且 $prices[i] \le prices[j]$ 的最小下标。

**证明**：先证 $prices[i] \le prices[j]$：弹出条件即 $prices[j] \ge p$。再证 $i$ 最小：反设存在 $j < i' < i$ 且 $prices[i'] \le prices[j]$。考察 $i'$ 入栈的时刻：若 $i'$ 当时在栈中位于 $j$ 之上（或取代被弹出的 $j$），由于 $prices[i'] \le prices[j]$，$j$ 在 $i'$ 入栈的弹栈循环中就会被弹出（弹栈条件 $\ge$），轮不到 $i$ 来弹出它；若 $j$ 在 $i'$ 入栈时已不在栈中，则 $j$ 已被某个更早的 $i'' < i'$ 结算过，与 $j$ 存活到 $i$ 矛盾。两种情形都矛盾，故 $i$ 是最小下标。∎

**定理**：算法输出的 ans[i] 等于 $prices[i] -$（右侧第一个 $\le$ 它的价格，若存在，否则 0）。

**证明**：由引理 2，每个被弹出的下标 $j$ 恰在「其折扣来源」$i$ 出现的瞬间被结算为 $prices[j] - prices[i]$，且此后不再修改（已出栈）；由引理 1 与弹栈逻辑，扫描结束时仍在栈中的下标右侧不存在任何 $\le$ 它的价格——否则那个价格出现时会将其弹出——故按无折扣（原价）结算正确。每个下标要么被弹出（有折扣分支）要么留栈（无折扣分支），二者穷尽所有情形且互不冲突。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标入栈、出栈各至多一次，while 循环总步数 $\le 2n$；$n \le 500$ 远在安全区。
- **空间**：$O(n)$。栈深度最坏 $n$（严格递增输入，如示例 2）；输出数组不计入额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> finalPrices(vector<int>& prices) {
        int n = (int)prices.size();
        vector<int> ans(n);
        stack<int> st;                          // 存下标，栈内价格自底向顶严格递增
        for (int i = 0; i < n; ++i) {
            while (!st.empty() && prices[st.top()] >= prices[i]) {
                ans[st.top()] = prices[st.top()] - prices[i];   // i 是首个 ≤ 它的后续下标
                st.pop();
            }
            st.push(i);
        }
        while (!st.empty()) { ans[st.top()] = prices[st.top()]; st.pop(); }  // 无折扣
        return ans;
    }
};
```

### Python

```python
class Solution:
    def finalPrices(self, prices: List[int]) -> List[int]:
        ans = prices[:]                         # 默认原价，被弹出时覆盖
        st = []                                 # 下标栈，栈内价格严格递增
        for i, p in enumerate(prices):
            while st and prices[st[-1]] >= p:
                j = st.pop()
                ans[j] = prices[j] - p          # i 就是 j 的折扣来源
            st.append(i)
        return ans
```

> 💡 两份代码均通过全部官方示例（[4,2,4,2,3] / [1,2,3,4,5] / [9,0,1,6]）及相等价格、单元素等边界；并与暴力实现做了 5 万组随机对拍（含全相等、严格递增/递减定向用例），失配数为 0。

## 8. 边界情况与易错点

1. **相等价格也算折扣**：弹栈条件必须是 $\ge$ 而非 $>$。示例 3 中 prices[2]=1 给 prices[1]=1 当折扣（ans[1]=0），写错条件会得到 [9,0,0,6] 的错误答案。
2. **无折扣的收尾**：留栈下标容易忘结算。Python 版用 `ans = prices[:]` 预填原价天然规避；C++ 版需显式收尾循环。
3. **单元素数组**：直接入栈后留栈收尾，输出原价，逻辑自然覆盖。
4. **溢出无虞但别写反**：$prices[j] - prices[i] \ge 0$ 恒成立（弹出时保证 $prices[j] \ge prices[i]$），不会出现负数；若把弹出条件写成 $\le$ 就会出现负的价格差。
5. **栈里存价格**：常见错误——只存价格就找不到该给谁打折，务必存下标。
