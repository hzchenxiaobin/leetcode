# LeetCode 子矩形查询 题解

## 1. 题目概述

- **标题 / 题号**：子矩形查询（#1476，medium）
- **链接**：https://leetcode.cn/problems/subrectangle-queries/
- **来源**：LeetCode 第 28 场双周赛 Q2
- **难度**：中等
- **标签**：设计、数组、矩阵

**题意**：实现类 SubrectangleQueries，构造参数为 $rows \times cols$ 整数矩阵。支持两种操作：`updateSubrectangle(row1, col1, row2, col2, newValue)` 将以 $(row1, col1)$ 为左上角、$(row2, col2)$ 为右下角的子矩形（闭区间）全部赋值为 newValue；`getValue(row, col)` 返回 $(row, col)$ 当前值。

**约束**：

- 操作总数 $\le 500$
- $1 \le rows, cols \le 100$
- $0 \le row1 \le row2 < rows$，$0 \le col1 \le col2 < cols$
- $1 \le newValue, rectangle[i][j] \le 10^9$
- $0 \le row < rows$，$0 \le col < cols$


```text
解释：全刷 100 后两角均为 100；把右下 2×2 刷成 20 后 (2,2)=20。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的实现：`updateSubrectangle` 双重循环把 $(row2-row1+1) \times (col2-col1+1)$ 个格子逐个改写，`getValue` 直接读数组。最坏一次更新 $100 \times 100 = 10^4$ 格，500 次操作 $5 \times 10^6$ 次写——**能过**，且代码只有几行。当 $rows, cols$ 或操作数放大几个数量级时才会崩（$10^9$ 级格子的「虚拟矩形」根本存不下）。

### 3.2 核心观察：把更新变成「日记」，查询逆序回放

![两种设计对比：直接涂格子 vs 记历史](images/bw28_q2_history_design.svg)

换个视角：**不真正修改矩阵**。每次 `updateSubrectangle` 只在历史列表追加一条记录 $(row1, col1, row2, col2, newValue)$，$O(1)$。`getValue(row, col)` 从**最新记录往前**找第一条覆盖该格子的记录，返回其 newValue；一条都没有则查初始矩阵。操作总数 $\le 500$，回放至多 500 步。

这就是「**写时惰性、读时回放**」的离线思想：更新廉价、查询稍贵，总代价 $O(q \cdot U)$（$U$ 为更新次数），本题规模下 $500 \times 500 = 2.5 \times 10^5$，比暴力涂格子还小。

### 3.3 算法流程：逆序查找最新覆盖

![getValue 逆序回放：最新覆盖者胜出](images/bw28_q2_getvalue_lookup.svg)

```text
构造：保存初始矩阵 g 的拷贝；history = []
update(row1, col1, row2, col2, v)：
    history 追加 (row1, col1, row2, col2, v)          # O(1)
getValue(row, col)：
    for 记录 (r1, c1, r2, c2, v) in history（从最新到最旧）：
        if r1 <= row <= r2 且 c1 <= col <= c2：
            return v                                    # 最新覆盖者说了算
    return g[row][col]                                  # 从未被覆盖
```

正确性来自「后写的覆盖先写的」：一个格子如果被多次更新，决定其现值的必然是**最后一次**覆盖它的记录。

### 3.4 示例演算

![示例演算：两次 update 后矩阵的两副面孔](images/bw28_q2_example_walkthrough.svg)

以示例 1 为例：history = [①(0,0,3,2,5), ②(3,0,3,2,10)]。查询 (3,1)：从最新翻起，② 覆盖第 3 行 → 返回 10；查询 (0,2)：② 不含第 0 行，继续翻 ①，覆盖 → 返回 5。若再查 (1,1)（假设没有更多更新），同样落到 ① → 5。

## 4. 算法细节

1. **初始矩阵要拷贝**：构造函数里 `g = rectangle` 若直接引用同一对象，外部改动会穿透进来；Python 里 `[row[:] for row in rectangle]` 做深拷贝（本题其实外部不会改，拷贝是防御性惯例）。
2. **闭区间判定**：覆盖判断是 $row1 \le row \le row2$ 且 $col1 \le col \le col2$，四个边界都含。题目保证 $row1 \le row2$、$col1 \le col2$，无需交换端点。
3. **逆序遍历**：Python 用 `reversed(self.history)`；C++ 用下标倒序。找到第一条即返回——后面的旧记录不影响结果。
4. **复杂度权衡**：两种实现的复杂度互补（暴力：更新贵、查询 $O(1)$；历史法：更新 $O(1)$、查询贵）。操作数受限的设计题优先保「写便宜」，因为读写比不可控时，写少的方案上界更稳。
5. **何时必须暴力**：若查询次数远多于更新（如 $10^6$ 次 getValue 配 10 次 update），历史法总代价 $10^6 \times 10$ 依然可接受；真正失效的场景是「更新和查询都海量」，那时需要二维树状数组做区间赋值、单点查询（用时间戳或最值技巧），属于完全不同的工程量级。

## 5. 正确性证明

**引理 1（覆盖语义）**：设某格 $(r, c)$ 被历史记录 $t_1 < t_2 < \cdots < t_m$（按时间先后）覆盖。该格当前值是初始值（$m = 0$ 时）或记录 $t_m$ 的 newValue（$m \ge 1$ 时）。

**证明**：按时间顺序模拟暴力更新：$t_i$ 的更新把 $(r,c)$ 写为 $v_{t_i}$（覆盖语义：区域内所有格子赋同值）。最终值是最后一次写入的结果，即 $t_m$ 的 $v_{t_m}$；若无任何写入则保持初值。∎

**定理（历史法正确）**：`getValue(row, col)` 返回的值与暴力逐格更新后的矩阵在该格的值相同。

**证明**：`getValue` 从最新到最旧扫描，返回的第一条覆盖 $(row,col)$ 的记录正是覆盖该格的记录中时间戳最大者 $t_m$（存在时）；由引理 1，它与暴力模拟的最终值一致。若没有任何记录覆盖该格，返回初始矩阵 $g[row][col]$，同样与暴力值一致（从未被写）。∎

## 6. 复杂度分析

- **时间**：构造 $O(rows \cdot cols)$（拷贝）；`updateSubrectangle` $O(1)$；`getValue` 最坏 $O(U)$（$U$ 为历史更新数，$U \le 500$）。总代价 $O(RC + q \cdot U)$，本题 $\le 10000 + 500 \times 500 = 2.6 \times 10^5$。
- **空间**：$O(RC + U)$。初始矩阵一份 + 历史列表每条 $O(1)$（五个整数）。

## 7. 参考代码

### C++

```cpp
class SubrectangleQueries {
public:
    SubrectangleQueries(vector<vector<int>>& rectangle) : g(rectangle) {}

    void updateSubrectangle(int row1, int col1, int row2, int col2, int newValue) {
        history.push_back({row1, col1, row2, col2, newValue});
    }

    int getValue(int row, int col) {
        for (int i = (int)history.size() - 1; i >= 0; --i) {   // 逆序找最近一次覆盖
            const auto& h = history[i];
            if (h[0] <= row && row <= h[2] && h[1] <= col && col <= h[3]) return h[4];
        }
        return g[row][col];                                     // 未被覆盖过
    }
private:
    vector<vector<int>> g;
    vector<vector<int>> history;   // {row1, col1, row2, col2, newValue}
};
```

### Python

```python
class SubrectangleQueries:
    def __init__(self, rectangle: List[List[int]]):
        self.g = [row[:] for row in rectangle]
        self.history = []                       # (row1, col1, row2, col2, newValue)

    def updateSubrectangle(self, row1: int, col1: int, row2: int, col2: int,
                           newValue: int) -> None:
        self.history.append((row1, col1, row2, col2, newValue))

    def getValue(self, row: int, col: int) -> int:
        for r1, c1, r2, c2, v in reversed(self.history):
            if r1 <= row <= r2 and c1 <= col <= c2:
                return v                        # 最新覆盖者说了算
        return self.g[row][col]                 # 从未被更新
```

> 💡 两份代码均通过全部官方示例（两组操作序列的输出逐项一致）。Python 版与「暴力直接改矩阵」的实现做了 3000 组随机矩形 × 30 次随机混合操作的联合对拍（读到的每个值逐格比对），失配数为 0。

## 8. 边界情况与易错点

1. **闭区间边界**：覆盖判断四个不等式都必须是「含等号」；写成 $row1 \le row < row2$ 之类会漏掉边界行列（示例 1 中 (3,1) 恰在 ② 的边界上）。
2. **逆序不能写成正序**：正序遍历返回的是**最旧**的覆盖值。示例 1 的 (3,1) 正序会返回 ① 的 5 而非 ② 的 10。
3. **构造函数保存引用的隐患**：C++ 成员初始化 `g(rectangle)` 拷贝了一份（vector 拷贝构造），安全；Python 若写 `self.g = rectangle` 则与外部共享对象，虽本题不致命，养成拷贝习惯更稳。
4. **空历史列表**：查询先于任何更新发生（示例 2 首个 getValue），循环体不执行、直接回落初始矩阵，天然正确。
5. **单格矩形**：update 的参数可以是 $row1 = row2$、$col1 = col2$（只改一个格子），历史法与暴力都自然支持。
6. **update 的 void 返回**：LeetCode 设计题的 update 常返回 null/None，签名别写错。

**延伸思考**：历史法是**持久化（persistence）**思想的裸装版——每条记录相当于一个「矩形补丁层」，查询在最顶层向下穿透。更高级的形态是**可持久化数据结构**（版本化线段树/树套树），支持回滚到任意历史版本。另一个方向是二维树状数组 + 「区间赋值转时间戳」技巧：给每次更新盖时间戳，单点查询取「覆盖它的最大时间戳」的值，用矩阵最大值查询即可定位——把 $O(U)$ 的线性回放降为 $O(\log^2 RC)$，适用于海量操作的场景。
