# LeetCode 叶值的最小代价生成树 题解

## 1. 题目概述

- **标题 / 题号**：叶值的最小代价生成树（#1130，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-tree-from-leaf-values/
- **来源**：LeetCode 第 146 场周赛 Q3
- **难度**：中等
- **标签**：栈，贪心，数组，动态规划，笛卡尔树，单调栈

**题意**：给定正整数数组 `arr`，只考虑这样的二叉树——每个节点有 $0$ 个或 $2$ 个孩子，且叶子按**中序遍历**恰好依次是 `arr` 的各个元素。每个非叶节点的值定义为「左子树叶子最大值 × 右子树叶子最大值」。在所有合法树中，求**非叶节点值之和**的最小值。

换句话说，树只有**形状**的自由度，叶子的排列被 `arr` 钉死；每个内部节点收取一次「左右两边各自最大叶值」的乘积，要求总收费最小。

**约束**：

- $2 \le \text{arr.length} \le 40$
- $1 \le \text{arr}[i] \le 15$
- 答案保证落在 32 位有符号整数范围内（$< 2^{31}$）

> 💡 「每个节点 0 或 2 个孩子」意味着 $n$ 个叶子必然对应 $n-1$ 个内部节点，而一棵树的形状与「把 $n$ 个叶子按顺序两两合并成一段的过程」一一对应——这是本题所有推演的起点。

## 2. 示例

**示例 1**

```text
输入：arr = [6,2,4]
输出：32
解释：只有两种形状。
      (1) 先并 6,2：内部节点 6×2 = 12，再并 (6,2) 与 4：6×4 = 24，总和 36。
      (2) 先并 2,4：内部节点 2×4 = 8，再并 6 与 (2,4)：6×4 = 24，总和 32。
      取较小者 32。
```

**示例 2**

```text
输入：arr = [4,11]
输出：44
解释：只有一次合并，4 × 11 = 44。
```

**示例 3（补充，便于对照后文的贪心）**

```text
输入：arr = [5,2,3,1]
输出：24
解释：1 与右侧的 3 合并（1×3 = 3），2 与 3 合并（2×3 = 6），剩下 5 与 3 合并（3×5 = 15），总和 3+6+15 = 24。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的是**枚举所有合法形状**：$n$ 个叶子的满二叉树共有第 $n-1$ 个卡特兰数种，$n = 40$ 时约为 $6.8\times 10^{20}$，显然不可行。

稍加思考就能把它变成区间 DP（也是官方提示的做法）。记

$$dp[i][j] = \text{把 } arr[i..j] \text{ 建成一棵子树的最小非叶和},\qquad mx[i][j] = \max(arr[i..j])$$

最后一次合并必然把区间切成左右两段：

$$dp[i][j] = \min_{i \le k < j}\Big(dp[i][k] + dp[k+1][j] + mx[i][k]\cdot mx[k+1][j]\Big)$$

$n \le 40$ 时 $O(n^3) \approx 1.1\times 10^4$ 次转移，足够通过；但如果每次都要重新求 $mx$，常数会翻倍，所以应当先 $O(n^2)$ 预处理出最大值表（或按区间长度递推）。

DP 是正确的，可它**没有揭示结构**：题面里「乘积」这个特殊代价其实允许更强的结论——存在一个 $O(n)$ 的贪心，答案完全由「每个元素和它左右最近的不小于它的元素」决定。

### 3.2 核心观察：树 = 合并顺序，代价逐元素计费

![合并模型与逐元素计费公式](images/wc146_q3_merge_cost_model.svg)

把 $n$ 个叶子看成 $n$ 个长度为 $1$ 的**块**，每个内部节点对应一次「把相邻两块合成一块」的操作。一块的最大值合并后就是两者中的较大者，与原块内部长什么样**无关**。于是：

> **观察 1**：第 $t$ 次合并的代价只取决于两个块各自的**最大值**，与块内部的树形无关。

因此问题彻底变成：有 $n$ 个初值，每次合并相邻两个并把二者的较大值保留下来作为新块，代价为二者之积，求 $n-1$ 次合并的最小总代价。

接下来是关键的**计费（charging）视角**。除全局最大者外，每个元素 $a[i]$ 终将被「吸收」一次：终有一刻它所在的块（最大值就是 $a[i]$）与一个**最大值更大**的块合并。由于只能合并相邻块，那个更大的块只能来自 $a[i]$ 的左边或右边——精确地说，来自左右两侧**最近的 ≥ 邻居**方向，且代价中乘上的因子不小于该邻居的值。两侧都能选时，取较小的那侧最便宜：

$$G = \sum_{i}\ a[i]\cdot \min\big(a[L(i)],\ a[R(i)]\big)$$

其中 $L(i)$ / $R(i)$ 是 $i$ 左右两侧第一个 $\ge a[i]$ 的下标（不存在记 $+\infty$），全局最大者不计入。示例 1 中 $2$ 的左右邻居是 $6$ 与 $4$，取 $4$ 得 $8$；$4$ 只有左侧 $6$，得 $24$；合计 $32$ —— 与示例 1 的最优值一致。

> **观察 2**：这个式子与「树形」完全无关，只与数组本身有关。下面 §5 会证明：最优值**恰好**等于 $G$。

### 3.3 算法流程：从「删除最小」贪心到单调栈

![单调递减栈的弹栈结算流程](images/wc146_q3_monotonic_stack_flow.svg)

先看一个把观察 2 直接翻译成操作的贪心（容易验证、但 $O(n^2)$）：

```text
cur = arr                     # 当前各块的最大值（值不变，只是逐个删除元素）
ans = 0
while len(cur) > 1:
    k = argmin(cur)           # 当前最小值
    left  = cur[k-1] if k > 0 else ∞
    right = cur[k+1] if k < len-1 else ∞
    ans += cur[k] * min(left, right)   # 与较小的邻居配对
    cur.pop(k)                # 该块被邻居吸收
return ans
```

每一轮删除的那个元素，其左右邻居恰是它左右最近的 ≥ 元素（所有被删过的元素都更小），所以总代价正好是 $G$。

$O(n^2)$ 对 $n \le 40$ 已经足够，但仍可以压到 $O(n)$：**用一个从底到顶严格递减的单调栈维护「还没被右边更大元素吸收的那些位置」**。

```text
st = [∞]                      # 哨兵，永不出栈
ans = 0
for x in arr:
    while st.top <= x:        # x 能吸收栈顶
        mid = st.pop()
        ans += mid * min(st.top, x)
    st.push(x)
while len(st) > 2:            # 收尾：弹到只剩哨兵与全局最大
    mid = st.pop()
    ans += mid * st.top
return ans
```

弹栈时的**新栈顶**就是 `mid` 左侧最近的 ≥ 邻居（在 ⊳ 全序下），而当前 `x` 就是它右侧最近的 ≥ 邻居，所以每次弹栈恰好结算公式中的一项。

### 3.4 示例演算

![arr = [6,2,4] 的栈变化与两次结算](images/wc146_q3_walkthrough.svg)

以 `arr = [6,2,4]` 为例（「栈」按底 → 顶书写）：

| 步 | 读入 | 动作 | 累计 | 栈 |
|----|------|------|------|-----|
| 1 | 6 | 栈顶 $\infty > 6$，压栈 | 0 | $\infty,\ 6$ |
| 2 | 2 | 栈顶 $6 > 2$，压栈 | 0 | $\infty,\ 6,\ 2$ |
| 3 | 4 | 弹 2：$2\times\min(6,4) = 8$ | 8 | $\infty,\ 6,\ 4$ |
| 4 | 收尾 | 弹 4：$4\times 6 = 24$ | 32 | $\infty,\ 6$ |
| 5 | 结束 | 栈只剩哨兵与最大值 6 | 32 | $\infty,\ 6$ |

第 3 步结算的正是「$2$ 被 $4$ 吸收」这次合并，第 4 步是「$4$ 被 $6$ 吸收」。两次合起来构成方案 B（$8 + 24 = 32$），而方案 A 先并 $6,2$ 要付 $12$，反而更贵——**让最小的元素去吸收更大的邻居是亏的**，这正是贪心取 $\min$ 的直觉来源。示例 2 里 $[4,11]$ 只有一次合并：弹掉 $4$ 时新栈顶是哨兵，取 $\min(\infty,11) = 11$，得 $44$。

## 4. 算法细节

1. **哨兵 $\infty$ 垫底**：它能省掉「栈空」与「端点只有单侧邻居」两类特判，而且永远不会被弹出（没有比它更大的元素）。C++ 用 `INT_MAX`，Python 用 `float('inf')`。
2. **走 DP 路线时的枚举顺序**：`dp[i][i] = 0`，且必须按**区间长度从小到大**枚举，保证 $dp[i][k]$、$dp[k+1][j]$ 都已算好。若按 $i$ 从小到大、$j$ 从小到大枚举，长区间的右半段还没算，用未初始化的 0 会得到偏小的错误答案。
3. **弹栈时用「新栈顶」而不是 `mid` 自己**：`mid` 已经出栈，它的左邻居此刻就是 `st.top`，所以乘数写成 `min(st.top, x)`；顺序写反（先用旧栈顶）会重复使用中间元素。
4. **收尾循环条件写 `size > 2`**：要留下哨兵与全局最大两个元素才算结束。写成 `> 1` 会把哨兵也弹出，随后 `mid * INT_MAX` 溢出（Python 里会得到 `inf`）。
5. **答案规模**：每个内部节点 $\le 15\times 15 = 225$，共 $n-1 \le 39$ 个，故答案 $\le 8775$，`int` 完全够（`arr` 全为 $15$ 时恰好取到 $8775$）；C++ 里不必开 `long long`。
6. **`mx` 表的预处理**（走 DP 路线时）：`mx[i][j] = max(mx[i][j-1], arr[j])`，务必按 $i$ 递增、$j$ 递增的顺序填，或按区间长度递推。
7. **`st` 里存值而不是下标**：本题只需要最大值本身，存值即可；若需要输出合并方案，则改存下标，用 `arr[idx]` 比较。
8. **复杂度取舍**：$n \le 40$ 时 DP 更「无脑」，栈解更快但需要想清楚；面试/复盘时建议两种都写，并说明栈解为什么对。

## 5. 正确性证明

为了处理相等元素，先约定一个**全序** ⊳：$a[i] \triangleright a[j]$ 当且仅当 $a[i] > a[j]$，或 $a[i] = a[j]$ 且 $i > j$（相等时下标大者更大）。任何乘积只用到「最大值本身」，用 ⊳ 取代「$>$」不会改变任何一次合并的代价，因此下面**不妨设所有比较都用严格全序 ⊳**，从而 $\max$ 唯一。

**引理 1（下界）**：任一合法树的非叶和 $\ge G$。

**证明**：把树的内部节点按自底向上的顺序排成 $n-1$ 次相邻块合并。对每个不是 ⊳-全局最大的 $i$，取「$i$ 所在块第一次与一个最大值 ⊳-大于 $a[i]$ 的块合并」这一步 $E_i$——它一定存在，因为最终整块包含全局最大者。在 $E_i$ 之前，$i$ 所在块 $B$ 的最大值就是 $a[i]$（更早的合并伙伴块最大值都 ⊳-小于 $a[i]$），设 $E_i$ 的伙伴块为 $C$，则该步代价 $= a[i]\cdot \max(C)$。

- 若 $C$ 在 $B$ 的右侧：$B$ 中 $i$ 右侧的元素都 ⊳-小于 $a[i]$，而 $\max(C) \triangleright a[i]$，故 $i$ 右侧第一个 ⊳-更大的元素 $R(i)$ 必落在 $C$ 内，于是 $\max(C) \ge a[R(i)] \ge \min(a[L(i)], a[R(i)])$。
- 若 $C$ 在 $B$ 的左侧：对称地 $\max(C) \ge a[L(i)] \ge \min(a[L(i)], a[R(i)])$。

故 $E_i$ 的代价 $\ge a[i]\cdot\min(a[L(i)], a[R(i)])$。又同一个 $E$ 至多被一个 $i$ 认领：能认领者必须是「较小一侧块」的 ⊳-最大元素，而它是唯一的。把各元素认领的步骤相加即得总代价 $\ge G$。∎

**引理 2（贪心可达）**：§3.3 的「删除最小」贪心得到一个合法合并序列，其代价恰为 $G$。

**证明**：贪心的当前数组就是 `arr` 删除掉若干元素后剩下的序列（合并只是删掉较小块，存留的最大值不变），所以每一步都是合法的相邻块合并。设当前最小值在位置 $k$：更早被删掉的元素在删除时都是当时的最小值，而 $a[k]$ 当时还在，故它们都 ⊳-小于 $a[k]$；仍在数组里的元素都 $\trianglerighteq a[k]$。于是 $k$ 在**当前数组**里的左右邻居，正是原数组中 $k$ 左右两侧第一个 $\trianglerighteq a[k]$ 的元素，即 $L(k)$ 与 $R(k)$。该步代价 $= a[k]\cdot\min(a[L(k)], a[R(k)])$，正是公式里 $k$ 的那一项；除 ⊳-全局最大者外每个元素恰好被删一次，故总和 $=G$。∎

**引理 3（单调栈输出 = $G$）**。

**证明**：归纳可得不变量：扫描到位置 $t$ 时，栈（除哨兵）自底向上恰是 $arr[0..t]$ 中所有「右侧不存在 ⊳-更大元素」的下标，按位置升序排列，且它们的值按 ⊳ 严格递减。读到 $x$ 时，凡 $\trianglelefteq x$ 的栈顶都会把 $x$ 认作自己右侧最近的 ⊳-更大元素（更靠右的更大元素尚未出现；若二者之间还有 ⊳-更大者，前者早被它弹出），于是被逐个弹出。

再证「新栈顶就是 $mid$ 的 $L$」：设栈顶下方是 $p$，若存在 $p$ 与 $mid$ 之间的位置 $z$（其值 $\trianglerighteq a[mid]$，否则 $mid$ 会是更靠左的 $L$），则 $z$ 已被某个更靠右的 $\trianglerighteq$ 元素弹出；沿「被谁弹出」一路向右移动位置严格增大，最终必越过 $mid$ 的位置，而这会给出一个位于 $mid$ 右侧、⊳-大于 $mid$ 的元素——与 $mid$ 仍在栈中（右侧无更大者）矛盾。故 $p = L(mid)$，而当前 $x = R(mid)$，该次弹栈结算的正是 $a[mid]\cdot\min(a[L],a[R])$。收尾阶段把栈清到只剩哨兵与 ⊳-最大值，每次结算的同样是某项，只有 ⊳-全局最大者不被结算。故输出 $=G$。∎

**定理**：`mctFromLeafValues` 返回最优非叶和。

**证明**：由引理 2 存在代价为 $G$ 的合法树，故最优值 $\le G$；由引理 1 最优值 $\ge G$；由引理 3 算法输出就是 $G$。三者合并即得算法输出等于最优值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素入栈一次、出栈至多一次，每次弹栈只做一次乘法与比较；收尾阶段总共也只弹出不超过 $n$ 次。
- **空间**：$O(n)$，即单调栈；栈深不超过 $n+1$（含哨兵），最坏情况是 `arr` 严格递减。
- **对照区间 DP**：时间 $O(n^3)$、空间 $O(n^2)$。$n \le 40$ 时两者都轻松通过，但 $n$ 放大到 $10^5$ 时只有栈解可用。
- **常数**：栈解只有比较与整数乘法，$n = 40$ 时耗时可忽略；答案上限 $8775$，不会触及 32 位边界。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <climits>
#include <algorithm>
using namespace std;

class Solution {
public:
    int mctFromLeafValues(vector<int>& arr) {
        vector<int> st{INT_MAX};              // 哨兵：永不出栈
        int ans = 0;
        for (int x : arr) {
            while (st.back() <= x) {          // 栈顶被 x 吸收
                int mid = st.back();
                st.pop_back();
                ans += mid * min(st.back(), x);   // 与较小的那个邻居配对
            }
            st.push_back(x);
        }
        while ((int)st.size() > 2) {          // 收尾：留下哨兵与全局最大值
            int mid = st.back();
            st.pop_back();
            ans += mid * st.back();
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def mctFromLeafValues(self, arr: list[int]) -> int:
        st = [float('inf')]              # 哨兵：永不出栈
        ans = 0
        for x in arr:
            while st[-1] <= x:           # 栈顶被 x 吸收
                mid = st.pop()
                ans += mid * min(st[-1], x)   # 与较小的那个邻居配对
            st.append(x)
        while len(st) > 2:               # 收尾：留下哨兵与全局最大值
            mid = st.pop()
            ans += mid * st[-1]
        return ans
```

## 8. 边界情况与易错点

1. **$n = 2$**：只有一次合并，答案就是 $a[0]\cdot a[1]$。栈解里若 $a[0] \le a[1]$ 会正常弹一次，若 $a[0] > a[1]$ 则留给收尾阶段弹出，两条路径都正确——不要在循环里额外特判长度。
2. **端点只有单侧邻居**：`arr[0]` 与 `arr[n-1]` 的「另一侧邻居」是 $\infty$（哨兵或收尾时的空侧），`min` 会自动选中存在的那一侧；手工写 `arr[k-1]` / `arr[k+1]` 时最容易在这里越界。
3. **弹出条件的方向与相等值**：必须写「栈顶 $\le x$ 就弹」，这样栈从底到顶严格递减，弹出的 `mid` 右边第一个 $\ge$ 它的元素恰好是 `x`；把方向写反（`栈顶 >= x`）会弹掉不该弹的大元素，栈立刻失去单调性。值相等时 `<=` 与 `<` 在本实现里都能得到正确答案（相等因子的乘积是对称的），但两者对应的破平局口径不同，不要在同一份代码里混用。
4. **收尾循环的边界 `size > 2`**：栈里必须至少留两个元素（哨兵 + 全局最大）。写成 `> 1` 会与 $\infty$/`INT_MAX` 相乘，C++ 溢出、Python 返回 `inf`。
5. **`ans` 的类型**：DP 写法里 `mx[i][k] * mx[k+1][j]` 用 `int` 相乘不会溢出（$\le 225$），但若把值域放大到 $10^9$ 就必须用 `long long`；栈解同理，乘之前先确认量级。
6. **切分点不固定**：直觉上会想「按最大值把数组切成两半」，但示例 1 的两棵树的根部分别切在 $6\,|\,2$ 与 $(6,2)\,|\,4$ 之间，切分点不同、代价相差 4。区间 DP 必须枚举**所有** $k$，不能只试最大值所在的切分点。
7. **返回值的语义**：题目要的是**非叶节点值之和**，叶子的值不计入；实现里不要顺手把叶子也乘进去。

- [LeetCode 312. 戳气球](https://leetcode.cn/problems/burst-balloons/)：区间 DP 的经典变体，代价与区间端点相关。
- [LeetCode 84. 柱状图中最大的矩形](https://leetcode.cn/problems/largest-rectangle-in-histogram/)：单调栈找「左右最近更小元素」的标准模板，本题找的是「左右最近不小于」。
- [LeetCode 654. 最大二叉树](https://leetcode.cn/problems/maximum-binary-tree/)：最大笛卡尔树的构造，递归写法与本题的栈过程互为镜像。

**延伸思考**：把代价从「乘积」换成「和」或「差的绝对值」，本题的计费公式立刻失效——引理 1 里「取较小的邻居更便宜」依赖 $a[i]\cdot x$ 关于 $x$ 单调，而加法把代价摊给了两侧，无法再归到单个元素头上，此时只能用区间 DP。另一个方向是**笛卡尔树**：§3.3 的单调栈正是最大笛卡尔树的构造过程，答案也可以理解为「在笛卡尔树上自底向上，把每个节点与较矮的那个孩子方向合并」，据此还能输出具体的合并顺序（即最优树的形状），这是 $O(n)$ 做法的另一种叙述方式。
