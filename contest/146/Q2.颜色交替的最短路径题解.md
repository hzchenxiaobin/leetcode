# LeetCode 颜色交替的最短路径 题解

## 1. 题目概述

- **标题 / 题号**：颜色交替的最短路径（#1129，medium）
- **链接**：https://leetcode.cn/problems/shortest-path-with-alternating-colors/
- **来源**：LeetCode 第 146 场周赛 Q2
- **难度**：中等
- **标签**：广度优先搜索，图

**题意**：给一张 $n$ 个节点的**有向图**，每条边被染成红色或蓝色（题面明确允许**自环**与**平行边**）。对每个节点 $X$，求从节点 $0$ 出发、走到 $X$、且**相邻两条边的颜色必须不同**的最短路径长度（按边数计）；不存在这样的路径时输出 $-1$。长度为 $0$ 的空路径天然合法，所以 `answer[0]` 恒为 $0$。

**约束**：

- $1 \le n \le 100$
- $0 \le \text{redEdges.length},\ \text{blueEdges.length} \le 400$
- 每条边形如 $[u, v]$，$0 \le u, v < n$

## 2. 示例

**示例 1**

```text
输入：n = 3, redEdges = [[0,1],[1,2]], blueEdges = []
输出：[0,1,-1]
解释：0 → 1 走红边，长度 1；
      要到 2 必须 0 → 1（红）再接一条蓝边，但全图没有蓝边，故 2 不可达。
```

**示例 2**

```text
输入：n = 3, redEdges = [[0,1]], blueEdges = [[2,1]]
输出：[0,1,-1]
解释：蓝边是 2 → 1（有向），它既不能反向使用，也没法接在 0 → 1 之后；
      而 0 没有蓝色出边，所以从 0 出发的第二条边无处可走，2 不可达。
```

**补充示例**（同一题的其他官方用例，覆盖「两步交替成功」）

```text
输入：n = 3, redEdges = [[0,1]], blueEdges = [[1,2]]
输出：[0,1,2]
解释：0 → 1 走红边，1 → 2 走蓝边，红蓝交替，因此 answer[2] = 2。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是「在节点上跑一次 BFS，`dist[u]` 存到达 $u$ 的最短距离」。但它**不成立**：BFS 从 $u$ 出队时，我们不知道「到达 $u$ 的那条边是什么颜色」，于是无法判断 $u$ 的哪些出边可以使用——两条同色边相邻就违规了。若两种颜色都放行，会构造出非法路径（答案偏小）；若只放行其中一种，又会漏掉最优解。

另一种直觉是 DFS 枚举所有「颜色交替的行走」。这条路也走不通：自环（如 $0 \xrightarrow{红} 0$）让合法行走的长度**没有上界**，枚举会死循环；即使人为限长，分支数也是指数级的。

关键结论：能不能从 $u$ 继续走，只取决于**「到达 $u$ 时最后一条边的颜色」**，与更早的历史无关。于是把它塞进状态。

### 3.2 核心观察：状态是 (节点, 最后一条边的颜色)

![把原图拆成红蓝两层状态](images/wc146_q2_state_layers.svg)

把状态定义为二元组 $(u, c)$，其中 $u$ 是节点编号，$c \in \{\text{红}, \text{蓝}\}$ 表示**到达 $u$ 时走过的最后一条边的颜色**。原图因此被展开成一张有 $2n$ 个状态的有向图 $G'$：

- 对每条颜色为 $c$ 的原边 $u \to v$，在 $G'$ 中连一条 $(u, 1-c) \to (v, c)$ 的有向边；
- $G'$ 中每条边的权都是 $1$，所以最短路就是**无权图 BFS**；
- 节点 $0$ 没有「上一条边」，红、蓝两种身份都可以当起点，故 $\text{dist}[0][\text{红}] = \text{dist}[0][\text{蓝}] = 0$，两个状态一起入队，等价于「第一步随便选颜色」；
- 答案取两种到达方式中更优的那个：$\text{answer}[x] = \min\bigl(\text{dist}[0][x],\ \text{dist}[1][x]\bigr)$。

> 💡 **一句话总结**：把「上一条边的颜色」升格为一个维度，颜色交替就被翻译成「在两层之间来回跳」，最短路问题立刻退化成标准 BFS。

### 3.3 算法流程

![两状态 BFS 流程](images/wc146_q2_bfs_flow.svg)

1. 建表：`adj[c][u]` 存从 $u$ 出发、颜色为 $c$ 的所有终点（红蓝各一份邻接表）。
2. 初始化：`dist[0][0] = dist[1][0] = 0`，把 $(0,0)$ 与 $(0,1)$ 两个状态压入队列。
3. 出队状态 $(u, c)$，只扫描**另一种颜色**的出边 $u \to v$（颜色 $1-c$）。
4. 若 `dist[1-c][v]` 仍是 INF，就置为 `dist[c][u] + 1` 并入队；否则跳过。
5. 队列为空后逐节点合并：`answer[x] = min(dist[0][x], dist[1][x])`，仍为 INF 则输出 $-1$。

转移式写出来就是一次松弛：

$$\text{dist}[1-c][v] \leftarrow \min\Bigl(\text{dist}[1-c][v],\ \text{dist}[c][u] + 1\Bigr),\qquad (u \to v) \text{ 的颜色为 } 1-c$$

### 3.4 示例演算

![出队顺序走查表](images/wc146_q2_walkthrough.svg)

取 $n = 5$：红边 $0\to1,\ 1\to2,\ 2\to3,\ 0\to4,\ 4\to0$，蓝边 $1\to0,\ 3\to4,\ 4\to2$。队列出队顺序与松弛结果：

| 步 | 出队状态 | dist | 扫描的边 | 更新 |
|----|----------|------|----------|------|
| 1 | $(0, \text{红})$ | 0 | 蓝出边：无 | — |
| 2 | $(0, \text{蓝})$ | 0 | 红 $0\to1$、红 $0\to4$ | $(1,\text{红})=1$、$(4,\text{红})=1$ |
| 3 | $(1, \text{红})$ | 1 | 蓝 $1\to0$ | $(0,\text{蓝})$ 已为 0，跳过 |
| 4 | $(4, \text{红})$ | 1 | 蓝 $4\to2$ | $(2,\text{蓝})=2$ |
| 5 | $(2, \text{蓝})$ | 2 | 红 $2\to3$ | $(3,\text{红})=3$ |
| 6 | $(3, \text{红})$ | 3 | 蓝 $3\to4$ | $(4,\text{蓝})=4$ |
| 7 | $(4, \text{蓝})$ | 4 | 红 $4\to0$ | $(0,\text{红})$ 已为 0，跳过 |

合并后 `answer = [0, 1, 2, 3, 1]`。注意节点 $4$：红层 $d = 1$、蓝层 $d = 4$，取 $\min$ 得 $1$。这个例子也说明了为什么必须**按颜色分开存距离**：同一个节点、不同「最后颜色」的状态，后续可用的出边集合不同（红层只能走蓝边，蓝层只能走红边），所以不能只保留最小的那一个。

## 4. 算法细节

1. **用颜色做第一维**：`adj[c][u]` 存颜色 $c$ 的出边终点，出队 $(u,c)$ 时只扫 `adj[1-c][u]`，「交替」这个约束由下标运算完成，代码里不需要任何 `if` 分支。
2. **`dist` 兼任访问标记**：入队的同时把 `dist` 写成具体值，`dist == INF` 即「未访问」。不要另开 `visited` 数组，否则两套标记容易不同步，导致重复入队或漏扩展。
3. **起点双状态入队**：这是「第一步颜色自由」的唯一正确表达方式；写成「先只放红层入队」会漏掉以蓝边开头的路径。
4. **自环与平行边不必去重**：自环 $0 \xrightarrow{c} 0$ 只会尝试把 `dist[1-c][0]` 从 $0$ 改成 $1$，被「已访问」直接挡住；平行边在第二次之后的扫描全部命中已访问。所以 `adj` 里保留原样的重边即可，最坏多扫几遍常数。
5. **INF 的取值**：最短交替路径最多 $2n$ 条边（状态数上界），取 `1e9` 或 $4n$ 都不会溢出 `int`；合并时先取 `min` 再判 `== INF`，不要先做 `INF + 1`。
6. **队列规模**：状态总数 $2n \le 200$，每个状态只入队一次，所以队列长度恒定很小；BFS 的层数也自然被限制在 $2n$ 以内，不需要额外设深度上限。
7. **等价写法**：加一个虚拟源点 $S$，用两条权为 $0$ 的边连到 $(0,\text{红})$、$(0,\text{蓝})$，可以把「起点特判」统一掉，但零权边要么用 0-1 BFS，要么手工把距离定为 $0$；周赛里不如直接双入队干净。

## 5. 正确性证明

**引理 1（可行性 / soundness）**：若 BFS 结束时 $\text{dist}[c][v] = d < \infty$，则存在一条从 $0$ 到 $v$、最后一条边颜色为 $c$、长度为 $d$ 的合法交替路径。

**证明**：对 $d$ 归纳。$d = 0$ 只可能出现在 $v = 0$，此时空路径合法且「没有最后一条边」，与 $c$ 的初始化方式一致。$d > 0$ 时，$\text{dist}[c][v]$ 是被某条真实存在的、颜色为 $c$ 的边 $u \to v$ 从状态 $(u, 1-c)$ 松弛出来的，且 $\text{dist}[1-c][u] = d - 1$。由归纳假设存在到 $u$、最后一条边颜色 $1-c$、长度 $d-1$ 的合法交替路径；在它末尾接上 $u \to v$，最后两条边颜色为 $1-c$ 与 $c$，仍然交替，长度变为 $d$。∎

**引理 2（最优性 / completeness）**：若存在一条从 $0$ 到 $v$、最后一条边颜色为 $c$、长度为 $L$ 的合法交替路径，则 BFS 结束时 $\text{dist}[c][v] \le L$。

**证明**：对 $L$ 归纳。$L = 0$ 即 $v = 0$，有 $\text{dist}[c][0] = 0 \le 0$。$L \ge 1$ 时，把路径拆成前缀 $P'$（到 $u$，长度 $L-1$，最后一条边颜色 $1-c$）与末边 $u \to v$（颜色 $c$）。由归纳假设 $\text{dist}[1-c][u] \le L-1$。BFS 中 $(u, 1-c)$ 必定会入队并出队（距离有限），出队时它会扫描 `adj[c][u]` 的全部出边，其中包括 $u \to v$：若此刻 $\text{dist}[c][v]$ 仍为 $\infty$，则被赋为 $\text{dist}[1-c][u] + 1 \le L$；若已被赋过更小的值，则更满足 $\le L$。∎

**引理 3（BFS 分层正确）**：状态按 `dist` 非降序出队，且每个状态出队时其 `dist` 已是最终最小值。

**证明**：分两点。(i) **队列值单调不减**：出队值为 $k$ 的状态时，新入队的值只能是 $k+1$，而队列中剩余元素的值都不小于 $k$，故单调性保持。(ii) **首次写入即最终值**：`dist` 只在为 `INF` 时被写入，之后不再改动，所以每个状态入队时距离已经定死。若它在第 $k$ 层入队，则存在一条长度 $k$ 的合法交替路径（引理 1 的构造），而任何长度 $k' < k$ 的合法路径按引理 2 的论证会让它在层 $k'$ 就被写入——矛盾。故写入值等于真实最短距离，出队时自然最优。∎

**定理**：设 $\text{OPT}(x)$ 为题目所求的最短交替路径长度，则 $\text{answer}[x] = \min(\text{dist}[0][x], \text{dist}[1][x])$（两者皆 $\infty$ 时取 $-1$）等于 $\text{OPT}(x)$。

**证明**：由引理 2，两种颜色的状态距离都不超过 $\text{OPT}(x)$，故 $\text{answer}[x] \le \text{OPT}(x)$；由引理 1，$\min$ 取得有限值时就对应一条真实合法的交替路径，而 $\text{OPT}(x)$ 是最短长度，故 $\text{OPT}(x) \le \text{answer}[x]$。两侧夹逼得相等。若两者皆为 $\infty$，由引理 2 的逆否命题不存在任何合法交替路径，输出 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n + E)$，其中 $E = \lvert\text{redEdges}\rvert + \lvert\text{blueEdges}\rvert \le 800$。建表 $O(E)$；每个状态至多入队、出队一次（共 $2n$ 个状态）；每条原边 $u \to v$（颜色 $c$）只在状态 $(u, 1-c)$ 出队时被扫描一次，总共 $O(E)$；每次松弛 $O(1)$。
- **空间**：$O(n + E)$。两个邻接表存 $n$ 个表头 + $E$ 条边；`dist` 为 $2 \times n$；队列最多 $2n$ 个状态。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> shortestAlternatingPaths(int n, vector<vector<int>>& redEdges,
                                        vector<vector<int>>& blueEdges) {
        // adj[0] 存红边，adj[1] 存蓝边
        vector<vector<vector<int>>> adj(2, vector<vector<int>>(n));
        for (auto& e : redEdges)  adj[0][e[0]].push_back(e[1]);
        for (auto& e : blueEdges) adj[1][e[0]].push_back(e[1]);

        const int INF = 1e9;                       // 最短交替路径最多 2n 条边
        vector<vector<int>> dist(2, vector<int>(n, INF));
        dist[0][0] = dist[1][0] = 0;               // 起点两种「身份」都成立

        queue<pair<int, int>> q;                   // (节点, 最后一条边的颜色)
        q.push({0, 0});
        q.push({0, 1});
        while (!q.empty()) {
            auto [u, c] = q.front();
            q.pop();
            int nc = 1 - c;                        // 下一步只能走相反颜色
            for (int v : adj[nc][u]) {
                if (dist[nc][v] == INF) {
                    dist[nc][v] = dist[c][u] + 1;  // 入队即定值，兼作访问标记
                    q.push({v, nc});
                }
            }
        }

        vector<int> ans(n);
        for (int i = 0; i < n; i++) {
            int d = min(dist[0][i], dist[1][i]);
            ans[i] = (d == INF ? -1 : d);
        }
        return ans;
    }
};
```

### Python

```python
from collections import deque
from typing import List


class Solution:
    def shortestAlternatingPaths(self, n: int, redEdges: List[List[int]],
                                 blueEdges: List[List[int]]) -> List[int]:
        RED, BLUE = 0, 1
        adj = [[[] for _ in range(n)] for _ in range(2)]
        for u, v in redEdges:
            adj[RED][u].append(v)
        for u, v in blueEdges:
            adj[BLUE][u].append(v)

        INF = 10 ** 9
        dist = [[INF] * n for _ in range(2)]
        dist[RED][0] = dist[BLUE][0] = 0

        q = deque([(0, RED), (0, BLUE)])
        while q:
            u, c = q.popleft()
            nc = 1 - c
            for v in adj[nc][u]:
                if dist[nc][v] == INF:
                    dist[nc][v] = dist[c][u] + 1
                    q.append((v, nc))

        ans = []
        for i in range(n):
            d = min(dist[RED][i], dist[BLUE][i])
            ans.append(-1 if d == INF else d)
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$ 且没有边**：答案必须是 `[0]`。不要因为队列很快变空就整体返回 `-1`——空路径长度为 $0$ 是合法的。
2. **只按节点打访问标记**：同一个节点可能以红层、蓝层两种身份到达，而两种身份的出边集合不同，必须用 `(节点, 颜色)` 作标记，否则会漏扩展。
3. **把有向边当无向边**：示例 2 的蓝边是 $2 \to 1$，不能反着从 $1$ 走到 $2$；一旦把它当成无向边（$1$ 可以走蓝边到 $2$），答案会从 `[0,1,-1]` 变成 `[0,1,2]`，直接错。
4. **自环与平行边**：题面明确写了它们可能存在。自环不会把某个状态的距离改小（它只能给「同节点的另一层」提供一个 $+1$ 的候选，通常已被更优值占据，命中「已访问」直接跳过）；平行边在第二次之后的扫描全部无效。代码不能假设「每对点之间最多一条边」。
5. **`answer[0]` 的特殊性**：它不经过任何边，因此与颜色无关、恒为 $0$；如果强行要求「至少一条边」，会让 `answer[0]` 变成正数。
6. **INF 泛滥**：合并时先 `min(dist[0][x], dist[1][x])` 再判 `== INF`；若先写 `dist[0][x] + 1` 之类，$10^9 + 1$ 与 `INF` 不再相等，判空失效。
7. **入队与标记的顺序**：Python 里若写 `if dist[nc][v] == INF: q.append(...)` 却忘了同步写 `dist[nc][v]`，会退化成「重复入队 + 超时」；两件事必须写在一起。
