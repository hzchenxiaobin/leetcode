# LeetCode 等价多米诺骨牌对的数量 题解

## 1. 题目概述

- **标题 / 题号**：等价多米诺骨牌对的数量（#1128，easy）
- **链接**：https://leetcode.cn/problems/number-of-equivalent-domino-pairs/
- **来源**：LeetCode 第 146 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定 $n$ 张骨牌 $dominoes[i] = [a, b]$。两张骨牌**等价**当且仅当 $(a = c \wedge b = d)$ 或 $(a = d \wedge b = c)$，也就是其中一张旋转 $180^\circ$ 后与另一张完全相同。统计满足 $0 \le i < j < n$ 且 $dominoes[i]$ 与 $dominoes[j]$ 等价的二元组个数。

**约束**：

- $1 \le n \le 4 \times 10^4$
- $dominoes[i].length = 2$，即每张骨牌恰好两格
- $1 \le dominoes[i][j] \le 9$

> 💡 值域只有 $1 \sim 9$，所以「等价类」总数不超过 $\binom{10}{2} = 45$：这题天然是**计数题**，桶比哈希表更快。

## 2. 示例

**示例 1**

```text
输入：dominoes = [[1,2],[2,1],[3,4],[5,6]]
输出：1
解释：(0,1) 等价，因为 [2,1] 旋转 180° 就是 [1,2]；
      [3,4] 与 [5,6] 各自孤立，没有别的骨牌与之等价。
```

**示例 2**

```text
输入：dominoes = [[1,2],[1,2],[1,1],[1,2],[2,2]]
输出：3
解释：三张 [1,2] 两两配对，共 C(3,2) = 3 对：(0,1)、(0,3)、(1,3)；
      [1,1] 与 [2,2] 数值不同，互不等价。
```

**示例 3**（自测边界）

```text
输入：dominoes = [[1,1],[1,1],[1,1]]
输出：3
解释：两格同值，旋转 0° 或 180° 都还是 [1,1]，3 张骨牌两两配对得 C(3,2) = 3。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $i < j$，按题面两种情形逐一比较：

```text
for i in [0, n):
  (a, b) = dominoes[i]
  for j in (i, n):
    (c, d) = dominoes[j]
    if (a == c and b == d) or (a == d and b == c): ans += 1
```

正确但太慢：$n = 4 \times 10^4$ 时有 $\frac{n(n-1)}{2} \approx 8 \times 10^8$ 次比较，没有通过的可能。不过它结构简单、绝不出错，非常适合当**对拍基准**。

### 3.2 核心观察：规范化到无序对

![规范化键：旋转 180° 后落在同一个桶](images/wc146_q1_canonical_key.svg)

题面列出的两种情形其实在说同一件事：**骨牌只看两个数字构成的集合，与左右顺序无关**。于是把每张骨牌写成

$$\text{key}(a, b) = \bigl(\min(a, b),\ \max(a, b)\bigr)$$

就有

$$\text{dominoes}[i] \sim \text{dominoes}[j] \iff \text{key}(a, b) = \text{key}(c, d).$$

**等价关系被压缩成了一次「字符串相等」判断**。设规范化键 $k$ 出现了 $c_k$ 次，那么同一组内的任意两张都等价，答案就是

$$\text{ans} = \sum_{k} \binom{c_k}{2}.$$

上式有两种落地方式：

1. **两趟**：先统计每组大小 $c_k$，再对每组累加 $\frac{c_k(c_k-1)}{2}$；
2. **一趟（推荐）**：扫描到当前骨牌时，让 `ans += cnt[key]`，再把 `cnt[key]` 加一。含义是「**这张骨牌与之前所有同键骨牌各配成一对**」，天然只统计 $i < j$。

再加上值域只有 $1 \sim 9$：$\min \le \max$ 保证 $1 \le \min \le \max \le 9$，于是 $10\min + \max$ 落在 $[11, 99]$，一个长 100 的数组就是全部桶，连哈希都不用。

### 3.3 算法流程

![一趟扫描的流程与循环不变式](images/wc146_q1_count_flow.svg)

```text
1. ans ← 0，cnt[0..99] 清零
2. 对 dominoes 中的每张骨牌 [a, b]：
     2.1 若 a > b，交换 a、b（规范化，保证 a ≤ b）
     2.2 key ← a*10 + b                // 唯一编码，11 ≤ key ≤ 99
     2.3 ans ← ans + cnt[key]          // 与「之前的」同键骨牌配对
     2.4 cnt[key] ← cnt[key] + 1
3. 返回 ans
```

关键点只有一句：**先累加旧计数，再把自己放进桶**。顺序反了就会把自己也算进去，答案凭空多出 $n$。

### 3.4 示例演算

以示例 2 的 `[[1,2],[1,2],[1,1],[1,2],[2,2]]` 走一遍：

![示例 2 的逐张演算表](images/wc146_q1_walkthrough.svg)

前两张 `[1,2]` 都落进桶 12：第 2 张进入时桶里已有 1 张，`ans` 从 0 变 1。第 3 张 `[1,1]` 的键是 11，空桶，`ans` 不动。第 4 张 `[1,2]` 进入时桶 12 已有 2 张，`ans` 一次跳 +2 到 3。最后 `[2,2]` 的键是 22，同样空桶。

最终 $ans = 3$，与「桶 12 里有 3 张骨牌，$\binom{3}{2} = 3$」完全一致；`[1,1]`、`[2,2]` 各占一个桶，互不干扰。

## 4. 算法细节

1. **规范化方向统一为「小值在前」**：只允许 $a \le b$，`[2,1]` 与 `[1,2]` 都必须落到 `(1,2)`。比较时不要写 `a < b` 之外的花样，避免出现「小值在后」的漏网。
2. **编码必须无碰撞**：$key = a \times 10 + b$（$1 \le a \le b \le 9$）是单射，值域 $[11, 99]$；等价写法 $key = (a-1) \times 9 + (b-1)$ 把值域压到 $[0, 44]$，桶数组开 45 即可。凡是把有序信息压成 $a+b$、$a \times b$ 这类「聚合量」的键都会撞键。
3. **先加后置的顺序**：`ans += cnt[key]; ++cnt[key];`。颠倒之后当前骨牌把自己统计进去，结果多 $n$。
4. **两种公式等价**：增量式累加的总和恰为 $\sum_k \binom{c_k}{2}$（组 $k$ 的第 $t$ 张（$t$ 从 0 计）进入时贡献 $t$ 个「之前的同伴」，累加即 $0+1+\dots+(c_k-1)$），所以两种写法可以互相校验。
5. **桶数组长度**：编码最大到 99，数组要开 100（下标 0 浪费也无妨）；开 45 配 `a*10+b` 会直接越界。
6. **不排序也能做**：排序后扫描相邻同键是 $O(n\log n)$ 的等价做法，虽然能过，但白丢一个 $\log$，也丢掉了「值域小」这个提示。
7. **无需保存历史**：只需要 45 个计数器，$O(1)$ 额外空间；不必把 key 全部存进 vector 再回头配对。

## 5. 正确性证明

记 $\kappa(a,b) = (\min(a,b), \max(a,b))$。

**引理 1（等价 $\iff$ 规范化键相等）**：$dominoes[i] \sim dominoes[j] \iff \kappa(a, b) = \kappa(c, d)$。

**证明**：

- 若 $\kappa(a,b) = \kappa(c,d)$，则 $\{\min(a,b), \max(a,b)\} = \{\min(c,d), \max(c,d)\}$，即无序对 $\{a,b\} = \{c,d\}$。两个二元集合相等，要么逐元素相同（$a = c,\ b = d$），要么交错相同（$a = d,\ b = c$），正是题面给出的两种等价情形。
- 反之，若 $a = c \wedge b = d$，则两边的 $\min$、$\max$ 逐项相同；若 $a = d \wedge b = c$，则 $\kappa(a,b) = (\min(a,b),\max(a,b)) = (\min(c,d),\max(c,d))$ 同样成立。∎

**引理 2（编码是单射）**：对 $1 \le a \le b \le 9$，映射 $(a,b) \mapsto 10a + b$ 是单射。

**证明**：设 $10a_1 + b_1 = 10a_2 + b_2$，其中 $1 \le b_i \le 9$。两边对 10 取余得 $b_1 = b_2$，代回得 $10a_1 = 10a_2$，故 $a_1 = a_2$。∎

**引理 3（增量恰为新建对数）**：扫描到第 $j$ 张骨牌时，若它的键为 $k$，则 `cnt[k]` 恰等于满足 $i < j$ 且 $\text{dominoes}[i] \sim \text{dominoes}[j]$ 的下标 $i$ 的个数。

**证明**：证明更强的不变式 $P(j)$：处理完前 $j$ 张骨牌后，对任意键 $k$ 都有 `cnt[k]` 等于前 $j$ 张中键为 $k$ 的张数。

- 基础：$P(0)$ 成立，所有 `cnt` 为 0。
- 归纳步：设 $P(j)$ 成立，第 $j+1$ 张骨牌的键为 $k_0$。它先读出 `cnt[k0]`，由 $P(j)$ 该值等于前 $j$ 张中键为 $k_0$ 的张数；然后 `cnt[k0]` 加一，其余桶不变，故 $P(j+1)$ 成立。

由引理 1，键等于 $k_0$ 的先前骨牌正是与第 $j+1$ 张等价的骨牌。于是扫描到任意第 $j$ 张（$j \ge 1$）骨牌时，读出的 `cnt` 恰是与它等价的先前骨牌个数，也就是本步的增量。∎

**定理**：算法返回的 $ans$ 等于满足 $0 \le i < j < n$ 且两骨牌等价的二元组个数。

**证明**：任意等价对 $(i, j)$（$i < j$）在扫描到第 $j$ 张骨牌的那一步被统计，此时第 $i$ 张已在桶中；由引理 3，这一步的增量恰好是「所有与第 $j$ 张等价的先前骨牌」的数量，故 $(i,j)$ 被计入且仅被计入一次。另一方面，每一步的增量都对应真实存在的等价对，不会多计。所有等价对按较大的下标 $j$ 唯一归类，故求和后数目相等。∎

**推论**：最终 $cnt[k] = c_k$，且 $ans = \sum_k \binom{c_k}{2} = \sum_k \frac{c_k(c_k-1)}{2}$，两种实现方式给出同一答案。

## 6. 复杂度分析

- **时间**：$O(n)$。每张骨牌只做一次大小比较（必要时一次交换）、一次乘法加法和两次数组读写，均为 $O(1)$；不需要排序，也不需要遍历 45 个桶。
- **空间**：$O(1)$。桶数组固定 100 个 `int`（实际用到的只有 45 个），与 $n$ 无关；若改用哈希表则额外空间为 $O(\min(n, 45))$，属同一量级。
- **常数**：数组下标访问比哈希表快，$n = 4 \times 10^4$ 时整趟只需几万次操作，远低于任何时限。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int numEquivDominoPairs(vector<vector<int>>& dominoes) {
        int cnt[100] = {0};              // key = min * 10 + max ∈ [11, 99]
        int ans = 0;
        for (auto& d : dominoes) {
            int a = d[0], b = d[1];
            if (a > b) swap(a, b);       // 规范化：小值在前
            int key = a * 10 + b;        // 唯一编码
            ans += cnt[key];             // 与之前所有同键骨牌各配一对
            ++cnt[key];                  // 再把自己放进桶
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numEquivDominoPairs(self, dominoes: list[list[int]]) -> int:
        cnt = [0] * 100                  # 下标是 a * 10 + b
        ans = 0
        for a, b in dominoes:
            if a > b:
                a, b = b, a              # 规范化：保证 a <= b
            key = a * 10 + b
            ans += cnt[key]              # 先前同键的张数 = 本轮新增的等价对数
            cnt[key] += 1
        return ans
```

## 8. 边界情况与易错点

1. **只有一张骨牌**：循环里读到的 `cnt[key]` 恒为 0，自然返回 0。不要给 $n = 1$ 特判返回 1——$i < j$ 严格要求两个不同的下标，单张骨牌与自身不构成对。
2. **最大答案不溢出**：$n = 4 \times 10^4$ 且全部相同时 $ans = \binom{40000}{2} = 799{,}980{,}000 < 2^{31} - 1$，`int` 足够；本题连中间量 $c_k(c_k-1) \approx 1.6 \times 10^9$ 也在 32 位内。若把规模换成 $10^5$ 量级，$\binom{n}{2} \approx 5 \times 10^9$ 就必须换 `long long`，习惯上直接写 `long long` 也不亏。
3. **自对称骨牌 `[a,a]`**：`key = 11a`，与自身另一种朝向完全相同，不需要特判；但也不能因为「两种朝向相同」而重复计数。
4. **交换与取键的顺序**：必须先交换再算 `key`。若先算 `key = a*10+b` 再交换，`[2,1]` 会得到 21、`[1,2]` 得到 12，同一张牌被拆进两个桶，答案偏小。
5. **键不能只用和或积**：$(1,4)$ 与 $(2,3)$ 的和都是 5，$(1,6)$ 与 $(2,3)$ 的积都是 6，用这类「聚合量」当键会把不等价的骨牌并到一组，答案偏大。
6. **数组长度与下标**：`a * 10 + b` 最大 99，桶要开 100；若换成 $(a-1)\times 9 + (b-1)$ 编码，则桶开 45、下标 `0..44`，两者不要混用。
7. **重复计数**：只对「较大的下标」做统计（即只加 `cnt[key]`，不加 `n - 1 - cnt[key]`），双向相加会把每对算两遍。
