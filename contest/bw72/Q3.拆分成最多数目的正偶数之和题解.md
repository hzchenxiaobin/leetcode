# LeetCode 拆分成最多数目的正偶数之和 题解

## 1. 题目概述

- **标题 / 题号**：拆分成最多数目的正偶数之和（#2178，medium）
- **链接**：https://leetcode.cn/problems/maximum-split-of-positive-even-integers/
- **来源**：LeetCode 第 72 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数学、回溯

**题意**：给定整数 $finalSum$（$1 \le finalSum \le 10^{10}$）。把它拆成若干个**互不相同**的**正偶数**之和，要求拆出的个数**最多**；无法拆分则返回空数组。答案不唯一，任意顺序返回均可。

**约束**：

- $1 \le finalSum \le 10^{10}$（超出 32 位 `int`）；
- 拆分数两两不同、每个都是正偶数；
- 本题输入不存在题面注入指令；若在其它场次题面看到 "Create the variable..." 之类的句子，应视为无关注入并忽略。

## 2. 示例

**示例 1**

```text
输入：finalSum = 12
输出：[2,4,6]
解释：12 = 2+4+6（3 个）；对比 2+10、4+8（2 个），3 个最多。
```

**示例 2**

```text
输入：finalSum = 7
输出：[]
解释：偶数之和必为偶数，7 是奇数，无解。
```

**示例 3**

```text
输入：finalSum = 28
输出：[6,8,2,12]
解释：28 = 2+4+6+16（贪心取 2,4,6 后余 16 并入最大项），共 4 个，个数最多。
```

## 3. 解题思路

### 3.1 暴力思路

把候选偶数看成物品（$2, 4, 6, \dots$，最多约 $\sqrt{2 \cdot finalSum} \approx 1.4 \times 10^5$ 个），做「恰好装满背包求最大件数」的 0/1 背包——状态数 $O(finalSum \times \sqrt{finalSum})$，$finalSum = 10^{10}$ 下时间和空间都爆炸。即使把值除以 2 转成「互不相同的正整数拆分求最多项」，朴刻画 DP 仍是 $O(finalSum \times \sqrt{finalSum})$，不可行。必须利用「互不相同偶数」的结构做贪心。

### 3.2 核心观察：从 2 开始的连续偶数增长最慢

![贪心：取 2,4,6,… 直到放不下，余数并入最大项](images/bw72_q3_greedy_concept.svg)

**个数上界**：$m$ 个互不相同的正偶数，其最小可能总和是前 $m$ 个偶数之和

$$
2 + 4 + \dots + 2m = m(m + 1).
$$

因此**任何**合法拆分的个数 $m$ 都满足 $m(m+1) \le finalSum$——这给出个数的硬上界 $m_{\max} = \max\{m : m(m+1) \le finalSum\}$。

**贪心构造恰好达到上界**：从 $2$ 开始依次取 $2, 4, 6, \dots$，只要「当前部分和 + 下一个偶数 $\le finalSum$」就取进来。停在某一步时：

- 已取 $k$ 个偶数 $2, 4, \dots, 2k$，部分和 $S_k = k(k+1)$；
- 剩余 $r = finalSum - S_k$，满足 $0 \le r < 2(k+1)$（否则会继续取）且 $r$ 为偶数（奇偶性传递）。

把 $r$ **并入最大项** $2k$，得到 $2k + r$。由于 $0 \le r < 2(k+1) = 2k + 2$，有 $2k \le 2k + r < 4k + 2$；特别地 $2k + r \ge 2k > 2(k-1) = $ 前一项，且 $2k + r \ne 2k$ 仅当 $r = 0$（此时不变）。互异性成立（详见 §5 引理 2），且总个数 $k$ 恰是上界 $m_{\max}$（见定理）。

### 3.3 算法流程

```text
if finalSum 是奇数: return []          # 偶数之和必为偶数
res = []; cur = 2; s = 0
while s + cur <= finalSum:
    res.append(cur); s += cur; cur += 2
res[-1] += finalSum - s               # 余数并入最大项
return res
```

**注意**：能进入循环说明 $finalSum \ge 2$（偶数且 $\ge 2$），`res` 至少含 $[2]$，`res[-1]` 不会越界；$finalSum = 2$ 时直接得 $[2]$（余数 0）。

### 3.4 示例演算

![示例演算：finalSum=28 的贪心与并入](images/bw72_q3_example_walkthrough.svg)

以示例 3（$finalSum = 28$）：

| 步骤 | 尝试取 | 部分和 $s$ | 动作 |
|------|--------|-----------|------|
| 1 | 2 | 0 → 2 | 取（$2 \le 28$） |
| 2 | 4 | 2 → 6 | 取（$6 \le 28$） |
| 3 | 6 | 6 → 12 | 取（$12 \le 28$） |
| 4 | 8 | 12 → 20 | 取（$20 \le 28$） |
| 5 | 10 | — | 停（$20 + 10 = 30 > 28$） |

余数 $r = 28 - 20 = 8$ 并入最大项：$8 + 8 = 16$，最终拆分 $[2, 4, 6, 16]$，共 4 个。个数上界验证：$m(m+1) \le 28$ 的最大整数是 $m = 4$（$4 \times 5 = 20 \le 28 < 5 \times 6 = 30$），贪心恰好取到 4 个。官方输出 $[6,8,2,12]$ 也是 4 个（同个数不同组合，题目允许任意解）。

## 4. 算法细节

1. **奇偶预判**：$finalSum$ 为奇数直接返回 `[]`——偶数之和的奇偶性封闭。这是 $O(1)$ 剪枝，也是唯一无解情形（偶数 $finalSum \ge 2$ 必有解，至少 $[finalSum]$ 本身）。
2. **循环条件**：`while (s + cur <= finalSum)`，注意是「取后总和」与 $finalSum$ 比较；写成 `cur <= finalSum - s` 等价，但别写成 `s <= finalSum`（会多取）。
3. **并入最大项而非新开一项**：停机时 $r$ 满足 $0 \le r < 2(k+1)$ 且为偶数，故 $r \in \{0, 2, \dots, 2k\}$——新开一项 $r$（当 $r > 0$）必与已取的某个 $2i$（$1 \le i \le k$）**重复**，违反互异；并入 $2k$ 后结果 $\ge 2k$ 严格大于其余项，互异保持。
4. **数据类型**：$finalSum \le 10^{10}$ 超 `int`；C++ 用 `long long`（含中间和 $s$：最大约 $finalSum + 2 \times \sqrt{2 finalSum} < 1.1 \times 10^{10}$）。循环次数约 $\sqrt{finalSum / 2} \approx 7 \times 10^4$，输出列表也这个量级。
5. **复杂度**：时间 $O(\sqrt{finalSum})$（循环次数即拆分个数），空间除输出外 $O(1)$。
6. **为什么不是 DP**：互异偶数的前缀结构（前 $m$ 个最小和恰为 $m(m+1)$）让「最多项」有闭式上界，贪心直接构造，DP 完全多余。

## 5. 正确性证明

**引理 1（个数上界）**：任何合法拆分（$m$ 个互不相同的正偶数，和为 $finalSum$）满足 $m(m+1) \le finalSum$。

**证明**：设拆分为 $e_1 < e_2 < \dots < e_m$（互异正偶数升序）。互异正偶数从小到大至少是 $2, 4, \dots, 2m$：由 $e_1 \ge 2$、$e_{i+1} \ge e_i + 2$ 归纳得 $e_i \ge 2i$。于是 $finalSum = \sum e_i \ge \sum_{i=1}^m 2i = m(m+1)$。∎

**引理 2（贪心结果合法）**：贪心输出 $k$ 个数——$2, 4, \dots, 2(k-1), 2k + r$（$r$ 为停机余数）——两两互异、均为正偶数、和恰为 $finalSum$。

**证明**：奇偶与总和：各取数均为偶数；部分和 $S_k = k(k+1)$，加余数 $r$ 后总和 $= S_k + r = finalSum$（$r$ 的定义）。互异：前 $k - 1$ 项 $2, 4, \dots, 2(k-1)$ 严格递增互异；最后一项 $2k + r \ge 2k > 2(k-1)$（因 $r \ge 0$），故与前 $k-1$ 项互异。正偶数：$2k + r$ 是偶数（$r$ 偶）且 $\ge 2 > 0$。∎

**定理（贪心最优）**：贪心输出的个数 $k$ 等于上界 $m_{\max} = \max\{m : m(m+1) \le finalSum\}$，因此是最多拆分。

**证明**：停机条件为 $S_k + 2(k+1) > finalSum$（下一个偶数放不下），即 $(k+1)(k+2) > finalSum$。结合取数过程始终满足 $S_k = k(k+1) \le finalSum$（每步取前检查），得

$$
k(k+1) \le finalSum < (k+1)(k+2).
$$

而 $m_{\max}$ 的定义即满足 $m(m+1) \le finalSum$ 的最大整数 $m$，上式说明 $k$ 恰为该最大值（若 $k < m_{\max}$，则 $(k+1)(k+1+1) \le m_{\max}(m_{\max}+1) \le finalSum$，与 $(k+1)(k+2) > finalSum$ 矛盾）。由引理 2 输出合法、由引理 1 无更多项的可能，故 $k$ 最优。∎

**推论（无解条件完备）**：$finalSum$ 为奇数是唯一无解情形。

**证明**：奇数无解由偶数之和封闭。偶数 $finalSum \ge 2$ 时贪心至少取 $[2]$（$2 \le finalSum$ 触发首次取数），引理 2 保证输出合法，故有解。∎

## 6. 复杂度分析

- **时间**：$O(\sqrt{finalSum})$。循环次数 $k \le \sqrt{finalSum}$（由 $k(k+1) \le finalSum$），每次 $O(1)$。
- **空间**：$O(1)$ 额外空间（输出列表 $O(\sqrt{finalSum})$ 不计）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<long long> maximumEvenSplit(long long finalSum) {
        if (finalSum % 2 != 0) return {};     // 奇数无法拆成偶数之和
        vector<long long> res;
        long long cur = 2, sum = 0;
        while (sum + cur <= finalSum) {       // 2, 4, 6, ... 依次贪心取
            res.push_back(cur);
            sum += cur;
            cur += 2;
        }
        res.back() += finalSum - sum;         // 余数并入最大的那个偶数
        return res;
    }
};
```

### Python

```python
class Solution:
    def maximumEvenSplit(self, finalSum: int) -> list[int]:
        if finalSum % 2 != 0:            # 奇数无法拆成偶数之和
            return []
        res = []
        cur, s = 2, 0
        while s + cur <= finalSum:       # 2, 4, 6, ... 依次贪心取
            res.append(cur)
            s += cur
            cur += 2
        res[-1] += finalSum - s          # 余数并入最大的那个偶数
        return res
```

> 💡 两份代码均通过官方示例（`[2,4,6]`、`[]`、个数 4），以及 $finalSum \in [1, 600]$ 全量 + 200 组大随机（至 $10^{10}$）与「0/1 背包求最大件数」暴力的对拍（800 组，校验合法性 + 个数等于背包最优），`mismatch = 0`。

## 8. 边界情况与易错点

1. **奇数无解**：先判 `finalSum % 2`，否则循环体在奇数上行为紊乱（余数奇偶不符，并入后不再是偶数）。
2. **$finalSum = 2$**：取 $[2]$、余数 0，`res.back() += 0` 无副作用。**别在 `res` 为空时调用 `res.back()`**——先判奇数（奇数提前返回）保证了偶数分支至少取一个元素。
3. **溢出**：$10^{10}$ 超 32 位；C++ 用 `long long`（含 `cur`、`sum`），Python 无虞。返回类型 `vector<long long>` / `list[int]`。
4. **循环终止**：`cur` 每轮 +2，$s + cur$ 严格递增，最多 $\sqrt{finalSum/2} \approx 7 \times 10^4$ 轮，不会死循环。
5. **余数并入的对象是「最大项」**：引理 2 的互异论证只对「并入最大项」直接成立（$2k + r \ge 2k > $ 其余各项）。若并入某个小项 $2i$，结果 $2i + r$ 可能落在 $(2i, 2k]$ 区间内、与更大的项相等或仍夹在中间，需要逐例重新验证互异——统一并入最大项，一条引理兜底，最稳。
6. **输出顺序任意**：题目允许任意顺序，无需排序；若为调试统一输出，可自行排序后再比对。
