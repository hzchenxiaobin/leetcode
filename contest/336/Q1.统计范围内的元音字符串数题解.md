# LeetCode 统计范围内的元音字符串数 题解

## 1. 题目概述

- **标题 / 题号**：统计范围内的元音字符串数（#2586，easy）
- **链接**：https://leetcode.cn/problems/count-the-number-of-vowel-strings-in-range/
- **来源**：LeetCode 第 336 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、计数、一次遍历

**题意**：给定下标从 $0$ 开始的字符串数组 `words` 与整数 `left`、`right`。若字符串**以元音字母开头并以元音字母结尾**（元音集合 $V = \{\texttt{a},\texttt{e},\texttt{i},\texttt{o},\texttt{u}\}$），则称其为**元音字符串**。返回下标落在**闭区间** $[\text{left},\text{right}]$ 内的元音字符串个数。

**约束**：

- $1 \le \text{words.length} \le 1000$
- $1 \le \text{words}[i].\text{length} \le 10$
- `words[i]` 仅由小写英文字母组成
- $0 \le \text{left} \le \text{right} < \text{words.length}$

> 💡 **读题要点**：骨架只有三个成分——**区间遍历 + 单串 $O(1)$ 判定 + 计数**。算法上没有任何发挥空间，全部风险集中在两处：**闭区间的两端**与**元音集合的边界（'y' 不算）**。

## 2. 示例

**示例 1**

```text
输入：words = ["are","amy","u"], left = 0, right = 2
输出：2
解释：
  "are"：'a' 开头、'e' 结尾 → 元音字符串 ✓
  "amy"：'a' 开头、'y' 结尾 → 'y' 非元音 ✗
  "u"  ：'u' 开头、'u' 结尾 → 元音字符串 ✓（单字符，首尾同位）
```

**示例 2**

```text
输入：words = ["hey","aeo","mu","ooo","artro"], left = 1, right = 4
输出：3
解释：闭区间 [1,4] 内——
  "aeo"  ：a..o ✓
  "mu"   ：m..u ✗（首字符非元音）
  "ooo"  ：o..o ✓
  "artro"：a..o ✓
（"hey" 在下标 0，范围外，不参与判定）
```

**示例 3**（自造边界用例）

```text
输入：words = ["hey","aeo","mu","ooo","artro"], left = 3, right = 3
输出：1
解释：区间收缩成单点，只判 "ooo"（o..o ✓）→ ans = 1。
若把闭区间误写成半开（漏 right），同一数据错答 0。
```

## 3. 解题思路

签到题的目标是**读题 30 秒锁定骨架 + 零调试一次过**。本题不存在"选哪个算法"的问题，存在的是"别想多、别想岔"的问题。

### 3.1 暴力思路：照定义直译

最直白的做法就是对范围内每个字符串做一次定义判定：计数器 $\text{ans} \leftarrow 0$，遍历 $i$ 从 `left` 到 `right`，取 `words[i]` 的首字符与末字符，**皆**在 $V$ 内则计数。时间 $O(\text{right}-\text{left}+1)$，空间 $O(1)$——对 $n \le 1000$ 的规模，**这就是最优解，无需再优化**。

真正值得复盘的是两类「想多了」和一类「想岔了」：

- **想多了之一：上前缀和**。赛前刷过 2559（多查询版同款判定）的人容易条件反射建 $0/1$ 前缀和。但本题**只有一个查询**，$O(n)$ 预处理换不来任何加速，还平添 $O(n)$ 空间——杀鸡用牛刀；
- **想多了之二：整串扫描**。找首字符 / 末字符不需要扫，`w[0]` 与 `w.back()` 下标直取，$O(1)$；
- **想岔了：把 `right` 排除**。区间是**闭**的，半开区间的肌肉记忆（`for i in range(left, right)`、`words[left:right]`）会**静默**漏掉 `right` 处的字符串——示例 2 里漏掉 `"artro"` 错答 2 ≠ 3，样例能抓住，但罚时已产生。

### 3.2 核心观察：判定只看首尾两个字符

![核心观察：元音字符串判定只看首尾两个字符，中间字符与串长无关](images/wc336_q1_first_last_only.svg)

三个要点：

1. **谓词 $O(1)$**：`words[i]` 是否为元音字符串，**只取决于 `w[0]` 与 `w.back()` 两个字符**，与中间字符、与串长全然无关——长度 $1$ 的 `"u"` 与长度 $10$ 的串判定成本完全相同；
2. **元音集合是常数**：$|V| = 5$，五连比较、成员判断、位掩码任选其一，都是 $O(1)$；
3. **单查询不配前缀和**：直接扫 $[\text{left},\text{right}]$ 一趟即达下界——范围内每个字符串都可能改变答案，必须逐个看一眼。

### 3.3 算法流程

![算法流程：闭区间扫描 + 首尾双判定 + 计数](images/wc336_q1_range_scan_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `ans ← 0` | 计数器 |
| ② 遍历 | `i` 从 `left` 到 `right`，**含两端** | 闭区间，至多 $n$ 轮 |
| ③ 判首 | `w[0]` ∈ V？ | 否 → 看下一个 i |
| ④ 判尾 | `w.back()` ∈ V？ | 否 → 看下一个 i |
| ⑤ 计数 | 两个都过 → `ans++` | 串长 1 时首尾同位 |
| ⑥ 返回 | 循环结束返回 `ans` | 全不满足时天然为 0 |

### 3.4 示例演算

![示例演算：闭区间 [1,4] 逐串走查 + 单点区间边界实验](images/wc336_q1_example_walkthrough.svg)

对示例 2 `words = ["hey","aeo","mu","ooo","artro"]`，`left = 1, right = 4`：

| $i$ | `words[i]` | 首 | 尾 | 首元音? | 尾元音? | 计数? | `ans` |
|-----|-----------|----|----|---------|---------|-------|-------|
| 1 | "aeo" | a | o | ✓ | ✓ | ✓ | 1 |
| 2 | "mu" | m | u | ✗ | ✓ | ✗ | 1 |
| 3 | "ooo" | o | o | ✓ | ✓ | ✓ | 2 |
| 4 | "artro" | a | o | ✓ | ✓ | ✓ | 3 |

返回 `3` ✓。下标 $0$ 的 `"hey"` 在范围外全程不看——注意它的首字符 `'h'` **恰好也不是元音**，就算误把它圈进来也不影响答案，纯属烟雾弹；真正的考点 `"mu"`（首非元音）与 `"artro"`（恰在 `right` 处）都藏在区间内。

边界实验（示例 3）：`left = right = 3` 时区间收缩为单点，只判 `"ooo"` → `ans = 1`；若循环误写 `i < right`，此例一趟都不跑、错答 0——**单点区间是"半开区间"错误的最小复现现场**。

## 4. 算法细节

1. **首尾直取**：`w.front()` / `w.back()`（C++）、`w[0]` / `w[-1]`（Python），下标访问 $O(1)$，不写整串扫描；
2. **元音判定写法任选**：五连 `==`（编译期内联、零依赖）、`ch in "aeiou"`（Python 成员判断）、`set('aeiou')` 哈希、位掩码 `(0x104111 >> (ch - 'a')) & 1`（$0x104111 = (1\ll0)|(1\ll4)|(1\ll8)|(1\ll14)|(1\ll20)$，恰是 a/e/i/o/u 在字母表中的位）——全是 $O(1)$，选顺手的；
3. **闭区间三连**：C++ `for (int i = left; i <= right; ++i)`；Python `range(left, right + 1)`；切片 `words[left:right+1]`——**三处都要带 `<=` / `+1`**；
4. **`bool` 直接累加**：`ans += (判定表达式)`，把 if 收进一行；C++ 中 `bool` 提升为 `int` 恰为 0/1；
5. **`const string& w`**：引用避免逐串拷贝（$n \le 1000$ 无所谓，是肌肉记忆）；
6. **'y' 不是元音**：题目白纸黑字 $V = \{a,e,i,o,u\}$，语言学争议与做题无关。

## 5. 正确性证明

**引理 1（判定等价）**：设 $V = \{\texttt{a},\texttt{e},\texttt{i},\texttt{o},\texttt{u}\}$，$w$ 是长度 $m \ge 1$ 的字符串，则 $w$ 是元音字符串 $\iff$ $w[0] \in V$ 且 $w[m-1] \in V$。

**证明**：按定义，元音字符串即"以元音开头且以元音结尾"的字符串。$m \ge 1$ 保证首末字符均存在；"以元音开头"即 $w[0] \in V$，"以元音结尾"即最后一个字符 $w[m-1] \in V$。两条件恰为算法所判的两个谓词，等价成立。∎

**引理 2（计数不变量）**：算法每处理完下标 $i$ 后，`ans` 等于 $\{j \in [\text{left},\, i] : \text{words}[j] \text{ 是元音字符串}\}$ 的大小。

**证明**：对 $i$ 归纳。初始（未处理任何下标）时 `ans = 0`，集合为空，成立。设处理完 $i-1$ 后结论成立。处理 $i$ 时，由引理 1，算法判定 `words[i]` 是元音字符串当且仅当其首尾皆元音；判定为真则 `ans++`，否则不变——两种情形下 `ans` 都与 $[\text{left}, i]$ 上已处理部分的元音字符串个数一致。∎

**定理**：算法返回 $[\text{left}, \text{right}]$ 中元音字符串的个数。

**证明**：循环自 `i = left` 起至 `i = right` 止（含两端），范围内每个下标恰被处理一次，范围外下标从不被访问。循环终止时，由引理 2（取 $i = \text{right}$），`ans` 即 $[\text{left}, \text{right}]$ 中元音字符串的计数，返回它即得答案。∎

**推论（无需特判）**：串长为 $1$ 时 $w[0] = w[m-1]$，引理 1 退化为单字符判定（如 `"u"` ✓、`"b"` ✗）；范围内无元音字符串时 `ans` 保持 $0$——单字符串与空答案均被同一套逻辑覆盖。

## 6. 复杂度分析

- **时间复杂度**：$O(\text{right} - \text{left} + 1) \subseteq O(n)$。范围内每个字符串做两次 $O(1)$ 元音判定，已达下界 $\Omega(\text{right}-\text{left}+1)$——每个字符串都可能改变答案，必须逐个看；
- **空间复杂度**：$O(1)$。一个计数器 + 常数大小的元音集合（$|V| = 5$），无任何容器随 $n$ 增长。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int vowelStrings(vector<string>& words, int left, int right) {
        auto isVowel = [](char c) {
            return c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u';
        };
        int ans = 0;
        for (int i = left; i <= right; ++i) {          // 闭区间：i <= right
            const string& w = words[i];
            ans += isVowel(w.front()) && isVowel(w.back());
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def vowelStrings(self, words: List[str], left: int, right: int) -> int:
        vowels = set('aeiou')
        return sum(words[i][0] in vowels and words[i][-1] in vowels
                   for i in range(left, right + 1))     # 闭区间：right + 1
```

> 💡 Python 一行流：`sum(w[0] in 'aeiou' and w[-1] in 'aeiou' for w in words[left:right+1])`——切片会复制子列表，显式下标更省；单字符成员判断 `in 'aeiou'` 连集合都不用建。

## 8. 边界情况与易错点

1. **闭区间含 `right`（头号罚时点）**：C++ 写 `i <= right`、Python 写 `right + 1`、切片写 `right+1`——半开肌肉记忆会**静默**漏答。单点区间 `left == right` 是最小复现场景（示例 3：正确 1，误写 0）；
2. **'y' 不是元音**：$V = \{a,e,i,o,u\}$ 是硬性约定，`"amy"` 出局（官方示例 1 的考点）——别把英语里"y 有时是元音"的语感带进来；
3. **单字符串**：`"u"` 首 = 尾 = 同一个字符，`front()/back()` 自然覆盖，无需特判长度；`"b"` 同理判 ✗；
4. **C++ `front()/back()` 空串 UB**：约束 $\text{len} \ge 1$ 挡住了它——但这是"约束救了代码"，知道为什么安全比安全本身更重要；
5. **全不满足返回 0**：如 `["bb"]`，`ans` 从未自增，天然正确，无需特判；
6. **无需前缀和**：单查询 $q = 1$，直接扫描即最优；多查询（2559）才需要 $0/1$ 前缀和——别把"数据结构升级"错用在签到题上；
7. **小写字母已保证**：无需 `tolower`；若题面改成含大写，判定前先归一化；
8. **规模极小**：$n \le 1000$、串长 $\le 10$，无溢出、无性能压力，唯一的敌人是手滑——读题 30 秒锁定"闭区间 + 首尾判定"，60 秒写完提交。

**延伸思考**：

- **单查询 → 多查询的临界**：直接扫 $O(n)$/查询；前缀和 $O(n)$ 预处理 + $O(1)$/查询。$q = 1$ 时同阶但直接扫省空间；$q$ 一大前缀和完胜——**查询次数决定数据结构**；
