# LeetCode 重排数组以得到最大前缀分数 题解

## 1. 题目概述

- **标题 / 题号**：重排数组以得到最大前缀分数（#2587，medium）
- **链接**：https://leetcode.cn/problems/rearrange-array-to-maximize-prefix-score/
- **来源**：LeetCode 第 336 场周赛 Q2
- **难度**：中等
- **标签**：贪心、排序、前缀和

**题意**：给定下标从 $0$ 开始的整数数组 `nums`，允许把元素按**任意顺序**重排。重排后定义 $\text{prefix}[i]$ 为前 $i+1$ 个元素之和，**分数**是 `prefix` 数组中**正整数**（严格 $>0$）的个数。求可达的**最大分数**。

**约束**：

- $1 \le n = \text{nums.length} \le 10^5$
- $-10^6 \le \text{nums}[i] \le 10^6$

> 💡 **读题定位**：题面三个关键词——「**重排**」「**前缀和**」「**统计正数个数**」。「重排」说明顺序是唯一可动的决策变量；「统计个数」说明不关心正数多大、只关心是否为正。「重排 + 逐位置目标」这类问题，第一反射应是**排序贪心**：越靠前的位置对每个前缀和都有贡献，就该把**大数放前面**——降序。

## 2. 示例

**示例 1**

```text
输入：nums = [2,-1,0,1,-3,3,-3]
输出：6
解释：重排为 [2,3,1,-1,-3,0,-3] 时 prefix = [2,5,6,5,2,2,-1]，6 个为正。
```

**示例 2**

```text
输入：nums = [-2,-3,0]
输出：0
解释：没有正元素垫底，任何重排下前缀和都非正，分数恒为 0。
```

**示例 3**（自造：恰好穿零）

```text
输入：nums = [1,-1]
输出：1
解释：降序 [1,-1] → prefix = [1, 0]。第二个前缀和恰好为 0，
而 0 不是正数、不计数——答案 1 而非 2。「严格 > 0」是隐藏判分考点。
```

**示例 4**（自造：全正）

```text
输入：nums = [5, 100, 7]
输出：3
解释：全正时无论怎么排，前缀和都单调增且恒正，答案 = n。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有排列

最朴素的做法是枚举 `nums` 的全部 $n!$ 种排列，对每种排列累加一遍前缀和、统计正数个数，取最大值（C++ 可用 `next_permutation` 直译）。每种排列算前缀需 $O(n)$，总时间 $O(n! \cdot n)$：$n = 7$ 时约 $3.5\times10^4$ 次操作尚可，$n = 10^5$ 时排列数是一个**四十多万位**的十进制天文数字。它暴露了问题结构：**顺序是唯一自由度**，而「哪种顺序好」有极强的局部结构（大数在前），盲搜排列等于亲手放弃这个结构，不可行。

### 3.2 核心观察：降序排序「逐点支配」一切重排

![核心观察：降序排列的前缀和在每个位置都压住输入原序重排，分数 6 对 5 封顶](images/wc336_q2_desc_domination.svg)

**关键洞察**：位置 $i$ 的前缀和是「排在最前面的 $i+1$ 个数之和」。无论怎么重排，这 $i+1$ 个数都是数组的一个子集，其和**不会超过**数组中**最大的 $i+1$ 个数之和**——而降序排列恰好让每个位置的前 $i+1$ 个数都取到这个最大和：

$$
\text{prefix}_{\text{降序}}[i] \;=\; \max_{\text{任意重排 } \pi}\; \text{prefix}_{\pi}[i] \qquad \text{对每个 } i \text{ 同时成立。}
$$

这比「降序是某个最优解」强得多——是**逐点支配**：降序的前缀和数组在**每一个位置**都不小于任何重排的对应值。若降序下 $\text{prefix}[i] \le 0$，任何重排都无法让位置 $i$ 为正；反之，某个重排让位置 $i$ 为正，降序必然也让它为正。**任何重排的正位置集合都被降序全盘包含**，分数自然封顶（严格证明见 §5）。

**三段单峰结构**：降序后数组自动呈「正数区 → 零区 → 负数区」三段——

- **正数区**：每加一个正数前缀和**单调增**，起步为正则一路为正；
- **零区**：加 $0$ **持平**，此刻若 $\text{prefix} > 0$ 照样计分；
- **负数区**：剩余元素全 $\le 0$，前缀和**单调减**。

于是前缀和形如「升 → 平 → 降」的**单峰曲线**，正位置恰是**连续前缀段** $[0, m)$；一旦穿零（$\le 0$），后面全是更小的数，**永不回升**——统计可在首次穿零处提前终止。

> 💡 **负数区为何也按降序？** $-1$ 排在 $-3$ 前面，让前缀和**下落得最慢**，在穿零前多撑几步。全局降序一次到位，不必手工分三段绕弯。

> ⚠️ **「正」是严格 $>0$**：$\text{prefix} = 0$ 不计分（示例 3）。判据必须写 `sum > 0`，写成 `>=` 会把恰好为零的前缀和错算进分数。

### 3.3 算法流程

![算法流程：降序排序 → 初始化滚动和 → 逐格累加判定 sum>0 → 计数或穿零 break → 返回](images/wc336_q2_flow.svg)

流程五阶段：

1. **降序排序**：`sort(reverse=True)`，正数、零、负数自动归位且内部有序；
2. **初始化**：滚动和 `sum = 0`、计数 `cnt = 0`，不建 `prefix` 数组；
3. **逐格累加**：`sum += x`；
4. **判定**：`sum > 0` 则 `cnt++` 继续；否则 `break`（引理 2 保证后面不会再有正前缀）；
5. **返回** `cnt`（遍历完自然到达同一出口）。

> 💡 不 `break`、扫到底只统计 `sum > 0` 的位置，结果相同——穿零后前缀和恒非正，不会再贡献计数；`break` 只是省掉后半段无效累加，常数更小。赛场上写哪个都能过。

### 3.4 示例演算

![示例演算：降序后 [3,2,1,0,-1,-3,-3] 逐格累加，前 6 格为正、第 7 格穿零即停](images/wc336_q2_walkthrough.svg)

以示例 1 为例，降序后得 $[3,2,1,0,-1,-3,-3]$：

| 步 $i$ | $x$ | sum | sum > 0? | cnt | 说明 |
|--------|-----|-----|----------|-----|------|
| 0 | 3  | 3  | ✓ | 1 | 最大正数起步，sum 即正 |
| 1 | 2  | 5  | ✓ | 2 | 正数区单调增 |
| 2 | 1  | 6  | ✓ | 3 | 最后一个正数，sum 达峰 |
| 3 | 0  | 6  | ✓ | 4 | 零区：加 0 持平，sum > 0 照计 |
| 4 | -1 | 5  | ✓ | 5 | 负数区开始，绝对值小者先行 |
| 5 | -3 | 2  | ✓ | 6 | 递减但仍为正 |
| 6 | -3 | -1 | ✗ break | 6 | 穿零，后续只会更小，停 |

返回 $6$ ✓。示例 2 `[-2,-3,0]`：降序 $[0,-2,-3]$，首格 $\text{sum}=0$ 非正即停，返回 $0$ ✓——全负/全零情形被循环天然覆盖，无需特判。

## 4. 算法细节

1. **一次全局降序即可**：正数、零、负数自动归位且各自内部有序。「正数在前、负数升序」等手工分段写法只是全局降序的等价描述，多写多错；
2. **滚动求和**：只保留 `sum` 与 `cnt` 两个标量，不建前缀和数组，额外空间 $O(1)$；
3. **判据严格性**：`sum > 0` 计数、`sum <= 0` 终止，两者互为逆条件，条件别写岔；
4. **C++ 溢出**：全正时 $\text{sum}$ 可达 $10^5 \times 10^6 = 10^{11}$，超出 32 位 `int`（约 $2.1\times10^9$）约 47 倍，**必须用 `long long`**；用 `accumulate` 也别忘 `0LL` 初值；
5. **原地排序**：`sort(nums.begin(), nums.end(), greater<int>())` / `nums.sort(reverse=True)`，无需新数组，参数数组本身就是可修改的；
6. **提前终止是纯优化**：`break` 与扫到底结果一致（§5 引理 2），别为它写额外逻辑引入新 bug。

## 5. 正确性证明

设 $a_1 \ge a_2 \ge \dots \ge a_n$ 为 `nums` 降序排列后得到的数组（$a_k$ 即全集第 $k$ 大的元素）。记某个重排 $\pi = (\pi_1, \dots, \pi_n)$ 在位置 $i$（$0 \le i < n$）的前缀和为 $P_\pi(i) = \sum_{k=1}^{i+1} \pi_k$；降序时 $P_{\text{desc}}(i) = a_1 + \dots + a_{i+1}$。

**引理 1（逐点支配）**：对任意重排 $\pi$ 与任意位置 $i \in [0, n)$，有 $P_\pi(i) \le P_{\text{desc}}(i)$。

**证明**：$P_\pi(i)$ 是某个大小为 $i+1$ 的子集 $B \subseteq \{a_1,\dots,a_n\}$ 的元素和。设 $B$ 中第 $k$ 大的元素为 $b_k$（$k = 1, \dots, i+1$）。断言 $b_k \le a_k$：若不然 $b_k > a_k$，则由 $b_1 \ge \dots \ge b_k$ 知全集中有 $k$ 个元素都严格大于 $a_k$；而全集是降序的，严格大于第 $k$ 大元素 $a_k$ 的至多 $k-1$ 个（即 $a_1, \dots, a_{k-1}$），矛盾。逐项求和得 $P_\pi(i) = \sum_{k=1}^{i+1} b_k \le \sum_{k=1}^{i+1} a_k = P_{\text{desc}}(i)$。∎

**引理 2（穿零后永不回升）**：降序排列下若 $P_{\text{desc}}(i) \le 0$，则对一切 $j > i$ 均有 $P_{\text{desc}}(j) \le 0$。

**证明**：$a_{i+1}$ 是降序前 $i+1$ 个元素中的最小者，不超过其平均值：$a_{i+1} \le \frac{P_{\text{desc}}(i)}{i+1} \le 0$。对 $j > i$，$P_{\text{desc}}(j) = P_{\text{desc}}(i) + \sum_{k=i+2}^{j+1} a_k$，其中每个 $a_k \le a_{i+1} \le 0$，故新增部分 $\le 0$，从而 $P_{\text{desc}}(j) \le P_{\text{desc}}(i) \le 0$。∎

**定理**：降序排列取得最大分数，即 $\text{score}(\text{desc}) = \max_{\pi} \text{score}(\pi)$。

**证明**：$\text{score}(\pi) = \bigl|\{\, i \in [0,n) : P_\pi(i) > 0 \,\}\bigr|$。若位置 $i$ 满足 $P_\pi(i) > 0$，由引理 1 得 $P_{\text{desc}}(i) \ge P_\pi(i) > 0$，即 $i$ 也落在降序的正位置集合中。于是任意 $\pi$ 的正位置集合都被降序的正位置集合包含，故 $\text{score}(\pi) \le \text{score}(\text{desc})$；取 $\pi = \text{desc}$ 时等号可达。∎

**推论（早停正确性）**：由引理 2，降序的正位置集合恰为连续前缀段 $[0, m)$，算法在首个 $P_{\text{desc}}(i) \le 0$ 处 `break`（或扫完整个数组）均返回 $m = \text{score}(\text{desc})$，由定理即最大分数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，降序排序主导（$n = 10^5$ 时约 $1.7\times10^6$ 次比较）；随后一趟线性扫描至多 $O(n)$（`break` 后往往远小于 $n$），被排序掩盖，对 $n \le 10^5$ 绰绰有余；
- **空间复杂度**：$O(\log n)$——C++ `std::sort`（introsort）递归栈；Python `list.sort` 为 timsort，额外合并缓冲最坏 $O(n)$。除排序外仅 `sum`/`cnt` 两个标量，不建前缀和数组，$O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxScore(vector<int>& nums) {
        sort(nums.begin(), nums.end(), greater<int>());  // 降序：大数靠前，自动三段
        long long sum = 0;    // 全正时前缀和可达 1e11，int 会溢出
        int cnt = 0;
        for (int x : nums) {
            sum += x;
            if (sum > 0) ++cnt;   // 严格 > 0 才算正
            else break;           // 穿零后剩余元素全 <= 0，提前收手（引理 2）
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def maxScore(self, nums: List[int]) -> int:
        nums.sort(reverse=True)
        s = 0
        cnt = 0
        for x in nums:
            s += x
            if s <= 0:        # 穿零，后面只会更小
                break
            cnt += 1           # 严格 > 0 才计
        return cnt
```

> 💡 两种语言逻辑等价（`sum > 0` 计数与 `s <= 0` 终止互为逆条件）。Python 整数任意精度无溢出之虞；C++ 的 `long long` 是本题唯一的"隐性"提交门槛。

## 8. 边界情况与易错点

1. **`long long` 溢出（头号罚时点）**：$n \le 10^5$、$|\text{nums}[i]| \le 10^6$，全正时前缀和上限 $10^{11}$，超 32 位 `int` 约 47 倍。C++ 的 `sum` 必须 `long long`，`accumulate` 要给 `0LL` 初值；Python 天然免疫；
2. **「正」是严格 $>0$**：$\text{sum} = 0$ 不计分（自造示例 3：`[1,-1]` 答案 1 不是 2；`[0,0,0]` 答案 0）。判据写 `>=` 直接 WA；
3. **全负 / 全零数组**：降序后首格 $\le 0$，立即 `break` 返回 0——循环天然覆盖，无需特判；
4. **零元素的双重身份**：$0$ 本身不是正数，但**加 0 那步**若此刻 `sum > 0`，该位置前缀和仍为正、照常计分（示例 1 下标 3）——「元素正负」与「前缀和正负」别混为一谈；
5. **别建 `prefix` 数组**：滚动求和 $O(1)$ 空间足够，建数组白吃 $O(n)$ 内存与一趟遍历；
6. **`break` 非正确性必需**：不 `break` 扫到底同样正确（引理 2），别为提前终止写复杂控制流引入新 bug；
7. **「重排」≠ 全排列 / 状压 DP**：$n = 10^5$ 直接封死排列枚举；见到「任意重排使逐位置指标最优」，先想**排序 + 交换/支配论证**；
8. **中途「回升」是幻觉**：任意排列的前缀和可能跌了又涨（§3.2 原序重排下标 5 回到 +2），但涨不过降序的对应位置——别被「要不要回溯」带偏，降序已封顶。
