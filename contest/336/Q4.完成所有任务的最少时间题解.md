# LeetCode 完成所有任务的最少时间 题解

## 1. 题目概述

- **标题 / 题号**：完成所有任务的最少时间（#2589，hard）
- **链接**：https://leetcode.cn/problems/minimum-time-to-complete-all-tasks/
- **来源**：LeetCode 第 336 场周赛 Q4
- **难度**：困难
- **标签**：贪心、排序、数组、区间调度

**题意**：有一台电脑可以**同时**运行无数个任务。给定二维整数数组 `tasks`，其中 `tasks[i] = [start_i, end_i, duration_i]` 表示第 $i$ 个任务需要在**闭区间** $[\text{start}_i, \text{end}_i]$ 内运行 $\text{duration}_i$ 个整数时间点（不要求连续）。电脑在某个时间点开机时，可同时为所有「窗口覆盖该时刻」的任务干活。求完成所有任务时，电脑最少需要开机多少个整数时间点。

**约束**：

- $1 \le \text{tasks.length} \le 2000$
- $\text{tasks}[i].\text{length} == 3$
- $1 \le \text{start}_i, \text{end}_i \le 2000$
- $1 \le \text{duration}_i \le \text{end}_i - \text{start}_i + 1$（每个任务单独必然可完成）

> 💡 **读题定位**：「同时运行无数任务」翻译一下：**一个开机时间点可以被任意多个任务共享**。于是问题不再是调度问题，而是一个覆盖问题——选一个**时间点集合** $S$，使每个任务 $i$ 满足 $|S \cap [\text{start}_i, \text{end}_i]| \ge \text{duration}_i$，最小化 $|S|$。这是经典的「**带需求的最小区间点覆盖**」，数据范围 $n, T \le 2000$ 提示 $O(n \cdot T)$ 的贪心扫描。关键决策只有两个：**任务按什么顺序处理**（按 $\text{end}$ 升序）与**缺口补在哪**（窗口内最右侧）。

## 2. 示例

**示例 1**（官方）

```text
输入：tasks = [[2,3,1],[4,5,1],[1,5,2]]
输出：2
解释：开机点 {2, 5}——
- 任务 0 [2,3] 需 1：2 ∈ [2,3] ✓
- 任务 1 [4,5] 需 1：5 ∈ [4,5] ✓
- 任务 2 [1,5] 需 2：2、5 ∈ [1,5] ✓
任务 2 完全「白嫖」了前两个任务的开机点。
```

**示例 2**（官方）

```text
输入：tasks = [[1,3,2],[2,5,3],[5,6,2]]
输出：4
解释：开机点 {2, 3, 5, 6}——
- 任务 0 在 [2,3] 运行；
- 任务 1 在 [2,3]（复用）和 [5,5] 运行；
- 任务 2 在 [5,5]（复用）和 [6,6] 运行。
```

**示例 3**（自造：隔离「补点位置」这一个变量）

```text
输入：tasks = [[1,4,2],[2,5,3]]
输出：3
解释：先处理 [1,4]，缺口 2 从右端补 {4,3}；
再处理 [2,5]，窗口内已有 3、4 两个点，缺口 1，从右端补 {5}。
开机集 {3,4,5} 共 3 个点。
若改成从左端补：{1,2} + {3,4} = 4 个点——同样的顺序，只换补点方向就多花 1 个点。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「开机时间点集合」不可行：时间点取值有 $2000$ 个，子集数 $2^{2000}$。退一步，对每个任务独立地在其窗口内选 $\text{duration}_i$ 个点，再对并集大小取最小，需要搜索所有组合并合并，同样是指数级。约束 $n \le 2000$、$T \le 2000$ 说明正确做法应当是 $O(n \cdot T)$ 或 $O(n \log n)$ 级别的**确定性扫描**——贪心。

### 3.2 核心观察：共享 + 按 end 排序 + 从右端补点

![核心观察：开机点可被共享，缺口补在右端](images/wc336_q4_reuse_concept.svg)

三个观察环环相扣：

1. **共享性（问题的本质）**：电脑能同时跑无限任务，一个开机点 $t$ 同时服务所有满足 $\text{start}_i \le t \le \text{end}_i$ 的任务。最优解里不同任务的开机点必然高度重叠——否则可以把重叠的需求合并。目标就是让这种**复用最大化**。

2. **处理顺序：按 $\text{end}_i$ 升序**。先处理结束早的任务，它固定的开机点靠左；后续任务 $j$ 满足 $\text{end}_j \ge \text{end}_i$，窗口整体不早于当前窗口结束，先开的点更可能落进后续窗口被复用。

3. **补点位置：缺口补在窗口最右侧**。处理任务 $i$ 缺 $\text{need}$ 个点时，把点放在 $[\text{start}_i, \text{end}_i]$ 内**尽量靠右**的位置。理由：对后续任务 $j$，上界条件 $\text{新点} \le \text{end}_i \le \text{end}_j$ **恒成立**，复用与否只取决于下界 $\text{新点} \ge \text{start}_j$——**新点越靠右，越容易 $\ge \text{start}_j$**。

> ⚠️ **为什么必须按 end 排序而不是按 start？** 「从右补点」的优越性依赖 $\text{end}_j \ge \text{end}_i$ 这一偏序。按 start 排序时，先处理任务的窗口可能远远超过后续任务（如 $[1,100]$ 在前、$[2,3]$ 在后），补在 $100$ 附近的点对 $[2,3]$ 毫无用处。按 end 排序则保证补的点永远不会超过后续任务的上界。这与 [435. 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/)、[452. 用最少数量的箭引爆气球](https://leetcode.cn/problems/minimum-number-of-arrows-to-burst-balloons/) 一脉相承——**区间贪心几乎总是按 end 排序**。

### 3.3 算法流程

![算法流程：排序 → 复用统计 → 从右补缺](images/wc336_q4_greedy_flow.svg)

1. 将 `tasks` 按 $\text{end}_i$ **升序**排序；
2. 维护布尔数组 `on[0..maxEnd]`，`on[t] = true` 表示时刻 $t$ 已开机（开机只增不减，无需模拟关机）；
3. 依次处理每个任务 $[s, e, d]$：
   - 统计窗口 $[s, e]$ 内已开机的点数 `cnt`；
   - 若 `cnt >= d`：需求已被前序开机点**复用**满足，跳过；
   - 否则从 $e$ **向左**扫描，把未开机的点逐个开机，直到新增 $d - \text{cnt}$ 个；
4. 答案 = `on[]` 中 `true` 的总数。

### 3.4 示例演算

![示例演算：先复用后补缺](images/wc336_q4_walkthrough.svg)

以示例 2 `tasks = [[1,3,2],[2,5,3],[5,6,2]]` 为例（已按 end 升序）：

| 任务 | 窗口 | 需求 $d$ | 窗口内已有 cnt | 动作 | 本轮新增 | 累计开机集 |
|------|------|----------|----------------|------|----------|-----------|
| A | [1,3] | 2 | 0 | 从右补 2 个 | {3, 2} | {2, 3} |
| B | [2,5] | 3 | 2（复用 2、3） | 从右补 1 个 | {5} | {2, 3, 5} |
| C | [5,6] | 2 | 1（复用 5） | 从右补 1 个 | {6} | {2, 3, 5, 6} |

- 任务 A：窗口内无开机点，从右端 3 向左补 $\{3, 2\}$；
- 任务 B：窗口 $[2,5]$ 内已有 $\{2,3\}$，全部复用，缺口 1，从右端 5 向左补 $\{5\}$；
- 任务 C：窗口 $[5,6]$ 内已有 $\{5\}$，复用，缺口 1，从右端 6 向左补 $\{6\}$；
- 最终开机集 $\{2,3,5,6\}$，答案 $4$ ✓。

注意每轮「先复用、后补缺」：补的点永远只**增加**窗口内的开机数，不会破坏任何已满足的任务（正确性见 §5 引理 1）。

## 4. 算法细节

1. **`on` 数组的语义**：`on[t]` 是「全局时间轴」上时刻 $t$ 是否开机，由**所有**前序任务共同贡献。统计 `cnt` 时必须看全局数组，而不是只看上一个任务开的点。

2. **一遍倒序扫描同时完成统计与补点**：从 $e$ 向左扫到 $s$，遇已开机的点则 `cnt++`，遇未开机的点且仍有缺口则开机——统计与补点可在一次倒序扫描中完成，因为从右补点恰好也是从右统计。

3. **补点循环不会越界**：约束保证 $d \le e - s + 1$，故缺口总能在窗口内补满；当 `cnt < d` 时窗口内**未开机的点数** $= (e - s + 1) - \text{cnt} > (e - s + 1) - d \ge 0$，循环必在 $i \ge s$ 时终止，无需额外防御条件（但写上 `i >= s` 更稳妥）。

4. **排序比较器只比 `end`**：`end` 相同的任务处理顺序无关紧要——交换论证（§5 引理 3）只用到「后续任务 $\text{end}_j \ge \text{end}_i$」，相等时同样成立。

5. **复杂度可行性**：$n \le 2000$，$T \le 2000$，每个任务至多扫窗口两遍，总量 $\le 2 \times 4 \times 10^6$，常数极小，稳过。若值域巨大再考虑离散化 + 树状数组（见「相关题目与扩展」）。

6. **C++ 实现细节**：`on` 用 `vector<char>` 而非 `vector<bool>`——后者是位压缩特化，`cnt += on[i]` 有隐式转换开销且不支持直接取址；规模仅 $2001$，`char` 更快也更直观。

## 5. 正确性证明

约定：任务按 $\text{end}$ 升序编号 $1, 2, \dots, n$，记 $W_i = [\text{start}_i, \text{end}_i]$。贪心处理完前 $i$ 个任务后的开机集为 $G_i$（$G_0 = \varnothing$），处理任务 $i$ 时新增的点集为 $P_i$，即 $G_i = G_{i-1} \cup P_i$。称点集 $S$ **可行**，若对一切 $i$ 有 $|S \cap W_i| \ge d_i$。所求即最小可行集的大小 $\mathrm{OPT}$。

**引理 1（超集单调性）**：可行集的任何超集仍可行。

**证明**：对任意窗口 $W_i$，$S \subseteq S' \Rightarrow |S \cap W_i| \le |S' \cap W_i|$。覆盖次数只增不减，需求下限不被破坏。∎

**引理 2（贪心可行性）**：对一切 $j \le i$，$|G_i \cap W_j| \ge d_j$。特别地，最终集合 $G = G_n$ 可行，故 $|G| \ge \mathrm{OPT}$。

**证明**：对 $i$ 归纳。$i = 0$ 时无任务，平凡。设结论对 $i-1$ 成立。处理任务 $i$ 时，若 $|G_{i-1} \cap W_i| \ge d_i$ 则 $G_i = G_{i-1}$，结论自然延续；否则 $P_i$ 恰含 $d_i - |G_{i-1} \cap W_i|$ 个 $W_i$ 内的新点，补满后 $|G_i \cap W_i| = d_i$。又 $G_{i-1} \subseteq G_i$，由引理 1，前 $i-1$ 个任务的约束依旧满足。∎

**引理 3（右端交换引理）**：设处理任务 $i$ 时有缺口，即 $P_i \ne \varnothing$，注意 $P_i$ 恰为 $W_i$ 内未被 $G_{i-1}$ 占用的位置中**最靠右的** $|P_i|$ 个（$|P_i| = d_i - |G_{i-1} \cap W_i|$）。则对任意满足 $O \supseteq G_{i-1}$ 的可行集 $O$，存在可行集 $O' \supseteq G_i$ 且 $|O'| \le |O|$。

**证明**：

- **交换的构造**：由 $O$ 可行，$|O \cap W_i| \ge d_i$。把 $O \cap W_i$ 按「是否属于 $G_{i-1}$」分成两段，前段至多 $|G_{i-1} \cap W_i|$ 个，故「其余的」构成的集合 $B := (O \cap W_i) \setminus G_{i-1}$ 满足
  $$|B| \ge d_i - |G_{i-1} \cap W_i| = |P_i|.$$
  于是 $|B \setminus P_i| \ge |P_i \setminus B|$。取子集 $B' \subseteq B \setminus P_i$ 使 $|B'| = |P_i \setminus B|$，令
  $$O' = (O \setminus B') \cup (P_i \setminus B).$$
  直观上：把 $O$ 中落在窗口内、又不属于贪心已选的那些「散点」删掉若干个，换成贪心新补的右端点，删多少补多少。
- **$O' \supseteq G_i$**：$B' \cap G_{i-1} = \varnothing$（因 $B \cap G_{i-1} = \varnothing$），故 $G_{i-1} \subseteq O$ 中未被删去；$P_i \cap B$ 本就属于 $O$ 且未被删，$P_i \setminus B$ 被显式加入，故 $P_i \subseteq O'$。
- **大小**：$P_i \setminus B$ 与 $O$ 不交（$P_i$ 中的点若属于 $O$，则它 $\in W_i$ 且 $\notin G_{i-1}$，应归入 $B$，矛盾），故 $|O'| = |O| - |B'| + |P_i \setminus B| = |O|$。
- **位置关系**：任取 $b \in B \setminus P_i$。$b$ 是 $W_i$ 内未被 $G_{i-1}$ 占用、又没被贪心选中的位置；而 $P_i$ 取的是**最靠右的** $|P_i|$ 个未占用位置，所以没被选中的必然更小：
  $$b < \min P_i \le p, \quad \forall p \in P_i. \tag{$\ast$}$$
- **$O'$ 可行**，对三类任务分别验证：
  - **$j < i$**：$G_{i-1} \subseteq O'$，而 $G_{i-1}$ 单独已满足前 $i-1$ 个任务（引理 2），再由引理 1，$O'$ 满足它们。
  - **$j = i$**：窗口 $W_i$ 内删去 $|B'|$ 个（$B' \subseteq B \subseteq W_i$）、加入 $|P_i \setminus B| = |B'|$ 个（$P_i \subseteq W_i$），窗口内点数不变，仍 $\ge d_i$。
  - **$j > i$**（由排序 $\text{end}_j \ge \text{end}_i$）：只需证 $|O' \cap W_j| \ge |O \cap W_j|$。若 $B' \cap W_j = \varnothing$，只删了窗外点、只加了窗内点，成立。否则任取被删的 $b \in B' \cap W_j$，有 $\text{start}_j \le b$，结合 $(\ast)$ 得：对**每个** $p \in P_i$，
    $$\text{start}_j \le b < p \le \text{end}_i \le \text{end}_j,$$
    即 $P_i \setminus B$ **整体**落入 $W_j$，新增 $|B'| \ge |B' \cap W_j|$ 个点 $\ge$ 删除数。∎

**定理**：贪心开机集 $G$ 的规模等于最优值，$|G| = \mathrm{OPT}$。

**证明**：$G$ 可行（引理 2），故 $|G| \ge \mathrm{OPT}$。反之，取任一最优解 $O^*$，从 $O_0 = O^*$ 出发，对 $i = 1, 2, \dots, n$ 反复应用引理 3（$P_i = \varnothing$ 时直接取 $O_i = O_{i-1}$），得到一列可行集，且 $O_n \supseteq G_n = G$、$|O_n| \le |O^*|$。于是
$$|G| \le |O_n| \le |O^*| = \mathrm{OPT}.$$
两个方向结合即 $|G| = \mathrm{OPT}$。∎

> 💡 **证明结构复盘**：引理 1 说「加点无害」——贪心可以放心地只增不减；引理 2 说「贪心的解合法」——给出下界；引理 3 是灵魂：**从右端占位 = 把「对后续最友好」的让步形式化**，任何可行解都能在不变大、且不丢掉贪心已选点的前提下被逐步改造成包含 $G$ 的解——贪心选的每个点都「不亏」。这是「交换论证（exchange argument）」在区间贪心上的标准用法。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n + n \cdot T)$，其中 $T = \max\,\text{end}_i - \min\,\text{start}_i + 1 \le 2000$。排序 $O(n \log n)$；每个任务对窗口 $[s, e]$ 至多做两次线性扫描（统计 `cnt` + 从右补点，也可合并为一次倒序扫描），单任务 $O(T)$。本题 $n \cdot T \le 4 \times 10^6$，常数小。
- **空间复杂度**：$O(\max \text{end}_i) \le O(2001)$，即 `on` 布尔数组；排序若原地则 $O(1)$ 额外。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int findMinimumTime(vector<vector<int>>& tasks) {
        sort(tasks.begin(), tasks.end(),
             [](const auto& a, const auto& b) { return a[1] < b[1]; });
        int maxEnd = 0;
        for (auto& t : tasks) maxEnd = max(maxEnd, t[1]);
        vector<char> on(maxEnd + 1, 0);            // on[t]=1 表示时刻 t 已开机
        for (auto& t : tasks) {
            int s = t[0], e = t[1], d = t[2];
            int cnt = 0;
            for (int i = s; i <= e; ++i)            // 统计窗口内已开机点数
                cnt += on[i];
            for (int i = e; i >= s && cnt < d; --i) // 从右向左补缺口
                if (!on[i]) { on[i] = 1; ++cnt; }
        }
        return accumulate(on.begin(), on.end(), 0);
    }
};
```

### Python

```python
class Solution:
    def findMinimumTime(self, tasks: List[List[int]]) -> int:
        tasks.sort(key=lambda t: t[1])                 # 按 end 升序
        max_end = max(t[1] for t in tasks)
        on = [False] * (max_end + 1)                    # on[t] = 是否已开机
        for s, e, d in tasks:
            cnt = sum(on[s:e + 1])                      # 复用窗口内已开机点
            i = e
            while cnt < d:                             # 从右向左补缺口
                if not on[i]:
                    on[i] = True
                    cnt += 1
                i -= 1
        return sum(on)
```

## 8. 边界情况与易错点

1. **排序键必须是 `end`，不是 `start`**：反例 `tasks = [[1,4,2],[2,3,2]]`。按 end 先处理 `[2,3]` 补 $\{3,2\}$，`[1,4]` 窗口内已有 2 个点，直接复用，答案 2；按 start 先处理 `[1,4]` 补 $\{4,3\}$，`[2,3]` 只能复用 1 个再补 2，答案 3。**同样的补点规则，只换处理顺序就变差**——顺序与方向是一对绑定的决策。

2. **补点必须从右端向左，而不是从左端向右**：反例即正文示例 3 `[[1,4,2],[2,5,3]]`，从右补得 3、从左补得 4。从左补的点 $\text{start}_i$ 处只满足**更早**的任务，而按 end 排序后根本没有「更早」任务需要照顾（前面的任务已被满足），等于白白放弃复用。

3. **补点时要跳过已开机的点**：`if (!on[i])` 不可少。若把已开机点重复计入 `cnt`，会补不够导致答案偏大甚至错误。

4. **统计 `cnt` 必须查全局 `on` 数组**：窗口内已开机点来自**所有**前序任务，不只是上一个任务。误用「上一个任务的开机点集」会在三个以上任务时出错。

5. **闭区间边界**：窗口 $[s, e]$ 两端均可用。Python 切片 `on[s:e+1]` 的 `+1` 是经典错点；C++ 循环 `i <= e` 的等号同理。

6. **补点循环的终止性**：约束 $d \le e - s + 1$ 保证窗口内未开机的点在 `cnt < d` 时至少剩一个（见 §4 第 3 条），倒序扫描不会越过 $s$ 下溢。若不放心可显式加上 `i >= s` 的防御条件，两者答案一致。

7. **C++ 的 `vector<bool>` 陷阱**：位压缩特化导致 `operator[]` 返回代理对象、取址不合法、累加需隐式转换，改用 `vector<char>` 即可。

8. **无需模拟关机**：题面「空闲时可关机」是烟雾弹——开机点集合的补集自动是关机时间，统计 `on[]` 中 `true` 的个数即为答案。

9. **多任务共享同一时间点不冲突**：题目明说可同时运行无数任务，同一时刻可以同时推进所有窗口覆盖它的任务，无需任何容量检查。

**延伸思考**：

- **值域巨大时怎么办**？若 $\text{end}_i$ 达 $10^9$，逐点扫描不可行。可将所有 $s_i, e_i$ 离散化，用**树状数组**维护前缀开机数：查询 $|S \cap [s,e]|$ 变成 $O(\log n)$；补点阶段用「未开机位置的有序集合」`lower_bound` 从 $e$ 往左找空位，单次 $O(\log n)$，总体 $O(n \log n)$。本题 $T \le 2000$ 用不上，但思想值得沉淀。
- **若任务要求连续运行**（窗口内选一段长度恰为 $d_i$ 的连续区间）？那就从「多点覆盖」变成「区间选择」，直接贪心失效，需按左端点用优先队列做最小化并集长度的区间覆盖 DP/贪心，模型类似 [LC 1526. 形成目标数组的子数组最小和个数](https://leetcode.cn/problems/minimum-number-of-increments-on-subarrays-to-form-a-target-array/) 的分解思想。
- **若同一时刻最多服务 $k$ 个任务**（电脑容量有限）？问题立即升维成带容量约束的覆盖，满足 Hall 条件的判定可用流量模型刻画，难度陡增——正说明本题的「无数任务」是刻意留出的贪心突破口。
