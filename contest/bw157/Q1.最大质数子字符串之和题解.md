# LeetCode 最大质数子字符串之和 题解

## 1. 题目概述

- **标题 / 题号**：最大质数子字符串之和（#3556，medium）
- **链接**：https://leetcode.cn/problems/sum-of-largest-prime-substrings/
- **来源**：LeetCode 第 157 场双周赛 Q1
- **难度**：中等
- **标签**：哈希表、数学、字符串、数论、排序

**题意**：给定一个只由数字组成的字符串 `s`。把 `s` 的**每一个**子串解释成一个整数（**忽略前导零**），其中是**质数**的那些数值构成一个集合（同一个质数即使由多个不同子串得到，也只算一次）。取这个集合中**最大的 3 个**求和；如果不足 3 个，就把全部不同质数求和。

**约束**：

- $1 \le |s| \le 10$
- `s` 仅由数字字符组成

> 💡 数据范围小到可以「暴力枚举 + 逐个数判质数」，所以本题的难点不在算法，而在**去重**与**边界**（前导零、$0$ 和 $1$ 不是质数、不足 3 个时怎么返回）。

## 2. 示例

**示例 1**

```text
输入：s = "12234"
输出：1469
解释：子串形成的不同质数为 2、3、23、223、1223。
     最大的 3 个是 1223、223、23，和为 1469。
```

**示例 2**

```text
输入：s = "111"
输出：11
解释：不同质数只有 11（子串 "11" 出现两次，但只计一次），不足 3 个，全部求和得 11。
```

**示例 3（自造，覆盖前导零与重复）**

```text
输入：s = "011"
输出：11
解释：子串有 "0"、"1"、"1"、"01"(=1)、"11"、"011"(=11)；
     其中质数只有 11 —— 注意 "01" 与 "1" 都是 1，而 1 不是质数。
```

## 3. 解题思路

### 3.1 暴力思路

长度只有 $\le 10$，子串总数 $\frac{n(n+1)}{2} \le 55$。最直接的做法是：

1. 用两重循环枚举左右端点 $(i, j)$；
2. 把 `s[i..j]` 取出来转成整数；
3. 试除法判定质数；
4. 用一个集合去重，最后排序取前 3 个。

复杂度 $O(n^2\sqrt{V})$，其中 $V < 10^{10}$ 是子串对应的最大数值，$\sqrt{V} \approx 10^5$，总量约 $5.5\times 10^6$ 次运算——**这就是正解**，无需筛法、更不需要 Miller–Rabin。

### 3.2 核心观察：增量拼数 + 集合去重

![全部子串变成整数后去重，只留质数](images/bw157_q1_substring_enum.svg)

- **增量拼数**：固定左端点 $i$，让 $j$ 向右走，同时维护 $v \leftarrow v \times 10 + (s_j - \text{'0'})$。这样每个数值只需 $O(1)$ 更新，避免了 `substr` 的字符串复制（那会退化到 $O(n^3)$ 的字符搬运）。
- **前导零自动消失**：$v$ 从 $0$ 开始累乘，遇到 `'0'` 时 $v \leftarrow 10v$，等价于数值不变。例如 `"011"` 从下标 1 开始时得到 `0`、`1`、`11`，而 `"011"` 整段得到的是 $11$ —— 与「忽略前导零」的语义完全一致。
- **去重**：同一个质数可能来自不同子串（示例 2 的 `"11"` 出现两次、示例 1 的 `"2"` 出现两次），必须用集合而不是数组。这一条是本题最容易漏的细节。

### 3.3 算法流程

![算法流程：枚举 -> 判质 -> 集合去重 -> 取前三大](images/bw157_q1_top3_sum.svg)

```text
1. primes = 空哈希集合
2. for i = 0 .. n-1:
       v = 0
       for j = i .. n-1:
           v = v * 10 + (s[j] - '0')
           若 isPrime(v): primes.insert(v)
3. 把 primes 降序排序
4. 求和前 min(3, |primes|) 个，返回
```

### 3.4 示例演算

![演算：12234 的 15 个子串里只有 5 个质数](images/bw157_q1_example_walk.svg)

对 `s = "12234"`，全部 15 个子串中能拼出质数的只有下表几类（其余如 $1, 4, 12, 22, 34, 122, 234, 2234, 12234$ 都是合数或 $<2$）：

| 子串 | 数值 | 质数？ |
|------|------|--------|
| `"2"`（两处） | 2 | ✓ |
| `"3"` | 3 | ✓ |
| `"23"` | 23 | ✓ |
| `"223"` | 223 | ✓ |
| `"1223"` | 1223 | ✓ |
| `"22"` / `"234"` | 22 / 234 | ✗ |

集合为 $\{2, 3, 23, 223, 1223\}$，降序后取前 3 个：$1223 + 223 + 23 = 1469$，与示例 1 一致。

## 4. 算法细节

1. **增量拼数**：$v$ 在 $j$ 的循环内持续累乘，每个 `(i, j)` 只需一次乘加，是本做法的性能关键。
2. **质数判定**：从 $d = 2$ 试除到 $d^2 \le x$。用 `d * d <= x`（而不是 `d <= sqrt(x)`）既没有浮点误差，也不会像 `d * d` 那样在 `long long` 下溢出（因为 $x < 10^{10}$，$d \le 10^5$，$d^2 \le 10^{10}$ 仍在 `long long` 范围内）。
3. **$0$ 与 $1$ 特判**：`isPrime` 第一行就 `if (x < 2) return false`，否则 $0$、$1$ 会被误判（试除循环对它们直接通过）。
4. **去重结构**：C++ 用 `unordered_set<long long>`，Python 用 `set`；最后统一排序（集合无序，不能直接「取前 3 个」）。
5. **返回类型**：题目返回 `long`，最大和约 $3 \times 10^{10}$，超出 32 位整数，C++ 必须用 `long long`、Python 天然是大整数。
6. **排序方向**：降序取前 3；不要写成升序取前 3（那是**最小**的三个质数）。

## 5. 正确性证明

**引理 1（枚举完备性）**：两重循环枚举到的 `(i, j)` 与 `s` 的全部子串一一对应，且循环体内的 $v$ 恰为子串 `s[i..j]` 忽略前导零后的整数值。

**证明**：任意子串都由唯一的左端点 $i$ 和右端点 $j \ge i$ 确定，两重循环显然覆盖且仅覆盖一次。对固定的 $i$ 归纳：$j = i$ 时 $v = s_i - \text{'0'}$，即单字符串的数值；设 $j$ 时的 $v$ 等于 `s[i..j]` 的数值 $V_j$，则 $j+1$ 时 $v' = 10V_j + (s_{j+1} - \text{'0'})$，正是「在末尾追加一位数字」的十进制展开，即 `s[i..j+1]` 的数值。前导零在数值意义上不改变大小（$10 \times 0 + d = d$），故 $v$ 等于忽略前导零后的值。∎

**引理 2（判质正确性）**：`isPrime(x)` 返回真当且仅当 $x \ge 2$ 且 $x$ 只有 $1$ 与自身两个正因数。

**证明**：若 $x < 2$ 直接返回假，符合质数定义。否则若 $x$ 是合数，则存在因数分解 $x = a b$ 且 $2 \le a \le b$，于是 $a \le \sqrt{x}$，试除循环必在 $a$ 处发现整除关系并返回假；若 $x$ 是质数，则 $[2, \sqrt{x}]$ 内没有它的因数，循环跑完返回真。∎

**定理**：算法返回值等于「`s` 的所有子串对应整数中不同质数」的最大 3 项之和（不足 3 项时取全部之和）。

**证明**：由引理 1，循环结束时集合 `primes` 恰好是所有「由某子串得到的质数」构成的集合，且集合语义保证了重复质数只保留一份；由引理 2，每个数值的质数性判定正确。降序排序后前 3 项即最大的 3 个不同质数，求和即为所求；若 $|\text{primes}| < 3$，排序后全部相加与题目要求一致。∎

## 6. 复杂度分析

- **时间**：$O(n^2\sqrt{V} + P\log P)$。子串共 $\frac{n(n+1)}{2}$ 个，每个做一次 $O(\sqrt{V})$ 的试除；$P \le \frac{n(n+1)}{2}$ 为不同质数个数，排序 $O(P\log P)$。取 $n = 10$、$\sqrt V \approx 10^5$，总量约 $5.5 \times 10^6$ 次取模判断，毫秒级完成。
- **空间**：$O(P)$ 存放不同质数，$P \le 55$；此外只用了常数个临时变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long sumOfLargestPrimes(string s) {
        int n = (int)s.size();
        unordered_set<long long> primes;   // 去重：同一个质数只计一次
        for (int i = 0; i < n; i++) {
            long long v = 0;
            for (int j = i; j < n; j++) {
                v = v * 10 + (s[j] - '0'); // 前导零自然被忽略
                if (isPrime(v)) primes.insert(v);
            }
        }
        vector<long long> all(primes.begin(), primes.end());
        sort(all.begin(), all.end(), greater<long long>());
        long long ans = 0;
        for (int i = 0; i < (int)all.size() && i < 3; i++) ans += all[i];
        return ans;
    }

private:
    bool isPrime(long long x) {
        if (x < 2) return false;
        for (long long d = 2; d * d <= x; d++) {
            if (x % d == 0) return false;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def sumOfLargestPrimes(self, s: str) -> int:
        primes = set()
        n = len(s)
        for i in range(n):
            v = 0
            for j in range(i, n):
                v = v * 10 + int(s[j])   # 前导零自然被忽略
                if self._is_prime(v):
                    primes.add(v)
        return sum(sorted(primes, reverse=True)[:3])

    def _is_prime(self, x: int) -> bool:
        if x < 2:
            return False
        d = 2
        while d * d <= x:
            if x % d == 0:
                return False
            d += 1
        return True
```

## 8. 边界情况与易错点

1. **$0$ 和 $1$ 不是质数**：`s = "0"` 或 `s = "1"` 时答案应为 $0$，`isPrime` 必须先判 `x < 2`。
2. **重复质数只算一次**：`s = "111"` 中 `"11"` 出现两次；示例 1 中 `"2"` 出现两次。用集合而非列表。
3. **前导零**：`s = "011"` 时 `"011"` 的数值是 $11$；增量拼数天然处理，但若改用 `substr + stoll` 需要自己注意（`stoll` 其实也忽略前导零，`stoi` 会抛异常的地方要注意长度）。
4. **不足 3 个质数**：示例 2 只有 1 个，必须返回全部之和，不能返回 $-1$ 或 $0$。
5. **升序 / 降序**：要的是**最大** 3 个，排序方向写反会得到最小的 3 个。
6. **整数类型**：最大子串值可到 $9\,999\,999\,999$（10 位全是 9），超出 32 位，C++ 必须 `long long`。
7. **`d * d <= x` 溢出**：本题 $x < 10^{10}$、$d \le 10^5$，不会溢出；若值域扩大到 $10^{18}$，应改成 `d <= x / d`。
