# LeetCode 设置时间的最少代价 题解

## 1. 题目概述

- **标题 / 题号**：设置时间的最少代价（#2162，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-set-cooking-time/
- **来源**：LeetCode 第 71 场双周赛 Q3
- **难度**：中等
- **标签**：数学、枚举、模拟

**题意**：微波炉加热时间用**至多 4 个数字**输入，不足 4 位自动**补前导 0**；前两位是分钟、后两位是秒（秒可达 99，1 分钟 = 60 秒）。手指初始在数字 $startAt$ 上：移到**不同**数字花费 $moveCost$，每按一次当前数字花费 $pushCost$。要求把加热时长设为恰好 $targetSeconds$ 秒，求最小总代价。

**约束**：

- $0 \le startAt \le 9$；
- $1 \le moveCost, pushCost \le 10^5$；
- $1 \le targetSeconds \le 6039$（即至多 99 分 99 秒）。

## 2. 示例

**示例 1**

```text
输入：startAt = 1, moveCost = 2, pushCost = 1, targetSeconds = 600
输出：6
解释：输入 1 0 0 0（10 分 0 秒）：按 1（+1）、移到 0（+2）、按 0/0/0（+3），共 6。
      对照 9 6 0（09:60，同为 600 秒）需 2+1+2+1+2+1 = 9；0 9 6 0 需 12。
```

**示例 2**

```text
输入：startAt = 0, moveCost = 1, pushCost = 2, targetSeconds = 76
输出：6
解释：输入 7 6（1 分 16 秒 = 76 秒）：移到 7（+1）、按 7（+2）、移到 6（+1）、按 6（+2），共 6。
```

**示例 3（边界补充）**

```text
输入：startAt = 9, moveCost = 100000, pushCost = 1, targetSeconds = 6039
输出：4
解释：6039 = 99 分 99 秒，唯一合法分解，按键串 9999。startAt = 9 与首位相同，
      全程无需移动，总代价 = 4 × 1 = 4。
```

> ⚠️ 示例 3 提醒两件事：$targetSeconds = 6039$ 只有 $99{:}99$ 一种合法分解；$startAt$ 与首个按键相同时**不需要移动**。

## 3. 解题思路

### 3.1 暴力思路

枚举一切长度 $1 \sim 4$ 的按键串（$10 + 100 + 1000 + 10000 \approx 10^4$ 个），逐个算「补前导 0 后表示的秒数是否等于 $targetSeconds$」再求代价——$O(10^4 \times 4)$ 可行但笨拙，且容易在「显示语义」上绕晕。正确姿势是**先枚举显示值，再反推按键串**。

### 3.2 核心观察：先枚举 mm:ss 分解，再去前导 0 得按键串

![按键代价模型：移动与按下两种成本](images/bw71_q3_keypad_cost_model.svg)

**第一层枚举（时间分解）**：设显示为 $mm$ 分 $ss$ 秒，则

$$
60 \times mm + ss = targetSeconds, \quad 0 \le mm \le 99, \quad 0 \le ss \le 99.
$$

由 $ss = targetSeconds - 60 \times mm \in [0, 99]$ 可知 $mm$ 的合法取值**至多 2 个**（相差 1：向 $ss$ 「借」一次 60 秒的余地只有 $[0,99]$ 共 100 的宽度，而步长是 60）。所以合法分解只有 $1 \sim 2$ 种，枚举空间极小。

**第二层（按键串自动确定）**：显示四位是 $mm \times 100 + ss$ 的 4 位零填充。但**实际按下**的数字串是它去掉前导 0 后的形式——例如显示 $0954$ 只需按 $9,5,4$ 三个键，省一次 $pushCost$。因此按键串 $s = \text{str}(mm \times 100 + ss)$。

**第三层（代价公式）**：从 $startAt$ 出发逐位模拟：

$$
\text{cost}(s) = |s| \times pushCost + \left(\#\{\text{相邻不同位对}\} \cup \{\text{首位} \ne startAt\}\right) \times moveCost.
$$

![枚举 mm 的两种借位分解](images/bw71_q3_decompose_flow.svg)

### 3.3 算法流程

```text
best = +∞
for mm in [0, 99]:
    ss = targetSeconds - 60*mm
    if 0 <= ss <= 99:                     # 合法分解
        s = str(mm*100 + ss)              # 去前导 0 的按键串
        cost = 0; finger = startAt
        for c in s:
            d = int(c)
            if d != finger: cost += moveCost; finger = d
            cost += pushCost
        best = min(best, cost)
return best
```

### 3.4 示例演算

![示例演算：600 秒的三种方案对比](images/bw71_q3_example_walkthrough.svg)

以示例 1（$startAt=1, moveCost=2, pushCost=1, target=600$）：

- **分解一** $10{:}00$：按键串 `1000`。按 1（+1）→ 移 0（+2）→ 按 0×3（+3），合计 $6$。
- **分解二** $09{:}60$：按键串 `960`。移 9（+2）→ 按 9（+1）→ 移 6（+2）→ 按 6（+1）→ 移 0（+2）→ 按 0（+1），合计 $9$。
- 同一显示全按 `0960` 则为 $12$（前导 0 白按一次还多一次移动）。

三者取最小，答案 $6$。

## 4. 算法细节

1. **$mm$ 的循环范围**：直接 $[0, 99]$ 全枚举最省心（只有 100 次迭代），也可只试 $targetSeconds / 60$ 向下取整的两个候选 $m_0 = \lfloor target/60 \rfloor$ 与 $m_0 - 1$（当 $m_0 \le 99$ 时前者给 $ss \in [0, 59]$，后者给 $ss \in [60, 119]$ 需截断到 $\le 99$）。
2. **去前导 0 用数值**：`to_string(mm * 100 + ss)` 天然无前导 0（当 $mm = ss = 0$ 时串为 `"0"`，长度 1；但题目保证 $targetSeconds \ge 1$，不会出现全 0）。
3. **首位移动判定**：初始手指在 $startAt$，若按键串首字符对应数字 $\ne startAt$ 需先付一次 $moveCost$；**相等则免费**。连续相同数字（如 `1000` 的三个 0）只付一次移动。
4. **溢出**：$|s| \le 4$、$pushCost \le 10^5$、移动次数 $\le 4$、$moveCost \le 10^5$，总代价 $\le 8 \times 10^5$，`int` 足够。
5. **为什么不用枚举「少按键数」以外的策略**：对固定显示值，按更少键（去前导 0）严格不劣——少付 $pushCost$ 且移动次数只会不变或减少（前导 0 的按下要么省掉一次移动，要么多一次）。

## 5. 正确性证明

**引理 1（分解有限）**：所有能显示为 $targetSeconds$ 秒的 $mm{:}ss$ 组合恰为 $\{(m, targetSeconds - 60m) : 0 \le m \le 99,\ 0 \le targetSeconds - 60m \le 99\}$，且该集合大小 $\le 2$。

**证明**：显示语义即 $60m + s = targetSeconds$。$s$ 被 $m$ 唯一确定，条件 $s \in [0, 99]$ 等价于 $\lceil (targetSeconds - 99)/60 \rceil \le m \le \lfloor targetSeconds/60 \rfloor$，该整数区间长度 $\le \lfloor 99/60 \rfloor + 1 = 2$。∎

**引理 2（最优按键串）**：对固定显示值 $v = mm \times 100 + ss$，代价最小的按键串是 $\text{str}(v)$（即去掉前导 0 的最短按键串）。

**证明**：任何按键串 $t$ 若被微波炉解释为 $v$，则 $t$ 的各位（含前导 0 补齐后）必须与 $v$ 的 4 位零填充逐位一致，故 $t$ 是该 4 位串的**前缀删除若干前导 0** 的结果；最短的此类串即删除全部前导 0，得 $\text{str}(v)$。对串 $t'$ 与其延长串 $t$（在 $t'$ 前多按若干个 0）：按下次数多 $k \ge 1$ 次付 $k \times pushCost > 0$；移动次数上，多出的前导 0 至多引入与后继位相同的一次移动（若后继非 0 还要额外一次移回），故移动代价不减。总代价严格更大或相等，且当 $pushCost \ge 1$ 时严格更大当 $k \ge 1$。∎

**定理**：算法返回值是设置 $targetSeconds$ 秒的最小代价。

**证明**：任一可行方案对应一个按键串与一个显示值；显示值必须满足引理 1 的分解，按键串中代价最小者由引理 2 给出。算法枚举全部（$\le 2$ 个）合法分解、对每个分解取最优按键串的代价、再取最小，故覆盖了所有可行方案的最优值。∎

## 6. 复杂度分析

- **时间**：$O(1)$。外层至多 100 次迭代（有效 $\le 2$ 次），每次模拟 $\le 4$ 位按键。
- **空间**：$O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCostSetTime(int startAt, int moveCost, int pushCost, int targetSeconds) {
        long long best = LLONG_MAX;
        for (int mm = 0; mm <= 99; ++mm) {
            int ss = targetSeconds - mm * 60;
            if (ss < 0 || ss > 99) continue;      // 该 mm:ss 分解不合法
            string seq = to_string(mm * 100 + ss); // 去掉前导 0 的按键序列
            long long cost = 0;
            int finger = startAt;
            for (char c : seq) {
                int d = c - '0';
                if (d != finger) { cost += moveCost; finger = d; }
                cost += pushCost;
            }
            best = min(best, cost);
        }
        return (int)best;
    }
};
```

### Python

```python
class Solution:
    def minCostSetTime(self, startAt: int, moveCost: int, pushCost: int, targetSeconds: int) -> int:
        best = None
        for mm in range(100):
            ss = targetSeconds - mm * 60
            if ss < 0 or ss > 99:                 # 该 mm:ss 分解不合法
                continue
            seq = str(mm * 100 + ss)              # 去掉前导 0 的按键序列
            cost, finger = 0, str(startAt)
            for ch in seq:
                if ch != finger:
                    cost += moveCost
                    finger = ch
                cost += pushCost
            best = cost if best is None else min(best, cost)
        return best
```

> 💡 两份代码均通过官方示例（`6`、`6`）、$target \in [1, 300]$ 全量 + 400 组随机参数与「枚举一切长度 $\le 4$ 按键串」语义级暴力（含补前导 0 显示判定）的对拍共 700 组，`mismatch = 0`；另跑通 $target \in [1, 6039]$ 全部 6039 个值的双语一致性。

## 8. 边界情况与易错点

1. **借位分解别漏**：600 秒有 $10{:}00$ 与 $09{:}60$ 两种分解；只按 $target/60$ 直除会漏掉借位解，而借位解在「按键串更短」（如 `960` 只有 3 位）时可能更优。
2. **$ss$ 的合法区间是 $[0, 99]$ 不是 $[0, 59]$**：微波炉允许 99 秒，这是借位可行的前提；但 $ss \ge 100$ 或 $ss < 0$ 必须跳过。
3. **前导 0 的省与不省**：`to_string(mm * 100 + ss)` 自动去掉前导 0。若手写补零逻辑（如 `%02d%02d` 再裁剪），裁剪边界极易出错。
4. **首位与 $startAt$ 相同免移动**：例如 $startAt = 9$、按 `9999`，移动次数为 0。逐位模拟写法天然正确，公式写法（统计相邻不同对）要把「首位 vs $startAt$」单独并入。
5. **$targetSeconds = 6039$**：唯一分解 $99{:}99$，不存在任何借位选择，最小代价就是该串的代价。
6. **别把分钟上界写成 59**：显示允许 $mm \le 99$（99 分 99 秒 = 6039 秒 > 6039? 恰好等于），循环上界 99 别手滑写 59。
