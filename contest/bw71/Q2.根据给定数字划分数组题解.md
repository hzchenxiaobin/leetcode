# LeetCode 根据给定数字划分数组 题解

## 1. 题目概述

- **标题 / 题号**：根据给定数字划分数组（#2161，medium）
- **链接**：https://leetcode.cn/problems/partition-array-according-to-given-pivot/
- **来源**：LeetCode 第 71 场双周赛 Q2
- **难度**：中等
- **标签**：数组、双指针、模拟、稳定划分

**题意**：给定整数数组 $nums$ 与整数 $pivot$（保证 $pivot$ 在 $nums$ 中出现）。重排 $nums$ 使得：

1. 所有**小于** $pivot$ 的元素都在所有**大于** $pivot$ 的元素之前；
2. 所有**等于** $pivot$ 的元素夹在两者**中间**；
3. 小于段内部、大于段内部的**相对顺序**与原数组一致（稳定）。

返回重排后的数组。

**约束**：

- $1 \le nums.length \le 10^5$；
- $-10^6 \le nums[i] \le 10^6$；
- $pivot$ 等于 $nums$ 中的某个元素（等于段非空）。

## 2. 示例

**示例 1**

```text
输入：nums = [9,12,5,10,14,3,10], pivot = 10
输出：[9,5,3,10,10,12,14]
解释：小于段 [9,5,3]、等于段 [10,10]、大于段 [12,14]，各自保持原相对顺序。
```

**示例 2**

```text
输入：nums = [-3,4,3,2], pivot = 2
输出：[-3,2,4,3]
解释：小于段 [-3]，等于段 [2]，大于段 [4,3]（注意 4 在 3 前的原顺序）。
```

**示例 3（边界补充）**

```text
输入：nums = [5,5,5], pivot = 5
输出：[5,5,5]
解释：全部等于 pivot，小于段与大于段均为空。
```

## 3. 解题思路

### 3.1 暴力思路

对 $nums$ 做**稳定排序**，比较函数为「按 $x$ 与 $pivot$ 的大小关系三值排序」（$x < pivot$ 记 0、$= $ 记 1、$>$ 记 2），$O(n \log n)$ 能过；或者三重循环逐段挑元素，$O(n^2)$ 在 $n = 10^5$ 下约 $10^{10}$ 次操作，超时。两种做法都没有利用「只有三个桶」这一结构——本题其实一趟线性扫描就够了。

### 3.2 核心观察：三桶收集，天然稳定

![三段稳定划分：小于/等于/大于三段拼接](images/bw71_q2_three_way_partition.svg)

把每个元素按与 $pivot$ 的比较结果丢进三个列表 $less$、$equal$、$greater$。由于**扫描按原顺序进行、append 到列表尾部**，每个桶内的元素序列就是它们在原数组中出现的顺序——稳定性免费获得。最终答案即 $less + equal + greater$ 的拼接。「等于段」夹在中间的语义由拼接顺序直接保证。

### 3.3 算法流程（附一趟扫描变体）

![一趟扫描三分：写指针的分段接力写法](images/bw71_q2_onepass_flow.svg)

```text
版本一（三列表，最直观）：
1. 扫描 nums：x < pivot 入 less；x == pivot 入 equal；x > pivot 入 greater
2. 返回 less + equal + greater

版本二（一趟扫描 + 原地写）：
1. 第一遍统计 cntLess（小于个数）、cntEq（等于个数）
2. 第二遍：x < pivot 写到 res[i++]（i 从 0 起）；
   x == pivot 记数；x > pivot 暂存列表
3. res[cntLess .. cntLess+cntEq) 填 pivot，末尾接上大于段
```

版本二把「等于段」整体压缩成一次区间填充（值都相同，无所谓顺序），只有大于段需要暂存，可进一步省成「倒序写入尾部」的原地 $O(1)$ 额外空间版本：第二遍扫描时把大于段从右往左写到 $res[n-1], res[n-2], \dots$，小于段从左往右写，等于段自动留在中间。这就是**荷兰国旗问题的稳定版**。

### 3.4 示例演算

以示例 1（$nums = [9,12,5,10,14,3,10]$，$pivot = 10$）走版本一：

| 元素 | 比较 | 落桶 |
|------|------|------|
| 9 | $9 < 10$ | $less = [9]$ |
| 12 | $12 > 10$ | $greater = [12]$ |
| 5 | $5 < 10$ | $less = [9,5]$ |
| 10 | $= 10$ | $equal = [10]$ |
| 14 | $> 10$ | $greater = [12,14]$ |
| 3 | $< 10$ | $less = [9,5,3]$ |
| 10 | $= 10$ | $equal = [10,10]$ |

拼接得 $[9,5,3] + [10,10] + [12,14] = [9,5,3,10,10,12,14]$。大于段 $[12,14]$ 中 12 先于 14 出现，与原数组一致。

## 4. 算法细节

1. **为什么必须三桶而不是两桶**：等于段有固定「居中」语义，若把等于并入小于段（或大于段），大于（小于）元素会跑到错误的一侧。
2. **稳定性来源**：遍历顺序 = 原数组顺序，append 保序。任何「先收集再排序」的写法都要显式保证稳定比较键，反而绕远。
3. **原地双指针版本的下标推算**：小于段写指针 $i$ 从 $0$ 起；大于段写指针 $j$ 从 $n-1$ 起**倒着写**；扫完后 $[i, j]$ 闭区间内剩余位置恰好 $cntEq$ 个，全填 $pivot$。倒序写大于段同样保序（第 $t$ 个遇到的大于元素写到 $n-t$，先遇到的位置更大，仍保持相对顺序）。
4. **拼接实现**：C++ 用 `insert` 三次（$O(n)$ 总移动）；Python 用列表 `+` 直接拼接。
5. **数据规模**：$n \le 10^5$，$O(n)$ 时空都宽裕；不需要担心 $nums[i]$ 的值域，比较只有三种结果。

## 5. 正确性证明

**引理 1（桶内保序）**：按原数组顺序把元素 append 到某列表，列表内元素的相对顺序与原数组一致。

**证明**：设 $x$ 与 $y$ 是同桶元素，$x$ 在原数组中下标 $i < j$（即 $y$ 的下标）。扫描按 $i < j$ 顺序访问，$x$ 先 append，故列表中 $x$ 位于 $y$ 之前。∎

**引理 2（三段布局合法）**：拼接 $less + equal + greater$ 后，条件 1 与条件 2 成立。

**证明**：小于段所有元素来自 $less$，位于结果前 $|less|$ 位；大于段位于结果后 $|greater|$ 位；两者之间是等于段。故任意小于元素的位置 $<$ 任意大于元素的位置（条件 1），且任意等于元素位置介于两者之间（条件 2）。∎

**定理**：三桶收集再拼接的输出是满足全部条件的一个合法重排。

**证明**：三桶按比较结果划分，$nums$ 的每个元素恰进入一个桶，输出是 $nums$ 的一个排列（多重集合相同）。由引理 2 知布局条件满足；由引理 1 知小于段、大于段内部相对顺序与原数组一致；等于段所有元素相同，其内部顺序无约束。故输出合法。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟扫描 + 一次拼接，每个元素 $O(1)$ 处理。
- **空间**：$O(n)$。三个桶（或结果数组）合计存 $n$ 个元素；原地双指针版本可降到 $O(1)$ 额外空间（不计输出数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> pivotArray(vector<int>& nums, int pivot) {
        vector<int> less, equal, greater;
        for (int x : nums) {
            if (x < pivot) less.push_back(x);
            else if (x == pivot) equal.push_back(x);
            else greater.push_back(x);
        }
        less.insert(less.end(), equal.begin(), equal.end());
        less.insert(less.end(), greater.begin(), greater.end());
        return less;
    }
};
```

### Python

```python
class Solution:
    def pivotArray(self, nums: list[int], pivot: int) -> list[int]:
        less, equal, greater = [], [], []
        for x in nums:
            if x < pivot:
                less.append(x)
            elif x == pivot:
                equal.append(x)
            else:
                greater.append(x)
        return less + equal + greater
```

> 💡 两份代码均通过官方示例（`[9,5,3,10,10,12,14]`、`[-3,2,4,3]`）、500 组随机输入与「独立校验器」（布局合法性 + 两段稳定性逐位核对）的对拍，`mismatch = 0`；$n = 10^5$ 规模 C++ 0.13s / Python 0.09s。

## 8. 边界情况与易错点

1. **全部元素等于 $pivot$**：小于、大于两段为空，输出原数组。别在「段为空」上做特殊分支，拼接逻辑天然兼容。
2. **$pivot$ 是最小值 / 最大值**：小于段或大于段为空，同样无需特判（题目保证 $pivot$ 出现过，等于段至少 1 个元素）。
3. **稳定性别用 `sort` 破坏**：若写 `sort(key=lambda x: 0 if x<pivot else (1 if x==pivot else 2))`，必须确认所用排序稳定（Python 的 Timsort 稳定，C++ `std::sort` **不稳定**，需 `stable_sort`）。
4. **负数与值域**：$nums[i]$ 可为 $-10^6$，比较逻辑不受影响；不要假设非负。
5. **$n = 1$**：唯一元素即 $pivot$，输出不变。
6. **别遗漏「等于段计数」**（版本二）：等于元素无需暂存（值全同），但个数要数对，否则中间段长度错误。

**延伸思考**：本题是**稳定划分（stable partition）**的直接考察。C++ 标准库有 `std::stable_partition`，一趟调用即可 AC，但它内部为保序可能付出 $O(n)$ 额外空间（或无额外空间时的 $O(n \log n)$ 时间分治）；「三值 + 稳定」是它的一次具体化。更进一步的思考：若要求**所有四段**（$<, =, >$ 之外再按另一关键字 $k$ 细分）且全稳定，就进入**基数排序 / 计数排序**的领地——本质都是「按关键字的桶收集，桶间有序、桶内保序」。
