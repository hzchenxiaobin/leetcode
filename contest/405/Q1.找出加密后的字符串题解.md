# LeetCode 找出加密后的字符串 题解

## 1. 题目概述

- **标题 / 题号**：找出加密后的字符串（#3210，easy）
- **链接**：https://leetcode.cn/problems/find-the-encrypted-string/
- **来源**：LeetCode 第 405 场周赛 Q1
- **难度**：简单
- **标签**：字符串、数学

**题意**：给定字符串 `s` 与整数 `k`，把 `s` 中每个字符 `c` 替换为它**后面的第 `k` 个字符**（以**循环**方式——越过末尾从开头绕回），返回加密后的字符串。

**约束**：

- $1 \le s.length \le 100$
- $1 \le k \le 10^4$
- `s` 仅由小写英文字母组成

> 💡 读题关键：①「后面的第 $k$ 个」从自身往后数 $k$ 步（不含自身），即下标 $i$ 换成 $i+k$；②「循环」= 下标对 $n$ 取模；③ $k$ 上限 $10^4$ 是 $n$ 上限 $100$ 的 100 倍——**会绕好几圈**，这正是命题人埋的唯一考点。

## 2. 示例

**示例 1**

```text
输入：s = "dart", k = 3
输出："tdar"
解释：
- i=0：'d' 后面的第 3 个字符是 't'（d→a→r→t）
- i=1：'a' 后面的第 3 个字符是 'd'（a→r→t→绕回首）
- i=2：'r' 后面的第 3 个字符是 'a'
- i=3：'t' 后面的第 3 个字符是 'r'
```

**示例 2**

```text
输入：s = "aaa", k = 1
输出："aaa"
解释：字符全相同，无论怎么绕结果都一样。
```

**补充示例（k > n，绕圈情形）**

```text
输入：s = "dart", k = 5
输出："artd"
解释：5 = 4 + 1：绕一整圈回到原点、只多走 1 步，等价于 k = 1，
      即 res[i] = s[(i+5) mod 4] = s[(i+1) mod 4] → "artd"
```

## 3. 解题思路

### 3.1 暴力思路

对每个位置 $i$，从 $j = i$ 出发老老实实走 $k$ 步，每步 $j \leftarrow (j+1) \bmod n$，走完的落点就是替换字符。总复杂度 $O(nk)$，代入上限 $n = 100$、$k = 10^4$ 约 $10^6$ 步，**能过但纯属浪费**：走满一整圈 $n$ 步等于原地不动，$k$ 步里绝大部分是整圈重复劳动。

### 3.2 核心观察：环上瞬移 $(i+k) \bmod n$

![核心观察：循环走 k 步等价于一次取模瞬移](images/w405_encrypt_ring_concept.svg)

**观察 1（落点公式）**：把字符串首尾相接看成一个环，从 $i$ 往后走 $k$ 步的落点就是 $(i+k) \bmod n$——「循环往后走 $k$ 步」这个动作已经被取模运算**完整编码**，不需要真走、直接瞬移：

$$res[i] = s[(i+k) \bmod n]$$

**观察 2（先消整圈）**：绕一整圈回到原点，真正起作用的只有余数 $k \bmod n$。先做 `k %= n` 把 $k$ 压进 $[0, n)$，顺带暴露一个边界结论：**若 $k \bmod n = 0$，每个字符都被自己替换，结果就是原串**。

**观察 3（整体左旋视角）**：所有位置统一前移 $r = k \bmod n$，等价于把字符串**整体左旋 $r$ 位**——前 $r$ 个字符整体搬到尾部：

$$res = s[r:] + s[:r]$$

这是 Python 一行切片的依据（但必须先 `k %= n`，否则翻车，见 §8 的现场）。

### 3.3 算法流程

![算法流程：先消整圈，再单趟瞬移填表](images/w405_encrypt_flow.svg)

```text
1. n = len(s)，k %= n          ← 消掉整圈，k 压进 [0, n)
2. for i = 0 .. n-1:
3.     res[i] = s[(i + k) % n] ← O(1) 瞬移到落点
4. 返回 res
```

### 3.4 示例演算

![示例演算：s = "dart", k = 3 的逐步走查](images/w405_encrypt_walkthrough.svg)

以 `s = "dart"`、$k = 3$、$n = 4$ 为例：

| $i$ | $i+k$ | $(i+k) \bmod 4$ | 取到的字符 | res 累积 |
|-----|-------|-----------------|-----------|---------|
| 0   | 3     | 3               | `t`       | `"t"`   |
| 1   | 4     | **0**（绕回）   | `d`       | `"td"`  |
| 2   | 5     | **1**（绕回）   | `a`       | `"tda"` |
| 3   | 6     | **2**（绕回）   | `r`       | `"tdar"`|

结果为 **`"tdar"`**。后三行 $i+k$ 越过末尾、取模后从头绕回——正是「循环方式」的体现。切片视角：$s[3:] + s[:3] =$ `"t" + "dar"` $=$ `"tdar"`，与逐位取模严丝合缝。

## 4. 算法细节

1. **落点公式的来历**：「后面的第 1 个字符」是 $s[(i+1) \bmod n]$，第 2 个是 $s[(i+2) \bmod n]$，归纳即得第 $k$ 个是 $s[(i+k) \bmod n]$——把题面自然语言**逐词映射**成下标运算：「往后数 $k$ 步」= $+k$，「循环」= $\bmod\; n$，本题的全部内容就这两条。
2. **`k %= n` 何时必须**：对逐位取模写法，`(i+k) % n` 本身已含取模，`k %= n` 只是让加法更小（$i + k \le 10099$，`int` 毫无压力），属于习惯性预处理；但对 Python **切片**写法它是**生死攸关**的一步（见 §8）。若 $k$ 达到 `long long` 级别或题目改成「拼接 $k$ 份字符串」，先取余则是必须的防溢出手段。
3. **两种实现完全等价**：C++ 逐位 `res[i] = s[(i+k)%n]` 与 Python `s[k:]+s[:k]` 输出一致——前者保留通用的「目标位置 ← 源位置」逐位映射写法（可推广到任意置换，如 1528），后者利用本题映射的特殊结构（统一平移）做批量搬运。
4. **这是一个保位置换**：$\sigma(i) = (i+k) \bmod n$ 是下标集上的**双射**（证明见 §5 引理 2），字符只是整体挪了位置、频次完全不变——所以 `"aaa"` 怎么加密都还是 `"aaa"`，也说明这种「加密」毫无混淆性。

## 5. 正确性证明

**引理 1（落点公式）**：从下标 $i$ 出发在环上往后走 $k$ 步，落点下标为 $(i+k) \bmod n$。

**证明**：作带余除法 $k = qn + r$（$0 \le r < n$）。每走一步下标增加 $1$（模 $n$），故走 $n$ 步共增加 $n \equiv 0 \pmod n$，回到出发点。于是走 $qn$ 步后仍停在 $i$，剩余 $r$ 步把下标推进到 $(i + r) \bmod n$。又 $k \equiv r \pmod n$，故 $(i + k) \bmod n = (i + r) \bmod n$，落点即 $(i+k) \bmod n$。∎

**引理 2（双射性）**：映射 $\sigma(i) = (i+k) \bmod n$ 是 $\{0, 1, \dots, n-1\}$ 上的双射。

**证明**：若 $\sigma(i) = \sigma(j)$，则 $i + k \equiv j + k \pmod n$，即 $i \equiv j \pmod n$；由 $0 \le i, j < n$ 得 $i = j$，故 $\sigma$ 单射。单射映射把 $n$ 元有限集映入 $n$ 元有限集必为双射。∎

**定理**：算法输出恰为逐字符按题意替换的结果，且等于 $s$ 循环左旋 $k \bmod n$ 位后的串。

**证明**：由引理 1，位置 $i$ 的替换字符恰为 $s[(i+k) \bmod n]$，与题意逐字对应；由引理 2，$i$ 遍历 $0..n-1$ 时源下标不重复、不遗漏地取遍全体下标，每个 `s[j]` 恰被使用一次，结果串良定义。记 $r = k \bmod n$：当 $i < n - r$ 时 $res[i] = s[i + r]$；当 $i \ge n - r$ 时 $res[i] = s[i + r - n]$。故 $res = s[r..n-1] + s[0..r-1]$，即 $s$ 左旋 $r$ 位。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。预处理 `k %= n` 为 $O(1)$；单趟扫描，每个位置一次加法、一次取模、一次赋值。
- **空间复杂度**：$O(n)$。结果串本身（若语言允许原地覆盖且 $r$ 与 $n$ 互质可做到 $O(1)$，见延伸思考）；Python 切片产生两个总长 $n$ 的子串，同为 $O(n)$。
- **暴力对照**：$O(nk)$，上限约 $10^6$ 步也能过——但这题数据范围的暗示（$k \gg n$）本身就是在提醒你消掉整圈。

## 7. 参考代码

### C++（逐位取模填表）

```cpp
class Solution {
public:
    string getEncryptedString(string s, int k) {
        int n = s.size();
        k %= n;                       // 消掉整圈，k 压进 [0, n)
        string res(n, ' ');
        for (int i = 0; i < n; i++) {
            res[i] = s[(i + k) % n];  // 环上瞬移：一步定位落点
        }
        return res;
    }
};
```

### Python（切片一行流）

```python
class Solution:
    def getEncryptedString(self, s: str, k: int) -> str:
        k %= len(s)           # 必须先取模！切片不会替你绕圈
        return s[k:] + s[:k]  # 整体左旋 k 位
```

## 8. 边界情况与易错点

1. **Python 切片不先取模必错**：$k = 5$、`s = "dart"` 时直接 `s[5:] + s[:5]` 得 `"" + "dart" = "dart"`，而正确答案是 `"artd"`（$5 \bmod 4 = 1$）——切片语义里下标越界**静默截断**，不会绕圈。务必先 `k %= len(s)` 再切片。
2. **$k \bmod n = 0$**：绕整圈回到自己，结果为原串。逐位取模天然正确（$(i+0) \bmod n = i$）；切片 `s[0:] + s[:0]` 也拼回原串——均无需特判。
3. **$k > n$ 是常态而非边界**：约束刻意让 $k$ 上限是 $n$ 上限的 100 倍，考的就是「会不会取模」；只模拟不取模虽 $O(nk)$ 能过，但没读懂出题意图。
4. **「后面的第 $k$ 个」不含自身**：从 $c$ 数起，往后第 1 个是 $i+1$、第 $k$ 个是 $i+k$；理解成 $i + k + 1$ 会整体偏移一位。
5. **$n = 1$**：任何 $k$ 模 1 均为 0，返回原串，循环写法自然覆盖、无需特判。
6. **C++ 负数取模**：本题 $i, k$ 均非负，`(i+k) % n` 不可能为负；若题面改成「往前第 $k$ 个」（$i - k$ 可能为负），才需要 $((i - k) \% n + n) \% n$ 的防负技巧——判断标准是「表达式可能为负吗」，而不是无脑加 $n$。
