# LeetCode 找出最小平衡下标 题解

## 1. 题目概述

- **标题 / 题号**：找出最小平衡下标（#3862，medium）
- **链接**：https://leetcode.cn/problems/find-the-smallest-balanced-index/
- **来源**：LeetCode 第 492 场周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和、后缀积

**题意**：给定整数数组 `nums`。下标 $i$ 是**平衡下标**，当且仅当 **$i$ 左侧所有元素之和**等于 **$i$ 右侧所有元素之积**（两侧均不含 $nums[i]$ 本身）。左侧为空时和视为 $0$，右侧为空时积视为 $1$。返回**最小**的平衡下标；不存在则返回 $-1$。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,2]
输出：1
解释：i = 1 时左侧和 = 2，右侧积 = 2，相等；i = 0 时左侧和 0 ≠ 右侧积 1×2 = 2，故最小平衡下标是 1。
```

**示例 2**

```text
输入：nums = [2,8,2,2,5]
输出：2
解释：i = 2 时左侧和 = 2+8 = 10，右侧积 = 2×5 = 10，相等。
```

**示例 3**

```text
输入：nums = [1]
输出：-1
解释：i = 0 时左侧和 = 0（空），右侧积 = 1（空），0 ≠ 1，不存在平衡下标。
```

**补充示例（覆盖空积约定）**

```text
输入：nums = [1,5]
输出：1
解释：i = 1 时左侧和 = 1，右侧积 = 1（空积约定），相等——「右侧空积是 1 不是 0」是本题一个考点。
```

## 3. 解题思路

### 3.1 朴素思路

对每个下标 $i$ 现场求左侧和与右侧积再比较：$O(n)$ 个下标 × 每处 $O(n)$ 次运算 = $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次运算，必然超时。

更致命的是**右侧积是大数**：$10^5$ 个高达 $10^9$ 的因子相乘，真实乘积可达 $10^{9 \times 10^5}$，即一个约 **90 万位**的十进制数。即便用 Python 大整数硬算，乘法按位数付费，总代价是 $O(n^2)$ 量级的字级操作——这是继循环次数之后的第二重爆炸。

### 3.2 核心观察：前缀和 × 后缀积，配合「超限封顶」

本题是「中心下标」（左侧和 = 右侧和）的变体：右边的**和**换成了**积**。两边的量都能 $O(1)$ 递推：

- **前缀和**（从左往右）：$L(i) = nums[0] + \cdots + nums[i-1]$，且 $L(i+1) = L(i) + nums[i]$；
- **后缀积**（从右往左）：$R(i) = nums[i+1] \times \cdots \times nums[n-1]$，且 $R(i) = nums[i+1] \times R(i+1)$。

![核心观察：左边求和、右边求积，双向递推](images/wc492_q2_prefix_suffix_model.svg)

后缀积直接递推仍会溢出 / 大数爆炸，突破口是两个条件的**组合**：

> 💡 **封顶观察**：左侧和有上界——$L(i) \le (n-1) \times 10^9 < 10^{14}$；而元素全 $\ge 1$，从右往左递推时 $R(i) = nums[i+1] \times R(i+1) \ge R(i+1)$，**真实后缀积单调不减**。于是：一旦某步真实积超过 $10^{14}$，它就不可能等于任何左侧和，且之后只会更大、**永远回不来**——可以放心封顶为哨兵 $\text{INF} = 10^{14} + 1$，此后一路保持 $\text{INF}$。

![封顶观察：超限戴帽，永不回头](images/wc492_q2_cap_product.svg)

如此一来所有「数值」都是小整数：真实值 $\le 10^{14}$ 时保留精确值，否则记 $\text{INF}$。C++ 中配合整除预检 $r > \text{LIMIT} \,/\, nums[i+1]$ 先判断再乘，乘法永远不会溢出 `long long`。

> ⚠️ **方向别搞反**：封顶只对「**从右往左**（不断乘上因子）」的递推方向合法。封顶值不能「除回去」恢复左边的真值——信息已经丢失；好在单调性保证超限即永远超限，根本不需要回头。

### 3.3 算法流程

1. **第一趟（从右往左）**：令 $R[n-1] = 1$（空积约定）。对 $i = n-2 \dots 0$：若 $R[i+1] > \text{LIMIT} \,/\, nums[i+1]$（整除），令 $R[i] = \text{INF}$；否则令 $R[i] = nums[i+1] \times R[i+1]$（此乘积 $\le \text{LIMIT}$，精确）。
2. **第二趟（从左往右）**：维护前缀和 $L = 0$。对每个 $i$：若 $L = R[i]$，立即返回 $i$（第一个命中即最小）；否则 $L \mathrel{+}= nums[i]$。
3. 两趟结束仍未命中，返回 $-1$。

### 3.4 示例演算

![示例演算：两列相向递推](images/wc492_q2_example_walkthrough.svg)

以 $[2,8,2,2,5]$ 为例（$R$ 一列自下而上递推，$L$ 一列自上而下递推）：

| $i$ | 左侧和 $L(i)$ | 右侧积 $R(i)$ | 平衡？ |
|---|---|---|---|
| 0 | 0 | $8 \times 2 \times 2 \times 5 = 160$ | ✗ |
| 1 | 2 | $2 \times 2 \times 5 = 20$ | ✗ |
| 2 | $2+8 = 10$ | $2 \times 5 = 10$ | ✓ **答案** |
| 3 | 12 | 5 | ✗ |
| 4 | 14 | 1（空积） | ✗ |

## 4. 算法细节

1. **LIMIT 的选取**：只需严格大于最大可能左侧和 $(n-1) \times 10^9 = 9.9999 \times 10^{13}$，取整 $\text{LIMIT} = 10^{14}$ 便于记忆；哨兵 $\text{INF} = \text{LIMIT} + 1$ 大于任何可能的 $L$，绝不会误判相等。
2. **整除预检防溢出（C++）**：乘之前先比较 $r > \text{LIMIT} \,/\, nums[i+1]$（整数除法）。不成立时 $nums[i+1] \times r \le nums[i+1] \cdot \lfloor \text{LIMIT} / nums[i+1] \rfloor \le \text{LIMIT}$，乘积必然安全；成立时可证真实积严格大于 $\text{LIMIT}$（见引理 3），记 $\text{INF}$。**不能先乘再判**——$10^9 \times 10^{14} = 10^{23}$ 早已溢出 `long long`。
3. **哨兵自动传播**：若 $R[i+1] = \text{INF}$，由 $\text{INF} > \text{LIMIT} \ge \lfloor \text{LIMIT}/nums[i+1] \rfloor$，预检条件自动成立，$R[i]$ 也记 $\text{INF}$——封顶状态沿递推方向自动传播，无需特判。
4. **空侧约定即递推起点**：$R[n-1] = 1$（空积）、$L(0) = 0$（空和），两个哨兵值天然融入递推，不需要单独 if 分支。
5. **空间可压到 $O(1)$**：先算数组总和，再从右往左一趟同时维护封顶积 $p$（代表 $R(i)$）与后缀和 $t = \sum_{j \ge i} nums[j]$，则 $L(i) = \text{total} - t$；命中时记录最小下标。数组版更直观，比赛时推荐先写数组版。
6. **为什么第二趟从左往右**：题目要**最小**平衡下标，从左往右首个命中立即返回，天然满足「最小」，无需再取 min。

## 5. 正确性证明

**引理 1（左侧和的上界）**：对一切 $0 \le i \le n-1$，$L(i) \le (n-1) \times 10^9 < 10^{14} = \text{LIMIT}$。

**证明**：$L(i)$ 是至多 $n-1$ 个不超过 $10^9$ 的正整数之和，$n \le 10^5$。∎

**引理 2（后缀积的单调性）**：设真实后缀积 $R(i) = \prod_{j=i+1}^{n-1} nums[j]$（约定 $R(n-1) = 1$）。因 $nums[j] \ge 1$，有 $R(i) = nums[i+1] \cdot R(i+1) \ge R(i+1)$，即 $R(n-1) \le R(n-2) \le \cdots \le R(0)$。

**证明**：给 $R(i+1)$ 乘上因子 $nums[i+1] \ge 1$ 不会使乘积变小。∎

**引理 3（封顶保真）**：按算法递推得到的 $\hat R(i)$ 满足：(a) 若 $R(i) \le \text{LIMIT}$，则 $\hat R(i) = R(i)$（精确）；(b) 若 $R(i) > \text{LIMIT}$，则 $\hat R(i) = \text{INF} > \text{LIMIT}$。且递推中所有乘法结果 $\le \text{LIMIT}$，无溢出。

**证明**：对 $i$ 从 $n-1$ 向 $0$ 归纳。奠基：$\hat R(n-1) = 1 = R(n-1)$，(a) 成立。设 $\hat R(i+1)$ 满足归纳假设，记 $r = \hat R(i+1)$，考察 $i$：

- **预检成立**（$r > \lfloor \text{LIMIT}/nums[i+1] \rfloor$）：证真实积必超限。
  - 若 $r = \text{INF}$：由 (b) 知 $R(i+1) > \text{LIMIT}$，故 $R(i) = nums[i+1] \cdot R(i+1) \ge R(i+1) > \text{LIMIT}$；
  - 若 $r$ 精确（$r = R(i+1)$）：由 $r \ge \lfloor \text{LIMIT}/nums[i+1] \rfloor + 1$ 及 $nums[i+1] \cdot \lfloor \text{LIMIT}/nums[i+1] \rfloor > \text{LIMIT} - nums[i+1]$，得
    $$R(i) = nums[i+1] \cdot r \ge nums[i+1] \left( \left\lfloor \frac{\text{LIMIT}}{nums[i+1]} \right\rfloor + 1 \right) > \text{LIMIT}.$$

  两种情形均有 $R(i) > \text{LIMIT}$，算法记 $\hat R(i) = \text{INF}$，(b) 成立。
- **预检不成立**（$r \le \lfloor \text{LIMIT}/nums[i+1] \rfloor$）：因 $\text{INF} = \text{LIMIT} + 1 > \lfloor \text{LIMIT}/nums[i+1] \rfloor$，必有 $r \ne \text{INF}$；由归纳假设 $r = R(i+1)$ 精确，且 $R(i) = nums[i+1] \cdot r \le nums[i+1] \cdot \lfloor \text{LIMIT}/nums[i+1] \rfloor \le \text{LIMIT}$，算法精确记录 $\hat R(i) = R(i)$，(a) 成立且乘积无溢出。∎

**定理**：算法返回数组的最小平衡下标；不存在时返回 $-1$。

**证明**：第二趟的比较条件是 $L(i) = \hat R(i)$。

- 若 $R(i) \le \text{LIMIT}$：由引理 3(a)，$\hat R(i) = R(i)$，比较与定义中的 $L(i) = R(i)$ 等价；
- 若 $R(i) > \text{LIMIT}$：由引理 3(b)，$\hat R(i) = \text{INF}$，而由引理 1，$L(i) < \text{LIMIT} < \text{INF}$，比较结果为「不相等」——与真实情形一致（$R(i) > \text{LIMIT} > L(i)$，本就不可能平衡）。

故「命中」当且仅当 $i$ 是平衡下标。第二趟从左往右扫描并立即返回首个命中，返回值即最小平衡下标；全程未命中则返回 $-1$。∎

**推论（唯一性与提前判负）**：平衡下标至多一个；且从左往右扫描时一旦 $L(i) > \hat R(i)$，可立即返回 $-1$。

**证明**：元素 $\ge 1$ 使 $L(i)$ 随 $i$ 每步至少增 $1$；真实 $R(i)$ 随 $i$ 增大单调不增（右侧每少乘一个 $\ge 1$ 的因子），取 $\min$ 后的 $\hat R(i)$ 保持单调不增。于是差值 $d(i) = L(i) - \hat R(i)$ 满足

$$d(i+1) \;=\; L(i) + nums[i] - \hat R(i+1) \;\ge\; d(i) + nums[i] \;\ge\; d(i) + 1,$$

即 $d$ **严格递增**，$d(i) = 0$ 至多发生一次。又因 $L(i) < \text{LIMIT} < \text{INF}$，条件 $L(i) > \hat R(i)$ 成立时必有 $\hat R(i) \ne \text{INF}$（即精确），此后 $d$ 只增不减、永不再为 $0$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。两趟扫描，每步只有常数次比较和至多一次 64 位乘法；封顶让所有数值不超过 $2 \times 10^{14}$，彻底避免大数运算。
- **空间复杂度**：$O(n)$，存后缀积数组（前缀和是滚动变量）；按 §4 第 5 点可压到 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int smallestBalancedIndex(vector<int>& nums) {
        const long long LIMIT = 100000000000000LL;
        const long long INF = LIMIT + 1;
        int n = nums.size();
        vector<long long> rightProd(n);
        rightProd[n - 1] = 1;
        for (int i = n - 2; i >= 0; i--) {
            long long r = rightProd[i + 1];
            rightProd[i] = (r > LIMIT / nums[i + 1])
                               ? INF
                               : (long long)nums[i + 1] * r;
        }
        long long leftSum = 0;
        for (int i = 0; i < n; i++) {
            if (leftSum == rightProd[i]) return i;
            leftSum += nums[i];
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def smallestBalancedIndex(self, nums: list[int]) -> int:
        n = len(nums)
        LIMIT = 10 ** 14
        INF = LIMIT + 1
        right_prod = [1] * n
        for i in range(n - 2, -1, -1):
            r = right_prod[i + 1]
            right_prod[i] = INF if r > LIMIT // nums[i + 1] else r * nums[i + 1]
        left_sum = 0
        for i, x in enumerate(nums):
            if left_sum == right_prod[i]:
                return i
            left_sum += x
        return -1
```

## 8. 边界情况与易错点

1. **下标 0 永远不平衡**：$L(0) = 0$，而 $nums[j] \ge 1$ 保证 $R(0) \ge 1$（$n = 1$ 时空积也是 1）。因此 $n = 1$ 答案必为 $-1$；一般情形答案若存在必 $\ge 1$。
2. **末下标也几乎不可能平衡**：$R(n-1) = 1$，需要 $L(n-1) = 1$，即前缀恰为单个 1——只有 $n = 2$ 且 $nums[0] = 1$ 才会发生（如 $[1,5]$ 答案为 1）。$n \ge 3$ 时 $L(n-1) \ge n - 1 \ge 2$，末下标必不平衡。
3. **空积是 1 不是 0**：右侧为空的约定记反（写成 0），$[1,5]$ 这类用例立刻出错。
4. **C++ 必须整除预检**：先乘再判会溢出（$10^9 \times 10^{14} = 10^{23}$ 远超 `long long` 的 $9.2 \times 10^{18}$）；前缀和也不能用 `int` 存（最大约 $10^{14}$）。
5. **封顶只在从右往左的递推中合法**：封顶值不能除法还原；单调性（元素 $\ge 1$）保证超限即永远超限，一遍递推足够。
6. **LIMIT 必须严格大于最大前缀和**：取 $10^{14}$（大于 $9.9999 \times 10^{13}$）即可，别取贴边值；也不必取得过大——毫无收益还增加心智负担。
7. **全程整数运算**：整除预检 + 整数乘法零精度风险，不要图省事用浮点。
8. **全 1 数组**：$[1,1,\dots,1]$（$n \ge 2$）在 $i = 1$ 处 $L = 1$、$R = 1$ 命中，答案恒为 1。
9. **Python 别硬乘大数**：真实后缀积可达约 90 万位，大整数乘法按位数付费，即使循环只有 $O(n)$ 轮也会超时；封顶后每步都是小整数运算。
10. **平衡下标至多一个**（§5 推论）：$d(i) = L(i) - \hat R(i)$ 严格递增——对拍或手算时若发现多个候选，必有一处递推写错；比赛时也可用「一旦 $L > R$ 提前返回 $-1$」做个小优化。
