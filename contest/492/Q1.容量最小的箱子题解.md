# LeetCode 容量最小的箱子 题解

## 1. 题目概述

- **标题 / 题号**：容量最小的箱子（#3861，easy）
- **链接**：https://leetcode.cn/problems/minimum-capacity-box/
- **来源**：LeetCode 第 492 场周赛 Q1
- **难度**：简单
- **标签**：数组、单次遍历

**题意**：给定整数数组 `capacity` 与整数 `itemSize`。下标 $i$ 的箱子能装下该物品，当且仅当 $capacity[i] \ge itemSize$。在**所有能装下物品的箱子**中，返回**容量最小**的那个箱子的下标；若有多个容量并列最小的箱子，返回其中**下标最小**的一个；若没有任何箱子能装下，返回 $-1$。

**约束**：

- $1 \le capacity.length \le 100$
- $1 \le capacity[i] \le 100$
- $1 \le itemSize \le 100$

## 2. 示例

**示例 1**

```text
输入：capacity = [1,5,3,7], itemSize = 3
输出：2
解释：达标的是 5、3、7（下标 1、2、3），其中容量最小的是 3（下标 2）。
```

**示例 2**

```text
输入：capacity = [3,5,4,3], itemSize = 2
输出：0
解释：容量 3 在下标 0 和 3 各出现一次，并列最小，取更小的下标 0。
```

**示例 3**

```text
输入：capacity = [4], itemSize = 5
输出：-1
解释：没有任何箱子的容量 ≥ 5。
```

## 3. 解题思路

### 3.1 朴素思路

两种直觉做法都正确：

1. **排序法**：把二元组 $(capacity[i],\ i)$ 升序排序，从前往后找第一个 $capacity \ge itemSize$ 的二元组，其下标即答案（容量是第一关键字，下标是第二关键字，故命中的必然是「容量最小、并列下标最小」）。$O(n \log n)$，还要注意别原地排序把下标弄丢。
2. **两趟扫描**：第一趟在达标者中求出最小容量 $m$，第二趟找第一个 $capacity[i] = m$ 的下标。两趟 $O(n)$，正确但要写两个循环。

签到题追求「从题面到代码的最短路径」：这两种做法都对，但都能压成**一趟扫描**。

### 3.2 核心观察：带过滤的 argmin，一遍就够

本题本质是一个**条件 argmin**：

$$\text{ans} \;=\; \arg\min_{i \,:\, capacity[i] \ge itemSize} capacity[i] \qquad (\text{并列取最小 } i，\text{空集取 } -1)$$

「过滤」和「取最小」可以合在同一个循环里：维护一个变量 `ans`（当前最优下标，初始 $-1$），从左到右扫描，仅当 $capacity[i]$ **达标**且比当前最优**严格更小**（或尚无候选）时才覆盖。

> ⚠️ 本题最大的陷阱：答案**不是**「第一个能装下的箱子」！示例 1 中第一个达标的是下标 1（容量 5），但正确答案是下标 2（容量 3）。必须**先过滤、再在达标者里挑最小**，顺序不能反。

![核心观察：先过门槛，再挑最矮](images/wc492_q1_filter_argmin.svg)

> 💡 一句话：**「过门槛」是入场券，「最矮」才是获奖条件**。扫描顺序从左到右 + 严格小于，天然保证并列时保留最先出现的下标。

### 3.3 算法流程

![算法流程：一遍扫描](images/wc492_q1_algorithm_flow.svg)

1. 初始化 `ans = -1`（哨兵：尚无达标箱子）
2. 从左到右扫描 $i = 0 \dots n-1$：
   - 若 $capacity[i] \ge itemSize$ 且（`ans == -1` 或 $capacity[i] < capacity[ans]$）：令 `ans = i`
3. 返回 `ans`

### 3.4 示例演算

![示例演算](images/wc492_q1_example_walkthrough.svg)

- **示例 1**（$[1,5,3,7]$，门槛 3）：$i{=}0$ 容量 1 不达标，跳过；$i{=}1$ 达标且 `ans == -1` → `ans = 1`；$i{=}2$ 达标且 $3 < 5$ → `ans = 2`；$i{=}3$ 达标但 $7 \nless 3$ → 保持。答案 **2**。
- **示例 2**（$[3,5,4,3]$，门槛 2）：全部达标；`ans = 0` 之后，$5,4$ 都不小于 $3$；$i{=}3$ 时 $3 \nless 3$（**严格小于**不成立），不覆盖。答案 **0**。
- **示例 3**（$[4]$，门槛 5）：无人达标，`ans` 保持哨兵 $-1$，直接返回 **-1**。

## 4. 算法细节

1. **更新条件是过滤与比较的合取**：$capacity[i] \ge itemSize$（入场券）$\wedge$（`ans == -1` $\vee$ $capacity[i] < capacity[ans]$）。用 `ans == -1` 作「尚无候选」的哨兵，省去 `INT_MAX` 初值，也避免把不达标的箱子误当候选。
2. **严格 `<` 是并列规则的本体**：从左往右扫，只有严格更小才覆盖 $\Rightarrow$ 容量并列时，**最早出现的下标存活**。写成 `<=` 会变成「并列取最大下标」，示例 2 立刻翻车（返回 3 而不是 0）。
3. **哨兵 −1 同时承担返回值**：循环结束 `ans` 仍为 $-1$ $\iff$ 没有箱子达标 $\iff$ 题目要求的 $-1$，无需额外特判。
4. **为什么不用排序**：值域只有 $[1,100]$，甚至可以按值域建桶做到 $O(n + V)$，但单趟扫描 $O(n)$ 已是下界（每个元素至少要看一眼才能判断达标与否），代码也最短、常数最小。

## 5. 正确性证明

**引理 1（答案刻画）**：记达标集 $C = \{\, i : capacity[i] \ge itemSize \,\}$。若 $C = \varnothing$，答案为 $-1$；否则答案为满足 $capacity[j] = \min_{i \in C} capacity[i]$ 的**最小**下标 $j$。

**证明**：题面规定：「能存放」$\iff capacity[i] \ge itemSize$；返回「能存放者中容量最小的箱子的下标，并列取下标最小」；不存在则返回 $-1$。这正是对 $C$ 取条件 argmin（并列取最小下标）的定义。∎

**引理 2（循环不变量）**：处理完 $i = 0 \dots k$ 后，`ans` 等于 $C_k = C \cap [0, k]$ 上的条件 argmin（并列取最小下标）；$C_k = \varnothing$ 时 `ans = -1`。

**证明**：对 $k$ 归纳。$k = -1$（未开始）：$C_{-1} = \varnothing$，`ans = -1`，成立。设处理完 $k-1$ 时结论成立，考虑 $i = k$：

- 若 $k \notin C$：更新条件第一项不满足，`ans` 不变，而 $C_k = C_{k-1}$，结论保持。
- 若 $k \in C$ 且 `ans == -1`：由归纳假设 $C_{k-1} = \varnothing$，故 $C_k = \{k\}$，`ans = k` 正确。
- 若 $k \in C$ 且 `ans != -1`：
  - $capacity[k] < capacity[ans]$：由归纳假设 $capacity[ans] \le capacity[j]$ 对一切 $j \in C_{k-1}$，故 $capacity[k]$ 严格小于 $C_{k-1}$ 中所有容量，$k$ 是 $C_k$ 上**唯一**的最小容量持有者，`ans = k` 正确。
  - $capacity[k] \ge capacity[ans]$：若严格大于，$k$ 不是最小者，$C_k$ 的最小值与最小者集合均不变，`ans` 仍为最小下标；若相等，则 $k$ 与当前 `ans` 并列，而 `ans` 是 $C_{k-1}$ 中并列最小里下标最小者且 $ans < k$，故不更新正确。∎

**定理**：算法返回值等于题目答案。

**证明**：扫描结束时 $k = n-1$，$C_{n-1} = C$。由引理 2，`ans` 是 $C$ 上的条件 argmin（并列取最小下标），$C = \varnothing$ 时为 $-1$；由引理 1，这正是所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个元素只做常数次比较。
- **空间复杂度**：$O(1)$。只维护 `ans` 一个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumIndex(vector<int>& capacity, int itemSize) {
        int ans = -1;
        for (int i = 0; i < (int)capacity.size(); i++) {
            if (capacity[i] >= itemSize &&
                (ans == -1 || capacity[i] < capacity[ans])) {
                ans = i;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumIndex(self, capacity: list[int], itemSize: int) -> int:
        ans = -1
        for i, c in enumerate(capacity):
            if c >= itemSize and (ans == -1 or c < capacity[ans]):
                ans = i
        return ans
```

## 8. 边界情况与易错点

1. **别返回「第一个能装下的」**：$capacity[i] \ge itemSize$ 只是入场券，还要在达标者里比容量。示例 1 的第一个达标下标是 1，答案是 2。
2. **并列取小下标 $\Rightarrow$ 必须严格小于**：更新条件用 `<` 而非 `<=`。示例 2 的 $[3,5,4,3]$ 若用 `<=` 会返回 3。
3. **初值用 $-1$ 哨兵，别用 0**：若误设 `ans = 0`，「下标 0 不达标、后面才有达标者」的情形会算错（例如 $[1,5]$、门槛 3 应返回 1），且丢失「无人达标返回 $-1$」的信息。
4. **无人达标**：全程不更新，`ans` 自然是 $-1$，无需特判（前提是初值正确）。
5. **单元素数组**：$n = 1$ 时循环只跑一轮，两种结果（达标 → 0 / 不达标 → $-1$）都覆盖。
6. **无溢出风险**：$n \le 100$、值域 $[1,100]$，`int` 绰绰有余。

**延伸思考**：

- **多次询问**：若要对许多不同的 `itemSize` 反复查询，可预处理——将 $(capacity[i],\ i)$ 升序排序后，每次询问二分找第一个 $capacity \ge itemSize$ 的二元组即可，单次 $O(\log n)$；值域只有 $100$ 时甚至可按值域建桶做到 $O(1)$ 查询。
- **条件反转**：若改成「装不下物品的箱子中容量最大的下标」，只是过滤条件与比较方向同时取反，一遍扫描的骨架不变——学会把题目翻译成「谓词 + argmin/argmax」的组合，这类变形都是同一个模板。
- **流式数据**：若箱子一个个到来、要求随时给出当前答案，本算法原样可用——它只依赖「历史最优」与「当前元素」两个信息，天然是流式算法，这也是不选排序法（需要全量数据）的深层原因。
