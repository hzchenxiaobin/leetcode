# LeetCode 最小相邻交换至奇偶交替 题解

## 1. 题目概述

- **标题 / 题号**：最小相邻交换至奇偶交替（#3587，medium）
- **链接**：https://leetcode.cn/problems/minimum-adjacent-swaps-to-alternate-parity/
- **来源**：LeetCode 第 159 场双周赛 Q1
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定互不相同的整数数组 `nums`。一次操作可以交换**任意两个相邻元素**。若某个排列中**所有相邻元素的奇偶性都不同**，则称它是**有效排列**。求把 `nums` 变成任意一种有效排列所需的**最少相邻交换次数**；若无法做到，返回 $-1$。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$，且**所有元素互不相同**

> 💡 元素互不相同保证了「相同奇偶性内部的相对顺序」不会被误判为等价，也保证答案唯一可算。

## 2. 示例

**示例 1**

```text
输入：nums = [2,4,6,5,7]
输出：3
解释：交换 5 与 6 -> [2,4,5,6,7]；交换 5 与 4 -> [2,5,4,6,7]；交换 6 与 7 -> [2,5,4,7,6]，奇偶交替。
```

**示例 2**

```text
输入：nums = [2,4,5,7]
输出：1
解释：交换 4 与 5 -> [2,5,4,7]，已交替。
```

**示例 3**

```text
输入：nums = [1,2,3]
输出：0
解释：已经交替，无需操作。
```

**示例 4**

```text
输入：nums = [4,5,6,8]
输出：-1
解释：偶数 3 个、奇数 1 个，数量差 2 > 1，永远无法交替。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有排列，检查交替性，再用「逆序对」算相邻交换次数。$n!$ 个排列在 $n = 10^5$ 时完全不可行；即便只考虑「奇数 / 偶数的放置图案」（只有 2 种图案），仍需要解决「把指定元素移到指定位置的最小相邻交换次数」。

### 3.2 核心观察：先判可行性，再按「保序匹配」算距离

![先看奇偶个数，再决定目标位置集合](images/bw159_q1_parity_counts.svg)

- **可行性**：交替排列要求奇数与偶数的个数之差不大于 $1$。设偶数 $n_e$ 个、奇数 $n_o$ 个：
  - $|n_e - n_o| > 1$：返回 $-1$；
  - $n_e = n_o$：两种图案都可行（偶数打头或奇数打头），取代价小者；
  - $n_e = n_o + 1$：只能偶数打头（偶数占下标 $0,2,4,\dots$）；
  - $n_o = n_e + 1$：只能奇数打头。
- **代价**：固定图案后，**较稀有**的那一类「占住」下标 $0,2,4,\dots$（或 $1,3,5,\dots$）。设这类元素的原下标依次为 $p_0 < p_1 < \cdots < p_{t-1}$，目标位置为 $0,2,\dots,2(t-1)$，则最小相邻交换次数为

$$\text{cost} = \sum_{k=0}^{t-1} \big| p_k - 2k \big|$$

**为什么保序**：两类元素各自内部的相对顺序在最优解中一定不变——若把同奇偶性的两个元素交叉，交换它们会额外引入逆序对，不会让总距离变小。因此「第 $k$ 个（按原顺序）该类元素」只能去「第 $k$ 个该类目标位」。

### 3.3 算法流程

![代价公式：Σ|原位 - 目标位|](images/bw159_q1_cost_model.svg)

```text
1. 扫一遍，收集 偶数下标 evenPos[]、奇数下标 oddPos[]
2. ne = |evenPos|, no = |oddPos|
3. 若 |ne - no| > 1：返回 -1
4. cost(pos) = Σ_t |pos[t] - 2t|
5. 若 ne == no：返回 min(cost(evenPos), cost(oddPos))
   否则若 ne > no：返回 cost(evenPos)
   否则：返回 cost(oddPos)
```

注意 `cost` 只按「目标位 $0,2,4,\dots$」计算：两种图案里，占位的那一类总是落在偶数下标上，所以同一个函数对 `evenPos` 或 `oddPos` 调用即可。

### 3.4 示例演算

![四个示例的判定与代价](images/bw159_q1_example_walk.svg)

`nums = [2,4,6,5,7]`，偶数 $3$ 个（下标 $0,1,2$）、奇数 $2$ 个（下标 $3,4$），只能偶数打头：

| 元素（偶） | 原位 | 目标位 | 距离 |
|-----------|------|--------|------|
| 2 | 0 | 0 | 0 |
| 4 | 1 | 2 | 1 |
| 6 | 2 | 4 | 2 |

代价 $0+1+2 = 3$，与示例 1 一致。示例 2 中偶数 $[0,1]$、奇数 $[2,3]$，两种图案的代价都是 $1$，答案 $1$；示例 4 中 $n_e = 3, n_o = 1$，差为 $2$，返回 $-1$。

## 4. 算法细节

1. **只收集下标**：数值本身不重要，只需奇偶性；用两个 `vector` 按下标递增顺序存即可，天然有序。
2. **代价的绝对值**：元素可能左移（原位 $>$ 目标位）也可能右移，方向不定，必须取绝对值；直接求和会互相抵消。
3. **`int` 还是 `long long`**：最坏代价约 $n^2/8 = 1.25\times 10^9$（$n = 10^5$），接近 `int` 上界，内部用 `long long` 累加再转 `int` 更安全。
4. **两种图案都试**：数量相等时不能只试一种——示例 2 两者相等（都为 1），但很多用例两者差很多。
5. **`-1` 的判定必须在最前**：数量差 $>1$ 时任何图案都不可能，先返回避免后续计算。
6. **无需真的交换**：题目只要次数，逆序对/位移和与具体交换序列一一对应，不用模拟。
7. **$n = 1$**：只有一个元素，视为已交替，答案 $0$（代码中 `ne` 或 `no` 为 1、另一个为 0，差为 1，走对应分支，代价 $|0-0| = 0$）。

## 5. 正确性证明

**引理 1（可行性条件）**：存在有效排列 $\iff |n_e - n_o| \le 1$。

**证明**：有效排列中奇偶性严格交替，所以两类个数相差至多 $1$（交替序列的两种字符计数差 $\le 1$），必要性成立。充分性：若 $n_e = n_o$，交替排成「偶奇偶奇…」或「奇偶奇偶…」；若 $n_e = n_o + 1$，排成「偶奇偶…偶」；对称情形同理。∎

**引理 2（最小交换次数 = 位移和）**：设某类元素（如偶数）的原下标为 $p_0 < p_1 < \cdots < p_{t-1}$，目标下标为 $q_0 < q_1 < \cdots < q_{t-1}$，且保持相对顺序，则把它移到目标位置所需的最少相邻交换次数为 $\sum_k |p_k - q_k|$。

**证明**：相邻交换只能让元素在位置上移动一格，故总次数不少于所有元素位移之和 $\sum_k |p_k - q_k|$（下界）。另一方面，按 $k$ 从小到大依次把第 $k$ 个元素移动到 $q_k$：由于前 $k-1$ 个已就位且 $q$ 递增，第 $k$ 个元素的目标位必然在它当前位的右侧或左侧，且中间只隔着尚未就位的同类或异类元素，逐格交换恰好用 $|p_k - q_k|$ 次，且不会破坏已就位元素（异类元素被顺带推挤到该去的方向）。故下界可达。∎

**引理 3（保序最优）**：在最优解中，同类元素的相对顺序可以保持原序。

**证明**：设最优解中某类元素 $a$（原下标 $p_a < p_b$）排在了 $b$ 之后，即目标位置 $q_a > q_b$。交换这两个元素的目标位置（让 $a$ 去 $q_b$、$b$ 去 $q_a$）后：交替性只由奇偶性决定，同类互换不破坏交替性；而由排序不等式，$|p_a - q_b| + |p_b - q_a| \le |p_a - q_a| + |p_b - q_b|$，位移和不增。于是可反复消除逆序，得到保序且不劣的解。∎

**定理**：算法返回值为最少相邻交换次数（不可行时为 $-1$）。

**证明**：由引理 1 判定可行性正确。可行时任取一种合法图案，该类元素的占位是确定的（$0,2,4,\dots$ 或 $1,3,5,\dots$，具体由图案决定），由引理 3 可假设保序，由引理 2 代价恰为 $\sum|p_k - q_k|$，即 `cost` 函数的值；算法在两种可行图案中取最小，故为全局最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟扫描收集下标 $O(n)$；`cost` 各遍历一次该类的下标，两类合计 $O(n)$；数量相等时调用两次仍是 $O(n)$。
- **空间**：$O(n)$。两个下标数组合计 $n$ 个整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minSwaps(vector<int>& nums) {
        int n = (int)nums.size();
        vector<int> evenPos, oddPos;
        for (int i = 0; i < n; i++) {
            if (nums[i] % 2 == 0) evenPos.push_back(i);
            else oddPos.push_back(i);
        }
        int ne = (int)evenPos.size(), no = (int)oddPos.size();
        if (abs(ne - no) > 1) return -1;          // 数量差超过 1，不可能交替

        // 把一组元素分别对到 start, start+2, start+4, ... 这些目标位置上的总距离
        auto cost = [&](const vector<int>& pos) {
            long long sum = 0;
            for (int t = 0; t < (int)pos.size(); t++) sum += abs(pos[t] - 2 * t);
            return sum;
        };

        long long ans = LLONG_MAX;
        if (ne == no) {                            // 两种起点都可以
            ans = min(cost(evenPos), cost(oddPos));
        } else if (ne > no) {                      // 只能偶数打头（偶数占 0,2,4,...）
            ans = cost(evenPos);
        } else {                                   // 只能奇数打头
            ans = cost(oddPos);
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def minSwaps(self, nums: list[int]) -> int:
        even_pos = [i for i, v in enumerate(nums) if v % 2 == 0]
        odd_pos = [i for i, v in enumerate(nums) if v % 2 == 1]
        ne, no = len(even_pos), len(odd_pos)
        if abs(ne - no) > 1:            # 数量差超过 1，不可能交替
            return -1

        def cost(pos: list[int]) -> int:
            """把 pos 里的元素分别对到 0,2,4,... 这些目标位置所需的总距离"""
            return sum(abs(p - 2 * t) for t, p in enumerate(pos))

        if ne == no:                    # 两种起点都可以
            return min(cost(even_pos), cost(odd_pos))
        if ne > no:                     # 只能偶数打头（偶数占 0,2,4,...）
            return cost(even_pos)
        return cost(odd_pos)            # 只能奇数打头
```

## 8. 边界情况与易错点

1. **数量差 $>1$**：示例 4 直接 $-1$，不要试图「先交换再看」。
2. **数量相等时只算一种图案**：示例 2 两种都是 1，但例如 `[1,2,3,4]` 两种图案代价分别为 0 与 2，必须取最小。
3. **绝对值**：元素既可能左移也可能右移，漏掉 `abs` 会导致正负抵消。
4. **目标位公式**：占位类的目标位是 $0,2,4,\dots$（步长 2），不是 $0,1,2,\dots$；写成 `2*t` 而非 `t`。
5. **用哪一类算代价**：数量相等时任选一类（另一类的位置自动确定）；数量不等时必须用**数量多的那一类**（它占据 $0,2,4,\dots$）。
6. **`int` 溢出**：最坏位移和约 $1.25\times10^9$，接近 `int` 上限，内部用 `long long`。
7. **$n=1$**：答案 0，代码天然正确（单元素差为 1，代价 0）。
8. **元素互不相同**：若允许重复，需要额外说明「相同值视为可区分」，本题不需要处理。
