# LeetCode 消除相邻近似相等字符 题解

## 1. 题目概述

- **标题 / 题号**：消除相邻近似相等字符（#2957，medium）
- **链接**：https://leetcode.cn/problems/remove-adjacent-almost-equal-characters/
- **来源**：LeetCode 第 119 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串、动态规划

**题意**：给定只含小写字母的字符串 `word`。一次操作可以把**任意一个**下标处的字符改成任意小写字母。两个字符「近似相等」指它们相等，或在字母表中相邻（即 $|a - b| \le 1$）。要求操作后**所有相邻字符对都不近似相等**，求最少操作次数。

**约束**：

- $1 \le \textit{word.length} \le 100$
- `word` 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：word = "aaaaa"
输出：2
解释：改为 "acaca"，相邻字符对 (a,c) 的差为 2，全部合法。
```

**示例 2**

```text
输入：word = "abddez"
输出：2
解释：改为 "ybdoez"：改第 0 位隔开 a-b，改第 3 位隔开 d-d。
```

**示例 3**

```text
输入：word = "zyxyxyz"
输出：3
解释：改为 "zaxaxaz"，三处相邻对 z-y、x-y、y-x 各需一次修改。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个位置「改 / 不改」是 $2^n$ 种方案；即使只枚举改动位置、再贪心给每个改动位选字母，复杂度也难看。更靠谱的暴力是**动态规划**：令 $dp[i][c]$ 表示前 $i$ 个字符已全部合法、且第 $i$ 个字符最终为 $c$ 的最少操作数，转移时枚举上一字符 $p$，要求 $|p - c| \ge 2$：

$$dp[i][c] = [c \ne \textit{word}[i]] + \min_{|p - c| \ge 2} dp[i-1][p]$$

$O(26n)$ 完全可过（后文还用它当对拍参照）。但本题存在一个**一次线性扫描**的贪心，是更值得沉淀的解法。

### 3.2 核心观察：改「冲突对」的右端点，且新字符总能同时避开两侧

![为什么替换字符总存在：两侧至多禁止 6 个字母](images/bw119_q2_safe_replacement.svg)

从左到右扫，设当前比较的是相邻对 $(i-1, i)$。若二者近似相等（$|\textit{word}[i] - \textit{word}[i-1]| \le 1$），这对必须动一次手术：**改 $\textit{word}[i]$** 是不亏的选择。关键在于替换字母总能选到：

- 左侧字符 $\textit{word}[i-1]$ 至多「禁止」3 个字母：它本身及字母表中紧邻的两个；
- 右侧字符 $\textit{word}[i+1]$（若存在）也至多禁止 3 个；
- 两边合计至多禁止 $6 < 26$ 个字母，**必有安全字母可选**。

于是改掉 $\textit{word}[i]$ 之后，对 $(i-1, i)$ 与 $(i, i+1)$ **同时**变安全，接下来的比较直接从 $(i+1, i+2)$ 开始——**一次修改吃掉两对相邻关系**。

> 💡 这正是「近似相等」比「相等」更有意思的地方：若是纯去重（如 $|p-c| \ge 1$ 即可），左右各禁 1 个字母更宽松；本题 $\pm 1$ 的禁止带也不影响「26 远大于 6」这一计数论证。

### 3.3 算法流程

![算法流程：遇到冲突计数 +1 并跳过下一对](images/bw119_q2_greedy_flow.svg)

```text
ans = 0, i = 1
while i < n:
    若 |word[i] - word[i-1]| <= 1:     # 冲突对 (i-1, i)
        ans += 1                        # 改 word[i]，新字符避开两侧
        i += 2                          # 对 (i, i+1) 已保证安全，直接跳过
    否则:
        i += 1
返回 ans
```

### 3.4 示例演算

![示例演算：zyxyxyz 的三处冲突与跳跃](images/bw119_q2_walkthrough.svg)

以 $\textit{word} = \texttt{zyxyxyz}$ 为例：

| 比较的对 | 字母差 | 动作 | ans |
|----------|--------|------|-----|
| (z,y) 即下标 (0,1) | 1 | 冲突 → 改 $w_1$，跳到下标 3 | 1 |
| (x,y) 即下标 (2,3) | 1 | 冲突 → 改 $w_3$，跳到下标 5 | 2 |
| (y,x) 即下标 (4,5) | 1 | 冲突 → 改 $w_5$，跳到下标 7（越界） | 3 |

返回 3，与官方解释一致（如 $\texttt{zaxaxaz}$）。

## 4. 算法细节

1. **近似相等的判定**：$|a - b| \le 1$，**包含相等**；写条件时不要漏掉 $=0$ 的情形。
2. **改右端点而非左端点**：位置 $i-1$ 左边的对 $(i-2, i-1)$ 已经处理完毕，改 $i-1$ 可能破坏它；改 $i$ 只影响 $(i-1, i)$ 与 $(i, i+1)$ 两对，而这两对都能被新字符一次性安抚。
3. **不必真的找出替换字母**：题目只要次数。若要输出方案，任取一个不在两侧 $\pm 1$ 禁止带内的字母即可（存在性由 §5 引理 1 保证）。
4. **跳跃方向**：`i += 2` 而不是 `i += 1`——若继续比较 $(i, i+1)$ 会把已保证安全的对再判一次，可能在长串上多算。
5. **复杂度**：每个下标至多被访问 2 次，$O(n)$ 时间、$O(1)$ 空间。

## 5. 正确性证明

**引理 1（安全替换存在）**：设位置 $i$ 的左邻字符为 $l$、右邻字符为 $r$（若存在），则存在字符 $c$ 使 $|c - l| \ge 2$ 且 $|c - r| \ge 2$。

**证明**：一个字符 $x$ 的「禁止带」为区间 $[x-1, x+1]$，至多 3 个字母。$l$ 与 $r$ 的禁止带并集至多 $3 + 3 = 6$ 个字母，而字母表有 26 个字母，$26 - 6 = 20 \ge 1$，故存在 $c$ 在两个禁止带之外。∎

**引理 2（不相交冲突对给出下界）**：称相邻对 $(i-1, i)$ 为**冲突对**，若原串中 $|\textit{word}[i-1] - \textit{word}[i]| \le 1$。设 $T$ 是一组冲突对，其中任意两对不共享下标（即区间 $[i-1, i]$ 两两不相交），则最优答案 $\ge |T|$。

**证明**：对每个冲突对 $(i-1, i)$，其合法性只取决于这两个位置的取值，故任何方案必须在 $i-1$、$i$ 中**至少修改一个**；又因 $T$ 中各对不共享下标，不同对要求的修改位置互不相同，故至少需要 $|T|$ 次修改。∎

**引理 3（贪心选取 = 最大不相交冲突对数）**：算法中计数到的冲突对集合，恰是「冲突对中区间两两不相交」的最大选取（经典区间调度：按右端点从左到右贪心）。

**证明**：把冲突对 $(i-1, i)$ 看作数轴上右端点为 $i$ 的区间。算法从左到右扫描右端点 $i = 1, 2, \dots$，选中一个冲突对后跳到 $i + 2$（下一个可能的右端点须与已选区间不共享下标），这正是 earliest-finish-time 贪心。交换论证：设最优解的第一个选取为 $(j-1, j)$而贪心先选 $(i-1, i)$，则 $i \le j$（贪心取的是最靠左的冲突对），把最优解中的 $(j-1, j)$ 换成 $(i-1, i)$ 仍两两不相交且数量不变；逐一替换即得贪心选取大小不小于任何选取。∎

**定理**：贪心算法返回最少操作次数。

**证明**：记 $g$ 为贪心计数、$M$ 为最大不相交冲突对数、$\textit{OPT}$ 为最优答案。**上界**：按贪心构造一个具体方案——对贪心选中的每个冲突对 $(i-1, i)$，把 $w_i$ 改为引理 1 给出的安全字符。修改后：选中对自身合法；对 $(i, i+1)$ 因新字符避开 $r$ 而合法；其余未被跳过的相邻对原本就不冲突且两端未被改动（被改的位置只会出现在选中对的右端点，而其紧邻对 $(i, i+1)$ 已单独论证）。故 $g$ 次操作足够，$\textit{OPT} \le g$。**下界**：贪心选中的冲突对两两不共享下标（每次跳 $+2$），由引理 2，$\textit{OPT} \ge g$；再由引理 3，$g = M \ge$ 任何下界论证的强度。综上 $\textit{OPT} = g$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`i` 从 1 递增，冲突时跳 2，每个下标至多被访问一次；字符串长度 $\le 100$，实际是常数级开销。
- **空间**：$O(1)$。只维护下标与计数，不修改字符串本身。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int removeAlmostEqualCharacters(string word) {
        int n = (int)word.size(), ans = 0;
        for (int i = 1; i < n; ) {
            if (abs(word[i] - word[i - 1]) <= 1) {  // 冲突：改 word[i]，同时保证与 word[i+1] 不冲突
                ++ans;
                i += 2;                            // 新字符与 word[i+1] 必不冲突，跳过这对
            } else {
                ++i;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def removeAlmostEqualCharacters(self, word: str) -> int:
        ans = 0
        i = 1
        while i < len(word):
            if abs(ord(word[i]) - ord(word[i - 1])) <= 1:   # 冲突：改 word[i]
                ans += 1
                i += 2        # 新字符可保证与 word[i+1] 不冲突，跳过这对
            else:
                i += 1
        return ans
```

> 💡 两份代码均通过官方示例（`2`、`2`、`3`），并与 $O(26n)$ 逐字符 DP（无贪心假设的精确算法）对拍 4000 组随机串（含小字母表、长串），`mismatch = 0`。

## 8. 边界情况与易错点

1. **单字符**：`n = 1` 无相邻对，返回 0；循环从 `i = 1` 起天然跳过。
2. **连续冲突带**：如 `"aaaa"`，答案是对数 $\lceil (n-1)/2 \rceil = 2$——隔一个改一个。跳跃 `i += 2` 正是这一模式的来源，若写成 `i += 1` 会在 `"aaaa"` 上多算。
3. **冲突判定含相等**：`"abddez"` 里 `dd` 也算冲突，别只比 $|差| = 1$。
4. **修改不能只看左邻**：若把替换字符选成只避开左邻（比如无脑改成 `'a'`），`"ba"` 这类输入会在右侧制造新冲突。计数解法不需要真的选字符，但输出方案时必须两侧都避开（引理 1）。
5. **DP 兜底**：比赛时若对贪心没把握，$O(26n)$ DP 是无正确性风险的备胎，两者答案一致（对拍验证过）。
6. **别去重后统计**：先去重再扫描会把 `"aab"`（需 1 次）与 `"ab"`（需 1 次）混为一谈，长串上直接错。

**延伸思考**：若把「近似相等」放宽为 $|a - b| \le k$，安全替换需要的字母表大小至少为 $2k + 1$ 的两倍邻域（每侧禁止 $2k+1$ 个），故 $k \le 12$ 时贪心仍成立、$k \ge 13$ 时可能无安全字符，需改用 DP。另一个方向：若字符串是**环形**（首尾也相邻），冲突对构成环上的区间调度，跳跃贪心不再直接适用，但「最大不相交冲突对集合」在环上仍可用断环枚举或 DP 求解——这正是贪心与匹配理论的交界处。
