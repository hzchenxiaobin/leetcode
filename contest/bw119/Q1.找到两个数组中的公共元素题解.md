# LeetCode 找到两个数组中的公共元素 题解

## 1. 题目概述

- **标题 / 题号**：找到两个数组中的公共元素（#2956，easy）
- **链接**：https://leetcode.cn/problems/find-common-elements-between-two-arrays/
- **来源**：LeetCode 第 119 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定两个下标从 0 开始的整数数组 `nums1`（长度 $n$）与 `nums2`（长度 $m$），计算两个数值：

- `answer1`：满足「`nums1[i]` 在 `nums2` 中出现过」的下标 $i$ 的数量；
- `answer2`：满足「`nums2[i]` 在 `nums1` 中出现过」的下标 $i$ 的数量。

返回 $[\textit{answer1}, \textit{answer2}]$。注意统计的是**下标个数**而不是不同值的个数，同一个值出现多少次就贡献多少。

**约束**：

- $1 \le n, m \le 100$
- $1 \le \textit{nums1}[i], \textit{nums2}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums1 = [2,3,2], nums2 = [1,2]
输出：[2,1]
解释：nums1 中下标 0、2 的元素 2 出现在 nums2 中，answer1 = 2；
      nums2 中只有下标 1 的元素 2 出现在 nums1 中，answer2 = 1。
```

**示例 2**

```text
输入：nums1 = [4,3,2,3,1], nums2 = [2,2,5,2,3,6]
输出：[3,4]
解释：nums1 中下标 1、2、3 的元素出现在 nums2 中，answer1 = 3；
      nums2 中下标 0、1、3、4 的元素出现在 nums1 中，answer2 = 4。
```

**示例 3**

```text
输入：nums1 = [3,4,2,3], nums2 = [1,5]
输出：[0,0]
解释：两个数组没有相同的数字。
```

## 3. 解题思路

### 3.1 暴力思路

对 `nums1` 的每个元素 $x$，线性扫一遍 `nums2` 判断 $x$ 是否出现；再对称地对 `nums2` 每个元素扫 `nums1`。时间 $O(nm)$，本题 $n, m \le 100$ 时最多 $10^4$ 次比较，完全能过——官方提示也明说暴力可写。但 $O(nm)$ 的写法把「同一个值重复扫描」做了无数遍，一旦 $n, m$ 放大到 $10^5$ 就会超时，签到题也值得沉淀**线性套路**。

### 3.2 核心观察：只问「是否出现」，用值集合即可

![核心观察：两个数组各自建值集合，交叉判断计数](images/bw119_q1_hash_sets.svg)

关键在两点：

1. 判断条件是「$x$ 在另一个数组中**出现过**」，与出现**几次**无关，因此只需把另一个数组压成一个**哈希集合**，`count(x)` 一次判断即可，均摊 $O(1)$。
2. 统计的是**下标个数**，所以对数组做一遍线性扫描逐个计数，不能只对集合做交集（交集丢掉了出现次数）。

> 💡 一句话：`answer1` = `nums1` 中落在 `set(nums2)` 里的元素个数，`answer2` 对称。两个集合各自建一次，总时间 $O(n + m)$。

### 3.3 算法流程

```text
1. s1 = set(nums1)，s2 = set(nums2)        # 各扫一遍建集合，O(n + m)
2. ans1 = 0, ans2 = 0
3. for x in nums1: 若 x ∈ s2，则 ans1 += 1
4. for x in nums2: 若 x ∈ s1，则 ans2 += 1
5. 返回 [ans1, ans2]
```

### 3.4 示例演算

![示例演算：示例 2 的双向计数过程](images/bw119_q1_walkthrough.svg)

以示例 2 为例：$s_1 = \{1,2,3,4\}$，$s_2 = \{2,3,5,6\}$。

| 扫描对象 | 逐元素判断 | 计数 |
|----------|-----------|------|
| nums1 = [4,3,2,3,1] | 4∉s2，3∈s2，2∈s2，3∈s2，1∉s2 | answer1 = 3 |
| nums2 = [2,2,5,2,3,6] | 2∈s1，2∈s1，5∉s1，2∈s1，3∈s1，6∉s1 | answer2 = 4 |

注意 `nums1` 中两个 3 都落在 $s_2$ 中，各贡献一次——这正是「按下标计数」的含义。

## 4. 算法细节

1. **集合只建一次**：`answer1` 的判断用 `s2`，`answer2` 的判断用 `s1`，两个集合都要建，别只建一个。
2. **计数方式**：遍历**原数组**而非集合，保证每个合法下标都被统计一次；等价写法是先对值做 `Counter`，再对每个下标查 `cnt[值] > 0`。
3. **数据结构选择**：值域只有 $1 \sim 100$，用长度 101 的 `bool` 数组当集合更快；但哈希集合是值域无关的通用写法，$O(n+m)$ 的时间复杂度对 $10^9$ 级别的值同样成立，这里按通用写法实现。
4. **无序性**：`unordered_set` 的查找均摊 $O(1)$，最坏 $O(n)$ 的构造性数据在本题规模下无需担心。

## 5. 正确性证明

**引理 1（值集合等价）**：对任意值 $x$，$x$ 在数组 $A$ 中出现 $\iff$ $x \in \mathrm{set}(A)$。

**证明**：集合 $\mathrm{set}(A)$ 的定义就是 $A$ 中出现过的所有值构成的集合，双向包含由构造直接成立。∎

**定理**：算法返回的 $[\textit{answer1}, \textit{answer2}]$ 与题目定义一致。

**证明**：由引理 1，`answer1` 的第 $i$ 项条件「`nums1[i]` 在 `nums2` 中出现」等价于 `nums1[i] ∈ s2`，算法在第 3 步对每个下标 $i$ 独立判断并累加，不重不漏地覆盖了 $0 \sim n-1$ 全部下标，故累加值等于满足条件的下标总数；`answer2` 同理对称。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。建两个集合各线性扫描一次，随后两趟计数各扫描一次，每步均为均摊 $O(1)$ 的集合查询。
- **空间**：$O(n + m)$，即两个哈希集合的开销；若利用值域 $\le 100$ 改用 `bool[101]`，可降到 $O(C)$，$C$ 为值域大小。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findIntersectionValues(vector<int>& nums1, vector<int>& nums2) {
        unordered_set<int> s1(nums1.begin(), nums1.end());
        unordered_set<int> s2(nums2.begin(), nums2.end());
        int ans1 = 0, ans2 = 0;
        for (int x : nums1) if (s2.count(x)) ++ans1;   // nums1[i] 出现在 nums2 中
        for (int x : nums2) if (s1.count(x)) ++ans2;   // nums2[i] 出现在 nums1 中
        return {ans1, ans2};
    }
};
```

### Python

```python
class Solution:
    def findIntersectionValues(self, nums1: list[int], nums2: list[int]) -> list[int]:
        s1, s2 = set(nums1), set(nums2)
        ans1 = sum(x in s2 for x in nums1)   # nums1[i] 出现在 nums2 中的下标数
        ans2 = sum(x in s1 for x in nums2)   # nums2[i] 出现在 nums1 中的下标数
        return [ans1, ans2]
```

> 💡 两份代码均通过官方示例（`[2,1]`、`[3,4]`、`[0,0]`），并与 $O(nm)$ 双向暴力扫描对拍 3000 组随机数据，`mismatch = 0`。

## 8. 边界情况与易错点

1. **按下标计数 ≠ 按值计数**：`answer1` 是「满足条件的下标数量」，重复值各贡献一次。若误写成 `len(s1 & s2)`（交集大小）会丢掉重复元素，示例 2 会错算成 `[2,2]`。
2. **别把计数写成次数乘积**：`sum(cnt2[x] for x in nums1)` 是「出现次数之和」而非「出现过的下标数」，比如示例 1 中 2 在 `nums2` 只出现一次但条件对两个下标都成立，两种口径在次数 $> 1$ 时 diverge。
3. **返回顺序**：先 `answer1`（`nums1` 视角）后 `answer2`，别搞反。
4. **$n, m \ge 1$**：无空数组，不需要对空集特判；但循环计数写法天然支持空数组，更稳。
5. **值域很小时的优化**：可换成 `bool` 数组把空间压到 $O(100)$，面试中可作为加分点主动提。
