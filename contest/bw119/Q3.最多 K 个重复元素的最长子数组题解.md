# LeetCode 最多 K 个重复元素的最长子数组 题解

## 1. 题目概述

- **标题 / 题号**：最多 K 个重复元素的最长子数组（#2958，medium）
- **链接**：https://leetcode.cn/problems/length-of-longest-subarray-with-at-most-k-frequency/
- **来源**：LeetCode 第 119 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：一个数组的元素 $x$ 的**频率**是它在数组中的出现次数。若数组中**所有**元素的频率都 $\le k$，称该数组为**好数组**。给定整数数组 `nums` 与整数 $k$，返回 `nums` 中**最长好子数组**（连续非空）的长度。

**约束**：

- $1 \le \textit{nums.length} \le 10^5$
- $1 \le \textit{nums}[i] \le 10^9$
- $1 \le k \le \textit{nums.length}$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,1,2,3,1,2], k = 2
输出：6
解释：最长好子数组 [1,2,3,1,2,3]：1、2、3 各出现 2 次，都不超过 k = 2。
```

**示例 2**

```text
输入：nums = [1,2,1,2,1,2,1,2], k = 1
输出：2
解释：任何长度 3 的子数组必含重复，最长好子数组形如 [1,2]。
```

**示例 3**

```text
输入：nums = [5,5,5,5,5,5,5], k = 4
输出：4
解释：[5,5,5,5] 中 5 恰好出现 4 次。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $O(n^2)$ 个子数组并统计频率，$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时；即便用「固定左端点向右扩张、`Counter` 增量维护」，遇到首个超频值就 break，最坏（如全相同元素、$k$ 很大）仍是 $O(n^2)$。必须利用**子数组合法性关于包含关系封闭**这一单调结构。

### 3.2 核心观察：合法性对「缩短」封闭 → 滑动窗口

![核心观察：窗口超频时收缩左端，频率只减不增](images/bw119_q3_sliding_window.svg)

「好子数组」有一条天然的单调性：**好子数组的任意子数组也是好子数组**——把窗口两端往里缩，任何元素的频率都不会增加。于是对每个右端点 $r$，存在一个最小的左端 $l^\*(r)$ 使 $[l, r]$ 合法，且 $l^\*(r)$ 随 $r$ **单调不减**。这正是滑动窗口适用的标准形态：

- 右端 $r$ 每右移一位，**只有新进入的元素 `nums[r]` 的频率可能超过 $k$**（其余元素频率不变）；
- 一旦 `freq[nums[r]] > k`，从左往右收缩，直到 `nums[r]` 在窗口内恰好剩 $k$ 个（即窗口越过了旧的某个 `nums[r]`）为止；
- 每步用当前窗口长度更新答案。

> 💡 换个说法：超频的元凶一定是刚进来的那个值，所以收缩的**停止条件**只看它一个——这是把「检查所有值」简化成「检查一个值」的关键。

### 3.3 算法流程

```text
freq = 哈希表, l = 0, ans = 0
for r in 0..n-1:
    freq[nums[r]] += 1
    若 freq[nums[r]] > k:                  # 只有新元素可能超频
        while freq[nums[r]] > k:           # 收缩到首个同值出窗
            freq[nums[l]] -= 1
            l += 1
    ans = max(ans, r - l + 1)
返回 ans
```

### 3.4 示例演算

![示例演算：nums=[1,2,3,1,2,3,1,2], k=2 的窗口推进](images/bw119_q3_walkthrough.svg)

以示例 1（$k = 2$）为例，关键几步：

| 步骤 (r) | 事件 | 窗口 | 说明 |
|----------|------|------|------|
| r = 0..4 | 1、2、3 各进窗，频率均 ≤ 2 | [1,2,3,1,2] | 长度 5 |
| r = 5 | 3 第二次进窗，频率 = 2 | [1,2,3,1,2,3] | 长度 6 ✓ |
| r = 6 | 1 第三次进窗，频率 = 3 > 2 | 收缩：弹出 1 → [2,3,1,2,3,1] | 长度 6 |
| r = 7 | 2 第三次进窗，频率 = 3 > 2 | 收缩：弹出 2、3、1 → [2,3,1,2] 中 2 共 2 次 | 长度 4 |

答案 6，与示例一致（注意收缩时**连续弹出**到越过首个同值元素为止）。

## 4. 算法细节

1. **先加再判**：先 `++freq[nums[r]]`，若 `> k` 才收缩。不要在进入前预判，否则边界容易写错。
2. **收缩条件只看 `nums[r]`**：`while (freq[nums[r]] > k)`——其余元素在收缩前频率均 ≤ k，弹出只会更小，天然合法。
3. **摊还分析**：左端 `l` 全程只前进不后退，总移动量 $\le n$，故整个算法 $O(n)$。
4. **哈希表选择**：值域到 $10^9$，必须用 `unordered_map` / `dict`，不能用数组计数。
5. **答案更新位置**：放在收缩之后、每轮循环末尾，保证被统计的窗口一定合法。

## 5. 正确性证明

**引理 1（收缩封闭性）**：好子数组的任意（非空）子数组也是好子数组；反之，若 $[l, r]$ 不是好子数组，则任何包含它的子数组也不是。

**证明**：子数组中每个元素的出现次数 $\le$ 其在父子数组中的出现次数，故频率上界约束在取子数组时保持。反向：包含 $[l, r]$ 的子数组中，$[l, r]$ 内那个频率 $> k$ 的值的频率只会更大。∎

**引理 2（窗口不变式）**：算法在每轮收缩结束后，窗口 $[l, r]$ 是好子数组。

**证明**：归纳。$r = 0$ 时窗口单元素，$k \ge 1$，合法。设处理 $r-1$ 后 $[l, r-1]$ 合法。处理 $r$：加入 `nums[r]` 后，除 `nums[r]` 外的元素频率均不变仍 $\le k$；若 `nums[r]` 频率 $\le k$ 则直接合法；否则进入收缩，收缩过程中各元素频率单调不增，`nums[r]` 的频率随窗口越过其旧出现位置逐步下降，循环终止时恰为 $k$（窗口内至少保留刚进入的这个 `nums[r]`，$k \ge 1$ 保证能停），其余元素频率只会更小，故 $[l, r]$ 合法。∎

**引理 3（最小左端的单调性）**：记 $l^\*(r)$ 为使 $[l, r]$ 合法的最小左端，则 $l^\*(r)$ 随 $r$ 单调不减。

**证明**：若 $l^\*(r) < l^\*(r-1)$，则 $[l^\*(r), r]$ 合法，由引理 1 其子窗口 $[l^\*(r), r-1]$ 也合法，于是 $l^\*(r-1) \le l^\*(r)$，与假设矛盾。∎

**引理 4（左端最优性）**：算法处理完右端 $r$ 后，左端 $l$ 恰等于 $l^\*(r)$。

**证明**：对 $r$ 归纳。$r = 0$ 时 $l = 0 = l^\*(0)$。设处理完 $r-1$ 时 $l = l^\*(r-1)$。处理 $r$ 时分两种情形：**无收缩**（$[\textit{freq}(\textit{nums}[r]) \le k]$），则 $[l, r]$ 合法给出 $l^\*(r) \le l = l^\*(r-1)$，结合引理 3 得 $l^\*(r) = l^\*(r-1) = l$。**有收缩**：收缩循环每弹出一步前，窗口 $[l-1, r]$ 中 `nums[r]` 的频率仍 $> k$（循环条件），故弹出的左端都不合法；循环终止时 $[l, r]$ 合法，故 $l$ 是最小合法左端，即 $l = l^\*(r)$。∎

**定理**：算法返回最长好子数组的长度。

**证明**：一方面，每次计入答案的窗口都合法（引理 2），故输出 $\le \textit{OPT}$。另一方面，设最优好子数组为 $[L, R]$，长度 $\textit{OPT} = R - L + 1$。由引理 4，处理 $r = R$ 时窗口为 $[l^\*(R), R]$；由 $[L, R]$ 合法知 $L \ge l^\*(R)$，故窗口长度 $R - l^\*(R) + 1 \ge R - L + 1 = \textit{OPT}$，输出 $\ge \textit{OPT}$。二者结合，输出 $= \textit{OPT}$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。右端 $r$ 移动 $n$ 次；左端 $l$ 全程至多前进 $n$ 次（摊还），每步伴随 $O(1)$ 哈希操作。
- **空间**：$O(n)$ 最坏（所有元素互不相同），即频次哈希表的开销；若值域有限可换成计数数组，空间 $O(\min(n, C))$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxSubarrayLength(vector<int>& nums, int k) {
        unordered_map<int, int> freq;
        int ans = 0;
        for (int l = 0, r = 0; r < (int)nums.size(); ++r) {
            if (++freq[nums[r]] > k) {              // 右端进入后该值超频，收缩到首个同类元素出窗
                while (freq[nums[r]] > k) --freq[nums[l++]];
            }
            ans = max(ans, r - l + 1);
        }
        return ans;
    }
};
```

### Python

```python
from collections import defaultdict

class Solution:
    def maxSubarrayLength(self, nums: list[int], k: int) -> int:
        freq = defaultdict(int)
        ans = 0
        l = 0
        for r, x in enumerate(nums):
            freq[x] += 1
            if freq[x] > k:                  # 右端进入后该值超频，收缩到首个同类元素出窗
                while freq[x] > k:
                    freq[nums[l]] -= 1
                    l += 1
            ans = max(ans, r - l + 1)
        return ans
```

> 💡 两份代码均通过官方示例（`6`、`2`、`4`），并与 $O(n^2)$ 逐子数组暴力对拍 2020 组随机数据（小值域高重复 + $n = 300$ 大数组），`mismatch = 0`；$n = 10^5$ 的 C++ 实测约 6 ms。

## 8. 边界情况与易错点

1. **收缩条件写 `> k` 而非 `>= k`**：频率恰为 $k$ 是合法的；写成 `>=` 会让 $k = 1$ 时单元素窗口也被收缩，答案偏小。
2. **收缩必须弹到「越过首个同值」**：`while (freq[nums[r]] > k)` 循环会连弹多个**不同**元素（见 3.4 中 r = 7 的连弹 2、3、1），只弹一个是不够的。
3. **$l$ 不会越过 $r$**：窗口内至少保留刚进窗的 `nums[r]` 本身（频率 $\ge 1 \le k$ 时循环终止），不存在空窗口或 $l > r$ 的越界。
4. **全相同元素**：答案 $= \min(n, k)$，可当手测样例（示例 3 即此形态）。
5. **值域 $10^9$**：不要开数组计数，哈希表是必需的。
6. **别把「子数组」当「子序列」**：删掉中间元素让频率达标是不允许的，窗口必须连续。
