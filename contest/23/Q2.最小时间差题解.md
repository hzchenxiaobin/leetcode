# LeetCode 最小时间差 题解

## 1. 题目概述

- **标题 / 题号**：最小时间差（#539，medium）
- **链接**：https://leetcode.cn/problems/minimum-time-difference/
- **来源**：LeetCode 第 23 场周赛 Q2
- **难度**：中等
- **标签**：数组、数学、字符串、排序

**题意**：给定若干 24 小时制时刻（格式 `"HH:MM"`，`00:00` 到 `23:59`），在**一天之内循环**的时间轴上，求任意两个时刻的**最小分钟差**。两个时刻 $a,b$ 的差取「沿时间轴两个方向走，较短的那一段长度」，即 $\min(\lvert a-b\rvert,\ 1440-\lvert a-b\rvert)$；若列表中有重复时刻，答案为 $0$。

**约束**：

- $2 \le \text{timePoints.length} \le 2 \times 10^4$
- `timePoints[i]` 形如 `"HH:MM"`，两位小时 + 两位分钟，合法且无前导冗余

> 💡 **一句话抓要害**：时间是**环**而不是**线**——这是本题唯一容易翻车的点。所有「线性排序后看相邻差」的题，一旦值域首尾相接，就必须额外补一条回绕边。

## 2. 示例

**示例 1**

```text
输入：timePoints = ["23:59","00:00"]
输出：1
解释：23:59 与 00:00 相隔 1 分钟（跨零点）。若按普通数值相减会得到 1439，
      但时间轴是环，答案取较短的 1 分钟。
```

**示例 2**

```text
输入：timePoints = ["00:00","23:59","00:00"]
输出：0
解释：两个 "00:00" 完全相同，差为 0，已是最小可能值。
```

**示例 3（自造边界：回绕才是最优）**

```text
输入：timePoints = ["00:10","23:50","12:00"]
输出：20
解释：转成分钟 [10, 1430, 720]，排序 [10, 720, 1430]；
      相邻差 710、710，回绕差 10 + 1440 − 1430 = 20 → 答案 20。
```

## 3. 解题思路

### 3.1 暴力思路

两两枚举所有时刻对，按环上定义算差并取最小值：时间 $O(n^2)$。

$n = 2\times10^4$ 时有 $\binom{n}{2} \approx 2\times10^8$ 对，C++ 勉强卡在边缘、Python 必超时；而且看着 2 万个数只想两两比较，说明完全没用上「**值域只有 1440**」这个关键信息。

### 3.2 核心观察：时间是一个首尾相接的环

![时间轴是环：最短差可能跨过零点](images/wc23_q2_ring_concept.svg)

把每个时刻换算成当天的第几分钟：

$$v = 60h + m \in [0, 1439]$$

**观察一（环上距离）**：$a$ 与 $b$ 的实际间隔是

$$d(a,b) = \min\bigl(\lvert a-b\rvert,\ 1440 - \lvert a-b\rvert\bigr)$$

后半项就是「跨过零点那一边」的长度。

**观察二（最优对在环上必相邻）**：在环上按顺序排好所有时刻后，最短的那段弧**内部不可能再夹着别的时刻**——否则夹在中间的 $c$ 连同端点组成更短的一段。所以只需检查环上**每一对相邻点**之间的空隙，共 $n$ 段（$n-1$ 段普通相邻 + $1$ 段跨零点回绕），取最小值即可。

于是「排序 + 看相邻差」在直线上是标准套路，在环上只需**多算一条首尾边**：

$$\text{回绕差} = t[0] + 1440 - t[n-1]$$

> 💡 **套路沉淀**：值域是「周期」的题目（时间、角度、取模坐标、循环数组）统称**环形问题**。通用改写方式：把首元素加上一个周期后追加到末尾（即 `t[0] + 1440`），环就被「切开」成一条链，链上所有相邻差（含新加的尾巴）就是环上所有间隙。

### 3.3 算法流程

![算法流程：解析 → 排序 → 相邻差 + 首尾回绕](images/wc23_q2_flow.svg)

1. **解析**：`h = tp[0..1]`、`m = tp[3..4]`，得到 $v = 60h + m$；
2. **鸽巢剪枝**：若 $n > 1440$，$1440$ 个可能的分钟值装不下 $n$ 个时刻，必有重复 $\Rightarrow$ 直接返回 $0$；
3. **排序**：$t[0] \le t[1] \le \cdots \le t[n-1]$；
4. **回绕边**：`ans = t[0] + 1440 - t[n-1]`；
5. **相邻边**：对 $i = 1 \ldots n-1$ 做 `ans = min(ans, t[i] - t[i-1])`，若中途出现 $0$ 可直接提前返回；
6. 返回 `ans`。

### 3.4 示例演算

![示例演算：排序、相邻差与回绕差](images/wc23_q2_walkthrough.svg)

以示例 3 的 `["00:10","23:50","12:00"]` 走查（见上图）：

| 步骤 | 处理 | 结果 |
|------|------|------|
| ① 换算 | $00{:}10 \to 10$，$23{:}50 \to 1430$，$12{:}00 \to 720$ | `[10, 1430, 720]` |
| ② 排序 | 升序 | `[10, 720, 1430]` |
| ③ 回绕 | $10 + 1440 - 1430$ | `ans = 20` |
| ④ 相邻 | $720 - 10 = 710$ | `ans = min(20, 710) = 20` |
| ⑤ 相邻 | $1430 - 720 = 710$ | `ans = min(20, 710) = 20` |

最终答案 $20$。注意 ③ 这一步**必须先做**：如果只在相邻差上取最小，会得到 710，直接错过真正的答案。

## 4. 算法细节

1. **字符串解析方式**：`int(tp[0:2]) * 60 + int(tp[3:5])` 比 `tp.split(":")` 少一次列表分配，在 $2\times10^4$ 规模下更稳；C++ 用 `stoi(s.substr(0,2))`。格式固定为两位，不需要处理 `"9:05"` 这种单位数小时。
2. **回绕公式的推导**：环上从 $t[n-1]$ 顺时针走到 $t[0]$，要走 $1440 - t[n-1]$ 到零点，再走 $t[0]$ 到目标，故为 $t[0] + 1440 - t[n-1]$；它一定 $\ge 1$（重复时刻已在相邻差里暴露为 $0$）。
3. **$n = 2$ 的自洽性**：此时没有普通相邻边，`ans` 直接等于回绕差；两个方向的差满足 $d + (1440-d) = 1440$，取较小者正是回绕差或它的补，公式天然正确，无需特判。
4. **鸽巢剪枝是可选优化**：即使不写 `n > 1440` 的判断，排序后重复值必然产生相邻差 $0$，答案依旧正确。写上它的价值在于：把 $n$ 很大（$2\times10^4$）的那部分最坏常数直接压成 $O(1)$，同时也解释了为什么合法答案一定落在 $[0, 720]$ 内——超过 $1440$ 个时刻根本不可能两两不同。
5. **排序 vs 计数排序**：值域只有 $1440$，可以开 `bool seen[1440]` 做桶，先 $O(n)$ 打标记（撞到已标记的立刻返回 $0$），再顺序扫描求相邻下标差、并单独处理首尾回绕，总时间 $O(n + 1440)$、空间 $O(1440) = O(1)$。$n$ 只有 $2\times10^4$ 时两者都过；当 $n$ 逼近值域上限时桶法更优，当 $n$ 远小于值域时排序更省事。
6. **答案上界**：任意时刻差 $\le 720$（半个环），因此 `ans` 初值可直接取 $1440$ 或 $720$ 的哨兵，不必用 `INT_MAX`，也就不存在溢出问题（全部运算都是 $[0, 2880]$ 内的整数）。
7. **提前返回**：一旦某条边长为 $0$（重复时刻），答案已到下界，立刻 `return 0`，避免无意义的剩余扫描。

## 5. 正确性证明

**引理 1（环上最短弧内部无点）**：设排序后 $a = t[i] < b = t[j]$ 是一对使 $d(a,b)$ 取到全局最小值的时刻。则 $a$ 与 $b$ 之间沿较短弧不含任何其它时刻，从而它们在环上相邻。

**证明**：反设较短弧内部存在时刻 $c$。不妨设较短弧就是「从 $a$ 递增到 $b$」那段，长度 $L = b - a = d(a,b) \le 720$，且 $a < c < b$。则 $d(a,c) = \min(c-a,\ 1440-(c-a))$。因为 $0 < c - a < L \le 720$，故 $c - a \le 720$，于是 $d(a,c) = c - a < L = d(a,b)$，与 $(a,b)$ 最优矛盾。若较短弧是「从 $b$ 递增到 $a$（跨零点）」那段，同理用 $c$ 在其内部得到 $d(b,c) < d(a,b)$，同样矛盾。∎

**引理 2（候选集覆盖环上全部相邻对）**：排序数组的相邻差 $t[i]-t[i-1]$（$i = 1..n-1$）加上回绕差 $t[0]+1440-t[n-1]$，恰好是环上 $n$ 段弧长。

**证明**：排序把 $[0,1440)$ 内的点按顺时针列出，相邻点之间的弧依次为 $t[1]-t[0],\ t[2]-t[1],\ \ldots,\ t[n-1]-t[n-2]$，最后剩下从 $t[n-1]$ 绕回 $t[0]$ 的一段，长度 $1440 - t[n-1] + t[0]$。共 $n$ 段且互不重叠、并集为整个环。∎

**引理 3（鸽巢）**：$n > 1440$ 时必有两个时刻完全相同，答案为 $0$。

**证明**：每个时刻取值于 $1440$ 个整数（$0$ 到 $1439$），$n$ 个时刻映射进 $1440$ 个格子，由抽屉原理必有两者落进同一格。∎

**定理**：算法返回的值等于所有时刻对环上距离的最小值。

**证明**：设全局最小值为 $D$。由引理 1，取得 $D$ 的那对时刻在环上相邻，由引理 2 它的距离是候选集中的一个元素，故 `ans` $\le D$。另一方面候选集中的每一条都是某对真实时刻的环上距离，而 $D$ 是这些距离的最小值，故 `ans` $\ge D$。两者结合 `ans` $= D$。若 $n > 1440$，引理 3 保证返回 $0$，而 $0$ 已是距离的下界，同样正确。∎

## 6. 复杂度分析

- **时间**：解析 $O(n)$；排序 $O(n\log n)$ 为主项；回绕与相邻扫描各 $O(1)$ 与 $O(n)$。合计 $O(n \log n)$。若改用桶（计数）法，则为 $O(n + 1440)$，在 $n$ 很大时更优。
- **空间**：排序版除输入与长度为 $n$ 的分钟数组外，额外空间 $O(n)$（C++ `sort` 为 $O(\log n)$ 栈）；桶版只需 $1440$ 个布尔位，额外空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int findMinDifference(vector<string>& timePoints) {
        const int DAY = 24 * 60;
        int n = (int)timePoints.size();
        // 鸽巢原理：1440 个取值装不下更多时刻，必有两个相同
        if (n > DAY) return 0;

        vector<int> mins(n);
        for (int i = 0; i < n; ++i) {
            int h = stoi(timePoints[i].substr(0, 2));
            int m = stoi(timePoints[i].substr(3, 2));
            mins[i] = h * 60 + m;
        }
        sort(mins.begin(), mins.end());

        // 首尾回绕：从最后一个时刻顺时针绕回第一个
        int ans = mins[0] + DAY - mins[n - 1];
        for (int i = 1; i < n; ++i) {
            ans = min(ans, mins[i] - mins[i - 1]);
            if (ans == 0) return 0;          // 重复时刻，已到下界
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findMinDifference(self, timePoints: List[str]) -> int:
        DAY = 24 * 60
        n = len(timePoints)
        if n > DAY:                    # 鸽巢原理：必有重复时刻
            return 0

        mins = []
        for tp in timePoints:
            mins.append(int(tp[0:2]) * 60 + int(tp[3:5]))
        mins.sort()

        ans = mins[0] + DAY - mins[-1]  # 先算跨零点的首尾回绕
        for i in range(1, n):
            ans = min(ans, mins[i] - mins[i - 1])
            if ans == 0:
                return 0
        return ans
```

## 8. 边界情况与易错点

1. **漏掉回绕**：只算相邻差的话，`["23:59","00:00"]` 会输出 1439 而不是 1——这是本题最高频的 WA。记住「排序 + 相邻差」是直线结论，环上必须补首尾边。
2. **重复时刻**：`["00:00","23:59","00:00"]` 输出 0。排序后重复值相邻，差为 0，天然被覆盖；但若用 `set` 去重再算就会出错。
3. **$n = 2$ 的对称性**：两者间只有两段弧，答案取较短者；回绕公式对 $n = 2$ 已足够，不要为了「相邻差」再写特判。
4. **鸽巢阈值的边界**：判断必须是 `n > 1440` 而不是 `n >= 1440`——恰好 $1440$ 个互不相同的时刻是合法输入，此时答案为 1（每一分钟都占满）。
5. **字符串解析**：时刻固定两位，`tp[0:2]`、`tp[3:5]` 即可；不要用 `int(tp[0])`，否则 `"00"` 到 `"09"` 能过、`"10"` 就错。
6. **`ans` 初值**：先赋回绕差再逐条比，比先设一个大哨兵更不容易漏步骤；哨兵写法要确保循环一定执行到，而 $n \ge 2$ 时有回绕边兜底。
7. **桶法的首尾**：若改用 `bool[1440]`，扫描完相邻标记后必须再算一次「最后一个标记 + 1440 − 第一个标记」，否则同样漏回绕；且打标记时撞到重复要立即返回 0。
