# LeetCode 反转字符串 II 题解

## 1. 题目概述

- **标题 / 题号**：反转字符串 II（#541，easy）
- **链接**：https://leetcode.cn/problems/reverse-string-ii/
- **来源**：LeetCode 第 23 场周赛 Q1
- **难度**：简单
- **标签**：双指针、字符串

**题意**：从字符串开头起，每 $2k$ 个字符视为一块：反转块内**前 $k$ 个**字符，块内**后 $k$ 个**保持原样，然后从下一块重新计数。若最后一块剩余不足 $k$ 个字符，则把这一块**整体反转**；若剩余大于等于 $k$ 但不足 $2k$ 个，则只反转前 $k$ 个、其余保持。

**约束**：

- $1 \le \lvert s \rvert \le 10^4$
- `s` 仅由小写英文字母组成
- $1 \le k \le 10^4$

> 💡 **签到题的题眼**：题面列出的三条规则（完整块、$k \le$ 剩余 $< 2k$、剩余 $< k$）看起来要写三个分支，其实都能被一个右端点 $\min(i+k,\ n)$ 吸收——三种情况不过是「剩余长度」的三个取值区间，而反转**永远不能越过字符串末尾**。抓住这一点，代码只剩一个 `min`。

## 2. 示例

**示例 1**

```text
输入：s = "abcdefg", k = 2
输出："bacdfeg"
解释：每 2k = 4 个一块。
      块 0 = "abcd" → 反前 2 个得 "ba" + "cd" = "bacd"；
      块 1 = "efg"  → 剩余 3 ≥ k，反前 2 个得 "fe" + "g" = "feg"。
      拼接得 "bacdfeg"。
```

**示例 2**

```text
输入：s = "abcd", k = 2
输出："bacd"
解释：只有一个完整块 "abcd"，反前 2 个 "ab" → "ba"，后 2 个 "cd" 原样，得 "bacd"。
```

**示例 3（自造边界：剩余不足 k）**

```text
输入：s = "abc", k = 5
输出："cba"
解释：剩余 3 < k = 5，整段反转。
```

**示例 4（自造边界：k = 1）**

```text
输入：s = "abcd", k = 1
输出："abcd"
解释：每块的反转段长度只有 1，反转长度为 1 的段是空操作。
```

## 3. 解题思路

### 3.1 暴力思路：照题面切块再拼接

最直白的实现是「切块 + 三条分支」：把 $s$ 按 $2k$ 切成若干子串，逐块判断

```text
if 块长 < k:        反转整块
elif 块长 < 2k:     反转前 k 个，其余保持
else:               反转前 k 个，后 k 个保持
```

再依次拼起来。复杂度同为 $O(n)$，但每块都 `substr` 拷贝一次，累计 $O(n)$ 额外空间；更麻烦的是分支边界——`块长 == k` 到底归第二条还是第三条、`块长 == 2k` 会不会多反转一段，都要靠试。

另一种更笨的纯模拟是**逐位反推源下标**：对每个输出位置 $j$，算出它属于哪一块、块内偏移、该偏移是否落在反转段内，再换算成源下标。逻辑上是 $O(n)$ 但常数大、下标表达式长，属于「能过但没必要」的写法（本文用它做对拍基准）。

> 本题是简单题，暴力已经是 $O(n)$ 最优，**不存在「用更好算法降复杂度」的空间**。复盘价值在于：把三条规则压成一条公式，让边界错误无处发生。

### 3.2 核心观察：三种剩余情况是一个 `min`

![以 2k 为周期分块：每块只反转前 k 个](images/wc23_q1_block_cycle_concept.svg)

设当前块起点为 $i$（$i = 0, 2k, 4k, \dots$），剩余长度 $m = n - i$，反转段长度 $L$。逐条翻译题面：

| 剩余 $m$ | 题面规则 | 反转段长度 $L$ | 右端点 $i + L$ |
|---|---|---|---|
| $m < k$ | 整块反转 | $m$ | $n$ |
| $k \le m < 2k$ | 只反前 $k$ 个 | $k$ | $i + k$ |
| $m \ge 2k$ | 反 $2k$ 块中的前 $k$ 个 | $k$ | $i + k$ |

三行合成一个式子：

$$L = \min(k,\ n - i),\qquad r = i + L = \min(i + k,\ n)$$

关键在于恒等式 $k \le n - i \iff i + k \le n$：于是

- $m < k$ 时 $i + k > n$，$\min$ 取 $n$，正好整段反转；
- $m \ge k$ 时 $i + k \le n$，$\min$ 取 $i+k$，正好只反前 $k$ 个。

**两类情况的分界线 $m = k$ 被 $\min$ 的分段点自动踩中**，不需要任何 `if`。

每块内部用**双指针**相向交换：$l = i$，$j = r - 1$，交换后 $l \leftarrow l+1$、$j \leftarrow j-1$，直到 $l \ge j$。交换次数 $\lfloor L/2 \rfloor$，长度奇数时中位字符原地不动。

### 3.3 算法流程

![算法流程：按 2k 步进，反转 [i, min(i+k,n))](images/wc23_q1_two_pointer_flow.svg)

1. **初始化**：$n \leftarrow \lvert s \rvert$，块起点 $i \leftarrow 0$。
2. **循环条件**：若 $i \ge n$，说明所有块处理完毕，返回 $s$。
3. **定右端点**：$r \leftarrow \min(i + k,\ n)$，反转区间为半开区间 $[i,\ r)$。
4. **区间反转**：双指针 $l = i$、$j = r - 1$，相向交换至 $l \ge j$（C++ 直接 `std::reverse`）。
5. **步进**：$i \leftarrow i + 2k$，回到第 2 步。

循环共执行 $\lceil n / (2k) \rceil$ 轮，每轮反转的字符数为 $\min(k,\ n-i)$。

### 3.4 示例演算

![示例演算：abcdefg 与 abcd 的逐轮结果](images/wc23_q1_walkthrough.svg)

**示例 1** `s = "abcdefg"`，$k = 2$，$2k = 4$：

| 轮次 | 反转区间 | 变化 | 当前串 |
|---|---|---|---|
| $i = 0$ | $[0, 1]$ | `ab` → `ba`，`cd` 不动 | `bacdefg` |
| $i = 4$ | $[4, 5]$ | `ef` → `fe`，`g` 不动 | `bacdfeg` |
| $i = 8$ | $8 \ge 7$ 退出 | — | `bacdfeg` ✓ |

**示例 2** `s = "abcd"`，$k = 2$：

| 轮次 | 反转区间 | 变化 | 当前串 |
|---|---|---|---|
| $i = 0$ | $[0, 1]$ | `ab` → `ba`，`cd` 不动 | `bacd` |
| $i = 4$ | $4 \ge 4$ 退出 | — | `bacd` ✓ |

**边界**：`s = "abcdefg"`、$k = 5$ 时 $2k = 10$，剩余 $7 \ge k$ 但 $< 2k$，只反前 5 个 → `edcbafg`；`s = "abc"`、$k = 5$ 时剩余 $3 < k$，整段反转 → `cba`。

## 4. 算法细节

1. **步进是 $2k$ 而不是 $k$**：循环变量代表**块起点**，块内已经同时包含「反转区」和「保持区」，所以一次跨过 $2k$。写成 $i \mathrel{+}= k$ 会把本该保留的后 $k$ 个也反转。
2. **右端点用 $\min(i+k,\ n)$**：这是整份代码唯一的「边界开关」，缺了它 C++ 会在 $\lvert s \rvert < i+k$ 时构造越界迭代器（未定义行为），而 Python 切片恰好自带截断，会把错误藏起来——同一份思路在两种语言里的安全性并不对等。
3. **半开区间 $[i,\ r)$ 与切片天然对齐**：C++ 的 `reverse(s.begin()+i, s.begin()+r)` 与 Python 的 `a[i:i+k]` 都不含右端点，不需要 $r-1$ 修正；闭区间写法才需要 `min(i+k, n) - 1`，两者混用是最常见的一处 off-by-one。
4. **双指针交换次数 $\lfloor L/2 \rfloor$**：$L$ 为奇数时中位字符自己和自己配对，不必交换；$L = 1$（$k = 1$ 或末尾只剩 1 个字符）时一次交换都不做，结果不变。
5. **Python 切片赋值的长度安全**：`a[i:i+k] = a[i:i+k][::-1]` 两侧都按同一区间截断到 $n$，长度必然相等，不会意外改变列表长度；若写成 `a[i:i+k] = ...` 而右侧长度不同，就会变成插入/删除操作。
6. **空间开销的两种口径**：C++ 函数签名按值传入 `string s`，进入函数时已拷贝一份 $O(n)$；若追求严格 $O(1)$ 额外空间需改为引用就地修改。Python 中 `list(s)` 与 `"".join(...)` 合计 $O(n)$，这是语言层无法避免的。
7. **可推广的写法**：把 $k$ 换成随块变化的 $k_t$，只需把右端点改成 $\min(i + k_t,\ n)$，循环骨架不变——「步进 + 定右端点 + 局部反转」是这个模式的通用模板。

## 5. 正确性证明

**引理 1（区间不交且不越界）**：对每个满足 $i < n$ 的块起点 $i = 2kt$，反转区间 $[i,\ \min(i+k,\ n))$ 含于 $[0,\ n)$；且不同块的反转区间两两不交。

**证明**：左端点 $i \ge 0$，右端点 $\min(i+k,\ n) \le n$，故含于 $[0,\ n)$。设 $i < i'$ 是两个相邻块起点，$i' = i + 2k$，则 $i' \ge i + 2k > i + k \ge \min(i+k,\ n)$，即 $i'$ 严格大于前一个区间的右端点，区间不交；不相邻的块由传递性同样不交。∎

**引理 2（逐位一致）**：设位置 $p$ 属于块 $t$（$i = 2kt \le p < i + 2k$，且 $p < n$），记 $L = \min(k,\ n - i)$、偏移 $d = p - i$。则算法输出满足

$$
\text{out}[p] = \begin{cases} s[i + L - 1 - d], & d < L\\ s[p], & d \ge L \end{cases}
$$

**证明**：算法对区间 $[i,\ i+L)$ 做首尾交换，交换把区间内第 $d$ 个字符换到第 $L-1-d$ 个位置，双向对称，故 $d < L$ 时 $\text{out}[p] = s[i + L - 1 - d]$。$d \ge L$ 时 $p \notin [i,\ i+L)$，由引理 1，$p$ 不被任何反转区间覆盖，$\text{out}[p] = s[p]$。∎

**定理（题面一致性）**：算法返回的字符串与题面三条规则定义的字符串逐位相同。

**证明**：块的划分与题面「每数满 $2k$ 个字符重新计数」一致（步进恰为 $2k$，最后一块允许不满）。设剩余 $m = n - i$：

- $m < k$ 时 $L = m$，由引理 2 整块反转，符合题面第一条；
- $k \le m < 2k$ 时 $L = k$，前 $k$ 个反转、后 $m-k$ 个保持，符合题面第二条；
- $m \ge 2k$ 时 $L = k$，即 $2k$ 块中前 $k$ 个反转、后 $k$ 个保持，符合题面主规则「反转 $2k$ 个字符中的前 $k$ 个」（此时该块是完整块）。

三种情况覆盖所有 $m \ge 1$，且每块内逐位由引理 2 确定，故整体逐位相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。循环 $\lceil n/(2k) \rceil$ 轮；每轮反转 $\min(k,\ n-i)$ 个字符，做 $\lfloor L/2 \rfloor$ 次交换，所有轮的交换次数之和不超过 $n/2$，即每个字符至多被访问常数次。
- **空间复杂度**：$O(1)$ 额外空间（不计输入/输出）。C++ 的双指针只在原地交换两个 `char`，只用 $l, j, i, r$ 四个整型变量；Python 版因字符串不可变，`list(s)` 与 `"".join(...)` 各需 $O(n)$ 空间，属语言特性。若计入 C++ 按值传参的形参拷贝，则为 $O(n)$。
- **数值规模**：$n \le 10^4$ 时交换次数 $\le 5000$，$k$ 最大 $10^4$ 也不会溢出任何 32 位整型；循环变量用 `int` 足够。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string reverseStr(string s, int k) {
        int n = (int)s.size();
        // 块起点以 2k 步进；右端点用 min 兜住「剩余不足 k」与「跨过末尾」两种情况
        for (int i = 0; i < n; i += 2 * k) {
            // 半开区间 [i, min(i + k, n)) 恰好是「块内前 k 个」
            reverse(s.begin() + i, s.begin() + min(i + k, n));
        }
        return s;
    }
};
```

> 需要 `#include <algorithm>`（LeetCode 环境已隐式包含 `std::reverse`）。

### Python

```python
class Solution:
    def reverseStr(self, s: str, k: int) -> str:
        a = list(s)
        n = len(a)
        for i in range(0, n, 2 * k):
            # 切片右端自动截断到 n，等价于 min(i + k, n)
            a[i:i + k] = a[i:i + k][::-1]
        return "".join(a)
```

等价的纯双指针写法（不依赖切片，便于迁移到可变字符数组的语言）：

```python
class Solution:
    def reverseStr(self, s: str, k: int) -> str:
        a = list(s)
        n = len(a)
        for i in range(0, n, 2 * k):
            l, r = i, min(i + k, n) - 1
            while l < r:
                a[l], a[r] = a[r], a[l]
                l += 1
                r -= 1
        return "".join(a)
```

## 8. 边界情况与易错点

1. **忘记 `min`，右端点越界**：$\lvert s \rvert = 3$、$k = 5$ 时 `i + k = 5 > 3`，C++ 的 `s.begin() + 5` 越过 `end()`，`std::reverse` 行为未定义（实践中可能崩溃或悄悄改坏内存）。Python 切片不报错，会把这类错误带到下一题。
2. **$k \ge n$ 时整串反转**：如 `"abcdefg"`、$k = 10$，第一轮 $r = \min(10, 7) = 7$，整串反转后 $i = 20 \ge 7$ 立即退出，答案是 `"gfedcba"`。
3. **$k = 1$ 是空操作**：每块反转段长 1，`l < r` 从不成立，答案必然等于原串。可以用一组随机数据在 $k = 1$ 时自检：若输出与输入不同，说明右端点或步进写错了。
4. **剩余恰好 $k$**：如 `"abcdef"`、$k = 2$，第二轮 $i = 4$、剩余 $2 = k$，只反转 `"ef"` 这两个，不能因为「不足 $2k$」就跳过反转。
5. **步进写成 `k`**：`i += k` 会让「保持区」的起点也成为块起点，`"abcdefg"`、$k=2$ 时第二轮从下标 2 开始反转，错误表现得像「多反了一段」。这是本题最高频的 WA。
6. **半开区间与闭区间混用**：`reverse(s.begin()+i, s.begin()+min(i+k,n))` 是对的；若下意识写成 `s.begin() + min(i+k, n) - 1`，末字符会被漏掉（$k=2$ 时只交换 `a` 与自身，输出 `"abcdefg"` 原串）。
7. **`k` 与 `2k` 的乘法**：$k = 10^4$ 时 $2k = 2\times10^4$，用 `int` 无虞；但若把步进写成 `i = i * 2` 或位移运算，会得到错误的块序列。

**延伸思考**：

1. **反转后 $k$ 个**：把区间改成 $[\min(i+k,\ n),\ i+2k)$ 即可，但要注意「剩余 $<k$ 时整段反转」这条规则会随之改写，$O(1)$ 状态不再够用。
2. **块大小与 $k$ 解耦**：若规则改为「每 $m$ 个字符反转前 $t$ 个」，右端点变成 $\min(i+t,\ n)$、步进变成 $m$，模板完全不变。
3. **流式处理**：若 $s$ 长到无法一次读入（例如从网络流读取），只需维护一个大小为 $2k$ 的缓冲区：攒满 $2k$ 个就反转前 $k$ 个并输出，最后不足一块时按同一 $\min$ 规则收尾，空间 $O(k)$ 与总长无关。
4. **按字符而非字节反转**：本题限定小写字母，`char` 即字符；若输入含 UTF-8 多字节字符（中文、emoji），必须先按字形簇切分成字符数组再反转，否则会把一个字符的字节拆散，产生乱码。
