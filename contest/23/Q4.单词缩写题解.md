# LeetCode 单词缩写 题解

## 1. 题目概述

- **标题 / 题号**：单词缩写（#527，hard）
- **链接**：https://leetcode.cn/problems/word-abbreviation/
- **来源**：LeetCode 第 23 场周赛 Q4
- **难度**：困难
- **标签**：贪心、字典树、数组、字符串、排序

**题意**：给定 $n$ 个**互不相同**的非空小写串，为每个串生成「最短且互不撞车」的缩写。缩写格式为：**取首 $p$ 个字符 + 中间被省略的字符个数 + 末字符**（$p$ 从 1 开始）。若多个串撞上同一缩写，就让这些撞车的串**同步**把 $p$ 加一，直到映射唯一；若最终缩写没能让串变短，则保留原串。按原下标顺序返回。

**约束**：

- $1 \le n \le 400$
- 每个串的长度 $> 1$，且不超过 $400$
- 串只含小写英文字母
- 输出顺序必须与输入一致

> 💡 **审题关键**：缩写里那个**数字**不是装饰，它是「长度指纹」——$\mathrm{cnt} = L - p - 1$ 反解出原串长度 $L$，所以**不同长度的串永远不可能撞车**。这一条把「全体 $n$ 个串互相比较」压成了「组内比较」，是本题所有解法的共同地基。

> 💡 本题在本仓库另有[每日题解 527](../../solution/0501-0600/527_单词缩写.md)：以「分组 + 最长公共前缀」为主线。本篇按**周赛复盘视角**重写，主线是**逐层分桶的贪心（迭代加深）**——侧重「为什么可以按层整体推进」的两条单调性、引理—定理闭环，以及定稿/回退三态在实现上的踩坑点。

## 2. 示例

**示例 1**

```text
输入：words = ["like","god","internal","me","internet","interval","intension","face","intrusion"]
输出：["l2e","god","internal","me","i6t","interval","inte4n","f2e","intr4n"]
解释：like → l+2+e；internal 与 interval 首层同为 i6l，加长到 inte3l 仍撞，第 6 层才分成
      intern1l / interv1l —— 但长度 8 等于原长，故双双保留原串；god 的 g1d 同样没变短。
```

**示例 2**

```text
输入：words = ["aa","aaa"]
输出：["aa","aaa"]
解释：aa 长度 2，摘不出中间部分；aaa 的 a1a 长度 3 = 原长，都不算变短。
```

**示例 3**（自拟：唯一性是「同层」概念）

```text
输入：words = ["aa","aaa","aaaa"]
输出：["aa","aaa","a2a"]
解释：aaaa 的 p=1 缩写 a2a 长度 3 < 4 且全场唯一，直接定稿；它不必和 aaa 的 a1a 比——
      两者数字段不同（2 与 1），本来就撞不上。
```

**示例 4**（自拟：撞到尽头只能回退）

```text
输入：words = ["abcde","abxde"]
输出：["abcde","abxde"]
解释：二者等长、首 a 末 e 全同，只差倒数第二个字符。p=1 撞 a3e，p=2 撞 ab2e，
      p=3 的 abc1e 长度已等于原长，故都保留原串。
```

## 3. 解题思路

### 3.1 暴力思路：逐串试前缀

对每个串独立地枚举前缀长度 $p = 1, 2, \dots$，每次把本串的缩写与**其余所有串**在同一 $p$ 下的缩写逐一比较，取第一个不撞且更短者：

```text
for each w:
    for p = 1 .. L-2:
        a = abbr(w, p)
        if len(a) >= L: break
        if 对所有 w' != w、len(w') == L 都有 abbr(w', p) != a: 取 a; break
```

正确但昂贵：$O(n)$ 个串 × $O(L)$ 个前缀长度 × $O(n)$ 个比较对象 × $O(L)$ 次字符比较 = $O(n^2L^3)$，$n = L = 400$ 时约 $2.6\times10^{10}$，不可行。更要命的是它**重复劳动**：同一个 $p$ 层被每个串各扫了一遍，而「谁撞谁」在这一层是**公共信息**。

### 3.2 核心观察：长度指纹 + 短路规则，让层可以整体推进

![核心观察：缩写自带长度指纹，撞车只发生在同长、同首段、同末字符的串之间](images/wc23_q4_abbr_conflict_concept.svg)

把缩写记作 $\text{abbr}_p(w) = w[0:p] \cdot \mathrm{cnt} \cdot w[L-1]$，其中 $\mathrm{cnt} = L-p-1$，长度

$$f(p) = p + \operatorname{digits}(L-p-1) + 1 .$$

缩写串的形态是「纯字母段 + 纯数字段 + 单字母」，**分解唯一**，于是有两条把问题「压平」的性质：

- **层间不可比**：缩写相等 ⟹ 字母段长度 $p$ 相等、数字段数值 $L-p-1$ 相等 ⟹ 层号相同且原串等长。所以撞车判定可以**只在同一层内做**；
- **层内三要素**：第 $p$ 层撞车 ⟺ 等长、前 $p$ 个字符相同、末字符相同，缺一不可。

再补两条**单调性**，它们决定了「逐层加深」是合法的而不是盲试：

- **唯一性单调**：第 $p$ 层已经独一无二，第 $p+1$ 层必然还是（前缀更长，只会更少撞）；
- **长度单调**：$f(p)$ 随 $p$ **不减**（$p$ 加 1 最多省掉一位数字）。于是一旦 $f(p) \ge L$，再加前缀也永远不短 —— 立刻判定为「保留原串」，永不复查。

两条合起来给出直接的结论：**每个串的答案就是「最浅的、独一无二的那一层」**，而这一层可以按 $p$ 从小到大整体扫出来。

### 3.3 算法流程：逐层分桶，桶内独苗定稿

![算法流程：逐层 p 分桶，桶内独苗定稿，撞车的留到下一层](images/wc23_q4_abbr_round_flow.svg)

1. `res[i] = ""`、`done[i] = False`、`remaining = n`，层号 `p = 1`；
2. 只要 `remaining > 0`，就做一轮**整层分桶**：遍历所有未定稿的串
   - 若 `p > L-2`（cnt 会变成 0 或负数）或 `len(abbr) >= L`（没变短）→ 该串**永久**落定为原串，`done = True`、`remaining -= 1`，本轮不再参与分桶；
   - 否则计算 `abbr`，把它塞进 `bucket[abbr]` 的下标列表；
3. **整层插完之后**统一判定：桶里只有 1 个下标 → 它在该层唯一，定稿为这个缩写，`done = True`、`remaining -= 1`；桶里有多个 → 谁都不定稿；
4. `p += 1` 回到第 2 步；`remaining == 0` 时按原下标输出 `res`。

关键不变量：**所有未定稿串的层号恒等于当前轮次**（初始化都是 1，每轮只有「定稿」或「+1」两种去向）。所以一轮分桶里的比较永远发生在同一层，与 §3.2 的「层间不可比」恰好对上，不存在跨层误判。

### 3.4 示例演算

![示例演算：4 个 i 开头串的逐层分桶拆解](images/wc23_q4_abbr_walkthrough.svg)

拿示例 1 的 4 个 `i` 开头串走查（`internal`/`interval` 长 8，`intension`/`intrusion` 长 9）：

- **第 1 层**：`internal` 与 `interval` 同为 `i6l`，`intension` 与 `intrusion` 同为 `i7n`，两个桶各有 2 人，全部不动；`like`→`l2e`、`internet`→`i6t`、`face`→`f2e` 各自独苗，当场定稿；`god` 的 `g1d` 长度 3 = 原长，直接回退；`me` 长度 2 连 cnt 都凑不出，一并回退；
- **第 2、3 层**：`in5l`/`in6n`/`int4l`/`int5n` 依旧两两相撞 —— 撞车伙伴的第 2、3 个字符完全相同；
- **第 4 层**：`intension`→`inte4n`、`intrusion`→`intr4n`，第 4 个字符 `e`/`r` 终于分叉，**双双定稿**；而 `internal`/`interval` 第 4 个字符同为 `e`，仍撞在 `inte3l`；
- **第 5、6 层**：`inter2l` 继续撞，第 6 层才分成 `intern1l`/`interv1l`，此时长度已等于 8，按单调性判为「不可能更短」，两者都保留原串。

输出 `["l2e","god","internal","me","i6t","interval","inte4n","f2e","intr4n"]` ✓ 与官方一致。全部 9 个串最多走到第 6 层，累计仅 25 次建串。

## 4. 算法细节

1. **三态落定缺一不可**：`(a)` 桶内独苗 → 定稿为该缩写；`(b)` `p > L-2` → 回退原串；`(c)` `len(abbr) >= L` → 回退原串。`(b)(c)` 都必须在**建串之前/建串当下**就判掉并 `done = True`，否则它每轮都会重新入桶，`remaining` 永远减不到 0。
2. **`remaining` 的三处递减**：`(b)(c)` 分支各一次、桶内独苗一次。这是最容易漏的地方——漏一处就退化成死循环，而 `n = 400` 时死循环会稳定 TLE 而不是报错，很难定位。
3. **必须整层插完再判独苗**：若边插边判，先插进去的串会被后到的同缩写伙伴「追尾」，结果把非唯一的缩写当成答案。分两趟（先建桶、再遍历桶）是硬性要求。
4. **`p > L-2` 必须先挡**：$L = 2$ 时 `L-p-1 = -1`，`to_string(-1)` / `str(-1)` 会产出 `-1`，缩写直接变成 `m-1e` 这种带负号的非法串，后续所有比较都被污染。
5. **数字段无前导零**：`to_string` 与 Python 的 `str` 都不补零，这正是 §5 引理 1「分解唯一」的依赖点；如果换成补零格式化，$p$ 与 $L$ 就反解不出来了。
6. **用桶的 key 直接当答案**：定稿时 `res[idx] = abbr`（C++ 里是 `kv.first`），不必再按 $p$ 重算一次前缀。
7. **回退时用** `res[i] = words[i]`，不要写 `substr(0, L)` 之类；原串本身也是合法的「答案」，且原串只含字母、缩写必含数字，二者天然不冲突（见 §5 推论）。

## 5. 正确性证明

**引理 1**（层间不可比）：设 $p, p' \ge 1$。若 $\text{abbr}_p(w) = \text{abbr}_{p'}(w')$，则 $p = p'$ 且 $|w| = |w'|$。

**证明**：缩写串形如「纯小写字母段 $A$ + 纯数字段 $D$ + 单个小写字母」，且 $D$ 无前导零。字母与数字不相交，故这种三段分解是唯一的；于是 $|A| = p$、$|D|$ 的数值为 $|w| - p - 1$。两边缩写相等 ⟹ 分解一致 ⟹ $p = p'$ 且 $|w| - p - 1 = |w'| - p' - 1$，即 $|w| = |w'|$。∎

**引理 2**（唯一性单调）：若 $w$ 在第 $p$ 层唯一（即与一切等长串 $w' \ne w$ 都有 $\text{abbr}_p(w') \ne \text{abbr}_p(w)$），且 $p+1 \le L-2$，则 $w$ 在第 $p+1$ 层也唯一。

**证明**：反设存在等长串 $w'$ 使 $\text{abbr}_{p+1}(w') = \text{abbr}_{p+1}(w)$。由引理 1 证明中的三段分解，两边 $|A| = p+1$，即二者前 $p+1$ 个字符相同，故前 $p$ 个字符也相同；末字符、长度已相同。于是 $\text{abbr}_p(w') = \text{abbr}_p(w)$，与第 $p$ 层唯一矛盾。∎

**引理 3**（长度单调）：在 $1 \le p \le L-2$ 上，$f(p) = p + \operatorname{digits}(L-p-1) + 1$ 单调不减。

**证明**：$f(p+1) - f(p) = 1 + \operatorname{digits}(L-p-2) - \operatorname{digits}(L-p-1)$。随 $p$ 增大，数字段数值减少 1，位数只可能不变或减 1，故 $\operatorname{digits}(L-p-2) - \operatorname{digits}(L-p-1) \in \{-1, 0\}$，差为 $0$ 或 $1$，非负。∎

**引理 4**（最浅唯一层即答案）：记 $p^*$ 为 $w$ 的最浅唯一层。若 $f(p^*) < L$，则 $\text{abbr}_{p^*}(w)$ 是 $w$ 的最短可行缩写；若 $f(p^*) \ge L$，则 $w$ 不存在可行缩写。

**证明**：$p < p^*$ 时 $w$ 在该层不唯一，与某个等长串的缩写相同，按题意不可用。$p \ge p^*$ 时由引理 3 得 $f(p) \ge f(p^*)$，故若 $f(p^*) \ge L$ 则所有层的缩写都不比原串短，无可行缩写；若 $f(p^*) < L$，则 $p^*$ 层可行且长度是全部可行层中最小的（更小的层不可行），即为最短。∎

**定理**：逐层分桶算法输出的数组正是题目要求的答案。

**证明**：由算法不变量，第 $r$ 轮所有未定稿串的层号都是 $r$，故每轮分桶恰是「第 $r$ 层内」的比较（引理 1 保证跨层不可能撞，不会被漏检）。

- **定稿的串**：若 $w$ 在第 $r$ 轮因桶内独苗而定稿，则它在第 $1..r-1$ 轮都落在多人桶中（每轮都未定稿且未回退），即前 $r-1$ 层都不唯一；第 $r$ 层桶大小为 1，即唯一。故 $r = p^*$，由引理 4 输出即最短可行缩写。
- **回退的串**：在第 $r$ 轮因 $r > L-2$ 或 $f(r) \ge L$ 而落定为原串。此时 $p^* \ge r$（否则第 $p^* < r$ 层就该定稿），由引理 3 得 $f(p^*) \ge f(r) \ge L$，引理 4 说明 $w$ 确无可行的更短缩写，保留原串正确。
- **顺序**：结果按原下标写回 `res`，满足「与输入同序」。

故算法正确。∎

**推论**（最终映射单射）：不会有两个串输出同一个缩写。

**证明**：若 $w \ne w'$ 的最终答案相同，二者必都是缩写（原串互不相同）。设分别在层 $p, p'$ 定稿，由引理 1 得 $p = p'$ 且等长；但同层定稿要求该桶大小为 1，两者不可能同时定稿于同一桶，矛盾。另一方面，**回退的原串只含小写字母，而任何缩写都必含数字段**（$\mathrm{cnt} \ge 1$），因此原串也不可能与某个缩写串相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(nL^2)$。外层层数至多 $\max L \le 400$（$p$ 单调递增，超过 $L-2$ 即全员落定）；每层扫一遍未定稿串，每串拼接并哈希一个长度 $O(L)$ 的缩写串，故单层 $O(nL)$。代入 $n = L = 400$ 约 $6.4\times10^7$ 个字符级操作，且未定稿集合逐层收缩，实测 Python 约 $0.09$ s、C++ 约 $0.03$ s（400 个长 398 且前 395 字符全同的极端串）。
- **空间复杂度**：$O(nL)$。桶里最多同时存放 $n$ 个长度不超过 $L$ 的缩写串，加上 `res`（$nL$）与两个长度为 $n$ 的标记数组；哈希表的键数不超过 $n$。递归栈为 $O(1)$（纯迭代）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
  public:
    vector<string> wordsAbbreviation(vector<string>& words) {
        int n = words.size();
        vector<string> res(n);
        vector<char> done(n, 0);
        int remaining = n;

        for (int p = 1; remaining > 0; ++p) {
            unordered_map<string, vector<int>> bucket;   // 本层：缩写 -> 下标列表
            for (int i = 0; i < n; ++i) {
                if (done[i]) continue;
                int L = words[i].size();
                if (p > L - 2) {                          // cnt 会变成 0 / 负数
                    res[i] = words[i]; done[i] = 1; --remaining; continue;
                }
                string a = words[i].substr(0, p) + to_string(L - p - 1) + words[i].back();
                if ((int)a.size() >= L) {                 // 没变短：永久回退原串
                    res[i] = words[i]; done[i] = 1; --remaining; continue;
                }
                bucket[a].push_back(i);
            }
            for (auto& kv : bucket)                       // 整层插完再判独苗
                if (kv.second.size() == 1) {
                    int i = kv.second[0];
                    res[i] = kv.first; done[i] = 1; --remaining;
                }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def wordsAbbreviation(self, words: List[str]) -> List[str]:
        n = len(words)
        res = [""] * n
        done = [False] * n
        remaining, p = n, 1

        while remaining:
            bucket = {}                                    # 本层：缩写 -> 下标列表
            for i, w in enumerate(words):
                if done[i]:
                    continue
                L = len(w)
                if p > L - 2:                              # cnt 会变成 0 / 负数
                    res[i], done[i], remaining = w, True, remaining - 1
                    continue
                a = w[:p] + str(L - p - 1) + w[-1]
                if len(a) >= L:                            # 没变短：永久回退原串
                    res[i], done[i], remaining = w, True, remaining - 1
                    continue
                bucket.setdefault(a, []).append(i)
            for a, idx in bucket.items():                  # 整层插完再判独苗
                if len(idx) == 1:
                    res[idx[0]] = a
                    done[idx[0]] = True
                    remaining -= 1
            p += 1
        return res
```

> ⚠️ 两版刻意同构，对照着读只需盯三处：两个「永久回退」分支必须同时 `done = True` 与 `remaining -= 1`；桶内判定放在两层循环**之间**；`res[i] = words[i]` 而不是任何重新拼接出来的串。

## 8. 边界情况与易错点

1. **长度 2 的串**：$p = 1$ 时 $L-p-1 = -1$，必须先被 `p > L-2` 挡下。否则 `to_string(-1)` 产出 `-1`，得到 `m-1e` 这类带负号的假缩写，判重和长度比较全线崩坏。
2. **长度 3 的串**（`god`）：`g1d` 长度 3 与原串**等长**。题面要求「没让串变短就保留原串」，所以判据是 `len(a) < L` 而不是 `<=`；写成 `<=` 会输出 `g1d`，示例 1 直接挂。
3. **撞到尽头的行为**：`internal`/`interval` 要到第 6 层才分叉、`abcde`/`abxde` 一辈子分不开。必须允许「撞到 $p$ 越界后优雅回退」，而不是假设一定能分开——否则要么死循环，要么在 $p = L-1$ 时拼出 cnt = 0 的怪串。
4. **判独苗的时机**：整层插完再遍历桶。边插边判会把「先来者」误当成唯一，示例 1 的 `internal` 就会错定成 `i6l`。
5. **`remaining` 递减点**：三个分支各减一次，缺一则 while 永不退出。这类 bug 在 $n = 400$ 的小数据上表现为 TLE 而不是答案错误，排查成本很高。
6. **不要跨层比较**：把判定写成「整个数组里这个缩写出现几次」在语义上就是错的——第 3 层的 `int4l` 与第 4 层的 `inte3l` 本就不该互相干扰（引理 1）；分层桶天然避免了这一点。
7. **不要按定稿顺序 append**：定稿是乱序发生的（第 4 层先定 `intension`、第 1 层就定了 `like`），必须用原下标写回 `res`。
8. **重复串不必去重**：题面保证互不相同；若强行去重，反而破坏了「输入下标 → 输出下标」的一一映射。

**延伸思考**：① 从 LCP 视角看，本算法求出的最浅唯一层恰为 $p^* = 1 + \max_{w' \ne w,\ \text{同长同末}} \operatorname{LCP}(w, w')$（无同组伙伴时 $p^* = 1$）——因为 $\text{abbr}_p$ 相同当且仅当 $p \le \operatorname{LCP}$。由此可把「逐层扫」换成「组内排序后只看相邻串的 LCP」（字典序下 LCP 最大者必是邻居），复杂度降到 $O(nL\log n)$。② 把「同 (长度, 末字符) 组」的中间部分建 Trie，则 $p^*$ 就是「从根往下第一个子树单词数恰为 1 的深度」，一趟 DFS 得到全部答案，做到 $O(nL)$ 与 $O(nL)$ 空间——这是本题最优的写法，也是标签里 `Trie` 的落点。③ 若推广成「保留首尾各 $k$ 个字符」，缩短判据变为 $2k + \operatorname{digits}(L-2k) < L$，逐层加深的骨架原封不动，只是每层的「前缀」变成「前缀 + 后缀」。
