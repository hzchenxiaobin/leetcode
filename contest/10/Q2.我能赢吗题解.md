# LeetCode 我能赢吗 题解

## 1. 题目概述

- **标题 / 题号**：我能赢吗（#464，medium）
- **链接**：https://leetcode.cn/problems/can-i-win/
- **来源**：LeetCode 第 10 场周赛 Q2
- **难度**：中等
- **标签**：位运算、记忆化搜索、数学、动态规划、状态压缩、博弈论

**题意**：整数池里有 $1 \sim \text{maxChoosableInteger}$ 的每个整数各一个。两名玩家轮流从池中取走一个**尚未被取走**的整数，累加到公共总和上；谁在某一手之后让总和 $\ge \text{desiredTotal}$，谁**立即获胜**，游戏结束。两人都按最优策略行动，问**先手**是否能保证获胜。

**约束**：

- $1 \le \text{maxChoosableInteger} \le 20$
- $0 \le \text{desiredTotal} \le 300$

两个上限各给出一个关键事实。其一，$n = 20$ 时池中数字的总和只有 $\frac{20 \times 21}{2} = 210$，所以 $\text{desiredTotal} > 210$ 时谁都不可能达标。其二，$n \le 20$ 意味着「已取数字的集合」至多 $2^{20} \approx 1.05 \times 10^{6}$ 种，正好够做**状态压缩**。

## 2. 示例

**示例 1**

```text
输入：maxChoosableInteger = 10, desiredTotal = 11
输出：false
解释：先手取 x 后，后手总取 11 − x：两轮累计和恰为 11 ≥ 11，
      后手先达标，先手没有任何一手能翻盘。
```

**示例 2**

```text
输入：maxChoosableInteger = 10, desiredTotal = 0
输出：true
解释：开局累计和 0 已经 ≥ 0，先手不必出手就已达成目标（官方口径按 true 计）。
```

**示例 3**

```text
输入：maxChoosableInteger = 10, desiredTotal = 1
输出：true
解释：先手直接取 1，累计和 1 ≥ 1，一步获胜。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是把整棵博弈树搜一遍：每一层枚举所有未取的数字，走到「某一手让总和 $\ge T$」或「数字取完」为止。总路径数是

$$\sum_{k=0}^{n} \frac{n!}{(n-k)!} \approx e \cdot n!$$

$n = 20$ 时约 $10^{18}$ 量级，完全不可行；即使 $n = 10$，也有近 $10^{7}$ 条路径，明显超时。

但注意一个反差：不同的**取数顺序**会反复到达同一个「已取集合」。$n = 10$ 时集合只有 $2^{10} = 1024$ 个，路径却有上千万条——状态空间远小于路径空间。这就是记忆化搜索的切入点。

### 3.2 核心观察：局面 = 位掩码，胜负沿博弈树互推

![局面压缩成 mask，胜负自底向上互推](images/wc10_q2_game_tree_concept.svg)

**观察 1（状态只由集合决定）**：刻画一个局面需要两样信息——「哪些数已被取走」与「当前累计和」。而后者是前者的函数：把 $mask$ 中为 1 的位所对应的数字集合记作 $S(mask)$，则

$$\text{used}(mask) = \sum_{i \in S(mask)} i$$

于是局面可以压成一个 $n$ 位二进制数 $mask$：第 $i-1$ 位为 1 表示数字 $i$ 已被取走。状态数不超过 $2^{n}$，且**累计和不必进状态**。

**观察 2（一步定胜负）**：设 $T = \text{desiredTotal}$。站在 $mask$ 上轮到的玩家必胜，当且仅当存在某个未取的数字 $i$ 满足

$$\text{used}(mask) + i \ge T \qquad \text{或} \qquad W\bigl(mask \mid 2^{i-1}\bigr) = \text{必败}$$

前者是「这一手直接达标」，后者是「这一手把对手送进必败局面」。反之，若所有可走的手都让对手进入必胜态，本局面就是必败态。合起来：

$$W(mask) = \bigvee_{i \notin mask}\Bigl[\,\text{used}(mask) + i \ge T \ \lor\ \lnot W(mask \mid 2^{i-1})\,\Bigr]$$

这是标准的**有限无环博弈**递推：每走一步 $mask$ 就多一个 1，状态图是 DAG，从「位数更多」往「位数更少」回填，不会循环。

> 💡 一句话记住：**「已取集合」才是状态，「累计和」只是它的函数**。把这两件事拆开，$n!$ 条路径的博弈树就塌缩成 $2^{n}$ 个节点的 DAG。

**观察 3（本题没有和局）**：会不会出现「数字取完、谁都没到 $T$」的和局？只要 $\frac{n(n+1)}{2} \ge T$ 就不会——取光全部数字时累计和恰为总和，必然在某一手中已经越过 $T$。正因如此，先做「$\frac{n(n+1)}{2} < T$ 直接返回 `false`」的特判，就能把和局这种第三态彻底排除，让递推只剩「胜 / 负」两态。

### 3.3 算法流程 / 状态转移

![记忆化搜索的执行流程](images/wc10_q2_dfs_memo_flow.svg)

1. 特判 ①：$T \le 0$ → 返回 `true`（开局累计和已达标）。
2. 特判 ②：$\frac{n(n+1)}{2} < T$ → 返回 `false`（取光也凑不到）。
3. 特判 ③：$n \ge T$ → 返回 `true`（先手直接取 $T$ 这一手）。
4. 从 $mask = 0$、$used = 0$ 开始深搜：枚举每个未取的 $i$，先看 $used + i \ge T$ 是否成立，成立即返回 `true`；否则递归 $mask \mid 2^{i-1}$，若对手在该子局面必败（递归返回 `false`），则当前局面必胜。
5. 所有分支都失败 → 当前局面必败，返回 `false`。
6. 用 `memo[mask]` 缓存胜负；因为 $\text{used}$ 是 $mask$ 的函数，键只需要 $mask$。

### 3.4 示例演算

![n=5、T=8 的配对走查](images/wc10_q2_walkthrough.svg)

取 $n = 5$、$T = 8$（总和 $15 \ge 8$，不触发特判）。先手第一步取 1，池中剩 $2,3,4,5$，而「距离目标还差 7」恰好可以两两配对：

$$2 + 5 = 3 + 4 = 7$$

后手取 $y$，先手就取 $7 - y$，两轮之后累计和必然到 $1 + 7 = 8$，先手先达标：

| 后手取 $y$ | 先手取 $7-y$ | 累计和 | 判定 |
|---|---|---|---|
| 2 | 5 | 8 | $\ge 8$，先手胜 |
| 3 | 4 | 8 | $\ge 8$，先手胜 |
| 4 | 3 | 8 | $\ge 8$，先手胜 |
| 5 | 2 | 8 | $\ge 8$，先手胜 |

于是 $mask = \{1\}$ 是必败态（轮到谁谁输），`dfs` 只需试到「取 1」就能返回 `true`。

**示例 1 是同一套配对的镜像**：$T = 11$ 为奇数，先手取 $x$（$1 \le x \le 10$）之后，后手取 $11 - x$ 必然合法——$11 - x \ne x$（奇数保证不会自己配自己），且 $1 \le 11 - x \le 10$。两轮累计恰为 11，后手先达标，所以返回 `false`。由此可推广出两个 $O(1)$ 判据：**若 $T$ 为奇数且 $n = T - 1$，先手必败**；**若 $T = \frac{n(n+1)}{2}$（必须取光所有数），则 $n$ 为奇数时先手胜、为偶数时后手胜**。

## 4. 算法细节

1. **特判顺序**：$T \le 0$ 必须最先判；$\frac{n(n+1)}{2} < T$ 一定要在深搜之前判（见 §8 第 2 条的反例）；$n \ge T$ 可省一次完整搜索。
2. **位的表示**：数字 $i$ 对应 `1 << (i-1)`，即 $mask$ 的第 $i-1$ 位。$n \le 20$ 时 `1 << n` 在 32 位 `int` 内安全；若上限放大到 31，`1 << n` 会溢出成负数，须改用 `1LL << n`。
3. **memo 用三态**：0 = 未计算、1 = 必胜、−1 = 必败。C++ 用 `vector<signed char>` 分配 $2^{n}$ 字节（$n=20$ 约 1 MB）。**不能**用「`false` 既表示没算过又表示必败」的二态写法，否则必败态会被反复重算。
4. **键里只放 $mask$**：$\text{used}$ 由 $mask$ 唯一确定，塞进键会让缓存体积凭空翻 $n$ 倍且毫无必要。实现上把 $\text{used}$ 作为递归参数传递最省事，每层 $O(1)$。
5. **先判直接达标，再递归**：`if (used + i >= T) return true;` 写在递归调用之前，既省一次函数调用，又能把「一步终结」的分支以下整棵子树剪掉。
6. **搜索顺序不影响正确性**：从 $1$ 到 $n$ 或从 $n$ 到 $1$ 都得到同一答案，枚举顺序只改变常数（实测两种顺序互有快慢），不改变最坏复杂度，不必在此纠结。
7. **C++ 的 `memo` 是成员变量**：LeetCode 会在同一个 `Solution` 对象上连续跑多组用例，所以 `assign` 必须写在 `canIWin` 里，否则上一组的缓存会污染这一组。
8. **Python 用 `functools.lru_cache`**：递归深度最多 $n \le 20$，远小于默认上限 1000，无需 `setrecursionlimit`；缓存键写 `(mask, used)` 也无妨，因为 $\text{used}$ 由 $mask$ 决定，键空间仍是 $O(2^{n})$。
9. **数值范围**：总和 $\le 210$、$T \le 300$、$mask < 2^{20}$，全部运算都在 `int` 内，不需要 `long long`。

## 5. 正确性证明

**引理 1（状态充分性）**：局面 $mask$ 的累计和唯一确定，即 $\text{used}(mask) = \sum_{i \in S(mask)} i$；因此同一 $mask$ 上的胜负结果唯一，按 $mask$ 记忆化不会混淆不同局面。

**证明**：每取一个数就把它在 $mask$ 中置位，累计和是「已取数字之和」，是已取集合的函数，与取数顺序无关。故给定 $mask$ 时 $\text{used}$ 只有一个取值，剩余数字集合与当前和都完全确定。∎

**引理 2（被访问的状态必有合法手）**：若 $\frac{n(n+1)}{2} \ge T$，则 `dfs` 只会被调用在 $\text{used} < T$ 且 $mask$ 非满集的状态上。

**证明**：初始调用 $mask = 0$、$used = 0 < T$（$T \ge 1$ 时成立，$T \le 0$ 已在特判中返回）。递归调用只在 $used + i < T$ 成立后发生，故子状态 $used' = used + i < T$ 仍满足条件。若 $mask$ 是满集，则 $used = \frac{n(n+1)}{2} \ge T$，与 $used < T$ 矛盾，所以 $mask$ 必非满集，至少还剩一个可取的数。∎

**引理 3（递推式正确）**：记 $W^*(mask)$ 为「轮到当前玩家、局面为 $mask$ 时，他能否强制获胜」。在 $used < T$ 且 $mask$ 非满集时，

$$W^*(mask) = \bigvee_{i \notin mask}\Bigl[\,used + i \ge T \ \lor\ \lnot W^*(mask \mid 2^{i-1})\,\Bigr]$$

**证明**：

- ($\Leftarrow$) 若某个 $i$ 使 $used + i \ge T$，当前玩家取 $i$ 立刻达标获胜；若某个 $i$ 使 $\lnot W^*(mask \mid 2^{i-1})$，当前玩家取 $i$ 后，对手在子局面上无法强制获胜，即当前玩家获胜。
- ($\Rightarrow$) 设当前玩家能强制获胜，取他第一步实际执行的 $i$。这一手要么直接达标（第一项成立），要么把局面交给对手而对手无法强制获胜（第二项成立）。∎

**定理**：`canIWin(n, T)` 返回 `true` 当且仅当先手在双方最优博弈下必胜。

**证明**：按代码的判定顺序分四种情况。

1. $T \le 0$：开局累计和 $0 \ge T$，先手已达标，返回 `true` 正确。
2. $\frac{n(n+1)}{2} < T$：即使取光所有数字，累计和也不足 $T$，无人能达标，先手不可能获胜，返回 `false` 正确。
3. $n \ge T \ge 1$：先手直接取 $T$（它在池中），累计和 $T \ge T$，一手获胜，返回 `true` 正确。
4. 其余情况进入 `dfs`。对「剩余可选数字个数」做归纳，证明 `dfs(mask)` 恒等于 $W^*(mask)$：由引理 2，被访问状态都满足引理 3 的前提，且递归只走向「剩余数字更少」的状态，归纳假设可用；`dfs` 的实现逐字对应引理 3 的右侧（$used + i \ge T$ 立刻返回 `true`，否则看子状态是否为 `false`），故相等成立。于是 `dfs(0)` $= W^*(\varnothing)$，正是先手的胜负。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot 2^{n})$。状态数不超过 $2^{n}$，每个状态枚举 $n$ 个候选数字，命中缓存后 $O(1)$ 返回。$n = 20$ 时约 $2 \times 10^{7}$ 次基本操作，C++ 约 20 ms，Python 最坏约 1.5 s（实测 $n=20,\ T \approx 150$）。
- **空间**：$O(2^{n})$。`memo` 有 $2^{n}$ 个状态、每个 1 字节（$n = 20$ 约 1 MB）；递归栈深度不超过 $n \le 20$，可忽略。
- **特判的收益**：三组特判把「$T$ 过小 / 过大」的输入挡在深搜之外，真正的最坏情况只出现在 $T$ 接近总和一半的位置。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool canIWin(int maxChoosableInteger, int desiredTotal) {
        int n = maxChoosableInteger, T = desiredTotal;
        if (T <= 0) return true;                  // 开局累计和已达标
        if (n * (n + 1) / 2 < T) return false;    // 取光也凑不到目标
        if (n >= T) return true;                  // 一手取 T 直接获胜

        memo.assign(1 << n, 0);                    // 0 未算 / 1 必胜 / -1 必败
        return dfs(0, 0, n, T);                    // 从空集、累计和 0 出发
    }

private:
    vector<signed char> memo;

    bool dfs(int mask, int used, int n, int T) {
        if (memo[mask] != 0) return memo[mask] > 0;        // 命中记忆
        for (int i = 1; i <= n; ++i) {
            int bit = 1 << (i - 1);
            if (mask & bit) continue;                      // 已被取走
            if (used + i >= T) { memo[mask] = 1; return true; }        // 直接达标
            if (!dfs(mask | bit, used + i, n, T)) {                    // 对手必败
                memo[mask] = 1;
                return true;
            }
        }
        memo[mask] = -1;                                   // 所有手都把对手送进必胜态
        return false;
    }
};
```

### Python

```python
from functools import lru_cache


class Solution:
    def canIWin(self, maxChoosableInteger: int, desiredTotal: int) -> bool:
        n, T = maxChoosableInteger, desiredTotal
        if T <= 0:                       # 开局累计和已达标
            return True
        if n * (n + 1) // 2 < T:         # 取光也凑不到目标
            return False
        if n >= T:                       # 先手直接取 T
            return True

        @lru_cache(maxsize=None)
        def dfs(mask: int, used: int) -> bool:
            # used 由 mask 唯一确定，键里带上它不增加状态数
            for i in range(1, n + 1):
                bit = 1 << (i - 1)
                if mask & bit:           # 已被取走
                    continue
                if used + i >= T:        # 这一手直接达标
                    return True
                if not dfs(mask | bit, used + i):   # 对手在该子局面必败
                    return True
            return False                 # 所有手都把对手送进必胜态

        return dfs(0, 0)
```

## 8. 边界情况与易错点

1. **`desiredTotal = 0`**：官方口径返回 `true`（开局和已达标）。不要按「必须出手才算」写成 `false`。
2. **总和都不够**：$n = 1$、$T = 2$ 时池里只有 1，没人能到 2。若省掉「$\frac{n(n+1)}{2} < T$」的特判，`dfs` 会因「无合法手」返回 `false`，而调用方把它理解成「对手必败」，最终错误地返回 `true`。这是本题最隐蔽的 WA。
3. **「无手可走」不等于「对手输」**：本题是「抢先达到 $T$」，不是「取走最后一手者胜」，所以不能把「对手无手可走」当成自己获胜；必须靠特判 ② 保证和局根本不存在。
4. **$n \ge T$**：先手取 $T$ 一步到位。漏掉这条结果仍然正确（`dfs` 也能算出来），但会白跑一趟搜索。
5. **memo 退化成二态**：用 0 同时表示「没算过」和「必败」，必败状态每次都要重算，$O(n2^{n})$ 退化为指数级路径枚举，$n = 20$ 直接超时。
6. **C++ 成员 memo 未重置**：同一对象多次调用会串答案，`assign` 必须写在 `canIWin` 内部。
7. **`used` 忘记累加**：递归写成 `dfs(mask | bit)` 而丢掉 `used + i`，所有局面都被当成累计和 0，$T$ 稍大就全判 `false`。
8. **`1 << n` 的位宽**：$n \le 20$ 安全；若上限改成 31，`1 << n` 溢出成负数，需改成 `1LL << n` 并用 `long long` 掩码。
9. **Python 的最坏耗时**：$n = 20$、$T \approx 150$ 时约 1.5 s，属于「能过但要留意」；若想再快，可加「先用配对 / 奇偶等数学判据短路」的预处理，但正确性不依赖它。
