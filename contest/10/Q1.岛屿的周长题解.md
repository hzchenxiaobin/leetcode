# LeetCode 岛屿的周长 题解

## 1. 题目概述

- **标题 / 题号**：岛屿的周长（#463，easy）
- **链接**：https://leetcode.cn/problems/island-perimeter/
- **来源**：LeetCode 第 10 场周赛 Q1
- **难度**：简单
- **标签**：深度优先搜索，广度优先搜索，数组，矩阵

**题意**：给定一个 $row \times col$ 的 0/1 网格，$grid[i][j] = 1$ 为陆地、$0$ 为水域。陆地格子在**水平/垂直**方向上四连通（对角线不算），整个网格被水完全包围且恰好有一个岛屿，岛上没有「湖」。每个格子是边长 $1$ 的正方形，求这个岛屿的周长，也就是**陆地与水域（含网格外）之间单位边界边的条数**。

**约束**：

- $1 \le row, col \le 100$
- $grid[i][j] \in \{0, 1\}$
- 恰好一个岛屿，无湖，网格外一圈全是水
- 要求返回整数，规模最大时周长不超过 $4 \times 10^4$

> 💡 签到题的关键不是「遍历岛屿」，而是发现**周长可以完全局部地统计**：格子只和它的四个邻居打交道，整道题不需要任何连通性信息。

## 2. 示例

**示例 1**

```text
输入：grid = [[0,1,0,0],
             [1,1,1,0],
             [0,1,0,0],
             [1,1,0,0]]
输出：16
解释：陆地格共 7 个（4×7 = 28 条边），相邻陆地对共 6 对（每对共享 1 条边），
      28 − 2×6 = 16，即全部边界边共 16 条。
```

**示例 2**

```text
输入：grid = [[1]]
输出：4
解释：孤立的单格，四条边全部暴露。
```

**示例 3**

```text
输入：grid = [[1,0]]
输出：4
解释：1×2 的窄网格，右侧邻居是水、其余三侧越界，同样是 4。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**先找到岛，再沿着岛数边界**：从任意陆地格出发做 DFS/BFS，用一个 `visited` 数组标记访问过的格子；每访问一个格子，检查它的上下左右四个方向，若越界或为水域，就把答案加一。

这个做法完全正确，时间复杂度 $O(row \cdot col)$，但需要：

- 一个与网格同规模的 `visited` 数组，额外 $O(row \cdot col)$ 空间；
- 一个栈或队列（递归还可能爆栈），代码量明显变大；
- 为了「找到岛」还要先扫一遍网格定位起点。

另一种暴力是**枚举单位边**：网格共 $row \cdot col$ 个格子、约 $2 \cdot row \cdot col$ 条候选单位边，对每条边判断两侧是否「恰好一侧是陆地」。这是 $O(row \cdot col)$ 但常数翻倍的写法，而且边界下标处理非常啰嗦。

$100 \times 100$ 的规模当然能过，但这道题其实**比暴力更简单**：答案与「哪些格子属于同一个岛」无关，只与相邻关系有关。

### 3.2 核心观察：每个格子先算 4 条边，相邻陆地共享的边被多算了一次

![核心观察：4 × 陆地格数 − 2 × 相邻陆地对数](images/wc10_q1_shared_edge_concept.svg)

把每个陆地格子**孤立地**看：它有 4 条边。于是全部陆地格的边数之和是 $4L$（$L$ 为陆地格数量）。

问题在于：如果两个陆地格**相邻**（共边），这条边既不属于岛的边界，又被两边的格子各数了一次。所以每出现一对相邻陆地，就要从 $4L$ 里扣掉 $2$。

设 $S$ 为相邻陆地对的数目（水平相邻 + 垂直相邻），则

$$P = 4L - 2S$$

举例：示例 1 中 $L = 7$、$S = 6$，故 $P = 28 - 12 = 16$。

**为什么可以只往两个方向看**：统计 $S$ 时，只检查每个格子的**下方**与**右方**邻居是否也是陆地。这样任意一对相邻陆地（无论是左右相邻还是上下相邻）都恰好被「靠上/靠左」的那个格子数到一次，不会重复也不会遗漏。

> 💡 这个观察还有两个副产品：不需要 `visited`，不需要 BFS/DFS，甚至不需要「恰好一个岛」「没有湖」这两条保证 —— 对任意 0/1 网格，公式都返回所有陆地的总暴露边数。

### 3.3 算法流程

![算法流程：一次扫描同时统计 land 与 shared](images/wc10_q1_algorithm_flow.svg)

```text
land = 0, shared = 0
for i in 0 .. row-1:
    for j in 0 .. col-1:
        if grid[i][j] == 0: continue
        land += 1
        if i+1 < row and grid[i+1][j] == 1: shared += 1   // 下邻
        if j+1 < col and grid[i][j+1] == 1: shared += 1   // 右邻
return 4 * land - 2 * shared
```

只有一层双重循环、四个计数器动作，整体是「一遍扫描」的线性算法。

### 3.4 示例演算

![示例演算：逐格数出暴露边](images/wc10_q1_walkthrough.svg)

以示例 1 的 $4 \times 4$ 网格为例。逐格统计「暴露边数」（$4$ 减去该格四邻中的陆地数），结果如下表：

| 陆地格 $(i,j)$ | 相邻陆地格 | 暴露边数 |
|---|---|---|
| $(0,1)$ | $(1,1)$ | 3 |
| $(1,0)$ | $(1,1)$ | 3 |
| $(1,1)$ | $(0,1),(1,0),(1,2),(2,1)$ | 0 |
| $(1,2)$ | $(1,1)$ | 3 |
| $(2,1)$ | $(1,1),(3,1)$ | 2 |
| $(3,0)$ | $(3,1)$ | 3 |
| $(3,1)$ | $(2,1),(3,0)$ | 2 |

暴露边数之和为 $3+3+0+3+2+3+2 = 16$，与示例输出一致。

再用公式核对：$L = 7$；相邻对分两类 —— 水平 $3$ 对（行 $i=1$ 内两对、行 $i=3$ 内一对）、垂直 $3$ 对（列 $j=1$ 上 3 个陆地格依次上下相连），共 $S = 6$。于是 $P = 4 \times 7 - 2 \times 6 = 16$，两种数法互相验证。

## 4. 算法细节

1. **只检查下、右两个方向**：若四个方向都检查，每对相邻会被计两次，$S$ 变成 $2S$，答案就错成 $4L - 4S$（示例 1 会得到 $4$ 而不是 $16$）。真要用四方向，就必须把扣除量写成 $-4S$，或者把每条边除以 2 —— 都不如只查两个方向干净。
2. **越界判断放在前面做短路**：写成 `i + 1 < row && grid[i + 1][j] == 1`，C++ 的 `&&` 短路保证不会访问到网格外；Python 同理依赖 `and` 的短路语义。不要先算 `grid[i+1][j]` 再判越界。
3. **`land` 与 `shared` 用同一个循环维护**：两个量都是对陆地的局部计数，合并在一趟扫描里完成，既省时间也避免了「先统计格子数再统计相邻数」的两趟写法。
4. **结果范围**：$L \le 10^4$，$4L \le 40000$，$S \le 2 \times 10^4$，普通 `int` 完全够用，无需 `long long`；但注意不要把 `4 * land` 写成无符号运算后在减法里回绕。
5. **空网格防御**：题目保证 $row, col \ge 1$，工程代码里若想更稳，可在取 `grid[0]` 之前判空返回 $0$。
6. **两种写法等价**：$4L - 2S$ 与「逐格累加 $4 - \deg$」在数学上是同一个式子（$\sum \deg = 2S$）。前者少一层方向循环，常数更小；后者更直观，适合作为对拍用的暴力实现。
7. **不要真的去「找岛」**：本题答案与连通分量无关，任何 `visited`/BFS 都是不必要的复杂度；如果面试官追问「多个岛怎么办」，答案仍然是同一个公式（把所有陆地的暴露边加起来）。

## 5. 正确性证明

**引理 1（每对相邻陆地恰好被统计一次）**：在一次只检查「下方」与「右方」的两重循环中，任意一对共边相邻的陆地格恰好使 `shared` 增加 $1$。

**证明**：设这对格子为 $(i,j)$ 与 $(i',j')$，共边相邻意味着它们的坐标只在行或列上相差 $1$。

- 若 $i' = i+1, j' = j$（上下相邻），则在处理 $(i,j)$ 时 `i + 1 < row` 成立且 `grid[i+1][j] == 1`，`shared` 加一；而处理 $(i',j')$ 时只查 $(i'+1,j')$ 与 $(i', j'+1)$，都不会命中 $(i,j)$。
- 若 $j' = j+1, i' = i$（左右相邻），对称地只有 $(i,j)$ 的「右方」检查命中。

两个方向互不重叠，故该对恰好被计数一次。∎

**引理 2（度数求和）**：记陆地格 $c$ 的相邻陆地格个数为 $\deg(c)$，则 $\sum_{c \text{ 为陆地}} \deg(c) = 2S$。

**证明**：一条共享边连接两个陆地格，因此它在「按格子数邻居」时被两端各计一次。每条共享边恰好贡献 $2$ 到总和中，而 $S$ 是共享边（即相邻陆地对）的条数，故总和为 $2S$。∎

**定理**：算法返回的 $4L - 2S$ 等于岛屿的周长。

**证明**：岛屿周长等于所有陆地格中「不与陆地相邻」的边数之和。对格子 $c$，其 $4$ 条边里有 $\deg(c)$ 条与陆地共享，故暴露边数为 $4 - \deg(c)$。于是

$$P = \sum_{c} \bigl(4 - \deg(c)\bigr) = 4L - \sum_{c} \deg(c) = 4L - 2S .$$

算法中的 `land` 由遍历每个为 $1$ 的格子得到，恰为 $L$；由引理 1，`shared` 恰为 $S$。因此返回值就是 $P$。∎

## 6. 复杂度分析

- **时间**：$O(row \cdot col)$。每个格子被访问常数次，每次只做两次 $O(1)$ 的邻格判断，无递归、无回溯。
- **空间**：$O(1)$ 额外空间（不计输入本身）。不需要 `visited`、栈或队列，只维护 `land`、`shared` 两个计数器。
- **对比**：DFS/BFS 需要 $O(row \cdot col)$ 额外空间和递归栈风险；枚举单位边是同一复杂度但常数约 $2$ 倍。本题的一趟计数是该问题的最优量级（至少要把网格读一遍）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int islandPerimeter(vector<vector<int>>& grid) {
        int rows = (int)grid.size(), cols = (int)grid[0].size();
        int land = 0, shared = 0;
        for (int i = 0; i < rows; ++i) {
            for (int j = 0; j < cols; ++j) {
                if (grid[i][j] == 0) continue;
                ++land;                                        // 该格先按 4 条边计
                if (i + 1 < rows && grid[i + 1][j] == 1) ++shared;  // 下邻
                if (j + 1 < cols && grid[i][j + 1] == 1) ++shared;  // 右邻
            }
        }
        return 4 * land - 2 * shared;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def islandPerimeter(self, grid: List[List[int]]) -> int:
        rows, cols = len(grid), len(grid[0])
        land = shared = 0
        for i in range(rows):
            for j in range(cols):
                if grid[i][j] == 0:
                    continue
                land += 1                                     # 该格先按 4 条边计
                if i + 1 < rows and grid[i + 1][j] == 1:
                    shared += 1                               # 下邻
                if j + 1 < cols and grid[i][j + 1] == 1:
                    shared += 1                               # 右邻
        return 4 * land - 2 * shared
```

## 8. 边界情况与易错点

1. **四个方向都查导致重复计数**：只查下、右时 `shared` 就是相邻对数 $S$；查满四方向时它变成 $2S$，必须用 $4L - 4S$ 或先除以 $2$。这是本题最高频的错误。
2. **越界访问**：先判 `i + 1 < rows` 再读 `grid[i+1][j]`，顺序写反会在最后一行/最后一列越界。越界一侧应视为水域，不需要给网格补一圈 $0$（补边也可，但会多 $O(row+col)$ 的空间与写法）。
3. **单格与退化网格**：`[[1]]` 返回 $4$；`[[1,0]]`、`[[1],[0]]` 也是 $4$；全为 $0$ 时返回 $0$（题面保证有岛，但代码应自然给出 $0$ 而不是崩溃）。
4. **岛屿贴边**：陆地贴着网格四边是常态，贴边的那些边同样算周长（外侧就是水），上述越界判空恰好处理了这一点，不要额外「裁掉」边界。
5. **全陆地 $100 \times 100$**：答案是 $400$，即只剩最外圈；此时 $S = 19800$，$4L - 2S = 40000 - 39600 = 400$，说明公式在大规模下也不溢出（`int` 足够）。
6. **别把扣除系数记混**：等价形式是 $(2L - S) \times 2$，但写成 $(2L - S)$ 却漏掉外面的 $2$ 就会得到答案的一半；直接用 `4 * land - 2 * shared` 最不容易错。
7. **「恰好一个岛、无湖」不是算法前提**：即使题目放宽为多岛或允许湖，本解法依旧正确；若换成 DFS 写法，则必须重新处理这条件。
