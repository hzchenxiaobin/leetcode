# LeetCode 最优账单平衡 题解

## 1. 题目概述

- **标题 / 题号**：最优账单平衡（#465，hard）
- **链接**：https://leetcode.cn/problems/optimal-account-balancing/
- **来源**：LeetCode 第 10 场周赛 Q4
- **难度**：困难
- **标签**：位运算，数组，动态规划，回溯，状态压缩

**题意**：给定若干笔历史转账 $transactions[i] = [from_i, to_i, amount_i]$，表示 $from_i$ 曾给过 $to_i$ 共 $amount_i$ 元。现在允许**重新安排**转账：只要最终每个人的净头寸都归零，谁给谁、给多少都可以。求**最少需要多少笔**转账才能把所有人的账结清。

**约束**：

- $1 \le transactions.length \le 8$
- $transactions[i].length = 3$，$0 \le from_i, to_i < 12$，$from_i \ne to_i$
- $1 \le amount_i \le 100$
- 由此可推出：涉及的人数不超过 $12$（ID 只有 $0 \sim 11$），去掉净额为 $0$ 的人后，非零余额个数 $n \le 12$，且所有净额之和恒为 $0$

> 💡 数据范围极小（交易最多 8 笔、人数最多 12）是本题最重要的信号：答案可以用**回溯 / 状压 DP** 精确求出，不要试图用贪心「就近配对」蒙一个近似解。

## 2. 示例

输入：transactions = [[0,1,10],[2,0,5]]
输出：2
解释：#0 给过 #1 十元，#2 给过 #0 五元。
      净额：#0 = −5、#1 = +10、#2 = −5。

```

```

## 3. 解题思路

### 3.1 暴力思路

直接枚举「谁给谁多少钱」的所有方案：金额可以取任意实数，状态空间连续，无法枚举；即使把金额离散到 $1 \sim 100$，方案数也是天文数字。必须先把问题化简到「只看净额」这一层。

### 3.2 核心观察：净额化 + 零和分组

![交易流水归并为净额](images/wc10_q4_net_balance.svg)

**第一步：只保留净额。** 记录 $bal[v] = (\text{收到} - \text{付出})$，对每笔流水执行

$$bal[from] \leftarrow bal[from] - amount, \qquad bal[to] \leftarrow bal[to] + amount$$

于是 $bal[v] > 0$ 表示 $v$ **收得太多、应当付出**，$bal[v] < 0$ 表示 $v$ **付得太多、应当收回**，且 $\sum_v bal[v] = 0$ 恒成立。一次转账 $u \to v$ 金额 $x$，等价于 $bal[u] \leftarrow bal[u] - x,\ bal[v] \leftarrow bal[v] + x$。谁曾经给过谁钱，从此不再重要。

**第二步：切成零和组。** 把 $n$ 个非零余额分成 $g$ 个组，每组余额之和为 $0$。组内 $k$ 个人只要 $k-1$ 笔就能全部结清，于是

$$T = \sum_{i=1}^{g} (k_i - 1) = n - g$$

要想笔数最少，就要让**零和组数 $g$ 尽量大**。

![零和分组与 n − g 公式](images/wc10_q4_zero_sum_groups.svg)

### 3.3 算法流程：回溯搜索

![回溯 dfs 的流程](images/wc10_q4_dfs_flow.svg)

在 $n \le 12$ 的规模上，直接回溯枚举「合并顺序」即可：

1. 预处理出 $debt[]$（所有非零净额），$n = |debt|$。
2. `dfs(start)`：`while` 跳过 `debt[start] == 0` 的项（已结清的人），若越界则返回 $0$。
3. 否则枚举 $j > start$ 且 $debt[j] \cdot debt[start] < 0$（**异号**）：
   - 合并：`debt[j] += debt[start]`，此时 `debt[start]` 清零，等价于两人之间转了一笔钱；
   - 递归 `1 + dfs(start + 1)`，回溯时 `debt[j] -= debt[start]` 撤销；
4. 对所有分支取最小值。

合并的语义：把 $start$ 的整笔余额并给 $j$，就是「$start$ 与 $j$ 之间转一笔 $\lvert bal[start] \rvert$ 元」——被并入者当场清零，被并入方可能清零（那就结清了一个零和组），也可能变号（继续留在后面处理）。

### 3.4 示例演算

![示例 1 的合并过程](images/wc10_q4_dfs_walkthrough.svg)

示例 1 的净额为 $\#0 = -5,\ \#1 = +10,\ \#2 = -5$：

| 步骤 | $\#0$ | $\#1$ | $\#2$ | 合并动作 | 等价转账 |
|------|--------|--------|--------|----------|----------|
| 初始 | $-5$ | $+10$ | $-5$ | — | — |
| ① | $0$ | $+5$ | $-5$ | $\#0$ 并入 $\#1$ | $\#1$ 付 $\#0$ 5 元 |
| ② | $0$ | $0$ | $0$ | $\#1$ 并入 $\#2$ | $\#1$ 付 $\#2$ 5 元 |

共 $2$ 笔，与 $n - g = 3 - 1 = 2$ 一致。示例 2 的净额只剩 $-4$ 与 $+4$，一次合并即归零，答案 $1$。

## 4. 算法细节

1. **ID 可能不连续**：题面明确说 ID 可能是 $0,1,2$ 也可能是 $0,2,6$，因此必须用哈希表（`dict` / `unordered_map`）按 ID 累加，写成数组只能按「出现顺序」收集，不能假设下标连续。
2. **符号约定要统一**：本文取 `bal[from] -= amount`、`bal[to] += amount`，正数代表「应付」。若把正负号写反，合并后余额仍会归零（因为只是整体取负），但中间判断容易写错，务必全篇一致。
3. **先去掉零余额**：净额为 $0$ 的人不参与结算，剔除后 $n$ 变小，搜索树明显收缩；示例 2 的 $\#2$ 就是这种情况。
4. **只并入异号项**：同号合并只会让绝对值变大，绝不会多凑出一个零和组；加上这条剪枝，分支数从 $O(n!)$ 降到最坏约 $5\times 10^5$ 量级。
5. **`while` 跳过零项 + `start` 单调前移**：每次递归只处理「最靠前的未结清者」，保证同一合并集合不会被不同顺序重复枚举，这既是正确性要求也是效率要求。
6. **必须恢复现场**：`debt[j] += debt[start]` 之后要在递归返回时减回去，否则后续分支看到的是被污染的余额。Python 中列表可直接原地修改后恢复。
7. **`best` 的初值**：初始化为 $+\infty$，但在「只并入异号项」的剪枝下，只要剩余总和为 $0$ 就一定能找到异号伙伴，不会出现死分支；稳妥起见仍可显式判断。
8. **数值范围**：单笔最多 $100$、最多 $8$ 笔，单人余额绝对值不超过 $800$，`int` 足够；C++ 里用 `long long` 只是习惯性防御。

## 5. 正确性证明

**引理 1（组内 $k-1$ 笔可结清）**：若一组 $k$ 个人的余额之和为 $0$，则至多 $k-1$ 笔转账即可使这 $k$ 人全部归零。

**证明**：组内和为零且不全为零，故同时存在余额为正者 $u$ 与余额为负者 $v$。令 $x = \min(bal[u], -bal[v])$，在 $u, v$ 之间转 $x$：$bal[u] \leftarrow bal[u] - x$、$bal[v] \leftarrow bal[v] + x$。由 $x$ 的取法，$u, v$ 中至少一人变为 $0$，组内剩余非零人数至多 $k-1$，且组内余额和仍为 $0$。对 $k$ 归纳即得至多 $k-1$ 笔。∎

**引理 2（任意方案的下界）**：设某个方案用 $T$ 笔结清了 $n$ 个人，则存在把这 $n$ 人分成 $c$ 个零和组的划分，使 $T \ge n - c$。

**证明**：以人为点、每笔转账为一条边建无向图。钱只在同一连通分量内流动，故每个连通分量的余额和必为 $0$，这给出一个零和组划分。若连通分量 $C$ 有 $\lvert C \rvert$ 个点，连通性要求它至少含 $\lvert C \rvert - 1$ 条边，于是 $T \ge \sum_C (\lvert C \rvert - 1) = n - c$。∎

**引理 3（回溯不漏最优）**：存在一个最优方案，可以写成「不断把某人当前余额整体并给另一个异号的人」的合并序列。

**证明**：取组数最多的那个零和组划分（引理 2 给出其存在性），逐组处理。对每个组反复执行引理 1 的贪心：取组内一个余额非零的人 $s$（可取当前下标最小者）与一个异号的人 $t$，把 $s$ 的**整笔**余额并给 $t$。由于组内余额和为 $0$ 而 $bal[s] \ne 0$，异号的 $t$ 必然存在；每次合并让 $s$ 归零，组内余额和仍为 $0$。一个 $k$ 人组恰好用 $k-1$ 次合并清零，总计 $n - g$ 次，且每次都发生在异号两人之间，正是回溯搜索覆盖的形态。∎

**定理**：设 $g$ 为「把 $n$ 个非零余额划分成零和组」的最多组数，则最少转账笔数恰为 $n - g$。

**证明**：

- **可行性**：由引理 1，按 $g$ 个组分别贪心结清，第 $i$ 组至多 $k_i - 1$ 笔，合计至多 $\sum (k_i - 1) = n - g$ 笔，故最优值 $\le n - g$。
- **最优性**：任取一个 $T$ 笔的方案，由引理 2 得其连通分量给出 $c$ 个零和组，$T \ge n - c \ge n - g$（因 $c \le g$）。
- **回溯返回值**：`dfs` 只产生合法合并序列。一条序列的合并次数为 $n - g'$，其中 $g'$ 是这条序列过程中凑出的零和组数，故恒有 $n - g' \ge n - g$；而由引理 3 存在一条恰好 $n - g$ 次的序列被搜索到，故 `dfs` 返回 $\min = n - g$。∎

## 6. 复杂度分析

- **时间**：预处理 $O(m + p)$（$m$ 为交易数、$p$ 为涉及人数）。回溯的搜索树每层「最靠前的未结清者」尝试并入一个异号项，最坏上界为 $O(n!)$；在 $n \le 12$、异号剪枝与跳过零项的双重作用下，最坏实测约 $3\times10^5$ 个递归节点（$n = 12$、不存在零和真子集时），Python 也在 $0.2$ s 量级。
- **空间**：余额表与 $debt$ 数组 $O(p)$，递归深度不超过 $n \le 12$，即 $O(n)$；若用状压 DP 则需 $O(2^n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <climits>
using namespace std;

class Solution {
public:
    int minTransfers(vector<vector<int>>& transactions) {
        unordered_map<int, long long> bal;          // bal[v] = 收到 − 付出，正数代表“应付”
        for (auto& t : transactions) {
            bal[t[0]] -= t[2];
            bal[t[1]] += t[2];
        }
        vector<long long> debt;
        for (auto& kv : bal)
            if (kv.second != 0) debt.push_back(kv.second);
        int n = debt.size();
        if (n == 0) return 0;
        return dfs(debt, 0, n);
    }

private:
    int dfs(vector<long long>& debt, int start, int n) {
        while (start < n && debt[start] == 0) start++;   // 跳过已结清的人
        if (start == n) return 0;                        // 全部结清
        int best = INT_MAX;
        for (int j = start + 1; j < n; j++) {
            if (debt[start] * debt[j] < 0) {             // 只和异号的人合并
                debt[j] += debt[start];                  // 一笔转账：start 整体并入 j
                int cand = dfs(debt, start + 1, n);
                debt[j] -= debt[start];                  // 回溯恢复现场
                if (cand != INT_MAX && cand + 1 < best) best = cand + 1;
            }
        }
        return best;
    }
};
```

### Python

```python
from typing import List
from collections import defaultdict


class Solution:
    def minTransfers(self, transactions: List[List[int]]) -> int:
        # bal[v] = 收到 - 付出：正数表示“应当付出”，负数表示“应当收回”
        bal = defaultdict(int)
        for frm, to, amount in transactions:
            bal[frm] -= amount
            bal[to] += amount

        debt = [v for v in bal.values() if v != 0]
        n = len(debt)

        def dfs(start: int) -> int:
            while start < n and debt[start] == 0:      # 跳过已结清的人
                start += 1
            if start == n:                             # 全部结清
                return 0
            best = float("inf")
            for j in range(start + 1, n):
                if debt[start] * debt[j] < 0:          # 只和异号的人合并
                    debt[j] += debt[start]             # 一笔转账：start 整体并入 j
                    best = min(best, 1 + dfs(start + 1))
                    debt[j] -= debt[start]             # 回溯恢复现场
            return best

        return dfs(0) if n else 0
```

## 8. 边界情况与易错点

1. **净额全为零**（如 `[[0,1,1],[1,0,1]]`）：剔除零项后 $n = 0$，必须直接返回 $0$，否则 `dfs(0)` 会因为数组为空而越界或返回 `inf`。
2. **只有一笔交易**：净额是一正一负，返回 $1$；不要写成 $0$。
3. **ID 不连续**（$0, 2, 6$）：用哈希表按 ID 归并，或者按首次出现顺序编号；若直接开 `maxId+1` 的数组并假设「有效人数 = 最大值」，会把空洞当成人参与搜索。
4. **合并方向写反**：`debt[j] += debt[start]` 与 `debt[j] -= debt[start]` 必须配对出现在递归两侧，恢复时用同一个量，否则后续分支读到错误余额，答案偏大甚至死循环。
5. **`INT_MAX + 1` 溢出**：C++ 中若某分支返回 `INT_MAX`，先判断再 `+1`，否则整数溢出成负数被当成更优解。
6. **剪枝写错成同号**：`debt[start] * debt[j] < 0` 是「异号」；写成 `> 0` 会只合并同号，导致很多组永远无法清零，返回 `inf`。
7. **递归里修改共享数组**：Python 的 `debt` 是可变列表，被 `dfs` 原地修改；如果先把 `debt` 切片传参，回溯就失效（不会污染）但会多消耗内存；两种写法都可，但必须明确其中一种语义。
8. **金额范围与溢出**：单笔 $100$、最多 $8$ 笔，最多累加到 $800$，`int` 安全；但若按「把多笔并到一个人身上」的中间状态估算，用 `long long` 更省心。

**延伸思考**：

1. **状压 DP 写法**：令 $sum[mask]$ 为子集余额和，$dp[mask]$ 表示把 $mask$ 恰好划分成零和组的最多组数（$sum[mask] \ne 0$ 时无定义）。固定 $mask$ 的最低位 $i$，枚举包含 $i$ 且 $sum = 0$ 的子集 $sub$，有 $dp[mask] = \max(1 + dp[mask \oplus sub])$，答案 $n - dp[2^n - 1]$，复杂度 $O(3^n)$，比回溯有更好的最坏保证。
2. **若把「笔数」换成「手续费之和」**：目标是让总额最小，此时问题变成带权的最小费用流，零和分组不再是充分刻画，需要建模成二分图匹配 / 网络流。
3. **人数很大时**（例如 $10^5$ 人）：最大化零和组数是 NP-hard 的（子集和归约），只能接受近似——任意「欠钱者配收钱者」的贪心一定能在 $n-1$ 笔内结清，但不保证最少；若要精确解，只能依赖人数很小这个前提。
