# LeetCode 收集元素的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：收集元素的最少操作次数（#2869，easy）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-collect-elements/
- **来源**：LeetCode 第 114 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：正整数数组 `nums` 与整数 $k$。一次操作把数组**最后一个**元素删掉并加入集合。返回使集合包含元素 $1, 2, \dots, k$ 的最少操作次数（题目保证可以收集到）。

**约束**：

- $1 \le nums.length \le 50$
- $1 \le nums[i] \le nums.length$
- $1 \le k \le nums.length$
- 输入保证可以收集到元素 $1, 2, \dots, k$

## 2. 示例

**示例 1**

```text
输入：nums = [3,1,5,4,2], k = 2
输出：4
解释：依次弹出 2、4、5、1，集合此时包含 1 和 2。
```

**示例 2**

```text
输入：nums = [3,1,5,4,2], k = 5
输出：5
解释：依次弹出 2、4、5、1、3，集合包含 1 到 5。
```

**示例 3**

```text
输入：nums = [3,2,5,3,1], k = 3
输出：4
解释：依次弹出 1、3、5、2，集合包含 1 到 3。
```

## 3. 解题思路

### 3.1 暴力思路

老老实实模拟：每弹出一个元素加入集合，检查 `all(v in S for v in 1..k)` 是否成立，成立即返回当前操作数。单次检查 $O(k)$，总体 $O(nk)$。$n, k \le 50$，最多 2500 次操作，当然能过。但「每次都全量检查」是多余的——收集进度是**单调**的，只增不减，用一个计数器就能 $O(1)$ 判断是否集齐。

### 3.2 核心观察：弹出的永远是后缀，问题 = 找「最短后缀覆盖 1..k」

![从尾部弹出，直到集齐 1..k](images/bw114_q1_pop_collect.svg)

操作 $t$ 次后，加入集合的恰好是后缀 $nums[n-t..n-1]$（多重集）。于是：

$$
\text{答案} = \min \{\, t : \{1,\dots,k\} \subseteq nums[n-t..n-1] \,\}
$$

后缀随 $t$ 增大只会**包含更多**元素，具备单调性：**从右往左**扫描，第一次「集齐」的位置就是最优解。等价的说法：答案是 $n - \min_{v \in [1,k]} \text{last}(v)$，其中 $\text{last}(v)$ 是值 $v$ 最后一次出现的下标——最靠左的「必需元素末次出现」决定了要弹多深。

### 3.3 算法流程

1. `seen[1..k]` 置 false，计数 `got = 0`；
2. 从 $i = n-1$ 向左扫：若 $nums[i] \le k$ 且未标记，标记并 `got += 1`；
3. `got == k` 时返回 $n - i$（弹出了下标 $i..n-1$ 共 $n-i$ 个元素）。

值 $> k$ 的元素永远没用，直接跳过。

### 3.4 示例演算

![示例演算：两例对照](images/bw114_q1_walkthrough.svg)

- `[3,1,5,4,2]`，$k=2$：$i=4$ 弹 2（集齐 $\{2\}$）；$i=3,2$ 的 4、5 无用；$i=1$ 弹 1，集齐，答案 $5-1=4$；
- `[3,2,5,3,1]`，$k=3$：$i=4$ 弹 1；$i=3$ 弹 3；$i=2$ 的 5 无用；$i=1$ 弹 2 集齐，答案 $5-1=4$（下标 3 处的重复 3 只标记一次）。

## 4. 算法细节

1. **标记数组开 $k+1$ 大小**：`seen` 下标 $0..k$；判 $v \le k$ 之后再访问 `seen[v]`，避免越界（$nums[i]$ 最大可到 $n$，而 $k$ 可能远小于 $n$）。
2. **计数器代替全量检查**：`got` 每标记一个新值加一，`got == k` 即停，把 $O(nk)$ 降到 $O(n)$。
3. **返回时机**：在**标记后立即**判断，返回 $n - i$——此时恰好弹出包括 $nums[i]$ 在内的后缀；不要先扫完再回头算。
4. **值域特征**：$1 \le nums[i] \le n$ 且保证能集齐，故循环内不须判「扫完还没集齐」的失败情形（保险起见可返回 $-1$ 兜底）。

## 5. 正确性证明

**引理 1（操作与后缀）**：执行 $t$ 次操作后，集合恰为数组后缀 $nums[n-t..n-1]$ 中出现过的值（多重计数）。

**证明**：操作只删末尾元素，$t$ 次删掉的恰是原数组的最后 $t$ 个位置。∎

**引理 2（单调性与最优停点）**：记 $S_t$ 为后缀 $nums[n-t..n-1]$ 的值集合，则 $S_t \subseteq S_{t+1}$；使 $S_t \supseteq \{1,\dots,k\}$ 的最小 $t$ 即为答案。

**证明**：包含性：后缀变长只会加入新元素。最优性：答案的定义就是最小的可行 $t$；由引理 1，可行性由后缀覆盖决定，故最小的可行 $t$ 正确。∎

**定理**：从右向左扫描、首次 `got == k` 时返回 $n - i$ 的算法输出该最小 $t$。

**证明**：扫描到下标 $i$ 时已标记的值集合恰为 $S_{n-i}$。由引理 2 的单调性，首次满足覆盖的 $i$ 使 $n - i$ 为最小可行 $t$；算法在此时返回，故正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素至多访问一次，标记与计数均 $O(1)$。
- **空间**：$O(k)$。`seen` 数组大小 $k+1$（$k \le n \le 50$，可视为常数级）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int k) {
        int n = nums.size();
        vector<char> seen(k + 1, 0);
        int got = 0;
        for (int i = n - 1; i >= 0; --i) {        // 每次操作弹出最后一个元素
            int v = nums[i];
            if (v <= k && !seen[v]) {
                seen[v] = 1;
                if (++got == k) return n - i;     // 弹到下标 i，共弹出 n-i 个
            }
        }
        return -1;                                // 题目保证能收集齐，不会走到这里
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int], k: int) -> int:
        n = len(nums)
        seen = [False] * (k + 1)
        got = 0
        for i in range(n - 1, -1, -1):            # 每次操作弹出最后一个元素
            v = nums[i]
            if v <= k and not seen[v]:
                seen[v] = True
                got += 1
                if got == k:
                    return n - i                  # 弹到下标 i，共弹出 n-i 个
        return -1                                 # 题目保证能收集齐
```

> 💡 两份代码均通过全部官方示例（`4`、`5`、`4`），并与「逐步弹出、每次全量检查集合」的暴力模拟对拍 10000 组随机数据（含 $k=n$、大量重复值），`mismatch = 0`。

## 8. 边界情况与易错点

1. **`nums[i] > k` 的元素**：对收集无用但**占用操作次数**——它们若在末尾，必须被弹掉才能碰到更左的必需元素，不能跳过计数；扫描时直接忽略即可，操作数由位置差 $n-i$ 自动体现。
2. **`k = n`**：必须把整个数组弹完（值域恰为 $1..n$，每个都要收集），答案是 $n$。
3. **重复值**：同一个值第二次出现时不再累加 `got`，否则会提前误判集齐。
4. **返回 `n - i` 而非 `i + 1`**：操作次数是「弹出多少个」= 后缀长度 $n - i$；下标转长度的 off-by-one 是本题唯一容易翻车的点。
5. **数组越界**：先判 $v \le k$ 再写 `seen[v]`；若先标记后判，`nums[i] = n`、`k < n` 时会越界。
6. **不要用 `set` 反复查询**：`v in S` 每次调用本身已是 $O(1)$，但全量 `all(...)` 检查是 $O(k)$，大数据下会退化（本题规模小，属于习惯问题）。
