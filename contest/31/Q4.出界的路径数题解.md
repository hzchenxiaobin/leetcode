# LeetCode 出界的路径数 题解

## 1. 题目概述

- **标题 / 题号**：出界的路径数（#576，medium）
- **链接**：https://leetcode.cn/problems/out-of-boundary-paths/
- **来源**：LeetCode 第 31 场周赛 Q4
- **难度**：中等
- **标签**：动态规划

**题意**：给定 $m \times n$ 的网格与起点 $(startRow, startColumn)$，每一步可以把球向上下左右移动一格；若这一步跨过网格边界，球就离开网格、这条路径到此结束。求在**至多** $maxMove$ 步内让球离开网格的**路径条数**，结果对 $10^9+7$ 取模。

**约束**：

- $1 \le m, n \le 50$
- $0 \le maxMove \le 50$
- $0 \le startRow < m$，$0 \le startColumn < n$

> 💡 状态空间只有 $m \cdot n \le 2500$ 个格子、$maxMove \le 50$ 层，但走法数是 $4^{50}$ 量级——典型的「状态少、路径多」，答案只能靠计数 DP 得到。

## 2. 示例

**示例 1**

```text
输入：m = 2, n = 2, maxMove = 2, startRow = 0, startColumn = 0
输出：6
解释：起点 (0,0) 是角格，向上、向左各 1 步即出界，贡献 2 条；
      走 1 步进入 (0,1) 或 (1,0) 后，2 步之内这两个角格各有 2 个出界方向，
      贡献 1×2 + 1×2 = 4 条；合计 2 + 4 = 6。
```

**示例 2**

```text
输入：m = 1, n = 3, maxMove = 3, startRow = 0, startColumn = 1
输出：12
解释：第 1 步向上、向下都出界 → 2 条；
      第 2 步从 (0,0)、(0,2) 各有 3 个出界方向（上、下、左/右）→ 6 条；
      第 3 步 (0,1) 聚集了 2 条界内路径，各 2 个出界方向 → 4 条；
      2 + 6 + 4 = 12。
```

## 3. 解题思路

### 3.1 暴力思路

从起点做 DFS，枚举所有长度不超过 $maxMove$ 的走法，在跨出边界时给答案加一。做法正确，但走法总数是

$$4^{maxMove} \le 4^{50} \approx 1.27 \times 10^{30}$$

即便 $maxMove = 20$ 也有 $10^{12}$ 条，必然超时。更糟的是暴力在重复劳动：**很多不同走法会在同一时刻落在同一格**，它们之后的走向完全相同，却被反复展开。

### 3.2 核心观察：按「步数 + 格子」合并路径

![出界结算：计数 × 出界方向数](images/wc31_q4_exit_settlement_concept.svg)

两个关键事实：

1. **出界即终止**：一条路径只有一个「出界时刻」，离开网格后不会再回来，也不会被后面的步骤再次统计。
2. **界内路径的未来只取决于当前格**：从 $(i,j)$ 出发还能怎么走，与「它是怎么走到 $(i,j)$ 的」无关。于是可以把「到达 $(i,j)$ 的所有路径」打包成一个计数值。

定义

$$dp_k[i][j] = \text{走 } k \text{ 步后仍在网格内、且落在 } (i,j) \text{ 的路径条数}$$

再定义格子 $(i,j)$ 的**出界方向数**

$$e(i,j) = [i = 0] + [i = m-1] + [j = 0] + [j = n-1]$$

角格 $e = 2$，非角边格 $e = 1$，内部格 $e = 0$。因为「从 $(i,j)$ 一步跨出边界」当且仅当沿某个指向界外的方向走，所以第 $k$ 步（$1 \le k \le maxMove$）出界的路径数恰好是

$$\text{exit}_k = \sum_{i,j} dp_{k-1}[i][j] \cdot e(i,j)$$

最终答案 $= \sum_{k=1}^{maxMove} \text{exit}_k$。**逐步结算**让「至多 $maxMove$ 步」自然被覆盖，无需额外处理。

### 3.3 算法流程 / 状态转移

![滚动 DP 流程](images/wc31_q4_rolling_dp_flow.svg)

界内路径的转移就是「四个邻居把计数推过来」：

$$dp_{k}[i][j] = \sum_{(i',j') \sim (i,j)} dp_{k-1}[i'][j']$$

其中 $(i',j') \sim (i,j)$ 表示两者在网格内相邻。由于 $dp_k$ 只依赖 $dp_{k-1}$，用两个 $m \times n$ 数组滚动即可，空间降到 $O(mn)$。

流程：

1. `dp[startRow][startColumn] = 1`，其余为 0；`ans = 0`。
2. 循环 `step = 1 … maxMove`：遍历每个 $v = dp[i][j] > 0$ 的格子与 4 个方向：
   - 方向指向界外 → `ans += v`（**立即结算**，这条路径此后不再参与转移）；
   - 方向仍在界内 → `nxt[ni][nj] += v`（**计数合并**）。
3. `dp ← nxt`；若 `nxt` 全为 0 则提前结束（界内已无路径，后续不可能再出界）。
4. 返回 `ans mod (10^9+7)`。

「边转移边结算」与「先算 $\sum dp \cdot e$ 再转移」完全等价，前者少写一次网格遍历。

### 3.4 示例演算

![示例 1 演算](images/wc31_q4_walkthrough.svg)

示例 1（$m = n = 2$，$maxMove = 2$，起点 $(0,0)$）：2×2 网格的四格全是角格，$e \equiv 2$。

| 轮次 | 结算前的 dp（非零项） | 本步出界 | 累计 ans |
|---|---|---|---|
| 第 1 步 | $dp[(0,0)] = 1$ | $1 \times 2 = 2$ | 2 |
| 第 2 步 | $dp[(0,1)] = dp[(1,0)] = 1$ | $1\times 2 + 1\times 2 = 4$ | 6 |

第 2 步结束后 $dp[(0,0)] = 2$、$dp[(1,1)] = 2$（两条走法汇入同一格被合并），但 $maxMove = 2$ 已用完，不再结算。示例 2 的三步结算量分别是 $2$、$6$、$4$，累计 $12$，与官方输出一致。

## 4. 算法细节

1. **$e(i,j)$ 不必预处理**：它由四个边界判断在 $O(1)$ 内得到；代码中直接在「方向是否越界」的分支里结算，效果相同且省掉一次遍历。
2. **滚动数组**：只保留上一层 `dp` 与下一层 `nxt`。C++ 里 `nxt` 每轮重新构造（或整体 `fill` 成 0），交换后不能残留旧值——这是本题最常见的实现 bug。
3. **取模时机**：`dp`、`nxt`、`ans` 中的值都保持 $< 10^9+7$，两个这样的数相加 $< 2\times10^9+7$，用 `int` 也不会溢出（`ans` 仍建议用 `long long`，语义更清晰）。Python 整数无溢出，直接 `% MOD`。
4. **「至多」不能写成「恰好」**：只统计第 $maxMove$ 步出界的路径，会漏掉更早出界的路径。正确写法是每一轮都结算并累加。
5. **不要给「已出界」建状态**：出界路径若继续参与转移就会重复计数；它在结算后本就不会进入 `nxt`。
6. **起点在边界**：起点是角格时第 1 步就有 2 条路径出界，代码无需特判——$dp_0$ 在起点处为 1，第一轮自然结算。
7. **提前终止的判据**：`nxt` 全 0 时此后每轮 $dp$ 都是全 0，`ans` 不再变化；用「本轮是否存在界内转移」标记比每轮扫一遍 `nxt` 更省。
8. **转移量级**：$maxMove \cdot m \cdot n \le 50\times50\times50 = 1.25\times10^5$ 次状态转移，每次 4 个方向，常数极小。

## 5. 正确性证明

**引理 1（dp 的含义）**：对任意 $k \ge 0$，$dp_k[i][j]$ 等于「走 $k$ 步、每一步都落在网格内、最终停在 $(i,j)$」的走法数。

**证明**：对 $k$ 归纳。$k = 0$ 时只有起点有 1 条空走法，与初始化一致。设 $dp_k$ 满足结论，则
$dp_{k+1}[i][j] = \sum_{(i',j') \sim (i,j)} dp_k[i'][j']$，求和遍历 $(i,j)$ 在网格内的所有邻居。任一条 $k+1$ 步界内路径去掉最后一步，恰是一条 $k$ 步界内路径停在某个邻居处；反之任一「$k$ 步界内路径 + 相邻格」组合唯一拼出一条 $k+1$ 步路径。故求和恰好枚举全部走法且互不重复。∎

**引理 2（单步结算公式）**：第 $k$ 步（$1 \le k \le maxMove$）出界的路径数等于 $\sum_{i,j} dp_{k-1}[i][j] \cdot e(i,j)$。

**证明**：构造双射。一条第 $k$ 步出界的路径，前 $k-1$ 步都在界内、末步跨出边界，把它映射到（前 $k-1$ 步的界内路径，末步出界方向）。由引理 1，前 $k-1$ 步路径按终点 $(i,j)$ 分组后，每组有 $dp_{k-1}[i][j]$ 条；终点为 $(i,j)$ 时能一步跨出边界的方向恰有 $e(i,j)$ 个（角格 2 个、非角边格 1 个、内部格 0 个）。两部分独立选取、组合唯一还原原路径，故总数为乘积之和。∎

**引理 3（互不重叠）**：设 $S_k$ 为第 $k$ 步出界的路径集合，则 $k \ne k'$ 时 $S_k \cap S_{k'} = \varnothing$。

**证明**：一条路径的每一步都是确定的，其出界时刻唯一；若它属于 $S_k$，就不可能在另一步「首次」出界。∎

**定理**：算法输出的 `ans` 等于「至多 $maxMove$ 步内出界的路径总数」对 $10^9+7$ 取模的结果。

**证明**：算法把 $\text{exit}_k$（$k = 1..maxMove$）逐个加入 `ans`。由引理 2，它分别是第 $k$ 步出界的路径数；由引理 3，这些集合两两不交，故总和恰为「出界时刻 $\le maxMove$」的路径数，正是题意所求；每步加法后取模不改变余数。算法在 `nxt` 全 0 时提前退出，此时后续各轮的 $\text{exit}$ 均为 0，不影响总和。∎

## 6. 复杂度分析

- **时间**：$O(maxMove \cdot m \cdot n)$。每轮遍历 $m \cdot n$ 个格子、每格 4 个方向（常数 4），提前退出只会更少；代入上界约 $1.25\times10^5$ 次转移。
- **空间**：$O(mn)$。只需两层 $m\times n$ 的 DP 表，与 $maxMove$ 无关，其余为常数个辅助变量。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findPaths(int m, int n, int maxMove, int startRow, int startColumn) {
        const long long MOD = 1000000007LL;
        vector<vector<long long>> dp(m, vector<long long>(n, 0));
        dp[startRow][startColumn] = 1;
        long long ans = 0;
        const int di[4] = {1, -1, 0, 0}, dj[4] = {0, 0, 1, -1};
        for (int step = 0; step < maxMove; step++) {
            vector<vector<long long>> nxt(m, vector<long long>(n, 0));
            bool alive = false;
            for (int i = 0; i < m; i++) {
                for (int j = 0; j < n; j++) {
                    long long v = dp[i][j];
                    if (v == 0) continue;
                    for (int d = 0; d < 4; d++) {
                        int ni = i + di[d], nj = j + dj[d];
                        if (ni >= 0 && ni < m && nj >= 0 && nj < n) {
                            nxt[ni][nj] = (nxt[ni][nj] + v) % MOD;  // 界内：合并计数
                            alive = true;
                        } else {
                            ans = (ans + v) % MOD;                  // 出界：立即结算
                        }
                    }
                }
            }
            if (!alive) break;          // 界内已无路径，后续不可能再出界
            dp.swap(nxt);
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def findPaths(self, m: int, n: int, maxMove: int, startRow: int, startColumn: int) -> int:
        MOD = 10 ** 9 + 7
        dirs = ((1, 0), (-1, 0), (0, 1), (0, -1))
        dp = [[0] * n for _ in range(m)]
        dp[startRow][startColumn] = 1
        ans = 0
        for _ in range(maxMove):
            nxt = [[0] * n for _ in range(m)]
            alive = False
            for i in range(m):
                row = dp[i]
                for j in range(n):
                    v = row[j]
                    if v == 0:
                        continue
                    for di, dj in dirs:
                        ni, nj = i + di, j + dj
                        if 0 <= ni < m and 0 <= nj < n:
                            nxt[ni][nj] = (nxt[ni][nj] + v) % MOD  # 界内：合并计数
                            alive = True
                        else:
                            ans = (ans + v) % MOD                 # 出界：立即结算
            if not alive:
                break  # 网格内已无路径，后续步数不可能再出界
            dp = nxt
        return ans
```

## 8. 边界情况与易错点

1. **$maxMove = 0$**：一步都不能走，答案 0。循环不执行，返回 0，代码天然正确。
2. **$1\times1$ 网格**：四个方向全部出界，$maxMove \ge 1$ 时答案是 4；随后 `nxt` 全 0 提前退出，不会重复累加。
3. **单行 / 单列**：$m = 1$ 时 $[i = 0]$ 与 $[i = m-1]$ 同时成立，每格的 $e$ 至少为 2（上下都能出界）；用公式时别把这两个指示函数当成互斥的两种情况。
4. **取模与溢出**：C++ 中 `ans` 若用 `int` 且长时间不取模，累计会溢出；要么用 `long long`，要么每次加法后立刻取模。
5. **「至多」写成「恰好」**：只在最后一轮结算会显著偏小，这是本题最典型的错误。
6. **忘记清空 `nxt`**：滚动复用旧数组时必须整体置 0，否则会把上一轮结果再算一遍。
7. **把出界路径留在 DP 里**：出界后不能再走，把它当普通状态继续转移会重复计数。
