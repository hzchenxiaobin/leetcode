# LeetCode 分糖果 题解

## 1. 题目概述

- **标题 / 题号**：分糖果（#575，easy）
- **链接**：https://leetcode.cn/problems/distribute-candies/
- **来源**：LeetCode 第 31 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：Alice 有 $n$ 枚糖（$n$ 为偶数），第 $i$ 枚糖的类型是 `candyType[i]`。医生要求她**恰好吃掉 $n/2$ 枚**。在这个前提下，她希望吃到的糖**种类尽量多**，求这个最大种类数。

**约束**：

- $n = \text{candyType.length}$，$2 \le n \le 10^4$，且 $n$ 一定是偶数
- $-10^{5} \le \text{candyType}[i] \le 10^{5}$，**允许负数**（不能当成计数数组的下标）
- 由于 $n \le 10^4$，不同种类数 $U$ 满足 $1 \le U \le n$

## 2. 示例

**示例 1**

```text
输入：candyType = [1,1,2,2,3,3]
输出：3
解释：只能吃 6 / 2 = 3 枚糖；恰好只有 3 种糖，每种吃一枚即可，答案 3。
```

**示例 2**

```text
输入：candyType = [1,1,2,3]
输出：2
解释：只能吃 4 / 2 = 2 枚糖。虽然有 3 种糖（1、2、3），
      但只能挑其中 2 枚，无论怎么选最多吃到 2 种。
```

**示例 3**

```text
输入：candyType = [6,6,6,6]
输出：1
解释：可以吃 4 / 2 = 2 枚糖，但 4 枚全是同一种，
      无论吃哪 2 枚都只有 1 种，答案 1。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是**枚举所有大小为 $n/2$ 的子集**，对每个子集统计不同数值个数，取最大值。方案数是组合数

$$\binom{n}{n/2}$$

$n=10^4$ 时这个数量完全无法枚举；即使 $n=30$ 也有 $1.5\times10^{8}$ 量级。

另一条「看起来合理」的暴力是排序后从前往后贪心：先按类型排序，再依次尝试把新类型放进篮子，篮子满了就停。它其实已经是对的（复杂度 $O(n\log n)$），但排序是多余的——问题根本不需要顺序信息。这说明**先把题意压缩成数学形式**，比急着写循环更重要。

### 3.2 核心观察：答案是两个上限的较小值

![两个上限夹住答案](images/wc31_q1_two_caps_concept.svg)

设 $U$ 为数组中**不同数值的个数**（即糖的种类数），$k = n/2$ 为她必须吃掉的枚数。答案同时受两个条件限制：

- **上限 A（枚数）**：吃到一种糖至少要 1 枚，总共只能吃 $k$ 枚，所以种类数 $\le k$。
- **上限 B（种类）**：糖本身只有 $U$ 种，所以种类数 $\le U$。

于是答案 $\le \min(U, k)$。关键的第二半是：**这个上界可以取到**。

- 若 $U \le k$：每种各拿 1 枚，用掉 $U$ 枚；还差 $k-U$ 枚，从剩下的重复糖里随便补（$n - U \ge n - k \ge k - U$，一定补得满）。
- 若 $U > k$：直接挑 $k$ 个互不相同的种类，各拿 1 枚，正好 $k$ 枚、$k$ 种。

两种情形都能凑满 $k$ 枚，所以

$$\text{ans} = \min(U,\ k),\qquad k = \frac{n}{2}$$

> 💡 **一句话记忆**：她想「多尝几种」，但胃和糖的种类都不答应，谁更小听谁的。

### 3.3 算法流程

![算法流程](images/wc31_q1_greedy_flow.svg)

1. 建一个哈希集合 `S`，遍历 `candyType`，把每个元素插入。
2. 遍历结束后 $U = |S|$。
3. 计算 $k = n/2$（$n$ 为偶数，整数除法即精确值）。
4. 返回 $\min(U, k)$。

整个过程只有一次线性扫描 + 一次比较，不需要排序、不需要枚举方案、也不需要真的去「分配」糖果。

### 3.4 示例演算

![三组示例的演算](images/wc31_q1_walkthrough.svg)

| `candyType` | $n$ | $U$ | $k=n/2$ | $\min(U,k)$ | 瓶颈在哪 |
|---|---|---|---|---|---|
| `[1,1,2,2,3,3]` | 6 | 3 | 3 | **3** | 两个上限相等 |
| `[1,1,2,3]` | 4 | 3 | 2 | **2** | 枚数 $k$ 卡住 |
| `[6,6,6,6]` | 4 | 1 | 2 | **1** | 种类 $U$ 卡住 |

三行分别覆盖了「恰好相等」「种类多于可吃数」「种类极少」三种情况，也说明 $\min$ 的两边都可能是真正起作用的那个上限。

## 4. 算法细节

1. **去重用哈希集合而不是计数数组**：值域是 $[-10^5, 10^5]$，用数组要开 $2\times10^5+1$ 并做偏移，虽可行但没有必要；`unordered_set<int>` / `set` 直接用原值当键，更简洁也更省。
2. **不要用 `vector<bool>` 或 `map` 做无谓的排序**：题目只关心「有多少个不同的值」，与出现次数和顺序都无关。C++ 里 `unordered_set` 期望 $O(n)$；若用 `set` 则退化成 $O(n\log n)$，能过但没必要。
3. **整数除法**：`n` 保证是偶数，`n / 2` 在 C++/Python 中都精确；不要写成浮点的 `n / 2.0` 再转回整数，多余且易错。
4. **可选剪枝**：一旦集合大小达到 $k$，答案已经确定为 $k$（不可能再大），可以立即返回。剪枝只是常数优化，不剪枝也同样正确。
5. **Python 一行写法**：`min(len(set(candyType)), len(candyType) // 2)`。注意两处 `len(candyType)` 只读长度，不要误写成 `min(len(set(candyType)), n) / 2`——那是「先取小再除以 2」，与题意完全不符。
6. **负数值不影响去重**：哈希集合对负数天然友好；只有在用「值当数组下标」的写法时才需要加偏移量，本题不推荐那种写法。

## 5. 正确性证明

**引理 1（种类上限）**：任意合法方案吃到的种类数不超过 $U$。

**证明**：方案中出现的每一种糖，其类型值都来自 `candyType`，而 `candyType` 中一共只有 $U$ 个不同的值，故方案涉及的种类数 $\le U$。∎

**引理 2（枚数上限）**：任意合法方案吃到的种类数不超过 $k = n/2$。

**证明**：设方案吃到 $t$ 种，每种至少包含 1 枚糖，故方案吃的总枚数 $\ge t$；而合法方案恰好吃 $k$ 枚，于是 $t \le k$。∎

**引理 3（上界可达）**：存在合法方案，恰好吃到 $\min(U,k)$ 种。

**证明**：分两种情形。

- 若 $U \le k$：每种取 1 枚，共 $U$ 枚且 $U \le k$；此时剩余糖果数为 $n - U \ge n - k = k \ge k - U$，从中任取 $k - U$ 枚补足。总枚数 $= k$，种类数 $= U = \min(U,k)$。
- 若 $U > k$：存在至少 $k$ 个互不相同的类型，从中挑出 $k$ 个、每类取 1 枚，总枚数 $= k$，种类数 $= k = \min(U,k)$。

两情形都构造出枚数为 $k$、种类数为 $\min(U,k)$ 的方案。∎

**定理**：算法返回的 $\min(U,k)$ 是最大可能的种类数。

**证明**：由引理 1、2，任何合法方案的种类数都 $\le \min(U,k)$；由引理 3，存在方案达到 $\min(U,k)$。故最大值为 $\min(U,k)$，恰为算法返回值。∎

## 6. 复杂度分析

- **时间**：期望 $O(n)$。一次线性扫描，每个元素做一次哈希插入，期望 $O(1)$；最后 $O(1)$ 比较。若用有序 `set`，则上界为 $O(n\log n)$（$n\le10^4$ 时两者都远低于限制）。理论上哈希最坏可退化到 $O(n^2)$，但本题数据为整数、无对抗性构造，实际不构成风险。
- **空间**：$O(U) \le O(n)$。哈希集合最多存 $n$ 个不同的整数；除输入外没有额外数组。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
#include <algorithm>
using namespace std;

class Solution {
public:
    int distributeCandies(vector<int>& candyType) {
        int n = (int)candyType.size();
        int k = n / 2;                       // n 为偶数，整除即精确值
        unordered_set<int> kinds;
        kinds.reserve(candyType.size() * 2); // 预留桶，减少 rehash
        for (int x : candyType) {
            kinds.insert(x);
            if ((int)kinds.size() == k) return k; // 已达上界，提前返回
        }
        return min((int)kinds.size(), k);
    }
};
```

### Python

```python
class Solution:
    def distributeCandies(self, candyType: List[int]) -> int:
        n = len(candyType)
        k = n // 2                       # n 一定为偶数
        u = len(set(candyType))          # 不同种类数 U
        return min(u, k)
```

## 8. 边界情况与易错点

1. **全部相同**：`[6,6,6,6]` → $U=1$，答案是 1，而不是 $k=2$。别把「能吃的枚数」当成答案。
2. **全部不同**：`[1,2,3,4]` → $U=4 > k=2$，答案是 2（$k$ 才是瓶颈）。此时 $\min$ 的另一侧起作用。
3. **最小规模 $n=2$**：`[1,1]` → 1；`[1,2]` → 1。注意 $k=1$，答案恒为 1，代码不需要特判。
4. **负数值**：`[-1,-1,0,0]` → $U=2$、$k=2$，答案 2。若用「值当数组下标」的计数法，负数会直接越界崩溃；哈希集合没有这个坑。
5. **别把 `min` 放在除号左边**：`min(U, n) / 2` 与 `min(U, n/2)` 含义不同，前者在 `[1,1,2,3]` 上会给出错误结果，这是本题最典型的笔误。
6. **剪枝不等于必须**：`if (kinds.size() == k) return k;` 只是加速；删掉它对答案没有影响，但保留时要注意 $k\ge1$（$n\ge2$ 保证），不会出现提前返回 0 的情况。

**延伸思考**：若医生改口为「**至多**吃 $n/2$ 枚」（可以不吃完），答案立刻变成 $U$——因为上限 A 消失，只要把每种各吃一枚即可；若再加一条「每类糖至多吃 $c_i$ 枚」，问题就变成带容量约束的贪心/背包，需要按收益排序，不再是 $O(n)$ 的常数公式。这说明本题的简洁完全来自「恰好 $n/2$ + 每种至少 1 枚」这两个强假设，做题时先把假设写清楚，往往就能直接读出公式。
