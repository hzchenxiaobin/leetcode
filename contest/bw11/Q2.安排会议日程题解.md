# LeetCode 安排会议日程 题解

## 1. 题目概述

- **标题 / 题号**：安排会议日程（#1229，medium）
- **链接**：https://leetcode.cn/problems/meeting-scheduler/
- **来源**：LeetCode 第 11 场双周赛 Q2
- **难度**：中等
- **标签**：数组、双指针、排序

**题意**：两个人各自的空闲时段列表为 `slots1` 与 `slots2`，时段形如 `[start, end]`。给定会议时长 `duration`，返回**最早**的、两人都有空且长度不小于 `duration` 的时刻——即返回长度恰为 `duration` 的区间 $[t, t + duration]$；不存在这样的公共时段时返回空数组。

**约束**：

- $1 \le slots1.length, slots2.length \le 10^4$
- $slots1[i].length = slots2[i].length = 2$，且 $slots1[i][0] < slots1[i][1]$，$slots2[i][0] < slots2[i][1]$
- $0 \le slots1[i][j], slots2[i][j] \le 10^9$
- $1 \le duration \le 10^6$
- **同一个人**的任意两个时段互不相交（但**两个列表都不保证有序**，且两人之间的时段可以任意交叠）

> ⚠️ 最容易看漏的条件是「同一个人的时段互不相交但**列表未排序**」——这决定了必须先排序再扫；而「每段长度可能小于 duration」意味着可以先过滤掉注定无用的时段（可选优化）。

## 2. 示例

**示例 1**

```text
输入：slots1 = [[10,50],[60,120],[140,210]], slots2 = [[0,15],[60,70]], duration = 8
输出：[60,68]
解释：两人时段 [60,120] 与 [60,70] 的交集为 [60,70]，长度 10 ≥ 8，
     从 60 开始安排 8 个单位即 [60,68]，这是最早的可行时刻。
```

**示例 2**

```text
输入：slots1 = [[10,50],[60,120],[140,210]], slots2 = [[0,15],[60,70]], duration = 12
输出：[]
解释：交集候选只有 [10,15]（长度 5）与 [60,70]（长度 10），都小于 12。
```

**补充示例（无序输入）**

```text
输入：slots1 = [[60,120],[10,50]], slots2 = [[60,70],[0,15]], duration = 8
输出：[60,68]
解释：与示例 1 相同的时段、打乱的顺序——排序后结果一致。
```

## 3. 解题思路

### 3.1 暴力思路

两两枚举时段对 $(A, B)$，其中 $A \in slots1$、$B \in slots2$，计算交集 $[\max(A_s, B_s),\ \min(A_e, B_e)]$：若长度 $\ge duration$，记录候选起点 $\max(A_s, B_s)$；全部枚举完后取最小候选。时间 $O(n_1 n_2)$，最坏 $10^4 \times 10^4 = 10^8$ 次比较，会在时间限制边缘挣扎。暴力唯一的价值是当**对拍参照**（本文对拍脚本正是这么做的）。要利用「同一个人的时段互不相交」这一结构性条件，就得排序后让两个列表像归并一样互推。

### 3.2 核心观察：排序后，「先结束的时段」再也等不来更大的交集

![核心观察：区间交集由 max(起点)、min(终点) 决定，先结束者可弃](images/bw11_q2_interval_intersect.svg)

两个时段 $A = [A_s, A_e]$、$B = [B_s, B_e]$ 的交集长度为

$$\min(A_e, B_e) - \max(A_s, B_s)$$

交集非空（且长度达到 `duration`）时，最优的会议起点就是交集的左端点 $\max(A_s, B_s)$。现在把两个列表各自**按起点排序**，用指针 $i, j$ 指向当前比较的时段，每次考察 $(slots1[i], slots2[j])$：

- 若交集长度 $\ge duration$，立刻返回 $[\max(A_s,B_s),\ \max(A_s,B_s) + duration]$；
- 否则**抛弃先结束的那个时段**：不妨设 $A_e \le B_e$，由「同一个人的时段互不相交且有序」知 $slots2$ 中排在 $B$ 之后的时段 $B'$ 满足 $B'_s > B_e \ge A_e$，即 $B'$ 与 $A$ 的交集为空——**$A$ 已无任何利用价值**，$i$ 安全右移。

被抛弃的时段在另一个列表中**再也配不上任何更晚的时段**，这就是双指针的正确性根基；同时由于两个列表各自按起点有序，指针每一步推进时候选起点 $\max(A_s, B_s)$ **单调不减**，故第一个命中的可行交集就是全局最早的。

> 💡 一个常见的前置优化：长度本身小于 $duration$ 的时段不可能承载会议，排序前可先过滤掉它们，能显著减少后续比较量（不影响正确性，只是加速）。

### 3.3 算法流程

![算法流程：双指针互推，先结束者出局](images/bw11_q2_two_pointer_flow.svg)

```text
1. 将 slots1、slots2 分别按起点升序排序
2. i = 0, j = 0
3. while i < n1 且 j < n2:
4.     lo = max(slots1[i][0], slots2[j][0])      # 交集左端
5.     hi = min(slots1[i][1], slots2[j][1])      # 交集右端
6.     if hi - lo >= duration: 返回 [lo, lo + duration]
7.     if slots1[i][1] < slots2[j][1]: i += 1    # 先结束者出局
8.     else:                      j += 1
9. 返回 []（无可行时段）
```

每轮循环至少一个指针前进一格，总推进次数不超过 $n_1 + n_2$。

### 3.4 示例演算

![示例演算：duration=8 与 duration=12 的指针轨迹](images/bw11_q2_example_walkthrough.svg)

以示例 1/2 的数据走查（slots1 = [10,50],[60,120],[140,210]，slots2 = [0,15],[60,70]）：

| 步骤 | $(i,j)$ | 时段对 | 交集 $[lo,hi]$ | 长度 vs duration | 动作 |
|------|---------|--------|----------------|------------------|------|
| 1 | (0,0) | [10,50] × [0,15] | [10,15] | 5 < 8 | 50 > 15，$j$ 前移 |
| 2 | (0,1) | [10,50] × [60,70] | 空（60 > 50） | 0 < 8 | 50 < 70，$i$ 前移 |
| 3 | (1,1) | [60,120] × [60,70] | [60,70] | $10 \ge 8$ ✓ | 返回 **[60,68]** |

当 `duration = 12` 时，同样的轨迹走到第 3 步：交集 [60,70] 长度 10 < 12，不命中；$70 < 120$ 故 $j$ 前移，$j$ 越界，循环结束返回 `[]`——与官方输出一致。注意第 3 步若命中，答案从交集**左端点**起算，而不是「把会议塞进交集正中间」。

## 4. 算法细节

1. **必须先排序**：题目不保证输入有序，而双指针的「先结束者出局」论证完全依赖两端列表各自按起点有序（从而同人的后续时段起点更大）。
2. **先结束者出局，而不是先开始者**：移动指针的依据是**终点**的大小（小者出局）；若写成比较起点，遇上一长一短两段（如 $[10,90]$ 与 $[20,30]$）会把还大有可为的长时段提前扔掉。
3. **返回的是恰为 duration 的区间**：命中后返回 $[lo, lo+duration]$，即便交集比 duration 长也只取前一段——「最早」由起点定义，起点越小越好，自然取交集左端点。
4. **过滤短时段（可选）**：排序前丢弃 $end - start < duration$ 的时段，能把 3.4 第 1 步这类注定失败的比较直接省掉。
5. **「最早」的单调性论证**：指针只在起点有序的列表上前进，候选起点 $\max(A_s, B_s)$ 随每一步单调不减（见 5 引理 3），因此**首个命中即最早**，无需再回头比较。
6. **区间语义**：题面称时段「inclusive」，但会议时长是连续量，判断条件始终是 $\min(e_1,e_2) - \max(s_1,s_2) \ge duration$，不需要 $\pm 1$ 的离散修正。

## 5. 正确性证明

**引理 1（抛弃的安全性）**：设两列表按起点升序、同人时段互不相交。若当前对 $(A, B)$ 未命中（交集长度 $< duration$）且 $A_e \le B_e$，则对 $slots2$ 中所有排在 $B$ 之后（含 $B$ 之后才被考察）的时段 $B'$，$(A, B')$ 的交集为空。

**证明**：同人时段互不相交且按起点有序，故 $B'_s > B_e \ge A_e \ge A_s$。于是 $\min(A_e, B'_e) = A_e < B'_s = \max(A_s, B'_s)$，交集为空，更遑论长度 $\ge duration$。∎

**引理 2（未考察对的有效性下界）**：双指针扫描过程中的任一时刻，所有「尚未被考察过、且至少一端已被跳过」的时段对 $(A, B)$ 要么交集为空，要么交集长度 $< duration$——即**不存在被错过的可行对**。

**证明**：对指针推进次数做归纳。初始时无任何被跳过的时段，命题平凡。设命题在某步成立且该步因 $A_e \le B_e$ 而弃 $A$（$i$ 前移）：其一，$A$ 与 $slots2$ 中尚未考察的所有 $B'$ 的配对由引理 1 知交集为空；其二，$A$ 与 $slots2$ 中**更早**的 $B''$ 的配对，在当初 $j$ 越过 $B''$ 时已由归纳假设覆盖（当时 $B''$ 因「先结束」被弃，同样的论证保证 $B''$ 与其后所有 $slots1$ 时段的配对不可行）。故弃 $A$ 后命题仍成立。对称地，弃 $B$ 时同理。∎

**引理 3（最早性）**：扫描中候选起点 $t_{i,j} = \max(slots1[i][0], slots2[j][0])$ 随每步指针推进**单调不减**；且首个命中的可行对的起点是所有可行对起点中的最小值。

**证明**：两列表按起点有序，$i$ 前移使 $slots1[i][0]$ 增大、$j$ 前移使 $slots2[j][0]$ 增大，二者取 max 只会不减，第一部分得证。对于第二部分：任取可行对 $(A^\ast, B^\ast)$，若扫描过程中它被「跳过」（即扫描在 $A^\ast$ 或 $B^\ast$ 被弃之后才考察到对方列表的某时段），则由引理 2 它本不可行，矛盾；故 $(A^\ast, B^\ast)$ 必然在扫描中被显式考察到，而它之前的所有考察要么不命中（起点 $\le t$ 但长度不足）要么未命中就跳过，首个命中对的起点 $\le$ 任何可行对被考察时的起点 $\le (A^\ast, B^\ast)$ 的起点。又命中对本身是可行对，故其起点即全局最小可行起点。∎

**定理**：算法返回最早的可行会议区间 $[t^\ast, t^\ast + duration]$；不存在时返回空数组。

**证明**：存在性方向：若扫描命中，由交集定义 $\min(A_e,B_e) - \max(A_s,B_s) \ge duration$，取 $t = \max(A_s,B_s)$，则 $[t, t+duration] \subseteq A \cap B$，输出合法。完备性方向：若存在可行对而算法未命中，与引理 2、引理 3 矛盾（可行对必被考察且必命中）。最早性由引理 3 保证。扫描终止时（$i$ 或 $j$ 越界），引理 2 保证不存在任何可行对，返回空数组正确。∎

## 6. 复杂度分析

- **时间**：$O(n_1 \log n_1 + n_2 \log n_2)$。排序主导；扫描阶段每轮至少推进一个指针，至多 $n_1 + n_2$ 轮，每轮 $O(1)$。若先过滤短时段，$n$ 进一步缩小但量级不变。
- **空间**：$O(1)$ 额外空间（C++ 原地排序；若语言排序需要额外缓冲或不想修改输入，则为 $O(n)$ 存副本）。

对照暴力 $O(n_1 n_2)$：$10^4$ 对 $10^4$ 时约 $10^8$ 次操作，双指针把它压到两万次级别的扫描加上排序，这正是「有序结构 + 单调舍弃」的经典收益。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minAvailableDuration(vector<vector<int>>& slots1, vector<vector<int>>& slots2, int duration) {
        sort(slots1.begin(), slots1.end());
        sort(slots2.begin(), slots2.end());
        int i = 0, j = 0, n1 = (int)slots1.size(), n2 = (int)slots2.size();
        while (i < n1 && j < n2) {
            int lo = max(slots1[i][0], slots2[j][0]);   // 交集左端
            int hi = min(slots1[i][1], slots2[j][1]);   // 交集右端
            if (hi - lo >= duration) return {lo, lo + duration};
            if (slots1[i][1] < slots2[j][1]) ++i;       // 先结束者出局
            else ++j;
        }
        return {};
    }
};
```

### Python

```python
class Solution:
    def minAvailableDuration(self, slots1: list[list[int]], slots2: list[list[int]], duration: int) -> list[int]:
        slots1.sort()
        slots2.sort()
        i = j = 0
        while i < len(slots1) and j < len(slots2):
            lo = max(slots1[i][0], slots2[j][0])
            hi = min(slots1[i][1], slots2[j][1])
            if hi - lo >= duration:
                return [lo, lo + duration]
            if slots1[i][1] < slots2[j][1]:
                i += 1
            else:
                j += 1
        return []
```

**验证记录**：两份代码均通过官方双示例（[60,68] 与 []）；与「两两枚举全部时段对取最早可行起点」的暴力器对拍 **40000 组**随机用例（时段数 1–6、时间点打乱、duration 1–15，刻意包含大量无解情形），0 失配；另以 $10^4 \times 10^4$ 规模的随机大例验证 C++ 与 Python 结果一致且耗时毫秒级。

## 8. 边界情况与易错点

1. **忘记排序**：题目并未承诺输入有序，直接双指针会在无序输入上漏解；排序是第一步。
2. **指针移动方向写反**：应比较**终点**、弃先结束者；比较起点会让长时段被过早丢弃（反例：$[10,90]$ 与 $[20,30]$、$[40,50]$、$[70,80]$，duration=5——若按起点移动会丢掉与 $[90]$ 内多个时段的命中机会）。
3. **命中后别再前移指针**：题目只要**一个**最早时刻，命中即返回；继续扫描反而可能被后面更晚的命中覆盖。
4. **答案从交集左端点起算**：返回 $[lo, lo + duration]$ 而非交集整体；「最早」指的是开始时刻最小。
5. **短时段是纯噪音**：长度 $< duration$ 的时段永远无法命中，过滤与否不影响正确性，但能显著降低比较量——注意过滤应在排序前后保持一致（先过滤再排序更划算）。
6. **空解返回格式**：C++ 返回 `{}`、Python 返回 `[]`，不要返回 `{-1,-1}` 之类的哨兵。
7. **数值范围**：时刻上限 $10^9$、$lo + duration$ 上溢不可能（约 $10^9 + 10^6$），`int` 足够。
