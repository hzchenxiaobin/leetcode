# LeetCode 等差数列中缺失的数字 题解

## 1. 题目概述

- **标题 / 题号**：等差数列中缺失的数字（#1228，easy）
- **链接**：https://leetcode.cn/problems/missing-number-in-arithmetic-progression/
- **来源**：LeetCode 第 11 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：数组 `arr` 原本是一个**等差数列**——对所有 $0 \le i < n-1$，相邻差 $arr[i+1] - arr[i]$ 全相等。后来从中**删掉了恰好一个值**，且被删的值**不是原数组的首项也不是尾项**。要求返回这个被删掉的值。

**约束**：

- $3 \le arr.length \le 1000$
- $0 \le arr[i] \le 10^5$

> 💡 两个关键前提容易被忽略：其一，「等差」允许公差为负（递减数列）甚至为 0（常数列）；其二，「删的不是首尾」意味着**现数组的首尾就是原数组的首尾**——这是一切解法能够「端点定乾坤」的根基。

## 2. 示例

**示例 1**

```text
输入：arr = [5,7,11,13]
输出：9
解释：原数组为 [5,7,9,11,13]，公差 d = 2，删掉 9 后相邻差为 [2,4,2]。
```

**示例 2**

```text
输入：arr = [15,13,12]
输出：14
解释：原数组为 [15,14,13,12]，公差 d = -1，删掉 14 后相邻差为 [-2,-1]。
```

**补充示例（公差为 0）**

```text
输入：arr = [7,7,7]
输出：7
解释：原数组为 [7,7,7,7]，删除任意一个内部 7 后剩下的全是 7。
```

示例 2 提醒我们**不能**假设数列递增；补充示例提醒我们 $d = 0$ 时「差分找断点」的思路会彻底失效，而本文采用的做法天然覆盖它。

## 3. 解题思路

### 3.1 暴力思路

最朴素的办法：枚举缺失位置与公差，重建数列再验证——猜测缺失值落在 $arr[i]$ 与 $arr[i+1]$ 之间，公差 $d$ 一旦确定缺失值即 $arr[i] + d$，于是枚举 $i$ 与候选 $d$、逐项检查重建数组是否为等差数列，$O(n^2)$ 量级才能搜完。更直接的暴力是**差分扫描**：对每个相邻差 $arr[i+1] - arr[i]$，正常位置都等于公差 $d$，缺失处会变成 $2d$，于是「找最大相邻差、取其中点」即可（官方提示即是此法）。它要求先辨明方向：递增取最大差、递减取最小差，还得**特判 $d=0$**（此时所有差都是 0，无从找「断点」）。这些分支都不难，但签到题更好的习惯是找一条**不依赖任何特判**的路径。

### 3.2 核心观察：等差数列求和公式，一次减法还原缺项

![核心观察：首尾未动，用求和公式反推缺失值](images/bw11_q1_ap_sum_model.svg)

被删的值**不在首尾** ⇒ 现数组的 $arr[0]$ 与 $arr[n-1]$ 就是原数列的首项与末项。原数列共 $m = n+1$ 项，由等差数列求和公式：

$$S_{\text{原}} = \frac{m \cdot (\text{首项} + \text{末项})}{2} = \frac{(n+1)\cdot(arr[0] + arr[n-1])}{2}$$

而缺失值恰为「原和 − 现和」：

$$\boxed{\;answer = \frac{(n+1)\cdot(arr[0] + arr[n-1])}{2} \;-\; \sum_{i=0}^{n-1} arr[i]\;}$$

这条式子的两个潜在坑都被数学本身消化了：

- **$d = 0$ 无需特判**：常数列 $[v,\dots,v]$（$n+1$ 项）的和为 $(n+1)\cdot v$，现和为 $n\cdot v$，差值恰为 $v$——公式自动给出正确答案；
- **整数除法无精度问题**：记首项 $a$、公差 $d$、项数 $m$，则 $m\,(a + l) = m\,(2a + (m-1)d)$，其中 $m(m-1)$ 必为偶数，故 $(n+1)\cdot(arr[0]+arr[n-1])$ **必是 2 的倍数**，整除精确、全程可用整数运算。

> ⚠️ 唯一要当心的是 C++ 的溢出：$(n+1)\cdot(arr[0]+arr[n-1])$ 最大约 $1001 \times (2\times 10^5) \approx 2\times 10^8$，恰好还在 `int` 范围内，但距上限 $2^{31}-1 \approx 2.1\times 10^9$ 只差一个 2 的因子，养成用 `long long` 的习惯更稳妥。

### 3.3 算法流程

![算法流程：一步求和公式，无分支无特判](images/bw11_q1_algorithm_flow.svg)

```text
1. n = arr.length
2. original = (n + 1) * (arr[0] + arr[n-1]) / 2     # 64 位整数
3. cur = sum(arr)
4. 返回 original - cur
```

流程里没有任何条件分支——公差正、负、零三种情形走的是同一条路。

### 3.4 示例演算

![示例演算：三个用例的求和与差值](images/bw11_q1_example_walkthrough.svg)

| arr | 原项数 $m$ | $S_{\text{原}} = m(\text{首}+\text{末})/2$ | 现和 | 缺失值 |
|-----|-----------|-------------------------------------------|------|--------|
| [5,7,11,13] | 5 | $5\times(5+13)/2 = 45$ | 36 | $45-36=9$ |
| [15,13,12] | 4 | $4\times(15+12)/2 = 54$ | 40 | $54-40=14$ |
| [7,7,7] | 4 | $4\times(7+7)/2 = 28$ | 21 | $28-21=7$ |

第三行是 $d=0$ 的情形：差分法需要特判它，而求和法的计算过程与前两行**逐字符相同**。

## 4. 算法细节

1. **「首尾不动」是公式成立的前提**：题目保证被删值不是首尾，故 $arr[0]$、$arr[n-1]$ 即原首末项。若题目改为「可能删首尾」，此式失效，只能回到差分或枚举法。
2. **整数除法的整除性**：见 3.2 的推导，$m(a+l)$ 必为偶数，故 `// 2` 不产生舍入误差；不必担心用浮点数引入精度问题。
3. **差分法作对照**（可作为对拍参照）：$d = \dfrac{arr[n-1] - arr[0]}{n}$（原数列跨距为 $n\cdot d$），从左到右找第一个 $arr[i+1]-arr[i] \ne d$ 的位置，答案为 $arr[i] + d$；若全程未找到断点则必然 $d = 0$，答案 $arr[0]$。两种做法可互相验证。
4. **求和顺序**：先算前缀和或直接累加皆可，$n \le 1000$ 规模下无性能差异；若数据范围放大到 $10^6$ 级别，两种解法都仍是线性，无压力。
5. **数据类型**：C++ 用 `(long long)` 完成乘法；Python 原生大整数，无此虞。

## 5. 正确性证明

**引理 1（端点保持）**：设原等差数列为 $A_0, A_1, \dots, A_m$（$m = n+1$），被删项下标 $t$ 满足 $1 \le t \le m-1$，则现数组 $arr[i] = A_i$（$0 \le i < t$），$arr[i] = A_{i+1}$（$t-1 < i \le m-1$，即 $i \le n-1$）；特别地 $arr[0] = A_0$，$arr[n-1] = A_m$。

**证明**：删除中间一项后，其左侧元素下标不变，右侧元素整体左移一位，首项 $A_0$ 与末项 $A_m$ 分别落在现数组下标 $0$ 与 $m-1 = n-1$。∎

**引理 2（求和公式与整除性）**：项数为 $m$、首项 $a$、公差 $d$ 的等差数列其和为 $S = m\,(a+l)/2$，其中 $l = a + (m-1)d$ 为末项；且 $m\,(a+l)$ 是偶数。

**证明**：$S = \sum_{i=0}^{m-1}(a + id) = ma + d\,\frac{m(m-1)}{2} = \frac{m\,(2a + (m-1)d)}{2} = \frac{m(a+l)}{2}$。又 $m(a+l) = m\cdot 2a + m(m-1)d$，第一项含因子 2，第二项中 $m(m-1)$ 为相邻整数之积、必为偶数，故 $m(a+l)$ 为偶数，除法精确。∎

**定理**：算法返回被删除的值。

**证明**：由引理 1，$arr[0] = A_0$、$arr[n-1] = A_m$，引理 2 给出原数列和 $S_{\text{原}} = \frac{(n+1)(arr[0]+arr[n-1])}{2}$（此即算法第 2 步，且由引理 2 整除精确）。现数组的和 $\sum arr = S_{\text{原}} - A_t$：因为现数组恰是原数列去掉 $A_t$ 后剩余 $n$ 项之和。于是算法第 4 步返回
$$S_{\text{原}} - \sum arr = S_{\text{原}} - (S_{\text{原}} - A_t) = A_t,$$
即被删值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次遍历求和，其余为常数次算术运算。
- **空间**：$O(1)$。只使用常数个变量，无额外数据结构。

作为对照，暴力枚举公差与断点需要 $O(n^2)$；差分扫描同为 $O(n)$ 但需要为负公差与 $d=0$ 各开一个分支，求和法在实现简洁性上胜出。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int missingNumber(vector<int>& arr) {
        int n = (int)arr.size();
        long long total = (long long)(n + 1) * (arr[0] + arr[n - 1]) / 2;  // 原和，乘法用 64 位
        long long sum = 0;
        for (int v : arr) sum += v;                                        // 现和
        return (int)(total - sum);
    }
};
```

### Python

```python
class Solution:
    def missingNumber(self, arr: list[int]) -> int:
        n = len(arr)
        original = (n + 1) * (arr[0] + arr[-1]) // 2   # 原和（整除必精确）
        return original - sum(arr)
```

**验证记录**：两份代码均通过官方双示例（9、14）；另以「随机生成等差数列（项数 4–12，公差含 0、负数，值域 ±50 至 $10^5$）→ 随机删除内部一项」的生成器对拍 **200000 组**，与被删真值 0 失配；同批用例喂给 C++ 与 Python 亦全部一致。

## 8. 边界情况与易错点

1. **$d = 0$（全相等）是差分类解法的坟场**：所有相邻差都为 0，既没有「2 倍公差」的断点也无从谈「最大差」；求和法无需理会这一特判。
2. **递减数列**（$d<0$）：示例 2 即是。若按「找最大相邻差取中点」的提示做，必须先统一方向（或对差取绝对值），否则会把 -2 当成「更小的差」漏掉。
3. **别误以为缺项必在正中间**：删除位置可以在任意内部下标（含紧邻端点的第二项/倒数第二项），求和法对此无感，差分法也只需找到那一个断点。
4. **溢出**：$(n+1)\cdot(arr[0]+arr[n-1])$ 上界约 $2\times 10^8$，`int` 勉强够但很贴边（若约束改成 $10^9$ 级就炸了），统一上 `long long`。
5. **整除性**：$m(a+l)$ 必为偶数（证明见引理 2），因此 `/ 2` 不会丢精度；若随手写成 `1.0 *` 浮点版本，反而可能在边界上抖出 $10^{-9}$ 误差再被截断。
6. **输入不保证递增**：题面只说等差，公差可正可负可为零，任何「先假设递增再翻转」的实现都要记得负公差这条测试线。
