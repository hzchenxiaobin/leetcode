# LeetCode 可被三整除的最大和 题解

## 1. 题目概述

- **标题 / 题号**：可被三整除的最大和（#1262，Medium）
- **链接**：https://leetcode.cn/problems/greatest-sum-divisible-by-three/
- **来源**：LeetCode 第 163 场周赛 Q3
- **难度**：中等
- **标签**：动态规划、贪心、数组

**题意**：给定正整数数组 `nums`，从中任意挑选若干元素（同一个下标最多用一次，也可以一个都不选），要求所选元素之和能被 3 整除，求这个和的**最大值**。

**约束**：

- $1 \le \text{nums.length} \le 4 \times 10^4$
- $1 \le \text{nums[i]} \le 10^4$
- 选择是**子集**（按下标挑），与顺序无关；空子集和为 0，而 $0$ 能被 3 整除，所以答案一定存在

## 2. 示例

**示例 1**

```text
输入：nums = [3,6,5,1,8]
输出：18
解释：选出 3 + 6 + 1 + 8 = 18，能被 3 整除。
      再多选一个 5 得 23，23 mod 3 = 2，反而不合法。
```

**示例 2**

```text
输入：nums = [4]
输出：0
解释：唯一的 4 不能被 3 整除，只能一个都不选；空集和为 0，仍满足「能被 3 整除」。
```

**示例 3**

```text
输入：nums = [1,2,3,4,4]
输出：12
解释：1 + 3 + 4 + 4 = 12；全选的和是 14，14 mod 3 = 2，必须放弃一个余数为 2 的元素（即 2）。
```

## 3. 解题思路

### 3.1 暴力思路

子集共 $2^n$ 个，枚举每个子集、求和、判断能否被 3 整除并取最大值，复杂度 $O(2^n \cdot n)$。$n = 4 \times 10^4$ 时毫无可能。

「局部贪心」同样不成立：若总和不能被 3 整除就删掉最小的元素，那么 `nums = [2,2,6]` 总和为 10，删掉最小的 2 后得 8，仍然不能被 3 整除；正确做法是删掉**两个** 2 得 6。可见必须让算法能同时考虑「删一个」和「删两个」的所有组合。

### 3.2 核心观察：只保留「和 mod 3」三个状态

![余数状态机：三种转移与支配性](images/wc163_q3_mod_state_ring.svg)

暴力的浪费在于把 $2^n$ 个子集当成互不相同的东西，而题目只关心**和除以 3 的余数**：三个余数 $0,1,2$ 就足以刻画「当前和落在哪一类」。

关键性质（**支配性**）：若两个已选子集 $A, B$ 的和模 3 相同，且 $\text{sum}(A) \ge \text{sum}(B)$，那么往后无论再加哪些元素（同一批候选、同样的加法），$A$ 的和都不会比 $B$ 差。于是 $B$ 可以整个丢掉——**每个同余类只需留下和最大的那个代表**。

据此定义

$$dp[r] = \text{已扫描前缀的所有子集中，和} \equiv r \pmod 3 \text{ 的最大和}$$

不可达时记 $dp[r] = -\infty$。状态数恒为 3，与前缀长度无关，这正是把指数级搜索压成线性 DP 的原因。

### 3.3 状态转移与算法流程

![DP 流程：副本继承 + 三状态转移](images/wc163_q3_dp_flow.svg)

对当前元素 $v$，任何子集只有两种命运：**不选 $v$**（继承旧值），或**选 $v$**（和加上 $v$，余数整体平移 $v \bmod 3$）。按「源状态」推送的转移最好写：

$$ndp\bigl[(r + v) \bmod 3\bigr] = \max\Bigl(ndp\bigl[(r + v) \bmod 3\bigr],\ dp[r] + v\Bigr), \quad dp[r] \ne -\infty$$

等价的目标式写法是

$$ndp[r] = \max\Bigl(dp[r],\ dp\bigl[(r - v) \bmod 3\bigr] + v\Bigr)$$

其中约定 $-\infty + v = -\infty$。完整流程：

1. 初始化 $dp = (0, -\infty, -\infty)$：空集和为 0、余数为 0；另外两个余数尚不可达。
2. 依次取出 $v \in \text{nums}$，把 $dp$ **整体复制**成 $ndp$（这一步代表「不选 $v$」）。
3. 对 $r = 0,1,2$：若 $dp[r]$ 可达，用 $dp[r] + v$ 去更新 $ndp[(r + v) \bmod 3]$。
4. 令 $dp \leftarrow ndp$ 进入下一轮；扫描结束后返回 $dp[0]$。

### 3.4 示例演算

![示例演算：nums = [3,6,5,1,8] 的三状态表](images/wc163_q3_walkthrough.svg)

以 `nums = [3,6,5,1,8]` 为例，前三个数的余数是 $0,0,2$，状态还很稀疏；真正开始分叉是加入 `1` 的时候：

- 加入前 $dp = (9, -\infty, 14)$，其中 $9 = 3+6$（余数 0），$14 = 9+5$（余数 2）。
- 选 `1`：$9 + 1 = 10$ 落到余数 1，$14 + 1 = 15$ 落到余数 0，于是 $dp = (15, 10, 14)$。
- 再选 `8`（余数 2）：$10 + 8 = 18$ 落到余数 0，$15 + 8 = 23$ 落到余数 2，$14 + 8 = 22$ 落到余数 1，故 $dp = (18, 22, 23)$。

答案 $dp[0] = 18$，与官方示例一致。注意 $23$（全选）虽然最大，但余数是 2，只能待在 $dp[2]$ 里；能直接交出答案的只有余数 0 那一格。

## 4. 算法细节

1. **不可达必须显式表示**：$dp[1], dp[2]$ 的初值取 $-\infty$ 而不是 0。用 0 占位等于宣称「已经有一组元素凑出余数 1 且和为 0」，后续会凭空生出非法状态，答案被高估。
2. **必须借助副本（滚动数组）**：原地更新会让同一个 $v$ 被反复使用，等价于把题改成「每种元素无限个」的完全背包。例如 `nums = [4]` 时，原地更新先用唯一的 4 得到 $dp[1] = 4$，再用它得到 $dp[2] = 8$——这个 8 是选了两个 4 的非法结果。
3. **取模只作用于余数，累加要用完整的 $v$**：状态里存的是「和」本身而不是「和除以 3 的商」，$v \bmod 3$ 只用来算下一个状态的下标。
4. **数据范围**：最大可能和约为 $4 \times 10^4 \times 10^4 = 4 \times 10^8$，仍在 32 位有符号整数范围内；但哨兵与和相加时建议统一用 64 位，或先判可达再相加，避免 $-\infty$ 参与加法造成溢出。
5. **哨兵可以取 $-1$**：元素全为正，任何真实子集的和都 $\ge 0$，用 $-1$ 表示不可达既安全又便于写 `dp[r] >= 0`。若改用 `float('-inf')`，$-\infty$ 会参与加法与 `max`，和里就混进浮点，返回类型容易出问题；统一用整数哨兵（$-1$ 或 $-10^{18}$）最稳。
6. **贪心对照（等价写法）**：记 $S = \sum \text{nums}$、$r = S \bmod 3$。若 $r = 0$ 答案就是 $S$；否则要丢掉一个「和 $\equiv r \pmod 3$」的最便宜子集 $C$，答案 $= S - \text{sum}(C)$，而 $C$ 的候选只有两类：
   - $r = 1$：丢掉一个最小的 $\equiv 1$ 元素，或丢掉两个最小的 $\equiv 2$ 元素；
   - $r = 2$：丢掉一个最小的 $\equiv 2$ 元素，或丢掉两个最小的 $\equiv 1$ 元素。

   只需扫一遍维护两类各自的「最小两个值」，$O(n)$ 时间、$O(1)$ 空间，与 DP 完全等价（证明见 §5 引理 3）。
7. **不需要排序**：DP 与上述贪心都是扫一遍，排序只会把 $O(n)$ 抬到 $O(n \log n)$，对大数组是纯浪费。

## 5. 正确性证明

**引理 1（支配性）**：设 $A, B$ 是同一前缀的两个子集，$\text{sum}(A) \equiv \text{sum}(B) \pmod 3$ 且 $\text{sum}(A) \ge \text{sum}(B)$。则对任意取自剩余元素的子集 $T$，仍有 $\text{sum}(A) + \text{sum}(T) \equiv \text{sum}(B) + \text{sum}(T) \pmod 3$，且前者不小于后者。

**证明**：同余关系对加法封闭，两边同加 $\text{sum}(T)$ 后余数相同；大小关系两边同加同一个数保持不变。∎

**引理 2（状态不变式）**：处理完前 $i$ 个元素后，

$$dp[r] = \max\bigl\{\text{sum}(S) : S \subseteq \text{nums}[0..i),\ \text{sum}(S) \equiv r \pmod 3\bigr\}$$

若该集合为空则 $dp[r] = -\infty$。

**证明**：对 $i$ 归纳。$i = 0$ 时只有空集，和为 0，$dp = (0, -\infty, -\infty)$，成立。设处理完前 $i$ 个元素后不变式成立，考察第 $i$ 个元素 $v$：任一子集 $S \subseteq \text{nums}[0..i]$ 分两类。不含 $v$ 时 $\text{sum}(S)$ 取自旧状态；含 $v$ 时 $S = S' \cup \{v\}$，其中 $S' \subseteq \text{nums}[0..i)$，有 $\text{sum}(S) = \text{sum}(S') + v$，且 $\text{sum}(S) \equiv r$ 等价于 $\text{sum}(S') \equiv (r - v) \bmod 3$。转移在每一类里取最大值，覆盖了全部子集；再由引理 1，同余类里只保留最大和的代表不会丢掉最优解。故不变式在 $i+1$ 时仍成立。∎

**定理**：算法返回的 $dp[0]$ 等于「能被 3 整除的最大子集和」。

**证明**：由引理 2，扫描完所有元素后 $dp[0] = \max\{\text{sum}(S) : \text{sum}(S) \equiv 0 \pmod 3\}$。空集的和为 0，而 $0 \bmod 3 = 0$，所以这个集合非空，$dp[0]$ 取到有限值且 $\ge 0$；它由某个合法子集达成，故 $dp[0] \le \text{OPT}$。反过来，任一合法子集的和都是 $dp[0]$ 的候选，故 $\text{OPT} \le dp[0]$。两边夹得 $dp[0] = \text{OPT}$。∎

**引理 3（贪心删除的等价性）**：记 $S = \sum \text{nums}$、$r = S \bmod 3$。若 $r = 0$ 则 $\text{OPT} = S$；若 $r \ne 0$ 则

$$\text{OPT} = S - \min\begin{cases}\min\{\,v : v \equiv r \pmod 3\,\}\\[2pt] \text{两个最小的、}\equiv (-r) \pmod 3 \text{ 的元素之和}\end{cases}$$

**证明**：$T$ 合法 $\iff \text{sum}(T) \equiv 0 \pmod 3$，其补集 $C = \text{nums} \setminus T$ 满足 $\text{sum}(C) = S - \text{sum}(T) \equiv r \pmod 3$；反之任一和 $\equiv r$ 的子集 $C$ 都给出合法补集 $T$。于是最大化 $\text{sum}(T)$ 等价于在所有「和 $\equiv r \pmod 3$」的子集 $C$ 中最小化 $\text{sum}(C)$。

看 $C$ 的余数构成：设其中 $\equiv 1$ 的元素有 $c_1$ 个、$\equiv 2$ 的有 $c_2$ 个，则 $c_1 + 2c_2 \equiv r \pmod 3$。当 $r = 1$：若 $c_1 \ge 1$，代价最小的方案是取一个最小的 $\equiv 1$ 元素；若 $c_1 = 0$，则 $2c_2 \equiv 1 \pmod 3$，即 $c_2 \equiv 2 \pmod 3$，代价最小的方案是取两个最小的 $\equiv 2$ 元素。$r = 2$ 时对称。所有元素为正，故每种结构里取「最小的一个／两个」即代价最小，多取元素只会让 $\text{sum}(C)$ 更大。又因 $r = S \bmod 3$ 保证候选至少有一类存在（$r = 1$ 且无 $\equiv 1$ 元素时必有 $c_2 \equiv 2 \pmod 3$，即至少两个），贪心总有可行解，与 DP 的最优值一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素进入内层后只做 3 次 $O(1)$ 的比较与赋值，总计约 $3n$ 次操作；贪心写法同样是一趟扫描维护 4 个最小值。
- **空间**：$O(1)$。只有 $dp$、$ndp$ 两个长度为 3 的数组与若干标量，与 $n$ 无关（不计输入本身）；贪心写法只需 4 个整数。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int maxSumDivThree(vector<int>& nums) {
        const long long NEG = -1;                    // 和恒非负，-1 表示不可达
        long long dp[3] = {0, NEG, NEG};             // 空集：和 0，余数 0
        for (int v : nums) {
            long long ndp[3] = {dp[0], dp[1], dp[2]};// 不选 v：整组继承
            for (int r = 0; r < 3; r++) {
                if (dp[r] < 0) continue;             // 不可达状态跳过
                int nr = (r + v) % 3;                // 选 v：余数平移
                if (dp[r] + v > ndp[nr]) ndp[nr] = dp[r] + v;
            }
            for (int r = 0; r < 3; r++) dp[r] = ndp[r];
        }
        return (int)dp[0];
    }
};
```

### Python

```python
class Solution:
    def maxSumDivThree(self, nums: list[int]) -> int:
        dp = [0, -1, -1]                 # -1：该余数不可达；dp[0] = 0 对应空集
        for v in nums:
            ndp = dp[:]                  # 不选 v：整组继承
            for r in range(3):
                if dp[r] < 0:            # 不可达状态跳过
                    continue
                nr = (r + v) % 3         # 选 v：余数平移
                if dp[r] + v > ndp[nr]:
                    ndp[nr] = dp[r] + v
            dp = ndp
        return dp[0]
```

## 8. 边界情况与易错点

1. **元素全是 3 的倍数**：答案就是总和，DP 与贪心都会直接给出 $S$，无需特判。
2. **答案可以是 0**：`[4]`、`[2,5]`、`[1,1]` 的答案都是 0，对应「一个都不选」。因此返回值不能初始化为 $-1$，更不能把 $-\infty$ 传出去。
3. **贪心时「凑不够两个元素」要显式判空**：$r = 1$ 且数组里只有一个 $\equiv 2$ 的元素时，不能拿 0 顶替第二个元素，否则会算出一个并不存在的删除方案。虽然由引理 3，$r = S \bmod 3$ 已保证候选至少存在一类，兜底分支仍要写对。
4. **原地更新会把元素用两次**：见 §4 第 2 条。本题状态只有 3 个，直接开 $ndp$ 最直观；若为了省空间在原数组上更新，必须先把三个旧值全部缓存下来，否则一定会读到本轮刚写入的结果（三个余数首尾相接成环，单纯「倒序」也躲不开）。
5. **不要把「和」与「余数」混用**：$dp$ 存的是和，转移是拿 $dp[r]$ 与 $v$ 相加后写入 $ndp$；若误把本轮刚更新的 $ndp$ 值再当源状态继续转移，等价于把同一个元素重复使用。
6. **Python 的类型问题**：整数哨兵（$-1$、$-10^{18}$）全程只在整数间比较相加；若用 `float('-inf')`，一旦漏掉可达性判断、让 $-\infty$ 参与运算，$dp$ 里就会混进浮点，LeetCode 会判类型错误。
7. **别只删一个元素**：`[2,2,6]` 中 $S = 10$，正确做法是删掉两个 2（和 4）得到 6；只删最小的 2 得 8，$8 \bmod 3 = 2$ 依然不合法。
