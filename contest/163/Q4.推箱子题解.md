# LeetCode 推箱子 题解

## 1. 题目概述

- **标题 / 题号**：推箱子（#1263，hard）
- **链接**：https://leetcode.cn/problems/minimum-moves-to-move-a-box-to-their-target-location/
- **来源**：LeetCode 第 163 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、数组、矩阵、堆（优先队列）

**题意**：给定 $m \times n$ 的仓库网格，`'S'` 是玩家，`'B'` 是唯一的箱子，`'T'` 是唯一的目标格，`'#'` 是墙，`'.'` 是地板。玩家每次可以向上下左右走一格（不能进墙，也不能穿过箱子）；当玩家**紧贴箱子**并朝箱子的方向再走一格时，箱子被推到相邻的地板格，记作**一次推动**。求把箱子推到 `'T'` 所需的最少**推动次数**，无解返回 `-1`。

**约束**：

- $1 \le m, n \le 20$，即格子总数 $mn \le 400$
- `grid` 的字符只可能是 `'.'`、`'#'`、`'S'`、`'T'`、`'B'`
- `'S'`、`'B'`、`'T'` 各恰好出现一次，因此箱子初始**必然不在**目标格上

## 2. 示例

**示例 1**

```text
输入：grid = [["#","#","#","#","#","#"],["#","T","#","#","#","#"],["#",".",".","B",".","#"],
             ["#",".","#","#",".","#"],["#",".",".",".","S","#"],["#","#","#","#","#","#"]]
输出：3
解释：先绕到 (2,4) 把箱子向左推两格到 (2,1)，再绕到 (3,1) 向上推一格，共 3 次推动。
```

**示例 2**

```text
输入：grid = [["#","#","#","#","#","#"],["#","T","#","#","#","#"],["#",".",".","B",".","#"],
             ["#","#","#","#",".","#"],["#",".",".",".","S","#"],["#","#","#","#","#","#"]]
输出：-1
解释：与示例 1 只差一格——(3,1) 变成墙，玩家站不到箱子下方，无法把它推上去。
```

**示例 3**

```text
输入：grid = [["#","#","#","#","#","#"],["#","T",".",".","#","#"],["#",".","#","B",".","#"],
             ["#",".",".",".",".","#"],["#",".",".",".","S","#"],["#","#","#","#","#","#"]]
输出：5
解释：向下、向左、向左、向上、再向上（5 次推动，中间的绕路不计入答案）。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的写法是以「一步动作」为单位做 BFS，状态记 $(箱子, 玩家)$，距离记动作数。这行不通：题目只数**推动次数**，玩家绕路不计数。示例 3 的最优方案是 8 步走动 + 5 次推动 = 13 个动作，按动作数分层会让「走一步」和「推一次」等价，BFS 第一次到达终点时的层数不是推动次数，答案语义直接错了。另一种暴力是枚举推动序列（迭代加深 DFS）：每步 4 个方向，答案是 $k$ 就要搜 $4^k$ 条路径，$k$ 稍大立刻爆炸，而且每次判断「玩家能否站到推箱位置」都要重算可达性。

### 3.2 核心观察：(箱子, 玩家) 状态 + 0/1 权图

![状态设计与 0/1 权边](images/wc163_q4_state_model.svg)

玩家位置不必精确到「每一步怎么走」，但它决定了**下一步能不能推、往哪推**，所以状态必须同时包含两者：

$$\text{state} = (b, p), \qquad b, p \in [0, mn)$$

状态之间只有两类转移：

- **玩家走动**：固定箱子 $b$，玩家走到相邻的非墙、非箱子格 $p'$，代价 $0$，得到 $(b, p')$；
- **推动**：玩家 $p$ 的相邻格**正好是箱子** $b$，且箱子沿同方向的后一格 $b'$ 在界内且不是墙，代价 $1$，得到 $(b', b)$（玩家接管箱子原来的格子）。

于是问题变成一张**边权只有 $0$ 和 $1$** 的图上求最短路，答案只关心箱子是否到达 $T$：

$$\text{answer} = \min_{p}\ dist\big((T, p)\big)$$

0/1 权图用 **0-1 BFS**：双端队列中 $0$ 权边入队首、$1$ 权边入队尾，队列按距离非降排列，等价于 Dijkstra 但不需要堆。

### 3.3 算法流程

![0-1 BFS 主循环](images/wc163_q4_zerone_bfs_flow.svg)

1. 扫描网格定位 `'S'`、`'B'`、`'T'`，起点状态 `id = b0 * N + p0`（$N = mn$），`dist[id] = 0`，`push_front`。
2. 取队首状态，读出 `d0 = dist[cur]`，用 `b = cur / N`、`p = cur % N` 反解坐标。
3. 展开 $0$ 权边：四个方向尝试玩家移动，目标格须在界内、非墙、非箱子格；能松弛则更新后 `push_front`。
4. 展开 $1$ 权边：四个方向中若相邻格正是箱子，再检查箱子后一格；可走则用 `d0 + 1` 松弛状态 `(b', b)`，更新后 `push_back`。
5. 队列空后取 $\min_p dist[T \cdot N + p]$；若全为 $\infty$ 则返回 $-1$。

### 3.4 示例演算

![示例 3 的 5 次推动演算](images/wc163_q4_walkthrough.svg)

以示例 3 为例（箱子起点 $(2,3)$，目标 $(1,1)$），推与走交替如下：

| 推动次序 | 玩家先站到 | 方向 | 箱子到 | 推动后玩家在 |
|----------|------------|------|--------|--------------|
| 1 | $(1,3)$ | ↓ | $(3,3)$ | $(2,3)$ |
| 2 | $(3,4)$ | ← | $(3,2)$ | $(3,3)$ |
| 3 | $(3,3)$ | ← | $(3,1)$ | $(3,2)$ |
| 4 | $(4,1)$ | ↑ | $(2,1)$ | $(3,1)$ |
| 5 | $(3,1)$ | ↑ | $(1,1)$ | $(2,1)$ |

「玩家先站到」之间的移动全是 $0$ 权边：第 1 次绕 4 步、第 2 次绕 2 步、第 4 次绕 2 步，第 3、5 次玩家恰好已在位（0 步）。总动作数 $8 + 5 = 13$，但 $0$ 权边代价为 $0$，`dist[T]` 只累计出 $5$，正是答案。

## 4. 算法细节

1. **状态编码**：`id = b * N + p`，一维数组 `dist` 大小 $N^2 = (mn)^2 \le 160000$，比四维数组更省更快；出队时 `b = id / N`、`p = id % N` 反解。
2. **双端队列**：$0$ 权 `push_front`、$1$ 权 `push_back`，才能保证出队距离非降、每个状态只被处理一次；若 $0$ 权边也塞进队尾，正确性还能靠反复松弛兜住（类 SPFA），但复杂度没有保证。
3. **无需 `in_queue` 标记**：只在 `dist` **严格变小**时入队，出队时一律以当前 `dist[cur]` 为准扩展；即使出现重复条目也不影响结果，省掉标记既省时间也少一处出错点。
4. **$0$ 权扩展把箱子当墙**：判断条件是「非墙**且**不是箱子格」，漏掉后半句会让玩家瞬移到箱子另一侧，得到偏小的错误答案。
5. **$1$ 权扩展的判定顺序**：先确认「玩家相邻格正是箱子」，再单独检查「箱子后一格」是否越界或为墙；两个判断不能合并。
6. **玩家新位置**：推动后玩家一定落在**箱子推动前的格子**，不是玩家原来的位置；写错会让后续可达性判断全盘失真。
7. **终点收集**：只关心箱子，答案是 $\min_{0 \le p < N} dist[T \cdot N + p]$，遍历 $N \le 400$ 个玩家格即可。

## 5. 正确性证明

**引理 1（状态图忠实刻画游戏）**：真实游戏的任意时刻都可用状态 $(b, p)$ 表示；一次合法的玩家移动恰好对应一条 $0$ 权边，一次合法的推动恰好对应一条 $1$ 权边，反之每条边的终点都是可达的游戏局面。

**证明**：按定义核对。玩家移动的合法性要求目标格在界内、非墙、非箱子，这正是 $0$ 权边的条件；推动的合法性要求玩家与箱子相邻、箱子后方在界内且非墙，这正是 $1$ 权边的条件，且推动后玩家必然站在箱子原来的格子，与边终点一致，故两侧一一对应。∎

**引理 2（0-1 BFS 出队即最优）**：算法运行中双端队列内的 `dist` 单调不减，每次 `pop_front` 取出的状态，其 `dist` 已是最终最短距离。

**证明**：设当前出队距离为 $d$，由单调性队列内元素距离均 $\ge d$；任何尚未发现的更短路径，其最后一条边只能从距离 $d-1$（$1$ 权）或 $d$（$0$ 权）的状态出发，而这些状态都已扩展过（$0$ 权边插入队首保证同层先处理完），矛盾。归纳即得出队即最优，本质是 $0/1$ 权下的 Dijkstra。∎

**定理**：算法返回的值等于最小推动次数；若无法把箱子推到 `'T'`，返回 $-1$。

**证明**：任何可行方案都是玩家移动与推动的交替序列，由引理 1 对应为一条从起点到某个 $(T, p)$ 的路径，其 $1$ 权边数即推动次数；反之任一到达 $(T, \cdot)$ 的路径都给出可行方案，$1$ 权边数即推动次数。故「最小推动次数」等于「状态图中到集合 $\{(T, p)\}$ 的最少 $1$ 权边数」。由引理 2，0-1 BFS 给出精确最短路，对 $p$ 取最小即全局最优；若全部为 $\infty$，则不存在任何可行方案，返回 $-1$。∎

## 6. 复杂度分析

- **时间**：状态数 $N^2 = (mn)^2$，每个状态最多展开 $4$ 条 $0$ 权边与 $4$ 条 $1$ 权边，每条边 $O(1)$，总时间 $O\big((mn)^2\big)$；$mn \le 400$ 时约 $1.6 \times 10^5$ 个状态、$1.3 \times 10^6$ 次松弛。
- **空间**：`dist` 数组 $N^2$ 个 `int`（约 $640$ KB），队列最坏同时容纳 $O(N^2)$ 个状态，合计 $O\big((mn)^2\big)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <deque>
#include <algorithm>
#include <climits>
using namespace std;

class Solution {
public:
    int minPushBox(vector<vector<char>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int sr = 0, sc = 0, br = 0, bc = 0, tr = 0, tc = 0;
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 'S') { sr = i; sc = j; }
                else if (grid[i][j] == 'B') { br = i; bc = j; }
                else if (grid[i][j] == 'T') { tr = i; tc = j; }
            }

        int N = m * n;
        vector<int> dist(N * N, INT_MAX);
        deque<int> dq;
        int start = (br * n + bc) * N + (sr * n + sc);
        dist[start] = 0;
        dq.push_front(start);
        const int dr[4] = {-1, 1, 0, 0}, dc[4] = {0, 0, -1, 1};

        while (!dq.empty()) {
            int cur = dq.front(); dq.pop_front();
            int b = cur / N, p = cur % N;
            int bx = b / n, by = b % n, px = p / n, py = p % n;
            int d0 = dist[cur];
            for (int k = 0; k < 4; k++) {              // 玩家走动，代价 0
                int nx = px + dr[k], ny = py + dc[k];
                if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                if (grid[nx][ny] == '#' || (nx == bx && ny == by)) continue;
                int ns = b * N + (nx * n + ny);
                if (d0 < dist[ns]) { dist[ns] = d0; dq.push_front(ns); }
            }
            for (int k = 0; k < 4; k++) {              // 推箱子，代价 1
                int nx = px + dr[k], ny = py + dc[k];
                if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                if (nx != bx || ny != by) continue;    // 相邻格必须是箱子
                int nbx = bx + dr[k], nby = by + dc[k];
                if (nbx < 0 || nbx >= m || nby < 0 || nby >= n) continue;
                if (grid[nbx][nby] == '#') continue;   // 箱子后一格必须可走
                int ns = (nbx * n + nby) * N + b;      // 玩家接管箱子旧格
                if (d0 + 1 < dist[ns]) { dist[ns] = d0 + 1; dq.push_back(ns); }
            }
        }

        int ans = INT_MAX, target = tr * n + tc;
        for (int p = 0; p < N; p++) ans = min(ans, dist[target * N + p]);
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
from collections import deque
from typing import List


class Solution:
    def minPushBox(self, grid: List[List[str]]) -> int:
        m, n = len(grid), len(grid[0])
        for i in range(m):
            for j in range(n):
                if grid[i][j] == 'S': sr, sc = i, j
                elif grid[i][j] == 'B': br, bc = i, j
                elif grid[i][j] == 'T': tr, tc = i, j

        N = m * n
        INF = float('inf')
        dist = [INF] * (N * N)                     # dist[box * N + player]
        start = (br * n + bc) * N + (sr * n + sc)
        dist[start] = 0
        dq = deque([start])
        dirs = ((-1, 0), (1, 0), (0, -1), (0, 1))

        while dq:
            cur = dq.popleft()
            b, p = divmod(cur, N)
            bx, by = divmod(b, n)
            px, py = divmod(p, n)
            d0 = dist[cur]

            for dx, dy in dirs:                    # ① 玩家走动：0 权，入队首
                nx, ny = px + dx, py + dy
                if not (0 <= nx < m and 0 <= ny < n): continue
                if grid[nx][ny] == '#' or (nx == bx and ny == by): continue
                ns = b * N + (nx * n + ny)
                if d0 < dist[ns]:
                    dist[ns] = d0
                    dq.appendleft(ns)

            for dx, dy in dirs:                    # ② 推箱子：1 权，入队尾
                nx, ny = px + dx, py + dy
                if not (0 <= nx < m and 0 <= ny < n): continue
                if nx != bx or ny != by: continue   # 相邻格必须是箱子
                nbx, nby = bx + dx, by + dy
                if not (0 <= nbx < m and 0 <= nby < n): continue
                if grid[nbx][nby] == '#': continue  # 箱子后一格必须可走
                ns = (nbx * n + nby) * N + b        # 玩家接管箱子旧格
                if d0 + 1 < dist[ns]:
                    dist[ns] = d0 + 1
                    dq.append(ns)

        target = tr * n + tc
        ans = min(dist[target * N + p] for p in range(N))
        return -1 if ans == INF else ans
```

## 8. 边界情况与易错点

1. **玩家绕不到箱子背后**：示例 2 中箱子向左推得动，但要把它推上去就必须站到 $(3,1)$，而那一格是墙，于是无解；只判断箱子前方是否可走是典型错误。
2. **玩家被墙围死**：一条 $0$ 权边都出不去，箱子永远推不动，答案必须映射成 $-1$。
3. **一维走廊**（$m = 1$ 或 $n = 1$）：玩家无法绕过箱子，只能沿唯一方向连续推动，代码无需特判。
4. **状态漏掉玩家坐标**：只用箱子位置当状态，会让玩家「瞬移」到箱子任意一侧，答案偏小；玩家位置必须进状态。
5. **推动判定顺序颠倒**：先判方向上是箱子、再判箱子后方，两处都要查越界与 `'#'`，顺序反了会漏解或越界。
6. **玩家新位置写错**：推动后玩家落在箱子旧格，与「玩家原地不动」的结果相差一格，会让后续推箱全部错位。
7. **终点收集写窄**：答案要对所有玩家位置取 $\min$，只取箱子某个固定方位（如「玩家在箱子左侧」）会漏掉合法解。
