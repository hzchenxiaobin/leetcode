# LeetCode 在受污染的二叉树中查找元素 题解

## 1. 题目概述

- **标题 / 题号**：在受污染的二叉树中查找元素（#1261，medium）
- **链接**：https://leetcode.cn/problems/find-elements-in-a-contaminated-binary-tree/
- **来源**：LeetCode 第 163 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、设计、哈希表、二叉树

**题意**：原本有一棵值由结构决定的二叉树：根为 $0$，父节点值为 $x$ 时左孩子为 $2x+1$、右孩子为 $2x+2$。现在所有节点的值都被污染成 $-1$，但**树形完好**——哪些位置有节点、哪些位置是 `null` 都没有变。请先按规则还原每个节点的真实值，再实现 `FindElements` 类：`FindElements(TreeNode* root)` 完成还原，`bool find(int target)` 判断还原后的树里是否存在值为 $target$ 的节点。构造函数与 `find` 会被交替调用上万次，所以必须把还原结果**缓存**下来，而不是每次查询重算。

**约束**：

- 初始时所有节点的值都是 $-1$
- 树的高度不超过 $20$
- 节点数在 $[1, 10^4]$ 内
- `find()` 的总调用次数在 $[1, 10^4]$ 内
- $0 \le target \le 10^6$

## 2. 示例

**示例 1**

```text
输入：
["FindElements","find","find"]
[[[-1,null,-1]],[1],[2]]
输出：[null,false,true]
解释：根 0 只有右孩子，值为 2*0+2 = 2，还原后值集合为 {0,2}；
      故 find(1)=false，find(2)=true。
```

**示例 2**

```text
输入：
["FindElements","find","find","find"]
[[[-1,-1,-1,-1,-1]],[1],[3],[5]]
输出：[null,true,true,false]
解释：根 0 有左右孩子 1、2，根的左孩子又有 3、4，
      值集合为 {0,1,2,3,4}；故 1、3 存在，5 不存在。
```

**示例 3**

```text
输入：
["FindElements","find","find","find","find"]
[[[-1,null,-1,-1,null,-1]],[2],[3],[4],[5]]
输出：[null,true,false,false,true]
解释：层序数组为 [-1,null,-1,-1,null,-1]：根无左孩子，右孩子值 2；
      2 的左孩子值 5，5 的左孩子值 11，值集合为 {0,2,5,11}。
      故 find(2)=find(5)=true，find(3)=find(4)=false。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是「每次 `find` 都从根重新走一遍」：还原根为 $0$，递归下推，看能否碰到 `target`。单次查询 $O(n)$，而 $n$ 与 $q$ 都可以是 $10^4$，总操作量 $10^8$，在 Python 里必然超时；更差的写法是每次查询都把整棵树重新赋值一遍，多余开销更大。

暴力之所以浪费，是因为**值只与树形有关、与查询无关**：结构被污染后依然不变，于是还原结果在对象生命周期内是常量。正确做法是「构造时算一次、查询时只查表」。

### 3.2 核心观察：值由根到节点的路径唯一决定

![污染树的值编码：v 与 u=v+1](images/wc163_q2_recover_encoding.svg)

**观察一（值被路径锁定）**：从根出发，每走一步的规则是确定的（左 $2x+1$、右 $2x+2$），所以一个节点的值完全由「根到它的 01 路径」决定，与其它子树无关。被污染的只是数值，路径信息一个都没丢——只要遍历一遍结构，就能把全部值算回来。

**观察二（把加 1 提出来，规则变成纯粹移位）**：令 $u = v + 1$，则

$$v \to 2v+1 \iff u \to 2u, \qquad v \to 2v+2 \iff u \to 2u+1$$

也就是说：**左孩子给 $u$ 的二进制末尾补 $0$，右孩子补 $1$**，而根的 $u = 0 + 1 = 1$。于是节点值 $v$ 的编码就是「前导 $1$ + 根到该节点的 01 串」，二者互为唯一表示。深度为 $k$ 的节点值恰好落在 $[2^k-1,\ 2^{k+1}-2]$ 之内，值域随深度指数增长，同一层内不会重复。

**观察三（查询只需回答「在不在」）**：`find` 不关心位置，只关心值是否存在。既然一次 DFS 就能得到全部值，把它们塞进**哈希集合**，`find` 就退化成一次成员判断，期望 $O(1)$。这就是本题的最优结构：预处理 $O(n)$ + 每次查询 $O(1)$。

> 💡 观察二还有一处额外红利：判断 $target$ 是否存在可以完全不用哈希表——沿 `target+1` 的二进制位从根往下走（$0$ 走左、$1$ 走右），中途撞到 `null` 就返回 `false`。时间 $O(\log target)$、额外空间 $O(1)$，见 §4 第 7 条与延伸思考。

### 3.3 算法流程

![DFS 还原 + 哈希集合的流程图](images/wc163_q2_dfs_hashset_flow.svg)

1. 若 `root` 为空（约束保证非空，这里只做防御）直接返回，集合保持空；
2. 令 `root.val = 0`，用显式栈 `stack = [root]` 存放「值已确定、孩子还没处理」的节点；
3. 循环直到栈空：弹出 `cur`，把 `cur.val` 插入 `seen`；若 `cur.left` 非空，令其值为 $2\cdot cur.val+1$ 后压栈；若 `cur.right` 非空，令其值为 $2\cdot cur.val+2$ 后压栈；
4. 遍历结束时 `seen` 恰好等于还原后树的全部节点值；
5. `find(target)` 直接返回 `target ∈ seen`。

顺序上必须**先给子节点赋值、再压栈**（或者压栈时把值一起带上），因为节点没有父指针，弹出时才去算值就找不到父节点的值了。

### 3.4 示例演算

![示例 3 的结构与查询走查](images/wc163_q2_walkthrough.svg)

以示例 3 的层序数组 `[-1,null,-1,-1,null,-1]` 为例，先按层序还原结构：根只有右孩子；该右孩子有左孩子；这个左孩子又有左孩子。再按规则自上而下填值：

| 节点 | 从根走的路径 | 值 $v$ | $u = v+1$ |
|------|--------------|--------|-----------|
| 根 | 空 | 0 | 1 |
| 根的右孩子 | 右 | 2 | 11 |
| 右孩子的左孩子 | 右, 左 | 5 | 110 |
| 再往左的孩子 | 右, 左, 左 | 11 | 111 |

值集合 `seen = {0, 2, 5, 11}`。四个查询：

| target | $u = t+1$（二进制） | 路径（0 左 / 1 右） | 是否存在 |
|--------|-----------|--------------------|----------|
| 2 | 3 = 11 | 右 | ✓（值 2） |
| 3 | 4 = 100 | 左, 左 | ✗（根没有左孩子） |
| 4 | 5 = 101 | 左, 右 | ✗（根没有左孩子） |
| 5 | 6 = 110 | 右, 左 | ✓（值 5） |

与官方输出 `[null,true,false,false,true]` 完全一致。同样的流程作用在示例 1 上得到 $\{0,2\}$，作用在示例 2 的满两层树上得到 $\{0,1,2,3,4\}$。

## 4. 算法细节

1. **一次遍历必须走完整棵树**：不能只沿「可能的目标路径」下推——构造函数不知道将来会查询哪些值，所以只能老老实实 DFS（或 BFS）全部节点，每个节点算一次值、插一次集合。
2. **不能用层序数组的下标推值**：层序数组是带 `null` 空洞的紧凑表示，下标与二叉树编号（堆式编号）不是同一个东西。示例 3 中下标 5 的节点真实路径是「右、左、左」，值 $11$，而按下标硬推会得到完全错误的值。**结构只能由指针关系读出**。
3. **值域要算清楚**：高度不超过 $20$ 意味着最深节点的值不超过 $2^{21}-2 = 2097150$，`int` 足够，不需要 `long long`；`target` 上限 $10^6$ 只是查询范围，**不属于**还原范围——不要拿它去给还原过程剪枝，否则会漏掉深层的合法值。
4. **哈希集合的选型**：C++ 用 `unordered_set<int>`，节点数最多 $10^4$，可以 `reserve` 预留桶数以避开 rehash；Python 直接用 `set`，整数哈希均匀。
5. **迭代 DFS 优于递归**：高度只有 $20$，递归在 Python 里也不会爆栈，但迭代写法不依赖递归深度、更稳，且显式栈的峰值大小是 $O(h)$。
6. **入栈时机与判空**：只在孩子非空时给孩子赋值并压栈，避免把 `nullptr` 压栈后解引用；`find` 里也不需要对空集合做特判（空集合的成员判断天然返回 `false`）。
7. **无哈希表的替代写法**：`find(target)` 令 $u = target+1$，从根开始读 $u$ 的二进制（去掉最高位），遇 $0$ 走左、遇 $1$ 走右，中途为 `null` 即返回 `false`，否则返回 `true`。时间 $O(\log target) \le 21$，额外空间 $O(1)$；适合节点极多、内存受限的场景。

## 5. 正确性证明

**引理 1（还原的值唯一且正确）**：构造函数执行完后，每个节点 $x$ 的 `val` 等于「按 $v_{\text{root}}=0$、左 $2v+1$、右 $2v+2$ 递归定义」的真实值。

**证明**：对节点的深度 $d$ 归纳。$d=0$ 时根被显式赋值 $0$，成立。设深度 $< d$ 的节点都已正确赋值。取深度 $d$ 的节点 $x$，其父 $p$ 深度为 $d-1$，由归纳假设 $p$ 的值正确；$p$ 被弹出时若 $x$ 是左孩子则赋值 $2\cdot p.\text{val}+1$，若是右孩子则赋值 $2\cdot p.\text{val}+2$，正是真实值。归纳完成。∎

**引理 2（编码是双射）**：设节点值为 $v$、$u=v+1$，则根到该节点的路径去掉「起点」后，恰是 $u$ 的二进制去掉最高位 $1$ 所得的 01 串（$0$ 表示走左、$1$ 表示走右）；反之，任一 01 串唯一确定一个值。

**证明**：由引理 1 的值规则直接推得 $u_{\text{child}} \in \{2u,\ 2u+1\}$：左孩子 $u' = (2v+1)+1 = 2(v+1) = 2u$，右孩子 $u' = (2v+2)+1 = 2u+1$。而 $2u$ 与 $2u+1$ 在二进制上分别是「$u$ 左移补 $0$」与「$u$ 左移补 $1$」。从 $u_{\text{root}} = 1$ 出发，长度 $k$ 的路径恰好在其后追加 $k$ 位，得到唯一一个 $k$ 位后缀；二进制表示唯一，故路径与值一一对应。∎

**引理 3（集合完整）**：DFS 结束后 `seen` 恰好等于还原树的全部节点值集合，既无遗漏也无多余。

**证明**：（$\subseteq$）每次插入的 `cur.val` 都是某个真实节点的值，故 `seen` 不含多余元素。（$\supseteq$）任意节点都会且只会被压栈一次：根在初始化时入栈，其余节点在其父节点被弹出时入栈，而父节点本身在栈中等待弹出，深搜必然弹完整个栈；因此每个节点都被弹出并插入一次。∎

**定理**：`find(target)` 返回 `true` 当且仅当还原后的树中存在值为 $target$ 的节点。

**证明**：`find` 返回 `target ∈ seen`。若返回 `true`，由引理 3 的（$\subseteq$）方向，存在真实节点其值等于 $target$；若返回 `false`，由引理 3 的（$\supseteq$）方向，不存在这样的节点。两个方向合起来即所求。∎

## 6. 复杂度分析

- **时间**：构造 $O(n)$——每个节点恰好被压栈、弹栈、插入集合各一次，哈希插入期望 $O(1)$；单次 `find` 期望 $O(1)$，$q$ 次共 $O(q)$。总计 $O(n+q)$，其中 $n \le 10^4$、$q \le 10^4$，总操作量在 $2\times10^4$ 量级。
- **空间**：`seen` 存 $n$ 个整数，$O(n)$；显式栈在 DFS 中峰值不超过 $O(h)$，$h \le 20$，可视为 $O(1)$ 级常数；加上还原过程中未额外分配节点，总额外空间 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
using namespace std;

// TreeNode 的定义由评测系统给出
class FindElements {
private:
    unordered_set<int> seen;

public:
    FindElements(TreeNode* root) {
        if (root == nullptr) return;
        root->val = 0;
        vector<TreeNode*> st;
        st.push_back(root);
        while (!st.empty()) {
            TreeNode* cur = st.back();
            st.pop_back();
            seen.insert(cur->val);            // 值已确定，直接入集合
            if (cur->left != nullptr) {
                cur->left->val = 2 * cur->val + 1;
                st.push_back(cur->left);
            }
            if (cur->right != nullptr) {
                cur->right->val = 2 * cur->val + 2;
                st.push_back(cur->right);
            }
        }
    }

    bool find(int target) {
        return seen.count(target) > 0;
    }
};
```

### Python

```python
from typing import Optional


class FindElements:
    def __init__(self, root: Optional[TreeNode]):
        self.seen = set()
        if root is None:                 # 防御性判空，约束保证非空
            return
        root.val = 0
        stack = [root]
        while stack:
            node = stack.pop()
            self.seen.add(node.val)      # 值已确定，直接入集合
            if node.left is not None:
                node.left.val = 2 * node.val + 1
                stack.append(node.left)
            if node.right is not None:
                node.right.val = 2 * node.val + 2
                stack.append(node.right)

    def find(self, target: int) -> bool:
        return target in self.seen
```

## 8. 边界情况与易错点

1. **单节点树 `[-1]`**：还原后值集合是 $\{0\}$，所以 `find(0)` 恒为 `true`，`find(1)` 等一律 `false`。根一定存在，不要对 $target=0$ 写额外的「特判存在」逻辑，集合已经覆盖。
2. **只有右孩子（示例 1）**：右孩子是 $2x+2$ 而不是 $2x+1$，这两个公式写反是本场最常见的错，示例 1 与示例 3 都能稳定暴露它。
3. **层序数组里的 `null` 是位置空缺**：不能把 `null` 当成「值为空但节点存在」。示例 3 中下标 2 是根的右孩子、下标 3 是它左孩子，跳过 `null` 的方式一旦写错（例如把 `null` 也占一个孩子槽位反过来算），整棵树的形状都会错。
4. **值可以超过 $10^6$**：`target` 上限只是查询范围。高度 $20$ 的链式树最深值约 $2\times10^6$，若用 `target` 上限给 DFS 剪枝，会漏掉这些节点的值（虽然它们查询不到，但对「集合是否完整」的正确性理解是错的）。
5. **累加过程不会溢出**：最大 $2097150 < 2^{31}-1$，`int` 安全；但如果把高度误读成「节点数 $\le 20$」而随手写 `1 << 30` 之类常量，就会在 $h=20$ 时出问题。
6. **构造与查询的调用次序**：`FindElements` 只被构造一次，`find` 会被调用多次，二者交替出现。把集合放在成员里、构造后不再修改，是这道设计题的关键；若把集合写成局部变量，查询时就是空集合。
7. **递归版在 Python 中的深度**：高度 $\le 20$ 时递归绝对安全（远小于默认 $1000$ 的递归上限），但判空仍要放在递归入口，否则 `None.val` 会抛异常。

**延伸思考**：（1）引理 2 给出的「按位下行」可以不建任何集合，直接回答查询，代码只有六七行：

```python
def find(self, target: int) -> bool:
    node, u = self.root, target + 1
    for bit in bin(u)[3:]:            # 去掉前缀 "0b1"
        node = node.left if bit == '0' else node.right
        if node is None:
            return False
    return True
```

它把空间从 $O(n)$ 降到 $O(1)$、把单次查询从 $O(1)$ 变成 $O(\log target)$，是「时间换空间」的另一个端点；由于 $target \le 10^6$，路径长度不超过 $20$，实际差距极小。

（3）本题只要求判定存在性。若要返回**节点本身**或**路径**，哈希表就得从 `set` 换成 `map<值, 节点指针>`，构造开销不变；而按位下行法可以天然地边下边收集路径，这是它比哈希方案更强的地方。
