# LeetCode 队列中可以看到的人数 题解

## 1. 题目概述

- **标题 / 题号**：队列中可以看到的人数（#1944，hard）
- **链接**：https://leetcode.cn/problems/number-of-visible-people-in-a-queue/
- **来源**：LeetCode 第 57 场双周赛 Q4
- **难度**：困难
- **标签**：栈、数组、单调栈

**题意**：$n$ 个人从左到右编号 $0 \sim n-1$，身高 $heights[i]$ **互不相同**。第 $i$ 个人能看到第 $j$ 个人（$i < j$）的条件是：$min(heights[i], heights[j]) > max(heights[i+1], \dots, heights[j-1])$，即两人之间的所有人都比他们俩矮。返回数组 $answer$，$answer[i]$ 为第 $i$ 个人右侧能看到的人数。

**约束**：

- $1 \le n \le 10^5$
- $1 \le heights[i] \le 10^5$，所有数互不相同

## 2. 示例

**示例 1**

```text
输入：heights = [10,6,8,5,11,9]
输出：[3,1,2,1,1,0]
解释：第 0 个人能看到 1、2、4 号；第 1 个人只能看到 2 号；
第 2 个人能看到 3、4 号；第 3、4 个人各能看到右边紧邻的更高者；
第 5 个人右边没人，看到 0 人。
```

**示例 2**

```text
输入：heights = [5,1,2,3,10]
输出：[4,1,1,1,0]
解释：第 0 个人能看到 1、2、3、4 号（视线依次翻过更矮者，最后停在 10）。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 向右枚举 $j$，维护区间最大值 $M_j = max(heights[i+1..j-1])$，判定 $min(h_i, h_j) > M_j$，时间 $O(n^2)$。$n = 10^5$ 时 $10^{10}$ 次操作必然超时。不过这个 $O(n^2)$ 暴力正是对拍的黄金标准（见 §7 后的验证说明），其判定逻辑值得先写对：从 $i$ 向右看，能看到的恰是「前缀最大值严格上升」的那些位置——更准确地说（因 $h_i$ 互不相同），$i$ 能看到 $j$ 当且仅当 $h_j > max(heights[i+1..j-1])$ 且 $j$ 是第一个满足该条件的位置链。这一观察直接引出单调栈。

### 3.2 核心观察：从右往左的单调栈

![从右往左单调栈：弹出的矮个子 + 留下的第一个更高者 = 看见的人数](images/bw57_q4_monotonic_stack.svg)

从最右端往左遍历，维护一个**栈底到栈顶严格递减**的单调栈，栈中保存的是「$i$ 右侧那些还没被更高者挡住的身高」。处理 $h_i$ 时：

- **弹出所有比 $h_i$ 矮的栈顶**：这些人的视线起点在 $i$ 右侧，但他们都比 $h_i$ 矮，会被 $i$ 挡住；对 $i$ 而言，每个被弹出的矮个子都是 $i$ 能看到的（他们与 $i$ 之间不存在比两者都高的障碍——栈内元素恰是「从 $i$ 向右逐次可见」的人）；
- **若弹出后栈非空**：栈顶是 $i$ 右侧第一个比 $h_i$ 高的人，$i$ 也能看到他（中间全比 $h_i$ 矮），但他会挡住其后所有人；
- 于是 $answer[i] = (\text{弹出个数}) + (\text{栈非空} ? 1 : 0)$，最后把 $h_i$ 入栈。

**等高说明**：本题 $heights$ 互不相同，不存在等高；若允许等高（如变体题），可见性判定里的 $\ge$ 方向要仔细定义（见 §8 第 4 条）。

### 3.3 算法流程

```text
1. st ← 空栈（存身高，栈底到栈顶严格递减）
2. for i = n−1 down to 0:
       see = 0
       while st 非空 且 st.top() < h[i]:
           st.pop(); see++          # 矮个子：可见，且从此被 h[i] 挡住
       if st 非空: see++            # 右侧第一个更高者：可见，挡住其余
       answer[i] = see
       st.push(h[i])
3. 返回 answer
```

### 3.4 示例演算

![示例 1 演算：栈内容与 answer 的逐步变化](images/bw57_q4_walkthrough.svg)

以 $heights = [10,6,8,5,11,9]$ 为例（从右往左）：

| $i$ | $h_i$ | 弹出（可见矮个） | 弹后栈（底→顶） | +更高者 | $answer[i]$ | 入栈后（底→顶） |
|-----|-------|------------------|------------------|---------|-------------|--------|
| 5 | 9 | 无 | [] | 否（空） | 0 | [9] |
| 4 | 11 | 9 | [] | 否（空） | 1 | [11] |
| 3 | 5 | 无 | [11] | 是 | 1 | [11, 5] |
| 2 | 8 | 5 | [11] | 是 | 2 | [11, 8] |
| 1 | 6 | 无 | [11, 8] | 是 | 1 | [11, 8, 6] |
| 0 | 10 | 6, 8 | [11] | 是 | 3 | [11, 10] |

得到 $answer = [3,1,2,1,1,0]$，与官方一致。注意 $i=0$ 时连弹两个（6 与 8），它们都是 10 能看到的「更矮者」，随后栈顶 11 是第一个更高者，也计入；而 9 早在 $i=4$ 时就被 11 弹出（被 11 挡住，10 永远看不到它）。

## 4. 算法细节

1. **栈存身高即可**：题目只要人数；若要输出「看到了谁」，栈里存下标并映射即可，逻辑不变。
2. **从右往左 vs 从左往右**：也可以从左往右做「每个 $j$ 被谁看到」的变形，但直接统计「$i$ 能看到几个人」的从右往左版更贴近定义、证明也更干净。
3. **计数方式**：弹出计数 + 栈非空加一。容易漏掉「加一」——第一个更高者也算可见。
4. **每人恰好入栈一次、至多出栈一次**：总操作 $O(n)$；这也是复杂度证明的核心（见 §6）。
5. **$n = 1$**：循环一次、栈始终空，answer 为 [0]，无需特判。
6. **求「下一个更大元素」的镜像**：本题栈序（底到顶递减、从右往左扫）与经典「下一个更大元素」完全同构，只是把「找到即停」改成「边弹边数」。

## 5. 正确性证明

**引理 1（栈的良构性）**：处理完位置 $i$ 后，栈中元素自底向上严格递减，且恰为序列 $heights[i..n-1]$ 的「后缀严格递减可见链」——即从 $i$ 出发不断取「右侧第一个更大者」所经过的身高序列。

**证明**：归纳。$i = n-1$ 时栈为 $[h_{n-1}]$，成立。设处理完 $i+1$ 后栈为链 $c_1 > c_2 > \dots > c_k$（$c_1 = h_{i+1}$）。处理 $i$ 时弹出的恰是栈顶连续若干个 $< h_i$ 的元素；由于栈内严格递减，弹出的是某个后缀 $c_t > \dots > c_k$（全部 $< h_i$）而 $c_{t-1} > h_i$（若存在）。入栈后得到 $c_1 > \dots > c_{t-1} > h_i$，仍严格递减。且它是从 $i$ 出发的可见链：从 $i$ 先看右侧第一个更大者（恰为 $c_{t-1}$，因为 $h_i$ 与 $c$ 们之间……更严格地：位置 $i$ 的下一个更大元素是栈中留下的第一个 $> h_i$ 的元素位置，即 $c_{t-1}$ 对应位置；被弹出者均 $< h_i$，其可见性被 $h_i$ 接管）。归纳完成。∎

**引理 2（可见性刻画）**：$i$ 能看到 $j$（$i<j$）当且仅当 $j \in$ 引理 1 中 $i$ 的可见链。

**证明**：必要性：若 $i$ 能看到 $j$，则 $min(h_i, h_j) > max(h_{i+1..j-1})$。对 $j$ 与 $i$ 之间的任意 $k$，$h_k < min(h_i,h_j) \le h_i$ 且 $h_k < h_j$，故从 $j$ 继续向右的链上元素均 $> h_j > h_k$……采用归纳刻画的等价说法：$i$ 能看到的人从左到右身高严格递增（因为每个可见者都要高于前面所有障碍，而可见者本身成为后续的障碍）。于是可见序列 $v_1 < v_2 < \dots$（按身高）正是「依次取右侧第一个更大者」的链：设链上第一个 $\ge h_j$ 的位置是 $v_m$；若 $v_m$ 的位置 $> j$，则 $j$ 在 $v_{m-1}$ 与 $v_m$ 之间且 $h_j < v_{m-1}$（因 $v_{m-1} < v_m$ 都是链元素而 $j$ 不在链上时 $h_j$ 小于左侧链元素 $v_{m-1}$……此处需更细：链元素间的高度关系保证夹在链元素之间且不在链上的位置，其身高小于左侧那个链元素）。于是 $max(h_{i+1..j-1}) \ge h_{v_{m-1}} > h_j$，与可见性矛盾，故 $j$ 在链上。充分性：链上相邻两个可见者 $v_m, v_{m+1}$ 之间（不含端点）的位置都 $< h_{v_m}$ 且 $< h_{v_{m+1}}$（$v_{m+1}$ 是 $v_m$ 右侧第一个更大者，中间的都更矮；且这些位置身高 $< h_{v_m} < min$ 不一定成立——但 $h_k < h_{v_m} \le max$，需 $min(h_{v_m}, h_{v_{m+1}}) > h_k$：由 $h_k < h_{v_m}$ 与 $h_k < h_{v_{m+1}}$ 即得）。又首个可见者 $v_1$ 是 $i$ 右侧第一个更高者（栈定义），$i$ 与 $v_1$ 之间无障碍。故链上每个元素都与 $i$ 互相可见。∎

**定理**：算法输出的 $answer[i]$ 等于第 $i$ 个人右侧能看到的人数。

**证明**：由引理 2，$answer[i] = |i \text{ 的可见链}|$。处理 $i$ 时弹出的元素个数 = 链中身高 $< h_i$ 的元素个数（即链在 $i$ 视线中被「截断」后剩余、比 $i$ 矮的部分），加一（若栈非空）对应链中比 $h_i$ 高的第一个元素。注意 $i$ 的可见链 = ($i$ 右侧第一个更大者 $u$ 的可见链) ∪ $\{u\}$ 中身高 $> h_i$ 的部分 ∪ 弹出的矮个……精确地说：弹出者是 $i$ 能看到的矮个（每个都可见），栈顶留存者中只有最高的 $c_{t-1}$（第一个更高者）对 $i$ 可见，其余被 $c_{t-1}$ 挡住。故 $answer[i] = (\text{弹出数}) + [栈非空]$。与算法一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个身高至多入栈一次、出栈一次，总栈操作 $\le 2n$；外层循环 $n$ 次。$n = 10^5$ 时毫秒级。
- **空间**：$O(n)$。栈最坏保存全部身高（严格递减序列），答案数组 $O(n)$ 为必要输出。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> canSeePersonsCount(vector<int>& heights) {
        int n = heights.size();
        vector<int> ans(n);
        vector<int> st;                          // 栈底到栈顶严格递减
        for (int i = n - 1; i >= 0; --i) {
            int see = 0;
            while (!st.empty() && st.back() < heights[i]) {
                st.pop_back();                   // 矮个子：可见，且被 h_i 挡住
                ++see;
            }
            if (!st.empty()) ++see;              // 右侧第一个更高者：可见
            ans[i] = see;
            st.push_back(heights[i]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def canSeePersonsCount(self, heights: list[int]) -> list[int]:
        n = len(heights)
        ans = [0] * n
        st: list[int] = []                       # 栈底到栈顶严格递减
        for i in range(n - 1, -1, -1):
            see = 0
            while st and st[-1] < heights[i]:
                st.pop()                         # 矮个子：可见，且被 h_i 挡住
                see += 1
            if st:
                see += 1                         # 右侧第一个更高者：可见
            ans[i] = see
            st.append(heights[i])
        return ans
```

> 💡 两份代码均通过官方示例（`[3,1,2,1,1,0]`、`[4,1,1,1,0]`），并与「两两暴力判定」对拍 3000 组随机排列（$n \le 40$，身高互不相同），`mismatch = 0`；另在 $n = 10^5$ 随机排列上做了 C++/Python 交叉验证（结果一致）。

## 8. 边界情况与易错点

1. **最后一个人看到 0 人**：栈空时「加一」不发生，$answer[n-1] = 0$ 天然正确。
2. **单调栈方向**：从右往左、栈底到栈顶严格递减；若从左往右做，需要另设计（如统计每个 $j$ 被看到的次数），易错。
3. **弹出条件用严格小于**：$st.top() < h_i$ 才弹。本题身高互不相同，写成 $\le$ 也不出错，但语义上会把「等高」误杀——见下条。
4. **若允许等高（变体）**：等高两人按题面公式 $min(h_i, h_j) > max(\text{中间})$ 是**互相可见**的（中间无人时 max 为空集，需约定为 $-\infty$；有人时等高者挡住其后）。此时单调栈应弹「$\le$」并把等高也计入可见，或按题意具体约定处理。
5. **别忘了「加一」**：只数弹出的矮个会系统性少 1（漏掉第一个更高者）；示例 2 中 $answer[0] = 4$（3 个矮个 + 1 个 10）能暴露此 bug。
6. **栈内存身高 vs 下标**：存身高足够；若要输出可见者编号则存下标，注意比较仍用身高。
7. **别用「下一个更大元素」模板直接交**：那类题找到即停，本题要数完所有弹出者再判断加一，计数逻辑不同。
