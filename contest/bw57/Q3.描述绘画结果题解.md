# LeetCode 描述绘画结果 题解

## 1. 题目概述

- **标题 / 题号**：描述绘画结果（#1943，medium）
- **链接**：https://leetcode.cn/problems/describe-the-painting/
- **来源**：LeetCode 第 57 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、前缀和、排序、扫描线

**题意**：数轴上的一幅画由若干带颜色的线段组成，`segments[i] = [start_i, end_i, color_i]` 表示半开区间 $[start_i, end_i)$ 涂有颜色 $color_i$，**每种颜色互不相同**。重叠部分的颜色混合，混合色用「集合中所有颜色之和」表示。要求用**最少数目**的不重叠半开区间 $[left_j, right_j)$ 表示整幅画，每个区间内混色之和恒定，返回 $painting[j] = [left_j, right_j, mix_j]$。未涂色部分不出现在结果中，答案顺序任意。

**约束**：

- $1 \le segments.length \le 2 \times 10^4$
- $1 \le start_i < end_i \le 10^5$
- $1 \le color_i \le 10^9$，且每种颜色互不相同

## 2. 示例

**示例 1**

```text
输入：segments = [[1,4,5],[4,7,7],[1,7,9]]
输出：[[1,4,14],[4,7,16]]
解释：[1,4) 由 {5,9} 混合（和 14），[4,7) 由 {7,9} 混合（和 16）。
```

**示例 2**

```text
输入：segments = [[1,7,9],[6,8,15],[8,10,7]]
输出：[[1,6,9],[6,7,24],[7,8,15],[8,10,7]]
解释：[1,6) 只有颜色 9；[6,7) 是 {9,15} 和 24；
[7,8) 只剩 15；[8,10) 是 7。注意 7 和 8 是两处断点。
```

**示例 3（边界补充）**

```text
输入：segments = [[1,4,5],[1,4,7],[4,7,1],[4,7,11]]
输出：[[1,4,12],[4,7,12]]
解释：[1,4) 是 {5,7}=12，[4,7) 是 {1,11}=12。两段 mix 值相同，
但颜色集合不同，必须输出两段——净变化为 0 的端点也要断开！
```

## 3. 解题思路

### 3.1 暴力思路

对每个单位位置 $p$（$1 \le p \le 10^5$）求出覆盖它的线段集合，直接求和并记录集合内容，然后把相邻且集合相等的单位段合并：时间 $O(n \cdot T)$（$n = 2\times10^4$ 条线段、$T = 10^5$ 个位置）约 $2 \times 10^9$，超时。若用 `map<int, set<int>>` 记录每位置的活跃集合再判等合并，空间同样爆炸。瓶颈在于「每个位置的混色」被独立计算，而**混色只在线段端点处发生变化**。

### 3.2 核心观察：混色之和只在端点处变化 → 差分 + 扫描线

![差分扫描线：+c 与 −c 只落在端点，净和零变化处也要断段](images/bw57_q3_diff_sweep.svg)

设 $mix(p)$ 为位置 $p$ 处的混色之和。一条线段 $[s, e)$ 的颜色 $c$ 使 $mix(p)$ 在 $p \in [s, e)$ 上增加 $c$——这是标准的**区间加**，用差分数组：$diff[s] \mathrel{+}= c$，$diff[e] \mathrel{-}= c$。扫过位置轴做前缀和即得每个位置的 $mix(p)$。

但输出要求「最少数目的区间表示」且**两段混色集合不同就不能合并**。关键点有二：

- **断点只可能出现在线段端点处**：非端点位置的左右邻点覆盖集合完全相同，不可能断开；
- **净变化为 0 的端点也必须断开**：示例 3 中位置 4 处 $+1+11-5-7 = 0$，$mix$ 前后都是 12，但覆盖集合从 $\{5,7\}$ 换成了 $\{1,11\}$——题目以「颜色集合」定义段的划分，而非以和值。故只要**有任一端点落在位置 $p$**（无论 $diff[p]$ 是否为 0），$p$ 就是一个潜在断点。

于是做法是：对每个坐标 $p$，用 `touch[p]` 标记「是否有端点落在 $p$」，在端点位置间做段切分；对每段 $[p_i, p_{i+1})$ 输出当前前缀和（混色值），**跳过和为 0 的段**（未涂色区域不输出）。

### 3.3 算法流程

```text
1. mx = max(所有 end)
2. diff[0..mx] 清零，touch[0..mx] 清零
3. 对每条 [s, e, c]：diff[s] += c；diff[e] -= c；touch[s] = touch[e] = 1
4. cur = 0, last = -1
5. 对 p = 0..mx：
       若 touch[p]：
           若 last >= 0 且 cur != 0：输出段 [last, p, cur]
           last = p
       cur += diff[p]
6. 返回所有输出段（天然升序）
```

注意「先输出后累加」的顺序：处理到端点 $p$ 时，$cur$ 累加了 $diff[0..p-1]$，恰是区间 $[last, p)$ 上的和——这正是待输出段的混色值；随后 `cur += diff[p]` 才让 $p$ 之后的新段生效。

### 3.4 示例演算

![示例 2 的差分表与段切分演算](images/bw57_q3_walkthrough.svg)

以示例 2（$segments = [[1,7,9],[6,8,15],[8,10,7]]$）为例：

| 位置 $p$ | touch | diff 事件 | 进入 $p$ 前的 $cur$（即 $[last, p)$ 的 mix） | 输出 |
|------|-------|-----------|--------------------------|------|
| 1 | ✓ | $+9$ | 0 | （和为 0，跳过 $[0,1)$） |
| 6 | ✓ | $+15$ | 9 | $[1,6,9]$ |
| 7 | ✓ | $-9$ | 24 | $[6,7,24]$ |
| 8 | ✓ | $-15,+7$ | 15 | $[7,8,15]$ |
| 10 | ✓ | $-7$ | 7 | $[8,10,7]$ |

与官方输出完全一致。

## 4. 算法细节

1. **必须用 long long**：$2\times 10^4$ 条线段、颜色上限 $10^9$，极端混色之和 $\approx 2\times 10^{13}$，远超 32 位整型。实测构造数据中最大 mix 达 $3.7\times 10^{12}$。C++ 用 `long long`，Python 天然大整数无虞。
2. **touch 数组不可省**：只看 $diff[p] \ne 0$ 会漏掉「净变化为 0」的端点（示例 3 的位置 4），导致把两段颜色不同但和值相同的段错误合并。
3. **「先判段、后累加」的顺序**：`cur` 在到达端点 $p$ 时保存的是 $[last, p)$ 的和。若先 `cur += diff[p]` 再输出，会把 $p$ 处的变化提前混入左侧段。
4. **和为 0 的段要跳过**：`cur == 0` 表示未涂色，题目要求不出现在结果中；注意 $mix$ 不可能为负（颜色全正、差分前缀和即覆盖和）。
5. **数组大小开到 $\max end$**：右端点本身是最后一个 touch 位置，扫描到 $mx$ 才能闭合最后一段；开 $\max end + 1$ 长度防越界。
6. **颜色互不相同**是「集合判等 → 和判等」合法性的前提：若颜色可重，两个不同集合可能凑出相同和（如 $\{5\}$ 与 $\{2,3\}$），此时必须改用 `map<位置, multiset>` 级别的真集合差分。本题约束保证了和的差分足够。
7. **返回前不必排序**：扫描天然按 left 升序产出；题目允许任意顺序。

## 5. 正确性证明

**引理 1（端点不变性）**：设 $P$ 为所有线段端点的集合。对任意开区间 $(p, p+1)$，若 $p, p+1 \notin P$，则覆盖 $(p, p+1)$ 的线段集合与覆盖任一 $q \in (p, p+1)$ 的集合相同。

**证明**：线段 $[s, e)$ 覆盖位置 $q \iff s \le q < e$。若 $s, e$ 都不落在 $(p, p+1)$ 的边界 $\{p, p+1\}$ 上，则 $[s, e)$ 要么覆盖整个 $(p, p+1)$，要么不覆盖其中任何点；而覆盖性发生改变的惟一位置是 $s$（从不含到含）与 $e$（从含到不含），故只要边界不在 $P$ 内，覆盖集合在 $(p, p+1)$ 内恒定。∎

**引理 2（差分正确性）**：扫描中到达端点 $p$ 之前的 $cur$ 值等于 $\sum_{c \text{ 覆盖 } [last, p)} c$，即该段的混色之和。

**证明**：$cur$ 是 $diff[0..p-1]$ 的前缀和。每条线段 $[s, e)$ 在 $diff[s]$ 与 $diff[e]$ 处贡献 $+c$ 与 $-c$，故其贡献被计入前缀和当且仅当 $s < p \le e$ 不成立且 $s \le q < e$ 形式化后恰为 $s \le last$ 且 $e \ge p$，即线段完整覆盖 $[last, p)$。因此 $cur$ 恰为覆盖 $[last, p)$ 的全部颜色之和。∎

**定理（最优分段数）**：设 $P = \{p_1 < p_2 < \dots < p_m\}$ 为所有端点。最优（最少段数）的合法表示恰为「相邻端点间为一个候选段，再剔除未涂色段」。

**证明**：由引理 1，任何候选断点必须在 $P$ 内——否则断点两侧的覆盖集合相同，把两段合并仍合法且段数更少，与最优性矛盾。故最优表示的段边界集合 $B$ 满足 $\{0\} \cup \{T_{\max}$ 之外$\}$ …，即每个断点 $\in P$。反过来，相邻端点之间的覆盖集合**必然变化**：位置 $p_{i+1}$ 是某线段的 $s$ 或 $e$，该线段覆盖 $p_{i+1}$ 与否和覆盖 $p_{i+1}-1$ 不同（半开区间：$s = p_{i+1}$ 者开始覆盖，$e = p_{i+1}$ 者停止覆盖），故 $[p_i, p_{i+1})$ 与 $[p_{i+1}, p_{i+2})$ 的覆盖集合必不同，不可再合并。最后，未涂色段（覆盖集合为空、和为 0）按题意不输出，从候选段中剔除后剩余段即最优表示。∎

**推论**：算法输出即为最优表示：扫描按 $p_1 < \dots < p_m$ 顺序切分（每步输出 $[last, p)$），且仅当 $cur \ne 0$ 输出，与定理描述的表示一致。∎

## 6. 复杂度分析

- **时间**：$O(n + T)$，$T = \max end \le 10^5$。建差分 $O(n)$，扫描 $O(T)$；与线段条数无关的坐标轴扫描是主要开销，总量 $\approx 1.2 \times 10^5$，毫秒级。实测 $n = 2\times 10^4$ 随机数据 C++ 0.06s、Python 0.14s。
- **空间**：$O(T)$。差分数组与 touch 数组各 $O(T)$；输出至多 $2n$ 段。
  若坐标范围极大（如 $10^{18}$）则需改用排序端点 + map 差分，复杂度 $O(n \log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<long long>> splitPainting(vector<vector<int>>& segments) {
        int mx = 0;
        for (auto& s : segments) mx = max(mx, s[1]);
        vector<long long> diff(mx + 1, 0);
        vector<char> touch(mx + 1, 0);
        for (auto& s : segments) {
            diff[s[0]] += s[2];
            diff[s[1]] -= s[2];
            touch[s[0]] = 1;
            touch[s[1]] = 1;              // 净变化为 0 的端点也要断段
        }
        vector<vector<long long>> ans;
        long long cur = 0;
        int last = -1;
        for (int p = 0; p <= mx; ++p) {
            if (touch[p]) {
                if (last >= 0 && cur != 0)
                    ans.push_back({(long long)last, (long long)p, cur});
                last = p;
            }
            cur += diff[p];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def splitPainting(self, segments: list[list[int]]) -> list[list[int]]:
        mx = max(s[1] for s in segments)
        diff = [0] * (mx + 1)
        touch = [0] * (mx + 1)
        for s, e, c in segments:
            diff[s] += c
            diff[e] -= c
            touch[s] = 1
            touch[e] = 1                  # 净变化为 0 的端点也要断段
        ans = []
        cur = 0
        last = -1
        for p in range(mx + 1):
            if touch[p]:
                if last >= 0 and cur != 0:
                    ans.append([last, p, cur])
                last = p
            cur += diff[p]
        return ans
```

> 💡 两份代码均通过全部官方示例（含「净变化为 0 也断段」的示例 3），并在 $n = 2\times10^4$、$T = 10^5$、$color \le 10^9$ 的随机数据上做了 C++/Python 交叉验证（输出逐段一致，最大 mix $3.7\times 10^{12}$，实证 `long long` 必要）。

## 8. 边界情况与易错点

1. **long long / 大整数**：混色之和上界 $2\times10^4 \times 10^9 = 2\times10^{13}$，`int` 必溢出；C++ 差分数组与返回值都必须 `long long`。返回类型是 `vector<vector<long long>>`。
2. **漏掉零净变化的断点**：示例 3 是官方特设陷阱——位置 4 处 $+1+11-5-7=0$，若只按 $diff[p] \ne 0$ 断段会把两段错误合并。`touch` 标记不可省。
3. **输出未涂色段**：$cur = 0$ 的段（如示例 2 的 $[0,1)$）不能输出；但也别把「和为 0」与「没有 touch」混淆——前者是真空隙，后者根本不是断点。
4. **扫描终点**：必须扫到 $\max end$，否则最后一段（右端点为 $\max end$ 的段）无法闭合。数组开 $\max end + 1$。
5. **先判段后累加**：处理端点 $p$ 时先输出 $[last, p)$（用旧 $cur$），再 `cur += diff[p]`。顺序颠倒会把 $p$ 处的变化量错误计入左段。
6. **颜色互不相同的保证**：这正是「用和代表集合」合法的原因；若颜色可重，需换成真集合差分（见延伸思考）。
7. **别用 map 存每个位置的活跃集合**：$T \times n$ 的空间与时间都会爆炸；差分是本题的正解。
