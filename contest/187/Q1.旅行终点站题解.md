# LeetCode 旅行终点站 题解

## 1. 题目概述

- **标题 / 题号**：旅行终点站（#1436，easy）
- **链接**：https://leetcode.cn/problems/destination-city/
- **来源**：LeetCode 第 187 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：给定数组 `paths`，`paths[i] = [cityAi, cityBi]` 表示有一条从 `cityAi` 直达 `cityBi` 的线路。所有线路首尾相接、不含环，恰好存在一个**终点站**——它没有任何通往其它城市的出边。返回这个终点站的城市名。

**约束**：

- $1 \le \text{paths.length} \le 100$
- $\text{paths}[i]\text{.length} = 2$，且 $\text{cityA}_i \ne \text{cityB}_i$
- $1 \le \lvert \text{cityA}_i \rvert, \lvert \text{cityB}_i \rvert \le 10$
- 城市名仅由大小写英文字母和空格组成
- 数据保证线路形成一条无环的线，且恰有一个终点站

> 💡 规模极小（$n \le 100$，城市至多 $200$ 个），$O(n^2)$ 硬扫也能过。但这题真正的价值在于：**用一张哈希集合把「是否还有出边」这一判断压成 $O(1)$**，是「度数/集合差」套路的入门模板。

## 2. 示例

**示例 1**

```text
输入：paths = [["London","New York"],["New York","Lima"],["Lima","Sao Paulo"]]
输出："Sao Paulo"
解释：线路为 London -> New York -> Lima -> Sao Paulo，
      Sao Paulo 没有任何出边，是终点站。
```

**示例 2**

```text
输入：paths = [["B","C"],["D","B"],["C","A"]]
输出："A"
解释：线路为 D -> B -> C -> A（输入的边顺序被打乱），
      A 没有任何出边，是终点站。
```

**示例 3**

```text
输入：paths = [["A","Z"]]
输出："Z"
解释：只有一条边 A -> Z，Z 的出度为 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：枚举每条边的**到达站** $b$，再遍历一遍所有边，检查是否存在某条边的**出发站**等于 $b$。若整张表里都找不到以 $b$ 为出发站的边，则 $b$ 就是终点站。

- 时间 $O(n^2)$（每条到达站都要重扫整张表），空间 $O(1)$。
- 本题 $n \le 100$，约 $10^4$ 次比较，实测毫无压力。

但它的浪费很明显：对每个到达站的查验用的都是**同一个**「出发站全集」，却被重复计算了 $n$ 次。而且它丢掉了题目最重要的结构信息——每条边只贡献一个出发站、一个到达站，城市最多 200 个，**完全可以先把出发站集合一次性建好**。

### 3.2 核心观察：终点 = 到达站里「从未出发」的那一个

![终点站、起点与中间城市的出入度模型](images/wc187_q1_endpoint_model.svg)

线路是一条**无环的链**：$k$ 条边串起 $k+1$ 个互不相同的城市 $c_0 \to c_1 \to \dots \to c_k$。链上每个城市的入度、出度都不超过 1，于是城市只有三类：

| 城市类型 | 入度 | 出度 | 在 `cityA` 列 | 在 `cityB` 列 |
|----------|------|------|---------------|---------------|
| 起点 $c_0$ | 0 | 1 | 出现 1 次 | **不出现** |
| 中间城市 $c_i$ | 1 | 1 | 出现 1 次 | 出现 1 次 |
| 终点 $c_k$ | 1 | 0 | **不出现** | 出现 1 次 |

令 $D$ 为所有 `cityAi` 组成的集合（有出边的城市），$E$ 为所有 `cityBi` 组成的集合（有入边的城市）。由上表，$D$ 与 $E$ 只差两个城市：

$$E \setminus D = \{c_k\} \quad (\text{终点站}), \qquad D \setminus E = \{c_0\} \quad (\text{起点})$$

> 💡 一句话总结：**终点站是唯一「只在 `cityB` 列出现、从不在 `cityA` 列出现」的城市**。于是问题退化成一次集合构建 + 一次顺序扫描，$O(n)$ 即可。

### 3.3 算法流程

![两遍扫描：先建出发站集合，再检查到达站](images/wc187_q1_scan_flow.svg)

1. **第一遍**：遍历 `paths`，把所有 `cityAi` 插入哈希集合 $D$。
2. **第二遍**：按输入顺序遍历 `paths`，取出当前边的到达站 $b$（即 `p[1]`）；若 $b \notin D$，立即返回 $b$。
3. 循环结束仍未返回则返回空串——由题面「恰有一个终点站」的保证，这种情况不会发生，仅为防御性收尾。

两遍扫描的**顺序不能颠倒、也不能合并**：必须等 $D$ 收齐全部出发站后再判断，否则会提前误判（示例 2 就是反例，详见 §3.4）。

### 3.4 示例演算

![示例 2 的集合构建与扫描过程](images/wc187_q1_walkthrough.svg)

以示例 2 的 `paths = [[B,C],[D,B],[C,A]]` 为例：

1. 第一遍收集出发站：$D = \{B, D, C\}$。
2. 第二遍按输入顺序扫描到达站：
   - 第 0 条边 `B->C`，到达站 $C \in D$：$C$ 有出边（`C->A`），跳过；
   - 第 1 条边 `D->B`，到达站 $B \in D$：$B$ 有出边（`B->C`），跳过；
   - 第 2 条边 `C->A`，到达站 $A \notin D$：$A$ 从没作为出发站出现，没有出边。
3. 返回 `"A"`，与官方答案一致。

若把两遍合并成「边建边查」，第 0 条边的到达站 $C$ 在当时还没进集合（此时 $D=\{B\}$），会被误判成答案——这正是本题最典型的错误写法。

## 4. 算法细节

1. **必须两遍扫描**：先完整建出 $D$，再查 $E$。边建边查在示例 2 上直接错（见 §3.4）。
2. **不能用 `paths[0][1]` 或 `paths.back()[1]` 直接作答**：输入边序是任意的。示例 2 的第一条边是 `B->C`，其到达站 $C$ 不是终点站。
3. **容器选择**：C++ 用 `unordered_set<string>`，插入与查询均摊 $O(1)$，可 `reserve(2 * n)` 减少 rehash；Python 直接用 `set`，成员判断 `b not in D` 为平均 $O(1)$。
4. **遍历用引用/解包**：C++ 写 `for (auto &p : paths)`，避免 `auto p` 拷贝两个字符串；Python 写 `for _, b in paths`，直接解包成两个变量。
5. **哈希的代价要算进去**：每次集合操作都要对城市名求哈希，单次 $O(L)$，$L \le 10$ 是常数；因此总时间仍是线性的，但常数比整数键大，`reserve` 与「只建一次集合」都能实打实提速。
6. **返回值的唯一性**：题面保证只有一个终点站，所以第二遍「命中即返回」是安全的；若担心数据违约，可在循环外 `return ""` 兜底。
7. **等价的链式走法**：另建映射 `nxt[cityA] = cityB`，从 `paths[0][0]` 出发，`while (nxt.count(cur)) cur = nxt[cur];` 一路走到没有出边为止，返回 `cur`。它同样是 $O(n)$，且不需要第二遍扫描，但哈希表要存「键 + 值」两份字符串；两相对照可以看出本题的数据结构选型空间很大。
8. **自己写测试时的输入解析**：城市名**可以含空格**（如 `"New York"`、`"Sao Paulo"`），不要用 `cin >> s` 或按空格 `split()`，必须整行读取（C++ `getline`、Python `input()` 后按分隔符切）。

## 5. 正确性证明

**引理 1（结构引理）**：设线路有 $k = \text{paths.length}$ 条边（$k \ge 1$），则存在互不相同的城市序列 $c_0, c_1, \dots, c_k$，使 `paths` 中的边恰为 $(c_0,c_1), (c_1,c_2), \dots, (c_{k-1},c_k)$。从而 `cityA` 列恰为 $c_0,\dots,c_{k-1}$（各一次），`cityB` 列恰为 $c_1,\dots,c_k$（各一次）。

**证明**：题面保证线路图「形成一条不存在循环的线路，且恰有一个终点站」，即所有边拼成一条从 $c_0$ 到 $c_k$ 的简单路径：$k$ 条边连接 $k+1$ 个互不相同的城市。于是每条边的起点是某个 $c_i$、终点是 $c_{i+1}$；每个 $c_i$ 至多作为一次起点（仅当 $i \le k-1$），也至多作为一次终点（仅当 $i \ge 1$）；而边数为 $k$，恰好用尽这 $k$ 个起点名额与 $k$ 个终点名额，故每列中各城市恰好出现一次。∎

**引理 2（差集刻画）**：记 $D=\{\text{cityA}_i\}$、$E=\{\text{cityB}_i\}$，则 $E \setminus D = \{c_k\}$。

**证明**：由引理 1，$D=\{c_0,\dots,c_{k-1}\}$、$E=\{c_1,\dots,c_k\}$，且 $c_i$ 两两不同。一方面 $c_k \in E$，而若 $c_k \in D$，则存在 $i \le k-1$ 使 $c_i=c_k$，与互不相同矛盾，故 $c_k \in E \setminus D$。另一方面取 $c_j \in E \setminus D$（$1 \le j \le k$），若 $j < k$，则 $c_j \in D$，矛盾；故只能 $j = k$。因此 $E \setminus D = \{c_k\}$。∎

**定理**：算法返回终点站 $c_k$。

**证明**：第一遍结束后，$D$ 恰为全部出发站的集合。第二遍按输入顺序枚举 $E$ 的每个元素 $b$，返回条件是 $b \notin D$，因此返回值必属于 $E \setminus D = \{c_k\}$（引理 2），即必为 $c_k$，不可能返回其它城市。又因 $k \ge 1$ 且 $c_k$ 在 `cityB` 列出现恰好一次（引理 1），扫描必然会遇到它并返回，算法不会落到兜底分支。∎

**推论（链式走法正确）**：从任意 $c_j$ 出发沿出边前进，最多 $k-j$ 步到达 $c_k$ 且路径唯一——因为链上每个城市出度不超过 1，且不存在环，出边链必然终止于唯一的出度为 0 的城市。

## 6. 复杂度分析

- **时间**：$O(n)$，$n = \text{paths.length}$。第一遍做 $n$ 次哈希插入，第二遍最多 $n$ 次哈希查询，每次均摊 $O(1)$；若把城市名长度 $L \le 10$ 计入，每次哈希为 $O(L)$，总计 $O(nL)$，仍为线性。每条边只做一次 `cityBi` 的集合查找，不涉及子串比较或排序。
- **空间**：$O(n)$，即 $O(nL)$ 字符。集合最多存 $n$ 个不同的出发站（城市总数不超过 $2n$）；除集合外只用常数个指针/迭代变量，递归栈深度为 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_set>
using namespace std;

class Solution {
public:
    string destCity(vector<vector<string>>& paths) {
        unordered_set<string> departures;
        departures.reserve(paths.size() * 2);
        for (auto &p : paths) departures.insert(p[0]);   // 第一遍：收集全部出发站

        for (auto &p : paths)                            // 第二遍：找从不出发的到达站
            if (!departures.count(p[1])) return p[1];

        return "";                                       // 题面保证不会走到这里
    }
};
```

### Python

```python
from typing import List


class Solution:
    def destCity(self, paths: List[List[str]]) -> str:
        departures = {a for a, _ in paths}      # 第一遍：收集全部出发站
        for _, b in paths:                      # 第二遍：找从不出发的到达站
            if b not in departures:
                return b
        return ""                               # 题面保证不会走到这里
```

## 8. 边界情况与易错点

1. **只有一条边**：`paths = [["A","Z"]]`，$D=\{A\}$，扫描到 $Z \notin D$ 直接返回 `"Z"`，无需特殊处理。
2. **边序任意**：示例 2 把 `[D,B]` 放在 `[B,C]` 之后，终点站可能藏在任何位置，不能取首/末条边的到达站。
3. **边建边查必错**：合并成一遍时，先遇到的边其到达站可能尚未进入集合，示例 2 会把 `C` 误判为答案。
4. **城市名含空格**：`"New York"`、`"Sao Paulo"` 是合法城市名，读入与拆分必须以整串为单位，不能按空格切词。
5. **大小写敏感**：`"A"` 与 `"a"` 是两个不同城市，比较用原始字符串，不要 `lower()` 归一化。
6. **C++ 判空写法**：`if (!departures.count(p[1]))` 才是「不在集合中」；写成 `if (!departures.find(p[1]))` 语义完全相反（迭代器判空恒为假）。
7. **重复出发站不会出现**：链结构保证每个中间城市/起点在 `cityA` 列恰好出现一次，因此 $|D| = n$；若数据违约出现重复，集合仍能正确去重，但「唯一终点」的结论不再成立。
8. **兜底返回值**：循环外 `return ""` 只用于满足编译器/类型检查，题面保证有解；若把该分支当作真实情况处理，说明对约束理解有误。

**延伸思考**：

1. 若线路不是单条链而是**若干条互不相交的链**，答案就不唯一了：此时 $E \setminus D$ 恰好是所有链的终点集合，返回集合本身即可，算法**完全不用改**——这正是「集合差」视角比「沿链走」更通用的地方。
2. 若允许分叉且有环，问题变成「找出度为 0 的全部城市」，先用哈希集合判出度即可；但若还要判断「哪些城市最终一定能走到终点」，则需要反向建图 + BFS/拓扑排序。
3. 若要求输出**整条线路的顺序**（而不只是终点），就得从入度为 0 的起点出发沿唯一出边前进，或对一般图使用 332 题的做法；此时「终点」只是这条路径的末端。
