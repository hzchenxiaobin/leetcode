# LeetCode 绝对差不超过限制的最长连续子数组 题解

## 1. 题目概述

- **标题 / 题号**：绝对差不超过限制的最长连续子数组（#1438，medium）
- **链接**：https://leetcode.cn/problems/longest-continuous-subarray-with-absolute-diff-less-than-or-equal-to-limit/
- **来源**：LeetCode 第 187 场周赛 Q3
- **难度**：中等
- **标签**：数组、队列、滑动窗口、单调队列、有序集合、堆（优先队列）

**题意**：给定整数数组 nums 与非负整数 limit，求最长的非空连续子数组，使其中**任意两个元素之差的绝对值**都不超过 limit。由于「任意两元素之差 ≤ limit」等价于「最大值 − 最小值 ≤ limit」，问题转化为：找最长的连续区间 $[l,r]$，满足 $\max(nums[l..r]) - \min(nums[l..r]) \le limit$。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^9$
- $0 \le limit \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [8,2,4,7], limit = 4
输出：2
解释：长度 3 的窗口 [8,2,4]、[2,4,7] 极差分别为 6、5，都超过 4；
      长度 2 的 [2,4] 极差为 2，合法，故答案为 2。
```

**示例 2**

```text
输入：nums = [10,1,2,4,7,2], limit = 5
输出：4
解释：[2,4,7,2] 的极差为 7 - 2 = 5 ≤ 5，长度 4；
      再往左扩展会引入 1，极差变成 7 - 1 = 6 > 5，所以最长为 4。
```

**示例 3**

```text
输入：nums = [4,2,2,2,4,4,2,2], limit = 0
输出：3
解释：limit = 0 时窗口内所有元素必须相等，
      最长的是连续的 [2,2,2]（以及 [4,4]），长度为 3。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有区间 $[l,r]$，再扫描区间求 $\max$ 与 $\min$，判断极差是否不超过 limit。

- 区间共 $O(n^2)$ 个，每个区间求极值 $O(n)$，总计 $O(n^3)$；即使边扩展边维护极值做到 $O(1)$ 更新，也仍是 $O(n^2)$。
- $n = 10^5$ 时 $O(n^2) \approx 10^{10}$，必然超时。必须让每个右端点只花 $O(1)$ 的代价拿到当前窗口的极值。

### 3.2 核心观察：极差只由最大值与最小值决定，窗口收缩单调

![极差只由窗口最大值与最小值决定](images/wc187_q3_range_model.svg)

关键有三条：

1. **合法性只取决于极值**：判断条件是 $\max - \min \le limit$，中间元素不参与。
2. **合法性对子区间封闭**：若 $[l,r]$ 合法，则任意子区间 $[l',r'] \subseteq [l,r]$ 也合法——子区间的 $\max$ 不会更大、$\min$ 不会更小。逆否命题同样有用：某区间不合法，则任何包含它的区间都不合法。
3. **极差的单调性**：右端加入元素，$\max$ 不减、$\min$ 不增，极差只增不减；左端删掉元素，极差只减不增。

由前两条得：对固定的 right，合法的左端点恰好构成一段后缀 $[l_r, right]$，其中 $l_r$ 是**最小合法左端点**，$right - l_r + 1$ 就是以 right 结尾的最长合法长度，答案即 $\max_r (right - l_r + 1)$。

由第三条得：$l_r$ 随 $r$ **单调不减**。一旦某个左端点因极差超限被淘汰，right 继续右移只会让极差更大，它不可能重新变合法。于是可以**双指针**：left 只右移，right 每前进一步就把 left 推到最小合法位置。

剩下一个问题：如何在 left 右移、right 前移的过程中始终 $O(1)$ 拿到窗口的 max 与 min？**单调队列**正好提供「尾部插入、头部删除、查询队头极值」这三个操作。

### 3.3 算法流程

![双单调队列 + 双指针流程](images/wc187_q3_two_deque_flow.svg)

维护两个存**下标**的双端队列：

- `maxQ`：队内下标对应的值**严格递减**，队头是窗口最大值。
- `minQ`：队内下标对应的值**严格递增**，队头是窗口最小值。

对 right = 0 … n−1 依次执行：

1. 把 right 压入 `maxQ`：先反复弹出队尾满足 $nums[back] \le nums[right]$ 的下标，再压入 right。
2. 把 right 压入 `minQ`：先反复弹出队尾满足 $nums[back] \ge nums[right]$ 的下标，再压入 right。
3. 当 $nums[maxQ.front] - nums[minQ.front] > limit$ 时循环：
   - 若 `maxQ` 队头等于 left，弹出队头；
   - 若 `minQ` 队头等于 left，弹出队头；
   - left 加一。
4. 用 $right - left + 1$ 更新答案。

### 3.4 示例演算

![示例 2 的逐步演算](images/wc187_q3_walkthrough.svg)

以 nums = [10,1,2,4,7,2]、limit = 5 为例：

| r | nums[r] | maxQ（值） | minQ（值） | 收缩 | left | 窗口长度 | ans |
|---|---------|-----------|-----------|------|------|---------|-----|
| 0 | 10 | 10 | 10 | — | 0 | 1 | 1 |
| 1 | 1 | 1 | 1 | 弹 10，left→1 | 1 | 1 | 1 |
| 2 | 2 | 2 | 1 2 | — | 1 | 2 | 2 |
| 3 | 4 | 4 | 1 2 4 | — | 1 | 3 | 3 |
| 4 | 7 | 7 | 2 4 7 | 弹 1，left→2 | 2 | 3 | 3 |
| 5 | 2 | 7 2 | 2 | — | 2 | 4 | **4** |

关键是 right = 4 这一行：此时窗口 [1..4] 的极差是 7 − 1 = 6 > 5，把 left 从 1 推到 2 后窗口变成 [2,4,7]，极差 5 合法；right = 5 时再加入 2，`maxQ` 变成 [7,2]、`minQ` 变成 [2]，极差仍是 7 − 2 = 5，窗口扩展到长度 4。

顺带看 `maxQ` 在 right = 5 时的变化：新元素 2 挤不掉队头 7，只能排在队尾；而 `minQ` 里原来的 2、4、7 全部被新来的 2 挤掉（它们都 $\ge 2$），队头换成新的 2。这正是「更靠右且值更极端的老元素一定更有用」的体现。

## 4. 算法细节

1. **队列存下标而不是值**：收缩窗口时要判断「队头元素是否正好是 left」，只有存下标才能判断；值相等时比较下标也没有歧义。
2. **弹出条件取非严格 $\le$ / $\ge$**：新元素与队尾值相等时把老下标弹掉。老下标更小、活得更短，留着毫无用处；弹出后队列内值严格单调，队头永远是「最值中位置最右的那个」。
3. **收缩用 while 而非 if**：一次加入可能让 left 连续右移多步（例如 limit = 0 且新元素与窗口内所有值都不同）。
4. **两个队列都要检查队头**：只有队头可能等于 left（其余下标都大于 left）；漏掉 `minQ` 的队头弹出，收缩判断就会用到已经离开窗口的旧最小值，可能把非法窗口当成合法（也可能过度收缩），答案必然出错。
5. **先弹队头再 left 加一**：顺序颠倒会让「队头 == left」的判断失效，离开窗口的元素残留在队列里。
6. **收缩结束后再更新答案**：此时 [left, right] 才是以 right 结尾的最长合法窗口；在收缩之前更新会取到非法长度。
7. **数值范围**：$nums[i] \le 10^9$，极差最大 $10^9 - 1$，`int` 足够；若值域扩展到 $10^{18}$ 级别则需 `long long`。
8. **Python 必须用 `collections.deque`**：`list.pop(0)` 为 $O(n)$，会把整体拖成 $O(n^2)$。

## 5. 正确性证明

**引理 1（子区间封闭）**：若区间 $[l,r]$ 合法，则任意子区间 $[l',r'] \subseteq [l,r]$ 也合法。

**证明**：设 $M = \max nums[l..r]$、$m = \min nums[l..r]$，有 $M - m \le limit$。子区间满足 $\max nums[l'..r'] \le M$ 且 $\min nums[l'..r'] \ge m$，故其极差 $\le M - m \le limit$。∎

**引理 2（单调队列不变量）**：在处理完 right 并完成收缩后，`maxQ` 队头的值等于 $\max nums[left..right]$，`minQ` 队头的值等于 $\min nums[left..right]$，且两个队列中的下标都落在 $[left, right]$ 内。

**证明**：只证 `maxQ`，`minQ` 完全对称。把 `maxQ` 中的下标按升序记为 $i_1 < i_2 < \dots < i_k$，则 $nums[i_1] > nums[i_2] > \dots > nums[i_k]$，且每个 $i_t$ 都大于它右侧（窗口内）的所有元素：

- 压入 right 时，队尾凡是 $nums[back] \le nums[right]$ 的都被弹出，等价于「right 破坏了它们的后缀最大性质」；新的 right 自身右侧为空，性质成立。其余元素的性质不受影响。
- left 加一时，若队头恰为 left 就弹出；由于队列下标递增，其余下标都大于 left，窗口内没有别的元素被删，性质保持。
- 反过来，任何被弹出的下标 $i$ 都满足存在 $j > i$ 且 $nums[j] \ge nums[i]$。沿这条「被谁弹出」的关系不断往后走，下标严格增大，必终止于某个仍在队列中的 $j^*$，且 $nums[j^*] \ge nums[i]$。因此窗口内不在队列中的下标，其值一定被队列中某个更靠右的下标「覆盖」，窗口最大值必在队列中取得。
- 队列内值严格递减，故窗口最大值就是队头值。∎

**引理 3（left 的最小性）**：对每个 right，收缩结束时 $[left, right]$ 合法，且 left 是所有合法窗口 $[l, right]$ 中最小的 $l$。

**证明**：循环退出时 $nums[maxQ.front] - nums[minQ.front] \le limit$，由引理 2 即 $[left, right]$ 合法。若 left > 0，说明上一次迭代检查过 $[left-1, right]$ 且极差超限（否则不会把 left 从 $left-1$ 加到 left），由引理 1 的逆否命题，任何 $l' \le left-1$ 的 $[l', right]$ 都不合法，故 left 最小。循环必然终止：单元素窗口 $[right,right]$ 极差为 $0 \le limit$，left 至多推到 right。∎

**定理**：算法返回的长度是最长合法连续子数组的长度。

**证明**：由引理 3，每个 right 处得到的长度 $right - left + 1$ 是以 right 结尾的最长合法长度，且该窗口确实合法，故答案不大于最优值。反之，设最优区间为 $[l^*, r^*]$，它是以 $r^*$ 结尾的合法窗口，长度不超过该处的最长合法长度 $r^* - left_{r^*} + 1$，故最优值不超过答案。两者相等。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个下标进入 `maxQ`、`minQ` 各一次，从队尾被弹出各至多一次，从队头被弹出各至多一次；left 单调右移，总共加不超过 $n$ 次。全部操作均摊 $O(1)$。
- **空间复杂度**：$O(n)$。最坏情况（数组严格递增时 `minQ` 会存下所有下标）两个队列合计 $O(n)$ 个下标；除此之外只有常数个变量。
- **对比**：有序集合（multiset / `SortedList`）写法为 $O(n \log n)$，堆 + 懒删除也是 $O(n \log n)$，双单调队列是本题最优解法。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int longestSubarray(vector<int>& nums, int limit) {
        deque<int> maxQ, minQ;          // 存下标：值分别严格递减 / 严格递增
        int n = nums.size(), left = 0, ans = 0;
        for (int right = 0; right < n; ++right) {
            while (!maxQ.empty() && nums[maxQ.back()] <= nums[right]) maxQ.pop_back();
            maxQ.push_back(right);
            while (!minQ.empty() && nums[minQ.back()] >= nums[right]) minQ.pop_back();
            minQ.push_back(right);

            while (nums[maxQ.front()] - nums[minQ.front()] > limit) {
                if (maxQ.front() == left) maxQ.pop_front();
                if (minQ.front() == left) minQ.pop_front();
                ++left;
            }
            ans = max(ans, right - left + 1);
        }
        return ans;
    }
};
```

### Python

```python
from collections import deque


class Solution:
    def longestSubarray(self, nums: list[int], limit: int) -> int:
        max_q, min_q = deque(), deque()   # 存下标：值分别严格递减 / 严格递增
        left = ans = 0
        for right, x in enumerate(nums):
            while max_q and nums[max_q[-1]] <= x:
                max_q.pop()
            max_q.append(right)
            while min_q and nums[min_q[-1]] >= x:
                min_q.pop()
            min_q.append(right)

            while nums[max_q[0]] - nums[min_q[0]] > limit:
                if max_q[0] == left:
                    max_q.popleft()
                if min_q[0] == left:
                    min_q.popleft()
                left += 1

            ans = max(ans, right - left + 1)
        return ans
```

## 8. 边界情况与易错点

1. **`n = 1`**：循环一次，left = 0，答案 1，无需特判。
2. **`limit = 0`**：退化为「最长等值连续段」，收缩循环会把窗口压到只剩相同值；不要为此写额外分支。
3. **收缩不会越过 right**：单元素窗口极差为 0 必然合法，while 一定在 left ≤ right 时停下；若把合法条件写成 `>=` 或漏掉单元素情形，left 可能超过 right 导致越界。
4. **只维护一个队列会出错**：极差由最大值与最小值共同决定，只更新 `maxQ` 而忘记 `minQ`，收缩判断用到的可能是窗口外的旧最小值。
5. **ans 初值**：数组非空（$n \ge 1$），初值取 0 即可，最终至少为 1；不要为了省一次比较把初值设成 1 并跳过更新。
6. **相等元素的处理**：弹出条件写成严格 `<`（保留相等元素）也正确，只是队列更长、常数更大；真正致命的是收缩时用「队头值是否等于 left」来判断——必须比较**下标** `maxQ.front() == left`，比较值在存在重复元素时会误删或漏删。
7. **大数组性能**：$10^5$ 次操作、常数很小，双端队列足够快；用 Python `list` 模拟队头删除会 TLE。
