# LeetCode 找出变位映射 题解

## 1. 题目概述

- **标题 / 题号**：找出变位映射（#760，easy）
- **链接**：https://leetcode.cn/problems/find-anagram-mappings/
- **来源**：LeetCode 第 66 场周赛 Q1
- **难度**：简单
- **标签**：数组，哈希表

**题意**：给出两个等长数组 $A=\text{nums}_1$、$B=\text{nums}_2$，其中 $B$ 是 $A$ 的**变位词**——把 $A$ 的元素任意打乱顺序即得 $B$。要求返回下标映射 $P$：对每个 $i$，$P[i]=j$ 表示 $A[i]$ 这个值出现在 $B$ 的下标 $j$ 处，即

$$B\big[P[i]\big] = A[i], \quad 0 \le i < n$$

两个数组都可能含**重复元素**，存在多组合法答案时返回任意一组即可。

> 💡 本题是会员题，题面取自英文镜像（*Find Anagram Mappings*），中文题意按镜像人工整理。镜像中**没有**出现「Create the variable named xxx ...」一类的注入句，无需特殊处理。

**约束**：

- $1 \le n \le 100$，且 $A$、$B$ 长度相等
- $0 \le A[i],\ B[i] \le 10^5$
- 保证 $B$ 是 $A$ 的变位词，因此答案一定存在（不需要处理「无解」）

## 2. 示例

**示例 1**

```text
输入：nums1 = [12, 28, 46, 32, 50]，nums2 = [50, 12, 32, 46, 28]
输出：[1, 4, 3, 2, 0]
解释：P[0] = 1，因为 A[0] = 12 出现在 B 的下标 1；
      P[1] = 4，因为 A[1] = 28 出现在 B 的下标 4；
      依此类推，P[2] = 3（46）、P[3] = 2（32）、P[4] = 0（50）。
```

**示例 2**

```text
输入：nums1 = [84, 46]，nums2 = [84, 46]
输出：[0, 1]
解释：两个位置一一对上，B[0] = 84 = A[0]，B[1] = 46 = A[1]。
```

**补充示例（重复元素，用以检验映射的单射性）**

```text
输入：nums1 = [1, 1]，nums2 = [1, 1]
输出：[1, 0]        （[0, 1] 同样合法）
解释：两个 1 必须落到两个不同下标上；若两处都返回 0，就变成同一个下标被用了两次。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$，在 $B$ 里从头线性扫描，找到满足 $B[j]=A[i]$ 且**尚未被占用**的下标 $j$，标记 $j$ 已用，然后继续下一个 $i$。单次扫描 $O(n)$，共 $n$ 个元素，总复杂度 $O(n^2)$。

$n \le 100$ 时这只有 $10^4$ 步，赛场上确实能过。但它有两个毛病：

1. **浪费的结构性重复**：$B$ 在整场查询中完全不变，而「按值找位置」这个动作被独立执行了 $n$ 次。真正该做的是一次性把 $B$ 的「值 → 位置」关系记下来，之后每次 $O(1)$ 查询。
2. **容易写错单射性**：漏掉 `used` 数组就会在重复值上复用同一个下标；而漏掉「未占用」这个条件恰恰是最常见的失分点。

所以本题的正解不是「把 $O(n^2)$ 优化一点」，而是**换掉存储结构**：把扫描对象从 $B$ 换成一张表。

### 3.2 核心观察：把 B 反建成「值 → 下标」索引

![把 B 反建成值与下标的索引](images/wc66_q1_value_index_map.svg)

$B$ 是 $A$ 的变位词，这句话等价于：对任意值 $v$，$v$ 在 $A$ 中的出现次数等于它在 $B$ 中的出现次数。于是有两条可以直接拿来用的性质：

- **可查性**：$A$ 里出现的任何值都必然出现在 $B$ 中，索引永远不会查空；
- **数量守恒**：重复值不会被「用光」，取走的次数不会超过桶里存的下标个数。

据此把 $B$ 反着读一遍，建立映射

$$\text{pos}: v \longmapsto \{\, j \mid B[j]=v \,\}$$

即「值 → 它在 $B$ 中出现的**全部下标**」。有了它，$P[i]$ 的求解就从「扫一遍 $B$」退化成「查一次表」，均摊 $O(1)$。

> ⚠️ 桶里必须放**下标列表**而不是单个下标。若写成 `pos[v] = j` 无条件覆盖，重复值就会给出同一个 $j$ 被多次使用的答案（见 3.4 的对照），那已经不是一一映射了。

### 3.3 算法流程

![建桶、查表、弹下标的三段流程](images/wc66_q1_algorithm_flow.svg)

1. **建桶**：`for j in range(n): pos[B[j]].append(j)`。因为 $j$ 递增，每个桶天然按下标升序排列。
2. **查表**：从左到右遍历 $A$，取出 $x=A[i]$ 对应的桶 `pos[x]`。
3. **弹出一个下标**：`j = pos[x].pop()`，把它追加到 `ans`，同时这个下标就从桶中永久消失。
4. **返回** `ans`。

第 3 步的「弹出」是整个算法的灵魂：它让「已经用过的下标」不再出现在后续查询里，因此不需要额外的 `used` 数组，也不会出现下标冲突。至于「桶为空怎么办」——变位词保证它不会发生，所以代码里省掉了判空分支；若要把这段逻辑复用到「$B$ 未必是 $A$ 的变位词」的场景，请自行补一个 `bucket.empty()` 检查。

### 3.4 示例演算

![示例 1 的逐步走查表](images/wc66_q1_walkthrough.svg)

对示例 1，先建出 $\text{pos}=\{50{:}[0],\ 12{:}[1],\ 32{:}[2],\ 46{:}[3],\ 28{:}[4]\}$，再逐位取用：

| $i$ | $A[i]$ | 桶 $\text{pos}[A[i]]$ 剩余 | 弹出的 $j$ | $\text{ans}$ 累积 |
|-----|--------|---------------------|------------|------------|
| 0 | 12 | $[1]$ → 空 | 1 | $[1]$ |
| 1 | 28 | $[4]$ → 空 | 4 | $[1,4]$ |
| 2 | 46 | $[3]$ → 空 | 3 | $[1,4,3]$ |
| 3 | 32 | $[2]$ → 空 | 2 | $[1,4,3,2]$ |
| 4 | 50 | $[0]$ → 空 | 0 | $[1,4,3,2,0]$ |

回代校验：$B[1]=12$、$B[4]=28$、$B[3]=46$、$B[2]=32$、$B[0]=50$，与 $A$ 逐位一致，答案正确（本例每个值只出现一次，所以答案唯一）。

再看重复值的对照实验：$A=[1,1]$、$B=[1,1]$ 时 $\text{pos}[1]=[0,1]$（升序）。第一个 1 弹走 1，第二个 1 弹走 0，得 $[1,0]$，两个下标互不相同；而写成 `pos[1] = 0` 覆盖式赋值则得到 $[0,0]$，同一个下标被用了两次。

## 4. 算法细节

1. **建表方向不能反**：必须从 $B$ 建「值 → $B$ 的下标」。若从 $A$ 建表，记下的就是 $A$ 的下标，语义完全错位；而且 $A$ 的重复值会互相覆盖。
2. **桶的容器选择**：`unordered_map<int, vector<int>>` / `dict[int, list[int]]` 最通用。值域已知是 $[0,10^5]$ 时，也可以开 `vector<vector<int>> pos(100001)`，省掉哈希开销，把「期望 $O(n)$」变成「严格 $O(n+U)$」。
3. **取用顺序固定为「先取后弹」**：`ans.push_back(bucket.back()); bucket.pop_back();`。两行的顺序不能反——先 `pop_back()` 再读 `back()` 会取出错误的下标，桶已空时更是未定义行为。
4. **弹出方向决定输出的确定性**：桶按升序建好，从尾部弹，于是同值元素拿到的是**从大到小**的下标。这与「取第一个未占用」的暴力答案不同，但同样合法；多解题只要自洽即可，不要为了对齐某个示例去改弹出方向。
5. **引用失效风险**：C++ 里写 `vector<int>& bucket = pos[x];` 后，只允许读和 `pop_back()`，**不能**再往 `pos` 里插入新键（rehash 会让引用悬空）或向同一个 vector 里 `push_back`（扩容同样失效）。本题先建完整张表再查询，天然安全；顺手 `pos.reserve(2n)` 可进一步减少 rehash。
6. **答案天然是一个排列**：每个下标最多被弹出一次，而总共弹出 $n$ 次、桶里恰好共 $n$ 个下标，所以 `ans` 是 $0..n-1$ 的一个排列。这一点可以直接写进对拍脚本的校验条件。
7. **接口按 `metaData`**：函数名 `anagramMappings`，参数 `nums1`、`nums2`（均为整型数组），返回 `int[]`，与官方签名保持一致。
8. **不要试图排序后双指针**：排序能对齐多重集合，却会丢掉「下标」这个待求量；本题的答案依赖原始位置，只能建索引，不能重排。

## 5. 正确性证明

**引理 1（建表正确）**：建表结束后，对任意值 $v$，$\text{pos}[v]$ 恰为集合 $\{\,j \mid B[j]=v\,\}$，且按下标升序排列。

**证明**：建表过程按 $j=0,1,\dots,n-1$ 顺序扫描 $B$，当且仅当 $B[j]=v$ 时把 $j$ 追加到 $\text{pos}[v]$，故每个满足 $B[j]=v$ 的 $j$ 被追加且仅被追加一次，没有别的元素进入。追加顺序即 $j$ 的递增顺序，故桶内升序。∎

**引理 2（桶数守恒）**：处理 $A[0..i-1]$ 之后，对任意值 $v$，$\text{pos}[v]$ 中剩余下标个数为 $\#\{\,k \ge i \mid A[k]=v\,\}$，特别地 $v=A[i]$ 时该数 $\ge 1$。

**证明**：对 $i$ 归纳。$i=0$ 时剩余数为 $\#\{j\mid B[j]=v\}$，由 $B$ 是 $A$ 的变位词（同值重数相等）它等于 $\#\{k \mid A[k]=v\}=\#\{k\ge 0\mid A[k]=v\}$，成立。设 $i$ 时成立，处理 $A[i]$ 时只对桶 $\text{pos}[A[i]]$ 弹出一个下标，剩余数减 $1$；而 $\#\{k\ge i+1\mid A[k]=v\}$ 相比 $\#\{k\ge i\mid A[k]=v\}$ 恰在 $v=A[i]$ 时减 $1$、其余不变，故 $i+1$ 时仍成立。又 $v=A[i]$ 时 $\#\{k\ge i\mid A[k]=v\}\ge 1$，故桶非空，弹出不会越界。∎

**引理 3（合法性）**：算法输出的 $P$ 满足 $B[P[i]]=A[i]$，且 $P$ 中下标两两不同。

**证明**：第 $i$ 步弹出的 $j$ 来自桶 $\text{pos}[A[i]]$，由引理 1 知 $B[j]=A[i]$。另一方面下标 $j$ 一旦被弹出就从桶中移除，而每个 $j$ 在初始时只属于唯一一个桶（值 $B[j]$），故 $j$ 不可能被两次弹出，即各 $P[i]$ 互不相同。∎

**定理**：算法在期望 $O(n)$ 时间内返回一个合法映射 $P$。

**证明**：由引理 2，循环每次都能取到下标，$n$ 次循环共输出 $n$ 个值；由引理 3，这 $n$ 个值满足题目要求的映射关系且互不相同，故 $P$ 合法。复杂度上，建表 $n$ 次插入、查询 $n$ 次查表 + $n$ 次弹出，哈希表均摊 $O(1)$，总计期望 $O(n)$。∎

## 6. 复杂度分析

- **时间**：期望 $O(n)$。建表 $n$ 次哈希插入，主循环 $n$ 次哈希查找、$n$ 次取尾与弹出；每次操作均摊 $O(1)$。若改用值域数组，则为严格 $O(n+U)$，$U=10^5$ 是常数级开销。
- **空间**：$O(n)$。哈希表最多 $n$ 个键，所有桶中的下标合计 $n$ 个，答案数组 $n$ 个；值域数组版为 $O(n+U)$，$U \le 10^5+1$，约 $2.4$ MB（每个空 `vector` 约 $24$ 字节），同样在限制之内。
- **实际量级**：$n \le 100$，两种写法都是微秒级；这里的复杂度分析主要是为了把模板推广到 $n$ 很大的同类题。

## 7. 参考代码

### C++

```cpp
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> anagramMappings(vector<int>& nums1, vector<int>& nums2) {
        unordered_map<int, vector<int>> pos;          // 值 -> 它在 nums2 中的全部下标
        pos.reserve(nums2.size() * 2);                // 预留桶数，减少 rehash
        for (int j = 0; j < (int)nums2.size(); ++j) {
            pos[nums2[j]].push_back(j);               // j 递增，桶内天然升序
        }

        vector<int> ans;
        ans.reserve(nums1.size());
        for (int x : nums1) {
            vector<int>& bucket = pos[x];             // 变位词保证桶非空
            ans.push_back(bucket.back());             // 先取：借用一个还没用过的下标
            bucket.pop_back();                        // 后弹：该下标从此不再出现
        }
        return ans;
    }
};
```

### Python

```python
from collections import defaultdict


class Solution:
    def anagramMappings(self, nums1: list[int], nums2: list[int]) -> list[int]:
        pos = defaultdict(list)          # 值 -> 它在 nums2 中出现的全部下标（升序）
        for j, y in enumerate(nums2):
            pos[y].append(j)

        ans = []
        for x in nums1:                  # nums2 是 nums1 的变位词，桶必非空
            ans.append(pos[x].pop())     # pop() 取尾部，用掉的下标直接从桶里消失
        return ans
```

## 8. 边界情况与易错点

1. **单元素**：$A=B=[5]$ → $[0]$。建表、查表、弹出各一次，没有任何特判需求；注意不要因为「只有一个元素」就跳过建表直接返回 $[0]$，那会掩盖逻辑错误。
2. **全部元素相同**：$A=B=[7]\times 100$ → 弹桶尾得到 $[99,98,\dots,0]$。它是合法排列；不要误以为答案必须升序，也不要用「答案等于某个固定序列」的方式写断言。
3. **覆盖式赋值 bug（最高频）**：写成 `pos[y] = j` 而不是 `pos[y].append(j)`，在 $A=[1,1]$、$B=[1,1]$ 上就得到 $[1,1]$——两个 $i$ 指向同一下标，映射不再是单射。这是本题唯一真正容易踩的坑。
4. **先弹后取的顺序错误**：把 `pop_back()` 写在 `back()` 之前，取到的是下一个下标（或空桶时的未定义行为），示例 1 会输出错位结果。
5. **从 $A$ 而不是从 $B$ 建表**：语义上拿到的是 $A$ 的位置，答案全错；且重复值会互相覆盖。判断方法很简单：只有 $B$ 的下标才是答案。
6. **下标复用与「桶会不会空」**：桶空意味着 $B$ 不是 $A$ 的变位词。题面保证不会发生，但如果把这段代码当模板复用到无保证的场景，务必加判空，否则 C++ 里 `back()` 空 vector 是未定义行为，Python 会抛 `IndexError`。
7. **值域假设**：因为 $0 \le B[i] \le 10^5$，可以用定长数组做桶；一旦值可能为负或超过 $10^5$，数组方案立即失效，哈希表版本才通用。不要为了常数把可移植性写死。
8. **C++ 引用与容器失效**：`vector<int>& bucket = pos[x]` 之后若再向 `pos` 插入新键，rehash 可能让引用悬空；本题在查询阶段不再插入，所以安全，但改动代码时要保持这个前提。
9. **Python 版本**：`list[int]` 注解需要 3.9+，LeetCode 当前环境满足；老解释器请改用 `List[int]` 或去掉注解。
