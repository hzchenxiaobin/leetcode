# LeetCode 字符串中的加粗单词 题解

## 1. 题目概述

- **标题 / 题号**：字符串中的加粗单词（#758，medium）
- **链接**：https://leetcode.cn/problems/bold-words-in-string/
- **来源**：LeetCode 第 66 场周赛 Q2
- **难度**：中等
- **标签**：数组，哈希表，字符串，字符串匹配，字典树，AC 自动机

**题意**：给定关键词表 `words` 与字符串 `s`，把 `s` 中**每一次**关键词出现都加粗：凡是落在某个关键词某次出现区间内的字符，必须被 `<b>` 与 `</b>` 包住。返回结果串，要求**标签对数最少**且标签合法配对——即不允许出现 `<b>a<b>b</b>c</b>` 这类嵌套，也不允许把本该合并的相邻命中拆成两对标签。

**约束**：

- $0 \le \lvert \text{words} \rvert \le 50$
- $1 \le \lvert \text{words}[i] \rvert \le 10$
- $0 \le \lvert s \rvert \le 500$
- `words[i]` 与 `s` 仅由小写英文字母组成

> 💡 本题是 Plus 会员题，中文题面不可见，只能读英文镜像。它的免费姊妹题是 [616. 给字符串添加加粗标签](../../solution/0601-0700/616_给字符串添加加粗标签.md)，两题**算法完全一致**：本题只是把关键词的规模从「少而长」换成「多而短」（$m \le 50$、$L \le 10$）。官方标签给出**字典树**与 **AC 自动机**，暗示 $m$ 继续变大时的优化方向，见 §4 第 7 点。

## 2. 示例

**示例 1**

```text
输入：words = ["ab","bc"]，s = "aabcd"
输出："a<b>abc</b>d"
解释："ab" 覆盖 [1,2]，"bc" 覆盖 [2,3]，二者在位置 2 重叠 → 合并成一段 [1,3]。
      故只插一对标签；写成 "a<b>a<b>b</b>c</b>d" 用了 3 对标签，不符合「最少」。
```

**示例 2**

```text
输入：words = ["ab","cb"]，s = "aabcd"
输出："a<b>ab</b>cd"
解释："ab" 只覆盖 [1,2]；"cb" 在 s 中不出现，不产生任何覆盖。
      因此只有一段 [1,2]，首字符 'a' 与尾部的 "cd" 都不加粗。
```

**补充对照（相邻命中）**

```text
输入：words = ["ab","cd"]，s = "abcd"
输出："<b>abcd</b>"
解释："ab" 覆盖 [0,1]、"cd" 覆盖 [2,3]，两段首尾相接（端点接触、没有空隙），
      仍属同一段连续覆盖，必须合并为一对标签。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是「边找边插标签」：对每个关键词的每次命中，直接在字符串里插入 `<b>`、`</b>`。这条路会同时踩三个坑：

1. **嵌套**：两个命中重叠时产生 `<b>a<b>b</b>c</b>`，需要事后去嵌套；
2. **相邻未合并**：端点接触的两个命中产生 `<b>ab</b><b>cd</b>`，标签对数不是最少；
3. **下标错位**：插入标签后原串下标全部右移，后续命中的位置全部失效。

修补这三种情况的代码互相纠缠，极易在边界上出错。根因是**没有先把「哪些字符该加粗」一次性算清**，就去改动字符串。

### 3.2 核心观察：布尔掩码把区间合并「拍平」

与其在字符串上动刀，不如先离线回答一个更简单的问题：**每个下标该不该加粗？**

- 开一个长度 $n = \lvert s \rvert$ 的布尔数组 `bold`，初值全为 `false`；
- 对每个关键词 $w$ 的每一次出现（起点 $j$），把下标 $j$ 到 $j+\lvert w \rvert-1$ 全部置 `true`；
- 最后扫描 `bold`：连续 `true` 的一段就是一对标签的包裹范围。

这一步的关键在于：**重叠**的两个命中会共用某些格子，**相邻**的两个命中之间没有 `false` 隔开，两种情况在掩码里都表现为「一段连续 `true`」——合并逻辑根本不用写，它被数据结构免费送给了我们。

![布尔掩码：重叠与相邻都连成连续 true 段](images/wc66_q2_bold_mask.svg)

> 💡 **为什么连续 `true` 段恰好等于「最少标签」？** 因为一段极大连续 `true` 的两侧（若存在）都是 `false`，也就是不该加粗的字符。若把两段塞进同一对标签，中间那段 `false` 字符会被迫变粗；若把一段拆成多对标签，对数只增不减。所以**一段一对、段数即最少对数**（形式化见 §5 引理 3）。

### 3.3 算法流程

![两阶段流程：打掩码 → 扫描插标签](images/wc66_q2_scan_tag_flow.svg)

**完整步骤**：

1. **建掩码**：`bold = [False] * n`。
2. **标记**：对每个起点 $i \in [0, n)$ 与每个词 $w$，若 $s[i..i+\lvert w \rvert) = w$（先判 $i + \lvert w \rvert \le n$），就把区间内全部置 `True`。实现上可以反过来遍历词、用子串查找枚举它的每次出现（含重叠出现）。
3. **扫描拼接**：指针 $i$ 从 0 出发：
   - `bold[i]` 为 `True`：追加 `<b>`，然后 `while i < n and bold[i]`，逐字符追加并右移，退出后追加 `</b>`；
   - `bold[i]` 为 `False`：追加 `s[i]`，$i$ 加一。
4. 返回拼接结果。整个过程中 $i$ 单调前进，总代价 $O(n)$。

### 3.4 示例演算

以示例 1 的 `s = "aabcd"`、`words = ["ab","bc"]` 为例，掩码为 `[F,T,T,T,F]`：

![示例演算：5 步扫描，只看跳变插标签](images/wc66_q2_walkthrough.svg)

| 步骤 | $i$ | $s[i]$ | `bold[i]` | 动作 | 累积输出 |
| ---- | --- | ------ | --------- | ---- | -------- |
| 1 | 0 | a | F | 直接追加 | `a` |
| 2 | 1 | a | T | $F \to T$，先插 `<b>` | `a<b>a` |
| 3 | 2 | b | T | 段内追加 | `a<b>ab` |
| 4 | 3 | c | T | 段内追加 | `a<b>abc` |
| 5 | 4 | d | F | $T \to F$，先补 `</b>` | `a<b>abc</b>d` |

注意第 2 步的 `F→T` 与第 5 步的 `T→F`：**插标签只看跳变，不看命中个数**。示例 1 里有两处命中（`ab`、`bc`），但只有一段连续 `true`，所以只插一对标签。

## 4. 算法细节

1. **掩码容器**：C++ 用 `vector<char>` 而不是 `vector<bool>`——后者是按位压缩的特化，逐位置赋值要做读改写、且元素不能取地址，在 $n \le 500$ 这种小规模上纯属自找麻烦。
2. **匹配方式**：C++ 用 `s.compare(i, l, w) == 0`，Python 用 `s.startswith(w, i)`，都不创建子串；也可以像参考代码那样反向枚举「词的所有出现」用 `find`。无论哪种，**必须先保证 $i + l \le n$**，否则 `compare` 会越界抛异常。
3. **重叠出现不能漏**：用 `find` 枚举同一词的多次出现时，下一次查找起点必须是 `start + 1`，不能是 `start + len(w)`。例如 `["aa"]` 与 `"aaaaa"`：按 `start += 2` 推进会只找到起点 0、2 的两次出现，漏掉起点 1、3 的命中，最后一个 `'a'` 就加不上粗。
4. **指针推进**：进入 `bold[i] = true` 分支后，内层 `while` 已经把 $i$ 推到段尾的下一位（或 $n$），外层**不得再自增**。C++ 写成 `for (int i = 0; i < n;)`，只在 `else` 分支 `i++`；Python 用单个 `while i < n` 统一控制最稳。
5. **标签成对**：每段独立地「开标签 → 输出 → 闭标签」，天然成对且不嵌套；不要试图跨段复用标签。
6. **空输入**：$n = 0$ 时循环体一次都不执行，直接得到空串；`words` 为空时掩码全 `false`，原样返回 $s$，两条路径都不需要特判。
7. **用 Trie 优化匹配（可选）**：把 $m$ 个词建成前缀树，从每个起点沿树走至多 $L_{\max} = 10$ 层，命中词尾节点就标记区间。匹配从 $O(n \cdot m \cdot L)$ 降到 $O(n \cdot L_{\max})$，建树 $O(\sum \lvert w_i \rvert)$。再进一步用 AC 自动机（fail 指针）可做到一次线性扫描 $O(n + \sum \lvert w_i \rvert)$，这也是官方标签的来源。

## 5. 正确性证明

**引理 1（掩码恰为命中并集）**：标记结束后，对任意 $0 \le i < n$，`bold[i] = true` 当且仅当存在某个词 $w$ 与起点 $j$，使得 $s[j..j+\lvert w \rvert) = w$ 且 $j \le i < j + \lvert w \rvert$。

**证明**：掩码初值全 `false`，只有「匹配成功」这一处写入 `true`，写入范围正是该次命中的覆盖区间。因此每个 `true` 都来自某次命中，且每次命中的全部位置都被置 `true`。∎

**引理 2（极大段 = 标签区间）**：设 `bold` 的一段极大连续 `true` 区间为 $[a,b]$（即 `bold[a..b]` 全真，且 $a=0$ 或 `bold[a-1]` 假，$b=n-1$ 或 `bold[b+1]` 假）。则任何合法输出中包住 $[a,b]$ 的那对标签，其覆盖范围必须恰好是 $[a,b]$。

**证明**：一方面，$[a,b]$ 内每个字符都被命中（引理 1），必须加粗，标签区间必须包含 $[a,b]$；另一方面，若标签区间向左右扩张到 $a-1$ 或 $b+1$，由极大性这两个位置（若存在）是 `false`，即不被任何命中覆盖，扩张会把它们错误地加粗，违反「只加粗命中字符」。故恰好为 $[a,b]$。∎

**引理 3（最少标签对数 = 段数）**：记 `bold` 的极大 `true` 段数为 $k$，则任何合法输出至少需要 $k$ 对标签，且 $k$ 对可以做到。

**证明**：由引理 2，每段由一个标签区间恰好覆盖，而一个标签区间是连通的、只能落在一段之内（跨段必然包含 `false` 位置），故不同段必须用不同标签对，下界 $k$。扫描算法对每段各开闭一次，恰好 $k$ 对，达到下界。∎

**定理**：算法返回的字符串满足：① 所有关键词的所有出现都被加粗；② 没有被命中覆盖的字符不加粗；③ 标签对数最少；④ 标签正确配对、互不嵌套。

**证明**：由引理 1，掩码为真的位置恰是命中并集，扫描阶段逐字符原序输出、并只在 `true` 段两侧插标签，故 ① ② 成立；由引理 3，对数达到 $k$ 这一下界，故 ③ 成立；每段内先写 `<b>`、写完本段再写 `</b>`，开关严格配对且段与段之间不会交叉，故 ④ 成立。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot m \cdot L)$。标记阶段枚举 $n$ 个起点 × $m$ 个词，每次比较 $O(L)$；扫描阶段 $O(n)$。代入上界 $500 \times 50 \times 10 = 2.5 \times 10^5$ 次字符比较，完全可接受。若用 Trie，匹配降为 $O(n \cdot L_{\max} + \sum \lvert w_i \rvert)$。
- **空间**：$O(n)$。掩码占 $n$ 个布尔值；结果串每段最多增加 7 个字符（`<b>` + `</b>`），段数至多 $\lceil n/2 \rceil$，故长度不超过 $n + 7\lceil n/2 \rceil = O(n)$。
- **两阶段可分离**：匹配与拼接互不依赖，标记可以随意换实现（暴力 / Trie / AC 自动机），扫描段代码一行都不用改——这是本题解法的最大工程优势。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
  public:
    string boldWords(vector<string>& words, string s) {
        int n = s.size();
        vector<char> bold(n, 0);                 // ① 布尔掩码

        for (int i = 0; i < n; ++i) {
            for (const string& w : words) {
                int l = w.size();
                if (i + l <= n && s.compare(i, l, w) == 0) {
                    for (int j = i; j < i + l; ++j) bold[j] = 1;
                }
            }
        }

        string res;                              // ② 扫描插标签
        for (int i = 0; i < n;) {
            if (bold[i]) {
                res += "<b>";
                while (i < n && bold[i]) res += s[i++];
                res += "</b>";
            } else {
                res += s[i++];
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def boldWords(self, words: list[str], s: str) -> str:
        n = len(s)
        bold = [False] * n

        # ① 枚举每个词的每一次出现（start + 1 保证重叠出现不被漏掉）
        for w in words:
            l = len(w)
            start = s.find(w)
            while start != -1:
                for j in range(start, start + l):
                    bold[j] = True
                start = s.find(w, start + 1)

        # ② 连续 True 段两侧各插一个标签
        res = []
        i = 0
        while i < n:
            if bold[i]:
                res.append("<b>")
                while i < n and bold[i]:
                    res.append(s[i])
                    i += 1
                res.append("</b>")
            else:
                res.append(s[i])
                i += 1
        return "".join(res)
```

## 8. 边界情况与易错点

1. **空串 / 空词表**：`s = ""` 或 `words = []` 时不能崩，也不能多出标签；掩码长度 0、循环不进入即可自然返回 `""` 或原串，无需特判。
2. **关键词比串长**：如 `words = ["abc"]`、`s = "ab"`，必须先判 `i + l <= n`，否则 C++ `s.compare(i, l, w)` 会抛 `out_of_range`；Python 的 `find` 则天然返回 `-1`。
3. **相邻命中被拆成两对标签**：`["ab","cd"]` 与 `"abcd"` 的正确输出是 `<b>abcd</b>`。这是最常被漏掉的用例——掩码法天然正确，而「按命中逐个插标签」的写法会输出两对。
4. **重叠出现漏标**：`["aa"]` 与 `"aaaaa"` 中 `find` 必须以 `start + 1` 推进；若写成 `start += len(w)`，只会标记 [0,1] 与 [2,3]，末尾的 `'a'` 漏标，输出 `<b>aaaa</b>a` 而非正确的 `<b>aaaaa</b>`。
5. **指针双自增**：内层 `while` 已经把 $i$ 推过整段，外层若再 `i++` 会跳过一个字符；C++ 的 `for (int i = 0; i < n;)` 里**只能在 `else` 分支自增**。
6. **全部覆盖**：`["a","b","c"]` 与 `"abcabc"` 应输出 `<b>abcabc</b>`，只一对标签；若掩码相邻处被误判成两段，检查是否把「端点接触」当成了间隔。
7. **输入含重复词**：`words` 允许重复（如 `["a","a"]`），置位是幂等的，重复标记不影响结果，不必去重。
