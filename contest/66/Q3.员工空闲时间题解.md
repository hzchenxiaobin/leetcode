# LeetCode 员工空闲时间 题解

## 1. 题目概述

- **标题 / 题号**：员工空闲时间（#759，hard）
- **链接**：https://leetcode.cn/problems/employee-free-time/
- **来源**：LeetCode 第 66 场周赛 Q3
- **难度**：困难
- **标签**：数组、排序、扫描线、堆（优先队列）

**题意**：`schedule` 是 $k$ 名员工的日程表，`schedule[i]` 是第 $i$ 名员工的**忙碌**区间列表，已按起点升序且**彼此不重叠**。求**所有员工同时空闲**的时间段——即时间轴上没有被任何一个忙碌区间覆盖的极大连续区间，要求长度**严格为正**、按起点升序返回，并**丢弃**两端的无限长区间 $(-\infty, L_1)$ 与 $(R_m, +\infty)$。

区间以 `Interval(start, end)` **对象**给出（不是数组：`schedule[0][0].start` 才有意义，`schedule[0][0][0]` 无定义），语义是半开区间 $[\text{start}, \text{end})$：包含 `start`、不含 `end`。

**约束**：

- $1 \le \lvert\text{schedule}\rvert \le 50$，$1 \le \lvert\text{schedule}[i]\rvert \le 50$，故总区间数 $N \le 2500$
- $0 \le \text{start} < \text{end} \le 10^8$
- 每名员工的区间已按 `start` 升序、且两两不重叠
- 答案不含零长度区间（如 $[5,5]$ 不合法）

## 2. 示例

**示例 1**

```text
输入：schedule = [[[1,2],[5,6]], [[1,3]], [[4,10]]]
输出：[[3,4]]
解释：三人的忙碌并集是 [1,3)∪[4,10)，
      共同空闲为 (-∞,1)、[3,4)、[10,+∞)；
      去掉两端无限区间，只剩 [3,4)。
```

**示例 2**

```text
输入：schedule = [[[1,3],[6,7]], [[2,4]], [[2,5],[9,12]]]
输出：[[5,6],[7,9]]
解释：忙碌并集是 [1,5)∪[6,7)∪[9,12)，
      相邻并集段之间的两条缝隙即 [5,6) 与 [7,9)。
```

**示例 3（补充，验证「相接不算空闲」）**

```text
输入：schedule = [[[1,3]], [[3,5]]]
输出：[]
解释：[1,3) 与 [3,5) 首尾相接，并集成 [1,5)，
      两段之间没有正长度缝隙，答案是空数组。
```

## 3. 解题思路

### 3.1 暴力思路

**思路 A（逐时间点扫描）**：取 $\min\text{start}$ 到 $\max\text{end}$，对每个整数时刻检查是否有人忙碌，把连续空闲点拼成区间。值域高达 $10^8$，直接 TLE；而且它只对整数时刻有定义，无法表示实数时间轴。

**思路 B（端点离散化 + 逐段检查）**：把所有 $2N$ 个端点排序去重，得到至多 $2N-1$ 个**基本段**；由于区间边界只在端点处变化，每个基本段内「是否被覆盖」是常量。对每个基本段遍历全部 $N$ 个区间，看是否存在区间完整盖住它，未盖住的就是空闲段：$O(N\log N)$ 排序 + $O(N^2)$ 检查，$N=2500$ 时约 $6\times10^6$ 次判断，能过但很浪费。

瓶颈很清楚：**每个基本段都从头扫一遍所有区间**。而基本段与区间在时间轴上都是有序的，只要沿着时间轴走一遍就够了。

### 3.2 核心观察：共同空闲 = 忙碌并集的补集

![共同空闲是忙碌并集的补集](images/wc66_q3_union_complement.svg)

某时刻 $t$ 是共同空闲 $\iff$ **没有**任何员工在 $t$ 忙碌 $\iff t \notin U$，其中

$$U=\bigcup_{i}\bigcup_{[s,e)\in \text{schedule}[i]}[s,e)$$

是**全体忙碌区间的并集**。于是问题变成纯粹的集合运算：求 $U$ 的补集。

把 $U$ 分解为**极大不相交段**

$$[L_1,R_1),\;[L_2,R_2),\;\dots,\;[L_m,R_m),\qquad R_j < L_{j+1}$$

则 $U$ 的补集是 $(-\infty,L_1)$、$\bigcup_{j}(R_j,L_{j+1})$、$(R_m,+\infty)$ 三部分。题目要的正是中间那批**有限**区间：

$$\text{answer}=\bigl\{\,[R_j,\,L_{j+1})\;\bigm|\;R_j<L_{j+1}\,\bigr\}$$

> 💡 **为什么必须先「合并」再「挖缝」？** 不同员工的区间会互相交错：员工 A 忙 $[1,5)$、员工 B 忙 $[3,8)$。若直接在原始列表里找空隙，会把 A 的 $[5,8)$ 误判成所有人空闲，而 B 明明在忙。合并把这类跨员工重叠吃掉后，段与段之间才是真正的「无人忙碌」。

### 3.3 算法流程：摊平 → 排序 → 一趟扫描

![排序后一趟扫描的流程](images/wc66_q3_merge_flow.svg)

**做法（排序 + 扫描，推荐）**：

1. **摊平**：把所有员工的区间丢进一个列表 `all`，丢弃员工归属——并集与区间来自谁无关。
2. **排序**：按 `(start, end)` 升序排序。
3. **初始化**：`prevEnd = all[0].end`，它表示当前并集段（连通块）的右端点。
4. **扫描**：对 `i = 1 … N-1` 取 `cur = all[i]`：
   - 若 `cur.start > prevEnd`：出现缝隙，输出 `[prevEnd, cur.start)`，并令 `prevEnd = cur.end`；
   - 否则（`cur.start ≤ prevEnd`，重叠或相接）：`prevEnd = max(prevEnd, cur.end)`，并把缝隙「吞掉」。
5. 扫描结束返回结果（不会再输出 $R_m$ 右侧的无限区间）。

**做法二（k 路堆归并，利用「每人已排序」）**：把每人的第一条区间入堆，堆顶是全局起点最小者；弹出一条就交出缝隙判定结果，再把该员工的下一条入堆。即把「对 $N$ 条区间整体排序」换成「对 $k$ 个有序列表做 $k$ 路归并」，时间 $O(N\log k)$、空间 $O(k)$。

### 3.4 示例演算

以示例 2 为例，摊平排序后

$$\text{all}=[1,3),\ [2,4),\ [2,5),\ [6,7),\ [9,12)$$

![示例 2 的扫描演算](images/wc66_q3_walkthrough.svg)

| 步骤 | $cur$ | $cur.\text{start}$ 与 `prevEnd` | 动作 | `prevEnd` | 输出 |
|------|-------|------------------------------|------|-----------|------|
| 初始 | $[1,3)$ | — | 令 `prevEnd = 3` | 3 | — |
| ① | $[2,4)$ | $2 \le 3$ 重叠 | 合并 | 4 | — |
| ② | $[2,5)$ | $2 \le 4$ 重叠 | 合并 | 5 | — |
| ③ | $[6,7)$ | $6 > 5$ 有缝 | 输出缝隙 | 7 | $[5,6)$ |
| ④ | $[9,12)$ | $9 > 7$ 有缝 | 输出缝隙 | 12 | $[7,9)$ |

最终返回 $[[5,6],[7,9]]$。注意第 ③ 步输出后用 `cur.end = 7` 覆盖 `prevEnd`——此时旧值 5 已完成使命。

## 4. 算法细节

1. **摊平后用 `(start, end)` 排序**：同一 `start` 时按 `end` 升序只是让排序结果唯一确定，正确性由合并时的 `max` 保证，与同起点区间的内部顺序无关。
2. **`prevEnd` 初值必须是 `all[0].end`**：若误写成 `0`（或任何小于 `all[0].start` 的哨兵），首段无限区间 $(-\infty,L_1)$ 就会被当成缝隙输出——示例 1 会多出一条 `[0,1)`。
3. **判缝用 `>` 而非 `>=`**：`cur.start == prevEnd` 是「首尾相接」，相接点属于后一段，不是空闲时间；用 `>=` 会输出零长度区间 `[3,3)`，违反「长度严格为正」。
4. **合并分支必须取 `max`**：`prevEnd = max(prevEnd, cur.end)`。若写成 `prevEnd = cur.end`，遇到被完全包含的区间会让右端点**回退**：如 `[[[1,10]],[[2,3],[11,12]]]`，处理 $[2,3)$ 后 `prevEnd` 从 10 掉到 3，真正的缝隙 $[10,11)$ 会被错报成 $[3,11)$。判缝分支则可以直接赋值 `prevEnd = cur.end`，因为此时必有 $cur.\text{end} > cur.\text{start} > prevEnd$。
5. **结果天然有序，无需二次排序**：缝隙按 `cur.start` 递增产生、`prevEnd` 单调不减，`res` 自动按起点升序。
6. **`Interval` 是对象**：C++ 里 `vector<vector<Interval>>` 的元素不能隐式转成 `pair`，输出时用 `push_back(Interval(a, b))` 或 `emplace_back(a, b)`；Python 里要显式构造 `Interval(prevEnd, cur.start)`，不能直接放元组。
7. **堆版的元组格式**：`heapq` 按元组字典序比较，必须存 `(start, pid, idx)` 三元组；`Interval` 对象不可比较，直接入堆会在 `start` 相同时抛 `TypeError`。
8. **`prevEnd` 的语义是「当前连通块最右端点」**，不是「上一条区间的 `end`」——这正是扫描正确性的来源，也是证明里引理 1 的内容。

## 5. 正确性证明

**引理 1（扫描不变量）**：设前 $i$ 条（排序后）区间之并为 $U_i$，则每轮循环结束时 `prevEnd` $=\max U_i$，即已处理区间的并集里最靠右的右端点。

**证明**：$i=1$ 时 `prevEnd` $=$ `all[0].end` $=\max U_1$，成立。设处理第 $i$ 条 $c$ 前有 `prevEnd` $=\max U_{i-1}$。若 $c.\text{start} \le \text{prevEnd}$，则 $c$ 与 $U_{i-1}$ 中右端点所在的连通块相交或相接，$U_i$ 在该处仍连通，$\max U_i = \max(\max U_{i-1},\, c.\text{end})$，与代码取 `max` 一致；若 $c.\text{start} > \text{prevEnd}$，则 $c$ 整体位于 $U_{i-1}$ 右侧且与它不交，$U_i = U_{i-1}\cup c$，$\max U_i = c.\text{end}$，与代码直接赋值一致。由归纳，不变量对每个 $i$ 成立。∎

**引理 2（输出的缝隙确实空闲且长度为正）**：当 $c.\text{start} > \text{prevEnd}$ 时输出的 $[\text{prevEnd}, c.\text{start})$ 内不含任何忙碌区间的点，且长度 $>0$。

**证明**：由引理 1，已处理区间的并 $U_{i-1}\subseteq(-\infty,\text{prevEnd}]$，故不覆盖开区间 $(\text{prevEnd}, c.\text{start})$。对尚未处理的区间 $c'$，排序保证 $c'.\text{start}\ge c.\text{start}$；而 $c'$ 要覆盖 $(\text{prevEnd}, c.\text{start})$ 内某点必须 $c'.\text{start} < c.\text{start}$，矛盾。故所有区间都不覆盖半开区间 $[\text{prevEnd}, c.\text{start})$，长度 $c.\text{start}-\text{prevEnd}>0$ 由判缝条件保证，这段区间内每个时刻都无人忙碌。∎

**引理 3（极大性与完整性）**：输出集合恰为 $U$ 的全部「有限、正长度」极大补区间，且按起点升序。

**证明**：把 $U$ 写成极大不相交段 $[L_1,R_1),\dots,[L_m,R_m)$，$R_j<L_{j+1}$。对 $j$ 归纳：由引理 1，处理完落在 $[L_j,R_j)$ 内的全部区间后 `prevEnd` $=R_j$；排序保证下一条被读到的区间正是起点为 $L_{j+1}$ 的那条（$[L_{j+1},\cdot)$ 中若有更小起点会更早出现），于是 $L_{j+1}>R_j$ 判缝成立并输出 $(R_j,L_{j+1})$，其余区间继续把 `prevEnd` 推进到 $R_{j+1}$。另一方面，扫描以 `all[0].end` 起步、以最后一条区间的 `end` 收尾，从不输出 $(-\infty,L_1)$ 与 $(R_m,+\infty)$；输出顺序随 $j$ 递增。∎

**定理**：算法返回值恰为「所有员工共同空闲的有限正长度区间，按起点升序」。

**证明**：$t$ 是共同空闲 $\iff$ 无人忙碌 $\iff t\notin U$。由引理 3，输出恰为 $U$ 的全部有限正长度补区间且有序；引理 2 保证每段都真正无人忙碌。故结果正确。∎

## 6. 复杂度分析

- **时间**：排序 $O(N\log N)$，扫描 $O(N)$，合计 $O(N\log N)$，其中 $N\le 2500$、$N\log N \approx 3\times10^4$ 次比较，远低于限制。
- **空间**：$O(N)$——摊平列表存放 $N$ 个区间；返回结果按惯例不计入，堆版只需 $O(k)$ 的堆。
- **堆版**：时间 $O(N\log k)$（$k\le 50$ 为员工数），空间 $O(k)$；$N$ 只有 2500，两版的实际耗时都在毫秒级。
- **值域无关**：复杂度只与区间条数有关，与端点大小 $10^8$ 无关——这是离散化/扫描相对于「按时间点开数组」的本质优势。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<Interval> employeeFreeTime(vector<vector<Interval>> schedule) {
        // 1. 摊平所有忙碌区间
        vector<pair<int, int>> all;
        for (const auto& person : schedule)
            for (const auto& iv : person)
                all.emplace_back(iv.start, iv.end);

        // 2. 按起点排序
        sort(all.begin(), all.end());

        // 3. 一趟扫描：合并并集段，遇到缝隙就收集
        vector<Interval> res;
        int prevEnd = all[0].second;
        for (size_t i = 1; i < all.size(); ++i) {
            int s = all[i].first, e = all[i].second;
            if (s > prevEnd) {                 // 有正长度缝隙
                res.emplace_back(prevEnd, s);
                prevEnd = e;
            } else {                           // 重叠或相接，并入同一段
                prevEnd = max(prevEnd, e);
            }
        }
        return res;
    }
};
```

### Python

```python
import heapq


class Solution:
    def employeeFreeTime(self, schedule: '[[Interval]]') -> '[Interval]':
        # k 路归并：每个员工的列表本身已按起点有序，用堆取全局最小起点
        heap = []
        for pid, person in enumerate(schedule):
            if person:
                heapq.heappush(heap, (person[0].start, pid, 0))

        # prev_end 是当前并集段（连通块）的最右端点
        prev_end = schedule[heap[0][1]][heap[0][2]].end
        res = []
        while heap:
            _, pid, idx = heapq.heappop(heap)
            cur = schedule[pid][idx]
            if cur.start > prev_end:           # 有正长度缝隙
                res.append(Interval(prev_end, cur.start))
            prev_end = max(prev_end, cur.end)  # 两个分支统一为取 max
            if idx + 1 < len(schedule[pid]):   # 该作者的下一条继续参与归并
                heapq.heappush(heap, (schedule[pid][idx + 1].start, pid, idx + 1))
        return res
```

> 两个版本对应 3.3 的两种做法：C++ 版对全部区间整体排序 $O(N\log N)$，Python 版对 $k$ 个有序列表做堆归并 $O(N\log k)$。它们共用同一个判定式 `cur.start > prevEnd`，可以互相印证。

## 8. 边界情况与易错点

1. **只有一名员工**：答案是他**自己**相邻区间之间的缝隙，例如 `[[[1,2],[5,6]]]` → `[[2,5]]`，不是空数组；只有他的区间连成一片时才为空。
2. **全部连成一片**：`[[[1,3]],[[3,5]]]` → `[]`。首尾相接的点不属于空闲时间，判缝必须用 `>`。
3. **只有一条区间**：如 `[[[1,10]]]` → `[]`。两侧都是无限区间，必须丢弃；`prevEnd` 的初值与「不输出首尾」这两点共同保证不会误输出 $[0,1)$ 或 $[10,\cdot)$。
4. **零长度区间**：题目明确不返回 $[5,5]$；用 `>` 判缝天然满足，若改成 `>=` 则必须再过滤一遍。
5. **被完全包含的区间**：如 `[[[1,10]],[[2,3],[11,12]]]`（答案是 `[[10,11]]`），合并分支不取 `max` 会让 `prevEnd` 从 10 回退到 3，把缝隙错报成 `[3,11]`。
6. **重复区间**：同一区间出现多次（不同员工），`max` 与 `>` 都能正确处理，不需要去重，也不能因为「相等」就提前退出。
7. **`Interval` 的构造方式**：C++ 的 `emplace_back(a, b)` 依赖 `Interval(int, int)` 构造函数，若题目环境只提供默认构造，需改用 `Interval tmp; tmp.start = a; tmp.end = b; res.push_back(tmp);`；Python 必须显式 `Interval(...)`。
8. **值域与溢出**：端点最大 $10^8$，任何差值也在 $10^8$ 量级，`int` 完全够用；只有把多条区间长度相加时才需要 `long long`（本题不需要）。
