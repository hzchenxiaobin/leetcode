# LeetCode 最小元素各数位之和 题解

## 1. 题目概述

- **标题 / 题号**：最小元素各数位之和（#1085，easy）
- **链接**：https://leetcode.cn/problems/sum-of-digits-in-the-minimum-number/
- **来源**：LeetCode 第 2 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定一个由**正整数**组成的数组 `A`。设 $S$ 为 `A` 中**最小元素**的**各数位之和**。若 $S$ 是**奇数**返回 $0$，否则（偶数）返回 $1$。

**约束**：

- $1 \le A.length \le 100$
- 元素为正整数；英文题面 Note 写作 $1 \le A[i].length \le 100$，但 $A[i]$ 是整数而非字符串，这行是模板笔误，按接口 `integer[]` 理解为普通 32 位正整数即可

> ⚠️ 注意返回值语义是**反直觉**的：数位和为**偶**返回 $1$，为**奇**返回 $0$。这是本题最容易写反的地方。

## 2. 示例

**示例 1**

```text
输入：A = [34,23,1,24,75,33,54,8]
输出：0
解释：最小元素是 1，其数位和 S = 1，为奇数，返回 0。
```

**示例 2**

```text
输入：A = [99,77,33,66,55]
输出：1
解释：最小元素是 33，数位和 S = 3 + 3 = 6，为偶数，返回 1。
```

**示例 3**（自造，验证「数组无序」与「最小值唯一影响答案」）

```text
输入：A = [7, 240, 115]
输出：0
解释：最小元素是 7，S = 7 为奇数，返回 0；240、115 根本不用分解数位。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法有两类：一是**先排序**再取 `A[0]`，$O(n \log n)$；二是对**每个元素**都求一遍数位和再比较，$O(n \cdot d)$。在 $n \le 100$ 的范围下它们当然都能过，但都是绕远路——排序引入了与答案无关的偏序信息，逐个求和则做了大量无用功。正确姿势是抓住问题的形状：**只有最小元素的那一份答案有用**。

### 3.2 核心观察：先一趟求最小值，再只对最小值分解数位

![算法流程：单趟求最小值、数位求和、判奇偶](images/bw2_q1_min_digit_flow.svg)

两个关键观察：

1. **只依赖最小值**：$S$ 完全由 $\min(A)$ 决定，与其余元素无关 → 先用一趟 $O(n)$ 扫描求出 $mn = \min(A)$，再只对这一个数分解数位，其余元素直接无视。
2. **数位分解的标准写法**：对正整数 $v$ 反复「取个位、去个位」：$s \leftarrow s + v \bmod 10$，$v \leftarrow \lfloor v / 10 \rfloor$，直到 $v = 0$。得到的 $s$ 即各数位之和。

最后按题意做**奇偶判定**：$S \bmod 2 = 0$ 返回 $1$，否则返回 $0$。整条链路是「求 min → 数位求和 → 判奇偶」三段流水线，没有分支、没有特例。

### 3.3 算法流程

```text
sumOfDigits(A):
1. mn = A[0]                        # 用首元素初始化，不能用 0
2. for x in A:                       # 单趟扫描
3.     若 x < mn: mn = x
4. S = 0
5. while mn > 0:                     # 数位分解
6.     S += mn % 10
7.     mn = mn // 10
8. 若 S % 2 == 0: 返回 1
9. 否则: 返回 0
```

### 3.4 示例演算

![示例演算：三组输入的完整走查](images/bw2_q1_example_walkthrough.svg)

| 输入 | 最小元素 $mn$ | 数位分解 | $S$ | 奇偶 | 输出 |
|------|--------------|----------|-----|------|------|
| [34,23,1,24,75,33,54,8] | 1 | 1 | 1 | 奇 | 0 |
| [99,77,33,66,55] | 33 | 3、3 | 6 | 偶 | 1 |
| [7, 240, 115] | 7 | 7 | 7 | 奇 | 0 |

注意第三行：240 和 115 的数位和（6、7）与答案毫无关系——**判定只发生在最小值身上**，这正是本做法省时间的原因。

## 4. 算法细节

1. **求最小值用一趟扫描**：初始化 `mn = nums[0]`，再逐个比较。元素全为正且数组非空（$A.length \ge 1$），不需要哨兵值。
2. **数位分解的循环条件是 `mn > 0`**：因为元素是正整数（$\ge 1$），循环至少执行一次；顺带天然兼容了「10 的幂」（如 100 → 1+0+0 = 1）这类易错值。
3. **奇偶判定用 `S % 2`**：写 `S % 2 == 0 ? 1 : 0`，与题面「偶返回 1」严格对应，不要依赖「奇偶性取反」之类的捷径写法（`1 - S % 2` 虽对，但可读性差）。
4. **Python 的另一种数位求和**：`sum(map(int, str(min(nums))))`——先把数转字符串再逐字符转 int 求和，与 `%10 //10` 循环等价，实测两者都对。
5. **为什么不用排序**：$O(n)$ 扫描在时间与空间上都严格优于 $O(n \log n)$ 排序，且代码更短；签到题也应保持「复杂度与问题规模匹配」的习惯。

## 5. 正确性证明

**引理 1（单趟最小值）**：扫描结束后 $mn = \min_{x \in A} x$。

**证明**：对扫描进行归纳。循环不变量：处理完前 $k$ 个元素后，$mn = \min(x_0, \dots, x_{k-1})$。初始 $k=1$ 时 $mn = x_0$ 成立；若处理 $x_k$ 前不变量成立，则当 $x_k \ge mn$ 时 $\min(x_0,\dots,x_k) = mn$ 不变，当 $x_k < mn$ 时执行 `mn = x_k` 后仍等于新的最小值。循环结束即得结论。∎

**引理 2（数位分解）**：对正整数 $v$，其十进制写法为 $d_{k-1} \cdots d_1 d_0$（$d_i \in [0,9]$，$d_{k-1} \ge 1$），则循环 `while v > 0: S += v % 10; v //= 10` 结束时 $S = \sum_{i=0}^{k-1} d_i$，且迭代次数恰为 $k$。

**证明**：第 $t$ 次迭代开始时（从 0 计数），$v_t = \lfloor v / 10^t \rfloor$，于是 $v_t \bmod 10 = d_t$，$v_{t+1} = \lfloor v_t / 10 \rfloor = \lfloor v / 10^{t+1} \rfloor$。当 $t \ge k$ 时 $v_t = 0$ 循环终止，此时累加了 $d_0, d_1, \dots, d_{k-1}$ 各一次，即 $S = \sum_i d_i$。∎

**定理**：算法返回 $1$ 当且仅当 $A$ 的最小元素的各数位之和为偶数，否则返回 $0$。

**证明**：由引理 1，分解数位的对象确为最小元素；由引理 2，得到的 $S$ 是它的各数位之和；最后一步 $S \bmod 2 = 0 \Leftrightarrow S$ 为偶数，按分支分别返回 $1$ 与 $0$，与题意逐句对应。∎

## 6. 复杂度分析

- **时间**：$O(n + d)$。一趟扫描 $O(n)$；数位分解 $O(d)$，$d$ 为最小元素的位数（32 位正整数至多 10 位，故 $d \le 10$）。总体退化为 $O(n)$。
- **空间**：$O(1)$。只用了常数个变量 `mn`、`S`，没有复制数组（排序做法则需 $O(n)$ 或 $O(\log n)$ 的额外开销）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int sumOfDigits(vector<int>& nums) {
        int mn = nums[0];                      // 单趟扫描求最小值
        for (int x : nums)
            if (x < mn) mn = x;
        int s = 0;                             // 数位求和：反复取个位
        while (mn > 0) {
            s += mn % 10;
            mn /= 10;
        }
        return s % 2 == 0 ? 1 : 0;             // S 为偶数返回 1，奇数返回 0
    }
};
```

### Python

```python
class Solution:
    def sumOfDigits(self, nums: list[int]) -> int:
        s = sum(map(int, str(min(nums))))      # 最小元素的各数位之和
        return 1 if s % 2 == 0 else 0           # S 为偶数返回 1，奇数返回 0
```

## 8. 边界情况与易错点

1. **返回值写反是头号坑**：题面是「偶返回 1、奇返回 0」，与直觉的「真/假」相反。写完用示例 1（应为 0）自测一下最稳。
2. **最小值别初始化为 0**：`mn = 0` 会让最小值恒为 0，数位和恒为 0（偶），大面积 WA。用首元素或一个足够大的哨兵初始化。
3. **题面约束的笔误**：英文题面写 $1 \le A[i].length \le 100$，但接口是 `integer[]`，实际数据就是普通 32 位整数。即便按「大数」的极端理解，本做法也只需把求最小值改成数值比较（Python 大整数天然支持；C++ 读入为字符串时按「先比长度、再比字典序」比较），数位求和部分不变。
4. **单元素数组**：`A = [7]` 直接得 $S = 7$ → 0；`A = [8]` → 1。一趟扫描模板天然覆盖。
5. **数组无序**：最小值可能出现在任何位置，别假设排序输入。
6. **正数假设**：元素为正，`while (mn > 0)` 安全；若数据混入 0 或负数（本题为正整数，不会），数位分解要另行处理。
7. **C++ 中 `nums` 保证非空**（$A.length \ge 1$），`nums[0]` 访问合法；如果封装成通用工具函数，建议先判空。
