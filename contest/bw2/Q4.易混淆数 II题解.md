# LeetCode 易混淆数 II 题解

## 1. 题目概述

- **标题 / 题号**：易混淆数 II（#1088，hard）
- **链接**：https://leetcode.cn/problems/confusing-number-ii/
- **来源**：LeetCode 第 2 场双周赛 Q4
- **难度**：困难
- **标签**：数学、回溯、数位 DFS

**题意**：把一个数位的图像旋转 $180°$ 后，$0,1,6,8,9$ 分别变成 $0,1,9,8,6$，而 $2,3,4,5,7$ 旋转后**不合法**。把整个数旋转 $180°$，等价于「**数位倒序 + 逐位映射**」（旋转结果允许出现前导零，如 $10 \to 01 = 1$）。一个**易混淆数**是一个旋转 $180°$ 后得到**每位都合法**、且与原数**不同**的数（旋转结果可以比原数大）。给定正整数 $N$，返回 $[1, N]$ 中易混淆数的个数。

**约束**：

- $1 \le N \le 10^9$

> ⚠️ 两个语义要点：①「不同」按**数值**比较，前导零会消失，所以 $10 \to 1$ 是不同的数、$10$ 算易混淆数；② 旋转后与自身相等的数（如 $1, 8, 11, 69, 88, 96$，下称**中心对称数**）**不计入**答案。

## 2. 示例

**示例 1**

```text
输入：N = 20
输出：6
解释：易混淆数是 [6, 9, 10, 16, 18, 19]。
     6 → 9，9 → 6，10 → 01 = 1，16 → 91，18 → 81，19 → 61。
```

**示例 2**

```text
输入：N = 100
输出：19
解释：易混淆数是 [6,9,10,16,18,19,60,61,66,68,80,81,86,89,
     90,91,98,99,100]。
```

**示例 3**（自造，验证下界）

```text
输入：N = 5
输出：0
解释：1 → 1、8 之外的单数字无候选；1..5 中只有 1 合法但它旋转后不变。
```

## 3. 解题思路

### 3.1 暴力思路

从 $1$ 枚举到 $N$，逐个数检查「数位是否全在 $\{0,1,6,8,9\}$」与「旋转后是否不同」：$O(N \log N) \approx 10^{10}$ 次操作，必然超时。浪费在哪儿？一个 $9$ 位数每位都落在合法集合的概率是 $(5/10)^9 \approx 0.2\%$——**超过 99% 的枚举对象在第一步检查就出局**。正确方向：**不枚举所有数，只枚举可能成为答案的数**，即数位全部合法的候选。

### 3.2 核心观察：只在合法数位上 DFS + 增量维护旋转值 + 剪枝

![数位旋转 180° 的映射表](images/bw2_q4_rotate_mapping.svg)

**观察一（候选刻画）**：易混淆数的必要条件是每个数位 $\in D = \{0, 1, 6, 8, 9\}$（首位非零）。于是把搜索空间从 $[1, N]$ 的所有数收缩到「$D$ 上的字符串」：

$$\#\{\text{候选}\} \le 4(5^0 + 5^1 + \cdots + 5^8) + 1 = 5^9 = 1\,953\,125$$

（长度 $1..9$ 的全量计数加上 $10^9$ 本身）。约 $2 \times 10^6$ 个候选，每个 $O(1)$ 判定即可。

**观察二（旋转的增量维护）**：判定「旋转后是否不同」若每次都反向重算数位是 $O(\log N)$。更好的做法是在 DFS 状态里**随身携带旋转值**：设当前数为 $v$、其旋转值为 $r = rot(v)$、$p = 10^{len(v)}$，向右追加数位 $d$ 得到 $v' = 10v + d$，则

$$rot(v') = map(d) \cdot p + r$$

> 💡 直观理解：向 $v$ 的**右边**追加数位，对**原数**来说是「旧数位集体升一位再加 $d$」（$v' = 10v + d$）；而对**旋转数**来说，新数位 $d$ 经映射后恰好拼在旋转值的**最前面**，旧旋转值的位权一个都不动。两边的更新规则不对称，这正是公式的巧妙之处。

![增量维护旋转值](images/bw2_q4_incremental_rotation.svg)

**观察三（剪枝）**：追加数位只会让数严格变大。于是有两层剪枝：入口处 $v > N$ 直接返回（其后代必然更大）；扩展前若 $v \cdot 10 > N$，则**所有**子节点 $10v + d \ge 10v > N$ 都必然超界，连循环都不必进入。后者把大量「叶子的无效子女调用」也省掉了。

### 3.3 算法流程

![数位 DFS 树与剪枝](images/bw2_q4_dfs_tree.svg)

```text
dfs(v, r, p):                       # 不变量：r = rot(v)，p = 10^len(v)
1. 若 v > N: 返回                    # 剪枝 1：子孙只会更大
2. 若 v != 0 且 r != v: ans += 1     # 旋转后是不同的数 → 易混淆
3. 若 v * 10 > N: 返回               # 剪枝 2：所有子节点必然超界
4. for d in {0, 1, 6, 8, 9}:
5.     若 v == 0 且 d == 0: continue # 首位不为 0
6.     dfs(10v + d, map(d)·p + r, 10p)

confusingNumberII(N): dfs(0, 0, 1)  # 哨兵 v=0 表示尚未放首位
```

哨兵 $v = 0$ 表示「还没有任何数位」，它本身不在 $[1, N]$ 内、也不计数；从它出发的首位枚举 $\{1,6,8,9\}$（跳过 $0$）保证每个数无前导零。

### 3.4 示例演算

以 $N = 20$ 为例，DFS 实际只访问 $9$ 个候选（数位全合法且 $\le 20$）：

| 候选 $v$ | $rot(v)$ | $rot \ne v$? | 说明 |
|----------|----------|--------------|------|
| 1 | 1 | ✗ | 旋转后不变，中心对称数 |
| 6 | 9 | ✓ 计 1 | |
| 8 | 8 | ✗ | 旋转后不变 |
| 9 | 6 | ✓ 计 1 | |
| 10 | 1 | ✓ 计 1 | 前导零消失：$01 = 1$ |
| 11 | 11 | ✗ | 旋转后不变 |
| 16 | 91 | ✓ 计 1 | $map(6) \cdot 10 + 1 = 91$ |
| 18 | 81 | ✓ 计 1 | |
| 19 | 61 | ✓ 计 1 | |

共 $6$ 个，与示例 1 的列表 $\{6,9,10,16,18,19\}$ 完全一致。$6$ 开头的子树（$60,61,66,\dots$）整体 $> 20$ 被剪掉，一次都没生成。

再看 $N = 100$：候选共 $4 + 20 + 1 = 25$ 个（$1$ 位数 $4$ 个、$2$ 位数 $4 \times 5 = 20$ 个、$3$ 位数只有 $100$），其中**中心对称数** $\{1, 8, 11, 69, 88, 96\}$ 共 $6$ 个被剔除，$25 - 6 = 19$，与示例 2 一致。

## 4. 算法细节

1. **状态三元组 $(v, r, p)$**：$v$ 是当前枚举到的数；$r$ 是它的旋转值，由引理 2 的增量公式维护，每步 $O(1)$，全程无需回读 $v$ 的数位；$p$ 始终等于 $10^{len(v)}$。
2. **两处剪枝缺一不可**：入口的 `v > N` 保证不访问、不计数超界候选；扩展前的 `v*10 > N` 保证不为必然超界的子女产生函数调用。实测后者能把 $N = 10^9$ 时的调用量压缩近半（只有 $v \le N/10$ 的节点才继续展开）。
3. **溢出**：$N \le 10^9$，判断 `v * 10 > N` 时 $v \cdot 10$ 可达 $10^{10}$，超出 32 位 `int` 上限（约 $2.1 \times 10^9$），C++ 必须**全程用 `long long`**（本篇代码即如此）；Python 无此问题。
4. **首位非零**：只有哨兵 $v = 0$ 的扩展需要跳过 $d = 0$；一旦放了首位，后续数位可以随意用 $0$（如 $10, 100, 160$）。
5. **$10^9$ 是 10 位数**：路径 $\varnothing \to 1 \to 10 \to 100 \to \cdots \to 10^9$ 会走到第 10 层，且 $10^9$ 本身数位全合法、$rot = 1 \ne 10^9$，**是**易混淆数——别把深度或位数上限定成 9。
6. **对拍验证**：与暴力（枚举 $1..n$ 逐数检查）对 $n = 1..1000$ **全量**一致，另在 $n \in \{5000, 9999, 10^4, 2\times10^4, 67890, 87654, 5\times10^4, 99999, 10^5\}$ 等边界样本一致（C++ 与 Python 两份代码都做）；再用「合法数个数 $-$ 中心对称数个数」的组合计数交叉验证到 $N = 10^9$（两法都给出 $1\,950\,627$）。

## 5. 正确性证明

**引理 1（候选刻画）**：对正整数 $x$，$x$ 是易混淆数，当且仅当 $x$ 的每个数位都属于 $D = \{0,1,6,8,9\}$，且 $rot(x) \ne x$。其中 $rot(x)$ 定义为：把 $x$ 的数位倒序、逐个换成其 $180°$ 映射后，按十进制读出的**数值**（前导零按数值自然消失）。

**证明**：旋转 $x$ 得到的"数"的每个数位恰是 $x$ 的对应数位的映射。若 $x$ 某数位 $d \notin D$，其映射不合法，旋转结果不满足「每位都合法」，$x$ 不是易混淆数。反之，若全部数位 $\in D$，则映射后每位 $\in \{0,1,6,8,9\}$ 合法，旋转结果是一个合法数；再按定义要求它与 $x$ **数值不同**。两条合并即为所述判据。∎

**引理 2（旋转的增量公式）**：设 $v \ge 1$ 的数位为 $d_1 d_2 \cdots d_k$（$d_1$ 为最高位），$p = 10^k$。则

$$rot(10v + d) = map(d) \cdot p + rot(v)$$

**证明**：按位值展开，$v = \sum_{j=1}^{k} d_j \cdot 10^{k-j}$，且 $rot(v) = \sum_{j=1}^{k} map(d_j) \cdot 10^{j-1}$（倒序映射恰让第 $j$ 个数位取得位权 $10^{j-1}$；最高位 $d_1$ 落在个位，最低位 $d_k$ 落在最高位 $10^{k-1}$，此展开式自动处理旋转结果的前导零）。$v' = 10v + d$ 的数位为 $d_1 \cdots d_k d$（长度 $k+1$），于是

$$rot(v') = \sum_{j=1}^{k} map(d_j) \cdot 10^{j-1} + map(d) \cdot 10^{k} = rot(v) + map(d) \cdot p. \qquad \blacksquare$$

（注意旧数位在旋转值中的位权**不**随追加而移动——移动的是原数那边；这正是「原数乘十、旋转值拼头」的不对称性。）

**引理 3（DFS 不变量）**：每次调用 $dfs(v, r, p)$ 都满足：$r = rot(v)$、$p = 10^{len(v)}$、$v$ 的数位全 $\in D$ 且无前导零（哨兵 $v=0$ 除外）。

**证明**：对调用深度归纳。根调用 $dfs(0, 0, 1)$：$len(0) = 0$、$p = 10^0 = 1$、$r = 0$，成立（哨兵无数位，条件为空）。设某调用满足不变量，考察其子女 $dfs(10v+d,\ map(d) \cdot p + r,\ 10p)$：

- **旋转值**：由引理 2，$map(d) \cdot p + r = rot(10v+d)$（$v \ge 1$ 时直接引用；$v = 0$ 时 $10v+d = d$ 单数位，$rot(d) = map(d) = map(d) \cdot 10^0 + 0$，公式同样成立）；
- **位权**：$10p = 10^{len(v)+1} = 10^{len(10v+d)}$；
- **数位集合**：新数位 $d \in D$，旧数位归纳假设 $\in D$；
- **无前导零**：$v = 0$ 时因跳过 $d = 0$，子女 $v' = d \ge 1$ 首位非零；$v \ge 1$ 时子女首位即 $v$ 的首位，非零。

归纳完成。∎

**引理 4（剪枝可靠 + 枚举不重不漏）**：DFS 访问的非哨兵节点集合恰为 $C_N = \{x \ge 1 : x \text{ 的数位全} \in D,\ x \text{ 无前导零}\}$ 中所有 $\le N$ 的元素，且每个恰访问一次。

**证明**：

- **可靠性（剪枝不会误删）**：设 $x \in C_N$、$x \le N$，记 $k = len(x)$。$x$ 的生成路径逐位追加，第 $t$ 个节点 $x_t$ 是 $x$ 的前 $t$ 位构成的数（$1 \le t \le k$），由位值展开 $x = x_t \cdot 10^{k-t} + (\text{后缀}) \ge x_t \cdot 10^{k-t} \ge x_t$（$t = k$ 时取等号），故路径上每个节点都 $\le x \le N$，**入口剪枝**不会截断该路径。再看**扩展剪枝**：直接父节点 $x_{k-1}$ 满足 $x_{k-1} \cdot 10 \le x \le N$；更早的祖先 $x_s$（$s \le k-2$）满足 $x \ge x_s \cdot 10^{k-s} \ge x_s \cdot 100$，于是 $x_s \cdot 10 \le x / 10 \le N$。两个剪枝都不会截断 $x$ 的路径。
- **不重**：正整数的十进制表示（无前导零）唯一，而 DFS 中「节点 $\leftrightarrow$ 从根到它的路径 $\leftrightarrow$ 一个数位串」一一对应，同一 $x$ 只能由唯一路径生成一次。
- **不漏**：任意 $x \in C_N$、$x \le N$，其唯一表示对应的路径如上所示不被剪枝，必被访问。∎

**定理**：`confusingNumberII(N)` 返回 $[1, N]$ 中易混淆数的个数。

**证明**：算法的计数事件是「访问节点 $v \ne 0$ 且 $rot(v) \ne v$」。由引理 3，每个被访问节点的旋转值正确、数位全 $\in D$；由引理 4，被访问的非哨兵节点恰为 $C_N$ 中 $\le N$ 的全部元素且各一次。于是计数条件与引理 1 的判据逐点吻合、求和范围恰为 $[1, N]$，计数不重不漏。∎

## 6. 复杂度分析

- **时间**：$O(|C_N|)$，每个节点 $O(1)$（增量旋转，无回读数位）。$|C_N| \le 5^9 = 1\,953\,125$（$N = 10^9$ 的最坏情形），实测 C++ 约 $10\,\mathrm{ms}$ 内、Python 约 $0.5\,\mathrm{s}$——两级剪枝让「必然超界的子女」一次调用都不产生。
- **空间**：$O(\log_{10} N)$ 的递归栈（深度至多 10 层），加 $O(1)$ 变量。若改为显式栈或迭代展开，空间不变。

## 7. 参考代码

### C++

```cpp
class Solution {
    static constexpr int DS[5] = {0, 1, 6, 8, 9};   // 旋转 180° 后仍合法的数位
    long long N = 0;
    int ans = 0;

    static int rotDigit(int d) { return d == 6 ? 9 : (d == 9 ? 6 : d); }

    // 不变量：r = v 旋转 180° 后的数值，p = 10^(v 的位数)
    void dfs(long long v, long long r, long long p) {
        if (v > N) return;                    // 剪枝：追加数位只会更大，整棵子树剪掉
        if (v != 0 && r != v) ++ans;          // 旋转后是不同的数 → 易混淆数
        if (v * 10 > N) return;               // 所有子节点都必然超界，不必再扩展
        for (int d : DS) {
            if (v == 0 && d == 0) continue;   // 首位不为 0（v==0 表示尚未放首位）
            dfs(v * 10 + d, (long long)rotDigit(d) * p + r, p * 10);
        }
    }

public:
    int confusingNumberII(int n) {
        N = n;
        ans = 0;
        dfs(0, 0, 1);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def confusingNumberII(self, n: int) -> int:
        ROT = {0: 0, 1: 1, 6: 9, 8: 8, 9: 6}    # 数位 → 旋转 180° 后的数位
        ans = 0

        def dfs(v: int, r: int, p: int) -> None:
            # 不变量：r = v 旋转 180° 后的数值，p = 10^(v 的位数)
            nonlocal ans
            if v > n:                            # 剪枝：追加数位只会更大，整棵子树剪掉
                return
            if v != 0 and r != v:               # 旋转后是不同的数 → 易混淆数
                ans += 1
            if v * 10 > n:                      # 所有子节点都必然超界，不必再扩展
                return
            for d, rd in ROT.items():
                if v == 0 and d == 0:           # 首位不为 0（v==0 表示尚未放首位）
                    continue
                dfs(v * 10 + d, rd * p + r, p * 10)

        dfs(0, 0, 1)
        return ans
```

## 8. 边界情况与易错点

1. **旋转的前导零**：$10 \to 01 = 1$、$100 \to 001 = 1$、$160 \to 091 = 91$。判「不同」必须用**数值**比较；若按字符串比较且不剥前导零，会误把「$01$ vs $10$」这类比较做对、却在「是否合法」上纠结——题面的判据只有两条：每位合法（由数位集合保证）且数值不同。
2. **中心对称数是最大陷阱**：$1, 8, 11, 69, 88, 96, 609, \dots$ 旋转后等于自身，**不计入**。忘写 `r != v` 会把这些数全算进去；$N \le 5$ 时答案应为 $0$。
3. **溢出**：`v * 10` 最大 $10^{10}$，C++ 用 `int` 直接溢出成负数，剪枝失效。全流程 `long long`（本篇代码）；另外 `(long long)rotDigit(d) * p` 先转再乘，避免中间乘法用 `int`。
4. **$10^9$ 本身是易混淆数**：它是 10 位数、数位全合法且 $rot = 1$。若把枚举上限定为「9 位数」或把 `p` 溢出保护写错，会恰好丢掉它。
5. **哨兵 $v=0$ 不能计数**：$0 \notin [1, N]$；且从哨兵出发必须跳过 $d=0$，否则 $000\cdots$ 会把同一数以多个带前导零的写法重复枚举。
6. **剪枝的顺序**：`v > N` 的判断必须在**计数之前**（否则超界候选被数进去）；`v*10 > N` 的判断必须在**循环之前**（否则白产生五个注定 `return` 的调用）。
7. **务必对拍**：本篇代码已与暴力枚举在 $n = 1..1000$ 全量、$10^5$ 内多个边界样本逐一对拍一致（C++/Python 双份），并与「合法数个数 $-$ 中心对称数个数」的组合计数在 $N = 10^9$ 处互证（答案 $1\,950\,627$）。数位类题目的判定逻辑分支多，纯靠眼睛检查极不可靠。
