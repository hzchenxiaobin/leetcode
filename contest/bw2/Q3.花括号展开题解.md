# LeetCode 花括号展开 题解

## 1. 题目概述

- **标题 / 题号**：花括号展开（#1087，medium）
- **链接**：https://leetcode.cn/problems/brace-expansion/
- **来源**：LeetCode 第 2 场双周赛 Q3
- **难度**：中等
- **标签**：字符串、回溯、广度优先搜索、排序

**题意**：字符串 `S` 表示一组单词。单词中的每个字母位置有一个或多个**选项**：只有一个选项时直接写该字母；有多个选项时用花括号包裹、逗号分隔，如 `"{a,b,c}"` 表示该位置可选 `a`、`b` 或 `c`。例如 `"{a,b,c}d{e,f}"` 表示单词列表 `["ade","adf","bde","bdf","cde","cdf"]`。请返回所有能形成的单词，**按字典序**排列。

**约束**：

- $1 \le S.length \le 50$
- 花括号**不嵌套**
- 同一对花括号内的字母**互不相同**

## 2. 示例

**示例 1**

```text
输入：S = "{a,b}c{d,e}f"
输出：["acdf","acef","bcdf","bcef"]
解释：4 个位置分别有 2、1、2、1 个选项，共 2×1×2×1 = 4 个单词。
```

**示例 2**

```text
输入：S = "abcd"
输出：["abcd"]
解释：没有花括号，每个位置都只有一个选项，唯一单词就是 S 本身。
```

**示例 3**（题面中的说明示例）

```text
输入：S = "{a,b,c}d{e,f}"
输出：["ade","adf","bde","bdf","cde","cdf"]
```

## 3. 解题思路

### 3.1 暴力思路

直观做法是 **BFS 逐层扩展**：维护「已生成的部分单词列表」，从左到右处理每个位置，把列表中每个部分串与该位置的所有选项做笛卡尔积，得到新列表；处理完全部位置后，把最终列表整体 `sort` 输出。这样做完全正确——输出规模很小（见下），但有两个不优雅之处：一是扩展过程中要同时保存整层所有部分串，空间多耗一个 $O(W \cdot L)$ 量级；二是「生成后再排序」没有利用题目结构——其实只要**组内选项先升序排列**，按 **DFS 先序**生成的序列天然就是字典序，末尾的排序可以整个省掉。

> 💡 **输出规模上界**：一个含 $t$ 个选项的花括号组占 $2t+1$ 个字符、让单词数乘 $t$。效率 $t^{1/(2t+1)}$ 在 $t = 3$ 时最大，故 $|S| \le 50$ 时单词数至多 $3^{\lfloor 50/7 \rfloor} = 3^7 = 2187$ 个——暴力与 DFS 都毫无压力。

### 3.2 核心观察：token 序列 + 组内升序 ⇒ DFS 先序即字典序

![核心观察：先切成 token 序列，每个 token 恰贡献一个字符](images/bw2_q3_tokenize_model.svg)

三个关键观察：

1. **先切分成 token 序列**：一遍扫描 `S`，把每个「单字母」或「花括号组」切成一个 **token** $T_1, \dots, T_L$。每个 token **恰贡献一个字符**，因此所有单词**等长**（长度 = token 数 $L$），且单词总数 = $\prod_i |T_i|$。
2. **递归树结构**：DFS 的第 $k$ 层对应 token $T_{k+1}$ 的选择。从根到叶的一条路径 = 一条选择序列 = 一个单词；题面保证组内互异，因此**不同的选择序列必然产生不同的单词**（见 §5 引理 2），无需去重。
3. **字典序免费获得**：把每个组内选项**升序排序**，DFS 按先序访问；因为所有单词等长，字典序等价于「首个不同位置上比大小」，而先序恰好保证「更小前缀的子树先走完」——生成序列严格递增（见 §5 引理 3），**末尾不需要再排序**。

### 3.3 算法流程

```text
expand(S):
1. tokens ← []；i ← 0
2. while i < |S|:
3.     若 S[i] == '{':                     # 选项组
4.         j ← 从 i 起第一个 '}' 的位置    # 无嵌套 ⇒ 配对唯一
5.         opts ← S[i+1..j-1] 中去掉逗号后的字母
6.         对 opts 升序排序
7.         tokens.append(opts)；i ← j + 1
8.     否则:                               # 单字母 token
9.         tokens.append([S[i]])；i ← i + 1
10. words ← []；cur ← []
11. DFS(k)：                              # 为 tokens[k] 选择一个字符
12.     若 k == L: words.append(cur)；返回
13.     for c in tokens[k]（升序）:
14.         cur.push(c)；DFS(k+1)；cur.pop()
15. 返回 words
```

## 4. 算法细节

1. **配对括号的定位**：`j = s.find('}', i)` 直接找**下一个**右花括号。这一步依赖「不嵌套」约束：若有嵌套，第一个 `'}'` 可能不是当前组的结束（本题不会发生，见 §8）。
2. **组内排序**：`sort(opts.begin(), opts.end())`，这是「生成序 = 字典序」的前提之一；单字母 token 本身天然有序。
3. **复用缓冲区**：`cur` 只做 `push_back`/`pop_back`，一条完整单词只在叶子处拷贝一次进 `words`，总拷贝量为答案总长 $O(W \cdot L)$，没有多余开销。
4. **复杂度匹配**：解析 $O(|S|)$（含组内排序共 $O(|S| \log |S|)$ 量级），DFS 访问的节点数 $\le \sum_i \prod_{j \le i} |T_j|$，叶子即单词，输出本身就要 $O(W \cdot L)$，故整体 $O(|S| + W \cdot L)$。
5. **防御性写法**：如果担心数据不满足「组内互异」，可以在返回前 `sort + unique`；在题面约束成立时它们是空操作（引理 2 保证无重复），加上无害但掩盖了问题的结构。

## 5. 正确性证明

**引理 1（token 划分）**：解析器输出 token 序列 $T_1, \dots, T_L$，满足：「`S` 能形成的单词」恰好等于「在每个 $T_i$ 中选一个字符并按序拼接得到的串」。

**证明**：对 $S$ 从左到右扫描。花括号外任意字符是单选项位置，成为大小为 1 的 token；每个 `'{'` 与其后**第一个** `'}'` 配对——若配对区间内再出现 `'{'`，则与「不嵌套」矛盾，故配对唯一，且括号内恰为题面给定的选项集合（逗号是分隔符）。扫描不重不漏地覆盖 $S$ 的每个字符，且每个 token 与题面定义的「一个位置的选项集合」一一对应；一个合法单词的每个字符恰来自其对应位置的选项，反之每个「逐 token 选一字符」的串都满足题面规则。∎

**引理 2（无重复）**：两条不同的选择序列 $(c_1, \dots, c_L) \ne (c'_1, \dots, c'_L)$ 生成的单词不同。

**证明**：取首个不同位置 $i$：$c_i \ne c'_i$。两条序列在 $T_i$ 中选了**不同的选项**，而同一花括号内字母互异（单字母 token 只有一个选项，不会成为首个不同处），故两单词的第 $i$ 个字符不同，又因两单词等长，它们是不同的串。于是「选择序列 → 单词」是单射，DFS 生成的 $W = \prod_i |T_i|$ 个单词两两不同。∎

**引理 3（先序 = 字典序）**：若每个 token 内部选项升序，则 DFS 先序生成的单词序列按字典序**严格递增**。

**证明**：对 token 数 $L$ 归纳。$L = 0$ 时只有一个空词，平凡成立。设结论对 $L-1$ 成立，考察 $L \ge 1$：DFS 先进入 $T_1$ 的最小选项 $c_1$ 的子树并**完整**遍历，再进入次小 $c_2$ 的子树，依此类推。

- **子树间**：设 $c < c'$ 是 $T_1$ 中两个不同选项，$c$ 子树中任意单词 $u$ 与 $c'$ 子树中任意单词 $v$ 首个不同位置是第 1 位（$c \ne c'$），且 $c < c'$，故 $u < v$；结合 $c_1 < c_2 < \cdots$ 的访问顺序，任意先访问的子树整体小于后访问的子树。
- **子树内**：$c$ 子树中的单词去掉公共首字符 $c$ 后，就是 $T_2, \dots, T_L$（各自升序）上的先序遍历，由归纳假设严格递增。

两部分拼接即得整个序列严格递增。∎

**定理**：`expand` 返回 `S` 能形成的全部单词，按字典序严格递增排列，且无重复。

**证明**：DFS 在每层对当前 token 的**全部**选项逐一递归，故每条选择序列恰被访问一次：由引理 1，所有能形成的单词都被生成（完备性）；由引理 2，生成列表无重复；由引理 3，生成顺序即字典序。返回值与题目要求逐一吻合。∎

## 6. 复杂度分析

- **时间**：解析 $O(|S| \log |S|)$（组内排序主导）；DFS 每个内部节点 $O(1)$、每个叶子拷贝一个长 $L$ 的串，共 $O(W \cdot L)$，其中 $W = \prod |T_i| \le 3^7 = 2187$、$L \le 50$。总时间 $O(|S| \log |S| + W \cdot L)$，在本题约束下不超过 $10^5$ 量级。
- **空间**：递归栈与缓冲区 $O(L)$；输出 $O(W \cdot L)$（不可避免，答案本身）。相比 BFS 版本省去了中间层整层串的 $O(W \cdot L)$ 额外峰值。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<string> blocks;   // 每个 token 的候选字符（组内已升序排序）
    vector<string> words;
    string cur;

    void dfs(int i) {
        if (i == (int)blocks.size()) {
            words.push_back(cur);          // 每个 token 都已选定一个字符
            return;
        }
        for (char c : blocks[i]) {         // 组内升序 ⇒ 生成顺序即字典序
            cur.push_back(c);
            dfs(i + 1);
            cur.pop_back();                // 回溯：撤销选择
        }
    }

public:
    vector<string> expand(string s) {
        blocks.clear();
        words.clear();
        cur.clear();
        int i = 0, n = (int)s.size();
        while (i < n) {
            if (s[i] == '{') {                            // 选项组：截到配对的 '}'
                int j = (int)s.find('}', i);
                string opts;
                for (int k = i + 1; k < j; ++k)
                    if (s[k] != ',') opts.push_back(s[k]);
                sort(opts.begin(), opts.end());           // 组内字符升序
                blocks.push_back(opts);
                i = j + 1;
            } else {                                     // 单字母 token
                blocks.push_back(string(1, s[i]));
                ++i;
            }
        }
        dfs(0);
        return words;
    }
};
```

### Python

```python
class Solution:
    def expand(self, s: str) -> list[str]:
        blocks = []                                      # 每个 token 的候选串（组内已升序）
        i, n = 0, len(s)
        while i < n:
            if s[i] == '{':                              # 选项组：截到配对的 '}'
                j = s.index('}', i)
                blocks.append(''.join(sorted(s[i + 1:j].split(','))))
                i = j + 1
            else:                                        # 单字母 token
                blocks.append(s[i])
                i += 1

        words, cur = [], []

        def dfs(k: int) -> None:
            if k == len(blocks):                          # 每个 token 都已选定一个字符
                words.append(''.join(cur))
                return
            for c in blocks[k]:                           # 组内升序 ⇒ 生成顺序即字典序
                cur.append(c)
                dfs(k + 1)
                cur.pop()                                 # 回溯：撤销选择

        dfs(0)
        return words
```

## 8. 边界情况与易错点

1. **没有花括号**：`"abcd"` 切成 4 个单字母 token，唯一单词就是 `S` 本身；解析循环天然处理，不需要特判。
2. **忘记组内排序**：若选项组按出现顺序枚举而组内乱序（如 `"{b,a}"`），生成序列不再是字典序，必须组内 `sort`，或在末尾对结果整体 `sort` 兜底——两种做法保留其一即可。
3. **「不嵌套」是解析的前提**：`find('}')` 找的是下一个右花括号；一旦允许嵌套（见延伸思考），这个定位就不再正确，必须换递归下降解析。
4. **重复问题被约束排除**：组内互异 ⇒ 引理 2 ⇒ 无需 `unique`。若去掉该约束，不同选择可能拼出相同单词，此时「先序 = 字典序」也会失效（重复词会分处两棵子树），必须整体 `sort` + 去重——这也是别盲目相信「不用排序」的原因，条件成立时才可省。
5. **逗号不是单词字符**：解析时跳过，千万别把逗号当作选项之一拼进单词。
6. **每个 token 恰一个字符**：`"ab"` 是两个 token，不要把连续的裸字母合并成一个 token（合并会让「等长」性质失效，破坏字典序论证）。
7. **C++ 细节**：`string(1, s[i])` 把单个字符构造成字符串；`s.find('}', i)` 返回 `string::size_type`，找不到时是 `string::npos`（合法输入不会发生，但封装成库要判）。
8. **递归深度**：$\le L \le 50$，无爆栈风险。
