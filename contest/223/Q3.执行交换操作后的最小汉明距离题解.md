# LeetCode 执行交换操作后的最小汉明距离 题解

## 1. 题目概述

- **标题 / 题号**：执行交换操作后的最小汉明距离（#1722，medium）
- **链接**：https://leetcode.cn/problems/minimize-hamming-distance-after-swap-operations/
- **来源**：LeetCode 第 223 场周赛 Q3
- **难度**：中等
- **标签**：并查集、哈希表、数组

**题意**：给定长度均为 $n$ 的整数数组 `source` 和 `target`，以及交换列表 `allowedSwaps`，其中 `allowedSwaps[i] = [ai, bi]` 表示可以**交换** `source` 中下标 `ai` 与 `bi` 处的两个元素——每对下标可按**任意顺序**执行**任意多次**。两个等长数组的**汉明距离**定义为元素不同的下标数量。求执行任意多次交换后，`source` 与 `target` 之间的**最小汉明距离**。

**约束**：

- $n = \text{source.length} = \text{target.length}$，$1 \le n \le 10^5$
- $1 \le \text{source}[i], \text{target}[i] \le 10^5$
- $0 \le \text{allowedSwaps.length} \le 10^5$
- $0 \le a_i, b_i \le n - 1$，$a_i \ne b_i$

> 💡 **Q3 的定位**：本场的中档关键题，题眼是识别「交换的传递性」——能互换的下标通过交换边连成**连通分量**，分量内的值可以**任意重排**，于是问题从「搜索最优交换序列」坍缩为「分量内做多重集频率匹配」。这是并查集的招牌应用，与 1202. 交换字符串中的元素 是同一套孪生套路，赛后值得一起沉淀。

## 2. 示例

**示例 1**

```text
输入：source = [1,2,3,4], target = [2,1,4,5], allowedSwaps = [[0,1],[2,3]]
输出：1
解释：交换下标 0、1 得 [2,1,3,4]，再交换下标 2、3 得 [2,1,4,3]，
      与 target = [2,1,4,5] 仅在下标 3 处不同（3 ≠ 5）。
```

**示例 2**

```text
输入：source = [1,2,3,4], target = [1,3,2,4], allowedSwaps = []
输出：2
解释：无交换可用，source 保持原样，与 target 在下标 1（2≠3）、下标 2（3≠2）失配。
```

**示例 3**

```text
输入：source = [5,1,2,4,3], target = [1,5,4,2,3], allowedSwaps = [[0,4],[4,2],[1,3],[1,4]]
输出：0
解释：四条边把全部 5 个下标连成一个分量，source 的值可在分量内任意重排，
      恰好能排成 target。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是把「交换」当作**操作序列**来搜索：尝试所有可能的交换序列，对每条序列执行后计算汉明距离取最小。但同一对下标可以反复交换，序列空间是**无穷的**；即便限制每条边至多使用一次，顺序组合仍是 $m!$（$m$ 为 `allowedSwaps` 长度），$m \le 10^5$ 完全不可行。

退一步用 BFS 搜索「所有可达的 `source` 排列」：状态空间为 $n$ 个下标的全排列 $n!$，$n \le 10^5$ 同样爆炸。

> ⚠️ **症结**：暴力把「交换」当作逐步的操作来模拟，忽略了交换的**传递性**已经把下标划分成若干「内部自由」的连通分量。一旦看出这一结构，就根本不需要搜索任何交换序列——问题直接变成**分组统计**。

### 3.2 核心观察：交换边 → 连通分量 → 分量内自由重排

![核心概念：交换边连成连通分量，分量内的值可任意重排，逐值频率匹配](images/wc223_q3_components_concept.svg)

把每个下标看成一个节点，每条 `allowedSwaps[i] = [a, b]` 看成一条无向边，得到**交换图**。它有两个方向截然相反的结构性质：

**观察一（不变性）**：合法交换只能发生在**有边的下标对**之间，而任何边的两端必属同一连通分量。因此值永远无法跨分量流动——**每个分量内 `source` 值的多重集是交换过程中的不变量**。这给出了答案的下界来源：某个值在某分量内「供需不平衡」的部分，无论怎么换都补不上。

**观察二（自由性）**：分量内连通 ⟹ 沿生成树做「冒泡传值」，分量内的值可以重排成**任意排列**（严格证明见 §5 引理 3）。于是各位置上具体放什么值**不重要**，重要的是每个值**出现的次数**——即分量内 `source` 值的**多重集**。

两个观察合起来，问题坍缩为：对每个连通分量 $C$，把 `source` 在 $C$ 中的值多重集与 `target` 在 $C$ 中的值多重集做**频率匹配**，最大化能对齐的位置数：

$$
\text{match}(C) = \sum_{v} \min\bigl(\text{src\_cnt}_C[v],\; \text{tgt\_cnt}_C[v]\bigr)
$$

分量 $C$ 对汉明距离的贡献为：

$$
\boxed{\;d(C) = |C| - \text{match}(C)\;}
$$

各分量独立叠加，总答案 $= n - \sum_C \text{match}(C)$。

> 💡 **为什么取 min？** 对值 $v$，`source` 侧有 $s_v$ 个、`target` 侧有 $t_v$ 个。一个位置要对齐为 $v$，必须在两侧各消耗一个 $v$，故至多 $\min(s_v, t_v)$ 个位置能对齐（鸽笼）；而由观察二的自由重排性，所有值的 min 配对可以**同时达成**。这正是「多重集交集大小」的定义——匹配数 = 两个多重集的交。

### 3.3 算法流程

![算法流程：并查集建分量，分桶计数，消费式匹配](images/wc223_q3_algorithm_flow.svg)

1. **初始化并查集**：`parent[i] = i`，$n$ 个下标各自为根。
2. **合并**：对每条边 $[a, b]$ 执行 `union(a, b)`，同属一个分量的下标最终共享同一个根。
3. **第一趟分桶计数**：遍历所有下标 $i$，向「根 → 值 → 计数」的桶中累加 `bucket[find(i)][source[i]]`——这一步按根分桶，统计每个分量内 `source` 各值的出现次数。
4. **第二趟消费匹配**：再次遍历所有下标 $i$，若 `bucket[find(i)]` 中 `target[i]` 的计数仍大于 0，就消费一个（计数减一）并 `match++`。
5. **返回** $n - \text{match}$。

第 4 步的**消费式匹配**是实现的精髓：桶里每个计数都是一张「待配对名额」，`target` 侧来一个同值就销一张，消费总额恰等于 $\sum_v \min(s_v, t_v)$——无需显式做完两侧统计再取 min，一趟边读边配。

### 3.4 示例演算

先看示例 3，体会「传递连通」如何把整个数组变成一个自由分量：

![示例演算：四条交换边把 5 个下标连成一个分量，多重集相同，距离为 0](images/wc223_q3_example_walkthrough.svg)

边 $[0,4]$、$[4,2]$ 把 $\{0,2,4\}$ 连在一起，边 $[1,3]$、$[1,4]$ 又把 $\{1,3\}$ 挂进来——最终 $C = \{0,1,2,3,4\}$ 整体连通。分量内 `src` 多重集与 `tgt` 多重集同为 $\{1,2,3,4,5\}$，每个值 $\min(1,1)=1$，$\text{match}=5$，$d = 5-5 = 0$。

再用示例 1 走一遍完整的两分量匹配（对应概念图）：

| 分量 | src 多重集 | tgt 多重集 | 逐值匹配 | match | $d(C)$ |
|------|-----------|-----------|----------|-------|--------|
| $\{0,1\}$ | $\{1, 2\}$ | $\{2, 1\}$ | $v{=}1$: $\min(1,1){=}1$；$v{=}2$: $\min(1,1){=}1$ | 2 | $2-2=0$ |
| $\{2,3\}$ | $\{3, 4\}$ | $\{4, 5\}$ | $v{=}3$: $\min(1,0){=}0$；$v{=}4$: $\min(1,1){=}1$；$v{=}5$: $\min(0,1){=}0$ | 1 | $2-1=1$ |

总匹配数 $= 2 + 1 = 3$，答案 $= 4 - 3 = \mathbf{1}$ ✓。注意分量 $\{2,3\}$ 中 `source` 侧的 $3$ 在 `target` 侧没有需求、`target` 侧的 $5$ 在 `source` 侧不存在——这两个「落单」的值被分量边界锁死、无法跨分量求助。最优重排后 $[4,3]$ 对 $[4,5]$：下标 2 的 $4$ 对齐，下标 3 的 $3 \ne 5$ 失配，$d(\{2,3\}) = |C| - \text{match} = 2 - 1 = 1$ 自动给出正确计数。

## 4. 算法细节

1. **两级哈希「根 → 值 → 计数」**：不需要显式收集每个分量的下标列表再逐组统计，直接以并查集的根作为分组键，`unordered_map<int, unordered_map<int,int>>`（C++）或 `defaultdict(Counter)`（Python）一层到位。所有分量的键值对总数不超过 $n$，空间线性。
2. **消费式匹配与 min 公式的等价性**：第一趟把每个 `source[i]` 的计数 $+1$，第二趟对每个 `target[i]` 尝试 $-1$。对值 $v$，成功消费的次数 $= \min(s_v, t_v)$：前 $\min$ 次消费时计数恒为正，之后（若 $t_v > s_v$）计数归零再也无法消费；若 $s_v > t_v$ 则最多消费 $t_v$ 次。故消费总额 $= \sum_v \min(s_v, t_v)$，与显式取 min 完全等价，且省掉一侧的完整统计。
3. **两趟都必须先 `find(i)` 再归组**：所有 `union` 在两趟遍历之前完成，并查集就此「冻结」——路径压缩只改变树高、不改变「同根」关系，因此两趟中每个下标算出的根必然一致，分桶不会错位。
4. **`find` 用迭代 + 路径压缩**：$10^5$ 个下标被链式 `union` 成长链时，递归版 `find` 的深度可达 $O(n)$，有栈溢出风险；迭代两趟写法（先找根、再沿途挂根）稳且快。单次均摊 $O(\alpha(n))$，$\alpha(n) \le 5$ 视为常数。
5. **重复边无需去重**：`union` 是幂等操作，第二次合并同一分量不再改变结构；边的输入顺序也无关紧要——分量划分只取决于边的集合。
6. **值域 $10^5$、`int` 足够**：全程只有计数与比较，无算术放大，不存在溢出问题。

## 5. 正确性证明

**引理 1**（分量不变性）：无论执行怎样的合法交换序列，每个连通分量内 `source` 值的多重集保持不变。

**证明**：每次合法交换发生在某条边 $(a,b)$ 的两端，而任何边的两端必属同一连通分量。交换是该分量内两个位置上值的重排，不改变该分量的值多重集，更不涉及其它分量的任何位置。对交换次数归纳即得。∎

**引理 2**（送值）：设 $T$ 为某分量的生成树，$u, v$ 是 $T$ 中两点，树上路径为 $x_0 = u, x_1, \dots, x_k = v$，则依次执行 $\text{swap}(x_0,x_1), \text{swap}(x_1,x_2), \dots, \text{swap}(x_{k-1},x_k)$ 后，原 $u$ 处的值到达 $v$，路径上其余位置的值各向 $u$ 的方向前移一格。

**证明**：对 $j$ 归纳：执行前 $j$ 次交换后，原 $u$ 的值位于 $x_j$。$j=0$ 平凡；若原 $u$ 的值在 $x_j$，第 $j+1$ 次交换 $(x_j, x_{j+1})$ 把它送到 $x_{j+1}$。每步交换的两点相邻（树上有边），均为合法操作；其余值的前移是交换的直接结果。∎

**引理 3**（分量内自由重排）：设 $C$ 为任一连通分量，$\pi$ 为 $C$ 上任意排列，则存在有限次合法交换序列，使 $C$ 内 `source` 的值重排为 $\pi$，且分量外的值不动。

**证明**：取 $C$ 的生成树 $T$，对 $|C|$ 归纳。$|C| = 1$ 平凡。$|C| > 1$ 时，取 $T$ 的叶子 $\ell$（目标：$\ell$ 处应放值 $w = \pi(\ell)$ 所对应的当前值）。设值 $w$ 当前位于 $q$，沿 $T$ 上 $q \to \ell$ 的路径用引理 2 送值，$w$ 到达 $\ell$ 且路径上其余值前移一格（若 $q = \ell$ 则跳过）。此后将 $\ell$ 从 $T$ 中删去：$\ell$ 已就位，而剩余操作只在 $T - \ell$ 上进行（仍是树，保持连通），路径不再经过 $\ell$。对剩下的 $|C|-1$ 个位置与限制在 $T-\ell$ 上的排列，由归纳假设可继续实现。所有交换均在 $C$ 内部的树上边执行，分量外不动。∎

**引理 4**（分量内最优对齐）：分量 $C$ 内对齐位置数（满足 $\text{source}[i] = \text{target}[i]$ 的 $i \in C$）的最大值恰为 $\text{match}(C) = \sum_v \min(s_v, t_v)$，其中 $s_v, t_v$ 分别为 `source`、`target` 限制在 $C$ 中时值 $v$ 的出现次数。

**证明**：**上界**：对每个值 $v$，一个位置对齐为 $v$ 需要在 `source` 侧与 `target` 侧各消耗一个 $v$，故对齐为 $v$ 的位置数 $\le \min(s_v, t_v)$；对所有 $v$ 求和即得上界。**可达**：构造排列 $\pi$——对每个 $v$，把 `source` 侧的 $v$ 中任意 $\min(s_v, t_v)$ 个映到 `target` 中 $v$ 所在的（任意）$\min(s_v, t_v)$ 个位置，其余位置任意填充；各值的目标位置集互不相交，$\pi$ 是良定义的排列。由引理 3，$\pi$ 可达，且对齐数恰为 $\sum_v \min(s_v, t_v)$。∎

**定理**：所求最小汉明距离 $= n - \sum_C \text{match}(C)$，其中求和遍历所有连通分量。

**证明**：下标集合被分量划分，各分量的对齐数独立相加。由引理 1，任何可达局面中各分量的值多重集与初始相同，故每个分量的对齐数不超过引理 4 的上界 $\text{match}(C)$，总对齐数 $\le \sum_C \text{match}(C)$，从而任何可达局面的汉明距离 $\ge n - \sum_C \text{match}(C)$。反过来，由引理 3 与引理 4，可构造交换序列使每个分量**同时**达到其上界（各分量使用的交换均在各自内部，互不干扰），总对齐数 $= \sum_C \text{match}(C)$，汉明距离取到该下界。∎

## 6. 复杂度分析

- **时间复杂度**：$O\bigl((n + m) \cdot \alpha(n)\bigr)$。$m$ 条边各做一次 `union`（含两次 `find`），两趟遍历共 $2n$ 次 `find`，均摊每次 $O(\alpha(n))$；哈希分桶与消费匹配合计 $O(n)$。$\alpha(n) \le 5$，实际等同于线性 $O(n + m)$，$n, m \le 10^5$ 下宽裕。
- **空间复杂度**：$O(n)$。`parent` 数组 $O(n)$；两级哈希桶中所有分量的（值, 计数）对总数不超过 $n$。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<int> parent;

    int find(int x) {                       // 迭代 + 路径压缩，防深递归
        int r = x;
        while (parent[r] != r) r = parent[r];
        while (parent[x] != r) {
            int nxt = parent[x];
            parent[x] = r;
            x = nxt;
        }
        return r;
    }

public:
    int minimumHammingDistance(vector<int>& source, vector<int>& target,
                               vector<vector<int>>& allowedSwaps) {
        int n = source.size();
        parent.resize(n);
        iota(parent.begin(), parent.end(), 0);

        for (auto& s : allowedSwaps) {
            parent[find(s[0])] = find(s[1]);        // 合并可交换下标
        }

        // 桶[根][值] = 该分量内尚未配对的 source 值计数
        unordered_map<int, unordered_map<int, int>> bucket;
        for (int i = 0; i < n; ++i) {
            ++bucket[find(i)][source[i]];
        }

        int match = 0;
        for (int i = 0; i < n; ++i) {
            auto& cnt = bucket[find(i)];
            auto it = cnt.find(target[i]);
            if (it != cnt.end() && it->second > 0) { // 本分量还剩同值可配
                --it->second;
                ++match;
            }
        }
        return n - match;
    }
};
```

### Python

```python
class Solution:
    def minimumHammingDistance(self, source: List[int], target: List[int],
                               allowedSwaps: List[List[int]]) -> int:
        n = len(source)
        parent = list(range(n))

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]       # 隔代压缩
                x = parent[x]
            return x

        for a, b in allowedSwaps:
            parent[find(a)] = find(b)

        bucket = defaultdict(Counter)               # 根 → {值: 剩余计数}
        for i, v in enumerate(source):
            bucket[find(i)][v] += 1

        match = 0
        for i, v in enumerate(target):
            c = bucket[find(i)]
            if c[v] > 0:                            # 本分量还剩同值可配
                c[v] -= 1
                match += 1
        return n - match
```

> 💡 两版逻辑逐行对应：**union 建分量 → 第一趟分桶计数 → 第二趟消费匹配 → 返回 $n - \text{match}$**。Python 的 `Counter` 缺键访问返回 0 且不插入，`c[v] > 0` 天然安全；C++ 用迭代器 `find` 而非 `operator[]`，避免为 `target` 独有的值插入空条目。

## 8. 边界情况与易错点

1. **重复值必须计数，不能用 set**：这是本题最典型的 WA 点。例如 `source = [1,1,2]`、`target = [1,2,2]` 且三者全连通时，两侧的值**集合**都是 $\{1,2\}$，但多重集不同——$v{=}1$: $\min(2,1)=1$，$v{=}2$: $\min(1,2)=1$，$\text{match}=2$，正确答案是 $1$ 而非 $0$。频率（多重集）才是对的抽象。
2. **`allowedSwaps` 为空**：每个下标自成大小为 1 的分量，退化为逐位比较（示例 2），算法无需特判自然覆盖。
3. **全部下标连成一个分量**：退化为整体多重集比较（示例 3）。此时也可排序后双指针比较，$O(n \log n)$，但并查集写法更通用。
4. **全连通 ≠ 答案为 0**：即使能任意重排，两侧多重集不同就必有失配（见第 1 条反例）。答案下界由「供需缺口」决定，与连通性无关。
5. **递归 `find` 的栈深**：链式 `union` 可造出深度 $O(n)$ 的链，$n = 10^5$ 时递归 `find` 有爆栈风险，用迭代 + 路径压缩（或按秩合并）更稳。
6. **忘记「任意多次」的含义**：每对下标可重复交换是传递性的来源——若每条边只能用一次，结论不再成立（自由重排性依赖边的可复用）。
7. **第二趟不要边读边 `union`**：必须先完成全部合并再分桶，否则前后两趟的根可能不一致，导致同分量的值被拆进不同的桶。

**延伸思考**：若 `target` 也允许执行同样的交换操作，答案会变吗？——不会。两侧各自分量的值多重集都是交换不变量，$\min(s_v, t_v)$ 的匹配公式对两侧完全对称，答案不变。若进一步把「每次交换有单位代价、求达成该最小距离的最少交换次数」作为进阶，则需要研究分量内重排所需对换次数的下界——经典结论是「元素个数 − 置换的循环个数」，可与图论中欧拉回路/置换环一类的题目对照思考。
