# LeetCode 完成所有工作的最短时间 题解

## 1. 题目概述

- **标题 / 题号**：完成所有工作的最短时间（#1723，hard）
- **链接**：https://leetcode.cn/problems/find-minimum-time-to-finish-all-jobs/
- **来源**：LeetCode 第 223 场周赛 Q4
- **难度**：困难
- **标签**：二分查找、回溯、剪枝、位运算、状态压缩 DP

**题意**：给定整数数组 `jobs`（`jobs[i]` 为完成第 $i$ 项工作所需时间）与工人数 $k$。把**每项工作恰好分配给一位工人**，工人的**工作时间**是其分到的所有工作的时间总和。设计分配方案，使工人的**最大工作时间最小化**，返回这个最小值。

**约束**：

- $1 \le k \le \text{jobs.length} \le 12$
- $1 \le \text{jobs}[i] \le 10^7$

> 💡 **Q4 的定位**：本题是经典的**最小化最大值负载划分**问题（makespan scheduling）。它是 NP-hard 的——不存在多项式精确算法，出题人用 $n \le 12$ 留出了指数级解法的活口。它有两条正解路径：**二分答案 + 回溯剪枝**（实战主流，写好剪枝毫秒级出解）与**状压 DP**（$O(k \cdot 3^n)$ 确定性上界）。这两条路径本身就是周赛困难题的一对标志性套路，赛后值得成对沉淀。

## 2. 示例

**示例 1**

```text
输入：jobs = [3,2,3], k = 3
输出：3
解释：给每位工人分配一项工作，最大工作时间为 3。
```

**示例 2**

```text
输入：jobs = [1,2,4,7,8], k = 2
输出：11
解释：1 号工人分配 1、2、8（工作时间 11）；2 号工人分配 4、7（工作时间 11）。
```

```text
输出：12
解释：sum = 22，⌈22/2⌉ = 11，但 11 取不到：{5,5}=10 与 {4,4,4}=12 是最均衡

```

## 3. 解题思路

### 3.1 暴力思路

最直觉的暴力是**逐个工作选工人**：每个工作有 $k$ 种去向，共 $k^n$ 个方案。$k = n = 12$ 时达 $12^{12} \approx 9 \times 10^{12}$，完全不可行。即使限制「每个工人至少一项工作」并按工人的可交换性去重（方案数为 $k! \cdot S(n,k)$，$S$ 为第二类斯特林数），$k = 6$ 时仍约 $4.8 \times 10^8$ 种，再乘上二分所需的 27 次判定，依然必然超时。

> ⚠️ **症结**：直接枚举「分配方案」是把搜索空间想成了 $k^n$ 这一整块。突破口有两个：一是答案的**值域**很小且**单调**（二分答案）；二是状态可以按「工作集合」压缩（状压 DP）。NP-hard 决定了多项式解法不存在，$n \le 12$ 决定了这两条指数路都走得通。

### 3.2 核心观察：最小化最大值 ⟹ 单调性 ⟹ 二分答案

![核心概念：check(T) 的可行域是后缀，二分找第一个可行值](images/wc223_q4_binary_search_concept.svg)

「最小化最大值」类问题的招牌转化：**不直接构造最优分配，而是改判可行性**。定义

$$
\text{check}(T) = \text{能否把所有工作划成 } k \text{ 份，使每份之和} \le T \text{？}
$$

则所求答案就是**使 check 成立的最小 $T$**。它有两个立即可用的性质：

**观察一（值域）**：答案落在 $[\max(\text{jobs}),\; \sum \text{jobs}]$ 内——任何工人至少要装下最大的一件工作（下界），全给一个人总是可行（上界）。值域宽度 $\le 12 \times 10^7$，逐值扫描不行，但 $\log_2(1.2 \times 10^8) \approx 27$，**二分只需约 27 次判定**。

**观察二（单调性）**：$\text{check}(T)$ 成立 $\Rightarrow$ $\text{check}(T')$ 对一切 $T' \ge T$ 成立——同一份分配方案原样搬过去，最大负载 $\le T \le T'$。可行域是值域上的一条**后缀**，二分找最左边界即可。

下界还可以再强化：由鸽笼原理，某个工人的负载 $\ge \lceil \sum \text{jobs} / k \rceil$，故

$$
lo = \max\Bigl(\max(\text{jobs}),\; \Bigl\lceil \tfrac{\sum \text{jobs}}{k} \Bigr\rceil\Bigr), \qquad hi = \sum \text{jobs}
$$

### 3.3 可行性判定：按「工作」回溯装桶 + 四大剪枝

![check(11) 的回溯判定过程与四大剪枝](images/wc223_q4_backtrack_pruning.svg)

check 是一道「$k$ 份划分」判定题，用回溯求解。框架选**按工作逐个分配**（而不是按工人枚举子集）：`dfs(idx)` 尝试把第 `idx` 个工作放入某个工人，失败则撤销换下一个。骨架如下：

```text
dfs(idx):                       # jobs 已降序排序
    if idx == n: return true    # 全部工作放完
    x = jobs[idx]
    for w in 0..k-1:
        ① 若 load[w] + x > T：continue        # 容量剪枝
        ② 若 w > 0 且 load[w] == load[w-1]：continue   # 同负载剪枝
        load[w] += x
        若 dfs(idx+1) 成功：return true
        load[w] -= x                           # 回溯还原
        ③ 若 load[w] == 0：break               # 空桶剪枝
    return false
```

四条剪枝把最坏 $k^n$ 的搜索树砍到毫秒级：

| 剪枝 | 内容 | 依据 |
|------|------|------|
| **⓪ 预处理** | `jobs` **降序排序**；进入回溯前若 $k \cdot T < \sum \text{jobs}$ 直接 `false` | 大件先放冲突早暴露；鸽笼总容量不足时无解 |
| **① 容量** | `load[w] + x > T` 则跳过工人 $w$ | 该分支必然非法 |
| **② 同负载** | `load[w] == load[w-1]` 则跳过 $w$ | 负载多重集相同的两个分支搜索结果完全相同（工人可交换），前者已失败则后者必失败 |
| **③ 空桶** | 放入**空工人**后仍失败则 `break` | 空桶状态**支配**一切非空桶分支（§5 引理 5） |

> 💡 **为什么按工作而不按工人搜索**：按工人枚举子集的框架天然要去重「工人集合的排列」，剪枝只能按子集哈希做，代价高且易写错；按工作逐个放桶时，剪枝条件全部落在 `load` 数组上，三个整型比较就完成了去重与支配判定，代码短、常数小。

### 3.4 示例演算

![示例演算：二分区间四次收缩锁定答案 11](images/wc223_q4_example_walkthrough.svg)

以示例 2（`jobs = [1,2,4,7,8]`，`k = 2`，降序 `[8,7,4,2,1]`，`sum = 22`，`max = 8`）走一遍完整流程。若采用基础下界 `lo = max = 8`，二分轨迹为：

| 步 | lo | hi | mid | check(mid) | 判定 | 新区间 |
|----|----|----|-----|-----------|------|--------|
| 1 | 8 | 22 | 15 | $\{8,7\}{=}15$，$\{4,2,1\}{=}7$，回溯成功 | ✓ | $[8,15]$ |
| 2 | 8 | 15 | 11 | $\{8,2,1\}{=}11$，$\{7,4\}{=}11$，回溯成功 | ✓ | $[8,11]$ |
| 3 | 8 | 11 | 9 | $2 \times 9 = 18 < 22$，鸽笼直接否 | ✗ | $[10,11]$ |
| 4 | 10 | 11 | 10 | $2 \times 10 = 20 < 22$，鸽笼直接否 | ✗ | $[11,11]$ |

区间收缩到单点，**答案 11**。其中 `check(11)` 的回溯路径正是 §3.3 判定图所示：8 入 $w_1$；7 放不进 $w_1$（15 > 11）入 $w_2$；4 放不进 $w_1$（12 > 11）入 $w_2$ 恰好补满 11；2、1 依次落进 $w_1$ 凑成 11——一次成功，无任何回退。

> 💡 若采用 §3.2 的强化下界 $lo = \max(8, \lceil 22/2 \rceil) = 11$，则 $lo = hi = 11$，**零次判定直接命中**。鸽笼下界在很多「均衡」数据上威力极大。

### 3.5 替代方案：状压 DP（确定性上界）

![状压 DP：按工作集合转移，强制工人 i 拿 lowbit(j)](images/wc223_q4_bitmask_dp.svg)

回溯的复杂度是「最坏指数、实测极快」，若想要**确定性上界**，用 $n \le 12$ 的 bitmask DP。把「哪些工作已分配」压成 $n$ 位比特，定义

$$
dp[i][j] = \text{用前 } i \text{ 个工人完成工作集 } j \text{ 的最小最大负载}
$$

边界 $dp[0][0] = 0$、$dp[0][j \ne 0] = +\infty$。转移时让**工人 $i$ 拿走一个含 $\text{lowbit}(j)$ 的子集 $s$**，其余 $j \setminus s$ 留给前 $i-1$ 个工人：

$$
dp[i][j] = \min_{s \subseteq j,\; s \ni \text{lowbit}(j)} \max\bigl(dp[i-1][\,j \setminus s\,],\; \text{sum}[s]\bigr)
$$

强制 $s$ 含 $\text{lowbit}(j)$ 是**交换论证**的产物：工人之间可整体互换集合，负载多重集与最大值都不变，故总能假设「编号最大的工人拿走编号最小的剩余工作」，枚举量直接减半。答案为 $dp[k][\text{全集}]$。

## 4. 算法细节

1. **二分下界的强化**：$lo$ 同时取 $\max(\text{jobs})$（单件装不下）与 $\lceil \text{sum}/k \rceil$（鸽笼），$hi$ 取 $\text{sum}$（一人全包，天然可行）。闭区间写法 `check(mid) ? hi = mid : lo = mid + 1` 保证终止时 $lo = hi =$ 最小可行值。
2. **降序排序是剪枝的基石**：大件先放，搜索树在浅层就被容量剪枝拦腰截断；升序或乱序时小件先铺满，冲突推迟到最后几层才爆发，搜索树呈「宽爆炸」形态。社区公认的最刁钻用例 `[254,256,256,254,251,256,254,253,255,251,254,255]`（$k=10$）在不排序 / 少剪枝的实现上直接 TLE。
3. **同负载剪枝的实现**：按 $w = 0..k-1$ 顺序枚举时，`load[w] == load[w-1]` 即可跳过——相邻等负载意味着「等价状态刚被试过且失败」。若工人不按序枚举，则需用「本层已试负载集合」去重（更彻底但更慢）。注意 `w > 0` 的保护与「跳过不影响正确性、只是少剪」的语义。
4. **空桶剪枝的判定位点**：必须在**回溯还原之后**判断 `load[w] == 0`（还原后为 0 ⟺ 放入前该工人为空）。它的本质是「空桶支配一切」：当前工作放入空工人给出的是**剩余容量最大**的分支，若它都无解，其他分支必无解。
5. **鸽笼预判写在 check 开头**：$k \cdot T < \text{sum}$ 时无需进入回溯。它对二分的价值是让「不可行侧」的判定几乎免费（本例第 3、4 步都没跑回溯）。
6. **状压 DP 的子集和预处理**：$\text{sum}[j] = \text{sum}[j \oplus \text{lowbit}(j)] + \text{jobs}[\text{lowbit 下标}]$，$O(2^n)$ 一趟递推；含 lowbit 的子集枚举写作「枚举 $\text{rest} = j \oplus \text{lowbit}(j)$ 的全部子集 $t$（模板 `t = (t-1) & rest`），$s = \text{lowbit} \,|\, t$」。
7. **溢出**：$\sum \text{jobs} \le 12 \times 10^7 = 1.2 \times 10^8$，`int` 放得下；但 C++ 中 `limit * k` 可达 $1.44 \times 10^9$，贴近 `int` 上限，用 `long long` 计算更稳。

## 5. 正确性证明

**引理 1**（值域）：最优答案 $\text{ans} \in [\max(\text{jobs}),\; \text{sum}]$。

**证明**：任何方案中，拿到最大工作 $x^* = \max(\text{jobs})$ 的工人负载 $\ge x^*$，故 $\text{ans} \ge x^*$；「全部工作给工人 0」是合法方案，最大负载为 sum，故 $\text{ans} \le \text{sum}$。∎

**引理 2**（单调性）：若 $\text{check}(T)$ 成立，则对一切 $T' \ge T$，$\text{check}(T')$ 成立。

**证明**：设 $T$ 可行方案为 $S_1, \dots, S_k$（各工人工作集），则 $\max_i \text{sum}[S_i] \le T \le T'$，同一组 $S_i$ 即为 $T'$ 的可行方案。∎

**定理 1**（二分正确性）：闭区间二分返回值等于最优答案。

**证明**：由引理 2，check 在整数域上单调。初始 $hi = \text{sum}$ 可行（引理 1），$lo - 1$ 不可行：若 $lo - 1 < \max(\text{jobs})$，最大工作无处可放；若 $lo - 1 < \lceil \text{sum}/k \rceil$，则 $k(lo-1) < \text{sum}$，由鸽笼原理某工人负载 $> lo - 1$。故最小可行值 $\in [lo, hi]$。二分循环保持不变量「$lo - 1$ 不可行且 $hi$ 可行」（每次迭代恰有一侧被更新为 `mid` 或 `mid + 1`，另一侧不变量由 mid 的判定结果传递），终止时 $lo = hi$ 即最小可行值。又「$\text{check}(T)$ 成立 $\iff$ 存在方案使最大负载 $\le T$ $\iff \text{ans} \le T$」，最小可行 $T$ 恰为 $\text{ans}$。∎

**引理 3**（状态对称性）：回溯在某节点能否成功，只取决于当前负载向量的**多重集**与剩余工作序列，与工人的编号无关。

**证明**：可行性等价于「存在剩余工作的一个划分使每桶最终 $\le T$」，该存在性命题只与各桶当前负载的集合（无序）有关；交换任意两个工人的编号并同步替换后续所有决策，得到的是同一个划分存在性问题的同构搜索。∎

**引理 4**（同负载剪枝）：设某节点按 $w = 0, 1, \dots$ 顺序枚举工人且均未成功。若到达 $w$ 时 $\text{load}[w] = \text{load}[w-1]$，则「$x$ 放入 $w$」的分支必失败。

**证明**：考察 $w-1$ 的处理情况（到达 $w$ 意味着无 `break` 发生，$w-1$ 要么被尝试、要么被跳过）：
- $w-1$ 因容量被跳过：$\text{load}[w-1] + x > T$ 且 $\text{load}[w] = \text{load}[w-1]$，则 $w$ 同样超限，结论成立；
- $w-1$ 因同负载被跳过：沿相等负载链回溯到**第一个**负载为该值的工人 $v$（其前驱负载不同，故 $v$ 不可能因同负载被跳过），$v$ 要么因容量被跳过（归结为上一情形），要么被真正尝试且失败；
- $w-1$ 被尝试且失败：放入 $w$ 与放入 $w-1$ 后的负载多重集相同（仅两个等值位置互换），由引理 3，$w$ 的分支同样失败。∎

**引理 5**（空桶支配）：设当前工作 $x$，工人 $w$ 为空（$\text{load}[w] = 0$），工人 $u$ 任意。若「$x$ 放入 $w$」后的状态无解，则「$x$ 放入 $u$」后的状态也无解。

**证明**（模仿论证）：反设放入 $u$ 后存在剩余工作的合法分配 $\sigma$。构造放入 $w$ 后的分配 $\sigma'$：把 $\sigma$ 中分给 $u$ 的剩余工作全部改分给 $w$。工人 $w$ 的最终负载为 $x + \Sigma_u(\sigma)$，其中 $\Sigma_u(\sigma)$ 为 $\sigma$ 分给 $u$ 的剩余工作总和，则

$$
x + \Sigma_u(\sigma) \;\le\; \text{load}[u] + x + \Sigma_u(\sigma) \;=\; u \text{ 在 } \sigma \text{ 下的最终负载} \;\le\; T
$$

其余工人负载不变，$\sigma'$ 合法，与「放入 $w$ 后无解」矛盾。∎

**定理 2**（check 完备性）：带全部剪枝的 `dfs` 返回 true 当且仅当存在合法分配。

**证明**：「返回 true ⟹ 存在合法分配」：dfs 只在每步放置均满足 $\text{load}[w] + x \le T$ 时递进，返回 true 时得到一个每桶 $\le T$ 的完整分配。「存在合法分配 ⟹ 返回 true」：对搜索树归纳。三条剪枝各自不丢失「有解」分支：①剪掉的分支本身非法；②由引理 4，剪掉的分支必然失败；③由引理 5，「放入空工人」失败时其余分支（空工人分支状态全同，非空工人分支被支配）均无解，`break` 安全。故只要有解，未被剪掉的等价分支必然搜到。∎

**引理 6**（lowbit 交换）：把工作集 $j$ 划给 $i$ 个工人的任一最优划分，都可调整为「工人 $i$ 的集合含 $\text{lowbit}(j)$」而不改变最大负载。

**证明**：设最优划分中 $\text{lowbit}(j)$ 所在工人的集合为 $A$，工人 $i$ 的集合为 $B$。交换 $A$ 与 $B$：各工人负载的多重集不变（$A, B$ 作为整体对调），最大负载不变，仍是合法最优划分，且此时工人 $i$ 拿到含 $\text{lowbit}(j)$ 的 $A$。∎

**定理 3**（DP 正确性）：$dp[k][\text{全集}]$ 等于最优答案。

**证明**：对 $i$ 归纳证明 $dp[i][j]$ 为「$j$ 划给 $i$ 个工人（允许空集）」的最小最大负载。$i = 0$ 时仅 $j = \emptyset$ 可划分为 $0$。对 $i \ge 1$：一方面，任取转移候选 $s \ni \text{lowbit}(j)$，由归纳假设 $dp[i-1][j \setminus s]$ 可达，配上工人 $i$ 拿 $s$（负载 $\text{sum}[s]$）得到 $j$ 的一个 $i$ 人划分，故 $dp[i][j] \le \max(dp[i-1][j \setminus s],\, \text{sum}[s])$，对 $s$ 取 min 后仍 $\le$；另一方面，由引理 6，存在最优划分使工人 $i$ 的集合 $s^* \ni \text{lowbit}(j)$，该划分的最大负载 $\ge \max(dp[i-1][j \setminus s^*],\, \text{sum}[s^*]) \ge dp[i][j]$，故 $dp[i][j]$ 不超过最优值。两方向夹逼即得。∎

## 6. 复杂度分析

- **时间复杂度（二分 + 回溯）**：二分至多 $O(\log \sum \text{jobs}) \approx 27$ 次 check。单次 check 的**最坏**复杂度仍是指数级（NP-hard 问题无多项式界），但四大剪枝后 $n \le 12$ 的所有输入实测在毫秒级（含社区最刁钻的 $k=10$ 高重复用例，Python 实测 0.1ms），这是周赛实战的取舍点。
- **空间复杂度（二分 + 回溯）**：$O(n + k)$——`load` 数组与深度为 $n$ 的递归栈，排序原地完成。
- **时间复杂度（状压 DP）**：$O(2^n + k \cdot 3^n)$——子集和预处理 $O(2^n)$；转移枚举「含 lowbit 的子集」，总量 $\sum_j 2^{|j|-1} = 3^n / 2$，共 $k$ 层。$n = 12, k = 12$ 时约 $3.2 \times 10^6$ 次转移，**与数据分布无关的确定性上界**。
- **空间复杂度（状压 DP）**：$O(2^n)$，滚动数组只需相邻两层。

## 7. 参考代码

### C++（二分答案 + 回溯剪枝）

```cpp
class Solution {
    int n, k;
    long long total;
    vector<int> a, load;

    bool dfs(int idx, int limit) {
        if (idx == n) return true;                         // 工作全部放完
        int x = a[idx];
        for (int w = 0; w < k; ++w) {
            if (load[w] + x > limit) continue;             // 剪枝①：容量
            if (w > 0 && load[w] == load[w - 1]) continue; // 剪枝②：同负载等价
            load[w] += x;
            if (dfs(idx + 1, limit)) return true;
            load[w] -= x;                                  // 回溯还原
            if (load[w] == 0) break;                       // 剪枝③：空桶失败即止
        }
        return false;
    }

    bool check(int limit) {
        if ((long long)limit * k < total) return false;    // 剪枝⓪：鸽笼总容量
        fill(load.begin(), load.end(), 0);
        return dfs(0, limit);
    }

public:
    int minimumTimeRequired(vector<int>& jobs, int k) {
        n = jobs.size();
        this->k = k;
        a = jobs;
        sort(a.rbegin(), a.rend());                        // 剪枝⓪：大件优先
        total = accumulate(a.begin(), a.end(), 0LL);
        load.assign(k, 0);

        long long lo = max<long long>(a[0], (total + k - 1) / k); // 单件+鸽笼下界
        long long hi = total;                              // 一人全包，必然可行
        while (lo < hi) {                                  // 闭区间二分
            long long mid = lo + (hi - lo) / 2;
            if (check((int)mid)) hi = mid;
            else lo = mid + 1;
        }
        return (int)lo;
    }
};
```

### Python（二分答案 + 回溯剪枝）

```python
class Solution:
    def minimumTimeRequired(self, jobs: List[int], k: int) -> int:
        jobs.sort(reverse=True)                        # 剪枝⓪：大件优先
        n, total = len(jobs), sum(jobs)
        load = [0] * k

        def dfs(idx: int, limit: int) -> bool:
            if idx == n:                               # 工作全部放完
                return True
            x = jobs[idx]
            for w in range(k):
                if load[w] + x > limit:                # 剪枝①：容量
                    continue
                if w > 0 and load[w] == load[w - 1]:   # 剪枝②：同负载等价
                    continue
                load[w] += x
                if dfs(idx + 1, limit):
                    return True
                load[w] -= x                           # 回溯还原
                if load[w] == 0:                       # 剪枝③：空桶失败即止
                    break
            return False

        def check(limit: int) -> bool:
            if limit * k < total:                      # 剪枝⓪：鸽笼总容量
                return False
            for i in range(k):
                load[i] = 0
            return dfs(0, limit)

        lo = max(jobs[0], (total + k - 1) // k)        # 单件 + 鸽笼下界
        hi = total                                     # 一人全包，必然可行
        while lo < hi:                                 # 闭区间二分
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

### C++（状压 DP）

```cpp
class Solution {
public:
    int minimumTimeRequired(vector<int>& jobs, int k) {
        int n = jobs.size(), full = (1 << n) - 1;
        vector<int> sub(full + 1, 0);                   // 子集和：lowbit 递推
        for (int j = 1; j <= full; ++j) {
            int lb = j & -j;
            sub[j] = sub[j ^ lb] + jobs[__builtin_ctz(j)];
        }
        const int INF = INT_MAX / 2;
        vector<int> dp(full + 1, INF);
        dp[0] = 0;                                      // 第 0 层：dp[0][*]
        for (int i = 1; i <= k; ++i) {
            vector<int> ndp(full + 1, INF);
            ndp[0] = 0;
            for (int j = 1; j <= full; ++j) {
                int lb = j & -j, rest = j ^ lb;
                int best = INF;
                for (int t = rest;; t = (t - 1) & rest) {  // 枚举 rest 的子集 t
                    int s = lb | t;                        // s 必含 lowbit(j)
                    best = min(best, max(dp[j ^ s], sub[s]));
                    if (t == 0) break;
                }
                ndp[j] = best;
            }
            dp = move(ndp);
        }
        return dp[full];
    }
};
```

### Python（状压 DP）

```python
class Solution:
    def minimumTimeRequired(self, jobs: List[int], k: int) -> int:
        n = len(jobs)
        full = (1 << n) - 1
        sub = [0] * (full + 1)                          # 子集和：lowbit 递推
        for j in range(1, full + 1):
            lb = j & -j
            sub[j] = sub[j ^ lb] + jobs[lb.bit_length() - 1]

        INF = float('inf')
        dp = [0] + [INF] * full                         # 第 0 层：dp[0][*]
        for _ in range(k):
            ndp = [0] + [INF] * full
            for j in range(1, full + 1):
                lb = j & -j
                rest = j ^ lb
                best = INF
                t = rest
                while True:                             # 枚举 rest 的子集 t
                    s = lb | t                          # s 必含 lowbit(j)
                    cand = max(dp[j ^ s], sub[s])
                    if cand < best:
                        best = cand
                    if t == 0:
                        break
                    t = (t - 1) & rest
                ndp[j] = best
            dp = ndp
        return dp[full]
```

> 💡 两套实现逐行对应同一套逻辑：**降序 → 鸽笼预判 → 逐工作装桶（三剪枝）→ 闭区间二分**；DP 版则是 **lowbit 递推子集和 → 强制含 lowbit 的子集枚举 → 滚动转移**。实战优先写二分 + 回溯（代码短、跑得快），面试或要求确定性复杂度时拿出状压 DP。

## 8. 边界情况与易错点

1. **答案 ≠ $\lceil \text{sum}/k \rceil$**：鸽笼只是**下界**。补充示例 `[5,5,4,4,4]`、`k=2` 中 $\lceil 22/2 \rceil = 11$ 取不到，答案是 12。把二分下界当答案返回是本题最典型的 WA。
2. **$k = 1$ 与 $k = n$ 退化**：答案分别为 sum 与 max，二分写法无需特判自然覆盖（后者如 `[3,2,3], k=3`：$lo = \max(3, \lceil 8/3 \rceil) = 3 = hi$，零次 check 直接返回）。
3. **忘记降序排序**：剪枝威力大打折扣，高重复值用例（如 `[254,256,256,...]`、$k=10$）极易 TLE——这也是区分「能过」与「超时」的分水岭。
4. **`limit * k` 溢出**：C++ 中可达 $1.44 \times 10^9$，贴近 `int` 上限，务必转 `long long`；Python 无此忧。
5. **边界比较用 $\le$ 不是 $<$**：`load[w] + x == T` 是允许放置的（负载恰好等于上限不违规），写成 `>=` 会漏解。
6. **同负载剪枝的顺序依赖**：`load[w] == load[w-1]` 的写法依赖「按序枚举工人」；若换成乱序或优先队列枚举，必须改用「本层已试负载集合」去重，否则剪错分支。
7. **空桶剪枝的判断时机**：必须在回溯还原 `load[w] -= x` **之后**判 `load[w] == 0`（还原后为 0 才说明放入前是空桶），写在还原前会把非空桶误判成空桶。
8. **回溯忘记还原**：`load[w] -= x` 漏写会导致后续分支的负载被污染，答案随机性错误。
9. **DP 细节**：子集和下标用 `__builtin_ctz(j)`（或 Python 的 `lb.bit_length() - 1`）；`INF` 取 `INT_MAX / 2` 防比较溢出；含 lowbit 的子集枚举要枚举 `rest` 的子集再或上 lowbit，直接枚举 $j$ 的全部子集会多算一倍且需另行保证覆盖。
