# LeetCode 通过连接另一个数组的子数组得到一个数组 题解

## 1. 题目概述

- **标题 / 题号**：通过连接另一个数组的子数组得到一个数组（#1764，medium）
- **链接**：https://leetcode.cn/problems/form-array-by-concatenating-subarrays-of-another-array/
- **来源**：LeetCode 第 46 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、双指针、字符串匹配、KMP 算法

**题意**：给定长度为 $n$ 的二维数组 `groups` 与数组 `nums`。问能否从 `nums` 中选出 $n$ 个**互不相交**的子数组（区间不重叠），使第 $i$ 个子数组与 `groups[i]` **完全相同**，且这些子数组在 `nums` 中出现的先后顺序与 `groups` 的下标顺序一致。能则返回 `true`，否则 `false`。

**约束**：

- `groups.length == n`
- $1 \le n \le 10^3$
- $1 \le groups[i].length$ 且 $groups[i].length$ 的总和 $\le 10^3$
- $1 \le nums.length \le 10^3$
- $-10^7 \le groups[i][j], nums[k] \le 10^7$

## 2. 示例

**示例 1**

```text
输入：groups = [[1,-1,-1],[3,-2,0]], nums = [1,-1,0,1,-1,-1,3,-2,0]
输出：true
解释：第 0 个子数组 [1,-1,-1] 出现在下标 3..5，第 1 个 [3,-2,0] 出现在 6..8，
     顺序一致且不相交。
```

**示例 2**

```text
输入：groups = [[10,-2],[1,2,3,4]], nums = [1,2,3,4,10,-2]
输出：false
解释：[10,-2] 必须出现在 [1,2,3,4] 之前，但 nums 中顺序相反。
```

**示例 3**

```text
输入：groups = [[1,2,3],[3,4]], nums = [7,7,1,2,3,4,7,7]
输出：false
解释：[1,2,3] 只能匹配下标 2..4，[3,4] 只能匹配 3..4，两者共享下标 4，不相交的要求被破坏。
```

## 3. 解题思路

### 3.1 暴力思路

对 `groups[0]` 枚举全部可行起点递归匹配 `groups[1]`，再枚举 `groups[1]` 的全部起点……状态为「已匹配到第 $gi$ 组、消耗到 `nums` 下标 $k$」，记忆化后是 $O(m \cdot n)$ 个状态、每状态 $O(n \cdot L)$ 转移。本题规模下完全可过，但代码量偏大；更关键的是，这个搜索里藏着一条**不必回头的贪心**。

### 3.2 核心观察：能匹配就取最早出现，给后续留最长剩余

![贪心：最早匹配留下最长的剩余后缀](images/bw46_q2_greedy_earliest.svg)

直觉：匹配 `groups[i]` 时，如果在剩余部分里它出现多次，**取最早的那次**。越早匹配完，`nums` 剩下的后缀越长，后续 `groups[i+1..]` 的可选空间严格更大——「剩余空间」是唯一的资源，早点消耗它没有任何好处。

形式化：设某个可行方案把 `groups[i]` 放在起点 $p$，而贪心放在更早的 $p' \le p$。那么贪心匹配完后的可用区间 $[p' + |g_i|, m)$ **包含**方案匹配完后的可用区间 $[p + |g_i|, m)$。后续每一组照此传递「剩余区间只增不减」的不变量——方案能继续匹配，贪心必然也能（在更长的剩余里逐组取最早出现即可，归纳即得）。

> ⚠️ 两个细节：① 相邻子数组可以**紧贴**（上一组的结尾正好是下一组的开头），不要求中间有空隙；② 「不相交」按**下标**判断，示例 3 中两组都想用下标 4，即使值对得上也不行。

### 3.3 算法流程：单指针 + 局部匹配

```text
k = 0                        # nums 中下一个可用下标
for g in groups:
    L = |g|, found = false
    while k + L <= m:        # 剩余区间放得下 g 才有戏
        若 nums[k .. k+L) == g:  found = true; break
        k += 1               # 失配：起点右移一格
    若 not found: return false
    k += L                   # 消耗掉这段子数组
return true
```

`k` 是**全局单调指针**：外层逐组推进、内层逐起点推进，`k` 从不回退——这就是贪心「不回头」的代码形态。

### 3.4 示例演算

![示例 1 与示例 3 的走查](images/bw46_q2_walkthrough.svg)

**示例 1**：`groups = [[1,-1,-1],[3,-2,0]]`。匹配第 0 组：$k = 0$ 时 `nums[0..3) = [1,-1,0] ≠ [1,-1,-1]`，$k = 1$ 时 `[−1,0,1]` 不符，$k = 2$ 时 `[0,1,−1]` 不符，$k = 3$ 时 `[1,-1,-1]` ✓，$k \to 6$。匹配第 1 组：$k = 6$ 处 `[3,-2,0]` ✓，$k \to 9 = m$。全部匹配，返回 `true`。

**示例 3**：`groups = [[1,2,3],[3,4]]`，`nums = [7,7,1,2,3,4,7,7]`。第 0 组在 $k = 2$ 匹配（`[1,2,3]`），$k \to 5$；第 1 组 `[3,4]` 从 $k = 5$ 起：`[4,7]`、`[7,7]` 皆不符且 $k + 2 > m$，返回 `false`。两组「共享下标 4」的非法方案在贪心里被自然排除——贪心永远从上一个匹配之后开始找。

## 4. 算法细节

1. **失配只前进一格**：起点 $k$ 失配后改为 $k+1$（而不是跳到「失配位置的下一个」），因为 `g` 可能从任何位置开始；这是朴素串匹配的正确写法。复杂度每格至多比较 $O(L)$ 次，总量 $O((\text{总失配数} + \text{组数}) \cdot L)$。
2. **越界判定的写法**：`while k + L <= m` 保证切片合法；Python 直接用切片 `nums[k:k+L] == g` 比较，注意切片越界不报错但结果必不等长，仍会正确判 `false`（配合 `while` 的边界，稳妥）。
3. **紧贴允许**：成功匹配后 `k += L`，下一组从紧贴的位置开始找也合法——不要在 `k += L` 后再额外 `+1`。
4. **贪心不需要回溯的完整理由**：见 §5 定理。比赛时若没时间写证明，用「小规模穷举对拍」兜底是最实际的保险。
5. **KMP 加速（可选）**：把每组 `g` 当模式串对 `nums` 做一次 KMP 匹配，找到第一个出现位置后令 `k` 跳到匹配尾，总时间 $O(n + \sum|g_i|)$，线性。本题 $10^3$ 规模用朴素比较足够。

## 5. 正确性证明

**引理 1（可行方案的单调替换）**：设存在可行方案 $P$，第 $i$ 组放在起点 $p_i$，即对每个 $i$ 有 $p_i + |g_i| \le p_{i+1}$（相邻不相交、顺序递增）且 `nums[p_i .. p_i+|g_i|) == g_i`。若贪心把前 $i$ 组匹配在起点 $q_0, \dots, q_{i-1}$ 且满足 $q_j \le p_j$（$\forall j < i$），则贪心当前可用起点 $k_i = q_{i-1} + |g_{i-1}| \le p_{i-1} + |g_{i-1}| \le p_i$。

**证明**：对 $j$ 归纳即得（相邻不等式链直接相加）。含义：贪心匹配到第 $i$ 组时，方案 $P$ 为第 $i$ 组选的起点 $p_i$ 仍在可用区间内。∎

**引理 2（最早出现的存在性）**：若存在合法起点 $p \ge k$ 使 `nums[p..p+L) == g`，则贪心从 $k$ 起第一次命中位置 $q = \min\{p' \ge k : nums[p'..p'+L) == g\}$ 存在，且 $q \le p$，匹配后 $q + L \le p + L \le m$。

**证明**：合法起点集合非空，最小元存在；$q \le p$ 由最小性，$q \ge k$ 由搜索范围。∎

**定理（贪心正确性）**：贪心返回 `true` $\iff$ 存在可行方案。

**证明**：（$\Leftarrow$）设 $P$ 为可行方案。对组数 $i$ 归纳：设贪心已正确匹配前 $i$ 组且 $q_j \le p_j$（$j < i$，归纳基：$i = 0$ 时空）。由引理 1，$k_i \le p_i$，即方案 $P$ 给第 $i$ 组的起点落在贪心的可用区间内；由引理 2，贪心能在 $q_i \le p_i$ 处匹配第 $i$ 组，且匹配后消耗下界 $q_i + |g_i| \le p_i + |g_i| \le p_{i+1}$（用方案的下一组起点）——归纳条件保持。于是贪心能匹配完所有 $n$ 组，返回 `true`。
（$\Rightarrow$）贪心本身就是按组合法匹配的构造过程：每一步要么在可用区间内找到出现（合法且消耗），要么返回 `false`。它返回 `true` 时产生的正是一组「顺序一致、互不相交、逐组相等」的子数组，即可行方案。∎

**推论（复杂度）**：外层指针 $k$ 单调不减；内层每次失配 $k$ 加一，成功匹配比较 $O(L)$。总计失配次数 $\le m$，比较成本 $O(L \cdot m)$，其中 $L \le \max |g_i|$；本题 $\le 10^3 \times 10^3 = 10^6$ 量级，绰绰有余。

## 6. 复杂度分析

- **时间**：$O(m \cdot L + \sum |g_i|)$，$L$ 为最大组长度。每次失配把全局起点 $k$ 推进 $1$、代价 $O(L)$；每组成功匹配一次代价 $O(|g_i|)$。本题数据下上界约 $10^6$ 次整数比较。
- **空间**：$O(1)$ 额外。只维护指针与比较下标；Python 切片比较产生临时列表，最坏 $O(L)$，可改用逐位比较压到常数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canChoose(vector<vector<int>>& groups, vector<int>& nums) {
        int m = (int)nums.size(), k = 0;
        for (const vector<int>& g : groups) {
            int len = (int)g.size();
            bool found = false;
            for (; k + len <= m; ++k) {             // 在剩余部分找 g 的最早出现
                int t = 0;
                while (t < len && nums[k + t] == g[t]) ++t;
                if (t == len) { found = true; break; }
            }
            if (!found) return false;
            k += len;                               // 跳过已使用的子数组
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canChoose(self, groups: list[list[int]], nums: list[int]) -> bool:
        k, m = 0, len(nums)
        for g in groups:
            L = len(g)
            while k + L <= m and nums[k:k + L] != g:
                k += 1                          # 尝试下一个起点
            if k + L > m:                       # 剩余部分放不下 g
                return False
            k += L                              # 消耗这一段子数组
        return True
```

> 💡 两份代码均通过官方 3 组示例，并与「枚举每组全部可行起点 + 记忆化搜索」的不依赖贪心的穷举实现随机对拍 250 组（含把组拷贝进 `nums` 制造多解、重叠陷阱、顺序陷阱），结果全部一致。

## 8. 边界情况与易错点

1. **相邻子数组可以紧贴**：匹配后 `k += len` 即可，误加 `+1` 会把「无缝衔接」的合法情形判成 `false`。
2. **重叠即非法**（示例 3）：两组不能共享同一下标。贪心从上一组结束处开始找，天然规避；但若手滑把匹配起点回退（例如每组都从 0 重找），就会破坏不相交性。
3. **顺序约束**（示例 2）：即使两组各自都能在 `nums` 中找到，出现先后与 `groups` 不符也是 `false`——单指针天然保序，回溯版搜索则要小心别让后续组「越过」前面组的位置。
4. **剩余长度不足**：`k + len(g) > m` 时立刻失败，别让切片比较偷偷越界（C++ 手写下标前必须判）。
5. **负数元素**：值域含 $-10^7$，不要用「把元素当字符拼成串」的野路子（`-` 与分隔符会打架），直接整数值比较。
6. **$n = 1$**：单组匹配即答案；「最早出现」的贪心在单组时退化为朴素的子串查找。
