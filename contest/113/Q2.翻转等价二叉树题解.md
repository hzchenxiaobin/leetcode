# LeetCode 翻转等价二叉树 题解

## 1. 题目概述

- **标题 / 题号**：翻转等价二叉树（#951，medium）
- **链接**：https://leetcode.cn/problems/flip-equivalent-binary-trees/
- **来源**：LeetCode 第 113 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、二叉树

**题意**：**翻转操作**指选中一个节点，交换它的左右子树。若经过若干次翻转能使树 $X$ 与树 $Y$ **完全相同**（结构 + 值），则称 $X$ 与 $Y$ **翻转等价**。给定两棵树的根 `root1`、`root2`，判断是否翻转等价。

**约束**：

- 每棵树节点数在 $[0, 100]$ 内
- 每棵树内每个值**唯一**，范围 $[0, 99]$

## 2. 示例

**示例 1**

```text
输入：root1 = [1,2,3,4,5,6,null,null,null,7,8]
     root2 = [1,3,2,null,6,4,5,null,null,null,null,8,7]
输出：true
解释：翻转值 1、3、5 三个节点的左右子树后，两棵树完全一致。
```

**示例 2**

```text
输入：root1 = [], root2 = []
输出：true
解释：两棵空树等价。
```

**示例 3**

```text
输入：root1 = [], root2 = [1]
输出：false
解释：一空一非空，必然不等价。
```

**示例 4（补充，单节点相同）**

```text
输入：root1 = [1], root2 = [1]
输出：true
解释：没有孩子可翻，值相同即等价。
```

## 3. 解题思路

### 3.1 暴力思路

一种思路是：枚举每棵树的所有翻转组合（每个节点翻或不翻，共 $2^{n}$ 种），把它们全部"物化"成树，再看两棵树的集合是否有交集。$n = 100$ 时 $2^{100}$ 不可行。

另一种思路是**层序数组直接比较**——这更常见也更容易错：翻转会改变层序数组里的排列顺序，即使两棵树等价，层序数组也可能完全不同（示例 1 的两棵树层序就不同）。所以"数组相同"既不充分也不必要。

### 3.2 核心观察：每层只有"对调"或"不对调"两种可能

![翻转等价：每个节点的左右孩子可以互换](images/wc113_q2_flip_equiv.svg)

看两个节点的匹配：若 `root1` 的值为 $v$、`root2` 的值也是 $v$，那么它们的子树只有两种对应方式：

- **不交换**：`root1.left ↔ root2.left`，`root1.right ↔ root2.right`；
- **交换**：`root1.left ↔ root2.right`，`root1.right ↔ root2.left`。

因为翻转操作**只改变左右顺序、不改变孩子集合**，所以"$root1$ 的孩子集合 = $root2$ 的孩子集合"是必要条件，而上面的两种对应方式恰好穷尽了所有可能。

于是判定变成递归：

```
flipEquiv(a, b) =
    都为 null            → true
    一个为 null          → false
    a.val != b.val       → false
    (不交换 && 两边都等价) || (交换 && 两边都等价)
```

**关键点**：交换分支里四个孩子要**交叉**配对（`a.left↔b.right`、`a.right↔b.left`），这正是"翻转"的语义；两条分支都要试，因为不确定这个节点到底翻没翻。

### 3.3 算法流程

![每层只有两种匹配方式](images/wc113_q2_recursion.svg)

```text
1. 若两节点都为空 → 返回 true
2. 若恰有一个为空 → 返回 false
3. 若两节点的值不同 → 返回 false
4. 返回：
      (flipEquiv(a.left, b.left)  && flipEquiv(a.right, b.right))
   || (flipEquiv(a.left, b.right) && flipEquiv(a.right, b.left))
```

递归出口与"值判定"都必须放在最前面，否则会访问空指针。

### 3.4 示例演算

以示例 1 的两棵树为例（只画关键层）：

| 层 | 树 1 | 树 2 | 匹配方式 |
|----|------|------|---------|
| 根 | 1（左 2、右 3） | 1（左 3、右 2） | **交换**：2↔2 走右边，3↔3 走左边 |
| 值 2 | 左 4、右 5 | 左 6、右 4 | 交换：4↔4 对应右，5↔6 对应左 |
| 值 3 | 左 6、右 null | 左 5、右 null | 不交换：6↔6 走右边 |
| 值 5 | 左 7、右 8 | 左 8、右 7 | **交换** ✓ |

每一层都能找到合适的对应方式，最终所有叶子都成对匹配，返回 `true`。示例 3 中一边为空一边非空，在第 2 步直接返回 `false`。

## 4. 算法细节

1. **判空顺序**：先判"都为空"，再判"恰有一个为空"，最后判值——这个顺序保证不会解引用空指针，也能正确返回 `true`（两空树等价）。
2. **短路求值**：`||` 与 `&&` 的短路让第一个分支失败时立即尝试第二个，且能提前剪枝（值不同直接失败）。
3. **交叉匹配写对**：交换分支必须是 `(a.left, b.right)` 与 `(a.right, b.left)`，写成 `(a.left, b.left)` 就完全失去意义。
4. **值唯一是便利条件**：题面保证值唯一，所以"值相同"就确定了节点配对，不需要按值查表。若值可重复，需额外按"多重集"匹配，问题会难很多。
5. **递归深度**：节点数 $\le 100$，最坏链状深度 100，不会爆栈；若放宽到 $10^5$ 需改迭代（用栈存 `(a, b)` 对）。
6. **迭代等价写法**：用一个栈存待比较的节点对，弹出时按上面两条分支判断；先尝试不交换，再尝试交换。写起来比递归长，但没有栈深风险。
7. **规范形（canonical form）视角**：把每个节点表示成 `(val, sorted([canon(left), canon(right)]))`，则"翻转等价 ⟺ 规范形相同"。这是判断"树的同构类"的通用技巧，见下图。

## 5. 正确性证明

记 $T(x)$ 为以 $x$ 为根的树，$\text{flip}(a,b)$ 表示"$a$ 与 $b$ 翻转等价"。

**引理 1（孩子集合不变式）**：翻转操作不改变任何节点的**孩子值多重集**，也不改变节点总数与每个节点值的出现次数。

**证明**：翻转只交换某节点的左右指针，该节点的孩子集合（无序）不变；其余节点的结构未被修改。故每个节点的孩子值集合、以及整棵树的值多重集都不变。∎

**引理 2（两种对应方式穷尽）**：若 $\text{flip}(a,b)$ 且 $a.val = b.val$，则要么「$a.left$ 与 $b.left$ 等价 且 $a.right$ 与 $b.right$ 等价」，要么「$a.left$ 与 $b.right$ 等价 且 $a.right$ 与 $b.left$ 等价」。

**证明**：设把 $a$ 经过若干翻转得到 $b$。考虑对根节点是否执行翻转：若未翻转，则 $a$ 的左子树最终成为 $b$ 的左子树、右对右；若翻转了，则左变右、右变左。子树内部的翻转不影响"哪个子树落到左边"这一事实。因此只有这两种对应。∎

**引理 3（递归充分）**：若上述两种对应之一成立（即两侧子树分别翻转等价），则 $\text{flip}(a,b)$。

**证明**：不妨设「$a.left \sim b.left$、$a.right \sim b.right$」（$\sim$ 表示翻转等价）。由定义，$a.left$ 经若干翻转得到 $b.left$、$a.right$ 同理得到 $b.right$；这些翻转都不涉及根，依次执行后 $a$ 的左、右子树分别等于 $b$ 的左右子树，且根的值为 $a.val=b.val$，故 $a$ 与 $b$ 完全相同，即 $\text{flip}(a,b)$。交换对应的情形只需在根上多做一次翻转。∎

**定理**：算法返回 `true` 当且仅当两棵树翻转等价。

**证明**：对两棵树的节点总数归纳。

- 都为 0：两棵空树显然等价，算法返回 `true` ✓。
- 恰有一棵为空：节点数不同，由引理 1（翻转不改变节点数）不可能等价，算法返回 `false` ✓。
- 都非空且 $a.val \ne b.val$：翻转不改变根的值（根不会被换掉），故不可能等价，算法返回 `false` ✓。
- 都非空且 $a.val = b.val$：由引理 2，等价 $\Rightarrow$ 两种对应之一成立；由引理 3，两种对应之一成立 $\Rightarrow$ 等价。而算法正是对"两种对应之一"做递归判定，且递归到的是规模更小的子树，由归纳假设递归返回值正确。因此算法返回值 $\iff$ 存在一种对应 $\iff$ 两树等价。∎

## 6. 复杂度分析

- **时间**：$O(\min(n_1, n_2))$。每个节点对最多被比较常数次；实际是 $O(n)$（$n$ 为较小树的节点数），值不同或结构不同时可提前剪枝。
- **空间**：$O(h)$ 递归栈，$h$ 为树高，最坏 $O(n)$（链状），平均 $O(\log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool flipEquiv(TreeNode* root1, TreeNode* root2) {
        if (!root1 && !root2) return true;                 // 都空
        if (!root1 || !root2) return false;                // 一空一非空
        if (root1->val != root2->val) return false;        // 值不同
        return (flipEquiv(root1->left, root2->left) &&
                flipEquiv(root1->right, root2->right))     // 不交换
            || (flipEquiv(root1->left, root2->right) &&
                flipEquiv(root1->right, root2->left));     // 交换
    }
};
```

### Python

```python
class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def flipEquiv(self, root1: "TreeNode | None", root2: "TreeNode | None") -> bool:
        if root1 is None and root2 is None:
            return True
        if root1 is None or root2 is None:
            return False
        if root1.val != root2.val:
            return False
        return (self.flipEquiv(root1.left, root2.left)
                and self.flipEquiv(root1.right, root2.right)) \
            or (self.flipEquiv(root1.left, root2.right)
                and self.flipEquiv(root1.right, root2.left))
```

## 8. 边界情况与易错点

1. **两棵空树返回 `true`**：这是最容易被漏掉的正例；判空顺序必须"都空"在前。
2. **一空一非空返回 `false`**：不能因为"剩下的子树还有机会"而继续，节点数不同直接否。
3. **交换分支的交叉配对**：`a.left ↔ b.right`、`a.right ↔ b.left`；写成一个左对一个左就退化成了"结构完全相同"的判定。
4. **两条分支用 `||`**：只写"不交换"分支会把示例 1 判成 `false`（示例 1 的根需要交换）。
5. **不能比较层序数组**：翻转会改变层序中的顺序，示例 1 的两棵树层序数组完全不同却等价。
6. **不能只比较中序/前序遍历序列**：翻转后中序序列会变化，前序也不稳定；若真要用序列法，必须用"规范形"而不是原始遍历。
7. **值相同但不是同一节点**：题面保证值唯一，所以"值相同"可以直接配对；如果值可重复，需要改用规范形/多重集匹配。
8. **递归栈深度**：$n \le 100$ 安全；若题目放宽，改迭代版（栈存节点对）。
