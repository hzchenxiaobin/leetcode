# LeetCode 按公因数计算最大组件大小 题解

## 1. 题目概述

- **标题 / 题号**：按公因数计算最大组件大小（#952，hard）
- **链接**：https://leetcode.cn/problems/largest-component-size-by-common-factor/
- **来源**：LeetCode 第 113 场周赛 Q4
- **难度**：困难
- **标签**：并查集、数组、哈希表、数学、数论、质因数分解

**题意**：给定由**互不相同**的正整数组成的非空数组 `nums`。以 `nums[i]` 为节点建图：若 $nums[i]$ 与 $nums[j]$ 有**大于 1 的公因数**（即 $\gcd > 1$），则它们之间有一条边。求图中**最大连通组件的大小**。

**约束**：

- $1 \le nums.length \le 2\times10^4$
- $1 \le nums[i] \le 10^5$
- `nums` 中所有值互不相同

## 2. 示例

**示例 1**

```text
输入：nums = [4,6,15,35]
输出：4
解释：4-6 共享 2；6-15 共享 3；15-35 共享 5 ⇒ 4 个节点全连通。
```

**示例 2**

```text
输入：nums = [20,50,9,63]
输出：2
解释：20-50 共享 10；9-63 共享 9；两组各 2 个节点，最大为 2。
```

**示例 3**

```text
输入：nums = [2,3,6,7,4,12,21,39]
输出：8
解释：全部连通（6=2·3 起枢纽作用，12、21、39 依次接入），最大组件 8。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：枚举所有点对，$\gcd > 1$ 就连边，然后 BFS/并查集求最大连通分量。

复杂度 $O(n^2\log A)$：$n = 2\times10^4$ 时点对约 $2\times10^8$，每次 `gcd` 还要几个整数除法，C++ 勉强、Python 必然超时。**必须利用数论结构减少边数**。

### 3.2 核心观察：用「质因子」作枢纽节点

![把「质因子」当作枢纽节点，数字通过质因子相连](images/wc113_q4_factor_graph.svg)

关键数论事实：

$$\gcd(a,b) > 1 \iff a \text{ 与 } b \text{ 有公共的\textbf{质}因子}.$$

（因为 $\gcd>1$ 必有质因数，而任何公因数都包含某个公共质因子。）

于是可以引入**中间节点**：把每个**质数**也当成图里的节点，让"数值 $v$"与它的每个**质因子** $p$ 相连。这样：

- 两个数共享质因子 $p$ $\iff$ 它们在图中通过 $p$ 连通（$u - p - v$）；
- 原图的连通性 $\iff$ 新图的连通性（只在"数"节点之间传导）。

**收益**：每个数至多有 $O(\log A)$ 个不同质因子（$A \le 10^5$ 时最多 6 个不同质因子，$2\cdot3\cdot5\cdot7\cdot11\cdot13 = 30030$，再加 17 就超过 $10^5$），因此边数从 $O(n^2)$ 降到 $O(n\log A)$——约 $10^5$ 级别。

用并查集把所有"数 ↔ 质因子"合并，最后统计**每个根下有多少个"数"节点**（质因子节点不计数），取最大值。

### 3.3 算法流程

![largestComponentSize：筛法 + 并查集](images/wc113_q4_flow.svg)

```text
1. M = max(nums)
2. 用筛法求 spf[x]（x 的最小质因子），x ∈ [1, M]
3. 并查集初始化：每个 nums[i] 与每个出现的质因子都是独立节点
4. for v in nums:
       把 v 分解成不同质因子 p1, p2, ...
       for p in 该集合: union(v, p)        // 同一质因子的数被合并到一起
5. 统计 cnt[root(v)]++（只对 v ∈ nums）
6. return max cnt
```

### 3.4 示例演算

![示例 1：4、6、15、35 通过 2、3、5 串成一条链](images/wc113_q4_factor_graph.svg)

对 `nums = [4,6,15,35]`：

| 数 | 质因子分解 | union 操作 |
|----|-----------|-----------|
| 4 | $2^2$ | union(4, 2) |
| 6 | $2 \cdot 3$ | union(6, 2)、union(6, 3) |
| 15 | $3 \cdot 5$ | union(15, 3)、union(15, 5) |
| 35 | $5 \cdot 7$ | union(35, 5)、union(35, 7) |

合并过程：$4 - 2 - 6 - 3 - 15 - 5 - 35 - 7$，全部落在同一个根下。计数时只看 4、6、15、35 四个数，得 4，与答案一致。

示例 2 中 $20 = 2^2\cdot5$、$50 = 2\cdot5^2$ 共享 $\{2,5\}$ → 同组 2 个；$9 = 3^2$、$63 = 3^2\cdot7$ 共享 $\{3\}$ → 另一组 2 个；两组互不相干，最大为 2。

## 4. 算法细节

![最小质因子筛：每个合数只被最小的质数标记](images/wc113_q4_sieve.svg)

1. **最小质因子筛（SPF）**：`spf[x]` 记录 $x$ 的最小质因子，用埃氏筛从 $p^2$ 开始标记，只在 `spf[j] == j` 时赋值，保证取到最小值。复杂度 $O(M\log\log M)$。
2. **分解时除尽同一个质因子**：`while (x % p == 0) x /= p;` 保证每个**不同**质因子只处理一次，避免重复 `union`（虽不致命，但会拖慢常数）。
3. **并查集节点**：数值与质因子共用同一个编号空间（数值 $\le 10^5$、质因子也 $\le 10^5$），可以直接开大小为 $M+1$ 的数组，无需哈希。
4. **计数只算数值节点**：`cnt` 按根累加时只遍历 `nums` 中的数，质因子节点若也计数就会把答案放大。
5. **`nums[i] = 1`**：1 没有质因子，独立成组件（大小 1）。要保证它自己的根是自己。
6. **筛的上界**：取 `max(nums)` 即可；若 `max(nums) == 1`，筛循环不执行，也不会出错。
7. **路径压缩**：`find` 递归压缩即可，深度很小（并查集是"数—质因子"两级结构，路径长度通常 ≤ 3）。
8. **不用哈希表**：坐标范围小（$10^5$），数组比 `unordered_map` 快一个量级；Python 用字典也可以，但数组更快。

## 5. 正确性证明

设原图 $G$ 的节点集为 $V = \{nums[i]\}$，边集 $E = \{(u,v) : \gcd(u,v) > 1\}$；构造辅助二分图 $H$：节点集为 $V \cup P$（$P$ 为所有出现在 `nums` 中的质因子），边集 $E_H = \{(v, p) : p \mid v,\ p \text{ 为质数}, v \in V\}$。并查集合并的正是 $E_H$ 的边。

**引理 1（公因数 ⟺ 公共质因子）**：对 $a, b \ge 1$，$\gcd(a,b) > 1 \iff \exists$ 质数 $p$ 使 $p \mid a$ 且 $p \mid b$。

**证明**：若 $p \mid a, p \mid b$ 则 $p \mid \gcd(a,b)$，故 $\gcd > 1$。反之若 $d = \gcd(a,b) > 1$，取 $d$ 的任一质因数 $p$（算术基本定理保证存在），则 $p \mid a$、$p \mid b$。∎

**引理 2（连通性等价）**：对 $u, v \in V$，$u$ 与 $v$ 在 $G$ 中连通 $\iff$ 在 $H$ 中连通。

**证明**：

- "$\Leftarrow$"：设 $H$ 中存在路径 $u = x_0 - x_1 - \cdots - x_k = v$。路径在 $V$ 与 $P$ 之间交替，模式为 $v_0 - p_1 - v_1 - p_2 - \cdots - v_t$，其中 $p_i$ 同时整除 $v_{i-1}$ 与 $v_i$；由引理 1，$(v_{i-1}, v_i) \in E$。故 $u$ 与 $v$ 在 $G$ 中通过 $v_0, v_1, \dots, v_t$ 连通。
- "$\Rightarrow$"：设 $G$ 中路径 $u = v_0 - v_1 - \cdots - v_k = v$，每条边 $\gcd(v_{i-1},v_i)>1$ 由引理 1 给出公共质因子 $p_i$，于是 $v_{i-1} - p_i - v_i$ 是 $H$ 中的两跳路径。拼接即得 $H$ 中的 $u$–$v$ 路径。∎

**引理 3（并查集正确刻画连通分量）**：算法结束时，两个数值 $u,v$ 属于同一并查集根 $\iff$ 它们在 $H$ 中连通。

**证明**：并查集合并的边集恰为 $E_H$，而并查集的连通分量与"由 $E_H$ 生成的连通关系"一致（对合并次数归纳：每次 union 把两个分量化为一，恰与图中加边效果相同）。∎

**引理 4（组件大小计数正确）**：对任一 $G$ 的连通分量 $C \subseteq V$，算法统计的 `cnt[root]` 恰为 $\lvert C\rvert$。

**证明**：由引理 2、3，$C$ 中所有数落在同一根下；$C$ 外的数与 $C$ 不连通、根不同。计数循环只遍历 $V$ 中的节点（每个数值出现一次，因 `nums` 互不相同），所以每根累加的正是该分量内数值节点的个数。∎

**定理**：算法返回 $G$ 中最大连通分量的大小。

**证明**：由引理 4，`cnt` 的每个非零值都是某个 $G$ 连通分量的大小，且每个分量都对应一个非零 `cnt`；因此 `max cnt` 恰为最大连通分量大小。∎

## 6. 复杂度分析

- **时间**：
  - 筛法求 SPF：$O(M\log\log M)$，$M = \max(nums) \le 10^5$；
  - 分解并合并：每个数分解 $O(\log A)$ 步、每步一次 `union`（$O(\alpha)$），合计 $O(n\log A\cdot\alpha)$；
  - 计数：$O(n)$。总计约 $O(M\log\log M + n\log A)$，远优于 $O(n^2\log A)$。
- **空间**：$O(M + n)$ 的 SPF 数组、并查集数组与计数数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> par;

    int findRoot(int x) {
        if (par[x] != x) par[x] = findRoot(par[x]);   // 路径压缩
        return par[x];
    }

    int largestComponentSize(vector<int>& nums) {
        int M = *max_element(nums.begin(), nums.end());

        // 1. 最小质因子筛
        vector<int> spf(M + 1);
        for (int i = 0; i <= M; i++) spf[i] = i;
        for (int i = 2; (long long)i * i <= M; i++) {
            if (spf[i] != i) continue;                 // i 不是质数
            for (int j = i * i; j <= M; j += i)
                if (spf[j] == j) spf[j] = i;           // 只记录最小质因子
        }

        // 2. 并查集：数值与质因子共用编号空间
        par.resize(M + 1);
        for (int i = 0; i <= M; i++) par[i] = i;
        for (int v : nums) {
            int x = v;
            while (x > 1) {
                int p = spf[x];                        // x 的最小质因子
                int a = findRoot(v), b = findRoot(p);
                if (a != b) par[a] = b;
                while (x % p == 0) x /= p;             // 除尽同一质因子
            }
        }

        // 3. 只统计数值节点的个数
        vector<int> cnt(M + 1, 0);
        int best = 0;
        for (int v : nums) best = max(best, ++cnt[findRoot(v)]);
        return best;
    }
};
```

### Python

```python
class Solution:
    def largestComponentSize(self, nums: list[int]) -> int:
        M = max(nums)

        # 1. 最小质因子筛
        spf = list(range(M + 1))
        i = 2
        while i * i <= M:
            if spf[i] == i:                 # i 是质数
                for j in range(i * i, M + 1, i):
                    if spf[j] == j:
                        spf[j] = i
            i += 1

        # 2. 并查集
        parent = {v: v for v in nums}

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        for v in nums:
            x = v
            while x > 1:
                p = spf[x]                       # 取最小质因子
                if p not in parent:
                    parent[p] = p                # 质因子也作为节点
                ra, rb = find(v), find(p)
                if ra != rb:
                    parent[ra] = rb
                while x % p == 0:                # 除尽同一质因子
                    x //= p

        # 3. 只统计数值节点
        cnt, best = {}, 0
        for v in nums:
            r = find(v)
            cnt[r] = cnt.get(r, 0) + 1
            best = max(best, cnt[r])
        return best
```

## 8. 边界情况与易错点

1. **`nums[i] = 1`**：1 没有质因子，分解循环不执行，它自成一个大小为 1 的组件；若用 `spf[1]` 参与合并会出错（`spf[1] = 1`，不能当质数）。
2. **重复质因子要除尽**：$4 = 2^2$ 只应产生一次 union(4, 2)；不除尽会重复合并（结果对但变慢），若用"记录质因子列表"的方式还可能把 $p$ 重复计数。
3. **计数只算数值**：把质因子节点也计入 `cnt` 会让答案偏大（例如 `[4,6]` 会算成 4 个节点）。
4. **筛的上界**：`spf` 大小取 `max(nums)+1`；若 `max(nums) = 1`，数组只有 2 个元素，循环不执行，不越界。
5. **`i * i <= M` 的溢出**：$M \le 10^5$ 时 `int` 不溢出，但写成 `(long long)i * i` 更稳妥（若上界放宽到 $10^9$ 就必须这样）。
6. **不要用 $O(n^2)$ 的 gcd 建图**：$n = 2\times10^4$ 时 $2\times10^8$ 次 gcd，Python 必超时。
7. **大质数**：如 $99991$ 这样的质数，其 `spf` 是自身，union(v, v) 完全合法（自合并），不会出错。
8. **`nums` 互不相同**：题面保证；若有重复值，计数会重复计入同一个节点，需要先去重。
9. **路径压缩的递归深度**：并查集形态是"数 → 质因子 → 其它数"，路径很短，递归安全。
