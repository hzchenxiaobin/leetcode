# LeetCode 给定数字能组成的最大时间 题解

## 1. 题目概述

- **标题 / 题号**：给定数字能组成的最大时间（#949，medium）
- **链接**：https://leetcode.cn/problems/largest-time-for-given-digits/
- **来源**：LeetCode 第 113 场周赛 Q1
- **难度**：中等
- **标签**：数组、字符串、回溯、枚举

**题意**：给定 4 个数字组成的数组 `arr`，用这 4 个数字**各一次**排成 24 小时制的最大合法时刻 `"HH:MM"`（$00 \le HH \le 23$，$00 \le MM \le 59$）。无合法时刻时返回空字符串 `""`。

**约束**：

- `arr.length == 4`
- $0 \le arr[i] \le 9$

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,3,4]
输出："23:41"
解释：合法时刻共 10 个（12:34、12:43、13:24、13:42、14:23、14:32、
     21:34、21:43、23:14、23:41），最大者为 23:41。
```

**示例 2**

```text
输入：arr = [5,5,5,5]
输出：""
解释：所有数字都是 5，"55:55" 的小时与分钟都不合法。
```

**示例 3**

```text
输入：arr = [0,0,0,0]
输出："00:00"
解释：00:00 是合法时刻（最小）。
```

**示例 4**

```text
输入：arr = [0,0,1,0]
输出："10:00"
解释：用 1 与一个 0 组成 10 时，分钟 00。
```

## 3. 解题思路

### 3.1 暴力思路

4 个数字的**全排列只有 $4! = 24$ 种**，每种排列按 `HH = p[0]p[1]`、`MM = p[2]p[3]` 组一个时刻，检查合法性（$HH<24$ 且 $MM<60$），取最大值即可。

这个"暴力"本身就是最优解：$24$ 种候选、每种 $O(1)$ 判定，总运算量不到百次。**没有任何必要**去做更复杂的贪心或搜索——本题的考点就是"意识到枚举规模极小"。

另一种等价枚举是"从 23:59 倒着枚举所有 $24\times60=1440$ 个时刻，检查其数字多重集是否与 `arr` 相同"，同样只有 1440 次判定，作为**独立的验证手段**非常好用（见 §5 的验证思路）。

### 3.2 核心观察：24 种排列 + 等长字符串比较

![4 个数字 → 24 种排列 → 过滤合法 → 取最大](images/wc113_q1_permute.svg)

两个小观察让代码极短：

1. **合法性只取决于两个两位数**：$HH = 10\,p_0 + p_1$、$MM = 10\,p_2 + p_3$，条件就是 $HH \le 23$ 且 $MM \le 59$。不需要按位拆开判断"十位是否 ≤2"之类。
2. **`"HH:MM"` 定长 5 字符，字典序 = 时间先后**：因为小时、分钟都是两位补零，比较字符串与比较 $(HH, MM)$ 完全等价。所以更新答案只需 `if (cur > best)`。

![时刻合法性的三个约束](images/wc113_q1_constraints.svg)

### 3.3 算法流程

```text
1. 把 arr 排序（next_permutation 需要有序起点）
2. best = ""
3. do:
       h = arr[0]*10 + arr[1]
       m = arr[2]*10 + arr[3]
       若 h < 24 且 m < 60:
           cur = "HH:MM"（直接用 4 个数字字符拼出）
           若 cur > best: best = cur
   while next_permutation(arr)
4. return best
```

### 3.4 示例演算

![示例 1 过滤后的 10 个合法时刻，最大者为 23:41](images/wc113_q1_permute.svg)

$arr = [1,2,3,4]$ 的 24 种排列里，合法的恰有 10 个：

| 小时 | 合法分钟（由剩余两位组成） | 时刻 |
|------|--------------------------|------|
| 12 | 3,4 → 34 / 43 | 12:34, 12:43 |
| 13 | 2,4 → 24 / 42 | 13:24, 13:42 |
| 14 | 2,3 → 23 / 32 | 14:23, 14:32 |
| 21 | 3,4 → 34 / 43 | 21:34, 21:43 |
| 23 | 1,4 → 14 / 41 | 23:14, **23:41** |

其余小时（24、31、32、34、41、42、43…）都超过 23，被淘汰。字符串最大值是 `"23:41"`。

## 4. 算法细节

1. **先排序**：C++ 的 `next_permutation` 必须从**最小排列**出发才能枚举全部 $n!$ 个排列；不排序会漏解。
2. **字符串拼接**：由于每个数字恰好一位，`"HH:MM"` 可以直接由 4 个字符拼成 `c0 c1 ':' c2 c3`，无需 `snprintf`，也避免格式化开销。
3. **判定用整数**：`h < 24 && m < 60` 比按位判断"十位 ≤ 2，且若十位为 2 则个位 ≤ 3"更不容易写错。
4. **字符串比较**：定长补零保证字典序与时间序一致，直接 `>` 比较；若小时是个位数不补零就会错（"9:00" > "10:00"）。
5. **答案初值**：`""` 空串，与任何合法时刻比较都更小，因此第一次命中就会更新。
6. **Python 用 `itertools.permutations`**：自动去重不需要（数字可能重复，但重复排列得到的时刻相同，只是多算几次，$24$ 次无所谓）。
7. **不需要去重**：`[0,0,1,0]` 这类有重复数字的输入，重复排列会得到相同的候选，取最大不受影响。
8. **答案唯一**：字典序最大者唯一，没有多解问题。

## 5. 正确性证明

**引理 1（枚举完备）**：$\{$按排列 $p$ 拼出的时刻$\} = \{$用 `arr` 的 4 个数字各一次能拼出的全部时刻$\}$。

**证明**：任一时刻由 4 个位置（$h_1, h_2, m_1, m_2$）上的数字确定，这 4 个位置填的正是 `arr` 的一个排列；反之每个排列都给出一个时刻。二者一一对应。∎

**引理 2（合法判据）**：排列 $p$ 拼出的时刻合法 $\iff 10p_0 + p_1 < 24$ 且 $10p_2 + p_3 < 60$。

**证明**：$HH = 10p_0+p_1$，24 小时制要求 $0 \le HH \le 23$；$MM = 10p_2+p_3$ 要求 $0 \le MM \le 59$。两位数自动非负，故只需上界。∎

**引理 3（字典序等价）**：对两个合法时刻 $t_1, t_2$，$t_1$ 的字符串表示 $> t_2$ 的字符串表示 $\iff t_1$ 在时间上更晚。

**证明**：两串都是 `H H : M M` 形式，前半段比较小时、后半段比较分钟；由于小时与分钟都固定两位且首位补零，字符串的逐字符比较恰好先比小时的十位、个位，再比分钟的十位、个位，与数值比较 $(HH, MM)$ 的顺序一致。∎

**定理**：算法返回最大合法时刻；不存在合法时刻时返回 `""`。

**证明**：由引理 1 与引理 2，算法恰好遍历所有合法时刻（且不遗漏任何非法时刻）；由引理 3，`best` 的更新规则取到了其中的字典序最大者，即时间上最晚者。若无合法时刻，`best` 保持初值 `""`，正是题目要求的输出。∎

## 6. 复杂度分析

- **时间**：$O(4!)=O(1)$，24 次枚举，每次 $O(1)$ 的整数判断与 5 字符拼接；排序 4 个元素 $O(1)$。
- **空间**：$O(1)$（Python 的 `permutations` 惰性生成，不占额外空间；C++ 用 `next_permutation` 原地）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string largestTimeFromDigits(vector<int>& arr) {
        sort(arr.begin(), arr.end());          // next_permutation 需要最小排列起点
        string best = "";
        do {
            int h = arr[0] * 10 + arr[1];
            int m = arr[2] * 10 + arr[3];
            if (h < 24 && m < 60) {
                string cur;
                cur += char('0' + arr[0]);
                cur += char('0' + arr[1]);
                cur += ':';
                cur += char('0' + arr[2]);
                cur += char('0' + arr[3]);
                if (cur > best) best = cur;    // 定长补零，字典序即时间序
            }
        } while (next_permutation(arr.begin(), arr.end()));
        return best;
    }
};
```

### Python

```python
import itertools


class Solution:
    def largestTimeFromDigits(self, arr: list[int]) -> str:
        best = ""
        for p in itertools.permutations(arr):
            h = p[0] * 10 + p[1]
            m = p[2] * 10 + p[3]
            if h < 24 and m < 60:
                cur = f"{h:02d}:{m:02d}"
                if cur > best:
                    best = cur
        return best
```

## 8. 边界情况与易错点

1. **没有合法时刻**：如 `[5,5,5,5]`，必须返回空串 `""`，而不是 `"00:00"` 或 `"24:00"`。
2. **`00:00` 是合法时刻**：`[0,0,0,0]` 要返回 `"00:00"`；不要因为"看起来没有时间"而返回空串。
3. **小时与分钟都要判**：只判 $HH<24$ 会把 `[1,2,3,4]` 的 `12:43` 之类判对，但 `[2,0,7,9]` 会出现 `20:79` 漏判。
4. **不要漏掉"分钟十位 ≤ 5"**：`h<24 && m<60` 已覆盖，但若手写按位判断（`m1<=5`），容易在 `m1 == 5` 时把 `m2` 的限制写错。
5. **字符串比较必须补零**：`"9:00" > "10:00"` 是字符串比较的经典坑；本题用 `%02d` 或直接拼字符可避免。
6. **`next_permutation` 前必须排序**：不排序只会枚举从当前排列开始的"后续"排列，漏掉更小的起点。
7. **重复数字**：`[0,0,1,0]` 会枚举出多个相同的候选，取最大不受影响；不要试图先去重数组（会丢解）。
8. **贪心构造的陷阱**：若尝试"先选最大的可行小时十位、再选小时个位……"，每步都要检查"剩余两位能否组成合法分钟"，漏掉这一步会返回非法时刻。本题枚举更稳。

**延伸思考**：若数字个数扩大到 $k$ 位（例如 6 个数字拼 `HH:MM:SS`），$k!$ 迅速膨胀，此时应改为**贪心 + 可行性剪枝**：从最高位开始，对每一位尝试从大到小的数字，并用"剩余位能否填成合法后缀"的贪心判定（对 `HH:MM:SS` 这样的多段结构，每段的合法区间是独立的，可行性检查是 $O(1)$ 的）。再进一步，若要求"第 $k$ 大的合法时刻"，则变成按位确定 + 组合计数的问题。
