# LeetCode 按递增顺序显示卡牌 题解

## 1. 题目概述

- **标题 / 题号**：按递增顺序显示卡牌（#950，medium）
- **链接**：https://leetcode.cn/problems/reveal-cards-in-increasing-order/
- **来源**：LeetCode 第 113 场周赛 Q3
- **难度**：中等
- **标签**：队列、数组、排序、模拟

**题意**：牌组初始正面朝下，重复执行：

1. 从牌组顶部抽一张牌、**亮出**并移出；
2. 若还有牌，把**新的顶牌移到牌组底部**；
3. 回到第 1 步，直到牌全部亮出。

给定一组**互不相同**的牌面值 `deck`，求一种牌组排列（数组首位是牌组顶部），使得亮出的顺序**严格递增**。

**约束**：

- $1 \le deck.length \le 1000$
- $1 \le deck[i] \le 10^6$
- 所有 $deck[i]$ **互不相同**

## 2. 示例

**示例 1**

```text
输入：deck = [17,13,11,2,3,5,7]
输出：[2,13,3,11,5,17,7]
```

**示例 2**

```text
输入：deck = [1,1000]
输出：[1,1000]
```

**示例 3（补充，三张牌）**

```text
输入：deck = [1,2,3]
输出：[1,3,2]
解释：亮出 1 → 把 3 移到底 → [2,3]；亮出 2 → 把 3 移到底 → [3]；亮出 3。
     亮出序列 1,2,3 递增 ✓
```

## 3. 解题思路

### 3.1 暴力思路

正向的思路是"尝试把每张牌放到某个位置，再模拟发牌检查"。直接枚举牌组排列是 $n!$，$n = 1000$ 时完全不可行。

普通的回溯也不行：每次放牌都会影响后续"移到底"的位置关系，搜索树规模指数级。

### 3.2 核心观察：逆向"放牌"

![逆向构造：把牌按升序「放回」队列给出的位置](images/wc113_q3_reverse.svg)

本题的关键是**把过程倒过来看**。

**正向过程**（发牌）只做两件事：取顶、把下一张顶牌移到底。这两步**只与"牌的张数"和"位置"有关，与牌面值无关**。因此：

> 整个发牌过程中"第 $k$ 次亮出的位置"完全由 $n$ 决定，是一个固定的位置序列 $\pi(0), \pi(1), \dots, \pi(n-1)$。

既然亮出顺序必须**递增**，那就意味着：

- 第 $0$ 次亮出的位置 $\pi(0)$ 上放**最小的牌**；
- 第 $1$ 次亮出的位置 $\pi(1)$ 上放**第二小**的牌；
- ……

于是**逆向构造**：先把牌排序，然后按 $\pi(0), \pi(1), \dots$ 的顺序把牌依次"放回"牌组对应的位置。

**如何得到 $\pi$？** 用一个**下标队列**模拟"位置"本身：

- 初始 `idx = [0, 1, ..., n-1]`，队首表示"下一次被亮出的位置"；
- 每轮：取队首 $p$（它就会被亮出），然后——正向过程"取走后把下一个移到底"——等价于**把队首移到队尾**。

### 3.3 算法流程

```text
1. 排序 deck
2. idx = deque([0, 1, ..., n-1])
3. res = [0]*n
4. for card in sorted(deck):
       p = idx.popleft()          // 本次亮出的位置
       res[p] = card
       if idx 非空: idx.append(idx.popleft())   // 把下一个位置移到底
5. return res
```

注意第 4 步的"移到底"发生在**取走队首之后**，且只在队列非空时执行——这对应正向过程"取走后若还有牌才移到底"。

### 3.4 示例演算

![示例 1：排序后依次放入](images/wc113_q3_walkthrough.svg)

`deck = [17,13,11,2,3,5,7]`，排序后为 $[2,3,5,7,11,13,17]$：

| 牌 | `idx` 队首 | 放入位置 | `idx` 变化 |
|----|-----------|---------|-----------|
| 2 | 0 | `res[0] = 2` | $[1,2,3,4,5,6] \to [2,3,4,5,6,1]$ |
| 3 | 2 | `res[2] = 3` | $[3,4,5,6,1] \to [4,5,6,1,3]$ |
| 5 | 4 | `res[4] = 5` | $[5,6,1,3] \to [6,1,3,5]$ |
| 7 | 6 | `res[6] = 7` | $[1,3,5] \to [3,5,1]$ |
| 11 | 1 | `res[1] = 11` | $[3,5,1] \to [5,1,3]$ |
| 13 | 3 | `res[3] = 13` | $[5,1] \to [1,5]$ |
| 17 | 5 | `res[5] = 17` | $[1]$ |

得到 `res = [2,13,3,11,5,17,7]`，与题面输出一致。

![正向模拟验证：res 发牌恰好递增](images/wc113_q3_verify.svg)

反过来用正向模拟验证：亮出 $2$，$13$ 移到底 → 亮出 $3$，$11$ 移到底 → … → 亮出 $17$，序列 $2,3,5,7,11,13,17$ 严格递增 ✓。

## 4. 算法细节

1. **位置队列**：`deque` 的 `popleft` + `append` 正好对应"取顶 / 移到底"，均摊 $O(1)$。
2. **排序不可省**：必须按升序把牌放进 $\pi(k)$，否则亮出顺序就不递增。
3. **"移到底"的时机**：先取走队首，再判断队列是否非空；顺序写反会让位置序列整体错位。
4. **只在非空时旋转**：最后一轮取出后队列为空，此时不应再 `append`（会索引空队列报错，或容量对不上）。
5. **数组下标从 0 开始**：`res[p]` 直接写入，不需要 `insert` 或链表——因为位置序列是预先算好的，而不是边构造边插入。
6. **答案唯一**：亮出顺序被强制为升序，位置序列由 $n$ 唯一确定，故结果唯一（题面也只要求返回一个）。
7. **Python 用 `collections.deque`**：`list.pop(0)` 是 $O(n)$，整体会退化为 $O(n^2)$。
8. **值互不相同**：若允许重复，亮出顺序"非严格递增"时答案不再唯一，本题不做考虑。

## 5. 正确性证明

设牌组数组为 $D$（$D[0]$ 是顶部），下标集合 $\{0,\dots,n-1\}$。定义正向过程在 $D$ 上产生的**亮出位置序列** $\pi_D(0), \pi_D(1), \dots, \pi_D(n-1)$（$\pi_D(k)$ 表示第 $k$ 次亮出的牌在初始数组中的下标）。

**引理 1（位置序列与牌面无关）**：对任意两个长度相同、只是牌面不同的牌组，亮出位置序列相同。即 $\pi$ 只由 $n$ 决定，记作 $\pi_n$。

**证明**：正向过程的每一步只做"取走当前队首 / 把队首移到队尾"这两种**结构操作**，判断依据只有"队列是否非空"，完全不涉及牌面值。故过程的轨迹（访问的下标顺序）只与 $n$ 有关。∎

**引理 2（队列模拟即 $\pi_n$）**：算法中的 `idx` 队列每次 `popleft` 得到的下标序列恰为 $\pi_n$。

**证明**：对轮数归纳。`idx` 初始为 $[0,\dots,n-1]$，与正向过程开始时"牌组自顶向下"的下标序列一致（把队列首视为顶部）。算法每轮取出队首（这正是"亮出当前顶牌"）、然后把新队首移到队尾（正是"把下一张顶牌移到牌组底部"）。故 `idx` 始终保持"当前牌组自顶向下的下标序列"，取出的队首序列就是亮出位置序列 $\pi_n$。∎

**引理 3（构造后亮出即升序）**：按算法构造 $D$ 后，正向亮出的牌面序列为 `sorted(deck)`。

**证明**：设排序后牌面为 $c_0 < c_1 < \dots < c_{n-1}$，算法令 $D[\pi_n(k)] = c_k$。正向过程第 $k$ 次亮出的牌位于初始下标 $\pi_n(k)$（引理 1、2），故亮出的是 $c_k$。于是亮出序列恰为 $c_0, c_1, \dots, c_{n-1}$，严格递增。∎

**定理**：算法返回的牌组排列能使亮出顺序严格递增。

**证明**：由引理 3 直接得到。此外由引理 1，任何满足"亮出递增"的排列都必须满足 $D[\pi_n(k)] = c_k$（否则第 $k$ 次亮出的不是第 $k$ 小的牌），故解唯一，算法给出的就是唯一解。∎

## 6. 复杂度分析

- **时间**：$O(n\log n)$。排序 $O(n\log n)$；下标队列共 $n$ 次 `popleft` 与至多 $n$ 次旋转，每次 $O(1)$，合计 $O(n)$。
- **空间**：$O(n)$。`res` 数组与 `idx` 队列各 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> deckRevealedIncreasing(vector<int>& deck) {
        int n = deck.size();
        sort(deck.begin(), deck.end());
        deque<int> idx;
        for (int i = 0; i < n; i++) idx.push_back(i);   // 记录"位置"而非牌面
        vector<int> res(n);
        for (int card : deck) {                          // 从小到大地放牌
            res[idx.front()] = card;                     // 放到"下一次会亮出"的位置
            idx.pop_front();
            if (!idx.empty()) {                          // 对应"把下一张移到底"
                idx.push_back(idx.front());
                idx.pop_front();
            }
        }
        return res;
    }
};
```

### Python

```python
from collections import deque


class Solution:
    def deckRevealedIncreasing(self, deck: list[int]) -> list[int]:
        n = len(deck)
        idx = deque(range(n))       # 位置队列，队首 = 下一次亮出的位置
        res = [0] * n
        for card in sorted(deck):   # 升序放牌
            res[idx.popleft()] = card
            if idx:                 # 模拟"把下一张顶牌移到底部"
                idx.append(idx.popleft())
        return res
```

## 8. 边界情况与易错点

1. **旋转时机写反**：先旋转再取队首会把位置序列整体错一位，结果不再递增。
2. **最后一轮多旋转一次**：队列已空时再 `popleft` 会抛异常（Python）或越界（C++）。
3. **`n = 1`**：`idx = [0]`，放入后队列空，直接返回 `[deck[0]]`。
4. **`n = 2`**：`[1,1000]` 应返回 `[1,1000]`——第一张亮出 1，剩下 1000 不用移底（移了也无所谓，但只剩一张）。
5. **用 `list.pop(0)`**：那是 $O(n)$ 操作，整体退化为 $O(n^2)$；必须用 `deque`。
6. **忘记排序**：不排序就无法保证亮出递增，构造出的位置序列是"按原顺序放牌"，答案错误。
7. **误以为可以边构造边插**：牌的插入会改变队列内容，与"位置预先确定"矛盾；本解法把"位置"和"牌面"彻底解耦，才做到 $O(n\log n)$。
8. **牌面重复**：题面保证互不相同；若有重复，"递增"变"非严格递增"后答案不再唯一，需重新推导。
