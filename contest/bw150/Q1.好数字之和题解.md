# LeetCode 好数字之和 题解

## 1. 题目概述

- **标题 / 题号**：好数字之和（#3452，easy）
- **链接**：https://leetcode.cn/problems/sum-of-good-numbers/
- **来源**：LeetCode 第 150 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定整数数组 `nums` 与整数 $k$。元素 `nums[i]` 是**好**的，当且仅当它**严格大于**下面两个位置上的元素（**如果存在**）：

- 下标 $i - k$ 处的元素；
- 下标 $i + k$ 处的元素。

若这两个下标都不存在（或只存在其中一个，则只需与存在的那一个比较），元素仍按上述规则判定。返回所有好元素的**和**。

**约束**：

- $2 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 1000$
- $1 \le k \le \lfloor \text{nums.length} / 2 \rfloor$

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,2,1,5,4], k = 2
输出：12
解释：好元素是 nums[1] = 3（大于 nums[3] = 1）、nums[4] = 5（大于 nums[2] = 2）、
      nums[5] = 4（大于 nums[3] = 1），和为 3 + 5 + 4 = 12。
```

**示例 2**

```text
输入：nums = [2,1], k = 1
输出：2
解释：nums[0] = 2 大于 nums[1] = 1，是好元素；nums[1] = 1 不大于 nums[0] = 2。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$，检查 $i-k$ 与 $i+k$ 是否存在，存在就比较一下。每个元素最多看两个位置，复杂度 $O(n)$ —— 这题没有"更优"的空间，难点只在**边界**：下标越界时该侧不参与比较，而不是判为不合法。

### 3.2 核心观察：只和"距离 $k$"的两个位置比较

![好元素只与距离 k 的两个邻居比较，缺邻居时自动算满足](images/bw150_q1_neighbors.svg)

判据可以写成：

$$\text{good}(i) = \big(i - k < 0 \ \lor\ \text{nums}[i-k] < \text{nums}[i]\big) \ \wedge\ \big(i + k \ge n \ \lor\ \text{nums}[i+k] < \text{nums}[i]\big)$$

三个要点：

- **"存在"才比较**：边界元素只有一个邻居，甚至（当 $k$ 很大时）一个都没有，此时另一侧的条件**自动视为满足**；
- **严格大于**：相等不满足，所以判定要用 `<`（邻居小于自己）而不是 `<=`；
- **不加任何预处理**：直接双重判断，$O(n)$、$O(1)$ 空间。

### 3.3 算法流程

```text
1. sum = 0
2. for i = 0 .. n-1:
       good = true
       若 i-k >= 0 且 nums[i-k] >= nums[i]:  good = false
       若 i+k <  n 且 nums[i+k] >= nums[i]:  good = false
       若 good:  sum += nums[i]
3. 返回 sum
```

注意判定用的是"邻居**不小于**自己就淘汰"，这与"自己严格大于所有存在的邻居"完全等价，且只需处理两个方向各一次。

### 3.4 示例演算

![示例 1 的逐元素判定表：3、5、4 三个元素被计入](images/bw150_q1_walkthrough.svg)

对 `nums = [1,3,2,1,5,4]`、$k=2$：

| $i$ | $\text{nums}[i]$ | $i-k$ | $i+k$ | 结论 | 计入 |
|-----|------|-------|-------|------|------|
| 0 | 1 | 不存在 | 2（值 2） | $1 > 2$ 不成立 | — |
| 1 | 3 | 不存在 | 3（值 1） | $3 > 1$ ✓ | +3 |
| 2 | 2 | 0（值 1） | 4（值 5） | $2 > 5$ 不成立 | — |
| 3 | 1 | 1（值 3） | 5（值 4） | $1 > 3$ 不成立 | — |
| 4 | 5 | 2（值 2） | 不存在 | $5 > 2$ ✓ | +5 |
| 5 | 4 | 3（值 1） | 不存在 | $4 > 1$ ✓ | +4 |

总和 $3 + 5 + 4 = 12$，与题面一致。

## 4. 算法细节

1. **两个方向分别判**：写成"若存在且邻居 $\ge$ 自己则淘汰"，避免用一个 `&&` 把边界情况写乱。
2. **"严格大于"用 `>=` 淘汰**：`nums[i-k] >= nums[i]` 或 `nums[i+k] >= nums[i]` 都不行，等于也不满足。
3. **不用单独处理"两个都不存在"**：那时两个条件都不触发，`good` 保持 `true`，符合题意。
4. **下标范围**：$i - k \ge 0$ 与 $i + k < n$ 是唯一需要判断的越界条件，$k \ge 1$ 保证不会访问自身。
5. **求和用 `long long`/Python 原生整数**：$100 \times 1000 = 10^5$，`int` 足够，但写 `long long` 无害。

## 5. 正确性证明

**引理 1（判定式等价）**：对任意 $i$，`good(i)` 为真当且仅当 `nums[i]` 严格大于所有**存在的**邻居 $\text{nums}[i-k]$、$\text{nums}[i+k]$。

**证明**：分情况。若某侧下标不存在，该侧条件为真，与"不存在则无需比较"一致；若存在，条件为 $\text{nums}[i] > \text{nums}[\text{邻居}]$。两侧条件取合取，正是"严格大于所有存在的邻居"。∎

**定理**：算法返回值等于所有好元素之和。

**证明**：算法对每个 $i$ 恰好判定一次，由引理 1 判定结果与定义一致；当且仅当判定为好时把 `nums[i]` 加入总和。求和遍历了全部下标，故得到的是所有好元素之和，不重不漏。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素常数次比较，$n \le 100$。
- **空间**：$O(1)$。只用一个累加变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int sumOfGoodNumbers(vector<int>& nums, int k) {
        int n = (int)nums.size();
        long long sum = 0;
        for (int i = 0; i < n; i++) {
            bool good = true;
            if (i - k >= 0 && nums[i - k] >= nums[i]) good = false;
            if (i + k < n && nums[i + k] >= nums[i]) good = false;
            if (good) sum += nums[i];
        }
        return (int)sum;
    }
};
```

### Python

```python
class Solution:
    def sumOfGoodNumbers(self, nums: list[int], k: int) -> int:
        n = len(nums)
        total = 0
        for i, x in enumerate(nums):
            if i - k >= 0 and nums[i - k] >= x:
                continue
            if i + k < n and nums[i + k] >= x:
                continue
            total += x
        return total
```

## 8. 边界情况与易错点

1. **把"不存在"当成不合法**：边界元素只与存在的邻居比较，若写成"两个邻居都必须小于自己"，边界元素会被全部漏掉。
2. **相等不算好**：`nums[i] == nums[i+k]` 时不是好元素，用 `>=` 淘汰即可。
3. **$k$ 较大时可能一个邻居都没有**：如 $n = 3, k = 1$ 时中间元素两个邻居都在，而 $n=4,k=2$ 时 $i=1$ 只有右邻居。
4. **求和使用 `int` 足够**：上界 $100 \times 1000 = 10^5$，不会溢出；但仍建议中间量用宽类型。
5. **不要修改原数组**：本题是纯查询，任何排序/去重都会破坏下标关系。
6. **`k` 的取值范围**已保证 $k \le n/2$，因此"两个邻居都不存在"只会出现在 $k$ 接近 $n/2$ 的个别位置，仍需按规则处理。
