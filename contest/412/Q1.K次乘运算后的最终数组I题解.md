# LeetCode K 次乘运算后的最终数组 I 题解

## 1. 题目概述

- **标题 / 题号**：K 次乘运算后的最终数组 I（#3264，easy）
- **链接**：https://leetcode.cn/problems/final-array-state-after-k-multiplication-operations-i/
- **来源**：LeetCode 第 412 场周赛 Q1
- **难度**：简单
- **标签**：数组、堆（优先队列）、模拟

**题意**：给定整数数组 `nums`、整数 $k$ 与整数 `multiplier`（下记 $m$）。执行恰好 $k$ 次操作：每次取出 `nums` 的**最小值** $x$（并列时取**最前面**的），将其替换为 $x \cdot m$。返回最终的 `nums` 数组。元素**位置不动、只改值**——返回的是原下标序，不是排序结果。

**约束**：

- $1 \le n = \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 100$
- $1 \le k \le 10$
- $1 \le m \le 5$

> 💡 **签到定位**：$n \le 100$、$k \le 10$ 是白给的数据范围，暴力 $O(k \cdot n) \le 1000$ 次比较也能过。但**同场 Q3（#3266，困难）就是同一操作、$k$ 放大到 $10^9$ 且取模的强化版**——签到时直接写小根堆模拟版，「弹顶 $\times m$ 塞回」这份代码在 Q3 里原样充当「模拟阶段」。I 版按 II 版的结构写代码，是本题性价比最高的签到姿势。


## 3. 解题思路

### 3.1 暴力思路：每轮线性扫最小

每轮从头扫一遍数组找最小值下标（比较用**严格小于**，保证并列时保留更早下标），原地乘上 $m$，重复 $k$ 轮：

```python
for _ in range(k):
    idx = min(range(len(nums)), key=lambda j: nums[j])  # min 并列返回最前
    nums[idx] *= multiplier
```

时间 $O(k \cdot n)$、空间 $O(1)$，本题范围**可过**。浪费也明显：每轮都把「找最小」从零做起，上一轮的信息全部作废；$n, k$ 放大到 $10^5$ 量级（乃至 Q3 的 $10^9$ 轮）就不可接受。把「动态集合反复取最小」沉淀成数据结构，就是小根堆。

### 3.2 核心观察：小根堆装 (值, 下标) 二元组

![核心观察：小根堆装 (值, 下标) 二元组，并列取最前零特判](images/c412_q1_heap_concept.svg)

**观察 1（并列取最前 = 字典序 tie-break）**：把每个元素建模成 `(值, 下标)` 二元组塞进小根堆。`pair` / `tuple` 按字典序比较——值相等时自动比下标，小下标先弹。「并列取最前」这条规则**零特判**，二元组天然编码了它（示例 3 正是考这条）。

**观察 2（弹一个塞一个，堆序自持）**：$m \ge 1$ 意味着新值不小于旧值。每轮「弹出堆顶 → 乘 → 塞回去」，堆中始终维护全部 $n$ 个元素的**当前值**，堆序自动恢复，无需重建。

**观察 3（同步写回，原地成答）**：堆的弹出序是**值序**，题目要的是**下标序**——位置信息就藏在二元组里：每轮弹出的下标 $i$ 顺手执行 `nums[i] = x * m`，$k$ 轮跑完原数组本身就是答案，连收尾的一趟都省了。

**观察 4（连续被乘是正确行为）**：乘完的元素若仍是全局最小（如 `[1,100]` 乘 2 后 2 仍最小），下一轮弹出的还是它——堆不「嫌弃」刚塞回去的元素，这恰好就是题目语义。

> ⚠️ **值域核查**：最坏情况一个元素被乘满 $k = 10$ 次，值上界 $100 \times 5^{10} = 976{,}562{,}500 \approx 9.77 \times 10^8 < 2^{31} - 1$，`int` 不会溢出，可以放心乘。

### 3.3 算法流程

![算法流程：建堆、k 轮弹顶乘塞、同步写回](images/c412_q1_algorithm_flow.svg)

| 步骤 | 操作 | 要点 |
|------|------|------|
| ① 建堆 | 所有 `(nums[i], i)` 入小根堆 | `heapify` 一次 $O(n)$ |
| ② 弹顶 | 取出堆顶 `(x, i)`——全局最小，并列取小下标 | $O(\log n)$ 定位目标 |
| ③ 乘塞回 | `push (x·m, i)`，同步 `nums[i] ← x·m`，`k ← k − 1` | 堆序自动恢复 |
| ④ 收尾 | $k$ 轮用完，返回 `nums` | 原地更新，无收尾趟 |

> 💡 本题 $k \le 10$，循环**硬跑满就是全部工作**——不需要 Q3 那样的停机条件；反之，Q3 恰好是在这套循环的出口处加一个「堆顶 $\times m > mx$ 则停机」的判据，再接周期快进。同一份「阶段一」代码服务两题。

### 3.4 示例演算

![示例 1 演算：五轮弹顶乘塞，并列取最前出现两次](images/c412_q1_example_walkthrough.svg)

以示例 1（`nums = [2,1,3,5,6]`，$k = 5$，$m = 2$）为例：

- 建堆后堆顶是 `(1,1)`——全局最小 1 在下标 1，乘成 2 写回；
- 第 ② 轮：数组已是 `[2,2,3,5,6]`，两个 2 并列，堆中 `(2,0)` 与 `(2,1)` 值相等、比下标，弹出 `(2,0)`——**取最前**正是字典序的效果；第 ⑤ 轮两个 4 并列弹出 `(4,0)` 同理；
- 五轮结束，每步都已同步写回，`nums` 即 `[8,4,6,5,6]`。

观察每一轮：**被乘的格子值变大后自动「沉」下去**，后续轮次自然轮到别的最小格子——乘法在堆上完成了一次「自我调度」。

## 4. 算法细节

1. **二元组字典序 = 并列取最前**：C++ `priority_queue<pair<int,int>, vector<...>, greater<>>` 与 Python `heapq` 都按 `(值, 下标)` 字典序比较，小根堆先弹值最小者、值相等时下标最小者——与题意「最前面的一个」逐字对应，无需任何特判。
2. **带身份入堆**：值会变，但「身份」不能丢。下标既是 tie-break 的依据，又是写回原位置的地址（`nums[i]` 同步更新）。只塞裸值则并列时归属随机（见 §8 易错点 2）。
3. **$\text{multiplier} = 1$ 不需要特判**：弹顶乘 1 塞回，$k \le 10$ 轮跑完数组不变，天然正确。但同样这段循环放到 Q3（$k \le 10^9$）会傻跑满 $10^9$ 轮——那道题必须开头特判。本题顺手写上也不亏，防的是「把 Q1 代码直接复制进 Q3」的赛场事故。
4. **值域与类型**：值上界 $100 \times 5^{10} \approx 9.77 \times 10^8 < 2^{31}-1$，`int` 安全；Q3 规模（值 $10^9$、$m \le 10^6$）下判停机的中间量已达 $10^{15}$，必须 `long long`——本题练的就是「先核值域再选类型」的习惯。

## 5. 正确性证明

**引理 1（堆内容不变式）**：任意时刻，堆中恰好包含每个下标 $i$ 的一个二元组 $(\text{nums}[i],\ i)$。

**证明**：对已执行的操作轮数归纳。建堆后初始成立。每轮弹出的 $(\text{nums}[i], i)$ 与压回的 $(\text{nums}[i] \cdot m,\ i)$ 针对同一下标，且 `nums[i]` 同步更新为 $\text{nums}[i] \cdot m$——弹出与压入配对，堆内容（下标集合）不变，对应值与数组实况一致。∎

**引理 2（堆顶即题意目标）**：每轮弹出前，堆顶二元组恰为「值最小、值并列时下标最小」的元素。

**证明**：二元组按字典序比较：$(a, b) < (a', b') \iff a < a'$ 或（$a = a'$ 且 $b < b'$）。小根堆顶为字典序最小者：值互不相等时即值最小；值相等时下标最小即「最前面」。∎

**定理**：算法返回的数组与逐字模拟 $k$ 次操作的结果相同。

**证明**：对轮数归纳。设某轮开始前引理 1 成立。题意操作为「取最小、并列取最前者乘 $m$」；由引理 2，弹出的堆顶正是该元素，乘法与写回与题意一致；压回新值后引理 1 对下一轮保持。归纳至 $k$ 轮耗尽，全程每一步与逐字模拟相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k \log n)$。建堆 $O(n)$；$k$ 轮各一次弹出 + 一次压入，每次 $O(\log n)$；写回 $O(1)$。本题 $k \le 10$ 近乎瞬间完成；对照暴力 $O(k \cdot n)$，堆版对 $n, k$ 的增长都是对数级消化。
- **空间复杂度**：$O(n)$。堆中常驻 $n$ 个二元组（输出即原数组，不计额外）。

## 7. 参考代码

### C++（小根堆 + 二元组）

```cpp
class Solution {
public:
    vector<int> getFinalState(vector<int>& nums, int k, int multiplier) {
        using P = pair<int, int>;                        // (值, 下标)
        priority_queue<P, vector<P>, greater<P>> pq;     // 小根堆，字典序破平
        for (int i = 0; i < (int)nums.size(); ++i)
            pq.emplace(nums[i], i);                      // ① O(n) 建堆
        while (k--) {
            auto [x, i] = pq.top(); pq.pop();            // ② 全局最小，并列取小下标
            x *= multiplier;
            pq.emplace(x, i);                            // ③ 乘完塞回，堆序自持
            nums[i] = x;                                 //    同步写回原位置
        }
        return nums;                                     // ④ 原数组即答案
    }
};
```

### Python（heapq）

```python
from heapq import heapify, heappop, heappush
from typing import List

class Solution:
    def getFinalState(self, nums: List[int], k: int, multiplier: int) -> List[int]:
        heap = [(x, i) for i, x in enumerate(nums)]  # ① (值, 下标) 二元组
        heapify(heap)                                #    O(n) 建堆
        for _ in range(k):
            x, i = heappop(heap)                     # ② 全局最小，并列取小下标
            x *= multiplier
            heappush(heap, (x, i))                   # ③ 乘完塞回，堆序自持
            nums[i] = x                              #    同步写回原位置
        return nums                                  # ④ 原数组即答案
```

> 💡 两种语言的堆都按字典序比较二元组，`greater<>` / `heapq` 默认即小根——「并列取最前」零特判。

## 8. 边界情况与易错点

1. **$\text{multiplier} = 1$**：乘了等于没乘，数组原样返回。本题 $k \le 10$ 循环硬跑也不超时；同一份循环在 Q3（$k \le 10^9$）必须开头特判防超时——「边界值杀死停机条件」在姊妹题里才致命。
2. **并列最小值的归属（本题唯一考点）**：只存值不存下标，并列时归属由实现决定，直接出错。反例：`[4,4]`、$k=1$、$m=2$，正确 `[8,4]`，错取后者得 `[4,8]`（示例 3）。
3. **同一元素连续被乘**：`[1,100]`、$k=3$、$m=2$ → `1→2→4` 一路最小连乘三次得 `[8,100]`——是题目语义，不是堆的 bug（观察 4）。
4. **位置不动只改值**：返回原下标序，不要排序输出；排序会把「原地成答」的优势也一并丢掉。
5. **溢出核查**：本题值上界 $100 \times 5^{10} \approx 9.77 \times 10^8 < 2^{31}-1$，`int` 安全；到 Q3 规模（中间量 $\approx 10^{15}$、最终乘法 $\approx 10^{18}$）必须 `long long` + 取模——先核值域再选类型。
6. **不需要提前停机**：$k$ 只有 10 轮，不存在「跑不完」的问题；Q3 的停机条件、周期快进在这里全是多余的——别把简单题做复杂。
