# LeetCode 统计近似相等数对 I 题解

## 1. 题目概述

- **标题 / 题号**：统计近似相等数对 I（#3265，medium）
- **链接**：https://leetcode.cn/problems/count-almost-equal-pairs-i/
- **来源**：LeetCode 第 412 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数、枚举

**题意**：给定正整数数组 $nums$。若**至多一次**「选择 $x$ 或 $y$ 之一，交换该数的两个数位」可使 $x = y$，则称数对近似相等。返回满足 $i < j$ 且 $nums[i]$、$nums[j]$ 近似相等的数对数目。操作后允许**前导 0**（"30" 换成 "03" 就是 3）。

**约束**：

- $2 \le n \le 100$
- $1 \le nums[i] \le 10^6$

> 💡 **本场定位**：第 412 场是「I / II 双生题」专场——Q1/Q3 是乘法堆双生，Q2/Q4 是数位交换双生。Q4（#3267，困难）把 $n$ 放大到 5000、操作放宽到**至多两次**交换。本题 $n \le 100$，$O(n^2 \cdot d^2)$ 暴力稳过；但赛场上直接写**哈希计数版**——它是 Q4 的正解骨架，届时只需把变体闭包扩到两步。读题三个关键：①「至多一次」含**零次**，相等本身就算；②「选择 $x$ 或者 $y$ 之一」看着双向，3.2 节证明它能**塌缩成单向**判定；③ 前导 0 意味着**位数不同的数也能配上**（30 与 3），裸字符串比较必漏。

## 2. 示例

**示例 1**

```text
输入：nums = [3,12,30,17,21]
输出：2
解释：
  3 和 30 —— 交换 30 中的数位 3 和 0，得到 3（前导 0 型）。
  12 和 21 —— 交换 12 中的数位 1 和 2，得到 21（纯换位型）。
```

**示例 2**

```text
输入：nums = [1,1,1,1,1]
输出：10
解释：任意两元素都近似相等——「至多一次」含零次，相等即命中，C(5,2) = 10。
```

**示例 3**

```text
输入：nums = [123,231]
输出：0
解释：无法通过一次交换把 123 变成 231（循环移位需要两步）。
```

**示例 4**（自拟，防「变体集交集」误判）

```text
输入：nums = [213,132]
输出：0
解释：S(213) 与 S(132) 都含 123、312、231，但 132 ∉ S(213) 且 213 ∉ S(132)
     ——「变体集合有交集」不是近似相等的充分条件，一步互换才是。
```

## 3. 解题思路

### 3.1 暴力思路：逐对双向判定

$n \le 100$，数对至多 $\binom{100}{2} = 4950$ 个。对每对 $(a, b)$ 判定：$a = b$，或 $b \in \text{swap1}(a)$，或 $a \in \text{swap1}(b)$，其中 $\text{swap1}(x)$ 是 $x$ 的字符串任换两位后的**数值**集合。每数至多 7 位、$\binom{7}{2} = 21$ 种交换，总计约 $5 \times 10^5$ 次基本操作，稳过。

但暴力有两个必须绕开的坑：一是变体必须**数值化再比较**——"03" 与 "3" 字符串不等而数值相等，按串比较直接漏掉示例 1 的 $3$ 与 $30$；二是**双向判定不能省**——$[3, 30]$ 中 3 只有一位换不动，只能靠 30 的变体 $03 = 3$ 命中。更要命的是规模：同一份平方暴力搬到 Q4（$n = 5000$、两步交换）是 $1.25 \times 10^7$ 对 × 每对两轮闭包展开，彻底不可行。把「逐对判定」倒过来做「逐元素生成变体、哈希查之前的元素」，平方因子即消。

### 3.2 核心观察：一次交换是对合，补零恢复对称——「或」塌缩成单向

![核心观察：交换是对合，补前导零恢复对称，或条件塌缩成单向](images/c412_q2_swap_involution_concept.svg)

**观察 1（swap 是对合）**：把字符串的两位 $i, j$ 交换，对**同样两位**再换一次就还原。因此在**等长字符串**层面，$x$ 一步到 $y$ $\iff$ $y$ 一步到 $x$——「或」条件的两半天然等价。

**观察 2（前导 0 破坏对称，补零修复）**：数值层面 $30 \to 03 = 3$ 是**单向**的（3 只有一位换不动）。修复极其简单：$nums[i] \le 10^6$ 至多 7 位，**全部补前导 0 到定长 7 位**。"0000030" 换第 5、6 位得 "0000003"，反向同样是这一步——位数对齐后，对称性完整体恢复。

**观察 3（判定塌缩 + 一趟计数）**：定义 $S(x) = \{x\} \cup \{x \text{ 的一次交换变体}\}$（统一 7 位补零串生成、**数值化**入集合），则

$$\text{近似相等} \iff y \in S(x) \iff x \in S(y)$$

只需查一个方向。于是从左到右扫一遍：哈希表 $seen$ 记录**之前原值**的出现次数，处理 $x$ 时先 $ans \mathrel{+}= \sum_{v \in S(x)} seen[v]$，再 $seen[x] \mathrel{+}= 1$——与两数之和同款「先查后插」模板，只是查询键从一个 `target` 变成一个**变体集合**。$S$ 用集合去重（"11" 换两位不变、补零串里换两个 0 产生重复），保证每个数对至多计一次。

### 3.3 算法流程

![算法流程：补零定长、枚举交换生成变体、先查后插](images/c412_q2_hash_count_flow.svg)

| 步骤 | 操作 | 要点 |
|------|------|------|
| ① 补零 | $t \leftarrow x$ 的 7 位定长串 | $nums[i] \le 10^6$，位数 $\le 7$ |
| ② 生成变体 | $S \leftarrow \{x\}$；枚举 $0 \le i < j < 7$ 共 21 种交换，$t$ 换 $(i,j)$ → 数值化入 $S$ → **换回来** | 对合复用同一串；集合自动去重 |
| ③ 查 | $ans \mathrel{+}= \sum_{v \in S} seen[v]$ | 键两侧都用数值，键空间一致 |
| ④ 插 | $seen[x] \mathrel{+}= 1$，转下一个元素 | **必须后插**，否则 $x$ 命中自己 |

> ⚠️ 最容易写错的就是「先查后插」的顺序（图中橙色节点）：若先把 $seen[x]$ 加一再去查，$S(x) \ni x$ 会命中自己刚插入的记录，凭空多算一堆 $(x, x)$ 对。

### 3.4 示例演算

![示例 1 演算：两次命中分别是前导 0 型与纯换位型](images/c412_q2_example_walkthrough.svg)

以 $nums = [3, 12, 30, 17, 21]$ 走一遍（$S(x)$ 由 7 位补零串生成，展示数值）：

| $j$ | $x$ | $S(x)$ 关键变体 | 命中 $seen$ | $ans$ |
|-----|-----|-----------------|-------------|-------|
| 0 | 3 | $\{3,\ 30,\ 300,\ \dots,\ 3000000\}$ | — | 0 |
| 1 | 12 | $\{12,\ 21,\ 102,\ 120,\ \dots\}$ | — | 0 |
| 2 | 30 | $\{30,\ \mathbf{3},\ 300,\ \dots\}$ | $\checkmark\ seen[3] = 1$ | 1 |
| 3 | 17 | $\{17,\ 71,\ 107,\ \dots\}$ | — | 1 |
| 4 | 21 | $\{21,\ \mathbf{12},\ 120,\ \dots\}$ | $\checkmark\ seen[12] = 1$ | 2 |

两次命中恰好是两种典型：**前导 0 型**（"0000030" 末两位 "30" → "03"，数值 3）与**纯换位型**（"21" ↔ "12"）。输出 2 与示例一致 ✓。示例 2 中每个 $S(1)$ 虽含 $10, 100, \dots$ 等变体，但 $seen$ 里只有原值 1 命中，累计 $0+1+2+3+4 = 10$ ✓；示例 4 中 213 与 132 互不为对方变体（三循环需两步）→ 0 ✓。

## 4. 算法细节

1. **定长 7 位从哪来**：$nums[i] \le 10^6$，故位数 $\le 7$；统一补零到 7 位后，**所有数共享同一个串长与交换位置空间**（$\binom{7}{2} = 21$ 种），位数差异被前导 0 抹平——这正是观察 2 的落地。
2. **键空间一致性**：变体统一转 `int` 入集合，$seen$ 的键也是原值数值——两侧键空间天然一致（"0000003" 数值化后就是 3）。若一侧裸串、一侧补零串，则永远查不中，且示例 1 恰好能测出（$3$ 与 $30$ 这对全靠它）。
3. **换回来而非复制**：枚举 21 种交换时，对同一个 $t$「换 $(i,j)$ → 数值化 → **换回 $(i,j)$**」，利用对合零拷贝；若换后不还原，后续交换会叠加在已换的串上，产生**两步交换**的产物（如 "213" 误生出 "132"），直接破坏正确性。
4. **$S$ 必须含 $x$ 自身**：这一项覆盖「零次操作」——漏掉它，示例 2 的 10 对全部归零。
5. **集合去重**：全同数位（111、补零串里的 0）交换不变会产生重复变体；不去重的话 $seen[v]$ 会被同一个数对重复累加。
6. **值域核查**：7 位补零串任意交换后的数值 $\le 9\,999\,999 < 2^{31} - 1$，`int` 安全，无需 64 位。

## 5. 正确性证明

**引理 1（定长串上单次交换的对称性）**：设 $X, Y$ 为等长串。若 $X$ 经一次数位交换（位置 $i < j$）得到 $Y$，则 $Y$ 经一次数位交换也可得到 $X$。

**证明**：位置交换 $\sigma_{i,j}$ 是**对合**：$\sigma_{i,j} \circ \sigma_{i,j} = \mathrm{id}$。$Y = \sigma_{i,j}(X)$ 时，$\sigma_{i,j}(Y) = \sigma_{i,j}(\sigma_{i,j}(X)) = X$。∎

**引理 2（判定的塌缩）**：对数值 $x, y$（补零串 $X, Y$），以下三条等价：(a) $x, y$ 近似相等；(b) $y \in S(x)$；(c) $x \in S(y)$。

**证明**：(a) $\iff$ $X = Y$，或 $X$ 一步到 $Y$，或 $Y$ 一步到 $X$。若 $X = Y$，则数值相等，$y = x \in S(x)$ 且 $x = y \in S(y)$。若 $X$ 一步到 $Y$，则 $y \in S(x)$；且由引理 1，$Y$ 一步到 $X$，故 $x \in S(y)$。反之，(b) $\iff$ $y = x$（零次）或 $X$ 一步到 $Y$，均推出 (a)。数值化不损失信息：每个数值的 7 位补零串唯一，串相等 $\iff$ 数值相等。∎

**定理（一趟扫描计数的正确性）**：算法返回值恰为 $\#\{(i, j) : i < j,\ nums[i] \text{ 与 } nums[j] \text{ 近似相等}\}$。

**证明**：对处理到第 $j$ 个元素时的状态归纳——不变式：$seen$ 是 $\{nums[i] : i < j\}$ 的多重计数，$ans$ 是 $\{(i, j') : i < j' < j,\ \text{近似相等}\}$ 的基数。处理 $x = nums[j]$ 时，增量为

$$\Delta = \sum_{v \in S(x)} seen[v] = \#\{i < j : nums[i] \in S(x)\}$$

（$S$ 去重保证每个 $i$ 至多计一次）；由引理 2，$nums[i] \in S(x) \iff nums[i]$ 与 $x$ 近似相等。随后 $seen[x] \mathrel{+}= 1$ 维护不变式。对 $j = 0, 1, \dots, n-1$ 求和，全部数对恰好各计一次。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot D^2)$，其中 $D = 7$ 为定长串位数。每个数生成 $1 + \binom{7}{2} = 22$ 个候选变体（去重后更少）并查哈希；$n = 100$ 约 2200 次查插。对照暴力 $O(n^2 \cdot D^2)$：$n$ 的平方因子被「先查后插」消成一趟线性扫描——这也是 Q4（$n = 5000$）唯一可行的路。
- **空间复杂度**：$O(n)$。$seen$ 哈希表随元素数增长；单个变体集合 $O(D^2) = O(1)$，逐元素即弃。

## 7. 参考代码

### C++（补零 + 变体集合 + 先查后插）

```cpp
class Solution {
public:
    int countPairs(vector<int>& nums) {
        unordered_map<int, int> seen;          // 之前原值 → 出现次数
        int ans = 0;
        for (int x : nums) {
            string t = to_string(x);
            t = string(7 - t.size(), '0') + t; // ① 补前导 0 到定长 7 位
            unordered_set<int> S{x};           //   零次操作：自身
            for (int i = 0; i < 7; ++i)
                for (int j = i + 1; j < 7; ++j) {
                    swap(t[i], t[j]);          // ② 一次交换
                    S.insert(stoi(t));         //   "0000003" → 3，前导 0 自动消
                    swap(t[i], t[j]);          //   换回来（对合！）
                }
            for (int v : S)                    // ③ 先查
                if (auto it = seen.find(v); it != seen.end())
                    ans += it->second;
            ++seen[x];                         // ④ 后插
        }
        return ans;
    }
};
```

### Python（itertools.combinations 枚举交换位）

```python
from collections import Counter
from itertools import combinations
from typing import List

class Solution:
    def countPairs(self, nums: List[int]) -> int:
        seen = Counter()                       # 之前原值 → 出现次数
        ans = 0
        for x in nums:
            t = f"{x:07d}"                     # ① 补前导 0 到定长 7 位
            S = {x}                            #   零次操作：自身
            lst = list(t)
            for i, j in combinations(range(7), 2):
                lst[i], lst[j] = lst[j], lst[i]
                S.add(int(''.join(lst)))       # ② "0000003" → 3
                lst[i], lst[j] = lst[j], lst[i]  #   换回来（对合！）
            ans += sum(seen[v] for v in S)     # ③ 先查
            seen[x] += 1                       # ④ 后插
        return ans
```

> 💡 两份代码结构逐行对应四个步骤；`stoi` / `int()` 自动消前导 0，与 $seen$ 的数值键天然同空间。

## 8. 边界情况与易错点

1. **「至多一次」含零次**：$S$ 必须含 $x$ 自身。漏掉这一项，示例 2 的 10 对全归零——「相等」是最常见的漏判。
2. **前导 0 型数对**：$[3, 30]$、$[10, 1, 100]$（答案 3）全靠补零串交换后数值化命中。任何按裸字符串比较键的写法都会漏；补零定长 + `int` 键是最省心的修法。
3. **交换后必须换回来**：不还原会让 21 种交换互相叠加，产生两步交换的产物（"213" 误生出 "132"），把答案算大。每次复制新串也可，但「换回」零拷贝且正好体现对合。
4. **变体集合要去重**：交换两个相同数位（"11"、补零串中的两个 0）结果不变，全同数位的所有交换都回到自身。不去重则同一数对被重复累加。
5. **变体集交集 ≠ 近似相等**：$[213, 132]$ 的变体集都含 $123/312/231$，但互不为对方的一步变体（三循环需两步），答案 0——判据必须是「$y \in S(x)$」，不是「$S(x) \cap S(y) \ne \varnothing$」。
6. **先查后插的顺序**：先插后查会让 $x$ 命中自己（$S \ni x$），凭空多算 $(x, x)$ 对；顺序对了，$i < j$ 的约束由「表里只有之前的元素」天然保证。
7. **值域**：变体是 7 位补零串的重排，数值 $\le 9\,999\,999$，`int` 足够；到 Q4 也无需换 `long long`（数值本身没变大）。
8. **别排序**：本题与顺序无关（只需 $i<j$ 的计数），先排序再双指针反而绕远——官方标签里的 Sorting 是另一条可行路的痕迹，不是必需。
