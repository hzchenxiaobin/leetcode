# LeetCode 得到 0 的操作数 题解

## 1. 题目概述

- **标题 / 题号**：得到 0 的操作数（#2169，easy）
- **链接**：https://leetcode.cn/problems/count-operations-to-obtain-zero/
- **来源**：LeetCode 第 280 场周赛 Q1
- **难度**：简单
- **标签**：数学、模拟、数论

**题意**：给定两个**非负**整数 `num1` 和 `num2`，每步操作中：若 $\text{num1} \ge \text{num2}$ 则 $\text{num1} \mathrel{-}= \text{num2}$，否则 $\text{num2} \mathrel{-}= \text{num1}$。返回直到某一数变为 $0$ 所执行的操作总数。

**约束**：

- $0 \le \text{num1}, \text{num2} \le 10^5$

> 💡 **读题定位**：签到题。照题意写一个 `while` 循环逐次相减即可 AC——最坏约 $10^5$ 次循环，约束内毫无压力，这是赛场上 3 分钟交卷的最短路径。本题的复盘价值在于识别出它是**辗转相减法（更相减损术）的计数版**：把「一串同向连减」折叠成「一次除法取商」即可降到 $O(\log \max)$——与快速幂「把连乘折叠成平方」是同一个**批量折叠**思维，套路可迁移。

> 💡 本题在本仓库另有[每日题解 2169](../../solution/2101-2200/2169_得到0的操作数.md)：主线同为「连减批量化为除法」，附与 GCD 的同构对照表及面试问答。本篇按**周赛复盘视角**展开：给出对称性引理 + 批量刻画引理 + 两版本计数一致的完整正确性链、答案上界 $O(\text{num1}+\text{num2})$ 的初等论证、以及「操作数不是 $\gcd$ 的函数」这类赛场易错点，两篇互为印证。

## 2. 示例

**示例 1**（官方）

```text
输入：num1 = 2, num2 = 3
输出：3
解释：
  操作 1：2 < 3，num2 = 3 - 2 = 1 → (2, 1)
  操作 2：2 ≥ 1，num1 = 2 - 1 = 1 → (1, 1)
  操作 3：1 ≥ 1，num1 = 1 - 1 = 0 → (0, 1)，停止。
```

**示例 2**（官方：相等输入一步归零）

```text
输入：num1 = 10, num2 = 10
输出：1
解释：10 ≥ 10，num1 = 10 - 10 = 0，一步停止。
```

**示例 3**（自造：多轮辗转，覆盖方向来回反转）

```text
输入：num1 = 7, num2 = 3
输出：5
解释：7 → 4 → 1（连减两次 3），3 → 2 → 1 → 0（连减三次 1），
      共 2 + 3 = 5 次操作。
```

**示例 4**（自造：零边界）

```text
输入：num1 = 0, num2 = 5
输出：0
解释：初始即有 num1 = 0，无需任何操作。
```

## 3. 解题思路

### 3.1 暴力思路：照题意逐次相减

维护计数器 `ops`，只要两数都大于 $0$ 就按大小关系做一次减法并计数：

```text
ops = 0
while num1 > 0 and num2 > 0:
    if num1 >= num2: num1 -= num2
    else:            num2 -= num1
    ops += 1
return ops
```

每次操作两数之和至少减少 $1$（减数 $\ge 1$），故总操作数 $\le \text{num1}+\text{num2} \le 2\times10^5$——本题约束下这就是**与数据范围匹配的正解**，赛时直接交。它的短板只在扩展性：约束一旦放大到 $10^{18}$，逐次相减立即不可行。

### 3.2 核心观察：一串同向连减 = 一次除法

![核心观察：一串同向连减等价于一次除法取商与余数](images/wc280_q1_concept.svg)

暴力版浪费在哪？当 $\text{num1} \gg \text{num2}$ 时，会**连续多次执行同方向的减法** $\text{num1} \mathrel{-}= \text{num2}$，方向不变。设这一串连减共 $k$ 次，写 $\text{num1} = q \cdot \text{num2} + r$（$0 \le r < \text{num2}$），则：

$$
k = q = \left\lfloor \frac{\text{num1}}{\text{num2}} \right\rfloor, \qquad \text{num1}_{\text{新}} = \text{num1} \bmod \text{num2} = r
$$

即「连减到方向反转（或归零）」恰好等价于「做一次除法」：**商 $q$ 是这一段贡献的操作数，余数 $r$ 是替换进去的新值**。这正是辗转相减法的批量版——辗转相除法（欧几里得算法）的同构形式。GCD 只留余数、丢掉商；本题还要把每轮的商累加进答案。

### 3.3 算法流程：除法批量版

![算法流程：循环内按大小取商累加、取模替换，直到某个数归零](images/wc280_q1_algorithm_flow.svg)

1. `ops = 0`；
2. 当 `num1 > 0` 且 `num2 > 0` 时循环：
   - 若 $\text{num1} \ge \text{num2}$：`ops += num1 / num2`，`num1 %= num2`；
   - 否则：`ops += num2 / num1`，`num2 %= num1`；
3. 返回 `ops`。

循环条件 `> 0` 天然保证除数非零；每轮较大数被替换为「较大数 $\bmod$ 较小数」，严格减小，必然终止。最坏轮数由拉梅定理给出 $O(\log \max(\text{num1},\text{num2}))$——最坏输入是相邻斐波那契数（每轮商恰为 $1$，批量版退化回逐次版，但轮数仍是 $O(\log)$ 级）。

### 3.4 示例演算

![示例演算：(7,3) 与官方示例 (2,3) 的逐轮走查表](images/wc280_q1_example_walkthrough.svg)

以 $\text{num1}=7,\ \text{num2}=3$（示例 3）走查批量版：

| 轮次 | num1 | num2 | 比较 | 商 $q$ | 余数 $r$ | 累计 ops |
|------|------|------|------|--------|----------|----------|
| 1 | 7 | 3 | $7 \ge 3$ | $7/3 = 2$ | $1$ | $2$ |
| 2 | 1 | 3 | $1 < 3$ | $3/1 = 3$ | $0$ | $5$ |

第 2 轮后 `num2 = 0` 退出，返回 $5$ ✓。对照暴力：$7 \to 4 \to 1$ 共 2 次、$3 \to 2 \to 1 \to 0$ 共 3 次，一致。

官方示例 1 的 $(2, 3)$：第 1 轮 $3/2 = 1$、余 $1$，ops $= 1$；第 2 轮 $2/1 = 2$、余 $0$，ops $= 3$ ✓。两轮走查等价于暴力的 3 次逐减——高亮格的余数正是下一轮替换进去的新值。

## 4. 算法细节

1. **批量段的精确刻画**：设 $a \ge b > 0$，$a = qb + r$（$0 \le r < b$）。则从 $(a, b)$ 起**恰好**连做 $q$ 次「$a$ 减 $b$」：第 $k$ 次（$k \le q$）操作前 $a$ 侧值为 $(q-k+1)b + r \ge b$，条件始终成立；第 $q$ 次后 $a$ 侧降为 $r < b$，方向反转（或 $r = 0$ 直接终止）。商就是本段操作数，不多不少。

2. **无序对视角**：交换 `num1`、`num2` 不改变操作计数（见引理 0），因此实现里不必刻意排序或 `swap`，每轮用 `if (num1 >= num2)` 分流即可，两支代码对称。

3. **除零防护**：循环条件 `num1 > 0 && num2 > 0` 保证进入循环体时除数必非零。不要改成 `do-while` 或「先除后判」，否则零输入立即除零。

4. **答案上界与整型选择**：每次操作两数之和至少减 $1$，故 $\text{ops} \le \text{num1}+\text{num2} \le 2\times 10^5$，`int` 绰绰有余。本题无需 `long long`；但若约束放宽到 $10^{18}$，单轮商即可达 $10^{18}$，届时 C++ 须换 `long long` 累加（Python 天然大数无此虑）。

5. **为什么批量版是 $O(\log)$ 而非 $O(\sqrt{\cdot})$ 级**：每轮结束后「新较大数 = 旧较小数」，且新较小数 $= r <$ 旧较小数。经典结论：每两轮必使较大数至少减半（否则 $r = a - qb \ge b$ 矛盾于 $r < b$ 的情形会连续出现——精确表述即拉梅定理，最坏输入是相邻斐波那契数）。对 $10^5$ 规模至多约 $25$ 轮。

## 5. 正确性证明

**约定**：把状态 $(\text{num1}, \text{num2})$ 视为**无序对** $\{a, b\}$，操作规则即「较大数减去较小数；相等时任选一方」。

**引理 0（对称性）**：交换 `num1`、`num2` 的初值，操作总数不变。

**证明**：对操作步数归纳。设某步前两版本状态互为交换。规则「若 $\text{num1} \ge \text{num2}$ 则 $\text{num1} \mathrel{-}= \text{num2}$，否则 $\text{num2} \mathrel{-}= \text{num1}$」在交换下协变：$a \ge b$ 时原状态得 $\{a-b,\ b\}$，交换状态同样得 $\{b,\ a-b\}$，作为无序对完全一致（$a = b$ 时双方都一步归零）。归纳即得全过程无序对序列相同，计数相同。∎

**引理 1（批量刻画）**：设无序对 $\{a, b\}$ 中 $a \ge b > 0$，$a = qb + r$（$0 \le r < b$）。则接下来恰好 $q$ 次操作均由「$a$ 侧减 $b$」执行，随后到达状态 $\{r,\ b\}$；且 $r = 0$ 时恰在第 $q$ 次操作后出现零。

**证明**：第 $k$ 次（$1 \le k \le q$）操作前 $a$ 侧值为 $a - (k-1)b = (q-k+1)b + r$。由 $q - k + 1 \ge 1$ 得该值 $\ge b$（$r = 0$ 且 $k = q$ 时恰等于 $b$，仍满足 $\ge$），故「$a$ 减 $b$」的条件成立，第 $k$ 次仍由 $a$ 侧执行。第 $q$ 次后 $a$ 侧值为 $r < b$：若 $r = 0$ 则已出现零；否则下一轮角色互换。期间不可能提前停止（前 $q-1$ 次后值 $\ge b + r' > 0$）。∎

**引理 2（终止性）**：逐步模拟至多执行 $\text{num1} + \text{num2}$ 次操作。

**证明**：两数均正时，每次操作从和中减去 $\min(\text{num1}, \text{num2}) \ge 1$，和严格递减且非负，故有限步内某一数必为 $0$。∎

**定理（批量版计数正确）**：除法批量算法返回值等于按题意逐步模拟的操作数。

**证明**：由引理 0 可按无序对讨论。对批量轮数归纳：设当前无序对 $\{a, b\}$，$a \ge b > 0$。由引理 1，逐步版接下来 $q = \lfloor a/b \rfloor$ 次操作恰好构成批量版的一轮——批量版执行 `ops += q` 并把状态替换为 $\{r, b\}$（$r = a \bmod b$），两版本状态与计数逐轮对齐。若 $r = 0$，逐步版恰在第 $q$ 次后归零停止，批量版同轮后检测到零退出循环。归纳链衔接至终止（引理 2 保证逐步版终止，批量版每轮较大数严格减小亦然），两版本操作总数相等。∎

> 💡 **证明结构复盘**：引理 0 是「无损抽象」（把有序对退化为无序对），引理 1 是「批量折叠的精确刻画」（商不多算不少算），定理把两者粘合成两算法的逐轮双射。「先证抽象不丢信息、再证折叠精确、最后对齐两过程」——这正是快速幂、倍增、矩阵快速幂等一切「折叠加速」类算法的正确性证明模板。

## 6. 复杂度分析

- **时间复杂度**：暴力版 $O(\text{num1}+\text{num2})$，本题最坏约 $2\times10^5$ 次整数减法，约束内可过；除法批量版 $O(\log \max(\text{num1},\text{num2}))$（拉梅定理，$10^5$ 规模至多约 $25$ 轮，每轮一次除法一次取模）。
- **空间复杂度**：两种实现均为 $O(1)$，仅 `ops`、`num1`、`num2` 三个变量，无额外数据结构。

## 7. 参考代码

### C++

赛时保底版（逐次相减，约束内可过）：

```cpp
class Solution {
  public:
    int countOperations(int num1, int num2) {
        int ops = 0;
        while (num1 > 0 && num2 > 0) {
            if (num1 >= num2) {
                num1 -= num2;
            } else {
                num2 -= num1;
            }
            ++ops;
        }
        return ops;
    }
};
```

除法批量版（推荐，$O(\log)$）：

```cpp
class Solution {
  public:
    int countOperations(int num1, int num2) {
        int ops = 0;
        while (num1 > 0 && num2 > 0) {
            if (num1 >= num2) {
                ops += num1 / num2;
                num1 %= num2;
            } else {
                ops += num2 / num1;
                num2 %= num1;
            }
        }
        return ops;
    }
};
```

### Python

```python
class Solution:
    def countOperations(self, num1: int, num2: int) -> int:
        ops = 0
        while num1 > 0 and num2 > 0:
            if num1 >= num2:
                ops += num1 // num2
                num1 %= num2
            else:
                ops += num2 // num1
                num2 %= num1
        return ops
```

> ⚠️ Python 必须用 `//` 整除：误写 `/` 会得到浮点数，后续取模与比较全部失真。暴力版同理把 `-= 1` 计数写进 `while` 即可，此处从略。

## 8. 边界情况与易错点

1. **零输入直接返回 0**：$\text{num1} = 0$ 或 $\text{num2} = 0$ 时一步操作都不需要。`while (num1 > 0 && num2 > 0)` 天然处理；若改写为 `do-while` 或「先做一次除法再判空」，立即除零或多算一次。

2. **相等输入一步归零**：$(10, 10)$ 返回 $1$。`>=` 保证相等时由 `num1` 侧执行，一次减到 $0$ 即停——批量版里对应「商 $q = 1$、余 $r = 0$」，一轮退出。

3. **除零防护依赖循环条件**：进入循环体时两数均 $> 0$，除数必然非零。任何「把取模提前」「循环外先除一次」的重排都会破坏这一前提。

4. **溢出评估**：$\text{ops} \le \text{num1}+\text{num2} \le 2\times10^5$，`int` 充裕。但别把这条经验无条件带走的题：约束若放宽到 $10^{18}$，单轮商可达 $10^{18}$，C++ 必须 `long long` 累加。

5. **Python 的 `//` 与 `/`**：整除误写 `/` 得浮点，是 Python 赛场最常见的低级失分点之一；本题函数签名返回 `int`，浮点结果甚至可能侥幸通过部分用例，危害更隐蔽。

6. **操作数不是 $\gcd$ 的函数**：$(6, 4)$ 需要 $3$ 次、$(4, 2)$ 需要 $2$ 次，而 $\gcd$ 同为 $2$——**不能**只求出 $\gcd$ 再想办法折算，答案依赖输入本身在辗转过程中的整条商链。

7. **批量段「不多算」的直觉校验**：$a = qb$（整除）时，前 $q - 1$ 次减到 $(b, b)$，第 $q$ 次减到 $0$——商恰为 $q$，不多不少。若误以为「整除时只算 $q-1$ 次」会在 $(10,10)$、$(4,2)$ 类输入上少算。

8. **Q1 策略复盘**：约束 $10^5$ 下暴力版完全可过，赛时最短路径就是暴力；除法批量版的价值是**约束放大后依然成立**的同结构升级，写完暴力花两分钟折叠成除法，是零成本的降复杂度训练。
