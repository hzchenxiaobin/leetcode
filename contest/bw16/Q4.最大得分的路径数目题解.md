# LeetCode 最大得分的路径数目 题解

## 1. 题目概述

- **标题 / 题号**：最大得分的路径数目（#1301，hard）
- **链接**：https://leetcode.cn/problems/number-of-paths-with-max-score/
- **来源**：LeetCode 第 16 场双周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、矩阵

**题意**：给定 $n \times n$ 字符矩阵 `board`，从**右下角**的 `'S'` 出发，目标是**左上角**的 `'E'`。每步只能**向上、向左或左上**移动，且不能进入障碍 `'X'`。路径得分为路径上数字字符（`'1'`~`'9'`）之和（`S`、`E` 不计分）。返回 $[\text{最大得分},\ \text{取得最大得分的路径数} \bmod (10^9+7)]$；若 `E` 不可达返回 $[0, 0]$。

**约束**：

- $2 \le board.length = board[i].length \le 100$
- 除 `S`、`E`、`X` 外均为数字字符

## 2. 示例

**示例 1**

```text
输入：board = ["E23","2X2","12S"]
输出：[7,1]
解释：唯一最优路径为 S→上(2)→上(3)→左(2)→E（得分 2+3+2=7）。
     注意 (1,1) 是 X，对角线被挡，路径必须绕行。
```

**示例 2**

```text
输入：board = ["E12","1X1","21S"]
输出：[4,2]
解释：两条得分 4 的路径：
     S→上(1)→上(2)→左(1)→E（右列绕上去）与
     S→左(1)→左(2)→上(1)→E（底行绕过去）。
```

**示例 3**

```text
输入：board = ["E11","XXX","11S"]
输出：[0,0]
解释：中间整行是障碍，S 无法抵达 E。
```

## 3. 解题思路

### 3.1 暴力思路

从 `S` 出发 DFS 枚举全部 $3^{\ell}$ 条路径（$\ell$ 为步数上界，$n = 100$ 时天文数字），维护最大得分与计数。指数爆炸，必须用 DP 合并「同格同尾」的路径。

### 3.2 核心观察：起点在右下、终点在左上 → 倒序 DP 顺势而为

![反向 DP 模型：f[r][c] 依赖下方/右方/右下三方](images/bw16_q4_reverse_dp_model.svg)

正向走只能「上 / 左 / 左上」，即坐标单调减小。把视角反过来定义——

$$f[r][c] = \text{从 } (r,c) \text{ 出发走到 } E(0,0) \text{ 的最大得分},\qquad g[r][c] = \text{方案数}$$

则 $f[r][c]$ 依赖 $(r+1,c),\ (r,c+1),\ (r+1,c+1)$ —— 恰好是**行、列都更大的格子**。于是按 $r$ 从 $n-1$ 到 $0$、$c$ 从 $n-1$ 到 $0$ 的双重循环，被依赖者先算好，一个循环方向天然无后效性。边界是 $f[n-1][n-1] = 0$（`S` 自身不计分），障碍格与越界视为不可达（$f = -1$）。

### 3.3 算法流程：每个格子「先取 max 再按等于 max 的邻居累加计数」

![每个格子的两步转移](images/bw16_q4_dp_flow.svg)

```text
初始化：f[n-1][n-1] = 0, g[n-1][n-1] = 1；其余 f = -1, g = 0
for r = n-1 down to 0:
    for c = n-1 down to 0:
        跳过 S 格与 X 格
        best = max{ f[r+1][c], f[r][c+1], f[r+1][c+1] }（仅取 ≥ 0 者）
        若 best < 0：该格不可达，continue（保持 f=-1, g=0）
        f[r][c] = best + ch(r,c)        # ch：数字为数值，'E' 为 0
        g[r][c] = Σ g[邻]，只对 f[邻] == best 的邻居累加，逐次取模
返回 f[0][0] < 0 ? [0,0] : [f[0][0], g[0][0]]
```

**计数的关键纪律**：比较用 `f` 的**原值**（未取模的得分，最大 $9 \times 199 < 2000$，不会溢出），累加才对 `g` 取模——若拿取模后的 `g` 参与「等于 best」判断，逻辑立刻崩坏（计数才需要模，得分不需要）。

### 3.4 示例演算

![示例 2 的 f 表与 g 表走查](images/bw16_q4_example_walkthrough.svg)

以示例 2（`board = ["E12","1X1","21S"]`，行 0 在上）演算：

| 格子 | ch | 三邻（下/右/右下）f 值 | best | f | g |
|------|----|------------------------|------|---|---|
| (2,2) `S` | 0 | —（初始化） | — | 0 | 1 |
| (2,1) | 1 | 下越界，右 f=0，右下越界 | 0 | 1 | 1 |
| (2,0) | 2 | 右 f=1 | 1 | 3 | 1 |
| (1,2) | 1 | 下 f=0，右越界 | 0 | 1 | 1 |
| (1,1) `X` | — | — | — | −1 | 0 |
| (1,0) | 1 | 右 f=−1，下 f=3，右下 f=1 | 3 | 4 | 1 |
| (0,2) | 2 | 下 f=1 | 1 | 3 | 1 |
| (0,1) | 1 | 右 f=3，下 f=−1，右下 f=1 | 3 | 4 | 1 |
| (0,0) `E` | 0 | 右 f=4，下 f=4，右下 f=−1 | 4 | 4 | g(0,1)+g(1,0) = 2 |

返回 $[4, 2]$。✓ 两条最优路径：$S(2,2) \to (1,2) \to (0,2) \to (0,1) \to E$（右列绕上，$1+2+1=4$）与 $S(2,2) \to (2,1) \to (2,0) \to (1,0) \to E$（底行绕左，$1+2+1=4$），恰对应 `E` 的两个「达到 best=4」的后继 $(0,1)$ 与 $(1,0)$。

## 4. 算法细节

1. **为什么倒序而不是正序**：正向定义 $h[r][c] = $ 从 $S$ 到 $(r,c)$ 的最大得分也完全可行，依赖变为 $(r-1,c),(r,c-1),(r-1,c-1)$，按 $r, c$ 升序枚举即可。倒序版的好处是 `S`（初始化点）与答案点 `E` 的语义直观：**从任意格到 `E`** 的函数天然把「不可达」编码为 $f = -1$，最终 `f[0][0] < 0` 即返回 `[0,0]`，无需额外标记数组。
2. **得分上限与取模**：路径至多 $2n - 2 = 198$ 步、每格 $\le 9$，得分 $\le 1782$，`int` 富余；**`g` 才是必须取模的量**（路径数可指数增长）。计数累加处 `(g[r][c] += g[nr][nc]) %= MOD`。
3. **`-1` 哨兵的鲁棒性**：不可达用 $f = -1$ 而不是 $0$——若用 0，「经过一串 0 分格子」与「不可达」无法区分（本题数字 $\ge 1$ 无碍，但哨兵写法在任何变体下都稳）。
4. **`S` 格的特判**：`S` 是初始化点，循环里要跳过（`r==n-1 && c==n-1` 时 `continue`），否则会被当作普通格重新计算（其三邻全越界，`best<0` 会把已设好的 $f=0$ 保持——但保险起见显式跳过）。
5. **`X` 格跳过时机**：在循环开头跳过即可，$f$ 保持 $-1$，自动成为邻居眼中的「不可达」，无需显式置数。
6. **C++ 结构化绑定遍历邻居**：`for (auto& [nr, nc] : from)` 配合数组 `{{r+1,c},{r,c+1},{r+1,c+1}}`，比展开三段重复代码更不易错；注意 `nr < n && nc < n` 的越界检查（负方向由循环顺序天然排除：$r+1 \ge 1 > -1$ 恒真，无需判下界）。
7. **两遍扫邻居可合并为一遍吗**：可以——先算 `best` 再累加的两趟其实能合并成「打擂台 + 同分累加」的单趟（维护当前最优与计数，遇更大者重置），但两趟写法更直白、调试更容易，$n = 100$ 时性能毫无差别。

## 5. 正确性证明

**引理 1（状态等价）**：$f[r][c]$ 等于所有从 $(r,c)$ 出发、仅经非障碍格、终于 $(0,0)$ 的路径的最大得分；$g[r][c]$ 等于取得该最大得分的路径条数（不取模意义下）。无路径时 $f[r][c] = -1$。

**证明**：对 $r + c$ 从大到小归纳（基例：$(n-1,n-1)$，零步路径得分 0、条数 1，与初始化一致；$(0,0)$ 自身若为起点则不属于讨论——注意 `E` 格的值不计分）。任何从 $(r,c)$ 出发的合法路径，第一步必达 $(r+1,c),(r,c+1),(r+1,c+1)$ 三者之一（正向移动的逆），此后是从该后继出发的合法路径。反之，后继处的任何合法路径接上这一步仍合法且得分恰增 $ch(r,c)$。故「$(r,c)$ 处路径得分的集合」$= ch(r,c) + \bigcup_{\text{后继}}$「后继处路径得分集合」，最大值与计数随之按引理所述递推（计数取并集中等于最大值的总数，注意两个不同后继的路径集互不相交——首步不同）。障碍格无路径出发（第一步即非法或自身不可站）。∎

**引理 2（取模不破坏计数）**：算法对 $g$ 的每次累加后取模 $10^9+7$，不影响任何「$\pm 1 \bmod (10^9+7)$」意义下计数的正确性；$f$ 全程不取模，比较 `f[邻] == best` 用的是精确得分。

**证明**：取模是环同态 $\mathbb{Z} \to \mathbb{Z}/(10^9+7)$，加法结构保持；计数路径条数只需加法（后继计数两两不相交地相加），故模运算下结果与「先精确计数最后取一次模」一致。$f$ 的最大值为 $1782 < 10^9$，精确存储与比较无歧义。∎

**定理**：算法返回 $[\max, \max \bmod\text{意义下的方案数}]$，其中 $\max$ 是 `S` 到 `E` 的最大路径得分；不可达时返回 $[0,0]$。

**证明**：由引理 1（含归纳实现与循环顺序：$r+1$ 行先于 $r$ 行整体算完，$c+1$ 列先于 $c$ 列，故三邻在被读取时已是终值），$f[0][0], g[0][0]$ 即所求；`E` 格 $ch = 0$ 使其自身不计分。由引理 2，返回的计数模 $10^9+7$ 正确。当 `E` 不可达时 $f[0][0] = -1 < 0$，按题意返回 $[0,0]$。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。每格常数个邻居检查（3 个方向、各 $O(1)$），$n = 100$ 时约 $3 \times 10^4$ 次操作。
- **空间**：$O(n^2)$。`f`、`g` 两个 $n \times n$ 矩阵。可滚动到 $O(n)$（`f`/`g` 各一行，注意右下对角依赖需要暂存左下旧值），但 $n = 100$ 时二维数组仅 $10^4$ 个整数，不值得为省这点空间增加错风险。

## 7. 参考代码

### C++

```cpp
class Solution {
    static constexpr int MOD = 1'000'000'007;
public:
    vector<int> pathsWithMaxScore(vector<string>& board) {
        int n = (int)board.size();
        // f[r][c]：从 S(r,c) 出发到达 E(0,0) 的最大得分；g[r][c]：方案数
        vector<vector<int>> f(n, vector<int>(n, -1)), g(n, vector<int>(n, 0));
        f[n - 1][n - 1] = 0;                     // S 格：得分 0、方案 1
        g[n - 1][n - 1] = 1;
        for (int r = n - 1; r >= 0; --r) {
            for (int c = n - 1; c >= 0; --c) {
                if (board[r][c] == 'X' || (r == n - 1 && c == n - 1)) continue;
                int best = -1;
                int from[3][2] = {{r + 1, c}, {r, c + 1}, {r + 1, c + 1}}; // 反向：下/右/右下
                for (auto& [nr, nc] : from) {
                    if (nr < n && nc < n && f[nr][nc] >= 0)
                        best = max(best, f[nr][nc]);
                }
                if (best < 0) continue;          // 无法通向 E
                f[r][c] = best + (board[r][c] == 'E' ? 0 : board[r][c] - '0');
                for (auto& [nr, nc] : from) {
                    if (nr < n && nc < n && f[nr][nc] == best)
                        g[r][c] = (g[r][c] + g[nr][nc]) % MOD;
                }
            }
        }
        if (f[0][0] < 0) return {0, 0};          // E 不可达
        return {f[0][0], g[0][0]};
    }
};
```

### Python

```python
class Solution:
    def pathsWithMaxScore(self, board: List[str]) -> List[int]:
        MOD = 10 ** 9 + 7
        n = len(board)
        # f[r][c]：从 (r,c) 出发到达 E(0,0) 的最大得分；g[r][c]：方案数
        f = [[-1] * n for _ in range(n)]
        g = [[0] * n for _ in range(n)]
        f[n - 1][n - 1] = 0
        g[n - 1][n - 1] = 1
        for r in range(n - 1, -1, -1):
            for c in range(n - 1, -1, -1):
                if board[r][c] == 'X' or (r == n - 1 and c == n - 1):
                    continue
                best = -1
                neigh = [(r + 1, c), (r, c + 1), (r + 1, c + 1)]
                for nr, nc in neigh:
                    if nr < n and nc < n and f[nr][nc] >= 0:
                        best = max(best, f[nr][nc])
                if best < 0:
                    continue
                f[r][c] = best + (0 if board[r][c] == 'E' else ord(board[r][c]) - ord('0'))
                for nr, nc in neigh:
                    if nr < n and nc < n and f[nr][nc] == best:
                        g[r][c] = (g[r][c] + g[nr][nc]) % MOD
        if f[0][0] < 0:
            return [0, 0]
        return [f[0][0], g[0][0]]
```

> 💡 两份代码均通过官方六个示例（含缓存 `["E3283",...]` 等三个 $5\times5$ 板面，输出 `[40,1]`、`[37,1]`、`[33,1]`），与 DFS 全路径枚举暴力对拍 3000 组（C++）/ 1500 组（Python）随机板面（$n \le 6$，含 20% 障碍密度），`mismatch = 0`；$100 \times 100$ 全 '9' 板面输出 `[1773, 690285631]`，C++ 用时约 3 ms、Python 约 0.4 s。

## 8. 边界情况与易错点

1. **取模对象是计数不是得分**：`f` 全程不模（上限 1782），`g` 边加边模。若把 `f` 也模了，「等于 best」判断会在 `f` 溢出后失真；若忘了模 `g`，大板面计数溢出（$100 \times 100$ 全 9 的方案数是天文数字）。
2. **`S` / `E` 计 0 分**：`S` 初始化 $f=0$；`E` 格 $ch = 0$（用 `board[r][c] == 'E' ? 0 : ...` 分支），把 `E` 按 `'E' - '0'` 算分会多加约 40 分。
3. **初始化顺序**：`S` 格先于主循环赋值（$f=0, g=1$），且主循环跳过它；若被主循环覆盖，三邻越界 `best<0` 会 `continue` 保留初值——碰巧没事，但依赖巧合的代码是隐患。
4. **不可达返回 `[0,0]` 而非 `[0,1]`**：不可达时方案数也是 0；判据是 `f[0][0] < 0`。
5. **障碍隔断的中间格**：某格三邻全为 `-1`（或越界）时 `best<0`，必须 `continue` 保持 $f=-1$；若误置 $f=0$ 会「复活」死路。
6. **方向别搞反**：题面从 `S`（右下）走到 `E`（左上），移动是「上/左/左上」；倒序 DP 的依赖是「下/右/右下」。正反两套方向写反一个，答案立刻错，建议用 $1 \times 2$ 或 $2 \times 2$ 的小板面手验。
7. **`upper` 邻居 $(r+1, c+1)$ 别漏**：三个后继缺一不可，漏掉对角转移会丢路径（示例 2 的两条路径都用到对角步）。
8. **计数溢出的隐性风险**：即使取模，C++ 中 `g[r][c] + g[nr][nc]` 两数均 $< 10^9+7$，和 $< 2.1 \times 10^9$ 恰好超过 `int` 上界（$2.147 \times 10^9$）一点点——实际 $< 2 \times (10^9+6) = 2.000\ldots \times 10^9 < 2.147 \times 10^9$，安全但贴边；写成 `(g[r][c] + g[nr][nc]) % MOD` 无虞，若先乘后加则务必 `long long`。
