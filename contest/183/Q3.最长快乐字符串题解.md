# LeetCode 最长快乐字符串 题解

## 1. 题目概述

- **标题 / 题号**：最长快乐字符串（#1405，medium）
- **链接**：https://leetcode.cn/problems/longest-happy-string/
- **来源**：LeetCode 第 183 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、堆（优先队列）

**题意**：只含 `'a'`、`'b'`、`'c'` 且**不含** `aaa`、`bbb`、`ccc` 任何一个是子串的字符串称为**快乐字符串**（等价于：任意字符连续出现至多 2 次）。给定三个整数 $a$、$b$、$c$，返回**任意一个**尽可能长的快乐字符串，其中 `'a'` 至多用 $a$ 个、`'b'` 至多用 $b$ 个、`'c'` 至多用 $c$ 个；若不存在则返回空串。

**约束**：

- $0 \le a, b, c \le 100$
- $a + b + c > 0$

> 💡 **约束翻译**：「不含 `aaa`」=「每个字符连续段长度 $\le 2$」，唯一的放置禁忌是**尾部已有 `XX` 时不能再放 `X`**。数据范围极小（总长 $\le 300$），任何线性做法都能过，考点在**构造的正确性**。

## 2. 示例

**示例 1**

```text
输入：a = 1, b = 1, c = 7
输出："ccaccbcc"
解释：c 用 6 个、a 和 b 各 1 个，总长 8。c 有 7 个但放不完——
      2 个分隔字符最多撑起 3 组 "cc"，即 c 至多 6 个。
```

**示例 2**

```text
输入：a = 2, b = 2, c = 1
输出："aabbc"
解释：最大配额 2 ≤ 2×(其余 3 + 1)，瓶颈不卡，5 个字符全部放完。
```

**示例 3**

```text
输入：a = 7, b = 1, c = 0
输出："aabaa"
解释：唯一的分隔符 b 只能撑起 2 组 "aa"，a 至多用 4 个，总长 5；
      这是该用例的唯一正确答案。
```

## 3. 解题思路

### 3.1 暴力思路：逐位回溯

每个位置依次尝试 `'a'`/`'b'`/`'c'`，只要不与末尾两位构成三连就向下递归，维护全局最长解。搜索树深度可达 $a+b+c \le 300$、宽度恒为 3，最坏 $3^{300}$ 个分支，且很难设计有效的剪枝——回溯无法回答「当前局面是否还有希望超过已知最优」。

> 💡 暴力的根本问题是**没有利用频率结构**：三种字符的配额决定了谁是「瓶颈」——配额最多的字符最需要被间隔打散。回溯盲目尝试，把这一关键信息浪费掉了。

### 3.2 核心观察：贪心——每步放「剩余最多且可用」的字符

![贪心核心概念：每步放剩余最多且不三连的字符](images/wc183_happy_greedy_concept.svg)

与 [767. 重构字符串](https://leetcode.cn/problems/reorganize-string/)（「不相邻」）一脉相承，但约束从「同字符最大连续 1」放宽到「最大连续 2」：

- **选谁**：剩余次数最多的字符。高频字符是瓶颈，最需要被均匀打散，应尽早消耗，避免它堆积到结尾放不进去；
- **何时不选**：若结果末尾已是 `"XX"`，则 `X` 此刻**不可用**（再放即三连），必须换一个字符当**分隔符**；放完一个分隔符，`X` 立即解除阻塞。

与 767 的关键区别：767 每次要弹两个不同字符交替放置，而本题**每轮只放一个**，被两连阻塞时才被迫切换——因此用「大根堆 + 阻塞检查」即可，无需成对弹出。

**贪心能达到多长？** 先推出一个上界（证明见 §5）：

![长度上界：R 个分隔字符最多撑起 R+1 组 XX](images/wc183_happy_upper_bound.svg)

设 $S = a+b+c$，$M = \max(a,b,c)$，$R = S - M$（其余配额之和）。任何快乐串中字符 X 的个数 $\le 2 \times (\text{其余个数} + 1)$——$R$ 个分隔字符至多把 X 分成 $R+1$ 组、每组 $\le 2$ 个。于是

$$
\text{maxLen} \;\le\; \min\big(S,\; 3R + 2\big)
$$

- $M \le 2(R+1)$：瓶颈塞得下，三个配额**全部放完**，长度 $= S$；
- $M > 2(R+1)$：X 超额，至多放 $2(R+1)$ 个 X 加全部 $R$ 个其他字符，长度 $= 3R + 2$。

§5 将证明：贪心恰好钉在这个上界上。

### 3.3 算法流程：大根堆 + 两种运行节奏

用大根堆维护三个 `(剩余数, 字符)`，每步弹堆顶决策：

1. 把配额 $> 0$ 的 `(配额, 字符)` 全部入大根堆，结果串 `res` 置空；
2. 弹出堆顶 $(cnt_1, ch_1)$：
   - **可用**（`res` 末尾两位不都是 $ch_1$）：放一个 $ch_1$，$cnt_1 - 1$ 若仍 $> 0$ 则放回堆；
   - **被阻塞**（末尾已是 $ch_1ch_1$）：若堆已空则**停机**；否则弹出次顶 $(cnt_2, ch_2)$，放一个 $ch_2$ 作分隔符，$cnt_2 - 1$ 若仍 $> 0$ 放回，堆顶 $(cnt_1, ch_1)$ **原封不动**放回；
3. 回到步骤 2，直至堆空。

贪心的实际运行按 $M$ 与 $2(R+1)$ 的大小分成两种节奏，殊途同归地达到上界：

![贪心的两种运行节奏：交错混排 vs XX·Y 固定节奏](images/wc183_happy_case_rhythm.svg)

- **情形 A**（$M \le 2(R+1)$）：最多者不断被打断、交错消耗，不变量「剩余最大 $\le 2 \times$ (其余 + 1)」全程保持，贪心**绝不搁浅**，最终配额清零，$L = S$；
- **情形 B**（$M > 2(R+1)$）：最大字符 X **严格主导**（剩余量始终超过其余之和），节奏固定为「2 个 X + 1 个分隔符」循环 $R$ 轮，再补 2 个 X 后在尾部 `"XX"` 处停机，$L = 3R+2$。

### 3.4 示例演算

以示例 1（$a=1, b=1, c=7$，情形 B，$R=2$）为例逐步走查：

![示例演算：a=1,b=1,c=7 逐步贪心得到 ccaccbcc](images/wc183_happy_walkthrough.svg)

第 3、6 步是关键决策：最高频的 `c` 被 `"cc"` 阻塞时，**及时切换**次顶字符 `a`/`b` 作分隔，随后继续消耗 `c`；第 9 步仅剩 `c=1` 且尾部 `"cc"`、分隔符耗尽，停机。最终 `"ccaccbcc"` 长 8，恰等于上界 $3R+2 = 8$。

> 💡 对照示例 3（$a=7, b=1, c=0$）：贪心得 `"aabaa"`，用掉 4 个 a + 1 个 b。1 个分隔符至多撑起 2 组 `"aa"`，7 个 a 中必有 3 个永远放不下——这是任何策略的理论上限，贪心恰好达到。

## 4. 算法细节

1. **数据结构**：大根堆存 `(剩余数, 字符)`。字符种数 $k = 3$，每次堆操作 $O(\log 3)$ 是常数；等价写法是每轮对 3 个二元组按剩余数降序排序（见本站[每日题解 1405](../../solution/1401-1500/1405_最长快乐字符串.md)），堆版本的优势是能直接推广到 $k$ 种字符。
2. **可用性判定 $O(1)$**：只看 `res` 末尾两个字符是否都等于该字符，不扫描整串。
3. **被阻塞的堆顶原封放回**：它这一步没有被消耗，配额不减——这是最容易写错的一行。
4. **每次只放 1 个就回炉重比**：放置会改变配额、可能逆转「谁最多」（如 $3,3$ 放一个后变 $2,3$），逐个比较最稳妥。
5. **平局任意打破**：两种代码的平局方向不同（C++ 的 `pair<int,char>` 平局取字符大者，Python 的 `(-cnt, ch)` 平局取字母小者），输出串可能不同，但长度相同且都合法——本题是 special judge，任意最优解均可；正确性证明（§5）不依赖平局方向。
6. **只求长度的闭式解**：若不需要具体串，$\text{maxLen} = \min(S, 3R+2)$ 直接得出，可作为写完代码后的对拍公式。

## 5. 正确性证明

记 $S = a+b+c$，$M = \max(a,b,c)$，$R = S - M$。称字符 $ch$ 在某局面**可用**，若其剩余配额 $> 0$ 且放入后不构成三连（即结果末尾两位不都是 $ch$）。贪心每步放「剩余最多的**可用**字符」；由构造，输出必是快乐串且不超配额，以下只证**最长性**。

**引理 1（单字符上界）**：任何快乐串中，任一字符 X 的出现次数 $\le 2 \times (\text{其余字符次数} + 1)$。

**证明**：把 X 的出现划分成 $k$ 个极大连续段，快乐性保证每段长 $\le 2$；相邻两段之间至少隔 1 个非 X 字符，故其余字符 $\ge k - 1$，即 $k \le \text{其余} + 1$。于是 X 的次数 $\le 2k \le 2(\text{其余} + 1)$。∎

**推论（总长上界）**：$L \le \min(S,\ 3R + 2)$。

**证明**：显然 $L \le S$。对配额最大的字符 X（总数 $M$、其余总数 $R$）用引理 1：$L = \text{X 用量} + \text{其余用量} \le 2(\text{其余用量} + 1) + \text{其余用量} = 3 \cdot \text{其余用量} + 2 \le 3R + 2$。∎

**引理 2（停机形态）**：贪心停机当且仅当 (i) 所有配额耗尽，或 (ii) 仅剩一种字符 X（个数 $> 0$）且尾部已是 `XX`。

**证明**：「尾部两连」至多阻塞一种字符（尾部只是某个 `YY`）。若剩余字符至少两种，其中至多一种被阻塞，必存在可用字符，贪心不会停。∎

**引理 3（情形 A 的不变量）**：设初始 $M \le 2(R+1)$。记某局面剩余配额的最大值为 $m$、其余剩余之和为 $r$，则贪心全程保持：

- (a) $m \le 2(r + 1)$；
- (b) 若当前尾部是 `XX`，则 X 的剩余 $\le 2 \times$（非 X 剩余之和）。

因此贪心不会停在形态 (ii)，最终 $L = S$。

**证明**：对放置次数归纳。初始时 (a) 即前提，(b) 空真。设当前不变量成立，看这一步：

- **放全局最大字符 X**（X 可用）。
  - (a)：若放后 X 仍是最大，则 $m$ 减 1、$r$ 不变，显然保持。若次大 $m_2$ 反超，由 $m_2 \le m$ 且 $m_2 > m - 1$ 知 $m_2 = m$（并列），新最大为 $m$、新其余为 $r - 1$；由 $m_2 \le r$ 得 $m \le r \le 2r = 2\big((r-1) + 1\big)$ ✓。
  - (b)：放 X 后尾部变 `XX` 当且仅当这是**连续第二个** X。断言：连续两个 X 中的前一个必是作为全局最大放下的——若它是「被迫放置」（存在被阻塞的全局最大 $W \ne X$，$W$ 配额 $> $ X 配额），放完后尾部为 `WX`，$W$ 已解除阻塞且配额仍大于 X，下一步贪心必放 $W$ 而非 X，与「连续」矛盾。于是回到两步之前：X 是全局最大、配额为当前剩余 $+ 2$，其余和仍为 $r$，对该状态用 (a) 得「X 当前剩余 $+\,2 \le 2(r+1)$」，即 X 剩余 $\le 2r$ ✓。
- **放次大字符 Y**（仅当全局最大 X 被尾部 `XX` 阻塞）。放后 X 不变、$r \to r - 1$、尾部变 `XY`。由 (b)，阻塞时 X 剩余 $\le 2r$，故新局面 (a) 成立；尾部非 `XX`，(b) 空真 ✓。

归纳完成。若贪心停在形态 (ii)——仅剩 X 且尾部 `XX`——(b) 要求 X 剩余 $\le 2 \times 0 = 0$，与个数 $> 0$ 矛盾。故情形 A 下只能停在形态 (i)，$L = S$。∎

**引理 4（情形 B 的节奏）**：设初始 $M > 2(R+1)$，X 为最大字符。则贪心按「放 2 个 X、放 1 个其余字符」循环 $R$ 轮，再补 2 个 X 后停机；X 恰好用 $2(R+1)$ 个、其余全用完，$L = 3R + 2$。

**证明**：先证 X 全程严格主导：归纳设第 $k$ 轮开始时 X 剩 $M - 2k$、其余共剩 $R - k$（$0 \le k \le R$），由 $M \ge 2R + 3$ 得

$$
(M - 2k) - (R - k) \;\ge\; R + 3 - k \;\ge\; 3 \;>\; 0,
$$

故 X 是唯一全局最大。于是每轮：放 X（可用）、再放 X（尾部单 X，仍最大且可用）、尾部 `XX` 被阻塞、放一个次大字符解除——恰耗 2 个 X 与 1 个其余。$R$ 轮后其余耗尽，X 剩 $M - 2R \ge 3$，尾部 `?Y`（X 可用）：再放 2 个 X 后尾部 `XX` 且堆空，停机。$L = 2R + R + 2 = 3R + 2$。∎

**定理**：贪心返回的长度等于 $\min(S,\ 3R + 2)$，达到推论的上界，故为最长。

**证明**：情形 A（$M \le 2(R+1)$）等价于 $S = M + R \le 3R + 2$，故 $\min(S, 3R+2) = S$，由引理 3 得 $L = S$ ✓；情形 B（$M > 2(R+1)$）等价于 $S \ge 3R + 3 > 3R + 2$，故 $\min = 3R + 2$，由引理 4 得 $L = 3R + 2$ ✓。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big((a+b+c) \log 3\big) \approx O(a+b+c)$。至多放置 $a+b+c \le 300$ 个字符，每步一次堆操作，堆大小 $\le 3$，$\log 3$ 为常数。
- **空间复杂度**：$O(a+b+c)$ 存结果串；额外空间 $O(1)$（堆中至多 3 个元素）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string longestDiverseString(int a, int b, int c) {
        string res;
        priority_queue<pair<int, char>> pq;
        if (a > 0) pq.push({a, 'a'});
        if (b > 0) pq.push({b, 'b'});
        if (c > 0) pq.push({c, 'c'});
        while (!pq.empty()) {
            auto [cnt1, ch1] = pq.top();      // 剩余最多的字符
            pq.pop();
            int n = res.size();
            if (n >= 2 && res[n - 1] == ch1 && res[n - 2] == ch1) {
                if (pq.empty()) break;        // 分隔符耗尽，被三连卡死
                auto [cnt2, ch2] = pq.top();  // 次多者放一个当分隔符
                pq.pop();
                res += ch2;
                if (cnt2 > 1) pq.push({cnt2 - 1, ch2});
                pq.push({cnt1, ch1});         // 被阻塞的堆顶原封放回
            } else {
                res += ch1;                   // 最多的字符可用，直接放
                if (cnt1 > 1) pq.push({cnt1 - 1, ch1});
            }
        }
        return res;
    }
};
```

### Python

```python
import heapq

class Solution:
    def longestDiverseString(self, a: int, b: int, c: int) -> str:
        res = []
        heap = [(-v, ch) for v, ch in ((a, 'a'), (b, 'b'), (c, 'c')) if v > 0]
        heapq.heapify(heap)
        while heap:
            cnt1, ch1 = heapq.heappop(heap)          # 剩余最多的字符
            if len(res) >= 2 and res[-1] == res[-2] == ch1:
                if not heap:
                    break                            # 分隔符耗尽，停机
                cnt2, ch2 = heapq.heappop(heap)      # 次多者放一个当分隔符
                res.append(ch2)
                if cnt2 < -1:
                    heapq.heappush(heap, (cnt2 + 1, ch2))
                heapq.heappush(heap, (cnt1, ch1))    # 被阻塞的堆顶原封放回
            else:
                res.append(ch1)
                if cnt1 < -1:
                    heapq.heappush(heap, (cnt1 + 1, ch1))
        return ''.join(res)
```

> 💡 两份代码都已对全部 $0 \le a, b, c \le 15$ 与闭式 $\min(S, 3R+2)$ 对拍验证。平局方向不同导致输出串可能不同（如 $(1,1,7)$：Python 得官方示例的 `"ccaccbcc"`，C++ 得 `"ccbccacc"`），长度均为 8 且合法，均可被接受。

## 8. 边界情况与易错点

1. **阻塞时堆为空必须立即 `break`**：此时只剩一种字符且被 `XX` 卡死，继续放堆顶必然产生三连。
2. **被阻塞的堆顶放回时配额不减**：它没有被消耗；误写成 `cnt1 - 1` 会凭空丢字符。
3. **减到 0 不要再入堆**：`cnt - 1 > 0`（Python：`cnt < -1`）判断不可省，否则空转死循环。
4. **三连判定只查末尾两位**：$O(1)$；不要每步扫描整个结果串（虽也能过，但没必要）。
5. **每轮只放一个就重新比较**：配额变化可能逆转「谁最多」；「一次放两个」的变体在剩余为 1、被阻塞切换等边界处分支更多，易错。
6. **输出不唯一**：本题 special judge，任何达到 $\min(S, 3R+2)$ 的合法串都对；用官方示例对拍时若串不同，先比对长度与合法性，别急着改代码。
7. **空输入**：约束保证 $a+b+c > 0$，但代码对全 0 也稳健（堆为空直接返回 `""`）。
