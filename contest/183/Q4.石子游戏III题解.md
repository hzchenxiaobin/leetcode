# LeetCode 石子游戏 III 题解

## 1. 题目概述

- **标题 / 题号**：石子游戏 III（#1406，hard）
- **链接**：https://leetcode.cn/problems/stone-game-iii/
- **来源**：LeetCode 第 183 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、博弈论、Minimax、后缀和

**题意**：$n$ 堆石子排成一行，第 $i$ 堆价值 $\text{stoneValue}[i]$（**可为负**）。Alice 先手，双方轮流行动；每个回合当前玩家**必须**拿走剩下石子中的**前 1、2 或 3 堆**，直到全部拿完。每人得分 = 所拿各堆价值之和。双方均采取最优策略，返回胜者：Alice 分高返回 `"Alice"`，Bob 分高返回 `"Bob"`，平分返回 `"Tie"`。

**约束**：

- $1 \le n = \text{stoneValue.length} \le 5 \times 10^4$
- $-1000 \le \text{stoneValue}[i] \le 1000$

> 💡 **约束翻译**：$O(n^2)$ 约为 $2.5 \times 10^9$ 次运算会超时，需要线性做法。价值可负 + 「必须拿」意味着可能被迫吞负分——博弈的全部张力来自这里。另外所有堆最终都会被拿完，**总分固定**，所以「最大化自己得分」与「最大化分差」等价，是标准的零和博弈。

## 2. 示例

**示例 1**

```text
输入：values = [1,2,3,7]
输出："Bob"
解释：Alice 最好拿前三堆共 6 分，Bob 拿走 7 分的那堆，7 > 6，Bob 获胜。
```

**示例 2**

```text
输入：values = [1,2,3,-9]
输出："Alice"
解释：Alice 拿前三堆（6 分），把 -9 整堆甩给 Bob；6 > -9，Alice 获胜。
```

**示例 3**

```text
输入：values = [1,2,3,6]
输出："Tie"
解释：Alice 拿前三堆得 6 分，Bob 拿 6 分的那堆，双方 6 : 6 平局。
```

## 3. 解题思路

### 3.1 暴力思路：展开整棵博弈树

从后缀 0 出发，每个局面至多 3 种拿法、博弈深度可达 $n$，博弈树规模 $O(3^n)$，$n = 5 \times 10^4$ 时是天文数字。想用记忆化剪枝，必须先回答「一个局面由什么**完全**刻画」：若把双方当前得分（或分差）塞进状态，分差取值范围宽达 $\pm 5 \times 10^7$，状态数爆炸，记忆化形同虚设。

> 💡 **破局一步**：别记录两个人的分数，只记录**差值**，而且只看**未来**的差值——历史得分是常数偏移，不改变任何一方在剩余博弈中的最优选择。

### 3.2 为什么不能贪心：一个反例

![贪心反例：values=[-1,-1,-100]，贪心输 100 分，最优赢 98 分](images/wc183_stone_greedy_fail.svg)

「每轮拿使**本轮得分** $s_k$ 最大的堆数 $k$」是最直觉的策略，但它完全忽略了「**留给对手的局面**」。取 `values = [-1,-1,-100]`：

- **贪心 Alice**：比较 $s_1 = -1 > s_2 = -2 > s_3 = -103$，拿 1 堆（$-1$）；Bob 面对同样的贪心选择也拿 1 堆（$-1$）；Alice 最后**被迫**吞下 $-100$。终局 Alice $-101$ : Bob $-1$，**输 100 分**。
- **最优 Alice**：一次拿 2 堆（共 $-2$），把 $-100$ 整堆甩给别无选择的 Bob。终局 Alice $-2$ : Bob $-100$，**赢 98 分**。

同一局面，贪心与最优相差 **198 分**。教训：每个选项的真实收益 = 本轮得分 − 对手随后的最优反制收益，局部最优 ≠ 全局最优——这正是 minimax 博弈 DP 的用武之地。

### 3.3 核心观察：后缀状态 + 净分差 DP

![净分差 DP 的状态设计与转移](images/wc183_stone_diff_concept.svg)

**观察一（无后效性）**：已拿走的堆与已产生的比分**不影响未来**——每一步的合法动作只由「剩余堆的起点 $i$」决定，历史分差只是最后统一加上的常数。因此状态只需一个下标。

**观察二（角色互换）**：定义

$$f[i] \;=\; \text{双方都最优时，面对后缀 } v[i..n-1] \text{ 的行动者的（先手 − 后手）分差}$$

若行动者拿走前 $k$ 堆（得 $s(i,k) = v_i + v_{i+1} + \cdots + v_{i+k-1}$），此后**对手**成为后缀 $i+k$ 上的「先手」，其净分差为 $f[i+k]$。于是选 $k$ 的整局分差是 $s(i,k) - f[i+k]$，取最大即得转移：

$$f[i] \;=\; \max_{k \in \{1,2,3\},\; i+k \le n} \Big( s(i,k) \;-\; f[i+k] \Big), \qquad f[n] = 0$$

**答案**：Alice 是后缀 0 的行动者，$f[0]$ 就是 Alice − Bob：

- $f[0] > 0$ → `"Alice"`；$f[0] < 0$ → `"Bob"`；$f[0] = 0$ → `"Tie"`。

> 💡 **等价形式**：设后缀和 $T[i] = \sum_{j \ge i} v_j$、先手最大总得分为 $g[i]$，则 $g[i] = T[i] - \min\big(g[i+1],\, g[i+2],\, g[i+3]\big)$，且 $f[i] = 2g[i] - T[i]$。两种写法完全等价，本文采用差分形式——直接与 0 比大小最省事。

### 3.4 示例演算：values = [1,2,3,7]

![示例演算：从右往左填 f 表](images/wc183_stone_walkthrough.svg)

$i$ 从 $n$ 往左递推（转移依赖 $i+1, i+2, i+3$，必须先算下标大的）：

| $i$ | 先手面对的堆 | 候选值 $s_k - f[i+k]$ | $f[i]$ | 最优拿法 |
|-----|-------------|----------------------|--------|---------|
| 4 | 空（边界） | — | 0 | — |
| 3 | 7 | $k{=}1$: $7-0=7$ | 7 | 拿 1 堆 |
| 2 | 3, 7 | $k{=}1$: $3-7=-4$；$k{=}2$: $10-0=10$ | 10 | 拿 2 堆 |
| 1 | 2, 3, 7 | $k{=}1$: $2-10=-8$；$k{=}2$: $5-7=-2$；$k{=}3$: $12-0=12$ | 12 | 拿 3 堆 |
| 0 | 1, 2, 3, 7 | $k{=}1$: $1-12=-11$；$k{=}2$: $3-10=-7$；$k{=}3$: $6-7=-1$ | **−1** | 拿 3 堆（少输当赢） |

$f[0] = -1 < 0$，输出 `"Bob"`：Alice 的最优是拿前三堆得 6 分、把 7 分的堆留给 Bob，净差恰好 1 分。

## 4. 算法细节

1. **递推方向**：$i$ 从 $n-1$ 递减到 $0$；$f$ 开成长度 $n+1$ 的数组，$f[n] = 0$ 作边界。
2. **增量求和**：内层 $k$ 从 1 到 $\min(3, n-i)$，维护 `take += stoneValue[i+k-1]` 累加本轮得分，$O(1)$ 完成区间和（等价写法是预处理后缀和数组）。
3. **每行必有候选**：$k=1$ 永远合法（$i \le n-1$ 时 $i+1 \le n$），故 `f[i]` 必被覆盖，初始化为极小值即可。
4. **终判三态**：$f[0]$ 与 0 比较输出 `"Alice"` / `"Bob"` / `"Tie"`。
5. **空间优化**：转移只依赖 $f[i+1..i+3]$，可滚动成 4 个变量做到 $O(1)$ 额外空间；$n \le 5 \times 10^4$ 时数组开销本就不大，优先可读性。
6. **避免递归**：自顶向下记忆化逻辑相同，但递归深度达 $5 \times 10^4$——Python 默认递归上限 1000 会直接 `RecursionError`（强行调大也可能触发 C 层爆栈），C++ 同样有栈深风险。推荐迭代递推。

## 5. 正确性证明

**引理 1（局面由起点 $i$ 完全刻画）**：设游戏进行到某中间局面，剩余堆为 $v[i..n-1]$，行动者与对手的历史得分为 $a, b$。则最终分差 $= (a-b) + D_i$，其中 $D_i$ 为双方从该局面起的未来得分之差；且合法动作集合与双方在该子博弈中的最优策略只依赖 $i$，与 $a, b$ 及更早的历史无关。

**证明**：每回合的合法动作是「拿剩余堆的前 1~3 堆」，只由剩余堆的起点决定，与已拿走的堆无关；得分逐堆累加，历史贡献 $(a-b)$ 是与未来任何行动无关的常数。故子博弈的结构只由 $i$ 刻画，其上的最优策略亦然。∎

**引理 2（递推式）**：对 $0 \le i \le n$，设 $f[i]$ 为双方在后缀 $i$ 上均采取最优策略时的（先手 − 后手）分差，则 $f[n] = 0$，且对 $i < n$ 有 $f[i] = \max_{1 \le k \le \min(3,\, n-i)} \big( s(i,k) - f[i+k] \big)$。

**证明**（对 $n-i$ 归纳）：

- **基础**：$i = n$ 时无堆可拿，双方未来得分均为 0，$f[n] = 0$。
- **归纳步骤**：设结论对一切大于 $i$ 的下标成立。先手的合法动作是拿 $k \in \{1,2,3\}$（$i+k \le n$）堆。选定 $k$ 后：先手立即得 $s(i,k)$；此后**对手**成为后缀 $i+k$ 的先手，由归纳假设，「对手 − 原先手」的未来分差恰为 $f[i+k]$（引理 1 保证历史得分只是常数偏移，不影响双方在该子博弈中的最优选择）。于是选 $k$ 的整局分差 $= s(i,k) - f[i+k]$。先手在非空有限候选集上取最大值即为其最优，递推式成立。∎

**定理**：双方都采取最优策略时，Alice − Bob $= f[0]$。故 $f[0] > 0$ 时输出 `"Alice"`，$f[0] < 0$ 时输出 `"Bob"`，$f[0] = 0$ 时输出 `"Tie"`。

**证明**：Alice 即后缀 0 的先手，由引理 2，$f[0]$ 是双方最优下的分差。本博弈有限步、完全信息、零和，由逆向归纳（Zermelo）定理，博弈值唯一，且 $f$ 的定义中对手始终按最优策略反应，任何一方单方面偏离都无法改善自身结果。因此 $f[0]$ 的符号唯一决定胜负。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个 $i$ 至多 3 次转移，每次转移用增量累加 $O(1)$ 求区间和；$n = 5 \times 10^4$ 时总共约 $1.5 \times 10^5$ 次转移，毫秒级。
- **空间复杂度**：$O(n)$，即长度 $n+1$ 的 $f$ 数组；滚动优化后额外空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string stoneGameIII(vector<int>& stoneValue) {
        int n = stoneValue.size();
        vector<int> f(n + 1, INT_MIN);
        f[n] = 0;
        for (int i = n - 1; i >= 0; i--) {
            int take = 0;
            for (int k = 1; k <= 3 && i + k <= n; k++) {
                take += stoneValue[i + k - 1];
                f[i] = max(f[i], take - f[i + k]);
            }
        }
        if (f[0] > 0) return "Alice";
        if (f[0] < 0) return "Bob";
        return "Tie";
    }
};
```

### Python

```python
class Solution:
    def stoneGameIII(self, stoneValue: List[int]) -> str:
        n = len(stoneValue)
        f = [0] * (n + 1)
        for i in range(n - 1, -1, -1):
            take = 0
            best = float('-inf')
            for k in range(1, min(3, n - i) + 1):
                take += stoneValue[i + k - 1]
                best = max(best, take - f[i + k])
            f[i] = best
        if f[0] > 0:
            return "Alice"
        if f[0] < 0:
            return "Bob"
        return "Tie"
```

## 8. 边界情况与易错点

1. **必须拿堆**：即使剩余的堆全为负，每回合也必须拿 1~3 堆，**不能弃权**。转移中 $k \ge 1$ 已保证；千万不要加「$k=0$ 不拿」的分支，否则 $[-1,-1,-100]$ 这类局面的答案会算错。
2. **末尾不足 3 堆**：$k$ 的上界是 $\min(3, n-i)$，注意 `i + k <= n` 的越界检查。
3. **递归爆栈**：$n = 5 \times 10^4$ 的记忆化递归在 Python 默认栈深 1000 下必炸；即便 `sys.setrecursionlimit(10**5)` 也可能触发 C 层段错误。一律写迭代。
4. **平局别漏**：答案有三态，$f[0] = 0$ 返回 `"Tie"`（注意大小写：首字母大写、其余小写）。
5. **比较对象是 0**：$f[0]$ 可正可负可为零，不要写成 `if f[0]: return "Alice"` 之类的布尔技巧——会把 Bob 获胜误判成 Alice。
6. **贪心陷阱**：任何只比较前 1~3 堆前缀和的策略都能被 §3.2 的反例击溃。提交前先自测 `[-1,-1,-100]`，正确答案是 `"Alice"`。
7. **数值范围**：总分绝对值 $\le 5 \times 10^4 \times 1000 = 5 \times 10^7$，`int32` 足够，C++ 无需 `long long`；Python 无溢出问题。

**延伸思考**：

- **一次可拿 $1..K$ 堆且 $K$ 很大**：利用 $s(i,k) = T[i] - T[i+k]$，转移可改写为 $f[i] = T[i] - \min_{i < j \le i+K} \big( T[j] + f[j] \big)$，括号内只依赖 $j$，用**单调队列**维护滑动窗口最小值，可把 $O(nK)$ 优化到 $O(n)$。
- **从两端拿**（如 877）：状态变为区间 $(l, r)$，$f[l][r]$ 同样定义为先手 − 后手分差，转移 $O(1)$、总复杂度 $O(n^2)$。
- **允许「跳过」一回合**：双方可能都想永远跳过，需附加终止规则（如最多连续跳过一次），局面还需记录连续跳过次数，状态升维——「只能从前端拿且必须拿」保证了每回合后剩余仍是连续后缀，状态才能压成一维。
