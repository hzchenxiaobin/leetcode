# LeetCode 非递增顺序的最小子序列 题解

## 1. 题目概述

- **标题 / 题号**：非递增顺序的最小子序列（#1403，easy）
- **链接**：https://leetcode.cn/problems/minimum-subsequence-in-non-increasing-order/
- **来源**：LeetCode 第 183 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、排序

**题意**：给定数组 `nums`，从中抽取一个子序列，使其元素之和**严格大于**数组中其余元素之和。若存在多个解，返回**长度最小**者；仍并列时返回**元素之和最大**者。答案按**非递增顺序**排列，题目保证满足条件的解唯一。

**约束**：

- $1 \le \text{nums.length} \le 500$
- $1 \le \text{nums}[i] \le 100$

> 💡 子序列不要求元素连续，即「选哪些」与原数组顺序无关——这是本题能**先排序再取**的合法性来源。

## 2. 示例

**示例 1**

```text
输入：nums = [4,3,10,9,8]
输出：[10,9]
解释：[10,9] 与 [10,8] 都是最小的合法子序列（长度 2），但 [10,9] 的和更大。
```

**示例 2**

```text
输入：nums = [4,4,7,6,7]
输出：[7,7,6]
解释：[7,7] 的和为 14，不严格大于剩余元素之和（4+4+6 = 14），必须再取一个 6。
```

**示例 3**（自拟：最坏要取满全部元素）

```text
输入：nums = [8,8]
输出：[8,8]
解释：total = 16，取一个 8 后 cur = 8 = 剩余 8，不严格大于；只能全部取走。
```

## 3. 解题思路

### 3.1 暴力思路：枚举所有子序列

朴素做法是枚举全部 $2^n$ 个子序列，对每个子序列计算元素和、检查 $2 \cdot \text{sum} > \text{total}$，再在合法解中按「长度最小、和最大」取最优。$n = 500$ 时 $2^{500}$ 完全不可枚举；更本质的问题是它**没有利用任何结构**——题目只关心「子和 vs 剩余和」的相对大小，与元素在原数组中的位置无关，把「选哪些元素」的组合搜索省掉才是正道。

### 3.2 核心观察：降序排序 + 贪心取前缀

![核心观察：降序排序后贪心取前缀，前缀和首次严格过半即停](images/minsub_greedy_concept.svg)

把数组**降序排序**后，三个目标在「取前 $k$ 大元素」下同时达成：

1. **长度最小**：要「用最少的元素让子和过半」，就该优先拿最大的元素——大元素性价比最高，一个顶几个；
2. **和最大**：长度固定为 $k$ 时，取最大的 $k$ 个元素之和显然是最大可能和；
3. **非递增**：沿降序逐个取出，答案天然有序。

于是一趟扫描即可：累加前缀和 $\text{cur}$，一旦 $\text{cur} > \text{total} - \text{cur}$（等价于 $2 \cdot \text{cur} > \text{total}$）立即停止。注意是**严格大于**——前缀和恰好等于剩余和时不许停。

### 3.3 算法流程

1. **降序排序**：`sort(nums, greater)`；
2. **求总和**：$\text{total} = \sum \text{nums}[i]$；
3. **贪心累加**：从左到右遍历，每个元素先累加进 $\text{cur}$、放入答案；
4. **判停**：一旦 $\text{cur} > \text{total} - \text{cur}$，`break` 返回。

排序消除「选哪些」的组合空间，遍历在首次过半处提前终止——从 $2^n$ 降到 $n$。

## 4. 算法细节

1. **判停条件**：`cur > total - cur` 是题意「子和严格大于剩余和」的直译，与 $2 \cdot \text{cur} > \text{total}$ 完全等价；写前者最不易在「等号」上翻车。
2. **先累加后判停**：使前缀和首次过线的那个元素是「临门一脚」，必须计入答案——所以循环体是先 `cur += x; ans.push_back(x);` 再判停。若把判停挪到累加之前，压线一步会漏掉该元素。
3. **原地降序排序**：直接对形参数组排序（判题不检查输入是否被修改），取出的前缀即非递增序，无需二次排序或反转。
4. **并列无需处理**：「长度并列时取和最大」的规则不用写任何分支——同长度、同和的子序列的多重集合唯一（见 §5 引理 1 的取等条件），结构上不存在需要 tie-break 的并列。
5. **数值规模**：$n \le 500$、$\text{nums}[i] \le 100$，故 $\text{total} \le 5 \times 10^4$，`int` 即可，无溢出风险。

## 5. 正确性证明

设降序排列后为 $a_1 \ge a_2 \ge \cdots \ge a_n > 0$，记 $T = \sum_{i=1}^{n} a_i$，前缀和 $p_k = \sum_{i=1}^{k} a_i$（$p_0 = 0$）。子序列 $S$ **合法** $\iff 2\,\mathrm{sum}(S) > T$。设 $k$ 为使 $p_k > T - p_k$ 成立的最小下标（即贪心的停机位置），由元素全正，$p_n = T > 0 = T - p_n$，故 $k$ 存在且 $k \le n$。

**引理 1（固定长度的和上界与取等条件）**：任意长度为 $j$ 的子序列 $S$ 满足 $\mathrm{sum}(S) \le p_j$；且取等当且仅当 $S$ 的多重集合恰为 $\{a_1, \dots, a_j\}$。

**证明**：把 $S$ 的元素降序排为 $b_1 \ge \cdots \ge b_j$。断言 $b_i \le a_i$：否则 $b_i > a_i$，则 $b_1, \dots, b_i$ 是数组中 $i$ 个互异下标的元素且每个 $\ge b_i > a_i$；而数组中值严格大于 $a_i$ 的元素只可能出现在下标 $1, \dots, i-1$ 中（至多 $i - 1$ 个），矛盾。于是 $\mathrm{sum}(S) = \sum_{i=1}^{j} b_i \le \sum_{i=1}^{j} a_i = p_j$；取等当且仅当逐位 $b_i = a_i$，即 $S$ 恰由前 $j$ 大元素组成。∎

**引理 2（更短的子序列必不合法）**：对任意 $j < k$ 与任意长度为 $j$ 的子序列 $S$，有 $2\,\mathrm{sum}(S) \le T$。

**证明**：由 $k$ 的最小性，$j < k \Rightarrow p_j \le T - p_j$。结合引理 1，$\mathrm{sum}(S) \le p_j$，于是 $2\,\mathrm{sum}(S) \le 2 p_j \le T$，即 $S$ 不满足严格大于。∎

**定理**：贪心输出 $A = (a_1, \dots, a_k)$ 是满足题意的唯一答案。

**证明**：

- **长度最小**：$A$ 长度为 $k$ 且合法（$p_k > T - p_k$）；任何长度 $< k$ 的子序列由引理 2 不合法。
- **和最大**：任何长度为 $k$ 的合法子序列 $S$ 由引理 1 满足 $\mathrm{sum}(S) \le p_k = \mathrm{sum}(A)$。
- **唯一性**：若长度为 $k$ 且 $\mathrm{sum}(S) = p_k$，由引理 1 的取等条件，$S$ 的多重集合与 $A$ 相同，按非递增输出即为同一序列。
- **非递增**：$A$ 沿降序取出，天然非递增。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$，排序主导（$n \le 500$ 时约几千次比较）；一趟贪心遍历 $O(n)$，且通常提前终止。签到题毫秒级通过。
- **空间复杂度**：C++ 原地内省排序仅需 $O(\log n)$ 递归栈；Python `list.sort` 使用 $O(n)$ 辅助空间。答案数组按惯例不计入。
- **理论优化**：值域 $[1, 100]$ 为常数，可用计数排序把排序降到 $O(n + 100)$，整体 $O(n)$；本题规模下无必要，仅作储备。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minSubsequence(vector<int>& nums) {
        sort(nums.begin(), nums.end(), greater<int>());
        int total = accumulate(nums.begin(), nums.end(), 0);
        int cur = 0;
        vector<int> ans;
        for (int x : nums) {
            cur += x;
            ans.push_back(x);
            if (cur > total - cur) break;  // 严格大于，差一个等号都不行
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minSubsequence(self, nums: List[int]) -> List[int]:
        nums.sort(reverse=True)
        total = sum(nums)
        cur = 0
        ans = []
        for x in nums:
            cur += x
            ans.append(x)
            if cur > total - cur:  # 严格大于，差一个等号都不行
                break
        return ans
```

## 8. 边界情况与易错点

1. **严格大于是头号大坑**：判停条件必须是 `cur > total - cur` 而非 `>=`。示例 2 中取两个 7 后 $14 = 14$，用 `>=` 会提前停、返回错误的 $[7,7]$。

   ![易错点：> 与 >= 在压线处的分叉](images/minsub_equal_pitfall.svg)

2. **压线元素必须计入**：判停放在累加与入栈之后；使和首次过线的元素正是答案的最后一个元素，先判后加会把它漏掉。
3. **可能取满全部元素**：如 $[8,8]$、$[1,1]$——任何时刻全取后 $\text{cur} = \text{total} > 0 = \text{total} - \text{cur}$，循环必然终止，不需要特判，也不存在死循环或越界；$n = 1$ 时首个元素即答案。
4. **排序方向**：必须降序。误写升序会变成「小元素优先」的最长解，输出顺序也不符合非递增要求。
5. **别手写并列分支**：「长度并列取和最大」由引理 1 的取等条件结构性保证（同长同和 ⟹ 同一多重集合），代码里不需要任何 tie-break 逻辑。
6. **数值范围**：$\text{total} \le 50000$，`int` 足够，无需 `long long`。
