# LeetCode 将二进制表示减到 1 的步骤数 题解

## 1. 题目概述

- **标题 / 题号**：将二进制表示减到 1 的步骤数（#1404，medium）
- **链接**：https://leetcode.cn/problems/number-of-steps-to-reduce-a-number-in-binary-representation-to-one/
- **来源**：LeetCode 第 183 场周赛 Q2
- **难度**：中等
- **标签**：位运算、字符串、模拟

**题意**：给定一个二进制字符串 $s$ 表示的正整数，反复执行：偶数则除以 2，奇数则加 1，直到变为 1，返回总步数。注意操作序列是**唯一确定**的——每一步做哪个操作由当前奇偶性唯一决定，不存在选择，因此答案就是唯一过程的长度。

**约束**：

- $1 \le s.length \le 500$
- $s$ 仅由 `'0'` / `'1'` 组成，且 $s[0] = '1'$（无前导零）

> ⚠️ 关键陷阱在长度：500 位二进制远超 64 位整数（$2^{63} \approx 9.2 \times 10^{18}$ 只装得下 63 位），C++/Java **不能**直接转整型模拟；输入必须当作**字符串**处理。

## 2. 示例

**示例 1**

```text
输入：s = "1101"
输出：6
解释："1101" 即 13。
13 →(+1) 14 →(/2) 7 →(+1) 8 →(/2) 4 →(/2) 2 →(/2) 1
```

**示例 2**

```text
输入：s = "10"
输出：1
解释：2 →(/2) 1。
```

**示例 3**

```text
输入：s = "1"
输出：0
解释：已经是 1，一步不用。
```

**示例 4**（自拟：覆盖进位穿透情形）

```text
输入：s = "1011"
输出：6
解释：11 →(+1) 12 →(/2) 6 →(/2) 3 →(+1) 4 →(/2) 2 →(/2) 1
其中 "1011" 最低位 1 触发 +1 后，进位连锁穿透 "011" 段：1011 + 1 = 1100。
```

## 3. 解题思路

### 3.1 暴力思路：转整数直接模拟

最直接的想法是把 $s$ 转成整数再循环：判奇偶、加一或减半，直至为 1。

- **Python** 天然支持任意精度整数，`int(s, 2)` 可行；但每次 `+1` / `//2` 都是对 500 位大数的 $O(n)$ 操作，总步数 $O(n)$，整体 $O(n^2) \approx 2.5 \times 10^5$ 位运算——本题规模下能过，却完全没有利用二进制的结构。
- **C++/Java** 则连第一步都走不通：500 位二进制远超 `long long` 上限，`stol` 直接抛 `out_of_range`。

正路是注意到两个操作在**二进制位层面**都有极简含义，直接在字符串上模拟。

### 3.2 核心观察：除 2 = 右移消位，加 1 = 末位进位

![核心观察：除2等价右移消位，加1的连锁进位折叠成单个carry变量](images/binsteps_core_concept.svg)

两条位级观察：

1. **除以 2 = 二进制右移一位**：消去最低位，高位原封不动。于是整个模拟过程可以看作一条**从右往左的扫描线**——每处理一位，就把这一位「消掉」，数字缩短一格。
2. **加 1 只发生在最低位为 1 时**（奇数），且效果固定是「最低位 1 变 0、向高位进 1」；加完必变偶数，紧接着就要 `/2`。所以**奇数消掉一位固定花 2 步**（+1 再 /2），并向上传出进位；**偶数消掉一位固定花 1 步**（仅 /2）。

进位可能连锁穿透一串 1（如 $1011 + 1 = 1100$ 穿透了低三位），但**不必显式修改这些位**：把「传向高位的 +1」折叠成单个变量 $\text{carry} \in \{0, 1\}$，处理第 $i$ 位时把它的实际值取为

$$v = s_i + \text{carry} \in \{0, 1, 2\}$$

三种取值对应三种消位方式：

| $v$ | 含义 | 奇偶 | 操作 | 步数 | 新 carry |
|-----|------|------|------|------|----------|
| 0 | 该位就是 0 且无进位 | 偶 | `/2` | 1 | 0 |
| 1 | 该位是 1（或 0 叠上进位变 1） | 奇 | `+1` 再 `/2` | 2 | 1 |
| 2 | 1 叠上进位 = $10_2$：本位实际为 0，进位继续上供 | 偶 | `/2` | 1 | 1 |

### 3.3 算法流程

![算法流程：逐位扫描v=s[i]+carry三分支计步，末尾补carry](images/binsteps_case_flow.svg)

1. 初始化 `ans = 0`，`carry = 0`；
2. 从最低位 $i = n-1$ 扫到 $i = 1$（**不含**最高位）：
   - 计算 $v = s_i + \text{carry}$；
   - $v = 0$：`ans += 1`，`carry = 0`；
   - $v = 1$：`ans += 2`，`carry = 1`；
   - $v = 2$：`ans += 1`，`carry = 1`；
3. 收尾：最高位 $s_0 = 1$，实际值 $= 1 + \text{carry}$。若 `carry = 0`，数字恰为 1，结束；若 `carry = 1`，数字是 $10_2 = 2$，还需最后一步 `/2`。故**返回 `ans + carry`**。

一行扫描、一个进位变量，从「大数模拟」降到一趟字符串遍历。

### 3.4 示例演算

![示例演算：s=1101逐位走查，2+2+1步加收尾carry共6步](images/binsteps_walkthrough.svg)

**示例 1**（`s = "1101"`，13）：

| 位 $i$ | $s_i$ | carry 入 | $v$ | 判定 | 步数 | carry 出 | 累计 |
|--------|-------|----------|-----|------|------|----------|------|
| 3 | 1 | 0 | 1 | 奇：+1 再 /2 | 2 | 1 | 2 |

| 0 | 1 | 1 | — | 最高位实为 1+1=2，即 "10" | 1 | — | 6 |

| 位 $i$ | $s_i$ | carry 入 | $v$ | 步数 | carry 出 | 累计 |
|--------|-------|----------|-----|------|----------|------|
| 3 | 1 | 0 | 1 | 2 | 1 | 2 |
| 2 | 0 | 1 | 1 | 2 | 1 | 4 |

返回 $5 + 1 = 6$，与 $11 \to 12 \to 6 \to 3 \to 4 \to 2 \to 1$ 的 6 步吻合。✓

## 4. 算法细节

1. **carry 的三态转移**是全题核心：`v=1` 是唯一花 2 步的情形（奇数必须先 +1 凑偶再 /2）；`v=0` 与 `v=2` 都是偶数、各花 1 步，区别仅在是否延续进位。三分支可压缩为 `ans += 1 + (v == 1); carry = v ? 1 : 0;`。
2. **carry 的单调性**：`v = 0` 要求 `carry = 0` 才可能出现，故一旦 carry 变 1 就**再也不会回到 0**——进位链必然一路传到最高位。这意味着进位是「一次性点燃、全程燃烧」的，单变量足矣，无需栈或数组。
3. **最高位单独收尾**：循环只扫 $i \ge 1$。最高位实际值 $1 + \text{carry} \in \{1, 2\}$，为 2 即 "10"，多一步 /2 得 1——这就是 `return ans + carry` 的由来，也是最容易漏掉的一步。
4. **不构造中间字符串**：我们只数步数，中间态全部隐含在 `(已扫前缀, carry)` 里，无需拼接/修改字符串，空间 $O(1)$。
5. **数值范围**：每位至多贡献 2 步，加上收尾 1 步，$\text{ans} \le 2(n-1) + 1 \le 999$，`int` 绰绰有余。

## 5. 正确性证明

设 $N$ 为 $s$ 表示的整数，$n = |s|$，$s_i$ 为第 $i$ 位（$s_0$ 最高、$s_{n-1}$ 最低）。真实模拟产生序列 $x_0 = N, x_1, x_2, \dots$：$x_t$ 偶则 $x_{t+1} = x_t / 2$，奇则 $x_{t+1} = (x_t + 1)/2$。由 $x_t > 1 \Rightarrow x_{t+1} \le (x_t+1)/2 < x_t$，序列严格递减，必达 1，过程唯一。

**引理 1（进位不变量）**：对 $0 \le t \le n-1$，有 $x_t = \lfloor N / 2^t \rfloor + \epsilon_t$，其中 $\epsilon_t \in \{0, 1\}$。

**证明**（对 $t$ 归纳）：$t = 0$ 时 $x_0 = N$，$\epsilon_0 = 0$。设 $x_t = y + \epsilon_t$，其中 $y = \lfloor N/2^t \rfloor$，记 $b = y \bmod 2 = s_{n-1-t}$（$y$ 的最低位正是原串第 $n-1-t$ 位），则 $x_t$ 的奇偶性由 $b + \epsilon_t \in \{0,1,2\}$ 决定：

- $b + \epsilon_t = 0$：$x_t$ 偶，$x_{t+1} = x_t / 2 = \lfloor y/2 \rfloor$，故 $\epsilon_{t+1} = 0$；
- $b + \epsilon_t = 1$：$x_t$ 奇。写 $y = 2m + b$，则两种取法（$b{=}1,\epsilon{=}0$ 或 $b{=}0,\epsilon{=}1$）均给出 $x_t = 2m+1$，于是 $x_{t+1} = (x_t+1)/2 = m + 1 = \lfloor y/2 \rfloor + 1$，故 $\epsilon_{t+1} = 1$；
- $b + \epsilon_t = 2$：$x_t = 2m + 2$ 偶，$x_{t+1} = x_t/2 = m + 1 = \lfloor y/2 \rfloor + 1$，故 $\epsilon_{t+1} = 1$。

由 $\lfloor y/2 \rfloor = \lfloor N/2^{t+1} \rfloor$，归纳完成。∎

**引理 2（步数与进位的对应）**：第 $t$ 步（$x_t \to x_{t+1}$）的开销与算法扫到第 $i = n-1-t$ 位时的行为完全一致：$b + \epsilon_t = 0$ 花 1 步、新 carry 为 0；$= 1$ 花 2 步、新 carry 为 1；$= 2$ 花 1 步、新 carry 为 1。其中 $b = s_i$、$\epsilon_t$ 即算法的 carry 入值。

**证明**：逐情形对照引理 1 证明中的三种分支与 §3.2 转移表即得。∎

**定理**：逐位扫描算法返回的值等于真实模拟把 $N$ 变为 1 的总步数。

**证明**：算法对 $i = n-1, \dots, 1$ 扫描，对应 $t = 0, \dots, n-2$；由引理 2，累计值 `ans` 逐项等于模拟前 $n-1$ 步的开销，且扫描结束时的 carry 恰为 $\epsilon_{n-1}$。由引理 1，$x_{n-1} = \lfloor N/2^{n-1} \rfloor + \epsilon_{n-1} = 1 + \epsilon_{n-1}$（$s_0 = 1$）：若 $\epsilon_{n-1} = 0$ 则 $x_{n-1} = 1$，模拟恰在 $n-1$ 步后终止，返回 `ans + 0` 正确；若 $\epsilon_{n-1} = 1$ 则 $x_{n-1} = 2$，还需一步（$2/2 = 1$，开销 1），返回 `ans + 1` 正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，一趟从右往左的扫描，每个字符 $O(1)$ 判断。对比暴力：Python 大数模拟每次操作 $O(n)$、共 $O(n)$ 步，为 $O(n^2)$；C++ 则需先手写大数类，代价更高。$n \le 500$ 时本解法约几百次整数运算，微秒级。
- **空间复杂度**：$O(1)$ 额外空间——仅 `ans` 与 `carry` 两个整数变量，不构造任何中间字符串（输入串不计入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numSteps(string s) {
        int ans = 0, carry = 0;
        for (int i = (int)s.size() - 1; i >= 1; --i) {
            int v = (s[i] - '0') + carry;
            if (v == 0) {        // 偶数：一步右移消位
                ans += 1;
                carry = 0;
            } else if (v == 1) { // 奇数：+1 再 /2，两步，进位点燃
                ans += 2;
                carry = 1;
            } else {             // v == 2：本位实为 0，进位穿透，偶数一步
                ans += 1;
                carry = 1;
            }
        }
        return ans + carry;      // 最高位 1+carry：为 2 即 "10"，再 /2 一步
    }
};
```

### Python

```python
class Solution:
    def numSteps(self, s: str) -> int:
        ans, carry = 0, 0
        for ch in reversed(s[1:]):      # 跳过最高位，从最低位扫到次高位
            v = (ch == '1') + carry     # 当前最低有效位的实际值
            ans += 1 + (v == 1)         # v=1 花 2 步；v=0/2 花 1 步
            carry = 1 if v else 0       # v>=1 时进位延续
        return ans + carry              # carry=1 时最高位为 "10"，补最后一步 /2
```

## 8. 边界情况与易错点

1. **不能转整数**：$n$ 可达 500 位，C++/Java 的 `long` / `long long` 上溢，`stol` 抛异常；Python 虽可转但沦为 $O(n^2)$，面试/比赛正解应直接扫字符串。
2. **`v == 2` 是头号大坑**：`s[i]='1'` 且 `carry=1` 时本位**实际是 0**（$1+1=10_2$，本位归零、进位上供），此时是偶数、只花 **1** 步——误写成 2 步是最常见 bug。示例 1 的第 1 位正是此情形。
3. **收尾的 `ans + carry` 别漏**：扫完 $i \ge 1$ 后，最高位实际值可能是 2（"10"），需要补最后一步 /2。漏掉会少算 1（如 "1101" 得 5 而非 6）。
4. **`s = "1"` 零步返回**：循环体不执行，`ans + carry = 0`，无需特判；同理 `s = "10"` 走 `v=0` 分支得 1。
5. **carry 归零时机**：仅 `v = 0`（该位为 0 且无进位）时 `carry = 0`；一旦点燃就烧到最高位（见 §4 第 2 点），不要在 `v = 2` 分支错误地清零。
6. **循环范围**：`i` 从 `n-1` 递减到 `1`，最高位不进循环——它由 `+ carry` 的收尾统一处理，混进循环会重复计步。
