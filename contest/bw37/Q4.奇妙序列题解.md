# LeetCode 奇妙序列 题解

## 1. 题目概述

- **标题 / 题号**：奇妙序列（#1622，hard）
- **链接**：https://leetcode.cn/problems/fancy-sequence/
- **来源**：LeetCode 第 37 场双周赛 Q4
- **难度**：困难
- **标签**：设计、线段树、数学、数论

**题意**：实现 `Fancy` 类，维护一个初始为空的整数序列，支持四种操作：

- `append(val)`：把 `val` 追加到序列末尾；
- `addAll(inc)`：序列中**所有现有**元素加 `inc`（只影响已存在的元素，不影响之后 append 的）；
- `multAll(m)`：序列中所有现有元素乘 `m`；
- `getIndex(idx)`：返回下标 `idx` 处元素对 $10^9+7$ 取余的结果；`idx ≥ 序列长度` 时返回 $-1$。

**约束**：

- $1 \le val, inc, m \le 100$
- $0 \le idx \le 10^5$
- 总调用次数不超过 $10^5$

> ⚠️ 注意 `getIndex` 要的是**当前真实值 mod p**。真实值本身可以指数级巨大（连乘 $m$ 多次），所以任何「老老实实存真值」的实现都必须与取模打交道——这是本题的第一道门槛。

## 2. 示例

**示例**

```text
输入：
["Fancy","append","addAll","append","multAll","getIndex","addAll","append","multAll","getIndex","getIndex","getIndex"]
[[],[2],[3],[7],[2],[0],[3],[10],[2],[0],[1],[2]]
输出：[null,null,null,null,null,10,null,null,null,26,34,20]

解释：
append(2)   → 序列 [2]
addAll(3)   → 序列 [5]
append(7)   → 序列 [5, 7]        （7 不吃之前的 addAll）
multAll(2)  → 序列 [10, 14]
getIndex(0) → 10
addAll(3)   → 序列 [13, 17]
append(10)  → 序列 [13, 17, 10]
multAll(2)  → 序列 [26, 34, 20]
getIndex(0) → 26，getIndex(1) → 34，getIndex(2) → 20
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法：真的用数组存每个元素，`addAll` / `multAll` 时遍历全体元素逐个修改——单次 $O(n)$，最坏 $10^5$ 次操作共 $O(10^{10})$，超时。即使全程对 $p = 10^9+7$ 取模（同余对加乘封闭，见 §5 引理 1），复杂度仍是 $O(n^2)$。标准数据结构解法是**线段树**：区间仿射更新（lazy tag 存 $(mul, add)$）+ 单点查询，单次 $O(\log n)$，总 $O(n \log n)$，能过。但本题有一个更轻、更优雅的 $O(1)$（append 为 $O(\log p)$）做法——把「全体操作」压缩成两个数。

### 3.2 核心观察：全局仿射变换只需 $(mul, add)$ 两个数

![核心观察：仿射 tag 与正逆变换](images/bw37_q4_affine_tag.svg)

`addAll` 和 `multAll` 都作用于**全体现有元素**，且都是仿射（一次多项式）函数：

$$v \mapsto m \cdot v + b.$$

若干次全局仿射的复合还是仿射：先 $(a_1, b_1)$（$v \mapsto a_1 v + b_1$）再 $(a_2, b_2)$，得 $v \mapsto a_2(a_1 v + b_1) + b_2 = (a_2 a_1) v + (a_2 b_1 + b_2)$。于是任意时刻，「从元素被 append 进来到现在」所经历的全部全局操作，可以汇总成**一对数** $(mul, add)$：

$$\text{真实值} \equiv base \cdot mul + add \pmod p,$$

其中 $base$ 是该元素「折算回追加时刻」的基坐标。全局操作只更新这一对数：

- `addAll(inc)`：$add \mathrel{+}= inc$；
- `multAll(m)`：$mul \mathrel{*}= m$，$add \mathrel{*}= m$（**加法偏移也要被放大**：$(v + add_{old}) \cdot m = m \cdot v + m \cdot add_{old}$）。

### 3.3 关键难点：append 发生在「过去」，需要历史重放式折算

![append 的历史折算与 getIndex 的正变换](images/bw37_q4_timeline.svg)

`append(val)` 的 `val` 是**当时**的真实值，而 $(mul, add)$ 此后还会继续演化。做法是把 `val` 按**当前的** tag 做逆变换，折算成基坐标存起来：

$$base = (val - add) \cdot mul^{-1} \bmod p.$$

这样无论之后全局 tag 怎么变，恒等式「真实值 $\equiv base \cdot mul + add$」始终成立；`getIndex(idx)` 直接做正变换：

$$\text{answer} = (base_{idx} \cdot mul + add) \bmod p.$$

除法 $mul^{-1}$ 在模 $p = 10^9+7$（素数）下用**费马小定理**求乘法逆元：$mul^{-1} \equiv mul^{p-2} \pmod p$，快速幂 $O(\log p)$。此处 $mul$ 永不为 $0 \bmod p$：$p$ 是大于 $100$ 的素数，每个 $m \le 100$ 都与 $p$ 互素，其乘积也与 $p$ 互素（§5 引理 2），逆元恒存在。

### 3.4 示例演算

![示例演算：tag 与 base 的全程演化](images/bw37_q4_walkthrough.svg)

回放官方示例，追踪 $(add, mul)$ 与数组中存的基坐标：

| 操作 | 全局 tag $(add, mul)$ | 数组（基坐标） | 真实序列（校验） |
|------|------------------|----------------|------------------|
| `append(2)` | $(0, 1)$ | $base = (2-0)\cdot 1 = 2$ → `[2]` | $[2]$ |
| `addAll(3)` | $(3, 1)$ | `[2]` | $[5]$ |
| `append(7)` | $(3, 1)$ | $base = (7-3)\cdot 1 = 4$ → `[2, 4]` | $[5, 7]$ |
| `multAll(2)` | $(6, 2)$ | `[2, 4]` | $[10, 14]$ |
| `getIndex(0)` | — | $2 \cdot 2 + 6 = 10$ | ✓ 返回 10 |
| `addAll(3)` | $(9, 2)$ | `[2, 4]` | $[13, 17]$ |
| `append(10)` | $(9, 2)$ | $base = (10-9)\cdot 2^{-1} = 1/2$ → `[2, 4, 1/2]` | $[13, 17, 10]$ |
| `multAll(2)` | $(18, 4)$ | `[2, 4, 1/2]` | $[26, 34, 20]$ |
| `getIndex(0/1/2)` | — | $2\cdot4+18{=}26$，$4\cdot4+18{=}34$，$\tfrac12\cdot4+18{=}20$ | ✓ 26/34/20 |

注意 `append(10)` 这一步：$1/2$ 是模 $p$ 意义下的「一半」即 $mul^{-1}(2) = 500000004$；查询时 $\tfrac12 \cdot 4 + 18 = 2 + 18 = 20$，恰好还原真实值——「先折回过去、再放回现在」的时间旅行闭环。

## 4. 算法细节

1. **tag 复合顺序别记反**：`multAll(m)` 是「先乘后看」——旧值 $v$ 的真实值为 $mul_{old} \cdot v + add_{old}$，全体再乘 $m$ 得 $m \cdot mul_{old} \cdot v + m \cdot add_{old}$，故 $(mul, add) \to (m \cdot mul,\ m \cdot add)$。`addAll(inc)` 只动 $add$。
2. **append 的折算公式**：$base = (val - add) \cdot mul^{-1} \bmod p$。$val - add$ 可能为负，先 $(val - add + p) \bmod p$ 再乘逆元。
3. **逆元求法**：$p$ 素数，费马小定理 $mul^{p-2} \bmod p$，快速幂 $O(\log p)$。$10^5$ 次 append 共约 $3 \times 10^6$ 次乘法，轻松。
4. **为什么 $mul \not\equiv 0$**：$p = 10^9 + 7 > 100 \ge m$，故 $\gcd(m, p) = 1$；同余乘积保持互素（若 $p \mid m_1 m_2 \cdots m_t$，由 $p$ 素数与欧几里得引理必有某个 $m_i$ 被 $p$ 整除，矛盾）。逆元永远良定义。
5. **getIndex 越界**：$idx \ge$ 数组长度返回 $-1$，先判再算。
6. **为什么可以全程取模**：`getIndex` 只要真实值 $\bmod p$；而「加 $inc$」「乘 $m$」都与 $\bmod\ p$ 交换（同余式两边可加可乘）。所以即便把 base 存成模 $p$ 的余数、tag 存成模 $p$ 的余数，读出的 $base \cdot mul + add \bmod p$ 仍等于真实大整数 $\bmod p$（§5 引理 1）。
7. **与线段树对比**：线段树把「区间」问题做全，本题只有「全体」操作，所以两个标量就够——线段树是杀鸡用牛刀，但若题目改成「对区间 $[l,r]$ 加/乘」，lazy tag 思路与本题同源。

## 5. 正确性证明

以下 $p = 10^9 + 7$，「真实值」指按题意用任意精度整数演化出的无界整数值。

**引理 1（同余保持）**：若整数 $x \equiv y \pmod p$，则对任意非负整数 $a, b$：$ax + b \equiv ay + b \pmod p$。因此「记录 $\bmod p$ 的余数 + 按模运算演化」与「记录真实值、最终取模」给出相同的 `getIndex` 结果。

**证明**：$x - y = kp \Rightarrow (ax + b) - (ay + b) = a(x-y) = (ak)p$。归纳于操作序列即得第二条。∎

**引理 2（逆元存在）**：任意时刻 $mul \not\equiv 0 \pmod p$，且 $\gcd(mul, p) = 1$，故 $mul^{-1} \bmod p$ 存在（费马小定理 $mul^{p-2} \cdot mul \equiv 1$）。

**证明**：$mul$ 初始为 $1$，每次乘 $m \in [1, 100]$。$p$ 是素数且 $p > 100$，每个 $m$ 满足 $p \nmid m$。若 $p \mid mul$（即 $mul$ 的整数原值被 $p$ 整除），由欧几里得引理（$p$ 素数，$p \mid m_1 \cdots m_t \Rightarrow p \mid m_i$ 对某 $i$）矛盾。故 $mul$ 与 $p$ 互素。∎

**定理（tag 不变量）**：设某下标 $i$ 于某时刻被 `append(val)` 加入。定义 $base_i = (val - add_t) \cdot mul_t^{-1} \bmod p$（$t$ 为 append 时刻的 tag）。则对**之后**任意时刻 $u$ 的 tag $(mul_u, add_u)$：

$$\text{真实值}_i^{(u)} \equiv base_i \cdot mul_u + add_u \pmod p.$$

**证明**：对 append 之后的操作次数 $u - t$ 归纳。基础 $u = t$：真实值 $= val$，而 $base_i \cdot mul_t + add_t \equiv (val - add_t) \cdot mul_t^{-1} \cdot mul_t + add_t \equiv val \pmod p$（引理 2 保证 $mul_t^{-1}$ 存在）。归纳步：设命题对 $u$ 成立。
- 若第 $u \to u+1$ 个操作是 `addAll(inc)`：真实值 $+inc$，tag 变 $(mul_u, add_u + inc)$，右端也 $+inc$，等式保持；
- 若是 `multAll(m)`：真实值 $\times m$，tag 变 $(m \cdot mul_u,\ m \cdot add_u)$，右端变为 $m \cdot (base_i \cdot mul_u + add_u)$，恰为原值 $\times m$；
- 若是 `append`（影响别的下标）或 `getIndex`：$i$ 的真实值与 tag 均不变。
归纳完成。`getIndex(idx)` 在当前 tag 下计算 $base_{idx} \cdot mul + add \bmod p$，由引理 1 与本定理，即真实值 $\bmod p$；越界返回 $-1$ 与题意一致。∎

## 6. 复杂度分析

- **时间**：`addAll` / `multAll` / `getIndex` 均为 $O(1)$；`append` 需一次快速幂求逆元，$O(\log p) \approx 30$ 次乘法。总调用 $\le 10^5$，总计 $O(N \log p) \approx 3 \times 10^6$。
- **空间**：$O(N)$ 存每个元素的基坐标（$N \le 10^5$ 个 `long long`，约 0.8 MB）。

对比：朴素数组 $O(N^2) = 10^{10}$ 会超时；线段树 $O(N \log N)$ 能过但代码长、常数大；本做法渐近与常数均最优。

## 7. 参考代码

### C++

```cpp
class Fancy {
    static constexpr long long MOD = 1000000007LL;
    vector<long long> vals;          // 基坐标：折算回追加时刻的值
    long long add = 0, mul = 1;      // 全局仿射 tag：真实值 ≡ base*mul + add (mod p)
    long long power(long long a, long long b) {
        long long r = 1;
        a %= MOD;
        while (b) {
            if (b & 1) r = r * a % MOD;
            a = a * a % MOD;
            b >>= 1;
        }
        return r;
    }
public:
    void append(int val) {
        // val = base*mul + add  =>  base = (val-add)*mul^{-1}
        long long base = (val % MOD - add + MOD) % MOD * power(mul, MOD - 2) % MOD;
        vals.push_back(base);
    }
    void addAll(int inc) { add = (add + inc) % MOD; }
    void multAll(int m) { add = add * m % MOD; mul = mul * m % MOD; }
    int getIndex(int idx) {
        if (idx < 0 || idx >= (int)vals.size()) return -1;
        return (int)(vals[idx] * mul % MOD + add) % MOD;
    }
};
```

### Python

```python
class Fancy:
    MOD = 1_000_000_007

    def __init__(self):
        self.vals = []              # 基坐标：折算回追加时刻的值
        self.add = 0
        self.mul = 1                # 全局仿射 tag

    def append(self, val: int) -> None:
        base = (val - self.add) % self.MOD * pow(self.mul, self.MOD - 2, self.MOD) % self.MOD
        self.vals.append(base)

    def addAll(self, inc: int) -> None:
        self.add = (self.add + inc) % self.MOD

    def multAll(self, m: int) -> None:
        self.add = self.add * m % self.MOD
        self.mul = self.mul * m % self.MOD

    def getIndex(self, idx: int) -> int:
        if idx >= len(self.vals):
            return -1
        return (self.vals[idx] * self.mul + self.add) % self.MOD
```

> 💡 两份代码均通过官方示例（`10, 26, 34, 20`）与越界返回 $-1$ 用例；并与两个独立暴力对拍：(1) 200 组小随机（`val/inc/m ≤ 4`）对照 **Python 大整数全程重放**（真实值不取模，最后才 mod），验证「取模演化」的数学基础；(2) 100 组中随机（参数上限 100）对照**全数组 mod 重放**（每次操作 $O(n)$ 施加到所有元素）；(3) 20 组 $\times$ 5000 次操作的大随机 C++/Python 互拍，全部一致，`mismatch = 0`。

## 8. 边界情况与易错点

1. **`getIndex` 越界返回 $-1$**：约束允许 `idx` 超过当前长度（$idx \le 10^5$ 但序列可能更短），先判界再取值。
2. **`multAll` 忘记同步放大 `add`**：只乘 `mul` 不乘 `add` 是最常见的 bug——tag 是「复合函数」，$(a, b)$ 再乘 $m$ 得 $(ma, mb)$ 而非 $(ma, b)$。
3. **`append` 折算时 `val - add` 为负**：C++ 中先 `+MOD` 再取模；Python 的 `%` 天然非负，但写清楚更稳。
4. **逆元不是除法**：模意义下没有「除」，必须 $mul^{p-2}$；且只有 $p$ 为素数、$\gcd(mul, p)=1$ 时费马小定理才适用（本题恒满足，引理 2）。若题目把 $m$ 的范围放宽到 $\ge p$ 或允许 $0$，此路不通，需改用扩展欧几里得或另想办法。
5. **`getIndex` 的运算优先级**：`(vals[idx] * mul % MOD + add) % MOD`，`base*mul` 先取模再加 `add`，最后再取一次——`add` 本身 $< p$，加完仍可能 $\ge p$。
6. **`static constexpr` 与成员初始化**：C++ 类内 `vector` 成员在构造时为空即可，无需显式构造函数；LeetCode 会默认构造。
7. **「只影响现有元素」**：`addAll`/`multAll` 不作用于未来 append 的值——这正是需要「历史折算」而不是「统一对 val 取模」的原因；若误解为「全局缓存一个待加量，append 时直接加上」，`multAll` 之后逻辑就乱了。
