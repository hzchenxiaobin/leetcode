# LeetCode 移除盒子 题解

## 1. 题目概述

- **标题 / 题号**：移除盒子（#546，hard）
- **链接**：https://leetcode.cn/problems/remove-boxes/
- **来源**：LeetCode 第 25 场周赛 Q4
- **难度**：困难
- **标签**：记忆化搜索，数组，动态规划

**题意**：给定一排盒子，`boxes[i]` 是盒子的颜色（用正整数表示）。每一轮可以移除**同色且连续**的 $k$ 个盒子（$k \ge 1$），得到 $k^2$ 分；移除后左右两侧的盒子会拼接成新的相邻关系。反复操作直到盒子全部移除，求能获得的**最大积分和**。

注意得分是**平方**而非线性：把两段同色盒子攒到一起消掉，收益严格大于分开消。这正是本题的关键，也是所有错误的来源。

**约束**：

- $1 \le \text{boxes.length} \le 100$
- $1 \le \text{boxes}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：boxes = [1,3,2,2,2,3,4,3,1]
输出：23
解释：
[1, 3, 2, 2, 2, 3, 4, 3, 1]
--> [1, 3, 3, 4, 3, 1]   (3*3 = 9 分，消掉三个 2)
--> [1, 3, 3, 3, 1]      (1*1 = 1 分，消掉孤立的 4)
--> [1, 1]               (3*3 = 9 分，三个 3 连成一段)
--> []                   (2*2 = 4 分，两个 1)
合计 9 + 1 + 9 + 4 = 23，可以证明这是最优。
```

**示例 2**

```text
输入：boxes = [1,1,1]
输出：9
解释：三个同色盒子一次消掉，3*3 = 9；若分三次消只有 1+1+1 = 3。
```

**示例 3**

```text
输入：boxes = [1]
输出：1
解释：只有一个盒子，消掉得 1*1 = 1。
```

## 3. 解题思路

### 3.1 暴力思路

直接搜索「每一步选哪一段消」：每一轮的状态是一个数组，分支是当前所有极大的同色连续段。$n = 100$ 时状态数指数级爆炸，因为同一个「剩余盒子集合」可能由无数种顺序到达，而消去的顺序又影响下一步的拼接关系。即使记忆化，状态也是「剩余盒子的多重集合 + 排列」，不可行。

强行按区间做普通区间 DP 同样不行：设 $f(l,r)$ 表示消掉 `boxes[l..r]` 的最大得分，转移写成

$$f(l,r) = \max_{l \le m < r}\bigl(f(l,m) + f(m+1,r)\bigr)$$

这个式子在本题是**错的**——它假设左半段与右半段可以各自独立消完。但 `[1,2,1,2,1]` 的最优解是「先消掉两个 2，再把三个 1 一起消」，三个 1 在区间被切开后永远无法合并到同一段里，上式只能给出 $5$，而正解是 $11$。

### 3.2 核心观察：把「右端外挂了几个同色盒子」写进状态

![为什么状态要多带一个 k](images/wc25_q4_k_state_concept.svg)

失败的原因很明确：**一个区间的答案依赖于它右侧还残留着哪些同色盒子**。如果 `boxes[r]` 右边还有 $k$ 个同色盒子，那么 `boxes[r]` 这一段的真实长度是 $k+1$，把它消掉能得 $(k+1)^2$ 分，而不是 $1$ 分；更妙的是，它还可以选择「先不消」，等中间的盒子被清空后与左侧同色盒子并成更大的段。

于是把 $k$ 提升为状态的一维：

$$dp(l,r,k) = \text{只考虑 boxes}[l..r]\ \text{，右端点外挂 } k \text{ 个与 boxes}[r] \text{ 同色的盒子时的最大得分}$$

- $k$ 个「外挂」盒子的含义：它们在原数组中位于 $r$ 的右侧（或来自更右侧的递归合并），已经确定要与 `boxes[r]` 所在的那一段**一起被消掉**，所以只需记录个数。
- 答案就是 $dp(0,n-1,0)$。
- 有了 $k$，`[1,2,1,2,1]` 就能被正确表达：$dp(0,4,0)$ 可以把下标 4 的 `1` 挂到下标 2 的 `1` 上，递归成 $dp(0,2,1)$，再把下标 2 挂到下标 0 上，最终 $dp(0,0,2)$ 一次消掉三个 `1`。

**为什么 $k$ 就够用**：一个盒子的颜色只可能与同色盒子合并，而合并只发生在「中间的东西被消光」之后。因此对当前区间而言，外部世界的影响只有「右侧积压了几个同色待并盒」这一项信息，其余细节都不影响得分。

### 3.3 状态转移

![dp(l,r,k) 的两类决策](images/wc25_q4_dp_transition_flow.svg)

进入 $dp(l,r,k)$ 后先做一个**尾段压缩**：只要 $r > l$ 且 `boxes[r] == boxes[r-1]`，就令 $r \leftarrow r-1$、$k \leftarrow k+1$。相邻同色的盒子必然同轮被消，等价于其中靠右的那个变成「外挂」，区间规模缩小、$k$ 增大。

压缩之后再从两种互斥且穷尽的情形中取最大：

- **① 立刻消掉右端这一整段**：得到 $(k+1)^2$ 分，剩余 $dp(l,r-1,0)$：

$$dp(l,r,k) = dp(l,r-1,0) + (k+1)^2$$

- **② 留到左边某个同色盒子 $i$ 处合并**（$l \le i < r$ 且 `boxes[i] == boxes[r]`）：要合并，就必须先把 $(i, r)$ 之间的一切消光，即 $dp(i+1,r-1,0)$；然后右端那 $k+1$ 个盒子继续「挂」在左区间上，即 $dp(l,i,k+1)$：

$$dp(l,r,k) = \max_{l \le i < r,\ \text{boxes}[i] = \text{boxes}[r]} \Bigl(dp(l,i,k+1) + dp(i+1,r-1,0)\Bigr)$$

边界：$l > r$ 时 $dp = 0$。

### 3.4 示例演算

![dp(0,4,0) 的决策链](images/wc25_q4_walkthrough.svg)

以 `boxes = [1,2,1,2,1]` 为例（答案 11）：

| 状态 | 决策 | 值 |
|------|------|----|
| $dp(0,4,0)$ | ② 与下标 2 的 `1` 合并 | 11 |
| $dp(0,2,1)$ | ② 与下标 0 的 `1` 合并 | 10 |
| $dp(0,0,2)$ | ① 一次消三个 `1`，$(2+1)^2 = 9$ | 9 |
| $dp(1,1,0)$ | ① 单独消一个 `2`，$1^2 = 1$ | 1 |
| $dp(3,3,0)$ | ① 单独消一个 `2`，$1^2 = 1$ | 1 |

代入得 $dp(0,4,0) = 10 + 1 = 11$，其中 $dp(0,2,1) = 9 + 1 = 10$。对应的实际执行顺序是：先消下标 1 的 `2`（1 分），再消下标 3 的 `2`（1 分），此时三个 `1` 已经连续，一次性消掉（9 分），合计 11。若按普通区间 DP 以为「先分开消更好」，只能拿到 $1+1+1+1+1 = 5$。

官方示例 `[1,3,2,2,2,3,4,3,1]` 的决策链同样如此：$dp(0,8,0)$ 在下标 0 处的 `1` 上合并（把最右侧的 `1` 挂过去），中间 $dp(1,7,0)$ 再处理 `3,2,2,2,3,4,3`，一路累计出 $23$。

## 4. 算法细节

1. **状态语义要写死在注释里**：$k$ 是「位于 $r$ 右侧、已确定要与 `boxes[r]` 所在段同消的盒子个数」，而不是「区间内与 `boxes[r]` 同色的个数」。两种理解会导致完全不同的转移式。
2. **尾段压缩放在取记忆值之前还是之后**：本文代码先按**原始** $(l,r,k)$ 取引用与查表，再压缩。这样缓存键与语义严格一致；若先压缩再以压缩后的键存表，也正确但会重复计算同一状态，不如前者直观。
3. **压缩是「剪辑」而非「等价类」**：$dp(l,r,k) = dp(l,r-1,k+1)$ 成立的前提是 `boxes[r] == boxes[r-1]`——两者相邻，任何消法都会把它们放进同一段（否则把两段合并只会更优）。压缩把这类冗余状态直接折叠，实测能省掉大量分支。
4. **$k$ 的上界**：外挂盒子必须互不相同，且都在 $r$ 右侧，故 $k \le n-1-r \le n-1$。因此 C++ 用 `int memo[n][n][n]`、Python 用 `lru_cache` 都不会越界；$n = 100$ 时三维数组约 $4$ MB。
5. **递归顺序**：转移的两个子问题区间长度都严格小于当前区间（$dp(l,i,k+1)$ 的 $i < r$，$dp(i+1,r-1,0)$ 更短），所以带记忆化的递归天然无环，无需显式确定遍历顺序。若写成递推，需要按区间长度从短到长、$k$ 从大到小枚举。
6. **剪枝不必写**：分支②只在 `boxes[i] == boxes[r]` 时展开，已经自动跳过大量无效 $i$；再加「同一个颜色只保留最右的 $i$」会破坏最优性，不能加。
7. **C++ 取引用的位置**：`int &res = memo[l][r][k];` 必须在压缩**之前**取，因为压缩改变了 $l,r,k$ 的局部值；取引用后写 `res` 仍然写回原始下标对应的格子。

## 5. 正确性证明

**引理 1（尾段压缩不改变最优值）**：若 $r > l$ 且 `boxes[r] == boxes[r-1]`，则 $dp(l,r,k) = dp(l,r-1,k+1)$。

**证明**：相邻且同色的两个盒子在任何消法中都不能被「分开得更优」地处理。设最优方案中二者分别所在的两轮大小为 $a$、$b$。这两个盒子在整个过程中始终相邻且同色，直到其中之一被消掉为止，因此可以构造交换：

- 若 $a \le b+1$，把 `boxes[r-1]` 所在那一轮提前、与 `boxes[r]` 的那一轮合并，得分变化为 $(b+1)^2 - b^2 - \bigl(a^2 - (a-1)^2\bigr) = 2(b - a + 1) \ge 0$；
- 若 $a \ge b+1$，反过来把 `boxes[r]` 推迟到 `boxes[r-1]` 那一轮，得分变化为 $(a+1)^2 - a^2 - \bigl(b^2 - (b-1)^2\bigr) = 2(a - b + 1) > 0$。

两种情形至少有一种不劣，故存在最优方案使二者同轮被消——把这两个盒子视作一个整体，正是「右端点左移一格、外挂数 $k$ 加一」。反过来，任给 $dp(l,r-1,k+1)$ 的一个方案，把外挂的 $k+1$ 个同色盒子看成一段、并把 `boxes[r]` 并入其中，就得到 $dp(l,r,k)$ 的一个同分方案，故 $dp(l,r,k) \ge dp(l,r-1,k+1)$；两个方向合起来即得等号。∎

**引理 2（转移覆盖且可行）**：$dp(l,r,k)$ 的两条转移式覆盖了最优方案的全部可能，且每一支都对应一个真实可执行的消法。

**证明**：考察最优方案中「`boxes[r]` 连同 $k$ 个外挂盒子」这一整段的最终去向：

- 它们作为一个整体被消掉。由于区间内 $[l,r-1]$ 的消法与它们互不干扰，得分是 $(k+1)^2$ 加上 $[l,r-1]$ 的最优值，即分支①。
- 它们与左侧某个同色 `boxes[i]`（$l \le i < r$）合并。由于合并要求二者相邻，$(i,r)$ 之间的盒子必须先被全部消光，这部分贡献恰为 $dp(i+1,r-1,0)$；而剩余任务正好是「消掉 $[l,i]$，且右端外挂 $k+1$ 个同色」，即 $dp(l,i,k+1)$。这就得到分支②，且对同色的 $i$ 取最大覆盖了所有合并对象。

两种情形互斥且穷尽。可行方向上，分支①先执行 $[l,r-1]$ 的最优消法、再消右端段；分支②先执行 $(i,r)$ 的最优消法、再执行 $dp(l,i,k+1)$，其内部递归地在适当时候消掉整段，均合法，故 $dp$ 值不超过最优值。∎

**定理**：$dp(0,n-1,0)$ 等于可获得的最大积分。

**证明**：对区间长度归纳。长度 $\le 0$ 时 $dp = 0$ 显然最优。设所有更短区间（含任意 $k$）的 $dp$ 值都等于最优值。由引理 1，可先做尾段压缩而不改变最优值，压缩后 $dp(l,r,k)$ 由引理 2 的①、②两支构成：分支①、②内部引用的子问题区间都严格更短，由归纳假设其值等于对应子任务的最优值；两支的取值又分别对应可行方案，且最优方案必属其一。因此 $dp(l,r,k)$ 恰为最优值。取 $l=0$、$r=n-1$、$k=0$ 即得答案。∎

## 6. 复杂度分析

- **时间**：状态数 $O(n^3)$（$l$、$r$ 各 $n$ 种，$k$ 不超过 $n$），每个状态枚举 $i$ 为 $O(n)$，故上界 $O(n^4)$。$n = 100$ 时上界约 $10^8$，但尾段压缩与「只有同色 $i$ 才展开」把实际转移数压低了一到两个数量级；实测 $n=100$ 的随机数据在 Python 下耗时约 $0.3$ s 量级。
- **空间**：记忆化表 $O(n^3)$ 个整数，$n=100$ 时 C++ 的三维 `int` 数组约 $4$ MB；另加递归栈 $O(n)$（每层至少消掉一个盒子或缩小一个端点）。Python 的 `lru_cache` 只存真正访问过的状态，实际远小于 $n^3$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int removeBoxes(vector<int>& boxes) {
        int n = boxes.size();
        memo.assign(n, vector<vector<int>>(n, vector<int>(n, -1)));
        return dp(boxes, 0, n - 1, 0);
    }

private:
    vector<vector<vector<int>>> memo;

    // [l, r] 区间，右端外挂 k 个与 boxes[r] 同色的盒子
    int dp(vector<int>& b, int l, int r, int k) {
        if (l > r) return 0;
        int& res = memo[l][r][k];          // 先按原始 (l, r, k) 取引用
        if (res != -1) return res;

        while (r > l && b[r] == b[r - 1]) { // 尾段同色压缩
            --r;
            ++k;
        }

        res = dp(b, l, r - 1, 0) + (k + 1) * (k + 1);          // ① 立刻消掉
        for (int i = l; i < r; ++i) {                            // ② 留到左侧同色处
            if (b[i] == b[r]) {
                res = max(res, dp(b, l, i, k + 1) + dp(b, i + 1, r - 1, 0));
            }
        }
        return res;
    }
};
```

### Python

```python
from functools import lru_cache


class Solution:
    def removeBoxes(self, boxes: list[int]) -> int:
        n = len(boxes)

        @lru_cache(maxsize=None)
        def dp(l: int, r: int, k: int) -> int:
            # boxes[l..r] 区间，右端外挂 k 个与 boxes[r] 同色的盒子
            if l > r:
                return 0
            while r > l and boxes[r] == boxes[r - 1]:   # 尾段同色压缩
                r -= 1
                k += 1

            # ① 立刻消掉右端这一整段
            best = dp(l, r - 1, 0) + (k + 1) * (k + 1)
            # ② 留到左侧同色盒子 i 处合并
            for i in range(l, r):
                if boxes[i] == boxes[r]:
                    cand = dp(l, i, k + 1) + dp(i + 1, r - 1, 0)
                    if cand > best:
                        best = cand
            return best

        return dp(0, n - 1, 0)
```

## 8. 边界情况与易错点

1. **$n = 1$**：直接返回 $1$。递归写法里 $dp(0,0,0)$ 命中分支①，得 $(0+1)^2 = 1$，无需特判。
2. **全部同色**：答案 $n^2$。压缩循环会把 $r$ 一路收到 $l$、$k$ 涨到 $n-1$，注意 `memo` 的 $k$ 维度必须开到 $n$（不是 $n-1$ 的下标之外再溢出）。
3. **错把 $k$ 理解成「区间内同色个数」**：会把 `[1,2,1,2,1]` 算成 $11$ 之外的错误值；$k$ 只统计**区间外**待合并的数量。
4. **漏掉 $k$ 维（退化成区间 DP）**：`[1,2,1,2,1]` 会输出 $5$ 而不是 $11$，这是最典型的 WA。
5. **压缩顺序与缓存键不一致**：先压缩再用新键递归、却又用旧键存表，会读到错位的状态。统一规则：查表用入口参数，压缩只作用于局部变量。
6. **Python 递归深度**：递归层数约为 $2n$，$n = 100$ 时远小于默认上限 $1000$，无需 `setrecursionlimit`；但若把题目扩到 $n \sim 1000$，必须改成递推或手动加限。
7. **贪心「能合并就先合并」**：`[1,3,2,2,2,3,4,3,1]` 里 `4` 夹在两个 `3` 之间，直觉上先消 `4` 是对的；但 `[1,2,1,2,1]` 里先凑两个 `2`（4 分 + 两个 `1` 的 4 分 + 中间 `1` 的 1 分 = 9）反而不如攒三个 `1`（11 分）。平方收益必须用 DP 权衡，不能贪心。
8. **`(k+1)^2` 的溢出**：$k \le 99$，最大值 $10^4$，`int` 足够；但若题目把平方改成更高次幂，需要换 `long long`。
