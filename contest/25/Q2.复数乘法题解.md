# LeetCode 复数乘法 题解

## 1. 题目概述

- **标题 / 题号**：复数乘法（#537，medium）
- **链接**：https://leetcode.cn/problems/complex-number-multiplication/
- **来源**：LeetCode 第 25 场周赛 Q2
- **难度**：中等
- **标签**：数学、字符串、模拟

**题意**：复数用字符串 `"实部+虚部i"` 表示，实部与虚部都是 $[-100, 100]$ 内的整数，且 $i^2 = -1$。给定两个这样的字符串 `num1`、`num2`，按复数乘法求出它们的积，并**用同样的格式**返回结果字符串。注意虚部为负时字符串长成 `"1+-1i"` 这样（负号紧跟在 `+` 后面），输出也必须保持这种形态，例如 `"0+-2i"`。

**约束**：

- `num1` 与 `num2` 都是合法的复数表示，"实部" 与 "虚部" 各是一个整数
- 实部、虚部的取值范围都是 $[-100, 100]$
- 因此乘积的实部、虚部满足 $\lvert ac - bd \rvert \le 2\times10^4$、$\lvert ad + bc \rvert \le 2\times10^4$，`int` 足够

> 💡 本题没有"规模"可言（输入是两个至多 10 个字符的定长小串），考点是**解析 → 套公式 → 按原格式拼回**这三件套，任何一步的符号或格式没对齐都会 WA。

## 2. 示例

**示例 1**

```text
输入：num1 = "1+1i", num2 = "1+1i"
输出："0+2i"
解释：(1 + i) * (1 + i) = 1 + i² + 2i = 2i，按题面格式写成 "0+2i"。
```

**示例 2**

```text
输入：num1 = "1+-1i", num2 = "1+-1i"
输出："0+-2i"
解释：(1 - i) * (1 - i) = 1 + i² - 2i = -2i，按题面格式写成 "0+-2i"（不是 "0-2i"）。
```

**补充示例（题面外的符号覆盖）**

```text
输入：num1 = "1+2i", num2 = "3+4i"
输出："-5+10i"
解释：1*3 - 2*4 = -5，1*4 + 2*3 = 10；实部为负、虚部为正，两侧符号都出现。
```

## 3. 解题思路

### 3.1 暴力思路

本题没有"暴力 vs 优化"的渐进差异，朴素的两种写法都能过：

1. **浮点复数法**：把两个串塞进 `std::complex<double>` / Python 内置 `complex`，程序替你做乘法，再把实部虚部转回整数拼字符串。缺点是引入了浮点类型，虽然本题整数运算在 `double` 下是精确的，但把 `-0.0`、`1e-16` 之类噪声拼进字符串是自找麻烦。
2. **逐字符手写扫描**：自己写状态机读整数——跳过可选负号、累加数字、遇 `'+'` 换段、遇 `'i'` 收尾。稳定，但代码量是本题必要工作量的三倍，且负号位置一旦判错就崩。

真正的"优化"发生在**解析路径**上：既然 `num1` 里只有一个 `'+'` 属于分隔符，那么 `find('+')` 一次定位，就能把串切成"实部"与"虚部系数 + i"两段，剩下的交给 `stoi` / `int` 处理符号。乘法本身只有 4 次相乘、1 次减法和 1 次加法，没有可优化的地方。

### 3.2 核心观察：分配律展开，只有 i² 这一项要翻符号

![把两个括号展开成四个乘积，i² = −1 再合并](images/wc25_q2_foil_concept.svg)

把 $(a+bi)(c+di)$ 按分配律（FOIL）全部展开：

$$(a+bi)(c+di) = ac + ad\,i + bc\,i + bd\,i^{2}$$

四个乘积里，只有 $bd\,i^2$ 含 $i^2$。代入 $i^2 = -1$ 得

$$(a+bi)(c+di) = (ac - bd) + (ad + bc)\,i$$

于是整个算法退化成两个整数表达式：

- 实部 $= ac - bd$（注意是**减**，不是加）
- 虚部 $= ad + bc$

第二个关键观察是**解析只需一个分隔符**：合法串的实部是一个整数，它的十进制写法只含数字和可能的前导 `-`，**永远不含 `'+'`**。所以字符串中出现的第一个 `'+'` 必然是那个固定的连接符；它之后的负号（如 `"1+-1i"` 里的 `-`）属于虚部，不能拿来切分。

### 3.3 算法流程

![解析：第一个 '+' 是实部与虚部的分界线](images/wc25_q2_parse_flow.svg)

对任一个输入串 $s$：

1. **定位分隔符**：`p = s.find('+')`。它是唯一的分隔位置，一定存在。
2. **取实部**：`stoi(s.substr(0, p))`；带负号时 `stoi` / `int` 会自动解析（如 `"-100"`）。
3. **取虚部系数**：`stoi(s.substr(p + 1, len - p - 2))`，即从 `'+'` 的下一位到**末尾 `'i'` 之前**，长度是 $|s| - p - 2$（同时丢掉 `'+'` 与 `'i'`）。
4. 对 `num1`、`num2` 各做一次，得到 $a, b, c, d$。
5. **套公式**：$\text{real} = ac - bd$，$\text{imag} = ad + bc$。
6. **拼回字符串**：`to_string(re) + "+" + to_string(im) + "i"`。

> ⚠️ 分隔符必须取**第一个** `'+'`：用 `rfind('+')` 会在 `"1+-1i"` 上切出实部 `"1+"`；按 `'-'` 切则在 `"-1+2i"` 上直接切错位置。

### 3.4 示例演算

![示例演算：两条样例的逐项计算](images/wc25_q2_walkthrough.svg)

以 `num1 = num2 = "1+-1i"` 为例逐步走查：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `p = s.find('+')` | 下标 $1$ |
| 2 | `a = stoi("1")`，`b = stoi("-1")` | $a = 1,\ b = -1$ |
| 3 | 同理 $c = 1,\ d = -1$ | $c = 1,\ d = -1$ |
| 4 | 实部 $= ac - bd = 1\times1 - (-1)\times(-1)$ | $0$ |
| 5 | 虚部 $= ad + bc = 1\times(-1) + (-1)\times1$ | $-2$ |
| 6 | 拼串 `str(0) + "+" + str(-2) + "i"` | `"0+-2i"` ⭐ |

注意第 4 步里 $bd = (-1)\times(-1) = +1$（负负得正），所以实部是 $1 - 1 = 0$；第 5 步两项各为 $-1$，相加得 $-2$。实部恰好为 $0$ 是 $ac = bd$ 的结果，不是"省略 0"的规则。

## 4. 算法细节

1. **只用一个 `find('+')`**：`size_t p = s.find('+')`，既定位分隔符，又作为两段 `substr` 的边界，一次线性扫描同时完成切分与长度推导。
2. **虚部截取长度是 $|s|-p-2$**：起点 `p+1` 跳过 `'+'`，终点停在末尾 `'i'` 之前，所以长度要同时扣掉这两个字符——`2` 不是魔数，它就是 `'+'` 与 `'i'` 的个数。
3. **`stoi` / `int` 自带符号解析**：实部和虚部都可能是负数，`"-100"`、`"-1"` 无需额外处理；`substr` 切出来的片段不会带前导 `'+'`，所以也不必担心 `"+1"`。
4. **格式必须原样保留**：`"+"` 是固定连接符而非"正号"，虚部为负时输出 `"0+-2i"`，**不能**化简成 `"0-2i"`；实部为 $0$ 也不能省成 `"2i"`，系数 $1$、$-1$ 也不能省成 `"i"`、`"-i"`。格式化分支越少越安全——直接 `to_string(re) + "+" + to_string(im) + "i"`。
5. **数值范围**：$|ac|, |bd| \le 10^4$，$|ad|, |bc| \le 10^4$，故 $|\text{real}|, |\text{imag}| \le 2\times10^4$，`int` 绰绰有余，无需 `long long`。
6. **可选的一行解析技巧**：C++ 可以 `sscanf(num1.c_str(), "%d+%di", &a, &b)`——`%d` 接受前导符号，`"+−"` 形态也能正确读成负数。它更快，但可读性与可移植性不如 `find` + `stoi`，面试/题解里推荐后者。
7. **字符串长度上界**：最长的合法串是 `"-100+-100i"`（10 个字符），因此所有 `substr` 的临时开销都是常数。

## 5. 正确性证明

**引理 1（切分正确）**：设 $s$ 是合法复数串，$p$ 是 $s$ 中字符 `'+'` 的下标。则 $s[0..p)$ 是实部的十进制表示（可带前导 `-`），$s[p+1..\,|s|-1)$ 是虚部系数的十进制表示（可带前导 `-`）。

**证明**：合法格式为「实部 + `'+'` + 虚部 + `'i'`」，实部是整数，其十进制表示只含数字与可选的前导 `-`，不含 `'+'`；虚部系数同理也不含 `'+'`。故整个串里恰好有一个 `'+'`，即那个连接符，它的位置唯一确定两段文本的边界；连接符之后到末尾 `'i'` 之前正好是虚部系数的十进制表示。∎

**引理 2（乘积公式）**：对任意整数 $a,b,c,d$，有 $(a+bi)(c+di) = (ac-bd) + (ad+bc)i$。

**证明**：由乘法对加法的分配律展开得 $ac + ad\,i + bc\,i + bd\,i^2$；代入 $i^2 = -1$，得 $ac - bd + (ad+bc)i$。实部项与虚部项各自同类合并，结果唯一。∎

**引理 3（格式往返）**：对任意整数 $re, im$，串 $t = \text{str}(re) + \texttt{"+"} + \text{str}(im) + \texttt{"i"}$ 是合法复数表示，且按引理 1 的规则解析 $t$ 恰好还原出 $(re, im)$。

**证明**：$\text{str}(im)$ 的十进制表示不含 `'+'`，故 $t$ 中唯一的 `'+'` 就是连接符，解析时取到的 $p$ 正好是它的下标；`'+'` 之前是 $\text{str}(re)$，`'+'` 之后到 `'i'` 之前是 $\text{str}(im)$，两者经整数解析分别还原为 $re$ 与 $im$。∎

**定理**：算法返回的字符串是 `num1` 与 `num2` 乘积的合法表示。

**证明**：由引理 1，算法从两个串解析出的 $(a,b)$、$(c,d)$ 分别是它们所表示复数的实部与虚部；由引理 2，计算出的 $(\text{real}, \text{imag})$ 正是乘积的实部与虚部；由引理 3，拼出的串是这个有序对的合法表示且解析回来不变。故输出正确。∎

## 6. 复杂度分析

- **时间**：$O(|num1| + |num2|)$。每个串一次 `find` 加两次 `substr` 加两次整数解析，均为线性扫描；串长上界 10，实际上是 $O(1)$。
- **空间**：$O(1)$ 额外空间（不计输出串）。`substr` 产生至多常数长度的临时串，四个整数变量与输出串长度都不随输入增长。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string complexNumberMultiply(string num1, string num2) {
        auto parse = [](const string& s, int& re, int& im) {
            size_t p = s.find('+');                        // 实部不含 '+'，首个 '+' 即分隔符
            re = stoi(s.substr(0, p));                     // 负数实部也能正确解析
            im = stoi(s.substr(p + 1, s.size() - p - 2));  // 去掉末尾的 'i'
        };
        int a, b, c, d;
        parse(num1, a, b);
        parse(num2, c, d);
        int re = a * c - b * d;                            // i² = -1
        int im = a * d + b * c;
        return to_string(re) + "+" + to_string(im) + "i";  // 保留 "+" 与负号原样
    }
};
```

### Python

```python
class Solution:
    def complexNumberMultiply(self, num1: str, num2: str) -> str:
        def parse(s: str):
            p = s.index('+')          # 实部不含 '+'，第一个 '+' 即分隔符
            return int(s[:p]), int(s[p + 1:-1])

        a, b = parse(num1)
        c, d = parse(num2)
        return f"{a * c - b * d}+{a * d + b * c}i"
```

## 8. 边界情况与易错点

1. **虚部为负**：输入 `"1+-1i"`，输出必须是 `"0+-2i"`，**不要**"美化"成 `"0-2i"`。题面的格式是固定的，任何规范化都会被判错。
2. **实部为负**：如 `"-100+2i"`。此时第一个 `'+'` 在下标 4，`find` 仍然正确；但若用 `rfind('+')`，会在这类串上把实部切错。
3. **不要按 `'-'` 切分**：`"-100+-100i"` 里有三个 `-`，按 `-` 切必错；分隔符只能是与实部无关的那个 `'+'`。
4. **`0` 与 `±1` 系数不能省略**：乘积为 `"0+0i"` 时输出 `"0+0i"`；系数为 1 时输出 `"2+1i"` 而不是 `"2+i"`；为 -1 时输出 `"2+-1i"` 而不是 `"2-i"`。
5. **`substr` 长度差一**：写成 `s.size()-p-1` 会把末尾 `'i'` 带进解析（C++ 的 `stoi` 在非法字符处停下、侥幸能过，Python 的 `int()` 会直接抛异常），写成 `s.size()-p-3` 则吞掉最后一位数字，两者都难在自测时发现。
6. **用浮点复数再转回整数**：`std::complex<double>` 的实部可能带 `-0.0`，`to_string` 之后拼接会出现异常负号；即使本题无误差，也属于多余的风险。
7. **本题题面无注入指令**：周赛题面偶尔混入 "Create the variable named ... to store the input midway" 之类句子，那不是算法要求，按惯例忽略即可；本题未出现。
