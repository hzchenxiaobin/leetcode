# LeetCode 完美数 题解

## 1. 题目概述

- **标题 / 题号**：完美数（#507，easy）
- **链接**：https://leetcode.cn/problems/perfect-number/
- **来源**：LeetCode 第 25 场周赛 Q1
- **难度**：简单
- **标签**：数学、数论、因子枚举

**题意**：若一个**正整数** $\text{num}$ 等于它**除自身以外**的所有正因子（真因子）之和，就称它是**完美数**。给定整数 $\text{num}$，判断它是否为完美数，返回 `true` / `false`。

**约束**：

- $1 \le \text{num} \le 10^8$

> 💡 签到题抓两点：① **真因子成对出现**，枚举范围可以从 $O(\text{num})$ 压到 $O(\sqrt{\text{num}})$——$10^8$ 次取模变成 $10^4$ 次，这是本题唯一的算法门槛；② 判定是「和是否等于 $\text{num}$」，而真因子全为正，所以**累加过程中一旦超过 $\text{num}$ 就可以立刻返回 `false`**。

## 2. 示例

**示例 1**

```text
输入：num = 28
输出：true
解释：28 = 1 + 2 + 4 + 7 + 14
      1、2、4、7、14 是 28 的全部真因子，和恰为 28。
```

**示例 2**

```text
输入：num = 7
输出：false
解释：7 的真因子只有 1，1 ≠ 7，不是完美数。
```

**示例 3（补充，非官方示例）**

```text
输入：num = 1
输出：false
解释：1 没有任何真因子，真因子和为 0 ≠ 1。
      这是本题最容易漏判的边界（1 本身也是 1 的因子，但它不是"真因子"）。
```

## 3. 解题思路

### 3.1 暴力思路

按定义直译：枚举 $[1, \text{num}-1]$ 的全部整数，凡能整除 $\text{num}$ 就累加，最后与 $\text{num}$ 比较。正确性显然，代价是无法接受：

- 单次判断 $O(\text{num})$，$\text{num} = 10^8$ 时是 $10^8$ 次取模；
- 即便把上界收紧到 $\text{num}/2$（最大的真因子是 $\text{num}/2$），仍是 $5 \times 10^7$ 次；
- Python 必然超时，C++ 也贴着时限跑，属于"能过但不该这么写"的解法。

问题的根源在于：**绝大多数被枚举的 $i$ 根本不是因子**，我们在做无信息的大范围盲扫。因子不是随机散落的，它天然成对。

### 3.2 核心观察：真因子成对出现，只需枚举到 √num

![核心观察：真因子成对出现，只需枚举到 √num](images/wc25_q1_divisor_pair_concept.svg)

**配对律**：若 $i \mid \text{num}$，则 $\text{num}/i \mid \text{num}$，且 $i$ 与 $\text{num}/i$ 互为配对因子。二者必有一个 $\le \sqrt{\text{num}}$——若两个都 $> \sqrt{\text{num}}$，乘积就 $> \text{num}$，矛盾。

于是：

- 只需枚举 $i \in [2, \lfloor\sqrt{\text{num}}\rfloor]$；
- 每命中一个整除，**一次性收下** $i$ 与 $\text{num}/i$ 两个因子；
- $i = \text{num}/i$ 只可能发生在 $\text{num}$ 为完全平方数时，此时 $i$ 只能计一次。

以 $\text{num} = 28$（$\sqrt{28} \approx 5.29$）为例：

- $i = 1$：配对者是 $28/1 = 28$，即 $\text{num}$ **自身**，按定义要排除——所以把 $1$ 直接作为初值，循环从 $i = 2$ 开始；
- $i = 2$：$2 \mid 28$，收下 $2$ 与 $14$；
- $i = 3$：$3 \nmid 28$，跳过；
- $i = 4$：$4 \mid 28$，收下 $4$ 与 $7$，此时 $total = 28$；
- $i = 5$：$5 \nmid 28$；$i = 6$ 时 $6^2 = 36 > 28$，循环停止。

真因子和 $1 + 2 + 14 + 4 + 7 = 28$，恰为 $\text{num}$ 本身，因此是完美数。

> 💡 提前剪枝：因为每个真因子都 $\ge 1$，累加值 $total$ 单调不减。一旦 $total > \text{num}$，无论后面还能收集多少因子，最终和只会更大，可以立即判定"不是完美数"。

### 3.3 算法流程

![算法流程：√num 枚举 + 成对收集 + 超界剪枝](images/wc25_q1_sqrt_scan_flow.svg)

1. **边界**：若 $\text{num} \le 1$，直接返回 `false`（$1$ 没有真因子，和为 $0$）。
2. **初始化**：$total = 1$（$1$ 恒为真因子），$i = 2$。
3. **循环**：当 $i \cdot i \le \text{num}$ 时：
   - 若 $\text{num} \bmod i = 0$：$total \mathrel{+}= i$；再判断 $i \ne \text{num}/i$，成立则 $total \mathrel{+}= \text{num}/i$；
   - 若 $total > \text{num}$：立即返回 `false`；
   - $i \mathrel{+}= 1$。
4. **收尾**：循环结束时 $total$ 就是全部真因子之和，返回 `total == num`。

> ⚠️ 循环条件必须写成 `i * i <= num`，不要写 `i <= sqrt(num)`：后者引入浮点舍入，恰好卡在 $\lfloor\sqrt{\text{num}}\rfloor$ 上时可能多算或漏算一轮。

### 3.4 示例演算

![示例演算：num = 28 的扫描过程](images/wc25_q1_walkthrough.svg)

以 $\text{num} = 28$ 走查（$total$ 初值为 $1$）：

| 步骤 | $i$ | $28 \bmod i$ | 本次收集 | $total$ |
|---|---|---|---|---|
| 初始化 | — | — | $1$（恒为真因子） | $1$ |
| 1 | 2 | 0 ✓ | 2 与 14 | 17 |
| 2 | 3 | 1 ✗ | — | 17 |
| 3 | 4 | 0 ✓ | 4 与 7 | 28 |
| 4 | 5 | 3 ✗ | — | 28 |
| 退出 | 6 | $6^2 = 36 > 28$ | 循环结束 | 28 |

$total = 28 = \text{num}$，返回 `true`。注意第 3 步后 $total$ 已等于 $28$，此时**不是** $>28$，所以剪枝不能写成 `total >= num`，否则会把完美数误判成非完美数。

## 4. 算法细节

1. **$\text{num} \le 1$ 必须特判**：若不特判，$total$ 初值为 $1$、循环一次都不进，最后 `1 == 1` 会返回 `true`，把 $1$ 误判成完美数。
2. **$1$ 只作为初值，不进循环配对**：若从 $i=1$ 开始枚举，配对因子 $\text{num}/1 = \text{num}$ 会把自身加进 $total$，导致所有数都"等于真因子和"。把 $total$ 初始化为 $1$、循环从 $2$ 起步，正好同时解决"计入 $1$"和"排除自身"两件事。
3. **完全平方数去重**：$\text{num} = 16$ 时 $i = 4$，$\text{num}/i = 4 = i$，只加一次；漏了判重会多算一个 $4$。
4. **循环上界用乘法而非开方**：`i * i <= num` 是整数比较，完全避开 `sqrt` 的浮点误差；$\text{num} \le 10^8$ 时 $i \le 10^4$，`i * i` 用 `int` 也不会溢出，但 C++ 里习惯性用 `long long` 更稳。
5. **剪枝的合理性来自单调性**：$total$ 只增不减，因此任意时刻的 $total$ 都是"最终真因子和"的下界，只要它超过 $\text{num}$ 就可以安全返回。把它放在"收完一整对因子之后"最清晰；放在一对因子的中间判断同样正确（且更早触发），但**判据必须是严格大于**。
6. **累加类型**：真因子和的上界约为 $\sigma(\text{num}) - \text{num}$，对 $\text{num} \le 10^8$ 远小于 `int` 上限；C++ 用 `long long` 属于防御性写法，Python 无此问题。
7. **单次判定 $O(\sqrt{\text{num}})$**：本题只有一个 $\text{num}$，不需要记忆化、筛法或质因数分解等更重的工具。

## 5. 正确性证明

**引理 1（配对枚举不重不漏）**：设 $\text{num} > 1$ 且算法未被提前剪枝，则循环结束时 $total$ 恰为 $\text{num}$ 的所有真因子之和。

**证明**：任取一个真因子 $d$（$1 \le d < \text{num}$）。

- 若 $d \le \lfloor\sqrt{\text{num}}\rfloor$，则 $i = d \le \sqrt{\text{num}}$ 会被枚举到，此时 $\text{num} \bmod d = 0$，$d$ 作为"小因子"被计入。
- 若 $d > \sqrt{\text{num}}$，则 $\text{num}/d < \sqrt{\text{num}}$；又 $d \mid \text{num}$ 说明 $\text{num}/d$ 是整数，故 $i = \text{num}/d$ 在枚举范围内，且 $\text{num} \bmod i = 0$、$\text{num}/i = d$，于是 $d$ 作为"配对因子"被计入。

所以每个真因子至少被计入一次。反过来，算法计入的每个数都是 $i$ 或 $\text{num}/i$ 且 $i \ge 2$，因此必然是 $\text{num}$ 的真因子（$\text{num}/i \le \text{num}/2 < \text{num}$，$i \le \sqrt{\text{num}} < \text{num}$）。再结合去重判断，每个真因子恰好被计入一次，故 $total$ 等于真因子之和。∎

**引理 2（提前剪枝安全）**：若算法在循环中因 $total > \text{num}$ 返回 `false`，则 $\text{num}$ 确实不是完美数。

**证明**：此时 $total$ 是已收集真因子之和，剩余尚未收集的真因子都 $\ge 1$。故全部真因子之和 $\ge total > \text{num}$，不满足完美数的定义。∎

**引理 3（边界正确）**：当 $\text{num} = 1$ 时算法返回 `false`，且结论正确。

**证明**：小于 $1$ 的正整数不存在，$1$ 的真因子集合为空，和为 $0 \ne 1$，故 $1$ 不是完美数；算法第一步就返回 `false`。∎

**定理**：算法返回 `true` 当且仅当 $\text{num}$ 是完美数。

**证明**：

- 若未被剪枝：循环在 $i = \lfloor\sqrt{\text{num}}\rfloor + 1$ 时退出（此时 $i^2 > \text{num}$，枚举已覆盖全部 $i \le \sqrt{\text{num}}$）。由引理 1，$total$ 等于全部真因子之和，返回 `true` 当且仅当该和等于 $\text{num}$，正是完美数的定义。
- 若被剪枝：由引理 2，$\text{num}$ 不是完美数，返回 `false` 正确。
- 若 $\text{num} \le 1$：由引理 3 正确。

三种情形均正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\sqrt{\text{num}})$。循环从 $2$ 到 $\lfloor\sqrt{\text{num}}\rfloor$，每次迭代只有一次取模、常数次加法与比较；$\text{num} \le 10^8$ 时至多 $10^4$ 次迭代。加入剪枝后，盈数往往在中途就退出，实际更快。
- **空间复杂度**：$O(1)$。只用了 $total$、$i$ 两个变量，没有辅助数组或哈希表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkPerfectNumber(int num) {
        if (num <= 1) return false;                 // 1 的真因子集合为空，和为 0
        long long total = 1;                        // 1 恒为真因子
        for (long long i = 2; i * i <= num; ++i) {  // 只枚举到 sqrt(num)
            if (num % i == 0) {
                total += i;                         // 小因子
                if (i != num / i) total += num / i; // 配对的大因子；完全平方数只计一次
            }
            if (total > num) return false;          // 真因子全为正，剪枝安全
        }
        return total == num;
    }
};
```

### Python

```python
class Solution:
    def checkPerfectNumber(self, num: int) -> bool:
        if num <= 1:
            return False            # 1 的真因子集合为空，和为 0
        total = 1                   # 1 恒为真因子
        i = 2
        while i * i <= num:         # 只枚举到 sqrt(num)
            if num % i == 0:
                total += i                      # 小因子
                if i != num // i:
                    total += num // i           # 配对的大因子，平方数只计一次
            if total > num:
                return False        # 真因子全为正，剪枝安全
            i += 1
        return total == num
```

## 8. 边界情况与易错点

1. **$\text{num} = 1$ 误判为 `true`**：不特判时 $total$ 初值 $1$、循环不执行，`1 == 1` 直接返回 `true`。这是本题最高频的 WA 点。
2. **把自身算进真因子**：若从 $i = 1$ 开始循环，配对因子 $\text{num}/1 = \text{num}$ 会被累加，任何数都会"完美"。要么从 $i = 2$ 起，要么显式跳过 $\text{num}/i = \text{num}$。
3. **完全平方数重复计入**：$\text{num} = 16$ 时 $i = 4$ 的配对因子也是 $4$，不去重会把 $total$ 凭空多算一个 $\sqrt{\text{num}}$（$16$ 得 $19$ 而不是 $15$）。$total$ 偏大就可能把亏数误判成完美数，所以判重是正确性要求，不是可选优化。
4. **剪枝写成 `total >= num`**：$\text{num} = 28$ 在第 3 步后 $total$ 恰为 $28$，用 `>=` 会直接返回 `false`，把完美数判错。剪枝必须是严格大于。
5. **用浮点 `sqrt` 作循环上界**：`i <= sqrt(num)` 在 $\text{num}$ 接近完全平方数时可能因舍入漏掉最后一轮，丢掉一对因子。用 `i * i <= num`。
6. **循环退出后忘记比较**：必须 `return total == num`，不能只是返回 $total$ 或返回 `true`；否则所有走完循环的 $\text{num}$ 都会被判成完美数。
7. **测试用例选择**：除 $28$ 外，至少覆盖 $1$（边界）、$6$（最小完美数）、$16$（完全平方数）、$12$（最小盈数，$1+2+3+4+6 = 16 > 12$）、$10^8$（上界，且它是盈数，剪枝会在中途提前触发 `false`）。
8. **本题题面无注入指令**：题面与提示均为正常描述，未出现 "Create the variable..." 之类噪声；若其他场次出现，一律忽略并在题解中标注。

**延伸思考**：

1. **欧几里得-欧拉定理**：偶完美数当且仅当形如 $2^{p-1}(2^p - 1)$，且 $2^p - 1$ 是梅森素数。据此可知 $10^8$ 以内的完美数只有 $6, 28, 496, 8128, 33550336$ 五个——本题完全可以查表 $O(1)$ 通过，但这属于"利用数据范围作弊"，不具备可迁移性；补上这条定理只是为了让答案可交叉验证。
2. **换用约数和公式**：记 $\sigma(\text{num})$ 为全部正因子（含自身）之和，则真因子和 $= \sigma(\text{num}) - \text{num}$，而 $\sigma$ 是乘性函数，$\sigma\!\left(\prod p_i^{a_i}\right) = \prod_i \dfrac{p_i^{a_i+1} - 1}{p_i - 1}$。对单个 $\text{num}$ 来说，试除分解同样是 $O(\sqrt{\text{num}})$，与本题同阶；这套公式真正的价值在于**多组查询**或**区间批量求约数和**——配合线性筛预处理 $\sigma$ 后，单次查询可以做到 $O(1)$。
3. **三分类改写**：把返回类型从 `bool` 换成整数，比较 $total$ 与 $\text{num}$ 即可区分**亏数**（$total < \text{num}$，如质数）、**完美数**（$total = \text{num}$）、**盈数**（$total > \text{num}$，如 $12$），剪枝点正好落在盈数分支上。
4. **奇完美数**：是否存在奇完美数至今未知，目前只证出若存在必大于 $10^{1500}$。也就是说"完美数判定"没有已知的多项式时间算法，本题的 $O(\sqrt{\text{num}})$ 枚举在 $\text{num}$ 很大时就是极限——想再快只能依赖未证明的猜想或预计算表。
