# LeetCode 判断两个事件是否存在冲突 题解

## 1. 题目概述

- **标题 / 题号**：判断两个事件是否存在冲突（#2446，easy）
- **链接**：https://leetcode.cn/problems/determine-if-two-events-have-conflict/
- **来源**：LeetCode 第 316 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、区间

**题意**：给定两个长度为 $2$ 的字符串数组 `event1` 与 `event2`，表示同一天的两个**闭区间**时间段事件：`event1 = [startTime1, endTime1]`、`event2 = [startTime2, endTime2]`，时间均为合法 24 小时制 `HH:MM` 格式。若两事件存在**非空的公共时刻**（即闭区间相交），则称出现**冲突**，返回 `true`；否则返回 `false`。

**约束**：

- $\text{event1.length} == \text{event2.length} == 2$
- $\text{event1}[i].length == \text{event2}[i].length == 5$
- $\text{startTime1} \le \text{endTime1}$，$\text{startTime2} \le \text{endTime2}$（端点天然有序，无需归一化）
- 所有时间均为合法 `HH:MM` 格式（定长 5 位、零填充）

> 💡 签到题的定位：这是一道**把题面定义直接翻译成一个不等式**的题。赛中要做的只有两件事——识别出「冲突 = 闭区间相交」，以及看清「端点相接也算」。真正的坑不在算法选择，而在**等号**上。

## 2. 示例

**示例 1**

```text
输入：event1 = ["01:15","02:00"], event2 = ["02:00","03:00"]
输出：true
解释：两个事件在 02:00 出现交集（端点相接也算冲突）。
```

**示例 2**

```text
输入：event1 = ["01:00","02:00"], event2 = ["01:20","03:00"]
输出：true
解释：两个事件的交集从 01:20 开始，到 02:00 结束。
```

**示例 3**

```text
输入：event1 = ["10:00","11:00"], event2 = ["14:00","15:00"]
输出：false
解释：两个事件不存在交集。
```

## 3. 解题思路

### 3.1 暴力思路：转分钟逐刻扫描

最朴素的做法：把每个 `HH:MM` 解析成「自 00:00 起的分钟数」，得到四个整数 $S_1, E_1, S_2, E_2$，然后枚举一天 $0 \sim 1439$ 共 $1440$ 个分钟时刻，看是否存在某个时刻 $t$ 同时满足 $S_1 \le t \le E_1$ 且 $S_2 \le t \le E_2$。$O(1440)$ 显然能过，但它把「一个布尔判定」拆成了「逐点求交」，完全掩盖了区间相交的结构——**两个闭区间是否相交，本来只需端点比较，不需要任何遍历**。

> ⚠️ 赛中警示：签到题的时间应该花在读清「闭区间」三个字上，而不是写解析 + 循环。多写一步解析，就多一处 `substr` 下标写错的机会。

### 3.2 核心观察：闭区间相交的端点不等式

![核心观察：闭区间相交判定](images/conflict_events_interval_condition.svg)

记两区间为 $[s_1, e_1]$ 与 $[s_2, e_2]$。两个关键观察：

1. **相交判定是一条不等式**：两个闭区间相交，当且仅当**各自的起点都不超过对方的终点**：
   $$\text{冲突} \iff s_1 \le e_2 \;\wedge\; s_2 \le e_1$$
   等价表述：交区间为 $[\max(s_1,s_2), \min(e_1,e_2)]$，非空即冲突。反向表述（德摩根对偶）：不相交 $\iff e_1 < s_2 \vee e_2 < s_1$，即一方**严格**整体在另一侧。注意**闭区间端点相等也算相交**——示例 1 中 $e_1 = s_2 =$ `02:00`，该时刻被两个事件同时包含，算冲突。
2. **字符串可以直接比较**：`HH:MM` 是定长 5 位、零填充的格式（如 `09:05`）。两个这种字符串的字典序与时间先后**完全一致**：先比时块两位、再比分块两位，每一位都是 `'0'`–`'9'` 的字符比较，而数字字符的 ASCII 序即数值序。故 `"01:15" < "02:00"`、`"11:00" < "14:00"` 直接用 `<` / `<=`，**连转分钟都可省去**。

> 💡 「定长零填充表示 $\Rightarrow$ 字典序 = 数值序」是常用结论，反之若时间是 `"9:00"` 这类变长写法则失效（字典序 `"9:00" > "10:00"` 但时间更早），必须先归一化。本题已保证恰 5 位，安全。

### 3.3 算法流程

![算法流程：两次比较判定冲突](images/conflict_events_flow.svg)

只需两步端点比较，逻辑上对称覆盖「两个相离方向」：

```text
1. 若 s1 ≤ e2 不成立（事件1整体在事件2之后）→ 相离，返回 false
2. 若 s2 ≤ e1 不成立（事件2整体在事件1之后）→ 相离，返回 false
3. 否则两区间互相跨过对方起点 → 冲突，返回 true
```

两个比较缺一不可：$s_1 \le e_2$ 只能排除「事件 2 在前」的相离，排除不了反向。短路特性下单次比较即可提前返回 `false`，最坏（真冲突）也只需两次比较。

### 3.4 示例演算

![示例演算：三个情形的端点比较](images/conflict_events_walkthrough.svg)

| 示例 | $s_1 \le e_2$ | $s_2 \le e_1$ | 交集 | 结果 |
|------|---------------|---------------|------|------|
| 1 | `"01:15" ≤ "03:00"` ✓ | `"02:00" ≤ "02:00"` ✓（等号） | $\{02{:}00\}$ 单点 | `true` |
| 2 | `"01:00" ≤ "03:00"` ✓ | `"01:20" ≤ "02:00"` ✓ | $[01{:}20, 02{:}00]$ | `true` |
| 3 | `"10:00" ≤ "15:00"` ✓ | `"14:00" ≤ "11:00"` ✗ | $\varnothing$ | `false` |

示例 1 是本题的题眼：$s_2 = e_1$ 恰好成立，等号保住了单点交集；示例 3 则在第二个比较处短路返回 `false`。

## 4. 算法细节

1. **两种等价写法**：正向形式 `s1 <= e2 && s2 <= e1`；取反形式 `!(e1 < s2 || e2 < s1)`（先判相离再取反）。二者互为德摩根对偶。**推荐正向形式**——语义是「双方都跨过对方起点」，边界符号不易写错。
2. **比较的对象是原始字符串**：`event1[0]` 即 $s_1$、`event1[1]` 即 $e_1$。C++ 的 `string::operator<=` 与 Python 的 `str` 比较都按字典序，对定长零填充的 `HH:MM` 即时间序。
3. **无需交换或排序**：输入保证 $\text{start} \le \text{end}$；两个比较方向对称，事件谁前谁后不影响结果。
4. **稳妥版（转分钟）**：若担心格式问题，可先转成分钟数 $t = \mathrm{HH} \times 60 + \mathrm{MM}$ 再做同样的两个比较，正确性等价，只是多一次解析。
5. **max/min 视角**：`max(s1, s2) <= min(e1, e2)` 与两不等式等价，且顺手给出交区间 $[\max(s_1,s_2), \min(e_1,e_2)]$——若题目进一步问交集长度，用这个形式最自然。

## 5. 正确性证明

**引理 1**：对两个合法 `HH:MM` 定长字符串 $t_1, t_2$，字典序 $t_1 \le t_2$ 当且仅当 $t_1$ 所示时刻不晚于 $t_2$ 所示时刻。

**证明**：写 $t_1 = h_1 h_1' : m_1 m_1'$，$t_2 = h_2 h_2' : m_2 m_2'$，其中时块、分块各为两位零填充数字串，第 3 个字符同为 `':'`，必相等。先证一个子事实：两位零填充数字串 $ab$ 与 $a'b'$ 的字典序等价于数值序 $10a+b \le 10a'+b'$——字典序先比首位：$a < a'$，或 $a = a'$ 且 $b \le b'$，逐条对应数值比较的两种情况（数字字符 `'0' < \cdots < '9'` 的 ASCII 序即数值序）。回到时间串：字典序比较先落在时块（第 1、2 位），时块字典序小即小时数值小，时刻更早；时块相等时落在分块，同理分钟数值决定先后。故字典序与时间序一致。∎

**引理 2**：闭区间 $[s_1, e_1]$、$[s_2, e_2]$（$s_1 \le e_1$，$s_2 \le e_2$）有非空交集，当且仅当 $s_1 \le e_2$ 且 $s_2 \le e_1$。

**证明**：（$\Rightarrow$）设 $x$ 属于两区间之交，则 $s_1 \le x \le e_2$ 与 $s_2 \le x \le e_1$ 同时成立，两端分别传递即得 $s_1 \le e_2$、$s_2 \le e_1$。（$\Leftarrow$）注意 $\max(s_1,s_2) \le \min(e_1,e_2)$ 等价于「每个左元不超过每个右元」共四个不等式：$s_1 \le e_1$、$s_1 \le e_2$、$s_2 \le e_1$、$s_2 \le e_2$，其中两个由区间自身有序给出，另两个即所设条件，故 $\max(s_1,s_2) \le \min(e_1,e_2)$ 成立，区间 $[\max(s_1,s_2), \min(e_1,e_2)]$ 非空且含于两区间之交。∎

**定理**：算法返回 `true` 当且仅当两事件存在冲突。

**证明**：代码中的两次比较是 `HH:MM` 字符串比较，由引理 1，其结果与对应时刻的比较一致，故算法判定的是 $s_1 \le e_2 \wedge s_2 \le e_1$。由引理 2，该条件与「两闭区间有非空交集」等价；而题面定义冲突为存在两事件都包含的时刻，即闭区间之交非空。故算法输出与「是否冲突」一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$。至多两次字符串比较，每次比较定长 5 个字符（实际仅在数字位逐位比较，遇 `':'` 必相等），常数开销；相比之下逐分钟扫描为 $O(1440)$，转分钟法为 $O(1)$ 但多两步解析。
- **空间复杂度**：$O(1)$。仅按下标访问输入数组，无额外数据结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool haveConflict(vector<string>& event1, vector<string>& event2) {
        return event1[0] <= event2[1] && event2[0] <= event1[1];
    }
};
```

### Python

```python
class Solution:
    def haveConflict(self, event1: List[str], event2: List[str]) -> bool:
        return event1[0] <= event2[1] and event2[0] <= event1[1]
```

### 稳妥版（转分钟，正确性等价）

```python
class Solution:
    def haveConflict(self, event1: List[str], event2: List[str]) -> bool:
        def to_min(t: str) -> int:
            return int(t[:2]) * 60 + int(t[3:])
        return to_min(event1[0]) <= to_min(event2[1]) and \
               to_min(event2[0]) <= to_min(event1[1])
```

## 8. 边界情况与易错点

1. **端点相接算冲突（本题最大坑，示例 1）**：$e_1 = s_2$ 时闭区间共享该时刻，是冲突。把正向式写成严格不等 `event1[0] < event2[1] && ...` 会在示例 1 上返回 `false`——**等号必须保留**。取反写法 `!(e1 < s2 || e2 < s1)` 中相离用严格 `<`，同样是在保护这个等号。
2. **只判「包含」会漏解**：`s1 <= s2 && e2 <= e1` 只覆盖事件 1 完全包含事件 2 的情形，漏掉部分重叠（示例 2 的交错形态）与反向包含，WA。
3. **字符串直比的前提是定长零填充**：题面保证 `HH:MM` 恰 5 位。若输入可能是 `"9:00"` 这类变长格式，字典序失效（`"9:00" > "10:00"`），必须先转分钟或补零归一化。本题无需处理。
4. **输入已保证 start ≤ end**：不要画蛇添足做交换归一；两个比较方向本身对称，谁先谁后结果一致。
5. **一天没有 24:00**：合法时刻上界是 `23:59`（分钟数 $1439$），若写逐分钟扫描枚举 $0 \sim 1439$ 即可，不存在回绕问题（两事件同属一天）。
6. **全天事件必冲突**：`["00:00","23:59"]` 与任何事件都冲突（含在 `23:59` 处相接的情形），可用于对拍 sanity check。
