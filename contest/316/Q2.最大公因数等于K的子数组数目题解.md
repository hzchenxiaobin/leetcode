# LeetCode 最大公因数等于 K 的子数组数目 题解

## 1. 题目概述

- **标题 / 题号**：最大公因数等于 K 的子数组数目（#2447，medium）
- **链接**：https://leetcode.cn/problems/number-of-subarrays-with-gcd-equal-to-k/
- **来源**：LeetCode 第 316 场周赛 Q2
- **难度**：中等
- **标签**：数组、数学、数论

**题意**：给定整数数组 $\text{nums}$ 与整数 $k$，统计 $\text{nums}$ 中**元素最大公因数（GCD）恰好等于 $k$** 的**连续非空子数组**数目。

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $1 \le \text{nums[i]},\ k \le 10^9$

> 💡 本题在本仓库另有[每日题解 2447](../../solution/2401-2500/2447_最大公因数等于K的子数组数目.md)：侧重与 2470（lcm 版）的对偶视角、$O(n \log V)$ 段表进阶与面试问答。本篇按周赛复盘视角展开，侧重**赛场上的识别路径**、**不重不漏的完整证明**、**「k 倍数墙」分段归约观察**与**边界情况清单**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [9,3,1,2,6,3], k = 3
输出：4
解释：gcd 等于 3 的子数组是 [9,3]、[3]（下标 1）、[6,3]、[3]（下标 5），共 4 个。
```

**示例 2**

```text
输入：nums = [4], k = 7
输出：0
解释：不存在 gcd 等于 7 的子数组。
```

**示例 3**（自构造，覆盖「是 k 的倍数但 gcd 偏大」「非 k 倍数切断」两种关键情形）

```text
输入：nums = [3,6,9,2,3], k = 3
输出：5
解释：gcd 等于 3 的子数组是 [3]、[3,6]、[3,6,9]、[6,9]、[3]（末尾），共 5 个。
单独的 [6]、[9] 虽是 3 的倍数，但 gcd 分别为 6、9，不等于 3；
元素 2 不是 3 的倍数，任何跨过它的子数组 gcd 都不含因子 3。
```

## 3. 解题思路

### 3.1 暴力思路：枚举子数组 + 独立求 gcd

最朴素的做法：枚举全部 $O(n^2)$ 个子数组 $[i, j]$，每次从左到右重新累积一遍 gcd。每个子数组要扫完整个区间，共 $\Theta(n^3)$ 次 gcd 合并，$n = 1000$ 时 $10^9$ 量级，不可行。

第一个改进是**复用前缀 gcd**：固定左端点 $i$，右端点 $j$ 右移时增量维护 $g \leftarrow \gcd(g, \text{nums}[j])$（gcd 满足结合律，增量维护正确），每步一次欧几里得 $O(\log V)$，总 $O(n^2 \log V)$。$n \le 1000$ 时内层至多 $\binom{n+1}{2} \approx 5 \times 10^5$ 步，赛时已稳 AC。但若就此打住，仍未利用「**单调性 + 整除传递**」做**早退剪枝**——下文两条性质把「明知无望仍硬扫」的步数砍掉。

> 💡 **赛场识别路径**：$n \le 1000$ 直接发 $O(n^2)$ 许可证；「子数组 + 聚合量恰好等于定值」是「319 场 Q2（lcm）/ 713（乘积）/ 本题（gcd）」一族的标准骨架，套路固定为「固定一端、增量维护聚合量、按单调性剪枝」。

### 3.2 核心观察：前缀 gcd + 整除链早退

![核心观察：gcd 单调不增与整除链早退](images/wc316_q2_gcd_monotone.svg)

固定左端点 $i$，记 $G_j = \gcd(\text{nums}[i], \dots, \text{nums}[j])$。三条性质：

1. **单调不增 + 整除链**：$G_{j+1} = \gcd(G_j, \text{nums}[j+1])$，而 gcd 必整除其操作数，故 $G_{j+1} \mid G_j$。一路传递下去：**未来的每一步 gcd 都是当前 $g$ 的因子**。
2. **一票判定**：子数组的 gcd 要等于 $k$，未来某步必须取到 $k$，而未来取值全部是当前 $g$ 的因子。于是「还有没有希望」由一条整除式判定：
   - 若 $k \mid g$：$k$ 仍是未来 gcd 的可能取值，**继续扩展**；
   - 若 $k \nmid g$：未来所有 gcd 都是 $g$ 的因子、都不被 $k$ 整除，**永远到不了 $k$**，立即 `break`。
3. **命中后的惰性**：$g = k$ 后继续吞并 $k$ 的倍数，$\gcd(k, tk) = k$ 不变。所以命中时**计数但不 break**——更长的子数组继续合法（如 $[6,3,9],\ k=3$ 中 $[6,3]$ 与 $[6,3,9]$ 都算）。

> ⚠️ 剪枝判据必须是 $k \nmid g$（即 `g % k != 0`）。三个近亲写法都不行：`g != k` 会把 $[9,3]$ 这种「先 9 后 3」的路径错杀；`g < k` 是正确但更弱的剪枝（$g = 8,\ k = 3$ 时该退不退，白扫）；拿 `g % k == 0` 当计数条件则会把 $g = 9$ 这类「含因子 $k$ 但更大」的子数组多算进去。

### 3.3 算法流程

![算法流程：双重枚举与前缀 gcd 早退](images/wc316_q2_gcd_flow.svg)

```text
ans = 0
for i = 0 to n-1:
    g = 0                        # gcd(0, x) = x，首元素直接进位
    for j = i to n-1:
        g = gcd(g, nums[j])
        if g % k != 0: break     # k ∤ g：未来永不可能等于 k
        if g == k: ans += 1      # 命中；不 break，续吞 k 的倍数
return ans
```

结构上是「外层枚举左端点、内层向右扩张」的双重循环，内层只有三种出口：`k ∤ g` 早退、命中计数后继续、$j$ 走到 $n$ 自然结束。无论哪种出口，都回到外层换下一个起点，$g$ 重置。

### 3.4 示例演算

![示例演算：每个起点的扩展路径](images/wc316_q2_gcd_walkthrough.svg)

以 $\text{nums}=[9,3,1,2,6,3],\ k=3$ 为例，逐起点展开（$g$ 初值 $0$）：

| $i$ | 扩展路径 $j$ | 前缀 gcd 序列 | 命中 |
|-----|-------------|--------------|------|
| 0 | $0 \to 1 \to 2$ | $9,\ 3,\ 1$ | $[9,3]$ |
| 1 | $1 \to 2$ | $3,\ 1$ | $[3]$ |
| 2 | $2$ | $1$ | —（$3 \nmid 1$，break） |
| 3 | $3$ | $2$ | —（$3 \nmid 2$，break） |
| 4 | $4 \to 5$ | $6,\ 3$ | $[6,3]$ |
| 5 | $5$ | $3$ | $[3]$ |

合计 **4 个**。$i=0$ 处 $g=9>3$ 但 $3 \mid 9$ 故继续，下一步收敛到 $3$ 命中——这正是「$g > k$ 不能 break，要看 $k \mid g$」的体现；$i=2,3$ 首元素即 $k \nmid g$，内层只跑一步。

## 4. 算法细节

1. **枚举方向与增量维护**：固定左端点 $i$ 向右扩 $j$（对称地固定右端点向左扩也等价）。$g$ 初值取 $0$，利用 $\gcd(0, x) = x$ 让首元素自然进位，免特判 $j = i$。gcd 的结合律 $\gcd(\gcd(a,b),c) = \gcd(a,\gcd(b,c))$ 保证「增量合并」与「整体求 gcd」结果一致。
2. **剪枝判据的「一票否决」**：判据问的是「$k$ 是否还是未来 gcd 的可能取值」，等价于 $k \mid g$，对应代码 `g % k != 0` 即 break。辨析见 §3.2 的 ⚠️。
3. **命中不 break**：$\gcd(k, tk) = k$，$k$ 的倍数进窗不改 $g$；只有 $k \nmid g$ 才终止内层。
4. **「k 倍数墙」分段归约（本篇的增量观察）**：gcd 等于 $k$ 的子数组内**每个元素都是 $k$ 的倍数**（$G$ 整除每个元素）。于是非 $k$ 倍数元素是「墙」，把数组切成若干独立段；段内令 $b_t = \text{nums}[t] / k$，则 $[i,j]$ 的 gcd 等于 $k \iff \gcd(b_i, \dots, b_j) = 1$，问题归约为「gcd = 1 的子数组计数」。这层归约不写进代码也不影响正确性（剪枝天然处理墙：第一步 $k \nmid g$ 即 break），但它是手算验算与进阶变形的抓手。
5. **语言与溢出**：C++17 `<numeric>` 的 `std::gcd` 与 Python 的 `math.gcd` 都满足 $\gcd(0, x) = x$。gcd 结果 $\le$ 最小元素 $\le 10^9 < 2^{31} - 1$，`int` 全程无溢出——对照 319 场 Q2 的 lcm 版（$\mathrm{lcm}$ 连乘会爆 `long long`，须先判 $x \mid k$ 再乘），gcd 族天然安全。
6. **计数上限**：答案 $\le \binom{n+1}{2} \le 500500$，`int` 足够。

## 5. 正确性证明

**引理 1（整除链与单调性）**：固定左端点 $i$，记 $G_j = \gcd(\text{nums}[i], \dots, \text{nums}[j])$（$i \le j$）。则对任意 $i \le j \le j'$，有 $G_{j'} \mid G_j$；特别地 $G_{j+1} \mid G_j$，且 $G_{j'} \le G_j$。

**证明**：先证 $G_{j+1} = \gcd(G_j, \text{nums}[j+1])$。一个数是 $\{\text{nums}[i], \dots, \text{nums}[j+1]\}$ 的公因子，当且仅当它同时是 $\{\text{nums}[i], \dots, \text{nums}[j]\}$ 的公因子与 $\text{nums}[j+1]$ 的因子（逐元素验证），故两边的公因子集合相同，最大元一致，此即 gcd 的结合律。其次，$\gcd(x, y)$ 是 $x$ 与 $y$ 的公因子，故整除 $x$，于是 $G_{j+1} \mid G_j$。对 $j' > j$ 链式传递：$G_{j'} \mid G_{j'-1} \mid \cdots \mid G_j$。均为正整数，整除蕴含不超过，得 $G_{j'} \le G_j$。∎

**引理 2（剪枝安全性）**：若 $k \nmid G_j$，则对一切 $j' \ge j$，$G_{j'} \ne k$。

**证明**：反证：设存在 $j' \ge j$ 使 $G_{j'} = k$。由引理 1，$G_{j'} \mid G_j$，故 $k \mid G_j$，与 $k \nmid G_j$ 矛盾。∎

**引理 3（命中后的保持性）**：若 $G_j = k$，且 $\text{nums}[j+1], \dots, \text{nums}[t]$ 均为 $k$ 的倍数，则 $G_t = k$。

**证明**：对 $t$ 归纳。$t = j$ 时显然。设已有 $G_t = k$，加入 $k$ 的倍数 $mk$：$G_{t+1} = \gcd(G_t, mk) = \gcd(k, mk)$。$k$ 整除 $k$ 与 $mk$，是公因子；而任何公因子都整除 $k$，故不超过 $k$。因此最大公因子恰为 $k$，即 $G_{t+1} = k$。∎

**定理**：算法返回值恰为 gcd 等于 $k$ 的子数组个数（不重不漏）。

**证明**：子数组与数对 $(i, j)$（$i \le j$）一一对应。**不重**：双重循环按 $i$ 外层、$j$ 内层推进，每个数对至多被访问一次；算法仅在访问 $(i,j)$ 且当前 $g = G_j = k$ 时计数一次，故每个合法子数组贡献恰为 $1$。**不漏**：设 $[i, j]$ 满足 $G_j = k$，证 $(i,j)$ 必被访问且被计数。反设内层循环在某个 $j'' \in [i, j)$ 处 break，即 $k \nmid G_{j''}$；但 $[i, j] \supseteq [i, j'']$，子数组越大公因子约束越多，故 $G_j \mid G_{j''}$，于是 $k \mid G_{j''}$，矛盾。故从 $i$ 出发不会在到达 $j$ 之前 break，$(i,j)$ 被访问；且到达时 $g = G_j = k$，触发计数。两方向合并，返回值 $= \#\{[i,j] : G_j = k\}$。∎

> 💡 引理 3 单独解释了算法设计里「命中不 break」的正当性：它保证命中之后循环继续跑不是无用功——后续 $k$ 的倍数段内的每个右端点都会继续命中并被计入（这正是「不漏」证明中 $(i,j)$ 到达即计数的具体来源）。

## 6. 复杂度分析

- **时间复杂度**：最坏 $O(n^2 \log V)$，$V = \max(\text{nums})$。内层总步数不超过 $\binom{n+1}{2} \approx 5 \times 10^5$，每步一次欧几里得 gcd 为 $O(\log V) \approx 30$，合计约 $1.5 \times 10^7$ 量级的基本运算。最坏触发条件是「永不 break」，例如 $k = 1$（一切 $g$ 被 $1$ 整除）；但此时答案本身可达 $\binom{n+1}{2}$ 个，**输出规模就是 $\Theta(n^2)$**，任何正确算法都至少要把答案数出来，故该情形下 $O(n^2)$ 已最优。当 $k$ 的倍数在数组中稀疏时，多数起点第一步即 break，实际接近 $O(n \log V)$。
- **空间复杂度**：$O(1)$，仅 $g,\ i,\ j,\ \text{ans}$ 四个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int subarrayGCD(vector<int>& nums, int k) {
        int n = nums.size(), ans = 0;
        for (int i = 0; i < n; ++i) {
            int g = 0;
            for (int j = i; j < n; ++j) {
                g = gcd(g, nums[j]);
                if (g % k != 0) break;
                if (g == k) ++ans;
            }
        }
        return ans;
    }
};
```

> 💡 `gcd` 来自 `<numeric>`（C++17 `std::gcd`，`__gcd` 亦可），$\gcd(0, x) = x$。$g \le \max(\text{nums}) \le 10^9$，`int` 无溢出。

### Python

```python
import math
from typing import List

class Solution:
    def subarrayGCD(self, nums: List[int], k: int) -> int:
        n = len(nums)
        ans = 0
        for i in range(n):
            g = 0
            for j in range(i, n):
                g = math.gcd(g, nums[j])
                if g % k != 0:
                    break
                if g == k:
                    ans += 1
        return ans
```

> 💡 `math.gcd(0, x) = x`；$n \le 1000$，双层循环 + 早退在 Python 也轻松 AC。

## 8. 边界情况与易错点

1. **break 判据写成 `g != k`（漏解）**：$i=0$ 行 $g$ 序列 $9 \to 3$，首步 $g = 9 \ne 3$ 若 break 就漏掉 $[9,3]$。判据必须是 `g % k != 0`。
2. **计数条件写成 `g % k == 0`（多算）**：会把 $g = 9$（$3 \mid 9$ 但 $g \ne 3$）这类子数组也数进去。计数条件必须是 `g == k`。
3. **命中后 break（少算）**：$g = k$ 后吞入 $k$ 的倍数 gcd 保持 $k$（引理 3），break 会漏掉这些更长的合法子数组。只有 $k \nmid g$ 才终止。
4. **`g < k` 作判据（正确但弱）**：$g < k$ 时未来确实无望，可以 break；但 $g = 8,\ k = 3$ 这类「$g > k$ 且 $k \nmid g$」的分支它不退，白白扫到底。判据统一用 $k \nmid g$。
5. **k = 1 永不剪枝**：一切 $g$ 被 $1$ 整除，退化为全量 $O(n^2)$ 枚举。这不是 bug——此时答案可达 $\frac{n(n+1)}{2}$ 个，输出规模决定了下界。
6. **n = 1 单元素**：`nums[0] == k` 要计数；`nums[0] % k != 0` 时第一步即 break 返回 0（示例 2）。
7. **溢出辨析**：gcd 结果 $\le$ 最小元素 $\le 10^9$，`int` 安全；同族 319 场 Q2（lcm 版）的 lcm 会爆 `long long`，须「先判 $k \bmod x == 0$ 再乘」——一个要防溢出、一个天然安全，两题细节别记混。
8. **g 初值取 0**：借 $\gcd(0, x) = x$ 免特判首元素。若写 `g = nums[i]` 再从 `j = i+1` 起也正确，但两套写法不要混用（混用会重复并入首元素或漏并入）。
9. **善用「k 倍数墙」验算**：非 $k$ 倍数元素切断一切跨越它的子数组。手算对拍时先用墙分段、再在段内检查（对照示例 3 的元素 2），比直接枚举 $\Theta(n^2)$ 个子数组快得多。
