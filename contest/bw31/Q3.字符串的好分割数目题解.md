# LeetCode 字符串的好分割数目 题解

## 1. 题目概述

- **标题 / 题号**：字符串的好分割数目（#1525，medium）
- **链接**：https://leetcode.cn/problems/number-of-good-ways-to-split-a-string/
- **来源**：LeetCode 第 31 场双周赛 Q3
- **难度**：中等
- **标签**：位运算、哈希表、字符串、动态规划、前缀和

**题意**：给定字符串 $s$（仅小写字母）。把 $s$ 分割成非空字符串 $p$、$q$ 使 $p + q = s$；若 $p$ 与 $q$ 中**不同字符的数目相同**，则称该分割为「好分割」。返回好分割的数目。

**约束**：

- $s$ 只包含小写英文字母
- $1 \le |s| \le 10^5$

## 2. 示例

**示例 1**

```text
输入：s = "aacaba"
输出：2
解释：分割 ("aac", "aba") 与 ("aaca", "ba") 中两段不同字符数都是 2，是好分割。
```

**示例 2**

```text
输入：s = "abcd"
输出：1
解释：好分割为 ("ab", "cd")。
```

**示例 3**

```text
输入：s = "aaaaa"
输出：4
解释：所有 4 个分割点两侧都只有 1 种字符，全是好分割。
```

**示例 4（边界补充）**

```text
输入：s = "a"
输出：0
解释：长度为 1 无法分割成两个非空串。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $n - 1$ 个分割点，每个分割点各扫一遍左右两段统计不同字母数，总时间 $O(26 \cdot n^2)$（或 $O(n^2)$ 用集合）。$n = 10^5$ 时约 $10^{10}$ 次操作，超时。问题在于**每个分割点都从头统计**——左右两侧的信息其实可以增量滑动。

### 3.2 核心观察：左右不同字母数可增量维护

![好分割与左右集合](images/bw31_q3_split_distinct.svg)

定义 $\textit{left}(i)$ = $s[0..i]$ 的不同字母数，$\textit{right}(i)$ = $s[i+1..n-1]$ 的不同字母数。好分割条件即 $\textit{left}(i) = \textit{right}(i)$（$0 \le i < n-1$）。

两个函数都能 $O(1)$ 递推：

- 分割点右移一位（字符 $c = s[i+1]$ 进入左段）：左段计数数组 +1，**只有当 $c$ 是左段新字母**时 $\textit{left} + 1$；
- 同时 $c$ 离开右段：右段计数数组 $-1$，**只有当右段该字母计数归零**时 $\textit{right} - 1$。

用两个长度 26 的计数数组即可，无需真集合。位运算视角：维护 26 位掩码，进入用 `mask |= bit`，离开用 `mask ^= bit`（计数归零时），不同字母数即掩码中 1 的个数。

### 3.3 算法流程

![流程与演算表](images/bw31_q3_walkthrough_table.svg)

```text
1. 从右往左（或直接统计整串）建立右段计数 rcnt[26]，right = 整串不同字母数
2. lcnt[26] 全 0，left = 0，ans = 0
3. 对 i = 0 .. n-2：                 # 左段 = s[0..i]
       c = s[i]
       if lcnt[c] == 0: left += 1    # c 首次进入左段
       lcnt[c] += 1
       rcnt[c] -= 1
       if rcnt[c] == 0: right -= 1   # c 在右段绝迹
       if left == right: ans += 1
4. 返回 ans
```

### 3.4 示例演算

以 $s = \text{"aacaba"}$ 为例（见上图演算表）：分割点 $i = 1..5$ 处 $(\textit{left}, \textit{right})$ 依次为 $(1,3), (1,3), (2,2), (2,2), (3,1)$，其中 $i = 3, 4$ 两处相等，答案 $2$，与官方示例一致。

## 4. 算法细节

1. **初始化方向**：先统计**整串**作为右段（分割点 $i = 0$ 时右段恰为 $s[1..]$ 的前身），再从左往右滑动。也可以倒序先算 `sufDistinct[i]` 数组再正序扫，两遍独立、更不易写错，代价是 $O(n)$ 额外空间——本题两种写法都是 $O(26n)$ 时间。
2. **「首次进入 / 彻底离开」的判断**：`lcnt[c] == 0` 才 `left++`；`rcnt[c]` 减到 `0` 才 `right--`。这两个判断顺序不能颠倒（先加再判断会把刚归零的计数又看成 1）。
3. **分割点范围**：左段非空且右段非空 ⟹ $i \in [0, n-2]$，共 $n - 1$ 个分割点。`n = 1` 时循环体不执行，自然返回 0。
4. **只有 26 个字母**：计数数组长度 26 是复杂度的关键；若字符集是任意 Unicode，改用哈希表，均摊仍 $O(n)$。
5. **掩码写法（C++ 备选）**：`leftMask |= bit`；离开时若 `--rcnt[c] == 0` 则 `rightMask &= ~bit`；`__builtin_popcount` 取不同字母数。与计数器写法等价，位运算更快但可读性略低。

## 5. 正确性证明

**引理 1（增量正确性）**：设左段为 $s[0..i]$、右段为 $s[i+1..n-1]$。把分割点移到 $i+1$ 后，左段新增唯一字符 $c = s[i+1]$、右段移除唯一字符 $c$，且 $\textit{left}(i+1) = \textit{left}(i) + [\textit{lcnt}_{i}(c) = 0]$，$\textit{right}(i+1) = \textit{right}(i) - [\textit{rcnt}_{i+1}(c) = 0]$。

**证明**：不同字母数只由「每个字母是否出现」决定。左段从 $s[0..i]$ 变为 $s[0..i+1]$ 只增加了位置 $i+1$ 的字母 $c$：若 $c$ 已在 $s[0..i]$ 出现过（$\textit{lcnt}_i(c) > 0$），出现集合不变；否则集合新增 $c$。右段从 $s[i+1..]$ 变为 $s[i+2..]$ 只移除了位置 $i+1$ 的字母 $c$：若 $c$ 在 $s[i+2..]$ 仍出现（$\textit{rcnt}_{i+1}(c) > 0$，即移除后计数不为 0），出现集合不变；否则集合失去 $c$。∎

**定理**：算法返回的 $\textit{ans}$ 等于好分割的数目。

**证明**：对 $i$ 归纳：初始（$i = -1$，左段空）$\textit{left} = 0$、$\textit{right}$ = 整串不同字母数，与定义一致。由引理 1，每一步滑动后 $(\textit{left}, \textit{right})$ 恰为 $(\textit{left}(i), \textit{right}(i))$；算法在每个 $i \in [0, n-2]$ 处检查 $\textit{left}(i) = \textit{right}(i)$ 并累加。由好分割的定义（分割 $p = s[0..i]$、$q = s[i+1..]$ 好当且仅当两段不同字母数相等），且分割与 $i \in [0, n-2]$ 一一对应，故 $\textit{ans}$ 恰为数目。∎

## 6. 复杂度分析

- **时间**：$O(n + |\Sigma|)$，$|\Sigma| = 26$。一次倒序建计数（或正序双扫）加一次滑动，每步 $O(1)$。
- **空间**：$O(|\Sigma|) = O(26)$。两个计数数组与几个计数变量；若采用「先算 sufDistinct 数组」的两遍写法则为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numSplits(string s) {
        int n = (int)s.size();
        vector<int> rcnt(26, 0), lcnt(26, 0);
        int right = 0, left = 0, ans = 0;
        for (char c : s) if (rcnt[c - 'a']++ == 0) right++;   // 右半初始 = 整串
        for (int i = 0; i + 1 < n; ++i) {                     // 左 = s[0..i]，右 = s[i+1..]
            if (lcnt[s[i] - 'a']++ == 0) left++;
            if (--rcnt[s[i] - 'a'] == 0) right--;
            if (left == right) ans++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numSplits(self, s: str) -> int:
        rcnt, lcnt = [0] * 26, [0] * 26
        right = 0
        for c in s:                     # 右半初始 = 整串
            if rcnt[ord(c) - 97] == 0:
                right += 1
            rcnt[ord(c) - 97] += 1
        left = ans = 0
        for i in range(len(s) - 1):     # 左 = s[:i+1]，右 = s[i+1:]
            j = ord(s[i]) - 97
            if lcnt[j] == 0:
                left += 1
            lcnt[j] += 1
            rcnt[j] -= 1
            if rcnt[j] == 0:
                right -= 1
            if left == right:
                ans += 1
        return ans
```

> 💡 两份代码均通过官方全部示例（`2`、`1`、`4`、`2`）与长度 1 的边界，另与 405 组随机串（含单字母串、双字母串、全字母串）上「每个分割点各建两个集合」的暴力对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$|s| = 1$**：没有任何合法分割点，循环 `range(len(s) - 1)` 为空，返回 0；不要在 $|s|=1$ 时误返回 1。
2. **分割点个数是 $n-1$ 不是 $n$**：左右两段都必须非空，`i` 的上界是 `n - 2`。
3. **先加后判的顺序**：左段判断 `lcnt[c] == 0` 必须在 `lcnt[c] += 1` 之前；右段 `--rcnt[c] == 0` 必须用减之后的值判断。写成 `rcnt[c]-- == 0`（先判断后减）会把计数从 1 减到 0 的情况漏掉。
4. **左右不能共用一个计数数组**：同一字母可能同时在左右两段出现（如 `"aa|a"`），必须分别维护。
5. **注意 $\textit{left} \le \textit{right}$ 的单调性陷阱**：$\textit{left}(i)$ 随 $i$ 单调不减、$\textit{right}(i)$ 单调不增，但**相等的位置不一定连续区段？其实是连续区段**（两者之差单调不减），可据此二分，但 $O(n)$ 线性已最优，不必画蛇添足。
