# LeetCode 最大的偶数 题解

## 1. 题目概述

- **标题 / 题号**：最大的偶数（#3798，easy）
- **链接**：https://leetcode.cn/problems/largest-even-number/
- **来源**：LeetCode 第 483 场周赛 Q1
- **难度**：简单
- **标签**：贪心、字符串

**题意**：给定仅由 `'1'` 和 `'2'` 组成的字符串 $s$。可以删除**任意数量**的字符（保持剩余字符相对顺序），使剩余串表示一个**偶数**整数。返回能得到的**最大**结果字符串；若不存在这样的字符串，返回空字符串 `""`。

**约束**：

- $1 \le s.length \le 100$
- $s$ 仅由字符 `'1'` 和 `'2'` 组成

> 💡 **签到题秒切三连**：① 删字符保序 ⇒ 答案落在 $s$ 的**子序列**里；② 整数奇偶性只看**个位**，而字符集里唯一的偶数字符是 `'2'` ⇒ 合法答案必须以 `'2'` 结尾；③ 字符集没有 `'0'` ⇒ 任何保留结果都无前导零 ⇒ **位数多者数值大**。三条合起来一句话：**找最后一个 `'2'`，返回它的整个前缀**。

## 2. 示例

**示例 1**

```text
输入：s = "1112"
输出："1112"
解释：该字符串已经表示了最大的偶数，因此不需要删除任何字符。
```

**示例 2**

```text
输入：s = "221"
输出："22"
解释：删除 '1' 后，可以得到最大的偶数，即 22。
```

**示例 3**

```text
输入：s = "1"
输出：""
解释：无法通过删除字符得到偶数。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的枚举：$s$ 的每个非空子序列都试一遍（$2^n$ 个），留下末位是 `'2'` 的，再取数值最大——$n=100$ 时是天文数字，直接爆炸。

收敛一步：合法答案必以某个 `'2'` 结尾，而「以某位置 $p$ 的 `'2'` 结尾的最长子序列」就是前缀 $s[0..p]$。于是候选只有 $O(n)$ 个（每个 `'2'` 对应一个），两两比较是 $O(n^2)$。签到题到这里已经能过，但还差最后一层窗户纸：**这些候选里究竟谁最大？**——下面一步观察直接把比较也省掉。

### 3.2 核心观察：答案 = 最后一个 `'2'` 的前缀

![核心观察：偶数看末位、位数定大小，最后一个'2'的前缀独占长度上界](images/wc483_q1_greedy_concept.svg)

两条性质 + 一个上界论证，把答案钉死：

1. **偶数 ⟺ 末位是 `'2'`**：整数的奇偶性只由个位决定。字符集只有 `'1'`（奇）和 `'2'`（偶），所以合法答案必须以 `'2'` 结尾；一个 `'2'` 都没有 ⇒ 无解，返回 `""`；
2. **位数多者数值大**：保留的字符全是 `'1'`/`'2'`，首位永不为零，于是**位数多的正整数一定更大**——连逐位比较都不用做；
3. **上界被前缀独占**：设 $s$ 中**最后一个 `'2'` 的下标为 $i$**。任何以 `'2'` 结尾的子序列，其末字符只能是 $s$ 中某个 `'2'`，下标必 $\le i$，因此长度 $\le i+1$。而前缀 $s[0..i]$ 恰好以 `'2'` 结尾、长度恰为 $i+1$——要凑满 $i+1$ 位且末字符下标 $\le i$，只能整段保留 $s[0..i]$，**它独占长度上界**。

结论一步到位：

$$\text{ans} = \begin{cases} s[0..i] & \text{若 } s \text{ 中存在 } '2' \\ \text{""} & \text{否则} \end{cases}$$

### 3.3 算法流程

![算法流程：一趟反向查找，一刀切前缀](images/wc483_q1_algorithm_flow.svg)

**逻辑执行步骤**：

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 反向查找 | `pos = s.rfind('2')` | 一趟从右往左，撞上第一个 `'2'` 停 |
| ② 存在性判定 | `pos` 找到了吗？ | 没有任何 `'2'` ⇒ 无偶数子序列 |
| ③ 无解分支 | 返回 `""` | 全 `'1'` 串的宿命 |
| ④ 有解分支 | 返回 `s[0..pos]` | 截到最后一个 `'2'` 为止的整个前缀 |

### 3.4 示例演算

![示例演算：三个示例覆盖整串保留、删尾、无解三种形态](images/wc483_q1_example_walkthrough.svg)

| 输入 | 最后一个 `'2'` 的下标 | 保留前缀 | 输出 | 形态 |
|------|----------------------|----------|------|------|
| `"1112"` | $3$ | $s[0..3]$ | `"1112"` | 末位恰是 `'2'`，整串即答案 |
| `"221"` | $1$ | $s[0..1]$ | `"22"` | 末位是 `'1'`，其后全删 |
| `"1"` | 不存在 | — | `""` | 无 `'2'` 即无偶数解 |

以 `"221"` 走一遍贪心论证：合法候选是所有以 `'2'` 结尾的子序列——`"2"`（首位那个）、`"22"`，长度上界是 $i+1=2$，前缀 `"22"` 独占上界且末位为 `'2'`，即最大偶数 $22$ ✓。

## 4. 算法细节

1. **`rfind` 而非 `find`**：答案是**最后**一个 `'2'` 的前缀。若误用 `find` 取第一个 `'2'`，`"221"` 会返回 `"2"`——白白丢掉一位，直接 WA；
2. **一个字符都不多删**：删除任何中间字符在保序意义下**只会减少位数**，而位数优先 ⇒ 末位 `'2'` 之前的字符全保留才是最优。贪心方向与直觉「删得越少越好」完全一致；
3. **全程字符串操作，禁止转数值**：$n \le 100$，结果可达 $10^{100}$ 量级，远超 `long long`（约 $9.2 \times 10^{18}$）与 Python 大整数不该用的场景——本题的「比大小」已被位数优先论证绕开，根本不需要数值运算；
4. **判定符号差异**：C++ `rfind` 找不到返回 `string::npos`，Python `rfind` 返回 `-1`，两者语义对应但判空写法不同，别互相抄串；
5. **接口即一行**：反向查找 + 前缀截取两步，签到题的标准形态——`rfind('2')` + `substr`/切片，没有循环没有分支（除判空外）。

## 5. 正确性证明

**引理 1（合法子序列刻画）**：非空子序列 $t$ 表示偶数整数，当且仅当 $t$ 的末字符为 `'2'`。

**证明**：整数的奇偶性由个位数字的奇偶决定。$t$ 的每位字符只能是 `'1'` 或 `'2'`，其中仅 `'2'` 为偶数数字，故 $t$ 为偶数当且仅当其个位（末字符）为 `'2'`。空串不表示整数，不构成偶数解。∎

**引理 2（位数优先）**：若正整数字符串 $a$、$b$ 均由 `'1'`/`'2'` 组成且 $|a| > |b|$，则 $a$ 表示的整数大于 $b$ 表示的整数。

**证明**：对正整数而言，位数较多者数值严格更大：设 $|a|=p>|b|=q$，则 $a \ge 10^{p-1} > 10^p - 1 \ge b$（$b$ 为 $q$ 位，$q \le p-1$，其值至多 $10^q - 1 \le 10^{p-1} - 1$）。∎

**定理**：设 $i$ 为 $s$ 中最后一个 `'2'` 的下标。若存在 `'2'`，则 $s[0..i]$ 是所有能表示偶数的子序列中数值最大的；否则不存在偶数子序列。

**证明**：**合法性**——$s[0..i]$ 非空且末字符为 $s[i]='2'$，由引理 1 表示偶数。**最优性**——任取表示偶数的子序列 $t$，由引理 1 其末字符为 `'2'`，设其对应原串下标 $j$，则 $j \le i$（$i$ 是最后一个 `'2'` 的下标），故 $|t| \le j+1 \le i+1 = |s[0..i]|$。若 $|t| < |s[0..i]|$，由引理 2 知 $t$ 数值更小；若 $|t| = i+1$，则 $t$ 需从下标 $\le i$ 的范围内取满 $i+1$ 个字符，唯一可能是整段保留 $s[0..i]$，即 $t = s[0..i]$。故 $s[0..i]$ 数值最大。**无解情形**——$s$ 无 `'2'` 时任何非空子序列的末字符均为 `'1'`，由引理 1 不表示偶数，返回 `""`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`rfind` 一趟反向扫描，$n \le 100$；前缀截取至多复制 $n$ 个字符。
- **空间复杂度**：$O(1)$ 额外空间。仅下标与若干标量；返回串是输出本身，不计入开销。
- **对比暴力**：子序列枚举 $O(2^n)$、候选比较 $O(n^2)$，贪心把「挑哪个子序列」压缩成**一个下标**，签到题的理想复杂度。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string largestEven(string s) {
        size_t pos = s.rfind('2');                       // 反向找最后一个 '2'
        return pos == string::npos ? "" : s.substr(0, pos + 1);
    }
};
```

> 💡 **写法要点**：`rfind('2')` 一趟反向扫描，找不到返回 `string::npos`；`substr(0, pos + 1)` 取含末位 `'2'` 的前缀，长度恰为 $i+1$。

### Python

```python
class Solution:
    def largestEven(self, s: str) -> str:
        pos = s.rfind('2')                    # 反向找最后一个 '2'
        return "" if pos == -1 else s[:pos + 1]
```

> 💡 **写法要点**：Python 的 `rfind` 找不到返回 `-1`（对应 C++ 的 `npos`）；`s[:pos + 1]` 切片含头含尾，一步取出前缀。

## 8. 边界情况与易错点

1. **`find` 与 `rfind` 一字之差**：取**第一个** `'2'` 的前缀在 `"221"` 上返回 `"2"`，比 `"22"` 少一位——位数优先，必错。赛时手滑高发点；
2. **全 `'1'` 串**：如 `"1"`、`"111"`，无任何 `'2'` ⇒ 无偶数解，返回 `""`。判定时注意 C++ 用 `npos`、Python 用 `-1`，两者不可混用；
3. **数值溢出**：结果最长 100 位，转 `long long` 必炸。全程按字符串操作，「比大小」已被位数优先论证替代，不发生任何数值运算；
4. **「多删一点会不会更大」的错觉**：保序删除不可能改变字符相对顺序，任何删除都只减位数不减值（引理 2），因此末位 `'2'` 之前一个字符都不删才是最优——不需要任何「删中间小字符」的局部调整；
5. **末位恰是 `'2'`**：如 `"1112"`，前缀即整串，原样返回，勿多余地删除或特判；
6. **空串输出**：本题字符集无 `'0'`，答案不会是 `"0"` 之类的退化形态；无解时返回**空串**而非 `"0"`，别自作主张。
