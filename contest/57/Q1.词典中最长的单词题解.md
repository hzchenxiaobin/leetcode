# LeetCode 词典中最长的单词 题解

## 1. 题目概述

- **标题 / 题号**：词典中最长的单词（#720，medium）
- **链接**：https://leetcode.cn/problems/longest-word-in-dictionary/
- **来源**：LeetCode 第 57 场周赛 Q1
- **难度**：中等
- **标签**：字典树，数组，哈希表，字符串，排序

**题意**：给定字符串数组 `words` 作为一本英语词典。一个单词称为**可构造**的，当且仅当它能从空串出发、每次只在**末尾追加一个字母**、并且每一步得到的中间串都是词典中的单词，最终长成它自己。求所有可构造单词中**最长**的那个；若长度相同则取**字典序最小**者；若一个都没有，返回空串。

**约束**：

- $1 \le \lvert \text{words} \rvert \le 1000$
- $1 \le \lvert \text{words}[i] \rvert \le 30$
- 所有单词仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：words = ["w","wo","wor","worl","world"]
输出："world"
解释：world 可由 w → wo → wor → worl → world 逐步在末尾追加一个字母得到。
```

**示例 2**

```text
输入：words = ["a","banana","app","appl","ap","apply","apple"]
输出："apple"
解释：apple 与 apply 都能由词典中的单词逐步构造，长度同为 5；
      apple 的字典序更小，因此返回 "apple"。
```

**补充示例（同长取字典序）**

```text
输入：words = ["a","ab","ac"]
输出："ab"
解释：ab 与 ac 都可构造且长度同为 2，取字典序更小的 "ab"。
```

## 3. 解题思路

### 3.1 暴力思路

对每个单词独立判定：从 $w$ 开始不断砍掉最后一个字符，逐级查前缀是否在哈希表里，全部命中才算可构造。单词长度最多 30，单次判定 $O(L^2)$（每级截取子串 $O(L)$），总计 $O(nL^2)$；在 $n \le 1000$、$L \le 30$ 下约 $9\times 10^5$ 次操作，其实也能过。

但这个写法有三处不舒服：

1. **同一条前缀链被反复判定**：`apple`、`apples`、`applepie` 共享 `appl`，却各自把前缀重新走一遍；
2. **tie-break 得额外处理**：要自己维护「最长且字典序最小」，一不留神就写成「最长且最先出现」；
3. **截取开销随 $L$ 放大**：每级都要切一次子串，若 $L$ 到 $10^3$ 级别，$O(nL^2)$ 立刻不安全。

### 3.2 核心观察：按长度升序递推「可构造集合」

![链式条件：可构造等价于每个前缀都在词典里](images/wc57_q1_prefix_chain.svg)

从构造规则可以直接读出**链式刻画**：

$$w \text{ 可构造} \iff w \text{ 及其所有真前缀都在词典中}$$

于是判定 $w$ 不必回溯整条链，只要看它的**直接前缀**：

$$w \text{ 可构造} \iff w \in \text{words} \ \wedge\ w[:-1] \text{ 可构造}$$

这是一个按长度分层的递推：只要保证处理 $w$ 时所有比它短的单词都已判定完毕，$w[:-1]$ 的可构造性就一定已经落在集合 `buildable` 里，一次哈希查询即可。为此把词典按 $(\text{长度},\ \text{字典序})$ 升序排序，并把空串 $\varepsilon$ 预先放进集合作为链首——否则所有单字母单词都会判失败。

排序还顺手解决了 tie-break：同长度时字典序小的先被访问，只要用「严格更长才更新」，答案自然就是「最长且字典序最小」。

### 3.3 算法流程

![排序 + 递推可构造集合的流程](images/wc57_q1_algorithm_flow.svg)

1. 把 `words` 按 $(\lvert w \rvert,\ w)$ 升序排序（可先去重）；
2. 初始化集合 `buildable = {""}` 与答案 `best = ""`；
3. 依次取出 $w$：若 $w[:-1] \in$ `buildable`，把 $w$ 加入集合；若此时 $\lvert w \rvert > \lvert best \rvert$，令 `best = w`；
4. 全部处理完，返回 `best`（可能仍是空串）。

### 3.4 示例演算

![示例演算：排序后逐个判定](images/wc57_q1_walkthrough.svg)

排序后依次为 `a`、`ap`、`app`、`appl`、`apple`、`apply`、`banana`：

| 步 | $w$ | $w[:-1]$ | 在集合中 | 动作 |
|----|-----|----------|----------|------|
| 1 | `a` | `""` | ✓ | 加入，`best = a` |
| 2 | `ap` | `a` | ✓ | 加入，`best = ap` |
| 3 | `app` | `ap` | ✓ | 加入，`best = app` |
| 4 | `appl` | `app` | ✓ | 加入，`best = appl` |
| 5 | `apple` | `appl` | ✓ | 加入，`best = apple` |
| 6 | `apply` | `appl` | ✓ | 加入，同长不更新 |
| 7 | `banana` | `banan` | ✗ | 跳过 |

第 6 步是 tie-break 的关键：`apply` 与 `apple` 同为长度 5，但 `apple` 字典序更小、先被访问，且「严格更长」才更新，故答案保持 `apple`。

## 4. 算法细节

1. **排序键**：C++ 比较器写成 `a.size() != b.size() ? a.size() < b.size() : a < b`，必须是严格弱序；Python 用 `key=lambda w: (len(w), w)`。
2. **空串必须预置**：`buildable` 初始为 `{""}`，它是长度 1 单词的前缀；漏掉这一步会让所有单字母单词判失败，答案恒为空。
3. **取前缀不越界**：Python 的 `w[:-1]` 对长度 1 的串合法地给出 `""`；C++ 用 `w.substr(0, w.size() - 1)`，`w.size() >= 1` 由约束保证。
4. **更新条件必须是严格大于**：写成 `>=` 会让同长度中字典序更大的后者覆盖前者；用 `>` 才能保留先到（字典序更小）的那个。
5. **去重是可选优化**：`sorted(set(words))` 能减少重复查询；不去重也完全正确，重复项第二次进来时 `w[:-1]` 已在集合、长度也不更大。
6. **字典序就是 ASCII 逐字符比较**：小写字母下 C++ 的 `operator<` 与题目定义一致；不要把「先比长度」混进两个候选的字典序比较里，长度已经单独处理。
7. **另一种等价实现**：把所有单词插入 Trie 并标记词尾，从根开始逐层 BFS，只沿「词尾节点」向下走，最深一层里的最小字符串即答案；复杂度 $O(\sum \lvert w \rvert)$，与排序法同阶但常数更大。本题数据规模下排序 + 哈希足够，代码也更短。

## 5. 正确性证明

**引理 1（链式刻画）**：单词 $w$ 可构造，当且仅当 $w$ 的每个前缀（含 $\varepsilon$ 与 $w$ 自身）都在词典中。

**证明**：

- ($\Rightarrow$) 设构造序列为 $\varepsilon = w_0, w_1, \dots, w_k = w$，每步只在末尾追加一个字母。对 $i$ 归纳可知 $w_i$ 恰是 $w$ 长度为 $i$ 的前缀，且 $w_i \in \text{words}$；故 $w$ 的所有前缀都在词典中。
- ($\Leftarrow$) 若 $w$ 的所有前缀都在词典中，那么按长度排列 $w_0, w_1, \dots, w_k = w$ 就是合法构造序列（$w_{i+1}$ 由 $w_i$ 末尾加一个字母得到）。∎

**引理 2（不变式）**：扫描过程中，集合 `buildable` 恰好等于 $\{\varepsilon\}$ 与「已处理过的单词里所有可构造者」的并集。

**证明**：初始时集合为 $\{\varepsilon\}$，已处理集合为空，成立。设处理到 $w$ 之前不变式成立：若 $w$ 不可构造，则不加入 $w$，不变式保持；若 $w$ 可构造，加入后集合恰好多出「已处理集合中的可构造者 $w$」，不变式保持。∎

**引理 3（判定等价）**：处理单词 $w$ 时，$w[:-1] \in$ `buildable` $\iff$ $w$ 可构造。

**证明**：

- ($\Leftarrow$) 设 $w$ 可构造。由引理 1，$w[:-1]$ 在词典中且其所有前缀也在词典中，故 $w[:-1]$ 可构造；又 $\lvert w[:-1] \rvert < \lvert w \rvert$，排序保证它先于 $w$ 被处理，由引理 2 此时 $w[:-1] \in$ `buildable`。
- ($\Rightarrow$) 设 $w[:-1] \in$ `buildable`。由引理 2，$w[:-1]$ 是词典中可构造的单词，再由引理 1，它的所有前缀都在词典中；而 $w$ 本身也在词典（它正被遍历），于是 $w$ 的所有前缀都在词典中，由引理 1 知 $w$ 可构造。∎

**引理 4（tie-break）**：设所有可构造单词的最大长度为 $L^{*}$，则算法结束时 `best` 等于这些长度 $L^{*}$ 的可构造单词中字典序最小者。

**证明**：排序键为 $(\lvert w \rvert,\ w)$，故所有长度为 $L^{*}$ 的可构造单词按字典序升序被依次处理，记第一个为 $w^{*}$。在 $w^{*}$ 之前不存在长度 $L^{*}$ 的单词，故此时 `best` 长度必小于 $L^{*}$，于是 $\lvert w^{*} \rvert > \lvert best \rvert$，$w^{*}$ 一定被写入 `best`。此后同长度的单词都满足 $\lvert w \rvert = \lvert best \rvert$，不触发「严格更长」的更新，`best` 不再改变。所以 `best` $= w^{*}$，恰为字典序最小者。∎

**定理**：算法返回的是长度最长、且同长中字典序最小的可构造单词；若不存在可构造单词则返回空串。

**证明**：由引理 2 与引理 3，扫描结束时「被加入 `buildable` 的单词」恰是「词典中可构造单词」的全集。若该集合除 $\varepsilon$ 外为空，`best` 从未被赋值，返回 `""`，符合题意；否则最大长度 $L^{*}$ 存在，由引理 4，`best` 是长度 $L^{*}$ 的可构造单词中字典序最小者，同时满足「最长」与「同长字典序最小」两项要求。∎

## 6. 复杂度分析

- **时间**：排序 $O(n \log n \cdot L)$，每次字符串比较最坏 $O(L)$；扫描 $O(nL)$，每个单词一次取前缀 $O(L)$、一次哈希查询与插入 $O(L)$；总计 $O(n \log n \cdot L)$。取 $n = 1000$、$L = 30$，实际运算量约 $3 \times 10^5$ 级别。
- **空间**：$O(nL)$，`buildable` 最坏存下全部单词，另有哈希表桶的常数倍开销；Python 的 `sorted` 需要 $O(n)$ 的指针数组，C++ 的 `sort` 为 $O(\log n)$ 栈空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_set>
#include <algorithm>
using namespace std;

class Solution {
public:
    string longestWord(vector<string>& words) {
        // 按 (长度, 字典序) 升序：保证 w[:-1] 一定先被判定
        sort(words.begin(), words.end(), [](const string& a, const string& b) {
            if (a.size() != b.size()) return a.size() < b.size();
            return a < b;
        });

        unordered_set<string> buildable;
        buildable.insert("");              // 空串是构造链的起点
        string best;

        for (const string& w : words) {
            if (buildable.count(w.substr(0, w.size() - 1))) {
                buildable.insert(w);
                if (w.size() > best.size()) best = w;   // 严格更长才更新
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def longestWord(self, words: list[str]) -> str:
        # 去重后按 (长度, 字典序) 升序，保证 w[:-1] 先于 w 被处理
        words = sorted(set(words), key=lambda w: (len(w), w))

        buildable = {""}          # 空串是构造链的起点
        best = ""
        for w in words:
            if w[:-1] in buildable:        # 直接前缀可构造 -> w 也可构造
                buildable.add(w)
                if len(w) > len(best):     # 严格更长才更新，同长保留字典序更小者
                    best = w
        return best
```

## 8. 边界情况与易错点

1. **没有任何可构造单词**：如 `words = ["banana"]`，所有单字母前缀都不在词典，返回 `""`。`best` 初值要取空串，且不要用长度 $-1$ 之类的哨兵参与比较。
2. **单字母单词**：它的前缀是空串，必须预先把 `""` 放进集合；否则 `["a"]` 会错误地返回空串（正确答案是 `"a"`）。
3. **同为最长时选字典序**：`["a","ab","ac"]` 应返回 `"ab"`。排序键中的字典序与更新时的严格 `>` 缺一不可；只按长度排序会让 `ac` 后来居上。
4. **重复单词**：`["a","a","a"]` 返回 `"a"`。重复不影响正确性，但 `set` 去重后哈希表压力更小；C++ 不去重时重复项连续处理，判定结果不变。
5. **前缀在词典中但不可构造**：`["ab","abc"]` 返回 `""` —— `ab` 的前缀 `a` 缺失；`abc` 的前缀 `ab` 虽在词典却不可构造。判定看的是「前缀**可构造**」，不是「前缀**存在**」。
6. **C++ 的 `w.substr(0, w.size() - 1)`**：`w` 长度至少为 1，不会下溢；若把接口扩展成允许空串输入，必须特判，否则 `size() - 1` 会回绕成极大值。Python 的 `w[:-1]` 天然安全。
7. **不要用「长度优先」的字典序做最终比较**：题目要求「最长优先，其次字典序」，若比较函数只比字典序，会把短词选出来。
