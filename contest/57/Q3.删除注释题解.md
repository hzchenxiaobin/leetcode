# LeetCode 删除注释 题解

## 1. 题目概述

- **标题 / 题号**：删除注释（#722，medium）
- **链接**：https://leetcode.cn/problems/remove-comments/
- **来源**：LeetCode 第 57 场周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、模拟、状态机

**题意**：给定一个 C++ 程序按行拆开的数组 `source`，删掉其中所有注释，再按原格式返回剩下的代码行（列表里只保留非空行）。

两种注释：

- **行注释** `//`：从 `//` 起到本行末尾全部丢弃，不跨行。
- **块注释** `/* ... */`：从 `/*` 起到下一个 `*/` 之间全部丢弃，可以跨行，并且**连中间的换行符一起吞掉**。

必须同时遵守的四条细则：

1. **第一个有效注释优先**：块注释内部的 `//`、`/*` 都不生效；行注释内部的 `/*` 也不生效。
2. **非重叠匹配**：`/*/` 不构成一次「开 + 闭」，因为闭合用的 `*` 与开头用的 `*` 是同一个字符。
3. 删除后变成**空串**的行不输出；行内保留的前导空格、尾随空格原样不动（`"  "` 是合法输出行）。
4. 每个块注释保证闭合；题面没有字符串字面量、转义序列、引号等干扰。

**约束**：

- $1 \le \lvert \text{source} \rvert \le 100$，即最多 100 行
- $0 \le \lvert \text{source}[i] \rvert \le 80$，单行最长 80 个字符
- `source[i]` 只由可打印 ASCII 字符组成
- 每个块注释最终都会被闭合
- 不含单引号、双引号与其他控制字符

> 💡 总字符数上限约 $100 \times 80 = 8000$，任何线性做法都绰绰有余。本题的难点不在复杂度，而在**状态不能错、边界不能漏**。

## 2. 示例

**示例 1（官方）**

```text
输入：source = ["/*Test program */", "int main()", "{ ", "  // variable declaration ",
               "int a, b, c;", "/* This is a test", "   multiline  ",
               "   comment for ", "   testing */", "a = b + c;", "}"]
输出：["int main()", "{ ", "  ", "int a, b, c;", "a = b + c;", "}"]
解释：第 1 行、第 6~9 行是块注释，第 4 行是行注释；第 4 行删完剩两个空格，
      是非空串所以要输出 "  "，而第 1 行与第 6~8 行删完是空串，不输出。
```

**示例 2（官方）**

```text
输入：source = ["a/*comment", "line", "more_comment*/b"]
输出：["ab"]
解释：拼起来是 "a/*comment\nline\nmore_comment*/b"。块注释吞掉了两个隐式换行，
      'a' 与 'b' 被接到同一行，输出只有一个元素 "ab"。
```

**示例 3（补充，非官方，用于确认「非重叠」与「空行丢弃」两条细则）**

```text
输入：source = ["/*/ */x", "", "  "]
输出：["x", "  "]
解释：下标 0 的 "/*" 进块后紧邻的 '/' 不能当作 "*/" 的一部分，只有后面的 " */" 才真正闭合，整段被删只剩 'x'；空串行不输出，但纯空格的 "  " 不是空串。
```

## 3. 解题思路

### 3.1 暴力思路

把 `source` 用 `\n` 拼成一个大字符串，再用正则「删块注释 + 删行注释」。两个顺序都错：先删块注释时，`a // x /* y` 里的 `/*` 会被误判成注释起点，把后面的真实代码一起删掉；先删行注释时，块注释里的 `//`（如 `/* url: http://x */`）又会被误删。根因是正则替换是「模式优先」而非「位置优先」，表达不了「第一个有效注释优先」。

即便不看正确性，外层 `find` 再 `erase` 的朴素写法也会退化到 $O(N^2)$。正确方向是**显式模拟一个从当前位置往前走、遇标记就跳转的扫描器**。

### 3.2 核心观察：一个布尔标志就够

![两状态自动机：in_block 与 buffer](images/wc57_q3_state_machine.svg)

把「现在读到的字符算不算代码」抽象成一个只有两个状态的自动机：

| 状态 | `in_block` | 认识的标记 | 其它字符 |
|------|-----------|-----------|----------|
| 代码态 | `false` | `/*` 进块；`//` 丢到行末 | 追加进 `buffer` |
| 块注释态 | `true` | `*/` 出块 | 直接丢弃 |

两个关键点：

1. **`in_block` 必须贯穿所有行**。块注释能跨行，所以「这一行要不要当注释看」不能只看本行，必须由上一行遗留的状态决定。
2. **`buffer` 也必须跨行保留**。块注释吞掉换行，意味着「进块前攒下的代码」和「出块后攒下的代码」属于**同一输出行**，所以行末只有在 `in_block == false` 时才交付并清空。至于「第一个有效注释优先」，它已被状态天然编码：代码态才检查 `/*`、`//`，块注释态只检查 `*/`。

### 3.3 算法流程

![逐行逐字符扫描流程](images/wc57_q3_scan_flow.svg)

```text
res ← []；in_block ← false；buf ← ""
for line in source:
    for (i ← 0; i < len(line); ):
        if in_block and line[i..i+2] == "*/": in_block ← false；i += 2
        elif in_block:                        i += 1
        elif line[i..i+2] == "/*":            in_block ← true；i += 2
        elif line[i..i+2] == "//":            break        # 丢到行末
        else:                                 buf += line[i]；i += 1
    if (not in_block) and buf ≠ "": res.append(buf)；buf ← ""
return res
```

扫描指针的走向只有三种，且每次至少前进 1：`i += 1`（普通字符或被跳过的字符）、`i += 2`（吃掉一个双字符标记）、`break`（行注释直接结束本行）。因此每行恰好被扫一遍。

### 3.4 示例演算

![示例 2 的跨行合并走查](images/wc57_q3_walkthrough.svg)

以示例 2 逐行推演：

| 行号 | 当前行 | 扫描过程 | `in_block` | `buffer` | 行末是否输出 |
|------|--------|----------|-----------|----------|--------------|
| 0 | `a/*comment` | 收下 `a`；`/*` 进块，`i += 2`；`comment` 全被跳过 | true | `"a"` | 否（块内，buffer 保留） |
| 1 | `line` | 块内逐字符跳过，找不到 `*/` | true | `"a"` | 否（buffer 原样保留） |
| 2 | `more_comment*/b` | 块内跳过；遇 `*/` 出块 `i += 2`；再收下 `b` | false | `"ab"` | 是 → `"ab"` |

再看示例 1 的行级结果：

| 输入行 | 判定 | 输出行 |
|--------|------|--------|
| `/*Test program */` | 整行是块注释 | 空串，丢弃 |
| `int main()`、`{ ` | 纯代码（`{ ` 的尾随空格保留） | `"int main()"`、`"{ "` |
| `  // variable declaration ` | 行注释，只留下前导两空格 | `"  "` |
| `/* This is a test` … `   testing */` | 连续四行的块注释（第 6 行开、第 9 行闭） | 空串，丢弃（不进 buffer） |

## 4. 算法细节

1. **识别双字符标记时必须 `i += 2`**。这是「非重叠」的直接落地：`/*/` 中紧跟的 `/` 已经排在已消费的两个字符之后，不能被拿去和前面的 `*` 配成闭合符。写成 `i += 1` 会把 `/*/` 误判成「开 + 闭」。
2. **`/*` 与 `//` 必须在同一层 `if / elif` 里互斥判断**。两者都以 `/` 开头，靠第二个字符区分；若写成两个独立 `if` 且都执行 `i += 2`，指针会一次跳过 4 个字符。同时必须先检查 `i + 1 < n`：行尾单个 `/` 是普通字符，越界读 `line[i+1]` 在 C++ 里是未定义行为。
3. **`buffer` 用可变容器累积**。Python 里用 `list[str]` + `append` / `"".join`，避免 `buf += c` 在最坏 $O(N)$ 次拼接上退化成 $O(N^2)$；C++ 的 `string::push_back` 均摊 $O(1)$，直接追加即可。
4. **行末结算是唯一的输出时机**：`!in_block && !buf.empty()` 才 push 并清空，交付顺序即源码顺序。若在块注释态强行清空，示例 2 的 `"ab"` 会被拆成 `["a", "b"]`。
5. **判空只看长度**。题面要求「删除注释后成为空字符串」才不输出，因此纯空白行（如 `"   "`）必须保留；实现里绝不能顺手 `strip()` 或 `trim()`。

## 5. 正确性证明

**引理 1（前缀不变式）**：内层循环每轮开始时，`buffer` 恰为「已扫描前缀中的代码字符」按序拼接；`in_block` 为真当且仅当指针位于某个已开启未闭合的块注释内部。

**证明**：对扫描步数归纳。初始为空/假，成立。设第 $t$ 步前成立：若 `in_block = true`，读到 `*/` 则闭合（指针 +2、状态置假、`buffer` 不变），否则该字符在块内被跳过、`buffer` 不变；若 `in_block = false`，读到 `/*` 则开启块注释（指针 +2、`buffer` 不变），读到 `//` 则本行剩余属于行注释、直接结束本行，其余字符属于代码、追加后指针 +1。四种转移都保持上述两条性质，归纳成立。∎

**引理 2（注释区间与「非重叠」）**：设某块注释的开启标记 `/*` 位于全局位置 $p$，则扫描在 $p$ 处进块，并在满足 $q \ge p+2$ 的最小 $q$（使 `s[q..q+2] = "*/"`）处退出，$[p, q+2)$ 内字符全部丢弃。

**证明**：由引理 1，读到 `/*` 后指针置为 $p+2$、状态为块注释态，此后每轮只判断「当前是否为 `*/`」，故退出位置就是满足 $q \ge p+2$ 的最小 $q$；块注释态下字符不写入 `buffer`，区间内全部丢弃。$q \ge p+2$ 即非重叠——闭合符不能与开启符共用字符，故 `/*/` 不闭合。∎

**引理 3（行末结算）**：行末 `in_block = false` 且 `buffer = w \ne ""` 时，`w` 恰为该输出行的完整内容；`in_block = true` 时该输出行尚未结束，`buffer` 必须留到后续行继续累积。

**证明**：由引理 1，`buffer` 是本输出行至今的代码字符。`in_block = false` 说明行末无未闭合块注释，而块注释是唯一吞换行的结构，故输出行到此结束、`w` 即完整内容（为空则按题意丢弃）。`in_block = true` 说明换行被块注释吞掉、后续代码同属一行，故不能交付也不能清空。∎

**定理**：算法输出等于题意要求的「删除全部注释后按行拆分、丢弃空串」的结果。

**证明**：由引理 1、2，注释字符（含被吞的换行）全部丢弃，代码字符按原序不重不漏进入 `buffer`；由引理 3，`buffer` 在每条输出行结束时被交付一次且内容完整；交付条件 `buffer \ne ""` 与「空行不输出」一致。故输出与题意逐项相等。∎

## 6. 复杂度分析

- **时间**：$O(N)$，$N = \sum_i \lvert \text{source}[i] \rvert$ 为总字符数。内层指针每轮至少 +1、至多 +2，单行不超过 $\lvert \text{source}[i] \rvert + 1$ 步；行末结算与字符追加均摊 $O(1)$，总时间线性。
- **空间**：$O(N)$。`res` 存放全部输出（总量 $\le N$），`buffer` 最多累积一整条输出行（$\le N$）；`in_block`、`i` 为 $O(1)$。交付后 `buffer` 立即清空，故除输出以外没有额外的大块占用。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> removeComments(vector<string>& source) {
        vector<string> res;
        bool in_block = false;   // 是否处于块注释中（跨行保留）
        string buf;              // 当前这条输出行的内容（跨行保留）
        for (const string& line : source) {
            int i = 0, n = (int)line.size();
            while (i < n) {
                if (in_block) {
                    if (line[i] == '*' && i + 1 < n && line[i + 1] == '/') {
                        in_block = false;      // 出块
                        i += 2;                // 非重叠：两个字符一起消费
                    } else {
                        i += 1;                // 块内字符一律丢弃
                    }
                } else {
                    if (line[i] == '/' && i + 1 < n && line[i + 1] == '*') {
                        in_block = true;       // 进块
                        i += 2;
                    } else if (line[i] == '/' && i + 1 < n && line[i + 1] == '/') {
                        break;                 // 行注释：本行剩余全丢
                    } else {
                        buf.push_back(line[i]);
                        i += 1;
                    }
                }
            }
            if (!in_block && !buf.empty()) {   // 行末结算
                res.push_back(buf);
                buf.clear();
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def removeComments(self, source: list[str]) -> list[str]:
        res: list[str] = []
        in_block = False          # 是否处于块注释中（跨行保留）
        buf: list[str] = []       # 当前这条输出行的内容（跨行保留）
        for line in source:
            i, n = 0, len(line)
            while i < n:
                if in_block:
                    if line[i] == '*' and i + 1 < n and line[i + 1] == '/':
                        in_block = False        # 出块
                        i += 2                  # 非重叠：两个字符一起消费
                    else:
                        i += 1                  # 块内字符一律丢弃
                else:
                    if line[i] == '/' and i + 1 < n and line[i + 1] == '*':
                        in_block = True         # 进块
                        i += 2
                    elif line[i] == '/' and i + 1 < n and line[i + 1] == '/':
                        break                   # 行注释：本行剩余全丢
                    else:
                        buf.append(line[i])
                        i += 1
            if not in_block and buf:            # 行末结算
                res.append(''.join(buf))
                buf = []
        return res
```

## 8. 边界情况与易错点

1. **`/*/` 不闭合**。这是题面里最容易读漏的一句。只要坚持 `i += 2`，`/*/` 的第三个字符 `/` 就落在「块注释内的普通字符」上，不会被拿来闭合。
2. **纯空格行要输出**。`"  // variable declaration "` 的答案是 `"  "`，示例 1 的输出里确实有这么一项。用 `if line.strip()` 或 `res.append("".join(buf).strip())` 判空都会错。
3. **块注释结束时行内还有代码**。`/*a*/b` 与示例 2 的 `more_comment*/b` 都要求出块后**继续扫本行**，而不是 `break` 或跳到下一行。另外块注释可跨任意多行，一条输出行也可能由三行以上拼成，`buffer` 在此期间必须一直保留。
4. **行注释末尾就是行尾**。`"a//"` 与 `"//"` 分别输出 `"a"` 与不输出；`break` 之后仍然要走行末结算，不能在 `break` 里提前 `continue` 掉结算逻辑。
5. **连续多个块注释**。`/*a*/b/*c*/d` 应得到 `"bd"`：进块 → 出块 → 收 `b` → 再进块 → 再出块 → 收 `d`，`buffer` 全程不丢。

**延伸思考**：
