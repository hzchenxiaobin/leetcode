# LeetCode 账户合并 题解

## 1. 题目概述

- **标题 / 题号**：账户合并（#721，medium）
- **链接**：https://leetcode.cn/problems/accounts-merge/
- **来源**：LeetCode 第 57 场周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索，广度优先搜索，并查集，数组，哈希表，字符串，排序

**题意**：`accounts[i]` 的第一个元素是姓名，其余元素是该账户的邮箱。若两个账户存在**至少一个相同邮箱**，则它们必定属于同一个人（可以只有部分邮箱重合）。一个人可以有任意多个账户，但这些账户的姓名都相同。要求把所有账户按「同一个人」合并：每行先是姓名，其余是该人的全部邮箱，**按字符 ASCII 升序**排列；各行的顺序任意。

**约束**：

- $1 \le \text{accounts.length} \le 1000$
- $2 \le \text{accounts}[i]\text{.length} \le 10$，即每个账户最多 9 个邮箱，邮箱总数 $N \le 9000$
- $1 \le \text{accounts}[i][j]\text{.length} \le 30$
- `accounts[i][0]` 只含英文字母；`accounts[i][j]`（$j>0$）是合法邮箱
- 输出约定：行的顺序任意，但行内邮箱必须严格按 ASCII 升序，因此每行的邮箱集合是唯一确定的

## 2. 示例

**示例 1**

```text
输入：accounts = [["John", "johnsmith@mail.com", "john00@mail.com"],
                 ["John", "johnnybravo@mail.com"],
                 ["John", "johnsmith@mail.com", "john_newyork@mail.com"],
                 ["Mary", "mary@mail.com"]]
输出：[["John", "john00@mail.com", "john_newyork@mail.com", "johnsmith@mail.com"],
      ["John", "johnnybravo@mail.com"],
      ["Mary", "mary@mail.com"]]
解释：账户 0 与账户 2 共享 johnsmith@mail.com，属于同一个人，合并成第一行；
      账户 1 与账户 3 的邮箱没有被其他账户使用，各自独立成行 —— 两行 John 是不同的人。
```

**示例 2**

```text
输入：accounts = [["Gabe","Gabe0@m.co","Gabe3@m.co","Gabe1@m.co"],
                 ["Kevin","Kevin3@m.co","Kevin5@m.co","Kevin0@m.co"],
                 ["Ethan","Ethan5@m.co","Ethan4@m.co","Ethan0@m.co"],
                 ["Hanzo","Hanzo3@m.co","Hanzo1@m.co","Hanzo0@m.co"],
                 ["Fern","Fern5@m.co","Fern1@m.co","Fern0@m.co"]]
输出：[["Ethan","Ethan0@m.co","Ethan4@m.co","Ethan5@m.co"],
      ["Gabe","Gabe0@m.co","Gabe1@m.co","Gabe3@m.co"],
      ["Hanzo","Hanzo0@m.co","Hanzo1@m.co","Hanzo3@m.co"],
      ["Kevin","Kevin0@m.co","Kevin3@m.co","Kevin5@m.co"],
      ["Fern","Fern0@m.co","Fern1@m.co","Fern5@m.co"]]
解释：五个账户两两没有公共邮箱，因此一行都不合并，只把每行邮箱排序。
```

## 3. 解题思路

### 3.1 暴力思路

1. **按姓名分组**：把同名账户的邮箱直接并成一行。示例 1 立刻反例——三个 John 只有前两个（账户 0、账户 2）共享邮箱，账户 1 必须单列，按姓名合并会把 `johnnybravo@mail.com` 错并进去。
2. **反复扫描合并**：枚举账户对 $(i,j)$，若有交集就合并，再重新扫描直到不再变化。单轮枚举 $O(n^2)$ 次、每次集合求交 $O(k)$，最坏要 $n$ 轮（链式合并），复杂度 $O(n^3k)$，$n=1000$ 时约 $10^{10}$，不可行。

问题的本质是**等价关系的传递闭包**：共享邮箱是「相邻」，要求的是「连通」。这正好是**连通分量**问题。

### 3.2 核心观察：邮箱是图的节点，连通分量就是一个人

![邮箱建图：连通分量就是同一个人](images/wc57_q2_email_graph.svg)

把每个**邮箱**看成图上的一个节点（不是账户）：

- 同一个账户内的邮箱**两两连边**（等价于每个邮箱都连向该账户的第一个邮箱）；
- 两个账户共享某个邮箱时，这个邮箱同时挂在两条边上，两个账户的邮箱就落进同一个连通分量。

于是「合并账户」= **求这张无向图的连通分量**，每个分量恰好对应一个人；某个分量的姓名就是该分量里任意一个账户的姓名（同分量内姓名必定相同，否则题意自相矛盾）。

为什么不能把账户当节点？账户之间可能通过**中间账户**间接相连：$A$ 与 $B$ 共享 $x$，$B$ 与 $C$ 共享 $y$，$A$ 与 $C$ 并无公共邮箱，却仍是同一个人。以账户为节点只能连出「直接共享」的边，还要再求一次传递闭包；以邮箱为节点时，连通性天然就是传递闭包。

### 3.3 算法流程：并查集 + 按根聚合

![并查集三步走：建集合、合并、按根聚合](images/wc57_q2_union_find_flow.svg)

用并查集（DSU）维护邮箱的连通性，只需三趟：

1. **建集合**：遍历所有账户的所有邮箱，`parent[e] = e`，并给每个邮箱分配编号，用哈希表 `email → id` 做映射（避免字符串比较带来的开销）。
2. **账户内合并**：对每个账户 `acc`，取锚点 `acc[1]`，对 $j \ge 2$ 依次 `union(acc[1], acc[j])`。每个账户至多 8 次 union，总 union 次数 $O(N)$。
3. **按根聚合**：再遍历一遍所有邮箱，`r = find(e)`，把 `e` 放进以 `r` 为键的哈希表，同时记录 `r` 对应的姓名；最后对每组的邮箱排序，拼上姓名即为一行。

**状态转移**（并查集核心两行）：

$$
\text{find}(x)=\begin{cases} x, & \text{parent}[x]=x \\ \text{find}(\text{parent}[x]), & \text{否则}\end{cases}
\qquad
\text{union}(a,b):\ \text{parent}\big[\text{find}(b)\big] \leftarrow \text{find}(a)
$$

路径压缩让单次操作均摊 $O(\alpha(N))$（$\alpha$ 为反阿克曼函数，实际可视为常数）。

### 3.4 示例演算

![示例 1 的合并走查](images/wc57_q2_walkthrough.svg)

对示例 1 按题意顺序处理（简写 `js / j0 / jn / jb / m`）：

| 步骤 | 操作 | 集合状态（根 : 成员） |
|------|------|------------------------|
| 账户 0 | `union(js, j0)` | $\{js:\ js, j0\}$ |
| 账户 1 | `jb` 独立成集合 | $\{js:\ js, j0\},\ \{jb:\ jb\}$ |
| 账户 2 | `union(js, jn)`，`jn` 挂到 `js` 下 | $\{js:\ js, j0, jn\},\ \{jb:\ jb\}$ |
| 账户 3 | `m` 独立成集合 | $\{js:\ js, j0, jn\},\ \{jb:\ jb\},\ \{m:\ m\}$ |

三组分别排序后输出：`John: john00@mail.com, john_newyork@mail.com, johnsmith@mail.com`、`John: johnnybravo@mail.com`、`Mary: mary@mail.com`。排序结果值得对照字符编码：`'0'`(48) < `'_'`(95) < `'s'`(115)，所以 `john00@...` 最前、`johnsmith@...` 最后——**不能按邮箱长度或字典序的「自然语感」排**，必须严格用字符编码比较（C++ `std::sort` 与 Python `sorted` 对 `std::string` / `str` 的默认比较就是逐字符编码比较）。

## 4. 算法细节

1. **邮箱编号化**：C++ 用 `unordered_map<string,int>` 把邮箱映射到 $[0, N)$ 的下标，并查集数组用 `vector<int>`，避免在 DSU 里反复比较长字符串；Python 直接用 `dict[str, str]` 存 `parent` 也足够快（$N \le 9000$）。
2. **合并的锚点选择**：每个账户只需把 `acc[1]` 与其余邮箱依次 union，不必两两 union。$k$ 个点连成星形（$k-1$ 条边）与连成完全图（$\binom{k}{2}$ 条边）连通性相同，这样每账户的合并次数从 $O(k^2)$ 降到 $O(k)$。
3. **路径压缩的写法**：Python 的递归写法有 `RecursionError` 风险，推荐两趟迭代：先沿 `parent` 找到根，再把路径上所有点直接指向根。
4. **姓名如何取**：聚合时对每个根 `r` 记录第一次遇到的账户姓名。同分量内姓名必相同（题意保证），所以取任意一个都合法；C++ 用 `nameOf.emplace(r, name)` 保持「首次写入不覆盖」。
5. **去重与行顺序**：用 `set` 收集每组邮箱，天然去重且顺带排序（C++ `std::set`、Python `sorted(set(...))`）；行顺序任意，无需对结果行排序（本地对拍时再排序即可）。

## 5. 正确性证明

**引理 1**：算法执行完毕后，同一账户内的任意两个邮箱 `find` 结果相同。

**证明**：设账户邮箱为 $e_1, e_2, \dots, e_k$。处理该账户时，对每个 $j \ge 2$ 执行了 `union(e_1, e_j)`，之后 $\text{find}(e_1) = \text{find}(e_j)$。并查集只做「把一棵树的根挂到另一棵树的根上」，两个元素的根一旦相等就永远相等（不会分裂），故该账户处理完后，$e_1, \dots, e_k$ 的根恒相同。∎

**引理 2**：若某时刻 $\text{find}(u) = \text{find}(v)$，则在「同一账户内两两连边」的图 $G$ 中 $u$ 与 $v$ 连通。

**证明**：并查集森林中每条父子边 $(x, \text{parent}[x])$ 都来自某次 `union`，而 `union` 只连接**同一账户内**的两个邮箱，故每条父子边都是 $G$ 中的一条边。$u$ 到根的路径与 $v$ 到根的路径在根处汇合，拼成一条 $G$ 中的 $u$–$v$ 通路，因此连通。∎

**引理 3**：若在 $G$ 中 $u$ 与 $v$ 连通，则算法结束时 $\text{find}(u) = \text{find}(v)$。

**证明**：取 $G$ 中一条 $u$–$v$ 通路 $w_0=u, w_1, \dots, w_t=v$。相邻的 $w_{i}, w_{i+1}$ 属于同一账户，由引理 1 它们最终同根；根相等是等价关系，沿通路逐段传递得 $\text{find}(u) = \text{find}(v)$。∎

**定理**：算法输出的每一行恰为 $G$ 的一个连通分量（姓名 + 该分量全部邮箱升序）。

**证明**：

- **不重不漏**：第三趟遍历全部账户的全部邮箱，每个邮箱被放入且仅被放入 `find(e)` 对应的一组，故每个邮箱恰好出现一次；行内邮箱已排序，满足 ASCII 升序要求。
- **组就是分量**：组键为 `find(e)`；由引理 2 同组邮箱在 $G$ 中连通，所以一组落在某个连通分量内；由引理 3 连通的邮箱必然同组，所以一个分量不会跨组。两个方向合起来，组与分量一一对应。
- **姓名合法**：分量内任取一个账户的姓名。若同一分量内出现两个不同姓名，说明这两个账户通过共享邮箱相连却姓名不同，这与题意「同一个人所有账户姓名相同」矛盾，故姓名唯一且正确。

因此输出是题目要求的合法答案。∎

## 6. 复杂度分析

- **时间**：$O\big(N\,\alpha(N) + \sum_i k_i \log k_i\big)$。其中 $N$ 为邮箱总数（$\le 9000$），$\alpha$ 为反阿克曼函数。建集合与两次遍历各 $O(N)$ 次哈希操作；union 共 $O(N)$ 次，均摊近似 $O(1)$；排序按组进行，$\sum k_i \log k_i \le N \log N$。字符串哈希的代价为 $O(30)$ 的常数，可忽略。
- **空间**：$O(N)$。`parent` 表 $N$ 项、`email → id` 哈希表 $N$ 项、分组表存 $N$ 个邮箱字符串，外加答案本身。递归栈深度通过迭代实现控制在 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <map>
#include <set>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
    unordered_map<string, string> parent;

    string find(const string& x) {
        string r = x;
        while (parent[r] != r) r = parent[r];   // 第一趟：找根
        string cur = x;
        while (parent[cur] != r) {              // 第二趟：路径压缩
            string nxt = parent[cur];
            parent[cur] = r;
            cur = nxt;
        }
        return r;
    }

public:
    vector<vector<string>> accountsMerge(vector<vector<string>>& accounts) {
        parent.clear();
        // ① 每个邮箱自成一个集合
        for (auto& acc : accounts)
            for (size_t i = 1; i < acc.size(); ++i)
                parent.emplace(acc[i], acc[i]);

        // ② 同一账户内合并：以第 1 个邮箱为锚点，星形足够
        for (auto& acc : accounts)
            for (size_t i = 2; i < acc.size(); ++i) {
                string ra = find(acc[1]), rb = find(acc[i]);
                if (ra != rb) parent[rb] = ra;
            }

        // ③ 按根聚合，同时记录姓名（同一分量姓名相同，取首次即可）
        unordered_map<string, string> nameOf;
        map<string, set<string>> groups;
        for (auto& acc : accounts)
            for (size_t i = 1; i < acc.size(); ++i) {
                string r = find(acc[i]);
                nameOf.emplace(r, acc[0]);
                groups[r].insert(acc[i]);
            }

        vector<vector<string>> res;
        for (auto& kv : groups) {
            vector<string> row{nameOf[kv.first]};
            row.insert(row.end(), kv.second.begin(), kv.second.end());
            res.push_back(row);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def accountsMerge(self, accounts):
        parent = {}

        def find(x):
            r = x
            while parent[r] != r:          # 第一趟：找根
                r = parent[r]
            while parent[x] != r:          # 第二趟：路径压缩（迭代版，避免深递归）
                parent[x], x = r, parent[x]
            return r

        # ① 每个邮箱自成一个集合
        for acc in accounts:
            for e in acc[1:]:
                parent.setdefault(e, e)

        # ② 同一账户内合并：以第 1 个邮箱为锚点
        for acc in accounts:
            for e in acc[1:]:
                ra, rb = find(acc[1]), find(e)
                if ra != rb:
                    parent[rb] = ra

        # ③ 按根聚合 + 记录姓名
        name_of, groups = {}, {}
        for acc in accounts:
            for e in acc[1:]:
                r = find(e)
                name_of.setdefault(r, acc[0])
                groups.setdefault(r, set()).add(e)

        # ④ 每组排序后拼上姓名（行顺序任意）
        return [[name_of[r]] + sorted(v) for r, v in groups.items()]
```

## 8. 边界情况与易错点

1. **同名不同人**：绝不能按姓名分组。示例 1 的两个 `John` 分量、以及「只有部分邮箱重合」的情形都会让按姓名合并出错。
2. **链式传递**：账户 0 与 1 共享 `x`、账户 1 与 2 共享 `y`，账户 0 与 2 无公共邮箱也必须合并。并查集天然处理；若只做「一轮两两比较」就会漏掉。注意合并顺序无影响，因为 `find` 会一路上溯到根。
3. **单邮箱账户与行格式**：`accounts[i].length == 2` 时该账户没有 union 动作，但仍要建集合、单独成行，否则会漏掉该邮箱；输出行第一个元素是姓名，邮箱列表**不含**姓名。
4. **排序必须是 ASCII 序**：`'0'`(48) < `'_'`(95) < `'s'`(115)，故 `john00` 在 `john_newyork` 之前、`johnsmith` 之后；不要用「忽略大小写」「按长度」等自定义比较。
5. **递归栈深与 `setdefault`**：极端链式输入下未压缩的递归 `find` 可能压到 9000 层，故用迭代 + 路径压缩；`name_of.setdefault(r, acc[0])` 保证姓名取首次出现的那个，不会被后续写入覆盖。
