# LeetCode 粉碎糖果 题解

## 1. 题目概述

- **标题 / 题号**：粉碎糖果（#723，medium）
- **链接**：https://leetcode.cn/problems/candy-crush/
- **来源**：LeetCode 第 57 场周赛 Q4
- **难度**：中等
- **标签**：数组，双指针，矩阵，模拟

**题意**：给定 $m \times n$ 的盘面 `board`，正整数表示糖果种类，$0$ 表示空格。反复执行下面三步直到盘面**稳定**：

1. **同时**消除所有满足「同一行或同一列上连续至少 $3$ 个且种类相同」的糖果，这些格子变为 $0$；
2. 所有消除**完成之后**，每列糖果在重力作用下整体下坠，压在下方已有糖果或底边上，顶部空出的格子保持 $0$（不会从盘外掉入新糖果）；
3. 若下坠后出现新的可消除段，回到第 1 步；否则返回当前盘面。

关键语义有两个：**「同时」**指同一轮内所有段基于**同一份**盘面判定，横向与纵向段可以在某一格十字交叉、交叉格只算一次；**「先消后坠」**指下坠必须发生在整轮消除之后，而不是消一段坠一次。

**约束**：

- $3 \le m \le 50$，$3 \le n \le 50$
- 初始 $\text{board}[i][j] \in [1, 2000]$，$0$ 只在消除过程中产生
- 本题为会员题，题面以英文镜像为准，规则即上述三步循环，不含任何额外输入输出要求

## 3. 解题思路

### 3.1 暴力思路

最直白的写法：扫描到一个长度 $\ge 3$ 的段就**立即**清零，清零后立刻压实，然后重新扫描，直到一轮无事发生。

这个写法有三处硬伤：

1. **同时性被破坏**：先用 `board[i][j] = 0` 抹掉一段，后续按「相邻值相等」的扫描就会把本应一起消除的相邻段判漏。十字交叉处最典型——横向段刚被清掉，纵向段从交点开始就断了。
2. **消除与下坠的次序被颠倒**：规则要求整轮消除完毕才统一下坠；边消边坠会把后面的段放到位移后的坐标上重新判定，结论与规则不一致。
3. **轮数说不清**：每消一条段就全盘重扫，一旦下坠引入新段，循环次数难以界定。

真正需要的不是更快的「边扫边删」，而是**把判定与执行拆开**。

### 3.2 核心观察：标记与删除分离

一轮只做两件互不干扰的事：**标记阶段**只往布尔矩阵 `dead` 里写 `true`，完全不碰 `board`；**执行阶段**才按 `dead` 统一清零，然后逐列压实。由此得到三个直接好处：

- **同时性天然成立**：行扫描、列扫描读的都是同一份原始盘面，不会因为先删了某段而漏判后面的段；
- **交叉格无需去重**：横向段与纵向段的交点被标记两次，`dead[i][j] = true` 写两遍还是 `true`；
- **长段整段清掉**：长度 $> 3$ 的段在命中后继续向右/向下吸收同色格，整段标记，而不是只消前 3 个。

![十字交叉：横向段与纵向段共用一格，覆盖式标记无需去重](images/wc57_q4_crush_detect.svg)

### 3.3 算法流程：标记 → 清零 → 压实

每一轮固定三步，第三步是另一处容易写错的地方：**同一列内**非零糖果必须整体下坠，等价于「把该列所有非零值按原相对顺序压到底部」。用读写双指针就能在 $O(m)$ 内完成一列，且天然保持相对顺序。

![重力压实：读指针从底向上收集非零，写指针从底向上落位](images/wc57_q4_gravity_drop.svg)

```
循环：
  1. dead 置 false、found ← false
  2. 逐行标记横向段：三格同色即整段向右吸收（读的都是原始 board）
  3. 逐列标记纵向段：同理向下吸收
  4. found == false → 盘面稳定，返回 board
  5. 所有 dead 为 true 的格子置 0 —— 这一步才是「同时消除」
  6. 逐列压实：w = m-1 自底向上落位非零值，再把 board[0..w][j] 补 0
```

### 3.4 示例演算

以示例 2 走一遍，两轮即稳定：

![示例演算：竖三连 4 消除并下坠，拼出横向 5,5,5 后再消除](images/wc57_q4_walkthrough.svg)

| 轮次 | 触发消除的段 | 消除数量 | 下坠带来的变化 |
|------|--------------|----------|----------------|
| 第 1 轮 | 第 3 列底部三个 $4$ | 3 | 该列上方的 $5,3$ 落到底部，$5$ 与第 4 行已有的 $5,5$ 连成横三连 |
| 第 2 轮 | 第 4 行第 3~5 列的 $5,5,5$ | 3 | 第 3 列只剩一个 $3$ 落底，第 4、5 列各自压实 |
| 第 3 轮 | 无可消除段 | 0 | 返回稳定盘面 |

注意第 1 轮只消了 3 个糖果，却因为下坠**制造**出新的三连——这说明「稳定」必须靠反复循环判定，扫一遍是不够的。

## 4. 算法细节

1. **`dead` 每轮重置**：不要沿用上一轮的标记，否则会误删已经稳定的糖果。用 `vector<vector<bool>>` 或 `[[False]*n for _ in range(m)]` 每轮新建最稳妥。
2. **行扫描的指针跳跃**：只需检查 `board[i][j]` 与右侧两格是否同色。命中后从 `j` 起沿同色吸收到段尾（前两格必然同色，重复标记无副作用），`j` 直接落到段尾之后，同一段不会被重复判定；未命中则 `j++`，整体仍是线性扫描。
3. **`0` 不参与匹配**：判定条件必须先写 `v != 0`。若省略，连续三个空格的列会被当成「同色段」反复标记，直接死循环。
4. **长度 $>3$ 整段清除**：命中 `j, j+1, j+2` 后继续向同方向贪心扩展，把整段都标记。漏掉这一步会让长段残留尾巴，轮数变多甚至结果错误。
5. **压实用读写双指针**：读指针 `i` 从底向上扫全列，写指针 `w` 从底向上落位。写指针停下后，`board[0..w][j]` 统一置 $0$；这样一次遍历即可完成「整体下坠 + 顶部补零」，且保持列内相对顺序。
6. **返回值即入参**：函数就地修改 `board` 并返回它。C++ 用 `vector<vector<int>>&` 引用接收，Python 直接改列表，不需要额外拷贝。
7. **循环的终止条件**来自标记结果**而不是**「这一轮有没有改动」：只要行、列扫描都没命中，就说明盘面不存在任何长度 $\ge 3$ 的同色段，此时直接返回，不必再压一次。

## 5. 正确性证明

**引理 1（标记完备）**：一轮扫描结束后，`dead[i][j] = true` 当且仅当 $(i,j)$ 属于某个同行或同列、长度 $\ge 3$ 的同色连续段。

**证明**：任取一个长度 $\ge 3$ 的同色段，其最左（最上）位置记作起点 $s$。扫描指针每次未命中只前进一格，命中则跳到**该段段尾之后**；任何早于 $s$ 的命中都属于更靠前的段、其段尾不超过 $s-1$，因此指针既不会跳过 $s$，也必在 $j=s$ 时满足「三格同色」，随后沿同色向右（向下）吸收整段。故段内每格都被标记；反向地，被标记的格子都来自某次三格同色命中后的吸收，必落在这样的段内。∎

**引理 2（一轮重力后的列形态）**：清零再压实之后，第 $j$ 列自底向上依次是「该列中所有**未被标记**的糖果，按它们在原盘中自下而上的顺序」，其余位置全为 $0$。

**证明**：清零把被标记格子变成 $0$，零值在压实中一律被跳过，故不参与落位；写指针 $w$ 从 $m-1$ 起随读指针自下而上的扫描次序逐个递减，恰好把「原盘中自下而上的未标记序列」原样贴到底部，收尾再把 $w$ 以上的格子补 $0$。∎

**引理 3（轮数有限）**：若某一轮存在可消除段，则该轮至少把 $3$ 个糖果永久清除，糖果总数严格减少。

**证明**：由引理 1，可消除段长度 $\ge 3$，其格子全部被标记并清零；重力只会移动糖果、不新增糖果，因此非零格子总数至少减少 $3$，且不会回升。∎

**定理**：上述循环在有限轮后返回稳定盘面，且该盘面与题目规则逐轮执行得到的结果完全一致。

**证明**：终止性由引理 3——非零糖果数单调严格递减，至多 $\lfloor mn/3 \rfloor$ 轮后必有一轮无标记，循环退出。正确性对轮数归纳：归纳假设第 $k$ 轮开始时算法盘面与规则盘面相同；第 $k$ 轮算法按引理 1 标记出**恰好全部**可消除格子，等价于规则中「同时消除所有可消除段」，再按引理 2 与规则「消除完毕统一按列下坠」等价，故第 $k+1$ 轮开始时二者仍相同。退出时不存在长度 $\ge 3$ 的同色段，正是规则定义的稳定状态。∎

## 6. 复杂度分析

- **时间**：单轮包含行扫描 $O(mn)$、列扫描 $O(mn)$、清零 $O(mn)$、压实 $O(mn)$，合计 $O(mn)$。由引理 3，轮数至多 $\lfloor mn/3 \rfloor$，故最坏 $O\!\left(\frac{(mn)^2}{3}\right) = O(m^2 n^2)$。在 $m,n \le 50$ 时上界约 $2 \times 10^6$ 次基本操作，实际每轮通常消除远多于 3 个糖果，轮数是个小常数（示例 1 只有 2 轮）。
- **空间**：`dead` 布尔矩阵 $O(mn)$；清零与压实均就地完成，不额外开辟盘面，故总空间 $O(mn)$。行扫描命中即跳过整段、压实只搬非零格，实际运行远快于这一上界。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> candyCrush(vector<vector<int>>& board) {
        int m = board.size(), n = board[0].size();
        while (true) {
            vector<vector<bool>> dead(m, vector<bool>(n, false));
            bool found = false;
            for (int i = 0; i < m; ++i) {                 // 横向段：命中后整段吸收
                int j = 0;
                while (j + 2 < n) {
                    int v = board[i][j];
                    if (v && v == board[i][j + 1] && v == board[i][j + 2]) {
                        found = true;
                        while (j < n && board[i][j] == v) dead[i][j++] = true;
                    } else ++j;
                }
            }
            for (int j = 0; j < n; ++j) {                 // 纵向段：读的仍是原始 board
                int i = 0;
                while (i + 2 < m) {
                    int v = board[i][j];
                    if (v && v == board[i + 1][j] && v == board[i + 2][j]) {
                        found = true;
                        while (i < m && board[i][j] == v) dead[i++][j] = true;
                    } else ++i;
                }
            }
            if (!found) return board;                     // 无段可消 → 稳定
            for (int i = 0; i < m; ++i)                   // 同时清零
                for (int j = 0; j < n; ++j)
                    if (dead[i][j]) board[i][j] = 0;
            for (int j = 0; j < n; ++j) {                 // 整列压实：读写双指针
                int w = m - 1;
                for (int i = m - 1; i >= 0; --i)
                    if (board[i][j]) board[w--][j] = board[i][j];
                while (w >= 0) board[w--][j] = 0;
            }
        }
    }
};
```

### Python

```python
class Solution:
    def candyCrush(self, board: list[list[int]]) -> list[list[int]]:
        m, n = len(board), len(board[0])
        while True:
            dead = [[False] * n for _ in range(m)]
            found = False

            for i in range(m):                      # 横向段
                j = 0
                while j + 2 < n:
                    v = board[i][j]
                    if v and v == board[i][j + 1] == board[i][j + 2]:
                        found = True
                        while j < n and board[i][j] == v:
                            dead[i][j] = True
                            j += 1
                    else:
                        j += 1

            for j in range(n):                      # 纵向段
                i = 0
                while i + 2 < m:
                    v = board[i][j]
                    if v and v == board[i + 1][j] == board[i + 2][j]:
                        found = True
                        while i < m and board[i][j] == v:
                            dead[i][j] = True
                            i += 1
                    else:
                        i += 1

            if not found:                           # 无段可消 → 稳定
                return board

            for i in range(m):                      # 同时清零
                for j in range(n):
                    if dead[i][j]:
                        board[i][j] = 0

            for j in range(n):                      # 整列压实
                w = m - 1
                for i in range(m - 1, -1, -1):
                    if board[i][j]:
                        board[w][j] = board[i][j]
                        w -= 1
                while w >= 0:
                    board[w][j] = 0
                    w -= 1
```

## 8. 边界情况与易错点

1. **边扫边删**：在行扫描里直接 `board[i][j] = 0`，会让随后按「同色相邻」判定的纵向段从交点处断开，漏消一片。必须用 `dead` 缓冲。
2. **消一段坠一次**：把压实塞进扫描循环内部，会得到与规则不同的盘面（规则要求整轮消完再一起坠）。压实只能出现在清零之后。
3. **忘记长段扩展**：只标记命中的 `j, j+1, j+2` 而不吸收后续同色格，四个连排的糖果会残留一个，可能引出错误的第二轮。
4. **`0` 参与匹配**：判定漏掉 `v != 0` 时，一整列空格或空格加同色会被反复标记，导致死循环或误删。
5. **扫描边界**：循环条件是 `j + 2 < n` / `i + 2 < m`（等价于 `j <= n-3`），写成 `j + 2 <= n` 会越界访问，写成 `j + 2 < n - 1` 则会漏掉末尾的段。
6. **写指针收尾**：压实只搬非零值，`board[0..w][j]` 必须显式补 $0$；若省略，旧值会残留在列顶。
7. **返回时机**：`found == false` 时直接返回，不要再做一次清零/压实，否则会把本来稳定的盘面多动一次（虽然结果相同，但多写了无用代码，也容易在「已消除但未标记」的变体中出错）。
