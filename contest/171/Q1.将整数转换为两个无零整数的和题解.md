# LeetCode 将整数转换为两个无零整数的和 题解

## 1. 题目概述

- **标题 / 题号**：将整数转换为两个无零整数的和（#1317，easy）
- **链接**：https://leetcode.cn/problems/convert-integer-to-the-sum-of-two-no-zero-integers/
- **来源**：LeetCode 第 171 场周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：「无零整数」指十进制表示中不含数字 `0` 的正整数。给定整数 $n$，要求把它写成两个无零正整数之和，即返回列表 $[a, b]$，满足 $a + b = n$，且 $a$、$b$ 的十进制写法里都没有 `0`。题目保证至少存在一组解，若有多组解，返回任意一组即可（本题是 special judge，输出不唯一）。

**约束**：

- $2 \le n \le 10^4$
- 题目数据保证至少有一个有效解
- 答案不唯一：例如 $n = 11$ 返回 $[2, 9]$ 或 $[8, 3]$ 都算正确
- 由于是 special judge，**不能**与官方输出逐字比对，只能校验「和为 $n$ + 两个数都无零」

> 💡 一句话本质：**无零性是逐位性质**，把 $n$ 拆成「高位和」与「最低位对」之后，最低位那一位总能用 $1 + 9 = 10$ 之类的组合把进位吸收掉，于是问题规模直接掉一个十进制位。

## 2. 示例

**示例 1**

```text
输入：n = 2
输出：[1, 1]
解释：a = 1、b = 1，两数的十进制表示都不含 0，且 1 + 1 = 2。
```

**示例 2**

```text
输入：n = 11
输出：[2, 9]（或任意合法答案）
解释：2 + 9 = 11，2 与 9 都不含 0；官方提示 [8, 3] 同样是正确答案。
```

**示例 3**

```text
输入：n = 1010
输出：[11, 999]（官方答案；本题解构造出 [111, 899]，同样合法）
解释：11 + 999 = 1010，两个加数都不含 0。
      注意 a = 1 在这里行不通：1010 − 1 = 1009 含 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：从小到大枚举 $a = 1, 2, \dots, n-1$，令 $b = n - a$，用「逐位取模判断是否为 0」检查 $a$、$b$ 是否都无零，第一个通过的即为答案。检查一个数是否无零是 $O(\log n)$，总复杂度 $O(n \log n)$。

对 $n \le 10^4$ 这个量级，$10^4 \times 5$ 次操作绰绰有余，官方提示也正是「循环枚举 + 检查」。实测把 $n$ 从 $2$ 扫到 $10^4$，**枚举量最坏的一次只到 $a = 112$**（$n = 1101$，答案 $112 + 989$），因为合法的末位组合极多，答案非常稠密。

但枚举里有两个坑：

1. **不能把 $a$ 写死成 1**。$n = 69$ 时 $1 + 68$ 恰好可行，$n = 1010$ 时 $1 + 1009$ 就不行（$1009$ 含 0），必须让枚举继续走。
2. **$a$ 与 $b$ 都要检查**。只检查 $n - a$ 无零、却忘了 $a$ 自己也不行：$a = 10$ 虽然 $n - 10$ 可能合法，但 $a$ 本身已经带 0。

既然 $O(n\log n)$ 都能过，为什么还要往下想？因为本题的核心结论非常漂亮：可以用**逐位构造**把复杂度压到 $O(\log n)$，且顺带证明了「答案一定存在」。这正是签到题值得复盘的地方。

### 3.2 核心观察：无零性可以逐位隔离

![逐位拆分：最低位管进位，高位和是同一个子问题](images/wc171_q1_digit_split.svg)

十进制加法是**逐位带进位**的。把 $n$ 写成

$$n = 10q + r, \qquad q = \left\lfloor \frac{n}{10} \right\rfloor,\; r = n \bmod 10,$$

同样地，把答案写成「高位部分 + 最低位」的形式：

$$a = 10a' + x, \qquad b = 10b' + y .$$

由**拼接引理**（§5 引理 1）：只要最低位 $x, y \in [1,9]$ 非零，$a$ 是否无零就**只取决于高位部分 $a'$**——十进制表示不过是把 $a'$ 的数字原样写在 $x$ 左边（$a' = 0$ 时 $a$ 就是一位数 $x$）。于是「$a$、$b$ 都无零」等价于「$a'$、$b'$ 都无零且 $x, y \ge 1$」。

代入 $a + b = n$：

$$10(a' + b') + (x + y) = 10q + r .$$

两边对比，$x + y$ 只有两种可能，因为 $x, y \ge 1$ 保证 $x + y \ge 2$：

- **不进位**（$r \ge 2$）：取 $x + y = r$，此时 $a' + b' = q$。最省事的取法是 $(x, y) = (1, r-1)$，两个都落在 $[1,9]$；
- **进一位**（$r \in \{0, 1\}$）：$x + y \le 18$ 装不下 $r$，只能取 $x + y = r + 10$，此时 $10(a' + b') = 10q + r - (r + 10) = 10(q-1)$，即 $a' + b' = q - 1$。取 $(x, y) = (1, 9)$ 覆盖 $r = 0$，取 $(x, y) = (2, 9)$ 覆盖 $r = 1$。

关键点：**无论 $r$ 是什么，$(x, y)$ 都能选成两个非零数字**，代价只是把高位和从 $q$ 调成 $q-1$。而「高位和」本身又是一个**同型子问题**（求两个无零整数之和为 $q$ 或 $q - 1$），规模只有一个十进制位。递归下去，几层就到底（$n \le 10^4$ 时最多 4 层）。

> 💡 为什么 $(1,9)$ 这么万能：它把 $n$ 的 0 位「吃掉」——$1 + 9 = 10$ 在个位写 0、向高位进 1，恰好把 $n$ 在这一位上的 0 补上，而两个加数在这一位都不为 0。

### 3.3 算法流程

![按最低位分三支的递归流程](images/wc171_q1_recursion_flow.svg)

定义 `solve(m)`：返回 $(a, b)$，满足 $a + b = m$，且 $a$、$b$ 的十进制数字全部非零；**约定 $0$ 表示「这一部分没有任何数字」**（哨兵，专供拼接用，不代表数字 0）。

```text
solve(m):
    if m <= 1:  return (m, 0)          # solve(0) = (0,0)，solve(1) = (1,0)
    q, r = m // 10, m % 10
    if r >= 2:  (a', b') = solve(q);      (x, y) = (1, r-1)
    elif r == 1:(a', b') = solve(q - 1);  (x, y) = (2, 9)
    else:       (a', b') = solve(q - 1);  (x, y) = (1, 9)
    return (10a' + x, 10b' + y)
```

递归可以等价地写成自底向上的迭代：用一个 `mul` 记录当前在处理第几位（$10^0, 10^1, \dots$），每轮把这一层的 $(x, y)$ 累加进答案，循环结束时如果还剩 $m = 1$，再把它补进高位：

```text
a = b = 0; mul = 1
while m >= 2:
    q, r = m // 10, m % 10
    (x, y, m) = (1, r-1, q)     if r >= 2
              = (2, 9, q-1)     if r == 1
              = (1, 9, q-1)     if r == 0
    a += x * mul; b += y * mul; mul *= 10
if m == 1: a += mul              # 高位残留的 1
```

两种写法的输出完全一致（已验证 $2 \le n \le 10^4$ 全部相同），递归版更贴近上面的推导，迭代版常数更小。

### 3.4 示例演算

![n = 1010 的递归链与拼接](images/wc171_q1_walkthrough.svg)

以 $n = 1010$ 为例，递归链是 $1010 \to 100 \to 9$，再自底向上拼接：

| 层 | $m$ | $q$ | $r$ | 分支 | 本层 $(x, y)$ | 得到的 $(a, b)$ |
|----|-----|-----|-----|------|----------------|------------------|
| 底 | 9 | 0 | 9 | $r \ge 2$ | $(1, 8)$ | $(1, 8)$ |
| 中 | 100 | 10 | 0 | $r = 0$ | $(1, 9)$ | $(10\cdot1+1,\ 10\cdot8+9) = (11, 89)$ |
| 顶 | 1010 | 101 | 0 | $r = 0$ | $(1, 9)$ | $(10\cdot11+1,\ 10\cdot89+9) = (111, 899)$ |

校验：$111 + 899 = 1010$，且两个数的每一位都是 $1, 8, 9$，不含 0。官方给的是 $[11, 999]$，同样合法，这正是 special judge 的含义。

再看两个边界值：

- $n = 10000$：链为 $10000 \to 999 \to 99 \to 9$；$999$ 一路走 $r \ge 2$ 得到 $111 + 888$，于是 $10000$ 得到 $1111 + 8889 = 10000$。
- $n = 69$：$q = 6,\ r = 9 \ge 2$，前缀和为 $6$，`solve(6)` 由 $q = 0, r = 6$ 得 $(1, 5)$，拼接得 $11 + 58 = 69$；官方给 $[1, 68]$，两者都合法。

## 4. 算法细节

1. **哨兵 $0$ 的语义**：`solve` 的返回值允许出现 0，它表示「该加数在这一层及以上没有数字」。$a = 10 \cdot 0 + x = x$ 是一位数，十进制写法里并没有 0，因此不违反题意。若把 0 误解为「数字 0」，就会错误地否定 $(1, 8)$ 这类结果。
2. **三个分支的划分依据是 $r$**，不是 $n$ 的大小；$r$ 只用一次，随后递归实参变成 $q$ 或 $q - 1$，一刻也不重复使用。
3. **$(x, y)$ 的选择不唯一**：$r \ge 2$ 时任何满足 $x + y = r$、$x, y \in [1,9]$ 的对都行；$r = 0$ 时 $(1,9), (2,8), \dots, (9,1)$ 均可；$r = 1$ 时 $(2,9), (3,8), \dots$ 均可。这里取「$x$ 尽量小」是为了让结果好看，对正确性没有影响。
4. **$r \in \{0,1\}$ 时必须进位**：$x, y \ge 1$ 保证 $x + y \ge 2 > r$，凑不出 $x + y = r$，只能取 $x + y = r + 10$，于是前缀和要从 $q$ 调成 $q - 1$。若这里误用 $q$，和会多出 10：$n = 1010$ 时前缀和算成 $101$，$\text{solve}(101) = (12, 89)$，拼接得 $(121, 899)$，和是 $1020 \ne 1010$。
5. **递归实参一定严格变小**：$q = \lfloor m/10 \rfloor \le m/2 < m$（$m \ge 2$），$q - 1 < m$，故终止性显然；深度不超过十进制位数，$n \le 10^4$ 时实测最多 4 层（如 $n = 2222$）。
6. **整型范围**：$a, b < n \le 10^4$，拼接 $10a' + x \le n$ 不会溢出，`int` 足够；即使把上界放宽到 $10^{18}$，只要换成 `long long` 同样的推导依然成立。
7. **返回类型**：C++ 返回 `vector<int>{a, b}`，Python 返回 `[a, b]`，顺序无所谓（先 $a$ 后 $b$ 与官方一致更好读）。
8. **不要用字符串拼接**：把数字转成字符串再判 0 也可以，但构造法根本不需要判 0——每一位都是显式选出来的非零数字，这是本题最省事的正确性来源。

## 5. 正确性证明

先约定：称 $(a, b)$ 是 $m$ 的**合法拆分**，若 $a + b = m$、$a, b \ge 0$，且 $a$、$b$ 的十进制数字全部非零（把 $0$ 看作「没有数字」，空串不违反「无零」）。

**引理 1（拼接引理）**：对任意整数 $m \ge 0$ 与数字 $d \in [1,9]$，十进制数 $10m + d$ 的数字串等于「$m$ 的数字串接上 $d$」（$m = 0$ 时就是单独一位 $d$）。因此 $10m + d$ 无零，当且仅当 $m = 0$ 或 $m$ 无零。

**证明**：$m = \sum_{i \ge 0} m_i 10^i$ 时 $10m + d = d + \sum_{i \ge 0} m_i 10^{i+1}$，正是把 $m$ 的数字整体左移一位、最低位填 $d$；由于 $d \ne 0$，最高位不会被抹掉，也不会产生新的 0。若 $m$ 含 0，则移位后该 0 仍在；若 $m$ 无零且 $m \ne 0$，则移位后全部非零、末位 $d \ne 0$，故无零。∎

**引理 2（分支合法）**：设 $n = 10q + r$（$n \ge 2$，$0 \le r \le 9$），并设 $(a', b')$ 是 $q$ 或 $q - 1$ 的合法拆分。按 $r$ 取 §3.3 中对应的 $(x, y)$ 后，$a = 10a' + x$、$b = 10b' + y$ 满足 $a + b = n$ 且都无零。

**证明**：分三种情况。

- $r \ge 2$：$(x, y) = (1, r-1)$，$r - 1 \ge 1$，前缀和 $a' + b' = q$。于是 $a + b = 10q + 1 + (r-1) = 10q + r = n$。
- $r = 1$：$(x, y) = (2, 9)$，前缀和 $a' + b' = q - 1$。于是 $a + b = 10(q-1) + 2 + 9 = 10q + 1 = n$。
- $r = 0$：$(x, y) = (1, 9)$，前缀和 $a' + b' = q - 1$。于是 $a + b = 10(q-1) + 1 + 9 = 10q = n$。

三种情况下 $x, y$ 都取自 $[1,9]$；由前提 $a'$、$b'$ 无零，再由引理 1，$10a' + x$ 与 $10b' + y$ 都无零。∎

**引理 3（良基）**：递归调用 `solve(m)` 时 $m \ge 2$，其子调用的实参 $m' \in \{q, q-1\}$ 满足 $0 \le m' < m$。

**证明**：$q = \lfloor m/10 \rfloor \le m/2$（$m \ge 2$ 时 $m/10 \le m/2$），故 $q < m$；$q - 1 < q < m$；又 $q \ge 0$、$q - 1 \ge -1$，而分支里只有在 $q \ge 1$ 时才会用到 $q - 1$（$m \ge 2$ 且 $r \in \{0,1\}$ 推出 $m \ge 10$，$q \ge 1$），故 $m' \ge 0$。∎

**定理**：对任意 $n \ge 2$，`solve(n)` 返回 $n$ 的一个合法拆分，且 $a, b \ge 1$；递归深度不超过 $n$ 的十进制位数。

**证明**：对 $n$ 归纳。$n \le 1$ 时返回 $(n, 0)$，和为 $n$，且出现的数字只能是 $0$ 或 $1$，合法。设所有 $m < n$ 的 `solve(m)` 都返回合法拆分；$n \ge 2$ 时由引理 3，子调用实参 $m' \le q < n$ 合法，据归纳假设子调用返回的 $(a', b')$ 是合法拆分，再由引理 2，顶层 $a + b = n$ 且 $a$、$b$ 都无零，故 `solve(n)` 合法。$a, b \ge 1$ 由 $x, y \ge 1$ 保证（$a = 10a' + x \ge 1$）。深度：每层实参至少缩小 10 倍（$q \le m/10$），到 $\le 1$ 为止，故深度不超过位数。∎

## 6. 复杂度分析

- **时间**：$O(\log_{10} n)$，即 $n$ 的十进制位数 $d \le 5$。每层只做一次除法取余、一次条件判断和两次「乘 10 加」。递归版与迭代版同阶。
- **空间**：递归版 $O(d)$ 的调用栈（$d \le 5$，常数级，可当 $O(1)$）；迭代版 $O(1)$，只有 `a`、`b`、`mul`、`m` 四个整型变量。
- **对比**：暴力枚举是 $O(n \log n)$（$n = 10^4$ 时约 $10^4 \times 5$ 次判断），构造法是 $O(\log n)$，快了两个数量级以上；不过本题数据极小，两者都能轻松通过，构造法的价值主要在于「顺带证明了存在性」。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <utility>
using namespace std;

class Solution {
    // solve(m) 返回 {a, b}：a + b = m，且 a、b 的十进制数字全部非零。
    // 0 表示「这一部分没有数字」，专供拼接使用。
    pair<int, int> solve(int m) {
        if (m <= 1) return {m, 0};                 // solve(0) = (0,0)，solve(1) = (1,0)
        int q = m / 10, r = m % 10;                // 高位前缀 q、最低位 r
        pair<int, int> pre = solve(r >= 2 ? q : q - 1);
        int a = pre.first, b = pre.second;
        if (r >= 2) return {10 * a + 1, 10 * b + (r - 1)};   // 不进位
        if (r == 1) return {10 * a + 2, 10 * b + 9};         // 进一位，末位 2 + 9 = 11
        return {10 * a + 1, 10 * b + 9};                     // 进一位，末位 1 + 9 = 10
    }

public:
    vector<int> getNoZeroIntegers(int n) {
        pair<int, int> ans = solve(n);
        return {ans.first, ans.second};
    }
};
```

### Python

```python
class Solution:
    def getNoZeroIntegers(self, n: int) -> list[int]:
        # solve(m) 返回 (a, b)：a + b = m，且 a、b 的十进制数字全部非零。
        # 0 表示「这一部分没有数字」，专供拼接使用。
        def solve(m: int) -> tuple[int, int]:
            if m <= 1:                       # solve(0) = (0,0)，solve(1) = (1,0)
                return m, 0
            q, r = divmod(m, 10)             # 高位前缀 q、最低位 r
            a, b = solve(q if r >= 2 else q - 1)
            if r >= 2:                       # 不进位：末位 (1, r-1)
                return 10 * a + 1, 10 * b + (r - 1)
            if r == 1:                       # 进一位：末位 (2, 9)
                return 10 * a + 2, 10 * b + 9
            return 10 * a + 1, 10 * b + 9    # 进一位：末位 (1, 9)

        a, b = solve(n)
        return [a, b]
```

## 8. 边界情况与易错点

1. **$n = 2$**：$q = 0,\ r = 2 \ge 2$，子调用 `solve(0)` 返回 $(0,0)$，拼接得 $(1,1)$，正确。若让 `solve(0)` 返回 $(1,1)$ 之类，这里就会拼出 $(11, 11)$，和变成 $22$。
2. **$n = 10$（$r = 0$ 且 $q = 1$）**：需要 `solve(0)`，得 $(1,9)$。若终止条件不允许 $m = 0$（例如写成 `m <= 0` 之外的形式），$q - 1 = 0$ 这一层就会被当成非法，$n = 10$ 这类直接漏掉。
3. **$n = 10000$**：返回 $(1111, 8889)$。注意两个加数的位数**不必相同**，也不必等于 $n$ 的位数——只要求和为 $n$ 且都不含 0。
4. **$r \in \{0,1\}$ 的分支里把前缀和写成 $q$**：和会多出 10，答案直接错（$n = 1010$ 会得到和为 $1020$ 的一对）。这个错误很隐蔽——两个数确实都不含 0，只有校验「和等于 $n$」时才会暴露。
5. **让最低位取 0 图省事**：例如为了对齐而选 $x = 0$，此时 $a$ 的十进制写法里就真的有一个 0，直接违反题意。$x, y$ 必须落在 $[1,9]$。
6. **误判 0 为数字 0**：中间结果里出现的 0 是「无此部分」的哨兵，不能拿去检查「是否含 0」；判断无零只能对最终返回的两个正整数做。
7. **暴力枚举时只查一个数**：$a$ 和 $n - a$ 都要查；且循环上界是 $n - 1$（保证 $b \ge 1$），写成 $n$ 会得到 $a = n, b = 0$，而 0 不是正整数。
8. **答案不唯一导致的对拍方式**：不能用 `assert result == expected`，必须校验「和为 $n$ 且两数都无零」；本题所有官方示例都只保证「一个」合法答案。

**延伸思考**：

1. **把「不含 0」换成「不含数字 $d$」**：若 $d \in [1,9]$，逐位构造依然可行，只要在 $\{1,\dots,9\} \setminus \{d\}$ 里选 $(x, y)$ 即可；$r \ge 2$ 时要 $x + y = r$、$r \in \{0,1\}$ 时要 $x + y = r + 10$，可用数字少于 2 个时（例如只允许 $\{1\}$）才会无解。
2. **$n$ 放大到 $10^{18}$**：构造法 $O(\log n)$ 原样可用（换成 `long long`），而暴力枚举 $O(n \log n)$ 立刻失效——这正是「签到题也值得想最优解」的现实原因。
3. **要求解字典序最小**：即让 $a$ 尽量小。此时不能随便取 $(x, y) = (1, r-1)$，需要从最高位开始贪心并在进位处回溯：最高位希望取 $1$，但它会连带决定低位是否必须「借位」，这是一个自顶向下的可行性判定问题，可以用「剩余位数能否消化进位」的 DP 在 $O(d)$ 内完成。
4. **统计解的个数**：给定 $n$，数一数有多少对 $(a, b)$ 都无零。这等价于在逐位 DP 中统计路径数，状态是（当前位、$a$ 是否已经「结束」、进位），是对本题构造过程的自然计数版本。
