# LeetCode 或运算的最小翻转次数 题解

## 1. 题目概述

- **标题 / 题号**：或运算的最小翻转次数（#1318，medium）
- **链接**：https://leetcode.cn/problems/minimum-flips-to-make-a-or-b-equal-to-c/
- **来源**：LeetCode 第 171 场周赛 Q2
- **难度**：中等
- **标签**：位运算

**题意**：给定正整数 $a$、$b$、$c$。一次「位翻转」可以把 $a$ 或 $b$ 的二进制表示中**任意一位**取反（$0 \to 1$ 或 $1 \to 0$），$c$ 不能改。求让 $a \,\text{OR}\, b = c$ 成立的**最少翻转次数**。

**约束**：

- $1 \le a, b, c \le 10^9$
- 只涉及按位或与非负整数，无进位、无符号问题

$10^9 < 2^{30}$，所以二进制最多 30 位；答案至多 $2 \times 31 = 62$，$O(1)$ 空间、$O(1)$ 时间即可。

## 2. 示例

**示例 1**

```text
输入：a = 2, b = 6, c = 5
输出：3
解释：a = 010, b = 110, c = 101
      第 1 位：a、b 都是 1，而 c 要 0 → 两个 1 都得清掉，翻 2 次
      第 0 位：a、b 都是 0，而 c 要 1 → 补一个 1 即可，翻 1 次
      第 2 位：b 已经是 1，c 也要 1 → 无需翻转
      翻完 a = 001 = 1，b = 100 = 4，1 OR 4 = 5 = c，共 3 次
```

**示例 2**

```text
输入：a = 4, b = 2, c = 7
输出：1
解释：a = 100, b = 010, c = 111，只有第 0 位缺一个 1，
      把 a 或 b 的第 0 位翻成 1 即可，共 1 次
```

**示例 3**

```text
输入：a = 1, b = 2, c = 3
输出：0
解释：1 OR 2 = 3，已经满足，无需任何翻转
```

## 3. 解题思路

### 3.1 暴力思路

把「翻转」看成状态搜索：状态是 $(a, b)$，一次操作翻转其中一个数的某一位。状态空间高达 $2^{60}$，BFS 完全不可行。即便把位宽压到 30 位，仍是 $(2^{30})^2$ 级别。

另一个朴素想法是「枚举最终的目标值 $a', b'$，要求 $a' \,\text{OR}\, b' = c$」，候选对同样是天文数字。暴力的症结在于：它把 30 个**互不相干**的位绑在一起枚举了。

### 3.2 核心观察：每一位完全独立

![按位独立的真值表](images/wc171_q2_bit_truth_table.svg)

按位或**不进位**：结果的第 $i$ 位只取决于 $a_i$ 与 $b_i$，与其它位毫无关系。而一次翻转也只改动一个数的某一位。于是

$$\text{总代价} = \sum_{i} \text{第 } i \text{ 位的最小代价}$$

每一位上只有 4 种输入组合，穷举即得规则：

| $c_i$ | $(a_i, b_i)$ | 需要的结果 | 最小代价 | 做法 |
|-------|--------------|------------|----------|------|
| 0 | $(0,0)$ | $0 \lor 0 = 0$ | 0 | 已满足 |
| 0 | $(1,0)$ 或 $(0,1)$ | 必须是 $0 \lor 0$ | 1 | 把那个 1 清 0 |
| 0 | $(1,1)$ | 必须是 $0 \lor 0$ | 2 | 两个 1 都要清 0 |
| 1 | $(0,0)$ | 至少一个 1 | 1 | 补出一个 1 |
| 1 | $(1,0)$ 或 $(0,1)$ | 至少一个 1 | 0 | 已满足 |
| 1 | $(1,1)$ | 至少一个 1 | 0 | 已满足 |

压缩成两句话：

- $c_i = 0$：要求 $a_i = b_i = 0$，代价就是 $a_i + b_i$（清掉所有现存的 1）。
- $c_i = 1$：要求至少一个 1，代价是 $[\,a_i = b_i = 0\,]$（缺才补 1 个，已有则 0）。

### 3.3 算法流程

![逐位统计流程图](images/wc171_q2_algorithm_flow.svg)

对 $i = 0, 1, \dots, 30$：

1. 取出三个位 $a_i = (a \gg i) \,\&\, 1$，$b_i$、$c_i$ 同理。
2. 若 $c_i = 0$：`ans += a_i + b_i`。
3. 若 $c_i = 1$：`ans += (a_i | b_i) == 0 ? 1 : 0`。
4. 循环结束返回 `ans`。

高位不必特殊处理：$i \ge 31$ 时 $a$、$b$、$c$ 的位全为 0，而 $c_i = 0$ 且 $a_i = b_i = 0$ 的代价恰为 0，所以答案不会被漏算。

### 3.4 示例演算

![示例 1 逐位走查](images/wc171_q2_example_walkthrough.svg)

以 $a = 2 = 010_2$、$b = 6 = 110_2$、$c = 5 = 101_2$ 为例（从高位到低位）：

| 位 $i$ | $a_i$ | $b_i$ | $a_i \lor b_i$ | $c_i$ | 判定 | 代价 |
|--------|-------|-------|----------------|-------|------|------|
| 2 | 0 | 1 | 1 | 1 | 已有 1，满足 | 0 |
| 1 | 1 | 1 | 1 | 0 | 两个 1 都清掉 | 2 |
| 0 | 0 | 0 | 0 | 1 | 缺 1，补一个 | 1 |

合计 $0 + 2 + 1 = 3$，与官方输出一致。翻转后的一个可行方案是 $a' = 001_2 = 1$、$b' = 100_2 = 4$，$1 \lor 4 = 5 = c$。

## 4. 算法细节

1. **位宽取 31**：$10^9 < 2^{30}$，故下标 $0 \sim 30$ 的 31 位足以覆盖全部可能为 1 的位。取 31 而不是 30 只是多一次恒为空转的迭代，安全。
2. **取位写法**：一律用 `(x >> i) & 1`，不要写 `x & (1 << i)`——当 $i \ge 31$ 时 `1 << i` 在有符号 32 位 `int` 上属于未定义行为，而右移 + 掩码永远安全。
3. **$c_i = 0$ 的代价**：`ans += a_i + b_i`，即把 $a$、$b$ 该位上所有的 1 全部清零，一个 1 一次翻转，恰好是最优。
4. **$c_i = 1$ 的代价**：`ans += (a_i | b_i) == 0`，C++ 中布尔值可隐式转 `int`，Python 中写 `int(a_i | b_i == 0)` 或直接 `if` 分支。
5. **两种等价写法**：也可以写成 `while (a || b || c) { ...; a >>= 1; b >>= 1; c >>= 1; }`，循环次数等于三者最高位的位数，代码更短且天然不需要指定位宽。
6. **一行公式（可选）**：设 $p = a \lor b$，$q = a \land b$，则答案
   $$\text{ans} = \operatorname{popcount}(p \oplus c) + \operatorname{popcount}(q \,\&\, \lnot c)$$
   前一项数「$a \lor b$ 与 $c$ 不一致的位」，后一项把「$c_i = 0$ 但 $a_i = b_i = 1$」这种需要**额外**再清一次的位补上。它和逐位循环完全等价，但一行即可，适合面试速写。
7. **不需要真正修改 $a$、$b$**：本题只问次数，不必构造出翻转后的数；若面试官追问方案，就在每位上按表格记录「清 $a_1$」「清 $a$、$b$」「置 $a_0$」等动作即可。
8. **答案范围**：每位最多 2 次，31 位最多 62，`int` / Python `int` 都绰绰有余，不会溢出。

## 5. 正确性证明

**引理 1（按位独立）**：对任意 $i \ne j$，$(a \lor b)$ 的第 $i$ 位只由 $a_i, b_i$ 决定，与 $a_j, b_j$ 无关；翻转第 $i$ 位也只改变第 $i$ 位。

**证明**：按位或的定义是逐位取「或」，第 $i$ 位的值就是 $a_i \lor b_i$，不产生进位，也不读取其它位。翻转操作只对 $a$ 或 $b$ 的单个位取反，其余位保持不变。故不同位上的判定与操作互不影响。∎

**引理 2（单位最优代价）**：给定第 $i$ 位的 $(a_i, b_i, c_i)$，使 $a_i \lor b_i = c_i$ 的最小翻转次数为
$$\text{cost}_i = \begin{cases} a_i + b_i, & c_i = 0 \\ 1, & c_i = 1 \text{ 且 } a_i = b_i = 0 \\ 0, & c_i = 1 \text{ 且 } (a_i, b_i) \ne (0,0) \end{cases}$$

**证明**：列举全部 $2 \times 4 = 8$ 种组合。

- $c_i = 0$：结果必须是 $0$，只能 $a_i = b_i = 0$。原有 1 的个数是 $a_i + b_i$，每个 1 必须翻一次且翻一次即可消除，故代价 $a_i + b_i$，且这是下界（每个 1 至少要翻一次），可达，故最优。
- $c_i = 1$ 且 $(a_i, b_i) \ne (0,0)$：已经满足「至少一个 1」，代价 0（下界）。
- $c_i = 1$ 且 $a_i = b_i = 0$：至少要有一个 1，翻一次即可满足，故代价 1。

八种组合逐一覆盖，故结论成立。∎

**引理 3（可加性）**：任意合法方案的翻转次数等于各位代价之和，且各位的独立最优选择可以同时实现。

**证明**：一次翻转只作用在单个数的单个位上，因此可把整个方案按位拆分成 30 组互不重叠的翻转，第 $i$ 组恰好实现第 $i$ 位的目标，其大小为 $\text{cost}_i$ 的下界；反之，把各位最优操作合并，得到的方案总次数为 $\sum_i \text{cost}_i$，且每位的目标都达成，故合法。∎

**定理**：算法返回的 `ans` 等于最小翻转次数。

**证明**：算法逐位累加 $\text{cost}_i$，由引理 2 每一步取的都是该位的下界，由引理 3 这些下界可同时达到，故 $\text{ans} = \sum_i \text{cost}_i$ 既是一个合法方案的代价，又是所有方案的下界，即为最小值。高位（$i \ge 31$）上三者均为 0，$\text{cost}_i = 0$，不影响结论。∎

## 6. 复杂度分析

- **时间**：$O(\log \max(a,b,c))$，循环固定 31 轮，每轮常数次位运算，视作 $O(1)$（约 30 次迭代）。
- **空间**：$O(1)$，只用了累加器 `ans` 和几个临时位变量，与输入规模无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minFlips(int a, int b, int c) {
        int ans = 0;
        for (int i = 0; i < 31; ++i) {
            int ba = (a >> i) & 1;
            int bb = (b >> i) & 1;
            int bc = (c >> i) & 1;
            if (bc == 0) {
                ans += ba + bb;              // c 该位为 0：两个 1 都要清掉
            } else if (!(ba | bb)) {
                ans += 1;                    // c 该位为 1：缺 1 才补，已有一个 1 则免费
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minFlips(self, a: int, b: int, c: int) -> int:
        ans = 0
        for i in range(31):
            ba = (a >> i) & 1
            bb = (b >> i) & 1
            bc = (c >> i) & 1
            if bc == 0:
                ans += ba + bb          # 两个 1 都得清 0
            elif (ba | bb) == 0:
                ans += 1                # 至少保留一个 1，补一个即可
        return ans
```

## 8. 边界情况与易错点

1. **$c_i = 1$ 而 $a_i = b_i = 0$ 只翻 1 次**：容易误写成 2 次（以为两个数都要补），实际上只需把其中一个数该位置 1，OR 就为 1。
2. **$c_i = 0$ 而 $a_i = b_i = 1$ 要翻 2 次**：容易只算 1 次（只清 $a$），结果 $b$ 的 1 让 OR 仍为 1。
3. **移位未定义行为**：写 `x & (1 << i)` 而 $i = 31$ 时，`1 << 31` 在有符号 `int` 上是 UB（可能得到负数）；统一用 `(x >> i) & 1` 可以完全规避。
4. **循环上界不足**：若只循环到 20 位，$a = 10^9$ 的高位会被漏掉（$10^9 \approx 2^{29.9}$，第 29 位为 1）。取 31 位，或改成 `while (a || b || c)` 边移边算。
5. **$a$、$b$、$c$ 均 $\ge 1$**：本题没有 0 或负数输入，不必考虑补码、符号位；即便输入 0，逐位循环的结论也依然成立（代价 0）。
6. **不要把「翻转」理解成「整数量级操作」**：每次只能改一位，$a = 6 \to 4$ 是翻 1 次而不是 1 次「减法」，题目给的是位代价而非数值差。
7. **答案不会超过 62**：若写出比 62 更大的结果，多半是把 $c_i = 0$、$(1,1)$ 的情况重复计数了。
