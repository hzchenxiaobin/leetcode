# LeetCode 连通网络的操作次数 题解

## 1. 题目概述

- **标题 / 题号**：连通网络的操作次数（#1319，medium）
- **链接**：https://leetcode.cn/problems/number-of-operations-to-make-network-connected/
- **来源**：LeetCode 第 171 场周赛 Q3
- **难度**：中等
- **标签**：并查集、图、深度优先搜索、广度优先搜索

**题意**：$n$ 台计算机编号 $0 \sim n-1$，`connections[i] = [a, b]` 表示 $a$ 与 $b$ 之间已有一根线缆。一次操作是「**拔开**一对已直连计算机之间的线缆，再把它**插到**一对**尚未直连**的计算机之间」。求让整张网络连通所需的**最少操作次数**；若无论如何都做不到，返回 `-1`。

两个要点决定了本题的形态：其一，操作只是**搬移**线缆，**边的总数永远不变**；其二，插入的目标必须是「原本没有直连」的一对点，所以不会造出重边。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{connections.length} \le \min\!\left(\frac{n(n-1)}{2},\,10^5\right)$
- `connections[i].length == 2`，$0 \le \text{connections}[i][0], \text{connections}[i][1] < n$
- `connections[i][0] != connections[i][1]`，无自环、无重边、无重复连接

## 2. 示例

**示例 1**

```text
输入：n = 4, connections = [[0,1],[0,2],[1,2]]
输出：1
解释：三台机器 0、1、2 已经连通（还多一条 1-2 的冗余边），4 号是孤立点。
      拔下 1-2，插到 1-3 上 → 1 次操作让 4 台机器全连通。
```

**示例 2**

```text
输入：n = 6, connections = [[0,1],[0,2],[0,3],[1,2],[1,3]]
输出：2
解释：0、1、2、3 连成一块，4 和 5 各自孤立 → 共 3 个连通分量，
      需要 3 − 1 = 2 次操作。
```

**示例 3**

```text
输入：n = 6, connections = [[0,1],[0,2],[0,3],[1,2]]
输出：-1
解释：只有 4 条线缆，而 6 台机器连通至少需要 5 条，线缆数量不足。
```

**示例 4**

```text
输入：n = 5, connections = [[0,1],[0,2],[3,4],[2,3]]
输出：0
解释：0-1-2-3-4 已经串成一条链，全图连通，不需要任何操作。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「枚举操作序列」：每次从当前边集里挑一条边拔下、再挑一对非边插上，用 BFS 搜索状态空间，直到某状态连通。$n$ 台机器最多 $10^5$ 条边，状态数是指数级的，毫无可行性。

另一个常见误区是把它当成**最小生成树**：MST 只告诉我们「$n$ 个点连通需要 $n-1$ 条边」，但本题的边**不能凭空新增，只能搬家**，而且搬一条就是一次操作，代价模型完全不同——真正要数的是「缺几条边才能把 $c$ 块拼成一块」，而不是「选哪些边最便宜」。

还有一条看似聪明的退路：直接数「孤立点个数」。它同样错——示例 2 里 4、5 都是孤立点，答案 2 恰好相等；但若两块各含 3 个点、互不相连（$c = 2$，无孤立点），答案仍是 1。

问题的实质只有两个量：**连通分量数 $c$**，以及**有没有足够的边可搬**。

### 3.2 核心观察：答案就是 $c - 1$

![核心观察：c 个分量与 r 条冗余边](images/wc171_q3_components_redundant.svg)

把图看成 $c$ 个连通分量，分量 $i$ 有 $n_i$ 个点、$m_i$ 条边。一个分量内部至少要 $n_i - 1$ 条边才连通，于是**落在环上的边（冗余边）**总数为

$$r = \sum_i \bigl(m_i - (n_i - 1)\bigr) = m - (n - c)$$

这些冗余边正是唯一「拆得动」的资源：删掉环上的一条边，图的分量结构分毫不变。于是：

- **下界**：一次操作「删一条 + 加一条」，删边至多让 $c$ 增加 1，加边至多让 $c$ 减少 1，净效果是 $c$ **至多减少 1**。要从 $c$ 降到 1，至少需要 $c - 1$ 次。
- **上界**：若 $m \ge n - 1$，则 $r = m - (n - c) \ge c - 1 \ge 1$，$c \ge 2$ 时总有冗余边可拆。每拆一条，$c$ 不变而 $m$ 少 1、待补的缺口也少 1；把它插到**两个不同分量**中的任意两点之间（这两点必然尚未直连），$c$ 正好减 1。重复 $c - 1$ 次就只剩一块。
- **无解**：操作不改变边数，而 $n$ 点连通图至少需要 $n - 1$ 条边。因此 $m < n - 1$ 时**永远**不可能连通，返回 `-1`（这正是官方提示的第一句）。

于是答案被完全刻画：

$$\text{answer} = \begin{cases} -1, & m < n-1 \\ c - 1, & m \ge n-1 \end{cases}$$

> 💡 一句话记忆：**先看边够不够（$m \ge n-1$），再数块数减一（$c - 1$）。**

### 3.3 算法流程

![算法流程：判边数 + 并查集统计分量](images/wc171_q3_union_find_flow.svg)

1. **边数检查**：若 $m < n - 1$，直接返回 `-1`（省掉后续全部计算）。
2. **初始化并查集**：`parent[i] = i`，并令计数器 `comp = n`（每个点自成一个分量）。
3. **扫描每条边**：`ra = find(a)`、`rb = find(b)`。若 `ra != rb`，合并两棵树并令 `comp -= 1`；若 `ra == rb`，说明这条边在环上，是冗余边，跳过即可。
4. **返回** `comp - 1`——用「计数器」而不是最后再扫一遍数根，统计工作摊到每次成功合并上，代码更短、常数更小。

### 3.4 示例演算

![示例 2 走查：并查集合并过程](images/wc171_q3_walkthrough.svg)

以示例 2（$n = 6$，5 条边）为例，初始 `comp = 6`：

| 边 $(a,b)$ | 两端所在集合 | 动作 | `comp` |
|------------|--------------|------|--------|
| (0, 1) | $\{0\} \leftrightarrow \{1\}$ | 合并 | 6 → 5 |
| (0, 2) | $\{0,1\} \leftrightarrow \{2\}$ | 合并 | 5 → 4 |
| (0, 3) | $\{0,1,2\} \leftrightarrow \{3\}$ | 合并 | 4 → 3 |
| (1, 2) | $\{0,1,2,3\}$ 同根 | 冗余边，跳过 | 3 |
| (1, 3) | $\{0,1,2,3\}$ 同根 | 冗余边，跳过 | 3 |

扫描结束后剩下 $\{0,1,2,3\}$、$\{4\}$、$\{5\}$ 三块，答案 $3 - 1 = 2$。自检一下冗余边数：$r = m - (n - c) = 5 - (6 - 3) = 2$，恰好等于 $c - 1$，说明「可搬的边」刚好够用——这两条边（1-2 与 1-3）正是被拔下来去连 4 和 5 的那两根。

其余示例：示例 1 中 $c = 2$（$\{0,1,2\}$ 与 $\{3\}$），答案 $1$；示例 3 中 $m = 4 < 6 - 1$，返回 `-1`；示例 4 中 $c = 1$，答案 $0$。

## 4. 算法细节

1. **先判边数、再建并查集**：$m < n-1$ 的判断必须用**边的条数**与 $n-1$ 比较，不能写成「是否有孤立点」或「$m < n$」之类的近似条件；示例 3 就是专门用来打这种错判的。
2. **路径压缩 + 按大小合并**：`find` 用「路径减半」的迭代写法，`union` 把小子树挂到大的下面，单次操作均摊近 $O(1)$，整题 $O\bigl((n+m)\,\alpha(n)\bigr)$。
3. **`comp` 的更新点只有一处**：必须在确认 `ra != rb` 之后 `--comp`；在 `find` 之前或无条件 `--comp` 都会把冗余边也算成「一次合并」，示例 2 会算成 `6-5-1 = 0`。
4. **冗余边不必显式存**：`ra == rb` 的分支直接 `continue` 即可；若想自检，用 $r = m - (n - c)$ 核对「可搬的边是否够 $c-1$ 条」。
5. **不要用递归版 DFS 数分量**：$n = 10^5$ 且图可能是一条长链，递归深度直接爆栈（Python 默认上限 1000，C++ 也会栈溢出）；要么用并查集，要么用显式栈 / BFS 迭代。
6. **Python 的 `find` 写成迭代**：内嵌函数用 `while parent[x] != x: parent[x] = parent[parent[x]]; x = parent[x]`，既压缩了路径又完全不依赖递归上限。
7. **返回值是 `comp - 1`**：当图本来就连通（示例 4）时 `comp = 1`，答案必须是 `0`；顺手让 $n = 1$ 也自然得 `0`，无需特判。
8. **重边与自环**：题面保证不存在，但并查集天然容忍——重边同样会走 `ra == rb` 分支，被当成冗余边，语义一致。

## 5. 正确性证明

**引理 1（边数下界）**：若 $m < n - 1$，则无论怎样操作都无法使 $n$ 台计算机全连通。

**证明**：一次操作删一条边、加一条边，边数恒为 $m$。而 $n$ 个顶点的连通简单图至少含一棵生成树，即至少 $n - 1$ 条边。故 $m < n-1$ 时边数永远不足，不可能连通。∎

**引理 2（冗余边计数）**：设图连通分量数为 $c$、边数为 $m$，则落在环上的边（冗余边）数恰为 $r = m - (n - c) \ge 0$。

**证明**：分量 $i$ 有 $n_i$ 个点、$m_i$ 条边。分量内部连通，故 $m_i \ge n_i - 1$，其中 $m_i - (n_i - 1)$ 正是该分量内「删掉后仍保持分量连通」的边数，也就是环上的边数。对 $i$ 求和并用 $\sum n_i = n$、$\sum m_i = m$，得 $r = m - (n - c)$，且每一项非负故 $r \ge 0$。∎

**引理 3（下界）**：若当前有 $c$ 个连通分量，任何使全图连通的方案都至少需要 $c - 1$ 次操作。

**证明**：考察一次操作对分量数的影响。删去边 $e$：$e$ 在环上则 $c$ 不变，$e$ 是桥则 $c$ 增加 1。插入边 $f$：$f$ 连接两个不同分量则 $c$ 减 1，否则 $c$ 不变。两步合起来，$c$ 的净减少量至多为 1。要从 $c$ 降到 1，至少需要 $c - 1$ 次。∎

**引理 4（上界）**：若 $m \ge n - 1$，则 $c - 1$ 次操作足以让全图连通。

**证明**：对「剩余操作次数」做归纳，维护不变量 $(c, r) \to (c-1, r-1)$。

设当前 $c \ge 2$。由引理 2 及 $m \ge n-1$ 得 $r = m - n + c \ge c - 1 \ge 1$，故存在冗余边 $e$（在环上）。删去 $e$ 后分量数仍为 $c$（引理 2 的刻画：环上删边不破坏连通性），且边数变为 $m - 1$。

接着从两个**不同**分量中任取点 $u, v$ 连边。二者若已直连，则它们必在同一分量，矛盾；所以 $(u,v)$ 必是一对未直连的点，插入操作合法。插入后两分量合并，$c$ 变为 $c - 1$，边数回到 $m$，于是新的冗余边数为 $r' = m - n + (c - 1) = r - 1$，不变量保持。

重复上述步骤：第 $k$ 步时 $c = c_0 - k$、$r = r_0 - k \ge (c_0 - k) - 1 \ge 1$（只要 $c_0 - k \ge 2$），故每一步都有冗余边可用。走满 $c_0 - 1$ 步后 $c = 1$，全图连通，共用了 $c_0 - 1$ 次操作。∎

**引理 5（并查集统计正确）**：扫描完 $m$ 条边后，`comp` 等于原图的连通分量数 $c$。

**证明**：对已处理边数 $k$ 归纳证明不变式：任意两点同根 $\iff$ 在以 $0..k$ 条边构成的子图中连通，且 `comp` 等于该子图的分量数。$k = 0$ 时每点自成一根、`comp = n`，成立。处理第 $k+1$ 条边 $(a,b)$：若 `find(a) != find(b)`，说明这两块此前互不连通，合并后分量数恰减 1，与「`comp -= 1`」一致；若同根，说明 $a,b$ 已连通，该边不改变连通性，分量数不变，与「跳过」一致。任一情况下，分量之间的连通关系都只由这些边决定，不变式保持。取 $k = m$ 即得结论。∎

**定理**：算法返回值等于使网络连通的最少操作次数。

**证明**：若 $m < n - 1$，由引理 1 不可能连通，算法返回 `-1`，正确。否则算法由引理 5 得到 $c$，返回 $c - 1$：由引理 3 它是任何方案的下界，由引理 4 该下界可被达到，故 $c-1$ 是最少操作次数。∎

## 6. 复杂度分析

- **时间**：$O\bigl(n + m\,\alpha(n)\bigr)$。初始化 `parent` 与 `size` 是 $O(n)$；对 $m$ 条边各做两次 `find` 与至多一次合并，路径压缩 + 按大小合并下均摊 $O(\alpha(n))$，$\alpha$ 是反阿克曼函数，实际不超过 5。$n, m \le 10^5$ 时总操作量约 $10^6$ 量级，远低于时限。
- **空间**：$O(n)$。`parent` 与 `size` 各一个长度 $n$ 的整型数组；只做原地路径压缩，不建邻接表、不用递归栈。输入 `connections` 本身占 $O(m)$，不计入额外空间。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <numeric>
using namespace std;

class Solution {
public:
    int makeConnected(int n, vector<vector<int>>& connections) {
        int m = (int)connections.size();
        if (m < n - 1) return -1;              // 线缆总数不足，永远连不通

        vector<int> parent(n), sz(n, 1);
        iota(parent.begin(), parent.end(), 0);
        int comp = n;                          // 当前连通分量数

        // 迭代版 find + 路径减半，避免 n = 1e5 时递归爆栈
        auto find = [&](int x) {
            while (parent[x] != x) {
                parent[x] = parent[parent[x]];
                x = parent[x];
            }
            return x;
        };

        for (auto& e : connections) {
            int ra = find(e[0]), rb = find(e[1]);
            if (ra == rb) continue;            // 这条边在环上：冗余边，不减少分量
            if (sz[ra] < sz[rb]) swap(ra, rb); // 按大小合并
            parent[rb] = ra;
            sz[ra] += sz[rb];
            --comp;
        }
        return comp - 1;                       // c 个分量要 c-1 次操作
    }
};
```

### Python

```python
from typing import List


class Solution:
    def makeConnected(self, n: int, connections: List[List[int]]) -> int:
        m = len(connections)
        if m < n - 1:                 # 线缆不足，直接无解
            return -1

        parent = list(range(n))
        size = [1] * n

        def find(x: int) -> int:      # 迭代 + 路径减半，避开递归深度限制
            while parent[x] != x:
                parent[x] = parent[parent[x]]
                x = parent[x]
            return x

        comp = n
        for a, b in connections:
            ra, rb = find(a), find(b)
            if ra == rb:
                continue              # 冗余边
            if size[ra] < size[rb]:
                ra, rb = rb, ra
            parent[rb] = ra
            size[ra] += size[rb]
            comp -= 1                 # 只有真正合并才减一

        return comp - 1
```

## 8. 边界情况与易错点

1. **$m < n - 1$ 必须返回 `-1`**：示例 3 就是 $4 < 5$。判据是**边的条数**，不是「有没有孤立点」——$n = 3$、边只有 0-1 时 $m = 1 < 2$，同样无解。
2. **返回 `comp` 而不是 `comp - 1`**：这是本题最高频的 WA。图已连通时 `comp = 1`，答案应为 `0`（示例 4）。
3. **`comp` 被无条件自减**：若在 `ra == rb` 时也减，示例 2 会输出 `0`，示例 1 会输出 `0`。`--comp` 只能写在成功合并的分支里。
4. **递归 DFS 数分量**：$n = 10^5$ 的链状图会让递归栈溢出（Python 报 `RecursionError`，C++ 直接段错误）。用并查集，或改成显式栈 / BFS。
5. **$n = 1$ 的退化输入**：约束下不可能出现（`connections[i][0] != connections[i][1]` 且下标 $< n$，而 `connections.length >= 1`），但代码里 `comp - 1 = 0` 天然正确，无需特判。
6. **把「孤立点个数」当答案**：两块各 3 个点、互不相连时没有孤立点，答案仍是 $1$。只有**分量数**才是正确的计数口径。
7. **误用最小生成树**：本题边不能新增、只能搬移，MST 的「选边」逻辑不适用；MST 只在「允许直接拉新线缆」的变体里才是正解。
8. **自己连自己 / 重边**：题面保证不存在，但即便出现，并查集也会走 `ra == rb` 分支把它当冗余边处理，不会让 `comp` 少算。
