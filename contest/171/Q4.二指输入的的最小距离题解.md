# LeetCode 二指输入的的最小距离 题解

## 1. 题目概述

- **标题 / 题号**：二指输入的的最小距离（#1320，hard）
- **链接**：https://leetcode.cn/problems/minimum-distance-to-type-a-word-using-two-fingers/
- **来源**：LeetCode 第 171 场周赛 Q4
- **难度**：困难
- **标签**：字符串，动态规划

**题意**：键盘是固定的 $5$ 行布局（前 4 行各 6 个字母，末行只有 `Y`、`Z`），字母按行优先编号，字母 $i$ 的坐标是 $(i/6,\ i \bmod 6)$。两根手指从**任意位置**出发（起手不花代价），必须按顺序输入 `word`：每个字符由某一根手指从它当前的位置移动过去并按下，代价是两点间的**曼哈顿距离**。求输完整个字符串的最小总移动距离。

**约束**：

- $2 \le \lvert word \rvert \le 300$
- `word[i]` 都是大写英文字母

## 2. 示例

**示例 1**

```text
输入：word = "CAKE"
输出：3
解释：手指 1：C -> A，距离 |0-0| + |2-0| = 2；
      手指 2：起手直接落在 K（代价 0），再 K -> E，距离 |1-0| + |4-4| = 1；
      总距离 = 2 + 1 = 3。
```

**示例 2**

```text
输入：word = "HAPPY"
输出：6
解释：手指 1：H -> A（2），再 A -> Y（|0-4| + |0-0| = 4）；
      手指 2：起手落在 P（0），P -> P（0）；
      总距离 = 2 + 4 + 0 + 0 = 6。
```

## 3. 解题思路

### 3.1 暴力思路

**枚举分工**：每个字符都有「手指 1 按」或「手指 2 按」两种选择，共 $2^n$ 种分工；每种分工沿各自手指的顺序累加距离，$O(n)$ 求值。总复杂度 $O(2^n n)$，$n$ 最大 $300$，天文数字。

**贪心不成立**：「每一步都交给离目标字母更近的那根手指」会在示例 1 上算出 4：它让手指 2 免费落在第二个字母 `A` 上，后面 `K` 只能由手指 1 从 `C` 移动（3），再 `K -> E`（1），合计 4；而最优解让手指 1 连打 `C`、`A`（2），把手指 2 的**免费落点**留给 `K`，总代价只有 3。免费落点该留给谁，是全局决策，贪心看不到。

**朴素的 DP**：官方提示给出的 $dp[i][j][k]$ 表示「两指分别在字母 $j$、$k$，已输入前 $i$ 个字符」，状态量 $n \times 26^2 \approx 2 \times 10^5$，能过但明显冗余。

### 3.2 核心观察：活动手指一定停在 word[i] 上

![键盘布局与曼哈顿距离](images/wc171_q4_keyboard_layout.svg)

字符必须**按顺序**输入，所以 `word[i]` 一定是被某根手指刚刚按下的：按下这一瞬间，那根手指就停在 `word[i]` 上。于是任意时刻（处理完前缀 `word[0..i]` 后）两指的分布必然是

$$
(\text{活动手指} = word[i],\ \text{另一根手指} = j),\qquad j \in \{0,1,\dots,25\}
$$

其中 $j$ 可以是任意字母（两指重合也合法）。而三维状态 $(j,k)$ 里只有「其中一个恰为 `word[i]`」的那些才真正可达，其余绝大部分是死状态：真正自由的只有 $j$ 这**一维**，状态量从 $n \times 26^2$ 降到 $n \times 26$。

**起手的处理**：输入第一个字符 `word[0]` 之前不算任何移动，等价于「手指 1 落在 `word[0]`，手指 2 落在任意 $j$，代价都是 $0$」，所以初值是

$$
dp[j] = 0 \quad (j = 0,1,\dots,25)
$$

这也解释了题面那句「两根手指的起始位置不必从首字母或前两个字母开始」：手指 2 甚至可以一直不动，留到最后一个字符才用。

### 3.3 状态转移

![状态设计与两条转移](images/wc171_q4_state_design.svg)

设当前状态为 $dp[j]$（已输入 `word[0..i]`，活动手指在 `word[i]`，另一指在 $j$），下一个字符 $c = word[i+1]$。按下 $c$ 的手指只有两种可能：

1. **同一根手指继续**：活动手指从 `word[i]` 移到 $c$，另一指仍在 $j$，新状态 $(i+1,\ j)$：

$$
dp'[j] = dp[j] + d(word[i], c)
$$

2. **换手**：停在 $j$ 的手指移向 $c$，移动完后活动手指换成它，原来那根留在 `word[i]`，新状态 $(i+1,\ word[i])$：

$$
dp'[word[i]] = \min_{0 \le j < 26}\bigl(dp[j] + d(j, c)\bigr)
$$

两条转移合起来覆盖了全部可能，答案为 $\min_j dp[j]$（全部字符打完，另一根手指无需再动）。

其中

$$
d(a,b) = \left\lvert \left\lfloor \frac{a}{6} \right\rfloor - \left\lfloor \frac{b}{6} \right\rfloor \right\rvert + \left\lvert (a \bmod 6) - (b \bmod 6) \right\rvert
$$

### 3.4 示例演算

![CAKE 的一维 DP 走查](images/wc171_q4_walkthrough.svg)

以 `word = "CAKE"` 为例，只列出关键的 $j$：

| 已输入 | 活动手指 | 另一手指 $j \to dp[j]$ | $\min$ |
|--------|----------|------------------------|--------|
| `C` | `C` | $dp[j]=0$（任意 $j$，起手免费） | 0 |
| `CA` | `A` | $dp[C]=0$（手指 2 起手就落在 `A` 上，零代价），其余 $2$ | 0 |
| `CAK` | `K` | $dp[A]=2$，$dp[C]=5$，其余 $7$ | 2 |
| `CAKE` | `E` | $dp[A]=3$，$dp[C]=6$，$dp[K]=6$，其余 $8$ | 3 |

逐行看：

- **C**：一根手指按 `C`，另一根随意，代价 $0$。
- **CA**：若手指 1 从 `C` 移到 `A`，所有 $dp[j]$ 变成 $2$；若手指 2 从某个 $j$ 直接落到 `A`（$j=A$ 时距离 $0$），则 $dp[C] = 0$，更优。
- **CAK**：换手候选 $\min_j(dp[j] + d(j,K)) = 0 + d(C,K) = 3$ 或 $2 + 0 = 2$（$j=K$ 时手指 2 从 `K` 直接按下，零距离），取 $2$ 更新 $dp[A]$；同指继续则是 $dp[j] + d(A,K) = dp[j] + 5$。
- **CAKE**：换手候选 $\min(2 + d(A,E),\ 5 + d(C,E),\ 7 + d(K,E)) = \min(6, 7, 8) = 6$，落到 $dp[K]$；同指继续把 $dp[A]$ 推到 $2 + 1 = 3$。取全局最小得 **3**。

## 4. 算法细节

1. **字母编号**：`idx = c - 'A'`，坐标 `(idx/6, idx%6)`。末行 `Y=24`、`Z=25` 分别落在 $(4,0)$、$(4,1)$，公式天然正确——千万别按「5 列」或「6 行」去想。
2. **预处理距离表**：先算 $26 \times 26$ 的 `dist[a][b]`，转移里就只有两次查表加法；也可以像参考代码那样写成 `lambda`（$O(1)$ 计算）。
3. **状态语义只记另一根手指**：$dp[j]$ 中的活动手指位置由下标 $i$ 隐含，不要显式存。
4. **初值**：$dp[0..25]$ 全部为 $0$。若写成「只有 $dp[word[0]]=0$、其余 $\infty$」，等于禁止手指 2 停在尚未用过的字母上，答案会偏大（例如 `"AAAE"` 会从 $0$ 变成 $4$）。
5. **滚动更新顺序**：必须先把上一轮 $dp$ 拷成 $ndp$，两条转移都基于旧值；换手项要在同一个循环里用旧 $dp$ 求出最小值 $best$，最后 $ndp[word[i]] = \min(ndp[word[i]], best)$，不要在原数组上就地改。
6. **无穷大取 $10^9$**：真实答案上界是 $10(n-1) \le 2990$；用 `INT_MAX` 做加法会溢出。
7. **答案是 $\min_j dp[j]$**：最后一个字符打完就结束，另一根手指停在哪里都不再产生代价。

## 5. 正确性证明

**引理 1（活动手指不变量）**：任何合法方案在输入完 `word[0..i]` 的瞬间，至少有一根手指位于字母 `word[i]` 上。

**证明**：字符按顺序输入，`word[i]` 必由某根手指按下；手指按下后若不移动，它就停在 `word[i]`。若方案在按下后立刻移动它，可以把这段移动推迟到「下次真正需要它按键」时执行，起点终点相同、路径与代价不变，因此总存在一个「按下后即可视为停住」的等价方案。∎

**引理 2（无后效性）**：若两个方案在输入完 `word[0..i]` 后，活动手指都在 `word[i]`、另一根手指都在 $j$，则它们补全后缀 `word[i+1..n-1]` 的最小追加代价相同。

**证明**：后缀的输入过程只与两指当前位置和待输入字符串有关；任意一段后续动作的代价只由它的起点与落点决定，与如何到达该起点无关。∎

**引理 3（转移完备）**：从状态 $(i, j)$ 输入 $c = word[i+1]$，合法的下一步只有两种——活动手指移向 $c$（代价 $d(word[i], c)$，新状态 $(i+1, j)$），或另一根手指从 $j$ 移向 $c$（代价 $d(j, c)$，新状态 $(i+1, word[i])$）。

**证明**：$c$ 必须由两根手指之一按下，二者互斥且穷尽；按下后该手指位于 $c$，另一根保持原位不动。由引理 1，新状态的活动手指是 $c$，另一根手指分别保持 $j$ 或变为 `word[i]`。∎

**定理**：按上述初值与转移迭代，$dp^{(i)}[j]$ 等于「已输入 `word[0..i]`、活动手指在 `word[i]`、另一指在 $j$」的所有方案中的最小总代价；算法返回的 $\min_j dp^{(n-1)}[j]$ 就是题目所求的最小总移动距离。

**证明**：对 $i$ 归纳。$i = 0$ 时 $dp[j] = 0$：手指 1 置于 `word[0]`、手指 2 置于 $j$，两指起手均免费，代价 $0$，已是最小可能值。设 $i$ 时结论成立。任取输入完 `word[0..i+1]` 的最优方案，删去「按下 `word[i+1]`」这一步，得到输入完 `word[0..i]` 的方案，其代价不小于 $dp^{(i)}[j^*]$（$j^*$ 是该方案此刻另一指的位置）；由引理 3，该方案的最后一步属于两条转移之一，于是它的总代价不小于转移式给出的值，即 $dp^{(i+1)}$ 是下界；反之对每个 $j$ 取达到 $dp^{(i)}[j]$ 的方案再接上对应的那一步，就得到 $dp^{(i+1)}$ 的一个可行方案，故又是上界。上下界相等，归纳成立。最后，全部字符输入完毕后不必再移动手指，故最小代价即 $\min_j dp^{(n-1)}[j]$。∎

## 6. 复杂度分析

- **时间**：$O(26n)$。每一轮对 $26$ 个字母各做常数次距离计算与取 $\min$，共 $n-1$ 轮；距离若预处理成表，额外 $O(26^2)$。$n \le 300$ 时约 $8 \times 10^3$ 次运算。
- **空间**：$O(26)$。只需两行长度为 $26$ 的数组（滚动数组）；若预处理距离表再占 $O(26^2)$，仍是常数。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <algorithm>
#include <cstdlib>
using namespace std;

class Solution {
public:
    int minimumDistance(string word) {
        int n = (int)word.size();
        // 字母 a 的坐标：(a / 6, a % 6)，曼哈顿距离
        auto dis = [](int a, int b) {
            return abs(a / 6 - b / 6) + abs(a % 6 - b % 6);
        };
        const int INF = 1000000000;
        // dp[j]：已输入 word[0..i]，活动手指在 word[i]，另一根手指在 j 的最小代价
        // 起手免费：打完 word[0] 后另一根手指可在任意字母上，代价 0
        vector<int> dp(26, 0);
        for (int i = 1; i < n; ++i) {
            int prev = word[i - 1] - 'A';
            int cur  = word[i] - 'A';
            vector<int> ndp(26, INF);
            int bestSwitch = INF;                 // 换手：另一根手指从 j 移到 cur
            for (int j = 0; j < 26; ++j) {
                ndp[j] = min(ndp[j], dp[j] + dis(prev, cur));      // 同一根手指继续
                bestSwitch = min(bestSwitch, dp[j] + dis(j, cur));
            }
            ndp[prev] = min(ndp[prev], bestSwitch);                // 新状态：(i+1, prev)
            dp.swap(ndp);
        }
        return *min_element(dp.begin(), dp.end());
    }
};
```

### Python

```python
class Solution:
    def minimumDistance(self, word: str) -> int:
        def dis(a: int, b: int) -> int:
            return abs(a // 6 - b // 6) + abs(a % 6 - b % 6)

        INF = 10 ** 9
        # dp[j]：已输入 word[0..i]，活动手指在 word[i]，另一根手指在 j 的最小代价
        dp = [0] * 26                      # 起手免费，另一根手指可在任意字母上
        for i in range(1, len(word)):
            prev = ord(word[i - 1]) - ord('A')
            cur = ord(word[i]) - ord('A')
            ndp = [INF] * 26
            best_switch = INF
            for j in range(26):
                ndp[j] = min(ndp[j], dp[j] + dis(prev, cur))       # 同一根手指继续
                best_switch = min(best_switch, dp[j] + dis(j, cur))
            ndp[prev] = min(ndp[prev], best_switch)                # 换手
            dp = ndp
        return min(dp)
```

## 8. 边界情况与易错点

1. **长度为 2**：两个字符可以分别由两根手指零代价按下，答案恒为 $0$。初值全 $0$ 时，第二轮转移会自然得到 $0$，无需特判。
2. **免费落点可以推迟**：`"AAAE"` 的答案是 $0$——手指 1 从头到尾打 `A`（距离 $0$），手指 2 起手就停在 `E`，直到最后一个字符才用。若初值只把 `dp[word[0]]` 设为 $0$，这组会错算成 $4$。
3. **允许两指重合**：$j$ 可以等于 `word[i]`，也可以等于 `cur`，不要加「两指不能在同一键上」的限制，否则会丢掉「同一根手指连续打同一个字母」之外的合法状态。
4. **滚动数组的就地更新**：若直接写 `dp[prev] = min(dp[prev] + d(prev,cur), ...)` 后再让循环读 `dp[j]`，读到的是被污染的旧轮数据；必须先算 `ndp` 再整体替换。
5. **无穷大与溢出**：答案上界约 $2990$，用 `int` 足够；但把 $dp$ 初值设成 `INT_MAX` 再做 `+ dis(...)` 会溢出为负，取 $10^9$ 更稳。
6. **键盘行宽写错**：本题是 6 列布局但末行只有 2 个字母，`row = idx/6`、`col = idx%6` 必须配合「按行优先、每行 6 个」的编号；若误以为末行补齐、或按 5 列编号，`P`、`Z` 的坐标全错，示例 1 立刻对不上。
7. **重复字母**：`d(x,x) = 0`，`"HAPPY"` 里两个 `P` 之间不产生代价，别把「换手」误写成必须有正距离。
