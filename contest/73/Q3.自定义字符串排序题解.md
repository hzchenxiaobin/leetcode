# LeetCode 自定义字符串排序 题解

## 1. 题目概述

- **标题 / 题号**：自定义字符串排序（#791，medium）
- **链接**：https://leetcode.cn/problems/custom-sort-string/
- **来源**：LeetCode 第 73 场周赛 Q3
- **难度**：中等
- **标签**：哈希表，字符串，排序，计数排序

**题意**：给定字符串 `order` 与 `s`。`order` 中的字符互不相同，且已按某种**自定义顺序**排好。要求重排 `s` 的字符得到 `t`，使得：对 `order` 中任意两个字符 $x,y$，若 $x$ 在 `order` 中出现在 $y$ 之前，则 $x$ 在 `t` 中也出现在 $y$ 之前。**不在 `order` 中的字符位置完全自由**。返回任意一个满足条件的 `t`。

**约束**：

- $1 \le \lvert \text{order} \rvert \le 26$
- $1 \le \lvert s \rvert \le 200$
- `order` 与 `s` 均只含小写英文字母
- `order` 中所有字符**互不相同**

> 💡 本题是**输出型判题**：只要答案合法即通过。读题时不要误以为必须输出与示例完全相同的那一个排列——示例里的 `"dcba"`、`"cdba"` 同样正确。不过若按「名次升序 + 剩余按字母序」输出，恰好会与官方示例逐字符一致，便于本地对拍。

## 2. 示例

**示例 1**

```text
输入：order = "cba"，s = "abcd"
输出："cbad"
解释：a、b、c 都在 order 中出现，它们的先后必须与 order 一致，即 c → b → a。
      d 不在 order 中，位置任意，因此 "dcba"、"cdba"、"cbda" 也都是合法输出。
```

**示例 2**

```text
输入：order = "bcafg"，s = "abcd"
输出："bcad"
解释：order 中的 b、c、a 决定了 s 里这三个字符的次序为 b → c → a。
      order 中的 f、g 在 s 中不存在，不起作用；
      d 不在 order 中，位置自由。故 "bca" + "d" = "bcad" 合法。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举 `s` 的全部排列，对每个排列用 $O(n)$ 检查所有 `order` 约束，复杂度 $O(n! \cdot n)$。当 $n = 200$ 时天文数字，完全不可行。

退一步的「暴力升级版」：把 `order` 变成**优先级表**，即 `rank[c]` 表示 `c` 在 `order` 中的下标（不在 `order` 中的字符记作 26），然后对 `s` 用带自定义比较器的 `sort` 排序，得到 $O(n \log n)$ 的可行解。

这一步已经能过题，但它**忽略了题目的关键结构**：优先级只有 $\lvert \text{order} \rvert + 1 \le 27$ 种取值，字符集只有 26 个小写字母。**键的种类数极小**，意味着可以用「计数」代替「比较」，把 $O(n\log n)$ 压到 $O(n)$——这正是计数排序（桶排序）的适用条件。

> 💡 本场的取舍点：能不能识别出「排序键的取值范围是常数」，从而用计数排序把一次 `sort` 换成两次线性扫描。

### 3.2 核心观察：名次键 + 计数排序

![名次键与计数桶模型](images/wc73_q3_rank_key_model.svg)

定义**名次键**

$$\text{key}(c)=\begin{cases} \text{index}(c), & c \in \text{order}\\ 26\ (\infty), & c \notin \text{order}\end{cases}$$

其中 $\text{index}(c) \in [0, 25]$ 是 $c$ 在 `order` 中从左往右数的下标。

于是「`t` 合法」可以翻译成一个关于键序列的论断：

- **充分方向**：若 `t` 中所有 $c \in \text{order}$ 的字符按 key 升序出现（也就是它们的相对次序与 `order` 完全一致），则 `t` 合法——因为题目施加约束的**只有**「同在 `order` 中的字符对」。
- **构造方向**：把 `s` 里属于 `order` 的字符按 key 升序全部输出，再把剩下的字符接在末尾，一定合法。原因是第一段内部已满足所有约束，而第二段的字符不与任何字符产生约束。

所以根本不需要真的排序：**第一段就是「按 `order` 顺序把每个桶倒空」，第二段就是「把 key $=26$ 的桶倒空」**。同一字符落在同一个桶里，桶内元素完全相同，连「稳定性」都不必操心。

![算法流程](images/wc73_q3_counting_flow.svg)

### 3.3 算法流程

1. 开一个长度 26 的数组 `freq`，遍历 `s` 统计每个字符的出现次数；
2. 准备空串 `res`，按 `order` 从左到右遍历字符 `c`：若 `freq[c] > 0`，把 `c` 重复 `freq[c]` 次追加到 `res`，然后令 `freq[c] = 0`（标记「已消费」）；
3. 按 `'a'` 到 `'z'` 扫描 `freq`，遇到 `freq[c] > 0` 的字符就把它重复 `freq[c]` 次追加到 `res`（这就是 key $=26$ 的桶，内部顺序任意）；
4. 返回 `res`。

第 2 步的循环对 `order` 中每个字符只做一次 $O(1)$ 的判空与 $O(\text{freq})$ 的追加，第 3 步固定只扫 26 个桶，因此总开销与「排序」无关，只与字符串长度线性相关。

### 3.4 示例演算

![示例演算走查](images/wc73_q3_walkthrough.svg)

对 `order = "cba"`、`s = "abcd"`：初始 `freq = {a:1, b:1, c:1, d:1}`，按 `order` 依次取出 `c`、`b`、`a`，每个桶只含 1 个字符，`res` 依次变成 `"c"` → `"cb"` → `"cba"`；收尾阶段只剩 `d` 未被消费，追加得 `"cbad"`。

再看 `order = "bcafg"`、`s = "abcd"`，按 `order` 的名次，`b` 是 0、`c` 是 1、`a` 是 2、`f` 是 3、`g` 是 4（`d` 不在 `order` 中，名次为 26）：

| 轮次 | 取出的桶 | 追加片段 | `res` |
|------|----------|----------|--------|
| 1 | `b` | `"b"` | `"b"` |
| 2 | `c` | `"c"` | `"bc"` |
| 3 | `a` | `"a"` | `"bca"` |
| 4、5 | `f`、`g` | 空（`freq = 0`） | `"bca"` |
| 收尾 | `d` | `"d"` | `"bcad"` |

`f`、`g` 两轮虽然访问了桶，但桶是空的，什么也不输出——这正是「`if freq` 判空」不可省略的原因。

## 4. 算法细节

1. **用定长数组而非哈希表**：字符集固定为 26 个小写字母，`int freq[26]` 的下标运算比 `unordered_map` 更快，也没有哈希冲突与扩容开销，空间是常数。
2. **「消费」必须清零**：追加完 `c` 的 `freq[c]` 份后立刻令 `freq[c] = 0`，否则收尾阶段会把 `order` 中的字符**再输出一遍**，结果长度超过 $\lvert s \rvert$。
3. **追加前判空**：`freq[c] == 0` 时不能调用追加（C++ 的 `append(0, c)` 虽无害，但 Python 里 `c * 0` 会产生空串，逻辑上容易让人误判），显式判空也更清晰。
4. **拼接方式决定常数**：C++ 先 `res.reserve(s.size())` 再 `res.append(cnt, ch)`；Python 用 `list` 收集字符串片段，最后 `"".join(parts)`，避免 `res += ch` 造成 $O(n^2)$ 的重复拷贝。
5. **收尾阶段的顺序**：题目允许任意，实现里按 `'a'` 到 `'z'` 输出，好处是**输出确定**，便于与暴力对拍、复现官方示例。
6. **`order` 可以短于 26**：此时 `order` 循环只消费部分桶，剩余桶留到收尾阶段，顺序天然合法（它们之间毫无约束），这一点正是引理 2 保证的。
7. **长度自检**：返回串长度必然等于 $\lvert s \rvert$，可用作调试断言；若不等，几乎一定是漏了清零或漏了第一段。

## 5. 正确性证明

先明确约束集合：题目只要求「同时出现在 `order` 中的字符对」保持相对次序。据此定义 $\text{key}(c)$ 如 §3.2。

**引理 1（约束只发生在 `order` 内部）**：设 `t` 是 `s` 的一个排列。若对任意 $x, y \in \text{order}$，$\text{key}(x) < \text{key}(y)$ 都有 $x$ 在 `t` 中位于 $y$ 之前，则 `t` 合法。

**证明**：题目的要求是「对任意 $x$ 在 `order` 中先于 $y$，`t` 中 $x$ 也必须先于 $y$」。而「$x$ 在 `order` 中先于 $y$」等价于 $x, y \in \text{order}$ 且 $\text{key}(x) < \text{key}(y)$——只要 $x \notin \text{order}$，它就不与任何字符构成需要满足的约束。因此前提条件恰好覆盖了全部约束，结论成立。∎

**引理 2（构造合法）**：设 $A = \{c \in \text{order} : \text{freq}_s(c) > 0\}$，$B = \{c \in s : c \notin \text{order}\}$。把 $A$ 中的字符按 key 升序依次重复 $\text{freq}_s(c)$ 次输出，再任意输出 $B$ 中的字符，得到的串 `t` 合法。

**证明**：任取 $x, y \in \text{order}$ 且 $\text{key}(x) < \text{key}(y)$。若两者都在 `t` 中出现，则它们都属于 $A$，且按 key 升序输出，故 $x$ 的全部副本都排在 $y$ 的全部副本之前，$x$ 先于 $y$，满足引理 1 的前提。∎

**定理（算法正确）**：`customSortString` 返回的 `res` 是 `s` 的合法排列。

**证明**：分两步。

1. **结构合法**：`order` 循环恰好按 key 升序访问了 `order` 中的全部字符（顺序由 `order` 自身给出），且仅当 `freq[c] > 0` 时才输出，输出内容是把 `c` 重复 $\text{freq}_s(c)$ 次；收尾循环输出的字符要么不在 `order` 中，要么是 `order` 中 `freq` 已为 0 的字符（此时重复 0 次，不输出）。因此 `res` 的结构正好是「$A$ 按 key 升序 → $B$」，由引理 2 知 `res` 合法。
2. **计数正确**：对 $c \in \text{order}$，第一段输出 $\text{freq}_s(c)$ 份后立即清零，第二段不再输出；对 $c \notin \text{order}$，第一段不触碰，第二段输出 $\text{freq}_s(c)$ 份。故每个字符在 `res` 中的出现次数都等于它在 `s` 中的出现次数。

由第 1 步合法、第 2 步为排列，两条合起来即得 `res` 是 `s` 的合法排列。∎

**推论（长度）**：由计数正确性立得 $\lvert \text{res} \rvert = \sum_c \text{freq}_s(c) = \lvert s \rvert$，即 `res` 是排列而非子序列。

## 6. 复杂度分析

- **时间**：$O(\lvert s \rvert + \lvert \text{order} \rvert + 26) = O(\lvert s \rvert)$。统计 `freq` 一遍 $O(\lvert s \rvert)$；`order` 循环 $O(\lvert \text{order} \rvert)$ 次判空 + 全部追加合计 $O(\lvert s \rvert)$；收尾固定扫描 26 个桶；拼接本身也是线性的。由于 $\lvert \text{order} \rvert \le 26$，总时间是严格线性的，比 `sort` 的 $O(n \log n)$ 更优。
- **空间**：除输出外 $O(1)$——`freq` 只占 26 个整数。若把返回串计入，则为 $O(\lvert s \rvert)$，且这是任何输出型问题都无法避免的下界（`reserve` / `join` 也只是同阶）。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string customSortString(string order, string s) {
        int freq[26] = {0};
        for (char ch : s) freq[ch - 'a']++;      // ① 统计频次

        string res;
        res.reserve(s.size());                   // ② 预留容量，避免反复扩容
        for (char ch : order) {                  // ③ 按 order 的名次依次倒空桶
            int &c = freq[ch - 'a'];
            if (c > 0) {
                res.append(c, ch);
                c = 0;                           // ④ 已消费，必须清零
            }
        }
        for (int i = 0; i < 26; i++)             // ⑤ 收尾：key = ∞ 的桶
            if (freq[i] > 0) res.append(freq[i], (char)('a' + i));
        return res;
    }
};
```

### Python

```python
class Solution:
    def customSortString(self, order: str, s: str) -> str:
        freq = [0] * 26
        for ch in s:                              # ① 统计频次
            freq[ord(ch) - 97] += 1

        parts = []
        for ch in order:                          # ③ 按 order 的名次依次倒空桶
            i = ord(ch) - 97
            if freq[i] > 0:
                parts.append(ch * freq[i])        # ④ 一次成型，避免 += 的 O(n²)
                freq[i] = 0                       # 已消费，必须清零

        for i in range(26):                       # ⑤ 收尾：key = ∞ 的桶
            if freq[i] > 0:
                parts.append(chr(97 + i) * freq[i])
        return "".join(parts)                     # ⑥ 线性拼接
```

## 8. 边界情况与易错点

1. **`order` 里的字符在 `s` 中不存在**（如 `order = "bcafg"` 中的 `f`、`g`）：`freq` 为 0，必须判空后再追加，否则会凭空多输出字符，答案长度超过 $\lvert s \rvert$。
2. **忘记把 `freq` 清零**：`order` 中的字符会在收尾阶段被再输出一次，长度超标。这是本题最高频的错误，写完最好加一句「返回串长度应等于 `s` 长度」的断言。
3. **`s` 的字符全都不在 `order` 中**（如 `order = "a"`、`s = "bbbb"`）：`order` 循环空转，全部由收尾阶段输出，按实现结果是「剩余字符按字母序」，输出确定、便于复现。
4. **`s` 为空串或单字符**（LeetCode 实际数据满足 $\lvert s \rvert \ge 1$）：两个循环对空串天然安全（返回空串），无需特判；但若手动加特判，注意别在特判分支里返回未初始化的变量或访问 `s[0]`。
5. **Python 用 `res += ch` 累积**：字符串不可变，循环里累加退化为 $O(n^2)$；必须用 `list` + `"".join`。
6. **本地对拍别逐字符比期望值**：本题是「任意合法排列」判题，除非双方都用相同的收尾顺序（都按 `'a'`→`'z'`），否则两个都正确的答案可能不相等。这也是本题官方示例的期望输出恰好等于「名次升序 + 剩余按字母序」规范形式的原因。
7. **字符集写死为 26**：若题目扩展到 ASCII 或含大写字母，`26` 必须改成 `128`，且 `'a'` 基准与收尾循环上界要同步修改。

**延伸思考**：若额外要求「不在 `order` 中的字符**保持它们在 `s` 中的原始相对顺序**」，解法要升级为**稳定**的计数排序：先按 `order` 的名次分组，再让 key $=26$ 的字符按在 `s` 中的原始下标排列——此时不能只存频次，得按字符收集下标，复杂度仍是 $O(\lvert s \rvert)$，但要额外 $O(\lvert s \rvert)$ 的桶。更一般地，若把约束从「一条链」换成任意的「$x$ 必须先于 $y$」列表，问题就变成**在偏序下求任一合法线性扩序**，需要拓扑排序；本题之所以能用计数排序一步到位，正是因为约束图是一条链（外加一批孤立顶点），链上的顺序已由 `order` 直接给出，无需再做拓扑排序。如果再要求**字典序最小**的合法排列，则在链 + 孤立点的结构下，每步贪心选「当前可放的最小字符」即可，可用频次数组 + 「下一个可放名次」指针维护，仍是线性的。
