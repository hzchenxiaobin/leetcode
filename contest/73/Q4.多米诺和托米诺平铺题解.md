# LeetCode 多米诺和托米诺平铺 题解

## 1. 题目概述

- **标题 / 题号**：多米诺和托米诺平铺（#790，medium）
- **链接**：https://leetcode.cn/problems/domino-and-tromino-tiling/
- **来源**：LeetCode 第 73 场周赛 Q4
- **难度**：中等
- **标签**：动态规划

**题意**：有两种瓷砖——$2 \times 1$ 的**多米诺**（可横放、可竖放）和形如 `L` 的**托米诺**（$2 \times 2$ 方块去掉一格，共 4 种朝向）。用它们无缝铺满 $2 \times n$ 的面板，每个格子恰好被一块瓷砖覆盖，求方案数对 $10^9 + 7$ 取模的结果。

两种铺法不同，当且仅当存在一对四方向相邻的格子，在这一种铺法里被同一块瓷砖盖住，在另一种里不是。也就是说，这里比较的是**瓷砖划分方式**，而不是"哪块砖放在哪"。

**约束**：

- $1 \le n \le 1000$
- 答案需要对 $10^9 + 7$ 取模

## 2. 示例

**示例 1**

```text
输入：n = 3
输出：5
解释：五种铺法拆开看是
      (1) 3 块竖砖；(2) 左侧一对横砖 + 1 块竖砖；
      (3) 1 块竖砖 + 右侧一对横砖；(4)(5) 两块 L 互相咬合（左右镜像）。
```

**示例 2**

```text
输入：n = 1
输出：1
解释：只能竖放一块多米诺。
```

**示例 3（补充，便于对照递推）**

```text
输入：n = 2
输出：2
解释：2 块竖砖，或 1 对横砖。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是从左上角开始 DFS，枚举每个空格上能放的瓷砖。可行，但方案数本身就是答案：由后文的递推可知它按 $\lambda^n$ 增长，其中 $\lambda \approx 2.2056$ 是 $x^3 = 2x^2 + 1$ 的最大实根，$n = 1000$ 时约为 $10^{343}$ 量级，枚举完全不可能。

另一个常见设想是"状压 DP"：把每个格子的占用情况压成掩码。但 $2 \times n$ 面板按格压缩需要 $2^n$ 个状态，同样爆炸。真正的出路是**按列推进**并合并等价状态。

### 3.2 核心观察：边界只有两种形态

![瓷砖两种与两种边界形态](images/wc73_q4_tile_shapes.svg)

所有瓷砖都只跨越**相邻两列**，所以可以像扫雪一样从左往右推：每次取**最左边的未覆盖格**，用它所在的那块瓷砖把它盖住。这样"已铺完的区域"和"还没铺的区域"之间的边界就非常有限：

- $A_k$（整齐竖切）：前 $k$ 列完全铺满，第 $k+1$ 列及之后一格都没碰过；
- $H_k$（一个台阶）：前 $k$ 列铺满，并且第 $k+1$ 列的**上格**已被占用、下格还空着。

**为什么不可能出现更复杂的边界？** 因为一旦某块 L 形把相邻两列都占了、却在本列留下一个空格，这个空格就永远补不上——竖砖需要同列另一格空闲，横砖和 L 形都需要右侧同行的格子空闲，而那些格子都已被同一块 L 占掉。所以"台阶"最多只有一级，且只在一个方向上。

### 3.3 五条合法转移与两个递推式

![双状态转移与递推式](images/wc73_q4_state_transition.svg)

从 $A_k$ 出发，覆盖第 $k+1$ 列的最左格（上格）：

1. **竖放一块多米诺**：占满第 $k+1$ 列 → $A_{k+1}$，$1$ 种；
2. **横放两块多米诺**：第 $k+1$、$k+2$ 列各放一横 → $A_{k+2}$，$1$ 种；
3. **L 形，两格在第 $k+1$ 列**：第三格落在第 $k+2$ 列，可以在上也可以在下 → $H_{k+1}$，$2$ 种。

从 $H_k$ 出发（第 $k+1$ 列上格已占，只剩**下格**）：

4. **横放一块多米诺**补下格并伸到第 $k+2$ 列 → $H_{k+1}$，$1$ 种；
5. **L 形**：补下格的同时占满第 $k+2$ 列两格 → $A_{k+2}$，$1$ 种。

还有一类**看着可行、其实是死路**的放法：L 形把一格放在第 $k+1$ 列、两格放在第 $k+2$ 列。它把第 $k+2$ 列占满，于是第 $k+1$ 列剩下的那一格既不能用竖砖（同列上格已占）、也不能用横砖或 L（右侧同行格子已被占），永远补不完，贡献 $0$——这正是 $A_k$ 只有三类去向的原因。

于是（$H_k$ 只统计"上台阶"这一种朝向，镜像方向同数）：

$$A_k = A_{k-1} + A_{k-2} + 2H_{k-2}, \qquad H_k = A_{k-1} + H_{k-1}$$

边界：$A_0 = 1$（空板算一种铺法），$A_1 = 1$，$H_0 = 0$，$H_1 = 1$（第一列两块加第二列上格，正好一块 L）。

**消去 $H$**：把第一式对 $k+1$ 写一遍，减去对 $k$ 的那一式，中间用 $H_k = A_{k-1} + H_{k-1}$ 把 $2H_{k-1}$ 换成 $2A_{k-2} + 2H_{k-2}$，就有

$$A_{k+1} - A_k - A_{k-1} = 2A_{k-2} + \bigl(A_k - A_{k-1} - A_{k-2}\bigr)$$

整理即 $A_{k+1} = 2A_k + A_{k-2}$，也就是

$$A_n = 2A_{n-1} + A_{n-3} \quad (n \ge 3)$$

### 3.4 示例演算

![递推演算表](images/wc73_q4_walkthrough.svg)

| $k$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|-----|---|---|---|---|---|---|---|
| $A_k$ | 1 | 1 | 2 | 5 | 11 | 24 | 53 |
| $H_k$ | 0 | 1 | 2 | 4 | 9 | 20 | 44 |

抽查第 3 行：$A_2 + A_1 + 2H_1 = 2 + 1 + 2 = 5$，与示例 1 的 $n = 3$ 一致。用消元式交叉验证：$A_4 = 2A_3 + A_1 = 10 + 1 = 11$、$A_5 = 2A_4 + A_2 = 22 + 2 = 24$，两条路完全吻合。

## 4. 算法细节

1. **边界值要手写**：$A_0 = 1$、$A_1 = 1$、$A_2 = 2$。消元式 $A_n = 2A_{n-1} + A_{n-3}$ 只在 $n \ge 3$ 成立，若强行对 $n = 1, 2$ 套公式会读到 $A_{-1}, A_{-2}$。
2. **滚动三个变量**：递推只回头 $3$ 项，用 `a, b, c` 分别存 $A_{k-3}, A_{k-2}, A_{k-1}$，循环中整体右移即可，空间 $O(1)$。
3. **取模只做一次加法**：每步计算 `(2 * c + a) % MOD`。C++ 中 $2c \le 2 \times (10^9 + 6) < 2^{31}$，仍在 `int` 范围内，但用 `long long` 更稳妥、也不影响速度。
4. **$H$ 的等价定义**：由 $H_k = A_{k-1} + H_{k-1}$、$H_0 = 0$ 可得 $H_k = A_0 + A_1 + \cdots + A_{k-1}$，即 $A$ 的前缀和。如果不想推消元式，也可以一边算 $A$ 一边维护这个前缀和，复杂度同为 $O(n)$。
5. **系数 2 从哪来**：若把 $H_k$ 定义成"台阶在任意一侧"（把上下两种朝向合并计数），则递推变成 $A_k = A_{k-1} + A_{k-2} + H_{k-2}$、$H_k = 2A_{k-1} + H_{k-1}$，结果完全一致；两种写法不要混用，否则会漏乘或多乘 2。
6. **不必真的模拟棋盘**：状态里没有任何具体的瓷砖位置信息，只有"推到第几列"和"台阶朝哪边"，这是能压到一维递推的根本原因。

## 5. 正确性证明

**引理 1（边界封闭）**：按"每次覆盖最左未覆盖格"的顺序推进，任意中间时刻未铺区域只有 $A_k$、$H_k$ 两种形态。

**证明**：对推进步数归纳。初始为 $A_0$。设当前为 $A_k$，则第 $k+1$ 列两格都空、第 $k+2$ 列及之后未被触碰，覆盖第 $k+1$ 列上格的瓷砖只能产生引理 2 中列举的四种局面，其中合法的只有 $A_{k+1}$、$A_{k+2}$、$H_{k+1}$。设当前为 $H_k$，则覆盖第 $k+1$ 列下格的瓷砖：竖砖与朝上的横砖都要用到已占的上格，L 形的"两格在本列"朝向同样要用上格，只剩 3.3 节第 4、5 条的两种局面，得到 $H_{k+1}$ 或 $A_{k+2}$。故两种形态对转移封闭。∎

**引理 2（转移穷尽且互斥）**：覆盖最左未覆盖格的那块瓷砖，其类型与摆放位置只有竖砖、横砖对、L 形（两格在左列，上凸/下凸）、L 形（一格在左列、两格在右列）四类；在前三类中每一类都对应唯一的下一个状态，第四类必然留下无法覆盖的格子。

**证明**：瓷砖只有 $2 \times 1$ 与 $3$ 格的 L 两种，且都只跨相邻两列。含指定格子的摆放方式穷举如下：竖砖 $1$ 种；横砖 $1$ 种（必须成对使用，否则同列另一格无砖可用）；L 形共 $4$ 种朝向，其中两格在指定列的有 $2$ 种（第三格落在右侧列的上或下），一格在指定列、两格在右侧列的有 $2$ 种。最后一类会使右侧列被占满、而指定列的另一个格子之后再也找不到可用瓷砖，故不产生合法铺法。∎

**引理 3（递推成立）**：对 $k \ge 2$ 有 $A_k = A_{k-1} + A_{k-2} + 2H_{k-2}$，对 $k \ge 1$ 有 $H_k = A_{k-1} + H_{k-1}$。

**证明**：由引理 2，$A_{k}$ 的来源恰为：$A_{k-1}$ 竖放、$A_{k-2}$ 横放一对、$H_{k-2}$ 的两种朝向各用一块 L 收尾，合计 $A_{k-1} + A_{k-2} + 2H_{k-2}$；$H_{k}$ 的来源恰为：$A_{k-1}$ 的两种 L 朝向中对应这一朝向的 $1$ 种，以及 $H_{k-1}$ 横放 $1$ 种，合计 $A_{k-1} + H_{k-1}$。∎

**定理**：$A_n$ 等于 $2 \times n$ 面板的合法铺法数，且 $A_n = 2A_{n-1} + A_{n-3}$（$n \ge 3$）。

**证明**：由引理 1、2，任何一种铺法按"最左未覆盖格"的顺序唯一对应状态图 $A_0 \to \cdots \to A_n$ 上的一条路径，反之每条这样的路径也唯一还原出一种铺法（瓷砖由每步的选择唯一确定），故 $A_n$ 就是所求方案数。再由引理 3 的两式消去 $H$（推导见 3.3），得 $A_n = 2A_{n-1} + A_{n-3}$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。循环 $n - 2$ 次，每次只有一次乘法、一次加法和一次取模，均为 $O(1)$；$n \le 1000$ 时不到 $3000$ 次基本运算。
- **空间**：$O(1)$。只保留三个滚动变量（若改写成显式数组则为 $O(n)$，本题没有必要）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numTilings(int n) {
        const long long MOD = 1000000007LL;
        if (n == 1) return 1;
        if (n == 2) return 2;
        long long a = 1, b = 1, c = 2;      // A[k-3], A[k-2], A[k-1]
        for (int k = 3; k <= n; ++k) {
            long long d = (2 * c + a) % MOD;  // A[k] = 2A[k-1] + A[k-3]
            a = b; b = c; c = d;
        }
        return (int)c;
    }
};
```

### Python

```python
class Solution:
    def numTilings(self, n: int) -> int:
        MOD = 10 ** 9 + 7
        if n == 1:
            return 1
        if n == 2:
            return 2
        a, b, c = 1, 1, 2                   # A[k-3], A[k-2], A[k-1]
        for _ in range(3, n + 1):
            a, b, c = b, c, (2 * c + a) % MOD
        return c
```

## 8. 边界情况与易错点

1. **$n = 1$ 与 $n = 2$**：必须直接返回 $1$、$2$，否则递推会访问下标 $-1$ 的项。
2. **$A_0 = 1$ 而不是 $0$**：空板视为一种铺法，这样 $A_2 = A_1 + A_0 + 2H_0 = 2$ 才成立；写成 $0$ 会让所有项错位。
3. **只乘一个 2**：$A_k = A_{k-1} + A_{k-2} + 2H_{k-2}$ 里的 $2$ 来自台阶方向的镜像；若事先把 $H$ 定义成双向合计，这里的系数就要去掉，两处不能同时乘。
4. **别漏掉"死路"分支**：若把 L 形的四类朝向不加筛选地全部计入，会多算出实际无法铺完的路径（$n = 3$ 就会得到 $> 5$）。
5. **取模时机**：每一步都要取模，虽然 $n = 1000$ 时数字会膨胀到 $10^{343}$，Python 无所谓，C++ 必须每步取模防止溢出。

**延伸思考**：若 $n$ 放宽到 $10^{18}$，上面的 $O(n)$ 递推就不够用了，但 $A_n = 2A_{n-1} + A_{n-3}$ 是常系数线性递推，可以写成矩阵形式

$$\begin{pmatrix} A_n \\ A_{n-1} \\ A_{n-2} \end{pmatrix} = \begin{pmatrix} 2 & 0 & 1 \\ 1 & 0 & 0 \\ 0 & 1 & 0 \end{pmatrix} \begin{pmatrix} A_{n-1} \\ A_{n-2} \\ A_{n-3} \end{pmatrix}$$

再用快速幂做到 $O(\log n)$。若把面板换成 $3 \times n$ 或允许带孔的瓷砖，状态会从两种膨胀成多种掩码，思路不变：**先确定边界形态的封闭族，再对族内元素建转移**——这正是"轮廓线 DP"（broken profile DP）的通用套路。
