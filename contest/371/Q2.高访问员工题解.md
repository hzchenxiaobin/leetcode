# LeetCode 高访问员工 题解

## 1. 题目概述

- **标题 / 题号**：高访问员工（#2933，medium）
- **链接**：https://leetcode.cn/problems/high-access-employees/
- **来源**：LeetCode 第 371 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、排序

**题意**：给定二维字符串数组 `access_times`，每条记录是（姓名， 访问时间），时间用四位 24 小时制字符串 `"HHMM"` 表示，**所有记录都发生在同一天内**。若某员工在**同一小时内**访问系统**三次或更多**，则称其为**高访问员工**。以任意顺序返回所有高访问员工的姓名。题面对「同一小时」给了两条精确澄清：**恰好相差一小时不算**（如 `"0815"` 与 `"0915"`）；**一天首尾不环绕**（如 `"0005"` 与 `"2350"` 不算同一小时内）。

**约束**：

- $1 \le \text{access\_times.length} \le 100$
- $1 \le \text{access\_times}[i][0].\text{length} \le 10$，姓名仅由小写英文字母组成
- $\text{access\_times}[i][1]$ 是四位数字串，24 小时制

> 💡 读题胜负手：「同一小时」**不是钟点对齐的一小时**（如 05:00–06:00），而是**从任意分钟起算的滑动 60 分钟窗口**——示例 1 中 `a` 的 05:32 / 05:49 / 06:21 跨了两个钟点，却依然是高访问员工。识破这一点后，正解只剩三步：**哈希分组、转分钟排序、查相邻三元组跨度是否严格小于 60**。

```text
      但全部落在滑动窗口 [05:32, 06:31] 内（跨度 49 分钟 < 60），是高访问员工。
      "b" 只有两条记录，不算。
```

## 3. 解题思路

### 3.1 暴力思路与典型错误

**朴素暴力**：对每位员工的 $m$ 条记录枚举全部 $\binom{m}{3}$ 个三元组，检查「最大 − 最小 < 60」，每人 $O(m^3)$；或以每条记录为窗口起点数 60 分钟内的访问次数，每人 $O(m^2)$。$n \le 100$ 时都能过，但排序后一趟 $O(m)$ 扫描即可，纯属多余。

**⚠️ 更危险的典型错误**：把「同一小时」理解成**钟点小时**，按 `"HH"` 前两位分桶、统计每个钟点内次数 $\ge 3$。这个做法被示例 1 直接证伪：`a` 的三条记录被 05 时 / 06 时两个桶拆成 2 + 1 次，每个桶都不满 3，误判非高访问——**窗口是滑动的，不对齐钟点**。这是本题的第一读题陷阱。

### 3.2 核心观察：分组归约 + 滑动 60 分钟窗口

![核心观察：「同一小时」是任意起点的滑动 60 分钟窗口，不是钟点分桶](images/wc371_q2_sliding_window_concept.svg)

**观察 1（员工彼此独立）**：是否高访问只取决于该员工自己的时间序列，与其他员工无关。用**哈希表**按姓名分组，把混合的打卡流水归约为若干单人子问题——分组这步把大问题拆成了互不干扰的小问题。

**观察 2（同窗判定）**：三次访问同属某一小时 $\iff$ **最晚 − 最早 < 60 分钟**（严格小于）。半开窗口 $[t, t+60)$ 的视角把题面两条澄清一并解释清楚：`"0815"` 与 `"0915"` 恰好相差 60，落在窗口端点两侧，不算同窗；所有记录同一天，无跨天环绕，分钟值直接比较即可。

**观察 3（排序后最优三元组必相邻）**：排序为 $ts_0 \le ts_1 \le \cdots \le ts_{m-1}$ 后，若存在任一同窗三元组（即存在 $p < r$、$r \ge p+2$ 使 $ts_r - ts_p < 60$），取 $i = p + 2$ 便有

$$ts_i - ts_{i-2} \;\le\; ts_r - ts_p \;<\; 60$$

即**跨度最小的三元组一定取在相邻三个位置上**。于是判定只需扫一遍 $ts[i] - ts[i-2] < 60$，$O(m)$ 完成，无需枚举组合——与「排序后最小差必在相邻元素间产生」是同一原理。

**观察 4（HHMM 必须转分钟）**：`"HHMM"` 不是 60 进制数值——`"0910" − "0850"` 按数值算是 60，实际只差 20 分钟，直接拿四位数字做差必然判错。正确度量是 $HH \times 60 + MM$。

### 3.3 算法流程

![算法流程：分组、转分钟、排序、扫描相邻三元组](images/wc371_q2_algorithm_flow.svg)

1. **哈希分组**：遍历 `access_times`，把 `"HHMM"` 转成分钟值 $HH \times 60 + MM$，追加到以姓名为 key 的哈希表中；
2. **逐员工判定**：对其分钟列表**排序**，扫描 $i$ 从 2 到 $m-1$，若存在 $ts[i] - ts[i-2] < 60$（**严格小于**），该员工为高访问员工，记入答案，**命中即 break**；
3. **收集输出**：答案按字典序排序返回（题目允许任意顺序，排序只为与示例输出一致、便于核对）。

### 3.4 示例演算

![示例演算：示例 2 三位员工逐一走查](images/wc371_q2_example_walkthrough.svg)

以示例 2 为例逐员工走查：

| 员工 | 原始 HHMM | 排序后（分钟） | 相邻三元跨度 | 判定 |
|------|-----------|----------------|--------------|------|
| `c` | 0808 0829 0809 | 488 · 489 · 509 | $509 - 488 = 21 < 60$ | ✓ 高访问 |
| `d` | 0002 1508 1444 1410 | 2 · 850 · 884 · 908 | $884 - 2 = 882$ ✗；$908 - 850 = 58$ ✓ | ✓ 高访问 |
| `e` | 0215 | 135 | 不足 3 条，无三元组 | ✗ |

`d` 的细节最值得看：排序后为 $[2, 850, 884, 908]$，第一个三元组跨度 882 远超 60，第二个三元组 58 命中——**任意一个**相邻三元组满足即可，这正是「存在性」判定。再用示例 3 核边界：`ab` 排序后 625 · 680 · 684，跨度 59 差一分钟仍压线入窗；而 `"0815"` 与 `"0915"` 相差恰好 60，严格小于不成立，不算同窗。

## 4. 算法细节

1. **转分钟公式**：$t = HH \times 60 + MM$，即 `stoi(t.substr(0,2))*60 + stoi(t.substr(2))` / `int(t[:2])*60 + int(t[2:])`。所有比较都在分钟域进行。
2. **排序与判窗是两回事**：定长四位数字串的字典序等于数值序，**排序可以直接按字符串**做；但**判窗差值**必须用分钟值——排序可以偷懒，做差不能。
3. **严格小于**：条件是 $< 60$ 不是 $\le 60$，这是半开窗口 $[t, t+60)$ 的直接体现（`"0815"` 与 `"0915"` 的临界用例）。
4. **存在性短路**：`break` / `any` 命中即停，不必统计窗口内具体次数。
5. **不足 3 条**：循环从 $i = 2$ 起，列表长度 $< 3$ 时循环体不执行，自然判否，无需特判。
6. **数据结构**：`unordered_map<string, vector<int>>` / `defaultdict(list)`，姓名长度 $\le 10$、$n \le 100$，无性能压力。
7. **输出排序**：姓名字典序排序仅为对齐示例输出，不是算法要求。

## 5. 正确性证明

**引理 1（同窗等价）**：若干访问时刻同属某个 60 分钟窗口，当且仅当其中最晚与最早时刻之差严格小于 60 分钟。

**证明**：（⇒）设窗口为 $[s, s+60)$，最早时刻 $a \ge s$、最晚时刻 $b < s + 60$，故 $b - a < 60$。（⇐）设最早 $a$、最晚 $b$ 且 $b - a < 60$，取 $s = a$，则任意时刻 $t$ 满足 $a \le t \le b < a + 60$，即全部落在 $[a, a+60)$ 内。∎

**引理 2（相邻三元组完备性）**：设某员工的 $m$ 个时刻转分钟后排序为 $ts_0 \le ts_1 \le \cdots \le ts_{m-1}$。存在同窗三元组 $\iff$ 存在下标 $i$（$2 \le i \le m-1$）使 $ts_i - ts_{i-2} < 60$。

**证明**：（⇐）$(ts_{i-2}, ts_{i-1}, ts_i)$ 本身就是一个真实三元组，跨度 $ts_i - ts_{i-2} < 60$，由引理 1 同窗。（⇒）设存在下标 $p < q < r$ 使 $ts_r - ts_p < 60$。由 $r \ge p + 2$ 知 $i = p + 2$ 是合法下标，且 $ts_i = ts_{p+2} \le ts_r$、$ts_{i-2} = ts_p$，于是 $ts_i - ts_{i-2} \le ts_r - ts_p < 60$。∎

**定理**：算法返回的集合恰为全体高访问员工。

**证明**：每条记录的姓名是其唯一分组键，哈希分组把全部记录不重不漏地分给各自员工，员工间的判定互相独立。对员工 $k$（记其排序后时刻为 $ts$）：由引理 1，「高访问 $\iff$ 存在三条记录同窗 $\iff$ 最小跨度三元组的跨度 $< 60$」；由引理 2，这等价于存在跨度 $< 60$ 的**相邻**三元组。算法恰好遍历全部 $m - 2$ 个相邻三元组做此判定（$m < 3$ 时不遍历、恒判否，与「三次或更多」的语义一致），命中即 `break` 不改变存在性结论，故单人判定正确；逐员工判定正确，故返回集合正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。分组一遍 $O(n)$（不计单条记录的常数转换开销）；各员工排序合计 $\sum_k m_k \log m_k \le n \log n$（由 $\log m_k \le \log n$ 放缩）；全部扫描合计 $O(n)$。
- **空间复杂度**：$O(n)$。哈希表存放全部 $n$ 个分钟值与姓名（不含返回值）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> findHighAccessEmployees(vector<vector<string>>& access_times) {
        unordered_map<string, vector<int>> g;                     // 姓名 -> 分钟值列表
        for (auto& rec : access_times) {
            const string& t = rec[1];
            g[rec[0]].push_back(stoi(t.substr(0, 2)) * 60 + stoi(t.substr(2)));
        }
        vector<string> ans;
        for (auto& [name, ts] : g) {
            sort(ts.begin(), ts.end());                           // 每人独立排序
            for (size_t i = 2; i < ts.size(); ++i) {
                if (ts[i] - ts[i - 2] < 60) {                     // 严格小于 60 分钟
                    ans.push_back(name);
                    break;                                        // 存在性判定，命中即定型
                }
            }
        }
        sort(ans.begin(), ans.end());                             // 字典序输出
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findHighAccessEmployees(self, access_times: List[List[str]]) -> List[str]:
        g = defaultdict(list)                       # 姓名 -> 分钟值列表
        for name, t in access_times:
            g[name].append(int(t[:2]) * 60 + int(t[2:]))
        ans = []
        for name, ts in g.items():
            ts.sort()                               # 每人独立排序
            if any(ts[i] - ts[i - 2] < 60 for i in range(2, len(ts))):
                ans.append(name)                    # 存在跨度 < 60 的相邻三元组
        return sorted(ans)                          # 字典序输出
```

## 8. 边界情况与易错点

1. **别按钟点分桶**：按 `"HH"` 前两位统计次数会被示例 1 证伪——05:32 / 05:49 / 06:21 跨钟点同窗却拆成 2 + 1。「同一小时」是滑动 60 分钟窗口。
2. **严格小于 60**：`"0815"` 与 `"0915"` 相差恰好 60 不算同窗，条件写 $\le 60$ 必错；示例 3 的跨度 59 差一分钟压线入窗，反向印证。
3. **转分钟后再做差**：`"0910" − "0850"` 数值差 60、实际差 20 分钟。排序可按字符串（定长数字字典序 = 数值序），判窗必须用分钟值。
4. **无跨天环绕**：`"0005"` 与 `"2350"` 直接做差，不要 mod 1440 环绕——所有记录同一天，与 539 首尾环绕的场景刻意区分。
5. **不足 3 条记录**：循环从 $i = 2$ 起，自然判否，无需特判（如示例 2 的 `e`）。
6. **重复时间戳**：同一时刻打卡三次（跨度 0）也是高访问，记录**不要去重**。
7. **输出顺序任意**：题目允许任意顺序，排序只为对齐示例；不要误以为顺序也是判定条件。
8. **注入指令**：本题题面没有 "Create the variable..." 之类的注入句子；周赛题面若混入这类指令，按惯例忽略并标注。
