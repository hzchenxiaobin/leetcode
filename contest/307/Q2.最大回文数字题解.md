# LeetCode 最大回文数字 题解

## 1. 题目概述

- **标题 / 题号**：最大回文数字（#2384，medium）
- **链接**：https://leetcode.cn/problems/largest-palindromic-number/
- **来源**：LeetCode 第 307 场周赛 Q2
- **难度**：中等
- **标签**：贪心、哈希表、字符串、计数

**题意**：
给定仅由数字 $0\sim 9$ 组成的字符串 $\text{num}$（长度 $n$）。从中**挑选若干数字**（可重排、不必用完，但**至少用一个**），拼成一个**不含前导零**的**最大回文整数**，以字符串形式返回。

**约束**：

- $1 \le n \le 10^5$
- $\text{num}$ 仅由数字 $0\sim 9$ 组成

> 💡 **审题关键**：回文的结构是「左半 + 可选中心 + 右半（左半的镜像）」——凡出现在两侧的数字必然**成对**消耗，中心至多放 **1 个落单**数字。于是 $10^5$ 个字符的搜索问题瞬间坍缩成 **10 个桶的计数问题**：每个桶贡献 $\lfloor \text{cnt}[d]/2 \rfloor$ 对，奇计数者竞争中心。剩下的只有三件事：对怎么排（降序）、中心选谁（最大落单）、前导零怎么躲。

## 2. 示例

**示例 1**

```text
输入：num = "444947137"
输出："7449447"
解释：选用 4,4,4,9,4,7,7 共 7 个数字。4 有 2 对、7 有 1 对 → 左半 "744"；
     落单数字中最大的是 9 → 中心 "9"；拼接得 "744" + "9" + "447" = "7449447"。
```

**示例 2**

```text
输入：num = "00009"
输出："9"
解释：0 有 2 对 → 左半 "00"，但拼出的 "00900" 以 '0' 开头，含前导零非法；
     无任何非零数字成对，只能退化为单个数字，落单最大者 9 → "9"。
```

**示例 3**（自拟：中心可以是 0）

```text
输入：num = "00011"
输出："10001"
解释：1 有 1 对、0 有 1 对 → 左半 "10"（降序）；落单的是 0 → 中心 "0"；
     res = "10" + "0" + "01" = "10001"。只要最高位非零，中间的 0 完全合法。
```

## 3. 解题思路

### 3.1 暴力思路

$n$ 达 $10^5$：枚举「选哪些位、如何排列」是 $O(n!)$ 量级的组合爆炸。即便想到按数码聚合、枚举「每种数字取几对」，组合数也有 $\prod_d \big(\lfloor c_d/2 \rfloor + 1\big)$ 种（最坏约 $(\frac{n}{20}+1)^{10}$），同样不可行。真正的突破口是回文的**结构对称性**：回文由「左半 + 中心 + 右半（左半镜像）」唯一确定，自由度只剩「每种数字几对 + 中心是谁 + 左半怎么排」；而**位数优先**（无前导零时位数多的回文必大，见 §5 引理 2）直接把「几对」锁死为**取满**，剩下两个贪心都是一步显然的。

### 3.2 核心观察：配对计数 + 取满对数 + 最大落单当中心

![核心观察：回文 = 镜像配对 + 至多一个落单中心](images/wc307_q2_palindrome_pairs_concept.svg)

设 $\text{cnt}[d]$ 为数字 $d$ 的出现次数，回文的原料只有两种：

1. **成对部分**：每个 $d$ 至多贡献 $\lfloor \text{cnt}[d]/2 \rfloor$ 对，每对在左半、右半各放一个 $d$；
2. **中心部分**：至多一个「落单」数字（$\text{cnt}[d]$ 为奇数者剩下的那一枚），放正中。

**贪心三原则**：

| 原则 | 做法 | 理由 |
|------|------|------|
| **对数取满** | 每个 $d$ 取满 $\lfloor \text{cnt}[d]/2 \rfloor$ 对 | 无前导零的回文**位数多的必大**；多一对垫在最内层，不动最高位、只增长度 |
| **大数字放外层** | 左半按 $d$ 从大到小拼接 | 最高位即左半首字符，高位越大整数越大（交换论证） |
| **中心取最大落单** | 从 $9$ 往 $0$ 找首个奇计数 $d$ | 同长度下中心越大整数越大；塞中心只增长度不动最高位 |

> ⚠️ **唯一的坑——前导零**：左半按降序拼接，首字符恰是「最大的有配对的数字」。它为 `'0'` 当且仅当 $1\sim 9$ **都没有配对**、只剩一堆 $0$ 对——此时任何长度 $\ge 2$ 的拼法都以 `'0'` 开头，非法。处理：**丢弃全部配对**，只留中心；中心也为空则兜底返回 `"0"`。这正是示例 2 的情形。反之，只要存在非零配对，左半首字符必非零，$0$ 对与 $0$ 中心都可以放心用（如示例 3 的 `"10001"`）。

### 3.3 算法流程

![算法流程：计数→拼左半→选中心→前导零判定→拼接](images/wc307_q2_palindrome_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 统计频次 | 扫描 $\text{num}$ 得 $\text{cnt}[0..9]$ | $O(n)$，值域只有 10 |
| ② 拼左半 | $d$ 从 $9$ 到 $0$：$\text{left} \mathrel{+}= d$ 重复 $\lfloor \text{cnt}[d]/2 \rfloor$ 次 | 大数字天然排到外层（最高位） |
| ③ 选中心 | $d$ 从 $9$ 到 $0$：首个奇计数者作 $\text{center}$ | 最大落单，至多一个 |
| ④ 前导零判定 | 若 $\text{left}$ 非空且 $\text{left}[0]=\texttt{'0'}$ → 清空 $\text{left}$ | 当且仅当无任何非零配对 |
| ⑤ 拼接 | $\text{res} = \text{left} + \text{center} + \text{left}^R$；为空则返回 `"0"` | 兜底单字符 |

### 3.4 示例演算

![示例演算：444947137 正常构造与 00009 前导零陷阱](images/wc307_q2_palindrome_walkthrough.svg)

- **示例 1** `"444947137"`：$\text{cnt}$ 为 $c_4=4,\ c_7=2,\ c_9=c_3=c_1=1$。对数：$4\to 2$ 对、$7\to 1$ 对 → $\text{left}=\texttt{"744"}$；落单 $\{9,3,1\}$ 中最大为 $9$ → $\text{center}=\texttt{"9"}$；$\text{left}[0]=\texttt{'7'}$ 非零不丢 → $\text{res}=\texttt{"744"}+\texttt{"9"}+\texttt{"447"}=\texttt{"7449447"}$。
- **示例 2** `"00009"`：$c_0=4,\ c_9=1$。对数：$0\to 2$ 对 → $\text{left}=\texttt{"00"}$；$\text{left}[0]=\texttt{'0'}$ → 清空；$\text{center}=\texttt{"9"}$ → $\text{res}=\texttt{"9"}$。

## 4. 算法细节

1. **值域收缩是第一生产力**：字符集只有 10 种，先一趟 $O(n)$ 计数，之后所有操作都在长度 10 的数组上进行——$n=10^5$ 的字符串问题变成 10 个桶的算术。
2. **左半的降序拼接**：外层循环固定 `for d = 9..0`，依序追加 $\lfloor \text{cnt}[d]/2\rfloor$ 个 $d$。这一步**同时**完成了「选哪些对」（全选）与「怎么排」（降序），无需显式排序。
3. **中心的选取**：从 $9$ 往 $0$ 找**第一个**奇计数的数字，找到即 `break`——落单数字至多用一个，取最大；不区分它是不是 $0$（见 §8 第 3 条）。
4. **前导零判定只看一个字符**：因左半降序，$\text{left}[0]=\texttt{'0'} \iff$ 没有任何 $1\sim 9$ 成对。这是「降序排列的单调红利」：判定从逐位检查坍缩为看首字符；清空时丢弃的必然是一串连续的 0，且不影响其它数字（它们本来就没有对）。
5. **拼接与兜底**：$\text{res}=\text{left}+\text{center}+\mathrm{reverse}(\text{left})$。若 $\text{res}$ 为空（全零且零计数为偶，如 `"0000"`），按「至少用一个数字」返回 `"0"`。

## 5. 正确性证明

**引理 1（回文的配对结构）**：多重集 $S$ 可重排成回文，当且仅当 $S$ 中出现奇数次的字符至多一种。且长度 $\ge 2$ 的回文，其首字符与末字符（互为镜像）相同，构成一对相同字符。

**证明**：必要性：回文中位置 $i$ 与 $|s|-1-i$ 互为镜像、字符相同，双指针两两配对，每对消耗同字符两枚；仅 $|s|$ 为奇时正中一位落单，故奇数次字符至多一种。充分性：每种字符取一半任意序排进左半，奇者多出的一枚放中心，右半取左半的镜像即得回文。后半句：位置 $0$ 的镜像位是 $|s|-1$，两者相等即成一对。∎

**引理 2（位数优先）**：两个均不含前导零的回文整数，位数多者严格更大。

**证明**：设长者位数 $L$、短者 $L' \le L-1$。无前导零故长者 $\ge 10^{L-1}$，短者 $\le 10^{L'}-1 \le 10^{L-1}-1 < 10^{L-1}$。∎

**引理 3（最大长度的结构唯一）**：设 $P=\sum_{d=0}^{9}\lfloor \text{cnt}[d]/2 \rfloor$，$c=1$ 若存在奇计数数字、否则 $c=0$。任何能拼出的回文长度 $\le L^*=2P+c$；且长度恰为 $L^*$ 的回文，其使用的多重集唯一——每个 $d$ 恰用 $2\lfloor \text{cnt}[d]/2 \rfloor$ 枚，再另加**某一个奇计数数字**一枚作中心。

**证明**：设回文使用数字 $d$ 共 $k_d$ 枚，记 $p_d=\lfloor k_d/2 \rfloor \le \lfloor \text{cnt}[d]/2 \rfloor$。由引理 1 至多一个 $k_d$ 为奇。若全部为偶，长度 $=2\sum p_d \le 2P$；若某个 $k_{d^*}$ 为奇，则 $k_{d^*}=2p_{d^*}+1 \le \text{cnt}[d^*]$ 给出 $p_{d^*} \le \lfloor(\text{cnt}[d^*]-1)/2\rfloor$——当 $\text{cnt}[d^*]$ 为偶时比上限少 $1$，为奇时不少，故长度 $=2\sum p_d+1 \le 2P+1-\lfloor\text{cnt}[d^*]\text{ 为偶}\rfloor \le 2P+c$（若 $c=0$ 则全体偶计数，奇情形给 $\le 2P-1 < 2P$）。取等 $L^*$ 时：$c=1$ 情形需 $\sum p_d = P$，逐项不超过上限故每项取等即 $p_d=\lfloor \text{cnt}[d]/2 \rfloor$；且中心 $d^*$ 须不丢对，即 $\text{cnt}[d^*]$ 为奇。$c=0$ 情形同理各项取等且无中心。∎

**引理 4（同长比较）**：在长度同为 $L^*$ 的回文中，「左半为对多重集的降序排列、中心为最大奇计数数字」者字典序最大。

**证明**：由引理 3，这些回文使用同一多重集，区别仅在于左半（对多重集的一个排列）与中心（某个奇计数数字）。回文的前 $\lfloor L^*/2 \rfloor$ 位恰是其左半：降序排列是同一多重集所有排列中字典序最大者（若存在相邻「小前大后」，交换后严格变大，冒泡至降序即最大），故左半不同的对手在左半内部已分出高下、必不大于我方；左半同为降序则与我方完全相同，比较落到正中一位，取最大奇计数者胜。∎

**定理**：上述算法的输出是能拼出的最大回文。

**证明**：分两种情形。

**情形 A（存在非零数字成对）**：算法保留 $\text{left}$，其首字符为最大的有配对数字（非零），输出无前导零；且使用全部对 + 最大落单中心，长度 $=L^*$。由引理 2，任何更短的无前导零回文均更小；由引理 4，任何同长回文均不超过它。故输出最大。

**情形 B（无任何非零数字成对）**：此时 $1\sim 9$ 的计数至多为 1。任何长度 $\ge 2$ 的合法回文首字符非零，由引理 1 后半句其首末字符构成一对非零数字，与前提矛盾，故合法回文长度 $\le 1$，最优解即**出现的最大数字**。算法侧：$\text{left}$ 全由 $0$ 对构成（或为空），触发清空；输出即中心。若存在非零数字，其计数必为 $1$（奇），中心 $=$ 其中最大者 $=$ 出现的最大数字；若只有 $0$，奇计数时中心为 $\texttt{'0'}$，偶计数时 $\text{res}$ 为空、兜底返回 $\texttt{"0"}$——均为 $0$，即该情形下的最大数字。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。计数一趟 $O(n)$；左半与中心的构造各固定循环 10 步、总追加字符 $\le n$；拼接与翻转合计 $\le n$。
- **空间复杂度**：$O(n)$。输出串最长为 $n$；除输出外仅一个长度 10 的计数数组，即 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string largestPalindromic(string num) {
        int cnt[10] = {0};
        for (char c : num) ++cnt[c - '0'];          // ① 计数

        string left;
        for (int d = 9; d >= 0; --d)                // ② 降序拼左半：大数字放外层
            left += string(cnt[d] / 2, '0' + d);

        string center;
        for (int d = 9; d >= 0; --d)                // ③ 最大落单当中心
            if (cnt[d] % 2 == 1) { center = string(1, '0' + d); break; }

        if (!left.empty() && left[0] == '0')        // ④ 无非零配对 → 弃全部 0 对
            left.clear();

        string res = left + center + string(left.rbegin(), left.rend());
        return res.empty() ? "0" : res;             // ⑤ 全零兜底
    }
};
```

### Python

```python
class Solution:
    def largestPalindromic(self, num: str) -> str:
        cnt = [0] * 10
        for c in num:
            cnt[int(c)] += 1                        # ① 计数

        left = "".join(str(d) * (cnt[d] // 2) for d in range(9, -1, -1))
        center = next((str(d) for d in range(9, -1, -1) if cnt[d] % 2), "")

        if left and left[0] == "0":                 # ④ 前导零陷阱
            left = ""

        res = left + center + left[::-1]
        return res if res else "0"                  # ⑤ 全零兜底
```

## 8. 边界情况与易错点

1. **前导零误修成「修剪左半末尾的 0」**：错。降序下 $0$ 对本来就排在左半**末尾**（最内层），完全合法；非法的是**首字符**为 `'0'`（即无非零配对），此时必须**整体清空**——`"00009"` 若只修剪末尾会得到 `"09"` 一类的残废串，仍含前导零。
2. **全零输入**（`"0000"`、`"00"`）：left 被清空、中心为空（偶计数无落单），res 为空，必须兜底返回 `"0"`；漏掉兜底会返回空串，违反「至少用一个数字」。
3. **中心可以是 `'0'`**：`"00011"` → `"10001"`。不要在选中心时跳过 0——只要最高位（左半首字符）非零，正中的 0 完全合法。
4. **清空 left 后中心仍可能为空**：即第 2 条的兜底分支，`res.empty()` 判定不可省。
5. **单个 `"0"` 不算前导零**：兜底返回的 `"0"` 是唯一合法的单零回文。
6. **误判「少用几对更好」**：不会。位数优先（引理 2）保证无前导零时对数取满恒优；唯一例外恰是前导零情形，已被清空分支覆盖。
7. **性能**：$n=10^5$，全程 $O(n)$；Python 侧避免在循环里 `left = left + ...` 反复建串，用 `join` 生成器一次成型。
8. **返回类型是字符串**：结果可达 $10^{10^5}$ 量级，绝不能转成整数比较或输出。
