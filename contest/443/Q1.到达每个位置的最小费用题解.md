# LeetCode 到达每个位置的最小费用 题解

## 1. 题目概述

- **标题 / 题号**：到达每个位置的最小费用（#3502，easy）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-reach-every-position/
- **来源**：LeetCode 第 443 场周赛 Q1
- **难度**：简单
- **标签**：数组、前缀最值、贪心

**题意**：

你在位置 $n$（队伍末尾），队伍共 $n+1$ 人，编号 $0$ 到 $n$（编号 $i$ 的人初始站在位置 $i$，你就是编号 $n$）。与编号 $i$ 的人交换位置的费用为 $\text{cost}[i]$，交换规则如下：

- 对方在**你前面**（位置编号比你小）：你**必须付费** $\text{cost}[i]$ 才能与他交换，交换后你落到他站的位置；
- 对方在**你后面**：**免费**交换，对方顶到你身后。

返回数组 $\text{answer}$，其中 $\text{answer}[i]$ 是到达位置 $i$ 的最小总费用。

**约束**：

- $1 \le n = \text{cost.length} \le 100$
- $1 \le \text{cost}[i] \le 100$

> 💡 **复盘定位**：典型签到题。数据范围小到几乎任何做法都能过，真正的考点是**读规则**：交换是与某个人互换位置，「付费」意味着你瞬间落到他站的位置，而回程不要钱。看穿这一点后，答案就是一个前缀最小值数组，一次遍历 $O(n)$ 收工。比赛时值得花 30 秒用小样例验证结论，再花 1 分钟想清楚为什么不是别的（比如区间和、或与位置 $i$ 本身绑定的某种代价）。

## 2. 示例

**示例 1**

```text
输入：cost = [5,3,4,1,3,2]
输出：[5,3,3,1,1,1]
解释：
i = 0：付费 5 与编号 0 的人交换，直接到位置 0。
i = 1：付费 3 与编号 1 的人交换。
i = 2：付费 3 与编号 1 的人交换，再免费与位置 2 的人交换。
i = 3：付费 1 与编号 3 的人交换。
i = 4：付费 1 到位置 3 后，免费退到位置 4。
i = 5：同理免费退到位置 5。
```

**示例 2**

```text
输入：cost = [1,2,4,6,7]
输出：[1,1,1,1,1]
解释：付费 1 与编号 0 的人交换后，队伍里所有人都在你后面，
      免费退到任何位置，全程只花 1。
```

## 3. 解题思路

### 3.1 暴力思路：模拟交换 = 掉进排列组合的坑

最直觉的做法是把「你的位置 + 队伍排列」整体当状态做 BFS/最短路：每次枚举与任意一人交换，边权为 $\text{cost}[i]$ 或 $0$，跑到位置 $i$ 的最短路即答案。

问题在于：**每次交换都会改变队伍的排列**。状态上限是 $(n+1)!$ 种排列 × $(n+1)$ 个你的位置，$n=6$ 时就已数十万级，$n=100$ 完全不可想象。若只把「你的位置」当状态又会错——付费对象是谁、他站在哪，都依赖排列的历史。

好在 $n \le 100$ 且人人 $1 \le \text{cost}[i] \le 100$（边权恒正、无零环收益），比赛时对小样例跑一遍朴素 BFS 就能发现规律：每个 $\text{answer}[i]$ 都恰好等于 $\min(\text{cost}[0..i])$。签到题的正解通常就是这样一个一行观察，值得做「BFS 打表 → 猜结论 → 证明」的完整闭环。

### 3.2 核心观察：付一次最低价，回程全免费

先把两条规则翻译成几何语言（见下图）：

- **付费 = 传送**：付 $\text{cost}[i]$ 后你直接落到位置 $i$，中间的人原地不动，可以一次跨过任意远；
- **回程 = 白嫖**：一旦站上某个位置 $p$，所有编号 $> p$ 的人都在你身后，免费退到 $p+1 \ldots n$ 中任何位置。

![交换规则：向前付费，向后免费](images/c443_q1_queue_swap_rules.svg)

于是到达位置 $i$ 的最优策略呼之欲出：

1. 在 $0..i$ 中挑最便宜的那个人 $p = \arg\min_{k \le i} \text{cost}[k]$；
2. 付费 $\text{cost}[p]$，**一步传送**到位置 $p$（$p \le i$，且他在你前面，付费合法）；
3. 若 $p < i$，与位置 $i$ 的人免费交换退回去——此时位置 $i$ 的人在你身后，免费。

总费用恰为 $\text{cost}[p] = \min(\text{cost}[0..i])$。而任何方案都必须付费至少一次（见 §5 证明），所以：

$$\text{answer}[i] = \min_{0 \le k \le i} \text{cost}[k]$$

即 **answer 是 cost 的前缀最小值数组**。

![前缀最小值模型](images/c443_q1_prefix_min_model.svg)

> ⚠️ 常见误读：把「到达位置 $i$」理解成「必须付到 $i$ 这个人的钱」或「逐个相邻交换付一路」。交换是**与某个人互换位置**的传送语义，且与身后的人交换免费——这两条合起来才是前缀最小值成立的原因。

### 3.3 算法流程

一次遍历，维护滚动最小值 $\text{cur}$：

| 步骤 | 动作 | 说明 |
|------|------|------|
| ① | `cur = +∞` | 滚动最小值初始化 |
| ② | 从左到右扫描 $i = 0, 1, \ldots, n-1$ | |
| ③ | `cur = min(cur, cost[i])` | **先**更新：位置 $i$ 自己也是候选付费对象 |
| ④ | `answer[i] = cur` | **后**写入答案 |

写不出错的关键就是③④的顺序：先更新再写入，否则 `answer[i]` 会漏掉 `cost[i]` 本身（`i = 0` 时直接出 bug）。

### 3.4 示例演算

对示例 1 `cost = [5,3,4,1,3,2]` 逐步走查：

![示例1演算走查表](images/c443_q1_walkthrough.svg)

`cur` 从 $5$ 起只降不升：$i=1$ 降到 $3$，$i=3$ 刷新为 $1$，此后所有位置的 `answer` 都按这个新低价结算，得到 `[5,3,3,1,1,1]`，与官方输出一致。这也说明 **answer 一定是非严格递减的**——提交后可作自检。

## 4. 算法细节

- **滚动最小值**：不需要前缀最小值的完整定义式 $\text{answer}[i] = \min(\text{answer}[i-1], \text{cost}[i])$，一个变量 `cur` 滚动即可，额外空间 $O(1)$。
- **原地写法**：C++ 里可以直接把 `cost` 刷成 `answer`（LeetCode 允许修改输入；不放心就另开数组，$n \le 100$ 无压力）。
- **Python 一行流**：`itertools.accumulate(cost, min)` 就是前缀最小值的标准库实现，比赛里可以直接用。
- **为什么不用管「付费对象可能不是初始站在 $p$ 的人」**：因为我们构造的上界方案里，目标 $p$ 号人从未被动过，一定还站在位置 $p$；下界证明（§5）则说明绕路把他挪走只会花更多钱。

## 5. 正确性证明

**引理 1（付费对象的位置守恒）**：只有你在发起交换，其他人的位置仅在与你互换时改变；且每次付费交换后，你落到的位置恰是付费对象**交换前**所站的位置。

**证明**：题面规定交换由你发起、两人位置互换，队列中其他人之间不发生交换，位置变化只能来自与你互换。若对方在你前面，他的原位置 $q <$ 你的位置，互换后你到 $q$。∎

**引理 2（首次付费必付「原住民」）**：设 $i < n$。你**第一次**位于 $\le i$ 区域的那次交换，付费对象必是编号 $\le i$ 的人，故该次付费 $\ge \min(\text{cost}[0..i])$。

**证明**：设首次到达的时刻，你从位置 $> i$ 交换到位置 $x \le i$。该步从 $> i$ 直达 $\le i$，是向前跳，必付费；付费对象当时站在 $x \le i$。反设他编号 $k > i$：编号 $k$ 的人初始站在位置 $k > i$，由引理 1，他只能在更早某次与你的交换中被挪动。而任何一次他被挪到 $\le i$ 区域的交换，都意味着「他落到你当时的位置 $\le i$」，即你当时已位于 $\le i$ 区域——与「本时刻才是第一次」矛盾。∎

**定理**：$\text{answer}[i] = \min(\text{cost}[0..i])$ 对所有 $0 \le i < n$ 成立。

**证明**：

- **下界**：你从位置 $n$ 出发、终点位置 $i < n$，过程中必然存在第一次进入 $\le i$ 区域的时刻。由引理 2，这次付费 $\ge \min(\text{cost}[0..i])$，故任何方案总费用 $\ge \min(\text{cost}[0..i])$。
- **上界**：取 $p = \arg\min_{k \le i} \text{cost}[k]$。由引理 1，编号 $p$ 的人未被挪动过、仍站在位置 $p < n$，在你前面；付费 $\text{cost}[p]$ 与他交换，你落到 $p \le i$。若 $p < i$，此时位置 $i$ 的人在你身后，与其免费交换即达位置 $i$。总费用恰为 $\min(\text{cost}[0..i])$。∎

> 💡 证明的灵魂在引理 2：**想混进便宜的外区人（编号 $> i$ 但 $\text{cost}$ 低）替你买单是不可能的**——把任何编号 $> i$ 的人搬进 $\le i$ 区域，前提是你自己已经进去过一次，而那次进去就已付过不低于 $\text{cost}[p]$ 的钱。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单次遍历，每个位置做一次 $\min$ 更新和一次写入。
- **空间复杂度**：$O(1)$ 额外空间。只用一个滚动变量 `cur`（返回数组按惯例不计入）。

对 $n \le 100$ 的数据范围而言绰绰有余；即便 $n$ 放大到 $10^7$ 该做法也直接成立。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> minCosts(vector<int>& cost) {
        int cur = INT_MAX;
        for (int& c : cost) {
            cur = min(cur, c);
            c = cur;              // 原地刷成前缀最小值
        }
        return cost;
    }
};
```

### Python

```python
from itertools import accumulate

class Solution:
    def minCosts(self, cost: List[int]) -> List[int]:
        return list(accumulate(cost, min))   # accumulate(cost, min) = 前缀最小值
```

保守写法（不依赖输入可修改、不依赖标准库技巧）：

```python
class Solution:
    def minCosts(self, cost: List[int]) -> List[int]:
        cur = inf
        ans = []
        for c in cost:
            if c < cur:
                cur = c
            ans.append(cur)
        return ans
```

## 8. 边界情况与易错点

1. **先更新后写入**：`cur = min(cur, cost[i])` 必须在 `answer[i] = cur` 之前，否则 `answer[0]` 会错误地保持 `+∞`。
2. **$n = 1$**：`answer = [cost[0]]`，循环天然覆盖，无需特判。
3. **别把交换当成相邻移动**：付费交换可以一步跨越任意距离，把问题想成「逐格走」会推出区间和之类的错误结论。
4. **别对「你」重复付费**：你就是编号 $n$，`cost` 数组长度只有 $n$，遍历时不会碰到自己，无需防御。
5. **付费对象被挪过的坑**：不要假设「付费时编号 $p$ 的人一定还站在位置 $p$」对所有方案成立——这只在上界构造（他不动的方案）里成立，一般方案里成立的是引理 1/2 那两条。
6. **单调性自检**：`answer` 非严格递减，若提交后发现不单调，一定是更新顺序或取错 `min` 方向出了问题。
7. **溢出**：$n, \text{cost}[i] \le 100$，任何整型都够；`cur` 初始化用 `INT_MAX` / `inf` 时注意别把初值写进答案。
