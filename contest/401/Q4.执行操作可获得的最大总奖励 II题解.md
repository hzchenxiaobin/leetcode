# LeetCode 执行操作可获得的最大总奖励 II 题解

## 1. 题目概述

- **标题 / 题号**：执行操作可获得的最大总奖励 II（#3181，hard）
- **链接**：https://leetcode.cn/problems/maximum-total-reward-using-operations-ii/
- **来源**：LeetCode 第 401 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、动态规划、排序

**题意**：与同场 Q3（#3180）完全同题。给定长度为 $n$ 的数组 `rewardValues`，初始总奖励 $x = 0$，所有下标未标记。可执行**任意次**操作：选一个未标记下标 $i$，若 $\text{rewardValues}[i]$ **严格大于**当前 $x$，则 $x \mathrel{+}= \text{rewardValues}[i]$ 并标记 $i$。返回 $x$ 能达到的最大值。与 Q3 的唯一差别是数据范围：$n$ 与值域同时放大 25 倍。

**约束**：

- $1 \le \text{rewardValues.length} \le 5 \times 10^4$
- $1 \le \text{rewardValues}[i] \le 5 \times 10^4$

> 💡 **周赛现场策略**：题面与 Q3 一字不差、数据范围 $\times 25$，这是明确的「同题加码」信号——Q3 的 $O(V^2)$ 逐位背包在这里内层总量 $\sum v \approx 1.25 \times 10^9$，C++ 也是超时边缘的赌博。Q3 题解 §4 埋的伏笔 $f \mathrel{|=} \big(f \,\&\, (2^v - 1)\big) \ll v$ 正是为此准备的：整条转移是**纯位级批量操作**，交给机器字 64 路并行，$V^2/64 \approx 2 \times 10^7$ 次字操作收工。

## 2. 示例

**示例 1**

```text
输入：rewardValues = [1,1,3,3]
输出：4
解释：依次标记下标 0 和 2（值 1、3）：x 从 0 → 1 → 4，每步都满足 值 > x。
      第二个 3 要求 3 > 4，不成立——同值至多取一次。
```

**示例 2**

```text
输入：rewardValues = [1,6,4,3,2]
输出：11
解释：依次标记下标 0、2、1（值 1、4、6）：x 从 0 → 1 → 5 → 11。
```

**示例 3（满规模直觉）**

```text
输入：rewardValues = [1,2,3,…,49999,50000]
输出：99999
解释：取 49999，再取 50000（50000 > 49999）。
      可达总和被钳制在 2·v_max − 1 = 99999 以内——值域再大，答案也翻不过两倍最大值。
```

## 3. 解题思路

### 3.1 暴力思路：Q3 的背包原样搬过来会超时

Q3 已把问题钉死成「排序去重 + 可行性 0-1 背包」：$dp[j]$ 表示总奖励**恰好**为 $j$ 是否可达，按升序处理每个值 $v$，转移 $dp[j + v] \mathrel{|}= dp[j]$（$j \in [0, v-1]$）。三个关键结论（Q3 题解 §3.2、§5 有完整证明）直接沿用：

1. 可行序列必严格递增 → 排序消灭顺序维度，去重消灭重复值；
2. 读区 $[0, v-1]$、写区 $[v, 2v-1]$ 不相交 → 正序枚举也安全；
3. 可达总和 $< 2 v_{\max}$ → $dp$ 只需开 $2 v_{\max}$。

问题只在**速度**：内层逐位枚举总量 $\sum_{v} v \le \frac{V(V+1)}{2} \approx 1.25 \times 10^9$（$V = 5\times10^4$）。实测 C++ 满规模（值 $1 \sim 5\times10^4$ 全相异）约 0.4 s，已是超时边缘；Python 同款预估数百秒，毫无机会。

> ⚠️ 注意这里的「暴力」不是思路错误，而是**位宽浪费**：转移对每个下标只做「读一个布尔、加 $v$、或一个布尔」三件事，重复了 $1.25 \times 10^9$ 次纯位级操作——这正是 bitset 的主场。

### 3.2 核心观察：把 dp 数组折进一个整数

![核心观察：dp 折进整数 f，一条位级流水线](images/max_reward2_bitset_model.svg)

把 `dp[j]` 看作大整数 $f$ 的第 $j$ 个二进制位（$dp[0] = \text{true}$ 即 $f = 1$），一轮转移浓缩成一条：

$$f \mathrel{|=} \big(f \,\&\, (2^v - 1)\big) \ll v$$

- **掩码 $2^v - 1$**：低 $v$ 位为 1，恰是读区 $[0, v-1]$——「严格大于」条件的位级化身；
- **左移 $\ll v$**：读区整体搬进写区 $[v, 2v-1]$；
- **或 $\mathrel{|=}$**：新旧可达位合并，幂等，天然防重。

一次「与 + 移位 + 或」对**整个状态集**同时生效：转移批量并行了 64 倍（机器字长）。这是相对 Q3 的全部增量——思路零新增，只是把 `for j` 循环交给了位级流水线。

### 3.3 算法流程：两个实现口径

![算法流程：字级拆分与跨字搬运](images/max_reward2_word_split.svg)

**Python——大整数就是现成的 bitset**：

1. 排序去重：`for v in sorted(set(rewardValues))`；
2. 对每个 $v$ 执行 `f |= (f & ((1 << v) - 1)) << v`；
3. 答案 = `f.bit_length() - 1`（最高置位）。

CPython 的大整数四则与位运算都是 C 实现，$10^5$ 位的 `&`/`<<`/`|` 就是几趟内存搬移，满规模实测约 0.1 s。

**C++——手写字级转移**：动态移位量用不上 `bitset` 的整条流水线，于是把 $f$ 存成 `unsigned long long` 数组手动搬字：

1. 分解 $v = 64w + r$；
2. 只扫读区覆盖的字 $i \in [0, w]$：整字直接取，尾字用 $(2^r - 1)$ 截出低 $r$ 位，得 `low`；
3. `low` 整体左移 $r$ 位跨字：低段 `low << r` 写进字 $i + w$，高段 `low >> (64 - r)` 写进字 $i + w + 1$；
4. 答案 = 最高置位：`i*64 + 63 - __builtin_clzll(f[i])`。

### 3.4 示例演算

![示例演算：f 的位被逐轮点亮](images/max_reward2_walkthrough.svg)

以示例 2 为例，排序去重得 $[1,2,3,4,6]$，逐轮点亮 $f$（1 = 该位可达）：

| 处理值 $v$ | 掩码后读区 | $\ll v$ 产生 | 合并后 $f$ 的置位集 |
|------|------|------|------|
| 初始 | — | — | $\{0\}$ |
| $v=1$ | $\{0\}$ | $\{1\}$ | $\{0,1\}$ |
| $v=2$ | $\{0,1\}$ | $\{2,3\}$ | $\{0,\dots,3\}$ |
| $v=3$ | $\{0,1,2\}$ | $\{3,4,5\}$ | $\{0,\dots,5\}$ |
| $v=4$ | $\{0,\dots,3\}$ | $\{4,\dots,7\}$ | $\{0,\dots,7\}$ |
| $v=6$ | $\{0,\dots,5\}$ | $\{6,\dots,11\}$ | $\{0,\dots,11\}$ |

最高置位 $11$ ✓，对应取法 $1 \to 4 \to 6$（$x$ 轨迹 $0 \to 1 \to 5 \to 11$）。

## 4. 算法细节

1. **容量 $2 v_{\max}$，再多开一个字**：可达总和 $\le 2 v_{\max} - 1 \le 99999$（Q3 引理 3），位向量开 $\lceil 2 v_{\max}/64 \rceil$ 个字；C++ 版再**多开一个字**接住跨字高段，`i + w + 1` 永不越界。
2. **跨字拆分公式**：源字 $i$ 中位 $p$ 的目标全局位是 $i\cdot 64 + p + v = (i+w)\cdot 64 + (p + r)$。$p + r < 64$ 落回字 $i + w$（`low << r` 的第 $p+r$ 位）；$p + r \ge 64$ 溢出到字 $i + w + 1$（`low >> (64 - r)` 的第 $p + r - 64$ 位）。两段拼接恰是 `low` 整体左移 $r$ 位，不重不漏。
3. **$r = 0$ 的两个坑**：`1ull << 64` 与 `low >> 64` 都是**未定义行为**——高段写入必须 `if (r)` 守卫；同时尾字掩码 $(2^r - 1) = 0$，$i = w$ 的循环体自然空转，逻辑自动正确。
4. **原地更新安全**：本轮写入的全局位都 $\ge v$（源位 $+\ v$），本轮读取的全局位都 $< v$（掩码保证），两类集合不相交——这是 Q3「读写区不相交」的字级版本，所以内层正序扫、就地 `|=` 都安全。
5. **只扫 $i \le w$**：读区 $[0, v-1]$ 只覆盖前 $w$ 个整字加尾字低 $r$ 位，内层代价 $O(v/64)$，总量 $\sum_v \lceil v/64 \rceil \le V^2/128 + V \approx 2\times10^7$ 次字操作。若每个 $v$ 都扫全表，会退化到 $D \cdot 2V/64 \approx 8\times10^7$——结果仍对，但慢 4 倍。
6. **去重照做**：同值第二份是 no-op（读写区结论不变），不去重不错、只是白花字操作；`sorted(set(...))` 一行的事。
7. **`bit_length() − 1` 而非 `bit_length()`**：前者是最高置位下标（= 最大可达总和），后者是二进制位数，差一。

## 5. 正确性证明

**引理 1（Q3 三结论沿用）**：可行取法序列可重排为严格升序；同值至多取一次；任何可行方案总和 $S \le 2 v_{\max} - 1$。

**证明**：见 Q3 题解 §5 引理 1–3：先取 $a$ 后取 $b$ 则 $b > x \ge a$，故可行序列严格递增，升序即唯一可行形状；由此同值至多一次；末步取 $v_{\text{last}}$ 前有 $S - v_{\text{last}} < v_{\text{last}} \le v_{\max}$，故 $S < 2 v_{\max}$。∎

**引理 2（位转移 ≡ 逐位转移）**：设处理值 $v$ 之前 $f$ 的第 $j$ 位等于 $dp[j]$，令 $f' = f \,\vert\, \big((f \,\&\, (2^v - 1)) \ll v\big)$，则 $f'$ 的第 $s$ 位等于 $dp[s] \lor \big(s \in [v, 2v-1] \land dp[s-v]\big)$。

**证明**：$f \,\&\, (2^v - 1)$ 的第 $j$ 位为 $dp[j] \land [j \le v-1]$，其余位为 0；左移 $v$ 位后它仅在第 $j + v$（$j \in [0, v-1]$）位有贡献。按位或不改变 $f$ 原有位，故 $f'$ 第 $s$ 位 = $dp[s] \lor \big(s - v \in [0, v-1] \land dp[s-v]\big) = dp[s] \lor \big(s \in [v, 2v-1] \land dp[s-v]\big)$，恰是 Q3 的转移（读区 $[0,v-1]$、写区 $[v,2v-1]$）。∎

**引理 3（字级实现 ≡ 位运算语义，且原地安全）**：C++ 字级循环执行完后 $f$ 的值等于引理 2 中的 $f'$。

**证明**：拆位映射：源字 $i$ 中位 $p$ 的目标全局位 $= i\cdot 64 + p + v = (i + w)\cdot 64 + (p + r)$（$v = 64w + r$）。`f[t] |= low << r`（$t = i + w$）把位 $p$（$p + r < 64$）送到字 $t$ 的位 $p + r$；`f[t+1] |= low >> (64 - r)` 把位 $p$（$p \ge 64 - r$，即 $p + r \ge 64$）送到字 $t + 1$ 的位 $p + r - 64$。每个源位恰被一条路径搬运，两段之并 = `low` 整体左移 $r$ 位。又，$i \in [0, w]$ 的枚举恰覆盖全局位 $< v$ 的全体（$i < w$ 的整字，加上 $i = w$ 时掩码截出的低 $r$ 位），故整轮效果 = 把 $(f \,\&\, (2^v - 1)) \ll v$ 按位或进 $f$。原地安全：读取的全局位 $< v$，写入的全局位 = 源位 $+\ v \ge v$，两类位集不相交，边读边写互不污染。∎

**定理**：算法返回可行方案能达到的最大总奖励。

**证明**：对已处理的值个数归纳。由 Q3 定理（DP 不变式），逐位 $dp$ 的 true 下标集始终等于「已处理值集的可行总和集」；由引理 2、3，整数 $f$（Python 大整数或 C++ 字级循环）与逐位 $dp$ 逐步等值。故处理完全部值后，$f$ 的置位集 = 全体可行总和集，由引理 1 含于 $[0, 2 v_{\max} - 1]$，位向量容量充足不漏。最大可行总和即置位集的最大元素 = 最高置位（Python `bit_length() − 1`；C++ 从高向低扫字 + `clz`），算法返回它。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(n \log n + \sum_{v \in \text{去重值}} \lceil v/64 \rceil\big) \le O(n \log n + V^2/64)$。排序 $O(n \log n)$；字操作总量 $\approx 2 \times 10^7$，满规模（值 $1 \sim 5\times10^4$ 全相异）实测 C++ 约 31 ms。Python 大整数版每个 $v$ 做常数趟 $O(2V/64)$ 的字级搬运，同一数据实测约 0.1 s。
- **空间复杂度**：$O(V/64)$——位向量 $\lceil 2 v_{\max}/64 \rceil \approx 1563$ 个机器字（约 12.5 KB）；排序原地完成。

## 7. 参考代码

### C++（字级 bitset，满规模 31 ms）

```cpp
class Solution {
public:
    int maxTotalReward(vector<int>& rewardValues) {
        sort(rewardValues.begin(), rewardValues.end());
        rewardValues.erase(unique(rewardValues.begin(), rewardValues.end()),
                           rewardValues.end());
        int m = rewardValues.back();                 // v_max，可达总和 <= 2m-1
        int words = (2 * m + 63) / 64;
        vector<unsigned long long> f(words + 1, 0);  // 多开一字接住跨字高段
        f[0] = 1;                                    // dp[0] = true
        for (int v : rewardValues) {
            int w = v >> 6, r = v & 63;              // v = 64w + r
            for (int i = 0; i <= w; i++) {           // 只扫读区覆盖的字
                unsigned long long low = (i < w) ? f[i]
                                          : f[i] & ((1ull << r) - 1);
                if (!low) continue;
                int t = i + w;
                f[t] |= low << r;                    // 低段：留在本字
                if (r) f[t + 1] |= low >> (64 - r);  // 高段：跨字溢出
            }
        }
        for (int i = (int)f.size() - 1; i >= 0; i--)
            if (f[i]) return i * 64 + 63 - __builtin_clzll(f[i]);
        return 0;
    }
};
```

### Python（大整数，满规模 0.1 s）

```python
class Solution:
    def maxTotalReward(self, rewardValues: List[int]) -> int:
        f = 1
        for v in sorted(set(rewardValues)):
            f |= (f & ((1 << v) - 1)) << v   # 读低 v 位、左移 v、或回去
        return f.bit_length() - 1            # 最高置位 = 最大可达总和
```

> 💡 C++ 还有一个偷懒口径：`bitset<100000>` 配**递增掩码**——升序处理时掩码 $(2^v - 1)$ 只增不减，用 `while (cur < v) mask.set(cur++)` 累计构造，转移 `f |= (f & mask) << v` 全交给库。复杂度同为 $O(V^2/64)$，代码更短；手写字级版的优势是不受模板长度限制、跨字细节可控。

## 8. 边界情况与易错点

1. **位向量只开 $v_{\max}$**：答案可达 $2 v_{\max} - 1 = 99999$（见示例 3），开 $5 \times 10^4$ 直接漏解——Q3 的老坑在 Q4 换了张皮。
2. **`1ull << 64` / `>> 64` 是 UB**：$r = 0$（$v$ 为 64 的倍数）时两个移位都非法，高段必须 `if (r)` 守卫；小随机对拍未必撞上 64 倍数值，属于「潜伏到满规模才炸」的坑。
3. **忘写跨字高段**：漏掉 `f[t+1] |= low >> (64 - r)` 后，只有移位恰好对齐的数据能过——小值域随机对拍（值域几百）必能暴露，写完务必对拍。
4. **尾字掩码方向**：读区是 $[0, v-1]$，尾字保留**低** $r$ 位（`& (2^r - 1)`）；方向搞反就变成读 $[v, 2v)$，违反「严格大于」。
5. **`bit_length()` 差一**：返回的是位数，最高置位要减一；C++ 侧对应 `63 − __builtin_clzll`。
6. **扫全表而非 $i \le w$**：结果仍正确（多余的字被掩码清零），只是白扫——慢 4 倍，但失去了 $V^2/64$ 的意义。
7. **不去重**：同值第二份是 no-op，正确但白费字操作；`[7,7,7,…]` 极端输入不去重会多做 $n$ 轮空转。
8. **单元素 / 全同值**：`[7]` → 7、`[5,5,5]` → 5，无需特判；$f$ 的位 0 恒为 1，最高位扫描必然命中。
