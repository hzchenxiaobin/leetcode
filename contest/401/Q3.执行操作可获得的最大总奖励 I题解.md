# LeetCode 执行操作可获得的最大总奖励 I 题解

## 1. 题目概述

- **标题 / 题号**：执行操作可获得的最大总奖励 I（#3180，medium）
- **链接**：https://leetcode.cn/problems/maximum-total-reward-using-operations-i/
- **来源**：LeetCode 第 401 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、排序、位运算

**题意**：给定长度为 $n$ 的数组 `rewardValues`。初始总奖励 $x = 0$，所有下标未标记。可以执行**任意次**操作：选一个未标记下标 $i$，若 $\text{rewardValues}[i]$ **严格大于**当前 $x$，则 $x \mathrel{+}= \text{rewardValues}[i]$ 并标记 $i$。返回 $x$ 最终能达到的最大值。

**约束**：

- $1 \le \text{rewardValues.length} \le 2000$
- $1 \le \text{rewardValues}[i] \le 2000$

> 💡 **周赛现场策略**：条件「值 > 当前总和」意味着 $x$ 只增不减、门槛越抬越高——第一反应应是「排序 + 背包」。$n, v \le 2000$ 互为镜像的数据范围是强烈暗示：总奖励被压在 $4000$ 以内，值域极小，天然是**可行性 0-1 背包**的形状；标签里的「位运算」则提示还能把整个状态集装进一个大整数批量转移（见 §4，正是同场 Q4 的钥匙）。

## 2. 示例

**示例 1**

```text
输入：rewardValues = [1,1,3,3]
输出：4
解释：依次标记下标 0 和 2（值 1、3）：x 从 0 → 1 → 4，每步都满足 值 > x。
      两个 3 只能取一个——第二个 3 要求 3 > 4，不成立。
```

**示例 2**

```text
输入：rewardValues = [1,6,4,3,2]
输出：11
解释：依次标记下标 0、2、1（值 1、4、6）：x 从 0 → 1 → 5 → 11。
```

**示例 3（全同值）**

```text
输入：rewardValues = [5,5,5]
输出：5
解释：取第一个 5 后 x = 5，其余的 5 不大于 x——同值至多取一次。
```

## 3. 解题思路

### 3.1 暴力思路：爆搜与贪心双双失效

最直接的做法是回溯：每步枚举所有「值 > $x$ 且未标记」的下标，搜索全部取数序列——子集数 $2^{2000}$，而且「同一组数以不同顺序取，合法性完全不同」，顺序维度让剪枝都无从下手。

两个方向的贪心也都被示例 2 反杀（排序后为 $[1,2,3,4,6]$）：

- **升序「能取就取」**：取 $1, 2$（$x=3$），3 卡住跳过，取 $4$（$x=7$），6 卡住 → 总和 $7$；
- **先取最大**：取 $6$（$x=6$），其余值全部 $\le 6$ → 总和 $6$。

都不及最优的 $11$（取 $1,4,6$）。**局部「能取就取」会污染后续门槛**——小值看似白捡，实则是垫高 $x$、逼走大值的负资产；必须让 DP 把「取 / 不取」两种决策都留在状态里。

### 3.2 核心观察：可行序列必严格递增

![核心观察：取数序列必严格递增，x 轨迹如上台阶](images/max_reward_ladder_concept.svg)

设某合法操作序列先取 $a$、后取 $b$。取 $b$ 时要求

$$b > x \ge a \quad\Longrightarrow\quad b > a$$

（此时的 $x$ 已包含 $a$）。于是**任何可行序列按执行顺序严格递增**。一步推理，三连推论：

1. **顺序维度被消灭**：升序不是众多可行顺序中「最优」的一种，而是**唯一可能**的形状——排序后取数顺序自动确定，问题退化为纯「选或不选」的 0-1 背包；
2. **重复值无效**：严格递增 $\Rightarrow$ 同值至多取一次，排序后去重；
3. **总和有上界**：设最大值为 $v_{\max}$，最后取的数 $v_{\text{last}} \le v_{\max}$，而取它之前 $x < v_{\text{last}} \le v_{\max}$，故 $S = x + v_{\text{last}} < 2 v_{\max} \le 4000$。

> 💡 一句话：**「值 > x」这道门槛把顺序锁死成升序、把问题锁死成背包、把值域锁死在 $2 v_{\max}$。**

### 3.3 算法流程：排序去重 + 可行性 0-1 背包

![DP 转移模型：读 [0,v−1] 写 [v,2v−1]](images/max_reward_dp_model.svg)

定义 $dp[j] = \text{true}$ 表示「存在取法使总奖励**恰好**为 $j$」，初始 $dp[0] = \text{true}$。按升序枚举去重后的值 $v$，转移为

$$dp[j + v] \mathrel{|}= dp[j], \qquad j \in [0, v-1]$$

- **读区** $[0, v-1]$：取 $v$ 的前提是 $x < v$；
- **写区** $[v, 2v-1]$：取完的落点 $x + v \in [v, 2v-1]$。

**两区不相交**带来一个漂亮性质：本轮写入的下标（$\ge v$）永远碰不到本轮读取的下标（$< v$），同一个 $v$ 天然只用一次——传统 0-1 背包必须倒序枚举来防止重复选取，这里**正序、倒序都正确**。流程总结：

1. 排序 + 去重，得升序数组；
2. `dp` 开 $2 v_{\max}$ 大小，$dp[0] = \text{true}$；
3. 依次处理 $v$：把 $[0, v-1]$ 中可达的 $j$ 映射到 $j + v$；
4. 答案 = 最大的满足 $dp[j] = \text{true}$ 的下标 $j$。

### 3.4 示例演算

![示例演算：逐值转移的可达集合](images/max_reward_walkthrough.svg)

以示例 2 `rewardValues = [1,6,4,3,2]` 为例，排序去重得 $[1,2,3,4,6]$，用集合表示 `dp` 为 true 的下标：

| 处理值 $v$ | 读区 $dp \cap [0, v-1]$ | 读区 $+ v$ | 合并后的 $dp$ |
|------|------|------|------|
| 初始 | — | — | $\{0\}$ |
| $v=1$ | $\{0\}$ | $\{1\}$ | $\{0,1\}$ |
| $v=2$ | $\{0,1\}$ | $\{2,3\}$ | $\{0,\dots,3\}$ |
| $v=3$ | $\{0,1,2\}$ | $\{3,4,5\}$ | $\{0,\dots,5\}$ |
| $v=4$ | $\{0,\dots,3\}$ | $\{4,\dots,7\}$ | $\{0,\dots,7\}$ |
| $v=6$ | $\{0,\dots,5\}$ | $\{6,\dots,11\}$ | $\{0,\dots,11\}$ |

最高位 $11$ ✓，对应取法 $1 \to 4 \to 6$（$x$ 轨迹 $0 \to 1 \to 5 \to 11$）。

> ⚠️ $v=6$ 时不能读下标 6：$x = 6$ 时 6 并不大于 $x$，位 6 是非法起点——这正是读区上界取 $v-1$ 而非 $v$ 的原因。

## 4. 算法细节

1. **`dp` 大小取 $2 v_{\max}$**：由 §3.2 推论 3，可达总和 $\le 2 v_{\max} - 1$；又 $j \le v-1 \Rightarrow j + v \le 2v - 1 < 2 v_{\max}$，**下标天然不越界**，无需上界保护。图省事直接开 4000 也行。
2. **去重可选、但推荐**：不去重也不会错——处理第一份 $v$ 的写入全落在 $[v, 2v-1]$，低区 $[0, v-1]$ 不变，第二份同值读到的读区与写出的结果完全相同，是一次 no-op；去重纯粹省时间（对拍可验证两者结果一致）。
3. **内层只需枚举 $[0, v-1]$**：读区之外的下标与转移无关，内层总开销 $\sum_v v \le \frac{V(V+1)}{2} \approx 2\times 10^6$（$V = 2000$）。
4. **答案的取法**：处理完全部值后，`dp` 中为 true 的最大下标即答案；$dp[0]$ 恒为 true，从高位向低位扫必有命中，无需特判。
5. **位运算视角（Q4 的钥匙）**：把 $dp[j]$ 视为大整数 $f$ 的第 $j$ 位，转移浓缩成一条
   $$f \mathrel{|}= \big(f \,\&\, (2^v - 1)\big) \ll v$$
   读低 $v$ 位、左移 $v$ 位、或回去。本篇值域小用不上；Q4 把 $n, v$ 放大到 $5\times10^4$ 时，它配合 `bitset` / Python 大整数就是标准解法。
6. **数值范围**：总和 $\le 3999$，C++ 用 `int` / `vector<char>` 足够，无溢出风险。

## 5. 正确性证明

**引理 1（顺序锁死）**：对互异值集合 $S$，以下等价：(a) $S$ 存在一种合法取法；(b) 将 $S$ 升序排列后，每个数严格大于其前缀和。

**证明**：(b)$\Rightarrow$(a)：按升序逐个取，第 $t$ 步的操作条件「$a_t >$ 当前总和」恰为前缀条件。(a)$\Rightarrow$(b)：设合法顺序为 $\pi$，取第 $t$ 个时要求 $a_t > x_{t-1} = a_1 + \cdots + a_{t-1} \ge a_s$（任意 $s < t$），故 $\pi$ 严格递增；互异值的严格递增全序唯一，即 $\pi$ 就是升序，其每步都满足操作条件即 (b)。∎

**引理 2（同值至多一次）**：一个可行方案中，同一个值至多被取一次。

**证明**：若 $a_s = a_t = v$（$s < t$），由引理 1 的 (a)$\Rightarrow$(b) 有 $a_t > a_s$，矛盾。∎

**引理 3（总和上界）**：任何可行方案的总和 $S \le 2 v_{\max} - 1$。

**证明**：设最后取的是 $v_{\text{last}}$，取它之前 $x = S - v_{\text{last}} < v_{\text{last}} \le v_{\max}$，故 $S < 2 v_{\max}$，整数即 $S \le 2 v_{\max} - 1$。∎

**定理（DP 不变式）**：按升序处理完去重数组的前 $i$ 个值后，$dp[j] = \text{true}$ 当且仅当存在只用这前 $i$ 个值的合法取法，其总和恰为 $j$。

**证明**：对 $i$ 归纳。$i = 0$ 时空方案总和为 0，仅有 $dp[0] = \text{true}$，成立。设对 $i$ 成立，处理第 $i+1$ 个值 $v$（升序去重数组中，前 $i$ 个值均 $< v$）：

- **可靠性（新 true 均真实可达）**：转移只新增 $dp[j+v]$（旧 $dp[j] = \text{true}$，$j \le v-1$）。由归纳假设存在合法方案 $S_0$，仅用前 $i$ 个值、总和为 $j$。考察 $S_0 \cup \{v\}$ 的升序排列：$v$ 是最大值、排在最后，其前缀和为 $j < v$；其余各数的前缀和与 $S_0$ 中一致（追加最大值不影响它们）。由引理 1，$S_0 \cup \{v\}$ 是合法方案且总和 $j + v$。旧 true 项对应的方案仍是前 $i+1$ 个值上的方案，保持成立。
- **完备性（真实可达均在 `dp` 中）**：设 $T$ 是仅用前 $i+1$ 个值、总和 $j'$ 的合法方案。若 $v \notin T$：$T$ 只用前 $i$ 个值，由归纳假设旧 $dp[j']$ 已为 true。若 $v \in T$：由引理 1 的 (a)$\Rightarrow$(b)，$T$ 升序排列满足前缀条件，$v$ 是 $T$ 的最大值、位于末位，其前缀和 $j' - v < v$，即 $j' - v \in [0, v-1]$；$T \setminus \{v\}$ 仅用前 $i$ 个值且仍满足前缀条件（去掉最大值不影响其余数的前缀和），由归纳假设处理 $v$ 之前 $dp[j'-v] = \text{true}$，转移恰好覆盖 $dp[j']$。∎

**推论**：处理完全部值后，$dp$ 的 true 下标集恰为所有可行方案的总和集合；由引理 3 它含于 $[0, 2 v_{\max} - 1]$，数组开 $2 v_{\max}$ 不漏；最大 true 下标即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n + V^2)$，其中 $V = v_{\max} \le 2000$。排序 $O(n \log n)$；去重后互异值至多 $\min(n, V)$ 个，每个 $v$ 的内层枚举 $[0, v-1]$ 共 $\sum v \le \frac{V(V+1)}{2} \approx 2\times 10^6$。即便偷懒不去重、内层全范围扫，$O(nV) \le 4\times 10^6$ 同样通过。
- **空间复杂度**：$O(V)$。`dp` 数组 $2 v_{\max} \le 4000$ 个布尔位；排序原地完成，无其他大数组。

## 7. 参考代码

### C++（排序去重 + 可行性背包）

```cpp
class Solution {
public:
    int maxTotalReward(vector<int>& rewardValues) {
        sort(rewardValues.begin(), rewardValues.end());
        rewardValues.erase(unique(rewardValues.begin(), rewardValues.end()),
                           rewardValues.end());
        int m = rewardValues.back();              // v_max
        vector<char> dp(2 * m);                   // 可达总和 <= 2m-1
        dp[0] = 1;
        for (int v : rewardValues) {
            for (int j = v - 1; j >= 0; j--) {    // 只读 [0, v-1]，与写区不相交
                if (dp[j]) dp[j + v] = 1;
            }
        }
        for (int j = 2 * m - 1; j >= 0; j--)
            if (dp[j]) return j;
        return 0;
    }
};
```

### Python

```python
class Solution:
    def maxTotalReward(self, rewardValues: List[int]) -> int:
        vals = sorted(set(rewardValues))
        m = vals[-1]
        dp = [False] * (2 * m)                   # 可达总和 <= 2m-1
        dp[0] = True
        for v in vals:
            for j in range(v - 1, -1, -1):       # 只读 [0, v-1]
                if dp[j]:
                    dp[j + v] = True
        return max(j for j, ok in enumerate(dp) if ok)
```

> 💡 位运算版（Q4 同款思路）：`f = 1`，对每个去重升序的 `v` 执行 `f |= (f & ((1 << v) - 1)) << v`，答案即 `f.bit_length() - 1`。把整条转移交给大整数的位级并行，代码更短、跑得更快。

## 8. 边界情况与易错点

1. **`dp` 只开 $v_{\max}$ 是最经典 WA**：可达总和能到 $2 v_{\max} - 1$，示例 2 的答案 11 就超过最大值 6——必须开 $2 v_{\max}$（或直接 4000）。
2. **忘记排序**：转移依赖「处理 $v$ 时已就绪的值都 $\le v$」，不排序则读写区逻辑全盘崩溃；排序方向必须是升序。
3. **把「严格大于」写成 $\ge$**：$x = 3$ 时 3 不能取；读区上界是 $v-1$ 不是 $v$。
4. **枚举顺序与防重复**：读写区 $[0, v-1]$ 与 $[v, 2v-1]$ 不相交，$j$ 正序、倒序都正确；但若**丢掉 $j < v$ 的条件**只写 `dp[j+v] |= dp[j]`，就退化成可重复选取的完全背包，总和还会越过 $2 v_{\max}$ 造成越界——条件本身就是防重复的闸门。
5. **不去重不会错、只会慢**：同值的第二份是 no-op（§4 第 2 点）；全同值输入如 `[5,5,...,5]` 时不去重白扫 $n$ 遍 $[0,4]$，无伤大雅但没必要。
6. **单元素 / 全同值**：`[7]` → 7，`[5,5,5]` → 5，转移自然覆盖，无需特判。
7. **C++ 细节**：总和 $\le 3999$ 用 `int` 足够；`vector<char>` 比 `vector<bool>` 语义直白；从高位向低位找第一个 true 时 $dp[0]$ 恒真兜底，循环必然返回。
