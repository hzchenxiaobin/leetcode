# LeetCode 商店的最少代价 题解

## 1. 题目概述

- **标题 / 题号**：商店的最少代价（#2483，medium）
- **链接**：https://leetcode.cn/problems/minimum-penalty-for-a-shop/
- **来源**：LeetCode 第 92 场双周赛 Q3
- **难度**：中等
- **标签**：字符串、前缀和

**题意**：顾客访问日志为字符串 `customers`（长度 $n$），第 $i$ 个字符为 `'Y'` 表示第 $i$ 小时有顾客到达，`'N'` 表示没有。若商店在第 $j$ 小时关门（$0 \le j \le n$，第 $j$ 小时及之后处于关门状态），代价为：

- 开门期间（第 $0 \sim j-1$ 小时）每小时没有顾客（`'N'`）：代价 $+1$；
- 关门期间（第 $j \sim n-1$ 小时）每小时有顾客（`'Y'`）：代价 $+1$。

返回代价**最小**前提下的**最早**关门时间 $j$。

**约束**：

- $1 \le n \le 10^5$
- `customers` 只包含 `'Y'` 与 `'N'`

## 2. 示例

**示例 1**

```text
输入：customers = "YYNY"
输出：2
解释：各关门时刻的代价：j=0 → 3，j=1 → 2，j=2 → 1，j=3 → 2，j=4 → 1。
j=2 与 j=4 并列最小，取更早的 j=2。
```

**示例 2**

```text
输入：customers = "NNNNN"
输出：0
解释：从没有顾客，第 0 小时关门（全程不营业）代价为 0。
```

**示例 3**

```text
输入：customers = "YYYY"
输出：4
解释：每小时都有顾客，营业到底（j=4，即第 4 小时起才关门）代价为 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $j \in [0, n]$ 独立计算代价：扫前缀数 `'N'`、扫后缀数 `'Y'`，取最小——$O(n^2)$，$n = 10^5$ 时 $10^{10}$ 次操作不可行。瓶颈在于前缀/后缀计数被每个 $j$ 重复计算，这正是前缀和（或等价的增量维护）的用武之地。

### 3.2 核心观察：代价 = 前缀 N 数 + 后缀 Y 数

![核心观察：关门时刻把字符串切成两段](images/bw92_q3_prefix_suffix.svg)

固定关门时刻 $j$，字符串被切成前缀 $s[0..j)$ 与后缀 $s[j..n)$：

$$penalty(j) = \underbrace{\#\{t < j : s[t] = \texttt{N}\}}_{prefixN(j)} + \underbrace{\#\{t \ge j : s[t] = \texttt{Y}\}}_{suffixY(j)}$$

两个计数器在 $j \to j+1$ 时的变化量都只跟字符 $s[j]$ 有关：它从前缀挪到后缀——若它是 `'N'`，`prefixN` 加 1（`suffixY` 不变）；若它是 `'Y'`，`suffixY` 减 1（`prefixN` 不变）。于是**一遍扫描**就能从 $penalty(0)$ 递推到 $penalty(n)$，边扫边维护最小值与最早下标。

### 3.3 算法流程

```text
1. suffixY = 全串 'Y' 的个数；prefixN = 0
2. best = 0，bestPenalty = suffixY            # j = 0：全程关门
3. for j = 1 .. n：
       若 s[j−1] == 'N'：prefixN++
       否则：suffixY−−
       p = prefixN + suffixY
       若 p < bestPenalty：best = j，bestPenalty = p   # 严格小于 → 保最早
4. 返回 best
```

### 3.4 示例演算

![示例演算：YYNY 的五个候选时刻](images/bw92_q3_walkthrough.svg)

以 `"YYNY"` 演算：初值 $penalty(0) = suffixY = 3$（三个 Y）。$j=1$：$s[0]=Y$，$suffixY \to 2$，$p = 0 + 2 = 2$；$j=2$：$s[1]=Y$，$suffixY \to 1$，$p = 0 + 1 = 1$；$j=3$：$s[2]=N$，$prefixN \to 1$，$p = 1 + 1 = 2$；$j=4$：$s[3]=Y$，$suffixY \to 0$，$p = 1 + 0 = 1$。最小值 1 首次出现在 $j = 2$（严格小于比较保证不会被 $j=4$ 覆盖），返回 2。示例 2 `"NNNNN"`：$penalty(0) = 0$ 已是最小，答案 0；示例 3 `"YYYY"`：$penalty(4) = prefixN(4) = 0$，答案 4。

## 4. 算法细节

1. **初值取 $j = 0$**：全程关门的代价 = 全串 `Y` 的个数；它也是递推的起点（$prefixN = 0$）。
2. **严格小于才更新**：并列最小取更早的 $j$，用 `<` 而非 `<=`。
3. **增量更新别写反**：$s[j-1]$ 是「刚进入开门时段」的字符——`'N'` 才让 `prefixN` 增、`'Y'` 才让 `suffixY` 减；写反会把代价算成「前缀 Y + 后缀 N」。
4. **等价的前缀和写法**：预处理 $preN[j]$（前 $j$ 个字符中 N 的个数）与 $sufY[j]$（从 $j$ 起的 Y 个数），再枚举 $j$ 取 $preN[j] + sufY[j]$——两遍 $O(n)$，与增量法等价，看个人口味。
5. **无须担心负数/溢出**：$penalty \le n \le 10^5$，`int` 足够。
6. **答案范围是 $[0, n]$**：$j = n$ 表示「第 $n$ 小时（最后一小时之后）才关门」即全程营业，别漏掉这个候选。

## 5. 正确性证明

**引理 1（代价分解）**：关门时刻 $j$ 的代价 $penalty(j) = prefixN(j) + suffixY(j)$。

**证明**：开门时段为第 $0 \sim j-1$ 小时（恰为前缀 $s[0..j)$），其间每个 `'N'` 贡献 1；关门时段为第 $j \sim n-1$ 小时（后缀 $s[j..n)$），其间每个 `'Y'` 贡献 1。两类贡献互不相交（不同小时）且覆盖全部代价来源。∎

**引理 2（增量公式）**：$penalty(j) - penalty(j-1) = [s[j-1] = \texttt{Y}] - [s[j-1] = \texttt{N}]$，即字符为 `Y` 时代价减 1、为 `N` 时加 1。

**证明**：由引理 1，$prefixN(j) = prefixN(j-1) + [s[j-1]=\texttt{N}]$；$suffixY(j) = suffixY(j-1) - [s[j-1]=\texttt{Y}]$（字符 $s[j-1]$ 从后缀移入前缀）。相加即得。∎

**定理**：一遍扫描维护的最小值及其首次出现的下标，等于「代价最小的最早关门时刻」。

**证明**：算法按 $j = 0, 1, \dots, n$ 顺序计算每个 $penalty(j)$（引理 1 与引理 2 保证数值正确），维护过程只在遇到**严格更小**的代价时更新 `best`。设最优值为 $p^*$、其最早出现下标为 $j^*$。$j < j^*$ 时 $penalty(j) > p^*$（否则 $j^*$ 不是最早），任何更新后的 `bestPenalty` $\ge p^*$ 且在 $j^*$ 处必有 $penalty(j^*) = p^* <$ 当前 `bestPenalty`（当前值来自某个 $j' < j^*$，其代价 $> p^*$），故 `best` 必被更新为 $j^*$；$j > j^*$ 时 $penalty(j) \ge p^*$（$p^*$ 是最小值），严格小于比较不再触发更新。故返回 $j^*$。∎

## 6. 复杂度分析

- **时间**：$O(n)$——初值统计 $O(n)$ + 一遍递推 $O(n)$。
- **空间**：$O(1)$ 额外（只维护两个计数器与最优值）；前缀和写法需 $O(n)$ 数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int bestClosingTime(string customers) {
        int n = (int)customers.size();
        int suffixY = 0;
        for (char c : customers) suffixY += (c == 'Y') ? 1 : 0;
        int prefixN = 0;
        int best = 0, bestPenalty = suffixY;          // j = 0：全程关门
        for (int j = 1; j <= n; ++j) {
            if (customers[j - 1] == 'N') ++prefixN;   // s[j−1] 进入开门前缀
            else --suffixY;                           // s[j−1] 移出关门后缀
            int penalty = prefixN + suffixY;          // 关门时刻 j 的代价
            if (penalty < bestPenalty) {              // 严格小于 → 保留最早时刻
                bestPenalty = penalty;
                best = j;
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def bestClosingTime(self, customers: str) -> int:
        suffix_y = customers.count('Y')
        prefix_n = 0
        best, best_penalty = 0, suffix_y          # j = 0：全程关门
        for j in range(1, len(customers) + 1):
            if customers[j - 1] == 'N':
                prefix_n += 1                     # s[j−1] 进入开门前缀
            else:
                suffix_y -= 1                     # s[j−1] 移出关门后缀
            penalty = prefix_n + suffix_y         # 关门时刻 j 的代价
            if penalty < best_penalty:            # 严格小于 → 保留最早时刻
                best, best_penalty = j, penalty
        return best
```

> 💡 两份代码均通过官方三个示例，并与「对每个 $j$ 独立重扫前缀后缀」的暴力对拍 2000 组随机串（$n \le 12$），结果完全一致。

## 8. 边界情况与易错点

1. **并列最小取最早**：比较必须严格小于（`<`），写成 `<=` 会在 `"YYNY"` 上返回 4 而不是 2。
2. **$j = 0$ 与 $j = n$ 两个端点候选**：$j=0$ 是初值（全程关门），$j=n$ 是循环最后一轮（全程营业），漏掉任何一端都可能错——如 `"NNNNN"` 答案 0、`"YYYY"` 答案 4。
3. **增量方向**：`'Y'` 使代价**减** 1（它从「关门罚」变成「开门不罚」），`'N'` 使代价**加** 1；方向写反会把最优关门时刻系统性偏移。
4. **第 $j$ 小时的归属**：题面明确「第 $j$ 小时及之后处于关门状态」，即 $s[j]$ 属于关门时段——递推时移动的是 $s[j-1]$，别错挪 $s[j]$。
5. **空串不会出现**（$n \ge 1$），但防御性代码中 $n = 0$ 时返回 0 即可（循环体不执行）。
6. **不必真的建前缀和数组**：两计数器增量法空间 $O(1)$，前缀和数组是「能用但多余」的选择。
