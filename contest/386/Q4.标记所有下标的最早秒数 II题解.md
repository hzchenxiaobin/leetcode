# LeetCode 标记所有下标的最早秒数 II 题解

## 1. 题目概述

- **标题 / 题号**：标记所有下标的最早秒数 II（#3049，hard）
- **链接**：https://leetcode.cn/problems/earliest-second-to-mark-indices-ii/
- **来源**：LeetCode 第 386 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、二分查找、堆（优先队列）

**题意**：给定下标从 1 开始的数组 `nums`（长 $n$）与 `changeIndices`（长 $m$）。初始时 `nums` 所有下标均未标记，目标是标记**全部**下标。第 $1 \sim m$ 秒中每一秒 $s$ 可执行**之一**：

1. 任选下标 $i \in [1, n]$，将 $\text{nums}[i]$ 减 1；
2. 将 $\text{nums}[\text{changeIndices}[s]]$ 设为**任意非负整数**（下文称**清零**）；
3. 任选一个满足 $\text{nums}[i] = 0$ 的下标 $i$ 并**标记**之；
4. 什么都不做。

返回标记所有下标的**最早秒数**（在 $[1, m]$ 内）；无法做到返回 $-1$。

**约束**：

- $1 \le n \le 5000$
- $0 \le \text{nums}[i] \le 10^9$
- $1 \le m \le 5000$
- $1 \le \text{changeIndices}[i] \le n$

> 💡 与本场 [Q3（3048. I）](https://leetcode.cn/problems/earliest-second-to-mark-indices-i/)的两处关键差异：① **标记不再绑定秒**——任意秒都能标记任意已清零的下标，不再要求 $\text{changeIndices}[s]$ 恰等于该下标；② 多了「设为任意非负整数」这记重拳。$\text{nums}[i]$ 高达 $10^9$，逐次减 1 根本不现实，必须靠清零一键归零——这正是本题升为困难的原因。

      秒 3~5 把 nums[4] 减两次、nums[3] 减一次；秒 6/7 标记下标 3、4。

## 3. 解题思路

### 3.1 暴力思路：逐秒决策的搜索

每一秒有「减 1（$n$ 种）+ 清零（1 种）+ 标记（至多 $n$ 种）+ 发呆」共 $O(n)$ 种选择，直接搜索操作序列是 $n^m$ 级爆炸；正向逐秒模拟做决策同样不可行。更糟的是 $\text{nums}[i]$ 可达 $10^9$，硬磨式模拟连边都摸不到。

和 Q3 一样，该问的问题其实是判定：「**只给前 $x$ 秒，能否标记完所有下标？**」可行性关于 $x$ 单调（$x$ 秒够 $\Rightarrow$ $x+1$ 秒发呆即可），于是**二分答案**：先 $\text{check}(m)$ 判死返回 $-1$，再二分最小可行 $x$。外壳照搬 Q3，全部难点浓缩为一个高效判定 $\text{check}(x)$——而这个 check 与 Q3 的前缀不等式**完全不同**。

### 3.2 核心观察一：清零的「省时账本」

![省时账本：硬磨与一键清零的成本对比](images/mark_indices2_ledger.svg)

**观察 1（基准账）**：完全不碰清零，总耗时为 $\sum \text{nums} + n$——每个值磨到 0 需 $\text{nums}[v]$ 秒减 1，再花 $n$ 秒逐个标记。记这个基准为 $\text{total}$。

**观察 2（清零用在哪最划算）**：清零只能作用于 $\text{nums}[\text{changeIndices}[s]]$。对下标 $v$ 而言：

- 硬磨要 $\text{nums}[v] + 1$ 秒（$\text{nums}[v]$ 次减 1 + 1 次标记）；
- 改用清零只要 **2 秒**（1 秒清零 + 1 秒**更晚**的标记），净省 $\text{nums}[v] - 1$ 秒；
- 清零应打在 $v$ 在前 $x$ 秒的**最早出现秒** $\text{first}(v)$——出现越早，留给「更晚标记」的窗口 $(\text{first}(v), x]$ 越大，支配一切更晚的出现秒；
- 值为 $0$ 的下标别用（净省 $-1$ 秒，倒赔）；值为 $1$ 的下标白忙（净省 $0$ 秒，无害）。

### 3.3 核心观察二：每个入选者要占 2 秒——后缀容量不等式

![后缀容量：每个入选者在后缀里占 2 秒](images/mark_indices2_suffix_quota.svg)

清零不是免费午餐：入选者 $v$ 占掉第 $\text{first}(v)$ 秒做清零，其标记必须落在开区间 $(\text{first}(v), x]$ 内的另一秒。于是对**任意**后缀 $[\tau, x]$：

$$2 \times \bigl|\{\,v \text{ 入选} : \text{first}(v) \ge \tau\,\}\bigr| \;\le\; x - \tau + 1$$

**直观**：$\text{first}(v) \ge \tau$ 的每个入选者，其清零秒与标记秒都被锁进 $[\tau, x]$（标记 > 清零 ≥ $\tau$），两两互异，$k$ 个人就要 $2k$ 秒，后缀只有 $x - \tau + 1$ 秒。这正是「带截止期的单位任务调度」的 **Hall 容量条件**在时间轴上的影子。

### 3.4 核心观察三：反向扫描 + 小根堆反悔

![反向扫描与小根堆反悔流程](images/mark_indices2_reverse_heap.svg)

如何求「满足后缀容量的最大省时集合」？**把时间轴倒过来**：从第 $x$ 秒倒着扫回第 1 秒，维护空闲名额 $\text{cnt}$（已扫过秒中还能当标记用的数量）与一个存 $\text{nums}[v]$ 的小根堆：

- 遇到**非最早出现秒**（或该下标值为 0）：这一秒随时可当标记用 → $\text{cnt} \mathrel{+}= 1$；
- 遇到 $v$ 的最早出现秒且 $\text{nums}[v] > 0$：入堆并记账 $\text{total} \mathrel{-}= \text{nums}[v] - 1$；若**堆大小超过 $\text{cnt}$**（标记名额不够，等价于 $2 \times \text{堆大小} > \text{后缀长度}$），弹出堆里省得最少的 $w$：$\text{total} \mathrel{+}= w - 1$，同时 $\text{cnt} \mathrel{+}= 1$（被踢者的清零秒从「占用」变回「空闲」，还给名额池）。

扫完后 $\text{total} \le x$ 即可行。

> 💡 **为什么贪心最优？** 时间倒流后，每个入选者像一个**截止期为** $d_v = \lfloor (x - \text{first}(v) + 1)/2 \rfloor$ 的单位任务，收益 $\text{nums}[v] - 1$——超员时踢收益最小的，正是经典的**带权 Moore–Hodgson 反悔贪心**（同款套路见 630. 课程表 III）。证明见 §5 引理 3。

### 3.5 示例演算

![示例 1 演算：check(6) 恰好卡线通过](images/mark_indices2_example_walk.svg)

以示例 1 `nums = [3,2,3], changeIndices = [1,3,2,2,2,2,3]` 演算，基准 $\text{total} = 8 + 3 = 11$：

**check(6)**（倒序扫，$\text{first}$：下标 1→秒 1，下标 3→秒 2，下标 2→秒 3）：

| 秒 | ci[s] | 动作 | 小根堆 | total | cnt |
|----|-------|------|--------|-------|-----|
| 6 | 2 | 非首次 → cnt+1 | { } | 11 | 1 |
| 5 | 2 | 非首次 → cnt+1 | { } | 11 | 2 |
| 4 | 2 | 非首次 → cnt+1 | { } | 11 | 3 |
| 3 | 2 | 首次 ✓ 入堆 2（省 1 秒） | {2} | 10 | 3 |
| 2 | 3 | 首次 ✓ 入堆 3（省 2 秒） | {2,3} | 8 | 3 |
| 1 | 1 | 首次 ✓ 入堆 3（省 2 秒） | {2,3,3} | 6 | 3 |

$\text{total} = 6 \le 6$ ✓ 可行——三个候选恰好挤进三个名额，对应官方方案：秒 1/2/3 清零、秒 4/5/6 标记。

**check(5)**：倒序只有秒 4、5 贡献名额（cnt 停在 2），扫到秒 1 时堆 $\{2,3,3\}$ 超员 → 弹最小 2，$\text{total}$ 回到 7；$7 > 5$ ✗ 不可行。故答案 **6**。

再看示例 2 `nums = [0,0,1,2], changeIndices = [1,2,1,2,1,2,1,2]`：前 7 秒中下标 1、2 的最早出现秒上值均为 0，按守则跳过清零（否则倒赔）；下标 3、4 从未出现，走基准账硬磨。$\text{total} = 3 + 4 = 7 \le 7$ ✓，而 $\text{check}(6)$ 因 $\text{total} = 7 > 6$ 失败，答案 7。

## 4. 算法细节

1. **二分外壳**：先做一次 $\text{check}(m)$——为假直接返回 $-1$；为真则 $[1, m]$ 内必有解，闭区间二分最小可行 $x$。
2. **check 的两趟倒序扫描**：第一趟从 $x-1$ 倒扫到 $0$ 求 $\text{first}[v]$（倒序写入，最终留在数组里的就是最早出现）；第二趟再倒序扫一遍维护「小根堆 + 名额 + 账本」。秒号统一 0 起，公式中 1 起，注意换算。
3. **cnt 的记账规则**：非最早出现秒 → $\text{cnt} \mathrel{+}= 1$；最早出现秒但 $\text{nums}[v] = 0$ → 同样 $\text{cnt} \mathrel{+}= 1$（这秒没法当清零用）；被踢者的清零秒解冻 → $\text{cnt} \mathrel{+}= 1$。**不变式**：$\text{cnt} = \text{已扫后缀长度} - \text{堆大小}$，故「堆大小 > cnt」与「$2 \times \text{堆大小} > \text{后缀长度}$」严格等价。
4. **权为 0 / 负的候选**：$\text{nums}[v] = 0$ 直接跳过（净省 $-1$ 倒赔）；$\text{nums}[v] = 1$ 净省 0，入堆无害（超员时必是第一个被踢的）。
5. **溢出**：$\sum \text{nums}$ 最大 $5000 \times 10^9 = 5 \times 10^{12}$，C++ 记账必须 `long long`；Python 无此虞。
6. **未出现的下标不需特判**：与 3048 相反，标记不依赖 `changeIndices`，没出现过的下标照样走「硬磨 + 标记」的基准账，`first` 初值 $-1$ 天然把它们排除在候选之外。

## 5. 正确性证明

**引理 1（单调性）**：$\text{check}(x)$ 为真 $\Rightarrow \text{check}(x+1)$ 为真。

**证明**：取前 $x$ 秒的可行方案，第 $x+1$ 秒执行「什么都不做」，其余不变，仍是前 $x+1$ 秒的可行方案。∎

**引理 2（账本等价）**：记 $\text{first}[v]$ 为下标 $v$ 在前 $x$ 秒内的最早出现秒。前 $x$ 秒能标记全部下标 $\iff$ 存在**入选集** $H$（选用清零的下标集合，$H \subseteq \{v : \text{first}[v] \text{ 存在}\}$）同时满足：

- **容量**：对一切 $\tau \in [1, x]$，$2\,|\{v \in H : \text{first}[v] \ge \tau\}| \le x - \tau + 1$；
- **总量**：$n + |H| + \sum_{v \notin H} \text{nums}[v] \le x$。

**证明**：

（$\Rightarrow$）任取可行方案，令 $H$ 为其中被清零的下标集。$v \in H$ 的清零秒 $o_v \ge \text{first}[v]$，标记秒 $M_v > o_v$。当 $\text{first}[v] \ge \tau$ 时 $o_v \ge \tau$ 且 $M_v > o_v \ge \tau$，即 $v$ 在 $[\tau, x]$ 内占用两个互异秒；不同下标占用的秒互不相同，故容量条件成立。整个方案恰用 $|H|$ 个清零秒、$n$ 个标记秒、$\sum_{v \notin H} \text{nums}[v]$ 个减 1 秒（互异且都在 $[1,x]$ 内），故总量条件成立。

（$\Leftarrow$）设 $H$ 满足两条件，清零统一放在 $\text{first}[v]$。先为入选者分配标记秒：建二部图，$v$ 连向 $(\text{first}[v], x]$ 中不属于任何 $\text{first}[w]\ (w \in H)$ 的秒。对任意 $T \subseteq H$，设 $f$ 为 $T$ 中最小的 $\text{first}$，记 $H_f = \{v \in H : \text{first}[v] \ge f\}$，则 $T$ 的邻域包含 $(f, x]$ 去掉其中至多 $|H_f| - 1$ 个清零秒（$\text{first}$ 两两互异，仅 $f$ 本身不在开区间内），于是由容量条件 $2|H_f| \le x - f + 1$：

$$|N(T)| \ge (x - f) - (|H_f| - 1) \ge \frac{x - f + 1}{2} \ge |H_f| \ge |T|$$

Hall 条件成立，可为每个 $v \in H$ 分配互异标记秒 $M_v \in (\text{first}[v], x]$。再把其余 $x - 2|H|$ 秒自左向右分成两段：前 $\sum_{v \notin H} \text{nums}[v]$ 秒做硬磨者的减 1，后 $n - |H|$ 秒做硬磨者的标记——由总量条件秒数足够，且每个硬磨下标的减 1 全部先于其标记。所得方案可行。∎

**引理 3（截止期改写与反悔贪心最优性）**：对候选 $v$（$\text{first}[v]$ 存在且 $\text{nums}[v] > 0$），令权 $w_v = \text{nums}[v] - 1 \ge 0$、截止期 $d_v = \lfloor (x - \text{first}[v] + 1)/2 \rfloor$。则：

（a）$H$ 满足引理 2 的容量条件 $\iff$ 对一切 $d \ge 0$：$|\{v \in H : d_v \le d\}| \le d$；

（b）满足（a）的集合族构成**拟阵**（横贯拟阵：$v$ 可匹配到槽位 $[1, d_v]$ 中的任一个，可行即存在完美匹配，由 Rado 定理即得交换公理）；

（c）「按 $\text{first}$ 从大到小（即 $d_v$ 从小到大）逐个入小根堆；一旦堆大小超过已扫过的空闲名额 $\text{cnt}$ 就弹出堆中最小权」最终得到**最大权**可行集，即 $\sum_{v \in H} w_v$ 最大。

**证明**：

（a）$\text{first}[v] \ge \tau \iff d_v \le \lfloor (x - \tau + 1)/2 \rfloor$，且 $\tau$ 与 $d$ 通过 $\tau = x - 2d$ 一一对应（$\tau = x - 2d + 1$ 处的约束被 $\tau = x - 2d$ 处的约束蕴含）。又倒序扫描中 $\text{cnt} = \text{后缀长度} - \text{堆大小}$，故「堆大小 > cnt」$\iff$ $2 \times \text{堆大小} > \text{后缀长度}$ $\iff$ $|\{d \le d_v\}| > d_v$——算法执行的正是（a）中前缀容量的在线检查。

（c）对首个超员时刻归纳。设任务 $j$ 入堆时超员，$m$ 为当时堆（含 $j$）的最小权者并被踢出。关键事实：**去掉 $m$ 后，贪心在此后的堆演化与原过程完全一致**（踢出后堆内容相同，后续入堆/踢出照旧）。因此只需证明：存在不包含 $m$ 的最大权可行集。任取最大权可行集 $B$：

- 若 $m \notin B$，得证。
- 若 $j \notin B$：令 $B' = B - m + j$。因 $d_j \ge d_m$（$m$ 截止期不晚于当前层），把 $m$ 换成 $j$ 后每个前缀计数不增，$B'$ 可行；又 $w_j \ge w_m$（$m$ 是最小权），$w(B') \ge w(B)$，故 $B'$ 是不含 $m$ 的最大权可行集。
- 若 $j, m \in B$：由 $|B \cap \{d \le d_j\}| \le d_j < d_j + 1 = |H \cup \{j\}|$（$H$ 为踢出前的堆），必存在 $x \in (H \cup \{j\}) \setminus B$，且 $w_x \ge w_m$。将 $B$ 中的 $m$ 逐层换成这类 $x$ 并在容量不足处顺延交换（经典的 Moore–Hodgson 交换链），可得权不变劣、不含 $m$ 的可行集。

归纳到底，贪心的最终堆是最大权可行集。（由（b），这也可由拟阵「按权降序 + 可行性判定」的经典贪心殊途同归。）∎

**定理**：$\text{check}(x)$ 为真 $\iff$ 前 $x$ 秒能标记所有下标；二分返回的即最早秒数，$\text{check}(m)$ 为假时无解返回 $-1$。

**证明**：由引理 2，可行性 $\iff$ 存在满足容量与总量的 $H$；由引理 3，反悔贪心求出满足容量约束的最大省时集合，故 $\text{total} \le x$ $\iff$ 存在满足两个条件的 $H$（若贪心的最优 $H^*$ 都压不到 $x$，任何满足容量的 $H$ 都压不到，而可行方案导出的 $H$ 必满足两个条件，矛盾）。于是 check 与可行性等价；再由引理 1 的单调性，二分收敛到最小可行 $x$ 即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \log m \log n)$。二分 $O(\log m)$ 次；每次 check 两趟倒序扫描共 $O(m)$，其中每个候选秒至多一次堆操作 $O(\log n)$。$n, m \le 5000$ 时总量约 $10^6$ 量级，轻松通过。
- **空间复杂度**：$O(n)$。`first` 数组 + 小根堆。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int earliestSecondToMarkIndices(vector<int>& nums, vector<int>& changeIndices) {
        int n = nums.size(), m = changeIndices.size();
        long long base = n;                          // 基准账：Σnums + n（硬磨 + 逐个标记）
        for (int v : nums) base += v;

        // check(x)：只使用前 x 秒能否标记所有下标
        auto check = [&](int x) -> bool {
            vector<int> first(n, -1);                // first[v]：v 在前 x 秒的最早出现秒号(0 起)
            for (int s = x - 1; s >= 0; --s) first[changeIndices[s] - 1] = s;
            priority_queue<long long, vector<long long>, greater<long long>> pq;
            long long total = base;                  // 当前方案的总耗时（会超 int）
            int cnt = 0;                             // 空闲名额：已扫过秒中可当标记用的数量
            for (int s = x - 1; s >= 0; --s) {
                int v = changeIndices[s] - 1;
                if (first[v] == s && nums[v] > 0) {  // v 的最早出现秒且清零有赚
                    pq.push(nums[v]);
                    total -= nums[v] - 1;            // 净省 nums[v] − 1 秒
                    if ((int)pq.size() > cnt) {      // 标记名额不够：踢掉省得最少的
                        total += pq.top() - 1;
                        pq.pop();
                        ++cnt;                       // 被踢者的清零秒还给名额池
                    }
                } else {
                    ++cnt;                           // 这秒不当清零用，随时可标记
                }
            }
            return total <= x;
        };

        if (!check(m)) return -1;                    // 整个 m 秒都做不到，直接判死
        int lo = 1, hi = m;
        while (lo < hi) {                            // 二分最小可行 x
            int mid = lo + (hi - lo) / 2;
            if (check(mid)) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def earliestSecondToMarkIndices(self, nums: List[int], changeIndices: List[int]) -> int:
        n, m = len(nums), len(changeIndices)
        base = sum(nums) + n                        # 基准账：硬磨 + 逐个标记

        def check(x: int) -> bool:                  # 只用前 x 秒能否全部标记
            first = [-1] * n                        # first[v]：v 在前 x 秒的最早出现秒号
            for s in range(x - 1, -1, -1):
                first[changeIndices[s] - 1] = s
            heap, cnt, total = [], 0, base          # cnt：空闲名额（可当标记秒）
            for s in range(x - 1, -1, -1):
                v = changeIndices[s] - 1
                if first[v] == s and nums[v] > 0:   # 最早出现秒且清零有赚
                    heapq.heappush(heap, nums[v])
                    total -= nums[v] - 1            # 净省 nums[v] − 1 秒
                    if len(heap) > cnt:             # 名额不够：踢掉省得最少的
                        total += heapq.heappop(heap) - 1
                        cnt += 1                    # 被踢者的清零秒还给名额池
                else:
                    cnt += 1
            return total <= x

        if not check(m):
            return -1
        lo, hi = 1, m
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

> 💡 先做一次 `check(m)` 有双重作用：不可行时提前返回 $-1$，同时保证后续二分闭区间内必然存在可行解，循环结束时 `lo` 即答案。另注意 `first` 是在**前 $x$ 秒**范围内求的，不是前 $m$ 秒。

## 8. 边界情况与易错点

1. **前缀和溢出**：$\sum \text{nums}$ 最大 $5000 \times 10^9 = 5 \times 10^{12}$，C++ 用 `int` 直接判死，记账必须 `long long`。
2. **被踢后 cnt 要 +1**：最易漏的一行。被踢者的清零秒从「占用」变回「空闲」，名额池回血；漏掉它会导致超员判定过严、答案偏大。
3. **值为 0 的候选要跳过**：清零花 1 秒却没省任何减 1（基准只要 1 秒标记），净省 $-1$ 倒赔，当普通秒计名额即可。值为 1 净省 0，入堆无害。
4. **未出现的下标不需特判不可行**：与 3048 相反！标记不依赖 `changeIndices`，它们走基准账硬磨即可；`first` 的 $-1$ 初值天然将其排除在候选外。
5. **first 必须在「前 x 秒」内求**：二分中途 $x < m$，若误用前 $m$ 秒的 first，会把窗口外的秒当成候选。
6. **别照搬 3048 的 last 思路**：I 里标记绑定出现秒、要挪到**最晚**出现秒；II 里标记自由、清零要打在**最早**出现秒——一动一静，方向恰好相反。
7. **先 check(m) 再二分**：若直接二分不判 $-1$，区间内可能无解，循环结束返回的 `lo` 是假答案。
8. **倒序写入求 first**：`for s in range(x-1, -1, -1): first[ci[s]] = s` 依赖「后写的覆盖先写的」，最终留下最小秒号；若正序扫需另行判空，易错。
