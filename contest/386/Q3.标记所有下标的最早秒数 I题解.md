# LeetCode 标记所有下标的最早秒数 I 题解

## 1. 题目概述

- **标题 / 题号**：标记所有下标的最早秒数 I（#3048，medium）
- **链接**：https://leetcode.cn/problems/earliest-second-to-mark-indices-i/
- **来源**：LeetCode 第 386 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找、贪心、调度

**题意**：给定下标从 1 开始的数组 `nums`（长 $n$）与 `changeIndices`（长 $m$）。初始时 `nums` 所有下标均未标记，目标是标记**全部**下标。第 $1 \sim m$ 秒中每一秒 $s$ 可执行**之一**：

1. 任选下标 $i \in [1, n]$，将 $\text{nums}[i]$ 减 1；
2. 若 $\text{nums}[\text{changeIndices}[s]] = 0$，标记下标 $\text{changeIndices}[s]$；
3. 什么都不做。

返回标记所有下标的**最早秒数**（在 $[1, m]$ 内）；无法做到返回 $-1$。

**约束**：

- $1 \le n \le 2000$
- $0 \le \text{nums}[i] \le 10^9$
- $1 \le m \le 2000$
- $1 \le \text{changeIndices}[i] \le n$

> 💡 读题关键：操作 2 的目标是**由该秒的 changeIndices 决定的**——第 $s$ 秒只能标记 $\text{changeIndices}[s]$ 这一个下标，还不能自由挑选；而减 1 操作任意秒可用、任意下标可选。这种「半受限」结构正是本题的突破口。

## 2. 示例

**示例 1**

```text
输入：nums = [2,2,0], changeIndices = [2,2,2,2,3,2,2,1]
输出：8
解释：秒 1~4 把 nums[1]、nums[2] 各减到 0；秒 5 标记下标 3（本来就是 0）；
      秒 6 标记下标 2；秒 7 发呆；秒 8 标记下标 1。最早第 8 秒全部标记。
```

**示例 2**

```text
输入：nums = [1,3], changeIndices = [1,1,1,2,1,1,1]
输出：6
解释：秒 1~3 把 nums[2] 减 3 次到 0；秒 4 标记下标 2；秒 5 把 nums[1] 减到 0；
      秒 6 标记下标 1。
```

**示例 3**

```text
输入：nums = [0,1], changeIndices = [2,2,2]
输出：-1
解释：下标 1 从不在 changeIndices 中出现，永远无法被标记。
```

## 3. 解题思路

### 3.1 暴力思路：逐秒三选一的搜索

每一秒有「减 1 / 标记 / 发呆」三类选择，直接搜索全部操作序列是指数级爆炸（$3^m$）。即便加上「标记只能发生在值恰好为 0 的出现秒」这类剪枝，正向模拟仍要逐秒做决策，$m = 2000$ 时毫无希望。

暴力失败的根源：**问错了问题**。题目要求的是「最早完成的时刻」，而不是「某一秒该做什么」。一旦把问题改成判定——「只给前 $t$ 秒，能否标记完所有下标？」——结构立刻显现。

### 3.2 关键建模：标记的双重硬约束

![每秒三种操作与标记的硬约束](images/mark_indices_ops_timeline.svg)

把题面翻译成约束语言：

- 下标 $i$ 想被标记，必须挑一个**满足 $\text{changeIndices}[s] = i$ 的秒** $s$，且**那一时刻** $\text{nums}[i]$ 已被减到 0；
- 每秒只能承载一个操作：减 1 与标记不能挤在同一秒；
- $\text{nums}[i]$ 要从初值减到 0 恰需 $\text{nums}[i]$ 次「减 1」，且这些减 1 **必须全部落在标记之前**。

于是「前 $t$ 秒能否完成」是一个纯粹的**带截止期的调度问题**：每个下标是一件任务，需要 $\text{nums}[i]$ 个「减 1」工时 + 1 个「标记」工位，标记工位只能放在该下标的出现秒上，减 1 工时必须排在它之前。

### 3.3 核心观察一：判定关于秒数单调 ⇒ 二分答案

**单调性**：若前 $t$ 秒可行，则前 $t+1$ 秒也可行——原方案照搬、第 $t+1$ 秒发呆即可。

> 💡 「求最早时刻」+「可行性关于时刻单调」= 标准的**二分答案**框架：二分最小可行 $t$；若 $\text{check}(m)$ 为假则返回 $-1$。剩余全部难点浓缩为一个高效判定 $\text{check}(t)$。

### 3.4 核心观察二：标记规范化到「最晚出现秒」（交换论证）

![交换论证：标记推迟到最晚出现秒](images/mark_indices_exchange_argument.svg)

固定 $t$，记 $\text{last}[i]$ 为下标 $i$ 在前 $t$ 秒中**最晚**的出现秒。

**断言**：只需检验「每个下标都在各自的 last 秒标记」这一种方案。

**交换论证**：任取可行方案，设下标 $i$ 被标记在出现秒 $s' < \text{last}[i]$。看 $\text{last}[i]$ 这一秒原来在干什么——

- 若是「减 1」（对某下标 $j$）或「发呆」：把 $i$ 的标记挪到 $\text{last}[i]$，原操作移到 $s'$。$\text{nums}$ 只减不增，$i$ 在 $s'$ 时已是 0，在更晚的 $\text{last}[i]$ 仍是 0，标记合法；被挪的减 1 只是**提前**，减 1 只需早于 $j$ 自己的标记，提前无害；
- 若是「标记 $i$ 本身」（$\text{changeIndices}[\text{last}[i]] = i$，只能标 $i$）：相当于重复标记，直接交换无影响。

逐个下标做此交换，最终得到一个**所有标记都在 last 秒**的可行方案。反过来，该方案若可行当然原问题也可行——所以判定只需考虑这一种「最晚标记」方案。

### 3.5 核心观察三：一个前缀不等式完成判定

![判定不等式的容量账本](images/mark_indices_check_inequality.svg)

各下标的 last 秒互不相同（每秒只对应一个下标），按时间升序排成 $t_1 < t_2 < \cdots < t_n$，第 $j$ 个被标记的下标记为 $v_j$（即其 $\text{nums}$ 值），令前缀和 $S_j = v_1 + \cdots + v_j$。则：

$$\text{check}(t) \iff \text{每个下标都出现} \text{ 且 } \forall j:\ S_j \le t_j - j$$

**直观（容量账本）**：站在第 $j$ 个标记秒 $t_j$ 回望——之前共 $t_j - 1$ 秒，其中 $j - 1$ 秒已被前 $j-1$ 个标记占用，剩 $t_j - j$ 秒可供「减 1」；而前 $j$ 个下标共需 $S_j$ 次减 1 且全部必须完成于各自标记之前（即都在 $t_j$ 之前）。$S_j$ 个球塞 $t_j - j$ 个盒子，塞不下就是不可行。

这就是**截止期调度**的 Hall 条件特例（等价于最早截止期优先 EDF 的可行性判据），把「逐秒构造方案」压缩成了「逐前缀核对一个不等式」。

### 3.6 示例演算

![示例 2 演算：t=6 卡满、t=5 差一步](images/mark_indices_example2_tight.svg)

以示例 2 `nums = [1,3], changeIndices = [1,1,1,2,1,1,1]` 演算边界感：

| $t$ | last 映射 | 校验 | 结果 |
|-----|-----------|------|------|
| 6 | 下标 2→秒 4，下标 1→秒 6 | $j{=}1$：$S=3 \le 4-1=3$ ✓（紧）；$j{=}2$：$S=4 \le 6-2=4$ ✓（紧） | 可行 |
| 5 | 下标 2→秒 4，下标 1→秒 5 | $j{=}2$：$S=4 > 5-2=3$ | 不可行 |

答案 6。注意 $j=1$ 的 $3 \le 3$ 恰好卡满——**减 1 必须严格早于标记**，同一秒不能既减又标；$t=5$ 时下标 1 的标记被挤到秒 5，它的减 1 就没有秒可放了。

再看示例 1 `nums = [2,2,0], changeIndices = [2,2,2,2,3,2,2,1]` 的 $\text{check}(8)$：

| $j$ | 标记下标 | $t_j$ | $v_j$ | $S_j$ | $t_j - j$ | 判定 |
|-----|---------|-------|-------|-------|-----------|------|
| 1 | 3（秒 5） | 5 | 0 | 0 | 4 | ✓ |
| 2 | 2（秒 7） | 7 | 2 | 2 | 5 | ✓ |
| 3 | 1（秒 8） | 8 | 2 | 4 | 5 | ✓ |

可行；而 $\text{check}(7)$ 中下标 1 从未出现 ⇒ 不可行，故答案 8。

## 4. 算法细节

1. **二分外壳**：先做一次 $\text{check}(m)$——为假直接返回 $-1$；为真则保证 $[1, m]$ 内必有解，闭区间二分最小可行 $t$。
2. **check 的两趟扫描（免排序）**：第一趟扫前 $t$ 秒求 $\text{last}[i]$（顺带发现未出现下标）；第二趟再扫一遍秒号，遇到 $s = \text{last}[\text{changeIndices}[s]]$ 即「这是某个下标的标记秒」，此时累加 $S$、计数 $j{+}{+}$ 并核对 $S \le s - j$。**免排序的依据**：标记时刻互不相同且就是秒号，按秒号扫天然有序——省掉 $O(n \log n)$，check 降到 $O(n + m)$。
3. **last 初值用 0**：秒号从 1 开始，0 即「未出现」哨兵，无需额外布尔数组。
4. **溢出**：$S_j$ 最大 $2000 \times 10^9 = 2 \times 10^{12}$，C++ 必须用 `long long`；Python 无此虞。
5. **值为 0 的下标**：贡献 $v_j = 0$ 次「减 1」，但仍占据一个标记秒、消耗一个 $j$——公式自动覆盖，切勿特判跳过。

## 5. 正确性证明

**引理 1（单调性）**：$\text{check}(t)$ 为真 $\Rightarrow \text{check}(t+1)$ 为真。

**证明**：取前 $t$ 秒的可行方案，第 $t+1$ 秒执行「什么都不做」，其余不变，仍是前 $t+1$ 秒的可行方案。∎

**引理 2（规范化）**：前 $t$ 秒存在可行方案 $\Rightarrow$ 存在「每个下标都在其 last 秒标记」的可行方案。

**证明**：对可行方案中「标记不在 last 秒」的下标个数归纳。若个数非零，取一个标记在 $s' < \text{last}[i]$ 的下标 $i$，考察 $\text{last}[i]$ 秒的原操作：若是减 1 或发呆，将 $i$ 的标记与该操作对调——由 $\text{nums}$ 只减不增，$i$ 在 $s'$ 秒为 0 则在 $\text{last}[i]$ 秒仍为 0，标记合法；被前移的减 1 仍在其所属下标标记之前。若原操作是标记 $i$ 自身，直接对调。两种情形都使该个数减一且方案保持可行。归纳到底即得。∎

**引理 3（必要性）**：若存在全在 last 秒标记的可行方案，则对每个 $j$（按标记时刻升序）有 $S_j \le t_j - j$。

**证明**：前 $j$ 个下标的全部 $S_j$ 次「减 1」必须发生在各自标记之前，故均落在 $[1, t_j - 1]$ 内；且这 $t_j - 1$ 秒中有 $j - 1$ 秒被前 $j - 1$ 个标记占用（标记秒不能同时减 1），可用减 1 秒至多 $t_j - 1 - (j - 1) = t_j - j$。故 $S_j \le t_j - j$。∎

**定理（充要判定）**：$\text{check}(t)$ 为真 $\iff$ 每个下标都在前 $t$ 秒出现，且对所有 $j$：$S_j \le t_j - j$。

**证明**：

- **必要性**：由引理 2 与引理 3 链式可得。
- **充分性（构造）**：设条件成立。按秒号从左到右构造：凡遇标记秒（某个 $t_k$）执行标记 $k$；其余秒执行「减 1」。减 1 的分配规则：每次挑「已出现 last 秒、尚未清零、last 秒最早」的下标（EDF，最早截止期优先）。只需证到每个 $t_k$ 时刻，前 $k$ 个下标均已完成全部 $S_k$ 次减 1：在 $[1, t_k - 1]$ 中共 $t_k - k$ 个非标记秒，由条件这些秒**足够容纳**前 $k$ 个下标的全部减 1（对任意 $j < k$ 同理，$S_j \le t_j - j$ 保证 EDF 不会把早期该做的活挤掉——这是 EDF 可行性的标准结论）；于是第 $k$ 个下标在 $t_k$ 秒时值为 0，标记合法。所有下标在各自 last 秒被标记，方案可行。∎

由定理，$\text{check}$ 的两趟扫描实现正确；由引理 1，二分收敛到最小可行 $t$ 即为答案；$\text{check}(m)$ 为假时无解返回 $-1$。

## 6. 复杂度分析

- **时间复杂度**：$O((n + m) \log m)$。二分 $O(\log m)$ 次；每次 check 第一趟扫秒求 last 为 $O(m)$，第二趟扫秒核对为 $O(m + n)$（每个下标恰触发一次核对）。
- **空间复杂度**：$O(n)$。仅 `last` 数组与常数个计数器。

本题 $n, m \le 2000$ 十分宽裕；该 $O(n+m)$ 的 check 正是同场 Q4（#3049，$n, m \le 10^5$）所需的基础姿势。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int earliestSecondToMarkIndices(vector<int>& nums, vector<int>& changeIndices) {
        int n = nums.size(), m = changeIndices.size();

        // check(t)：只使用前 t 秒能否标记所有下标
        auto check = [&](int t) -> bool {
            vector<int> last(n + 1, 0);              // last[i]：i 在前 t 秒的最晚出现秒号，0=未出现
            for (int s = 1; s <= t; s++) last[changeIndices[s - 1]] = s;
            for (int i = 1; i <= n; i++)
                if (last[i] == 0) return false;      // 有下标从未出现，无法标记
            long long need = 0;                      // S_j：已截止下标的 nums 前缀和（会超 int）
            int cnt = 0;                             // j：已发生的标记个数
            for (int s = 1; s <= t; s++) {
                int i = changeIndices[s - 1];
                if (last[i] == s) {                  // 秒 s 是下标 i 的最晚出现 → 在此标记
                    need += nums[i - 1];
                    cnt++;
                    if (need > s - cnt) return false; // S_j > t_j − j，塞不下
                }
            }
            return true;
        };

        if (!check(m)) return -1;                    // 整个 m 秒都做不到，直接判死
        int lo = 1, hi = m;
        while (lo < hi) {                            // 二分最小可行 t
            int mid = lo + (hi - lo) / 2;
            if (check(mid)) hi = mid;
            else lo = mid + 1;
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def earliestSecondToMarkIndices(self, nums: List[int], changeIndices: List[int]) -> int:
        n, m = len(nums), len(changeIndices)

        def check(t: int) -> bool:
            last = [0] * (n + 1)                     # last[i]：i 在前 t 秒的最晚出现秒号
            for s, i in enumerate(changeIndices[:t], 1):
                last[i] = s
            if 0 in last[1:]:                        # 有下标从未出现
                return False
            need = cnt = 0                           # S_j 与 j
            for s, i in enumerate(changeIndices[:t], 1):
                if last[i] == s:                     # 秒 s 是 i 的最晚出现 → 标记秒
                    need += nums[i - 1]
                    cnt += 1
                    if need > s - cnt:
                        return False
            return True

        if not check(m):
            return -1
        lo, hi = 1, m
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

> 💡 免排序的巧劲在第二趟循环：`last[i] == s` 一行同时完成「筛出标记秒」与「按时刻升序处理」——因为 last 值两两不同且就是秒号本身。

## 8. 边界情况与易错点

1. **前缀和溢出**：$S_j$ 最大 $2000 \times 10^9 = 2 \times 10^{12}$，C++ 用 `int` 直接判死；必须 `long long`。
2. **「减 1 严格早于标记」**：同一秒不能既减又标。不等式右边是 $t_j - j$ 而不是 $t_j - j + 1$，示例 2 的 $j{=}1$ 恰好卡在 $3 \le 3$ 上，边界差一点答案就错。
3. **值为 0 的下标也占标记秒**：它不需要任何减 1，但占据一个 $t_j$、使 $j$ 增一，天然被公式覆盖；若实现时「跳过零值下标」反而漏掉容量核算。
4. **下标未出现**（示例 3）：last 保持哨兵值 0，直接返回 false——这是唯一的「结构性」无解来源；数值上的无解（减 1 塞不下）由不等式捕捉。
5. **先 check(m) 再二分**：若直接二分不判 $-1$，区间内可能无解，循环结束返回的 `lo` 是假答案。
6. **二分边界写法**：`lo + (hi - lo) / 2` 防溢出（本题 $m \le 2000$ 用 `(lo+hi)/2` 也安全，但习惯要养好）；循环条件 `lo < hi` 配 `hi = mid` 收敛到最小可行值。
7. **勿把「操作 2」当成可选任意下标**：第 $s$ 秒只能标记 $\text{changeIndices}[s]$，标记目标与秒绑定，这是 last 归一化成立的前提。
8. **免排序依赖「last 互不相同」**：若实现改为排序版，注意排序键是 last 值而非下标号。
