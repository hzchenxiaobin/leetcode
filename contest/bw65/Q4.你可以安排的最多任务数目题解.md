# LeetCode 你可以安排的最多任务数目 题解

## 1. 题目概述

- **标题 / 题号**：你可以安排的最多任务数目（#2071，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-tasks-you-can-assign/
- **来源**：LeetCode 第 65 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、二分查找、双指针、队列、排序

**题意**：$n$ 个任务、$m$ 个工人。任务 $i$ 需要力量 $tasks[i]$；工人 $j$ 力量 $workers[j]$。工人 $j$ 不吃药丸能完成任务 $i$ 当且仅当 $workers[j] \ge tasks[i]$。另有 `pills` 颗药丸，每颗可给**一个**工人力量增加 `strength`（每个工人至多一颗）。每个工人至多完成一个任务，问最多能完成多少个任务。

**约束**：

- $1 \le n, m \le 5 \times 10^4$
- $0 \le pills \le m$
- $0 \le tasks[i], workers[j], strength \le 10^9$

## 2. 示例

**示例 1**

```text
输入：tasks = [3,2,1], workers = [0,3,3], pills = 1, strength = 1
输出：3
解释：0 号工人吃药丸完成任务 2（0+1≥1），1 号完成任务 1（3≥2），2 号完成任务 0（3≥3）。
```

```text
解释：给 0 号工人药丸，0+5≥5 完成任务 0；剩 2 工人 0 药丸做不了任务 1。
```

**示例 3**

```text
输入：tasks = [10,15,30], workers = [0,10,10,10,10], pills = 3, strength = 10
输出：2
解释：0、1 号工人吃药丸分别完成 10 与 15；任务 30 无人能做。
```

```text
输入：tasks = [5,9,8,5,9], workers = [1,6,4,2,6], pills = 1, strength = 5

```

## 3. 解题思路

### 3.1 暴力思路

枚举"哪些工人做哪些任务、谁吃药丸"：状态是任务集合到工人的带药丸约束的匹配，指数级。退而求其次的 DP（任务逐个决策、工人用位掩码）是 $O(n \cdot 2^m)$，$m$ 到 $5 \times 10^4$ 完全不可行。必须利用"只问**最多多少个**"这一结构。

### 3.2 核心观察一：答案具有单调性，可二分

![二分答案：可行性单调](images/bw65_q4_binary_search_monotone.svg)

若能完成 $k$ 个任务，则任取其中 $k-1$ 个也能完成（方案是子集）。于是"完成 $k$ 个"关于 $k$ 单调，答案 $k^*$ 可二分：`check(k)` 判定能否完成 $k$ 个，在 $[0, \min(n, m)]$ 上找最大可行 $k$。

进一步固定形态：**只需考察"最简单的 $k$ 个任务 + 最强的 $k$ 个工人"**——若存在任一 $k$ 对匹配方案，则把方案中的任务换成更简单的、工人换成更强的（保持配对与药丸分配），仍可行（§5 引理 2）。于是 `check(k)` 只处理排序后 `tasks[0..k-1]` 与 `workers[m-k..m-1]`。

### 3.3 核心观察二：从最难任务出发的双端队列贪心

![贪心匹配：任务从难到易，队列从弱到强](images/bw65_q4_greedy_matching.svg)

对固定的 $k$，任务按需求**从难到易**依次决策（`need` 单调不增）。维护一个双端队列，存"已被激活（吃过药丸就能做当前难度）但尚未使用"的工人，队首最弱、队尾最强：

- **激活**：对当前 `need`，把所有满足 $w + strength \ge need$ 的未用工人从最强者开始依次入队（弱者进队首）。由于 `need` 递减，激活门槛只降不升，每个工人至多入队一次。
- **决策**：若队尾（最强）不吃药丸就能做（$w \ge need$），派队尾直接做——最强者留给更难任务的机会成本最低；否则派**队首（最弱的可用药丸救活者）**吃药丸做——省下更强的工人与药丸。

队列为空或药丸耗尽则 `check(k)` 失败。

### 3.4 示例演算

![示例 4 演算：check(3) 成功与 check(4) 失败](images/bw65_q4_example_walkthrough.svg)

示例 4：`tasks = [5,5,8,9,9]`（升序），`workers = [1,2,4,6,6]`（升序），`pills=1, s=5`。

`check(3)`：任务 {8,5,5}，工人 {4,6,6}。任务 8：激活 $w+5\ge 8$ 的工人 4,6,6，队列 [4|6|6]（队首弱队尾强）；队尾 6 < 8 → 队首 4 吃药丸（4+5=9≥8）✓，药丸归零。任务 5：队尾 6 ≥ 5 直接做。任务 5：队尾 6 ≥ 5 直接做。全部完成 → true。

`check(4)`：任务 {9,8,5,5}，工人 {2,4,6,6}。任务 9：激活 4,6,6（$w+5\ge 9$），队尾 6 < 9 → 队首 4 吃药丸（9≥9）✓。任务 8：队 [6|6]，队尾 6 < 8 → 需再吃一颗但药丸已用光 → false。

二分收敛 $k^* = 3$，与官方一致。

## 4. 算法细节

1. **check(k) 的窗口**：排序后取 `tasks[0..k-1]`（最易）与 `workers[m-k..m-1]`（最强）。$k=0$ 恒真。
2. **遍历顺序**：任务下标 $i$ 从 $k-1$ **递减**到 0（从难到易），`need = tasks[i]` 单调不增。
3. **激活边界**：指针 `j` 从 `m` 向 `base = m-k` 递减，每轮把 `workers[j-1] + strength >= need` 者从队首压入（`push_front`）。`need` 递减保证已激活者永不过期，无需出队。
4. **两个出口**：优先"队尾直接做"（不耗药丸）；仅当队尾不足时才"队首吃药丸"。队首在激活时已保证 $w+s \ge need$，故出队安全。
5. **失败条件**：队列为空（无人可激活）或药丸数为 0 而队尾不足。
6. **溢出**：$w + strength \le 2 \times 10^9$ 超 `int`，C++ 判定处必须 `long long`。
7. **二分模板**：`lo=0, hi=min(n,m)`，`mid = (lo+hi+1)/2` 向上取整，可行则 `lo=mid` 否则 `hi=mid-1`，避免死循环。

## 5. 正确性证明

**引理 1（可行性单调）**：若可完成 $k$ 个任务，则可完成任意 $k' < k$ 个。

**证明**：取可行方案中任意 $k'$ 个"工人-任务"配对（连同各自的药丸使用），它是原方案的子集，单独仍合法：每对约束不变、药丸用量只减不增。∎

**引理 2（窗口引理）**：若存在某 $k$ 个任务与 $k$ 个工人的可行匹配，则"最易的 $k$ 个任务 + 最强的 $k$ 个工人"也存在可行匹配。

**证明**：设原方案匹配任务集 $T$、工人集 $W$（$|T|=|W|=k$），其中 $t$ 个任务分给药丸工人。取最易 $k$ 个任务 $T^* \preceq T$（按需求逐位 $\le$）、最强 $k$ 个工人 $W^* \succeq W$（按力量逐位 $\ge$）。构造：对 $T^*$ 升序、$T$ 升序，把 $T$ 的配对方案"降维映射"到 $T^*$——第 $i$ 个（升序）$T^*$ 任务接替原方案中第 $i$ 个 $T$ 任务的工人；同理把工人替换成 $W^*$ 中按力量对应更强者。替换后每对约束 $w \ge t$ 或 $w + s \ge t$ 中，$w$ 变大、$t$ 变小，仍成立；药丸分配随工人一一携带，数量不变。故新匹配可行。∎

**引理 3（贪心可交换性）**：`check(k)` 中，对当前最难未处理任务（需求 `need`），若队尾最强者 $w_{max} \ge need$，则存在最优方案让 $w_{max}$ 不吃药丸做该任务。

**证明**：设某可行方案中该任务由工人 $w'$ 做。若 $w' = w_{max}$ 且未吃药丸，结论已成立。否则交换：令 $w_{max}$ 不吃药丸接手该任务（$w_{max} \ge need$ ✓），$w'$ 改做原方案中 $w_{max}$ 的任务 $t'$（或闲置，若 $w_{max}$ 原本闲置）：因 $w_{max}$ 是队列中最强者且 $w'$ 在队列中（已激活），有 $w' \le w_{max}$。若 $w'$ 原来不吃药丸做 `need`，则 $w' \ge need > t'$ 或 $w' \ge t'$ 需分情况——更严谨地：交换后 $w'$ 需满足 $w' \ge t'$ 或 $w' + s \ge t'$。由队列激活条件 $w' + s \ge need \ge t'$（need 是当前最难，$t'$ 更易），故 $w'$ 吃一颗药丸必能做 $t'$；若原方案 $w_{max}$ 未吃药丸而 $w'$ 吃了药丸，交换后药丸总数不变；若 $w'$ 未吃药丸（即 $w' \ge need$），则 $w' \ge need \ge t'$，直接做 $t'$ 也不耗药丸。各情形均保持任务数与药丸数不劣。∎

**引理 4（药丸给最弱者）**：队尾不足时（所有队列内 $w < need$），让**队首最弱者**吃药丸做该任务不劣于让任何更强者吃。

**证明**：设方案 A 中更强的 $w''$（$w'' > w'$，两者均在队列中，即均满足 $w+s \ge need$）吃药丸做该任务。交换成 $w'$ 吃药丸做该任务、$w''$ 接手 $w'$ 原任务 $t''$（或闲置）：因 $t'' \le need \le w'' + s$，$w''$ 必要時吃一颗药丸可做 $t''$，药丸总数不变；若 $w'$ 原本闲置则直接省下。任务数不减、药丸不增。∎

**定理**：`check(k)` 返回 true 当且仅当存在 $k$ 个任务的可行匹配；二分得到答案 $k^*$。

**证明**：由引理 1，可行性单调，二分合法。由引理 2，只需在"最易 $k$ 任务 + 最强 $k$ 工人"上判定。在此窗口内，引理 3 与引理 4 说明：贪心在每一步选择的配对都可交换到某个可行方案中（若存在），即贪心决策不丢失可行性——这是标准交换论证的逐步形式：每步贪心后，剩余子问题的可行性与"任一可行方案存在"等价（未被选中的工人集合仍覆盖所有可行方案的需求，由引理 3/4 的交换保持）。归纳至所有任务处理完毕：全部匹配成功当且仅当初始存在可行方案。故 `check` 正确，二分收敛于最大 $k$。∎

## 6. 复杂度分析

- **时间**：排序 $O(n \log n + m \log m)$；二分 $O(\log \min(n,m))$ 轮，每轮 `check(k)` 中每个任务 $O(1)$ 均摊（每工人至多入队/出队各一次）共 $O(n + m)$。总计 $O((n + m) \log(n m))$，约 $10^5 \times 17$ 量级。
- **空间**：$O(m)$（双端队列）+ 排序的 $O(\log)$ 栈深，Python 版额外 $O(n)$ 存切片。

## 7. 参考代码

### C++

```cpp
class Solution {
    // 判定：能否完成（排序后）最简单的 k 个任务，只用最强的 k 个工人
    bool check(vector<int>& task, vector<int>& worker, int pills, long long strength, int k) {
        int m = worker.size();
        deque<int> q;              // 已"激活"且未使用的工人，队首最弱、队尾最强
        int j = m;                 // worker[m-k .. j-1] 尚未激活（j 是激活边界）
        int base = m - k;          // 参与本次判定的工人窗口为 worker[base .. m-1]
        for (int i = k - 1; i >= 0; --i) {          // 任务从难到易
            int need = task[i];
            // 激活所有"吃药丸后能完成当前任务"的工人（从最强未激活者开始）
            while (j > base && (long long)worker[j - 1] + strength >= need) {
                q.push_front(worker[j - 1]);
                --j;
            }
            if (!q.empty() && q.back() >= need) {
                q.pop_back();                        // 最强够格者直接做，不消耗药丸
            } else {
                if (q.empty() || pills == 0) return false;
                q.pop_front();                       // 最弱者吃药丸做（队首必满足 w+s>=need）
                --pills;
            }
        }
        return true;
    }
public:
    int maxTaskAssign(vector<int>& tasks, vector<int>& workers, int pills, int strength) {
        sort(tasks.begin(), tasks.end());
        sort(workers.begin(), workers.end());
        int lo = 0, hi = min((int)tasks.size(), (int)workers.size());
        while (lo < hi) {                            // 求最大可行 k
            int mid = lo + (hi - lo + 1) / 2;
            if (check(tasks, workers, pills, strength, mid)) lo = mid;
            else hi = mid - 1;
        }
        return lo;
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def maxTaskAssign(self, tasks: list[int], workers: list[int], pills: int, strength: int) -> int:
        tasks.sort()
        workers.sort()

        def check(k: int) -> bool:
            # 最容易的 k 个任务（tasks[:k]）+ 最强的 k 个工人（workers[-k:]）
            q = deque()                 # 队首最弱、队尾最强
            j = len(workers)            # 激活边界：workers[len-k : j] 未激活
            base = len(workers) - k
            left = pills
            for i in range(k - 1, -1, -1):        # 任务从难到易
                need = tasks[i]
                while j > base and workers[j - 1] + strength >= need:
                    q.appendleft(workers[j - 1])  # 吃药丸可做 → 激活，弱者排队首
                    j -= 1
                if q and q[-1] >= need:           # 最强者不吃药直接做
                    q.pop()
                else:
                    if not q or left == 0:
                        return False
                    q.popleft()                   # 最弱者吃药丸做
                    left -= 1
            return True

        lo, hi = 0, min(len(tasks), len(workers))
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if check(mid):
                lo = mid
            else:
                hi = mid - 1
        return lo
```

> 💡 两份代码均通过官方 4 组示例（`3` / `1` / `2` / `3`）、$n = m = 5 \times 10^4$ 大规模冒烟、$10^9$ 极值溢出用例，以及 C++ 3000 组、Python 1500 组随机数据与**记忆化暴力**（位掩码枚举全部工人-任务-药丸分配，$n, m \le 6$）的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出**：$workers[j] + strength$ 可达 $2 \times 10^9$，C++ 判定必须显式转 `long long`（Python 无此虞）。
2. **pills = 0**：退化为纯双指针匹配（最强 $k$ 工人 vs 最易 $k$ 任务），贪心退路必须正确处理"队列非空但药丸为 0"。
3. **strength = 0**：药丸无用，答案只由直配决定；不要特判跳过激活逻辑（激活条件 $w \ge need$ 会让药丸路径自然退化）。
4. **k = 0**：恒真，二分下界从 0 出发即可，无需单独分支。
5. **激活条件用当前 need**：因为任务从难到易，`need` 只降，早激活的工人不会失效；若把遍历顺序写反（从易到难）整个激活单调性崩塌，必须重写。
6. **队列里"队尾直接做"优先于"队首吃药"**：顺序反了会把药丸浪费在强工人身上，构造 `tasks=[5,9], workers=[6,4], pills=1, s=5` 可立刻翻车。
7. **二分上界**：$\min(n, m)$，工人比任务少时不可能完成更多。
