# LeetCode 模拟行走机器人 II 题解

## 1. 题目概述

- **标题 / 题号**：模拟行走机器人 II（#2069，medium）
- **链接**：https://leetcode.cn/problems/walking-robot-simulation-ii/
- **来源**：LeetCode 第 65 场双周赛 Q2
- **难度**：中等
- **标签**：设计、模拟、数学

**题意**：在 $width \times height$ 的网格图（左下角 $(0,0)$，右上角 $(width-1, height-1)$）上，一个机器人初始位于 $(0,0)$、面朝 **East**。每一步它沿当前方向尝试前进；若下一步将出界，则**逆时针**转 90° 后再前进一步（转完必有界内一步可走，因为机器人永远在网格**周界**上，见 §5 引理 1）。要求实现 `Robot` 类：`step(num)` 前进 `num` 步；`getPos()` 返回坐标；`getDir()` 返回朝向字符串 `"North"/"East"/"South"/"West"`。

**约束**：

- $2 \le width, height \le 100$
- $1 \le num \le 10^5$
- `step` / `getPos` / `getDir` 总调用次数 $\le 10^4$

> ⚠️ 朝向语义是本题最大坑点：**朝向在"停下那一刻"返回**。若机器人某步恰好停在角点，朝向仍是**抵达该角点时的方向**，转向发生在"下一次尝试出界"时；特别地，绕整圈回到 $(0,0)$ 后朝向是 **South**（向南进入 $(0,0)$），而初始未动时是 **East**。

## 2. 示例

**示例 1（官方调用序列）**

```text
输入：
["Robot","step","step","getPos","getDir","step","step","step","getPos","getDir"]
[[6,3],[2],[2],[],[],[2],[1],[4],[],[]]
输出：
[null,null,null,[4,0],"East",null,null,null,[1,2],"West"]
解释：
step(2) → (2,0) 朝 East；step(2) → (4,0) 朝 East。
step(2)：第 1 步到 (5,0)（East），第 2 步向东出界 → 逆时针转 North → 到 (5,1)。
step(1) → (5,2)，朝 North（角点 (5,2)=(w-1,h-1)，此刻仍朝 North）。
step(4)：向北出界 → 转 West → 走 4 步到 (1,2)，朝 West。
```

**示例 2（整圈回起点，补充）**

```text
输入：Robot(3,3); step(8); getPos(); getDir()
输出：[0,0], "South"
解释：周长 per = 2*(3-1)+2*(3-1) = 8，走满一圈回到 (0,0)，是"向南"进入的。
```

**示例 3（最小网格，补充）**

```text
输入：Robot(2,2); step(4); getPos(); getDir()
输出：[0,0], "South"
解释：2×2 网格周界即 4 个角，走 4 步一圈回 (0,0)，朝 South。
```

## 3. 解题思路

### 3.1 暴力思路

`step(num)` 真的一步一步走：每步检查下一格是否出界，出界则方向 $d \leftarrow (d+1) \bmod 4$ 再走。单次 `step` 最坏 $10^5$ 步、调用 $10^4$ 次，总计 $10^9$ 次模拟——超时。需要把"走 num 步"压缩成 $O(1)$ 的位置计算。

### 3.2 核心观察：机器人永远贴着周界走，外圈可拍平成一维环

![周界展开：外圈拍平成一维环](images/bw65_q2_perimeter_unfold.svg)

初始在角点 $(0,0)$，沿 East 出发；每次出界前一格必是周界上的格子，逆时针转向后仍在周界上（§5 引理 1）。因此机器人的轨迹**永远在网格外圈**上，外圈构成一个长度

$$per = 2(width-1) + 2(height-1)$$

的环（四个角各只算一次）。把外圈按行走顺序（East → North → West → South）展开编号 $p = 0, 1, \dots, per-1$，其中 $p=0$ 对应 $(0,0)$、$p = width-1$ 对应 $(width-1, 0)$、$p = width+height-2$ 对应 $(width-1, height-1)$、$p = 2(width-1)+height-1$ 对应 $(0, height-1)$。于是

$$p \leftarrow (p + num) \bmod per$$

一次取模就完成了任意步数的移动，`step` 变 $O(1)$。

### 3.3 算法流程：由 $p$ 反解坐标与朝向

![朝向由 p 所在段唯一决定](images/bw65_q2_direction_segments.svg)

**坐标**按 $p$ 落在哪条边分四段反解：

| 段（含端点） | 边 | 坐标 |
|---|---|---|
| $0 \le p \le w{-}1$ | 下边 | $(p, 0)$ |
| $w{-}1 \le p \le w{+}h{-}2$ | 右边 | $(w{-}1,\; p - (w{-}1))$ |
| $w{+}h{-}2 \le p \le 2w{+}h{-}3$ | 上边 | $(2(w{-}1)+h{-}1-p,\; h{-}1)$ |
| 其余 | 左边 | $(0,\; per - p)$ |

**朝向**由 $p$ 所在段决定，但有两个特殊语义要单独处理：

1. **角点归属**：停在角点 $(w{-}1, 0)$ 时朝向仍是 East（还没尝试出界）、$(w{-}1, h{-}1)$ 是 North、$(0, h{-}1)$ 是 West——即每个角点归入"抵达方向"那一段。
2. **$p = 0$ 特例**：从未移动（累计步数为 0）是初始 East；动过（绕完整圈或多圈回来）是 South（左边一段向南进入 $(0,0)$）。

### 3.4 示例演算

以官方示例（$6 \times 3$，$per = 2 \times 5 + 2 \times 2 = 14$）走一遍：

| 操作 | 累计步数 | $p$ | 位置 | 朝向 |
|---|---|---|---|---|
| step(2) | 2 | 2 | $(2,0)$ | East |
| step(2) | 4 | 4 | $(4,0)$ | East |
| step(2) | 6 | 6 | $(5,1)$ | North |
| step(1) | 7 | 7 | $(5,2)$ | North（角点仍朝 North） |
| step(4) | 11 | 11 | $(1,2)$ | West |

与官方输出 `[4,0] East`、`[1,2] West` 一致。

## 4. 算法细节

1. **累计步数用 `long long`**：$10^4$ 次调用 × 每次 $10^5$ 步 = $10^9$，`int` 边界危险（虽然先取模再累加也可避免，但直接用 64 位最省心）。取模后才落在 $[0, per)$。
2. **四段区间端点重叠**：表格中角点被归入"抵达方向"段（例如 $p = w{-}1$ 归下边，返回 East），这正对应"转向发生在下一步尝试"的语义，写条件时用 $\le$ 串起来即可，不要把角点写成独立分支返回新方向。
3. **$p = 0$ 用累计步数区分**：`steps == 0` → East（初始态）；`steps > 0`（模完为 0 说明绕过整圈）→ South。
4. **坐标反解公式**：上边一段 $x = 2(w{-}1) + h{-}1 - p$、左边一段 $y = per - p$，代入 $p$ 的段端点可自检：$p = 2w{+}h{-}3$ 时 $x = 0$（左边顶端），$p = per{-}1$ 时 $y = 1$（$(0,1)$，即 $(0,0)$ 的下一个顺时针邻格——注意逆时针行走时从 $(0,1)$ 向南进 $(0,0)$）。
5. **不需要存方向状态机**：朝向完全由 $p$（和是否动过）推导，类里只需 `w、h、per、steps` 四个字段。
6. **`getPos`/`getDir` 可重复调用**：二者都是纯查询，不改状态，实现成 `const` 语义最稳。

## 5. 正确性证明

**引理 1（周界不变性）**：机器人从周界格出发，则任意时刻都在周界格上；且下一步出界当且仅当当前位于角点且方向指向圈外。

**证明**：周界格的非角格恰有两个周界邻居（左右或上下），且这两个邻居方向相反。机器人沿周界直线走到角点：角点的两个周界邻居方向互相垂直。设到达角点时方向为 $d$，若 $d$ 指向的邻格在界内（即沿周界拐弯方向），下一步仍走周界格；若出界，逆时针转 90° 后的方向恰指向另一条周界边上的邻居（逆时针行走时，角点处原方向必指向圈外，转后必指向圈内的周界邻居）。归纳即得任意时刻都在周界上，且转向只发生在角点。∎

**引理 2（环上位置）**：按行走顺序给周界格编号 $p \in [0, per)$，则每移动一步 $p$ 增加 1（在 $per - 1$ 之后回到 0），与逆时针转向规则等价。

**证明**：由引理 1，机器人沿编号顺序访问周界格；在 $p = per - 1$（即 $(0,1)$）处向南走一步到 $(0,0) = p = 0$，正好是编号回卷，无需任何特殊转向处理。∎

**定理**：`step(num)` 后以 $p = (\text{累计步数}) \bmod per$ 反解的坐标与朝向，与逐步模拟的结果一致。

**证明**：对累计步数归纳。基础：0 步时 $p = 0$，坐标 $(0,0)$、朝向 East（未动过），正确。归纳：设 $t$ 步后 $p_t$ 正确且位置为环上第 $p_t$ 号格。由引理 2，再走一步 $p_{t+1} = (p_t + 1) \bmod per$；故走 num 步后 $p = (p_t + num) \bmod per$，坐标由 §3.3 表格的分段双射给出。朝向：非 $p=0$ 时，环上第 $p$ 号格的"抵达方向"就是所在边的行进方向，段划分含角点归属，正确；$p = 0$ 时若动过，最后一步是从 $per-1$ 号格向南进入，故 South；未动过则保持初始 East。∎

## 6. 复杂度分析

- **时间**：`step`、`getPos`、`getDir` 各 $O(1)$（一次取模与常数次比较）；总调用 $10^4$ 次即 $O(1) \times 10^4$。
- **空间**：$O(1)$，只存宽、高、周长、累计步数四个整数。

## 7. 参考代码

### C++

```cpp
class Robot {
    long long steps;      // 累计步数（1e4 次 × 1e5 步 = 1e9，用 long long 稳妥）
    int w, h, per;        // 网格宽高与周长 per = 2*(w-1) + 2*(h-1)
public:
    Robot(int width, int height) : w(width), h(height), steps(0) {
        per = 2 * (w - 1) + 2 * (h - 1);
    }

    void step(int num) { steps += num; }

    vector<int> getPos() {
        long long p = steps % per;
        int W = w - 1, H = h - 1;                  // 角点坐标
        if (p <= W) return { (int)p, 0 };                          // 下边：向东
        if (p <= W + H) return { W, (int)(p - W) };                // 右边：向北
        if (p <= 2 * W + H) return { 2 * W + H - (int)p, H };      // 上边：向西
        return { 0, (int)(per - p) };                              // 左边：向南
    }

    string getDir() {
        long long p = steps % per;
        if (p == 0) return steps > 0 ? "South" : "East";  // (0,0)：动过=向南抵达；没动=初始向东
        if (p <= w - 1) return "East";                    // 含角点 (w-1,0)
        if (p <= w - 1 + h - 1) return "North";           // 含角点 (w-1,h-1)
        if (p <= 2 * (w - 1) + h - 1) return "West";      // 含角点 (0,h-1)
        return "South";                                   // 左边（不含 (0,0)）
    }
};
```

### Python

```python
class Robot:
    def __init__(self, width: int, height: int):
        self.w, self.h = width, height
        self.per = 2 * (width - 1) + 2 * (height - 1)
        self.steps = 0

    def step(self, num: int) -> None:
        self.steps += num

    def getPos(self) -> list[int]:
        p = self.steps % self.per
        W, H = self.w - 1, self.h - 1
        if p <= W:
            return [p, 0]
        if p <= W + H:
            return [W, p - W]
        if p <= 2 * W + H:
            return [2 * W + H - p, H]
        return [0, self.per - p]

    def getDir(self) -> str:
        p = self.steps % self.per
        if p == 0:
            return "South" if self.steps > 0 else "East"
        if p <= self.w - 1:
            return "East"
        if p <= self.w - 1 + self.h - 1:
            return "North"
        if p <= 2 * (self.w - 1) + self.h - 1:
            return "West"
        return "South"
```

> 💡 两份代码均通过官方调用序列回放（`[4,0] East` / `[1,2] West`）、整圈回 $(0,0)$ 朝 South 的定向用例，以及 C++ 3000 张随机网格共 40654 次、Python 600 张网格共 6159 次 `getPos`/`getDir` 与逐步模拟暴力的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$p = 0$ 的双重语义**：未移动是 East、绕圈回来是 South，只看 $p$ 不看累计步数必错。这是本题 WA 重灾区。
2. **角点朝向**：停在 $(w{-}1, 0)$ 朝 East 而非 North（转向发生在下一步）。四段区间必须"含抵达端点"。
3. **周长公式**：$per = 2(w{-}1) + 2(h{-}1)$，角点不能重复计数；$w = h = 2$ 时 $per = 4$。
4. **溢出**：累计步数上界 $10^9$，C++ 用 `long long`（或每次 `step` 先取模再累加）。
5. **坐标系**：$y$ 向上为正（右下角是 $(w{-}1, 0)$ 不是 $(0, h{-}1)$），与屏幕坐标相反。
6. **`step` 可连续调用**：步数要累加而非覆盖；每次 `step` 独立取模也可，但保留累计值更简单。
