# LeetCode 矩阵中移动的最大次数 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中移动的最大次数（#2684，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-moves-in-a-grid/
- **来源**：LeetCode 第 345 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、矩阵

**题意**：给定 $m \times n$ 的正整数矩阵 `grid`，从**第一列任一单元格**出发，每次可从 $(row, col)$ 移动到 $(row-1, col+1)$、$(row, col+1)$、$(row+1, col+1)$ 三个格子中任一**值严格大于**当前值的格子。返回最多能移动多少次。

**约束**：

- $2 \le m, n \le 1000$
- $4 \le m \cdot n \le 10^5$
- $1 \le \text{grid}[i][j] \le 10^6$

> 💡 **关键信号**：三种走法的列坐标都变成 $col+1$——每走一步**恰好右移一列**，列下标严格递增。这既保证了无环、可按列 DP，还藏着一个更强的化简：**移动次数 = 终点列下标**，连"走了几步"这个数值都不用维护，布尔可达性就够。

## 2. 示例

**示例 1**

```text
输入：grid = [[2,4,3,5],[5,4,9,3],[3,4,2,11],[10,9,13,15]]
输出：3
解释：从 (0,0) 出发：(0,0) → (0,1) → (1,2) → (2,3)，
     值 2 → 4 → 9 → 11 严格递增，共移动 3 次。
```

**示例 2**

```text
输入：grid = [[3,2,4],[2,1,9],[1,1,7]]
输出：0
解释：三个起点 3、2、1 的右邻分别是 2/1/1、1/1、1/1，
     没有任何一个严格更大（注意 1 → 1 相等不可走），一步都走不了。
```

**补充示例（中途断链）**

```text
输入：grid = [[5,6,1],[6,7,2]]
输出：1
解释：列 1 可达（5→6、5→7、6→7），但列 2 的 1、2 都不大于列 1 的 6、7，
     可达列停在 1，故最多移动 1 次。
```

## 3. 解题思路

### 3.1 暴力思路

从第一列每个起点各做一次 DFS，枚举三条分支递归到底，取最深的路径。问题在于**路径数随列数指数增长**（每步至多 3 个分支，最坏约 $3^{n-1}$ 条路径），$n = 1000$ 时完全不可行；同一格子"以后怎么走"会被不同前缀反复重算，本质是**重复子问题**没有消除。

### 3.2 核心观察：移动次数 = 终点列下标，布尔可达性足矣

![三种移动都恰好右移一列](images/wc345_q3_move_dag_concept.svg)

**观察一：每步恰好右移一列 → 无环。**
三种走法 $(r-1,c+1)$、$(r,c+1)$、$(r+1,c+1)$ 的列坐标都是 $c+1$，列下标只增不减。状态依赖构成 **DAG**，从左往右按列推进即可 DP，绝无循环依赖。

**观察二：到达列 $c$ ⟺ 已移动 $c$ 次。**
从第 0 列出发，每移动一次列下标恰好 $+1$，故任意路径的移动次数**就等于终点的列下标**。于是"最大移动次数" = "可达格子的最大列下标"——**不需要维护步数这个数值**，每个格子只需回答"可达 / 不可达"。

**观察三：可达性按列整体转移。**
设 $R_c \subseteq \{0,\dots,m-1\}$ 为列 $c$ 中可达格子的行号集合，则：

$$R_0 = \{0,1,\dots,m-1\},\qquad nr \in R_{c+1} \iff \exists\, r \in \{nr-1, nr, nr+1\} \cap R_c:\ \text{grid}[nr][c+1] > \text{grid}[r][c]$$

一旦某列 $R_{c+1} = \varnothing$，后续所有列都不可达（任何路径必经列 $c+1$），可以**提前终止**。

> 💡 与通用"数值 DP"（$dp[r][c]$ 存到达 $(r,c)$ 的最大移动次数）对比：本题中可达格子的 $dp$ 值**恒等于其列下标 $c$**，数值信息完全冗余——布尔化简后代码更短、缓存更友好。

### 3.3 算法流程

![逐列布尔 DP 流程](images/wc345_q3_column_dp_flow.svg)

1. `reach[m]` 全置 `true`（第 0 列整列都是起点），`ans = 0`；
2. 对 $c = 1, \dots, n-1$：
   - 新建 `nreach[m]` 全 `false`；
   - 对每个目标行 $nr$：若存在 $r \in \{nr-1, nr, nr+1\}$ 使 `reach[r]` 且 $\text{grid}[nr][c] > \text{grid}[r][c-1]$，则 `nreach[nr] = true`；
   - 若 `nreach` 全 `false`：**提前终止**（后续列必全灭），跳出循环；
   - 否则 `reach = nreach`，`ans = c`；
3. 返回 `ans`。

### 3.4 示例演算

![示例 1 的逐列可达性演算](images/wc345_q3_walkthrough.svg)

以示例 1（$4\times4$）为例逐列推进：

| 列 $c$ | 该列值 | 可达行集合 $R_c$ | 说明 |
|--------|--------|------------------|------|
| $0$ | $[2,5,3,10]$ | $\{0,1,2,3\}$ | 整列都是起点 |
| $1$ | $[4,4,4,9]$ | $\{0,1,2,3\}$ | 如 $4>2$ ✓、$9>3$ ✓，每行都进得来 |
| $2$ | $[3,9,2,13]$ | $\{1,3\}$ | $9>4$ ✓、$13>4$ ✓；而 $3\le 4$、$2\le 4$ 被卡 |
| $3$ | $[5,3,11,15]$ | $\{0,1,2,3\}$ | $5>3$ ✓、$3>2$ ✓、$11>9$ ✓、$15>13$ ✓ |

最后一个非空可达列是第 $3$ 列，答案 $=3$，对应路径 $(0,0)\to(0,1)\to(1,2)\to(2,3)$（值 $2\to4\to9\to11$ 严格递增）。

**示例 2** 中列 $1$ 的 $R_1 = \varnothing$：$2\not>3$、$1\not>2$、$1\not>1$（**相等不可走**），提前终止，答案 $0$。

## 4. 算法细节

1. **滚动数组，整列算完再换**：算列 $c$ 时要反复读 `reach`（列 $c-1$ 的旧值），必须新开 `nreach`、整列算完后整体替换；原地覆盖会让后面的目标行读到已被污染的数据。
2. **提前终止的正确性**：$R_c = \varnothing \Rightarrow R_{c+1} = \varnothing$（到达列 $c+1$ 的路径必经列 $c$ 的某格，归纳可得其后各列全空），因此一旦本列全灭即可 `break`，最多白算一列。
3. **`ans` 的更新时机**：`ans = c` 放在"本列非空"确认之后；也可不维护 `ans`——全灭时返回 $c-1$、循环自然结束返回 $n-1$，两种写法等价，但别混用。
4. **枚举方向的对称性**：按目标行 $nr$ 聚合时候选来源是 $\{nr-1, nr, nr+1\}$（"谁能走到我"），与"我能走到谁"的 $\{r-1,r,r+1\}$ 互为转置，复杂度相同；按目标聚合写循环更顺，也天然配合滚动数组。
5. **数据规模适配**：$m\cdot n \le 10^5$，其实二维数组也开得下；滚动到 $O(m)$ 后，$m=1000$ 的瘦高、$n=1000$ 的扁长矩阵都毫无压力。答案 $\le n-1 \le 999$，`int` 足够，无溢出风险。

## 5. 正确性证明

**引理 1（列下标 = 移动次数）**：从第 0 列出发的任意合法路径，其第 $i$ 次移动后所在格子的列下标恰为 $i$；特别地，路径的移动次数等于终点的列下标。

**证明**：对移动次数 $i$ 归纳。$i=0$ 时位于第 0 列，成立。若第 $i$ 次移动后列下标为 $i$，则第 $i+1$ 次移动的三种目标 $(r-1,c+1)$、$(r,c+1)$、$(r+1,c+1)$ 的列下标均为 $i+1$，归纳完成。∎

**引理 2（可达集合的递推）**：设 $R_c$ 为从第一列出发、经合法路径可到达的列 $c$ 格子的行号集合，则 $R_0 = \{0,\dots,m-1\}$，且对 $0 \le c \le n-2$：

$$nr \in R_{c+1} \iff \exists\, r \in \{nr-1,nr,nr+1\}\cap[0,m)\cap R_c,\quad \text{grid}[nr][c+1]>\text{grid}[r][c]$$

**证明**：$R_0$ 即"第一列任一格可作为起点"。对 $c$ 归纳：一条到达 $(nr, c+1)$ 的非空路径去掉最后一步，是到达列 $c$ 某格 $(r,c)$ 的合法路径，由归纳假设 $r \in R_c$；且最后一步按移动规则只能从行 $\{nr-1,nr,nr+1\}$ 走来，合法性即 $\text{grid}[nr][c+1]>\text{grid}[r][c]$。反之，把到达 $(r,c)$ 的合法路径接上这一合法步，即得到达 $(nr,c+1)$ 的合法路径。两方向合并即得等价式。∎

**引理 3（可达列是前缀）**：若 $R_c = \varnothing$，则对一切 $c' > c$ 有 $R_{c'} = \varnothing$。

**证明**：对 $c'$ 归纳。$c' = c+1$ 时，引理 2 右侧不存在满足 $r \in R_c$ 的来源，故 $R_{c+1} = \varnothing$；若 $R_{c'-1} = \varnothing$，同理 $R_{c'} = \varnothing$。∎

**定理**：算法返回值等于最大移动次数 $\mathrm{OPT} = \max\{\,c : R_c \ne \varnothing\,\}$。

**证明**：算法按 $c = 1, \dots, n-1$ 依次以引理 2 的等价式计算 $R_c$（布尔数组即集合的特征向量），维护 `ans` 为最后一个非空列下标；由引理 3，循环在首个空列处提前终止不损失任何可达列。一方面，`ans` 非空意味着存在合法路径到达列 `ans` 的某格，由引理 1 该路径恰移动 `ans` 次，故 $\mathrm{OPT} \ge \text{ans}$；另一方面，任何移动 $k$ 次的路径终点在列 $k$ 且可达，即 $R_k \ne \varnothing$，由 `ans` 的最大性 $k \le \text{ans}$，故 $\mathrm{OPT} \le \text{ans}$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \cdot n)$。每列对每个目标行检查至多 3 个来源行，共 $n-1$ 列，总操作数约为 $3mn$；提前终止时只会更少。
- **空间复杂度**：$O(m)$。两个长度 $m$ 的布尔滚动数组；输入矩阵本身不计入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxMoves(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<char> reach(m, 1), nreach(m, 0);   // 第 0 列整列可达
        int ans = 0;
        for (int c = 1; c < n; c++) {
            bool any = false;
            for (int nr = 0; nr < m; nr++) {
                nreach[nr] = 0;
                for (int r = nr - 1; r <= nr + 1; r++) {   // 谁能走到 (nr, c)
                    if (0 <= r && r < m && reach[r] && grid[nr][c] > grid[r][c - 1]) {
                        nreach[nr] = 1;
                        any = true;
                        break;
                    }
                }
            }
            if (!any) break;                      // 本列全灭，后续列必全灭
            reach = nreach;
            ans = c;                              // 移动次数 = 最大可达列下标
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxMoves(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        reach = [True] * m                         # 第 0 列整列都是起点
        ans = 0
        for c in range(1, n):
            nreach = [False] * m
            for nr in range(m):
                for r in (nr - 1, nr, nr + 1):     # 谁能走到 (nr, c)
                    if 0 <= r < m and reach[r] and grid[nr][c] > grid[r][c - 1]:
                        nreach[nr] = True
                        break
            if not any(nreach):                    # 提前终止
                break
            reach = nreach
            ans = c                                # 移动次数 = 最大可达列下标
        return ans
```

## 8. 边界情况与易错点

1. **严格大于**：值**相等**不能移动（示例 2 中起点 $1$ 面对目标 $1$ 被卡住）。误写成 `>=` 会对相等场景多算一步。
2. **第 0 列整列可达**：所有行都是合法起点，`reach` 初始全 `true`；漏掉任何一行都可能压低答案。答案下界为 $0$（一步都走不了）。
3. **滚动数组别原地覆盖**：计算列 $c$ 时全程要读列 $c-1$ 的旧 `reach`，必须"整列算完再换"；同一个数组边算边写是典型 WA 点。
4. **提前终止的返回值**：`break` 发生在"本列全空"时，答案是**上一列**下标（当前的 $c-1$）；若用 `ans = c` 写法，务必只在非空分支更新，两种写法别混用。
5. **行边界**：$r-1$ 与 $r+1$ 都可能越界，`0 <= r < m` 只判一边就会越界或漏解。
6. **移动次数 vs 格子数**：移动次数 = 经过的格子数 $-1$；若题目改问"最多经过多少格子"，答案要 $+1$。
7. **复杂度错觉**：$m, n \le 1000$ 但 $m \cdot n \le 10^5$，二维数组其实开得下；真正致命的是不带记忆化的指数级 DFS，与数组大小无关。
