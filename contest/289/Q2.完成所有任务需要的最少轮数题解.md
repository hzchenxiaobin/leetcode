# LeetCode 完成所有任务需要的最少轮数 题解

## 1. 题目概述

- **标题 / 题号**：完成所有任务需要的最少轮数（#2244，medium）
- **链接**：https://leetcode.cn/problems/minimum-rounds-to-complete-all-tasks/
- **来源**：LeetCode 第 289 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、哈希表、计数

**题意**：给定下标从 0 开始的整数数组 `tasks`，`tasks[i]` 表示任务的难度级别。每一轮你可以完成 **2 个或 3 个相同难度级别** 的任务。返回完成所有任务需要的最少轮数；如果无法完成所有任务，返回 `-1`。

**约束**：

- `1 <= tasks.length <= 10^5`
- `1 <= tasks[i] <= 10^9`

## 2. 示例

**示例 1**

```text
输入：tasks = [2,2,3,3,2,4,4,4,4,4]
输出：4
解释：第一轮完成 3 个难度 2 的任务；第二轮完成 2 个难度 3 的任务；
     第三轮完成 3 个难度 4 的任务；第四轮完成 2 个难度 4 的任务。
```

**示例 2**

```text
输入：tasks = [2,3,3]
输出：-1
解释：难度 2 的任务只有 1 个，凑不出「2 个或 3 个」的一轮，无法完成。
```

**补充示例 3**

```text
输入：tasks = [2,2,3,3]
输出：2
解释：难度 2 与难度 3 各用一轮（每轮 2 个）完成。
```

## 3. 解题思路

### 3.1 朴素思路：逐组枚举拆分

先按难度分组计数。对某个出现次数 $c$，设用 $x$ 个「一轮 2 个」、$y$ 个「一轮 3 个」，需满足 $2x + 3y = c$，最小化 $x + y$。朴素地双重枚举 $(x, y)$ 是 $O(c^2)$，当所有任务同难度（$c = n = 10^5$）时约 $10^{10}$ 次操作，超时。

对每个 $c$ 做完全背包 DP：$f[c] = \min(f[c-2], f[c-3]) + 1$，总时间 $O(n)$ 可以通过。但本题面额只有 $\{2, 3\}$，可以直接推出 $O(1)$ 公式，无需任何搜索或 DP。

### 3.2 核心观察：分组独立 + 拆 3 和 2

![核心观察：把出现次数 c 拆成若干个 3 和 2](images/min_rounds_decompose.svg)

两个关键观察：

1. **组间独立**：每一轮只能处理**同一难度**的任务，因此不同难度之间互不影响，总最少轮数 = 各难度组的最少轮数之和。问题化归为：某难度出现次数为 $c$，求它的最少轮数。
2. **单组最优是 $\lceil c/3 \rceil$**：每轮最多消化 3 个任务，轮数下界为 $\lceil c/3 \rceil$；而 2 和 3 恰好能以达成该下界的方式凑出任何 $c \ge 2$：
   - $c \bmod 3 = 0$：全拆 3，共 $c/3$ 轮；
   - $c \bmod 3 = 2$：补 1 个 2，其余拆 3，共 $(c+1)/3$ 轮；
   - $c \bmod 3 = 1$（此时 $c \ge 4$）：退 1 个 3 换成 2 个 2，共 $(c+2)/3$ 轮。

   三种情况统一为 $\lceil c/3 \rceil$，整数除法写作 `(c + 2) / 3`。

> 💡 **唯一的无解情形是 $c = 1$**：单独一个任务既凑不成 2 个也凑不成 3 个。除此之外任何 $c \ge 2$ 都有解。

### 3.3 算法流程

![算法流程：哈希计数、特判 c=1、求和上取整](images/min_rounds_flow.svg)

```text
1. 用哈希表统计每种难度的出现次数 c          —— O(n)
2. 遍历每个 (难度 d, 次数 c)：
   a. 若 c == 1 → 整体无解，返回 -1
   b. 否则 ans += (c + 2) / 3              —— 即 ⌈c/3⌉
3. 返回 ans
```

### 3.4 示例演算

![示例演算：计数、分组拆分与求和](images/min_rounds_example.svg)

以 `tasks = [2,2,3,3,2,4,4,4,4,4]` 为例：计数得 难度 2 × 3、难度 3 × 2、难度 4 × 5；三组的最少轮数分别为 1、1、2，合计 4 轮，与示例输出一致。

## 4. 算法细节

1. **计数必须用哈希表**：`tasks[i]` 高达 $10^9$，不能开桶数组，用 `unordered_map<int,int>`（C++）或 `Counter`（Python）。
2. **上取整技巧**：`(c + 2) / 3` 在整数除法下等于 $\lceil c/3 \rceil$，三种余数情况一行统一处理，无需分类讨论。
3. **为什么优先拆 3**：2 和 3 是允许值中最小的两个，且任何 $c \ge 2$ 都能写成若干个 2 与 3 之和（$2$、$3$ 本身可拆，$4 = 2+2$，$5 = 2+3$，更大的数归纳加一个 3 即可）。要轮数最少就尽量用 3，余 1 时把一个 3 换成两个 2。
4. **DP 对拍验证**（可选）：设 $f[0] = 0$、$f[1] = +\infty$、$f[c] = \min(f[c-2], f[c-3]) + 1$，可归纳证明 $f[c] = \lceil c/3 \rceil$（$c \ge 2$），与公式一致，可用于小数据对拍。

## 5. 正确性证明

**引理 1（组间独立、答案可加）**：总最少轮数等于各难度组最少轮数之和。

**证明**：任一可行方案中，每一轮的任务难度全部相同。把方案 $S$ 的每一轮按其难度归类，得到每个难度 $d$ 的一组轮 $S_d$，它恰好把 $c_d$ 个难度 $d$ 的任务拆成若干个 2/3，即 $S_d$ 是难度 $d$ 的可行方案，且 $|S| = \sum_d |S_d| \ge \sum_d \mathrm{opt}(d)$。反过来，取每组各自的可行方案 $S_d^*$，其并集（轮的执行顺序任意）仍是全局可行方案，轮数为 $\sum_d |S_d^*|$。故总最优值 $= \sum_d \mathrm{opt}(d)$。∎

**引理 2（单组最优轮数）**：某难度出现次数为 $c$ 时，$c = 1$ 无解；$c \ge 2$ 时最少轮数为 $\lceil c/3 \rceil$。

**证明**：

- $c = 1$：一轮需要 2 或 3 个同难度任务，1 个任务无法构成任何一轮，无解。
- **下界**：每轮至多完成 3 个任务，若用 $r$ 轮完成 $c$ 个，则 $3r \ge c$，即 $r \ge \lceil c/3 \rceil$。
- **上界（构造）**：按 $c \bmod 3$ 分类。
  - $c = 3k$：$k$ 轮、每轮 3 个，$r = k = \lceil c/3 \rceil$；
  - $c = 3k+2$（$k \ge 0$）：$k$ 轮 3 个 + 1 轮 2 个，$r = k+1 = \lceil c/3 \rceil$；
  - $c = 3k+1$（$k \ge 1$，即 $c \ge 4$）：$(k-1)$ 轮 3 个 + 2 轮 2 个，$r = k+1 = \lceil c/3 \rceil$。

  三类构造均达到下界，故最少轮数恰为 $\lceil c/3 \rceil$。∎

**定理**：算法返回值为正确答案——存在某个 $c = 1$ 时返回 $-1$，否则返回 $\sum_d \lceil c_d/3 \rceil$。

**证明**：由引理 1，答案为各组最优之和；由引理 2，每组最优即 $\lceil c/3 \rceil$，且任何 $c = 1$ 的组使全局无解。算法先计数，再逐组检查 $c = 1$ 并累加 $(c+2)/3 = \lceil c/3 \rceil$，与上述结论一一对应。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟哈希计数 $O(n)$；再遍历哈希表，不同难度数不超过 $n$，每组 $O(1)$ 用公式计算。
- **空间复杂度**：$O(n)$。哈希表最多存储 $n$ 个不同难度。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumRounds(vector<int>& tasks) {
        unordered_map<int, int> cnt;
        for (int t : tasks) {
            cnt[t]++;
        }
        int ans = 0;
        for (auto& [d, c] : cnt) {
            if (c == 1) {
                return -1;
            }
            ans += (c + 2) / 3; // 即 ceil(c / 3)
        }
        return ans;
    }
};
```

### Python

```python
from collections import Counter

class Solution:
    def minimumRounds(self, tasks: List[int]) -> int:
        cnt = Counter(tasks)
        ans = 0
        for c in cnt.values():
            if c == 1:
                return -1
            ans += (c + 2) // 3
        return ans
```

## 8. 边界情况与易错点

1. **`c == 1` 是唯一无解情形**：不要误判 `c = 2`（一轮 2 个）或 `c = 4`（2+2 两轮）无解。
2. **余 1 不能下取整**：如 `c = 4` 的答案是 2 不是 1，`c = 7` 的答案是 3 不是 2；必须用 `(c + 2) / 3` 而不是 `c / 3`。
3. **难度值域大**：`tasks[i] <= 10^9`，必须哈希表计数，不能开数组当桶。
4. **`n = 1`**：单个任务即 `c = 1`，返回 `-1`。
5. **答案不会溢出**：轮数上界为 $\lceil n/2 \rceil \le 5 \times 10^4$，`int` 足够。
6. **读清题意**：一轮内必须**难度完全相同**，「2 个 + 1 个其他难度」是不合法的一轮。

**延伸思考**：

- 若每轮可完成 **2 或 4** 个同难度任务：2、4 均为偶数，奇数 $c$ 无解；偶数 $c$ 的答案是 $\lceil c/4 \rceil$（尽量用 4，余 2 补一个 2）。
- 若每轮可完成 $[2, k]$ 中任意个数（$k \ge 3$）：$c \ge 2$ 时答案仍为 $\lceil c/k \rceil$——下界仍是每轮容量，上界可构造达到。
- 若面额为任意 $\{a, b\}$：可解性与最优解需同余分析或小规模 DP，例如 $\{4, 6\}$ 凑不出任何奇数与 2。
