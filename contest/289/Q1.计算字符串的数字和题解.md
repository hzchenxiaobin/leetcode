# LeetCode 计算字符串的数字和 题解

## 1. 题目概述

- **标题 / 题号**：计算字符串的数字和（#2243，easy）
- **链接**：https://leetcode.cn/problems/calculate-digit-sum-of-a-string/
- **来源**：LeetCode 第 289 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定数字串 $s$（由 `0`–`9` 组成）与整数 $k$。当 $\text{len}(s) > k$ 时可执行一轮操作：把 $s$ 依次切成若干长度为 $k$ 的连续段（**末段可不足 $k$**），每段替换为该段数字之和的十进制串，再拼接成新串；如此反复，直到长度 $\le k$，返回最终的 $s$。

**约束**：

- $1 \le \text{s.length} \le 100$
- $2 \le k \le 100$
- `s` 仅由数字 `0`–`9` 组成

> 💡 签到题，**题意即算法**：`while len > k` 里做「切段 → 求和 → 拼接」。赛时唯一值得多想 30 秒的是「循环会不会停」（全 `9` 串一轮后长度可能不变），这也是本题作为签到题唯一能沉淀的证明素材。

> 💡 本题在本仓库另有[每日题解 2243](../../solution/2201-2300/2243_计算字符串的数字和.md)：主线同为模拟，附面试问答与「为何不能套用数字根公式」的展开论证。本篇按**周赛复盘视角**展开，补齐引理-定理化的终止性证明与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：s = "11111222223", k = 3
输出："135"
解释：
- 第一轮："111" | "112" | "222" | "23" → 和 3, 4, 6, 5 → "3465"
- 第二轮："346" | "5" → 和 13, 5 → "135"
- len("135") = 3 ≤ k，返回 "135"
```

**示例 2**

```text
输入：s = "00000000", k = 3
输出："000"
解释："000" | "000" | "00" → 和 0, 0, 0 → "000"，长度恰为 3 = k，停止。
注意和为 0 时拼的是 "0"，不是空串。
```

**补充示例 3（长度一度不缩，关键边界）**

```text
输入：s = "9999", k = 2
输出："99"
解释：
- 第一轮："99" | "99" → 和 18, 18 → "1818"（长度 4 → 4，没有缩短！）
- 第二轮："18" | "18" → 和 9, 9 → "99"（长度 4 → 2，停止）
```

## 3. 解题思路

### 3.1 暴力思路

数据范围 $L \le 100$、$k \ge 2$，任何按题意逐轮模拟的写法都能过：每轮新建空串 `next`，`i` 从 0 以步长 $k$ 走到串尾，取 `s[i:i+k]` 求数位和并拼接到 `next`，一轮结束令 `s = next`。这就是正解——本题不存在需要绕过模拟的更优做法。

### 3.2 核心观察：总数字和单调不增，循环必终止

![核心：切段→求和→拼接循环，总数字和单调不增保证终止](images/wc289_q1_digit_sum_loop_concept.svg)

看似每段求和可能让新串不比旧串短（补充示例 3 中 `"9999"` → `"1818"` 长度不变），但有两个不变量保证收敛：

1. **总数字和 $S$ 单调不增**：设一轮前所有字符数值之和为 $S$，各段和为 $g_1, \dots, g_m$，则 $\sum g_i = S$；新串的总数字和 $S' = \sum \text{digitSum}(g_i) \le \sum g_i = S$。由数位和基本性质 $\text{digitSum}(t) \le t$（$t \ge 10$ 时严格成立），**只要存在某段和 $\ge 10$，$S$ 就严格递减**。
2. **所有段和均为一位数时长度骤缩**：每段替换为单字符，新长度 $L' = \lceil L/k \rceil$。由循环条件 $L > k \ge 2$ 得 $L \ge 3$，故 $\lceil L/k \rceil \le \lceil L/2 \rceil < L$，长度严格下降。

> 💡 两类轮必居其一：**要么 $S$ 严格递减，要么长度骤缩**——不存在「既不递减又不缩短」的原地踏步轮，因此循环必然终止。

### 3.3 算法流程

![算法流程：外层 while len>k，内层按步长 k 取组求和拼接](images/wc289_q1_digit_sum_flow.svg)

1. **外层判断**：`len(s) > k` 才进一轮；初始即满足 `len ≤ k` 时原样返回。
2. **内层遍历**：`i` 从 $0$ 步进 $k$ 枚举每段起点，切片 `s[i:i+k]` 越界自动截断。
3. **求和拼接**：段内字符数值求和 `g`，把 `str(g)` 追加到 `next`（注意 `str(0)` 是 `"0"`）。
4. **更新**：`s = next`，回到外层判断。

### 3.4 示例演算

![示例演算：长度骤缩与总数字和递减两种收敛机制](images/wc289_q1_digit_sum_walkthrough.svg)

| 输入 | 轮次 | 切分 | 各段和 | 新串 | 长度 | 机制 |
|------|------|------|--------|------|------|------|
| `s="11111222223"`, $k=3$ | 1 | `111`\|`112`\|`222`\|`23` | 3, 4, 6, 5 | `"3465"` | 11 → 4 | 长度骤缩（$S$ 保持 18） |
| | 2 | `346`\|`5` | 13, 5 | `"135"` | 4 → 3 | 段和 13 ≥ 10，$S$ 递减到 9，停止 |
| `s="9999"`, $k=2$ | 1 | `99`\|`99` | 18, 18 | `"1818"` | 4 → 4 | 长度不变，但 $S$ 递减 36 → 18 |
| | 2 | `18`\|`18` | 9, 9 | `"99"` | 4 → 2 | 长度骤缩，停止 |

**答案**：示例 1 为 `"135"`；补充示例为 `"99"` ✓

## 4. 算法细节

1. **切段**：`range(0, len(s), k)` 枚举起点，切片 `s[i:i+k]`（Python）或 `substr(i, k)`（C++）在越界时自动取到串尾，**末段无需任何特判**。
2. **求和**：逐字符 `int(c)` / `s[j] - '0'` 累加；每段至多 $k \le 100$ 个数字，段和 $\le 9k = 900$，`int` 足够。
3. **拼接**：C++ 用 `next += to_string(g)`；Python 用列表 `append` + `"".join`（避免字符串 `+=` 的反复分配）。
4. **循环条件**：`len(s) > k`——注意是**严格大于**，等于 $k$ 即停；初始长度 $\le k$ 时 `while` 一次都不进，天然返回原串。

## 5. 正确性证明

**引理 1**（轮等价）：算法执行一轮循环后得到的字符串，与题面一轮操作的结果完全相同。

**证明**：题面一轮 = 依次切段 + 各段替换为和的十进制串 + 按序拼接。算法中 `i` 以步长 $k$ 从 $0$ 遍历，`s[i:i+k]` 恰为第 $\lfloor i/k \rfloor + 1$ 段（切片越界截断保证末段取到串尾、长度为 $L \bmod k$ 或 $k$）；对该段求字符数值之和 $g$，`str(g)`/`to_string(g)` 即 $g$ 的十进制表示（$g=0$ 时为 `"0"`，非空）；按遍历顺序拼接即题面合并结果。∎

**引理 2**（终止性）：循环经有限轮后必满足 $\text{len}(s) \le k$。

**证明**：记某轮开始时长度为 $L > k$、总数字和为 $S = \sum \text{字符数值}$，各段和为 $g_1, \dots, g_m$（$m = \lceil L/k \rceil$）。每轮必属以下两类之一：

- **类 A（存在 $g_i \ge 10$）**：新串总数字和 $S' = \sum \text{digitSum}(g_i)$。由 $\text{digitSum}(t) \le t$ 且 $t \ge 10$ 时严格成立，$S' \le S - 1$，即 $S$ 至少减 1。
- **类 B（所有 $g_i \le 9$）**：每段替换为单个字符，新长度 $L' = m = \lceil L/k \rceil$。由 $L > k \ge 2$ 知 $L \ge 3$，故 $L' \le \lceil L/2 \rceil \le \frac{L+1}{2} < L$，长度至少减 1。

初始 $S_0 \le 9L_0$、$L_0 \ge 1$。类 A 轮使非负整数 $S$ 每次至少减 1，至多出现 $S_0 \le 9L_0$ 次；类 B 轮使正整数 $L$ 每次至少减 1，至多出现 $L_0$ 次。两类轮数之和有限，故循环有限轮后终止。∎

**定理**：算法返回题面所求的最终字符串。

**证明**：对执行轮数归纳。由引理 1，每一轮变换与题面一轮操作逐一相同；循环条件 `len > k` 与题面「长度大于 $k$ 才可操作」一致。由引理 2 循环终止，终止时 $\text{len} \le k$ 恰为题面停止条件，此时 $s$ 即按题面操作到底的结果。∎

## 6. 复杂度分析

- **时间复杂度**：$O(L \cdot R)$，其中 $L = \text{len}(s)$、$R$ 为轮数。每轮切段求和拼接为 $O(L)$。由引理 2 的证明，$R \le 10L$（宽松上界）；实际收敛极快——最坏情形（$k=2$ 的全 `9` 串，$L=100$）实测约 12 轡，长度大致每两轮减半，即实际 $R \approx 2\log_2 L$。$L \le 100$ 时总操作数不超过 $10^4$ 量级，远在时限内。
- **空间复杂度**：$O(L)$。每轮新建 `next` 字符串，峰值长度 $O(L)$（新长度 $\le 3\lceil L/k \rceil \le 3L/2$，常数级），旧串用后即弃。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string digitSum(string s, int k) {
        while ((int)s.size() > k) {
            string next;
            for (int i = 0; i < (int)s.size(); i += k) {
                int g = 0;
                for (int j = i; j < min(i + k, (int)s.size()); ++j)
                    g += s[j] - '0';
                next += to_string(g);
            }
            s = move(next);
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def digitSum(self, s: str, k: int) -> str:
        while len(s) > k:
            nxt = []
            for i in range(0, len(s), k):
                nxt.append(str(sum(int(c) for c in s[i:i + k])))
            s = "".join(nxt)
        return s
```

## 8. 边界情况与易错点

1. **末段不足 $k$**：切片 `s[i:i+k]` / `substr(i, k)` 越界自动截断，**无需特判**；手动计算末段长度（$L \bmod k$，为 0 时恰为 $k$）是本题最常见的写错点。
2. **段和为 0 拼成 `"0"` 而非空串**：示例 2 的 `"00000000"` 考察此点；`str(sum(...))` / `to_string(g)` 天然正确，若手写「和为 0 跳过」会漏字符。
3. **停止条件是 `len ≤ k` 不是 `len < k`**：长度恰好等于 $k$（如 `"000"`、`k=3`）必须立即停止，写成 `<` 会多操作一轮导致答案错误。
4. **初始长度 $\le k$**：直接原样返回，`while` 写法天然覆盖，切勿写成 do-while 结构。
5. **多位段和参与下一轮**：段和可以是两位数（如 13），下一轮把它当普通数字串继续切分——这是题意而非 bug。
6. **C++ 符号比较**：`s.size()` 是无符号类型，与 `int k` 直接比较在 $k$ 可能为负时才出问题，本题安全，但 `(int)s.size() > k` 的显式转换是更稳的习惯。
7. **无溢出风险**：段和 $\le 9k \le 900$，轮内累加与字符串长度均在 `int` 与 $O(L)$ 范围内。
