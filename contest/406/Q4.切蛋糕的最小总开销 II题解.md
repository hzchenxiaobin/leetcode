# LeetCode 切蛋糕的最小总开销 II 题解

## 1. 题目概述

- **标题 / 题号**：切蛋糕的最小总开销 II（#3219，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-for-cutting-cake-ii/
- **来源**：LeetCode 第 406 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、排序、双指针、计数

**题意**：与同场 Q3（#3218）完全同款：把一块 $m \times n$ 的矩形蛋糕切成 $1\times 1$ 小块，每次操作任选一块**当前不是 $1\times 1$** 的矩形蛋糕，沿一条水平线 $i$ 或竖直线 $j$ 把它一分为二，开销固定为 $horizontalCut[i]$ / $verticalCut[j]$（**按刀计费、与块的大小无关**），求全部切开的最小总开销。唯一的区别：数据范围从 $m, n \le 20$ 放大到 $m, n \le 10^5$。

**约束**：

- $1 \le m, n \le 10^5$
- $horizontalCut.length == m-1$，$verticalCut.length == n-1$
- $1 \le horizontalCut[i], verticalCut[i] \le 10^3$

> 💡 I/II 双胞胎是周赛的固定戏码：Q3 用小范围养活区间 DP、暴力搜索等"保底解"，Q4 把范围放大 $5000$ 倍，逼你交出**结构性结论**。如果 Q3 是靠 DP 过的，Q4 就是检验你是否看穿了本质——而本题的本质异常漂亮：**最优答案根本不依赖切线的位置，也不依赖 $m, n$ 的具体值，只依赖两条开销表的内容**。

## 2. 示例

**示例 1**

```text
输入：m = 3, n = 2, horizontalCut = [1,3], verticalCut = [5]
输出：13
解释：先切 v₀（5×1 刀）；再在两个 3×1 竖条里各切 h₁（3×2 刀）；
     最后在两块 2×1 里各切 h₀（1×2 刀）。总计 5 + 6 + 2 = 13。
```

**示例 2**

```text
输入：m = 2, n = 2, horizontalCut = [7], verticalCut = [4]
输出：15
解释：先切贵的 h₀（7×1 刀），蛋糕变成两个 1×2 横条；
     每个横条里各切 v₀（4×2 刀）。总计 7 + 4 + 4 = 15。
```

**示例 3**（自造，覆盖多刀乘数与闭式核对）

```text
输入：m = 4, n = 3, horizontalCut = [7,1,1], verticalCut = [5,3]
输出：29
解释：Σ线开销 = 7+1+1+5+3 = 17；6 个交叉点逐对取较便宜者：
     min(7,5)+min(7,3)+min(1,5)+min(1,3)+min(1,5)+min(1,3)
     = 5+3+1+1+1+1 = 12；合计 17 + 12 = 29。
```

## 3. 解题思路

### 3.1 暴力思路：Q3 的全部保底解被 10⁵ 封死

![Q4 的复杂度墙：DP 与模拟全部超时，只看线才活得了](images/cut_cake_ii_scale_wall.svg)

Q3 能过的三条路——全排列枚举、记忆化搜索、区间 DP（状态 $O(m^2n^2)$、转移 $O(m+n)$）——在 $m = n = 10^5$ 下分别需要约 $10^{40}$、同量级与 $10^{20}$ 级的操作数，全部超时。更绝望的是：**任何"盯着块"的做法都活不了**，因为蛋糕最终有 $mn = 10^{10}$ 块，连把块遍历一遍都做不到。这堵墙指出唯一出路：最优解必须能**不看块、只看线**地算出来——我们需要一个只关于"两条开销表"的公式。

### 3.2 核心观察：交叉点配对 → 闭式

![闭式：每个交叉点贡献 min(h,v)，答案只由两条开销表决定](images/cut_cake_ii_min_pair_grid.svg)

两个观察（图解展开见 Q3 题解 3.2 节，这里直取结论）：

**观察一（放大器）**：一条水平线被切穿时，若竖直方向已被分成 $v$ 个竖条，它必须切 $v$ 刀、付 $h \times v$；**越晚切，穿过的块越多**。所以贵的线要赶早，便宜线殿后。

**观察二（配对计数）**：每对水平线 $h$、竖直线 $v$ 恰有一个**交叉点**，交叉处**后切的那条**必须为这个交叉额外多付一刀线开销（先切者一刀越过交叉点，后切者被挡在两侧各切一次）。于是任一完整方案的总开销可以精确拆成：

$$\text{Total} \;=\; \underbrace{\sum_{\text{线 } c} cost(c)}_{\text{每条线至少一刀}} \;+\; \underbrace{\sum_{\text{每对 }(h,v)} cost(\text{后切者})}_{(m-1)(n-1)\ \text{对}}$$

每对交叉至少贡献 $\min(h, v)$，立刻得到下界；而把所有切线**按开销从大到小**依次切穿，每对的后切者恰好都是较便宜的那条（贵线总是先来），逐对取到 $\min$——下界紧可达。于是得到本题的**闭式**：

$$\boxed{\ \text{ans} \;=\; \sum_c cost(c) \;+\; \sum_{i=1}^{m-1}\sum_{j=1}^{n-1} \min(h_i,\, v_j)\ }$$

这个闭式对 Q4 是"救命"级别的：它说明**答案只依赖两条开销数组的多元集合**——与切线的位置、与 $m, n$ 的具体大小统统无关（$m, n$ 只通过数组长度起作用）。右边虽有 $(m-1)(n-1) \approx 10^{10}$ 对，看似也要枚举，但 $\min$ 的结构允许**不枚举对而直接统计**（见 3.3 与 §4）。

### 3.3 算法流程：降序双指针归并 / 闭式阈值分层

**实现一（推荐，与 Q3 同款代码换个类型）**：两列各自降序，双指针归并模拟"全局从贵到便宜"：

```text
1. H ← horizontalCut 降序；V ← verticalCut 降序
2. i ← j ← 0；h_cnt ← v_cnt ← 1（整块蛋糕各算 1 条）；ans ← 0
3. 循环直到两列取尽：
   a. 头较大者胜（平局任取）：
      取 H[i] → ans += H[i] × v_cnt；h_cnt++；i++
      取 V[j] → ans += V[j] × h_cnt；v_cnt++；j++
4. 返回 ans
```

- 切水平线乘 $v\_cnt$：此刻竖直方向已有 $v\_cnt$ 个竖条，水平线横穿每条各一刀；
- 每步 $O(1)$、每条线只出列一次，排序之后线性扫完。

**实现二（闭式 + 阈值分层，$O(m+n+C)$）**：利用恒等式

$$\min(a,b) \;=\; \sum_{t=1}^{\infty} [\,a \ge t\,]\,[\,b \ge t\,]$$

把 $\sum_{(h,v)} \min(h,v)$ 的**求和次序按"层"翻转**：

$$\sum_{(h,v)} \min(h,v) \;=\; \sum_{t=1}^{C} H_{\ge}(t) \cdot V_{\ge}(t)$$

其中 $H_{\ge}(t)$ 为开销 $\ge t$ 的水平线条数（$V_{\ge}$ 同理），$C = 10^3$ 是开销上限。直觉：把每条线的开销想成一摞单位高度的"层"，$\min(a,b)$ 就是两条线**共同拥有的层数**；把逐对求和换成逐层清点"这一层上有几条 $h$ × 几条 $v$"，即为上式。

![阈值分层：min(a,b) 等于共同层数，按层清点代替按对枚举](images/cut_cake_ii_threshold_layers.svg)

两个后缀计数用**桶**统计：先数出每个开销值的出现次数，再从 $t = C$ 往 $t = 1$ 一趟累加即得 $H_{\ge}, V_{\ge}$，全程 $O(m+n+C)$，连排序都省了——开销 $\le 10^3$ 这个"不起眼"的约束，在这里变成了免排序的通行证。

### 3.4 示例演算

![双指针归并演算：H=[7,1,1]，V=[5,3]，闭式两路互验](images/cut_cake_ii_merge_walkthrough.svg)

以自造示例 3 走一遍（$H$ 排成 $[7,1,1]$，$V = [5,3]$）：

| 步骤 | 取谁 | 乘数（另一方向块数） | 代价 | 累计 |
|------|------|:---:|:---:|:---:|
| 1 | $h=7$ | $v\_cnt=1$ | $7\times 1=7$ | 7 |
| 2 | $v=5$ | $h\_cnt=2$ | $5\times 2=10$ | 17 |
| 3 | $v=3$ | $h\_cnt=2$ | $3\times 2=6$ | 23 |
| 4 | $h=1$ | $v\_cnt=3$ | $1\times 3=3$ | 26 |
| 5 | $h=1$ | $v\_cnt=3$ | $1\times 3=3$ | **29** ✓ |

三条路互验：贪心得 $29$；闭式 $\sum cost = 17$、配对项 $5+3+1+1+1+1 = 12$、合计 $29$；阈值分层 $H_\ge = (3,1,1,1,1,1,1)$、$V_\ge = (2,2,2,1,1,0,0)$、逐层乘积 $6+2+2+1+1+0+0 = 12$、合计 $29$——完全对上。

## 4. 算法细节

1. **排序方向**：两列都**降序**。归并时每次取较大头，输出的合并序列恰是全局非增的——这正是"按开销从大到小切"的等价实现；无需真的把两列合并排序（同向平行线互不交叉，先后无代价差异）。
2. **乘数方向**：切水平线乘 $v\_cnt$（**另一方向**的块数），切竖直线乘 $h\_cnt$。方向写反是最隐蔽的 WA——样例前两刀的乘数恰好都是 1。
3. **计数器初值为 1**：整块蛋糕初始就是 1 个横条、1 个竖条，写成 0 会让所有乘数少 1。
4. **64 位整数（Q4 头号杀手）**：答案上界 $\sum h_i \cdot n + \sum v_j \cdot m \le 10^5 \times 10^3 \times 10^5 \times 2 = 2\times 10^{13}$，`int32` 必炸。C++ 返回值本身就是 `long long`，但**乘法现场**两个 `int` 相乘会先溢出再累加，必须 `1LL *` 先转换；Python 大数自然安全。
5. **桶统计方向**：实现二从 $t = C$ 往低累加才得到"$\ge t$"的**后缀**计数；别忘了基础项 $\sum cost$（每条线的第一刀）。
6. **平局任取**：$\min$ 对相等对称，比较写成 `>=` 或 `>` 均最优，但要全篇一致，别写出两边都取不到的死循环。
7. **闭式对拍**：实现一、实现二互为对拍器；再叠上 Q3 的小范围暴力 DFS 三方对拍最稳。

## 5. 正确性证明

约定一次**操作**选中一块矩形并沿一条横穿它的切线切开；每对 $(h, v)$ 有唯一**交叉点**，交叉处两条线各自的刀按时间先后分称先切者 / 后切者。（框架与 Q3 题解 §5 相同，此处收紧陈述。）

**引理 1（切数分解）**：任一完整方案中，水平线 $h$ 的操作次数 $k_h = 1 + \big|\{v : v \text{ 在交叉点 } (h,v) \text{ 处先切}\}\big|$；竖直线对称。

**证明**：$h$ 上的各刀把它切成 $k_h$ 段，相邻两段的拼接处称为**断点**。断点必落在某竖直线 $v$ 上，且"该处是断点" $\iff$ "$v$ 在交叉处先切"：若 $v$ 先切，包含交叉点的块已被 $v$ 分成左右两块，$h$ 的任何一刀无法同时越过 $v$，该处必为断点；反之，切断点右侧那刀时所在块以 $v$ 为左边界，说明 $v$ 已先切。段数 = 断点数 + 1。∎

**推论（总代价分解）**：$\text{Total} = \sum_c cost(c) \cdot k_c = \sum_c cost(c) + \sum_{(h,v)} cost(\text{后切者})$。

**证明**：由引理 1，$\sum_c (k_c - 1) = \sum_{(h,v)} 1$，且每个交叉点恰归给后切者一次。∎

**定理 1（下界）**：$\text{Total} \;\ge\; \sum_c cost(c) + \sum_{(h,v)} \min(cost(h),\, cost(v))$。

**证明**：推论中每个交叉点贡献 $cost(\text{后切者}) \ge \min(cost(h), cost(v))$。∎

**定理 2（降序贪心最优）**：将全部切线按开销从大到小依次切穿（等价实现：两列各自降序 + 双指针归并），总开销恰为 $\sum_c cost(c) + \sum_{(h,v)} \min(cost(h), cost(v))$，达到下界，故为最优；其值即 3.2 节闭式，亦等于实现二的阈值分层和 $\sum_c cost(c) + \sum_{t=1}^{C} H_\ge(t) \cdot V_\ge(t)$。

**证明**：任取一对 $(h, v)$，不妨 $cost(h) \ge cost(v)$。降序序列中 $h$ 先处理：处理 $h$ 时 $v$ 尚未切，含交叉点的块未被 $v$ 分开，$h$ 的刀连续越过交叉点——该交叉点的后切者是 $v$，贡献 $cost(v) = \min(cost(h), cost(v))$。每条线轮到时切穿其当前穿过的所有块，全部操作集中在这一轮，故每个交叉点恰被计入一次；由推论，总开销等于定理 1 的下界。阈值分层等价性由恒等式 $\min(a,b) = \sum_t [a \ge t][b \ge t]$ 交换求和次序即得。∎

> 💡 大数据版的意义正在于此：证明给出的不只是"贪心对"，而是一个**与规模无关的公式**——$m, n$ 各放大到 $10^5$，公式一个字符都不用改。这正是"I/II 双胞胎"题的教育价值：小数据骗你写 DP，大数据逼你发现公式。

## 6. 复杂度分析

- **时间复杂度**：实现一 $O(m\log m + n\log n)$，排序主导，归并每步 $O(1)$、共 $m+n-2$ 步；实现二 $O(m+n+C)$，$C = 10^3$。两者在 $m, n \le 10^5$ 下都远低于时限。
- **空间复杂度**：实现一 C++ 原地降序排序、双指针与两个计数器，额外 $O(1)$；Python `sorted` 拷贝为 $O(m+n)$。实现二只需两个长度 $C+1$ 的计数桶，$O(C)$。

## 7. 参考代码

### C++（实现一：降序归并，全程 64 位）

```cpp
class Solution {
public:
    long long minimumCost(int m, int n, vector<int>& horizontalCut, vector<int>& verticalCut) {
        sort(horizontalCut.rbegin(), horizontalCut.rend());   // 降序：贵的先切
        sort(verticalCut.rbegin(), verticalCut.rend());
        long long ans = 0;
        int i = 0, j = 0, hCnt = 1, vCnt = 1;
        while (i < m - 1 || j < n - 1) {
            if (j == n - 1 || (i < m - 1 && horizontalCut[i] >= verticalCut[j])) {
                ans += 1LL * horizontalCut[i++] * vCnt;  // 水平线横穿 vCnt 个竖条
                hCnt++;                                  // 此后竖直线多穿一个横条
            } else {
                ans += 1LL * verticalCut[j++] * hCnt;    // 竖直线横穿 hCnt 个横条
                vCnt++;                                  // 此后水平线多穿一个竖条
            }
        }
        return ans;
    }
};
```

### Python（实现一：降序归并）

```python
class Solution:
    def minimumCost(self, m: int, n: int, horizontalCut: List[int],
                    verticalCut: List[int]) -> int:
        H = sorted(horizontalCut, reverse=True)     # 降序：贵的先切
        V = sorted(verticalCut, reverse=True)
        i = j = 0
        h_cnt = v_cnt = 1
        ans = 0
        while i < len(H) or j < len(V):
            if j == len(V) or (i < len(H) and H[i] >= V[j]):
                ans += H[i] * v_cnt    # 水平线横穿 v_cnt 个竖条
                h_cnt += 1
                i += 1
            else:
                ans += V[j] * h_cnt    # 竖直线横穿 h_cnt 个横条
                v_cnt += 1
                j += 1
        return ans
```

### Python（实现二：闭式 + 桶，$O(m+n+C)$）

```python
class Solution:
    def minimumCost(self, m: int, n: int, horizontalCut: List[int],
                    verticalCut: List[int]) -> int:
        C = 1000
        hb = [0] * (C + 2)
        vb = [0] * (C + 2)
        for c in horizontalCut:
            hb[c] += 1
        for c in verticalCut:
            vb[c] += 1
        total = sum(horizontalCut) + sum(verticalCut)
        pair_min = 0
        h_ge = v_ge = 0
        for t in range(C, 0, -1):      # 从高到低累加 → 开销 ≥ t 的条数
            h_ge += hb[t]
            v_ge += vb[t]
            pair_min += h_ge * v_ge    # min(a,b) = Σt [a≥t]·[b≥t]
        return total + pair_min
```

## 8. 边界情况与易错点

1. **32 位溢出（Q4 的 WA 重灾区）**：答案上界约 $2\times 10^{13}$，C++ `int` 必炸。光把 `ans` 声明成 `long long` 还不够——`horizontalCut[i] * vCnt` 两个 `int` 相乘**先溢出再累加**照样错，必须 `1LL *` 先转换（见参考代码）。
2. **$m = 1$ 或 $n = 1$**：一个方向没有切线，循环只剩另一方向、乘数恒为 1（每刀只穿一块）；$m = n = 1$ 时两表皆空、答案 0——均无需特判，空数组排序也无害。
3. **把 Q3 的 DP 搬过来**：区间 DP 状态数 $\sim 10^{20}$，稳 TLE；II 版存在的意义就是封死这条路。反过来，本篇两个实现都能直接过 Q3。
4. **乘数方向写反**：切水平线乘的是 $v\_cnt$（**竖**条数）；样例 1 前两刀乘数恰好都是 1，错得极其隐蔽（详见 Q3 题解 §8 的反例推演）。
5. **升序排序**：反向贪心把放大器用反，样例 1 直接算出 $19 \ne 13$。
6. **计数器初值写成 0**：所有乘数系统性少 1。
7. **桶版细节**：`range(C, 0, -1)` 从高往低累加才是"$\ge t$"后缀计数；漏加基础项 $\sum cost$ 会整体偏小。
8. **平局处理**：比较符全篇一致（`>=` 或 `>`），别写出两边都取不到的死循环。
