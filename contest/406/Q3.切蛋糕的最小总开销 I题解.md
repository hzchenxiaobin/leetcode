# LeetCode 切蛋糕的最小总开销 I 题解

## 1. 题目概述

- **标题 / 题号**：切蛋糕的最小总开销 I（#3218，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-for-cutting-cake-i/
- **来源**：LeetCode 第 406 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、双指针、动态规划、排序

**题意**：把一块 $m \times n$ 的矩形蛋糕切成 $1 \times 1$ 小块。每次操作任选一块**当前不是 $1\times 1$** 的矩形蛋糕，沿一条水平线 $i$ 或竖直线 $j$ 把它一分为二，开销固定为 $horizontalCut[i]$ 或 $verticalCut[j]$。同一条线切几次就付几次钱（示例 1 中开销 1 和 3 的水平线都付了两次）。求全部切成 $1\times 1$ 的最小总开销。

**约束**：

- $1 \le m, n \le 20$
- $horizontalCut.length == m-1$，$verticalCut.length == n-1$
- $1 \le horizontalCut[i], verticalCut[i] \le 10^3$

> 💡 题意里最容易被忽略的一句是「每次操作的开销都为最开始对应切割线的开销」——**开销按"刀"计、与块的大小无关**，于是"什么时候切这条线"（决定这条线要切几刀）成为唯一的自由度，这正是本题的全部戏肉。

## 2. 示例

**示例 1**

```text
输入：m = 3, n = 2, horizontalCut = [1,3], verticalCut = [5]
输出：13
解释：先切 v₀（5×1 刀）；再在两个 3×1 竖条里各切 h₁（3×2 刀）；
     最后在两块 2×1 里各切 h₀（1×2 刀）。总计 5 + 6 + 2 = 13。
```

**示例 2**

```text
输入：m = 2, n = 2, horizontalCut = [7], verticalCut = [4]
输出：15
解释：先切 h₀（7×1 刀），蛋糕变成两个 1×2 横条；
     每个横条里各切 v₀（4×2 刀）。总计 7 + 4 + 4 = 15。
```

**示例 3**

```text
输入：m = 2, n = 3, horizontalCut = [10], verticalCut = [1,1]
输出：14
解释：先切贵的 h₀（10×1 刀），再切两条便宜的竖线（各 1×2 刀）。
     若反过来先切竖线，h₀ 就要穿过 3 个横条：1+1+10×3 = 32，直接翻倍还多。
```

## 3. 解题思路

### 3.1 暴力思路：枚举切割顺序

切割顺序决定一切，最直接的想法是枚举 $m+n-2$ 条切线的全排列——$20+20-2=38$ 条线有 $38! \approx 5\times 10^{43}$ 种排法，天文数字。

退一步：$m, n \le 20$ 允许**区间 DP**。设 $f(r_1, r_2, c_1, c_2)$ 为把子矩形（保证当前是完整一块）全部切开的最小开销，枚举第一刀：

$$f = \min\Big(\min_{r_1<i<r_2} h_i + f(r_1,i,c_1,c_2) + f(i,r_2,c_1,c_2),\ \min_{c_1<j<c_2} v_j + f(r_1,r_2,c_1,j) + f(r_1,r_2,j,c_2)\Big)$$

状态 $O(m^2n^2)$、转移 $O(m+n)$，$m=n=20$ 时约 $6.4\times 10^6$，稳过——这是赛时的保底解。但它看不出任何结构，且搬到同场 Q4（$m,n\le 10^5$）直接爆炸。真正的结论要漂亮得多。

### 3.2 核心观察：开销放大器与"交叉点配对"

![核心观察：切得越晚穿过的块越多，贵线要趁早切](images/cut_cake_multiplier_concept.svg)

两个层层递进的观察：

**观察一（放大器）**：一条水平线最终要被切几刀，取决于它被切时**穿过了几块蛋糕**。若它轮到时竖直方向已被切成 $v$ 个竖条，它就得切 $v$ 刀、付 $h \times v$。越晚切，穿过的块越多——同样一条线，晚一步代价就翻倍（见上图）。所以**贵的线要赶早切**，便宜线殿后。

**观察二（配对计数）**：每对水平线 $h$ 与竖直线 $v$ 恰有一个交叉点。在交叉处，两条线中**后切的那条**必须为这个交叉额外多付一刀线开销（先切者一刀越过交叉点，后切者被挡在两侧各切一次）。于是任一完整方案的总开销可以精确拆成：

$$\text{总开销} \;=\; \sum_{\text{线 } c} cost(c) \;+\; \sum_{\text{每对 }(h,v)} \text{后切者的开销}$$

由观察二立刻得到下界：每对 $(h,v)$ 至少贡献 $\min(h, v)$，故

$$\text{总开销} \;\ge\; \sum_c cost(c) + \sum_{(h,v)} \min(h, v)$$

而**把所有切线按开销从大到小依次切穿**的方案，恰好让每一对的"后切者"都是较便宜的那条（贵线总是先来），逐对取到 $\min$——下界紧可达，这就是最优解，甚至是个**闭式**。

### 3.3 算法流程：两个降序列表归并

![算法流程：两个降序列表双指针归并，乘数是另一方向的块数](images/cut_cake_greedy_merge.svg)

实现上不需要显式排序全体（同向平行线互不交叉、先后无代价差异，各自降序即可），用**双指针归并**模拟"全局从贵到便宜"：

```text
1. H ← horizontalCut 降序；V ← verticalCut 降序
2. i ← j ← 0；h_cnt ← v_cnt ← 1（整块蛋糕各算 1 条）；ans ← 0
3. 循环直到两列取尽：
   a. 头较大者胜（相等任取）：取 H[i] → ans += H[i] × v_cnt；h_cnt++；i++
                      取 V[j] → ans += V[j] × h_cnt；v_cnt++；j++
4. 返回 ans
```

- 切水平线时乘 $v\_cnt$：此时竖直方向已有 $v\_cnt$ 个竖条，水平线横穿每条各一刀；
- 切完一条水平线后 $h\_cnt{+}{+}$：此后每条竖直线要多穿一个横条。

### 3.4 示例演算

![示例演算：m=3, n=2, H=[1,3], V=[5] 的最优切割过程](images/cut_cake_example_walkthrough.svg)

以示例 1 走一遍（$H$ 排成 $[3,1]$，$V=[5]$）：

| 步骤 | 取谁 | 乘数（另一方向块数） | 代价 | 累计 |
|------|------|:---:|:---:|:---:|
| 1 | $v=5$ | $h\_cnt=1$ | $5\times 1=5$ | 5 |
| 2 | $h=3$ | $v\_cnt=2$ | $3\times 2=6$ | 11 |
| 3 | $h=1$ | $v\_cnt=2$ | $1\times 2=2$ | **13** ✓ |

闭式复核：$\sum cost = 1+3+5=9$，配对项 $\min(1,5)+\min(3,5)=4$，合计 $13$，两条路完全对上。

## 4. 算法细节

1. **排序方向**：两列都**降序**。归并时每次取较大头，输出的合并序列恰是全局非增的——这正是"按开销从大到小切"的等价实现。
2. **乘数方向**：切水平线乘 $v\_cnt$（竖条数），切竖直线乘 $h\_cnt$（横条数）。**乘的是另一方向的块数**，方向写反是最常见的 WA。
3. **计数器初值为 1**：整块蛋糕初始就是 1 个横条、1 个竖条，写成 0 会让所有乘数少 1。
4. **同向顺序无关**：两条平行线不交叉，交换相邻两条同向切线不改变任何乘数——这保证了"各自降序 + 只决定交错方式"不漏最优解。
5. **相等开销任取**：$\min(h,v)$ 关于相等对称，平局时取哪边都不影响最优值（贪心比较写成 `>=` 或 `>` 均可）。
6. **溢出**：本题最坏约 $38 \times 10^3 \times 20 \approx 7.6\times 10^5$，`int` 绰绰有余；但同场 Q4（II 版 $m,n\le 10^5$）最坏约 $2\times 10^{13}$，C++ 必须 `long long`——建议一开始就按 64 位写。
7. **闭式自检**：答案应等于 $\sum_c cost(c) + \sum_{(h,v)} \min(h,v)$，可当对拍器用。

## 5. 正确性证明

约定：一次**操作**选中一块矩形并沿一条横穿它的切线切开；**完整方案**指把蛋糕切成全部 $1\times 1$ 的操作序列。每对 $(h, v)$ 有唯一**交叉点**；在交叉处两条线各自被某一刀切过，按时间先后称先切者 / 后切者。

**引理 1（次数分解）**：任一完整方案中，水平线 $h$ 的操作次数 $k_h = 1 + \big|\{v : \text{在交叉点 } (h,v) \text{ 处 } v \text{ 先切}\}\big|$；竖直线对称。

**证明**：把 $h$ 看成从左边缘到右边缘的一维线段，$h$ 上的各刀把它切成 $k_h$ 段，相邻两段拼接处称为**断点**。断点必是某竖直线 $v$ 的位置：切右侧那刀时，所在块以 $v$ 为左边界，说明 $v$ 在交叉处已先切；反之若 $v$ 在交叉处先切，则 $h$ 在该处被切时所在块已被 $v$ 分成左右两块，$h$ 的刀无法同时越过 $v$，该处必为断点。故断点集合恰为"$v$ 先切"的交叉点集合，段数 = 断点数 + 1。∎

**推论（总代价分解）**：$\text{Total} = \sum_c cost(c)\cdot k_c = \sum_c cost(c) + \sum_{(h,v)} cost(\text{交叉点处的后切者})$。

**证明**：每个交叉点在 $\sum_c (k_c - 1)$ 中被计数恰好一次，归给后切者；由引理 1 求和即得。∎

**定理 1（下界）**：$\text{Total} \;\ge\; \sum_c cost(c) + \sum_{(h,v)} \min(cost(h), cost(v))$。

**证明**：推论中每个交叉点贡献后切者开销 $\ge \min(cost(h), cost(v))$。∎

**定理 2（贪心最优）**：把所有切线按开销**从大到小**排成序列，依次把每条线在其当前穿过的所有块上切穿，总开销恰为 $\sum_c cost(c) + \sum_{(h,v)} \min(cost(h), cost(v))$，达到下界，故为最优。双指针归并（各自降序、每次取较大头）输出的正是这样一个全局非增序列，因此贪心正确。

**证明**：设 $(h,v)$ 为任意一对，不妨 $cost(h) \ge cost(v)$（相等时任取 $h$ 在前）。按全局降序，$h$ 先于 $v$ 被处理：处理 $h$ 时 $v$ 尚未切，包含交叉点的块未被 $v$ 分开，$h$ 的一刀连续越过交叉点——该交叉点的后切者是 $v$，贡献 $cost(v) = \min(cost(h), cost(v))$。每条线轮到时被切穿所有当前块，其全部操作都发生在这一轮，故每个交叉点恰被计入一次。由推论，总开销 $= \sum_c cost(c) + \sum_{(h,v)} \min(cost(h), cost(v))$，与定理 1 的下界相等。∎

> 💡 证明的弦外之音：最优值甚至有**闭式** $\sum_c cost(c) + \sum_{(h,v)} \min(cost(h), cost(v))$——贪心只是这个闭式的构造性 witnesses，两路互验是本题最扎实的对拍方式（我用暴力搜索在 $\le 4\times 4$ 的 520 组随机数据上验证过三解一致）。

## 6. 复杂度分析

- **时间复杂度**：$O(m\log m + n\log n)$。排序主导；随后的归并每步消耗一条切线，共 $m+n-2$ 步，每步 $O(1)$。
- **空间复杂度**：$O(1)$ 额外空间（C++ 原地降序排序，只多用双指针与两个计数器）；Python 若用 `sorted` 拷贝则为 $O(m+n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumCost(int m, int n, vector<int>& horizontalCut, vector<int>& verticalCut) {
        sort(horizontalCut.rbegin(), horizontalCut.rend());   // 降序：贵的先切
        sort(verticalCut.rbegin(), verticalCut.rend());
        int i = 0, j = 0, hCnt = 1, vCnt = 1, ans = 0;
        while (i < m - 1 || j < n - 1) {
            if (j == n - 1 || (i < m - 1 && horizontalCut[i] >= verticalCut[j])) {
                ans += horizontalCut[i++] * vCnt;   // 水平线横穿 vCnt 个竖条
                hCnt++;                             // 此后竖直线多穿一个横条
            } else {
                ans += verticalCut[j++] * hCnt;     // 竖直线横穿 hCnt 个横条
                vCnt++;                             // 此后水平线多穿一个竖条
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, m: int, n: int, horizontalCut: List[int],
                    verticalCut: List[int]) -> int:
        H = sorted(horizontalCut, reverse=True)     # 降序：贵的先切
        V = sorted(verticalCut, reverse=True)
        i = j = 0
        h_cnt = v_cnt = 1
        ans = 0
        while i < len(H) or j < len(V):
            if j == len(V) or (i < len(H) and H[i] >= V[j]):
                ans += H[i] * v_cnt    # 水平线横穿 v_cnt 个竖条
                h_cnt += 1
                i += 1
            else:
                ans += V[j] * h_cnt    # 竖直线横穿 h_cnt 个横条
                v_cnt += 1
                j += 1
        return ans
```

## 8. 边界情况与易错点

1. **$m=1$ 或 $n=1$**：一个方向没有切线，循环自然只剩另一方向、乘数恒为 1（每刀只穿一块），无需特判；空数组排序也无害。
2. **乘数方向写反**：切水平线乘的应是 $v\_cnt$（**竖直**方向块数）。写反后样例 1 会算出 $5\times 1 + 3\times 1 + 1\times 2 = 10 \ne 13$——前两刀两个计数器恰好都是 1，错得相当隐蔽。
3. **升序排序**：反向贪心在样例 1 上得 $1\times 1 + 3\times 1 + 5\times 3 = 19 \ne 13$——"便宜先切"正好把放大器用反。
4. **计数器初值写成 0**：所有乘数少 1，输出系统性偏小。
5. **误把开销当成"正比块长/面积"**：本题开销**按刀计、与块大小无关**，先想清楚这一点再动手；想成"正比长度"就会往区间 DP 的方向跑（能过 Q3 但 Q4 直接废）。
6. **去模拟具体块**：不需要维护任何块的集合——乘数只由"另一方向已切几条线"决定，与块的具体位置无关。
7. **溢出**：本题 `int` 安全（上界约 $7.6\times 10^5$）；同款代码交 II 版（Q4，$m,n \le 10^5$、答案可达 $2\times 10^{13}$）必须换 64 位。
8. **平局处理**：相等开销取哪边都最优（$\min$ 对称），但比较要一致（`>=` 或 `>`），别写出两头都取不到的死循环。
