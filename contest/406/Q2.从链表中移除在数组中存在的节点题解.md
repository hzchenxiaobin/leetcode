# LeetCode 从链表中移除在数组中存在的节点 题解

## 1. 题目概述

- **标题 / 题号**：从链表中移除在数组中存在的节点（#3217，medium）
- **链接**：https://leetcode.cn/problems/delete-nodes-from-linked-list-present-in-array/
- **来源**：LeetCode 第 406 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、链表

**题意**：给定整数数组 `nums` 和单链表头节点 `head`，把链表中所有**值出现在 `nums` 中**的节点删掉，返回结果链表的头节点。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^5$，且 `nums` 内元素**互不相同**
- 链表节点数在 $[1, 10^5]$ 内，$1 \le Node.val \le 10^5$
- 输入保证链表中**至少存在一个**值不在 `nums` 中出现（结果链表非空）

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3], head = [1,2,3,4,5]
输出：[4,5]
解释：值为 1、2、3 的节点全部移除——注意头节点本身就要删，且三个被删节点连成一段。
```

**示例 2**

```text
输入：nums = [1], head = [1,2,1,2,1,2]
输出：[2,2,2]
解释：值为 1 的节点散布在链表各处（含头节点），逐一绕过后只剩三个 2。
```

**示例 3**

```text
输入：nums = [5], head = [1,2,3,4]
输出：[1,2,3,4]
解释：链表中没有值为 5 的节点，一个不删、原样返回。
```

## 3. 解题思路

### 3.1 暴力思路：逐节点线性查数组

对链表每个节点 `cur`，从头到尾扫一遍 `nums` 判断 `cur->val` 是否命中，命中则摘除。链表遍历本身 $O(n)$，但每次成员判定 $O(m)$，总计 $O(n \cdot m) \le 10^{10}$，必然超时。退一步先排序再二分：$O(m\log m + n\log m) \approx 1.7 \times 10^6$ 勉强能过，但代码更长还带着一个 $\log$——这个判定理应更快。

### 3.2 核心观察：判定才是瓶颈，哈希集合一步到位

![核心观察：哈希集合把单次成员判定从 O(m) 降到 O(1)](images/del_nodes_hash_filter_concept.svg)

本题唯一的非链表零件是「值在不在 `nums` 里」这个成员判定，它要执行 $n$ 次，**单次成本直接决定总复杂度**：数组线性查 $O(m)$、有序数组二分 $O(\log m)$、**哈希集合平均 $O(1)$**。把 `nums` 一次性倒进 `unordered_set`，总代价立刻坍缩为 $O(n + m) \approx 2 \times 10^5$，判定从此不再是瓶颈。

### 3.3 算法流程：哨兵 + prev/cur 一遍扫

![算法流程：dummy 哨兵与 prev/cur 双指针，删除即绕过](images/del_nodes_dummy_relink.svg)

链表删除的经典姿势：**哨兵 `dummy` 挂在 `head` 之前**，`prev`/`cur` 双指针同向前进；`cur` 命中就「绕过」（`prev->next = cur->next`），未命中就「转正」（`prev = cur`）。

```text
1. S ← nums 全部倒入哈希集合                  ← O(m)
2. dummy.next ← head；prev ← dummy；cur ← head
3. 循环直到 cur 为空：
   a. cur.val ∈ S ？ → prev.next ← cur.next   （删除：绕过去，prev 不动）
   b. cur.val ∉ S ？ → prev ← cur             （保留：转正）
   c. cur ← cur.next
4. 返回 dummy.next
```

`dummy` 的价值在「头节点也要删」时兑现：示例 1 的前三个节点全要删，没有哨兵就得在循环前先特判剥头；有了哨兵，**头删与普通删完全同构**，返回值永远是 `dummy.next`。

### 3.4 示例演算

![示例演算：nums={1,2,3} 过滤链表 1→2→3→4→5 的完整走查](images/del_nodes_example_walkthrough.svg)

以示例 1 走一遍：`cur` 依次是 1、2、3，全部命中——`prev` 停在 `dummy` 原地不动，`dummy->next` 被连续改写为 2、3、4；`cur=4` 首次未命中，`prev` 才前进到 4；`cur=5` 转正后 `cur` 到空、循环结束，返回 `dummy->next` 即 `4→5`。示例 3 则一次都不命中，`prev` 一路随行，链表原样返回。

## 4. 算法细节

1. **建集合**：C++ 用 `unordered_set<int> S(nums.begin(), nums.end())` 迭代器区间构造一步到位；Python 直接 `set(nums)`。
2. **哨兵写在栈上**：`ListNode dummy(0, head);` 栈对象免 `new` 免释放，比堆上哨兵干净。
3. **prev 的纪律**：命中时只改 `prev->next`，**`prev` 本身不动**——这是连续删除整段节点（示例 1 连删 1、2、3）不出错的根基。
4. **值域小可上数组**：$val \le 10^5$，可用 `bool vis[100001]` 代替哈希集合，判定退化为一次下标访问，无哈希冲突、无最坏退化，空间约 100 KB。
5. **单指针压缩写法**：候选永远取 `prev->next`，可省掉 `cur`：命中就 `prev->next = prev->next->next`，否则 `prev = prev->next`；循环体恰好执行 $n$ 次。
6. **是否 `delete`**：OJ 不要求释放被删节点；若要释放，必须**先存下 `cur->next` 再 `delete`**，否则就是访问已释放内存。

## 5. 正确性证明

**引理（循环不变量）**：任意循环步开始时，从 `dummy->next` 沿 `next` 走到 `prev` 的链段，恰好是「已扫描节点中所有未命中节点」按原相对顺序构成的前缀，且 `prev->next == cur`（`cur` 为下一个待判定节点）。

**证明**：对已处理节点数归纳。初始 `prev = dummy`（空前缀）、`cur = head`，命题成立。设某步开始时命题成立，考察 `cur`：

- 若 `cur->val ∈ S`：执行 `prev->next = cur->next`。前缀不变（`cur` 不入库），新 `cur' = cur->next` 仍满足 `prev->next == cur'`；
- 若 `cur->val ∉ S`：执行 `prev = cur`。`cur` 作为未命中节点接到前缀末尾，相对顺序显然保持，且 `prev->next == cur->next == cur'`。

两种情况均把不变量完整传递给下一步。∎

**定理**：算法返回的链表等于原链表剔除所有值属于 `nums` 的节点之后的链表，且保留节点的相对顺序不变。

**证明**：循环每步消耗且仅消耗一个节点，故恰经 $n$ 步后 `cur == nullptr`。由引理，此时从 `dummy->next` 出发的整条链恰为全部未命中节点按原序的连接，命中节点从未进入该链。而命中判定 `cur->val ∈ S` 与删除条件「值在 `nums` 中」完全一致（$S$ 正是 `nums` 的集合），故返回链表即所求。∎

> 💡 输入保证至少一个节点保留，因此 `dummy->next` 非空；但证明不依赖这条保证——即便全部删光，算法也正确返回 `nullptr`。

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。建哈希集合 $O(m)$；链表单趟遍历共 $n$ 步，每步一次平均 $O(1)$ 的哈希查询与 $O(1)$ 的指针操作。
- **空间复杂度**：$O(m)$。哈希集合存放 `nums`（若改用值域数组则为 $O(C)$，$C = 10^5$）；链表原地修改，不占额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    ListNode* modifiedList(vector<int>& nums, ListNode* head) {
        unordered_set<int> S(nums.begin(), nums.end());
        ListNode dummy(0, head);                  // 哨兵：头删不再特判
        ListNode *prev = &dummy, *cur = head;
        while (cur) {
            if (S.count(cur->val)) prev->next = cur->next;  // 命中：绕过去，prev 不动
            else                   prev = cur;             // 未命中：转正
            cur = cur->next;
        }
        return dummy.next;
    }
};
```

### Python

```python
class Solution:
    def modifiedList(self, nums: List[int], head: Optional[ListNode]) -> Optional[ListNode]:
        S = set(nums)
        dummy = ListNode(0, head)
        prev, cur = dummy, head
        while cur:
            if cur.val in S:
                prev.next = cur.next   # 命中：绕过去，prev 不动
            else:
                prev = cur             # 未命中：转正
            cur = cur.next
        return dummy.next
```

## 8. 边界情况与易错点

1. **头节点本身要删**（示例 1、2 都踩）：没有哨兵时最容易 WA——必须先 `while (head && S.count(head->val)) head = head->next;` 剥头；用 `dummy` 后此特例彻底消失。
2. **连续命中一整段**（示例 1 连删 1、2、3）：`prev` 停在原地连续改写 `next`。误写成命中也 `prev = cur`，被删节点就仍挂在结果链上，WA 且常常是「输出多出开头若干节点」的典型形态。
3. **返回 `dummy.next` 而非 `head`**：`head` 指向的节点可能已被删除，返回它等于交出一条残链。
4. **`nums` 元素互不相同**：集合大小恰为 $m$；即便有重复，`set` 自动去重，正确性也不受影响。
5. **值域 $[1, 10^5]$**：担心哈希最坏退化可改用 `vis` 数组（见 §4）；本题数据下 `unordered_set` 足够稳。
6. **C++ 释放内存**：要 `delete` 就先存 `next` 再删；不 `delete` 在 OJ 上同样 AC（工程习惯上建议释放）。
7. **空链表防御**：约束保证节点数 $\ge 1$，无需特判 `head == nullptr`，代码自然兼容。
