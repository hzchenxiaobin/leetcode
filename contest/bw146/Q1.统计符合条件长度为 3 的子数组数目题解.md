# LeetCode 统计符合条件长度为 3 的子数组数目 题解

## 1. 题目概述

- **标题 / 题号**：统计符合条件长度为 3 的子数组数目（#3392，easy）
- **链接**：https://leetcode.cn/problems/count-subarrays-of-length-three-with-a-condition/
- **来源**：LeetCode 第 146 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定整数数组 `nums`，统计长度恰为 $3$ 的**连续**子数组 `[a, b, c]` 的个数，满足「第一个数与第三个数之和恰好等于第二个数的一半」，即

$$a + c = \frac{b}{2} \iff 2(a + c) = b$$

**约束**：

- $3 \le nums.length \le 100$
- $-100 \le nums[i] \le 100$

> 💡 数据规模只有 $100$，$O(n)$ 的枚举完全够用。本题唯一的陷阱是**不要用除法**做判定。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,1,4,1]
输出：1
解释：长度为 3 的子数组有三个：
      [1,2,1]：1 + 1 = 2，而 2/2 = 1，不等 → 不合法；
      [2,1,4]：2 + 4 = 6，而 1/2 = 0.5，不等 → 不合法；
      [1,4,1]：1 + 1 = 2，而 4/2 = 2，相等 → 合法。
      答案为 1。
```

**示例 2**

```text
输入：nums = [1,1,1]
输出：0
解释：唯一的子数组 [1,1,1] 中 1 + 1 = 2 ≠ 1/2 = 0.5，不合法。
```

**示例 3（自造，考察负数与奇数）**

```text
输入：nums = [-1,0,1,6]
输出：1
解释：[-1,0,1]：-1 + 1 = 0 = 0/2 ✓；
      [0,1,6]：0 + 6 = 6，而 1/2 = 0.5 ✗。
      b = 1 是奇数，无论 a + c 取何整数都不可能等于 0.5，故答案为 1。
```

## 3. 解题思路

### 3.1 暴力思路

长度为 3 的子数组只有 $n - 2$ 个，直接枚举起点 $i$（$0 \le i \le n-3$），取 `nums[i]`、`nums[i+1]`、`nums[i+2]` 判定即可，复杂度 $O(n)$。

这就是正解——本题作为签到题没有更优的渐进复杂度，但**判定的写法**有两种，差别在于是否引入浮点/除法。

### 3.2 核心观察：把除法改成整式判定

![把"中间数的一半"改写成整式，避免浮点与整除语义的坑](images/bw146_q1_window.svg)

条件 $a + c = \dfrac{b}{2}$ 里有除法。直接写 `nums[i] + nums[i+2] == nums[i+1] / 2` 在 Python 里会得到浮点数（`1/2 = 0.5`），看起来没问题；但在 C++ 里 `int / int` 是**截断整除**，`1 / 2 == 0`，会让 `a + c == 0` 的情况被误判为合法。这题在 C++ 下用整除写法是经典 WA 点。

正确做法是**两边同乘 2**：

$$a + c = \frac{b}{2} \iff 2(a + c) = b$$

- 左右都是整数，比较精确，全程不出现小数；
- 无需关心 $b$ 的奇偶（奇数时等式自然不成立）；
- 负数的情形同样成立（负数乘法仍是精确的整数运算）。

### 3.3 算法流程

![算法流程：滑窗长度 3 逐位判定](images/bw146_q1_flow.svg)

```text
1. ans = 0
2. for i = 0 .. n-3:
       if 2 * (nums[i] + nums[i+2]) == nums[i+1]:
           ans += 1
3. return ans
```

### 3.4 示例演算

对示例 1 的 `nums = [1,2,1,4,1]`：

| $i$ | 窗口 | $2(a+c)$ | $b$ | 是否相等 |
|-----|------|----------|-----|----------|
| 0 | $[1,2,1]$ | $2 \times (1+1) = 4$ | 2 | 否 |
| 1 | $[2,1,4]$ | $2 \times (2+4) = 12$ | 1 | 否 |
| 2 | $[1,4,1]$ | $2 \times (1+1) = 4$ | 4 | **是** |

答案为 1，与题面一致。示例 3 中 $i = 0$ 时 $2 \times (-1 + 1) = 0 = b$ 直接命中；$i = 1$ 时 $2 \times (0 + 6) = 12 \ne 1$。

## 4. 算法细节

1. **乘法代替除法**：判定统一写成 `2 * (nums[i] + nums[i+2]) == nums[i+1]`。
2. **循环上界**：`i + 2 < n`，即 $i \le n - 3$；写成 `i + 2 <= n - 1` 或 `i <= n - 3` 都可以，但**不要**写成 `i < n - 2` 之外的变体导致越界或多算。
3. **类型**：`nums[i] \in [-100, 100]`，两数之和 $\in [-200, 200]$，乘 2 后 $\in [-400, 400]$，`int` 绰绰有余；即使放宽到 $10^5$ 级别，也为安全用 `long long`。
4. **不需要前缀和/哈希**：窗口长度固定为 3，且条件只涉及窗口内三个位置，任何「预处理」都是多余的。
5. **子数组是连续的**：这不是「子序列」，不要写成枚举组合。

## 5. 正确性证明

**引理 1（判定等价）**：对整数 $a, b, c$，$a + c = b/2$（实数意义）当且仅当 $2(a+c) = b$。

**证明**：两边同乘 2 即可，乘法在实数上可逆且不改变等式的真假；又 $a+c$、$b$ 均为整数，$2(a+c) = b$ 是整数等式，不存在浮点误差。∎

**引理 2（窗口完备）**：长度 3 的连续子数组恰为 $\{\text{nums}[i..i+2] : 0 \le i \le n-3\}$，且两两不同。

**证明**：长度 3 的连续子数组由其起始下标唯一确定，合法起始下标正是 $0 \le i \le n-3$，故枚举 $i$ 不漏不重。∎

**定理**：算法返回值等于满足条件的长度 3 子数组个数。

**证明**：由引理 2，循环恰好遍历每个长度 3 子数组一次；由引理 1，判定条件与题面条件等价，故每次命中都对应且仅对应一个合法子数组，`ans` 累加值即所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每轮 $O(1)$ 次算术比较，共 $n - 2$ 轮。
- **空间**：$O(1)$，只用一个计数器（不复制子数组）。

## 7. 参考代码

### C++

```cpp
#include <vector>

using namespace std;

class Solution {
public:
    int countSubarrays(vector<int>& nums) {
        int ans = 0;
        int n = (int)nums.size();
        for (int i = 0; i + 2 < n; i++)
            if (2 * (nums[i] + nums[i + 2]) == nums[i + 1]) ans++;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countSubarrays(self, nums: list[int]) -> int:
        ans = 0
        for i in range(len(nums) - 2):
            if 2 * (nums[i] + nums[i + 2]) == nums[i + 1]:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **C++ 整除截断**：`nums[i+1] / 2` 在 C++ 里是整数除法，$b$ 为奇数时会截断，导致把 `a + c == 0` 误判为合法。**必须**用乘 2 的写法（本题最高频 WA 点）。
2. **Python 的除法则相反**：`/` 返回浮点，长数组下还可能有精度隐患，同样建议改成整式。
3. **循环边界**：$n = 3$ 时只有 1 个窗口，`i + 2 < n` 让循环只跑 1 次，正确。
4. **负数**：条件和乘 2 对负数完全成立（示例 3），不要额外加「非负」特判。
5. **不要统计子序列**：本题是连续子数组，$[1,2,1,4,1]$ 里的 $[1,2,4]$ 不是子数组。
6. **`ans` 上界**：最多 $n - 2 = 98$，`int` 足够。
