# LeetCode 判断网格图能否被切割成块 题解

## 1. 题目概述

- **标题 / 题号**：判断网格图能否被切割成块（#3394，medium）
- **链接**：https://leetcode.cn/problems/check-if-grid-can-be-cut-into-sections/
- **来源**：LeetCode 第 146 场双周赛 Q3
- **难度**：中等
- **标签**：数组、排序

**题意**：有一个 $n \times n$ 的网格图（坐标原点在左下角），以及若干**互不重叠**的矩形 `rectangles`，第 $i$ 个为 $[\text{start}_x, \text{start}_y, \text{end}_x, \text{end}_y]$（左下角与右上角）。判断能否找到**两条都垂直**（或**两条都水平**）的切割线，把网格切成 3 个部分，要求：

1. 三部分**都至少**含一个矩形；
2. 每个矩形**恰好**属于其中一部分（即没有任何矩形被切割线切到）。

**约束**：

- $3 \le n \le 10^9$
- $3 \le \text{rectangles.length} \le 10^5$
- $0 \le \text{rectangles}[i][0] < \text{rectangles}[i][2] \le n$，$0 \le \text{rectangles}[i][1] < \text{rectangles}[i][3] \le n$
- 矩形两两不重叠

> 💡 题眼：竖直切割线只关心矩形的 $x$ 投影区间，水平切割线只关心 $y$ 投影区间。**$n$ 有多大完全无关**，只要看「投影区间能被空隙切成几段」。

## 2. 示例

**示例 1**

```text
输入：n = 5, rectangles = [[1,0,5,2],[0,2,2,4],[3,2,5,3],[0,4,4,5]]
输出：true
解释：在 y = 2 与 y = 4 处做两条水平切割：
      下段（y < 2）含 [1,0,5,2]；中段（2 ≤ y < 4）含 [0,2,2,4] 与 [3,2,5,3]；
      上段（y ≥ 4）含 [0,4,4,5]。三段都非空，返回 true。
```

**示例 2**

```text
输入：n = 4, rectangles = [[0,0,1,1],[2,0,3,4],[0,2,2,3],[3,0,4,3]]
输出：true
解释：在 x = 2 与 x = 3 处做两条竖直切割，三段分别含 1、2、1 个矩形。
```

**示例 3**

```text
输入：n = 4, rectangles = [[0,2,2,4],[1,0,3,2],[2,2,3,4],[3,0,4,2],[3,2,4,4]]
输出：false
解释：$x$ 投影合并后只有 2 段，$y$ 投影合并后也只有 2 段，都无法切出 3 段。
```

**示例 4（自造，考察「只在端点相接」）**

```text
输入：n = 6, rectangles = [[0,0,2,1],[2,0,4,1],[4,0,6,1]]
输出：true
解释：三个矩形的 x 投影是 [0,2]、[2,4]、[4,6]，两两只在端点处接触（没有重叠）。
      取 x = 2 与 x = 4 两条竖直线，正好把三个矩形分到左、中、右三部分，
      所以「端点相接」也算可以被切开。
```

## 3. 解题思路

### 3.1 暴力思路

想法 1：枚举切割线位置。切割线虽然在整数坐标上，但 $n$ 可达 $10^9$，枚举 $O(n^2)$ 的组合不可能；即便只考虑「矩形端点」这 $O(n)$ 个候选位置，两两枚举也是 $O(n^2)$，$n = 10^5$ 时超时。

想法 2：建图/模拟切割。把网格离散化后逐条扫描，同样是 $O(n^2)$ 或 $O(n \cdot \text{值域})$。

关键是要发现：**切割是否可行只取决于投影区间的「分段结构」**，而这个结构可以排序后一次线性扫描求出。

### 3.2 核心观察：投影成区间，看能分成几段

![竖直切割只看 x 投影区间；两条切割线把区间分成 3 段](images/bw146_q3_interval.svg)

先只看竖直切割。把每个矩形投影到 $x$ 轴得到区间 $[x_1, x_2]$。

- 一条竖直线 $x = c$ 能合法放置 $\iff$ **没有矩形跨过它**，即不存在 $x_1 < c < x_2$；
- 若 $c$ 合法，则所有矩形被分成「$x_2 \le c$（左）」与「$x_1 \ge c$（右）」两类。

于是问题变成：能否用**两条**竖直线把区间集合切成 3 组，每组至少一个区间？这等价于：把所有区间按「能否被空隙/端点分开」分成若干**段（block）**，段数 $\ge 3$ 即可。

> ⚠️ 「相接」也算能分开：区间 $[0,2]$ 与 $[2,4]$ 在 $x = 2$ 处只共享端点，取 $c = 2$ 时前者全部在左（$x_2 = 2 \le 2$）、后者全部在右（$x_1 = 2 \ge 2$），合法。所以判定用 `s >= reach`（不是 `s > reach`）。

**分段怎么求**：按 $x_1$ 升序排序，维护「当前段内所有区间的最大右端点」`reach`：

- 若当前区间 $[s, e]$ 满足 $s \ge \text{reach}$，说明它和之前的段**没有任何重叠**，可以在此处切一刀 → 段数 +1，`reach` 重置为 $e$；
- 否则它与当前段有交叠，并入当前段，`reach = max(reach, e)`。

遍历完得到的段数 $\ge 3$ 就返回 `true`。对 $y$ 轴同理，两个方向做一次「或」即可。

**复杂度**：排序 $O(n \log n)$，扫描 $O(n)$；两个方向共 $O(n \log n)$。

### 3.3 算法流程

![算法流程：分别投影 x / y，排序合并数段数](images/bw146_q3_flow.svg)

```text
1. 定义 canCut(lo, hi):        // lo/hi 取 0/2 时看 x 投影，取 1/3 时看 y 投影
       segs = [(r[lo], r[hi]) for r in rectangles]
       segs 按 (左端点, 右端点) 升序排序
       blocks = 1;  reach = segs[0].right
       for (s, e) in segs[1:]:
           if s >= reach: blocks += 1
           reach = max(reach, e)
       return blocks >= 3
2. return canCut(0, 2) or canCut(1, 3)
```

### 3.4 示例演算

![示例 1 的水平切割：y 投影分成 3 段，在 y = 2 与 y = 4 处切开](images/bw146_q3_walkthrough.svg)

对示例 1，先试竖直方向（$x$ 投影 $[x_1, x_2]$）：

| 矩形 | $x$ 投影 |
|------|----------|
| $[1,0,5,2]$ | $[1,5]$ |
| $[0,2,2,4]$ | $[0,2]$ |
| $[3,2,5,3]$ | $[3,5]$ |
| $[0,4,4,5]$ | $[0,4]$ |

按左端点排序：$[0,2], [0,4], [1,5], [3,5]$。扫描：`reach = 2`；$[0,4]$ 的 $0 < 2$ 并入（`reach = 4`）；$[1,5]$ 的 $1 < 4$ 并入（`reach = 5`）；$[3,5]$ 的 $3 < 5$ 并入。段数 $= 1 < 3$，竖直方向不行。

再试水平方向（$y$ 投影 $[y_1, y_2]$）：

| 矩形 | $y$ 投影 |
|------|----------|
| $[1,0,5,2]$ | $[0,2]$ |
| $[0,2,2,4]$ | $[2,4]$ |
| $[3,2,5,3]$ | $[2,3]$ |
| $[0,4,4,5]$ | $[4,5]$ |

按左端点排序：$[0,2], [2,3], [2,4], [4,5]$。扫描：`reach = 2`；$[2,3]$ 的 $2 \ge 2$ → 新段，`blocks = 2`，`reach = 3`；$[2,4]$ 的 $2 < 3$ 并入（`reach = 4`）；$[4,5]$ 的 $4 \ge 4$ → 新段，`blocks = 3`，`reach = 5`。段数 $= 3 \ge 3$ → 返回 `true`，与输出一致。切点正是 $y = 2$ 与 $y = 4$。

## 4. 算法细节

1. **两个方向独立**：题目要求两条切割线**同向**，所以「竖直可行」与「水平可行」是并列的两个判定，取或即可，不能混用。
2. **排序键**：按左端点升序；左端点相同时按右端点升序，可让合并更自然（其实只要按左端点排序，`reach` 取最大值就能保证正确性）。
3. **`>=` 而不是 `>`**：相接的区间可以被端点处的切割线分开（见示例 4 的说明），这是本题最容易写成 `>` 而 WA 的一处。
4. **`reach` 的更新无条件执行**：即使 `s >= reach` 开了新段，也要把 `reach` 设为 $e$；若 `s < reach`，则 `reach = max(reach, e)`。两种情形合并写成 `blocks += (s >= reach); reach = max(reach, e)` 是常见写法，但要注意「开新段时 `max` 等价于直接赋 $e$」。
5. **段数上界**：段数最多为 $n$（全部不相交），一旦达到 3 即可提前返回，无需扫完。
6. **$n$ 只是坐标上界**：算法完全没有用到 $n$，这也解释了为什么 $n \le 10^9$ 不影响复杂度。
7. **矩形不重叠并非必需**：$x$ 投影的合并逻辑对任意区间集合都成立；题目给的「不重叠」只是让几何意义更自然（不会出现「矩形之间互相穿插」的歧义）。

## 5. 正确性证明

固定一个方向。设区间集合为 $\{I_k = [s_k, e_k]\}$，排序后为 $I_1, \dots, I_m$（按 $s$ 升序）。定义贪心扫描：`blocks` 与 `reach` 如算法所述，记最终段数为 $B$。称 $c$ 是**合法切点**，若不存在 $k$ 使 $s_k < c < e_k$。

**引理 1（切点的分离性）**：若 $c$ 合法，则每个区间要么满足 $e_k \le c$（完全在左），要么满足 $s_k \ge c$（完全在右）。

**证明**：若 $e_k > c$ 且 $s_k < c$，则 $s_k < c < e_k$，$c$ 不合法，矛盾。而 $e_k > c$ 且 $s_k \ge c$ 即「完全在右」，$e_k \le c$ 即「完全在左」；$s_k = c$ 时 $e_k > s_k = c$，属右侧。两情形互斥且穷尽。∎

**引理 2（每个新段都给出合法切点）**：设扫描到 $I_i$ 时因 $s_i \ge \text{reach}_{i-1}$ 开启新段，其中 $\text{reach}_{i-1} = \max\{e_1, \dots, e_{i-1}\}$，则 $c = \text{reach}_{i-1}$ 是合法切点，且把前 $i-1$ 个区间与其余区间分开。

**证明**：对 $j < i$：$e_j \le \text{reach}_{i-1} = c$，完全在左。对 $j \ge i$：$s_j \ge s_i \ge c$（排序后 $s$ 不降），完全在右。故不存在跨越 $c$ 的区间，$c$ 合法且两侧都非空（$i \ge 2$ 时左侧非空，右侧含 $I_i$）。∎

**引理 3（$B \ge 3 \Rightarrow$ 存在两条合法切点切成 3 段）**：若 $B \ge 3$，则存在合法切点 $c_1 < c_2$，使三个部分

$$\{\,e_k \le c_1\,\},\quad \{\,s_k \ge c_1,\ e_k \le c_2\,\},\quad \{\,s_k \ge c_2\,\}$$

都非空。

**证明**：$B \ge 3$ 说明扫描中至少发生 2 次「开新段」，设对应切点候选为 $c_1 = \text{reach}_{i_1 - 1}$、$c_2 = \text{reach}_{i_2 - 1}$（$i_1 < i_2$）。由引理 2，两者都合法；且 $c_1 < s_{i_1} \le s_{i_2 - 1} < e_{i_2 - 1} \le c_2$，故 $c_1 < c_2$。三部分分别包含第 1 段、第 2 段、第 3 段及以后的区间，均非空。∎

**引理 4（两条合法切点 $\Rightarrow B \ge 3$）**：若存在合法切点 $c_1 < c_2$ 把区间分成三个非空部分，则贪心扫描至少开 2 次新段。

**证明**：设三部分为 $A$（$e \le c_1$）、$B'$（$s \ge c_1, e \le c_2$）、$C$（$s \ge c_2$），均非空。对任意 $a \in A$、$b \in B'$ 有 $s_a \le e_a \le c_1 \le s_b$，故排序后 $A$ 中所有区间都排在 $B'$ 之前（左端点不更大）；同理 $B'$ 排在 $C$ 之前。设 $A$ 的区间占据排序后的前若干位置，处理完它们后 $\text{reach} \le \max_{a \in A} e_a \le c_1 \le s_{b_0}$（$b_0$ 为 $B'$ 中排序最前者），故扫描到 $b_0$ 时必开新段。同理处理完 $A \cup B'$ 后 $\text{reach} \le c_2 \le s_{c_0}$，处理 $C$ 的首个区间时再开一段。共至少 2 次新段，即 $B \ge 3$。∎

**定理**：算法返回 `true` 当且仅当存在两条同向切割线满足题面要求。

**证明**：由引理 3、引理 4，对任意一个方向，「$B \ge 3$」与「该方向存在两条合法切割线并切成 3 个非空部分」等价；而算法对竖直、水平两个方向各判一次并取或，故返回 `true` 恰对应题面条件成立。∎

## 6. 复杂度分析

- **投影**：$O(n)$ 生成两组区间。
- **排序**：每个方向 $O(n \log n)$，共 2 次。
- **扫描**：每个方向 $O(n)$（可提前退出）。
- **总时间**：$O(n \log n)$，$n = 10^5$ 时约 $3.4 \times 10^6$ 次比较，非常宽裕。
- **空间**：$O(n)$ 存区间数组；不依赖 $n$ 的坐标值域，因此 $n \le 10^9$ 不产生任何额外开销。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>

using namespace std;

class Solution {
public:
    bool checkValidCuts(int n, vector<vector<int>>& rectangles) {
        return canCut(rectangles, 0, 2) || canCut(rectangles, 1, 3);
    }
private:
    bool canCut(vector<vector<int>>& rectangles, int lo, int hi) {
        vector<pair<int, int>> segs;
        segs.reserve(rectangles.size());
        for (auto& r : rectangles) segs.push_back({r[lo], r[hi]});
        sort(segs.begin(), segs.end());
        int blocks = 1;
        int reach = segs[0].second;
        for (size_t i = 1; i < segs.size(); i++) {
            if (segs[i].first >= reach) blocks++;
            reach = max(reach, segs[i].second);
        }
        return blocks >= 3;
    }
};
```

### Python

```python
class Solution:
    def checkValidCuts(self, n: int, rectangles: list[list[int]]) -> bool:
        def can_cut(lo: int, hi: int) -> bool:
            segs = sorted((r[lo], r[hi]) for r in rectangles)
            blocks = 1
            reach = segs[0][1]
            for s, e in segs[1:]:
                if s >= reach:
                    blocks += 1
                reach = max(reach, e)
            return blocks >= 3

        return can_cut(0, 2) or can_cut(1, 3)
```

## 8. 边界情况与易错点

1. **`>=` 与 `>` 的区别**：相接的区间可以被分离（示例 2 中 $[0,1]$ 与 $[2,3]$ 之间有真实空隙，但像 $[0,2]$ 与 $[2,4]$ 只在端点接触的情形，题面同样允许切割）。用 `>` 会漏掉这类合法切法。
2. **两个方向都要试**：示例 1 竖直方向只有 1 段、水平方向 3 段，只判一个方向必然错。
3. **切割线数量恰好为 2**：段数 $\ge 3$ 时总能选出 2 条线（切第 1 段之后与倒数第 2 段之后），不必要求恰好 3 段。
4. **`reach` 忘记更新**：只写 `if (s >= reach) blocks++;` 而漏掉 `reach = max(reach, e)`，会导致段数被高估（把本应合并的区间当成新段）。
5. **排序稳定性不影响正确性**：左端点相同的区间顺序任意，因为 `reach` 取的是最大值，合并结果与顺序无关。
6. **三部分都必须非空**：这正是要求段数 $\ge 3$ 的原因；若只要求「不切到矩形」，$n$ 个互不相交的矩形中取两条线即可，但段数 $< 3$ 时无法保证三部分都非空。
7. **矩形坐标范围**：$x_1 < x_2$ 且 $y_1 < y_2$，不会出现零面积矩形，因此「相接」只发生在不同矩形之间。
