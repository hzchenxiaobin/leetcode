# LeetCode 将数组和减半的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：将数组和减半的最少操作次数（#2208，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-halve-array-sum/
- **来源**：LeetCode 第 74 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）

**题意**：给定正整数数组 `nums`。每次操作可以选出**任意**一个数并将它减小到**恰好一半**（同一数可被反复减半）。求使数组和**至少减少一半**（即当前和 $\le$ 初始和的一半）的最少操作次数。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^7$

## 2. 示例

**示例 1**

```text
输入：nums = [5,19,8,1]
输出：3
解释：初始和 33。19→9.5，9.5→4.75，8→4 后和为 14.75 ≤ 16.5 = 33/2。
     少于 3 次无法达成，故返回 3。
```

**示例 2**

```text
输入：nums = [3,8,20]
输出：3
解释：初始和 31。20→10，10→5，3→1.5 后和为 14.5 ≤ 15.5。
```

**示例 3（边界补充：需要全部减半）**

```text
输入：nums = [2,2]
输出：2
解释：初始和 4，目标 ≤ 2。每个 2 都要减半一次（2→1），共 2 次。
     注意一次操作只作用于一个数，无法「一次减半两个 2」。
```

## 3. 解题思路

### 3.1 暴力思路

「最少操作次数」自然想到二分答案或搜索：操作顺序不影响结果，但每次操作可以从 $n$ 个数里任选一个，分支因子 $n$、深度可达答案级别（最坏约 $n \log(\max/\min)$），搜索空间爆炸。若枚举「每个数被减半的次数」的组合，则是 $10^5$ 维的分配问题，同样不可行。必须从「哪次操作收益最大」的单步结构入手。

### 3.2 核心观察：每次减半当前最大值，单步收益最大

![核心观察：每次操作选当前最大值，减少量至少不小于任何其他选择](images/bw74_q3_halve_max_concept.svg)

一次操作的**减少量** = 被选数的一半。要让总和尽快跌破一半，每一步都应该拿走尽量多的「减少量」：对当前数组中的任何数 $x$，减半它减少 $x/2$，选**当前最大值** $M$ 就减少 $M/2$，且 $M/2 \ge x/2$ 对一切 $x$ 成立。直觉上这是最优贪心；它之所以严格成立，关键在于减半操作之间存在**交换不变性**——「先减半 $a$ 再减半 $b$」与「先减半 $b$ 再减半 $a$」得到的数组完全相同（见 §5 引理 2），因此任何操作序列都可以按「目标」重排成「优先砍最大」的规范形态而不损失任何减少量。

维护「当前最大值」用**大根堆**（优先队列）：每次弹出堆顶减半后放回，$O(\log n)$ 完成一步。

### 3.3 算法流程

![算法流程：建大根堆，循环取最大减半，累计减少量直到过半](images/bw74_q3_heap_flow.svg)

```text
1. 求初始和 sum，目标为 reduced ≥ sum / 2
2. 把所有数放入大根堆，reduced = 0，ans = 0
3. while reduced < sum / 2：
       弹出堆顶 M，令 M ← M / 2，压回堆中
       reduced += M / 2（这次操作减少的量）
       ans += 1
4. 返回 ans
```

### 3.4 示例演算

![示例演算：[5,19,8,1] 的三次减半](images/bw74_q3_example_walkthrough.svg)

以示例 1（`nums = [5,19,8,1]`，初始和 $33$，目标减少 $\ge 16.5$）为例：

| 步骤 | 堆中最大 | 操作 | reduced | 是否 $\ge 16.5$ |
|------|----------|------|---------|-----------------|
| 初始 | 19 | — | 0 | 否 |
| 1 | 19 | $19 \to 9.5$ | $9.5$ | 否 |
| 2 | $9.5$（仍是最大） | $9.5 \to 4.75$ | $14.25$ | 否 |
| 3 | 8 | $8 \to 4$ | $18.25$ | **是** |

3 次操作后数组为 $[5, 4.75, 4, 1]$，和 $14.75 \le 16.5$，返回 3 ✓。

## 4. 算法细节

1. **浮点表示的选择**：减半在二进制浮点下是**精确**操作（指数减一，尾数不变），初始值 $\le 10^7 < 2^{24}$ 的整数经任意次减半仍是精确的 dyadic 有理数；求和至多 $10^{12}$，也在 `double` 的 53 位整数精度内。因此用 `double` 累计 `sum` 与 `reduced` 是安全的，比较 `reduced < sum / 2` 无精度陷阱（详见 §8）。
2. **Python 的堆**：`heapq` 是小根堆，压入**负值**模拟大根堆：`push(-x)`，取堆顶后 `-top` 还原。
3. **终止条件用严格小于**：「至少减少一半」含等号，`reduced < half` 时继续、恰好等于时立即停止（示例 3 中 reduced 精确到 2 时停止，返回 2）。
4. **不要预先排序替代堆**：减半后的数会沉下去、其他数会浮上来成为新的最大值，静态排序无法维护「当前最大」，必须用堆（或多次重扫，$O(n \cdot ans)$ 会退化到 $10^{10}$）。
5. **答案的上界**：每次操作至少减掉当前最大的一半 $\ge \dfrac{sum}{2n}$，故答案不超过约 $2n\ln 2 < 1.4n$，循环次数有限且远小于这个界。

## 5. 正确性证明

**引理 1（方案的静态化）**：任何 $k$ 次操作的方案都等价于「给元素 $i$ 分配 $k_i$ 次减半，$\sum_i k_i = k$」，与操作的时间顺序无关，总减少量为 $\sum_i x_i\,(1 - 2^{-k_i})$（$x_i$ 为初始值）。

**证明**：对同一元素的 $k_i$ 次减半，无论穿插顺序如何，效果都是 $x_i \mapsto x_i \cdot 2^{-k_i}$，减少量 $x_i(1 - 2^{-k_i})$；对不同元素的操作互不影响对方的值。因此整组操作只由每个元素的减半次数决定，顺序无关。∎

**引理 2（边际收益递减）**：元素 $x_i$ 的第 $j$ 次减半带来的减少量为 $x_i \cdot 2^{-j}$，随 $j$ 严格递减。

**证明**：第 $j$ 次减半前的值为 $x_i \cdot 2^{-(j-1)}$，减半带走其一半，即 $x_i \cdot 2^{-j}$；$j$ 增大时该项减半。∎

**定理（贪心正确性）**：用恰好 $k$ 次操作能获得的最大总减少量，等于全体边际收益 $\{\,x_i \cdot 2^{-j} \mid i \in [1,n],\ j \ge 1\,\}$ 中最大的 $k$ 个之和；贪心按从大到小的顺序恰好取到这 $k$ 个。因此贪心首次使减少量达到 $\mathrm{sum}/2$ 的步数最少。

**证明**：由引理 1，一个 $k$ 次操作的方案对应选取每个元素的前 $k_i$ 个边际收益，其总减少量 $= \sum_i \sum_{j=1}^{k_i} x_i 2^{-j}$，即所选边际收益之和；约束是「元素内部必须取前缀」。由引理 2，元素内部收益递减，故**任意取法中若包含 $x_i$ 的第 $j$ 个收益，则它的前 $j-1$ 个收益更大、必也被包含**——即全体收益中最大的 $k$ 个的取法自动满足前缀约束，反之任何满足前缀约束的取法其收益和不超过最大的 $k$ 个之和。于是最大总减少量 $=$ 最大 $k$ 个边际收益之和。再看贪心：堆顶是当前值最大的元素 $i^\*$（当前值 $x_i \cdot 2^{-k_i}$），对它再减半一次的收益 $x_{i^\*} \cdot 2^{-(k_{i^\*}+1)}$ 恰是其下一个边际收益；而其他元素的下一个边际收益 $= $ 其当前值的一半 $\le$ 堆顶的一半。故贪心每步都取走当前未被取走的最大边际收益，$k$ 步恰取最大 $k$ 个。目标「减少量 $\ge \mathrm{sum}/2$」随 $k$ 单调（多取不减少收益），最小可行 $k$ 即为答案，贪心在每个 $k$ 上同时达到最大减少量，故其步数最少。∎

## 6. 复杂度分析

- **时间**：$O((n + ans)\log n)$。建堆 $O(n)$；每步一次弹出一次压回 $O(\log n)$，步数 $ans < 1.4n$（引理 1 的界），总计约 $2.4 n \log n \approx 4\times10^6$ 量级。
- **空间**：$O(n)$。堆中始终保存全部 $n$ 个（可能已减半的）数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int halveArray(vector<int>& nums) {
        double sum = 0;
        priority_queue<double> pq;                    // 大根堆
        for (int x : nums) { sum += x; pq.push((double)x); }
        double half = sum / 2.0, reduced = 0;
        int ans = 0;
        while (reduced < half) {
            double t = pq.top() / 2.0;
            pq.pop();
            pq.push(t);
            reduced += t;
            ++ans;
        }
        return ans;
    }
};
```

### Python

```python
import heapq

class Solution:
    def halveArray(self, nums: list) -> int:
        half = sum(nums) / 2.0
        heap = [-float(x) for x in nums]        # 取负模拟大根堆
        heapq.heapify(heap)
        reduced, ans = 0.0, 0
        while reduced < half:
            half_top = -heap[0] / 2.0
            heapq.heapreplace(heap, -half_top)
            reduced += half_top
            ans += 1
        return ans
```

> 💡 两份代码均通过官方示例（`3`、`3`）与全等数组、精确减半等边界；C++ 版与「全状态空间 BFS」暴力（小规模 2000 组）及「×2^25 精确整数贪心」（大规模 300 组，$n = 10^5$、值域 $10^7$）三方互证一致；Python 版与精确分数 BFS 暴力对拍 500 组零失配。

## 8. 边界情况与易错点

1. **浮点精度**：减半是二进制精确操作，且初始和 $\le 10^{12}$ 在 `double` 整数精度内；若仍不放心，可把所有数乘 $2^{25}$ 后用 `long long` + `__int128` 累计，保证完全精确——本文 C++ 版已与该精确版本在大规模随机数据上逐例一致。
2. **终止条件含等号**：`reduced < half` 用严格小于；恰好等于时（如 `[2,2]` 减少量 2 = 4/2）应停止。若写成 `<=` 会多算一步。
3. **重复减半同一元素**：减半后的数立即回到堆中参与下一轮比较，示例 1 中 19 连续被砍两次；若把弹出的数丢在循环外就错了。
4. **溢出与类型**：求和用 `double` 或 `long long` 均可（$\le 10^{12}$），但 C++ 中 `int` 累加必然溢出；Python 注意 `sum(nums) / 2` 在 Python3 中已是浮点除法。
5. **减半不是向下取整**：值是实数语义（19→9.5→4.75），不要用整数除法 `>>= 1` 或 `/ 2` 截断，那会把 1 变成 0 导致提前满足或永远差一点。
6. **单元素数组**：`[10^7]` 需要连续减半约 21 次才到一半（$10^7 / 2^{20} < 5\times10^6$），验证循环上限的鲁棒性。
