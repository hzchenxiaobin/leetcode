# LeetCode 用地毯覆盖后的最少白色砖块 题解

## 1. 题目概述

- **标题 / 题号**：用地毯覆盖后的最少白色砖块（#2209，hard）
- **链接**：https://leetcode.cn/problems/minimum-white-tiles-after-covering-with-carpets/
- **来源**：LeetCode 第 74 场双周赛 Q4
- **难度**：困难
- **标签**：字符串、动态规划、前缀和

**题意**：给定二进制字符串 `floor`（`'1'` 表示白砖、`'0'` 表示黑砖）与 `numCarpets` 条**黑色**地毯，每条恰好覆盖连续 `carpetLen` 块砖。地毯之间**允许互相重叠**，也可以盖住黑砖（不产生收益）。要求安排地毯的位置，使**未被任何地毯覆盖的白砖**数量最少，返回该最小值。

**约束**：

- $1 \le carpetLen \le floor.length \le 1000$
- `floor[i]` 为 `'0'` 或 `'1'`
- $1 \le numCarpets \le 1000$

## 2. 示例

**示例 1**

```text
输入：floor = "10110101", numCarpets = 2, carpetLen = 2
输出：2
解释：两条地毯分别盖住砖 2~3 与 5~6，未被覆盖的白砖只剩位置 0 与 7，共 2 块。
```

**示例 2**

```text
输入：floor = "11111", numCarpets = 2, carpetLen = 3
输出：0
解释：第一条盖 0~2、第二条盖 2~4（中间重叠一块），5 块白砖全部被盖住。
```

**示例 3（边界补充：地毯比地面长）**

```text
输入：floor = "111", numCarpets = 1, carpetLen = 3
输出：0
解释：一条地毯盖满整条地面；注意 carpetLen 不超过 floor.length，但可以贴齐右端。
```

## 3. 解题思路

### 3.1 暴力思路

每条地毯的起点可以是 $0 \sim n-1$ 中的任意位置，暴力枚举全部起点组合是 $O(n^{numCarpets})$——$numCarpets = 1000$ 时是天文数字；即使带「覆盖集合」记忆化，状态也是指数级。另一种思路是「从白砖集合里挑不超过 $k \cdot carpetLen$ 个覆盖」的匹配问题，同样无法直接枚举。规模（$n, k \le 1000$）提示一个 $O(nk)$ 的二维 DP。

### 3.2 核心观察：WLOG 地毯不重叠、不悬空，问题化为前缀 DP

![核心观察：重叠与悬出永远可以消去](images/bw74_q4_dp_state_model.svg)

先做一个简化命题（引理 1，§5 给证明）：**存在一种最优铺法，其中所有地毯互不重叠、且都完整落在地砖范围内**——重叠的部分是浪费，把右边的地毯顺次右移总能不损失覆盖。于是可以按「从左到右处理前 $i$ 块砖」做阶段化决策，每条地毯贴着已处理区域的右端铺，天然保证不重叠。

定义状态：

$$dp[i][j] = \text{前 } i \text{ 块砖、恰好用 } j \text{ 条地毯（互不重叠、都落在前 } i \text{ 块内）时，最少仍露出的白砖数}$$

每一步只需对「第 $i$ 块砖」做二选一转移（铺 / 不铺），配合**前缀白砖和** $\mathrm{pre}[i]$（前 $i$ 块砖中白砖总数）即可刻画「整段被盖住」的收益。

### 3.3 状态转移：铺与不铺

![状态转移：不铺第 i 块（露出白砖 +1）或铺一条盖住末尾 L 块](images/bw74_q4_cover_transition.svg)

对第 $i$ 块砖（下标 $i-1$）有两种选择：

- **不铺**：第 $i$ 块砖裸露，若它是白砖则代价 +1：
$$dp[i][j] = dp[i-1][j] + \mathbb{1}[floor[i-1] = 1]$$
- **铺**：用一条地毯盖住**末尾的 $carpetLen$ 块**（下标区间 $[i - carpetLen,\ i-1]$），这些砖全部不再露出，地毯之前的部分交给 $j-1$ 条地毯：
$$dp[i][j] = dp[\max(i - carpetLen,\ 0)][j - 1]$$

被盖住区间内的白砖数恰为 $\mathrm{pre}[i] - \mathrm{pre}[i - carpetLen]$——转移把它整体清零，这正是前缀和的作用。两者取最小：

$$dp[i][j] = \min\Big(dp[i-1][j] + \mathbb{1}[floor[i-1]=1],\ \ dp[\max(i-carpetLen,\ 0)][j-1]\Big)$$

答案为 $dp[n][numCarpets]$。

### 3.4 示例演算

![示例演算：10110101 用两条长度为 2 的地毯的最优铺法](images/bw74_q4_example_walkthrough.svg)

以示例 1（`floor = "10110101"`，$k=2$，$L=2$）为例。白砖位于下标 $0,2,3,5,7$。最优铺法：第一条盖 $[2,3]$（压住 2 块白砖），第二条盖 $[5,6]$（压住 1 块白砖），露出的白砖为下标 $0$ 与 $7$，共 2 块。DP 表的关键格（$L = 2$）：

| $dp[i][j]$ | $j=0$ | $j=1$ | $j=2$ |
|-----------|-------|-------|-------|
| $i=6$（前 6 块） | 4 | 2 | 1 |
| $i=7$ | 4 | 2 | **1** |
| $i=8$ | 5 | 3 | **2** |

例如 $dp[8][2] = \min(dp[7][2] + 1,\ dp[6][1]) = \min(1 + 1,\ 2) = 2$，两种转移殊途同归：「不铺」最后一块砖（白砖裸露 +1）对应前 7 块用 2 条毯的 $dp[7][2] = 1$（盖住 $[2,3]$ 与 $[5,6]$，只露出下标 0），加上裸露的下标 7；「铺」一条盖 $[6,7]$ 的毯子则对应前 6 块用 1 条毯的 $dp[6][1] = 2$（盖住 $[2,3]$，露出下标 0 与 5）。两条路径的最终代价都是 2。

## 4. 算法细节

1. **前缀白砖和**：$\mathrm{pre}[i] = \mathrm{pre}[i-1] + (floor[i-1] == 1)$。转移本身是 $O(1)$ 的（不铺 +1、铺直接跳到 $i-L$），前缀和主要用于快速核对「一段盖住多少白砖」以及推导；DP 数组即答案的载体。
2. **边界 $\max(i - carpetLen, 0)$**：当 $i \le carpetLen$ 时一条毯子盖满整个前缀，代价 0（$dp[0][j-1] = 0$）；不加大括号会访问负下标。
3. **初始化**：$dp[0][j] = 0$（没有砖就没有露出的白砖）；$j = 0$ 列单独沿 $i$ 累加白砖（一条毯都不铺时的裸露数）。
4. **C++ 用二维、Python 用滚动行**：C++ 开 $(n+1)\times(k+1)$ 的 `int` 二维数组（约 4 MB），转移清晰；Python 为提速按「毯子数 $j$ 为外层、砖数 $i$ 为内层」滚动两行（$prev$ 行是 $j-1$ 条毯的完整结果，满足 $i - L$ 的任意回看）。
5. **「恰好 $j$ 条」与「至多 $j$ 条」**：$dp$ 定义为恰好 $j$ 条，但由于多铺一条毯子不会更差（$dp[i][j+1] \le dp[i][j]$ 可由转移归纳），$dp[n][numCarpets]$ 同时就是「至多」语义的答案，无需再取 $\min$。
6. **地毯数量用不完**：$numCarpets \cdot carpetLen \ge n$ 时答案必为 0，DP 自然得出（铺满路径代价 0），不必特判。

## 5. 正确性证明

**引理 1（不重叠不失一般性）**：任何铺法都存在一个覆盖白砖集合不减少的「不重叠、不悬空」铺法。

**证明**：把地毯按起点从左到右排序。若第 $t+1$ 条与第 $t$ 条重叠，把第 $t+1$ 条整体右移，使其起点等于第 $t$ 条的终点；移动腾出的区间 $[\text{原起点},\ \text{第 } t \text{ 条终点})$ 本就被第 $t$ 条覆盖，故覆盖集合不减，而新盖住的右侧区间只会增加覆盖。逐条向右平移（必要时截断到地面右端）后所有地毯互不重叠；起点排序保持不变，归纳完成。同理，任何向右悬出地面末端的地毯左移至贴齐右端后，覆盖只增不减。∎

**引理 2（转移的完备性）**：任何互不重叠且完整落在地面内的铺法，其覆盖区间的并可以唯一分解为若干条「贴着某前缀末尾」的毯子；反之 DP 的每条转移路径对应一个合法铺法。

**证明**：设某合法铺法用了 $j$ 条毯子，考虑其最靠右的一条，它覆盖 $[s, s+L)$，且其后无毯子。设 $i^\* = s + L$（若毯子右端贴地面末端则 $i^\* = n$）。前 $i^\*$ 块砖的露出白砖 = 前 $s$ 块砖用其余 $j-1$ 条毯子的最优露出值（区间 $[s, i^\*)$ 全被盖住，贡献 0），即 $dp[i^\*][j] \le dp[s][j-1]$；而 $s = i^\* - L$，正是「铺」转移。对毯子数归纳，逐条剥离最右毯子即把任意铺法的代价表示成 DP 转移链上的一个值，故 $dp[n][numCarpets]$ 不大于任何铺法的代价。反向：DP 值沿转移回溯展开，每一步「铺」对应一条起点 $i - L$、长 $L$ 的毯子，转移链各毯子右端递减、互不重叠且在地面内，「不铺」链累计裸露白砖——展开结果是一个真实铺法的代价，故 $dp[n][numCarpets]$ 不小于最优值。两个方向合一。∎

**定理**：算法返回未覆盖白砖数的最小值。

**证明**：由引理 1，最优值可在「不重叠、不悬空」的铺法中取到；由引理 2，$dp[n][numCarpets]$ 恰是这类铺法代价的最小值（DP 是对这类铺法的精确枚举：每个铺法对应一条转移链，每条转移链对应一个铺法）。故返回值即答案。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot numCarpets)$。共 $(n+1)(k+1)$ 个状态，每个状态两个 $O(1)$ 转移；$n = k = 1000$ 时约 $2\times10^6$ 次。
- **空间**：C++ 二维数组 $O(nk) \approx 4\,\mathrm{MB}$；Python 滚动两行 $O(n)$。输出不需要前缀和数组以外的额外结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumWhiteTiles(string floor, int numCarpets, int carpetLen) {
        int n = floor.size();
        // dp[i][j]：前 i 块砖恰好用 j 条地毯覆盖后，最少仍露出的白砖数
        vector<vector<int>> dp(n + 1, vector<int>(numCarpets + 1, 0));
        for (int i = 1; i <= n; ++i) {
            dp[i][0] = dp[i - 1][0] + (floor[i - 1] == '1');
            for (int j = 1; j <= numCarpets; ++j)
                dp[i][j] = min(dp[max(i - carpetLen, 0)][j - 1],           // 铺：末尾 L 块全覆盖
                               dp[i - 1][j] + (floor[i - 1] == '1'));      // 不铺第 i 块
        }
        return dp[n][numCarpets];
    }
};
```

### Python

```python
class Solution:
    def minimumWhiteTiles(self, floor: str, numCarpets: int, carpetLen: int) -> int:
        n = len(floor)
        # j=0 行：一条毯都不铺，前 i 块的白砖全露
        prev = [0] * (n + 1)
        for i in range(1, n + 1):
            prev[i] = prev[i - 1] + (floor[i - 1] == '1')
        for j in range(1, numCarpets + 1):
            cur = [0] * (n + 1)                    # cur[i] = 用 j 条毯处理前 i 块
            for i in range(1, n + 1):
                cur[i] = min(prev[max(i - carpetLen, 0)],                 # 铺
                             cur[i - 1] + (floor[i - 1] == '1'))          # 不铺
            prev = cur
        return prev[n]
```

> 💡 两份代码均通过官方示例（`2`、`0`）与毯长等于地面长、毯子远多于需要等边界；另与「枚举每条毯子的全部起点（允许重叠、允许悬出）」的位掩码暴力对拍，随机 6 万组（C++）+ 4000 组（Python）零失配——这同时验证了引理 1「不重叠不失一般性」的结论。

## 8. 边界情况与易错点

1. **允许重叠但不必重叠**：题面明确允许重叠，但引理 1 说明最优解总可取到不重叠版本；若 DP 转移写成「毯子可以从任意位置盖过来」，状态会失去无后效性。别把「允许」误当「必须」。
2. **$\max(i - carpetLen,\ 0)$ 不能省**：$i \le carpetLen$ 时毯子盖满前缀，应取 $dp[0][j-1] = 0$；负下标轻则越界崩溃，重则（用 `Python` 负索引）悄悄取错值。
3. **$j = 0$ 列要先填**：不加毯子的裸露数是所有「铺」转移的回看基础；漏填会把 0 当成起点导致答案偏小。
4. **黑砖也要能被盖**：毯子盖黑砖不产生收益但合法，DP 里「铺」转移对区间内黑白一视同仁——不要试图「只盖白砖」剪枝，会破坏状态定义。
5. **毯子数量多于需要**：$numCarpets \cdot carpetLen \ge$ 白砖数时答案 0；DP 的「恰好 $j$ 条」语义下多出来的毯子可以铺在纯黑区域或右端，不会被迫「制造代价」。
6. **下标换算**：`floor[i-1]` 是第 $i$ 块砖；「铺」盖的是下标 $[i-L, i-1]$ 共 $L$ 块，不是 $[i-L+1, i]$。
7. **性能**：$O(nk) = 10^6$ 的 DP 在 Python 下要控制常数：把毯子数放外层滚动数组、避免在循环里重复下标 `floor[i-1] == '1'` 的判断开销（可预转 0/1 列表）。
