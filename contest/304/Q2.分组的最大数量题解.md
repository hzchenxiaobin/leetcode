# LeetCode 分组的最大数量 题解

## 1. 题目概述

- **标题 / 题号**：分组的最大数量（#2358，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-groups-entering-a-competition/
- **来源**：LeetCode 第 304 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、数学、二分查找

**题意**：给定正整数数组 `grades` 表示学生成绩。要把**所有**学生分成若干个**有序**的非空分组，满足：

1. 第 `i` 组的**学生总数**严格小于第 `i+1` 组的学生总数；
2. 第 `i` 组的**成绩总和**严格小于第 `i+1` 组的成绩总和。

返回能形成的**最大**组数。

**约束**：

- `1 <= grades.length <= 10^5`
- `1 <= grades[i] <= 10^5`

## 2. 示例

**示例 1**

```text
输入：grades = [10,6,12,7,3,5]
输出：3
解释：
  第 1 组 [12]：总成绩 12，1 人
  第 2 组 [6,7]：总成绩 13，2 人
  第 3 组 [10,3,5]：总成绩 18，3 人
  人数 1 < 2 < 3，总和 12 < 13 < 18，无法形成超过 3 个分组。
```

**示例 2**

```text
输入：grades = [8,8]
输出：1
解释：若分成 2 组，两组人数只能都是 1，违反「人数严格递增」。
```

**补充示例 3**（覆盖「剩余学生并入末组」与「成绩全部相同」）

```text
输入：grades = [1,1,1,1,1,1,1]（n = 7）
输出：3
解释：
  排序后切成 [1]、[1,1]、[1,1,1,1]：人数 1 < 2 < 4，总和 1 < 2 < 4。
  因为 1+2+3 = 6 ≤ 7 < 10 = 1+2+3+4，最多 3 组。
```

## 3. 解题思路

### 3.1 暴力思路：排序切块 + 逐组验证

最朴素的设想是枚举所有划分方式再逐个检查两个条件，组合数是指数级，`n = 10^5` 下完全不可行——它既没利用「人数递增」给出的强结构，也没利用「成绩可排序」。

比赛里更常见的实况是折中写法：把数组**升序排序**，猜想按 `1, 2, 3, …` 人切连续块，然后**老老实实逐组验证**「人数递增、总和递增」，甚至对每个候选 `k` 都重新验证一遍，`O(n log n)` 也能过。但只要把「验证」写进代码，就说明还没看清它**永远不需要**——本题真正的考点是发现下面两个观察，把整道题压缩成一行算术。

### 3.2 核心观察：答案只由人数 n 决定

两个观察合起来直接封顶+封底：

- **观察一（上界）**：合法方案中各组人数是**严格递增的正整数**，所以 `k` 个组至少要 `1 + 2 + … + k = k(k+1)/2` 个人。人数不够，组数就上不去——这与成绩具体是多少完全无关。
- **观察二（可达）**：把成绩**升序排序**后，前 1 人给第 1 组、接下来 2 人给第 2 组、……凑不满下一组时把剩余学生**全部塞进最后一组**。由于成绩全是**正数**，后一组的最小元素 ≥ 前一组的最大元素、且人数还多一个，**总和必然严格递增**，无需任何挑选。

于是「最多几组」与成绩值彻底解耦，答案就是满足 $k(k+1)/2 \le n$ 的最大整数 $k$，即三角形数模型：

![人数严格递增推出三角数下界的概念图](images/wc304_q2_staircase_concept.svg)

### 3.3 算法流程

![算法流程图](images/wc304_q2_algorithm_flow.svg)

用两个变量从零累积：`k` 为当前组数，`used` 为已占用人数 $1+2+\cdots+k$。只要 `used + (k+1) <= n` 就再开一组；否则返回 `k`：

1. 读入 `n = len(grades)`（**不排序、不看成绩值**）；
2. `k = 0, used = 0`；
3. 当 `used + (k+1) <= n` 时：`k += 1; used += k`；
4. 返回 `k`。

循环次数 $k \le \sqrt{2n} \approx 447$（$n = 10^5$），也可以直接套公式 $k = \left\lfloor \frac{\sqrt{8n+1}-1}{2} \right\rfloor$ 或在 $[0, n]$ 上二分。

### 3.4 示例演算

![示例逐步演算图](images/wc304_q2_example_walkthrough.svg)

以示例 1 为例：`n = 6`，排序得 `[3, 5, 6, 7, 10, 12]`，按 `1、2、3` 人切块：

```text
第 1 组 [3]        人数 1，总和 3
第 2 组 [5,6]      人数 2，总和 11
第 3 组 [7,10,12]  人数 3，总和 29
人数 1 < 2 < 3 ✓   总和 3 < 11 < 29 ✓
```

题面解释里给的方案是 `[12] / [6,7] / [10,3,5]`，与我们的 `[3] / [5,6] / [7,10,12]` 都合法——**构造不唯一**，但组数都顶到了上界 `3`（因为 `1+2+3 = 6 ≤ 6 < 10 = 1+2+3+4`）。

## 4. 算法细节

1. **答案只依赖 `n`**：「人数递增」提供结构性下界，「总和递增」由排序构造免费满足；成绩值只要为正就不影响 `k`。读题后的第一反应应当是「把 `n` 代进三角数不等式」。
2. **循环写法（推荐）**：`k`、`used` 两个变量即可，循环次数 $k \le \lfloor\sqrt{2n}\rfloor \approx 447$，时间 $O(\sqrt{n})$，比赛里最无脑最稳。
3. **公式写法**：解 $k(k+1)/2 \le n$ 得 $k = \left\lfloor\frac{\sqrt{8n+1}-1}{2}\right\rfloor$。C++ 用浮点 `sqrt` 后必须对结果做 ±1 整数校验防精度误差；Python 直接 `math.isqrt(8*n+1)`，整数开根无精度问题，一行解决。
4. **二分写法**：在 `[0, n]` 上二分最大的 `k` 使 `k*(k+1)/2 <= n`，`O(log n)`，对应官方标签里的 Binary Search。三种写法比赛里皆可。
5. **构造为何免验证**：升序后相邻块满足 $\min(\text{后块}) \ge \max(\text{前块})$。设第 `i` 组人数 `i`、最大值 `M_i`，则 $S_{i+1} \ge (i+1)\,M_i = i\,M_i + M_i \ge S_i + M_i > S_i$——两处分别用了「组内每个元素 ≤ 最大值」和「成绩为正」，一步到位。
6. **剩余学生**：凑不满第 `k+1` 组时，剩余的 $n - T_{k-1}$ 人全部并入第 `k` 组，其人数 $\ge k > k-1$ 仍严格递增，总和同理。

## 5. 正确性证明

**引理 1（组数上界）**：若存在 `k` 个分组的合法方案，则 $n \ge k(k+1)/2$。

**证明**：合法方案中各组人数 $c_1 < c_2 < \cdots < c_k$ 均为正整数。对 `i` 归纳：`c_1 ≥ 1`；若 $c_{i-1} \ge i-1$，则 $c_i \ge c_{i-1} + 1 \ge i$。故 $c_i \ge i$ 对所有 `i` 成立，求和得 $n = \sum_i c_i \ge \sum_{i=1}^{k} i = k(k+1)/2$。∎

**引理 2（构造可行）**：设 `k` 为满足 $k(k+1)/2 \le n$ 的最大整数。将 `grades` 升序排序为 $a_1 \le a_2 \le \cdots \le a_n$，记 $T_i = i(i+1)/2$，令第 `i` 组（$1 \le i \le k-1$）取 $a_{T_{i-1}+1}, \dots, a_{T_i}$，第 `k` 组取剩余全部 $n - T_{k-1}$ 个学生。则该方案满足题意。

**证明**：**人数**：前 `k−1` 组人数恰为 $1, 2, \dots, k-1$；第 `k` 组人数 $n - T_{k-1} \ge T_k - T_{k-1} = k > k - 1$，严格递增。**总和**：排序后的连续块使得第 `i+1` 组的每个元素都 $\ge M_i := a_{T_i}$（第 `i` 组的最大值，下标更大）。设第 `i+1` 组人数为 $c_{i+1} \ge i+1$，则

$$S_{i+1} \ \ge\ c_{i+1} \cdot M_i \ \ge\ (i+1)\,M_i \ =\ i\,M_i + M_i \ \ge\ S_i + M_i \ >\ S_i,$$

其中「$i\,M_i \ge S_i$」因为第 `i` 组的 $i$ 个元素每个 $\le M_i$，「$M_i > 0$」因为成绩为正。∎

**定理**：最大组数等于满足 $k(k+1)/2 \le n$ 的最大整数 $k$，即 $k = \left\lfloor\frac{\sqrt{8n+1}-1}{2}\right\rfloor$。

**证明**：由引理 1，任何合法方案的组数都不超过该 `k`；由引理 2，该 `k` 可以取到。两者夹逼即得。∎

> 💡 顺带一提：即便按「允许部分学生不入组」的宽松读法，答案也是同一个 `k`——塞进末组不破坏合法性，两种题意殊途同归。

## 6. 复杂度分析

- **时间复杂度**：$O(\sqrt{n})$
  - 循环版：每轮组数加一，循环次数 $k \le \sqrt{2n} \approx 447$（$n = 10^5$）；
  - 公式版 $O(1)$、二分版 $O(\log n)$。若 paranoid 地先排序再逐组验证则是 $O(n \log n)$，能过但完全多余。
- **空间复杂度**：$O(1)$
  - 只需 `k`、`used` 两个变量，不排序、不建任何辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumGroups(vector<int>& grades) {
        int n = grades.size();
        int k = 0;
        long long used = 0;              // used = 1 + 2 + ... + k
        while (used + (k + 1) <= n) {
            ++k;
            used += k;
        }
        return k;                        // 满足 k(k+1)/2 <= n 的最大 k
    }
};
```

公式版（浮点开根后必须整数校验 ±1）：

```cpp
class Solution {
public:
    int maximumGroups(vector<int>& grades) {
        long long n = grades.size();
        long long k = (long long)((sqrt((double)8 * n + 1) - 1) / 2);
        while ((k + 1) * (k + 2) / 2 <= n) ++k;   // 向前校验
        while (k * (k + 1) / 2 > n) --k;          // 向后校验
        return (int)k;
    }
};
```

### Python

```python
class Solution:
    def maximumGroups(self, grades: List[int]) -> int:
        n = len(grades)
        k, used = 0, 0
        while used + k + 1 <= n:
            k += 1
            used += k
        return k
```

一行版（`isqrt` 是整数开根，无精度问题）：

```python
from math import isqrt

class Solution:
    def maximumGroups(self, grades: List[int]) -> int:
        return (isqrt(8 * len(grades) + 1) - 1) // 2
```

## 8. 边界情况与易错点

1. **最小规模**：`n = 1` 答案 1；`n = 2` 答案 1（两组只能各 1 人，违反严格递增，即示例 2 的 `[8,8]`）。
2. **「所有学生都要分组」**：凑不满下一组时，剩余学生必须**全部并入最后一组**而不是丢弃——人数 1、2、…、k−1、$n - T_{k-1}$ 仍严格递增。好在该处理不影响答案（见 §5 备注）。
3. **浮点开根精度**：公式版直接 `(int)` 截断 `sqrt(8n+1)` 可能差 1，必须 ±1 校验；Python 用 `isqrt` 免疫。
4. **画蛇添足排序**：答案与成绩值无关，`sort` 是纯浪费。比赛中「读完题肌肉记忆先排序」是常态，本题恰恰考**发现无关**的洞察力。
5. **误以为「总和递增」需要挑选**：不需要——排序后连续切块，正数保证免费严格递增（§4 第 5 点的推导一步完成）。
6. **溢出**：本题 `k*(k+1)` 与 `8*n+1` 最大约 $8 \times 10^5$，`int` 安全；但二分/公式中做乘法时养成 `long long` 习惯更稳。
