# LeetCode 图中的最长环 题解

## 1. 题目概述

- **标题 / 题号**：图中的最长环（#2360，hard）
- **链接**：https://leetcode.cn/problems/longest-cycle-in-a-graph/
- **来源**：LeetCode 第 304 场周赛 Q4
- **难度**：困难
- **标签**：图、拓扑排序、深度优先搜索

**题意**：给一个 $n$ 个节点的**有向图**，每个节点**至多有一条出边**：`edges[i]` 是节点 $i$ 的出边目标，`edges[i] == -1` 表示 $i$ 没有出边。返回图中**最长环**的长度；没有环则返回 $-1$（环指起点终点为同一节点的路径）。

**约束**：

- $n = \text{edges.length}$，$2 \le n \le 10^5$
- $-1 \le \text{edges[i]} < n$
- $\text{edges[i]} \ne i$（无自环，环长至少为 2）

> 💡 本题在仓库另有[每日题解 2360](../../solution/2301-2400/2360_图中的最长环.md)，主推**全局时间戳一次遍历**的写法；本文与其互为印证，换**拓扑排序「剥挂链」**这条赛场路线展开——先把所有不在环上的链节点剥光，剩下「剥不动的」恰好全是环上节点，一圈一圈数长度取最大。这条路线也是同仓库 [365 场 Q4 · 2876](../365/Q4.有向图访问计数题解.md) 的前菜：2876 剥完还要给每个点算答案，本题只需环长本身。

## 2. 示例

**示例 1**

```text
输入：edges = [3,3,4,2,3]
输出：3
解释：图中的最长环是：2 -> 4 -> 3 -> 2。
      这个环的长度为 3，所以返回 3。
```

**示例 2**

```text
输入：edges = [2,-1,3,1]
输出：-1
解释：图中没有任何环（0 -> 2 -> 3 -> 1 -> -1，一条链撞死在 -1 上）。
```

**补充示例 3**（覆盖「多分量各带一个环 + 无环分量共存」）

```text
输入：edges = [1,2,0,-1,5,4]
输出：3
解释：分量一：0 -> 1 -> 2 -> 0，环长 3；
      分量二：4 -> 5 -> 4，环长 2；
      分量三：3 -> -1，无环。
      取所有环长的最大值 3。
```

## 3. 解题思路

### 3.1 暴力思路：每个起点各走一遍

对每个起点 $s$，沿出边行走并用集合记录本轮走过的节点，一旦踩到本轮已走过的节点 $u$，就找到一个环、长度为「当前步数 − $u$ 首次被踩到的步数」；撞到 $-1$ 或旧节点则换下一个起点。单轮最坏 $O(n)$，总计 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 步，必然超时。

> ⚠️ 暴力法的浪费是**结构性重复**：同一根挂链、同一个环会被链上每个起点反复重走。要让每个节点只被碰一次，得先看清这张图长什么样、环上的节点和链上的节点到底差在哪。

### 3.2 核心观察：函数图 + 「剥不动的就是环」

![函数图结构：每个分量是挂链加至多一个环](images/wc304_q4_functional_graph_concept.svg)

三个层层递进的观察：

**观察一（图的结构）**：每个节点出度 $\le 1$，这是一张**函数图**（functional graph）。沿任意节点的出边行走，路径是唯一的，命运只有两种：**撞 $-1$ 终止**，或者**进入一个环**绕圈。于是每个弱连通分量的形态是「若干条挂链 + 至多一个环」（$\rho$ 形），或者「纯挂链撞 $-1$」（无环）。**每个分量至多一个环**（§5 引理 1），全图的环互不相交。

**观察二（入度为 0 的节点不在环上）**：环上的每个节点都有一条**环内前驱**指向它；而入度为 0 的节点没有任何边指向它，走遍全图也回不到它，必然不在任何环上。剥掉它，也不影响任何剩余节点的「在环性」——它唯一能影响的是**后继的入度**。

**观察三（剥不动的恰是环）**：把入度 0 的节点反复剥掉（剥 $u$ 时给后继 `edges[u]` 的入度减一，归零则接着剥），最终能幸存（入度仍 $> 0$）的节点**恰好是全部环上节点**——环上节点互为前驱、入度永远有环内那条边顶着，剥不动；链上节点离环再近，也终将被剥光（§5 引理 3、4）。

> 💡 一句话：「找环」被改写成「删链」——不必沿着边去追环在哪，只要把注定到不了环、或只是路过环的链节点全部清场，留下来的就是环本身。这与 [207. 课程表](https://leetcode.cn/problems/course-schedule/) 的 Kahn 拓扑排序判环同源，只是函数图上连邻接表都不用建。

### 3.3 算法流程：拓扑排序剥挂链

![拓扑剥挂链算法流程图](images/wc304_q4_topo_peeling_flow.svg)

1. **统计入度**：`indeg[v]` = 有多少条边指向 $v$；对每个 $i$，若 `edges[i] != -1`，则 `indeg[edges[i]]++`。
2. **初始入队**：所有 `indeg[i] == 0` 的节点进入队列 `order`。
3. **剥离**：按下标从左到右扫 `order`（扫到即「出队」）；对出队节点 $u$，若 `edges[u] != -1`，给后继入度减一，**恰好归零**则追加进 `order` 尾部。
4. **识环**：队空后，`indeg[i] > 0` 的节点就是全部环上节点，无需任何额外标记。
5. **数环**：对每个未访问的环上节点出发，沿出边走一圈（`vis` 哨兵防重复），走过的步数即环长；答案取所有环长的最大值，一个环都没有则返回 $-1$。

### 3.4 示例演算

![示例 1 演算：剥掉 0 和 1 后剩环 2、4、3](images/wc304_q4_example_walkthrough.svg)

以示例 1 `edges = [3,3,4,2,3]` 为例（边：$0\to3,\ 1\to3,\ 2\to4,\ 3\to2,\ 4\to3$）：

1. **入度**：$0\!:\!0$，$1\!:\!0$，$2\!:\!1$（来自 $3$），$3\!:\!3$（来自 $0,1,4$），$4\!:\!1$（来自 $2$）。
2. **剥离**：$0,1$ 入队。出队 $0$：`indeg[3]` 由 3 减到 2；出队 $1$：`indeg[3]` 由 2 减到 1，均未归零，队空。
3. **识环**：`indeg > 0` 的幸存者 $\{2,3,4\}$，挂链 $0,1$ 已全部剥光。
4. **数环**：从 $2$ 出发沿出边走：$2 \to 4 \to 3 \to$ 回到 $2$，走了 3 步，环长 3，`ans = 3` ✓。

示例 2 `edges = [2,-1,3,1]` 则被**整图剥光**：入度 $[0,1,1,1]$，剥 $0$ 使 `indeg[2]` 归零入队，剥 $2$ 使 `indeg[3]` 归零入队，剥 $3$ 使 `indeg[1]` 归零入队，剥 $1$（出边 $-1$，不减任何入度）。幸存者为空，无环，返回 $-1$ ✓。

## 4. 算法细节

1. **无需邻接表**：每点出边唯一，`edges[u]` 即后继，$O(1)$ 定位；反图、邻接表一概不用建，空间比 DFS/Tarjan 系解法更省。
2. **队列即顺序表**：`order` 数组一物两用——先把入度 0 的节点顺序压入，再用下标从左到右扫描，扫到的即「出队」；新归零的追加到尾部。C++ 用下标循环，Python 直接 `for u in order` 边遍历边追加，不需要 `deque`。
3. **环检测零成本**：剥完直接判 `indeg[i] > 0`，这是结构判据（§5 引理 3、4），不需要另开「在环上」标记数组；`vis` 只在最后数环时充当「此环已数过」的哨兵。
4. **$-1$ 的两处处理**：统计入度时跳过；剥离时后继为 $-1$ 不减任何入度。漏掉前者会越界，漏掉后者虽然不减不存在的节点（`edges[u] == -1` 时本来就不会用作下标），但要显式写清以防误用负下标。
5. **每条入边至多扣一次**：`indeg[后继]--` 只在 $u$ 出队时执行，而每个 $u$ 恰好出队一次，不存在重复扣减把环误剥的情况。
6. **与 2876 的关系**：本题是 [2876. 有向图访问计数](../365/Q4.有向图访问计数题解.md)的「半成品」——那边剥完还要「环上定值 + 逆序递推挂链」，这边数完环长就收工；但本题多了 `edges[i] == -1` 的无环分量，是「函数图 + 空值」形态的最小样本。

## 5. 正确性证明

**引理 1（每分量至多一环）**：任何环上节点沿出边行走永远绕环，不会离开该环。

**证明**：设环 $C$ 上节点 $x$ 的出边为 $f(x)$（$f = \text{edges}$）。$C$ 是环意味着对每个 $x \in C$，$f(x)$ 是 $C$ 中 $x$ 的环内后继——出边唯一，$x$ 再无别的去向，故从 $C$ 内任一点出发的行走始终留在 $C$ 内。若另一环 $C' \ne C$ 与 $C$ 同处一个弱连通分量，则存在无向路径连接二者，该路径的第一条「离开 $C$」的有向边必然以某个 $x \in C$ 为端点，与 $x$ 的出边在 $C$ 内矛盾。∎

**引理 2（入度 0 不在环上）**：若 $\text{indeg}(u) = 0$，则 $u$ 不在任何环上。

**证明**：环上每个节点都有一条环内前驱指向它（环长 $\ge 2$），入度 $\ge 1$。逆否即得。∎

**引理 3（环上节点永不被剥）**：剥离的全过程中，任何环上节点都不会入队。

**证明**：对归纳命题 $P(t)$：「前 $t$ 轮剥离后，所有环上节点均未被剥」施归纳。$P(0)$ 平凡成立。设 $P(t)$ 成立：任取环上节点 $v$，其环内前驱 $p$ 未被剥，故边 $p \to v$ 仍在入度统计中，$v$ 的当前入度 $\ge 1$，第 $t+1$ 轮入队的（入度 0 的）节点不可能是 $v$。故 $P(t+1)$ 成立。∎

**引理 4（链上节点必被剥光）**：若某时刻存在未被剥的非环上节点，则此刻必存在一个入度为 0 的非环上节点。

**证明**：反设所有未剥的非环上节点入度均 $\ge 1$（当前入度只统计未剥前驱的边）。取未剥非环上节点 $u_1$，它有某个未剥前驱 $u_2$（$f(u_2) = u_1$）。若 $u_2$ 在环上，则 $u_2$ 的唯一出边指向 $u_1$，即 $u_1$ 是 $u_2$ 的环内后继，$u_1$ 也在该环上，矛盾；故 $u_2$ 也是未剥的非环上节点。如此生成序列 $u_1, u_2, u_3, \dots$，有限图中必出现 $u_i = u_j\ (i < j)$，则 $u_i \to u_{i+1} \to \cdots \to u_{j-1} \to u_i$ 构成一个全部由「非环上节点」组成的环——这些节点明明就在环上，矛盾。∎

**定理（剥不动的恰是环）**：剥离终止（队列空）时，未被剥的节点集合恰为全部环上节点；且「`indeg[i] > 0`」这一判定不重不漏地识别它们。

**证明**：终止时队列空，即无入度 0 的节点；由引理 4 的逆否，未剥的非环上节点不存在。由引理 3，环上节点全部幸存，且由其归纳过程知幸存环上节点的入度恒 $\ge 1$。另一方面，被剥节点出队时入度为 0，而其后入度只会减不会增（每条边至多被扣一次），故终态入度恰为 0。两侧合起来：`indeg > 0` ⟺ 环上节点。∎

**定理（答案正确）**：对每个未访问的幸存节点 $i$，沿出边行走到首次重访所走的步数等于 $i$ 所在环的长度；这些环恰是全图所有环。

**证明**：$i$ 在环上（上一定理），其所在分量恰有一个环（引理 1）。从 $i$ 出发沿出边行走路径唯一且绕环，回到 $i$ 之前经过的节点两两不同（否则出现更小的环，与每分量至多一环矛盾），首次重访恰是回到 $i$，步数 = 环上节点数 = 环长。`vis` 哨兵保证每个环只被数一次；每个环上都有幸存节点，故所有环均被枚举，取最大值即最长环，无环时返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$
  - 入度统计一次遍历 $O(n)$；剥离阶段每个节点至多入队出队各一次、每条边至多被扣一次，合计 $O(n)$；「`order` 边追加边扫描」的总推进次数等于 `order` 长度 $\le n$；数环阶段每个环上节点恰被访问一次。
- **空间复杂度**：$O(n)$
  - `indeg`、`order`、`vis` 三个长度 $n$ 的数组；全程迭代无递归，不占栈空间，也不建邻接表。

## 7. 参考代码

### C++（拓扑剥挂链）

```cpp
class Solution {
  public:
    int longestCycle(vector<int>& edges) {
        int n = edges.size();
        vector<int> indeg(n, 0);
        for (int v : edges)
            if (v != -1) indeg[v]++;

        vector<int> order;                    // 一物两用：队列 + 剥离顺序表
        for (int i = 0; i < n; ++i)
            if (indeg[i] == 0) order.push_back(i);
        for (int k = 0; k < (int)order.size(); ++k) {   // 扫到即出队
            int u = order[k], v = edges[u];
            if (v != -1 && --indeg[v] == 0) order.push_back(v);
        }

        int ans = -1;
        vector<char> vis(n, 0);
        for (int i = 0; i < n; ++i) {
            if (indeg[i] == 0 || vis[i]) continue;   // 剥不动的 = 环上节点
            int len = 0, u = i;
            while (!vis[u]) {                        // 沿出边走一圈数环长
                vis[u] = 1;
                u = edges[u];
                ++len;
            }
            ans = max(ans, len);
        }
        return ans;
    }
};
```

### Python（拓扑剥挂链）

```python
class Solution:
    def longestCycle(self, edges: List[int]) -> int:
        n = len(edges)
        indeg = [0] * n
        for v in edges:
            if v != -1:
                indeg[v] += 1

        order = [i for i in range(n) if indeg[i] == 0]
        for u in order:                      # 列表边遍历边追加，天然队列
            v = edges[u]
            if v != -1:
                indeg[v] -= 1
                if indeg[v] == 0:
                    order.append(v)

        ans = -1
        vis = [False] * n
        for i in range(n):                   # 入度仍 > 0 的节点都在环上
            if indeg[i] == 0 or vis[i]:
                continue
            length, u = 0, i
            while not vis[u]:                # 沿出边走一圈数环长
                vis[u] = True
                u = edges[u]
                length += 1
            ans = max(ans, length)
        return ans
```

> 💡 两版逻辑一致，全程迭代、无递归、不建邻接表。已与「每起点独立模拟」的暴力做过 20000 组随机对拍（$n \le 12$），并覆盖官方两示例、补充示例 3，全部一致。

### 解法二：全局时间戳一次遍历（与每日版互证）

不剥链、直接沿出边走：全局 `clock` 给每个首次访问的节点盖唯一戳 `vis[u]`，每轮记录起点戳 `start`；若撞到的已访问节点 `vis[u] >= start`，说明是**本轮**盖的戳——重逢点即环入口，环上时间戳恰取 `vis[u], vis[u]+1, …, clock-1`，环长 $=\text{clock}-\text{vis}[u]$；若 `vis[u] < start` 则只是汇入旧分量的挂链，不算新环。

```cpp
class Solution {
  public:
    int longestCycle(vector<int>& edges) {
        int n = edges.size();
        vector<int> vis(n, 0);       // 0 = 未访问，否则为盖戳时刻
        int clock = 1, ans = -1;
        for (int s = 0; s < n; ++s) {
            if (vis[s]) continue;
            int start = clock, u = s;
            while (u != -1 && !vis[u]) {
                vis[u] = clock++;
                u = edges[u];
            }
            if (u != -1 && vis[u] >= start)   // 本轮重逢 ⇒ 新环
                ans = max(ans, clock - vis[u]);
        }
        return ans;
    }
};
```

> 💡 `clock` 从 1 起而非 0，让 0 专属表示「未访问」。完整推导、Python 版与逐行演算见[每日题解 2360](../../solution/2301-2400/2360_图中的最长环.md)。两条路线都是 $O(n)$：时间戳法代码更短、单数组；剥挂链法与课程表拓扑同源、可平移到「环上点计数 / 每点答案」类问题（如 2876），值得都过一遍。

## 8. 边界情况与易错点

1. **`edges[i] == -1` 的两处分支**：入度统计跳过；剥离时出边为 $-1$ 不减任何入度。把 $-1$ 直接当下标会越界（RE）。
2. **无环整图**：全部剥光，数环循环体一次不执行，`ans` 保持初值 $-1$ 返回——初值必须是 $-1$ 而不是 $0$（示例 2）。
3. **无自环保证**：`edges[i] != i` ⇒ 环长 $\ge 2$，不需要特判长度 1 的环；但若哪天约束放开允许自环，本题算法依然成立（自环节点的入度含自己的边，剥不动，数圈时走一步回到自己）。
4. **入队去重**：只在入度**恰好减到 0** 时入队，配合「每点只出队一次」，天然不会重复入队；不要写成「减完就入队」。
5. **别把分量大小当环长**：最长环只数环上节点，挂链不算（示例 1 分量大小 5，环长只有 3）。
6. **递归 DFS 爆栈**：$n = 10^5$ 的长链会把递归深度顶到 $10^5$（C++ 默认栈约 1 MB、Python 默认上限 1000 层），两版参考代码均为迭代写法，天然免疫。
7. **官方标签里的 Tarjan**：函数图上大小 $\ge 2$ 的强连通分量恰是环（每分量至多一个），Tarjan 求所有 SCC 取最大也能做，但栈、dfn/low 三数组齐全，常数与代码量都大——赛场优先剥挂链或时间戳。
8. **数环的哨兵**：`vis` 只防「同一环被多个入口重复数」；环上任意节点出发走一圈都得到同一长度，哨兵让每环只走一次。

- [LeetCode 2876. 有向图访问计数](https://leetcode.cn/problems/count-visited-nodes-in-a-directed-graph/)：本题的「全量版」，同一张函数图要给**每个**点算答案，剥挂链后还需环上定值 + 逆序递推；周赛复盘见[本文仓库 365 场 Q4 题解](../365/Q4.有向图访问计数题解.md)。

- [LeetCode 802. 找到最终的安全状态](https://leetcode.cn/problems/find-eventual-safe-states/)：反向拓扑排序剥「走不到环」的节点，与本文剥挂链互为镜像（一个收集剥掉的，一个收集剩下的）。
- [LeetCode 565. 数组嵌套](https://leetcode.cn/problems/array-nesting/)：排列（每点出入度皆 1）是**无挂链**的纯函数图，全图不相交环的并集，求最长环思路直接复用。
- [LeetCode 287. 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/)：隐式函数图上的 Floyd 龟兔赛跑**单点**找环入口，与本文「全图扫描」是找环的两种范式。
- [LeetCode 2127. 参加会议的最多员工数](https://leetcode.cn/problems/maximum-employees-to-be-invited-to-a-meeting/)：内向基环森林上的经典最值题，环长与挂环链深度的组合取最值。

**延伸思考**：

- 若要输出最长环**本身**（节点序列）而不仅是长度？——数环时从入口 $i$ 出发再走一遍并记录路径即可，$O(n)$ 不变。
- 若每个节点出度可以**多于一条**（一般有向图）？——最长简单环的判定包含哈密顿回路，是 NP 完全问题；「至多一条出边」正是本题多项式可解的命门。
- 若支持**单点修改** `edges[i]` 后实时查询最长环？——每次重构是 $O(n)$；要摊还更低需要维护环结构的动态信息，是基环森林上更深的功课。
