# LeetCode 使数组中所有元素都等于零 题解

## 1. 题目概述

- **标题 / 题号**：使数组中所有元素都等于零（#2357，easy）
- **链接**：https://leetcode.cn/problems/make-array-zero-by-subtracting-equal-amounts/
- **来源**：LeetCode 第 304 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组、哈希表、排序、模拟

**题意**：给定一个非负整数数组 `nums`。每一步操作必须：

1. 选出一个正整数 `x`，要求 `x` 小于或等于 `nums` 中**最小**的**非零**元素；
2. 将 `nums` 中**每个正整数**都减去 `x`。

返回使所有元素等于 `0` 的**最少操作数**。

**约束**：

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [1,5,0,3,5]
输出：3
解释：
  第一步操作：选出 x = 1，之后 nums = [0,4,0,2,4]
  第二步操作：选出 x = 2，之后 nums = [0,2,0,0,2]
  第三步操作：选出 x = 2，之后 nums = [0,0,0,0,0]
```

**示例 2**

```text
输入：nums = [0]
输出：0
解释：所有元素已经是 0，不需要任何操作。
```

**补充示例 3**（覆盖「重复值只算一次」）

```text
输入：nums = [2,2,4]
输出：2
解释：
  第一步操作：选出 x = 2，两个 2 同时归零，nums = [0,0,2]
  第二步操作：选出 x = 2，nums = [0,0,0]
  重复出现的值共享同一次操作，答案只与不同值的个数有关。
```

## 3. 解题思路

### 3.1 暴力思路：直接模拟

比赛中最快的落地写法是**老老实实模拟**：每一轮先扫一遍数组找出最小非零元素 `m`，再扫一遍把所有非零元素减去 `m`，操作数加一，直到数组全零。

- 由于每轮至少把一个元素（值为 `m` 的那些）归零，最多 `n` 轮就会结束；
- 每轮两次 `O(n)` 扫描，总时间 `O(n^2)`。

本题 `n <= 100`，`O(n^2)` 绰绰有余，可以直接交。但模拟写起来分支多（找最小值、跳过 0、判结束），签到题也容易在边界上翻车，更值得沉淀的是下面的观察。

### 3.2 核心观察：答案 = 不同非零值的个数

把数组中的元素**按值分层**：值相同的一批元素同生共死——因为每一步操作对所有非零元素减去**同一个** `x`，两个相等的值在归零之前永远相等，也必然在**同一步**一起归零。

于是「数组」可以压缩成一个「值的集合」：

![不同非零值分层概念图](images/2357_distinct_values_concept.svg)

- 设 `k` 为 `nums` 中**不同非零值**的个数，则答案就是 `k`。

直觉上的两半：

- **快不了**：所有非零值减去同一个 `x` 之后仍然两两互异，一步至多恰好归零一个值层，所以 `k` 层至少要 `k` 步；
- **慢不了**：每步贪心取 `x =` 当前最小非零值，恰好削平一层，`k` 步内必然全零。

### 3.3 算法流程

![算法流程图](images/2357_algorithm_flow.svg)

一次遍历 + 哈希集合去重：

1. 遍历 `nums`，把每个**非零**元素 `x` 插入集合 `seen`（`0` 直接跳过）；
2. 答案即为 `len(seen)`。

### 3.4 示例演算

以示例 1 为例，跟踪「不同非零值集合」的演变，可以看到它每步恰好减少一个：

![示例逐步演算图](images/2357_example_walkthrough.svg)

```text
[1,5,0,3,5]  →  {1,3,5}   (3 层)
减 1         →  {2,4}     (值 1 层归零)
减 2         →  {2}       (原值 3 层归零)
减 2         →  { }       (原值 5 层归零)
```

三步恰好削掉三个值层（1、3、5），与「不同非零值个数 = 3」一致。

## 4. 算法细节

1. **去重计数**：`k = |{nums[i] : nums[i] > 0}|`，用哈希集合一次遍历得到，`O(n)`。
2. **剔除 0**：`0` 不参与操作（题目只对正整数减 `x`），计数前必须排除，否则 `[0]` 会错误地答 1。
3. **排序数段法**：也可将数组排序后，统计满足 `nums[i] != nums[i-1]` 且 `nums[i] > 0` 的位置个数（若 `nums[0] > 0` 需额外加 1），`O(n log n)`，好处是 `O(1)` 额外空间（原地排序时）。
4. **值域布尔数组**：本题 `0 <= nums[i] <= 100`，可开长度 101 的布尔数组标记出现过的非零值，最后累加，`O(n + V)`。
5. **贪心策略解释**：模拟做法中每轮应取 `x = m`（最小非零值）。若取 `x < m`，则所有非零元素减 `x` 后仍是正数，没有元素归零，白白消耗一步——这正是引理 2 中「下界」的另一面。

## 5. 正确性证明

**引理 1（一步至多消灭一层）**：设某步操作前数组的不同非零值集合为 `S`，`|S| = k >= 1`。该步取正整数 `x <= min S`，操作后 `S` 的大小至少为 `k - 1`。

**证明**：操作后每个 `v ∈ S` 变为 `v - x`。

- 若 `v > x`：`v - x > 0` 仍是非零值；且对任意 `v ≠ v'`，有 `v - x ≠ v' - x`，即剩余非零值仍两两互异；
- 若 `v = x`：`v` 恰好归零。由 `S` 中值互异且 `x` 固定，这样的 `v` 至多一个。

所以操作后不同非零值个数只可能从 `k` 降到 `k - 1`（当且仅当 `x = min S` 时），或保持 `k` 不变。∎

**引理 2（下界）**：设初始不同非零值个数为 `k`，则任何合法操作序列的长度至少为 `k`。

**证明**：终态的不同非零值个数为 0。由引理 1，每步操作使该计数至多减少 1，因此从 `k` 降到 0 至少需要 `k` 步。∎

**引理 3（可达性）**：策略「每步取 `x =` 当前最小非零值」恰好 `k` 步使数组全零。

**证明**：对该计数归纳。当前计数 `k >= 1` 时，取 `x = min S`，由引理 1 的取等条件，恰好最小层归零，计数变为 `k - 1`。归纳可得 `k` 步后计数为 0，即所有元素为 0。∎

**定理**：最少操作数等于初始数组中不同非零值的个数 `k`。

**证明**：由引理 2，任何方案至少 `k` 步；由引理 3，存在 `k` 步的方案。两者夹逼即得。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n)`
  - 哈希做法：一次遍历插入集合，`O(n)` 平均；
  - 排序做法：`O(n log n)`；值域布尔做法：`O(n + V)`，`V = 101`。三者在本题数据下都远低于限。
- **空间复杂度**：`O(min(n, V))`
  - 哈希集合至多存 `min(n, 101)` 个值；排序做法若原地排序则 `O(1)` 额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        unordered_set<int> seen(nums.begin(), nums.end());
        seen.erase(0);          // 0 不参与操作，必须剔除
        return (int)seen.size(); // 答案 = 不同非零值个数
    }
};
```

### Python

```python
class Solution:
    def minimumOperations(self, nums: List[int]) -> int:
        return len(set(nums) - {0})
```

## 8. 边界情况与易错点

1. **忘记剔除 0**：`set(nums)` 直接计数会把 0 算进去，`[0]` 会错答 1。必须 `set(nums) - {0}` 或插入时跳过 0。
2. **全零数组**：答案为 0，去重后集合为空，`len` 自然为 0，无需特判。
3. **重复元素**：`[2,2,4]` 答案是 2 而不是 3——重复值共享一次操作，这正是要用**集合**而非计数的根本原因。
4. **模拟实现中的 x**：若选 `x < min`，没有元素归零，模拟会死循环或浪费步数；模拟时必须取 `x = min`（题目允许 `x <= min`，但取等号才是最优）。
5. **范围虽小，思路要正**：`n, nums[i] <= 100` 让 `O(n^2)` 甚至 `O(sum)` 的模拟都能过，但 `k = |set - {0}|` 这个结论与数据范围无关，元素换成 `10^9` 依然一行解决。
