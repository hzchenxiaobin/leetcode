# LeetCode 找到离给定两个节点最近的节点 题解

## 1. 题目概述

- **标题 / 题号**：找到离给定两个节点最近的节点（#2359，medium）
- **链接**：https://leetcode.cn/problems/find-closest-node-to-given-two-nodes/
- **来源**：LeetCode 第 304 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索、图

**题意**：给定 $n$ 个节点的**有向图**，每个节点**至多一条出边**：`edges[i]` 是节点 $i$ 唯一出边指向的节点，`edges[i] == -1` 表示没有出边。再给两个起点 `node1`、`node2`，找一个从两者**都能到达**的节点 $x$，使 $\max(\text{dist}(node1, x),\ \text{dist}(node2, x))$ **最小化**；多解取**最小编号**，无解返回 $-1$。注意图里**可能有环**。

**约束**：

- $2 \le n \le 10^5$
- $-1 \le \text{edges}[i] < n$，且 $\text{edges}[i] \ne i$（无自环）
- $0 \le node1, node2 < n$

> 本题另有[每日题解 2359](../../solution/2301-2400/2359_找到离给定两个节点最近的节点.md)：同一算法的面试向展开。本文是**赛场复盘**视角：ρ 形路径的结构观察、合流点唯一性证明与环处理的易错点，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：edges = [2,2,3,-1], node1 = 0, node2 = 1
输出：2
解释：0→2 距离 1，1→2 距离 1，max = 1，无法更小，返回节点 2。
```

**示例 2**

```text
输入：edges = [1,2,-1], node1 = 0, node2 = 2
输出：2
解释：0→1→2 距离 2；节点 2 到自身距离 0；max = 2，返回节点 2。
```

**示例 3**（自造，覆盖环场景）

```text
输入：edges = [1,2,0,1], node1 = 1, node2 = 3
输出：1
解释：1→2→0→1 构成环，节点 3 挂在环外指向 1。
      从 1 出发标记：dist1 = [2, 0, 1, -1]（走回 1 时已标记，停止）
      从 3 出发标记：dist2 = [3, 1, 2, 0]
      候选 0 / 1 / 2 的 max 分别为 3 / 1 / 2，最小在节点 1。
```

## 3. 解题思路

### 3.1 暴力思路

对每个节点 $x$ 逐一判定：从 `node1` 沿出边一步步走（最多 $n$ 步），看能否遇到 $x$、第几步遇到；对 `node2` 同理，两边都能遇到则得到一个候选。单个 $x$ 判定 $O(n)$，全体合计 $O(n^2) \approx 10^{10}$（$n = 10^5$），**超时**。

另一种常见 reflex 是把图当一般有向图，从 `node1`、`node2` 各跑一遍 BFS 求单源最短路——复杂度 $O(n)$ 其实能过（边数 $=$ 点数），但在本题结构下 BFS 的队列里**永远只有一个元素**：每个节点至多一条出边，根本不存在"分支"。认出这一点，BFS 就退化成一个 `while` 循环。

### 3.2 核心观察：出边唯一 ⇒ 路径唯一 ⇒ 首次到达即最短

- **观察 1（路径唯一）**：每个节点出边至多一条，从任意起点 $s$ 出发的节点序列 $s \to \text{edges}[s] \to \text{edges}[\text{edges}[s]] \to \cdots$ **唯一确定**——不存在第二种走法。这条路径要么终止于 $-1$，要么最终**进入一个环**无限循环，整体呈 **ρ 形**（rho，先链后环）。
- **观察 2（首次到达 = 最短距离）**：既然从 $s$ 出发只有一条路，$s$ 到可达节点 $x$ 的**最短距离就是首次走到 $x$ 的步数**——不存在"绕近路"。环也不例外：绕环一圈再回到 $x$ 只会更长。于是一次线性扫描（遇到已标记节点或 $-1$ 即停）就能得到**全部**单源距离，不需要 BFS / Dijkstra。
- **观察 3（合流后不分叉）**：两条路径一旦出现公共节点 $c$，从 $c$ 起它们**完全重合**（$c$ 的后继唯一）。因此两起点的公共可达集是一条**共享尾巴**链；沿尾巴每前进一格，两个距离同时 $+1$，$\max$ **严格递增**——最小值恰在**合流点**取得。

![ρ形路径与共享尾巴](images/wc304_q3_functional_graph.svg)

> 💡 一句话总结：**"每个节点至多一条出边"把最短路问题变成了"沿唯一路径打标记"**——一个 `while` 扫描代替整套 BFS 框架；两条路径相交即合流，$\max$ 在合流点取最小。

### 3.3 算法流程

1. `dist1`、`dist2` 初始化为全 $-1$（未访问哨兵）；
2. 从 `node1` 出发扫描：$u = node1$，$d = 0$；当 $u \ne -1$ 且 `dist1[u] == -1` 时，标记 `dist1[u] = d`，然后 $d \gets d + 1$，$u \gets \text{edges}[u]$；
3. 从 `node2` 出发同样扫描得 `dist2`；
4. 从 $0$ 到 $n - 1$ 升序枚举 $i$：若 `dist1[i]`、`dist2[i]` 均 $\ge 0$，令 $m = \max(\text{dist1}[i], \text{dist2}[i])$；若 $m < \text{best}$ 则更新 $\text{best} = m$、$\text{ans} = i$；
5. 返回 `ans`（无公共可达节点时保持 $-1$）。

![算法流程图](images/wc304_q3_algorithm_flow.svg)

### 3.4 示例演算

以自造的示例 3（`edges = [1,2,0,1]`，`node1 = 1`，`node2 = 3`，含环）走一遍：

- **第一趟（node1 = 1）**：$1_{d=0} \to 2_{d=1} \to 0_{d=2} \to 1$（已标记，停）→ `dist1 = [2, 0, 1, -1]`；
- **第二趟（node2 = 3）**：$3_{d=0} \to 1_{d=1} \to 2_{d=2} \to 0_{d=3} \to 1$（已标记，停）→ `dist2 = [3, 1, 2, 0]`；
- **枚举合并**：

| 节点 $i$ | dist1 | dist2 | $\max$ | 备注 |
|---|---|---|---|---|
| 0 | 2 | 3 | 3 | 尾巴第 3 站 |
| 1 | 0 | 1 | **1** | **合流点，答案** |
| 2 | 1 | 2 | 2 | 尾巴第 2 站 |
| 3 | × | 0 | — | node1 不可达 |

$\max$ 沿共享尾巴 $1 \to 2 \to 0$ 依次为 $1, 2, 3$ **严格递增**，验证了观察 3。

## 4. 算法细节

1. **单趟扫描的终止条件**：`u != -1 && dist[u] == -1`——两个条件分别对应"路径尽头（无出边）"与"踏入已访问节点（进环）"。**缺第二个条件必死循环**（环上无限绕）。反过来，第二个条件也让扫描天然处理环：每个节点至多被标记一次。
2. **哨兵 $-1$ 的一语双关**：`edges[i] == -1` 表示无出边，`dist[i] == -1` 表示未访问——两处语义不同但都用 $-1$，别混淆。起点到自身距离为 $0$，**不能用 $0$ 当"未访问"哨兵**，否则起点被误判不可达。
3. **平局取最小编号**：升序枚举、且只在 $m < \text{best}$（**严格小于**）时更新——后面的同 $m$ 节点不会覆盖先来的小编号；写成 `<=` 会取到最大编号。由第 5 节推论，本题实际不存在平局（$\max$ 在候选链上严格递增），但枚举写法不依赖这一点，更稳。
4. **为什么不用 BFS**：functional graph 出度 $\le 1$，BFS 队列长度恒为 1，`visited` 数组被 `dist` 本体兼任，直接 `while` 扫描等价且更短。坚持写 BFS 也正确，只是白背模板。
5. **合流点视角的另一实现**：由观察 3，答案就是两路径的第一个公共节点。可以先标记 `dist1`，再扫 `node2` 的路径，**第一个**满足 `dist1[u] >= 0` 的 $u$ 即答案——省去一次全量枚举；两种写法都是 $O(n)$，枚举版更直白、不易错。

## 5. 正确性证明

**引理 1（序列唯一）**：从任一起点 $s$ 出发、长度为 $k$ 的 walk（若存在）的终点唯一，记为 $u_k$；且 $u_0 = s$，$u_{k+1} = \text{edges}[u_k]$。

**证明**：对 $k$ 归纳。$k = 0$ 时唯一终点为 $s$。设长度为 $k$ 的 walk 终点均为 $u_k$；长度为 $k+1$ 的 walk 由某条长度为 $k$ 的 walk 加一步组成，末步沿 $u_k$ 的唯一出边，故终点均为 $\text{edges}[u_k]$（若其为 $-1$ 则长度 $k+1$ 的 walk 不存在）。∎

**引理 2（首次标记即最短）**：扫描结束后，对每个节点 $x$：`dist[x]` $\ge 0$ 当且仅当 $x$ 从 $s$ 可达，且此时 `dist[x]` $= \delta(s, x)$（最短 walk 长度）。

**证明**：考察由 $u_0 = s$、$u_{k+1} = \text{edges}[u_k]$ 定义的（可能截断的）序列。由引理 1，任何从 $s$ 出发、长度为 $k$ 的 walk 终点均为 $u_k$，故 $x$ 可达当且仅当 $x$ 在序列中出现，且 $\delta(s, x)$ 等于 $x$ 在序列中**首次出现的下标** $f(x)$：下标不足 $f(x)$ 的 walk 终点都不是 $x$，而恰为 $f(x)$ 的前缀 walk 到达 $x$。扫描按 $d = 0, 1, 2, \dots$ 逐个处理 $u_d$，仅在未标记时写入当前下标，故写入值恰为首次出现下标。再证不漏：扫描终止于 $u_d = -1$（序列截断，此后无节点），或 $u_d$ 已标记，即存在 $j < d$ 使 $u_d = u_j$；由序列确定性，$u_{d+t} = u_{j+t}$ 对一切 $t \ge 0$ 成立，序列自 $d$ 起周期重复、不再出现新节点。两种情形下，序列中出现的节点全部在终止前被标记。∎

**引理 3（合流不分叉）**：自 $s_1$、$s_2$ 出发的两条路径若有公共节点 $c$，则两路径自 $c$ 起完全重合。

**证明**：自 $c$ 出发的序列唯一（引理 1），两条路径自 $c$ 之后都沿该序列延伸。∎

**定理**：算法返回的 `ans` 为题目所求——使 $M(x) = \max(\delta(node1, x),\ \delta(node2, x))$ 最小的公共可达节点中编号最小者（不存在则为 $-1$）。

**证明**：由引理 2，`dist1`、`dist2` 精确记录两起点的全部最短距离（不可达为 $-1$），故第 4 步枚举的候选集 $\{i : \text{dist1}[i] \ge 0 \wedge \text{dist2}[i] \ge 0\}$ 恰为公共可达集，且 $M(i) = \max(\text{dist1}[i], \text{dist2}[i])$。枚举按编号升序、仅严格更小时更新，故 `ans` 为 $M$ 最小者中最小编号；候选为空则 `ans` 保持初值 $-1$。∎

**推论（答案唯一）**：公共可达集是一条链（引理 3 的共享尾巴），沿链每前进一格两个距离同时 $+1$，故 $M$ 沿链**严格递增**、在合流点取得最小值——题目中"多解取最小编号"在 functional graph 上实际不会触发。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。两趟扫描各至多 $n + 1$ 次迭代——每次迭代标记一个新节点，节点共 $n$ 个，多出的一次用于触发终止条件；枚举合并再花 $O(n)$。总计常数级线性。
- **空间复杂度**：$O(n)$。`dist1`、`dist2` 两个距离数组；扫描本身只用常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int closestMeetingNode(vector<int>& edges, int node1, int node2) {
        int n = edges.size();
        vector<int> d1 = walk(edges, node1);
        vector<int> d2 = walk(edges, node2);
        int ans = -1, best = INT_MAX;
        for (int i = 0; i < n; i++) {
            if (d1[i] >= 0 && d2[i] >= 0) {
                int m = max(d1[i], d2[i]);
                if (m < best) {
                    best = m;
                    ans = i;
                }
            }
        }
        return ans;
    }
private:
    vector<int> walk(vector<int>& edges, int start) {
        int n = edges.size();
        vector<int> dist(n, -1);
        int u = start, d = 0;
        while (u != -1 && dist[u] == -1) {
            dist[u] = d;
            u = edges[u];
            d++;
        }
        return dist;
    }
};
```

### Python

```python
class Solution:
    def closestMeetingNode(self, edges: List[int], node1: int, node2: int) -> int:
        n = len(edges)

        def walk(start: int) -> list:
            dist = [-1] * n
            u, d = start, 0
            while u != -1 and dist[u] == -1:
                dist[u] = d
                u, d = edges[u], d + 1
            return dist

        d1, d2 = walk(node1), walk(node2)
        ans, best = -1, float('inf')
        for i in range(n):
            if d1[i] != -1 and d2[i] != -1:
                m = max(d1[i], d2[i])
                if m < best:
                    best, ans = m, i
        return ans
```

## 8. 边界情况与易错点

1. **环上死循环（本题主坑）**：只判 `u != -1` 不判 `dist[u] == -1`，遇到环直接死循环 / TLE。终止必须**双条件**。
2. **不要给环"绕圈取 min"**：functional graph 路径唯一，首次到达就是最短，不存在"另一条更短的路"，也不存在顺 / 逆时针之争。
3. **哨兵用 $-1$ 别用 $0$**：起点到自身距离为 $0$，用 $0$ 当"未访问"会把起点判成不可达。
4. **平局更新符号**：`m < best` 严格小于保住最小编号；`<=` 会反向选到最大编号（虽然由第 5 节推论本题无平局，但按题意保守处理更稳）。
5. **node1 == node2**：答案即该节点（$M = 0$），两趟扫描结果一致，算法自动覆盖，无需特判。
6. **无公共可达节点**：两条路径互不相交（一条止于 $-1$、另一条进环，或进不同的环）时 `ans` 保持 $-1$，注意初值别设成 $0$。
7. **自环被输入保证排除**（$\text{edges}[i] \ne i$）；即便出现自环，`dist[u] == -1` 判定也能正确终止并给出距离 $0$ 之外的正确结果。
8. **数据规模**：$n \le 10^5$，距离 $\le n - 1$，`int` 足够，无溢出风险。
