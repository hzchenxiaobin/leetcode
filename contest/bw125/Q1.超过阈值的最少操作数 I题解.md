# LeetCode 超过阈值的最少操作数 I 题解

## 1. 题目概述

- **标题 / 题号**：超过阈值的最少操作数 I（#3065，easy）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-exceed-threshold-value-i/
- **来源**：LeetCode 第 125 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定下标从 $0$ 开始的整数数组 `nums` 和整数 `k`。一次操作中，你可以**删除 `nums` 中的最小元素**。要求让数组中所有元素都**大于或等于** `k`，返回需要的最少操作次数。

**约束**：

- $1 \le nums.length \le 50$
- $1 \le nums[i] \le 10^9$
- $1 \le k \le 10^9$
- 输入保证至少存在一个满足 $nums[i] \ge k$ 的下标 $i$（因此答案不超过 $n - 1$，数组不会被删空）

**关键前提**：操作**只能删除**，不会修改任何元素的值。这一点决定了整道题的走向——凡是小于 $k$ 的元素，除了被删除别无出路。

## 2. 示例

**示例 1**

```text
输入：nums = [2,11,10,1,3], k = 10
输出：3
解释：依次删除最小元素 1、2、3，剩下的 [11,10] 全部 ≥ 10。
```

**示例 2**

```text
输入：nums = [1,1,2,4,9], k = 1
输出：0
解释：所有元素都已 ≥ 1，无需任何操作。
```

**示例 3**

```text
输入：nums = [1,1,2,4,9], k = 9
输出：4
解释：只有 9 达标，需要把 1、1、2、4 全部删掉。
```

**示例 4（边界补充）**

```text
输入：nums = [5], k = 5
输出：0
解释：单元素且已达标；答案不可能超过 n−1 = 0。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**真的模拟**：每轮线性扫描找出最小值并删除，直到所有元素 ≥ `k`。单轮 $O(n)$、最多 $n$ 轮，总复杂度 $O(n^2)$——在 $n \le 50$ 时当然能过，但它把一个只需要数个数的问题写成了数据结构的模拟，既慢又容易写错边界（比如删空时越界）。

更好的暴力是**排序后模拟**：升序排序，从头开始删，直到遇到第一个 $\ge k$ 的元素，$O(n \log n)$。它已经接近正解——因为「删除最小的」在排序后就是从前往后扫，于是「模拟」自然退化为「计数」。

### 3.2 核心观察：值不变，所以小于 $k$ 的元素必须全部消失

![核心观察：小于 k 的元素必须被删除，计数即可](images/bw125_q1_threshold_count.svg)

由于操作只有「删除最小元素」一种效果，数组元素的值在整个过程中**永不改变**。由此得到两条直接结论：

1. **必要性**：任何初始值 $< k$ 的元素，无论怎么操作它都还是 $< k$，只能被删除；而任何初始值 $\ge k$ 的元素都无需被删除（删了反而浪费一次操作）。
2. **充分性**：操作强制删除当前最小值，等价于按**从小到大**的顺序依次删除。于是只要还有 $< k$ 的元素，当前最小值一定 $< k$，它就在下一轮被删掉。

两者合起来：需要且恰好需要删掉「所有 $< k$ 的元素」，操作次数等于这些元素的**个数**。不需要排序、不需要堆、也不需要真的删除——一遍计数就够。

### 3.3 算法流程

![算法流程：一次遍历计数](images/bw125_q1_scan_flow.svg)

```text
1. cnt ← 0
2. 对 nums 中每个 x：
       若 x < k：cnt ← cnt + 1
3. 返回 cnt
```

### 3.4 示例演算

以示例 1（`nums = [2,11,10,1,3]`，`k = 10`）为例：

| 元素 | 与 $k=10$ 比较 | 是否必须删除 | cnt |
|------|----------------|--------------|-----|
| 2 | $2 < 10$ | 是 | 1 |
| 11 | $11 \ge 10$ | 否 | 1 |
| 10 | $10 \ge 10$ | 否（等于也算达标） | 1 |
| 1 | $1 < 10$ | 是 | 2 |
| 3 | $3 < 10$ | 是 | 3 |

计数得 $3$，与按升序依次删除 $1, 2, 3$ 的三次操作完全对应。

## 4. 算法细节

1. **不要真的删除元素**：删除操作在数组上要移动内存，在堆上要维护结构，而本题只需要个数。识别出「答案就是计数」是本题唯一的门槛。
2. **比较符必须是 `<` 而不是 `<=`**：题目要求「大于或等于 $k$」，所以 $nums[i] = k$ 保留，只删严格小于 $k$ 的。
3. **计数上限是 $n - 1$**：由「保证至少有一个 $nums[i] \ge k$」，至少有一个元素留下，答案最多 $n - 1 = 49$。若题面没有这条保证，$k$ 大于所有元素时答案是无解的（删到最后只剩 1 个，无法再删），这也是该保证存在的意义。
4. **一遍遍历即可，无需排序**：排序只是把「模拟」变得直观，对计数没有帮助。若为了可读性写成「排序 + 找到第一个 $\ge k$ 的位置」，复杂度会从 $O(n)$ 涨到 $O(n \log n)$。
5. **整型范围**：$nums[i]$、$k$ 最大 $10^9$，比较本身不会溢出；答案最大 $50$，`int` 足够。不需要 `long long`。
6. **Python 的布尔求和**：`sum(x < k for x in nums)` 直接得到计数，因为 `bool` 是 `int` 的子类；写成 `sum(1 for x in nums if x < k)` 可读性更好。
7. **与 Q2 的关系**：这是同一故事的第一幕（只删不合并），Q2 把「删除」升级为「删除并合并」，从计数题变成堆模拟题。

## 5. 正确性证明

设数组长度为 $n$，记 $S = \{\,i \mid nums[i] < k\,\}$，$c = |S|$。

**引理 1（操作不改值）**：任意次操作后，未被删除的每个元素的值与初始值相同。

**证明**：对操作次数归纳。$0$ 次操作时显然。设第 $t$ 次操作前成立，第 $t$ 次操作删除当前最小元素、其余元素原封不动，故第 $t$ 次操作后未被删除的元素值仍与初始值相同。∎

**引理 2（$S$ 中的元素必须被删除）**：任一使所有元素 $\ge k$ 的操作序列，都必须删除 $S$ 中的每一个元素。

**证明**：任取 $i \in S$，若它最终仍在数组中，由引理 1 其值仍为 $nums[i] < k$，与「所有元素 $\ge k$」矛盾。∎

**引理 3（$c$ 次操作足够）**：前 $c$ 次操作恰好删除 $S$ 中的全部元素。

**证明**：把数组升序排列为 $a_1 \le a_2 \le \cdots \le a_n$。由于操作删除当前最小值，第 $t$ 次操作删除的正是 $a_t$（删除 $a_1, \dots, a_{t-1}$ 后最小值为 $a_t$），对 $t$ 归纳可证。又因为 $a_1, \dots, a_c$ 恰为 $S$ 中元素（升序排列的前 $c$ 个正是所有 $< k$ 的元素），故前 $c$ 次操作删完 $S$。此时数组中只剩初始值 $\ge k$ 的元素，由引理 1 全部仍 $\ge k$，目标达成。∎

**定理**：使所有元素 $\ge k$ 的最少操作次数等于 $c$。

**证明**：由引理 2，任何可行方案至少删除 $|S| = c$ 个元素，而一次操作只删一个元素，故操作次数 $\ge c$；由引理 3，$c$ 次操作可以达成目标，故操作次数 $\le c$。上下界相等，答案为 $c$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。只需一次线性扫描，每个元素做一次比较与至多一次自增；$n \le 50$，实际运行时间可忽略。
- **空间**：$O(1)$。只用一个计数器，不复制数组、不排序、不建堆。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int k) {
        int cnt = 0;
        for (int x : nums) {
            if (x < k) ++cnt;          // 小于 k 的元素必须被逐个删除
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int], k: int) -> int:
        return sum(1 for x in nums if x < k)   # 严格小于 k 的元素个数
```

> 💡 两份代码通过官方三个示例（`3`、`0`、`4`）以及 `[5], k = 5`（答案 `0`）、`[1], k = 10^9`（答案 `1`）等边界，并与「排序后逐个 `pop` 掉最小值、直到首个 $\ge k$」的真实删除模拟在 251 组随机数组（$n \le 12$，值域 $\le 20$，已过滤掉不满足「至少一个 $\ge k$」的用例）上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **全部元素已达标**：循环中一次自增都不发生，返回 `0`，不会进入任何删除分支。
2. **$k = 1$**：由 $nums[i] \ge 1$，必然全部达标，答案 `0`；这说明「$<$」的边界方向不能写反。
3. **相等不算超标**：$nums[i] = k$ 保留，判断必须是 `x < k`；写成 `x <= k` 会把恰好的元素也计入，答案偏大。
4. **答案上界 $n - 1$**：题目保证至少一个元素 $\ge k$；若没有这条保证，$k$ 大于全体元素时无解，暴力模拟删到只剩 1 个元素就会卡住（此时长度 1，无法继续删），这也是不能盲目写 `while` 的原因。
5. **不要用堆或排序**：本题 $O(n)$ 足够。用堆是把简单问题复杂化，且引入不必要的 $O(n \log n)$ 与代码风险。
6. **原地删除的副作用**：若真的用 `erase` 删元素，注意下标失效与 $O(n)$ 的搬移开销；计数方案完全避开了这类 bug。
7. **空数组**：约束保证 $n \ge 1$，无需特判；但若扩展到空数组，计数方案自然返回 `0`，仍然是合理语义。

**延伸思考**：本题的答案是「计数」，这依赖于「操作只删不改」。若把操作改成「任选一个元素加 1」，最优策略就变成每次给最小元素加 1（也让所有元素达标的最少次数等于把每个元素补到 $k$ 的总缺口）；若改成「一次操作可删除任意 $m$ 个最小元素」，答案变为 $\lceil c / m \rceil$；若删除还附带「其余元素整体减 1」之类的副作用，计数就不再成立，必须回到模拟或推导更细的结构。这类「先判断操作是否改变值 / 是否强制顺序」的读题习惯，是签到题最值得沉淀的部分。
