# LeetCode 超过阈值的最少操作数 II 题解

## 1. 题目概述

- **标题 / 题号**：超过阈值的最少操作数 II（#3066，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-exceed-threshold-value-ii/
- **来源**：LeetCode 第 125 场双周赛 Q2
- **难度**：中等
- **标签**：数组、模拟、堆（优先队列）

**题意**：给定数组 `nums` 与整数 `k`。一次操作中，你必须**选出 `nums` 中最小的两个整数 `x` 和 `y`**，把它们删除，并把 $min(x, y) \times 2 + \max(x, y)$ 加回数组。求使数组中所有元素都大于或等于 `k` 所需的**最少**操作次数。

**约束**：

- $2 \le nums.length \le 2 \times 10^5$
- $1 \le nums[i] \le 10^9$
- $1 \le k \le 10^9$
- 输入保证答案一定存在：经过若干次操作后数组所有元素都能 $\ge k$

**关键前提**：操作的对象是「**最小的两个**」，这是被题面写死的，**没有选择余地**。这一点决定了本题不需要任何贪心决策——它是一道**确定性模拟**题，「最少」二字只是描述「第一次达到目标时的步数」。

## 2. 示例

**示例 1**

```text
输入：nums = [2,11,10,1,3], k = 10
输出：2
解释：删除 1 与 2，加入 1*2+2 = 4，数组变 [4,11,10,3]；
      再删除 3 与 4，加入 3*2+4 = 10，数组变 [10,11,10]，全部 ≥ 10。
```

**示例 2**

```text
输入：nums = [1,1,2,4,9], k = 20
输出：4
解释：1,1 → 3；2,3 → 7；4,7 → 15；9,15 → 33。共 4 步。
```

**示例 3（边界补充，说明「合并顺序被强制」）**

```text
输入：nums = [1,2,10,10], k = 12
输出：3
解释：第一步只能合并 1 与 2（它们是最小的两个）得到 4；
      第二步合并 4 与 10 得到 18；第三步合并 10 与 18 得到 38。
      虽然把 1 和 10 直接合并（12）看起来更快，但题面不允许这样选。
```

## 3. 解题思路

### 3.1 暴力思路

「模拟」是唯一正确的方向，问题只在于用**什么结构**找出每次的两个最小值：

- 每轮线性扫描找最小两个值：单轮 $O(n)$，最多 $n - 1$ 轮，总 $O(n^2)$。$n = 2 \times 10^5$ 时是 $4 \times 10^{10}$ 次操作，必然超时。
- 排序 + 每轮插入回有序数组：单轮插入 $O(n)$，同样退化为 $O(n^2)$。
- **小根堆**：取两次堆顶、压入一次，单轮 $O(\log n)$，总 $O(n \log n)$，这是正解的数据结构选择。

除去结构选择，本题**没有算法设计空间**：最小两个元素是唯一确定的两个元素（有重复值时只是取了哪一份副本的差别，值相同，多重集合完全一样），因此合并结果、后续状态、直至步数全部唯一确定（见 §5）。

### 3.2 核心观察：操作被题面写死，答案 = 模拟步数

![核心观察：取两个最小值 a、b 合并成 2a+b 压回堆](images/bw125_q2_heap_merge.svg)

设当前最小的两个元素为 $a \le b$。题面规定的合并值是

$$f(a, b) = \min(a,b) \times 2 + \max(a,b) = 2a + b,$$

它同时满足两条性质：

1. $f(a,b) = a + b + \min(a,b) \ge \max(a,b)$：合并**不会**让数值变小，且严格大于两数中的较大者（因为 $a \ge 1$）。
2. $f$ 对两个参数分别单调不减：输入越大，输出越大。

由于「取最小两个」是强制规则，整个数组的演化是一条**唯一的状态链**：$V_0 \to V_1 \to V_2 \to \cdots$，其中 $V_{t+1}$ 由 $V_t$ 删掉最小两个、加回 $2a+b$ 得到。于是：

- 每步元素个数减 1，最多 $n - 1$ 步后数组长度为 1（此时若仍未达标，则无解，题面保证不会发生）；
- 答案是「首次满足全体 $\ge k$ 的步数」，也就是模拟到第一次全部达标为止的循环次数。

**为什么不叫贪心**：贪心意味着「在若干候选操作中选一个最优的」。本题候选只有一个（两个最小值是唯一确定的），所以正确性证明的核心是**确定性**而不是「贪心选择性质」，这也是本题比一般堆模拟题更容易被误解的地方。

### 3.3 算法流程

![算法流程：堆模拟直到堆顶 ≥ k](images/bw125_q2_flow.svg)

```text
1. 把 nums 全部入小根堆（C++ 可直接用 vector 构造）
2. ops ← 0
3. 当 堆大小 ≥ 2 且 堆顶 < k 时：
       a ← 弹出堆顶（当前最小值）
       b ← 弹出堆顶（当前次小值）
       压入 2a + b
       ops ← ops + 1
4. 返回 ops
```

循环结束的条件恰好是「堆顶 $\ge k$」——因为堆顶是最小值，堆顶达标就意味着全体达标；而堆大小 $< 2$ 时无法再操作。

### 3.4 示例演算

![示例演算：两个示例的合并过程](images/bw125_q2_example_walkthrough.svg)

**示例 1**（`nums = [1,2,3,10,11]` 排序后，`k = 10`）：

| 步 | 弹出 $a$ | 弹出 $b$ | 压入 $2a+b$ | 数组（排序后） | 全体 $\ge 10$？ |
|----|----------|----------|-------------|----------------|------------------|
| 1 | 1 | 2 | 4 | $[3,4,10,11]$ | 否 |
| 2 | 3 | 4 | 10 | $[10,10,11]$ | 是，停止 |

**示例 2**（`nums = [1,1,2,4,9]`，`k = 20`）：

| 步 | $a$ | $b$ | $2a+b$ | 数组（排序后） | 全体 $\ge 20$？ |
|----|-----|-----|--------|----------------|------------------|
| 1 | 1 | 1 | 3 | $[2,3,4,9]$ | 否 |
| 2 | 2 | 3 | 7 | $[4,7,9]$ | 否 |
| 3 | 4 | 7 | 15 | $[9,15]$ | 否 |
| 4 | 9 | 15 | 33 | $[33]$ | 是，停止 |

小元素被反复「喂」进合并里，像滚雪球一样被放大：$1 \to 3 \to 7 \to 15 \to 33$，四步就突破 $20$。

## 4. 算法细节

1. **数据类型必须是 `long long`**：单次合并值最大可达 $2 \times (10^9 - 1) + 10^9 \approx 3 \times 10^9$，超过 `int` 上限。例如 `[999999999, 1000000000, 1000000000], k = 1000000000`，一次合并得到 $2999999998$，用 `int` 会溢出成负数，从而把「已达标」误判为「未达标」，答案错误甚至死循环。
2. **堆的类型**：C++ 用 `priority_queue<long long, vector<long long>, greater<long long>>`（`greater` 让小根堆顶最小），构造时可以直接用 `nums` 的迭代器区间；Python 用 `heapq`，先 `heapify`（$O(n)$）而不是逐个 `heappush`（$O(n \log n)$）。
3. **循环条件写成 `size >= 2 && top < k`**：两个条件都不能省。漏掉 `size >= 2` 会在只剩一个元素时弹空堆（C++ 未定义行为，Python 抛异常）；漏掉 `top < k` 则会多做无意义的合并（合并只会减少元素个数、不会让它变小，但会浪费步数并使答案偏大）。
4. **`2a + b` 的顺序不能写反**：$a$ 是先弹出的最小值、$b$ 是次小值，所以要写 `2 * a + b`；写成 `2 * b + a` 在 $a \ne b$ 时结果偏大，示例 1 会算出 2 步以外的错误结果，且对拍很容易漏（若随机数据多为等值元素就看不出差别）。
5. **每步规模递减 1**：答案上界是 $n - 1$。这个性质也可用于提前判断「是否无解」——若循环因 `size < 2` 退出而堆顶仍 $< k$，说明该输入无解；题面保证不会出现，但代码里保留 `size >= 2` 的判断天然安全。
6. **合并结果插回哪里**：题面说「添加到数组中的任意位置」，而堆会自动维护有序性，所以「位置」信息无关紧要；这也说明题目关心的是**多重集合**而非下标顺序。
7. **相同元素的取舍**：当多个元素取值相同，先弹哪一个都不影响结果，因为多重集合相同；这也保证了「唯一状态链」的说法在实现层面成立。
8. **`nums` 被原地修改**：C++ 用区间构造不会改动 `nums`；Python `heapq.heapify(nums)` 会原地打乱输入，若在本地测试中需要复用，先 `nums = nums[:]` 复制一份。

## 5. 正确性证明

记初始多重集合为 $V_0$，第 $t$ 步后的多重集合为 $V_t$（按升序记作 $v^{(t)}_1 \le v^{(t)}_2 \le \cdots$）。

**引理 1（合并结果唯一且不减）**：对任意 $a \le b$（正整数），$f(a,b) = 2a + b$ 唯一确定，且 $f(a,b) > b \ge a$。

**证明**：$f$ 由 $a,b$ 唯一确定。又 $f(a,b) - b = 2a > 0$（因 $a \ge 1$），故 $f(a,b) > b$。∎

**引理 2（状态链唯一）**：对每个 $t$，$V_t$ 由 $V_{t-1}$ 唯一确定。

**证明**：$V_{t-1}$ 升序排列后，最小的两个元素是 $v^{(t-1)}_1$ 与 $v^{(t-1)}_2$，它们在多重集合意义下唯一（即使有并列值，取到的值也相同）。由题面规则，$V_t = V_{t-1} \setminus \{v_1, v_2\} \cup \{f(v_1, v_2)\}$，由引理 1 该结果唯一确定。对 $t$ 归纳即得。∎

**引理 3（模拟恰好等于合法执行序列）**：任何符合题面规则的操作序列，都是上述唯一状态链的前缀；且只要 $|V_t| \ge 2$ 且 $\min V_t < k$，第 $t+1$ 步操作就**必须**执行且唯一。

**证明**：由引理 2，每一步的输入状态与操作结果都被唯一确定，故任何合法序列都只能是 $V_0 \to V_1 \to \cdots$ 的前缀。当 $|V_t| \ge 2$ 时，题面允许且只允许对最小两个元素操作，故下一步必然把 $V_t$ 变为 $V_{t+1}$。∎

**定理**：算法返回的 `ops` 等于使所有元素 $\ge k$ 的最少操作次数。

**证明**：由引理 3，从 $V_0$ 出发的合法操作序列只有一条（唯一状态链），要达到「全体 $\ge k$」只能沿这条链走，故所需步数唯一，从而「最少」等于「首次达标时的步数」。

算法在每步后检查堆顶（最小值）是否 $\ge k$：堆顶 $\ge k$ 等价于全体 $\ge k$，此时立即停止并返回已执行步数 $t$，正是首次达标步数。若 $V_0$ 已全体 $\ge k$，循环不进入、返回 $0$，同样正确。又因为每步长度减 1，循环至多执行 $n - 1$ 次即终止（长度 $< 2$），故算法一定停机；题面保证答案存在，意味着终止前必然先达到全体 $\ge k$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。建堆 $O(n)$（C++ 区间构造、Python `heapify`）；每步两次弹出 + 一次压入，各 $O(\log n)$，最多 $n - 1$ 步，共 $O(n \log n)$。$n = 2 \times 10^5$ 时约 $2 \times 10^5 \times 18$ 次堆内比较，实测 C++ 约 $0.13$ 秒、Python 约 $0.12$ 秒。
- **空间**：$O(n)$。堆中元素个数从 $n$ 单调递减到 $1$，最多 $n$ 个 `long long`（Python 为 `int` 对象），即 $O(n)$；除此之外只有常数个辅助变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int k) {
        priority_queue<long long, vector<long long>, greater<long long>>
            pq(nums.begin(), nums.end());          // 小根堆，O(n) 建堆
        int ops = 0;
        while (pq.size() >= 2 && pq.top() < k) {   // 堆顶即最小值，未达标就继续
            long long a = pq.top(); pq.pop();      // 最小
            long long b = pq.top(); pq.pop();      // 次小
            pq.push(a * 2 + b);                    // min*2 + max
            ++ops;
        }
        return ops;
    }
};
```

### Python

```python
import heapq


class Solution:
    def minOperations(self, nums: list[int], k: int) -> int:
        heapq.heapify(nums)                        # 原地建小根堆，O(n)
        ops = 0
        while len(nums) >= 2 and nums[0] < k:      # nums[0] 是最小值
            a = heapq.heappop(nums)                # 最小
            b = heapq.heappop(nums)                # 次小
            heapq.heappush(nums, a * 2 + b)        # min*2 + max
            ops += 1
        return ops
```

> 💡 两份代码通过官方示例（`2`、`4`）、示例 3（`3`）、以及 `[999999999,1000000000,1000000000], k = 10^9`（答案 `1`，合并值 $2999999998$ 会溢出 `int`）、`[10**9], k = 1`（答案 `0`）等边界。堆实现与「排序 + `bisect.insort` 有序列表」的独立实现在 405 组随机数据（$n \le 40$，值域 $\le 30$）上对拍，`mismatch = 0`；$n = 2 \times 10^5$ 的极限数据 C++ 耗时 $0.13$ 秒。

## 8. 边界情况与易错点

1. **`int` 溢出**：合并值可达 $3 \times 10^9$，堆内元素必须用 `long long`。这是本题最容易 WA 的点，因为小数据完全看不出来。
2. **初值已全部达标**：如示例 `[1,4,9], k = 1`，循环不进入，返回 `0`。
3. **漏判 `size >= 2`**：只剩一个元素而它仍 $< k$ 时，若继续弹堆会访问空容器；即使题面保证有解，也建议保留该判断。
4. **把 `top < k` 写成 `top <= k`**：会让本已达标（恰好等于 $k$）的数组继续合并，步数偏大。目标条件是「大于或等于」。
5. **合并方向写反**：必须是「较小者的两倍加大者」。写反后小元素得不到放大，答案会偏大甚至无法达标。
6. **以为可以自由选元素**：题面限定「最小的两个」。若误以为可以任选两个，就会写出「先合并 1 和 10」这类非法方案，从而得出比正确解更小的错误答案（示例 3 就是这个陷阱的对照：正解 3 步，自由选元素只需 2 步）。
7. **`nums` 的副作用**：Python `heapify` 与 `heappop` 会原地修改传入列表；调用方若复用需先复制。
8. **死循环风险**：每步长度严格减 1，循环最多 $n - 1$ 次，不会死循环；但如果溢出成负数，`top < k` 会一直成立而长度持续减小，最终靠 `size >= 2` 退出并返回偏大的答案——所以溢出问题表现为「答案偏大」而不是「卡死」。
