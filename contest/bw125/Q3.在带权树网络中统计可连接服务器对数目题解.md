# LeetCode 在带权树网络中统计可连接服务器对数目 题解

## 1. 题目概述

- **标题 / 题号**：在带权树网络中统计可连接服务器对数目（#3067，medium）
- **链接**：https://leetcode.cn/problems/count-pairs-of-connectable-servers-in-a-weighted-tree-network/
- **来源**：LeetCode 第 125 场双周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、数组

**题意**：给定一棵 $n$ 个节点的无根带权树（节点即服务器，编号 $0 \sim n-1$），边以 `edges[i] = [a, b, weight]` 给出，再给定整数 `signalSpeed`。若两台服务器 $a, b$ 满足以下四条，则称它们**通过服务器 $c$ 可连接**：

1. $a < b$，且 $a \ne c$、$b \ne c$；
2. 从 $c$ 到 $a$ 的距离能被 `signalSpeed` 整除；
3. 从 $c$ 到 $b$ 的距离能被 `signalSpeed` 整除；
4. 从 $c$ 到 $b$ 的路径与从 $c$ 到 $a$ 的路径**没有任何公共边**。

返回长度 $n$ 的数组 `count`，其中 `count[i]` 表示通过服务器 $i$ 可连接的服务器对数目。

**约束**：

- $2 \le n \le 1000$
- $edges.length = n - 1$，$edges[i].length = 3$
- $0 \le a_i, b_i < n$，$1 \le weight_i \le 10^6$
- $1 \le signalSpeed \le 10^6$
- 输入保证 `edges` 构成一棵合法的树

## 2. 示例

**示例 1**

```text
输入：edges = [[0,1,1],[1,2,5],[2,3,13],[3,4,9],[4,5,2]], signalSpeed = 1
输出：[0,4,6,6,4,0]
解释：signalSpeed = 1 时所有距离都能整除，count[c] = c 左侧服务器数 × 右侧服务器数
      = c × (5 − c)，即 0, 4, 6, 6, 4, 0。
```

**示例 2**

```text
输入：edges = [[0,6,3],[6,5,3],[0,3,1],[3,2,7],[3,1,6],[3,4,2]], signalSpeed = 3
输出：[2,0,0,0,0,0,2]
解释：通过 0 可连接 (4,5)、(4,6)；通过 6 可连接 (4,5)、(0,5)；其余服务器为 0 对。
```

**示例 3（边界补充：$n = 2$）**

```text
输入：edges = [[0,1,3]], signalSpeed = 3
输出：[0,0]
解释：通过 0 只能用 1 这一个分支，凑不出「不同分支的两台」，故为 0；通过 1 同理。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：对每个中心 $c$、枚举所有无序对 $(a,b)$（$O(n^2)$ 对），再分别求 $c \to a$、$c \to b$ 的路径与距离。求路径若从 $c$ 做一次 DFS/BFS 记录父节点、回溯得到边集，单次 $O(n)$，总复杂度 $O(n^4)$（$n = 1000$ 时 $10^{12}$ 级别）。即便用 $c$ 出发的一次 DFS 预处理距离，判断「两条路径是否共享边」仍需 $O(n)$ 的路径比对，整体 $O(n^3) = 10^9$，仍然危险。

暴力的浪费在于：对固定的 $c$，几乎所有的 $a$ 都被反复检查「是否与 $b$ 共享边」。而这个条件其实有极其简单的等价形式（见 3.2），一旦转化，就只需**按分支计数再两两配对**，完全不必逐对检查。

### 3.2 核心观察：不同分支 $\iff$ 无公共边

![核心观察：按 c 的邻居划分分支，各分支内的计数两两配对](images/bw125_q3_branch_counting.svg)

从 $c$ 出发，把树「按 $c$ 的邻居」切成若干**分支**：删掉 $c$ 之后，每个邻居 $v$ 所在的连通块就是一个分支，记分支内满足「到 $c$ 的距离被 `signalSpeed` 整除」的节点数为 $cnt_v$。

**关键等价**：对 $a, b \ne c$，从 $c$ 到 $a$ 与从 $c$ 到 $b$ 的路径无公共边 $\iff$ $a, b$ 属于**不同分支**。

- 若属于同一分支：两条路径都要先从 $c$ 走到该分支的那个邻居，第一条边相同，共享边成立；
- 若属于不同分支：树中 $c$ 到任意节点的路径唯一，两条路径只在 $c$ 处相交（公共部分是顶点 $c$，不是边），故无公共边。

于是「通过 $c$ 可连接」的服务器对，就是「**不同分支**中各自被标记的节点」构成的配对。设分支计数为 $cnt_1, cnt_2, \dots, cnt_m$，则

$$count[c] = \sum_{1 \le i < j \le m} cnt_i \cdot cnt_j = \frac{1}{2}\left(S^2 - \sum_{i=1}^{m} cnt_i^2\right), \quad S = \sum_i cnt_i.$$

代码里更省事的写法是**增量式**：从左到右扫描分支，维护「已处理分支的计数和」`total`，每遇到新分支就把 `pairs += total * cnt` 累加，再 `total += cnt`。这恰好等于 $\sum_{i<j} cnt_i cnt_j$，且不需要存全部 $cnt_i$。

### 3.3 算法流程

![算法流程：对每个中心遍历各分支做 DFS 计数](images/bw125_q3_dfs_flow.svg)

```text
1. 由 edges 建无向邻接表 g[u] = [(v, w), ...]
2. 对每个中心 c ∈ [0, n)：
       pairs ← 0, total ← 0
       对 c 的每个邻居 (v, w)：               # 一个邻居 = 一个分支
           cnt ← 0
           以 (v, w) 为起点做 DFS，父节点为 c：
               若当前距离 d 能被 signalSpeed 整除：cnt ← cnt + 1
               继续走向所有非父邻居，距离累加边权
           pairs ← pairs + total * cnt         # 本分支与之前所有分支配对
           total ← total + cnt
       count[c] ← pairs
3. 返回 count
```

DFS 用「父节点」避免走回 $c$，因此天然只在当前分支内部搜索；距离沿路径累加，正是「$c$ 到该节点的距离」。

### 3.4 示例演算

![示例 2 的树结构与各分支计数](images/bw125_q3_example_tree.svg)

**示例 2**（`signalSpeed = 3`）的树形状：$0$ 连 $6$（权 3）与 $3$（权 1）；$6$ 连 $5$（权 3）；$3$ 连 $2$（权 7）、$1$（权 6）、$4$（权 2）。

以 $c = 0$ 为例，两个分支：

| 分支 | 分支内节点 | 到 $0$ 的距离 | 距离 $\bmod 3 = 0$ 的节点 | $cnt$ |
|------|------------|----------------|---------------------------|-------|
| 经 $6$ | 6, 5 | 3, 6 | 6（3）、5（6） | 2 |
| 经 $3$ | 3, 2, 1, 4 | 1, 8, 7, 3 | 4（3） | 1 |

`pairs` = $2 \times 1 = 2$，对应 $(4,5)$ 与 $(4,6)$。

以 $c = 6$ 为例：

| 分支 | 节点 | 到 $6$ 的距离 | 整除的节点 | $cnt$ |
|------|------|----------------|------------|-------|
| 经 $5$ | 5 | 3 | 5 | 1 |
| 经 $0$ | 0, 3, 2, 1, 4 | 3, 4, 11, 10, 6 | 0（3）、4（6） | 2 |

`pairs` = $1 \times 2 = 2$，对应 $(4,5)$ 与 $(0,5)$。

注意 $c = 6$ 的分支「经 $0$」里，节点 $0$ 与 $4$ 都达标却**不能**配对——它们共享边 $(0,3)$，这正是「必须跨分支」的意义；而节点 $3$ 距离为 $4$ 不整除 $3$，即使在同一分支也不计入。

其余节点（$1,2,3,4,5$）作为中心要么只有一个有效分支、要么分支计数为 $0$，故 `count` 为 $0$，最终得到 `[2,0,0,0,0,0,2]`。

## 4. 算法细节

1. **邻接表存双向边**：`g[u].push_back({v, w})` 与 `g[v].push_back({u, w})` 都要加；DFS 时用父节点 `p` 剪枝即可，不必删除边。
2. **按分支分别 DFS，而不是从 $c$ 做一次全局遍历**：全局遍历虽然也能算出距离，但还要额外记录「该节点属于哪个分支」；直接以每个邻居为入口做一次 DFS，分支信息天然由循环变量给出，代码更短也不易错。
3. **距离用 `long long`**：最坏路径长度约 $999 \times 10^6 \approx 10^9$，`int` 恰好不溢出但贴近上限；用 `long long` 避免任何边角溢出，代价可忽略。
4. **整除判断放在 DFS 内部**：每到一个节点就判断 `d % signalSpeed == 0` 并累加，无需把距离存进数组再二次遍历。
5. **组合计数的两种写法**：增量式 `pairs += total * cnt`（推荐，一遍扫描、无需额外数组）或闭式 $\frac{S^2 - \sum cnt_i^2}{2}$（需要先把 $cnt_i$ 收集起来）。两者数学等价，增量式不会出现除法精度问题。
6. **避免递归过深**：$n = 1000$，若树退化成链，递归深度可达 $1000$；C++ 默认栈通常够用（约 $10^4 \sim 10^5$ 层），但 Python 默认递归上限是 $1000$，链状输入会抛 `RecursionError`。因此 Python 版用**显式栈**迭代 DFS，C++ 版也可以用显式栈保持一致。
7. **答案范围**：最多 $\binom{1000}{2} \approx 5 \times 10^5$，`int` 足够；但中间乘积 `total * cnt` 也在 $10^6$ 以内，用 `long long` 只是保险。
8. **整体复杂度 $O(n^2)$**：$n$ 个中心，每个中心做一次覆盖全树的 DFS（$O(n)$）。$n = 1000$ 时约 $10^6$ 次访问，实测 C++ 约 $0.02$ 秒、Python 约 $0.2$ 秒。

## 5. 正确性证明

固定中心 $c$，记 $c$ 的邻居集合为 $N(c)$，对每个 $v \in N(c)$ 令 $B_v$ 为删去 $c$ 后 $v$ 所在连通块的节点集合（分支），并令 $cnt_v = |\{x \in B_v : dist(c,x) \bmod signalSpeed = 0\}|$。

**引理 1（分支划分）**：$\{B_v\}_{v \in N(c)}$ 构成 $V \setminus \{c\}$ 的一个划分。

**证明**：删去 $c$ 后，树的每个连通块恰含 $c$ 的一个邻居（否则两块之间无路径连回 $c$，与树连通矛盾），且每个 $v \in N(c)$ 的连通块非空（含 $v$）。故这些集合互不相交且并为 $V \setminus \{c\}$。∎

**引理 2（同分支 $\iff$ 有公共边）**：对 $a, b \ne c$，路径 $c \to a$ 与 $c \to b$ 无公共边当且仅当 $a, b$ 属于不同分支。

**证明**：
（$\Leftarrow$）设 $a \in B_{v_1}$、$b \in B_{v_2}$，$v_1 \ne v_2$。树中任意两点间路径唯一，故 $c \to a$ 的路径必以边 $(c, v_1)$ 起始（否则会经另一个邻居离开 $c$，从而进入别的分支，与 $a \in B_{v_1}$ 矛盾），同理 $c \to b$ 以 $(c, v_2)$ 起始。两条路径若还共享其他边，设共享边为 $e$，则在树 $-$ $c$ 中 $a$ 与 $b$ 通过 $e$ 连通，与 $a,b$ 分属不同连通块矛盾。故只共享顶点 $c$，无公共边。
（$\Rightarrow$）若 $a, b \in B_v$（同一分支），则两条路径都含边 $(c, v)$，共享该边，矛盾。∎

**引理 3（计数公式）**：通过 $c$ 可连接的服务器对数目等于 $\sum_{1 \le i < j \le m} cnt_i \, cnt_j$，其中 $m = |N(c)|$，且每对 $(a,b)$ 被恰好计一次。

**证明**：由引理 1、2，$(a,b)$ 满足题面四条当且仅当 $a \in B_{v_i}$、$b \in B_{v_j}$、$i \ne j$，且二者到 $c$ 的距离都整除 `signalSpeed`。对固定的有序分支对 $(i,j)$（$i<j$），这样的 $(a,b)$ 有 $cnt_i \cdot cnt_j$ 个；又分支对互不重叠，故总数为 $\sum_{i<j} cnt_i cnt_j$。由于 $a<b$ 的约束只是「无序对」的书写方式，$cnt_i cnt_j$ 计的是无序对（一个来自 $B_i$、一个来自 $B_j$），不会重复。∎

**引理 4（增量式与公式一致）**：算法中维护 `total` $= \sum_{k < i} cnt_k$ 时执行的 `pairs += total * cnt_i`，累加结果等于 $\sum_{i<j} cnt_i cnt_j$。

**证明**：第 $i$ 步累加的是 $cnt_i \sum_{k<i} cnt_k = \sum_{k<i} cnt_k cnt_i$，对所有 $i$ 求和即得所有下标对 $k < i$ 的乘积之和。∎

**定理**：算法输出的 `count[i]` 等于通过服务器 $i$ 可连接的服务器对数目。

**证明**：对每个中心 $c$，DFS 正确枚举了分支 $B_v$ 内的全部节点并沿树路径累加距离（由 $c$ 到任意节点路径唯一、DFS 沿父子关系遍历整棵子树可知），故 $cnt_v$ 计算正确；由引理 3、4 组合计数正确。对全部 $c$ 成立，故输出数组正确。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。外层 $n$ 个中心；对每个中心，各分支的 DFS 合起来恰好访问除 $c$ 外的每个节点一次（由引理 1 的划分），即 $O(n)$；组合计数 $O(\deg(c))$。总计 $O(n^2)$，$n = 1000$ 时约 $10^6$ 次节点访问。
- **空间**：$O(n)$。邻接表存 $2(n-1)$ 条边；DFS 的显式栈或递归深度不超过树高 $O(n)$；`count` 数组 $O(n)$。不含递归调用栈的隐式开销时为 $O(n)$，含则为 $O(n)$ 量级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> countPairsOfConnectableServers(vector<vector<int>>& edges, int signalSpeed) {
        int n = edges.size() + 1;
        vector<vector<pair<int, int>>> g(n);
        for (auto& e : edges) {
            g[e[0]].push_back({e[1], e[2]});
            g[e[1]].push_back({e[0], e[2]});
        }
        vector<int> ans(n, 0);
        for (int c = 0; c < n; ++c) {
            long long total = 0, pairs = 0;
            for (auto& [v, w] : g[c]) {                  // 每个邻居是一个分支
                long long cnt = 0;
                function<void(int, int, long long)> dfs = [&](int u, int p, long long d) {
                    if (d % signalSpeed == 0) ++cnt;
                    for (auto& [nxt, w2] : g[u])
                        if (nxt != p) dfs(nxt, u, d + w2);
                };
                dfs(v, c, w);
                pairs += total * cnt;                    // 与之前所有分支两两配对
                total += cnt;
            }
            ans[c] = (int)pairs;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countPairsOfConnectableServers(self, edges: list[list[int]], signalSpeed: int) -> list[int]:
        n = len(edges) + 1
        g = [[] for _ in range(n)]
        for u, v, w in edges:
            g[u].append((v, w))
            g[v].append((u, w))
        ans = [0] * n
        for c in range(n):
            total = pairs = 0
            for v, w in g[c]:                     # 每个邻居对应一个分支
                cnt = 0
                stack = [(v, c, w)]               # 显式栈，避免递归过深
                while stack:
                    u, p, d = stack.pop()
                    if d % signalSpeed == 0:
                        cnt += 1
                    for nxt, w2 in g[u]:
                        if nxt != p:
                            stack.append((nxt, u, d + w2))
                pairs += total * cnt              # 与先前分支两两配对
                total += cnt
            ans[c] = pairs
        return ans
```

> 💡 两份代码通过官方示例（`[0,4,6,6,4,0]`、`[2,0,0,0,0,0,2]`）、$n = 2$ 边界，以及与「枚举所有 $(a,b)$、显式取出两条路径的边集并求交集判共享」的定义级暴力在 200 组随机树（$n \le 8$，权值 $\le 9$，`signalSpeed` $\le 4$）上对拍，`mismatch = 0`；$n = 1000$ 的链状树 C++ 耗时 $0.02$ 秒、Python $0.2$ 秒。

## 8. 边界情况与易错点

1. **$n = 2$**：每个中心只有一个分支，`pairs += total * cnt` 中 `total` 恒为 $0$，结果必为 `[0,0]`。不要误以为「两个节点距离整除就能配对」——它们在同一分支，路径共享那条边。
2. **同一分支内不能配对**：示例 2 中 $c=6$ 时节点 $0$ 与 $4$ 都达标却不可配对，是本题最典型的错点。凡是「直接数全树达标节点、再算 $\binom{S}{2}$」的写法都会错。
3. **必须排除 $a = c$ 或 $b = c$**：$c$ 自身到 $c$ 的距离为 $0$，$0$ 能被任何 `signalSpeed` 整除，若把 $c$ 计入会凭空多出配对。按分支 DFS 天然不含 $c$，这正是不从 $c$ 开始 DFS 的原因之一。
4. **距离从边权起算**：DFS 第一层的距离是邻居边的权重 $w$，不是 $1$，也不是 $0$。漏加首条边权是最常见的实现 bug。
5. **Python 递归深度**：默认上限 $1000$，链状树会触发 `RecursionError`，必须用显式栈（或 `sys.setrecursionlimit`，但显式栈更稳）。
6. **整除用 `%` 而非浮点除法**：距离是整数，`d % signalSpeed == 0` 精确；用除法再判断「是否为整数」在浮点下可能误判。
7. **`total` 与 `pairs` 要用 64 位**：`total * cnt` 最大约 $10^6$，`int` 尚可，但结果累加上界 $\binom{1000}{2}$ 接近 $5\times 10^5$，仍建议用 `long long` 统一处理，避免在不同约束下溢出。
8. **无向边重复遍历**：只靠父指针剪枝即可；若忘记传父节点，会在两个相邻节点间来回弹跳导致死循环。

**延伸思考**：本题对每个中心都重新做了一次 DFS，$O(n^2)$ 在 $n \le 1000$ 下足够。若把 $n$ 放大到 $10^5$，就需要换根思想：先以 $0$ 为根预处理每个节点到根的距离，再用「点分治」或「按距离模 `signalSpeed` 分类的换根 DP」把每个中心的答案在 $O(1)$ 或 $O(\deg)$ 内更新。另一个自然变体是把「距离整除」换成「距离 $\le D$」，此时分支计数需要按深度截断，配合长链剖分/DSU on tree 也能做到近线性——本质都是「对每个中心汇总各分支的计数」，只是汇总的手段从暴力扫描升级成了数据结构。
