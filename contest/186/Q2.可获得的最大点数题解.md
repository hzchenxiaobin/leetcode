# LeetCode 可获得的最大点数 题解

## 1. 题目概述

- **标题 / 题号**：可获得的最大点数（#1423，medium）
- **链接**：https://leetcode.cn/problems/maximum-points-you-can-obtain-from-cards/
- **来源**：LeetCode 第 186 场周赛 Q2
- **难度**：中等
- **标签**：数组、滑动窗口、前缀和

**题意**：$n$ 张卡牌排成一行，第 $i$ 张点数为 $\text{cardPoints}[i]$。每次行动从行的**开头**或**末尾**拿一张牌，**恰好拿 $k$ 张**，得分为手中所有牌的点数之和。求可获得的最大得分。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{cardPoints}[i] \le 10^4$
- $1 \le k \le n$

## 2. 示例

**示例 1**

```text
输入：cardPoints = [1,2,3,4,5,6,1], k = 3
输出：12
解释：先拿最右边的 1，再拿 6，再拿 5，1 + 6 + 5 = 12。
```

**示例 2**

```text
输入：cardPoints = [1,79,80,1,1,1,200,1], k = 3
输出：202
解释：从两端拿 {1, 200, 1}；中间的 79 和 80 无论怎么拿都够不到。
```

**示例 3**

```text
输入：cardPoints = [9,7,7,9,7,7,9], k = 7
输出：55
解释：k = n，所有牌都必须拿走，答案即总和。
```

**示例 4**

```text
输入：cardPoints = [1,1000,1], k = 1
输出：1
解释：两端各是 1，中间的 1000 永远拿不到。
```

## 3. 解题思路

### 3.1 暴力思路：两种"第一反应"都会翻车

看到"从两端取数"，赛时最容易被两种直觉带偏：

- **区间 DP**：设 $f(l, r)$ 表示只剩区间 $[l, r]$ 未动时的最优得分——状态数 $O(n^2)$，$n \le 10^5$ 时光状态就有 $10^{10}$ 个，直接出局。区间 DP 是"双方轮流取"博弈题的套路，不适合"单方取定 $k$ 张"。
- **贪心**（每步拿两端较大者）：反例 $\text{cardPoints} = [2,10,1,3]$，$k = 2$：贪心先拿右端 3（$3 > 2$），之后两端只剩 2 与 1，共得 5；而先拿左端 2 暴露出 10，得 $2 + 10 = 12$。当前选择会改变后续暴露出的牌，局部最优不保全局。

**能过的暴力**：枚举左端拿 $a$ 张（$0 \le a \le k$），右端必拿 $k - a$ 张，用前缀和 $O(1)$ 算每种分配的得分，$O(n)$ 预处理 + $O(k)$ 枚举即可通过。但这仍停留在"正面枚举拿走的形态"；换成看**留下的牌**，可以少建数组、把空间压到 $O(1)$，还能顺手看清问题的连续结构。

### 3.2 核心观察：取两端 $k$ 张 ⇔ 中间留下长 $n-k$ 的连续窗口

![核心观察：取两端共 k 张 ⇔ 中间留下长度 n−k 的连续窗口](images/wc186_q2_complement_window.svg)

拿走的牌只可能来自两端：左端前缀 $[0, a)$ 加右端后缀 $[n-b, n)$，且 $a + b = k$。于是**没被拿走的牌恰好是中间一段连续子数组 $[a, n-b)$**，长度

$$n - b - a = n - k$$

**与分配方案无关、恒为 $n - k$**，变的只是起点。记总和为 $\text{total}$、留下窗口的和为 $W$，则拿走之和 $= \text{total} - W$。$\text{total}$ 是常数，所以

**最大化拿走之和 ⟺ 最小化长度为 $n-k$ 的连续子数组的和**

> 💡 这是"**正难则反**"的招牌转化：正面问"两端各拿几张"，反面只需问"中间那个定长窗口的和最小能压到多少"。转化后问题退化为标准的**定长滑动窗口求最小和**。

### 3.3 算法流程：定长滑动窗口

![算法流程：定长滑动窗口求最小窗口和](images/wc186_q2_slide_flow.svg)

1. **预处理**：求 $\text{total}$，令 $m = n - k$（窗口长度）。
2. **特判**：$m = 0$（即 $k = n$）时一张不剩，直接返回 $\text{total}$。
3. **初始化**：$\text{winSum} = c_0 + c_1 + \cdots + c_{m-1}$，$\text{minSum} = \text{winSum}$（即起点 $a = 0$ 的窗口）。
4. **滑动**：窗口右端 $i$ 从 $m$ 到 $n-1$，每步右移一格，$O(1)$ 增量更新：

   $$\text{winSum} \mathrel{+}= c_i - c_{i-m}, \qquad \text{minSum} = \min(\text{minSum}, \text{winSum})$$

5. **返回** $\text{total} - \text{minSum}$。

窗口起点从 $0$ 滑到 $k$，恰好 $k+1$ 个候选位置，与"左端拿 $a$ 张"的 $a \in [0, k]$ 一一对应，不重不漏。

> 💡 **对偶写法（换边法）**：先假设拿走最左 $k$ 张，得 $\text{sum} = c_0 + \cdots + c_{k-1}$；然后第 $i$ 轮（$i = 1, \dots, k$）把左端退回一张、右端补进一张：$\text{sum} \mathrel{+}= c_{n-i} - c_{k-i}$。第 $i$ 轮后 $\text{sum} = \text{pre}[k-i] + \text{suf}[i]$，与滑窗法严格对偶——一个枚举"留下的窗口"，一个枚举"拿走的两段"。

### 3.4 示例演算

![示例演算：窗口从左到右滑动的 4 个位置](images/wc186_q2_walkthrough.svg)

以 $\text{cardPoints} = [1,2,3,4,5,6,1]$，$k = 3$ 为例：$n = 7$，$m = 4$，$\text{total} = 22$。

| 起点 $a$ | 留下窗口 | $W(a)$ | 拿走 $= 22 - W(a)$ | 增量更新 |
|------|----------|--------|-------------------|----------|
| 0 | `[1,2,3,4]` | 10 | 12 | 初始求和 |
| 1 | `[2,3,4,5]` | 14 | 8 | $+5-1$ |
| 2 | `[3,4,5,6]` | 18 | 4 | $+6-2$ |
| 3 | `[4,5,6,1]` | 16 | 6 | $+1-3$ |

$\text{minSum} = 10$，答案 $= 22 - 10 = 12$，对应"左端不拿、右端拿 $\{5,6,1\}$"。✓

## 4. 算法细节

1. **三个量**：$\text{total}$（总和）、$m = n - k$（窗口长）、$\text{minSum}$（最小窗口和）。全程只需常数个变量，**无需前缀和数组**。
2. **$m = 0$ 特判**：$k = n$ 时窗口长为 0。若不特判，C++ 中 $c_{i-0}$ 会减去自身使 $\text{winSum}$ 恒为初始值，属于隐蔽的逻辑错误；直接返回 $\text{total}$。
3. **增量更新**：窗口 $[l, r)$ 右移到 $[l+1, r+1)$，和的变化恰为"进 $c_r$ 出 $c_l$"，即 $\text{winSum} \mathrel{+}= c_i - c_{i-m}$，单步 $O(1)$。
4. **滑动次数**：循环 $i \in [m, n-1]$ 共 $k$ 次，加上初值共 $k+1$ 个窗口，覆盖 $a \in [0, k]$ 的全部分配。少滑一步会漏掉"全部从右端拿"的极端方案。
5. **换边法**：初始 $\text{sum}$ 取前 $k$ 项，第 $i$ 轮 $\text{sum} \mathrel{+}= c_{n-i} - c_{k-i}$，此后 $\text{sum} = \text{pre}[k-i] + \text{suf}[i]$。它只触碰**前 $k$ 张与后 $k$ 张**共 $2k$ 个元素，时间 $O(k)$、与 $n$ 无关；$k = n$ 时每轮加减的是同一张牌，$\text{sum}$ 恒为 $\text{total}$，**天然正确、无需特判**。当 $k \ll n$ 时优于滑窗法的 $O(n)$。
6. **数值范围**：$\text{total} \le 10^5 \times 10^4 = 10^9$，恰好塞进 `int`（上限约 $2.1 \times 10^9$）但已贴边；若题面范围放大，应换 `long long`。

## 5. 正确性证明

**引理 1（结构引理）**：任意拿满 $k$ 张的合法方案，其拿走集合必为"前缀 $[0, a)$ + 后缀 $[n-b, n)$"且 $a + b = k$；反之任意 $a, b \ge 0$、$a + b = k$ 的分配都可实现。得分只与拿走集合有关，与拿牌顺序无关。

**证明**：对步数 $t$ 归纳：$t = 0$ 时拿走的是空前缀与空后缀。设 $t$ 步后拿走的前缀长 $p$、后缀长 $s$（$p + s = t$），则未被触碰的连续段为 $[p, n-s)$，第 $t+1$ 步只能拿其左端 $c_p$（使 $p \to p+1$）或右端 $c_{n-s-1}$（使 $s \to s+1$），"前缀 + 后缀"形态保持不变。故 $k$ 步后 $a + b = k$。可实现性：先拿左端 $a$ 张、再拿右端 $b$ 张即可。得分为拿走元素之和，与顺序无关。∎

**引理 2（补集转化）**：最优得分 $= \text{total} - \min_{0 \le a \le k} W(a)$，其中 $m = n - k$，$W(a) = \sum_{i=a}^{a+m-1} c_i$。

**证明**：由引理 1，合法方案与 $a \in [0, k]$ 一一对应（$b = k - a$），此时留下的连续段为 $[a, n-b) = [a, a+m)$，长度恒为 $m$，其和即 $W(a)$；拿走之和 $= \text{total} - W(a)$。$\text{total}$ 与 $a$ 无关，故最大化拿走之和等价于最小化 $W(a)$，且 $a$ 的可行域恰为 $[0, k]$。∎

**引理 3（覆盖与增量不变式）**：设 $m \ge 1$。算法中作为 $\text{minSum}$ 候选的值恰好为 $W(0), W(1), \dots, W(k)$，且每次滑动后 $\text{winSum}$ 恒等于当前窗口之和。

**证明**：初始窗口 $[0, m)$ 的和为 $W(0)$。循环变量 $i$ 依次取 $m, m+1, \dots, n-1$（共 $k$ 次），第 $i$ 次滑动后窗口为 $[i-m+1, i+1)$，起点 $i-m+1$ 依次取 $1, 2, \dots, n-m = k$，故候选值恰为 $W(1), \dots, W(k)$，与初值合并即全部 $k+1$ 个。窗口 $[l, r)$ 变为 $[l+1, r+1)$ 时和变化 $c_r - c_l$，即代码中的 $c_i - c_{i-m}$，不变式归纳保持。∎

**定理**：算法返回最大得分。

**证明**：$m = 0$ 时由引理 1，唯一方案是拿走全部，返回 $\text{total}$ 正确。$m \ge 1$ 时，由引理 3，$\text{minSum} = \min_{0 \le a \le k} W(a)$；由引理 2，最大得分 $= \text{total} - \text{minSum}$，即返回值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。求 $\text{total}$ 扫一遍 $O(n)$，首窗口求和 $O(m)$，滑动 $k$ 次每次 $O(1)$ 增量，合计 $O(n + m + k) = O(n)$。
- **空间复杂度**：$O(1)$。仅 $\text{total}$、$\text{winSum}$、$\text{minSum}$ 等常数个变量，不建前缀和数组。
- **换边法**：时间 $O(k)$（只读前 $k$ 张与后 $k$ 张）、空间 $O(1)$；当 $k \ll n$ 时优于滑窗法的 $O(n)$，赛时可按数据形态二选一。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxScore(vector<int>& cardPoints, int k) {
        int n = cardPoints.size();
        int total = accumulate(cardPoints.begin(), cardPoints.end(), 0);
        int m = n - k;
        if (m == 0) return total;                      // k == n：全部拿走
        int winSum = accumulate(cardPoints.begin(), cardPoints.begin() + m, 0);
        int minSum = winSum;                           // 起点 a = 0 的窗口
        for (int i = m; i < n; ++i) {
            winSum += cardPoints[i] - cardPoints[i - m];
            minSum = min(minSum, winSum);
        }
        return total - minSum;
    }
};
```

**变体：换边法（对偶实现，天然覆盖 $k = n$，时间 $O(k)$）**

```cpp
class Solution {
public:
    int maxScore(vector<int>& cardPoints, int k) {
        int n = cardPoints.size();
        int sum = accumulate(cardPoints.begin(), cardPoints.begin() + k, 0);
        int ans = sum;                                 // 左端 k 张、右端 0 张
        for (int i = 1; i <= k; ++i) {                 // 第 i 轮：左端退 1 张、右端补 1 张
            sum += cardPoints[n - i] - cardPoints[k - i];
            ans = max(ans, sum);                       // 此后 sum = pre[k-i] + suf[i]
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxScore(self, cardPoints: List[int], k: int) -> int:
        n = len(cardPoints)
        total = sum(cardPoints)
        m = n - k
        if m == 0:
            return total
        win_sum = sum(cardPoints[:m])
        min_sum = win_sum
        for i in range(m, n):
            win_sum += cardPoints[i] - cardPoints[i - m]
            min_sum = min(min_sum, win_sum)
        return total - min_sum
```

## 8. 边界情况与易错点

1. **k = n 必须特判（滑窗法）**：$m = 0$ 时 C++ 里 `cardPoints[i - 0]` 减去自身、首窗口求和 `accumulate(begin, begin + 0)` 得 0，都是隐蔽的逻辑错误；正确行为是返回 $\text{total}$（示例 3）。换边法则天然正确、无需特判。
2. **不要贪心**："每步拿两端较大者"在 $[2,10,1,3]$、$k=2$ 上只得 5，正确答案是 12；贪心破坏的原因是当前选择改变了后续暴露的牌。
3. **minSum 初值必须是首窗口和**：若初始化为 0，全正数据下恒有 $0 < W(a)$，最终答案会错算成 $\text{total}$。
4. **滑动终点含 n−1**：共 $k$ 步。反例 $[9,9,1,1]$、$k=2$：最优解 18 恰好对应最后一个窗口（留下 $[1,1]$），漏滑最后一步只会得到 10。
5. **int 贴边**：$\text{total} \le 10^9$，在 32 位有符号整数内但已接近上限；赛时若题目加强数据范围，果断换 `long long`。
6. **顺序无关**：得分只依赖最终拿走的集合，不需要（也不应该）模拟拿牌过程；同理区间 DP 在本题既不可行也无必要。
