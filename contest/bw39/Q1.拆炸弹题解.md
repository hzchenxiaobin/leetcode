# LeetCode 拆炸弹 题解

## 1. 题目概述

- **标题 / 题号**：拆炸弹（#1652，easy）
- **链接**：https://leetcode.cn/problems/defuse-the-bomb/
- **来源**：LeetCode 第 39 场双周赛 Q1
- **难度**：简单
- **标签**：数组、滑动窗口

**题意**：给定一个长度为 $n$ 的**循环**数组 `code` 与整数密钥 $k$，需要**同时**把每个数字替换掉：当 $k > 0$ 时第 $i$ 个数字替换为其**右侧**（循环意义下）连续 $k$ 个数字之和；当 $k < 0$ 时替换为其**左侧**连续 $|k|$ 个数字之和；当 $k = 0$ 时全部替换为 $0$。返回替换后的数组。

**约束**：

- $n = code.length$，$1 \le n \le 100$
- $1 \le code[i] \le 100$
- $-(n-1) \le k \le n-1$（$|k|$ 严格小于 $n$，窗口不会与自己重叠）

## 2. 示例

**示例 1**

```text
输入：code = [5,7,1,4], k = 3
输出：[12,10,16,13]
解释：res[0] = 7+1+4 = 12，res[1] = 1+4+5 = 10（绕回到 code[0]），
      res[2] = 4+5+7 = 16，res[3] = 5+7+1 = 13。
```

**示例 2**

```text
输入：code = [1,2,3,4], k = 0
输出：[0,0,0,0]
解释：k 为 0 时所有数字都替换为 0。
```

**示例 3**

```text
输入：code = [2,4,9,3], k = -2
输出：[12,5,6,13]
解释：res[0] = code[2]+code[3] = 9+3 = 12，res[1] = code[3]+code[0] = 3+2 = 5，
      res[2] = code[0]+code[1] = 2+4 = 6，res[3] = code[1]+code[2] = 4+9 = 13。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i$ 从零开始累加 $|k|$ 个数，下标全程对 $n$ 取模。总时间 $O(n|k|) \le O(n^2) = 10^4$，在本题 $n \le 100$ 的规模下完全够用，是最快写完的赛场路径。但它没有利用「相邻输出窗口高度重叠」这一结构：$res[i]$ 与 $res[i+1]$ 的窗口只差「进来一个数、出去一个数」，于是有下面的 $O(n)$ 做法。

### 3.2 核心观察：循环数组上的定长滑动窗口

![核心观察：循环数组摊平两遍后窗口和滚动](images/bw39_q1_circular_window.svg)

把 `code` 想象成首尾相接的环，或者等价地**在右边再摊平一份**。那么：

- $k > 0$ 时，$res[i] = \sum_{j=i+1}^{i+k} code[j \bmod n]$，是一个长度为 $k$、起点为 $i+1$ 的窗口；
- $k < 0$ 时，$res[i] = \sum_{j=i-|k|}^{i-1} code[(j+n) \bmod n]$，是一个长度为 $|k|$、终点为 $i-1$ 的窗口。

窗口从 $i$ 滑到 $i+1$ 时，只有一个元素进入、一个元素离开：

$$res[i+1] = res[i] + code[(i+k+1) \bmod n] - code[(i+1) \bmod n] \quad (k>0)$$

$$res[i+1] = res[i] + code[i \bmod n] - code[(i-|k|) \bmod n] \quad (k<0)$$

$O(1)$ 滚动，整体 $O(n)$。

### 3.3 算法流程

1. 特判 $k = 0$：直接返回全 $0$ 数组。
2. 记 $kk = |k|$，先计算 $res[0]$ 的初始窗口和：
   - $k > 0$：$\sum_{j=1}^{kk} code[j \bmod n]$；
   - $k < 0$：$\sum_{j=n-kk}^{n-1} code[j]$。
3. 对 $i = 0, 1, \dots, n-1$ 依滚动公式更新：写入 $res[i]$ 后，把窗口右移一位（加进、减出），所有下标对 $n$ 取模。
4. 返回 $res$。

### 3.4 示例演算

![示例演算：k 为负时左侧窗口的逐位计算](images/bw39_q1_slide_walkthrough.svg)

以示例 3（$code = [2,4,9,3]$，$k=-2$）为例：初始窗口是 $code[2]+code[3]=12$；滑到 $i=1$ 时加入 $code[3]$、减去 $code[2]$ 得 $5$；再滑加入 $code[0]$、减去 $code[3]$ 得 $6$；最后加入 $code[1]$、减去 $code[0]$ 得 $13$。全程四次取模加法，无任何特判分支。

## 4. 算法细节

1. **取模统一处理环绕**：$(i+kk+1) \bmod n$、$(i+n-kk) \bmod n$ 这类写法保证下标落在 $[0, n)$；由于 $|k| \le n-1 < n$，加 $n$ 一次足以把负下标拉回正数。
2. **初始窗口的对齐**：$k>0$ 的窗口从下标 $1$ 开始；$k<0$ 的窗口从下标 $n-kk$ 开始（即 $i=0$ 左侧最近的 $kk$ 个）。两种情况分开初始化，避免在循环里做方向判断。
3. **k = 0 必须最先特判**：否则 $kk=0$ 会构造出「空窗口」，滚动公式虽然数学上仍给 0，但初始求和循环写法容易踩到 $[n-0, n-1]$ 这类空区间边界，特判最稳。
4. **溢出**：$n \le 100$、$code[i] \le 100$、$|k| \le 99$，窗口和至多 $9900$，`int` 毫无压力。
5. **顺带一提**：如果不想写滚动，也可以用「前缀和数组加倍」的写法——把 `code` 复制两遍求前缀和，$res[i] = P[i+kk] - P[i]$（$k>0$）或 $P[i+n] - P[i+n-kk]$（$k<0$），思路等价，代码量差不多。

## 5. 正确性证明

**引理 1（窗口表达式）**：对任意 $i$ 与 $1 \le kk \le n-1$，循环数组中「$i$ 右侧连续 $kk$ 个元素」恰为 $code[(i+1) \bmod n], \dots, code[(i+kk) \bmod n]$；「左侧连续 $kk$ 个元素」恰为 $code[(i-kk) \bmod n], \dots, code[(i-1) \bmod n]$。

**证明**：循环数组的下标集合按 $+1 \bmod n$ 构成置换环。从 $i$ 出发向右走 $t$ 步到达 $(i+t) \bmod n$，因为 $1 \le t \le kk \le n-1$，这 $kk$ 个下标两两不同（若 $(i+t_1) \bmod n = (i+t_2) \bmod n$ 且 $t_1 \ne t_2$，则 $n \mid |t_1 - t_2|$，但 $0 < |t_1-t_2| \le n-1$，矛盾），且都不是 $i$ 本身，故恰为右侧 $kk$ 个位置。左侧同理用 $-t$ 步与 $(i-t+n) \bmod n$ 验证。∎

**引理 2（滚动公式）**：记 $W_i = \sum_{t=1}^{kk} code[(i+t) \bmod n]$（$k>0$ 情形），则 $W_{i+1} - W_i = code[(i+kk+1) \bmod n] - code[(i+1) \bmod n]$。

**证明**：$W_{i+1}$ 的项集为 $\{code[(i+1+t) \bmod n] : 1 \le t \le kk\}$，与 $W_i$ 的项集 $\{code[(i+t) \bmod n] : 1 \le t \le kk\}$ 相比，公共项为 $t = 2..kk$ 对应的 $kk-1$ 个（两集合均为环上连续段，平移一位后恰差首尾），故差值只剩进入的 $code[(i+kk+1) \bmod n]$ 与离开的 $code[(i+1) \bmod n]$。$k<0$ 情形将「左侧窗口」改写为 $W_i = \sum_{t=1}^{kk} code[(i-t+n) \bmod n]$，同法平移一位相减得 $W_{i+1} - W_i = code[i \bmod n] - code[(i-kk+n) \bmod n]$。∎

**定理**：上述算法输出的数组与「按题意逐位置替换」的结果完全一致。

**证明**：对 $i$ 归纳。初始时由引理 1，$W_0$ 恰为 $i=0$ 的替换值（$k>0$ 取右侧、$k<0$ 取左侧，两种初始化各自对应）；设 $res[i] = W_i$ 正确，则由引理 2 的滚动公式算出的 $res[i+1] = W_{i+1}$ 亦正确。又 $k=0$ 时题意即全 $0$，算法特判返回全 $0$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。初始化窗口 $O(|k|)$，随后 $n-1$ 次 $O(1)$ 滚动；$|k| \le n-1$，总计线性。（暴力为 $O(n|k|)$，在本题规模下同样可过。）
- **空间**：$O(n)$，即输出数组本身；不计输出则 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> decrypt(vector<int>& code, int k) {
        int n = code.size();
        vector<int> res(n, 0);
        if (k == 0) return res;                 // 全 0，直接返回
        int kk = abs(k);
        long long sum = 0;
        if (k > 0) {
            for (int j = 1; j <= kk; ++j) sum += code[j % n];      // res[0] 的右窗口
        } else {
            for (int j = n - kk; j < n; ++j) sum += code[j];       // res[0] 的左窗口
        }
        for (int i = 0; i < n; ++i) {
            res[i] = (int)sum;
            if (k > 0) {
                sum += code[(i + kk + 1) % n] - code[(i + 1) % n];
            } else {
                sum += code[i % n] - code[(i + n - kk) % n];
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def decrypt(self, code: list[int], k: int) -> list[int]:
        n = len(code)
        res = [0] * n
        if k == 0:
            return res
        kk = abs(k)
        if k > 0:
            s = sum(code[j % n] for j in range(1, kk + 1))   # res[0] 的右窗口
        else:
            s = sum(code[j] for j in range(n - kk, n))        # res[0] 的左窗口
        for i in range(n):
            res[i] = s
            if k > 0:
                s += code[(i + kk + 1) % n] - code[(i + 1) % n]
            else:
                s += code[i % n] - code[(i + n - kk) % n]
        return res
```

> 💡 两份代码均通过官方三个示例，并与「逐位取模暴力求和」在 3000 组随机数据（$n \le 12$，$k \in [-(n-1), n-1]$）下对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$k = 0$ 忘记特判**：不特判时 $kk = 0$，初始窗口为空，某些写法（如 `range(n - kk, n)` 恰好不空而窗口逻辑错乱）会输出垃圾值；先判 $k=0$ 一了百了。
2. **负下标取模**：C++ 的 `%` 对负数保留符号，$(i - kk)$ 必须写成 $(i + n - kk) \% n$ 或先加 $n$；Python 的 `%` 恒非负可直接用，但两份代码统一写法更不易错。
3. **$k = \pm(n-1)$ 的最大窗口**：窗口长度 $n-1$，正好差一个覆盖整个环，不会包含 $code[i]$ 自身——这是题目约束 $|k| \le n-1$ 保证的；若题目放宽到 $|k| \ge n$ 则公式需按 $\min(|k|, n)$ 截断，本题不用考虑。
4. **$n = 1$**：此时 $k$ 只能为 $0$（约束 $-(n-1) \le k \le n-1$ 即 $k=0$），返回 `[0]`，特判分支天然覆盖。
5. **滚动方向搞反**：$k>0$ 滑动时「进」的是 $(i+kk+1)$、「出」的是 $(i+1)$；写成相反顺序会得到整体左移的错答案，对拍一轮即可暴露。
