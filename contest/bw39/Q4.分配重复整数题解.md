# LeetCode 分配重复整数 题解

## 1. 题目概述

- **标题 / 题号**：分配重复整数（#1655，hard）
- **链接**：https://leetcode.cn/problems/distribute-repeating-integers/
- **来源**：LeetCode 第 39 场双周赛 Q4
- **难度**：困难
- **标签**：位运算、位掩码、动态规划、回溯、数组、哈希表

**题意**：给定长度 $n$ 的整数数组 `nums`（至多 50 个**不同的值**），与 $m$ 位顾客的订单 `quantity`。第 $i$ 位顾客要**恰好** $quantity[i]$ 个**互不相同下标但取值全相同**的整数（即全从某一种值里拿）。判断是否存在一种分配方式让所有顾客都被满足。可以不把 `nums` 用完。

**约束**：

- $1 \le n \le 10^5$
- $1 \le nums[i] \le 1000$
- $1 \le m = quantity.length \le 10$
- $1 \le quantity[i] \le 10^5$
- `nums` 中至多 50 个不同的数字

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4], quantity = [2]
输出：false
解释：任何一种值都只出现 1 次，凑不出 2 个相同的整数给顾客 0。
```

**示例 2**

```text
输入：nums = [1,2,3,3], quantity = [2]
输出：true
解释：把两个 3 都给顾客 0；1、2 闲置不用。
```

**示例 3**

```text
输入：nums = [1,1,2,2], quantity = [2,2]
输出：true
解释：顾客 0 拿 [1,1]，顾客 1 拿 [2,2]。
```

## 3. 解题思路

### 3.1 暴力思路

对 $m \le 10$ 位顾客逐一枚举「分给哪一种值」，即从 50 种值中带放回地选 $m$ 次，再验证每种值的库存够不够——$50^{10} \approx 10^{17}$，显然爆炸。改进一点的回溯是「按顾客 DFS、按值剪枝」，最坏仍是指数级；只有把「哪些顾客共享同一种值」的信息压进**位掩码**，才能把指数从底数 50 降到子集枚举的 $3^m$。

### 3.2 核心观察：顾客集合的位掩码 + 按数字种类的 0-1 背包

![核心观察：mask 编码顾客子集](images/bw39_q4_mask_model.svg)

三个关键观察把问题压到可解规模：

1. **顾客只关心「和」，不关心具体是谁**：第 $i$ 位顾客的需求就是一个数 $quantity[i]$。一种值 $v$（库存 $cnt_v$）能喂饱的顾客组合，是任何满足「需求总和 $\le cnt_v$」的顾客集合。集合用 $m$ 位掩码 $mask$ 表示，需求总和 $subSum[mask]$ 可 $O(2^m)$ 预处理。
2. **每种值的决策互相独立**：一种值要么整份库存拆给某组顾客（这组的需求和 $\le cnt_v$），要么不用；不存在「两个顾客组分摊同一种值的库存」——注意每个顾客只需一种值，但**同一组顾客共享同一种值**。于是把 50 种值看成 50 个「物品」，每个物品可选可不清，就是**分组 0-1 背包**。
3. **状态只需记 mask**：$dp[mask] = true$ 表示「用已处理过的数字种类，可以恰好满足集合 $mask$ 中的所有顾客」。处理新一种值（库存 $cnt$）时，转移为枚举 $mask$ 的子集 $sub$：若 $subSum[sub] \le cnt$ 且 $dp[mask \setminus sub]$ 已为 true，则 $dp[mask]$ 变 true。最终看 $dp[(1 \ll m) - 1]$。

### 3.3 算法流程

![算法流程：预处理 subSum，逐数字子集转移](images/bw39_q4_dp_flow.svg)

```text
1. 统计频次：cnt[v] = v 在 nums 中的出现次数，得到至多 50 个库存值 freq[]
2. 预处理 subSum[mask] = Σ quantity[i]（i ∈ mask）   —— O(2^m)
3. dp[0] = true，其余 false
4. 对每个库存 f ∈ freq：
       倒序枚举 mask（从 (1<<m)−1 到 1）：
           若 dp[mask] 已 true：跳过
           枚举 mask 的子集 sub：
               若 subSum[sub] ≤ f 且 dp[mask ^ sub]：
                   dp[mask] = true，跳出子集循环
5. 返回 dp[(1<<m)−1]
```

「倒序枚举 mask + 子集转移」等价于 0-1 背包的滚动数组：倒序保证当前这枚「物品」（一种数字）不会被拆给两个不同的 mask 组合重复使用。事实上本转移即使不倒序也不会让一种值被用两次（$sub$ 与 $mask \setminus sub$ 不相交，且同一种值在一次外层迭代内只允许贡献一个 $sub$），倒序只是避免同一种值通过 $dp[mask^{sub}] \to dp[mask]$ 链式「借用」自己——稳妥起见保留。

### 3.4 示例演算

以示例 3（`nums = [1,1,2,2]`，`quantity = [2,2]`，$m=2$）为例：频次为 $freq = [2, 2]$；$subSum[01_2]=2$（顾客 0），$subSum[10_2]=2$（顾客 1），$subSum[11_2]=4$（两位）。

| 处理的库存 | 转移 | dp 状态 |
|---|---|---|
| 初始 | — | $dp[00]=T$ |
| $f=2$（值 1） | $sub=01$，$subSum=2\le 2$，$dp[00]=T$ | $dp[01]=T$ |
|  | $sub=10$，$subSum=2\le 2$，$dp[00]=T$ | $dp[10]=T$ |
|  | $sub=11$，$subSum=4>2$，不行 | $dp[11]=F$ |
| $f=2$（值 2） | $mask=11$，枚举 $sub=01$：$dp[10]=T$，$subSum[01]=2\le 2$ | $dp[11]=T$ ✓ |

返回 `true`，与示例一致。注意第二种值是**整份**喂给顾客 1（$sub=01$ 交给新值，剩余顾客 $10$ 由旧值负责），两种值各司其职。

## 4. 算法细节

1. **频次统计是第一步**：`nums` 长到 $10^5$，但**不同值至多 50 个**，先 `Counter` 压缩成库存数组，之后的所有复杂度只与 $m$ 和种类数有关，与 $n$ 无关。
2. **$subSum$ 的递推**：`subSum[mask] = subSum[mask & (mask-1)] + quantity[__builtin_ctz(mask)]`，即「去掉最低位 1 的子集和 + 该位顾客的需求」，$O(2^m)$ 无需双重循环。
3. **子集枚举模板**：`for (int sub = mask; sub; sub = (sub - 1) & mask)` 枚举 `mask` 的全部非空子集，总代价 $\sum_{mask} 2^{popcount(mask)} = 3^m$。
4. **剪枝**：`dp[mask]` 已为 true 就跳过整个子集循环（最常见的常数优化）；还可以把库存降序排序，大库存先处理更容易早把大 mask 点亮，进而更多剪枝生效。
5. **总量快速否决**：若 $\sum quantity[i] > \sum freq$ 直接 false，可省一轮 DP（非必需）。
6. **数据范围**：$quantity[i] \le 10^5$、$m \le 10$，$subSum$ 上界 $10^6$，`int` 够用；库存计数同样 `int`。

## 5. 正确性证明

**引理 1（分配的规范化）**：存在合法分配当且仅当存在「顾客到值的一对一指派 $\phi$（每位顾客恰好指派一种值）」使得对每种值 $v$，被指派到 $v$ 的顾客需求总和 $\le cnt_v$。

**证明**：（⟸）按指派直接从库存里取数即可，每位顾客拿到的都是同一种值、数量恰好等于需求（库存足够）。（⟹）合法分配中每位顾客拿到的整数全相同，把该值记为其指派 $\phi(i)$，则该值被取走至少 $quantity[i]$ 个；同种值 $v$ 的库存被所有指派到它的顾客共享，故 $\sum_{i:\phi(i)=v} quantity[i] \le cnt_v$。∎

**引理 2（DP 可达性与指派的等价）**：处理完前 $k$ 种值后 $dp[mask]=true$，当且仅当存在指派 $\phi$ 把集合 $mask$ 中的顾客全部指派到前 $k$ 种值且库存约束满足。

**证明**：对 $k$ 归纳。$k=0$：只有 $dp[\varnothing]=true$，空指派平凡成立。设对 $k$ 成立。前 $k+1$ 种值：若 $dp[mask]=true$ 由「第 $k+1$ 种值（库存 $f$）负责子集 $sub$、前 $k$ 种负责 $mask \setminus sub$」达成，则归纳假设给出前 $k$ 种值对 $mask\setminus sub$ 的合法指派，再把 $sub$ 中顾客全部指派到第 $k+1$ 种值（$subSum[sub] \le f$ 保证库存），合成对 $mask$ 的合法指派。反之，若存在对 $mask$ 用前 $k+1$ 种值的合法指派 $\phi$，令 $sub = \{i \in mask : \phi(i) = \text{第}k+1\text{种值}\}$，则 $subSum[sub] \le f$（引理 1 的库存约束），且 $\phi$ 限制在 $mask \setminus sub$ 上是用前 $k$ 种值的合法指派，由归纳假设 $dp[mask \setminus sub]=true$，于是转移使 $dp[mask]=true$。∎

**定理**：算法返回 `dp[(1<<m)−1]`，其值恰为「存在合法分配」的布尔值。

**证明**：$dp[(1 \ll m)-1]=true$ 当且仅当（引理 2，$k=$ 全部种类数）存在把**全部** $m$ 位顾客指派到某些值且库存约束满足的方案，由引理 1 这等价于存在合法分配。DP 覆盖了所有种类与所有子集转移，枚举完备。∎

## 6. 复杂度分析

- **时间**：$O(n + D \cdot 3^m)$，$D \le 50$ 为不同值的个数。频次统计 $O(n)$；DP 外层 $D$ 次，内层全部子集枚举合计 $3^m = 59049$（$m=10$），总计约 $50 \times 59049 \approx 3 \times 10^6$，加上 `subSum` 预处理 $O(2^m)$。
- **空间**：$O(2^m + D)$：`dp`、`subSum` 各 $2^m$，库存数组 $D$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canDistribute(vector<int>& nums, vector<int>& quantity) {
        unordered_map<int, int> cnt;
        for (int v : nums) ++cnt[v];
        vector<int> freq;
        freq.reserve(cnt.size());
        for (auto& [k, v] : cnt) freq.push_back(v);      // 库存数组（≤ 50 个）
        int m = quantity.size();
        int full = (1 << m) - 1;

        vector<int> subSum(full + 1, 0);                 // 子集需求和
        for (int mask = 1; mask <= full; ++mask)
            subSum[mask] = subSum[mask & (mask - 1)] + quantity[__builtin_ctz(mask)];

        vector<char> dp(full + 1, 0);
        dp[0] = 1;
        for (int f : freq) {
            for (int mask = full; mask > 0; --mask) {
                if (dp[mask]) continue;                  // 已可达，跳过
                for (int sub = mask; sub; sub = (sub - 1) & mask) {
                    if (subSum[sub] <= f && dp[mask ^ sub]) {
                        dp[mask] = 1;
                        break;
                    }
                }
            }
        }
        return dp[full];
    }
};
```

### Python

```python
from collections import Counter

class Solution:
    def canDistribute(self, nums: list[int], quantity: list[int]) -> bool:
        freq = list(Counter(nums).values())              # 库存数组（≤ 50 个）
        m = len(quantity)
        full = (1 << m) - 1

        sub_sum = [0] * (1 << m)                         # 子集需求总和
        for mask in range(1, 1 << m):
            low = mask & (-mask)
            sub_sum[mask] = sub_sum[mask ^ low] + quantity[low.bit_length() - 1]

        dp = [False] * (1 << m)
        dp[0] = True
        for f in freq:
            for mask in range(full, 0, -1):
                if dp[mask]:
                    continue
                sub = mask
                while sub:
                    if sub_sum[sub] <= f and dp[mask ^ sub]:
                        dp[mask] = True
                        break
                    sub = (sub - 1) & mask
        return dp[full]
```

> 💡 两份代码均通过官方三个示例，并与「按顾客 DFS 枚举指派」的暴力在 3000 组（C++）/ 2000 组（Python）随机数据（$\le 5$ 种值、$\le 5$ 位顾客、库存与需求 $\le 7$）上对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **一位顾客**：$m=1$ 退化为「是否存在某种值出现次数 $\ge quantity[0]$」，DP 自然处理；示例 1/2 正是这个形态。
2. **同一顾客不能拆到两种值**：这是题意的隐含点——顾客拿到的整数必须全部相同。DP 中 $sub$ 整体指派给一种值恰好编码了这一约束；若错误地允许拆分，贪心可解的问题就变味了。
3. **subSum 溢出与类型**：$m \le 10$、$quantity[i] \le 10^5$，子集和上界 $10^6$，`int` 安全。
4. **倒序枚举 mask**：保持 0-1 背包语义（一种值在一次迭代内只贡献一个子集）；虽然本转移因 $sub \cap (mask \setminus sub) = \varnothing$ 而对顺序不敏感，正序也在对拍中通过，倒序是更稳的书写惯例。
5. **跳过已达 dp[mask]**：不仅省时，还避免同一 mask 被同一库存反复点亮的无效循环；写反条件（`if (!dp[mask]) continue;`）会直接全错。
6. **忘了 $dp[0]=true$**：空集合永远「已满足」，这是所有转移的起点；漏掉后全表恒 false。
7. **n 与 m 的量级错觉**：$n=10^5$ 只影响统计频次的线性扫描；真正决定复杂度的是 $m \le 10$ 与 $D \le 50$，别把 $n$ 卷进 DP。
