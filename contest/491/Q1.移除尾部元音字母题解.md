# LeetCode 移除尾部元音字母 题解

## 1. 题目概述

- **标题 / 题号**：移除尾部元音字母（#3856，easy）
- **链接**：https://leetcode.cn/problems/trim-trailing-vowels/
- **来源**：LeetCode 第 491 场周赛 Q1
- **难度**：简单
- **标签**：字符串、倒序扫描

**题意**：给定一个由小写英文字母组成的字符串 `s`，返回移除 `s` **尾部所有元音字母**后得到的字符串。元音字母为 `'a'`、`'e'`、`'i'`、`'o'`、`'u'`（注意 `'y'` **不是**元音）。

**约束**：

- $1 \le s.length \le 100$
- `s` 仅由小写英文字母组成

> ⚠️ **审题关键**：① 只删**尾部**——头部的元音（如 `"idea"` 的 `'i'`）必须保留；② 尾部元音指**从末位起连续**的一段，中间的元音（如 `"day"` 的 `'a'`）不动；③ 全元音串要能正确返回空串。

## 2. 示例

**示例 1**

```text
输入：s = "idea"
输出："id"
解释：尾部连续元音段是 "ea"，移除后得到 "id"。
注意：头部 'i' 虽是元音但不在尾部，保留。
```

**示例 2**

```text
输入：s = "day"
输出："day"
解释：末位 'y' 不是元音，尾部没有可删的元音；
中间的 'a' 也不属于尾部连续段，原样返回。
```

**示例 3**

```text
输入：s = "aeiou"
输出：""
解释：整个字符串都是元音，全部移除后为空串。
```

## 3. 解题思路

### 3.1 暴力思路：逐个弹出末尾元音

最直接的模拟：只要 `s` 非空且末位是元音，就把末位删掉，重复直到末位非元音：

```python
while s and s[-1] in "aeiou":
    s = s[:-1]      # ⚠️ 每轮切片整串拷贝，一次 O(n)
```

判定逻辑本身正确，但有两个毛病：

1. **Python 的 `s[:-1]` 每轮整串重建**，删 $k$ 个尾部元音共 $O(nk)$（本题 $n \le 100$ 无所谓，放到 $10^6$ 就是坏习惯）；C++ 的 `pop_back` 虽是 $O(1)$，但"一刀一刀试"的思路终究绕远。
2. 删除「若干个末尾字符」其实不必逐个试——**一次算出从哪里切**就够了。

### 3.2 核心观察：删后缀 ⟺ 保前缀，切割点由「最右非元音」唯一确定

![核心观察：切割点模型](images/wc491_q1_cut_point_model.svg)

被删的永远是一段**后缀** $s[i+1..n-1]$，它由切割点 $i$ 唯一确定——

$$i = \max\{\, k : s[k] \notin V \,\}, \qquad V = \{\texttt{a}, \texttt{e}, \texttt{i}, \texttt{o}, \texttt{u}\}$$

（全元音时约定 $i = -1$。）$s[i+1..n-1]$ 恰是「极长全元音后缀」，答案就是前缀 $s[0..i]$。于是算法坍缩成**一趟倒序扫描**：`i` 从 $n-1$ 出发向左走，只要 `s[i]` 是元音就继续左移，**一旦遇到非元音（或越过 0）立即停止**，返回 `s[0..i]`。

为什么倒序天然占优？「某字符该不该删」只取决于**它右侧是否全是元音**——这是后缀性质，信息流从右往左传播；且一旦停在非元音处，更左边的字符无论是什么都与答案无关，可以**早停**。正序扫描则没法单趟判断：扫到中间某个元音时，并不知道右边还有没有非元音。

> 💡 $i = -1$（全元音串一路扫穿）时前缀长度为 0，`substr(0, 0)` / `s[:0]` 天然返回空串——**下标语义自动消化边界**，零 if 特判。

### 3.3 算法流程

![算法流程：倒序扫描定位切割点](images/wc491_q1_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `i = n - 1` | 从末位出发 |
| ② 循环判定 | `i ≥ 0` 且 `s[i] ∈ {a,e,i,o,u}` ？ | **两条件缺一不可**，且 `i ≥ 0` 必须在前（短路求值） |
| ③ 左移 | 是 → `i -= 1`，回到 ② | 至多 $n$ 轮 |
| ④ 收工 | 否 → 返回 `s[0..i]` | `i = -1` 时恰为空串 |

> ⚠️ **条件顺序坑**：若把元音判定写在前面，`i = -1` 时 Python 的 `s[-1]` **合法但取到末位字符**（语义错位、判定对象整个错），C++ 则直接越界未定义行为。循环条件务必先判 `i ≥ 0`。

### 3.4 示例演算

![示例演算：三组样例走查](images/wc491_q1_example_walkthrough.svg)

| 示例 | 倒序扫描过程 | 停在 | 返回 |
|------|--------------|------|------|
| `"idea"` | 'a' 元音→左移，'e' 元音→左移，'d' 非元音 | `i = 1`（'d'） | `"id"` |
| `"day"` | 'y' 非元音，第一轮即停 | `i = 2` | `"day"` |
| `"aeiou"` | 五个字符全是元音，一路扫穿 | `i = -1` | `""` |

## 4. 算法细节

1. **判定与定位合一**：`while (i >= 0 && isVowel(s[i])) --i;` 一行完成"判定 + 左移"，循环退出的那一刻 `i` 就是切割点，无需额外的标记变量或第二趟扫描。
2. **元音判定**：C++ 写五连比较 `c=='a' || c=='e' || ...`（编译器可优化为位运算），或 `"aeiou"s.find(c) != npos`；Python 直接 `c in "aeiou"`（单字符时子串语义等价于集合成员判定）。
3. **返回前缀**：C++ `s.substr(0, i + 1)` 产生一次 $O(n)$ 拷贝；由于 LeetCode 签名按值传串，追求极致可 `s.resize(i + 1); return s;` 原地收尾。Python `s[:i]` 切片同理。
4. **Python 的防负下标写法**：让 `i` 直接充当"保留长度"——从 $n$ 出发，条件写 `i > 0 and s[i-1] in "aeiou"`，返回 `s[:i]`。判断的对象永远是 `s[i-1]`（合法下标），从根上规避 `s[-1]` 陷阱。
5. **一行流**（语义等价，可口述加分）：
   - C++：`return s.substr(0, s.find_last_not_of("aeiou") + 1);`——`find_last_not_of` 返回最后一个非元音下标，全元音时返回 `npos`，而 `npos + 1 == 0` 恰好落回空串，边界同样自动消化；
   - Python：`return s.rstrip("aeiou")`——`rstrip` 的参数是**字符集合**而非子串，语义正是「删掉尾部所有属于该集合的字符」。

## 5. 正确性证明

**引理 1（答案刻画）**：记 $n = |s|$，$i^* = \max\{\, k \in [0, n-1] : s[k] \notin V \,\}$（集合为空时约定 $i^* = -1$）。则题目所求答案为前缀 $s[0..i^*]$。

**证明**：题意要求删除「尾部所有元音」，形式化为：删除集合 $D$ 是一个后缀 $s[j..n-1]$，须满足 (a) $D$ 中字符全为元音；(b) 删完后剩余部分的末位不再是元音（否则与"所有尾部元音已删"矛盾）。考察 $j = i^* + 1$：因 $i^*$ 是最右非元音，$s[i^*+1..n-1]$ 全为元音，(a) 成立；若 $i^* \ge 0$ 则 $s[i^*] \notin V$，(b) 成立；若 $i^* = -1$（全元音），$D$ 为整串，剩余为空，(b) 平凡成立。再证唯一性：若 $j < i^* + 1$（删得更长），$D$ 包含非元音 $s[i^*]$，违反 (a)；若 $j > i^* + 1$（删得更短），则剩余末位 $s[j-1]$ 落在全元音段 $s[i^*+1..n-1]$ 内，违反 (b)。故删除集合唯一确定为 $s[i^*+1..n-1]$，答案 $= s[0..i^*]$。∎

**引理 2（循环不变量）**：`while` 循环每轮判定开始时，`i` 右侧的全部字符 $s[i+1..n-1]$ 都是元音。

**证明**：对轮数归纳。首轮 $i = n-1$，右侧为空串，平凡成立。设某轮判定时结论成立且条件 `i ≥ 0 且 s[i] ∈ V` 为真，执行 `i ← i − 1` 后进入下一轮：新 `i` 的右侧 = 旧 `i` 的右侧 $\cup$ $\{s[\text{旧 } i]\}$，由归纳假设与条件均为元音，结论保持。∎

**定理**：算法返回 $s[0..i^*]$，即正确答案。

**证明**：`i` 每轮减 1，循环必在有限步后终止，且终止时条件为假，即 `i < 0` 或 `s[i] ∉ V` 之一成立（注意短路求值保证取 `s[i]` 时必有 `i ≥ 0`）：

- `s[i] ∉ V`：由引理 2，`i` 右侧全为元音，又 `s[i]` 非元音，故 `i` 恰为最右非元音下标 $i^*$；
- `i < 0`：`i` 从 $n-1$ 逐轮减 1，终止时 `i = -1`，意味着途中判定的每个字符都是元音，即 $s$ 全为元音，$i^* = -1$。

两种情形均有 `i = i*`，算法返回 `s.substr(0, i + 1) = s[0..i*]`；由引理 1，这正是所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟倒序扫描，每个字符至多判定一次；最坏情形（全元音）扫完整串，一般情形遇非元音即早停。这也是信息论下界：全元音串必须每个字符都读过才能确认「右侧全是元音」，$\Omega(n)$ 不可避免。
- **空间复杂度**：$O(1)$ 额外。倒序只动下标；返回值本身占 $O(n)$（C++ 可 `resize` 原地收尾做到返回零拷贝）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string trimTrailingVowels(string s) {
        auto isVowel = [](char c) {
            return c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u';
        };
        int i = (int)s.size() - 1;
        while (i >= 0 && isVowel(s[i])) --i;   // 倒序定位最右非元音
        return s.substr(0, i + 1);             // i = -1 时恰为空串
    }
};
```

### Python

```python
class Solution:
    def trimTrailingVowels(self, s: str) -> str:
        i = len(s)
        while i > 0 and s[i - 1] in "aeiou":   # 先判 i > 0，短路防 s[-1]
            i -= 1
        return s[:i]
```

> 💡 **一行流对照**：C++ `s.substr(0, s.find_last_not_of("aeiou") + 1)`；Python `s.rstrip("aeiou")`。
> ⚠️ **经典错误**：`s.strip("aeiou")` 会**双端齐删**，`"idea".strip("aeiou")` 得 `"d"`；`removesuffix` 只删一段**精确匹配**的后缀且只删一次——都不是本题语义。

## 8. 边界情况与易错点

1. **'y' 不是元音**：示例 2 的陷阱，元音集合只有 `a/e/i/o/u` 五个，别凭语感把 'y' 加进去。
2. **头部/中间元音不删**：`"idea"` → `"id"` 而不是 `"d"`——只删**从末位起连续**的那段；这也是禁用 `strip`（双端齐删）的原因。
3. **全元音串返回空串**：`i` 扫穿到 $-1$，`substr(0, 0)` / `s[:0]` 天然返回 `""`，**无需特判**——前提是返回时用的是 `i + 1` / `i` 这种下标语义，而不是另写 `if (i >= 0)` 分支。
4. **循环条件顺序**：`i ≥ 0` 必须写在元音判定**之前**（短路求值）。反了的话：Python `s[-1]` 合法但取到**末位字符**（判定对象错位），C++ 越界是未定义行为。
5. **别用 `pop_back` 逐个删 + 判空**：功能上等价，但"先定位切割点、一次裁剪"代码更短、意图更清晰，也避免了 Python 切片反复拷贝的 $O(nk)$。
6. **单字符串**：`"a"` → `""`、`"b"` → `"b"`，分别是「全元音」与「第一轮即停」的最小特例，都被同一套逻辑覆盖。
7. **规模极小**：$n \le 100$，无溢出、无性能压力——签到题的目标是**零调试一次过**，边界全部交给下标语义。
