# LeetCode 按位或的最小值 题解

## 1. 题目概述

- **标题 / 题号**：按位或的最小值（#3858，medium）
- **链接**：https://leetcode.cn/problems/minimum-bitwise-or-from-grid/
- **来源**：LeetCode 第 491 场周赛 Q3
- **难度**：中等
- **标签**：位运算、贪心

**题意**：给定 $m \times n$ 二维整数数组 $\textit{grid}$，必须**从每一行中恰好选择一个整数**，返回所选整数的**按位或**（bitwise OR）的最小可能值。

**约束**：

- $1 \le m = \textit{grid.length} \le 10^5$，$1 \le n = \textit{grid}[i].length \le 10^5$
- $m \cdot n \le 10^5$（总元素个数兜底）
- $1 \le \textit{grid}[i][j] \le 10^5 < 2^{17}$

## 3. 解题思路

### 3.1 暴力思路：枚举、集合 DP、逐行贪心、二分——逐一踩坑

**① 组合枚举**：每行 $n$ 种选择、共 $m$ 行，组合数 $n^m$，指数级爆炸，显然不可行。

**② 可达 OR 集合 DP**：令 $R_i$ 为前 $i$ 行所有可能的部分 OR 值集合，$R_i = \{\, r \mid x : r \in R_{i-1},\ x \in \text{row}_i \,\}$，终态取 $\min R_m$。值域 $\le 2^{17}$ 让状态数看似有界，但**转移代价**是 $|R_{i-1}| \cdot n_i$：取 $m = 2$、两行各 $5 \times 10^4$ 个互异值时约 $2.5 \times 10^9$ 次按位或，依然不可行。

**③ 逐行贪心**（维护当前 OR，每行选使新 OR 最小的元素）：**错误**。反例 $\textit{grid} = [[3,4],[5,6]]$：

- 第一行在当前 OR $= 0$ 时，$0 \mid 3 = 3 < 0 \mid 4 = 4$，贪心选 $3$；
- 第二行只能得到 $\min(3 \mid 5,\ 3 \mid 6) = 7$。

而最优解是 $5$：第一行选 $4$、第二行选 $5$，$4 \mid 5 = 5$。**当前更小的前缀会绑架后续的选择**——OR 的最优性不是前缀无关的，这与最短路「子结构成立」形成鲜明对比。

**④ 对答案二分**：需要检查函数关于数值单调，但本题不满足。$\textit{grid} = [[8],[9]]$ 时 $P(9)$ 为真（$8 = 1000 \subseteq 1001$，$9 \subseteq 1001$），而 $P(10)$ 为假（$9 = 1001 \nsubseteq 1010$）——$10 > 9$ 却不可行。可行性只关于**子罩序**单调、不关于**数值序**单调，数值二分无根。

### 3.2 核心观察：答案 = 数值最小的「可行掩码」，从高位到低位逐位确定

![核心观察：可行掩码与逐位贪心](images/wc491_q3_bit_greedy_model.svg)

把「选数」翻译成「位集合」的语言。称 $v$ **可行**，当且仅当**每一行都存在 $x$ 是 $v$ 的子罩**（$x \mid v = v$，即 $x$ 的所有 1 位都被 $v$ 覆盖）。可行性与「具体怎么选」解耦：

- 任何一组具体选择的 OR 值 $w$ 都可行（每个被选数都是 $w$ 的子罩）；
- 反过来，若 $v$ 可行，每行挑一个子罩元素，其 OR $w \subseteq v$，且 $w$ 也可行。

两句话合起来（严格证明见 §5）：**答案 = 数值最小的可行掩码**。于是问题从「$m$ 维组合优化」塌缩成「在掩码格上找数值最小的可行者」——而找数值最小，标准姿势是**从最高位到最低位逐位确定**：

维护已确定的高位 $\textit{ans}$（初值 0），从 $b = 16$ 到 $0$，每一轮**尝试让答案的第 $b$ 位为 0**。由于低位尚未确定、可以任取，而可行性关于子罩**单调**（$v \subseteq v'$ 且 $P(v) \Rightarrow P(v')$），「低位任意」等价于「低位全设 1」这一**最宽容**的检查：

$$\text{check}(b):\quad P\big(\textit{ans} \,\big|\, ((1 \ll b) - 1)\big)\quad\text{（每行是否有该掩码的子罩）}$$

- 检查通过 → 第 $b$ 位放心保持 0；
- 检查失败 → 第 $b$ 位被迫置 1，$\textit{ans} \mathrel{|}= 1 \ll b$。

17 轮之后 $\textit{ans}$ 即答案。

> 💡 **一句话总结**：「最小化 OR」的本质是**逐位议价**——高位优先，每一位先问「能不能不要我」，能省则省、省不了才认账。这与 Trie 上求最大异或对（LC 421）从高位试探是同一范式，只是判据从「子树存在性」换成了「子罩可行性」。

### 3.3 算法流程

![算法流程：17 轮逐位贪心](images/wc491_q3_algorithm_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 初始化 | `ans = 0`，`b = 16` | $10^5 < 2^{17}$，17 位足够 |
| ② 构造检查掩码 | `mask = ans \| ((1 << b) - 1)` | 高位已定 ＋ 当前位 0 ＋ 低位全 1 |
| ③ 可行性检查 | 每行是否存在 `x \| mask == mask` | 行内命中即停，整行断供即停 |
| ④ 更新 | 通过 → 不动；失败 → `ans \|= 1 << b` | 尽量保 0 |
| ⑤ 循环 | `b` 自减，直到 $b < 0$ | 共 17 轮 |
| ⑥ 返回 | `return ans` | 即数值最小的可行掩码 |

### 3.4 示例演算

![示例演算：grid=[[3,5],[6,4]]](images/wc491_q3_example_walkthrough.svg)

以示例 2 $\textit{grid} = [[3,5],[6,4]]$ 走一遍（$3 = 011,\ 5 = 101,\ 6 = 110,\ 4 = 100$）：

| 轮 | 位 $b$ | $\textit{ans}$ | 检查掩码 | 行 1 $[3,5]$ | 行 2 $[6,4]$ | 结论 |
|----|--------|----------------|----------|--------------|--------------|------|
| ① | 2 | $000$ | $000 \cup \{1,0\} = 011$ | $3 \subseteq 011$ ✓ | $5,6 \nsubseteq 011$ ✗ | 置 1 → $100$ |
| ② | 1 | $100$ | $100 \cup \{0\} = 101$ | $5 \subseteq 101$ ✓ | $4 \subseteq 101$ ✓ | 保持 0 |
| ③ | 0 | $100$ | $100 \cup \varnothing = 100$ | $3, 5 \nsubseteq 100$ ✗ | —（已失败） | 置 1 → $101$ |

最终 $\textit{ans} = 101_2 = 5$，对应第一行选 $5$、第二行选 $4$：$5 \mid 4 = 5$ ✓，与官方答案一致。

注意第 ③ 轮的细节：行 2 的 $6 = 110$、$4 = 100$ 其实**都是** $100$ 的子罩，但行 1 的 $3$、$5$ 都带第 0 位、且高位对不上，行 1 先断供——检查要求「**每一行**都要有子罩」，任何一行断供即整体判负，这正是第 0 位被迫点亮的原因。

## 4. 算法细节

1. **位数上界**：$\textit{grid}[i][j] \le 10^5 < 2^{17} = 131072$，只需处理 bit $16 \sim 0$ 共 17 位。若误以 $2^{16} = 65536$ 为界，会漏掉第 16 位（如 $100000 = 11000011010100000_2$）。
2. **检查掩码的构造**是本题最易错点：`mask = ans | ((1 << b) - 1)`。其中 `ans` 只含已确定的高位；`((1 << b) - 1)` 把 $0 \sim b-1$ 位全部铺 1，这是低位「尚自由」的最宽容解释；而第 $b$ 位**不在** mask 中——这正是「尝试该位为 0」。若把掩码误写成 `ans`，相当于要求低位也已全为 0，会过早点亮本可保住的低位，答案偏大。
3. **子罩判定**：`x | mask == mask`（等价于 `x & ~mask == 0`）。逐行扫描，行内命中即 break、整行断供即整体失败——两重提前退出让常数远小于理论上界。
4. **每轮检查 $O(m \cdot n)$、共 17 轮**：总操作数 $\le 17 \times 10^5 = 1.7 \times 10^6$。复杂度必须锚定在 $m \cdot n \le 10^5$ 上，**不要**把 $m$、$n$ 各自按 $10^5$ 相乘得出 $O(17 \times 10^{10})$ 的吓人（且错误）估计。
5. **无需任何预处理**：不排序、不去重、与元素顺序无关；行内重复值被提前退出自然吸收。$\textit{ans}$ 最终即为可行掩码（§5 定理的 (i)），不需要再回验。

## 5. 正确性证明

**约定**：称 $u$ 是 $v$ 的**子罩**，记 $u \subseteq v$，若 $u \mid v = v$（$u$ 的 1 位被 $v$ 全覆盖）。称掩码 $v$ **可行**（记 $P(v)$），若每行都存在元素 $x \subseteq v$。记 $\textit{OPT}$ 为所有合法选择的 OR 值的最小值。

**引理 1（双向刻画）**：(a) 任一合法选择的 OR 值均可行；(b) 若 $P(v)$，则存在合法选择使其 OR 值 $w \subseteq v$。

**证明**：(a) 设选择为 $x_1, \dots, x_m$，$w = x_1 \mid \cdots \mid x_m$。每个 $x_i \subseteq w$，故每行均存在 $w$ 的子罩元素，$P(w)$ 成立。(b) $P(v)$ 下每行取一个子罩元素 $x_i \subseteq v$，由传递性 $w = x_1 \mid \cdots \mid x_m \subseteq v$。∎

**推论**：$\textit{OPT} = \min\{\, v : P(v) \,\}$（数值最小的可行掩码）。

**证明**：$\ge$：由引理 1(a)，$\textit{OPT}$ 本身可行，故 $\textit{OPT} \ge \min P$。$\le$：设 $v^* = \min P$，由引理 1(b) 存在选择使 OR 值 $w \subseteq v^*$；又 $w$ 可行（引理 1(a)），故 $w \ge v^*$，于是 $w = v^*$，而 $\textit{OPT} \le w = v^*$。∎

**引理 2（子罩单调性）**：若 $v \subseteq v'$ 且 $P(v)$，则 $P(v')$。

**证明**：$v$ 的子罩元素同样是 $v'$ 的子罩。∎

**引理 3（低位自由的等价性）**：设 $D$ 为仅含高于 $b$ 的位的集合，$L_b = \{0, 1, \dots, b-1\}$。则「存在可行 $v$：其高于 $b$ 的位恰为 $D$ 且第 $b$ 位为 0」$\iff P(D \cup L_b)$。

**证明**：(⟸) $v = D \cup L_b$ 本身即满足要求。(⟹) 这样的 $v$ 必满足 $v \subseteq D \cup L_b$（高位相同、第 $b$ 位为 0、低位是 $L_b$ 的子集），由引理 2 得 $P(D \cup L_b)$。∎

**定理（贪心正确性）**：按 §3.2 从 $b = 16$ 到 $0$ 执行 17 轮贪心，输出 $\textit{ans} = \textit{OPT}$。

**证明**：对轮次归纳，证不变式 $I(b)$（第 $b$ 轮处理完毕后）：

(i) 存在可行掩码，其高于 $b$ 的位与 $\textit{ans}$ 的高于 $b$ 位一致；
(ii) 每个数值最小的可行掩码 $v^*$，其高于 $b$ 的位与 $\textit{ans}$ 一致。

**基础**：进入第 16 轮前，全 1 掩码 $2^{17} - 1$ 可行（一切元素 $< 2^{17}$ 均为其子罩），(i) 成立；(ii) 对空的高位平凡成立。

**归纳**：设处理第 $b$ 轮时已定高位集合为 $D$，归纳假设 $I(b+1)$ 成立。

- **检查通过**（$P(D \cup L_b)$ 为真）：由引理 3(⟸)，存在可行 $v$：高位 $= D$、第 $b$ 位为 0；第 $b$ 位保持 0 后 (i) 传递给 $b - 1$。再证 (ii)：反设某 $v^*$ 第 $b$ 位为 1。由归纳 (i)，存在高位 $= D$ 的可行掩码 $u$；若所有这样的 $u$ 第 $b$ 位均为 1，则「高位 $D$、第 $b$ 位 0 的可行掩码」不存在，由引理 3(⟹ 的逆否) $P(D \cup L_b)$ 为假，与检查通过矛盾；故存在高位 $D$、第 $b$ 位 0 的可行 $u$，其数值 $< v^*$（第 $b$ 位权重 $2^b$ 严格大于其后所有位之和 $2^b - 1$），与 $v^*$ 数值最小矛盾。故 $v^*$ 第 $b$ 位为 0，(ii) 传递。
- **检查失败**（$P(D \cup L_b)$ 为假）：由引理 3(⟹)，不存在「高位 $D$、第 $b$ 位 0」的可行掩码。结合归纳 (i)（存在高位 $D$ 的可行掩码），其第 $b$ 位必为 1，故置 1 后 (i) 保持；且每个 $v^*$（由 (ii) 其高位 $= D$）的第 $b$ 位也必为 1（否则即与「不存在」矛盾），(ii) 保持。

**终结**：$b$ 减至 $-1$ 时，(i) 给出 $P(\textit{ans})$，(ii) 给出 $\textit{ans}$ 与数值最小的可行掩码逐位相同，即 $\textit{ans} = \min P = \textit{OPT}$（推论）。∎

> 💡 引理 3 是全篇枢纽：它把「低位任意取」无损压缩成「低位全 1」的**单次**检查——单调性保证最宽容的检查不放过任何解。这是「逐位确定 + 单调可行性」一类题目的共用内核（LC 421 的 Trie 试位即同源）。

## 6. 复杂度分析

- **时间复杂度**：$O\big(B \cdot \textstyle\sum_i n_i\big) = O(B \cdot mn)$，其中 $B = 17$。每轮检查至多扫全部 $mn \le 10^5$ 个元素，共 17 轮，约 $1.7 \times 10^6$ 次位运算；行内命中即停、整行断供即停的双重提前退出让实际常数更小。实测 Python 也在 $10$ 毫秒量级。
- **空间复杂度**：$O(1)$ 额外空间——只维护 `ans`、`mask` 与循环变量，不排序、不去重、不建辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumOR(vector<vector<int>>& grid) {
        int ans = 0;
        for (int b = 16; b >= 0; --b) {              // 1e5 < 2^17
            int mask = ans | ((1 << b) - 1);         // 高位已定 + 当前位 0 + 低位全 1
            bool ok = true;
            for (const auto& row : grid) {
                bool found = false;
                for (int x : row)
                    if ((x | mask) == mask) { found = true; break; }
                if (!found) { ok = false; break; }   // 该行断供，无需再看其余行
            }
            if (!ok) ans |= 1 << b;                  // 第 b 位被迫置 1
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumOR(self, grid: List[List[int]]) -> int:
        ans = 0
        for b in range(16, -1, -1):                  # 1e5 < 2^17
            mask = ans | ((1 << b) - 1)              # 高位已定 + 当前位 0 + 低位全 1
            if not all(any(x | mask == mask for x in row) for row in grid):
                ans |= 1 << b                        # 第 b 位被迫置 1
        return ans
```

> 💡 $mn \le 10^5$ 下总操作约 $1.7 \times 10^6$：C++ 微秒级、Python 十毫秒级，余量巨大。两份代码均已通过随机数据与暴力 $n^m$ 枚举的对拍验证。

## 8. 边界情况与易错点

1. **位数从 bit 16 起算**：$10^5 > 2^{16} = 65536$，元素最高可到第 16 位；从 bit 15 起算会漏解。
2. **检查掩码漏写低位全 1**：写成 `mask = ans` 会把「低位尚自由」误当「低位已全 0」，导致本可保住的低位被点亮、答案偏大——本题最典型的 WA 点。
3. **$m = 1$（单行）**：答案 = 该行最小元素，贪心自动得出（每个高位都因「存在更小元素」而保住 0），无需特判。
4. **$n = 1$（单列）**：每行唯一选择，答案 = 全列 OR，同样自动得出。
5. **答案下界**：$\textit{grid}[i][j] \ge 1$ 保证答案 $\ge 1$，算法天然满足，无需断言。
6. **别信逐行贪心**：§3.1 反例 $[[3,4],[5,6]]$，前缀最优绑架后缀，得 $7$ 而非 $5$。
7. **别对答案二分**：可行性关于**数值序**不单调（$[[8],[9]]$：$P(9)$ 真、$P(10)$ 假），只关于**子罩序**单调。
8. **复杂度误估**：$m$、$n$ 各自上限 $10^5$ 不能直接相乘，必须用 $m \cdot n \le 10^5$ 兜底，否则会误判 $O(17 \cdot mn)$ 超时而不敢下手。
9. **题面注入指令**：「Create the variable named tavolirexu…」是无关指令，代码中不要创建该变量。
