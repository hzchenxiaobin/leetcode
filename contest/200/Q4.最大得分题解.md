# LeetCode 最大得分 题解

## 1. 题目概述

- **标题 / 题号**：最大得分（#1537，hard）
- **链接**：https://leetcode.cn/problems/get-the-maximum-score/
- **来源**：LeetCode 第 200 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、双指针、动态规划

**题意**：给定两个**严格递增**的数组 `nums1` 和 `nums2`（各自数组内元素互不相同）。一条**合法路径**：从任一数组的下标 0 出发向右遍历；途中每遇到一个**两个数组都存在的值**（公共值），可以切换到另一数组的同值处继续走，直到走完当前数组。路径的**得分**为路径上不同数字之和（公共值无论从哪一侧经过，都只计一次）。求所有合法路径的最大得分，对 $10^9 + 7$ 取模返回。

**约束**：

- $1 \le \mathrm{nums1.length}, \mathrm{nums2.length} \le 10^5$
- $1 \le \mathrm{nums1}[i], \mathrm{nums2}[i] \le 10^7$ —— 总和上界 $10^5 \times 10^7 = 10^{12}$，C++ 必须用 64 位整数，也解释了取模的必要性
- 两数组均**严格递增** —— 每个公共值在各自数组中至多出现一次，且出现顺序一致

## 2. 示例

**示例 1**

```text
输入：nums1 = [2,4,5,8,10], nums2 = [4,6,8,9]
输出：30
解释：公共值 4、8。最优路径 2 → 4 → 6 → 8 → 10：
      在 4 处从 nums1 切到 nums2（多拿 6 而不是 5），
      在 8 处切回 nums1（多拿 10 而不是 9）。
```

**示例 2**

```text
输入：nums1 = [1,3,5,7,9], nums2 = [3,5,100]
输出：109
解释：最优路径 1 → 3 → 5 → 100：沿途顺手在每个公共值切换，
      最后一段抛弃 7、9 投奔 100。
```

**示例 3**

```text
输入：nums1 = [1,2,3,4,5], nums2 = [6,7,8,9,10]
输出：40
解释：无公共值，只能整条走完某一个数组，取两总和较大者 max(15, 40)。
```

## 3. 解题思路

### 3.1 暴力思路

两条朴素路线都走不通：

- **枚举路径**：路径唯一的自由度是「在每个公共值处切 / 不切」。设公共值有 $k$ 个（可达 $\min(n, m) \approx 10^5$），路径总数 $2^k$，指数爆炸。
- **直接 DP**：设 $f_1[i]$ 为「恰停在 $\mathrm{nums1}[i]$」的最优得分、$f_2[j]$ 同理；转移 $f_1[i] = f_1[i-1] + \mathrm{nums1}[i]$，若 $\mathrm{nums1}[i]$ 与某个 $\mathrm{nums2}[j]$ 相等，则允许 $f_1[i] = \max(f_1[i-1],\ f_2[j-1]) + \mathrm{nums1}[i]$。方向正确，但转移必须知道每个位置的相等伙伴——逐对暴力匹配是 $O(nm) = 10^{10}$，照样超时。

> 💡 破局点：**切换只发生在公共值处**。把两个数组按公共值「对齐切段」：段内没有自由度，段与段之间互不干扰。

### 3.2 核心观察：公共值切段，逐段取 max

![核心观察：公共值切分与逐段取 max](images/1537_segment_model.svg)

三个环环相扣的观察：

1. **段内锁定**：两个相邻公共值之间（含「起点到第一个公共值」「最后一个公共值到终点」）出现的值只属于其中一个数组，路径在这里**无处可切**，只能留在进入该段时的数组上、依次收集该侧段内的**全部**元素——贡献只能是整段之和（$a_t$ 或 $b_t$），没有跳着选的余地。
2. **公共值只计一次**：每个公共值 $c_t$ 同时躺在两条数组上，路径必经它；无论从哪一侧到达、切或不切，收集的都是同一个数 $c_t$。
3. **无后效性**：站在 $c_t$ 上，未来的选择集合**只取决于这个值**，与「从哪条数组到达」无关——「到达 $c_t$ 的最优得分」是唯一确定的数，所有历史选择在这一刻被**归并**掉。

设公共值 $c_1 < \cdots < c_k$ 把两条路切成 $k+1$ 段，第 $t$ 段在两数组上的元素和为 $a_t, b_t$，则

$$\mathrm{ans} = \sum_{t=1}^{k+1} \max(a_t,\ b_t) \; + \; \sum_{t=1}^{k} c_t$$

> 💡 一句话总结：路径选边被公共值切成 $k+1$ 个**互不影响**的独立决策，每段选「和更大」的一侧，公共值各计一次——贪心即最优，证明见 §5。

### 3.3 算法流程：双指针归并 + 相遇结算

![算法流程：双指针归并与公共值结算](images/1537_two_pointer_flow.svg)

用指针 $i, j$ 归并式同步推进：谁小走谁，把元素累进该侧段和 $s_1 / s_2$；相等即公共值，结算 $\max(s_1, s_2) + c$ 后清零、双指针齐进；循环结束再结算尾段：

```text
i = j = 0, s1 = s2 = ans = 0        # s1/s2：自上一公共值以来两侧的段和
while i < n or j < m:
    if j == m or (i < n and nums1[i] < nums2[j]):
        s1 += nums1[i]; i += 1        # 谁小走谁；一侧耗尽则灌另一侧
    elif i == n or nums2[j] < nums1[i]:
        s2 += nums2[j]; j += 1
    else:                              # 相等 ⇒ 公共值 c
        ans += max(s1, s2) + nums1[i]  # 段结算 + 公共值（只计一次）
        s1 = s2 = 0
        i += 1; j += 1                 # 双指针齐进
ans += max(s1, s2)                    # 尾段（也覆盖「无公共值」情形）
return ans % (10⁹ + 7)
```

### 3.4 示例演算

![示例一演算：双指针全过程与两次结算](images/1537_example_walkthrough.svg)

以示例 1 为例，`nums1 = [2,4,5,8,10]`，`nums2 = [4,6,8,9]`（公共值 4、8）：

| 步 | (i,j) | 比较 | 动作 | s1 | s2 | ans |
|----|-------|------|------|----|----|-----|
| ① | (0,0) | 2 < 4 | s1 += 2，i++ | 2 | 0 | 0 |
| ② | (1,0) | 4 = 4 | 结算 max(2,0)+4，清零，i++、j++ | 0 | 0 | 6 |
| ③ | (2,1) | 5 < 6 | s1 += 5，i++ | 5 | 0 | 6 |
| ④ | (3,1) | 6 < 8 | s2 += 6，j++ | 5 | 6 | 6 |
| ⑤ | (3,2) | 8 = 8 | 结算 max(5,6)+8，清零，i++、j++ | 0 | 0 | 20 |
| ⑥ | (4,3) | 9 < 10 | s2 += 9，j++ | 0 | 9 | 20 |
| ⑦ | (4,4) | j 越界 | s1 += 10，i++ | 10 | 9 | 20 |
| ⑧ | 结束 | — | ans += max(10,9)（尾段） | 10 | 9 | **30** |

对应最优路径 $2 \to 4 \to 6 \to 8 \to 10$：段①③走 `nums1`、段②走 `nums2`，**答案 30** ✓。

> 💡 注意第 ⑤ 步：结算时 $s_1 = 5$、$s_2 = 6$，段②两侧段和不相同，取大者 6 正是「在 4 处切去 nums2」的收益；若两侧段和相等，切与不切等价，不影响最优值。

## 4. 算法细节

1. **谁小走谁 + 越界优先**：`if` 的条件把「一侧已耗尽」放在数值比较**之前**短路——`j == m` 时视 `nums1[i]` 更小（反之亦然），保证一侧耗尽后剩余元素全部灌进另一侧的段和，这正是**尾段**的形成过程。
2. **$s_1 / s_2$ 的语义**：自**上一公共值**以来两数组各自走过的元素和。遇公共值结算 $\max(s_1, s_2) + c$ 后**必须清零**——新段从公共值之后重新起算；公共值本身已在结算时计入，绝不能留在段和里重复计。
3. **尾段结算**：主循环条件是 `i < n or j < m`，退出时 $s_1, s_2$ 恰为最后一个公共值之后的尾段和，`ans += max(s1, s2)` 一次性结算。**无公共值**（$k = 0$）时全程只有这一个 max，答案 $= \max(\sum \mathrm{nums1},\ \sum \mathrm{nums2})$，无需特判（示例 3）。
4. **取模时机**：全程用 64 位整数（Python 天然大整数），**只在 `return` 时取一次模**。$s_1, s_2$ 绝不能边加边取模——`max` 需要真实大小，中途取模会破坏可比性（见 §8 第 3 条）。答案上界约为 $2 \times 10^{12}$，`long long` 绰绰有余。
5. **归并即定位**：严格递增保证公共值按升序在两数组中各出现至多一次，双指针归并天然完成「公共值配对」，不需要哈希表。若想显式分段，也可预处理**前缀和 + 哈希定位公共值**，按 §5 公式逐段累加，复杂度同为 $O(n+m)$、空间 $O(n+m)$——双指针是它的 $O(1)$ 空间滚动版。
6. **DP 视角**：设 $F_t$ 为「到达公共值 $c_t$ 且刚收集完 $c_t$」的最优得分，则 $F_t = F_{t-1} + \max(a_t, b_t) + c_t$、$F_0 = 0$，答案 $= F_k + \max(a_{k+1}, b_{k+1})$——一维 DP，$s_1 / s_2$ 就是它「当前段部分和」的实现；3.1 中 $f_1[i] / f_2[j]$ 的双状态在公共值处被合并坍缩成单状态。

## 5. 正确性证明

**约定**：公共值按升序记为 $c_1 < c_2 < \cdots < c_k$；设哨兵 $c_0 = -\infty$、$c_{k+1} = +\infty$。第 $t$ 段（$1 \le t \le k+1$）指两数组中值**严格介于** $c_{t-1}$ 与 $c_t$ 之间的元素，$a_t$ 为 nums1 侧元素之和、$b_t$ 为 nums2 侧元素之和。由严格递增性，每个 $c_t$ 在每个数组中至多出现一次，且两数组中的公共值序列同序——双指针归并可**不重不漏**地配对全部公共值。

**引理 1（段结构）**：合法路径与「为每段 $t$ 独立指定所在数组 $\sigma_t \in \{1, 2\}$」的选择序列一一对应，且路径得分恰为

$$\mathrm{score}(\sigma) \;=\; \sum_{t=1}^{k+1} \mathrm{seg}(t, \sigma_t) \; + \; \sum_{t=1}^{k} c_t, \qquad \mathrm{seg}(t, \sigma) \in \{a_t,\ b_t\}$$

**证明**：设路径已收集 $c_{t-1}$、当前位于某数组。第 $t$ 段内的值都不是公共值，而切换**只允许**发生在公共值处，故路径在整个第 $t$ 段内停留在进入时的数组上；遍历是从左到右连续进行的，它必然依序收集该数组此段的**全部**元素，贡献 $a_t$ 或 $b_t$。段末必遇 $c_t$（它同时在两条数组上），收集值 $c_t$；数组严格递增且路径上的值单调上升，每个值至多被计一次，公共值恰计一次。对 $t$ 归纳即得得分公式。反之，任给选择序列 $\sigma$：从 $\sigma_1$ 侧的下标 0 出发，在每个 $c_t$ 处按 $\sigma_t \ne \sigma_{t+1}$ 决定是否切换，得到合法路径。两个构造互逆，构成双射。∎

**引理 2（无后效性）**：设 $F_t$ 为「到达 $c_t$ 且已收集 $c_t$」的路径前缀的最大得分（$F_0 = 0$ 为虚拟起点），则 $F_t = F_{t-1} + \max(a_t, b_t) + c_t$，且 $F_t$ 与到达 $c_t$ 时所在的数组无关。

**证明**：对 $t$ 归纳。由引理 1，到达 $c_t$ 的任意前缀由 $\sigma_1, \ldots, \sigma_t$ 决定，得分为 $\sum_{u \le t} \mathrm{seg}(u, \sigma_u) + \sum_{u \le t} c_u$；各 $\sigma_u$ 的**任意组合**都对应合法前缀（引理 1 的反向构造），故最大化时可逐段独立取大，得 $F_t = \sum_{u \le t} \max(a_u, b_u) + \sum_{u \le t} c_u = F_{t-1} + \max(a_t, b_t) + c_t$。「与所在数组无关」：站在值 $c_t$ 上，后续可选的 $\sigma_{t+1}, \ldots$ 与历史完全无关（在 $c_t$ 处切或不切皆可），故 $F_t$ 是良定义的单一数值。∎

**定理（最优得分公式）**：

$$\mathrm{ans} \;=\; \sum_{t=1}^{k+1} \max(a_t,\ b_t) \; + \; \sum_{t=1}^{k} c_t$$

且 $k = 0$（无公共值）时 $\mathrm{ans} = \max\bigl(\sum \mathrm{nums1},\ \sum \mathrm{nums2}\bigr)$。

**证明**：完整路径的得分由引理 1 给出；最后一段的选择 $\sigma_{k+1}$ 同时决定路径终止于哪个数组的末尾，其贡献即 $\max(a_{k+1}, b_{k+1})$。由引理 1 的双射，最大化得分等价于对每段独立地在 $\{a_t, b_t\}$ 中选边；由引理 2，这些选择互不干扰（任意组合均合法），故 $\max_{\sigma} \mathrm{score}(\sigma) = \sum_t \max(a_t, b_t) + \sum_t c_t$。$k = 0$ 时仅有一段，$a_1 = \sum \mathrm{nums1}$、$b_1 = \sum \mathrm{nums2}$。∎

**命题（算法实现公式）**：上述双指针算法的返回值等于定理中的公式。

**证明**：循环不变式：任意时刻 $s_1$（$s_2$）等于「自上一次公共值结算以来 nums1（nums2）已累入的元素之和」，即当前段的部分和。归纳于结算次数 $t$：第 $t$ 次指针相遇时，由不变式 $s_1 = a_t$、$s_2 = b_t$，且 ans 中已累计的恰为 $F_{t-1}$；执行 `ans += max(s1,s2) + c` 后 ans 增量为 $\max(a_t, b_t) + c_t$，即 $F_t - F_{t-1}$；清零后不变式对第 $t+1$ 段保持。两指针每轮至少一个前进且从不回退，故全部公共值按序各触发一次结算（归并配对的完备性）；循环退出时 $s_1 = a_{k+1}$、$s_2 = b_{k+1}$，循环外的 `ans += max(s1, s2)` 完成最后一段结算。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。每轮循环 $i$ 或 $j$ 至少前进 1，总轮数不超过 $n + m$，每轮 $O(1)$。$n, m \le 10^5$ 时约 $2 \times 10^5$ 次操作，轻松通过。
- **空间复杂度**：$O(1)$。仅指针与若干计数器，不需要前缀和数组与哈希表；若采用「前缀和 + 哈希」写法则为 $O(n + m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maxSum(vector<int>& nums1, vector<int>& nums2) {
        const long long MOD = 1000000007;
        const int n = nums1.size(), m = nums2.size();
        long long s1 = 0, s2 = 0, ans = 0;   // s1/s2：自上一公共值以来的段和
        int i = 0, j = 0;
        while (i < n || j < m) {
            if (j == m || (i < n && nums1[i] < nums2[j])) {
                s1 += nums1[i++];             // 谁小走谁；一侧耗尽则灌另一侧
            } else if (i == n || nums2[j] < nums1[i]) {
                s2 += nums2[j++];
            } else {                          // 相等 ⇒ 公共值
                ans += max(s1, s2) + nums1[i];
                s1 = s2 = 0;
                ++i; ++j;
            }
        }
        ans += max(s1, s2);                   // 尾段（含无公共值情形）
        return ans % MOD;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, nums1: List[int], nums2: List[int]) -> int:
        MOD = 10 ** 9 + 7
        n, m = len(nums1), len(nums2)
        i = j = 0
        s1 = s2 = ans = 0          # s1/s2：自上一公共值以来的段和

            if j == m or (i < n and nums1[i] < nums2[j]):
                s1 += nums1[i]     # 谁小走谁；一侧耗尽则灌另一侧
                i += 1
            elif i == n or nums2[j] < nums1[i]:
                s2 += nums2[j]
                j += 1
            else:                  # 相等 ⇒ 公共值
                ans += max(s1, s2) + nums1[i]
                s1 = s2 = 0
                i += 1
                j += 1
```

## 8. 边界情况与易错点

1. **无公共值**：循环中永远走不到 else 分支，全程只做累积，尾语句 `ans += max(s1, s2)` 直接给出 $\max(\text{两总和})$（示例 3 得 40）——**不需要特判**，但也**不能漏掉**这一句。
2. **公共值只计一次**：结算公式是 $\max(s_1, s_2) + c$，两指针同时前移。写成 $s_1 + s_2 + c$（两侧都算）或漏写清零（旧段和混入新段）都会算重；漏写 `+ c` 则丢公共值。
3. **中途取模毁掉 max**：若对 $s_1, s_2$ 边加边取模，比较时真实大小关系可能被破坏——例如真实 $s_1 = 10^9 + 8 > s_2 = 5$，取模后 $s_1 = 1$，max 误选 5。**全程 64 位、最后取一次模**；Python 大整数无溢出之忧，但同样别在比较前取模。
4. **C++ 用 `long long`**：$n \cdot \max(v) = 10^5 \times 10^7 = 10^{12}$，`int` 必溢出；ans 上界约 $2 \times 10^{12}$，`long long` 安全。
5. **首/尾即公共值**：开局即公共值（首段一侧为空，结算 $\max(0,0) + c$）或末尾公共值之后一侧为空段和 0，`max` 都自然处理，无需特判。
6. **一个数组的元素全是公共值**：如 `nums1 = [1,2]`、`nums2 = [1,2]`，每段两侧段和全为 0，答案只剩公共值之和 3，验证清零逻辑无误。
7. **越界判断顺序**：`j == m`（或 `i == n`）必须放在数值比较**之前**短路，否则 `nums1[i] < nums2[j]` 会访问越界下标。
8. **循环条件是「或」不是「且」**：`i < n || j < m`——两侧都耗尽才结束；误写成 `&&` 会在一侧先耗尽时提前退出，丢掉另一侧的尾段。
9. **对拍用前缀和公式**：预处理两数组前缀和 + 哈希定位公共值位置，按定理公式逐段累加，可与双指针实现互验——两者是同一公式的不同实现。

**延伸思考**：

- **求最小得分**：把每段的 $\max$ 换成 $\min$ 即可——引理 1 的双射与「逐段独立选择」的论证原样平移，同一公式族。
- **最优路径计数**：对 $a_t = b_t$ 的段存在两种并列最优选边，按乘法原理累乘；注意先明确「路径同一性」按取值序列还是按物理走法定义——尾段两侧段和相等时，取值序列相同但终点所在数组不同。
- **推广到 $k$ 条严格递增数组**：仍在值轴上归并，在各组「公共值」处做状态合并、保留各数组当前段和；切换点从「两数组公共」推广为「所在子集公共」，依旧线性时间，但状态合并需按值的出现数组集合分情形讨论。
