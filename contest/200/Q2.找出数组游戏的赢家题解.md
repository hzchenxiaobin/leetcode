# LeetCode 找出数组游戏的赢家 题解

## 1. 题目概述

- **标题 / 题号**：找出数组游戏的赢家（#1535，medium）
- **链接**：https://leetcode.cn/problems/find-the-winner-of-an-array-game/
- **来源**：LeetCode 第 200 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：给定一个由**互不相同**的整数组成的数组 `arr` 和整数 `k`。每回合比较数组前两个元素 `arr[0]` 与 `arr[1]`：较大者获胜并**留在位置 0**，较小者**移到数组末尾**。当某个整数**连续赢得 k 个回合**时游戏结束，它就是赢家。返回赢家（题目数据保证存在赢家）。

**约束**：

- `2 <= arr.length <= 10^5`
- `1 <= arr[i] <= 10^6`，元素互不相同
- `1 <= k <= 10^9` —— 关键陷阱：k 远大于 n，不能逐轮硬模拟

## 2. 示例

**示例 1**

```text
输入：arr = [2,1,3,5,4,6,7], k = 2
输出：5
解释：4 个回合依次为 2 vs 1（2 胜）、2 vs 3（3 胜）、3 vs 5（5 胜）、5 vs 4（5 胜），
      5 连胜 2 回合，成为赢家。
```

**示例 2**

```text
输入：arr = [3,2,1], k = 10
输出：3
解释：3 在前 10 个回合中连续获胜（n−1 = 2 轮后 3 已是全局最大，此后永恒卫冕）。
```

**示例 3**

```text
输入：arr = [1,9,8,2,3,7,6,4,5], k = 7
输出：9
解释：第 1 轮 9 击败 1，随后连胜 8、2、3、7、6、4，第 7 轮达成 k = 7（仍在第一圈内）。
```

**示例 4**

```text
输入：arr = [1,11,22,33,44,55,66,77,88,99], k = 1000000000
输出：99
解释：k ≫ n，第一圈结束后的擂主 99 = max(arr) 将永远连胜，赢家必为 99。
```

## 3. 解题思路

### 3.1 暴力思路

用双端队列忠实还原比赛：每轮比较队首两个元素，败者 `push_back` 到队尾，给胜者计连胜；连胜达 `k` 即返回。

问题在复杂度：第一圈至多 `n−1` 轮会把全局最大值推上擂主之位，此后擂主不再失败，再连赢至多 `k−1` 轮游戏必然结束——总轮数是 $O(n+k)$。本题 $k \le 10^9$，逐轮模拟约 $10^9$ 次必然超时；若还用 `list.pop(0)` / `erase` 搬移元素，更是每轮 $O(n)$，直接不可行。**必须利用"第二圈起永恒卫冕"的结构，把复杂度降到与 k 无关。**

### 3.2 核心观察：擂主是前缀最大值，一趟扫描足矣

![核心观察：败者去队尾但对手顺序不变，擂主为前缀最大值](images/array_game_champion_prefix_max.svg)

两个观察：

1. **对手顺序不变**：败者被移到队尾时，排在所有"未上场"元素**之后**，因此第一圈的 `n−1` 轮里，擂主遇到的挑战者依次恰为 `arr[1], arr[2], …, arr[n−1]`——**第 i 轮就是比较 $\max(arr[0..i-1])$ 与 $arr[i]$**，与队列怎么旋转无关。
2. **擂主单调不减**：擂主只在遇到更大元素时被替换，所以擂主序列就是**前缀最大值序列**。**一旦扫完整个数组，擂主 = max(arr)**，此后每轮必胜、连胜只增不减，游戏必在其后有限轮内结束，赢家必是它。

于是整个游戏只取决于"第一圈"的 `n−1` 次比较，单趟扫描即可完全复现：

- 若游戏在第一圈内结束：逐轮维护 `(擂主 cur, 连胜 cnt)`，途中 `cnt == k` 立即返回；
- 若第一圈扫完仍未达成 `k`（挑战者一路递增不断换擂，或 `k` 过大如示例 2/4）：此时 `cur` 已等于 `max(arr)`，由观察 2 它此后永恒卫冕，赢家必是它——**直接返回 cur，后面 ~k 轮完全不用模拟**。这正是 $k \le 10^9$ 陷阱的破解点。

> 💡 一句话总结：别盯着队列怎么搬，盯住**擂主本身**——它是前缀最大值，一趟线性扫描就拿到了游戏的全部有效信息。

### 3.3 算法流程

![单趟扫描算法流程](images/array_game_one_pass_flow.svg)

```text
cur = arr[0], cnt = 0            # cur：当前擂主；cnt：cur 的当前连胜
for i = 1 to n-1:
    if arr[i] > cur: cur = arr[i], cnt = 1    # 换擂：新擂主当轮即第 1 胜
    else:           cnt = cnt + 1             # 卫冕成功
    if cnt == k: return cur                   # 达成 k 连胜，游戏结束
return cur                                    # 扫描结束 ⇒ cur = max(arr)
```

### 3.4 示例演算

![示例一演算：四轮比赛与连胜计数](images/array_game_rounds_walkthrough.svg)

示例 1 的四轮如表：擂主从 2 一路换到 5，第 4 轮 5 卫冕后连胜达到 `k = 2`，返回 5 ✓。此时 `arr[5] = 6`、`arr[6] = 7` 根本不必再扫——5 已先达成条件。

示例 2（`k = 10`）：扫描结束后 `cur = 3 = max(arr)`，由观察 2 它此后永恒卫冕、连胜终会到 10，直接返回 3 ✓。

## 4. 算法细节

1. **变量含义**：`cur` 是当前擂主（= 已扫前缀的最大值），`cnt` 是 `cur` 的当前连胜数；循环变量 `i` 同时就是"第 i 轮挑战者"的下标。
2. **换擂重置 cnt = 1 而非 0**：新擂主击败旧擂主的那一轮就是它的第 1 胜（示例 1 第 3 轮：5 胜 3 后 cnt 立即为 1）。初始 `cnt = 0` 是因为 `arr[0]` 尚未比过任何回合。
3. **统一检查 `cnt == k`**：换擂与卫冕两个分支都可能达成 k（`k = 1` 时第一轮即结束），检查放在分支之后统一进行，随后提前 `return`。
4. **循环自然结束即返回 cur**：此时 `cur` 已是 `max(arr)`，由观察 2 它就是赢家，无需继续模拟第二圈。
5. **不搬移任何元素**：旋转只影响第二圈及以后的对手顺序，而第一圈顺序恰是原数组顺序、第二圈结果完全由 `max(arr)` 决定——两个信息都不需要真实的队列。
6. **元素互不相同**：无平局，严格 `>` 比较即可；这也是引理中"严格更大/更小"成立的前提。

## 5. 正确性证明

**引理 1（对手顺序）**：对 $1 \le i \le n-1$，第 $i$ 轮比较的双方是 $\max(arr[0..i-1])$ 与 $arr[i]$。

**证明**：对 $i$ 归纳。$i = 1$ 时队列即原数组，比较 $arr[0]$ 与 $arr[1]$，成立。设第 $i-1$ 轮结束后队列形如 $[\,\max(arr[0..i-1]),\ arr[i],\ \ldots,\ arr[n-1],\ \text{已败元素（按落败顺序）}\,]$。第 $i$ 轮比较队首两元素，即 $\max(arr[0..i-1])$ 与 $arr[i]$；败者被追加到队尾，位于全部未上场元素之后，队首前段不变，归纳不变式保持。∎

**引理 2（扫完即永恒卫冕）**：若游戏在前 $n-1$ 轮内未结束，则第 $n-1$ 轮后的擂主为 $\max(arr)$，此后它每轮都获胜，游戏必然结束且赢家为 $\max(arr)$。

**证明**：由引理 1，第 $n-1$ 轮后的擂主为 $\max(arr[0..n-1]) = \max(arr)$。数组中其余 $n-1$ 个元素均严格小于它，故此后任何一轮的挑战者都被它击败，其连胜数每轮加一、单调不减，有限轮内达到 $k$。∎

**定理**：算法返回值即游戏赢家。

**证明**：分两种情况。

- **游戏在前 $n-1$ 轮内结束**（设结束于第 $i$ 轮）：由引理 1，算法第 $i$ 次迭代的比较双方 $(cur,\ arr[i])$ 与真实比赛完全一致；连胜计数亦逐轮同步——真实比赛中换擂当轮新擂主连胜记 1、卫冕加 1，与算法的更新规则逐字相同。故算法恰在第 $i$ 次迭代检测到 $cnt = k$，返回该轮擂主，即赢家。
- **游戏未在前 $n-1$ 轮内结束**：由引理 2，赢家为 $\max(arr)$；算法此时恰好完成整个循环，返回 $cur = \max(arr)$。

两种情况返回值均与游戏赢家一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描，循环至多 `n−1` 次（$n \le 10^5$），**与 k 无关**——这就是 $k \le 10^9$ 也能瞬间出解的原因。
- **空间复杂度**：$O(1)$。仅 `cur`、`cnt`、`i` 三个变量，不建队列、不搬移元素。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int getWinner(vector<int>& arr, int k) {
        int cur = arr[0];   // 当前擂主 = 已扫前缀的最大值
        int cnt = 0;        // cur 的当前连胜
        for (int i = 1; i < (int)arr.size(); i++) {
            if (arr[i] > cur) {
                cur = arr[i];   // 换擂：新擂主当轮即第 1 胜
                cnt = 1;
            } else {
                cnt++;          // 卫冕成功
            }
            if (cnt == k) return cur;  // 达成 k 连胜，游戏结束
        }
        return cur;  // 扫完数组：cur = max(arr)，必为赢家
    }
};
```

### Python

```python
class Solution:
    def getWinner(self, arr: List[int], k: int) -> int:
        cur, cnt = arr[0], 0   # cur：擂主；cnt：当前连胜
        for x in arr[1:]:      # x 依次是第 1..n-1 轮的挑战者
            if x > cur:
                cur, cnt = x, 1   # 换擂：新擂主当轮即第 1 胜
            else:
                cnt += 1          # 卫冕成功
            if cnt == k:
                return cur        # 达成 k 连胜，游戏结束
        return cur  # 扫完数组：cur = max(arr)，必为赢家
```

## 8. 边界情况与易错点

1. **k 高达 $10^9$**：逐轮模拟（哪怕 deque 每轮 $O(1)$）是 $O(n+k)$，必超时；正解必须一趟扫描 + "扫完返回 cur"。
2. **换擂重置 cnt = 1，不是 0**：击败旧擂主的当轮就是新擂主的第 1 胜，写成 0 会漏算一轮。
3. **k = 1**：第 1 轮结束即返回 $\max(arr[0], arr[1])$；`cnt == k` 的检查必须对两个分支统一生效。
4. **循环退出后返回 cur**（= max(arr)），别误返回 `arr[0]`，也不必再开一趟求最大值。
5. **对拍暴力用 deque**：若写队列模拟版对拍，用 `collections.deque` / `std::deque`，别用 `list.pop(0)` / `erase`（每轮 $O(n)$）。
6. **元素互不相同 ⇒ 无平局**：严格 `>` 即可；若变体允许重复，需先约定平局规则再改比较符。
7. **n = 2**：仅一轮比较；`k = 1` 立即返回较大者，`k > 1` 扫描结束返回较大者，逻辑自洽。
8. **"扫不完"未必意味着 k > n−1**：递增数组（如 `[1,2,3,4,5]`，`k = 2`）每轮都换擂、连胜始终为 1，第一圈也凑不出 k——但兜底返回 `cur = max(arr)` 依然正确。
