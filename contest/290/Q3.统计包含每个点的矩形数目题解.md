# LeetCode 统计包含每个点的矩形数目 题解

## 1. 题目概述

- **标题 / 题号**：统计包含每个点的矩形数目（#2250，medium）
- **链接**：https://leetcode.cn/problems/count-number-of-rectangles-containing-each-point/
- **来源**：LeetCode 第 290 场周赛 Q3
- **难度**：中等
- **标签**：树状数组、数组、哈希表、二分查找、排序

**题意**：给定二维整数数组 `rectangles`，其中 `rectangles[i] = [li, hi]` 表示第 $i$ 个矩形左下角在原点、右上角在 $(l_i, h_i)$。再给定数组 `points`，其中 `points[j] = [xj, yj]`。要求返回数组 `count`，`count[j]` 为**包含**点 $(x_j, y_j)$ 的矩形数目。点在矩形**边上**也算被包含，即 $0 \le x_j \le l_i$ 且 $0 \le y_j \le h_i$。

**约束**：

- $1 \le \mathrm{rectangles.length},\ \mathrm{points.length} \le 5 \times 10^4$
- $1 \le l_i,\ x_j \le 10^9$
- $1 \le h_i,\ y_j \le 100$
- 所有矩形互不相同，所有点互不相同

> 💡 这题的全部戏眼藏在约束的**不对称**里：横向 $l, x$ 可以大到 $10^9$，纵向 $h, y$ 却被压在 $[1, 100]$。「一维巨大、一维极小」几乎是在明示——**把小维度当桶下标，把大维度留给二分**。

## 2. 示例

**示例 1**

```text
输入：rectangles = [[1,2],[2,3],[2,5]], points = [[2,1],[1,4]]
输出：[2,1]
解释：第二个矩形 (2,3) 包含 (2,1)；第三个矩形 (2,5) 包含 (2,1) 和 (1,4)。
      点 (2,1) 恰在两个矩形的右边上（x = l = 2），也算包含。
      包含 (2,1) 的矩形有 2 个，包含 (1,4) 的只有 1 个。
```

**示例 2**

```text
输入：rectangles = [[1,1],[2,2],[3,3]], points = [[1,3],[1,1]]
输出：[1,3]
解释：只有 (3,3) 高度够到 (1,3)，故答案为 1；
      三个矩形都包含 (1,1)，故答案为 3。
```

**边界示例（点在边上）**

```text
输入：rectangles = [[5,3]], points = [[5,3]]
输出：[1]
解释：点恰为矩形的右上角，x = l 且 y = h，视为包含。
```

## 3. 解题思路

### 3.1 暴力思路

对每个点独立地扫一遍所有矩形，逐个判定 $x_j \le l_i$ 且 $y_j \le h_i$。总判定次数 $n \times q = (5 \times 10^4)^2 = 2.5 \times 10^9$，无论 C++ 还是 Python 都必然超时。必须让每个查询的代价降到 polylog 级别，或者至少把「矩形」预处理成可复用的结构。

另一个方向的死路同样值得一看：想开一个二维计数数组 `cnt[l][h]` 做**前缀和**，$O(1)$ 回答查询——但 $l$ 高达 $10^9$，值域数组直接爆炸。这提醒我们：**长度的巨大值域只能靠排序 + 二分（或离散化）来消化**。

### 3.2 核心观察：h ≤ 100，按高度分桶

![核心观察：h ≤ 100 是钥匙，l ≤ 10⁹ 交给二分](images/2250_rect_bucket_concept.svg)

**观察 A（判定是两个独立不等式）**：由于 $x_j, y_j \ge 1 > 0$，包含条件 $0 \le x_j \le l_i \wedge 0 \le y_j \le h_i$ 中左侧恒成立，等价于

$$l_i \ge x_j \ \wedge\ h_i \ge y_j$$

——矩形与点之间**没有任何耦合**，就是两条独立的一维比较。问题化为纯粹的**二维计数**：数有多少个矩形对 $(l_i, h_i)$ 落在「以 $(x_j, y_j)$ 为左上角的左下无限区域」里。

**观察 B（高度维度极小）**：$h_i, y_j \in [1, 100]$。以 $h$ 为下标建 100 个桶，`buckets[h]` 收集**所有满足 $h_i \ge h$ 的矩形的 $l_i$**（注意是 $\ge$ 不是 $=$，即「后缀」语义）。则查询 $(x, y)$ 的答案就是

$$\mathrm{ans}_j = \#\{\, l \in \mathrm{buckets}[y_j] : l \ge x_j \,\}$$

桶内排序后一次**二分查找**（`bisect_left` / `lower_bound`）即得，长度的 $10^9$ 值域被二分的 $O(\log n)$ 完全消化。

**观察 C（桶可以增量合并）**：`buckets[h]` 与 `buckets[h+1]` 只差「$h_i$ 恰好等于 $h$ 的那批矩形」。先把 $h_i = h$ 的 $l_i$ 放进 `equal[h]`，再**从 $h = 100$ 向 $h = 1$ 逐层归并**：`buckets[h] = merge(equal[h], buckets[h+1])`。两个来源各自有序，归并（或排序）代价线性。

### 3.3 算法流程

![算法流程：分桶、后缀归并、单点二分](images/2250_rect_query_flow.svg)

```text
1. equal[h] ← { lᵢ : hᵢ = h }        （h ∈ [1, 100]，共 100 个桶）
2. for h = 100 down to 1：
       buckets[h] ← merge(equal[h], buckets[h+1])，保持有序
3. 对每个查询 (xⱼ, yⱼ)：
       ans[j] ← len(buckets[yⱼ]) − bisect_left(buckets[yⱼ], xⱼ)
4. 返回 ans
```

`bisect_left(arr, x)` 返回 `arr` 中**第一个 ≥ x 的下标**，因此 `len(arr) − bisect_left(arr, x)` 恰是「≥ x 的元素个数」。

### 3.4 示例演算

![示例演算：三个矩形分桶、归并与两次查询](images/2250_rect_walkthrough.svg)

对示例 1 走查（`rectangles = [[1,2],[2,3],[2,5]]`）：

| 步骤 | 内容 |
|------|------|
| 分桶 | `equal[5] = [2]`，`equal[3] = [2]`，`equal[2] = [1]`，其余为空 |
| 归并（100→1） | `buckets[5] = [2]` → `buckets[4] = [2]` → `buckets[3] = [2,2]` → `buckets[2] = [1,2,2]` → `buckets[1] = [1,2,2]` |
| 查询 (2,1) | `buckets[1] = [1,2,2]`，`bisect_left(·, 2) = 1`，答案 $3 - 1 = 2$ ✓ |
| 查询 (1,4) | `buckets[4] = [2]`，`bisect_left(·, 1) = 0`，答案 $1 - 0 = 1$ ✓ |

注意 `buckets[4] = [2]` 的来源：只有 $(2,5)$ 的 $h = 5 \ge 4$；$(2,3)$ 的 $h = 3 < 4$，尽管它的 $l = 2 \ge 1$ 也进不了这个桶——这正是「后缀」语义在起作用。

## 4. 算法细节

1. **桶开 101/102 个，下标 $1 \sim 100$**：$h = 100$ 的桶也需要保证有序——若归并循环只跑到 $h = 99$，`buckets[100]` 就是未经排序的 `equal[100]`，查询 $y_j = 100$ 时直接出错。最省心的写法是把数组开到下标 101（留一个空桶 101），循环 `for h in range(100, 0, -1)` 统一处理。
2. **归并方向必须从大到小**：`buckets[h]` 吸收 `buckets[h+1]`，语义是后缀 $\{i : h_i \ge h\}$。方向写反就成了前缀 $\{i : h_i \le h\}$，整个算法语义颠覆。
3. **两个有序序列的合并用归而非反复排序**：C++ 用 `inplace_merge`（线性）；Python 直接 `sorted(a + b)`，排序在 C 层完成，总量最坏 $O(100\,n \log n)$ 也够快（见 §6）。
4. **空间上界的直观估计**：第 $i$ 个矩形会出现在 `buckets[1..hᵢ]` 共 $h_i$ 个桶里，总元素数 $\sum_i h_i \le 100 n = 5 \times 10^6$（C++ `int` 约 20 MB）。若内存敏感，可退化为「不归并、查询时对 `equal[y..100]` 逐桶二分求和」：空间 $O(n)$，时间 $O(100\,q \log n)$，C++ 同样轻松通过，只是 Python 下 $5 \times 10^6$ 次 `bisect` 调用偏慢。本文主推归并版。
5. **空桶共享引用（Python 小优化）**：`if not buckets[h]: buckets[h] = buckets[h+1]` 直接复用下层桶的引用（只读不写），大量 $h_i$ 集中在高位时能显著减少复制的列表。注意共享后**不得再修改**任何桶。
6. **`l` 重复是正常现象**：矩形互不相同只保证 $(l_i, h_i)$ 二元组不重复，不同高度的矩形可以有相同的 $l$，桶内出现重复值不影响计数语义（多重集）。

## 5. 正确性证明

**引理 1（包含刻画）**：矩形 $i$ 包含点 $(x, y)$ $\iff$ $l_i \ge x$ 且 $h_i \ge y$。

**证明**：按题意，包含即 $0 \le x \le l_i$ 且 $0 \le y \le h_i$。由约束 $x, y \ge 1$，左侧不等式 $0 \le x$、$0 \le y$ 恒成立，条件简化为 $x \le l_i \wedge y \le h_i$。∎

**引理 2（后缀桶归纳）**：对每个 $h \in [1, 100]$，归并结束后 `buckets[h]` 作为多重集恰为 $\{\, l_i : h_i \ge h \,\}$，且有序。

**证明**：对 $h$ 自 100 向 1 归纳。奠基 $h = 100$：`buckets[100] = merge(equal[100], buckets[101])`，而空桶 `buckets[101]` 为空集、`equal[100]` 恰为 $\{l_i : h_i = 100\} = \{l_i : h_i \ge 100\}$，且 `equal[100]` 排序后有序。归纳步：设 `buckets[h+1]` $= \{l_i : h_i \ge h+1\}$ 有序，则

$$\mathrm{buckets}[h] = \mathrm{equal}[h] \uplus \mathrm{buckets}[h{+}1] = \{l_i : h_i = h\} \uplus \{l_i : h_i \ge h+1\} = \{l_i : h_i \ge h\}$$

（$\uplus$ 为多重集不交并：$h_i = h$ 与 $h_i \ge h+1$ 互斥且穷尽 $h_i \ge h$）。两个有序序列归并结果仍有序。∎

**引理 3（二分计数）**：对长度为 $m$ 的非降序列 $A$，$m - \mathrm{bisect\_left}(A, x) = \#\{\, a \in A : a \ge x \,\}$。

**证明**：`bisect_left(A, x)` 返回第一个满足 $A[k] \ge x$ 的最小下标 $k$，故 $A[0..k-1]$ 恰为全部 $< x$ 的元素（非降序列中它们必然连成前缀），共 $k$ 个；$A[k..m-1]$ 全部 $\ge x$，共 $m - k$ 个。∎

**定理**：算法对每个查询 $(x_j, y_j)$ 返回的正是包含该点的矩形数目。

**证明**：由引理 2，`buckets[y_j]` 是多重集 $\{l_i : h_i \ge y_j\}$ 的有序化；由引理 3，`len − bisect_left` 数出其中 $l_i \ge x_j$ 的元素个数，即同时满足 $l_i \ge x_j$ 与 $h_i \ge y_j$ 的二元组 $(l_i, h_i)$ 个数（多重集计数与矩形一一对应）。由引理 1，这正是包含点 $(x_j, y_j)$ 的矩形数目。∎

## 6. 复杂度分析

- **时间复杂度**：C++ 归并版 $O(n \log n + 100\,n + q \log n)$——分桶后单桶排序合计 $O(n \log n)$，100 层线性归并合计至多 $O(100 n) = 5 \times 10^6$，每次查询一次二分 $O(\log n) \approx 17$ 次比较。Python 的逐层 `sorted(a+b)` 上界 $O(100\,n \log n) \approx 8.5 \times 10^7$ 次比较，但排序是 C 实现，实测远快于同规模的 Python 级循环。对比暴力的 $2.5 \times 10^9$ 次判定，快了两个数量级以上。
- **空间复杂度**：$O(100\,n)$，即后缀桶的总元素数 $\sum_i h_i \le 5 \times 10^6$（C++ 约 20 MB）。若采用「不归并、逐桶二分」的变体可降到 $O(n)$，代价是查询侧乘上 100 倍二分；离线 + 树状数组版（§7 备选）则是 $O(n + q)$ 空间、$O((n+q)\log(n+q))$ 时间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> countRectangles(vector<vector<int>>& rectangles, vector<vector<int>>& points) {
        vector<vector<int>> buckets(102);
        for (auto& r : rectangles) {
            buckets[r[1]].push_back(r[0]);
        }
        for (int h = 100; h >= 1; --h) {
            auto& cur = buckets[h];
            sort(cur.begin(), cur.end());
            auto& nxt = buckets[h + 1];
            size_t keep = cur.size();
            cur.insert(cur.end(), nxt.begin(), nxt.end());
            inplace_merge(cur.begin(), cur.begin() + keep, cur.end());
        }
        vector<int> ans;
        ans.reserve(points.size());
        for (auto& p : points) {
            auto& arr = buckets[p[1]];
            ans.push_back((int)(arr.end() - lower_bound(arr.begin(), arr.end(), p[0])));
        }
        return ans;
    }
};
```

### Python

```python
from bisect import bisect_left

class Solution:
    def countRectangles(self, rectangles: List[List[int]], points: List[List[int]]) -> List[int]:
        buckets = [[] for _ in range(102)]
        for l, h in rectangles:
            buckets[h].append(l)
        for h in range(100, 0, -1):
            if not buckets[h]:
                buckets[h] = buckets[h + 1]
            else:
                buckets[h] = sorted(buckets[h] + buckets[h + 1])
        return [len(buckets[y]) - bisect_left(buckets[y], x) for x, y in points]
```

### 备选：离线 + 树状数组版（Python）

把矩形看作 $(l_i, h_i)$ 平面上的点，查询即「数 $l \ge x$ 且 $h \ge y$ 的点数」——标准**二维偏序计数**。按 $y$ 从大到小离线处理，用树状数组维护已加入矩形的 $l$ 的离散化前缀计数，就不再依赖 $h \le 100$：

```python
from bisect import bisect_left

class Solution:
    def countRectangles(self, rectangles: List[List[int]], points: List[List[int]]) -> List[int]:
        vals = sorted({l for l, _ in rectangles} | {x for x, _ in points})
        m = len(vals)
        tree = [0] * (m + 1)

        def add(i):
            i += 1
            while i <= m:
                tree[i] += 1
                i += i & -i

        def acc(i):
            s = 0
            i += 1
            while i > 0:
                s += tree[i]
                i -= i & -i
            return s

        rects = sorted(rectangles, key=lambda r: -r[1])
        order = sorted(range(len(points)), key=lambda j: -points[j][1])
        ans = [0] * len(points)
        i = 0
        for j in order:
            x, y = points[j]
            while i < len(rects) and rects[i][1] >= y:
                add(bisect_left(vals, rects[i][0]))
                i += 1
            k = bisect_left(vals, x)
            ans[j] = i - (acc(k - 1) if k > 0 else 0)
        return ans
```

## 8. 边界情况与易错点

1. **`bisect_left` 不能换成 `bisect_right`（最大坑）**：`len − bisect_right` 数的是 $> x$ 的元素，恰好把 $l_i = x$（点贴在矩形右边上）的矩形全部漏掉。示例 1 的查询 $(2,1)$ 若误用 `bisect_right`，$l = 2$ 的两个矩形都被漏，答案变成 0。
2. **$h = 100$ 的桶忘记排序**：归并循环如果只从 $h = 99$ 开始，`buckets[100]` 保持插入序，查询 $y_j = 100$ 时二分结果未定义。统一 `range(100, 0, -1)` 并让 `buckets[101]` 作空哨兵。
3. **归并方向反了**：必须 $h$ 从大到小、低桶吸收高桶。写成从小到大就变成前缀桶 $\{h_i \le h\}$，示例 2 的 $(1,3)$ 会把 $(1,1)$、$(2,2)$ 也数进去，答案从 1 错成 3。
4. **$l$ 值域 $10^9$**：任何试图对 $l$ 开值域数组的做法（包括桶内计数数组、前缀和矩阵）都会爆内存，只能排序 + 二分或离散化。
5. **空桶访问**：$y_j$ 对应的桶可能为空列表（没有 $h_i \ge y_j$ 的矩形），`len([]) - bisect_left([], x) = 0`，代码无需特判，但手写二分时注意返回值约定。
6. **桶内 $l$ 重复**：允许且正常（不同高度的矩形同长），计数语义按多重集处理，`bisect_left` 天然支持重复元素。
7. **答案上界**：单查询至多 $n = 5 \times 10^4$，`int` 足够；内存最坏 $\sum h_i = 5 \times 10^6$ 个整数，C++ 约 20 MB，若题目进一步收紧内存限制，改用 §4 第 4 点的逐桶二分或 §7 的 BIT 版。
