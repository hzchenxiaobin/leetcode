# LeetCode 多个数组求交集 题解

## 1. 题目概述

- **标题 / 题号**：多个数组求交集（#2248，easy）
- **链接**：https://leetcode.cn/problems/intersection-of-multiple-arrays/
- **来源**：LeetCode 第 290 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数、排序

**题意**：给定二维整数数组 `nums`，其中每个 `nums[i]` 是一个由**互异**正整数组成的非空数组。返回一个**升序**数组，包含在 `nums` 的**所有**数组中都出现过的元素。

**约束**：

- $1 \le \mathrm{nums.length} \le 1000$
- $1 \le \sum_i \mathrm{nums}[i].\mathrm{length} \le 1000$
- $1 \le \mathrm{nums}[i][j] \le 1000$
- `nums[i]` 中的所有值互不相同

> 💡 两条「送分」约束决定了最短路径：**值域 $\le 1000$** 允许开桶数组直接计数；**每个数组内部互异**使得「总出现次数 $= n$」与「出现在全部 $n$ 个数组」等价。于是两趟线性扫描搞定，连显式排序都能省掉。

## 2. 示例

**示例 1**

```text
输入：nums = [[3,1,2,4,5],[1,2,3,4],[3,4,5,6]]
输出：[3,4]
解释：3 和 4 是同时在 nums[0]、nums[1]、nums[2] 中出现的仅有两个数。
```

**示例 2**

```text
输入：nums = [[1,2,3],[4,5,6]]
输出：[]
解释：不存在同时出现在两个数组中的整数，返回空数组。
```

**边界示例（$n = 1$）**

```text
输入：nums = [[7,34,45,10,12,27,49]]
输出：[7,10,12,27,34,45,49]
解释：只有一个数组时，交集就是它本身（升序输出）。
```

## 3. 解题思路

### 3.1 暴力思路

对第一个数组的每个元素 $x$，逐个检查它是否出现在其余 $n-1$ 个数组中（每个数组线性扫描或转集合查询），全部命中则收集，最后排序。朴素实现约为 $O(L \cdot n)$ 量级（$L$ 为总元素数）。数据规模下（总元素 $\le 1000$）也能过，但分支多、细节杂，签到题应该选**更机械、更难写错**的那条路。

另一条等价路线是哈希集合：以 `set(nums[0])` 为初始答案，依次与每个 `set(nums[i])` 求交集，最后**显式排序**输出。同样完全正确（见 §7 备选写法），只是比桶计数多一步排序。

### 3.2 核心观察：互异性 ⇒ 计数即交集判定

![核心观察：计数达到 n 即属于交集](images/2248_intersection_count_concept.svg)

两个关键点：

1. **「出现次数」语义被互异性净化**：每个 `nums[i]` 内部互异，故任意值 $x$ 至多在每个数组中出现一次。于是 $x$ 在全部数据中的总出现次数 $\mathrm{cnt}[x]$，**恰等于包含 $x$ 的数组个数**。判定「出现在所有数组中」退化为一次整数比较：$\mathrm{cnt}[x] = n$。
2. **值域 $[1,1000]$ ⇒ 桶计数天然有序**：用大小 1001 的数组做计数器，最后**按下标 $1 \to 1000$ 顺序扫描**，输出自动升序——显式 `sort` 都省了。能少写一行是一行，更重要的是少一个可能出错的角落。

### 3.3 算法流程

```text
1. cnt = [0] * 1001，n = len(nums)
2. 对每个数组 row ∈ nums：
       对每个 x ∈ row：cnt[x] += 1        （row 内互异，不会重复累加）
3. ans = [ x for x in 1..1000 if cnt[x] == n ]
4. 返回 ans
```

一趟扫数据、一趟扫值域，两趟都是纯线性。

### 3.4 示例演算

![示例演算：计数表逐步累计](images/2248_intersection_walkthrough.svg)

以示例 1（$n = 3$）为例，逐行累计计数表：

| 扫描进度 | cnt[1] | cnt[2] | cnt[3] | cnt[4] | cnt[5] | cnt[6] |
|----------|--------|--------|--------|--------|--------|--------|
| 初始 | 0 | 0 | 0 | 0 | 0 | 0 |
| 加入 `[3,1,2,4,5]` | 1 | 1 | 1 | 1 | 1 | 0 |
| 加入 `[1,2,3,4]` | 2 | 2 | 2 | 2 | 1 | 0 |
| 加入 `[3,4,5,6]` | 2 | 2 | **3** | **3** | 2 | 1 |

过滤 $\mathrm{cnt}[x] = 3$：只有 $x = 3, 4$ 命中；按值域顺序输出 `[3,4]`。示例 2 中所有计数都 $\le 1 < 2$，输出 `[]`。

## 4. 算法细节

1. **桶大小**：值域 $[1,1000]$，开 `cnt[1001]`，下标 0 弃置不用。
2. **判 $= n$ 而非 $\ge n$**：互异性保证 $\mathrm{cnt}[x] \le n$ 恒成立，两者等价；但 $= n$ 直接对齐「恰好被每个数组各贡献一次」的语义，验证时不易绕晕。
3. **输出顺序来自扫描顺序**：第 3 步按 $x$ 从小到大扫桶，`ans` 天然升序，无需 `sort`。若改用哈希集合求交集（如 Python 的 `set.intersection(*map(set, nums))`），结果顺序任意，**必须** `sorted(...)`，见 §8。
4. **不要画蛇添足去重**：题目已保证每个数组内部互异，直接累加即可；先去重再计数反而多一处可能写错的逻辑。
5. **两趟循环的规模**：外层扫数据 $O(L)$、内层扫值域 $O(V)$（$V = 1000$），互不嵌套，总体线性。

## 5. 正确性证明

**引理 1**：对任意值 $x$，设 $S(x) = \{\, i : x \in \mathrm{nums}[i] \,\}$ 为包含 $x$ 的数组下标集合，则扫描结束后 $\mathrm{cnt}[x] = |S(x)|$。

**证明**：第 2 步对每个下标 $i$ 恰遍历 `nums[i]` 的全部元素各一次。由互异性，若 $x \in \mathrm{nums}[i]$，该数组恰为 $\mathrm{cnt}[x]$ 贡献一次增量；若 $x \notin \mathrm{nums}[i]$，贡献为零。各数组贡献独立可加，故 $\mathrm{cnt}[x] = \sum_{i} [\, x \in \mathrm{nums}[i] \,] = |S(x)|$。∎

**定理**：算法输出恰为所求交集，且严格升序。

**证明**：$x$ 属于所求交集当且仅当 $x$ 出现在每个数组中，即 $S(x) = \{0, 1, \dots, n-1\}$，等价于 $|S(x)| = n$；由引理 1 即 $\mathrm{cnt}[x] = n$。第 3 步收集的正是 $\{\, x \in [1, 1000] : \mathrm{cnt}[x] = n \,\}$，与交集定义一致（值域约束保证交集元素都在 $[1,1000]$ 内，不会遗漏）。收集时外层循环按 $x$ 从 1 到 1000 递增，故 `ans` 严格升序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(L + V)$，其中 $L = \sum_i \mathrm{nums}[i].\mathrm{length} \le 1000$ 是扫数据的开销，$V = 1000$ 是扫值域过滤的开销。相比「哈希交集 + 排序」的 $O(L + K \log K)$（$K$ 为交集大小），桶法把 $K \log K$ 换成常数 $V$，在本题值域下更优也更稳。
- **空间复杂度**：$O(V)$，即计数数组 `cnt` 的 1001 个整数；返回值不计入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> intersection(vector<vector<int>>& nums) {
        int n = nums.size();
        vector<int> cnt(1001, 0);
        for (auto& row : nums) {
            for (int x : row) {
                cnt[x]++;
            }
        }
        vector<int> ans;
        for (int x = 1; x <= 1000; x++) {
            if (cnt[x] == n) {
                ans.push_back(x);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def intersection(self, nums: List[List[int]]) -> List[int]:
        n = len(nums)
        cnt = [0] * 1001
        for row in nums:
            for x in row:
                cnt[x] += 1
        return [x for x in range(1, 1001) if cnt[x] == n]
```

备选一行（哈希集合语义，注意必须排序）：

```python
class Solution:
    def intersection(self, nums: List[List[int]]) -> List[int]:
        return sorted(set.intersection(*map(set, nums)))
```

## 8. 边界情况与易错点

1. **$n = 1$**：交集就是该数组本身。桶法天然正确（所有元素 $\mathrm{cnt} = 1 = n$），输出自动升序——这是最容易被「心里没底」的边界，实测用例里就有。
2. **空交集**：示例 2 的情形，所有 $\mathrm{cnt}[x] < n$，返回 `[]`。不要对空结果做特殊处理（比如错误地返回 `nums[0]`）。
3. **哈希写法忘记排序（最大坑）**：`set.intersection` 的结果顺序任意，**必须** `sorted(...)`；桶法免排序靠的是「按值域扫描」，不是交集运算本身的性质。
4. **桶大小差一**：值域上界 1000，数组开 1001；开 1000 会在 $x = 1000$ 时越界（C++ 直接 RE）。
5. **多重集合误区**：若误以为数组内可能重复而改判 $\mathrm{cnt}[x] \ge n$，互异前提下碰巧也对；但一旦变体放开互异（见延伸思考），这套判定会**静默出错**——对约束的依赖要心里有数。
6. **复杂度错觉**：`nums.length ≤ 1000` 与 `sum ≤ 1000` 同时成立，意味着两层 for 的名义开销被 $\sum$ 封顶在 1000，不存在 $1000 \times 1000$ 的最坏组合。
