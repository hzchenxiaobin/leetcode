# LeetCode 1 比特与 2 比特字符 题解

## 1. 题目概述

- **标题 / 题号**：1 比特与 2 比特字符（#717，easy）
- **链接**：https://leetcode.cn/problems/1-bit-and-2-bit-characters/
- **来源**：LeetCode 第 56 场周赛 Q1
- **难度**：简单
- **标签**：数组、贪心

**题意**：有两种特殊字符——第一种用**一比特** `0` 表示，第二种用**两比特**表示，只有 `10` 和 `11` 两种写法。给定一个以 `0` 结尾的二进制数组 `bits`（即一段合法的编码串），如果**最后一个字符必须是一比特字符**则返回 `true`，否则返回 `false`。

等价地看：把整串切成若干片，每片是单比特 `0` 或两比特 `10` / `11`，问唯一的那种切法里，**最后一片是不是单独的 `0`**。

**约束**：

- $1 \le \text{bits.length} \le 1000$
- `bits[i]` 为 `0` 或 `1`
- `bits` 一定以 `0` 结尾

> 💡 「必须」二字并不神秘：这套编码是**前缀码**（见 3.2），任何以 `0` 结尾的合法串都只有**唯一**一种切法，所以「必须是一比特字符」＝「那唯一一次解码的末片是 `0`」。

## 2. 示例

**示例 1**

```text
输入：bits = [1,0,0]
输出：true
解释：唯一的解码是 [1,0] + [0]，即一个两比特字符加一个一比特字符；
      末片是单个 0，所以最后一个字符是一比特字符。
```

**示例 2**

```text
输入：bits = [1,1,1,0]
输出：false
解释：唯一的解码是 [1,1] + [1,0]，即两个两比特字符；
      末位 0 被前面的 1 拼成 10，没有单独成字。
```

**示例 3（补充的边界用例）**

```text
输入：bits = [0]
输出：true
解释：只有一位 0，它自己就是一比特字符；此时循环体一次都不执行。
```

## 3. 解题思路

### 3.1 暴力思路

暴力的自然写法是**枚举所有切分**：从下标 0 出发，每一步都尝试「吃一位」和「吃两位」两种走法，走到底后只保留合法的那些（每片必须恰好是 `0`、`10` 或 `11`），再看保留下来的解码里末片是否都为单比特 `0`。

这样的搜索树有 $2^{n}$ 量级的节点，$n = 1000$ 时完全不可行；更尴尬的是绝大多数分支第一步就不合法（`1` 不能单独成片，`0` 也不能作为两比特片的首位），白白枚举。退一步用 DP 记 `dp[i]` 表示前缀 `bits[0..i)` 是否可解码，虽然能压到 $O(n)$ 时间，但要 $O(n)$ 空间，而且本题根本不问「方案数」或「可行性」——只问末片形态，一句话的贪心就够。

### 3.2 核心观察：前缀码 + 单向贪心

![前缀码规则：0 必是一比特，1 必开启两比特](images/wc56_q1_prefix_code_rule.svg)

关键事实：两个字符集合的**首比特不相交**。

- 一比特字符只有 `0`，以 `0` 开头；
- 两比特字符只有 `10`、`11`，都以 `1` 开头。

也就是说，没有任何合法字符是另一个合法字符的**前缀**（这就是「前缀码」，prefix code）。因此读到一个比特时，它属于长度为 1 还是长度为 2 的字符，是**当场唯一确定**的：

$$\text{bits}[i] = 0 \Rightarrow \text{长度为 } 1,\qquad \text{bits}[i] = 1 \Rightarrow \text{长度为 } 2$$

于是解码过程既没有分支也没有回溯，直接用一个指针从左往右跳即可：

$$i \leftarrow \begin{cases} i + 2, & \text{bits}[i] = 1 \\ i + 1, & \text{bits}[i] = 0 \end{cases}$$

指针最终落在哪里，就完整描述了末片的形态：停在末位 `0` 上说明它被单独识别，越过末位说明它被前面的 `1` 拼走了。

### 3.3 算法流程

![贪心扫描流程：一个指针走到底](images/wc56_q1_greedy_flow.svg)

流程只有五行：

```text
i = 0
while i < n - 1:          # 刻意在末位 0 之前收手
    i += 2 if bits[i] == 1 else 1
return i == n - 1         # 恰好落在末位 0 上 ⇒ 它单独成字
```

- 循环条件写成 $i < n-1$ 而不是 $i < n$，是为了**不让指针把末位 `0` 再消费一次**；
- 退出循环时 $i$ 只可能是 $n-1$ 或 $n$（证明见 §5 引理 3），所以最后的判定一次比较就够；
- 整个过程不需要区分「`1` 后面跟的是 `0` 还是 `1`」——两比特字符具体是 `10` 还是 `11` 与答案无关。

### 3.4 示例演算

![两个官方示例的指针轨迹与分组](images/wc56_q1_walkthrough.svg)

**示例 2 `bits = [1,1,1,0]`（$n = 4$）逐轮走查**：

| 轮次 | 进入时 $i$ | `bits[i]` | 判定 | 动作后 $i$ | 已切出的片 |
|------|-----------|-----------|------|-----------|-----------|
| 1 | 0 | `1` | $0 < 3$，两比特 | 2 | `[1,1]` |
| 2 | 2 | `1` | $2 < 3$，两比特 | 4 | `[1,1]`、`[1,0]` |
| 退出 | 4 | — | $4 < 3$ 为假 | 4 | 末片是 `10` |

$i = 4 = n$，指针越过了末位，返回 **false**。

**四个输入的横向对比**：

| `bits` | 指针轨迹 | 末片 | 返回值 |
|--------|----------|------|--------|
| `[1,0,0]` | $0 \to 2$ 后停住 | `0` | true |
| `[1,1,1,0]` | $0 \to 2 \to 4$ 越过 | `10` | false |
| `[0]` | $0$（循环未执行） | `0` | true |
| `[1,1,0]` | $0 \to 2$ 后停住 | `0` | true |

## 4. 算法细节

1. **循环上界必须是 $n-1$**。写成 $i < n$ 时，指针落到末位 `0` 后还会再执行一次 $i \leftarrow i+1$，恒有 $i = n$，答案永远是 `false`——这是本题最高频的 WA。
2. **`i += 2` 不会越界**。进入循环体的前提是 $i \le n-2$，所以 `bits[i+1]` 一定存在；跳完至多 $i+2 \le n$，`bits` 的下标不会越界，不需要额外的边界判断。
3. **判定写成 `i == n-1`**。由引理 3，退出时 $i \in \{n-1, n\}$，两种取值恰好对应「末片是单比特 `0`」与「末片是 `10`」，因此一次比较即是完整判定，不必再去检查 `bits[n-1]`。
4. **等价写法：末段连续 `1` 的奇偶性**。为了让末位 `0` 单独成字，它前面的 `1` 必须两两配对成 `11`；只要紧贴末位 `0` 之前的连续 `1` 个数 $k$ 为偶数就不剩孤立的 `1`，答案为 `true`，否则必有一个 `1` 拉走末位 `0` 组成 `10`，答案为 `false`：

   ```python
   from typing import List


   class Solution:
       def isOneBitCharacter(self, bits: List[int]) -> bool:
           k, i = 0, len(bits) - 2
           while i >= 0 and bits[i] == 1:   # 只数紧贴末位 0 的那一串 1
               k += 1
               i -= 1
           return k % 2 == 0
   ```

   它和正向扫描同为 $O(n)$ / $O(1)$，但从右往左可以**提前停**（遇到第一个 `0` 就结束），平均更快；缺点是只对「以 `0` 结尾」的输入成立，讲清前缀码本质仍以正向扫描为好。
5. **不需要判「是否可解码」**。末位是 `0` 保证了贪心一定能恰好收在 $n-1$ 或 $n$（引理 3 与推论），代码里不必写「解不出来怎么办」的兜底分支。
6. **下标与接口**。C++ 用 `bool isOneBitCharacter(vector<int>& bits)`，注意参数是引用、不要拷贝；Python 用 `List[int]` 并在函数内部只读，不能原地修改输入。
7. **常数优化可选**。$n \le 1000$，正向扫描至多 $n$ 轮、每轮一次比较一次加法，已经贴着最优；真要更快只能靠第 4 条的从右往左提前退出。

## 5. 正确性证明

约定：把 `bits` 切成若干片、每片取值于 $\{\,0,\ 10,\ 11\,\}$ 且首尾相接覆盖全串，称为一个**合法解码**；末片的取值称为**末片形态**。

**引理 1（首片唯一，故解码至多一种）**：任意二进制串 `bits` 的首片长度由 `bits[0]` 唯一确定，因而 `bits` 的合法解码至多有一个。

**证明**：若 `bits[0] = 0`，由于两比特字符都以 `1` 开头，首片只能是单比特 `0`，长度为 1；若 `bits[0] = 1`，单比特字符 `0` 无法匹配，首片只能是两比特字符（`10` 或 `11`），长度为 2。所以只要存在合法解码，其首片就被 `bits[0]` 唯一确定。对串长归纳：去掉首片后对剩余串递归，每片长度都唯一，故整个解码唯一。∎

**引理 2（指针不变量）**：每次判断循环条件之前，$i$ 是当前待解码后缀的起点，且 `bits[0..i)` 已被切成若干完整字符；当 $i \le n-2$ 时，按 $i \leftarrow i+2$（若 `bits[i]=1`）或 $i \leftarrow i+1$（若 `bits[i]=0`）前进，跳过的是引理 1 中那个唯一首片。

**证明**：初始 $i=0$，空前缀对应空切分，成立。设某轮开始时不变量成立且 $i \le n-2$，则后缀非空，其首片长度由 $bits[i]$ 唯一确定：为 `0` 时长度 1，为 `1` 时长度 2（同引理 1 的论证，且 $i \le n-2$ 保证 `bits[i+1]` 存在）。指针正好跳过这一个字符，前缀扩大一个完整字符，不变量保持。∎

**引理 3（终止位置）**：循环退出时 $i \in \{n-1,\, n\}$，且
$$i = n-1 \iff \text{末片是单比特 } 0, \qquad i = n \iff \text{末片是两比特字符 } 10.$$

**证明**：$i$ 单调递增，每次 $+1$ 或 $+2$，循环条件为 $i < n-1$，故退出时 $i \ge n-1$。设退出前一刻为 $i_0$，则 $i_0 \le n-2$，从而 $i \le i_0 + 2 \le n$，于是 $i \in \{n-1, n\}$。

- 若 $i = n-1$：由引理 2，`bits[0..n-1)` 已解完，剩下的是 `bits[n-1] = 0`（题设末位为 `0`），它只能单独成片，故末片是单比特 `0`。
- 若 $i = n$：最后一步必然是从 $i_0 = n-2$ 跳了 2，即 `bits[n-2] = 1`，于是末片是 `bits[n-2..n) = 10`，是两比特字符。

两个方向的充分性都已说明，必要性由「$i$ 只取这两种值」直接得到。∎

**推论（存在性）**：任意以 `0` 结尾的 `bits` 恰有一个合法解码。

**证明**：由引理 2 的指针轨迹，`bits[0..i)` 是合法切分；由引理 3，退出时 $i = n-1$ 或 $i = n$，前者把剩下的单个 `0` 作为最后一片即可，后者已覆盖全串，故合法解码至少有一个；再由引理 1，至多有一个。∎

**定理**：算法返回的 `i == n-1` 当且仅当最后一个字符必须是一比特字符。

**证明**：由推论，合法解码唯一存在，「必须是一比特字符」即「唯一解码的末片是单比特 `0`」。由引理 3，$i = n-1$ 与「末片是单比特 `0`」互为充要条件。因此返回值与该命题同真同假，算法正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。指针每轮至少前进 1，循环体执行不超过 $n-1$ 次，每次只做一次比较、一次加法；末尾一次比较。无排序、无嵌套循环。
- **空间**：$O(1)$。只用了 `i` 与 `n` 两个整型变量，未开辟任何辅助数组。
- **第 4 条的奇偶写法**：同样 $O(n)$ 时间、$O(1)$ 空间，但只需扫描末尾那一段连续 `1`，遇到第一个 `0` 立即停止，实际运行更快。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool isOneBitCharacter(vector<int>& bits) {
        int n = (int)bits.size();
        int i = 0;
        while (i < n - 1) {               // 刻意停在末位 0 之前
            i += (bits[i] == 1) ? 2 : 1;  // 1 开头必是两比特字符
        }
        return i == n - 1;                // 恰好落在末位 0 上 ⇒ 它是单比特字符
    }
};
```

### Python

```python
from typing import List


class Solution:
    def isOneBitCharacter(self, bits: List[int]) -> bool:
        n = len(bits)
        i = 0
        while i < n - 1:            # 末位 0 留给最后的判定
            i += 2 if bits[i] == 1 else 1
        return i == n - 1           # 停在末位 0 上即为一比特字符
```

## 8. 边界情况与易错点

1. **$n = 1$**：`bits = [0]`，循环体一次都不执行，$i = 0 = n-1$，返回 `true`。若把循环写成 `do-while` 或先自增再判断，这里就会越界或误判。
2. **`[1,0]`**：$i$ 从 0 直接跳到 2 越过了末位，返回 `false`；它是最短的「末片是两比特字符」样例，适合做单元测试的第一条。
3. **循环条件写成 $i < n$**：末位 `0` 会被再消费一次，$i$ 恒为 $n$，答案永远是 `false`。这是本题最典型的错误。
4. **把判定写成 `bits[n-1] == 0`**：末位恒为 `0`，这样写永远返回 `true`。判定必须落在**指针位置**上，而不是末位的值上。
5. **全 `0` 串**（如 `[0,0,0,...,0]`）：每步 $+1$，指针走 $n-1$ 步恰好停在末位，返回 `true`，不要误以为「多个 0 会互相配对」。
6. **末段奇数个 `1`**（如 `[1,1,1,0]`、`[1]*999 + [0]`）：必然有一个 `1` 与末位 `0` 组成 `10`，返回 `false`；用奇偶写法时要记得只数**紧贴末位 `0`** 的那一串。
7. **越界**：`i += 2` 之前已由 $i \le n-2$ 保证 `bits[i+1]` 存在，无需额外判断；但若把循环条件放宽到 $i < n$，就真的会读到 `bits[n]`。
8. **不要把输入当作可以原地修改**：本题只需读，C++ 传引用不拷贝，Python 用列表索引只读。

**延伸思考**：

1. 本题之所以能 $O(n)$ 贪心，全靠「两个字符的首比特不同」。若码表换成 $\{0,\,10,\,110\}$ 这类仍然无前缀的编码，贪心只需多看几位（按最长前缀匹配），仍然是 $O(n)$；但一旦码表**有前缀冲突**（如 $\{0,\,01\}$），解码不再唯一，就必须回到 DP：`dp[i]` 表示前 `i` 位是否可解码，转移枚举所有能匹配的码字。
2. 若把问题改成「最后一个字符是两比特字符的概率 / 方案数」，前缀码前提下答案是 0 或 1，与本题等价；加上歧义码表后就需要 91 题那样的计数 DP，复杂度 $O(n \cdot L)$（$L$ 为码字最大长度）。
3. 若去掉「以 `0` 结尾」的保证，输入可能整体无解（如 `[1]`），题意要重新定义为「是否存在合法解码且末片单比特」；此时贪心仍能判定可解码性——合法当且仅当指针恰好收在 $n$（末片是完整的两比特字符），或收在 $n-1$ 且 `bits[n-1] = 0`（末片是单比特字符）。
4. 前缀码与**哈夫曼编码**同源：哈夫曼树保证任何码字都不是另一个码字的前缀，从而译码无歧义。本题的 `0` / `10` / `11` 就是一株只有三个叶子的哈夫曼树，正向扫描正是标准译码器的做法。
