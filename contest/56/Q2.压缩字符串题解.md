# LeetCode 压缩字符串 题解

## 1. 题目概述

- **标题 / 题号**：压缩字符串（#443，medium）
- **链接**：https://leetcode.cn/problems/string-compression/
- **来源**：LeetCode 第 56 场周赛 Q2
- **难度**：中等
- **标签**：双指针、字符串

**题意**：给定字符数组 `chars`，对每一组**连续重复字符**做游程编码：组长为 1 时只保留该字符；组长 $\ge 2$ 时保留字符本身，后面紧跟组长的**十进制写法**（逐位拆成单字符，如 $12 \to$ `'1'`、`'2'`）。压缩结果必须**原地写回** `chars`，返回新长度；超出新长度的格子内容无关紧要。额外空间必须是 $O(1)$。

**约束**：

- $1 \le \text{chars.length} \le 2000$
- `chars[i]` 可为小写字母、大写字母、数字或符号
- 压缩结果长度**一定不大于**原长度（这是原地写法可行的前提）

## 2. 示例

**示例 1**

```text
输入：chars = ["a","a","b","b","c","c","c"]
输出：6
解释：分组为 "aa"、"bb"、"ccc"，压缩为 "a2b2c3"。
      原地修改后 chars 的前 6 个字符应为 ["a","2","b","2","c","3"]。
```

**示例 2**

```text
输入：chars = ["a"]
输出：1
解释：唯一的组是 "a"，组长为 1，不写数字，chars[0] 仍为 "a"。
```

**示例 3**

```text
输入：chars = ["a","b","b","b","b","b","b","b","b","b","b","b","b"]
输出：4
解释：分组为 "a" 和 "bbbbbbbbbbbb"（12 个 b），压缩为 "ab12"。
      注意 12 被拆成两个字符 '1'、'2'，所以结果占 4 格而不是 3 格。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是新建一个字符串 $s$，边扫边追加，最后把 $s$ 拷回 `chars`：

- 时间 $O(n)$，但额外空间 $O(n)$，**直接违反题目「常量额外空间」的硬性要求**；
- 另一种「每写一位就整体后移」的做法虽然也原地，但每次搬移 $O(n)$，最坏 $O(n^2)$，$n = 2000$ 时虽然能过，却不是本题想考的东西。

所以必须找到一种**不需要回退、不需要搬移**的就地写法。

### 3.2 核心观察：读指针分组，写指针落笔

![双指针原地压缩与 write ≤ read 不变量](images/wc56_q2_two_pointer_group.svg)

维护两个指针：

- `read`：**探路**。每轮从组首 `start = read` 出发，一直右移直到「越界」或「字符变了」，此时 `[start, read)` 恰好是一整组；
- `write`：**落笔**。把这一组的编码（字符 + 可选数字）从 `write` 开始逐个写出。

关键洞察是两者的**相对位置**：压缩只会让内容变短，因此每一步写出的格数都不超过刚读过的字符数，从流程一开始就有

$$\text{write} \le \text{read}$$

于是所有写入都落在**已经被读过、以后再也不会用到**的前缀里，未处理的后缀永远不会被覆盖——这正是 $O(1)$ 额外空间能成立的真正原因。代码里甚至不需要显式判断这一点，只要保证**先把整组读完、再开始写**即可。

### 3.3 算法流程

![组长度与写入字符的对应关系](images/wc56_q2_cnt_write.svg)

1. `read = write = 0`。
2. 当 `read < n`：
   1. 记 `start = read`，`read` 右移直到 `read == n` 或 `chars[read] != chars[start]`；
   2. `cnt = read - start`；
   3. 写出字符本身：`chars[write++] = chars[start]`；
   4. 若 `cnt > 1`，把 `cnt` 的十进制表示逐位写出：`chars[write++] = digit`。
3. 返回 `write`。

第 2.3 步与 2.4 步的**顺序不能反**：题面要求「字符在前、数字在后」。第 2.4 步之所以用 `to_string(cnt)` / `str(cnt)`，是因为数字的十进制拆位（尤其是位数不固定）交给标准库最不容易错；位数最多 4 位（$cnt \le 2000$），仍是 $O(1)$ 空间。

### 3.4 示例演算

![示例 aabbccc 的逐组走查](images/wc56_q2_walkthrough.svg)

对 `chars = ["a","a","b","b","c","c","c"]`（$n = 7$）：

| 轮次 | `start` | 组（`read` 扫过的下标） | `cnt` | 写入 | `write` 变化 |
|------|---------|--------------------------|-------|------|--------------|
| 1 | 0 | `a a`（0 ~ 1） | 2 | `a`、`2` | 0 → 2 |
| 2 | 2 | `b b`（2 ~ 3） | 2 | `b`、`2` | 2 → 4 |
| 3 | 4 | `c c c`（4 ~ 6） | 3 | `c`、`3` | 4 → 6 |

结束后 `read = 7 = n`、`write = 6`，返回 6，前 6 格为 `a 2 b 2 c 3`，第 7 格（下标 6）仍是旧值 `c`，按题意忽略。

再看示例 3 的两位数情形：`a` 单独成组写 1 格；`b` 组 $cnt = 12$，写出 `b`、`1`、`2` 共 3 格，总长 $1 + 3 = 4$。

## 4. 算法细节

1. **分组只靠一次线性扫描**：`start` 固定组首，`read` 一直右移，不回头；整轮外层循环里 `read` 只增不减，因此总比较次数恰好 $n$ 次量级。
2. **`cnt` 用 `read - start` 计算**：此时 `read` 已经指向**下一组的首字符**（或 $n$），不要再 `read - start + 1`，否则组长度会多 1。
3. **先写字符、后写数字**：顺序写反会得到 `2a`，与题意不符。
4. **`cnt == 1` 必须特判**：只写字符本身，绝不能写 `'1'`；这是本题最高频的 WA 点。
5. **十进制拆位不要手写逆序**：若手写 `while (cnt) { buf.push_back('0' + cnt % 10); cnt /= 10; }`，取到的是**逆序**数字（12 会变成 `2`、`1`），必须反转或用标准库；直接 `to_string(cnt)` / `str(cnt)` 最稳。
6. **写指针推进与返回值**：`write` 始终指向「下一个空位」，所以循环结束时它**就是**新长度，直接返回，不要再 `+1`。
7. **尾部旧数据不必清理**：题面明确「超出返回长度的字符无关紧要」，判题只看 `chars[0..返回值)`，因此既不需要清零尾部，也不需要 `del chars[write:]` 之类的截断——多做一步只会引入出错面。
8. **`char` 与数字字符**：C++ 里 `chars[write++] = c;` 中的 `c` 来自 `string`，本身就是字符 `'0'`~`'9'`，不要再做 `'0' + c` 的二次转换。

## 5. 正确性证明

**引理 1（分组正确且完备）**：每轮得到的 `[start, read)` 是一段**极大**的连续相同字符段；所有轮次的区间首尾相接，恰好覆盖 `[0, n)`，不重不漏。

**证明**：内层循环结束时（若 `read < n`）必有 `chars[read] != chars[start]`，且 `[start, read)` 内所有字符都等于 `chars[start]`，故该段右侧无法再延伸，是极大的；左侧由 `start` 取自上一轮的 `read` 保证无法再延伸。下一轮从本轮 `read` 开始，故区间依次相接；每轮至少消耗 1 个字符，故最终并集为 `[0, n)`。∎

**引理 2（单组编码正确）**：对组 $[start, read)$，记 $cnt = read - start$，算法写出的内容恰好是：$cnt = 1$ 时 1 个字符；$cnt \ge 2$ 时该字符后接 $cnt$ 的十进制表示（无前导零、高位在前）。

**证明**：由代码分支直接可得。$cnt=1$ 分支只执行一次字符赋值；$cnt \ge 2$ 分支先写字符，再把 `to_string(cnt)` / `str(cnt)` 的字符按从左到右顺序逐个写入，而标准库给出的正是无前导零、高位在前的十进制串。∎

**引理 3（压缩不膨胀）**：对任意 $cnt \ge 2$，若 $d(cnt)$ 表示 $cnt$ 的十进制位数，则 $1 + d(cnt) \le cnt$。

**证明**：先证 $d(cnt) \le cnt - 1$，对 $cnt$ 归纳。$2 \le cnt \le 9$ 时 $d = 1 \le cnt - 1$。设 $cnt \ge 10$，令 $m = \lfloor cnt/10 \rfloor \ge 1$，则 $d(cnt) = d(m) + 1$：若 $m = 1$，$d(cnt) = 2 \le 9 \le cnt - 1$；若 $m \ge 2$，由归纳假设 $d(m) \le m - 1$，于是 $d(cnt) \le m \le cnt/10 < cnt - 1$。故 $1 + d(cnt) \le cnt$。∎

**引理 4（写入安全，即 $write \le read$ 不变量）**：处理完第 $k$ 组后恒有 $write \le read$；并且该组写入的格子区间 $[write_{\text{旧}}, write_{\text{新}})$ 落在处理完该组后的已读前缀 $[0, read_{\text{新}})$ 内。

**证明**：对 $k$ 归纳。$k = 0$ 时 $write = read = 0$。设处理第 $k$ 组前 $write \le start$（因 $start$ 即上一轮的 $read$），该组消耗 $cnt$ 个字符（$read$ 增加 $cnt$），写出 $1 + d(cnt)$ 格（$cnt = 1$ 时为 1 格）。由引理 3 与 $cnt = 1$ 时的 $1 \le 1$，写出格数不超过 $cnt$，故 $write_{\text{新}} \le write_{\text{旧}} + cnt \le start + cnt = read_{\text{新}}$，不变量保持；写入区间上界为 $write_{\text{新}} \le read_{\text{新}}$，故完全落在已读前缀内。∎

**定理**：算法返回的 `write` 等于压缩结果的长度，且 `chars[0..write)` 恰好是题面要求的压缩结果。

**证明**：由引理 1，分组恰好是题面定义的所有连续重复字符组；由引理 2，每组写出的内容与题面编码规则完全一致，且各组写出顺序与出现顺序一致，故拼接结果就是压缩串 $s$。由引理 4，所有写入都落在已读前缀内、互不覆盖且按顺序紧密排列，所以 `chars[0..write)` 的内容恰为 $s$，`write = |s|` 即返回值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`read` 指针单调右移，总共前进 $n$ 步，内层 `while` 的每次比较都伴随一次 `read` 自增，故总比较次数 $\le n$；`write` 指针总共前进 $|s| \le n$ 步；数字拆位每位 $O(1)$，总位数 $\le n$。常数很小，单趟扫描。
- **空间**：$O(1)$。除两个下标变量外，只在写数字时需要一个临时串，长度最多 $d(2000) = 4$，与 $n$ 无关；没有使用任何与输入规模相关的辅助数组。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int compress(vector<char>& chars) {
        int n = chars.size();
        int read = 0;   // 读指针：当前组的起点
        int write = 0;  // 写指针：下一个压缩字符要落到的位置
        while (read < n) {
            int start = read;
            // 找这一组的右边界：值变了或越界就停
            while (read < n && chars[read] == chars[start]) read++;
            int cnt = read - start;
            chars[write++] = chars[start];   // 先写字符本身
            if (cnt > 1) {                   // 长度 > 1 才写数字
                string s = to_string(cnt);   // 十进制逐位拆开
                for (char c : s) chars[write++] = c;
            }
        }
        return write;                        // write 就是新长度
    }
};
```

### Python

```python
from typing import List

class Solution:
    def compress(self, chars: List[str]) -> int:
        n = len(chars)
        read = 0    # 读指针：当前组的起点
        write = 0   # 写指针：下一个压缩字符要落到的位置
        while read < n:
            start = read
            # 找这一组的右边界：值变了或越界就停
            while read < n and chars[read] == chars[start]:
                read += 1
            cnt = read - start
            chars[write] = chars[start]      # 先写字符本身
            write += 1
            if cnt > 1:                      # 长度 > 1 才写数字
                for d in str(cnt):           # 十进制逐位拆开
                    chars[write] = d
                    write += 1
        return write                          # write 就是新长度
```

## 8. 边界情况与易错点

1. **单字符输入**：`["a"]` 或 `["a","b"]` → 组长为 1，只写字符本身，返回原长度。若写成 `a1`、`b1` 则直接 WA。
2. **两位数陷阱**：$cnt = 12$ 要占两个格子（`'1'`、`'2'`）；$cnt = 10$ 也是两个格子。别把 `cnt` 当成「一个字符」处理。
3. **顺序不能反**：必须是「字符 + 数字」，写成「数字 + 字符」即错。
4. **`read - start` 与 `read - start + 1`**：内层循环退出时 `read` 指向下一组首字符，组长为 `read - start`；多减 / 多加 1 都会让长度错误。
5. **返回值是长度而不是下标**：`write` 指向下一个空位，正好等于长度；若返回 `write - 1`，示例 1 会输出 5。
6. **手写拆位容易逆序**：`cnt % 10` 先取到的是个位，直接顺序写入会得到 `21` 而不是 `12`；用 `to_string` / `str` 可彻底避免。
7. **覆盖未读数据**：只要遵守「本轮 `read` 先走完、再写」，并且利用压缩不膨胀的性质（引理 3），`write` 不会越过 `read`；反过来若先写字符再统计 `cnt`，就可能写坏正在读的字符。
8. **不要做多余的尾部清理**：`chars` 超出返回长度的部分是允许残留的旧值，题目要求忽略；多余清空不影响正确性，但会引入不必要的分支。
9. **全不同字符**：如 2000 个互不相同的字符，`write == n`，返回 2000，此时数组内容与原来完全一致。
10. **单组超长**：2000 个相同字符 → 写出 `字符 + "2000"` 共 5 个字符，返回 5；说明「压缩长度 $\le$ 原长度」在极端情形下也成立（$5 \ll 2000$）。
