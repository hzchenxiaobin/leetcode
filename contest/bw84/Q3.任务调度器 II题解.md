# LeetCode 任务调度器 II 题解

## 1. 题目概述

- **标题 / 题号**：任务调度器 II（#2365，medium）
- **链接**：https://leetcode.cn/problems/task-scheduler-ii/
- **来源**：LeetCode 第 84 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：正整数数组 `tasks` 表示**必须按顺序**完成的任务（`tasks[i]` 为第 $i$ 件任务的类型），正整数 `space` 表示同一类型任务两次完成之间至少要隔 $space$ 天。每一天要么完成 `tasks` 中的下一个任务，要么休息。求完成所有任务的最少天数。

**约束**：

- $1 \le \text{tasks.length} \le 10^5$
- $1 \le \text{tasks}[i] \le 10^9$（类型编号很大，必须哈希）
- $1 \le \text{space} \le \text{tasks.length}$

## 2. 示例

**示例 1**

```text
输入：tasks = [1,2,1,2,3,1], space = 3
输出：9
解释：第 1 天任务 0、第 2 天任务 1、第 3~4 天休息、第 5 天任务 2、
      第 6 天任务 3、第 7 天休息、第 8 天任务 4、第 9 天任务 5。
```

**示例 2**

```text
输入：tasks = [5,8,8,5], space = 2
输出：6
解释：第 1 天任务 0、第 2 天任务 1、第 3~4 天休息、第 5 天任务 2、第 6 天任务 3。
```

**边界补充**

```text
输入：tasks = [1], space = 1            输出：1    # 单任务
输入：tasks = [1,1,1,1], space = 1      输出：7    # 同类相邻：完成日 1,3,5,7
输入：tasks = [1,1,1,1], space = 0      输出：4    # 无间隔连做
输入：tasks = [1,2,3], space = 5        输出：3    # 互不相同：顺序连做
```

## 3. 解题思路

### 3.1 暴力思路

按天模拟：`day` 从 1 起步，每天看下一个任务是否「冷却已过」——若该类型上次完成日在 `day - space` 之后（间隔不足 $space$ 天）就休息一天。单天 $O(1)$，但总天数最坏 $1 + (n-1)(\text{space}+1) \approx 10^5 \times 10^5 = 10^{10}$ 天（全部同类型、`space` 拉满），逐天循环会超时。需要把「连续休息」折叠成一次跳转——这正是 O(1) 递推的由来。

### 3.2 核心观察：休息只由「同类型冷却」触发，可一步跳到解禁日

![时间轴与关键递推](images/bw84_q3_timeline_model.svg)

任务必须按序完成，所以第 $i$ 个任务的完成日 $d_i$ 只受两类约束：

- **顺序约束**：$d_i \ge d_{i-1} + 1$（至少比前一个任务晚一天）；
- **冷却约束**：若同类型的前一个任务完成日为 $d'$，则中间须隔至少 $space$ 天，即 $d_i \ge d' + \text{space} + 1$（完成日差 $\ge space + 1$，见示例 1：第 1 天与第 5 天完成同类型任务，中间恰好休息 $3$ 天）。

于是维护哈希表 `last[t]`（类型 $t$ 上次完成日），当前天数一步跳到位：

$$d_i = \max(d_{i-1} + 1,\ \text{last}[t] + \text{space} + 1)$$

休息不用逐天数——被折叠进这个 $\max$ 里。

### 3.3 算法流程

```text
cur = 0, last = 空哈希表
遍历 t ∈ tasks：
    若 t ∈ last：cur = max(cur + 1, last[t] + space + 1)
    否则：      cur = cur + 1
    last[t] = cur
返回 cur
```

### 3.4 示例演算

![示例 2 演算：6 天日程](images/bw84_q3_example_walkthrough.svg)

示例 2：`tasks = [5,8,8,5]`，`space = 2`。任务 5：首次 → 第 1 天；任务 8：首次 → 第 2 天；任务 8：$\max(3,\ 2 + 2 + 1 = 5)$ → 第 5 天；任务 5：$\max(6,\ 1 + 2 + 1 = 4)$ → 第 6 天。日程「5 8 休 休 8 5」共 6 天。注意最后一个任务取的是 $\max$ 的**顺序分支**——冷却早解禁也要等前面的任务做完。

## 4. 算法细节

1. **「间隔最少 space 天」的准确换算**：完成日差 $\ge \text{space} + 1$。题面说「任务完成后，另一相同类型任务完成前需间隔最少 `space` 天」——两个完成日之间**夹着**的天数（休息或做别的任务）就是差值减一，故解禁日为 $\text{last}[t] + \text{space} + 1$。漏掉 $+1$ 是最典型的 WA。
2. **不同类型互不冷却**：`last` 只按「同类型」记录，当前任务与前一任务类型不同时无冷却分支，纯顺序推进。
3. **首次出现走 `cur + 1`**：哈希表无记录时直接顺延，不要去查默认值 $0$ 再算 $0 + \text{space} + 1$（$\text{space}$ 可以很大，反而会把首任务推迟）。
4. **天数上界**：最坏 $1 + (n-1)(\text{space}+1) \approx 10^{10}$，超出 `int`，C++ 用 `long long` 累加（题目返回类型即 `long`）。
5. **类型值域 $10^9$**：必须哈希表（`unordered_map` / `dict`），不能开数组。

## 5. 正确性证明

记递推得到的完成日为 $d_0, d_1, \dots, d_{n-1}$（$d_{-1} = 0$，即 $d_0 = \max(1, \ldots) = 1$，首次任务无冷却分支）。

**引理（可行性刻画）**：一个调度方案可行，当且仅当每个任务 $i$ 的完成日 $D_i$ 满足（a）$D_{i} \ge D_{i-1} + 1$；（b）若 $j$ 是 $i$ 之前最近的同类型任务，则 $D_i \ge D_j + \text{space} + 1$。

**证明**：任务按序且每天至多完成一个 ⇒ 完成日严格递增 ⇒ (a)。同类型 $j$ 与 $i$ 之间至少隔 $space$ 天：完成日之差 $\ge space + 1$ ⟺ 夹在中间的天数 $D_i - D_j - 1 \ge space$，即 (b)。反之，满足 (a)(b) 的任何整数序列都可实现——把 $D_{i-1}+1$ 到 $D_i - 1$ 之间的天标为休息即可。∎

**定理（贪心最优）**：任意可行调度中 $D_i \ge d_i$ 对所有 $i$ 成立；且 $d$ 本身可行。故最终完成日 $d_{n-1}$ 最小。

**证明**：对 $i$ 归纳。$i = 0$：$D_0 \ge 1 = d_0$。设 $D_{i-1} \ge d_{i-1}$，且 $j$ 为 $i$ 之前最近同类型任务（若存在）。由 (a) $D_i \ge D_{i-1} + 1 \ge d_{i-1} + 1$；由 (b) $D_i \ge D_j + \text{space} + 1 \ge d_j + \text{space} + 1 = \text{last}[t] + \text{space} + 1$（归纳假设应用于 $j < i$，且 $d_j$ 正是递推中查到的 `last[t]`）。两下界取 $\max$ 得 $D_i \ge d_i$。$d$ 的可行性由引理直接验证：(a) $d_i \ge d_{i-1} + 1$ 由 $\max$ 第一分支保证；(b) 同理由第二分支保证。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个任务一次哈希表查询与写入，均摊 $O(1)$；「连续休息」被公式折叠，与天数无关。
- **空间**：$O(\min(n, \text{类型数}))$。哈希表至多存 $n$ 个类型（去重后更少）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long taskSchedulerII(vector<int>& tasks, int space) {
        long long cur = 0;                                  // 当前任务完成的天
        unordered_map<int, long long> last;                 // 任务类型 → 上次完成的天
        for (int t : tasks) {
            auto it = last.find(t);
            if (it != last.end())                           // 同类型：最早可完成 = last + space + 1
                cur = max(cur + 1, it->second + (long long)space + 1);
            else
                ++cur;
            last[t] = cur;
        }
        return cur;
    }
};
```

### Python

```python
class Solution:
    def taskSchedulerII(self, tasks: list[int], space: int) -> int:
        cur = 0
        last = {}                                  # 任务类型 → 上次完成的天
        for t in tasks:
            if t in last:                          # 同类型：最早可完成 = last + space + 1
                cur = max(cur + 1, last[t] + space + 1)
            else:
                cur += 1
            last[t] = cur
        return cur
```

> 💡 两份代码均通过官方 2 个示例与 4 个补充边界（单任务 / 同类连发 space=1、space=0 / 互异类型），并与「逐天休息模拟」的独立暴力对拍：C++ 3 万组、Python 3 千组（$n \le 18$、类型 $\le 5$），`mismatch = 0`；另通过 $n = 10^5$ 全同类型、`space` $= 10^5$ 的大数据校验（答案 $10^{10}$，验证 64 位无溢出）。

## 8. 边界情况与易错点

1. **`+1` 漏加**：冷却解禁日是 $\text{last}[t] + \text{space} + 1$，不是 $+\ \text{space}$；「间隔 $space$ 天」夹在两次完成之间，完成日差是 $space + 1$。
2. **溢出**：最坏答案约 $10^{10}$，C++ 中 `cur`、哈希表的值都必须 `long long`；`it->second + space + 1` 里 `space` 也要显式转 64 位。
3. **首次出现别查默认值**：`last` 里没有该类型时直接 `cur + 1`；用 `dict.get(t, 0)` 之类的默认值参与冷却公式会凭空多等 $space$ 天。
4. **$\max$ 的两个分支都要**：示例 2 的最后一个任务说明顺序分支也可能成为瓶颈；只看冷却会把答案算小。
5. **任务顺序不可重排**：这是与「任务调度器 I」（LC 621，可重排 + 贪心/构造）的本质区别，本题只能顺序模拟。
6. **`space` 可以等于 `n`**：约束 $1 \le \text{space} \le n$，同类型任务至多 $n$ 个出现一次时冷却永远够用，公式天然处理。
