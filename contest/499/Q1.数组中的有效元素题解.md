# LeetCode 数组中的有效元素 题解

## 1. 题目概述

- **标题 / 题号**：数组中的有效元素（#3912，easy）
- **链接**：https://leetcode.cn/problems/valid-elements-in-an-array/
- **来源**：LeetCode 第 499 场周赛 Q1
- **难度**：简单
- **标签**：数组、前后缀分解

**题意**：给定整数数组 `nums`。若元素 `nums[i]` 满足以下**至少一个**条件，则它是**有效**元素：

1. **严格大于**其左侧的所有元素；
2. **严格大于**其右侧的所有元素。

第一个元素和最后一个元素始终有效。返回所有有效元素组成的数组，顺序与它们在 `nums` 中出现的顺序相同。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $1 \le \text{nums}[i] \le 100$

> 💡 **审题关键**：①「严格大于」——**打平不算赢**；② 两个条件是「**或**」——赢过任意一边的所有人即可；③ 首尾「始终有效」其实是空侧语义的自然推论（一侧没有对手即 vacuously 成立），用 $-\infty$ 哨兵即可自动吸收，无需特判。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4,2,3,2]
输出：[1,2,4,3,2]
解释：nums[0] 和 nums[5] 始终有效；
     nums[1]、nums[2] 严格大于其左侧的所有元素；
     nums[4] 严格大于其右侧的所有元素；
     nums[3]（值 2）左边有 4、右边有 3，两边都打不过，无效。
```

**示例 2**

```text
输入：nums = [5,5,5,5]
输出：[5,5]
解释：中间两个 5 的左侧最大值和右侧最大值都是 5，5 > 5 不成立，
     「严格大于」下打平不算赢，双双无效，只剩首尾。
```

**示例 3**

```text
输入：nums = [1]
输出：[1]
解释：唯一元素既是首也是尾，始终有效。
```

## 3. 解题思路

### 3.1 暴力思路

照定义直译：对每个下标 $i$，向左扫一遍检查是否存在 $j < i$ 使 $nums[j] \ge nums[i]$，再向右扫一遍检查是否存在 $j > i$ 使 $nums[j] \ge nums[i]$；两侧都遇到「打不过的对手」才无效。总复杂度 $O(n^2)$。

$n \le 100$ 时至多 $10^4$ 次比较，比赛时直接写也能过。但「我左侧（右侧）所有人的最大值」这个信息在相邻下标之间只变化**一个元素**，暴力却每个 $i$ 都从头重扫两侧——同一份信息被重复计算了 $n$ 遍，应当**增量传递**。

### 3.2 核心观察：前后缀最大值

![有效判定：只需赢过一侧的最大值](images/valid_elements_prefix_suffix.svg)

**观察一（集合比较 → 单值比较）**：「严格大于左侧所有元素」⟺「严格大于左侧元素的**最大值**」。记

$$\text{leftMax}[i] = \max(nums[0..i-1]), \qquad \text{rightMax}[i] = \max(nums[i+1..n-1])$$

（空侧记为 $-\infty$），则判定式坍缩为单值比较：

$$nums[i]\ \text{有效} \iff nums[i] > \text{leftMax}[i]\ \lor\ nums[i] > \text{rightMax}[i]$$

两侧的完整分布都用不上，各压缩成一个数就够了。

**观察二（递推 $O(1)$ 转移）**：最大值满足结合律，相邻下标之间只差一个元素：

$$\text{leftMax}[i] = \max(\text{leftMax}[i-1],\ nums[i-1]), \qquad \text{rightMax}[i] = \max(\text{rightMax}[i+1],\ nums[i+1])$$

前者正序一趟、后者倒序一趟，每步 $O(1)$，整体 $O(n)$。

**观察三（空侧 = $-\infty$，首尾白送）**：$i=0$ 左侧没有元素，$\text{leftMax}[0] = -\infty$，则 $nums[0] > -\infty$ 恒真；尾部对称。题目那句「首尾始终有效」不是需要特判的边界，而是空侧语义的推论——哨兵一到，特判全消。

**记录视角**：左条件成立 ⟺ $nums[i]$ 是**严格前缀记录**，右条件 ⟺ **严格后缀记录**。全局最大值的首次出现必是前缀记录、末次出现必是后缀记录，所以 $n \ge 2$ 时答案至少 2 个（首尾各保底一个）。

### 3.3 算法流程

```text
① 倒序建表：rightMax[n-1] = −∞；i 从 n−2 到 0：
      rightMax[i] = max(rightMax[i+1], nums[i+1])
② 正序扫描：i 从 0 到 n−1，滚动维护 leftMax（初始 −∞）
③ 判定收集：若 nums[i] > leftMax 或 nums[i] > rightMax[i]，收入答案
④ 收尾：leftMax ← max(leftMax, nums[i])，扫完返回
```

要点：右侧信息与正序扫描**逆向**，必须先倒序建表备好；左侧信息与扫描**同向**，一个滚动变量即可。判定在更新之前——判定时 `leftMax` 恰为 $\max(nums[0..i-1])$。

### 3.4 示例演算

![示例演算：前后缀最大值逐下标走查](images/valid_elements_walkthrough.svg)

以 `nums = [1,2,4,2,3,2]` 逐下标走查：

| $i$ | $nums[i]$ | leftMax | rightMax | 左边全赢？ | 右边全赢？ | 收入答案 |
|-----|-----------|---------|----------|-----------|-----------|----------|
| 0 | 1 | $-\infty$ | 4 | ✓（白送） | ✗ | 1 |
| 1 | 2 | 1 | 4 | ✓ | ✗ | 2 |
| 2 | 4 | 2 | 3 | ✓ | ✓ | 4 |
| 3 | 2 | 4 | 3 | ✗（$2 \le 4$） | ✗（$2 \le 3$） | — |
| 4 | 3 | 4 | 2 | ✗ | ✓（$3 > 2$） | 3 |
| 5 | 2 | 4 | $-\infty$ | ✗ | ✓（白送） | 2 |

得 $[1,2,4,3,2]$ ✓。

## 4. 算法细节

1. **倒序建 rightMax**：`rightMax[n-1]` 置 $-\infty$（哨兵），从 $i = n-2$ 倒序递推 `rightMax[i] = max(rightMax[i+1], nums[i+1])`。右侧信息「还没见过」，逆向扫描才拿得到。
2. **正序滚动 leftMax**：初始 $-\infty$，每判定完一个元素再执行 `leftMax = max(leftMax, nums[i])`。左侧信息「已经全部见过」，与扫描同向，无需数组。
3. **先判后更新**：若先更新再判定，比较对象就混入了 $nums[i]$ 自己，口径变成「$\ge$ 左侧含自己」，逻辑变脏。
4. **哨兵取 $-\infty$**：本题值域 $\ge 1$，用 `0` 当哨兵也恰好安全，但值域含负数或 $0$ 时会翻车，养成 $-\infty$ 习惯（C++ 用 `INT_MIN`，Python 用 `float('-inf')`）。
5. **输出保序**：正序扫描按 $i$ 升序收集，天然与出现顺序一致，无需排序。

## 5. 正确性证明

**引理 1**：$nums[i]$ 严格大于其左侧所有元素 $\iff nums[i] > \text{leftMax}[i]$。

**证明**：（⇒）若 $nums[i]$ 大于左侧每个元素，则大于其中的最大值 $\text{leftMax}[i]$。（⇐）若 $nums[i] > \text{leftMax}[i]$，因左侧每个元素 $x \le \text{leftMax}[i] < nums[i]$，故 $nums[i]$ 严格大于左侧所有元素。右侧对称。∎

**引理 2**（递推正确性）：按算法流程，正序扫描到 $i$ 时滚动变量 `leftMax` $= \max(nums[0..i-1])$，数组元素 `rightMax[i]` $= \max(nums[i+1..n-1])$。

**证明**：对 `leftMax` 归纳：$i=0$ 时左侧为空，初值 $-\infty$ 即空集最大值；设处理完 $i-1$ 后 `leftMax` $= \max(nums[0..i-1])$，则处理 $i$ 时「先判后更」保证判定用的是旧值，随后更新为 $\max(\max(nums[0..i-1]),\ nums[i]) = \max(nums[0..i])$，命题对 $i+1$ 成立。对 `rightMax` 同理倒序归纳。∎

**定理**：算法返回的数组恰为全部有效元素，且顺序与在 `nums` 中出现的顺序相同。

**证明**：由引理 2，每次判定使用的 `leftMax`、`rightMax` 即定义所需的两侧最大值；由引理 1，判定条件与「严格大于左侧所有元素 $\lor$ 严格大于右侧所有元素」等价，故收入答案的恰为有效元素。首尾：$i=0$ 时 $\text{leftMax} = -\infty < nums[0]$ 恒成立（值域 $\ge 1$），$i=n-1$ 对称，覆盖「首尾始终有效」。顺序：正序扫描按下标升序收集。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。倒序建 `rightMax` 一趟 + 正序判定一趟，每步 $O(1)$。
- **空间复杂度**：$O(n)$。`rightMax` 数组（不计输出）；左侧只需 $O(1)$ 滚动变量。对照暴力 $O(n^2)$ / $O(1)$：$n \le 100$ 时暴力也能过，但 $n$ 放大到 $10^5$ 即差三个数量级，前后缀分解是通用解。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findValidElements(vector<int>& nums) {
        int n = nums.size();
        vector<int> rightMax(n, INT_MIN);            // 空侧哨兵 −∞（尾部）
        for (int i = n - 2; i >= 0; --i)
            rightMax[i] = max(rightMax[i + 1], nums[i + 1]);

        vector<int> ans;
        int leftMax = INT_MIN;                       // 滚动维护 max(nums[0..i-1])
        for (int i = 0; i < n; ++i) {
            if (nums[i] > leftMax || nums[i] > rightMax[i])
                ans.push_back(nums[i]);
            leftMax = max(leftMax, nums[i]);         // 先判后更新
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findValidElements(self, nums: list[int]) -> list[int]:
        n = len(nums)
        right_max = [float('-inf')] * n               # 空侧哨兵 −∞（尾部）
        for i in range(n - 2, -1, -1):
            right_max[i] = max(right_max[i + 1], nums[i + 1])

        ans, left_max = [], float('-inf')             # 滚动维护 max(nums[0..i-1])
        for i, x in enumerate(nums):
            if x > left_max or x > right_max[i]:
                ans.append(x)
            left_max = max(left_max, x)               # 先判后更新
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：唯一元素既是首也是尾，$-\infty$ 哨兵使其直接收入，`rightMax` 循环体不执行，天然正确。
2. **全相等**：如 $[5,5,5,5]$，中间元素的 leftMax 与 rightMax 均为 5，$5 > 5$ 不成立，只剩首尾。
3. **严格大于**：判定必须用 `>` 而非 `>=`，打平不算赢（示例 2 正是考点）。
4. **先判后更新**：`leftMax` 更新必须放在判定之后，否则自己和自己比，口径变脏。
5. **哨兵取值**：值域 $\ge 1$ 时 `0` 也能过，但养成 `INT_MIN` / `float('-inf')` 习惯，值域含负数时不翻车。
6. **两侧是「或」不是「且」**：写成「且」时答案退化为严格大于其余**所有**元素者，至多 1 个（唯一全局最大值），与题意不符。
7. **输出保序**：正序扫描天然保序；若倒序收集需最后翻转。
