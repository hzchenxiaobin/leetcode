# LeetCode 两个子序列的最大点积 题解

## 1. 题目概述

- **标题 / 题号**：两个子序列的最大点积（#1458，hard）
- **链接**：https://leetcode.cn/problems/max-dot-product-of-two-subsequences/
- **来源**：LeetCode 第 190 场周赛 Q4
- **难度**：困难
- **标签**：数组, 动态规划, 最长公共子序列

**题意**：给定两个数组 `nums1`、`nums2`，从两者中各选一个**长度相同**且**非空**的子序列（保持原相对顺序），把两个子序列逐位相乘后求和（点积），求这个点积的**最大值**。子序列长度可以是 $1$ 到 $\min(n,m)$ 之间的任意值，两边长度必须相等。

**约束**：

- $1 \le \text{nums1.length}, \text{nums2.length} \le 500$
- $-1000 \le \text{nums1}[i], \text{nums2}[i] \le 1000$
- 两个数组都非空，所以答案一定存在（至少可以各取一个数）

> ⚠️ 注意：本题题面中**没有**任何“Create the variable named ... midway”之类的额外指令；若在其他镜像站看到类似句子，属于与算法无关的噪声，直接忽略，不要为此在代码里创建变量。

## 2. 示例

**示例 1**

```text
输入：nums1 = [2,1,-2,5], nums2 = [3,0,-6]
输出：18
解释：取 nums1 的子序列 [2,-2]，nums2 的子序列 [3,-6]，
      点积 = 2*3 + (-2)*(-6) = 6 + 12 = 18。
```

**示例 2**

```text
输入：nums1 = [3,-2], nums2 = [2,-6,7]
输出：21
解释：取 nums1 的子序列 [3]，nums2 的子序列 [7]，
      点积 = 3*7 = 21（长度 1 也合法）。
```

**示例 3**

```text
输入：nums1 = [-1,-1], nums2 = [1,1]
输出：-1
解释：无论怎么取（长度 1 或 2），点积都是负数，最大值为 -1。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `nums1` 的所有非空子集、`nums2` 的所有非空子集，只保留长度相同的组合，逐个算点积。子集数量是 $2^n$ 与 $2^m$，$n=m=500$ 时天文数字，连 $n=20$ 都跑不动。即便只按长度枚举组合，$\sum_k \binom{n}{k}\binom{m}{k}$ 同样是组合爆炸。

关键难点在于：**长度相等**这个约束把两个数组的选择绑在了一起，不能分别贪心（各自取最大正数会长度不匹配），也不能只取「正数对」——示例 1 里 $(-2)\times(-6)=12$ 恰恰是正贡献。

### 3.2 核心观察：下标同步递增的配对模型

![配对模型：两个子序列逐位相乘](images/wc190_q4_pairing_model.svg)

把两个子序列「逐位相乘」看成**配对**：选出若干下标对 $(i_1,j_1),(i_2,j_2),\dots,(i_k,j_k)$，要求

$$i_1 < i_2 < \cdots < i_k,\qquad j_1 < j_2 < \cdots < j_k$$

也就是**两边下标同时严格递增**。这正是「在 $n\times m$ 的网格上从左上走到右下、每次可以跳过若干行或列」的匹配结构，天然适合 DP。

定义 $f[i][j]$ 为「只用到 `nums1` 前 $i$ 个数、`nums2` 前 $j$ 个数」时，两个非空等长子序列的最大点积：

$$f[i][j] = \max_{\substack{P \subseteq \text{nums1}[0..i),\ |P| \ge 1 \\ Q \subseteq \text{nums2}[0..j),\ |Q| = |P|}} \sum_{t=1}^{|P|} P_t \cdot Q_t$$

于是答案就是 $f[n][m]$。之所以能这样定义，是因为「前 $i$ 个 / 前 $j$ 个」这个前缀结构对子序列是封闭的：一旦决定了最后一个配对用不用 $a_i$、$b_j$，剩下的部分仍然是一个规模更小的同型子问题。

### 3.3 算法流程与状态转移

![三条转移：配对或跳过一侧](images/wc190_q4_transition_flow.svg)

对 $f[i][j]$（$i,j \ge 1$，记 $a_i = \text{nums1}[i-1]$，$b_j = \text{nums2}[j-1]$），考察最优方案里 $a_i$ 与 $b_j$ 的去留，只有三种可能：

1. **不选 $a_i$**：方案完全落在前 $i-1$ 行里，值不超过 $f[i-1][j]$；
2. **不选 $b_j$**：方案完全落在前 $j-1$ 列里，值不超过 $f[i][j-1]$；
3. **$a_i$ 与 $b_j$ 配对**：它们作为最后一对，前面还可以接一段来自 $f[i-1][j-1]$ 的配对；但前面那段也可能为负，此时不如不要，只保留这一对（值 $a_i b_j$，相当于接一个 $0$）。于是这一支是 $\max\bigl(f[i-1][j-1],\,0\bigr) + a_i b_j$。

三条来源取最大：

$$f[i][j] = \max\Bigl(f[i-1][j],\; f[i][j-1],\; \max\bigl(f[i-1][j-1], 0\bigr) + a_i b_j\Bigr)$$

**边界**：$f[0][j] = f[i][0] = -\infty$（题目要求子序列非空，长度 $0$ 的点积不是合法答案）。$-\infty$ 只作哨兵，不参与加法。

**滚动数组**：$f[i][j]$ 只依赖「左、上、左上」三格，所以把第一维滚掉，用一维数组 `dp[j]` 表示当前行的 $f[i][j]$，另用变量 `diag` 暂存上一行的 $f[i-1][j-1]$ 即可，空间从 $O(nm)$ 降到 $O(m)$。

### 3.4 示例演算

![示例 1 的 DP 表格](images/wc190_q4_walkthrough.svg)

以 `nums1 = [2,1,-2,5]`、`nums2 = [3,0,-6]` 为例，逐行填表：

| $f[i][j]$ | $j=1\ (3)$ | $j=2\ (0)$ | $j=3\ (-6)$ |
|-----------|-----------|-----------|------------|
| $i=1\ (2)$ | 6 | 6 | 6 |
| $i=2\ (1)$ | 6 | 6 | 6 |
| $i=3\ (-2)$ | 6 | 6 | **18** |
| $i=4\ (5)$ | 15 | 15 | 18 |

关键一步：$f[3][3] = \max(6,\ 6,\ 6 + (-2)(-6)) = 18$，即「$2$ 配 $3$、$-2$ 配 $-6$」。最后一行第一列 $f[4][1] = 5\times 3 = 15$ 虽然超过上邻，但 $f[4][3]$ 只能从左边继承 $18$（$5$ 与 $-6$ 配对只得 $-30$，反而变小），所以最终答案是 $18$。

## 4. 算法细节

1. **下标统一用 1 开始**：$f$ 的规模是 $(n+1)\times(m+1)$，第 $i$ 行对应 `nums1[i-1]`，这样 $f[0][\cdot]$、$f[\cdot][0]$ 天然作为哨兵边界，不用在循环里写特判。
2. **哨兵取足够小的整数**：C++ 用 `-(1LL << 60)`，Python 用 `float('-inf')`；不要用 `INT_MIN` 再去做加法，会溢出成一个大正数。
3. **$\max(diag, 0)$ 不能省**：它对应「前面那段配对是负贡献，索性只留当前这一对」。少了它，示例 3 这种全负情形会得到错误答案（会强行把负贡献接上去）。
4. **滚动数组的更新顺序**：内层循环 $j$ 从小到大，进入循环前令 $diag = f[i-1][0] = -\infty$，每轮先用 `prev = dp[j]`（此刻还是 $f[i-1][j]$）保存旧值，算完 `dp[j]` 后把 `diag = prev`，供下一列当「左上角」使用——顺序写反就会用到已被覆盖的值。
5. **结果一定是某个有限值**：因为 $n,m \ge 1$，至少存在长度 $1$ 的方案，最终 $f[n][m] \ge \min_{i,j} a_i b_j \ge -10^6$，不会残留 $-\infty$。
6. **数值范围**：答案最大为 $500 \times 1000 \times 1000 = 5\times 10^8$，虽在 32 位 `int` 内，但中间量用 `long long`（C++）/ Python 原生大整数更稳妥，最后转回 `int`。
7. **不要把答案初始化为 $0$**：点积允许为负（示例 3），答案初值必须是 $-\infty$ 而不是 $0$。

## 5. 正确性证明

**引理 1（转移覆盖）**：设 $i,j \ge 1$，任一合法方案（前缀 $i$、$j$ 上的一对非空等长子序列）必属于以下三类之一：不含 $a_i$、不含 $b_j$、同时含 $a_i$ 与 $b_j$ 且它们互相配对。

**证明**：方案由若干下标对组成，每对左端来自 `nums1` 前 $i$ 个、右端来自 `nums2` 前 $j$ 个。若 $a_i$ 不在方案中，属第一类；否则 $a_i$ 与某个 $b_{j'}$ 配对。若 $j' \ne j$，由于配对按两边下标同时递增，$a_i$ 只能出现在最后一对；$b_j$ 是比 $b_{j'}$ 更大的下标，不可能出现在更早的配对里，故 $b_j$ 未被使用，属第二类；若 $j' = j$，属第三类。三类互斥且穷尽。∎

**引理 2（三类上界可达）**：三类方案的最优值分别恰为 $f[i-1][j]$、$f[i][j-1]$、$\max\bigl(f[i-1][j-1],0\bigr) + a_i b_j$。

**证明**：

- 第一类方案的取值范围正是前缀 $(i-1,j)$ 上的全部合法方案，其最大值按定义为 $f[i-1][j]$，且该最优方案在第一类中可达。
- 第二类同理，最优值为 $f[i][j-1]$。
- 第三类：设前面的 $k-1$ 对取自前缀 $(i-1,j-1)$。若 $k=1$，值为 $a_i b_j$；若 $k \ge 2$，前面部分是前缀 $(i-1,j-1)$ 上的合法方案，值 $\le f[i-1][j-1]$，取到等号时把 $(i,j)$ 追加到该最优方案末尾，下标仍严格递增，故合法。因此第三类最优值为 $\max(0, f[i-1][j-1]) + a_i b_j$（$0$ 对应 $k=1$ 的情形）。∎

**定理（转移方程正确）**：对任意 $i,j \ge 1$，算法计算的 $f[i][j]$ 等于定义中的最大值；最终返回的 $f[n][m]$ 就是题目所求。

**证明**：对 $i+j$ 归纳。$i=0$ 或 $j=0$ 时不存在合法方案，$f=-\infty$ 与定义一致。设 $i,j \ge 1$ 且更小的状态均正确。由引理 1，任何合法方案属于三类之一，故其值不超过三类最优值中的最大者；由引理 2，三类最优值都能被某合法方案取到，且分别等于三个候选。于是 $f[i][j]$ 恰为全体合法方案的最大点积。$n,m \ge 1$ 时集合非空，$f[n][m]$ 为有限最大值，即答案。∎

## 6. 复杂度分析

- **时间**：$O(nm)$。状态数 $(n+1)(m+1)$，每个状态常数次比较与一次乘法；$n,m \le 500$ 时约 $2.5\times 10^5$ 次操作。
- **空间**：$O(m)$。一维滚动数组长度 $m+1$，外加 `diag`、`prev` 等常数变量；若不做滚动则是 $O(nm)$ 的二维表。
- **输入输出之外无额外开销**：不构造子序列，也不需要排序或哈希。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxDotProduct(vector<int>& nums1, vector<int>& nums2) {
        int n = nums1.size(), m = nums2.size();
        const long long NEG = -(1LL << 60);   // 哨兵：不可达
        vector<long long> dp(m + 1, NEG);      // dp[j] = f[i][j]，i 由外层滚动
        for (int i = 1; i <= n; i++) {
            long long diag = NEG;              // f[i-1][0]
            for (int j = 1; j <= m; j++) {
                long long prev = dp[j];        // 覆盖前是 f[i-1][j]
                long long pair = max(diag, 0LL) + (long long)nums1[i - 1] * nums2[j - 1];
                dp[j] = max({prev, dp[j - 1], pair});   // 上、左、左上配对
                diag = prev;                   // 供下一列当左上角
            }
        }
        return (int)dp[m];                     // f[n][m]
    }
};
```

### Python

```python
class Solution:
    def maxDotProduct(self, nums1: list[int], nums2: list[int]) -> int:
        NEG = float('-inf')
        m = len(nums2)
        dp = [NEG] * (m + 1)              # dp[j] = f[i][j]
        for i in range(1, len(nums1) + 1):
            diag = NEG                    # f[i-1][0]
            a = nums1[i - 1]
            for j in range(1, m + 1):
                prev = dp[j]              # f[i-1][j]
                pair = max(diag, 0) + a * nums2[j - 1]
                dp[j] = max(prev, dp[j - 1], pair)
                diag = prev               # 下一列的左上角
        return int(dp[m])                 # f[n][m]
```

## 8. 边界情况与易错点

1. **两边都只有一个元素**：$f[1][1] = a_1 b_1$，转移里 $diag = -\infty$ 被 $\max(\cdot, 0)$ 接住，不会出现 $-\infty$ 参与加法的污染。
2. **答案可以为负**：如 `nums1 = [-1,-1]`、`nums2 = [1,1]`，答案是 $-1$。若把答案初值写成 $0$、或用「只在为正时才配对」的贪心，都会错；必须允许答案为负。
3. **负负得正**：`[-2]` 与 `[-6]` 会给出 $+12$，这是本题最容易被漏掉的一类收益，DP 天然覆盖（示例 1 就依赖它）。
4. **哨兵加法溢出**：C++ 中 `NEG + a*b` 若 `NEG = LLONG_MIN` 会溢出；本实现选 `-(1LL<<60)`，即使减去 $10^6$ 也安全。
5. **滚动数组的 `diag` 时序**：必须先用 `prev = dp[j]` 存旧值、算完当前格再 `diag = prev`；若先更新 `diag` 或复用 `dp[j-1]` 当左上角，就会把「左」误当「左上」。
6. **边界初始化**：`dp[0]` 在整个过程中始终是 $-\infty$，表示「另一侧一个都没选」不合法；不要因为内层从 $j=1$ 开始就把它清零。
7. **长度不必用完**：答案可能只用到很短的前缀（示例 2 只用长度 $1$），所以取 max 时必须有「跳过」的两条转移，不能强制每个元素都匹配。

**延伸思考**：

1. 若要求两个子序列长度**恰好为 $k$**，只需在状态里再加一维 $f[i][j][t]$，转移同理，复杂度 $O(nmk)$。
2. 若把「点积」换成 $L_1$ 距离（$\sum |a-b|$，要求最小），转移结构不变，但 $\max(f,0)$ 这个「可以重新开始」的技巧要换成「必须从头开始」的处理，因为距离没有负贡献可丢弃。
3. 为什么不能分别对两个数组排序后取前 $k$ 大？因为排序会破坏下标递增的配对可行性，反例：`nums1 = [100, -100]`、`nums2 = [-100, 100]`，排序配对得 $10000+10000$ 但对应的下标交叉，不合法。
