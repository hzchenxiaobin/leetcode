# LeetCode 检查单词是否为句中其他单词的前缀 题解

## 1. 题目概述

- **标题 / 题号**：检查单词是否为句中其他单词的前缀（#1455，easy）
- **链接**：https://leetcode.cn/problems/check-if-a-word-occurs-as-a-prefix-of-any-word-in-a-sentence/
- **来源**：LeetCode 第 190 场周赛 Q1
- **难度**：简单
- **标签**：字符串，双指针，字符串匹配

**题意**：给定句子 `sentence`（若干单词，用单个空格分隔）与检索词 `searchWord`，判断 `searchWord` 是否为句中某个单词的**前缀**。是则返回该单词的下标（**从 1 开始**）；若有多个单词都满足，返回**最小**下标；都不是则返回 `-1`。前缀指字符串的任意前导连续子串，允许等于整个单词。

**约束**：

- $1 \le \lvert \text{sentence} \rvert \le 100$
- $1 \le \lvert \text{searchWord} \rvert \le 10$
- `sentence` 只含小写英文字母和空格，单词之间恰好一个空格，首尾无空格
- `searchWord` 只含小写英文字母（**不含空格**，这一条后面会用到）

## 2. 示例

**示例 1**

```text
输入：sentence = "i love eating burger", searchWord = "burg"
输出：4
解释："burg" 是 "burger" 的前缀，而 "burger" 是句中第 4 个单词。
```

**示例 2**

```text
输入：sentence = "this problem is an easy problem", searchWord = "pro"
输出：2
解释："problem" 既是第 2 个也是第 6 个单词，但要求返回最小下标，故答案为 2。
```

**示例 3**

```text
输入：sentence = "i am tired", searchWord = "you"
输出：-1
解释：没有任何单词以 "you" 开头。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法：按空格切分出所有单词，再对每个单词调用 `startswith` / `compare` 判断前缀，第一个满足的返回其序号。

设句子长度 $n$、检索词长度 $m$，切分需要 $O(n)$，每个单词最多再比 $m$ 个字符，总共 $O(n \cdot m)$——本题 $n \le 100$ 完全够用。它的缺点不在复杂度，而在**实现方式**：每个单词都要分配一次字符串（C++ 的 `substr`、Python 的 `split`），代码里还得额外维护序号变量。

另外两个“看起来更聪明、其实有坑”的写法：

- 直接 `sentence.find(searchWord)`：返回的位置可能落在**单词中间**，例如 `sentence = "hello"`、`searchWord = "ell"` 会返回 1，必须再检查前一个字符是不是空格（或已到句首），不合法还要继续往后找。
- 用 `stringstream` / 正则切分：正确但没有必要，Q1 想沉淀的是一条最短路径。

### 3.2 核心观察：前缀判定只在词首落地

![词首比较：只有落在单词起点的窗口才算前缀](images/wc190_q1_word_start_scan.svg)

两个关键点：

1. 只有当窗口起点 $i$ 本身是某个单词的第一个字符时，$s[i..i+m)$ 才可能是该单词的前缀。判别方式极简：$i = 0$ 或者 $s[i-1]$ 是空格。
2. 因为从左到右扫描，**第一次命中时它就是最小下标**，不需要额外维护 `min`。

还有一个极易被忽略的细节：**不需要检查词尾**。若窗口跨过了空格，这 $m$ 个字符里就含空格，而 `searchWord` 只含小写字母，比较必然失败；若窗口越过句子末尾，直接用 $i + m \le n$ 挡掉。于是判定只剩一句：

$$i + m \le n \quad \text{且} \quad s[i..i+m) = \text{searchWord}$$

### 3.3 算法流程

![单指针扫描流程](images/wc190_q1_algorithm_flow.svg)

1. `word = 0` 记录“当前是第几个单词”，`i` 从 $0$ 扫到 $n-1$。
2. 若 `i == 0` 或 `s[i-1] == ' '`，说明 `i` 是词首，令 `word += 1`。
3. 在词首处做一次长度为 $m$ 的比较，先判 `i + m <= n` 防止窗口越界。
4. 相等 → 返回 `word`；不相等 → `i += 1` 继续扫描。
5. 扫完整句仍未命中 → 返回 `-1`。

### 3.4 示例演算

![示例 2 的逐位置走查](images/wc190_q1_walkthrough.svg)

以 `sentence = "this problem is an easy problem"`、`searchWord = "pro"` 为例，$n = 31$，词首位置只有 0、5、13、16、19、24：

| 词首 $i$ | 窗口 $s[i..i+3)$ | 与 "pro" 比较 | 动作 |
|---|---|---|---|
| 0 | "thi" | 不等 | i++ |
| 5 | "pro" | **相等** | **返回 2** |
| 13 | "is " | 不等（末位是空格） | 已提前返回 |
| 16 | "an " | 不等（末位是空格） | 未访问 |
| 19 | "eas" | 不等 | 未访问 |
| 24 | "pro" | 相等 | 未访问 |

$i = 5$ 处命中即返回，所以第 6 个单词虽然也以 "pro" 开头，却根本不会被访问——“最小下标”是扫描顺序白送的，这也是本题不需要排序、不需要取 `min` 的原因。

## 4. 算法细节

1. **词首判定**：`i == 0 || sentence[i-1] == ' '`。题目保证单词间恰好一个空格、首尾无空格，因此不会出现空单词，序号也不会虚高。
2. **不切分句子**：直接在下标层面扫描，避免 `substr` / `split` 的分配；C++ 用 `sentence.compare(i, m, searchWord)`，Python 用切片 `sentence[i:i+m] == searchWord`（$m \le 10$，切片开销可忽略）。
3. **`i + m <= n` 的作用**：严格说，C++ 的 `compare` 与 Python 的切片在“剩余字符不足 $m$ 个”时都不会误判为相等（长度不同天然不等），保留这个判断是为了把“窗口恰好是完整的 $m$ 个字符”这一不变量**显式化**，不去依赖库函数在长度不足时的比较语义；同时也顺手排除了越界访问。
4. **单词计数的时机**：`word += 1` 只在词首执行，因此它始终等于“已经开始的单词个数”，返回值天然是 1-indexed。
5. **不要用 `find` 替代扫描**：`find` 会把单词内部的匹配也当成命中，必须再判前驱字符；一旦前驱不是空格还得从下一个位置继续找，代码更长也更容易错。
6. **返回值语义**：返回的是**单词序号**（1-indexed），不是字符下标（0-indexed）。这是本题最常见的丢分点。

## 5. 正确性证明

**引理 1（词首的刻画）**：在题目保证下（单词间恰好一个空格、首尾无空格），下标 $i$ 是某个单词的首字符当且仅当 $i = 0$ 或 $s[i-1]$ 是空格。

**证明**：若 $i = 0$，句子的第一个字符显然是第一个单词的首字符。若 $i > 0$ 且 $s[i-1]$ 是空格，由“空格只出现在单词之间且恰好一个”，$s[i]$ 必为下一个单词的首字符。反向：若 $i$ 是词首且 $i > 0$，则 $s[i-1]$ 只能是空格，否则 $s[i-1]$ 与 $s[i]$ 之间没有空格，二者同属一个单词，与 $i$ 是词首矛盾。∎

**引理 2（词首处判定的充要性）**：设 $i$ 是词首，它所在单词为 $s[i..j)$。若 $i + m \le n$，则 $s[i..i+m) = \text{searchWord}$ 当且仅当 searchWord 是该单词的前缀。

**证明**：

- ($\Leftarrow$) 若 searchWord 是单词前缀，则 $m \le j - i$，单词的前 $m$ 个字符正是 $s[i..i+m)$，故两者相等。
- ($\Rightarrow$) 若 $s[i..i+m) = \text{searchWord}$：searchWord 不含空格，故这 $m$ 个字符也不含空格，全部落在单词 $s[i..j)$ 内部，即 $i + m \le j$；它们正是该单词的前 $m$ 个字符。∎

**定理**：算法输出正确——命中时返回满足条件的最小单词序号，否则返回 `-1`。

**证明**：完备性：若 searchWord 是某单词 $s[i..j)$ 的前缀，则 $m \le j-i$ 且 $j \le n$，故 $i+m \le n$，守卫条件通过；由引理 1，$i$ 会被识别为词首；由引理 2，该处的比较必然相等，于是算法返回而不会漏掉。最小性：由引理 1，算法恰好在每个词首做判定且不漏不重；扫描方向从左到右，命中的第一个单词序号最小，返回后不再访问更大的下标。正确性：由引理 2，每次比较为真都对应“确实是前缀”，不存在误报。若扫完从未命中，说明不存在以 searchWord 为前缀的单词，返回 `-1` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n \cdot m)$ 最坏。扫描本身 $O(n)$；比较只在词首发生，每次 $O(m)$。单词个数 $k$ 满足 $n \ge 2k-1$（每个单词至少 1 个字符，单词间 1 个空格），故 $k \le (n+1)/2$，比较总代价 $O(n \cdot m)$。本题 $n \le 100$、$m \le 10$，实际字符比较不超过千次。
- **空间**：$O(1)$ 额外空间，只用 `i`、`word` 两个整数（不计输入本身）。若改用切分写法，则额外需要 $O(n)$ 的字符串数组。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    int isPrefixOfWord(string sentence, string searchWord) {
        int n = (int)sentence.size(), m = (int)searchWord.size();
        int word = 0;
        for (int i = 0; i < n; ++i) {
            if (i == 0 || sentence[i - 1] == ' ') {   // i 是单词起点
                ++word;                               // 当前是第 word 个单词
                if (i + m <= n && sentence.compare(i, m, searchWord) == 0) {
                    return word;                      // 第一次命中即最小下标
                }
            }
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def isPrefixOfWord(self, sentence: str, searchWord: str) -> int:
        n, m = len(sentence), len(searchWord)
        word = 0
        for i in range(n):
            # 只有句首或空格之后才是单词起点
            if i == 0 or sentence[i - 1] == ' ':
                word += 1
                # 窗口放得下 m 个字符，且它们与检索词完全相同
                if i + m <= n and sentence[i:i + m] == searchWord:
                    return word
        return -1
```

## 8. 边界情况与易错点

1. **整句只有一个单词**：`sentence = "i"`、`searchWord = "i"` → 返回 1；`searchWord = "ii"` → 返回 -1（$i+m > n$，根本不给比较机会）。
2. **searchWord 比任何单词都长**：如 `sentence = "hello"`、`searchWord = "helloworld"`，守卫条件恒不成立，扫完返回 -1，绝不能越界访问。
3. **匹配落在单词中间**：`sentence = "hello"`、`searchWord = "ell"` → -1。若用 `find` 而不校验前驱字符，会错答 1。
4. **前缀等于整个单词**：`sentence = "a ab"`、`searchWord = "a"` → 返回 1。前缀允许与单词等长，别把条件写成“后面还必须剩字符”。
5. **多个单词同时满足**：`"this problem is an easy problem"` + `"pro"` → 2。必须从左到右、命中即返回，才是最小下标。
6. **空格规则的隐含假设**：解法依赖“单空格、无首尾空格”。若放宽成连续空格，词首后面可能紧跟空格形成空单词，`word` 需要跳过连续空格后再自增，否则序号会虚高。
7. **返回值混淆**：返回 1-indexed 的单词序号，不是字符下标。`"i love eating burger"` + `"burg"` 返回 4 而不是 16。

**延伸思考**：

- 若要求返回**所有**满足条件的单词序号，扫描就不能提前返回，需要把命中位置全部收集起来，时间仍是 $O(n \cdot m)$。
- 若 `searchWord` 有很多次查询（同一个 `sentence` 反复用），可以先把单词建成前缀树（Trie），单次查询降到 $O(m)$；或对所有单词按字典序排序后二分，查询 $O(m \log k)$。
- 若句子允许连续空格与首尾空格，词首判别应改为“$i = 0$ 或 $s[i-1]$ 是空格，且 $s[i]$ 不是空格”，同时空单词不能计入序号。
