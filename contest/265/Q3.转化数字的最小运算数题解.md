# LeetCode 转化数字的最小运算数 题解

## 1. 题目概述

- **标题 / 题号**：转化数字的最小运算数（#2059，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-convert-number/
- **来源**：LeetCode 第 265 场周赛 Q3
- **难度**：中等
- **标签**：广度优先搜索、隐式图最短路、状态去重

**题意**：给定互不相同整数的数组 `nums` 与整数 `start`、`goal`。变量 $x$ 初始为 `start`，每次运算可任取一个 `nums[i]` 把 $x$ 变为 $x + nums[i]$、$x - nums[i]$、$x \oplus nums[i]$ 三者之一，算一步。限制是：**只有** $0 \le x \le 1000$ 时才允许继续运算；使 $x$ 越出该范围的运算**同样生效**，但执行后不能再做任何运算（成为终态）。求把 $x$ 变为 `goal` 的最少运算次数，不可达返回 $-1$。

**约束**：

- `1 <= nums.length <= 1000`
- $-10^9 \le nums[i], goal \le 10^9$
- $0 \le start \le 1000$，且 `start != goal`
- `nums` 中元素互不相同

> 💡 本题的两个题眼：① 求**最少步数**且每步代价相同 → 想到无权图最短路 = **BFS**；② 运算的前提条件把**可扩展状态**限制在 $[0,1000]$，而 `goal` 却可达 $\pm 10^9$ → 「判等」必须发生在**丢弃越界结果之前**。这是分场胜负的关键一步。

## 2. 示例

**示例 1**

```text
输入：nums = [2,4,12], start = 2, goal = 12
输出：2
解释：2 →(+12)→ 14 →(−2)→ 12，共 2 步。
goal = 12 在 [0,1000] 域内，属于"普通节点"式命中。
```

**示例 2**

```text
输入：nums = [3,5,7], start = 0, goal = -4
输出：2
解释：0 →(+3)→ 3 →(−7)→ −4，共 2 步。
最后一步 3 − 7 = −4 越出 [0,1000]，运算仍然生效且恰好等于 goal。
```

**示例 3**

```text
输入：nums = [2,8,16], start = 0, goal = 1
输出：-1
解释：0 出发能凑出的数与 2、8、16 的组合均为偶数，1 永远不可达。
```

## 3. 解题思路

### 3.1 暴力思路

朴素做法是从 `start` 出发 DFS 枚举所有运算序列，取到达 `goal` 的最小步数。两个死穴：

- **序列可以无限长**：$+num$ 与 $-num$ 互为逆运算，来回执行值不变，搜索树深度无界；
- **记忆化 DFS 求最小步数在有环图上不成立**：状态间成环（$x \to x + num \to x$），而 DFS 深入优先、不按层扩展，**首次**到达某状态时的步数不一定是最短步数；按「访问过就跳过」直接记忆化，会把非最短的值缓存成答案。

另有一种错误直觉是找数学规律贪心构造（比如按二进制位用 $\oplus$ 逼近），但 $\oplus$ 与 $\pm$ 混合后毫无单调性可言。正解只能老老实实做**最短路搜索**——而最短路的正确姿势是 BFS。

### 3.2 核心观察：可扩展状态只有 1001 个

![核心观察：可扩展状态域与越界终态](images/wc265_min_ops_state_space.svg)

关键是把「**可扩展状态**」和「**终态**」区分开：

- **可扩展状态**：$x \in [0, 1000]$，共 **1001** 个。只有这些值能继续做运算，是 BFS 真正需要入队、遍历的节点——**与 $nums[i]$、$goal$ 高达 $10^9$ 无关**。
- **越界终态**：某次运算的结果 $nx < 0$ 或 $nx > 1000$。它是一次**合法运算**的结果（越界运算同样生效），但之后不能再运算，所以只做一次「$nx == goal$？」的判等就丢弃，不入队。

于是整个问题被建模成一张**隐式无权图**：

- **节点**：$[0,1000]$ 中的全部整数（外加一个虚拟终点 `goal`）；
- **边**：每个节点 $x$ 引出 $3n$ 条边（$n$ = `nums.length`，每个 `num` 三种运算），边权全为 1；
- **goal 的两种位置**：若 `goal` $\in [0,1000]$，它是图中的普通节点；若在域外（$|goal|$ 可达 $10^9$），它**没有出边、也无法被扩展到**，只能作为某条边的终点被「一锤定音」地判等命中。

> 💡 无权图最短路 = BFS：按层扩展，**首次**让某条运算结果等于 `goal` 的层数就是最少运算次数。状态只有 1001 个，每个只处理一次，复杂度立刻可控。

### 3.3 算法流程：先判等、再判域、后入队

![BFS 流程：先判等、再判域、后入队](images/wc265_min_ops_bfs_flow.svg)

1. **初始化**：`dist` 数组大小 1001 填 $-1$（兼做 visited 与步数）；`dist[start] = 0`，`start` 入队。
2. **主循环**：取出队首 $x$。对每个 `num ∈ nums`、每个 $nx \in \{x + num,\ x - num,\ x \oplus num\}$：
   - **先判等**：$nx == goal$ → 立即返回 $dist[x] + 1$（越界结果也能在这里命中）；
   - **再判域**：$0 \le nx \le 1000$ 且 `dist[nx] == -1` → 置 `dist[nx] = dist[x] + 1` 并入队；
   - 否则丢弃。
3. **队空未命中**：返回 $-1$。

> ⚠️ **判等必须在判域之前**——本题最大的坑。若先判 `0 <= nx <= 1000`，那么当 `goal` 在域外（如示例 2 的 `goal = -4`）时，唯一的命中机会（越界结果 $-4$）会先被「不在域内」分支丢弃，答案永远是 $-1$。把「判等」放在一切分支之前，才能让越界结果参与比较。

### 3.4 示例演算

![示例 2 演算：goal 在域外，靠越界运算命中](images/wc265_min_ops_walkthrough.svg)

以示例 2 `nums = [3,5,7]`，`start = 0`，`goal = −4` 为例：

**层 0**：$\{0\}$，`dist[0] = 0`。

**层 1**：从 $x=0$ 展开：$0+3=3$、$0+5=5$、$0+7=7$ 入队（$0 \oplus num = num$，与加法结果相同被去重）；$0-3=-3$、$0-5=-5$、$0-7=-7$ 越界且 $\ne -4$，丢弃。队列：$\{3, 5, 7\}$。

**层 2**：先处理 $x=3$：$3+3=6$、$3+5=8$、$3 \oplus 5=6$、$3+7=10$ 等常规入队；轮到 $num=7$ 的减法时 $3-7=-4$ **== goal** ⭐ 返回 `dist[3] + 1 = 2`。路径 $0 \to(+3)\to 3 \to(-7)\to -4$，末步越界命中。

再看示例 1 `nums = [2,4,12]`，`start = 2`，`goal = 12`（goal 在域内）：

| 层 | 出队状态 | 关键邻居 | 结果 |
|----|---------|---------|------|
| 0 | 2 | $2{\pm}2, 2{\oplus}2 \to \{0,4\}$；$2{\pm}4 \to \{6,-2\}$；$2{\pm}12 \to \{14,-10\}$ | 入队 $\{0,4,6,14\}$ |
| 1 | 0（先出队） | $0+12=12$ **== goal** ⭐ | 返回 `dist[0]+1 = 2` |

（若先处理 $14$，则 $14-2=12$ 同样命中；两条 2 步路径 $2 \to(-2)\to 0 \to(+12)\to 12$ 与 $2 \to(+12)\to 14 \to(-2)\to 12$ 并列最短。）

## 4. 算法细节

1. **`dist` 数组一举三得**：状态域恰是连续整数 $[0,1000]$，用大小 1001 的数组同时完成「visited 去重」「步数记录」「默认 $-1$」三件事，比哈希集合省常数。
2. **邻居枚举的去重**：同一个 `num` 的三种运算可能产生相同值（如 $x - num = x \oplus num$，或 $num=0$ 时三者都等于 $x$），`dist[nx] == -1` 的检查天然把重复邻居挡在队列外，无需显式去重。
3. **判等先于判域**：见 3.3 的 ⚠️——这是本题唯一的新考点，也是 WA 率最高的地方。
4. **入队即标记**：`dist[nx]` 在**入队时**赋值，而不是出队时。否则同一状态会被多个前驱重复入队，队列规模失控。
5. **扩展时返回 vs 出队时返回**：本实现选择在扩展邻居时判等并提前返回，能覆盖「goal 在域外」的命中；goal 在域内时同样正确（BFS 出队顺序按层单调，首次命中必为最短，见第 5 节证明）。
6. **负数参与 $\oplus$**：$x \ge 0$ 与负数 `num` 异或，结果的符号位为 1，**必为负数**，自动落入「越界只判等」分支，不影响正确性（C++20 起有符号位运算按补码明确定义；Python 按无限位补码，行为一致）。

## 5. 正确性证明

**引理 1（中间状态有界）**：任何 $k$ 步合法操作序列 $x_0 = start \to x_1 \to \cdots \to x_k = goal$ 中，前 $k-1$ 个结果均满足 $x_1, \ldots, x_{k-1} \in [0, 1000]$。

**证明**：对 $1 \le j \le k-1$，第 $j$ 步之后还要执行第 $j+1$ 步运算；题意规定只有 $0 \le x_j \le 1000$ 时才允许继续运算，故 $x_j \in [0,1000]$。$x_k = goal$ 是最后一步的结果，允许越界。∎

**引理 2（BFS 距离正确）**：算法运行过程中，任一状态 $y \in [0,1000]$ 被赋值 `dist[y]` 时，`dist[y]` 恰等于从 `start` 到 $y$ 的最少运算步数 $d^*(y)$。

**证明**：按赋值次序归纳。`dist[start] = 0` 正确。任一赋值形如 `dist[y] = dist[x] + 1`，其中 $x \to y$ 是一步合法运算；反向追溯赋值链得到一条长度为 `dist[y]` 的合法路径，故 `dist[y]` $\ge d^*(y)$。反之设 $d^*(y) = m$，取一条最短路径 $z_0 \to \cdots \to z_m = y$；与引理 1 同理，$z_1, \ldots, z_{m-1}$ 均在域内，且 $d^*(z_i) = i$（若 $d^*(z_i) < i$，则拼上后缀得 $d^*(y) < m$，矛盾）。归纳于 $i$：$z_i$ 由 $z_{i-1}$（`dist` 已为 $i-1$）一步可达，BFS 处理完所有 `dist` $\le i-1$ 的状态后，$z_i$ 必已被赋值 $\le i$，结合下界得恰为 $i$。∎

**定理**：算法返回的值是使 $x = start$ 变为 `goal` 的最少运算次数；不可达时返回 $-1$。

**证明**：

- **返回值是合法步数（无多报）**：命中时返回 `dist[x] + 1`，其中 `dist[x]` 由引理 2 对应一条真实的最短路径，最后一步 $x \to nx = goal$ 是合法运算（越界运算同样生效）。故最少运算次数 $\le$ 返回值。
- **返回值不多不少（无漏报）**：设最少运算次数为 $k$，最优路径如引理 1 所述，其倒数第二个状态 $x_{k-1} \in [0,1000]$ 且 $d^*(x_{k-1}) = k-1$，必在 `dist` $= k-1$ 层被处理。BFS 出队状态的 `dist` 单调不降：在处理 `dist` $\le k-2$ 的状态期间若已命中，则返回值 $\le k-1$，与「返回值是合法步数且 $k$ 最小」矛盾；故算法恰好（最迟在处理 $x_{k-1}$、扩展出 $nx = goal$ 时）返回 $k$。
- **不可达时**：任何扩展的判等均不成立（否则由第一条可达），状态至多 1001 个，队列必空，返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1001 \times 3n) = O(n)$，其中 $n$ 为 `nums.length`。每个域内状态至多出队一次，每次展开 $3n$ 个邻居；$n \le 1000$ 时总量约 $3 \times 10^6$ 次整数运算，毫秒级。
- **空间复杂度**：$O(1001)$。`dist` 数组与队列中的状态数均以 1001 为上界（不计输入数组）。

> 💡 判断这类题可行性的口诀：**可扩展状态总数 × 单状态转移数 = BFS 的时间上界**。本题前者是被题目规则硬限定的常数 1001，后者 $3n$，一眼可过。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumOperations(vector<int>& nums, int start, int goal) {
        vector<int> dist(1001, -1);
        queue<int> q;
        dist[start] = 0;
        q.push(start);

        while (!q.empty()) {
            int x = q.front();
            q.pop();
            for (int num : nums) {
                for (int nx : {x + num, x - num, x ^ num}) {
                    if (nx == goal) {
                        return dist[x] + 1;      // 先判等：越界结果也能命中
                    }
                    if (nx >= 0 && nx <= 1000 && dist[nx] == -1) {
                        dist[nx] = dist[x] + 1;  // 再判域：入队即标记
                        q.push(nx);
                    }
                }
            }
        }
        return -1;                               // 队空仍未命中
    }
};
```

### Python

```python
class Solution:
    def minimumOperations(self, nums: List[int], start: int, goal: int) -> int:
        dist = [-1] * 1001
        q = deque([start])
        dist[start] = 0

        while q:
            x = q.popleft()
            for num in nums:
                for nx in (x + num, x - num, x ^ num):
                    if nx == goal:
                        return dist[x] + 1       # 先判等：越界结果也能命中
                    if 0 <= nx <= 1000 and dist[nx] == -1:
                        dist[nx] = dist[x] + 1   # 再判域：入队即标记
                        q.append(nx)
        return -1                                # 队空仍未命中
```

## 8. 边界情况与易错点

1. **判等顺序（最高频 WA）**：`nx == goal` 必须写在 `0 <= nx <= 1000` 之前，否则域外 goal（示例 2）永远命不中，输出错误的 $-1$。
2. **goal 在域内 ≠ 可当普通节点搜**：goal 即使在 $[0,1000]$ 内，也应在**扩展邻居时**判等返回（本实现的写法两种位置通吃）；若改成因内 goal 出队判等，需保证逻辑覆盖。
3. **负数参与异或**：$x \ge 0$ 与负 `num` 异或结果必为负，只走「越界判等」分支；数值不超过 $2^{30}$ 量级，无溢出风险。
4. **加减法溢出**：$|x \pm num| \le 1000 + 10^9 < 2^{31} - 1$，32 位 `int` 安全；Python 无此问题。
5. **`num = 0` 的自环**：$x+0 = x-0 = x \oplus 0 = x$，`dist[x] != -1` 自然跳过，无需特判。
6. **`start == goal`**：题目约束已排除；若数据放开，需在 BFS 前特判返回 0。
7. **重复邻居**：$x + num$ 与 $x \oplus num$ 可能相等，`dist` 的检查天然去重，不要重复计数。
8. **别把「越界」当「失败」**：越界运算**生效**——它不仅合法，还可能是命中域外 goal 的唯一途径。
