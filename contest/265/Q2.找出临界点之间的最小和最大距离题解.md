# LeetCode 找出临界点之间的最小和最大距离 题解

## 1. 题目概述

- **标题 / 题号**：找出临界点之间的最小和最大距离（#2058，medium）
- **链接**：https://leetcode.cn/problems/find-the-minimum-and-maximum-number-of-nodes-between-critical-points/
- **来源**：LeetCode 第 265 场周赛 Q2
- **难度**：中等
- **标签**：链表、一次遍历、有序序列最值

**题意**：链表中的**临界点**定义为**局部极大值点**或**局部极小值点**：当前节点值**严格大于**前后两个邻居为局部极大，**严格小于**前后两个邻居为局部极小。头节点与尾节点因为缺少一侧邻居，永远不构成临界点。给定链表 `head`，返回 `[minDistance, maxDistance]`，分别为任意两个**不同**临界点之间的最小距离与最大距离；临界点少于两个时返回 `[-1, -1]`。

**约束**：

- 链表节点数 $n \in [2, 10^5]$
- $1 \le$ `Node.val` $\le 10^5$

> 💡 距离即两个临界点**下标之差的绝对值**。临界点在链表中天然按下标升序出现，因此距离就是「后一个下标 − 前一个下标」。

## 2. 示例

**示例 1**

```text
输入：head = [3,1]
输出：[-1,-1]
解释：链表只有 2 个节点，不存在同时拥有前后邻居的中间节点，无临界点。
```

**示例 2**

```text
输入：head = [5,3,1,2,5,1,2]
输出：[1,3]
解释：存在三个临界点：
- 下标 2（值 1）：1 < 3 且 1 < 2，局部极小值点
- 下标 4（值 5）：5 > 2 且 5 > 1，局部极大值点
- 下标 5（值 1）：1 < 5 且 1 < 2，局部极小值点
minDistance = 5 − 4 = 1（相邻的一对），maxDistance = 5 − 2 = 3（首尾一对）。
```

**示例 3**

```text
输入：head = [1,3,2,2,3,2,2,2,7]
输出：[3,3]
解释：存在两个临界点：下标 1（值 3，局部极大）与下标 4（值 3，局部极大）。
两个临界点之间的距离 4 − 1 = 3，既是最小也是最大。
注意：下标 2、3 的值相等（2 与 2），不满足"严格"，均非临界点；
末尾的 7 因为之后没有节点，也不算临界点。
```

**示例 4**

```text
输入：head = [2,3,3,2]
输出：[-1,-1]
解释：两个 3 相等，既不严格大于也不严格小于邻居，链表无临界点。
```

## 3. 解题思路

### 3.1 基线思路：收集全部临界点下标，再统计

比赛中最稳的写法：一趟扫描，用「前驱值 `prev`、当前节点 `curr`、后继值 `curr.next`」三元组逐个判定临界点，把所有临界点的下标存入数组 `idxs`。然后：

- `minDistance` = 相邻下标差的最小值：$\min_i (idxs[i+1] - idxs[i])$
- `maxDistance` = 首尾差：$idxs[k-1] - idxs[0]$

时间 $O(n)$、空间 $O(k)$（$k$ 为临界点个数，最坏 $O(n)$），已经能通过。但仔细观察：`min` 只用到**相邻两个**临界点的差，`max` 只用到**首尾**两个临界点——整个数组从未被整体复用，完全可以边扫边算，把空间压到 $O(1)$。

### 3.2 核心观察：升序位置序列的最值差有结构

![核心观察：min 看相邻对，max 看首尾对](images/critical_points_concept.svg)

设临界点位置按发现顺序为 $p_1 < p_2 < \cdots < p_k$（链表扫描天然升序），则：

- **最大差必在首尾**：对任意 $i < j$，$p_j - p_i \le p_k - p_1$，因为 $p_j \le p_k$ 且 $p_i \ge p_1$。所以只需记 `first`（首个临界点位置）和最后一个临界点位置。
- **最小差必在相邻对**：任意非相邻差可以拆成若干相邻差之和，$p_j - p_i = \sum_{t=i}^{j-1}(p_{t+1} - p_t) \ge p_{i+1} - p_i$，故它不小于其中任何一个相邻差，更不小于最小的相邻差。所以只需在每发现一个新临界点时，用「当前位置 − 上一个临界点位置」更新 `minGap`。

于是整条链表一趟扫描、三个变量即可：`first`（首个临界点位置）、`prevIdx`（上一个临界点位置）、`minGap`（相邻临界点最小间距）。扫描结束时 `prevIdx` 恰为最后一个临界点位置，`maxGap = prevIdx - first`。

> ⚠️ **「严格」二字不可丢**：判定必须用 `>` / `<`。`[2,3,3,2]` 中两个 `3` 相等，既非极大也非极小。误用 `>=` / `<=` 会把相等平台误判为临界点。

### 3.3 算法流程：滑动三元组一趟扫描

![算法流程：滑动三元组与三个变量的更新](images/critical_points_flow.svg)

1. **初始化**：`pos = 1`（从第二个节点开始扫描，头节点无前驱），`prev = head.val`，`curr = head.next`，`first = prevIdx = -1`，`minGap = ∞`。
2. **循环条件**：`curr.next` 存在——保证 `curr` 同时有前驱和后继，才有资格成为临界点。
3. **临界判定**：`curr.val` 严格大于 `prev` 与 `curr.next.val`（极大），或严格小于两者（极小）。
4. **记录**：若 `first == -1`，此为首个临界点，记 `first = pos`；否则用 `pos - prevIdx` 更新 `minGap`。两种情况都滚动 `prevIdx = pos`。
5. **推进**：`prev = curr.val`，`curr = curr.next`，`pos++`，回到第 2 步。
6. **结算**：若 `first == -1`（零个临界点）或 `prevIdx == first`（仅一个临界点），返回 `[-1, -1]`；否则返回 `[minGap, prevIdx - first]`。

### 3.4 示例演算

以 `head = [5,3,1,2,5,1,2]` 为例逐步演算（`pos` 即当前节点下标，从 1 开始）：

![示例演算：[5,3,1,2,5,1,2] 的滑动三元组走查](images/critical_points_walkthrough.svg)

| pos | prev, curr, next | 判定 | first / prevIdx / minGap |
|-----|------------------|------|--------------------------|
| 1 | 5, 3, 1 | 3<5 但 3>1 → 非临界 | −1 / −1 / ∞ |
| 2 | 3, 1, 2 | 1<3 且 1<2 → **极小** ✓ | 2 / 2 / ∞（首个，记 first） |
| 3 | 1, 2, 5 | 2>1 但 2<5 → 非临界 | 2 / 2 / ∞ |
| 4 | 2, 5, 1 | 5>2 且 5>1 → **极大** ✓ | 2 / 4 / min(∞, 4−2) = 2 |
| 5 | 5, 1, 2 | 1<5 且 1<2 → **极小** ✓ | 2 / 5 / min(2, 5−4) = **1** |
| 6 | 1, 2, null | 无后继 → 停 | — |

**结算**：`first = 2`，最后临界点 `prevIdx = 5`，`minGap = 1`，`maxGap = 5 - 2 = 3`，返回 `[1, 3]`，与示例 2 一致。

## 4. 算法细节

1. **滑动三元组只记「值」不记「指针」**：判定 `curr` 是否临界只需要前驱的**值** `prev` 和后继的值 `curr.next.val`，因此每步推进时保存 `prev = curr.val` 一个整数即可，无需持有前驱节点指针，更轻量。
2. **`pos` 的语义**：`curr` 从 `head.next` 出发且 `pos` 从 1 起步，则 `pos` 恰为 `curr` 的 0 起点下标。距离只依赖下标之差，`pos` 全程统一，起点取几都不影响结果。
3. **首个临界点的双重赋值**：发现首个临界点时，`first` 与 `prevIdx` 被同时赋为该位置。此后 `prevIdx` 随每个新临界点滚动，而 `first` 不再变——`prevIdx - first` 在结算时自然就是首尾差。
4. **`minGap` 的更新时机**：只有第二个及以后的临界点才触发 `minGap = min(minGap, pos - prevIdx)`，因为相邻差需要两个端点。首个临界点不更新 `minGap`。
5. **临界点少于两个的统一判定**：`first == -1` 覆盖「零个」；`prevIdx == first` 覆盖「仅一个」（只有一个临界点时两者相等且 `minGap` 从未更新）。一行判断同时处理两种情况，无需额外计数器。
6. **循环条件 `curr && curr->next`**：前者是防御性写法（本题 $n \ge 2$ 时 `head.next` 必非空），后者保证尾节点不被判定——它没有后继，天然无资格成为临界点。

## 5. 正确性证明

**引理 1（判定等价）**：节点 $v$（值 $x$，前驱值 $a$，后继值 $b$）是临界点，当且仅当 $(x > a \wedge x > b) \vee (x < a \wedge x < b)$。

**证明**：即临界点定义的形式化：局部极大值为严格大于两侧，局部极小值为严格小于两侧；相等任一侧均不成立时既非极大也非极小。∎

**引理 2（最大差在首尾）**：设 $p_1 < p_2 < \cdots < p_k$ 为升序整数列，则对任意 $1 \le i < j \le k$，$p_j - p_i \le p_k - p_1$。

**证明**：由升序性 $p_j \le p_k$ 且 $p_i \ge p_1$，两式相减即得 $p_j - p_i \le p_k - p_1$，且 $i=1, j=k$ 时取等。∎

**引理 3（最小差在相邻对）**：对上述升序数列，$\min_{i<j}(p_j - p_i) = \min_{i}(p_{i+1} - p_i)$。

**证明**：对任意 $i < j$，$p_j - p_i = \sum_{t=i}^{j-1}(p_{t+1} - p_t)$，而每项 $p_{t+1} - p_t \ge 0$，故 $p_j - p_i \ge p_{i+1} - p_i \ge \min_t (p_{t+1} - p_t)$。即任何非相邻差都不小于最小相邻差，而相邻差本身也是合法的两两差，故全局最小恰为最小相邻差。∎

**定理**：算法返回 `[minDistance, maxDistance]`；临界点少于两个时返回 `[-1, -1]`。

**证明**：链表从左到右扫描，发现临界点的位置序列严格升序。由引理 1，循环内的判定与临界点定义一致，不漏判不误判；头节点未参与判定（`curr` 从 `head.next` 出发）、尾节点被循环条件排除，符合定义中「必须同时存在前后邻居」。由引理 2，`maxDistance = p_k - p_1`，算法结算时 `prevIdx` 恰为最后临界点位置 $p_k$、`first` 为 $p_1$，故 `prevIdx - first` 正确。由引理 3，`minDistance` 等于最小相邻差，而算法在每发现新临界点时恰好用 `pos - prevIdx` 枚举了全部相邻差并取最小，故 `minGap` 正确。临界点为零个时 `first == -1`；仅一个时 `prevIdx == first` 且引理 2、3 不适用（不存在两个不同临界点）——两种情况均返回 `[-1, -1]`，与题意一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`curr` 从第二个节点单向推进到倒数第二个节点，每个节点只访问一次；临界判定与三个变量的更新均为 $O(1)$。
- **空间复杂度**：$O(1)$。只维护 `first / prevIdx / minGap / pos / prev` 等常数个变量，不存储临界点数组。相比基线做法省掉了 $O(k)$ 的下标数组。

## 7. 参考代码

### C++

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    vector<int> nodesBetweenCriticalPoints(ListNode* head) {
        int first = -1, prevIdx = -1, minGap = INT_MAX;
        int prev = head->val;
        ListNode* curr = head->next;
        int pos = 1;                       // curr 的下标（head 为 0）
        while (curr && curr->next) {
            int cv = curr->val, nv = curr->next->val;
            if ((cv > prev && cv > nv) || (cv < prev && cv < nv)) {
                if (first == -1) first = pos;              // 首个临界点
                else minGap = min(minGap, pos - prevIdx);  // 相邻差取最小
                prevIdx = pos;                             // 滚动上一个临界点
            }
            prev = cv;
            curr = curr->next;
            ++pos;
        }
        if (first == -1 || prevIdx == first) return {-1, -1}; // 临界点 < 2
        return {minGap, prevIdx - first};
    }
};
```

### Python

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next
class Solution:
    def nodesBetweenCriticalPoints(self, head: Optional[ListNode]) -> List[int]:
        first = prev_idx = -1
        min_gap = float('inf')
        prev = head.val
        curr = head.next
        pos = 1                      # curr 的下标（head 为 0）
        while curr and curr.next:
            cv, nv = curr.val, curr.next.val
            if (cv > prev and cv > nv) or (cv < prev and cv < nv):
                if first == -1:
                    first = pos                    # 首个临界点
                else:
                    min_gap = min(min_gap, pos - prev_idx)  # 相邻差取最小
                prev_idx = pos                     # 滚动上一个临界点
            prev = cv
            curr = curr.next
            pos += 1
        if first == -1 or prev_idx == first:
            return [-1, -1]                        # 临界点 < 2
        return [min_gap, prev_idx - first]
```

## 8. 边界情况与易错点

1. **节点数恰为 2**：`head.next.next` 为空，循环体一次都不执行，`first == -1`，返回 `[-1, -1]`。这是最小规模输入，无需特判。
2. **相等平台**：`[2,3,3,2]` 中相邻相等值既非极大也非极小。判定必须用**严格**比较 `>` / `<`，用 `>=` / `<=` 会得到错误答案。
3. **头尾节点不可判临界**：头节点无前驱（`curr` 从 `head.next` 出发天然跳过）、尾节点无后继（循环条件 `curr.next` 排除）。示例 3 末尾的 `7` 就是靠这一点被排除的。
4. **仅一个临界点**：`first` 与 `prevIdx` 相等且 `minGap` 保持 $\infty$，必须走 `[-1, -1]` 分支；若忘记判断就返回，会把 $\infty$ 当作 `minDistance` 输出（C++ 中是 `INT_MAX` 溢出风险前的错误值）。
5. **`minGap` 的初始化**：C++ 用 `INT_MAX`、Python 用 `float('inf')`。由于结算前必先确认临界点 $\ge 2$，`minGap` 此时必已被至少更新过一次，不会把哨兵值带进答案。
6. **`pos` 起点不影响正确性**：距离是下标之差，`pos` 从 0 或 1 起都行，只要全程一致。本文实现中 `pos` 恰等于 `curr` 的 0 起点下标，演算表与题面示例可直接对照。
7. **链表只能单向走**：不要试图"回头"取前驱指针——保存前驱的**值** `prev` 即可，这正是一趟扫描的关键。

**延伸思考**：

- 若把"严格"改成"非严格"（$\ge$ / $\le$），相等平台如何处理？——连续相等段内部节点全部同时非严格大于且非严格小于两侧，需要先去重或按平台端点判定，题目会变成另一道题。
- 若要求任意两临界点距离的**第 $k$ 小**？——相邻差结构不够用，需收集全部下标（或分治统计），退回 $O(n)$ 空间。
- 「最小差看相邻、最大差看首尾」是对任意**升序序列**都成立的性质；序列无序时需先排序再套用，如"数组中距离最近的一对数"。
