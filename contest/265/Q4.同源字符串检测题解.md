# LeetCode 同源字符串检测 题解

## 1. 题目概述

- **标题 / 题号**：同源字符串检测（#2060，hard）
- **链接**：https://leetcode.cn/problems/check-if-an-original-string-exists-given-two-encoded-strings/
- **来源**：LeetCode 第 265 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、记忆化搜索、双指针、字符串

**题意**：一个由小写字母组成的**原字符串**按三步编码：① 任意分割为若干非空子字符串的序列；② 任意选择其中一些元素，替换为其各自**长度**（数字型字符串）；③ 重新顺次连接。例如 `"abcdefghijklmnop"` 分割为 `["ab","cdefghijklmn","o","p"]`，把第 2、3 段替换为长度 `"12"`、`"1"`，连接得 `"ab121p"`。给定两个编码后的字符串 `s1`、`s2`（由小写字母和数字 `1-9` 组成），判断是否存在**同一个**原字符串能同时编码成 `s1` 和 `s2`。

**约束**：

- `1 <= s1.length, s2.length <= 40`
- `s1`、`s2` 仅由数字 `1-9` 和小写字母组成
- `s1`、`s2` 中连续数字不超过 3 位（单段数值 $\le 999$，是本题复杂度的关键保证）

> 💡 本题两个题眼：① **数字切分有歧义**——`"12"` 既可解析为一个长度 12 的段，也可拆成 `"1"` 和 `"2"` 两个段，`"112"` 更有 `[112]`、`[1,12]`、`[11,2]`、`[1,1,2]` 等拆法，任何贪心对齐都会被歧义击穿；② 原字符串**不需要还原**，需要发现的只是一个「只看长度、几乎不看内容」的对账模型。

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是枚举原字符串本身：`s1` 的每个数字段都有多种切分（连续 3 位数字有 `[3]`、`[1,2]`、`[2,1]`、`[1,1,1]` 四种 token 化），两边各自的所有切分组合是**指数级**；即使只看长度，原串长度也可达约 $13 \times 999 + 40 \approx 1.3 \times 10^4$，再叠加每个位置 26 种字母取值，彻底不可行。

另一种直觉是「贪心对齐」——两边指针同时前进，遇到数字就比大小补差。但数字拆分的歧义（示例 4 中 `"112"` 要拆成 `[1][12]` 才能与 `"841"` 对齐）使任何局部决策都可能失败。**必须把「解析方式」纳入搜索状态，同时避免真的构造原串。**

### 3.2 核心观察：双指针 + 差值 $k$ 的同步消费模型

![双指针与差值 k 模型](images/wc265_coe_diff_model.svg)

把两边的编码串看作对**同一条原串**的两种「消费方式」：

- **字母 token**：恰消费原串的 **1 个**字符，并**声明**该字符的内容；
- **数字 token**（值为 $v$）：一次性消费原串的 **$v$ 个**字符，**内容完全未知**。

于是验证「同源」等价于：让 $s_1$、$s_2$ 的 token 序列**按原串位置对齐地交错消费**，全程不产生矛盾。用双指针 $i$（$s_1$）、$j$（$s_2$）加一个**差值**维护进度：

$$k = (\text{s}_1\text{ 已消费的原串字符数}) - (\text{s}_2\text{ 已消费的原串字符数})$$

- $k = 0$：双方指向原串同一位置。**两个字母声明同一位置时必须相等**（当场比较一次）；涉及数字时产生新的差值。
- $k > 0$：$s_1$ 领先 $k$ 个字符。**$s_1$ 冻结**，只有 $s_2$ 能追赶：消费字母 $k \to k-1$，消费数字（值 $v$）$k \to k - v$。
- $k < 0$：完全对称，$s_2$ 冻结，$s_1$ 追赶。

> 💡 **为什么状态里一个字符都不用记？** 关键不变式：**领先只能由数字造成**——$k=0$ 时字母必须成对消费（$k$ 不变），只有数字才会把 $k$ 推离 0。因此领先的 $|k|$ 个原字符全部被数字 token 覆盖（内容未知），追赶方接下来用**任何字母**去声明这些位置都不矛盾；而「两个字母声明同一位置」只会发生在 $k=0$ 的双字母转移里，当场比较即可。这就是 $(i, j, k)$ 三元组成为**充分状态**的根因。

### 3.3 算法流程：记忆化搜索

![记忆化搜索决策流程](images/wc265_coe_flow.svg)

记 `dfs(i, j, k)` 为「$s_1$ 从 $i$、$s_2$ 从 $j$ 开始、当前差值为 $k$ 时，能否完成对齐」。**数字解析**：从当前位置起取连续数字的 $1/2/3$ 位前缀，得到 $(l, v)$，如 `"12"` → $(1,1)$、$(2,12)$，覆盖该数字段的一切 token 化方式（后续拆分交给递归继续）。

| 条件 | `s1[i]` | `s2[j]` | 操作 | 新状态 |
|------|---------|---------|------|--------|
| $k=0$ | 字母 | 字母 | 相等才各前进 1，不等为死路 | $(i{+}1,\,j{+}1,\,0)$ |
| $k=0$ | 字母 | 数字 | 字母匹配数字消费的首字符，枚举解析 $v$ | $(i{+}1,\,j{+}l,\,1{-}v)$ |
| $k=0$ | 数字 | 字母 | 对称 | $(i{+}l,\,j{+}1,\,v{-}1)$ |
| $k=0$ | 数字 | 数字 | 枚举 $v_1$、$v_2$ 的全部组合（至多 $3\times3$） | $(i{+}l_1,\,j{+}l_2,\,v_1{-}v_2)$ |
| $k>0$ | — | 字母 | $s_2$ 追赶 1 个字符（无约束） | $(i,\,j{+}1,\,k{-}1)$ |
| $k>0$ | — | 数字 | 枚举解析 $v$ | $(i,\,j{+}l,\,k{-}v)$ |
| $k<0$ | 字母 | — | $s_1$ 追赶 1 个字符（无约束） | $(i{+}1,\,j,\,k{+}1)$ |
| $k<0$ | 数字 | — | 枚举解析 $v$ | $(i{+}l,\,j,\,k{+}v)$ |

**边界与终止**：

- $i = n_1$ 且 $j = n_2$：返回 $k = 0$（两边 token 耗尽且消费总数相等，才可能是同一条原串）；
- $k = 0$ 但恰有一侧耗尽：返回 `false`（另一侧剩余 token 至少还要消费 1 个字符，$k$ 永远回不到 0）；
- $k \ne 0$ 且落后侧已耗尽：返回 `false`（无法追赶）。

所有状态记忆化到 `memo[i][j][k+1000]`。

### 3.4 示例演算

![示例 4 演算](images/wc265_coe_walkthrough.svg)

以示例 4 `s1 = "112s"`、`s2 = "g841"`（原串 `"g" + 12 个 a + "s"`）为例，沿一条可行路径走查：

| 步 | 状态 $(i,j,k)$ | 所用规则 | 结果 |
|----|---------------|---------|------|
| 1 | $(0,0,0)$ | $k{=}0$：$s_1$ 数字 `"1"`($v{=}1$) 配 $s_2$ 字母 `g` | $(1,1,0)$ |
| 2 | $(1,1,0)$ | $k{=}0$：双数字，$s_1$ 取 `"12"`($v_1{=}12$)、$s_2$ 取 `"8"`($v_2{=}8$) | $(3,2,4)$ |
| 3 | $(3,2,4)$ | $k{=}4{>}0$：$s_1$ 冻结，$s_2$ 独自追赶，取数字 `"4"`($v{=}4$) | $(3,3,0)$ |
| 4 | $(3,3,0)$ | $k{=}0$：$s_1$ 字母 `s` 配 $s_2$ 数字 `"1"`($v{=}1$) | $(4,4,0)$ |
| 5 | $(4,4,0)$ | $i{=}n_1$、$j{=}n_2$、$k{=}0$ | **true** ⭐ |

第 2 步是本题精髓：`"112"` 必须拆成 $[1][12]$（而非 $[12]$ 或 $[112]$），与 `"841"` 的 $[8]$ 产生差值 $12-8=4$，再由 `"4"` 追平——枚举数字前缀解析的记忆化搜索天然覆盖了所有拆法。

## 4. 算法细节

1. **数字解析只枚举 1~3 位前缀**：一个数字 token 是连续数字的某个前缀（$1 \le l \le 3$），更长拆分由后续递归完成。题目保证「连续数字不超过 3 位」⇒ 每次分支至多 3、数值 $v \le 999$。
2. **$k=0$ 时字母不单独前进**：若允许领先方用字母「先走一步」，领先段就含已知字符，追赶方无法验证，破坏 3.2 的不变式。实现上把「字母 + 数字」合并为一步转移 $(i{+}1, j{+}l, 1{-}v)$——它与「数字先走、字母随后追上」的两步路径到达完全相同的状态，但少一层展开。
3. **$k$ 的取值范围 $|k| \le 998$**：$k=0$ 时双数字一步最大 $999 - 1 = 998$；追赶中数字「超射」产生的 $|k'| = v - |k| \le 999 - 1 = 998$；字母追赶只会把 $|k|$ 减 1。故 `memo` 第三维开 2001、偏移 1000 绰绰有余（可达状态下标落在 $[2, 1998]$）。
4. **记忆化容器**：C++ 用三维 `char` 数组（0=未算 / 1=false / 2=true），约 $41 \times 41 \times 2001 \approx 3.4$ MB；Python 用 `@cache`，只存实际可达状态（远小于上界，因为固定 $(i,j)$ 的可达 $k$ 由前缀消费方式决定，通常很少）。
5. **耗尽侧的三个死路判定**要显式写出（见 3.3 边界），否则要么数组越界、要么无限递归。
6. **双数字的 9 种组合都要试**：$3 \times 3$ 种 $(l_1, v_1) \times (l_2, v_2)$ 解析不能只挑「位数相同」的——第 3.4 节第 2 步正是 2 位配 1 位。

## 5. 正确性证明

**引理 1（领先段未知不变式）**：对搜索树中每个可达状态 $(i,j,k)$：若 $k > 0$，则 $s_1$ 比 $s_2$ 多消费的 $k$ 个原字符全部落在 $s_1$ 的某个数字 token 的覆盖区间内（未被任何字母声明）；$k < 0$ 时对称。

**证明**：对转移步数归纳。初始 $(0,0,0)$ 平凡。设当前状态满足不变式，逐一检验：

- $k{=}0$ 双字母相等：双方声明同一位置且字符相同，$k$ 不变；
- $k{=}0$ 字母 + 数字：$k' = 1 - v \le 0$。若 $k' < 0$，$s_2$ 领先 $v-1$ 个位置，全在其数字覆盖内；若 $v = 1$ 则 $k' = 0$；
- $k{=}0$ 双数字：$k' = v_1 - v_2$。若 $k' > 0$，由 $v_2 \ge 1$ 知领先的 $v_1 - v_2 \le v_1 - 1$ 个位置落在 $s_1$ 的数字覆盖内；$k' < 0$ 对称；
- $k > 0$ 追赶：字母使 $k' = k - 1 \ge 0$，领先段是原数字覆盖的后缀；数字使 $k' = k - v$，若 $k' > 0$ 同前，若 $k' < 0$ 则 $s_2$ 领先 $v - k$ 个位置，恰为其数字覆盖超出 $s_1$ 领先段的部分（数字不声明内容）；
- $k < 0$ 对称。∎

**引理 2（充分性）**：若 `dfs(0,0,0)` 返回 `true`，则存在共同原串。

**证明**：沿接受路径把每步还原为双方 token 的消费。对任一原串位置 $p$：若 $p$ 被 $s_1$ 侧字母声明，则由引理 1，$s_2$ 对 $p$ 要么用数字覆盖（不声明），要么恰在 $k=0$ 双字母转移中声明同一字符；故**所有声明两两相容**。构造 $T$：每个位置取任一侧对它的字母声明，无声明则任取（如 `a`）。路径终态为 $i=n_1, j=n_2, k=0$，即双方各消费恰好 $L$ 个字符；沿路径回放，$s_1$ 的 token 序列（数字替换段的长度 = 其数值）恰好给出 $T \to s_1$ 的编码方案，$s_2$ 同理。故 $T$ 是共同原串。∎

**引理 3（必要性）**：若存在长度为 $L$ 的原串 $T$ 及两组编码方案，则 `dfs(0,0,0)` 返回 `true`。

**证明**：把两组方案展开为 token 序列 $A$（对应 $s_1$）、$B$（对应 $s_2$），各自把 $[0, L)$ 划分为若干区间（数字 token 覆盖 $v$ 个连续位置，字母 token 覆盖 1 个并声明字符）。构造路径使每步恰消费**落后方**（$k=0$ 时为双方）的下一个 token：

- $k = 0$：双方 frontier 相同。若 $A$、$B$ 的下一 token 都是字母，它们声明 $T$ 的同一位置，字符必相等（否则两组编码矛盾）→ 双字母转移；若一侧字母一侧数字，取该数字 token 的实际解析 $(l, v)$ → 字母+数字转移（实际解析是 $1 \sim 3$ 位前缀之一，被枚举覆盖）；若都是数字 → 双数字转移，$k' = v_1 - v_2$；
- $k > 0$：$s_2$ 的 frontier 严格靠后，故 $B$ 有剩余 token：字母 → 字母追赶，数字（取实际解析）→ 数字追赶。$k < 0$ 对称；
- $A$、$B$ 同时耗尽时 $i = n_1$、$j = n_2$ 且双方消费数都为 $L$，即 $k = 0$，返回 `true`。

归纳可知每个构造出的中间状态都合法（不触发任何 `false` 死路分支：落后方未耗尽、$k=0$ 时双方均有 token），且路径长度有限。∎

**定理**：`dfs(0,0,0)` 为 `true` 当且仅当存在能同时编码为 $s_1$ 与 $s_2$ 的原字符串。

**证明**：由引理 2、3 立得。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n_1 \cdot n_2 \cdot K)$，其中 $K \le 2001$（$|k| \le 998$）。状态总数上界 $41 \times 41 \times 2001 \approx 3.4 \times 10^6$；每个 $k \ne 0$ 状态至多 3 个数字解析分支，每个 $k = 0$ 状态至多 $3 \times 3 = 9$ 个组合。实际可达状态远小于上界（固定 $(i,j)$ 的可达 $k$ 受前缀消费方式约束），$n_1 = n_2 = 40$ 满规模实测毫秒级。
- **空间复杂度**：$O(n_1 \cdot n_2 \cdot K)$。C++ 三维 `char` 数组约 3.4 MB；Python `@cache` 只存可达状态。

> 💡 复杂度成立的两个前提都来自题目约束：**连续数字不超过 3 位**封顶了单步跳变（$v \le 999$，从而 $|k| \le 998$）与解析分支（$\le 3$）；串长 $\le 40$ 封顶了 $n_1 n_2$。

## 7. 参考代码

### C++

```cpp
class Solution {
    static constexpr int SZ = 2001, OFF = 1000;   // k ∈ [-998, 998]
    int n1, n2;
    string s1, s2;
    vector<vector<vector<char>>> memo;            // 0=未算，1=false，2=true

    static bool isDigit(char c) { return '1' <= c && c <= '9'; }

    // 枚举 s[pos..] 连续数字的 1~3 位前缀解析 (l, v)，逐个调用 chk，命中即短路
    template <class F>
    bool enumNumbers(const string& s, int pos, int n, F chk) {
        int v = 0;
        for (int l = 1; l <= 3 && pos + l - 1 < n && isDigit(s[pos + l - 1]); ++l) {
            v = v * 10 + (s[pos + l - 1] - '0');
            if (chk(l, v)) return true;
        }
        return false;
    }

    bool dfs(int i, int j, int k) {
        if (i == n1 && j == n2) return k == 0;

        char& c = memo[i][j][k + OFF];
        if (c) return c == 2;

        bool res = false;
        if (k == 0) {
            if (i < n1 && j < n2) {
                bool d1 = isDigit(s1[i]), d2 = isDigit(s2[j]);
                if (!d1 && !d2) {                          // 双字母：必须相等
                    res = s1[i] == s2[j] && dfs(i + 1, j + 1, 0);
                } else if (!d1) {                          // s1 字母 + s2 数字
                    res = enumNumbers(s2, j, n2, [&](int l, int v) {
                        return dfs(i + 1, j + l, 1 - v);
                    });
                } else if (!d2) {                          // s1 数字 + s2 字母
                    res = enumNumbers(s1, i, n1, [&](int l, int v) {
                        return dfs(i + l, j + 1, v - 1);
                    });
                } else {                                   // 双数字：9 种解析组合
                    res = enumNumbers(s1, i, n1, [&](int l1, int v1) {
                        return enumNumbers(s2, j, n2, [&](int l2, int v2) {
                            return dfs(i + l1, j + l2, v1 - v2);
                        });
                    });
                }
            }
        } else if (k > 0) {                                // s1 领先：s2 独自追赶
            if (j < n2) {
                if (isDigit(s2[j]))
                    res = enumNumbers(s2, j, n2, [&](int l, int v) {
                        return dfs(i, j + l, k - v);
                    });
                else
                    res = dfs(i, j + 1, k - 1);
            }
        } else {                                           // s2 领先：s1 独自追赶
            if (i < n1) {
                if (isDigit(s1[i]))
                    res = enumNumbers(s1, i, n1, [&](int l, int v) {
                        return dfs(i + l, j, k + v);
                    });
                else
                    res = dfs(i + 1, j, k + 1);
            }
        }

        c = res ? 2 : 1;
        return res;
    }

public:
    bool possiblyEquals(string s1, string s2) {
        this->s1 = move(s1);
        this->s2 = move(s2);
        n1 = this->s1.size();
        n2 = this->s2.size();
        memo.assign(n1 + 1, vector<vector<char>>(n2 + 1, vector<char>(SZ, 0)));
        return dfs(0, 0, 0);
    }
};
```

### Python

```python
from functools import cache


class Solution:
    def possiblyEquals(self, s1: str, s2: str) -> bool:
        n1, n2 = len(s1), len(s2)

        def nums(s, pos, n):                # 枚举连续数字的 1~3 位前缀解析 (l, v)
            v = 0
            for l in range(1, 4):
                if pos + l - 1 < n and '1' <= s[pos + l - 1] <= '9':
                    v = v * 10 + int(s[pos + l - 1])
                    yield l, v
                else:
                    return

        @cache
        def dfs(i: int, j: int, k: int) -> bool:
            if i == n1 and j == n2:
                return k == 0
            if k == 0:
                if i == n1 or j == n2:      # 一侧耗尽：剩余 token 至少再消费 1 字符
                    return False
                c1, c2 = s1[i], s2[j]
                if not ('1' <= c1 <= '9') and not ('1' <= c2 <= '9'):   # 双字母
                    return c1 == c2 and dfs(i + 1, j + 1, 0)
                if not ('1' <= c1 <= '9'):                               # s1 字母 + s2 数字
                    return any(dfs(i + 1, j + l, 1 - v) for l, v in nums(s2, j, n2))
                if not ('1' <= c2 <= '9'):                               # s1 数字 + s2 字母
                    return any(dfs(i + l, j + 1, v - 1) for l, v in nums(s1, i, n1))
                return any(dfs(i + l1, j + l2, v1 - v2)                   # 双数字
                           for l1, v1 in nums(s1, i, n1)
                           for l2, v2 in nums(s2, j, n2))
            if k > 0:                       # s1 领先：s2 独自追赶
                if j == n2:
                    return False
                if '1' <= s2[j] <= '9':
                    return any(dfs(i, j + l, k - v) for l, v in nums(s2, j, n2))
                return dfs(i, j + 1, k - 1)
            if i == n1:                     # s2 领先：s1 独自追赶
                return False
            if '1' <= s1[i] <= '9':
                return any(dfs(i + l, j, k + v) for l, v in nums(s1, i, n1))
            return dfs(i + 1, j, k + 1)

        return dfs(0, 0, 0)
```

## 8. 边界情况与易错点

1. **数字解析歧义（最高频 WA）**：只枚举「1~3 位前缀」作为**下一个** token，更长拆分交给递归。既不能只按整段数值解析（漏掉 `"112" → [1][12]`），也不能只按单 digit 解析（漏掉 `"12"` 整体为 12）。
2. **领先方必须冻结**：$k \ne 0$ 时若让领先方继续消费字母，领先段将含「已知字符」，追赶方无法验证——不变式被破坏，会出假阳性。同理 $k=0$ 时字母不能单独前进。
3. **$|k| \le 998$ 的数组边界**：`memo` 第三维按偏移 1000、大小 2001 开；开小直接越界。推导见第 4 节第 3 点。
4. **一侧耗尽的三种死路**：$k=0$ 恰一侧耗尽、$k>0$ 且 $j=n_2$、$k<0$ 且 $i=n_1$，都必须显式返回 `false`，否则越界或死递归。
5. **终态必须判 $k=0$**：两边指针同时到头但 $k \ne 0$，说明两边消费的原串长度不同，不可能同源（示例 5：`"ab"` 与 `"a2"` 各消费 2 与 3）。
6. **双数字 9 种组合都要试**：位长不同的解析也能配对（示例 4 中 2 位的 `12` 配 1 位的 `8`），只试同位长会漏解。
7. **全字母串的隐含强约束**：一边全字母意味着原串内容被完全声明（长度 = 字母数），另一边的任何数字消费都要与这些声明共存——算法自动处理，但手推时容易忽略（如 `"ab"` vs `"ba"` 在 $k=0$ 双字母处直接死路）。
8. **C++ 判数字**：题面字符集只有 `1-9` 与小写字母，直接 `'1' <= c && c <= '9'` 即可，绕开 `isdigit` 需要 `unsigned char` 参数的坑。
