# LeetCode 缺失的最小倍数 题解

## 1. 题目概述

- **标题 / 题号**：缺失的最小倍数（#3718，easy）
- **链接**：https://leetcode.cn/problems/smallest-missing-multiple-of-k/
- **来源**：LeetCode 第 472 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、数学

**题意**：给定整数数组 `nums` 和整数 `k`，返回**没有在 `nums` 中出现的、最小的 `k` 的正倍数**。倍数指能被 $k$ 整除的任意正整数，即候选答案只能取 $k, 2k, 3k, \dots$。

**约束**：

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`
- `1 <= k <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [8,2,3,4,6], k = 2
输出：10
解释：k = 2 的倍数为 2、4、6、8、10、12……其中 2、4、6、8 都在 nums 中，最小的缺失倍数是 10。
```

**示例 2**

```text
输入：nums = [1,4,7,10,15], k = 5
输出：5
解释：k = 5 的倍数为 5、10、15、20……第一个倍数 5 就不在 nums 中，答案即 5。
```

**示例 3（极端上界）**

```text
输入：nums = [1,2,3,…,100], k = 1
输出：101
解释：1~100 全部存在，答案超出值域 100，但必不超过 200。
```

## 3. 解题思路

### 3.1 暴力思路

对候选倍数 $m = k, 2k, 3k, \dots$ 逐个**线性扫描** `nums` 判断是否存在，返回第一个不存在的，单次判断 $O(n)$。本题 $n \le 100$、值域 $\le 100$，怎么写都能过。真正要回答的问题是：**倍数序列无穷长，枚举到哪里停？**（见 3.2 的观察 3。）此外把存在性判断做成 $O(1)$ 即为最优做法。

### 3.2 核心观察：升序枚举倍数 + 哈希集合判存在 + 值域保证终止

![核心观察：升序枚举倍数序列 + 集合判存在](images/smallest_missing_multiple_concept.svg)

三个关键观察：

1. **候选序列天然升序**：$k$ 的正倍数 $k, 2k, 3k, \dots$ 本身就是严格递增序列，**按顺序枚举，第一个不在 `nums` 里的就是答案**——无需排序，无需维护"当前最小"。
2. **无关元素无需过滤**：`nums` 中不是 $k$ 倍数的元素与答案无关，不必预先筛掉；把 `nums` 整体倒入哈希集合 $S$，每个候选的判断就是一次 $O(1)$ 查询。
3. **终止性有保证**：约束 $nums[i] \le 100$，所以**任何大于 100 的倍数必然缺失**。最小的超过 100 的倍数为 $(\lfloor 100/k \rfloor + 1) \cdot k \le 100 + k \le 200$，枚举至多 $\lfloor 100/k \rfloor + 1 \le 101$ 步必命中答案。

> 💡 一句话：**沿倍数阶梯往上爬，遇到第一个"不在集合里"的台阶就停下**。

### 3.3 算法流程

![算法流程图：建集合后沿倍数序列爬升](images/smallest_missing_multiple_flow.svg)

流程总结：建集合 $S = \mathrm{set}(nums)$ → $m = k$ → 若 $m \in S$ 则 $m \mathrel{+}= k$ 继续爬 → 否则返回 $m$。

### 3.4 示例演算

![示例演算：nums=[8,2,3,4,6], k=2 的逐步走查](images/smallest_missing_multiple_walkthrough.svg)

以 `nums = [8,2,3,4,6]`、`k = 2` 为例：$S = \{2,3,4,6,8\}$，依次检查 $2✓\ 4✓\ 6✓\ 8✓\ 10✗$，返回 **10**。

## 4. 算法细节

1. **建集合**：C++ 用 `unordered_set<int>`（平均 $O(1)$ 查询），Python 直接 `set(nums)`。值域仅 `1..100`，也可用 `bool exist[101]` 数组代替；但注意**答案可能大于 100**，查询前须先短路判断 `m > 100`（或把数组开到 201），否则越界。
2. **枚举写法**：`m` 从 `k` 出发、步长 `k`，`while (m ∈ S) m += k;`，循环自然结束处即答案，**无需显式上界**。
3. **上界推导**：设 $q = \lfloor 100/k \rfloor$，则 $qk \le 100 < (q+1)k$，即 $m = (q+1)k$ 是第一个必然缺失的候选，枚举步数至多 $q + 1 \le 101$。
4. **更强的界（与值域无关）**：`nums` 只有 $n$ 个元素，至多"挡住" $n$ 个倍数，故候选 $k, 2k, \dots, (n+1)k$ 中必有缺失，答案 $\le (n+1)k$。即使值域无界，本算法也只需 $O(n)$ 次爬升。

## 5. 正确性证明

**引理 1（答案存在且有上界）**：存在缺失的正倍数，且答案 $m^* \le (\lfloor 100/k \rfloor + 1) \cdot k \le 200$。

**证明**：记 $q = \lfloor 100/k \rfloor$，$M = (q+1)k$。由带余除法，$qk \le 100 < (q+1)k = M$，即 $M > 100$。而所有 $nums[i] \le 100$，故 $M \notin nums$，即 $M$ 是一个缺失的正倍数。答案取最小，故 $m^* \le M$；又 $M = qk + k \le 100 + k \le 200$。∎

**定理**：算法返回最小的缺失正倍数。

**证明**：$k$ 的正倍数全体按升序恰为 $k, 2k, 3k, \dots$。算法按此顺序逐一检验 $m \in S$，其中 $S$ 为 `nums` 的元素集合，故 $m \in S \iff m$ 出现在 `nums` 中。设 $m^*$ 为最小缺失倍数。对每个小于 $m^*$ 的倍数 $jk$（$jk < m^*$），由 $m^*$ 的最小性可知 $jk$ 均在 `nums` 中，算法对这些候选均执行 `m += k` 继续爬升；枚举到 $m^*$ 时首次不满足 $m \in S$，循环结束并返回 $m^*$。又由引理 1，$m^*$ 存在，故循环必在至多 $\lfloor 100/k \rfloor + 1$ 步内终止。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + \lfloor V/k \rfloor)$，其中 $V = 100$ 为值域上界。建集合 $O(n)$；倍数爬升至多 $\lfloor 100/k \rfloor + 1 \le 101$ 步，每步一次 $O(1)$ 集合查询。整体即 $O(n)$。
- **空间复杂度**：$O(n)$，哈希集合存储全部元素；若改用 `bool exist[101]` 则为 $O(V)$，仍是常数级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int missingMultiple(vector<int>& nums, int k) {
        unordered_set<int> s(nums.begin(), nums.end());
        int m = k;
        while (s.count(m)) {
            m += k;
        }
        return m;
    }
};
```

### Python

```python
class Solution:
    def missingMultiple(self, nums: List[int], k: int) -> int:
        s = set(nums)
        m = k
        while m in s:
            m += k
        return m
```

## 8. 边界情况与易错点

1. **答案可能超过 100**：`k = 1` 且 `nums` 恰为 `1..100` 时答案为 101（必不超过 200）。若用 `exist[101]` 布尔数组实现，查询前必须先判断 `m > 100` 直接视为不存在，否则数组越界。
2. **k 本身缺失**：如示例 2，一次循环都不进，直接返回 `k`，`while` 写法天然覆盖，无需特判。
3. **重复元素**：题面未保证 `nums` 互不相同，集合自动去重，无影响；若手写计数逻辑别把重复元素当多次阻挡。
4. **不要反向枚举**：先在 `[1,100]` 里找所有缺失数、再挑出 $k$ 的倍数取最小是绕路；正着沿 $k, 2k, 3k$ 爬升一步到位。
5. **溢出**：答案 $\le 200$，`m += k` 至多执行 101 次，`int` 绰绰有余。
6. **终止性来源**：循环能停全靠值域有界（或更强的 $(n+1)k$ 界）；若枚举的是 `nums` 里的值而不是倍数序列，既容易漏解也写不出干净的终止条件。
