# LeetCode 替换字符串中的括号内容 题解

## 1. 题目概述

- **标题 / 题号**：替换字符串中的括号内容（#1807，medium）
- **链接**：https://leetcode.cn/problems/evaluate-the-bracket-pairs-of-a-string/
- **来源**：LeetCode 第 234 场周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、模拟

**题意**：给定字符串 `s`，其中包含若干**不嵌套**的括号对，每个括号内是一个**非空**的键。另给二维数组 `knowledge`，`knowledge[i] = [key_i, value_i]` 表示键 `key_i` 对应值 `value_i`（键互不重复）。要求把 `s` 中**所有**括号对替换掉：键在表中则整段 `(key)` 换成 `value_i`，不在表中则换成 `"?"`。返回替换后的完整字符串。

**约束**：

- $1 \le s.length \le 10^5$
- $0 \le knowledge.length \le 10^5$
- $1 \le key_i.length, value_i.length \le 10$，均只含小写字母，键不重复
- `s` 只含小写字母与 `'('` `')'`，每个 `'('` 都有配对的 `')'`，括号内键非空、无嵌套

> 💡 **本题的真实考点**：算法上只是「查表 + 扫描」，但 $n, k \le 10^5$ 的规模专治两类写法：① 对每个键线性扫描 `knowledge` 的 $O(nk)$ 查找；② 逐字符拼接字符串在某些语言里退化为 $O(n^2)$。把这两个坑绕开，就是一次干净的线性扫描。

## 2. 示例

**示例 1**

```text
输入：s = "(name)is(age)yearsold", knowledge = [["name","bob"],["age","two"]]
输出："bobistwoyearsold"
解释："(name)" → "bob"，"(age)" → "two"，括号外的字符原样保留。
```

**示例 2**

```text
输入：s = "hi(name)", knowledge = [["a","b"]]
输出："hi?"
解释：键 "name" 不在 knowledge 中，"(name)" 整段替换为 "?"。
```

**示例 3**

```text
输入：s = "(a)(a)(a)aaa", knowledge = [["a","yes"]]
输出："yesyesyesaaa"
解释：同一个键可出现多次，每次都查表替换；
括号外的 'a' 是普通字符，不查表、不替换。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法有两类，各有致命伤：

1. **对每个括号段线性查 `knowledge`**：扫到 `(key)` 时遍历整个 `knowledge` 找键。单次查找 $O(k)$，括号段最多 $n/2$ 个（键长 $\ge 1$），最坏约 $\frac{n}{2} \times k = 5 \times 10^9$ 次比较，**超时**。
2. **对 `knowledge` 逐条做全局 `replace`**：把每个 `"(key)"` 替换成 `value`。问题更多：`s` 中出现但 `knowledge` 中没有的键无法替换成 `"?"`（`replace` 根本找不到目标）；更隐蔽的是，若某个 `value` 本身含括号（如 `"x(y)"`），后续轮次的 `replace` 会把**替换结果**再次展开——**正确性都不保**。

> ⚠️ **症结**：① 查找无索引；② 用「反复改写原串」的方式做替换，既引入二次展开的正确性风险，又带来反复搬移字符的开销。正确姿势是**只读原串、只写一次结果**。

### 3.2 核心观察：哈希表建索引 + 单趟扫描 + 只追加的缓冲区

![核心观察：括号段送入哈希表查出 value 或问号，普通字符直通](images/1807_hash_lookup_concept.svg)

三个要点把暴力优化到线性：

**① 哈希表建索引**：先把 `knowledge` 整理成哈希表 $map$，建表 $O(k)$，此后每次查键 $O(1)$，彻底消除逐条线性查找。

**② 单趟扫描 + 游标跳跃**：括号不嵌套，所以从 `'('` 出发向后遇到的**第一个** `')'` 必然就是它的配对（证明见 §5 引理 1），无需栈。扫描时只需区分两种情况：

- 遇 `'('`：切出键，查表，把 `value` 或 `"?"` 追加进结果，游标直接跳过整段括号；
- 遇普通字符：直接追加，游标前进一步。

**③ 结果只写不改**：结果放进可增长的缓冲区（C++ 的 `std::string`、Python 的 `list`），只做**追加**，最后一次性输出。已写入的部分永不回头修改，避免「反复改写原串」的二次展开风险与搬移开销。

> 💡 **直觉理解**：把 `s` 看成一条流水线，括号段是「需查表加工」的工位，普通字符走直通道。哈希表是工位旁的速查手册，一次翻到、即时出料；游标只在括号工位停留，普通字符一掠而过。

### 3.3 算法流程

![算法流程：建表后单趟扫描，遇左括号切键查表，否则追加普通字符](images/1807_scan_flow.svg)

```text
1. 建表：map = { key_i → value_i }，O(k)
2. res ← 空缓冲区，i ← 0
3. 循环（i < n）：
   a. 若 s[i] == '('：
      - j ← 从 i+1 起第一个 ')' 的位置
      - key ← s[i+1 .. j-1]        # 不含两端括号
      - res += (key ∈ map ? map[key] : "?")
      - i ← j + 1                  # 跳过整段
   b. 否则：res += s[i]，i += 1
4. 返回 res
```

> ⚠️ **细节**：键切片是 $s[i+1..j-1]$，**不含**括号本身；游标必须跳到 $j+1$ 而非 $j$，否则 `')'` 会被当作普通字符追加进结果。

### 3.4 示例演算

以示例 1 `s = "(name)is(age)yearsold"`，`knowledge = [["name","bob"],["age","two"]]` 走查：

![示例演算：四个阶段逐步累积 res，游标在括号段整体跳跃](images/1807_walkthrough.svg)

| 阶段 | 扫描片段 | 动作 | res 累积 | i 跳到 |
|------|----------|------|----------|--------|
| ① | `(name)` | 切键 `"name"`，查表命中 `"bob"` | `bob` | 6 |
| ② | `is` | 普通字符逐个直通 | `bobis` | 8 |
| ③ | `(age)` | 切键 `"age"`，查表命中 `"two"` | `bobistwo` | 13 |
| ④ | `yearsold` | 普通字符逐个直通 | `bobistwoyearsold` | 21 = n，结束 |

> 💡 **对照**：若 `knowledge` 里没有 `"age"`，阶段 ③ 追加的就是 `"?"`，输出变为 `"bobis?yearsold"`。注意阶段 ②④ 中的字母虽然也出现在某些键里，但**不在括号内就不查表**——这是本题最容易看错的地方。

## 4. 算法细节

1. **建表**：C++ 用 `unordered_map<string, string>`，先 `reserve` 减少扩容 rehash；Python 直接字典推导 `{k: v for k, v in knowledge}`。键不重复保证无覆盖歧义。
2. **定位右括号**：C++ `s.find(')', i)` 与手写 `while` 循环等价，均为 $O(\text{键长})$；题目保证配对存在，不会返回 `npos`。
3. **切键**：C++ `s.substr(i + 1, j - i - 1)` 会产生一个临时串（长度 $\le 10$，常数开销，可接受）；Python 切片 `s[i+1:j]` 同理。
4. **查表与追加**：命中追加 `it->second`，未命中追加 `'?'`；Python 用 `mp.get(key, "?")` 一步到位。
5. **游标跳跃**：`i = j + 1` 跳过整段 `(key)`。这一步既是正确性的要求（括号字符不能进结果），也是线性复杂度的保证（括号段内每个字符不被二次处理）。
6. **缓冲区**：C++ `res.reserve(s.size())` 预分配（结果长度与 $n$ 同量级：值长 $\le 10$、段长 $\le 11$，膨胀/收缩均有限），`append`/`+=` 均摊 $O(1)$；Python 用 `list` 收集片段，最后 `"".join(parts)` 一次拼接。

## 5. 正确性证明

记 $n = |s|$，$f(\cdot)$ 为题目定义的替换函数。

**引理 1（配对定位）**：设 $s$ 无嵌套括号且每个 `'('` 均有配对 `')'`。若 $s_i = $ `'('`，$j$ 为 $i$ 之后第一个 `')'` 的位置，则 $(i, j)$ 恰为一对配对括号，且 $s_{i+1..j-1}$ 全为小写字母。

**证明**：设 $i$ 的配对为 $j' > i$，即 $s_{i..j'}$ 是平衡的且任意真前缀的未闭合 `'('` 数为正。若 $j' \ne j$，则 $j < j'$（$j$ 是 $i$ 之后第一个 `')'`）。考察位置 $j < j'$ 的 `')'`：它不是 $i$ 的配对，故必与某个 $i'' \in (i, j)$ 的 `'('` 配对（从 $i+1$ 扫到 $j$，中途未出现 `')'`，若也未出现 `'('`，则扫描到 $j$ 时唯一未闭合的就是 $s_i$，$j$ 即 $i$ 的配对，矛盾）。于是括号对 $(i'', j'')$（$j'' \le j < j'$）严格含于 $(i, j')$ 内部——嵌套括号对，与题设矛盾。故 $j' = j$。又括号内键非空且 `s` 只含小写字母与括号，而 $(i,j)$ 之间无任何括号字符（$j$ 是第一个 `')'`，且若有 `'('` 则其配对必在 $(i,j)$ 内，同样构成嵌套），故 $s_{i+1..j-1}$ 全为小写字母。∎

**引理 2（循环不变式）**：每轮循环开始时，$s_{0..i-1}$ 可分解为若干**完整的括号段与普通字符**的拼接（即 $i$ 从不落在某个括号段中间），且 $res = f(s_{0..i-1})$。

**证明**：对循环轮数归纳。初始 $i = 0$，空前缀两条均平凡成立。归纳步设某轮开始时结论成立：

- 若 $s_i \ne$ `'('`：普通字符，$res' = res + s_i = f(s_{0..i})$，$i' = i+1$ 仍不在括号段中间；
- 若 $s_i =$ `'('`：由引理 1，$j$ 为其配对，键 $key = s_{i+1..j-1}$ 正是该段内容。按替换规则 $f$ 对该段输出 $map[key]$（存在时）或 `"?"`（不存在时），与算法追加的内容一致，故 $res' = res + (\text{该段替换值}) = f(s_{0..j})$，且 $i' = j + 1$ 不落在括号段中间。

两种情况均维持不变式。∎

**定理**：算法终止并返回 $f(s)$；时间复杂度 $O(n + k)$，空间复杂度 $O(n + k)$（不计输出则 $O(k)$）。

**证明**：循环中 $i$ 严格递增且有上界 $n$，故终止；终止时 $i = n$，由引理 2 得 $res = f(s_{0..n-1}) = f(s)$。时间：建表遍历 `knowledge` 一次，每条键值长度 $\le 10$，共 $O(k)$；主循环中普通字符分支 $O(1)$，括号分支处理长为 $\ell = j - i + 1$ 的段花费 $O(\ell)$（定位 `')'`、切片、查表），由引理 2 各段互不重叠，全部段与普通字符合计恰覆盖 $s$ 的每个字符常数次，共 $O(n)$。空间：哈希表 $O(k)$，结果缓冲 $O(n)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k)$——建表 $O(k)$（键值长度 $\le 10$ 视作常数因子）；单趟扫描 $O(n)$，每字符被访问常数次；每次哈希查找 $O(1)$（键长 $\le 10$，哈希与比较均为常数）。
- **空间复杂度**：$O(n + k)$——哈希表存放 `knowledge` 占 $O(k)$；结果字符串最长约 $10 \cdot \frac{n}{2} + n$（全部段被长度 10 的值替换），仍是 $O(n)$ 量级；若不计输出则 $O(k)$。
- **对比**：暴力线性查表为 $O(nk)$，在 $n = k = 10^5$ 下约 $5 \times 10^9$ 次操作，超时两个数量级以上。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string evaluate(string s, vector<vector<string>>& knowledge) {
        unordered_map<string, string> mp;
        mp.reserve(knowledge.size() * 2);
        for (auto& kv : knowledge) {
            mp[kv[0]] = kv[1];
        }

        string res;
        res.reserve(s.size());
        int n = s.size(), i = 0;
        while (i < n) {
            if (s[i] == '(') {
                int j = s.find(')', i);          // 保证存在，无 npos 风险
                auto it = mp.find(s.substr(i + 1, j - i - 1));
                res += (it != mp.end() ? it->second : "?");
                i = j + 1;                       // 跳过整段 (key)
            } else {
                res += s[i++];
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def evaluate(self, s: str, knowledge: List[List[str]]) -> str:
        mp = {k: v for k, v in knowledge}

        res = []
        i, n = 0, len(s)
        while i < n:
            if s[i] == '(':
                j = s.find(')', i)
                res.append(mp.get(s[i + 1:j], "?"))
                i = j + 1
            else:
                res.append(s[i])
                i += 1
        return "".join(res)
```

> 💡 **实现说明**：① C++ `res.reserve(s.size())` 只是下界提示（结果可能因值比键长而变长），但已显著减少重分配次数；`unordered_map::reserve` 同理减少 rehash。② Python 用 `list` + `join` 而非对 `str` 反复 `+=`，规避不可变字符串拷贝的最坏 $O(n^2)$。③ `s.find(')', i)` 一步定位右括号，比手写内层 `while` 更简洁，复杂度相同。

## 8. 边界情况与易错点

1. **`knowledge` 为空**（$k = 0$）：所有 `(key)` 都替换成 `"?"`，哈希表为空表，逻辑无需特判。
2. **`s` 无括号**：扫描退化为逐字符拷贝，原样返回。
3. **括号外的字符不参与替换**：如示例 3 中括号外的 `aaa`，即使字母与键相同也不动。判定依据是**是否位于括号段内**，而不是字符内容。
4. **同一键多次出现**：每次都独立查表，输出相同值；哈希表只存一份，无额外开销。
5. **游标必须跳到 $j + 1$**：跳到 $j$ 会把 `')'` 追加进结果；逐字符 `i += 1` 穿过括号段则会把键名字母当普通字符输出，两种都是典型 WA。
6. **切片边界**：键是 $s[i+1..j-1]$，两端括号都不包含；`substr(i + 1, j - i - 1)` 的第二参数是**长度**不是下标，写错会切出错误内容。
7. **字符串拼接性能**：C++ 不 `reserve` 时 `string` 倍增扩容仍均摊 $O(1)$，但反复构造 + 赋值的写法（如 `res = res + ch`，每步生成新串）是 $O(n^2)$；Python 对 `str` 的 `+=` 在 CPython 有单引用就地优化，但 `list + join` 是无争议的安全写法。
8. **不要用「迭代 replace 原串」实现**：`knowledge` 中没有的键处理不了，且 `value` 含括号时会被后续 replace 二次展开（见 §3.1），正确性与性能双输。
