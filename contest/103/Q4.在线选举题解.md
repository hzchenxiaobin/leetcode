# LeetCode 在线选举 题解

## 1. 题目概述

- **标题 / 题号**：在线选举（#911，medium）
- **链接**：https://leetcode.cn/problems/online-election/
- **来源**：LeetCode 第 103 场周赛 Q4
- **难度**：中等
- **标签**：设计、数组、哈希表、二分查找

**题意**：第 $i$ 张票在时刻 `times[i]` 投给候选人 `persons[i]`（`times` 严格递增）。对任意查询时刻 $t$，返回**截至时刻 $t$**（含 $t$ 时刻投出的票）得票最多者的编号；**平票时最近获得投票的候选人获胜**。

需要实现 `TopVotedCandidate` 类：构造函数用 `persons`、`times` 初始化；`q(t)` 返回时刻 $t$ 的领先者。

**约束**：

- $1 \le persons.length \le 5000$，$times.length = persons.length$
- $0 \le persons[i] < persons.length$
- $0 \le times[i] \le 10^9$，`times` 严格递增
- $times[0] \le t \le 10^9$，每个测试用例最多调用 $10^4$ 次 `q`

## 2. 示例

```text
输入：
["TopVotedCandidate","q","q","q","q","q","q"]
[[[0,1,1,0,0,1,0],[0,5,10,15,20,25,30]],[3],[12],[25],[15],[24],[8]]
输出：[null, 0, 1, 1, 0, 0, 1]

解释：
TopVotedCandidate( persons = [0,1,1,0,0,1,0], times = [0,5,10,15,20,25,30] )
q(3)  → 0   时刻 3 只有第一张票（投给 0）
q(12) → 1   票数 [0:1, 1:2]
q(25) → 1   票数 [0:2, 1:2]，平票，最近一票投给 1
q(15) → 0   票数 [0:2, 1:1]
q(24) → 0   票数 [0:2, 1:1]
q(8)  → 1   票数 [0:1, 1:1]，平票，最近一票投给 1
```

**补充示例（自造，验证「最近得票」规则）**

```text
输入：
["TopVotedCandidate","q","q"]
[[[0,0,1,1,2],[0,1,2,3,4]],[4],[2]]
输出：[null, 1, 0]

解释：
q(4) 时三人的票数为 [0:2, 1:2, 2:1]；0 与 1 并列最多，1 的最后一票在时刻 3，比 0 的最后一票（时刻 1）更近 → 1。
q(2) 时票数 [0:2, 1:1] → 0 领先。
```

## 3. 解题思路

### 3.1 暴力思路

每次查询 $q(t)$ 时，从头扫一遍 `persons`，只统计 $times[i] \le t$ 的票，用哈希表计票，最后按「票数降序、时刻降序」找到领先者。单次查询 $O(n \log n)$ 或 $O(n)$，$10^4$ 次查询 × $5000$ = $5\times10^7$，勉强能过但不够优雅，而且每次都重复计算了大量相同的前缀。

注意到查询之间**高度重复**：$q(15)$ 与 $q(24)$ 的票数统计完全一样（$[15, 24]$ 之间没有新票），暴力做法却要各算一遍。

### 3.2 核心观察：领先者只会在「投票时刻」变化

![预处理：每个前缀的领先者](images/wc103_q4_prefix_leader_concept.svg)

候选人得票数只可能在**有人投票的时刻**发生变化，因此领先者也只可能在这些时刻变化。于是：

1. **预处理**数组 `lead[i]`：表示「处理完第 $0 \sim i$ 张票之后」的领先者。整个过程只需扫一遍票，边投票边更新。
2. **查询** $q(t)$：先二分找出**最后一个满足 $times[i] \le t$ 的下标** $idx$，答案就是 `lead[idx]`。因为 `times` 严格递增、查询时刻单调可二分，这一步 $O(\log n)$。

**怎么在线维护领先者？** 设当前领先者为 $L$（初始为第一张票的候选人）。当第 $i$ 张票投给 $p$ 时：

- `cnt[p]` 加一，其他人的票数不变；
- 若 `cnt[p] >= cnt[L]`，则 $p$ 成为新的领先者；
- 否则 $L$ 保持不变。

第二条的依据是平票规则：`cnt[p] == cnt[L]` 时，$p$ 刚刚得票、比 $L$ 的最后一票更近，所以 $p$ 胜出；`cnt[p] > cnt[L]` 更不用说。而当 `cnt[p] < cnt[L]` 时，$p$ 的票数仍低于 $L$，$L$ 的最大票数地位不变，且其他候选人的票数与「最近得票时刻」都没变，故 $L$ 仍是领先者。

### 3.3 算法流程

![构造 + 二分查询](images/wc103_q4_binary_search_flow.svg)

```text
构造 TopVotedCandidate(persons, times):
1. cnt = 全 0 数组，lead = 长度 n 的数组
2. leader = -1
3. for i = 0 .. n-1:
4.     p = persons[i]
5.     cnt[p]++
6.     若 leader == -1 或 cnt[p] >= cnt[leader]:  leader = p
7.     lead[i] = leader
8. 保存 times 与 lead

查询 q(t):
9. idx = upper_bound(times, t) - 1        # 最后一个 times[i] <= t
10. 返回 lead[idx]
```

由于题目保证 $times[0] \le t$，`idx` 一定 $\ge 0$，不需要处理越界。

### 3.4 示例演算

![示例查询：answer = [0,1,1,0,0,1]](images/wc103_q4_walkthrough.svg)

对 `persons = [0,1,1,0,0,1,0]`、`times = [0,5,10,15,20,25,30]`：

| $i$ | 时刻 | 投给 | 票数 | `lead[i]` |
|-----|------|------|------|-----------|
| 0 | 0 | 0 | 0:1 | 0 |
| 1 | 5 | 1 | 0:1, 1:1（平票，1 更新） | 1 |
| 2 | 10 | 1 | 0:1, 1:2 | 1 |
| 3 | 15 | 0 | 0:2, 1:2（平票，0 更新） | 0 |
| 4 | 20 | 0 | 0:3, 1:2 | 0 |
| 5 | 25 | 1 | 0:3, 1:3（平票，1 更新） | 1 |
| 6 | 30 | 0 | 0:4, 1:3 | 0 |

查询时只需二分：$q(12)$ → `times` 中小于等于 12 的最后一个下标是 2 → `lead[2] = 1`；$q(25)$ → 下标 5 → `lead[5] = 1`。

## 4. 算法细节

1. **`upper_bound` 的语义**：返回第一个 $> t$ 的位置，减一即「最后一个 $\le t$」。C++ 用 `upper_bound(times.begin(), times.end(), t) - times.begin() - 1`；Python 用 `bisect_right(times, t) - 1`。
2. **`lead` 数组与 `times` 一一对应**：`lead[i]` 表示「处理完时刻 `times[i]` 及之前所有票」的状态，正好是查询所需的粒度，无须额外偏移。
3. **平票的更新方向**：条件必须是 `cnt[p] >= cnt[leader]`（大于**或等于**），写成 `>` 会漏掉「平票时最近得票者胜」的规则。
4. **`leader` 的初始化**：用 $-1$ 作哨兵，第一张票时无条件赋值，避免访问 `cnt[-1]`。
5. **票数数组大小**：`persons[i] < persons.length`，开 $n$ 大小即可；开 $10^9$ 会浪费内存。
6. **成员变量**：C++ 类中把 `times` 与 `lead` 存为成员，`q` 是 `const` 语义的只读查询（不需要 mutable）。

## 5. 正确性证明

**引理 1（领先者的增量更新）**：设处理完第 $i-1$ 张票后 `leader` 是真实领先者，第 $i$ 张票投给 $p$，则按规则「若 `cnt[p] >= cnt[leader]` 则 `leader = p`，否则不变」得到的仍是处理完第 $i$ 张票后的真实领先者。

**证明**：记更新前票数为 $c(\cdot)$，更新后 $c'(p) = c(p) + 1$，其他候选人 $c'(x) = c(x)$。设更新前领先者为 $L$，即 $c(L) = \max_x c(x)$，且在票数等于 $c(L)$ 的候选人中 $L$ 的最后一票最晚。

*情形一：$c(p) + 1 \ge c(L)$。* 此时 $c'(p) \ge c(L) = \max_{x \ne p} c'(x)$，故 $p$ 的票数最大。在所有票数最大的候选人中，$p$ 的最后一票就是刚投出的第 $i$ 张票，时刻最晚，故 $p$ 是领先者。

*情形二：$c(p) + 1 < c(L)$。* 此时 $c'(L) = c(L) > c'(p)$，且对其他 $x$ 有 $c'(x) = c(x) \le c(L)$，故 $L$ 仍是票数唯一最大或并列最大者之一。注意 $p$ 的票数严格小于 $c(L)$，不可能进入「票数最大」的集合；其他候选人的票数与最后得票时刻均未变。因此票数最大的候选人集合与更新前相同，$L$ 在该集合中最后得票最晚，仍是领先者。∎

**引理 2（前缀覆盖）**：`lead[i]` 等于「只统计前 $i+1$ 张票（即时刻 $\le times[i]$ 的票）」时的领先者。

**证明**：对 $i$ 归纳。$i = 0$ 时只有一张票，领先者显然是其候选人，构造过程给出同样结果。设 `lead[i-1]` 正确，处理第 $i$ 张票时由引理 1 得到正确的领先者，赋给 `lead[i]`。∎

**引理 3（二分定位）**：对查询 $t$，令 $idx$ 为满足 $times[idx] \le t$ 的最大下标（因 $times[0] \le t$ 必存在），则「截至时刻 $t$ 的票」恰为前 $idx + 1$ 张票。

**证明**：`times` 严格递增，故集合 $\{i : times[i] \le t\}$ 是前缀 $[0, idx]$（若某个 $i \le idx$ 满足 $times[i] > t$，与 $times$ 递增及 $times[idx] \le t$ 矛盾；若某个 $i > idx$ 满足 $times[i] \le t$，与 $idx$ 的最大性矛盾）。∎

**定理**：`q(t)` 返回时刻 $t$ 的真实领先者。

**证明**：由引理 3，截至 $t$ 的票恰为前 $idx+1$ 张；由引理 2，`lead[idx]` 正是这批票对应的领先者。故返回值正确。∎

## 6. 复杂度分析

- **构造时间**：$O(n)$。一遍扫描，每张票做 $O(1)$ 的计数与比较。
- **单次查询时间**：$O(\log n)$。`upper_bound` 二分；$10^4$ 次查询共约 $10^4 \times 13$ 次比较。
- **空间**：$O(n)$。`lead` 与 `times` 各长度 $n$，`cnt` 长度 $n$（候选人编号 $< n$）。

## 7. 参考代码

### C++

```cpp
class TopVotedCandidate {
public:
    TopVotedCandidate(vector<int>& persons, vector<int>& times) : times_(times) {
        int n = (int)persons.size();
        vector<int> cnt(n, 0);
        lead_.resize(n);
        int leader = -1;
        for (int i = 0; i < n; i++) {
            int p = persons[i];
            cnt[p]++;
            if (leader == -1 || cnt[p] >= cnt[leader]) leader = p;
            lead_[i] = leader;
        }
    }

    int q(int t) {
        int idx = (int)(upper_bound(times_.begin(), times_.end(), t) - times_.begin()) - 1;
        return lead_[idx];
    }

private:
    vector<int> times_;
    vector<int> lead_;
};
```

### Python

```python
from bisect import bisect_right


class TopVotedCandidate:
    def __init__(self, persons: list[int], times: list[int]):
        n = len(persons)
        cnt = [0] * n
        self.times = times
        self.lead = [0] * n
        leader = -1
        for i in range(n):
            p = persons[i]
            cnt[p] += 1
            if leader == -1 or cnt[p] >= cnt[leader]:
                leader = p
            self.lead[i] = leader

    def q(self, t: int) -> int:
        idx = bisect_right(self.times, t) - 1
        return self.lead[idx]
```

## 8. 边界情况与易错点

1. **平票规则写反**：条件必须是 `cnt[p] >= cnt[leader]`。若写成 `>`，示例中 $q(8)$ 会返回 0 而不是 1。
2. **`upper_bound` 与 `lower_bound` 混用**：查询包含「时刻恰好等于 $t$ 的票」，必须用 `upper_bound`（最后一个 $\le t$），用 `lower_bound` 会漏掉当期票。
3. **`idx` 可能为 $-1$**：题目保证 $times[0] \le t$，所以不会发生；但若把该保证去掉，需要特判返回 $-1$ 或抛错（LeetCode 原题保证不越界）。
4. **`lead` 记录的是「第 i 张票之后」**：构造时先投票再记录，顺序反了会整体偏移一位。
5. **`cnt` 数组大小**：`persons[i] < persons.length`，开 $n$ 即可；若开成最大值 $10^9$ 会 MLE。
6. **每次查询重扫**：$10^4 \times 5000$ 的单次 $O(n)$ 扫描虽然理论可过，但用二分更稳，也更能体现「预处理 + 查询」的设计题思路。
7. **`t` 超过最后一张票的时刻**：$t$ 最大 $10^9$，可能大于 `times[n-1]`，此时 `idx = n-1`，答案就是最终领先者，二分自然处理。
