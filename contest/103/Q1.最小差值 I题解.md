# LeetCode 最小差值 I 题解

## 1. 题目概述

- **标题 / 题号**：最小差值 I（#908，easy）
- **链接**：https://leetcode.cn/problems/smallest-range-i/
- **来源**：LeetCode 第 103 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 `nums` 和整数 `k`。对每个下标 $i$，**最多**执行一次操作：把 `nums[i]` 改成 `nums[i] + x`，其中 $x \in [-k, k]$ 且为整数（等价于把每个元素移动到 $[nums[i]-k, nums[i]+k]$ 内的任意位置）。操作完成后，数组的**分数**是最大值与最小值之差，返回能达到的**最低分数**。

**约束**：

- $1 \le nums.length \le 10^4$
- $0 \le nums[i] \le 10^4$
- $0 \le k \le 10^4$

## 2. 示例

**示例 1**

```text
输入：nums = [1], k = 0
输出：0
解释：只有一个元素，最大值 = 最小值，分数为 0。
```

**示例 2**

```text
输入：nums = [0,10], k = 2
输出：6
解释：把 0 抬到 2、把 10 降到 8，分数 8 − 2 = 6。原极差 10 减少 2k = 4。
```

**示例 3**

```text
输入：nums = [1,3,6], k = 3
输出：0
解释：把三个数都变成 4（1 加 3、3 加 1、6 减 2，改变量都在 [−3, 3] 内），分数 0。
```

**示例 4（自造，调整量恰好用满）**

```text
输入：nums = [2,7,2], k = 1
输出：3
解释：极差 5，最多缩小 2，答案 3（把 2 抬到 3、7 降到 6）。
```

## 3. 解题思路

### 3.1 暴力思路

每个元素有 $2k+1$ 种可选值，$n$ 个元素共有 $(2k+1)^n$ 种组合，$k$ 最大 $10^4$ 时完全不可行。即使只关心「让最大值尽量小、最小值尽量大」，也需要意识到：**只有原来的最大值和最小值值得动**，其余元素怎么调都不会让极差更小。

### 3.2 核心观察：区间两端各向中间收缩 $k$

![每个元素只能在自己的 ±k 区间内移动](images/wc103_q1_range_shift_concept.svg)

设原数组最大值为 $M$、最小值为 $m$。无论怎么操作：

- 原来等于 $M$ 的那个元素最多只能降到 $M - k$，所以操作后的最大值**至少**是 $M - k$；
- 原来等于 $m$ 的那个元素最多只能升到 $m + k$，所以操作后的最小值**至多**是 $m + k$。

因此任何方案的分数都满足

$$\text{分数} \ge (M - k) - (m + k) = (M - m) - 2k.$$

再结合「分数非负」这一显然事实，得到下界 $\max\bigl(0, (M - m) - 2k\bigr)$。

这个下界是**可以达到**的，构造方式非常直接：把每个元素「夹」到区间 $[\,m + k,\; M - k\,]$ 上，即令

$$b_i = \min\bigl(\max(nums[i],\, m + k),\, M - k\bigr).$$

- 每个 $b_i$ 都在 $[m+k, M-k]$ 内，所以最终极差不超过 $(M-k)-(m+k)$；
- 夹取移动的距离不超过 $k$：若 $nums[i] < m + k$，则 $b_i - nums[i] = m + k - nums[i] \le k$（因为 $nums[i] \ge m$）；若 $nums[i] > M - k$，同理 $nums[i] - b_i \le k$；
- 原来取到 $m$ 的元素会被夹到 $m + k$，原来取到 $M$ 的元素会被夹到 $M - k$，所以最终极差**恰好**是 $(M-m)-2k$（当这个值非负时）。

若 $(M-m) - 2k \le 0$，则区间 $[m+k, M-k]$ 非空（甚至可能退化），所有元素都能夹到同一个值附近，分数 0 可达。

### 3.3 算法流程

![算法流程：两端同时收缩，负数截断为 0](images/wc103_q1_algorithm_flow.svg)

```text
1. m = min(nums), M = max(nums)
2. d = (M - m) - 2 * k
3. 返回 max(0, d)
```

只有三步：求极值、算差值、与 0 取较大者。不需要模拟任何操作。

### 3.4 示例演算

![三个示例：把公式逐项算出来](images/wc103_q1_walkthrough.svg)

| `nums` | $k$ | $M - m$ | $(M-m) - 2k$ | 答案 |
|--------|-----|---------|--------------|------|
| [1] | 0 | 0 | 0 | 0 |
| [0,10] | 2 | 10 | 6 | 6 |
| [1,3,6] | 3 | 5 | −1 → 截断为 0 | 0 |
| [2,7,2] | 1 | 5 | 3 | 3 |

第三个示例中区间宽度只有 5，而 $2k = 6$，两端的调整范围已经重叠，于是能全部压到 4。

## 4. 算法细节

1. **只关心极值**：中间的 $n-2$ 个元素不必出现在公式里。它们只会被「夹」进目标区间，既不会成为新的最大值，也不会成为新的最小值。
2. **「最多一次」允许不操作**：题目说每个下标最多应用一次操作，取 $x = 0$ 即不操作，所以「夹取」构造不需要考虑「必须移动」的约束。
3. **整数性**：$x$ 取整数，而 $m$、$M$、$k$ 都是整数，夹取后的值仍是整数，不存在「只能逼近不能到达」的问题。
4. **负数截断**：$(M-m)-2k$ 可能为负（示例 3 是 $-1$），必须与 0 取 `max`，否则会返回负的「分数」。
5. **`k = 0`**：公式退化为 $M - m$，即不做任何调整，符合预期。
6. **不用排序**：求极值只需一遍扫描，$O(n)$；排序是 $O(n \log n)$ 的多余开销。

## 5. 正确性证明

**引理 1（下界）**：设操作后的数组为 $b$，则 $\max(b) - \min(b) \ge (M - m) - 2k$。

**证明**：取原数组中等于 $M$ 的下标 $p$、等于 $m$ 的下标 $q$（可能 $p = q$，当且仅当所有元素相等）。由操作规则，$b_p \le M + k$ 且 $b_p \ge M - k$，$b_q \ge m - k$ 且 $b_q \le m + k$。

因为 $\max(b) \ge b_p \ge M - k$，且 $\min(b) \le b_q \le m + k$，两式相减得

$$\max(b) - \min(b) \ge (M - k) - (m + k) = (M - m) - 2k. \qquad \blacksquare$$

**引理 2（分数非负）**：对任意 $b$，$\max(b) - \min(b) \ge 0$。

**证明**：最大值不小于最小值，这是定义的直接推论。∎

**引理 3（上界可达）**：存在合法操作使分数等于 $\max\bigl(0, (M-m)-2k\bigr)$。

**证明**：令 $L = m + k$、$R = M - k$，定义 $b_i = \min(\max(nums[i], L), R)$（当 $L > R$ 时，把区间理解为单点 $L$，即所有元素都取 $L$，其移动量 $|nums[i] - L| \le k$ 依然成立，因为 $nums[i] \in [m, M]$ 且 $L = m+k \in [m, M]$）。

移动量检验：若 $nums[i] < L$，则 $b_i = L$，$b_i - nums[i] = m + k - nums[i] \le m + k - m = k$；若 $nums[i] > R$，则 $b_i = R$，$nums[i] - b_i \le M - (M - k) = k$；否则 $b_i = nums[i]$，移动量为 0。三种情况都满足 $|b_i - nums[i]| \le k$，因此该 $b$ 是合法结果。

分数检验：

- 所有 $b_i \in [L, R]$，故 $\max(b) - \min(b) \le R - L = (M-m) - 2k$；
- 若 $L \le R$：取到 $m$ 的元素被夹到 $L$，取到 $M$ 的元素被夹到 $R$，故 $\min(b) = L$、$\max(b) = R$，分数恰为 $(M-m)-2k$；
- 若 $L > R$：所有 $b_i = L$（或全在 $[R, L]$ 内被压到单点），分数为 0。

两种情形都达到 $\max\bigl(0, (M-m)-2k\bigr)$。∎

**定理**：算法返回 $\max\bigl(0, (M-m)-2k\bigr)$，等于所有合法操作下分数的最小值。

**证明**：由引理 1、2，任何方案的分数都不小于 $\max(0, (M-m)-2k)$；由引理 3，该值可被某个合法方案达到。故它是最小值。∎

> 💡 **注意**：本题的「最优」只由 $(M, m, k)$ 三个量决定，与数组其余元素、元素顺序、重数都无关——这是把「$n$ 元优化」压缩为「两端极值」的典型例子。

## 6. 复杂度分析

- **时间**：$O(n)$。只需要一遍遍历求最小值和最大值，随后的算术运算是 $O(1)$。
- **空间**：$O(1)$。只用了 `mn`、`mx`、`ans` 几个整型变量，没有额外数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int smallestRangeI(vector<int>& nums, int k) {
        int mn = nums[0], mx = nums[0];
        for (int x : nums) {
            mn = min(mn, x);
            mx = max(mx, x);
        }
        return max(0, mx - mn - 2 * k);
    }
};
```

### Python

```python
class Solution:
    def smallestRangeI(self, nums: list[int], k: int) -> int:
        mn, mx = min(nums), max(nums)
        return max(0, mx - mn - 2 * k)
```

## 8. 边界情况与易错点

1. **忘记与 0 取 max**：$(M-m)-2k$ 为负时必须返回 0，示例 3 的 $-1$ 就是陷阱。
2. **`k = 0` 或 `n = 1`**：公式自然退化为原极差或 0，不需要特判。
3. **误以为要模拟操作**：本题是纯数学题，模拟每个元素的调整既慢又容易错。
4. **误以为每个元素都必须动**：题目是「最多一次」，`x` 可以取 0；构造时中间元素保持不动是合法的。
5. **`int` 范围**：$nums[i] \le 10^4$、$k \le 10^4$，差值在 `int` 范围内，无溢出风险。
6. **把「两个篮子」式的约束套进来**：本题没有「只能挑两种」之类的限制，所有元素都可以调。
