# LeetCode 执行指令后的得分 题解

## 1. 题目概述

- **标题 / 题号**：执行指令后的得分（#3522，medium）
- **链接**：https://leetcode.cn/problems/calculate-score-after-performing-instructions/
- **来源**：LeetCode 第 446 场周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、字符串、模拟

**题意**：给定长度均为 $n$ 的数组 `instructions` 与 `values`，从下标 $i = 0$、得分 $0$ 出发模拟：若 `instructions[i] == "add"`，把 `values[i]` 加进得分并移动到 $i+1$；若 `instructions[i] == "jump"`，不得分、移动到 $i + \text{values}[i]$（`values[i]` 可为负，即可以**往回跳**）。过程在**越界**（$i < 0$ 或 $i \ge n$）或**试图重复执行已执行过的指令**这两种情况之一发生时终止。返回过程结束时的得分。

**约束**：

- $1 \le n \le 10^5$
- `instructions[i]` 只能是 `"add"` 或 `"jump"`
- $-10^5 \le \text{values}[i] \le 10^5$

> 💡 **读题关键**：① `jump` 的目标是 $i + \text{values}[i]$，负值意味着往回跳，轨迹**不单调**；② 终止只有"越界 / 重访"两种情形，它们恰好覆盖所有可能——这是模拟必然停机的根基；③ 被 `jump` 跨过的指令**从未执行**、不得分；④ 得分上界 $10^5 \times 10^5 = 10^{10}$，**超出 32 位 int**，C++ 必须 `long long`。本题虽排在 Q1 且是标准签到题，但埋了"往回跳"与"溢出"两个坑，标了中等。

## 2. 示例

**示例 1**

```text
输入：instructions = ["jump","add","add","jump","add","jump"], values = [2,1,3,1,-2,-3]
输出：1
解释：0 --jump+2--> 2 --add(+3)--> 3 --jump+1--> 4 --add(-2)--> 5 --jump-3--> 2(重访，停)
      得分 = 3 + (-2) = 1。下标 1 被 jump 跨过，从未执行、不得分。
```

**示例 2**

```text
输入：instructions = ["jump","add","add"], values = [3,1,1]
输出：0
解释：下标 0 是 jump，跳到 0 + 3 = 3，越界，过程立即结束，得分 0。
```

**示例 3**

```text
输入：instructions = ["jump"], values = [0]
输出：0
解释：jump + 0 原地自环：第 1 轮执行下标 0，第 2 轮试图重访，立即终止，得分 0。
```

## 3. 解题思路

### 3.1 暴力思路

照题面逐步模拟即可，但有两个必须先解决的问题：

- **怎么判重访？** 不做任何记录，示例 3（`jump + 0` 自环）直接死循环。朴素的判重是每走一步就把下标塞进列表线性扫一遍——单步 $O(n)$、总体 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。改用**哈希表**（`unordered_set`）可把单步降到均摊 $O(1)$。
- **到底会走多少步？** 往回跳让轨迹可以来回绕，步数上界不明显。不解决这个疑虑，即使写对了也心里没底——见核心观察。

### 3.2 核心观察：出度恒为 1 的函数图，线性模拟即最优

![核心观察：出度恒为 1，轨迹是一条链（ρ 形回环或飞出边界）](images/c446_q1_rho_trajectory.svg)

- **观察一（出度恒为 1）**：站在下标 $i$，无论指令是 `add` 还是 `jump`，下一位置都唯一确定——$\text{next}(i) = i+1$ 或 $i + \text{values}[i]$。整个系统是一张**函数图**（每节点出度恰为 1），从 $0$ 出发的轨迹是一条**没有分叉的链**。
- **观察二（轨迹只有两种命运）**：链要么中途飞出 $[0, n)$（越界停，示例 2），要么在有限步后撞上自己的脚印——首次重访处正是环入口，轨迹呈"**尾巴 + 环**"的 ρ 形（示例 1 的尾巴 $0 \to 2$，环 $2 \to 3 \to 4 \to 5 \to 2$）。没有第三种可能。
- **观察三（鸽笼 ⇒ 步数上界）**：重访即终止 ⇒ $n$ 个下标**每个至多执行一次** ⇒ 总步数 $\le n + 1$。"往回跳会不会绕不完"的疑虑一扫而空——线性模拟本身就是 $O(n)$，不存在死循环，也不存在超时。
- **观察四（判重结构选型）**：判重的键是**下标**，值域恰为 $[0, n)$ 的连续整数——直接开 `bool visited[n]` 数组即可，一次内存访问完事，比哈希表省去哈希计算与冲突处理，缓存更友好。这也是标签里带"哈希表"但实际**不必**用哈希表的原因：键值域太规整了。

### 3.3 算法流程

![算法流程：越界与重访合并进 while 条件，循环体只做标记与执行](images/c446_q1_simulation_flow.svg)

| 步骤 | 动作 | 说明 |
|------|------|------|
| ① 初始化 | `i = 0`，`score = 0`，`visited` 全 `false` | `score` 用 64 位，上界 $10^{10}$ |
| ② 循环条件 | `0 <= i < n && !visited[i]` | 两种终止（越界 / 重访）**合并**进 `while`，零特判 |
| ③ 标记 | `visited[i] = true` | **先标记再执行**，`jump + 0` 自环在下一轮被条件拦下 |
| ④ 执行 | `add`：`score += values[i]`，`i += 1`；`jump`：`i += values[i]` | 只有 `add` 影响得分 |
| ⑤ 返回 | `score` | 每轮执行一条新指令，至多 $n+1$ 轮 |

### 3.4 示例演算

![示例 1 演算：5 步执行，下标 1 被跳过，重访下标 2 终止](images/c446_q1_example_walkthrough.svg)

用**示例 1** 逐步走一遍：

| 轮次 | 当前 $i$ | 指令 | 动作 | 得分变化 | 下一 $i$ | 是否继续 |
|------|---------|------|------|---------|---------|---------|
| 1 | 0 | `jump` +2 | 跳转，不得分 | $0$ | $2$ | ✓ |
| 2 | 2 | `add` +3 | 累加，右移 | $0 \to 3$ | $3$ | ✓ |
| 3 | 3 | `jump` +1 | 跳转，不得分 | $3$ | $4$ | ✓ |
| 4 | 4 | `add` −2 | 累加，右移 | $3 \to 1$ | $5$ | ✓ |
| 5 | 5 | `jump` −3 | 跳转，不得分 | $1$ | $2$ | ✗ 重访，停 |

最终得分 $\boxed{1}$。全程共执行 5 条指令；下标 1 被 `jump` 跨过、从未执行，**不贡献得分**。

**示例 3**（自环）：第 1 轮先标记 `visited[0] = true`，`jump + 0` 使 $i$ 仍为 $0$；第 2 轮 `while` 条件发现已访问，立即退出，得分 $0$——"先标记再执行"天然防住死循环。

## 4. 算法细节

1. **循环条件合并**：把越界（$i < 0$ 或 $i \ge n$）与重访（`visited[i]`）两种终止统一写进 `while` 条件，循环体内只剩"标记 → 执行"两件事，代码零特判。
2. **条件顺序**：`0 <= i < n` 必须写在 `!visited[i]` **前面**——若先查 `visited[i]`，负下标在 C++ 中越界 UB，在 Python 中负索引静默回绕到队尾，更加隐蔽。
3. **先标记再执行**：进入循环体立即 `visited[i] = true`。若先执行后标记，`jump + 0` 的自环会在标记前原地打转。
4. **判重用数组不用哈希表**：键是值域为 $[0, n)$ 的整数下标，`vector<char>` / `list[bool]` 直接索引，单步 $O(1)$ 且常数远小于哈希表。
5. **得分 64 位**：全 `add` 时 $\text{score} \le \sum \text{values}[i] \approx 10^{10}$，C++ 用 `long long`；Python 天然大整数无此坑。

## 5. 正确性证明

**引理 1（确定性）**：在终止之前，过程的每一步从当前下标到下一下标的转移是唯一确定的。

**证明**：`instructions[i]` 只有 `"add"` / `"jump"` 两种取值：前者转移到 $i + 1$，后者转移到 $i + \text{values}[i]$，二者由输入唯一给出，无任何选择分支。故从 $0$ 出发的执行序列（若存在）是唯一的。∎

**引理 2（停机性）**：过程在至多 $n$ 次指令执行、$n + 1$ 轮循环内终止。

**证明**：算法第 $k$ 轮执行前检查 `visited[i]`，故每轮执行的是一个**从未执行过**的下标；下标共 $n$ 个，由鸽笼原理，至多 $n$ 轮有效执行。第 $n + 1$ 轮时：若 $i$ 越界则条件 $0 \le i < n$ 失败退出；否则 $n$ 个下标已被全部执行，`visited[i]` 必为真，重访条件拦下。两种终止之一必在 $\le n + 1$ 轮内发生。∎

**定理**：算法返回值等于题目定义的过程结束时的得分。

**证明**：对轮数 $k$ 归纳：第 $k$ 轮开始时，算法变量 $(i_k, \text{score}_k)$ 与真实过程第 $k$ 步前的状态一致（$k = 1$ 时 $i = 0$、score $= 0$，成立）。若本轮终止条件成立，由引理 1，真实过程同样在此处停止且得分不再变化；否则两边执行同一条指令：`add` 时同为 $\text{score} \mathrel{+}= \text{values}[i]$、$i \mathrel{+}= 1$，`jump` 时同为 $i \mathrel{+}= \text{values}[i]$，状态保持一致。由引理 2 过程有限步终止，终止时算法的 `score` 即为答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。由引理 2，循环至多 $n + 1$ 轮；每轮开销为一次数组判重、一次字符串比较、一次加法，均为 $O(1)$。$n = 10^5$ 时约 $10^5$ 轮，远低于时限。
- **空间复杂度**：$O(n)$。`visited` 布尔数组占 $n$ 字节（C++ 用 `vector<char>` 同量级）；除判重外无其他非常数空间。
- **得分范围**：$\lvert \text{score} \rvert \le n \cdot \max_i \lvert \text{values}[i] \rvert \approx 10^{10}$，超出 `int` 的约 $2.1 \times 10^9$，64 位必带。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long calculateScore(vector<string>& instructions, vector<int>& values) {
        int n = instructions.size();
        vector<char> visited(n, 0);          // 下标值域 [0,n)，数组判重比哈希表更快
        long long score = 0;                 // 上界 10^10，必须 64 位
        int i = 0;
        while (i >= 0 && i < n && !visited[i]) {   // 越界与重访合并进循环条件，顺序不能反
            visited[i] = 1;                  // 先标记再执行（防 jump+0 自环）
            if (instructions[i] == "add") {
                score += values[i];
                i += 1;
            } else {
                i += values[i];              // 可正可负，可前跳可回跳
            }
        }
        return score;
    }
};
```

### Python

```python
class Solution:
    def calculateScore(self, instructions: List[str], values: List[int]) -> int:
        n = len(instructions)
        visited = [False] * n
        score, i = 0, 0
        while 0 <= i < n and not visited[i]:     # 越界检查在前，防负索引静默回绕
            visited[i] = True                    # 先标记再执行（防 jump+0 自环）
            if instructions[i] == "add":
                score += values[i]
                i += 1
            else:
                i += values[i]                   # 可正可负，可前跳可回跳
        return score
```

## 8. 边界情况与易错点

1. **得分溢出**：全 `add` 时得分约 $10^{10}$，C++ `int` 必炸，必须 `long long`；Python 天然大整数无此坑。
2. **`while` 条件顺序**：越界检查必须放在 `visited[i]` 之前短路，否则 `jump` 回跳到负下标时，C++ 数组越界 UB、Python 负索引静默回绕到队尾（更隐蔽）。
3. **先标记再执行**：`jump + 0` 的原地自环若先执行后标记会死循环；先标记则下一轮被 `visited` 拦下（示例 3）。
4. **被 `jump` 跨过的指令不得分**：不要把区间内所有 `add` 都累加——只有真正执行过的 `add` 才计分（示例 1 的下标 1）。
5. **"被跨过"≠"已执行"**：判重标记的是"已执行"，若后续 `jump` 恰好落在当初被跨过的下标上，它会正常执行并计分。
6. **别假设单调右移**：`values[i]` 可为负，`jump` 可以往回跳，判重结构不能省。
7. **$n = 1$ 全枚举**：`["add"]` 得 `values[0]` 后 $i = 1$ 越界停；`["jump"]` 配 $0$ 自环停、配非零值越界停，得分均为 $0$。
8. **得分可为负**：`values` 含负数，`score` 初值取 $0$ 即可，不要设成极小值。
