# LeetCode 无法吃午餐的学生数量 题解

## 1. 题目概述

- **标题 / 题号**：无法吃午餐的学生数量（#1700，easy）
- **链接**：https://leetcode.cn/problems/number-of-students-unable-to-eat-lunch/
- **来源**：LeetCode 第 42 场双周赛 Q1
- **难度**：简单
- **标签**：栈、队列、数组、模拟

**题意**：学生排成**队列**（每个学生喜欢圆形 $0$ 或方形 $1$ 三明治），三明治摞成**栈**（`sandwiches[i]` 是栈中第 $i$ 个，$i=0$ 为栈顶）。每一轮：队首学生若**喜欢**栈顶三明治就取走并离队；否则放弃并回到**队尾**。过程持续到队列里**没有人**喜欢栈顶三明治为止。返回吃不到午餐的学生数量。

**约束**：

- $1 \le students.length = sandwiches.length \le 100$
- 所有元素非 $0$ 即 $1$

## 2. 示例

**示例 1**

```text
输入：students = [1,1,0,0], sandwiches = [0,1,0,1]
输出：0
解释：经过若干轮"放弃回队尾 / 拿走离队"，所有学生都吃到了午餐。
```

**示例 2**

```text
输入：students = [1,1,1,0,0,1], sandwiches = [1,0,0,0,1,1]
输出：3
解释：栈顶依次是 1,0,0,0,…：前三个三明治被吃掉后，喜欢 0 的学生已绝迹，
      栈顶剩 0 无人问津，剩下的 3 名喜欢 1 的学生吃不到午餐。
```

**示例 3（边界补充）**

```text
输入：students = [0], sandwiches = [1]
输出：1
解释：唯一的学生喜欢 0，栈顶是 1，直接卡死。
```

## 3. 解题思路

### 3.1 暴力思路

老老实实模拟：用真队列 `deque` 存学生、指针存栈顶，每轮看队首是否喜欢栈顶，不喜欢就转队尾。需要一个"连续放弃次数 = 当前队列长度"的计数来检测卡死。$O(n^2)$ 最坏（每个三明治最多引发一整轮转圈），$n \le 100$ 完全够用——但这题有更妙的观察。

### 3.2 核心观察：队列会"转圈"，卡死的本质是类型计数归零

![核心观察：栈顶类型无人喜欢时队列转一整圈也不会变化](images/bw42_q1_queue_stack.svg)

学生只是不断从队首挪到队尾——**队列的多重集（各类型的人数）永远不变**，除非有人吃到三明治离队。于是：

- 栈顶三明治为类型 $s$ 时，只要还有喜欢 $s$ 的学生，转一圈后必然轮到他，三明治必被吃掉；
- 栈顶为 $s$ 而喜欢 $s$ 的人数恰为 $0$ 时，无论队列怎么转，没有任何人会取走它——**过程永久卡死**，压在它下面的三明治永远吃不到。

所以根本不用模拟转圈：**只需两个计数器** `cnt[0]`、`cnt[1]`，从栈顶往下扫三明治，类型 $s$ 有库存就 `cnt[s]--`，没库存就停——剩余计数之和即答案。

### 3.3 算法流程

![算法流程：计数器扫描三明治栈](images/bw42_q1_counting_flow.svg)

```text
1. cnt[0] = 喜欢圆形的人数，cnt[1] = 喜欢方形的人数
2. 从栈顶到底遍历 sandwiches：
       若 cnt[s] == 0：break        # 没人喜欢栈顶 → 卡死，后面的更轮不到
       否则 cnt[s] -= 1             # 一个喜欢它的学生吃掉它离队
3. 返回 cnt[0] + cnt[1]
```

### 3.4 示例演算

以示例 2 为例：`students = [1,1,1,0,0,1]` → `cnt[1] = 4, cnt[0] = 2`；`sandwiches = [1,0,0,0,1,1]`。

| 步骤 | 栈顶三明治 | cnt[0] | cnt[1] | 动作 |
|------|-----------|--------|--------|------|
| 初始 | — | 2 | 4 | — |
| 1 | 1 | 2 | 3 | 有喜欢 1 的，吃掉 |
| 2 | 0 | 1 | 3 | 有喜欢 0 的，吃掉 |
| 3 | 0 | 0 | 3 | 再吃一个 0 |
| 4 | 0 | **0** | 3 | 喜欢圆形的绝迹 → **卡死** |

答案 $= 0 + 3 = 3$ ✓。

## 4. 算法细节

1. **`break` 而非 `continue`**：遇到 `cnt[s] == 0` 必须立即停止整个扫描——栈是先进后出，顶上的三明治不消失，压在下面的永远轮不到。写成 `continue` 会把后面同类型的三明治也"吃掉"，答案偏小。
2. **学生顺序无用**：`students` 数组里 $0/1$ 的排列顺序完全不影响结果，只有**数量**重要。同理三明治栈只有**从顶到底的类型前缀**直到第一个卡死位有效。
3. **答案的另一面**：`cnt[0] + cnt[1]` 也等于"没被吃掉的三明治数"——每个吃到三明治的学生对应一个被吃掉的三明治，两者天然同步减少。
4. **为什么不用模拟队首队尾**：模拟法每个三明治至多引发一整圈 $O(n)$ 的无效转圈，总 $O(n^2)$；计数法 $O(n)$ 且代码只有几行。比赛里 Q1 就该这么"偷懒"。
5. **检测卡死的等价条件**（若坚持模拟）：连续 $n$ 次（当前队列长度）放弃且无人吃栈顶 ⟺ 卡死；更简单的实现是"放弃计数 ≥ 队列长度即停"。

## 5. 正确性证明

**引理 1（队列多重集不变性）**：学生放弃三明治回队尾的操作不改变队列中各类型学生的数量；只有"吃掉栈顶"才会使对应类型计数减一。

**证明**：放弃操作只是把队首元素移到队尾，多重集不变。吃掉操作使一名喜欢类型 $s$（= 栈顶类型）的学生离队，`cnt[s]` 恰减一。∎

**引理 2（卡死判定）**：某时刻栈顶三明治类型为 $s$ 且 $cnt[s] = 0$，则此后过程不再有任何三明治被吃掉；反之，只要 $cnt[s] > 0$，栈顶三明治必在至多一整轮（当前队列长度次移动）内被吃掉。

**证明**：$cnt[s] = 0$ 时队列里全是喜欢另一类型的学生，任何人都不会取走类型 $s$ 的栈顶，队首学生不断回队尾，状态永远不变，后续三明治被压在下面无法触及。$cnt[s] > 0$ 时，喜欢 $s$ 的学生从队首出发至多经过"当前队列长度 − 1"次放弃即可回到队首，届时取走栈顶。∎

**定理**：计数法返回的正是吃不到午餐的学生数。

**证明**：由引理 2，被吃掉的三明治恰是栈从顶到底的一段前缀——直到第一个类型 $s^*$ 满足累计消费后 $cnt[s^*] = 0$（若不存在则全部被吃掉）。计数法逐个模拟这段前缀的消费（每吃一个对应类型计数减一，与真实过程同步，引理 1），并在第一个库存耗尽处停止，与真实卡死位置一致。每个离队学生对应一个被吃掉的三明治，故吃不到的学生数 = 剩余计数之和 = 算法返回值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。统计计数一遍 + 扫描三明治栈一遍（至多 $n$ 步）。
- **空间**：$O(1)$。两个计数器；若把输入数组本身视作栈（C++ 中 `sandwiches` 按下标读），无需额外结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countStudents(vector<int>& students, vector<int>& sandwiches) {
        int cnt[2] = {0, 0};
        for (int s : students) ++cnt[s];           // 队列里两类学生的人数
        for (int s : sandwiches) {
            if (cnt[s] == 0) break;                // 没人喜欢栈顶 → 永久卡死
            --cnt[s];
        }
        return cnt[0] + cnt[1];                    // 剩下的都吃不上
    }
};
```

### Python

```python
class Solution:
    def countStudents(self, students: list[int], sandwiches: list[int]) -> int:
        cnt = [0, 0]
        for s in students:
            cnt[s] += 1
        for s in sandwiches:
            if cnt[s] == 0:              # 没人喜欢栈顶三明治 → 卡死
                break
            cnt[s] -= 1
        return cnt[0] + cnt[1]
```

> 💡 两份代码均通过全部官方示例（`0`、`3`）及 3000 组随机数据与"真队列 + 卡死检测"完整模拟的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **全部吃到 / 全部卡死**：`students = [0,0], sandwiches = [0,0]` 返回 0；`students = [0], sandwiches = [1]` 扫第一个就 break，返回 1。两种极端都由同一循环覆盖，无需特判。
2. **中途才卡死**：卡死位置之前的三明治必须先消费掉计数——计数法天然按栈序处理，若先扫 `students` 再扫 `sandwiches` 的顺序写反不影响（两者独立），但扫描 `sandwiches` 必须从**栈顶（下标 0）**开始。
3. **别用 `continue`**：见 §4.1，见到 `cnt[s] == 0` 只能停，不能跳——这正是本题最经典的错误。
4. **模拟法的卡死检测**：若写模拟，"放弃次数达到队列长度"才停；只判"一次放弃"会提前退出。
5. **数据范围陷阱不存在**：$n \le 100$ 极小，但计数法是 $O(n)$ 的，即使 $n = 10^6$ 也稳。
