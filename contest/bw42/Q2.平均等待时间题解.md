# LeetCode 平均等待时间 题解

## 1. 题目概述

- **标题 / 题号**：平均等待时间（#1701，medium）
- **链接**：https://leetcode.cn/problems/average-waiting-time/
- **来源**：LeetCode 第 42 场双周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：餐厅只有一位厨师。顾客数组 $customers[i] = [arrival_i, time_i]$，到达时间**非递减**。顾客到达即下单，厨师**一空闲就开始做**，**同时只能做一单**，且严格**按下单顺序**做菜。每位顾客从到达到拿到菜的时间是他的等待时间。返回所有顾客等待时间的平均值。

**约束**：

- $1 \le n \le 10^5$
- $1 \le arrival_i, time_i \le 10^4$
- $arrival_i \le arrival_{i+1}$

**与正确答案误差 $10^{-5}$ 以内皆可**。

## 2. 示例

**示例 1**

```text
输入：customers = [[1,2],[2,5],[4,3]]
输出：5.00000
解释：顾客1 在 1 开始、3 完成，等待 2；顾客2 在 3 开始、8 完成，等待 6；
      顾客3 在 8 开始、11 完成，等待 7。平均 (2+6+7)/3 = 5。
```

**示例 2**

```text
输入：customers = [[5,2],[5,4],[10,3],[20,1]]
输出：3.25000
解释：四位顾客的等待分别为 2、6、4、1，平均 13/4 = 3.25。
```

**示例 3（边界补充：所有顾客同时到达）**

```text
输入：customers = [[3,1],[3,1],[3,1]]
输出：2.00000
解释：三位顾客的完成时刻为 4、5、6，等待 1、2、3，平均 2。
```

## 3. 解题思路

### 3.1 暴力思路

本题"暴力"与正解同构——因为厨师行为完全确定（无任何决策空间：顺序固定、空闲即做），直接逐位顾客模拟就是正确算法。真正的风险点只有两个：一是**状态维护错误**（如忘记厨师空闲时"顺延到顾客到达时刻"），二是**精度与溢出**（累加用浮点或 `int` 溢出）。

### 3.2 核心观察：开始时刻 = max(厨师空闲时刻, 顾客到达时刻)

![核心观察：开始时刻取 max(空闲, 到达)，两种情形](images/bw42_q2_timeline.svg)

厨师同一时刻只做一单且顺序固定，于是第 $i$ 位顾客的做菜**开始时刻**只有两种可能：

- 厨师在他到达时已空闲（上一单完成 $\le arrival_i$）：立刻开始，等待 = $time_i$；
- 厨师还忙（上一单完成 $> arrival_i$）：等待到空闲才开始，等待 = $freeAt - arrival_i + time_i$。

统一成一行：$start_i = \max(freeAt, arrival_i)$，$finish_i = start_i + time_i$，$wait_i = finish_i - arrival_i$，随后 $freeAt \leftarrow finish_i$。**一个变量 `freeAt` 贯穿全程**，无需任何数组。

### 3.3 算法流程

![算法流程：单变量 freeAt 滚动推进](images/bw42_q2_flow.svg)

```text
1. freeAt = 0（厨师初始空闲），totalWait = 0
2. 对每位顾客 (arrival, t)：
       start  = max(freeAt, arrival)
       finish = start + t
       totalWait += finish − arrival
       freeAt = finish
3. 返回 totalWait / n
```

### 3.4 示例演算

以示例 2 为例（$freeAt$ 初值 0）：

| 顾客 | arrival | time | start = max(freeAt, arrival) | finish | wait = finish − arrival |
|------|---------|------|------------------------------|--------|--------------------------|
| 1 | 5 | 2 | max(0,5) = 5 | 7 | 2 |
| 2 | 5 | 4 | max(7,5) = **7** | 11 | 6 |
| 3 | 10 | 3 | max(11,10) = **11** | 14 | 4 |
| 4 | 20 | 1 | max(14,20) = 20 | 21 | 1 |

总等待 $13$，平均 $13/4 = 3.25$ ✓。注意第 1 位顾客做完厨师已空闲到 14，第 3 位顾客 10 到达仍要等到 11；第 4 位顾客 20 才到，厨师从 14 闲到 20，他不用等。

## 4. 算法细节

1. **`freeAt` 初值取 0**：$arrival_i \ge 1$，第一位顾客必然"立即开始"；取 0 或 $-\\infty$ 等价（也可直接初始化为第一位顾客的到达时刻）。
2. **整数累加，最后再除**：等待总和最大约 $n \times (arrival + \sum time) \approx 10^5 \times (10^4 + 10^9)$——精确算：$\sum wait_i \le \sum (finish_i - arrival_i)$，$finish$ 至多 $10^4 + 10^5 \times 10^4 \approx 10^9$，总和 $\le 10^{14}$，`int` 必溢出，C++ 用 `long long` 累加；浮点累加则可能损失精度（$10^{14}$ 量级下 `double` 尚有 15~16 位有效数字，勉强够但没必要冒险）。
3. **返回值类型**：LeetCode 接口返回 `double`，整数累加后一次除法转 `double`，误差仅最后一次舍入，远小于 $10^{-5}$。
4. **`arrival` 非递减不是必需条件**：即使乱序到达（题目保证不会），"按数组顺序做菜"的规则下本算法依然正确——`max` 天然处理"先来的订单堵住后来的"。
5. **无需优先队列**：没有"选哪单先做"的决策，别惯性思维套堆。

## 5. 正确性证明

**引理 1（开始时刻公式）**：按题目规则，第 $i$ 位顾客做菜的开始时刻 $start_i = \max(finish_{i-1}, arrival_i)$（约定 $finish_0 = 0$），且 $finish_i = start_i + time_i$。

**证明**：厨师按下单顺序做菜且同时只做一单，故第 $i$ 单最早能开始于第 $i-1$ 单完成时刻 $finish_{i-1}$；又不能早于顾客到达 $arrival_i$，故 $start_i \ge \max(finish_{i-1}, arrival_i)$。另一方面，"厨师一旦空闲就开始做"意味着 $start_i$ 取到该下界：若 $finish_{i-1} \ge arrival_i$，厨师完成上一单即刻开始第 $i$ 单（订单已在等），$start_i = finish_{i-1}$；否则顾客到达时厨师空闲，立即开始，$start_i = arrival_i$。两种情形都取等号。∎

**定理**：算法返回的 totalWait$/n$ 等于真实的平均等待时间。

**证明**：第 $i$ 位顾客的等待定义为"从到达到拿到菜"，即 $wait_i = finish_i - arrival_i$。对 $i$ 归纳：算法维护的 $freeAt$ 在处理完第 $i$ 位后等于 $finish_i$（基础：$freeAt = 0 = finish_0$；归纳步：由引理 1，`start = max(freeAt, arrival)` 计算出的正是真实 $start_i$，`finish` 与更新后的 `freeAt` 即真实 $finish_i$）。故累加的每个 $wait_i$ 与真实值一致，平均值亦然。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每位顾客常数次比较与加减。
- **空间**：$O(1)$ 辅助（仅 `freeAt`、`totalWait` 两个变量），不随输入规模增长。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    double averageWaitingTime(vector<vector<int>>& customers) {
        long long totalWait = 0;
        long long freeAt = 0;                      // 厨师完成上一单的时刻
        for (const auto& c : customers) {
            long long start = max(freeAt, (long long)c[0]);   // 开始做菜的时刻
            long long finish = start + c[1];
            totalWait += finish - c[0];            // 等待 = 完成 − 到达
            freeAt = finish;
        }
        return (double)totalWait / (double)customers.size();
    }
};
```

### Python

```python
class Solution:
    def averageWaitingTime(self, customers: list[list[int]]) -> float:
        total_wait = 0
        free_at = 0                       # 厨师完成上一单的时刻
        for arrival, t in customers:
            start = max(free_at, arrival)
            finish = start + t
            total_wait += finish - arrival
            free_at = finish
        return total_wait / len(customers)
```

> 💡 两份代码均通过全部官方示例（`5.00000`、`3.25000`）及 3000 组随机数据与独立重算（逐步记录完成时刻再汇总）对拍，误差 0，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：只有一位顾客，等待恰为 $time_1$（他到达即开始），公式自动成立。
2. **同时到达**：$arrival$ 相同的顾客排队依次做，后到者等待累加——`max` 保证不会"插队"（见示例 3）。
3. **厨师长闲**：$arrival_i$ 很大时 `max` 取 $arrival_i$，`freeAt` 向后**跳变**而非线性累加——若错误地写成 `freeAt += time_i`（无条件累加）会把空闲时间也计入等待，示例 2 第 4 位顾客会算错。
4. **溢出**（C++）：总等待可达 $10^{14}$ 量级，`int` 累加必然溢出（UB），必须 `long long`；`(long long)c[0]` 的强转要在 `max` 之前，避免 `int` 与 `long long` 混合比较的告警。
5. **精度**：整数路径 + 最终一次除法是最稳的；若全程 `double` 累加，$10^{14}$ 量级下单步舍入误差可能累积到 $10^{-2}$ 级——题面允许 $10^{-5}$ 误差，侥幸能过但属"踩线"，不推荐。
6. **平均值分母是 $n$（顾客数）**，不是 $n-1$（不要手滑写成样本均值）。
