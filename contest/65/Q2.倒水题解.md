# LeetCode 倒水 题解

## 1. 题目概述

- **标题 / 题号**：倒水（#755，medium）
- **链接**：https://leetcode.cn/problems/pour-water/
- **来源**：LeetCode 第 65 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：给定高度数组 `heights`，`heights[i]` 是第 $i$ 列的地形高度（每列宽度为 1）。把 $V$ 单位水依次从下标 $K$ 正上方滴下。每滴水先落在第 $K$ 列的顶部，然后按优先级流动：

1. 如果向左移动能**最终落到底部更低的位置**，就向左移动；
2. 否则如果向右能最终落到更低处，就向右移动；
3. 否则在当前位置抬升一格。

求 $V$ 单位水全部滴完后的高度数组。

**约束**：

- $1 \le \text{heights.length} \le 100$
- $0 \le \text{heights}[i] \le 99$
- $0 \le V \le 2000$
- $0 \le K \le \text{heights.length} - 1$
- 水不可分割：每单位水必须完整落在某一列，不会摊平到多列
- 数组左右边界外视为无限高的地形，水不会溢出边界

## 2. 示例

**示例 1**

```text
输入：heights = [2,1,1,2,1,2,2], V = 4, K = 3
输出：[2,2,2,3,2,2,2]
解释：4 单位水依次落到列 2、列 1、列 4，最后一滴无处可落，抬升列 3。
```

**示例 2**

```text
输入：heights = [1,2,3,4], V = 2, K = 2
输出：[2,3,3,4]
解释：第一滴向左滑到列 0；第二滴停在列 1 —— 再往左是等高的列 0，
      不会"最终落到更低处"，所以停在列 1 抬升。
```

**示例 3**

```text
输入：heights = [3,1,3], V = 5, K = 1
输出：[4,4,4]
解释：前 3 滴原地抬升列 1 至 4；第 4 滴向左落到列 0，第 5 滴向右落到列 2。
```

## 3. 解题思路

### 3.1 暴力思路

按题面字面模拟：每滴水从 $K$ 出发，每次只向左或向右挪一格，每挪一格都重新朝该方向扫描到边界来判断"继续走是否最终会落得更低"。单滴的判断是 $O(n)$、最多挪 $n$ 格，总量 $O(Vn^2)$；若把每一格水都展开成二维网格再做状态搜索，还会再乘一个高度因子。

$Vn^2 \le 2 \times 10^7$ 在本题范围内勉强能过，但存在大量重复计算：同一段"越往左越矮"的结构在相邻两滴之间被反复扫描。而这层结构其实一次扫描就能完整读出来。

### 3.2 核心观察：落点是不增链上"最靠右的最小值"

![不增链与最靠右的最小值](images/wc65_q2_min_chain.svg)

把当前高度数组记作 $h$（**已经包含**先前落下的水）。水滴在列 $c$ 上时，它的底部位于第 $h[c]$ 行，于是：

- 能否向左滚一格？可以 $\iff$ 左邻列在第 $h[c]$ 行是空的 $\iff h[c-1] \le h[c]$；
- 滚过去之后它落到那一列的底部，底部行变成 $h[c-1]$，只会更低或等高。

因此从 $K$ 向左能到达的列恰好是一个连续区间 $[L, K]$，并满足

$$h[L] \le h[L+1] \le \cdots \le h[K]$$

（越往左越矮或等高）；再往左一格就被"墙" $h[L-1] > h[L]$ 挡住（或已到边界）。这段区间称为**不增链** —— 沿下标增大方向高度不减，反过来从 $K$ 往左看则一路不增。

由此得到两条关键结论：

1. **水滴只会停在一处**：向左滚时底部行单调不增，第一次踩到链上的最小值 $h[L]$ 就停住 —— 再往左全是等高或更高的列，不会"最终落到更低处"。所以落点是**最靠右的那个最小值位置**，而不是最左端的 $L$。
2. **严格更低才值得滚**：若该最小值 $< h[K]$，向左就一定"最终落到更低处"，规则 1 必然触发；若最小值 $= h[K]$，左侧没有任何更低的列，规则 1 不触发，转去判断右侧。

> 💡 这条观察把一个"逐格滚动"的物理过程压成了"在一条不增链上找最靠右的最小值"，一次线性扫描就够，不必一格一格挪。示例 2 的第 2 滴正是"停在前一个最小值"而非最左端：$h=[2,2,3,4]$、$K=2$，左链一直延伸到列 0 都还是高度 2，于是停在列 1。

### 3.3 算法流程 / 状态转移

![每滴水的判定流程](images/wc65_q2_algorithm_flow.svg)

对每一单位水（共 $V$ 轮），执行：

1. **向左扫描**：令 `best = K`、`i = K-1`；当 $i \ge 0$ 且 $h[i] \le h[i+1]$ 时，若 $h[i] < h[\text{best}]$ 则 `best = i`，然后 `i -= 1`。循环结束时 `best` 即最靠右的最小值位置。
2. **向左判定**：若 $h[\text{best}] < h[K]$，落点就是 `best`，执行 `h[best] += 1`，本轮结束。
3. **向右扫描（对称）**：令 `best = K`、`i = K+1`；当 $i < n$ 且 $h[i] \le h[i-1]$ 时，若 $h[i] < h[\text{best}]$ 则 `best = i`，`i += 1`；若最小值 $< h[K]$，执行 `h[best] += 1`。
4. **原地抬升**：两侧都不存在更低的可达列，执行 `h[K] += 1`。

两个容易混淆的点：**链条件**用的是相邻列 `h[i+1]`（表示"能滚过去"），**更新条件**是严格小于当前 `best`（表示"取最靠右的最小值"）。前者写成 `h[i] <= h[K]` 会越过谷底之后的墙，后者写成 `<=` 会退化成最靠左的最小值。

### 3.4 示例演算

![示例 1 与示例 2 的逐滴演算](images/wc65_q2_example_walkthrough.svg)

以示例 1 的 $h=[2,1,1,2,1,2,2]$、$K=3$、$V=4$ 逐滴走查：

| 滴数 | 当前 $h$ | 左链扫描 | 右链扫描 | 落点 | 滴后 $h$ |
|------|----------|----------|----------|------|----------|
| 1 | [2,1,1,2,1,2,2] | 列 2、1 高度都是 1，列 0 高度 2 挡住 | — | 列 2 | [2,1,2,2,1,2,2] |
| 2 | [2,1,2,2,1,2,2] | 列 2 等高，列 1 更低（1） | — | 列 1 | [2,2,2,2,1,2,2] |
| 3 | [2,2,2,2,1,2,2] | 左链全为 2，无严格更低 | 列 4 高度 1 | 列 4 | [2,2,2,2,2,2,2] |
| 4 | [2,2,2,2,2,2,2] | 全等高 | 全等高 | 列 3（原地） | [2,2,2,3,2,2,2] |

第 1 滴与第 2 滴都向左，但落点从列 2 换到列 1：第 2 滴时列 2 已被填到 2，与 $h[3]=2$ 等高，最靠右的最小值随之前移到列 1 —— 这就是"每滴都要重新扫描"的原因。

再看示例 2 的第 2 滴：$h=[2,2,3,4]$、$K=2$。左邻列高度 2 比 3 低，水滴滚过去落到列 1 顶部（高度 2）；此时左边列 0 也是 2，再往左是边界，**没有严格更低的列**，于是停在列 1 抬升为 3，得到 `[2,3,3,4]`。

## 4. 算法细节

1. **一个数组就够了**：`heights` 本身就是"地形 + 已落下的水"，判定与更新都基于它，不要额外维护"纯地形高度"和"水量"两份数据，否则两套数据极易不同步。
2. **扫描条件写相邻列**：`while i >= 0 and h[i] <= h[i+1]` 表达的是"从 $i+1$ 能滚到 $i$"；写成 `h[i] <= h[K]` 会让水滴越过谷底左侧的墙。
3. **取最靠右的最小值**：只在 `h[i] < h[best]` 时更新 `best`，等号不更新。用 `<=` 会得到 [3,2,3,4]（示例 2 的经典错误答案）。
4. **比较基准是 `h[K]`**：判定的是"链上最小值是否严格小于水滴起点列的高度"，不是 `h[best]`，也不是上一滴的落点列高度。
5. **左优先**：两侧都有严格更低的列时必须先看左（题面顺序）。代码用"先扫左、命中即跳过右扫描"的 `if / else` 结构保证。
6. **每滴只改一列**：水不可分割，不存在半格分摊；`h[drop] += 1` 之后直接进入下一滴，天然保证下一步判定读到的是最新水位。
7. **越界即墙**：`i >= 0` 与 `i < n` 同时承担"边界"和"无限高地形"两种角色，不需要哨兵值。
8. **下标变量用整型**：$n \le 100$、$V \le 2000$，无需长整型；但循环里 `i` 递减到 $-1$ 再退出，注意别用无符号类型。

## 5. 正确性证明

固定某一滴落下前的数组 $h$ 与落点列 $K$。称区间 $[j, K]$ 为**不增链**，若对一切 $i \in [j, K-1]$ 都有 $h[i] \le h[i+1]$。

**引理 1（左可达性）**：水滴从 $K$ 向左能到达的列恰好是最大的不增链 $[L, K]$；到达列 $c$ 时其底部位于第 $h[c]$ 行。

**证明**：对移动步数归纳。水滴落在 $K$ 顶部时底部行是 $h[K]$。设它在列 $c$ 的底部行为 $h[c]$，向左滚一格到 $c-1$ 要求第 $h[c]$ 行在列 $c-1$ 上为空，即 $h[c-1] \le h[c]$，滚过去后落到该列底部，底部行变为 $h[c-1]$。因此可达性恰由链条件刻画，$L$ 由"再往左一格即被 $h[L-1] > h[L]$ 挡住或已出界"唯一确定。∎

**引理 2（落点判定）**：令 $p = \max\{i \in [L, K] : h[i] = h[L]\}$（最靠右的最小值位置），则

- 若 $h[L] < h[K]$，水滴沿左侧滚动的终点恰为 $p$，且停在 $p$ 后左右两个方向都不会再"最终落到更低处"；
- 若 $h[L] = h[K]$，左侧不存在严格更低的列，规则 1 不触发。

**证明**：由引理 1，链上高度按下标单调不减，故 $h[L]$ 是链上最小值。向左滚时底部行单调不增，只有踩到严格更低的行才算"最终落下去"。到达 $p$ 时底部行为 $h[p] = h[L]$，是链上最小：继续向左只会遇到等高的列（一直到 $L$，再往左被墙挡住），不会严格下降，故左侧不再触发规则 1。若此时转向右：$[p, K]$ 上的高度均 $\ge h[L]$，而 $h[K] > h[L]$，越过等高段后必被高于 $h[L]$ 的列挡住，同样不会严格下降。所以停点唯一为 $p$。若 $h[L] = h[K]$，链上各列高度全等于 $h[K]$，向左每一步都不下降，"最终落到更低处"不成立，规则 1 不触发。∎

**定理**：算法为每单位水选出的落点与题面定义的物理过程一致，故 $V$ 轮后的数组即为答案。

**证明**：对 $V$ 归纳。$V = 0$ 时数组不变，成立。设前 $t$ 滴后的数组与物理过程一致，记为 $h$，考虑第 $t+1$ 滴：

- 若 $h[L] < h[K]$：由引理 2，水滴必然向左并停在 $p$，算法第 1、2 步恰好把 $h[p]$ 加一；
- 若 $h[L] = h[K]$ 且右侧最小值 $< h[K]$：对右侧套用对称的引理 2，落点为算法第 3 步的 `best`；
- 若左右两侧最小值都等于 $h[K]$：两个方向都不存在更低的列，题面规定"在当前位置抬升"，算法第 4 步执行 $h[K] \mathrel{+}= 1$。

三种情形互斥且穷尽，落点与题面一致，故第 $t+1$ 滴后仍一致。∎

## 6. 复杂度分析

- **时间**：$O(V \cdot n)$。每单位水做一次左扫（至多 $n$ 列）和一次右扫（至多 $n$ 列），每次比较 $O(1)$；总计不超过 $2Vn \le 4 \times 10^5$ 次比较。相比逐格模拟的 $O(Vn^2)$，省掉了"每挪一格重新扫描"的重复开销。
- **空间**：$O(1)$（不计结果数组）。原地修改 `heights`，只需 `i`、`best`、`drop` 等常数个下标变量；若不希望改动输入，可复制一份数组，空间变为 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> pourWater(vector<int>& heights, int volume, int k) {
        int n = (int)heights.size();
        for (int t = 0; t < volume; ++t) {
            int drop = k;

            // 向左：沿"高度不增"的链，找最靠右的最小值
            int best = k;
            for (int i = k - 1; i >= 0 && heights[i] <= heights[i + 1]; --i) {
                if (heights[i] < heights[best]) best = i;
            }
            if (heights[best] < heights[k]) {
                drop = best;                      // 左侧有严格更低的列，优先向左
            } else {
                // 向右：对称扫描，注意落点同样取最靠右的最小值
                best = k;
                for (int i = k + 1; i < n && heights[i] <= heights[i - 1]; ++i) {
                    if (heights[i] < heights[best]) best = i;
                }
                if (heights[best] < heights[k]) drop = best;
            }

            ++heights[drop];
        }
        return heights;
    }
};
```

### Python

```python
class Solution:
    def pourWater(self, heights: List[int], volume: int, k: int) -> List[int]:
        n = len(heights)
        for _ in range(volume):
            drop = k

            # 向左：沿"高度不增"的链，找最靠右的最小值
            best = k
            i = k - 1
            while i >= 0 and heights[i] <= heights[i + 1]:
                if heights[i] < heights[best]:
                    best = i
                i -= 1

            if heights[best] < heights[k]:
                drop = best                       # 左侧有严格更低的列，优先向左
            else:
                # 向右：对称扫描，落点同样取最靠右的最小值
                best = k
                i = k + 1
                while i < n and heights[i] <= heights[i - 1]:
                    if heights[i] < heights[best]:
                        best = i
                    i += 1
                if heights[best] < heights[k]:
                    drop = best

            heights[drop] += 1

        return heights
```

> 说明：`List` 来自 `typing`，LeetCode 的 Python 环境已自动导入；本地运行时补一句 `from typing import List` 即可。

## 8. 边界情况与易错点

1. **"停在前一个最小值"而不是最左端**：$h=[2,2,3,4]$、$K=2$ 的第 2 滴应停在列 1。把 `best` 更新条件写成 `<=`，或直接拿最左端 $L$ 当落点，都会得到 `[3,2,3,4]` 这类错误答案。
2. **`V = 0`**：一滴也不倒，直接返回原数组；循环体一次都不进，不要漏掉这个分支。
3. **`n = 1`**：左右都越界，每滴只能原地抬升，答案为 $[h_0 + V]$；此时左扫的 `i = -1` 立即退出，天然正确。
4. **`K` 在两端**：$K = 0$ 时左扫立刻结束，只能向右或原地；$K = n-1$ 对称。判越界要在访问 `heights[i]` 之前完成，避免负下标被 Python 解释成"从末尾数"。
5. **两侧都有更低列**：必须优先向左。例如 $h=[1,9,1]$、$K=1$、$V=1$，正确答案是 `[2,9,1]`。
6. **把"等高"误当成"能落下去"**：等高只代表"能滚过去"，滚过去后若不再遇到更低的列就必须停；判定用的永远是**严格更低**。
7. **一次性算完再修正的写法不可行**：每滴都会改变地形，进而改变下一条链的形状，必须逐滴重算。
