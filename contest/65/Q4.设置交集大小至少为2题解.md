# LeetCode 设置交集大小至少为2 题解

## 1. 题目概述

- **标题 / 题号**：设置交集大小至少为2（#757，hard）
- **链接**：https://leetcode.cn/problems/set-intersection-size-at-least-two/
- **来源**：LeetCode 第 65 场周赛 Q4
- **难度**：困难
- **标签**：贪心，数组，排序

**题意**：给定若干闭整数区间 $[start_i, end_i]$，求最小的整数集合 $nums$ 的大小，使得**每个**区间都至少包含 $nums$ 中的 **2** 个整数。只输出大小，不要求输出具体集合。

**约束**：

- $1 \le intervals.length \le 3000$
- $intervals[i].length = 2$
- $0 \le start_i < end_i \le 10^8$

注意 $start_i < end_i$ 意味着每个区间自身至少含两个整数，因此问题一定有解，且答案在 $[2, 2n]$ 之间。

## 2. 示例

**示例 1**

```text
输入：intervals = [[1,3],[3,7],[8,9]]
输出：5
解释：nums = [2,3,4,8,9]。可以证明不存在大小为 4 的包含集合。
```

**示例 2**

```text
输入：intervals = [[1,3],[1,4],[2,5],[3,5]]
输出：3
解释：nums = [2,3,4]。只选 2 个点时，两点必须同时落在 [1,3] 与 [3,5] 中，
      而这两个区间只共享整数 3，容纳不下两个不同的点，故 2 不可行。
```

**示例 3**

```text
输入：intervals = [[1,2],[2,3],[2,4],[4,5]]
输出：5
解释：nums = [1,2,3,4,5]。[1,2] 强制取 1、2，[4,5] 强制取 4、5，[2,3] 还需要 3，故至少要 5 个点。
```

## 3. 解题思路

### 3.1 暴力思路

坐标值域高达 $10^8$，无法按坐标开数组做 DP。把每个候选整数看成「覆盖一组区间」的向量，问题就变成「每个区间至少被覆盖 2 次」的带下界集合覆盖，一般图上是 NP-hard；即使候选点只有 $O(n)$ 个，状态也要记录每个区间已覆盖 $0/1/2$ 个点，共 $3^n$ 种，$n = 3000$ 时完全不可行。

暴力唯一的价值是**对小数据对拍**：把候选点限制在 $[\min start, \max end]$ 内的整数，用 $3^n$ 状态的 DP 求精确答案（本文验证脚本即如此）。正解必须利用「区间」这一强结构。

### 3.2 核心观察：按右端点排序，只记最大的两个已选点

![只需盯住最大的两个已选点](images/wc65_q4_last_two_points.svg)

把区间按**右端点升序**（右端点相同时按**左端点降序**）排列，从左往右扫描。贪心只在当前区间内加点，而当前区间的右端点 $e$ 单调不减，所以**已选点全部 $\le e$**。于是处理 $[s,e]$ 时，「区间内有几个已选点」只取决于已选点中最大的两个 $a < b$：

- $s \le a$：$a, b$ 都满足 $s \le a < b \le e$，两点都在区间内，**跳过**；
- $a < s \le b$：只有 $b$ 在区间内，**补 1 个点**，取最靠右的 $e$；
- $s > b$：两个点都不在，**补 2 个点**，取 $e-1$ 与 $e$。

**为什么加点总选最靠右的位置？** 设已选点集为 $S$，当前区间右端点为 $e$。把某个 $q < e$（$q \notin S$）换成 $e$ 后：

- 已处理过的区间本来就含 $S$ 中 2 个点，而 $q \notin S$，所以不受影响；
- 尚未处理的区间右端点 $e_J \ge e$，若 $q \in J$ 则 $s_J \le q < e \le e_J$，故 $e \in J$。

也就是说，**把区间内偏左的点右移到区间右端点 $e$，永远不会破坏任何区间的覆盖**。这提示我们：每次必须加点时，就取当前区间最靠右的点，把「覆盖能力」尽可能留给后面的区间。

之所以「只记两个点」就够：设 $c \le a$ 是某个更小的已选点。若当前区间满足 $s > a$，则 $s > a \ge c$，$c$ 同样不在区间内；若 $s \le a$，则 $a, b$ 两点都已在区间内，要求已经满足。因此更小的点不会改变任何一种判定的结果。

### 3.3 算法流程

![贪心流程](images/wc65_q4_algorithm_flow.svg)

1. 将区间按 $(end_i,\,-start_i)$ 升序排序；
2. 维护 `ans = 0`，以及已选点中最大的两个 $a < b$，初值置 $-1$（因为 $start_i \ge 0$）；
3. 依次取出区间 $[s,e]$，按上面三种情况更新：
   - 情况 1：什么都不做；
   - 情况 2：$a \leftarrow b,\ b \leftarrow e,\ ans \leftarrow ans+1$；
   - 情况 3：$a \leftarrow e-1,\ b \leftarrow e,\ ans \leftarrow ans+2$；
4. 扫描结束后返回 `ans`。

### 3.4 示例演算

![示例 2 走查](images/wc65_q4_walkthrough.svg)

以示例 2 为例，排序后顺序为 $[1,3] \to [1,4] \to [3,5] \to [2,5]$（注意 $[3,5]$ 与 $[2,5]$ 右端点相同，起点大的先处理）：

| 步骤 | 区间 | 判定 | 动作 | $(a,b)$ | ans |
|------|------|------|------|---------|-----|
| ① | $[1,3]$ | 均不在 | 取 $2,3$ | $(2,3)$ | 2 |
| ② | $[1,4]$ | $1 \le 2$ | 跳过 | $(2,3)$ | 2 |
| ③ | $[3,5]$ | 仅 $b=3$ 在内 | 取 $5$ | $(3,5)$ | 3 |
| ④ | $[2,5]$ | $2 \le 3$ | 跳过 | $(3,5)$ | 3 |

最终选点 $\{2,3,5\}$（答案 3）；官方示例给出的 $\{2,3,4\}$ 同样最优，说明最优集合本身并不唯一。

## 4. 算法细节

1. **排序键必须是 $(end_i, -start_i)$**：右端点升序是贪心的骨架；右端点相同时按左端点**降序**，是为了让更窄（更靠右）的区间先被满足。若同右端点用左端点升序，$a$ 与 $b$ 可能取到同一个点，后续判定会凭空多算一个点（见 §8 的反例）。
2. **$a, b$ 的初值取 $-1$**：因为 $start_i \ge 0$，所以 $s \le a$ 与 $s \le b$ 都不会被误触发，第一次一定走情况 3。若坐标允许负数，应改为 $-\infty$。
3. **情况 2 补 $e$ 而不是 $e-1$**：$b$ 已在区间内，第二个点必须落在 $[s,e]$ 中且越靠右越好，$e$ 是唯一的最优选择。
4. **情况 3 取 $e-1$ 与 $e$**：由 $start_i < end_i$ 知 $s \le e-1$，两点都在区间内；不能取 $e-2, e-1$，否则后续区间更容易缺覆盖。
5. **跳过时不要更新 $a,b$**：$a<b\le e$ 且两点都在 $[s,e]$ 内，$b$ 仍是「最大的已选点」，更新反而会丢失信息。
6. **只维护计数**：不需要真的把点存进 `set` 再去重计数，那会把复杂度抬到 $O(n\log n)$ 且容易写错；每个点只会在被选中的那次计入，天然不重复。
7. **整数范围**：坐标 $\le 10^8$、答案 $\le 2n = 6000$，`int` 足够；$e-1$ 也不会下溢（$e \ge 1$）。

## 5. 正确性证明

**引理 1（右移不亏）**：设当前处理区间 $I=[s,e]$，$S$ 为贪心已选点集，且所有已处理区间都至少含 $S$ 中 2 个点。设 $T \supseteq S$，$q \notin S$ 且 $q < e$，令 $T' = (T \setminus \{q\}) \cup \{e\}$。则（i）每个已处理区间在 $T'$ 中仍至少含 2 个点；（ii）每个未处理区间 $J=[s_J,e_J]$，若 $q \in J$ 则 $e \in J$。

**证明**：（i）已处理区间含 $S$ 的 2 个点，而 $S \subseteq T'$（由 $q \notin S$）。（ii）未处理区间满足 $e_J \ge e$；$q \in J$ 给出 $s_J \le q < e \le e_J$，故 $e \in J$。∎

**引理 2（不变量）**：扫描过程中恒有 $a < b$ 且 $b \le e$（$e$ 为当前区间右端点）；同一右端点的区间中，只有第一个可能新增点，其余必然命中情况 1。

**证明**：$b$ 取自某个右端点 $\le e$ 的区间，故 $b \le e$。$a<b$：情况 3 直接得到 $a = e-1 < e = b$；情况 2 需要 $b_{\text{old}} < e$，若 $b_{\text{old}} = e$，说明之前已有右端点为 $e$ 的区间贡献了点 $e$，而同一右端点的第一个区间 $[s_1,e]$ 处理完后必有 $a \ge s_1$（情况 3：$a = e-1 \ge s_1$；情况 2：$a = b_{\text{old}} \ge s_1$ 正是进入该分支的条件；情况 1：$a \ge s_1$ 即判定本身），随后同右端点的区间 $s < s_1 \le a$ 必命中情况 1，不可能再进入情况 2，矛盾。故后一句成立，$b_{\text{old}} < e$，$a = b_{\text{old}} < e = b$。∎

**引理 3（贪心可行）**：每个区间被处理完时，$S$ 在它内部至少有 2 个点。

**证明**：情况 1 由 $s \le a$ 及 $a<b\le e$，$a,b \in [s,e]$；情况 2 有 $b \in [s,e]$（$b \ge s$ 是该分支条件）且新加 $e \in [s,e]$；情况 3 新加 $e-1, e$，由 $s < e$ 得 $s \le e-1$，两点都在区间内。∎

**引理 4（可嵌入最优解）**：贪心每执行一步后，都存在全实例的最优解 $O$ 使 $S \subseteq O$。

**证明**：对步数归纳，$S=\emptyset$ 时取任一最优解。设当前 $S \subseteq O$，当前区间为 $I=[s,e]$，按分支讨论：

- 情况 1：$S$ 不变，结论保持。
- 情况 2：$S \cap I = \{b\}$，而 $O$ 可行，故存在 $q \in O \cap I$ 且 $q \notin S$。若 $q=e$，则 $S \cup \{e\} \subseteq O$；否则 $q<e$，由引理 1 得 $O' = (O \setminus \{q\}) \cup \{e\}$ 仍可行（$I$ 由 $b$ 与 $e$ 覆盖，其余由引理 1 保证），且 $|O'| = |O|$、$S \cup \{e\} \subseteq O'$，故 $O'$ 仍是（同大小的）最优解。
- 情况 3：$S \cap I = \emptyset$，取 $O \cap I$ 中两点 $p < q$（均 $\notin S$）。若 $p = e-1$ 则 $e-1 \in O$，只需把 $q$ 换成 $e$；否则 $p \le e-2$。先对 $q$ 用引理 1 换成 $e$，再对 $p$ 用引理 1 换成 $e-1$（未处理区间满足 $s_J \le p < e-1 \le e_J$），得到与 $O$ 同大小、可行、并包含 $S \cup \{e-1,e\}$ 的解。∎

**定理**：贪心返回的 `ans` 就是最优大小 $OPT$。

**证明**：由引理 3，贪心输出是可行解，故 $|S| \ge OPT$；由引理 4（最后一步），存在最优解 $O$ 满足 $S \subseteq O$，故 $|S| \le |O| = OPT$。两者合并得 $|S| = OPT$。∎

## 6. 复杂度分析

- **时间**：$O(n\log n)$。排序占主导；扫描每个区间只做常数次比较与赋值，$O(n)$。
- **空间**：$O(1)$ 额外空间（不计排序）。只维护 $a,b,ans$ 三个整数；C++ 的 `std::sort` 需要 $O(\log n)$ 栈空间，Python 的 `sorted` 需要 $O(n)$ 的列表副本。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int intersectionSizeTwo(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end(), [](const vector<int>& x, const vector<int>& y) {
            if (x[1] != y[1]) return x[1] < y[1];   // 右端点升序
            return x[0] > y[0];                      // 右端点相同则左端点降序
        });

        int ans = 0;
        int a = -1, b = -1;                          // 已选点中最大的两个，a < b
        for (const auto& in : intervals) {
            int s = in[0], e = in[1];
            if (s <= a) {
                continue;                            // a、b 都在 [s, e] 内
            } else if (s <= b) {
                a = b;                               // 只有 b 在区间内
                b = e;                               // 补最靠右的一个点
                ans += 1;
            } else {
                a = e - 1;                           // 两点都不在区间内
                b = e;                               // 补 e-1 与 e
                ans += 2;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def intersectionSizeTwo(self, intervals: list[list[int]]) -> int:
        # 右端点升序；右端点相同时左端点降序
        intervals = sorted(intervals, key=lambda x: (x[1], -x[0]))

        ans = 0
        a, b = -1, -1                    # 已选点中最大的两个，a < b
        for s, e in intervals:
            if s <= a:                   # a、b 都在区间内
                continue
            elif s <= b:                 # 只有 b 在区间内，补一个最靠右的点
                a, b = b, e
                ans += 1
            else:                        # 两个点都不在，补 e-1 与 e
                a, b = e - 1, e
                ans += 2
        return ans
```

## 8. 边界情况与易错点

1. **最小规模**：`[[0,1]]` 必须返回 2。此时走情况 3，取 $e-1=0$ 与 $e=1$，恰好合法。
2. **同右端点必须按左端点降序**：反例 `[[2,4],[3,4],[0,5],[4,5],[1,2]]`（正确答案 5）。若用左端点升序，顺序变成 `[1,2] → [2,4] → [3,4] → [0,5] → [4,5]`：处理 `[2,4]` 后 $(a,b)=(2,4)$，再处理 `[3,4]` 又命中情况 2，得到 $(a,b)=(4,4)$——$a$ 与 $b$ 退化成同一个点，实际只有 $\{1,2,4\}$ 三个点却记成 4 个，于是 `[4,5]` 被误判为「已含 2 个点」而跳过，最终少数 1。
3. **情况 2 只能补 $e$**：例如 `[[1,2],[2,5],[5,9]]`，第二个区间只有 $b=2$ 在内，补 $e=5$ 得 $\{1,2,5\}$，第三个区间含 $5$，再补 $9$ 即可，共 4 个点；若补 $e-1=4$，第三个区间一个点都没有，必须补 $8,9$，答案变成 5。
4. **情况 3 必须补 $e-1$ 与 $e$**：例如 `[[0,5],[4,6]]`，第一次取 $4,5$ 后可跳过第二个区间（共 2 个点）；若取 $3,4$，第二个区间只含 4，还得再补 6，答案变成 3。
5. **$a,b$ 初值**：取 $-1$ 依赖 $start_i \ge 0$；若把初值写成 0，会漏掉含 0 的点的贡献（`[[0,1]]` 会算错）。
6. **不要用 `set` 模拟**：真实维护集合再统计大小虽然正确，但既慢又容易在「重复选同一个点」时出错；本文的计数法保证每个点只被计一次。
7. **答案上界**：最坏 $2n = 6000$，用 `int` 足够；坐标 $10^8$ 也不会让 $e-1$ 溢出。
