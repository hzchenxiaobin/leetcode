# LeetCode 插入后的最大值 题解

## 1. 题目概述

- **标题 / 题号**：插入后的最大值（#1881，medium）
- **链接**：https://leetcode.cn/problems/maximum-value-after-insertion/
- **来源**：LeetCode 第 243 场周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串

**题意**：给定一个用字符串表示的大整数 `n` 和一个数字 $x$。允许在 `n` 的十进制表示的**任意位置**插入一个 $x$（不能插在负号左边），使 `n` 的**数值**最大，返回操作后的字符串。`n` 的每位数字与 $x$ 均在 $[1,9]$ 内，`n` 可能为负。

**约束**：

- $1 \le \text{n.length} \le 10^5$
- $1 \le x \le 9$
- `n` 中每一位数字都在 $[1,9]$ 内
- `n` 表示一个有效整数；为负时以 `'-'` 开头

> 💡 本题在本仓库另有[每日题解 1881](../../solution/1801-1900/1881_插入后的最大值.md)，两篇为姊妹篇：那边侧重两套镜像规则的直觉切入、逐位扫描走查与面试问答。本篇按周赛复盘视角，聚焦**候选串「错位对齐」的严格交换论证**（引理-定理链，完整处理 $=$ 打平的传递，比每日版更形式化）、**比较符反号与 char/int 混比两大 WA 陷阱**的反例复盘，以及「一次操作最大化数字串」套路（670 交换 / 1881 插入 / 1946 突变）的沉淀。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：n = "99", x = 9
输出："999"
解释：不管把 9 插在哪里，结果都是 "999"。
```

**示例 2**

```text
输入：n = "-13", x = 2
输出："-123"
解释：所有插入结果 -213、-123、-132 中最大的是 -123。
```

**自造边界样例**

```text
输入：n = "665", x = 6
输出："6665"
解释：R0 = R1 = R2 = "6665"（窗口 [0,2) 内全为 6 = x，逐位打平），
     R3 = "6656" 更小——贪心停在首个 5 < 6 处（下标 2），无损。

输入：n = "-55", x = 5
输出："-555"
解释：数字部分全为 5 = x，四个插入位置结果同为 "-555"，
     扫描落空自然追加到末尾。
```

## 3. 解题思路

### 3.1 暴力思路：枚举全部 n+1 个插入位置

照题面模拟：枚举 $n+1$ 个插入位置，每个位置切片构造新串 $O(n)$，再取字典序最大者。总复杂度 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次字符操作，必然超时。

> ⚠️ **浪费在哪**：$n+1$ 个候选**等长**，等长串的大小由**首个不同位**一锤定音——根本不需要两两构造比较，最优位置可以被**直接锁定**。

### 3.2 核心观察：等长候选的「错位对齐」

![核心观察：候选串错位对齐，首差位定胜负](images/wc243_q2_candidate_alignment.svg)

插入不改变长度，所有候选均为 $m+1$ 位，**字典序即数值序**（负数比较绝对值串，方向翻转）。把「在位置 $i$ 插入」的结果记为

$$R_i = d_0 \cdots d_{i-1}\ x\ d_i \cdots d_{m-1}$$

任取 $i < j$，将 $R_i$、$R_j$ **逐位对齐**：公共前缀 $d_0 \cdots d_{i-1}$ 与尾部 $d_j \cdots d_{m-1}$ 逐位相同；中间窗口 $[i, j]$ 上两串分别是

$$R_i:\ (x,\ d_i,\ \cdots,\ d_{j-1}) \qquad R_j:\ (d_i,\ \cdots,\ d_{j-1},\ x)$$

——**同一批数字的滑窗里，只有 $x$ 的落点不同**。窗口内 $d_k = x$ 的位逐位打平、比较继续右移，胜负由窗口内**首个 $d_k \ne x$ 的位**决定：该位上 $R_i$ 是 $x$、$R_j$ 是 $d_k$，于是：

- **正数**（要最大）：$d_k < x$ 时 $R_i > R_j$——用 $x$ 顶掉一个更小的数字是净赚；
- **负数**（要最大 $\Leftrightarrow$ 绝对值最小）：$d_k > x$ 时 $R_i$ 绝对值更小、数值更大；
- 若窗口内 $d$ 全 $= x$，则 $R_i = R_j$（**打平无损**，这正是示例 1「插哪都一样」的原因）。

由此贪心规则呼之欲出：**正数找首个 $d_i < x$ 的位置、负数找首个 $d_i > x$ 的位置（从下标 1 起），把 $x$ 插在它前面；找不到就追加到末尾**——末位是最低位，变动损失最小。

### 3.3 算法流程

![算法流程：判符号，跳过不增益位，首个停靠点插入或末尾追加](images/wc243_q2_greedy_flow.svg)

1. **判符号**：`n[0] == '-'` 决定分支与扫描起点（负数从下标 1 起）。
2. **正数分支**：跳过所有 $d \ge x$ 的位，停在首个 $d < x$ 处或串尾。
3. **负数分支**：跳过所有 $d \le x$ 的位，停在首个 $d > x$ 处或串尾。
4. **插入**：在停靠下标处插入 $x$；`while` / `for` / `find_if` 扫到头自然落到末尾，**无需特判**。

两分支共用「跳过不增益的位、在首个增益点出手」的骨架，仅比较方向相反。

### 3.4 示例演算

![示例演算：665 插 6、-13 插 2、-55 插 5 三组走查](images/wc243_q2_example_walkthrough.svg)

**正数 `n = "665"`、`x = 6`**（跳过 $\ge 6$，找首个 $< 6$）：

| 下标 | 位 | 比较 | 动作 |
|------|----|------|------|
| 0 | 6 | $6 \ge 6$ | 跳过（在此插入与继续走结果打平） |
| 1 | 6 | $6 \ge 6$ | 跳过 |
| 2 | 5 | $5 < 6$ | **插入**：`"66" + "6" + "5"` → `"6665"` ✓ |

**负数 `n = "-13"`、`x = 2`**（跳过负号，跳过 $\le 2$，找首个 $> 2$）：

| 下标 | 位 | 比较 | 动作 |
|------|----|------|------|
| 1 | 1 | $1 \le 2$ | 跳过（在此插入使绝对值变大） |
| 2 | 3 | $3 > 2$ | **插入**：`"-1" + "2" + "3"` → `"-123"` ✓ |

**负数全打平 `n = "-55"`、`x = 5`**：两位均满足 $5 \le 5$ 跳过，扫描落空追加末尾 → `"-555"`（四个插入位置结果全同）✓

> 💡 **对照体会**：`"665"` 里前两个 $6$（$= x$）处停不停**结果相同**（打平传递）；而 `"-13"` 的 $1$（$d \le x$）处若插入，绝对值串首差位变成 $2 > 1$，绝对值变大、数值变小，必须跳过。$=$ 位与「方向不利」位在跳过条件里待遇不同（前者可停可不停，后者绝不能停）——这正是跳过条件取 $\ge$ / $\le$ 带等号的原因：等号归属无所谓，不等号方向绝不能反。

## 4. 算法细节

1. **等长性是字典序比较的前提**：所有候选长度均为 $m+1$，「字典序 = 数值序」才成立；若插入的是多位串（长度仍统一增加，性质保持），但若操作会改变各候选间的长度（如替换成变长段），该性质失效（见延伸思考）。
2. **跳过条件与目标关系「反号」**：正数要找 $d < x$ ⟺ 跳过条件 $d \ge x$；负数要找 $d > x$ ⟺ 跳过条件 $d \le x$。等号归属两可（推论见 §5），不等号方向唯一。
3. **char 直接比较**：`'0'..'9'` 的 ASCII 序与数值序一致，C++ 中把 $x$ 转成 `char('0' + x)` 后与 `n[i]` 按字符比较，省去逐位 `- '0'` 的转换。
4. **末尾兜底零特判**：C++ `find_if` 找不到返回 `end()`，`insert(end(), c)` 即末尾追加；Python `for` 扫完落到函数末行 `n + c`。兜底语义：末位是最低位，插入 $x$ 带来的数值扰动最小。
5. **负数扫描起点为 1**：从第二个字符起扫，天然满足「不能插在负号左边」。
6. **大数意识**：$10^5$ 位远超 `long long`（约 19 位），`stoi` / `int(n)` 直接越界，全程按字符串处理。

## 5. 正确性证明

记数字部分为 $d_0 d_1 \cdots d_{m-1}$（负数时 $d_0$ 从负号后起算，比较基于**绝对值串**），插入位置 $i \in [0, m]$ 的候选

$$R_i = d_0 \cdots d_{i-1}\ x\ d_i \cdots d_{m-1}$$

长度均为 $m+1$。正数情形「数值最大」即绝对值串字典序最大；负数情形「数值最大」即绝对值串字典序**最小**（数值 $= -$ 绝对值）。

**引理 1（首差位定胜负）**：设等长数字串 $A$、$B$ 长为 $L$，$t$ 为首个 $A[t] \ne B[t]$ 的下标，则 $A > B \iff A[t] > B[t]$；特别地，逐位 $A[i] \ge B[i]$（对所有 $i$）蕴含 $A \ge B$。

**证明**：$A - B = \sum_{i=0}^{L-1} (A[i] - B[i]) \times 10^{L-1-i}$。首项绝对值 $\ge 10^{L-1-t}$，而其后各项绝对值之和 $\le 9 \sum_{i>t} 10^{L-1-i} = 10^{L-1-t} - 1 < 10^{L-1-t}$，故差值符号由首个不同位唯一决定。∎

**引理 2（候选对的错位对齐）**：对 $0 \le i < j \le m$：$R_i$ 与 $R_j$ 在前缀 $[0, i)$ 与尾部 $(j, m]$ 上逐位相同；窗口 $[i, j]$ 上分别为 $(x, d_i, \cdots, d_{j-1})$ 与 $(d_i, \cdots, d_{j-1}, x)$。设 $k$ 为 $[i, j)$ 内首个 $d_k \ne x$ 的下标，则：

- (a) 若 $k$ 不存在（窗口内 $d$ 全 $= x$），则 $R_i = R_j$；
- (b) 若 $k$ 存在，则两串的首个不同位恰为 $k$，且 $R_i$ 在该位是 $x$、$R_j$ 在该位是 $d_k$。

**证明**：尾部：位置 $j+1$ 起 $R_i$ 依次是 $d_j, \cdots, d_{m-1}$，$R_j$ 亦是，逐位相同；前缀显然相同。

(a) 若 $[i, j)$ 内 $d$ 全 $= x$：窗口上 $R_i$ 为 $(x, d_i, \cdots, d_{j-1}) = (x, x, \cdots, x)$，$R_j$ 为 $(d_i, \cdots, d_{j-1}, x) = (x, \cdots, x, x)$，逐位相等，故 $R_i = R_j$。

(b) 由 $k$ 的定义，$[i, k)$ 内 $d$ 全 $= x$。对 $t \in [0, k-i)$：位置 $i + t$ 上，$R_i$ 的字符是 $x$（$t = 0$ 时即插入位；$t \ge 1$ 时为 $d_{i+t-1} = x$），$R_j$ 的字符是 $d_{i+t} = x$，两串打平。到 $t = k - i$ 即位置 $k$：$R_i$ 的字符是 $x$（$k = i$ 时为插入位，否则为 $d_{k-1} = x$），$R_j$ 的字符是 $d_k \ne x$——故首个不同位为 $k$，且 $R_i$ 该位是 $x$、$R_j$ 该位是 $d_k$。∎

**定理（正数贪心最优性）**：设 $i^{\ast} = \min\{\, i : d_i < x \,\}$（不存在则 $i^{\ast} = m$），则对所有 $j \in [0, m]$ 有 $R_{i^{\ast}} \ge R_j$。

**证明**：任取 $j \ne i^{\ast}$，分两种情形。

- **$j > i^{\ast}$**：对候选对 $(i^{\ast}, j)$ 用引理 2：$[i^{\ast}, j)$ 内首个 $d_k \ne x$ 恰是 $k = i^{\ast}$（因 $d_{i^{\ast}} < x$ 即 $d_{i^{\ast}} \ne x$），故首个不同位为 $i^{\ast}$，该位上 $R_{i^{\ast}}$ 是 $x > d_{i^{\ast}} = R_j$ 该位，引理 1 给出 $R_{i^{\ast}} > R_j$。
- **$j < i^{\ast}$**：由 $i^{\ast}$ 的最左性，$[j, i^{\ast})$ 内所有 $d \ge x$。对候选对 $(j, i^{\ast})$ 用引理 2：若窗口内存在 $d_k \ne x$，则必有 $d_k > x$，首个不同位 $k$ 上 $R_j$ 是 $x < d_k = R_{i^{\ast}}$，引理 1 给出 $R_j < R_{i^{\ast}}$；若窗口内 $d$ 全 $= x$，引理 2(a) 给出 $R_j = R_{i^{\ast}}$（打平无损）。
- $i^{\ast} = m$（无 $d_i < x$）时，第二情形对任意 $j < m$ 直接适用。∎

**定理（负数贪心最优性）**：设 $i^{\ast} = \min\{\, i \ge 1 : d_i > x \,\}$（不存在则 $i^{\ast} = m$），则 $R_{i^{\ast}}$ 的数值最大。

**证明**：负数数值最大 $\Leftrightarrow$ 绝对值串字典序最小。把正数定理的证明逐字重跑、把「最大化」换成「最小化」：$j > i^{\ast}$ 时首个不同位 $i^{\ast}$ 上 $x < d_{i^{\ast}}$，$R_{i^{\ast}}$ 绝对值更小；$j < i^{\ast}$ 时窗口内 $d_k \ne x$ 必有 $d_k < x$，首个不同位 $k$ 上 $R_j$ 是 $x > d_k$，$R_j$ 绝对值更大；窗口全 $= x$ 时打平。故 $R_{i^{\ast}}$ 绝对值最小、数值最大。∎

**推论（$=$ 打平的无损性）**：在任意 $d_i = x$ 的位置停与不停，结果串完全相同——这既是「跳过条件带等号与否不影响正确性」的依据（引理 2(a) 封死了并列最大的担忧），也解释了示例 1 与自造样例 `"665"` 中多个候选并列最大的现象。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描每位 $O(1)$ 比较，插入 / 拼接 $O(n)$，总计线性。对照暴力 $O(n^2)$：贪心把「枚举 $n+1$ 个候选再两两比较」压缩为「一次扫描找首个增益点」，增益来源于等长候选的首差位结构。
- **空间复杂度**：$O(n)$。结果串长度 $n+1$（C++ 原地 `insert` 触发 $O(n)$ 搬移；Python 切片产生新串）；除输出外仅 $O(1)$ 辅助变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string maxValue(string n, int x) {
        char c = '0' + x;  // '0'..'9' 的 ASCII 序 = 数值序
        auto it = (n[0] != '-')
            ? find_if(n.begin(),     n.end(), [c](char ch) { return ch < c; })  // 正数：首个 < x
            : find_if(n.begin() + 1, n.end(), [c](char ch) { return ch > c; }); // 负数：跳过负号，首个 > x
        n.insert(it, c);    // it == end() 时即末尾追加，兜底零特判
        return n;
    }
};
```

### Python

```python
class Solution:
    def maxValue(self, n: str, x: int) -> str:
        c = str(x)
        if n[0] != '-':
            for i, ch in enumerate(n):          # 正数：找首个 < x
                if ch < c:
                    return n[:i] + c + n[i:]
        else:
            for i, ch in enumerate(n[1:], 1):   # 负数：跳过负号，找首个 > x
                if ch > c:
                    return n[:i] + c + n[i:]
        return n + c                            # 扫描落空：末尾追加（最低位损失最小）
```

> 💡 **写法对照**：① C++ 用 `find_if` + 原地 `insert`，谓词按分支取 `ch < c` / `ch > c`，`find_if` 失败返回 `end()` 使末尾兜底零特判；Python 用 `enumerate` 提前返回，扫完自然落到末行 `n + c`。② 两版都以单字符比较代替数值比较（`'0'..'9'` 的 ASCII 序与数值序一致），避免逐位 `int()` 转换。③ 官方样例（`"999"` / `"-123"`）与自造样例（`"6665"` / `"-555"`）均验证通过，并与 $O(n^2)$ 暴力对拍随机数据一致。

## 8. 边界情况与易错点

1. **跳过条件与目标关系「反号」（最经典 WA）**：找 $< x$ ⟺ 跳过 $\ge x$；找 $> x$ ⟺ 跳过 $\le x$。若把正数分支写成「停在 `ch > c`」，样例 `"73"` + 6 会错误输出 `"673"`。等号归属无妨（推论：$=$ 停不停都对），**不等号方向**绝不能反。
2. **C++ char 与 int 混比**：`n[i] >= x` 把字符 ASCII 码（如 `'7'` = 55）与整数 7 比较，对 `[1,9]` 的数字恒真，逻辑全错——必须 `n[i] - '0' >= x`，或统一转 `char('0' + x)` 后按字符比较（本文 C++ 版的做法）。
3. **$=$ 打平无损 ≠ 可以随便停**：「停不停结果相同」仅对 $d = x$ 的位成立（引理 2(a)）；增益点（正数的 $d < x$、负数的 $d > x$）由引理 2(b) 锁定为**必须停**（贪心停的位置），其余位**必须不停**。自造样例 `"665"`：停在下标 0、1、2 输出同为 `"6665"`，不存在「停错方向位反而更优」的可能。
4. **扫描落空插末尾**：正数全 $d \ge x$（如 `"99"` + 9）或负数全 $d \le x$（如 `"-55"` + 5）时，末位是最低位、变动损失最小；`find_if` / `for` 自然落尾，若手写 `while` 须确认 $i = m$ 时插入位置合法（恰为末尾）。
5. **负数起点下标 1**：从 `n.begin() + 1` / `n[1:]` 起扫，天然满足「不能插在负号左边」；从 0 起扫会把 `'-'` 拿去与数字比较，直接出界语义。
6. **别转整数**：$10^5$ 位远超 `long long` 与 Python 大数比较的开销预算，全程字符串处理。
7. **正负分支两处自由度**（起点 0/1、跳过 $\ge$ / $\le$）组合出四种写法，比赛时建议默走两遍样例 `"73"` + 6 与 `"-13"` + 2 再提交，是最便宜的 WA 保险。

**延伸思考**：

- **插入 $k$ 个相同的 $x$**：等价于把 $n$ 与串 $\underbrace{xx \cdots x}_{k}$ **保序归并**成字典序最大的串，退化为 [1754. 构造字典序最大的合并字符串](https://leetcode.cn/problems/largest-merge-of-two-strings/) 式双指针贪心（每步取「更大后缀」的首字符）；$k = 1$ 时该贪心即本文规则。
- **求最小值镜像**：正数求最小 ⟺ 找首个 $d > x$ 插其前、全 $d \le x$ 插末尾（如 `"73"` + 6 最小是 `"673"`）；负数求最小（绝对值最大）⟺ 找首个 $d < x$。四象限规则表可一并记忆，证明全部由引理 1、2 翻转不等号得到。
- **插入多位串**：若允许插入一个 $t$ 位串，候选仍等长（均 $+t$），首差位定胜负保持，但「打平传递」需按整段匹配处理，贪心不再是一行谓词——可作为 1881 的进阶练习。
