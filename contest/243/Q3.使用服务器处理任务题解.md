# LeetCode 使用服务器处理任务 题解

## 1. 题目概述

- **标题 / 题号**：使用服务器处理任务（#1882，medium）
- **链接**：https://leetcode.cn/problems/process-tasks-using-servers/
- **来源**：LeetCode 第 243 场周赛 Q3
- **难度**：中等
- **标签**：堆、优先队列、模拟、调度、双堆

**题意**：给定长度为 $n$ 的服务器权重数组 `servers` 与长度为 $m$ 的任务耗时数组 `tasks`（均下标从 0 开始）。第 $j$ 项任务在第 $j$ 秒到达；分配时选**权重最小**的空闲服务器，权重并列选**下标最小**者；服务器在第 $t$ 秒接到任务 $j$，则在 $t + \text{tasks}[j]$ 秒恢复空闲。若无空闲服务器，任务等待到**尽可能早**的可用时刻；同一时刻多台空闲则多项等待任务可**同时**分别分配，等待任务按**下标递增**顺序分派。返回 `ans[j]` = 处理第 $j$ 项任务的服务器下标。

**约束**：

- $1 \le n, m \le 2 \times 10^5$
- $1 \le \text{servers}[i], \text{tasks}[j] \le 2 \times 10^5$

> 💡 本题在本仓库另有[每日题解 1882](../../solution/1801-1900/1882_使用服务器处理任务.md)，两篇为姊妹篇：每日版侧重双堆直觉切入、与 1834 单线程 CPU 的「单堆 → 双堆」演进和面试问答。本篇按周赛复盘视角展开：**事件驱动的时间快进**（逐秒模拟为何必 TLE、跳跃为何无损）、**堆序对选择规则的精确刻画**、**模拟一致性的引理-定理链证明**，以及比赛中最伤的两大 WA 陷阱——C++ `int` 溢出与 `now = max(now, j)` 误写成 `now = j` 的反例复盘。

## 3. 解题思路

### 3.1 暴力思路：逐秒模拟 + 线性扫描

照题意直译：`time` 从 0 逐秒递增，每秒先释放所有完成时刻 $\le$ `time` 的服务器，再把等待队列队首逐个分配给「线性扫描找出的权重最小空闲服务器」。两个维度同时爆炸：

- **时间维度**：$n = 1$、$m = 2 \times 10^5$、每个任务 $2 \times 10^5$ 秒时，总时长约 $4 \times 10^{10}$ 秒，逐秒循环必 TLE；
- **选择维度**：即使把空转秒跳过，每轮「找权重最小的空闲服务器」线性扫是 $O(n)$，总计 $O(nm) \approx 4 \times 10^{10}$，同样必 TLE。

> ⚠️ 两处瓶颈要分开治：**选服务器**用堆（按 $(权重, 下标)$ 取最小）；**空转时间**用事件快进（跳到下一个事件时刻，而不是逐秒走）。

### 3.2 核心观察：双堆分工 + 时间快进

![核心观察：双堆分工与时间快进](images/wc243_q3_time_jump_concept.svg)

系统里的事件只有两类：**任务到达**（第 $j$ 项固定在第 $j$ 秒，无需数据结构）与**服务器完成**（由分配决定）。把「服务器」这个可复用资源拆成两个堆：

1. **空闲堆 `free`**：键 $(权重, 下标)$ 的小顶堆。堆序**逐字编码**了题目的选择规则——权重最小、同则下标最小，分配即 `pop` 堆顶。
2. **忙碌堆 `busy`**：键 $(完成时刻, 权重, 下标)$ 的小顶堆。堆顶是**最早完成**的服务器：空闲堆空时，`now` 直接跳到堆顶完成时刻——这就是时间快进。
3. **守恒不变量**：$|free| + |busy| = n$ 恒成立。于是 `free` 空 $\iff$ 全忙 $\iff$ `busy` 满，快进必有目标。

每个任务的处理循环：`now ← max(now, j)` 补上到达时刻 → 释放所有完成 $\le$ `now` 的服务器 → 若 `free` 空则快进再释放 → `pop free` 分配 → 入 `busy`。

### 3.3 算法流程

![算法流程：逐任务处理，时间只在事件处推进](images/wc243_q3_algorithm_flow.svg)

```text
for j in range(m):
    now = max(now, j)                 # 任务 j 最晚在第 j 秒到达
    while busy 非空 且 堆顶完成 ≤ now:  # 释放（同刻可能多台！）
        pop busy → push free
    if free 空:                        # 全忙 → 快进到最早完成时刻
        now = busy 堆顶完成时刻
        while busy 非空 且 堆顶完成 ≤ now: 释放
    (w, i) = pop free                  # 选择规则 = 堆序
    ans[j] = i
    push busy: (now + tasks[j], w, i)  # 占用区间 [now, now+tasks[j])
```

### 3.4 示例演算

![示例演算：示例 1 的甘特图走查](images/wc243_q3_gantt_walkthrough.svg)

示例 1 的全程如上图甘特图所示，两个关键时刻：

- **t=2（不释放 + 权重并列）**：`busy` 堆顶完成时刻 $3 > 2$，本轮不释放；`free = {(3,#0),(3,#1)}`，权重并列 3，按第二关键字取下标小者 $\#0$。
- **t=5（三台同刻完成）**：处理完 j=4 后 `free` 空；处理 j=5 时 `now` 快进到 5，`while` 把 $\#0,\#1,\#2$ **一次性全部**释放回 `free`，再按 $(权重, 下标)$ 选出 $(2,\#2)$。

自造样例 `servers = [1,1], tasks = [5,5,1,1,1,1]` 的积压场景（见 §2 表格）：算法按 $j$ 递增逐任务处理，j=3 时 `now = max(6, 3) = 6`——**任务虽然到达于 t=3，但系统时间已经走到 6**，`release(6)` 释放同刻完成的两台，T3 取走 #0 后 `free` 还剩 #1，紧接着 j=4 在同一时刻 `now = max(6, 4) = 6` 取走 #1。「等待任务按下标递增、同秒并发分配」由外层循环顺序 + `max(now, j)` 天然实现，无需显式任务队列。

## 4. 算法细节

1. **堆序设计**：`free` 存 $(w, i)$，`pair` 的字典序比较先比 $w$ 再比 $i$，与题目选择规则一一对应，**零特判**；`busy` 存 $(fin, w, i)$，完成时刻作第一关键字。后两个键 $(w, i)$ 不参与正确性（同刻完成的释放顺序无所谓，反正 `while` 全释放），存进去只是为了释放时直接拿到 `free` 需要的键，省一次查表。
2. **`now` 的两处推进**：`now = max(now, j)` 保证单调不减（前一个任务可能等待到远晚于 $j$ 的时刻）；`free` 空时 `now = busy 顶完成时刻` 是唯一的跳跃来源。两处合起来实现「时间只在事件处推进」。
3. **释放用 `while` 不用 `if`**：同一时刻可能多台服务器同时完成（示例 1 的 t=5、自造样例的 t=6 都是三台/两台同刻）。`if` 只还一台，`free` 可能仍然缺员。
4. **释放条件带等号**：占用区间是半开 $[t, t + dur)$，完成时刻即空闲时刻，条件必须是 `fin ≤ now`；写成 `<` 会让服务器「迟到一秒」。
5. **任务侧零数据结构**：任务到达时刻 = 下标，天然有序，外层 `for` 循环即「下标递增分配」，等待队列被循环顺序隐式实现。
6. **溢出推导（C++）**：$n = 1$、$m = 2 \times 10^5$、全部 $\text{tasks}[j] = 2 \times 10^5$ 时，最后一个任务的开始时刻 $\approx 4 \times 10^{10}$，远超 `int` 上限 $2.1 \times 10^9$——`now` 与 `busy` 的键必须用 `long long`。Python 天然大整数无此问题。

## 5. 正确性证明

**真实调度的形式化**（题意的逐字直译）：时间逐秒推进；每一秒，先把所有完成时刻 $\le$ 当前秒的服务器置为空闲，再把等待队列中的任务按下标递增逐个分配给空闲服务器（选权重最小、同则下标最小者），直到队列空或无空闲服务器；第 $j$ 项任务在第 $j$ 秒进入等待队列。该过程每步确定，产生唯一的 $\text{ans}$。记 $t_j$ 为真实调度中任务 $j$ 的开始时刻。

**引理 1（选择规则 = 堆序）**：任意非空空闲集 $F$ 中，题目规则选中的服务器恰为键 $(w_i, i)$ 字典序最小的元素，即 `free` 小顶堆的堆顶。

**证明**：$(w_i, i) < (w_k, k)$（字典序）$\iff w_i < w_k$，或 $w_i = w_k$ 且 $i < k$，逐字对应「权重最小、同则下标最小」。小顶堆 `pop` 每次取出键最小元。∎

**引理 2（释放完备性）**：设 `busy` 中各服务器的完成时刻与真实调度一致。对任意时刻 $s$，执行释放循环（把完成 $\le s$ 者全部移入 `free`）后：完成 $\le s$ 的服务器在 $s$ 秒真实空闲、完成 $> s$ 者在 $s$ 秒真实忙碌。

**证明**：服务器 $i$ 在 $s$ 秒真实空闲 $\iff$ 它的占用区间 $[t, t + dur)$ 不覆盖 $s$ $\iff$（在「开始时刻 $\le s$ 已定」的前提下）完成时刻 $\le s$。释放循环恰好按此分界搬运，且每台至多搬运一次。∎

**引理 3（快进无损）**：若释放循环终止后 `free` 为空，记 $t^{\ast}$ 为 `busy` 堆顶完成时刻，则 $t^{\ast} > $ 当前 `now`，真实空闲集在 $[\text{now}, t^{\ast})$ 上恒为空，在 $t^{\ast}$ 秒非空。

**证明**：`free` 空时由守恒不变量（$|free| + |busy| = n \ge 1$）知 `busy` 非空；释放循环刚终止说明 `busy` 中所有完成时刻 $>$ `now`，故堆顶 $t^{\ast} > \text{now}$。区间 $[\text{now}, t^{\ast})$ 内无任何服务器完成（$t^{\ast}$ 是最小完成时刻），已忙者保持忙，故真实空闲集恒空；$t^{\ast}$ 秒堆顶那台完成，空闲集非空。∎

**引理 4（开始时刻单调）**：真实调度中 $t_0 \le t_1 \le \cdots \le t_{m-1}$。

**证明**：对相邻对 $(j-1, j)$：若 $t_{j-1} < j$，则 $t_j \ge j > t_{j-1}$（到达时刻约束）。若 $t_{j-1} \ge j$，则任务 $j-1$ 在第 $j-1$ 秒起持续等待至 $t_{j-1}$——等待期间每一秒空闲集必为空（否则队首早被分配）；任务 $j$ 在第 $j$ 秒进入队列，排在 $j-1$ 之后，而分配事件中等待队列按序清空，故任务 $j$ 获得服务器的时刻不早于 $j-1$，即 $t_j \ge t_{j-1}$。∎

**定理（模拟一致性）**：对每个 $j \in [0, m)$，算法分配给任务 $j$ 的服务器与真实调度一致，且分配时刻 `now` $= t_j$。

**证明**：对 $j$ 归纳。归纳假设：第 $j$ 轮开始前，`now` $= t_{j-1}$（$j = 0$ 时 `now` $= 0$），且 `free`/`busy` 恰为真实调度在任务 $0..j-1$ 已按真实方式分配后于该时刻的空闲/忙碌集（含完成时刻）。

第 $j$ 轮：① `now` $\leftarrow \max(t_{j-1}, j)$，由引理 4 其值 $\le t_j$；② 释放循环，由引理 2 得到真实调度在 `now` 秒的精确状态。③ **若 `free` 非空**：断言 `now` $= t_j$。若 `now` $= j$：真实空闲集在 `now` 非空且 $t_j \ge j$，故 $t_j = j = \text{now}$。若 `now` $= t_{j-1} > j$：由引理 4 证明中的论证，任务 $j-1$ 等待期间 $[j-1, t_{j-1})$ 空闲集恒空，故真实 $t_j \ge t_{j-1} = \text{now}$，而 `now` 秒空闲非空给出 $t_j \le \text{now}$，即 $t_j = \text{now}$。④ **若 `free` 空**：由引理 3，真实空闲集在 $[\text{now}, t^{\ast})$ 恒空、$t^{\ast}$ 秒非空，且 `now` $\ge j$，故真实 $t_j = t^{\ast}$；算法快进 `now` $\leftarrow t^{\ast}$ 并再次释放（引理 2），状态精确。⑤ 两情形下均由引理 1，算法 `pop` 出的服务器与真实选择一致；算法 push 的 $(\text{now} + \text{tasks}[j], w, i)$ 与真实占用区间 $[t_j, t_j + \text{tasks}[j])$ 一致，`now` $= t_j$——归纳假设对 $j+1$ 成立。∎

**推论（同秒并发分配）**：真实调度允许同一秒把多项等待任务分给多台空闲服务器；算法外层按 $j$ 递增、`now = max(now, j)` 单调不减，后续任务在同一 `now` 被立即处理，逐台取走 `free` 堆顶——「下标递增 + 同秒并发」被循环结构精确复刻。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n + m) \log n)$。初始 `heapify` 建 `free` 堆 $O(n)$；此后每个任务恰触发一次 `free` 出堆 + 一次 `busy` 入堆，每台服务器每次「释放再分配」对应一次 `busy` 出堆 + 一次 `free` 入堆——由守恒不变量，两类堆的元素总数恒为 $n$，全程序堆操作总数为 $O(n + m)$，每次 $O(\log n)$。
- **空间复杂度**：$O(n)$（不计输出）。两个堆的元素总数恒为 $n$；答案数组 $O(m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> assignTasks(vector<int>& servers, vector<int>& tasks) {
        int m = tasks.size();
        // 空闲堆：键 (权重, 下标) —— 堆序即题目选择规则
        priority_queue<pair<int,int>, vector<pair<int,int>>, greater<>> free;
        for (int i = 0; i < (int)servers.size(); ++i) free.emplace(servers[i], i);
        // 忙碌堆：键 (完成时刻, 权重, 下标) —— 堆顶驱动时间快进
        priority_queue<tuple<long long,int,int>,
                       vector<tuple<long long,int,int>>, greater<>> busy;

        auto release = [&](long long now) {   // 完成时刻 ≤ now 的服务器全部归还空闲堆
            while (!busy.empty() && get<0>(busy.top()) <= now) {
                auto [fin, w, i] = busy.top(); busy.pop();
                free.emplace(w, i);
            }
        };

        vector<int> ans(m);
        long long now = 0;
        for (int j = 0; j < m; ++j) {
            now = max(now, (long long)j);     // 任务 j 最晚在第 j 秒到达
            release(now);
            if (free.empty()) {               // 全忙 → 快进到最早完成时刻（busy 必非空）
                now = get<0>(busy.top());
                release(now);
            }
            auto [w, i] = free.top(); free.pop();  // 权重最小、同则下标最小
            ans[j] = i;
            busy.emplace(now + tasks[j], w, i);    // 占用区间 [now, now+tasks[j])
        }
        return ans;
    }
};
```

### Python

```python
import heapq

class Solution:
    def assignTasks(self, servers: List[int], tasks: List[int]) -> List[int]:
        m = len(tasks)
        free = [(w, i) for i, w in enumerate(servers)]  # 空闲堆：(权重, 下标)
        heapq.heapify(free)                              # O(n) 建堆
        busy = []                                        # 忙碌堆：(完成时刻, 权重, 下标)

        def release(now):                                # 完成时刻 ≤ now 的全部归还空闲堆
            while busy and busy[0][0] <= now:
                _, w, i = heapq.heappop(busy)
                heapq.heappush(free, (w, i))

        ans = [0] * m
        now = 0
        for j in range(m):
            now = max(now, j)          # 任务 j 最晚在第 j 秒到达（单调不减！）
            release(now)
            if not free:               # 全忙 → 快进到最早完成时刻
                now = busy[0][0]
                release(now)
            w, i = heapq.heappop(free)  # 权重最小、同则下标最小
            ans[j] = i
            heapq.heappush(busy, (now + tasks[j], w, i))
        return ans
```

## 8. 边界情况与易错点

1. **C++ `int` 溢出（最隐蔽的 WA）**：$n=1$、$m = 2\times10^5$、全时长 $2\times10^5$ 时 `now` 与 `busy` 键达 $4\times10^{10}$，`int` 必炸且样例测不出（官方样例最大时刻仅 9）。`now`、`busy` 的键全部 `long long`。
2. **`now = max(now, j)` 误写成 `now = j`（反例可证）**：反例 `servers=[1,1], tasks=[5,5,1,1,1,1]`，正确答案 `[0,1,0,0,1,0]`。写成 `now = j` 后处理 j=3 时 `now=3`，但 `free` 里躺着「t=6 才真正释放」的 #1（算法状态停留在 t=6，`release(3)` 释放不了它），误在 t=3 分配并记完成时刻 4——后续全盘错位，输出 `[0,1,0,0,0,1]`。**`now` 单调不减是算法的命根**。
3. **释放用 `while` 不用 `if`**：同刻多台完成（示例 1 的 t=5 三台、自造样例 t=6 两台）。`if` 只还一台，`free` 缺员时后续任务被误判为需等待。
4. **释放条件 `fin ≤ now` 带等号**：占用是半开区间 $[t, t+dur)$，完成时刻即空闲时刻；写 `<` 全局慢一秒。
5. **`free` 空时 `busy` 必非空**：由守恒 $|free| + |busy| = n \ge 1$ 保证，跳跃前无需判 `busy` 空——但前提是别把服务器弄丢（每轮恰好一进一出，堆操作配平）。
6. **`free` 堆必须双关键字**：只存权重，权重并列时 `heapq` 无稳定序（C++ `priority_queue` 同样不保证），并列下标小的选择会随机；存 $(w, i)$ 才是确定性堆序。
7. **别建显式任务队列**：任务到达时刻 = 下标，`for j` 循环本身即队列；再建队列/堆反而画蛇添足。

**延伸思考**：

- **权重动态变化**：若服务器权重随时间改变（如负载衰减），`free` 堆序失效，需换成平衡树 / 线段树按当前键取最小——堆的优势建立在「键不变」上。
- **抢占式调度**：若允许新任务抢占（如最短剩余时间优先），`busy` 堆需改按剩余时间组织，释放与入堆的时机要重新设计，可进一步阅读操作系统调度的 SJF / SRTF 材料延伸。
- **离线视角**：本题规则是在线 FIFO（到达序）+ 资源侧贪心（权重最小），并非吞吐最优；若目标是「最小化总完成时间」，将任务按耗时排序的 SJF 才是最优——规则由题面规定，正是模拟题「照章办事」的趣味所在。
