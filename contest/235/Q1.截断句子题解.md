# LeetCode 截断句子 题解

## 1. 题目概述

- **标题 / 题号**：截断句子（#1816，easy）
- **链接**：https://leetcode.cn/problems/truncate-sentence/
- **来源**：LeetCode 第 235 场周赛 Q1
- **难度**：简单
- **标签**：字符串、一次遍历

**题意**：**句子**是单词列表，单词之间用**单个空格**隔开，无前导或尾随空格，每个单词仅由大小写英文字母组成。给定句子 `s` 与整数 `k`，将 `s` 截断为**仅含前 $k$ 个单词**的句子并返回。

**约束**：

- $1 \le \text{s.length} \le 500$
- $k \in [1,\ \text{s 中单词数目}]$
- `s` 仅由大小写英文字母和空格组成
- 单词之间由单个空格隔开，不存在前导或尾随空格

> 💡 **审题关键**：签到题 30 秒出解的抓手是「单词间**仅单个空格**、无多余空格」——它意味着**空格数 = 单词数 − 1**，第 $k$ 个单词之后必然紧跟第 $k$ 个空格（除非它是末词）。抓住这层观察，「取前 $k$ 个单词」就转化为「找第 $k$ 个空格」，连 `split` 都可以省掉。

> 💡 本题在本仓库另有[每日题解 1816](../../solution/1801-1900/1816_截断句子.md)：以「审题直觉、`split` 对比、标准库 API 扩展与面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时最短路径决策**（Python 一行流 vs C++ 手写计数 vs `find` 链式定位的取舍）、**「约束 → 观察 → 转化」的签到题切入框架**，以及 off-by-one 兜底的完整证明链，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：切分再拼接

最直觉的做法是「按空格切分，取前 $k$ 个单词再拼接」：

- **Python**：`' '.join(s.split()[:k])`，一行流，赛时约 40 秒可 AC——签到阶段用 Python 的最短路径就是它；
- **C++**：`istringstream >> word` 逐词读入 `vector<string>`，取前 $k$ 个再用空格拼接，写起来 15 行起步。

正确性无虞，但两版都要**创建全部单词的副本**（辅助空间 $O(n)$），且必然扫描完整字符串——即便答案只是原串的一个前缀。$n \le 500$ 下性能毫无问题，**赛时选它完全合理**；但复盘时值得沉淀「不切分」的写法，把空间压到 $O(1)$。

### 3.2 核心观察：单词边界 = 空格位置，第 k 个空格即截断点

![核心观察：第 k 个空格即截断点](images/wc235_q1_kth_space_concept.svg)

「单空格、无多余空格」的约束把**单词边界**和**空格位置**变成一一对应：

- 第 $j$ 个单词（$j <$ 单词总数 $m$）的结尾紧跟着第 $j$ 个空格；
- 因此前 $k$ 个单词 + 其间 $k - 1$ 个空格，恰好是**第 $k$ 个空格左侧的整段前缀**（当 $k < m$）。

于是问题「取前 $k$ 个单词」转化为「找第 $k$ 个空格」：设其下标为 $i$，答案即 `s.substr(0, i)`；若不存在第 $k$ 个空格（$k = m$），答案就是整个 `s`。**一次线性扫描、遇第 $k$ 个空格立即停止**，连后面的字符都不必看。

### 3.3 算法流程：计数空格，命中即截断

![算法流程：一次扫描计数空格，cnt 达 k 即截断](images/wc235_q1_scan_flow.svg)

1. `cnt = 0`，从左向右枚举下标 $i$；
2. 若 $s[i]$ 是空格：`cnt++`；
3. 若 `cnt == k`：当前 $i$ 即第 $k$ 个空格的下标，立即返回 $s[0..i-1]$；
4. 循环自然扫完仍未命中（说明 $k$ = 单词总数）：返回整个 `s`。

**提前终止**是这条流程的效率关键：一旦定位截断点就不再访问后续字符（见 3.4 演算中 `"Contestant"` 从未被扫到）。「扫完兜底 `return s`」则免去了对 $k = m$ 的任何特判——这是「**计数 + 兜底返回**」框架在签到题上的典型红利。

### 3.4 示例演算

![示例演算：s = "Hello how are you Contestant", k = 4](images/wc235_q1_walkthrough.svg)

以示例 1 走查（$k = 4$）：

| 事件 | 下标 $i$ | cnt | 动作 |
|------|---------|-----|------|
| 扫过 `"Hello"` | 0–4 | 0 | 继续扫描 |
| 遇空格 `s[5]` | 5 | 1 | 词 1 结束 |
| 遇空格 `s[9]` | 9 | 2 | 词 2 结束 |
| 遇空格 `s[13]` | 13 | 3 | 词 3 结束 |
| 遇空格 `s[17]` | 17 | 4 | $4 == k$ → **截断**，返回 $s[0..16]$ |

再对照示例 3（$k = 5 =$ 单词总数）：全串只有 4 个空格，扫完 `cnt = 4 < 5`，走兜底分支返回原句——**无需一行特判代码**。

## 4. 算法细节

1. **返回长度**：第 $k$ 个空格下标为 $i$ 时返回 `s.substr(0, i)`（C++）/ `s[:i]`（Python），**不含** `s[i]` 这个空格本身——截断后的句子保留前 $k$ 个单词与其间 $k - 1$ 个空格，恰好是 $s[0..i-1]$。
2. **提前终止**：命中即 `return`，第 $k$ 个空格之后的字符（如示例 1 的 `"Contestant"`）从未被访问；最坏情况（$k = m$）才扫全串。
3. **C++ `find` 链式写法**：`pos = s.find(' ', pos + 1)` 循环 $k$ 次，第 $k$ 次命中的 `pos` 即截断点；返回 `npos` 说明 $k = m$，直接返回 `s`。与手写计数循环完全等价，语义更聚焦「找第 $k$ 个空格」。
4. **语言选择（赛时决策）**：Python 选手直接 `' '.join(s.split()[:k])`，代码量最小、不易错；C++ 选手在手写计数（12 行、$O(1)$ 空间）与 `istringstream`（15 行、$O(n)$ 空间）之间选前者更快。签到题的目标是**零调试成本**，不是炫技。

## 5. 正确性证明

**引理 1**（边界对应）：设 `s` 含 $m$ 个单词、满足单空格约束，则第 $j$ 个单词（$1 \le j < m$）的最后一个字符的下一位置恰为第 $j$ 个空格，且该空格是第 $j+1$ 个单词的前一个字符。

**证明**：单词按定义仅由空格分隔。无前导空格 ⇒ 第 1 个单词前无空格；无连续空格 ⇒ 相邻单词 $j$ 与 $j+1$ 之间恰有一个空格。按出现顺序对空格编号，第 $j$ 个空格即分隔第 $j$ 与第 $j+1$ 个单词的那个空格，位于第 $j$ 个单词末字符之后一格。∎

**引理 2**（前缀刻画）：当 $1 \le k < m$ 时，设第 $k$ 个空格下标为 $i$，则 $s[0..i-1]$ 恰由前 $k$ 个单词及其间 $k-1$ 个空格构成。

**证明**：由引理 1，第 $k$ 个单词终止于下标 $i-1$，故前 $k$ 个单词全部落在 $s[0..i-1]$ 内；又 $s[0..i-1]$ 中出现的空格恰为第 $1 \sim k-1$ 个空格（第 $k$ 个空格在下标 $i$ 处，不在其中），共 $k-1$ 个，即前 $k$ 个单词之间的全部空格。反之 $s[0..i-1]$ 中的字符都属于前 $k$ 个单词或这些间隔空格。∎

**定理**（算法正确性）：计数空格算法返回的串恰由 `s` 的前 $k$ 个单词组成。

**证明**：分两种情况。若 $k < m$：`s` 恰有 $m - 1 \ge k$ 个空格，扫描在第 $k$ 个空格处 `cnt` 达到 $k$ 并返回 `s[0..i-1]`，由引理 2 该串即前 $k$ 个单词。若 $k = m$：`s` 仅含 $m - 1 < k$ 个空格，扫描中 `cnt` 至多为 $m - 1$，条件 `cnt == k` 永不触发，循环自然结束走兜底 `return s`，即前 $m = k$ 个单词。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个字符至多访问一次、$O(1)$ 处理；$k < m$ 时在第 $k$ 个空格处提前终止，实际访问字符数少于 $n$，最坏（$k = m$）扫全串。对比 `split` 写法：同为 $O(n)$ 但必扫全串。
- **空间复杂度**：$O(1)$ 辅助空间。仅用 `cnt` 与下标 `i` 两个变量；返回的子串是输出本身，不计入辅助空间（C++ `substr` / Python 切片构造结果串不可避免）。对比 `split` 写法的 $O(n)$ 单词列表副本。

## 7. 参考代码

### C++（计数空格 + 提前截断）

```cpp
class Solution {
public:
    string truncateSentence(string s, int k) {
        int cnt = 0;
        for (int i = 0; i < (int)s.size(); ++i) {
            if (s[i] == ' ') {
                if (++cnt == k) return s.substr(0, i);  // 第 k 个空格处截断
            }
        }
        return s;                                        // k == 单词总数，兜底返回原句
    }
};
```

### C++（find 链式定位第 k 个空格）

```cpp
class Solution {
public:
    string truncateSentence(string s, int k) {
        int pos = -1;
        while (k--) {
            pos = s.find(' ', pos + 1);
            if (pos == string::npos) return s;           // 不足 k 个空格 → 返回原句
        }
        return s.substr(0, pos);
    }
};
```

### Python（计数空格）

```python
class Solution:
    def truncateSentence(self, s: str, k: int) -> str:
        cnt = 0
        for i, c in enumerate(s):
            if c == ' ':
                cnt += 1
                if cnt == k:
                    return s[:i]
        return s
```

### Python（split 一行流，赛时最短路径）

```python
class Solution:
    def truncateSentence(self, s: str, k: int) -> str:
        return ' '.join(s.split()[:k])
```

> ⚠️ 一行流正确且快写，但切出全部单词副本（$O(n)$ 空间）并扫全串；计数版 $O(1)$ 辅助空间且提前终止。**赛时用前者抢时间，复盘沉淀后者**。

## 8. 边界情况与易错点

1. **off-by-one（本题最高频翻车点）**：命中时返回 `s.substr(0, i)` 而非 `substr(0, i + 1)`——`s[i]` 本身是空格，含进去结果会带尾随空格。同理 Python 是 `s[:i]` 不是 `s[:i+1]`。
2. **k = 单词总数**：不存在第 $k$ 个空格，循环兜底 `return s`，**无需特判**（示例 3）。若写成「找不到就返回空串」就是没吃透兜底分支。
3. **单单词句子**：`s = "Hello"`、`k = 1` 时全串无空格，`cnt` 恒为 0，同样走兜底（自拟示例 4）。
4. **`find` 写法的 `npos`**：链式定位中任一次返回 `npos` 都说明空格不足 $k$ 个，必须立即 `return s`；漏判会对 `npos` 做 `substr` 导致未定义行为。
5. **不要为「多余空格」写防御代码**：约束已排除前导/尾随/连续空格，数空格法才因此成立。若放宽约束（如 151 题），需改为「跳过连续空格再数单词」的两指针扫描，数空格法直接失效。
6. **C++ 比较字符字面量**：`s[i] == ' '` 是字符比较；误写成 `" "`（字符串字面量，指针比较）在 C++ 中编译报错，Python 中 `c == " "` 反而碰巧可行——跨语言提交时留意。
