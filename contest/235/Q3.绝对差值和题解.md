# LeetCode 绝对差值和 题解

## 1. 题目概述

- **标题 / 题号**：绝对差值和（#1818，medium）
- **链接**：https://leetcode.cn/problems/minimum-absolute-sum-difference/
- **来源**：LeetCode 第 235 场周赛 Q3
- **难度**：中等
- **标签**：数组、排序、二分查找、有序集合

**题意**：给定长度均为 $n$ 的正整数数组 `nums1` 与 `nums2`，定义**绝对差值和**为

$$S = \sum_{i=0}^{n-1} \left| \text{nums1}[i] - \text{nums2}[i] \right|$$

允许执行**至多一次**替换：选一个下标，把 `nums1` 中该位置的元素替换为 `nums1` 中**任意一个**元素的值（候选只能是现有值，不是任意数；替换值可以就是它自己，等价于不换）。求替换后**最小**的绝对差值和，结果对 $10^9+7$ 取模返回。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{nums1}[i],\ \text{nums2}[i] \le 10^5$

> 💡 **审题关键**：三处定生死——① 替换值只能从 `nums1` 的**现有元素**里选，不是改成任意数（否则每位直接换成 $\text{nums2}[i]$，全场差值清零，题目退化）；② **至多**替换一个位置，全部收益集中在被换的那一位；③ 答案虽取模，但 $S$ 最大可达 $n \cdot \max|\text{nums1}[i]-\text{nums2}[i]| = 10^{10}$，必须**先 64 位累加、最后一次取模**。赛时识别信号：$n = 10^5$ 直接排除 $O(n^2)$，而「从数组中挑一个最接近目标值的元素」正是**排序 + 二分**的招牌场景。

> 💡 本题在本仓库另有[每日题解 1818](../../solution/1801-1900/1818_最小绝对差之和.md)：以「审题直觉、二分边界与面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时信号识别**（$O(n^2)$ 到排序 + 二分的转化路径）、**引理—定理完整证明链**与**溢出 / 取模踩坑清单**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums1 = [1,7,5], nums2 = [2,3,5]
输出：3
解释：原始差值和 = |1−2| + |7−3| + |5−5| = 1 + 4 + 0 = 5。
      把 nums1[1]=7 替换为 nums1[2]=5（或 nums1[0]=1）：
      新差值和 = 1 + 2 + 0 = 3。
```

**示例 2**

```text
输入：nums1 = [2,4,6,8,10], nums2 = [2,4,6,8,10]
输出：0
解释：两数组逐位相等，差值和为 0，无需替换。
```

**示例 3**

```text
输入：nums1 = [1,10,4,4,2,7], nums2 = [9,3,5,1,7,4]
输出：20
解释：原始差值和 = 8+7+1+3+5+3 = 27。把 nums1[0]=1 替换为 10（数组中现有值），
      该位差值 8 → |10−9| = 1，新差值和 = 27 − 7 = 20。
```

**示例 4**（自拟，覆盖二分两端边界）

```text
输入：nums1 = [5,3], nums2 = [1,7]
输出：6
解释：total = |5−1| + |3−7| = 8。
      i=0：t=1 小于全部元素（p=0，无左候选），最近值 3，gain = 4−2 = 2；
      i=1：t=7 大于全部元素（p=n，无右候选），最近值 5，gain = 4−2 = 2。
      答案 = 8 − 2 = 6。
```

## 3. 解题思路

### 3.1 暴力思路：枚举（替换位， 替换值）二元组

最直觉的做法：先算出原始总和 $\text{total}$，再枚举替换位置 $i$ 与替换值来源 $j$（即换成 $\text{nums1}[j]$），每次 $O(1)$ 更新答案：

```text
ans = total
for i in range(n):
    for j in range(n):
        ans = min(ans, total - (|nums1[i]-nums2[i]| - |nums1[j]-nums2[i]|))
```

正确性无虞，但 $O(n^2)$ 在 $n = 10^5$ 下约 $10^{10}$ 次操作，必然超时。瓶颈非常集中：**对每个 $i$ 线性扫描整个 `nums1` 找最优的 $j$**。

> 💡 **转化**：内层循环的本质是「在数组中找**最接近** $\text{nums2}[i]$ 的值」——把候选排好序，这个问题二分 $O(\log n)$ 就能回答。

### 3.2 核心观察：只换一位 ⇒ 各位独立；找最近值 ⇒ 排序 + 二分

![核心观察：各位独立求 gain + 二分找左右夹板](images/wc235_q3_gain_decompose.svg)

**观察一（收益分解，各位独立）**：替换只发生在一位，而绝对差值和的每一项只依赖对应下标的两个值——所以换哪一位，**其它位的差值分毫不动**。对每个位置 $i$ 独立计算「换成最优值能把该位差值压掉多少」：

$$\text{gain}_i = \underbrace{|\text{nums1}[i] - \text{nums2}[i]|}_{\text{原差值 } d_i} - \underbrace{\min_j |\text{nums1}[j] - \text{nums2}[i]|}_{\text{最优替换后的差值}}$$

由于只允许换一位，答案就是 $\text{total} - \max_i \text{gain}_i$——**一次取最大，同时完成「换哪位 + 换成啥」的双重决策**，无需枚举任何组合。

**观察二（单点最优 = 找最近值）**：把 `nums1` 排序得到副本 `sorted1`。对目标 $t = \text{nums2}[i]$，二分定位插入点 $p = \text{lower\_bound}(\text{sorted1},\ t)$（首个 $\ge t$ 的下标），则 $\text{sorted1}[p-1] < t \le \text{sorted1}[p]$——$t$ 被**相邻两个元素夹住**，全数组中最接近 $t$ 的值必在这两个「夹板」之中。每位只需 $O(\log n)$ 二分 + $O(1)$ 比较两个候选。

> ⚠️ **gain 恒非负**：替换值允许取 $\text{nums1}[i]$ 自身（$j = i$，即不换），该候选的差值恰为 $d_i$，故 $\min_j |\text{nums1}[j] - \text{nums2}[i]| \le d_i$，$\text{gain}_i \ge 0$。这意味着**最坏情况就是不变**，`maxGain` 初始化为 0 即可，无需特判「不换更优」。

### 3.3 算法流程

![算法流程：排序 + 逐位二分找最近值](images/wc235_q3_binary_flow.svg)

1. **算总和**：$\text{total} = \sum_i |\text{nums1}[i] - \text{nums2}[i]|$（64 位累加）；
2. **排序副本**：`sorted1 = sorted(nums1)`，原数组不动；
3. **逐位求 gain**：对每个 $i$，二分得插入点 $p$，比较 $\text{sorted1}[p]$、$\text{sorted1}[p-1]$ 两个候选（越界跳过）得 `best`，更新 $\text{maxGain} = \max(\text{maxGain},\ d_i - \text{best})$；
4. **返回**：$(\text{total} - \text{maxGain}) \bmod (10^9+7)$。

### 3.4 示例演算

![示例演算：nums1=[1,7,5]，nums2=[2,3,5] 的逐位二分走查](images/wc235_q3_walkthrough.svg)

以示例 1 走查，`sorted1 = [1,5,7]`：

| $i$ | $t=\text{nums2}[i]$ | 原差 $d_i$ | 二分候选（左右夹板） | best | gain |
|---|---|---|---|---|---|
| 0 | 2 | 1 | 1 → \|1−2\|=1；5 → \|5−2\|=3 | 1 | 0 |
| 1 | 3 | 4 | 1 → \|1−3\|=2；5 → \|5−3\|=2 | 2 | **2** ★ |
| 2 | 5 | 0 | 1 → \|1−5\|=4；5 → \|5−5\|=0 | 0 | 0 |

- $\text{total} = 1 + 4 + 0 = 5$；$\text{maxGain} = 2$（$i=1$ 把 7 换成 5 或 1，差值 4 → 2）；
- 答案 $= (5 - 2) \bmod (10^9+7) = 3$。

再对照示例 3 验证：`sorted1 = [1,2,4,4,7,10]`，逐位二分可得 $i=0$ 处 $t=9$ 的最近值是 10（夹板 7 与 10，距离 2 与 1），$\text{gain} = 8 - 1 = 7$ 为全场最大，答案 $27 - 7 = 20$ ✓。示例 4 则同时踩中 $p=0$ 与 $p=n$ 两个二分边界。

## 4. 算法细节

1. **必须排序副本**：原差值 $d_i$ 依赖 `nums1` 的**原始顺序与原始配对**；原地排序会打乱 `nums1[i]` 与 `nums2[i]` 的对应关系，`total` 就算错了。排序只为建立「找最近值」的有序索引。
2. **二分语义**：`lower_bound` / `bisect_left` 返回**首个 $\ge t$** 的位置 $p$，保证 $\text{sorted1}[p-1] < t \le \text{sorted1}[p]$ 的夹板关系。两个边界——$p = 0$（$t$ 不超过最小值，无左候选，只看 $\text{sorted1}[0]$）、$p = n$（$t$ 大于全部元素，无右候选，只看 $\text{sorted1}[n-1]$）。
3. **`best` 初值取 $d_i$ 的一石三鸟**：① 天然表达「$j = i$ 即不替换」这个合法候选；② $p$ 越界时无需空集特判；③ 保证 $\text{gain} \ge 0$，`maxGain` 从 0 起步即可。
4. **64 位与取模时机**：$\text{total} \le 10^{10}$ 超 32 位 int，C++ 用 `long long` 累加；$\text{total} - \text{maxGain} \ge 0$ 恒成立（$\text{maxGain} \le \max_i d_i \le \text{total}$），故全程不取模、**只在 return 处一次性取模**最稳。Python 整数无溢出，直接算。
5. **桶加速备选**：值域 $\le 10^5$，也可对 `nums1` 建 `exist[V+1]` 布尔桶，对每个 $t$ 从 $t$ 向两侧扩散找最近的存在值，整体 $O(n + V)$。赛时若担心二分边界写挂可用，但通常「排序 + `lower_bound`」更短更稳。

## 5. 正确性证明

**引理 1**（替换的局部性）：设替换发生在位置 $j$（把 $\text{nums1}[j]$ 的值改为 $v$），则差值和中仅第 $j$ 项由 $d_j$ 变为 $|\,v - \text{nums2}[j]\,|$，其余各项不变。

**证明**：差值和的每一项 $|\text{nums1}[i] - \text{nums2}[i]|$ 只依赖下标 $i$ 处的两个值，替换仅改变 $\text{nums1}[j]$，对 $i \ne j$ 的项无影响。∎

**引理 2**（夹板性质）：设 `sorted1` 为升序数组，$t$ 为任意目标，$p$ 为首个 $\ge t$ 的元素下标，则 $\min_k |\text{sorted1}[k] - t|$ 在 $k \in \{p-1,\ p\}$（存在者）处取得。

**证明**：分三种情况。若 $p = n$：无元素 $\ge t$，一切 $k$ 有 $\text{sorted1}[k] < t$，距离 $t - \text{sorted1}[k]$ 随 $k$ 递增而减小，最小在 $k = n-1$。若 $p = 0$：一切 $k$ 有 $\text{sorted1}[k] \ge t$，距离 $\text{sorted1}[k] - t$ 随 $k$ 递增而增大，最小在 $k = 0$。若 $0 < p < n$：$\text{sorted1}[p-1] < t \le \text{sorted1}[p]$；对任意 $k \le p-1$，$\text{sorted1}[k] \le \text{sorted1}[p-1] < t$，距离 $t - \text{sorted1}[k] \ge t - \text{sorted1}[p-1]$；对任意 $k \ge p$，$\text{sorted1}[k] \ge \text{sorted1}[p] \ge t$，距离 $\text{sorted1}[k] - t \ge \text{sorted1}[p] - t$。故最小距离必在 $k = p-1$ 或 $k = p$ 处取得。∎

**引理 3**（gain 非负）：对每个 $i$，$\text{gain}_i = d_i - \min_k |\text{sorted1}[k] - \text{nums2}[i]| \ge 0$。

**证明**：$\text{nums1}[i]$ 的值出现在 `sorted1` 中（排序不改变值集合），取该处为 $k$ 即得 $\min_k |\text{sorted1}[k] - \text{nums2}[i]| \le |\text{nums1}[i] - \text{nums2}[i]| = d_i$。∎

**定理**（算法正确性）：算法返回值 $\left(\text{total} - \max_i \text{gain}_i\right) \bmod (10^9+7)$ 是最优的绝对差值和。

**证明**：任一替换方案（含不替换）由引理 1 可表示为新总和 $\text{total} - (d_j - d_j')$，其中 $d_j'$ 为位置 $j$ 换后差值。最小化新总和等价于最大化 $d_j - d_j'$。对每个固定的 $j$，候选值集合恰为 `nums1` 的全部值（与 `sorted1` 的值集合相同），由引理 2，最优 $d_j' = \min_k |\text{sorted1}[k] - \text{nums2}[j]|$ 由二分 + 两候选比较求得，故单个位置的最大可减小量恰为 $\text{gain}_j$。又「不替换」对应 $d_j' = d_j$（减小量 0），由引理 3 有 $\max_j \text{gain}_j \ge 0$，不替换方案天然被覆盖。故全局最优值 $= \text{total} - \max_j \text{gain}_j$，算法输出即最优值取模。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序 $O(n \log n)$；主循环 $n$ 次，每次一次二分 $O(\log n)$ 与两次候选比较 $O(1)$，合计仍为 $O(n \log n)$。对比暴力 $O(n^2) \approx 10^{10}$：$n = 10^5$ 时约 $10^5 \times 17 \approx 1.7 \times 10^6$ 次基本操作，快约四个数量级。
- **空间复杂度**：$O(n)$。`sorted1` 副本占 $O(n)$；排序递归栈 $O(\log n)$ 被吸收。若原地排序会破坏原差值计算（见 §4 第 1 条），这 $O(n)$ 不能省。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minAbsoluteSumDiff(vector<int>& nums1, vector<int>& nums2) {
        const int MOD = 1e9 + 7;
        int n = nums1.size();
        vector<int> sorted1(nums1);
        sort(sorted1.begin(), sorted1.end());

        long long total = 0;
        int maxGain = 0;
        for (int i = 0; i < n; ++i) {
            int d = abs(nums1[i] - nums2[i]);
            total += d;

            auto it = lower_bound(sorted1.begin(), sorted1.end(), nums2[i]);
            int best = d;  // j = i（不替换）入候选 => gain >= 0，兼护 p 的两个边界
            if (it != sorted1.end())
                best = min(best, abs(*it - nums2[i]));
            if (it != sorted1.begin())
                best = min(best, abs(*(it - 1) - nums2[i]));

            maxGain = max(maxGain, d - best);
        }
        return (int)((total - maxGain) % MOD);
    }
};
```

### Python

```python
class Solution:
    def minAbsoluteSumDiff(self, nums1: List[int], nums2: List[int]) -> int:
        from bisect import bisect_left
        MOD = 10**9 + 7
        sorted1 = sorted(nums1)
        n = len(nums1)

        total = 0
        max_gain = 0
        for i in range(n):
            d = abs(nums1[i] - nums2[i])
            total += d
            p = bisect_left(sorted1, nums2[i])
            best = d  # j = i（不替换）入候选 => gain >= 0，兼护 p 的两个边界
            if p < n:
                best = min(best, abs(sorted1[p] - nums2[i]))
            if p > 0:
                best = min(best, abs(sorted1[p - 1] - nums2[i]))
            max_gain = max(max_gain, d - best)

        return (total - max_gain) % MOD
```

> ⚠️ 两版刻意保持同构：`best` 初始化为 `d` 之后，`p` 的边界检查只需「存在才比较」，不存在任何空候选分支；`total` 全程不取模，最后一步 `(total - maxGain) % MOD` 一次完成。

## 8. 边界情况与易错点

1. **`total` 溢出（本题最高频翻车点）**：$n \cdot \max|\text{diff}| \le 10^5 \times (10^5 - 1) \approx 10^{10}$，超 32 位 int 上限约 $2.1 \times 10^9$。C++ 必须 `long long` 累加；`d`、`best`、`maxGain` 本身 $\le 10^5$ 用 int 即可，但**参与减法时留意整体类型提升**。
2. **取模时机**：中途对 `total` 取模再减 `maxGain` 可能得到负数（`maxGain` 未经取模），需 `+MOD` 修正。最稳写法：全程裸累加，return 处 `(total - maxGain) % MOD`——由引理 3 括号内恒非负，直接取模无坑。
3. **`p` 的两个边界**：`p = 0` 时 `sorted1[p-1]` 是 `sorted1[-1]`——Python 里**不报错**而是静默取到末元素，C++ 里是未定义行为，双双埋雷；`p = n` 时 `sorted1[p]` 同理。两个候选都要「存在才比较」。
4. **不能原地排序 `nums1`**：原差值 $d_i$ 与 `total` 依赖原始配对，排了序 `nums1[i]` 对 `nums2[i]` 就串位了。排序的只是**副本**。
5. **`maxGain` 初始化为 0 而非极小值**：不替换是合法方案（引理 3 保证 $\text{gain} \ge 0$），初始 0 自然涵盖「换了反而更差 → 不换」的全部分支；示例 2（两数组相等）全程 `gain = 0`，靠这个初值直接返回 0。
6. **候选集包含 `nums1[i]` 自身**：题目允许用 `nums1` 中**任意**元素替换，$j = i$ 合法。这不是废话——它是 `gain ≥ 0` 的根源，也让 `best` 的初值有了语义。
7. **答案别提前取模参与比较**：若先算 `(total % MOD)` 再与 `maxGain` 运算，逻辑虽可修但极易出负数坑（见第 2 条）；全程只在最后取一次模。
