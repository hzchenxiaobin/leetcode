# LeetCode 按奇偶排序数组 II 题解

## 1. 题目概述

- **标题 / 题号**：按奇偶排序数组 II（#922，easy）
- **链接**：https://leetcode.cn/problems/sort-array-by-parity-ii/
- **来源**：LeetCode 第 106 场周赛 Q1
- **难度**：简单
- **标签**：数组、双指针、排序

**题意**：给定一个非负整数数组 `nums`，长度一定是偶数，且**恰好一半是偶数、一半是奇数**。把数组重排，使得「偶数出现在偶数下标、奇数出现在奇数下标」。返回**任一**合法数组即可，原地修改也是允许的。

本题的关键不在于「怎么排」，而在于「题目已经保证了可排」：一半偶一半奇，恰好能填满 $k$ 个偶数位与 $k$ 个奇数位。

**约束**：

- $2 \le \text{nums.length} \le 2 \times 10^4$，且长度为偶数
- `nums` 中一半是偶数、一半是奇数（题目保证，无需自行校验）
- $0 \le \text{nums}[i] \le 1000$
- **进阶**：能否**不使用额外空间**解决？

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,5,7]
输出：[4,5,2,7]
解释：[4,7,2,5]、[2,5,4,7]、[2,7,4,5] 等任意合法排列都会被接受。
```

**示例 2**

```text
输入：nums = [2,3]
输出：[2,3]
解释：只有一个偶数位（下标 0）和一个奇数位（下标 1），已经就绪。
```

**示例 3（补充）**

```text
输入：nums = [2,4,6,1,3,5]
输出：[2,1,4,3,6,5]
解释：偶数位 0、2、4 放 2、4、6；奇数位 1、3、5 放 1、3、5。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是「先分离、再拼接」：扫一遍把偶数放进数组 $A$、奇数放进数组 $B$，再按 $A[0], B[0], A[1], B[1], \dots$ 写回结果。时间 $O(n)$、空间 $O(n)$，逻辑毫无风险，但恰好落在题目「进阶」的反面——$2 \times 10^4$ 虽然放得下，可它并不是本题想考的点。

更笨的枚举法（尝试所有排列）是 $O(n!)$，显然不可行。介于两者之间的是「排序后交错取数」，同样是 $O(n \log n)$ 的额外代价，也不必要。

### 3.2 核心观察：两处错位相邻而居，一次交换同时修复

![错位互换：一次 swap 同时修好两个下标](images/wc106_q1_two_pointer_concept.svg)

把「合法」翻译成可检测的条件：对每个下标 $i$，要求
$$\text{nums}[i] \bmod 2 = i \bmod 2$$
即**偶数下标上必须是偶数、奇数下标上必须是奇数**。

现在只看偶数下标这一条线。让指针 $i$ 以步长 2 前进，扫过 $0, 2, 4, \dots$：

- 若 `nums[i]` 是偶数 → 该位置已经正确，$i \leftarrow i + 2$；
- 若 `nums[i]` 是奇数 → 这里**多了一个奇数、少了一个偶数**。

由于全局「奇数总数 = 奇数位总数」，一次「奇数跑到偶数位」必然伴随一次「偶数跑到奇数位」。于是让另一个指针 $j$ 以步长 2 扫奇数下标 $1, 3, 5, \dots$：一旦发现 `nums[j]` 是偶数，就说明找到了那个「跑错地方」的偶数。此时
$$\text{swap}(\text{nums}[i], \text{nums}[j])$$
一步就能同时修好 $i$ 与 $j$ 两处错位——这是本题最漂亮的一点：**错误总是成对出现，且交换不会破坏任何已正确的位置**。

### 3.3 算法流程

![算法流程：i 步进 2，只在错位时回看 j](images/wc106_q1_algorithm_flow.svg)

```text
1. i = 0, j = 1
2. while i < n:
       if nums[i] % 2 == 0:      i += 2          # 偶数位正确
       elif nums[j] % 2 == 1:    j += 2          # 奇数位正确
       else:
           swap(nums[i], nums[j])                # 两处错位一起修
           i += 2
           j += 2
3. 返回 nums
```

注意 `while` 的条件只看 $i$，因为**偶数位是「主动」扫描的对象**，$j$ 只在需要时才被动前进。返回的是原地修改后的 `nums`。

### 3.4 示例演算

![示例演算：一次交换完成](images/wc106_q1_walkthrough.svg)

对 `nums = [4,2,5,7]`：

| 步骤 | i | j | 判断 | 动作 | nums |
|------|---|---|------|------|------|
| 1 | 0 | 1 | `nums[0] = 4` 是偶数 | `i += 2` | `[4,2,5,7]` |
| 2 | 2 | 1 | `nums[2] = 5` 是奇数；`nums[1] = 2` 是偶数 | `swap(2,1)`，`i+=2`，`j+=2` | `[4,5,2,7]` |
| 3 | 4 | 3 | `i = 4 = n`，退出 | 返回 | `[4,5,2,7]` |

结果 `[4,5,2,7]` 与官方示例输出完全一致。

## 4. 算法细节

1. **双指针分工**：$i$ 只走偶数下标、$j$ 只走奇数下标，二者的「奇偶职责」不会互相污染；交换的是值而不是下标，指针本身不需要回退。
2. **为什么 $j$ 不会越界**：当 `nums[i]` 是奇数时，$i$ 是偶数下标；既然「偶数总数 = 偶数位总数」，那么在偶数位上出现奇数的同时，奇数位上必然还留着一个「多余的偶数」等待交换。因此 $j$ 一定能在 $< n$ 的奇数下标内找到它（形式化见引理 2）。
3. **交换后两个指针都 +2**：$i$ 位变成偶数、$j$ 位变成奇数，两个位置同时转为正确，无需再检查。
4. **终止条件**：只有 $i$ 会「卡住」，而每次卡住必然消费一次交换并推进 $i$，故循环必然终止。
5. **不需要排序**：题目只要求「奇偶就位」，不要求有序，任何多余排序都是白花的 $O(n \log n)$。

## 5. 正确性证明

**引理 1（交换的局部正确性）**：设 $i$ 为偶数下标且 `nums[i]` 为奇数，$j$ 为奇数下标且 `nums[j]` 为偶数。交换二者后，$i$ 位为偶数、$j$ 位为奇数，且数组其他位置不变。

**证明**：交换只是把 $i$、$j$ 两处的值对调。$i$ 位原本是奇数，交换后得到 $j$ 位原来的偶数值；$j$ 位原本是偶数，交换后得到 $i$ 位原来的奇数值。其余下标未被触碰。又 $i$ 是偶数下标、$j$ 是奇数下标，故两位同时满足「偶位放偶、奇位放奇」。∎

**引理 2（配对存在性）**：只要存在某个偶数下标 $i$ 使 `nums[i]` 为奇数，就必然存在某个奇数下标 $j$ 使 `nums[j]` 为偶数。

**证明**：设偶数总数 $= E$、奇数总数 $= O$，由题设 $E = O = k$，偶数下标共 $k$ 个、奇数下标共 $k$ 个。假设所有奇数下标的数都是奇数，则奇数下标上共有 $k$ 个奇数；而偶数下标上还有一个奇数（即 `nums[i]`），于是奇数总数 $\ge k + 1 > k = O$，矛盾。故必存在奇数下标 $j$ 上放着偶数。∎

**引理 3（已正确位置不被破坏）**：算法推进过程中，凡是被指针越过的位置始终保持正确。

**证明**：对 $i$ 归纳。$i$ 只在「`nums[i]` 为偶数」或「交换之后」推进，两种情况下 $i$ 位均为偶数，此后 $i$ 不再回头，且交换只在 $i' \ge i$、$j' \ge j$ 处发生，不会改动已越过的位置。对 $j$ 同理：$j$ 只在「`nums[j]` 为奇数」或交换后推进，均有 $j$ 位为奇数，且此后不回头。∎

**定理**：算法终止时，数组满足「偶数下标放偶数、奇数下标放奇数」。

**证明**：由引理 3，算法结束时所有 $< i$ 的偶数下标都正确。终止条件为 $i \ge n$，而 $i$ 每次 $+2$ 且从 $0$ 出发，故所有偶数下标都被越过、全部正确。由引理 2，每次 $i$ 卡在奇数上时 $j$ 都能找到配对，因此不存在「循环卡死」的情形。又引理 1 保证每次交换让 $i$、$j$ 两位同时正确，交换后 $i$、$j$ 各 $+2$，被越过的奇数下标也全部正确。于是每个下标都满足 $\text{nums}[i] \bmod 2 = i \bmod 2$，即数组合法。∎

## 6. 复杂度分析

- **时间**：$O(n)$。指针 $i$ 与 $j$ 都只单向前进，合计最多走 $n$ 步；每一步是常数次取模与比较。
- **空间**：$O(1)$。只用两个整型指针，原地交换，满足题目的进阶要求（若用「分离数组」写法则为 $O(n)$）。
- **常数**：每步最多两次 `% 2`，实际运行时间接近线性扫描的下限。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> sortArrayByParityII(vector<int>& nums) {
        int n = (int)nums.size();
        int i = 0, j = 1;          // i 只扫偶数下标，j 只扫奇数下标
        while (i < n) {
            if (nums[i] % 2 == 0) {
                i += 2;            // 偶数位已放偶数，前进
            } else if (nums[j] % 2 == 1) {
                j += 2;            // 奇数位已放奇数，前进
            } else {
                swap(nums[i], nums[j]);   // 两个错位位置互换，一次修复两处
                i += 2;
                j += 2;
            }
        }
        return nums;
    }
};
```

### Python

```python
class Solution:
    def sortArrayByParityII(self, nums: list[int]) -> list[int]:
        n = len(nums)
        i, j = 0, 1                    # i 扫偶数下标，j 扫奇数下标
        while i < n:
            if nums[i] % 2 == 0:
                i += 2
            elif nums[j] % 2 == 1:
                j += 2
            else:
                nums[i], nums[j] = nums[j], nums[i]
                i += 2
                j += 2
        return nums
```

## 8. 边界情况与易错点

1. **「返回任一答案」不等于「随便返回」**：判题器会校验每个下标上的奇偶性，必须真正合法；不能只交换相邻元素了事。
2. **`while` 条件只看 $i$**：有人写成 `while i < n and j < n`，理论上也能过，但会掩盖「$j$ 由数量关系保证不越界」这一关键事实，容易在变体题上出错。
3. **两处 `i += 2` 都要写**：`if` 分支与 `else` 分支各一次，漏掉 `else` 里的会让循环卡在原地。
4. **别用排序**：`sort` 之后再交错取数会破坏原有奇偶对应关系，还得额外判断，纯属自找麻烦。
5. **最小用例 `[2,3]`**：长度 2 时 $i = 0$ 直接前进，$j$ 从头到尾不动，注意别在初始化时就越界访问 `nums[1]`（长度为 2 时下标 1 合法，但长度为 0 的假设不成立，题目保证 $\ge 2$）。
6. **值为 0**：$0$ 是偶数，`0 % 2 == 0` 成立，不要写成 `nums[i] % 2 == 0 and nums[i] != 0` 之类的多余特判。
