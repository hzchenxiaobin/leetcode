# LeetCode 使括号有效的最少添加 题解

## 1. 题目概述

- **标题 / 题号**：使括号有效的最少添加（#921，medium）
- **链接**：https://leetcode.cn/problems/minimum-add-to-make-parentheses-valid/
- **来源**：LeetCode 第 106 场周赛 Q2
- **难度**：中等
- **标签**：栈、贪心、字符串、括号序列

**题意**：给定只含 `(` 与 `)` 的字符串 `s`。一次操作可以在**任意位置**插入一个括号（左括号或右括号）。返回使 `s` 变成**有效括号串**所需的最少插入次数。有效括号串的定义是：空串、两个有效串相接、或形如 `(A)`（$A$ 有效）。

**约束**：

- $1 \le \text{s.length} \le 1000$
- `s` 只包含 `(` 和 `)` 字符

**直觉**：插入是「单边修补」，只能在缺的地方补。真正要做的是**数清楚缺多少个左括号、缺多少个右括号**。

## 2. 示例

**示例 1**

```text
输入：s = "())"
输出：1
解释：右侧多出一个 ')'，在左侧补一个 '(' 得到 "()()" 或 "(())-"，最少 1 次。
```

**示例 2**

```text
输入：s = "((("
输出：3
解释：三个 '(' 都缺右括号，补 3 个 ')' 即可。
```

**示例 3（补充）**

```text
输入：s = ")("
输出：2
解释：最左的 ')' 缺左括号、最右的 '(' 缺右括号，两边各补 1 个。
```

**示例 4（补充）**

```text
输入：s = "()))(("
输出：4
解释：中间多 2 个 ')'、末尾多 2 个 '('。
```

## 3. 解题思路

### 3.1 暴力思路

插入位置有 $O(n)$ 种、插入两种括号、要插几次未知——直接搜索的状态空间是 $O(n^3)$ 起步的，而且「最少」需要 BFS 才能保证正确：把每个字符串视作状态，每次在任意位置插入一个括号，找出第一次变为有效串的层数。长度到 $1000$ 时这条路完全不可行。

换个角度：既然是**插入**而不是删除或替换，插入不会破坏原有的任何字符匹配关系。因此最优策略一定是「在必要的地方补最少的括号」，问题变成**找出所有「无法被匹配」的括号**。

### 3.2 核心观察：两类失衡互不相干，答案就是它们的和

![栈的高度 ↔ 未匹配括号：两种缺失分开数](images/wc106_q2_balance_concept.svg)

扫描字符串，维护一个计数器 `open`＝当前**尚未被匹配的左括号个数**（等价于栈的大小）：

- 遇到 `(`：`open += 1`，它等着将来被配对；
- 遇到 `)`：
  - `open > 0`：与最近一个未配对的 `(` 配对，`open -= 1`；
  - `open == 0`：**前面已经没有 `(` 可以配它**。这个 `)` 无论怎么插都救不回来，只能在它左边补一个 `(`，故 `needRight += 1`。

扫完之后，`open` 个左括号还悬着，各自需要补一个 `)` 收尾。

于是答案就是
$$\text{needRight} + \text{open}$$
两个量是**两种不同的缺失**：`needRight` 数的是「左侧缺 `(`」的右括号，`open` 数的是「右侧缺 `)`」的左括号。它们位于扫描线的两侧，不会互相抵消，所以可以放心相加。

### 3.3 算法流程

![算法流程：单遍扫描](images/wc106_q2_algorithm_flow.svg)

```text
1. open = 0, needRight = 0
2. for c in s:
       if c == '(':        open += 1
       elif open > 0:      open -= 1
       else:               needRight += 1
3. 返回 needRight + open
```

整个过程只用两个整数，$O(1)$ 额外空间。

### 3.4 示例演算

![示例演算："())" 与 "((("](images/wc106_q2_walkthrough.svg)

`s = "())"`：

| 字符 | open | needRight | 说明 |
|------|------|-----------|------|
| `(` | 1 | 0 | 悬空左括号 +1 |
| `)` | 0 | 0 | 与它配对 |
| `)` | 0 | 1 | 无可配，补一个 `(` |
| 结束 | 0 | 1 | 答案 $1 + 0 = 1$ |

`s = "((("`：三个 `(` 全部悬空，`open = 3`、`needRight = 0`，答案 $0 + 3 = 3$。

`s = ")("`：第一个 `)` 使 `needRight = 1`，接着 `(` 使 `open = 1`，答案 $1 + 1 = 2$——注意这里两个量同时非零，正说明「两侧都缺」是真实存在的。

## 4. 算法细节

1. **`open` 的语义**：它是「当前前缀中未匹配的 `(` 个数」。由于括号匹配的**最近配对原则**，栈的具体内容无关紧要，只需栈的大小，所以一个整数足够——这就是本题从 $O(n)$ 空间栈优化到 $O(1)$ 的关键。
2. **为什么不用真的建栈**：只有一种括号、且匹配只依赖数量关系（任意前缀中 `)` 的个数不能超过 `(` 的个数），所以计数即等价于栈。
3. **加法顺序无关**：`needRight` 与 `open` 分别对应前缀与后缀的缺失，互不影响；最后一次性相加即可。
4. **不要尝试「先统计总 '(' 与总 ')' 的差」**：`")("` 的总数相等但答案是 2，光看总数会得到 0，是典型错解。
5. **类型**：`s.length ≤ 1000`，答案不超过 1000，`int` 足够，无需 `long long`。

## 5. 正确性证明

先引入两个定义。设扫描到位置 $t$ 时，`open` 的值为 $o_t$，`needRight` 的值为 $r_t$。

**引理 1（前缀下界）**：对 `s` 的任意前缀 $p$，设其中 `)` 的个数为 $a$、`(` 的个数为 $b$。为让该前缀成为「合法括号串的某个前缀」，至少要在其左侧补 $\max(0, a - b)$ 个 `(`。

**证明**：合法括号串的任意前缀中，`)` 的个数不能超过 `(` 的个数。前缀 $p$ 内部 `)` 比 `(` 多出 $a - b$ 个（若为正），这些 `)` 在 $p$ 内部找不到配对，只能靠**从左侧插入**的 `(` 来配。每次插入至多消掉一个多余的 `)`，故至少需要 $a - b$ 个。∎

**引理 2（$r_t$ 的正确性）**：扫描完前 $t$ 个字符后，$r_t$ 恰等于「前 $t$ 个字符中，必须从左侧补入的 `(` 的最少个数」，且
$$r_t = \max_{0 \le k \le t}\bigl(\#)_k - \#(_k\bigr)$$
其中 $\#)_k$、$\#(_k$ 分别表示前 $k$ 个字符中 `)` 与 `(` 的个数。

**证明**：对 $t$ 归纳。$t = 0$ 时 $r_0 = 0$，公式给出 $0$。设前 $t$ 步成立，考察第 $t+1$ 个字符：

- 若是 `(`，则 $o_{t+1} = o_t + 1$、$r_{t+1} = r_t$；公式右侧的 $\#) - \#($ 减小 $1$，最大值不可能变大，仍是 $r_t$，一致。
- 若是 `)`：若 $o_t > 0$，说明该 `)` 能被前面的 `(` 配掉，不需要补，$r_{t+1} = r_t$；此时 $\#) - \#($ 增加 $1$ 但不超过历史最大值（因为 $o_t > 0$ 意味着历史上 `(` 至少多出一个），公式不变。若 $o_t = 0$，则该 `)` 无人可配，$r_{t+1} = r_t + 1$，公式的 $\#) - \#($ 达到新的最大值，同样 $+1$。∎

**引理 3（$o_t$ 的正确性）**：$o_t$ 等于前 $t$ 个字符中「已配对的括号之外、剩余的 `(` 个数」，即 $\#(_t - \#)_t + r_t$，它也等于「为使前 $t$ 个字符成为合法前缀，在末尾还需补的 `)` 个数」的下界。

**证明**：每个 `)` 要么消耗一个 `(`（当 $o > 0$），要么被 `needRight` 记账（当 $o = 0$）。因此 $\#(_t = o_t + (\text{已配对数})$、$\#)_t = r_t + (\text{已配对数})$，两式相减即得 $o_t = \#(_t - \#)_t + r_t$。这 $o_t$ 个 `(` 在字符串内部找不到配对的 `)`，只能在其**右侧**补 `)`，故至少需要 $o_t$ 个。∎

**定理**：$\text{needRight} + \text{open}$ 既是可行解，也是最优解，即答案恰为 $r_n + o_n$。

**证明**：

*可行性*：由引理 2，在原串最左侧补 $r_n$ 个 `(`；由引理 3，在最右侧补 $o_n$ 个 `)`。补完后，任意前缀中 `)` 的个数都不超过 `(` 的个数（左侧补齐后前缀性质成立），且总数相等（$(\#( + r_n) - (\#) + o_n) = (o_n + r_n) - (r_n + o_n) = 0$），故为合法括号串。因此答案 $\le r_n + o_n$。

*最优性*：任何解都必须处理引理 2 中「前缀 `)` 超出」的那些 `)`，至少补 $r_n$ 个 `(`；同理必须处理引理 3 中悬空的 $o_n$ 个 `(`，至少补 $o_n$ 个 `)`。且被补的 `(` 与 `)` 是两类不同的字符，无法用同一个插入同时满足两个下界。故答案 $\ge r_n + o_n$。

两者结合，答案 $= r_n + o_n$，正是算法返回值。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每个字符一次比较、至多一次加法或减法。
- **空间**：$O(1)$，只用 `open` 与 `needRight` 两个整型（若显式建栈则为 $O(n)$）。
- **常数**：单次分支判断，实测 $n = 1000$ 时微秒级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minAddToMakeValid(string s) {
        int needRight = 0;  // 无法匹配的右括号个数（必须在其左侧补 '('）
        int open = 0;       // 当前未匹配的左括号个数
        for (char c : s) {
            if (c == '(') {
                open++;
            } else if (open > 0) {
                open--;         // 与最近的未匹配 '(' 配对
            } else {
                needRight++;    // 前面没有 '(' 可配，必须补一个 '('
            }
        }
        return needRight + open;  // 尾部残留的 '(' 各补一个 ')'
    }
};
```

### Python

```python
class Solution:
    def minAddToMakeValid(self, s: str) -> int:
        need_right = 0     # 必须从左侧补的 '(' 数量
        open_cnt = 0       # 当前未被匹配的 '(' 数量
        for c in s:
            if c == '(':
                open_cnt += 1
            elif open_cnt > 0:
                open_cnt -= 1
            else:
                need_right += 1
        return need_right + open_cnt   # 尾部残留的 '(' 各补一个 ')'
```

## 8. 边界情况与易错点

1. **只数总数会错**：`")("` 的 `(` 与 `)` 数量相等，但答案是 2，因为顺序错了。必须扫描过程中就判断。
2. **`open` 不能为负**：遇到 `)` 时若 `open == 0`，绝不能写成 `open -= 1`，那会把「缺左括号」错记成「多左括号」，答案直接错。
3. **两个量都要加**：只返回 `needRight` 会漏掉 `"((("` 这类全是左括号的用例（答案 3）。
4. **全部合法的用例**：`"()"`、`""`（虽然题目 $n \ge 1$）、`"()()"`，答案均为 0，注意初始值不要写成 1。
5. **插入位置合法**：本题允许在**任意位置**插入，所以「最左补 `(`、最右补 `)`」总是合法的；若题目改成「只能在两端插入」答案不变，若改成「只能追加」，则最优值会不同。
6. **长度上限 1000**：答案最大 1000，`int` 完全足够；即使换成 $10^9$ 长度，计数也只需要 `long long`，算法本身不变。
