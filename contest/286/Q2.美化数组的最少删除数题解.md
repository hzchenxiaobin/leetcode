# LeetCode 美化数组的最少删除数 题解

## 1. 题目概述

- **标题 / 题号**：美化数组的最少删除数（#2216，medium）
- **链接**：https://leetcode.cn/problems/minimum-deletions-to-make-array-beautiful/
- **来源**：LeetCode 第 286 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、栈

**题意**：给定下标从 0 开始的整数数组 `nums`。「美丽数组」需同时满足：① 长度为**偶数**；② 所有**偶数下标** $i$ 满足 $\text{nums}[i] \ne \text{nums}[i+1]$（空数组也认为是美丽数组）。每次可以删除任意一个元素，被删元素右侧的所有元素整体左移一格。求使 `nums` 变为美丽数组的最少删除数。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $0 \le \text{nums}[i] \le 10^5$ —— 值域对本题无影响（只用到相邻元素的相等性判断），提示解法与数值大小无关

> 💡 **关键转译**：删除后保留下来的元素恰好构成原数组的一个**子序列**，「美丽数组」条件等价于——把保留元素按顺序两两分组 $(\text{第}1,2\text{个}),(\text{第}3,4\text{个}),\dots$，每组内两值不同。于是问题变成：**保留一个尽量长的子序列使其能如此配对**，答案 $= n - \text{保留长度}$。这是本题一切思路的出发点。

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,2,3,5]
输出：1
解释：删除 nums[0]（或 nums[1]），得到 [1,2,3,5]：长度 4 为偶数，
     配对 (1,2)、(3,5) 均不相等，是美丽数组。
```

**示例 2**

```text
输入：nums = [1,1,2,2,3,3]
输出：2
解释：删除 nums[0] 与 nums[5]，得到 [1,2,2,3]：配对 (1,2)、(2,3) 均不相等。
     注意保留流中两个 2 虽相邻，但落在 (奇, 偶) 位，不构成一对，完全合法。
```

**补充示例（全相等）**

```text
输入：nums = [7,7,7,7]
输出：4
解释：任何配对都是 (7,7)，一对也配不成，只能全部删空（空数组也是美丽数组）。
```

**补充示例（尾部落单）**

```text
输入：nums = [1,2,3]
输出：1
解释：[1,2] 配对成功后，尾部 3 落单——奇数长度必须再删一个（删 3 或删 1 均可）。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个元素删/不删，共 $2^n$ 种组合，逐一检查保留子序列能否按「(1,2)(3,4)…」配对且对内不等——$n \le 10^5$ 直接爆炸。退一步做记忆化搜索：状态为（当前下标 $i$，已保留个数的奇偶 $p$，若 $p$ 为奇数还需记「最后一个保留元素的值 $v$」），转移合法但 $v$ 这一维让状态数达到 $O(n \cdot V)$，代价高昂。而下面的观察表明，这维状态可以被彻底消掉：**每一步的最优决策只取决于当前流最前面的两个元素，根本不需要回看历史**。

### 3.2 核心观察：从左到右贪心配对，撞上相等才删

![核心观察：保留流两两配对、撞相等必删其一](images/2216_min_deletion_pairing_concept.svg)

最终保留流按位置 $(0,1),(2,3),\dots$ 配对，对内必须不等。维护「当前配对起点」指针 $i$（**始终指向当前流的偶数位**），从左到右扫描：

- 若 $\text{nums}[i] \ne \text{nums}[i+1]$：这两个元素**立即锁成一对**，$i \mathrel{+}= 2$；
- 若 $\text{nums}[i] == \text{nums}[i+1]$：这两个相等的元素**必删其一**（§5 引理 2），且删左删右得到的数组**逐位相同**（§5 引理 3），不存在选错的风险，$i \mathrel{+}= 1$；
- 扫描结束后若剩一个落单元素，再删它，保证长度为偶数。

两个支撑直觉：

1. **配对成功时不亏**：把 $(\text{nums}[i], \text{nums}[i+1])$ 锁成一对后，后续元素从「新的一对」的起点继续，等价于规模减 2 的同构子问题（§5 情形 B 会严格化）；
2. **相等时无分歧**：相邻且值相等的两个元素删谁都一样，这一步**不存在选择错误的可能性**——贪心最怕「局部选择影响全局」，而这一步天然免疫。

### 3.3 算法流程

![算法流程：双指针贪心流程图](images/2216_min_deletion_flow.svg)

1. 初始化 $i = 0$，$\text{ans} = 0$；
2. 循环：若 $i + 1 \ge n$（凑不出两个元素）则跳出；
3. 若 $\text{nums}[i] == \text{nums}[i+1]$：$\text{ans} \mathrel{+}= 1$，$i \mathrel{+}= 1$（删一个，右侧元素滑入补位，继续在新偶位上比较）；
4. 否则：$i \mathrel{+}= 2$（配对成功，跳到下一对起点）；
5. 循环结束后若 $i == n-1$（剩一个落单元素）：$\text{ans} \mathrel{+}= 1$；
6. 返回 $\text{ans}$。

**不变量**：$i$ 始终是当前流的偶数位。$i \mathrel{+}= 2$ 保持偶位；$i \mathrel{+}= 1$ 发生在删除 $\text{nums}[i]$ 之后，原 $\text{nums}[i+1]$ 恰好顶到偶位——两种步进都维持不变量。

### 3.4 示例演算

![示例演算：双指针逐步走查](images/2216_min_deletion_walkthrough.svg)

以示例 2 演算 `nums = [1,1,2,2,3,3]`：

| 步 | 指针 $i$ | 比较（当前流下两位） | 动作 | ans |
|----|------|------|------|-----|
| 1 | 0 | $\text{nums}[0]{=}1$ 与 $\text{nums}[1]{=}1$ 相等 | 删 $\text{nums}[0]$，$i \to 1$ | 1 |
| 2 | 1 | $\text{nums}[1]{=}1$ 与 $\text{nums}[2]{=}2$ 不等 | 配成对①，$i \to 3$ | 1 |
| 3 | 3 | $\text{nums}[3]{=}2$ 与 $\text{nums}[4]{=}3$ 不等 | 配成对②，$i \to 5$ | 1 |
| 4 | 5 | $i{+}1=6$ 越界，无伙伴可配 | 删落单的 $\text{nums}[5]$，结束 | 2 |

保留流 $[1,2,2,3]$：长度 4 为偶数，对① $(1,2)$、对② $(2,3)$ 对内均不等 ✓，与官方答案一致。

## 4. 算法细节

1. **为什么只比较 $\text{nums}[i]$ 与 $\text{nums}[i+1]$**：配对条件只约束「当前流中相邻两位」。扫描过程中所有被删元素的下标都 $\le i$，下标 $i, i+1, i+2, \dots$ 的元素**全部存活**，因此原数组的 $\text{nums}[i]$ 与 $\text{nums}[i+1]$ 恰好就是当前流的下两位（偶位与奇位），直接比较即可，无需真的做元素删除与左移。
2. **删除的语义等价**：相等分支里删的是 $\text{nums}[i]$，也可以视作删 $\text{nums}[i+1]$——两值相同，删后数组逐位一致（引理 3），实现上任选其一。
3. **「栈」视角**：本题标签含 Stack。等价实现是奇偶扫描：维护一个**深度恒 $\le 1$ 的栈**（当前落单元素 `prev`）。元素 $x$ 到达时：栈空 → 压栈（$x$ 成为新落单元素）；栈顶 $\ne x$ → 弹栈（配对成功）；栈顶 $== x$ → 删除 $x$（栈不动）。栈深不超过 1，退化为一个变量，这就是「标签是栈、代码里却没有栈」的原因。
4. **答案的两部分**：扫描中的删除（撞相等）+ 末尾落单补刀，两部分相加才是完整答案，缺一不可。
5. **原地性**：整个算法只读 `nums`，不修改原数组，「左移补位」只是脑内模拟。

## 5. 正确性证明

先约定：保留流的位置从 1 开始编号（槽 1, 槽 2, …），配对为 (槽 1, 槽 2), (槽 3, 槽 4), …；「合法方案」指一个使保留流成为美丽数组的删除集合，$\text{OPT}$ 为最优方案的删除数。

**引理 1（首元素必居首槽）**：任何合法方案中，若 $\text{nums}[0]$ 被保留，它必居保留流的槽 1；此时若 $\text{nums}[1]$ 也被保留，它必居槽 2，二者恰好配成一对。

**证明**：保留子序列保持相对顺序，$\text{nums}[0]$ 是全数组第一个元素，若被保留必为保留流首个元素（槽 1）；$0$ 与 $1$ 之间无其他元素，$\text{nums}[1]$ 若被保留必为下一个保留元素（槽 2）。槽 (1, 2) 恰是一对。∎

**引理 2（相等首对必删其一）**：若 $\text{nums}[0] == \text{nums}[1]$，则任何合法方案至少删除这两个元素中的一个。

**证明**：反设两者都保留，由引理 1 它们占据槽 (1, 2) 构成一对，要求两值不同，与相等矛盾。∎

**引理 3（删左删右等价）**：若 $\text{nums}[0] == \text{nums}[1] == x$，则「删 $\text{nums}[0]$、保留 $\text{nums}[1]$」与「删 $\text{nums}[1]$、保留 $\text{nums}[0]$」在其余决策相同时产生的保留流**逐位相同**（首位均为 $x$，其后均为同一子序列），故两方案同时合法且删除数相等。

**证明**：保留流由保留元素按原顺序排成，交换一对**相邻且相等**的保留/删除标记不改变流的内容，合法性（配对不等式逐对相同）与删除数均不变。∎

**定理（贪心最优性）**：设 $g(\text{nums})$ 为贪心答案，则 $g(\text{nums}) = \text{OPT}(\text{nums})$ 对任意数组成立。

**证明**：先注意 $g$ 是合法方案（每对内部不等由算法分支保证；末尾补刀保证偶数长度），故 $g \ge \text{OPT}$ 恒成立。下证 $g \le \text{OPT}$，对 $n$ 强归纳。

$n = 0$ 时两者均为 0。设 $n \ge 1$，分两种情形：

- **情形 A（$n = 1$，或 $\text{nums}[0] == \text{nums}[1]$）**：此时 $g = 1 + g(\text{nums}[1:])$（$n = 1$ 时 $g = 1$，且任何方案因奇数长度必删该元素，$g = \text{OPT} = 1$ 成立；下设 $n \ge 2$）。任取合法方案，由引理 2 它在前两个元素上至少删 1 个：若恰删其一，由引理 3 不妨设删的是 $\text{nums}[0]$，其保留集合落在 $\text{nums}[1:]$ 上构成合法方案，故 $\text{OPT} \ge 1 + \text{OPT}(\text{nums}[1:])$；若两个都删，则 $\text{OPT} \ge 2 + \text{OPT}(\text{nums}[2:]) \ge 1 + \text{OPT}(\text{nums}[1:])$（后者用上界 $\text{OPT}(\text{nums}[1:]) \le 1 + \text{OPT}(\text{nums}[2:])$）。两种情况均有 $\text{OPT} \ge 1 + \text{OPT}(\text{nums}[1:]) \ge 1 + g(\text{nums}[1:]) = g$（对更短的 $\text{nums}[1:]$ 用归纳假设）。

- **情形 B（$\text{nums}[0] \ne \text{nums}[1]$，且 $n \ge 2$）**：贪心把 $(\text{nums}[0], \text{nums}[1])$ 锁成第一对，$g = g(\text{nums}[2:])$。取最优方案，设其保留下标集 $S = \{o_1 < o_2 < o_3 < \cdots\}$（$|S|$ 为偶数；$|S| = 0$ 时 $\text{OPT} = n \ge g$ 平凡成立，下设 $|S| \ge 2$）。构造 $S' = \{0, 1\} \cup \{o_3, o_4, \dots\}$：由于 $o_3 \ge 2$，$S'$ 中下标互异且有序。$S'$ 与 $S$ 大小相同（删 $\{o_1, o_2\}$ 补 $\{0, 1\}$），配对结构完全一致——第一对为 $(\text{nums}[0], \text{nums}[1])$，满足不等（情形 B 假设）；其余各对 $(o_3,o_4),(o_5,o_6),\dots$ 与原方案中的对应对完全相同，仍满足不等。故 $S'$ 也是最优方案，且它在 $\text{nums}[2:]$ 上的剩余部分 $\{o_3, o_4, \dots\}$ 是一个删除数为 $n - |S| = \text{OPT}$ 的合法方案，即 $g(\text{nums}[2:]) \le \text{OPT}$（归纳假设下 $g(\text{nums}[2:]) = \text{OPT}(\text{nums}[2:])$）。于是 $g = g(\text{nums}[2:]) \le \text{OPT}$。

两种情形均有 $g \le \text{OPT}$，结合反向不等式得 $g = \text{OPT}$。∎

> 💡 证明的骨架：**每一步贪心决策都能「无损失地」对齐到某个最优方案**——相等时删除是被迫且无分歧的（引理 2、3），不等时直接用贪心的首对替换最优方案的首对、尾部配对原封不动（情形 B 的 $S'$ 构造）。这正是「贪心 = 最优」的标准交换论证。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。指针 $i$ 每轮前进 1 或 2 格且单调不减，循环总轮数不超过 $n$；每轮只做一次比较与常数次赋值。
- **空间复杂度**：$O(1)$。双指针版只需 $i$、`ans` 两个变量；「栈」版栈深恒 $\le 1$，同样 $O(1)$。无需修改或复制数组。

## 7. 参考代码

### C++（双指针）

```cpp
class Solution {
public:
    int minDeletion(vector<int>& nums) {
        int n = nums.size(), ans = 0, i = 0;
        while (i + 1 < n) {
            if (nums[i] == nums[i + 1]) {
                ++ans;          // 相等：必删其一（删 nums[i]），右侧滑入补位
                ++i;
            } else {
                i += 2;         // 不等：锁成一对，跳到下一对起点
            }
        }
        return ans + (i < n);   // 末尾剩一个落单元素：再删一个
    }
};
```

### Python（双指针）

```python
class Solution:
    def minDeletion(self, nums: List[int]) -> int:
        n, ans, i = len(nums), 0, 0
        while i + 1 < n:
            if nums[i] == nums[i + 1]:
                ans += 1        # 相等：必删其一
                i += 1
            else:
                i += 2          # 不等：配对成功
        return ans + (i < n)    # 末尾落单补一刀
```

### Python（奇偶扫描，一变量「栈」）

```python
class Solution:
    def minDeletion(self, nums: List[int]) -> int:
        ans, kept, prev = 0, 0, 0
        for x in nums:
            if kept & 1 and prev == x:
                ans += 1          # 与落单元素相等：删除 x
            else:
                kept += 1         # x 落在偶位（成为新落单）或完成配对
                prev = x
        return ans + (kept & 1)   # 末尾落单补一刀
```

> 💡 三个版本两两等价：双指针版的 $i \mathrel{+}= 1$ 与「栈」版删除 $\text{nums}[i+1]$ 对应（引理 3 的删左删右等价），保留流的**数值序列**完全一致，只是删除的原始下标可能不同。

## 8. 边界情况与易错点

1. **忘删末尾落单元素（本题最经典的 WA）**：如 `[1,2,3]` 配对 (1,2) 后剩 3，必须再删一个——漏掉末尾的 `+ (i < n)` 或 `+ (kept & 1)` 直接输出 0。
2. **$n = 1$**：答案为 1。循环体一次不执行，全靠落单补刀返回正确值，不需要特判。
3. **全相等数组**：`[7,7,7,7]` → 4，一对也配不成，只能删空；别误以为答案上界是 $n-1$。
4. **比较对象错位（奇偶扫描版专属坑）**：`prev` 必须是「最后一个**保留**的元素」，不能图省事用 `nums[j-1]`——前者可能已被删除。双指针版无此坑。
5. **相等时步进写错**：应 `i += 1` 而非 `i += 2`——删一个后新元素滑入**同一个偶位**继续比较；写成 +2 会漏比、得到偏小的错误答案。
6. **已经美丽数组**：`[1,2,3,4]` → 0，全程走配对分支即可，无需特判。
7. **无溢出风险**：`ans` ≤ $n \le 10^5$，`int` 足够；值域 $[0, 10^5]$ 也不需要任何值域处理。
