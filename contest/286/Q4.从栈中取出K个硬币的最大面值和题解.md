# LeetCode 从栈中取出 K 个硬币的最大面值和 题解

## 1. 题目概述

- **标题 / 题号**：从栈中取出 K 个硬币的最大面值和（#2218，hard）
- **链接**：https://leetcode.cn/problems/maximum-value-of-k-coins-from-piles/
- **来源**：LeetCode 第 286 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、分组背包、前缀和

**题意**：桌子上有 `n` 个硬币**栈**，`piles[i]` 按从顶到底的顺序给出第 `i` 个栈中每枚硬币的面值（正整数）。每次操作可以从**任意一个栈的顶部**取走 1 枚硬币。要求**恰好**操作 `k` 次，求钱包里面值之和的最大值。

**约束**：

- $1 \le n \le 1000$ —— 组数上千，任何「每组开一维」的 $O(n \cdot k)$ 表面下限要掂量
- $1 \le \text{piles}[i][j] \le 10^5$ —— 面值全正：多取不亏，「恰好」与「至多」等价（§4）
- $1 \le k \le \sum \text{len}(\text{piles}[i]) \le 2000$ —— **总硬币数不超过 2000**，且 $k$ 不超过它，保证恰取 $k$ 枚必然可行

> 💡 **题眼**：栈只能从顶**连续**地取——「从栈 $i$ 取 $j$ 枚」的价值没有选择余地，就是前 $j$ 个面值之和（**前缀和**）。于是每个栈坍缩成一个「取几枚」的**互斥选项组**，问题立刻归约为**恰好装满的分组背包**：$n$ 组、容量 $k$、每组选一个选项。$\sum \text{len} \le 2000$ 是复杂度的护城河：三层循环总代价 $k \cdot \sum \text{len} \le 4 \times 10^6$。

## 2. 示例

**示例 1**

```text
输入：piles = [[1,100,3],[7,8,9]], k = 2
输出：101
解释：从栈 1 连取 2 枚：1 + 100 = 101。
      每步取「当前可见最大栈顶」的贪心会取 7、8，只得 15。
```

**示例 2**

```text
输入：piles = [[100],[100],[100],[100],[100],[100],[1,1,1,1,1,1,700]], k = 7
输出：706
解释：7 次全部花在最后一个栈上：1×6 + 700 = 706，
      压过「取 6 个 100」的 600。
```

**补充示例（单栈取满，k = Σlen）**

```text
输入：piles = [[100,1]], k = 2
输出：101
解释：k 恰好等于总硬币数，只能全部取走；k = 1 时则只取栈顶 100。
```

## 3. 解题思路

### 3.1 暴力思路

两条歧路，比赛时都真实地淘汰过人：

1. **贪心**：每一步取当前可见的最大栈顶。示例 1 直接给出反例——贪心取 7、8 得 15，而最优是忍住先取 1、解锁 100。失败根源：栈顶只是「门票」，取走它才露出下面的更大面值，**局部比较看不到连锁的未来收益**。
2. **回溯枚举**：对每个栈枚举取 0、1、…、len$_i$ 枚，回溯所有组合数 $\prod_i (\text{len}_i + 1)$，在 $\sum \text{len} = 2000$、$n = 1000$ 的规模下是天文数字。

> ⚠️ 贪心与回溯的共同盲区：没有利用「取 $j$ 枚的价值 = 前 $j$ 枚之和」这一**结构性**，也就看不到问题其实是背包。

### 3.2 核心观察：取 $j$ 枚 = 前缀和，每栈一组互斥选项

![核心观察：只能连续取顶 → 前 j 枚之和 = 前缀和 → 每栈一组互斥选项](images/2218_piles_to_groups_concept.svg)

**转化 ①（消灭「怎么取」）**：栈是 LIFO，取 $j$ 枚**必然**是顶部 $j$ 个元素，没有跳着取的余地。于是「从栈 $i$ 取 $j$ 枚的价值」是一个只依赖 $j$ 的数：

$$\text{prefix}[i][j] = \sum_{t=0}^{j-1} \text{piles}[i][t], \qquad j = 0, 1, \dots, \text{len}_i$$

每个栈预处理 $O(\text{len}_i)$，全局 $O(S)$（$S = \sum \text{len}_i \le 2000$），查询 $O(1)$。

**转化 ②（识别背包模型）**：把每个栈看成一个**物品组**，组内选项「取 $j$ 枚」重 $j$、值 $\text{prefix}[i][j]$，**组内互斥、至多选一个**（取了 2 枚就不存在再独立「取 1 枚」）；容量为**恰好** $k$。这正是**分组背包**：

$$\text{dp}[t] = \max_{0 \le j \le \min(t,\ \text{len}_i)} \big(\text{dp}_{\text{旧}}[t - j] + \text{prefix}[i][j]\big)$$

> 💡 为何不是 0-1 / 完全背包：0-1 背包每组只有一个物品（选/不选），完全背包允许同物品重复取；本题「取 1 枚」与「取 2 枚」是**同一栈的两种取法**，只能二选一——组内互斥是分组背包的签名。

### 3.3 算法流程：一维滚动 + 容量倒序

![算法流程：前缀和预处理 → 滚动数组分组背包，t 倒序](images/2218_knapsack_dp_flow.svg)

1. **预处理**：对每个栈求前缀和（C++ 可原地累加，见 §7）；
2. **初始化**：$\text{dp}[0] = 0$，$\text{dp}[1..k] = -\infty$（$-\infty$ 表示「恰好 $t$ 次」暂不可达）；
3. **外层**：依次处理每个栈 $i$；
4. **中层**：$t$ 从 $k$ 到 $1$ **倒序**——保证转移读到的 $\text{dp}[t-j]$ 是**上一轮（前 $i-1$ 栈）**的旧值，防止同组选两个选项（正序的反例见 §8.1）；
5. **内层**：枚举 $j = 1 \dots \min(t, \text{len}_i)$，仅当 $\text{dp}[t-j]$ 可达时用 $\text{dp}[t-j] + \text{prefix}[i][j]$ 更新 $\text{dp}[t]$（$j=0$ 是恒等转移，天然保留旧值）；
6. **返回** $\text{dp}[k]$。

### 3.4 示例演算

![示例演算：piles=[[1,100,3],[7,8,9]], k=2 两轮 DP 演变](images/2218_dp_table_walkthrough.svg)

以示例 1（`piles = [[1,100,3],[7,8,9]]`，`k = 2`）走查。前缀和：栈 1 为 $[0, 1, 101, 104]$，栈 2 为 $[0, 7, 15, 24]$。

**第 1 轮 · 处理栈 1**（初始 $\text{dp} = [0, -\infty, -\infty]$，$t = 2 \to 1$ 倒序）：

| $t$ | $j$ 候选 | 计算 | 新 $\text{dp}[t]$ |
|----|---------|------|------------------|
| 2 | 1 | $-\infty + 1$，不可达 ✗ | — |
| 2 | 2 | $0 + 101 = \mathbf{101}$ ✓ | **101** |
| 1 | 1 | $0 + 1 = \mathbf{1}$ ✓ | **1** |

得 $\text{dp} = [0, 1, 101]$。

**第 2 轮 · 处理栈 2**（$t = 2 \to 1$ 倒序，读到的旧值来自第 1 轮）：

| $t$ | $j$ 候选 | 计算 | 新 $\text{dp}[t]$ |
|----|---------|------|------------------|
| 2 | 0 | 沿用旧值 $101$ | — |
| 2 | 1 | $\text{dp}[1] + 7 = 1 + 7 = 8$ | — |
| 2 | 2 | $\text{dp}[0] + 15 = 15$ | **101**（三者最大） |
| 1 | 1 | $0 + 7 = \mathbf{7}$ ✓ | **7** |

得 $\text{dp} = [0, 7, 101]$，**答案 $\text{dp}[2] = 101$**：栈 1 取 2 枚、栈 2 取 0 枚 ✓。

> 💡 第 2 轮算 $t=2$ 时读到的 $\text{dp}[1] = 1$ 是**第 1 轮**的旧值——若误读为本轮刚算出的 $7$，就成了「栈 2 的选项叠加两次」。倒序正是为了封死这条路。

## 4. 算法细节

1. **前缀和原地计算**：`piles[i]` 本身就从顶到底，直接 `p[j] += p[j-1]` 原地累加，`p[j-1]` 即 $\text{prefix}[i][j]$，额外空间从 $O(S)$ 降到 $O(1)$。注意**不要反转数组**——「顶部」对应下标 0，方向反了前缀和就全错。
2. **$j$ 从 1 开始**：$j = 0$ 的转移是 $\text{dp}[t] = \max(\text{dp}[t], \text{dp}[t] + 0)$，恒等式；「本栈一枚不取」由保留旧值天然表达，无需显式枚举。
3. **$-\infty$ 哨兵的选择**：C++ 用 `INT_MIN / 2` 而非 `INT_MIN`——万一漏写可达性判断就做加法，`INT_MIN + prefix` 是**有符号溢出 UB**，而 `INT_MIN/2 + 2×10^8` 仍落在 `int` 范围内、只会得到一个足够小的错误值（配合判断则根本不会发生）。Python 的 `float("-inf")` 参与加法不溢出，判断可省。
4. **「恰好」与「至多」**：初始化 $-\infty$ 是「恰好 $k$ 次」的精确语义。本题面值全正、且 $k \le S$ 保证可达，故初始化全 0（「至多」语义）答案相同；但「恰好 + $-\infty$」的写法可原样迁移到面值可能为 0/负数、或「装满计数」的变体，比赛时建议写精确语义。
5. **内层上界 $\min(t, \text{len}_i)$**：既防止 $t - j$ 负下标越界，又天然剪掉「超出容量」的选项。
6. **复杂度不是 $O(n \cdot k^2)$ 的原因**：栈 $i$ 的内层操作数为 $\sum_{t=1}^{k} \min(t, \text{len}_i) \le k \cdot \text{len}_i$，全局 $\le k \cdot S \le 2000 \times 2000 = 4 \times 10^6$——$j$ 的上界被栈长钳住，这是 $\sum \text{len} \le 2000$ 约束送的分。

## 5. 正确性证明

记 $\text{len}_i = \text{piles}[i].\text{length}$，$S = \sum_i \text{len}_i$，prefix 如 §3.2 定义。

**引理 1（方案 ⇄ 取数向量）**：恰进行 $k$ 次操作的合法取法，与向量 $(j_1, \dots, j_n)$（$0 \le j_i \le \text{len}_i$，$\sum_i j_i = k$）一一对应（在「总面值」意义下），且任一对应方案的总面值均为 $\sum_i \text{prefix}[i][j_i]$。

**证明**：任一合法操作序列中，栈只能从顶取，故从栈 $i$ 恰取走 $j_i$ 枚等价于取走其顶部 $j_i$ 个元素——「取走哪些」没有自由度，「取几枚」才有。于是该序列由向量 $(j_1, \dots, j_n)$ 在「总面值」意义下唯一决定：总面值 $= \sum_i \sum_{t<j_i} \text{piles}[i][t] = \sum_i \text{prefix}[i][j_i]$，与各栈之间取的先后顺序无关。反之，任给满足约束的向量，逐栈从顶连取 $j_i$ 枚即拼出一个合法操作序列。∎

**推论**：原问题等价于——在 $0 \le j_i \le \text{len}_i$、$\sum_i j_i = k$ 约束下最大化 $\sum_i \text{prefix}[i][j_i]$，即恰好装满的分组背包。

**引理 2（最优子结构）**：设 $D_i(t)$ 为仅用前 $i$ 个栈、恰取 $t$ 枚的最大面值和（不可达记 $-\infty$），则 $D_0(0) = 0$、$D_0(t) = -\infty\ (t > 0)$，且对 $i \ge 1$：

$$D_i(t) = \max_{0 \le j \le \min(t,\ \text{len}_i)} \Big( D_{i-1}(t - j) + \text{prefix}[i][j] \Big)$$

**证明**（对 $i$ 归纳）：$i = 0$ 显然。设结论对 $i-1$ 成立。任取前 $i$ 栈、恰取 $t$ 枚的方案，设其从栈 $i$ 取 $j$ 枚（$0 \le j \le \min(t, \text{len}_i)$），其余 $t - j$ 枚取自前 $i-1$ 栈。前 $i-1$ 栈恰取 $t-j$ 枚的最大值是 $D_{i-1}(t-j)$（归纳假设），故该方案的总值 $\le D_{i-1}(t-j) + \text{prefix}[i][j] \le$ 递推式右端。反之，取到右端最大值的 $j^*$：若 $D_{i-1}(t-j^*)$ 可达，取一个达成它的方案，与「栈 $i$ 连取 $j^*$ 枚」拼接（引理 1 保证可实现且价值可加），得到总面值恰为 $D_{i-1}(t-j^*) + \text{prefix}[i][j^*]$ 的合法方案；若不可达，则该项为 $-\infty$，不大于任何可达方案。故等式成立。∎

**引理 3（倒序滚动的等价性）**：一维数组 dp 按「外层 $i$ 升序、中层 $t$ 从 $k$ 到 $1$ 倒序」更新，第 $i$ 轮结束后 $\text{dp}[t] = D_i(t)$ 对一切 $t$ 成立。

**证明**（对 $i$ 归纳）：第 $i$ 轮开始时 $\text{dp}[t] = D_{i-1}(t)$。本轮按 $t$ 递减次序写入：处理容量 $t$ 时，写入值为

$$\max\Big(\text{dp}[t],\ \max_{1 \le j \le \min(t,\ \text{len}_i)} \text{dp}[t-j] + \text{prefix}[i][j]\Big)$$

因 $j \ge 1$，一切下标 $t - j < t$ 尚未在本轮被写入，读到的仍是 $D_{i-1}(t-j)$；而 $\text{dp}[t]$ 本身即「$j = 0$」选项 $D_{i-1}(t)$。故写入值与引理 2 的递推式一致。若改用正序，$t - j$ 可能已被本轮写入为 $D_i(t-j)$，转移被污染为「前 $i$ 栈的方案再从栈 $i$ 取 $j$ 枚」——同一组选了两个选项，递推式不再成立。∎

**定理**：算法返回 $\text{dp}[k]$ 等于原问题最优解。

**证明**：由约束 $k \le S$，取向量（如逐栈装满直到凑足 $k$）可知恰取 $k$ 枚可达，故 $D_n(k) > -\infty$。由引理 1，原问题最优值 $= \max_{\text{向量}} \sum_i \text{prefix}[i][j_i] = D_n(k)$；由引理 3，算法输出的 $\text{dp}[k] = D_n(k)$。∎

> 💡 证明骨架是背包题的标准三板斧：**结构化方案**（引理 1 把操作序列压缩成向量）→ **最优子结构**（引理 2 证明递推不多不少）→ **实现等价**（引理 3 证明滚动数组算的就是递推式）。其中引理 3 是一维滚动写法的专属义务——二维 dp 则可跳过。

## 6. 复杂度分析

- **时间复杂度**：$O(k \cdot S)$，其中 $S = \sum \text{len}_i \le 2000$。前缀和预处理 $O(S)$；栈 $i$ 的转移为 $\sum_{t=1}^{k} \min(t, \text{len}_i) \le k \cdot \text{len}_i$ 次比较，求和得 $k \cdot S \le 4 \times 10^6$，远低于常见 1 秒 $10^8$ 的预算。
- **空间复杂度**：$O(k)$ 额外空间（dp 数组）——C++ 前缀和原地累加；Python 每轮重建 $O(\text{len}_i)$ 的前缀数组，峰值 $O(k + \max \text{len}_i)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxValueOfCoins(vector<vector<int>>& piles, int k) {
        const int NEG = INT_MIN / 2;                     // -inf：恰好 t 次暂不可达
        vector<int> dp(k + 1, NEG);
        dp[0] = 0;
        for (vector<int>& p : piles) {
            int len = p.size();
            for (int j = 1; j < len; ++j) p[j] += p[j - 1];   // 原地前缀和：p[j-1] = 取 j 枚的价值
            for (int t = k; t >= 1; --t) {                    // 倒序：dp[t-j] 只读上一轮旧值
                int upper = min(t, len);
                for (int j = 1; j <= upper; ++j) {
                    if (dp[t - j] != NEG) {                   // 只从可达状态转移
                        dp[t] = max(dp[t], dp[t - j] + p[j - 1]);
                    }
                }
            }
        }
        return dp[k];
    }
};
```

### Python

```python
class Solution:
    def maxValueOfCoins(self, piles: List[List[int]], k: int) -> int:
        dp = [float("-inf")] * (k + 1)
        dp[0] = 0
        for p in piles:
            acc = [0]
            for v in p:
                acc.append(acc[-1] + v)          # acc[j] = 从本栈取 j 枚的价值
            for t in range(k, 0, -1):            # 倒序：dp[t-j] 只读上一轮旧值
                for j in range(1, min(t, len(p)) + 1):
                    cand = dp[t - j] + acc[j]
                    if cand > dp[t]:             # -inf 参与加法不溢出，判断可省
                        dp[t] = cand
        return dp[k]
```

> 💡 两份代码语义完全一致：`p[j-1]`（C++ 原地前缀和）与 `acc[j]`（Python 独立数组）都表示「取 $j$ 枚的价值」。Python 版省去可达性判断的原因：`-inf + 任何数 = -inf`，不可能赢得 `max`。

## 8. 边界情况与易错点

1. **$t$ 正序遍历（头号 WA）**：正序时本轮算 $t=2$ 会读到刚更新的 $\text{dp}[1]$，同组选项被叠加。反例 `piles = [[100,1]], k = 2`：正确答案 101（全取），正序算出 $\text{dp}[1] + \text{prefix}[1] = 100 + 100 = 200$——栈顶 100 被数了两遍。别死记「背包倒序」：本质是**转移只许读上一轮的旧值**。
2. **`INT_MIN` 哨兵 + 加法 = 溢出 UB**：若用 `INT_MIN` 表示不可达又忘了判断，`dp[t-j] + prefix` 直接触发 C++ 未定义行为；用 `INT_MIN / 2` 或显式判可达（§7 的写法两者兼备）。
3. **$j$ 上界漏写 $\min(t, \text{len}_i)$**：只写 $\text{len}_i$ 时 $j > t$ 导致 `dp[t-j]` 负下标越界（RE）；只写 $t$ 时读到不存在的 `prefix[i][j]`（越界或语义错）。
4. **「恰好」忘了 $-\infty$ 初始化**：全 0 初始化是「至多 $t$ 次」语义。本题面值全正恰好不出错，但若面值允许 0 或负（变体），或要求统计恰好 $k$ 的方案数，全 0 初始化必错——比赛时养成写精确语义的习惯。
5. **$k$ 可达性由约束兜底**：题目保证 $k \le S$，故 $\text{dp}[k]$ 一定可达、无需特判；若变体允许 $k > S$，「恰好」语义下应返回 $\text{dp}[k] = -\infty$（或按题意取 0），别无脑返回下标。
6. **栈方向搞反**：`piles[i]` **从顶到底**排列，顶部即下标 0，前缀和直接从左往右累加；若误把数组当「从底到顶」先翻转，所有 $\text{prefix}$ 全错（WA 得毫无规律）。
7. **单栈退化情形**：$n = 1$ 时答案就是 $\text{prefix}[1][k]$（$k \le \text{len}_1$），DP 循环自然得到它，无需特判；同理 $k = S$（取走所有硬币）时答案是全体面值之和，也可用作手造数据的对拍基准。
8. **原地前缀和破坏输入**：C++ 版直接改写 `piles`，LeetCode 判题不介意；但本地对拍、多组测试复用同一输入时要注意先拷贝。

- [LeetCode 322. 零钱兑换](https://leetcode.cn/problems/coin-change/)：完全背包求最值，容量**正序**遍历表示「同物品可重复取」——与本题倒序对照，理解遍历方向与物品语义的绑定关系。
- [LeetCode 1049. 最后一块石头的重量 II](https://leetcode.cn/problems/last-stone-weight-ii/)：0-1 背包求最值的另一形态（赋 ± 号最小化两组差）。

**延伸思考**：若规则改成「每栈可以跳着取任意若干枚」，引理 1 的双射失效，但「取 $j$ 枚的最优价值」变为该栈**最大的 $j$ 个面值之和**——把每栈降序排序后仍做前缀和，分组背包模型原封不动，只是 prefix 的定义换了内核。若再叠加「面值可为负」，则选项价值不再随 $j$ 单调，$j$ 的枚举上界要重新收紧（只枚举到「边际收益转负」处）。若 $k$ 与 $S$ 放大到 $10^5$ 量级，$O(k \cdot S)$ 不再可行，需转向凸优化或「栈顶前缀的边际收益单调」结构上的更激进剪枝——正是约束送分的反面：约束松一档，算法难一档。
