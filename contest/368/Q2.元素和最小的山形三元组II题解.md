# LeetCode 元素和最小的山形三元组 II 题解

## 1. 题目概述

- **标题 / 题号**：元素和最小的山形三元组 II（#2909，medium）
- **链接**：https://leetcode.cn/problems/minimum-sum-of-mountain-triplets-ii/
- **来源**：LeetCode 第 368 场周赛 Q2
- **难度**：中等
- **标签**：数组、前后缀最小值、枚举

**题意**：给定下标从 **0** 开始的整数数组 `nums`。若下标三元组 $(i, j, k)$ 满足 $i \lt j \lt k$ 且 $\text{nums}[i] \lt \text{nums}[j]$、$\text{nums}[k] \lt \text{nums}[j]$（中间高、两头矮），则称其为**山形三元组**。求元素和 $\text{nums}[i] + \text{nums}[j] + \text{nums}[k]$ 最小的山形三元组，返回其和；不存在则返回 $-1$。

**约束**：

- $3 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^8$

> 💡 本题与**同场 Q1**（2908）题面一字不差，差别只在数据范围：I 版 $n \le 50$、$\text{nums}[i] \le 50$，$O(n^3)$ 暴力可过；II 版 $n \le 10^5$、$\text{nums}[i] \le 10^8$，把**线性解**从加分项变成生死线。赛时最短路径：Q1 用暴力抢分，Q2 把「枚举山峰 + 前后缀最小」平移过来（[Q1 题解](Q1.元素和最小的山形三元组I题解.md)已给出该线性解）；本篇则复盘这条优化链路本身——数据范围如何倒推目标复杂度、$O(n^2) \to O(n)$ 的分水岭在哪里。另见[每日题解](../../solution/2901-3000/2909_元素和最小的山形三元组II.md)（面试问答视角），互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [8,6,1,5,3]
输出：9
解释：三元组 (2, 3, 4) 是一个元素和等于 9 的山形三元组：
- 2 < 3 < 4
- nums[2] < nums[3] 且 nums[4] < nums[3]
元素和 = nums[2] + nums[3] + nums[4] = 1 + 5 + 3 = 9。不存在元素和更小的山形三元组。
```

**示例 2**

```text
输入：nums = [5,4,8,7,10,2]
输出：13
解释：三元组 (1, 3, 5) 是一个元素和等于 13 的山形三元组：
- 1 < 3 < 5
- nums[1] < nums[3] 且 nums[5] < nums[3]
元素和 = nums[1] + nums[3] + nums[5] = 4 + 7 + 2 = 13。不存在元素和更小的山形三元组。
```

```text
输入：nums = [6,5,4,3,4,5]
输出：-1

```

## 3. 解题思路

### 3.1 暴力思路：两条死路，先让数据范围定生死

第一反应是 Q1 的三重循环 $O(n^3)$：枚举全部 $i \lt j \lt k$，判两个不等式取最小。$n = 10^5$ 时三元组多达 $\binom{10^5}{3} \approx 1.7 \times 10^{14}$ 个——把 Q1 的暴力代码原样复制过来必然超时。

退一步，**固定山峰 $j$**、左右各扫一遍找更矮的腿：$O(n^2)$，约 $10^{10}$ 次比较，依然超时。

按「1 秒约 $10^8 \sim 10^9$ 次运算」的经验法则，$n \le 10^5$ 只给 $O(n)$ 与 $O(n \log n)$ 留门：

![数据范围倒推复杂度阶梯](images/mtn_ii_complexity_ladder.svg)

### 3.2 核心观察：固定山峰 j，两侧约束解耦

两个不等式 $\text{nums}[i] \lt \text{nums}[j]$ 与 $\text{nums}[k] \lt \text{nums}[j]$ 都锚定在 $\text{nums}[j]$ 上——**固定 $j$ 当山峰后，$i$ 与 $k$ 的选择互不干扰**：$i$ 的候选集 $\{0..j-1\}$ 与 $k$ 的候选集 $\{j+1..n-1\}$ 不相交，两个值之间也没有任何约束。于是

$$\text{best}(j) = \underbrace{\min_{i \lt j} \text{nums}[i]}_{\text{preMin}} + \text{nums}[j] + \underbrace{\min_{k \gt j} \text{nums}[k]}_{\text{sufMin}}$$

一个 $\min$ 同时干两件事：

- **选最优**：固定 $j$ 时和最小 $\iff$ 两条腿各自取到本侧最小值——合法性对位置的要求只有「在 $j$ 的同一侧」，本侧最小值元素天然满足；
- **判合法**：若 $\text{preMin} \ge \text{nums}[j]$，说明左侧全体不比山峰矮，$j$ 当不成山峰，直接跳过；右侧同理。

于是每个 $j$ 的处理从 $O(n)$ 降到 $O(1)$——前提是「本侧最小值」能 $O(1)$ 拿到，这正是下一步要做的事。

### 3.3 算法流程：扩张侧顺手滚，收缩侧先建表

$O(n^2)$ 慢在**每个 $j$ 都把两侧重扫一遍**。而 $j$ 从左往右移动时，两个候选窗口的演化方向截然相反：

- **左窗口 $[0, j)$**：右端随 $j$ 推进而**扩张**——新元素直接 $\min$ 进滚动变量 `preMin`，$O(1)$ 摊还；
- **右窗口 $(j, n)$**：左端随 $j$ 推进而**收缩**——$\min$ 只会「并入」不会「删除」，滚不动；但沿**右→左**方向看这个窗口反而在扩张，于是可以事先递推 $\text{suf}[i] = \min(\text{nums}[i], \text{suf}[i+1])$ 存进数组，主循环里查表。

![扩张与收缩的分水岭](images/mtn_ii_two_windows.svg)

**完整步骤**：

1. **预处理**（右→左）：$\text{suf}[n-1] = \text{nums}[n-1]$，$\text{suf}[i] = \min(\text{nums}[i], \text{suf}[i+1])$；
2. **主循环**（$j$ 从 $1$ 到 $n-2$，山峰不可能是端点）：`preMin` 始终等于 $\min(\text{nums}[0..j-1])$；
3. 若 `preMin < nums[j]` 且 `suf[j+1] < nums[j]`，用 `preMin + nums[j] + suf[j+1]` 更新 `ans`；
4. 随后 `preMin = min(preMin, nums[j])`，把 `nums[j]` 并入左侧留给下一个山峰；循环结束 `ans` 仍是 $+\infty$ 则返回 $-1$。

### 3.4 示例演算

以示例 2 `nums = [5,4,8,7,10,2]` 为例。先从右往左建 `suf`：尾部的 $2$ 一路锁死，整表全是 $2$；再从左往右枚举山峰（$j \in [1,4]$）：

| $j$ | nums[j] | preMin（左侧最小） | suf[j+1]（右侧最小） | 山峰成立？ | 候选和 | ans |
|-----|---------|-------------------|---------------------|-----------|--------|-----|
| 1 | 4 | 5 | 2 | ✗（$5 \ge 4$） | — | $\infty$ |
| 2 | 8 | 4 | 2 | ✓ | $4+8+2=14$ | 14 |
| **3** | **7** | **4** | **2** | **✓** | **$4+7+2=13$** | **13** |
| 4 | 10 | 4 | 2 | ✓ | $4+10+2=16$ | 13 |

![示例演算表](images/mtn_ii_example_walkthrough.svg)

返回 $13$ ✓（三元组 $(1,3,5)$：$4+7+2$）。注意 $j=4$：山峰 $10$ 全场最高，却被左腿 $4$ 拖到 $16$ 落选——**最小和常藏在「矮胖山」里**，必须枚举每个 $j$，不能只盯最高峰。示例 3 `[6,5,4,3,4,5]` 先降后升是座「山谷」，全程无合法山峰，返回 $-1$ ✓。示例 1 `[8,6,1,5,3]` 同一流程在 $j=3$ 处得 $1+5+3=9$ ✓。

## 4. 算法细节

1. **山峰范围 $[1, n-2]$**：$j=0$ 与 $j=n-1$ 缺一侧，天然不合法，循环范围直接排除。嫌边界烦可改**哨兵写法**——`suf` 多开一格存 $+\infty$、`preMin` 起步 $+\infty$、$j$ 扫满 $[0, n-1]$，端点自动失效，即 [Q1 题解](Q1.元素和最小的山形三元组I题解.md)的版本，两份代码完全等价。
2. **`suf` 递推方向必须右→左**：主循环从左往右走、右窗口只缩不放，而 $\min$ 不支持删除元素，只能沿右窗口自己的扩张方向（右→左）先建表。
3. **更新顺序**：先用「旧的」`preMin` 判定 $j$，再把 `nums[j]` 并进去；写反了会让山峰自身混进左侧候选，山形条件退化为自比。`preMin` 初值取 `nums[0]`，进入 $j=1$ 时恰为 $\min(\text{nums}[0..0])$。
4. **溢出评估**：三项之和 $\le 3 \times 10^8 \lt 2^{31}-1 \approx 2.1 \times 10^9$，C++ `int` 安全；值域放大到 $10^8$ 是 I/II 版的又一差异，但还远没到需要 `long long` 的程度。
5. **为什么赛时选前后缀分解**：两趟扫描、常数极小、最好写；单调栈等做法在此题并无额外收益（它擅长「最近更小元素」这类成对关系，而本题只需要「某一侧的整体最小」），把简单题写复杂反而增加罚时风险。

## 5. 正确性证明

记 $P(j) = \min_{0 \le i \lt j} \text{nums}[i]$（前缀最小），$S(j) = \min_{j \lt k \le n-1} \text{nums}[k]$（后缀最小）。

**引理 1（固定 j 的最优分解）**：设 $1 \le j \le n-2$。若 $P(j) \lt \text{nums}[j]$ 且 $S(j) \lt \text{nums}[j]$，则以 $j$ 为山峰的山形三元组的最小元素和为 $P(j) + \text{nums}[j] + S(j)$；若两条件任一不成立，则不存在以 $j$ 为山峰的山形三元组。

**证明**：固定 $j$ 后目标函数 $\text{nums}[i] + \text{nums}[j] + \text{nums}[k]$ 关于 $i$、$k$ 可分离，且约束也可分离：$i$ 合法 $\iff i \in [0, j-1]$ 且 $\text{nums}[i] \lt \text{nums}[j]$，$k$ 合法 $\iff k \in [j+1, n-1]$ 且 $\text{nums}[k] \lt \text{nums}[j]$，两变量之间再无任何约束，故最小化可分解为两个独立子问题。左侧：合法集合非空 $\iff$ 存在 $i \lt j$ 使 $\text{nums}[i] \lt \text{nums}[j]$ $\iff P(j) \lt \text{nums}[j]$；非空时，任一合法 $i$ 满足 $\text{nums}[i] \ge P(j)$，而取到 $P(j)$ 的下标 $i^\ast$ 本身合法（$i^\ast \lt j$ 且 $\text{nums}[i^\ast] = P(j) \lt \text{nums}[j]$），故左子问题最优值恰为 $P(j)$。右侧对称。∎

**引理 2（覆盖性）**：任意山形三元组 $(i, j, k)$ 的中间下标 $j$ 满足 $1 \le j \le n-2$、$P(j) \lt \text{nums}[j]$ 且 $S(j) \lt \text{nums}[j]$。

**证明**：$i \ge 0$、$k \le n-1$ 与 $i \lt j \lt k$ 推出 $1 \le j \le n-2$。又 $\text{nums}[i] \lt \text{nums}[j]$ 且 $i \lt j$，故 $P(j) \le \text{nums}[i] \lt \text{nums}[j]$；同理 $S(j) \le \text{nums}[k] \lt \text{nums}[j]$。∎

**定理**：算法返回 `nums` 中元素和最小的山形三元组的元素和；不存在时返回 $-1$。

**证明**：主循环枚举了全部 $j \in [1, n-2]$，且 `preMin`、`suf[j+1]` 分别等于 $P(j)$、$S(j)$（递推式与滚动顺序保证，见 §4 第 2、3 点）。由引理 2，全体山形三元组按中间下标分组后，每组对应的 $j$ 都会被枚举到且判定成立；由引理 1，算法在该组产生的候选值恰为该组最小和；`ans` 取遍所有组的 $\min$，即全局最小。反之，若循环结束 `ans` 从未更新，说明不存在满足引理 1 条件的 $j$，由引理 2 的逆否命题不存在任何山形三元组，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。预处理 `suf` 一趟 + 主循环一趟，每步常数次比较；对照 §3.1 的两条死路：$O(n^3) \approx 1.7 \times 10^{14}$、$O(n^2) = 10^{10}$，在 $n \le 10^5$ 下均不可行。
- **空间复杂度**：$O(n)$。一个后缀最小数组 `suf`；`preMin`、`ans` 均为滚动变量。本解法已把「前缀 + 后缀」两个数组砍成一个（前缀滚动化）；再往下压空间需值域数据结构，得不偿失（见「相关题目与扩展」的延伸思考）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumSum(vector<int>& nums) {
        int n = nums.size();
        // 后缀最小：suf[i] = min(nums[i..n-1])——右侧窗口只收缩，须沿右→左先建表
        vector<int> suf(n);
        suf[n - 1] = nums[n - 1];
        for (int i = n - 2; i >= 0; i--)
            suf[i] = min(nums[i], suf[i + 1]);

        int ans = INT_MAX, preMin = nums[0];        // preMin 滚动维护 = min(nums[0..j-1])
        for (int j = 1; j <= n - 2; j++) {          // 山峰不可能是端点，j ∈ [1, n-2]
            if (preMin < nums[j] && suf[j + 1] < nums[j])
                ans = min(ans, preMin + nums[j] + suf[j + 1]);
            preMin = min(preMin, nums[j]);          // 用完 j 再并入左侧
        }
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minimumSum(self, nums: List[int]) -> int:
        n = len(nums)
        suf = [0] * n                              # suf[i] = min(nums[i:])
        suf[-1] = nums[-1]
        for i in range(n - 2, -1, -1):
            suf[i] = min(nums[i], suf[i + 1])

        ans = inf
        pre_min = nums[0]                          # pre_min 滚动维护 = min(nums[:j])
        for j in range(1, n - 1):                  # 山峰 j ∈ [1, n-2]，端点免检
            if pre_min < nums[j] and suf[j + 1] < nums[j]:
                ans = min(ans, pre_min + nums[j] + suf[j + 1])
            pre_min = min(pre_min, nums[j])        # 用完 j 再并入左侧
        return -1 if ans == inf else ans
```

> 💡 这份代码与 [Q1 题解](Q1.元素和最小的山形三元组I题解.md)的哨兵版等价，只是把端点处理从「哨兵自动失效」换成「循环范围显式排除」——赛时用哪种都行，别把 Q1 的**暴力**代码平移过来就行。

## 8. 边界情况与易错点

1. **严格小于别写成 $\le$**：山形条件两侧都是**严格**比较。`nums = [3,3,3]` 正确答案是 $-1$（等高不算山峰）；把判定写成 `<=` 会错答 $9$。
2. **更新顺序别写反**：先用「旧的」`preMin` 判定 $j$，再把 `nums[j]` 并进去，否则山峰自己当自己的左腿，判定失真。
3. **无解的三种形态**：单调递增（没有更矮的右腿）、单调递减（没有更矮的左腿）、先降后升的山谷（两腿都缺）；`ans` 保持初值时要返回 $-1$，别返回 `INT_MAX` 或 $0$。
4. **最高峰未必最优**：见 §3.4 中 $j=4$ 落选——「枚举全部 $j$ 取 $\min$」这一步不可省略成只查最高峰。
5. **$n = 3$ 的最小规模**：唯一候选三元组 $(0,1,2)$，主循环只跑 $j=1$ 一次，两套代码天然覆盖。
6. **I/II 平移陷阱**：两题题面一字不差，复制提交前先看数据范围——Q1 的 $O(n^3)$ 在 $n \le 10^5$ 下必挂；反过来，本文的线性解倒是可以原样交 Q1。
