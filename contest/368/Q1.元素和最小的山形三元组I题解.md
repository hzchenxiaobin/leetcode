# LeetCode 元素和最小的山形三元组 I 题解

## 1. 题目概述

- **标题 / 题号**：元素和最小的山形三元组 I（#2908，easy）
- **链接**：https://leetcode.cn/problems/minimum-sum-of-mountain-triplets-i/
- **来源**：LeetCode 第 368 场周赛 Q1
- **难度**：简单
- **标签**：数组、枚举、前后缀最小值

**题意**：给定下标从 **0** 开始的整数数组 `nums`。若下标三元组 `(i, j, k)` 满足 `i < j < k` 且 `nums[i] < nums[j]`、`nums[k] < nums[j]`（中间高、两头矮），则称其为**山形三元组**。求元素和 `nums[i] + nums[j] + nums[k]` 最小的山形三元组，返回其和；不存在则返回 `-1`。

**约束**：

- $3 \le \text{nums.length} \le 50$
- $1 \le \text{nums}[i] \le 50$

> 💡 本题与**同场 Q2** [2909. 元素和最小的山形三元组 II](https://leetcode.cn/problems/minimum-sum-of-mountain-triplets-ii/) 题面一字不差，只是把数据范围放大到 $n \le 10^5$、$1 \le \text{nums}[i] \le 10^8$——Q1 官方留给暴力一条活路，Q2 逼出线性解。赛时 Q1 用三重循环抢时间，Q2 把「枚举山峰 + 前后缀最小」平移过去即可。本题在本仓库另有[每日题解](../../solution/2901-3000/2908_元素和最小的山形三元组I.md)：以线性解为主线展开面试问答，与本文互为印证；本篇是赛场复盘视角，主打从题面到代码的最短路径与边界处理。

## 2. 示例

**示例 1**

```text
输入：nums = [8,6,1,5,3]
输出：9
解释：三元组 (2, 3, 4) 是一个元素和等于 9 的山形三元组：
- 2 < 3 < 4
- nums[2] < nums[3] 且 nums[4] < nums[3]
元素和 = nums[2] + nums[3] + nums[4] = 1 + 5 + 3 = 9。不存在元素和更小的山形三元组。
```

**示例 2**

```text
输入：nums = [5,4,8,7,10,2]
输出：13
解释：三元组 (1, 3, 5) 元素和 = nums[1] + nums[3] + nums[5] = 4 + 7 + 2 = 13。
```

**示例 3**

```text
输入：nums = [6,5,4,3,4,5]
输出：-1
解释：数组先降后升，是一座「山谷」，任何中间元素都无法成为山峰，不存在山形三元组。
```

## 3. 解题思路

### 3.1 暴力思路：三重循环（赛时最短路径）

签到题的取态：**用最短时间写对，把时间留给后面的题**。直接枚举所有满足 `i < j < k` 的三元组，判断山形条件并取最小：

```cpp
int minimumSum(vector<int>& nums) {
    int n = nums.size(), ans = INT_MAX;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)
            for (int k = j + 1; k < n; k++)
                if (nums[i] < nums[j] && nums[k] < nums[j])
                    ans = min(ans, nums[i] + nums[j] + nums[k]);
    return ans == INT_MAX ? -1 : ans;
}
```

$n \le 50$ 时三元组至多 $\binom{50}{3} \approx 1.96 \times 10^4$ 个，$O(n^3)$ 毫无压力。但同一份代码提交 Q2（2909，$n \le 10^5$）约 $1.7 \times 10^{14}$ 次运算必然超时——这正是本题值得多想一步的地方：**写出能直接平移到 Q2 的解法**。

### 3.2 核心观察：枚举山峰 j，两侧各自取最小

山形条件 `nums[i] < nums[j] > nums[k]` 的中心是 $j$——**山峰**。换个视角：不枚举三元组，而是**枚举 $j$ 当山峰**。固定 $j$ 后：

- 最优的 $i$ 一定是 $j$ **左侧的最小值** $\text{preMin}$（前缀最小）；
- 最优的 $k$ 一定是 $j$ **右侧的最小值** $\text{sufMin}$（后缀最小）。

两个选择**互不干扰**：$i$ 的候选集 $\{0..j-1\}$ 与 $k$ 的候选集 $\{j+1..n-1\}$ 不相交，`nums[i]` 与 `nums[k]` 之间也没有任何约束，所以「各自取最小」拼起来就是 $j$ 固定时的全局最小：

$$\text{best}(j) = \underbrace{\min_{i<j} \text{nums}[i]}_{\text{preMin}} + \text{nums}[j] + \underbrace{\min_{k>j} \text{nums}[k]}_{\text{suf}[j+1]}$$

而且合法性检查是**免费**的：若 $\text{preMin} \ge \text{nums}[j]$，说明左边全体都不比山峰矮，$j$ 根本当不成山峰，跳过；右侧同理。

![山形三元组概念图](images/mtn_i_triplet_concept.svg)

### 3.3 算法流程：后缀数组 + 一趟扫描

预处理 + 一遍扫描，总共两趟：

![枚举山峰 + 前后缀最小模型](images/mtn_i_peak_prefix_suffix.svg)

**完整步骤**：

1. **从右往左**递推后缀最小数组：$\text{suf}[n] = +\infty$（哨兵），$\text{suf}[k] = \min(\text{nums}[k], \text{suf}[k+1])$，于是 $\min(\text{nums}[j+1..n-1]) = \text{suf}[j+1]$；
2. **从左往右**枚举山峰 $j$，滚动变量 `preMin` 维护 $\min(\text{nums}[0..j-1])$（初始 $+\infty$）；
3. 若 `preMin < nums[j]` 且 `suf[j+1] < nums[j]`，用 `preMin + nums[j] + suf[j+1]` 更新答案；
4. 处理完 $j$ 后 `preMin = min(preMin, nums[j])`；扫描结束答案仍为 $+\infty$ 则返回 `-1`。

### 3.4 示例演算

以示例 1 `nums = [8,6,1,5,3]` 为例。先从右往左建 `suf`（$\text{suf}[k] = \min(\text{nums}[k..4])$）得 $[1,1,1,3,3,+\infty]$，再从左往右枚举山峰：

| $j$ | nums[j] | preMin（左侧最小） | suf[j+1]（右侧最小） | 山峰成立？ | 候选和 |
|-----|---------|-------------------|---------------------|-----------|--------|
| 0 | 8 | $+\infty$（左边没元素） | 1 | ✗ | — |
| 1 | 6 | 8 | 1 | ✗（$8 \ge 6$） | — |
| 2 | 1 | 6 | 3 | ✗（$6 \ge 1$） | — |
| **3** | **5** | **1** | **3** | **✓（$1 < 5$ 且 $3 < 5$）** | **$1+5+3 = 9$** |
| 4 | 3 | 1 | $+\infty$（右边没元素） | ✗ | — |

![示例演算表](images/mtn_i_example_walkthrough.svg)

答案 $9$ ✓。示例 2 `[5,4,8,7,10,2]` 同一流程：$j=2,3,4$ 处分别得候选 $14,13,16$，最小 $13$（三元组 $(1,3,5)$：$4+7+2$）✓。示例 3 `[6,5,4,3,4,5]` 全程无合法山峰，返回 $-1$ ✓——它是先降后升的**山谷**，一座山都没有。

## 4. 算法细节

1. **后缀数组 + 哨兵**：`suf` 开 $n+1$ 格，$\text{suf}[n] = +\infty$。$j$ 恰为最后一个元素时「右侧最小」自动取到哨兵，判定 `suf[j+1] < nums[j]` 天然失败，**无需特判右边界**。
2. **滚动前缀最小**：`preMin` 是单变量，从左往右扫 $j$ 时顺手更新。判定**之后**才把 `nums[j]` 并入，保证它永远只代表 $j$ **严格左侧**的最小值。
3. **更新顺序**：`if (preMin < nums[j] && suf[j+1] < nums[j])` 在前，`preMin = min(preMin, nums[j])` 在后——写反了会把 `nums[j]` 自己算进左侧候选，山形条件退化为自比。
4. **答案初值**：`ans = INT_MAX`（Python 用 `inf`），循环结束仍为初值即返回 `-1`。本题元素均为正数，不存在和为 $0$ 的合法三元组干扰判定。

## 5. 正确性证明

**引理 1（合法性等价判定）**：固定 $j$，存在合法的 $i$（即 $i < j$ 且 $\text{nums}[i] < \text{nums}[j]$）当且仅当 $\text{preMin}(j) < \text{nums}[j]$；右侧同理，存在合法的 $k$ 当且仅当 $\text{suf}(j+1) < \text{nums}[j]$。

**证明**：若存在合法 $i$，则 $\text{preMin}(j) \le \text{nums}[i] < \text{nums}[j]$。反之若 $\text{preMin}(j) < \text{nums}[j]$，取到前缀最小值的下标 $i^\ast$ 即合法的 $i$。右侧对称。∎

**引理 2（固定山峰的最优分解）**：若 $j$ 是合法山峰（引理 1 两条件同时成立），则 $j$ 固定时元素和最小的山形三元组恰为 $(i^\ast, j, k^\ast)$，其中 $i^\ast$ 取左侧最小、$k^\ast$ 取右侧最小，和为 $\text{preMin}(j) + \text{nums}[j] + \text{suf}(j+1)$。

**证明**：目标函数 $\text{nums}[i] + \text{nums}[j] + \text{nums}[k]$ 中三项分别只依赖 $i$、$j$、$k$。固定 $j$ 后，$i \in \{0..j-1\}$、$k \in \{j+1..n-1\}$ 两个候选集不相交、取值互不约束，最小化可分解为两个独立子问题，各自取最小即全局最小。又由引理 1，取最小值的位置本身合法。∎

**定理**：算法返回 `nums` 中元素和最小的山形三元组的元素和；不存在时返回 `-1`。

**证明**：任意山形三元组 $(i,j,k)$ 的中间下标 $j$ 必是合法山峰（山形条件即引理 1 的两条件），故全体山形三元组被「枚举合法山峰 $j$」完备覆盖。对每个合法 $j$，由引理 2 算法取到该 $j$ 下的最小和；再对所有 $j$ 取 $\min$，即全局最小。若全程无合法山峰，则由上述覆盖关系不存在任何山形三元组，返回 `-1` 正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。从右往左建 `suf` 一遍 + 从左往右枚举山峰一遍，每步常数次比较。暴力版为 $O(n^3)$，在 $n \le 50$ 下约 $2 \times 10^4$ 次也能通过，但无法平移到 Q2（$n \le 10^5$ 时 $O(n^3) \approx 1.7 \times 10^{14}$、$O(n^2) \approx 10^{10}$ 均超时）。
- **空间复杂度**：$O(n)$。后缀最小数组 `suf`；`preMin` 与 `ans` 均为滚动变量，只占 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumSum(vector<int>& nums) {
        int n = nums.size();
        vector<int> suf(n + 1, INT_MAX);            // suf[k] = min(nums[k..n-1])，哨兵 suf[n] = +∞
        for (int k = n - 1; k >= 0; k--)
            suf[k] = min(nums[k], suf[k + 1]);

        int ans = INT_MAX, preMin = INT_MAX;        // preMin 滚动维护 = min(nums[0..j-1])
        for (int j = 0; j < n; j++) {
            if (preMin < nums[j] && suf[j + 1] < nums[j])   // 两侧都有更矮的 → j 是合法山峰
                ans = min(ans, preMin + nums[j] + suf[j + 1]);
            preMin = min(preMin, nums[j]);                  // 用完 j 再收编 nums[j]
        }
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minimumSum(self, nums: List[int]) -> int:
        n = len(nums)
        suf = [inf] * (n + 1)                       # suf[k] = min(nums[k:])，哨兵 suf[n] = +∞
        for k in range(n - 1, -1, -1):
            suf[k] = min(nums[k], suf[k + 1])

        ans = pre_min = inf                         # pre_min 滚动维护 = min(nums[:j])
        for j, x in enumerate(nums):
            if pre_min < x and suf[j + 1] < x:      # 两侧都有更矮的 → j 是合法山峰
                ans = min(ans, pre_min + x + suf[j + 1])
            pre_min = min(pre_min, x)               # 用完 j 再收编 x
        return -1 if ans == inf else ans
```

> 💡 这份线性代码**一字不改**提交同场 Q2（2909，$n \le 10^5$）即可通过：元素和上限 $3 \times 10^8 < 2^{31}-1$，`int` 也不会溢出。

## 8. 边界情况与易错点

1. **严格小于别写成 $\le$**：山形条件两侧都是**严格**比较。`nums = [3,3,3]` 正确答案是 `-1`（等高不算山峰）；把 `preMin < nums[j]` 写成 `<=` 会错误返回 9。
2. **更新顺序别写反**：必须先用「旧的」`preMin` 判定 $j$，再把 `nums[j]` 并进去；否则左侧候选混入山峰自身，判定失真。
3. **端点山峰靠哨兵兜底**：$j = 0$（左侧无元素）由 `preMin` 初值 $+\infty$ 兜住，$j = n-1$（右侧无元素）由 `suf[n] = +∞` 兜住，都无需 if 特判。
4. **无解返回 -1**：单调递增、单调递减、山谷形数组都没有山峰；`ans` 保持初值时返回 `-1`，不要返回 `INT_MAX` 或 0。
5. **$n = 3$ 的最小规模**：唯一候选三元组 $(0,1,2)$，判一次即可，两套代码天然覆盖。
6. **溢出评估**：I 版和至多 $150$；即便 Q2 版和至多 $3 \times 10^8$，仍在 `int` 范围内，无需 `long long`。
