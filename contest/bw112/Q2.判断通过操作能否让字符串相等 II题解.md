# LeetCode 判断通过操作能否让字符串相等 II 题解

## 1. 题目概述

- **标题 / 题号**：判断通过操作能否让字符串相等 II（#2840，medium）
- **链接**：https://leetcode.cn/problems/check-if-strings-can-be-made-equal-with-operations-ii/
- **来源**：LeetCode 第 112 场双周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、排序

**题意**：给定长度均为 $n$、只含小写字母的字符串 $s_1, s_2$。你可以对**任意一个**字符串执行**任意次**以下操作：选择下标 $i < j$ 且 $j - i$ 为**偶数**，交换这两个下标上的字符。若能让 $s_1$ 与 $s_2$ 相等，返回 `true`；否则返回 `false`。

**约束**：

- $1 \le n \le 10^5$
- 两串只含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s1 = "abcdba", s2 = "cabdab"
输出：true
解释：对 s1 依次操作：(0,2)→"cbadba"，(2,4)→"cbbdaa"，(1,5)→"cabdab" = s2。
```

**示例 2**

```text
输入：s1 = "abe", s2 = "bea"
输出：false
解释：s1 的偶下标字符是 {a,e}、奇下标是 {b}；
     s2 的偶下标字符是 {b,a}、奇下标是 {e}。
     'a'（偶轨道）在 s2 的偶轨道中，但 'e' 与 'b' 分属的轨道恰好错开，
     两串的偶轨道多重集 {a,e} ≠ {b,a}，无法相等。
```

**示例 3（边界补充）**

```text
输入：s1 = "a", s2 = "a"
输出：true
解释：n = 1，两串已相等；奇轨道为空。
```

## 3. 解题思路

### 3.1 暴力思路

与 Q1（#2839）同一操作，但长度从 4 放大到 $10^5$，「枚举全部可达状态」彻底失效：偶轨道大小约 $n/2$，可达排列数高达 $(n/2)!$。然而**判定条件**并不需要枚举——Q1 里「轨道多重集相等」的必要条件在此依然成立，唯一要补齐的是**充分性**：长轨道上，只靠「距离为偶数」的交换能否实现轨道内的**任意**重排？答案是肯定的，证明也简短（见 §5）。

### 3.2 核心观察：两条轨道内交换生成全排列

![核心观察：偶下标链与奇下标链各自可任意重排](images/bw112_q2_even_odd_permutation.svg)

$j - i$ 为偶数 $\iff i, j$ 同奇偶。于是字符被锁进两条轨道：偶下标 $\{0, 2, 4, \dots\}$ 与奇下标 $\{1, 3, 5, \dots\}$；轨道内**任意两点**都可一步交换（距离必为偶数）。轨道内「任意对换都可用」意味着轨道内的**任意排列都可达**——对换生成对称群。

因此判定与 Q1 完全同构：**$s_1$ 能变成 $s_2$ $\iff$ 两串偶下标字符多重集相等，且奇下标字符多重集相等**。实现上取 $s_1[0::2]$、$s_2[0::2]$、$s_1[1::2]$、$s_2[1::2]$ 四个切片，各自排序后比较；或用 26 桶计数比较。

### 3.3 算法流程

```text
1. a0 = s1 的偶下标子序列，b0 = s2 的偶下标子序列
2. a1 = s1 的奇下标子序列，b1 = s2 的奇下标子序列
3. 返回 sorted(a0) == sorted(b0) 且 sorted(a1) == sorted(b1)
```

计 $n = |s_1|$：切片 $O(n)$，排序 $O(n \log n)$；用 26 桶可压到 $O(n + 26)$。

### 3.4 示例演算

![示例演算：切片排序比较的完整流程](images/bw112_q2_walkthrough.svg)

以示例 1 为例：$s_1 = $ a(0) b(1) c(2) d(3) b(4) a(5)，$s_2 = $ c(0) a(1) b(2) d(3) a(4) b(5)。

| 串 | 偶下标序列（0,2,4） | 排序 | 奇下标序列（1,3,5） | 排序 |
|----|--------------------|------|--------------------|------|
| "abcdba" | a c b → "acb" | abc | b d a → "bda" | abd |
| "cabdab" | c b a → "cba" | abc | a d b → "adb" | abd |

两轨道排序后均相等（`abc` = `abc`，`abd` = `abd`），返回 `true`，与官方「三次交换」的解释殊途同归——官方给出的 (0,2)、(2,4)、(1,5) 三次操作全是同奇偶交换，本质上就是在两条轨道内各自归位。

示例 2：$s_1 = $ a(0) b(1) e(2)，$s_2 = $ b(0) e(1) a(2)。偶下标 $s_1$ 取 "ae"（排序 "ae"）、$s_2$ 取 "ba"（排序 "ab"），`ae ≠ ab`，返回 `false`——'a' 与 'b' 各自被锁在自己的轨道里，永远换不过去。

## 4. 算法细节

1. **切片即轨道**：`s[0::2]` 恰是偶下标子序列、`s[1::2]` 恰是奇下标子序列，Python 一步取好；C++ 用 `i & 1` 分桶累加。
2. **多重集比较的两 implements**：排序（$O(n\log n)$，代码最短）或 26 个计数桶（$O(n)$，最稳）。$n = 10^5$ 下两者都轻松，标签里的「哈希表」即计数桶思路。
3. **空轨道**：$n = 1$ 时奇轨道为空串，空串排序后相等恒真，无需特判。
4. **「任意一个字符串」操作**：判定条件对称（多重集相等），不区分对谁操作；若两串轨道多重集相等，把 $s_1$ 轨道内重排成 $s_2$ 即可（充分性见 §5）。
5. **$j-i$ 偶数包含 $j = i$？**：题目要求 $i < j$，同一位置不构成操作；这不影响结论——对换本就要求两点不同。
6. **复杂度核**：排序版 $O(n \log n)$ 时间、$O(n)$ 空间；计数版 $O(n + |\Sigma|)$ 时间、$O(|\Sigma|)$ 空间（$|\Sigma| = 26$）。

## 5. 正确性证明

**引理 1（奇偶不变量）**：任何操作交换的两个下标奇偶性相同，故每个字符始终处于与初始下标同奇偶的位置。

**证明**：$j - i$ 为偶数 $\iff i \equiv j \pmod 2$。交换不改变「占据各下标的字符来自哪条轨道」，归纳于操作次数即得。∎

**推论（必要性）**：若 $s_1$ 可变为 $s_2$，则两串偶下标字符多重集相等、奇下标字符多重集相等——偶轨道字符始终在偶轨道，终态 $s_2$ 的偶下标字符恰为 $s_1$ 偶下标字符的某个排列。

**引理 2（轨道内对换完备）**：同一轨道（同奇偶下标集合）内任意两个不同下标 $p, q$，存在一步操作直接交换它们。

**证明**：同轨道内 $|p - q|$ 为偶数且非零，取 $i = \min(p,q), j = \max(p,q)$，满足 $i < j$ 与 $j - i$ 偶，恰为一次合法操作。∎

**引理 3（轨道内可达任意排列）**：设轨道大小为 $t$，轨道内字符的任意目标排列均可经有限次轨道内操作实现。

**证明**：对称群 $S_t$ 由全部对换生成。对目标排列 $\pi$，从左到右归位：位置 $p$ 当前字符若不是目标字符，由引理 2 可与「该目标字符当前所在位置 $q$」（同轨道）一步对换；每次对换至少归位一个位置（把目标字符放到 $p$），至多 $t$ 次后全部归位。∎

**定理**：$s_1$ 可经有限次操作变为 $s_2$ $\iff$ 两串偶下标字符多重集相等且奇下标字符多重集相等。

**证明**：（⇒）引理 1 推论。（⇐）设两轨道多重集分别相等，则存在偶轨道排列 $\pi_e$ 与奇轨道排列 $\pi_o$ 使 $s_1$ 的偶、奇轨道分别映到 $s_2$ 的对应轨道。两条轨道互不相交、操作各自独立，由引理 3 分别实现 $\pi_e$ 与 $\pi_o$，按任意顺序执行后 $s_1 = s_2$。∎

## 6. 复杂度分析

- **时间**：排序实现 $O(n \log n)$（四个切片的排序合计）；计数实现 $O(n + 26)$。$n = 10^5$ 时排序版约 $10^5 \times 17$ 次比较，毫无压力。
- **空间**：排序实现 $O(n)$（切片副本）；计数实现 $O(26)$ 桶、若原地遍历可 $O(1)$ 额外。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkStrings(string s1, string s2) {
        int c1[2][26] = {0}, c2[2][26] = {0};
        for (int i = 0; i < (int)s1.size(); ++i) {
            ++c1[i & 1][s1[i] - 'a'];
            ++c2[i & 1][s2[i] - 'a'];
        }
        for (int p = 0; p < 2; ++p)
            for (int ch = 0; ch < 26; ++ch)
                if (c1[p][ch] != c2[p][ch]) return false;
        return true;
    }
};
```

### Python

```python
class Solution:
    def checkStrings(self, s1: str, s2: str) -> bool:
        return sorted(s1[0::2]) == sorted(s2[0::2]) and \
               sorted(s1[1::2]) == sorted(s2[1::2])
```

> 💡 两份代码均通过官方示例（`true`、`false`）与 $n = 1$ 两例，并与「枚举偶轨道全排列 × 奇轨道全排列」的暴力（$n \le 7$，小字母表提高碰撞率）做了 6 万组（C++，等效桶比较）/ 6 千组（Python）随机对拍，失配数为 0。

## 8. 边界情况与易错点

1. **多重集而非集合**：必须带重数比较（排序或计数桶）；用 `set` 去重会在重复字符场景下误判，如 `s1 = "aabb"` vs `s2 = "bbaa"`（偶轨道 `ab` vs `ba` 排序同为 `ab` ✓，奇轨道同 ✓ → true；但 `set` 版会把 `ab` 与 `ab` 混同后漏掉数量差）。
2. **空奇轨道**：$n = 1$ 时 `s[1::2]` 为空串，空 == 空成立，无需特判；C++ 桶版本天然处理。
3. **$i < j$ 且偶差**：别把「$j - i$ 是偶数」误读成「$j$ 与 $i$ 都是偶数」——奇下标之间的差同样为偶数，两条轨道都开放。
4. **大 $n$ 的字符串拷贝**：Python 切片 `s[0::2]` 会复制约 $n/2$ 字符，四次拷贝 $O(n)$，可接受；若追求常数可用 `Counter(s[0::2]) == Counter(...)` 或双指针原地计数。
5. **与 Q1 的关系**：判定条件一模一样，Q1 是 $n = 4$（轨道大小 2）的特例；Q2 的证明重心在「长轨道内对换生成全排列」（引理 2/3），Q1 只需验证大小 2 的两条排列。
