# LeetCode 几乎唯一子数组的最大和 题解

## 1. 题目概述

- **标题 / 题号**：几乎唯一子数组的最大和（#2841，medium）
- **链接**：https://leetcode.cn/problems/maximum-sum-of-almost-unique-subarray/
- **来源**：LeetCode 第 112 场双周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口

**题意**：给定整数数组 `nums` 与正整数 $m, k$。若 `nums` 的一个子数组含有**至少 $m$ 个互不相同的元素**，称它是**几乎唯一**子数组。返回长度恰为 $k$ 的几乎唯一子数组的**最大和**；不存在则返回 $0$。

**约束**：

- $1 \le n \le 2 \times 10^4$
- $1 \le m \le k \le n$
- $1 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,6,7,3,1,7], m = 3, k = 4
输出：18
解释：长度为 4 的子数组中 [2,6,7,3] 不同元素 4 个 ≥ 3，和 18 最大。
```

**示例 2**

```text
输入：nums = [5,9,9,2,4,5,4], m = 1, k = 3
输出：23
解释：[5,9,9] 含 2 个不同元素 ≥ 1，和 23 最大。
```

**示例 3**

```text
输入：nums = [1,2,1,2,1,2,1], m = 3, k = 3
输出：0
解释：任何长度 3 的窗口最多 2 个不同元素，不满足 m = 3，返回 0。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $n - k + 1$ 个长度为 $k$ 的子数组，每个用哈希表统计不同元素数并求和——$O(nk)$，$n = 2 \times 10^4$、$k$ 同阶时约 $4 \times 10^8$ 次操作，会超时。连续窗口的重叠部分（相邻窗口共享 $k-1$ 个元素）被反复重算，这正是**滑动窗口**的用武之地。

### 3.2 核心观察：定长窗口的三个量都可增量维护

![核心观察：相邻窗口共享 k−1 个元素，三量增量更新](images/bw112_q3_sliding_window.svg)

窗口从 $[i-k, i-1]$ 滑到 $[i-k+1, i]$：离开的只有 $nums[i-k]$、进入的只有 $nums[i]$，其余 $k - 1$ 个元素原封不动。因此三个统计量都能 $O(1)$ 增量更新：

- **和** `sum`：进 $+\ nums[i]$，出 $-\ nums[i-k]$；
- **每个值的出现次数** `cnt`：进 `cnt[nums[i]]++`，出 `cnt[nums[i-k]]--`；
- **不同值个数** `distinct`：某值计数从 0 变 1 时 $+1$，从 1 变 0 时 $-1$。

窗口右端 $i$ 从 $k-1$ 扫到 $n-1$，每个右端恰对应一个合法窗口，`distinct >= m` 时用 `sum` 更新答案。

### 3.3 算法流程

```text
1. cnt 为空哈希表，sum = 0, distinct = 0, ans = 0
2. for i in 0..n−1：
       进入 nums[i]：cnt 从 0 → 1 则 distinct++；sum += nums[i]
       若 i ≥ k：离开 nums[i−k]：cnt 减到 0 则 distinct−−（并删除键）；sum −= nums[i−k]
       若 i ≥ k−1 且 distinct ≥ m：ans = max(ans, sum)
3. 返回 ans
```

注意进出顺序：先处理「进」再处理「出」（或反之）皆可，但必须保证同一轮内进出都发生在检查答案**之前**，且 $i = k - 1$ 时窗口首次成型、尚无元素离开。

### 3.4 示例演算

![示例演算：三个窗口的 distinct 与 sum 逐步变化](images/bw112_q3_walkthrough.svg)

以示例 1 `nums = [2,6,7,3,1,7]`、$m = 3$、$k = 4$ 为例：

| i | 窗口 | cnt（值→次数） | distinct | sum | 更新 ans |
|---|------|----------------|----------|-----|----------|
| 3 | [2,6,7,3] | 2:1,6:1,7:1,3:1 | 4 | 18 | 18 |
| 4 | [6,7,3,1] | 6:1,7:1,3:1,1:1 | 4 | 17 | 18 |
| 5 | [7,3,1,7] | 7:2,3:1,1:1 | 3 | 18 | 18 |

$i = 5$ 时 `7` 第二次出现，distinct 不增（仍 3），窗口仍满足 $m = 3$。最终答案 $18$ ✓。注意第三个窗口里 `7:2` 展示了「重复值不增加 distinct 但占窗口容量」的关键区别。

## 4. 算法细节

1. **先判空再返回 0**：`ans` 初始化为 0，若没有任何窗口满足 `distinct >= m` 自然返回 0——「不存在返回 0」不需要特判分支（和全为正数，`max` 初值 0 不会误判负数窗口；本题 $nums[i] \ge 1$ 保证了这一点）。
2. **计数表的键删除**：`cnt[v]` 减到 0 时把键删掉（Python `del`）或保留 0 计数（C++ 哈希表 0 值无碍），两种写法的 `distinct` 维护都必须以「计数跨过 0 ↔ 1 边界」为触发，别用「键存在与否」判断。
3. **进出的下标错位**：进入的是 `nums[i]`，离开的是 `nums[i - k]`；`i >= k` 才有元素离开。写成 `nums[i - 1]` 或 `nums[i - k + 1]` 是最常见的 off-by-one。
4. **溢出**：$k \times \max(nums) \le 2 \times 10^4 \times 10^9 = 2 \times 10^{13}$，超出 32 位；C++ 必须用 `long long`，Python 天然大整数。
5. **unordered_map 的键类型**：$nums[i] \le 10^9$ 用 `int` 键即可；也可先离散化（排序 + 去重 + 二分）压成下标，对 $n = 2 \times 10^4$ 无必要。
6. **定长窗口写法**：本题窗口长度固定为 $k$（不是「至多/至少」的可变窗口），用「右端扫一遍 + 左端 $i-k$ 自动出窗」的单循环最不易错；经典两指针 while 收缩写法在这里反而容易把长度搞错。

## 5. 正确性证明

**引理 1（窗口遍历完备）**：算法在右端 $i = k-1, k, \dots, n-1$ 各检查一个窗口 $[i-k+1, i]$，恰好无重复无遗漏地覆盖全部长度为 $k$ 的子数组。

**证明**：长度为 $k$ 的子数组由其右端 $r \in [k-1, n-1]$ 唯一确定，算法对每个 $r$ 恰检查一次窗口 $[r-k+1, r]$。∎

**引理 2（增量维护的正确性）**：在每个检查时刻，`sum` 等于当前窗口元素之和，`distinct` 等于当前窗口内不同值的个数。

**证明**：对 $i$ 归纳。$i < k$ 时窗口未成型，仅维护 `sum/cnt` 的进入部分，归纳显然。设 $i \ge k$ 且第 $i-1$ 轮结束时三量对窗口 $[i-k, i-1]$ 正确。第 $i$ 轮：进入 $x = nums[i]$ 使 `cnt[x]` 加一——从 0 变 1 意味着 $x$ 是窗口新出现的不同值（旧窗口不含 $x$），`distinct` 加 1 正确；从 $\ge 1$ 变为更大意味着 $x$ 已在旧窗口中，不同值集合不变，`distinct` 不动正确。离开 $y = nums[i-k]$ 使 `cnt[y]` 减一——减到 0 意味着新窗口（$[i-k+1, i]$）不再含 $y$，`distinct` 减 1 正确；减后仍 $\ge 1$ 意味着 $y$ 在新窗口中仍出现，`distinct` 不动正确。`sum` 的加减与元素进出严格对应。故第 $i$ 轮结束时三量对 $[i-k+1, i]$ 正确。∎

**定理**：算法返回长度为 $k$ 的几乎唯一子数组的最大和（不存在时为 0）。

**证明**：由引理 1，候选窗口全覆盖；由引理 2，每个窗口的判定（`distinct >= m`）与取值（`sum`）均准确。`ans` 为所有满足条件窗口之和的最大值；若不存在满足条件的窗口，`ans` 保持初值 0。∎

## 6. 复杂度分析

- **时间**：$O(n)$ 均摊。每个元素恰好进入窗口一次、离开一次，每次进出是 $O(1)$ 哈希操作（`unordered_map` 均摊 $O(1)$；最坏哈希冲突可换离散化 + 数组计数保证严格 $O(1)$）。
- **空间**：$O(k)$。计数表至多容纳窗口内 $k$ 个不同键（键数 $\le \min(k, n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxSum(vector<int>& nums, int m, int k) {
        unordered_map<int, int> cnt;      // 窗口内每个值的出现次数
        int distinct = 0;
        long long sum = 0, ans = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (cnt[nums[i]]++ == 0) ++distinct;
            sum += nums[i];
            if (i >= k) {                              // 左端滑出
                int out = nums[i - k];
                sum -= out;
                if (--cnt[out] == 0) { cnt.erase(out); --distinct; }
            }
            if (i >= k - 1 && distinct >= m) ans = max(ans, sum);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, nums: list[int], m: int, k: int) -> int:
        cnt = Counter()
        distinct = 0
        s = 0
        ans = 0
        for i, x in enumerate(nums):
            if cnt[x] == 0:
                distinct += 1
            cnt[x] += 1
            s += x
            if i >= k:                     # 左端滑出
                out = nums[i - k]
                s -= out
                cnt[out] -= 1
                if cnt[out] == 0:
                    del cnt[out]
                    distinct -= 1
            if i >= k - 1 and distinct >= m:
                ans = max(ans, s)
        return ans
```

> 💡 两份代码均通过官方示例（`18`、`23`、`0`）与 $k = n$ 全窗、$k = 1$ 单元素等边界，并与暴力枚举子数组做了 10 万组（C++）/ 2 万组（Python）随机对拍（小字母表提高 $m$ 命中与不命中两分支覆盖率），另验证 $n = 2\times10^4$、值 $10^9$ 的溢出用例（结果 $2 \times 10^{13}$，`long long` 正确承接），失配数为 0。

## 8. 边界情况与易错点

1. **答案初值 0**：「不存在返回 0」由初值天然覆盖；但若题目改成元素可负、要求「无解返回 −1」之类，初值语义要跟着改——本题 $nums[i] \ge 1$ 使 0 是安全的「无解哨兵」。
2. **进出的下标**：出窗下标是 $i - k$ 不是 $i - k + 1$；`i >= k` 才有出窗（首个成型窗口 $i = k-1$ 时没有离开者）。
3. **distinct 的增减时机**：以「计数跨越 0 ↔ 1」为准；先加后查（`cnt[v]++ == 0`）或先查后加（`cnt[v] == 0` 再 `+= 1`）都对，但两处（进/出）必须对称，混用会算重或算漏。
4. **溢出**：窗口和最大 $2 \times 10^{13}$，C++ 用 `long long`（返回类型题目已给 `long`）；`int` 会静默溢出出负数。
5. **$m > $ 窗口可达不同数**：如示例 3（值域只有 2 个不同值、$m = 3$），全程不更新，返回 0——对拍时专门覆盖这种「永远无解」分支。
6. **$m = 1$ 退化**：任何非空窗口都满足，等价于「长度 $k$ 的最大子数组和」，滑窗照跑即可，无需特判。
7. **重复值**：`[7,3,1,7]` 中第二个 7 不增加 distinct（见 §3.4 表）；「不同元素个数」不是「元素个数」，判 $m$ 的对象别搞错。
