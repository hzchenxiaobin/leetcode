# LeetCode 有向图访问计数 题解

## 1. 题目概述

- **标题 / 题号**：有向图访问计数（#2876，hard）
- **链接**：https://leetcode.cn/problems/count-visited-nodes-in-a-directed-graph/
- **来源**：LeetCode 第 365 场周赛 Q4
- **难度**：困难
- **标签**：图、拓扑排序、动态规划、基环森林

**题意**：$n$ 个节点（编号 $0 \sim n-1$）构成一张有向图，图中**恰好有 $n$ 条有向边**，且第 $i$ 条边从节点 $i$ 指向 `edges[i]`——即**每个节点的出度恰为 1**。从任意节点 $x$ 出发不断沿出边走，直到**在此过程中首次**再次碰到已访问过的节点为止。对每个起点 $i$，求这一过程访问到的**不同节点数** `answer[i]`。

**约束**：

- $2 \le n \le 10^5$
- $0 \le \text{edges}[i] \le n-1$
- $\text{edges}[i] \ne i$（无自环，环长至少为 2）

> 💡 破题的钥匙全藏在「$n$ 个点配 $n$ 条边、每点恰一条出边」这句约束里：这不是普通图，是**函数图**（functional graph），即**内向基环森林**。本题另有[每日题解 2876](../../solution/2801-2900/2876_有向图访问计数.md)，主推**全局时间戳一次遍历**的写法；本文与其互为印证，换**拓扑排序「剥叶子」**这条赛场模板路线展开——先剥尽树枝、再对环整体定值、最后沿剥离逆序递推，分阶段、可证明、易默写。

## 2. 示例

**示例 1**

```text
输入：edges = [1,2,0,0]
输出：[3,3,3,4]

解释：0 -> 1 -> 2 -> 0 构成环，从 0/1/2 出发都是绕环一圈回到自己，访问 3 个节点；
     从 3 出发先走 3 -> 0 进环，之后与从 0 出发无异，共 3 + 1 = 4 个。
```

**示例 2（整图一个大环）**

```text
输入：edges = [1,2,3,4,0]
输出：[5,5,5,5,5]

解释：5 个节点连成一个环，从任何点出发都能访问全部 5 个节点。
```

**补充示例（森林：多个分量各带一个环）**

```text
输入：edges = [1,2,0,0,5,4,4,5]
输出：[3,3,3,4,2,2,3,3]

解释：分量一：环 0→1→2→0（L=3），挂树枝 3→0；
     分量二：环 4↔5（L=2），挂两条树枝 6→4、7→5。
     环上答案 = 环长；树枝答案 = 到环步数 + 环长。
```

## 3. 解题思路

### 3.1 暴力思路：每个起点各自模拟

对每个起点 $i$ 沿出边走，用布尔数组记录访问过的节点，碰到已访问节点即停，计数即为 `answer[i]`。单次最坏走 $O(n)$ 步，总计 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时。

> ⚠️ 暴力法的浪费是**结构性重复**：同一根「树枝」上的所有起点，路径都是「环上某点的路径」前面拼一小截；每个点都独立重走一遍，做了海量重复功。要让先算出的答案被后来的起点复用，必须先看清这张图长什么样。

### 3.2 核心观察：内向基环森林

![内向基环森林结构](images/wc365_q4_functional_forest.svg)

三个层层递进的观察：

**观察一（图的结构）**：每点出度恰为 1，从任意节点沿出边走 $n+1$ 步，由**鸽巢原理**必有重复，重复点集构成**环**；不在环上的节点沿出边走最终都汇入环。于是每个连通分量都是「一个环 + 若干指向环的树枝」，即**内向基环树**，整图是基环树的森林。`edges[i] != i` 排除了自环，环长至少为 2。

**观察二（答案公式）**：从任何点出发，过程都是「先沿树枝进环，再绕环一整圈回到进环点」，到此为止——**环外的其他树枝根本走不到**。于是：

$$\text{ans}[u] = d(u) + L$$

其中 $L$ 是 $u$ 所在环的长度，$d(u)$ 是 $u$ 沿出边走到环上的步数（环上节点 $d = 0$，答案就是 $L$）。

**观察三（一步递推）**：树枝节点 $u$ 走一步到 `edges[u]`，之后的旅程与从 `edges[u]` 出发完全相同，只多看一个节点 $u$ 自己：

$$\text{ans}[u] = \text{ans}[\text{edges}[u]] + 1$$

前提是**后继的答案已就绪**。环上节点的答案整环一起定（互为后继，谁也不依赖环外）；树枝节点的答案依赖更靠近环的后继。处理顺序自然浮出水面：**先定环，再从环向外倒推树枝**。

> ⚠️ 易错直觉：`ans[u]` **不等于**所在分量的大小。补充示例里分量一大小为 4，但节点 0 的答案只有 3——绕环一圈回到自己即停，节点 3 不会被访问到。能被访问到的恰好是「自己的进环路径 + 整个环」。

### 3.3 算法流程：拓扑排序「剥叶子」

![拓扑剥叶子流程](images/wc365_q4_topo_peeling_flow.svg)

「先定环、再向外倒推」的第一步，是把**环上节点**与**树枝节点**区分开。拓扑排序剥叶子恰好干的就是这件事：

1. **统计入度**：`indeg[v]` = 有多少条边指向 $v$。
2. **剥叶子**：入度为 0 的节点没有任何前驱，全部入队；每出队一个节点 $u$，把它对后继 `edges[u]` 的入度贡献减一；谁的入度因此归零，谁接着入队。
3. **剥不动的就是环**：环上每个节点永远有环内前驱（环长 ≥ 2），入度永不归零；而所有树枝节点最终都会被剥光。队空后，**入度仍大于 0 的节点恰好是全部环节点**。
4. **整环定值**：对每个未定值的环节点沿环走一圈，环长 $L$ 即环上所有点的答案。
5. **逆序递推**：按剥离顺序 `order` 的**逆序**扫一遍，`ans[u] = ans[edges[u]] + 1`——剥离时 $u$ 必然先于其后继（若后继也是树枝）被剥掉，逆序处理到 $u$ 时后继答案必已就绪。

### 3.4 示例演算

以示例 1 `edges = [1,2,0,0]` 为例，四个阶段完整走一遍：

![示例 1 演算](images/wc365_q4_example_walkthrough.svg)

1. **初始入度**：节点 0 被 2、3 指向（入度 2），节点 1、2 各入度 1，节点 3 无人指向（入度 0）。
2. **剥叶子**：3 入队并出队，`indeg[0]` 由 2 减到 1（仍大于 0，不再入队），队列空。剥离顺序 `order = [3]`。
3. **识环定值**：入度仍大于 0 的 $\{0,1,2\}$ 是环，沿 $0 \to 1 \to 2 \to 0$ 走一圈，$L = 3$，故 `ans[0] = ans[1] = ans[2] = 3`。
4. **逆序递推**：`order` 逆序只有 3 一个节点，`ans[3] = ans[edges[3]] + 1 = ans[0] + 1 = 4`。

最终 `answer = [3,3,3,4]` ✓。

## 4. 算法细节

1. **入度即「前驱计数」**：`indeg[v]` 统计所有满足 `edges[i] == v` 的 $i$。出边无需建邻接表——`edges[u]` 本身就是 $u$ 的唯一出边，全程 $O(1)$ 定位后继，空间也省下一份。
2. **队列与顺序表合一**：`order` 数组本身就是队列——先把入度为 0 的节点顺序压入，再用下标从左到右扫描，扫到的即「出队」节点；新归零的节点继续追加到尾部。C++ 用下标循环、Python 直接 `for u in order` 边遍历边追加，都不需要单独的 `deque`。
3. **环检测零成本**：剥完无需任何额外标记数组，直接判 `indeg[i] > 0`——能活到最后的节点必然在环上（§5 引理 3）。
4. **整环一起定值**：从一个环节点出发沿 `edges` 走回自身，即得整条环与环长 $L$。用 `ans[i] == 0` 做哨兵避免同一环被多个入口重复走——环上答案 $\ge 2$、树枝答案 $\ge 3$，合法答案不会是 0，故 0 可安全地表示「未定值」。
5. **剥离顺序天然「由外向内」**：离环越远的节点越早被剥（它是更外层的叶子），`order` 尾部是最贴近环的树枝；逆序即「由内向外」，从紧邻环的节点开始递推，一步接一步永不断链。

## 5. 正确性证明

**引理 1（必停与进环）**：从任意节点 $u$ 出发沿出边行走，必在有限步内首次重访某个节点；且首次重访发生时，恰好访问了「$u$ 到环的路径上的全部节点」与「环上全部节点」，合计 $d(u) + L$ 个不同节点。

**证明**：出度均为 1，行走序列 $u, f(u), f^2(u), \dots$（$f = \text{edges}$）无分叉。取最小的 $t$ 使 $f^t(u)$ 等于某个 $f^s(u)$（$s < t$），则 $f^s(u), \dots, f^{t-1}(u)$ 构成一个环，$f^s(u)$ 是路径上首个环上节点，$s = d(u)$，环长 $t - s = L$。途中不同节点恰为 $f^0(u), \dots, f^{t-1}(u)$：前 $s$ 个是入环路径（树枝部分），后 $L$ 个正是环上全部节点（从入口绕一圈回到入口，环上每个节点恰好经过一遍），共 $s + (t - s) = d(u) + L$ 个。∎

**引理 2（答案公式）**：设 $u$ 所在环长为 $L$，$d(u)$ 为 $u$ 沿出边到环的最少步数，则 $\text{ans}[u] = d(u) + L$。

**证明**：由引理 1，从 $u$ 出发的过程恰在访问 $d(u) + L$ 个不同节点后首次重访而停止。∎

**引理 3（剥不动的恰是环）**：拓扑剥离终止后，入度仍大于 0 的节点集合恰为全部环上节点；`order` 中恰为全部树枝节点。

**证明**：先证环节点剥不掉。反设环节点 $v$ 某时刻入度归零出队：$v$ 的入边中有一条来自环内前驱 $p$（环长 ≥ 2），该边被扣除要求 $p$ 已出队；而 $p$ 出队又要求 $p$ 的环内前驱先出队……沿环回溯一周，得到「$v$ 出队以 $v$ 自己先出队为前提」，矛盾。故环节点入度恒 $\ge 1$，永不出队。

再证树枝节点必被剥光。树枝节点 $w$ 的入边只可能来自树枝节点（环节点的出边指向环内后继，不出环），故「剥树枝」恰是 Kahn 算法在一片**内向有根森林**上运行：入度为 0 的节点是最外层叶子，剥掉后新暴露的叶子继续入队。对森林规模归纳：只要还有节点，就必有入度为 0 的叶子（否则沿入边回溯会出现环，与树枝无环矛盾），故森林被剥空，全部树枝节点进入 `order`。∎

**引理 4（逆序就绪）**：若树枝节点 $u$ 的后继 `edges[u]` 也是树枝节点，则 $u$ 在 `order` 中的位置严格靠前；逆序遍历时 `edges[u]` 必先于 $u$ 被处理。

**证明**：`edges[u]` 的入度中含 $u$ 贡献的 1。它入队当且仅当入度归零，这要求其全部前驱（含 $u$）都已出队，故 $u$ 出队严格在前、位置严格靠前。∎

**定理**：算法输出的 `ans` 与真实答案一致。

**证明**：环上节点：由引理 3，`indeg > 0` 的判据把它们不重不漏地全部识别，沿环赋值 $L$，与引理 2（$d = 0$）一致。树枝节点：对逆序处理到 $u$ 的时刻归纳——其后继要么在环上（已赋 $L$），要么是位置更靠后的树枝节点（由引理 4 已在之前处理完），故归纳成立：

$$\text{ans}[u] = \text{ans}[\text{edges}[u]] + 1 = \big(d(\text{edges}[u]) + L\big) + 1 = \big(d(u) - 1 + L\big) + 1 = d(u) + L$$

与引理 2 一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$
  - 入度统计一次遍历 $O(n)$；剥叶子阶段每个节点至多入队出队各一次、每条边至多被扣除一次；环走一圈对每个环节点恰好访问一次；逆序递推对每个树枝节点恰好一次。
  - 「`order` 边追加边扫描」的总推进次数等于 `order` 长度，$\le n$。
- **空间复杂度**：$O(n)$
  - `indeg`、`ans`、`order` 三个长度 $n$ 的数组；全程迭代无递归，不占栈空间。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> countVisitedNodes(vector<int>& edges) {
        int n = edges.size();
        vector<int> indeg(n);
        for (int v : edges) indeg[v]++;

        vector<int> order;                    // 一物两用：队列 + 剥离顺序表
        for (int i = 0; i < n; ++i)
            if (indeg[i] == 0) order.push_back(i);
        for (int k = 0; k < (int)order.size(); ++k) {   // 扫到即出队
            int u = order[k];
            if (--indeg[edges[u]] == 0) order.push_back(edges[u]);
        }

        vector<int> ans(n);
        for (int i = 0; i < n; ++i) {
            if (indeg[i] > 0 && ans[i] == 0) {          // 剥不动的 = 环上节点
                int len = 0, u = i;
                do { ++len; u = edges[u]; } while (u != i);   // 走一圈数环长
                u = i;
                do { ans[u] = len; u = edges[u]; } while (u != i);
            }
        }
        for (int k = (int)order.size() - 1; k >= 0; --k)      // 剥离逆序 = 从环向外
            ans[order[k]] = ans[edges[order[k]]] + 1;         // 后继必已就绪
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countVisitedNodes(self, edges: List[int]) -> List[int]:
        n = len(edges)
        indeg = [0] * n
        for v in edges:
            indeg[v] += 1

        order = [i for i in range(n) if indeg[i] == 0]
        for u in order:                      # 列表边遍历边追加，天然队列
            v = edges[u]
            indeg[v] -= 1
            if indeg[v] == 0:
                order.append(v)

        ans = [0] * n
        for i in range(n):                   # 入度仍 > 0 的节点都在环上
            if indeg[i] > 0 and ans[i] == 0:
                u, cycle = i, []
                while True:
                    cycle.append(u)
                    u = edges[u]
                    if u == i:
                        break
                for v in cycle:              # 整环一起定值
                    ans[v] = len(cycle)

        for u in reversed(order):            # 剥离逆序 = 从环向外
            ans[u] = ans[edges[u]] + 1       # 后继必已就绪
        return ans
```

> 💡 两版逻辑一致，全程迭代、无递归、不建邻接表。Python 版已与「每起点独立模拟」的暴力做过 3000 组随机对拍（$n \le 8$），并覆盖官方两示例、森林补充示例与 $n = 10^5$ 的整图大环 / 长链挂环烟测，全部一致。

## 8. 边界情况与易错点

1. **整图一个大环**（示例 2）：`order` 为空，一步没剥，直接全图定值 $L = n$；逆序循环自然不执行，无需任何特判。
2. **不能朴素记忆化 DFS**：`ans[u] = ans[edges[u]] + 1` 沿出边递归，环上节点循环依赖、没有递归出口，直接无限递归；必须**先破环**（整环定值）再递推。另外 $n = 10^5$ 的链形树枝会把递归深度顶到爆栈（C++ 默认栈约 1 MB、Python 默认上限 1000 层），两版参考代码均为迭代写法，天然免疫。
3. **逆序别写成正序**：正序扫 `order` 时靠外节点的后继答案尚未算好，一步错步步错；必须 `reversed`（C++ 下标倒扫）。
4. **环节点判据是「入度」不是「答案为 0」**：`indeg > 0` 是结构判据（引理 3）；`ans == 0` 只能当「此环尚未定值」的哨兵用——环长 $\ge 2$、树枝答案 $\ge 3$，合法答案不为 0，所以哨兵安全。
5. **`ans` ≠ 分量大小**：绕环一圈即止，同分量其他树枝不会被访问（§3.2 ⚠️），这是本题最常见的读题陷阱。
6. **多分量森林天然兼容**：补充示例这类森林无需按分量分组——初始入度为 0 的节点**一次性全部**入队，各分量互不干扰；环检测与整环定值也对每个环独立进行。
7. **每条入边只扣一次**：`indeg[edges[u]]--` 只在 $u$ 出队时执行，而每个 $u$ 恰好出队一次，不存在重复扣减导致环被误剥的情况。

- 若改问「从 $i$ 出发到**首次重访**共走了多少步」？——答案恰也是 $d(i) + L$：第 $d + L$ 步踩回环入口，与不同节点数相等，这正说明「路径 = 入环路径 + 整环，一步不多走」。
- 若每个点出度可以为 0（行走会中途「停死」）？——图不再是基环森林，递推需按「停在出度 0 / 进入环」两类出口分别处理，本题框架是它的特例；这也是把基环题推广到一般「函数图 + 空值」形态时最先崩塌的地方。
