# LeetCode 无限数组的最短子数组 题解

## 1. 题目概述

- **标题 / 题号**：无限数组的最短子数组（#2875，medium）
- **链接**：https://leetcode.cn/problems/minimum-size-subarray-in-infinite-array/
- **来源**：LeetCode 第 365 场周赛 Q3
- **难度**：中等
- **标签**：数组、数学、前缀和、滑动窗口

**题意**：给定下标从 0 开始的数组 `nums` 和整数 `target`。数组 `infinite_nums` 由 `nums` 无限次拼接自身得到（位置 $i$ 的元素恒为 $nums[i \bmod n]$）。请在 `infinite_nums` 中找出**元素和恰好等于** `target` 的**最短**子数组，返回其长度；不存在则返回 `-1`。

**约束**：

- $1 \le n = nums.length \le 10^5$
- $1 \le nums[i] \le 10^5$（**元素全为正**）
- $1 \le target \le 10^9$

> 💡 本场 Q1/Q2 是前后缀分解的姊妹签到题，Q3 开始上「无限」的包装，是分场的分水岭。破题钥匙就藏在约束里：**元素全正**（窗口和随端点单调，滑动窗口合法）+ **数组按 $n$ 周期重复**（无限可压缩为有限）。本题另有[每日题解 2875](../../solution/2801-2900/2875_无限数组的最短子数组.md)：与本文互为印证；本文侧重赛场视角——从「暴力滑窗被 $10^9$ 卡死」出发推出周期分解的完整思路链，并用「整份剥离」给出比常规「尾段 + 头段」更干净的严谨证明。

## 2. 示例

```text
输入：nums = [1,2,3], target = 5
输出：2
解释：infinite_nums = [1,2,3,1,2,3,1,2,...]，子数组 [2,3] 的元素和等于 5，长度 2 最短。
```


```text
输出：8
解释：17 = 2×6 + 5，即两个「连续 3 格」（和各为 6）接上环弧 [2,3]（和为 5），
长度 3 + 3 + 2 = 8。
```

## 3. 解题思路

### 3.1 暴力思路：在无限数组上硬扫滑动窗口

元素全正 ⇒ 窗口和随左右端点严格单调，「和恰好等于 $target$」看起来就是一个标准的滑窗问题：右端点不断右移，和超过 $target$ 就收缩左端点，命中就记一个候选。

> ⚠️ 问题出在「右端点要走多远」：$nums$ 全为 1、$n = 10^5$、$target = 10^9$ 时，凑出和 $10^9$ 的窗口要吞下 $10^9$ 个元素——右端点得前进 $10^9$ 步，**超时三个数量级**。「无限」的数组没法硬扫。

不过这个失败的暴力交代了两条后续全部依赖的性质：

1. **正数性**：窗口和关于端点严格单调——滑动窗口正确性的命根子；
2. **周期性**：位置 $i$ 的元素恒为 $nums[i \bmod n]$——把无限规模压缩回有限的钥匙。

### 3.2 核心观察：结构分解——任意子数组 = 整份底座 + 一段环弧

记 $S = \sum nums[i]$（一份的总和）。对 $target$ 做带余除法：

$$target = k \cdot S + r,\qquad k = \lfloor target / S \rfloor,\ r = target \bmod S$$

直观上，把一个和为 $target$ 的子数组按份切开：它由「某份的尾段 + 若干完整份 + 某份的头段」拼成，尾段与头段首尾相接，恰好是环 `nums` 上的**一段弧**；而「完整份」不必与份边界对齐——任意连续 $n$ 个元素都是 `nums` 的一个旋转，和恒为 $S$（§5 引理 1）。于是（证明见 §5）：

- **任意和为 $target$ 的子数组，长度都满足 $L \ge k \cdot n + \text{minlen}(r)$**，其中 $\text{minlen}(r)$ 是环上和恰为 $r$ 的最短弧长；
- **这个下界总能取到**：$k$ 个「连续 $n$ 格」打底、再接一段和为 $r$ 的环弧，拼起来正是一个连续子数组；
- $r = 0$ 时环弧为空，答案就是 $k \cdot n$。

$$\text{ans} = k \cdot n + \text{minlen}(r)\qquad (r > 0;\ \ r = 0 \text{ 时 } \text{ans} = k \cdot n)$$

![结构分解](images/wc365_q3_decompose.svg)

以补充示例走一遍：$nums = [1,2,3]$、$target = 17$ → $S = 6$，$k = 2$，$r = 5$。子数组 $[2,3,1,2,3,1,2,3]$ = 环弧 $[2,3]$（和 5）+ 两个连续 3 格（和各 6），总和 $5 + 6 + 6 = 17$，长度 $2 + 3 + 3 = 8 = k \cdot n + \text{环弧长}$。

### 3.3 算法流程：环弧 → 翻倍数组 → 滑动窗口

剩下唯一的子问题：**怎么找和恰为 $r$ 的最短环弧？** 三步化归：

1. **弧长必 $< n$**：和为 $r < S$ 的弧若长度 $\ge n$，则它包含连续 $n$ 个元素（一整份，和 $S$），总和 $\ge S > r$，矛盾；
2. **环弧 ↔ 翻倍数组窗口一一对应**：把 `nums` 拼成翻倍数组 $B = nums + nums$（长 $2n$）。长度 $< n$ 的环弧，不跨边界的是 $B$ 前半的普通子数组；跨边界的（尾段 + 头段）恰好横跨 $B$ 正中间的份边界——都装得下，且 $B$ 中任意窗口也都能折回环上；
3. **滑窗求最短**：元素全正 ⇒ 在 $B$ 上跑标准滑动窗口，$s > r$ 左缩、$s = r$ 记录最短，一趟 $O(n)$。

![算法流程](images/wc365_q3_algorithm_flow.svg)

**完整步骤**：

1. 计算 $n$ 与 $S = \sum nums[i]$（$S \le 10^{10}$，64 位整数）；
2. 带余除法 $k = \lfloor target / S \rfloor$，$r = target \bmod S$；
3. 若 $r = 0$，直接返回 $k \cdot n$；
4. 在（虚拟的）翻倍数组上滑窗：`right` 从 0 扫到 $2n - 1$（环形索引 `right % n` 取元素，免真开数组），维护窗口和 $s$；$s > r$ 就左缩，$s = r$ 记录最短窗口长 $\text{len}$；
5. 找到则返回 $k \cdot n + \text{len}$，否则返回 $-1$。

### 3.4 示例演算

仍用 $nums = [1,2,3]$、$target = 17$：$S = 6$，$k = 2$，$r = 5$，翻倍数组 $B = [1,2,3,1,2,3]$，滑窗找和恰为 5 的最短窗口：

| right | 入窗 | 收缩 | 窗口 | $s$ | 命中 |
|---|---|---|---|---|---|
| 0 | 1 | — | $[1]$ | 1 | |
| 1 | 2 | — | $[1,2]$ | 3 | |
| 2 | 3 | 弹 1 | $[2,3]$ | **5** | ✓ len 2 |
| 3 | 1 | 弹 2 | $[3,1]$ | 4 | |
| 4 | 2 | 弹 3 | $[1,2]$ | 3 | |
| 5 | 3 | 弹 1 | $[2,3]$ | **5** | ✓ len 2 |

![示例演算](images/wc365_q3_example_walkthrough.svg)

最短窗口长 2，答案 $= k \cdot n + 2 = 2 \times 3 + 2 = 8$ ✓。注意 $right = 3$ 时出现窗口 $[3,1]$——它**横跨两份的边界**，正对应示例 2 里最优解 $[3,1]$ 的形态；若只在一份（长度 $n$ 的窗口）里找，这类解会被整批漏掉。用其余示例复核：

- 示例 1：$[1,2,3]$，$target = 5$ → $k = 0$，$r = 5$，$B$ 中窗口 $[2,3]$ 长 2 → 答案 $0 + 2 = 2$ ✓
- 示例 2：$[1,1,1,2,3]$，$target = 4$ → $k = 0$，$r = 4$，最优窗口 $[3,1]$ 跨正中间边界，长 2 → 答案 2 ✓
- 示例 3：$[2,4,6,8]$，$target = 3$ → $k = 0$，$r = 3 \ge \min(nums) = 2$，快速短路不生效；但一切弧和都是偶数，扫完 $2n = 8$ 格无命中 → $-1$ ✓

## 4. 算法细节

1. **64 位整数（C++ 最大的坑）**：$S \le 10^5 \times 10^5 = 10^{10}$，超出 `int` 上限（约 $2.1 \times 10^9$），$S$、$k$、$r$、$s$、`k * n + ans` 全部用 `long long` 承载。**最终答案不会溢出**：每个元素 $\ge 1$ ⇒ $S \ge n$ ⇒ $k \cdot n \le target \le 10^9$，转 `int` 返回是安全的（极限用例 `nums = [1]`、`target = 10^9` 时恰好压着 `int` 上限之下）。
2. **$r = 0$ 提前返回**：环弧为空，$k$ 份「连续 $n$ 格」首尾相接即最优，直接返回 $k \cdot n$。若不提前返回而继续滑窗：空窗时 $s = 0 = r$ 会记出「长度 0」，最终仍得 $k \cdot n$——**碰巧也对，但语义脏**，建议显式返回。
3. **环形索引代替显式翻倍**：`nums[right % n]` 取元素，不开 $2n$ 数组，空间 $O(1)$；`left` 同理（`left` 最多前进到 `right + 1`，取模访问永远合法）。
4. **收缩循环的终止性**：`while (s > r)` 里 $r \ge 1$、元素全正——弹到窗口空时 $s = 0 < r$ 必然停住，不会越界弹出不存在的元素。
5. **`while` 不能写成 `if`**：入窗一个元素可能需要连弹多个（如 $nums = [5,1,1]$、$r = 2$，`right = 3` 入 5 后要连弹 3 个元素），收缩次数不定。
6. **对偶实现——前缀和 + 哈希表**：「$B$ 中和恰为 $r$ 的最短窗口」也可用 $\text{pre}[j] - \text{pre}[i] = r$ 求解：哈希表存每个前缀和**最后出现**的下标，对每个 $j$ 查 $\text{pre}[j] - r$ 的最新位置即得最短窗口。它不依赖元素符号（含零、负数也能找「和恰好」），代价是 $O(n)$ 空间；滑窗版依赖全正带来的单调性，换来 $O(1)$ 空间。

## 5. 正确性证明

记 $A$ 为无限数组，$A_i = nums[i \bmod n]$；子数组 $A[l..r]$ 指闭区间内的连续段。不加声明时约定 $target = kS + r$，$0 \le r < S$。

**引理 1（整份不变量）**：$A$ 中任意连续 $n$ 个元素之和恰为 $S$。

**证明**：$A[l..l+n-1]$ 依次为 $nums[(l+j) \bmod n]$（$j = 0, \dots, n-1$），是 $nums$ 的一个旋转，元素多重集相同，和不变。∎

**引理 2（下界）**：设 $T$ 是任意和为 $target$ 的子数组，长度 $L$。则 $L$ 从左端起按 $n$ 分块恰为 $kn + s$，且 $r > 0$ 时 $s \ge \text{minlen}(r)$（$s$ 即某条和为 $r$ 的环弧之长）；$r = 0$ 时 $s = 0$。特别地，$L \ge kn + \text{minlen}(r)$（$r > 0$）或 $L = kn$（$r = 0$）。

**证明**：写 $L = jn + s$，$0 \le s < n$。从左端起剥去 $j$ 个长度 $n$ 的块，每块和为 $S$（引理 1），余下长 $s$ 的连续段 $R$，$\text{sum}(R) = target - jS = (k - j)S + r$。

- 若 $s = 0$：$\text{sum}(R) = 0 = (k-j)S + r$。$r \in (0, S)$ 时 $(k-j)S = -r \in (-S, 0)$ 无整数解；$r = 0$ 时 $j = k$。故 $s = 0$ 仅在 $r = 0$ 时出现，且此时 $L = jn = kn$。
- 若 $s \ge 1$：$R$ 是长 $\le n-1$ 的连续段，对应环上一条长 $s$ 的弧，覆盖 $s$ 个**互不相同**的环位置，至少缺 1 个位置。全正元素 ⇒ $0 < \text{sum}(R) < S$（缺位之和 $\ge$ 最小元素 $> 0$）。代入 $(k-j)S + r \in (0, S)$ 且 $r \in [0, S)$：只有 $k - j = 0$，即 $j = k$；于是 $\text{sum}(R) = r$，$R$ 是一条和为 $r$ 的弧，$s \ge \text{minlen}(r)$（$r > 0$；$r = 0$ 时与 $s \ge 1$、$\text{sum}(R) > 0$ 矛盾，不出现）。∎

**引理 3（可达性）**：$r = 0$ 时，存在长 $kn$、和为 $target$ 的子数组；$r > 0$ 时，若存在长 $s$、和为 $r$ 的环弧，则存在长 $kn + s$、和为 $target$ 的子数组。

**证明**：$r = 0$：任取起点，连续 $kn$ 个元素是 $k$ 个 $n$-块，和 $kS = target$。$r > 0$：设弧自环位置 $p$ 起、长 $s$。取 $A$ 中起点 $x \equiv p \pmod n$（如 $x = p$，落在第 0 份内）。段 $[x, x + kn + s - 1]$ 的前 $kn$ 个元素是 $k$ 个 $n$-块（和 $kS$，引理 1），余下 $s$ 个元素自环位置 $(x + kn) \bmod n = p$ 起延续 $s$ 格，恰为那条弧（和 $r$）。总和 $kS + r = target$。∎

**引理 4（环弧 ↔ 翻倍数组窗口）**：和为 $r$ 的环弧与 $B$ 中和为 $r$ 的窗口一一对应（且长度都 $\le n - 1$），故 $\text{minlen}(r)$ 等于 $B$ 中和为 $r$ 的最短窗口长（若存在）。

**证明**：和为 $r < S$ 的弧长 $\le n - 1$：长 $\ge n$ 则含 $n$ 个连续位置、和 $\ge S > r$，矛盾。（→）弧起点环位置 $p \in [0, n-1]$、长 $\ell \le n-1$，对应 $B$ 中窗口 $[p, p + \ell - 1]$，右端 $\le (n-1) + (n-1) = 2n - 2 < 2n$，落在 $B$ 内，元素逐一相同。（←）$B$ 的任意窗口也是周期数组的连续段（$B_i = nums[i \bmod n]$），同理其长 $\ge n$ 时和 $\ge S > r$，故和为 $r$ 的窗口长 $\le n - 1$，按起点环位置折回即得弧。两个方向的映射都保持元素值，双射成立。∎

**引理 5（最长窗口不变式）**：收缩循环结束后，$[left, right]$ 是以 $right$ 结尾、和 $\le r$ 的最长窗口（窗口空时 $s = 0 \le r$）。

**证明**：对 $right$ 归纳。$right = 0$ 之前窗口为空（$left = 0$、$s = 0 \le r$），成立。设处理完 $right - 1$ 后 $[left, right - 1]$ 是以 $right-1$ 结尾、和 $\le r$ 的最长窗口。对任意 $left' < left$：$[left', right-1]$ 严格包含 $[left, right-1]$，全正元素 ⇒ $\text{sum}(left', right{-}1) > r$；入窗 $nums[right]$ 后只会更大，仍 $> r$——故以 $right$ 结尾的合法左端点只能 $\ge left$。从 $left$ 起逐格弹出：每弹一个 $s$ 严格减少，空窗 $s = 0 \le r$ 必停，停在**第一个**使和 $\le r$ 的 `left`，即以 $right$ 结尾、和 $\le r$ 的最长窗口。∎

**推论**：若存在以 $right$ 结尾、和恰为 $r$ 的窗口 $[i', right]$，则该轮必以 $s = r$ 命中且 $left = i'$。由引理 5，$[left, right]$ 是和 $\le r$ 的最长窗口，故 $left \le i'$；若 $left < i'$，则 $s = \text{sum}[left..right] > \text{sum}[i'..right] = r$（全正、窗口更长），与 $s \le r$ 矛盾。∎

**定理**：算法返回 `infinite_nums` 中和为 `target` 的最短子数组长度；不存在时返回 `-1`。

**证明**：分情况。

（$r = 0$）由引理 2，一切可行解长恰为 $kn$；由引理 3，$kn$ 可行。故答案 $= kn$，即算法的提前返回值。

（$r > 0$）**下界**：由引理 2，一切可行解 $L \ge kn + \text{minlen}(r)$（若 $\text{minlen}(r)$ 不存在，则无 $s \ge 1$ 的解、$s = 0$ 又不出现，无可行解）。**可达**：由引理 3，$kn + \text{minlen}(r)$ 可行。故答案 $= kn + \text{minlen}(r)$。**算法求出它**：由引理 4，$\text{minlen}(r)$ 等于 $B$ 中和为 $r$ 的最短窗口长；滑窗枚举右端点 $0 \sim 2n - 1$，由推论，每个右端点的唯一候选（若存在）必被 `s == r` 捕获，故记录值恰为 $B$ 中和为 $r$ 的最短窗口长（不存在时 `ans` 保持 $\infty$，返回 $-1$）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。带余除法 $O(1)$；滑窗中 `right` 扫 $2n$ 格，`left` 只进不退、全程至多前进 $2n$ 格，均摊每格 $O(1)$。对比暴力：全 1 数组、$target = 10^9$ 时右端点要走 $10^9$ 步，取模分解后无论 $target$ 多大都只扫 $2n \le 2 \times 10^5$ 格——**把「无限」压回「一个周期」**正是本题的价值所在。
- **空间复杂度**：$O(1)$。环形索引 `i % n` 代替显式翻倍数组，只维护 `left`、`s`、`ans` 等常数个变量。前缀和 + 哈希版为 $O(n)$ 空间。

## 7. 参考代码

### C++

```cpp
// 取模分解 + 翻倍数组滑动窗口：O(n) 时间 / O(1) 空间
class Solution {
public:
    int minSizeSubarray(vector<int>& nums, int target) {
        int n = nums.size();
        long long total = accumulate(nums.begin(), nums.end(), 0LL); // S ≤ 1e10，64 位
        long long k = target / total, r = target % total;
        if (r == 0) return (int)(k * n);          // 整份底座恰好凑满，环弧为空

        long long ans = LLONG_MAX, left = 0, s = 0;
        for (int right = 0; right < 2 * n; right++) { // 环形索引扫“翻倍数组”
            s += nums[right % n];
            while (s > r) {                        // 全正数：弹到空窗 s=0<r 必停
                s -= nums[left % n];
                left++;
            }
            if (s == r)                            // 以 right 结尾的唯一候选
                ans = min(ans, (long long)right - left + 1);
        }
        return ans == LLONG_MAX ? -1 : (int)(k * n + ans);
    }
};
```

```cpp
// 对偶版：前缀和 + 哈希表存“最后出现下标”，不依赖元素全正，O(n) 空间
class Solution {
public:
    int minSizeSubarray(vector<int>& nums, int target) {
        int n = nums.size();
        long long total = accumulate(nums.begin(), nums.end(), 0LL);
        long long k = target / total, r = target % total;
        if (r == 0) return (int)(k * n);

        unordered_map<long long, int> last;        // 前缀和 → 最后出现的下标
        last[0] = -1;
        long long ans = LLONG_MAX, s = 0;
        for (int j = 0; j < 2 * n; j++) {
            s += nums[j % n];
            auto it = last.find(s - r);
            if (it != last.end()) ans = min(ans, (long long)j - it->second);
            last[s] = j;                           // 覆盖为最新下标 → 窗口最短
        }
        return ans == LLONG_MAX ? -1 : (int)(k * n + ans);
    }
};
```

```python
class Solution:

        if r == 0:                              # 整份底座恰好凑满，环弧为空
            return k * n

        ans, left, s = float('inf'), 0, 0
        for right in range(2 * n):              # 环形索引扫“翻倍数组”
            s += nums[right % n]
            while s > r:                        # 全正数：弹到空窗 s=0<r 必停
                s -= nums[left % n]
                left += 1
            if s == r:                          # 以 right 结尾的唯一候选
                ans = min(ans, right - left + 1)
        return -1 if ans == float('inf') else k * n + ans
```

```python
class Solution:
    def minSizeSubarray(self, nums: List[int], target: int) -> int:
        n = len(nums)
        total = sum(nums)
        k, r = divmod(target, total)
        if r == 0:
            return k * n

        last = {0: -1}                          # 前缀和 → 最后出现的下标
        ans, s = float('inf'), 0
        for j in range(2 * n):
            s += nums[j % n]
            if s - r in last:
                ans = min(ans, j - last[s - r])
            last[s] = j                         # 覆盖为最新下标 → 窗口最短
        return -1 if ans == float('inf') else k * n + ans
```

> 💡 四份代码均与「枚举环上起点 × 长度」的暴力做过 3000 组随机对拍（$n \le 6$、$nums[i] \le 4$、$target \le 60$），并覆盖官方三示例、$k > 0$ 补充示例与 `nums = [1]`、`target = 10^9` 的 `int` 边界用例，全部一致。

## 8. 边界情况与易错点

1. **$S$ 溢出 `int`（C++ 最大的坑）**：$S \le 10^{10}$，`accumulate` 的初值必须写 `0LL`（写 `0` 会按 `int` 累加直接溢出）；$k$、$r$、$s$、`k * n + ans` 同样走 64 位。
2. **只在一份里找会漏解**：示例 2 的最优窗口 $[3,1]$ 横跨两份边界——必须扫**翻倍**数组（右端点扫满 $2n$ 格），只在长度 $n$ 的范围内滑窗会整批漏掉「尾段 + 头段」形态的解。
3. **$r = 0$ 忘记提前返回**：继续滑窗会靠「空窗 $s = 0 = r$ 记出长度 0」碰巧得到 $k \cdot n$，结果对但语义脏；显式返回更稳、更快。
4. **`while` 写成 `if`**：入窗一个元素可能需要连弹多个（$nums = [5,1,1]$、$r = 2$ 时 `right = 3` 入 5 后连弹 3 个），收缩次数不固定。
5. **$k = 0$ 的退化**（$target < S$）：整份底座消失，问题退化为「环上找和恰为 $target$ 的最短弧」，示例 1、2 都是；算法无需任何特判，天然覆盖。
6. **`k * n` 的 `int` 边界**：$nums$ 全 1、$target = 10^9$ 时答案恰为 $10^9$，仍在 `int` 内（上限约 $2.1 \times 10^9$），但**中间乘法必须用 64 位**完成后再转 `int`。
7. **无解的判定**：扫完 $2n$ 格无命中即返回 $-1$，无需其他特判（$r < \min(nums)$ 时必无解，但通用扫描已覆盖，不必专门短路）。
8. **哈希版的两个细节**：`last` 必须存**最新**下标（同前缀和重复出现时窗口才最短）；初值 `{0: -1}` 别漏，否则以 0 开头的窗口（前缀窗口）会丢。
9. **赛场策略**：看到「无限 + 周期」先想取模分解，看到「全正 + 和恰好」先想滑动窗口——两个信号同时出现，本题 $O(n)$ 的骨架 5 分钟内即可成型；卡住的选手多数是死在「想直接在无限数组上扫」。
