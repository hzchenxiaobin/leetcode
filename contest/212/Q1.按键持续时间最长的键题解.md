# LeetCode 按键持续时间最长的键 题解

## 1. 题目概述

- **标题 / 题号**：按键持续时间最长的键（#1629，easy）
- **链接**：https://leetcode.cn/problems/slowest-key/
- **来源**：LeetCode 第 212 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串

**题意**：测试人员依次按下 $n$ 个键。给定升序数组 `releaseTimes`（`releaseTimes[i]` 为第 $i$ 个键**松开**的时刻）与字符串 `keysPressed`（第 $i$ 个被按下的键）。第 0 个键在时刻 0 按下，之后每个键**恰在前一个键松开时**被按下，因此第 $i$ 次按键的持续时间为 `releaseTimes[i] - releaseTimes[i-1]`（第 0 次为 `releaseTimes[0]`）。求**单次**持续时间最长的键；若有多个键并列最长，返回**按字母顺序排列最大**的那个键。

**约束**：

- `releaseTimes.length == keysPressed.length == n`
- $2 \le n \le 1000$
- $1 \le \text{releaseTimes}[i] \le 10^9$
- `releaseTimes` 严格升序：`releaseTimes[i] < releaseTimes[i+1]`
- `keysPressed` 仅由小写英文字母组成

> 💡 签到题的题眼有两个：**「差分」**——按键区间首尾相接，单次持续时间就是相邻松开时刻之差；**「并列取字母序最大」**——这是复合最值，也是本题唯一的 WA 陷阱。抓住前者写出主循环，抓住后者补全更新条件，即可一遍过。

## 2. 示例

**示例 1**

```text
输入：releaseTimes = [9,29,49,50], keysPressed = "cbcd"
输出：'c'
解释：四次按键的持续时间依次为 9、29−9=20、49−29=20、50−49=1。
      'b' 与 'c'（第二次按下）并列最长（20），'c' 字母序更大，返回 'c'。
```

**示例 2**

```text
输入：releaseTimes = [12,23,36,46,62], keysPressed = "spuda"
输出：'a'
解释：五次按键的持续时间依次为 12、11、13、10、16，最长为 16，对应 'a'。
```

**示例 3**

```text
输入：releaseTimes = [5,25,45], keysPressed = "aba"
输出：'b'
解释：持续时间依次为 5、25−5=20、45−25=20。'a'（第 0 键）与 'b' 中，
      单次最长 20 由 'b'（i=1）与 'a'（i=2）并列，'b' 字母序更大，返回 'b'。
      同时可见同一个键 'a' 被按下两次、时长不同（5 与 20）——比的是「单次」而非「累计」。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的落笔方式：先一趟算出 `durations` 数组，再按「时长降序、并列字母降序」排序取首元素的键，$O(n \log n)$ 时间、$O(n)$ 空间；或者先求 $\max d$，再扫一遍在并列键中挑字母最大者，两趟 $O(n)$。对 $n \le 1000$ 都稳过，但都没抓住两个结构：

1. `durations` 是**差分**，可以边算边用，无需存表；
2. 只需要**一个最值**，无需任何整体顺序——排序是纯粹的浪费。

签到题也值得走「最短路径」：一趟扫描、$O(1)$ 空间。

### 3.2 核心观察：差分 + 复合最值

![核心观察：差分时间轴与并列判定](images/wc212_q1_timeline_concept.svg)

**观察一（差分）**：题面保证「每个键恰在前一个键松开时被按下」，即 $n$ 个按键区间在时间轴上**首尾相接**。于是第 $i$ 个键的持续时间就是**相邻松开时刻之差**：

$$
\text{duration}[i] =
\begin{cases}
\text{releaseTimes}[0], & i = 0 \\
\text{releaseTimes}[i] - \text{releaseTimes}[i-1], & i \ge 1
\end{cases}
$$

严格升序还保证每个 $\text{duration}[i] \ge 1$，不存在零或负时长，无需任何特判。

**观察二（复合最值）**：所求即 $n$ 个二元组 $(\text{duration}[i],\ \text{keysPressed}[i])$ 中「**时长最大、并列时字母最大**」者——等价于对这个二元组按**字典序**取最大元。因此一趟扫描中只需维护 $(\text{bestDur}, \text{bestKey})$，遇到更优的二元组就覆盖。

### 3.3 算法流程

![算法流程：差分求 d，复合比较维护最值](images/wc212_q1_scan_flow.svg)

```text
1. bestDur ← releaseTimes[0]，bestKey ← keysPressed[0]     # 第 0 键直接作初值
2. for i = 1 .. n−1:
     d ← releaseTimes[i] − releaseTimes[i−1]                # 差分
     若 d > bestDur 或 (d == bestDur 且 keysPressed[i] > bestKey):
         bestDur ← d，bestKey ← keysPressed[i]              # 更长覆盖；并列换键
3. 返回 bestKey
```

> ⚠️ 更新条件是一个「或」连接的**复合比较**，恰好是二元组字典序比较的展开。只写前一半 `d > bestDur` 会在并列时漏换键（示例 1 错返 `'b'`）；把整个条件简化成 `d >= bestDur` 则会错拿「最后按的键」（见 §8）。

### 3.4 示例演算

![示例 1 一趟扫描走查](images/wc212_q1_walkthrough.svg)

以示例 1（`releaseTimes = [9,29,49,50]`，`keysPressed = "cbcd"`）为例，初值 `best = (9, 'c')`：

- `i = 1`（`'b'`）：$d = 29 - 9 = 20 > 9$，更长 → 覆盖为 `(20, 'b')`；
- `i = 2`（`'c'`）：$d = 49 - 29 = 20$，与 `bestDur` 并列且 `'c' > 'b'` → 仅换键为 `(20, 'c')`；
- `i = 3`（`'d'`）：$d = 50 - 49 = 1 < 20$ → 跳过。

扫描结束返回 `'c'` ✓。

再看示例 2（`releaseTimes = [12,23,36,46,62]`，`keysPressed = "spuda"`），初值 `best = (12, 's')`：

| i | key | $d$ | 动作 | best |
|---|-----|-----|------|------|
| 0 | `s` | 12 | 初值 | `(12, 's')` |
| 1 | `p` | 11 | $11 < 12$，跳过 | `(12, 's')` |
| 2 | `u` | 13 | $13 > 12$，覆盖 | `(13, 'u')` |
| 3 | `d` | 10 | $10 < 13$，跳过 | `(13, 'u')` |
| 4 | `a` | 16 | $16 > 13$，覆盖 | `(16, 'a')` |

返回 `'a'` ✓。示例 3 则演示了**反向**的并列情形：`i = 2` 时 `'a'` 与 `'b'` 并列 20，但 `'a' < 'b'`，不换键，最终返回 `'b'`——并列分支的两个方向都被覆盖。

## 4. 算法细节

1. **初值取第 0 键**：`releaseTimes[0]` 是真实数据的一部分，必须纳入比较；直接拿它作初值、循环从 $i = 1$ 开始，逻辑最干净，避免哨兵特判。
2. **更新条件的两部分**：`d > bestDur`（更长覆盖）与 `d == bestDur && keysPressed[i] > bestKey`（并列换键）。并列分支里 `bestDur = d` 是无害的自赋值（两值相等），统一写两句赋值可省去内层 `if/else`。
3. **差分无需存表**：`d` 是循环内的临时变量，用完即弃；先算整个 `durations` 数组再扫描是多余的一趟与 $O(n)$ 空间。
4. **变体：26 桶收集 + 从 z 向 a 决策**。一趟扫描维护 `best[26]`（每个键的**单次**最长时长），结束后取全局最大 `top`，从 `'z'` 向 `'a'` 扫描返回第一个 `best[c] == top` 的键。把「并列取字母大」翻译成「按字母从大到小枚举」，同样 $O(n + 26)$，适合喜欢先收集再决策的写法；注意桶存的是单次最大而非累计和。
5. **无需排序 / 哈希 / 前缀和**：求最值不需要整体顺序，也不要被「升序数组」诱导去二分——`releaseTimes` 的有序性只被用来保证差分为正。
6. **数据范围**：$d \le 10^9 < 2^{31} - 1$，`int` 即可，无需 `long long`。

## 5. 正确性证明

对二元组 $p_1 = (d_1, k_1)$、$p_2 = (d_2, k_2)$，定义 $p_1 \prec p_2$ 当且仅当 $d_1 < d_2$，或 $d_1 = d_2$ 且 $k_1 < k_2$。易验证 $\prec$ 是全序（先比时长、再比字母的「双大者优先」序）。记 $P_i = (\text{duration}[i],\ \text{keysPressed}[i])$。

> 题面直接给出持续时间的计算方式（「每个键恰在前一键松开时按下」⇒ 区间首尾相接 ⇒ 差分公式），故 $\text{duration}[i]$ 的定义无需再证。

**引理 1（答案刻画）**：所求答案为 $k^*$，其中 $(d^*, k^*)$ 是集合 $\{P_i : 0 \le i < n\}$ 在 $\prec$ 下的最大元。

**证明**：「单次持续时间最长」即 $d$ 分量取到全集最大；在这些并列的元素中「按字母顺序排列最大」即 $k$ 分量最大——两步合起来恰是 $\prec$ 序下的最大元（先比 $d$，$d$ 相同再比 $k$）。全序下最大元作为**取值**唯一，故 $k^*$ 良定义。∎

**引理 2（更新条件即序比较）**：$P_i \succ (\text{bestDur}, \text{bestKey})$ 当且仅当 $d_i > \text{bestDur}$，或 $d_i = \text{bestDur}$ 且 $\text{keysPressed}[i] > \text{bestKey}$——正是代码中的复合条件。

**证明**：对 $\prec$ 的定义按「时长严格更大 / 时长相等再比字母」两种情形展开即得。∎

**定理**：算法返回题目所求的键。

**证明**：归纳证明循环不变式：**处理完下标 $i$ 后，$(\text{bestDur}, \text{bestKey})$ 等于前缀 $\{P_0, \dots, P_i\}$ 在 $\prec$ 下的最大元。**

- $i = 0$：前缀只含 $P_0$，初值 $(\text{releaseTimes}[0], \text{keysPressed}[0]) = P_0$ 即最大元。
- 设处理完 $i-1$ 时不变式成立。处理 $i$ 时新前缀的最大元 $= \max\{\text{旧最大元},\ P_i\}$：若 $P_i \succ$ 旧最大元，由引理 2 复合条件成立，程序覆盖为 $P_i$，恰为新最大元；否则条件不成立，$(\text{bestDur}, \text{bestKey})$ 保持不变，而旧最大元 $\succeq P_i$，仍是新最大元。

循环终止时 $(\text{bestDur}, \text{bestKey})$ 为全集 $\{P_0, \dots, P_{n-1}\}$ 的最大元，由引理 1 返回的 `bestKey` 即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个下标一次减法 + 至多两次比较与两次赋值，均为常数开销。
- **空间复杂度**：$O(1)$。仅 `bestDur`、`bestKey`、`d` 三个标量（26 桶变体为 $O(26)$，仍是常数）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    char slowestKey(vector<int>& releaseTimes, string keysPressed) {
        int n = releaseTimes.size();
        int bestDur = releaseTimes[0];
        char bestKey = keysPressed[0];
        for (int i = 1; i < n; ++i) {
            int d = releaseTimes[i] - releaseTimes[i - 1];
            if (d > bestDur || (d == bestDur && keysPressed[i] > bestKey)) {
                bestDur = d;
                bestKey = keysPressed[i];
            }
        }
        return bestKey;
    }
};
```

### Python

```python
class Solution:
    def slowestKey(self, releaseTimes: List[int], keysPressed: str) -> str:
        best_dur, best_key = releaseTimes[0], keysPressed[0]
        for i in range(1, len(releaseTimes)):
            d = releaseTimes[i] - releaseTimes[i - 1]
            if d > best_dur or (d == best_dur and keysPressed[i] > best_key):
                best_dur, best_key = d, keysPressed[i]
        return best_key
```

26 桶变体（先收集每键的单次最长时长，再从 `'z'` 向 `'a'` 决策，天然满足并列取字母大）：

```python
class Solution:
    def slowestKey(self, releaseTimes: List[int], keysPressed: str) -> str:
        best = [0] * 26
        prev = 0
        for t, k in zip(releaseTimes, keysPressed):
            best[ord(k) - ord('a')] = max(best[ord(k) - ord('a')], t - prev)
            prev = t
        top = max(best)
        for c in range(25, -1, -1):
            if best[c] == top:
                return chr(ord('a') + c)
```

严格升序保证每个时长 $\ge 1 > 0$，故未出现过的键桶值恒为 0，不会被 `top`（$\ge 1$）误中。

## 8. 边界情况与易错点

1. **第 0 键的持续时间是 `releaseTimes[0]`**（按下时刻为 0）：不是 0，也不能拿它与什么「哨兵」相减。用第 0 键直接作初值可同时避开这两类错。
2. **并列时取字母序「更大」，不是先按的、也不是后按的**：只写 `d > bestDur` 会漏换键，示例 1 错返 `'b'`；把复合条件简化成单条件 `d >= bestDur` 会错拿「最后满足者」——构造 `keysPressed = "ba"` 且两次时长并列 20 时，正确答案 `'b'`，`>=` 版本返回 `'a'`。
3. **「单次」≠「累计」**：同一键多次按下的时长**不累加**（示例 3 中 `'a'` 两次按下时长 5 与 20，比较的是 20 那一次）。若用 26 桶，桶里存单次最大，不是求和。
4. **溢出**：$d \le 10^9 < 2^{31} - 1$，`int` 安全；差分只减不增，无需更大类型。
5. **严格升序**保证 $d \ge 1$：无零 / 负时长需要处理；即便题面放宽为非降序（$d = 0$ 可能出现），本算法依然正确，无需改动。
6. **最小规模**：$n = 2$ 起步；算法对 $n = 1$ 也天然正确（循环不执行，直接返回第 0 键）。
7. **返回类型**：C++ 返回 `char`，Python 返回长度为 1 的 `str`，注意不要返回下标或时长。
