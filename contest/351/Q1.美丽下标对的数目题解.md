# LeetCode 美丽下标对的数目 题解

## 1. 题目概述

- **标题 / 题号**：美丽下标对的数目（#2748，easy）
- **链接**：https://leetcode.cn/problems/number-of-beautiful-pairs/
- **来源**：LeetCode 第 351 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、数学、计数、数论

**题意**：给定下标从 0 开始的整数数组 `nums`。若下标对 $(i, j)$（$0 \le i < j < n$）满足「`nums[i]` 的**第一个数字（首位）**与 `nums[j]` 的**最后一个数字（末位）**互质」，则称其为一组**美丽下标对**。返回美丽下标对的总数目。互质即 $\gcd(x, y) = 1$。

**约束**：

- $2 \le \mathrm{nums.length} \le 100$
- $1 \le \mathrm{nums}[i] \le 9999$
- $\mathrm{nums}[i] \bmod 10 \ne 0$（末位不为 0）

> 💡 签到题，两个关键读题点：① 条件用的是「**i 的首位** × **j 的末位**」，方向不能反；② 参与判定的只有**两个数位**，每个数位只有 $1 \sim 9$ 九种取值——这是把 $O(n^2)$ 优化到 $O(n)$ 的全部本钱。

## 2. 示例

**示例 1**

```text
输入：nums = [2, 5, 1, 4]
输出：5
解释：美丽对为 (0,1) (0,2) (1,2) (1,3) (2,3)。
      (0,3) 不算：首位 2 与末位 4 的 gcd 是 2。
```

**示例 2**

```text
输入：nums = [11, 21, 12]
输出：2
解释：(0,1)：gcd(首位 1, 末位 1) = 1；(0,2)：gcd(1, 2) = 1。
      (1,2) 不算：gcd(首位 2, 末位 2) = 2。
```

**示例 3**

```text
输入：nums = [4, 8, 16, 32]
输出：1
解释：只有 (2,3) 满足：gcd(首位 1, 末位 2) = 1。
      其余对的首位与末位都含公因数 2，全部落选。
```

## 3. 解题思路

### 3.1 暴力思路

按定义双重循环枚举所有 $(i, j)$：提取 `nums[i]` 的首位与 `nums[j]` 的末位，调用 $\gcd$ 判定，时间 $O(n^2)$。$n \le 100$ 时最多 $4950$ 对，直接可以通过。

但注意到判定对象**只有两个数位**，与 `nums[i]`、`nums[j]` 本身的大小无关——把每个元素抽象成「首位 + 末位」后，本题本质是一个**值域计数**问题，$O(n^2)$ 的枚举对里藏着大量重复判定。

### 3.2 核心观察：数位只有 9 种，桶计数一次遍历

![核心观察：首位与末位的互质判定](images/beautiful_pairs_digit_condition.svg)

1. **参与判定的数位只有 $1 \sim 9$**：首位天然非零，末位由约束 $\mathrm{nums}[i] \bmod 10 \ne 0$ 保证非零。于是互质关系是一张固定的 $9 \times 9$ 小表——例如 $2$ 与 $\{1,3,5,7,9\}$ 互质，$7$ 与除 $7$ 外的所有数字互质，$1$ 与一切互质。
2. **固定 $j$ 看贡献**：处理到下标 $j$ 时，能否配对只取决于 `nums[j]` 的末位 $b$——答案增量为「**之前元素里，首位与 $b$ 互质的个数**」，与这些元素的排列顺序、完整数值统统无关。
3. **桶计数**：维护 $\mathrm{cnt}[1..9]$，$\mathrm{cnt}[d]$ = 已扫过元素中首位为 $d$ 的个数。对每个新元素：先用末位 $b$ **查桶**求贡献，再把自己的首位**入桶**。「先查后入」天然保证只统计 $i < j$ 的对。

### 3.3 算法流程

![算法流程：先查桶、后入桶](images/beautiful_pairs_bucket_counting.svg)

```text
1. cnt[1..9] = 0，ans = 0
2. 从左到右遍历 x = nums[j]：
     b = x mod 10                          # 末位
     对 d = 1..9：若 gcd(d, b) = 1，ans += cnt[d]   # 查桶
     fd = x 的首位（除 10 直到 < 10）        # 首位
     cnt[fd] += 1                           # 入桶
3. 返回 ans
```

### 3.4 示例演算

![示例演算：桶的演变过程](images/beautiful_pairs_example_walkthrough.svg)

以 `nums = [2, 5, 1, 4]` 为例（演变见上图）：末位为 $1$ 的元素与前面**全部**元素配对；末位为 $4$ 时，首位 $2$ 因 $\gcd(2,4)=2$ 被排除，只有 $1$ 和 $5$ 计入——正好对应 $(0,3)$ 落选、$(1,3)$ 与 $(2,3)$ 入选。

## 4. 算法细节

1. **求首位**：`fd = x; while (fd >= 10) fd /= 10;`，最多除 $\lfloor \log_{10} 9999 \rfloor = 3$ 次；也可 `to_string(x)[0] - '0'`，两种写法等价。
2. **求末位**：`b = x % 10`。本题约束保证 $b \ne 0$；即便没有该约束，$\gcd(d, 0) = d$ 意味着只有 $d = 1$ 能与末位 $0$ 配对，标准 `gcd` 模板依然自动给出正确判定，无需特判。
3. **互质判定**：直接 `std::gcd` / `math.gcd`，$9 \times 9$ 的判定开销是常数；也可预计算互质表，本题没有必要。
4. **「先查后入」的顺序**：必须先用末位统计、再把首位入桶。若顺序颠倒，末位与自身首位互质的元素（如 $12$，$\gcd(1,2)=1$）会把自己算成 $(j,j)$，多算一次。
5. **答案上界**：$n \le 100$ 时答案至多 $\binom{100}{2} = 4950$，任何整型都绰绰有余，无需 `long long`。

## 5. 正确性证明

**引理 1**：处理下标 $j$ 之前，$\mathrm{cnt}[d]$ 恰等于集合 $\{\, i : i < j,\ \mathrm{first}(\mathrm{nums}[i]) = d \,\}$ 的大小。

**证明**：对 $j$ 归纳。$j = 0$ 时未处理任何元素，$\mathrm{cnt}$ 全零，成立。设处理 $j$ 前结论成立：查桶阶段不修改 $\mathrm{cnt}$，随后步骤把 $\mathrm{cnt}[\mathrm{first}(\mathrm{nums}[j])]$ 加一，于是处理 $j+1$ 前，$\mathrm{cnt}[d]$ 恰为 $i \le j$ 中首位为 $d$ 的个数，即 $i < j+1$ 的个数。归纳完成。∎

**引理 2**：处理 $j$ 时算法对 `ans` 的增量恰为 $\#\{\, i < j : \gcd(\mathrm{first}(\mathrm{nums}[i]),\ \mathrm{last}(\mathrm{nums}[j])) = 1 \,\}$。

**证明**：增量 $= \sum_{d :\, \gcd(d, b) = 1} \mathrm{cnt}[d]$，其中 $b = \mathrm{last}(\mathrm{nums}[j])$。把下标集合 $\{i : i < j\}$ 按首位值分桶：各桶互不相交且并为全集，桶 $\mathrm{first}(\mathrm{nums}[i]) = d$ 的大小由引理 1 即 $\mathrm{cnt}[d]$。故增量恰为「首位与 $b$ 互质的 $i < j$」的个数。∎

**定理**：算法返回值等于美丽下标对总数。

**证明**：每个有序对 $(i, j)$（$i < j$）在且仅在处理 $j$ 的时刻被考察：由引理 2，当且仅当 $\gcd(\mathrm{first}(\mathrm{nums}[i]),\ \mathrm{last}(\mathrm{nums}[j])) = 1$ 时被计入增量。不同 $j$ 的增量集合按第二下标划分、互不重叠，全部相加即不重不漏地覆盖所有 $i < j$ 对，与题目定义一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O\!\left(n \cdot (L + 9)\right)$，其中 $L \le 4$ 为求首位的除法次数，9 为查桶枚举的数字个数，总体即 $O(n)$。暴力做法 $O(n^2)$ 在 $n \le 100$ 下也能通过，但桶计数把套路从「枚举对」升级为「枚举值域」，是本题想考察的核心。
- **空间复杂度**：$O(1)$，只需 $\mathrm{cnt}$ 的 10 个计数与常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countBeautifulPairs(vector<int>& nums) {
        int cnt[10] = {0};
        int ans = 0;
        for (int x : nums) {
            int b = x % 10;
            for (int d = 1; d <= 9; d++) {
                if (cnt[d] && gcd(d, b) == 1) {
                    ans += cnt[d];
                }
            }
            int fd = x;
            while (fd >= 10) {
                fd /= 10;
            }
            cnt[fd]++;
        }
        return ans;
    }
};
```

### Python

```python
from math import gcd

class Solution:
    def countBeautifulPairs(self, nums: List[int]) -> int:
        cnt = [0] * 10
        ans = 0
        for x in nums:
            b = x % 10
            for d in range(1, 10):
                if cnt[d] and gcd(d, b) == 1:
                    ans += cnt[d]
            fd = x
            while fd >= 10:
                fd //= 10
            cnt[fd] += 1
        return ans
```

## 8. 边界情况与易错点

1. **方向别搞反**：条件是「$i$ 的**首位** × $j$ 的**末位**」，不是同一位、更不是「末位对首位」。周赛里最容易在这里白给一发 WA。
2. **先查后入**：先统计后入桶。若颠倒顺序，$(j, j)$ 会把自己算进去（例如 $x = 12$，$\gcd(1, 2) = 1$，多算一次）。
3. **首位不是固定除 $1000$**：元素 $1 \sim 4$ 位都可能出现，按最大位数硬编码（`x / 1000`）会把一位数算成 $0$。用循环或字符串求首位。
4. **$\gcd(1, 1) = 1$**：$1$ 与任何正整数（包括自身）互质，`11` 这种首末位都是 $1$ 的数照样正常判定（示例 2 的 $(0,1)$ 正是 $\gcd(1,1)=1$）。
5. **末位为 0 的假想陷阱**：本题约束末位非零，免疫了 $\gcd(d, 0)$ 的边界；即使约束放宽，`gcd` 模板给出 $\gcd(d, 0) = d$，只有 $d = 1$ 时配对成功，依然正确。
6. **重复元素**：值相同的元素占据不同下标、算不同对，桶计数按「个数」累计天然正确，无需去重。
