# LeetCode 得到整数零需要执行的最少操作数 题解

## 1. 题目概述

- **标题 / 题号**：得到整数零需要执行的最少操作数（#2749，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-the-integer-zero/
- **来源**：LeetCode 第 351 场周赛 Q2
- **难度**：中等
- **标签**：位运算、脑筋急转弯、枚举

**题意**：给定整数 `num1` 与 `num2`。每一步操作从 $[0, 60]$ 中选一个整数 $i$，把 `num1` 减去 $2^i + \text{num2}$。求把 `num1` 恰好变为 $0$ 的最少操作数；无法做到则返回 $-1$。

**约束**：

- $1 \le \text{num1} \le 10^9$
- $-10^9 \le \text{num2} \le 10^9$
- 每步的 $i$ 只能取 $0 \sim 60$，共 61 种

> 💡 读题第一眼就该抓住的点：**num2 可以为负**。当 $2^i + \text{num2} < 0$ 时，一步操作不减反增——值域双向无界，任何「对值搜最短路」的做法都没有天然终点。这是本题作为脑筋急转弯的核心陷阱：答案不是搜出来的，是**算出来的**。

## 2. 示例

**示例 1**

```text
输入：num1 = 3, num2 = -2
输出：3
解释：i=2：3 − (4−2) = 1；i=2：1 − (4−2) = −1；i=0：−1 − (1−2) = 0。
```

**示例 2**

```text
输入：num1 = 5, num2 = 7
输出：-1
解释：S = 5 − 7k 对一切 k ≥ 1 都是负数，凑不出任何「k 个 2 的幂之和」。
```

**示例 3**

```text
输入：num1 = 16, num2 = 0
输出：1
解释：16 − (2^4 + 0) = 0，一步到位；num2 = 0 时答案就是 popcount(num1)。
```

**示例 4**

```text
输入：num1 = 7, num2 = 0
输出：3
解释：7 = 111₂ 有 3 个置位，拆成 4 + 2 + 1 恰好三步。
```

## 3. 解题思路

### 3.1 暴力思路：为什么搜不动

- **BFS / DFS 搜值的变化**：`num2 < 0` 时每一步可能让 `num1` 变大，状态空间无界，搜索没有终点；
- **枚举指数序列**：每步 61 种选择，长度为 $k$ 的序列有 $61^k$ 种，组合爆炸；
- **DP**：$i$ 可重复选且与顺序无关，本质是多重组合问题，$10^9$ 的值域也开不下表。

正确的切入点是**换视角**：不去模拟每一步，而是把「$k$ 步之后的总效果」一次写完。

### 3.2 核心观察：k 步的总减量有封闭形式

![核心观察：k步总减量的封闭形式](images/min_ops_zero_closed_form.svg)

设 $k$ 步分别选了 $i_1, i_2, \dots, i_k$（可重复、与顺序无关），则 $k$ 步后

$$\text{num1}' = \text{num1} - \sum_{j=1}^{k}\left(2^{i_j} + \text{num2}\right) = \underbrace{\text{num1} - k \cdot \text{num2}}_{\text{记为 } S_k} - \sum_{j=1}^{k} 2^{i_j}$$

于是「$k$ 步把 num1 变为 0」等价于

$$S_k = \text{num1} - k \cdot \text{num2} = \sum_{j=1}^{k} 2^{i_j}$$

**关键**：num2 的贡献只与步数 $k$ 有关，与选哪些指数完全无关。所以「$k$ 步可行」$\iff$「$S_k$ 能写成**恰好 $k$ 个 2 的幂**之和（每个幂 $\le 2^{60}$）」。答案就是最小的可行 $k$——而 $k$ 是一个小整数，**直接枚举**即可。

### 3.3 判定：可行项数是一段连续区间

![可行项数是一段连续区间](images/min_ops_zero_split_range.svg)

正整数 $S$ 什么时候能写成恰好 $c$ 个 2 的幂之和？

1. **下界 $\mathrm{popcount}(S)$**：任何表示法经进位合并，项数不会少于二进制表示的置位数——进位只会把两个幂并成一个，1 的总数只减不增；
2. **上界 $S$**：每个幂 $\ge 2^0 = 1$，所以 $c$ 项之和 $\ge c$；
3. **中间全可行**：从二进制表示（$\mathrm{popcount}(S)$ 项）出发，每次把某个 $2^i\ (i \ge 1)$ 分裂成 $2^{i-1} + 2^{i-1}$，项数恰 $+1$、总和不变、幂只减不增；一路分裂到全 1 时项数 $= S$。

于是可行项数恰为连续区间 $[\mathrm{popcount}(S),\, S]$ 内的每个整数。本题中 $k \le 64$ 时 $S < 2^{37}$，二进制最高位 $\le 36 < 60$，**$i \in [0,60]$ 的上界永远碰不到**——判定只剩两个不等式：

$$\mathrm{popcount}(S_k) \le k \le S_k$$

### 3.4 算法流程

![算法流程：枚举k与两个判定条件](images/min_ops_zero_flow.svg)

```text
1. for k = 1, 2, 3, …, 64:
2.     S ← num1 − k · num2
3.     若 S ≥ k 且 popcount(S) ≤ k → 返回 k
4. 返回 −1
```

枚举上界 64 不是拍脑袋：§5 引理 3 证明**答案存在时必 $\le 36$**（`num2 < 0` 时 $k = 36$ 必可行；`num2 ≥ 0` 时若可行则 $\le 30$），64 只是再留一倍余量。

### 3.5 示例演算

![示例演算：num1=3, num2=−2](images/min_ops_zero_walkthrough.svg)

以 $(\text{num1}, \text{num2}) = (3, -2)$ 为例，$S_k = 3 + 2k$。$k=1$ 时 $S = 5 = 101_2$ 置位 2 个 $> 1$；$k=2$ 时 $S = 7 = 111_2$ 置位 3 个 $> 2$；$k=3$ 时 $S = 9 = 1001_2$ 置位 2 个 $\le 3$ 且 $9 \ge 3$——通过！把 9 里的 8 分裂一次得 $4 + 4 + 1$，对应 $i = 2, 2, 0$，与官方示例的三步完全一致。

## 4. 算法细节

1. **S 的计算与溢出**：$k \le 64$、$|\text{num2}| \le 10^9$，故 $k \cdot \text{num2} \in (-6.4 \times 10^{10},\ 6.4 \times 10^{10})$，$S$ 最大约 $6.5 \times 10^{10}$，**超出 int32 约 15 倍**——C++ 必须用 `long long`；Python 天然大整数无碍。
2. **popcount 的实现**：C++ 用 `__builtin_popcountll`——$S$ 可达 $6.5 \times 10^{10} > 2^{32}$，32 位版只看低 32 位会**静默算错**；Python 3.10+ 用 `int.bit_count()`，旧版本用 `bin(s).count('1')`。
3. **先判 $S \ge k$ 再取 popcount**：$S$ 为负（`num2 > 0` 的典型情形）直接淘汰。注意 Python 的 `int.bit_count()` 作用于绝对值，负数照样返回正的 popcount，不先判就会误判。
4. **2 的幂上界 $[0,60]$ 的处理**：结论是**不需要处理**——$k \le 64$ 时 $S < 2^{37}$，二进制最高位 $\le 36$，而分裂只会产生更小的幂，所以表示里所有幂 $\le 2^{36} < 2^{60}$。
5. **枚举必须有界**：上限 64 有引理 3 背书；写 `while (true)` 裸枚举，在 `num2 > 0` 无解（如示例 2）时会死循环。

## 5. 正确性证明

**引理 1（必要性）**：若 $k$ 步能把 num1 变为 0，则 $S_k = \text{num1} - k \cdot \text{num2}$ 满足 $S_k \ge k$ 且 $\mathrm{popcount}(S_k) \le k$。

**证明**：此时 $\sum_{j=1}^{k} 2^{i_j} = S_k$。每项 $2^{i_j} \ge 1$，故 $S_k \ge k$。又 popcount 对加法子可加：$\mathrm{popcount}(a+b) \le \mathrm{popcount}(a) + \mathrm{popcount}(b)$——二进制逐位相加时每个进位都把两个 1 合并成一个，1 的总数不增。归纳得 $\mathrm{popcount}(S_k) \le \sum_{j} \mathrm{popcount}(2^{i_j}) = k$。∎

**引理 2（判定充要）**：设正整数 $S < 2^{61}$。$S$ 可写成恰好 $c$ 个 2 的幂之和（每个幂 $\le 2^{60}$）当且仅当 $\mathrm{popcount}(S) \le c \le S$。

**证明**：必要性即引理 1 的两条。充分性：从 $S$ 的二进制表示出发，共 $\mathrm{popcount}(S)$ 项，最大幂为 $S$ 的最高位，由 $S < 2^{61}$ 知其 $\le 2^{60}$。若当前项数 $< c$，则必有某项 $2^i$ 满足 $i \ge 1$（否则全为 $2^0$，项数已达 $S \ge c$），把该项分裂为 $2^{i-1} + 2^{i-1}$：项数恰 $+1$、总和不变、最大幂不增。重复至项数 $= c$，得一组恰好 $c$ 个、每个 $\le 2^{60}$ 的幂。∎

**引理 3（枚举上界）**：若存在可行的 $k$，则存在可行的 $k \le 36$；且 `num2 < 0` 时答案必存在。

**证明**：若 `num2 < 0`，取 $k = 36$：$S_{36} = \text{num1} + 36|\text{num2}| \le 37 \times 10^9 < 2^{36}$，故 $\mathrm{popcount}(S_{36}) \le 36 = k$，且 $S_{36} \ge 1 + 36 = 37 > 36$，引理 2 的两条件均成立，$36$ 可行。若 `num2 ≥ 0`：$S_k \le \text{num1} < 2^{30}$，故对一切 $k$ 有 $\mathrm{popcount}(S_k) \le 30$。反设最小可行 $k \ge 31$，则 $\text{num1} = S_k + k \cdot \text{num2} \ge 31 + 31\,\text{num2}$，于是 $S_{30} = \text{num1} - 30\,\text{num2} \ge 31 + \text{num2} \ge 31 > 30$，且 $\mathrm{popcount}(S_{30}) \le 30$——$30$ 也可行，与最小性矛盾。∎

**定理**：算法返回最少操作数；无解时返回 $-1$。

**证明**：由引理 1 与引理 2，$k$ 可行 $\iff S_k \ge k \wedge \mathrm{popcount}(S_k) \le k$（引理 2 的前提 $S < 2^{61}$ 在 $k \le 64$ 时自动满足：$S \le 10^9 + 64 \times 10^9 < 2^{37}$）。算法按 $k$ 递增枚举，返回首个通过判定者即最小可行 $k$。由引理 3，若可行 $k$ 存在，最小可行 $k \le 36 \le 64$ 必被枚举到；若 64 轮内无一通过，则不存在可行 $k$，返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(1)$——至多 64 轮，每轮一次乘法、一次减法、一次 $\le 64$ 位的 popcount；按位计也仅 $O(64^2)$ 次位操作，仍是常数。
- **空间复杂度**：$O(1)$，只用常数个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int makeTheIntegerZero(int num1, int num2) {
        for (long long k = 1; k <= 64; k++) {
            long long s = (long long)num1 - k * num2;
            if (s >= k && __builtin_popcountll(s) <= k) {
                return (int)k;
            }
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def makeTheIntegerZero(self, num1: int, num2: int) -> int:
        for k in range(1, 65):
            s = num1 - k * num2
            if s >= k and s.bit_count() <= k:
                return k
        return -1
```

## 8. 边界情况与易错点

1. **int 溢出（C++ 头号坑）**：$k \cdot \text{num2}$ 可达 $\pm 6.4 \times 10^{10}$，必须 `long long`；`__builtin_popcount` 也必须用 `ll` 版本，32 位版只看低 32 位**静默算错**而非报错。
2. **负 S 别进 popcount**：先判 $S \ge k$（顺带覆盖 $S \le 0$）再数位；Python 的 `bit_count()` 作用于绝对值，顺序写反会把负数误判成可行。
3. **无界枚举死循环**：`num2 > 0` 且无解（如 $(5, 7)$）时 $S_k$ 只会越来越负——枚举必须有上界，64 有引理 3 背书。
4. **num2 = 0 的退化**：答案 $= \mathrm{popcount}(\text{num1})$，可当自测锚点（$(16,0) \to 1$、$(7,0) \to 3$）。
5. **−1 只出现在 num2 ≥ 1**：`num2 < 0` 时 $k = 36$ 必可行（引理 3），永远有解；`num2 = 0` 时 $\mathrm{popcount}(\text{num1}) \ge 1$ 也必有解。返回 $-1$ 前不妨自问 num2 是否真为正。
6. **「i ∈ [0,60]」是烟雾弹**：$S < 2^{37}$ 使表示中最大幂 $\le 2^{36}$，上界永远碰不到；比赛时想通这点，判定就敢只写两个不等式。
7. **k = 0 不是答案**：$\text{num1} \ge 1$，循环从 1 起即可，无需讨论。
