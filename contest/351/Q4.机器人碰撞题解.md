# LeetCode 机器人碰撞 题解

## 1. 题目概述

- **标题 / 题号**：机器人碰撞（#2751，hard）
- **链接**：https://leetcode.cn/problems/robot-collisions/
- **来源**：LeetCode 第 351 场周赛 Q4
- **难度**：困难
- **标签**：栈、数组、排序、模拟

**题意**：数轴上有 $n$ 个机器人，编号即输入下标（从 0 开始），各有位置 $\text{positions}[i]$、健康度 $\text{healths}[i]$、方向 $\text{directions}[i]$（`'L'` 向左 / `'R'` 向右），位置**互不相同且可能乱序**。所有机器人**同时同速**出发；两机器人到达同一位置即**碰撞**：健康度低者被移除、高者健康度**减 1**（相同时**双双移除**），幸存者保持原方向继续前进。求最终幸存机器人的健康度，**按输入编号顺序**返回。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{positions}[i],\ \text{healths}[i] \le 10^9$
- $\text{directions}[i] \in \{\text{'L'}, \text{'R'}\}$，`positions` 中所有值互不相同

> 💡 一句话定位：本题是 [735. 行星碰撞](https://leetcode.cn/problems/asteroid-collision/) 的「**乱序 + 扣血 + 带编号**」三重进阶版，母题范式仍是**栈模拟**，但每一重进阶都对应一个必须单独处理的实现细节。

## 2. 示例

**示例 1**

```text
输入：positions = [5,4,3,2,1], healths = [2,17,9,15,10], directions = "RRRRR"
输出：[2,17,9,15,10]
解释：所有机器人同向右行，永不碰撞，按原编号顺序原样返回。
```

**示例 2**

```text
输入：positions = [3,5,2,6], healths = [10,10,15,12], directions = "RLRL"
输出：[14]
解释：机器人 1、2（位置 3、5）相向碰撞，同血 10 = 10 双双移除；
      机器人 3、4（位置 2、6）相向碰撞，15 > 12，机器人 4 移除、机器人 3 变 14。仅剩 [14]。
```

**示例 3**

```text
输入：positions = [1,2,5,6], healths = [10,10,11,11], directions = "RLRL"
输出：[]
解释：两对相向机器人均同血同归于尽，无幸存者，返回空数组。
```

## 3. 解题思路

### 3.1 暴力思路：多轮扫描相邻碰撞

最直觉的做法：先把机器人按位置排序，然后反复扫描整个序列，找到相邻的「左 R 右 L」对就处理一次碰撞，直到某一轮再无碰撞为止。每轮扫描 $O(n)$，最坏情况每轮只消灭一个机器人（如一个满血 R 从左往右依次磨死一串 L），共需 $O(n)$ 轮，总复杂度 $O(n^2)$——$n = 10^5$ 时约 $10^{10}$ 次操作，必然超时。

另一种朴素做法是**按时间步进**模拟运动过程，但相遇点可能是半整数位置、时间跨度可达 $10^9$，既无法离散化步长、也无法控制轮数，方向根本走不通。

暴力的浪费在于：每轮扫描里绝大多数机器人根本没参与碰撞。真正会发生碰撞的只有「左 R 右 L」对，且一个机器人的命运一旦确定（例如它向右、且右边再没有向左的机器人）就可以**永久归档**——这提示我们把碰撞**增量地**消费掉，而不是整轮重复扫描。

### 3.2 核心观察：只有「左 R 右 L」相撞，栈顶就是 L 的第一个对手

![核心观察：只有左R右L相撞，栈天然维护碰撞顺序](images/robot_collision_stack_model.svg)

**观察 1（静态判定）**：所有机器人同速同时出发，方向在碰撞后也不改变。两个机器人会相撞，当且仅当初始时「**位置较小者向 R、位置较大者向 L**」——这种组合距离每单位时间缩短 2，必相遇；其余三种组合（左 L 右 R、双 R、双 L）距离只增不减，**永不相遇**。也就是说，**谁和谁会撞是初始配置的静态性质，与碰撞发生的先后无关**。

**观察 2（栈维护「待定 R」）**：把机器人**按位置升序**逐个处理，维护一个存**原下标**的栈：

- 当前是 **R**：直接入栈。它右侧的机器人尚未处理，未来可能与某个 L 相撞，命运待定；
- 当前是 **L**：它的第一个对手是**栈顶的 R**——即已处理机器人中位置最大、且仍存活的向右者。与 735 不同，胜者要**扣 1 血**：若 L 获胜，血量减 1、弹出栈顶，**继续与新栈顶比较**（连战多场）；若同血则同归于尽；若栈顶更强，栈顶扣 1 血留在栈中，L 出局——栈顶虽胜但变弱，仍要迎接下一个对手。

**观察 3（栈的形态）**：处理完任何一个机器人后，栈从底到顶恒为「若干 L 接若干 R」：R 只会压在任意栈顶之上（延长 R 段），而 L 必然先磨光整个 R 段才有资格入栈（压在 L 段上）。于是**栈内任何两个机器人都不构成「小 R 大 L」，此后永不再碰撞**——栈就是「命运已封存」的归档区。

### 3.3 算法流程：排序 → 栈遍历 → 按原编号输出

![算法流程：排序后栈遍历与血量三分支](images/robot_collision_flow.svg)

1. **按位置排序**：对下标数组按 `positions` 值升序排序，得到处理顺序 `idx`（**排下标而非排值**，否则丢失编号）；
2. **栈遍历**：按 `idx` 逐个处理。R 直接入栈；L 与栈顶 R 循环碰撞，血量三分支（`>` 栈顶胜扣血 / `=` 同归于尽 / `<` L 胜弹栈顶且 `h−1` 继续），直到 L 阵亡、或栈顶不再是 R（栈空 / 栈顶是幸存的 L）；L 若幸存则写回剩余血量 `h` 后入栈；
3. **按原编号收集**：遍历结束，栈中下标即幸存者。用存活标记数组**按原下标顺序**扫一遍输出 `healths`。

> 💡 两次「排序」各司其职：第一次按**位置**排是为了按真实碰撞时序处理；输出则按**编号**序还原——两者维度不同，缺一不可。

### 3.4 示例演算

![示例2演算：栈视角下的两场碰撞](images/robot_collision_walkthrough.svg)

以**示例 2**（`positions = [3,5,2,6]`, `healths = [10,10,15,12]`, `directions = "RLRL"`）走一遍：按位置排序后处理顺序为 3号(pos 2, R) → 1号(pos 3, R) → 2号(pos 5, L) → 4号(pos 6, L)。前两步 R 连续入栈得 `[3(15), 1(10)]`；第三步 2 号（L, 10）与栈顶 1 号（10）同血双双移除，栈变 `[3(15)]`；第四步 4 号（L, 12）挑战栈顶 3 号（15 > 12），4 号销毁、3 号扣 1 血变 14。幸存 `{3号: 14}`，按编号输出 `[14]`。

再验证两个极端：**示例 1** 全 R，四步全是入栈、零次碰撞，输出原数组——这说明「全同向」时代码退化为纯排序+复制，天然正确；**示例 3** 两组同血对撞，两 L 都死在第一场战斗里，栈最终为空，返回 `[]`。

## 4. 算法细节

1. **栈里存原下标而非健康度**：碰撞时要同时读方向（`directions[j]`）、读写健康度（`healths[j]`），输出时要编号——存下标一举三得。
2. **while 条件三件套**：`alive && !stk.empty() && directions[stk.back()] == 'R'`。第三个条件最易漏：栈中会**残留幸存的 L**（磨光了所有能撞的 R 后入栈）。后续 L 与它同向同速永不相遇，并且永远追不上它、无法越过它去撞更深的元素——遇到非 R 栈顶必须立即停。
3. **L 的血量用局部变量 `h` 携带**：每赢一场 `h -= 1`，只有最终幸存才写回 `healths[i]`；中途阵亡则什么都不写（原值作废）。栈顶获胜则是原地 `healths[j]--`——它留在栈中继续迎接下一场。
4. **三分支必须写全**：`>` 是**严格大于**才算栈顶胜；`==` 同归于尽（弹出栈顶 + L 出局）。漏写 `==` 会让相等情况错误落入不等分支，方向不同的漏法产生相反的错误结果。
5. **收尾 O(n) 还原编号序**：用 `alive` 标记数组按原下标扫一遍（比把 `(编号, 血量)` 对排序少一个 $\log$；两种写法结果一致）。
6. **为什么遍历顺序 = 真实碰撞时序**：见 §5 引理 3——「下一个碰撞事件」永远发生在当前 L 与栈顶 R 之间，按位置排序的线性扫描恰好按时间顺序消费事件，无需任何优先队列。

## 5. 正确性证明

**引理 1（碰撞对刻画）**：真实运动中，两机器人相撞当且仅当初始时位置较小者方向为 R、位置较大者方向为 L。

**证明**：所有机器人同时出发、同速运动，且碰撞不改变幸存者方向。设两机器人初始位置 $p < q$。若前者向左（双 L、L-R）或后者向右（双 R、R-R），二者距离 $q - p$ 随时间不减，永不相等；唯有「前者 R、后者 L」时距离以每单位时间 2 的速率缩短，必在时刻 $(q-p)/2$ 相遇于位置 $(p+q)/2$。∎

**推论（静态性）**：由引理 1，任意两机器人是否相撞**完全由二者初始位置与方向决定**，与其他机器人的存在、碰撞的先后顺序均无关。

**引理 2（栈不变量）**：按位置升序逐个处理机器人（R 入栈；L 与栈顶循环碰撞、幸存后入栈），每步结束后：

- (a) 栈内元素位置从底到顶严格递增；
- (b) 栈内元素从底到顶形如「若干 L 接若干 R」（不存在某个 R 上方压着 L）；
- (c) 栈内任意两个机器人此后永不再相撞。

**证明**：对处理步数归纳，栈空时三条平凡。设处理机器人 $a$ 前不变量成立，$a$ 的位置大于所有已处理者。

- $a$ 为 **R** 入栈：(a) 显然保持；(b) $a$ 压在栈顶（无论原栈顶是 L 还是 R）只是延长 R 段，不产生「R 下 L 上」；(c) 由推论，$a$ 与栈内任一元素 $b$ 是否相撞是静态性质：$b$ 位置更小，若 $b$ 为 R 则双 R 不撞、若 $b$ 为 L 则是「小 L 大 R」不撞（引理 1）。
- $a$ 为 **L**：while 循环依次与栈顶 R 按规则对决（严格大者胜且扣 1 血、同血双毁），每场结果与真实碰撞规则一致。若 $a$ 阵亡或战平，栈剩余部分仍满足 (a)(b)，且 (c) 中被弹出/存活的元素对的相撞性是静态的——已发生的碰撞使其中一方消亡，静态「会撞」对的另一方已不存在，结论保持。若 $a$ 幸存，则循环必终止于「栈空或栈顶为 L」：由 (b)，栈内 R 段已被全部弹出、剩余全为 L，$a$ 压上后仍为「L…L」形态，(b) 保持；(c) $a$ 与栈内 L 均为「双 L」不撞。∎

**引理 3（事件顺序）**：算法 while 循环内的每一次比较，恰好对应真实过程中**下一个发生**的碰撞事件。

**证明**：考虑处理机器人 $a$（按位置序）的时刻：已处理者都在 $a$ 左侧且栈内两两不再碰撞（引理 2c），未处理者都在 $a$ 右侧。

- $a$ 为 R：$a$ 与全部已处理者均不构成「小 R 大 L」（$a$ 位置最大且向右），与未处理者的碰撞留待后续处理——入栈正确。
- $a$ 为 L：由推论，$a$ 静态上「会撞」的对象是栈内所有 R 及右侧未来出现的位置更大的 R（后者为「小 L 大 R」，不撞）——实际只有**栈内的 R 段**。同速下 $a$ 与栈内 R 的相遇时刻为 $(p_a - p_R)/(2v)$，随 $p_R$ 增大而减小，故**位置最大的存活 R（栈顶）最早**。同时该相遇点 $(p_a + p_{top})/2 < p_a$，而任何未处理对（双方位置 $> p_a$）的相遇点 $> p_a$，未处理元素与 $a$ 均不相撞——因此下一个全局事件就是 $a$ × 栈顶 R。若 $a$ 胜（栈顶弹出、$h$ 减 1），下一个涉及 $a$ 的事件同理是与新栈顶 R 的碰撞；若新栈顶是 L，由推论 $a$ 与它永不相遇，循环终止正确。归纳可知 while 的每次比较都是按时间序的下一事件。∎

**定理**：算法结束后，栈中恰为真实幸存者集合，各 `healths` 值与真实过程一致，且输出顺序符合题目要求。

**证明**：对处理步数归纳：由引理 3，每步（含 while 内的每场对决）都按真实时间序回放一个碰撞事件，胜负判定与扣血（`h` 局部变量 / `healths[j]--`）与规则一一对应；由引理 2c，已处理区内部不再有未来碰撞。全部处理完毕后未处理区为空，所有碰撞已回放完毕，栈中即幸存者、`healths` 即终值。收集时按原下标扫描，恰为编号顺序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$。瓶颈在按位置排序；主循环中每个机器人至多入栈一次、每个栈元素至多被弹出一次，while 的总比较次数以总弹出次数 + 机器人个数为上界，均摊 $O(n)$；收尾标记扫描 $O(n)$。
- **空间复杂度**：$O(n)$。`idx`、`stk`、`alive` 标记数组各 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> survivedRobotsHealths(vector<int>& positions, vector<int>& healths, string directions) {
        int n = positions.size();
        vector<int> idx(n);
        iota(idx.begin(), idx.end(), 0);
        sort(idx.begin(), idx.end(), [&](int a, int b) {
            return positions[a] < positions[b];
        });

        vector<int> stk;
        for (int i : idx) {
            if (directions[i] == 'R') {
                stk.push_back(i);
                continue;
            }
            int h = healths[i];
            bool alive = true;
            while (alive && !stk.empty() && directions[stk.back()] == 'R') {
                int j = stk.back();
                if (healths[j] > h) {
                    healths[j]--;
                    alive = false;
                } else if (healths[j] < h) {
                    h--;
                    stk.pop_back();
                } else {
                    stk.pop_back();
                    alive = false;
                }
            }
            if (alive) {
                healths[i] = h;
                stk.push_back(i);
            }
        }

        vector<char> aliveFlag(n, 0);
        for (int i : stk) aliveFlag[i] = 1;
        vector<int> ans;
        for (int i = 0; i < n; i++) {
            if (aliveFlag[i]) ans.push_back(healths[i]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def survivedRobotsHealths(self, positions: List[int], healths: List[int], directions: str) -> List[int]:
        n = len(positions)
        idx = sorted(range(n), key=lambda i: positions[i])

        stk = []
        for i in idx:
            if directions[i] == 'R':
                stk.append(i)
                continue
            h = healths[i]
            alive = True
            while alive and stk and directions[stk[-1]] == 'R':
                j = stk[-1]
                if healths[j] > h:
                    healths[j] -= 1
                    alive = False
                elif healths[j] < h:
                    h -= 1
                    stk.pop()
                else:
                    stk.pop()
                    alive = False
            if alive:
                healths[i] = h
                stk.append(i)

        alive_flag = [False] * n
        for i in stk:
            alive_flag[i] = True
        return [healths[i] for i in range(n) if alive_flag[i]]
```

## 8. 边界情况与易错点

1. **`positions` 乱序是头号坑**：必须对**下标**按位置排序（`sort(positions)` 会直接丢失编号映射，后续输出无从还原）。
2. **输出按原编号序，不是栈序**：栈序 = 位置序。示例 1 全 R 时两者恰好相同，极具欺骗性；示例 2 立刻暴露差异。
3. **`==` 分支同归于尽**：必须与 `>` / `<` 三支写全；`>` 是严格大于，写成 `>=` 会把同血情况错误判给栈顶。
4. **while 条件的 `directions[stk.back()] == 'R'` 不能省**：栈中会残留幸存的 L；两个 L 同向同速永不相遇，且栈顶 L 会把更深的元素「屏蔽」在身后（见 §4 第 2 点）。
5. **L 幸存才写回血量**：`h` 是局部携带的实时血量，阵亡则原 `healths[i]` 作废不落盘；栈顶获胜则是原地 `healths[j]--`，两种扣血的位置不同，别写串。
6. **全灭返回空数组 / 单机器人原样返回**：都由通用逻辑自然覆盖（栈空 → 标记全 0；单机器人不进碰撞分支），无需特判。
7. **C++ 细节**：`iota` 在 `<numeric>` 头文件；数值上限 $10^9$ 但只做比较与减 1，`int`（上限约 $2.1 \times 10^9$）足够，无需 `long long`。
8. **别按时间离散模拟**：相遇点可能是半整数、时间跨度 $10^9$，步进模拟既超时又易错——栈模拟一次性把时序问题转化成位置序问题。
