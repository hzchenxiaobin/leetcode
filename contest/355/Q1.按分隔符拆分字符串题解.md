# LeetCode 按分隔符拆分字符串 题解

## 1. 题目概述

- **标题 / 题号**：按分隔符拆分字符串（#2788，easy）
- **链接**：https://leetcode.cn/problems/split-strings-by-separator/
- **来源**：LeetCode 第 355 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、模拟

**题意**：给定字符串数组 $\text{words}$ 与单字符分隔符 $\text{separator}$，把每个 $\text{words}[i]$ 中所有出现 $\text{separator}$ 的位置都「切一刀」，收集切出的所有**非空**子串，按原顺序拼成结果数组返回。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \text{words}[i]\text{.length} \le 20$
- $\text{words}[i]$ 仅由小写英文字母与 `.,|$#@` 中的字符组成
- $\text{separator}$ 是 `.,|$#@` 中的某个字符

> 💡 签到题切题三句话：① 语义 = 在每个分隔符处切一刀；② 结果**不含空串**；③ 顺序保持。总长 $\sum_i |\text{words}[i]| \le 2000$——纯模拟就是终点，拼的是读题到提交的最短路径与零 WA。

## 2. 示例

**示例 1**

```text
输入：words = ["one.two.three","four.five","six"], separator = "."
输出：["one","two","three","four","five","six"]
解释："one.two.three" 切出 one | two | three；"four.five" 切出 four | five；
      "six" 无分隔符，整段 six 原样入结果。
```

**示例 2**

```text
输入：words = ["$easy$","$problem$"], separator = "$"
输出：["easy","problem"]
解释：首尾都是 $，切出的首段、尾段均为空串，被丢弃。
```

**示例 3**

```text
输入：words = ["|||"], separator = "|"
输出：[]
解释：三刀切出四个空段，全部丢弃。
```

**补充示例（自构造，一次覆盖三个坑）**

```text
输入：words = ["a.b..c",".x","d."], separator = "."
输出：["a","b","c","x","d"]
解释：连续分隔符（"a.b..c" 的第 4 位）、首分隔符（".x"）、尾分隔符（"d."）
      产生的空段全部被过滤。
```

## 3. 解题思路

### 3.1 暴力思路：模拟即终点

把题面翻译成两步——「在每个分隔符处切开」+「丢掉空段」——直接就是 $O(L)$ 线性模拟（$L$ 为所有串总长），没有更快算法可言（§5 引理 3：每个字符至少读一次）。真正要警惕的反而是两个**陷阱写法**：

- **C++ 用 `strtok`**：会**原地改写**传入的字符串（把分隔符替换成 `\0`），等价于破坏输入；且依赖函数内静态缓冲，不可重入。
- **Python 用 `re.split`**：`$` `.` `|` 全是正则元字符，不 `re.escape` 直接切错。

### 3.2 核心观察：切分语义 + 空段三来源

![核心观察：在每个分隔符处切一刀，空段一律丢弃](images/wc355_q1_split_concept.svg)

切分操作可以完全形式化：设 $w$ 长为 $m$，把每个满足 $w[j] = \text{separator}$ 的位置 $j$ 都视为切口，$w$ 被切成至多 $m+1$ 段（可能为空），结果即所有非空段按序拼接。

本题**唯一考点**是空串过滤。空段恰有三个来源：

1. **首部分隔符**：$w[0] = \text{separator}$ → 首段为空（示例 2 的 `$easy$`）；
2. **尾部分隔符**：$w[m-1] = \text{separator}$ → 尾段为空（同上）；
3. **连续分隔符**：$w[j] = w[j+1] = \text{separator}$ → 中间夹出空段（示例 3 的 `|||`）。

只要收集时统一判空（一行 `if`），三个来源被同一处代码拦截，**无需任何特判**——为每种来源单写分支才是负优化。

### 3.3 算法流程：线性扫描 + 判空冲刷

![算法流程：线性扫描，遇分隔符或串尾即判空冲刷](images/wc355_q1_split_flow.svg)

手写扫描只维护一个累积段 $\text{cur}$（cur 的长度 $\le 20$，只是一个小缓冲区）：

1. $\text{ans} \gets [\ ]$，$\text{cur} \gets \epsilon$；
2. 按序扫描每个 $w$ 的每个字符 $c$：
   - 若 $c = \text{separator}$：**冲刷**——$\text{cur}$ 非空则追加进 $\text{ans}$，随后 $\text{cur} \gets \epsilon$；
   - 否则：$\text{cur} \gets \text{cur} + c$（累积）；
3. 每个 $w$ 扫描结束时做一次**尾冲刷**（动作同上），再切换下一个 $w$；
4. 所有 $w$ 处理完，返回 $\text{ans}$。

> 💡 「冲刷」是唯一出口：分隔符触发的冲刷与串尾触发的尾冲刷共用同一段代码（判空 + 收集 + 清空），这也是 C++ 参考代码里用 lambda 表达的结构。

### 3.4 示例演算

![示例演算：words = ["a.b..c", ".x", "d."]，separator = "."](images/wc355_q1_split_walkthrough.svg)

以补充示例中 `word = "a.b..c"` 走查（$\text{cur}$ 冲刷后为 $\epsilon$ 记作空）：

| $j$ | $c$ | $c = .$ ? | $\text{cur}$ | $\text{ans}$ | 说明 |
|-----|-----|----------|--------------|--------------|------|
| 0 | a | 否 | "a" | [ ] | 累积 |
| 1 | . | 是 | ε | ["a"] | 冲刷："a" 非空 → 入 ans |
| 2 | b | 否 | "b" | ["a"] | 累积 |
| 3 | . | 是 | ε | ["a","b"] | 冲刷："b" 入 ans |
| 4 | . | 是 | ε | ["a","b"] | **★ cur 已空 → 判空拦截，不入** |
| 5 | c | 否 | "c" | ["a","b"] | 累积 |
| 串尾 | ⊥ | 串尾 | ε | ["a","b","c"] | 尾冲刷："c" 入 ans |

随后 `".x"` 的首空段被拦截、尾冲刷收走 "x"；`"d."` 由分隔符冲刷收走 "d"。最终 $\text{ans} = [\texttt{"a"},\texttt{"b"},\texttt{"c"},\texttt{"x"},\texttt{"d"}]$ ✓。

## 4. 算法细节

1. **冲刷动作统一判空**：`if (cur 非空) ans.push_back(cur); cur = ""`——首、尾、连续分隔符三种空段来源在同一个 if 处被拦截，不写任何 case 特判。
2. **语言选择**：
   - **Python**：`str.split(sep)` 一行完成切分，但必须再过滤——`w.split(separator)` **保留空段**（`"$easy$".split("$") == ['', 'easy', '']`），`if seg` 不可省略；
   - **C++**：标准库没有现成 split，手写「累积 + 冲刷」最稳；备选 `getline(ss, seg, separator)` 流式切分——注意它遇**连续分隔符会产生空 seg**（同样判空），但遇**末尾分隔符不产生额外空段**（流到 EOF 即止），两种行为差异不影响判空写法的正确性。
3. **separator 的类型**：C++ 形参是 `char`，Python 形参是 `str`（题目保证单字符），`c == separator` 直接比较即可，无需要 `.front()` / `[0]` 取字符。
4. **顺序性**：外层按 $\text{words}$ 下标、内层按字符下标的双层循环天然保持「段在串内有序、串在结果内有序」，无需显式排序或索引管理。
5. **规模上界**：段数 $\le \sum_i (\text{cnt}_i + 1) \le 2100$，结果数组直接 `reserve`/列表推导即可，无性能敏感点。

## 5. 正确性证明

**引理 1（切分刻画）**：对长为 $m$ 的串 $w$，设切口集 $S = \{\, j : w[j] = \text{separator} \,\}$，则 $S$ 把 $w$ 切成 $|S| + 1$ 段：相邻切口之间（含串首之前与串尾之后的部分）的极大子串。$w$ 对答案的贡献 = 其中所有非空段按下标序构成的序列。

**证明**：由题意，结果须满足四条：① 每段是 $w$ 的子串；② 段互不重叠且按序拼接后去掉所有 separator 字符恰为 $w$；③ 分隔符不出现在结果字符串中；④ 保持原顺序。若某位置 $j \in S$ 处未切，则包含 $w[j]$ 的段含有 separator，与 ③ 矛盾，故每个切口必须切；反之，$S$ 的切口切出的段满足 ①②④，且每段不含 separator。切分方式唯一，再由题意丢弃空段即得贡献序列。∎

**引理 2（扫描不变式）**：扫描 $w$ 的前 $j$ 个字符后，$\text{cur} = w[s..j-1]$（$s$ 为 $j$ 之前最后一个切口之后的位置，即当前未闭合段），且 $\text{ans}$ 已按序包含前 $j$ 个字符切出的所有非空完整段。

**证明**：对 $j$ 归纳。$j = 0$：$\text{cur} = \epsilon$、$\text{ans}$ 无新增，成立。设 $j$ 时成立，考察第 $j$ 个字符 $c = w[j]$：若 $c \ne \text{separator}$，算法执行 $\text{cur} \gets \text{cur} + c$，未闭合段延长一格，$\text{ans}$ 不变；若 $c = \text{separator}$，$j$ 成为新切口，当前未闭合段 $w[s..j-1]$ 恰好闭合：非空则算法将其追加进 $\text{ans}$（与引理 1 的段定义一致），为空则不追加（空段被丢弃），随后 $\text{cur} \gets \epsilon$ 即 $s \gets j+1$。两种情况不变式均对 $j+1$ 保持。∎

**定理 1（正确性）**：算法返回的 $\text{ans}$ 即所求答案。

**证明**：对每个 $w$，在引理 2 中取 $j = m$：扫描后 $\text{cur} = w[s..m-1]$ 为最后一个未闭合段，尾冲刷将其判空后按需追加，故 $w$ 的全部非空段按序进入 $\text{ans}$；由引理 1，这正是 $w$ 的贡献。外层循环按 $\text{words}$ 下标序处理，段与段、串与串的相对顺序均保持。∎

**引理 3（下界）**：任何确定性正确算法在最坏情况下必须读取全部 $L$ 个字符，故时间复杂度 $\Omega(L)$。

**证明**（对手论证）：反设算法在某次运行中未读取某位置（$w_i$ 的第 $j$ 个字符）。构造两组输入 $A$、$B$：除该位置外完全相同，$A$ 中该字符取字母 `a`，$B$ 中取 separator（其余字符随意取合法值）。取 $w_i$ 长度为 1（合法）：$A$ 的答案含 `"a"` 一个段，$B$ 的答案为空（唯一段为空被丢）——正确答案不同；而算法在两组输入上的执行轨迹（读取内容与输出）完全相同，必有一组输出错误，矛盾。∎

**推论**：单趟 $O(L)$ 扫描渐近最优——不是「够用」，而是「不可能更快」。

## 6. 复杂度分析

- **时间复杂度**：$O(L)$，其中 $L = \sum_i |\text{words}[i]| \le 100 \times 20 = 2000$。每个字符恰一次比较、至多一次入段；所有段的总长 $\le L$，构造代价与扫描代价同阶。由引理 3，$O(L)$ 已是下界。
- **空间复杂度**：$O(L)$——即输出本身的规模；额外辅助空间仅累积段 $\text{cur}$（长度 $\le 20$）与常数个循环变量，可视为 $O(1)$ 额外开销。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> splitWordsBySeparator(vector<string>& words, char separator) {
        vector<string> ans;
        string cur;
        auto flush = [&]() {
            if (!cur.empty()) ans.push_back(cur);   // 判空冲刷：空段三来源在此统一拦截
            cur.clear();
        };
        for (string& w : words) {
            cur.clear();
            for (char c : w) {
                if (c == separator) flush();
                else cur.push_back(c);
            }
            flush();                                 // 尾冲刷：无分隔符的整段靠它入结果
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def splitWordsBySeparator(self, words: List[str], separator: str) -> List[str]:
        return [seg for w in words for seg in w.split(separator) if seg]
```

> 💡 两版对照：C++ 手写「累积 + 冲刷」把判空显式化；Python 一行列表推导里 `if seg` 就是全部的判空逻辑——`split(sep)` 帮你切好刀，但**不会**帮你丢空段（无参 `split()` 才会丢空白段），这一个 `if` 就是本题与「签到 AC」之间的全部距离。

## 8. 边界情况与易错点

1. **空段三来源**（本题唯一考点）：首分隔符、尾分隔符、连续分隔符——统一用「判空冲刷」/ `if seg` 拦截，**不要**为每种来源写 if 特判（多分支 = 多出错面）。
2. **Python `split` 语义**：带显式分隔符时**保留空段**（`"|||".split("|") == ['', '', '', '']`），与无参 `split()` 自动丢空白的行为不同——漏写 `if seg` 在示例 2/3 上必错。
3. **C++ `getline` 行为差异**：连续分隔符产生空 `seg`；末尾分隔符不产生额外空段（EOF 即止）——但「判空」写法对两种行为统一正确，无需关心差异。
4. **尾冲刷不能漏**：手写扫描在 `word` 结束后必须再冲刷一次，否则**无分隔符的 word（如示例 1 的 `"six"`）整段丢失**。
5. **别用 `strtok`**：原地改写输入串（把分隔符替换成 `\0`）、依赖静态缓冲不可重入——即使碰巧对，也是坏习惯。
6. **顺序性**：必须收集完 $\text{words}[i]$ 的全部段再处理 $\text{words}[i+1]$，双层循环天然保序，无需显式管理。
7. **性能 / 溢出**：总长 $\le 2000$，任何正确写法都瞬时完成——Q1 的目标是两分钟内零 WA，把时间留给 Q3/Q4。
