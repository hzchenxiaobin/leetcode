# LeetCode 长度递增组的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：长度递增组的最大数目（#2790，hard）
- **链接**：https://leetcode.cn/problems/maximum-number-of-groups-with-increasing-length/
- **来源**：LeetCode 第 355 场周赛 Q3
- **难度**：困难
- **标签**：贪心、排序、数学

**题意**：给定数组 `usageLimits`，其中 `usageLimits[i]` 表示数字 $i$ 在所有组中最多能使用的次数。创建若干组时需满足：

1. 同一组中的数字互不相同；
2. 数字 $i$ 的总使用次数不超过 `usageLimits[i]`；
3. 从第二组开始，每组长度都严格大于前一组。

求最多能创建多少组。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{usageLimits}[i] \le 10^9$

> 💡 把每个数字看成一种有使用上限的资源。除了“总资源是否足够”，还要考虑“资源是否足够分散”：最后一组若有 $k$ 个位置，就必须找到 $k$ 种不同的数字。

## 2. 示例

**示例 1**

```text
输入：usageLimits = [1,2,5]
输出：3
解释：可以创建 [2]、[1,2]、[0,1,2]。
      数字 0、1、2 分别使用 1、2、3 次，均未超过上限。
```

**示例 2**

```text
输入：usageLimits = [2,1,2]
输出：2
解释：可以创建 [0]、[1,2]，总使用次数只有 5，不足以再创建长度至少为 3 的第三组。
```

**补充示例（总配额够，仍然不可行）**

```text
输入：usageLimits = [1,1,5,5]
输出：3
解释：总和为 12，似乎足够创建长度 1、2、3、4 的四组（共需 10 个位置）。
      但第四组必须用完四种数字，两个上限为 1 的数字随之耗尽；
      剩余三组只能使用另外两种数字，连长度为 3 的组都无法组成。
```

## 3. 解题思路

### 3.1 先把组长度规范化为 $1,2,\dots,k$

假设已经能创建 $k$ 组，长度依次为

$$l_1<l_2<\cdots<l_k.$$

因为它们都是正整数，所以必有 $l_i\ge i$，总位置数至少为

$$1+2+\cdots+k=\frac{k(k+1)}2.$$

更重要的是，多出来的位置没有价值：把第 $i$ 组任意删到只剩 $i$ 个数字，不会增加任何数字的使用次数，也不会破坏组内互不相同的条件。

因此：

> **能创建 $k$ 组，当且仅当能创建长度恰好为 $1,2,\dots,k$ 的 $k$ 组。**

接下来只需研究这种最省资源的“阶梯形”方案。

### 3.2 总配额条件必要，但不充分

创建 $k$ 组至少需要三角数

$$T_k=\frac{k(k+1)}2$$

次数字使用，所以必须有 $\sum_i\text{usageLimits}[i]\ge T_k$。

但补充示例 `[1,1,5,5]` 表明，这个条件并不充分：大配额数字不能在同一组重复使用，两个小配额数字又无法参与很多组。因此不能直接对“总和能覆盖几个三角数”做除法或二分，还必须处理不同数字之间的配合。

### 3.3 核心贪心：升序累计，跨过下一个三角数就解锁一组

将配额从小到大排序，维护：

- `total`：已经处理的配额总和；
- `ans`：目前已经能创建的组数。

依次处理每个配额 $v$：

1. 执行 `total += v`；
2. 如果 `total >= T(ans + 1)`，就执行 `ans += 1`；
3. 否则保持 `ans` 不变。

每个元素至多解锁一组。扫描结束后的 `ans` 就是答案。

> 💡 **为什么升序？** 小配额数字能参与的组数少，是方案的瓶颈，必须先让它们暴露出来。大配额数字虽然能补足总使用次数，却不能掩盖前面“小配额不足、数字种类配合不上”的问题。排序后，前若干项恰好构成当前最受限的一组资源。

### 3.4 示例演算

对于 `usageLimits = [1,2,5]`，排序后仍为 `[1,2,5]`：

| 当前配额 | total | 下一组所需阈值 | 是否解锁 | ans |
|---|---:|---:|---|---:|
| 1 | 1 | $T_1=1$ | 是 | 1 |
| 2 | 3 | $T_2=3$ | 是 | 2 |
| 5 | 8 | $T_3=6$ | 是 | 3 |

最终返回 $3$。

对于补充示例 `[1,1,5,5]`：

| 当前配额 | total | 下一组所需阈值 | 是否解锁 | ans |
|---|---:|---:|---|---:|
| 1 | 1 | $T_1=1$ | 是 | 1 |
| 1 | 2 | $T_2=3$ | 否 | 1 |
| 5 | 7 | $T_2=3$ | 是 | 2 |
| 5 | 12 | $T_3=6$ | 是 | 3 |

最终返回 $3$。第二次处理小配额时没有解锁，正体现了总配额之外的限制。

## 4. 算法细节

1. **必须升序排序**：小配额是瓶颈，不能换降序。
2. **每轮只检查下一个三角数**：已有 `ans` 组时，目标是第 `ans + 1` 组，其总位置数阈值是

   $$T_{ans+1}=\frac{(ans+1)(ans+2)}2.$$

3. **使用 `if`，不能使用 `while`**：每加入一种数字，最多让可行组数增加一。若在大配额元素上用 `while` 连续解锁，就会绕过“每种数字在一组中只能出现一次”的限制。例如 `[100]` 只能创建一组，而不能凭总配额创建很多组。
4. **无需真的构造各组**：扫描过程是在判定最大可行组数，不需要记录每组具体包含哪些数字。
5. **使用 64 位整数**：总配额最大为 $10^{14}$，而 $ans$ 接近 $10^5$ 时三角数也超过 32 位整数范围。C++ 中 `total` 和阈值乘法都应使用 `long long`。

## 5. 正确性证明

**引理 1（长度规范化）**：$k$ 组可行，当且仅当长度为 $1,2,\dots,k$ 的 $k$ 组可行。

**证明**：必要性显然。若任意 $k$ 组可行，其严格递增的正整数长度满足 $l_i\ge i$；将第 $i$ 组删到只剩 $i$ 个数字，所得方案仍满足组内互异和配额上限，因此长度为 $1,2,\dots,k$ 的方案也可行。∎

**引理 2（加入一种数字，组数至多增加一）**：若当前数字集合最多能创建 $k$ 组，加入一种新数字后最多能创建 $k+1$ 组。

**证明**：从新方案的所有组中删除这个新数字。每组长度至多减少 1，所以剩余非空组的长度仍严格递增；若原第一组只有这个新数字，则删去该空组。于是旧数字集合至少能创建 $K-1$ 组，其中 $K$ 是新方案的组数。由旧方案最多为 $k$ 组，得 $K-1\le k$，即 $K\le k+1$。∎

下面说明累计阈值为什么不仅检查了总和，也保留了组内互异的约束。

对一组配额 $a_i$，记

$$F_r=\sum_i\min(a_i,r).$$

要创建长度 $1,\dots,k$ 的 $k$ 组，一个等价的可行性条件是：对每个 $1\le r\le k$，都有

$$F_r\ge (k-r+1)+(k-r+2)+\cdots+k.$$

原因是：任取最大的 $r$ 组，每种数字在这 $r$ 组中至多出现 $\min(a_i,r)$ 次，所以左边是这些组能获得的最多资源，右边是它们所需的位置数；该条件对最大若干组成立也是二分图度序列可行性的标准判定（Gale–Ryser 条件），其他列组合不会比“最大的 $r$ 组”更紧张。

**定理（贪心正确性）**：按升序扫描配额，每当累计和不小于 $T_{ans+1}$ 时令 `ans` 加一，最终得到最大可行组数。

**证明**：对扫描过的数字个数归纳。假设处理新数字 $v$ 前，`ans = k` 已是最大可行组数。由于配额升序，$v$ 不小于任何已处理配额。

- 若加入 $v$ 后 $k+1$ 组可行，由引理 1，总使用次数至少为 $T_{k+1}$，所以累计和必达到阈值，算法会解锁第 $k+1$ 组。
- 若累计和达到 $T_{k+1}$，可以用上述可行性条件验证 $k+1$ 组确实可行。对于任意 $1\le r\le k+1$：
  - 若 $v<r$，所有已处理配额也都小于 $r$，于是 $F_r$ 就等于全部配额总和，不小于 $T_{k+1}$，自然覆盖最大 $r$ 组的需求；
  - 若 $v\ge r$ 且 $r\le k$，新数字给 $F_r$ 增加 $r$；旧的 $k$ 组可行性已经保证原条件成立，而新方案最大 $r$ 组的需求恰比原来增加 $r$；
  - 若 $r=k+1$ 且 $v\ge r$，新数字单独贡献 $k+1$，旧条件已保证 $F_k\ge T_k$，而新增需求恰好也是 $k+1$。

  因此所有条件成立，$k+1$ 组可行。

两种情况下算法都会把答案更新为新的最优值；由引理 2，最优值又不可能一次增加超过一。归纳成立，扫描结束即得全局最大组数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n\log n)$。排序耗时 $O(n\log n)$，随后只进行一次 $O(n)$ 扫描。
- **空间复杂度**：不计排序所用空间为 $O(1)$，只维护 `total` 和 `ans`。若计入排序，C++ 通常为 $O(\log n)$ 栈空间，Python 的 Timsort 需要 $O(n)$ 辅助空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxIncreasingGroups(vector<int>& usageLimits) {
        sort(usageLimits.begin(), usageLimits.end());
        long long total = 0;
        int ans = 0;
        for (int v : usageLimits) {
            total += v;
            long long need = 1LL * (ans + 1) * (ans + 2) / 2;
            if (total >= need) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxIncreasingGroups(self, usageLimits: List[int]) -> int:
        usageLimits.sort()
        total = ans = 0
        for v in usageLimits:
            total += v
            if total >= (ans + 1) * (ans + 2) // 2:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **不能只检查最终总和**：`[1,1,5,5]` 的总和足够四组，但最多只能创建三组。
2. **不能直接按 $n$ 判定**：$n\ge k$ 只保证有 $k$ 种数字，不保证配额能填满所有组。
3. **不要用 `while` 连跨多个三角数**：一种新数字至多使组数增加一；`[100]` 的答案只能是 1。
4. **不要降序处理**：大配额先累计会过早跨过阈值，掩盖小配额造成的瓶颈。
5. **严格递增的最省形态是 $1,2,\dots,k$**：不能误设为 $0,1,\dots,k-1$，组长度从 1 开始。
6. **$n=1$**：无论配额多大都只能创建一组，因为第二组至少需要两种不同的数字；算法首轮解锁一组，之后没有元素可继续解锁。
7. **整数溢出**：C++ 写成 `1LL * (ans + 1) * (ans + 2) / 2`，避免先以 `int` 完成乘法。
