# LeetCode 合并后数组中的最大元素 题解

## 1. 题目概述

- **标题 / 题号**：合并后数组中的最大元素（#2789，medium）
- **链接**：https://leetcode.cn/problems/largest-element-in-an-array-after-merge-operations/
- **来源**：LeetCode 第 355 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定下标从 0 开始、由**正整数**组成的数组 $\text{nums}$。一次操作：选中满足 $0 \le i < n-1$ 且 $\text{nums}[i] \le \text{nums}[i+1]$ 的下标 $i$，把 $\text{nums}[i]$ **并入** $\text{nums}[i+1]$（后者变为两值之和），并删除 $\text{nums}[i]$。操作可执行**任意次**（含 $0$ 次），求最终数组中能出现的**最大元素**。

**约束**：

- $1 \le n \le 10^5$
- $1 \le \text{nums}[i] \le 10^6$

> 💡 赛场切入三句话：① 操作语义 =「右吃左」，**值只向右流动**；② 全正数 ⟹ 合并只会让右值变大，吞并能力只增不减；③ 于是「最大元素」必是某段**连续区间的和**——从右往左一趟贪心直接出答案。另外 $n \cdot \max(\text{nums}) \approx 10^{11}$，C++ 第一反应就上 `long long`。

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,7,9,3]
输出：21
解释：i=0 → [5,7,9,3]；i=1 → [5,16,3]；i=0 → [21,3]。
最终最大元素 21 = 2+3+7+9（前四项之和）——末尾那个 3 帮不上忙：
9 无法并入它（9 > 3），它也永远没机会并进左边的块。
```

**示例 2**

```text
输入：nums = [5,3,3]
输出：11
解释：i=1 → [5,6]；i=0 → [11]。注意 3 ≤ 3 相等也允许合并。
```

**补充示例（自构造，覆盖「重置」分支）**

```text
输入：nums = [1,100,1]
输出：101
解释：中间的 100 无法并入右边的 1（100 > 1，而右侧块的值上界只有 1）
      → 100 只能自立门户；左边的 1 ≤ 100 可并入 → [101,1]，
      101 > 1 无法再吞 → 返回 101。
```

## 3. 解题思路

### 3.1 暴力思路

三条朴素路线，全部卡在复杂度或正确性上：

- **枚举操作序列**：每步可选项最多 $O(n)$ 个、操作链长可达 $O(n)$，状态空间指数级，$n = 10^5$ 直接爆炸；
- **正向多轮扫描**：从左到右「能并就并」，扫完一轮再来一轮直到不动——单轮 $O(n)$，但合并可能逐轮「解锁」（先并出右边的 $5$，才能吞下左边的 $2$），最坏需 $O(n)$ 轮，总计 $O(n^2) \approx 10^{10}$，超时；且「扫到不动即最优」并不显然，正确性难证；
- **区间 DP**：记 $f(l, r)$ =「段 $[l..r]$ 能否合成一个元素」，枚举分割点判定 $O(n^3)$——把可合并性判清楚后还要枚举所有段取最大和，$n = 10^5$ 完全不可行。

瓶颈在于：**缺一个「段级」的单调结构**把二维的段信息压成一维递推。

### 3.2 核心观察：右吃左 + 全正数 ⟹ 从右往左一趟

![核心观察：值只能向右流，从右往左维护吞并者的成长值 cur](images/wc355_q2_merge_concept.svg)

三个环环相扣的观察：

1. **方向固定**：操作是「右吃左」，一个元素的归宿永远在它右侧——任何操作序列结束后，每个剩余元素恰好等于原数组某**连续段**的和（§5 引理 1）。目标于是变成：**找和最大的可合并连续段**。
2. **全正数**：合并只会让右值变大，**吞并能力只增不减**——把右块做大永远不亏，因为更大的右块只会让左边来者更容易被吞下。
3. **从右往左递推**：设 $R(i)$ = 「以 $i$ **开头**的可合并段能达到的最大和」。考察 $\text{nums}[i]$ 能不能接到以 $i+1$ 开头的最优段上：
   - $\text{nums}[i] \le R(i+1)$：能接——接上后 $R(i) = \text{nums}[i] + R(i+1)$；
   - $\text{nums}[i] > R(i+1)$：**永远接不上**。$i$ 右侧任何时刻的邻居元素，其值都不会超过 $R(i+1)$（它只能是某个以 $i+1$ 开头的段合出来的），所以 $\text{nums}[i]$ 在**任何策略**下都无法向右合并，只能自立门户，$R(i) = \text{nums}[i]$。

   这正是扫描中的两个分支：**吸收**与**重置**。

最后一步点睛：**cur 每步严格递增**（吸收时加上正数；重置时新值本来就该大于旧 cur），所以历史 cur 不必记录——**扫描结束时的 cur 就是全程最大值**，一趟 $O(n)$ 收工。

### 3.3 算法流程

![算法流程：一趟从右往左，吸收或重置二选一](images/wc355_q2_merge_flow.svg)

1. $\text{cur} \gets \text{nums}[n-1]$（最右元素自成一个块）；
2. $i$ 从 $n-2$ 往左走到 $0$，每步二选一：
   - 若 $\text{nums}[i] \le \text{cur}$：$\text{cur} \gets \text{cur} + \text{nums}[i]$（吸收，块向左长一格）；
   - 否则：$\text{cur} \gets \text{nums}[i]$（重置，新块从 $i$ 开始）；
3. 扫描结束，返回 $\text{cur}$。

### 3.4 示例演算

![示例演算：[2,3,7,9,3] 从右往左 cur 一路涨到 21](images/wc355_q2_merge_walkthrough.svg)

以示例 1 $\text{nums} = [2,3,7,9,3]$ 走查（「块」记当前 cur 对应的下标集合）：

| 步骤 | 比较 | 动作 | cur | 块 |
|------|------|------|-----|-----|
| 初始 | — | cur = nums[4] | 3 | {3}（下标 4） |
| i=3 | 9 vs 3 | 9 > 3：吞不下 → **重置** | 9 | {9} |
| i=2 | 7 vs 9 | 7 ≤ 9：吸收 | 16 | {7,9} |
| i=1 | 3 vs 16 | 3 ≤ 16：吸收 | 19 | {3,7,9} |
| i=0 | 2 vs 19 | 2 ≤ 19：吸收 | 21 | {2,3,7,9} |
| 返回 | — | cur 单调递增，终值即答案 | **21** | {2,3,7,9} |

注意第一步就把**末尾的 3 遗弃**了（$9 > 3$ 触发重置），最终块恰是前四项，和 $21$ 与官方输出一致。示例 2 $[5,3,3]$：$\text{cur} = 3 \to 6 \to 11$，返回 $11$ ✓。

## 4. 算法细节

1. **cur 的语义**：以当前下标右侧一格**开头**的可合并段的最大和——不是「后缀和」，而是**受可合并约束**的段和，两者在 $[2,3,7,9,3]$ 上就不同（后缀和到 $i=0$ 是 $24$，cur 只有 $21$）。
2. **初始化** $\text{cur} = \text{nums}[n-1]$：以 $n-1$ 开头的段只有它自己，天然覆盖 $n=1$ 的边界（循环不执行，直接返回）。
3. **两个分支压成一句**：`cur = nums[i] <= cur ? cur + nums[i] : nums[i];`——先比较后赋值，无分支爆炸。
4. **不需要 ans 变量**：由单调性（§5 推论），每步 cur 都严格大于上一步，终值即 $\max_i R(i)$。保守起见写 `ans = max(ans, cur)` 也对，但多余。
5. **等价的原地写法**：`for i in n-2..0: if nums[i] <= nums[i+1]: nums[i] += nums[i+1]`，最后 `return max(nums)`。循环不变式是「处理后 $\text{nums}[i] = R(i)$」——与 cur 版完全等价，代价是改写输入、多一次 `max`。
6. **语言细节**：C++ 返回类型与 cur 都必须是 `long long`；Python 的 `int` 无界，直接写。

## 5. 正确性证明

**引理 1（终态刻画）**：任何操作序列结束后，每个剩余元素恰好等于原数组某个连续段的和，且全体剩余元素对应 $[0, n-1]$ 的一个连续划分。

**证明**：对操作次数归纳，维护不变式「每个当前元素 = 某连续段之和，各段按序构成原数组的划分」。初始时每段为单元素，成立。一次操作删除段 $[a..i]$ 的元素、把其值加进右邻段 $[i+1..b]$，两段拼成 $[a..b]$，仍连续、仍构成划分。不变式保持。∎

**引理 2（可合并段的递归刻画）**：称段 $[l..r]$ **可合并**，若存在只涉及段内元素的操作序列把它合成一个元素（段外元素的存亡不影响段内的判定）。则 $[l..r]$ 可合并 $\iff$ $l = r$，或存在 $m \in [l, r-1]$ 使 $[l..m]$、$[m+1..r]$ 均可合并且 $S(l..m) \le S(m+1..r)$（$S$ 为段和）。且只要可合并，合成后的值恒为 $S(l..r)$。

**证明**：（$\Leftarrow$）先把 $[l..m]$ 内部合成单元素（合法性只依赖段内相邻关系与值），再把 $[m+1..r]$ 合成单元素，两者此刻相邻、值分别为 $S(l..m)$、$S(m+1..r)$，末次合并条件满足。（$\Rightarrow$）最后一次合并必是把两个相邻元素（各为子段 $[l..m]$、$[m+1..r]$ 合成的，归纳可知值 = 段和）合并，操作合法要求 $S(l..m) \le S(m+1..r)$，且两子段各自可合并。合并是「左值加进右值」，故合成值恒为段内元素之和。∎

**引理 3（左端可去）**：若 $[l..r]$ 可合并且 $l < r$，则 $[l+1..r]$ 也可合并。

**证明**：对 $r - l$ 归纳。取引理 2 中的分割点 $m$。若 $m = l$，则 $[l+1..r]$ 本身就是那个可合并的右段。若 $m > l$：$[l..m]$ 可合并且更短，由归纳假设 $[l+1..m]$ 可合并；又因元素全正，

$$S(l+1..m) \le S(l..m) \le S(m+1..r),$$

对 $[l+1..r]$ 以分割点 $m$ 应用引理 2 即得可合并。∎

**定义**：$R(i) := \max \{\, S(i..t) : t \ge i,\ [i..t] \text{ 可合并} \,\}$，即以 $i$ 开头的可合并段的最大和。

**引理 4（R 的贪心递推）**：

$$R(i) = \begin{cases} \text{nums}[i] + R(i+1), & \text{nums}[i] \le R(i+1) \\ \text{nums}[i], & \text{nums}[i] > R(i+1) \end{cases}$$

**证明**：

- 若 $\text{nums}[i] \le R(i+1)$：取 $t^*$ 使 $[i+1..t^*]$ 可合并且 $S(i+1..t^*) = R(i+1)$。对 $[i..t^*]$ 以分割点 $m = i$ 应用引理 2——左段 $[i..i]$ 平凡可合并，$S(i..i) = \text{nums}[i] \le R(i+1) = S(i+1..t^*)$——故 $[i..t^*]$ 可合并，$R(i) \ge \text{nums}[i] + R(i+1)$。反向：任何 $t > i$ 的可合并段 $[i..t]$，由引理 3 知 $[i+1..t]$ 可合并，故 $S(i..t) = \text{nums}[i] + S(i+1..t) \le \text{nums}[i] + R(i+1)$；$t = i$ 时 $S = \text{nums}[i] < \text{nums}[i] + R(i+1)$（正数）。两头夹逼得等号。
- 若 $\text{nums}[i] > R(i+1)$：反设存在 $t > i$ 使 $[i..t]$ 可合并，取引理 2 的分割点 $m \in [i, t-1]$。由正数性与 $m \ge i$：

$$S(i..m) \ge \text{nums}[i] > R(i+1) \ge S(i+1..t) \ge S(m+1..t),$$

与合并条件 $S(i..m) \le S(m+1..t)$ 矛盾。故以 $i$ 开头的可合并段只有 $[i..i]$，$R(i) = \text{nums}[i]$。∎

**定理（贪心最优性）**：答案 $= \max_{0 \le i < n} R(i)$，恰等于一趟从右往左扫描的最终 cur。

**证明**：由引理 1，最终数组的每个元素都是某可合并段的和；反之，任一可合并段都可独立合成一个元素（引理 2 的构造不依赖段外，其余元素保持原样即可）。故答案 = 所有可合并段和的最大值 $= \max_i R(i)$（每个段以某 $i$ 开头，且 $R(i)$ 由定义取到）。扫描中处理完下标 $i$ 后 $\text{cur} = R(i)$：$i = n-1$ 时 $R(n-1) = \text{nums}[n-1]$（唯一段）；往左每步由引理 4 的递推与代码分支一一对应，归纳成立。∎

**推论（cur 单调性）**：扫描中 cur 每步严格增大，故最终 cur $= \max_i R(i)$，代码无需显式取最大值。

**证明**：吸收分支 $\text{cur} \mathrel{+}= \text{nums}[i] \ge \text{cur} + 1$；重置分支的触发条件即 $\text{nums}[i] > \text{cur}$，新 cur 更大。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。从右往左单趟扫描，每个元素一次比较、至多一次加法与赋值，无排序、无回溯、无第二遍。
- **空间复杂度**：$O(1)$ 额外空间——仅一个累加器 cur（原地变体也只改写输入数组本身，额外空间仍 $O(1)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxArrayValue(vector<int>& nums) {
        long long cur = nums.back();                 // 最右元素自立门户
        for (int i = (int)nums.size() - 2; i >= 0; --i) {
            if (nums[i] <= cur) cur += nums[i];      // 吸收：块向左长一格
            else                cur  = nums[i];      // 重置：永远吞不下，自立门户
        }
        return cur;                                  // cur 单调递增，终值即最大
    }
};
```

### Python

```python
class Solution:
    def maxArrayValue(self, nums: List[int]) -> int:
        cur = nums[-1]
        for i in range(len(nums) - 2, -1, -1):
            cur = cur + nums[i] if nums[i] <= cur else nums[i]
        return cur
```

> 💡 两版对照：整台机器只有一句三目表达式。**重置分支**是本题的灵魂——它看起来像「丢掉了辛苦攒的 cur」，但正数性保证丢的时候新值必大于旧值（推论），所以「丢」而不损。漏写重置分支（见 §8 第 4 条）在示例 1 上就会翻车。

## 8. 边界情况与易错点

1. **C++ 溢出**：$\sum \text{nums}[i] \le 10^5 \times 10^6 = 10^{11} \approx 2^{37}$，远超 `int`。cur 与返回值都必须是 `long long`（返回类型本来就是），先用 `int` 累加再转就晚了。
2. **n = 1**：循环不执行，cur = nums[0] 直接返回——初始化天然覆盖，无需特判。
3. **方向陷阱（本题最大坑）**：从左往右一趟不回头会错。反例 $[2,1,4]$：正向扫 $i=0$（$2>1$ 跳过）、$i=1$（$1 \le 4$ 合并成 $[2,5]$）后若无第二轮，只能得 $5$；正解 $7$（先并 $[1,4]$ 再吞 $2$）。**信息必须从右往左流**——一个元素能否被吞，取决于它右侧能长多大，而右侧的潜力只有从右往左扫才能先算出来。
4. **重置分支不能省**：只写吸收分支（贪心小就一路小）在 $[2,3,7,9,3]$ 上得到 $8$（$3 \to 6 \to 8$），漏掉 $21$。重置的合法性由单调性推论兜底。
5. **≤ 不是 <**：操作条件与吸收判定都是「小于等于」，相等也允许合并（示例 2 的 $3 \le 3$）。写成 `<` 会丢解。
6. **「任意次」含 0 次**：全不操作时答案 $= \max(\text{nums})$。本算法无需特判——$R(i) \ge \text{nums}[i]$ 恒成立，且 cur 终值 $\ge \max_i \text{nums}[i]$。
7. **别把 cur 当后缀和**：cur 是「受可合并约束的段和」，$[2,3,7,9,3]$ 的后缀和最大 $24$，但末尾 $3$ 吞不进左块，cur 封顶 $21$。
8. **不需要真的模拟删除**：返回的是数值，不是数组；中途无需维护数组状态（原地变体只是顺手，不是必需）。
