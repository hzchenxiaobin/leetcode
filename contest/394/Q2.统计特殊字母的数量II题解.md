# LeetCode 统计特殊字母的数量 II 题解

## 1. 题目概述

- **标题 / 题号**：统计特殊字母的数量 II（#3121，medium）
- **链接**：https://leetcode.cn/problems/count-the-number-of-special-characters-ii/
- **来源**：LeetCode 第 394 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串

**题意**：给定字符串 `word`（只含大小写英文字母）。若字母 `c` 的小写形式和大写形式**都在** `word` 中出现过，并且**每个**小写形式的 `c` 都出现在**第一个**大写形式的 `c` 之前，则称 `c` 为**特殊字母**。返回特殊字母的数量。

**约束**：

- $1 \le word.length \le 2 \times 10^5$
- `word` 仅由小写和大写英文字母组成

> 💡 读题关键：Q1 埋下的伏笔在此兑现——两张 26 位「出勤表」只记得「来没来过」，本题追问「**先来还是后到**」。两个细节值得圈出来：其一，顺序锚点是「**第一个**大写」，大写自己出现多少次无关紧要；其二，计数的单位仍是 26 个**字母**而非 52 个字符。$n$ 放大到 $2 \times 10^5$ 只是逼你放弃反复全串扫描，真正的考点是把「每个小写都要核对」这句直觉压缩成**一次比较**。

## 2. 示例

**示例 1**

```text
输入：word = "aaAbcBC"
输出：3
解释：特殊字母是 'a'、'b' 和 'c'。
```

**示例 2**

```text
输入：word = "abc"
输出：0
解释：word 中不存在特殊字母（任何大写形式都缺席）。
```

**示例 3**

```text
输入：word = "AbBCab"
输出：0
解释：word 中不存在特殊字母。
```

## 3. 解题思路

### 3.1 暴力思路

沿袭 Q1 的「点名」框架，只是每个字母要查的档案变厚了：先找到首个大写的下标 $F$，再逐一核对**每个**小写的下标是否都小于 $F$。

```python
from string import ascii_lowercase

ans = 0
for ch in ascii_lowercase:
    U = ch.upper()
    if ch in word and U in word:                    # 双形态在场
        fu = word.index(U)                          # 首个大写下标
        if all(i < fu for i, c in enumerate(word) if c == ch):
            ans += 1                                # 每个小写都在其前
```

26 个字母各把全串扫上数遍，$O(26n)$ 次字符比较在 $n = 2 \times 10^5$ 时约五百万级，能过但毫无体面。更致命的是另一个方向：把 Q1 的位掩码出勤表直接搬来交——**WA**。位掩码每个二进制位只承载 1 bit 的**存在性**信息，而本题的顺序约束需要「谁先谁后」的**位置**信息，工具的表达能力从根上就不够。

真正值得在意的是思路层面的浪费：**「每个小写都小于 $F$」这句话看起来要枚举所有小写位置，实际上只有最靠右的那个小写有发言权**——只要它没越过 $F$，比它更靠左的同伴自然全体安全；反过来只要有任何一个小写越界，「最靠右」必然也在越界者之列。把「检查全体」换成「检查极端」，就是本题的全部优化空间。

### 3.2 核心观察：末个小写 vs 首个大写，两个极端位置定乾坤

![核心概念：每个字母只看末个小写与首个大写两个极端位置](images/special_chars_ii_concept.svg)

对每个字母 `c` 只需维护两个下标：

- **`lastLower[c]`**：字母 `c` 的**最后一个小写**出现的下标（缺席记 $-1$）；
- **`firstUpper[c]`**：字母 `c` 的**第一个大写**出现的下标（缺席记 $n$，顶替 $+\infty$）。

判定条件收敛为一行链式不等式：

$$-1 \;<\; \text{lastLower}[c] \;<\; \text{firstUpper}[c] \;<\; n$$

三个片段各司其职：$-1 < \text{lastLower}$ 说的是**小写在场**；$\text{firstUpper} < n$ 说的是**大写在场**（缺席时它恰是哨兵 $n$）；夹在中间的 $\text{lastLower} < \text{firstUpper}$ 说的才是**次序**。正确性两端各一句话：

- **充分性**：全体小写的下标都 $\le \text{lastLower}[c]$，若末小写都已排在首大写之前，则全体小写都在首个大写之前；
- **必要性**：若存在某个小写越界（下标 $\ge \text{firstUpper}[c]$），则 $\text{lastLower}[c] \ge$ 该下标 $\ge \text{firstUpper}[c]$，判定式必然不成立。

> 💡 这是「**用极端元素代表全体**」的经典手法：判定「全体满足某性质」时，往往只需盯住最可能违反性质的那一个元素（这里是最晚的小写与最早的大写）。它与 3. 无重复字符的最长子串用「最近一次出现位置」收缩窗口、387. 字符串中的第一个唯一字符用「首现位置 + 计数」是同一族思想——**哈希表里存位置，而不只是存存在性**。

维护也极其省事：一趟扫描，遇到小写就**覆盖式**更新 `lastLower`（天然留下最后一个）；遇到大写只在**更早**时更新 `firstUpper`（`min` 语义，天然留下第一个）。Q1 的两张出勤表在这里彻底退役，**存在性语义必须升级为位置（顺序）语义**。

### 3.3 算法流程

![算法流程：一趟扫描维护两张位置表，收尾 26 次链式判定](images/special_chars_ii_flow.svg)

流程分两幕：**第一幕一趟扫描**，按形态把下标分流进两张位置表（小写覆盖式、大写取 min）；**第二幕收尾判定**，对 26 个字母各做一次链式比较，通过则计数。

### 3.4 示例演算

![示例演算：三个示例的逐字母极端位置判定](images/special_chars_ii_walkthrough.svg)

| 输入 | a（末小 / 首大） | b（末小 / 首大） | c（末小 / 首大） | 答案 |
|------|------------------|------------------|------------------|------|
| `"aaAbcBC"` | 1 / 2 ✓ | 3 / 5 ✓ | 4 / 6 ✓ | **3** |
| `"abc"` | 0 / n ✗ | 1 / n ✗ | 2 / n ✗ | **0** |
| `"AbBCab"` | 4 / 0 ✗ | 5 / 2 ✗ | −1 / 3 ✗ | **0** |

（表中 `n` 是首大写的缺席哨兵，代表 $+\infty$）

三个示例各踩一个点：示例 1 三字母全员达标；示例 2 是「首大写缺席」的平凡情形；示例 3 `"AbBCab"` 才是官方给的「劝退」样例——三个字母演示了三种死法：`a`、`b` 的**末小写越过了首大写**（顺序违规），`c` 则**小写压根缺席**（双形态不齐）。注意 `a` 的死因正是顺序约束：`'A'` 在下标 0 首先登场，尾部那个 `'a'`（下标 4）越过了首个大写。

## 4. 算法细节

1. **哨兵设计**：`lastLower` 缺席记 $-1$（天然小于一切合法下标），`firstUpper` 缺席记 $n$（天然大于一切合法下标）。用 $n$ 而非某个 magic 大数的好处：缺席判定就是 `firstUpper < n` 本身，不需要额外布尔标记。
2. **更新方式由扫描方向决定**：小写要**最后一个**，从左到右扫则后写覆盖先写（覆盖式）；大写要**第一个**，则只在更早出现时更新（`min` 语义）。若改成从右往左扫，两种更新方式恰好互换。
3. **链式比较一行三条件**：`-1 < lastLower < firstUpper < n` 同时编码「小写在场、次序达标、大写在场」，Python / Java 风格的链式写法最顺手；C++ 没有链式比较，需显式拆成两个 `&&`。
4. **统一取槽位**：用 $(\,c \mathbin{\&} 31\,) - 1$ 可从大小写字符直接取出同一字母序号 $0 \sim 25$（`'a'` 与 `'A'` 同槽），省掉两套偏移 `'a'` / `'A'`——注意 `&` 优先级低于减法，括号不能省。
5. **等价实现：违规标记状态机**。把判定从收尾搬到扫描途中——某字母一旦见过大写，之后又冒出小写，当场记为违规：

   ```python
   seen_lower = [False] * 26
   seen_upper = [False] * 26
   bad = [False] * 26
   for c in word:
       j = (ord(c) & 31) - 1                # 'a' 与 'A' 同槽
       if c.islower():
           if seen_upper[j]: bad[j] = True  # 首个大写之后又来小写 → 违规
           seen_lower[j] = True
       else:
           seen_upper[j] = True
   ans = sum(l and u and not b for l, u, b in zip(seen_lower, seen_upper, bad))
   ```

   正确性一句话：`bad[c]` 被置位 $\iff$ 存在某个小写出现在某个大写之后 $\iff$ 存在小写不在首个大写之前。两版复杂度相同，前者像「先记账、收尾对账」，后者像「实时风控」，能互译才算真懂。

## 5. 正确性证明

**引理 1**（位置表不变量）：扫描完任意前缀 $word[0..i)$ 后，`lastLower[k]` 等于该前缀中最后一个字符 $\texttt{chr}(\texttt{'a'} + k)$ 的下标（未出现则为 $-1$）；`firstUpper[k]` 等于该前缀中第一个字符 $\texttt{chr}(\texttt{'A'} + k)$ 的下标（未出现则为 $n$）。

**证明**：对 $i$ 归纳。$i = 0$ 时两表为初始值 $-1$ 与 $n$，前缀为空，命题成立。设处理 $word[0..i)$ 后命题成立，考察第 $i$ 个字符 $c$：若 $c$ 为小写，记 $k = c - \texttt{'a'}$，执行 `lastLower[k] = i`——覆盖后 `lastLower[k]` 恰为前缀 $word[0..i+1)$ 中该小写的最后下标（$i$ 是最新且最大的下标），其余槽位与 `firstUpper` 不受影响，归纳假设维持；若 $c$ 为大写，记 $k = c - \texttt{'A'}$，仅当 $i < \text{firstUpper}[k]$ 时更新——更新后 `firstUpper[k]` 取「原首大写」与 $i$ 的较小者，仍是前缀中的第一个大写下标；缺席时由 $n$ 更新为 $i$（因 $i < n$），亦为首个。∎

**引理 2**（在场刻画）：字母 $k$ 的小写在场 $\iff -1 < \text{lastLower}[k]$；大写在场 $\iff \text{firstUpper}[k] < n$。

**证明**：取 $i = n$ 应用引理 1：`lastLower[k]` 为 $-1$ 当且仅当全串无该小写，否则为某个合法下标 $\ge 0$；`firstUpper[k]` 为 $n$ 当且仅当全串无该大写，否则为某个合法下标 $< n$。∎

**引理 3**（次序刻画）：设字母 $k$ 双形态均在场，则「每个小写都出现在第一个大写之前」$\iff \text{lastLower}[k] < \text{firstUpper}[k]$。

**证明**：（$\Rightarrow$）设首个大写下标为 $F = \text{firstUpper}[k]$。每个小写下标都 $< F$，特别地最晚者 $\text{lastLower}[k] < F$。（$\Leftarrow$）任取小写下标 $i$，则 $i \le \text{lastLower}[k] < \text{firstUpper}[k] = F$，即该小写出现在首个大写之前；由 $i$ 任意性，全体小写均在首个大写之前。∎

**定理**：算法返回值等于 `word` 中特殊字母的数量。

**证明**：字母 $k$ 是特殊字母，当且仅当「双形态在场」且「每个小写都在首个大写之前」。由引理 2，前者等价于 $-1 < \text{lastLower}[k]$ 且 $\text{firstUpper}[k] < n$；由引理 3（其前提「双在场」恰好由前者保证），后者等价于 $\text{lastLower}[k] < \text{firstUpper}[k]$。三段合并即链式判定 $-1 < \text{lastLower}[k] < \text{firstUpper}[k] < n$，算法对 26 个字母逐一检验并计数，故返回值即特殊字母数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。第一幕一趟扫描，每个字符一次 $O(1)$ 的判断与置位；第二幕 26 次常数级链式判定，总计与 $n$ 成线性。
- **空间复杂度**：$O(1)$。两张 26 槽位置表共 52 个整数，与 $n$ 无关。
- **答案规模**：$\le 26$，任何整型都装得下。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int numberOfSpecialChars(string word) {
        int n = word.size();
        vector<int> firstUpper(26, n);   // 首个大写下标，缺席记 n（视作 +∞）
        vector<int> lastLower(26, -1);   // 末个小写下标，缺席记 -1
        for (int i = 0; i < n; i++) {
            char c = word[i];
            if (c >= 'a') lastLower[c - 'a'] = i;   // 覆盖式：留最后一个
            else if (i < firstUpper[c - 'A'])       // min 语义：留第一个
                firstUpper[c - 'A'] = i;
        }
        int ans = 0;
        for (int c = 0; c < 26; c++)
            if (-1 < lastLower[c] && lastLower[c] < firstUpper[c] && firstUpper[c] < n)
                ans++;                               // 在场 ×2 + 次序，一式搞定
        return ans;
    }
};
```

### Python

```python
class Solution:
    def numberOfSpecialChars(self, word: str) -> int:
        n = len(word)
        first_upper = [n] * 26    # 首个大写下标（缺席记 n，视作 +∞）
        last_lower = [-1] * 26    # 末个小写下标（缺席记 -1）
        for i, c in enumerate(word):
            if c.islower():
                last_lower[ord(c) - 97] = i           # 覆盖式：留最后一个
            elif i < first_upper[ord(c) - 65]:
                first_upper[ord(c) - 65] = i          # min 语义：留第一个
        return sum(-1 < last_lower[c] < first_upper[c] < n for c in range(26))
```

## 8. 边界情况与易错点

1. **双缺席陷阱（本场最大 WA 源）**：只写中间段 `lastLower < firstUpper` 是不够的——从未露面的字母满足 $-1 < n$ 恒真，会被误判成特殊字母。必须补齐两端的存在性判定，链式三段一段都不能少。
2. **锚点是「第一个」大写**：大写出现多少次无关。`"aAbA"` 中 `A` 出现两次，`a` 的末小写 0 仍在首个大写 1 之前，字母 `a` 照样特殊；反之 `"aAa"` 中尾部的 `a`（下标 2）越过了首个大写（下标 1），直接出局。别把「每个大写都要在小写之后」当题意。
3. **别把 Q1 代码直接交**：位掩码只答「在场」不答「次序」，`"AbBCab"` 上 Q1 会数出 `a`（在场但越线），本题判 0。从 Q1 到 Q2 的跨越正是**存在性 → 顺序性**的语义升级。
4. **哨兵初值别乱取**：`firstUpper` 初始化成 $0$ 会把「大写缺席」误当成「在下标 0 出现」，`"abc"` 直接 WA。$-1$ 与 $n$ 的取值让缺席判定与不等式天然融合。
5. **C++ 无链式比较**：`a < b < c` 在 C++ 里是 `(a < b) < c` 的布尔比较，静默出错；必须写成 `a < b && b < c`。
6. **长度为 1**：单字符必为 0（另一形态必然缺席），算法无需特判。
7. **判大小写的前提**：`c >= 'a'` 依赖「输入纯英文字母」（$\texttt{'A'}..\texttt{'Z'}$ 全小于 $\texttt{'a'}$）；若放宽输入需改用 `islower`。
