# LeetCode 统计特殊字母的数量 I 题解

## 1. 题目概述

- **标题 / 题号**：统计特殊字母的数量 I（#3120，easy）
- **链接**：https://leetcode.cn/problems/count-the-number-of-special-characters-i/
- **来源**：LeetCode 第 394 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、位运算

**题意**：给定字符串 `word`（只含大小写英文字母）。若某个字母的小写形式和大写形式**都在** `word` 中出现过，则称该字母为**特殊字母**。返回特殊字母的数量。

**约束**：

- $1 \le word.length \le 50$
- `word` 仅由小写和大写英文字母组成

> 💡 读题关键：计数的单位是「**字母**」（26 个候选），不是「字符」（52 种形态）——同一字母的大小写无论出现多少次、以什么顺序出现，都只贡献一次。这是纯粹的**存在性**判定，与次数、位置统统无关。签到题的最短路径：把「来没来过」记下来，再对 26 个字母做配对点名。

## 2. 示例

**示例 1**

```text
输入：word = "aaAbcBC"
输出：3
解释：word 中的特殊字母是 'a'、'b' 和 'c'。
```

**示例 2**

```text
输入：word = "abc"
输出：0
解释：word 中不存在大小写形式同时出现的字母。
```

**示例 3**

```text
输入：word = "abBCab"
输出：1
解释：word 中唯一的特殊字母是 'b'。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的做法：先把字符丢进集合，再对 26 个字母逐个「点名」——小写在不在？大写在不在？

```python
s = set(word)
ans = sum(c in s and c.upper() in s for c in string.ascii_lowercase)
```

建集合 $O(n)$ + 26 次查询，$n \le 50$ 下毫无压力；甚至对每个字母线性扫两遍 `word`（$O(26n)$ 次比较）也能过。签到题写到这里就能提交，但有两个可以顺手「减负」的点：

- `set` 存的是 **52 种字符形态**，而要回答的问题只有 **26 个字母**——两种形态共享同一个字母下标，信息天然可以减半再配对；
- 哈希表每个键要占一个桶、做一次散列，而键域只是 26 个连续整数，一个 `int` 的 26 个二进制位就够当整张表用。

### 3.2 核心观察：两张 26 位「出勤表」，按位与后数 1

![核心概念：两种形态各记一张出勤表，交集大小即答案](images/special_chars_i_concept.svg)

把「是否出现过」拆成两张表：

- **lower 表**（26 位）：小写 `c` 出现 → 置第 $c - \texttt{'a'}$ 位；
- **upper 表**（26 位）：大写 `C` 出现 → 置第 $C - \texttt{'A'}$ 位。

由于 $\texttt{'a'} - \texttt{'a'} = \texttt{'A'} - \texttt{'A'} = 0$，**同一字母在两张表中的下标天然对齐**。于是：

$$\text{ans} = \operatorname{popcount}(\text{lower} \,\&\, \text{upper})$$

- 按位与 `&` 恰好是集合**交集**：只有两表都点过名的字母，对应位才是 1；
- `popcount`（数二进制 1 的个数）就是交集大小。

整个算法三步走：**一趟扫描置位 → 一次按位与 → 一次 popcount**。两张表各是一个 `int`，空间 $O(1)$，完全不在乎字符的顺序与重复。

> 💡 大小写的位运算彩蛋：$\texttt{'a'} = 97$ 与 $\texttt{'A'} = 65$ 恰好相差 $32 = 1 \ll 5$（仅第 5 位不同）。于是 `c ^ 32` 大小写互转、`c | 32` 归一为小写、`c & ~32` 归一为大写；更进一步，`c & 31` 直接取出字母序号，`(c >> 5) & 1` 区分形态（0 大写 / 1 小写）——连 if 分支都能省掉。

### 3.3 算法流程

![算法流程：一趟扫描置位，收尾 popcount(lower & upper)](images/special_chars_i_flow.svg)

流程只有三步：

1. `lower = upper = 0`；
2. 遍历 `word`：小写则 `lower |= 1 << (c - 'a')`，大写则 `upper |= 1 << (c - 'A')`；
3. 返回 `popcount(lower & upper)`。

### 3.4 示例演算

![示例演算：aaAbcBC 一趟扫描后两表求交](images/special_chars_i_walkthrough.svg)

| 输入 | lower 表 | upper 表 | 交集 | 答案 |
|------|----------|----------|------|------|
| `"aaAbcBC"` | $\{a,b,c\}$ | $\{a,b,c\}$ | $\{a,b,c\}$ | **3** |
| `"abc"` | $\{a,b,c\}$ | $\varnothing$ | $\varnothing$ | **0** |
| `"abBCab"` | $\{a,b\}$ | $\{b,c\}$ | $\{b\}$ | **1** |

三个示例各踩一个点：示例 1 两表内容完全一致，交集满员；示例 2 上表**整张空**，交集必空；示例 3 是「部分交集」——`a` 只有小写、`c` 只有大写，双双出局，只剩 `b` 一根独苗。

## 4. 算法细节

1. **下标对齐**：小写用 $c - \texttt{'a'}$、大写用 $c - \texttt{'A'}$ 归一化到 $[0, 26)$，同一字母落在两表的同一二进制位上，这是「按位与 = 求交集」成立的前提。
2. **置位幂等**：`|=` 只记录存在性，同一字符出现多次不会重复计数——天然处理「出现次数」，无需去重。
3. **收尾统计**：C++ 用 `__builtin_popcount`，Java 用 `Integer.bitCount`，Python 3.10+ 用 `int.bit_count()`（老版本 `bin(x).count('1')`）；手写则用 Brian Kernighan 技巧 `x &= x - 1` 每次消去最低位的 1。
4. **判大小写**：输入保证纯英文字母，`c >= 'a'` 足够（$\texttt{'A'}..\texttt{'Z'}$ 全都小于 $\texttt{'a'}$）；防御性写法是 `islower`。利用 3.2 的彩蛋还能写无分支版：`masks[c >> 5 & 1] |= 1 << ((c & 31) - 1);`（`masks[1]` 收小写、`masks[0]` 收大写）。
5. **等价实现**：两个 `bool seen[26]` 数组完全等价，位掩码只是键域连续时的常数优化；`set(word)` + 26 次配对查询的集合直译版语义最透明，比赛时先写对再优化即可。

## 5. 正确性证明

**引理 1**（出勤表不变量）：扫描完任意前缀 $word[0..i)$ 后，`lower` 的第 $k$ 位为 1，当且仅当前缀中出现过字符 $\texttt{chr}(\texttt{'a'} + k)$；`upper` 同理（对 $\texttt{chr}(\texttt{'A'} + k)$）。

**证明**：对 $i$ 归纳。$i = 0$ 时两表为 0，前缀为空，命题显然成立。设处理 $word[0..i)$ 后命题成立，考察第 $i$ 个字符 $c$：$c$ 必为小写或大写之一（输入约束），二者分支互斥且完备。若 $c$ 为小写，则 $k = c - \texttt{'a'}$，执行 `lower |= 1 << k` 后 `lower` 第 $k$ 位变 1，其余位不变——归纳假设保证其余位仍精确反映前缀 $word[0..i)$ 的出现情况，加上 $c$ 本身即前缀 $word[0..i+1)$；`upper` 未被触碰，仍精确。大写情形对称。∎

**引理 2**（特殊字母刻画）：字母 $\texttt{chr}(\texttt{'a'} + k)$ 是特殊字母，当且仅当 `lower` 与 `upper` 的第 $k$ 位同时为 1。

**证明**：由引理 1（取 $i = n$），`lower` 第 $k$ 位为 1 ⟺ 全串中出现过该字母的小写形式；`upper` 第 $k$ 位为 1 ⟺ 出现过大写形式。二者同时为 1 ⟺ 两种形式都出现过，即特殊字母的定义。∎

**定理**：算法返回 `popcount(lower & upper)` 等于 `word` 中特殊字母的数量。

**证明**：`lower & upper` 的第 $k$ 位为 1 ⟺ 两表的第 $k$ 位同时为 1，由引理 2 这恰是「第 $k$ 个字母是特殊字母」的指示变量。`popcount` 对 26 位求和，即特殊字母个数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描，每个字符做一次 $O(1)$ 判断与置位；收尾一次按位与 + popcount，仅 26 位，为 $O(1)$。
- **空间复杂度**：$O(1)$。两个 26 位 `int` 即全部状态；`set` 版为 $O(52)$，亦是常数。
- **答案规模**：$\le 26$，任何整型都装得下。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int numberOfSpecialChars(string word) {
        int lower = 0, upper = 0;                    // 两张 26 位出勤表
        for (char c : word) {
            if (c >= 'a') lower |= 1 << (c - 'a');   // 小写：记到 lower
            else          upper |= 1 << (c - 'A');   // 大写：记到 upper
        }
        return __builtin_popcount(lower & upper);    // 两表同时点名的字母数
    }
};
```

### Python

```python
class Solution:
    def numberOfSpecialChars(self, word: str) -> int:
        lower = upper = 0
        for c in word:
            if c.islower():
                lower |= 1 << (ord(c) - ord('a'))
            else:
                upper |= 1 << (ord(c) - ord('A'))
        return (lower & upper).bit_count()
```

## 8. 边界情况与易错点

1. **计数单位是字母不是字符**：`"aaAbcBC"` 中 `a` 出现两次、`A` 出现一次，字母 `a` 仍只算 1 个——幂等置位天然处理，切勿按出现次数累加。
2. **单一形态不算特殊**：`"abc"`（upper 全空）答案为 0；`"abBCab"` 中 `a` 只有小写、`c` 只有大写，都不算——别把「出现过的形态数」当成答案。
3. **长度为 1**：单个字符必为 0，算法无需特判。
4. **判大小写的前提**：`c >= 'a'` 依赖「输入纯英文字母」这一约束（$\texttt{'Z'} < \texttt{'a'}$）；若放宽输入需改用 `islower`。
5. **别混用偏移基准**：小写减 `'a'`、大写减 `'A'`，不要统一减 `'a'`（大写会得到负数/错位），也不要以为 $\texttt{'a'} - \texttt{'A'} = 26$（实际是 32）。
6. **`set(word)` 的大小不是答案**：52 键的集合需要的是「配对判定」，不是去重计数，`len(set(word))` 之类的一步到位是陷阱。
