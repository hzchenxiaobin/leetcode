# LeetCode 按类型和颜色删除元素 题解

## 1. 题目概述

- **标题 / 题号**：按类型和颜色删除元素（#4103，medium）
- **链接**：https://leetcode.cn/problems/remove-elements-by-type-and-color/
- **来源**：LeetCode 第 195 场双周赛 Q2
- **难度**：中等
- **标签**：栈、数组、模拟

**题意**：给定三个数组 `types`、`colors`（长度 $n$）与 `groupSize`（长度 $m$）。第 $i$ 个元素带有「类型 `types[i]`」与「颜色 `colors[i]`」。

一次操作：若存在**恰好** `groupSize[t]` 个**连续**元素，它们**类型都是 $t$ 且颜色相同**，就可以把它们整体移除；移除后剩下的元素自动靠拢并保持相对顺序。问能否通过若干次操作把**所有**元素删完。

**约束**：

- $1 \le n \le 10^5$，$1 \le m \le 10^5$
- $0 \le \textit{types}[i] \le m-1$，$1 \le \textit{colors}[i] \le 10^5$
- $1 \le \textit{groupSize}[t] \le n$

## 2. 示例

**示例 1**

```text
输入：types = [0,1,1,0], colors = [5,3,3,5], groupSize = [2,2]
输出：true
解释：先删下标 1、2（类型 1、颜色 3、恰好 2 个），剩余 (0,5)(0,5)，
     再删这两个（类型 0、颜色 5、恰好 groupSize[0]=2 个）。
```

**示例 2**

```text
输入：types = [0,1,0], colors = [9,9,9], groupSize = [3,2]
输出：false
解释：没有任意一段连续元素能凑够所需个数，一步都做不了。
```

**示例 3**

```text
输入：types = [2,0,1,2], colors = [7,5,4,7], groupSize = [3,1,2]
输出：false
解释：只能删下标 2（类型 1 的组大小为 1），删完剩 (2,7)(0,5)(2,7)，无法继续。
```

## 3. 解题思路

### 3.1 暴力思路

状态是「当前剩余的序列」，每一步枚举所有可删的连续块并递归。可删块的数量可达 $O(n)$，深度可达 $n$，最坏是指数级（$O(n!)$ 级别的搜索树）。$n = 10^5$ 时完全不可能，即便加记忆化，状态空间也是指数级的。

但暴力很适合**对拍**：$n \le 8$ 时用记忆化 DFS 枚举所有删除顺序，可以验证贪心/栈的正确性。

### 3.2 核心观察：只与「栈顶段」有关的消消乐

![栈中维护同 (type,color) 的连续块](images/bw195_q2_stack.svg)

两个关键观察：

**观察一：把 $(type, color)$ 看成一个「符号」。** 可删块就是「连续 `groupSize[t]` 个相同符号」，其中符号自带类型 $t$，决定需要几个。于是问题变成：给定符号序列，每次可以消掉连续 $g_{\text{sym}}$ 个相同符号，问能否消空。

**观察二：新元素只会影响「末尾那一段」。** 因为在序列中，能与新元素相邻的只有当前最后一个元素所在的那一段。所以整个序列可以被压缩成「连续段的列表」，每次只需与**最后一段**比较：

- 若符号相同 → 该段计数 $+1$；
- 否则 → 新开一段，计数 $1$。

当某段的计数恰好达到它所需的 $g$ 时，这一段**立刻整体可删**，于是直接弹栈；弹出后新的栈顶自然成为新的「末尾段」，后续元素会继续与它比较——这正是「消完之后两侧靠拢」的效果，而且**不需要数组平移**。

**观察三：能删就立刻删，不会变差。** 如果当前存在可删块，那么先删它一定不会破坏「最终能否删完」这件事。原因是：可删块与后续操作要么不重叠（可交换顺序），要么重叠（重叠的两个可删块必然在同一段里、符号相同、大小相同，删哪个结果序列都一样）。

### 3.3 算法流程

```text
1. stack = []        // 每项: [type, color, count]
2. for i = 0 .. n-1:
3.     t = types[i];  c = colors[i]
4.     if stack 非空 且 栈顶类型 == t 且 栈顶颜色 == c:
5.         stack.top.count += 1
6.     else:
7.         stack.push([t, c, 1])
8.     if stack.top.count == groupSize[stack.top.type]:
9.         stack.pop()
10. return stack 为空
```

注意第 4 行的合并条件是**类型与颜色都相同**，缺一不可——颜色不同即使类型相同也不能合并成一段。

**示例 1**：`types = [0,1,1,0]`，`colors = [5,3,3,5]`，`groupSize = [2,2]`。

## 4. 算法细节

1. **栈元素用三元组**：`{type, color, count}`。C++ 用 `vector<array<int,3>>`，Python 用 `list` 的列表。
2. **计数恰好等于 $g$ 时弹出**：因为一旦达到 $g$ 就立刻弹，栈中任何段的计数都严格小于 $g$，所以不需要处理「超过」的情况。
3. **`groupSize` 用类型索引**：`groupSize[stack.top.type]`，注意 `types[i]` 是 $0 \sim m-1$，与 `groupSize` 下标直接对应。
4. **弹出后不需要再主动合并**：栈中任意相邻两段的符号必然不同——新段只在「与当前栈顶符号不同」时才会被压入，而栈顶以下的段在压栈之后不会再被修改。因此弹出栈顶后暴露出来的新栈顶与更早的段符号依然不同，不需要额外的「合并两侧」检查。
5. **`groupSize[t] = 1`**：元素一入栈立刻弹出，等价于「单个元素自成可删块」。
6. **不需要维护数组下标**：整个算法与「元素在原数组中的位置」无关，只看相对顺序。

## 5. 正确性证明

**定义**：称符号 $\textit{sym} = (t, c)$ 在序列中的一段连续出现为**可删块**，若其长度恰为 $g_t$。记「序列可消空」为谓词 $\Phi$。

**引理 1（栈等于当前序列的段压缩）**：算法处理完前 $k$ 个元素后，栈中依次存储的 `(type, color, count)` 恰好是「对前 $k$ 个元素按贪心规则删去若干可删块之后所得序列」的**连续段压缩**（同段符号相同、相邻段符号不同）。

**证明**：对 $k$ 归纳。$k = 0$ 时栈空。设 $k-1$ 时成立，加入第 $k$ 个元素：

- 若它与当前序列末尾符号相同，则末尾段长度 $+1$，对应栈顶计数 $+1$；
- 否则它自成新的一段，对应压入新栈顶。

若更新后栈顶计数达到 $g$，则该段恰好是一个可删块，删除它后序列段压缩就是弹出栈顶后的结果（相邻段符号不同，无需合并）。若未达到 $g$，则没有新的可删块产生（其余段未改变）。∎

**引理 2（可删块的删除可交换）**：设序列 $S$ 中存在可删块 $B$。则 $S$ 可消空当且仅当删掉 $B$ 后的序列 $S'$ 可消空。

**证明**：($\Leftarrow$) 显然：先删 $B$ 再按 $S'$ 的方案删完。($\Rightarrow$) 设 $S$ 有一组合法删除序列，第一个被删的块为 $B_1$。

- 若 $B_1 = B$，则为 $S'$ 的合法删除序列。
- 若 $B_1$ 与 $B$ 位置集合不相交，则两者互不影响，交换顺序后「先删 $B$、再删 $B_1$ 的剩余部分」仍是 $S'$ 的合法删除序列。
- 若 $B_1$ 与 $B$ 位置集合相交，则它们的并是一段更长的、符号相同的连续段（同一段内的子块），且长度都为对应的 $g$；删除其中任意 $g$ 个连续元素后，剩下的仍是同一段符号的 $L - g$ 个元素，序列**完全相同**。故删 $B$ 后仍可用原方案删完。∎

**定理**：算法返回 `true` 当且仅当所有元素可以被删完。

**证明**：

若算法返回 `true`（最终栈空），则按引理 1，算法过程中做的每一次弹出都对应一次合法删除，于是这些删除构成一个把所有元素删完的合法序列，故可删完。

反之设存在删完的合法序列。对元素个数归纳：由引理 1，栈顶段若计数达到 $g$ 则算法删除它；由引理 2，这次删除不破坏「可消空」性质，且删除后的序列状态与归纳假设中「已处理前缀」的情形一致。因此算法每删一次都能对应到某个完整合法序列的前缀操作，最终必然把全部元素删完（否则剩余序列非空但已无任何可删块，与存在完整删除序列矛盾）。∎

**推论**：栈中相邻段符号必然互异，因此弹出后无需再做合并检查。

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素至多入栈一次、出栈一次，每次操作为常数次比较；`groupSize` 的下标访问 $O(1)$。
- **空间**：$O(n)$。栈最多保存 $n$ 个段（例如所有元素符号互不相同时）。

## 7. 参考代码

### C++

```cpp
#include <array>
#include <vector>

using namespace std;

class Solution {
public:
    bool canRemoveAll(vector<int>& types, vector<int>& colors, vector<int>& groupSize) {
        // 栈中每个元素是一段「同 (type,color) 的连续块」: {type, color, count}
        vector<array<int, 3>> st;
        st.reserve(types.size());
        for (size_t i = 0; i < types.size(); i++) {
            int t = types[i], c = colors[i];
            if (!st.empty() && st.back()[0] == t && st.back()[1] == c) {
                st.back()[2] += 1;
            } else {
                st.push_back({t, c, 1});
            }
            if (st.back()[2] == groupSize[st.back()[0]]) {
                st.pop_back();
            }
        }
        return st.empty();
    }
};
```

### Python

```python
from typing import List

class Solution:
    def canRemoveAll(self, types: List[int], colors: List[int], groupSize: List[int]) -> bool:
        stack = []  # [type, color, count]
        for t, c in zip(types, colors):
            if stack and stack[-1][0] == t and stack[-1][1] == c:
                stack[-1][2] += 1
            else:
                stack.append([t, c, 1])
            if stack[-1][2] == groupSize[stack[-1][0]]:
                stack.pop()
        return not stack
```

## 8. 边界情况与易错点

1. **$n = 1$**：只有 `groupSize[types[0]] == 1` 时返回 `true`，否则 `false`。
2. **`groupSize[t] = 1`**：入栈立即弹出；若写「达到即弹出」的判断条件为 `>=` 之外的 `>`，会漏掉这种情况。
3. **合并条件少判颜色**：类型相同但颜色不同**不能**合并成一段；只比较类型会把 `[0,1]` 与 `[0,2]` 这类情况算错。
4. **误以为弹出后要再合并两侧**：栈中相邻段符号天然互异（见推论），额外加合并逻辑反而会引入 bug；但若你把实现改成「用向量存储每个元素」，就必须显式处理靠拢。
5. **计数判断用 `==` 而非 `>=`**：因为一达到 $g$ 就弹出，计数不会超过 $g$；改成 `>=` 也对但无意义。
6. **`groupSize` 的下标是类型 $t$**，不是元素下标 $i$：`groupSize[types[i]]`，写错成 `groupSize[i]` 会越界（$m$ 可能小于 $n$）。
7. **大 $n$ 下的常数**：`array<int,3>` 与 `reserve` 能显著降低 C++ 的分配开销；用 `vector<vector<int>>` 也能过，但常数更大。
