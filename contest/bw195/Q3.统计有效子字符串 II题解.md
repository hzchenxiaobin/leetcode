# LeetCode 统计有效子字符串 II 题解

## 1. 题目概述

- **标题 / 题号**：统计有效子字符串 II（#4104，medium）
- **链接**：https://leetcode.cn/problems/count-valid-substrings-ii/
- **来源**：LeetCode 第 195 场双周赛 Q3
- **难度**：中等
- **标签**：哈希表、字符串、枚举、双指针

**题意**：给定只含 `'a'`、`'b'`、`'c'` 的字符串 $s$。若一个字符串**不把 `"abc"` 作为子序列**，则称它**有效**。求 $s$ 中有效**子串**的个数；起点或终点不同的子串分别计数。

**约束**：

- $1 \le |s| \le 10^5$
- $s$ 仅由 `a`、`b`、`c` 组成
- 答案最大约 $\frac{n(n+1)}{2} \approx 5 \times 10^9$，需 64 位整数

## 2. 示例

**示例 1**

```text
输入：s = "abac"
输出：9
解释：10 个子串中只有 s[0..3]="abac" 无效——它含子序列 a,b,c
     （下标 0、1、3）。
```

**示例 2**

```text
输入：s = "abc"
输出：5
解释：唯一的无效子串是 "abc" 本身。
```

**示例 3**

```text
输入：s = "ac"
输出：3
解释：所有子串都不含 "abc" 子序列。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $O(n^2)$ 个子串，对每个子串判断是否含 `"abc"` 子序列（贪心匹配 $O(n)$），总复杂度 $O(n^3)$；即便用「每个子串维护三个指针」的 $O(1)$ 判定，子串个数本身也是 $5 \times 10^9$，$n = 10^5$ 时无法接受。

与同场 Q1（子串版）相比，本题的「违规」更容易发生：只要子串里存在一个 `a` 在某个 `b` 左边、某个 `c` 右边，就违规。因此必须重新设计「最右起点」的定义。

### 3.2 核心观察：三指针取代单指针

![三个量：最近的 a、最优的 ab、最优的 abc](images/bw195_q3_pointers.svg)

固定右端点 $r$，定义

$$p_r = \max\{\, i \mid \exists\, i < j < k \le r,\ s[i]=\texttt{a},\ s[j]=\texttt{b},\ s[k]=\texttt{c} \,\}$$

即「$s[0..r]$ 中所有 `"abc"` 子序列里，**首个字符的最大下标**」（不存在时 $p_r=-1$）。

**断言**：子串 $s[l..r]$ 含 `"abc"` 子序列 $\iff l \le p_r$。

理由与 Q1 完全平行：$p_r$ 是「最靠右的那个起点」，任何含 `"abc"` 子序列的子串，其起点不可能在 $p_r$ 右边；而起点 $\le p_r$ 时，$p_r$ 对应的三元组整段落在子串内。

于是以 $r$ 结尾的合法子串数仍为 $r - p_r$，答案为 $\sum_r (r - p_r)$。剩下的问题是如何 $O(1)$ 维护 $p_r$。为此引入两个辅助量：

- $\textit{lastA}$：$s[0..r]$ 中**最靠右的 `a`** 的下标；
- $\textit{bestAB}$：所有形如 $i < j \le r$、$s[i]=\texttt{a}$、$s[j]=\texttt{b}$ 的二元组中，**最大**的 $i$。

它们之间的关系非常干净：

$$\textit{bestAB} \leftarrow \max(\textit{bestAB},\ \textit{lastA}) \quad (\text{当 } s[r]=\texttt{b})$$
$$p \leftarrow \max(p,\ \textit{bestAB}) \quad (\text{当 } s[r]=\texttt{c})$$

**为什么「最大下标」就够了？** 因为对固定右端点而言，起点越大，被排除的子串越少，而「起点 $\le p$ 全部违规」这一判定只依赖**最大的那个起点**。$p$ 单调不减，所以不需要考虑历史。

### 3.3 算法流程

```text
1. lastA = -1;  bestAB = -1;  p = -1;  ans = 0
2. for r = 0 .. n-1:
3.     if s[r] == 'a':   lastA = r
4.     elif s[r] == 'b': if lastA >= 0: bestAB = max(bestAB, lastA)
5.     else:             if bestAB >= 0: p = max(p, bestAB)
6.     ans += r - p
7. return ans
```

三个量都只增不减，因此每个字符 $O(1)$。

### 3.4 示例演算

![示例 1 的逐位走查](images/bw195_q3_example.svg)

以 $s = \texttt{"abac"}$ 为例：

| $r$ | $s[r]$ | $\textit{lastA}$ | $\textit{bestAB}$ | $p$ | 新增 $r-p$ | 累计 |
|-----|--------|------------------|-------------------|-----|-----------|------|
| 0 | a | 0 | −1 | −1 | 1 | 1 |
| 1 | b | 0 | 0 | −1 | 2 | 3 |
| 2 | a | 2 | 0 | −1 | 3 | 6 |
| 3 | c | 2 | 0 | 0 | 3 | 9 |

答案 $9$，与示例一致。与同场 Q1（子串版）对比：Q1 对同一个串给出 $10$，差的那一个正是 $s[0..3] = \texttt{"abac"}$——它含子序列 $a,b,c$（下标 $0,1,3$），故在本题中无效。

再看 $s = \texttt{"abc"}$：$r=1$ 时 $\textit{bestAB}=0$；$r=2$ 时 $p=0$，新增 $2$。累计 $1+2+2 = 5$，与示例一致。

## 4. 算法细节

1. **`bestAB` 的更新时机**：只有在遇到 `'b'` 时才用**当前**的 `lastA` 更新，表示「这个 `b` 与它左边最近的 `a` 配成一对」。用更大的 `lastA` 总是更好（起点后移）。
2. **`p` 的更新时机**：只有在遇到 `'c'` 时才用 `bestAB` 更新，表示「这个 `c` 与最优的 `ab` 配成三元组」。
3. **哨兵值 $-1$**：三个量都用 $-1$ 表示「不存在」，`max` 时自然被忽略（配合 `>= 0` 判断更清楚）。
4. **不要在同一轮里链式更新**：`s[r]` 只可能是一个字符，三个分支互斥；若把 `'a'` 分支也去更新 `bestAB`，会错误地把「同一个字符既当 a 又当 b」算进去。
5. **答案用 64 位**：$n = 10^5$ 时 $5 \times 10^9$，`int` 溢出。
6. **判定是「子序列」不是「子串」**：`"abc"` 只要求相对顺序，不要求连续；这也是与 Q1 的唯一区别。

## 5. 正确性证明

**引理 1（`lastA` / `bestAB` 的语义）**：处理完 $s[0..r]$ 后，`lastA` 等于 $s[0..r]$ 中最靠右 `'a'` 的下标（不存在为 $-1$）；`bestAB` 等于所有满足 $i<j\le r$、$s[i]=\texttt{a}$、$s[j]=\texttt{b}$ 的二元组中最大的 $i$（不存在为 $-1$）。

**证明**：对 $r$ 归纳。

- `lastA`：$s[r]=\texttt{a}$ 时更新为 $r$，正是最靠右的 `a`；否则继承上一步结果。
- `bestAB`：新的二元组只可能是「$j = r$ 且 $s[r]=\texttt{b}$」，其最大起点为 $\textit{lastA}_{r-1}$；故 $r$ 时刻的最大起点为 $\max(\textit{bestAB}_{r-1}, \textit{lastA}_{r-1})$，正是算法第 4 行（注意第 3、4 行互斥，`lastA` 的更新不影响本步的 `bestAB`）。∎

**引理 2（$p$ 的语义）**：处理完 $s[0..r]$ 后，$p = p_r$，即所有以 $k \le r$ 结尾的 `"abc"` 子序列中首个字符的最大下标。

**证明**：由引理 1，`bestAB` 是所有满足 $i<j\le r$ 的 `ab` 对中最大的 $i$。三元组 $(i,j,k)$ 的首字符下标 $i$ 的最大值，等于「在 $k \le r$ 的所有 `c` 上，取 $k$ 之前的 `ab` 对的最大 $i$」的最大值。算法在遇到每个 `c` 时用当时的 `bestAB` 更新 $p$ 并取 max，故 $p$ 恰为该最大值；不存在时为 $-1$。∎

**引理 3（判定准则）**：子串 $s[l..r]$ 含 `"abc"` 子序列当且仅当 $l \le p_r$。

**证明**：($\Rightarrow$) 若存在 $l \le i < j < k \le r$ 满足字符条件，则 $i$ 属于 $p_r$ 的定义集合，故 $i \le p_r$，从而 $l \le p_r$。($\Leftarrow$) 若 $l \le p_r$，取 $p_r$ 对应的三元组 $(p_r, j, k)$，则 $l \le p_r < j < k \le r$，三元组整段落在子串内。∎

**定理**：算法返回值等于 $s$ 中不含 `"abc"` 子序列的子串个数。

**证明**：所有子串按右端点分组。由引理 3，以 $r$ 结尾的合法子串恰为 $l \in (p_r, r]$ 共 $r - p_r$ 个；由引理 2，算法累加值正是 $r - p_r$。求和即得全部有效子串数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个字符做常数次比较与 `max`，一遍扫描。
- **空间**：$O(1)$。三个标量加一个累加器。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>

using namespace std;

class Solution {
public:
    long long countValidSubstrings(string s) {
        int n = (int)s.size();
        long long ans = 0;
        int lastA = -1, bestAB = -1, p = -1;
        for (int r = 0; r < n; r++) {
            if (s[r] == 'a') {
                lastA = r;
            } else if (s[r] == 'b') {
                if (lastA >= 0) bestAB = max(bestAB, lastA);
            } else {
                if (bestAB >= 0) p = max(p, bestAB);
            }
            ans += (long long)(r - p);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countValidSubstrings(self, s: str) -> int:
        ans = 0
        last_a = -1   # 最近的 'a' 下标
        best_ab = -1  # "ab" 子序列的最大起始下标
        p = -1        # "abc" 子序列的最大起始下标
        for r, ch in enumerate(s):
            if ch == 'a':
                last_a = r
            elif ch == 'b':
                if last_a >= 0:
                    best_ab = max(best_ab, last_a)
            else:  # 'c'
                if best_ab >= 0:
                    p = max(p, best_ab)
            ans += r - p
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$ 或 $2$**：不可能凑出长度为 3 的子序列，答案就是子串总数 $1$ 或 $3$。
2. **`p` 更新用「当时的」`bestAB`**：若先处理 `'c'` 再更新 `bestAB`（把分支顺序写乱），会用到尚未成立的配对。
3. **同一字符不能既当 `a` 又当 `b`**：三个分支必须互斥；`for` 里写三个独立 `if` 也正确（因为一个字符只可能命中一个），但千万不要在 `'a'` 分支里也更新 `bestAB`。
4. **`p` 单调不减**：用 `p = max(p, bestAB)` 而不是 `p = bestAB`。虽然 `bestAB` 本身也单调不减，但显式取 max 更能表达语义，也避免将来修改时出现回退。
5. **答案用 `long long`**：$5\times10^9$ 超出 `int`；C++ 里 `ans += (long long)(r - p)` 的强转不能省（否则先算 `int` 再累加，`r - p` 本身不会溢出，但累加会）。
6. **与 Q1 混淆**：Q1 判「连续子串」，本题判「子序列」。对 `"abac"`，两者答案是 $10$ 与 $9$，恰好差一个。
7. **`"c"` 分支写死 `else`**：输入保证只含 `a/b/c`，可以安全地用 `else`；若输入可能含其他字符，应显式判断 `ch == 'c'`。
