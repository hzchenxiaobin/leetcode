# LeetCode 不可能得到的最短骰子序列 题解

## 1. 题目概述

- **标题 / 题号**：不可能得到的最短骰子序列（#2350，hard）
- **链接**：https://leetcode.cn/problems/shortest-impossible-sequence-of-rolls/
- **来源**：LeetCode 第 83 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、哈希表

**题意**：一个 $k$ 面骰子（面值 $1 \sim k$）被投了 $n$ 次，第 $i$ 次的结果是 `rolls[i]`。一个长度为 $\text{len}$ 的「骰子子序列」是投 $\text{len}$ 次骰子得到的序列。**子序列**只需保持相对顺序、不必连续。求**无法**从 `rolls` 中取出的**最短**骰子子序列长度。

**约束**：

- $n = \text{rolls.length} \le 10^5$
- $1 \le \text{rolls}[i] \le k \le 10^5$

## 2. 示例

**示例 1**

```text
输入：rolls = [4,2,1,2,3,3,2,4,1], k = 4
输出：3
解释：长度 1 的 [1],[2],[3],[4] 全部可得；长度 2 的全部 16 个序列也全部可得；
      而 [1,4,2] 无法得到，故最短不可得长度为 3。
```

**示例 2**

```text
输入：rolls = [1,1,2,2], k = 2
输出：2
解释：长度 1 的 [1],[2] 都可得；[2,1] 取不到（2 只在 1 后面出现）。
```

**示例 3**

```text
输入：rolls = [1,1,3,2,2,2,3,3], k = 4
输出：1
解释：面值 4 从未出现，[4] 本身就取不到。
```

## 3. 解题思路

### 3.1 暴力思路

长度为 $L$ 的骰子子序列共有 $k^L$ 个，每个都可用「贪心逐位匹配」在 $O(n)$ 内检查是否为 `rolls` 的子序列。从 $L = 1$ 起逐层检查，直到某层存在取不到的序列。但 $k^L$ 指数膨胀：$k = 10^5$、$L = 2$ 就有 $10^{10}$ 个序列，彻底不可行。必须换视角——不要枚举「哪些序列可得」，而是刻画「**全部序列都可得**」需要什么条件。

### 3.2 核心观察：把序列按「组」切割，每出现一个完整组，就多撑起一个长度

![分组模型：集齐 1..k 切一组](images/bw83_q4_group_partition.svg)

从左到右扫 `rolls`，维护当前段内**已出现的面值集合**；集合大小一旦达到 $k$（集齐 $1 \sim k$），就切一组、清空集合继续。设共切出 $g$ 个**完整组**（末尾凑不齐的残段不算）。

**为什么组数决定答案**：第 $i$ 个组内包含全部 $k$ 种面值，所以任意目标序列的第 $i$ 个元素都能**在第 $i$ 组内部**找到出现位置，于是 $g$ 个组可以像传送带一样，为长度 $g$ 的任意序列逐组供给一个严格递增的位置——**所有长度 $\le g$ 的序列都可得**。反过来，若只有 $g$ 个完整组，末尾残组必缺某个面 $v$，可以构造一个长度 $g+1$ 的序列（每组取「收尾面」+ 末尾补 $v$）使其必然取不到。故**答案 $= g + 1$**。

### 3.3 算法流程

![示例 1 演算：两组完整 → 答案 3](images/bw83_q4_example_walkthrough.svg)

```text
groups = 0, seen = ∅
遍历 x ∈ rolls：
    seen.insert(x)
    若 |seen| == k：           # 本组集齐 1..k
        groups += 1
        seen = ∅               # 清空，开新组
返回 groups + 1
```

每组至少含 $k$ 个元素，`seen` 用长度 $k+1$ 的布尔数组（或哈希集合）即可，单次重置 $O(k)$、总重置 $O(n)$。

### 3.4 示例演算

示例 1（$k = 4$）：第 1 组 $[4,2,1,2,3]$ 在读到 3 时集齐；第 2 组 $[3,2,4,1]$ 在读到 1 时集齐；共 $g = 2$ 组，答案 $2 + 1 = 3$。验证：$[1,4,2]$ 确实取不到——1 只能取第 3 个位置，其后 4 只有第 8 个位置，再往后没有 2。示例 3：整个数组只出现 $\{1,2,3\}$，连第 1 组都集不齐，$g = 0$，答案 $1$。

## 4. 算法细节

1. **「组」的严格定义**：设 $e_0 = 0$，$e_i$ 为使得 $\text{rolls}[e_{i-1}+1..e_i]$ 包含全部 $k$ 个面值的**最小**下标；第 $i$ 组即区间 $(e_{i-1}, e_i]$。算法里「集齐即切」生成的正是这个划分。
2. **每组只多不少**：组内集合大小到达 $k$ 的瞬间就切组，保证每组「刚好集齐」——切晚只会让后面的组更难集齐，组数不增（贪心的交换论证见 §5 引理 1 的构造）。
3. **重置开销**：用布尔数组时每组结束 `fill` 一次 $O(k)$；由于每组至少 $k$ 个元素，$g \cdot k \le n$，总开销 $O(n + k)$。也可以记录「当前组号」`stamp[x]` 与组号比较实现 $O(1)$ 重置。
4. **`k = 1` 的退化情形**：每读一个元素就集齐一组，$g = n$，答案 $n + 1$——长度超过 $n$ 的序列必然取不到，符合直觉。
5. **答案无需与 $\log_k$ 之类挂钩**：$k^g \le$ 可行序列数的下界只在证明方向上有用，实现上直接 `groups + 1`。

## 5. 正确性证明

记 $e_0 = 0$，$e_1 < e_2 < \dots < e_g$ 为 §4 定义的组边界（$g$ 为完整组数），第 $i$ 组 $S_i = (e_{i-1}, e_i]$，尾部残段 $T = (e_g, n]$。

**引理 1（收尾面的性质）**：对每个 $i$，令 $v_i = \text{rolls}[e_i]$。则 $v_i$ 在 $S_i \setminus \{e_i\}$ 中不出现，且 $v_i$ 在 $S_i$ 内的首次（也是唯一一次）出现恰在 $e_i$。

**证明**：$e_i$ 是使 $S_i$ 集齐的最小下标，故 $S_i$ 的真前缀 $(e_{i-1}, e_i - 1]$ 至少缺一个面。把第 $e_i$ 个元素加入后恰好集齐，而加入单个元素至多使已见面值集合增加一个面，所以 $(e_{i-1}, e_i - 1]$ 缺的**恰是** $v_i = \text{rolls}[e_i]$，即 $v_i$ 在 $S_i$ 中仅在 $e_i$ 处出现。∎

**引理 2（充分性：$g$ 组撑起长度 $g$）**：若 $g \ge L$，则任何长度 $L$ 的序列 $s_1 s_2 \dots s_L \in \{1..k\}^L$ 都是 `rolls` 的子序列。

**证明**：对每个 $i \in [1, L]$，$S_i$ 包含全部 $k$ 种面值，故 $s_i$ 在 $S_i$ 内存在出现位置 $p_i$，且 $e_{i-1} < p_i \le e_i$。由 $p_i \le e_i < e_i + 1 \le p_{i+1}$（后者因 $p_{i+1} \ge e_i + 1$），诸 $p_i$ 严格递增，构成合法的子序列匹配。∎

**引理 3（必要性：$g$ 组撑不起长度 $g+1$）**：存在长度 $g + 1$ 的序列不是 `rolls` 的子序列。

![不可得序列的构造：每组取收尾面再补尾部缺失面](images/bw83_q4_construction_proof.svg)

**证明**：$T$ 是残段，未集齐，取 $T$ 中未出现的任一面 $v$（$T$ 为空时任取一面）。构造 $t = (v_1, v_2, \dots, v_g, v)$，其中 $v_i = \text{rolls}[e_i]$。反设存在匹配位置 $p_1 < p_2 < \dots < p_{g+1}$。归纳证明 $p_i \ge e_i$：$t_1 = v_1$ 在 $(0, e_1]$ 中的唯一出现是 $e_1$（引理 1，且组 1 之前的下标不存在），故 $p_1 \ge e_1$。设 $p_{i-1} \ge e_{i-1}$，则 $p_i > p_{i-1} \ge e_{i-1}$；而 $v_i$ 在 $(e_{i-1}, n]$ 中的首次出现是 $e_i$（引理 1：$v_i$ 在 $S_i$ 中仅出现于 $e_i$，$S_i$ 之后的出现不影响「首次」），故 $p_i \ge e_i$。于是 $p_{g+1} > p_g \ge e_g$，即 $p_{g+1} \in T$；但 $t_{g+1} = v$ 在 $T$ 中不出现，矛盾。∎

**定理**：无法得到的最短骰子子序列长度为 $g + 1$。

**证明**：由引理 2，所有长度 $\le g$ 的序列（特别地，长度 $g$ 的全部 $k^g$ 个）均可得；由引理 3，长度 $g+1$ 中存在不可得者。因此「全部序列可得」的最大长度为 $g$，最短不可得长度为 $g + 1$。∎

## 6. 复杂度分析

- **时间**：$O(n + k)$。一次线性扫描；`seen` 重置共 $g$ 次、每次 $O(k)$，而 $g \cdot k \le n$（每组至少 $k$ 个元素），合计不超过 $O(n)$；初始化布尔数组 $O(k)$。
- **空间**：$O(k)$。面值布尔标记数组（或哈希集合，最坏存下当前组内的全部相异面值 $\le k$ 个）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int shortestSequence(vector<int>& rolls, int k) {
        int groups = 0, distinct = 0;
        vector<char> seen(k + 1, 0);
        for (int x : rolls) {
            if (!seen[x]) {
                if (++distinct == k) {          // 本组集齐 1..k → 一组结束
                    ++groups;
                    distinct = 0;
                    fill(seen.begin(), seen.end(), 0);
                } else seen[x] = 1;
            }
        }
        return groups + 1;
    }
};
```

### Python

```python
class Solution:
    def shortestSequence(self, rolls: list[int], k: int) -> int:
        groups = 0
        seen = set()                       # 当前组已出现的面
        for x in rolls:
            seen.add(x)
            if len(seen) == k:             # 集齐 1..k → 一组结束
                groups += 1
                seen = set()
        return groups + 1
```

> 💡 两份代码均通过官方 3 个示例与 $k=1$ 两个边界（`[1], k=1 → 2`、`[1,1,1], k=1 → 4`），并与「穷举全部 $k^L$ 个序列逐个贪心匹配」的暴力对拍：C++ 2 万组（$k \le 4$、$n \le 12$）、Python 2 千组，`mismatch = 0`；另通过 $k = 10^5$、两轮完整 + 半轮的大数据冒烟（答案 3）。

## 8. 边界情况与易错点

1. **答案与 $n$ 的关系**：$g \le \lfloor n/k \rfloor$，答案 $g+1 \le \lfloor n/k \rfloor + 1$，永远不会超过 $n + 1$；但**不要**用 $k^g > n$ 之类的计数界来直接推答案——取不到的序列靠的是「面缺失」，不是数量不够。
2. **「最短」要求先排除短层**：答案定义为最短不可得长度，必须确认所有更短的长度全部可得（引理 2），只构造一个坏序列（引理 3）是不完整的。
3. **`k = 1`**：每个元素自成一组，答案 $n+1$；此时 $k^L \equiv 1$，序列空间只有全 1 一条，暴力对拍要覆盖。
4. **组内重复面不推进度**：`seen` 重复插入不影响 `len(seen)`；C++ 布尔版记得只在 `!seen[x]` 时 `++distinct`，否则计数虚高提前切组。
5. **重置成本**：C++ 每组 `fill` $O(k)$ 可能被误判为 $O(nk)$——由 $g \cdot k \le n$ 保证总开销线性；不放心可改用「组号戳记」$O(1)$ 重置。
6. **子序列不必连续**：别把组内匹配误解成连续段匹配；引理 2 的位置只要求组内出现且跨组递增。
