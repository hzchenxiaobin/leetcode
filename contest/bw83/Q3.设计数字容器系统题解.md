# LeetCode 设计数字容器系统 题解

## 1. 题目概述

- **标题 / 题号**：设计数字容器系统（#2349，medium）
- **链接**：https://leetcode.cn/problems/design-a-number-container-system/
- **来源**：LeetCode 第 83 场双周赛 Q3
- **难度**：中等
- **标签**：设计、哈希表、有序集合、堆（优先队列）

**题意**：实现 `NumberContainers` 类，支持两个操作：

- `change(index, number)`：在下标 `index` 处填入 `number`；若该下标已有数字，则**替换**之。
- `find(number)`：返回数字 `number` 在系统中的**最小下标**；不存在返回 $-1$。

**约束**：

- $1 \le \text{index}, \text{number} \le 10^9$（下标与数字都散布极大区间，无法开数组）
- `change` 与 `find` 的**总调用次数**不超过 $10^5$

## 2. 示例

**示例 1（官方调用序列回放）**

```text
操作：
["NumberContainers","find","change","change","change","change","find","change","find"]
[[], [10], [2,10], [1,10], [3,10], [5,10], [10], [1,20], [10]]

输出：
[null, -1, null, null, null, null, 1, null, 2]

解释：
nc.find(10);       // 系统里没有 10 → -1
nc.change(2, 10);  // 下标 2 填 10
nc.change(1, 10);  // 下标 1 填 10
nc.change(3, 10);  // 下标 3 填 10
nc.change(5, 10);  // 下标 5 填 10
nc.find(10);       // 10 的下标有 {1,2,3,5}，最小为 1
nc.change(1, 20);  // 下标 1 改为 20（旧的 10 需要被移除！）
nc.find(10);       // 10 的下标只剩 {2,3,5}，最小为 2
```

**示例 2（边界回放）**

```text
nc.find(7);        // → -1，空系统查找
nc.change(3, 5); nc.change(3, 5);   // 同下标同数字重复 change → find(5) 仍为 3
nc.change(1, 8);   // 数字 5 被从下标 3 全部搬空 → find(5) = -1，find(8) = 1
```

## 3. 解题思路

### 3.1 暴力思路

把 $10^9$ 的下标空间当成数组直接开——内存直接爆炸，不可行。退一步，用一张「下标 → 数字」哈希表存状态：`change` 是 $O(1)$；但 `find(number)` 需要全表扫描找该数字的最小下标，单次 $O(n)$、总 $O(n^2) \approx 10^{10}$，也不可行。瓶颈在 `find`：它要的是**每个数字各自维护一份下标集合，并能 $O(\log)$ 取最小**。

### 3.2 核心观察：同一份数据需要两种索引方向

![双哈希设计：下标→数字 + 数字→有序集合](images/bw83_q3_two_map_design.svg)

- **正向**：`idx2num`（哈希表）记录每个下标当前的数字，`change` 直接覆盖，$O(1)$。
- **反向**：`num2idx`（数字 → **有序集合**）记录每个数字当前出现在哪些下标，`find` 就是取集合首元素（最小值），$O(\log)$。

正向表解决「替换时旧数字是谁」，反向表解决「最小下标是谁」。两张表必须在 `change` 里**同步维护**——这是本题唯一的坑：若不先把下标从旧数字的集合里摘除，`find` 就会读到已经改嫁的「僵尸下标」。

### 3.3 算法流程

```text
change(index, number)：
    old = idx2num[index]（若存在）
    若 old 存在且 old != number：
        num2idx[old].erase(index)        # ① 旧数字集合中删除该下标
    idx2num[index] = number              # ② 覆盖正向表
    num2idx[number].insert(index)       # ③ 新数字集合中插入该下标

find(number)：
    若 num2idx[number] 为空或不存在 → 返回 -1
    否则返回其有序集合的首元素（最小下标）
```

### 3.4 示例演算

![官方示例回放：change 的旧值清理决定 find 的正确性](images/bw83_q3_example_walkthrough.svg)

沿用 §2 示例 1：四处 `change(?, 10)` 后 `num2idx[10] = {1,2,3,5}`，`find(10) = 1`；`change(1, 20)` 时先把 1 从 `num2idx[10]` 摘除、再插入 `num2idx[20]`，于是 `num2idx[10] = {2,3,5}`，`find(10) = 2`。若漏掉第 ① 步，第二次 `find(10)` 会错误地返回 1。

## 4. 算法细节

1. **C++ 选 `unordered_map<int, set<int>>`**：`set` 的 `begin()` 即最小下标，`erase` 是 $O(\log)$。总调用 $\le 10^5$，$O(\log)$ 绰绰有余。
2. **Python 用「最小堆 + 惰性删除」替代有序集合**：`change` 只往 `num2heap[number]` 里 `heappush(index)`（不去重、不删除）；`find` 时检查堆顶下标的**当前数字**是否仍是本数字（查正向表），不是就说明它已改嫁，弹出作废。每个下标每次 `change` 至多入堆一次，弹出总数 ≤ 入堆总数，`find` 均摊 $O(\log n)$——比 `SortedList` 依赖第三方库更可移植。
3. **同下标同数字重复 `change`**：C++ 里 `set::insert` 天然去重，无副作用；Python 堆里会留下重复下标，但两个副本都「有效」，不影响 `find` 结果。
4. **空集合不必清理**：数字被搬空后 `num2idx[old]` 可能剩空集合，`find` 判空返回 $-1$ 即可，无需从外层哈希表删除键（删除也行，省点内存）。
5. **先删后插的顺序**：若 `old == number`（重复操作）可以跳过删除，减少一次 $O(\log)$ 的开销；判不判都正确，写上更稳。

## 5. 正确性证明

**引理（双表不变量）**：任意操作序列后，对每个数字 $v$，集合 $\text{num2idx}[v]$ 与「当前 `idx2num` 中值为 $v$ 的下标集合」保持一致（C++ 语义下严格相等；Python 惰性删除语义下，真实集合 = 堆中未失效的元素）。

**证明**：对操作数归纳。初始两表皆空，成立。设某次操作前不变量成立，考察 `change(index, number)`：设旧值为 $old$（若存在）。

- C++ 版：先从 $\text{num2idx}[old]$ 中删除 `index`（仅当 $old \ne number$），再把 `index` 插入 $\text{num2idx}[number]$，最后 `idx2num[index] = number`。逐下标核对：`index` 在新正向表中属于 `number`，且已加入 `num2idx[number]` ✓；`index` 已从 `num2idx[old]` 移除 ✓；其余下标两表均未触碰 ✓。
- Python 版：正向表同样更新；反向堆中旧条目虽残留，但「有效元素」定义下的集合一致——失效条目（堆中下标的当前数字 ≠ 所查数字）会在 `find` 时被弹出，堆中残留的失效条目不影响任何一次 `find` 的返回值。

`find(number)` 在不变量下读取集合首元素即最小下标，空则 $-1$，与定义相符。∎

**定理（复杂度）**：`change` 为 $O(\log n)$（`set` 的插入/删除；Python 为 $O(\log n)$ 入堆）；`find` 为 $O(\log n)$（C++ 取首元素 $O(1)$ + 不涉及删除；Python 均摊——每次弹出都对应更早一次入堆，总弹出 ≤ 总入堆 ≤ 调用数）。总操作 $\le 10^5$，全程 $O(q \log q)$。∎

## 6. 复杂度分析

- **时间**：单次 `change` $O(\log q)$、`find` $O(\log q)$ 均摊（$q$ 为总调用数，$q \le 10^5$），合计 $O(q \log q) \approx 1.7 \times 10^6$ 次比较。
- **空间**：$O(q)$——正向表至多 $q$ 个键；反向结构中每个下标至多入堆一次（Python）或恰存一份（C++ `set`），合计 $O(q)$。

## 7. 参考代码

### C++

```cpp
class NumberContainers {
    unordered_map<int, int> idx2num;          // 下标 → 当前数字
    unordered_map<int, set<int>> num2idx;     // 数字 → 下标的有序集合
public:
    NumberContainers() {}

    void change(int index, int number) {
        auto it = idx2num.find(index);
        if (it != idx2num.end() && it->second != number)
            num2idx[it->second].erase(index);  // 先从旧数字的下标集合里摘除
        idx2num[index] = number;
        num2idx[number].insert(index);
    }

    int find(int number) {
        auto it = num2idx.find(number);
        if (it == num2idx.end() || it->second.empty()) return -1;
        return *it->second.begin();            // 有序集合首元素 = 最小下标
    }
};
```

### Python

```python
from heapq import heappush, heappop


class NumberContainers:
    def __init__(self):
        self.idx2num = {}                       # 下标 → 当前数字
        self.heaps = {}                         # 数字 → 下标最小堆（惰性删除）

    def change(self, index: int, number: int) -> None:
        self.idx2num[index] = number
        heappush(self.heaps.setdefault(number, []), index)

    def find(self, number: int) -> int:
        h = self.heaps.get(number)
        if not h:
            return -1
        while h and self.idx2num.get(h[0]) != number:   # 堆顶下标已改属其他数字 → 失效弹出
            heappop(h)
        return h[0] if h else -1
```

> 💡 两份代码均通过官方 9 步调用序列回放（`[-1, 1, 2]`）与补充边界（空查找 / 同值重复 change / 数字被搬空），并与「单表全扫描」暴力实现做随机操作序列对拍：C++ 4 千组、Python 2 千组（每组 30~200 次随机操作），`mismatch = 0`。

## 8. 边界情况与易错点

1. **`change` 的旧值清理是唯一考点**：漏掉「从旧数字集合摘除下标」会让 `find` 返回已被覆盖的下标。C++ 里别先赋值再取旧值——要先 `find` 再覆盖。
2. **同下标同数字重复操作**：跳过删除分支（`old == number`）或依赖 `set::insert` 幂等性都正确，但 Python 堆会积累重复项，需确认 `find` 的失效判定不受影响（当前实现不受）。
3. **下标与数字上界 $10^9$**：不能用数组，哈希表键就是数值本身；C++ 的 `unordered_map` 单次操作有常数风险但 $10^5$ 规模无压力。
4. **`find` 查询从未 `change` 过的数字**：哈希表查不到键 → 返回 $-1$；注意别对空键做 `begin()` 解引用。
5. **数字被搬空后再 `find`**：C++ 侧集合为空要返回 $-1$（判 `empty()`）；Python 侧堆被弹空同样返回 $-1$，别返回 `h[0]` 越界。
6. **构造函数要显式写**：LeetCode 设计题即使无状态也要有 `NumberContainers()` / `__init__`，否则回放报错。
