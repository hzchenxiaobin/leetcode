# LeetCode 找到最常见的回答 题解

## 1. 题目概述

- **标题 / 题号**：找到最常见的回答（#3527，medium）
- **链接**：https://leetcode.cn/problems/find-the-most-common-response/
- **来源**：LeetCode 第 155 场双周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表、字符串、计数

**题意**：给定二维字符串数组 `responses`，其中 `responses[i]` 是第 $i$ 天的回答列表。要求先把**每天内部去重**（同一天同一个回答只说一次），再统计每个不同回答**出现在多少天**里，返回出现天数最多的那个回答；若有并列，返回**字典序最小**者。

**约束**：

- $1 \le \text{responses.length} \le 1000$
- $1 \le \text{responses}[i]\text{.length} \le 1000$
- $1 \le \text{responses}[i][j]\text{.length} \le 10$
- `responses[i][j]` 仅由小写英文字母组成
- 总词数不超过 $10^6$

## 2. 示例

**示例 1**

```text
输入：responses = [["good","ok","good","ok"],["ok","bad","good","ok","ok"],["good"],["bad"]]
输出："good"
解释：每天去重后为 [["good","ok"],["ok","bad","good"],["good"],["bad"]]。
     good 出现在 3 天，ok 出现在 2 天，bad 出现在 2 天 → 返回 "good"。
```

**示例 2**

```text
输入：responses = [["good","ok","good"],["ok","bad"],["bad","notsure"],["great","good"]]
输出："bad"
解释：去重后 good、ok、bad 都出现 2 天，并列最高；
     取字典序最小者 "bad"。
```

## 3. 解题思路

### 3.1 暴力思路

最容易写错的"暴力"是**不按天去重**，直接对原始数组计数：示例 1 里 `good` 出现 4 次、`ok` 出现 5 次，会错答 `"ok"`，而正确答案是 `"good"`。所以「去重」是本题的**语义核心**，不是可以省略的优化。

一个朴素但正确的做法是：先收集所有出现过的不同回答（不超过总词数），再对每个候选词扫描全部天数、判断它是否在那一天出现过，复杂度 $O(V \cdot D \cdot L)$，其中 $V$ 是不同词数、$D$ 是天数、$L$ 是单词平均长度。总词数可达 $10^6$，这个做法在最坏情况下会被拉到 $10^9$ 量级。

### 3.2 核心观察：按天去重后一遍哈希计数

![每天先去重，再统计出现在多少天](images/bw155_q1_dedup_count.svg)

把「去重」放在**读取每一天时**完成，问题就退化为一次普通的频率统计：

- 对第 $i$ 天，先把 `responses[i]` 丢进集合（哈希集合去重）；
- 集合里每个词就是「该词在第 $i$ 天出现过」这一事实，于是 `cnt[word] += 1` 恰好把它记作**一天**；
- 全部天数处理完后，`cnt[word]` 就是 word 出现的**天数**，与题意完全一致。

这一步把 $O(V \cdot D \cdot L)$ 的重复扫描压缩成 $O(\sum_i |\text{responses}[i]|)$ 的单遍统计。

### 3.3 算法流程

```text
1. cnt = 空哈希表（词 -> 出现天数）
2. for day in responses:
       seen = set(day)                 // 当天内部去重
       for word in seen: cnt[word] += 1
3. best = max(cnt.values())
4. ans = cnt 中 cnt[word] == best 的词里字典序最小的那个
5. 返回 ans
```

### 3.4 示例演算

![示例 2：三个词并列最高，用字典序破并列](images/bw155_q1_example_walkthrough.svg)

对示例 2 的 `[["good","ok","good"],["ok","bad"],["bad","notsure"],["great","good"]]`：

| 词 | 出现天数 | 判定 |
|------|----------|------|
| good | 2 | 并列最高 |
| ok | 2 | 并列最高 |
| bad | 2 | 并列最高，字典序最小 → **选中** |
| notsure | 1 | 淘汰 |
| great | 1 | 淘汰 |

若按原始数组（不去重）计数，`good` 会变成 3 次、`ok` 变成 2 次、`bad` 变成 2 次，虽然本例答案碰巧仍是 `good`，但示例 1 会立刻暴露错误，所以必须严格按天去重。

## 4. 算法细节

1. **去重的实现**：C++ 用 `unordered_set<string>` 构造当天集合；Python 直接用 `set(day)`。单词长度 $\le 10$，哈希开销很小。
2. **计数语义**：`cnt` 的键是「不同回答」，值是「出现的天数」，因为每个键在每天最多被 `+1` 一次。
3. **并列处理**：先求 `best = max(cnt.values())`，再在满足 `cnt[word] == best` 的词里取字典序最小者，避免在遍历哈希表时用错误的条件比较。
4. **字典序比较**：直接比较字符串（C++ 的 `std::string` 与 Python 的 `str` 都按字典序），无需手写逐字符比较。
5. **返回类型**：题目保证至少有一天、每天至少一个回答，因此 `cnt` 非空，答案一定存在。

## 5. 正确性证明

**引理 1（去重后计数等于天数）**：对任意回答 $w$，上述流程结束后 `cnt[w]` 等于「$w$ 出现在多少天的列表里」的天数。

**证明**：设 $w$ 出现在第 $i_1 < i_2 < \cdots < i_m$ 天。处理第 $i$ 天时，若 $w \in \text{responses}[i]$，则 `seen = set(responses[i])` 中恰有 $w$ 一次，循环体对 `cnt[w]` 恰好执行一次 `+1`；若 $w \notin \text{responses}[i]$，则不会执行。所有天遍历完后，`cnt[w]` 恰好等于 $m$，即出现天数。∎

**引理 2（并列判定正确）**：算法返回的 `ans` 在所有回答中频次最高，且同频次中字典序最小。

**证明**：`best = max(cnt.values())` 是频次上界，`ans` 从 `cnt[word] == best` 的集合中选取，故频次最高；在该集合内取字典序最小者，故满足并列规则。又 `cnt` 的键集合恰为出现过的全部不同回答（由引理 1，未出现的词不会进入 `cnt`），所以不会漏掉候选。∎

**定理**：算法返回的字符串就是题目要求的最常见回答。

**证明**：由引理 1，频次语义与「出现在多少天」一致；由引理 2，最高频次与字典序破并列两条规则同时被满足。题意要求的答案唯一，故返回正确。∎

## 6. 复杂度分析

- **时间**：设总词数为 $N=\sum_i \lvert \text{responses}[i]\rvert$，不同词数为 $D$，单词长度上限为 $L_{\max}\le 10$。建表时每个词插入一次哈希集合、命中一次哈希计数，共 $O(N \cdot L_{\max})$ 的字符哈希开销，可视为 $O(N)$；最后的 `max` 与字典序筛选为 $O(D\cdot L_{\max})$。合计 $O(N)$ 期望时间。
- **空间**：哈希集合与哈希表最多合计 $O(N)$ 个字符串引用；同一时刻只保留当天的集合并加上全局表，字符总量 $O(\sum \lvert \text{word}\rvert)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string findCommonResponse(vector<vector<string>>& responses) {
        unordered_map<string, int> cnt;
        for (auto& day : responses) {
            unordered_set<string> seen(day.begin(), day.end());
            for (auto& s : seen) cnt[s]++;
        }
        string best;
        int bestCnt = -1;
        for (auto& kv : cnt) {
            if (kv.second > bestCnt || (kv.second == bestCnt && kv.first < best)) {
                bestCnt = kv.second;
                best = kv.first;
            }
        }
        return best;
    }
};
```

### Python

```python
from collections import Counter


class Solution:
    def findCommonResponse(self, responses: list[list[str]]) -> str:
        cnt = Counter()
        for day in responses:
            cnt.update(set(day))
        best = max(cnt.values())
        return min(word for word, c in cnt.items() if c == best)
```

## 8. 边界情况与易错点

1. **不按天去重**：最常见的 WA 原因。同一天重复回答会把频次刷高，示例 1 中 `ok` 会被误判为最高频。
2. **「出现次数」与「出现天数」混淆**：本题统计的是**天数**，不是总条数，务必先做集合去重。
3. **并列时忘记取字典序最小**：只写 `>` 判断会返回遍历顺序中的第一个，哈希表遍历顺序不确定，结果不可复现。
4. **字典序用数值/长度比较**：题目要求的是字符串字典序（逐字符 ASCII 比较），不能按长度或数值大小排序。
5. **空答案风险**：约束保证 `responses` 与每天列表都非空，`cnt` 不会为空；若自行加防御，请返回空串而不是越界访问。
6. **性能**：$N$ 可达 $10^6$，避免对每个候选词重扫全部天数，也不要对每天的回答排序（排序是 $O(L\log L)$ 的额外开销，去重只需要 $O(L)$）。
