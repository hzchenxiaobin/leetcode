# LeetCode 单位转换 I 题解

## 1. 题目概述

- **标题 / 题号**：单位转换 I（#3528，medium）
- **链接**：https://leetcode.cn/problems/unit-conversion-i/
- **来源**：LeetCode 第 155 场双周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、图

**题意**：有 $n$ 种单位（编号 $0 \sim n-1$），给出 $n-1$ 条形如 $[\text{sourceUnit}_i, \text{targetUnit}_i, \text{factor}_i]$ 的转换关系，表示「1 个 source 单位 = factor 个 target 单位」。求长度为 $n$ 的数组 `baseUnitConversion`，其中 `baseUnitConversion[i]` 表示「1 个 0 号单位等于多少个 $i$ 号单位」，结果对 $10^9+7$ 取模。

**约束**：

- $2 \le n \le 10^5$
- $\text{conversions.length} = n - 1$
- $0 \le \text{sourceUnit}_i, \text{targetUnit}_i < n$
- $1 \le \text{conversionFactor}_i \le 10^9$
- 保证 0 号单位能通过**唯一**的转换路径（不需要反向转换）到达任何单位

**关键结构性保证**：最后一条约束说明转换关系构成一棵**以 0 为根的有向树**——每个非根节点恰好有一条入边（它的父节点就是「换算到它的那个单位」），且根到每个节点路径唯一。这一点是全部算法的基石。

## 2. 示例

**示例 1**

```text
输入：conversions = [[0,1,2],[1,2,3]]
输出：[1,2,6]
解释：1 个 0 号 = 2 个 1 号；1 个 1 号 = 3 个 2 号，
     所以 1 个 0 号 = 2×3 = 6 个 2 号。
```

**示例 2**

```text
输入：conversions = [[0,1,2],[0,2,3],[1,3,4],[1,4,5],[2,5,2],[4,6,3],[5,7,4]]
输出：[1,2,3,8,10,6,30,24]
解释：ans[0]=1；ans[1]=2；ans[2]=3；
     ans[3]=2×4=8；ans[4]=2×5=10；ans[5]=3×2=6；
     ans[6]=2×5×3=30；ans[7]=3×2×4=24。
```

## 3. 解题思路

### 3.1 暴力思路

对每个目标单位 $i$ 单独求答案：从 $i$ 出发，沿「父指针」一路回溯到 0，把沿途的转换因子乘起来。单次回溯最坏要走 $O(n)$ 条边，总共 $O(n^2)$。$n=10^5$ 时是 $10^{10}$ 次乘法，直接超时。

瓶颈在于**大量路径是重复的**：节点 $3$ 的路径 $0 \to 1 \to 3$ 与节点 $4$ 的路径 $0 \to 1 \to 4$ 共享了前缀 $0 \to 1$。只要从根出发**先算父节点、再算子节点**，每条边就只需用一次。

### 3.2 核心观察：树上的路径乘积可以递推

![转换关系是一棵以 0 为根的树，路径乘积即答案](images/bw155_q2_tree_products.svg)

设 $\text{ans}[v]$ 表示「1 个 0 号单位 = ans[v] 个 $v$ 号单位」，$\text{par}(v)$ 是 $v$ 的父节点，$w(v)$ 是边 $\text{par}(v) \to v$ 上的转换因子。由于换算关系是**链式相乘**：

$$\text{ans}[v] = \text{ans}[\text{par}(v)] \times w(v)$$

理由：1 个 0 号单位等于 $\text{ans}[\text{par}(v)]$ 个父单位，而 1 个父单位又等于 $w(v)$ 个 $v$ 单位，两步相乘即可。这是典型的「树上从根向下递推」——每算完一个节点，它所有儿子的值都可以立刻确定。

再叠加取模：乘法在模意义下封闭，

$$\text{ans}[v] = \big(\text{ans}[\text{par}(v)] \bmod M\big)\cdot\big(w(v) \bmod M\big) \bmod M,\qquad M = 10^9+7$$

所以完全不必构造大整数。

### 3.3 算法流程

![示例 1：沿路径逐层相乘，每一步都取模](images/bw155_q2_example_walkthrough.svg)

```text
1. 建图：把每条 [u, v, w] 存成 u 的子边 (v, w)
2. ans[0] = 1，其余位置先置 0
3. 从 0 开始做一次 DFS/BFS：取出 u，对每个子边 (v, w)：
       ans[v] = ans[u] * w % MOD
       把 v 压入待处理容器
4. 返回 ans
```

用显式栈（迭代 DFS）而不是递归，是为了避开 $n=10^5$ 的递归深度问题。

### 3.4 示例演算

对示例 2，DFS 按树的层序展开，每一步都是「父值 × 因子」：

| 节点 $v$ | 父节点 | 因子 $w$ | 计算 | `ans[v]` |
|----------|--------|----------|------|----------|
| 0 | — | — | 起点 | 1 |
| 1 | 0 | 2 | 1×2 | 2 |
| 2 | 0 | 3 | 1×3 | 3 |
| 3 | 1 | 4 | 2×4 | 8 |
| 4 | 1 | 5 | 2×5 | 10 |
| 5 | 2 | 2 | 3×2 | 6 |
| 6 | 4 | 3 | 10×3 | 30 |
| 7 | 5 | 4 | 6×4 | 24 |

结果 `[1,2,3,8,10,6,30,24]`，与示例输出一致。

## 4. 算法细节

1. **建图方向**：`conversions` 的语义是 source → target 的单向换算，因此只建 `source → target` 的有向边，不需要反向边。题面保证「不需要反向转换」即可到达所有单位。
2. **为什么不会漏节点**：每个非根节点有且只有一条入边，所以从根做一次遍历必然覆盖全部节点（这是树的性质，见 §5 引理 1）。
3. **数据类型**：`ans[u] * w` 可达 $10^9 \times 10^9 = 10^{18}$，C++ 必须用 `long long`（或先对 `ans` 取模再乘）；Python 天然无溢出。
4. **迭代式遍历**：用 `vector<int>` 当栈，先压 0，弹出后给子节点赋值并压栈，遍历顺序可以是任意 DFS 序，不影响结果。
5. **答案数组类型**：题目要求返回 `int[]`，所以最后要把 `long long` 结果转成 `int`（取模后必然在 `int` 范围内）。
6. **初始值**：除根以外先置 0；因为每个节点都会被访问且只赋值一次，占位值不会被读到。

## 5. 正确性证明

**引理 1（结构是树）**：在题设保证下，把每个单位的「父节点」定义为换算到它的那个 source 单位，则所有节点构成一棵以 0 为根的树，且根到每个节点路径唯一。

**证明**：共有 $n$ 个单位、$n-1$ 条换算关系。题面保证从 0 出发可以沿换算方向到达任何单位，即每个节点都存在一条从 0 出发的有向路径，故图弱连通且有 $n-1$ 条边，连通图 $n-1$ 条边即为树（无环）。若某节点有两条不同的入边，则图中入度之和 $\ge n$，边数却只有 $n-1$，与树的性质矛盾；因此每个非根节点恰有一个父节点，父指针无环且必达根 0，根到每个节点的路径唯一。∎

**引理 2（递推式正确）**：对任意非根节点 $v$，$\text{ans}[v] = \text{ans}[\text{par}(v)] \cdot w(v)$。

**证明**：设 $\text{par}(v)=p$。由 $\text{ans}[p]$ 的定义，1 个 0 号单位 $= \text{ans}[p]$ 个 $p$ 单位；由换算关系的定义，1 个 $p$ 单位 $= w(v)$ 个 $v$ 单位。把后一个等式代入前一个，得 1 个 0 号单位 $= \text{ans}[p]\cdot w(v)$ 个 $v$ 单位，这正是 $\text{ans}[v]$ 的定义。∎

**引理 3（取模保持结果）**：对任意整数 $a, b \ge 0$ 与 $M>0$，有 $(a b) \bmod M = \big((a \bmod M)(b \bmod M)\big) \bmod M$。

**证明**：写 $a = q_1 M + r_1$、$b = q_2 M + r_2$，则 $ab = (q_1 q_2 M + q_1 r_2 + q_2 r_1)M + r_1 r_2$，故 $ab \equiv r_1 r_2 \pmod M$，两边取模即得。∎

**定理**：算法输出的数组等于题目要求的 `baseUnitConversion`。

**证明**：对树做归纳。根处 $\text{ans}[0]=1$ 符合「1 个 0 号单位等于 1 个 0 号单位」。设节点 $u$ 的值已正确，则算法在处理边 $u \to v$ 时按引理 2 的公式给 $\text{ans}[v]$ 赋值；由引理 3，边乘边取模与「先算精确乘积再取模」等价，所以 $\text{ans}[v]$ 等于精确值模 $M$。由引理 1，每个节点都会被某条父边恰好赋值一次，故所有位置都正确。∎

## 6. 复杂度分析

- **时间**：建图 $O(n)$；遍历中每条边被处理一次，每次做一次乘法与一次取模，$O(1)$，故遍历 $O(n)$。合计 $O(n)$，$n=10^5$ 时约 $10^5$ 次运算。
- **空间**：邻接表存 $n-1$ 条边，$O(n)$；答案数组与栈各 $O(n)$。合计 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> baseUnitConversions(vector<vector<int>>& conversions) {
        int n = (int)conversions.size() + 1;
        const long long MOD = 1000000007LL;
        vector<vector<pair<int, int>>> adj(n);
        for (auto& e : conversions) {
            adj[e[0]].push_back({e[1], (int)e[2]});
        }
        vector<long long> res(n, 0);
        res[0] = 1;
        vector<int> st;
        st.push_back(0);
        while (!st.empty()) {
            int u = st.back();
            st.pop_back();
            for (auto& nxt : adj[u]) {
                int v = nxt.first, w = nxt.second;
                res[v] = res[u] * w % MOD;
                st.push_back(v);
            }
        }
        vector<int> ans(n);
        for (int i = 0; i < n; i++) ans[i] = (int)res[i];
        return ans;
    }
};
```

### Python

```python
class Solution:
    def baseUnitConversions(self, conversions: list[list[int]]) -> list[int]:
        MOD = 10 ** 9 + 7
        n = len(conversions) + 1
        children = [[] for _ in range(n)]
        for src, dst, factor in conversions:
            children[src].append((dst, factor))

        res = [0] * n
        res[0] = 1
        stack = [0]
        while stack:
            u = stack.pop()
            for v, w in children[u]:
                res[v] = res[u] * w % MOD
                stack.append(v)
        return res
```

## 8. 边界情况与易错点

1. **溢出**：`ans[u] * w` 在取模前可达 $10^{18}$，`int` 必爆，C++ 要用 `long long`；Python 无此问题。
2. **还是溢出**：即使 `ans[u]` 已经取模（$<10^9+7$），乘以 $w\le 10^9$ 仍约为 $10^{18}$，依然要 `long long`。
3. **递归爆栈**：树可能是一条 $10^5$ 长的链，递归 DFS 会栈溢出，必须写迭代。
4. **建了反向边**：题面明确「不需要反向转换」，但多建反向边也不会错（本解法只从根沿有向边走，反向边不会被用到）；真正会错的是**只建反图**——那样从 0 出发一条边都走不出去。
5. **忘记初始化根**：`ans[0]` 必须为 1，它是整个递推的基准。
6. **节点编号不一定是拓扑序**：`conversions` 中边出现顺序任意，不能假设「`i` 号边一定是从小编号指向大编号」，必须老老实实建图后遍历。
7. **`n = 2`**：只有一条边，答案为 `[1, factor]`，代码路径与一般情况一致，无需特判。
