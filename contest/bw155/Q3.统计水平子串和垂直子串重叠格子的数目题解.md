# LeetCode 统计水平子串和垂直子串重叠格子的数目 题解

## 1. 题目概述

- **标题 / 题号**：统计水平子串和垂直子串重叠格子的数目（#3529，medium）
- **链接**：https://leetcode.cn/problems/count-cells-in-overlapping-horizontal-and-vertical-substrings/
- **来源**：LeetCode 第 155 场双周赛 Q3
- **难度**：中等
- **标签**：数组、字符串、矩阵、字符串匹配、哈希函数、滚动哈希

**题意**：给定 $m\times n$ 的字符矩阵 `grid` 与字符串 `pattern`，统计满足下面条件的格子数量：该格子属于**至少一个**等于 `pattern` 的**水平子串**，且属于**至少一个**等于 `pattern` 的**垂直子串**。

- **水平子串**：从左到右连续的 $L$ 个字符（$L=\lvert\text{pattern}\rvert$）；走到行末时**换行**，从下一行行首继续；不会从最后一行回到第一行。
- **垂直子串**：从上到下连续的 $L$ 个字符；走到列末时**换列**，从下一列顶部继续；不会从最后一列回到第一列。

**约束**：

- $m = \text{grid.length}$，$n = \text{grid}[i]\text{.length}$
- $1 \le m, n \le 1000$，$1 \le m\cdot n \le 10^5$
- $1 \le \lvert\text{pattern}\rvert \le m\cdot n$
- `grid` 与 `pattern` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：grid = [["a","a","c","c"],
             ["b","b","b","c"],
             ["a","a","b","a"],
             ["c","a","a","c"],
             ["a","a","b","a"]], pattern = "abaca"
输出：1
解释："abaca" 作为水平子串出现一次、作为垂直子串出现一次，二者交于 1 个格子。
```

**示例 2**

```text
输入：grid = [["c","a","a","a"],
             ["a","a","b","a"],
             ["b","b","a","a"],
             ["a","a","b","a"]], pattern = "aba"
输出：4
解释：所有既属于某个水平 "aba"、又属于某个垂直 "aba" 的格子共 4 个。
```

**示例 3**

```text
输入：grid = [["a"]], pattern = "a"
输出：1
解释：唯一的格子既是水平子串也是垂直子串。
```

## 3. 解题思路

### 3.1 暴力思路

朴素做法是**枚举每个格子的每个方向**：对每个格子，尝试以它作为起点取长度为 $L$ 的水平子串（含跨行）、再和 `pattern` 逐字符比较；垂直同理；最后按格子求交集。子串个数是 $O(mn)$、每次比较 $O(L)$，总代价 $O(mnL)$，最坏 $10^5\times10^5=10^{10}$，超时。

另一条暴力是「对每个格子，检查是否存在某个匹配窗口覆盖它」，同样要枚举 $O(mn)$ 个窗口，重复计算更多。

真正的出路是：**先把二维的"折线路径"压成一维串**，字符串匹配就变成标准问题；再想办法 $O(1)$ 判断每个位置被哪些窗口覆盖。

### 3.2 核心观察：两种展平 + 区间覆盖判定

![按行展平成 H，按列展平成 V](images/bw155_q3_flatten.svg)

**观察一（展平）**：把矩阵按**行优先**顺序拼成一个长为 $m n$ 的串

$$H = \text{grid}[0][0..n-1] + \text{grid}[1][0..n-1] + \cdots + \text{grid}[m-1][0..n-1]$$

那么「从格子 $(r,c)$ 出发的水平子串」恰好是 $H$ 中从下标 $r\cdot n+c$ 开始、长为 $L$ 的**窗口**——因为行优先顺序天然实现了「行末接下一行行首」的换行语义。同理，按**列优先**顺序拼成

$$V = \text{grid}[0..m-1][0] + \text{grid}[0..m-1][1] + \cdots + \text{grid}[0..m-1][n-1]$$

则垂直子串就是 $V$ 上长为 $L$ 的窗口，格子 $(r,c)$ 在 $V$ 中的位置是 $c\cdot m+r$。

「不回卷」意味着窗口必须完整落在数组内，即起点 $s \in [0,\,mn-L]$。

**观察二（覆盖判定）**：设 $L=\lvert\text{pattern}\rvert$。位置 $p$ 的格子被某个窗口覆盖，当且仅当存在匹配起点 $s$ 满足

$$s \le p \le s + L - 1 \iff s \in [\,p-L+1,\ p\,]$$

于是只要知道「所有匹配起点」，每个位置是否被覆盖就是一个**滑动窗口里有没有匹配起点**的问题：随着 $p$ 递增，区间右端进入一个新的起点、左端移出一个旧起点，用计数器维护即可 $O(1)$ 更新。

### 3.3 算法流程

```text
1. 按行优先展开得到 H，按列优先展开得到 V，长度均为 M = m*n
2. hcov = cover(H, pattern)，vcov = cover(V, pattern)
       cover(text, pat):
           L = len(pat)
           用 KMP 求出 text 中所有匹配起点 start[s] = true（匹配结束于 i 时 s = i-L+1）
           window = 0
           for p in 0..M-1:
               if p <= M-L and start[p]:      window += 1     // 新起点入窗
               if p-L >= 0 and start[p-L]:    window -= 1     // 旧起点出窗
               cov[p] = (window > 0)
3. ans = 0
   for 每个格子 (r, c):
       if hcov[r*n + c] and vcov[c*m + r]: ans += 1
4. 返回 ans
```

### 3.4 示例演算

![示例 2：H 匹配起点 {5,13}，V 匹配起点 {1,5,8,10}](images/bw155_q3_example_walkthrough.svg)

以示例 2 为例，$m=n=4$、$L=3$：

- 行优先 $H$ 上 `"aba"` 的匹配起点是 $5$ 和 $13$（其中起点 $5$ 就在跨行处）；
- 列优先 $V$ 上 `"aba"` 的匹配起点是 $1,5,8,10$（$5,8,10$ 都跨列）；
- 水平覆盖的格子：起点 $5$ 覆盖 $5,6,7$ 即 $(1,1),(1,2),(1,3)$；起点 $13$ 覆盖 $(3,1),(3,2),(3,3)$；
- 垂直覆盖的格子：起点 $1$ 覆盖 $(1,0),(2,0),(3,0)$；$5$ 覆盖 $(1,1),(2,1),(3,1)$；$8$ 覆盖 $(0,2),(1,2),(2,2)$；$10$ 覆盖 $(2,2),(3,2),(0,3)$；
- 交集为 $(1,1),(1,2),(3,1),(3,2)$，共 $4$ 个，与输出一致。

这也说明「允许跨行/跨列」不能省：若只允许在单行/单列内匹配，$V$ 上的起点 $5,8,10$ 都会丢失，答案会错算成 $3$。

再看示例 1（$5\times4$，`pattern = "abaca"`）：行优先串上唯一的匹配起点是 $9$，它覆盖下标 $9\sim13$，即格子 $(2,1),(2,2),(2,3),(3,0),(3,1)$——**横跨了第 2 行末尾与第 3 行行首**；而列优先串上的匹配起点是 $0$，覆盖 $(0,0),(1,0),(2,0),(3,0),(4,0)$，不跨列。两者的交集只有 $(3,0)$ 这一个格子，正好是答案 1。如果误以为水平子串不能跨行，示例 1 会得到 0，这就是「换行」语义最直接的判据。

## 4. 算法细节

1. **展平的实现**：C++ 直接双重循环 `push_back`；Python 用生成器 + `join`。两种展平都要 $O(mn)$，不要用字符串拼接（$O(m^2n^2)$）。
2. **匹配算法**：用 **KMP**，预处理 `lps` 数组 $O(L)$，扫描文本 $O(M)$，逐个记录匹配**起点**。也可用滚动哈希或 `std::string::find` 循环，但 KMP 是确定性的 $O(M+L)$。
3. **滑动窗口的下标范围**：匹配起点只可能落在 $[0, M-L]$，所以「入窗」要判 `p <= M-L`；「出窗」要判 `p-L >= 0`。两处任一漏判都会数组越界或计数错误。
4. **覆盖数组用 `vector<char>`/`bool`**：$M\le 10^5$，内存无所谓，但用 `char` 更省且不影响性能。
5. **坐标换算**：行优先位置 `posH = r*n + c`；列优先位置 `posV = c*m + r`。两者**不能**共用同一个下标，这是本题最容易写错的地方（把 $m$ 和 $n$ 用反）。
6. **最后统计**：双重循环遍历原矩阵，同时查两张覆盖表，$O(mn)$。

## 5. 正确性证明

**引理 1（展平双射）**：对任意起点 $p \in [0, mn-L]$，$H[p \dots p+L-1]$ 恰为「从格子 $(p\operatorname{div} n,\ p\bmod n)$ 出发的水平子串」；反之每个水平子串都对应某个这样的窗口。对 $V$ 与垂直子串同理（起点 $q$ 对应格子 $(q \bmod m,\ q\operatorname{div} m)$）。

**证明**：行优先把格子 $(r,c)$ 映射到下标 $r n+c$，且下标 $+1$ 正好是「同一行右移一格，若已到行末则下一行行首」，这正是题面对水平子串换行语义的定义；$p$ 与 $p+L-1$ 均不超过 $mn-1$ 保证子串不越界，也就是「不回卷」。反方向：给定水平子串的起点格 $(r,c)$，取 $p = rn+c$ 即得同一个窗口。列优先同理，$(r,c)\mapsto cm+r$，下标 $+1$ 对应「同列下移一行，到列末则下一列顶部」。∎

**引理 2（覆盖判定）**：位置 $p$ 被某个等于 `pattern` 的窗口覆盖 $\iff$ 存在匹配起点 $s\in[0, mn-L]$ 使 $s\le p\le s+L-1$。

**证明**：窗口 $[s, s+L-1]$ 覆盖位置 $p$ 的定义就是 $p$ 落在区间内。匹配起点集合由引理 1 与「窗口内容等于 pattern」共同刻画，故存在性等价于被某个匹配窗口覆盖。∎

**引理 3（KMP + 滑动窗口求出全部覆盖）**：`cover` 过程结束后，`cov[p]` 为真当且仅当位置 $p$ 被某匹配窗口覆盖。

**证明**：KMP 扫描结束时，每当 `j == L` 就记录起点 $i-L+1$，而 KMP 的正确性保证「文本中每一处与 pattern 相等的子串都会且仅会在其末尾触发一次」，故 `start` 与匹配起点集合完全一致。滑动窗口部分：处理到 $p$ 时，计数器 `window` 恰好统计了区间 $[p-L+1, p]$ 内 `start` 为真的个数——因为每次进入 $p$ 时加入了 `start[p]`（若 $p\le M-L$）、移出了 `start[p-L]`（若 $p-L\ge 0$），而此前已累加了 $[p-L, p-1]$ 的计数，归纳可知区间恰为 $[p-L+1,p]$。故 `cov[p] = window > 0` 与引理 2 等价。∎

**定理**：算法返回值等于同时属于某个水平匹配子串与某个垂直匹配子串的格子数。

**证明**：`hcov[r*n+c]` 为真当且仅当格子 $(r,c)$ 属于某个等于 `pattern` 的水平子串（引理 1、3 合并），`vcov[c*m+r]` 为真当且仅当它属于某个垂直匹配子串。算法对每个格子做一次「与」判定并计数，因此计数恰好是满足两个条件的格子数。∎

## 6. 复杂度分析

- **时间**：两次展平各 $O(mn)$；KMP 预处理 $O(L)$、扫描 $O(mn)$；滑动窗口与最终统计各 $O(mn)$。合计 $O(mn + L)$，$mn\le 10^5$ 时约 $10^5$ 量级运算。
- **空间**：两个展平串各 $O(mn)$，`lps` 数组 $O(L)$，两张覆盖表各 $O(mn)$。合计 $O(mn + L)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countCells(vector<vector<char>>& grid, string pattern) {
        int m = (int)grid.size(), n = (int)grid[0].size();
        int total = m * n;
        string H, V;
        H.reserve(total);
        V.reserve(total);
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++) H.push_back(grid[i][j]);
        for (int j = 0; j < n; j++)
            for (int i = 0; i < m; i++) V.push_back(grid[i][j]);

        vector<char> hcov(total, 0), vcov(total, 0);
        mark(H, pattern, hcov);
        mark(V, pattern, vcov);

        int ans = 0;
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (hcov[i * n + j] && vcov[j * m + i]) ans++;
        return ans;
    }

private:
    // cov[pos] = 位置 pos 的格子是否落在某个等于 pat 的窗口内
    void mark(const string& text, const string& pat, vector<char>& cov) {
        int M = (int)text.size(), L = (int)pat.size();
        vector<int> lps(L, 0);
        for (int i = 1; i < L; i++) {
            int j = lps[i - 1];
            while (j > 0 && pat[i] != pat[j]) j = lps[j - 1];
            if (pat[i] == pat[j]) j++;
            lps[i] = j;
        }
        vector<char> start(M, 0);
        int j = 0;
        for (int i = 0; i < M; i++) {
            while (j > 0 && text[i] != pat[j]) j = lps[j - 1];
            if (text[i] == pat[j]) j++;
            if (j == L) {
                start[i - L + 1] = 1;
                j = lps[j - 1];
            }
        }
        int window = 0;
        for (int pos = 0; pos < M; pos++) {
            if (pos <= M - L && start[pos]) window++;
            if (pos - L >= 0 && start[pos - L]) window--;
            cov[pos] = (window > 0);
        }
    }
};
```

### Python

```python
class Solution:
    def countCells(self, grid: list[list[str]], pattern: str) -> int:
        m, n = len(grid), len(grid[0])
        horizontal = ''.join(grid[i][j] for i in range(m) for j in range(n))
        vertical = ''.join(grid[i][j] for j in range(n) for i in range(m))

        hcov = self._cover(horizontal, pattern)
        vcov = self._cover(vertical, pattern)

        return sum(
            1
            for i in range(m)
            for j in range(n)
            if hcov[i * n + j] and vcov[j * m + i]
        )

    def _cover(self, text: str, pat: str) -> list[bool]:
        """cov[pos]：位置 pos 是否落在某个等于 pat 的长度为 L 的窗口内。"""
        M, L = len(text), len(pat)
        cov = [False] * M
        if L > M:
            return cov

        # KMP 求 pattern 的 lps 数组
        lps = [0] * L
        for i in range(1, L):
            j = lps[i - 1]
            while j and pat[i] != pat[j]:
                j = lps[j - 1]
            if pat[i] == pat[j]:
                j += 1
            lps[i] = j

        # 记录每个匹配窗口的起点
        start = [False] * (M - L + 1)
        j = 0
        for i, ch in enumerate(text):
            while j and ch != pat[j]:
                j = lps[j - 1]
            if ch == pat[j]:
                j += 1
            if j == L:
                start[i - L + 1] = True
                j = lps[j - 1]

        # 滑动窗口：位置 pos 覆盖 [pos-L+1, pos] 内的所有窗口起点
        window = 0
        for pos in range(M):
            if pos <= M - L and start[pos]:
                window += 1
            if pos - L >= 0 and start[pos - L]:
                window -= 1
            cov[pos] = window > 0
        return cov
```

## 8. 边界情况与易错点

1. **`pattern` 比整张矩阵还长**：$L>mn$ 时不存在任何窗口，答案 0。代码中 KMP 不会触发匹配、滑动窗口计数恒 0，`_cover` 里还显式提前返回，两条路都安全。
2. **`L = mn`**：只有唯一一个窗口（整张矩阵的展平），起点只能是 0；此时答案为「$H=V=$ pattern 时的全部格子数」或 0。
3. **`L = 1`**：窗口只覆盖自身；覆盖表的入窗/出窗逻辑退化，仍正确。示例 3 就是这种情形。
4. **坐标换算写反**：`hcov` 用 `r*n+c`，`vcov` 用 `c*m+r`；把 $m,n$ 互换是本题最高频的 WA。
5. **忘记允许跨行/跨列**：只在单行/单列内做匹配会漏掉跨边界窗口（示例 2 的 $5,8,10$ 三个起点全是跨列匹配）。
6. **误以为可以回卷**：水平方向不会从最后一行回到第一行、垂直方向不会从最后一列回到第一列，所以窗口起点必须 $\le mn-L$，不能把展平串当成循环串。
7. **滑动窗口下标越界**：`start` 只有 $M-L+1$ 个元素，取 `start[pos]` 前必须判 `pos <= M-L`，取 `start[pos-L]` 前必须判 `pos-L >= 0`。
8. **单行/单列矩阵**：$m=1$ 时垂直方向就是列优先展平后的整串，$n=1$ 时水平方向同理，逻辑无需特判，但要保证展平循环的行列数正确。
9. **结果范围**：答案是格子数，最多 $mn\le 10^5$，`int` 足够。
