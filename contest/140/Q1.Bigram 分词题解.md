# LeetCode Bigram 分词 题解

## 1. 题目概述

- **标题 / 题号**：Bigram 分词（#1078，easy）
- **链接**：https://leetcode.cn/problems/occurrences-after-bigram/
- **来源**：LeetCode 第 140 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定文本 `text` 与两个词 `first`、`second`，在 `text` 中寻找所有形如 `"first second third"` 的连续词片段：`second` 紧随 `first` 出现、`third` 紧随 `second` 出现。把每种这样的片段里的 `third` 按出现顺序收集成一个列表返回；同一位置只计一次，不同位置（即使词相同）都要保留。

**约束**：

- $1 \le \text{text.length} \le 1000$
- `text` 只含小写英文字母和空格，**单词之间恰好一个空格**，且无前缀、尾随空格
- $1 \le \text{first.length}, \text{second.length} \le 10$，两者只含小写字母

**一句话转化**：先把字符串切成词数组 $w$，问题就变成「在 $w$ 上找所有满足 $w[i] = \text{first}$ 且 $w[i+1] = \text{second}$ 的下标 $i$，收集 $w[i+2]$」。

## 2. 示例

**示例 1**

```text
输入：text = "alice is a good girl she is a good student", first = "a", second = "good"
输出：["girl","student"]
解释：
  "...a good girl..."     → 输出 "girl"
  "...a good student"     → 输出 "student"
```

**示例 2**

```text
输入：text = "we will we will rock you", first = "we", second = "will"
输出：["we","rock"]
解释：
  "we will we"    → 输出 "we"
  "we will rock"  → 输出 "rock"
```

**补充示例（重叠出现，非官方）**

```text
输入：text = "a a a a", first = "a", second = "a"
输出：["a","a"]
解释：i=0 的 "a a a" 与 i=1 的 "a a a" 都成立，两个窗口共享中间的 "a"，要输出两次。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**在原始字符串上做模式匹配**：对每个字符位置，尝试比较 `first + " " + second + " "` 这段前缀，命中后再往后截取一个词。单次比较 $O(\lvert \text{first} \rvert + \lvert \text{second} \rvert)$，共 $O(L)$ 个位置，最坏 $O(L^2)$；而且为了不漏掉相邻窗口重叠的情况，命中后不能直接跳过整个片段，必须只前进到下一个词的起点——这个「手动维护词边界」的细节正是最容易写错的地方。

$L \le 1000$ 时暴力完全跑得动，但它把「字符」和「词」两层结构混在一起。更好的做法是**先分词再匹配**：分词是一次 $O(L)$ 的线性扫描，之后问题退化为数组上的定长窗口问题，边界条件也全部由数组下标表达。

### 3.2 核心观察：三元窗口，起点每次只 +1

![三元窗口只右移一格](images/wc140_q1_triple_window.svg)

分词之后，一次「出现」就是**三个相邻词** $w[i], w[i+1], w[i+2]$ 按序等于 `first`、`second`、`third`。于是：

- **判定只看两个词**：命中条件是 $w[i] = \text{first}$ 且 $w[i+1] = \text{second}$，第三个词 $w[i+2]$ 只是被动的输出，不参与判定。
- **起点范围是 $0 \le i \le n-3$**：合法三元组恰好 $n-2$ 个，再往后就凑不出第三个词。
- **窗口之间会重叠**：起点 $i$ 的第三词 $w[i+2]$ 正是起点 $i+2$ 的第一词（图示中下标 2 的 `we` 被两个虚线框共用）。两次命中是**两次不同的出现**，所以输出不能去重、起点也不能因为命中就跳三格。
- **比较的是整词**：`"a"` 不该匹配 `"alice"`，因此必须整词相等；由于分隔符固定为单个空格，这项检查就是一次字符串相等。

### 3.3 算法流程

![算法流程图](images/wc140_q1_algorithm_flow.svg)

```text
1. words = split(text)          // 按空格切分，得到 n 个词
2. ans = 空列表
3. 对 i = 0, 1, ..., n-3：
4.     若 words[i] == first 且 words[i+1] == second：
5.         ans.append(words[i+2])
6. 返回 ans
```

循环上界写成 `i + 2 < n` 而不写 `i <= n - 3`，是为了避开无符号整数在 $n < 3$ 时的下溢（见 §4 与 §8）。

### 3.4 示例演算

![示例 2 逐窗口走查](images/wc140_q1_walkthrough.svg)

以 `text = "we will we will rock you"`、`first = "we"`、`second = "will"` 为例，$n = 6$，合法起点是 $i = 0,1,2,3$：

| $i$ | $w[i]\ \vert\ w[i+1]\ \vert\ w[i+2]$ | 命中 | `ans` |
|-----|--------------------------------------|------|-------|
| 0 | `we \| will \| we` | ✓ | `["we"]` |
| 1 | `will \| we \| will` | ✗ | `["we"]` |
| 2 | `we \| will \| rock` | ✓ | `["we","rock"]` |
| 3 | `will \| rock \| you` | ✗ | `["we","rock"]` |

结果 `["we","rock"]`，与官方示例 2 一致。注意 $i=0$ 输出的 `we` 又是 $i=2$ 窗口的首词，两个窗口互相重叠却互不影响。

## 4. 算法细节

1. **分词方式**：Python 用无参数的 `text.split()`（自动压缩连续空白，比 `split(" ")` 更不容易被脏数据坑到）；C++ 用 `istringstream` 按 `>>` 逐个取词，语义相同。
2. **不要重复分词**：只在开头切一次存成数组，之后全程按下标访问，避免在循环里反复 `find` 空格。
3. **循环上界**：条件写 `i + 2 < n`（或 Python 的 `range(n - 2)`，$n < 3$ 时 `range` 自动为空），C++ 中若用 `i <= n - 3` 且把 `n` 声明为 `size_t`，$n<3$ 时会发生下溢得到巨大正数而数组越界。
4. **整词相等比较**：`words[i] == first`，绝不能用 `words[i].find(first) == 0` 之类的**前缀**判断，否则 `first = "a"` 会误匹配 `"alice"`。
5. **命中后不跳步**：把 `i` 递增 3 会漏掉 $i+2$ 处的新窗口，正确答案因此变少；本循环天然每步 `+1`，重叠情况自动覆盖。
6. **用列表而不是集合**：答案是有序的**多重集**（重复词各占一项），`set` 会静默吞掉重复，顺序也会丢失。
7. **`first == second` 无需特判**：条件退化为 $w[i] = w[i+1] = \text{first}$，逻辑仍然正确。

## 5. 正确性证明

记 `text` 分词后得到词数组 $w[0..n-1]$，$\text{first} = f$、$\text{second} = s$。

**引理 1（分词保序且一一对应）**：由题面约束（单词之间恰好一个空格、无前缀与尾随空格），按空格切分得到的 $w$ 与 `text` 中的词逐一对应，且顺序相同。

**证明**：`text` 中没有连续空格也没有首尾空格，每个空格恰好分隔两个词。因此词的数量等于空格数加一，第 $k$ 个词恰好是第 $k-1$ 个空格与第 $k$ 个空格之间的非空子串，切分结果与「词序列」的定义完全一致。∎

**引理 2（窗口判定）**：对任意 $0 \le i \le n-3$，$w[i], w[i+1], w[i+2]$ 构成一次形如 `"first second third"` 的出现，当且仅当 $w[i] = f$ 且 $w[i+1] = s$；此时 $w[i+2]$ 就是该次出现对应的 `third`。

**证明**：

- 必要性：若 $w[i], w[i+1], w[i+2]$ 构成该形式，按定义前两个词分别等于 $f$、$s$，第三个词即 `third`。
- 充分性：若 $w[i]=f$、$w[i+1]=s$，令 $t = w[i+2]$，则三元组按序为 $f, s, t$，即 `"first second third"` 形式，且 $t$ 是要收集的词。

∎

**引理 3（枚举完备且有序）**：循环恰好让 $i$ 从 $0$ 递增到 $n-3$ 各取值一次，因此 $w$ 的所有合法三元组被不重不漏地访问，且 `ans` 中元素的追加顺序与 $i$ 的递增顺序一致。

**证明**：`range(n-2)` / `i + 2 < n` 产生的整数集合正是 $\{0,1,\dots,n-3\}$（$n \ge 3$；$n < 3$ 时为空集，恰无合法三元组）。每个 $i$ 对应唯一的窗口 $w[i..i+2]$，不同 $i$ 对应不同窗口，故不重不漏；`ans.append` 只在循环体内发生，追加次序即 $i$ 的次序。∎

**定理**：算法返回的列表恰好是题目要求的全部 `third`，顺序与出现位置一致，且重复出现不被合并。

**证明**：由引理 1 可把原问题等价地搬到数组 $w$ 上。由引理 2，循环对每个 $i$ 的判定与其输出分别精确对应「是否是一次出现」与「该次出现的 `third`」。由引理 3，所有出现都被枚举且顺序正确，且每次命中都无条件 `append`（没有去重或跳步），因此重复出现各占一项。三者合起来即得结论。∎

## 6. 复杂度分析

- **时间**：$O(L)$，其中 $L = \lvert \text{text} \rvert \le 1000$。分词一次线性扫描 $O(L)$；窗口共 $n-2$ 个，每个做至多两次整词比较，单次 $O(\lvert \text{first} \rvert)$ 或 $O(\lvert \text{second} \rvert)$，而所有词长之和不超过 $L$，因此总比较代价被 $O(L)$ 界定。
- **空间**：$O(n)$ 用于存放词数组（$n$ 为词数，$n \le L$），答案列表最坏 $O(n)$。若不缓存词数组、改为流式维护「前两个词」，可把额外空间降到 $O(1)$，但代码可读性下降。

## 7. 参考代码

### C++

```cpp
#include <sstream>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> findOcurrences(string text, string first, string second) {
        vector<string> words;
        istringstream iss(text);
        string w;
        while (iss >> w) words.push_back(w);   // 按空白切分出所有词

        vector<string> ans;
        int n = (int)words.size();
        for (int i = 0; i + 2 < n; ++i) {      // 用 i + 2 < n 避免 n < 3 时的下溢
            if (words[i] == first && words[i + 1] == second) {
                ans.push_back(words[i + 2]);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findOcurrences(self, text: str, first: str, second: str) -> list[str]:
        words = text.split()          # 单词间恰好一个空格，无参数 split 已足够
        ans = []
        for i in range(len(words) - 2):   # n < 3 时 range 为空，自动返回 []
            if words[i] == first and words[i + 1] == second:
                ans.append(words[i + 2])
        return ans
```

## 8. 边界情况与易错点

1. **词数不足 3**：`"a b"`、`"a"` 这类输入必须返回空列表。C++ 里写 `i <= n - 3` 且 `n` 为无符号类型时会下溢成巨大值，是本题最典型的越界崩溃。
2. **重叠命中不能去重**：`text = "a a a a"`、`first = "a"`、`second = "a"` 的答案是 `["a","a"]`；用 `set` 或命中后 `i += 3` 都只剩一项。
3. **`first == second`**：如 `"a a b a a b"`，答案 `["b","b"]`（$i=0$ 与 $i=3$ 两次命中），不要因为两个参数相同就跳过或特判。
4. **整词匹配而非前缀匹配**：`first = "a"` 时 `"alice"`、`"and"` 都不算命中；同理 `third` 也可能与 `first`/`second` 相同（示例 2 输出的 `"we"` 正是如此），照常收集。
5. **输出顺序**：题目要求按出现位置从左到右，返回有序列表即可，不要排序（排序会破坏出现顺序）。
6. **空结果表示**：返回空 `vector` / 空 `list`，不要返回 `nullptr` 或 `None`；C++ 直接 `return ans;`。
7. **不必要的字符串拼接**：不必构造 `first + " " + second` 再去 `find`，分词后按词比较既简单又能正确处理「词是更长单词的前缀」这类陷阱。
