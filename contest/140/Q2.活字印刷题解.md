# LeetCode 活字印刷 题解

## 1. 题目概述

- **标题 / 题号**：活字印刷（#1079，medium）
- **链接**：https://leetcode.cn/problems/letter-tile-possibilities/
- **来源**：LeetCode 第 140 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、回溯、计数

**题意**：有一套活字字模 `tiles`，每个字模上刻一个字母，且**每个字模最多只能用一次**。用任意多个字模（≥ 1）排成一个序列，问一共能印出多少个**不同**的非空字母序列。

关键一点：序列是否相同只看**字母内容和长度**，与「用了哪几个下标的字模」无关。`tiles = "AAB"` 里两个 `A` 互换位置，印出来的都还是 `"AAB"`，只能算一次。

**约束**：

- $1 \le n = \lvert \text{tiles} \rvert \le 7$
- `tiles` 只由大写英文字母组成
- 答案上界：字母全不同时 $\sum_{k=1}^{7} P(7,k) = 13699$，普通 32 位整数足够

## 2. 示例

**示例 1**

```text
输入：tiles = "AAB"
输出：8
解释：可能的序列：A, B, AA, AB, BA, AAB, ABA, BAA 共 8 个。
      注意 "A(0)A(1)B" 与 "A(1)A(0)B" 是同一个串，只算一次。
```

**示例 2**

```text
输入：tiles = "AAABBC"
输出：188
解释：3 个 A、2 个 B、1 个 C，按长度 1~6 的串数分别为 3、8、19、38、60、60，
      合计 188；而按下标枚举时，仅长度为 6 的排列就有 6! = 720 个，其中大量重复。
```

**示例 3**

```text
输入：tiles = "V"
输出：1
解释：只有一个字模，只能印出单字母序列 "V"。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的方法：把字模当成 $n$ 个**互不相同**的物件，枚举长度 $1 \sim n$ 的所有下标排列，每一组排列按顺序拼成字符串塞进 `set`，最后看 `set` 的大小。长度 $k$ 的排列有 $P(n,k)$ 个，总数

$$\sum_{k=1}^{n} P(n,k) \le \sum_{k=1}^{7} P(7,k) = 13699$$

单次拼接 $O(k)$，总复杂度 $O(n \cdot e \cdot n!)$。$n \le 7$ 时勉强能跑，但思路有明显缺陷：

- **冗余**：同一个串被多个下标排列重复产出。`"ABA"` 在 `"AAB"` 里就有 $2$ 种下标顺序（两个 `A` 谁在前），重复率随重复字母数量指数上升。
- **状态里混进了无关信息**：下标是「哪一个字模」，而答案只关心「还剩哪些字母」；把下标写进状态后，本质相同的子问题无法合并，记忆化也失去意义。$n = 15$ 时 $\sum P(15,k) \approx 3.6 \times 10^{12}$，直接崩掉。

所以真正要做的不是「加速枚举」，而是换一个**没有冗余**的状态。

### 3.2 核心观察：状态是「每个字母还剩几个」

![多重集状态模型：按字母分支而不是按下标分支](images/wc140_q2_letter_branch_model.svg)

把 `tiles` 压成一个计数向量

$$s = (s_A, s_B, \dots, s_Z), \qquad s_c = \#\{\, i \mid \text{tiles}[i] = c \,\}$$

对 `"AAB"` 就是 $s_A = 2, s_B = 1$，其余为 $0$。**两个不同的下标集合，只要字母计数相同，能印出的序列集合就完全相同**——这正是可以合并子问题的依据。

接着观察「序列如何被唯一分解」：任一非空序列，它的**首字母是唯一的**。设首字母为 $c$，那么它等于 $c$ 拼上「从 $s - e_c$ 出发印出的某个序列」（这个后缀可以是空串）。于是按首字母把全部序列分成 $|\{c : s_c > 0\}|$ 类，**类与类不重不漏**。定义

$$g(s) = \text{从剩余计数 } s \text{ 出发能印出的序列总数（含空序列）}$$

就有递推

$$g(s) = 1 + \sum_{c:\, s_c > 0} g(s - e_c), \qquad g(\mathbf{0}) = 1$$

其中 $e_c$ 表示「字母 $c$ 少用一个」，首项 $1$ 是空序列。最终答案 $= g(s_0) - 1$，扣掉空序列。

> 💡 **去重的本质**：每层只对**不同的字母**分支。即使还剩 2 个 `A`，首字母 `A` 也只走一个分支——两个 `A` 产出的串完全一样，只该数一次。

状态数等于 $\prod_{c}(s_c + 1)$。在 $\sum s_c = n$ 固定的前提下，把 $n$ 拆成尽量多的 $1$ 时乘积最大，所以 $n \le 7$ 时状态数 $\le 2^7 = 128$。整个搜索空间是**常数级**的。

### 3.3 算法流程 / 状态转移

![记忆化搜索流程](images/wc140_q2_state_dp_flow.svg)

```text
numTilePossibilities(tiles):
    cnt[0..25] ← tiles 中每个字母的出现次数
    return g(cnt) - 1

g(cnt):                          # 返回「含空序列」的序列数
    if cnt 在 memo 中: return memo[cnt]
    total ← 1                    # 空序列
    for c in 0..25:
        if cnt[c] > 0:
            cnt[c] ← cnt[c] - 1  # 首字母选 c
            total ← total + g(cnt)
            cnt[c] ← cnt[c] + 1  # 回溯
    memo[cnt] ← total
    return total
```

递归深度等于已用字模数，最多 $7$ 层；每层最多枚举 $26$ 个字母。因为状态和严格递减，递归一定终止。

### 3.4 示例演算

![tiles = "AAB" 的状态与计数](images/wc140_q2_walkthrough.svg)

以 `"AAB"` 为例，$s_0 = (2, 1)$，自底向上填表：

| 状态（A,B） | 含义 | 递推 | $g$ 值 |
|-------------|------|------|--------|
| (0,0) | 没有字模了 | 只有空序列 | 1 |
| (1,0) | 只剩 1 个 A | $1 + g(0,0)$ | 2 |
| (2,0) | 只剩 2 个 A | $1 + g(1,0)$ | 3 |
| (0,1) | 只剩 1 个 B | $1 + g(0,0)$ | 2 |
| (1,1) | 1 个 A、1 个 B | $1 + g(0,1) + g(1,0)$ | 5 |
| (2,1) | 起点 | $1 + g(1,1) + g(2,0)$ | 9 |

答案 $= g(2,1) - 1 = 9 - 1 = 8$，与官方示例一致。逐类展开 $g(2,1)$ 的两个分支：

- 首字母 `A`：$g(1,1) = 5$ 个——把 (1,1) 状态能印出的 5 个串（含空串）各加前缀 `A`，得到 `A, AA, AB, AAB, ABA`；
- 首字母 `B`：$g(2,0) = 3$ 个，产出 `B, BA, BAA`。

两边合起来 `A, AA, AB, AAB, ABA, B, BA, BAA`，恰好 8 个，没有重复。

## 4. 算法细节

1. **用计数数组代替字符串**：`cnt[26]` 由一次线性扫描得到，状态就是它本身；不需要排序、不需要哈希字符串内容。
2. **状态键的构造**：C++ 里把 26 个计数逐字节 `push_back` 成 `string` 当键（计数 $\le 7$，落进 `char` 安全）；Python 里用 `tuple(cnt)`（`list` 不可哈希，不能当键）。
3. **回溯必须成对**：`cnt[c]--` 后立刻递归，返回后马上 `cnt[c]++`。忘记恢复会让后续分支少一个字母、答案偏小，且这种 bug 只在有重复字母的数据上才明显。
4. **空序列口径统一**：把「空序列」固定算 $1$，只在最外层减一次。若改成给递归多加一个「当前长度」参数、在每层判断长度 > 0，状态就从「剩余计数」变成了「剩余计数 + 已用长度」，更容易漏算。
5. **只对 `cnt[c] > 0` 的不同字母分支**：这是整个算法**唯一**的去重手段。即使有 3 个 `A`，首字母 `A` 也只进一次递归——3 个 `A` 是「同一字母的副本」，产出完全相同。
6. **记忆化必须按「计数向量」建键**：按「下标是否使用」建键是 $2^n$ 个子集状态，既慢又把本可合并的子问题拆开；而按计数建键时，`"AAB"` 的两种下标顺序会落到同一个键上。
7. **复杂度上界**：状态数 $\prod(s_c+1) \le 2^7 = 128$，每状态 $O(26)$ 次尝试，总计约 $3300$ 次运算，远低于任何限制。
8. **不要用子集 DP**：`2^n` 子集枚举解决的是「选哪些字模」（组合），而本题要的是「按顺序排列」（排列），两者不是同一个问题。

## 5. 正确性证明

**引理 1（状态充分性）**：若两个状态的计数向量相同，则从它们出发能印出的序列集合完全相同。

**证明**：一个序列能否被印出，只取决于「每种字母各需要几个」是否超过剩余量；计数向量相同意味着对每个字母 $c$ 剩余量相同，记 $\text{need}_c(T)$ 为串 $T$ 中字母 $c$ 的个数，则 $T$ 可印出当且仅当对每个 $c$ 有 $\text{need}_c(T) \le s_c$；两种状态的 $s_c$ 逐项相同，故该条件同真同假。∎

**引理 2（分支互不相交）**：对 $c \ne c'$，首字母为 $c$ 的序列与首字母为 $c'$ 的序列不可能是同一个序列。

**证明**：一个序列的首字符唯一确定，$c \ne c'$ 时两串第一位就不同。∎

**引理 3（分支覆盖完整）**：任一从状态 $s$ 可印出的非空序列 $T$，都恰好属于某个分支 $c$（$T$ 的首字母），且其后缀 $T'$ 从 $s - e_c$ 可印出（可为空）。

**证明**：设 $T$ 的首字母为 $c$。因 $T$ 可印出，必有 $s_c \ge 1$，故分支 $c$ 存在；去掉首字母后，$T'$ 对字母 $c$ 的需求减少 1、其余不变，仍满足不超过 $s - e_c$ 的剩余量，故 $T'$ 从 $s - e_c$ 可印出。∎

**引理 4（终止性）**：递归在有限步内结束。

**证明**：每次递归调用都把 $\sum_c s_c$ 减少 1，且 $\sum_c s_c \ge 0$，故最多 $n$ 层即到达 $g(\mathbf{0})$。∎

**定理**：`numTilePossibilities` 返回的值等于可印出的不同非空序列个数。

**证明**：对 $n = \sum_c s_c$ 归纳证明 $g(s)$ 恰为从 $s$ 可印出的序列数（含空序列）。

- 基础：$n = 0$ 时只有空序列，$g(\mathbf{0}) = 1$，成立。
- 归纳：设所有 $n' < n$ 的状态成立。由引理 3，$s$ 的可印序列 = $\{\text{空序列}\} \cup \bigcup_{c: s_c>0} \{\, c \cdot T' : T' \text{ 从 } s - e_c \text{ 可印}\,\}$，二者之外无遗漏；由引理 2，各分支互不相交；由归纳假设，分支 $c$ 的大小为 $g(s - e_c)$。故总数 $= 1 + \sum_{c} g(s - e_c)$，与递推式一致。
- 记忆化只缓存已算过的值，由引理 1 相同状态答案相同，不会改变结果。

最后扣掉唯一的空序列，得到非空不同序列数。∎

## 6. 复杂度分析

- **时间**：$O(26 \cdot S + n)$，其中 $S = \prod_{c}(s_c + 1)$ 是状态数。每个状态枚举 26 个字母做常数次操作；$n \le 7$ 时 $S \le 2^7 = 128$，总计约 $3.3 \times 10^3$ 次运算，常数级。若不做记忆化、纯回溯，代价是 $O(n \cdot A)$，$A$ 为答案（$\le 13699$），同样可过，但状态数上界说明记忆化把代价从「答案规模」降到了「状态规模」。
- **空间**：$O(S)$ 的 `memo`（最坏 128 个键，每个键 26 字节）+ $O(n)$ 的递归栈（$\le 7$ 层）+ $O(26)$ 的计数数组，整体常数级。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int numTilePossibilities(string tiles) {
        vector<int> cnt(26, 0);
        for (char ch : tiles) cnt[ch - 'A']++;
        unordered_map<string, int> memo;
        return g(cnt, memo) - 1;                 // 扣掉空序列
    }

private:
    // 从剩余计数 cnt 出发能印出的序列数（含空序列）
    int g(vector<int>& cnt, unordered_map<string, int>& memo) {
        string key;
        key.reserve(26);
        for (int i = 0; i < 26; ++i) key.push_back((char)cnt[i]);
        auto it = memo.find(key);
        if (it != memo.end()) return it->second;  // 命中缓存
        int total = 1;                            // 空序列
        for (int i = 0; i < 26; ++i) {
            if (cnt[i] == 0) continue;            // 只对「不同字母」分支 → 天然去重
            cnt[i]--;                             // 首字母选 i
            total += g(cnt, memo);
            cnt[i]++;                             // 回溯
        }
        memo[key] = total;
        return total;
    }
};
```

### Python

```python
class Solution:
    def numTilePossibilities(self, tiles: str) -> int:
        cnt = [0] * 26
        for ch in tiles:
            cnt[ord(ch) - ord('A')] += 1

        memo = {}

        def g(state):
            """从剩余计数 state 出发能印出的序列数（含空序列）。"""
            if state in memo:
                return memo[state]
            total = 1                                  # 空序列
            for i in range(26):
                if state[i]:                           # 只对「不同字母」分支
                    nxt = state[:i] + (state[i] - 1,) + state[i + 1:]
                    total += g(nxt)
            memo[state] = total
            return total

        return g(tuple(cnt)) - 1                       # 扣掉空序列
```

## 8. 边界情况与易错点

1. **忘记扣掉空序列**：`"AAB"` 会输出 `9` 而不是 `8`。递推里「空序列」是递归基的一部分，只在最外层减一次，不要每层都减。
2. **全部字母相同**：`"AAAAAAA"` 的答案是 $7$（只有 `A`、`AA`、…、`AAAAAAA`），不是 $1$，也不是 $2^7$。此时每个状态只有一个分支，链路是直线。
3. **全部字母不同**：`"ABCDEFG"` 的答案是 $13699$，这是本题的答案上界；`int` 足够，不必用 `long long`。
4. **按下标分支会重复计数**：对 `"AAB"` 按下标（或对 `used[]` 不做同层去重）会得到 $3 + 6 + 6 = 15$，正确值是 $8$。必须按「字母」分支，或在排序后用 `i > 0 and tiles[i] == tiles[i-1] and not used[i-1]` 跳过同层重复。
5. **`used[]` 判重写法容易写错**：`tiles[i] == tiles[i-1] and not used[i-1]` 里的 `not used[i-1]` 不能写成 `used[i-1]`，方向反了会把不同排列误杀或漏杀；相比之下计数向量分支不需要思考这些细节。
6. **两种语言的键写法**：Python 的 `list` 不可哈希，必须转 `tuple`；C++ 把 26 个计数逐字节塞进 `string` 即可（计数 $\le 7$，`(char)` 不会截断）。切片构造键是 $O(26)$，在 $S \le 128$ 时可忽略。
7. **单字符输入**：`"V"` 只有一条路径，返回 $1$；循环边界与递归基都不需要额外特判，别为它单独写 `if`。
