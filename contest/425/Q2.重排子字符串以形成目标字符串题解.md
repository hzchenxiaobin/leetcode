# LeetCode 重排子字符串以形成目标字符串 题解

## 1. 题目概述

- **标题 / 题号**：重排子字符串以形成目标字符串（#3365，medium）
- **链接**：https://leetcode.cn/problems/rearrange-k-substrings-to-form-target-string/
- **来源**：LeetCode 第 425 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、字符串、计数

**题意**：给定互为字母异位词的字符串 `s`、`t` 与整数 `k`（$n = |s| = |t|$ 保证被 $k$ 整除）。把 `s` 切成 $k$ 个**等长**的连续子串，以任意顺序重排这些子串并连接，问能否恰好得到 `t`。

**约束**：

- $1 \le n \le 2 \times 10^5$
- $1 \le k \le n$，且 $k \mid n$
- `s`、`t` 仅由小写英文字母组成，且保证互为字母异位词

> 💡 **赛场切入**：读题第一反应可能是「切法有很多种，要搜索」——恰恰相反。「等长」二字把切点钉死在 $0, m, 2m, \dots$（$m = n/k$），**切法唯一**，唯一的自由度是块的排列顺序。于是整题坍缩为「两个块序列的多重集比较」，一次哈希计数解决。

## 2. 示例

**示例 1**

```text
输入：s = "abcd", t = "cdab", k = 2
输出：true
解释：s 切成 ["ab", "cd"]，重排为 ["cd", "ab"]，连接得 "cdab" = t。
```

**示例 2**

```text
输入：s = "aabbcc", t = "bbaacc", k = 3
输出：true
解释：s 切成 ["aa", "bb", "cc"]，重排为 ["bb", "aa", "cc"]，连接得 "bbaacc" = t。
```

**示例 3**

```text
输入：s = "aabbcc", t = "bbaacc", k = 2
输出：false
解释：s 只能切成 ["aab", "bcc"]，无论怎么排都拼不出 "bbaacc"——
      注意两者字符级仍是异位词，失败发生在「块级」。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $k$ 个块的所有 $k!$ 种排列，逐一连接后与 `t` 比较。$k$ 最大 $2 \times 10^5$，$k!$ 是天文数字；即便 $k$ 很小也是 $O(k! \cdot n)$ 的无谓浪费——「能否重排成目标」这类问题从来不需要真的排：比较**多重集**即可，正如判断两数组是否互为排列不必枚举排列。

另一个方向的理解偏差是把题读成「字符可任意重排」：题面已保证 `s`、`t` 互为字母异位词，字符级永远成立，胜负手全在**块级**。

### 3.2 核心观察：切法唯一 ⟹ 块多重集相等

![切块与重排示意](images/rearrange_k_blocks_concept.svg)

三个关键事实：

1. **切法唯一**：把长为 $n$ 的串切成 $k$ 段等长连续块，切点只能是 $0, m, 2m, \dots, n$（$m = n/k$）。`s` 的块集合唯一确定，没有任何「选切法」的自由度。
2. **块是原子**：重排只改变块的先后顺序，块内字符顺序原封不动。
3. **块边界对齐**：$k$ 个等长块连接后，结果的第 $j$ 段（区间 $[(j-1)m,\ jm)$）恰好是排列中的第 $j$ 个块。因此若某个排列拼出了 `t`，`t` 按同样位置切块得到的正是这组块的某个排列。

三条合起来，得到全题的充要条件：

> **能重排得到 $t$ ⟺ `s` 的块多重集 = `t` 的块多重集**

### 3.3 算法流程：哈希计数

![算法流程](images/rearrange_k_counter_flow.svg)

1. 计算块长 $m = n / k$；
2. 把 `s` 切成 $k$ 块，哈希表对每块 `+1`；
3. 把 `t` 切成 $k$ 块，对每块 `−1`；
4. 计数全零 ⟹ `true`，否则 `false`。

两边各 $k$ 块、总量相同，所以「从不减穿」与「最终全零」互为充要——实现里 `--cnt[块] < 0` 即可提前返回 `false`。

### 3.4 示例演算

![示例演算](images/rearrange_k_mismatch_walkthrough.svg)

同一对 `s = "aabbcc"`、`t = "bbaacc"`，两种 $k$ 的结局截然相反：

- $k = 2$（$m = 3$）：`s` 块 $\{aab,\ bcc\}$，`t` 块 $\{bba,\ acc\}$，`bba` 在计数表里无计数可减 → `false`；
- $k = 3$（$m = 2$）：`s` 块 $\{aa,\ bb,\ cc\}$，`t` 块 $\{bb,\ aa,\ cc\}$，逐块配平、计数全零 → `true`。

**块长一变，块边界随之移动，结论翻转**——这正说明本题考的是块级视角，与字符级异位与否无关。

## 4. 算法细节

1. **块长与切块**：$m = n / k$；第 $i$ 块（$0 \le i < k$）取 `s[i*m : (i+1)*m]`。$k \mid n$ 由题面保证，无需特判。
2. **哈希表选型**：键是长度为 $m$ 的子串。C++ 用 `unordered_map<string, int>`，Python 用 `Counter`。$k$ 个键的总字符数为 $n$，空间 $O(n)$。
3. **对称计数**：`s` 块 `+1`、`t` 块 `−1`，一张表搞定，避免开两张表再逐键比较；某键减到负数立即 `false`。
4. **提前退出的正确性**：两边块数同为 $k$，若全程无负数，则总计数 $\sum = k - k = 0$ 且各项 $\ge 0$，故各项全零——「不减穿」⟺「全零」。
5. **替代写法**：把两边的块分别排序后逐块比较（`sort` + `==`），$O(n \log k)$ 同样能过；哈希计数是更干净的平均 $O(n)$。
6. **切块成本**：`substr` / 切片每块 $O(m)$，$k$ 块合计 $O(n)$，无隐藏超标。

## 5. 正确性证明

**引理 1（切法唯一）**：把长度为 $n$ 的字符串切成 $k$ 个等长连续块（每块长 $m = n/k$），切点必为 $0, m, 2m, \dots, n$，切法唯一。

**证明**：设第 $i$ 块起点为 $a_i$。连续等长切割要求 $a_1 = 0$ 且 $a_{i+1} = a_i + m$，归纳得 $a_i = (i-1)m$；末块终点 $a_k + m = km = n$ 恰好覆盖全串。故每条切线位置被唯一确定。∎

**引理 2（块边界对齐）**：设 $p_1, \dots, p_k$ 为 $k$ 个长为 $m$ 的字符串，$\pi$ 为任一排列，则连接串 $p_{\pi(1)} \cdots p_{\pi(k)}$ 的第 $j$ 段（区间 $[(j-1)m,\ jm)$）恰为 $p_{\pi(j)}$。

**证明**：连接串中前 $j-1$ 个块共贡献 $(j-1)m$ 个字符，且各块内部字符连续、块间不交错，故第 $j$ 段的字符全部且恰好来自 $p_{\pi(j)}$。∎

**定理**：`s` 可以重排块得到 `t` ⟺ `s` 的块多重集与 `t` 的块多重集相等。

**证明**：
（必要性）设排列 $\pi$ 使 $p_{\pi(1)} \cdots p_{\pi(k)} = t$。由引理 2，`t` 的第 $j$ 块 $= p_{\pi(j)}$，即 `t` 的块恰为 `s` 的块的一个排列，多重集相等。
（充分性）设两多重集相等，则对每种块值 `v` 有 $\mathrm{cnt}_s(v) = \mathrm{cnt}_t(v)$，故存在排列 $\pi$ 使 $p_{\pi(j)}$ 等于 `t` 的第 $j$ 块（把 `t` 的每块指派给一个尚未使用的相同 `s` 块）。由引理 2，连接串的每一段与 `t` 的对应块逐字符相同，故连接串 $= t$。∎

**推论**：算法判定「计数全零」即判定该充要条件，输出正确。

## 6. 复杂度分析

- **时间复杂度**：平均 $O(n)$。共 $2k$ 次切块与哈希更新，每次代价 $O(m)$（构造并哈希长度为 $m$ 的键），合计 $O(km) = O(n)$；排序写法则为 $O(n \log k)$，$n \le 2 \times 10^5$ 下同样轻松。
- **空间复杂度**：$O(n)$。哈希表至多存 $k$ 个键、总字符数 $n$；排序写法额外存两个块数组共 $n$ 个字符。
- **无溢出风险**：计数值不超过 $k \le 2 \times 10^5$，`int` 足够。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool isPossibleToRearrange(string s, string t, int k) {
        int n = s.size(), m = n / k;
        unordered_map<string, int> cnt;
        for (int i = 0; i < n; i += m) cnt[s.substr(i, m)]++;   // s 的块 +1
        for (int i = 0; i < n; i += m)
            if (--cnt[t.substr(i, m)] < 0) return false;        // t 的块 −1，减穿即败
        return true;                                            // 两边各 k 块 → 必全零
    }
};
```

### Python

```python
class Solution:
    def isPossibleToRearrange(self, s: str, t: str, k: int) -> bool:
        m = len(s) // k
        a = Counter(s[i:i + m] for i in range(0, len(s), m))    # s 的块多重集
        b = Counter(t[i:i + m] for i in range(0, len(t), m))    # t 的块多重集
        return a == b


# 写法二：单表对称计数，减穿提前退出（对应 C++ 版）
class Solution:
    def isPossibleToRearrange(self, s: str, t: str, k: int) -> bool:
        m = len(s) // k
        cnt = Counter(s[i:i + m] for i in range(0, len(s), m))
        for i in range(0, len(t), m):
            if cnt[t[i:i + m]] == 0:                            # 无计数可减
                return False
            cnt[t[i:i + m]] -= 1
        return True
```

## 8. 边界情况与易错点

1. **别被「异位词」带偏**：题面已保证字符级互为异位词，`sorted(s) == sorted(t)` 恒真，拿它当判据必错；判据是**块级**多重集（示例 3 专治此错觉）。
2. **切法不用枚举**：等长 ⟹ 切点固定在 $m$ 的倍数上。若下意识写 DFS 枚举切法，会掉进组合数的深渊。
3. **重复块必须计数**：集合（去重）相等 ≠ 多重集相等。如 `s = "ababab"`、`t = "ababba"`、`k = 3`：块集合都是 $\{ab,\ ba\}$，但 `s` 有三个 `ab`、`t` 只有两个 → `false`。
4. **k = 1 退化为整串比较**：只有一块，答案即 `s == t`；异位词不保证相等（如 `s = "ab"`、`t = "ba"`），此时 `false`。
5. **k = n 恒真**：每块单字符，异位词保证逐块配平，可作 sanity check。
6. **减穿判断别写成 `<= 0`**：`--cnt[x] < 0` 才对——恰好配平到 $0$ 是合法状态，`<= 0` 会把「刚好用完」误判成失败。
7. **`substr` 参数是 (起点, 长度)**：C++ 的 `s.substr(i, m)` 若误写成 `(i, i + m)`（终点语义），切出的块会越来越长，小样例都过不了。
8. **本地调试数据自查整除**：题面保证 $k \mid n$，线上不会出除不尽的情况，但自造数据时先检查，否则 $m$ 取整后切块静默出错。
9. **复杂度红线**：$n \le 2 \times 10^5$，$O(n)$ / $O(n \log n)$ 都安全；千万别写 $O(k!)$ 或 $O(n^2)$ 的逐块配对。
