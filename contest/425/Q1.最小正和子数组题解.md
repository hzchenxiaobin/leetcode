# LeetCode 最小正和子数组 题解

## 1. 题目概述

- **标题 / 题号**：最小正和子数组（#3364，easy）
- **链接**：https://leetcode.cn/problems/minimum-positive-sum-subarray/
- **来源**：LeetCode 第 425 场周赛 Q1
- **难度**：简单
- **标签**：数组、前缀和、滑动窗口

**题意**：给定整数数组 `nums` 与两个整数 `l`、`r`，在所有**长度在 $[l, r]$ 内**（可取任一档中间长度）且**和严格大于 0** 的**连续**子数组中，求**最小的和**；不存在则返回 `-1`。

**约束**：

- $1 \le n \le 100$
- $1 \le l \le r \le n$
- $-1000 \le nums[i] \le 1000$

> 💡 **赛场切入**：$n \le 100$ 是明牌的「随便枚举」数据范围，$O(n^2)$ 只有 $10^4$ 量级。Q1 的目标是**三分钟内写对**，别在双指针上恋战——数组含负数，209 那套不定长滑窗在这里没有单调性兜底。

## 2. 示例

**示例 1**

```text
输入：nums = [3, -2, 1, 4], l = 2, r = 3
输出：1
解释：长度在 [2, 3] 且和大于 0 的子数组有 [3,-2]=1、[1,4]=5、[3,-2,1]=2、[-2,1,4]=3，
      其中最小正和为 1（子数组 [3, -2]）。
```

**示例 2**

```text
输入：nums = [-2, 2, -3, 1], l = 2, r = 3
输出：-1
解释：所有长度在 [2, 3] 之间的子数组和均不大于 0。注意 [-2,2] 与 [2,-3,1] 的和
      恰好等于 0——「严格大于」的红线之外，不算正和。
```

**示例 3**

```text
输入：nums = [1, 2, 3, 4], l = 2, r = 4
输出：3
解释：子数组 [1, 2] 的长度为 2、和为 3，是所有正和中最小的。
```

## 3. 解题思路

### 3.1 暴力思路

二重循环枚举子数组的起点 $i$ 与终点 $j$，先检查长度 $j - i + 1 \in [l, r]$，再对区间重新累加求和、检查是否大于 0。三重循环 $O(n^3)$，$n \le 100$ 时约 $10^6$ 次基本操作，赛场上也能过。

但「每个窗口从头累加」这层重复劳动是白费的——同一批元素被反复相加。用前缀和把「求一个区间的和」降到 $O(1)$，就得到签到题的标准姿势。

### 3.2 核心观察：前缀和把区间和降为 $O(1)$

![前缀和模型](images/min_pos_sum_prefix_model.svg)

定义前缀和 $P[0] = 0$，$P[j+1] = P[j] + nums[j]$，则任意子数组 $nums[i..j]$ 的和为

$$sum(i, j) = P[j+1] - P[i]$$

于是算法只剩两层循环：枚举起点 $i$，枚举终点 $j \in [i + l - 1,\ \min(i + r - 1,\ n - 1)]$（长度约束直接翻译成终点范围），用前缀和 $O(1)$ 取和，是正数就更新的 $ans$。整体 $O(n^2)$。

**为什么不能像 209 那样双指针滑窗**？209 的正确性依赖**全正数**：右端扩张、和严格变大，左端收缩、和严格变小，「和 $\ge target$ 就收缩」的指针移动才有方向感。本题数组含负数——右扩一步和可能**变小**、左缩一步和可能**变大**，「和 > 0」不再随窗口伸缩单调成立，双指针无法决策。而枚举 $(i, j)$ 不需要任何单调性，机械枚举反而最稳。

### 3.3 进阶：按长度分层 + 定长滑窗

![按长度分层与定长滑窗](images/min_pos_sum_length_layers.svg)

前缀和写法要 $O(n)$ 额外数组，还有一层可省的优化：把长度自由区间 $[l, r]$ 拆成 $r - l + 1$ 个**定长**子问题（$k = l$ 层、$k = l+1$ 层、……、$k = r$ 层）。定长窗口滑动一步是「右边进一个元素、左边出一个元素」，和的修正只需 $O(1)$：

$$sum \mathrel{+}= nums[i] - nums[i-k]$$

每层一遍线性扫描，总复杂度 $O(n \cdot (r - l + 1)) \le O(n^2)$，空间 $O(1)$，连前缀和数组都省了。两种写法同阶，赛场上哪个顺手写哪个。

### 3.4 示例演算

![示例 1 演算](images/min_pos_sum_walkthrough.svg)

**示例 1** `nums = [3, -2, 1, 4]，l = 2, r = 3`，逐个候选过一遍：

| 子数组 | 长度 | 和 | 和 > 0？ | ans |
|--------|------|----|----------|-----|
| $[3, -2]$ | 2 | 1 | ✓ | $+\infty \to 1$ |
| $[-2, 1]$ | 2 | $-1$ | ✗ | 1 |
| $[1, 4]$ | 2 | 5 | ✓ | 1（不更新） |
| $[3, -2, 1]$ | 3 | 2 | ✓ | 1（不更新） |
| $[-2, 1, 4]$ | 3 | 3 | ✓ | 1（不更新） |

答案 $1$ ✓。再看示例 2 `[-2, 2, -3, 1]`：所有长度 $\in [2, 3]$ 的窗口和均 $\le 0$，其中 $[-2, 2]$ 与 $[2, -3, 1]$ 的和**恰好为 0**，正卡在「严格大于」的红线外——`ans` 保持哨兵 $+\infty$，返回 $-1$。

## 4. 算法细节

1. **前缀和下标约定**：$P$ 开头补 $P[0] = 0$，$P[j]$ 表示前 $j$ 个元素之和；$sum(i..j) = P[j+1] - P[i]$，左闭右闭的下标换算要一致。
2. **终点范围**：起点为 $i$ 时，合法终点 $j \in [i + l - 1,\ \min(i + r - 1,\ n - 1)]$；上界用 $\min$ 截断，防止 $i + r - 1$ 越过数组尾部。
3. **起点的上界**：$i \le n - l$（至少要放得下一个长度为 $l$ 的窗口），循环自然覆盖，无需特判。
4. **更新条件**：`if (sum > 0) ans = min(ans, sum)`——严格大于，等于 0 跳过。
5. **哨兵与返回**：`ans` 初始化为 `INT_MAX` / `inf`，循环结束仍是哨兵则返回 `-1`。
6. **分层滑窗的增量**：每层 $k$ 先算首窗口 $nums[0..k-1]$ 的和，然后右端 $i$ 从 $k$ 推到 $n-1$，`sum += nums[i] - nums[i-k]`——注意减的是 $nums[i-k]$（滑出左端的那个），写成 $nums[i-1]$ 就把窗口长度悄悄改成了 2。

## 5. 正确性证明

**引理 1**：对任意 $0 \le i \le j < n$，$nums[i..j]$ 的元素和等于 $P[j+1] - P[i]$。

**证明**：对 $P$ 的递推式 telescoping：$P[j+1] - P[i] = \sum_{t=0}^{j} nums[t] - \sum_{t=0}^{i-1} nums[t] = \sum_{t=i}^{j} nums[t]$。∎

**引理 2**（枚举完备且不重）：二重循环中每个有序对 $(i, j)$ 恰好访问一次，且「$j - i + 1 \in [l, r]$」当且仅当 $j \in [i + l - 1, \min(i + r - 1, n - 1)]$。

**证明**：长度 $j - i + 1 \ge l \iff j \ge i + l - 1$；$j - i + 1 \le r \iff j \le i + r - 1$；再与 $j \le n - 1$（不越界）取交即得上界 $\min(i + r - 1, n - 1)$。二重循环每对 $(i, j)$ 只走一次，无重复无遗漏。∎

**定理**：算法返回所有长度在 $[l, r]$ 内、和大于 0 的子数组之和的最小值；不存在时返回 $-1$。

**证明**：由引理 2，候选子数组集合被完整枚举且每个恰好一次；由引理 1，每个候选的和值计算正确。`ans` 初值为 $+\infty$，仅在遇到 $sum > 0$ 时被更小的正和替换，故循环结束时 `ans` 等于所有正和的最小值（若存在）。若不存在任何正和候选，`ans` 保持 $+\infty$，返回 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot (r - l + 1)) \le O(n^2)$。前缀和预处理 $O(n)$，二重循环枚举所有合法 $(i, j)$ 对；$n \le 100$ 时约 $10^4$ 次操作。暴力三重循环 $O(n^3) \approx 10^6$ 同样可过，但两层写法零成本更优。
- **空间复杂度**：前缀和写法 $O(n)$（一个 $P$ 数组）；分层定长滑窗写法 $O(1)$（只滚动一个 `sum` 变量）。
- **数值范围**：$|sum| \le 100 \times 1000 = 10^5$，`int` 完全够用，无溢出风险。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumSumSubarray(vector<int>& nums, int l, int r) {
        int n = nums.size();
        vector<int> P(n + 1);                          // P[j] = nums[0..j-1] 之和
        for (int j = 0; j < n; j++) P[j + 1] = P[j] + nums[j];

        int ans = INT_MAX;                             // 哨兵：+∞，不能用 0
        for (int i = 0; i + l <= n; i++) {             // 起点最多到 n - l
            for (int j = i + l - 1; j <= min(i + r - 1, n - 1); j++) {
                int s = P[j + 1] - P[i];               // sum(i..j) O(1) 查询
                if (s > 0) ans = min(ans, s);          // 严格大于 0 才算
            }
        }
        return ans == INT_MAX ? -1 : ans;
    }
};
```

### Python

```python
class Solution:
    def minimumSumSubarray(self, nums: List[int], l: int, r: int) -> int:
        n = len(nums)
        P = [0] * (n + 1)                              # P[j] = nums[0..j-1] 之和
        for j, x in enumerate(nums):
            P[j + 1] = P[j] + x

        ans = float('inf')
        for i in range(n - l + 1):                     # 起点最多到 n - l
            for j in range(i + l - 1, min(i + r - 1, n - 1) + 1):
                s = P[j + 1] - P[i]
                if s > 0:
                    ans = min(ans, s)
        return -1 if ans == float('inf') else ans


# 写法二：按长度分层 + 定长滑窗（空间 O(1)，同阶 O(n·(r-l+1))）
class Solution:
    def minimumSumSubarray(self, nums: List[int], l: int, r: int) -> int:
        n, ans = len(nums), float('inf')
        for k in range(l, r + 1):                      # k = l … r 逐层
            s = sum(nums[:k])                          # 该层首窗口
            if s > 0:
                ans = min(ans, s)
            for i in range(k, n):                      # 滑一步：右进一格、左出一格
                s += nums[i] - nums[i - k]
                if s > 0:
                    ans = min(ans, s)
        return -1 if ans == float('inf') else ans
```

## 8. 边界情况与易错点

1. **「大于 0」是严格正**：和恰好为 0 的子数组不合法（示例 2 的 $[-2, 2]$ 与 $[2, -3, 1]$ 就是专门埋的坑），`if (s > 0)` 不能写成 `>=`。
2. **哨兵取 $+\infty$ 而非 0**：0 在本题是「非法值」，当初值既无法区分「没找到」，又可能与窗口和 0 混淆；返回前必须判哨兵输出 `-1`，把 `INT_MAX` / `inf` 原样返回是典型 WA。
3. **长度是 $[l, r]$ 内任取**：不是「只能取 $l$ 或 $r$」两档，中间每一档都是合法候选，例 1 的答案 $[3, -2]$ 恰在 $k = l$ 层、例 3 的答案也在最短层。
4. **终点上界截断**：$j$ 的上界是 $\min(i + r - 1,\ n - 1)$，漏掉 $\min$ 会越界（尤其 $i$ 靠近数组尾部时）。
5. **$l = r$（定长）与 $l = r = n$（唯一候选整串）**：两层写法天然覆盖，无需特判；单元素 `[0]`、`l = r = 1` 时唯一窗口和为 0，返回 `-1`。
6. **全负 / 全零数组**：不存在正和候选，走哨兵分支返回 `-1`。
7. **分层滑窗的下标**：增量是 `nums[i] - nums[i-k]`，减错成 `nums[i-1]` 会把窗口长度悄悄改成 2，小样例都过不了。
8. **溢出安全**：$|sum| \le 10^5$、$|P[j]| \le 10^5$，`int` 足够，无需 `long long`。
