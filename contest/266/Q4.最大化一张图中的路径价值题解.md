# LeetCode 最大化一张图中的路径价值 题解

## 1. 题目概述

- **标题 / 题号**：最大化一张图中的路径价值（#2065，hard）
- **链接**：https://leetcode.cn/problems/maximum-path-quality-of-a-graph/
- **来源**：LeetCode 第 266 场周赛 Q4
- **难度**：困难
- **标签**：图、回溯、DFS、剪枝

**题意**：给定一张 **无向图**，节点编号 $0$ 到 $n-1$，节点 $i$ 的价值为 $values[i]$；边 $edges[j] = [u_j, v_j, time_j]$ 表示一条通过需要 $time_j$ 秒的无向边。**合法路径**：从节点 $0$ 出发、最终回到节点 $0$、总时间不超过 $maxTime$ 的任意一条路径，节点和边都可以重复经过。一条合法路径的**价值**定义为路径中**不同节点**的价值之和（每个节点至多算一次）。求合法路径的最大价值。

**约束**：

- $1 \le n \le 1000$，$0 \le values[i] \le 10^8$
- $0 \le edges.length \le 2000$，节点对 $[u_j, v_j]$ 互不相同
- $10 \le time_j, maxTime \le 100$
- **每个节点至多有 4 条边**
- 图可能不连通

## 2. 示例

**示例 1**

```text
输入：values = [0,32,10,43], edges = [[0,1,10],[1,2,15],[0,3,10]], maxTime = 49
输出：75
解释：路径 0 → 1 → 0 → 3 → 0，总时间 10+10+10+10 = 40 ≤ 49。
      到过的不同节点为 {0, 1, 3}，价值 = 0 + 32 + 43 = 75。
```

**示例 3**

```text
输入：values = [1,2,3,4], edges = [[0,1,10],[1,2,11],[2,3,12],[1,3,13]], maxTime = 50
输出：7
解释：路径 0 → 1 → 3 → 1 → 0，总时间 10+13+13+10 = 46 ≤ 50。
      节点 1 被经过两次，价值只算一次；想把 2 也捎上（0→1→2→3→1→0）需 56 > 50，
      故最优只收 {0,1,3}，价值 = 1 + 2 + 4 = 7。
```

**示例 4**

```text
输入：values = [0,1,2], edges = [[1,2,10]], maxTime = 10
输出：0
解释：节点 0 孤立（图不连通），唯一合法路径是原地不动（时间 0），价值 = values[0] = 0。
```

## 3. 解题思路

### 3.1 暴力思路：为什么常规多项式算法全部失效

先排除错误方向，体会本题「困难」在外表哪里：

- **不是最短路/Dijkstra**：目标是最大化「到过的节点集合」的价值，而不是最小化时间；且最优解可能故意绕远路去捡高价值节点再折返（示例 1 的 $0 \to 1 \to 0 \to 3 \to 0$ 就是两个「口袋形」往返拼起来的）。
- **不是简单路径问题**：节点可以重复经过，枚举的对象其实是**闭合 walk**（回路），数量无显然上限。
- **状压 DP 不可行**：价值依赖「已访问集合」这一集合信息，$(节点, 集合)$ 的状态需要 $2^n$，$n \le 1000$ 直接爆炸；而 $(节点, 剩余时间)$ 的状态又不充分——同一个 $(u, t)$ 可以对应不同的已访问集合，无法合并取 max。

看起来需要很聪明的图论建模？其实不用——**数据范围里藏着两个关键数字**。

### 3.2 核心观察：数据范围把搜索空间钉死

![核心观察：步数与分支数都被约束限死](images/wc266_q4_concept.svg)

- **约束①（步数）**：每条边 $time_j \ge 10$ 且 $maxTime \le 100$，所以任何合法路径至多 $\lfloor 100/10 \rfloor = 10$ 条边、至多踩到 11 个不同节点。
- **约束②（分支）**：每个节点至多 4 条边，所以搜索树上每个状态至多 4 个后继（折返回父节点也占一个分支，上界还很松）。

两条相乘：从 $0$ 出发、时间预算内的 walk 总数不超过

$$\sum_{d=0}^{10} 4^d = \frac{4^{11}-1}{3} \approx 1.4 \times 10^6$$

**一百万量级**——直接**DFS 回溯枚举所有预算内的 walk** 即可，毫秒级跑完。这是典型的「困难标签、爆搜内核」：看似需要图论优化，实为**约束驱动的有界搜索**，考察的是对数据范围的敏感度。

### 3.3 算法流程：DFS 回溯 + 到 0 记账

状态设计：`(当前点 u, 已用时间 t, 当前价值和 cur)`，配合全局 `cnt[]` 记录每个节点在当前 walk 上的出现次数。三个要点：

1. **到达 0 就记账**：每次进入节点 $0$（包括起点本身）都执行 $ans \gets \max(ans, cur)$——任何「此刻在 0」的前缀都是一条合法路径。注意**到达 0 不终止**：walk 可以穿过 0 继续延伸（示例 1 的最优路径中途就两次经过 0）。
2. **cnt 计数管价值**：$cnt[v]$ 从 $0$ 变 $1$（首次进入）时把 $values[v]$ 计入 $cur$，从 $1$ 变 $0$（彻底离开）时减回；中间反复进出不改变 $cur$。
3. **唯一剪枝**：扩展边 $(v, w)$ 前检查 $t + w \le maxTime$，不满足直接跳过。这同时保证了复杂度——被探索的每条 walk 都在预算内，深度天然 $\le 10$。

![算法流程：到 0 记账、超时剪枝、进出配对](images/wc266_q4_flow.svg)

## 4. 算法细节

1. **建图**：邻接表 `vector<vector<pair<int,int>>>`，无向边 $(u, v, w)$ 要 `g[u]`、`g[v]` 各加一次。
2. **cnt 用计数而非布尔**：walk 可能中途重复经过同一节点（示例 3 的 $0 \to 1 \to 3 \to 1 \to 0$ 中节点 1 出现两次）。若用布尔标记「进入置真、离开置假」，第二次进入时 $cur$ 不会加值，但第一次离开的回溯就会错误地把还在 walk 上的节点价值减掉——必须用计数判断「是否归零」。
3. **cur 作为参数按值传递**：递归调用写作 `dfs(v, t + w, cnt[v] == 1 ? cur + values[v] : cur)`，扩展时的价值增量在**调用点**决定，回溯只需还原 `cnt[v]`，状态管理最省心。
4. **记账时机**：在函数入口判断 `u == 0`。初始调用 `dfs(0, 0, values[0])` 时天然覆盖平凡路径（原地不动，价值 $values[0]$），因此 `ans` 初始化为 0 即可（$values[i] \ge 0$）。
5. **初值**：`cnt[0] = 1`、`cur = values[0]`——出发点在 walk 开始时就已经「到过」。
6. **溢出防护**：至多 11 个不同节点、每个至多 $10^8$，价值和上限 $1.1 \times 10^9$，未超 `int`（约 $2.1 \times 10^9$）但已过半；C++ 中用 `long long` 承载 `cur`/`ans` 更稳妥，返回时再转 `int`。

## 5. 正确性证明

**引理 1**（步数上界）：任何合法路径至多包含 $L = \lfloor maxTime / 10 \rfloor \le 10$ 条边。

**证明**：每条边耗时 $\ge 10$，若路径含 $k$ 条边，则总时间 $\ge 10k$；又总时间 $\le maxTime \le 100$，故 $k \le 10$。∎

**引理 2**（搜索空间有界）：DFS 产生的递归调用总数不超过 $\sum_{d=0}^{L} 4^d < 1.4 \times 10^6$。

**证明**：深度为 $d$ 的调用由深度 $d-1$ 的调用发起，每个调用至多遍历 $deg(u) \le 4$ 条邻边、每条边至多发起一次递归（且需通过 $t + w \le maxTime$ 检查）。故深度 $d$ 的调用数至多 $4^d$，对 $d \le L$ 求和即得。∎

**引理 3**（价值不变量）：任一时刻，当前递归参数 $cur$ 恰等于当前 walk（从 $0$ 到当前点 $u$）上出现过的所有节点的价值之和（每个节点算一次）。

**证明**：对调用序列归纳。$cnt[v]$ 恰为 $v$ 在当前 walk 上的出现次数：每次扩展 $u \to v$ 时 $cnt[v]$ 先加一再传入递归，回溯时减一还原。基例：初始调用时 $cnt[0] = 1$、$cur = values[0]$，成立。归纳步：扩展 $u \to v$ 时，仅当 $cnt[v]$ 从 $0$ 变 $1$（$v$ 首次出现在 walk 上）时下一层 $cur' = cur + values[v]$，否则 $cur' = cur$，两种情况均与「walk 上出现过的节点集合新增至多 $\{v\}$」一致。兄弟分支之间由回溯的对称还原保证不变量恢复。∎

**定理**（算法正确性）：算法返回的 $ans$ 等于所有合法路径价值的最大值。

**证明**：分两个方向。

（i）**不多算**：$ans$ 仅在进入某个 $u = 0$ 的调用时被当时的 $cur$ 刷新。该调用对应一条从 $0$ 出发、当前回到 $0$ 的 walk，且每步扩展前均验证过 $t + w \le maxTime$，故总时间 $\le maxTime$，是合法路径；由引理 3，$cur$ 恰为其价值。初始候选 $values[0]$ 对应平凡路径。因此 $ans$ 的每个候选都来自某条合法路径的价值，$ans \le \max$。

（ii）**不漏算**：设 $P = (0 = v_0, v_1, \dots, v_k = 0)$ 是任意总时间 $T \le maxTime$ 的合法路径。由于时间非负，$P$ 的每个前缀的累计时间都 $\le T \le maxTime$，故 DFS 按边逐步扩展时会完整走到 $P$ 的终点；到达 $v_k = 0$ 的那次调用中，由引理 3，$cur$ 等于 $P$ 的不同节点价值之和，因此 $ans \ge value(P)$。

综合（i）（ii），$ans = \max_P value(P)$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + E + \sum_{d=0}^{L} 4^d)$，其中 $L = \lfloor maxTime / 10 \rfloor \le 10$。建图 $O(n + E)$；搜索部分调用数 $< 1.4 \times 10^6$，每次调用至多遍历 4 条邻边做 $O(1)$ 检查与记账，总计约 $5.6 \times 10^6$ 次基本操作。注意复杂度**不随 $n$ 指数增长**——$n$ 只影响建图，搜索规模由 $maxTime$ 与度数上界决定。
- **空间复杂度**：$O(n + E)$。邻接表与 `cnt` 数组各 $O(n + E)$ / $O(n)$，递归栈深度 $\le L + 1 \le 11$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int maximalPathQuality(vector<int>& values, vector<vector<int>>& edges, int maxTime) {
        int n = values.size();
        vector<vector<pair<int, int>>> g(n);
        for (auto& e : edges) {
            g[e[0]].push_back({e[1], e[2]});
            g[e[1]].push_back({e[0], e[2]});
        }

        vector<int> cnt(n, 0);
        cnt[0] = 1;                          // 出发点已在当前 walk 上
        long long ans = 0;

        function<void(int, int, long long)> dfs = [&](int u, int t, long long cur) {
            if (u == 0) ans = max(ans, cur); // 每次到 0 都可收尾记账
            for (auto [v, w] : g[u]) {
                if (t + w > maxTime) continue; // 唯一剪枝：时间预算
                ++cnt[v];
                dfs(v, t + w, cnt[v] == 1 ? cur + values[v] : cur); // 仅首访加值
                --cnt[v];                     // 回溯还原
            }
        };
        dfs(0, 0, values[0]);
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maximalPathQuality(self, values: List[int], edges: List[List[int]], maxTime: int) -> int:
        n = len(values)
        g = [[] for _ in range(n)]
        for u, v, t in edges:
            g[u].append((v, t))
            g[v].append((u, t))

        cnt = [0] * n
        cnt[0] = 1                            # 出发点已在当前 walk 上
        ans = 0

        def dfs(u: int, t: int, cur: int) -> None:
            nonlocal ans
            if u == 0:
                ans = max(ans, cur)           # 每次到 0 都可收尾记账
            for v, w in g[u]:
                if t + w > maxTime:
                    continue                  # 唯一剪枝：时间预算
                cnt[v] += 1
                dfs(v, t + w, cur + values[v] if cnt[v] == 1 else cur)  # 仅首访加值
                cnt[v] -= 1                   # 回溯还原

        dfs(0, 0, values[0])
        return ans
```

## 8. 边界情况与易错点

1. **节点 0 孤立 / 图不连通**（示例 4）：唯一合法路径是原地不动，答案为 $values[0]$。DFS 入口即记账，天然覆盖，无需特判。
2. **到达 0 不能提前终止**：路径可以穿过 0 继续延伸（示例 1 的 $0 \to 1 \to 0 \to 3 \to 0$ 中途两次经过 0）。若把「回到 0」当作递归出口，会漏掉所有穿过 0 的更优解——这是本题最高频的 WA 点。
3. **必须用计数标记而非布尔**：walk 中途重复经过同一节点（示例 3 的节点 1）时，布尔标记的「离开即清除」会把仍在 walk 上的节点价值错误撤销（见 §4 第 2 点）。
4. **价值之和接近 int 上限**：$\le 11$ 个不同节点 $\times\ 10^8 = 1.1 \times 10^9$，虽未溢出但只差不到一倍，约束稍变即炸；C++ 用 `long long` 累加（Python 无此问题）。
5. **无向边要加两次**：忘加反向边会漏掉大量 walk（例如从 1 折返 0 的所有路径）。
6. **maxTime 小于所有邻边时间**：起点一步迈不出去，剪枝自动挡住，答案停留在 $values[0]$，无需特判。
7. **别把答案初始化成 −1**：$values[i] \ge 0$ 且平凡路径价值为 $values[0] \ge 0$，初始化为 0 配合入口记账即可。
