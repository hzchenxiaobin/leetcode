# LeetCode 使数组中的所有元素都等于零 题解

## 1. 题目概述

- **标题 / 题号**：使数组中的所有元素都等于零（#2772，medium）
- **链接**：https://leetcode.cn/problems/apply-operations-to-make-all-array-elements-equal-to-zero/
- **来源**：LeetCode 第 353 场周赛 Q4
- **难度**：中等
- **标签**：数组、贪心、差分数组、前缀和

**题意**：给定下标从 $0$ 开始的整数数组 `nums` 与正整数 $k$。一次操作可以任选一个**长度恰为 $k$** 的连续子数组，把其中每个元素**减 1**；操作可执行任意次（也可不执行）。问是否存在一种操作方案，使数组中**所有元素都恰好变成 0**，存在返回 `true`，否则返回 `false`。

**约束**：

- $1 \le k \le n \le 10^5$ —— 排除 $O(n^2)$ 及以上，要求线性扫描
- $0 \le nums[i] \le 10^6$ —— 元素非负；总操作次数可达 $10^{11}$ 量级，只能「数次数」而不能模拟每次操作

## 2. 示例

**示例 1**

```text
输入：nums = [2,2,3,1,1,0], k = 3
输出：true
解释：
- 选出子数组 [2,2,3]，操作后 nums = [1,1,2,1,1,0]。
- 选出子数组 [2,1,1]，操作后 nums = [1,1,1,0,0,0]。
- 选出子数组 [1,1,1]，操作后 nums = [0,0,0,0,0,0]。
```

**示例 2**

```text
输入：nums = [1,3,1,1], k = 2
输出：false
解释：无法使数组中的所有元素都等于 0。
```

**示例 3（k = 1 恒真）**

```text
输入：nums = [5,0,3], k = 1
输出：true
解释：k = 1 时每个位置可独立减 1，对每个位置单独操作 nums[i] 次即可。
```

**示例 4（中部凹陷）**

```text
输入：nums = [3,1,3], k = 3
输出：false
解释：唯一的窗口 [0,2] 若执行 3 次，中间会变成 1-3 = -2；执行 1 次两端又剩 2。
     中间值低于两端时，长窗口无法兼顾。
```

## 3. 解题思路

### 3.1 暴力思路

只关心「次数」而不关心操作顺序：设 $c_s$ 为**起点在 $s$** 的操作次数（$s \in [0, n-k]$），则「全归零」等价于对每个位置 $i$ 覆盖方程成立：

$$
\sum_{s=\max(0,\,i-k+1)}^{\min(i,\,n-k)} c_s = nums[i]
$$

即一个 **$k$ 宽滑动窗口和逐位等于给定值** 的线性方程组。暴力两条路都走不通：

1. 搜索 / BFS 枚举操作序列——总操作量 $10^{11}$ 量级，状态空间天文数字；
2. 逐个枚举 $c_s \in [0, 10^6]$ 的组合——$10^5$ 个变量，每个 $10^6$ 种取值。

> ⚠️ 暴力的浪费在于：没意识到**这个方程组若可解则解唯一**——从左到右扫时每个 $c_s$ 被它左边的方程完全确定，根本没有搜索空间。

### 3.2 核心观察：从左到右贪心 + 差分追踪活跃操作

![核心观察：能减到位置 i 的操作，起点必落在 [i−k+1, i]](images/makezero_window_concept.svg)

三个观察叠加，把指数级搜索压到 $O(n)$：

> 💡 **观察一（窗口约束）**：一次操作覆盖区间 $[s, s+k-1]$，它减到位置 $i$ 当且仅当 $i-k+1 \le s \le i$。起点早于 $i-k+1$ 的操作已**过期**（最右只到 $i-1$），晚于 $i$ 的还没开始。

> 💡 **观察二（贪心唯一性）**：从左到右扫描，到达位置 $i$ 时，起点 $\le i-1$ 的操作数已全部确定，其中仍活跃的（起点在 $[i-k+1, i-1]$）对 $i$ 的减量已知，记为 `curr`。于是必须在 $i$ 处再启动 $need = nums[i] - \text{curr}$ 个操作——这个数**被唯一确定，没有任何选择空间**（后面证明）。

> 💡 **观察三（差分维护 curr）**：在 $i$ 处启动的操作覆盖到 $i+k-1$，于位置 $i+k$ 处**到期**。用差分数组记账：启动时 `diff[i+k] -= need`，扫描时每步先 `curr += diff[i]` 即可 $O(1)$ 结算到期操作。

**两条失败条件**（贪心每步先算 `need = nums[i] - curr` 再判定）：

| 条件 | 含义 | 返回 |
|------|------|------|
| `need < 0` | `curr > nums[i]`，位置 $i$ 已被前面的操作**超减**；操作只能减不能加，无法回退 | `false` |
| `need > 0` 且 `i + k > n` | 还需补启动新操作，但 $[i, i+k-1]$ 越界放不下 $k$ 长窗口 | `false` |

> 💡 **不变式**：成功处理完位置 $i$ 后恒有 $curr = nums[i]$（因为 $curr \leftarrow curr + need = nums[i]$）。因此 `curr` 恒被 $\max(nums) \le 10^6$ 上界约束，`int` 即可，无溢出风险。

### 3.3 算法流程

![算法流程：一趟扫描，两条剪枝](images/makezero_greedy_flow.svg)

整体只有一个循环，每轮四步：**结算到期**（`curr += diff[i]`）→ **算缺口**（`need = nums[i] - curr`）→ **两条剪枝**（超减 / 放不下）→ **启动并记账**（`curr += need`、`diff[i+k] -= need`）→ 前进。循环正常扫完即 `true`，任一剪枝命中即 `false`。

### 3.4 示例演算

![示例演算：每列覆盖数与 nums 的对照](images/makezero_example_walkthrough.svg)

**示例 1**（`nums = [2,2,3,1,1,0]`，`k = 3`，返回 `true`）：

| $i$ | $nums[i]$ | 结算后 curr | need | 动作 |
|-----|-----------|------------|------|------|
| 0 | 2 | 0 | **2** | 启动 2 个（`diff[3] -= 2`） |
| 1 | 2 | 2 | 0 | — |
| 2 | 3 | 2 | **1** | 启动 1 个（`diff[5] -= 1`） |
| 3 | 1 | 1 | 0 | —（`diff[3]` 生效，curr 2→1） |
| 4 | 1 | 1 | 0 | — |
| 5 | 0 | 0 | 0 | —（`diff[5]` 生效，curr 1→0） |

全部 `need ≥ 0` 且无越界，扫完返回 `true`。总操作数恰为 $2 + 1 = 3$，与示例解释的三次操作一致。

**示例 2**（`nums = [1,3,1,1]`，`k = 2`，返回 `false`）：

| $i$ | $nums[i]$ | 结算后 curr | need | 动作 |
|-----|-----------|------------|------|------|
| 0 | 1 | 0 | **1** | 启动 1 个（`diff[2] -= 1`） |
| 1 | 3 | 1 | **2** | 启动 2 个（`diff[3] -= 2`） |
| 2 | 1 | 2 | **−1** | ❌ `need < 0` → `false` |

$i=2$ 时 `curr = 2 > nums[2] = 1`：位置 2 已被位置 0/1 启动的操作过量减了 1，只能减不能加，无法回退。

## 4. 算法细节

1. **数据结构**：差分数组 `diff` 长度 $n+1$。`diff[i+k]` 记录「在 $i$ 启动的 `need` 个操作于 $i+k$ 处整体到期」，扫描到 $i+k$ 时 `curr += diff[i+k]` 一次结算。
2. **顺序敏感**：每轮必须**先** `curr += diff[i]`（结算到期）**再**算 `need`，否则 `curr` 多算了已过期的操作。
3. **两条剪枝的次序**：`need < 0` 先判——即使 `need > 0` 且放不下窗口也要先排除超减；两者都是**即时无解**，无需回溯（解唯一性见 §5）。
4. **越界安全**：写 `diff[i+k]` 前已检查 `i + k <= n`，故下标上界恰为 $n$，数组长度 $n+1$ 保证不越界；`need == 0` 时直接跳过不写。
5. **等价写法**：`i + k > n` 等价于 `i > n - k`，后者的含义是「尾部 $k-1$ 个位置根本无法启动新窗口」——若这些位置还有缺口，必为 `false`。

## 5. 正确性证明

**引理 1（覆盖约束）**：以 $s$ 为起点的操作覆盖区间 $[s, s+k-1]$；它减到位置 $i$ 当且仅当 $i-k+1 \le s \le i$，且合法起点需满足 $0 \le s \le n-k$。

**证明**：$i \in [s, s+k-1] \iff s \le i \le s+k-1 \iff i-k+1 \le s \le i$；窗口须完整落在 $[0, n-1]$ 内即 $s \in [0, n-k]$。∎

**引理 2（解的唯一性）**：把任意方案表示为起点计数 $c_s \ge 0$（$s \in [0, n-k]$，其余 $c_s = 0$），则方案可行（全归零）当且仅当每个位置 $i$ 满足覆盖方程 $\sum_{s=\max(0,i-k+1)}^{\min(i,n-k)} c_s = nums[i]$。若可行，则 $c$ 唯一，且与贪心的逐位计算完全一致：扫到 $i$ 时 `curr` 恰等于 $\sum_{s=\max(0,i-k+1)}^{\min(i-1,n-k)} c_s$（已确定的、仍活跃的操作数），故

$$
c_i = nums[i] - \text{curr} = need \quad (i \le n-k), \qquad \text{且 } need = 0 \quad (i > n-k).
$$

**证明**：对 $i$ 归纳。
$i = 0$：由引理 1，覆盖 0 的操作只能起点 $s = 0$，覆盖方程给出 $c_0 = nums[0]$，即贪心在 0 处的 `need`（初始 `curr = 0`）。
归纳步：设贪心与 $c$ 在起点 $0..i-1$ 的计数一致。贪心扫到 $i$ 时，`diff` 的记账保证结算 `diff[i]` 后 `curr` 等于「起点在 $[\max(0,i-k+1), i-1]$ 内的启动数」（在 $j$ 处加入 $\text{need}_j$、在 $j+k$ 处扣除，二者恰好框住活跃区间），由归纳假设该值 $= \sum_{s=\max(0,i-k+1)}^{\min(i-1,n-k)} c_s$。代入覆盖方程：$nums[i] = \text{curr} + c_i \cdot \mathbb{1}[i \le n-k]$。若 $i \le n-k$，解出 $c_i = nums[i] - \text{curr} = need$；若 $i > n-k$，$c_i$ 恒为 0，方程强制 $\text{curr} = nums[i]$，即 `need = 0`。归纳完成。∎

**定理**：算法返回 `true` 当且仅当存在可行操作方案；且返回 `true` 时，算法隐式构造的方案（每个位置 $i$ 启动 $\text{need}_i$ 个操作）可行。

**证明**：
**（必要性，可行 ⇒ true）** 设可行方案 $c$ 存在。由引理 2，贪心在每个位置算出的 `need` 与 $c_i$ 一致（或 `need = 0`）。因 $c_s \ge 0$，处处 `need ≥ 0`，第一条剪枝不触发；在 $i > n-k$ 处方程强制 `need = 0`，第二条剪枝也不触发。算法扫完全程返回 `true`。
**（充分性，true ⇒ 可行）** 设算法返回 `true`，取 $c_i = need_i$。先证不变式「处理完位置 $i$ 后 `curr == nums[i]`」：$i \le n-k$ 时执行了 `curr += need` 使其成立；$i > n-k$ 处若 `need > 0` 会触发剪枝返回 `false`，故 `need = 0`，即 `nums[i] - curr = 0`，同样成立。再注意此 `curr` 恰是 $c$ 方案中覆盖位置 $i$ 的操作数（起点在 $[\max(0,i-k+1), i]$ 内的计数，且 $i > n-k$ 处 $c_i = 0$）。于是每个位置被覆盖 `nums[i]` 次、恰被减 `nums[i]`，全归零，方案可行。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每步只有加法、比较和两次差分更新，均为 $O(1)$；无排序、无嵌套循环。
- **空间复杂度**：$O(n)$。差分数组 `diff` 长度 $n+1$。由于只有 $[i, i+k]$ 范围内的到期事件有意义，可用循环缓冲把空间压到 $O(k)$，但 $k$ 最大为 $n$，最坏仍是 $O(n)$，对 $n \le 10^5$ 无必要。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkArray(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> diff(n + 1, 0);
        int curr = 0;
        for (int i = 0; i < n; i++) {
            curr += diff[i];
            int need = nums[i] - curr;
            if (need < 0) return false;
            if (need > 0) {
                if (i + k > n) return false;
                curr += need;
                diff[i + k] -= need;
            }
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def checkArray(self, nums: List[int], k: int) -> bool:
        n = len(nums)
        diff = [0] * (n + 1)
        curr = 0
        for i in range(n):
            curr += diff[i]
            need = nums[i] - curr
            if need < 0:
                return False
            if need > 0:
                if i + k > n:
                    return False
                curr += need
                diff[i + k] -= need
        return True
```

## 8. 边界情况与易错点

1. **先结算再算缺口**：`curr += diff[i]` 必须在 `need = nums[i] - curr` 之前，否则 `curr` 混入已过期操作。
2. **`need < 0` 判定在前**：超减即无解（只能减不能加），不要试图回溯或搜索——解唯一，剪枝触发就是判了死刑。
3. **`diff` 长度开 $n+1$**：`i + k` 的上界恰为 $n$（剪枝保证），开 $n$ 会越界；`need == 0` 时跳过写入。
4. **`k == 1` 恒真**：每个位置独立减自身值，代码天然覆盖，无需特判（见示例 3）。
5. **全 0 数组**：`need` 恒 0，零次操作直接 `true`。
6. **尾部 $k-1$ 个位置**：$i > n-k$ 无法启动新窗口，此处若有缺口（`need > 0`）必 `false`；`i + k > n` 与 `i > n - k` 二选一，别写成 `i + k >= n`（会误杀合法的恰好贴边窗口）。
7. **溢出无忧**：不变式 `curr == nums[i]` 保证 `curr ≤ 10^6`，全程 `int` 安全，无需 `long long`。
8. **别把 `need` 当「可选」**：它是被唯一确定的缺口数（§5 引理 2），任何「换个起点试试」的回溯/搜索思路都是在否定解的唯一性，只会 TLE。

**延伸思考**：

1. **起点计数的 $k$ 步递推**：把相邻两个覆盖方程相减，窗口滑动一格只进出各一个变量，得 $c_i = c_{i-k} + nums[i] - nums[i-1]$（$1 \le i \le n-k$，越界取 0）；尾部 $i > n-k$ 处方程退化为 $c_{i-k} = nums[i-1] - nums[i]$ 的检验。这是方程组的显式解，与贪心逐步算出的 `need` 完全一致，可 $O(n)$ 直接求出唯一候选再统一验非负。
2. **操作总数唯一**：解唯一意味着总操作数 $\sum_i c_i$ 也唯一（示例 1 中恰为 3），「最少操作数」变体不构成新问题；若题目改为「输出一种方案」，直接按各位置 `need` 生成窗口即可。
3. **窗口长度 $\le k$ 的变体**：允许用更短的窗口则每个位置可用长度 1 的窗口独立减，恒为 `true`——固定长度 $k$ 正是本题难度的全部来源。
