# LeetCode 使数组变美的最小增量运算数 题解

## 1. 题目概述

- **标题 / 题号**：使数组变美的最小增量运算数（#2919，medium）
- **链接**：https://leetcode.cn/problems/minimum-increment-operations-to-make-array-beautiful/
- **来源**：LeetCode 第 369 场周赛 Q3
- **难度**：中等
- **标签**：数组、动态规划、状态机 DP

**题意**：给定长度为 $n$ 的数组 $nums$ 与整数 $k$。一次**递增运算**可任选下标 $i$ 使 $nums[i]$ 加 $1$，可执行任意次。若**任何长度 $\ge 3$ 的子数组**的最大值都 $\ge k$，则称数组为**美丽数组**。返回使数组变为美丽数组的最少递增运算次数。

**约束**：

- $3 \le n \le 10^5$
- $0 \le nums[i] \le 10^9$
- $0 \le k \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,0,0,2], k = 4
输出：3
解释：nums[1] 加 1（3→4），nums[4] 加 2（2→4），得 [2,4,0,0,4]。
      所有长度 ≥ 3 的子数组（[2,4,0]、[4,0,0]、[0,0,4]、[2,4,0,0]、[4,0,0,4]、[2,4,0,0,4]）
      的最大值均为 4 ≥ k。可以证明 3 次是最少的。
```

**示例 2**

```text
输入：nums = [0,1,3,3], k = 5
输出：2
解释：nums[2] 加 2（3→5），得 [0,1,5,3]。三个子数组 [0,1,5]、[1,5,3]、[0,1,5,3] 最大值均为 5。
```

**示例 3（自拟，贪心反例）**

```text
输入：nums = [5,1,1,1,5], k = 6
输出：5
解释：只抬 nums[2]（1→6）即可：[5,1,6,1,5]，三个窗口 [5,1,6]、[1,6,1]、[6,1,5]
      全部包含 6。注意抬「窗口里最便宜的位置」的贪心会先抬 nums[0]（代价 1）、
      再被迫抬 nums[1]（代价 5）、最后抬 nums[4]（代价 1），共 7 次 > 5。
```

## 3. 解题思路

### 3.1 暴力思路：为什么枚举与贪心都不可行

最直接的暴力是枚举每个位置「是否被抬到 $k$」（见 3.2 的二值化，抬不到 $k$ 或超过 $k$ 都是浪费），共 $2^n$ 种方案，每种再 $O(n)$ 检查所有窗口——$n \le 10^5$ 时天文数字，不可行。

那贪心呢？两种最自然的贪心都有反例：

- **贪心 A（抬当前位）**：从左往右扫，一旦窗口 $\{i-2, i-1, i\}$ 内没有任何 $\ge k$ 的元素，就抬 $nums[i]$。反例 $nums = [2,0,0,2],\ k = 3$：它在 $i=2$ 时抬 $nums[2]$（代价 3），总代价 3；而最优解是抬 $nums[0]$ 和 $nums[3]$（各代价 1），总代价 **2**。
- **贪心 B（抬窗口内最便宜者）**：发现窗口 $\{i-2,i-1,i\}$ 失效时，抬三者中最便宜的位置。反例即示例 3：先抬 $nums[0]$，后续被迫连锁抬 $nums[1]$、$nums[4]$，共 7；最优只有 5。

贪心失败的本质：**一个 high 位置能同时覆盖 3 个相邻窗口**，而各位置抬升代价又不均匀——「便宜但只覆盖一个残留窗口」与「稍贵但覆盖三个窗口」的取舍依赖后续全局结构，局部信息无法裁决 ⟹ 必须 DP。

### 3.2 核心观察：窗口归约 + high/low 二值化

![窗口归约与二值化](images/beautiful_array_window_reduction.svg)

**观察 1（只需检查长度恰为 3 的窗口）**：「所有长度 $\ge 3$ 的子数组最大值 $\ge k$」$\iff$「所有长度**恰好为 3** 的子数组最大值 $\ge k$」。因为任何长子数组的前 3 个元素就是一个 3 窗口，窗口的最大值不超过整个子数组的最大值。

**观察 2（每个位置只有 high / low 两种结局）**：运算只增不减，且约束只关心「是否 $\ge k$」。于是：

- 位置 $i$ 的终值 $\ge k$（记为 **high**）当且仅当我们付出 $\max(0,\ k - nums[i])$ 把它**恰好抬到 $k$**——抬得更高不会让任何窗口额外受益，抬到 $k$ 以下则不改变 high/low 属性，都是浪费；
- $nums[i] \ge k$ 的位置**免费 high**（且不可能 low，终值无法低于初值）。

**观察 3（约束改写）**：每个 3 窗口的最大值 $\ge k$ $\iff$ 每个 3 窗口至少含一个 high $\iff$ **不存在 3 个连续的 low**。

> 💡 一句话总结：题目被改写成——给每个位置选 high（付 $\max(0, k-nums[i])$，$nums[i] \ge k$ 时强制 high 免费）或 low（付 0，需 $nums[i] < k$），使无 3 连续 low，最小化总代价。这是标准的**有限状态机线性 DP**。

### 3.3 算法流程：末尾连续 low 计数的状态机 DP

![状态机转移图](images/beautiful_array_dp_states.svg)

定义 $f_i[j]$：处理完前缀 $[0..i]$，所有完全落在前缀内的窗口均已满足，且**末尾连续 low 的个数为 $j \in \{0,1,2\}$** 时的最小总代价。转移看位置 $i$ 的选择：

$$
\begin{aligned}
f_i[0] &= \underbrace{\max(0,\ k - nums[i])}_{\text{位置 } i \text{ 抬到 } k} + \min\big(f_{i-1}[0],\ f_{i-1}[1],\ f_{i-1}[2]\big) \\
f_i[1] &= \underbrace{c_{\text{low}}(i)}_{\text{位置 } i \text{ 保持 low}} + f_{i-1}[0] \\
f_i[2] &= c_{\text{low}}(i) + f_{i-1}[1]
\end{aligned}
$$

其中 $c_{\text{low}}(i) = 0$ 若 $nums[i] < k$，否则 $+\infty$（已 $\ge k$ 的位置被迫 high，不许当 low 用）。

要点：

1. **$f_i[1]$ 只能来自 $f_{i-1}[0]$**：末尾 1 个 low 意味着 $i$ 是 low 且 $i-1$ 是 high，恰好是 $f_{i-1}[0]$ 的语义；$f_i[2]$ 同理只能来自 $f_{i-1}[1]$。
2. **不存在 $j = 3$ 的状态**：末尾 3 个 low 意味着窗口 $\{i-2,i-1,i\}$ 全 low，非法——「无 3 连续 low」的约束由**状态集合本身**表达，无需额外判断。
3. **哨兵初始化**：$f_{-1} = (0, +\infty, +\infty)$（空前缀、0 个尾部 low、代价 0），首元素的边界情况全部自动覆盖。
4. **答案**：$\min\big(f_{n-1}[0],\ f_{n-1}[1],\ f_{n-1}[2]\big)$。

三个状态只需滚动变量，$O(1)$ 空间。

### 3.4 示例演算

![示例 1 演算](images/beautiful_array_walkthrough.svg)

以示例 1（$nums = [2,3,0,0,2],\ k = 4$，抬升代价 $[2,1,4,4,2]$）逐行递推（$f_0/f_1/f_2$ 即三个滚动变量）：

| $i$ | $nums[i]$ | 代价 | $f_0$ | $f_1$ | $f_2$ |
|-----|-----------|------|-------|-------|-------|
| 哨兵 | — | — | $0$ | $+\infty$ | $+\infty$ |
| 0 | 2 | 2 | $2$ | $\mathbf{0}$ | $+\infty$ |
| 1 | 3 | 1 | $\mathbf{1}$ | $2$ | $0$ |
| 2 | 0 | 4 | $4$ | $\mathbf{1}$ | $2$ |
| 3 | 0 | 4 | $5$ | $4$ | $\mathbf{1}$ |
| 4 | 2 | 2 | $\mathbf{3}$ | $5$ | $4$ |

答案 $= \min(3, 5, 4) = \mathbf{3}$。加粗格子回溯最优路径：$f_0^{(4)} = 3 \leftarrow f_2^{(3)} = 1 \leftarrow f_1^{(2)} = 1 \leftarrow f_0^{(1)} = 1 \leftarrow f_1^{(0)} = 0$，即 **pos0 low、pos1 抬到 4（+1）、pos2/pos3 low、pos4 抬到 4（+2）**，终态 $[2,4,0,0,4]$，与官方解释一致。

## 4. 算法细节

1. **代价预计算**：每个位置的抬升代价 $\max(0, k - nums[i])$，以及「允许 low」标志 $nums[i] < k$，在遍历到该位置时现算即可，无需建数组。
2. **$\infty$ 的表示**：C++ 用 `LLONG_MAX / 4` 之类的「安全大数」，保证与有限代价相加不溢出；Python 直接 `float("inf")`。
3. **滚动实现**：新值 $f'_0, f'_1, f'_2$ 由旧值同时算出后再统一赋值（$f'_1$ 用旧 $f_0$、$f'_2$ 用旧 $f_1$），不要边算边覆盖。
4. **哨兵初始化**：$(f_0, f_1, f_2) \leftarrow (0, \infty, \infty)$。若坚持手写 $i = 0$ 的边界（$f_0 = $ 代价，$f_1 = 0$，$f_2 = \infty$）也可，但哨兵写法把首元素、次元素的边界全部统一进转移，更不易错。
5. **答案取三态最小**：末尾允许 0/1/2 个 low，均在窗口约束之内。

## 5. 正确性证明

**引理 1（窗口归约）**：数组满足「所有长度 $\ge 3$ 的子数组最大值 $\ge k$」当且仅当「所有长度恰为 3 的子数组最大值 $\ge k$」。

**证明**：($\Rightarrow$) 长度 3 的子数组也是长度 $\ge 3$ 的子数组。($\Leftarrow$) 设子数组长 $L \ge 3$，其前 3 个元素构成一个长度 3 的子数组，由条件其最大值 $\ge k$；又前 3 个元素是它的子集，故整个子数组的最大值 $\ge k$。∎

**引理 2（二值化）**：存在最优方案，使每个被操作位置 $i$ 恰好被增加 $\max(0,\ k - nums[i])$ 次、其余位置不被操作；且方案的合法性只取决于每个位置「终值是否 $\ge k$」。

**证明**：任取一个合法方案，记增量为 $inc(i) \ge 0$，并记 $S = \{i : nums[i] + inc(i) \ge k\}$。构造新方案：对 $i \in S$ 取 $inc'(i) = \max(0, k - nums[i])$，其余 $inc'(i) = 0$。则每个 $i \in S$ 的终值为 $\max(nums[i], k) \ge k$（仍在 $S$ 「high」），每个 $i \notin S$ 的终值为 $nums[i] < k$（仍 low）——各位置的 high/low 属性与原方案完全一致，故每个 3 窗口是否含 high 也一致，新方案同样合法。又对 $i \in S$ 有 $inc(i) \ge k - nums[i]$（当 $nums[i] < k$），对 $i \notin S$ 有 $inc'(i) = 0 \le inc(i)$，故总代价不增。∎

**推论**：原问题等价于：为每个位置选择 high / low（$nums[i] \ge k$ 者强制 high 且免费；$nums[i] < k$ 者选 high 付 $k - nums[i]$、选 low 付 0），使不存在 3 个连续 low，最小化总代价。

**引理 3（无后效性）**：前缀 $[0..i]$ 合法且末尾连续 low 数为 $j$ 的两个方案，对后缀 $[i+1..n-1]$ 的最优延续代价相同。

**证明**：后缀位置的代价只取决于后缀自身的选择。合法性方面，涉及前缀信息的窗口只有跨界的 $\{i-1, i, i+1\}$ 与 $\{i, i+1, i+2\}$（完全落在前缀内的窗口已由前缀合法保证），而它们在前缀中的元素 $i-1, i$ 的 high/low 状态被 $j$ 完全编码：$j=0 \Rightarrow i$ high；$j=1 \Rightarrow i$ low、$i-1$ high；$j=2 \Rightarrow i, i-1$ 均 low。两方案这些状态相同，故后缀可行选择集与代价相同。∎

**定理**：$f_i[j]$ 等于「前缀 $[0..i]$ 合法且末尾连续 low 数为 $j$」的最小代价（不可行为 $+\infty$），从而 $\min_j f_{n-1}[j]$ 为原问题的答案。

**证明**：对 $i$ 归纳（$i = -1$ 为哨兵：空前缀合法、$j=0$ 代价 0、$j \ge 1$ 不可行，与初始化一致）。归纳步看位置 $i$：

- 若 $i$ 为 high（付 $\max(0, k-nums[i])$）：窗口 $\{i-2,i-1,i\}$ 含 $i$ 自动满足，其余窗口由前缀 $[0..i-1]$ 的合法性保证；去掉 $i$ 后前缀仍合法，故 $f_i[0] = \text{cost}(i) + \min_{j'} f_{i-1}[j']$，且两式互相穷尽「$i$ high」的全部方案。
- 若 $i$ 为 low（需 $nums[i] < k$，付 0）：末尾 low 数为 1 时 $i-1$ 必为 high，即前缀状态恰为 $f_{i-1}[0]$；为 2 时 $i-1$ low、$i-2$ 必为 high（否则窗口 $\{i-2,i-1,i\}$ 全 low 违法），即前缀状态恰为 $f_{i-1}[1]$。得 $f_i[1], f_i[2]$ 的转移，且不存在其他可达的 low 方案（3 个连续 low 非法）。

由引理 2 只需考虑此类方案，由引理 3 每步取 $\min$ 不丢失最优延续，归纳成立；$[0..n-1]$ 即整个数组，取三态最小即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个位置常数次比较与加法（三个状态各 $O(1)$ 转移），$n = 10^5$ 时约 $10^6$ 次基本操作。
- **空间复杂度**：$O(1)$。仅三个滚动变量，无需保留整张 DP 表。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long minIncrementOperations(vector<int>& nums, int k) {
        const long long INF = LLONG_MAX / 4;
        // 哨兵：空前缀、0 个尾部 low；f1/f2 不可行
        long long f0 = 0, f1 = INF, f2 = INF;
        for (int x : nums) {
            long long costHigh = max(0LL, (long long)k - x);  // 抬到恰好 k
            long long lowCost = (x < k) ? 0 : INF;             // 已 ≥ k：被迫 high
            long long nf0 = costHigh + min({f0, f1, f2});      // i 选 high
            long long nf1 = lowCost + f0;                      // i low，i-1 high
            long long nf2 = lowCost + f1;                      // i,i-1 low，i-2 high
            f0 = nf0;
            f1 = nf1;
            f2 = nf2;
        }
        return min({f0, f1, f2});
    }
};
```

### Python

```python
class Solution:
    def minIncrementOperations(self, nums: List[int], k: int) -> int:
        INF = float("inf")
        f0, f1, f2 = 0, INF, INF  # 哨兵：空前缀、0 个尾部 low
        for x in nums:
            cost_high = max(0, k - x)   # 抬到恰好 k
            low_cost = 0 if x < k else INF  # 已 ≥ k：被迫 high
            f0, f1, f2 = (cost_high + min(f0, f1, f2),
                          low_cost + f0,
                          low_cost + f1)
        return min(f0, f1, f2)
```

## 8. 边界情况与易错点

1. **溢出**：单点代价至多 $k \le 10^9$，$n = 10^5$ 个位置全抬时总和达 $10^{14}$，超出 `int`——C++ 必须用 `long long`（官方签名即返回 `long long`）；Python 天然安全。
2. **已 $\ge k$ 的位置不许当 low**：其终值不可能 $< k$，转移到 $f_1 / f_2$ 时必须置 $+\infty$。若误当作「代价 0 的 low」，会算出偏小的错误答案。
3. **哨兵初始化**：用 $(0, +\infty, +\infty)$ 起步。若把三变量全部初始化为 $+\infty$ 再从 $i=0$ 手写边界，容易漏掉「首元素 high」「前两个元素都 low」等路径（笔者对拍时就踩过：$i > 1$ 的越界守卫误杀了 $f_1^{(1)}$ 的可达性）。
4. **$k = 0$**：任何元素都 $\ge 0 = k$，全员免费 high，答案 0——DP 自动给出，无需特判。
5. **$n = 3$**：只有一个窗口，答案退化为 $\min_i \max(0, k - nums[i])$，可用于小规模对拍校验。
6. **别把约束看成「长度 $> 3$」**：长度**恰好为 3** 的子数组也在约束内，窗口归约正是基于它。
7. **贪心 tempting 但错误**：见 3.1 的两个反例；「先便宜后覆盖」与「先当前后将来」都无最优子结构。
