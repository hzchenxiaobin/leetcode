# LeetCode 数组的最小相等和 题解

## 1. 题目概述

- **标题 / 题号**：数组的最小相等和（#2918，medium）
- **链接**：https://leetcode.cn/problems/minimum-equal-sum-of-two-arrays-after-replacing-zeros/
- **来源**：LeetCode 第 369 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定两个由正整数和 0 组成的数组 `nums1` 与 `nums2`。必须把两个数组中**所有** 0 替换为**严格**正整数，使两个数组的元素和相等。返回能达到的**最小相等和**；若无法使两数组相等，返回 `-1`。

**约束**：

- $1 \le \text{nums1.length}, \text{nums2.length} \le 10^5$
- $0 \le \text{nums1}[i], \text{nums2}[i] \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums1 = [3,2,0,1,0], nums2 = [6,5,0]
输出：12
解释：nums1 的两个 0 分别换成 2 和 4，得 [3,2,2,1,4]；
     nums2 的一个 0 换成 1，得 [6,5,1]。
     两数组元素和都等于 12，且不存在更小的相等和。
```

**示例 2**

```text
输入：nums1 = [2,0,2,0], nums2 = [1,4]
输出：-1
解释：nums1 的两个 0 至少各换成 1，替换后和至少为 6；
     而 nums2 没有 0，和被定死在 5，无法相等。
```

**示例 3（补充：覆盖「当前和相等但替换后无解」的陷阱）**

```text
输入：nums1 = [5], nums2 = [2,0,3]
输出：-1
解释：当前两数组和都是 5，看似已经相等；但 nums2 的 0 至少要换成 1，
     替换后 nums2 的和至少为 6，而 nums1 无 0、被钉死在 5 ⟹ 无解。
```

## 3. 解题思路

### 3.1 暴力思路

「把和凑相等」最直接的想法是**枚举**，有两条路：

- **枚举替换方案**：每个 0 可换成任意正整数，方案空间是无穷的，无从枚举；
- **枚举目标和 $T$**：从小到大枚举 $T$，对每个 $T$ 分别验证两个数组能否取到该和，第一个可行的 $T$ 即答案。

第二条路的**验证规则**本身很简单（设某数组的原和为 $s$、0 的个数为 $z$）：$z > 0$ 时把某个 0 多换 $k$ 就能让和增加 $k$，因此一切 $T \ge s + z$ 都可达；$z = 0$ 时和是定值 $s$，只有 $T = s$ 可达。但 $T$ 的上界可达 $10^5 \times 10^6 = 10^{11}$，逐个枚举必然超时。

> ⚠️ 然而验证规则只依赖 $s$ 与 $z$ 这两个统计量，**与 $T$ 的大小无关**——这正说明「枚举 $T$」是伪需求：可行 $T$ 的整体结构是一条射线，答案可以直接由公式给出。这是「先写验证、再发现验证与 $T$ 无关」的典型优化路径。

### 3.2 核心观察：可行和只有「射线」与「单点」两种形态

![可行和的两种形态](images/mes_reachability_spectrum.svg)

对每个数组只保留两个统计量：原和 $s$ 与 0 的个数 $z$，并定义**基线和**（把所有 0 都换成 1 时的和）：

$$\text{min} = s + z$$

**观察 1（可达集合刻画）**：替换后元素和的可达集合为

$$R = \begin{cases} [\,\text{min},\ +\infty), & z > 0 \quad \text{（橡皮筋：可任意拉伸）} \\ \{\, s \,\}, & z = 0 \quad \text{（定值：区间塌缩成单点）} \end{cases}$$

**观察 2（射线无缺口）**：$z > 0$ 时，要凑更大的和 $T$，把全部增量 $\Delta = T - \text{min} \ge 0$ **堆给任意一个 0**（该 0 换成 $1 + \Delta$）、其余 0 保持换 1 即可——中间任何整数都不会被跳过。

**观察 3（答案 = 交的最小元素）**：两个可达集合若有交，交形如 $[\,\max(\text{min}_1, \text{min}_2),\ +\infty)$（或单点），其最小元素就是

$$\text{答案} = \max(\text{min}_1, \text{min}_2)$$

交为空当且仅当**下界小的一侧是定值**——它被锁死在自己的 $s$ 上，永远够不到对方的下界，此时返回 $-1$。

> 💡 一句话：两侧要么是能无限拉伸的橡皮筋，要么是一枚钉死的钉子；答案就是两把「尺子」起点的较大者，除非起点低的那个其实是钉子。

### 3.3 算法流程

![算法流程](images/mes_algorithm_flow.svg)

1. **一趟扫描**：同时统计 $s_1, z_1, s_2, z_2$（`s += x; z += (x == 0)`）。
2. **计算公共下界**：$\text{lo} = \max(s_1 + z_1,\ s_2 + z_2)$。
3. **判定 nums1 是否无解侧**：若 $z_1 = 0$ 且 $s_1 < \text{lo}$（nums1 被钉死且够不到 lo）→ 返回 $-1$。
4. **判定 nums2 是否无解侧**：若 $z_2 = 0$ 且 $s_2 < \text{lo}$ → 返回 $-1$。
5. **返回** $\text{lo}$，即最小相等和。

> 💡 两步判定完全对称，本质是同一句话：「定值侧必须已经 $\ge \text{lo}$，否则无解」。两侧下界相等时两个条件都不可能成立，直接返回 lo——即使两侧都无零（各取自身和）也有解。

### 3.4 示例演算

![示例演算](images/mes_example_walkthrough.svg)

**示例 1**：`nums1 = [3,2,0,1,0]`, `nums2 = [6,5,0]`

| 数组 | $s$ | $z$ | $\text{min} = s+z$ | 可达集合 |
|------|-----|-----|--------------------|----------|
| nums1 | 6 | 2 | **8** | $[8, +\infty)$ |
| nums2 | 11 | 1 | **12** | $[12, +\infty)$ |

$\text{lo} = \max(8, 12) = 12$；下界小的是 nums1，$z_1 = 2 > 0$，可拉高 ⟹ 答案 **12**。构造方案：nums1 取基线 $[3,2,1,1,1]$（和 8），把增量 4 全堆给一个 0 换成 5，得 $[3,2,5,1,1]$；nums2 的 0 换成 1，恰取基线 $[6,5,1]$，两边都是 12。

**示例 2**：`nums1 = [2,0,2,0]`, `nums2 = [1,4]`

| 数组 | $s$ | $z$ | $\text{min} = s+z$ | 可达集合 |
|------|-----|-----|--------------------|----------|
| nums1 | 4 | 2 | **6** | $[6, +\infty)$ |
| nums2 | 5 | 0 | **5** | $\{5\}$（定值） |

$\text{lo} = \max(6, 5) = 6 > 5 = s_2$，而 $z_2 = 0$：nums2 被钉死在 5 上，交为空 ⟹ 返回 **-1**。

## 4. 算法细节

1. **统计量只有四个**：一趟线性扫描同时累加 $s_i$ 与数 $z_i$（`z += (x == 0)`），不排序、不修改原数组。
2. **判定的两种等价写法**：
   - 对称式：$\text{min}_1 < \text{min}_2 \wedge z_1 = 0$（及对称）；
   - 统一式：$\text{lo} = \max(\text{min}_1, \text{min}_2)$ 后判 $(z_1 = 0 \wedge s_1 < \text{lo}) \vee (z_2 = 0 \wedge s_2 < \text{lo})$。

   二者等价：$z_i = 0$ 时 $\text{min}_i = s_i$，而 $s_i < \text{lo}$ 恰说明对面下界更大。统一式先算 lo 再判两次，少一次比较、更难写错。
3. **64 位整数**：数组和上界 $10^5 \times 10^6 = 10^{11}$，远超 32 位 `int`（约 $2.1 \times 10^9$）。C++ 中累加器与返回值都必须 `long long`；若用 `accumulate`，初值要写 `0LL`。Python 整数天然无溢出。
4. **只求值、无需构造**：算法不输出具体替换方案，但引理 1 的构造（增量全堆给一个 0）随时可给出显式方案，可用于对拍验证。

## 5. 正确性证明

**引理 1（可达集合刻画）**：对任意数组，记 $s$ 为元素和、$z$ 为 0 的个数、$\text{min} = s + z$。将全部 0 替换为严格正整数后，元素和的可达集合为

$$R = \begin{cases} [\,\text{min},\ +\infty), & z > 0 \\ \{\, s \,\}, & z = 0 \end{cases}$$

**证明**：替换方案与「把 $z$ 个 0 逐一映到正整数 $r_1, \dots, r_z \ge 1$」一一对应，替换后总和为 $s + \sum_j r_j$。

（必要性）每个 $r_j \ge 1$，故 $\sum_j r_j \ge z$，任何可达和 $\ge s + z$；$z = 0$ 时没有可替换元素，总和恒为 $s$。

（充分性）任取整数 $T$：若 $z > 0$ 且 $T \ge \text{min}$，令 $\Delta = T - \text{min} \ge 0$，取 $r_1 = 1 + \Delta$、$r_j = 1\ (j \ge 2)$，则总和 $= s + z + \Delta = T$，故 $T$ 可达；若 $z = 0$，则 $T = s$ 可达。∎

**引理 2（交集刻画）**：设两数组的可达集合为 $R_1, R_2$，$\text{lo} = \max(\text{min}_1, \text{min}_2)$。则

$$R_1 \cap R_2 = \varnothing \iff (z_1 = 0 \wedge s_1 < \text{lo}) \vee (z_2 = 0 \wedge s_2 < \text{lo})$$

且当交集非空时 $\min(R_1 \cap R_2) = \text{lo}$。

**证明**：

（⟸ 无解条件成立）设 $z_1 = 0$ 且 $s_1 < \text{lo}$。由 $s_1 = \text{min}_1 < \text{lo} = \max(\text{min}_1, \text{min}_2)$ 知 $\text{lo} = \text{min}_2$，即 $\text{min}_2 > s_1$。由引理 1，$R_1 = \{s_1\}$，而 $R_2$ 中一切元素 $\ge \text{min}_2 > s_1$，故交集为空。$z_2 = 0$ 的情形对称。

（⟹ 逆否：两条件均不成立）往证 $\text{lo} \in R_1 \cap R_2$。对每个 $i \in \{1, 2\}$：

- 若 $z_i > 0$：由引理 1，一切 $T \ge \text{min}_i$ 均属于 $R_i$，而 $\text{lo} \ge \text{min}_i$；
- 若 $z_i = 0$：条件不成立意味着 $s_i \ge \text{lo}$；又 $s_i = \text{min}_i \le \text{lo}$，故 $s_i = \text{lo} \in R_i$。

于是 $\text{lo} \in R_1 \cap R_2 \ne \varnothing$。又 $R_i$ 中一切元素 $\ge \text{min}_i$，故交集元素均 $\ge \text{lo}$，从而最小元恰为 $\text{lo}$。∎

**定理**：算法返回值等于最小相等和（无解时返回 $-1$）。

**证明**：合法替换方案存在当且仅当 $R_1 \cap R_2 \ne \varnothing$。算法计算的 $\text{lo} = \max(s_1 + z_1,\ s_2 + z_2) = \max(\text{min}_1, \text{min}_2)$ 与引理 2 一致；返回 $-1$ 当且仅当引理 2 的无解条件成立；否则返回 $\text{lo} = \min(R_1 \cap R_2)$，即一切可行相等和的最小值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$，$n, m$ 为两数组长度。各扫描一遍统计 $s, z$，其余是常数次比较。这也是信息下界——不读完每个元素就无法确定 $s$ 与 $z$。
- **空间复杂度**：$O(1)$。只用 $s_1, z_1, s_2, z_2, \text{lo}$ 等常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minSum(vector<int>& nums1, vector<int>& nums2) {
        long long s1 = 0, z1 = 0, s2 = 0, z2 = 0;    // s: 元素和, z: 0 的个数
        for (int x : nums1) { s1 += x; z1 += (x == 0); }
        for (int x : nums2) { s2 += x; z2 += (x == 0); }
        long long lo = max(s1 + z1, s2 + z2);        // 两条基线的较大者
        if ((z1 == 0 && s1 < lo) || (z2 == 0 && s2 < lo))
            return -1;                               // 定值侧够不到 lo
        return lo;                                   // 交集的最小元素
    }
};
```

### Python

```python
class Solution:
    def minSum(self, nums1: List[int], nums2: List[int]) -> int:
        s1, z1 = sum(nums1), nums1.count(0)          # 元素和 与 0 的个数
        s2, z2 = sum(nums2), nums2.count(0)
        lo = max(s1 + z1, s2 + z2)                   # 两条基线的较大者
        if (z1 == 0 and s1 < lo) or (z2 == 0 and s2 < lo):
            return -1                                # 定值侧够不到 lo
        return lo                                    # 交集的最小元素
```

## 8. 边界情况与易错点

1. **溢出是唯一实现陷阱**：和最大 $10^{11}$，C++ 累加器与返回值都要 `long long`（返回类型本身就是 `long long`）；`accumulate(nums.begin(), nums.end(), 0)` 会按 `int` 溢出，初值必须 `0LL`。
2. **「当前和相等」不代表有解**：补充示例 3 中两数组当前和都是 5，仍返回 -1。判定只看替换后的下界 $s + z$，不看替换前的和。
3. **定值侧恰好等于 lo 时有解**：如 `nums1 = [5]`, `nums2 = [2,3]`：$\text{lo} = \max(5, 5) = 5$，两条件均不成立，返回 5。不要把判定误写成「$z = 0$ 就返回 $-1$」。
4. **全零数组并非无解**：`[0,0,0]` 的 $s = 0, z = 3$，可达和为 $[3, +\infty)$，仍有调整余地。
5. **替换值下界是 1 不是 0**：「严格正整数」意味着基线是 $s + z$ 而非 $s$，每个零至少贡献 1。
6. **两侧下界相等时永有解**：即便两侧都无零（各取自身和），lo 即为答案；无需任何特判。
