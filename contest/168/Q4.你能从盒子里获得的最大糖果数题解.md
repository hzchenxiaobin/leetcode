# LeetCode 你能从盒子里获得的最大糖果数 题解

## 1. 题目概述

- **标题 / 题号**：你能从盒子里获得的最大糖果数（#1298，hard）
- **链接**：https://leetcode.cn/problems/maximum-candies-you-can-get-from-boxes/
- **来源**：LeetCode 第 168 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、图、数组

**题意**：有 $n$ 个盒子，第 $i$ 个盒子由四元组描述：`status[i]`（1 表示本身就开着，0 表示锁着）、`candies[i]`（盒子里的糖果数）、`keys[i]`（打开它之后能拿到的钥匙，钥匙对应盒子的下标）、`containedBoxes[i]`（它里面装着的盒子）。

你初始**拥有** `initialBoxes` 里的盒子，但「拥有」不等于「能打开」：盒子 $b$ 可以被打开，当且仅当

$$\text{canOpen}(b) \iff b \in H \ \land\ \bigl(\text{status}[b] = 1 \ \lor\ b \in K\bigr)$$

其中 $H$ 是你**手上拥有**的盒子集合，$K$ 是你**已经拿到钥匙**的盒子集合。打开一个盒子可以：拿走它的全部糖果、得到它的 `keys`、得到它内部的 `containedBoxes`。求沿着这套规则能拿到的糖果总数最大值。

**约束**：

- $1 \le n \le 1000$
- `status[i]` 只能是 $0$ 或 $1$
- $1 \le \text{candies}[i] \le 1000$，故答案上界 $n \times 1000 = 10^6$
- `keys[i]` 与 `containedBoxes[i]` 内部元素互不相同；每个盒子**至多**被一个盒子包含
- $0 \le \lvert\text{initialBoxes}\rvert \le n$

## 2. 示例

**示例 1**

```text
输入：status = [1,0,1,0], candies = [7,5,4,100], keys = [[],[],[1],[]]
     containedBoxes = [[1,2],[3],[],[]], initialBoxes = [0]
输出：16
解释：开 0 得 7 颗糖果、盒子 1 和 2；1 锁着且没钥匙，于是先开 2 得 4 颗与钥匙 1；
     再开 1 得 5 颗与盒子 3；但没有任何盒子给 3 的钥匙，盒子 3 的 100 颗拿不到。
```

**示例 2**

```text
输入：status = [1,0,0,0,0,0], candies = [1,1,1,1,1,1], keys = [[1,2,3,4,5],[],[],[],[],[]]
     containedBoxes = [[1,2,3,4,5],[],[],[],[],[]], initialBoxes = [0]
输出：6
解释：开 0 同时拿到盒子 1~5 与它们的全部钥匙，五个盒子都能开，1 × 6 = 6。
```

**示例 3**

```text
输入：status = [1,1,1], candies = [100,1,100], keys = [[],[0,2],[]]
     containedBoxes = [[],[],[]], initialBoxes = [1]
输出：1
解释：status 全为 1，但初始只拥有盒子 1，且它不含任何盒子 —— 有钥匙、没盒子。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是枚举「打开顺序」：每一步从当前可打开的盒子里任选一个，开到底后统计糖果，取所有分支的最大值。由于每个盒子最多开一次，搜索树是 $n!$ 量级的排列枚举，$n = 1000$ 时完全不可行；即便把「已开集合」压成状态去重，状态空间也是 $3^n$（每个盒子：未拥有 / 拥有未开 / 已开），同样爆炸。

两个**看起来很对、其实会错**的简化：只把 `status == 1` 的盒子入队扫一遍，会漏掉示例 1 里「先有盒子、后有钥匙」的盒子 1（输出 11）；拿到盒子就无条件打开，又会把锁着的盒子 3 算进去（输出 116）。真正的暴力参照只能是「反复扫描直到没有新盒子能开」的 $O(n^2)$ 松弛——它已经正确，只是慢，正好是下面 BFS 的对照版本。

### 3.2 核心观察：双资源单调闭包

![开盒的两个条件与单调性](images/wc168_q4_open_condition.svg)

把局面记成三元组 $(H, K, O)$：手上拥有的盒子、已拿到的钥匙、已打开的盒子。开一个盒子只带来三类变化：

$$O \leftarrow O \cup \{b\},\qquad H \leftarrow H \cup \text{containedBoxes}[b],\qquad K \leftarrow K \cup \text{keys}[b]$$

**关键点在于：三个集合都只增不减，而开盒没有任何代价。** 于是有两条极重要的性质：

1. **不会「开错」**：现在能开的盒子，将来一定能开（$H$、$K$ 变大只会让判定更容易满足），「先开哪个」不会把局面变差。
2. **答案与顺序无关**：设 $R$ 为从初始资源出发按上述规则能推出的盒子集合（单调算子的**最小不动点**，即闭包），则任何合法顺序最终打开的盒子恰好都是 $R$。

于是问题从「在 $n!$ 种顺序里找最优」退化成「**求闭包**」：答案就是 $R$ 内所有 `candies` 之和。示例 1 的闭包是 $R = \{0, 2, 1\}$（盒子 3 缺钥匙，进不来），答案为 $7 + 4 + 5 = 16$。

> 💡 **一句话本质**：这是「双资源（盒子 $\times$ 钥匙）单调闭包」模型。资源单调 ⇒ 局部贪心就是全局最优 ⇒ BFS 一次即可。若开盒有代价、或钥匙会被消耗，单调性消失，本题立刻变成需要搜索的难题。

### 3.3 算法流程

![BFS 求闭包](images/wc168_q4_bfs_flow.svg)

用一次 BFS 把「反复检查」加速到线性。队列里只放**已经拿到手、且此刻确实能开**的盒子，三个布尔数组兼任状态与去重：

1. **初始化**：遍历 `initialBoxes`，标记 `held[b] = true`；若 `status[b] == 1` 则入队（初始钥匙集为空，锁着的初始盒子此刻打不开）。
2. **弹出 $b$**：若 `opened[b]` 已为真则跳过；否则置 `opened[b] = true`，把 `candies[b]` 计入答案。
3. **处理钥匙**：遍历 `keys[b]`，对每个 $k$ 置 `keyed[k] = true`；若此时 `held[k]` 且未打开，说明「钥匙等到了盒子」，$k$ 入队。
4. **处理内嵌盒子**：遍历 `containedBoxes[b]`，对每个 $c$ 置 `held[c] = true`；若 `status[c] == 1` 或 `keyed[c]`，说明「盒子等到了钥匙」，$c$ 入队。
5. **回到第 2 步**；队列空即到达不动点，返回累计糖果数。

注意入队判断只发生在「新资源到手」的那一刻：新钥匙到手时检查盒子，新盒子到手时检查钥匙。这两条互补的检查覆盖了所有可能，不需要在别处补扫描。

### 3.4 示例演算

![示例 1 的逐步走查](images/wc168_q4_walkthrough.svg)

对示例 1 逐步走查（图中每一行就是队列的一轮）：初始 $H = \{0\}$、$K = \varnothing$，盒子 0 本身开着，入队。开 0 得 7 颗糖果与盒子 1、2：盒子 2 本身开着入队，盒子 1 锁着且没有钥匙，只能先搁置。开 2 得 4 颗与钥匙 1，此时盒子 1 已在手上，补一次入队就把它唤醒。开 1 得 5 颗与盒子 3，但没有任何盒子给出 3 的钥匙，盒子 3 永久搁置。队列空时闭包 $R = \{0,2,1\}$，答案 $7+4+5=16$。

对照示例 2：盒子 0 一次给出全部盒子与全部钥匙，闭包是全集，答案 6；对照示例 3：`status` 全为 1，但初始只拥有盒子 1 且它不含任何盒子，闭包 $R = \{1\}$，答案 1 —— 这正是「有钥匙（甚至不需要钥匙）、却没有盒子」的情形。

## 4. 算法细节

1. **三个布尔数组缺一不可**：`held` 表示「盒子在手上」，`keyed` 表示「钥匙在手上」，`opened` 表示「已结算」。开盒条件是二者的**与**，把 `held` 和 `keyed` 合成一个数组是本题最常见的错误来源。
2. **初始只把 `status == 1` 的盒子入队**：初始钥匙集必为空（钥匙只能从开盒得到），锁着的初始盒子要等到某次开盒拿到它的钥匙才可能被唤醒。
3. **两个唤醒点都必须写**：新钥匙到手时检查 `held[k]`，新盒子到手时检查 `status[c] || keyed[c]`。少写任意一条都会漏盒：前者对应「盒子先到、钥匙后到」，后者对应「钥匙先到、盒子后到」。
4. **`opened` 去重要在弹出时也判**：同一盒子可能既 `status == 1` 又被某次开盒给了钥匙，会入队两次；不在弹出时判 `opened` 就会重复累加糖果。
5. **不要做贪心**：由 3.2 的单调性，任何顺序结果相同，按糖果数排序、优先开「贵」的盒子毫无意义，只会增加代码复杂度。
6. **`held`/`keyed` 也要守卫**：题面保证 `containedBoxes[i]`、`keys[i]` 内元素互不相同，但不同盒子可能给出同一个盒子或同一把钥匙，用 `if (held[c]) continue;` 与 `if (!keyed[k])` 避免重复入队。
7. **答案用 `int` 足够**：$n \le 1000$、每个盒子至多 $1000$ 颗糖果，答案不超过 $10^6$，远小于 `int` 上限；不必上 `long long`（用也无害）。
8. **等价写法**：把「反复扫描所有盒子直到没有变化」写成一个 `while(changed)` 循环，复杂度 $O(n^2)$，$n = 1000$ 时约 $10^6$ 次判定也能通过。BFS 是它的队列加速版，面试/比赛都建议写 BFS。

## 5. 正确性证明

先给出「可打开」的形式化定义：给定局面 $S = (H, K, O)$，称盒子 $b$ 在 $S$ 下**可打开**，若 $b \in H \setminus O$ 且（$\text{status}[b] = 1$ 或 $b \in K$）。一次开盒操作把 $S$ 变为 $S' = (H \cup \text{containedBoxes}[b],\ K \cup \text{keys}[b],\ O \cup \{b\})$，并取得 $\text{candies}[b]$。

**引理 1（开盒单调）**：设局面 $S \subseteq S'$（三个分量逐一包含），若 $b$ 在 $S$ 下可打开且 $b \notin O'$，则 $b$ 在 $S'$ 下也可打开。

**证明**：由 $b \in H \subseteq H'$ 得 $b \in H' \setminus O'$；又 $b \in K \Rightarrow b \in K'$，且 `status[b]` 是常量，故 $\text{status}[b] = 1$ 或 $b \in K'$ 至少一条成立。∎

**引理 2（顺序无关 / 交换性）**：若在某局面下 $b_1, b_2$ 都可打开，则先开 $b_1$ 再开 $b_2$ 与先开 $b_2$ 再开 $b_1$ 得到完全相同的局面与糖果总额。

**证明**：资源更新全是集合并，满足交换律 $A \cup B = B \cup A$；$O$ 增加的是同一个二元集合；糖果是加法，与顺序无关；合法性方面，开 $b_1$ 后由引理 1 知 $b_2$ 仍可打开（$b_2 \notin O$）。∎ 于是任何合法开盒序列都能通过相邻交换重排成任意指定顺序而不改变最终局面，这就是「顺序无关」的严格表述。

**引理 3（算法打开的盒子都属于闭包 $R$）**：对盒子集合 $R$ 记
$$H(R) = \text{initialBoxes} \cup \bigcup_{b \in R}\text{containedBoxes}[b],\qquad K(R) = \bigcup_{b \in R}\text{keys}[b]$$
取 $R$ 为满足「$b \in H(R) \land (\text{status}[b] = 1 \lor b \in K(R)) \implies b \in R$」的最小集合（即闭包），则算法每打开一个盒子 $b$，都有 $b \in R$。

**证明**：对算法开盒的时刻做归纳。初始时算法的 $H \subseteq H(R)$（初始盒子直接属于 $H(R)$）、$K = \varnothing \subseteq K(R)$。设当前已开的盒子集合 $O \subseteq R$，则算法的 $H \subseteq \text{initialBoxes} \cup \bigcup_{x \in O}\text{containedBoxes}[x] \subseteq H(R)$，同理 $K \subseteq K(R)$。被打开的 $b$ 满足 $b \in H$ 且（$\text{status}[b] = 1$ 或 $b \in K$），于是 $b \in H(R)$ 且（$\text{status}[b] = 1$ 或 $b \in K(R)$），由 $R$ 的封闭性得 $b \in R$。∎

**引理 4（闭包 $R$ 中的盒子算法都会打开）**：算法结束时，所有 $b \in R$ 都满足 `opened[b] = true`。

**证明**：算法终止时队列为空，且「闭」性成立：对任意 $b \in H \setminus O$，必有 $\text{status}[b] = 0$ 且 $b \notin K$（否则第 4 步或第 3 步早已把它入队并弹出）。即终止局面 $O$ 是算子 $F(O) = O \cup \{b \in H(O) : \text{status}[b] = 1 \text{ 或 } b \in K(O)\}$ 的**不动点**：$F(O) = O$。$F$ 单调（$O_1 \subseteq O_2 \Rightarrow F(O_1) \subseteq F(O_2)$），而 $R = \bigcup_{k \ge 0} F^k(\varnothing)$ 是最小不动点。由 $\varnothing \subseteq O$ 与 $F$ 单调，归纳得 $F^k(\varnothing) \subseteq F^k(O) = O$ 对一切 $k$ 成立，故 $R \subseteq O$。∎

**定理**：算法返回的糖果数等于所有合法策略能取得的最大糖果数。

**证明**：设 $S$ 是任意合法策略最终打开的盒子集合，对其开盒步数归纳并用引理 3 的论证可知 $S \subseteq R$（每步打开的盒子都满足 $R$ 的封闭条件），故该策略的糖果总额 $\sum_{b \in S}\text{candies}[b] \le \sum_{b \in R}\text{candies}[b]$（糖果均为正）。另一方面，算法打开的集合恰为 $R$（引理 3 + 引理 4），每个盒子只结算一次，取得的正是 $\sum_{b \in R}\text{candies}[b]$。两边一致，故算法最优。∎

**推论**：不在 $R$ 中的盒子（如示例 1 的盒子 3）无论换什么打开顺序都拿不到，这正是「最大」二字在本题中其实不产生分支的原因。

## 6. 复杂度分析

- **时间**：$O\bigl(n + \sum_i \lvert\text{keys}[i]\rvert + \sum_i \lvert\text{containedBoxes}[i]\rvert\bigr)$。每个盒子最多入队并弹出一次（`opened` 保证），弹出时只遍历它自己的 `keys` 与 `containedBoxes`，每个元素被访问常数次；初始化 $O(\lvert\text{initialBoxes}\rvert)$。
- **空间**：$O(n)$。三个 `bool` 数组各 $n$ 个（C++ 用 `vector<char>`），队列最坏同时存 $O(n)$ 个下标；不复制输入数组。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    int maxCandies(vector<int>& status, vector<int>& candies,
                   vector<vector<int>>& keys, vector<vector<int>>& containedBoxes,
                   vector<int>& initialBoxes) {
        int n = status.size();
        vector<char> held(n, 0), keyed(n, 0), opened(n, 0);
        queue<int> q;

        // 1. 初始拥有的盒子：本身开着才能立刻打开，锁着的要等钥匙
        for (int b : initialBoxes) {
            if (held[b]) continue;
            held[b] = 1;
            if (status[b] == 1) q.push(b);
        }

        int ans = 0;
        while (!q.empty()) {
            int b = q.front();
            q.pop();
            if (opened[b]) continue;          // 同一盒子可能被多次入队
            opened[b] = 1;
            ans += candies[b];

            // 2. 新钥匙：若盒子已经在手上，立刻唤醒
            for (int k : keys[b]) {
                if (!keyed[k]) {
                    keyed[k] = 1;
                    if (held[k] && !opened[k]) q.push(k);
                }
            }

            // 3. 新盒子：若它本身开着、或钥匙已在手上，立刻唤醒
            for (int c : containedBoxes[b]) {
                if (held[c]) continue;
                held[c] = 1;
                if (!opened[c] && (status[c] == 1 || keyed[c])) q.push(c);
            }
        }
        return ans;
    }
};
```

### Python

```python
from collections import deque
from typing import List


class Solution:
    def maxCandies(self, status: List[int], candies: List[int],
                   keys: List[List[int]], containedBoxes: List[List[int]],
                   initialBoxes: List[int]) -> int:
        n = len(status)
        held = [False] * n       # 盒子在手上
        keyed = [False] * n      # 钥匙在手上
        opened = [False] * n     # 已经打开并结算过
        q = deque()

        # 1. 初始拥有的盒子：本身开着才能立刻打开
        for b in initialBoxes:
            if held[b]:
                continue
            held[b] = True
            if status[b] == 1:
                q.append(b)

        ans = 0
        while q:
            b = q.popleft()
            if opened[b]:
                continue
            opened[b] = True
            ans += candies[b]

            # 2. 新钥匙：盒子已在手上就立刻唤醒
            for k in keys[b]:
                if not keyed[k]:
                    keyed[k] = True
                    if held[k] and not opened[k]:
                        q.append(k)

            # 3. 新盒子：本身开着、或钥匙已在手上，就立刻唤醒
            for c in containedBoxes[b]:
                if held[c]:
                    continue
                held[c] = True
                if not opened[c] and (status[c] == 1 or keyed[c]):
                    q.append(c)

        return ans
```

## 8. 边界情况与易错点

1. **`initialBoxes` 为空**：队列一开始就空，直接返回 0（官方示例 4）。不要漏掉「初始什么都不拥有」这个合法输入。
2. **初始盒子锁着、且永远没人给钥匙**：不会入队，答案为 0；例如 `status = [0,1]`、`containedBoxes = [[1],[]]`、`initialBoxes = [0]`，盒子 1 开着但拿不到，返回 0。
3. **有钥匙没盒子**（示例 3）：`status` 全 1 也没用，必须先拥有盒子；只有 `held` 与 `keyed` 同时为真才入队。
4. **有盒子没钥匙**（示例 1 的盒子 3）：会一直躺在 `held` 里直到队列空，不能因为「手上有这个盒子」就开它。
5. **重复入队导致糖果重复计**：同一盒子既 `status == 1` 又收到钥匙时会入队两次，必须在弹出时判 `opened` 后 `continue`，而不是只在入队处判。
6. **初始盒子顺序无关**：示例 5 的 `initialBoxes = [2,1,0]` 与 `[0,1,2]` 结果都是 7；不要写「只能按给定顺序开」的依赖。
7. **长链导致递归爆栈**：$n = 1000$ 的链式嵌套（盒 $i$ 里装盒 $i+1$）深度可达 1000，DFS 递归在部分环境下有风险，用队列迭代更稳。
8. **答案规模**：$10^6$ 用 `int` 足够；若把 `candies` 累加成 `long long` 也无害，但用 `int` 不会溢出，不必特判。

**延伸思考**：本题之所以能用 BFS 一次扫完，靠的是**资源单调 + 开盒零代价**。把假设改掉，模型立刻变化：

- **开盒有代价或钥匙会被消耗**（每次开盒扣 1 把万能钥匙、一把钥匙只能开一个盒子）：闭包不再唯一，要把「剩余钥匙数」纳入状态，甚至退化成二分图匹配/搜索问题。
- **开盒需要两个条件同时满足**（如盒子里还要有电池）：仍是单调闭包，BFS 框架不变，只把判定条件改成合取式。
- **要求输出一种打开顺序**：记录 BFS 的弹出顺序即可；由引理 2，任何合法顺序都达到最优，顺序本身不影响答案。
