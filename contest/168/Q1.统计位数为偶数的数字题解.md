# LeetCode 统计位数为偶数的数字 题解

## 1. 题目概述

- **标题 / 题号**：统计位数为偶数的数字（#1295，easy）
- **链接**：https://leetcode.cn/problems/find-numbers-with-even-number-of-digits/
- **来源**：LeetCode 第 168 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 `nums`，统计其中**十进制位数是偶数**的元素个数。`12` 是 2 位（偶）、`345` 是 3 位（奇）、`2` 和 `6` 是 1 位（奇）、`7896` 是 4 位（偶）。

**约束**：

- $1 \le \text{nums.length} \le 500$
- $1 \le \text{nums}[i] \le 10^5$
- 由值域可知位数 $d \in \{1,2,3,4,5,6\}$，**偶数位数只可能是 2、4、6 位**
- 答案不超过 500，`int` 足够；不存在负数、前导零，也不存在 $0$

> 💡 一句话本质：**位数只由数量级决定，所以「位数奇偶」等价于「$x$ 落在几个固定区间中的哪一个」**。

## 2. 示例

**示例 1**

```text
输入：nums = [12,345,2,6,7896]
输出：2
解释：
12   → 2 位（偶数）✔
345  → 3 位（奇数）
2    → 1 位（奇数）
6    → 1 位（奇数）
7896 → 4 位（偶数）✔
只有 12 和 7896 的位数为偶数，故答案 2。
```

**示例 2**

```text
输入：nums = [555,901,482,1771]
输出：1
解释：555、901、482 都是 3 位（奇数），只有 1771 是 4 位（偶数）。
```

**示例 3（补充，专攻边界）**

```text
输入：nums = [1,10,100,1000,10000,100000]
输出：3
解释：位数依次为 1、2、3、4、5、6，偶数位的是 10、1000、100000。
      注意 100000 = 10^5 恰好是 6 位数，必须计入（它等于约束上界）。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的三种写法都能通过（$n \le 500$、位数 $\le 6$，总操作量不到 $3000$ 次），差别在常数与坑：

1. **转字符串数长度**：`len(str(x)) % 2 == 0`。时间 $O(n \log V)$，但每个元素都要分配一个字符串对象。
2. **反复除以 10**：`while (x) { x /= 10; ++d; }`，最后看 `d` 的奇偶。$O(n \log V)$，无任何额外分配，是最通用的模板。
3. **`log10` 推位数**：$d = \lfloor \log_{10} x \rfloor + 1$。数学上 $O(1)$，但把正确性交给了浮点：某些平台/libm 上 `log10(1000)` 返回 $2.999999\ldots$，截断后 $d = 3$，4 位数就被判成了奇数位。

所以暴力的问题不是「超时」，而是「多做功 + 有隐患」。既然位数与数量级一一对应，就可以把「数位数」直接换成「查区间」：**每个元素最多 6 次整型比较，无除法、无字符串、无浮点**，这正是 Q1 值得沉淀的模板。

### 3.2 核心观察：偶数位数 = 三段数量级区间

![偶数位数对应的三段数量级区间](images/wc168_q1_digit_parity_ranges.svg)

位数为 $d$ 的数恰好是 $[10^{d-1},\,10^{d})$ 这一段。于是「位数是偶数」就是只取 $d = 2, 4, 6, \dots$ 对应的那几段：

$$x \in [10, 100) \;\cup\; [1000, 10000) \;\cup\; [10^5, 10^6) \;\cup\; \cdots$$

本题 $x \le 10^5$，所以只需要前三段，而第三段在值域内**只含一个点** $10^5$：

$$x \in [10,100) \;\cup\; [1000,10000) \;\cup\; \{100000\}$$

三个条件用短路或串起来即可。用**半开区间**写（上界写 $10^k$ 而不是 $99$、$9999$）有两个好处：一是不用数 9 的个数，二是上界 $10^5$ 天然落在第三段左端点，不会写成 `x < 100000` 而把唯一合法的 6 位数漏掉。

### 3.3 算法流程 / 状态转移

![一次遍历 + 三段区间判定的流程](images/wc168_q1_count_flow.svg)

```text
ans ← 0
for x in nums:
    if (10 ≤ x < 100) or (1000 ≤ x < 10000) or (100000 ≤ x < 1000000):
        ans ← ans + 1
return ans
```

循环不变量（§5 证明）：**每轮开始时，`ans` 等于「已经扫描过的元素中位数为偶数的个数」**。`ans` 单调不减、只增 1，所以既不会重复计数，也不会漏掉已扫描的前缀。

短路求值让常见情形的比较次数更少：落在 1–9、100–999 的元素只需 1 次或 2 次整型比较就被否决。

### 3.4 示例演算

![示例 1 的逐元素走查](images/wc168_q1_walkthrough.svg)

对 `nums = [12, 345, 2, 6, 7896]`：

| 元素 | 位数 $d$ | 命中区间 | 位数奇偶 | `ans` |
|------|----------|----------|----------|-------|
| 12 | 2 | $[10,100)$ | 偶数 ✔ | 1 |
| 345 | 3 | — | 奇数 | 1 |
| 2 | 1 | — | 奇数 | 1 |
| 6 | 1 | — | 奇数 | 1 |
| 7896 | 4 | $[1000,10000)$ | 偶数 ✔ | 2 |

扫描结束返回 2。示例 2 同理：`555`、`901`、`482` 的位数都是 3，落在 $[100,1000)$——**这个区间不在我们的三段之中，条件自然为假**，只有 `1771` 命中 $[1000,10000)$，返回 1。

示例 3 检查端点：`1`（1 位）、`100`（3 位）、`10000`（5 位）都不命中；`10`（2 位）、`1000`（4 位）、`100000`（6 位）命中，返回 3。

## 4. 算法细节

1. **一律使用半开区间** $[10^k,\,10^{k+1})$：端点归属与「位数」定义完全一致，不会出现把 `x <= 99` 写成 `x < 99` 这种差一错误。
2. **上界 $10^5$ 本身是合法的 6 位数**：第三段必须能用左闭端点接住它。写成 `x == 100000` 也对，但 `x >= 100000 && x < 1000000` 更整齐，且值域变化时不用改。
3. **为何不必处理 $x = 0$**：约束保证 $x \ge 1$。若 $0$ 被允许，字符串法得到 1 位（`"0"`，奇数位），而 `while (x)` 循环一次都不进、得到 0 位（会被判成偶数位）——两种口径结论相反，必须显式特判。
4. **不要用 `log10` 推位数**：浮点舍入在 $10^k$ 附近可能给出 $k - \varepsilon$，`floor` 之后位数偏小 1；即使本机测试正确，也不能把正确性建立在 libm 实现上。
5. **值域不定时的通用写法**：`int d = 0; while (x) { x /= 10; ++d; } return d % 2 == 0;`。若只关心奇偶，可以省掉计数：`int p = 0; while (x) { x /= 10; p ^= 1; }`，最后 `p == 0` 即偶数位。
6. **枚举区间会随上界扩张**：上界若放宽到 $10^9$，要补 $[10^6,10^7)$（7 位）与 $[10^8,10^{10})$（9、10 位，其中 $10^9$ 本身是 10 位数）；上界若到 $10^{18}$ 就要再补两段。段数一多就容易漏，这时用循环或 `to_string` 反而更稳。
7. **Python 的 `len(str(x))` 是可读性优先的合法选择**：$n \le 500$ 时字符串分配的开销可以忽略；但若被判题环境放大到 $n = 10^6$，区间比较的优势才显现。
8. **不要排序、不要去重**：题目数的是「元素个数」，重复出现的 `12` 要各算一次，任何 `set` / 排序都会引入 $O(n \log n)$ 并改变语义。

## 5. 正确性证明

**引理 1（位数公式）**：对任意整数 $x \ge 1$，设其十进制位数为 $d(x)$，则

$$d(x) = \lfloor \log_{10} x \rfloor + 1, \qquad\text{且}\qquad d(x) = d \iff 10^{d-1} \le x < 10^{d}.$$

**证明**：若 $10^{d-1} \le x < 10^d$，对三项取以 10 为底的对数（单调递增）得 $d-1 \le \log_{10} x < d$，故 $\lfloor \log_{10} x \rfloor = d-1$。反之，若 $x$ 的十进制表示有 $d$ 位，则其最高位的位权是 $10^{d-1}$，故 $x \ge 10^{d-1}$；又 $d$ 位数的上界是 $\underbrace{99\cdots9}_{d} = 10^d - 1 < 10^d$，故 $x < 10^d$。两个方向合起来即得等价关系。∎

**引理 2（区间刻画）**：对 $1 \le x \le 10^5$，$d(x)$ 为偶数 $\iff x \in [10,100) \cup [1000,10000) \cup \{10^5\}$。

**证明**：由约束 $x \le 10^5$ 与引理 1，$d(x) \in \{1,2,3,4,5,6\}$，其中偶数只有 $2,4,6$。逐一代入引理 1：

- $d = 2 \iff 10^1 \le x < 10^2$，即 $x \in [10,100)$；
- $d = 4 \iff 10^3 \le x < 10^4$，即 $x \in [1000,10000)$；
- $d = 6 \iff 10^5 \le x < 10^6$，与 $x \le 10^5$ 取交集恰为单点 $\{10^5\}$。

三段互不相交，并集即为全体偶数位数的 $x$。∎

**引理 3（循环不变量）**：对每个 $0 \le i \le n$，第 $i$ 轮循环开始时

$$\text{ans} = \bigl|\{\, j < i : d(\text{nums}[j]) \text{ 为偶数} \,\}\bigr|.$$

**证明**：对 $i$ 归纳。$i = 0$ 时集合为空，`ans = 0`，成立。设第 $i$ 轮开始成立，本轮取出 $x = \text{nums}[i]$：由引理 2，三段条件的真假与「$d(x)$ 为偶数」完全等价，故命中时 `ans` 加 1、未命中时不变，恰好把下标 $i$ 计入或排除；其余元素不受影响，$i+1$ 轮命题成立。∎

**定理**：算法返回 `nums` 中位数为偶数的元素个数。

**证明**：循环恰好迭代 $n$ 次（对每个元素一次，无 `break`、无提前返回），结束时 $i = n$，代入引理 3 得 `ans` 等于全体 $n$ 个元素中位数为偶数者的个数，正是所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素至多 3 段判断、每段 2 次整型比较，共 6 次 $O(1)$ 操作；短路求值下平均更少。若改用除以 10 数位数，则为 $O(n \log_{10} V)$，本题 $\log_{10} V \le 6$，两者在 $n \le 500$ 时都远低于时限，但区间法的常数不含除法与分支预测失败。
- **空间**：$O(1)$。只用了答案计数器与当前元素；C++ 以 `vector<int>&` 传引用，Python 的 `for x in nums` 也不复制数组。
- **对比字符串法**：`len(str(x))` 每个元素要构造一个长度 $\le 6$ 的字符串对象，时间同为 $O(n \log V)$ 但多 $O(\log V)$ 的临时分配；数据量大时是明显的常数差距。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findNumbers(vector<int>& nums) {
        int ans = 0;
        for (int x : nums) {
            // 偶数位数 <=> x 落在下列半开区间之一
            // 2 位: [10,100)   4 位: [1000,10000)   6 位: [100000,1000000)
            if ((x >= 10 && x < 100) || (x >= 1000 && x < 10000) ||
                (x >= 100000 && x < 1000000)) {
                ++ans;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findNumbers(self, nums: list[int]) -> int:
        ans = 0
        for x in nums:
            # 偶数位数 <=> x 落在下列半开区间之一
            if (10 <= x < 100) or (1000 <= x < 10000) or (100000 <= x < 1000000):
                ans += 1
        return ans
```

> 💡 若不想依赖「上界 $10^5$」这一事实，把判定换成通用写法即可：`d = 0; while x: x //= 10; d += 1`，再判 `d % 2 == 0`；两者在本题都能通过，区间法只是把 $O(\log V)$ 压成了常数。

## 8. 边界情况与易错点

1. **漏掉上界 $10^5$**：`100000` 是 6 位数（偶数位）。把第三段写成 `x > 100000` 或干脆省略，示例 3 就会输出 2 而不是 3。
2. **左端点写成开区间**：`x > 10` 会漏掉 `10`（2 位），`x > 1000` 会漏掉 `1000`（4 位）；位数公式的左端是闭的。
3. **一位数被误判**：`1..9` 是奇数位，不计数；不要因为「只有 1 位」就特判加一或提前 `return`。
4. **三条分支之间不能有重叠**：三段互不相交，所以不会同一个元素被加两次；若把区间写成 `[10,1000)` 这类粗粒度的段，就会把 3 位数误算进去。
5. **`log10` 的浮点误差**：`int d = (int)log10(x) + 1` 在 $x = 10^k$ 附近可能少算一位，导致 4 位数（应为偶数位）被判成 3 位（奇数位）；这是本题最隐蔽的 WA 来源。
6. **空数组 / 单元素（约束边缘）**：`nums` 长度至少 1，但代码对长度 0 也应自然返回 0；单元素时只有该元素决定答案，不需要特判。
7. **全奇位与全偶位输入**：`[1,2,...,9]` 应返回 0，`[10,11,...,99]` 应返回其长度；这两组数据能快速验证区间端点与计数是否各就各位。

**延伸思考**：

1. **闭式计数**：若要统计 $[1, N]$ 中位数为偶数的整数个数，不必逐个判断——偶数位段之间总隔着一个奇数位段，每段各 $9 \times 10^{d-1}$ 个，可按 $d$ 累加，$O(\log N)$ 得解（本题的区间法就是它的单点版本）。
2. **加一个数位条件**：若要求「位数为偶数**且**各位数字之和为偶数」，区间法立刻失效，需要**数位 DP**（状态：位置、位数奇偶、数位和奇偶、是否压上界）。
3. **输入是大整数字符串**：超过 64 位时无法转 `int`，此时位数 = 去掉前导零后的字符串长度，判定退化成一次长度取模——数据表示变了，观察「位数由表示长度决定」这一点依然成立。
