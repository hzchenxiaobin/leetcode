# LeetCode 划分数组为连续数字的集合 题解

## 1. 题目概述

- **标题 / 题号**：划分数组为连续数字的集合（#1296，medium）
- **链接**：https://leetcode.cn/problems/divide-array-in-sets-of-k-consecutive-numbers/
- **来源**：LeetCode 第 168 场周赛 Q2
- **难度**：中等
- **标签**：贪心，数组，哈希表，排序

**题意**：给定整数数组 `nums` 与正整数 `k`，判断能否把 `nums` **恰好划分**成若干个集合，每个集合恰好含 `k` 个数、并且这 `k` 个数是**连续整数**。每个元素必须使用且仅使用一次；能划分返回 `true`，否则返回 `false`。

**约束**：

- $1 \le k \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$
- 元素可重复；分组只看数值是否连续，不要求原数组中的位置相邻

> 本题与 [846. 一手顺子](https://leetcode.cn/problems/hand-of-straights/) 完全同题，只是参数名从 `hand` 换成了 `nums`。

```

**示例 2**

```

输出：false

```

输出：true
解释：1、2、3 各有 2 份，可以分成两组 [1,2,3]。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是回溯：每次从剩余元素中挑出 $k$ 个互不相同的数，检查是否连续，若连续就把它们删掉继续递归，失败则回溯换一组。枚举量约为

$$\frac{n!}{(k!)^{n/k}\,(n/k)!}$$

当 $n = 10^5$ 时这是天文数字，必然超时。暴力之所以慢，是因为它把「哪些元素该配在一起」当成自由选择；而本题的关键恰恰是**这个选择几乎完全被确定**。

另一种常见错误直觉是「只要能凑出连续的一组就随便凑」——例如 `nums = [1,2,3,4,5,6], k = 3`，若先拿 `{2,3,4}` 开刀，剩下的 1 就再也找不到 0 号搭档，明明有解却被判死。可见**配组顺序不能随意，必须由某个不变量决定**。

### 3.2 核心观察：最小值只能是某个集合的首元素

![最小值 x 只能当首元素，整组被强制取出](images/wc168_q2_forced_min_chain.svg)

设当前剩余元素中的最小值为 $x$。任何覆盖 $x$ 的合法集合都是 $k$ 个连续整数

$$\{a,\ a+1,\ \dots,\ a+k-1\},\qquad a \le x \le a+k-1.$$

由于剩余元素都 $\ge x$，集合里的最小元 $a$ 也必须 $\ge x$；又 $a \le x$，于是 $a = x$。**结论：含 $x$ 的集合被唯一确定为 $\{x, x+1, \dots, x+k-1\}$。**

更进一步：集合内 $k$ 个数互不相同，所以一个集合最多含一个 $x$。若剩余中 $x$ 出现 $c$ 次，就必须有 $c$ 个集合都以 $x$ 开头，即 $x, x+1, \dots, x+k-1$ **每个值都要扣掉 $c$ 份**。若某个 $x+j$ 的份数不足 $c$，直接判定无解。

这条观察把「搜索」变成了**无分支的贪心**：每一轮的动作完全确定，不存在「这样配还是那样配」的选择，也就没有回溯的需要。

### 3.3 算法流程

![算法流程：两处失败出口 + 一轮一轮扣减](images/wc168_q2_greedy_flow.svg)

1. 若 `n % k != 0`，立即返回 `false`（每组固定 $k$ 个元素，总数必须被 $k$ 整除）。
2. 排序 `nums`，并用哈希表统计每个值的**剩余份数** `cnt[v]`。
3. 按值从小到大扫描：跳过 `cnt[x] == 0` 的值；对当前最小值 $x$，令 $c = \text{cnt}[x]$。
4. 依次检查 $x, x+1, \dots, x+k-1$：只要有任何一个值的份数 $< c$，返回 `false`；否则每个值各减 $c$。
5. 扫描结束后所有份数都归零，返回 `true`。

第 4 步「一次扣 $c$ 份」等价于「一口气取出以 $x$ 开头的这 $c$ 个集合」，于是外层只需对排序数组做**一遍**线性扫描：每轮至少消耗 $k$ 个元素，最多 $n/k$ 轮；每轮 $k$ 次哈希表操作，扣减总代价 $O(n)$。真正的加速点在于**计数表把「找下一个值 $x+1$」变成 $O(1)$**——若没有计数表、只能在数组里线性查找后继，每轮就要 $O(n)$，总代价退化成 $O(n^2/k)$——$k$ 较小时就是 $O(n^2)$，$n = 10^5$ 直接超时。

### 3.4 示例演算

![两个示例的扣减走查](images/wc168_q2_walkthrough.svg)

以示例 1（`nums = [1,2,3,3,4,4,5,6]`，$k = 4$）为例，初始 `cnt = {1:1, 2:1, 3:2, 4:2, 5:1, 6:1}`：

| 轮次 | 最小值 $x$ | $c$ | 需要 $x \dots x+k-1$ | 扣减后剩余 |
|------|-----------|-----|----------------------|------------|
| ① | 1 | 1 | 1,2,3,4 都 $\ge 1$ ✓ | 3×1, 4×1, 5×1, 6×1 |
| ② | 3 | 1 | 3,4,5,6 都 $\ge 1$ ✓ | 全部为 0 |

两轮后所有份数归零 ⇒ `true`，对应分组 `[1,2,3,4]` 与 `[3,4,5,6]`。

反例 `nums = [1,2,3,3,4,4]`，$k = 3$：① 轮 $x = 1$、$c = 1$，取走 `{1,2,3}` 后剩 3×1、4×2；② 轮 $x = 3$、$c = 1$，需要 `{3,4,5}`，但 5 的份数为 0 ⇒ 返回 `false`。可见**失败总是暴露在「当前最小值的连续区间被截断」这一刻**：堆到后面的元素再也找不到能接上它的起点。

## 4. 算法细节

1. **先做整除判定**：`n % k != 0` 直接 `false`。这同时覆盖了 $k > n$ 的情况（此时 $n \bmod k = n \ne 0$）。
2. **值域到 $10^9$，不能开桶数组**：要么排序后扫描，要么用哈希表按值计数。C++ 用 `unordered_map<int,int>`、Python 用 `collections.Counter`，键的数量不超过 $n$。
3. **按值升序处理**：排序后的 `nums` 天然非降序，直接顺序遍历即可，此时 `nums[i]` 就是「当前剩余元素的最小值」——所有比它小的值的份数都已被归零，所以引理 1 的前提始终成立。
4. **一次扣 $c$ 份，检查条件同步是「每个值份数 $\ge c$」**：$c = \text{cnt}[x]$ 既是 $x$ 的剩余份数，也是必须以 $x$ 开头的集合个数；把 $x, \dots, x+k-1$ 各减 $c$ 相当于一次性取走这 $c$ 个集合，而「每个值份数 $\ge c$」正是这 $c$ 个集合能同时凑齐的充要条件。
5. **先查存在性再扣**：C++ 里必须 `find` 之后判断迭代器，不能写 `cnt[nums[i] + j]` 直接下标——`unordered_map` 的 `operator[]` 会**插入**默认值 0 的键，白白撑大哈希表并可能触发 rehash；在持有迭代器的写法里，rehash 还会让迭代器失效。
6. **提前失败**：内层一旦发现某个 $x+j$ 缺失或份数不足，立刻 `return false`，不必把 $k$ 个值都检查完。
7. **溢出**：$x + k - 1 \le 10^9 + 10^5 < 2^{31}-1$，`int` 足够；若担心稳妥可换成 `long long`，代价可忽略。
8. **C++ 哈希表预分配**：`cnt.reserve(n * 2)` 避免多次 rehash，$10^5$ 规模下能把常数压下来。

## 5. 正确性证明

**引理 1（首元素被钉死）**：设当前剩余多重集的最小值为 $x$，则任何覆盖 $x$ 的合法集合必为 $\{x, x+1, \dots, x+k-1\}$。

**证明**：合法集合是 $k$ 个连续整数 $\{a, a+1, \dots, a+k-1\}$，且 $a \le x \le a+k-1$。该集合的每个元素都取自剩余多重集，故都 $\ge x$，特别地 $a \ge x$。结合 $a \le x$ 得 $a = x$，集合即 $\{x, \dots, x+k-1\}$。∎

**引理 2（份数强制）**：若剩余多重集中 $x$ 出现 $c$ 次，则任何合法划分中恰有 $c$ 个集合等于 $\{x, \dots, x+k-1\}$，从而对每个 $0 \le j < k$，值 $x+j$ 至少被消耗 $c$ 份。

**证明**：集合内元素互不相同（$k$ 个严格递增的连续整数），所以一个集合最多含一个 $x$；$c$ 份 $x$ 必须由 $c$ 个不同的集合覆盖。由引理 1，这 $c$ 个集合都等于 $\{x, \dots, x+k-1\}$，各自消耗一份 $x+j$，共 $c$ 份。∎

**引理 3（规模缩减等价）**：记 $S$ 为当前剩余多重集，$S'$ 为扣掉 $c$ 份 $\{x, \dots, x+k-1\}$ 之后的多重集，则 $S$ 可合法划分 $\iff$ $S'$ 可合法划分。

**证明**：

- ($\Rightarrow$) 由引理 2，$S$ 的任一合法划分中必含这 $c$ 个集合，把它们删去，剩下的集合构成 $S'$ 的合法划分。
- ($\Leftarrow$) 把 $S'$ 的合法划分与这 $c$ 个集合合并，即为 $S$ 的合法划分（元素不多不少）。∎

**定理**：算法返回 `true` 当且仅当 `nums` 能被划分为若干个 $k$ 元连续集合。

**证明**：对剩余元素个数归纳。

- 基础：剩余为空时算法返回 `true`，空划分合法。
- 失败出口：算法在检查 $x+j$ 时返回 `false`，说明某个 $x+j$ 的份数 $< c$。由引理 2，任何合法划分都需要至少 $c$ 份，矛盾，故不存在合法划分。
- 通过检查时：算法扣掉 $c$ 份 $\{x, \dots, x+k-1\}$，把问题交给规模为 $|S| - ck < |S|$ 的剩余多重集；由引理 3 两者可划分性等价，由归纳假设后续过程正确。
- 终止：所有份数为 0 时，被扣掉的每一批都是一个合法集合，它们恰好覆盖 `nums` 的全部元素（计数守恒），构成一个合法划分，故返回 `true` 正确。∎

**推论**：若 $n \bmod k \ne 0$，则不可能划分——每个集合恰含 $k$ 个元素，总元素数必为 $k$ 的倍数。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；建表 $O(n)$；扣减阶段外层至多 $n/k$ 轮（每轮至少消耗 $k$ 个元素），内层每轮 $k$ 次哈希表操作，合计 $O\!\left(\frac{n}{k}\cdot k\right) = O(n)$。故总复杂度由排序主导。
- **空间**：$O(n)$。哈希表最多 $n$ 个不同键；排序为原地（额外 $O(\log n)$ 递归栈）。Python 的 `sorted(cnt)` 会额外产生 $O(d)$ 的键列表，$d \le n$ 为不同值个数。

若用 `TreeMap` 等有序结构代替「排序 + 哈希表」，复杂度同样是 $O(n \log n)$，只是常数更大。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <unordered_map>

using namespace std;

class Solution {
public:
    bool isPossibleDivide(vector<int>& nums, int k) {
        int n = (int)nums.size();
        if (n % k) return false;                 // 每组恰好 k 个，总数必须被 k 整除

        sort(nums.begin(), nums.end());
        unordered_map<int, int> cnt;             // 值 -> 剩余份数
        cnt.reserve((size_t)n * 2);
        for (int v : nums) cnt[v]++;

        for (int i = 0; i < n; i++) {
            auto it = cnt.find(nums[i]);
            if (it == cnt.end() || it->second == 0) continue;   // 该值已用完
            int c = it->second;                  // 必须有 c 个集合以 x 开头
            int x = nums[i];
            for (int j = 0; j < k; j++) {
                auto jt = cnt.find(x + j);       // 先查存在性，避免 operator[] 插入
                if (jt == cnt.end() || jt->second < c) return false;
                jt->second -= c;                 // 一次扣掉 c 份
            }
        }
        return true;                             // 所有份数归零
    }
};
```

### Python

```python
from collections import Counter


class Solution:
    def isPossibleDivide(self, nums: list[int], k: int) -> bool:
        n = len(nums)
        if n % k:
            return False                          # 总数不是 k 的倍数

        cnt = Counter(nums)                       # 值 -> 剩余份数
        for x in sorted(cnt):                     # 按键升序，快照不受修改影响
            c = cnt[x]
            if c == 0:
                continue                          # 该值已被前面的集合用完
            for y in range(x, x + k):             # y = x, x+1, ..., x+k-1
                if cnt.get(y, 0) < c:
                    return False                  # 中间缺值或份数不足
                cnt[y] -= c                       # 一次扣掉 c 份
        return True
```

## 8. 边界情况与易错点

1. **$k > n$**：由 `n % k != 0` 直接覆盖（$k > n \ge 1$ 时 $n \bmod k = n \ne 0$），不要写成除以 0 或数组越界。
2. **$k = 1$**：任何数组都能划分（每个元素自成一个「连续」集合），代码里内层循环只跑 `j = 0`，结果为 `true`。
3. **$n \bmod k \ne 0$**：如 `[1,2,3,4], k = 3`，直接提前返回 `false`。其实贪心自己也会把这种输入判失败（它返回 `true` 时消耗总数必是 $k$ 的倍数），但提前判断省掉整趟排序与遍历，是最廉价的快速失败。
4. **$k = n$**：此时只有「整个数组排序后恰好是连续整数」才为 `true`，如 `[1,2,3]` 返回 `true`、`[1,2,4]` 返回 `false`、`[1,2,3,4,6], k = 5` 返回 `false`；批量扣减里 $c$ 必为 1。
5. **值域 $10^9$ 不能开桶**：`cnt` 必须是哈希表或「排序 + 压缩」，且 `x + k - 1` 可能超出数组最大值，内层查表自然会报缺失，不要用下标访问。
6. **`unordered_map::operator[]` 的陷阱**：它会在键不存在时插入 0 值条目，可能让后续的 `it->second` 判断失真，也会在 rehash 时让已有迭代器失效；一律用 `find`。
7. **同一个值会被多次访问**：排序后 `x` 的 $c$ 个副本占 $c$ 个相邻下标，`cnt[x]` 变成 0 之后仍会再次命中同一下标。必须 `continue` 跳过：否则每个已用尽的值都要白跑 $k$ 次查表，最坏 $n \cdot k \approx 10^{10}$ 次操作直接超时（答案仍对，但慢到不可接受）。
8. **返回 `true` 不需要再校验总和**：只要中途没有失败，每个元素都属于某个被取走的 $k$ 元批次，计数守恒自动成立；但注意不要在循环里 `break` 提前跳出（那会跳过后续值的检查，本该 `false` 的用例被误判成 `true`）。

**延伸思考**：

1. 若要求**输出具体划分方案**而不是布尔值，只需在扣减时记录每次的起点 $x$（重复 $c$ 次），代码几乎不用改——贪心的每一步都在**构造**答案，不只是判定。
2. 若组长度改为「$k$ 或 $k+1$」，强制首元素的性质失效（$a$ 仍等于 $x$，但长度有两种选择），需要退化成「链模型」：对每个值维护还在延伸的链条数，用队列记录每条链的起点与长度，思路与 659 题一致。
3. 若把「连续」换成「公差为 $d$ 的等差数列」，只需把内层枚举的 $x+j$ 换成 $x + j\cdot d$，算法与证明完全不变（$d = 1$ 即本题）；这也说明本题的本质是**按剩余最小值强行确定整组**，与差值是否为 1 无关。
4. 若 `nums` 含负数或 0，哈希表同样适用，算法不变；只有「开桶计数」的写法才需要额外偏移。
