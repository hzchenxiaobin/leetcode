# LeetCode 困于环中的机器人 题解

## 1. 题目概述

- **标题 / 题号**：困于环中的机器人（#1041，medium）
- **链接**：https://leetcode.cn/problems/robot-bounded-in-circle/
- **来源**：LeetCode 第 136 场周赛 Q1
- **难度**：中等
- **标签**：数学、字符串、模拟

**题意**：无限平面上的机器人初始位于 $(0,0)$、面朝**北**（$y$ 轴正方向）。指令串 `instructions` 由三种字符组成：

- `G`：沿当前朝向前进 1 格；
- `L`：左转 90°；
- `R`：右转 90°。

机器人**无限重复**执行整个指令串。若存在一个环使机器人永远无法离开（即轨迹被限制在有限区域内），返回 `true`；否则返回 `false`。

**约束**：

- $1 \le \text{instructions.length} \le 100$
- `instructions[i]` 仅为 `'G'`、`'L'`、`'R'`

**关键概念**：一轮执行完后机器人相对出发点的位移向量 $\vec{d}$ 与朝向变化 $k \cdot 90°$，这两个量完全决定后续所有轮次的轨迹。

## 2. 示例

**示例 1**

```text
输入：instructions = "GGLLGG"
输出：true
解释：一轮走完回到 (0,0) 但朝向转为南（转了 180°）；
      第二轮反向原路返回，轨迹是 (0,0)→(0,2)→(0,0) 的往返线段，被限制住。
```

**示例 2**

```text
输入：instructions = "GG"
输出：false
解释：朝向始终朝北，每轮向北走 2 格，越走越远，无环。
```

**示例 3**

```text
输入：instructions = "GL"
输出：true
解释：每轮结束朝向都逆时针转 90°，四轮后位移恰好抵消为 0，轨迹是一个闭合的正方形回路。
```

## 3. 解题思路

### 3.1 暴力思路

模拟 $10^6$ 轮后看坐标是否超过某个阈值。正确性依赖「阈值选得够大」，本质上是在用经验赌答案，且最坏情况下（例如每轮位移很小但持续漂移）需要模拟很多轮才能区分，不够优雅。真正需要的是**一轮之内的结构**。

### 3.2 核心观察：一轮变换确定了全部

![一轮后的位移与朝向](images/wc136_q1_round_vector.svg)

把一轮执行看作一个**刚性变换**：位移 $\vec{d}$ + 朝向旋转 $k \cdot 90°$（$k \in \{0,1,2,3\}$）。由于机器人无限重复同一指令串，第 $t$ 轮（$t = 0,1,2,\dots$）开始时机器人朝向是初始朝向旋转 $t \cdot k \cdot 90°$，而这一轮的位移是 $\vec{d}$ 经过同样的旋转。于是

- **$k = 0$（朝向不变）**：每轮位移都是 $\vec{d}$，总位移 $= t\vec{d}$。若 $\vec{d} \ne 0$，机器人直线（或折线）远去，无环；若 $\vec{d} = 0$，原地循环。
- **$k \ne 0$**：朝向每轮改变，最多 4 轮回到初始朝向。此时这 4 轮的位移分别是 $\vec{d}, R\vec{d}, R^2\vec{d}, R^3\vec{d}$，其中 $R$ 是 90° 旋转矩阵，四者之和恒为 $\vec{0}$（见下图）。也就是说**每 4 轮机器人回到原点**，轨迹必然被限制在有限区域。

![四轮位移互相抵消](images/wc136_q1_four_rounds.svg)

于是判据极其简单：

$$\text{true} \iff \vec{d} = \vec{0} \ \text{或}\ k \ne 0$$

### 3.3 算法流程

```text
1. 方向数组 dir = [(0,1) 北, (1,0) 东, (0,-1) 南, (-1,0) 西]，d = 0（朝北）
2. x = y = 0
3. 遍历 instructions：
       'G' → (x, y) += dir[d]
       'L' → d = (d + 3) % 4
       'R' → d = (d + 1) % 4
4. 返回 (x == 0 && y == 0) || d != 0
```

### 3.4 示例演算

以 `"GGLLGG"` 为例：

| 指令 | 位置 | 朝向 |
|------|------|------|
| 初始 | $(0,0)$ | 北 |
| `G` | $(0,1)$ | 北 |
| `G` | $(0,2)$ | 北 |
| `L` | $(0,2)$ | 西 |
| `L` | $(0,2)$ | 南 |
| `G` | $(0,1)$ | 南 |
| `G` | $(0,0)$ | 南 |

一轮结束：$\vec{d} = (0,0)$、$k = 2$。两个条件都满足 → `true`。

再看 `"GG"`：$\vec{d} = (0,2)$、$k = 0$ → `false`；`"GL"`：$\vec{d} = (0,0)$、$k = 1$ → `true`（其实四轮后也回到原点）。

## 4. 算法细节

1. **方向编号**：用 `d ∈ {0,1,2,3}` 表示北、东、南、西，`R` 是 `d = (d+1) % 4`，`L` 是 `d = (d+3) % 4`（等价于减 1 取模），顺序写反是最常见错误。
2. **坐标系**：题目规定北是 $y$ 正方向、东是 $x$ 正方向。向量表取 `北=(0,1), 东=(1,0), 南=(0,-1), 西=(-1,0)`。
3. **只需一轮**：不必真的模拟 4 轮，位移与朝向的模运算已经蕴含全部信息。
4. **`d != 0` 的含义**：一轮后朝向不是北，就意味着「4 轮后归零」，与 $\vec{d}$ 具体是多少无关。
5. **不要用「位置是否在某个小盒子里」判断**：那需要人为设定阈值，且对 `"G"` 这类单步指令串（$\vec{d}=(0,1)$、$k=0$）会误判。

## 5. 正确性证明

记一轮的位移为 $\vec{d}$、朝向增量为 $k$，令 $R$ 为逆时针 90° 的旋转矩阵（把向量旋转 $k$ 个 90°）。

**引理 1（第 t 轮位移）**：第 $t$ 轮（从 0 计）机器人的位移为 $R^{tk}\vec{d}$，且该轮结束时朝向为初始朝向旋转 $(t+1)k \cdot 90°$。

**证明**：对 $t$ 归纳。$t = 0$ 时即一轮本身的定义。若第 $t$ 轮开始时朝向为初始朝向旋转 $tk\cdot90°$，由于整串指令是「相对朝向」的（`G` 沿当前朝向、`L`/`R` 相对旋转），整轮的运动轨迹等于一轮轨迹整体旋转 $tk\cdot 90°$，故位移为 $R^{tk}\vec{d}$，结束时朝向再叠加 $k\cdot90°$。∎

**引理 2（$k = 0$ 的情形）**：若 $k = 0$，则机器人被困住 $\iff \vec{d} = \vec{0}$。

**证明**：$k=0$ 时由引理 1，每轮位移都是 $\vec{d}$，第 $t$ 轮结束时位置为 $t\vec{d}$。

- 若 $\vec{d} = \vec{0}$，位置始终为原点，轨迹有限，被困住。
- 若 $\vec{d} \ne \vec{0}$，位置序列 $\lVert t\vec{d}\rVert = t\lVert\vec{d}\rVert \to \infty$，机器人离开任意有限区域，不被困住。∎

**引理 3（$k \ne 0$ 的情形）**：若 $k \in \{1,2,3\}$，机器人必被困住。

**证明**：由引理 1，每 4 轮（$k=2$ 时每 2 轮）位移之和为

$$\sum_{t=0}^{3} R^{tk}\vec{d} = \Bigl(\sum_{t=0}^{3} R^{tk}\Bigr)\vec{d}.$$

当 $k = 1$ 时 $\sum_{t=0}^{3} R^{t} = I + R + R^2 + R^3 = 0$（四个 90° 旋转的矩阵和为零矩阵）；$k = 2$ 时 $I + R^2 = 0$；$k = 3$ 时同 $k=1$（旋转方向相反，和仍为 0）。故每 4 轮（或 2 轮）机器人回到原点。而一轮之内的轨迹是有限条线段，因此整条轨迹被限制在「一轮轨迹的 4 个旋转副本」的并集内——有限区域，机器人被困住。∎

**定理**：算法返回 `true` $\iff$ 机器人被困在环中。

**证明**：算法返回 `true` 当且仅当 $\vec{d} = \vec{0}$ 或 $k \ne 0$。

- 若 $\vec{d} = 0$：无论 $k$ 为何，每轮都回到原点（引理 1 中 $\vec{d}=0$ 使位移恒为 0），被困住 ✓。
- 若 $\vec{d} \ne 0$ 且 $k \ne 0$：由引理 3 被困住 ✓。
- 若 $\vec{d} \ne 0$ 且 $k = 0$：由引理 2 不被困住 ✓。

三种情形互斥且穷尽，故判据与「被困住」等价。∎

## 6. 复杂度分析

- **时间**：$O(L)$，$L$ 为指令串长度。只需扫描一遍，每字符 $O(1)$。
- **空间**：$O(1)$。只存位置 $(x,y)$ 与朝向 $d$。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    bool isRobotBounded(string instructions) {
        const int dx[4] = {0, 1, 0, -1};   // 北、东、南、西
        const int dy[4] = {1, 0, -1, 0};
        int d = 0, x = 0, y = 0;
        for (char c : instructions) {
            if (c == 'G') { x += dx[d]; y += dy[d]; }
            else if (c == 'L') d = (d + 3) % 4;
            else d = (d + 1) % 4;
        }
        return (x == 0 && y == 0) || d != 0;
    }
};
```

### Python

```python
class Solution:
    def isRobotBounded(self, instructions: str) -> bool:
        # 方向向量：北、东、南、西
        dx = (0, 1, 0, -1)
        dy = (1, 0, -1, 0)
        d = x = y = 0
        for c in instructions:
            if c == 'G':
                x += dx[d]
                y += dy[d]
            elif c == 'L':
                d = (d + 3) % 4
            else:                     # 'R'
                d = (d + 1) % 4
        # 回到原点，或一轮之后朝向发生改变，都会被困在环中
        return (x == 0 and y == 0) or d != 0
```

## 8. 边界情况与易错点

1. **`L`/`R` 的取模方向**：`L` 必须是 `(d+3)%4`。写成 `(d-1)%4` 在 C++ 中会得到负数下标而越界（Python 的 `%` 恰好返回正数，容易在两种语言间迁移时踩坑）。
2. **只转不动的指令串**：如 `"LLLL"`，$\vec{d} = 0$、$k = 0$ → `true`（原地不动）。判据中 $\vec{d}=0$ 的分支覆盖了它。
3. **`"G"`**：$\vec{d}=(0,1)$、$k=0$ → `false`（一直往北）。这类输入常被「模拟若干轮后看是否回到原点」的写法误判成 `true`。
4. **`"GL"` 类**：$\vec{d}=0$ 但 $k\ne 0$，两个条件都成立，不要因为「$\vec{d}=0$」就提前返回而漏掉检查（其实都返回 `true`，但逻辑上不要依赖巧合）。
5. **`d != 0` 不要写成 `d == 2`**：$k = 1,2,3$ 都会被困住，只判 180° 会漏掉 `"GL"` 这类旋转 90° 的情形。
6. **坐标范围**：$L \le 100$，坐标绝对值 $\le 100$，`int` 足够；即使指令串更长也不会溢出。
