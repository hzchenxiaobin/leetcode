# LeetCode 将字符串分割成值不超过 K 的子字符串 题解

## 1. 题目概述

- **标题 / 题号**：将字符串分割成值不超过 K 的子字符串（#2522，medium）
- **链接**：https://leetcode.cn/problems/partition-string-into-substrings-with-values-at-most-k/
- **来源**：LeetCode 第 326 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、动态规划

**题意**：给定字符串 $s$（每一位都是 $1 \sim 9$ 的数字）与整数 $k$。把 $s$ 切成若干连续子串，使每个子串表示的十进制数值 $\le k$，且每位数字恰好属于一个子串（即普通划分）。求**最少**子串数；若不存在这样的切法则返回 $-1$。

**约束**：

- $1 \le |s| \le 10^5$
- $s[i] \in [\texttt{'1'}, \texttt{'9'}]$——**没有 '0'**，这是全文所有单调性论证的地基
- $1 \le k \le 10^9$——$k$ 至多 10 位，合法段长以 10 封顶

> 💡 **赛时最短路径**：两个信号直指贪心——①每位 $1 \sim 9$、无 '0'，子串值随长度**严格递增**，从任一起点"能延伸多远"被 $k$ 唯一钉死，"每段尽量长"顺理成章；②$k \le 10^9$ 把段长封顶在 10，即便退一步写 DP 也只是 $O(10n)$。实现只需防两个坑：`cur * 10 + d` 的 32 位溢出、单字符值 $> k$ 时的 $-1$ 判定。

## 2. 示例

**示例 1**

```text
输入：s = "165462", k = 60
输出：4
解释：切成 "16" | "54" | "6" | "2"，每段值 16、54、6、2 均 ≤ 60；
      不存在段数更少的好分割。
```

**示例 2**

```text
输入：s = "238182", k = 5
输出：-1
解释：'8' 这一位单字符值 8 > 5，包含它的任何子串值只会更大，无好分割。
```

**示例 3（自造，展示贴边吸收）**

```text
输入：s = "165462", k = 16
输出：5
解释：切成 "16" | "5" | "4" | "6" | "2"。首段恰好贴着 k = 16 吸满两位；
      此后任何两位段最小也 54 > 16，只能逐位成段。
```

## 3. 解题思路

### 3.1 暴力思路：枚举切割方案

最朴素的做法是枚举 $n - 1$ 个切割位置的子集，共 $2^{n-1}$ 种方案、每种还要 $O(n)$ 验证，$n = 10^5$ 时是天文数字。稍加观察可以剪枝：段长 $\le 10$（见观察 2），于是从左往右 DFS 枚举"第一段的长度"，每个分支至多 10 个候选——但路径数最坏仍有 $10^{n/10} = 10^{10^4}$ 条，依旧爆炸。

问题出在"划分方案总数指数级"而"我们只要最少段数"——这是 DP（$O(10n)$，见 §7 对照代码）或者更快的贪心（$O(n)$）的典型信号。

### 3.2 核心观察：无 0 ⇒ 单调 ⇒ 每段尽量长

![核心观察：无 0 保证段值随长度严格递增，贪心切点唯一](images/wc326_q3_greedy_concept.svg)

三个环环相扣的观察：

- **观察 1（值严格递增）**：每位 $\ge 1$，往子串末尾追加一位 $d$，值从 $v$ 变为 $10v + d \ge 10v + 1 > v$。所以**固定起点后，子串值随终点右移严格递增**——从起点 $i$ 出发，"值 $\le k$ 的最长子串"右端点 $j^*$ 唯一存在。切点不是我们选的，是 $k$ 钉死的。
- **观察 2（段长上界）**：$k \le 10^9 < 1111111111 \le$ 任何 10 位正数串的值，故合法段长 $\le D = \lfloor \log_{10} k \rfloor + 1 \le 10$。
- **观察 3（无解判据）**：某位 $d > k \iff$ 无解。包含该位的任何子串值 $\ge d \cdot 10^{r} \ge d > k$（$r$ 为该位右侧剩余位数），这一位塞进任何段都超限。

于是**贪心策略**：从左到右扫描，当前段能吸就吸下一位；一旦吸入会超 $k$，就把当前段封掉、以新位开段。若新位自身 $> k$（单字符段都非法），直接返回 $-1$。

> ⚠️ **贪心为什么这次不翻车**：直觉是"第一段切得越长，留给后面的越短、总段数越少"。严格论证靠的是**后缀不等式**（引理 1(b)）：把某段延长后，被挤压段剩下的真后缀值只会**变小**、不会非法。对比 LC 132 回文拆分——延长第一段后剩余部分可能既难拆成回文也未必更优，"每段尽量长"在那边是错的。能否贪心，看的正是"延长一段是否让剩余部分更安全"这一性质。

### 3.3 算法流程：单趟扫描

![算法流程：单趟扫描，能吸则吸、吸不下就封段](images/wc326_q3_scan_flow.svg)

伪代码（`cur` 为当前正在生长的段的值，`ans` 为已封段数）：

```text
cur = 0, ans = 0
for 每个字符 c（其数值为 d）:
    if d > k:               return -1          # 观察 3：无解
    if cur * 10 + d <= k:   cur = cur * 10 + d # 还吸得下：并入当前段
    else:                   ans += 1; cur = d  # 封段；d 开新段（d ≤ k 已保证合法）
return ans + 1                                  # 末段收账
```

两条**循环不变式**贯穿全程：① $0 \le \text{cur} \le k$（吸入前判过、开新段时 $d \le k$ 判过）；② `cur` 恒等于当前段所覆盖子串的真实数值。它们合起来保证每一步封掉的段都合法、返回 $-1$ 的时机不早不晚。

## 4. 算法细节

1. **判定顺序不能换**：`if (d > k) return -1` 必须放在"封段开新段"**之前**。若先判 `cur*10+d <= k`，遇到 $d > k$ 会执行"封段、`cur = d`"，让 $\text{cur} > k$ 破坏不变式，把本应 $-1$ 的输入算出一个错误段数（反例见 §8 第 2 条）。
2. **末尾补 1**：循环里只在"超限封段"时 `ans++`，最后一段永远等不到超限事件，须 `return ans + 1`。
3. **溢出防护（C++）**：$\text{cur} \le k \le 10^9$，故 $\text{cur} \cdot 10 + d \le 10^{10} + 9 > 2^{31} - 1$，`int` 会溢出（UB）。用 `long long`，或把判断改写成 `cur > (k - d) / 10` 全程不越界。Python 无此虞。
4. **段长上界的用法**：贪心版天然满足（一超就切，无需回看）；DP 版要显式用它限制内层回看长度 $\le 10$，否则退化 $O(n^2)$。
5. **数据结构选择**：全程只有 `cur`、`ans` 两个标量，无任何辅助结构——这是"贪心优于 DP"的形态：DP 的 `dp[i]` 们其实全冗余，最优转移永远指向"最远的合法 $j$"，而那个 $j$ 正是贪心的切点。

## 5. 正确性证明

**引理 1（单调性与后缀不等式）**：设位串各位均属于 $[1, 9]$，记 $\mathrm{val}(\cdot)$ 为其十进制值。

- (a) *追加递增*：$\mathrm{val}(t \cdot d) = 10\,\mathrm{val}(t) + d \ge 10\,\mathrm{val}(t) + 1 > \mathrm{val}(t)$；
- (b) *后缀不等式*：若 $t = p \cdot q$（$q$ 为非空真后缀，$p$ 非空），则 $\mathrm{val}(t) = \mathrm{val}(p) \cdot 10^{|q|} + \mathrm{val}(q) \ge 10^{|q|} + \mathrm{val}(q) > \mathrm{val}(q)$；
- (c) *包含下界*：位 $d$ 在段 $w$ 中右侧还有 $r$ 位，则 $\mathrm{val}(w) \ge d \cdot 10^{r} \ge d$。

**证明**：(a)(c) 由十进制按位展开即得；(b) 中 $p$ 非空且每位 $\ge 1$ 故 $\mathrm{val}(p) \ge 1$，且 $|q| \ge 1$。∎

**引理 2（无解判据）**：$s$ 存在好分割 $\iff$ 每个单字符 $s[i] \le k$。

**证明**：(⇐) 全部单字符成段即好分割。(⇒) 若 $s[i] = d > k$，任何包含该位的段 $w$ 由引理 1(c) 有 $\mathrm{val}(w) \ge d > k$，而好分割中每位必属于某段，矛盾。∎

**定理（贪心最优性）**：设贪心分段 $H = (H_1, \dots, H_t)$（每段取从当前段首开始值 $\le k$ 的最长子串）。若贪心中途返回 $-1$，则无好分割；否则 $t = \min \{\, |G| : G \text{ 为好分割} \,\}$。

**证明**（延长论证 + 公共前缀归纳）：贪心中途返回 $-1$ 的情形由引理 2 直接给出正确性。以下设贪心完整产出 $H$，此时每个起点处的 $j^*$ 均存在（起点处单字符 $\le k$）。

对任意好分割 $G$，归纳断言：对 $0 \le r \le t$，存在好分割 $G^{(r)}$，其前 $r$ 段与 $H_1, \dots, H_r$ 完全相同，且 $|G^{(r)}| \le |G|$。

$r = 0$ 取 $G^{(0)} = G$。设已得 $G^{(r)}$（$r < t$）。注意 $H_1, \dots, H_r$（$r < t$）未覆盖到串尾，故 $G^{(r)}$ 必有第 $r{+}1$ 段，且与 $H_{r+1}$ 同起点 $i$。由引理 1(a)，起点 $i$ 处的合法终点恰组成区间 $[i, j^*]$；$G^{(r)}$ 的第 $r{+}1$ 段 $s[i..a]$ 合法意味着 $a \le j^*$：

- $a = j^*$：取 $G^{(r+1)} = G^{(r)}$。
- $a < j^*$：把第 $r{+}1$ 段延长为 $s[i..j^*]$（合法性由 $H_{r+1}$ 保证）。考察 $G^{(r)}$ 中自 $a{+}1$ 起的各段，取**第一个**右端点 $b > j^*$ 的段 $E$（若不存在，说明这些段全被 $s[i..j^*]$ 覆盖，而它们覆盖到串尾，故 $j^*$ 已达串尾，新分割恰为前 $r{+}1$ 段，段数 $r{+}1 \le |G^{(r)}|$）。设 $E = s[a'{+}1..b]$：$E$ 之前的段整段被吞（至少一个），故段数不增；$E$ 的起点紧随被吞段之后，$a' \le j^* < b$，于是接上新段 $s[j^*{+}1..b]$——它是 $E$ 的后缀（可能整段），当其为真后缀时由引理 1(b) 值 $< \mathrm{val}(E) \le k$，合法；再接 $E$ 之后的各段。得 $G^{(r+1)}$，段数 $\le |G^{(r)}| \le |G|$。

归纳至 $r = t$：$G^{(t)}$ 的前 $t$ 段 $= H$ 的全部段，已覆盖整个 $s$（$H$ 是 $s$ 的完整划分），故 $G^{(t)} = H$。于是 $|H| = |G^{(t)}| \le |G|$，由 $G$ 的任意性得证。

最后核对算法返回值恰为 $t$：当前段从段首生长，由单调性恰在第 $j^*{+}1$ 位吸入失败，封段次数为 $t - 1$，末段收账 $+1$ 得 $t$。∎

> 💡 **一句话版证明**：把任何好分割的第一段"掰长"到贪心位置，被挤扁的段只会变得更小更合法、段数不增——反复掰下去，任何好分割都能不增段数地变成贪心解。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个字符恰处理一次，每次一次 64 位乘加与两次比较，均为 $O(1)$；与段长上界 $D \le 10$ 无关（一超即切，无需回看）。
- **空间复杂度**：$O(1)$。仅 `cur`、`ans` 两个标量。
- **对照（DP）**：$O(nD)$ 时间、$O(n)$ 空间，$D \le 10$；**对照（暴力）**：$2^{n-1}$ 种切割方案或 $10^{n/10}$ 条 DFS 路径，均不可行。

## 7. 参考代码

### C++（单趟贪心）

```cpp
class Solution {
public:
    int minimumPartition(string s, int k) {
        long long cur = 0;          // 当前段的值，恒满足 cur <= k
        int ans = 0;                // 已封段数
        for (char c : s) {
            int d = c - '0';
            if (d > k) return -1;               // 单字符超限 → 无解
            if (cur * 10 + d <= k) {
                cur = cur * 10 + d;             // 吸得下：并入当前段
            } else {
                ans++;                          // 封段
                cur = d;                        // d 开新段（d <= k 已保证合法）
            }
        }
        return ans + 1;                         // 末段收账
    }
};
```

> 💡 `long long` 不可省：$\text{cur} \cdot 10 + d$ 最大 $10^{10} + 9$，超 `int` 上界。若坚持 32 位，把判断改写为 `cur > (k - d) / 10`。

### Python（单趟贪心）

```python
class Solution:
    def minimumPartition(self, s: str, k: int) -> int:
        ans, cur = 0, 0
        for c in s:
            d = int(c)
            if d > k:                    # 单字符超限 → 无解
                return -1
            if cur * 10 + d <= k:
                cur = cur * 10 + d       # 吸得下：并入当前段
            else:
                ans += 1                 # 封段，d 开新段
                cur = d
        return ans + 1                   # 末段收账
```

### 对照：O(nD) 动态规划

```python
class Solution:
    def minimumPartition(self, s: str, k: int) -> int:
        n = len(s)
        INF = float('inf')
        dp = [0] + [INF] * n             # dp[i]：前 i 位的最少段数
        for i in range(1, n + 1):
            cur, p = 0, 1
            for j in range(i - 1, max(-1, i - 11), -1):   # 段长 <= 10
                cur += int(s[j]) * p      # 新位加在最高位
                p *= 10
                if cur > k:
                    break                 # 更长只会更大
                if dp[j] + 1 < dp[i]:
                    dp[i] = dp[j] + 1
        return -1 if dp[n] == INF else dp[n]
```

> 💡 DP 版的价值在于**变形免疫**：一旦题目改成"好分割的方案数"（LC 139 单词拆分式计数）或"每段附加惩罚的最优划分"，骨架不变、只改转移；贪心则直接失效。内层从 $i-1$ 向左回看时新位 $s[j]$ 要加在**最高位**（`cur += int(s[j]) * p`），随手写成 `cur * 10 + int(s[j])` 会把段串反过来读——如 $s[7..8] = \texttt{"41"}$ 被算成 14，是此写法的高频笔误。

## 8. 边界情况与易错点

1. **32 位溢出**：`cur * 10 + d` 上界 $10^{10} + 9 > 2^{31} - 1$。C++ 用 `long long`（或 `cur > (k - d) / 10` 写法）；溢出是 UB，可能把"吸不下"错判成"吸得下"，输出偏小。
2. **漏判 `d > k` 或判晚了**：反例 $s = \texttt{"238182"}, k = 5$——正确输出 $-1$；若"封段开新段"先于 $d > k$ 判定执行，`'8'` 会被当作新段首继续算，错误输出 6。判定顺序是本题最大的坑。
3. **忘写 `ans + 1`**：末段没等到"超限"事件，循环内不会自增。反例 $s = \texttt{"1"}, k = 9$：漏写则返回 0。
4. **DP 不设段长上界 / 不 break**：内层一路回看到 $j = 0$ 且不提前 break，退化为 $O(n^2)$，$n = 10^5$ 直接 TLE。
5. **多写 '0' 特判**：题面保证 $s[i] \in [\texttt{'1'}, \texttt{'9'}]$，诸如"前导零""空段"的守卫代码纯属多余；但要把"无 0"记在心里——它是引理 1、也是贪心正确性的地基。
6. **k 的两个极端**：$k \ge 9$ 时 $-1$ 分支永不触发；$k \le 8$ 时 $\text{cur} \cdot 10 + d \ge 10 > k$ 恒成立，答案必为 $n$（逐位成段）。可作对拍 sanity check。
7. **读清"值"与"划分"的语义**：子串值是十进制整数（`"16"` 是 16 不是 $1 + 6$）；"好分割"要求每位**恰好**属于一个子串——即普通划分，不允许重叠或跳过，这让"段首紧密衔接"天然成立。

**延伸思考**：① 若 $s$ 可含 '0'（仍按十进制取值、允许前导零）：引理 1(b) 中前缀值仍 $\ge 1$，后缀不等式不变，贪心依然正确，且 '0' 单字符值 $0 \le k$ 恒合法；真正麻烦的是"子串不得含前导零"的变体（LC 902 风格），那里单调性被破坏、贪心失效。② 若 $k \le 10^{18}$：段长上界变 19，Python 无感，C++ 需 `__int128` 或按字符串比较。③ 若改问"好分割的方案数"：贪心失效，回到 §7 的 DP 骨架把 $\min$ 改为求和。④ 本题为何不能像 410 那样"二分答案"：$k$ 是**给定输入**而非可调目标，"段数关于 $k$ 单调"在这里没有可二分的对象；反过来 410 的判定步"该阈值下最少段数 $\le m$"正是本题的贪心。
