# LeetCode 大于平均值的最小未出现正整数 题解

## 1. 题目概述

- **标题 / 题号**：大于平均值的最小未出现正整数（#3678，easy）
- **链接**：https://leetcode.cn/problems/smallest-absent-positive-greater-than-average/
- **来源**：LeetCode 第 165 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定整数数组 `nums`，其**平均值**为所有元素之和除以元素个数。要求返回一个正整数 $x$，满足：

1. $x$ **严格大于** `nums` 的平均值；
2. $x$ **没有**在 `nums` 中出现过；
3. 在所有满足前两条的正整数中 $x$ **最小**。

注意 $x$ 只要求「是正整数且不在数组中」，并不要求 $x$ 与数组元素有任何其他关系。数组元素可以是负数，平均值也可能是负数。

**约束**：

- $1 \le nums.length \le 100$
- $-100 \le nums[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [3,5]
输出：6
解释：平均值 = (3+5)/2 = 4，严格大于 4 的正整数中，5 在数组里出现过，故答案是 6。
```

**示例 2**

```text
输入：nums = [-1,1,2]
输出：3
解释：平均值 = (-1+1+2)/3 = 0.667，从 1 开始检查：1 出现过、2 出现过，答案是 3。
```

**示例 3**

```text
输入：nums = [4,-1]
输出：2
解释：平均值 = (4+(-1))/2 = 1.5，严格大于 1.5 的最小正整数是 2，且 2 未出现，答案是 2。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法：先把整个数组扫一遍算出总和 $S$ 与长度 $n$，再从 $x=1$ 开始**逐一枚举**每个正整数，判断 $x \cdot n > S$（等价于 $x$ 严格大于平均值）且 $x$ 不在 `nums` 中，第一个满足条件的 $x$ 就是答案。判断「是否出现」如果每次线性扫描，单次判定 $O(n)$；用集合预处理后单次 $O(1)$。

暴力并不慢，因为答案的上界很小（见 §4），但它没有利用「答案的下界可以直接算出来」这一事实，需要从 1 一路试到答案。下面把这个下界显式地算出来。

### 3.2 核心观察：答案的下界是 $\lfloor \bar{a} \rfloor + 1$

![平均值给出下界，再从下界出发找第一个缺失正整数](images/bw165_q1_average_threshold.svg)

设平均值为 $\bar{a} = S / n$，则

$$\bar{a} = \frac{S}{n}, \qquad x > \bar{a} \iff x \cdot n > S .$$

把「严格大于平均值的最小整数」记作 $x_0$，它恰好是 $\bar{a}$ 的**下取整再加一**：

$$x_0 = \left\lfloor \bar{a} \right\rfloor + 1 .$$

于是候选集从 $\{1, 2, 3, \dots\}$ 缩小到 $\{x_0, x_0+1, x_0+2, \dots\}$：只要从 $x_0$ 开始，**不断加一到第一个不在数组中的值**即可。

两个必须处理的细节：

- **负平均值**：当 $\bar{a} < 0$ 时 $x_0 = \lfloor \bar{a} \rfloor + 1 \le 0$，但答案必须为正整数，因此取 $\max(1, x_0)$ 作为起点。
- **不要用浮点数**：$S/n$ 可能是无限小数（如 $2/3$），浮点误差会让 $\lfloor \cdot \rfloor$ 在边界上判错。全部用整数除法（向下取整）即可精确。

### 3.3 算法流程

![算法流程：一次扫描建集合，从下界逐个试](images/bw165_q1_algorithm_flow.svg)

```text
1. S = nums 之和，n = nums 长度，st = nums 的集合
2. x0 = floor(S / n) + 1            // 整数向下取整，负数也要向下取
3. x  = max(x0, 1)
4. while x ∈ st:  x = x + 1
5. 返回 x
```

### 3.4 示例演算

![三个示例的演算走查](images/bw165_q1_example_walkthrough.svg)

| 示例 | $S$ | $n$ | $\bar{a}$ | $x_0=\lfloor\bar a\rfloor+1$ | 起点 | 试值过程 | 答案 |
|------|-----|-----|-----------|------------------------------|------|----------|------|
| `[3,5]` | 8 | 2 | 4 | 5 | 5 | 5 ∈ st → 6 ∉ st | 6 |
| `[-1,1,2]` | 2 | 3 | 0.667 | 1 | 1 | 1 ∈ st → 2 ∈ st → 3 ∉ st | 3 |
| `[4,-1]` | 3 | 2 | 1.5 | 2 | 2 | 2 ∉ st | 2 |

三行分别覆盖了「起点被占用」「起点连续被占用」「起点直接可用」三种情形，也覆盖了平均值大于 1、介于 0 与 1 之间、为小数三类。

## 4. 算法细节

1. **下取整必须真的向下**：C++ 的 `/` 对负数是向零取整，$S=-10,n=3$ 时 `S/n = -3`，而 $\lfloor -10/3 \rfloor = -4$。代码中用 `(S >= 0) ? S / n : -((-S + n - 1) / n)` 统一成下取整；Python 的 `//` 本身就是下取整，可以直接写 `S // n`。
2. **起点钳到 1**：$\bar a \le 0$ 时 $x_0 \le 0$（例如 $S=-200,n=100$ 时 $x_0=-1$），此时最小可行正整数就是 1。
3. **答案上界**：$\bar a \le 100$，故 $x_0 \le 101$；`nums` 中最多只有 100 个不同的值，最坏情况下 101 起的 100 个整数全被占用，所以答案不超过 201。循环次数是常数级。
4. **集合 vs 布尔数组**：值域只有 $[-100,100]$，理论上可以开一个 201 长的布尔数组，但用哈希集合（Python 的 `set`、C++ 的 `unordered_set`）写起来更短，且能直接迁移到值域更大的变体。
5. **判定用乘法**：比较 $x \cdot n > S$ 与比较「$x$ 是整数且 $x > S/n$」完全等价，且不引入浮点。

## 5. 正确性证明

**引理 1（下界正确）**：对任意整数 $x$，$x > \bar a = S/n$ 当且仅当 $x \ge x_0 = \lfloor S/n \rfloor + 1$。

**证明**：设 $q = \lfloor S/n \rfloor$，则 $q \le S/n < q+1$。若 $x \ge q+1$，则 $x > S/n$；若 $x \le q$，则 $x \le q \le S/n$，不满足严格大于。故满足 $x > \bar a$ 的整数集合恰为 $\{q+1, q+2, \dots\}$，其最小元为 $q+1$。∎

**引理 2（起点合法）**：令 $start = \max(1, x_0)$，则 $start$ 是「正整数且严格大于 $\bar a$」的整数集合中的最小元。

**证明**：由引理 1，严格大于 $\bar a$ 的整数集合是 $\{x_0, x_0+1, \dots\}$；再与正整数集合 $\{1,2,\dots\}$ 取交，得到 $\{\max(1,x_0), \max(1,x_0)+1, \dots\}$，其最小元即 $\max(1,x_0)$。∎

**引理 3（跳步安全）**：设当前试到 $x$ 且 $x \in st$（即 $x$ 在 `nums` 中出现过），则任何 $y \le x$ 都不可能是答案。

**证明**：$y < start$ 时由引理 2 不满足「大于平均值且为正整数」；$start \le y \le x$ 时这些 $y$ 都在循环中被逐一检查过，且都被判定为 $y \in st$（否则答案早已返回）。故 $y \le x$ 全不合法。∎

**定理**：算法返回的 $x$ 是「严格大于平均值、未在 `nums` 中出现的最小正整数」。

**证明**：循环结束时 $x \notin st$，且 $x \ge start$，由引理 2 知 $x$ 是可行解。设 $y$ 是任一可行解，若 $y < x$，则 $y \ge start$（引理 2）且 $y$ 落在 $[start, x-1]$ 内，而该区间中每个值都在循环中被验证为属于 $st$（引理 3），与 $y$ 不在 `nums` 中矛盾。故不存在比 $x$ 更小的可行解，$x$ 最小。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建集合与求和各一遍扫描 $O(n)$；再从起点向上试，最多试到 201，循环次数被常数 $O(201)$ 界住，故总时间为 $O(n)$。
- **空间**：$O(n)$。哈希集合至多存 $\min(n, 201)$ 个不同的值。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int smallestAbsent(vector<int>& nums) {
        int n = (int)nums.size();
        long long sum = 0;
        unordered_set<int> st;
        for (int v : nums) {
            sum += v;
            st.insert(v);
        }
        // 向下取整除法（C++ 的 / 对负数是向零取整）
        long long q = (sum >= 0) ? sum / n : -((-sum + n - 1) / n);
        long long x = max(1LL, q + 1);
        while (st.count((int)x)) {
            x++;
        }
        return (int)x;
    }
};
```

### Python

```python
class Solution:
    def smallestAbsent(self, nums: list[int]) -> int:
        n = len(nums)
        total = sum(nums)
        st = set(nums)
        x = max(1, total // n + 1)   # Python 的 // 天然向下取整
        while x in st:
            x += 1
        return x
```

## 8. 边界情况与易错点

1. **负平均值**：`nums = [-100]` 时 $\bar a = -100$，$\lfloor \bar a \rfloor + 1 = -99$，必须钳到 1，返回 1；若漏掉钳位会返回 $-99$ 这种非正整数。
2. **负数的下取整**：`nums = [-1,-1,-1]` 时 $S=-3,n=3$，$\lfloor -1 \rfloor + 1 = 0$，钳到 1。C++ 若直接用 `S/n`（向零取整）会得到 $-1$，再 $+1=0$，虽然本例恰好还能被 `max(1,·)` 救回，但像 $S=-10,n=3$ 这种会得到 $-2$ 而非 $-3$，在「起点必须严格大于平均值」的判定上就会出错（$-2 > -3.34$ 其实仍成立，但边界情况下会漏掉正确下界）。统一写成向下取整最安全。
3. **浮点误差**：$S/n$ 不要用 `double`。例如 $S=2,n=3$ 时 $0.666\ldots$ 若被舍入成 $0.6666666666666667$，`floor` 仍是 0，问题不大；但 $S/n$ 恰为整数时（如 $8/2=4$）若误用 `ceil` 或四舍五入会得到 4，而正确答案的起点必须是 5——**严格大于**，不是大于等于。
4. **起点本身就在数组中**：示例 1 的 5 就是这种情况，`while` 循环必须真的执行，不能只返回 $x_0$。
5. **重复元素**：集合天然去重，`[3,3,3,5]` 与 `[3,5]` 结果相同（平均值变 3.5，起点 4，4 未出现 → 4）。
6. **只差一位的陷阱**：$x > \bar a$ 与 $x \ge \bar a$ 的差别只在 $\bar a$ 为整数时体现，这正是示例 1 的设计意图。
