# LeetCode 使库存平衡的最少丢弃次数 题解

## 1. 题目概述

- **标题 / 题号**：使库存平衡的最少丢弃次数（#3679，medium）
- **链接**：https://leetcode.cn/problems/minimum-discards-to-balance-inventory/
- **来源**：LeetCode 第 165 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数、滑动窗口、模拟

**题意**：给定整数 $w$、$m$ 与数组 $arrivals$，$arrivals[i]$ 是第 $i+1$ 天到达的**物品类型**。每个到达物品可以**保留**或**丢弃**，且只能在到达当天决定。规则是：

- 对每一天 $i$，考虑最近 $w$ 天的窗口 $[\max(1, i-w+1),\, i]$；
- 在这个窗口里，**被保留**的每种类型最多出现 $m$ 次；
- 如果保留第 $i$ 天的物品会使其类型在该窗口内超过 $m$ 次，则它**必须**被丢弃。

求把所有 $w$ 天窗口都满足约束所需的**最少丢弃数**（天数从 1 开始编号，但实现上用 0 开始更方便）。

**约束**：

- $1 \le arrivals.length \le 10^5$
- $1 \le arrivals[i] \le 10^5$
- $1 \le w \le arrivals.length$
- $1 \le m \le w$

## 2. 示例

**示例 1**

```text
输入：arrivals = [1,2,1,3,1], w = 4, m = 2
输出：0
解释：第 5 天窗口 [2,1,3,1] 中类型 1 恰好 2 次，未超限；全程无需丢弃。
```

**示例 2**

```text
输入：arrivals = [1,2,3,3,3,4], w = 3, m = 2
输出：1
解释：第 3、4 天各保留一个类型 3；第 5 天时窗口 [3,3,3] 内已有 2 个类型 3，
     再保留就变成 3 次，必须丢弃第 5 天的这个类型 3。第 6 天类型 4 正常保留。
```

**示例 3（补充例子，覆盖「窗口很短、类型很密」）**

```text
输入：arrivals = [1,1,1,1], w = 2, m = 1
输出：2
解释：任意连续两天最多保留 1 个类型 1。保留第 1、3 天，丢弃第 2、4 天，共丢 2 个；
     少于 2 个丢弃无法满足 w = 2 的窗口约束（4 天里最多留 2 个）。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每一天「保留 / 丢弃」的选择，共有 $2^{n}$ 种方案，对每种方案检查所有 $w$ 窗口是否超限，取合法方案中丢弃数最小者。$n \le 10^5$ 时完全不可行。即便改成按类型做 DP（每种类型独立），状态也要记录「最近 $w$ 天的保留情况」，是指数级的。

### 3.2 核心观察：同类型约束互相独立 + 早保留优于晚保留

![滑动窗口内只统计被保留的物品，同类型独立计数](images/bw165_q2_sliding_window.svg)

两个关键事实：

1. **类型之间互不影响**。约束的形式是「窗口内类型 $t$ 的保留数 $\le m$」，没有任何一条约束同时涉及两种类型。因此「保留数最小化」可以按类型拆开：对每种类型单独求最多能保留多少个，总和就是最多保留数，答案 = $n - $ 总和。
2. **同类型中，越早到达的物品越「划算」**。对同一类型的两个物品，早到达的那个只能被更少的窗口覆盖（它比晚到的更早滑出任何窗口的右端），所以「先保早的」永远不会比「先保晚的」差。这提示贪心：**按时间顺序处理，能保留就保留**。

于是判定只需一件事：处理到第 $i$ 天时，若把 $arrivals[i]$ 保留，它所在的那个窗口（右端为 $i$、长度 $w$）里该类型是否已经达到 $m$ 个。这可以用一个**长度固定的滑动窗口**维护：计数器 `cnt[t]` 记录当前窗口内类型 $t$ **已保留**的数量，每天进入新物品时把第 $i-w$ 天（若它被保留过）移出窗口。

![贪心决策：只维护最近 w 天的保留计数](images/bw165_q2_greedy_decision.svg)

### 3.3 算法流程

```text
1. cnt[t] = 0（t 为类型），keep[i] = false，ans = 0
2. for i = 0 .. n-1:
     若 i >= w 且 keep[i-w]:  cnt[arrivals[i-w]] -= 1      // 窗口左端滑出
     若 cnt[arrivals[i]] < m:  keep[i] = true;  cnt[arrivals[i]] += 1
     否则:                     keep[i] = false; ans += 1
3. 返回 ans
```

注意第 2 步的「滑出」必须发生在「判定当天」**之前**：窗口是 $[i-w+1, i]$，右端为 $i$ 时，下标 $i-w$ 已经不在窗口内。

### 3.4 示例演算

![示例 2 的逐步演算：第 5 天的类型 3 被丢弃](images/bw165_q2_example_walkthrough.svg)

以示例 2（`arrivals = [1,2,3,3,3,4]`，$w=3,m=2$）为例：

| 天 $i$（0 起） | 类型 | 滑出窗口的保留物品 | 窗口 $[i-2,i]$ 内该类型保留数 | 决策 |
|------|------|--------------------|------------------------------|------|
| 0 | 1 | — | 0 < 2 | 保留 |
| 1 | 2 | — | 0 < 2 | 保留 |
| 2 | 3 | — | 0 < 2 | 保留 |
| 3 | 3 | 无（$i-3<0$） | 1 < 2 | 保留 |
| 4 | 3 | 无（第 1 天的 2 不是类型 3） | 2 = 2 | **丢弃** |
| 5 | 4 | 第 2 天的 3 滑出 → 类型 3 变 1 | 0 < 2 | 保留 |

答案为 1，与题面一致。

对示例 1（`[1,2,1,3,1]`，$w=4,m=2$）：前 4 天类型 1 只保留 2 个；第 5 天（下标 4）滑出下标 0 的类型 1，计数降为 1，仍可保留，累计 2 个，答案 0。

## 4. 算法细节

1. **`cnt` 只统计保留的物品**：被丢弃的物品从不进入窗口，所以「滑出」时也只需判断 `keep[i-w]`。
2. **数组 vs 哈希表**：类型值域 $[1,10^5]$，直接开 `vector<int> cnt(maxVal+1)` 比 `unordered_map` 快得多；Python 用 `list` 或 `defaultdict` 均可。
3. **滑出时机**：先滑出、再判定。若反过来，第 $i$ 天判定时窗口会多含一个下标 $i-w$ 的物品，长度变成 $w+1$，恰好是示例 2 出错的地方。
4. **`keep` 数组必须有**：只知道 `cnt` 无法区分「第 $i-w$ 天被丢弃」与「被保留但已滑出」，所以要么存布尔数组，要么为每种类型维护一个保留日期队列，按 `pos <= i-w` 出队。
5. **答案即丢弃数**：不必求最大保留数，直接在每个「必须丢弃」的分支累加即可。
6. **一次遍历**：每个下标最多被「进入」一次、「滑出」一次，均摊 $O(1)$。

## 5. 正确性证明

**引理 1（类型独立）**：设 $K_t$ 为类型 $t$ 在所有可行方案中可保留数量的最大值，则全局最多可保留 $\sum_t K_t$ 个物品，且该上界可达。

**证明**：任一可行方案对每种类型 $t$ 的保留集合都单独满足「任意长度 $w$ 的窗口内 $\le m$ 个」，故该方案保留的类型 $t$ 数量 $\le K_t$，求和得总数 $\le \sum_t K_t$。反向：对每个 $t$ 取达到 $K_t$ 的集合，合并后每种类型的窗口计数依然各自不超限（约束不跨类型），故合并方案可行，总数达到上界。∎

**引理 2（可行性的等价刻画）**：设 $K$ 是某类型保留日的集合。则「任意长度 $w$ 的窗口内该类型的保留数 $\le m$」当且仅当

$$\forall k \in K: \quad \bigl| K \cap [k-w+1,\, k] \bigr| \le m .$$

**证明**：（$\Rightarrow$）窗口 $[k-w+1,k]$ 本身就是一个长度恰为 $w$ 的窗口（起点取 $\max(1,k-w+1)$，左端越界时窗口更短，计数只会更少），故计数 $\le m$。

（$\Leftarrow$）反设存在长度 $w$ 的窗口 $[a,b]$（$b = a + w - 1$）包含 $r > m$ 个保留日，取其中最大者 $k \le b$。由 $a \ge b - w + 1 \ge k - w + 1$ 知这 $r$ 个保留日全都落在 $[k-w+1,k]$ 内，于是 $|K \cap [k-w+1,k]| \ge r > m$，与条件矛盾。∎

引理 2 也说明了算法的正确性来源：算法在保留第 $i$ 天时检查的正是 $|K \cap [i-w+1,i]| < m$，这与可行性判据完全一致。

**引理 3（贪心的第 $r$ 个保留日不晚于任何可行方案）**：固定类型 $t$，其到达日依次为 $a_1 < a_2 < \cdots < a_p$。设贪心保留日为 $g_1 < g_2 < \cdots$，任一可行方案的保留日为 $f_1 < f_2 < \cdots$。则对每个 $r \ge 1$（只要 $g_r$ 存在）都有 $g_r \le f_r$。

**证明**：对 $r$ 归纳。$r=1$ 时贪心必保留最早到达的 $a_1$，而 $f_1 \ge a_1$，故 $g_1 = a_1 \le f_1$。

归纳步：设 $g_{r-1} \le f_{r-1}$。贪心处理到到达日 $f_r$（它是某个 $a_j$）时，已保留的恰为 $g_1, \dots, g_s$，其中 $s \ge r-1$（因为 $g_{r-1} \le f_{r-1} < f_r$，这些保留日都在 $f_r$ 之前）。若 $s \ge r$，则 $g_r \le g_s < f_r$ 或 $g_r = f_r$，结论已成立。故只需考虑 $s = r-1$ 的情形。

若此时贪心**保留** $f_r$，则 $g_r = f_r$，结论成立。若贪心**拒绝** $f_r$，由算法逻辑，窗口 $[f_r-w+1, f_r]$ 内贪心已保留 $m$ 个物品，故 $s = r-1 \ge m$；其中最近的第 $m$ 个是 $g_{s-m+1} = g_{r-m}$，满足

$$g_{r-m} \ge f_r - w + 1 .$$

另一方面，由引理 2 与 $f$ 的可行性，$f_r$ 的窗口内至多有 $m$ 个 $f$ 的保留日；而 $f_{r-m}, f_{r-m+1}, \dots, f_r$ 共 $m+1$ 个保留日都 $\le f_r$，若它们全落在 $[f_r-w+1, f_r]$ 内就超过 $m$，故必有 $f_{r-m} < f_r - w + 1$。再由归纳假设（$r-m \le r-1$）得 $g_{r-m} \le f_{r-m} < f_r - w + 1 \le g_{r-m}$，矛盾。因此 $s=r-1$ 时贪心不会拒绝，必有 $g_r = f_r$。∎

**定理**：算法返回的丢弃数最小。

**证明**：由引理 1，只需对每种类型分别求最大保留数。对类型 $t$，若某可行方案保留了 $R$ 个，则由引理 3 有 $g_R$ 存在且 $g_R \le f_R$，即贪心至少也保留了 $R$ 个。故贪心在该类型上保留数最大、丢弃数最小。算法对每种类型并行地执行了同样的贪心（每种类型有独立的 `cnt` 与滑出时机），因此总丢弃数最小。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标进入窗口一次、滑出一次，判定为 $O(1)$；类型值域与 $n$ 同阶，初始化 `cnt` 也是 $O(n)$。
- **空间**：$O(n + V)$。`keep` 布尔数组 $O(n)$，`cnt` 计数数组 $O(V)$，$V = \max arrivals \le 10^5$；若用哈希表则退化为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minArrivalsToDiscard(vector<int>& arrivals, int w, int m) {
        int n = (int)arrivals.size();
        int maxV = 0;
        for (int v : arrivals) maxV = max(maxV, v);
        vector<int> cnt(maxV + 1, 0);
        vector<char> keep(n, 0);
        int ans = 0;
        for (int i = 0; i < n; i++) {
            if (i >= w && keep[i - w]) {
                cnt[arrivals[i - w]]--;
            }
            int t = arrivals[i];
            if (cnt[t] < m) {
                keep[i] = 1;
                cnt[t]++;
            } else {
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minArrivalsToDiscard(self, arrivals: list[int], w: int, m: int) -> int:
        n = len(arrivals)
        cnt = [0] * (max(arrivals) + 1)
        keep = [False] * n
        ans = 0
        for i in range(n):
            if i >= w and keep[i - w]:
                cnt[arrivals[i - w]] -= 1
            t = arrivals[i]
            if cnt[t] < m:
                keep[i] = True
                cnt[t] += 1
            else:
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **滑出与判定的顺序**：必须先滑出下标 $i-w$ 再判定，否则窗口长度会变成 $w+1$。示例 2 的第 5 天（下标 4）正是靠「先滑出」才没有误判。
2. **被丢弃的物品不占窗口名额**：`keep[i-w] == false` 时不能减 `cnt`，否则会把没保留过的物品也扣掉，导致计数变成负数、放宽约束。
3. **$w = 1$**：窗口只含当天，$m$ 只能为 1；除每天第一个外，同类型全部丢弃。
4. **$m \ge w$**：理论上约束恒满足（窗口最长 $w$ 天，每天最多 1 个），答案必为 0。题面给 $m \le w$，属边界等价情形。
5. **全部同类型**：`[3,3,3,3,3]`、$w=3,m=2$ 时答案是 1（保留第 1、2 天，第 3 天丢弃；第 4 天滑出第 1 天后计数降为 1，可再留；第 5 天同理）。可以用「窗口内每类最多 $m$ 个」的节奏手算校验：连续 5 天、$w=3$ 时窗口 $[1,3]$ 与 $[2,4]$、$[3,5]$ 各限 2 个，至少要丢 1 个。
6. **类型值域开数组**：`max(arrivals)` 为空数组时不存在（$n \ge 1$），但注意 Python 里 `[0]*(max+1)` 在 $10^5$ 量级上没问题；若值域是 $10^9$ 就必须换哈希表。
7. **答案范围**：最多丢弃 $n$ 个，`int` 足够。
