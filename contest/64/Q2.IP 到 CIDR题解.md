# LeetCode IP 到 CIDR 题解

## 1. 题目概述

- **标题 / 题号**：IP 到 CIDR（#751，medium）
- **链接**：https://leetcode.cn/problems/ip-to-cidr/
- **来源**：LeetCode 第 64 场周赛 Q2
- **难度**：中等
- **标签**：位运算、字符串、贪心

**题意**：给定起始 IPv4 地址 `ip` 和需要覆盖的地址数 `n`，把从 `ip` 开始的连续 $n$ 个地址恰好剖分成若干 **CIDR 块** `a.b.c.d/p`，要求块数最少，按地址升序返回。块 `x/p` 的语义是：固定 `x` 的二进制前 $p$ 位、后 $32-p$ 位任意，所以它恰好覆盖一段**长度为 $2^{32-p}$、起点按 $2^{32-p}$ 对齐**的连续地址区间。

**约束**：

- `ip` 是合法的 IPv4 地址；
- 对每个 $0 \le x < n$，`ip + x` 仍是合法 IPv4 地址（不会越过 `255.255.255.255`）；
- $1 \le n \le 1000$。

注意两件事：$n$ 很小，但**块大小可以到 $2^{32}$**（前缀 `/0`），所以起点 $c=0$ 的对齐上限必须按 33 位处理——这是本题最容易踩的坑，见 §8。

## 2. 示例

**示例 1**

```text
输入：ip = "255.0.0.7", n = 10
输出：["255.0.0.7/32", "255.0.0.8/29", "255.0.0.16/32"]
解释：255.0.0.7 是奇数，只能单独成块（/32）；
      255.0.0.8 ~ 255.0.0.15 的低 3 位全 0，恰好是一个 /29 整块（8 个地址）；
      最后一个地址 255.0.0.16 用 /32。
      另一种写法 ["255.0.0.7/32","255.0.0.8/30","255.0.0.12/30","255.0.0.16/32"]
      要用 4 块，不是最短的。
```

**示例 2**

```text
输入：ip = "117.145.102.62", n = 8
输出：["117.145.102.62/31", "117.145.102.64/30", "117.145.102.68/31"]
解释：62 = 111110，lowbit 为 2 ⇒ /31，覆盖 62, 63；
      64 可对齐到 4 ⇒ /30，覆盖 64~67；
      剩 68, 69 两个地址 ⇒ /31。
      共 3 块，恰好覆盖 8 个地址。
```

## 3. 解题思路

### 3.1 暴力思路

朴素做法有两条，都不合适：

- **枚举所有分块方式**：把 $n$ 个地址切成若干段、每段都必须是合法块。切法有 $2^{n-1}$ 种，$n = 1000$ 时是指数级，完全不可行。
- **逐地址合并**：先给每个地址一个 `/32`，再从左到右尝试把相邻块合并。但"能否合并"取决于**对齐**：`x/31` 要求 $x$ 为偶数、`x/30` 要求 $x \bmod 4 = 0$……朴素的从左往右合并只能得到示 1 里那种 4 块的非最优解，无法保证最少。

所以不能"先碎后合"，必须**在每步直接算出能取的最大块**。

### 3.2 核心观察：块大小 = 「对齐上限」与「剩余数量」的较小者

![CIDR 块 = 起点对齐的 2 的幂区间](images/wc64_q2_cidr_alignment.svg)

把地址看成 32 位无符号整数 $c$。块 `x/p` 覆盖

$$[X,\; X + 2^{32-p}),\qquad X = \text{addr}(x)$$

且要求 $X$ 是 $2^{32-p}$ 的整数倍，否则前缀就不止 $p$ 位相同了（起点落在块内部）。

设当前待覆盖起点为 $c$、还剩 $m$ 个地址。若首块大小 $s = 2^k$，则

1. **对齐约束**：$s \mid c$。满足这个条件的最大 2 的幂正是 $\text{lowbit}(c) = c \,\&\, (-c)$，故 $s \le \text{lowbit}(c)$。约定 $\text{lowbit}(0) = 2^{32}$（`0.0.0.0/0` 合法）。
2. **不越界约束**：$s \le m$，否则会覆盖到 `ip + n` 之外的地址。

两个约束都只给上限，于是每步能取的最大块是

$$g = \min\Bigl(\text{lowbit}(c),\; 2^{\lfloor \log_2 m \rfloor}\Bigr),\qquad p = 32 - \log_2 g$$

> 💡 一句话：**能对齐多远就对齐多远，但别超过剩余数量**。

### 3.3 算法流程

![贪心流程：每步吃掉最大的合法块](images/wc64_q2_greedy_flow.svg)

维护两个变量：$c$（当前起点，整数）和 $m$（剩余地址数）。

```text
while m > 0:
    low = c & (−c)                  # 对齐上限
    if low == 0: low = 2^32         # 0.0.0.0 可对齐到 /0
    s = low
    while s > m: s >>= 1            # 不超过剩余数量
    p = 32 − log2(s)
    输出 addrToStr(c) + "/" + p
    c += s
    m −= s
```

**循环不变式**：已输出的块恰好覆盖 $[\text{ip}, c)$，块与块首尾相接、互不重叠，且每个块都对齐。每轮取的 $s$ 满足 $s \mid c$（对齐）与 $s \le m$（不越界），三条性质随之保持。

### 3.4 示例演算

![示例演算：255.0.0.7 与 n = 10](images/wc64_q2_trace_table.svg)

对 `ip = "255.0.0.7"`、$n = 10$：

| 步 | $c$ | lowbit | $2^{\lfloor\log_2 m\rfloor}$ | $s$ | $p$ | 输出 |
|----|-----|--------|------------------------------|-----|-----|------|
| 1 | 255.0.0.7 | 1 | 8 | 1 | 32 | 255.0.0.7/32 |
| 2 | 255.0.0.8 | 8 | 8 | 8 | 29 | 255.0.0.8/29 |
| 3 | 255.0.0.16 | 16 | 1 | 1 | 32 | 255.0.0.16/32 |

三步吃满 10 个地址。注意第 2 步：如果只合并成两个 `/30`，块数会变成 4；直接取 $\text{lowbit}(8) = 8$ 才能一步到位，这正是"先碎后合"拿不到最优的原因。

## 4. 算法细节

1. **IP ↔ 整数**：按 `.` 拆四段，$((a \ll 24) \mid (b \ll 16) \mid (c \ll 8) \mid d)$；还原时（Python 版）用 `(x >> 24) & 255` 等掩码逐字节拼回，避免数值越界。
2. **对齐上限**：$c \,\&\, (-c)$，即 lowest set bit。**$c = 0$ 时必须特判**为 $2^{32}$，否则得到 0 会产生负前缀或死循环。
3. **数量上限**：不是 $n$ 本身，而是"$\le m$ 的最大 2 的幂"。用 `while (s > m) s >>= 1` 最省心，等价于 $2^{\lfloor \log_2 m\rfloor}$。
4. **前缀长度**：$p = 32 - \log_2 s$。用 `__builtin_ctzll(s)`（C++）或 `s.bit_length() - 1`（Python）求 $\log_2$，**不要用浮点 `log2`**。
5. **输出顺序**：$c$ 单调递增，块天然按地址升序输出，不需要额外排序。
6. **数据类型**：`low` 的中间值可达 $2^{32}$，C++ 里 `cur` 与 `s` 一律用 `long long`，`1 << 32` 必须写成 `1LL << 32`；Python 大整数无需关心。

## 5. 正确性证明

**引理 1（块的形状）**：字符串 `x/p` 覆盖的地址集合恰为 $[X, X + 2^{32-p})$，其中 $X = \text{addr}(x)$；该集合对应一个合法块当且仅当 $X \bmod 2^{32-p} = 0$。

**证明**：`p` 表示前 $p$ 位相同、其余 $32-p$ 位自由，故恰好覆盖 $2^{32-p}$ 个地址，起点是低 $32-p$ 位全 0 的那个。若 $X$ 不是 $2^{32-p}$ 的倍数，则 $X$ 落在某个"低 $32-p$ 位全 0"的地址之后，覆盖区间不从一个块的起点开始，前缀也无法只由 $p$ 位描述，与 `x/p` 的定义矛盾。∎

**引理 2（首块大小上界）**：设当前起点 $c$、剩余 $m$，任一合法覆盖的首块大小 $s = 2^k$ 都满足 $s \le \text{lowbit}(c)$ 且 $s \le m$。

**证明**：由引理 1，$s \mid c$；$c$ 的约数中 2 的幂最大者就是 $\text{lowbit}(c)$，故 $s \le \text{lowbit}(c)$。又首块从 $c$ 起、必须落在 $[\text{ip}, \text{ip}+n)$ 内，故 $s \le m$。∎

**引理 3（贪心块可达且最大）**：$g = \min\bigl(\text{lowbit}(c), 2^{\lfloor\log_2 m\rfloor}\bigr)$ 是合法块大小，且不小于任何合法首块。

**证明**：$g$ 是 2 的幂；$g \le \text{lowbit}(c)$ 故 $g \mid c$，又 $g \le 2^{\lfloor\log_2 m\rfloor} \le m$，由引理 1 知 $[c, c+g)$ 是合法块。任取合法首块 $s$，由引理 2 有 $s \le \min(\text{lowbit}(c), m)$；$s$ 是 2 的幂且 $s \le m$，故 $s \le 2^{\lfloor\log_2 m\rfloor}$，从而 $s \le g$。∎

**引理 4（贪心首块不劣）**：若存在用 $t$ 块的合法覆盖，则存在用至多 $t$ 块的合法覆盖，其首块为 $[c, c+g)$。

**证明**：取任一 $t$ 块覆盖，设其首块为 $[c, c+s)$，由引理 3 有 $s \le g$。把首块换成 $[c, c+g)$：它对齐（引理 3）、且 $g \le m$ 故不越界，覆盖仍合法。原覆盖中凡完全落在 $[c+s, c+g)$ 内的块都被新首块包含，删去它们只会让块数不增。∎

**定理**：算法输出的块恰好覆盖 $[\text{ip}, \text{ip}+n)$，且块数最少。

**证明**：覆盖性由 §3.3 的循环不变式归纳得到：初始 $c = \text{ip}$、$m = n$，已覆盖区间为空；每轮吃掉 $[c, c+g)$ 并令 $c \leftarrow c+g$，循环结束时 $c = \text{ip}+n$，各块首尾相接。最优性对 $m$ 归纳：$m = 0$ 时 0 块最优。设贪心后继部分的块数为 $f(c+g, m-g)$，由归纳假设它等于最优值；由引理 4，存在最优解以 $g$ 为首块，故该最优解块数 $t \ge 1 + f(c+g, m-g)$，即贪心块数不超过最优值；而贪心本身是合法覆盖，块数不会低于最优值，两者相等。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。每轮只做 lowbit、移位与常数位宽的字符串拼接，$O(1)$。轮数有界：若某轮 $s$ 受 $m$ 限制，则 $s > m/2$，下一轮 $m$ 至少减半；若受对齐限制，则 $c$ 加上 $\text{lowbit}(c)$ 后其 lowbit 至少翻倍。两类交替出现，总轮数 $O(\log n)$；本题 $n \le 1000$ 时块数不超过十余个。
- **空间**：$O(\log n)$ 用于存放结果；除结果外只有 $c, m, s, p$ 等常数个变量，即 $O(1)$ 额外空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> ipToCIDR(string ip, int n) {
        long long cur = 0;
        int part = 0;
        for (char ch : ip) {
            if (ch == '.') { cur = (cur << 8) | part; part = 0; }
            else part = part * 10 + (ch - '0');
        }
        cur = (cur << 8) | part;              // 拼成 32 位整数

        auto toStr = [](long long x) {
            return to_string((x >> 24) & 255) + "." + to_string((x >> 16) & 255) + "." +
                   to_string((x >> 8) & 255) + "." + to_string(x & 255);
        };

        vector<string> res;
        while (n > 0) {
            long long low = cur & (-cur);     // 对齐上限：lowest set bit
            if (low == 0) low = 1LL << 32;    // 0.0.0.0 可对齐到 /0
            long long s = low;
            while (s > n) s >>= 1;            // 不超过剩余数量
            int prefix = 32 - __builtin_ctzll(s);
            res.push_back(toStr(cur) + "/" + to_string(prefix));
            cur += s;
            n -= (int)s;
        }
        return res;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def ipToCIDR(self, ip: str, n: int) -> List[str]:
        a, b, c, d = map(int, ip.split('.'))
        cur = (a << 24) | (b << 16) | (c << 8) | d

        def to_str(x: int) -> str:
            return "%d.%d.%d.%d" % ((x >> 24) & 255, (x >> 16) & 255,
                                    (x >> 8) & 255, x & 255)

        res = []
        while n > 0:
            low = cur & -cur              # 对齐上限：lowest set bit
            if low == 0:
                low = 1 << 32             # 0.0.0.0 可对齐到 /0
            s = low
            while s > n:                  # 不超过剩余数量
                s >>= 1
            res.append(to_str(cur) + "/" + str(32 - (s.bit_length() - 1)))
            cur += s
            n -= s
        return res
```

## 8. 边界情况与易错点

1. **`0.0.0.0` 的 lowbit 为 0**：`cur & -cur` 返回 0，若直接拿它当块大小就会死循环或产出非法前缀。必须特判成 $2^{32}$；本题 $n \le 1000$，实际会立刻缩到 512，输出 `0.0.0.0/23` 起步。
2. **`1 << 32` 溢出**：C++ 中 `int` 上的 `1 << 32` 是未定义行为，必须写 `1LL << 32`，且 `cur`/`s` 用 `long long`，因为 `low` 的中间值能取到 $2^{32}$。
3. **对齐上限大于剩余数量**：如 `cur = 255.0.0.8`（lowbit 为 8）但只剩 1 个地址，必须缩到 `/32`；输出 `/29` 会覆盖到区间之外。
4. **$n$ 恰好等于对齐长度**：如 `ip = "255.255.255.0", n = 256`，答案就是单个 `255.255.255.0/24`，一轮结束，不要多切一块 `/32`。
5. **每步都要重新算 lowbit**：如 `ip = "255.0.0.7", n = 12`，首块只能是 `/32`，推进到 `255.0.0.8` 时才吃得到 `/29`（8..15），再往后对齐长度又缩回 `/31`；若在循环外一次算好对齐，就会漏掉这个变化。
6. **前缀边界**：$s$ 最小为 1 ⇒ $p = 32$；本题 $s \le 1024$ ⇒ $p \ge 22$，不会出现负前缀。若把 $n$ 放大到 $2^{32}$ 量级，需保证 $p$ 的计算走 64 位整数。
7. **不要用浮点求 $\log_2$**：`log2` 的舍入误差会让 `32 - (int)log2(s)` 少 1（$s = 2^{k}$ 恰好落在整数边界时更危险），一律用 `ctz` / `bit_length`。
8. **输出必须升序且首尾相接**：块之间不能有空洞也不能重叠；本算法天然满足，但若自行改动（例如把大块提前输出）就会破坏"表示这段区间"的语义。

**延伸思考**：

- **覆盖任意区间 $[l, r]$ 而不是从 `ip` 起 $n$ 个**：两端各切一刀——先把 $l$ 按 $\text{lowbit}(l)$ 向上切成整块，再从 $r$ 尾部倒推，中间部分照旧取 $\min(\text{lowbit}(c), \text{剩余})$，复杂度仍是 $O(\log n)$。
- **限制前缀长度 $\le p_{\max}$（不允许超级网段）**：只需把对齐上限再与 $2^{32-p_{\max}}$ 取 min，贪心与全部证明一字不改，说明本题结论对"额外上界"是稳健的。
- **换到 IPv6**：地址变成 128 位，`lowbit`、对齐、$p = 128 - k$ 的逻辑完全不变；Python 直接用大整数，C++ 换 `__int128` 即可。
