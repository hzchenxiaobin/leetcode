# LeetCode 破解保险箱 题解

## 1. 题目概述

- **标题 / 题号**：破解保险箱（#753，hard）
- **链接**：https://leetcode.cn/problems/cracking-the-safe/
- **来源**：LeetCode 第 64 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索、图、字符串、欧拉回路、欧拉路径

**题意**：密码是一个 $n$ 位数字串，每一位取值 $0 \sim k-1$。保险箱只校验**最近输入的 $n$ 位**：每敲一位，就把末尾 $n$ 位与密码比对一次。求一个**最短**的输入序列，使无论密码是哪一个 $n$ 位数，都能在输入过程中被命中；返回任意一个这样的序列。

等价说法：求最短字符串 $S$，使得 $k^n$ 个长度为 $n$ 的数字串**全部**作为 $S$ 的连续窗口出现。

**约束**：

- $1 \le n \le 4$
- $1 \le k \le 10$
- $1 \le k^n \le 4096$

数据范围很小但状态空间并不小：$k^n$ 最大 4096，而答案长度为 $k^n + n - 1 \le 4099$，字符串层面的搜索完全不可行。

## 2. 示例

**示例 1**

```text
输入：n = 1, k = 2
输出："10"
解释：密码只有 1 位，把每个数字都敲一遍即可；"01" 同样能打开保险箱。
```

**示例 2**

```text
输入：n = 2, k = 2
输出："01100"
解释：长度为 2 的密码共 4 个，逐一起点验证：
      "00" 从第 4 位开始出现，"01" 从第 1 位开始，
      "10" 从第 3 位开始，"11" 从第 2 位开始。
      "10011"、"11001" 也同样合法（答案不唯一）。
```

**补充示例**（本文算法在 $n = 3, k = 2$ 时的输出）

```text
输入：n = 3, k = 2
输出："0001011100"（长度 10 = 8 + 3 - 1）
解释：8 个窗口依次为 000, 001, 010, 101, 011, 111, 110, 100，
      恰好把 8 个三位密码各覆盖一次。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：从小到大枚举长度 $L$，枚举所有 $k^L$ 个候选串，检查它是否覆盖全部 $k^n$ 个窗口。候选数量是指数级的——当 $n = 4, k = 8$ 时答案长达 4099 位，候选数 $8^{4099}$ 是天文数字，不可行。

另一个诱人的想法是贪心：每次追加「能覆盖最多新窗口」的数字。但局部最优会提前封死后续可用窗口，正确性没有保证。真正干净的结构是**图**：把「窗口」看成边。

### 3.2 核心观察：密码是 de Bruijn 图的边

![de Bruijn 图：n 位密码是一条有向边](images/wc64_q4_debruijn_graph.svg)

关键是换一个视角建模：

- **节点**：所有 $n-1$ 位数字串，共 $k^{n-1}$ 个；
- **边**：节点 $u$ 后接数字 $d$，得到 $n$ 位串 $u d$，看作一条从 $u$ 指向 $u[1:] + d$ 的有向边。

于是每个节点恰有 $k$ 条出边、全图恰有 $k^n$ 条边，与 $k^n$ 个密码一一对应（这个图叫 **de Bruijn 图**）。输入序列的「最近 $n-1$ 位」就是当前节点，再敲一位 $d$ 就是走一条边，所以

$$\text{输入序列覆盖全部密码} \iff \text{这条游走经过所有边} \iff \text{欧拉回路（Eulerian circuit）}.$$

由此得到两条基本事实：

1. **长度下界**：长度为 $L$ 的串只有 $L - n + 1$ 个窗口，要装下 $k^n$ 个互不相同的密码，必须有 $L \ge k^n + n - 1$。
2. **下界可达**：每个节点出度 = 入度 = $k$，且图强连通（从任意 $n-1$ 位串出发，逐位追加目标串的字符即可走到目标），由欧拉定理，欧拉回路必定存在。

所以最优答案恰好 $k^n + n - 1$ 位，问题转化为**在 de Bruijn 图上求一条欧拉回路**。

### 3.3 算法流程：Hierholzer

![Hierholzer：DFS 后序记录，逆序即欧拉回路](images/wc64_q4_hierholzer_flow.svg)

1. 起点取 $start = \underbrace{0\cdots0}_{n-1}$，它对应「还没输入任何数字」时的空节点。
2. 从 $start$ 出发 DFS，节点 $u$ 依次尝试出边 $u + d$（$d = 0, 1, \dots, k-1$）。
3. 若这条 $n$ 位串尚未走过：标记已访问，递归到新节点 $u[1:] + d$；**回溯时**把数字 $d$ 追加进序列 `path`。
4. DFS 结束后 `path` 是**逆序**的边序列，反转它，答案 $= start + \operatorname{rev}(path)$。

第 3 步的「回溯时记录」是 Hierholzer 的精髓：先一路钻到走不动，回溯时才把边记下来，于是**最后记下的边恰是最先走过的边**；整体反转就还原成一条从起点出发、按正向顺序走完全部边的回路。若把记录挪到递归之前，顺序就全错了（见 §8）。

### 3.4 示例演算

![示例演算：n = 2, k = 2 走一遍 DFS](images/wc64_q4_walkthrough.svg)

以 $n = 2, k = 2$ 为例：节点是单字符 `"0"`、`"1"`，边是 `00, 01, 10, 11`。DFS 依次走过 $00 \to 01 \to 10 \to 11$（走不动就回溯），回溯顺序记为 $10, 11, 01, 00$，反转为 $00, 01, 11, 10$，把各边末位数字拼在起点之后：

```text
start "0" + 反转数字 "0110" = "00110"
```

窗口是 `00, 01, 11, 10`，四个密码各出现一次，长度 $5 = k^n + n - 1$，达到下界。

顺带解释**答案不唯一**：官方示例给的 `"01100"` 正是 `"00110"` 的循环移位——欧拉回路换个起点、或出边尝试顺序不同，得到的串就不同但同样最短。本题是 Special Judge，按「长度最短 + 覆盖全部密码」判定。

## 4. 算法细节

1. **visited 记录的是边而不是节点**。边的 key 是 $n$ 位串。若只记 $n-1$ 位节点，会把不同的边当成同一状态而漏走，最终串变短但覆盖不全。
2. **整数编码（可选优化）**：把 $n-1$ 位节点编码成 $k$ 进制整数 $id$，则边为 $id \cdot k + d$，下一个节点为 $(id \cdot k + d) \bmod k^{\,n-1}$；用 `vector<char>` / `bytearray` 做 visited，单次判断 $O(1)$，省掉字符串哈希开销。
3. **后序 + 反转，两步都不能少**。先记录再反转才是欧拉回路；漏掉反转时绝大多数情况会得到非法串——$n = 3, k = 2$ 时会拼出 `"0000111010"`，8 个窗口只剩 7 种。
4. **用迭代替代递归**。递归深度最坏可达 $k^n = 4096$，Python 默认递归上限 1000 会直接 `RecursionError`。迭代时栈帧写成 `(节点, 下一个待尝试的数字, 入边数字)`，其中「入边数字」用于回溯时记录。
5. **出边枚举顺序任意**。$d$ 从 $0$ 到 $k-1$ 只为让结果确定；任何顺序都能得到合法答案，因为正确性只依赖「每条边恰好走一次」。
6. **$n = 1$ 要能自然跑通**：此时 $start$ 是空串，节点只有空串一个，边就是单个数字。根节点没有入边，回溯时不能追加任何东西——迭代实现里用「入边数字为空」区分根即可。
7. **$k = 1$ 时**只有 `"00…0"` 一条边，答案就是 $n$ 个 `0`，DFS 走一步就回溯，长度 $1 + n - 1 = n$ 依然正确。

## 5. 正确性证明

**引理 1（平衡且强连通）**：de Bruijn 图中每个节点的出度、入度都等于 $k$，且任意两节点互相可达。

**证明**：节点 $u$ 的出边是 $u + d$（$d = 0, \dots, k-1$），共 $k$ 条；指向节点 $v$ 的边必形如 $a + v$（$a$ 为任一数字），也恰有 $k$ 条。可达性：从 $u$ 出发，依次取目标节点 $v$ 的第 $1, 2, \dots, n-1$ 位作为追加数字，每步都走一条出边，节点不断左移，$n-1$ 步后正好等于 $v$。∎

**引理 2（长度下界）**：任何能命中全部密码的输入串 $S$ 满足 $\lvert S \rvert \ge k^n + n - 1$。

**证明**：长度 $L$ 的串只有 $L - n + 1$ 个长度为 $n$ 的窗口（起点为 $0, 1, \dots, L-n$）。要覆盖 $k^n$ 个互不相同的密码，需 $L - n + 1 \ge k^n$，即 $L \ge k^n + n - 1$。∎

**引理 3（边全部被访问）**：从 $start$ 出发运行上述 DFS，结束时每条边都被标记过。

**证明**：设存在未访问的边 $u \to w$。由引理 1，$u$ 从 $start$ 可达；DFS 从 $start$ 出发会访问到所有可达节点（否则取第一个未访问的可达节点，其路径前驱已被访问、且在返回前会尝试它这条出边，矛盾）。当 `dfs(u)` 返回时，它的每条出边要么早已被标记，要么刚刚被它标记，故 $u \to w$ 不可能未访问，矛盾。∎

**引理 4（回溯逆序是欧拉回路）**：把回溯顺序记录的数字序列反转，所得的边序列首条从 $start$ 出发、相邻两条首尾相接，且恰好覆盖所有边一次。

**证明**：该过程与 Hierholzer 算法的显式栈写法逐帧等价——递归进入一条边就是压栈，出边用尽后返回就是弹栈，弹栈时记录这条入边。对 Hierholzer 有标准结论：弹栈记录序列反转后是欧拉回路。其要点是一个不变式——**栈中节点始终构成一条连续的路径**（前一条边的终点 = 后一条边的起点）；弹栈相当于把已走完的那段闭合子回路接到路径末端，由于是闭合并以栈顶为连接点，拼接后路径仍连续；栈空时路径覆盖了所有走过的边，且由引理 3 覆盖了全部边。∎

**定理**：算法返回长度 $k^n + n - 1$ 的串，且覆盖全部 $k^n$ 个密码，故为最短合法输入。

**证明**：对根调用应用引理 4，得到覆盖全部 $k^n$ 条边的回路；回路上相邻两条边首尾共享 $n-1$ 位，把每条边的末位数字依次拼在 $start$（$n-1$ 位）之后，所成字符串的每个长度 $n$ 窗口恰好对应回路中的一条边，因此 $k^n$ 个窗口两两不同、全部出现。而长度为 $n$ 的数字串总共只有 $k^n$ 个，故每个密码都会被命中。长度 $\lvert start \rvert + \lvert path \rvert = (n-1) + k^n$ 达到引理 2 的下界，所以最短。∎

## 6. 复杂度分析

- **时间**：每个节点尝试 $k$ 条出边，节点共 $k^{n-1}$ 个，合计 $k^n$ 次尝试；每次对长度为 $n$ 的字符串做哈希与插入是 $O(n)$，故为 $O(n \cdot k^n)$。改用整数编码后单次 $O(1)$，总 $O(k^n)$。取 $n \le 4$、$k^n \le 4096$，约 $1.6 \times 10^4$ 次基本操作。
- **空间**：visited 存 $k^n$ 条边、每条 $n$ 位，共 $O(n \cdot k^n)$ 字符；答案与 `path` 各 $O(k^n)$；迭代栈最坏 $O(k^n)$。整数编码时 visited 仅需 $k^n$ 字节。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <unordered_set>
#include <functional>
#include <algorithm>
using namespace std;

class Solution {
public:
    string crackSafe(int n, int k) {
        string start(n - 1, '0');            // 起点：n-1 个 0
        unordered_set<string> seen;          // 已走过的边（n 位密码）
        string path;                         // 回溯时记录的数字（逆序）
        function<void(const string&)> dfs = [&](const string& node) {
            for (int d = 0; d < k; ++d) {
                string edge = node + char('0' + d);
                if (seen.insert(edge).second) {      // 这条边第一次走
                    dfs(edge.substr(1));             // 进入节点 node[1:] + d
                    path.push_back(char('0' + d));   // 回溯时才记录
                }
            }
        };
        dfs(start);
        reverse(path.begin(), path.end());    // 逆序还原正向欧拉回路
        return start + path;
    }
};
```

### Python

```python
class Solution:
    def crackSafe(self, n: int, k: int) -> str:
        start = "0" * (n - 1)
        seen = set()
        digits = []                                  # 回溯顺序记录的数字
        stack = [(start, 0, "")]                     # (节点, 下一个候选数字, 入边数字)
        while stack:
            node, d, incoming = stack[-1]
            while d < k and (node + str(d)) in seen:  # 跳过已走过的边
                d += 1
            if d == k:                                # 出边用尽 → 回溯
                stack.pop()
                if incoming != "":                    # 根节点没有入边，不记录
                    digits.append(incoming)
            else:
                edge = node + str(d)
                seen.add(edge)
                stack[-1] = (node, d + 1, incoming)   # 下次从 d+1 试起
                stack.append((edge[1:], 0, str(d)))
        digits.reverse()
        return start + "".join(digits)
```

## 8. 边界情况与易错点

1. **$n = 1$**：起点是空串，节点只有一个；答案是 $0 \sim k-1$ 的某个排列，长度 $k$。迭代写法靠「根没有入边」判断，不要给根追加 `""`。
2. **$k = 1$**：只有 `"00…0"` 一条边，答案是 $n$ 个 `0`（长度 $1 + n - 1 = n$），DFS 只走一步就得回溯。
3. **漏掉 `reverse`**：必须先记录、再反转。$n = 3, k = 2$ 时不反转会得到 `"0000111010"`，8 个窗口只出现 7 种，直接 WA。
4. **递归深度**：$k^n$ 最大 4096，Python 默认上限 1000，必须写成显式栈（或调 `sys.setrecursionlimit`，但判题环境更推荐前者）。
5. **visited 记错对象**：要记 $n$ 位的边，不能记 $n-1$ 位的节点，否则会跳过部分边、覆盖不全。
6. **答案与示例不同**：本题为 Special Judge，官方给 `"01100"`，本文代码给 `"00110"`，二者互为循环移位、同样合法，不要因为字符串不同就以为算法出错。
7. **起点长度**：起点必须是 $n-1$ 位（$n=1$ 时为空串）。写成 $n$ 位会让最终长度多 1，违反最短性。
8. **整数编码的模数**：下一节点为 $(id \cdot k + d) \bmod k^{\,n-1}$，$n=1$ 时 $k^{\,n-1} = 1$，取模恒为 0，恰好正确；误写成 $\bmod k^n$ 或 $k^{\,n-1}-1$ 都会出错。
