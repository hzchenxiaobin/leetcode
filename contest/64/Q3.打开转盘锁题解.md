# LeetCode 打开转盘锁 题解

## 1. 题目概述

- **标题 / 题号**：打开转盘锁（#752，medium）
- **链接**：https://leetcode.cn/problems/open-the-lock/
- **来源**：LeetCode 第 64 场周赛 Q3
- **难度**：中等
- **标签**：广度优先搜索，数组，哈希表，字符串，双向搜索

**题意**：锁有 4 个圆形拨轮，每位是 `'0'`~`'9'`；一次操作只能把**某一位**加 1 或减 1，且 `'9'` 与 `'0'` 相邻（循环）。初始状态为 `"0000"`。`deadends` 是"死亡数字"集合，一旦拨到其中任一状态，锁被永久锁死（不能再动），因此**这些状态不能踏进去**，包括起点。求从 `"0000"` 拨到 `target` 的**最少**旋转次数；无论如何都到不了则返回 `-1`。

**约束**：

- $1 \le \text{deadends.length} \le 500$
- `deadends[i].length == 4`，仅由数字组成
- `target.length == 4`，仅由数字组成
- `target` 不在 `deadends` 中

## 2. 示例

**示例 1**

```text
输入：deadends = ["0201","0101","0102","1212","2002"], target = "0202"
输出：6
解释：0000 -> 1000 -> 1100 -> 1200 -> 1201 -> 1202 -> 0202 共 6 步。
      看似更短的路 0000 -> 0001 -> 0002 -> 0102 -> 0202 走不通，
      因为拨到 0102 时锁已经被锁死。
```

**示例 2**

```text
输入：deadends = ["8888"], target = "0009"
输出：1
解释：把第 4 位反向转一次即可：0000 -> 0009。
```

**示例 3**

```text
输入：deadends = ["8887","8889","8878","8898","8788","8988","7888","9888"], target = "8888"
输出：-1
解释：8888 的 8 个邻居全部是死亡数字，任何一步都会被锁死，无法到达。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是**逐位贪心**：每一位独立地选 `+1` 或 `-1`，取较短的那个方向，单位置距离为 $\min(\lvert a-b \rvert,\ 10-\lvert a-b \rvert)$。对示例 1，`"0000"` → `"0202"` 的四位距离分别是 0、2、0、2，贪心给出的答案是

$$0+2+0+2 = 4 \ne 6$$

正确答案却是 **6**：逐位最短的路径必然经过 `"0102"`、`"0201"` 这些死亡数字，必须绕路——**各位之间通过 deadends 强耦合，贪心立即失效**。

另一个暴力方向是 DFS 枚举旋转序列：每层最多 8 个分支，深度 6 时有 $8^6 \approx 2.6\times10^5$ 条序列，看似还能接受，但 DFS 会重复访问同一状态、也无法保证第一次到达就是最短（要么存全局最优、要么按层搜），在 `target` 较远时状态数会涨到 $10^4$ 量级的指数形态。

真正的朴素正解是**从 `"0000"` 做单源 BFS**：把每个状态当图的节点，一次旋转当一条单位权边，答案就是 `"0000"` 到 `target` 的最短路长度，复杂度 $O(V+E) = O(8\times10^4)$，已经足够通过。本文在此之上再加一层优化：**双向 BFS**，把搜索层数对半砍。

### 3.2 核心观察：把锁看成无向图，答案是最短路

![状态图模型：10000 个状态，每个状态 8 条边](images/wc64_q3_state_graph_model.svg)

**关键观察 1（图模型）**：状态就是 4 位数字串，共 $10^4 = 10000$ 个。每个状态恰有 **8 条出边**：选一位，`+1` 或 `-1`（`0` 与 `9` 相邻）。因为 `+1` 与 `-1` 互为逆操作，这张图是**无向无权图**。

**关键观察 2（deadend = 删点）**：死亡数字不是"代价"，而是"禁止进入"，等价于把这些节点从图中**整个删掉**，与它相连的边也一起消失。题意保证 `target` 不在 deadends 中。

**关键观察 3（双向搜索）**：图无向 $\Rightarrow$ 也可以从 `target` 反向搜。若最短路长为 $d$，从两端各扩约 $d/2$ 层就能"接上"，访问量从 $O(b^d)$ 降到 $O(b^{d/2})$（$b=8$ 为分支因子）。本题状态只有 $10^4$ 个、单向 BFS 也能过，但双向版本把**层数**从 $d$ 砍到 $\lceil d/2 \rceil$，在 `target` 较远、需要绕开成片 deadends 时优势明显，也是这道题最值得沉淀的模板。

### 3.3 算法流程 / 状态转移

![双向 BFS：两端同时扩张，谁的前沿小就扩谁](images/wc64_q3_bidirectional_bfs.svg)

维护两个"已访问集 + 距离表" $\text{distA}$、$\text{distB}$，以及两个**前沿** $\text{frontA}$、$\text{frontB}$（当前这一层的节点集合）。每轮做三件事：

1. **扩较小的一侧**：比较 $\lvert \text{frontA} \rvert$ 与 $\lvert \text{frontB} \rvert$，对较小者做**整层扩张**（把它这一层的所有节点一次性展开），层计数 $d_A$ 或 $d_B$ 加 1。
2. **边生成时查对侧**：对每个新生成的节点 $v$，若 $v \in \text{distB}$，说明两侧搜索连上了，记 $\text{best} \leftarrow \min(\text{best},\ d_A + 1 + \text{distB}[v])$。
3. **终止判定**：当 $d_A + d_B \ge \text{best}$，或任意一侧前沿为空时停止，返回 `best`（仍为 $\infty$ 则 `-1`）。

> 💡 终止条件是本题最容易写错的地方：**不能在第一次相遇时立刻返回**。第一次接上的那条路未必最短，必须等"两侧层数之和已经不可能再变短"才收工；终止条件的正确性见 §5 引理 3。

### 3.4 示例演算

![示例 1 演算：两侧在 1201 相遇，4 + 2 = 6](images/wc64_q3_walkthrough.svg)

以示例 1（`deadends = {0201, 0101, 0102, 1212, 2002}`，`target = "0202"`）为例，两侧逐层展开：

| 层 | A 侧（从 `0000` 正向） | B 侧（从 `0202` 反向） |
|----|------------------------|-------------------------|
| 0 | `0000` | `0202` |
| 1 | `1000`、`9000`、`0100`、`0900`、`0010`、`0090`、`0001`、`0009`（8 个邻居都可走） | `1202`、`9202`、`0302`、`0212`、`0292`、`0203`（`0201`、`0102` 是 deadend，跳过） |
| 2 | 含 `1100`（`1000` 的第 2 位 +1） | 含 `1201`（`1202` 的第 4 位 −1） |
| 3 | 含 `1200` | — |
| 4 | 含 `1201`（`1200` 第 4 位 +1） | — |

`1201` 同时出现在两侧：$\text{distA}[1201] = 4$，$\text{distB}[1201] = 2$，于是 $\text{best} = 4 + 2 = 6$，对应路径 `0000 → 1000 → 1100 → 1200 → 1201 → 1202 → 0202`。

## 4. 算法细节

1. **先判起点**：`"0000"` 在 `deadends` 中时直接返回 `-1`（此时题目保证 `target ≠ "0000"`）。若把这一步放到 BFS 里，会从一个非法状态开始扩散。
2. **距离表与访问表合一**：用 `distA`/`distB`（键 → 距离）代替单纯的 `set`，相遇时一次查表就能拿到 $d_A+1+\text{distB}[v]$，不必再回溯。
3. **扩小不扩大**：每轮比较两侧前沿大小，只扩较小的一侧，把每层的常数压到 $\min(\lvert \text{frontA} \rvert, \lvert \text{frontB} \rvert)$；两侧同时扩张并不能降低总工作量的下界，反而容易写错层数。
4. **邻居生成**：4 位 × 2 方向 = 8 个邻居；`+1` 用 $(d+1)\bmod 10$，`-1` 用 $(d+9)\bmod 10$（C++ 里不要写 `d-1`，`0-1` 需要环绕）。
5. **入队即标记**：新节点在**生成时**就写入距离表，而不是出队时再标记，否则同一状态会在同一层被重复压入，前沿规模爆炸。
6. **状态编码**：C++ 里把串转成 $0..9999$ 的整数，用位权表 `[1, 10, 100, 1000]` 直接算出第 $i$ 位，避免每步都做字符串拼接；Python 里字符串切片足够快，直接用即可。

## 5. 正确性证明

**引理 1（图模型等价）**：一次旋转对应图中一条边，故从 `"0000"` 到 `target` 的任意合法旋转序列与图中的一条路径一一对应，且序列长度等于路径边数。于是"最少旋转次数" = "最短路长度"。

**证明**：旋转序列相邻两项恰好有一位相差 $\pm1$（模 10），这正是图中的边关系；反向同理，每条路径也能翻译成一段旋转序列，且两端都不碰 deadend。∎

**引理 2（`best` 始终对应真实路径）**：若 $v$ 由 A 侧第 $d_A+1$ 层生成且 $v \in \text{distB}$，则存在一条长度恰为 $d_A+1+\text{distB}[v]$ 的合法路径从 `"0000"` 到 `target`。

**证明**：由 `distA[v] = d_A+1` 存在长度 $d_A+1$ 的路径 `"0000"` $\to v$，每步都在非 deadend 节点间移动；由 `distB[v]` 存在长度 $\text{distB}[v]$ 的路径 $v \to$ `target`，同样合法。把两段在 $v$ 处拼接，得到一条长度 $d_A+1+\text{distB}[v]$ 的合法路径。故 `best` 记录的值都是真实可达的步数。∎

**引理 3（提前停安全）**：算法停止时若 $d_A+d_B \ge \text{best}$，则任意长度 $L \le d_A+d_B$ 的路径都被"检测"过，即 `best` $\le L$。

**证明**：设任一路径为 $x_0=\text{"0000"}, x_1, \dots, x_L=\text{target}$，取 $i = \min(d_A, L)$。则 $\text{distA}(x_i) \le i \le d_A$（$x_i$ 处的 A 侧距离不超过沿路走 $i$ 步），且当 $i < L$ 时 $\text{distB}(x_i) \le L - i \le L - d_A \le d_B$；当 $i = L \le d_A$ 时 $x_i$ 就是 `target`，$\text{distB}(x_i) = 0 \le d_B$。两种情况都有 $x_i \in \text{distA}$ 且 $x_i \in \text{distB}$，而"某个节点同时进入两侧距离表"这一事件发生时，代码必然更新过 `best`（可能由任一侧生成时触发），故 `best` $\le \text{distA}(x_i)+\text{distB}(x_i) \le L$。∎

**定理**：算法返回的值等于最少旋转次数；不可达时返回 `-1`。

**证明**：记真实最短路长为 $d^*$。由引理 2，`best` 始终是某条真实路径的长度，故 `best` $\ge d^*$。

若算法因 $d_A+d_B \ge \text{best}$ 停下：假设 $\text{best} > d^*$，则 $d^* < \text{best} \le d_A+d_B$，由引理 3 得 `best` $\le d^*$，矛盾；故 `best` $= d^*$。

若算法因某侧前沿为空停下：该侧已把本侧可达状态全部扩展完，而任意 `"0000"` 到 `target` 的合法路径上的每个节点都在该侧可达集内，若存在这样的路径，两侧必然在某个节点上"同时出现"，`best` 会被更新为有限值，与 `best = ∞` 矛盾；故不可达，返回 `-1` 正确。∎

## 6. 复杂度分析

- **时间**：单向 BFS 为 $O(V + E) = O(10^4 \times 8)$；双向 BFS 的上界相同（每个状态最多被一侧访问一次），但实际扩展的**层数**约为 $d^*/2$，前沿规模按 $8^{\lceil d^*/2 \rceil}$ 增长，因此在 $d^*$ 较大时显著更快。本题在不设 deadends 时最短路最长只有 20 步（如 `"5555"`，每位都差 5 步），即便加了绕路也远小于状态数，双向与单向都是毫秒级。
- **空间**：两侧距离表各 $O(10^4)$ 个整数，外加当前层前沿 $O(10^4)$；C++ 用 `vector<int>(10000)` 与 `vector<char>(10000)`，约几十 KB；Python 用两个 `dict` + 两个 `set`，量级同为 $O(10^4)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <climits>
using namespace std;

class Solution {
public:
    int openLock(vector<string>& deadends, string target) {
        vector<char> dead(10000, false);
        for (const string& s : deadends) dead[stoi(s)] = true;   // "0102" -> 102
        int start = 0, goal = stoi(target);
        if (dead[start]) return -1;                              // 起点就是死亡数字
        if (start == goal) return 0;

        vector<int> distA(10000, -1), distB(10000, -1);
        vector<int> frontA{start}, frontB{goal};
        distA[start] = distB[goal] = 0;
        int dA = 0, dB = 0, best = INT_MAX;
        const int pw[4] = {1, 10, 100, 1000};

        // 把 front 整层扩张一层：写入距离表，并在生成时立刻与对侧比对
        auto expand = [&](vector<int>& front, vector<int>& mine, int depth,
                          vector<int>& other, int& bestVal) {
            vector<int> nxt;
            for (int u : front) {
                for (int i = 0; i < 4; ++i) {
                    int d = (u / pw[i]) % 10;
                    int base = u - d * pw[i];
                    for (int delta : {1, 9}) {                   // +1 / -1 (mod 10)
                        int v = base + (d + delta) % 10 * pw[i];
                        if (dead[v] || mine[v] != -1) continue;
                        mine[v] = depth + 1;                     // 入队即标记
                        nxt.push_back(v);
                        if (other[v] != -1)                      // 两侧在 v 处相遇
                            bestVal = min(bestVal, depth + 1 + other[v]);
                    }
                }
            }
            front.swap(nxt);
        };

        while (!frontA.empty() && !frontB.empty() && dA + dB < best) {
            if (frontA.size() <= frontB.size()) {                // 只扩较小的一侧
                expand(frontA, distA, dA, distB, best);
                ++dA;
            } else {
                expand(frontB, distB, dB, distA, best);
                ++dB;
            }
        }
        return best == INT_MAX ? -1 : best;
    }
};
```

### Python

```python
class Solution:
    def openLock(self, deadends: list[str], target: str) -> int:
        dead = set(deadends)
        if "0000" in dead:
            return -1
        if target == "0000":
            return 0

        def nbrs(s: str):
            for i in range(4):
                d = ord(s[i]) - 48
                for nd in ((d + 1) % 10, (d + 9) % 10):   # +1 / -1（0 与 9 相邻）
                    yield s[:i] + chr(48 + nd) + s[i + 1:]

        frontA, frontB = {"0000"}, {target}
        distA, distB = {"0000": 0}, {target: 0}
        dA = dB = 0
        best = float("inf")

        while frontA and frontB and dA + dB < best:
            if len(frontA) <= len(frontB):                # 只扩较小的前沿
                nxt = set()
                for u in frontA:
                    for v in nbrs(u):
                        if v in distA or v in dead:
                            continue
                        distA[v] = dA + 1                 # 生成即标记
                        nxt.add(v)
                        if v in distB:                    # 两侧相遇，记账
                            best = min(best, dA + 1 + distB[v])
                frontA, dA = nxt, dA + 1
            else:
                nxt = set()
                for u in frontB:
                    for v in nbrs(u):
                        if v in distB or v in dead:
                            continue
                        distB[v] = dB + 1
                        nxt.add(v)
                        if v in distA:
                            best = min(best, dB + 1 + distA[v])
                frontB, dB = nxt, dB + 1

        return -1 if best == float("inf") else best
```

## 8. 边界情况与易错点

1. **起点被锁**：`deadends` 含 `"0000"` 时必须直接 `-1`，且要写在 `target == "0000"` 判断之前（题意保证 `target` 不在 `deadends` 中，所以两者不会同时成立，但顺序错了语义就变了）。
2. **零步答案**：`target == "0000"` 返回 `0`，不要让它走完 BFS（否则会得到 `2` 之类的绕路值，或者被"相遇即 `dA+1+dB`"的写法算成 `1`）。
3. **环绕**：`'0'` 减 1 是 `'9'`。Python 的 `%` 对负数已返回非负，C++ 必须写 `(d + 9) % 10`，直接写 `d - 1` 会得到 `-1` 并算出错误的位权偏移。
4. **第一次相遇 ≠ 最短路**：必须用 $d_A+d_B \ge \text{best}$ 作为终止条件（或改成严格按层同步推进），否则示例 1 这类"近处有陷阱、远处才是最短路"的数据会返回偏大的值。
5. **距离表不能退化成 `set`**：相遇公式需要 $\text{distB}[v]$ 的精确值，只存布尔访问标记就拿不到它。
6. **不可达**：示例 3 把 `"8888"` 的 8 个邻居全部封死，两侧各自搜完自己的连通块也接不上——此时两侧前沿先后变空，`best` 保持 $\infty$，返回 `-1`。
