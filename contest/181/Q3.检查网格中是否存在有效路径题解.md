# LeetCode 检查网格中是否存在有效路径 题解

## 1. 题目概述

- **标题 / 题号**：检查网格中是否存在有效路径（#1391，medium）
- **链接**：https://leetcode.cn/problems/check-if-there-is-a-valid-path-in-a-grid/
- **来源**：LeetCode 第 181 场周赛 Q3
- **难度**：中等
- **标签**：广度优先搜索、深度优先搜索、并查集、图、矩阵

**题意**：给定 $m \times n$ 网格 `grid`，每个格子是一条**形状固定**的街道，`grid[i][j] ∈ [1, 6]` 决定该街道连通哪两个相邻格：

- `1` 连通**左**、**右**；`2` 连通**上**、**下**；`3` 连通**左**、**下**；
- `4` 连通**右**、**下**；`5` 连通**左**、**上**；`6` 连通**右**、**上**。

从左上角 $(0,0)$ 出发，只能沿街道行走且**不能变更街道**，判断能否走到右下角 $(m-1, n-1)$。能则返回 `true`，否则 `false`。

**约束**：

- $1 \le m, n \le 300$
- $1 \le \text{grid}[i][j] \le 6$

> 💡 本场分胜负的一题：十分钟内要完成的转化是「格子 = 节点，街道接通 = 无向边，问的只是单源可达性」。真正的坑藏在「接通」的判定里——**必须双向核对两端开口**，示例 2/3 正是为此设下的陷阱。

## 2. 示例

**示例 1**

```text
输入：grid = [[2,4,3],[6,5,2]]
输出：true
解释：(0,0)→(1,0)→(1,1)→(0,1)→(0,2)→(1,2)，
     沿途每对相邻格都互相开口，恰好访问全部 6 格并到达终点。
```

**示例 2**

```text

输出：false
解释：(0,0)=1 朝左右开口，右邻 (0,1)=2 只朝上下开口——
     单向开口不接通，永远停在 (0,0)。
```

**示例 3**

```text
输入：grid = [[1,1,2]]
输出：false
解释：(0,0)→(0,1) 可走（同为 1，左右互通），
     但 (0,1)=1 朝右开口、(0,2)=2 只朝上下开口，断在 (0,1)。
```

**示例 4**

```text
输入：grid = [[1,1,1,1,1,1,3]]
输出：true
```

**示例 5**

```text

输出：true
```

## 3. 解题思路

### 3.1 暴力思路：沿街道模拟行走

最直觉的做法是从 $(0,0)$ 出发「顺着街道走」：看当前格的两个出口，挑一个能走的方向迈进邻居，重复直到终点。这个朴素框架有两个致命问题：

1. **死循环**：街道是**双向**的，两个互相接通的格子之间可以来回走。不加「已访问」标记，模拟会在 `A→B→A→B→…` 上永远打转（本题只问能否到达，走回头路不产生任何新信息）。
2. **单向核对的隐蔽 bug**：只检查「当前格子朝邻居开口」就跨过去，漏掉「邻居也要朝回开口」——示例 2 里 $(0,0)=1$ 朝右开口，按单向判定会误入 $(0,1)$，把答案错判成 `true`。

有趣的是，本题的「暴力」与「正解」复杂度**同阶**：修正这两个问题（加 `visited` + 双向核对）后，模拟本身就是 $O(mn)$ 的最优解。这场比赛比拼的不是优化能力，而是把「接通」判定写对。

### 3.2 核心观察：隐式无向图 + 双向开口核对

先把 6 种街道的开口方向编码清楚——每格恰有 **2 个出口**：

![六种街道类型及其开口方向](images/wc181_q3_street_types.svg)

**观察 1（格子 = 节点）**：把每个格子看作图的一个节点，格子的两个出口方向就是它的至多 2 条出边。网格是**隐式无向图**：不需要显式建边，走到格子时查表即可知道出口。

**观察 2（接通 = 两端核对）**：格子 $A$ 与邻居 $B$（沿方向 $(dr, dc)$）真正接通，必须**双方都承认这条边**：$A$ 的开口集合含 $(dr, dc)$，**且** $B$ 的开口集合含 $-(dr, dc)$。反向开口就是方向向量**取负**——这是本题最干净的实现技巧，连反向表都不用背。

![接通判定必须双向核对](images/wc181_q3_bidirectional_check.svg)

**观察 3（可达性 → 一次访问）**：题目只问「能否到达」，不问步数与路径。从 $(0,0)$ 做 BFS/DFS，`visited` 保证每格至多处理一次，到达 $(m-1, n-1)$ 即 `true`，队列空则 `false`。$mn \le 9 \times 10^4$，$O(mn)$ 稳过。

> 💡 **一句话**：开口信息**分散在两端格子里**，建边必须两端核对——「A 朝 B 开口」与「B 朝 A 开口」是两个独立条件，缺一即断。示例 2/3 的「停在半路」全是断在单向开口上。

### 3.3 算法流程：BFS

![BFS 判定有效路径流程](images/wc181_q3_bfs_flow.svg)

1. **初始化**：`vis` 全 `false`，$(0,0)$ 入队并标记。
2. **循环**：队列空 → 返回 `false`（所有可达格探索完，未到终点）。
3. 弹出 $(r, c)$；若 $(r, c) = (m-1, n-1)$ → 返回 `true`（**弹出时判终点**，天然覆盖 $1 \times 1$ 网格）。
4. 查表得 `grid[r][c]` 的两个出口 $(dr, dc)$，对每个出口：
   - 邻居 $(r+dr, c+dc)$ 越界、已访问 → 跳过；
   - 邻居的开口集合**不含** $-(dr, dc)$ → 跳过（单向开口，死边）；
   - 否则标记 `vis` 并入队。

> 💡 **终点判断时机**：放在「弹出时」而非「入队时」最稳妥——$1 \times 1$ 网格起点即终点，入队后第一次弹出即命中，零特判。

## 4. 算法细节

1. **出口表 `dirs`**：`dirs[t]` 存街道 `t` 的两个出口 $(dr, dc)$，直查索引 $O(1)$ 取出，替代 6 路 `if-else` 长链。注意本表用「行增量在前」的约定：下 = $(1,0)$、上 = $(-1,0)$、右 = $(0,1)$、左 = $(0,-1)$。
2. **反向开口 = 取负**：邻居 $B$ 朝 $A$ 开口的方向恰为 $-(dr, dc)$，于是双向核对一行搞定：`(-dr, -dc) in dirs[grid[nr][nc]]`。无需额外 `opp` 映射表——这是向量编码相对「上右下左 0123 编号」更省心的地方。
3. **`visited` 在入队时标记**（而非弹出时）：否则同一格子可能被多个邻居重复入队，队列规模退化到 $O(mn \cdot 2)$；入队即标记保证每格至多进队一次。
4. **为何选 BFS 而非 DFS**：可达性二者皆可，但 DFS 递归深度最坏达 $mn = 9 \times 10^4$（例如全 `2` 的 $300 \times 300$ 网格形成一条长链），Python 默认递归上限 1000 直接爆栈，C++ 也接近默认栈深。BFS 用显式队列，稳定无忧。
5. **并查集等价写法**：遍历每格的每个出口，双向接通则 `union(A, B)`；最后判 `find((0,0)) == find((m-1,n-1))`。复杂度 $O(mn \cdot \alpha(mn))$，同样一次遍历，适合作为模板对照（见延伸思考）。
6. **入口特判不需要**：$(0,0)$ 的两个出口可能都越界或都是死边（如 $1 \times 1$ 之外的 `grid = [[5]]` 变体），BFS 框架自动返回正确结果，不写任何针对起点的分支。

## 5. 正确性证明

记 $\mathrm{open}(t) \subseteq \{(\pm1,0),(0,\pm1)\}$ 为街道类型 $t$ 的开口集合：$\mathrm{open}(1)=\{\text{左},\text{右}\}$、$\mathrm{open}(2)=\{\text{上},\text{下}\}$、$\mathrm{open}(3)=\{\text{左},\text{下}\}$、$\mathrm{open}(4)=\{\text{右},\text{下}\}$、$\mathrm{open}(5)=\{\text{左},\text{上}\}$、$\mathrm{open}(6)=\{\text{右},\text{上}\}$。

**引理 1（接通刻画）**：设格 $A=(r,c)$ 与 $B=A+(dr,dc)$ 相邻且 $B$ 在界内，则 $A$ 与 $B$ 的街道拼接、可沿街道从 $A$ 走到 $B$，当且仅当 $(dr,dc) \in \mathrm{open}(\text{grid}[A])$ 且 $-(dr,dc) \in \mathrm{open}(\text{grid}[B])$。

**证明**：街道是各格内形状固定的线段，只在该格的两条开口边的中点处抵达边界。沿街道从 $A$ 穿到 $B$ 必须越过公共边，这要求 $A$ 的街道在公共边一侧有端点、即 $(dr,dc) \in \mathrm{open}(\text{grid}[A])$，**同时** $B$ 的街道在同一条公共边一侧有端点、即 $-(dr,dc) \in \mathrm{open}(\text{grid}[B])$；反之两端都开口时两段街道在公共边中点相接，构成连续可走的路段。∎

**引理 2（无向性）**：若 $A$ 与 $B$ 接通，则 $B$ 与 $A$ 接通。

**证明**：由引理 1，$A$—$B$ 接通的条件为 $(dr,dc) \in \mathrm{open}(A) \wedge -(dr,dc) \in \mathrm{open}(B)$；交换视角后 $B$—$A$ 接通的条件为 $-(dr,dc) \in \mathrm{open}(B) \wedge (dr,dc) \in \mathrm{open}(A)$，二者是同一组条件。∎

**引理 3（路径刻画）**：存在有效路径 $\Leftrightarrow$ 在无向图 $G$（节点 = 格子，边 = 接通的格子对）中 $(0,0)$ 与 $(m-1,n-1)$ 连通。

**证明**：有效路径是依次接通的格子序列，逐段应用引理 1 即得 $G$ 中的一条路径；反之 $G$ 中的路径逐边还原为沿街道的行走。∎

**定理（BFS 正确性）**：上述算法返回 `true` 当且仅当存在有效路径。

**证明**：

- **可靠性（返回 `true` ⇒ 有路径）**：归纳断言「凡入队的格子均从 $(0,0)$ 出发接通可达」。(0,0) 平凡成立；$(nr,nc)$ 仅在某已入队格 $(r,c)$ 弹出、且通过引理 1 的双向核对后入队，由归纳假设 $(r,c)$ 可达，故 $(nr,nc)$ 可达。返回 `true` 时终点已入队，由引理 3 存在有效路径。
- **完备性（有路径 ⇒ 返回 `true`）**：设 $v_0=(0,0), v_1, \dots, v_k=(m-1,n-1)$ 是一条接通路径，归纳证明每个 $v_i$ 都会入队。$v_0$ 初始入队；队列中元素终会被弹出，当 $v_i$ 被弹出处理时，枚举其出口必命中指向 $v_{i+1}$ 的方向（引理 1 前半），此时 $v_{i+1}$ 要么已 `visited`（则已入队），要么恰好被双向核对通过而入队。故终点必入队，弹出时返回 `true`。
- 队列空时返回 `false` 的情形由逆否命题即得：若存在路径，由完备性不可能在到达终点前耗尽队列。∎

**推论**：算法访问的格子集合恰为从 $(0,0)$ 可达的格子全集。

## 6. 复杂度分析

- **时间复杂度**：$O(mn)$。每格至多入队一次、弹出一次；每次弹出枚举 2 个出口，每个出口做一次 $O(1)$ 的界内判断与反向核对（邻居开口集合大小为 2）。$m, n \le 300$ 时约 $9 \times 10^4$ 格，毫秒级。
- **空间复杂度**：$O(mn)$。`vis` 矩阵 $O(mn)$；队列最坏容纳全部 $mn$ 格。若用并查集则同样 $O(mn)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool hasValidPath(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        // dirs[t]：街道 t 的两个出口方向 (dr, dc)
        static const vector<pair<int,int>> dirs[7] = {
            {},
            {{0, 1}, {0, -1}},    // 1：右、左
            {{1, 0}, {-1, 0}},    // 2：下、上
            {{0, -1}, {1, 0}},    // 3：左、下
            {{0, 1}, {1, 0}},     // 4：右、下
            {{0, -1}, {-1, 0}},   // 5：左、上
            {{0, 1}, {-1, 0}}     // 6：右、上
        };
        vector<vector<char>> vis(m, vector<char>(n, 0));
        queue<pair<int,int>> q;
        q.push({0, 0});
        vis[0][0] = 1;
        while (!q.empty()) {
            auto [r, c] = q.front(); q.pop();
            if (r == m - 1 && c == n - 1) return true;   // 弹出时判终点
            for (auto [dr, dc] : dirs[grid[r][c]]) {
                int nr = r + dr, nc = c + dc;
                if (nr < 0 || nr >= m || nc < 0 || nc >= n || vis[nr][nc]) continue;
                bool ok = false;                          // 邻居须有反向开口 (−dr,−dc)
                for (auto [br, bc] : dirs[grid[nr][nc]])
                    if (br == -dr && bc == -dc) { ok = true; break; }
                if (!ok) continue;
                vis[nr][nc] = 1;
                q.push({nr, nc});
            }
        }
        return false;
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def hasValidPath(self, grid: List[List[int]]) -> bool:
        m, n = len(grid), len(grid[0])
        # 街道 t 的两个出口方向 (dr, dc)
        dirs = {
            1: ((0, 1), (0, -1)),    # 右、左
            2: ((1, 0), (-1, 0)),    # 下、上
            3: ((0, -1), (1, 0)),    # 左、下
            4: ((0, 1), (1, 0)),     # 右、下
            5: ((0, -1), (-1, 0)),   # 左、上
            6: ((0, 1), (-1, 0)),    # 右、上
        }
        vis = [[False] * n for _ in range(m)]
        q = deque([(0, 0)])
        vis[0][0] = True
        while q:
            r, c = q.popleft()
            if r == m - 1 and c == n - 1:
                return True                         # 弹出时判终点
            for dr, dc in dirs[grid[r][c]]:
                nr, nc = r + dr, c + dc
                if 0 <= nr < m and 0 <= nc < n and not vis[nr][nc] \
                        and (-dr, -dc) in dirs[grid[nr][nc]]:   # 双向核对
                    vis[nr][nc] = True
                    q.append((nr, nc))
        return False
```

> 💡 **实现要点**：① `(-dr, -dc) in dirs[grid[nr][nc]]` 一行完成双向核对——反向开口就是向量取负；② C++ 里 `dirs` 声明为 `static const` 避免每次调用重建；③ `vis` 用 `vector<char>` / `list[bool]`，绕开 `vector<bool>` 位压缩的代理引用怪癖。

## 8. 边界情况与易错点

1. **单向开口陷阱**（最高频翻车点）：只核对「当前格朝邻居开口」就跨过去，示例 2 会被误判 `true`。开口信息分散在两端格子里，**两端都要核对**。
2. **缺 `visited` 死循环**：街道双向，两个接通的格子来回走永远不终止；即便改成带步数上限的模拟也是错的做法。入队时即标记。
3. **$1 \times 1$ 网格**：起点即终点，恒返回 `true`（无论街道类型）。终点判断放「弹出时」可零特判覆盖。
4. **起点的开口全部对外越界**：如 `grid = [[5]]` 之外的 `[[5],[6]]` 首格左上开口在 $m>1$ 时左开口越界、上开口越界，只剩死路——框架自动处理，勿手写针对起点的分支。
5. **DFS 栈深**：$mn$ 可达 $9 \times 10^4$，Python 递归必爆栈（默认上限 1000），C++ 亦逼近默认栈容。**比赛首选 BFS**。
6. **行列与 $(dr, dc)$ 对应**：$(1,0)$ 是**向下**（行增），$(0,1)$ 是向右（列增）。把 `dirs` 写反是除单向核对外第二高频 bug，建议画 $2\times2$ 小格自测。
7. **形状记忆别靠背**：赛时在草稿上画 6 个小格（1 横、2 竖、3 左下、4 右下、5 左上、6 右上）对照编码，比背口诀可靠——本仓库 510 场 Q3 题解同样踩过「构造类网格题先画小样」的套路。
8. **并查集写法的遍历顺序**：若改用并查集，注意每条接通边会被两端各枚举一次，`union` 两次无害但别漏反向核对，否则与 BFS 版行为不一致。

**延伸思考**：

- **并查集解法**：把每个格子按 $(r \cdot n + c)$ 编号，遍历全部格子的全部出口，双向接通则 `union` 两端，最终比较 `find(0)` 与 `find(mn-1)`。复杂度 $O(mn \cdot \alpha(mn))$。当问题变体为「多组询问某两格是否互通」时，一次建图 + 多次查询的并查集比每次 BFS 更划算。
- **双向 BFS**：从起点和终点**同时**扩展（终点侧需按「入边」反向走：枚举邻居时反过来核对），两侧集合相遇即 `true`。渐近复杂度不变，但在大网格、答案为 `true` 时可提前终止，是可达性判定的常用加速。
- **哈密顿性陷阱**：示例 1 的路径恰好经过所有格子，但本题只问**可达性**（两点连通），不要求访问全部格子——「访问所有格子恰好一次」是哈密顿路径问题，NP-hard，切勿混淆。
