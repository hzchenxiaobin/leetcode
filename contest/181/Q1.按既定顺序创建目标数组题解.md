# LeetCode 按既定顺序创建目标数组 题解

## 1. 题目概述

- **标题 / 题号**：按既定顺序创建目标数组（#1389，easy）
- **链接**：https://leetcode.cn/problems/create-target-array-in-the-given-order/
- **来源**：LeetCode 第 181 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟

**题意**：给定两个等长数组 `nums` 与 `index`。`target` 初始为空，按从左到右顺序，每步在 `target` 的下标 `index[i]` 处**插入** `nums[i]`（若插在中间，该位置及其右侧元素整体右移一位），处理完所有元素后返回 `target`。

**约束**：

- $1 \le \text{nums.length} = \text{index.length} \le 100$
- $0 \le \text{nums}[i] \le 100$
- $0 \le \text{index}[i] \le i$

> 💡 签到题的最短路径：题面那句「在下标 index[i] 处插入 nums[i]」逐字对应库函数 `insert(index[i], nums[i])`——**把题意翻译成代码就是正解**。约束 $0 \le \text{index}[i] \le i$ 已把插入合法性兜死，全程零特判、零分支；唯一真坑是把「插入」写成「下标赋值（覆盖）」。

```

nums       index     target

```

**示例 3**

输出：[5,4,3,2,1]

## 3. 解题思路

### 3.1 暴力思路：模拟本身就是正解

这题的「暴力」与「正解」重合：$n \le 100$，就算每步插入都引发满额搬移，总搬移量也只有 $\sum_{i=0}^{n-1} i \approx 5 \times 10^3$。若语言没有现成 `insert`，手写搬移也只多三行：从尾部起把 `target[j] = target[j-1]` 逐位右移，再把新值落进 `p`。真正需要警惕的不是复杂度，而是**语义**——把「插入」误写成「覆盖」（见 §8）。

至于「能不能不模拟、直接算每个元素的最终位置」——可以（逆序 + 树状数组找第 $k$ 个空位，$O(n \log n)$），但在 $n \le 100$ 的签到题上是纯粹的过度设计，作为延伸思考收录在文末。

### 3.2 核心观察：插入 = 挤开；缝隙编号与约束一一对应

![核心观察：缝隙编号与约束 0 ≤ index[i] ≤ i 一一对应，插入即挤开](images/wc181_q1_insert_shift_concept.svg)

**观察 1（插入 = 挤开）**：在下标 $p$ 处插入 $x$，等价于把原 `target[p..]` 整体右移一位、$x$ 落入空出的 $p$ 号位、长度 +1。这正是「后插的元素能排到先插元素前面」的机制——示例 1 第 5 步把 4 插到下标 1，原来的 1、3、2 全体右移，4 反超到 1 之前。

**观察 2（合法性白送）**：插入第 $i$ 个元素（0 索引）时 `target` 恰有 $i$ 个元素，可插的**缝隙**有 $i+1$ 个（含首前与尾后），编号恰为 $0 \ldots i$。约束 $0 \le \text{index}[i] \le i$ 与缝隙编号**逐值重合**——每一步的插入位置都天然合法。

**观察 3（「保证」是推论）**：题目那句「数字插入位置总是存在」并非额外信息，而是观察 2 的直接推论。比赛读题时确认这一点，就可以放心写「无检查」的代码。

### 3.3 算法流程

![算法流程：一个循环 + 一次库 insert，无分支无特判](images/wc181_q1_sim_flow.svg)

1. 初始化 `target = []`（C++ 建议 `reserve(n)` 预留容量）；
2. `i` 从 $0$ 遍历到 $n-1$，每步执行 `target.insert(index[i], nums[i])`；
3. 返回 `target`。

整个流程**一个循环 + 一次库调用**，没有分支、没有特判、没有哨兵——约束已把所有边界情形排除在代码之外。这就是签到题的「最短路径」形态：把题面逐句映射到库语义，不多写一行。

### 3.4 示例演算

![示例演算：示例 2 逐步插入与 index 全 0 的最坏情形](images/wc181_q1_walkthrough.svg)

以示例 2（`nums = [1,2,3,4,0]`、`index = [0,1,2,3,0]`）走查全过程（红 = 新插入，橙 = 被挤开右移）：

| 步骤 $i$ | $\text{nums}[i]$ | $\text{index}[i]$ | 插入后 `target` | 说明 |
|----------|------------------|-------------------|-----------------|------|
| 0 | 1 | 0 | `[1]` | 空数组首插 |
| 1 | 2 | 1 | `[1,2]` | 尾后缝隙，零搬移 |
| 2 | 3 | 2 | `[1,2,3]` | 尾后缝隙，零搬移 |
| 3 | 4 | 3 | `[1,2,3,4]` | 尾后缝隙，零搬移 |
| 4 | 0 | 0 | `[0,1,2,3,4]` | **插在缝隙 0：1,2,3,4 全体右移** |

前 4 步 $\text{index}[i] = i$ 都落在「尾后缝隙」，等价于追加、零搬移；只有第 5 步真正触发「挤开」。再对照自拟的最坏情形 `index = [0,0,0,0,0]`：每步都插头部、每步满额搬移，结果恰为 `nums` 的逆序 `[5,4,3,2,1]`——$O(n^2)$ 的最坏输入一眼可见，也可作对拍样例。

## 4. 算法细节

1. **insert 的精确语义**：C++ `target.insert(target.begin() + p, x)` 与 Python `target.insert(p, x)` 完全同义：位置 $p$ 及右侧元素右移一位、$x$ 落入 $p$、长度 +1，且都允许 $p = |\text{target}|$（追加）。注意 C++ 传的是**迭代器**，`begin() + index[i]` 即下标 $p$ 处。
2. **手写搬移的兜底写法**（无库 / 面试手搓）：从**尾**往**头**扫——`for (j = len-1; j >= p; --j) target[j+1] = target[j]; target[p] = x;`。方向不能反：从前往后挪会在后面的值被读走之前就把它覆盖。
3. **`reserve` 是优化不是正确性**：$n \le 100$ 时扩容至多发生 $\lfloor \log_2 100 \rfloor \approx 7$ 次，写不写都行；写上是为养成大 $n$ 场景的习惯。
4. **Python 的 `zip` 配对**：`for x, p in zip(nums, index)` 比下标访问少一层 `nums[i] / index[i]` 的重复索引，签到题提速器。
5. **零特判的底气**：不写 `if (p > target.size())` 之类的检查——由 §5 引理 2，约束已排除一切非法输入；多余检查反而稀释「题意即代码」的可读性。

## 5. 正确性证明

**引理 1（长度不变量）**：对任意 $k \in [0, n]$，算法处理完前 $k$ 对指令后 $|\text{target}| = k$。

**证明**：对 $k$ 归纳。$k = 0$ 时 `target` 为空。设结论对 $k$ 成立；第 $k+1$ 步执行一次 `insert`，由库语义数组长度恰增 1，故 $|\text{target}| = k+1$。∎

**引理 2（插入合法性）**：第 $i$ 步（0 索引）执行时，合法插入下标集合为 $[0, i]$，而 $0 \le \text{index}[i] \le i$ 保证 `index[i]` 落在其中。

**证明**：由引理 1，第 $i$ 步执行前 $|\text{target}| = i$；长度为 $i$ 的数组的插入位置是 $i+1$ 个缝隙，编号 $0 \ldots i$（编号 $p$ 的缝隙即「新值落下标 $p$」，含首前 $p=0$ 与尾后 $p=i$）。结合约束即得。∎

**定理（模拟的正确性）**：算法返回的数组与题意定义的目标数组逐元素相同。

**证明**：对步数 $k$ 归纳，加强命题：处理完前 $k$ 步后 `target` 恰为题意对前 $k$ 对指令定义的中间数组 $T_k$。$k=0$ 时两者皆空。设结论对 $k$ 成立；题意要求第 $k+1$ 步在 $T_k$ 的下标 $\text{index}[k]$ 处插入 $\text{nums}[k]$ 得 $T_{k+1}$。由引理 2 该 `insert` 合法，且 `insert(p, x)` 的结果恰为 $T_k[0..p-1] + [x] + T_k[p..]$，与题意「$p$ 及右侧右移一位、$x$ 落入 $p$」一致，故 `target` $= T_{k+1}$。$k = n$ 时即得所证。∎

**推论**：题面「数字插入位置总是存在」由引理 2 直接推出，是冗余保证——代码无需也不应有任何越界检查。

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。第 $i$ 次插入最坏搬移 $i$ 个元素（插在缝隙 0 时），总搬移 $\sum_{i=0}^{n-1} i = \frac{n(n-1)}{2}$；$n = 100$ 时约 $4950$ 次元素搬移，加上 $n$ 次调用开销，毫秒级。
- **空间复杂度**：$O(n)$。输出数组本身占 $O(n)$（题目要求返回，不可省）；额外空间 $O(1)$（`reserve` 只预留容量，不改量级）。
- **签到题视角**：$O(n^2)$ 与 $O(n \log n)$ 在 $n \le 100$ 下差距不足 1ms，选**代码最短、出错面最小**的写法才是正确取舍。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> createTargetArray(vector<int>& nums, vector<int>& index) {
        vector<int> target;
        target.reserve(nums.size());
        for (int i = 0; i < (int)nums.size(); ++i)
            target.insert(target.begin() + index[i], nums[i]);
        return target;
    }
};
```

### Python

```python
class Solution:
    def createTargetArray(self, nums: List[int], index: List[int]) -> List[int]:
        target = []
        for x, p in zip(nums, index):
            target.insert(p, x)
        return target
```

> ⚠️ 千万别写成 `target[index[i]] = nums[i]`——下标赋值是「**覆盖**」：不右移、长度不增长，在空数组上更是直接越界（Python 抛 `IndexError`，C++ 未定义行为）。判定自己是否踩坑的最快用例：`nums = [1,2], index = [0,0]`，正确答案 `[2,1]`，覆盖写法连长度都凑不出来。

## 8. 边界情况与易错点

1. **插入 ≠ 覆盖**（最高频翻车点）：`insert(p, x)` 挤开右侧、长度 +1；`target[p] = x` 直接替换、长度不变，空数组上即越界。题面每个字都在说「插入」。
2. **手写搬移方向**：必须从**尾**往**头**（`j` 从 `len-1` 递减到 `p`）；从前往后会在读走 `target[j]` 之前把它覆盖掉。
3. **两个极端下标**：`index[i] = i` 是尾后追加、零搬移（等价 `push_back`）；`index[i] = 0` 是头部插入、满额搬移。`index` 全 0 时答案为 `nums` 的逆序，可作对拍样例。
4. **单元素**：`nums = [1], index = [0]` → `[1]`，首插即尾插，别对「空数组插 0 号位」发怵——缝隙 0 永远存在。
5. **不要画蛇添足**：越界检查、空数组特判、`p == size` 分支全都不需要（引理 2 已兜底）；`insert` 本身就接受 `p == len`。
6. **C++ 迭代器写法**：`target.begin() + index[i]` 中 `index[i]` 是 `int` 偏移，别把 `index[i]` 误当迭代器；`(int)nums.size()` 防有符号比较警告。
7. **返回值**：直接 `return target;`（移动语义 / RVO 处理），无需额外拷贝。
