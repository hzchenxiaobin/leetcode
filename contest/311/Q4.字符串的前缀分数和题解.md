# LeetCode 字符串的前缀分数和 题解

## 1. 题目概述

- **标题 / 题号**：字符串的前缀分数和（#2416，hard）
- **链接**：https://leetcode.cn/problems/sum-of-prefix-scores-of-strings/
- **来源**：LeetCode 第 311 场周赛 Q4
- **难度**：困难
- **标签**：字典树（Trie）、字符串、计数、前缀

**题意**：给定长度为 $n$ 的非空字符串数组 `words`。定义字符串 `term` 的**分数**为 `words` 中以 `term` 为**前缀**的字符串数目（字符串视作它自身的前缀）。要求返回数组 `answer`，其中 $\text{answer}[i]$ 等于 `words[i]` 的**每个非空前缀的分数之和**。

**约束**：

- $1 \le n = \text{words.length} \le 1000$
- $1 \le \text{words}[i].\text{length} \le 1000$
- `words[i]` 仅由小写英文字母组成
- 记总字符数 $S = \sum_i \text{words}[i].\text{length} \le 10^6$

> 💡 **复盘视角**：本场唯一的困难题，算法内核却是「**Trie 前缀计数**」这一标准套路——分数的定义「有多少单词以 `term` 为前缀」几乎就是为 Trie 量身定做的。分水岭在于两点：一是能否立刻把「前缀的分数」翻译成「Trie 节点上的计数器」；二是绕开「物化每个前缀」的哈希表陷阱（那是 $O(N \cdot L^2)$ 的天坑）。识别出模板后，本题 10 分钟内可提交。

## 2. 示例

**示例 1**

```text
输入：words = ["abc","ab","bc","b"]
输出：[5,4,3,2]

解释：
- "abc" 的前缀 "a"/"ab"/"abc" 分数为 2/2/1 → 2+2+1 = 5
- "ab"  的前缀 "a"/"ab"       分数为 2/2   → 2+2 = 4
- "bc"  的前缀 "b"/"bc"       分数为 2/1   → 2+1 = 3
- "b"   的前缀 "b"            分数为 2     → 2
```

**示例 2**

```text
输入：words = ["abcd"]
输出：[4]

解释："abcd" 的 4 个前缀 "a"/"ab"/"abc"/"abcd" 分数均为 1，总计 1+1+1+1 = 4。
```

**示例 3**（重复单词，验证计数语义）

```text
输入：words = ["a","a","aa"]
输出：[3,3,4]

解释：以 "a" 为前缀的单词有 3 个（"a"、"a"、"aa"），以 "aa" 为前缀的有 1 个（"aa" 自身）。
- 两个 "a"：前缀 "a" 分数 3 → 3
- "aa"：前缀 "a"(3) + "aa"(1) → 4
重复单词的每次出现都要计入分数，Trie 的 cnt 沿路径累加，天然支持这一点。
```

## 3. 解题思路

### 3.1 暴力思路

**做法一：哈希表物化所有前缀**。第一遍扫 `words`，对每个单词枚举其全部非空前缀 `w[:k]` 并在哈希表中计数；第二遍再枚举前缀查表求和。逻辑与题意逐字对应，但每个 `w[:k]` 都要**真正拷贝**出长度为 $k$ 的子串——单个长度 $L$ 的单词枚举全部前缀的拷贝总长 $\sum_{k=1}^{L} k = O(L^2)$，$N$ 个单词合计 $O(N \cdot L^2)$。本题 $N = L = 1000$ 时高达 $10^9$ 字符；哈希表还要为**每个单词的每个前缀单独存一份字符串**，公共前缀被重复存储，空间同样 $O(N \cdot L^2) \approx 1\,\text{GB}$，时间空间双双爆表。

**做法二：两两求最长公共前缀**。单词 `words[j]` 对 $\text{answer}[i]$ 的贡献恰等于两者的公共前缀个数（含自身），即 $\text{LCP}(\text{words}[i], \text{words}[j])$，于是 $\text{answer}[i] = \sum_j \text{LCP}(\text{words}[i], \text{words}[j])$。两两比较为 $O(N^2 \cdot L) = 10^9$，同样过慢。

> ⚠️ 两种暴力的共同浪费：**相同的前缀被反复物化、反复比较**。`"abc"` 与 `"ab"` 共享 `"a"`、`"ab"`，哈希表却各存一份。把公共前缀**折叠进同一条树路径**，让每个字符只存一次、只处理一次——这正是 **Trie** 的主场。

### 3.2 核心观察：Trie 节点上的 cnt = 该前缀的分数

![核心观察：Trie 节点上的 cnt 即该前缀的分数](images/2416_trie_cnt_concept.svg)

把所有 `words` 插入一棵 Trie。给每个节点挂一个计数器 `cnt`，含义为「**插入过程中经过该节点的单词数**」：插入单词 `w` 时从根出发沿 `w` 的字符逐层下行，**每到达一个节点就给它的 `cnt` 加 1**。

由于「根到节点 $v$ 的路径」逐字符拼出的字符串恰是一个非空前缀，而「单词 $w$ 以该前缀为前缀」$\iff$「$w$ 的插入路径经过 $v$」，全部插完后：

$$\text{cnt}[v] = \#\{\,w \in \text{words} : \text{path}(v)\ \text{是}\ w\ \text{的前缀}\,\} = \text{前缀 path}(v)\ \text{的分数}$$

即 **`cnt` 就是分数**，定义与计数一一对齐。

> 💡 **前缀身份由完整路径决定**：`"ab"` 里的 `b`（路径 `根→a→b`）与单词 `"b"`（路径 `根→b`）是 Trie 中**两个不同的节点**。`cnt` 挂在节点而非字符上，末字符相同也不会串扰。

### 3.3 算法流程：一趟插入、一趟查询

![算法流程：阶段一插入沿路径 cnt+=1，阶段二查询沿路径累加 cnt](images/2416_insert_query_flow.svg)

两阶段骨架，共用同一棵 Trie：

```text
1. 阶段一 · 插入：遍历 words，对每个 w 执行 insert(w)
   insert(w): cur = root
              for c in w:
                  if cur.child[c] 不存在: 新建
                  cur = cur.child[c]        # 先下移
                  cur.cnt += 1               # 再计数（根永不被计数 → 空前缀不计分）

2. 阶段二 · 查询：遍历 words，对每个 w[i] 执行 query(w[i]) 得 answer[i]
   query(w): cur = root, sum = 0
             for c in w:
                 cur = cur.child[c]         # 必存在，无需判空
                 sum += cur.cnt
             return sum
3. 返回 answer
```

> 💡 **没有 `is_end` 标记**：本题只关心「前缀」不关心「单词边界」，一个 `cnt` 承载了全部信息。且**必须先全部插入、再统一查询**——查询依赖的是「全体单词统计完」的 `cnt`，不能边插边查。

### 3.4 示例演算

![示例演算：建好 Trie 后逐词沿路径累加 cnt](images/2416_example_walkthrough.svg)

以示例 1 `words = ["abc","ab","bc","b"]` 演算。

**阶段一 · 建 Trie**（每经过一个节点 `cnt += 1`）：

| 插入 | 触达节点与 cnt 变化 |
|------|---------------------|
| "abc" | 根→a(1)→b(1)→c(1) |
| "ab"  | 根→a(2)→b(2) |
| "bc"  | 根→b(1)→c(1)（另起 b 支，与 a 支无关）|
| "b"   | 根→b(2) |

最终各节点 `cnt`：`根→a = 2`、`根→a→b = 2`、`根→a→b→c = 1`、`根→b = 2`、`根→b→c = 1`。

**阶段二 · 查询**（沿路径逐节点累加 `cnt`）：

| word | 下行路径与累加 | answer |
|------|----------------|--------|
| "abc" | a(2) + b(2) + c(1) | 5 |
| "ab"  | a(2) + b(2)        | 4 |
| "bc"  | b(2) + c(1)        | 3 |
| "b"   | b(2)               | 2 |

最终 `answer = [5, 4, 3, 2]` ✓。

## 4. 算法细节

1. **节点结构**：`children[26] + cnt`。字符集仅小写字母，定长数组下标 `c - 'a'` 最快；无需 `is_end`（不关心单词边界，见 3.3）。
2. **计数时机**：`cur = child[c]` **之后**才 `++cnt`——即只对「下移后到达的节点」计数，根节点天然被跳过，恰好对应「非空前缀才计分」。
3. **查询不判空**：树中已含全部单词，查询路径必然存在，直接下移即可；根节点同理不参与求和。
4. **重复单词**：`["a","a"]` 插入两次，`cnt[a] = 2`，每次出现都计入分数，无需特判（见示例 3）。
5. **C++ 内存预算**：指针版 `TrieNode` 含 26 个指针 + `int`，约 $216$ 字节/节点；最坏 $S = 10^6$ 个节点时约 $216\,\text{MB}$，偏紧。改用**数组化 Trie**（`vector<array<int,26>>`，子节点存下标），每节点约 $104$ 字节，$S = 10^6$ 时约 $110\,\text{MB}$，更稳妥（见参考代码）。
6. **答案上界**：每个前缀分数 $\le n \le 1000$，每个单词至多 $1000$ 个前缀，故 $\text{answer}[i] \le 10^6$，`int` 足够，无需 `long long`。

## 5. 正确性证明

**引理 1（节点与前缀的双射）**：全部插入完成后，Trie 中除根外的节点集合与全体单词的非空前缀集合之间存在双射 $\text{path}: v \mapsto \text{path}(v)$（根到 $v$ 的路径拼出的字符串）。

**证明**：任取单词 $w$ 与其长度 $k \in [1, |w|]$ 的前缀 $w[:k]$。插入 $w$ 时从根下行 $k$ 步到达节点 $v$，且 Trie 无删除操作，则 $\text{path}(v) = w[:k]$，故每个前缀都有节点与之对应。反之，除根外每个节点都是在插入某个 $w$ 时被创建或经过的，其路径是那个 $w$ 的前缀。若两节点 $u \ne v$ 而 $\text{path}(u) = \text{path}(v)$，则从根出发逐字符确定下一节点的下行过程唯一，必有 $u = v$，矛盾。故为双射。∎

**引理 2（cnt 的语义）**：全部插入完成后，$\text{cnt}[v] = \#\{\,w \in \text{words} : \text{path}(v)\ \text{是}\ w\ \text{的前缀}\,\}$，即 $\text{cnt}[v]$ 恰为前缀 $\text{path}(v)$ 的分数。

**证明**：插入 $w$ 时路径上每个节点各 `+1`，故 $\text{cnt}[v]$ 等于「插入过程中经过 $v$ 的次数」。而插入 $w$ 经过 $v$ 当且仅当下行 $\text{path}(v)$ 的每个字符都匹配 $w$ 的对应位置，即 $\text{path}(v)$ 是 $w$ 的前缀（$|\text{path}(v)| \ge 1$ 且逐字符相同）。对所有 $w$ 求和即得。∎

**引理 3（查询和式）**：查询 $w$ 时，下行 $k$ 步到达的节点 $v_k$ 满足 $\text{path}(v_k) = w[:k]$，故

$$\text{sum} = \sum_{k=1}^{|w|} \text{cnt}[v_k] = \sum_{k=1}^{|w|} \text{score}(w[:k]).$$

**证明**：$v_k$ 的路径即 $w$ 的前 $k$ 个字符，引理 1 保证 $\text{path}(v_k) = w[:k]$；再由引理 2，$\text{cnt}[v_k] = \text{score}(w[:k])$。逐项求和即得。∎

**定理**：算法返回的 `answer` 满足题意，即 $\text{answer}[i]$ 等于 `words[i]` 所有非空前缀分数之和。

**证明**：阶段一无遗漏地插入了全部单词，引理 1、2 成立；阶段二对每个 `words[i]` 按引理 3 计算，`sum` 恰为 $\sum_{k=1}^{|\text{words}[i]|} \text{score}(\text{words}[i][:k])$，即题意所求（空前缀不计，$k$ 从 1 起）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(S)$，其中 $S = \sum_i \text{words}[i].\text{length} \le 10^6$。
  - 阶段一插入：每个字符处理一次（下移 + 计数），共 $O(S)$。
  - 阶段二查询：每个字符处理一次（下移 + 累加），共 $O(S)$。
  - 无任何子串物化与两两比较，对照暴力 $O(N \cdot L^2)$ / $O(N^2 L)$ 是数量级的改善。
- **空间复杂度**：$O(S)$。
  - Trie 节点数 $\le S + 1$（每读一个字符至多新建一个节点）。
  - 数组化实现约 $104$ 字节/节点；输出数组 $O(n)$。

## 7. 参考代码

### C++（数组化 Trie，省内存）

```cpp
class Solution {
  public:
    vector<int> sumPrefixScores(vector<string>& words) {
        int S = 0;
        for (const string& w : words) S += (int)w.size();

        // 0 号节点为根；ch[v][c] = 0 表示无该子节点
        vector<array<int, 26>> ch(S + 1);
        vector<int> cnt(S + 1, 0);
        int tot = 0;

        // 阶段一：插入，沿路径 cnt += 1
        for (const string& w : words) {
            int cur = 0;
            for (char c : w) {
                int x = c - 'a';
                if (!ch[cur][x]) ch[cur][x] = ++tot;
                cur = ch[cur][x];
                ++cnt[cur];
            }
        }

        // 阶段二：查询，沿路径累加 cnt
        vector<int> ans;
        ans.reserve(words.size());
        for (const string& w : words) {
            int cur = 0, sum = 0;
            for (char c : w) {
                cur = ch[cur][c - 'a'];
                sum += cnt[cur];
            }
            ans.push_back(sum);
        }
        return ans;
    }
};
```

### Python（嵌套 dict，'#' 为计数键）

```python
class Solution:
    def sumPrefixScores(self, words: List[str]) -> List[int]:
        root = {}
        for w in words:                      # 阶段一：插入，沿路径计数
            cur = root
            for c in w:
                cur = cur.setdefault(c, {})
                cur['#'] = cur.get('#', 0) + 1

        ans = []
        for w in words:                      # 阶段二：查询，沿路径累加
            cur, s = root, 0
            for c in w:
                cur = cur[c]                 # 树已含全部单词，必存在
                s += cur['#']
            ans.append(s)
        return ans
```

## 8. 边界情况与易错点

1. **根节点不能计入**：根对应空前缀，题目只对非空前缀计分。`++cnt` 与 `sum += cnt` 都必须写在**下移之后**——先到目标节点再操作，根天然被跳过。写在下移之前会把每个答案统一多算 $n$。
2. **重复单词**：每次出现都使路径 `+1`，`cnt` 语义自动覆盖（示例 3 的 `["a","a","aa"]`），不要去重。
3. **同字符不同节点**：`"ab"` 的 `b` 与 `"b"` 的 `b` 是两个节点、两个 `cnt`。若误用「当前层 + 字符」做键的哈希表计数就会串扰——这正是必须用 Trie（或以完整前缀为键）的原因。
4. **先插完再查询**：查询依赖全体单词统计完的 `cnt`，两阶段不可合并；也不要在查询阶段新建节点。
5. **C++ 内存**：指针版约 $216\,\text{B}/节点 \times (10^6 + 1)$ 节点 $\approx 216\,\text{MB}$，可能 MLE；数组化 `array<int,26>` 版约 $110\,\text{MB}$，节点数按 $S + 1$ 预分配即可（每字符至多新建一节点，$tot \le S$，下标不越界）。
6. **查询无需判空**：所有 `words[i]` 都在树中，查询路径必存在；若判空反而掩盖建树 bug。
7. **溢出**：$\text{answer}[i] \le n \times L \le 10^6$，`int` 足够；但节点计数涉及 `S` 时记得用 `int` 而非枚举细节导致的隐式截断（Python 无此虑）。

**延伸思考**：

- **排序 + LCP 视角**：由 $\text{answer}[i] = \sum_j \text{LCP}(\text{words}[i], \text{words}[j])$（换序求和可得），将 `words` 排序后相邻串的 LCP 仅依赖字典序邻域，配合差分/单调栈同样能在 $O(N \cdot L)$ 内完成——与「子数组最小值之和」同构，可作为 Trie 解法的对照实现。
- **单词动态加入（流式查询）**：若单词逐个到来且每次插入后都要查询，Trie 的 `cnt` 支持在线更新（插入即维护），这正是 1804 封装的 `erase` / `countWordsStartingWith` 场景；若还要求可撤销，则需考虑可持久化 Trie。
