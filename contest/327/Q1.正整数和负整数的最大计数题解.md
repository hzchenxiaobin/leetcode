# LeetCode 正整数和负整数的最大计数 题解

## 1. 题目概述

- **标题 / 题号**：正整数和负整数的最大计数（#2529，easy）
- **链接**：https://leetcode.cn/problems/maximum-count-of-positive-integer-and-negative-integer/
- **来源**：LeetCode 第 327 场周赛 Q1
- **难度**：简单
- **标签**：数组、二分查找、计数

**题意**：给定按**非递减顺序**排列的整数数组 `nums`，记其中正整数数目为 $\text{pos}$、负整数数目为 $\text{neg}$（`0` 既非正也非负，不计入任何一侧），返回 $\max(\text{pos}, \text{neg})$。

**约束**：

- $1 \le \text{nums.length} \le 2000$
- $-2000 \le \text{nums[i]} \le 2000$
- `nums` 按非递减顺序排列

**进阶**：设计并实现时间复杂度 $O(\log n)$ 的算法。

> 💡 **签到题最短路径**：读完题应抓住两个信号——①题面白送「非递减」；②进阶明示 $O(\log n)$。二者叠加即条件反射：**有序数组 + 按值分段计数 → 二分定位边界**。比赛时先交线性版保底、再补二分版，或直接写二分版（同样只有三行）。

## 2. 示例

**示例 1**

```text
输入：nums = [-2,-1,-1,1,2,3]
输出：3
解释：负数 3 个（-2,-1,-1），正数 3 个（1,2,3），max(3,3) = 3
```

**示例 2**

```text
输入：nums = [-3,-2,-1,0,0,1,2]
输出：3
解释：负数 3 个（-3,-2,-1），正数 2 个（1,2），两个 0 不计入，max(3,2) = 3
```

**示例 3**

```text
输入：nums = [5,20,66,1314]
输出：4
解释：负数 0 个，正数 4 个，max(0,4) = 4
```

## 3. 解题思路

### 3.1 保底思路：一次遍历计数

```python
neg = pos = 0
for x in nums:
    if x < 0:   neg += 1
    elif x > 0: pos += 1
return max(neg, pos)
```

单趟扫描逐元素分类计数，时间 $O(n)$、空间 $O(1)$，在 $n \le 2000$ 下稳过，且没有任何边界风险——作为签到保底 submissions 是合理的。但它把「非递减」这个条件完全浪费了：答案只取决于两段长度，而升序让两段边界可以被二分直接定位，无需逐元素看。

### 3.2 核心观察：升序 → 负 / 零 / 正三段连续，两次二分定段长

![核心观察：升序数组按 0 切成负/零/正三段，两次二分定位边界](images/posneg_maxcount_concept.svg)

**关键直觉**：非递减数组可被值 $0$ 切成至多三段**连续区间**——负数段（$<0$）、零段（$=0$）、正数段（$>0$），三段左右排列互不交错。于是两侧个数 = 段长 = 边界下标之差，而边界可用二分在 $O(\log n)$ 内取得：

- $\text{neg} = \text{lower\_bound}(0)$：首个满足 $\text{nums}[i] \ge 0$ 的下标 $l$，其左侧恰好全是负数；
- $\text{pos} = n - \text{upper\_bound}(0)$：首个满足 $\text{nums}[i] > 0$ 的下标 $r$，其右侧恰好全是正数；
- 零段长 $= r - l$：`0` 被 $l$、$r$ 两界「夹」在中间，**天然不计入任何一侧**，无需特判。

> 💡 **为什么切分值取 0？** `0` 是正负的分界：负数 $<0$、零 $=0$、正数 $>0$。`lower_bound` 用 $\ge 0$ 划出「非负」起点，`upper_bound` 用 $>0$ 划出「正」起点——同一目标值、仅判定符号一字之差，即得两个边界，这正是标准库 `std::lower_bound` / `std::upper_bound` 与 Python `bisect_left` / `bisect_right` 的设计原意。

### 3.3 算法流程

![算法流程：两次独立二分 → 各取段长 → 取 max](images/posneg_maxcount_flow.svg)

1. 在升序 `nums` 上二分求 $l = \text{lower\_bound}(0)$（首个 $\ge 0$ 的下标），得 $\text{neg} = l$；
2. 二分求 $r = \text{upper\_bound}(0)$（首个 $> 0$ 的下标），得 $\text{pos} = n - r$；
3. 返回 $\max(\text{neg}, \text{pos})$。

两次二分**相互独立**（都直接对原数组、对值 0 查找），先后顺序无关。

### 3.4 示例演算

![示例演算：三个示例的分段、定位与计数](images/posneg_maxcount_walkthrough.svg)

重点走查唯一含 `0` 的例 2（`nums = [-3,-2,-1,0,0,1,2]`，$n = 7$）：

| 步骤 | 计算 | 结果 |
|------|------|------|
| $\text{lower\_bound}(0)$ | 首个 $\ge 0$ 的元素是下标 3 的 `0` | $l = 3 \Rightarrow \text{neg} = 3$ |
| $\text{upper\_bound}(0)$ | 首个 $> 0$ 的元素是下标 5 的 `1` | $r = 5 \Rightarrow \text{pos} = 7 - 5 = 2$ |
| 零段验证 | $r - l = 2$ 恰为两个 `0` | `0` 被夹住、两侧都不计入 |
| 取 max | $\max(3, 2)$ | 输出 `3` |

- **例 1**（无 0）：$l = r = 3$，零段为空，$\max(3, 3) = 3$；
- **例 3**（全正）：$l = r = 0$，$\text{neg} = 0$、$\text{pos} = 4 - 0 = 4$，答案 4。

## 4. 算法细节

1. **切分值取 0**：0 是「正 / 负」的分界。`0` 既满足 $\ge 0$（被挡在负段之外）、又不满足 $> 0$（被挡在正段之外），两侧各被一个二分边界排除，题目「`0` 不计入」的要求由构造自动满足。
2. **`lower` 与 `upper` 的一字之差**：同一目标值 0，谓词分别是 $\text{nums}[mid] \ge 0$ 与 $\text{nums}[mid] > 0$，收缩方向相同但停点不同——前者停在**首个非负**处（= 负段长），后者停在**首个正数**处（= 零段终点 + 1）。
3. **两次二分独立**：无数据依赖，复杂度 $O(\log n) + O(\log n) = O(\log n)$。
4. **空段由库语义兜底**：标准库二分的「插入点」语义保证返回值落在 $[0, n]$——全负时 $l = r = n$（$\text{neg} = n$、$\text{pos} = 0$），全正 / 全零时 $l = r = 0$ / $l = 0, r = n$，三种极端输入都无需特判。

## 5. 正确性证明

**引理 1（三段连续）**：设 `nums` 非递减，记 $L = \{i : \text{nums}[i] < 0\}$、$Z = \{i : \text{nums}[i] = 0\}$、$G = \{i : \text{nums}[i] > 0\}$，则存在整数 $0 \le l \le r \le n$ 使 $L = [0, l)$、$Z = [l, r)$、$G = [r, n)$。

**证明**：对任意 $i < j$ 有 $\text{nums}[i] \le \text{nums}[j]$。若 $j \in L$，即 $\text{nums}[j] < 0$，则 $\text{nums}[i] \le \text{nums}[j] < 0$，故 $i \in L$，说明 $L$ 是前缀；对称地，若 $i \in G$ 则 $\text{nums}[j] \ge \text{nums}[i] > 0$，故 $j \in G$，说明 $G$ 是后缀；$Z$ 夹在前缀与后缀之间必为连续区间。取 $l = |L|$、$r = n - |G|$ 即证。∎

**引理 2（边界下标即段长）**：$\text{lower\_bound}(0) = l = |L| = \text{neg}$，$\text{upper\_bound}(0) = r$，从而 $\text{pos} = |G| = n - r$。

**证明**：$\text{lower\_bound}(0)$ 返回满足 $\text{nums}[i] \ge 0$ 的最小下标。由引理 1，$[0, l)$ 全为负（不满足），$[l, n)$ 全为非负（满足），故该最小下标恰为 $l$。$\text{upper\_bound}(0)$ 返回满足 $\text{nums}[i] > 0$ 的最小下标；$[0, r)$ 全为 $\le 0$（不满足），$[r, n)$ 全为 $> 0$（满足），故恰为 $r$。∎

**定理**：算法返回 $\max(\text{pos}, \text{neg})$，且 `0` 不被计入任何一侧。

**证明**：由引理 2，`neg`、`pos` 分别等于负数、正数的真实个数；零段 $[l, r)$ 中的元素既不在 $[0, l)$（排除于 `neg`）也不在 $[r, n)$（排除于 `pos`），与「`0` 不计入」一致。两个整数取 $\max$ 即为所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\log n)$。两次相互独立的二分各 $O(\log n)$，取 max 为 $O(1)$；满足进阶要求。线性版为 $O(n)$。
- **空间复杂度**：$O(1)$。仅 `l`、`r` 与两个计数下标，二分为迭代实现不递归。

## 7. 参考代码

### C++（二分，$O(\log n)$）

```cpp
class Solution {
public:
    int maximumCount(vector<int>& nums) {
        int neg = lower_bound(nums.begin(), nums.end(), 0) - nums.begin();
        int pos = nums.end() - upper_bound(nums.begin(), nums.end(), 0);
        return max(neg, pos);
    }
};
```

> 💡 `lower_bound` 返回迭代器减 `begin()` 得负段长 $\text{neg}$；`end()` 减 `upper_bound` 迭代器即 $n - r$ 得正段长 $\text{pos}$。

### Python（bisect，$O(\log n)$）

```python
from bisect import bisect_left, bisect_right

class Solution:
    def maximumCount(self, nums: List[int]) -> int:
        neg = bisect_left(nums, 0)
        pos = len(nums) - bisect_right(nums, 0)
        return max(neg, pos)
```

> 💡 `bisect_left` ≡ `std::lower_bound`（首个 $\ge$ 目标），`bisect_right` ≡ `std::upper_bound`（首个 $>$ 目标）。

### 对照：线性版（$O(n)$，签到保底）

```python
class Solution:
    def maximumCount(self, nums: List[int]) -> int:
        return max(sum(x < 0 for x in nums), sum(x > 0 for x in nums))
```

## 8. 边界情况与易错点

1. **`0` 不计入任一侧**（题目明示）：含 0 时 $\text{pos} + \text{neg} < n$。例 2 的两个 `0` 是最直接的验证点。
2. **两侧必须一个用 left、一个用 right**：若写成 $\text{pos} = n - \text{bisect\_left}(0)$（把 0 计入正数）或 $\text{neg} = \text{bisect\_right}(0)$（把 0 计入负数），无 0 时碰巧正确，含 0 时答案偏大——这是本题唯一的「陷阱」。
3. **全负 / 全正 / 全零**：无需特判，插入点语义自动兜底，答案分别为 $n$、$n$、$0$。
4. **手写二分的两个坑**：谓词 $\ge$ 与 $>$ 写反等价于把 0 算进某一侧；`l < r` 还是 `l \le r` 的循环模板需与找不到时的返回端点核对。用库函数可完全避开。
5. **溢出无虞**：$n \le 2000$，计数与答案都不超 `int`，C++ 直接返回 `int` 安全。
6. **别忽略进阶**：$O(n)$ 线性版在数据规模下同样 AC，但本题的复盘价值正是「升序 ⇒ 可二分」的信号识别。
