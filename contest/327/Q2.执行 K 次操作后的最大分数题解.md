# LeetCode 执行 K 次操作后的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：执行 K 次操作后的最大分数（#2530，medium）
- **链接**：https://leetcode.cn/problems/maximal-score-after-applying-k-operations/
- **来源**：LeetCode 第 327 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）

**题意**：给定下标从 $0$ 开始的整数数组 `nums` 与整数 $k$，起始分数为 $0$。每步**操作**：任选一个下标 $i$，分数**增加** $\text{nums}[i]$，随后将 $\text{nums}[i]$ **替换**为 $\lceil \text{nums}[i]/3 \rceil$（向上取整）。返回**恰好执行 $k$ 次**操作后可获得的**最大分数**。$\lceil \text{val} \rceil$ 表示不小于 $\text{val}$ 的最小整数。

**约束**：

- $1 \le \text{nums.length},\ k \le 10^5$
- $1 \le \text{nums}[i] \le 10^9$

> 💡 本题另有[每日题解 2530](../../solution/2501-2600/2530_执行K次操作后的最大分数.md)，侧重「轨迹归约」的直觉铺陈与面试问答。本文作为周赛复盘，聚焦**赛场上从信号到代码的最短路径**（识别「反复取最大」→ 套堆模板）与**贪心正确性的引理-定理证明**，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [10,10,10,10,10], k = 5
输出：50
解释：对数组中每个元素各操作一次，分数 = 10 + 10 + 10 + 10 + 10 = 50。
```

**示例 2**

```text
输入：nums = [1,10,3,3,3], k = 3
输出：17
解释：
  第 1 步：选 i = 1，分数 +10，nums → [1,4,3,3,3]
  第 2 步：选 i = 1，分数 +4 ，nums → [1,2,3,3,3]
  第 3 步：选 i = 2，分数 +3 ，nums → [1,2,1,3,3]
  最终分数 = 10 + 4 + 3 = 17。
```

**示例 3（单元素反复削弱）**

```text
输入：nums = [9], k = 3
输出：13
解释：9 → ⌈9/3⌉ = 3 → ⌈3/3⌉ = 1，同一元素被连续取三次，分数 = 9 + 3 + 1 = 13。
```

## 3. 解题思路

### 3.1 暴力思路：每步线性扫描找最大

最朴素的实现：**每步线性扫一遍 `nums` 找最大值的下标，累加后原地写回 $\lceil v/3 \rceil$**，循环 $k$ 次。

设 $n = \text{nums.length}$，每步扫描 $O(n)$、共 $k$ 步，总复杂度 $O(n \cdot k)$。代入上限 $n = k = 10^5$ 约 $10^{10}$ 次比较，**严重超时**。

> ⚠️ 暴力暴露的结构：每一步都在「一群随时被改写的数里重新找当前最大」。这正是**大顶堆**的标准战场——把「找最大」从 $O(n)$ 摊到 $O(\log n)$。但注意本题与 331 场 Q1（2558 拿走礼物，题目硬性规定每秒取最多的一堆）不同：**下标任选**，「每步取最大」是一个需要证明的贪心策略，而非题面强制。先证贪心，再上堆。

### 3.2 核心观察：轨迹固定且非递增 → 每步取最大即最优

![核心观察：轨迹固定且非递增，最优 = 取最大的 k 个轨迹值；大顶堆 pop/push 恰好实现之](images/wc327_q2_heap_concept.svg)

把「顺序相关的过程」拆成「顺序无关的选择」，分三步：

1. **单元素轨迹固定**。对元素 $e$ 定义轨迹 $t_0(e) = e$、$t_{j+1}(e) = \lceil t_j(e)/3 \rceil$。无论你在第几步去取 $e$、中间是否穿插取别的元素，**第 $j+1$ 次取 $e$ 恒得 $t_j(e)$**——轨迹只数「$e$ 被取了几次」，与被取的时刻毫无关系。例如 $e = 10$：$t = (10, 4, 2, 1, 1, \ldots)$。
2. **总分只依赖每个元素的被取次数**。设元素 $e$ 共被取 $c_e$ 次（$\sum_e c_e = k$），则总分

   $$\text{score} = \sum_e \sum_{j=0}^{c_e - 1} t_j(e)，$$

   即每个元素贡献其轨迹的一段**前缀和**。问题化为：在所有轨迹值 $\{t_j(e)\}$ 中选 $k$ 个使总和最大，但须满足**前缀约束**——选了 $t_j(e)$ 就必须也选 $t_0(e), \ldots, t_{j-1}(e)$。
3. **非递增让前缀约束自动满足**。轨迹单调不增（引理 2），若 $t_j(e)$ 有资格入选前 $k$ 大，则比它更大的 $t_0(e) \ldots t_{j-1}(e)$ 没有理由落选（若落选，用它们替换只会更优）。于是

   **最优解 = 全体轨迹值中最大的 $k$ 个之和。**

而「每步取当前最大」恰好逐个取出这最大的 $k$ 个轨迹值——这正是大顶堆每轮 `pop` 堆顶干的事。

### 3.3 算法流程

![算法流程：建大顶堆 O(n) → k 轮「pop v、score+=v、push ⌈v/3⌉」→ 返回](images/wc327_q2_heap_flow.svg)

1. **建堆**：把 `nums` 全部装入大顶堆——C++ 用 `priority_queue<int>` 迭代器区间构造（底层 Floyd 建堆 $O(n)$）；Python 的 `heapq` 是小顶堆，**存 $-x$ 后 `heapify`** 模拟；
2. 循环 $k$ 次：弹出堆顶 $v$（当前最大）；
3. `score += v`；再把 $\lceil v/3 \rceil$ 压回堆中；
4. $k$ 轮结束后返回 `score`。

> 💡 **向上取整的整数写法**：$v \ge 1$ 时 $\lceil v/3 \rceil = (v+2)/3$（整数除法向下取整）。验证：$10 \to 4$、$4 \to 2$、$3 \to 1$、$1 \to 1$。当 $v = 1$ 时压回的仍是 $1$，堆**永不空**，$k$ 轮循环始终有元素可取。

### 3.4 示例演算

![示例 2 逐步演算：弹出 10/4/3，回写 4/2/1，score 到 17](images/wc327_q2_walkthrough.svg)

以示例 2 为例（红 = 弹出累加，绿 = 削弱回堆）：

| 步 | 取出 $v$ | score | push $\lceil v/3 \rceil$ | 堆内剩余（降序） |
|----|----------|-------|---------------------------|------------------|
| 初始 | — | 0 | — | $\{10, 3, 3, 3, 1\}$ |
| 1 | 10 | 10 | 4 | $\{4, 3, 3, 3, 1\}$ |
| 2 | 4 | 14 | 2 | $\{3, 3, 3, 2, 1\}$ |
| 3 | 3 | 17 | 1 | $\{3, 3, 2, 1, 1\}$ |

$$\text{score} = 10 + 4 + 3 = 17 \ \checkmark$$

> 💡 第 1 步取 $10$ 后回写 $4$，此时 $4$ 比 $3$ 大，第 2 步堆自动改弹 $4$ 而非 $3$——「当前最大」始终由堆维护，无需任何手动判断。第 3 步堆顶是 $3$（三个并列，任取其一），回写 $\lceil 3/3 \rceil = 1$。整个过程与官方操作序列一一对应。

## 4. 算法细节

1. **建堆 $O(n)$**：C++ `priority_queue<int> pq(nums.begin(), nums.end())` 区间构造（Floyd 自底向上建堆），优于逐个 `push` 的 $O(n \log n)$；Python `[-x for x in nums]` 后 `heapq.heapify` 原地建堆。
2. **Python 大顶堆套路**：`heapq` 只提供小顶堆，**存 $-x$**——`heappop` 弹出最小（最负）即原数最大，取反还原。这是 Python 堆题的标配写法。
3. **$\lceil v/3 \rceil$ 用整数式 $(v+2)/3$**：不要写 `v/3`（整数除法是**向下**取整，$\lfloor 10/3 \rfloor = 3 \ne 4$，直接 WA）；也不要用浮点 `ceil(v/3)`（大数有精度风险）。Python 同理用 `(v + 2) // 3`。
4. **64 位累加**：最坏每步取 $10^9$、共 $k = 10^5$ 步，$\text{score} \approx 10^{14}$，远超 32 位有符号 `int` 上界（$\approx 2.1 \times 10^9$）。C++ 的 `score` 与返回值必须 `long long`（单个 $v \le 10^9$ 用 `int` 装即可）；Python 整数任意精度，无此忧。
5. **堆大小恒为 $n$**：每轮一弹一压净增为 $0$，空间稳定 $O(n)$；$k$ 可以大于 $n$（同一元素被反复取，示例 3），循环照常以 $k$ 计数。

## 5. 正确性证明

**引理 1（轨迹不变性）**：任一合法操作序列中，元素 $e$ 第 $j+1$ 次被选中时，分数增量恰为 $t_j(e)$（$t_0(e)=e$，$t_{j+1}(e)=\lceil t_j(e)/3\rceil$），与它在第几步被选、中间选了哪些别的元素无关。

**证明**：对操作步数归纳。$e$ 每被选中一次，其当前值就经历一次映射 $x \mapsto \lceil x/3 \rceil$；未被选中时值不变。故第 $j+1$ 次被选中时，其值恰为该映射复合 $j$ 次的结果 $t_j(e)$，增量即 $t_j(e)$。复合次数只依赖「$e$ 被选中的总次数」，与选择发生的时刻无关。∎

**引理 2（非递增与不动点）**：对一切 $v \ge 1$，有 $\lceil v/3 \rceil \le v$，且 $v \ge 2$ 时 $\lceil v/3 \rceil < v$；$v = 1$ 时 $\lceil 1/3 \rceil = 1$ 为不动点。从而每条轨迹非递增，且落到 $1$ 后恒为 $1$。

**证明**：$v \ge 1$ 时 $\lceil v/3 \rceil \le \frac{v+2}{3} \le v$（后者等价于 $v + 2 \le 3v$，即 $v \ge 1$）。当 $v \ge 2$ 时 $\frac{v+2}{3} < v \iff 2 < 2v \iff v > 1$，故严格下降；$v = 1$ 时 $\lceil 1/3 \rceil = 1$。∎

**引理 3（计数归约）**：一组非负整数 $\{c_e\}$（$\sum_e c_e = k$）恰好给出一个可实现的「被取次数」方案，且该方案的分数为 $\sum_e \sum_{j=0}^{c_e-1} t_j(e)$；反之每个合法操作序列都对应这样一组 $\{c_e\}$。

**证明**：（可实现性）把「取 $e$」共 $c_e$ 次按任意顺序排入 $k$ 步即得合法序列；由引理 1，无论怎样排列，分数都是各元素轨迹前缀 $c_e$ 项之和。（反方向）合法序列中每个元素被取的次数自然构成一组满足 $\sum c_e = k$ 的非负整数。∎

**定理（贪心最优性）**：最大分数等于全体轨迹值 $\{t_j(e) : e \in \text{nums},\ j \ge 0\}$ 中最大的 $k$ 个之和；「每步取当前最大」的堆算法恰好取得该值。

**证明**：分三点。

（i）**上界**：由引理 3，任何合法策略的分数都是 $k$ 个轨迹值之和，而任意 $k$ 个值之和不大于全局最大的 $k$ 个值之和（排序不等式），故后者是一切策略的上界。

（ii）**上界可达**：设 $S^*$ 为按降序排列取出的前 $k$ 大轨迹值（并列时任取）。若 $S^*$ 违反前缀约束，即存在 $t_i(e) \in S^*$、$j < i$ 且 $t_j(e) \notin S^*$，由引理 2 知 $t_j(e) \ge t_i(e)$；将 $t_i(e)$ 替换为 $t_j(e)$，集合仍是 $k$ 个轨迹值，总和不减（结合（i）知不变），且势函数 $\Phi = \sum_{t_i(e) \in S} i$ 严格减小。$\Phi$ 非负整数、有限步内必终止，终止时得到满足前缀约束、总和仍达上界的选择。由引理 3，它对应一个可实现的操作方案，故上界可达。

（iii）**堆算法实现之**：归纳证明循环不变量——每轮开始时，堆中恰存放每个元素的「下一个未取轨迹值」（已取走的不在堆中）。初始堆 $= \{t_0(e)\} = \text{nums}$，成立。每轮弹出堆顶 $v$：$v$ 是所有「下一个轨迹值」的最大者；而每个元素更后面的轨迹值不超过其下一个值（引理 2），故 $v$ 即**全体剩余轨迹值的最大者**，也就是第 $s$ 大轨迹值（$s$ 为当前轮数，并列时顺序无关）。压回 $\lceil v/3 \rceil$ 恰是把该元素的「下一个轨迹值」指针前移一位，不变量保持。故 $k$ 轮取出的恰是最大的 $k$ 个轨迹值，得分达上界。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k \log n)$。Floyd 建堆 $O(n)$；$k$ 轮循环各一弹一压，每次堆调整 $O(\log n)$。代入 $n, k \le 10^5$ 约 $10^5 + 10^5 \times 17 \approx 1.8 \times 10^6$，毫秒级。
- **空间复杂度**：$O(n)$。堆存全部 $n$ 个元素（每轮弹一压一，大小恒为 $n$），另有常数个标量。
- **对照暴力**：$O(n \cdot k) \approx 10^{10}$，超时约三个数量级；「每步重新排序」更差（$O(k \cdot n \log n)$），且初始序在第一次削弱后即被破坏，毫无意义。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxKelements(vector<int>& nums, int k) {
        priority_queue<int> pq(nums.begin(), nums.end()); // 大顶堆，O(n) 建堆
        long long score = 0;
        while (k-- > 0) {
            int v = pq.top();
            pq.pop();
            score += v;                      // 64 位累加
            pq.push((v + 2) / 3);            // ⌈v/3⌉；v = 1 时仍回 1，堆不空
        }
        return score;
    }
};
```

> 💡 返回类型 `long long`：最坏 $k \cdot 10^9 \approx 10^{14}$ 超 32 位 `int` 上界。`priority_queue` 的迭代器区间构造是 Floyd 建堆 $O(n)$，比逐个 `push` 更优。

### Python

```python
class Solution:
    def maxKelements(self, nums: List[int], k: int) -> int:
        heap = [-x for x in nums]      # 取负模拟大顶堆
        heapq.heapify(heap)            # 原地建堆 O(n)
        score = 0
        for _ in range(k):
            v = -heapq.heappop(heap)   # 弹出当前最大
            score += v
            heapq.heappush(heap, -((v + 2) // 3))   # ⌈v/3⌉ 取负回堆
        return score
```

> 💡 Python 无内置大顶堆，**取负 + `heapq`** 是标准套路。`(v + 2) // 3` 对正整数 $v$ 等价于 $\lceil v/3 \rceil$，注意整除用 `//`。两版逻辑等价，均 $O(n + k \log n)$ 时间、$O(n)$ 空间。

## 8. 边界情况与易错点

1. **溢出（最大坑）**：$\text{score}$ 最坏 $k \times 10^9 \approx 10^{14}$，超出 32 位 `int`。C++ 累加变量与返回值必须 `long long`；Python 整数任意精度无此忧。
2. **向上取整写错**：`(v + 2) / 3` 才是 $\lceil v/3 \rceil$；写成 `v / 3`（向下取整，$10 \to 3$ 而非 $4$）直接 WA；用浮点 `ceil(v / 3)` 有精度风险。
3. **削弱后必须放回**：被取的元素变小后继续参与后续竞争，不是删除。误写成「弹出后不压回」或「先取 $k$ 个最大再各自削弱一次」都会 WA——前者丢元素，后者错误地限制每个元素至多被操作一次。
4. **排序一次从头取行不通**：取走最大并削弱后，新值可能落到序列中段，初始有序被破坏；「动态有序集 + 反复取极值 + 改值回插」正是堆封装好的三件事。
5. **$k > n$ 合法**：同一元素可被反复取（示例 3：$[9]$ 取三次得 $9+3+1$）；$v$ 到 $1$ 后弹 $1$ 压 $1$、循环空转，本题 $k \le 10^5$ 无所谓。若 $k$ 大到 $10^9$，应在堆顶降为 $1$ 时提前退出（堆顶是全局最大，它为 $1$ 则全体为 $1$），剩余步数直接 `+1` 累计。
6. **别忽略「恰好 $k$ 次」**：即使所有元素都降到 $1$ 也必须做满 $k$ 次（每次 $+1$），不能提前停——分数是累加的，多做不少赚，但题目要求恰好 $k$ 次，少做是错的。
