# LeetCode 过桥的时间 题解

## 1. 题目概述

- **标题 / 题号**：过桥的时间（#2532，hard）
- **链接**：https://leetcode.cn/problems/time-to-cross-a-bridge/
- **来源**：LeetCode 第 327 场周赛 Q4
- **难度**：困难
- **标签**：数组、模拟、堆（优先队列）

**题意**：$k$ 位工人要把 $n$ 个箱子从**右岸旧仓库**搬到**左岸新仓库**，两仓库隔河相望，仅一座桥通行。第 $i$ 位工人的四段耗时为 $\text{time}[i] = [\text{right}_i,\ \text{pick}_i,\ \text{left}_i,\ \text{put}_i]$：左→右过桥 $\text{right}_i$、在旧仓库搬箱并回到桥边 $\text{pick}_i$、右→左过桥 $\text{left}_i$、在新仓库放箱并回到桥边 $\text{put}_i$。开始时所有工人都在左岸。过桥规则：桥同一时刻仅容一人；桥空闲时**优先让右岸效率最低的工人（已搬起箱子的）过桥**，若右岸无人再让左岸效率最低的工人过桥；若左岸已派出足以拾取所有剩余箱子的工人，则不再从左岸派人。工人 $i$ **效率低于** $j$ 定义为 $\text{left}_i + \text{right}_i > \text{left}_j + \text{right}_j$，或二者相等且 $i > j$。求最后一个箱子**到达桥左侧**的时刻（放箱时间不计入）。

**约束**：

- $1 \le n,\ k \le 10^4$
- `time.length == k`，`time[i].length == 4`
- $1 \le \text{left}_i,\ \text{pick}_i,\ \text{right}_i,\ \text{put}_i \le 1000$

> 💡 **赛场信号**：题面给的是一套**完整确定的调度规则**（右侧优先、效率最低者先行、派出封顶），而不是让我们自己找最优策略——这是「按规则模拟」题，不需要证明任何策略最优性，只需要**忠实执行**。数据范围 $n, k \le 10^4$ 意味着必须**事件驱动**而非逐分钟推进；「效率最低者优先」与「最早完成者先回收」天然对应**四个优先队列**加一条独占资源。

> 💡 本题另有[每日题解 2532](../../solution/2501-2600/2532_过桥的时间.md)，侧重「事件驱动直觉与面试问答」。本文作为周赛复盘，聚焦**从信号到代码的最短路径**、**派出上限的等价刻画**与**模拟等价性的引理-定理证明**，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：逐分钟推进时钟

让墙钟一分钟一分钟地走，每分钟检查桥是否空闲、谁在桥边等待、谁搬/放完毕，按规则放行。单次过桥最长 $2000$ 分钟，$n \le 10^4$ 个箱子各自一个往返，总时长 $T$ 上界约 $n(\text{right}+\text{left}) + 2n\max(\text{pick},\text{put}) \approx 4 \times 10^7$ 分钟。C++ 里 $O(1)/$ 分钟的空转循环勉强能跑，Python 必然超时；若每分钟还线性扫一遍 $k$ 个工人找就绪者，就是 $4 \times 10^7 \times 10^4 = 4 \times 10^{11}$，任何语言都不可行。

> ⚠️ 暴力暴露的浪费：绝大多数分钟里**桥正被占用**或**桥口根本无人**，时间在纯空转。系统的真实变化只发生在两类事件上——「一次过桥完成」「一名工人搬/放完毕」。用事件驱动把空转全部跳过，复杂度就从 $O(T)$ 降到 $O(n \log k)$。

### 3.2 核心观察：四个集合 + 事件驱动

![过桥问题模型：左岸右岸各配一个等待堆与一个工作堆，桥是唯一串行资源](images/wc327_q4_scene.svg)

**观察 1（六状态循环）**：每个工人任意时刻恰处于六种状态之一——左岸等待 →（过桥 L→R）→ 搬箱中 → 搬完右岸等待 →（过桥 R→L）→ 放箱中 → 放完回到左岸等待。前者的「等待」与后者的「工作」互不占用桥。

**观察 2（桥是唯一串行资源）**：搬箱、放箱完全并行，**不参与排队**，只需记录「何时完成」。因此系统只需四个集合：

| 集合 | 语义 | 堆序 |
|------|------|------|
| `waitL` | 左岸桥边等待的工人 | 效率最低者在顶：键 $(\text{left}+\text{right},\ i)$ 大者优先 |
| `waitR` | 右岸桥边等待（已搬起箱）的工人 | 同上 |
| `workR` | 右岸搬箱中的工人 | 完成时刻最早在顶：小根堆 $(\text{finish},\ i)$ |
| `workL` | 左岸放箱中的工人 | 同上 |

**观察 3（决策点只有「桥空闲」时刻）**：两次过桥之间系统只在「工作完成」事件处变化。当桥口两个等待堆都空（或左岸等待者因派出封顶不能走）时，把时钟直接**快进**到两个工作堆顶的较早完成时刻，跳过全部空转。

**观察 4（派出上限的口径）**：每次 L→R 过桥的工人**必搬起一只箱子**，所以「已派出足够拾取所有剩余箱子的工人」$\iff$ L→R 过桥总次数达到 $n$。于是只需一个计数器 `sent`（已 L→R 过桥的次数），仅当 `sent < n` 时才允许从左岸放行（§5 引理 3 给出证明）。

> 💡 过桥顺序不影响过桥段总时长（串行资源长度固定），只影响「谁更早回到等待集合」——「低效者先行」是题目指定的确定策略，照做即可，不必纠结其动机。

### 3.3 算法流程

![桥口调度流程：右岸优先、左岸派出封顶、否则快进时钟](images/wc327_q4_bridge_dispatch.svg)

```text
waitL ← 全部 k 位工人（效率最低者在堆顶），其余三个堆为空
cur = sent = arrived = ans = 0
while arrived < n:
    若 waitR 空 且 (waitL 空 或 sent == n):      # 桥口无人可放行
        cur = max(cur, min(workL 堆顶, workR 堆顶))  # 快进到最近完成事件
    收集 workL / workR 中 finish ≤ cur 的工人 → waitL / waitR
    若 waitR 非空:                               # 右岸绝对优先
        w ← waitR 堆顶（效率最低者）
        cur += left_w；ans = cur；arrived++
        w 入 workL（finish = cur + put_w）
    否则若 waitL 非空 且 sent < n:               # 派出未满
        w ← waitL 堆顶（效率最低者）
        cur += right_w；sent++
        w 入 workR（finish = cur + pick_w）
return ans
```

三个要点：**回收必须每轮决策前无条件执行**（哪怕刚过完桥，也要先把完成者收进等待堆，否则漏掉右侧优先权）；**快进目标取两个工作堆顶的最小值**且 `cur` 只进不退；`ans` 只在 R→L 完成时更新，天然不含最后的 `put`。

### 3.4 示例演算

![示例 2 的三泳道时间线：桥的占用段、搬箱放箱的并行段与三次快进](images/wc327_q4_walkthrough.svg)

以**示例 2**（$n=3$，$k=2$，`time = [[1,5,1,8],[10,10,10,10]]`）演算。效率键：$w_0$ 的 $1+1=2$、$w_1$ 的 $10+10=20$，故 $w_1$ 效率更低、首轮先行：

| cur | 动作 | 说明 |
|-----|------|------|
| 0 | 派 $w_1$ L→R（10 分钟） | 效率最低者先行 |
| 10 | 派 $w_0$ L→R（1 分钟） | 右岸无人就绪，sent $=2$ |
| 11 | 桥口无人 → **快进到 16** | $\min(w_0\ \text{搬完}\ 16,\ w_1\ \text{搬完}\ 20) = 16$ |
| 16 | $w_0$ R→L（1 分钟） | 右岸优先：$w_0$ 搬完就绪立即过桥 |
| 17 | 第 1 箱到左，ans $=17$ | $w_0$ 放箱（17→25）；快进到 20 |
| 20 | $w_1$ R→L（10 分钟） | $w_1$ 搬完就绪，右岸优先立即过桥 |
| 30 | 第 2 箱到左，ans $=30$ | $w_1$ 放箱（30→40）；$w_0$ 早在 25 已回左岸等待 |
| 30 | 派 $w_0$ L→R（1 分钟），sent $=3$ | 右岸无人、sent $=2<3$，放行 |
| 36 | $w_0$ 搬完（31+5）→ R→L | 快进到 36 后立即过桥 |
| 37 | 第 3 箱到左，ans $=37$ | 最后的 put 不计入，返回 37 |

整个过程桥的占用段为 $[0,10], [10,11], [16,17], [20,30], [30,31], [36,37]$，恰 $2n = 6$ 段；三次空闲区间全部被快进跳过。

## 4. 算法细节

1. **堆键设计**：`waitL` / `waitR` 按「效率最低在顶」——和越大越先出、平局下标越大越先出，C++ 比较器返回 `sa < sb`（和小的优先级低），Python 存负键 $(-(\text{left}+\text{right}),\ -i)$ 用小根堆模拟。`workL` / `workR` 按「完成时刻最早在顶」的小根堆，键 $(\text{finish},\ i)$。
2. **`sent` 的口径是 L→R 过桥总次数**：每次派出必对应搬起一只箱子，故 `sent < n` 等价于题面的「派出还未覆盖剩余箱子」（§5 引理 3）。它也等价于每日题解采用的 `inflight < n − picked` 口径（`inflight + picked` 即 `sent`），两种写法互为印证。
3. **回收无条件执行**：放在每轮循环「快进判断之后、过桥决策之前」，把所有 $\text{finish} \le \text{cur}$ 的工人一次性收进等待堆。若只在快进分支里回收，刚结束一次长过桥时（`cur` 已越过若干完成时刻）会漏收右侧就绪者、错判右岸优先。
4. **快进防回退**：完成时刻可能早于刚结束的过桥终点（例：桥上走了 10 分钟、岸上 5 分钟就搬完了），故写 `cur = max(cur, t)` 而非 `cur = t`。
5. **`ans` 无需取 max**：`cur` 单调不减，最后一次 R→L 过桥的终点即最大到达时刻；`arrived == n` 立即结束，最后一段 `put` 自然被排除。
6. **工人只存下标**：效率键现算（`time[i][0] + time[i][2]`）即可，$k \le 10^4$ 无任何性能压力。

## 5. 正确性证明

**引理 1（状态完备性）**：任一时刻每个工人恰处于「左岸等待、过桥→右、搬箱、右岸等待、过桥→左、放箱」六状态之一；时钟 `cur`、四个堆的内容、`sent` 与 `arrived` 完全决定系统的后续演化。

**证明**：题面强制每人的动作序列为「过桥→取箱→回桥边→过桥→放箱→回桥边」循环，无其他动作；六状态按「正在做的动作 / 在桥边排队」二分，互斥且覆盖全部情形。所有状态转移仅由「当前过桥完成」与「某工人搬/放完成」触发，二者均被 `cur` 与堆顶 `finish` 记录。∎

**引理 2（过桥次数守恒）**：全过程恰发生 $n$ 次 L→R 过桥与 $n$ 次 R→L 过桥，每个箱子恰由一次 R→L 过桥带到左岸。

**证明**：向右过桥者必搬起一只箱（题面动作序列），随后必以 R→L 携箱返回，故 `arrived` 每次 R→L 恰加 1，且 L→R 次数 = R→L 次数 = 已被搬运的箱子数（每个箱子的搬运是一个完整循环）。派出封顶使 L→R 至多 $n$ 次，故 R→L 亦至多 $n$ 次。另一方面 `arrived < n` 时循环不终止：`waitR` 非空则有人即将携箱返回；`waitR` 空而 `waitL` 非空且 `sent < n` 则派新工人；二者皆不可行时已派出未到达的箱子必在被搬运中（`workR` 非空），快进后终将有人就绪。故 R→L 恰进行 $n$ 次。∎

**引理 3（派出上限的等价刻画）**：规则「左岸已派出足够拾取所有剩余箱子的工人则不再派人」等价于「仅当 `sent` $< n$ 时允许 L→R 过桥」。

**证明**：每次派出恰取一只箱，故已派出的 `sent` 人最终取走 `sent` 只箱。设已被取走 $p$ 只，剩余 $n - p$ 只，已派出未取完者 `sent` $- p$ 人。「足够」即 `sent` $- p \ge n - p$，化简即 `sent` $\ge n$。∎

**引理 4（快进不变性）**：设某决策时刻桥空闲、`waitR` 空且（`waitL` 空或 `sent` $=n$），令 $t$ 为两个工作堆顶完成时刻的较小者，则 $[\text{cur},\ t)$ 内无任何工人就绪、桥保持空闲；将时钟快进到 $\max(\text{cur},\ t)$ 并回收 $\text{finish} \le \text{cur}$ 的工人，不改变此后任何过桥的执行者与时刻。

**证明**：回收每轮决策前已做完，故两个等待堆刻画的就绪集合在 $[\text{cur},\ t)$ 内为空，桥上亦无人（本分支仅在桥空闲时进入），区间内无事件发生，快进只跳过空转。回收把「本应按时就绪」的工人全部就位；若其真实就绪时刻早于 `cur`，则 $[\text{就绪},\ \text{cur})$ 内桥要么空闲（无决策点）、要么被上一次过桥占用（本就不做决策），延迟到 `cur` 处理不改变任何决策。∎

**定理（模拟等价与终止性）**：模拟恰按题面规则执行每一次过桥，并在最后一个箱子到达桥左侧时返回该时刻。

**证明**：对过桥次数归纳。每轮迭代中：(i) `waitR` 非空时规则要求右岸效率最低者先行——堆序使「和最大、平局下标最大」者在顶，恰为效率最低的定义；(ii) `waitR` 空且 `waitL` 非空且 `sent` $< n$ 时同理放行左岸效率最低者，`sent` $< n$ 的合法性由引理 3 保证；(iii) 二者皆不可行时由引理 4，快进不改变任何后续事件。故每次过桥的执行者与时刻与按题面逐步推演一致。终止性：过桥恰 $2n$ 次（引理 2）；每个非过桥迭代至少回收一名工人，而工作堆压入总量为 $2n$（$n$ 次搬箱 + $n$ 次放箱），故总迭代 $O(n)$。`ans` 记录每次 R→L 的完成时刻且 `cur` 单调不减，循环结束时 `arrived` $= n$，`ans` 即最后一次 R→L 的完成时刻——最后箱子到达桥左侧的时刻，不含最后的 `put`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log k)$。过桥事件恰 $2n$ 个，每次过桥涉及等待堆弹出与工作堆压入各 $O(\log k)$；非过桥迭代每轮至少回收一名工人、回收总量 $2n$，均摊后每个事件 $O(\log k)$。代入 $n = k = 10^4$ 约 $2 \times 10^4 \times 14$ 次堆操作，毫秒级。
- **空间复杂度**：$O(k)$。四个堆合计恰容纳全部工人（任一时刻每人在且在一个堆里），另有常数个计数器。
- **对照逐分钟暴力**：$O(T)$（$T \le 4 \times 10^7$，Python 不可行）；若每分钟再扫描 $k$ 个工人则 $O(Tk) \approx 4 \times 10^{11}$，任何语言都不可行——事件驱动是唯一出路。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findCrossingTime(int n, int k, vector<vector<int>>& time) {
        // 效率键：left+right 越大越低效；同和时下标越大越低效。
        // 比较器返回 true 表示 a 的优先级低于 b（更晚出堆）。
        auto cmp = [&](int a, int b) {
            int sa = time[a][0] + time[a][2], sb = time[b][0] + time[b][2];
            if (sa != sb) return sa < sb;
            return a < b;
        };
        priority_queue<int, vector<int>, decltype(cmp)> waitL(cmp), waitR(cmp);
        using P = pair<int, int>;                          // (完成时刻, 工人)
        priority_queue<P, vector<P>, greater<P>> workL, workR;
        for (int i = 0; i < k; ++i) waitL.push(i);

        int cur = 0, sent = 0, arrived = 0, ans = 0;
        while (arrived < n) {
            if (waitR.empty() && (waitL.empty() || sent == n)) {  // 桥口无人可放行
                int t = INT_MAX;
                if (!workL.empty()) t = min(t, workL.top().first);
                if (!workR.empty()) t = min(t, workR.top().first);
                cur = max(cur, t);                                // 快进，防回退
            }
            while (!workL.empty() && workL.top().first <= cur) {  // 无条件回收
                waitL.push(workL.top().second); workL.pop();
            }
            while (!workR.empty() && workR.top().first <= cur) {
                waitR.push(workR.top().second); workR.pop();
            }
            if (!waitR.empty()) {                                // 右岸绝对优先
                int w = waitR.top(); waitR.pop();
                cur += time[w][2];                               // left
                ans = cur; ++arrived;
                workL.push({cur + time[w][3], w});               // 之后放箱 put
            } else if (!waitL.empty() && sent < n) {             // 派出未满
                int w = waitL.top(); waitL.pop();
                cur += time[w][0];                               // right
                ++sent;
                workR.push({cur + time[w][1], w});               // 之后搬箱 pick
            }
        }
        return ans;
    }
};
```

> 💡 `priority_queue` 默认大根堆，配合比较器「和小的优先级低」即得「效率最低者在顶」。工人只存下标，效率键入堆时现算。

### Python

```python
import heapq
from typing import List


class Solution:
    def findCrossingTime(self, n: int, k: int, time: List[List[int]]) -> int:
        def key(i: int) -> tuple:          # 效率最低者在堆顶
            return (-(time[i][0] + time[i][2]), -i)

        waitL = [key(i) for i in range(k)]
        heapq.heapify(waitL)
        waitR, workL, workR = [], [], []   # work* 存 (完成时刻, 工人)

        cur = sent = arrived = ans = 0
        while arrived < n:
            if not waitR and (not waitL or sent == n):      # 桥口无人可放行
                ts = []
                if workL:
                    ts.append(workL[0][0])
                if workR:
                    ts.append(workR[0][0])
                cur = max(cur, min(ts))                      # 快进，防回退
            while workL and workL[0][0] <= cur:              # 无条件回收
                _, i = heapq.heappop(workL)
                heapq.heappush(waitL, key(i))
            while workR and workR[0][0] <= cur:
                _, i = heapq.heappop(workR)
                heapq.heappush(waitR, key(i))
            if waitR:                                        # 右岸绝对优先
                _, ni = heapq.heappop(waitR)
                i = -ni
                cur += time[i][2]
                ans = cur
                arrived += 1
                heapq.heappush(workL, (cur + time[i][3], i))  # 之后放箱 put
            elif waitL and sent < n:                         # 派出未满
                _, ni = heapq.heappop(waitL)
                i = -ni
                cur += time[i][0]
                sent += 1
                heapq.heappush(workR, (cur + time[i][1], i))  # 之后搬箱 pick
        return ans
```

> 💡 `heapq` 是小根堆，存 $(-(\text{left}+\text{right}),\ -i)$ 后堆顶即效率最低者。**弹出后必须把 $-i$ 取反恢复下标**——Python 的负下标会静默绕回成别的工人，出错不报异常（见 §8 第 10 条）。

## 8. 边界情况与易错点

1. **效率只含 $\text{left}+\text{right}$**：`pick` / `put` 完全不参与效率比较，只进工作堆的时间键。把四项全加进排序键是最常见的阅读陷阱。
2. **平局方向**：和相等时**下标大者**效率更低（$i > j$）。堆键务必放 $-i$（或比较器写 `a < b`）。自构造示例 3 里方向搞反答案从 3 变 102。
3. **右岸绝对优先**：只要 `waitR` 非空，哪怕左岸有更早到桥边、更高效的工人，也先让右岸最低效者过。先查 `waitR` 再查 `waitL`，顺序不能反。
4. **派出上限的口径**：是「L→R 过桥总次数 `sent` $< n$」，不是「右岸等待人数」「剩余箱数减右岸人数」之类的其他口径。它与每日题解的 `inflight < n − picked` 完全等价，可互为自检。
5. **回收必须每轮无条件做**：放在快进判断之后、过桥决策之前。若只在快进分支里回收，长过桥结束后刚搬完的右岸工人会被漏掉，错失右侧优先权。
6. **快进防回退**：完成时刻可能早于刚结束的过桥终点，写 `cur = max(cur, t)` 而非 `cur = t`；$t$ 取两个工作堆顶的**最小值**（要的是最早的下一个事件）。
7. **答案不含最后的 `put`**：`arrived == n` 即返回；同时**前 $n-1$ 次的 `put` 必须模拟**——它决定工人何时重回左岸待发（示例 2 中 $w_0$ 正是靠 25 分钟放完才赶上 30 分钟的再派出）。
8. **时间上限约 $4 \times 10^7$**：$n = 10^4$、四项全 $1000$ 时答案为 $39\,999\,000$，`int` 毫无溢出风险；但这个量级正是逐分钟暴力不可行的原因。
9. **$k > n$**：多出的工人因 `sent` 封顶永远不会被派出，无需特判，规则自然如此。
10. **Python 负下标静默绕回**：堆里存 $-i$，弹出后忘取反的话 `time[-3]` 会读到 `time[k-3]`——另一个真实存在的工人，程序不报错但结果全错。本篇代码在两处弹出后立即 `i = -ni`。
