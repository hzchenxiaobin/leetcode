# LeetCode 找出 3 位偶数 题解

## 1. 题目概述

- **标题 / 题号**：找出 3 位偶数（#2094，easy）
- **链接**：https://leetcode.cn/problems/finding-3-digit-even-numbers/
- **来源**：LeetCode 第 270 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、枚举、排序

**题意**：给定整数数组 `digits`（每个元素是 0-9 的数字，**可能重复**），找出**所有**满足下列条件且**互不相同**的整数：

1. 由 `digits` 中的三个元素按**任意顺序**依次连接组成（每个元素的使用次数不超过其在数组中的出现次数）；
2. **不含前导零**；
3. 是**偶数**。

结果按**递增顺序**排列，以数组形式返回。

**约束**：

- $3 \le \text{digits.length} \le 100$
- $0 \le \text{digits}[i] \le 9$ —— 值域仅 10，频次表可定长寻址（见 §4）

> 💡 作为签到题，最短路径是：**别从输入拼答案，直接枚举答案值域**。三位偶数只有 $[100, 998]$ 步长 2 共 450 个候选，用一个长度 10 的频次表逐一验证即可。「互不相同」「递增」两个输出要求被枚举方向**天然满足**，不需要 `set` 也不需要 `sort`。

## 2. 示例

**示例 1**

```text
输入：digits = [2,1,3,0]
输出：[102,120,130,132,210,230,302,310,312,320]
解释：所有满足题目条件的整数都在输出数组中列出。
      注意，答案数组中不含有奇数或带前导零的整数。
```

**示例 2（重复数字的频次语义）**

```text
输入：digits = [2,2,8,8,2]
输出：[222,228,282,288,822,828,882]
解释：同一数字可重复使用，但次数不超过其在 digits 中的出现次数。
      数字 2 出现 3 次 → 222 合法；数字 8 出现 2 次 → 888 不合法。
```

**示例 3（空答案合法）**

```text
输入：digits = [3,7,5]
输出：[]
解释：没有偶数数字可作个位，无法构造任何偶数。空数组是合法输出，无需特判。
```

## 3. 解题思路

### 3.1 暴力思路

从输入端出发：任选三个**互异下标** $i, j, k$，拼成 $100 \cdot d_i + 10 \cdot d_j + d_k$，判定百位非零、个位为偶，命中则塞进 `set`，最后 `sort` 输出。三重循环 $O(n^3)$，$n = 100$ 时约 $10^6$ 次迭代，能过但难受：重复元素让同一数值被反复拼出（`[2,2,8,8,2]` 选三个 2 有 $3! = 6$ 种位置组合，结果都是 222），全靠 `set` 兜底去重，末尾还要补一次排序。

> ⚠️ 「从输入生成候选」的固有痛点：候选**可能重复**、**无序**，必须事后去重 + 排序两步补救。

### 3.2 核心观察：反向枚举值域

![核心观察：正向枚举输入 vs 反向枚举答案值域](images/2094_even3_concept.svg)

答案本身是三位偶数，取值只可能是 $\{100, 102, \dots, 998\}$，**仅 450 个候选**。与其从输入端拼出 $O(n^3)$ 个候选再补救，不如**反过来枚举这 450 个候选**，逐个验证「能否由 `digits` 组成」。三个题目条件被枚举范围直接编码：

| 条件 | 如何被枚举范围自动满足 |
|------|----------------------|
| 三位数 | $100 \le x \le 998$ 本身就是三位数 |
| 无前导零 | $x \ge 100$ 保证百位 $\ge 1$ |
| 偶数 | 步长 2 枚举，$x$ 恒为偶数 |

于是只剩一个验证任务：候选 $x$ 的三个数位能否被 `digits` 的频次表支撑——对每个数位计数比较即可。

### 3.3 算法流程

![算法流程：频次表 + 值域枚举验证](images/2094_even3_flow.svg)

1. 扫一遍 `digits`，建长度 10 的频次数组 `freq[0..9]`，$O(n)$；
2. 枚举 $x = 100, 102, \dots, 998$（步长 2）：
   - 拆位：$d_0 = \lfloor x/100 \rfloor$、$d_1 = \lfloor x/10 \rfloor \bmod 10$、$d_2 = x \bmod 10$；
   - 计数：`need[d0]++`、`need[d1]++`、`need[d2]++`；
   - 若对所有 $d$ 都有 `need[d] <= freq[d]`，则收入 `ans`；
3. 返回 `ans`——枚举严格递增，天然升序；每个 $x$ 只枚举一次，天然互异。

### 3.4 示例演算

![示例演算：digits=[2,1,3,0] 的频次验证走查](images/2094_even3_walkthrough.svg)

以示例 1 `digits = [2,1,3,0]` 演算，`freq = {0:1, 1:1, 2:1, 3:1}`：

| 候选 $x$ | 百 / 十 / 个 | 所需频次 | freq 检查 | 结果 |
|----------|-------------|----------|-----------|------|
| 100 | 1 / 0 / 0 | $1{\times}1,\ 0{\times}2$ | `freq[0]=1 < 2` | ✗ |
| 102 | 1 / 0 / 2 | $1, 0, 2$ 各 1 | 全部满足 | ✓ |
| 132 | 1 / 3 / 2 | $1, 3, 2$ 各 1 | 全部满足 | ✓ |
| 200 | 2 / 0 / 0 | $2{\times}1,\ 0{\times}2$ | `freq[0]=1 < 2` | ✗ |
| 210 | 2 / 1 / 0 | $2, 1, 0$ 各 1 | 全部满足 | ✓ |
| … | … | … | … | … |

关键失败模式：候选含**重复数位**（`100`、`200` 各需两个 0）被频次比较拦截。最终命中 10 个，按枚举顺序即升序：`[102, 120, 130, 132, 210, 230, 302, 310, 312, 320]`。

## 4. 算法细节

1. **频次表定长 10**：值域 $0 \sim 9$，`int freq[10]` 直接寻址，无需 `unordered_map`，也无哈希开销。
2. **拆位公式**：$d_0 = \lfloor x/100 \rfloor$，$d_1 = \lfloor x/10 \rfloor \bmod 10$，$d_2 = x \bmod 10$；候选只有 450 个，拆位成本可忽略。
3. **验证必须「计数比较」而非「判存在」**：`100` 需要两个 0，只判「0 在 digits 中出现」会把 `freq[0]=1` 的 `100` 错放行。正确做法是按数位累计 `need` 再与 `freq` 逐位比较（或用下面的借还式）。
4. **借还式变体**：不开 `need` 数组，直接在 `freq` 上「借三位 → 判非负 → 还三位」。注意借、还都必须**无条件做满三次**——若用短路 `&&` 配合 `--freq[d]`，首位透支时后续位没借却仍被归还，`freq` 被污染（详见姊妹篇的展开讨论）。
5. **等价的数位三元组枚举**：`for h in 1..9, t in 0..9, u in {0,2,4,6,8}`，与值域枚举一一对应（$x = 100h + 10t + u$），同样 $9 \times 10 \times 5 = 450$ 个、天然升序互异。两版随便选，值域枚举拆位更省心。

## 5. 正确性证明

**引理 1（频次刻画）**：设 $x$ 的三个数位为 $d_0, d_1, d_2$，$\text{need}_x[d]$ 为 $d$ 在其中出现次数，$\text{freq}[d]$ 为 $d$ 在 `digits` 中的出现次数。则 $x$ 可由 `digits` 中三个元素连接组成 $\iff$ 对所有 $d \in \{0,\dots,9\}$，$\text{need}_x[d] \le \text{freq}[d]$。

**证明**：（$\Rightarrow$）若 $x$ 可组成，则存在三个互异下标分别提供 $d_0, d_1, d_2$；值为 $d$ 的下标共用了 $\text{need}_x[d]$ 个且互不相同，故 $\text{freq}[d] \ge \text{need}_x[d]$。（$\Leftarrow$）对每个 $d$，从 `digits` 中值为 $d$ 的出现里任取 $\text{need}_x[d]$ 个下标；不同 $d$ 取到的下标因值不同而两两不交，合计恰取 $3$ 个互异下标，按 $d_0, d_1, d_2$ 顺序连接即得 $x$。∎

**引理 2（候选集完备且互异）**：整数 $x$ 满足「三位数、偶数、无前导零」 $\iff$ $x \in \{100, 102, \dots, 998\}$；且该枚举序列严格递增、两两不同。

**证明**：三位数 $\iff 100 \le x \le 999$；偶数 $\iff x \equiv 0 \pmod 2$；两者联立即 $\{100, 102, \dots, 998\}$（$998$ 为不超过 $999$ 的最大偶数）。无前导零 $\iff$ 百位非零 $\iff x \ge 100$，已被下界蕴含。序列是公差为 2 的等差数列，严格递增故两两互异。∎

**定理**：算法输出恰为所求答案——元素集合正确、互异、且严格递增。

**证明**：由引理 2，枚举覆盖且仅覆盖所有满足前两条约束的候选，每个恰一次；由引理 1，频次验证恰筛出「可由 digits 组成」者。故输出元素集合等于答案集合；互异性由「每个 $x$ 至多入列一次」保证；升序由「枚举严格递增且命中即追加于尾部」保证。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + 450 \cdot 13) = O(n + C)$。预处理频次表 $O(n)$；枚举 450 个候选，每个拆位 3 次 + 计数 3 次 + 比较 $\le 10$ 次，约 4500 次常数操作。即便 $n$ 涨到 $10^5$，本解法仍是 $O(n)$，而暴力三重循环退化到 $O(n^3) \approx 10^{15}$ 不可行——「枚举值域」对输入规模渐近鲁棒。
- **空间复杂度**：$O(1)$。`freq[10]`、`need[10]` 均为定长数组（输出数组至多 450 个元素，不计入）。

## 7. 参考代码

### C++（need 计数版）

```cpp
class Solution {
public:
    vector<int> findEvenNumbers(vector<int>& digits) {
        int freq[10] = {0};
        for (int d : digits) freq[d]++;           // 预处理频次表

        vector<int> ans;
        for (int x = 100; x <= 998; x += 2) {     // 枚举三位偶数
            int need[10] = {0};
            need[x / 100]++;
            need[x / 10 % 10]++;
            need[x % 10]++;
            bool ok = true;
            for (int d = 0; d < 10; ++d)
                if (need[d] > freq[d]) { ok = false; break; }
            if (ok) ans.push_back(x);
        }
        return ans;                               // 天然升序、互异
    }
};
```

### Python

```python
class Solution:
    def findEvenNumbers(self, digits: List[int]) -> List[int]:
        freq = [0] * 10
        for d in digits:
            freq[d] += 1                          # 预处理频次表
        ans = []
        for x in range(100, 999, 2):              # 枚举三位偶数
            need = [0] * 10
            need[x // 100] += 1
            need[x // 10 % 10] += 1
            need[x % 10] += 1
            if all(need[d] <= freq[d] for d in range(10)):
                ans.append(x)
        return ans                                # 天然升序、互异
```

### C++（借还式变体，免开 need 数组）

```cpp
class Solution {
public:
    vector<int> findEvenNumbers(vector<int>& digits) {
        int freq[10] = {0};
        for (int d : digits) freq[d]++;
        vector<int> ans;
        for (int x = 100; x <= 998; x += 2) {
            int a = x / 100, b = x / 10 % 10, c = x % 10;
            --freq[a]; --freq[b]; --freq[c];      // 无条件借三位
            if (freq[a] >= 0 && freq[b] >= 0 && freq[c] >= 0)
                ans.push_back(x);                 // 借后均未透支 → 可行
            ++freq[a]; ++freq[b]; ++freq[c];      // 无条件归还，恢复 freq
        }
        return ans;
    }
};
```

> ⚠️ 借还式的不变式是「借几位就还几位」：递减必须放在短路 `&&` **之外**，否则首位透支时后续位没借却被归还，`freq` 虚高导致后续候选误判可行。重复数位同样被正确处理——$x = 222$ 时 `--freq[2]` 执行三次，借后 `freq[2] >= 0` 等价于原 `freq[2] >= 3`。

## 8. 边界情况与易错点

1. **重复数位的频次需求（本题最经典的 WA）**：`100`、`200` 各需两个 0，`222` 需三个 2。验证必须按**计数比较**（`need[d] <= freq[d]`），只判「每位是否在 digits 中出现」会错放行 `100`。示例 1 与示例 2 都是官方设的验证点。
2. **升序是硬性要求**：与「顺序任意」的题不同，本题要求递增返回。正向枚举忘记 `sort` 直接 WA；值域枚举天然免疫。
3. **空答案合法**：全奇数输入（如 `[3,7,5]`）输出 `[]`，不要特判塞哨兵值。
4. **前导零被下界排除**：值域枚举从 100 起，天然无前导零；若写数位三元组版，百位循环必须从 1 开始。
5. **个位枚举集合**：$\{0, 2, 4, 6, 8\}$；用步长 2 时注意上界是 998（`range(100, 999, 2)` 恰好停在 998）。
6. **$n = 3$ 最小规模**：恰好一个候选三元组，验证逻辑照常工作，无需特判。
7. **无溢出风险**：候选 $\le 998$、频次 $\le 100$，`int` 绰绰有余。
