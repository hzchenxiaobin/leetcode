# LeetCode 删除链表的中间节点 题解

## 1. 题目概述

- **标题 / 题号**：删除链表的中间节点（#2095，medium）
- **链接**：https://leetcode.cn/problems/delete-the-middle-node-of-a-linked-list/
- **来源**：LeetCode 第 270 场周赛 Q2
- **难度**：中等
- **标签**：链表、双指针

**题意**：给定单链表的头节点 `head`，删除链表的**中间节点**，返回修改后的链表头节点。长度为 $n$ 的链表，中间节点定义为从头数起第 $\lfloor n/2 \rfloor$ 个节点（下标从 0 开始）：$n = 1, 2, 3, 4, 5$ 时中间节点下标分别为 $0, 1, 1, 2, 2$。

**约束**：

- 链表中节点数目在范围 $[1, 10^5]$ 内 —— $n \ge 1$，**单节点链表也要删**（删完为空）
- $1 \le \text{Node.val} \le 10^5$ —— 值域本题完全用不上，纯指针操作

> 💡 本题是「链表中点」模板（876）的删除版：876 只要**找到**中点，本题要**删掉**中点。单链表删除一个节点需要它的**前驱**，于是「快慢指针 + 哑节点」一趟解决：快指针的速度差负责量出中点，哑节点负责把慢指针的落点整体左移一格、正好停在前驱上，顺带把 $n = 1$ 的删头边界也一并吞掉。

## 2. 示例

**示例 1**

```text
输入：head = [1,3,4,7,1,2,6]
输出：[1,3,4,1,2,6]
解释：n = 7，中间节点是下标 3（值为 7）的节点，删除后剩余 6 个节点。
```

**示例 2（偶数长度，中间偏右）**

```text
输入：head = [1,2,3,4]
输出：[1,2,4]
解释：n = 4，中间节点是下标 2（值为 3）的节点 —— n 为偶数时中间节点偏右。
```

**示例 3（最小规模）**

```text
输入：head = [2,1]
输出：[2]
解释：n = 2，中间节点是下标 1（值为 1）的节点，删除后只剩头节点。
```

**补充（n = 1，官方示例未覆盖）**

```text
输入：head = [5]
输出：[]
解释：n = 1，中间节点就是头节点本身，删除后为空链表，返回 null。
```

## 3. 解题思路

### 3.1 朴素思路：两趟定位

链表没有下标，最直接的想法是把链表的劣势抹掉：

- **数组直达**：一遍遍历把节点指针存进数组，令 `arr[n/2 - 1]->next = arr[n/2]->next` 完成删除（$n = 1$ 时返回空）。时间 $O(n)$，但**额外空间 $O(n)$** —— 为了删一个节点存下整个链表，性价比太低。
- **两趟计数**：第一趟数出长度 $n$，第二趟从头走 $\lfloor n/2 \rfloor - 1$ 步停在前驱，改一根指针。时间 $O(n)$、空间 $O(1)$，已经能过，但要**扫两遍**链表。

两趟法的问题在于：长度信息其实**边走就能知道** —— 让一个指针以两倍速先行，它撞到尾部的那一刻，慢指针恰好走过一半。这就是一趟解法。

### 3.2 核心观察：快慢指针找中点，哑节点补前驱

![核心观察：快慢指针找中点，哑节点补前驱](images/2095_midnode_concept.svg)

两个观察接力：

1. **速度差就是尺子**：`fast` 一次走 2 步、`slow` 一次走 1 步，同时出发则任意时刻 `fast` 走过的距离是 `slow` 的两倍。`fast` 到达链表尾部不能再跨时，`slow` 恰好在链表**中点** —— 一趟遍历同时完成「数长度」与「定位」。
2. **删除需要前驱，哑节点左移一格**：876 的模板让 `slow` 停在中点**上**，可单链表没有 `prev` 指针，拿着要删的节点却改不了指向它的那根指针。解决办法是在链表头前接一个**哑节点 `dummy`**，`slow`、`fast` 都从 `dummy` 出发 —— 两者落点整体左移一格，`slow` 停在中点的**前驱**上；`slow->next = slow->next->next` 一句话完成删除。

哑节点还附带一份红利：$n = 1$ 时要删的正是**头节点**，无哑节点的写法必须特判返回空，而这里 `dummy` 天然充当头节点的前驱，$n = 1$ 与一般情况**共用同一条删除语句**，一个分支都不用加。

### 3.3 算法流程

![算法流程：一趟快慢指针，定位即删除](images/2095_midnode_flow.svg)

1. 建哑节点 `dummy->next = head`，`slow = fast = dummy`；
2. 循环：只要 `fast->next` 与 `fast->next->next` 都存在，`slow` 走 1 步、`fast` 跨 2 步；
3. 循环结束时 `slow` 恰停在中点的前驱上（$n = 1$ 时即 `dummy`）；
4. 删除：`slow->next = slow->next->next`；
5. 返回 `dummy->next`（$n \ge 2$ 时就是原 `head`，$n = 1$ 时为 `nullptr`）。

### 3.4 示例演算

![示例演算：[1,3,4,7,1,2,6] 的快慢指针走查](images/2095_midnode_walkthrough.svg)

以示例 1 `[1,3,4,7,1,2,6]`（$n = 7$）演算，中间节点下标 $\lfloor 7/2 \rfloor = 3$：

| 检查 | fast 下标 | next / next.next | 进循环 | 移动后 slow / fast |
|------|-----------|------------------|--------|--------------------|
| ① | −1（dummy） | 0 / 1 | ✓ | 0 / 1 |
| ② | 1 | 2 / 3 | ✓ | 1 / 3 |
| ③ | 3 | 4 / 5 | ✓ | 2 / 5 |
| ④ | 5 | 6 / ∅ | ✗ 退出 | 2 / 5（不动） |

循环恰执行 $\lfloor n/2 \rfloor = 3$ 轮后，第 ④ 次检查发现 `fast->next->next` 越界而退出，`slow` 停在下标 2（值 4）—— 正是中间节点（下标 3，值 7）的前驱。执行 `slow->next = slow->next->next`，下标 3 的节点脱链，得到 `[1,3,4,1,2,6]`。

## 4. 算法细节

1. **起止配套**：`slow = fast = dummy` 必须配循环条件 `fast->next && fast->next->next`。这套配置的终止结论对奇偶长度统一：循环恰执行 $\lfloor n/2 \rfloor$ 轮，`slow` 停在下标 $\lfloor n/2 \rfloor - 1$（引理 2）。
2. **为什么条件要查两级 `next`**：`fast` 一次跨两格，跨之前必须确认两格都存在（否则解引用空指针）；同时这个「多看一格」的条件让循环比 876 模板**提前一轮**停住，把 `slow` 从中点挪到前驱 —— 起点左移与条件收紧缺一不可（见 §8 易错点 3）。
3. **删除语句的普适性**：`slow->next = slow->next->next` 对 $n = 1$（`slow` 即 `dummy`，删头）与 $n \ge 2$ 完全同构，无需任何特判。C++ 若在意内存可先保存 `slow->next->next` 再 `delete slow->next`，LeetCode 上不 `delete` 也能通过。
4. **返回值必须是 `dummy->next` 而非 `head`**：$n = 1$ 时头节点被删除，`head` 已不该再被引用；$n \ge 2$ 时两者相同。
5. 只用 `dummy`、`slow`、`fast` 三个指针，不修改任何节点值、不建辅助结构 —— 链表题的标准「无痕」操作。

## 5. 正确性证明

约定：哑节点记为下标 $-1$，真实节点下标 $0 \sim n-1$。

**引理 1（速度不变量）**：第 $m$ 轮循环结束后，`slow` 位于下标 $m-1$，`fast` 位于下标 $2m-1$；特别地 $2 \cdot \text{slow} + 1 = \text{fast}$ 恒成立（`fast` 始终指向真实节点，从不下越哑节点）。

**证明**：对 $m$ 归纳。$m = 0$（初始）：两者均在下标 $-1$，$2 \cdot (-1) + 1 = -1$ 成立。归纳步：设第 $m-1$ 轮结束时 `slow` 在 $m-2$、`fast` 在 $2m-3$，且循环条件成立（`fast` 之后至少还有 2 个节点，故推进合法）。第 $m$ 轮将 `slow` 推进 1 步到 $m-1$、`fast` 推进 2 步到 $2m-1$，且 $2(m-1) + 1 = 2m-1$，不变量保持。∎

**引理 2（终止位置）**：循环恰执行 $\lfloor n/2 \rfloor$ 轮；终止时 `slow` 位于下标 $\lfloor n/2 \rfloor - 1$，即中间节点的直接前驱；`fast` 位于下标 $2\lfloor n/2 \rfloor - 1$（$n$ 为偶数时是尾节点 $n-1$，$n$ 为奇数时是 $n-2$）。

**证明**：条件 `fast->next && fast->next->next` 成立当且仅当 `fast` 下标 $\le n-3$。由引理 1，第 $m$ 轮**开始前** `fast` 位于 $2m-3$，故第 $m$ 轮执行当且仅当 $2m - 3 \le n - 3$，即 $m \le n/2$。于是执行轮数 $m^\ast = \lfloor n/2 \rfloor$，终止时 `slow` 位于 $m^\ast - 1 = \lfloor n/2 \rfloor - 1$ —— 恰为中间节点（下标 $\lfloor n/2 \rfloor$）的前驱；`fast` 位于 $2m^\ast - 1$。∎

**定理**：算法返回的链表恰为原链表删去下标 $\lfloor n/2 \rfloor$ 的节点后的结果，其余节点次序不变；$n = 1$ 时返回空链表。

**证明**：由引理 2，`slow` 停在前驱 $p$（$n = 1$ 时 $p$ 即 `dummy`，中间节点为头节点）。语句 `slow->next = slow->next->next` 令 $p$ 的后继指针绕过中间节点、直指其原本的直接后继，中间节点从链上脱链；除此之外没有任何指针被修改，故其余 $n - 1$ 个节点依原次序保留。返回 `dummy->next`：$n \ge 2$ 时头节点未被触碰，返回原 `head`；$n = 1$ 时 `dummy->next` 已被置为 `nullptr`，返回空。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。循环执行 $\lfloor n/2 \rfloor$ 轮，`fast` 总共走约 $n$ 步、`slow` 约 $n/2$ 步，删除与返回均 $O(1)$。相比两趟计数法省掉一次全程扫描；$n = 10^5$ 时约 $10^5$ 次指针跳转，仍是严格线性，且是「读一遍链表」问题的信息论下界。
- **空间复杂度**：$O(1)$。仅 `dummy`、`slow`、`fast` 三个指针，不依赖节点值、不建辅助容器（对比数组直达法的 $O(n)$ 额外空间）。

## 7. 参考代码

### C++（dummy + 快慢指针，推荐）

```cpp
class Solution {
public:
    ListNode* deleteMiddle(ListNode* head) {
        ListNode dummy(0, head);
        ListNode *slow = &dummy, *fast = &dummy;
        while (fast->next && fast->next->next) {   // fast 之前至少还有两格才跨
            slow = slow->next;                     // 每轮走 1 步
            fast = fast->next->next;               // 每轮跨 2 步
        }
        slow->next = slow->next->next;             // n = 1 时删的正是 head
        return dummy.next;
    }
};
```

### Python

```python
class Solution:
    def deleteMiddle(self, head: Optional[ListNode]) -> Optional[ListNode]:
        dummy = ListNode(0, head)
        slow = fast = dummy
        while fast.next and fast.next.next:
            slow = slow.next                       # 每轮走 1 步
            fast = fast.next.next                  # 每轮跨 2 步
        slow.next = slow.next.next                 # n = 1 时删的正是 head
        return dummy.next
```

### C++（无 dummy：显式跟踪前驱）

```cpp
class Solution {
public:
    ListNode* deleteMiddle(ListNode* head) {
        if (!head->next) return nullptr;           // n = 1：删头，必须特判
        ListNode *prev = nullptr, *slow = head, *fast = head;
        while (fast && fast->next) {               // 876 原版条件：slow 停在中点上
            prev = slow;                           // prev 始终落后 slow 一格
            slow = slow->next;
            fast = fast->next->next;
        }
        prev->next = slow->next;                   // 用 prev 补上前驱再删除
        return head;
    }
};
```

> ⚠️ 无 dummy 版有两个额外负担：$n = 1$ 的删头特判，以及 `prev` 的时序更新（先记 `prev` 再走 `slow`）。对照可见 dummy 版把这两件事一并吞掉了。

## 8. 边界情况与易错点

1. **$n = 1$ 删头返回空（官方示例未覆盖）**：dummy 版自动处理（`slow` 即 `dummy`，删除语句同构）；无 dummy 版**必须** `if (!head->next) return nullptr;`，漏判即对空指针解引用 `slow->next->next`。
2. **`slow` 必须停在前驱，而不是中点**：直接照搬 876 模板（`slow = fast = head`）会让 `slow` 停在中点本身上，单链表拿不到 `prev`，删除无从下手。两个修法：dummy 左移（推荐）或显式 `prev` 跟踪。
3. **起点与条件必须配套**：`dummy` 出发要配 `fast->next && fast->next->next`；`head` 出发配 `fast && fast->next`。最隐蔽的错法是 dummy 起点配 876 的弱条件 —— 奇数长度时 `slow` 会停到中点**上**（少停一轮），偶数长度的部分用例又恰好蒙对，错误呈「奇偶依赖」，小规模对拍都未必暴露。
4. **返回 `head` 而非 `dummy.next`**：$n = 1$ 时返回已删除的头节点（悬垂指针 / 错误答案），$n \ge 2$ 时两者才等价。
5. **奇偶下标对齐**：$n$ 为偶数时中间节点偏右（$n = 4$ 删下标 2 而非 1）——这是 $\lfloor n/2 \rfloor$ 的定义，别用「四舍五入」直觉脑补。
6. **C++ 内存**：改指针前先存 `slow->next->next` 再 `delete slow->next` 的顺序问题；竞赛/LeetCode 场景通常省略 `delete`。
7. **链表为空的输入不存在**：约束保证 $n \ge 1$，无需判 `head == nullptr`。
