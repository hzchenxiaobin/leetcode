# LeetCode 汉明距离总和 题解

## 1. 题目概述

- **标题 / 题号**：汉明距离总和（#477，medium）
- **链接**：https://leetcode.cn/problems/total-hamming-distance/
- **来源**：LeetCode 第 13 场周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、数学

**题意**：给定长度为 $n$ 的整数数组 `nums`，对每一对下标 $i < j$ 计算 $nums[i]$ 与 $nums[j]$ 的**汉明距离**（两数二进制表示中取值不同的位个数），返回所有数对距离的**总和**。

**约束**：

- $1 \le n \le 10^4$
- $0 \le nums[i] \le 10^9$，即 $nums[i] < 2^{30}$
- 保证答案落在 32 位有符号整数范围内

## 2. 示例

**示例 1**

```text
输入：nums = [4,14,2]
输出：6
解释：二进制（补足低 4 位）4 = 0100，14 = 1110，2 = 0010。
      d(4,14) = 2，d(4,2) = 2，d(14,2) = 2，总和 2 + 2 + 2 = 6。
```

**示例 2**

```text
输入：nums = [4,14,4]
输出：4
解释：d(4,14) = 2，d(14,4) = 2，两个 4 之间距离为 0，总和 4。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i,j)$，用 `popcount(nums[i] ^ nums[j])` 求距离累加。数对数量为 $\frac{n(n-1)}{2}$，当 $n = 10^4$ 时约 $5 \times 10^7$ 对：C++ 中每次异或加一次位计数是常数级操作，勉强能卡过；Python 循环 $5\times10^7$ 次通常要几十秒，必然超时。更关键的是这个做法**没有利用题目结构**——只要 $n$ 放宽到 $10^5$，数对变成 $5\times10^9$，任何语言都救不回来。因此需要把「枚举数对」换成「枚举二进制位」。

### 3.2 核心观察：按位独立统计

![按位拆解：每一位只需统计 1 与 0 的个数](images/wc13_q2_bit_columns.svg)

汉明距离的定义本身就是「逐位比较」，于是可以把求和**按位拆开**：

$$d(x,y) = \sum_{b \ge 0} \bigl[\,\text{bit}_b(x) \ne \text{bit}_b(y)\,\bigr]$$

代回总和，并交换两个求和的次序：

$$S = \sum_{i<j} \sum_{b} \bigl[\,\text{bit}_b(nums_i) \ne \text{bit}_b(nums_j)\,\bigr] = \sum_{b} \Bigl(\text{第 } b \text{ 位上取值不同的数对个数}\Bigr)$$

此时每一位的统计彼此**完全独立**：固定位 $b$，设 $n$ 个数中该位为 $1$ 的有 $c_b$ 个、为 $0$ 的有 $n - c_b$ 个。任意一对数在这一位不同，等价于「一个取 1、一个取 0」，这样的配对恰有

$$c_b \times (n - c_b)$$

对。于是答案就是一个 31 项的求和，每项只需扫一遍数组数 1：

$$S = \sum_{b=0}^{30} c_b \,(n - c_b)$$

> 💡 **一句话记住**：把「两两比较」换成「竖着数每一列」，$O(n^2)$ 的数对枚举就退化成 31 次 $O(n)$ 的计数。

### 3.3 算法流程

![算法流程：31 轮位统计](images/wc13_q2_algorithm_flow.svg)

1. 令 `ans = 0`，`n = len(nums)`。
2. 枚举位 $b = 0,1,\dots,30$：遍历数组，累加 `(x >> b) & 1` 得到 `ones`。
3. 该位贡献 `ones * (n - ones)`，累加进 `ans`。
4. 31 位全部处理完，返回 `ans`。

这里取到第 30 位是**留了余量**：$nums[i] \le 10^9 < 2^{30}$，真正可能非零的位只有 $0 \sim 29$，多扫的一位必然数出 0，不影响结果。

### 3.4 示例演算

![示例演算：[4,14,2] 的逐位列统计](images/wc13_q2_walkthrough.svg)

对 `nums = [4,14,2]`，只列低 4 位：

| 位 $b$ | 0 | 1 | 2 | 3 | $\ge 4$ |
|--------|---|---|---|---|---------|
| 4 = 0100 | 0 | 0 | 1 | 0 | 0 |
| 14 = 1110 | 0 | 1 | 1 | 1 | 0 |
| 2 = 0010 | 0 | 1 | 0 | 0 | 0 |
| $c_b$ | 0 | 2 | 2 | 1 | 0 |
| $n - c_b$ | 3 | 1 | 1 | 2 | 3 |
| 贡献 | 0 | 2 | 2 | 2 | 0 |

总和 $0 + 2 + 2 + 2 = 6$，与示例 1 一致。第二组 `[4,14,4]` 中 $b=1$、$b=3$ 各贡献 2 对，$b=2$ 三位全为 1 贡献 0，答案 4。

## 4. 算法细节

1. **位宽选择**：`0 <= nums[i] <= 1e9 < 2^30`，最高非零位是第 29 位；写 `b < 31`（覆盖 $0\sim30$）最稳，写 `b < 30` 也够用。不要固定写 32 位再对 `int` 做 `x >> 31`，右移位数达到类型宽度在 C++ 中是未定义行为。
2. **只数 1，不数 0**：`ones` 一遍循环拿到，`zeros = n - ones` 直接推出，省掉一个计数器，也避免「漏数某个 0」的低级错误。
3. **移位写法**：`(x >> b) & 1` 每一步都基于原数；不要写 `x >>= 1` 的自毁式循环，否则外层位循环和内层元素遍历会互相污染。
4. **溢出边界**：$c_b(n-c_b) \le \frac{n^2}{4} = 2.5\times10^7$（$n=10^4$），31 项相加最大约 $7.5\times10^8 < 2^{31}-1$，用 `int` 安全，这也是题目「答案符合 32 位整数」的含义。若 $n$ 上限变成 $10^5$，单项就到 $2.5\times10^9$，必须换 `long long`。
5. **按位外提优于按元素外提**：外层循环位、内层顺序扫数组，访存是连续且可预测的；若反过来对每个元素单独拆 31 位，常数更大。
6. **可以提前定界**：先取 `maxv = max(nums)`，用 `while (1LL << b) <= maxv` 控制位宽，数组全 0 时一轮都不跑，语义同样正确。
7. **无需去重或排序**：相同的数对贡献为 0，公式自然给出 0（同一位上它们不可能一 1 一 0），不必特判。

## 5. 正确性证明

**引理 1（按位分解）**：对任意非负整数 $x,y$，有 $d(x,y) = \sum_{b \ge 0} [\text{bit}_b(x) \ne \text{bit}_b(y)]$。

**证明**：汉明距离定义为两数 $x,y$ 的二进制表示中不同位的个数。对每个位定义一个取值为 0 或 1 的指示量，所有位的指示量之和正是「不同位的个数」，即汉明距离。只有有限个位非零，求和有意义。∎

**引理 2（单列计数）**：固定位 $b$，在全部 $n$ 个数中，该位上取值不同的**无序数对**恰好有 $c_b(n-c_b)$ 个。

**证明**：设该位为 1 的下标集合为 $A$（$|A| = c_b$），为 0 的集合为 $B$（$|B| = n - c_b$）。定义映射 $f$：把每个「该位不同」的无序对 $\{i,j\}$ 映到有序对 $(u,v)$，其中 $u$ 是该位为 1 的那个下标、$v$ 是该位为 0 的那个下标。由于一对中一 1 一 0，$u,v$ 唯一确定，故 $f$ 是单射；反之任取 $u \in A$、$v \in B$，$\{u,v\}$ 必是该位不同的数对，且 $f(\{u,v\}) = (u,v)$，故 $f$ 是满射。于是 $f$ 是双射，两侧数量相等，为 $|A| \cdot |B| = c_b(n-c_b)$。∎

**引理 3（高位无贡献）**：所有 $b \ge 30$ 的位满足 $c_b = 0$，贡献为 0。

**证明**：$nums[i] \le 10^9 < 2^{30}$，其二进制展开中第 30 位及更高位全为 0，故 $c_b = 0$，$c_b(n-c_b) = 0$。∎

**定理**：上述算法返回的值等于数组中所有数对的汉明距离总和。

**证明**：由引理 1，$S = \sum_{i<j}\sum_{b\ge0}[\cdot] = \sum_{b\ge0} N_b$，其中 $N_b$ 是第 $b$ 位上不同的数对个数（有限和，可交换次序）。由引理 2，$N_b = c_b(n-c_b)$。算法对 $b=0,\dots,30$ 逐项累加 $c_b(n-c_b)$；由引理 3，被省略的 $b \ge 31$ 项全为 0，补上也不改变总和。因此返回值恰为 $S$。∎

## 6. 复杂度分析

- **时间**：$O(31n) = O(n \log C)$，其中 $C = \max(nums) \le 10^9$。外层固定 31 轮，内层一次线性扫描；对 $n = 10^4$ 约 $3.1\times10^5$ 次操作，比暴力少两个数量级。
- **空间**：$O(1)$ 额外空间，只用了 `n`、`ans`、`ones`、`b` 几个变量，不随 $n$ 增长。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int totalHammingDistance(vector<int>& nums) {
        int n = (int)nums.size();
        int ans = 0;
        for (int b = 0; b < 31; ++b) {       // 0..30，覆盖 1e9 的所有位
            int ones = 0;
            for (int x : nums) {
                ones += (x >> b) & 1;        // 第 b 位为 1 的个数
            }
            ans += ones * (n - ones);        // 一 1 一 0 的配对数
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def totalHammingDistance(self, nums: list[int]) -> int:
        n = len(nums)
        ans = 0
        for b in range(31):                  # 0..30，覆盖 1e9 的所有位
            ones = sum((x >> b) & 1 for x in nums)
            ans += ones * (n - ones)         # 一 1 一 0 的配对数
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：没有任何数对，答案 0；公式中 $n - c_b = 0$，自动得到 0，无需特判。
2. **全部元素相同（含全 0 数组）**：每一位上 `ones` 要么 0 要么 $n$，乘积恒为 0；全 0 数组答案 0。
3. **重复元素**：重复出现的数之间距离为 0，它们在同一位上要么同时为 1、要么同时为 0，不会被计入任何一位的「1 配 0」，结果正确。
4. **漏掉最高位**：$10^9$ 的第 29 位是 1，若位宽只写 `range(29)`（$0\sim28$）就会漏算这一位，答案偏小。写 31 位最稳妥。
5. **`int` 溢出**：$n = 10^4$ 时上界约 $7.5\times10^8$ 没问题；但若把数据范围改大（如 $n = 10^5$），单项 $c(n-c)$ 就超过 `int`，必须用 `long long`。
6. **`x >> 31` 的未定义行为**：对 32 位 `int` 右移 31 位虽多数编译器按算术移位处理，但移位量等于类型位宽属于未定义行为；本题位下标取到 30 就够（等价于循环 `b < 31`），不要盲目循环到 32。
7. **Python 无需担心溢出**：大整数自动扩容，同一份逻辑直接写即可；但**不要**退回 $O(n^2)$ 的双重循环，$5\times10^7$ 次 `bit_count` 在 Python 里仍然很慢。
