# LeetCode 火柴拼正方形 题解

## 1. 题目概述

- **标题 / 题号**：火柴拼正方形（#473，medium）
- **链接**：https://leetcode.cn/problems/matchsticks-to-square/
- **来源**：LeetCode 第 13 场周赛 Q3
- **难度**：中等
- **标签**：位运算，数组，动态规划，回溯，状态压缩

**题意**：给定 $n$ 根火柴的长度，要求**全部用上**、**不许折断**、每根**恰好用一次**，把它们首尾相连拼成一个正方形，判断是否可行。

设 $S=\sum \text{matchsticks}$，边长唯一确定：$t = S/4$。于是只需判断能否把火柴分成 4 组，每组长度和都等于 $t$。

**约束**：

- $1 \le n \le 15$
- $1 \le \text{matchsticks}[i] \le 10^8$

两个立刻可以判死的边界：$4 \nmid S$，或者某根火柴长度 $> t$。

## 2. 示例

**示例 1**

```text
输入：matchsticks = [1,1,2,2,2]
输出：true
解释：能拼成边长为 2 的正方形：三条边各用一根 2，第四条边用两根 1。
```

**示例 2**

```text
输入：matchsticks = [3,3,3,3,4]
输出：false
解释：总和 16、边长 4；4 独占一条边后，剩下的 3 无论怎么放都凑不出另外三条边。
```

**补充示例（边界）**

```text
输入：matchsticks = [1,1,2,4]
输出：false
解释：总和 8、边长 2，但有一根火柴长 4 > 2，直接无解。
```

## 3. 解题思路

### 3.1 暴力思路

最直观的搜索：每根火柴都有 4 种归属（四条边之一），枚举全部 $4^n$ 种分配再检查四条边是否等长。$n=15$ 时 $4^{15}\approx 1.07\times 10^9$，必然超时；更糟的是，其中绝大多数方案只是「边的标号置换」，彼此完全等价。要过题必须做两件事：让大棒先放（尽早失败）、把等价分支砍掉。

### 3.2 核心观察：边长固定 ⇒ 4 个容量为 $t$ 的桶

![把火柴装进四个容量为 target 的桶](images/wc13_q3_bins_concept.svg)

边长 $t=S/4$ 一旦确定，问题就变成了经典的**装箱可行性**：把 $n$ 件物品装进 4 个容量均为 $t$ 的桶，要求恰好装满。这里有两个关键结构性质：

1. **顺序无关**：火柴以什么顺序放不影响可行性，所以可以任意重排，按**降序**处理最有利——大棒能放的位置少，冲突早暴露、早剪枝。
2. **边没有标号**：交换两条边的名字得到的是同一个方案。因此状态只需要记录「每条边已经用了多少」$s_0,s_1,s_2,s_3$，不必记录具体哪些火柴在哪条边上。

状态即 $(i, s_0, s_1, s_2, s_3)$：$i$ 是当前要放的火柴下标，$s_k$ 是第 $k$ 条边已用长度。搜索树每一层最多 4 个分支，配合剪枝后规模远小于 $4^{15}$。

### 3.3 算法流程：降序 + 回溯 + 两条剪枝

![回溯流程与两条剪枝](images/wc13_q3_dfs_flow.svg)

```text
if S % 4 != 0 or max(matchsticks) > t: return false
将 matchsticks 降序排序；side[0..3] = 0
bool dfs(i):
    if i == n: return true
    for k in 0..3:
        if side[k] + a[i] > t: continue              # 剪枝①：装不下
        if k > 0 and side[k] == side[k-1]: continue  # 剪枝②：等价桶只试一次
        side[k] += a[i]
        if dfs(i + 1): return true
        side[k] -= a[i]                              # 回溯
    return false
```

- **剪枝①**：边只能变长不能变短，一旦超出容量，这个分支及其所有后代都不可能有解。
- **剪枝②**：若第 $k$ 条边和第 $k-1$ 条边已用长度相同，则把 $a_i$ 放进第 $k$ 条边的任何后续方案，只需互换这两条边的标号就能得到一个把 $a_i$ 放进第 $k-1$ 条边的方案，两者同构。既然 $k-1$ 已经试过，$k$ 就不必再试。它顺带覆盖了「多个空桶只需试第一个」的情形。

**等价视角（位掩码 DP）**：令 $\text{dp}[mask]$ 表示「已使用火柴集合为 $mask$ 时，当前正在填的那条边已经填了多长」，用 $-1$ 表示不可达，$\text{dp}[0]=0$。枚举 $i \notin mask$，若 $\text{dp}[mask]+a_i \le t$，则

$$\text{dp}[mask \mid 2^i] = (\text{dp}[mask] + a_i) \bmod t$$

最后 $\text{dp}[2^n-1] = 0$ 即可行。状态数 $2^n$，每个状态转移 $n$ 次，是 $O(n2^n)$ 的「无最坏情况」写法。

### 3.4 示例演算

![示例 1 逐步装桶](images/wc13_q3_walkthrough.svg)

对 `[1,1,2,2,2]`，$S=8$、$t=2$，降序后 $a=[2,2,2,1,1]$：

| 步骤 | $a_i$ | 放入 | 桶状态 $[s_0,s_1,s_2,s_3]$ |
|------|-------|------|-----------------------------|
| 第 1 根 | 2 | 边 1 | $[2,0,0,0]$ |
| 第 2 根 | 2 | 边 2 | $[2,2,0,0]$ |
| 第 3 根 | 2 | 边 3 | $[2,2,2,0]$ |
| 第 4 根 | 1 | 边 4（前三边已满） | $[2,2,2,1]$ |
| 第 5 根 | 1 | 边 4（恰好补满） | $[2,2,2,2]$ |

五根全部放完，返回 `true`。

反例 `[3,3,3,3,4]`：$S=16$、$t=4$，降序后 $[4,3,3,3,3]$。4 占满边 1，三个 3 分别占满边 2、3、4，此时每条边剩余容量只剩 0、1、1、1，最后一根 3 无处可放；回退也无济于事（四条边互相等价，4 放哪条边都是同一个本质方案），返回 `false`。

## 4. 算法细节

1. **用 `long long` 求和**：$n \le 15$、$a_i \le 10^8$，总和最大 $1.5\times 10^9$，恰好在 `int32` 边界内，但 `accumulate(v.begin(), v.end(), 0)` 会按 `int` 累加、`t` 的余数运算也容易踩边界，统一写 `0LL` 更稳。
2. **降序排序是剪枝的前提**：`sort(a.rbegin(), a.rend())` 让最大的火柴先占位，容量冲突在第一层就暴露，搜索树宽度迅速收缩；若不排序，剪枝①几乎不起作用。
3. **剪枝②不依赖 `side` 有序**：只用到「相邻两个桶剩余容量相等 ⇒ 两条边可互换」这一对称性，因此不需要维护有序结构；但 `k > 0` 的判断不能漏，否则会访问 `side[-1]`。
4. **放完即成功**：递归终点直接 `return true`，不必再逐条检查四条边是否都等于 $t$——每一步都保证 $s_k \le t$ 且总和恰为 $4t$，见引理 4。
5. **位掩码版的状态设计**：$mask$ 记录已用集合，$\text{dp}$ 值记录「当前边已填长度」，用取模把「填满一条边后开新边」编码进去；用 $-1$ 当哨兵，因为余数 $0$ 是合法状态（刚填满一条边）。
6. **DP 的终止条件**：返回 `dp[(1 << n) - 1] == 0`。$2^n-1$ 可达且余数为 0，等价于「所有火柴都用完且最后一条边刚好填满」。
7. **规模核算**：$n=15$ 时 DP 有 $32768$ 个状态、每状态最多 $15$ 次转移，约 $5\times 10^5$ 次操作，任何数据都在毫秒级；回溯版实测同样在毫秒级，但最坏上界仍是 $O(4^n)$。

## 5. 正确性证明

**引理 1（判定等价）**：火柴能拼成边长 $t$ 的正方形，当且仅当存在把火柴分成 4 组、每组长度和都等于 $t$ 的划分。

**证明**：若已拼成正方形，因火柴不能折断且是直线段，每根火柴必然完整落在某一条边上（拐角处线段方向改变 $90^\circ$，一根直火柴不可能同时覆盖两条边），于是按所在边分组即得到 4 组、每组和为 $t$。反之，若存在 4 组、每组和为 $t$ 的划分，把每组的火柴首尾相接连成一条长为 $t$ 的线段，四条线段首尾相接即得边长 $t$ 的正方形。∎

**引理 2（剪枝安全）**：设当前搜索到 $(i, side)$，且此前所有放置都满足 $s_k \le t$。则剪枝①、②删掉的分支都不含可行解，且降序排序不改变可行解的存在性。

**证明**：① 若 $s_k + a_i > t$，由于后续只会向桶里继续添加火柴，$s_k$ 只会更大，该分支永远无法满足容量约束，故无解。② 若 $k>0$ 且 $s_k = s_{k-1}$，设存在把 $a_i$ 放入边 $k$ 的完整方案 $P$。把 $P$ 中「边 $k$ 与边 $k-1$ 上所有火柴」互换，得到方案 $P'$：$P'$ 中 $a_i$ 被放入边 $k-1$，且四条边的总长集合不变，仍是一个可行划分。因此边 $k$ 的分支被边 $k-1$ 的分支完全覆盖，剪掉不丢解。降序只是把同一 $4^n$ 分配空间中元素的枚举次序改变，可行解集合不变。∎

**引理 3（完备性）**：不加剪枝时 DFS 恰好枚举全部 $4^n$ 个分配；加上引理 2 的两条剪枝后，若存在可行划分，DFS 仍会返回 `true`。

**证明**：对 $n$ 归纳。$n=0$ 时返回 `true`。设 $n>0$，若存在可行划分，$a_0$ 必属于某条边 $k^*$。若 $k^*$ 因剪枝①被跳过，则由引理 2 该分支无解，与划分存在矛盾；否则考察 $k^*$ 之前被跳过的同构分支（引理 2 ②），它们对应的方案经标号互换后同样可行，故未被跳过的某个等价分支里存在可行划分，归纳假设保证递归返回 `true`。若所有分支都失败，说明不存在可行划分。∎

**引理 4（放完即成功）**：递归到达 $i=n$ 时，四条边必然都恰好等于 $t$。

**证明**：全程维持 $s_k \le t$，且 $\sum_k s_k = S = 4t$。若某个 $s_k < t$，则 $\sum_k s_k < 4t$，矛盾。故所有 $s_k = t$。∎

**定理**：算法返回 `true` 当且仅当火柴能拼成正方形。

**证明**：由引理 1，只需证返回 `true` 与「存在 4 组和为 $t$ 的划分」等价。充分性：返回 `true` 意味着走过一条完整路径，由引理 4 四条边均为 $t$，再由引理 1 可拼成正方形。必要性：若存在这样的划分，由引理 3 搜索不会漏掉它，故必然返回 `true`。∎

## 6. 复杂度分析

- **时间（回溯版）**：最坏 $O(4^n)$，$n=15$ 时上界约 $1.07\times 10^9$；两条剪枝把实际搜索量压到很小，随机 15 根数据实测在毫秒级。
- **空间（回溯版）**：递归深度 $O(n)$，桶数组 $O(1)$，不计输入为 $O(n)$。
- **时间（位掩码 DP）**：$O(n2^n)$，$n=15$ 时约 $5\times 10^5$ 次转移。
- **空间（位掩码 DP）**：$O(2^n)$ 个 `int` 状态，$n=15$ 时约 $128$ KB。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
#include <numeric>
using namespace std;

class Solution {
public:
    bool makesquare(vector<int>& matchsticks) {
        long long total = accumulate(matchsticks.begin(), matchsticks.end(), 0LL);
        if (total % 4 != 0) return false;
        long long target = total / 4;
        sort(matchsticks.rbegin(), matchsticks.rend());
        if ((long long)matchsticks[0] > target) return false;
        vector<long long> sides(4, 0);
        return dfs(matchsticks, 0, sides, target);
    }

private:
    bool dfs(vector<int>& a, int i, vector<long long>& sides, long long target) {
        if (i == (int)a.size()) return true;
        for (int k = 0; k < 4; ++k) {
            if (sides[k] + a[i] > target) continue;              // 剪枝①
            if (k > 0 && sides[k] == sides[k - 1]) continue;     // 剪枝②
            sides[k] += a[i];
            if (dfs(a, i + 1, sides, target)) return true;
            sides[k] -= a[i];
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def makesquare(self, matchsticks: list[int]) -> bool:
        total = sum(matchsticks)
        if total % 4:
            return False
        target = total // 4
        sticks = sorted(matchsticks, reverse=True)
        if sticks[0] > target:
            return False
        sides = [0, 0, 0, 0]

        def dfs(i: int) -> bool:
            if i == len(sticks):
                return True
            for k in range(4):
                if sides[k] + sticks[i] > target:      # 剪枝①
                    continue
                if k > 0 and sides[k] == sides[k - 1]:  # 剪枝②
                    continue
                sides[k] += sticks[i]
                if dfs(i + 1):
                    return True
                sides[k] -= sticks[i]
            return False

        return dfs(0)
```

## 8. 边界情况与易错点

1. **总和不能被 4 整除**：如 `[1,1,1]`（$S=3$），必须先判死，否则搜索永远失败还白白跑一遍。
2. **最长火柴大于边长**：如 `[1,1,2,4]`，$S=8$、$t=2$ 但火柴长 4，即便总和能被 4 整除也无解；不提前判断会让首层就进入死路。
3. **火柴数少于 4**：如 `[4]`，$S=4$、$t=1$，此时 `max > t` 判定兜住；若漏写这个判断，会得到错误的 `true`。
4. **剪枝②的下标**：`k > 0` 不能省，C++ 中 `sides[-1]` 是未定义行为，Python 中会绕到最后一个桶，剪枝逻辑随之错乱。
5. **忘记回溯**：`sides[k] += a[i]` 之后必须在失败时减回去，否则同一根火柴被重复计入，答案偏 `true`。
6. **`accumulate` 的初值**：写 `accumulate(v.begin(), v.end(), 0)` 会按 `int` 运算，$1.5\times10^9$ 虽未溢出但离边界很近，用 `0LL`。
7. **位掩码版的哨兵**：`dp[mask] = -1` 表示不可达，余数 0 是合法值，不能拿 0 当哨兵；最后判 `dp[full] == 0` 而不是 `>= 0`。
8. **降序排序不能省**：省掉后剪枝①几乎失效，$n=15$ 的构造数据会退化到接近 $4^n$。
