# LeetCode 汉明距离 题解

## 1. 题目概述

- **标题 / 题号**：汉明距离（#461，easy）
- **链接**：https://leetcode.cn/problems/hamming-distance/
- **来源**：LeetCode 第 13 场周赛 Q1
- **难度**：简单
- **标签**：位运算

**题意**：两个整数之间的**汉明距离**定义为二者二进制表示中对应位取值不同的位置数目。给定 `x`、`y`，返回它们的汉明距离。题意也可读成「把 `x` 变成 `y` 最少要翻转几个二进制位」，两种表述等价。

**约束**：

- $0 \le x, y \le 2^{31} - 1$
- 两数都是非负机器字长整数，最多用到 bit 30（$2^{31}-1 = \underbrace{11\cdots1}_{31\text{ 位}}$）

本题与 [2220. 转换数字的最少位翻转次数](https://leetcode.cn/problems/minimum-bit-flips-to-convert-number/) 是同一道题，题面已注明。

## 2. 示例

**示例 1**

```text
输入：x = 1, y = 4
输出：2
解释：
1   (0 0 0 1)
4   (0 1 0 0)
       ↑   ↑
bit 2 与 bit 0 不同，共 2 位不同，故汉明距离为 2。
```

**示例 2**

```text
输入：x = 3, y = 1
输出：1
解释：
3   (0 0 1 1)
1   (0 0 0 1)
         ↑
只有 bit 1 不同，故答案为 1。
```

**示例 3（边界补充）**

```text
输入：x = 0, y = 2147483647   (即 2^31 - 1)
输出：31
解释：x 全为 0，y 的低 31 位全为 1，每一位都不同，故答案为 31。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是逐位比较：对 $i = 0, 1, \dots, 30$ 取 `(x >> i) & 1` 与 `(y >> i) & 1`，不同就累加。另一种写法是把两数都转成定长二进制串（如 `zfill(32)`）再逐字符比对。两种写法的复杂度都是 $O(32)$，本题范围下当然能过，但缺点明显：

- 需要自己决定循环到哪一位，位长写死 31 / 32 / 64 都容易出错；
- 把「找出不同的位」和「数出不同的个数」混在同一个循环里，代码不干净；
- 字符串写法还有长度对齐的坑，`bin(1)` 与 `bin(4)` 长度不同，必须补前导 0 才能对齐。

真正的目标是把**比较**与**计数**这两件事拆开，各自用最合适的工具。

### 3.2 核心观察：异或就是「差异位指示器」

![异或把逐位比较变成差异位图](images/wc13_q1_xor_concept.svg)

异或运算 $\oplus$ 是**按位独立**的：对每一位 $i$，$(x \oplus y)_i = x_i \oplus y_i$。而单比特异或的真值表恰好是「相同得 0、不同得 1」：

$$0 \oplus 0 = 0,\quad 0 \oplus 1 = 1,\quad 1 \oplus 0 = 1,\quad 1 \oplus 1 = 0$$

于是得到一个干净的恒等式：

$$\text{hamming}(x, y) = \sum_{i \ge 0} [x_i \ne y_i] = \sum_{i \ge 0} (x \oplus y)_i = \operatorname{popcount}(x \oplus y)$$

一次异或就把「哪些位不同」压缩进了 $n = x \oplus y$ 这一个整数里；剩下的问题只有一个：**数出 $n$ 的二进制表示里有多少个 1**，也就是 popcount（也称位计数）。注意求和时不存在进位干扰——每一位至多贡献 1，而二进制计数本身就是「1 的个数」的权值和。

### 3.3 算法流程与 popcount 的三种写法

![一次异或，三种数 1 的方式](images/wc13_q1_popcount_flow.svg)

```text
1. n = x ^ y              // 差异位图
2. cnt = popcount(n)      // 数 1
3. 返回 cnt
```

popcount 有三种常用实现，答案完全一致，只有循环次数不同：

- **移位法**：`while n: cnt += n & 1; n >>= 1`，逐位右移直到 `n` 归零，轮数等于最高有效位的位置；若按 32 位定长写 `for` 循环，则固定 32 轮（本题最多 31 轮）。
- **Brian Kernighan 法**：`while n: n &= n - 1; cnt += 1`。`n & (n-1)` 每次恰好清掉最低位的 1，因此**循环次数等于 popcount**，位稀疏时更快。
- **内置函数**：C++ 用 `__builtin_popcount`（C++20 起还有 `<bit>` 里的 `std::popcount`），Python 用 `bin(n).count("1")` 或 3.10+ 的 `int.bit_count()`，底层是单条指令或一次线性扫描。

### 3.4 示例演算

以示例 1 的 $x = 1$、$y = 4$ 为例，$n = 1 \oplus 4 = 5 = (0101)_2$：

![Kernighan 逐轮消 1 的走查](images/wc13_q1_walkthrough.svg)

| 轮次 | $n$ 的变化（`n &= n - 1`） | 计数值 |
|------|---------------------------|--------|
| 初始 | $0101$ | 0 |
| 第 1 轮 | $0101 \to 0100$（清掉 bit 0 的 1） | 1 |
| 第 2 轮 | $0100 \to 0000$（清掉 bit 2 的 1） | 2 |
| 退出 | $n = 0$，停止 | **2** |

移位法对照：$n \& 1$ 依次得到 $1, 0, 1, 0$，加起来同样为 2。再验示例 2：$x = 3 = (0011)_2$、$y = 1 = (0001)_2$，$n = 0010$，只有一个 1，答案为 1，与官方输出一致。

## 4. 算法细节

1. **先异或、再计数**：`int n = x ^ y;` 是所有写法的公共第一步，异或本身 $O(1)$，不要把它拆进循环里逐位做。
2. **`n & (n-1)` 为什么能清最低位 1**：设 $n$ 的最低位 1 在位置 $k$，则 $n-1$ 会把第 $k$ 位变 0、把 $0 \sim k-1$ 位全部由 0 变 1、$k$ 以上的位不变（这正是二进制减 1 的借位过程）。两者相与后，第 $k$ 位被清零，$0 \sim k-1$ 位本来就是 0 仍为 0，其余位不受影响——**每次恰好消灭一个 1**。
3. **循环终止条件是 `n == 0`**：Kernighan 写法千万不要再套一层 `for i in 0..31`，否则就退化成固定 32 轮，失去了「轮数 = popcount」的优势；同理，`n = 0` 时循环体一次都不进，`cnt` 初值必须是 0。
4. **无符号与越界**：约束保证 $x \oplus y \le 2^{31}-1$，仍落在 `int` 的非负区间内，因此 `x ^ y` 不会变成负数；但 `__builtin_popcount` 的形参是 `unsigned int`，显式写成 `__builtin_popcount((unsigned)(x ^ y))` 最稳妥，也避免将来放宽数据范围时踩坑。
5. **Python 的选择**：`bin(n).count("1")` 在任何版本都可用，代价是 $O(32)$ 的字符串；`int.bit_count()` 更直接但需要 3.10+（LeetCode 现役 Python3 已支持）。注意 `count(1)` 会抛 `TypeError`，参数必须是字符串 `"1"`。
6. **不要用减法求差集**：`popcount(x) - popcount(x & y)` 只统计了「x 有而 y 没有」的位，漏掉「y 有而 x 没有」的部分，答案会偏小，这是本题最常见的错误直觉。
7. **内置函数的名字别写错**：C++ 是 `__builtin_popcount`（两条前导下划线）与 `__builtin_popcountll`（`long long` 版）；`std::popcount` 需要 `#include <bit>` 且是 C++20。

## 5. 正确性证明

**引理 1（异或标记不同位）**：对任意位 $i$，$(x \oplus y)_i = 1$ 当且仅当 $x_i \ne y_i$。

**证明**：按单比特异或的真值表逐项验证：$0\oplus0=0$（相同得 0）、$1\oplus1=0$（相同得 0）、$0\oplus1=1$、$1\oplus0=1$（不同得 1）。四种输入组合穷尽，故命题成立。∎

**引理 2（Kernighan 每轮恰清一个 1）**：若 $n > 0$，则 $n \& (n-1)$ 的 popcount 恰为 $\operatorname{popcount}(n) - 1$，且消去的是 $n$ 的最低有效 1。

**证明**：设 $n$ 的最低有效 1 位于第 $k$ 位，即 $n = A \cdot 2^{k+1} + 2^k$（$A \ge 0$ 为高位部分）。则 $n - 1 = A \cdot 2^{k+1} + 2^k - 1 = A \cdot 2^{k+1} + (2^k - 1)$，其中 $2^k - 1$ 是 $k$ 个 1。于是 $n \& (n-1) = A \cdot 2^{k+1}$：第 $k$ 位由 1 变 0，低 $k$ 位由全 0 变全 1 后与全 0 相与仍为 0，高位 $A$ 不变。故 $n \& (n-1)$ 只少了第 $k$ 位这一个 1。∎

**定理**：算法返回的值等于 $x$ 与 $y$ 的汉明距离。

**证明**：由引理 1，$n = x \oplus y$ 的第 $i$ 位为 1 当且仅当 $x_i \ne y_i$，因此

$$\operatorname{popcount}(x \oplus y) = \#\{i : x_i \ne y_i\} = \text{hamming}(x, y)$$

而三种 popcount 实现都是精确计数：移位法逐位取 `n & 1` 累加后右移，等价于枚举每一位上的 1；Kernighan 法由引理 2 知每轮恰清一个 1，循环 $p$ 轮后 $n=0$ 当且仅当原本有 $p$ 个 1，故计数值为 popcount；内置函数按定义返回值中 1 的个数。三者与上式一致，故算法输出正确。∎

## 6. 复杂度分析

- **时间**：$O(1)$（按 32 位机器字长计）。一次异或为 $O(1)$；内置 popcount 是单条指令 $O(1)$；Kernighan 法为 $O(\operatorname{popcount}(x \oplus y)) \le O(32)$（本题最多 31）；移位法逐位右移、最多 32 轮（本题最多 31 轮，定长 `for` 写法则固定 32 轮）。按输入位长 $w = \lceil \log_2 \max(x,y) \rceil$ 记，则为 $O(w)$。
- **空间**：$O(1)$，只用了 `n` 与 `cnt` 两个整数。若在 Python 里用 `bin(n).count("1")`，会额外产生一个长度不超过 32 的临时字符串，仍为 $O(1)$（严格说是 $O(32)$ 常数空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int hammingDistance(int x, int y) {
        // 一次异或得到「差异位图」，再数 1 的个数
        return __builtin_popcount((unsigned int)(x ^ y));
    }
};
```

若不想依赖编译器内置函数，可换成 Kernighan 写法（循环次数 = 答案，可在位稀疏时提前结束）：

```cpp
class Solution {
public:
    int hammingDistance(int x, int y) {
        unsigned int n = (unsigned int)(x ^ y);
        int cnt = 0;
        while (n) {          // n == 0 时退出，轮数恰为 popcount
            n &= n - 1;      // 清掉最低位的 1
            ++cnt;
        }
        return cnt;
    }
};
```

### Python

```python
class Solution:
    def hammingDistance(self, x: int, y: int) -> int:
        return bin(x ^ y).count("1")


# 3.10+ 也可写成：return (x ^ y).bit_count()
```

## 8. 边界情况与易错点

1. **两数相等**：`x ^ y == 0`，Kernighan 循环一次也不进，返回 0；若把 `cnt` 初值写成 1 就会错。
2. **一位之差与 31 位之差**：$x=3, y=1$ 返回 1；$x=0, y=2^{31}-1$ 返回 31。后者接近 `INT_MAX`，用 `unsigned` 承接更安全。
3. **符号位陷阱**：本题约束确保 $x, y \ge 0$，`x ^ y` 不会为负。但若把范围放宽到负数（例如 `-1` 与 `0`），移位法里的 `n >>= 1` 是算术右移、负数会永远得到 `-1` 而陷入死循环；同时 `while (n)` 与补码表示绑在一起。稳妥写法是先把 `n` 转成 `unsigned`，再按 32 位固定轮数计数。
4. **把「数 1 的差」当成答案**：`popcount(x) - popcount(x & y)` 只算了「x 有而 y 没有」的那部分，例如 $x=(0011)_2$、$y=(1100)_2$ 时它给出 2，正确答案却是 4——必须用异或。
5. **`count(1)` 而非 `count("1")`**：Python 的 `str.count` 参数必须是字符串，写成 `count(1)` 直接抛 `TypeError`；同时别忘了 `bin()` 结果带 `0b` 前缀，好在 `b`、`0` 都不影响数 `"1"`。
6. **`__builtin_popcount` 的形参类型**：它接受 `unsigned int`，传入 `int` 会被隐式转换（非负数时无碍），但传入 `long long` 会被截断，此时应用 `__builtin_popcountll`。
7. **位长写死**：移位法里若写成 `for (int i = 0; i < 31; ++i)`，$2^{31}-1$ 恰好只用到 bit 30，看似够用；一旦数据范围变化就会漏位，建议用 `while (n)` 或 `32` 轮 + `unsigned`。
