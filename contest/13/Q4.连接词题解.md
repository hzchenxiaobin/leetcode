# LeetCode 连接词 题解

## 1. 题目概述

- **标题 / 题号**：连接词（#472，hard）
- **链接**：https://leetcode.cn/problems/concatenated-words/
- **来源**：LeetCode 第 13 场周赛 Q4
- **难度**：困难
- **标签**：深度优先搜索，字典树，数组，字符串，动态规划，排序

**题意**：给定一个不含重复字符串的数组 `words`，找出其中所有**连接词**——该字符串能由数组中**至少两个更短的单词**首尾相接拼成（组成单词可以重复使用同一个）。返回全部连接词，顺序不限。

**约束**：

- $1 \le \lvert words \rvert \le 10^4$
- $1 \le \lvert words[i] \rvert \le 30$
- `words[i]` 仅由小写英文字母组成
- `words` 中所有字符串互不相同
- $1 \le \sum \lvert words[i] \rvert \le 10^5$

## 2. 示例

**示例 1**

```text
输入：words = ["cat","cats","catsdogcats","dog","dogcatsdog","hippopotamuses","rat","ratcatdogcat"]
输出：["catsdogcats","dogcatsdog","ratcatdogcat"]
解释："catsdogcats" = "cats" + "dog" + "cats"
     "dogcatsdog" = "dog" + "cats" + "dog"
     "ratcatdogcat" = "rat" + "cat" + "dog" + "cat"
     "hippopotamuses" 无法由任何更短单词拼成
```

**示例 2**

```text
输入：words = ["cat","dog","catdog"]
输出：["catdog"]
解释："catdog" = "cat" + "dog"；"cat" 与 "dog" 都没有更短的组成部分
```

## 3. 解题思路

### 3.1 暴力思路

对每个单词 $w$（$|w| \le 30$）枚举所有"切成至少两段"的方案：$|w|-1$ 个空隙各选「切 / 不切」，共 $2^{|w|-1} \le 2^{29}$ 种，每段再去哈希表里查——单个单词就指数级，$10^4$ 个单词必然超时。换成 DFS 贪心匹配「字典中的某个单词」也不保险：像 `"aaaaaaaa..."` 配 `a, aa, aaa` 三种段长，搜索树照样指数级膨胀——**同一个前缀被反复搜索**，这正是 DP 要消灭的重叠子问题。

### 3.2 核心观察：只让"更短的单词"进字典树

![按长度升序 + 字典树 + 前缀 DP](images/wc13_q4_trie_split_concept.svg)

关键事实（§5 引理 1 会证明）：**若 $w$ 是连接词，它的每一段都严格短于 $w$**——拼接至少两段，且每段非空。于是：

1. 把所有单词**按长度升序**排序，逐个处理；
2. 处理 $w$ 时字典树里只有「更短的单词」，**检查完再插入 $w$**。

这样树里永远没有 $w$ 自身，"必须由更短单词拼成"被**结构性地**满足；而「某段是否是字典单词」只要沿 Trie 走一步，$O(1)$，不用字符串比较。

### 3.3 算法流程：前缀可达性 DP

![算法流程与 dp 转移](images/wc13_q4_dp_flow.svg)

设 `dp[i]` 表示用 Trie 中的单词拼出前缀 $w[0..i)$ 所需的**最少单词数**（拼不出记 $\infty$）。转移不要"先枚举切点再查表"，而是**从每个可达位置出发沿 Trie 往下走**：

$$\text{dp}[0]=0,\qquad \text{dp}[j+1]=\min\bigl(\text{dp}[j+1],\ \text{dp}[i]+1\bigr)\quad\bigl(\text{dp}[i]<\infty,\ \text{Trie 上 } w[i..j] \text{ 是完整单词}\bigr)$$

最后看 `dp[n]`，$\ge 2$ 即 $w$ 是连接词。

> 💡 为什么记"最少段数"而不是布尔值：布尔值只能说"能拼"；记段数后一句 `dp[n] ≥ 2` 同时排除了「整词恰好等于字典中某个单词」的情形，语义直白，还顺便拿到最优切分。

### 3.4 示例演算

![示例 1 的走查表](images/wc13_q4_walkthrough.svg)

对 `"catsdogcats"`（长度 11），此时 Trie 中只有 `cat, dog, rat, cats` 等更短的词：

| 起点 $i$ | `dp[i]` | 沿 Trie 匹配 | 更新 |
|---------|---------|--------------|------|
| 0 | 0 | `cat`（到 3）、`cats`（到 4） | `dp[3]=1`、`dp[4]=1` |
| 3 | 1 | 从 `s` 出发没有单词 | 无 |
| 4 | 1 | `dog`（到 7） | `dp[7]=2` |
| 7 | 2 | `cats`（到 11） | `dp[11]=3` |

`dp[11] = 3 ≥ 2`，判定为连接词。而 `"hippopotamuses"` 从起点 0 沿 Trie 就断了（没有以 `h` 开头的单词），`dp[14] = ∞`，不是连接词。

## 4. 算法细节

1. **排序键**：只按长度升序即可。等长单词谁先谁后都不影响正确性——拼成长度 $L$ 的词至少要两段，每段长度都 $< L$，所以等长单词永远不可能成为彼此的组成部分；加字典序做次级键只是让输出更稳定。
2. **结点编号**：根是 0 号结点，孩子指针用 0 表示"空"，新结点从 1 开始编号；C++ 用 `array<int,26>` 拍平（$26\times10^5$ 个 `int` 约 10 MB），Python 用 `list[dict]` 稀疏存储。
3. **先查后插**：每个单词必须走「用当前 Trie 检查 $w$」→「记录答案」→「再把 $w$ 插入」。写反顺序，则 `dp[n]` 恒为 1，**所有单词都会被误判成连接词**。
4. **转移方向**：外层枚举可达起点 $i$（`dp[i] != INF`），内层沿 Trie 从 $i$ 向后走，遇到终止结点就用 `dp[i]+1` 松弛 `dp[j+1]`。每对 $(i,j)$ 只花 $O(1)$，全程不切片、不 `substr`。
5. **提前退出**：`w` 自身不在树中，所以 `dp[n]` 不可能降到 1；一旦某轮结束后 `dp[n] == 2`，就直接返回 2。这条剪枝在 `"aaaa…"` 这类稠密匹配上收益明显。
6. **INF 的选择**：Python 取 $10^9$，`min` 不会溢出；C++ 取 `1e9` 的 `int`，`dp[i]+1` 远小于 `INT_MAX`，无需特判。

## 5. 正确性证明

**引理 1（组成部分严格更短）**：若 $w=p_1p_2\cdots p_k$ 且 $k\ge 2$、每段非空，则对任意 $i$ 有 $\lvert p_i\rvert < \lvert w\rvert$。

**证明**：$\lvert w\rvert=\sum_{t=1}^{k}\lvert p_t\rvert \ge \lvert p_i\rvert + (k-1) \ge \lvert p_i\rvert + 1$，因为其余 $k-1\ge 1$ 段都至少 1 个字符。∎

**引理 2（处理时机）**：按长度升序处理到 $w$ 时，字典树中包含且仅包含「排在 $w$ 之前的单词」，它们的长度都 $\le \lvert w\rvert$，并且其中**没有** $w$。

**证明**：算法对每个单词"先检查、后插入"，故树中恰为已处理过的单词；排序保证这些单词长度不超过 $\lvert w\rvert$。又数组内单词互不相同，而 $w$ 尚未插入，故树中不含 $w$。∎

**引理 3（dp 语义）**：DP 结束时 `dp[i]` 等于用 Trie 中单词拼出前缀 $w[0..i)$ 的最少单词数；不可拼出时为 $\infty$。

**证明**：上界——设 `dp[i]` 有限，则存在 $i'$ 使 `dp[i']` 有限且 $w[i'..i)$ 是 Trie 中的单词，`dp[i] ≤ dp[i']+1`；对 $i$ 归纳可知每个有限值都对应真实切分，故 `dp[i]` 不小于最优值。下界——设用 $m$ 个单词拼出 $w[0..i)$ 的最优方案，最后一段为 $w[i'..i)$，由归纳假设 `dp[i']` 不超过拼出前 $m-1$ 段所需的段数，而算法枚举起点 $i'$ 时必然沿 Trie 走到 $i$ 并松弛，故 `dp[i] ≤ m`。两端夹逼即得结论；无切分时任何松弛都不写入，故为 $\infty$。∎

**引理 4（判定等价）**：`min_parts(w) ≥ 2` 当且仅当 $w$ 能由至少两个更短的单词拼成。

**证明**：
- ($\Leftarrow$) 设 $w=p_1\cdots p_k$、$k\ge 2$、各 $p_t$ 是数组中的更短单词。由引理 1 有 $\lvert p_t\rvert<\lvert w\rvert$，再由引理 2 这些单词全在 Trie 中，逐段跳转可证 `dp[n]` 有限且 $\le k$；另一方面 `dp[n]≠1`——否则整词匹配一个长度等于 $\lvert w\rvert$ 的 Trie 单词，与「树中不含 $w$」矛盾——故 `dp[n]≥2`。
- ($\Rightarrow$) 若 `dp[n]≥2`，由引理 3 存在一个把 $w$ 切成 `dp[n]≥2` 段的合法方案，每段都是 Trie 中单词；由引理 2 它们都是数组中的单词，长度 $\le\lvert w\rvert$ 且不等于 $w$，故都严格更短。$w$ 是连接词。∎

**定理**：算法返回的集合恰为数组中全部连接词。

**证明**：每个单词恰好被检查一次，且由引理 2 检查时 Trie 的构成与算法前提一致；由引理 4，`min_parts(w)≥2` 与「$w$ 是连接词」等价。故加入答案的恰为全部连接词，无遗漏、无误报。∎

## 6. 复杂度分析

- **时间**：建树 $O\bigl(\sum\lvert w\rvert\bigr)$。对单词 $w$，DP 最多 $|w|$ 个起点，每个起点沿 Trie 走不超过 $|w|$ 步，$O(\lvert w\rvert^2)$。总计 $O\bigl(\sum\lvert w\rvert^2\bigr) \le O\bigl(L_{\max}\cdot\sum\lvert w\rvert\bigr)$，代入 $L_{\max}=30$、$\sum\lvert w\rvert\le10^5$ 约为 $3\times10^6$ 次操作。
- **空间**：Trie 结点数 $\le 1+\sum\lvert w\rvert$；C++ 每结点 26 个 `int`（约 104 B），最坏约 $10$ MB；Python 每个字典只存真实存在的边，共 $O\bigl(\sum\lvert w\rvert\bigr)$ 个键值对。DP 数组 $O(L_{\max})$，答案本身不计入辅助空间。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <array>
#include <algorithm>
using namespace std;

class Solution {
    vector<array<int, 26>> nxt;   // 0 号结点既是根，也表示"空指针"
    vector<char> fin;             // 是否是某个单词的结尾

    void insert(const string& w) {
        int p = 0;
        for (char c : w) {
            int k = c - 'a';
            if (nxt[p][k] == 0) {
                nxt[p][k] = (int)nxt.size();
                nxt.push_back(array<int, 26>{});
                fin.push_back(0);
            }
            p = nxt[p][k];
        }
        fin[p] = 1;
    }

    int minParts(const string& w) {
        int n = (int)w.size();
        const int INF = 1e9;
        vector<int> dp(n + 1, INF);
        dp[0] = 0;
        for (int i = 0; i < n; i++) {
            if (dp[i] == INF) continue;
            int p = 0;
            for (int j = i; j < n; j++) {
                p = nxt[p][w[j] - 'a'];
                if (p == 0) break;               // 前缀已不在树中，后面更不可能
                if (fin[p] && dp[i] + 1 < dp[j + 1]) dp[j + 1] = dp[i] + 1;
            }
            if (dp[n] == 2) return 2;            // 已切成两段，且不会降到 1
        }
        return dp[n] == INF ? -1 : dp[n];
    }

public:
    vector<string> findAllConcatenatedWordsInADict(vector<string>& words) {
        vector<string> s(words);
        sort(s.begin(), s.end(), [](const string& a, const string& b) {
            if (a.size() != b.size()) return a.size() < b.size();
            return a < b;
        });
        nxt.assign(1, array<int, 26>{});
        fin.assign(1, 0);
        vector<string> ans;
        for (const string& w : s) {
            if (minParts(w) >= 2) ans.push_back(w);  // 先检查
            insert(w);                               // 后插入
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findAllConcatenatedWordsInADict(self, words: list[str]) -> list[str]:
        words = sorted(set(words), key=lambda w: (len(w), w))
        nxt = [{}]
        end = [False]

        def insert(w: str) -> None:
            p = 0
            for ch in w:
                q = nxt[p].get(ch)
                if q is None:
                    q = len(nxt)
                    nxt[p][ch] = q
                    nxt.append({})
                    end.append(False)
                p = q
            end[p] = True

        def min_parts(w: str) -> int:
            n = len(w)
            INF = 10 ** 9
            dp = [INF] * (n + 1)
            dp[0] = 0
            for i in range(n):
                if dp[i] == INF:
                    continue
                p = 0
                for j in range(i, n):
                    p = nxt[p].get(w[j])
                    if p is None:
                        break              # 前缀不在树中，剪枝
                    if end[p] and dp[i] + 1 < dp[j + 1]:
                        dp[j + 1] = dp[i] + 1
                if dp[n] == 2:             # 已切成两段，且不会降到 1
                    return 2
            return -1 if dp[n] == INF else dp[n]

        ans = []
        for w in words:
            if min_parts(w) >= 2:          # 先检查
                ans.append(w)
            insert(w)                      # 后插入
        return ans
```

## 8. 边界情况与易错点

1. **先插后查 → 全员误判**：本题第一大坑。必须"先检查、再插入"，否则整词会匹配到自己（`dp[n]=1`），所有单词都被判为连接词。
2. **空答案**：没有任何连接词时返回 `[]`（C++ 的 `vector<string>` 保持为空），不要塞空串或返回野指针。
3. **长度为 1 的单词**：不可能是连接词（两段各至少 1 字符，总长 $\ge 2$），可以不检查，但**插入不能漏**——它是别人（如 `"aa"`）的组成部分。
4. **同一单词可重复使用**：`"aa" = "a"+"a"`，Trie 中单词允许被多次经过，DP 不需要任何"用过即删"的标记。
5. **等长单词**：只有长度严格不同才可能产生"组成"关系，等长单词可以放进同一批处理，不必额外分组。
6. **`dp` 初值**：必须用 $\infty$ 而非 0/-1，否则"拼不出"会被当成"0 段"，把 `"a"` 这类单词误判为连接词（Python 侧最容易踩）。
7. **输出顺序**：题目对顺序不敏感；若判题环境要求稳定顺序，可在返回前按原下标重排（C++ 用 `unordered_map<string,int>` 记下标）。

**延伸思考**：

- 把「至少两个单词」改成「恰好 $k$ 个单词」时，把 `dp` 从"最少段数"换成"可达段数集合"或"$\min(k,\cdot)$ 的计数"即可，复杂度只多一个 $k$ 的因子。
- 若要求输出**最长的**连接词，按长度降序检查、第一个满足条件的就是答案，DP 本身不用改。
- 若单词平均长度变大（如 $\lvert w\rvert\le10^3$），$O(\lvert w\rvert^2)$ 的单词开销会成为瓶颈，可换「按长度分桶 + 滚动哈希」或 AC 自动机做多模式匹配，把每段匹配降到摊还 $O(1)$。
- 另一个等价思路是**哈希集合 + 记忆化 DFS**：`f(i)` 表示后缀 `w[i:]` 能否拼出，状态数 $O(\lvert w\rvert^2)$；Trie 的优势是"前缀断了立刻停"，且完全不碰哈希碰撞。
