# LeetCode 坏了的计算器 题解

## 1. 题目概述

- **标题 / 题号**：坏了的计算器（#991，medium）
- **链接**：https://leetcode.cn/problems/broken-calculator/
- **来源**：LeetCode 第 123 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数学

**题意**：显示屏初始值为 $startValue$，只允许两种操作：

1. **双倍**：$x \to 2x$；
2. **递减**：$x \to x - 1$。

求把 $startValue$ 变成 $target$ 所需的**最少操作数**。

**约束**：

- $1 \le startValue, target \le 10^9$

> 💡 目标值可以比起点小（此时只能一路递减），也可以比起点大（此时需要加倍与递减配合）。$10^9$ 的量级排除了逐状态搜索，必须找到 $O(\log)$ 的贪心规律。

## 2. 示例

**示例 1**

```text
输入：startValue = 2, target = 3
输出：2
解释：2 → 4 → 3（先双倍再递减）。
```

**示例 2**

```text
输入：startValue = 5, target = 8
输出：2
解释：5 → 4 → 8（先递减再双倍）。
```

**示例 3**

```text
输入：startValue = 3, target = 10
输出：3
解释：3 → 6 → 5 → 10（双倍、递减、双倍）。
```

示例 2 说明「先变大再变小」并非总是最优：有时先减小再加倍更省。

## 3. 解题思路

### 3.1 暴力思路

BFS 从 $startValue$ 出发，每次扩展 $2x$ 与 $x-1$，第一次到达 $target$ 即为答案。状态空间是 $[1, 2 \cdot 10^9]$，规模太大；即便限制搜索范围，也无法在题目限制内完成。而朴素的 DFS 会在「先加倍再大量递减」与「先递减再加倍」之间反复试探，分支指数级。

### 3.2 核心观察：反着走，操作几乎被唯一确定

![正向难贪心，逆向只有一条路](images/wc123_q3_reverse_greedy.svg)

把过程倒过来看：从 $target$ 出发，每一步能做的逆向操作是

- **除以 2**：仅当当前值是**偶数**时合法（对应正向的「双倍」）；
- **加 1**：始终合法（对应正向的「递减」）。

于是：

- 当前值为**奇数**时，「除以 2」不合法，**只能加 1**——选择被唯一化；
- 当前值为**偶数**时，「除以 2」让数值减半，显然比「加 1」更快接近目标。

当值降到 $\le startValue$ 时，逆向的「加 1」已经不可能再缩小数值，剩下的差值只能由正向的「递减」补上，共 $startValue - target'$ 步。

关键的正确性直觉是：**偶数时除以 2 不会比加 1 差**。因为加 1 之后是奇数，下一步还是只能加 1，凭空多花两步却只把数值变大——反而是「先减半」更省。

### 3.3 算法流程

```text
1. ops = 0
2. while target > startValue:
       若 target 是偶数: target /= 2
       否则:            target += 1
       ops += 1
3. 返回 ops + (startValue - target)
```

复杂度 $O(\log target)$：偶数时值减半，奇数时加 1 变偶数、下一步必减半，因此每两轮至少缩小一半。

### 3.4 示例演算

![示例 3 的正向与逆向路径](images/wc123_q3_walkthrough.svg)

对 $startValue = 3$、$target = 10$：

| 逆向步 | 当前值 | 奇偶 | 操作 | 说明 |
|--------|--------|------|------|------|
| 1 | 10 | 偶 | $/2 \to 5$ | 正向对应最后一步「双倍」 |
| 2 | 5 | 奇 | $+1 \to 6$ | 正向对应「递减」 |
| 3 | 6 | 偶 | $/2 \to 3$ | 到达起点，结束 |

共 3 步，$3 = startValue$，补差为 0，答案 3。正向看就是 $3 \to 6 \to 5 \to 10$，与题面一致。

再看示例 2：$target = 8$ 偶 $\to 4$，此时 $4 \le 5$，补差 $5 - 4 = 1$，答案 $1 + 1 = 2$，对应正向 $5 \to 4 \to 8$ ✓。

## 4. 算法细节

1. **循环条件**：`while (target > startValue)`，一旦 $\le$ 就跳出，用一次减法补齐差值，避免在「加 1」上空转。
2. **奇偶判断**：`target % 2 == 0`；$target$ 始终为正，无需考虑负数取模。
3. **整数除法**：C++ 的 `/` 与 Python 的 `//` 对正数都是向下取整，安全。
4. **答案类型**：最坏情况 $1 \to 2$ 只需 1 步，$10^9 \to 1$ 需要约 $10^9$ 步递减，但那是 $startValue > target$ 的分支，一步减法直接得出；实际 `ops` 规模是 $O(\log target)$，`int` 足够。
5. **不修改输入**：$startValue$ 只读，$target$ 作为局部变量递减使用。

## 5. 正确性证明

记 $d(s, t)$ 为从 $s$ 变到 $t$ 的最少操作数（$s$ 固定，故简写 $d(t)$）。

**引理 1（起点不小于终点）**：若 $t \le s$，则 $d(t) = s - t$。

**证明**：**上界**：连续做 $s - t$ 次递减即可，代价 $s - t$。

**下界**：设某个解的总代价为 $C$ 且含至少一次双倍（若不含双倍，则只能一路递减，$C = s - t$，已是最优）。取该解中**最后一次**双倍，设其前一刻的值为 $v \ge 1$，此后连续 $r$ 次递减到达 $t$，于是 $t = 2v - r$，即 $r = 2v - t \ge 0$，且 $C = C_v + 1 + r$，其中 $C_v$ 是到达 $v$ 的代价。分两种情形：

1. $v \ge s$：由 $s \ge t$ 得 $r = 2v - t \ge 2s - t \ge s + (s - t) \ge s - t$，故 $C \ge 1 + r > s - t$。
2. $v < s$：从 $s$ 出发只能靠递减到达 $v$（双倍只会把值推得更大），故 $C_v \ge s - v$，于是 $C \ge (s - v) + 1 + (2v - t) = (s - t) + v + 1 > s - t$（因 $v \ge 1$）。

两种情形下含双倍的解都严格劣于纯递减，故 $d(t) = s - t$。∎

**引理 2（奇数只能加 1）**：若 $t > s$ 且 $t$ 为奇数，则 $d(t) = 1 + d(t+1)$。

**证明**：任何解的最后一步要么是双倍、要么是递减。双倍的结果必为偶数，不可能得到奇数 $t$，所以最后一步必是递减，来自 $t+1$。故 $d(t) = 1 + d(t+1)$（取最优的前缀）。∎

**引理 3（偶数可令双倍收尾）**：若 $t > s$ 且 $t$ 为偶数，则 $d(t) = 1 + d(t/2)$。

**证明**：**上界**：先按最优方案到达 $t/2$（$t/2 \ge 1$），再双倍，代价 $d(t/2) + 1$，故 $d(t) \le d(t/2) + 1$。

**下界**：任取最优解，因 $t > s$ 而递减只会减小数值，解中必有双倍。取**最后一次**双倍，设其前一刻的值为 $v$，此后连续 $r$ 次递减到达 $t$，于是 $t = 2v - r$，该解代价 $C = C_v + 1 + r$（$C_v$ 为到达 $v$ 的代价）。由 $t$ 偶、$2v$ 偶得 $r$ 必为偶，令 $r = 2q$。改造该解：到达 $v$ 后改为递减 $q$ 次到 $v - q = (2v - r)/2 = t/2$，再双倍到 $t$，代价 $C' = C_v + q + 1 \le C_v + 2q + 1 = C$（因 $q \le 2q$）。故存在一个代价不超过 $C$、且以双倍收尾的解；它必为最优（$C$ 已是最小），于是其前缀到达 $t/2$ 的代价 $\ge d(t/2)$，得 $d(t) \ge d(t/2) + 1$。两向合并即得等号。∎

**定理**：上述贪心算法返回的正是最少操作数。

**证明**：对 $t$ 做强归纳，证明「贪心值 $g(t) = d(t)$」。当 $t \le s$：贪心返回 $s - t$，由引理 1 正确。当 $t > s$：
- $t$ 奇：由引理 2，$d(t) = 1 + d(t+1)$；贪心先做 $+1$（即正向递减的逆）再对 $t+1$ 递归，$g(t) = 1 + g(t+1)$。注意 $t+1$ 为偶数，由引理 3，$d(t+1) = 1 + d((t+1)/2)$，且 $(t+1)/2 < t$（$t \ge 2$），归纳假设给出 $d((t+1)/2) = g((t+1)/2)$，而贪心对 $t+1$ 恰是「减半后递归」，故 $g(t+1) = 1 + g((t+1)/2) = d(t+1)$。
- $t$ 偶：由引理 3，$d(t) = 1 + d(t/2)$，$t/2 < t$，归纳假设给出 $d(t/2) = g(t/2)$，而贪心正是「减半后递归加一」，故 $g(t) = d(t)$。

归纳成立，贪心最优。∎

## 6. 复杂度分析

- **时间**：$O(\log target)$。偶数步值减半；奇数步加 1 后下一步必为偶数再减半，故每两轮至少让值缩小一半，循环次数不超过 $2 \log_2 target \approx 60$（$target \le 10^9$）。
- **空间**：$O(1)$。只用两个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int brokenCalc(int startValue, int target) {
        int ops = 0;
        while (target > startValue) {
            if (target % 2 == 0) target /= 2;
            else target += 1;
            ops++;
        }
        return ops + (startValue - target);
    }
};
```

### Python

```python
class Solution:
    def brokenCalc(self, startValue: int, target: int) -> int:
        ops = 0
        while target > startValue:
            if target % 2 == 0:
                target //= 2
            else:
                target += 1
            ops += 1
        return ops + (startValue - target)
```

## 8. 边界情况与易错点

1. **`startValue >= target`**：循环不进入，直接返回差值，如 `5, 3 → 2`、`5, 5 → 0`。
2. **奇数的处理**：奇数必须加 1，不能「减 1 再除 2」——逆向操作里没有减 1。
3. **先加 1 还是先减半**：偶数时若先加 1 会变成奇数、再被迫加 1，白花两步，务必先减半。
4. **差值的符号**：`startValue - target` 在跳出循环时必为非负（因 `target <= startValue`），不要写成 `target - startValue`。
5. **大数溢出**：$target$ 加 1 最多到 $10^9 + 1$，`int` 安全；若题面上限改成 $2^{31}-1$，加 1 会溢出，需用 `long long`。
6. **不需要记忆化**：贪心路径唯一，不存在重复子问题，无需 DP 或哈希表。
7. **示例 2 的启示**：先递减后双倍可能优于先双倍，贪心在逆向恰好给出「先减半」的选择，不要去正向硬猜。
