# LeetCode 最大唯一数 题解

## 1. 题目概述

- **标题 / 题号**：最大唯一数（#1133，easy）
- **链接**：https://leetcode.cn/problems/largest-unique-number/
- **来源**：LeetCode 第 5 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序

**题意**：给定一个整数数组 `nums`，返回其中**只出现一次**的最大整数；若每个整数都出现不止一次，返回 $-1$。

**约束**：

- $1 \le nums.length \le 2000$
- $0 \le nums[i] \le 1000$

## 2. 示例

**示例 1**

```text
输入：nums = [5,7,3,9,4,9,8,3,1]
输出：8
解释：数组最大值 9 出现了两次，不能选；8 只出现一次，是答案。
```

**示例 2**

```text
输入：nums = [9,9,8,8]
输出：-1
解释：没有任何数恰好出现一次。
```

**示例 3（边界补充）**

```text
输入：nums = [1000,1000,0]
输出：0
解释：1000 出现两次被排除；0 只出现一次，0 也是合法答案（不要误以为 0 等价于「无答案」）。
```

## 3. 解题思路

### 3.1 暴力思路

对每个元素 $x$ 都线性扫描整个数组统计出现次数，取满足「次数为 1」的最大者，时间 $O(n^2)$、空间 $O(1)$。$n \le 2000$ 时约 $4 \times 10^6$ 次比较，勉强能过，但毫无必要——出现次数显然可以**一趟**统计出来。另一条暴力路是排序后找「左右邻居都不等于自己」的最大段首，$O(n \log n)$，也能过，但仍逊于线性做法。

### 3.2 核心观察：值域很小 → 计数数组 + 倒序扫描

![核心观察：计数桶模型与从大到小扫描](images/bw5_q1_count_scan_model.svg)

两个观察直接确定最优做法：

1. **值域只有 $[0, 1000]$**，共 1001 个可能取值。用一个 `int cnt[1001]` 数组一趟遍历即可完成计数，比通用哈希表更快、更省，还天然把「按值有序」的信息免费送上——**计数数组的下标就是有序的值**。
2. **要的是最大值**：把 $v$ 从 $1000$ 往 $0$ 递减扫描，**第一个**满足 $cnt[v] = 1$ 的 $v$ 就是答案；扫到底都没有则返回 $-1$。不需要排序，也不需要在哈希表里再求 max。

两步合起来：一次 $O(n)$ 计数 + 一次 $O(1001)$ 扫描，总时间 $O(n + V)$，空间 $O(V)$，其中 $V = 1001$ 为值域大小。

### 3.3 算法流程

![算法流程：建计数数组、降序扫描、判定返回](images/bw5_q1_algorithm_flow.svg)

```text
1. cnt[0..1000] 清零
2. 遍历 nums：cnt[x]++
3. for v = 1000 downto 0:
       若 cnt[v] == 1：返回 v
4. 返回 -1                # 每个值都出现 ≥ 2 次
```

### 3.4 示例演算

![示例演算：两组官方数据的计数表与扫描结果](images/bw5_q1_example_walkthrough.svg)

**示例 1**（$nums = [5,7,3,9,4,9,8,3,1]$）：计数得 $cnt[1]=cnt[4]=cnt[5]=cnt[7]=cnt[8]=1$，$cnt[3]=cnt[9]=2$。从 $1000$ 往下扫：$9$ 出现 2 次跳过，$8$ 恰好 1 次 → 返回 $8$。

**示例 2**（$nums = [9,9,8,8]$）：$cnt[8] = cnt[9] = 2$，从 $9$ 扫到 $0$ 都不满足 $cnt[v] = 1$ → 返回 $-1$。

## 4. 算法细节

1. **计数数组 vs 哈希表**：值域上界 1000 是题面明示的礼物。`vector<int> cnt(1001)` / `int cnt[1001]` 连哈希函数的开销都省了；若值域放宽（如 $10^9$），才需要换 `unordered_map<int,int>`，最后再对「次数为 1 的键集合」求 max。
2. **扫描方向**：必须**从大到小**扫，保证第一个命中的就是最大值；从小到大扫再取最后命中也行，但要多一个变量记录，且语义绕。
3. **返回值语义**：题目约定「无唯一数返回 $-1$」，而 $0$ 是合法元素值。用「先扫描后返回」的自然结构就不会混淆——循环里命中任何 $v$（包括 $0$）都直接返回，循环自然结束才返回 $-1$。
4. **下标即值**：不要把「值」和「下标」搞混，$cnt[v]$ 存的是值 $v$ 的出现次数，而不是下标 $v$ 处的元素。

## 5. 正确性证明

**引理 1（计数正确性）**：一趟遍历后，对每个 $v \in [0, 1000]$ 有 $cnt[v] = |\{i : nums[i] = v\}|$。

**证明**：初始时所有 $cnt[v] = 0$。遍历到 $nums[i] = x$ 时执行 $cnt[x]$ 自增 1，且只影响 $cnt[x]$。故遍历结束时 $cnt[v]$ 恰好等于遍历中值等于 $v$ 的元素个数。∎

**定理**：算法返回的值等于数组中只出现一次的最大整数；若不存在这样的整数，返回 $-1$。

**证明**：设 $S = \{v \in [0, 1000] : cnt[v] = 1\}$。由引理 1，$S$ 正是「出现次数为 1」的全体取值。若 $S \ne \varnothing$，设 $v^* = \max S$。降序扫描时，所有大于 $v^*$ 的 $v$ 都不在 $S$ 中（$cnt[v] \ne 1$），循环在 $v = v^*$ 处首次满足条件并返回 $v^*$，即最大唯一数。若 $S = \varnothing$，循环全程无命中，自然结束返回 $-1$。∎

## 6. 复杂度分析

- **时间**：$O(n + V)$。计数一趟 $O(n)$，降序扫描 $O(V)$，$V = 1001$ 为常数级。
- **空间**：$O(V)$。计数数组 1001 个整数，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int largestUniqueNumber(vector<int>& nums) {
        int cnt[1001] = {0};                 // 0 <= nums[i] <= 1000，值域小 → 计数数组
        for (int x : nums) ++cnt[x];
        for (int v = 1000; v >= 0; --v)      // 从大到小找第一个恰好出现一次的值
            if (cnt[v] == 1) return v;
        return -1;                           // 每个值都重复出现
    }
};
```

### Python

```python
class Solution:
    def largestUniqueNumber(self, nums: list[int]) -> int:
        cnt = [0] * 1001                    # 0 <= nums[i] <= 1000
        for x in nums:
            cnt[x] += 1
        for v in range(1000, -1, -1):       # 从大到小找恰好出现一次的值
            if cnt[v] == 1:
                return v
        return -1
```

> 💡 两份代码均通过官方示例（`8`、`-1`）、单元素/全重复/含 0 边界，以及 1 万组（C++）/5 千组（Python）随机数据与「降序排序找孤立段」暴力的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **0 是合法答案**：$cnt[0] = 1$ 时应返回 $0$，而不是当作「没找到」；把「返回 0」和「返回 -1」混用（例如用 `cnt[v]` 直接当返回值）是本题最阴的坑。
2. **单个元素**：$n = 1$ 时唯一元素必然只出现一次，直接返回它。
3. **全部重复**：如 $[7,7,7]$，必须返回 $-1$；降序扫描自然覆盖，无需特判。
4. **值域边界**：$1000$ 与 $0$ 都在值域内，数组大小开 $1001$，循环上界写 $1000$、下界写 $0$。
5. **别用浮点或除法**：本题不涉及，但若改写成「次数恰为一半」之类的变体，记得用整数比较。
6. **哈希表版别忘求 max**：如果用 `Counter`，要在「次数为 1 的键」里取 max，`max((v for v, c in cnt.items() if c == 1), default=-1)` 一行即可，注意 `default` 处理空集。
