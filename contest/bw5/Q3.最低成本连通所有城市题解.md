# LeetCode 最低成本连通所有城市 题解

## 1. 题目概述

- **标题 / 题号**：最低成本连通所有城市（#1135，medium）
- **链接**：https://leetcode.cn/problems/connecting-cities-with-minimum-cost/
- **来源**：LeetCode 第 5 场双周赛 Q3
- **难度**：中等
- **标签**：并查集、图、最小生成树、堆（优先队列）

**题意**：有 $N$ 座编号 $1 \sim N$ 的城市与若干候选连接 `connections[i] = [city1, city2, cost]`（无向，花费 `cost` 把两城相连）。要求选出一些连接，使**任意两座城市之间都有路径可达**，且总花费最小。无法连通时返回 $-1$。

**约束**：

- $1 \le N \le 10^4$
- $1 \le connections.length \le 10^4$
- $1 \le connections[i][0], connections[i][1] \le N$
- $0 \le connections[i][2] \le 10^5$
- `connections[i][0] != connections[i][1]`（无自环；**重边可能存在**）

## 2. 示例

**示例 1**

```text
输入：N = 3, connections = [[1,2,5],[1,3,6],[2,3,1]]
输出：6
解释：任选 2 条边即可连通，选最便宜的 (2,3,1) 与 (1,2,5)，总花费 1 + 5 = 6。
```

**示例 2**

```text
输入：N = 4, connections = [[1,2,3],[3,4,4]]
输出：-1
解释：{1,2} 与 {3,4} 两个连通块之间没有任何边，无法全部连通。
```

**示例 3（边界补充）**

```text
输入：N = 1, connections = []
输出：0
解释：单城无需任何连接；n−1 = 0 条边即已"生成树"。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有边的子集（$2^M$ 种，$M \le 10^4$），检查是否连通并取最小花费——指数爆炸，显然不可行。退一步的「正确暴力」是 Prim 算法：任取起点，每轮把「与当前树相连的最小权边」扩展进来，朴素实现 $O(N^2 + M)$，在 $N = 10^4$ 时约 $10^8$ 次操作，勉强但难看。本题真正的考点是识别出**最小生成树（MST）模型**并熟练写出 Kruskal 或堆优化 Prim。

### 3.2 核心观察：连通所有城市的最省方案 = 最小生成树

![核心观察：Kruskal按边权升序贪心选边](images/bw5_q3_kruskal_model.svg)

把城市看作节点、候选连接看作带权无向边，「任意两城可达」即选出边构成**连通图**；花费最小化即求**最小生成树**。$n$ 个节点的连通无环图恰有 $n - 1$ 条边，于是问题转化为：选出 $n - 1$ 条边连通全部节点且权和最小。

**Kruskal 贪心**：边按权升序排序，逐条考察——若两端点**已属同一连通分量**则跳过（加入必成环，树不要环），否则选入并合并两分量。连通分量维护用**并查集**，判同分量为 $O(\alpha(n))$ 近似常数。贪心的正确性由「环性质」保证：环上任何一条边都可以被另一条替换而不破坏连通性，故最贵的边永远不必要（见 §5）。

### 3.3 算法流程

![算法流程：排序、并查集判合并、统计边数](images/bw5_q3_algorithm_flow.svg)

```text
1. 边按 cost 升序排序
2. 初始化并查集 fa[i] = i (i = 1..n)
3. cost = 0, used = 0
4. 依次考察每条边 (u, v, w)：
       ra = find(u), rb = find(v)
       若 ra != rb：fa[ra] = rb；cost += w；used++
       （used == n−1 可提前终止）
5. 返回 used == n−1 ? cost : −1      # 凑不满说明图不连通
```

### 3.4 示例演算

![示例演算：连通与不连通两例的选边过程](images/bw5_q3_example_walkthrough.svg)

**示例 1**（$N = 3$，边排序后为 $(2,3,1), (1,2,5), (1,3,6)$）：

| 步骤 | 边 | 两端分量 | 动作 | used | cost |
|------|-----|----------|------|------|------|
| 1 | (2,3,1) | {2}, {3} | 选入，合并 | 1 | 1 |
| 2 | (1,2,5) | {1}, {2,3} | 选入，合并 | 2 | 6 |
| 3 | (1,3,6) | {1,2,3}, {1,2,3} | 跳过（成环） | 2 | 6 |

$used = 2 = n - 1$，返回 $6$。

**示例 2**（$N = 4$）：边 (1,2,3) 与 (3,4,4) 都被选入，但 $used = 2 \ne n - 1 = 3$，返回 $-1$。

## 4. 算法细节

1. **排序关键字只看 `cost`**：同权边的顺序不影响结果（MST 权值和唯一，边集在等权边内部可能不唯一）。
2. **并查集写法**：路径压缩（`while (fa[x] != x) { fa[x] = fa[fa[x]]; x = fa[x]; }`）已把单次操作摊还为近似常数；按秩/大小合并是锦上添花，可加可不加。$n \le 10^4$ 规模下两者都绰绰有余。
3. **判定连通用「边数」而非重复扫分量**：初始 $n$ 个分量，每合并一次少一个，选满 $n - 1$ 条边 ⇔ 只剩 1 个分量 ⇔ 图连通。用计数器 `used` 免去了对每个点再跑一遍 `find`。
4. **提前终止**：`used == n - 1` 时后面的边必然全部成环，可 `break`，省一点排序后扫描时间。
5. **重边无需去重**：Kruskal 按权排序后，重边中较便宜者先被考察；等它把两端并入同一分量，其余重边自动被「成环」判定跳过。权为 0 的边也正常参与（白白连通，不要遗漏）。
6. **数据规模与溢出**：最坏 $n - 1 = 9999$ 条边、每条 $\le 10^5$，总和 $< 10^9$，`int` 恰好放得下，但接近上界，用 `long long` 累加更稳。
7. **Prim 备选**：堆优化 Prim 为 $O(M \log M)$，与 Kruskal 同阶；但本题输入是**边表**（非邻接矩阵），Kruskal 免建邻接表、代码更短，是边表输入下的首选。

## 5. 正确性证明

**引理 1（树的边数）**：$n$ 个节点的无向连通图是树（无环）当且仅当它恰有 $n - 1$ 条边。

**证明**：对 $n$ 归纳。$n = 1$ 时连通且无环即 0 条边，成立。设对 $n$ 成立。若 $n+1$ 节点连通图 $G$ 无环，取其生成过程中的任一节点 $v$：$G$ 连通故 $v$ 有关联边；若 $v$ 的度数 $\ge 2$，沿两条关联边可从 $v$ 出发再回到 $v$（连通无环图中删除 $v$ 后各分量间无边，两条边通向同分量即成环），与无环矛盾，故存在度为 1 的叶子 $v$。删去 $v$ 及其唯一关联边得 $n$ 节点的连通无环图，由归纳假设有 $n - 1$ 条边，故 $G$ 有 $n$ 条边 $= (n+1) - 1$。反之，$n$ 节点 $n - 1$ 条边的连通图必无环：若有环，删环上一条边仍连通且剩 $n - 2$ 条边，但 $n$ 节点连通图至少需 $n - 1$ 条边（每条边至多使分量数减 1），矛盾。∎

**引理 2（环性质 / cut 性质）**：设 $T$ 为连通图 $G$ 的某棵最小生成树，$e$ 为 $T$ 中任一条边，则 $G$ 中存在一棵不含 $e$ 的最小生成树，当且仅当 $T - e$ 的两个连通分量之间在 $G$ 中的最便宜边不比 $e$ 贵。特别地：**若 $e$ 是 $T$ 中最贵的边且环上（两端点间路径上）存在更便宜的替代边，则 $T$ 可改进，与最小性矛盾**。

**证明**：设 $e = (u, v)$，从 $T$ 中删去 $e$ 得两个连通分量 $A i, B$（$u \in A$，$v \in B$）。对 $G$ 中任何跨越 $A, B$ 的边 $f$，$T - e + f$ 仍是生成树（重新连通且边数 $n - 1$，由引理 1 无环）。若存在 $w(f) < w(e)$，则 $w(T - e + f) < w(T)$，与 $T$ 最小矛盾。故 $e$ 必是跨越 $A, B$ 的**最小权边之一**。∎

**定理（Kruskal 正确性）**：按权升序逐条考察边、跳过两端已连通者、选入其余，直到选出 $n - 1$ 条（或边耗尽），所得边集 $T$ 是最小生成树；若凑不满 $n - 1$ 条，则 $G$ 不连通。

**证明**：先证 $T$ 是生成树：算法只在「两端不同分量」时加边，故 $T$ 始终无环（加边成环 ⇔ 两端已连通）；终止时若 $|T| = n - 1$，由引理 1 的逆否与 $T$ 连通（每步合并分量，$n - 1$ 次合并后恰剩 1 个分量）知 $T$ 是树。再证最小性：设 $T = \{e_1, e_2, \dots, e_{n-1}\}$ 按选入顺序排列，任取最小生成树 $T^*$。经典交换论证：若 $T \ne T^*$，设 $e_i$ 为 $T$ 中第一个不属于 $T^*$ 的边。$T^* + e_i$ 含唯一环 $C$，环上必有边 $f \ne e_i$ 跨越「$T$ 中 $e_1..e_{i-1}$ 导出的两个分量」（否则 $C$ 整个落在其中一个分量内，而 $e_i$ 两端分属两分量，矛盾）。算法考察 $e_i$ 时 $f$ 尚未被选且 $w(f) \ge w(e_i)$（否则更便宜的 $f$ 会排在 $e_i$ 前被选入——$f$ 两端在 $e_1..e_{i-1}$ 之后仍属不同分量？恰相反，$f$ 跨越该分量划分，若 $f$ 更便宜，它在 $e_i$ 之前被考察时两端不同分量必被选入 $T$，与 $f \notin T$ 矛盾，故 $w(f) \ge w(e_i)$）。于是 $T^* - f + e_i$ 仍是生成树且权和**不增**。逐个交换可把 $T^*$ 变换为 $T$ 而总权不增，故 $w(T) \le w(T^*)$，$T$ 是最小生成树。最后，若算法耗尽所有边仍 $|T| < n - 1$，说明合并次数不足 $n - 1$，即剩余分量间无任何边，$G$ 不连通，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(M \log M + M \alpha(N))$。排序主导 $O(M \log M)$（$M \le 10^4$）；随后每条边一次至两次 `find`，并查集摊还 $O(\alpha(N))$ 近似常数。
- **空间**：$O(N + M)$。并查集数组 $O(N)$；排序若为原地则 $O(1)$ 额外（C++ `sort`），Python 的 `sorted` 需 $O(M)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumCost(int n, vector<vector<int>>& connections) {
        sort(connections.begin(), connections.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[2] < b[2]; });
        fa.assign(n + 1, 0);
        for (int i = 0; i <= n; ++i) fa[i] = i;
        long long cost = 0;
        int used = 0;                                  // 已选入生成树的边数
        for (const auto& c : connections) {
            int ra = find(c[0]), rb = find(c[1]);
            if (ra != rb) {                            // 两端不同连通分量 → 选入
                fa[ra] = rb;
                cost += c[2];
                ++used;
            }
        }
        return used == n - 1 ? (int)cost : -1;         // 凑不满 n-1 条 → 图不连通
    }
private:
    vector<int> fa;
    int find(int x) {                                  // 路径压缩
        while (fa[x] != x) { fa[x] = fa[fa[x]]; x = fa[x]; }
        return x;
    }
};
```

### Python

```python
class DisjointSet:                             # 独立并查集类
    def __init__(self, n):
        self.fa = list(range(n + 1))
    def find(self, x):
        while self.fa[x] != x:
            self.fa[x] = self.fa[self.fa[x]]   # 路径减半
            x = self.fa[x]
        return x
    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        self.fa[ra] = rb
        return True

class Solution:
    def minimumCost(self, n: int, connections: list[list[int]]) -> int:
        dsu = DisjointSet(n)
        connections.sort(key=lambda c: c[2])   # 边权升序
        cost = used = 0
        for u, v, w in connections:
            if dsu.union(u, v):                # 两端不同分量才选入
                cost += w
                used += 1
        return cost if used == n - 1 else -1
```

> 💡 两份代码均通过官方示例（`6`、`-1`）、$N = 1$ 与 0 权重边边界，以及 3 万组（C++）/4 千组（Python）随机图与**独立 Prim 实现**的对拍（含大规模 $N = 10^4$ 连通图），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$N = 1$**：`used == n - 1 == 0` 在循环前即成立（若边表为空），返回 0。判断条件必须用 `used == n - 1` 而非「选了至少 1 条边」。
2. **不连通判定**：返回 $-1$ 的条件是 `used != n - 1`，不要只看「边表耗尽」——边表耗尽但已凑满 $n-1$ 条是正常成功。
3. **重边与 0 权边**：两者都合法存在。重边靠「同分量跳过」自动去重；0 权边照常累加（对总花费无影响但占用一条树边名额）。
4. **溢出**：极端总和 $\approx 10^9$，贴近 `int` 上界；C++ 用 `long long` 累加最稳，返回前转 `int`。
5. **并查集初始化大小**：城市从 1 编号，数组开 $n + 1$，循环 `for i in 0..n` 初始化，别漏下标 0 或越界 $n$。
6. **排序不稳定无妨**：等权边顺序不同可能得到不同（但总权相同）的 MST，题目只要求最小总花费。
7. **邻接矩阵版 Prim 的陷阱**：$N = 10^4$ 时 $O(N^2)$ 的朴素 Prim 需 $10^8$ 次操作且要开 $10^8$ 大小的矩阵，时间和空间双爆；务必用堆优化 Prim 或 Kruskal。
