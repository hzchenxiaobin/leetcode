# LeetCode 设计内存文件系统 题解

## 1. 题目概述

- **标题 / 题号**：设计内存文件系统（#588，hard）
- **链接**：https://leetcode.cn/problems/design-in-memory-file-system/
- **来源**：LeetCode 第 33 场周赛 Q4
- **难度**：困难
- **标签**：设计，字典树，哈希表，字符串，排序

**题意**：用内存数据结构模拟一个类 Unix 文件系统，支持四个接口：

- `ls(path)`：若 `path` 是**文件**，返回只含该文件名的列表；若是**目录**，返回该目录下所有文件与子目录的名字，**按字典序升序**。
- `mkdir(path)`：创建目录，**中间缺失的目录一并创建**，无返回值。
- `addContentToFile(filePath, content)`：文件不存在则创建并写入 `content`，已存在则**追加**；无返回值。
- `readContentFromFile(filePath)`：返回该文件的内容。

**约束**：

- 所有路径都是绝对路径，以 `/` 开头、不以 `/` 结尾；唯一的例外是根路径 `/` 本身。
- 所有调用参数都合法：不会查询不存在的目录/文件，`mkdir` 的目录一定不存在（但其中间层可能不存在）。
- 文件名与目录名只含小写字母，同一目录下不会出现重名。
- 题面未给显式数值上限，下文按「操作次数 $q$、路径段数 $m$、单次 `ls` 结果数 $k$」做复杂度分析。

> 💡 本题是**数据结构建模题**，不涉及复杂算法；难点在于四个接口的行为差异（尤其是 `ls` 的两种分支）能否用**一套下行逻辑**统一表达。

## 2. 示例

**示例 1（官方）**

```text
输入：
["FileSystem","ls","mkdir","addContentToFile","ls","readContentFromFile"]
[[],["/"],["/a/b/c"],["/a/b/c/d","hello"],["/"],["/a/b/c/d"]]
输出：[null,[],null,null,["a"],"hello"]

解释：
ls("/")                  → 根目录下还没有任何东西，返回 []
mkdir("/a/b/c")          → 依次创建 a、b、c 三级目录
add("/a/b/c/d","hello")  → 在 c 下创建文件 d，内容为 hello
ls("/")                  → 根目录下只有 a，返回 ["a"]
read("/a/b/c/d")         → "hello"
```

**补充示例 2（`ls` 的两种分支 + 追加 + 排序）**

```text
前置：mkdir("/dir") → add("/dir/sub/file","hi") → add("/z/f1","ab")
      → add("/y","x") → mkdir("/m/n") → add("/z/f1","cd")

ls("/dir/sub/file") → ["file"]      ← 文件：只回文件名
ls("/dir/sub")      → ["file"]      ← 目录：列出直接子项
ls("/")             → ["m","y","z"] ← 文件与目录混排，字典序
read("/z/f1")       → "abcd"        ← 追加，不是覆盖
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**扁平存储**：用 `map<string, string>` 存「完整路径 → 文件内容」，再用一个 `set<string>` 存所有目录的完整路径。

这样 `read`、`add` 都是 $O(L)$ 的哈希操作，但 `ls` 就很难受：

- 无法直接拿到「某目录下的直接子项」，只能**遍历全部键**做前缀匹配，单次 $O(NL)$；好不容易匹配上，还要再排除更深层的间接子孙（`/a/b/c` 在 `ls("/a")` 时不能出现）；
- 文件与目录混在两个容器里，取并集后还要去重排序。

$N$ 一大会退化成 $O(qNL)$。更关键的是：路径的前缀关系本来就是一颗**树**，扁平存储把这个结构信息丢掉了，全靠字符串前缀重新猜回来。

### 3.2 核心观察：目录树就是一棵 Trie

![目录树就是 Trie：每个节点是三件套](images/wc33_q4_node_trie.svg)

把路径按 `/` 切段，每一段就是一个 Trie 的字符——**路径就是 Trie 的键**，从根一路往下读出的段的序列，恰好是它自己。于是只需要一个节点类型：

$$ \text{Node} = \langle \texttt{ch},\ \texttt{content},\ \texttt{isFile}\rangle, \qquad \texttt{ch}: \text{名字} \to \text{Node} $$

- `ch`：子节点表。**目录的 `ls` 就是它所有 key 排序后的结果**，天然去重、天然只含直接子项。
- `content`：文件内容。目录恒为空串。
- `isFile`：唯一的类型标记。文件与目录结构完全相同，只用这一个布尔区分。

这个设计的价值在于：**四个接口都退化成同一个动作——沿路径下行一次**，到达终点后再做一件小事：

| 接口 | 下行时 | 到达终点后 |
|------|--------|-----------|
| `ls` | `create = false` | 文件 → 返回自身名；目录 → 返回 `ch` 的 key 排序 |
| `mkdir` | `create = true` | 什么都不做（节点已建好） |
| `addContentToFile` | `create = true` | `isFile = true`，`content += content` |
| `readContentFromFile` | `create = false` | 返回 `content` |

### 3.3 算法流程：统一的 walk(path, create)

![walk 流程：一次下行，边下边补节点](images/wc33_q4_walk_flow.svg)

核心函数 `walk(path, create)` 返回路径对应的节点：

1. 把 `path` 按 `/` 切段并**跳过空段**（这样根路径 `/` 得到空序列，重复斜杠也能容忍），`node = root`；
2. 对每一段 `part`：若 `node.ch` 中有 `part` 就取出来；否则在 `create = true` 时新建一个空节点挂进 `node.ch`，`create = false` 时属非法查询（题面保证不会发生）；
3. 所有段走完后返回 `node`。

由于每个 `ch` 是哈希表，单次下行的期望时间是 $O(m)$（$m$ 为段数）——**与系统中已有文件数量无关**。这正是 Trie 相对扁平存储的收益：$O(N) \to O(m)$。

### 3.4 示例演算

![官方示例的五步走查与最终结构](images/wc33_q4_example_walkthrough.svg)

以官方示例走一遍（第 3 步后内存结构如上图下半部分）：根节点的 `ch` 只有 `a`；`a → b → c` 是一条单链；`c` 的 `ch` 里是 `d`，且 `d.isFile = true`、`d.content = "hello"`。

- `ls("/")`：`path` 切段后为空 → 直接返回 `root`；`root.isFile = false`，取 `ch` 的 key 排序 → 空列表 `[]`。
- `mkdir("/a/b/c")`：段序列 `[a, b, c]`，三次「查不到就新建」，一次下行完成，不需要额外写「补父目录」的循环。
- `addContentToFile("/a/b/c/d","hello")`：段序列 `[a,b,c,d]`，前三段都存在直接复用，末段 `d` 现场创建，打上 `isFile = true` 再 `+= "hello"`。
- `ls("/")`：此时 `root.ch = {a: …}`，排序后 `["a"]`；`readContentFromFile("/a/b/c/d")` 下行到 `d` 返回 `"hello"`。

## 4. 算法细节

1. **路径切分**：`path.split('/')` 会产生空串（`"/a/b"` → `["", "a", "b"]`），循环里必须 `if not part: continue`（C++ 用 `getline(ss, part, '/')` 加 `if (part.empty()) continue`）。这样 `/`、`/a/`、`//a` 都能自然处理，不必特判根。
2. **`ls` 的分支判定用 `isFile`，不要用 `ch.empty()`**：一个空目录的 `ch` 也是空的，用「有没有子节点」判断类型一定错。
3. **`ls` 返回文件名时取 `path` 的最后一段**：`path.split('/')[-1]`（C++ 取 `parts.back()`）。若想省这一次切分，可在节点里冗余存一个 `name` 字段，代价是每个节点多一个字符串。
4. **`mkdir` 必须补中间层**：把「查不到就新建」写进下行循环本身（`create = true`），就自动补全了 `/a/b/c` 中缺失的 `a`、`b`，无需第二次遍历。
5. **`add` 是追加且必须置 `isFile`**：`node.content += content`（**不是赋值**），并把 `node.isFile` 置真；新建与追加共用这一行代码，正是「不存在则创建、存在则追加」的语义。只写内容忘了置标记，`ls` 会把该文件当空目录返回 `[]`。
6. **`ls` 目录必须排序**：`unordered_map` 的遍历顺序是实现定义的，必须先 `sort` 再返回；Python 的 `dict` 是插入序，必须 `sorted(...)`。漏掉排序会大面积 WA。
7. **节点用引用语义**：C++ 全程 `Node*`（`new` 出来挂在父节点上），Python 用嵌套 `dict`；千万不要「按值返回节点再修改」——改了副本等于没改。

## 5. 正确性证明

**引理 1（下行正确性）**：设路径为 $p_1/p_2/\dots/p_m$，从根出发依次沿 $p_1,\dots,p_m$ 取子节点得到的节点 $v$，当且仅当该路径在文件系统中存在时非空；且 $v$ 的语义（是目录还是文件、内容为何）与路径语义一致。

**证明**：对段数 $m$ 归纳。$m=0$ 时 $v = \text{root}$，对应根路径 `/`，成立。设对 $m-1$ 成立，则走完前 $m-1$ 段得到 $v'$；第 $m$ 段 $p_m$ 对应的节点恰为 $v'.\texttt{ch}[p_m]$——因为「目录 $v'$ 下存在名为 $p_m$ 的子项」与「$v'.\texttt{ch}$ 中存在键 $p_m$」按 `ch` 的定义等价。故 $v$ 存在性、类型与内容均与路径一致。∎

**引理 2（`walk(path, true)` 建出完整前缀链）**：`create = true` 时，下行过程中遇到的每个缺失段都会新建节点并挂到上一级 `ch` 中，故返回后路径上每一级目录都已存在，且不会破坏已有节点。

**证明**：归纳同上。每一步只在该键**不存在**时插入新节点，因此已有节点被原样复用、不会被覆盖或复制；缺失的段按顺序补全，走完 $m$ 段后前缀链完整。∎

**引理 3（`ls` 输出正确）**：`ls` 返回的列表恰为「路径对应文件的名字」或「目录直接子项名字的升序列表」。

**证明**：若 `isFile` 为真，按 `ch` 的定义该节点没有子项，返回 `path` 最后一段即该文件名，列表只含它且正确。若为假，`ch` 的键集合恰为直接子项集合——因为每个子项都只在**其父节点**的 `ch` 中注册一次（`mkdir`/`add` 均由引理 2 保证只挂一层），更深层的项在更深节点的 `ch` 里，不会出现在本层；再按引理 1 路径合法，故排序后的键列表就是答案。∎

**定理**：`FileSystem` 的四个接口均满足题目规范，且 `add` 对已存在文件执行追加、对不存在文件执行创建。

**证明**：`ls` 由引理 1、3 直接得证（引理 1 保证下行到正确节点）。`mkdir` 由引理 2 得证：路径（含中间层）创建完整，且返回值为空。`add` 先由引理 2 拿到节点，再置 `isFile = true` 并执行 `content += c`：若文件原本不存在，`content` 为空串，结果为 $c$，即「创建并写入」；若已存在，结果为原内容拼接 $c$，即「追加」。`read` 由引理 1 返回该节点的 `content`，对文件即其完整内容。∎

## 6. 复杂度分析

- **时间**：设路径段数为 $m$，`ls` 目录时的直接子项数为 $k$。
  - `walk` 单次 $O(m)$：哈希查找期望 $O(1)$，与系统规模无关。
  - `mkdir`、`add`、`read` 均 $O(m)$（`add` 额外付出拼接内容的 $O(|c|)$）。
  - `ls` 目录为 $O(m + k\log k)$（排序）；`ls` 文件为 $O(m)$。
  - 总计 $O(qm + \sum k\log k)$，$q$ 为操作次数。
- **空间**：$O(V + T)$。$V$ 为文件系统里的节点总数（目录 + 文件），$T$ 为所有文件内容的总长度；哈希表与指针的额外开销按节点数线性计。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>
#include <sstream>
using namespace std;

class FileSystem {
    struct Node {
        unordered_map<string, Node*> ch;
        string content;
        bool isFile = false;
    };
    Node* root;

    static vector<string> split(const string& path) {
        vector<string> parts;
        string cur;
        stringstream ss(path);
        while (getline(ss, cur, '/')) {
            if (!cur.empty()) parts.push_back(cur);   // 跳过空段：兼容根与重复斜杠
        }
        return parts;
    }

    Node* walk(const string& path, bool create) {
        Node* node = root;
        for (const string& part : split(path)) {
            auto it = node->ch.find(part);
            if (it == node->ch.end()) {
                if (!create) return nullptr;          // 题面保证查询路径都存在
                Node* nxt = new Node();
                node->ch[part] = nxt;
                node = nxt;
            } else {
                node = it->second;
            }
        }
        return node;
    }

public:
    FileSystem() { root = new Node(); }

    vector<string> ls(string path) {
        Node* node = walk(path, false);
        vector<string> res;
        if (node->isFile) {                            // 文件：只回自身名
            res.push_back(split(path).back());
            return res;
        }
        for (auto& kv : node->ch) res.push_back(kv.first);   // 目录：列 key 并排序
        sort(res.begin(), res.end());
        return res;
    }

    void mkdir(string path) { walk(path, true); }

    void addContentToFile(string filePath, string content) {
        Node* node = walk(filePath, true);
        node->isFile = true;                           // 新建或复用，都标记为文件
        node->content += content;                      // 追加，不是覆盖
    }

    string readContentFromFile(string filePath) {
        Node* node = walk(filePath, false);
        return node ? node->content : string();
    }
};
```

### Python

```python
class FileSystem:
    def __init__(self):
        self.root = {"ch": {}, "content": "", "isFile": False}

    def _walk(self, path, create=False):
        node = self.root
        for part in path.split("/"):
            if not part:                     # 跳过空段：兼容 "/" 与重复斜杠
                continue
            nxt = node["ch"].get(part)       # 注意用 is None 判断，空字典是假值
            if nxt is None:
                if not create:               # 题面保证查询路径都存在
                    raise KeyError(path)
                nxt = {"ch": {}, "content": "", "isFile": False}
                node["ch"][part] = nxt
            node = nxt
        return node

    def ls(self, path):
        node = self._walk(path)
        if node["isFile"]:
            return [path.split("/")[-1]]     # 文件：只回自身名
        return sorted(node["ch"].keys())     # 目录：列 key 并排序

    def mkdir(self, path):
        self._walk(path, create=True)        # 中间层一并补建

    def addContentToFile(self, filePath, content):
        node = self._walk(filePath, create=True)
        node["isFile"] = True
        node["content"] += content           # 追加，不是覆盖

    def readContentFromFile(self, filePath):
        return self._walk(filePath)["content"]
```

## 8. 边界情况与易错点

1. **空系统上 `ls("/")`**：返回 `[]` 而不是 `null` 或 `["/"]`。根节点不是文件，`ch` 为空，`sorted` 空集合即可；不要给根节点乱设 `isFile`。
2. **`mkdir("/")`**：切段后是空序列，`walk` 一次都不走就返回根，什么也不建，也不报错——这不算非法输入。
3. **根路径特有的两种写法**：`ls("/")` 与 `read("/")` 的切分结果都是空序列，都指向根；不要因为 `split` 生成 `["", ""]` 多走一步。
4. **`add` 写成覆盖**：`node->content = content` 会让补充示例 2 输出 `"cd"` 而不是 `"abcd"`，这是本题最常见的 WA。
5. **忘记置 `isFile`**：只写内容不置标记，`ls` 会把该文件当成空目录返回 `[]`；反过来，`mkdir` 创建的节点绝不能置 `isFile`。
6. **漏排序**：`unordered_map` 的遍历顺序由哈希决定，测试数据往往正是按不同插入顺序构造的；`ls` 必须显式 `sort` / `sorted`。
7. **Python 里用 `if not nxt` 判断节点不存在**：空节点字典 `{"ch": {}, ...}` 是**非空**字典，没问题；但如果把节点设计成直接返回子字典，就会踩「空字典为假」的坑——统一用 `is None` 更安全。
8. **`ls` 文件时误返回完整路径**：应返回路径最后一段 `d`，而不是 `/a/b/c/d`；C++ 的 `walk` 返回 `nullptr` 时也要保留判空，别为「快一点」直接解引用。
