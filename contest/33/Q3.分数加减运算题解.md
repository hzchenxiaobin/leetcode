# LeetCode 分数加减运算 题解

## 1. 题目概述

- **标题 / 题号**：分数加减运算（#592，medium）
- **链接**：https://leetcode.cn/problems/fraction-addition-and-subtraction/
- **来源**：LeetCode 第 33 场周赛 Q3
- **难度**：中等
- **标签**：数学、字符串、最大公约数、欧几里得算法、模拟

**题意**：给定一个用 `+` / `-` 连接的分数表达式，每个分数是「符号 + 分子/分母」，按有理数做加减，返回**最简分数**字符串。结果为正时省略 `+`；整数写成 `x/1`；负号只出现在分子上，分母恒为正。

**约束**：

- 输入只包含数字、`/`、`+`、`-`；分数个数在 $[1, 10]$ 之间
- 每个分数的分子、分母都在 $[1, 10]$ 之间，且输入分数**已经最简**
- 若首项为正，省略 `+`；分母为 1 表示整数
- 结果的分子与分母保证是 32 位整数范围内的有效整数

## 2. 示例

**示例 1**

```text
输入：expression = "-1/2+1/2"
输出："0/1"
解释：-1/2 + 1/2 = 0，结果按 "0/1" 输出（不是 "0"）。
```

**示例 2**

```text
输入：expression = "-1/2+1/2+1/3"
输出："1/3"
解释：前两项相消为 0，再加上 1/3，得 1/3。
```

**示例 3**

```text
输入：expression = "1/3-1/2"
输出："-1/6"
解释：1/3 - 1/2 = 2/6 - 3/6 = -1/6，已是最简分数。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是「先把所有分母乘起来通分，最后再约分一次」，即

$$\frac{p}{q} = \sum_i \frac{s_i a_i}{b_i} = \frac{\sum_i s_i a_i \prod_{j \ne i} b_j}{\prod_i b_i}$$

这个式子数学上没错，但分母乘积随分数个数**指数膨胀**：$b_i \le 10$、最多 10 项，分母就可达 $10^{10}$，早已超出 32 位整数；若分数个数再放宽到 30 个，连 64 位也会溢出。题目只保证**结果**在 32 位内，中间量并不保证。

另一种常见错误是转成 `double` 累加再「猜」一个分数——浮点数无法精确表示 $1/3$，反解必然出错。

所以正确方向是：**每一步都通分并立即约分**，让分子分母始终很小。

### 3.2 核心观察：通分 + 立即约分，维持「最简精确」不变量

![通分与立即约分：累加器始终是最简精确分数](images/wc33_q3_reduce_concept.svg)

维护一个累加器 `num / den`，初值为 $0/1$。读入下一项 $s \cdot a/b$（$s \in \{+1,-1\}$）时，只做三件事：

$$
\text{num} \leftarrow \text{num}\cdot b + s\cdot a\cdot \text{den},\qquad
\text{den} \leftarrow \text{den}\cdot b,\qquad
g = \gcd(|\text{num}|,\ \text{den}),\ \ \text{num} \mathrel{/}= g,\ \text{den} \mathrel{/}= g
$$

这样每一步之后都有三条性质：**数值精确**（全程整数运算，没有浮点误差）、**已经最简**（分子分母互质）、**分母为正**（$\text{den} > 0$ 恒成立，因为 $b \ge 1$）。三条性质合起来意味着：累加器在任何时刻就是「已读前缀」的精确值，最后一步的输出无需再做任何整理。

还有一个很实用的小性质：$\gcd(0, d) = d$，所以当某一步分子变成 $0$ 时，约分自动把它规范成 $0/1$，**不需要为「结果为 0」写特判**。

> 💡 **分母上界**：输入分数已最简且分母 $\le 10$，因此约分后 `den` 始终整除 $\operatorname{lcm}(1,2,\dots,10) = 2520$，即 $\text{den} \le 2520$，分子也在 $10^5$ 量级。这就是「立即约分」带来的直接收益：中间量永远很小。

### 3.3 算法流程

![解析与累加流程：游标扫描 + 每步约分](images/wc33_q3_parse_flow.svg)

1. 为统一格式，若 `expression[0] != '-'`，在字符串前补一个 `'+'`；此后每一项都形如「符号 + 分子/分母」。
2. 初始化游标 $i = 0$、`num = 0`、`den = 1`。
3. 读符号：`expression[i]` 是 `'+'` 则 $s=+1$，是 `'-'` 则 $s=-1$，然后 $i$ 右移一位。
4. 读分子 $a$：连续读数字直到遇到 `/`；跳过 `/`；再连续读数字得到分母 $b$（读到 `+`/`-` 或串尾自然停止）。
5. 通分：`num = num * b + sign * a * den`，**然后**才 `den = den * b`（通分公式里用的是**旧**分母）。
6. 约分：$g=\gcd(|\text{num}|, \text{den})$，`num /= g`、`den /= g`。
7. 若 $i < n$ 回到第 3 步；否则返回 `to_string(num) + "/" + to_string(den)`。

解析上有一个容易踩的坑：`-1/2-1/2` 里第二个 `-` 既是**运算符**又是下一项的**符号**，所以不能简单地按 `+` / `-` 切分后再补符号——必须让游标「先吃符号，再吃分子，吃 `/`，再吃分母」，一步一项地推进。由于数字只能是 $1\sim 2$ 位，逐字符读比 `split` 更稳。

### 3.4 示例演算

![示例 2 的逐步演算表](images/wc33_q3_example_walkthrough.svg)

以 `expression = "-1/2+1/2+1/3"` 为例：

| 步骤 | 读入项 | 通分计算 $\text{num}\cdot b + s\cdot a\cdot \text{den}$ | 新 $\text{den}$ | 约分后 |
|------|--------|--------------------------------------------------------|------------------|--------|
| 0 | 初值 | $0$ | $1$ | $0/1$ |
| 1 | $-1/2$ | $0\cdot 2 + (-1)\cdot 1\cdot 1 = -1$ | $2$ | $-1/2$ |
| 2 | $+1/2$ | $(-1)\cdot 2 + 1\cdot 1\cdot 2 = 0$ | $2\cdot 2 = 4$ | $0/1$（$\gcd(0,4)=4$） |
| 3 | $+1/3$ | $0\cdot 3 + 1\cdot 1\cdot 1 = 1$ | $3$ | $1/3$ |

最终 `1/3`，与示例输出一致。第 2 步正好演示了「分子为 0 时 gcd 自动规范化」：$0/4$ 被约成 $0/1$，而不是原样保留一个未约分的分数。

再验证示例 3：`1/3-1/2` 只有一项初值 $1/3$，读入 $-1/2$ 后

$$\text{num} = 1\cdot 2 + (-1)\cdot 1\cdot 3 = -1,\qquad \text{den} = 3\cdot 2 = 6$$

$\gcd(1,6)=1$，输出 `-1/6`，负号落在分子、分母保持为正，符合要求。

## 4. 算法细节

1. **补 `'+'` 统一格式**：只在首字符不是 `'-'` 时补，这样循环内「每轮必有一个符号」成立，省掉首项特判。
2. **先算分子、后更新分母**：`num` 的公式用旧 `den`，写成 `num = num * b + sign * a * den; den *= b;` 才正确；若先执行 `den *= b`，分子就会被多乘一个 $b$。
3. **用 `gcd` 而不是「枚举因子」**：C++17 直接 `std::gcd`（需 `<numeric>`），Python 用 `math.gcd`。两者都返回非负公约数，传 `abs(num)` 主要是把意图写清楚，并避免依赖负数输入下的实现细节。
4. **$\gcd(0, d) = d$ 是免费的 0 特判**：不要额外写 `if (num == 0) return "0/1";`，但要知道它是靠这条性质工作的。
5. **取绝对值的位置**：只对 `num` 取绝对值；`den` 天然为正，对它取绝对值反而会掩盖符号错误。
6. **数值类型**：C++ 用 `long long`。虽然「每步约分」后数值很小，但通分那一行会先出现 `num * b`、`a * den` 这类乘积，用 `int` 留给未来的放宽约束没有余量。
7. **输出格式**：正数**不加** `'+'`（如 `1/3` 而非 `+1/3`）；负数由 `num` 自带负号；整数保留 `/1`；不要出现 `1/-6` 这种分母为负的写法。
8. **等价写法（利用约束）**：因为每个分母都整除 $2520$，也可以取固定公分母 $2520$，一次累加 $\sum_i s_i a_i \cdot (2520/b_i)$，最后约分一次。它更快，但只在「分母 $\le 10$」这个特殊约束下成立，通用性不如逐项约分——面试或题解里建议先写通用版。

## 5. 正确性证明

**引理 1（约分不变值且保持最简）**：设 $p, q$ 为整数、$q > 0$，$g = \gcd(|p|, q)$，则 $\dfrac{p}{q} = \dfrac{p/g}{q/g}$，且 $q/g > 0$、$\gcd(|p/g|, q/g) = 1$。特别地 $p = 0$ 时 $g = q$，结果为 $0/1$。

**证明**：由 $g \mid p$、$g \mid q$ 知 $p/g$、$q/g$ 都是整数，且 $\frac{p/g}{q/g} = \frac{p}{q}$（分子分母同除一个非零整数，值不变）。$g > 0$ 且 $q > 0$ 给出 $q/g > 0$。若 $\gcd(|p/g|, q/g) = h > 1$，则 $gh$ 同时整除 $|p|$ 与 $q$，与 $g$ 是最大公约数矛盾，故互质。$p = 0$ 时 $\gcd(0,q) = q$，得 $0/1$。∎

**引理 2（单步通分正确）**：若累加器 `num/den`（$\text{den} > 0$）等于已读前缀之和，下一项为 $s\cdot a/b$（$b > 0$），则令 $\text{num}' = \text{num}\cdot b + s\cdot a\cdot \text{den}$、$\text{den}' = \text{den}\cdot b$，有 $\dfrac{\text{num}'}{\text{den}'} = \dfrac{\text{num}}{\text{den}} + \dfrac{s\cdot a}{b}$。

**证明**：$\dfrac{\text{num}'}{\text{den}'} = \dfrac{\text{num}\cdot b}{\text{den}\cdot b} + \dfrac{s\cdot a\cdot \text{den}}{\text{den}\cdot b}$，第一项即 $\text{num}/\text{den}$（同除 $b$），第二项即 $s\cdot a/b$（同除 `den`），合并即得。∎

**引理 3（不变量保持）**：算法每轮结束时，`num/den` 等于已读前缀的精确值，且 $\text{den} > 0$、$\gcd(|\text{num}|,\text{den}) = 1$。

**证明**：初始 $0/1$ 满足三条。归纳假设第 $k$ 轮结束满足，则第 $k+1$ 轮：由引理 2，通分后的值等于新前缀之和；因 $\text{den} > 0$、$b \ge 1$，新分母 $\text{den}\cdot b > 0$；再由引理 1，约分后值不变，且分母为正、分子分母互质。三条性质同时保持。∎

**定理**：算法返回的字符串恰为整个表达式精确值的最简分数表示。

**证明**：由第 3.3 节流程，游标每轮恰好消费「符号 + 分子/分母」这一完整项，读完全部字符即读完所有项（题面保证输入合法，不会出现残缺项），故结束时 `num/den` 是**整个表达式**的值。由引理 3，它已最简且 $\text{den} > 0$，因此负号只能来自分子、分母不会为负。输出按 `num/den` 拼接：正数天然不含 `'+'`，整数因 `den = 1` 而写作 `x/1`，与题目要求逐条吻合。∎

## 6. 复杂度分析

- **时间**：$O(L)$，$L$ 为表达式长度。游标只向右移动，每个字符被读常数次；每项一次 `gcd`，操作数是 $10^5$ 量级的小整数，$O(\log M)$ 可视为常数。$L \le 10 \times 6 = 60$，实际运行时间可忽略。
- **空间**：$O(1)$ 额外空间（只存 `num`、`den`、`i`、`g`），不计长度为 $O(L)$ 的返回字符串。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <numeric>   // std::gcd
#include <cstdlib>   // llabs
#include <cctype>    // isdigit
using namespace std;

class Solution {
public:
    string fractionAddition(string expression) {
        long long num = 0, den = 1;          // num/den，始终最简且 den > 0
        int i = 0, n = (int)expression.size();
        while (i < n) {
            int sign = 1;
            if (expression[i] == '+' || expression[i] == '-') {
                if (expression[i] == '-') sign = -1;
                ++i;
            }
            long long a = 0;                 // 分子
            while (i < n && isdigit((unsigned char)expression[i]))
                a = a * 10 + (expression[i++] - '0');
            ++i;                             // 跳过 '/'
            long long b = 0;                 // 分母
            while (i < n && isdigit((unsigned char)expression[i]))
                b = b * 10 + (expression[i++] - '0');
            num = num * b + sign * a * den;  // 通分：注意用旧的 den
            den = den * b;
            long long g = std::gcd(llabs(num), den);   // 立即约分
            num /= g;
            den /= g;
        }
        return to_string(num) + "/" + to_string(den);
    }
};
```

### Python

```python
from math import gcd

class Solution:
    def fractionAddition(self, expression: str) -> str:
        num, den = 0, 1          # 累加器：num/den，始终最简且 den > 0
        i, n = 0, len(expression)
        while i < n:
            sign = 1
            if expression[i] in '+-':
                if expression[i] == '-':
                    sign = -1
                i += 1
            a = 0                # 分子
            while i < n and expression[i].isdigit():
                a = a * 10 + int(expression[i]); i += 1
            i += 1               # 跳过 '/'
            b = 0                # 分母
            while i < n and expression[i].isdigit():
                b = b * 10 + int(expression[i]); i += 1
            num = num * b + sign * a * den   # 通分：用旧的 den
            den = den * b
            g = gcd(abs(num), den)           # 立即约分，gcd(0, d) = d
            num //= g
            den //= g
        return f"{num}/{den}"
```

## 8. 边界情况与易错点

1. **首项没有 `'+'`**：`"-1/2+1/2"` 与 `"1/3-1/2"` 都以「符号或数字」开头。统一补 `'+'`（或把符号默认值设为 $+1$）即可避免首项特判漏读符号。
2. **结果为 0**：必须输出 `"0/1"`，不能是 `"0"`、`"0/4"` 或 `"-0/1"`。靠 $\gcd(0,\text{den}) = \text{den}$ 自动得到，注意别把 `gcd` 写成「分子为 0 就跳过」的自定义版本。
3. **分母恒正**：`den` 只会乘上正的分母 $b$，所以始终为正；约分时只对 `num` 取绝对值，负号就唯一落在分子上，输出 `"1/-6"` 必然是错的。
4. **先算分子再更新分母**：通分式里的 `den` 是**上一步**的分母。顺序写反会让分子多乘一个 $b$，示例 1 就会得到 `-1/2` 而不是 `0/1`。
5. **连续符号的解析**：`"-1/2-1/2"` 中第二个 `-` 是运算符。用 `split("+")` / `split("-")` 会丢掉符号信息；应逐字符扫描，「先读符号、再读分子、跳过 `/`、再读分母」。
6. **整数结果也要保留分母 1**：`den == 1` 时仍要输出 `x/1`；`"2/1+3/1"` 的答案是 `"5/1"` 而不是 `"5"`。
7. **不要用浮点数**：`double` 累加后反解分数几乎必然出错（$1/3$、$1/7$ 都不可精确表示），且题目要求最简分数，浮点路径没有可证明的正确性。
8. **输出不要带 `'+'`**：正数结果若写成 `"+1/3"` 会判错；`to_string` / f-string 天然不带符号前缀，但别手动拼接 `'+'`。
