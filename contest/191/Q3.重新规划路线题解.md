# LeetCode 重新规划路线 题解

## 1. 题目概述

- **标题 / 题号**：重新规划路线（#1466，medium）
- **链接**：https://leetcode.cn/problems/reorder-routes-to-make-all-paths-lead-to-the-city-zero/
- **来源**：LeetCode 第 191 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索、广度优先搜索、图

**题意**：$n$ 个城市之间共有 $n-1$ 条**有向**路线，把方向抹掉后整张网是一棵树，因此任意两城之间恰好有一条无向路径。城市 0 今年要办比赛，要求把其中若干条路线**掉头**，使得每个城市都能顺着箭头走到城市 0。返回最少需要掉头的路线数。

**约束**：

- $2 \le n \le 5\times 10^4$
- `connections.length == n - 1`
- `connections[i] = [a_i, b_i]` 表示一条从 $a_i$ 到 $b_i$ 的路线，且 $a_i \ne b_i$
- $0 \le a_i, b_i \le n-1$，并保证去掉方向后是一棵树

## 2. 示例

**示例 1**

```text
输入：n = 6, connections = [[0,1],[1,3],[2,3],[4,0],[4,5]]
输出：3
解释：把 0→1、1→3、4→5 掉头后，2→3→1→0、5→4→0 都能走到 0，共改 3 条。
      2→3 与 4→0 本来就已经指向 0，无需改动。
```

**示例 2**

```text
输入：n = 5, connections = [[1,0],[1,2],[3,2],[3,4]]
输出：2
解释：需要掉头的是 1→2 与 3→4；1→0、3→2 已经指向 0。
```

**示例 3**

```text
输入：n = 3, connections = [[1,0],[2,0]]
输出：0
解释：两条路线都直指城市 0，不需要任何改动。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是枚举「掉头集合」$S \subseteq E$，对每个子集重新建图、检查每个点能否到达 0，取可行子集中最小的 $|S|$。复杂度 $O(2^{n-1}\cdot n)$，$n = 5\times10^4$ 时完全不可行。

但暴力的失败方式提示了一个更强的结论：**每条边该朝哪边根本没有选择余地**。一旦确定了「树以 0 为根」这个前提，每条边的目标朝向就被拓扑唯一钉死了，剩下的只是「它当前是否已经朝对」这一道是非题。于是问题从「搜索改动方案」退化成「数一数有几条边朝错了」。

### 3.2 核心观察：每条边的目标朝向唯一

![每条边的目标方向由树结构唯一确定](images/wc191_q3_tree_orientation.svg)

把路线网看成无向树，以城市 0 为根。任取一条边 $e$，删掉它后树被切成两块，其中恰有一块含 0，记这块为 $A_e$，另一块为 $B_e$。

$B_e$ 中任意一个城市要到 0，唯一路径必然跨过 $e$，而且只能是从 $B_e$ 侧走向 $A_e$ 侧。反过来，只要所有边都满足这个方向，$B_e$ 里的每个点就都能一步步走向 0。因此

$$\text{target}(e) = \text{由远离 0 的一侧指向靠近 0 的一侧}$$

是 $e$ 在**任何**合法方案中都必须具有的朝向，也就是「最少修改数」的一个下界来源：

$$\text{answer} \ge \#\{\,e : \text{target}(e) \ne \text{original}(e)\,\}$$

而这个下界是**可以达到**的：把这些朝错的边全部翻过来、其余一条不动，每条边都指向 0 一侧，于是每个城市沿唯一路径走都会离 0 越来越近，最终抵达 0。所以答案恰好等于这个计数。

换个说法更好实现：以 0 为根做一次遍历，对每条「父 $u$ → 子 $v$」的边走查——若原方向是 $u \to v$（背离根），计 1；若原方向是 $v \to u$（指向根），计 0。

### 3.3 算法流程

![无向化 + 一次遍历累加标记](images/wc191_q3_bfs_flow.svg)

标记 $w$ 的含义要按「遍历方向」来定义，这是全题唯一容易写反的地方：

- 对原路线 $a \to b$，向邻接表 $g[a]$ 中压入 $(b,\,w=1)$：从 $a$ 出发走向 $b$ 与箭头同向，属于背离 0，必须掉头；
- 同时向 $g[b]$ 中压入 $(a,\,w=0)$：从 $b$ 出发走向 $a$ 与箭头反向，已经指向 0，免费。

然后从 0 开始遍历（DFS 或 BFS），维护 `vis` 数组防止回头：

1. 弹出 $u$，遍历它的每条邻接边 $(v, w)$；
2. 若 $v$ 已访问，说明这是回到父节点的回头边，跳过；
3. 否则 $v$ 是 $u$ 的孩子（$u$ 在根侧），令 `vis[v] = true`、`ans += w`，把 $v$ 入栈/入队。

遍历结束时 $ans$ 就是背离 0 的边数，直接返回。

### 3.4 示例演算

![示例 1 逐边走查](images/wc191_q3_walkthrough.svg)

对示例 1（$n = 6$，路线 `[0,1] [1,3] [2,3] [4,0] [4,5]`）从 0 出发：

- $0 \to 1$：原方向 $0\to1$，背离 0，$w=1$，$ans=1$；
- $0 \to 4$：原方向 $4\to0$，指向 0，$w=0$，$ans=1$；
- $4 \to 5$：原方向 $4\to5$，背离 0，$w=1$，$ans=2$；
- $1 \to 3$：原方向 $1\to3$，背离 0，$w=1$，$ans=3$；
- $3 \to 2$：原方向 $2\to3$，指向 0，$w=0$，$ans=3$。

5 条边各检查一次，其中 3 条背离 0，答案为 3，与官方输出一致。注意 $2\to3$ 为什么保留：遍历时是以「父 3 → 子 2」访问这条边，建图时 `g[3]` 里存的正是 $(2, 0)$，意思是「从 3 走向 2 与箭头反向」，可见原方向本来就指向 0，无须改动。

## 4. 算法细节

1. **标记的赋值方向**：`connections[i] = [a, b]` 时，一定是「从 $a$ 出去代价 1、从 $b$ 出去代价 0」，不能按数值大小或下标顺序判断。写反会得到 $(n-1) - ans$。
2. **用一个 `vis` 数组判「是否已从根侧访问过」**，不必额外记录深度：树中每个点只有一个父节点，回头边一律跳过，于是每条边恰好计一次；这也是不建反向图就能统计的原因。
3. **迭代式遍历**：Python 默认递归深度只有 1000，而 $n$ 可达 $5\times10^4$，退化成长链时递归 DFS 会 `RecursionError`，因此代码统一用显式栈。
4. **邻接表而非邻接矩阵**：$n^2 = 2.5\times10^9$ 个格子既存不下也跑不完；邻接表总长度恰好 $2(n-1)$。
5. **不必真的改图**：答案就是一个计数，真的去翻转边只会引入多余的常数和出错机会。
6. **答案值域**：$ans \in [0, n-1]$，`int` 足够；整个过程只做加法，不存在乘法溢出风险。
7. **遍历顺序无关**：DFS 与 BFS、边的输入顺序都不影响统计结果，因为「父 → 子」的组合只由树结构决定。

## 5. 正确性证明

**引理 1（目标朝向唯一）**：对任意一条边 $e$，所有使「每个城市都能到达 0」的方案中，$e$ 的朝向都相同，即由 $B_e$ 指向 $A_e$（$B_e$ 为删去 $e$ 后不含 0 的那块）。

**证明**：设 $e$ 连接 $x \in A_e$ 与 $y \in B_e$。任取 $b \in B_e$，由于底图是树，$b$ 到 0 的无向路径唯一且必经过 $e$，于是它在有向意义下要能走通，就必须能从 $B_e$ 侧跨到 $A_e$ 侧，即 $e$ 的方向是 $y \to x$。若方向相反，则 $B_e$ 中任何点都无法离开 $B_e$，与合法方案矛盾。∎

**引理 2（遍历标记的等价性）**：在从 0 出发的 DFS 中，边 $e$ 以「父 $u$ → 子 $v$」被访问；此时 $w = 1$ 当且仅当 $e$ 的原方向是 $u \to v$，当且仅当 $\text{target}(e) \ne \text{original}(e)$。

**证明**：DFS 从 0 向外扩张，先被访问的端点 $u$ 必在 0 侧、后被访问的 $v$ 在远离 0 侧，故 $u \in A_e$、$v \in B_e$。建图时，从 $u$ 出发、指向 $v$ 的那条弧正是「与 $a \to b$ 同向」的那条，其代价被置为 1，因此 $w=1 \iff$ 原方向 $u \to v$。由引理 1，$\text{target}(e)$ 是 $v \to u$，故原方向 $u \to v$ 恰等价于原方向与目标方向不同。∎

**引理 3（每条边恰计一次）**：DFS 中每条边只被作为「父 → 子」访问一次。

**证明**：树有 $n-1$ 条边且无环。DFS 只在 `vis[v]` 为假时从前驱 $u$ 前进到 $v$，并把 $v$ 标记；此后 $v$ 不会再作为未访问端点被任何边进入，所以每条边只可能被它的两个端点之一首次跨越，跨越时贡献恰好一次的标记值。另一端再看到这条边时 `vis` 已为真，被跳过。∎

**定理**：算法返回的值等于最少需要掉头的路线数。

**证明**：设 $F = \{\,e : \text{target}(e) \ne \text{original}(e)\,\}$。由引理 1，任何合法方案都必须改动 $F$ 中的每一条边（它们当前朝向与唯一合法朝向不同），故改动数 $\ge |F|$。另一方面，只改动 $F$、其余边保持不动，则每条边都指向 0 一侧，任一城市沿唯一路径行走时每一步都在靠近 0，必然到达 0，方案合法且改动数恰为 $|F|$，下界可达。而由引理 2 与引理 3，DFS 累计的正是 $|F|$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建图遍历 $n-1$ 条路线、每条压入两条弧，共 $O(n)$；遍历阶段每个点入栈一次、每条弧被查看一次，共 $O(n)$。总计 $O(n)$，$n = 5\times10^4$ 时约 $10^5$ 级别操作。
- **空间**：$O(n)$。邻接表存 $2(n-1)$ 条带标记的弧；`vis` 数组 $n$ 个布尔；显式栈最坏（长链）存 $n$ 个点。均与 $n$ 成正比，约几 MB 量级。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <utility>
using namespace std;

class Solution {
public:
    int minReorder(int n, vector<vector<int>>& connections) {
        // g[u] 中每个元素是 (v, w)：
        // 沿着 u -> v 走时，w = 1 表示与原始箭头同向（背离 0，必须掉头），w = 0 表示反向（已指向 0）
        vector<vector<pair<int, int>>> g(n);
        for (auto& e : connections) {
            g[e[0]].push_back({e[1], 1});
            g[e[1]].push_back({e[0], 0});
        }

        vector<char> vis(n, 0);
        vis[0] = 1;
        vector<int> st{0};
        int ans = 0;

        while (!st.empty()) {
            int u = st.back();
            st.pop_back();
            for (auto& p : g[u]) {
                int v = p.first, w = p.second;
                if (vis[v]) continue;   // 回头边（v 是父节点），不计数
                vis[v] = 1;             // v 是 u 的孩子
                ans += w;
                st.push_back(v);
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def minReorder(self, n: int, connections: List[List[int]]) -> int:
        g = [[] for _ in range(n)]
        for a, b in connections:
            g[a].append((b, 1))   # 从 a 走向 b：与原方向同向，背离 0，必须掉头
            g[b].append((a, 0))   # 从 b 走向 a：与原方向反向，已经指向 0

        vis = [False] * n
        vis[0] = True
        stack = [0]
        ans = 0

        while stack:
            u = stack.pop()
            for v, w in g[u]:
                if vis[v]:
                    continue          # 回到父节点，跳过
                vis[v] = True         # v 是 u 的孩子
                ans += w
                stack.append(v)

        return ans
```

## 8. 边界情况与易错点

1. **$n = 2$ 的最小规模**：`[[1,0]]` 已经指向 0，答案为 0；`[[0,1]]` 必须掉头，答案为 1。两个分支都要能走通。
2. **整条链全背离 0**：`0→1→2→…→n-1` 时答案为 $n-1$，是上界；反之全指向 0 时答案为 0，是下界。代码不能对极值做特殊假设。
3. **标记写反**：把 $w=1$ 放到 $g[b]$ 上会得到 $(n-1) - ans$。示例 3 恰好是对称形态，错误代码也可能过，属于隐蔽 WA，建议用「$0\to1$ 应为 1」这种两步例子自测。
4. **递归爆栈**：$n = 5\times10^4$ 的退化链在 Python 中会超过默认递归深度 1000，必须用显式栈（或调大 `sys.setrecursionlimit`）。
5. **忘记 `vis` 导致重复计数**：树虽然无环，但不加访问标记会沿同一条边来回走，把标记反复累加。
6. **误以为 $a_i$ 是父节点**：`connections[i]` 的先后顺序与树上的父子关系无关，父子关系只能由「从 0 出发的遍历」确定。
7. **误以为 0 可以是任意节点**：题面固定城市 0 为首都，不能按「入度为 0 的点」之类猜测根。

**延伸思考**：

- **反向问题**：若要求城市 0 能到达所有城市，则每条边要指向背离 0 的方向，答案变成 $(n-1) - ans$——同一套遍历，只需统计另一半。
- **一般有向图**：如果底图不是树，而是任意有向图、每条边可掉头且代价为 1，要求所有点可达 0，就先按 SCC 缩点，再在缩点 DAG 上求以 0 为根的最小代价入树（Chu–Liu / Edmonds 最小树形图，或转成二分图匹配）。
- **要求强连通**：树改方向造不出环，必须新增路线；把叶子两两配对即可，最少需要 $\lceil L/2 \rceil$ 条新路线（$L$ 为叶子数），这是经典的「树加边变强连通」结论。
