# LeetCode 句子中的有效单词数 题解

## 1. 题目概述

- **标题 / 题号**：句子中的有效单词数（#2047，easy）
- **链接**：https://leetcode.cn/problems/number-of-valid-words-in-a-sentence/
- **来源**：LeetCode 第 264 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：给定字符串 `sentence`，由小写字母、数字、连字符 `'-'`、标点（`'!'`、`'.'`、`','`）和空格组成。句子按空格切分成若干 **token**（token 之间由一个或多个空格分隔）。一个 token 是**有效单词**当且仅当同时满足：

1. **不含数字**：仅由小写字母、连字符和/或标点组成；
2. **至多一个连字符** `'-'`：若存在，两侧必须都是小写字母（`"a-b"` 有效，`"-ab"`、`"ab-"` 无效）；
3. **至多一个标点**：若存在，必须位于 token 的**末尾**。

返回 `sentence` 中有效单词的数目。

**约束**：

- $1 \le \text{sentence.length} \le 1000$
- `sentence` 由小写字母、数字（`0-9`）、`' '`、`'-'`、`'!'`、`'.'`、`','` 组成
- 句子中至少有 $1$ 个 token

## 2. 示例

**示例 1**

```text
输入：sentence = "cat and  dog"
输出：3
解释：有效单词为 "cat"、"and"、"dog"（注意 "and" 后有两个空格，切分时自动合并）
```

**示例 2**

```text
输入：sentence = "!this  1-s b8d!"
输出：0
解释：
  "!this" 无效：'!' 在开头，不在末尾
  "1-s"   无效：含数字
  "b8d!"  无效：含数字
```

**示例 3**

```text
输入：sentence = "alice and  bob are playing stone-game10"
输出：5
解释：有效单词为 "alice"、"and"、"bob"、"are"、"playing"
"stone-game10" 无效：含数字
```

**示例 4**

```text
输入：sentence = "a-b. afad, ba-c a! !"
输出：5
解释：五个 token 全部有效——连字符两侧均为字母、标点均在末尾且至多一个
```

## 3. 解题思路

### 3.1 暴力思路

签到题，数据规模 $n \le 1000$，任何正确做法都能过。最朴素的方案：先按空格切分，再对每个 token 分三轮扫描——第一轮查数字、第二轮查连字符的数量与位置、第三轮查标点的数量与位置。逻辑直白，但每个 token 要扫三遍。

另一种想法是**正则表达式**。三条规则合起来其实可以写成一个正则：

```text
^([a-z]+(-[a-z]+)?[!.,]?|[!.,])$
```

但正则这条路有两个坑：写成 `^[a-z]*(-[a-z]+)?[!.,]?$` 会错误地匹配 `"-ab"`（前缀字母数取 0 时连字符可以出现在开头）；写成 `^[a-z]+(-[a-z]+)?[!.,]?$` 又会漏掉单独一个标点 `"!"` 这种有效单词。比赛现场调正则的时间远超手写扫描，不推荐。

### 3.2 核心观察：单趟扫描同时校验三条规则

![核心概念：字符四分类互斥，三规则一趟扫描](images/valid_token_rules_concept.svg)

空格在切分时已经处理完毕，token 内部只剩四类**互斥**的字符：小写字母、数字、连字符、标点。而三条规则本质上都是「**数量约束 + 位置约束**」：

| 规则 | 数量约束 | 位置约束 |
|------|---------|---------|
| ① 不含数字 | 数字个数 $= 0$ | — |
| ② 连字符 | $\le 1$ 个 | 不在首尾，两侧均为小写字母 |
| ③ 标点 | $\le 1$ 个 | 必须在末尾 |

因此只需**一趟扫描**，维护两个计数器 `hyphen_cnt`、`punct_cnt`，按当前字符的类型分派检查：

- 遇到**数字** → 立即判否（一票否决）；
- 遇到**连字符** → 计数加一，若超过 $1$ 判否；若在首尾判否；若两侧不全是大写/小写字母判否；
- 遇到**标点** → 计数加一，若超过 $1$ 或不在末尾判否。

> 💡 **关键洞察**：三条规则全部支持**短路**——遇到任何违规立即返回 `false`，无需扫完整个 token。大多数无效 token 在前几个字符处就被淘汰，例如 `"1-s"` 扫到第一个字符即出局。

### 3.3 算法流程

![算法流程：切分、逐字符分类校验、短路返回](images/valid_token_check_flow.svg)

1. 切分：Python 用无参 `sentence.split()`，C++ 用 `istringstream >> token`——两者都**自动合并连续空格**且不产生空 token；
2. 对每个 token 从左到右逐字符扫描，按四类字符分派到规则 ①②③ 的检查；
3. 任一检查失败 → 该 token 无效，跳下一个；
4. 扫描完未触发任何短路 → 该 token 有效，`ans++`。

### 3.4 示例演算

以示例 2 `"!this  1-s b8d!"` 为例（详见下图）：

| token | 首个违规点 | 违反规则 | 结果 |
|-------|-----------|---------|------|
| `!this` | `'!'` 在 $i=0$，不在末尾 | ③（位置） | 无效 |
| `1-s` | `'1'` 是数字 | ① | 无效 |
| `b8d!` | `'8'` 是数字 | ① | 无效 |

三个 token 全部无效，返回 $0$。对照一个全程无违规的 token `"a-b."`：`'a'`、`'b'` 是字母无约束；`'-'` 计数后 `hyphen_cnt = 1` 且两侧 `'a'`、`'b'` 均为字母；`'.'` 计数后 `punct_cnt = 1` 且位于末尾——四个字符全部通过，计入答案。

![示例演算：三个无效 token 的短路点与 a-b. 的计数器走查](images/valid_token_walkthrough.svg)

## 4. 算法细节

1. **切分方式**：Python 无参 `split()` 以任意连续空白为分隔符并丢弃空串；C++ `iss >> token` 同理。**不要**用 `split(' ')`——它以单个空格为界，连续空格会产生空字符串。
2. **连字符的检查顺序**：先计数判重（`++hyphen > 1`），再判位置（`i == 0 || i == n-1`），最后才访问 `t[i-1]`、`t[i+1]` 判两侧——**位置检查必须先于两侧访问**，否则数组越界。
3. **标点合并判断**：数量与位置一次判完，`++punct > 1 || i != n-1` 即违规。
4. **"两侧均为小写字母"的语义**：`"a-b"` 中 `-` 的两侧是 token 内的相邻字符；若相邻字符是另一个连字符（如 `"a--b"`），第二个 `-` 会先触发计数超过 $1$ 而短路，不会走到两侧检查。
5. **计数器只增不清零**：每个 token 独立校验，进入新 token 时 `hyphen_cnt`、`punct_cnt` 重新初始化为 $0$。

## 5. 正确性证明

**引理 1**（切分正确性）：无参 `split()` / `istringstream >>` 得到的序列恰为 `sentence` 的全部极大非空空白分隔子串。

**证明**：两者均以一个或多个空格为分隔，且不产生空串。若某极大非空子串 $t$ 未出现在结果中，则 $t$ 的首字符要么与前一 token 相邻（与极大性矛盾），要么被跳过（与"逐字符消费、仅空格作分隔"矛盾）。故切分结果恰为全部 token。∎

**引理 2**（校验等价性）：`isValid(t)` 返回 `true` 当且仅当 $t$ 满足三条规则。

**证明**：

- （$\Rightarrow$）设 `isValid(t)` 返回 `true`，则循环未被任何分支短路。扫描中没有数字字符出现（规则 ①）；每个 `'-'` 处计数不超过 $1$、不在首尾且两侧均为小写字母（规则 ②）；每个标点处计数不超过 $1$ 且位于末尾（规则 ③）。
- （$\Leftarrow$）设 $t$ 满足三条规则。扫描中不可能遇到数字（否则违反 ①）；遇到 `'-'` 时计数必 $\le 1$、不在首尾且两侧为字母，三个检查均不触发；遇到标点时计数必 $\le 1$ 且在末尾。故循环完整执行，返回 `true`。∎

**定理**：算法返回 `sentence` 中有效单词的数目。

**证明**：由引理 1，每个 token 恰被校验一次；由引理 2，每次校验结果与有效单词的定义一致。对返回 `true` 的 token 计数求和，即有效单词数目。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n$ 为 `sentence` 长度。所有 token 长度之和不超过 $n$（空格不计入 token），每个字符至多被访问常数次；短路使实际开销往往更低。
- **空间复杂度**：$O(n)$，切分产生的 token 字符串。若改为就地双指针扫描（跳过空格定位区间 $[l, r]$，直接在原串上校验），可降至 $O(1)$，此时连字符的边界判断相应改为 `i == l || i == r`。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countValidWords(string sentence) {
        istringstream iss(sentence);
        string token;
        int ans = 0;
        while (iss >> token)
            if (isValid(token)) ans++;
        return ans;
    }
private:
    bool isValid(const string& t) {
        int hyphen = 0, punct = 0, n = t.size();
        for (int i = 0; i < n; ++i) {
            char ch = t[i];
            if (isdigit(ch)) return false;
            if (ch == '-') {
                if (++hyphen > 1) return false;
                if (i == 0 || i == n - 1) return false;
                if (!isalpha(t[i - 1]) || !isalpha(t[i + 1])) return false;
            }
            if (ch == '!' || ch == '.' || ch == ',') {
                if (++punct > 1 || i != n - 1) return false;
            }
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def countValidWords(self, sentence: str) -> int:
        def isValid(t: str) -> bool:
            hyphen = punct = 0
            n = len(t)
            for i, ch in enumerate(t):
                if ch.isdigit():
                    return False
                if ch == '-':
                    hyphen += 1
                    if hyphen > 1 or i == 0 or i == n - 1:
                        return False
                    if not (t[i - 1].isalpha() and t[i + 1].isalpha()):
                        return False
                elif ch in '!,.':
                    punct += 1
                    if punct > 1 or i != n - 1:
                        return False
            return True

        return sum(isValid(t) for t in sentence.split())
```

## 8. 边界情况与易错点

1. **多空格切分出空串**：若误用 `split(' ')`，连续空格会产生空字符串；空串送进 `isValid` 会因循环不执行而返回 `true`，把空串数成有效单词！必须用无参 `split()`（或先过滤空串），C++ 的 `iss >> token` 天然安全。
2. **连字符两侧访问越界**：必须先判 `i == 0 || i == n-1` 再访问 `t[i-1]`、`t[i+1]`，顺序颠倒会数组越界。
3. **单字符 token**：`"a"` 有效；`"!"` 有效（题目明确给出）；`"-"` 无效——它既是首也是尾。
4. **两个连字符**：`"a--b"` 由第二个 `'-'` 触发 `hyphen > 1` 短路。
5. **标点不在末尾 / 标点超一个**：`"a!b"` 触发 `i != n-1`；`"a!."` 触发 `punct > 1`。
6. **数字一票否决**：`"b8d!"` 尽管结尾标点合法，仍因数字无效——检查顺序上数字最先短路。
7. **就地扫描版的边界偏移**：token 在原串中不一定从下标 $0$ 开始，边界判断要用 `i == l || i == r` 而非 `i == 0 || i == n-1`。
