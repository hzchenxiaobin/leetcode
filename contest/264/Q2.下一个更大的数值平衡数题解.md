# LeetCode 下一个更大的数值平衡数 题解

## 1. 题目概述

- **标题 / 题号**：下一个更大的数值平衡数（#2048，medium）
- **链接**：https://leetcode.cn/problems/next-greater-numerically-balanced-number/
- **来源**：LeetCode 第 264 场周赛 Q2
- **难度**：中等
- **标签**：数学、枚举、计数、回溯

**题意**：

如果一个整数 $x$ 满足：对于**每个出现的数位 $d$**，这个数位在 $x$ 的十进制表示中**恰好出现 $d$ 次**，则称 $x$ 为**数值平衡数**。给定整数 $n$，返回**严格大于** $n$ 的**最小**数值平衡数。

> 💡 换句话说，数位与出现次数被「绑定」：数字 $d$ 要么完全不出现，要么恰好出现 $d$ 次。例如 `22` 平衡（`2` 出现 2 次）、`1333` 平衡（`1` 出现 1 次、`3` 出现 3 次）、`123` 不平衡（`2` 只出现 1 次）。

**约束**：

- $0 \le n \le 10^6$

## 2. 示例

**示例 1**

```text
输入：n = 1
输出：22
解释：22 是数值平衡数（数字 2 出现 2 次），也是严格大于 1 的最小数值平衡数。
```

**示例 2**

```text
输入：n = 1000
输出：1333
解释：1333 中 1 出现 1 次、3 出现 3 次，是严格大于 1000 的最小平衡数。
注意 1022 不能作为答案：数字 0 出现了 2 次，而 0 要求出现 0 次。
```

**示例 3**

```text
输入：n = 3000
输出：3133
解释：3133 中 1 出现 1 次、3 出现 3 次，是严格大于 3000 的最小平衡数。
```

**示例 4（边界）**

```text
输入：n = 0
输出：1
解释：1 是最小的平衡数（数字 1 恰好出现 1 次）。0 本身不是平衡数。
```

**示例 5（最坏空隙）**

```text
输入：n = 666666
输出：1224444
解释：666666 是最大的 6 位平衡数；此后再无 6 位平衡数，
下一个平衡数直接跳到 7 位的 1224444（1×1 + 2×2 + 4×4），跨度 557778。
```

## 3. 解题思路

### 3.1 暴力思路：从 n+1 逐个校验

最朴素的写法是从 $n+1$ 开始递增枚举，对每个数 $x$ 统计各数位出现次数，判断是否每个 $d$ 都恰好出现 $d$ 次（含 0 即非法，因为 0 要求出现 0 次），命中即返回。

单次校验 $O(\log x)$，问题在于**空隙**：平衡数极其稀疏，在 $n \le 10^6$ 范围内最大空隙出现在 $666666$ 之后——6 位平衡数到此为止，下一个直接是 7 位的 $1224444$，跨度 $557778$。逐个校验最坏要做约 $5.6 \times 10^5$ 次数位分解，C++ 勉强通过、Python 已属侥幸；且一旦 $n$ 上界放大，该做法立刻失效。比赛中它只配当保底，不配当答案。

### 3.2 核心观察：候选集合一共只有 278 个

![核心概念：平衡数由数字集合唯一决定，全部候选仅 278 个](images/next_balanced_multiset_concept.svg)

跳出「从 $n$ 出发往上找」的思维，反过来问：**所有平衡数总共才有多少个？** 三个观察给出答案：

- **观察一（无 0）**：数字 $0$ 若出现，须出现 $0$ 次，矛盾。故平衡数只由 $1$–$9$ 组成，天然没有前导 $0$ 问题。
- **观察二（集合定多重集）**：$d$ 一旦出现就必须出现 $d$ 次，所以一个平衡数的数字多重集完全由数字**集合** $S \subseteq \{1,\dots,9\}$ 决定——$d \in S$ 就贡献 $d$ 个 $d$，总位数 $L = \sum_{d \in S} d$。集合与多重集一一对应。
- **观察三（上界封顶）**：$n \le 10^6$，而 $1224444$（即 $S = \{1,2,4\}$ 的最小排列）已经是平衡数且 $> 10^6$，故**答案 $\le 1224444$，至多 7 位**。于是只需考虑 $L \le 7$ 的子集。

$S \subseteq \{1,\dots,7\}$（$d = 8, 9$ 自身就占 $8$、$9$ 位，自动出局）且 $\sum_{d \in S} d \le 7$ 的子集共 **18 个**：

| $S$ | $L$ | $S$ | $L$ | $S$ | $L$ |
|---|---|---|---|---|---|
| $\{1\}$ | 1 | $\{2,3\}$ | 5 | $\{1,2,4\}$ | 7 |
| $\{2\}$ | 2 | $\{1,4\}$ | 5 | $\{3,4\}$ | 7 |
| $\{1,2\}$ | 3 | $\{5\}$ | 5 | $\{2,5\}$ | 7 |
| $\{3\}$ | 3 | $\{1,2,3\}$ | 6 | $\{1,6\}$ | 7 |
| $\{1,3\}$ | 4 | $\{2,4\}$ | 6 | $\{7\}$ | 7 |
| $\{4\}$ | 4 | $\{1,5\}$ | 6 | | |
| | | $\{6\}$ | 6 | | |

对每个子集把「$d$ 个 $d$」拼成字符串，生成所有**互异全排列**（排列数 $\frac{L!}{\prod_{d \in S} d!}$，最大单项来自 $\{1,2,4\}$ 的 $\frac{7!}{1!\,2!\,4!} = 105$），合计恰好 **278 个候选**。

> 💡 **关键转折**：与其在数轴上逐个试，不如把全部 278 个平衡数**一次性造出来排成有序表**，任何查询都变成表上二分：找第一个严格大于 $n$ 的元素。这就是「枚举候选」对「搜索」的降维打击。

### 3.3 算法流程

![算法流程：位掩码枚举子集 → 全排列 → 排序 → 二分](images/next_balanced_pipeline_flow.svg)

分两个阶段：

1. **预生成**：位掩码枚举 $\{1,\dots,7\}$ 的全部 $2^7 - 1$ 个非空子集；计算 $L = \sum_{d \in S} d$，超过 $7$ 直接剪枝；否则构造多重集字符串（$d$ 个 $d$），生成互异全排列并转成整数收集。全部子集处理完后排序。
2. **查询**：在有序候选表上 `upper_bound` / `bisect_right` 定位第一个严格大于 $n$ 的元素，即为答案。

### 3.4 示例演算

![示例演算：n=3000 落在 3133，n=1000 落在 1333，同一多重集的排列接力](images/next_balanced_n3000_walkthrough.svg)

以 $n = 3000$ 为例，候选升序表在 $3000$ 附近依次为 $333,\ 1333,\ 3133,\ 3313,\ 3331,\ 4444,\ \dots$。$1333 \le 3000$ 被淘汰，二分落在 $3133$，即答案——它正是 $S = \{1,3\}$ 的**第二个**排列。以 $n = 1000$ 为例，二分落在 $1333$（$\{1,3\}$ 的第一个排列）。

> ⚠️ **本题最大的陷阱**：不能每个子集只保留「最小排列」。若 $\{1,3\}$ 只交出 $1333$，那么 $3000$ 之后的候选会直接跳到 $\{4\}$ 的 $4444$，错答 $4444$。官方示例 3（$n = 3000$）正是专门防这个坑。更极端地，$n = 1224444$ 的答案是 $1242444$——同一个多重集 $\{1,2,4\}$ 的相邻排列互相接力，候选表里一个都不能少。

## 4. 算法细节

1. **子集枚举域**：位掩码覆盖 $\{1,\dots,7\}$ 即可。$d = 8$ 或 $9$ 单独出现就占 $8$、$9$ 位，任何含它们的子集 $L \ge 8 > 7$，天然出局，无需枚举。
2. **剪枝顺序**：先累加 $L$ 再判断 $L \le 7$，超限的子集在构造字符串之前就跳过，省去无谓的排列生成（例如 $\{1,\dots,7\}$ 全选时 $L = 28$）。
3. **全排列去重**：C++ 的 `next_permutation` 对含重复元素的序列**从升序起点**枚举，产出的就是字典序递增的互异排列，天然去重——前提是先 `sort`；Python 的 `itertools.permutations` 按下标区分元素，$\{1,3,3,3\}$ 会产出 $24$ 个（实际互异仅 $4$ 个），用 `set` 收集即可，规模极小不影响效率。
4. **整数转换**：多重集不含 $0$，任何排列的首位都非 $0$，`stoi` / `int()` 转换没有前导 $0$ 风险。最大候选 $7777777 < 2^{31} - 1$，`int` 足够。
5. **严格大于**：查询用 `upper_bound(cand.begin(), cand.end(), n)`（Python `bisect_right`），恰好定位「第一个 $> n$」的位置。$n$ 本身是平衡数时（如 $n = 1333$），答案是其后继 $3133$，二分边界见 §8。

## 5. 正确性证明

**引理 1**（结构引理）：$x$ 是平衡数，当且仅当存在非空集合 $S \subseteq \{1,\dots,9\}$，使 $x$ 的数位多重集恰为 $\{\underbrace{d,\dots,d}_{d \text{ 个}} : d \in S\}$。

**证明**：（$\Leftarrow$）该多重集中数字 $d$ 恰出现 $d$ 次、$d \notin S$ 的数字出现 $0$ 次，每个出现的数位 $d$ 都恰好出现 $d$ 次，故 $x$ 平衡。（$\Rightarrow$）设 $x$ 平衡，令 $S$ 为 $x$ 中出现的数字集合。由定义，每个 $d \in S$ 出现 $d$ 次；又 $0$ 若出现须出现 $0$ 次，矛盾，故 $S \subseteq \{1,\dots,9\}$ 且 $x$ 的数位多重集恰如上式。∎

**引理 2**（答案上界）：对任意 $n \le 10^6$，严格大于 $n$ 的最小平衡数不超过 $1224444$。

**证明**：$1224444$ 的数位多重集为 $\{1,2,2,4,4,4,4\}$，即 $S = \{1,2,4\}$ 按引理 1 是平衡数；且 $1224444 > 10^6 \ge n$。答案取的是「大于 $n$ 的平衡数」的最小值，自然不超过任何一个大于 $n$ 的平衡数。∎

**引理 3**（生成完备性）：算法生成的候选集合 $C$ 恰为全部位数 $\le 7$ 的平衡数，$|C| = 278$。

**证明**：由引理 1，位数 $\le 7$ 的平衡数与满足 $\sum_{d \in S} d = L \le 7$ 的集合 $S$ 一一对应（$L$ 即总位数），且同 $S$ 下的平衡数恰为其多重集的全部互异排列。位数 $\le 7$ 的合法 $S$ 必满足 $S \subseteq \{1,\dots,7\}$（$d \ge 8$ 使 $L \ge 8$），共 18 个（§3.2 表格），其互异排列数之和为

$$\sum_{S} \frac{\left(\sum_{d \in S} d\right)!}{\prod_{d \in S} d!} = 1 + 1 + 3 + 1 + 4 + 1 + 10 + 5 + 1 + 60 + 15 + 6 + 1 + 105 + 35 + 21 + 7 + 1 = 278,$$

位掩码枚举覆盖全部 18 个子集且 `next_permutation` / `set` 保证排列互异，故 $C$ 恰为所求集合。∎

**定理**：算法对任意 $n \le 10^6$ 返回严格大于 $n$ 的最小平衡数。

**证明**：设真答案为 $a$。由引理 2，$a \le 1224444$，故 $a$ 是位数 $\le 7$ 的平衡数；由引理 3，$a \in C$。又 $a > n$，故 $a \in \{x \in C : x > n\}$，该集合非空，且算法经 `upper_bound` 返回其最小元 $m$。一方面 $m \ge a$ 不必然，但 $a$ 属于该集合而 $m$ 是其最小元，故 $m \le a$；另一方面 $m$ 是平衡数（$m \in C$）且 $m > n$，由 $a$ 是此类数的最小者得 $m \ge a$。二者夹逼 $m = a$。∎

## 6. 复杂度分析

- **时间复杂度**：预生成 $O(P \log P)$，其中 $P = 278$ 为候选总数（排列生成总量为 $P$，排序 $O(P \log P)$，$18$ 个子集的掩码枚举 $O(2^7 \cdot 7)$ 可忽略）；单次查询为有序表上的二分 $O(\log P) \approx O(1)$。即便把预生成放在查询函数内每次重算，总量也是常数级，无需静态缓存。
- **空间复杂度**：$O(P)$，即存储 278 个候选整数的数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int nextBeautifulNumber(int n) {
        vector<int> cand;
        for (int mask = 1; mask < (1 << 7); ++mask) {
            string s;
            int total = 0;
            for (int d = 1; d <= 7; ++d)
                if ((mask >> (d - 1)) & 1) {
                    s += string(d, '0' + d);   // d 个 d
                    total += d;
                }
            if (total > 7) continue;           // 位数上界：答案 <= 1224444
            sort(s.begin(), s.end());          // next_permutation 需升序起点
            do {
                cand.push_back(stoi(s));       // 不含 0，无前导 0 之忧
            } while (next_permutation(s.begin(), s.end()));
        }
        sort(cand.begin(), cand.end());
        return cand[upper_bound(cand.begin(), cand.end(), n) - cand.begin()];
    }
};
```

### Python

```python
from itertools import permutations
import bisect


class Solution:
    def nextBeautifulNumber(self, n: int) -> int:
        cand = set()
        for mask in range(1, 1 << 7):
            digits, total = [], 0
            for d in range(1, 8):
                if (mask >> (d - 1)) & 1:
                    digits.extend(str(d) * d)  # d 个 d
                    total += d
            if total > 7:
                continue                       # 位数上界：答案 <= 1224444
            cand.update(int("".join(p)) for p in permutations(digits))
        cand = sorted(cand)                    # set 去重后排序
        return cand[bisect.bisect_right(cand, n)]   # 第一个 > n
```

> 💡 两份实现均已对拍验证：$n = 0 \to 1$、$1 \to 22$、$1000 \to 1333$、$3000 \to 3133$、$1333 \to 3133$、$4444 \to 14444$、$666666 \to 1224444$、$1000000 \to 1224444$、$1224444 \to 1242444$，另与逐个递增的暴力校验在数百个随机点上一致。

## 8. 边界情况与易错点

1. **严格大于而非大于等于**：$n$ 本身是平衡数时，答案是它在候选表中的**后继**（$n = 1333 \to 3133$，$n = 1 \to 22$，$n = 22 \to 122$）。C++ 必须用 `upper_bound`，Python 必须用 `bisect_right`；误用 `lower_bound` / `bisect_left` 在 $n$ 已在表中时会把 $n$ 原样返回。
2. **必须生成全部排列**：只留每个子集的最小排列，$n = 3000$ 会错答 $4444$（正确 $3133$）；$n = 1224444$ 的答案 $1242444$ 与 $n$ 同为 $\{1,2,4\}$ 的排列。同一多重集内部可以「接力」，候选表缺一个就错。
3. **位数上界 7 的来源**：它不是「$n$ 的位数 + 1」这种拍脑袋，而是由 $1224444 > 10^6$ 锚定的（引理 2）。若 $n$ 上界放大，需同步放大 $L$ 的上界并重新数子集，见「延伸思考」。
4. **C++ 忘记先 `sort`**：`next_permutation` 从当前字典序继续枚举，非升序起点会漏掉一部分排列。它对重复元素天然去重，这点倒是免费的。
5. **Python 忘记去重**：`permutations` 按下标展开，$\{1,3,3,3\}$ 产出 $24$ 个序列（互异仅 $4$ 个），必须用 `set` 收集，否则表中出现重复元素虽不影响 `bisect_right` 的正确性，但排序数组里混重复是坏味道且规模失控（$L = 7$ 时单项可达 $5040$）。
6. **$n = 0$**：答案是 $1$ 而不是 $0$（$0$ 含数位 $0$ 一次，不合法）也不是 $11$（$1$ 出现 2 次，$\ne 1$）。
7. **数值范围**：最大候选 $7777777 < 2^{31} - 1$，全程 `int` 安全，无需 `long long`。
8. **暴力法的最坏情形**：$666666$ 之后候选断档至 $1224444$，逐个校验需 $5.6 \times 10^5$ 次数位分解；这是「枚举候选」做法在比赛中真正碾压「搜索」的地方。

**延伸思考**：

1. **上界放大后预生成何时失效？** 候选数随位数组合爆炸：$\sum d \le 9$ 时约 $3.1 \times 10^3$ 个、$\le 10$ 时约 $2.1 \times 10^4$ 个、$\le 12$ 时约 $2.7 \times 10^5$ 个——覆盖 $n \le 10^{12}$ 量级仍可行；但 $\le 18$（对应 $n \le 10^{18}$）时排列总数达约 $5.4 \times 10^9$，预生成彻底破产，必须改为**逐位构造**：从最高位起按字典序搜索、用「剩余位数能否凑出合法多重集」剪枝，复杂度与位数同阶。
2. **改成区间计数**：「$[l, r]$ 内平衡数有几个」在预生成表上两次二分相减即得（$f(r) - f(l-1)$，$f$ 用 `bisect_right` 实现）；更一般的逐位计数视角见 4095 的数位 DP 题解。
3. **为什么最大空隙恰好横跨 $666666 \to 1224444$？** 6 位平衡数的最大子集是 $\{6\}$（$666666$），而 7 位平衡数的最小排列来自 $\{1,2,4\}$（$1224444$）——「位数切换处」天然是平衡数最稀疏的地方，这一结构性观察也能用来估计任何「下一个平衡数」问题的空隙上界。
