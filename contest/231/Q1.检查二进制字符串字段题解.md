# LeetCode 检查二进制字符串字段 题解

## 1. 题目概述

- **标题 / 题号**：检查二进制字符串字段（#1784，easy）
- **链接**：https://leetcode.cn/problems/check-if-binary-string-has-at-most-one-segment-of-ones/
- **来源**：LeetCode 第 231 场周赛 Q1
- **难度**：简单
- **标签**：字符串、脑筋急转弯

**题意**：给定二进制字符串 `s`，保证**不含前导零**（即 `s[0]` 为 `'1'`）。若 `s` 中由连续 `'1'` 组成的字段数为**零个或一个**，返回 `true`；否则返回 `false`。

**约束**：

- $1 \le \text{s.length} \le 100$
- `s[i]` 为 `'0'` 或 `'1'`
- `s[0]` 为 `'1'`

> 💡 **签到题的题眼**：约束里最不起眼的「`s[0]` 为 `'1'`」是全部捷径的来源——它保证串里**已经有一段 1**，于是「零个或一个」直接退化为「恰好一个」，判定被压成找一个两字符禁式。从读题到提交，正确路径不超过三分钟。

## 2. 示例

**示例 1**

```text
输入：s = "1001"
输出：false
解释：由连续若干个 '1' 组成的字段数量为 2（"1" 和 "1"），返回 false。
```

**示例 2**

```text
输入：s = "110"
输出：true
解释：只有一个连续 '1' 字段 "11"，返回 true。
```

**示例 3（自造边界：最短串）**

```text
输入：s = "1"
输出：true
解释：单字符自成一段，段数为 1。
```

**示例 4（自造边界：三明治形状）**

```text
输入：s = "101"
输出：false
解释：两个 1 字段被一个 0 隔开，(1,2) 处出现相邻对 "01"。
```

## 3. 解题思路

### 3.1 暴力思路：扫描统计 1 的段数

最通用的做法是线性扫描数段数：维护上一个字符 `prev`（初值取哨兵 `'0'`），每当遇到 `prev == '0'` 且当前字符为 `'1'`，说明一次 `0→1` 转换开启了一段新的 1，段数加一；最后判断段数是否 $\le 1$。

```text
segments = 0
prev = '0'
for c in s:
    if c == '1' and prev == '0':
        segments += 1
    prev = c
return segments <= 1
```

时间 $O(n)$、空间 $O(1)$，$n \le 100$ 下毫无压力，渐近上已是最优。但它维护了「段数」这个**累加状态**，而题目真正要的只是一个**布尔答案**——存在冗余。签到题的复盘价值正在于：识别出结构条件，把这个冗余消掉。

### 3.2 核心观察：`s[0]='1'` ⇒ 判「至多一段」⇔ 查禁式 `"01"`

![核心观察：合法串必形如 1*0*，禁式是相邻对 01](images/wc231_q1_ones_segment_concept.svg)

三步推理把问题压到最短：

1. **下界**：`s[0]` 为 `'1'` ⇒ 串中至少存在一段 1。于是「零个或一个」**退化为「恰好一个」**——全 0 串已被约束排除，无需特判。
2. **形状**：恰好一段 ⇔ 所有 1 **连续挤在前缀**、其后只能跟 0，即合法串必形如

$$
\underbrace{1\cdots1}_{\text{唯一的 1 段}}\;\underbrace{0\cdots0}_{\text{可选的尾随 0}} \;=\; 1^{*}0^{*}
$$

3. **禁式**：「0 之后又出现 1」的**最小局部表现**就是相邻字符对 `"01"`。非相邻的 $0\cdots1$ 中间必然夹着一次 `0→1` 的相邻转换，故查相邻对就足够：

$$
\text{段数} \le 1 \;\Longleftrightarrow\; \text{子串 "01" 不存在} \;\Longleftrightarrow\; s \in 1^{*}0^{*}
$$

> 💡 **为什么查的是 `"01"` 而不是 `"10"`**：段数的变化只发生在相邻边界上——`0→1` **开启**新段（段数 $+1$），`1→0` 只是**关闭**当前段（段数不变）。既然初始已有一段，唯一的威胁是「第二段被开启」，对应的禁式正是 `"01"`。

### 3.3 算法流程

![算法流程：一趟扫描相邻字符对，命中 01 立即返回 false](images/wc231_q1_ones_scan_flow.svg)

1. **输入**：`s`（保证 `s[0]='1'`）。
2. **扫描**：遍历 $i = 0, 1, \dots, n-2$，检查相邻对 $(s[i], s[i+1])$。
3. **命中**：若某对等于 `"01"`（$s[i]$ 为 `'0'` 且 $s[i+1]$ 为 `'1'`），立即返回 `false`。
4. **终止**：扫描完毕未命中，返回 `true`。

每个下标 $O(1)$ 比较，整体单趟线性。实际提交时无需手写循环——语言内置的子串查找就是这份流程的成品：Python 的 `"01" in s`、C++ 的 `s.find("01")`。

### 3.4 示例演算

![示例演算：1001 命中 01 返回 false，110 未命中返回 true](images/wc231_q1_ones_walkthrough.svg)

**示例 1** `s = "1001"`（逐对扫描）：

| 相邻对 | 字符 | 是否 `"01"` | 动作 |
|--------|------|------------|------|
| $(0,1)$ | `"10"` | ✗ | 继续 |
| $(1,2)$ | `"00"` | ✗ | 继续 |
| $(2,3)$ | `"01"` | ✓ | 命中 → 返回 `false` |

下标 $2 \to 3$ 处 `0` 后紧跟 `1`，开启了第二段 1，段数为 2，返回 `false` ✓。

**示例 2 / 示例 4** `s = "110"`、`s = "101"`（逐对扫描）：

| 串 | 相邻对序列 | 结果 |
|----|-----------|------|
| `"110"` | `"11"`、`"10"` | 未命中 → `true` |
| `"101"` | `"10"`、`"01"` | 第 2 对命中 → `false` |

> ⚠️ `"10"` 不是禁式——它是 `1→0`，关闭当前段但**不开启新段**；只有 `"01"`（`0→1`）才开新段。方向记反是本题唯一的 WA 来源。

## 4. 算法细节

1. **等价链**：`s[0]='1'` ⇒ 段数 $\ge 1$，故「至多一段」⇔「恰好一段」⇔「无第二段」⇔「无 `"01"` 子串」⇔ $s \in 1^{*}0^{*}$。链上任何一环都可作为实现依据，取离内置函数最近的一环即可。
2. **一行实现**：判定即一次长度为 2 的子串查找——Python `return "01" not in s`；C++ `return s.find("01") == string::npos;`。模式长度固定为 2，查找本质是 $n-1$ 次两字符比较。
3. **显式扫描版（通用备选）**：统计相邻 `0→1` 转换次数 $t$，则段数 $= t + 1$（`s[0]='1'` 贡献初始段），判 $t = 0$ 即可。该写法不依赖「至多一段」的特殊性，推广到「至多 $k$ 段」时依然成立（判 $t \le k-1$）。
4. **正则备选**：合法串集合恰为 $1^{*}0^{*}$，正则 `^1*0*$` 语义等价。但正则引擎常数大，C++ 还需引入 `<regex>` 头文件拖慢编译，签到题抢时间的场景不作首选。

## 5. 正确性证明

**引理 1（段数下界）**：若 `s[0]` 为 `'1'`，则 `s` 中连续 1 字段的段数 $\ge 1$。

**证明**：`s[0]` 是 `'1'`，必然属于某个极大连续 1 字段，故至少存在一段。∎

**引理 2（禁式刻画）**：段数 $\ge 2$ $\Longleftrightarrow$ 存在下标 $i$ 使 $s[i]$ 为 `'0'` 且 $s[i+1]$ 为 `'1'`（即子串 `"01"` 出现）。

**证明**：（⇒）设段数 $\ge 2$。极大字段从左到右互不重叠且有序，含 $s[0]$ 的字段是第一段且起点为 $0$；取第二段的起点 $j$，则 $j \ge 1$。若 $s[j-1]$ 为 `'1'`，则位置 $j-1$ 与 $j$ 的两个 1 相连，同属一个字段，$j$ 就不是字段起点，矛盾；故 $s[j-1]$ 为 `'0'`，$(j-1, j)$ 处出现 `"01"`。（⇐）设 $s[i]$ 为 `'0'` 且 $s[i+1]$ 为 `'1'`。位置 $i+1$ 的 1 所在极大字段因左侧被 0 截断，起点恰为 $i+1$；而含 $s[0]$ 的字段起点为 $0 \ne i+1$，两者是不同字段，故段数 $\ge 2$。∎

**定理**：算法（判定 `"01"` 是否为 `s` 的子串）返回 `true` 当且仅当 `s` 的连续 1 字段数 $\le 1$。

**证明**：由引理 1，段数 $\ge 1$ 恒成立，故「段数 $\le 1$」⇔「段数 $< 2$」⇔「段数 $\ge 2$ 不成立」。再由引理 2，后者 ⇔「`"01"` 不是 `s` 的子串」，恰为算法的判定条件。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。子串查找对每个起点至多做两次字符比较，共 $n-1$ 个起点；$n \le 100$ 时也只是数百次操作。
- **空间复杂度**：$O(1)$。一行版不分配任何额外结构；显式扫描版也只需 `prev` 与计数器两个变量。

> 💡 本题的价值不在复杂度（扫描计数同为 $O(n)/O(1)$），而在**思维降维**：把「计数问题」压成「存在性问题」，代码从七行缩到一行。识别约束条件里的降维钥匙，正是签到题要沉淀的核心能力。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool checkOnesSegment(string s) {
        return s.find("01") == string::npos;
    }
};
```

### Python

```python
class Solution:
    def checkOnesSegment(self, s: str) -> bool:
        return "01" not in s
```

## 8. 边界情况与易错点

1. **禁式方向**：`"10"` 合法（`1→0` 只关段），`"01"` 非法（`0→1` 开新段）。把禁式误写成 `"10"` 会让 `"110"` 被误判为 `false`——方向反了全盘皆错，这是本题最典型的 WA 点。
2. **$n = 1$**：`s = "1"` 无相邻对可查，扫描循环体不执行，直接返回 `true`；一行版 `"01" not in "1"` 同样为 `true`，无需特判。
3. **全 1 串**：如 `"111"`，只有一段，返回 `true`，算法自然覆盖。
4. **别去处理全 0 串**：题面的「零个或一个」容易诱导人特判全 0 输入，但 `s[0]='1'` 已排除全 0，加了特判反而是死代码。
5. **去掉 `s[0]='1'` 后不能沿用**：如 `"0011"` 恰好一段 1，却含 `"01"` 子串，会被一行版误判为 `false`。一般情形需改用「段数 $=$ `0→1` 转换数 $+\ [\text{s}[0]\ \text{为}\ \text{'1'}]$」重新推导（见延伸思考）。
6. **正则慎用**：`^1*0*$` 语义等价但常数大，C++ 引入 `<regex>` 明显拖慢编译，签到题一律用子串查找。
