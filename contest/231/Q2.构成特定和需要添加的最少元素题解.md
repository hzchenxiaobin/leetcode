# LeetCode 构成特定和需要添加的最少元素 题解

## 1. 题目概述

- **标题 / 题号**：构成特定和需要添加的最少元素（#1785，medium）
- **链接**：https://leetcode.cn/problems/minimum-elements-to-add-to-form-a-given-sum/
- **来源**：LeetCode 第 231 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、数学

**题意**：给定整数数组 `nums` 与整数 `limit`、`goal`，数组满足 $\lvert \text{nums}[i] \rvert \le \text{limit}$。可以向数组中**添加**若干元素（每个新元素的绝对值同样不超过 `limit`），使数组元素总和恰好等于 `goal`。返回最少需要添加的元素数量。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{limit} \le 10^6$
- $-\text{limit} \le \text{nums}[i] \le \text{limit}$
- $-10^9 \le \text{goal} \le 10^9$

> ⚠️ **先看数据范围再动手**：$10^5$ 个绝对值至多 $10^6$ 的数求和，$\lvert S \rvert$ 可达 $10^{11}$，远超 32 位 `int` 上界（$\approx 2.1 \times 10^9$）。C++ 累加必须用 `long long`——这是本题最大的 WA 来源，比算法本身更容易翻车。

> 💡 **比赛视角**：这是一道「纸面一步、代码一行」的数学降维题。核心是把「添加哪些元素」的构造问题，换成「差距多大、每块最多补多少」的计数问题，答案是一步上取整除法。与 Q1 的套路同源：约束里藏着一步数学捷径。

## 2. 示例

**示例 1**

```text
输入：nums = [1,-1,1], limit = 3, goal = -4
输出：2
解释：添加 -2 和 -3，总和变为 1 - 1 + 1 - 2 - 3 = -4。
```

**示例 2**

```text
输入：nums = [1,-10,9,1], limit = 100, goal = 0
输出：1
```

**示例 3（自造边界：差距为零）**

```text
输入：nums = [1,2,3], limit = 5, goal = 6
输出：0
解释：总和已是 6 = goal，无需添加任何元素。
```

**示例 4（自造边界：limit = 1）**

```text
输入：nums = [5,5], limit = 1, goal = 0
输出：10
解释：总和为 10，每个新元素绝对值至多 1，需添加 10 个 -1。
```

## 3. 解题思路

### 3.1 暴力思路：逐块添加模拟

最直观的做法是模拟：算出当前总和 $S$ 与 `goal` 的差距 $\text{diff} = \text{goal} - S$，每次添加一个**绝对值打满**（即 $\pm\text{limit}$，符号与 `diff` 同号）的元素缩小差距，直到归零。

```text
diff = goal - sum(nums)
ans = 0
while diff != 0:
    step = sign(diff) * min(limit, abs(diff))   # 每次最多填 limit
    diff -= step
    ans += 1
return ans
```

逻辑正确，但当 $\lvert \text{diff} \rvert$ 很大、`limit` 很小时循环次数极大：最坏 $\lvert \text{diff} \rvert \approx 10^{11}$、$\text{limit} = 1$ 时需循环 $10^{11}$ 次，**必然超时**。但这个模拟里藏着降维钥匙——每一步的动作**完全相同**（除最后一步余数外都是 $\pm\text{limit}$），相同步骤重复 $k$ 次就该写成乘法，循环就该提炼成除法。

### 3.2 核心观察：差距 + 上取整 = 一步闭式

![核心观察：差距 |goal − S| 是坑深，每块新元素最多填 limit](images/wc231_q2_gap_fill_concept.svg)

**等价转化**：题目只约束「总和」，添加的元素彼此独立、与原数组元素无位置或顺序耦合，因此数组唯一有用的信息就是 $S = \sum \text{nums}[i]$——一遍求和后原数组即可丢弃。问题从「构造数组」坍缩为：

> 用最少的 $k$ 个数 $x_1, \dots, x_k$（每个 $\lvert x_i \rvert \le \text{limit}$），使 $\sum x_i = \text{diff}$。

把 $\lvert \text{diff} \rvert$ 看作**坑深**，每个新元素是一块**厚度不超过 `limit` 的砖**：

- **下界**（必要性）：$k$ 块砖总厚度至多 $k \cdot \text{limit}$，要填平深 $\lvert \text{diff} \rvert$ 的坑，必须 $k \cdot \text{limit} \ge \lvert \text{diff} \rvert$，即 $k \ge \left\lceil \lvert \text{diff} \rvert / \text{limit} \right\rceil$；
- **可达**（构造）：取 $k = \left\lceil \lvert \text{diff} \rvert / \text{limit} \right\rceil$，先铺 $k-1$ 块厚度打满的「整砖」$\text{sign}(\text{diff}) \cdot \text{limit}$，再补 1 块「余数砖」$\text{sign}(\text{diff}) \cdot r$，其中 $r = \lvert \text{diff} \rvert - (k-1)\text{limit} \in (0, \text{limit}]$，合法且恰好填平。

> 💡 **结论**：下界与构造重合，最少添加数就是

$$
\text{ans} = \left\lceil \frac{\lvert \text{goal} - S \rvert}{\text{limit}} \right\rceil = \frac{\lvert \text{goal} - S \rvert + \text{limit} - 1}{\text{limit}} \;(\text{整数除法})
$$

**符号无关性**：差距为正铺 $+\text{limit}$，为负铺 $-\text{limit}$，块数只取决于绝对值。当 $\text{diff} = 0$ 时公式给出 $(0 + \text{limit} - 1) \, // \, \text{limit} = 0$（因 $\text{limit} \ge 1$），**天然正确，无需特判**。

### 3.3 算法流程

![算法流程：求和 → 差距 → 上取整](images/wc231_q2_ceil_div_flow.svg)

1. **求和**：$S = \sum \text{nums}[i]$，C++ 用 `long long` 累加。
2. **算差距**：$d = \lvert \text{goal} - S \rvert$。
3. **上取整**：$\text{ans} = (d + \text{limit} - 1) \, // \, \text{limit}$。
4. **返回** `ans`。

> 💡 **整数上取整技巧**：$\lceil a / b \rceil = (a + b - 1) \, // \, b$（$a \ge 0$，$b \ge 1$）。全程整数运算，避开浮点 `ceil` 的精度隐患，这个式子在二分答案的验证函数里也反复出场（如 875. 爱吃香蕉的珂珂）。

### 3.4 示例演算

![示例演算：三个算例的求和、差距、上取整与验证](images/wc231_q2_example_walkthrough.svg)

**示例 1** `nums = [1,-1,1]`, `limit = 3`, `goal = -4`：

| 步骤 | 计算 | 结果 |
|------|------|------|
| ① 求和 | $S = 1 + (-1) + 1$ | $1$ |
| ② 差距 | $d = \lvert -4 - 1 \rvert$ | $5$ |
| ③ 上取整 | $\text{ans} = \lceil 5/3 \rceil = (5+3-1)//3$ | $2$ |

验证：添加 $-3$ 和 $-2$（$\lvert -3 \rvert = 3 \le 3$，$\lvert -2 \rvert = 2 \le 3$），$1 - 3 - 2 = -4 = \text{goal}$ ✓。

**示例 2** `nums = [1,-10,9,1]`, `limit = 100`, `goal = 0`：

| 步骤 | 计算 | 结果 |
|------|------|------|
| ① 求和 | $S = 1 - 10 + 9 + 1$ | $1$ |
| ② 差距 | $d = \lvert 0 - 1 \rvert$ | $1$ |
| ③ 上取整 | $\text{ans} = \lceil 1/100 \rceil$ | $1$ |

> ⚠️ 示例 2 说明：即使差距很小、`limit` 很大，只要差距**非零**就至少需要 $1$ 个元素——上取整保证了这一点。而示例 4（`limit = 1`，$d = 10$）是最「碎」的情形，答案就是坑深本身。

## 4. 算法细节

1. **等价转化的依据**：目标只约束「总和」这一全局量，添加元素之间、添加元素与原数组之间均无顺序/位置/互异性约束，所以问题自由度只剩「总和」，从「构造数组」降为「凑差额」。凡是见到「只问总和/总量」的构造题，先想这一步坍缩。
2. **整数上取整**：$(d + \text{limit} - 1) \, // \, \text{limit}$。注意必须先对 $d$ 取绝对值再除——Python 的 `//` 对负数向下取整，若直接写 $(\text{diff} + \text{limit} - 1) // \text{limit}$ 且 `diff` 为负会得到错误结果。
3. **C++ 类型链**：求和用 `long long`（`accumulate` 的**初值**决定累加类型，必须传 `0LL`）；作差前把 `goal` 显式转 `long long`（防御性写法，即使 `total` 类型笔误也能在编译期暴露）；除法在 64 位上做，最后强转 `int` 返回。
4. **为什么不做 DP**：这是「**单一面值**」凑数问题——只有一种面值 $\text{limit}$，最少块数直接是上取整。面值集合一旦变大（如 322. 零钱兑换），才需要 DP 或贪心讨论；面值连续可用时甚至要构造性贪心（如 1775）。
5. **贪心视角**：「每步放厚度最大的砖」是最优贪心，且任何最优方案都可调整为此形态而不改变个数（多余的小砖可以合并成大砖，个数不增），与下界论证殊途同归。

## 5. 正确性证明

**引理 1（总贡献上界）**：设 $x_1, \dots, x_k$ 满足 $\lvert x_i \rvert \le L$，则 $\left\lvert \sum_{i=1}^{k} x_i \right\rvert \le kL$。

**证明**：由三角不等式，$\left\lvert \sum_{i=1}^{k} x_i \right\rvert \le \sum_{i=1}^{k} \lvert x_i \rvert \le \sum_{i=1}^{k} L = kL$。∎

**引理 2（下界）**：若 $k$ 个绝对值不超过 $L$ 的数之和为 $d \ne 0$，则 $k \ge \lceil \lvert d \rvert / L \rceil$。

**证明**：由引理 1，$kL \ge \lvert d \rvert$，故 $k \ge \lvert d \rvert / L$；$k$ 为整数，向上取整即 $k \ge \lceil \lvert d \rvert / L \rceil$。∎

**引理 3（构造可达）**：对任意 $d \ne 0$，取 $k = \lceil \lvert d \rvert / L \rceil$，存在 $k$ 个绝对值不超过 $L$ 的数，其和恰为 $d$。

**证明**：设 $s = \operatorname{sign}(d)$，$r = \lvert d \rvert - (k-1)L$。由上取整定义，$k - 1 < \lvert d \rvert / L \le k$，故 $(k-1)L < \lvert d \rvert \le kL$，即 $0 < r \le L$。取前 $k-1$ 个数为 $sL$、第 $k$ 个数为 $sr$：前 $k-1$ 个绝对值为 $L$、第 $k$ 个绝对值为 $r \le L$，全部合法；且 $\sum x_i = s\big((k-1)L + r\big) = s \lvert d \rvert = d$。∎

**定理**：设 $S = \sum \text{nums}[i]$，则最少添加元素数为 $\text{ans} = \left\lceil \lvert \text{goal} - S \rvert / \text{limit} \right\rceil$（$\text{goal} = S$ 时取 $0$）。

**证明**：添加元素除总和外与原数组无任何耦合，问题等价于求最少的绝对值不超过 $\text{limit}$ 的数使其和为 $d = \text{goal} - S$。若 $d = 0$：零个数即满足；且公式给出 $\lceil 0 / L \rceil = 0$（$L \ge 1$），一致。若 $d \ne 0$：由引理 2，任何可行方案至少用 $\lceil \lvert d \rvert / L \rceil$ 个数；由引理 3，恰用该个数的方案存在。二者重合，故为最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，$n = \text{nums.length}$。唯一的一次遍历是求和；差距、上取整、返回均为 $O(1)$。
- **空间复杂度**：$O(1)$。只用常数个变量，连原数组都不需要再访问第二遍。

> 💡 对照暴力模拟的 $O(\lvert \text{diff} \rvert / \text{limit})$：最坏 $10^{11}$ 次循环必然 TLE；把「重复相同步骤」提炼为除法后，循环消失，这是本题从 TLE 到 AC 的关键一步，也是从「模拟」到「数学」的经典跃迁。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minElements(vector<int>& nums, int limit, int goal) {
        long long total = accumulate(nums.begin(), nums.end(), 0LL);
        long long diff = abs((long long)goal - total);
        return (int)((diff + limit - 1) / limit);
    }
};
```

### Python

```python
class Solution:
    def minElements(self, nums: List[int], limit: int, goal: int) -> int:
        diff = abs(goal - sum(nums))
        return (diff + limit - 1) // limit
```

## 8. 边界情况与易错点

1. **求和溢出（最高频 WA）**：$\lvert S \rvert$ 可达 $10^5 \times 10^6 = 10^{11}$，远超 `int`。C++ 的 `accumulate` 累加类型由**初值**决定——传 `0` 全程 `int` 累加必溢出，必须传 `0LL`。
2. **作差也要 64 位**：`goal` 虽在 `int` 范围（$\pm 10^9$），但 $\text{goal} - S$ 可达约 $10^{11}$。写 `(long long)goal - total` 是防御性习惯；若 `total` 已是 `long long`，普通写法也会被提升，安全但隐性。
3. **差距为零**：$(0 + \text{limit} - 1) // \text{limit} = 0$（$\text{limit} \ge 1$），公式天然覆盖，特判可省。比赛时先口头说一句「diff 为零返回 0」再指出公式已覆盖，是展示严谨的加分动作。
4. **答案的范围**：理论上 $\text{ans} \le \lceil 1.01 \times 10^{11} / 1 \rceil$ 超出 `int` 返回类型，LeetCode 数据保证实际答案在 `int` 内；但**中间量**（求和、差距）必须全程 64 位，返回时再强转。
5. **`abs` 的重载**：操作数是 `long long` 时要用 `std::abs` 的对应重载（C 的 `abs(int)` 会截断 64 位值）。最稳写法是先确保表达式类型为 `long long`，再在 `std` 作用域下调用 `abs`。
6. **Python 负数整除**：`//` 对负数向下取整，所以必须**先 `abs` 再除**；直接对负 `diff` 用上取整式会得到错值。
7. **别搭多余结构**：不需要排序、不需要 DP 表、不需要修改或重排原数组——它只是个求和对象。看到 medium 标签先想数学，再想数据结构。
