# LeetCode 保证文件名唯一 题解

## 1. 题目概述

- **标题 / 题号**：保证文件名唯一（#1487，medium）
- **链接**：https://leetcode.cn/problems/making-file-names-unique/
- **来源**：LeetCode 第 194 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串

**题意**：按顺序处理 $names[0 \dots n-1]$，为每个「想要的名字」分配一个「实际文件名」。若 $names[i]$ 还没被占用，就直接用它；否则在它**后面**拼接 `(k)`，其中 $k$ 是能让结果唯一的最小正整数。返回每个位置实际分配到的名字。

这题规则只有两句话，但有两个坑：

- **后缀会叠加**：`kaido(1)` 再次撞名时得到的是 `kaido(1)(1)`，而不是 `kaido(2)`——也就是说「基名」永远是 $names[i]$ 这整个串，**不要**把已有的 `(k)` 剥掉再当作基名。
- **$k$ 是最小可用正整数**：不是「当前最大后缀加一」，必须真的从小到大找第一个空闲的 $k$。

**约束**：

- $1 \le n \le 5 \times 10^4$
- $1 \le \lvert names[i] \rvert \le 20$
- $names[i]$ 只由小写英文字母、数字和圆括号组成

## 2. 示例

**示例 1**

```text
输入：names = ["gta","gta(1)","gta","avalon"]
输出：["gta","gta(1)","gta(2)","avalon"]
解释："gta" 先占住；"gta(1)" 之前未分配，原样保留；
      第三个 "gta" 撞名，k=1 时 gta(1) 已被占，故 k=2 → "gta(2)"。
```

**示例 2**

```text
输入：names = ["onepiece","onepiece(1)","onepiece(2)","onepiece(3)","onepiece"]
输出：["onepiece","onepiece(1)","onepiece(2)","onepiece(3)","onepiece(4)"]
解释：最后一个 "onepiece" 撞名，k=1,2,3 全被占，最小可用 k 是 4。
```

**示例 3**

```text
输入：names = ["kaido","kaido(1)","kaido","kaido(1)"]
输出：["kaido","kaido(1)","kaido(2)","kaido(1)(1)"]
解释：最后一个 "kaido(1)" 撞名，它的基名是完整的 "kaido(1)"，
      而不是 "kaido"，所以得到 "kaido(1)(1)"。
```

## 3. 解题思路

### 3.1 暴力思路

用一个集合 `used` 记录已分配的全部文件名，逐个处理：

```text
若 name ∉ used：落名 name
否则：k = 1；while name(k) ∈ used: k += 1；落名 name(k)
```

这个写法**结果是对的**，但复杂度在最坏情况下是 $O(n^2)$：如果 $n$ 个名字全都叫 `"wano"`，第 $i$ 次分配要连续试探 $i-1$ 个后缀，总试探次数

$$\sum_{i=1}^{n} (i-1) = \frac{n(n-1)}{2}$$

在 $n = 5 \times 10^4$ 时约 $1.25 \times 10^9$ 次「拼字符串 + 哈希查表」，远超 1 秒能接受的范围。

慢的根源很清楚：**第 $i$ 轮把前面已经确认「被占用」的那些后缀，又从 $k = 1$ 起逐个重验了一遍**。这些信息完全可以留下来复用。

### 3.2 核心观察：占用只增不减 ⇒ 每个基名只需要一个「单调指针」

![每个基名一个单调指针](images/wc194_q2_rename_model.svg)

**第一步：想清楚「占用」这个状态的方向性。** 题目只创建文件、从不删除，所以

$$\text{某个名字被占用} \;\Longrightarrow\; \text{它在之后任何时刻都被占用}$$

对固定基名 $b$，候选名字是 $b(1), b(2), b(3), \dots$，它们的可用性只会从「空闲」变成「占用」，绝不会反过来。因此一旦我们确认 $b(k)$ 已被占用，这个格子就**永远不必再看第二眼**。

**第二步：把「验过哪一格」记下来。** 为每个基名 $b$ 维护一个指针 $nxt[b]$，含义是：

$$nxt[b] = \text{下一个值得尝试的最小 } k,\qquad \text{即 } b(1), \dots, b(nxt[b]-1) \text{ 全部已被占用}$$

于是撞名时不必从 $k = 1$ 起步，而是从 $nxt[b]$ 起步继续向右探测；探测成功后把指针写成 $k+1$。指针**只增不减**，总移动量被「产生过的名字总数」$n$ 卡住，全局摊还 $O(n)$。

**第三步（也是最容易错的）：基名不解析。** `"kaido(1)"` 的基名就是 `"kaido(1)"`，它的候选是 `"kaido(1)(1)"`、`"kaido(1)(2)"`…… 如果为了「复用计数器」而把名字拆成「前缀 + 后缀数字」，示例 3 就会答成 `"kaido(3)"`，直接 WA。指针要按**完整输入串**建索引。

> 💡 一句话：**用一个 `used` 集合保证唯一，用一个「基名 → 下一个待试 k」的哈希表保证不重复劳动。**

### 3.3 算法流程

![算法流程图](images/wc194_q2_scan_flow.svg)

1. 初始化 `used ← ∅`（已分配名字），`nxt ← ∅`（基名到下一个待试 $k$），`ans ← []`。
2. 依次取 $name = names[i]$：
   - 若 $name \notin used$：说明它本来就空闲，落名 $name$，`used.add(name)`，进入下一轮。
   - 否则撞名：取 $k = nxt.get(name, 1)$（没有记录时从 1 开始，1 永远是一个安全下界）。
3. 循环生成候选 `cand`（`name` 后接 `(`、$k$ 的十进制表示、`)`）：只要 $cand \in used$，就 $k \leftarrow k+1$ 并重新生成，直到命中第一个空闲候选。
4. 落名 $cand$，把 $cand$ 加入 `used`，并写回指针 $nxt[name] \leftarrow k+1$。
5. 遍历结束返回 `ans`。

第 2、4 步的两次写入缺一不可：**只更新指针不加 `used`** 会分配出重名；**只加 `used` 不更新指针** 则退化成暴力，$5 \times 10^4$ 个同名数据必然超时。

### 3.4 示例演算

![示例演算走查](images/wc194_q2_walkthrough.svg)

以 $names = [\texttt{kaido}, \texttt{kaido(1)}, \texttt{kaido}, \texttt{kaido(1)}]$ 为例：

| $i$ | $name$ | 撞名？ | 探测过程 | 落名 | 指针更新 |
|-----|--------|--------|----------|------|----------|
| 0 | `kaido` | 否 | 不加后缀 | `kaido` | 无 |
| 1 | `kaido(1)` | 否 | 不加后缀 | `kaido(1)` | 无 |
| 2 | `kaido` | 是 | 无记录 → $k$ 从 1 试起；`kaido(1)` 被占 → $k=2$ 空闲 | `kaido(2)` | $nxt[\text{kaido}]=3$ |
| 3 | `kaido(1)` | 是 | $nxt$ 缺省 1；`kaido(1)(1)` 空闲 | `kaido(1)(1)` | $nxt[\text{kaido(1)}]=2$ |

再看示例 1 中第三个名字：$name = \texttt{gta}$，而 `gta(1)` 早在前一轮就以「原始名字」的身份进入 `used`，此时 $nxt[\texttt{gta}]$ 还没有记录（默认 1），$k=1$ 探测即命中「已占用」，于是 $k$ 前进到 2。这说明**默认下界 1 只是安全，不是有效**，循环里的探测一次都不能省。

## 4. 算法细节

1. **数据结构选择**：`used` 用 `unordered_set<string>` / `set`，`nxt` 用 `unordered_map<string,int>` / `dict`。两者都按「完整字符串」做键，不做任何分词。
2. **指针语义**：$nxt[b] = k$ 表示 $b(1) \dots b(k-1)$ 全部已被占用，因此 $k$ 及其之后才可能是答案；键不存在等价于 $k = 1$（$1 \le k$ 恒成立，是安全下界）。
3. **只写回基名自己的指针**：落名 `kaido(2)` 时只更新 $nxt[\texttt{kaido}]$，**不要**顺手给 `kaido(2)` 建指针——它作为基名时默认从 1 起步即可，多写反而浪费空间。
4. **指针单调**：写回值是 $k+1$ 而不是 $1$、也不是 $k$，否则同一格会被反复试探，摊还失效。
5. **候选名字的生成**：C++ 用 `name + "(" + to_string(k) + ")"`，Python 用 `f"{name}({k})"`。$k \le 5\times10^4$，后缀最多 7 个字符，整串长度上界约 $20 + 7 = 27$。
6. **C++ 记得 `reserve`**：`used.reserve(2 * n)`、`nxt.reserve(2 * n)`，避免 $5\times10^4$ 次插入触发多次 rehash。
7. **不要在多处维护状态**：有人会额外维护「每个前缀的最大后缀」，那需要解析字符串，正是 3.2 第三步否认的路线；本解法只有 `used` 与 `nxt` 两个结构。
8. **`k` 从 1 开始**：题目要求正整数，`(0)` 不是合法后缀；`nxt` 的缺省值必须写 1 而不是 0。

## 5. 正确性证明

**引理 1（未撞名时直接使用是唯一正解）**：若处理 $names[i] = b$ 时 $b \notin used$，则系统分配的就是 $b$ 本身。

**证明**：题面规定只有当文件名已被占用时才添加后缀。$b$ 空闲，因此不触发任何改名，分配 $b$；这也是唯一不产生新占用冲突的选择。∎

**引理 2（指针下界不变量）**：在算法的任意时刻，对任意基名 $b$，若 $nxt[b]$ 有定义且等于 $p$，则 $b(1), b(2), \dots, b(p-1)$ 都已被占用。

**证明**：对「写 `nxt` 的次数」归纳。初始时 `nxt` 为空，命题真空成立。设某一步写入 $nxt[b] = k+1$：由第 3 步的循环，$b(nxt_{old}), \dots, b(k-1)$ 都在循环中被判为已占用（否则循环不会前进），且 $b(k)$ 刚被加入 `used`；再由归纳假设 $b(1) \dots b(nxt_{old}-1)$ 已占用，合起来 $b(1) \dots b(k)$ 全部被占用。$used$ 从不删除元素，故这些占用状态此后一直保持，命题对 $p = k+1$ 成立。∎

**引理 3（首次命中即最小 $k$）**：设第 $i$ 步撞名、基名为 $b$，令 $k^{*}$ 为使 $b(k)$ 空闲的最小正整数，则第 3 步的循环恰好在 $k = k^{*}$ 处停下。

**证明**：记循环起点 $p = nxt[b]$（无记录时 $p = 1$）。一方面 $k^{*} \ge p$：若 $nxt[b]$ 有定义，由引理 2 可知 $b(1) \dots b(p-1)$ 全被占用，这些 $k$ 都不可能是答案；若无记录则 $p = 1 \le k^{*}$ 显然。另一方面循环从 $p$ 开始逐个 $k$ 递增、每次只跳过「已占用」的候选，因此它检查的正是 $p, p+1, \dots$，第一个空闲的就是 $k^{*}$（存在性：除本轮外最多还有 $n-1$ 个名字被占用，而候选 $k = 1 \dots n$ 有 $n$ 个，故至少有一个空闲）。∎

**引理 4（摊还 $O(n)$）**：整个算法中，第 3 步循环里「候选被占用、$k$ 自增」的次数总和不超过 $n$。

**证明**：对每个基名 $b$，指针 $nxt[b]$ 单调不减，而被判占用并自增的那些 $k$ 恰好是区间 $[nxt_{old}[b], k-1]$ 上的整数，因此同一对 $(b, k)$ 在整个过程中最多被判定为「占用」一次。又因为候选串的形态固定：末尾的 `)` 之前是一段无前导零的十进制数字，它就是 $k$，剩下的前缀就是 $b$，故由字符串可唯一反解出 $(b,k)$，不同的 $(b,k)$ 对应 `used` 中不同的名字。而 `used` 的大小始终不超过 $n$，所以这类失败判定的总数不超过 $n$。∎

**定理**：算法输出的 `ans` 与题面规则逐项一致，且时间复杂度为期望 $O(n \cdot L)$（$L \le 27$）。

**证明**：对 $i$ 归纳。$i$ 步之前假设 `ans[0..i-1]` 与题意一致，从而 `used` 恰为题目此时已占用的名字集合。若 $names[i]$ 空闲，由引理 1 输出正确；否则由引理 3，算法产生的 $k$ 正是最小可用正整数，输出 $names[i](k)$，与题意一致。每步结束后 `used` 都精确加入了刚落名的名字、$nxt$ 满足引理 2，故归纳可以继续。复杂度由引理 4，循环内失败判定总计 $O(n)$ 次，每次哈希操作与字符串拼接代价 $O(L)$，加上每个名字一次直接查询，总时间期望 $O(n \cdot L)$。∎

## 6. 复杂度分析

- **时间**：期望 $O(n \cdot L)$，$L \le 27$ 为单次字符串拼接加哈希的长度上界。其中每个名字至多一次「是否在 `used` 中」的查询（$O(1)$ 期望）；第 3 步循环的失败判定由引理 4 摊还为 $O(n)$ 次；每次失败判定要构造一个新候选串并查表，代价 $O(L)$。故总计 $O(n \cdot L)$，$n = 5\times10^4$ 时约 $1.4\times10^6$ 量级的字符操作。
- **空间**：$O(n \cdot L)$。`used` 中最多存 $n$ 个名字，每个长度 $O(L)$；`nxt` 最多存 $O(n)$ 个键，键是 `names` 中已有字符串（C++ 中为拷贝，量级同上）。
- **对比**：暴力为 $O(n^2 L)$ 且带一个很大的常数（同名数据下 $1.25\times10^9$ 次探测）；本解法把它降到线性，只多用一张 $O(n)$ 的哈希表。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
#include <unordered_set>
using namespace std;

class Solution {
public:
    vector<string> getFolderNames(vector<string>& names) {
        unordered_set<string> used;            // 已分配的真实文件名
        unordered_map<string, int> nxt;        // 基名 -> 下一个值得尝试的 k
        used.reserve(names.size() * 2);
        nxt.reserve(names.size() * 2);

        vector<string> ans;
        ans.reserve(names.size());
        for (const string& name : names) {
            if (used.find(name) == used.end()) {
                used.insert(name);             // 本来就是空闲的，原样使用
                ans.push_back(name);
                continue;
            }
            int k = 1;                         // 缺省下界
            auto it = nxt.find(name);
            if (it != nxt.end()) k = it->second;

            string cand;
            while (true) {                     // 从小到大找第一个空闲的 k
                cand = name + "(" + to_string(k) + ")";
                if (used.find(cand) == used.end()) break;
                ++k;
            }
            used.insert(cand);
            nxt[name] = k + 1;                 // 指针只前进，永不回退
            ans.push_back(cand);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getFolderNames(self, names: list[str]) -> list[str]:
        used = set()          # 已分配的真实文件名
        nxt = {}              # 基名 -> 下一个值得尝试的 k
        ans = []
        for name in names:
            if name not in used:
                used.add(name)             # 本来就空闲，原样使用
                ans.append(name)
                continue

            k = nxt.get(name, 1)           # 缺省下界是 1
            while f"{name}({k})" in used:  # 从小到大找第一个空闲的 k
                k += 1
            cand = f"{name}({k})"
            used.add(cand)
            nxt[name] = k + 1              # 指针只前进，永不回退
            ans.append(cand)
        return ans
```

## 8. 边界情况与易错点

1. **名字全都不同**：如 `["pes","fifa","gta"]`，一个后缀都不该加，`nxt` 全程不写。别写成「先加 `(0)` 再判断」。
2. **已有后缀的名字再撞名**：`["kaido(1)","kaido(1)"]` 的答案是 `["kaido(1)","kaido(1)(1)"]`。若把基名解析成 `kaido` + 1，就会错答 `kaido(2)`——这是本题第一大坑。
3. **后缀被「提前占位」**：`["gta","gta(1)","gta"]` 中 `gta(1)` 先以原始名字身份进入 `used`，所以第三个必须探测到 $k=2$。别假设 $nxt$ 缺省值 1 一定可用。
4. **极端同名**：$5\times10^4$ 个 `"wano"` 时 $k$ 一路涨到 $49999$，后缀是 5 位数字。拼接必须走 `to_string` / f-string，不能假设后缀只有一位。
5. **指针忘记写回**：写成 `nxt[name] = 0` 或干脆不写，会让每轮都从 $k = 1$ 重扫，退化成 $O(n^2)$，在极端同名数据上 TLE（而示例只有 4~5 个元素，完全测不出来）。
6. **落名后忘记加入 `used`**：`["a","a","a"]` 会输出 `["a","a(1)","a(1)"]`，出现重名。`used.add(cand)` 与 `nxt[name] = k + 1` 必须成对出现。
7. **`k` 从 0 开始**：会产生 `"a(0)"` 这种非法后缀；题目要求最小**正整数**。
8. **不要打乱输出顺序**：`ans` 必须与 `names` 逐位对应——同一个名字可能在多处出现、各处的分配结果还不同，所以既不能排序也不能去重后再输出。
