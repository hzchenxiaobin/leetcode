# LeetCode 找到最小生成树里的关键边和伪关键边 题解

## 1. 题目概述

- **标题 / 题号**：找到最小生成树里的关键边和伪关键边（#1489，hard）
- **链接**：https://leetcode.cn/problems/find-critical-and-pseudo-critical-edges-in-minimum-spanning-tree/
- **来源**：LeetCode 第 194 场周赛 Q4
- **难度**：困难
- **标签**：并查集、图、Kruskal 算法、最小生成树、排序

**题意**：给定一张 $n$ 个点的带权无向连通图，边用 `edges[i] = [u, v, w]` 给出，边用**下标**标识。要求把边分成三类并返回其中两类的下标：

- **关键边**：从图中删去它，最小生成树（MST）的权值和会变大（或图不再连通）；
- **伪关键边**：它出现在**某棵** MST 里，但不出现在**所有** MST 里；
- 剩下的边：不出现在任何 MST 里，直接丢弃。

两个下标列表的顺序任意，但每类内部的下标必须是原 `edges` 的下标，不是排序后的位置。

**约束**：

- $2 \le n \le 100$
- $1 \le \lvert edges \rvert \le \min(200, n(n-1)/2)$
- $edges[i] = [a_i, b_i, w_i]$，$0 \le a_i < b_i < n$，$1 \le w_i \le 1000$
- 所有 $(a_i, b_i)$ 数对互不相同；保证图连通

> 💡 $m \le 200$ 是关键信息：它允许对每条边各跑一次 $O(m \alpha(n))$ 的 Kruskal，总开销只有 $4 \times 10^4$ 量级。

## 2. 示例

**示例 1**

```text
输入：n = 5, edges = [[0,1,1],[1,2,1],[2,3,2],[0,3,2],[0,4,3],[3,4,3],[1,4,6]]
输出：[[0,1],[2,3,4,5]]
解释：边 0、1 出现在全部 MST 中 → 关键边；
      边 2、3、4、5 只出现在部分 MST 中 → 伪关键边；
      边 6 不出现在任何 MST 中，被丢弃。
```

**示例 2**

```text
输入：n = 4, edges = [[0,1,1],[1,2,1],[2,3,1],[0,3,1]]
输出：[[],[0,1,2,3]]
解释：4 条边权值全为 1，任取 3 条都能连成树，所以每条边都只出现在部分 MST 里，
      关键边列表为空，4 条边全是伪关键边。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的办法是**枚举所有生成树**：从 $m$ 条边里选 $n-1$ 条，判断是否连通无环，统计每棵树的总权值，取到最小值的那些树，再看每条边在其中出现了几次。组合数是 $C_{200}^{99}$ 量级，完全不可行。

稍好一点的是只判关键边：对每条边删掉后重跑 Kruskal，看权值和是否变大——这一步本身没错，$O(m^2 \alpha(n))$ 也能过。**问题在于伪关键边没有判据**：「删掉后权值和不变」只说明存在**不含**它的 MST，并不能说明存在**含**它的 MST。所以单靠删边测试，只能把边分成「关键」和「非关键」两类，无法继续细分。真正需要的是两个方向各查一次：**「存在不含 $e$ 的 MST 吗？」** 与 **「存在含 $e$ 的 MST 吗？」**。

### 3.2 核心观察：两类边 = 两个最小权值和查询

![三类边的判定：关键、伪关键、无关](images/wc194_q4_edge_classes.svg)

设全图 MST 的权值和为 $W$。

- **关键边**：题面给的定义就是「删掉后 MST 权值和变大」。删掉 $e$ 之后所有可行解都变成不含 $e$ 的生成树，所以 $G-e$ 的最小权值和满足

$$\text{e 关键} \iff \mathrm{W}' > W \ \text{或}\ G-e \text{ 不连通}$$

- **伪关键边**：存在含 $e$ 的 MST，即「钦定 $e$ 必须入选」的约束优化取到 $W$：

$$\text{存在含 } e \text{ 的 MST} \iff \mathrm{W}'' = W,\quad \mathrm{W}'' = \min\{\, w(T) : T \text{ 是生成树且 } e \in T \,\}$$

这两个量都能**用同一个 Kruskal 框架算出来**：跳过 $e$ 就是 $G-e$ 的 MST；把 $e$ 的两端事先并进同一集合、权值先计入 $w(e)$，就是「含 $e$ 的最小生成树」。后者等价于在**收缩边** $e$ 后的图 $G/e$ 上跑 Kruskal，正确性由贪心选择性质保证（生成树的集合构成拟阵，加约束后贪心仍给出最优基）。

> 💡 一句话记忆：**删边测试判「是不是所有树都要它」，强制测试判「是不是某棵树要它」。** 两者都失败 → 没有任何 MST 要它。

### 3.3 算法流程

![对每条边做两次假设检验的流程](images/wc194_q4_two_tests_flow.svg)

1. 把边下标按 `weight` 升序排序，得到 `order`（只排一次，后面所有 Kruskal 复用）。
2. 在 `order` 上跑一次 Kruskal，得到基准权值和 $W$。
3. 对每条边 $i$ 从 $0$ 到 $m-1$：
   - **删边测试**：在 `order` 上跑 Kruskal，遇到 $i$ 就跳过，得到 $(\mathrm{W}', \text{used})$。若 $\text{used} < n-1$（不连通）或 $\mathrm{W}' > W$ → $i$ 是关键边，结束本条边。
   - **强制测试**：新建并查集，先 `union(u_i, v_i)` 并把 $w_i$ 计入（`used = 1`），再扫描 `order`（遇到 $i$ 跳过），得到 $(\mathrm{W}'', \text{used})$。若 $\mathrm{W}'' = W$ → $i$ 是伪关键边。
   - 两条都失败 → 丢弃。
4. 分别返回 `critical` 与 `pseudo`。

注意**顺序不能反**：关键边也能通过强制测试（它本来就在所有 MST 里），所以必须先判关键、再判伪关键。

### 3.4 示例演算

![示例 1 的逐边走查表](images/wc194_q4_example_walkthrough.svg)

**基准**：按权值排序后依次是 $e_0(1),\ e_1(1),\ e_2(2),\ e_3(2),\ e_4(3),\ e_5(3),\ e_6(6)$。Kruskal 选 $e_0$、$e_1$、$e_2$，$e_3$ 因 $0$ 与 $3$ 已连通被跳过，再选 $e_4$，得到 $n-1=4$ 条边，$W = 1+1+2+3 = 7$。

逐边结果见上图（$\mathrm{W}'$ 为删边后权值和，$\mathrm{W}''$ 为强制后权值和）。两个值得注意的点：

- **$e_3$ 在基准 MST 里没被选中，却是伪关键边**：它与 $e_2$ 权值相同，都能连接 $\{0,1,2\}$ 与 $\{3\}$ 两块，本质是「同权重的可替换边」——所以不能拿「是否出现在某一次 Kruskal 结果里」当判据。
- **$e_6$ 的删边测试通过（$\mathrm{W}' = 7$）、强制测试失败（$\mathrm{W}'' = 10 > 7$）**，正是「不在任何 MST 中」的典型形态；若只看删边测试，它会被误判成伪关键边。

## 4. 算法细节

1. **排序一次、复用多次**：对下标 `order` 排序，而不是复制边数组；每次 Kruskal 只按 `order` 扫描，遇到 `ban` / `force` 下标就跳过，避免反复排序与拷贝。
2. **删除测试必须同时检查连通性**：删边后若只剩森林，$\mathrm{W}'$ 是各连通块 MST 权值之和，**完全可能小于 $W$**（例如 $n=4$、边集 `[[0,1,1],[1,2,1],[0,2,1],[2,3,5]]` 删掉最后一条边后森林权值只有 2）。所以判断条件是「`used < n-1` **或** $\mathrm{W}' > W$」，绝不能只比权值。
3. **强制测试的写法**：初始化并查集后先 `union(u,v)` 并令 `total = w`、`used = 1`，随后扫描时把 `force` 这条边也跳过（它已经被计入），否则会重复计入权值并把 `used` 多加 1。
4. **只判两个量就够**：不必真的维护 MST 的边集，也不必记录「某条边是否被选中」；判据只有权值和与边数，代码短且不易错。
5. **并查集实现**：路径压缩 + 按大小合并，`find` 写成迭代版，避免 $n=100$ 时的递归开销与潜在爆栈；`m` 很小，用 `vector<int> parent(n)` 每次重建即可，无需回滚。
6. **权值上界**：一棵生成树的权值和不超过 $(n-1) \times 1000 = 99000$，`int` 足够；不必用 `long long`，但用了也无害。
7. **下标不要丢失**：排序后要用原下标输出，`order` 里存的就是原下标，结果列表按 $i$ 递增生成，天然有序，不需要额外排序。
8. **空列表要返回**：示例 2 的关键边列表是空列表，Python 返回 `[]`、C++ 返回空 `vector`，不要写成 `null`。

## 5. 正确性证明

**引理 1（删边判据）**：$e$ 是关键边 $\iff$ $G-e$ 不连通，或 $G-e$ 的 MST 权值和 $\mathrm{W}' > W$。

**证明**：$G-e$ 的任一生成树都是 $G$ 中不含 $e$ 的生成树，反之亦然，故「$G$ 中存在不含 $e$ 且权值和为 $W$ 的生成树」$\iff$「$G-e$ 存在权值和为 $W$ 的生成树」$\iff \mathrm{W}' = W$。于是 $\mathrm{W}' > W$（不连通时视为 $+\infty$）$\iff$ 不存在不含 $e$ 的 MST $\iff$ 所有 MST 都含 $e$ $\iff$ $e$ 关键。∎

**引理 2（强制判据）**：存在含 $e$ 的 MST $\iff$ 强制选中 $e$ 后 Kruskal 得到的 $\mathrm{W}'' = W$。

**证明**：设 $e=(u,v)$，把 $u,v$ 收缩成一点得到 $G/e$。映射 $T \mapsto T - \{e\}$ 是「$G$ 中含 $e$ 的生成树」与「$G/e$ 的生成树」之间的双射，且 $w(T) = w(e) + w(T - \{e\})$，因此 $\min_{T \ni e} w(T) = w(e) + \mathrm{MST}(G/e)$。而「先把 $u,v$ 并入同一集合、权值计 $w(e)$，再按权值升序扫描其余边」正是对 $G/e$ 执行 Kruskal（$G/e$ 中 $u,v$ 已合并，其余边相对顺序不变），由 Kruskal 的正确性得 $\mathrm{W}'' = w(e) + \mathrm{MST}(G/e)$。该值不小于 $W$，故 $\mathrm{W}'' = W$ $\iff$ 存在含 $e$ 的 MST。∎

**引理 3（伪关键判据）**：$e$ 是伪关键边 $\iff$ $e$ 不是关键边，且 $\mathrm{W}'' = W$。

**证明**：由引理 1，$e$ 非关键 $\iff$ 存在不含 $e$ 的 MST；由引理 2，$\mathrm{W}'' = W$ $\iff$ 存在含 $e$ 的 MST。两者同时成立即「$e$ 出现在某些 MST 中但不出现在所有 MST 中」，正是伪关键边的定义。∎

**定理**：算法输出的两个列表恰为全部关键边与全部伪关键边的下标。

**证明**：对每条边 $i$，若删边测试失败，由引理 1 知 $i$ 关键，算法将其归入 `critical` 且不再做强制测试——这不影响结果，因为关键边不属于伪关键边（引理 3 要求非关键）。若删边测试通过，则 $i$ 非关键，算法再用强制测试按引理 2 判定其是否出现在某棵 MST 中，由引理 3 决定是否归入 `pseudo`；两次测试都失败时，由引理 1、2 的逆否命题，既不「存在不含 $i$ 的 MST」也不「存在含 $i$ 的 MST」，即 $i$ 不在任何 MST 中，丢弃正确。三类互斥且穷尽所有边，故输出完整且无冗余。∎

## 6. 复杂度分析

- **时间**：排序 $O(m \log m)$；每次 Kruskal 扫描 $m$ 条边，并查集操作近似 $O(\alpha(n))$，单次 $O(m \alpha(n))$；对 $m$ 条边各做至多 2 次，得 $O(m^2 \alpha(n) + m \log m)$。$m \le 200$ 时约 $8 \times 10^4$ 次并查集操作，远低于限制。
- **空间**：并查集 $O(n)$，排序下标 $O(m)$，结果列表 $O(m)$；每次 Kruskal 重建并查集，总计 $O(n + m)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <numeric>
#include <algorithm>
using namespace std;

class Solution {
    struct DSU {
        vector<int> p;
        explicit DSU(int n) : p(n) { iota(p.begin(), p.end(), 0); }
        int find(int x) { while (p[x] != x) { p[x] = p[p[x]]; x = p[x]; } return x; }
        bool unite(int a, int b) {
            a = find(a); b = find(b);
            if (a == b) return false;
            p[a] = b;                       // 规模小，不做按秩合并也足够
            return true;
        }
    };
    // 返回 {权值和, 选中的边数}; ban = force = -1 表示不启用
    pair<int, int> kruskal(int n, const vector<vector<int>>& edges,
                           const vector<int>& order, int ban, int force) {
        DSU dsu(n);
        int total = 0, used = 0;
        if (force >= 0) {                   // 强制选中：先把两端合并，权值先计入
            const auto& e = edges[force];
            dsu.unite(e[0], e[1]); total += e[2]; ++used;
        }
        for (int i : order) {
            if (i == ban || i == force) continue;
            const auto& e = edges[i];
            if (dsu.unite(e[0], e[1])) {
                total += e[2];
                if (++used == n - 1) break; // 已连接全部点
            }
        }
        return {total, used};
    }

public:
    vector<vector<int>> findCriticalAndPseudoCriticalEdges(int n, vector<vector<int>>& edges) {
        int m = (int)edges.size();
        vector<int> order(m);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) { return edges[a][2] < edges[b][2]; });
        int base = kruskal(n, edges, order, -1, -1).first;

        vector<int> critical, pseudo;
        for (int i = 0; i < m; ++i) {
            auto [wWithout, cntWithout] = kruskal(n, edges, order, i, -1);
            if (cntWithout < n - 1 || wWithout > base) {   // 不连通或权值变大
                critical.push_back(i); continue;
            }
            auto [wWith, cntWith] = kruskal(n, edges, order, -1, i);
            if (cntWith == n - 1 && wWith == base) pseudo.push_back(i);
        }
        return {critical, pseudo};
    }
};
```

### Python

```python
from typing import List


class Solution:
    def findCriticalAndPseudoCriticalEdges(self, n: int, edges: List[List[int]]) -> List[List[int]]:
        m = len(edges)
        order = sorted(range(m), key=lambda i: edges[i][2])

        def kruskal(ban: int = -1, force: int = -1):
            parent = list(range(n))

            def find(x: int) -> int:
                while parent[x] != x: parent[x] = parent[parent[x]]; x = parent[x]
                return x

            total = used = 0
            if force >= 0:                 # 强制选中：先合并两端，权值先计入
                u, v, w = edges[force]; parent[find(u)] = find(v)
                total, used = w, 1
            for i in order:
                if i == ban or i == force: continue
                u, v, w = edges[i]
                ru, rv = find(u), find(v)
                if ru != rv:
                    parent[ru] = rv; total += w; used += 1
                    if used == n - 1: break
            return total, used

        base, _ = kruskal()
        critical, pseudo = [], []
        for i in range(m):
            w_without, cnt_without = kruskal(ban=i)
            if cnt_without < n - 1 or w_without > base:   # 不连通或权值变大
                critical.append(i); continue
            w_with, cnt_with = kruskal(force=i)
            if cnt_with == n - 1 and w_with == base: pseudo.append(i)
        return [critical, pseudo]
```

## 8. 边界情况与易错点

1. **删边后不连通时不能只看权值和**：森林的权值和可能比 $W$ 更小，必须先判 `used < n-1`。这是本题第一大坑，写反了会在「图本身是树」或「桥边」的数据上出错。
2. **图本身是一棵树**（$m = n-1$）：每条边删掉都会不连通，因此**所有边都是关键边**，伪关键列表为空。
3. **$n = 2$**：只有一条边，删掉后剩 0 条边、`used = 0 < 1`，该边是关键边，返回 `[[0], []]`。
4. **大量等权边**（如示例 2 的四条权值 1）：每一条删掉或强制都能得到 $W$，于是全部是伪关键边，关键边列表为空；不要因为「Kruskal 选了某几条」就认为其余的不是伪关键边（示例 1 的 $e_3$ 就是反例）。
5. **先判关键、再判伪关键**：关键边也能通过强制测试，若先做强制测试并归入伪关键，就把关键边误分类了。
6. **强制测试里的 `used` 初值是 1**：忘了加 1 会让 `cnt == n-1` 的判定永远差一，导致伪关键边全部漏报。
7. **不要重复计入强制边**：先 `union` 之后仍要在扫描时跳过该下标，否则权值多加一次 $w(e)$。
8. **输出的是原下标**：排序只用于扫描顺序，结果必须用 `order` 中的原下标，不能用排序后的位置；题目保证 $(a,b)$ 互不相同，因此不存在平行边的歧义。
