# LeetCode 数组异或操作 题解

## 1. 题目概述

- **标题 / 题号**：数组异或操作（#1486，easy）
- **链接**：https://leetcode.cn/problems/xor-operation-in-an-array/
- **来源**：LeetCode 第 194 场周赛 Q1
- **难度**：简单
- **标签**：位运算、数组、模拟、数学

**题意**：给定整数 $n$ 与 $start$，按 $nums[i] = start + 2i$（$0 \le i < n$）生成数组，返回全部元素的按位异或值：

$$\bigoplus_{i=0}^{n-1} (start + 2i) = start \oplus (start + 2) \oplus \cdots \oplus (start + 2(n-1))$$

其中 $\oplus$ 表示按位异或。

**约束**：

- $1 \le n \le 1000$
- $0 \le start \le 1000$
- 数组下标从 $0$ 开始，元素为等差数列，公差恒为 $2$
- 元素最大值 $start + 2(n-1) \le 1000 + 1998 = 2998 < 2^{12}$，故答案也不超过 12 个二进制位

## 2. 示例

**示例 1**

```text
输入：n = 5, start = 0
输出：8

解释：nums = [0, 2, 4, 6, 8]，而 (0 ^ 2 ^ 4 ^ 6 ^ 8) = 8。
```

**示例 2**

```text
输入：n = 4, start = 3
输出：8

解释：nums = [3, 5, 7, 9]，而 (3 ^ 5 ^ 7 ^ 9) = 8。
```

**示例 3**

```text
输入：n = 1, start = 7
输出：7

解释：nums = [7]，只有一项，异或结果就是 7 本身。
```

## 3. 解题思路

### 3.1 暴力思路：先把数组造出来，再合并

最直白的写法分两步：先按定义生成 $nums$，再从头到尾做异或折叠。

- **时间** $O(n)$：一次生成 + 一次归约，各 $n$ 步；
- **空间** $O(n)$：额外存了一个长度为 $n$ 的数组。

在本题 $n \le 1000$ 的数据范围内，这个做法**完全可以 AC**，不需要任何优化。所以 Q1 真正的得分点不在「算出答案」，而在于**别把签到题写成体力活**：显式数组是纯粹的中间产物，一旦 $n$ 涨到 $10^7$，光这份数组就会 MLE。下面把空间压到 $O(1)$，顺手把结构看穿。

### 3.2 核心观察：异或是带单位元的可结合折叠

按位异或满足四条性质（对任意非负整数 $a, b, c$）：

1. **交换律**：$a \oplus b = b \oplus a$；
2. **结合律**：$(a \oplus b) \oplus c = a \oplus (b \oplus c)$；
3. **单位元**：$0 \oplus a = a$，所以累加器初值取 $0$ 天然正确；
4. **自逆**：$a \oplus a = 0$，相同的数成对出现会互相抵消。

前三条件说明：$n$ 个数的异或是一个**与顺序无关的折叠**，且不需要保存中间结果——每生成一项就当场并进 `ans`，数组可以立刻扔掉。第 4 条则解释了示例 1 里前缀异或为什么会「回落」到 $0$。

再补一个只依赖「公差为 2」的**低位不变式**：

- 公差是偶数，所以 $nums[i]$ 与 $start$ **同奇偶**，所有元素的最低位都等于 $start$ 的最低位；
- 异或的第 0 位是 $n$ 个相同比特的奇偶校验，故答案第 0 位 $= (start \bmod 2) \land (n \bmod 2)$；
- 推论：**$n$ 为偶数时答案必为偶数**。示例 1、示例 2 的答案都是 $8$，与这条自检一致。

![核心观察：流式折叠与低位不变式](images/wc194_q1_streaming_fold.svg)

> 💡 一句话：`ans = 0` 起手，第 $i$ 项现算现异或，$O(1)$ 空间一趟搞定。

### 3.3 算法流程

![算法流程：一次循环完成生成与归约](images/wc194_q1_algorithm_flow.svg)

```text
ans ← 0
for i = 0, 1, …, n-1:
    ans ← ans ⊕ (start + 2 * i)
return ans
```

循环不变量（见 §5 引理 2）：**第 $k$ 轮开始时，`ans` 恰为前 $k$ 项 $nums[0..k-1]$ 的异或**。循环结束时 $k = n$，`ans` 就是全数组的异或，直接返回即可——不需要任何额外判断。

### 3.4 示例演算

**示例 1**（$n = 5$，$start = 0$）：

| $i$ | $nums[i]$ | 二进制 | 异或后 `ans` |
|-----|-----------|--------|--------------|
| 0 | 0 | 0000 | 0 |
| 1 | 2 | 0010 | 2 |
| 2 | 4 | 0100 | 6 |
| 3 | 6 | 0110 | 0 |
| 4 | 8 | 1000 | 8 |

第 3 步的 $6 \oplus 6 = 0$ 就是「自逆」在起作用：两个相同的数抵消，随后 $0 \oplus 8 = 8$。这也说明前缀异或**没有单调性**，不能拿它做二分或双指针。

**示例 2**（$n = 4$，$start = 3$）：

| $i$ | $nums[i]$ | 二进制 | 异或后 `ans` |
|-----|-----------|--------|--------------|
| 0 | 3 | 0011 | 3 |
| 1 | 5 | 0101 | 6 |
| 2 | 7 | 0111 | 1 |
| 3 | 9 | 1001 | 8 |

![示例演算：两组官方示例的逐项折叠](images/wc194_q1_walkthrough.svg)

两组答案同为 $8$ 纯属巧合，不是规律；但两组都满足「$n$ 与 $start$ 至少有一个是偶数 ⇒ 答案末位为 0」的低位自检——真正做题时可以用它快速排除抄错样例的低级错误。

## 4. 算法细节

1. **接口签名**：按 `metaData`，函数名为 `xorOperation`，参数顺序为 `(n, start)`，返回 `int`。C++ 写成 `int xorOperation(int n, int start)`，Python 写成 `def xorOperation(self, n: int, start: int) -> int`。
2. **初值只能是 0**：`0` 是异或的单位元，唯一一个不改变结果的初值。写成 `1`、`start` 或 `-1` 都会把错误的位永久留在 `ans` 里。
3. **不建数组**：第 $i$ 项直接算 `start + 2 * i`，用完即弃。循环只需下标 `i` 和累加器 `ans`，空间 $O(1)$。
4. **不会溢出**：异或逐位进行、不进位，结果的每一个二进制位都来自某个操作数，所以 `ans` 的位宽不超过参与运算元素的位宽。本题元素 $\le 2998 < 2^{12}$，`int` 绰绰有余；`start + 2 * i` 的最大值也是 $2998$，同样安全。
5. **运算符优先级**：在 C++ 与 Python 中 `+` 的优先级都高于 `^`，所以 `ans ^= start + 2 * i` 与 `ans ^= (start + 2 * i)` 等价；真正的坑是先写 `ans ^ start` 再补 `+ 2 * i`，那会变成 `(ans ^ start) + 2 * i`（异或完再加法），结果彻底不同，建议始终显式加括号。
6. **`^` 不是幂、也不是逻辑或**：本题要的是按位异或。写成 `**`（Python 幂）、`pow`，或 `||`（逻辑或）都会直接 WA；C++ 里 `ans ^ start` 与 `ans || start` 结果完全不同。
7. **Python 的一行写法**：配合 `functools.reduce` 与 `operator.xor`，可写成 `reduce(xor, range(start, start + 2 * n, 2), 0)`——`range` 的步长正好是公差 $2$，恰好产生 $n$ 项，初值 $0$ 是单位元。可读性不如循环，但能验证自己对「等差数列 = 起始 + 步长」的理解。
8. **调试技巧**：先打印 $nums$ 的前几项与 `ans` 的中间值，再用低位不变式核对末位；这样能快速区分「公式写错」与「循环边界写错」。

## 5. 正确性证明

**引理 1（异或的代数性质）**：对任意非负整数 $a, b, c$：$a \oplus b = b \oplus a$，$(a \oplus b) \oplus c = a \oplus (b \oplus c)$，$0 \oplus a = a$，$a \oplus a = 0$。

**证明**：按位异或的第 $j$ 位 $(a \oplus b)_j = a_j \oplus b_j$，其中 $a_j, b_j \in \{0, 1\}$。布尔异或满足交换律与结合律，且 $0 \oplus b_j = b_j$、$b_j \oplus b_j = 0$。逐位成立即整体成立。∎

**引理 2（循环不变式）**：对 $0 \le k \le n$，第 $k$ 轮循环开始时 `ans` $= nums[0] \oplus nums[1] \oplus \cdots \oplus nums[k-1]$（$k = 0$ 时为空异或，规定为单位元 $0$）。

**证明**：对 $k$ 归纳。$k = 0$ 时 `ans` 初始化为 $0$，由空异或约定成立。设第 $k$ 轮开始时命题成立，本轮执行 `ans ← ans ⊕ (start + 2k)`，而 $start + 2k = nums[k]$，于是新值 $= nums[0] \oplus \cdots \oplus nums[k-1] \oplus nums[k]$，命题对 $k+1$ 成立。∎

**引理 3（低位不变式）**：答案的第 $0$ 位等于 $(start \bmod 2) \land (n \bmod 2)$；特别地，$n$ 为偶数时答案必为偶数。

**证明**：公差为 $2$ 是偶数，故 $nums[i] = start + 2i \equiv start \pmod 2$，即所有元素的第 $0$ 位都等于同一个比特 $b = start \bmod 2$。由引理 1，答案第 $0$ 位是这 $n$ 个相同比特的异或；$n$ 个 $b$ 异或，出现奇数次才为 $b$，即结果为 $b \land (n \bmod 2)$。$n$ 为偶数时该式为 $0$，答案为偶数。∎

**定理**：算法返回 $\bigoplus_{i=0}^{n-1} nums[i]$。

**证明**：循环共执行 $n$ 轮，取引理 2 中 $k = n$：循环结束时 `ans` $= nums[0] \oplus \cdots \oplus nums[n-1]$，正是题面要求的全部元素异或，且此时 `i = n` 退出循环，函数直接返回该值。由引理 1 的结合律，逐步折叠与一次性求异或等价，因此结果唯一且与生成顺序一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。循环 $n$ 轮，每轮一次乘法、一次加法、一次异或，都是 $O(1)$ 的字长运算；元素位宽不超过 12 位，可视为常数字长。
- **空间复杂度**：$O(1)$。只维护 `i` 与 `ans` 两个整型变量，不构造数组；相比显式建表的 $O(n)$ 空间，这是本题唯一的实质性优化。
- **下界**：在「只能逐个读取元素」的模型下，$O(n)$ 已是时间下界——每个元素都可能独立翻转答案的某一位。但本题元素由公式给出、并非外部输入，因此可以整体分析结构，用按位计数把时间降到 $O(\log U)$（$U$ 为值域上界，见「延伸思考」）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int xorOperation(int n, int start) {
        int ans = 0;                          // 0 是异或的单位元
        for (int i = 0; i < n; ++i) {
            ans ^= (start + 2 * i);           // 现算第 i 项，不建数组
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def xorOperation(self, n: int, start: int) -> int:
        ans = 0                               # 异或的单位元，无需特判 n 或 start
        for i in range(n):
            ans ^= start + 2 * i              # nums[i] = start + 2i，边算边异或
        return ans
```

## 8. 边界情况与易错点

1. **$n = 1$**：答案是 $start$ 本身（$0 \oplus start = start$）。示例 3 中 $n = 1, start = 7$ 输出 $7$；循环执行一次、`ans` 从 $0$ 变成 $7$，无需特判。
2. **$start = 0$**：数组从 $0$ 开始、全为偶数，答案末位必为 $0$。示例 1 得 $8$；别因为首项是 $0$ 就跳过它——$0$ 参与异或不改变结果，跳过也无害，但统一处理更不容易错。
3. **$n$ 为偶数**：答案必为偶数（引理 3）。若算出奇数，一定是数列项写错或循环多跑/少跑了一轮。
4. **最大规模**：$n = 1000, start = 1000$ 时末项为 $2998$，答案为 $0$（可自行用暴力对拍验证）。别把上界误写成 $start + 2n$，那会多算一项。
5. **`^` 的语义**：C++/Python 的 `^` 都是按位异或，不是幂、不是逻辑或。写成 `start ** 2`、`pow(start, 2)`，或把 `^` 换成 `||`，都会错得很离谱。
6. **初值污染**：`ans` 初始化成 `-1`（补码全 1 位）或 `1` 会让结果永久带着脏位，任何输入都错。
7. **Python 与 C++ 的差异**：Python 整数无溢出，`int` 是任意精度；C++ 用 `int` 时依赖「异或不进位」这一性质才安全，本题值域下 $2998 < 2^{31}$，两者都无需 `long long`。

**延伸思考**：如果 $n$ 变成 $10^{18}$（$start$ 不变），$O(n)$ 模拟就不可行了，但「公差为 2」这个结构仍然可拆。把每一项右移一位：

$$\left\lfloor \frac{start + 2i}{2} \right\rfloor = \left\lfloor \frac{start}{2} \right\rfloor + i = a + i, \qquad a = \left\lfloor \frac{start}{2} \right\rfloor$$

而 $x$ 的第 $k$ 位（$k \ge 1$）恰是 $\lfloor x/2 \rfloor$ 的第 $k-1$ 位。于是「公差 2 的异或」变成「连续整数区间 $[a, a+n)$ 的按位统计」：第 $k$ 位为 $1$ 的个数若为奇数，答案第 $k$ 位就是 $1$。区间上的按位计数有标准的周期公式（周期 $2^{k+1}$，前半段 $0$、后半段 $1$，用前缀差相减），逐位统计共 $O(\log U)$（$U$ 为值域上界），即 $O(1)$ 级别；第 $0$ 位直接用引理 3 的 $(start \bmod 2) \land (n \bmod 2)$ 单算。这条推导把签到题一路延伸到 $n \sim 10^{18}$，也是「异或可以逐位独立处理」这一思想的完整展示。
