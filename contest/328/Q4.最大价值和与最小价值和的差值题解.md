# LeetCode 最大价值和与最小价值和的差值 题解

## 1. 题目概述

- **标题 / 题号**：最大价值和与最小价值和的差值（#2538，hard）
- **链接**：https://leetcode.cn/problems/difference-between-maximum-and-minimum-price-sum/
- **来源**：LeetCode 第 328 场周赛 Q4
- **难度**：困难
- **标签**：树、深度优先搜索、动态规划、树形 DP、换根

**题意**：给定 $n$ 个节点的无向无根树 `edges` 与点权数组 `price`。任选节点 `root` 作为根，定义该选择的**开销**为：以 `root` 为起点的所有路径中，**价值和最大的一条**与**最小的一条**的差值（单节点路径也是合法路径）。返回所有根的选择中**最大**的开销。

**约束**：

- $1 \le n \le 10^5$，`edges` 保证构成一棵树
- $1 \le \text{price}[i] \le 10^5$ —— **点权全为正**

> ⚠️ **规模读法**：$n = 10^5$，对每个根独立 DFS 是 $O(n^2) \approx 10^{10}$，必超时；路径和上界 $10^5 \times 10^5 = 10^{10}$，**超出 32 位整型**，C++ 全程 `long long`。而「点权全为正」是本题最大的突破口——它让最小路径直接白送（§3.2），剩下的问题恰好是经典的换根 DP（§3.3）。

## 2. 示例

**示例 1**

```text
输入：n = 6, edges = [[0,1],[1,2],[1,3],[3,4],[3,5]], price = [9,8,7,6,10,5]
输出：24
解释：以 2 为根：最大路径 [2,1,3,4] 价值和 7+8+6+10 = 31，
      最小路径 [2] 价值 7，开销 31 − 7 = 24，为所有根中最大。
```

**示例 2**

```text
输入：n = 3, edges = [[0,1],[1,2]], price = [1,1,1]
输出：2
解释：以 0 为根：最大路径 [0,1,2] 和为 3，最小路径 [0] 和为 1，开销 2。
```

**补充用例**

```text
输入：n = 1, edges = [], price = [42]
输出：0
解释：唯一的根只有路径 [0]，最大 = 最小 = 42，开销 0。

输入：n = 2, edges = [[0,1]], price = [3,10]
输出：10
解释：以 0 为根：max = 13，min = 3，开销 10；以 1 为根：开销 3。取 10。

输入：n = 4, edges = [[0,1],[0,2],[0,3]], price = [5,1,2,3]（菊花图）
输出：8
解释：以叶子 2 为根：最大路径 [2,0,3] = 10，最小 [2] = 2，开销 8；
      以中心 0 为根只有 [0,x] 型路径，开销 3。叶子端比中心更优。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个根 $r$，从 $r$ 出发 DFS/BFS 一遍，求出以 $r$ 为起点的最大路径和 $\text{best}(r)$，则开销 $=\text{best}(r) - \text{price}[r]$（最小值为什么恰是 $\text{price}[r]$ 见 §3.2）。单次 $O(n)$、总计 $O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次操作，**超时**。

瓶颈在于 $n$ 个根各自独立搜索、大量子树信息被重复计算。**换根 DP** 正是把「每个根的答案」从「重新搜一遍」变成「从父亲的答案 $O(1)$ 修正而来」——这正是本题的考点。

### 3.2 核心观察一：最小路径不用求，白送

![核心观察：点权全为正，最小路径就是根自己](images/wc328_q4_min_path_concept.svg)

**点权全为正 $\Rightarrow$ 任意以 $r$ 为起点的路径，每多走一步都在加正数**。于是：

- 单节点路径 $[r]$ 的价值和恰为 $\text{price}[r]$，它就是最小值；
- 含至少一条边的路径，和 $\ge \text{price}[r] + 1 > \text{price}[r]$，永远争不到最小。

$$\text{cost}(r) = \text{best}(r) - \text{price}[r], \qquad \text{best}(r) = \text{以 } r \text{ 为起点的路径和最大值}$$

> 💡 **等价视角**：$\text{ans} = \max\limits_{\text{路径 } P} \bigl(\text{sum}(P) - \min(\text{两端点的 price})\bigr)$——把路径上**较便宜的端点**选作根。这解释了示例 1 的两个并列最优：路径 $\{0,1,3,4\}$ 总和 33，端点 0（价 9）作根得 $33 - 9 = 24$；路径 $\{2,1,3,4\}$ 总和 31，端点 2（价 7）作根得 $31 - 7 = 24$。也解释了补充用例 3 中「叶子端比中心优」：中心作根时两个方向只能算一个，叶子作根可以「穿过中心再延伸」。

于是问题化为：**对每个 $r$ 求 $\text{best}(r)$，答案取 $\max(\text{best}(r) - \text{price}[r])$**。

### 3.3 核心观察二：换根 DP —— down 与 up

![换根 DP 模型：best(v) = max(向下的 down，向上的 up)](images/wc328_q4_reroot_model.svg)

把树**任意**定根（取 $0$）。从任意点 $v$ 出发的简单路径，按第一条边的去向**恰好分两类**：

- **向下**（进入 $v$ 的子树）：定义 $\text{down}[v]$ 为其最大价值和。这是最经典的树形 DP：

$$\text{down}[u] = \text{price}[u] + \max\Bigl(0,\ \max_{c \in \text{children}(u)} \text{down}[c]\Bigr)$$

- **向上**（第一条边是 $(v, \text{parent}(v))$）：定义 $\text{up}[v]$ 为其最大价值和。这类路径走到父亲 $p$ 后，**要么继续向上，要么拐进 $p$ 的其他孩子**——但绝不能折回 $v$：

$$\text{up}[v] = \text{price}[v] + \max\Bigl(\text{up}[p],\ \text{price}[p] + d^*(p,v)\Bigr)$$

其中 $d^*(p,v)$ 是「$p$ 的孩子中**除 $v$ 外**的最大 $\text{down}$」（无则 $0$）。约定 $\text{up}[\text{root}] = \text{price}[\text{root}]$（根没有父边，只剩平凡路径）。

**排除自己分支**是实现的关键：给每个点额外维护 $\text{heavy}[u]$（$\text{down}$ 最大的孩子下标）与 $d_2[u]$（孩子 $\text{down}$ 的次大值），则

$$d^*(p, v) = \begin{cases} d_2[p] & v = \text{heavy}[p] \\ d_1[p] & \text{否则} \end{cases} \qquad (d_1[p] = \text{down}[p] - \text{price}[p])$$

最后：

$$\text{best}[v] = \max(\text{down}[v],\ \text{up}[v]), \qquad \text{ans} = \max_v \bigl(\text{best}[v] - \text{price}[v]\bigr)$$

> ⚠️ **`up` 递推最容易层级错位**：$\max$ 里比较的两项都是「**从 $p$ 出发**（含 $\text{price}[p]$）的链」——向父侧延伸的是 $\text{up}[p]$ 本身、向兄弟延伸的是 $\text{price}[p] + d^*$。常错写法 $\text{price}[v] + \max(\text{up}[p] - \text{price}[p],\ d^*)$ 把两项都错降了一层（当成了「从 $p$ 的父侧 / 从兄弟**出发**的链」）。用示例 1 自检：$\text{up}[1]$ 应为 $17$（路径 $[1,0] = 8+9$），错写法得 $8$。

### 3.4 算法流程

![算法流程：BFS 定序、逆序求 down、正序换根求 up](images/wc328_q4_algorithm_flow.svg)

```text
① 建邻接表；BFS 得 order[]（父先于子）与 parent[]
② 逆序扫 order（孩子先于父）：
     对 u 遍历孩子 v，维护 d1 / d2 / heavy
     down[u] = price[u] + d1
③ 正序扫 order（父先于子）：
     ans = max(ans, max(down[u], up[u]) − price[u])
     对 u 的每个孩子 v：
         d* = (v == heavy[u]) ? d2[u] : down[u] − price[u]
         up[v] = price[v] + max(up[u], price[u] + d*)
④ 返回 ans
```

三遍扫描**全部迭代、零递归**——链状树深达 $10^5$，递归 DFS 在 C++ 有爆栈风险、在 Python 必炸（`sys.setrecursionlimit` 也救不了段错误），BFS 定序一举消除。

### 3.5 示例演算

![示例 1 演算：down / up / best / 开销全表](images/wc328_q4_example_walkthrough.svg)

对示例 1（以 $0$ 为根定向，$0$ 的孩子是 $1$；$1$ 的孩子是 $2,3$；$3$ 的孩子是 $4,5$）：

**第二遍（逆序求 down）**：$\text{down}[4]=10$，$\text{down}[5]=5$，$\text{down}[3]=6+\max(10,5)=16$（$\text{heavy}[3]=4$，$d_2[3]=5$），$\text{down}[2]=7$，$\text{down}[1]=8+\max(7,16)=24$（$\text{heavy}[1]=3$，$d_2[1]=7$），$\text{down}[0]=9+24=33$。

**第三遍（正序换根）**：

| $v$ | 计算 | $\text{up}[v]$ | 路径 |
|-----|------|----------------|------|
| 1 | $8 + \max(\text{up}[0]{=}9,\ 9 + 0)$ | 17 | $[1,0]$ |
| 2 | $7 + \max(17,\ 8 + \mathbf{16})$ | 31 | $[2,1,3,4]$ |
| 3 | $6 + \max(17,\ 8 + \mathbf{7})$ | 23 | $[3,1,0]$ |
| 4 | $10 + \max(23,\ 6 + \mathbf{5})$ | 33 | $[4,3,1,0]$ |
| 5 | $5 + \max(23,\ 6 + \mathbf{10})$ | 28 | $[5,3,1,0]$ |

（粗体为 $d^*$：$v=2,5$ 不是 $\text{heavy}$，用 $d_1$；$v=3,4$ 是 $\text{heavy}$，用 $d_2$。）

**统计**：开销 $= [24, 16, 24, 17, 23, 23]$，最大 $= 24$ ✓。两个并列最优：节点 0（$[0,1,3,4]=33$，$33-9$）与节点 2（$[2,1,3,4]=31$，$31-7$），正对应 §3.2 的「便宜端点作根」视角。

## 4. 算法细节

1. **BFS 定序，`order` 本身当队列**：一遍建出 `order`（父先于子）与 `parent`。逆序扫 = 孩子先于父（求 down），正序扫 = 父先于子（求 up——它只依赖父亲的 `up` 与 `down`，恰好都已就绪）。零递归，链状树不爆栈。
2. **次大值 + 重孩子下标**：$d^*(p,v)$ 需要「除 $v$ 外的最大孩子 down」。为每个点记 `heavy[u]`（最大来源孩子**下标**）与 `d2[u]`（次大值，不足两个孩子时为 0——注意 down 值恒 $\ge 1$，0 可安全充当「无」）。**按下标判断** $v = \text{heavy}[p]$ 天然正确；按值判断 $\text{down}[v] = d_1$ 虽然在并列时碰巧也对（并列则 $d_2 = d_1$），但需要额外论证，不如按下标直接。
3. **溢出**：路径和上界 $10^{10}$，C++ 中 `down / up / d1 / d2 / ans` 全部 `long long`（`price[u] + d1` 会自动提升）；Python 整数无界。
4. **初始化**：`up[0] = price[0]`（根无父边，只剩平凡路径）；`ans` 初值 0——单节点树自然返回 0，无需特判。
5. **答案在正序扫描里顺手统计**：处理到 $u$ 时 `down[u]`、`up[u]` 均已就绪，`best = max(down, up)` 直接更新答案，不需要第四遍扫描，也不需要显式 `best` 数组。

## 5. 正确性证明

以下均在以 $0$ 为根的定向下讨论，$p = \text{parent}(v)$。

**引理 1**（最小路径）：对任意根 $r$，以 $r$ 为起点的路径价值和的最小值为 $\text{price}[r]$，且仅由单节点路径 $[r]$ 取到。

**证明**：以 $r$ 为起点的路径至少含 $r$。单节点路径的和恰为 $\text{price}[r]$。含至少一条边的路径和为 $\text{price}[r]$ 加上其余节点价格之和，而每个价格 $\ge 1$，故严格大于 $\text{price}[r]$。∎

**推论**：$\text{cost}(r) = \text{best}(r) - \text{price}[r]$，其中 $\text{best}(r)$ 为以 $r$ 为起点的路径和最大值。

**引理 2**（down）：$\text{down}[u]$ 等于「从 $u$ 出发、每一步都走向当前点孩子的路径（含单节点）」的最大价值和，且递推 $\text{down}[u] = \text{price}[u] + \max(0, \max_c \text{down}[c])$ 成立。

**证明**：对子树高度归纳。$u$ 为叶：唯一路径是 $[u]$，$\text{down}[u] = \text{price}[u]$ ✓。$u$ 内部：此类路径要么停在 $u$（值 $\text{price}[u]$），要么第一步到某孩子 $c$、其后缀恰是「从 $c$ 出发的同类路径」；两种情形不交且覆盖全部，选择哪个 $c$ 互相独立，由归纳假设其后缀最大值为 $\text{down}[c]$，故总最大值为 $\text{price}[u] + \max(0, \max_c \text{down}[c])$。∎

**引理 3**（up）：对非根 $v$，$\text{up}[v]$ 等于「从 $v$ 出发、第一条边为 $(v, p)$ 的路径」的最大价值和，且递推 $\text{up}[v] = \text{price}[v] + \max(\text{up}[p],\ \text{price}[p] + d^*(p,v))$ 成立（$d^*(p,v)$ 为 $p$ 的孩子中除 $v$ 外的最大 down，无则 $0$）。

**证明**：对 BFS 序（深度）归纳。所述路径去掉首节点后，恰为**从 $p$ 出发且不经过 $v$** 的路径 $Q$（至少含 $p$）。$Q$ 的第一步只有两种去向：

- 停在 $p$，或进入 $p$ 的其他孩子 $c \ne v$：由引理 2，此类最大值为 $\text{price}[p] + \max(0, \max_{c \ne v} \text{down}[c]) = \text{price}[p] + d^*(p,v)$；
- 走 $p$ 的父边：此类恰是「从 $p$ 出发、第一条边为父边的路径」，由归纳假设其最大值为 $\text{up}[p]$（含 $\text{price}[p]$；由 $\text{up}[p] \ge \text{price}[p]$，它同时覆盖了 $Q = [p]$ 的情形）。

两类取最大，加上 $\text{price}[v]$ 即得递推。归纳基础：$\text{up}[\text{root}] = \text{price}[\text{root}]$（无父边，只剩平凡路径，系约定）。∎

**定理**：$\text{best}(v) = \max(\text{down}[v], \text{up}[v])$，从而算法返回 $\max_v \text{cost}(v)$。

**证明**：从 $v$ 出发的简单路径按第一条边分两类。① 不用边 $(v, p)$：第一步必到 $v$ 的孩子 $c$；此后路径若要离开 $v$ 的子树，必须经过 $v$ 或边 $(v,p)$，均不可能，故路径全程在子树内，且归纳可证每一步都走向当前点的孩子（树上不回头）——恰为引理 2 的类，最大值 $\text{down}[v]$。② 首条边为 $(v, p)$：恰为引理 3 的类，最大值 $\text{up}[v]$（$v$ 为根时该类为空，$\text{up}$ 退化为 $\text{price}[v]$）。两类合并得 $\text{best}(v) = \max(\text{down}[v], \text{up}[v])$。结合引理 1 的推论，$\text{cost}(v) = \max(\text{down}[v], \text{up}[v]) - \text{price}[v]$；算法对每个 $v$ 取其最大值，即得答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。三遍扫描各访问每条边常数次：BFS 定序 $O(n)$；逆序求 down 时每个点的孩子遍历总计 $O(n)$（每条无向边被看两次）；正序换根同理。$n = 10^5$ 毫秒级完成，比暴力的 $O(n^2)$ 快两个数量级以上。
- **空间复杂度**：$O(n)$。邻接表、`order / parent / down / up / d2 / heavy` 各 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxOutput(int n, vector<vector<int>>& edges, vector<int>& price) {
        vector<vector<int>> g(n);
        for (auto& e : edges) {
            g[e[0]].push_back(e[1]);
            g[e[1]].push_back(e[0]);
        }
        // ① BFS 定序：order 本身当队列，父先于子
        vector<int> parent(n, -1), order;
        order.reserve(n);
        vector<char> vis(n, 0);
        order.push_back(0);
        vis[0] = 1;
        for (size_t i = 0; i < order.size(); i++) {
            int u = order[i];
            for (int v : g[u]) if (!vis[v]) {
                vis[v] = 1;
                parent[v] = u;
                order.push_back(v);
            }
        }
        // ② 逆序扫：求 down，同时记 d2（次大）与 heavy（最大来源孩子）
        vector<long long> down(n), d2(n, 0), up(n);
        vector<int> heavy(n, -1);
        for (int i = n - 1; i >= 0; i--) {
            int u = order[i];
            long long d1 = 0;
            for (int v : g[u]) if (v != parent[u]) {
                if (down[v] > d1) { d2[u] = d1; d1 = down[v]; heavy[u] = v; }
                else if (down[v] > d2[u]) d2[u] = down[v];
            }
            down[u] = price[u] + d1;
        }
        // ③ 正序扫：换根求 up，顺手统计答案
        up[0] = price[0];
        long long ans = 0;
        for (int i = 0; i < n; i++) {
            int u = order[i];
            ans = max(ans, max(down[u], up[u]) - price[u]);
            for (int v : g[u]) if (v != parent[u]) {
                long long dstar = (v == heavy[u]) ? d2[u] : down[u] - price[u];
                up[v] = price[v] + max(up[u], price[u] + dstar);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxOutput(self, n: int, edges: List[List[int]], price: List[int]) -> int:
        g = [[] for _ in range(n)]
        for a, b in edges:
            g[a].append(b)
            g[b].append(a)

        # ① BFS 定序：order 本身当队列，父先于子
        parent = [-1] * n
        order = [0]
        vis = [False] * n
        vis[0] = True
        for u in order:
            for v in g[u]:
                if not vis[v]:
                    vis[v] = True
                    parent[v] = u
                    order.append(v)

        # ② 逆序扫：求 down，同时记 d2（次大）与 heavy（最大来源孩子）
        down = [0] * n
        d2 = [0] * n
        heavy = [-1] * n
        for u in reversed(order):
            d1 = 0
            for v in g[u]:
                if v != parent[u]:
                    if down[v] > d1:
                        d2[u], d1, heavy[u] = d1, down[v], v
                    elif down[v] > d2[u]:
                        d2[u] = down[v]
            down[u] = price[u] + d1

        # ③ 正序扫：换根求 up，顺手统计答案
        up = [0] * n
        up[0] = price[0]
        ans = 0
        for u in order:
            ans = max(ans, max(down[u], up[u]) - price[u])
            for v in g[u]:
                if v != parent[u]:
                    dstar = d2[u] if v == heavy[u] else down[u] - price[u]
                    up[v] = price[v] + max(up[u], price[u] + dstar)
        return ans
```

## 8. 边界情况与易错点

1. **溢出（最隐蔽）**：路径和可达 $10^5 \times 10^5 = 10^{10}$，超 32 位 `int` 上限 $2.1 \times 10^9$ 的近 5 倍。C++ 中 `down / up / d1 / d2 / ans` 与返回值**全部** `long long`；只换返回值、中间量仍 `int` 照样溢出。
2. **把最小路径也做一套 DP**：看到「最大减最小」就想对称地再求个最小——点权全为正时最小路径恒为 $[r]$ 单节点，白送。只有点权可能出现负数时才需要另做一套「最小路径」DP（见延伸思考）。
3. **`up` 递推层级错位**（本题最高频错误）：正确式 $\text{up}[v] = \text{price}[v] + \max(\text{up}[p],\ \text{price}[p] + d^*)$；错写成 $\text{price}[v] + \max(\text{up}[p] - \text{price}[p],\ d^*)$ 会把两项各降一层。用示例 1 检验：$\text{up}[1]$ 应为 17（$[1,0]=8+9$），错写法得 8。
4. **漏做「排除自己分支」**：直接用 $d_1[p]$ 不排除 $v$，会把「从 $v$ 出发又绕回 $v$ 子树」的不合法路径计入（路径必须简单）。实现上靠 `heavy` + `d2`；**按下标判断** $v = \text{heavy}[p]$，两个孩子的 down 并列最大时也直接正确。
5. **`best` 写成 `down + up`**：路径从根**出发**，根是端点不是中转点，两个方向只能取一——$\max$ 而非相加。`down + up − price` 那套是「直径 / 最大路径和」类题（如 124 题）的套路，别串台。
6. **递归爆栈**：$n = 10^5$ 的链状树递归深度 $10^5$，Python 必挂、C++ 视栈大小也可能挂。本文三遍扫描全迭代（BFS 序），彻底规避。
7. **$n = 1$（无边）**：邻接表为空、`order = [0]`，`up[0] = price[0]`，答案自然为 0，无需特判——但 `ans` 初值必须是 0 而非「负无穷」。
8. **无向边要双向建**：`g[a].push_back(b)` 与 `g[b].push_back(a)` 都要有；遍历孩子时用 `v != parent[u]` 过滤回边。
