# LeetCode 香槟塔 题解

## 1. 题目概述

- **标题 / 题号**：香槟塔（#799，medium）
- **链接**：https://leetcode.cn/problems/champagne-tower/
- **来源**：LeetCode 第 75 场周赛 Q3
- **难度**：中等
- **标签**：动态规划

**题意**：把玻璃杯叠成金字塔，第 $0$ 行 $1$ 个、第 $1$ 行 $2$ 个……第 $r$ 行 $r+1$ 个，每个杯子恰好盛 $1$ 杯。从顶端 $(0,0)$ 倒入 `poured` 杯香槟：某个杯子装满后，**继续倒进来的**香槟以相等流量分给它的左下 $(r+1,c)$ 与右下 $(r+1,c+1)$；最后一行溢出的香槟直接流到地板上。求倒完之后 $(\text{query\_row}, \text{query\_glass})$ 这个杯子盛放的比例，取值必然落在 $[0,1]$。

**约束**：

- $0 \le \text{poured} \le 10^9$
- $0 \le \text{query\_glass} \le \text{query\_row} < 100$
- 返回值为 `double`，与标准答案误差在 $10^{-5}$ 以内即算通过

> 💡 这道题的全部难点是一句话：**「盛放量」会被截断，而「交付量」可以线性叠加**。想通这句话，剩下的就是一次按行推进的 $O(R^2)$ 递推，与 `poured` 的大小完全无关。

## 2. 示例

**示例 1**

```text
输入：poured = 1, query_row = 1, query_glass = 1
输出：0.00000
解释：只倒了 1 杯，恰好把 (0,0) 装满，没有一滴溢出，第 1 行全空。
```

**示例 2**

```text
输入：poured = 2, query_row = 1, query_glass = 1
输出：0.50000
解释：(0,0) 装满后还剩 1 杯，均分给 (1,0) 与 (1,1)，
      两个杯子各得 0.5 杯，都没有满。
```

**示例 3**

```text
输入：poured = 100000009, query_row = 33, query_glass = 17
输出：1.00000
解释：一亿多杯灌下去，第 33 行早就被灌满；该杯交付量仍约 1.36×10^7 杯，
      远超容量 1，截断后比例就是 1。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的模拟是「按杯倒」：循环 `poured` 次，每次把 1 杯从 $(0,0)$ 往下推，遇到满杯就拆成两个半杯分别给两个孩子。单次下推最坏要碰到 $O(R)$ 个杯子，总复杂度 $O(\text{poured}\cdot R)$。本题 `poured` 最大 $10^9$、$R=100$，量级 $10^{11}$，必然超时。

第二种朴素做法是直接照抄物理定义写递归：杯子 $(r,c)$ 的交付量由 $(r-1,c-1)$ 与 $(r-1,c)$ 的溢出量决定。但同一行会被反复展开，不加记忆化时调用次数随行数指数增长（$2^{99}$ 级别）；而一旦加上记忆化，状态数只有约 $\sum_{r<100}(r+1)\approx 5000$ 个——那它本质上就是本题的 DP，还不如直接按行递推来得干净。

真正要绕过的弯是：**不能让「时间顺序」进入状态**。倒水是一滴一滴发生的，但最终结果与倒水顺序无关，所以可以把过程压缩成「逐行结算」。

### 3.2 核心观察：存「交付量」而不是「盛放量」

![香槟塔的溢出规则与杯子编号](images/wc75_q3_pyramid_split.svg)

设 $x_r(c)$ 为**流到**杯子 $(r,c)$ 的总杯数（不管它接不接得住，都算「交付」给它），则

$$x_0(0) = \text{poured},\qquad x_0(c) = 0 \quad (c \ne 0)$$

对 $r \ge 1$，一个杯子只可能从左上 $(r-1,c-1)$ 和右上 $(r-1,c)$ 接到香槟，而每个父杯最多盛 $1$ 杯、多余的才往下分，于是

$$x_{r+1}(c) = \frac{\max\bigl(0,\;x_r(c-1)-1\bigr)}{2} + \frac{\max\bigl(0,\;x_r(c)-1\bigr)}{2}$$

（下标越界的 $x_r(\cdot)$ 一律视作 $0$。）答案就是

$$\text{ans} = \min\bigl(1,\; x_{\text{query\_row}}(\text{query\_glass})\bigr)$$

**为什么状态必须是 $x$ 而不是 $\min(1,x)$？** 因为截断不是线性的：$\min(1,u+v) \ne \min(1,u)+\min(1,v)$。若状态里存的是「已经截断过的盛放量」，那么一个杯子满了之后，我们就再也无法还原它到底往下送了多少（那部分信息被 `min` 吃掉了）。而交付量 $x$ 满足**线性叠加**：孩子收到的是两个父杯各自溢出量的一半之和。所以把截断推迟到最后一步做，递推就变成了纯粹的加法。

顺带确认数值范围：交付量的上界是 $x_r(c) \le \text{poured} \le 10^9$，而 `double` 有 53 位有效位、下溢线低到 $2.2\times 10^{-308}$；整个递推只做加法与「除以 $2$」，误差不会被放大，精度绰绰有余。

### 3.3 算法流程：两行滚动数组

![滚动数组的状态转移](images/wc75_q3_rolling_dp.svg)

观察递推式：第 $r+1$ 行只依赖第 $r$ 行，因此**不需要**保存整个金字塔，两个一维数组即可。长度至少要 $\text{query\_row}+1$：最后一轮里 $c$ 取到 $r=\text{query\_row}-1$，会往 `nxt[c+1]`（即下标 $\text{query\_row}$）里加数；代码里干脆开到 $\text{query\_row}+2$，多出的一格永远为 $0$。

把这些写成代码骨架：

```text
cur[0] = poured，其余为 0
for r = 0 .. query_row-1:          # 只推到目标行的上一行
    nxt 全部清 0
    for c = 0 .. r:
        if cur[c] > 1:             # 只有满了才溢出
            half = (cur[c] - 1) / 2
            nxt[c]   += half       # 给左下
            nxt[c+1] += half       # 给右下
    cur = nxt
return min(1, cur[query_glass])
```

代码用的是「**推**」的形式：由父杯把 $q_r(c)=\max(0,x_r(c)-1)/2$ 推给两个孩子；而 3.2 的公式是「**拉**」的形式：孩子去两个父杯各取一半。两者只是求和次序不同，数值上完全相等（见第 5 节引理 2）。用「推」写循环更自然，因为每一行的长度在循环变量里已经知道了。

关于行数：$\text{query\_row} < 100$，但**只需要算到 $\text{query\_row}$ 这一行**——第 $\text{query\_row}+1$ 行及以下不会影响答案。这也是为什么空间能压到 $O(\text{query\_row})$、时间只有 $\sum_{r<\text{query\_row}}(r+1)$。

### 3.4 示例演算

![poured = 6 的逐行演算表](images/wc75_q3_walkthrough.svg)

以 `poured = 6` 为例，逐行看交付量、盛放量与溢出量：

| 行 $r$ | 交付量 $x_r$ | 盛放 $\min(1,\cdot)$ | 溢出 $q_r$ |
|--------|--------------|----------------------|-------------|
| 0 | $[6]$ | $[1]$ | $[2.5]$ |
| 1 | $[2.5, 2.5]$ | $[1, 1]$ | $[0.75, 0.75]$ |
| 2 | $[0.75, 1.5, 0.75]$ | $[0.75, 1, 0.75]$ | $[0, 0.25, 0]$ |
| 3 | $[0, 0.25, 0.25, 0]$ | 同左 | $[0, 0, 0, 0]$ |

走查第 2 行中间那杯：它从 $(1,0)$、$(1,1)$ 各接到 $0.75$ 杯溢出，共交付 $1.5$ 杯；自己只盛 $1$ 杯，多出的 $0.5$ 杯再各分 $0.25$ 给 $(3,1)$ 与 $(3,2)$。于是查询 $(2,1)$ 得 $\min(1,1.5)=1.0$，查询 $(3,1)$ 得 $0.25$。

再回头核对三组官方示例：

- `poured = 1`：$x_1 = [0,0]$（$x_0(0)=1$ 没超过容量，不产生溢出），故 $(1,1)$ 为 $0$。
- `poured = 2`：$q_0(0) = 0.5$，$x_1 = [0.5,0.5]$，故 $(1,1)$ 为 $0.5$。
- `poured = 100000009`：推到第 33 行时 $(33,17)$ 的交付量仍约 $1.36\times 10^{7}$ 杯，远超容量 $1$，截断后为 $1.0$。

题面叙述里的「倒 4 杯」也能对上：$x_1=[1.5,1.5]$，$q_1=[0.25,0.25]$，$x_2=[0.25,0.5,0.25]$，正是题面图里第 3 层（即 0-indexed 的第 2 行）中间 $0.5$、两侧各 $0.25$ 的样子。

## 4. 算法细节

1. **状态定义要精确**：`cur[c]` 表示「交付给第 $r$ 行第 $c$ 杯的总杯数」，允许大于 $1$；只有返回时才做 $\min(1,\cdot)$。
2. **数组多开一格**：循环里会访问 `nxt[c+1]`，当 $c=r$ 时下标是 $r+1$，所以数组长度取 `query_row + 2`；用固定的 $101$ 也可以，但多开两格最省心。
3. **只在 `cur[c] > 1` 时计算溢出**：等于 $1$ 表示恰好装满、没有多余，判 `>=` 会多推出 $0$，虽不影响结果但语义不对；判 `>` 还能省掉大量无用的加法。
4. **只递推到 `query_row`**：循环写 `for r in range(query_row)`，最后一轮由第 $\text{query\_row}-1$ 行生成第 $\text{query\_row}$ 行，正好停在目标行；多推一行不影响答案但纯属浪费。
5. **朴素递归与 DP 的差别只在记忆化**：`x(r,c)` 的递归形式与递推完全一致，状态只有 $O(R^2)$ 个；面试里若先写递归，务必补一句「加记忆化后即 $O(R^2)$」。
6. **可以原地滚动**：把 `nxt` 省掉，倒序枚举 $c$：`q = max(0, cur[c]-1)/2; cur[c+1] += q; cur[c] = q`。倒序保证 `cur[c+1]` 的旧值已被消费过，`cur[c]` 在被覆盖前也已把溢出推给右边；`cur[c] = q` 让下一轮「从左边再接一份」。空间从两行降为一行（仍是 $O(R)$）。
7. **浮点类型**：`poured` 是 `int`（可达 $10^9$），必须先转成 `double`；`float`（约 7 位有效数字）在多行连续除以 2 之后误差会累积到 $10^{-6}$ 量级，靠近容差边界，不要用。
8. **不要用 `==` 判断装满**：`cur[c] == 1` 在浮点下几乎不可靠，本题只需要「$>1$ 才溢出」，用严格大于即可，$1+\varepsilon$ 多推的那点量在 $10^{-15}$ 级别，输出容差 $10^{-5}$ 完全覆盖。
9. **`query_glass` 一定合法**：约束给了 $\text{query\_glass} \le \text{query\_row}$，所以 `cur[query_glass]` 不会越界，无需额外特判；但 `query_row = 0` 时循环一次都不进，返回前仍要 `min(1, cur[0])`。

## 5. 正确性证明

先约定：$x_r(c)$ 按 3.2 的递推式定义（越界项为 $0$），$q_r(c)=\max\bigl(0,x_r(c)-1\bigr)/2$。

**引理 1（逐行结算合法）**：把倾倒过程视为「先把 `poured` 杯全部倒入 $(0,0)$，再让溢出逐行向下结算」，与真实的「连续滴水」过程得到相同的最终状态；且第 $r$ 行每个杯子的最终盛放量为 $\min\bigl(1,x_r(c)\bigr)$。

**证明**：对行数归纳。$r=0$ 时只有一个杯子，它最终盛放 $\min(1,\text{poured})=\min(1,x_0(0))$，正确。设第 $r$ 行成立：杯子 $(r,c)$ 容量为 $1$，流入 $x_r(c)$ 杯，能接住的至多是 $1$ 杯，剩 $x_r(c)-1$ 杯（若为正）会继续下流，且按题意以相等流量分给左右两个孩子——这正好是 $q_r(c)$ 各一份，故第 $r+1$ 行的交付量恰为 $q_r(c-1)+q_r(c)$，即 $x_{r+1}(c)$。由于每杯的容量截断只取决于它自己的流入总量，而流入总量只取决于上一行的最终状态，整个过程与滴水的先后顺序无关。∎

**引理 2（推、拉两种写法等价）**：对任意 $r\ge 0$、$0\le c\le r+1$，算法中 `nxt[c]` 收到的累加量等于 $\dfrac{\max(0,x_r(c-1)-1)}{2}+\dfrac{\max(0,x_r(c)-1)}{2}$。

**证明**：内层循环枚举 $c'=0..r$，把 $q_r(c')$ 加到 `nxt[c']` 与 `nxt[c'+1]`。固定目标下标 $c$，能加到它上面的只有 $c'=c$（作为左孩子）与 $c'=c-1$（作为右孩子）两项，合计 $q_r(c)+q_r(c-1)$；而 $q_r(\cdot)=\max(0,\cdot-1)/2$，与待证式相同。边界处 $c=0$ 只有 $q_r(0)$、$c=r+1$ 只有 $q_r(r)$，与「越界项为 $0$」的约定一致。∎

**引理 3（截断正确）**：杯子 $(\text{query\_row},\text{query\_glass})$ 的盛放比例等于 $\min\bigl(1,x_{\text{query\_row}}(\text{query\_glass})\bigr)$。

**证明**：由引理 1，该杯最终流入 $x$ 杯。若 $x\le 1$，容量足够，全部留下，比例 $x$；若 $x>1$，杯子装满，比例 $1$，多出的部分继续下流。两种情况都等于 $\min(1,x)$。∎

**定理**：算法返回的 `min(1, cur[query_glass])` 就是题目要求的盛放比例。

**证明**：循环执行 $r=0,1,\dots,\text{query\_row}-1$ 轮，第 $r$ 轮由 `cur`（等于 $x_r$）算出 `nxt`（由引理 2 等于 $x_{r+1}$），随后交换。归纳得循环结束时 `cur[c]` 等于 $x_{\text{query\_row}}(c)$。截断只影响低于目标行的杯子（它们不在查询范围内），不影响 $x_{\text{query\_row}}$ 本身。再由引理 3，返回值正确。∎

## 6. 复杂度分析

- **时间**：$O(\text{query\_row}^2)$。第 $r$ 轮内层循环 $r+1$ 次，总计 $\sum_{r=0}^{\text{query\_row}-1}(r+1)=\frac{\text{query\_row}(\text{query\_row}+1)}{2}\le 4950$ 次转移，每次 $O(1)$。**与 `poured` 无关**——这是本题从 $10^{11}$ 次模拟降到 $5\times 10^3$ 次加法的关键。
- **空间**：$O(\text{query\_row})$。两个长度 $\text{query\_row}+2$ 的 `double` 数组；原地滚动版只需一个。若按上限写死 $101$ 个杯子，则是 $O(1)$ 常数空间。
- **对比**：按杯模拟是 $O(\text{poured}\cdot \text{query\_row})$、$O(1)$ 额外空间；本题用「不按时间、只按行」换掉了对 `poured` 的依赖。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    double champagneTower(int poured, int query_row, int query_glass) {
        // cur[c]：交付给当前行第 c 杯的总杯数（可大于 1，只有返回时才截断）
        vector<double> cur(query_row + 2, 0.0), nxt(query_row + 2, 0.0);
        cur[0] = (double)poured;

        for (int r = 0; r < query_row; ++r) {   // 只推到目标行
            fill(nxt.begin(), nxt.end(), 0.0);
            for (int c = 0; c <= r; ++c) {
                if (cur[c] > 1.0) {             // 恰好 1 杯不溢出
                    double half = (cur[c] - 1.0) / 2.0;
                    nxt[c]     += half;         // 左下
                    nxt[c + 1] += half;         // 右下
                }
            }
            swap(cur, nxt);
        }
        return min(1.0, cur[query_glass]);      // 交付量再截断，即盛放比例
    }
};
```

### Python

```python
class Solution:
    def champagneTower(self, poured: int, query_row: int, query_glass: int) -> float:
        # cur[c] 表示交付给当前行第 c 个杯子的总杯数，允许 > 1
        cur = [0.0] * (query_row + 2)
        cur[0] = float(poured)

        for r in range(query_row):          # 只推到第 query_row 行
            nxt = [0.0] * (query_row + 2)   # 多开一格接最右侧的溢出
            for c in range(r + 1):
                if cur[c] > 1.0:            # 只有装满才溢出
                    half = (cur[c] - 1.0) / 2.0
                    nxt[c] += half          # 左下
                    nxt[c + 1] += half      # 右下
            cur = nxt

        return min(1.0, cur[query_glass])
```

## 8. 边界情况与易错点

1. **`poured = 0`**：`cur[0] = 0`，之后每一行都是 $0$，答案 $0.0$；不必特判，但别把「`cur[c] > 1` 才溢出」写成「非零就溢出」。
2. **`query_row = 0`**：循环一次都不执行，直接返回 `min(1, cur[0])`。若漏掉 `min`，`poured = 5` 时会返回 $5.0$，明显越界。
3. **`query_glass = query_row`（每行最右侧）**：`nxt[c+1]` 会取到下标 $r+1$，最后一轮即 `query_row`，所以数组长度下限是 `query_row + 1`；只开到 `query_row` 必然越界（C++ 的 `vector` 不报错只崩，Python 抛 `IndexError`）。
4. **中途截断是头号错误**：把 `cur[c] = min(1, cur[c])` 放进循环里，再算溢出就会得到 $0$——溢出量被抹掉了。溢出必须用**未截断**的交付量算。
5. **`nxt` 忘记清零**：复用数组时若不清零，上一轮残留会滚进下一行，答案偏大。`fill` / 重新 `[0.0] * n` 二者选一，务必显式。
6. **判满用严格大于**：`cur[c] > 1` 而不是 `>=`。用 `==` 更糟，浮点下 $1.0000000001$ 与 $1$ 几乎不会相等，容易漏溢出。
7. **整数溢出与精度**：`poured` 必须先转 `double`；别用 `float`——它只有约 7 位有效数字，$10^9$ 附近的量已无法精确表示，多行加减后误差可达 $10^{-7}$ 量级，白白吃掉 $10^{-5}$ 容差的余量。
8. **原地滚动的顺序**：写单数组版本时 $c$ 必须**倒序**（`r → 0`），并且先 `cur[c+1] += q` 再 `cur[c] = q`；顺序写反会把刚加进去的下一行数据当成当前行再推一次，结果翻倍。
9. **不要真的建 $100\times100$ 的表**：虽然 $R<100$ 建表也能过，但多开的一维纯属浪费；本题只需要两行。
10. **返回值范围**：结果必须落在 $[0,1]$，若测试里出现 $>1$ 或负数，一定是截断位置或清零步骤写错了。

**延伸思考**：

- **容量不等或分流不等**：若每个杯子容量是 $c_r$，或溢出按 $\alpha$ 与 $1-\alpha$ 分给左右，只需把公式里的 $1$、$\frac{1}{2}$ 换掉，状态与流程一字不变——这正是「交付量可叠加」带来的可扩展性。
- **边缘列的闭式解**：最左（最右）那一列可以 $O(1)$ 直接算。设 $e_r = x_r(0)$，则 $e_0 = \text{poured}$、$e_{r+1} = \max(0,e_r-1)/2$，展开得 $e_r = \max\bigl(0,\ (\text{poured}-(2^r-1))/2^r\bigr)$——每下一层先被扣掉 $1$ 杯再折半，累计扣除 $1+2+\dots+2^{r-1}$。所以 `poured` 一旦不超过 $2^r-1$，整条边就彻底干了；而中轴要「厚」得多（第 12 行中轴至少需要 44 杯才见第一滴），因此**不存在**按行数一刀切的截断。
- **超大 `query_row`**：本题 $R<100$ 让 $O(R^2)$ 稳过。若行数放大到 $10^5$，逐行递推不可行；可以证明每行的交付量都是关于 `poured` 的**分段线性函数**（`max(0,·-1)/2` 只会插入新折点），理论上能按行复合这些分段函数，但折点数随行数增长，实践上不如针对具体询问用「固定 poured 递推 / 固定位置找闭式」分工。
- **统计满杯个数**：在同一套 DP 上顺手累加 $\min(1,x)$（或统计 $x\ge 1$ 的格子数）即可；也可二分「第一次出现不满杯的行」，因为满杯集合随着行号单调外扩。
- **精确答案**：每行的分母都是 $2^{r}$ 的幂，用 `Fraction` 或大整数可以做到零误差，代价是常数变大、只适合小数据验证；工程上 `double` 加 $10^{-5}$ 容差已经足够。
