# LeetCode 旋转字符串 题解

## 1. 题目概述

- **标题 / 题号**：旋转字符串（#796，easy）
- **链接**：https://leetcode.cn/problems/rotate-string/
- **来源**：LeetCode 第 75 场周赛 Q1
- **难度**：简单
- **标签**：字符串，字符串匹配

**题意**：给定两个字符串 $s$ 与 $goal$。一次**旋转**只做一件事：把 $s$ 最左边的字符搬到最右边（如 `"abcde"` 旋转一次得 `"bcdea"`）。问能否在**若干次**（允许 0 次）旋转之后让 $s$ 与 $goal$ 完全相等。

**约束**：

- $1 \le \lvert s \rvert \le 100$，$1 \le \lvert goal \rvert \le 100$
- $s$ 与 $goal$ 只由小写英文字母组成

> 💡 签到题的关键不在算法，而在**把「旋转」换一种说法**：放弃「一次次搬运字符」的模拟，改用「在一个双写串里找一个长度为 $n$ 的窗口」。换成这种说法后，整题就是一次普通的子串匹配。

## 2. 示例

**示例 1**

```text
输入：s = "abcde", goal = "cdeab"
输出：true
解释：把 "ab" 整体左移 2 位（即旋转 2 次），得到 "cdeab"，与 goal 相等。
```

**示例 2**

```text
输入：s = "abcde", goal = "abced"
输出：false
解释：旋转只能整体搬动字符，不能交换字符的相对顺序；
      "abced" 把 e、d 换位了，任何次数的旋转都得不到它。
```

**补充示例（非官方，用于覆盖边界）**

```text
输入：s = "a", goal = "aa"
输出：false
解释：长度不同必然不行——注意 "aa" 确实出现在 s+s = "aa" 里，
      所以「先卡长度」这一步不能省。

输入：s = "ab", goal = "ba"
输出：true
解释：左移 1 位即可。

输入：s = "aaaa", goal = "aaaa"
输出：true
解释：无论旋转几次结果都是 "aaaa"。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是模拟：枚举左移次数 $k = 0,1,\dots,n-1$，每次拼出 $s[k:] + s[:k]$，再与 $goal$ 逐字符比较。拼接与比较各 $O(n)$，总计 $O(n^2)$。本题 $n \le 100$，$10^4$ 次字符操作对 C++ 和 Python 都是瞬间完成，**暴力完全能过**。

但暴力有两个问题：一是手写拼接时 $k$ 的取值范围容易错（$k=n$ 与 $k=0$ 是同一个旋转，循环上界多一位、少一位都隐蔽）；二是它的复杂度依赖 $n^2$，题目数据一旦放大到 $10^5$ 就立刻不可行。而本题存在一个**代码更短、复杂度更低**的等价刻画。

### 3.2 核心观察：旋转 = 双写串上的定长窗口

![双写串上的长度为 n 的窗口](images/wc75_q1_double_window.svg)

把 $s$ 连写两遍得到 $t = s + s$，长度 $2n$。对任意下标 $k$，考虑 $t$ 从 $k$ 开始、长度为 $n$ 的窗口：

$$t[k..k+n) = s[k \bmod n]\, s[(k+1) \bmod n] \cdots s[(k+n-1) \bmod n]$$

这串字符恰好是「把前 $k$ 个字符搬到末尾」的结果，也就是左移 $k$ 位的旋转：

$$t[k..k+n) = s[k:] + s[:k]$$

于是**所有旋转都被同一个东西统一表示**了：$s$ 的 $n$ 个旋转，就是 $t$ 里全部长度为 $n$ 的窗口（$t$ 中共有 $n+1$ 个，其中 $k=n$ 的那个窗口就是 $s$ 本身，与 $k=0$ 重复）。于是原问题等价于：

$$|s| = |goal| \quad\text{且}\quad goal \text{ 是 } t \text{ 的子串}$$

一个容易忽略的细节：**长度检查是必要的**，因为「$goal$ 出现在 $t$ 中」并不自动蕴含长度相等。例如 $s = \texttt{"a"}$、$goal = \texttt{"aa"}$，$t = \texttt{"aa"}$ 里确实含 `"aa"`，但两者长度不同，答案应为 `false`。先比长度，等价性才成立。

### 3.3 算法流程

![算法流程：长度判断 + 一次子串查找](images/wc75_q1_algorithm_flow.svg)

1. 若 $\lvert s \rvert \ne \lvert goal \rvert$，直接返回 `false`；
2. 构造 $t = s + s$；
3. 在 $t$ 中查找 $goal$：找到返回 `true`，否则返回 `false`。

第 3 步就是标准子串匹配。C++ 用 `t.find(goal)`，Python 直接写 `goal in t`。若把查找换成 KMP，整题就是严格的 $O(n+m)$；用内置函数则实现更短，且 $n \le 100$ 时差异不可见（详见第 6 节）。

### 3.4 示例演算

![示例走查表](images/wc75_q1_walkthrough.svg)

**示例 1**：$s = \texttt{"abcde"}$，$t = \texttt{"abcdeabcde"}$，$goal = \texttt{"cdeab"}$。

| 左移 $k$ | 旋转结果 | 与 goal 比较 |
|----------|----------|--------------|
| 0 | `abcde` | 第 1 位就不同 |
| 1 | `bcdea` | 第 1 位就不同 |
| 2 | `cdeab` | 5 位全部相同，命中 |

在 $t$ 上找 `"cdeab"`，首次出现的起点是下标 $2$，即左移 $2$ 位，返回 `true`。注意匹配一旦成功就没必要再看 $k=3,4$——`find` 的「找到即返回」天然带有提前退出。

**示例 2**：$goal = \texttt{"abced"}$。$t = \texttt{"abcdeabcde"}$ 中不存在这个子串，故返回 `false`。这里 $s$ 与 $goal$ 的字符多重集完全相同（`a`–`e` 各一个），但旋转只能整体搬动字符、不能换序，所以「多重集相同」只是必要条件。

**补充示例**：$s = \texttt{"a"}$、$goal = \texttt{"aa"}$，长度不同直接返回 `false`；这正是把长度检查放在查找之前的原因。

## 4. 算法细节

1. **长度检查必须放在查找之前**。它不只是剪枝，而是等价性的前提：少了它，$s = \texttt{"abc"}$、$goal = \texttt{"ab"}$ 会因为 `"ab"` 出现在 `"abcabc"` 里而被误判为 `true`。
2. **双写一次就够**。$t = s+s$ 的窗口数量是 $2n - n + 1 = n+1$ 个，覆盖了全部 $n$ 个不同旋转；不必写成 $s+s+s$，也不需要用 `goal+goal` 反查 $s$（两种写法等价，但多写一遍没有收益）。
3. **下标 $n$ 处的窗口是无害的**。`find` 会扫到 $p = n$，此时 $t[n..2n) = s$，对应 $k=0$ 的旋转。它不会制造假阳性，所以无需把搜索范围人为截断到 $[0, n-1]$；真要截断也可以写 `for (int p = 0; p < n; ++p) if (t.compare(p, n, goal) == 0) return true;`，只是多此一举。
4. **`string::npos` 不要和 `-1` 混用**。`npos` 的类型是 `size_t`，写成 `t.find(goal) != -1` 虽然通常能编译且结果正确，但语义上依赖了有符号/无符号转换；统一用 `!= string::npos` 或 `t.find(goal) < t.size()`。
5. **Python 的 `in` 会临时构造 $s+s$**，额外 $O(n)$ 空间。若要 $O(1)$ 额外空间，可以手写环形比较（两个起点 $i,j$ 在模 $n$ 下标上逐位比），但代码量翻倍，$n \le 100$ 时完全不值得。
6. **需要严格线性就换 KMP**。`std::string::find` 的典型实现最坏 $O(nm)$；在 $t$ 上跑 KMP（模式串为 $goal$）可保证 $O(n+m)$，代价是多写一个 $\pi$ 数组。
7. **可选的常数剪枝**：先分别统计 $s$ 与 $goal$ 的 26 个字母频次，不同则直接 `false`。这不改变复杂度，只是让大量随机用例在第一轮就被否决；对本题规模属于锦上添花。
8. **不需要单独特判 $s = goal$**。0 次旋转是合法的，而 `find` 在下标 0 处就会命中；反过来，若手写循环写成「从 $k=1$ 开始」，就会漏掉这个最常见的正确答案。

## 5. 正确性证明

**引理 1（窗口即旋转）**：设 $n = \lvert s \rvert$，$t = s+s$。对任意整数 $0 \le k \le n$，有 $t[k..k+n) = s[k \bmod n:] + s[:k \bmod n]$。

**证明**：由 $t$ 的定义 $t[i] = s[i \bmod n]$。窗口的第 $j$ 个字符（$0 \le j < n$）是 $t[k+j] = s[(k+j) \bmod n]$。而「左移 $k \bmod n$ 位」的结果，其第 $j$ 个字符正是 $s[(k \bmod n + j) \bmod n]$；由于 $(k+j) \bmod n = (k \bmod n + j) \bmod n$，两串逐位相等。∎

**引理 2（窗口覆盖全部旋转）**：$t$ 的长度为 $n$ 的窗口恰有 $n+1$ 个（起点 $0,1,\dots,n$），其中起点 $n$ 的窗口与起点 $0$ 的内容相同；其余 $n$ 个窗口与左移 $0,1,\dots,n-1$ 位这 $n$ 种操作逐一对应（若 $s$ 有周期，不同内容的窗口还会更少）。

**证明**：窗口起点 $p$ 需满足 $p+n \le 2n$，即 $0 \le p \le n$，共 $n+1$ 个。由引理 1，起点 $p \le n-1$ 的窗口就是左移 $p$ 位的旋转；起点 $n$ 的窗口是 $s[n \bmod n:] + s[:0] = s$，与起点 0 相同。故不同内容的窗口恰好是 $n$ 个旋转（若 $s$ 有周期，不同的还会更少，但每个旋转都在其中）。∎

**引理 3（长度是必要条件）**：若存在若干次旋转把 $s$ 变成 $goal$，则 $\lvert s \rvert = \lvert goal \rvert$。

**证明**：一次旋转把最左字符搬到最右，字符总数不变，故长度恒为 $n$；因此任何旋转结果长度都是 $n$。∎

**引理 4（子串判定等价）**：当 $\lvert s \rvert = \lvert goal \rvert = n$ 时，$goal$ 是 $s$ 的某个旋转 $\iff$ $goal$ 是 $t$ 的子串。

**证明**：

- ($\Rightarrow$) 设 $goal$ 是左移 $k$ 位的结果（$0 \le k < n$）。由引理 1，$goal = t[k..k+n)$，是 $t$ 的子串。
- ($\Leftarrow$) 设 $goal$ 在 $t$ 中首次出现于下标 $p$。因 $\lvert goal \rvert = n$ 且 $t$ 长 $2n$，有 $p + n \le 2n$，即 $p \le n$。由引理 1，$goal = t[p..p+n) = s[p \bmod n:] + s[:p \bmod n]$，正是左移 $p \bmod n$ 位的结果。∎

**定理**：算法返回 `true` 当且仅当存在若干次旋转使 $s$ 变成 $goal$。

**证明**：若 $\lvert s \rvert \ne \lvert goal \rvert$，由引理 3 的逆否命题不存在这样的旋转，算法返回 `false`，正确。若 $\lvert s \rvert = \lvert goal \rvert$，算法返回的正是「$goal$ 是否为 $t$ 的子串」，由引理 4 它与「$goal$ 是否为 $s$ 的旋转」等价。∎

## 6. 复杂度分析

- **时间**：构造 $t = s+s$ 为 $O(n)$。子串匹配若用 KMP 为 $O(2n + m) = O(n)$；若用 `std::string::find`，典型实现最坏 $O(nm)$，本题 $n,m \le 100$，最坏约 $10^4$ 次字符比较，可视为常数。因此整体 $O(n)$（KMP）或 $O(nm)$ 最坏（内置查找），两种都远低于限制。
- **空间**：$t$ 占 $2n$ 个字符，即 $O(n)$；KMP 的 $\pi$ 数组为 $O(m) = O(n)$。不构造 $t$ 的写法（环形比较）可做到 $O(1)$ 额外空间，但本题无必要。
- **对比暴力**：暴力枚举 $n$ 个旋转、每次比较 $O(n)$，时间 $O(n^2)$、额外空间 $O(n)$；本解法把「枚举 + 比较」合并成一次匹配，代码从双重循环缩到三行。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    bool rotateString(string s, string goal) {
        if (s.size() != goal.size()) return false;  // 长度不同，必不可能
        string t = s + s;                           // 所有旋转都是 t 的长度 n 窗口
        return t.find(goal) != string::npos;        // 找到即 true，否则 false
    }
};
```

### Python

```python
class Solution:
    def rotateString(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        return goal in s + s        # 双写后，旋转 = 长度 n 的窗口
```

## 8. 边界情况与易错点

1. **长度不同却「出现了」**：$s = \texttt{"a"}$、$goal = \texttt{"aa"}$ 时 `"aa"` 确实在 `"aa"` 中；$s = \texttt{"abc"}$、$goal = \texttt{"ab"}$ 时 `"ab"` 在 `"abcabc"` 中。漏掉长度检查会直接 WA。
2. **$n = 1$**：$s = \texttt{"a"}$ 时 $t = \texttt{"aa"}$，`find` 从下标 0 命中，返回 `true`；$goal = \texttt{"b"}$ 时返回 `false`。窗口数 $n+1 = 2$ 也说明双写逻辑在最短串上依然成立。
3. **全同字符**：$s = \texttt{"aaaa"}$、$goal = \texttt{"aaaa"}$，任意 $k$ 都命中，返回 `true`。此时不同内容的旋转只有 1 个，但 $t$ 中仍有 5 个窗口，`find` 在 0 处即返回。
4. **$s = goal$（0 次旋转）**：合法答案，`find` 在下标 0 命中。手写循环从 $k=1$ 开始是最常见的漏判写法。
5. **$k = n$ 的重复窗口**：$t$ 的最后一个窗口等于 $s$ 本身，与 $k=0$ 重复。它不会造成假阳性；若手写「枚举窗口」的循环，上界取 $n$ 或 $n-1$ 都能得到正确答案，但取 $n$ 会多比较一次。
6. **`npos` 的类型陷阱**：`t.find(goal) != -1` 依赖 `size_t` 与 `int` 的隐式转换，语义上不干净；统一写 `!= string::npos`。
7. **多重集相同 ≠ 旋转**：$s = \texttt{"abcd"}$、$goal = \texttt{"abdc"}$ 字符频次完全一致，却不是旋转。频次只能用来剪枝，不能作为判定依据。
8. **不要只比较一个窗口**：写成 `s[k:] + s[:k] == goal` 时若把 $k$ 写死（例如只试 `k = 1`），会漏掉 $k=0$ 与其他位移；要么完整枚举 $0..n-1$，要么直接用双写 + 查找。

**延伸思考**：

- **返回最小旋转次数**：`pos = t.find(goal)`；若 `pos == npos` 返回 $-1$，否则返回 $pos \bmod n$。因为 `find` 返回的是最小起点，所以这个次数天然就是最少左移次数（注意 $goal = s$ 时为 0）。
- **放松长度限制**：若问「$goal$ 是否是某个旋转的**子串**」（允许 $\lvert goal \rvert \le \lvert s \rvert$），那么**不必**先卡长度，直接判定 `goal in s + s` 即可：双写串中长度不超过 $n$ 的子串，必然完整落在某个长度 $n$ 的窗口内；反过来每个旋转的子串当然也是 $t$ 的子串。
- **循环同构的规范形**：若要不构造 $2n$ 串、又要 $O(n)$ 判定两个串是否循环同构，可分别求二者的**最小表示**（Booth 算法），比较最小表示是否相同即可；这是字符串最小表示法的主场。
- **多组询问**：若 $s$ 固定而 $goal$ 有大量查询，可对 $s+s$ 建后缀自动机或后缀数组，单次判定降到 $O(\lvert goal \rvert)$，把「一次匹配」升级成「一次预处理 + 多次查询」。
