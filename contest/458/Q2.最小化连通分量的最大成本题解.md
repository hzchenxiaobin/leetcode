# LeetCode 最小化连通分量的最大成本 题解

## 1. 题目概述

- **标题 / 题号**：最小化连通分量的最大成本（#3613，medium）
- **链接**：https://leetcode.cn/problems/minimize-maximum-component-cost/
- **来源**：LeetCode 第 458 场周赛 Q2
- **难度**：中等
- **标签**：并查集、图、二分查找、排序

**题意**：给定 $n$ 个节点（$0 \sim n-1$）的无向**连通**带权图和整数 $k$。可以删除任意多条边，要求最终图中**至多** $k$ 个连通分量。每个连通分量的**成本**定义为其内部边权的**最大值**（无边则成本为 $0$）。求所有分量成本的最大值的最小可能值。

**约束**：

- $1 \le n \le 5 \times 10^4$
- $0 \le \text{edges.length} \le 10^5$
- $0 \le u_i, v_i < n$，$1 \le w_i \le 10^6$
- $1 \le k \le n$
- 输入图是连通图

## 2. 示例

**示例 1**

```text
输入：n = 5, edges = [[0,1,4],[1,2,3],[1,3,2],[3,4,6]], k = 2
输出：4
解释：删掉权 6 的边 (3,4)，得到分量 {0,1,2,3}（成本 4）与 {4}（成本 0），最大成本 4。
      无法更小：阈值取 3 时只能保留 (1,3)、(1,2) 两条边，分量数 3 > 2。
```

**示例 2**

```text
输入：n = 4, edges = [[0,1,5],[1,2,5],[2,3,5]], k = 1
输出：5
解释：k = 1 要求图保持连通，一条边都不能删，成本即最大边权 5。
```

**示例 3（k = n 的边界）**

```text
输入：n = 3, edges = [[0,1,7],[1,2,9]], k = 3
输出：0
解释：k = n，把边全部删光也满足「至多 3 个分量」，每个分量无边、成本 0。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法是枚举「保留哪些边」：$m \le 10^5$ 条边有 $2^m$ 种保留方案，直接爆炸。退一步，注意到**答案只能取 $0$ 或某个边权**（最终图的最大成本就是保留边中的最大权），于是可以枚举候选值 $x$，对每个 $x$ 只保留 $w \le x$ 的边、用并查集数连通分量 $c(x)$，检查 $c(x) \le k$ 是否成立——单次检查 $O(m\,\alpha(n))$，但候选值最多 $m+1$ 个，总量 $O(m^2)$ 级别（$10^{10}$），仍然不可行。

### 3.2 核心观察：可行性关于阈值单调

![阈值 x 与分量数 c(x) 的单调关系](images/min_comp_cost_threshold_concept.svg)

固定阈值 $x$，考察所有「最大成本 $\le x$」的删边方案：

- 权 $> x$ 的边**必须删**：留着，所在分量的成本就超过 $x$ 了；
- 权 $\le x$ 的边**随便留**：多留一条边只会把两个分量**合并**成一个，分量数不增；而成本是 **max 语义**，加入 $w \le x$ 的边永远不会把任何分量的成本顶过 $x$。

于是「成本 $\le x$ 且分量数 $\le k$」有解 $\iff$ **只保留 $w \le x$ 的边后，连通分量数 $c(x) \le k$**——保留全部小边就是分量数最少的方案。而 $x$ 增大时边集只增不减，$c(x)$ **单调不增**（引理 2），所以：

$$\text{答案} = \min\{\,x : c(x) \le k\,\}$$

它无需对每个 $x$ 单独算：**把边按权升序逐条加入（正是 Kruskal 的扫描顺序），`comp` 从 $n$ 一路下降，首次 $\le k$ 时的边权就是答案**。反过来「从大到小删边，删到分量数将超 $k$ 为止」是同一结论的镜像。

> 💡 一句话：删边问题的答案，是「加边过程的停机时刻」——Kruskal 建生成树走到分量数恰好够少的那一步。

### 3.3 算法流程：Kruskal 式一次扫描

![Kruskal 式扫描流程](images/min_comp_cost_kruskal_flow.svg)

```text
comp ← n                        # 初始 n 个分量
if comp ≤ k: return 0           # k ≥ n：删光所有边即可
edges 按权 w 升序排序
for (u, v, w) in edges:
    if find(u) ≠ find(v):       # 这条边能合并两个分量
        union(u, v)
        comp ← comp − 1
        if comp ≤ k: return w   # 首次够少，当前边权即答案
return 0                        # 输入图连通，循环内必返回，兜底
```

### 3.4 示例演算

![示例 1 的逐步演算](images/min_comp_cost_example_walkthrough.svg)

对示例 1（$n=5$，$k=2$）走一遍：排序后边依次为 $(1,3,w{=}2)$、$(1,2,w{=}3)$、$(0,1,w{=}4)$、$(3,4,w{=}6)$，每次成功 union 使 `comp` 恰好减一：

| 步骤 | 加入边 | union? | comp | 判定 comp ≤ k=2 |
|------|--------|--------|------|-----------------|
| 初始 | — | — | 5 | $5 > 2$ ✗ |
| 1 | (1,3) w=2 | ✓ | 4 | $4 > 2$ ✗ |
| 2 | (1,2) w=3 | ✓ | 3 | $3 > 2$ ✗ |
| 3 | (0,1) w=4 | ✓ | 2 | $2 \le 2$ ✓ → **返回 4** |
| — | (3,4) w=6 | 无需处理 | — | — |

最终分量 $\{0,1,2,3\}$ 成本 4、$\{4\}$ 成本 0，最大成本 4，与示例答案一致。

## 4. 算法细节

1. **排序**：`edges` 按第三维 $w$ 升序，排序 $O(m \log m)$ 是复杂度瓶颈；同权边的组内顺序无关紧要（见第 4 点）。
2. **并查集**：路径压缩 + 按大小合并，单次均摊 $O(\alpha(n))$。$n \le 5\times10^4$、$m \le 10^5$，总操作量极小。无需建邻接表，逐条边处理即可。
3. **判停时机**：`comp` 只在「成功合并」时减一，判停 `--comp <= k` 必须写在 `if (ru != rv)` 分支内部，且是**先减再判**——写成 `comp <= k` 会差一，写在循环体顶层则会在 comp 未变时反复空判。
4. **同权边中途停也正确**：首次 $\le k$ 可能出现在同权组的中间，返回值是该组权值 $w$：组内继续加边只会让 `comp` 更小，$c(w) \le$ 当前 `comp` $\le k$ 仍可行；而任何 $x < w$ 的 $c(x)$ 对应更短的前缀，`comp` 必然 $> k$。因此**无需按权分组判停**。
5. **k ≥ n 特判**：删光所有边即得 $n$ 个零成本分量，答案 0。若漏判，扫描会在第一次成功合并时就返回那条边的权（此时 `comp` 从 $n$ 降到 $n-1$ 仍然 $\le k$），得到偏大的错解。该特判同时覆盖 $n=1$、`edges` 为空的情形。
6. **自环与重边**：`find(u) == find(v)` 时直接跳过，天然兼容，无需去重。
7. **二分写法（对照)**：候选集取 $\{0\} \cup \{w_i\}$ 去重后排序，`check(x)` 重建并查集统计 $c(x)$；复杂度同阶 $O(m \log m)$ 但常数更大，且要记得每轮重置 `parent` 数组。题目标签中的 Binary Search 即指此解法。

## 5. 正确性证明

**引理 1（可行性刻画）**：存在删边方案使最大成本 $\le x$ 且分量数 $\le k$ $\iff$ $c(x) \le k$，其中 $c(x)$ 为仅保留 $w \le x$ 的边后图的连通分量数。

**证明**：
（$\Rightarrow$）设方案所得图为 $G'$，其每条边权 $\le x$（否则成本超限），故 $G'$ 是 $G_x$（保留全部 $w \le x$ 边的图）的子图。同一顶点集上，子图中连通的两点在超图中仍连通，故 $G_x$ 的每个连通分量由 $G'$ 的若干个完整分量合并而成，即 $c(x) \le \text{分量数}(G') \le k$。
（$\Leftarrow$）取 $G' = G_x$（删去所有 $w > x$ 的边）。每个分量内所有边权 $\le x$，故每分量成本 $\le x$；分量数 $= c(x) \le k$，是合法方案。∎

**引理 2（单调性）**：$x \le y \Rightarrow c(x) \ge c(y)$。

**证明**：$G_x \subseteq G_y$。向图中加边只会合并分量、不会拆分分量（连通关系随边集增加只增不减）。∎

**定理**：题意所求的最小最大成本 $= \min\{\,x : c(x) \le k\,\}$，且升序扫描算法返回该值。

**证明**：记 $\mathrm{OPT}$ 为最优答案，$S = \{x : c(x) \le k\}$。由引理 2，$S$ 关于 $x$ 上闭（$x \in S, x' \ge x \Rightarrow x' \in S$）。

**第一部分（$\mathrm{OPT} = \min S$）**：任取分量数 $\le k$ 的方案 $G'$，令 $x'$ 为其最大成本，由引理 1（$\Rightarrow$）得 $x' \in S$，故 $\min S \le \mathrm{OPT}$；反之取 $x^* = \min S$，由引理 1（$\Leftarrow$），$G_{x^*}$ 是分量数 $\le k$、成本 $\le x^*$ 的合法方案，故 $\mathrm{OPT} \le x^*$。两向合并即 $\mathrm{OPT} = \min S$。

**第二部分（算法返回 $\min S$）**：若初始 $n \le k$，算法返回 $0$；此时 $c(0) = n \le k$（无边图），而一切成本非负，故 $\min S = 0$，正确。否则设排序后第 $j$ 条边（权 $w$）成功合并后 `comp` 首次 $\le k$，记 $\mathrm{comp}_i$ 为前 $i$ 条边加入后的分量数（随 $i$ 单调不增）。对任意 $x < w$：权 $\le x$ 的边全部位于前 $j-1$ 条中，设共 $i \le j-1$ 条，则 $c(x) = \mathrm{comp}_i \ge \mathrm{comp}_{j-1} > k$（首次性），故 $x \notin S$。而权 $\le w$ 的边至少有 $j$ 条，$c(w) = \mathrm{comp}_{i(w)} \le \mathrm{comp}_j \le k$，故 $w \in S$。因此 $w = \min S$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m \log m)$——排序占主导；并查集部分为 $O(m\,\alpha(n))$，$\alpha$ 为反阿克曼函数，视作常数。$m \le 10^5$ 时总操作量约 $10^6$ 级别，轻松通过。
- **空间复杂度**：$O(n)$，即并查集的 `parent` 与 `sz` 数组。C++ 原地排序 `edges` 无额外 $O(m)$ 开销；Python 的 `sorted` 另需 $O(m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(int n, vector<vector<int>>& edges, int k) {
        vector<int> parent(n), sz(n, 1);
        iota(parent.begin(), parent.end(), 0);
        // 路径压缩：一路把 parent 指向祖父
        auto find = [&](int x) {
            while (parent[x] != x) {
                parent[x] = parent[parent[x]];
                x = parent[x];
            }
            return x;
        };
        int comp = n;
        if (comp <= k) return 0;            // k >= n：删光所有边，答案 0
        sort(edges.begin(), edges.end(),
             [](const auto& a, const auto& b) { return a[2] < b[2]; });
        for (const auto& e : edges) {
            int ru = find(e[0]), rv = find(e[1]);
            if (ru == rv) continue;         // 冗余边（含自环/重边），跳过
            if (sz[ru] < sz[rv]) swap(ru, rv);
            parent[rv] = ru;                // 小树挂到大树
            sz[ru] += sz[rv];
            if (--comp <= k) return e[2];   // 首次降到 <= k：当前边权即答案
        }
        return 0;                           // 连通图下不可达，兜底
    }
};
```

### Python

```python
class Solution:
    def minCost(self, n: int, edges: List[List[int]], k: int) -> int:
        parent = list(range(n))

        def find(x):
            while parent[x] != x:
                parent[x] = parent[parent[x]]   # 路径压缩：指向祖父
                x = parent[x]
            return x

        comp = n
        if comp <= k:                            # k >= n：删光边，答案 0
            return 0
        for w, u, v in sorted((e[2], e[0], e[1]) for e in edges):
            ru, rv = find(u), find(v)
            if ru == rv:                         # 冗余边，跳过
                continue
            parent[ru] = rv
            comp -= 1
            if comp <= k:                        # 首次 <= k：当前边权即答案
                return w
        return 0
```

> 💡 两份代码是同一个扫描的两种写法：Python 把 `(w, u, v)` 排成元组直接 `sorted`，省去比较器；注意元组顺序必须是权在前。

## 8. 边界情况与易错点

1. **k ≥ n 忘判**：答案应为 0；不判的话，第一次成功合并就会触发 `comp ≤ k`，错误地返回那条边的权。示例 3 专门覆盖此情形。
2. **判停的差一错误**：必须「先 `--comp` 再比较 `≤ k`」，且判停在成功合并分支内。
3. **「至多 k」而非「恰好 k」**：两者在本题答案相同（见延伸思考），但按「至多」理解最直接；不要因「恰好」去做多余的拆分构造。
4. **成本是 max 不是 sum**：若误当成边权和，「多留小边不升成本」的单调性论证立刻崩塌（加边会推高和）。
5. **C++ 排序比较器**：必须按 `a[2]` 比较；直接默认排序 `vector<vector<int>>` 按首元素字典序排，顺序就错了。
6. **二分写法的坑**：候选集应是「去重边权 ∪ {0}」，且每轮 `check` 要重建并查集，不能复用上一轮的 `parent`。
7. **m = 0 / n = 1**：入口特判返回 0，扫描循环根本不进入。
8. **答案必存在**：输入图连通，全部边加完后 `comp` = 1 ≤ k，循环内必然返回；末尾 `return 0` 只是防御性兜底。
9. **别去建邻接表 / 判桥**：并查集逐边处理即可，Tarjan 找桥完全是杀鸡用牛刀且难以处理「删多条边」的组合效应。

**延伸思考**：

- **「恰好 k 个分量」变体**：答案与「至多 k」相同。从最优阈值图 $G_{x^*}$ 出发，每次把一个非孤立点的所有边删掉使其成为孤立点，分量数恰增加 1，因此分量数可在 $c(x^*)$ 与 $n$ 之间取到任意值，自然包括 $k$。
- **成本改为「分量内边权和」**：加边可能推高分量的和，可行性关于阈值不再单调，问题本质变成带平衡约束的图划分，复杂度骤增（一般情形 NP-hard）。
- **图不保证连通**：若初始连通分量数已超过 $k$ 则无解；否则每个初始分量内部独立做本题，答案取各分量结果的最大值。
