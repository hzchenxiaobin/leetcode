# LeetCode 最小公共值 题解

## 1. 题目概述

- **标题 / 题号**：最小公共值（#2540，easy）
- **链接**：https://leetcode.cn/problems/minimum-common-value/
- **来源**：LeetCode 第 96 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、双指针、二分查找

**题意**：给定两个**均已按非降序排序**的整数数组 `nums1` 和 `nums2`，返回两个数组的**最小公共整数**——即在两个数组中都至少出现一次的最小整数；不存在公共整数时返回 $-1$。

**约束**：

- $1 \le nums1.length, nums2.length \le 10^5$
- $1 \le nums1[i], nums2[j] \le 10^9$
- `nums1`、`nums2` 均非降序

## 2. 示例

**示例 1（官方）**

```text
输入：nums1 = [1,2,3], nums2 = [2,4]
输出：2
解释：两数组的公共元素只有 2，返回 2。
```

**示例 2（官方）**

```text
输入：nums1 = [1,2,3,6], nums2 = [2,3,4,5]
输出：2
解释：公共元素是 2 和 3，最小者是 2。
```

**示例 3（边界补充）**

```text
输入：nums1 = [1,3,5], nums2 = [2,4,6]
输出：-1
解释：两数组完全错开，没有公共值。
```

## 3. 解题思路

### 3.1 暴力思路

用哈希集合装下 `nums1` 的全部元素，再从小到大扫 `nums2`，第一个命中的就是答案。时间 $O(n + m)$、空间 $O(n)$，能过但完全没有利用"两个数组**已经有序**"这一条件。更朴素的双重循环 $O(nm)$ 则必然超时（$10^{10}$）。本题考察点正是：**在有序数组上，找公共值不需要任何额外空间**。

### 3.2 核心观察：双指针——谁小谁走，相等即最小公共值

![核心观察：双指针谁小移谁，相等即答案](images/bw96_q1_two_pointer_model.svg)

设指针 $i, j$ 分别指向两数组开头。比较 $nums1[i]$ 与 $nums2[j]$：

- **相等**：它就是最小公共值，直接返回；
- **$nums1[i] < nums2[j]$**：$nums1[i]$ 不可能再与 $nums2[j]$ 及其后的任何元素相等（后者都 $\ge nums2[j] > nums1[i]$），所以 $nums1[i]$ 已经"没用"了，$i$ 右移；
- **$nums1[i] > nums2[j]$**：对称地 $j$ 右移。

由于两数组都升序，第一对相等的元素必然是所有公共值中最小的——先被指针"跳过"的元素都已论证过不可能是公共值。

> 💡 这个"谁小移谁"的双指针是有序数组求交、求并、归并的公共骨架，$O(n + m)$ 时间、$O(1)$ 空间，是本题相对哈希法的优化点。

### 3.3 算法流程

```text
i = 0, j = 0
while i < n 且 j < m:
    if nums1[i] == nums2[j]: return nums1[i]
    elif nums1[i] < nums2[j]: i += 1
    else: j += 1
return -1          # 任一数组耗尽仍无相遇，无公共值
```

### 3.4 示例演算

![示例演算：示例 2 的指针移动轨迹](images/bw96_q1_example_walkthrough.svg)

以示例 2（`nums1 = [1,2,3,6]`，`nums2 = [2,3,4,5]`）走一遍：

| 步骤 | $i$ | $j$ | 比较 | 动作 |
|------|-----|-----|------|------|
| 1 | 0（值 1） | 0（值 2） | $1 < 2$ | $i$ 右移 |
| 2 | 1（值 2） | 0（值 2） | $2 = 2$ | 返回 2 |

再看无解的示例 3（`nums1 = [1,3,5]`，`nums2 = [2,4,6]`）：

| 步骤 | $i$（值） | $j$（值） | 比较 | 动作 |
|------|------------|------------|------|------|
| 1 | 0（1） | 0（2） | $1 < 2$ | $i$ 右移 |
| 2 | 1（3） | 0（2） | $3 > 2$ | $j$ 右移 |
| 3 | 1（3） | 1（4） | $3 < 4$ | $i$ 右移 |
| 4 | 2（5） | 1（4） | $5 > 4$ | $j$ 右移 |
| 5 | 2（5） | 2（6） | $5 < 6$ | $i$ 右移，越界 |

指针全程没有相遇，`nums1` 耗尽，返回 $-1$——正是两数组"完全错开"的直观含义。

## 4. 算法细节

1. **不要二分套二分**：对每个 `nums1[i]` 在 `nums2` 里二分是 $O(n \log m)$，比双指针慢，且二分到重复值时还要向左找首个，容易写错。
2. **返回 `-1` 的时机**：任一指针越界即可停止——升序数组里，剩下元素都 $\ge$ 另一数组已越过的值，不可能再相遇。
3. **重复元素无需处理**：相等即返回，重复值天然被"首个相遇"覆盖，不影响最小性。
4. **$O(1)$ 空间**是双指针相对哈希集合的核心优势；若两数组是流式输入（不能随机访问之外还要求小内存），双指针更是唯一选择。
5. C++ 中 `.size()` 返回无符号数，`i < nums1.size()` 与负数比较会有符号转换陷阱，存成 `int n, m` 更稳。

## 5. 正确性证明

**引理 1（扫描不变量）**：设 $i^\ast$、$j^\ast$ 分别为最小公共值 $c$ 在两数组中的**首次出现**下标（若有公共值）。若公共值存在，则双指针扫描全程保持 $i \le i^\ast$ 且 $j \le j^\ast$。

**证明**：归纳。初始 $i = j = 0 \le i^\ast, j^\ast$。设某步 $i \le i^\ast$、$j \le j^\ast$。算法只在 $nums1[i] < nums2[j]$ 时移动 $i$，此时若 $i = i^\ast$，则 $c = nums1[i^\ast] < nums2[j] \le nums2[j^\ast] = c$（用 $j \le j^\ast$ 与升序），自相矛盾；故 $i < i^\ast$，移动后 $i + 1 \le i^\ast$ 成立。$j$ 的移动同理。而相等时算法立即返回，指针不会越过 $(i^\ast, j^\ast)$。∎

**定理**：双指针返回的值等于最小公共值；无公共值时返回 $-1$。

**证明**：（1）若扫描中出现 $nums1[i] = nums2[j] = v$ 并返回：由引理 1，此时 $i \le i^\ast$。反设存在更小的公共值 $c < v$，其首次出现下标 $i^\ast_c$ 满足 $nums1[i^\ast_c] = c < v = nums1[i]$，由升序得 $i^\ast_c < i \le i^\ast$，于是 $c$ 是公共值且首次出现下标 $< i^\ast$，与 $i^\ast$ 是**最小公共值的**首次出现矛盾（$c$ 更小）。故 $v$ 就是最小公共值。（2）若扫描结束无相遇：反设有公共值 $c$，其首次出现 $(i^\ast, j^\ast)$ 有效；由引理 1 指针始终保持 $i \le i^\ast$、$j \le j^\ast$，且当 $i = i^\ast$、$j = j^\ast$ 时 $nums1[i] = nums2[j]$ 必然触发返回——但指针在到达前，每步至少一个指针前进且不会越过 $i^\ast / j^\ast$（引理 1 保证），有限步后必然同时到达 $(i^\ast, j^\ast)$ 并返回，与"无相遇结束"矛盾。故无公共值，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。每轮循环至少一个指针前进 1，两指针各最多走完自己的数组。
- **空间**：$O(1)$。仅两个下标变量——比哈希集合法的 $O(n)$ 更优，也是本题"有序"条件兑换出来的红利。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int getCommon(vector<int>& nums1, vector<int>& nums2) {
        int i = 0, j = 0, n = nums1.size(), m = nums2.size();
        while (i < n && j < m) {
            if (nums1[i] == nums2[j]) return nums1[i];  // 两指针所指相等即最小公共值
            if (nums1[i] < nums2[j]) ++i;
            else ++j;
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def getCommon(self, nums1: list[int], nums2: list[int]) -> int:
        i = j = 0
        while i < len(nums1) and j < len(nums2):
            if nums1[i] == nums2[j]:
                return nums1[i]      # 两指针所指相等即最小公共值
            if nums1[i] < nums2[j]:
                i += 1
            else:
                j += 1
        return -1
```

> 💡 两份代码均通过官方示例（`2`、`2`）与无公共值、单元素相等、首尾元素相等边界，并与哈希集合求交集的独立实现做了 2 万组（C++）/ 1 万组（Python）含大量重复值与重叠的随机对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **两个数组都非空**（约束 $length \ge 1$），但**公共值可能不存在**——漏掉 `return -1` 会在循环自然退出时返回垃圾值。
2. **重复元素**：如 `nums1 = [2,2,3]`、`nums2 = [2,2]`，首次相遇即返回，最小性不受重复影响。
3. **指针移动条件写反**：`nums1[i] < nums2[j]` 时动的是 $i$（较小一侧）。写反会导致死循环（相错时谁都不动）或漏解。
4. **无符号比较陷阱**（C++）：`i < nums1.size()` 中若 $i$ 是 `int` 而被比较方是 `size_t`，极端情况会有转换告警；先取出 `int n = nums1.size()` 最稳。
5. **想用二分时的坑**：对重复值，`lower_bound` 命中后还要确认两侧都一致；且 $O(n\log m)$ 在 $n = m = 10^5$ 时约 $1.7 \times 10^6$ 次比较，虽能过但明显逊于双指针。
6. **别先去重**：`set_intersection` 式写法要先去重排序，多一层空间与时间，毫无必要。

**延伸思考**：双指针在有序数组上的本质是一个**合并搜索空间**的过程——把 $O(nm)$ 的二维配对空间压缩成 $O(n+m)$ 的阶梯路径，每一步排除的不是一个元素，而是"整行/整列"的候选（$nums1[i]$ 小于 $nums2[j]$ 及其右边所有元素，一次性排除 $nums1[i]$ 与它们全部的配对可能）。这一"批量排除"视角同样适用于有序矩阵搜索（LC 240 搜索二维矩阵 II）与归并类问题。若两数组长度悬殊（$n \ll m$），对每个小数组元素在大数组里二分的 $O(n \log m)$ 反而可能优于 $O(n + m)$——算法选择永远跟着数量级走。
