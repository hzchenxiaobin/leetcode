# LeetCode 最大子序列的分数 题解

## 1. 题目概述

- **标题 / 题号**：最大子序列的分数（#2542，medium）
- **链接**：https://leetcode.cn/problems/maximum-subsequence-score/
- **来源**：LeetCode 第 96 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、排序、堆（优先队列）

**题意**：给定长度均为 $n$ 的整数数组 `nums1`、`nums2` 和正整数 $k$。需要从 $\{0, 1, \dots, n-1\}$ 中选出大小为 $k$ 的下标子集 $S$，分数定义为

$$score(S) = \Big(\sum_{i \in S} nums1[i]\Big) \times \min_{i \in S} nums2[i]$$

返回所有选法中的**最大分数**。

**约束**：

- $n = nums1.length = nums2.length$，$1 \le n \le 10^5$
- $0 \le nums1[i], nums2[j] \le 10^5$
- $1 \le k \le n$

## 2. 示例

**示例 1（官方）**

```text
输入：nums1 = [1,3,3,2], nums2 = [2,1,3,4], k = 3
输出：12
解释：选下标 {0, 2, 3}：(1+3+2) × min(2,3,4) = 6 × 2 = 12，为四种选法中最大。
```

**示例 2（官方）**

```text
输入：nums1 = [4,2,3,1,1], nums2 = [7,5,10,9,6], k = 1
输出：30
解释：k = 1 时选单个下标，最优是 nums1[2] × nums2[2] = 3 × 10 = 30。
```

**示例 3（边界补充）**

```text
输入：nums1 = [0,0,0], nums2 = [0,0,0], k = 2
输出：0
解释：元素可以取 0，分数下界是 0；不存在负数。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有大小为 $k$ 的下标子集，$O\binom{n}{k}$ 种，$n = 10^5$ 直接爆炸。即便是 $k$ 小的场合也撑不住（$\binom{10^5}{2} \approx 5 \times 10^9$）。分数是"和 × 最小值"的乘积结构，两半互相牵制——想让"和"大就把 $nums1$ 大的全塞进来，但塞进来的元素会拉低 $nums2$ 的最小值。破局点是**固定其中一半**。

### 3.2 核心观察：枚举"谁是瓶颈"，瓶颈一旦固定，剩下的就是前 k 大

![核心观察：按 nums2 降序扫描，以当前元素为瓶颈](images/bw96_q3_sort_heap_model.svg)

最优解 $S^\ast$ 的 $\min nums2$ 一定由**某个具体下标** $\mu \in S^\ast$ 实现（并列时任取其一）。于是可以按"瓶颈是谁"分类枚举所有解：

- 固定瓶颈 $\mu$：分数 $= nums2[\mu] \times \sum_{i \in S} nums1[i]$，且 $S$ 必须满足两个条件——包含 $\mu$，且其余元素全部从 $\{j : nums2[j] \ge nums2[\mu]\}$ 里挑；
- 在候选集固定为"nums2 不小于瓶颈"的前提下，**和最大化就是取 $nums1$ 最大的 $k$ 个**（瓶颈本身若不在前 $k$ 大里也无妨，见证明的放缩方向）。

为了高效地枚举瓶颈，把下标按 $nums2$ **降序**排序后从左到右扫：扫到位置 $t$ 时，候选集恰好是"前 $t$ 个下标"（它们全满足 $nums2 \ge nums2[\text{当前}]$）。同时用一个**大小为 $k$ 的最小堆**维护候选集里 $nums1$ 最大的 $k$ 个值及其和：新元素入堆，堆超过 $k$ 就弹出最小的，弹出后总和即"当前候选集前 $k$ 大之和"。每个瓶颈位置 $O(\log k)$ 更新，全局 $O(n \log n)$。

### 3.3 算法流程

```text
1. order ← 按 nums2 降序排好的下标序列
2. 小顶堆 heap（存 nums1 值）、sum = 0、ans = 0
3. for i in order:
       heap.push(nums1[i]); sum += nums1[i]
       if heap.size > k: sum -= heap.top(); heap.pop()
       if heap.size == k: ans = max(ans, sum × nums2[i])
4. return ans
```

### 3.4 示例演算

![示例演算：示例 1 的堆内容与候选分数](images/bw96_q3_example_walkthrough.svg)

示例 1（`nums1 = [1,3,3,2]`，`nums2 = [2,1,3,4]`，$k = 3$）。按 $nums2$ 降序，扫描顺序为下标 $3 (4) \to 2 (3) \to 0 (2) \to 1 (1)$：

| 步骤 | 进入下标（瓶颈 $nums2$） | 堆内容（$nums1$ 值） | sum | 候选分数 |
|------|------|------|-----|----------|
| 1 | 3（4） | {2} | 2 | —（不足 $k$） |
| 2 | 2（3） | {2, 3} | 5 | — |
| 3 | 0（2） | {1, 2, 3} | 6 | $6 \times 2 = 12$ |
| 4 | 1（1） | {2, 3, 3}（压入 3 弹出 1） | 8 | $8 \times 1 = 8$ |

答案 $\max(12, 8) = 12$ ✓。注意第 4 步弹出的恰是新进入的 1——这正是"瓶颈元素可能被挤出去"的情形，候选分数 $8 \times 1$ 只是真实分数（对应集合 $\{2,3\}\cup\{1\}$ 中 $nums2$ 最小值 $\ge 1$）的下界，不会越过最优值。

## 4. 算法细节

1. **排序的键与顺序**：按 $nums2$ **降序**；相等时顺序无所谓（证明中用"最后一个进入的瓶颈元素"统一处理并列）。
2. **堆存 $nums1$ 的值即可**，不必存下标；需要下标信息的写法（如输出方案）才存 pair。
3. **先压后弹**：先把当前元素压入再判断超限弹出，保证"当前瓶颈一定进过堆"这一性质，证明里的两个放缩方向都依赖它。
4. **`sum` 与 `ans` 用 64 位**：$k \times 10^5 \times 10^5 = 10^{10}$ 级，`int` 必溢出；Python 无碍。
5. **`nums2` 可以为 0**：候选分数可能全是 0，`ans` 初值 0 正确（分数非负，因为 $nums1, nums2 \ge 0$）。
6. **$k = n$**：堆永远不满直到最后一步，最后一步给出唯一子集（全集）的分数，逻辑自然覆盖。

## 5. 正确性证明

记 $a_i = nums1[i]$，$b_i = nums2[i]$。设按 $b$ 降序的扫描顺序为 $o_1, o_2, \dots, o_n$，记 $v_t = b_{o_t}$（第 $t$ 个进入元素的 $b$ 值），$C_t = \{o_1, \dots, o_t\}$（已见候选集），$H_t$ 为第 $t$ 步后堆内元素（$C_t$ 中 $a$ 值最大的 $\min(t, k)$ 个），$S_t = \sum_{x \in H_t} x$。算法输出 $\text{ans} = \max_{t \ge k} S_t \cdot v_t$。

**引理 1（候选不超过最优）**：对每个 $t \ge k$，$S_t \cdot v_t \le OPT$。

**证明**：$H_t$ 是大小恰为 $k$ 的合法候选集（含于 $C_t$），设其在原问题中的真实分数为 $S_t \times \min_{i \in H_t} b_i$。由扫描顺序，$H_t \subseteq C_t$ 的每个元素的 $b$ 值都 $\ge v_t$，故 $\min_{i \in H_t} b_i \ge v_t$，真实分数 $\ge S_t \cdot v_t$。而真实分数是某个 $k$ 子集的分数，$\le OPT$。链起来即得。∎

**引理 2（最优能被某个候选追平）**：存在 $t$ 使 $S_t \cdot v_t \ge OPT$。

**证明**：取最优集 $S^\ast$，设 $\mu$ 是 $S^\ast$ 中 $b$ 值最小的下标（并列时任取），令 $t^\ast$ 为 $S^\ast$ 中**最后**进入扫描序列的元素所对应的步数（显然 $t^\ast \ge |C \cap \text{前缀}| \ge k$，且第 $t^\ast$ 步进入的元素属于 $S^\ast$，其 $b$ 值 $\ge b_\mu$）。此时 $S^\ast \subseteq C_{t^\ast}$，故堆内是 $C_{t^\ast}$ 中前 $k$ 大的 $a$ 值，其和 $S_{t^\ast} \ge \sum_{i \in S^\ast} a_i$（$S^\ast$ 只是 $C_{t^\ast}$ 的一个 $k$ 子集，堆取的是最大 $k$ 个）。于是

$$S_{t^\ast} \cdot v_{t^\ast} \ \ge\ \Big(\sum_{i \in S^\ast} a_i\Big) \cdot v_{t^\ast} \ \ge\ \Big(\sum_{i \in S^\ast} a_i\Big) \cdot b_\mu\ =\ OPT,$$

中间一步用 $v_{t^\ast} \ge b_\mu$（第 $t^\ast$ 步进入的元素在 $S^\ast$ 内，其 $b$ 不小于 $S^\ast$ 的最小值 $b_\mu$）且两因子均非负。∎

**定理**：算法输出等于 $OPT$。

**证明**：由引理 1，输出 $\le OPT$；由引理 2，输出 $\ge OPT$。两者夹逼即得。∎

> 💡 引理 2 里"取最后进入的元素"这一步是并列 $b$ 值的埋点：若取"瓶颈 $\mu$ 首次进入的步数"，与 $\mu$ 并列的 $S^\ast$ 元素可能还没进堆，堆和不足以放缩。改为"最后一个进来的"之后候选集必然罩住整个 $S^\ast$。

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$ 主导；随后 $n$ 次堆操作各 $O(\log k) \le O(\log n)$。
- **空间**：$O(n)$。下标数组 $O(n)$，堆 $O(k)$；Python 的 `sorted` 另需 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxScore(vector<int>& nums1, vector<int>& nums2, int k) {
        int n = nums1.size();
        vector<int> idx(n);
        for (int i = 0; i < n; ++i) idx[i] = i;
        sort(idx.begin(), idx.end(), [&](int a, int b) { return nums2[a] > nums2[b]; });

        priority_queue<int, vector<int>, greater<int>> pq;   // 维护已选 k 个 nums1 的最小堆
        long long sum = 0, ans = 0;
        for (int t = 0; t < n; ++t) {
            int i = idx[t];
            pq.push(nums1[i]);
            sum += nums1[i];
            if ((int)pq.size() > k) { sum -= pq.top(); pq.pop(); }
            if ((int)pq.size() == k)
                ans = max(ans, sum * nums2[i]);   // 以 nums2[i] 为瓶颈时的最优分数
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxScore(self, nums1: list[int], nums2: list[int], k: int) -> int:
        from heapq import heappush, heappop      # 保持只贴 class 本体
        order = sorted(range(len(nums1)), key=lambda i: -nums2[i])
        heap = []                                # 维护已选 k 个 nums1 的最小堆
        s = 0
        ans = 0
        for i in order:
            heappush(heap, nums1[i])
            s += nums1[i]
            if len(heap) > k:
                s -= heappop(heap)
            if len(heap) == k:
                ans = max(ans, s * nums2[i])     # 以 nums2[i] 为瓶颈时的最优分数
        return ans
```

> 💡 两份代码均通过官方示例（`12`、`30`）、$k = n$、全零数组、$2 \times 10^{10}$ 级溢出用例，并与"枚举全部 $k$ 子集"的暴力做了 4000 组（C++）/ 2500 组（Python）随机对拍（$n \le 10$，含大量并列 $nums2$），`mismatch = 0`；$n = 10^5$、$k = 5 \times 10^4$ 冒烟测试 C++ 约 9ms。

## 8. 边界情况与易错点

1. **乘积溢出**：$sum \le 10^5 \times 10^5 = 10^{10}$，再乘 $nums2$ 可达 $10^{15}$，C++ 必须 `long long`。
2. **瓶颈元素被弹出**：第 4 步演算中，压入后立刻被弹出是正常现象——此时候选分数是某真实集合分数的下界（引理 1 的放缩方向），不是 bug，不要为此加"强制保留当前元素"的特判（那样反而会漏解）。
3. **降序不是升序**：堆要跟着扫描方向配合——降序扫 $nums2$ 配**小顶堆**保留前 $k$ 大。若误用升序，候选集语义反转，样例都过不了。
4. **并列的 $nums2$**：排序不稳定没关系，引理 2 的证明专门处理了并列（取最后进入的元素做瓶颈步）。
5. **$k = 1$**：每步候选分数是"当前前缀里最大 $a$ × 当前瓶颈 $b$"，扫描完全程必然覆盖单点最优 $\max_i a_i b_i$——示例 2 中下标 2 最先进入（$b = 10$ 最大），第一步就记录 $3 \times 10 = 30$。
6. **$nums2$ 含 0**：分数可能为 0 但永远不会为负（元素非负），`ans` 初值 0 安全。
7. **`k == n`**：所有元素都要选，最后一步才凑满 $k$，直接得到全集分数，无需特判。
