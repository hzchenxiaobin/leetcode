# LeetCode 使数组中所有元素相等的最小操作数 II 题解

## 1. 题目概述

- **标题 / 题号**：使数组中所有元素相等的最小操作数 II（#2541，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-array-equal-ii/
- **来源**：LeetCode 第 96 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、数学

**题意**：给定两个长度均为 $n$ 的数组 `nums1`、`nums2` 和整数 $k$。一次操作是：选择两个下标 $i, j$，令 $nums1[i]$ 增加 $k$ 且 $nums1[j]$ 减少 $k$（"左手加 $k$、右手减 $k$"，总量守恒）。要求把 `nums1` 变成与 `nums2` 完全相同，返回**最少操作数**；做不到返回 $-1$。

**约束**：

- $2 \le n \le 10^5$
- $0 \le nums1[i], nums2[j] \le 10^9$
- $0 \le k \le 10^5$

## 2. 示例

**示例 1（官方）**

```text
输入：nums1 = [4,3,1,4], nums2 = [1,3,7,1], k = 3
输出：2
解释：
第 1 步：i = 2, j = 0 → nums1 = [1,3,4,4]
第 2 步：i = 2, j = 3 → nums1 = [1,3,7,1]
```

**示例 2（官方）**

```text
输入：nums1 = [3,8,5,2], nums2 = [2,4,1,6], k = 1
输出：-1
解释：总和不守恒（18 ≠ 13），无法相等。
```

**示例 3（边界补充）**

```text
输入：nums1 = [1,2], nums2 = [1,3], k = 0
输出：-1
解释：k = 0 时任何操作都不改变数组，只能判相等与否。
```

## 3. 解题思路

### 3.1 暴力思路

把"加 $k$ / 减 $k$"看成在数值网格上搜索：从 `nums1` 出发 BFS，每步尝试所有 $(i, j)$，直到与 `nums2` 相同。状态空间天文数字，不可行。退一步的"模拟直觉"是：反复挑一对"需要加的位置"与"需要减的位置"执行操作直到全部对齐——方向正确，但如何证明这是最少的、以及何时根本无解，需要把操作抽象成**量**的计算。

### 3.2 核心观察：差值向量只需要"配平"，操作次数由缺口总量决定

![核心观察：正差与负差的天平](images/bw96_q2_balance_model.svg)

令 $d_i = nums2[i] - nums1[i]$（目标与现状的差）。一次操作把某个 $d_i$ 减 $k$（那里的数加了 $k$）、某个 $d_j$ 加 $k$（那里的数减了 $k$）。于是：

- **可行性两道门槛**：
  1. 每个位置的改变量必须是 $k$ 的倍数——即 $k \mid d_i$ 对所有 $i$ 成立（$k = 0$ 时则要求所有 $d_i = 0$，即两数组本来就相等）；
  2. 操作不改变 $\sum nums1$，故必须 $\sum d_i = 0$，也就是**正差总和 = 负差绝对值总和**。
- **操作次数**：一次操作至多"填掉 $k$ 份缺口"（把某个正差位置削去 $k$）。正差总量折合 $pos = \sum_{d_i > 0} d_i / k$ 步，这是下界；而只要可行，就总能每步同时削一份正差、一份负差，恰好用 $pos$ 步收工——下界即答案。

### 3.3 算法流程

```text
pos = neg = 0
for i = 0 .. n-1:
    d = nums2[i] - nums1[i]
    if k == 0:
        if d != 0: return -1
        continue
    if d % k != 0: return -1
    steps = d / k
    if steps > 0: pos += steps
    else:        neg -= steps
if pos != neg: return -1
return pos
```

### 3.4 示例演算

![示例演算：示例 1 的差值配平过程](images/bw96_q2_example_walkthrough.svg)

**示例 1**：$d = [1-4,\ 3-3,\ 7-1,\ 1-4] = [-3, 0, +6, -3]$，$k = 3$。逐位检查：$-3, 0, 6, -3$ 都是 3 的倍数 ✓；$pos = 6/3 = 2$，$neg = 3/3 + 3/3 = 2$，$pos = neg$ ✓，返回 $2$。与官方两步方案对应：位置 2 缺 6（两步加），位置 0 与 3 各富余 3（各承接一步减）。

**示例 2**：$d = [-1, -4, -4, +4]$，$k = 1$。整除性全部满足，但 $pos = 4$、$neg = 9$，$pos \ne neg$（即 $\sum d = -5 \ne 0$），返回 $-1$。

**边界**：$nums1 = nums2$ 时所有 $d_i = 0$，$pos = neg = 0$，返回 $0$——即便 $k = 0$ 也正确。

## 4. 算法细节

1. **$k = 0$ 必须特判**：代码中做除法与取模之前先分流。$k = 0$ 时答案是"两数组相等 ? 0 : -1"。
2. **差值可达 $10^9$**，$d_i / k$ 累加后最大 $10^5 \times 10^9 = 10^{14}$，必须 `long long`（Python 天然大整数无碍）。
3. **负数取模**：判断 $k \mid d_i$ 用 $d \% k == 0$ 在 C++ 截断语义与 Python 取模语义下都正确（能整除时余数必为 0）；整除后的商也是精确值。
4. **不要把答案写成 $\max(pos, neg)$ 或 $(pos+neg)/2$ 之外的花样**：可行时必有 $pos = neg$，答案就是 $pos$；不可行时这两个等价写法可能"碰巧"给出正数，掩盖 $-1$ 判定。
5. **操作允许 $i = j$ 吗**：无所谓——$i = j$ 是空操作；只要 $pos > 0$ 必同时存在正差与负差位置（$n \ge 2$ 且 $pos = neg > 0$），能取到 $i \ne j$。
6. **一次只挪 $k$、不要合并挪**：题目每步固定 $k$，不能一次挪 $2k$；所以答案按 $k$ 为单位折算，而不是按差值绝对值总和折半。

## 5. 正确性证明

**引理 1（可行性的必要条件）**：若 `nums1` 能变为 `nums2`，则 (a) $\sum_i d_i = 0$；(b) $k > 0$ 时对每个 $i$ 有 $k \mid d_i$（$k = 0$ 时每个 $d_i = 0$）。

**证明**：一次操作使 $\sum nums1$ 变化 $(+k) + (-k) = 0$，故任意步后总和不变，$\sum nums1 = \sum nums2$，即 $\sum d_i = 0$。又每个下标的值每次变化 $\pm k$，最终 $nums1[i] = nums2[i]$ 说明 $d_i$ 是若干个 $\pm k$ 的代数和，即 $k$ 的倍数；$k = 0$ 时"每次变化为零"迫使 $d_i = 0$。∎

**引理 2（操作次数下界）**：设可行且 $k > 0$。定义势函数 $\Phi = \sum_i |nums1[i] - nums2[i]| = \sum_i |d_i|$。任何一次操作至多使 $\Phi$ 减少 $2k$，故操作数 $\ge \dfrac{\Phi_0}{2k} = \dfrac{\sum_{d_i>0} d_i}{k} = pos$。

**证明**：一次操作只改变两个下标的值，每个下标对 $\Phi$ 的贡献每次至多减少 $k$（加 $k$ 恰好逼近目标时）——若该下标的"新值更接近目标"则贡献减少 $k$，否则增加或不变；两个下标合计变化 $\ge -2k$（其他下标不变）。初始 $\Phi_0 = \sum |d_i| = \sum_{d_i>0} d_i + \sum_{d_i<0} (-d_i) = 2\sum_{d_i>0} d_i = 2k \cdot pos$（末等号用引理 1 的 $\sum d_i = 0$ 与 $k \mid d_i$）。终止时 $\Phi = 0$，故操作数 $\times 2k \ge \Phi_0$。∎

**定理**：算法返回的值恰为最少操作数（不可行时为 $-1$）。

**证明**：可行性由引理 1 判定；仅需再证可行时 $pos$ 步足够。构造：只要仍有未配平的下标，由 $\sum d_i = 0$ 且存在正差，必同时存在正差下标 $i$（$nums1[i] < nums2[i]$，且 $d_i \ge k$）与负差下标 $j$（$nums1[j] > nums2[j]$，且 $-d_j \ge k$；两者由"$d$ 全为 $k$ 的倍数且不为 0"保证），取 $i \ne j$ 执行操作"$i$ 加 $k$、$j$ 减 $k$"。归纳可知每步后各 $d$ 仍为 $k$ 的倍数且总和为 0；每步使 $d_i$ 与 $-d_j$ 各减少 $k$，$\Phi$ 恰减 $2k$。经 $pos$ 步后 $\Phi = \Phi_0 - 2k \cdot pos = 0$，即两数组相等。结合引理 2 的下界，$pos$ 是最少操作数。$k = 0$ 时引理 1 已给出答案为 0（相等）或 $-1$。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次遍历，每步常数次整除与取模。
- **空间**：$O(1)$。只维护 `pos`、`neg` 两个累加量，不需要真的改动数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minOperations(vector<int>& nums1, vector<int>& nums2, int k) {
        long long pos = 0, neg = 0;                 // 需要增加 / 减少的总步数（以 k 为单位）
        for (int i = 0; i < (int)nums1.size(); ++i) {
            long long d = (long long)nums2[i] - nums1[i];
            if (k == 0) {
                if (d != 0) return -1;              // 无法做任何改变
                continue;
            }
            if (d % k != 0) return -1;              // 差距不是 k 的倍数，永远补不平
            long long steps = d / k;
            if (steps > 0) pos += steps;
            else neg -= steps;
        }
        if (pos != neg) return -1;                  // 总增量和总量必须守恒
        return pos;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums1: list[int], nums2: list[int], k: int) -> int:
        pos = neg = 0                 # 需要增加 / 减少的总步数（以 k 为单位）
        for a, b in zip(nums1, nums2):
            d = b - a
            if k == 0:
                if d != 0:
                    return -1         # 无法做任何改变
                continue
            if d % k != 0:
                return -1             # 差距不是 k 的倍数，永远补不平
            steps = d // k
            if steps > 0:
                pos += steps
            else:
                neg -= steps
        return pos if pos == neg else -1
```

> 💡 两份代码均通过官方示例（`2`、`-1`）、$k=0$ 的两种情形、$10^9$ 级溢出敏感用例，并与"逐步 BFS 模拟所有操作"的暴力（坐标限制在值域包络内）做了 800 组（C++）/ 400 组（Python）随机对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$k = 0$ 是第一陷阱**：直接做除法会除零崩溃；此时答案是 `nums1 == nums2 ? 0 : -1`。
2. **溢出**：$\sum |d_i| / k$ 可达 $10^{14}$，C++ 用 `long long`；注意 $d_i$ 本身就到 $\pm 10^9$，先转 64 位再做减法。
3. **漏判守恒**：只检查了整除性、忘记 $\sum d_i = 0$，会输出错误正数。示例 2 正是专为此设的（整除全过、和不守恒）。
4. **负数取模语义**：C++ 中 $-6 \% 3 = 0$ 没问题，但 $-7 \% 3 = -1 \ne 0$ 正确判负；Python 中 $-7 \% 3 = 2 \ne 0$ 同样正确。两语言判"整除"都安全，但**取模后直接当步数用**就不安全了，务必先判整除再做除法。
5. **答案是 $pos$ 不是 $\max(pos, neg)$**：可行时两者相等，但若漏了 `pos != neg → -1` 的判定，等价写法会把不可行误判成功。
6. **两个下标必须不同吗**：题目说"选择两个下标 $i$ 和 $j$"，即便要求 $i \ne j$，$n \ge 2$ 且可行时总能配对成功，无需特判。
7. **全部相等但 $k$ 很大**：答案 0 与 $k$ 无关，代码天然正确（循环里所有 $d = 0$）。

**延伸思考**：本题的骨架是**运输问题（transportation）**的一维最简形态：每个位置有供给（负差）或需求（正差），一次操作把 $k$ 单位货物从供给方运到需求方，最小车次数就是"总需求量 ÷ 车容量"。势函数下界（每步 $\Phi$ 至多降 $2k$）+ 显式构造（配对运输）是此类"计数型贪心"的标准证明套路。如果允许的操作变成"选一个区间同时 $+k$"或"$i, j$ 必须相邻"，问题就滑向差分数组或图上运输，但"可行性 = 整除 + 守恒，答案 = 缺口总量"这两步判断依然是分析的第一反应。
