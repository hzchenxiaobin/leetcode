# LeetCode 统计计算机解锁顺序排列数 题解

## 1. 题目概述

- **标题 / 题号**：统计计算机解锁顺序排列数（#3577，medium）
- **链接**：https://leetcode.cn/problems/count-the-number-of-computer-unlocking-permutations/
- **来源**：LeetCode 第 453 场周赛 Q2
- **难度**：中等
- **标签**：脑筋急转弯、数组、数学、组合数学

**题意**：房间里有 $n$ 台**上锁**的计算机，编号 $0$ 到 $n-1$，编号 $i$ 的密码复杂度为 $complexity[i]$。解锁规则：要解锁编号 $i$ 的计算机，必须先有一台**已解锁**的编号 $j$，满足 $j < i$ 且 $complexity[j] < complexity[i]$。编号 $0$ 的计算机初始已解锁（根）。求 $[0, 1, \cdots, n-1]$ 的排列中有多少个能表示「从 0 号机开始把所有计算机全部解锁」的有效顺序，答案对 $10^9 + 7$ 取余。

**约束**：

- $2 \le n = \text{complexity.length} \le 10^5$
- $1 \le complexity[i] \le 10^9$

> ⚠️ **读题陷阱**：初始已解锁的是**编号 0** 的那台计算机（按下标固定），而**不是**排列中第一个位置上的那台——不能把排列的首元素当成「免费的根」。排列记录的是各台机器**依次变为已解锁**的时间线，0 号机在一切解锁动作之前就被根密码解锁，因此**必然排第一**（示例 1 的解释「首先使用根密码解锁计算机 0」正是此意）。

> 💡 **读题关键**：别急着把「排列」当成搜索对象。先把「什么样的排列合法」翻译成两条结构性质——**谁必须排第一**、**解锁链上复杂度如何变化**——计数就会坍缩成一个 $O(n)$ 的判定。

## 2. 示例

**示例 1**

```text
输入：complexity = [1,2,3]
输出：2
解释：有效排列是 [0,1,2] 和 [0,2,1]——先用根密码解锁 0 号机；
      之后每台机器都由「编号更小且复杂度更小」的已解锁机器解锁。
```

**示例 2**

```text
输入：complexity = [3,3,3,4,4,4]
输出：0
解释：不存在任何有效排列——解锁 1 号机只能靠 j = 0，而 3 < 3 不成立。
```

**示例 3**（自构造，展示「乱序也合法」）

```text
输入：complexity = [2,5,3,7]
输出：6
解释：c[0] = 2 严格最小，3! = 6。连 [0,3,1,2] 这种「乱序」也合法：
      3、1、2 号机每台都能随时由 0 号机（c=2）解锁。
```

**示例 4**（自构造，展示「最小值不在 0 号位」）

```text
输入：complexity = [3,5,2,7]
输出：0
解释：c[2] = 2 < c[0] = 3，解锁 2 号机需要某台 c < 2 的机器，不存在。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $n!$ 个排列逐一模拟验证：第一个位置必须是 $0$；此后每台 $i$ 要求排列中**更早出现**过某台 $j$，满足 $j < i$ 且 $complexity[j] < complexity[i]$。单个排列的验证是 $O(n)$，但 $n!$ 本身就是天文数字，$n \le 10^5$ 下完全不可行——出路不是优化枚举，而是发现**答案只有两个可能取值**。

### 3.2 核心观察：答案非 $(n-1)!$ 即 $0$

![核心观察：解锁链复杂度严格递增，根必须严格唯一最小](images/wc453_q2_unlock_chain.svg)

**观察一（首位锁定）**：合法排列的第一个位置必然是 $0$。排列是各台机器「依次变为已解锁」的时间线，开局唯一可用的是根密码，而它解锁的正是 0 号机（题面「注意」排除了把首元素当根的误读）。于是计数的自由度只剩后 $n-1$ 个位置，**至多 $(n-1)!$ 种**。

**观察二（单调引理）**：任何被解锁的机器，复杂度必严格大于 $complexity[0]$。对解锁顺序做归纳：第一台被解锁的是 0 号机本身；此后每台 $i$ 都由某台更早解锁的 $j$ 解锁，要求 $complexity[j] < complexity[i]$——若 $j = 0$，直接得 $complexity[i] > complexity[0]$；若 $j \ne 0$，由归纳假设 $complexity[j] > complexity[0]$，传递下去依然 $complexity[i] > complexity[0]$。换言之，**解锁链从根出发，每一步复杂度严格递增**。

两条观察合起来，答案只剩两种情形：

- **存在 $i \ge 1$ 使 $complexity[i] \le complexity[0]$**（0 号机不是严格唯一的最小值）：由单调引理，这台机器**永远无法被解锁**，任何排列都非法，答案为 $0$。示例 2 正是如此——1 号机与 0 号机并列最小（$3 = 3$），解锁 1 号机只能靠 $j = 0$，而 $3 < 3$ 不成立。
- **$complexity[0]$ 是严格唯一最小值**：0 号机排第一后，任何一台 $i$ 在**任意时刻**都能由 0 号机单独解锁（$0 < i$ 且 $complexity[0] < complexity[i]$），后 $n-1$ 个位置**怎么排都合法**，恰好 $(n-1)!$ 种。

$$
\text{answer} =
\begin{cases}
(n-1)! \bmod (10^9+7), & complexity[0] < \min\limits_{i \ge 1} complexity[i] \\[4pt]
0, & \text{否则}
\end{cases}
$$

### 3.3 算法流程

![算法流程图](images/wc453_q2_flow.svg)

整个算法 = 一趟线性扫描做判定（遇到 $complexity[i] \le complexity[0]$ 立即返回 $0$）+ 一个 $n-1$ 步的阶乘累乘循环，乘法每一步取模。

### 3.4 示例演算

![示例演算：首位锁定 0、其余自由排列与死锁情形](images/wc453_q2_walkthrough.svg)

- $complexity = [1,2,3]$：$c[0]=1$ 严格最小 $\Rightarrow$ $2! = 2$，正是 $[0,1,2]$ 与 $[0,2,1]$；首位非 $0$ 的 $4$ 个排列一律不计。
- $complexity = [2,5,3,7]$：$c[0]=2$ 严格最小 $\Rightarrow$ $3! = 6$，$[0,3,1,2]$ 等「乱序」也合法——每台机器都能随时由 0 号机解锁。
- $complexity = [3,3,3,4,4,4]$：$c[1]=3 \le c[0]=3$（**并列也算失败**，严格小于！）$\Rightarrow$ $0$。
- $complexity = [3,5,2,7]$：$c[2]=2 < c[0]=3$，全局最小不在 0 号位 $\Rightarrow$ $0$。

## 4. 算法细节

1. **判定的三种等价写法**：$\forall i \ge 1: c[i] > c[0]$；或 $c[0]$ 是全局最小**且只出现一次**；或 $\min(c[1..n-1]) > c[0]$。注意必须**严格**大于——并列最小（示例 2 的 $3 = 3$）同样锁死。
2. **判定与计数可一趟完成**：扫描 $i = 1 \dots n-1$，一旦发现 $c[i] \le c[0]$ 立即 `return 0`；扫完全程再累乘 $(n-1)!$。也可先 `min_element` 判定再算阶乘，两趟 $O(n)$ 同价。
3. **阶乘取模**：$n$ 到 $10^5$，$(n-1)!$ 是天文数字，必须边乘边 `mod`。本题只乘不除，**无需乘法逆元**，也不用预处理阶乘表。
4. **溢出处理**：C++ 中 `ans * k` 最大约 $10^9 \times 10^5 = 10^{14}$，用 `long long` 中转即可安全落在 64 位范围内；Python 原生大整数无此虑，但同样要逐步取模防止数字膨胀拖慢速度。
5. **编号约束 $j < i$ 是烟雾弹**：观察二的归纳证明只用到「解锁者复杂度更小且已被解锁」，完全没碰 $j < i$。决定答案的只有「根 + 链上复杂度严格递增」这一结构——这也是本题被归为脑筋急转弯的原因：看似图论/拓扑序计数，实为一行判定。
6. **为什么根必须是 0 号机**：解锁 $i$ 只能靠 $j < i$，若换任何 $r > 0$ 号机当根，编号 $< r$ 的机器将永远无人能解——题目「0 号机当根」是唯一自洽的设定，顺带解释了观察一的必然性。

## 5. 正确性证明

**引理 1（首位锁定）**：任何有效排列必以 $0$ 开头；故有效排列总数不超过 $(n-1)!$。

**证明**：排列按题意记录 $n$ 台计算机依次变为已解锁的时间顺序。0 号机在一切解锁动作之前由根密码解锁（唯一初始解锁者），故其解锁时刻最早，必居首位。「注意」澄清初始解锁的固定是编号 0 的机器而非排列首元素，故首位为其他机器的排列不表示任何合法时间线。首位确定后，其余 $n-1$ 个位置至多自由排列 $(n-1)!$ 种。∎

**引理 2（单调引理）**：在有效排列 $p$ 中，对每个位置 $t \ge 1$ 都有 $complexity[p[t]] > complexity[0]$。

**证明**：对 $t$ 归纳。$t = 1$：此时已解锁集合仅 $\{p[0]\} = \{0\}$，解锁 $p[1]$ 必须由 $j = 0$ 提供，规则要求 $complexity[0] < complexity[p[1]]$。$t \ge 2$：$p[t]$ 由某台 $p[s]$（$s < t$）解锁，要求 $complexity[p[s]] < complexity[p[t]]$；若 $s = 0$ 即得结论，若 $s \ge 1$ 由归纳假设 $complexity[p[s]] > complexity[0]$，传递得 $complexity[p[t]] > complexity[0]$。∎

**推论**：若存在 $i \ge 1$ 使 $complexity[i] \le complexity[0]$，则答案为 $0$。

**证明**：反设存在有效排列 $p$。机器 $i$ 必出现在 $p$ 中某位置 $t \ge 1$（首位被 0 占据），由引理 2 需 $complexity[i] > complexity[0]$，与前提矛盾。∎

**定理（答案刻画）**：当且仅当 $complexity[0] < complexity[i]$ 对所有 $i \ge 1$ 成立时，答案恰为 $(n-1)! \bmod (10^9+7)$；否则答案为 $0$。

**证明**：「否则」的情形已由推论覆盖。设 $complexity[0]$ 为严格唯一最小值。由引理 1，有效排列必形如 $[0, \ast, \cdots, \ast]$，总数不超过 $(n-1)!$。反过来，任取 $0$ 开头的排列 $p$：对每个 $t \ge 1$，取 $s = 0$，则 $p[s] = 0 < p[t]$（因 $p[t] \ge 1$）且 $complexity[0] < complexity[p[t]]$（严格唯一最小），解锁条件满足，故 $p$ 有效。因此有效排列与「$0$ 开头的排列」一一对应，恰为 $(n-1)!$ 个；对 $10^9+7$ 取模即得返回值。∎

> 💡 上述刻画已用暴力对拍验证：$n \le 6$、值域 $\{1,2,3\}$ 的**全部**数组（穷举 $n!$ 个排列逐一模拟），加上 300 组随机用例与全部官方/自构造示例，公式输出与暴力计数完全一致。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟判定扫描（每步 $O(1)$ 比较）+ $n-1$ 步阶乘累乘（每步一次乘法取模），总共两趟线性遍历。
- **空间复杂度**：$O(1)$。只维护答案与循环变量，原地读数组，不复制、不排序。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int countPermutations(vector<int>& complexity) {
        const long long MOD = 1'000'000'007;
        int n = complexity.size();
        for (int i = 1; i < n; ++i)
            if (complexity[i] <= complexity[0]) return 0;  // 根必须严格唯一最小
        long long ans = 1;
        for (int k = 1; k <= n - 1; ++k) ans = ans * k % MOD;  // (n-1)! 边乘边模
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countPermutations(self, complexity: List[int]) -> int:
        MOD = 10**9 + 7
        if any(c <= complexity[0] for c in complexity[1:]):
            return 0                        # 根必须严格唯一最小
        ans = 1
        for k in range(1, len(complexity)): # (n-1)! 边乘边模
            ans = ans * k % MOD
        return ans
```

> 💡 两份代码都是「一趟判定 + 一趟累乘」；判定循环从 $i = 1$ 开始，别拿 $c[0]$ 跟自己比较。

## 8. 边界情况与易错点

1. **并列最小也是 $0$**：判定必须用严格小于。$c = [3,3,3,4,4,4]$ 中 $c[1] = c[0]$，1 号机同样锁死（解锁它需要 $3 < 3$）。写成 `$c[i] < c[0]$` 才返回 0 是经典 WA。
2. **「排列首位自动解锁」误读**：题面「注意」专门为此设卡——初始解锁的是编号 0 那台机器，与谁排在首位无关；据此把 $[1,0,2]$ 之类计入答案（对示例 1 报 $6$ 或 $4$）是本陷阱的标准错法。
3. **顺着 $j < i$ 想成拓扑序 / 建图 DFS**：$n \le 10^5$ 与答案只有两个取值都在提示这是判定题而非计数搜索；引理 2 的证明压根用不到编号约束。
4. **阶乘不取模直接算**：$n = 10^5$ 时 $(n-1)!$ 约有 $45$ 万位数字，C++ 中任何整型都存不下，Python 不取模也会慢到超时——必须边乘边 `mod`。
5. **C++ 中途用 `int` 乘**：`ans * k` 未取模时约 $10^{14}$，超出 `int` 范围；先落 `long long` 再取模。
6. **最小情形 $n = 2$**：$c = [1,1] \Rightarrow 0$；$c = [1,2] \Rightarrow 1! = 1$（仅 $[0,1]$）。
7. **全局最小不在 0 号位**：如 $[3,5,2,7]$，不要误以为「找到全局最小值的下标再讨论」——只需盯住 $c[0]$ 与其余的大小关系。
