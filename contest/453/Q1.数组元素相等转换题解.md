# LeetCode 数组元素相等转换 题解

## 1. 题目概述

- **标题 / 题号**：数组元素相等转换（#3576，medium）
- **链接**：https://leetcode.cn/problems/transform-array-to-all-equal-elements/
- **来源**：LeetCode 第 453 场周赛 Q1
- **难度**：中等
- **标签**：贪心、数组

**题意**：给定长度为 $n$、只含 $1$ 和 $-1$ 的整数数组 `nums` 与整数 $k$。一次操作可选择下标 $i$（$0 \le i < n-1$），将 `nums[i]` 与 `nums[i+1]` **同时乘以 $-1$**；同一下标可在不同操作中被多次选择。若**至多 $k$ 次**操作后能使数组**所有元素相等**，返回 `true`，否则返回 `false`。

**约束**：

- $1 \le n = \text{nums.length} \le 10^5$
- `nums[i]` 的值为 $-1$ 或 $1$
- $1 \le k \le n$

> 💡 **读题关键**：值域只有 $\pm 1$，「全部相等」只有两个候选目标——**全变 1** 或 **全变 $-1$**；操作固定翻转**相邻两个**元素，天然携带「乘积不变量」与「从左往右传导」两个性质。抓住这两点，签到题也能写出带证明的严谨解法。

## 2. 示例

**示例 1**

```text
输入：nums = [1,-1,1,-1,1], k = 3
输出：true
解释：选 i=1 翻转得 [1,1,-1,-1,1]；再选 i=2 翻转得 [1,1,1,1,1]，2 次即可。
```

**示例 2**

```text
输入：nums = [-1,-1,-1,1,1,1], k = 5
输出：false
解释：-1 有 3 个（奇数）⇒ 全变 1 不可达；1 有 3 个（奇数）⇒ 全变 -1 也不可达，
      乘积不变量把两个目标全灭了。
```

**示例 3**（自构造，展示「两个目标都要算」）

```text
输入：nums = [-1,1,1,-1,1,1], k = 2
输出：true
解释：全变 1 需 3 次（失配位 0、3 相距 3）；全变 -1 只需 2 次
      （失配位 1,2 与 4,5 各配一对，各花 1 次）——失配更多的目标反而更省。
```

## 3. 解题思路

### 3.1 暴力思路

把每种数组形态看作一个状态、每种操作看作一条边（共 $n-1$ 条），BFS 求到达任一全等状态的最短步数，再与 $k$ 比较。但状态数最坏 $2^n$（$n = 10^5$ 时天文数字），且同一下标可重复选择导致环极多。必须换视角：**目标只有两个，操作高度局部化**——分别求「变成每个目标的最少操作数」即可。

### 3.2 核心观察：目标坍缩 + 失配右推贪心

![三个观察：目标坍缩、乘积不变量、失配右推](images/wc453_q1_mismatch_push.svg)

**观察一（目标坍缩）**：值域是 $\{\pm 1\}$，全等数组只能是全 $1$ 或全 $-1$。分别求最少操作数 $\text{ops}_1$、$\text{ops}_2$，任一 $\le k$ 即 `true`。

**观察二（乘积不变量 ⇒ 可行性）**：操作同时翻转**两个**元素，数组总乘积不变。全 $1$ 的乘积为 $+1$，故「全变 1」可行当且仅当 $-1$ 的个数为**偶数**；同理「全变 $-1$」需要 $1$ 的个数为偶数。等价表述：相对目标的**失配位置必须两两成对**。

**观察三（失配右推 ⇒ 最少操作数）**：从左到右扫描，设左侧已全部对齐目标。若当前位置 $i$ 失配，能修它的只有「操作 $i$」与「操作 $i-1$」；而操作 $i-1$ 会翻转已对齐的 $i-1$，等于把失配**左移**，纯属性浪费。于是**操作 $i$ 被迫执行**：它修好 $i$，却顺带翻转 $i+1$——失配被**右推**。失配像粒子一路向右漂移，每推一格花一次操作，直到撞上后面那个失配，**双双湮灭**。由此得到闭式刻画：设相对目标的失配位置为 $p_1 < p_2 < \dots < p_{2m}$（失配数必为偶），则

$$\text{最少操作数} = \sum_{j=1}^{m} \left( p_{2j} - p_{2j-1} \right)$$

即**相邻失配两两配对的距离之和**。失配数为奇时扫描到末位必然剩一个修不掉，该目标不可达。

### 3.3 算法流程

![算法流程图](images/wc453_q1_flow.svg)

对两个目标各跑一趟 $O(n)$ 贪心扫描：维护操作数 `ops` 与「连带翻转」标记 `flipped`（当前位置是否已被操作 $i-1$ 翻转），得 $\text{ops}_1$、$\text{ops}_2$（不可达记 $\infty$），$\min(\text{ops}_1, \text{ops}_2) \le k$ 即返回 `true`。

### 3.4 示例演算

![示例演算：失配右推两步湮灭与双目标对比](images/wc453_q1_walkthrough.svg)

**示例 1** `nums = [1,-1,1,-1,1]`，$k=3$，目标全 $1$（失配位 1、3）：

| 步骤 | 数组状态 | 说明 |
|------|----------|------|
| 初始 | $[1, \underline{-1}, 1, -1, 1]$ | 位 1 失配 |
| 操作 1 | $[1, 1, \underline{-1}, -1, 1]$ | 修好位 1，失配右推给位 2 |
| 操作 2 | $[1, 1, 1, 1, 1]$ | 修好位 2 的同时修好位 3——两个失配一次湮灭 |

共 2 次 $\le 3$ → `true`。目标全 $-1$ 的失配位为 $0,2,4$（3 个，奇数），不可达。

**示例 3** `nums = [-1,1,1,-1,1,1]`，$k=2$，两个目标对比：

| 目标 | 失配位置 | 配对 | 最少操作数 | 判定 |
|------|----------|------|-----------|------|
| 全 $1$ | $0,\ 3$ | $(0,3)$ | $3-0 = 3$ | $3 > 2$ ✗ |
| 全 $-1$ | $1,\ 2,\ 4,\ 5$ | $(1,2),\ (4,5)$ | $1+1 = 2$ | $2 \le 2$ ✓ |

失配更多的目标反而更省——**只试「变成多数派」是经典 WA**，两个目标必须都算。

## 4. 算法细节

1. **`flipped` 标记的语义**：扫描到位置 $i$ 时，`flipped` 表示 $i$ 已被「操作 $i-1$」连带翻转，读取当前值须取反。这正是奇偶递推 $f_i = f_{i-1} \oplus m_i$（$m_i = [\text{nums}[i] \ne T]$，$f_i$ 为操作 $i$ 执行次数的奇偶）的代码化。
2. **转移规则**：当前值 $\ne$ target ⇒ 操作 $i$ 被迫执行，`ops++`、`flipped = true`（失配右推给 $i+1$）；当前值 $=$ target ⇒ 不操作，`flipped = false`（$i+1$ 不被连带）。
3. **末位失配 = 不可达**：$i = n-1$ 时已无操作可用，仍失配说明失配数为奇（乘积不变量破坏），该目标记 $\infty$。
4. **两个目标都要算**：$n$ 为奇数时 $c$ 与 $n-c$ 奇偶相反，恰好只有一个目标可行；$n$ 为偶数时二者**同生共死**（同时可行或同时不可行），但代价可能差很多（见 3.4 示例 3）。
5. **可选剪枝**：先数一遍 $-1$ 的个数做奇偶预判，两个目标都不可达直接 `false`，省去扫描。本题量级下无所谓，但「先说不变量再给贪心」是面试的好层次。
6. **免模拟的闭式实现**：一次遍历收集失配位置到列表，隔位作差累加即得最少操作数，与扫描版等价。

## 5. 正确性证明

设 $f_i$ 为下标 $i$ 被选择的次数（$0 \le i \le n-2$，约定 $f_{-1} = f_{n-1} = 0$）。位置 $i$ 的最终值为 $\text{nums}[i] \cdot (-1)^{f_{i-1} + f_i}$。记 $m_i = [\text{nums}[i] \ne T]$ 为相对目标 $T$ 的失配指示。

**引理 1（奇偶表征）**：最终数组只由 $(f_0 \bmod 2, \dots, f_{n-2} \bmod 2)$ 决定；总操作数 $\sum_i f_i \ge \#\{i : f_i \text{ 为奇}\}$，取等当且仅当每个下标至多选择一次。

**证明**：$(-1)^{f}$ 只依赖 $f$ 的奇偶，故最终数组只由奇偶向量决定；奇数 $f_i \ge 1$，求和即得下界，且每个 $f_i \in \{0,1\}$ 时取等。∎

**引理 2（可行判据）**：目标 $T$ 可达 $\iff$ 失配数 $m(T) = \sum_i m_i$ 为偶数。

**证明**：全变 $T$ 等价于对所有 $i$ 成立 $f_{i-1} + f_i \equiv m_i \pmod 2$。从 $i = 0$ 出发唯一递推：$f_0 = m_0$，$f_i = m_i \oplus f_{i-1}$，故奇偶向量（若存在）必唯一。相容性条件只在末位：需 $f_{n-2} = m_{n-1}$，而递推给出 $f_{n-2} = m_0 \oplus m_1 \oplus \cdots \oplus m_{n-2}$，两者合并即 $\bigoplus_{i=0}^{n-1} m_i = 0$，亦即 $m(T)$ 为偶。（这与乘积不变量给出的必要条件一致，且说明该条件也是充分的。）∎

**定理（贪心最优）**：若 $m(T)$ 为偶，贪心扫描输出的操作数恰为 $\#\{i \le n-2 : f_i = 1\} = \sum_j (p_{2j} - p_{2j-1})$，是达成目标 $T$ 的最少操作数。

**证明**：由引理 2，达成目标的方案的奇偶向量唯一，就是上述递推的解；由引理 1，任何方案的操作数 $\ge \#\{i : f_i = 1\}$。贪心扫描中 `flipped` 的转移恰是递推 $f_i = m_i \oplus f_{i-1}$，且对每个 $f_i = 1$ 的下标恰执行一次操作、$f_i = 0$ 的下标不执行，达到下界。而 $f_i = 1$ 的下标集合正是区间 $[p_1, p_2 - 1], [p_3, p_4 - 1], \dots$ 的并，计数即配对距离和。∎

**推论**：算法返回 `true` $\iff \min\limits_{T \in \{1, -1\}} \text{ops}(T) \le k$（不可达目标记 $\infty$）。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。两个目标各一趟线性扫描，每步 $O(1)$ 判断与转移；闭式实现同样 $O(n)$。
- **空间复杂度**：$O(1)$。只维护 `ops` 与 `flipped` 两个变量，不复制数组（闭式实现若收集失配位置列表则为 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool canMakeEqual(vector<int>& nums, int k) {
        int n = nums.size();
        // 对指定目标求最少操作数；不可达返回 -1
        auto minOps = [&](int target) -> int {
            int ops = 0;
            bool flipped = false;              // nums[i] 是否已被操作 i-1 连带翻转
            for (int i = 0; i < n; ++i) {
                int v = flipped ? -nums[i] : nums[i];
                if (v != target) {
                    if (i == n - 1) return -1; // 末位失配：失配数为奇，不可达
                    ++ops;                     // 操作 i 被迫执行
                    flipped = true;            // 失配右推给 i+1
                } else {
                    flipped = false;           // 不操作，i+1 不被连带
                }
            }
            return ops;
        };
        int a = minOps(1), b = minOps(-1);
        return (a >= 0 && a <= k) || (b >= 0 && b <= k);
    }
};
```

### Python

```python
class Solution:
    def canMakeEqual(self, nums: List[int], k: int) -> bool:
        n = len(nums)

        def min_ops(target: int) -> int:       # 不可达返回 -1
            ops, flipped = 0, False            # flipped：nums[i] 已被操作 i-1 连带翻转
            for i, x in enumerate(nums):
                v = -x if flipped else x
                if v != target:
                    if i == n - 1:
                        return -1              # 末位失配：失配数为奇，不可达
                    ops += 1                   # 操作 i 被迫执行
                    flipped = True             # 失配右推给 i+1
                else:
                    flipped = False            # 不操作，i+1 不被连带
            return ops

        a, b = min_ops(1), min_ops(-1)
        return (0 <= a <= k) or (0 <= b <= k)
```

> 💡 上述贪心已用 BFS 对拍验证：$n \le 7$ 的全部 $2^n$ 种数组 × 全部 $k$ 组合，贪心输出与 BFS 最短路完全一致。

## 8. 边界情况与易错点

1. **$n = 1$**：无操作可用也无需操作，单元素数组天然全等，恒 `true`（扫描版自然处理：首元素必与目标一致或末位判断通过）。
2. **初始已全等**：0 次操作即达标，两个目标中必有一个失配数为 0，直接 `true`。
3. **只试一个目标**：无论选 `nums[0]` 还是「多数派」都会 WA——前者倒在 $[1,-1,1]$（全 1 不可达、全 $-1$ 需 2 次），后者倒在 $[-1,1,1,-1,1,1]$（多数派目标全 1 要 3 次，全 $-1$ 只要 2 次）。
4. **忘记末位检查**：扫完 $0 \dots n-2$ 后必须确认末位（被 `flipped` 影响后）与目标一致，否则会把不可达误判为可行。
5. **最少操作数可以超过 $k$**：如 $[1,-1,1]$ 最少要 2 次而 $k$ 可为 1；$[\,-1, 1, \dots, 1, -1\,]$ 这类「两端失配」最少要 $n-1$ 次。$k \le n$ 并不保证够用。
6. **「同一下标可重复选择」是烟雾弹**：重复选择两次等于没选（奇偶不变），最优解永远不需要，贪心天然只选至多一次（引理 1）。
7. **「至多 $k$ 次」不是「恰好 $k$ 次」**：最少操作数 $\le k$ 即可，多余名额直接不用。
