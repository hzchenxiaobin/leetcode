# LeetCode 最大频率元素计数 题解

## 1. 题目概述

- **标题 / 题号**：最大频率元素计数（#3005，easy）
- **链接**：https://leetcode.cn/problems/count-elements-with-maximum-frequency/
- **来源**：LeetCode 第 380 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定一个正整数数组 `nums`，元素在数组中出现的次数称为该元素的**频率**。返回所有具有**最大频率**的元素的**频率之和**。

**约束**：

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,3,1,4]
输出：4
解释：元素 1 和 2 的频率均为 2，是最大频率，频率之和 = 2 + 2 = 4。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5]
输出：5
解释：所有元素频率均为 1，都是最大频率，频率之和 = 5 × 1 = 5。
```

## 3. 解题思路

### 3.1 暴力思路

签到题。对每个值统计出现次数，找出最大频率，再把所有等于最大频率的元素频率累加起来。数据范围极小（$n \le 100$，$nums[i] \le 100$），任何合理做法都能通过。

### 3.2 核心观察：答案只与计数有关，与具体元素无关

![计数 → 取最大频率 → 筛选求和](images/cmf_counting_concept.svg)

设不同元素的频率为 $c_1, c_2, \dots, c_m$。题目要的是所有等于 $\max_i c_i$ 的 $c_i$ 之和——**不需要知道是哪些元素**，只需要"计数的计数"。值域只有 `[1, 100]`，用一个长度 101 的**计数数组**代替哈希表即可，连哈希都省了。

### 3.3 算法流程

两遍扫描版（最稳）：

1. 遍历 `nums`，统计每个值的出现次数 `cnt[v]`；
2. 取 `maxFreq = max(cnt)`；
3. 累加所有 `cnt[v] == maxFreq` 的 `cnt[v]`，即为答案。

一遍遍历版（比赛中顺手可写）：同时维护当前最大频率 `maxFreq` 与"已达最大频率的元素频率之和" `total`：

- 某元素频率**超过** `maxFreq`：更新 `maxFreq`，`total` **重置**为新的 `maxFreq`（此前累计全部作废）；
- 某元素频率**恰好等于** `maxFreq`：`total += maxFreq`。

### 3.4 示例演算

`nums = [1,2,2,3,1,4]` 的一遍遍历演算：

| i | nums[i] | freq 变化 | maxFreq | total |
|---|---------|-----------|---------|-------|
| 0 | 1 | 1→1 | 1 ↑ | 1（重置） |
| 1 | 2 | 2→1 | 1 | 2 |
| 2 | 2 | 2→2 | 2 ↑ | 2（重置） |
| 3 | 3 | 3→1 | 2 | 2 |
| 4 | 1 | 1→2 | 2 | 4（+2） |
| 5 | 4 | 4→1 | 2 | 4 |

答案 `total = 4` ✓

![一遍遍历演算](images/cmf_example_walkthrough.svg)

## 4. 算法细节

1. **计数容器**：值域 `[1, 100]`，用长度 101 的静态数组最省事；Python 直接 `Counter(nums)`。
2. **两遍版更稳**：先 `max(cnt)` 再条件求和，逻辑直白，比赛中不易出 bug。
3. **一遍版的关键**：频率**超过**旧最大值时，`total` 必须重置为新的 `maxFreq`——此刻只有这一个元素达到新最大频率，旧累计全部作废。
4. **答案上界**：所有元素频率相同（如示例 2）时答案最大，为 $n \le 100$，`int` 绰绰有余。

## 5. 正确性证明

**引理 1**：设不同元素的频率为 $c_1, c_2, \dots, c_m$，$M = \max_i c_i$，则答案为 $\sum_{c_i = M} c_i$。

**证明**：频率为 $M$ 的元素恰有 $\#\{i : c_i = M\}$ 个，题目要求它们的频率之和，即 $\sum_{c_i = M} c_i = M \cdot \#\{i : c_i = M\}$。∎

**定理**：一遍遍历维护的 `total` 终值等于 $\sum_{c_i = M} c_i$。

**证明**：对遍历步数归纳，维护不变式："任一时刻，`total` 等于当前频率等于 `maxFreq` 的元素的频率之和"。设当前读入元素 $x$，其频率更新为 $f$：

- 若 $f > maxFreq$：$x$ 成为唯一达到新最大频率 $f$ 的元素，重置 `total = f` 保持不变式；
- 若 $f = maxFreq$：$x$ 新加入"达到最大频率"集合，`total += maxFreq` 保持不变式；
- 若 $f < maxFreq$：集合不变，不变式自然保持。

遍历结束时 `maxFreq` 即最终最大频率 $M$，`total` 即所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + V)$，其中 $V = 100$ 为值域大小。统计一遍 $O(n)$，取最大值与求和各扫一遍计数数组 $O(V)$。
- **空间复杂度**：$O(V)$。计数数组长度 101，与 $n$ 无关（用哈希表则为 $O(m)$，$m$ 为不同元素个数，不超过 $\min(n, V)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxFrequencyElements(vector<int>& nums) {
        int cnt[101] = {0};
        for (int x : nums) cnt[x]++;
        int maxFreq = *max_element(cnt, cnt + 101);
        int ans = 0;
        for (int c : cnt) {
            if (c == maxFreq) ans += c;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxFrequencyElements(self, nums: List[int]) -> int:
        cnt = Counter(nums)
        max_freq = max(cnt.values())
        return sum(c for c in cnt.values() if c == max_freq)
```

一遍遍历版（比赛中两种写法二选一即可）：

```python
class Solution:
    def maxFrequencyElements(self, nums: List[int]) -> int:
        freq = defaultdict(int)
        max_freq = total = 0
        for x in nums:
            freq[x] += 1
            if freq[x] > max_freq:
                max_freq = freq[x]
                total = max_freq
            elif freq[x] == max_freq:
                total += max_freq
        return total
```

## 8. 边界情况与易错点

1. **单元素数组**：`nums = [5]`，频率 1 即最大，答案 1。
2. **全部相同**：如 `[7,7,7]`，最大频率 3，只有一个元素达到，答案 3（不是 $3 \times 3 = 9$）。
3. **重置遗漏**：一遍遍历版中，频率**超过**旧最大值时若忘记把 `total` 重置，会多算已作废的旧值。
4. **加错对象**：答案累加的是**频率**（出现次数），不是元素本身的值。
5. **零桶干扰**：计数数组中大量为 0 的桶，因 $0 < maxFreq$ 自然被跳过，无需特判。
