# LeetCode 找出数组中的美丽下标 I 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的美丽下标 I（#3006，medium）
- **链接**：https://leetcode.cn/problems/find-beautiful-indices-in-the-given-array-i/
- **来源**：LeetCode 第 380 场周赛 Q2
- **难度**：中等
- **标签**：双指针、字符串、二分查找、字符串匹配

**题意**：给定下标从 0 开始的字符串 `s`、字符串 `a`、字符串 `b` 和整数 `k`。下标 `i` 是**美丽下标**，当且仅当：

- $0 \le i \le |s| - |a|$ 且 $s[i .. i+|a|-1] = a$（从 `i` 开始恰好匹配 `a`）；
- **存在**下标 $j$ 使得 $s[j .. j+|b|-1] = b$ 且 $|j - i| \le k$。

以数组形式按**从小到大排序**返回所有美丽下标。

**约束**：

- $1 \le k \le |s| \le 10^5$
- $1 \le |a|, |b| \le 10$（但 `s` 可能很短，`a`、`b` 可能比 `s` 还长）
- `s`、`a`、`b` 只包含小写英文字母

> ⚠️ 本题是同场 Q4 [3008. 找出数组中的美丽下标 II](https://leetcode.cn/problems/find-beautiful-indices-in-the-given-array-ii/) 的弱化版：II 把 $|s|$ 放大到 $5 \times 10^5$、$|a|,|b|$ 放大到 $|s|$，匹配阶段必须换成 KMP / 滚动哈希；本题 $|a|,|b| \le 10$，逐位比较即可，**判定阶段两种写法完全相同**。

## 2. 示例

**示例 1**

```text
输入：s = "isawsquirrelnearmysquirrelhouseohmy", a = "my", b = "squirrel", k = 15
输出：[16,33]
解释：存在 2 个美丽下标：[16,33]。
- 下标 16 是美丽下标，因为 s[16..17] == "my"，且存在下标 4，满足 s[4..11] == "squirrel" 且 |16 - 4| <= 15。
- 下标 33 是美丽下标，因为 s[33..34] == "my"，且存在下标 18，满足 s[18..25] == "squirrel" 且 |33 - 18| <= 15。
```

**示例 2**

```text
输入：s = "abcd", a = "a", b = "a", k = 4
输出：[0]
解释：下标 0 是美丽下标，因为 s[0..0] == "a"，且存在下标 0，满足 s[0..0] == "a" 且 |0 - 0| <= 4。
```

**示例 3**（边界补充：`b` 无匹配）

```text
输入：s = "abcd", a = "a", b = "e", k = 4
输出：[]
解释：s 中不存在 "e" 的匹配，任何 i 都找不到满足条件的 j，无美丽下标。
```

## 3. 解题思路

### 3.1 暴力思路

先把 `a`、`b` 在 `s` 中的全部匹配起点收集成升序列表 `A`、`B`，再枚举每一对 $(i, j) \in A \times B$，检查 $|i - j| \le k$。

配对数量是致命伤：取 `s = "aaa...a"`、`a = b = "a"`，则 $|A| = |B| = n = 10^5$，配对数约 $n^2 = 10^{10}$，必然超时。**收集匹配不是瓶颈**（逐位比较 $O(n \cdot L)$，$L = |a| + |b| \le 20$，至多 $2 \times 10^6$ 次字符比较），**瓶颈在「判定」**——必须利用两组下标各自有序的事实，把每个 `i` 的判定代价从 $O(|B|)$ 压到 $O(\log |B|)$ 甚至均摊 $O(1)$。

### 3.2 核心观察：窗口覆盖判定——只看「最近的 j」

![核心概念：i 是美丽下标当且仅当窗口 i−k 到 i+k 覆盖 b 的某个匹配点](images/fbi_window_concept.svg)

把美丽下标的条件翻译成集合语言：

$$i \text{ 是美丽下标} \iff B \cap [i-k,\ i+k] \ne \varnothing$$

而 `B` 是**升序**的，所以只需关注**第一个 $\ge i-k$ 的元素** $B[p]$（即 `lower_bound(B, i−k)`）：

- 若 $B[p] \le i+k$：命中，`i` 是美丽下标；
- 若 $B[p] > i+k$：比 $B[p]$ 早的元素都 $< i-k$（太靠左），比它晚的都 $\ge B[p] > i+k$（太靠右），**一次比较即可否定全部**。

> 💡 本质是**最近邻判定**：`i` 美丽 $\iff$ `B` 中离 `i` 最近的元素与 `i` 的距离 $\le k$。有序性把「扫描全部候选」压缩成「只看一个候选」，二分与双指针吃的都是这一口气。

### 3.3 算法流程：收集匹配 + 双指针单向扫描

![算法流程：两次扫描收集 A 与 B，再双指针判定](images/fbi_two_pointer_flow.svg)

`A` 同样升序，且随 `i` 增大，窗口左端点 $i-k$ **单调不减**——于是「第一个 $\ge i-k$」的指针 `p` 也单调不减，**永不回退**，整个判定阶段是一次归并式线性扫描：

1. 扫描 `s`，收集 `a` 的全部匹配起点到 `A`（升序）；
2. 扫描 `s`，收集 `b` 的全部匹配起点到 `B`（升序）；
3. `p = 0`，依次遍历 $i \in A$：先 `while p < |B| 且 B[p] < i−k` 时 `p++`；
4. 若 `p < |B|` 且 `B[p] ≤ i+k`，则 `i` 收入答案；`A` 天然升序，直接返回。

> 💡 也可以不维护指针，对每个 `i` 二分查找 `lower_bound(B, i−k)`，复杂度 $O(|A| \log |B|)$，在 $n \le 10^5$ 下同样轻松；双指针是它的均摊 $O(1)$ 改进，两者正确性同源——都只检查那**一个**关键候选。

### 3.4 示例演算

![示例 1 的双指针逐步演算](images/fbi_example_walkthrough.svg)

对示例 1：$A = [16, 33]$、$B = [4, 18]$、$k = 15$。

| 步骤 | i | 窗口 [i−k, i+k] | while 后 p | B[p] | 判定 | 结果 |
|------|---|------------------|-----------|------|------|------|
| 1 | 16 | [1, 31] | 0（B[0]=4 ≥ 1，不动） | 4 | 4 ≤ 31 ✓ | 收 16 |
| 2 | 33 | [18, 48] | 1（B[0]=4 < 18，前进） | 18 | 18 ≤ 48 ✓ | 收 33 |

`i = 33` 时窗口左边界恰好压住 $j = 18$（$|33 - 18| = 15 = k$，**闭区间边界命中**），两个 `i` 都美丽，返回 `[16, 33]`，全程 `p` 只前进了 1 步。

## 4. 算法细节

1. **收集匹配的写法**：本题 $|a|,|b| \le 10$，逐位比较足够——C++ 用 `s.compare(i, la, a) == 0`，Python 用 `s.startswith(a, i)`（零拷贝，别写 `s[i:i+la] == a`，切片白白多出 $O(n \cdot L)$ 的复制开销）。
2. **循环边界防下溢**：起点上界是 $|s| - |a|$，但 `s` 可能比 `a` 短。循环条件写 `i + la <= n`（`int` 运算）而不是 `i <= n - la`，避免 C++ 中 `size_t` 无符号下溢成天文数字导致越界。
3. **`p` 为什么不回退**：按升序遍历 `A`，窗口左端点 $i-k$ 单调不减；「第一个 $\ge i-k$」的位置关于下界单调不减。一旦 $B[p] < i-k$，它对后续所有更大的 `i` 同样太小，跳过是安全的。
4. **二分版**：每个 `i` 独立执行 `bisect_left(B, i−k)` 得 `q`，判定 `q < |B|` 且 `B[q] ≤ i+k`。写起来更短，适合赛中图快；双指针版更线性、更稳。
5. **答案无需排序**：`A` 按起点升序收集，遍历顺序即答案顺序；起点互不相同，`A` 内无重复。

## 5. 正确性证明

**引理 1**（窗口覆盖刻画）：$i \in A$ 是美丽下标 $\iff$ 存在 $j \in B$ 使 $|j - i| \le k$ $\iff$ $B \cap [i-k, i+k] \ne \varnothing$。

**证明**：条件 $|j - i| \le k$ 等价于 $i - k \le j \le i + k$，即 $j \in [i-k,\ i+k]$。故「存在这样的 $j$」$\iff$ 升序集合 $B$ 与闭区间 $[i-k, i+k]$ 有交。∎

**引理 2**（单候选判定的充分性）：设 $p = \min\{t : B[t] \ge i-k\}$（不存在时 $p = |B|$），则 $B \cap [i-k, i+k] \ne \varnothing \iff p < |B|$ 且 $B[p] \le i+k$。

**证明**：（$\Leftarrow$）$B[p] \in [i-k, i+k]$，交集非空。（$\Rightarrow$）若交集非空，取任一 $j \in B \cap [i-k, i+k]$，则 $j \ge i-k$，由 $p$ 的定义 $p \le j$ 在 `B` 中的位置且 $p < |B|$；又 $B[p]$ 是 `B` 中第一个 $\ge i-k$ 的元素，若 $B[p] > i+k$，则一切 $< B[p]$ 的元素都 $< i-k$、一切 $\ge B[p]$ 的元素都 $> i+k$，`B` 与窗口无交，矛盾。故 $B[p] \le i+k$。∎

**定理**：双指针算法输出的序列恰为全部美丽下标，且严格升序。

**证明**：对遍历步数归纳，维护不变式：**处理每个 $i$ 时，`p` 恰为第一个 $\ge i-k$ 的候选下标**。初始 $p = 0$（`B` 中元素均 $\ge 0 \ge i_1 - k$ 或 `B` 为空，不变式成立，`while` 结束后自然恢复）。归纳步：设处理 $i_{r-1}$ 后不变式成立，即 $B[p-1] < i_{r-1} - k$（或 $p = 0$）。因 $A$ 升序，$i_r \ge i_{r-1}$，故 $i_r - k \ge i_{r-1} - k > B[p-1]$，旧 `p` 仍是合法下界，`while` 只前进不后退，结束时 $B[p'] \ge i_r - k$ 且 $B[p'-1] < i_r - k$，不变式保持。由引理 2，每步判定恰给出「窗口是否非空」；由引理 1，收入答案的 $i$ 恰为美丽下标，无遗漏、无多收。`A` 严格升序且按序遍历，输出严格升序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L + |A| + |B|)$，其中 $n = |s|$，$L = |a| + |b| \le 20$。收集阶段每个起点至多比较 $L$ 个字符，共 $\le 2 \times 10^6$ 次字符比较；判定阶段 `i` 与 `p` 各自单向前进，合计 $O(|A| + |B|) \le O(n)$。二分版为 $O(n \cdot L + |A| \log |B|)$。
- **空间复杂度**：$O(|A| + |B|)$，最坏 $O(n)$ 存两个匹配起点列表；返回值不计入。

> 💡 若用 KMP / 滚动哈希收集匹配，时间降到 $O(n + |a| + |b|)$——这正是 Q4（3008）在 $L$ 放大到 $5 \times 10^5$ 后的唯一必要改动。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> beautifulIndices(string s, string a, string b, int k) {
        int n = s.size(), la = a.size(), lb = b.size();
        vector<int> A, B;
        for (int i = 0; i + la <= n; ++i)
            if (s.compare(i, la, a) == 0) A.push_back(i);
        for (int j = 0; j + lb <= n; ++j)
            if (s.compare(j, lb, b) == 0) B.push_back(j);

        vector<int> ans;
        int m = B.size(), p = 0;
        for (int i : A) {
            while (p < m && B[p] < i - k) ++p;
            if (p < m && B[p] <= i + k) ans.push_back(i);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def beautifulIndices(self, s: str, a: str, b: str, k: int) -> List[int]:
        A = [i for i in range(len(s) - len(a) + 1) if s.startswith(a, i)]
        B = [j for j in range(len(s) - len(b) + 1) if s.startswith(b, j)]

        ans, p = [], 0
        for i in A:
            while p < len(B) and B[p] < i - k:
                p += 1
            if p < len(B) and B[p] <= i + k:
                ans.append(i)
        return ans
```

二分版（与双指针等价，写起来更短）：

```python
from bisect import bisect_left

class Solution:
    def beautifulIndices(self, s: str, a: str, b: str, k: int) -> List[int]:
        A = [i for i in range(len(s) - len(a) + 1) if s.startswith(a, i)]
        B = [j for j in range(len(s) - len(b) + 1) if s.startswith(b, j)]
        return [i for i in A
                if (q := bisect_left(B, i - k)) < len(B) and B[q] <= i + k]
```

## 8. 边界情况与易错点

1. **`a` 或 `b` 比 `s` 长**：`s` 长度可低至 1，对应匹配列表为空——`A` 空则答案为空；`B` 空则任何 `i` 都不美丽（见示例 3）。C++ 循环条件务必写 `i + la <= n` 而非 `i <= n - la`，防止 `size_t` 下溢成天文数字后越界访问。
2. **`i - k` 可为负**：`i < k` 时窗口左端为负，无需特判——`B` 中元素均非负，比较 `B[p] < i - k` 天然正确。
3. **同一位置兼任 `i` 与 `j`**：示例 2 中下标 0 既是 `a` 的匹配又是 `b` 的匹配，$|0 - 0| = 0 \le k$，不要把 `i`、`j` 理解成必须不同。
4. **`k` 可达 $|s|$**：窗口远大于串长，只要 `B` 非空则 `A` 全部美丽，判定逻辑天然覆盖，无需特判。
5. **访问越界**：判定前先检查 `p < |B|` 再读 `B[p]`；二分版同理先查 `q < len(B)`。
6. **Python 切片开销**：`s[i:i+la] == a` 每个起点复制一次子串，多出 $O(n \cdot L)$ 拷贝；`startswith(a, i)` 零拷贝。`range(len(s) - len(a) + 1)` 在 `a` 比 `s` 长时是空区间，边界自动成立。
7. **答案顺序**：按升序遍历 `A` 收集，答案天然升序，不要再排一遍；也不必去重（匹配起点互异）。
