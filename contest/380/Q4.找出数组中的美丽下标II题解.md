# LeetCode 找出数组中的美丽下标 II 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的美丽下标 II（#3008，hard）
- **链接**：https://leetcode.cn/problems/find-beautiful-indices-in-the-given-array-ii/
- **来源**：LeetCode 第 380 场周赛 Q4
- **难度**：困难
- **标签**：字符串匹配、KMP 算法、双指针、二分查找

**题意**：与本场 Q2（#3006）一字不差。给定下标从 0 开始的字符串 `s`、字符串 `a`、字符串 `b` 和整数 `k`。下标 `i` 是**美丽下标**，当且仅当：

- $s[i .. i+|a|-1] = a$（从 `i` 开始恰好匹配 `a`）；
- **存在**下标 $j$ 使 $s[j .. j+|b|-1] = b$ 且 $|j - i| \le k$。

以数组形式按**从小到大排序**返回全部美丽下标。

**约束**：

- $1 \le k \le |s| \le 5 \times 10^5$
- $1 \le |a|, |b| \le 5 \times 10^5$（`a`、`b` 可以**比 `s` 更长**，此时无匹配）
- `s`、`a`、`b` 只包含小写英文字母

> ⚠️ **与 Q2 的唯一差别是数据规模**：$|s|$ 从 $10^5$ 放大到 $5 \times 10^5$，$|a|, |b|$ 从 $10$ 放大到 $5 \times 10^5$。题意、判定逻辑、输出格式全部原样——这正是本场压轴的设计：Q2 验证思路，Q4 收「复杂度硬门槛」的门票。

> 💡 本题另有[每日题解 3008](../../solution/3001-3100/3008_找出数组中的美丽下标II.md)：含 KMP 收集器的面试问答展开与算法选型对比，与本文互为印证；本文侧重**赛场复盘**——Q2 代码如何以最小改动平移升级、语言内置 `find` 的风险边界，以及 KMP「找全部出现」的正确性骨架。

## 2. 示例

**示例 1**

```text
输入：s = "isawsquirrelnearmysquirrelhouseohmy", a = "my", b = "squirrel", k = 15
输出：[16,33]
解释：存在 2 个美丽下标：[16,33]。
- 下标 16 是美丽下标，因为 s[16..17] == "my"，且存在下标 4，满足 s[4..11] == "squirrel" 且 |16 - 4| <= 15。
- 下标 33 是美丽下标，因为 s[33..34] == "my"，且存在下标 18，满足 s[18..25] == "squirrel" 且 |33 - 18| <= 15。
```

**示例 2**

```text
输入：s = "abcd", a = "a", b = "a", k = 4
输出：[0]
解释：下标 0 是美丽下标，因为 s[0..0] == "a"，且存在下标 0，满足 s[0..0] == "a" 且 |0 - 0| <= 4。
```

**示例 3**（边界补充：**重叠出现**）

```text
输入：s = "ababa", a = "aba", b = "ba", k = 1
输出：[0,2]
解释：A = [0,2]（"aba" 在 s 中重叠出现两次，共享中间的 'a'），B = [1,3]。
- i = 0：窗口 [-1,1] 覆盖 B[0] = 1，美丽；
- i = 2：窗口 [1,3] 覆盖 B[0] = 1 与 B[1] = 3，美丽。
若收集时命中起点 0 后把匹配指针清零，起点 2 会被漏掉，答案只剩 [0] —— 见 §3.3。
```

## 3. 解题思路

### 3.1 暴力思路：Q2 的代码为什么不能直接交

Q2 的完整解法是「逐位比较收集 + 双指针判定」。搬到 Q4，判定阶段毫无压力（$O(|A|+|B|) \le O(n)$），**死的只有收集阶段**：

- 逐位比较收集一个模式的代价是 $(n - m + 1) \cdot m$，在 $m \approx n/2$ 时取最大值 $\approx \frac{(n+1)^2}{4} \approx 6 \times 10^{10}$ 次字符比较，`a`、`b` 各来一遍——比时限（周赛经验上限约 $10^8 \sim 10^9$ 次基本运算）高出两个数量级，必然 TLE；
- 若再退一步用 $O(|A| \cdot |B|)$ 的配对暴力判定（Q2 已否定的做法），在 `s = "aaa…a"`、`a = b = "a"` 时又是 $2.5 \times 10^{11}$ 对——两头都得换成线性。

> ⚠️ 赛场上最常见的翻车不是想不出 KMP，而是**顺手把 Q2 的 Python 代码原样提交**：`s.startswith(a, i)` 逐起点收集正是上面的 $O(n \cdot m)$。周赛 I/II 双联题的出题意图就是抓这个惯性——读约束、算乘积、再动手。

### 3.2 核心观察：流水线拆解——只有「收集」一格需要换件

![核心概念：收集与判定两段流水线，Q2 到 Q4 只升级收集阶段](images/wc380_q4_upgrade_ladder.svg)

把解法看成两段独立流水线：

1. **收集**：求 `a` 在 `s` 中的**全部**出现起点（升序表 `A`）、`b` 同理（升序表 `B`）；
2. **判定**：$i \in A$ 美丽 $\iff B \cap [i-k,\ i+k] \ne \varnothing$，用双指针（或二分）单趟判定。

Q2 已把第 2 段做干净：引理（窗口覆盖刻画）、双指针单调性、`p` 只进不退的论证全部成立，**一行不改直接搬运**。本题的全部新意压缩在第 1 段：把 $O(n \cdot L)$ 的逐位比较换成 $O(n + m)$ 的线性匹配。线性工具箱有三件：

| 工具 | 一句话 | 备注 |
|------|--------|------|
| **KMP（前缀函数）** | 失配回跳 $\pi$，命中回跳 $\pi[m-1]$ | 无随机性、无碰撞，本文选它 |
| **Z 函数（扩展 KMP）** | 对 $p + \# + s$ 算 $Z$，$Z[i] = m$ 即匹配 | 与 KMP 等价，喜欢即用 |
| **滚动哈希** | 滑窗比对哈希值 | 代码短，需双模数防碰撞 |

> 💡 **内置 `find` 的风险边界**（赛场向）：C++ libstdc++ 的 `string::find` / `std::search` 是朴素逐位实现，最坏 $O(n \cdot m)$，`s = "a…a"`、`p = "a…ab"` 的卡满用例是现成的，不稳；Python 3.10+ 的 `str.find` 对长模式走 Crochemore–Perrin 两路算法，单次调用有线性保证，但**循环 `find` 收集大量重叠出现**时每次命中仍要完整比对 $m$ 个字符，总代价无理论保证——本题实测能过属于数据仁慈。周赛求稳，5 分钟手写 KMP；要赌 `find`，至少想清楚输在哪类数据上。

### 3.3 算法流程：KMP 收集 + Q2 双指针

收集器的命门在「**全部**出现」四个字上：命中后匹配指针要**回跳** $\pi[m-1]$，而不是清零。

![KMP 命中后回跳而非清零：重叠出现一个不漏](images/wc380_q4_kmp_overlap.svg)

完整流程：

1. 对 `a` 求前缀函数 $\pi_a$，扫一遍 `s`：已匹配长度 $j$ 随字符推进，失配时 $j \leftarrow \pi_a[j-1]$；$j$ 达到 $|a|$ 时记录起点 $i - |a| + 1$，并令 $j \leftarrow \pi_a[|a|-1]$ **继续**。得升序表 `A`（含重叠出现）；
2. 对 `b` 同理得升序表 `B`；
3. 双指针判定（与 Q2 逐字相同）：`p = 0`，依次遍历 $i \in A$：`while p < |B| 且 B[p] < i−k` 时 `p++`；若 `p < |B|` 且 `B[p] ≤ i+k`，则 `i` 收入答案；
4. 返回答案（`A` 天然升序，无需排序）。

其中「回跳而非清零」的直觉：命中时 $s[i-m+1..i] = p$ 整段对齐，$p$ 的最长相等真前后缀（长度 $\pi[m-1]$）**仍然**与主串尾部对齐——把它当作「已匹配部分」继续，错位重叠的出现（如 `"aa"` 在 `"aaaa"` 的 0、1、2 三处）才不会漏。清零则把这段已知信息全部丢弃，重叠出现被整段跳过（示例 3 的 `A` 少掉起点 2 正是这个坑）。

### 3.4 示例演算

![示例 1 的数轴窗口演算与双指针走位](images/wc380_q4_example_walkthrough.svg)

对示例 1：$A = [16, 33]$、$B = [4, 18]$、$k = 15$。

| 步骤 | i | 窗口 [i−k, i+k] | while 后 p | B[p] | 判定 | 结果 |
|------|---|------------------|-----------|------|------|------|
| 1 | 16 | [1, 31] | 0（B[0]=4 ≥ 1，不动） | 4 | 4 ≤ 31 ✓ | 收 16 |
| 2 | 33 | [18, 48] | 1（B[0]=4 < 18，前进） | 18 | 18 ≤ 48 ✓ | 收 33 |

`i = 33` 时窗口左端恰好压住 $j = 18$（$|33 - 18| = 15 = k$，闭区间边界命中）。整趟 `p` 只前进了 1 步——出窗的 `B[0]` 永久出局，这就是双指针线性代价的由来（单调性论证同 Q2 §5）。

## 4. 算法细节

1. **收集器封装**：`kmpFind(s, p)` 返回 `p` 在 `s` 中的全部出现起点，两次调用分别得 `A`、`B`。前缀函数构建 $O(m)$、主扫描均摊 $O(n)$，模板与 [28. 找出字符串中第一个匹配项的下标](https://leetcode.cn/problems/find-the-index-of-the-first-occurrence-in-a-string/) 只差「命中后 `break` 还是回跳继续」。
2. **命中回跳**：`j == m` 时记录起点后执行 `j = pi[j-1]`。这一行是「找首次出现」与「找全部出现」的分水岭，漏写则重叠出现缺失（图 2、示例 3）。
3. **`m > n` 早退**：II 允许 $|a|, |b|$ 达 $5 \times 10^5$ 而 $|s|$ 可低至 1——模式真可能比主串长，`kmpFind` 开头显式判断返回空表。C++ 中这一步同时规避 `size_t` 无符号下溢（`n - m` 天文数字）导致的越界，是 Q2 边界讨论在 II 的强化版。
4. **判定阶段零改动**：`while (p < m && B[p] < i - k) ++p;` + 单次比较，与 Q2 参考代码逐字相同；`i - k` 为负无需特判（`B` 中元素均非负），`B` 为空时 `p < m` 恒假、自然全不入选。
5. **双指针 vs 二分**：二分版对每个 `i` 做 `bisect_left(B, i-k)`，$O(|A| \log |B|)$，写起来短；双指针版 $O(|A| + |B|)$，更线性更稳。两者正确性同源——都只检查「第一个 $\ge i-k$」的那一个候选（Q2 引理 2）。
6. **输出规模**：`a = "a"`、`s = "aaa…a"` 时 $|A| = n$，答案数组本身 $O(n)$，属于输出必要开销。

## 5. 正确性证明

**引理 1（KMP 扫描不变式）**：设 $p$ 长为 $m$、前缀函数为 $\pi$。定义处理完 $s[i]$ 时的候选集 $C_i = \{t : 0 \le t \le m,\ s[i-t+1..i] = p[0..t-1]\}$。则算法维护不变式：若 $m \notin C_i$，则 $j = \max C_i$；若 $m \in C_i$（必有 $m = \max C_i$），则起点 $i-m+1$ 被记录，且 $j = \pi[m-1] = \max (C_i \setminus \{m\})$。

**证明**：对 $i$ 归纳。$i = 0$ 时直接比较一次即成立。归纳步设处理完 $i-1$ 后不变式成立，考察处理 $s[i]$：

- **失配链不跳过候选**：设处理 $s[i]$ 前 $j = t_0$（上一轮的 $j$）。若 $s[i] \ne p[t_0]$，则 $t_0 \notin C_i$ 的最大候选链恰为 $t_0 > \pi[t_0 - 1] > \pi[\pi[t_0-1]-1] > \cdots$——因为 $s[i-t+1..i-1] = p[0..t-1]$ 的候选 $t$ 若再延长一格失配，则更短的候选 $t'$ 必满足 $p[0..t'-1] = p[t-t'..t-1]$（同为 $s[i-t+1..i-1]$ 的后缀），即 $t'$ 是 $p[0..t-1]$ 的 border，落在 $\pi$ 回跳链上。`while` 循环恰按此链自大到小枚举，停在第一个使 $s[i] = p[t]$ 的 $t$（或 $t = 0$），随后 `++j` 得到新的最大候选。
- **命中回跳保持次大**：若 $j$ 到达 $m$，即 $s[i-m+1..i] = p$，记录起点。此时 $C_i$ 中所有 $t < m$ 的候选既是 $s[1..i]$ 的后缀、又因紧贴完整命中段而是 $p$ 的后缀，同时还是 $p$ 的前缀——即 $p$ 的 border，故最大者为 $\pi[m-1]$，回跳后 $j = \max(C_i \setminus \{m\})$，不变式保持。∎

**引理 2（收集完备性）**：`kmpFind(s, p)` 输出的序列恰为 $p$ 在 $s$ 中的全部出现起点，严格升序且无重复。

**证明**：**是出现则被记录**：设 $st$ 为任一出现起点，即 $s[st..st+m-1] = p$，则 $m \in C_{st+m-1}$。由引理 1，处理完 $s[st+m-1]$ 后（无论中途是否回跳过），$j$ 终值为 $m$ 或 $\pi[m-1]$——若为 $m$ 则 $st$ 恰在本轮被记录；若为 $\pi[m-1]$，说明本曾有更大的候选链经过 $m$……而 $j$ 到达 $m$ 的**当轮**即触发记录，故 $st$ 被记录。**被记录则是出现**：$j = m$ 由不变式等价于 $s[i-m+1..i] = p$，即 $i-m+1$ 是出现起点。**升序无重**：起点 $i - m + 1$ 随扫描下标 $i$ 严格递增地被记录，且同一 $i$ 至多触发一次记录。∎

**引理 3（窗口覆盖刻画与单候选判定）**：$i \in A$ 是美丽下标 $\iff B \cap [i-k,\ i+k] \ne \varnothing$；且设 $p^* = \min\{t : B[t] \ge i-k\}$（不存在时 $p^* = |B|$），则窗口非空 $\iff p^* < |B|$ 且 $B[p^*] \le i+k$；按升序遍历 $A$ 时指针 $p^*$ 单调不减。

**证明**：与 Q2 §5 的引理 1、引理 2 与定理的指针单调论证逐字相同（$|j - i| \le k \iff j \in [i-k, i+k]$；第一个 $\ge i-k$ 的元素是一次比较即可判定全部的充分候选；$i$ 递增使 $i-k$ 单调不减，出窗候选永久出局）。∎

**定理**：本文算法输出的序列恰为全部美丽下标，且严格升序。

**证明**：由引理 2，`A`、`B` 分别是 `a`、`b` 在 `s` 中全部匹配起点的升序无重表，故「$i \in A$ 且 $B \cap [i-k, i+k] \ne \varnothing$」恰刻画「$i$ 是美丽下标」（题意的两组存在条件）。由引理 3，双指针判定对每个 $i \in A$ 恰确判定窗口是否非空，无遗漏、无多收；`A` 严格升序且按序遍历，输出严格升序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(|s| + |a| + |b|)$。每个模式：前缀函数构建 $O(m)$；主扫描均摊 $O(n)$（势能论证：$j$ 每轮至多 $+1$，全程总增量 $\le n$；失配/命中回跳 $j = \pi[j-1]$ 严格减小 $j$，回跳总量不超过增量总量，故内层 `while` 总执行 $O(n)$ 次）。两个模式合计 $O(|s| + |a| + |b|)$；双指针判定 $O(|A| + |B|) \le O(|s|)$。
- **空间复杂度**：$O(|a| + |b| + |A| + |B|)$——两个 $\pi$ 数组与两张起点表；最坏 $|A| = |s| - |a| + 1$（`a = "a"`），连同返回值共 $O(n + m)$，$5 \times 10^5$ 规模下毫无压力。

> 💡 对比：暴力收集 $O(n \cdot m)$ 最坏约 $6 \times 10^{10}$；KMP 把「每个起点重比一遍」压缩成「整趟只扫一遍、失配用已匹配信息续命」，这正是前缀函数三十年不衰的理由。

## 7. 参考代码

### C++（KMP 收集 + 双指针判定）

```cpp
class Solution {
  public:
    vector<int> beautifulIndices(string s, string a, string b, int k) {
        vector<int> A = kmpFind(s, a), B = kmpFind(s, b);
        vector<int> ans;
        int p = 0, m = B.size();
        for (int i : A) {
            while (p < m && B[p] < i - k) ++p;    // 出左窗的候选，对后续 i 也永久无效
            if (p < m && B[p] <= i + k) ans.push_back(i);
        }
        return ans;
    }

  private:
    // p 在 s 中的全部出现起点（升序，含重叠出现）
    vector<int> kmpFind(const string& s, const string& p) {
        int n = s.size(), m = p.size();
        if (m > n) return {};                     // II 边界：模式可比主串长
        vector<int> pi(m, 0);
        for (int i = 1; i < m; ++i) {
            int j = pi[i - 1];
            while (j > 0 && p[i] != p[j]) j = pi[j - 1];
            if (p[i] == p[j]) ++j;
            pi[i] = j;
        }
        vector<int> res;
        int j = 0;                                // 已匹配长度
        for (int i = 0; i < n; ++i) {
            while (j > 0 && s[i] != p[j]) j = pi[j - 1];
            if (s[i] == p[j]) ++j;
            if (j == m) {
                res.push_back(i - m + 1);         // 记录起点
                j = pi[j - 1];                    // 回跳而非清零：重叠出现不漏
            }
        }
        return res;
    }
};
```

### Python（同思路）

```python
class Solution:
    def beautifulIndices(self, s: str, a: str, b: str, k: int) -> List[int]:
        def kmp_find(s: str, p: str) -> List[int]:
            n, m = len(s), len(p)
            if m > n:
                return []
            pi = [0] * m
            j = 0
            for i in range(1, m):
                while j and p[i] != p[j]:
                    j = pi[j - 1]                 # 失配回跳
                if p[i] == p[j]:
                    j += 1
                pi[i] = j
            res, j = [], 0
            for i, c in enumerate(s):
                while j and c != p[j]:
                    j = pi[j - 1]
                if c == p[j]:
                    j += 1
                if j == m:
                    res.append(i - m + 1)         # 起点
                    j = pi[j - 1]                 # 回跳，重叠出现不漏
            return res

        A, B = kmp_find(s, a), kmp_find(s, b)
        ans, p = [], 0
        for i in A:
            while p < len(B) and B[p] < i - k:    # 淘汰出左窗的 B[p]
                p += 1
            if p < len(B) and B[p] <= i + k:
                ans.append(i)
        return ans
```

## 8. 边界情况与易错点

1. **`a`、`b` 可以比 `s` 长**：II 的标志性边界（$|a|, |b| \le 5 \times 10^5$ 而 $|s| \ge 1$）。`kmpFind` 开头 `m > n` 早退返回空表；`A` 空则答案为空，`B` 空则任何 `i` 都不美丽。C++ 里这个判断同时防住 `size_t` 下溢（`n - m` 变天文数字后越界），比 Q2 里「写 `i + la <= n`」的防御更前置。
2. **命中后清零 → 漏重叠出现**：`j = pi[j-1]` 别写成 `j = 0`。示例 3 中 `"aba"` 在 `"ababa"` 的起点 2 会因此丢失；模式越长、自重叠越强（如 `"aaa…a"`），丢得越多。
3. **Q2 代码直接交必 TLE**：`startswith` / `s.compare` 逐起点收集是 $O(n \cdot m)$，$6 \times 10^{10}$ 量级——I/II 双联题的教训永远是**先看约束再搬代码**。
4. **C++ 内置 `find` 的陷阱**：libstdc++ 的 `string::find` 是朴素实现，`s = "a…a"`、`p = "a…ab"` 现成卡满；侥幸通过是数据不卡，不是算法对。
5. **`i - k` 可为负**：`i < k` 时窗口左端为负，无需特判——`B` 中元素均非负，`B[p] < i - k` 的比较天然正确。
6. **判定前先查 `p < |B|`**：越界检查放在读 `B[p]` 之前；二分版同理先查 `q < len(B)`。
7. **答案顺序与去重**：按升序遍历 `A` 收集，答案天然升序，不要再排一遍；匹配起点互异，`A` 内无重复。
8. **输出规模**：最坏 $|A| = |s| - |a| + 1$（如 `a = "a"`），答案数组长达 $5 \times 10^5$，属正常输出开销，`reserve` 可省一点realloc。
