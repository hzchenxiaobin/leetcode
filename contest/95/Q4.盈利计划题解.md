# LeetCode 盈利计划 题解

## 1. 题目概述

- **标题 / 题号**：盈利计划（#879，hard）
- **链接**：https://leetcode.cn/problems/profitable-schemes/
- **来源**：LeetCode 第 95 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、背包问题、0-1 背包

**题意**：集团有 $n$ 名员工。第 $i$ 种工作带来 `profit[i]` 的利润、需要 `group[i]` 名员工共同参与；同一名员工不能同时参与两项工作。若一组工作的子集满足「总人数 $\le n$」且「总利润 $\ge minProfit$」，称为一个**盈利计划**。求不同的盈利计划个数，结果对 $10^9+7$ 取模。

**关键点**：

- 每项工作**至多选一次**（0-1 背包），选择的是**子集**而非排列。
- 两个约束同时存在：人数上限 $n$、利润下限 $minProfit$。
- 「不同计划」按**下标集合**区分，与顺序无关。
- 空计划在 $minProfit = 0$ 时算作一个合法计划（利润 $0 \ge 0$，用 $0$ 名员工）。

**约束**：

- $1 \le n \le 100$
- $0 \le minProfit \le 100$
- $1 \le group.length \le 100$，且 $group.length = profit.length$
- $1 \le group[i] \le 100$，$0 \le profit[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：n = 5, minProfit = 3, group = [2,2], profit = [2,3]
输出：2
解释：可选 {工作 1}（2 人，利润 3）或 {工作 0, 工作 1}（4 人，利润 5）。
     只选工作 0 不满足利润 ≥ 3，故共 2 种。
```

**示例 2**

```text
输入：n = 10, minProfit = 5, group = [2,3,5], profit = [6,7,8]
输出：7
解释：任意非空子集的总人数都不超过 10、利润都不低于 5，
     共 2³ − 1 = 7 种：(0)(1)(2)(0,1)(0,2)(1,2)(0,1,2)。
```

**示例 3**（补充，验证空计划）

```text
输入：n = 1, minProfit = 0, group = [2], profit = [1]
输出：1
解释：唯一的「工作」需要 2 人、超出上限，无法选择；
     但空计划利润 0 ≥ 0，计 1 种。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有 $2^{m}$ 个子集（$m \le 100$），逐个判断人数与利润是否满足条件。$2^{100}$ 完全不可行。

注意到这是一个**双约束的 0-1 背包**问题：把「员工数」看作重量、把「利润」看作价值，要求**价值不低于** $minProfit$ 且重量不超过 $n$。区别只在于：普通背包求「最大价值」，本题求「方案数」。

### 3.2 核心观察：二维状态 + 利润封顶

![利润封顶：把 > minProfit 的利润一律记成 minProfit](images/wc95_q4_dp_state.svg)

若按「利润恰好为 $k$」设计状态，$k$ 最大会到 $100 \times 100 = 10^4$，状态数 $O(n \cdot 10^4)$ 尚可但最后还要把 $k \ge minProfit$ 的所有格子求和，容易写错。

**封顶技巧**：我们只关心利润「是否达到 $minProfit$」，不关心超出多少。于是把状态中的利润维度定义为**截断值**：

$$dp[j][k] = \text{使用 } j \text{ 名员工、总利润截断值恰为 } k \text{ 的方案数}, \quad 0 \le k \le minProfit$$

其中「截断值」定义为 $\min(\text{真实利润},\ minProfit)$。转移时

$$dp[j + g][\min(minProfit,\ k + p)] \mathrel{+}= dp[j][k]$$

这样利润维度只有 $minProfit + 1 \le 101$ 种取值，状态数 $O(n \cdot minProfit) \le 10^4$。

**为什么可以封顶？** 因为所有「利润 $\ge minProfit$」的情形在题目眼里是等价的（都满足条件），把它们合并成一格不损失任何信息；而转移的可加性在截断映射下仍然成立：$\min(a+b, P) = \min(\min(a,P) + b, P)$。

### 3.3 算法流程

![0-1 背包的倒序更新](images/wc95_q4_knapsack_flow.svg)

```text
1. dp = (n+1) × (minProfit+1) 的零矩阵；dp[0][0] = 1
2. for i in 0..m-1：
     g = group[i]，p = profit[i]
     for j = n-g downto 0：                     // 员工维度倒序（0-1 背包）
        for k = minProfit downto 0：
            nk = min(minProfit, k + p)
            dp[j+g][nk] = (dp[j+g][nk] + dp[j][k]) mod MOD
3. 答案 = Σ_{j=0..n} dp[j][minProfit] mod MOD
```

**为什么员工维度必须倒序？** 与经典 0-1 背包同理：若 $j$ 正序，`dp[j][k]` 可能在本轮已经被「选入本件工作」的结果覆盖，再被读取时就会让同一件工作被选多次（退化成完全背包），方案数偏大。

**为什么利润维度也倒序？** 不是必需的（写 `k` 正序结果也一样，因为写入目标行的 `k` 更大、而目标行在本轮不会再被读），但保持「两个维度都倒序」的写法最不容易出错，且与标准 0-1 背包模板一致。

**为什么答案是「整列求和」？** 题目要求员工数 $\le n$（不是恰好 $n$），所以要把所有 $dp[j][minProfit]$（$j = 0..n$）都加起来。

### 3.4 示例演算

对示例 2（$n = 10$，$minProfit = 5$，`group = [2,3,5]`，`profit = [6,7,8]`），利润全部 $\ge 5$，截断值都是 $5$：

![逐步转移：7 个子集逐个被计入](images/wc95_q4_walkthrough.svg)

| 处理 | 来源格 → 目标格 | 新增 | 对应子集 |
|------|----------------|------|---------|
| 工作 0 | $dp[0][0] \to dp[2][5]$ | +1 | $\{0\}$ |
| 工作 1 | $dp[0][0] \to dp[3][5]$ | +1 | $\{1\}$ |
| 工作 1 | $dp[2][5] \to dp[5][5]$ | +1 | $\{0,1\}$ |
| 工作 2 | $dp[0][0] \to dp[5][5]$ | +1 | $\{2\}$ |
| 工作 2 | $dp[2][5] \to dp[7][5]$ | +1 | $\{0,2\}$ |
| 工作 2 | $dp[3][5] \to dp[8][5]$ | +1 | $\{1,2\}$ |
| 工作 2 | $dp[5][5] \to dp[10][5]$ | +1 | $\{0,1,2\}$ |

最终 $dp[2][5]=1,\ dp[3][5]=1,\ dp[5][5]=2,\ dp[7][5]=1,\ dp[8][5]=1,\ dp[10][5]=1$，求和得 $7$，与示例一致。

**注意最后一行**：处理工作 2 时 $j$ 从 $5$ 递减到 $0$，所以 $j=5$ 的读取发生在 $dp[5][5]$ 被 $j=0$ 更新**之前**，读到的值是 $1$（只有 $\{0,1\}$），于是 $dp[10][5] = 1$（只有 $\{0,1,2\}$）。如果 $j$ 正序，$dp[5][5]$ 会先被更新成 $2$，再被读走，得到 $dp[10][5] = 2$，总和变成 $8$——这就是「同一件工作被重复选取」的错误。

## 4. 算法细节

1. **截断映射的写法**：`nk = min(minProfit, k + p)`。`k` 已是截断值，$k + p$ 可能超过 $minProfit$，取 `min` 即可。
2. **初始化 `dp[0][0] = 1`**：表示「一个工作都不选、0 名员工、利润 0」这一种方案，它是所有转移的源头。
3. **`dp` 用 `long long` 或每次取模**：方案数会指数增长，必须在每次加法后取模；C++ 中 `int` 存模值即可，但加法结果要避免溢出（两次取模之间最多加 $10^9+6$，`int` 够用，用 `long long` 更保险）。
4. **`j + g` 的越界**：内层 `j` 从 `n - g` 开始递减，保证 `j + g <= n`。
5. **`k` 的倒序**：见上，非必需但更安全；关键是**不能**在 `j` 正序时更新。
6. **`minProfit = 0`**：此时 `dp[*][0]` 就是全部方案（含空计划），答案是 $\sum_j dp[j][0]$，与题意「空计划算一种」一致。

## 5. 正确性证明

**定义**：对工作编号集合 $S \subseteq \{0,\ldots,m-1\}$，记 $g(S) = \sum_{i\in S} group[i]$、$p(S) = \sum_{i \in S} profit[i]$。称 $S$ 为**盈利计划**，当且仅当 $g(S) \le n$ 且 $p(S) \ge minProfit$。

**引理 1（截断等价）**：$\min(p(S), P)$ 与 $p(S)$ 携带同样的「是否盈利」信息：$p(S) \ge P \iff \min(p(S),P) = P$。且截断映射对加法保序：$\min(a+b,P) = \min(\min(a,P)+b,P)$ 对任意 $a,b \ge 0$ 成立。

**证明**：前半显然。后半：若 $a \ge P$，则左边 $= P$，右边 $= \min(P+b,P) = P$；若 $a < P$，则左边 $= \min(a+b,P)$，右边 $= \min(a+b,P)$，两边相同。∎

**引理 2（DP 的语义）**：处理完前 $t$ 件工作后，$dp[j][k]$ 等于满足下列条件的子集 $S \subseteq \{0,\ldots,t-1\}$ 的个数：$g(S) = j$ 且 $\min(p(S), P) = k$。

**证明**：对 $t$ 归纳。$t = 0$ 时只有空集，$dp[0][0] = 1$，其余为 $0$，成立。设对 $t$ 成立，考虑第 $t$ 件工作（$g, p$）：任何子集 $S' \subseteq \{0,\ldots,t\}$ 要么不含 $t$（对应 $dp$ 原值保留），要么形如 $S \cup \{t\}$，其中 $S \subseteq \{0,\ldots,t-1\}$ 且 $g(S) = j$、截断利润为 $k$。后者的员工数为 $j+g$、截断利润为 $\min(k+p,P) = \min(p(S)+p, P)$（由引理 1）。转移恰好把 $dp[j][k]$ 累加到 $dp[j+g][\min(k+p,P)]$，且倒序遍历保证每个 $dp[j][k]$ 只被读取一次旧值（$j$ 递减时目标行 $j+g > j$ 已处理完毕，不会再被读），故既不遗漏也不重复。∎

**定理**：算法返回盈利计划的个数（模 $10^9+7$）。

**证明**：处理完全部 $m$ 件工作后，由引理 2，$dp[j][P]$ 计数「$g(S) = j$ 且 $\min(p(S),P) = P$」的子集，由引理 1 即「$g(S)=j$ 且 $p(S) \ge P$」的子集。对所有 $j \le n$ 求和，得到全部满足 $g(S) \le n$、$p(S) \ge P$ 的子集个数，正是盈利计划的定义。∎

## 6. 复杂度分析

- **时间**：$O(m \cdot n \cdot minProfit)$。$m \le 100$、$n \le 100$、$minProfit \le 100$，最多约 $10^6$ 次加法。
- **空间**：$O(n \cdot minProfit)$（二维表）；若把工作维度也压缩，只需这两维，故空间约 $10^4$ 个整数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int profitableSchemes(int n, int minProfit, vector<int>& group, vector<int>& profit) {
        const int MOD = 1000000007;
        int m = group.size();
        // dp[j][k]：恰好用 j 名员工、利润截断值恰为 k 的方案数
        vector<vector<int>> dp(n + 1, vector<int>(minProfit + 1, 0));
        dp[0][0] = 1;
        for (int i = 0; i < m; i++) {
            int g = group[i], p = profit[i];
            for (int j = n - g; j >= 0; j--) {          // 人数维度倒序：0-1 背包
                for (int k = minProfit; k >= 0; k--) {
                    int nk = min(minProfit, k + p);
                    dp[j + g][nk] = (dp[j + g][nk] + dp[j][k]) % MOD;
                }
            }
        }
        long long ans = 0;
        for (int j = 0; j <= n; j++) ans = (ans + dp[j][minProfit]) % MOD;
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def profitableSchemes(self, n: int, minProfit: int, group: list[int], profit: list[int]) -> int:
        MOD = 10 ** 9 + 7
        # dp[j][k] = 用 j 名员工、利润截断值恰为 k 的方案数
        dp = [[0] * (minProfit + 1) for _ in range(n + 1)]
        dp[0][0] = 1
        for g, p in zip(group, profit):
            for j in range(n - g, -1, -1):          # 倒序：每件工作至多选一次
                for k in range(minProfit, -1, -1):
                    nk = min(minProfit, k + p)
                    dp[j + g][nk] = (dp[j + g][nk] + dp[j][k]) % MOD
        return sum(dp[j][minProfit] for j in range(n + 1)) % MOD
```

## 8. 边界情况与易错点

1. **`minProfit = 0`**：空计划合法，答案至少包含 $1$。若把答案写成 $\sum_{j \ge 1}$ 或漏掉 $j=0$，会少算空计划。
2. **员工维度正序**：会把每件工作当成可无限选取，方案数偏大（示例 2 会得到 $8$ 而不是 $7$）。
3. **答案是整列求和**：题目要求员工数 $\le n$，不是恰好 $n$；只取 $dp[n][minProfit]$ 会严重偏小。
4. **利润维度不封顶**：状态数变成 $O(n \cdot \sum profit)$（可达 $10^4$ 倍），且最后还要处理「超过 $minProfit$」的一堆格子，既慢又易错。
5. **忘记取模**：方案数是指数级，不取模必然溢出（C++ 中变成负数或错误值）。
6. **`group[i] > n` 的工作**：`n - g < 0`，内层循环直接不执行，相当于这件工作永远不能选，正确。
7. **`profit[i] = 0`**：截断值不变，`dp[j+g][k] += dp[j][k]`，仍然正确（只是不增加利润）。
