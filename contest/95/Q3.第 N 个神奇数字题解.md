# LeetCode 第 N 个神奇数字 题解

## 1. 题目概述

- **标题 / 题号**：第 N 个神奇数字（#878，hard）
- **链接**：https://leetcode.cn/problems/nth-magical-number/
- **来源**：LeetCode 第 95 场周赛 Q3
- **难度**：困难
- **标签**：数学、二分查找、容斥原理、最小公倍数

**题意**：正整数中，能被 $a$ 或 $b$ 整除的数称为**神奇数字**。给定 $n, a, b$，返回第 $n$ 个神奇数字，答案对 $10^9+7$ 取模。

**关键点**：

- 「能被 $a$ **或** $b$ 整除」是**并集**，公共倍数（即 $\mathrm{lcm}(a,b)$ 的倍数）只能算一次——这是容斥的用武之地。
- $n$ 高达 $10^9$，答案可达 $4\times10^{13}$，**必须用 64 位整数**；取模只作用于最终答案，二分过程中不能取模（否则单调性被破坏）。

**约束**：

- $1 \le n \le 10^9$
- $2 \le a, b \le 4\times 10^4$

## 2. 示例

**示例 1**

```text
输入：n = 1, a = 2, b = 3
输出：2
解释：神奇数依次为 2, 3, 4, 6, ...，第 1 个是 2。
```

**示例 2**

```text
输入：n = 4, a = 2, b = 3
输出：6
解释：2, 3, 4, 6 —— 第 4 个是 6（注意 6 同时是 2 和 3 的倍数，只能计一次）。
```

**示例 3**（补充，说明边界）

```text
输入：n = 1000000000, a = 40000, b = 39999
输出：999720007
解释：答案是约 4×10^13 的数，取模后为 999720007；必须用 64 位整数才能算对。
```

## 3. 解题思路

### 3.1 暴力思路

从 $1$ 开始逐个判断能否被 $a$ 或 $b$ 整除，数到第 $n$ 个就返回。单次判断 $O(1)$，但要走过约 $n \cdot \frac{ab}{a+b-\gcd}$ 个数，最坏约 $4\times10^{13}$ 次，完全不可行。

### 3.2 核心观察：容斥给出 $O(1)$ 的计数函数

![count(x) 的容斥公式](images/wc95_q3_counting.svg)

记 $c(x)$ 为 $[1, x]$ 内神奇数的个数。由容斥原理：

$$c(x) = \left\lfloor \frac{x}{a} \right\rfloor + \left\lfloor \frac{x}{b} \right\rfloor - \left\lfloor \frac{x}{\mathrm{lcm}(a,b)} \right\rfloor$$

其中 $\mathrm{lcm}(a,b) = \dfrac{a \cdot b}{\gcd(a,b)}$。三项分别是「$a$ 的倍数个数」「$b$ 的倍数个数」「同时是两者倍数（即公共倍数）的个数」——公共部分被加了两次，要减掉一次。

$c(x)$ 可以在 $O(1)$ 时间内算出，而且**关于 $x$ 单调不减**（$x$ 增大，区间只增不减）。

### 3.3 算法流程：二分找第一个 $c(x) \ge n$ 的位置

![二分：count(x) 单调，找第一个达标位置](images/wc95_q3_binary_search.svg)

要求第 $n$ 个神奇数，就是求**最小的** $x$ 使 $c(x) \ge n$。

- 下界 $lo = 1$。
- 上界 $hi = \min(a,b) \cdot n$：因为 $[1, \min(a,b)\cdot n]$ 内至少有 $n$ 个 $\min(a,b)$ 的倍数，它们都是神奇数，故 $c(\min(a,b)\cdot n) \ge n$。
- 二分：`mid = lo + (hi - lo) / 2`，若 $c(mid) \ge n$ 则 `hi = mid`，否则 `lo = mid + 1`。
- 结束时 $lo$ 即答案，返回 $lo \bmod (10^9+7)$。

**为什么二分得到的 $lo$ 一定是神奇数？** 假设 $lo$ 不是神奇数，则 $c(lo) = c(lo-1)$；而由二分不变式 $c(lo) \ge n$ 且 $c(lo-1) < n$，矛盾。所以 $lo$ 必是神奇数，且是第 $n$ 个。

**为什么二分过程中不能取模？** 取模会破坏数值的单调性（取模后大小关系翻转），导致二分走错方向。只有在最后返回时才取模。

**复杂度**：二分 $O(\log(\min(a,b)\cdot n)) \le \log(4\times10^{13}) \approx 46$ 轮，每轮 $O(1)$。

### 3.4 示例演算

![二分四轮收缩到 6](images/wc95_q3_walkthrough.svg)

对 $n = 4$、$a = 2$、$b = 3$（$\mathrm{lcm} = 6$，$hi = \min(2,3)\times 4 = 8$）：

| 轮次 | `lo, hi` | `mid` | $c(mid) = \lfloor m/2\rfloor+\lfloor m/3\rfloor-\lfloor m/6\rfloor$ | $\ge 4$? | 动作 |
|------|---------|-------|---------------------------------------------------|---------|------|
| 1 | 1, 8 | 4 | $2+1-0 = 3$ | ✗ | `lo = 5` |
| 2 | 5, 8 | 6 | $3+2-1 = 4$ | ✓ | `hi = 6` |
| 3 | 5, 6 | 5 | $2+1-0 = 3$ | ✗ | `lo = 6` |

`lo == hi == 6`，返回 $6$，与示例一致。神奇数序列 $2,3,4,6,8,9,10,12,\ldots$ 也印证了第 4 个是 $6$。

## 4. 算法细节

1. **`lcm` 的溢出**：$a,b \le 4\times10^4$，$a\cdot b$ 可达 $1.6\times10^9$，在 `int` 范围内勉强安全（接近 $2^{31}-1$），但稳妥起见用 `long long` 计算 `a / gcd * b`。
2. **计数器要用 `long long`**：`mid / a + mid / b` 可达 $4\times10^{13}$，`int` 溢出会让判定恒真或恒假。
3. **`hi` 的取值**：$\min(a,b)\cdot n$ 在 $n = 10^9$、$\min = 2$ 时为 $2\times10^9$（超过 `int`），$n = 10^9$、$\min = 4\times10^4$ 时达 $4\times10^{13}$，必须用 `long long`。
4. **取模时机**：只在 `return` 时取模。若在二分里取模，`mid` 序列会失去单调性，结果随机。
5. **`gcd` 的实现**：C++17 用 `std::gcd`（`<numeric>`），Python 用 `math.gcd`。
6. **`n = 1`**：答案就是 $\min(a,b)$。二分同样正确（`hi = min(a,b)`，收敛到它）。

## 5. 正确性证明

**引理 1（容斥公式）**：对任意正整数 $x$，$c(x) = \lfloor x/a\rfloor + \lfloor x/b\rfloor - \lfloor x/L\rfloor$，其中 $L = \mathrm{lcm}(a,b)$。

**证明**：设 $A = \{k \le x : a \mid k\}$、$B = \{k \le x : b \mid k\}$。则 $|A| = \lfloor x/a\rfloor$、$|B| = \lfloor x/b\rfloor$。$k \in A \cap B$ 当且仅当 $a\mid k$ 且 $b\mid k$，即 $\mathrm{lcm}(a,b) \mid k$，故 $|A\cap B| = \lfloor x/L\rfloor$。由容斥 $|A\cup B| = |A|+|B|-|A\cap B|$，即得。∎

**引理 2（单调性）**：$c(x)$ 关于 $x$ 单调不减。

**证明**：由引理 1，三项 $\lfloor x/a\rfloor$、$\lfloor x/b\rfloor$、$-\lfloor x/L\rfloor$ 中前两项单调不减、第三项单调不增。更直接地：$c(x) - c(x-1)$ 等于「$x$ 是否为神奇数」，取值 $0$ 或 $1$，故 $c$ 单调不减。∎

**引理 3（二分不变式）**：循环中始终满足 $c(hi) \ge n$ 且 $c(lo - 1) < n$（约定 $c(0) = 0$）。

**证明**：初始 $lo = 1$ 时 $c(0) = 0 < n$；$hi = \min(a,b)\cdot n$ 时，$[1, hi]$ 内有 $n$ 个 $\min(a,b)$ 的倍数（$\min(a,b), 2\min(a,b), \ldots, n\min(a,b)$），它们都是神奇数，故 $c(hi) \ge n$。设不变式成立，取 $mid \in [lo, hi)$：若 $c(mid) \ge n$，令 $hi \leftarrow mid$，则 $c(hi) \ge n$ 保持，$c(lo-1) < n$ 不变；若 $c(mid) < n$，令 $lo \leftarrow mid+1$，由引理 2 得 $c(lo - 1) = c(mid) < n$，而 $c(hi) \ge n$ 不变。∎

**定理**：算法返回第 $n$ 个神奇数。

**证明**：循环结束时 $lo = hi$，由引理 3 有 $c(lo) \ge n$ 且 $c(lo-1) < n$，即 $lo$ 是神奇数且其前面恰有 $n-1$ 个神奇数，故 $lo$ 是第 $n$ 个神奇数。最后取模不影响「是第几个」的判定（取模只改变数值表示，不改变它对应的位置）。∎

## 6. 复杂度分析

- **时间**：$O(\log(\min(a,b)\cdot n))$。二分区间长度不超过 $4\times10^{13}$，约 $46$ 轮，每轮一次 gcd（只在开始时算一次）与三次整数除法，$O(1)$。
- **空间**：$O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int nthMagicalNumber(int n, int a, int b) {
        const long long MOD = 1000000007LL;
        long long g = std::gcd(a, b);
        long long lcm = (long long)a / g * b;
        long long lo = 1, hi = (long long)min(a, b) * n;   // 答案不超过 n*min(a,b)
        while (lo < hi) {
            long long mid = lo + (hi - lo) / 2;
            long long cnt = mid / a + mid / b - mid / lcm;  // 容斥：≤mid 的神奇数
            if (cnt >= n) hi = mid;
            else lo = mid + 1;
        }
        return (int)(lo % MOD);
    }
};
```

### Python

```python
from math import gcd

class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        lcm = a // gcd(a, b) * b
        lo, hi = 1, min(a, b) * n        # 第 n 个不超过 n*min(a,b)
        while lo < hi:
            mid = (lo + hi) // 2
            if mid // a + mid // b - mid // lcm >= n:
                hi = mid
            else:
                lo = mid + 1
        return lo % (10 ** 9 + 7)
```

## 8. 边界情况与易错点

1. **`int` 溢出**：`hi`、`cnt`、`lcm` 都必须用 64 位。这是本题最主要的 WA 来源：`hi = min(a,b)*n` 在 $n = 10^9$ 时可达 $4\times10^{13}$。
2. **二分中取模**：绝对不能在二分内部对 `mid`、`cnt` 取模，否则单调性被破坏，答案完全随机。
3. **公共倍数重复计数**：只写 `mid/a + mid/b`、忘了减 `mid/lcm`，答案会偏小。
4. **`lcm` 计算顺序**：`a / gcd * b` 先除后乘，避免 `a*b` 溢出；反过来写在小值域也无妨，但习惯要养好。
5. **`a == b`**：此时 $\mathrm{lcm} = a$，公式退化为 $\lfloor x/a\rfloor$，答案应为 $n \cdot a$；二分同样收敛到它，无需特判。
6. **`n = 1`**：答案 $= \min(a,b)$；若把 `hi` 写成 `min(a,b) - 1` 会出错。
7. **取模后的值可能小于真实答案**：题目要求返回取模值，不要试图「还原」真实值。
