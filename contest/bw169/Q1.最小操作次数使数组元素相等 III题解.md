# LeetCode 最小操作次数使数组元素相等 III 题解

## 1. 题目概述

- **标题 / 题号**：最小操作次数使数组元素相等 III（#3736，easy）
- **链接**：https://leetcode.cn/problems/minimum-moves-to-equal-array-elements-iii/
- **来源**：LeetCode 第 169 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 `nums`。每步操作可把**任意一个**元素加 $1$（注意：只能加，不能减）。问最少多少步能让数组所有元素**相等**。

**约束**：

- $1 \le nums.length \le 100$
- $1 \le nums[i] \le 100$

> 💡 本题是「只能加」的版本。一旦允许减小，问题立刻变性质（参见文末《相关题目与扩展》里的 453 题），务必看清操作方向。

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,3]
输出：3
解释：把 2 加到 3（1 步），把 1 加到 3（2 步），共 3 步；全部变成 3。
```

**示例 2**

```text
输入：nums = [4,4,5]
输出：2
解释：两个 4 各自加 1 变成 5，共 2 步。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「最终的公共值」$t$，再扫一遍数组统计代价 $\sum_i (t - nums[i])$，取最小值：

$$ans = \min_{t}\ \sum_{i=0}^{n-1} (t - nums[i])$$

因为只能加不能减，$t$ 至少为 $\max(nums)$，否则有元素需要减小，非法。暴力若把 $t$ 枚举到 $\max + 100$，复杂度 $O(n \cdot 100)$，本题数据下也能过，但完全没必要枚举——代价值关于 $t$ 是**单调递增**的。

### 3.2 核心观察：目标值只能是最大值

![只能加不能减，所有元素最终都必须抬到 max](images/bw169_q1_push_to_max.svg)

把代价写成 $t$ 的函数：

$$f(t) = \sum_{i}(t - nums[i]) = n \cdot t - \sum_i nums[i]$$

由于 $n \ge 1$，斜率 $n > 0$，$f(t)$ 在 $t$ 上**严格单调递增**。而 $t$ 的可行下界正是 $t_0 = \max(nums)$（更小的 $t$ 会让最大值元素需要减小，非法）。因此最优解就是 $t = \max(nums)$，答案为：

$$ans = n \cdot \max(nums) - \sum_i nums[i]$$

**一句话**：每个元素独立地「补到最大值」，总和即为答案——不存在「先抬到更高值再省步数」的可能，因为抬得越高，每个元素都要多付。

### 3.3 算法流程

![算法流程：一趟求 max 与 sum，再一次减出答案](images/bw169_q1_algorithm_flow.svg)

```text
1. mx = max(nums), s = sum(nums)
2. 返回 n * mx - s
```

一趟遍历可同时维护 `mx` 与 `s`。

### 3.4 示例演算

对 `nums = [2,1,3]`：

| 下标 i | nums[i] | max | 补到 max 需要 |
|--------|---------|-----|---------------|
| 0 | 2 | 3 | +1 |
| 1 | 1 | 3 | +2 |
| 2 | 3 | 3 | +0 |
| 合计 | sum = 6 | — | 3 |

验证公式：$3 \times 3 - 6 = 3$ ✓。对 `nums = [4,4,5]`：$3 \times 5 - 13 = 2$ ✓。

## 4. 算法细节

1. **一次遍历**：`mx` 与 `s` 可在同一个循环里更新，无需两次扫描。
2. **用公式而非循环累加**：`n * mx - s` 与逐个累加 `mx - nums[i]` 等价，但少一层循环，也避免手写累加时把 `mx` 写错成 `nums[0]`。
3. **求和上界**：$n \le 100$、$nums[i] \le 100$，$s \le 10^4$、$n \cdot mx \le 10^4$，`int` 绰绰有余；若数据范围放大到 $10^9$，需改成 `long long`。
4. **空数组**：约束保证 $n \ge 1$，`max` 不会作用于空区间；若要做防御式编程，可先判空返回 0。

## 5. 正确性证明

**引理 1（可行域下界）**：任何合法终态的目标值 $t$ 都满足 $t \ge \max(nums)$。

**证明**：设 $j$ 为最大值所在下标。操作只能让元素增大，故 $nums[j]$ 的终值 $\ge nums[j] = \max(nums)$；所有元素终值都等于 $t$，于是 $t \ge \max(nums)$。∎

**引理 2（单元素代价）**：把 $nums[i]$ 从原值抬到 $t \ge nums[i]$ 恰好需要 $t - nums[i]$ 步，且这是下界。

**证明**：每次操作对该元素至多贡献 $1$ 的增量，需要净增 $t - nums[i]$，故至少 $t - nums[i]$ 步；而每次只对该元素加 $1$、重复 $t - nums[i]$ 次即可达到，故下界可取到。∎

**定理**：算法输出 $n \cdot \max(nums) - \sum_i nums[i]$ 等于最小总操作次数。

**证明**：由引理 1，只需在 $t \ge \max$ 中比较。由引理 2，目标值为 $t$ 时总代价为 $f(t) = \sum_i (t - nums[i]) = nt - \sum_i nums[i]$。因 $n \ge 1$，$f$ 关于 $t$ 严格递增，故在可行域上的最小值在 $t = \max(nums)$ 处取得，其值即 $n \max - \sum nums$。又各元素的代价互不影响（每次操作只改一个元素），总代价等于各元素代价之和，故该值可由「每个元素各自补到 max」这一策略实际达到，是最小值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟遍历同时求最大值与总和；公式计算 $O(1)$。
- **空间**：$O(1)$。只用了 `mx`、`s` 两个累加变量，未开额外数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minMoves(vector<int>& nums) {
        int mx = nums[0];
        int sum = 0;
        for (int x : nums) {
            mx = max(mx, x);
            sum += x;
        }
        return mx * (int)nums.size() - sum;
    }
};
```

### Python

```python
class Solution:
    def minMoves(self, nums: list[int]) -> int:
        mx = max(nums)
        return mx * len(nums) - sum(nums)
```

## 8. 边界情况与易错点

1. **「只能加」被误读成「可加可减」**：若允许减小，答案会变成 $\sum_i (\max - nums[i])$ 之外的另一种形式（实际是 453 题的「每次给 $n-1$ 个元素加 1」模型），两者数值恰好相同但推导完全不同；更危险的是误以为可以「降到最小值」，那会得到另一个答案。
2. **目标值取成最小值**：把 $t$ 设成 $\min(nums)$ 会出现负代价，答案错得离谱。
3. **单元素数组**：$n = 1$ 时 $1 \cdot nums[0] - nums[0] = 0$，公式天然正确，无需特判。
4. **整数溢出**：本题 `int` 足够；若把约束放大到 $nums[i] \le 10^9$、$n \le 10^5$，$n \cdot mx$ 会到 $10^{14}$，必须用 `long long` / Python 大整数。
5. **累加方向写反**：`sum - mx * n` 会得到负数，注意被减数与被减数顺序。

**延伸思考**：三题串起来看，「让数组相等」的最小代价完全由**代价函数形状**决定：只能加 → 端点 $\max$；只能减 → 端点 $\min$；可加可减（$L_1$）→ 中位数；平方代价（$L_2$）→ 均值。把这三四种情形记住，遇到变形就能一眼定位到「目标值该取哪个统计量」。
