# LeetCode 统计主要元素子数组数目 I 题解

## 1. 题目概述

- **标题 / 题号**：统计主要元素子数组数目 I（#3737，medium）
- **链接**：https://leetcode.cn/problems/count-subarrays-with-majority-element-i/
- **来源**：LeetCode 第 169 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数、前缀和

**题意**：给定整数数组 `nums` 与整数 `target`。若 `target` 在某个子数组中出现的次数**严格大于**该子数组长度的一半，则称 `target` 是该子数组的**主要元素**。求 `nums` 中所有**非空连续子数组**里，以 `target` 为主要元素的子数组个数。

形式化地说，对子数组 $nums[l..r]$（长度 $\text{len} = r-l+1$），记

$$\text{cnt}(l,r) = \sum_{k=l}^{r} [nums[k] = target]$$

则该子数组合法当且仅当 $2 \cdot \text{cnt}(l,r) > \text{len}$。

**约束**：

- $1 \le nums.length \le 1000$
- $1 \le nums[i] \le 10^9$
- $1 \le target \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,2,3], target = 2
输出：5
解释：合法的子数组为
      [2]（下标 1）、[2]（下标 2）、[2,2]（下标 1..2）、
      [1,2,2]（下标 0..2）、[2,2,3]（下标 1..3）。
```

**示例 2**

```text
输入：nums = [1,1,1,1], target = 1
输出：10
解释：全部 4*5/2 = 10 个子数组都以 1 为主要元素。
```

**示例 3**

```text
输入：nums = [1,2,3], target = 4
输出：0
解释：4 根本没出现，任何子数组都不可能以它为主要元素。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的写法是三处循环：枚举左右端点 $l \le r$，再内部扫一遍数 `target` 的出现次数，复杂度 $O(n^3)$，$n = 1000$ 时约 $10^9$，不可接受。但「内部数一遍」完全多余——固定左端点 $l$、让 $r$ 从左到右移动时，`cnt` 只会因为 $nums[r]$ 是否为 `target` 而 $+1$ 或不变，可以**增量维护**，于是复杂度降到 $O(n^2)$，约 $5 \times 10^5$ 次操作，轻松通过。

### 3.2 核心观察：把「主要」翻译成一次乘法比较

![主要元素判定：2*cnt 与窗口长度 len 比大小](images/bw169_q2_majority_condition.svg)

判定式 $2 \cdot \text{cnt} > \text{len}$ 有两个好处：

- **避免浮点**：不用写 `cnt > len / 2`（整数除法会把 $\text{len}=3, \text{cnt}=2$ 误判）。
- **等价于「权重和为正」**：令 $w_i = +1$（$nums[i] = target$）或 $-1$（否则），则

$$\sum_{k=l}^{r} w_k = \text{cnt} - (\text{len} - \text{cnt}) = 2\text{cnt} - \text{len}$$

于是「`target` 是主要元素」$\iff$ 区间权重和 $> 0$。这个改写让「求个数」变成「数非负前缀差」的问题——本题 $n \le 1000$ 用不上，但正是下一题（II 版）$n \le 10^5$ 的钥匙。

### 3.3 算法流程

![算法流程：固定左端点，右端点增量扩展](images/bw169_q2_algorithm_flow.svg)

```text
1. ans = 0
2. for l = 0 .. n-1:
       cnt = 0
       for r = l .. n-1:
           若 nums[r] == target:  cnt += 1
           若 2 * cnt > r - l + 1:  ans += 1
3. 返回 ans
```

### 3.4 示例演算

对示例 1 的 `nums = [1,2,2,3]`、`target = 2`，把每个左端点的扩展过程列成表（✓ 表示计入答案）：

| l | r | 子数组 | cnt | 2·cnt | len | 合法 |
|---|---|--------|-----|-------|-----|------|
| 0 | 0 | [1] | 0 | 0 | 1 | ✗ |
| 0 | 1 | [1,2] | 1 | 2 | 2 | ✗（需严格大于） |
| 0 | 2 | [1,2,2] | 2 | 4 | 3 | ✓ |
| 0 | 3 | [1,2,2,3] | 2 | 4 | 4 | ✗（平局不算） |
| 1 | 1 | [2] | 1 | 2 | 1 | ✓ |
| 1 | 2 | [2,2] | 2 | 4 | 2 | ✓ |
| 1 | 3 | [2,2,3] | 2 | 4 | 3 | ✓ |
| 2 | 2 | [2] | 1 | 2 | 1 | ✓ |
| 2 | 3 | [2,3] | 1 | 2 | 2 | ✗ |
| 3 | 3 | [3] | 0 | 0 | 1 | ✗ |

合计 5 个，与示例输出一致。注意两处「边界平局」都被正确排除：`[1,2]` 与 `[2,3]` 是 $2\text{cnt} = \text{len}$，`[1,2,2,3]` 是 $2\text{cnt} = 4 = \text{len}$。

## 4. 算法细节

1. **增量计数**：`cnt` 在 $r$ 增加时只按 $nums[r]$ 是否等于 `target` 更新，避免重复扫描区间。
2. **比较用乘法**：`2 * cnt > len`，不要写 `cnt > len / 2`（整数除法会丢掉 $0.5$）。
3. **`target` 不在数组中**：可以在开头 `count` 一次直接返回 0（示例 3），也可以什么都不做——此时 `cnt` 恒为 0，判定永不成立，答案自然是 0。两者都对，前者省时间。
4. **答案规模**：$n \le 1000$ 时子数组总数 $\frac{n(n+1)}{2} \le 500500$，`int` 足够；但若迁移到 $n \le 10^5$（II 版），最大可达约 $5 \times 10^9$，**必须**用 `long long`。
5. **值域无关**：$nums[i]$ 可达 $10^9$，但只做等值比较、不开桶数组，所以值域不影响实现。

## 5. 正确性证明

**引理 1（判定式等价）**：对任意子数组 $nums[l..r]$，$\text{target}$ 是其主要元素 $\iff 2 \cdot \text{cnt}(l,r) > r - l + 1$。

**证明**：设长度为 $\text{len}$，`target` 出现 $\text{cnt}$ 次。「严格大于一半」即 $\text{cnt} > \text{len}/2$。两边乘以正整数 $2$ 得 $2\text{cnt} > \text{len}$，不等式方向不变，与原条件等价。∎

**引理 2（增量维护的正确性）**：在固定 $l$、$r$ 从 $l$ 递增的循环中，每轮结束时变量 `cnt` 恰等于 $\text{cnt}(l,r)$。

**证明**：对 $r$ 归纳。$r = l$ 时初始 `cnt = 0`，随后按 $nums[l] = target$ 与否加 $0/1$，得 $\text{cnt}(l,l)$。设第 $r-1$ 轮结束时 `cnt` $=\text{cnt}(l,r-1)$，则第 $r$ 轮按 $nums[r]$ 加 $0/1$，得到 $\text{cnt}(l,r-1) + [nums[r] = target] = \text{cnt}(l,r)$。∎

**定理**：算法输出的 `ans` 等于以 `target` 为主要元素的子数组个数。

**证明**：外层循环枚举了全部 $l \in [0, n-1]$，内层枚举了全部 $r \in [l, n-1]$，因此每个非空子数组 $nums[l..r]$ 被**恰好访问一次**，不存在重复计数或遗漏。由引理 2，访问时 `cnt` 正是该子数组中 `target` 的出现次数；由引理 1，判定条件与「主要元素」定义等价。故每当且仅当该子数组合法时 `ans` 加 1，最终 `ans` 即所求。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。外层 $n$ 次，内层平均 $n/2$ 次，合计约 $\frac{n(n+1)}{2}$ 次 $O(1)$ 判定；$n = 1000$ 时约 $5 \times 10^5$ 次。
- **空间**：$O(1)$。只用了 `ans`、`cnt`、循环变量，未开数组或哈希表（无递归栈）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countMajoritySubarrays(vector<int>& nums, int target) {
        int n = (int)nums.size();
        int ans = 0;
        for (int l = 0; l < n; l++) {
            int cnt = 0;
            for (int r = l; r < n; r++) {
                if (nums[r] == target) cnt++;
                if (2 * cnt > r - l + 1) ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countMajoritySubarrays(self, nums: list[int], target: int) -> int:
        n = len(nums)
        ans = 0
        for l in range(n):
            cnt = 0
            for r in range(l, n):
                if nums[r] == target:
                    cnt += 1
                if 2 * cnt > r - l + 1:
                    ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **「严格大于」被写成「大于等于」**：`[1,2]`（$2\text{cnt} = \text{len} = 2$）会被误判为合法，答案偏大。示例 1 里恰好有三个这种平局，是最容易踩的坑。
2. **整数除法判一半**：`cnt > len / 2` 在 $\text{len}$ 为奇数时把 $\text{cnt} = \lceil \text{len}/2 \rceil$ 的情形误杀（如 $\text{len}=3,\text{cnt}=2$：`2 > 1` 侥幸成立，但 $\text{len}=5,\text{cnt}=3$ 时 `3 > 2` 也成立——真正会出错的是 $\text{len}=2,\text{cnt}=1$ 之外的情形，总之不要冒险，统一用乘法）。
3. **`target` 不存在**：答案必为 0（示例 3）。逻辑上已自动成立，但显式提前返回可省一遍 $O(n^2)$。
4. **答案溢出（为 II 版埋雷）**：$n = 1000$ 时 `int` 够；但同一份代码搬到 $n = 10^5$ 的 II 版会溢出，这也是 II 版必须换算法的信号之一。
5. **单元素子数组**：`[target]` 天然合法（$2 > 1$），循环不会漏掉——只要内层从 `r = l` 开始。
6. **别排序**：子数组统计类问题一旦排序就丢掉了位置信息，注意不要顺手 `sort(nums)`。
