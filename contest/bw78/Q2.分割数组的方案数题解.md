# LeetCode 分割数组的方案数 题解

## 1. 题目概述

- **标题 / 题号**：分割数组的方案数（#2270，medium）
- **链接**：https://leetcode.cn/problems/number-of-ways-to-split-array/
- **来源**：LeetCode 第 78 场双周赛 Q2
- **难度**：中等
- **标签**：数组、前缀和

**题意**：给定下标从 0 开始、长度为 $n$ 的整数数组 `nums`。下标 $i$ 处存在**合法分割**当且仅当：(1) 前 $i+1$ 个元素之和 **大于等于** 后 $n-i-1$ 个元素之和；(2) $i$ 右侧至少有一个元素，即 $0 \le i < n-1$。返回合法分割的方案数。

**约束**：

- $2 \le nums.length \le 10^5$
- $-10^5 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [10,4,-8,7]
输出：2
解释：i=0：10 ≥ 3 ✓；i=1：14 ≥ −1 ✓；i=2：6 < 7 ✗。共 2 种。
```

**示例 2**

```text
输入：nums = [2,3,1,0]
输出：2
解释：i=1：5 ≥ 1 ✓；i=2：6 ≥ 0 ✓。（i=0：2 < 4 ✗）
```

**示例 3（边界补充）**

```text
输入：nums = [-1, -2]
输出：1
解释：i=0：左和 −1，右和 −2，−1 ≥ −2 ✓（负数比较照常进行）。答案 1。
```

```text
输入：nums = [-3, 1]
输出：0
解释：i=0：左和 −3，右和 1，−3 < 1 ✗。唯一分割不合法，答案 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 $i \in [0, n-2]$ 现场累加两侧求和再比较，$O(n^2)$；$n = 10^5$ 时 $10^{10}$ 次操作超时。和上一题（最小平均差）完全同构的瓶颈：左右两段的和被反复重算，而相邻分割点之间和只差一个元素。

### 3.2 核心观察：前缀和 + 总和作差，判定化为 2·pre ≥ total

![前缀和模型：pre 与 total−pre 的比较](images/bw78_q2_prefix_model.svg)

记 $pre_i = \sum_{k \le i} nums[k]$、$total = pre_{n-1}$。分割点 $i$ 合法 $\iff$

$$pre_i \ge total - pre_i \iff 2 \cdot pre_i \ge total。$$

一遍扫描维护 $pre$ 增量，每个 $i$ 判定 $O(1)$。注意两点：右侧和是 $total - pre_i$（**包含** $nums[i]$ 之后的全部元素）；$i$ 的上界是 $n-2$（右边至少留一个元素）。

### 3.3 算法流程

```text
1. total = Σ nums（long long）
2. pre = 0，ans = 0
3. 对 i = 0 .. n−2：                 # 右侧至少留 nums[n−1]
       pre += nums[i]
       若 2 × pre ≥ total：ans += 1
4. 返回 ans
```

### 3.4 示例演算

![示例演算：四个分割点的判定表](images/bw78_q2_walkthrough.svg)

以示例 1（`nums = [10,4,-8,7]`，$total = 13$）为例：

| $i$ | $pre_i$ | 右和 | $2 \cdot pre_i$ | ≥ 13？ | 计数 |
|-----|---------|------|-----------------|--------|------|
| 0 | 10 | 3 | 20 | ✓ | +1 |
| 1 | 14 | −1 | 28 | ✓ | +1 |
| 2 | 6 | 7 | 12 | ✗ | — |

（$i = 3$ 不考虑：右侧为空。）答案 $2$ ✓。

## 4. 算法细节

1. **求和必须 64 位**：$n \le 10^5$、$\lvert nums[i] \rvert \le 10^5$，$total$ 与 $pre$ 的绝对值上界 $10^{10}$，`int`（约 $2.1 \times 10^9$）必溢出。C++ 用 `long long`；Python 原生大整数免虑。注意**负数**也参与求和，绝对值上界按 $\lvert \cdot \rvert$ 估计。
2. **循环上界 $n - 2$**：`for (i = 0; i + 1 < n; ++i)`。写成 `i < n` 会把「右侧为空」的 $i = n-1$ 也算进去——右侧和为 0 时 $pre \ge 0$ 恒真，多计一次。
3. **判定的等价变形**：`pre >= total - pre` 与 `2 * pre >= total` 等价（整数域移项无损）；后者少一次减法，也避免「先减后比」在负数边界的视觉错觉。两者都对，写哪个都行。
4. **负数的比较语义**：本题不是「非负和」，$pre$ 可以是负数、右侧和也可以是负数（示例 1 的 $i=1$：$14 \ge -1$）。比较是普通的有符号比较，无需任何特判。
5. **不重不漏**：每个 $i$ 独立判定，天然计数所有合法分割；无需担心「同一分割被计两次」（$i$ 唯一确定分割位置）。

## 5. 正确性证明

**引理 1（分割与下标一一对应）**：合法分割由且仅由下标 $i \in [0, n-2]$ 确定；下标 $i$ 对应的分割为 $nums[0..i] \mid nums[i+1..n-1]$，两段均非空。

**证明**：分割把数组切成左右两段连续部分，由切点位置唯一确定；左边含 $i+1$ 个元素、右边含 $n-i-1$ 个元素。「右边至少一个元素」即 $n - i - 1 \ge 1 \iff i \le n - 2$；左段非空即 $i \ge 0$（$n \ge 2$ 保证存在）。反之每个 $i \in [0, n-2]$ 给出唯一的合法切法。∎

**引理 2（前缀和递推）**：扫描到下标 $i$ 时 `pre` 的值为 $\sum_{k=0}^{i} nums[k]$；右侧和为 $total - pre$。

**证明**：对 $i$ 归纳：$i=0$ 时 `pre = nums[0]`；设 $i-1$ 轮末 `pre` $= \sum_{k \le i-1} nums[k]$，$i$ 轮执行 `pre += nums[i]` 后即 $\sum_{k \le i} nums[k]$。而 $total = \sum_{k=0}^{n-1} nums[k]$，故右侧和 $\sum_{k=i+1}^{n-1} nums[k] = total - \sum_{k \le i} nums[k] = total - pre$。∎

**定理（算法正确性）**：算法返回值等于合法分割数。

**证明**：由引理 1，合法分割与下标集 $\{0, \dots, n-2\}$ 一一对应，算法遍历的正是该集合。对每个 $i$，由引理 2，判定条件 `2 * pre >= total` 等价于 $pre_i \ge total - pre_i$，即「前 $i+1$ 个元素之和 ≥ 后 $n-i-1$ 个元素之和」——恰为题面的合法性条件。计数器对每个真判定加一，终值即合法分割数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次 $O(n)$ 求 `total`，一次 $O(n)$ 扫描判定；总计约 $2n$ 次加法与 $n$ 次比较。
- **空间**：$O(1)$ 额外空间。仅维护 `total / pre / ans` 三个变量，无前缀和数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int waysToSplitArray(vector<int>& nums) {
        int n = nums.size();
        long long total = 0;
        for (int x : nums) total += x;
        long long pre = 0;
        int ans = 0;
        for (int i = 0; i + 1 < n; ++i) {       // 右侧至少留一个元素
            pre += nums[i];
            if (2 * pre >= total) ++ans;        // pre >= total − pre
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def waysToSplitArray(self, nums: list[int]) -> int:
        n = len(nums)
        total = sum(nums)
        pre = 0
        ans = 0
        for i in range(n - 1):                  # 右侧至少留一个元素
            pre += nums[i]
            if 2 * pre >= total:                # pre >= total − pre
                ans += 1
        return ans
```

> 💡 两份代码均通过官方示例（`2`、`2`），并与「逐下标重新求和」的暴力对拍 2000 组随机数据（含全负、正负交替、$n = 2$ 最小规模、右和为 0 边界），`mismatch = 0`。

## 8. 边界情况与易错点

1. **溢出**：$total$、$pre$ 绝对值上界 $10^{10}$，C++ 必须 `long long`；判 `2 * pre` 时 `pre` 已是 64 位则安全，若 `pre` 是 `int` 乘 2 也溢出——全程 64 位。
2. **循环边界**：上界 $n - 2$（即 `i + 1 < n`）。包含 $i = n-1$ 会在右侧和为 0 时多计（例如全零数组本应答案 $n-1$，写错成 $n$）。
3. **负数不是异常**：$pre$、右和均可负，普通有符号比较即可；不要画蛇添足取绝对值或夹挤。
4. **「大于等于」含等号**：$pre_i = total - pre_i$（左右和相等）是合法分割，条件写 `>` 会漏计。
5. **$n = 2$ 最小规模**：只有 $i = 0$ 一个候选分割，判定 $2 \cdot nums[0] \ge total$；循环边界正确时无需特判。
6. **不要排序**：分割保持原序，排序后下标语义全毁——这是从「中位数/第 K 大」类题迁移来的惯性错误。
