# LeetCode 不同三位偶数的数目 题解

## 1. 题目概述

- **标题 / 题号**：不同三位偶数的数目（#3483，easy）
- **链接**：https://leetcode.cn/problems/unique-3-digit-even-numbers/
- **来源**：LeetCode 第 152 场双周赛 Q1
- **难度**：简单
- **标签**：递归、数组、哈希表、枚举

**题意**：给定一个数字数组 `digits`，从中选出**三个数字**组成一个三位偶数，求能组成多少个**不同**的三位偶数。

限制：每个**位置**上的数字只能使用 `digits` 中的一个元素各一次（即三个数字必须来自**三个不同的下标**）；三位数**不能有前导零**。

**约束**：

- $3 \le digits.length \le 10$
- $0 \le digits[i] \le 9$

## 2. 示例

**示例 1**

```text
输入：digits = [1,2,3,4]
输出：12
解释：124、132、134、142、214、234、312、314、324、342、412、432。
      222 不行——数组里只有一个 2。
```

**示例 2**

```text
输入：digits = [0,2,2]
输出：2
解释：202 与 220。数字 2 可以用两次，因为数组里本来就两个 2；
      022 有前导零，不合法。
```

**示例 3**

```text
输入：digits = [6,6,6]
输出：1
解释：只能组成 666。
```

**示例 4**

```text
输入：digits = [1,3,5]
输出：0
解释：没有偶数，个位凑不出偶数字，答案是 0。
```

## 3. 解题思路

### 3.1 暴力思路

$n \le 10$，三位数的每个位置只需枚举一个**下标**，三层循环共 $10^3 = 1000$ 种下标组合，每种组合 $O(1)$ 判合法，再把数值塞进集合去重。总代价一千次判断，完全不用优化——**本题就是让你老老实实枚举**。

但"按值枚举"或"用乘法原理直接算个数"都会翻车，原因值得写清楚：`digits` 里的**值可以重复**（`[0,2,2]`、`[6,6,6]`），必须按**下标**枚举，才能正确表达"同一个数字值最多用几次"。

### 3.2 核心观察：枚举下标，用集合去重

![三层枚举：分别挑百位、十位、个位，再丢进集合去重](images/bw152_q1_triple_scan.svg)

- **按值算为什么错**：设 `digits = [0,2,2]`。若按"百位 2 种 × 十位 2 种 × 个位 2 种"硬乘，会算出 $222$、$022$ 这些根本凑不出来的数——$222$ 需要三个 $2$，而数组里只有两个；$022$ 则有前导零。
- **按下标枚举为什么对**：数字值相同的不同下标被视为"可替换的座位"。三层下标循环天然保证每个位置用的是**不同的元素**，重复值的可用次数也就自动正确。
- **去重交给集合**：不同的下标组合可能拼出同一个数（例如 `[1,2,3,4]` 里 `1,2,4` 只有一种方式，但当值重复时组合会变多）。用 `unordered_set<int>` 存数值，最后返回集合大小。

两道闸门：

1. 百位数字不能是 $0$（前导零）；
2. 个位数字必须是偶数（$0,2,4,6,8$，注意 $0$ 是偶数，允许出现在个位）。

### 3.3 算法流程

```text
1. seen = 空集合
2. for i in 0..n-1:                       # 百位下标
       if digits[i] == 0: 跳过            # 前导零
       for j in 0..n-1:                   # 十位下标
           if j == i: 跳过
           for l in 0..n-1:               # 个位下标
               if l == i 或 l == j: 跳过
               if digits[l] 是奇数: 跳过
               seen.add(100*digits[i] + 10*digits[j] + digits[l])
3. 返回 |seen|
```

### 3.4 示例演算

![三个示例的关键差别：数字值能否重复使用](images/bw152_q1_example_walkthrough.svg)

以 `digits = [1,2,3,4]` 为例，固定百位为 1 时，个位只能取 $2$ 或 $4$：

| 百位 | 个位 | 十位可选 | 得到的数 |
|------|------|----------|----------|
| 1 | 2 | 3、4 | 132、142 |
| 1 | 4 | 2、3 | 124、134 |
| 2 | 4 | 1、3 | 214、234 |
| 3 | 2 | 1、4 | 312、342 |
| 3 | 4 | 1、2 | 314、324 |
| 4 | 2 | 1、3 | 412、432 |

共 12 个，与示例 1 输出一致。`[0,2,2]` 时百位只能是 $2$（唯一的非零值）：个位取 $2$（另一下标），十位取剩下的 $0$ 或另一个 $2$，得到 $202$、$220$；`[1,3,5]` 没有偶数，集合为空。

## 4. 算法细节

1. **下标互不相同**：三层循环里分别跳过 `j == i`、`l == i || l == j`。这里不比较**值**是否相等，比较的是**下标**——这是本题最核心的细节。
2. **前导零**：只在百位判 `digits[i] == 0` 即可跳过；十位是个零完全没问题（例如 $202$）。
3. **个位偶数**：`digits[l] % 2 == 0`。`0 % 2 == 0`，所以 $0$ 可以做个位（如 $130$）。
4. **数值拼接**：`100*a + 10*b + c`，三位数最大 $987$，`int` 完全够用。
5. **去重容器**：`unordered_set<int>` 或 Python 的 `set`；最多 $10^3$ 个候选，去重后不超过 $900$ 个，开销可忽略。

## 5. 正确性证明

**引理 1（枚举覆盖所有合法数）**：若某个整数 $N = 100a + 10b + c$ 能由题目规则组成，则存在互不相同的下标 $(i,j,l)$ 使 $digits[i] = a$、$digits[j] = b$、$digits[l] = c$，且 $a \ne 0$、$c$ 为偶数。

**证明**：题目要求"从 `digits` 中选择三个数字、每个数字只能使用一次"，按位置逐一对应，就是选出三个互不相同的下标并分别作为百、十、个位；前导零与三位偶数的要求给出 $a \ne 0$ 与 $c$ 为偶数。∎

**引理 2（枚举不产生非法数）**：三层下标循环中加入 `seen` 的每个数都是合法的三位偶数，且只与 `digits` 中可用的值有关。

**证明**：加入前已检查 `digits[i] != 0`（百位非零）、`digits[l] % 2 == 0`（个位偶数）、三个下标互不相同（每个元素至多用一次），拼接式给出恰好三位数，故全部合法。∎

**引理 3（去重完整）**：`seen` 中的每个值只出现一次，且覆盖引理 1 中的全部 $N$。

**证明**：集合的性质保证唯一性。覆盖性：对引理 1 给出的合法 $N$ 与其下标三元组 $(i,j,l)$，算法会枚举到该三元组（三层循环穷尽所有互异下标组合），把 $N$ 插入集合。∎

**定理**：算法返回的值等于不同三位偶数的个数。

**证明**：由引理 2，集合大小不超过真实答案；由引理 3，真实答案中的每个数都在集合里，故集合大小不小于真实答案。两者相等。∎

## 6. 复杂度分析

- **时间**：$O(n^3)$ 次下标组合枚举，每次 $O(1)$ 判断加一次哈希插入（均摊 $O(1)$），总计 $O(n^3)$；$n \le 10$ 时最多 1000 次。
- **空间**：$O(D)$，$D$ 为不同三位偶数的个数，最多 $900$（三位偶数总数），实际受输入限制远小于此。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int totalNumbers(vector<int>& digits) {
        int n = (int)digits.size();
        unordered_set<int> seen;
        for (int i = 0; i < n; i++) {
            if (digits[i] == 0) continue;          // 百位不能为 0
            for (int j = 0; j < n; j++) {
                if (j == i) continue;
                for (int l = 0; l < n; l++) {
                    if (l == i || l == j) continue;
                    if (digits[l] % 2 != 0) continue;   // 个位必须是偶数
                    seen.insert(digits[i] * 100 + digits[j] * 10 + digits[l]);
                }
            }
        }
        return (int)seen.size();
    }
};
```

### Python

```python
class Solution:
    def totalNumbers(self, digits: list[int]) -> int:
        n = len(digits)
        seen = set()
        for i in range(n):
            if digits[i] == 0:            # 百位不能为 0
                continue
            for j in range(n):
                if j == i:
                    continue
                for l in range(n):
                    if l == i or l == j:
                        continue
                    if digits[l] % 2:     # 个位必须是偶数
                        continue
                    seen.add(digits[i] * 100 + digits[j] * 10 + digits[l])
        return len(seen)
```

## 8. 边界情况与易错点

1. **按值而非按下标枚举**：这是最常见的错误。`[0,2,2]` 若允许同一个 $2$ 反复取用，会多出 $222$、$022$ 之类的非法结果。
2. **忘记前导零**：`[0,2,2]` 里 `022` 不是三位数，必须由百位判断挡掉；注意十位的 $0$ 是完全合法的。
3. **把 0 当成非偶数**：`0 % 2 == 0`，$0$ 必须是合法的个位数字，否则 `[0,1,3]` 会漏掉 $130$、$310$（正确输出为 2）。
4. **$n = 3$ 且值重复**：如 `[6,6,6]`，只有 $666$ 一个，答案 1；若用"排列数"公式 $3!/3! = 1$ 会碰巧对，但换成 `[0,2,2]` 就会错。
5. **用集合而不是计数器**：题目问"不同三位偶数的数目"，重复出现的同一数值只能计一次。
6. **全奇数输入**：`[1,3,5]` 直接得空集合，返回 0，不要漏掉这个分支的打印/返回。
