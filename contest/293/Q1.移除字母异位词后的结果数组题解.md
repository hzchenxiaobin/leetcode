# LeetCode 移除字母异位词后的结果数组 题解

## 1. 题目概述

- **标题 / 题号**：移除字母异位词后的结果数组（#2273，easy）
- **链接**：https://leetcode.cn/problems/find-resultant-array-after-removing-anagrams/
- **来源**：LeetCode 第 293 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串、排序

**题意**：给一个字符串数组 `words`。只要存在下标 $i$（$0 < i < |\text{words}|$）使得 `words[i-1]` 与 `words[i]` **互为字母异位词**（排序后相同），就可以删掉 `words[i]`；反复执行直到没有可删的下标，返回最终数组。题目保证：按任意顺序选择下标，结果都相同。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le |\text{words}[i]| \le 10$
- `words[i]` 仅由小写英文字母组成

> 💡 **签到题的两个关键点**：① 删除条件只看**相邻**两个字符串——不是全局去重；② 数据规模极小（$100 \times 10$），任何签名判定都绰绰有余，胜负手在**想清楚删完之后剩下什么**，而不是实现。

## 2. 示例

**示例 1**

```text
输入：words = ["abba","baba","bbaa","cd","cd"]
输出：["abba","cd"]
解释：bbaa ~ baba（删 bbaa）→ baba ~ abba（删 baba）→ cd ~ cd（删 cd），最终 ["abba","cd"]。
```

**示例 2**

```text
输入：words = ["a","b","c","d","e"]
输出：["a","b","c","d","e"]
解释：不存在互为字母异位词的相邻字符串，一次操作都不能做。
```

**示例 3（自拟，覆盖"不相邻的异位词"）**

```text
输入：words = ["ab","cd","ab"]
输出：["ab","cd","ab"]
解释："ab" 与 "cd"、"cd" 与 "ab" 都不是异位词，"cd" 永远删不掉，两个 "ab" 永远不会变成相邻——尽管它们互为异位词。
```

**示例 4（自拟，覆盖"同字母不同频次"）**

```text
输入：words = ["aab","ab","ba"]
输出：["aab","ab"]
解释："aab" 与 "ab" 字母频次不同，不是异位词；"ba" 与前一个 "ab" 互为异位词，被删除。
```

## 3. 解题思路

### 3.1 暴力思路：按题意直接模拟

老老实实模拟：反复扫描数组，找到任一满足 $\text{sig}(w_{i-1}) = \text{sig}(w_i)$ 的下标就删除 `words[i]`，直到扫不出可删下标。

- 每轮扫描 $O(n \cdot L)$，至多删 $n-1$ 个元素、每次删除伴随 $O(n)$ 搬移，总复杂度约 $O(n^2 L)$。
- 本题 $n \le 100$、$L \le 10$，暴力**完全能过**。但它把思考外包给了机器——签到题更值得做的是**一眼看出终态**，把模拟压成 $O(n \cdot L)$ 的一趟扫描，还能顺手证出题目所声称的"顺序无关"。

### 3.2 核心观察：删除只看相邻 ⇒ 极大异位词段各留一个

把数组按"相邻互为异位词"切成若干**极大段**：段内相邻两两互为异位词（由传递性，段内任意两个都互为异位词），段与段的交界处不是异位词。

> 💡 **一句话结论**：最终数组 = 每个极大段的**第一个元素**依次排列。段首是"删不动的锚点"，段内其余元素迟早被删。

![极大异位词段收缩为段首](images/wc293_q1_anagram_runs_concept.svg)

为什么删除后出现的新相邻不会引发失控的连锁反应（不像 1047 删除相邻重复项那样需要栈）？因为删除是**单向的**：只删右边的 `words[i]`、永远保住左边的 `words[i-1]`。设删除 `y` 后 `x` 与 `z` 变成新相邻：删 `y` 需要 $y \sim x$（左邻），若新相邻对也满足 $x \sim z$，则由传递性 $y \sim z$，而 `y`、`z` 原本就相邻 ⇒ 它们本就同段。**级联永远封死在段内，动不了段首**。

### 3.3 算法流程：一趟扫描 + 签名比较

给每个字符串算一个**规范签名**（排序串或 26 维频次向量），一趟扫描：`words[i]` 保留当且仅当 $i = 0$ 或 $\text{sig}[i] \ne \text{sig}[i-1]$（与**原始前驱**比较）。

![一趟扫描流程图](images/wc293_q1_anagram_scan_flow.svg)

### 3.4 示例演算

以 `words = ["abba","baba","bbaa","cd","cd"]` 为例，签名取排序串：

| i | words[i] | sig[i] | 与 sig[i−1] | 决策 |
|---|----------|--------|-------------|------|
| 0 | abba | aabb | —（i = 0） | 保留 ✓ |
| 1 | baba | aabb | 相同 | 删除 ✗ |
| 2 | bbaa | aabb | 相同 | 删除 ✗ |
| 3 | cd | cd | **不同** | 保留 ✓ |
| 4 | cd | cd | 相同 | 删除 ✗ |

结果 `["abba","cd"]`，与示例一致。

![示例演算与易错提示](images/wc293_q1_anagram_walkthrough.svg)

## 4. 算法细节

1. **签名怎么造**：排序串 `''.join(sorted(w))`（$O(L \log L)$）或频次向量 `cnt[26]`（$O(L + 26)$）。$L \le 10$，随便选，排序串手最短。
2. **不能拿"出现过的字母集合"当签名**：`"aab"` 与 `"ab"` 的出现集合都是 $\{a, b\}$，但频次不同、**不是**异位词（见示例 4）。签名必须完整编码字符多重集。
3. **比较对象**：与原始 `words[i-1]` 比较即可，无需维护"上一个保留元素"。两者等价：若 `words[i-1]` 被跳过，说明它与更早的保留元素同签名（同段），"当前类的代表"没变。写成与"上一个保留元素"比较同样正确。
4. **为什么不需要栈**：见 3.2——单向删除 + 异位词关系的传递性，把一切级联封死在段内。
5. **顺带的副产品**：若问"共执行了多少步操作"，答案固定为 $n - \text{段数}$，与顺序无关（每步恰好删掉一个非段首元素）。

## 5. 正确性证明

**引理 1（等价关系）**："互为字母异位词"（记 $\sim$）是字符串上的等价关系。

**证明**：$A \sim B$ 定义为字符多重集相等。相等关系自反、对称、传递，故 $\sim$ 是等价关系 □

**引理 2（段首永生）**：任何合法操作序列中，每个极大段的第一个元素永不被删。

**证明**：对段编号归纳。第 1 段段首是 `words[0]`，删除要求 $0 < i$，永不满足。设前 $k-1$ 个段的段首都永生，考察第 $k$ 段段首 $x$。$x$ 若在某时刻被删，需其当时左邻 $y$ 满足 $y \sim x$。$y$ 是 $x$ 左侧最近的幸存元素：若 $y$ 属于第 $k-1$ 段，由段交界处的极大性，第 $k-1$ 段的尾部元素与 $x$ 不互为异位词，而第 $k-1$ 段内两两异位词（引理 1 传递性），故第 $k-1$ 段全体与 $x$ 不互为异位词（否则交界对也是异位词，两段本会并成一段），删除条件不成立；若 $y$ 属于更早的段，意味着第 $k-1$ 段已全灭，与归纳假设（其段首永生）矛盾 □

**引理 3（终止时段内非首全灭）**：过程必终止（每步长度减 1）；终止时任何段的非首元素都已删除。

**证明**：反证：设终止时某段存在幸存的非首元素，取该段中最左侧的幸存非首元素 $s$（其段首 $f$ 由引理 2 幸存且在 $s$ 左侧）。由 $f$ 是段首，$f$ 与 $s$ 之间的原数组元素全部属于同一段，故 $s$ 当前的左邻 $t$（存在，因为 $f$ 幸存在前）要么是 $f$、要么是 $f$ 与 $s$ 之间的同段元素，都有 $t \sim s$——仍存在可删下标，与"终止"矛盾 □

**定理（终态刻画 + 顺序无关）**：任意操作顺序下，最终数组都是"各极大段段首依次排列"；一趟扫描（保留 `words[i]` $\iff i = 0$ 或 $\text{sig}[i] \ne \text{sig}[i-1]$）输出的正是这个数组。

**证明**：由引理 2、3，终态幸存集恰为全体段首；删除不改变剩余元素的相对顺序，故终态唯一且为段首序列——这也证明了题目所声称的"任意顺序结果相同"。一趟扫描挑选的恰是段首：$i$ 是段首 $\iff i = 0$ 或 `words[i]` 与 `words[i-1]` 不互为异位词 $\iff \text{sig}[i] \ne \text{sig}[i-1]$ ∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot L \log L)$（排序签名；本题 $L \le 10$），换 26 维计数签名则为 $O(n \cdot (L + 26))$。$n \le 100$、$L \le 10$，总共几千次字符级操作，毫秒级。
- **空间复杂度**：签名数组 $O(n \cdot L)$；若只保留"上一个签名"可降到 $O(L)$ 额外空间（输出数组本身 $O(n \cdot L)$ 不计）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<string> removeAnagrams(vector<string>& words) {
        int n = words.size();
        vector<string> sig(n);
        for (int i = 0; i < n; i++) {
            sig[i] = words[i];
            sort(sig[i].begin(), sig[i].end()); // 规范签名：排序串
        }
        vector<string> ans;
        for (int i = 0; i < n; i++) {
            if (i > 0 && sig[i] == sig[i - 1]) continue; // 段内非首：删
            ans.push_back(words[i]);                     // 段首：留
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def removeAnagrams(self, words: List[str]) -> List[str]:
        sig = [''.join(sorted(w)) for w in words]
        return [w for i, w in enumerate(words) if i == 0 or sig[i] != sig[i - 1]]
```

比赛一行版（对相邻两个各排一次序，量小无妨）：

```python
class Solution:
    def removeAnagrams(self, words: List[str]) -> List[str]:
        return [w for i, w in enumerate(words) if i == 0 or sorted(w) != sorted(words[i - 1])]
```

## 8. 边界情况与易错点

1. **不要全局去重**：只看相邻关系。`["ab","cd","ab"]` 原样返回；误用"按签名去重"会错成 `["ab","cd"]`（见示例 3）。
2. **出现集合 ≠ 频次多重集**：`"aab"` 与 `"ab"` 不是异位词，用 26 位"字母出现掩码"当签名会误判（见示例 4）。
3. **n = 1**：无操作，直接返回；循环从 $i = 1$ 起判定，天然处理。
4. **全相同 / 全不同**：`["a","a","a"] → ["a"]`；`["a","b","c"]` 原样返回。
5. **比较基准**：与原始前驱 `words[i-1]` 比较（与"上一个保留元素"比较等价，见 §4.3）；别把基准写成"上一个被删除的元素"之类的混乱变体。
6. **别被"任意顺序"吓到**：它不是暗示要枚举多种操作顺序，而是**终态唯一**的提示——直接构造终态即可。
