# LeetCode 按位与结果大于零的最长组合 题解

## 1. 题目概述

- **标题 / 题号**：按位与结果大于零的最长组合（#2275，medium）
- **链接**：https://leetcode.cn/problems/largest-combination-with-bitwise-and-greater-than-zero/
- **来源**：LeetCode 第 293 场周赛 Q3
- **难度**：中等
- **标签**：位运算、数组、哈希表、计数

**题意**：给定正整数数组 `candidates`，从中任意挑选若干数组成**组合**（子集，不要求连续），对组合内所有数做**按位与**。返回按位与结果**大于 0** 的最长组合的长度。

**约束**：

- $1 \le \text{candidates.length} \le 10^5$
- $1 \le \text{candidates}[i] \le 10^7$

> 💡 **本题的胜负手**：组合的可能性有 $2^n$ 种，但「AND > 0」这个条件只取决于一件事——**所有选中数是否共享某一个二进制位**。把视角从「数的集合」切换到「二进制位」上，$2^n$ 的搜索空间瞬间坍缩成 24 个计数器。

## 2. 示例

**示例 1**

```text
输入：candidates = [16,17,71,62,12,24,14]
输出：4
解释：组合 [16,17,62,24] 的按位与结果是 16 & 17 & 62 & 24 = 16 > 0，长度 4。
可以证明不存在按位与结果大于 0 且长度大于 4 的组合。
注意长度最大的组合可能不止一种：[62,12,24,14] 的按位与是 62 & 12 & 24 & 14 = 8 > 0。
```

**示例 2**

```text
输入：candidates = [8,8]
输出：2
解释：最长组合是 [8,8]，按位与结果 8 & 8 = 8 > 0。
```

**示例 3（自拟，覆盖单元素下界）**

```text
输入：candidates = [5]
输出：1
解释：单个正整数的按位与就是它自身，5 > 0，故答案至少为 1。
```

## 3. 解题思路

### 3.1 暴力思路：枚举子集

最直接的做法是枚举 `candidates` 的所有 $2^n$ 个子集，对每个子集计算按位并检查是否大于 0。$n \le 10^5$ 时子集数是天文数字，彻底不可行。

即使退一步做「增量式」搜索——往组合里逐个加数、一旦 AND 变成 0 就剪枝——由于每个正整数至少有一位是 1，搜索树依然指数级膨胀（例如全体都是 $111\cdots1$ 时，每个子集都合法）。

> 💡 **浪费在哪**：我们反复询问「这组数的 AND 是否大于 0」，而这个问题有一个**逐位**的等价判据。组合本身有 $2^n$ 种，但判据只涉及「哪一位上大家都是 1」——先转述判据，再谈搜索。

### 3.2 核心观察：AND > 0 ⟺ 存在「全 1 列」

把组合里的数按二进制**竖排**对齐。按位与的运算规则是：**每一位独立地**看这一列，全为 1 则结果该位为 1，只要出现一个 0 则该位为 0。于是：

$$\text{AND} > 0 \iff \text{至少存在某一位 } k\text{，使得组合中每个数的第 } k\text{ 位都是 1}$$

![核心观察：按位与逐列独立，全 1 列撑起结果](images/wc293_q3_bit_column_concept.svg)

这一转化把「选一个最长的组合，使 AND > 0」变成：**选定一个二进制位 $k$，把所有第 $k$ 位为 1 的数全部收进来**——它们恰好是「公共 1 位含 $k$」的最大组合。答案就是

$$\text{ans} = \max_{0 \le k < 24} \text{cnt}[k], \qquad \text{cnt}[k] = \#\{\,x \in \text{candidates} : x \text{ 的第 } k \text{ 位为 1}\,\}$$

至于为什么只需枚举 24 位：$\text{candidates}[i] \le 10^7 < 2^{24} = 16777216$，二进制表示不超过 24 位（bit₀ ~ bit₂₃）。

### 3.3 算法流程：枚举 24 个位，逐位计数

![算法流程：枚举 24 个位，逐位计数取最大](images/wc293_q3_bit_count_flow.svg)

1. **初始化**：`ans = 0`；
2. **枚举位**：$k$ 从 0 到 23；
3. **计数**：遍历数组，统计第 $k$ 位为 1 的数的个数 `cnt`；
4. **更新**：`ans = max(ans, cnt)`；
5. **返回** `ans`。

### 3.4 示例演算

以示例 1 演算：`candidates = [16,17,71,62,12,24,14]`，竖排成二进制表格后**逐列**数 1 的个数：

| 数值 | bit₆ | bit₅ | bit₄ | bit₃ | bit₂ | bit₁ | bit₀ |
|---|---|---|---|---|---|---|---|
| 16 | 0 | 0 | **1** | 0 | 0 | 0 | 0 |
| 17 | 0 | 0 | **1** | 0 | 0 | 0 | 1 |
| 71 | 1 | 0 | 0 | 0 | **1** | 1 | 1 |
| 62 | 0 | 1 | **1** | **1** | **1** | 1 | 0 |
| 12 | 0 | 0 | 0 | **1** | **1** | 0 | 0 |
| 24 | 0 | 0 | **1** | **1** | 0 | 0 | 0 |
| 14 | 0 | 0 | 0 | **1** | **1** | 1 | 0 |
| cnt | 1 | 1 | **4** | **4** | **4** | 3 | 2 |

$\text{ans} = \max(1,1,4,4,4,3,2) = 4$。bit₄ 列的四个 1 恰好属于 $\{16, 17, 62, 24\}$，验证 $16\,\&\,17\,\&\,62\,\&\,24 = 16 > 0$ ✓；bit₃ 列对应 $\{62,12,24,14\}$，$62\,\&\,12\,\&\,24\,\&\,14 = 8 > 0$ ✓——这正是题面解释里给出的两个组合。

![示例演算：逐列计数，三列并列最大](images/wc293_q3_example_walkthrough.svg)

再验证示例 2：`[8,8]` 的 bit₃ 列有两个 1，$\text{cnt}[3] = 2$，答案 2 ✓（重复元素各自计数，无需去重）。

## 4. 算法细节

1. **位宽 24 的精确推导**：$2^{23} = 8388608 \le 10^7 < 2^{24} = 16777216$，即 $\text{candidates}[i]$ 的最高有效位可能是 bit₂₃，必须枚举 $k \in [0, 24)$。写成 32 位也能过但白扫 1/3；**只枚举到 bit₂₂ 则会 WA**（例如 $\text{candidates} = [2^{23}, 2^{23}]$ 的答案是 2，漏掉 bit₂₃ 会错算成 0）。稳妥写法：`while ((1 << k) <= *max_element(...))` 或直接固定 24。
2. **两种等价的循环组织**：
   - **外层枚举位、内层扫数组**：`for k: for x: cnt += (x>>k)&1`，空间 $O(1)$；
   - **外层扫数组、内层拆位**：维护长度 24 的计数数组，一次遍历把每个数的所有位分发给计数器，空间 $O(24)$。两者时间同为 $O(24n)$，前者代码更短，后者对缓存更友好（Python 下差距可忽略）。
3. **取位写法**：`(x >> k) & 1`。C++ 中 `>>` 优先级高于 `&`，`x >> k & 1` 合法，但显式加括号可读性更好、避免翻车。
4. **「组合」是子集，不是子数组**：题目允许任意挑选，与顺序、相邻性无关，所以计数即答案；若误当成「最长连续子数组」去做滑窗/双指针，方向就错了（按位与随元素增多单调不增，但「子数组」版是完全不同的题）。
5. **无需排序、无需去重**：计数与顺序无关；重复元素（示例 2 的 `[8,8]`）各自计入同一列，天然正确。
6. **答案下界**：$\text{candidates}[i] \ge 1$ 保证每个数至少有一位是 1，故 $\max_k \text{cnt}[k] \ge 1$，与「单元素组合 AND = 自身 > 0」的直觉一致，不存在答案为 0 的输入。

## 5. 正确性证明

**引理 1（按位与的逐位刻画）**：对非空组合 $S$，其按位与 $\text{AND}(S)$ 的第 $k$ 位为 1，当且仅当 $S$ 中**每个**数的第 $k$ 位都为 1。从而

$$\text{AND}(S) > 0 \iff \exists k \in [0, 24),\ \forall x \in S:\ x \text{ 的第 } k \text{ 位为 1}$$

**证明**：按位与的定义是逐位运算：第 $k$ 位的结果为 $\min_{x \in S} b_k(x)$，其中 $b_k(x) \in \{0,1\}$ 表示 $x$ 的第 $k$ 位——一列全 1 时 $\min = 1$，出现 0 时 $\min = 0$。非负整数大于 0 当且仅当至少一位为 1，故 $\text{AND}(S) > 0$ 等价于存在 $k$ 使 $\min_{x \in S} b_k(x) = 1$，即该列全 1。又因 $x \le 10^7 < 2^{24}$，高于 bit₂₃ 的位恒为 0，只需检查 $k \in [0, 24)$ ∎

**引理 2（固定位的极大组合）**：固定 $k$，令 $S_k = \{\,x \in \text{candidates} : b_k(x) = 1\,\}$，$|S_k| = \text{cnt}[k]$。则任何「公共 1 位包含 $k$」的合法组合 $S$（即 $\forall x \in S,\ b_k(x) = 1$）都满足 $S \subseteq S_k$，从而 $|S| \le \text{cnt}[k]$；且 $S_k$ 非空时其自身是合法组合。

**证明**：$S$ 中每个数第 $k$ 位均为 1，按 $S_k$ 的定义它们全部落入 $S_k$，故 $S \subseteq S_k$、$|S| \le |S_k|$。若 $S_k \ne \varnothing$，由引理 1（取该组合自身），$S_k$ 的按位与在 第 $k$ 位为 1，故大于 0 ∎

**定理**：按位与结果大于 0 的最长组合长度等于 $\max_{0 \le k < 24} \text{cnt}[k]$，即逐位计数算法的输出。

**证明**：

（**可达性**，$\ge$）取 $k^\ast = \arg\max_k \text{cnt}[k]$。由约束 $\text{candidates}[i] \ge 1$，每个数至少贡献一位 1，故 $\text{cnt}[k^\ast] \ge 1$，$S_{k^\ast}$ 非空且是合法组合（引理 2），长度为 $\text{cnt}[k^\ast] = \max_k \text{cnt}[k]$。

（**最优性**，$\le$）设 $S$ 是任意 AND > 0 的组合。由引理 1，存在 $k$ 使得 $S$ 中每个数的第 $k$ 位均为 1；由引理 2，$|S| \le \text{cnt}[k] \le \max_k \text{cnt}[k]$。

两个方向合并即得结论 ∎

## 6. 复杂度分析

- **时间复杂度**：$O(24n)$。外层 24 个位、内层一趟 $n \le 10^5$ 的数组，约 $2.4 \times 10^6$ 次移位与累加，毫秒级。位宽 24 是**由值域决定的常数**，不随 $n$ 增长，可视为线性 $O(n)$。
- **空间复杂度**：$O(1)$。外位内数写法只需 `ans`、`cnt` 两个标量；外数内位写法需长度 24 的计数数组，即 $O(24) = O(1)$。

> 💡 从 $2^n$ 到 $O(24n)$，本质是把「组合的合法性」压缩到「单个共享位」上判断——**位运算题的常见杠杆：把对象从数换成位，搜索空间立刻从指数级跌到常数级**。

## 7. 参考代码

### C++（外层枚举位）

```cpp
class Solution {
  public:
    int largestCombination(vector<int>& candidates) {
        int ans = 0;
        for (int k = 0; k < 24; ++k) { // 10^7 < 2^24，bit0~bit23
            int cnt = 0;
            for (int x : candidates) {
                cnt += (x >> k) & 1;
            }
            ans = max(ans, cnt);
        }
        return ans;
    }
};
```

### Python（比赛最短版 + 单趟计数版）

```python
class Solution:
    def largestCombination(self, candidates: List[int]) -> int:
        return max(sum((x >> k) & 1 for x in candidates) for k in range(24))
```

单趟扫描、24 个计数器的等价写法（一次遍历拆位分发）：

```python
class Solution:
    def largestCombination(self, candidates: List[int]) -> int:
        cnt = [0] * 24
        for x in candidates:
            k = 0
            while x:
                cnt[k] += x & 1
                x >>= 1
                k += 1
        return max(cnt)
```

> ⚠️ `range(24)` 不能写成 `range(23)`：$2^{23} \approx 8.39 \times 10^6 \le 10^7$，bit₂₃ 上可能落着 1（见 §4.1）。用 `while x` 的写法则天然只扫到最高有效位，不会有此隐患。

## 8. 边界情况与易错点

1. **位宽漏算**：误以为 $10^7 < 2^{23}$ 只枚举 bit₀~bit₂₂，在 $\text{candidates}$ 含 $\ge 2^{23}$ 的元素时 WA。记住 $2^{23} = 8388608 \le 10^7 < 2^{24}$，需要 24 位。
2. **运算符优先级**：C++/Java 中 `x >> k & 1` 虽因 `>>` 优先级更高而正确，但 `x & 1 == 0` 这类写法会因 `==` 优先级更高而出错——位运算一律显式加括号。
3. **单元素 / 下界**：$n = 1$ 时答案恒为 1（正整数自身 AND > 0），算法由「每个数至少贡献一位 1」自动覆盖，无需特判。
4. **重复元素**：`[8,8]` 答案 2。计数天然包含重复，**不要去重**。
5. **组合 ≠ 子数组**：本题选数与顺序无关；不要套滑动窗口或双指针。
6. **初值**：`ans` 初始化为 0 安全（答案下界为 1，循环必能覆盖），不存在输出 0 的合法输入。
7. **别用 32 位 `int` 溢出焦虑**：计数值上界 $10^5$、数值上界 $10^7$，均在 `int` 范围内；Python 无此忧。

**延伸思考**：

- **AND 恰等于 $T$ 的最长组合**：要求 $T$ 的每个 1 位全 1、每个 0 位至少出现一个 0，单个计数器不再够用——可对 0 位做容斥，或用 **SOS DP（超集和）** 预处理「掩码 $m$ 的全部 1 位都被满足」的最大计数，$O(U \log U)$（$U$ 为值域）。
- **AND $\ge T$ 的最长组合**：数值比较不能逐位独立，需按 $T$ 的二进制从高位到低位贪心讨论（高位多 1 可弥补低位），适合作为本题的进阶变体。
- **OR / XOR 版**：正整数的 OR 恒大于 0，答案退化为 $n$；XOR $= 0$ 的最长组合则回归经典的前缀 XOR + 哈希分组问题。
