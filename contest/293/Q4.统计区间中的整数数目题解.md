# LeetCode 统计区间中的整数数目 题解

## 1. 题目概述

- **标题 / 题号**：统计区间中的整数数目（#2276，hard）
- **链接**：https://leetcode.cn/problems/count-integers-in-intervals/
- **来源**：LeetCode 第 293 场周赛 Q4
- **难度**：困难
- **标签**：设计、线段树、有序集合

**题意**：

设计数据结构 `CountIntervals`，维护一个初始为空的**整数覆盖集合**（若干区间的并集）：

- `void add(int left, int right)`：把闭区间 $[\text{left}, \text{right}]$ 并入集合；
- `int count()`：返回至少出现在一个区间中的整数个数，即并集的基数 $|S|$。

**约束**：

- $1 \le \text{left} \le \text{right} \le 10^9$：值域高达 $10^9$；
- `add` 与 `count` 总调用次数 $\le 10^5$；
- `count` 至少调用一次。

> 💡 **一句话定位**：大值域（$10^9$）× 少操作（$10^5$）× 只增不减的并集维护 × 全局基数查询——**动态开点线段树（区间染色）** 的教科书甜区。题目标签里的 Ordered Set 对应另一条「有序 map 维护不相交区间」路线，两种解法本文末尾有对比。

## 2. 示例

**示例 1**

```text
输入：
["CountIntervals", "add", "add", "count", "add", "count"]
[[], [2, 3], [7, 10], [], [5, 8], []]
输出：
[null, null, null, 6, null, 8]

解释：
add(2, 3)   → 覆盖 {2, 3}
add(7, 10)  → 并集 [2,3] ∪ [7,10]，count = 2 + 4 = 6
add(5, 8)   → 新增 5、6 两个整数（7、8 已被覆盖，不重复计数）
count = 8
```

**示例 2（自拟，覆盖相邻相接与完全吞并）**

```text
操作：add(1, 2), add(3, 4), add(2, 100), count()
输出：100
解释：[1,2] 与 [3,4] 相邻无缝，覆盖并成 [1,4]；add(2, 100) 完全吞掉 [1,4]，
最终并集为 [1,100]，count = 100。
```

**示例 3（自拟，重复添加与子区间添加）**

```text
操作：add(5, 10), add(5, 10), add(6, 7), count()
输出：6
解释：重复添加同一区间、再添加其子区间，并集不变，count = 10 − 5 + 1 = 6。
线段树中这两次 add 都会被「整段已覆盖」剪枝挡住，几乎零开销。
```

## 3. 解题思路

### 3.1 暴力思路

两种朴素做法分别被 $10^9$ 的值域与 $10^5$ 的操作次数卡死：

- **值域数组**：开 `bool covered[10^9]`，`add` 逐位置 `true`、`count` 全量累加。内存约 1 GB（位压缩也要 125 MB），单次 `add` 最坏 $O(10^9)$。
- **区间列表 + 线性合并**：用数组存当前互不相交的区间，每次 `add` 线性扫出所有相交/相邻区间合并，`count` 线性累加。单次 $O(n)$，总计 $O(Q^2) = 10^{10}$，超时。

> ⚠️ **不能离线离散化**：本题是**在线交互**判题——数据结构逐个响应操作，事先不知道后续 `add` 的端点。想「先收集所有端点、离散化后建普通线段树」是行不通的，必须选**在线**结构：动态开点线段树或平衡树（有序 map）。

### 3.2 核心观察：动态开点 + 只增染色的线段树

![核心观察：稀疏值域按需开点，节点只记 covered 与 full](images/wc293_q4_segment_tree_concept.svg)

三个观察层层递进：

1. **值域大、操作少 ⇒ 稀疏**：普通线段树按值域满建需要约 $4 \times 2^{30} \approx 4.3 \times 10^9$ 个节点，不可行；但全程只有 $\le 10^5$ 次 `add`、每次递归只经过 $O(\log V) \approx 30$ 层节点——真正会被「触碰」的树区域极小。**动态开点**：节点在递归首次经过时才创建，内存只花在被触碰的路径上，总量 $O(Q \log V)$。
2. **并集语义 ⇒ 染色只增不清**：`add` 永远是把一段染成「已覆盖」，不存在取消覆盖。于是懒标记 `full`（整段覆盖）只会从 `false` 翻成 `true`、**永不回退**——这意味着**无需 pushdown**（标记永久化）：递归进入一个 `full` 节点直接剪枝返回，标记留在原地即可保持正确（证明见 §5）。
3. **唯一的查询是全局基数 ⇒ covered 实时上传**：`count()` 恒等于根节点的覆盖数。让每个节点实时维护 `covered`（本段已覆盖整数数），递归返回时 `pushup: covered = l.covered + r.covered`，根节点的 `covered` 就**始终**是答案——`count()` 退化为 $O(1)$ 的字段读取。

### 3.3 算法流程：add 的递归

![算法流程：不相交剪枝、full 剪枝、完全覆盖打永久标记、分治 + pushup](images/wc293_q4_add_cover_flow.svg)

`update(o, lo, hi)` 在管辖 $[lo, hi]$ 的节点 `o` 上并入 $[\text{left}, \text{right}]$：

1. **不相交**（`right < lo || hi < left`）：直接 return，不创建节点、不改子树；
2. **`o.full == true`**：本段已整段覆盖，再并入任何子区间并集都不变，**剪枝** return（子节点根本不用建）；
3. **完全覆盖**（`left <= lo && hi <= right`）：打永久标记 `full = true`，`covered = hi - lo + 1`，return；
4. **部分相交**：取 `mid = (lo + hi) / 2`，递归左子树 $[lo, \text{mid}]$ 与右子树 $[\text{mid}+1, hi]$（子节点不存在则按需创建），回溯时 `pushup` 把两个儿子的 `covered` 累加到自己身上。

`count()`：`return root.covered`。

### 3.4 示例演算

![示例演算：三次 add 的并集覆盖演化](images/wc293_q4_example_walkthrough.svg)

对应 §2 示例 1（数轴只画 1~12 附近）：

| 步骤 | 操作 | 新覆盖整数 | 覆盖并集 | count |
|---|---|---|---|---|
| ① | `add(2, 3)` | 2, 3 | $[2,3]$ | 2 |
| ② | `add(7, 10)` | 7, 8, 9, 10 | $[2,3] \cup [7,10]$ | 2 + 4 = 6 |
| ③ | `add(5, 8)` | 5, 6 | $[2,3] \cup [5,10]$ | 6 + 2 = 8 |

树视角：①② 各沿一条 $O(\log V)$ 的路径下行、在 $[2,3]$ 与 $[7,10]$ 对应的节点上打满标记；③ 中 $[5,8]$ 的递归会在「半覆盖」节点处分叉下探，把 5、6 位置的路径补出来——**每次 add 只新建 $O(\log V)$ 个节点、只走 $O(\log V)$ 条边**，这就是稀疏值域下依然 $O(\log V)$ 单次操作的原因。

## 4. 算法细节

1. **节点定义极简**：`Node { Node *l, *r; int covered; bool full; }`——不存区间端点（端点由递归参数 `lo, hi` 随身携带，省一半内存），没有 `pushdown`。
2. **判定顺序有讲究**：入口先判「不相交」再判「full」，两者都通过才考虑建点/染色——不相交时连节点都不该创建；`full` 剪枝放在「完全覆盖打标记」之前，重复 `add` 同一大区间时直接短路。子节点在递归前 `if (o->l == nullptr) o->l = new Node()`。
3. **`covered` 只有两个写点**：完全覆盖时直接置 $hi - lo + 1$；部分相交递归返回后 `pushup`。二者不冲突：一个节点一旦 `full`，后续 `add` 在这里剪枝，`covered` 不会再被改。
4. **闭区间与分治边界**：根管辖 $[1, 10^9]$（因 $\text{left} \ge 1$）。`mid = lo + (hi - lo) / 2` 保证 $lo \le mid < hi$。叶节点 $lo = hi$ 不会死递归：单点区间与 $[\text{left}, \text{right}]$ 相交 $\iff$ 完全覆盖（此时 $\text{left} \le lo = hi \le \text{right}$ 必然成立），部分相交分支在叶子上不可能触发。
5. **节点数上界**：每次 `add` 的递归只在两条边界路径上「新建」节点，新建数 $\le 2\lceil \log_2 V \rceil + O(1) \approx 65$，理论松界 $65 \times 10^5 = 6.5 \times 10^6$；实际因区间重叠、路径前缀共享，远小于此（本题数据实测约数十万）。C++ 指针按需 `new`、Python 节点按需构造，内存即实际用量。
6. **为什么可以不做 pushdown（标记永久化）**：懒标记的本职是「延迟把整段信息下传」；本题唯一的查询是根的 `covered`，而它由 `pushup` 实时维护，不依赖任何标记下传。`full` 的唯一用途是 `add` 剪枝——标记留在半路不影响任何读取。若题目追加 `remove(left, right)`（取消覆盖），标记需要 0 / 1 / 无 三态并真正 `pushdown`，回到标准区间赋值线段树（见文末延伸思考）。

## 5. 正确性证明

设当前覆盖并集为 $S \subseteq [1, 10^9]$。对已建节点 $o$ 记其管辖区间 $I_o = [lo, hi]$，定义 $\sigma(o) = |S \cap I_o|$（未建节点视为 `covered = 0`、`full = false` 的虚拟节点）。称节点为**活跃**的，若从根到它的路径上（不含自身）没有 `full` 节点。

**引理 1（full 的语义）**：节点 `o.full == true` 的充要条件是打标记那一刻起 $I_o \subseteq S$，且此后恒有 $I_o \subseteq S$。

**证明**：`full` 只在「完全覆盖」分支置位，该分支执行 $S \gets S \cup [\text{left}, \text{right}]$ 且 $I_o \subseteq [\text{left},\text{right}]$，故执行后 $I_o \subseteq S$。此后每次 `add` 只向 $S$ 添加元素（并集单调不减），$I_o \subseteq S$ 恒保持。反之 `full` 不会被清回 `false`，故每个 `full` 节点都对应某次这样的置位 ∎

**引理 2（covered 不变式）**：任何时刻，每个活跃节点 $o$ 满足 `o.covered` $= \sigma(o)$。

**证明**：对 `add` 操作次数归纳。初始仅有根（`covered = 0`，$S = \varnothing$），成立。设某次 `add` 前不变式成立，考察其递归触及的节点：

- **不相交 / full 剪枝分支**：节点及子树零改动；且 $S$ 的变化（并入 $[\text{left},\text{right}]$）与 $I_o$ 无交（不相交），或 $I_o \subseteq S$ 原本成立（full，由引理 1 并入后仍覆盖，$\sigma$ 不变）。不变式保持。
- **完全覆盖分支**：执行后 $I_o \subseteq S$，`o.covered` $= |I_o| = \sigma(o)$ ✓。$o$ 的子孙退出活跃集，对它们不再有断言；而任何后续读取都不会触达它们——`add` 递归到 $o$ 即被 `full` 剪枝，`count` 只读根。
- **部分相交分支**：设左右儿子区间 $I_l = [lo, mid]$、$I_r = [mid+1, hi]$，则 $I_l \cup I_r = I_o$ 且不交。若儿子被递归触及，按同样的归纳论证其执行后不变式成立；若未触及（与 $[\text{left},\text{right}]$ 不交，或其为 `full`），其 `covered` 与 $\sigma$ 同步不变。故 `pushup` 后 `o.covered = l.covered + r.covered = σ(l) + σ(r) = σ(o)`（未建儿子按 0 计，其虚拟 `covered` = 0 正确）✓

  回溯路径上逐层应用上述论证，得所有活跃节点在 `add` 后不变式恢复 ∎

**引理 3（递归的完备性）**：`update(o, lo, hi)` 执行后，$S$ 恰好并入 $[\text{left},\text{right}] \cap I_o$。

**证明**：对分治深度归纳。$I_o \cap [\text{left},\text{right}] = \varnothing$ 时不相交分支零改动 ✓；$I_o \subseteq [\text{left},\text{right}]$ 时完全覆盖分支并入整个 $I_o$ ✓；$I_o \not\subseteq [\text{left},\text{right}]$ 且相交非空时，交集被 $mid$ 拆为 $[\text{left},\text{right}] \cap I_l$ 与 $[\text{left},\text{right}] \cap I_r$ 两部分，分别由两次递归按归纳假设并入，其中空的部分由不相交分支无害跳过；`full` 分支跳过的部分 $I_o \subseteq S$ 已在 $S$ 中，由引理 1 无损 ∎

**定理**：`count()` 返回 $|S|$。

**证明**：根是活跃节点（无祖先）。由引理 2，`root.covered` $= \sigma(\text{root}) = |S \cap [1, 10^9]|$。又所有 `add` 区间都含于 $[1, 10^9]$，故 $S \subseteq [1, 10^9]$，`root.covered` $= |S|$。由引理 3，每次 `add` 后 $S$ 恰为所有已加入区间的并集，与题目语义一致 ∎

## 6. 复杂度分析

- **时间复杂度**：单次 `add` 为 $O(\log V)$，其中 $V = 10^9$，$\lceil \log_2 V \rceil = 30$——递归只沿 `left`、`right` 两条边界路径下行，每层至多访问常数个节点（两个边界儿子 + 至多两个「完全覆盖即返回」的整段节点）。总计 $O(Q \log V) \approx 10^5 \times 30 = 3 \times 10^6$ 次节点操作。`count()` 为 $O(1)$。
- **空间复杂度**：节点数 $O(Q \log V)$，理论松界约 $6.5 \times 10^6$，实测远小（重叠区间的路径大量复用）。每节点 2 指针 + 1 个 `int` + 1 个 `bool`，按需分配、与值域无关。

> 💡 **对比有序 map 解法**（均摊 $O(\log Q)$ 单次、$O(Q)$ 空间）：map 更省内存、代码更短，是另一条完全合格的路线（本站 [每日题解版](https://leetcode.cn/problems/count-integers-in-intervals/) 有详述）；动态开点线段树胜在**天然支持更强的区间操作**（区间赋值 / 区间加 / 区间最值查询），当题目往这些方向扩展时无需换骨架。

## 7. 参考代码

### C++

```cpp
class CountIntervals {
    struct Node {
        Node *l = nullptr, *r = nullptr;
        int covered = 0;    // 本节点区间内已覆盖的整数数
        bool full = false;  // 本节点区间是否被整段覆盖（永久标记）
    };

  public:
    CountIntervals() : root(new Node()) {}

    void add(int left, int right) {
        update(root, 1, 1'000'000'000, left, right);
    }

    int count() { return root->covered; }

  private:
    Node *root;

    void update(Node *&o, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return;   // ① 不相交：不建点、不改动
        if (!o) o = new Node();         // ② 有交集才按需开点
        if (o->full) return;            // ③ 整段已覆盖：并集无变化，剪枝
        if (l <= lo && hi <= r) {       // ④ 完全覆盖：打永久标记
            o->full = true;
            o->covered = hi - lo + 1;
            return;
        }
        int mid = lo + (hi - lo) / 2;
        update(o->l, lo, mid, l, r);
        update(o->r, mid + 1, hi, l, r);
        o->covered = (o->l ? o->l->covered : 0) +
                     (o->r ? o->r->covered : 0);   // pushup
    }
};
```

> ⚠️ **两个关键细节**：
> （1）**`Node *&` 引用传指针**：`update(o->l, ...)` 把「指向儿子的指针」本身按引用传入，②处 `o = new Node()` 会直接挂到父节点的儿子字段上，无需在调用方判空。
> （2）**①必须在②之前**：不相交的子树连节点都不该创建；若把建点放在不相交判断之前，会为无关区间白白建点，内存常数翻倍。


### Python

```python
class CountIntervals:
    def __init__(self):
        self.l = None            # 左子树（同样是 CountIntervals 节点）
        self.r = None            # 右子树
        self.covered = 0         # 本段已覆盖整数数
        self.full = False        # 本段是否被整段覆盖

    def add(self, left: int, right: int) -> None:
        def update(o, lo, hi):
            if right < lo or hi < left or o.full:
                return
            if left <= lo and hi <= right:
                o.full = True
                o.covered = hi - lo + 1
                return
            mid = (lo + hi) // 2
            if left <= mid:
                if o.l is None:
                    o.l = CountIntervals()
                update(o.l, lo, mid)
            if right > mid:
                if o.r is None:
                    o.r = CountIntervals()
                update(o.r, mid + 1, hi)
            o.covered = (o.l.covered if o.l else 0) + \
                        (o.r.covered if o.r else 0)

        update(self, 1, 10**9)

    def count(self) -> int:
        return self.covered
```

> 💡 Python 版让**对象自身充当根节点**（`self` 即根），省去单独的 `root` 字段；建点在调用方显式完成，`update` 入口合并了「不相交」与「full」两个剪枝条件。

## 8. 边界情况与易错点

1. **不能离线离散化**：在线判题，端点事先未知；「先读全操作再离散化」直接方向性错误。
2. **值域边界**：根必须管辖 $[1, 10^9]$——写成 $[0, 10^9]$ 多一层、写成 $[1, 10^9 - 1]$ 会漏掉值 $10^9$（例如 `add(10^9, 10^9)`）。
3. **溢出**：`covered` 与 `hi - lo + 1` 最大 $10^9 < 2^{31} - 1 \approx 2.15 \times 10^9$，`int` 恰好安全但贴近上限，C++ 工程上可换 `long long` 求稳；`mid = lo + (hi - lo) / 2` 写法避免 `$lo + hi$` 相加溢出（本题值域下不溢，但习惯要好）。Python 无此忧。
4. **`full` 剪枝漏写不致错、但退化**：漏写后已覆盖区域会白白下探建点到叶子，节点数与常数显著变大；正确性不受影响（下探后各子段覆盖数加起来仍等于段长）。
5. **`full` 剪枝误写成「清除」逻辑**：有 `remove` 情节的模板（如 715）用三态标记 + pushdown，直接照搬会把本题写复杂；本题标记只置一次、永不下传。
6. **叶节点死递归**：靠「单点相交即完全覆盖」兜底（§4.4），无需对 $lo = hi$ 特判；若分治边界写错（如 `mid = (lo + hi + 1) / 2` 且区间长 1），会栈溢出。
7. **重复 add 同一区间**：第二次在很浅的节点就被剪掉，接近 $O(1)$ 开销；不要额外维护「已加入区间集合」去重，多此一举。
8. **构造时建根**：`count()` 可能在任何 `add` 之前调用（返回 0），根节点必须构造时就存在，否则空指针。
9. **递归深度**：30 层，C++ / Python 均无栈风险（Python 默认上限 1000）。

**延伸思考**：

- **追加 `remove(left, right)`**：懒标记升级为三态（0 全未染 / 1 全染 / 无标记），`pushdown` 必须实现，且「部分覆盖」时要把标记拆开下传——这正是 715 Range 模块的完整形态。此时线段树骨架几乎不变，而有序 map 路线需要重写「差集切分」逻辑，边界更多：这也是标签里 Segment Tree 的真正用武之地。
- **count 支持任意区间 $[a, b]$ 查询**：把查询也写成一次 $O(\log V)$ 的递归（在 $[a,b]$ 与节点区间的交上累加 `covered`），线段树无需大改；有序 map 路线则要引入前缀和或树状数组辅助。
- **若 `add` 次数升至 $10^7$、值域 $10^{18}$**：$\log V \approx 60$，动态开点节点数逼近 $10^9$ 量级，内存不可承受——回到「端点有序集合 + 均摊合并」（区间数 $\le Q$）或离线离散化才是正解。
