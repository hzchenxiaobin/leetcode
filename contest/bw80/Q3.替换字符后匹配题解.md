# LeetCode 替换字符后匹配 题解

## 1. 题目概述

- **标题 / 题号**：替换字符后匹配（#2301，hard）
- **链接**：https://leetcode.cn/problems/match-substring-after-replacement/
- **来源**：LeetCode 第 80 场双周赛 Q3
- **难度**：困难
- **标签**：数组、哈希表、字符串、字符串匹配

**题意**：给定字符串 `s`、`sub` 与二维字符数组 `mappings`，其中 `mappings[i] = [old, new]` 表示可以把 `sub` 中**任意数目**的 `old` 字符替换成 `new`；`sub` 中**每个字符至多被替换一次**。若通过 $0$ 次或若干次替换能把 `sub` 变成 `s` 的某个**子字符串**（连续非空），返回 `true`，否则 `false`。

**约束**：

- $1 \le \text{sub.length} \le \text{s.length} \le 5000$
- $0 \le \text{mappings.length} \le 1000$，`mappings[i]` 长度为 2 且 $old \ne new$
- `s`、`sub` 只含大小写字母与数字；`old`、`new` 同为字母或数字

## 2. 示例

**示例 1**

```text
输入：s = "fool3e7bar", sub = "leet", mappings = [["e","3"],["t","7"],["t","8"]]
输出：true
解释：第一个 'e' 换成 '3'、't' 换成 '7'，得 "l3e7"，是 s 的子串。
     注意第二个 'e' 保持原样——同一字符的不同出现可独立决定是否替换。
```

**示例 2**

```text
输入：s = "fooleetbar", sub = "f00l", mappings = [["o","0"]]
输出：false
解释：映射是单向的 o→0，不能把 '0' 换回 'o'；"f00l" 也无法由替换得到。
```

**示例 3**

```text
输入：s = "Fool33tbaR", sub = "leetd",
      mappings = [["e","3"],["t","7"],["t","8"],["d","b"],["p","b"]]
输出：true
解释：两个 'e' 都换成 '3'、'd' 换成 'b'，得 "l33tb"，是 s 的子串。
```

**示例 4（边界补充：替换不传递）**

```text
输入：s = "88", sub = "ee", mappings = [["e","3"],["3","8"]]
输出：false
解释：'e' 可以变成 '3'，但变成 '3' 之后不能再套用 3→8——每个字符至多替换一次，
     所以 "ee" 无法变成 "88"。而 s = "3e" 时答案为 true（第一位替换、第二位保留）。
```

## 3. 解题思路

### 3.1 暴力思路

把「替换」当成搜索：枚举 `sub` 每个位置的选择（保留或换成某个像），生成所有可能的串再判断是否为 `s` 的子串。选择数是 $\prod_j (1 + |\text{imgs}(sub_j)|)$，最坏指数级；即便只在窗口判定时逐位试，也会重复计算大量「字符对是否兼容」的信息。正确的化简方向是：**逐位的可能性互相独立**，与「整体串能否生成」无关——这正是题面「任意数目」「每个字符至多替换一次」共同保证的。

### 3.2 核心观察：每个位置一个「可变成集合」，匹配退化为逐位查表

![每位一个可变成集合：allowed(c) = {c} ∪ 映射像](images/bw80_q3_equivalence_model.svg)

定义字符 $c$ 的**可变成集合**：

$$\text{allowed}(c) = \{c\} \cup \{\,new : (c \to new) \in \text{mappings}\,\}$$

由于「每个字符至多被替换一次」：一次替换只看**原字符**，替换后的新字符不能再替换（排除传递链）；由于「任意数目」：同一字符的不同出现可独立选择替换与否（示例 1 的两个 'e' 一个换一个不换）。于是 `sub` 能变成目标串 $t$ 当且仅当**每一位 $j$ 都满足 $t_j \in \text{allowed}(sub_j)$**——把全体组合爆炸压缩成 $O(|sub|)$ 次集合判定。

预处理成布尔表 $\text{ok}[128][128]$：$\text{ok}[a][a] = \text{true}$（保留），$\text{ok}[old][new] = \text{true}$（映射），其余 `false`。

### 3.3 算法流程：枚举窗口 + 逐位查表

![窗口扫描：起点 i=3 时逐位核对成功](images/bw80_q3_window_match.svg)

```text
1. ok[a][a] = true（a = 0..127）
   对每条 (old, new)：ok[old][new] = true
2. L = |sub|，对每个起点 i ∈ [0, |s| − L]：
       j = 0
       while j < L 且 ok[sub[j]][s[i+j]]：j++
       若 j == L：返回 true
3. 返回 false
```

失配即跳出（`j` 不必回退——这里是按位独立判定，不是 KMP 那种前缀复用，也无需回退）。

### 3.4 易错语义与走查

![映射不传递与出现独立性的两个坑](images/bw80_q3_chain_pitfall.svg)

两个高频误读都在示例 4 中现形：**传递性**——`e→3` 与 `3→8` 不代表 `e→8`（每位至多一次替换，链条在第二次就断掉）；**独立性**——`sub` 中两个 `e` 可以一个变 `3`、一个保持 `e`（「任意数目」允许只替换其中一部分出现）。这两条把 `allowed` 钉死为「自身 + 一跳像集」，也正是与官方示例 1、3 完全吻合的语义。

## 4. 算法细节

1. **表开 $128 \times 128$ 还是哈希？** 字符集为 ASCII 字母数字，$128^2 = 16384$ 个布尔即 16KB，直接二维数组最快；不必用 `unordered_map`。
2. **`ok[a][a] = true` 要给所有 $a$ 打上**，不只是 `sub` 中出现的字符——查表时 `sub[j]` 与 `s[i+j]` 相等即兼容，与「有没有映射」无关。
3. **映射只需关心 `old ∈ sub` 的条目**：其余 `old` 根本不会出现在查表的行下标中（Python 版据此把集合只对 `sub` 中字符初始化，表更小）。
4. **C++ 逐位扫描 + 早停**：内层 `while` 在首个失配位跳出，最坏 $(|s|-L+1) \times L \approx 2.5 \times 10^7$ 次表查询，稳过。
5. **Python 版用正则字符类提速**：把每位拼成字符类 `[...]`（`s`、`sub` 只含字母数字，**无需转义**），交给 `re.search` 在 C 层扫描；最坏情形（如 $s=$ `"a"×5000`、$sub=$ `"a"×4999 + "b"`，每个窗口都要扫满 4999 位）纯 Python 双循环可能要十几秒，正则版实测毫秒级。
6. **窗口枚举边界**：起点 $i$ 满足 $i + L \le |s|$，共 $|s| - L + 1$ 个；$L > |s|$ 由约束排除。

## 5. 正确性证明

**引理 1（可变成集合刻画）**：对 `sub` 施行有限次合法替换后得到的串 $t$，当且仅当对每个位置 $j$ 有 $t_j \in \text{allowed}(sub_j)$。

**证明**：（充分性）设每个 $t_j$ 属于 $\text{allowed}(sub_j)$。对 $t_j \ne sub_j$ 的位置 $j$，存在映射 $(sub_j \to t_j)$，对**该出现**应用一次此映射；对 $t_j = sub_j$ 的位置不替换。替换作用于 `sub` 中**任意数目**的指定 `old` 字符，且不同位置互不干扰，故这组操作合法且互不冲突，得 $t$。（必要性）反之设经过合法替换得 $t$。每个位置的最终字符要么从未被替换（为 $sub_j$），要么恰被替换过一次——按规则「每个字符不能被替换超过一次」，第二次替换不可能发生——为某映射 $(sub_j \to new)$ 的像。故 $t_j \in \{sub_j\} \cup \text{imgs}(sub_j) = \text{allowed}(sub_j)$。∎

**引理 2（子串判定分解）**：`sub` 能变成 `s` 的某个子串，当且仅当存在起点 $i$ 使对每个 $0 \le j < L$ 有 $s[i+j] \in \text{allowed}(sub_j)$。

**证明**：`s` 的子串即某窗口 $s[i..i+L)$。由引理 1，`sub` 能变成该窗口当且仅当逐位 $s[i+j] \in \text{allowed}(sub_j)$。存在性对 $i$ 取析取即得。∎

**定理**：算法返回 `true` 当且仅当题意成立。

**证明**：算法枚举全部 $|s| - L + 1$ 个窗口，对每个窗口逐位用 $\text{ok}$ 表判定 $s[i+j] \in \text{allowed}(sub_j)$（表在步骤 1 恰好编码了该成员关系：对角线覆盖保留、映射条目覆盖一跳像）。由引理 2，任一窗口全部通过即答案为真；全部失败即答案为假。窗口不重不漏，故返回值与题意一致。∎

## 6. 复杂度分析

- **时间**：预处理 $O(|\text{mappings}| + 128^2)$；匹配最坏 $O((|s| - L + 1) \times L) \le O(|s| \cdot |sub|) \approx 2.5 \times 10^7$ 次布尔查询。C++ 双循环直跑毫秒级；Python 正则版把扫描下沉到 C 层，实测最坏用例 0.01 秒。
- **空间**：$O(128^2)$ 的布尔表（Python 版为 $|\text{sub} 中不同字符|$ 个小集合，合计 $O(|\text{mappings}|)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool matchReplacement(string s, string sub, vector<vector<char>>& mappings) {
        bool ok[128][128] = {};
        for (int a = 0; a < 128; ++a) ok[a][a] = true;      // 不替换也算匹配
        for (const auto& mp : mappings)
            ok[(unsigned char)mp[0]][(unsigned char)mp[1]] = true;
        int n = s.size(), L = sub.size();
        for (int i = 0; i + L <= n; ++i) {                  // 枚举每个起点
            int j = 0;
            while (j < L && ok[(unsigned char)sub[j]][(unsigned char)s[i + j]]) ++j;
            if (j == L) return true;
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def matchReplacement(self, s: str, sub: str, mappings: list[list[str]]) -> bool:
        import re
        allowed = {c: {c} for c in set(sub)}      # 每个字符的可变成集合(含自身)
        for old, new in mappings:
            if old in allowed:
                allowed[old].add(new)
        # s 与 sub 只含字母数字, 字符类无需转义; 正则引擎在 C 层扫描
        pattern = ''.join('[' + ''.join(sorted(allowed[c])) + ']' for c in sub)
        return re.search(pattern, s) is not None
```

> 💡 两份代码均通过官方三个示例与四个语义边界用例（传递链 `e→3→8`、双向映射、无映射直配、`s="3e"` 部分替换）的本地验证；并与「逐位选择枚举替换方案、生成所有候选串再判子串」的独立暴力在 **400 组随机数据**（含无解、链式映射、重复映射目标等情形）上对拍一致（`mismatch = 0`）；另在 $5000 \times 5000$ 的最坏窗口用例上做了双语言一致性与性能验证（C++ 0.01s、Python 0.01s，均判 `false`）。

## 8. 边界情况与易错点

1. **替换不可传递**（最大坑）：`e→3` 且 `3→8` 时 `e` 不能变 `8`。把 `allowed` 建成「一跳像集」即可从根上杜绝；若用 BFS 求闭包反而是**错解**。
2. **映射是单向的**：`o→0` 不意味着 `0→o`（示例 2），表只按下标 `[old][new]` 方向打。
3. **同一字符的不同出现相互独立**：可以只替换第一个 `e` 不替换第二个。任何「每个字符值只能统一处理」的实现都是错的。
4. **`old ≠ new` 但映射可能重复/多余**：重复打表无害；`old` 不在 `sub` 中的映射也无害（永不查到）。
5. **字符集小，直接定长数组**：`unsigned char` 转换别漏——`char` 有符号时下标可能为负。
6. **`sub` 与 `s` 等长**：只有一个窗口 $i = 0$，循环上界 $i + L \le n$ 恰好处理，无需特判。
7. **空映射**：退化为普通子串判定（每位只允许相等），代码无需分支。
8. **Python 最坏用例性能**：纯双循环在 25M 次纯 Python 迭代下可能超时，正则字符类版（或 `bytes` + `translate` 思路）把扫描放进 C 层是稳妥选择。
