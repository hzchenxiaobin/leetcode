# LeetCode 咒语和药水的成功对数 题解

## 1. 题目概述

- **标题 / 题号**：咒语和药水的成功对数（#2300，medium）
- **链接**：https://leetcode.cn/problems/successful-pairs-of-spells-and-potions/
- **来源**：LeetCode 第 80 场双周赛 Q2
- **难度**：中等
- **标签**：数组、双指针、二分查找、排序

**题意**：正整数数组 `spells`（长 $n$）与 `potions`（长 $m$），以及整数 `success`。咒语 $i$ 与药水 $j$ 组合**成功**当且仅当 $\text{spells}[i] \times \text{potions}[j] \ge \text{success}$。返回长为 $n$ 的数组 `pairs`，`pairs[i]` 为能与第 $i$ 个咒语成功组合的**药水数目**。

**约束**：

- $1 \le n, m \le 10^5$
- $1 \le \text{spells}[i], \text{potions}[j] \le 10^5$
- $1 \le \text{success} \le 10^{10}$

## 2. 示例

**示例 1**

```text
输入：spells = [5,1,3], potions = [1,2,3,4,5], success = 7
输出：[4,0,3]
解释：
咒语 5：5×[1,2,3,4,5] = [5,10,15,20,25]，10/15/20/25 ≥ 7，共 4 个；
咒语 1：全部乘积 < 7，共 0 个；
咒语 3：3×[1,2,3,4,5] = [3,6,9,12,15]，9/12/15 ≥ 7，共 3 个。
```

**示例 2**

```text
输入：spells = [3,1,2], potions = [8,5,8], success = 16
输出：[2,0,2]
解释：咒语 3 与 2 各有 2 个药水达标（8×3=24、8×2=16 恰好等于 16 也算成功）；咒语 1 无。
```

**示例 3（边界补充）**

```text
输入：spells = [100000], potions = [100000], success = 10000000000
输出：[1]
解释：10^5 × 10^5 = 10^10 恰好等于 success，「大于等于」也算成功。
```

## 3. 解题思路

### 3.1 暴力思路

对每个咒语枚举全部药水判定乘积：$O(n \cdot m) = 10^{10}$，必然超时。突破口在**单调性**：把药水排序后，对固定咒语，「成功」的药水恰好是排序数组的一段**后缀**——药水越强越容易成功。

### 3.2 核心观察：乘法判定化为「阈值 + 二分」

![排序后二分阈值：找第一个 ≥ t 的药水](images/bw80_q2_threshold_binary_search.svg)

固定咒语强度 $s > 0$，判定 $s \times p \ge \text{success}$ 可对 $p$ 解不等式：

$$p \ge \frac{\text{success}}{s} \iff p \ge t, \quad t = \left\lceil \frac{\text{success}}{s} \right\rceil$$

（$p$ 是整数，实数阈值向上取整即得最小可行整数 $t$。）于是把 `potions` **排序一次**，对每个咒语只需一次**二分查找**定位第一个 $\ge t$ 的药水，其后缀长度 $m - \text{pos}$ 就是答案。乘法比较被替换成「整数阈值比较」，顺带规避了中间乘法溢出的讨论。

### 3.3 算法流程

```text
1. 对 potions 排序（升序）
2. 对每个 spells[i]：
       t = (success + spells[i] − 1) / spells[i]     # 向上取整
       pos = lower_bound(potions, t)                 # 第一个 ≥ t 的下标
       pairs[i] = m − pos
3. 返回 pairs
```

> 💡 另一种等价写法：`pos = upper_bound(potions, (success−1)/spells[i])`，即找最后一个乘积 $< \text{success}$ 的药水。两者只差取整方向，阈值法语义更直白。

### 3.4 示例演算

![示例走查：三个咒语的阈值与计数](images/bw80_q2_example_walkthrough.svg)

以示例 1 走查：`potions` 排序为 $[1,2,3,4,5]$。咒语 $5$：$t = \lceil 7/5 \rceil = 2$，`lower_bound` 得 `pos = 1`，答案 $5 - 1 = 4$。咒语 $1$：$t = 7$，无药水达到，`pos = 5`，答案 $0$。咒语 $3$：$t = \lceil 7/3 \rceil = 3$，`pos = 2`，答案 $3$。得 `[4,0,3]`。

注意咒语 $3$ 的取整：$7/3 \approx 2.33$，若错误地向下取整成 $t = 2$，会把药水 $2$ 也计入（$3 \times 2 = 6 < 7$），答案错成 4——取整方向是本题最隐蔽的坑。

## 4. 算法细节

1. **只排序药水，不排序咒语**：答案按 `spells` 原顺序输出，排序咒语还得记录映射，得不偿失（除非用双指针，见第 5 点）。
2. **向上取整公式**：正整数下 $\lceil a/b \rceil = (a + b - 1) / b$（整数除法）。`success` 最大 $10^{10}$，C++ 中必须用 `long long` 承载 $t$；`lower_bound` 的比较 `int < long long` 会自动提升，安全。
3. **`lower_bound` 与 `upper_bound` 的选择**：求「第一个 $\ge t$」用 `lower_bound`；若用 `upper_bound` 应配 $t-1$ 的语义，两者混用是高频笔误。
4. **溢出分析**：阈值法全程无乘法，比较两侧分别是 `int`（药水）与 `long long`（阈值）；若坚持乘法判定，$s \times p \le 10^{10}$ 超出 `int`，同样需要 `long long`。
5. **双指针替代**：把 `spells` 按值**降序**处理，则阈值 $t$ 单调不增，`pos` 单调不左移——指针只扫一遍，总复杂度 $O(n \log n + m \log m)$，与逐个二分同阶、常数更小。两种写法都对，二分更好写对。

## 5. 正确性证明

**引理 1（阈值等价）**：对正整数 $s, p$ 与正整数 $\text{success}$，

$$s \cdot p \ge \text{success} \iff p \ge \left\lceil \text{success} / s \right\rceil.$$

**证明**：由 $s > 0$，不等式两边同除以 $s$ 得 $p \ge \text{success}/s$。$p$ 是整数，$p \ge x$（实数）等价于 $p \ge \lceil x \rceil$（不小于 $x$ 的最小整数即 $\lceil x \rceil$，整数 $p$ 越过它即越过 $x$）。∎

**引理 2（后缀性）**：`potions` 升序排序后，能与咒语 $s$ 成功组合的药水构成数组的一段后缀。

**证明**：设药水 $p_j$ 成功而 $p_k \ge p_j$。由引理 1，$p_j \ge t$，故 $p_k \ge t$，$p_k$ 亦成功。成功者对「$\ge$」封闭且排在升序数组中即后缀。∎

**定理**：算法返回的 `pairs[i]` 恰为与咒语 $i$ 成功组合的药水数。

**证明**：由引理 2，成功药水数 $=$ 排序数组中第一个成功者的下标之后的所有元素个数。`lower_bound(potions, t)` 返回第一个 $\ge t$ 的下标 `pos`；由引理 1，下标 $\ge \text{pos}$ 的药水全部成功、$< \text{pos}$ 的全部失败，故数目恰为 $m - \text{pos}$。∎

## 6. 复杂度分析

- **时间**：$O(m \log m + n \log m)$——排序药水 $O(m \log m)$，每个咒语一次二分 $O(\log m)$。$n, m \le 10^5$，总量约 $10^5 \times 17 \times 2$，轻松通过。
- **空间**：$O(1)$ 额外空间（C++ 原地排序 + 输出数组不计）；Python 的 `sort` 原地、答案数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> successfulPairs(vector<int>& spells, vector<int>& potions, long long success) {
        sort(potions.begin(), potions.end());
        int m = potions.size();
        vector<int> ans;
        ans.reserve(spells.size());
        for (int s : spells) {
            long long t = (success + s - 1) / s;   // 最小可行药水强度 = ceil(success/s)
            ans.push_back(m - (int)(lower_bound(potions.begin(), potions.end(), t) - potions.begin()));
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def successfulPairs(self, spells: list[int], potions: list[int], success: int) -> list[int]:
        from bisect import bisect_left
        potions.sort()
        m = len(potions)
        ans = []
        for s in spells:
            t = (success + s - 1) // s          # 最小可行药水强度
            ans.append(m - bisect_left(potions, t))
        return ans
```

> 💡 两份代码均通过官方示例（`[4,0,3]`、`[2,0,2]`）与边界用例（乘积恰好等于 `success`、阈值恰好卡在两档药水之间、`success = 1` 全成功），并与「逐对乘法判定」的 $O(n \cdot m)$ 暴力在 **300 组随机数据**上对拍一致（`mismatch = 0`）。

## 8. 边界情况与易错点

1. **取整方向（最大坑）**：阈值必须**向上取整**。$t = \lfloor \text{success}/s \rfloor$ 会把「乘积恰好差一点点」的药水误判为成功（见 3.4 的 $7/3$ 反例）。Python 的 `//` 与 C++ 的 `/` 都是向下取整，公式 $(\text{success} + s - 1) / s$ 别抄错。
2. **`success` 高达 $10^{10}$**：超出 32 位 `int`（约 $2.1 \times 10^9$）；C++ 里 `success`、`t` 都要 `long long`，`s - 1` 的加法在 `long long` 语境下进行才安全。
3. **「大于等于」而非「大于」**：$s \times p = \text{success}$ 算成功（示例 3），`lower_bound`（$\ge$）而非 `upper_bound`（$>$）配对要一致。
4. **原地排序的副作用**：`potions` 被排序后顺序改变；若调用方后续还依赖原序（本题没有），需先复制。
5. **全部成功 / 全部失败**：$t = 1$（`success` 很小）时答案全 $m$；$t > 10^5$（`success` 大而 $s$ 小）时 `pos = m`、答案 0——`lower_bound` 天然处理两端，无需特判。
6. **不要对每个咒语重新排序**：排序提到循环外是本题复杂度的关键；循环内排序会把复杂度推到 $O(n \, m \log m)$。
