# LeetCode 拼写单词 题解

## 1. 题目概述

- **标题 / 题号**：拼写单词（#1160，easy）
- **链接**：https://leetcode.cn/problems/find-words-that-can-be-formed-by-characters/
- **来源**：LeetCode 第 150 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、字符串、计数

**题意**：给定单词列表 `words` 与一堆可用字母 `chars`。如果一个单词的每个字母都能从 `chars` 里取到，并且**同一个字母的取用次数不超过它在 `chars` 中的出现次数**，就称它是好单词。要求返回所有好单词的**长度之和**。

这里最容易读错的一点是：`chars` 对**每个**单词都是**独立且完整可用**的，不是全局消耗——拼出 `"cat"` 并不影响后面还能不能拼出 `"hat"`。

**约束**：

- $1 \le \lvert \text{words} \rvert \le 1000$
- $1 \le \lvert \text{words}[i] \rvert, \lvert \text{chars} \rvert \le 100$
- `words[i]` 与 `chars` 均只包含小写英文字母

> 💡 字符集只有 26 个、单串长度不超过 100，所以本题的时间上限非常宽松。真正值得沉淀的不是"怎么过"，而是**把「能否拼出」改写成一个可提前终止的定量判据**，以及**为什么预算只需要统计一次**。这是后面 Q2、Q3 计数类题目的公共底座。

## 2. 示例

**示例 1**

```text
输入：words = ["cat","bt","hat","tree"], chars = "atach"
输出：6
解释：chars 的预算为 a×2、t×1、c×1、h×1。
      "cat" 需要 c1 a1 t1，满足；"hat" 需要 h1 a1 t1，满足；
      "bt" 需要 b1，而 b 的预算为 0；"tree" 需要 t1 r1 e2，r 与 e 的预算都是 0。
      答案 = 3 + 3 = 6。
```

**示例 2**

```text
输入：words = ["hello","world","leetcode"], chars = "welldonehoneyr"
输出：10
解释：chars 的预算为 w1 e3 l2 d1 o2 n2 h1 y1 r1。
      "hello" 需要 h1 e1 l2 o1，满足，长度 5；
      "world" 需要 w1 o1 r1 l1 d1，满足，长度 5；
      "leetcode" 需要 l1 e3 t1 c1 o1 d1，e 够用但 c 的预算为 0，不满足。
      答案 = 5 + 5 = 10。
```

```text
输入：words = ["a","aa","aaa"], chars = "aa"
输出：3
解释："a" 与 "aa" 都在预算内（长度 1 + 2），"aaa" 需要 3 个 a 但预算只有 2 个。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的模拟：对每个单词，把 `chars` 复制成一个**可删除的字符池**，然后逐字符在池里查找、找到就删掉；任何一个字符找不到，这个词就是坏串。对每个词做一遍 `string::find + erase` 的字符池模拟是 $O(\lvert w \rvert \cdot \lvert \text{chars} \rvert)$，最坏 $1000 \times 100 \times 100 = 10^7$ 次字符搬运——本题能过，但两处常数完全被浪费：

- **重复劳动**：每个单词都把 `chars` 从头扫一遍，而 `chars` 的字母组成对所有单词都一样；
- **删除代价**：`erase` 每次移动 $O(\lvert \text{chars} \rvert)$ 个字符，把一次"查表"变成了线性搬移。

另一种常见暴力是"对每个词重建一张 26 长度的频次表"，方向已经对了，但"重建"这一步仍然多余——**`chars` 的预算只需要统计一次**。

### 3.2 核心观察：把「能否拼出」化成多重集包含

![预算 vs 需求：把拼写化成逐字母比较](images/wc150_q1_budget_vs_need.svg)

关键改写：设 $\text{budget}[c]$ 为字母 $c$ 在 `chars` 中的出现次数，$\text{need}_w[c]$ 为它在单词 $w$ 中的出现次数，则

$$w \text{ 能被拼出} \iff \forall c \in [\text{a},\text{z}]:\ \text{need}_w[c] \le \text{budget}[c]$$

两条直觉支撑这个等价：

- **同字母的副本彼此不可区分**，取哪一个都一样，所以只需关心"够不够"，不关心"取哪个"；
- **不同字母互不争用**，字母 $c$ 的取用不会消耗字母 $d$ 的配额，所以 26 个约束彼此独立，可以分别检查。

于是判断从"模拟拼写"退化为"**26 个整数逐个比大小**"：预算算一次、反复使用，单词一侧边扫边扣减，一旦某个计数器变成负数就立刻宣布失败。

### 3.3 算法流程

![算法流程：预算只算一次，判词用副本](images/wc150_q1_algorithm_flow.svg)

1. **统计预算**：遍历 `chars`，`budget[c - 'a']++`，得到长度 26 的计数数组。
2. **取词 + 剪枝**：按输入顺序取单词 $w$。若 $\lvert w \rvert > \lvert \text{chars} \rvert$，直接跳过——长度都不够，必然是坏串。
3. **复制副本**：把 `budget` 整份拷进 `avail`（26 个整数，常数开销），保证 `budget` 不被污染。
4. **逐字符扣减**：遍历 $w$ 的每个字符 $c$，执行 `--avail[c]`；一旦 `avail[c] < 0`，说明该字母的超支已经发生，立即 `break` 并判为坏串。
5. **累计答案**：若整词走完都没有超支，则 `ans += |w|`。
6. **输出**：所有单词处理完毕后返回 `ans`。

> ⚠️ 第 3 步和第 4 步的分工是这题的核心：**预算只读，副本可写**。若直接在 `budget` 上扣减，第一个单词处理完就把预算改坏了，后续单词会集体误判。

### 3.4 示例演算

![示例 1 走查表](images/wc150_q1_walkthrough.svg)

对示例 1：`chars = "atach"` 给出预算 a×2、t×1、c×1、h×1，其余 22 个字母为 0。

| 单词 | 需求 | 与预算比对 | 判定 | 累计 |
|------|------|-----------|------|------|
| `cat` | c1 a1 t1 | 三个字母都在预算内 | 好 ✓ | 3 |
| `bt` | b1 t1 | b 的预算为 0 | 坏 ✗ | 3 |
| `hat` | h1 a1 t1 | 三个字母都在预算内 | 好 ✓ | 6 |
| `tree` | t1 r1 e2 | r 与 e 的预算都是 0 | 坏 ✗ | 6 |

注意 `"bt"` 在第一个字符 `b` 上就超支退出，整词只扫了 1 个字符，这正是"提前 break"省下的时间；`"tree"` 则要扫到第 2 个字符 `r` 才暴露问题。

## 4. 算法细节

1. **用 26 个桶，不要用哈希表**。字符集固定为小写字母，`ch - 'a'` 直接映射到 $[0, 25]$；数组寻址比 `unordered_map` 的哈希 + 探查快一个数量级，也没有迭代器开销。
2. **长度剪枝放在最前面**。 $\lvert w \rvert > \lvert \text{chars} \rvert$ 时无须建副本、无须扫字符，直接跳过；在大量长词的用例上这一条能省掉绝大部分工作。
3. **早退必须在超支的第一时间做**。`if (--avail[c] < 0) { ok = false; break; }` 把"扣减"和"判定"合成一步，避免先扫完整词再回头检查。
4. **两种等价写法，按需要挑**：
   - **副本法**（本文代码）：每个词拷贝 26 个整数，$O(26)$ 常数开销，逻辑最干净，不会污染预算。
   - **原地回滚法**：直接在 `budget` 上扣减，同时用一个小栈记录被扣过的字母，判完再逐个加回来。单词很短时它比拷贝 26 个整数更省，但**必须保证坏串路径也回滚**，否则错误会跨词传播。周赛现场推荐副本法，代码短、不易错。
5. **绝不要边检查边改 `budget`**。这是本题最高频的 WA：一旦在共享预算上扣减，前一个好串会把后续单词的可用字母永久吃掉，答案系统性偏小。
6. **Python 侧用 `budget[:]` 而不是 `Counter`**。`Counter.subtract` 会保留 0 和负计数（`-` 运算符则会静默丢弃非正项），两种语义都不是本题想要的"够不够"，用整型列表最不容易踩坑。
7. **答案是长度之和**：累加的是 $\lvert w \rvert$，不是匹配到的字母个数（两者相等，但前者更直白），也不是 `chars` 的长度。
8. **字符集变化的扩展点**：若把字母表换成大小写字母 + 数字，只需把数组长度从 26 改成 62 并调整映射函数，算法结构完全不变。

## 5. 正确性证明

**引理 1（必要性）**：若单词 $w$ 能由 `chars` 拼出，则对每个字母 $c$ 都有 $\text{need}_w[c] \le \text{budget}[c]$。

**证明**：拼出 $w$ 的过程为 $w$ 中每个位置指定了 `chars` 中一个**不同的**字符副本（题目规定每个字符只能使用一次）。$w$ 中字母 $c$ 出现 $\text{need}_w[c]$ 次，就要占用 `chars` 中 $\text{need}_w[c]$ 个互不相同的 $c$ 副本；而 `chars` 中总共只有 $\text{budget}[c]$ 个 $c$，故 $\text{need}_w[c] \le \text{budget}[c]$。∎

**引理 2（充分性）**：若对每个字母 $c$ 都有 $\text{need}_w[c] \le \text{budget}[c]$，则 $w$ 能由 `chars` 拼出。

**证明**：对每个字母 $c$ 单独构造映射：把 `chars` 中 $c$ 的前 $\text{need}_w[c]$ 个副本按任意顺序指派给 $w$ 中所有等于 $c$ 的位置。由条件，指派不会超出可用副本数，也不会重复使用同一副本；不同字母的副本集合天然不相交，因此各字母的指派互不冲突。把 $w$ 的每个位置换成它被指派的副本，就得到一个由 `chars` 的不同副本组成的串，它恰好等于 $w$。∎

**引理 3（各词判定互不干扰）**：算法对每个单词都从同一份 `budget` 派生 `avail`，因此第 $i$ 个词的判定结果与其它单词的处理顺序、处理结果无关。

**证明**：`budget` 在步骤 1 之后只被读取、从不被写入（扣减全部发生在 `avail` 上）；每个词开始时 `avail` 由 `budget` 完整复制而来，结束时不回写。故每个词的 `avail` 初值都等于同一个 `budget`，判定只依赖 $w$ 与 `chars`。∎

**定理**：算法返回值等于所有好单词的长度之和。

**证明**：对任意单词 $w$，步骤 4 结束后 `ok` 为真当且仅当 $\forall c:\ \text{need}_w[c] \le \text{budget}[c]$——因为每个超支都会把对应计数器扣成负数并触发 `break`，而未超支时扣减总量恰为 $\text{need}_w[c]$ 且从未越过 0。由引理 1、2，`ok` 为真当且仅当 $w$ 是好单词；此时步骤 5 恰好把 $\lvert w \rvert$ 计入 `ans`。由引理 3，各词贡献互不影响、可加。故 `ans` $=\sum_{w \text{ 是好串}} \lvert w \rvert$。∎

## 6. 复杂度分析

- **时间**：$O\!\left(\lvert \text{chars} \rvert + \sum_i \lvert w_i \rvert + 26n\right)$，其中 $n = \lvert \text{words} \rvert$。统计预算是 $O(\lvert \text{chars} \rvert)$；每个词建副本 $O(26)$、扫描字符 $O(\lvert w_i \rvert)$（坏串会更早退出）；26 是与输入规模无关的常数，故整体可视为 $O(\lvert \text{chars} \rvert + \sum_i \lvert w_i \rvert)$ 的线性时间。
- **空间**：$O(26) = O(1)$ 额外空间。`budget` 与 `avail` 各 26 个整数；Python 的 `budget[:]` 每轮新建一个 26 元素列表，但同一时刻只有一份存活，峰值仍是 $O(26)$。返回值只是整数，不占额外空间。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    int countCharacters(vector<string>& words, string chars) {
        int budget[26] = {0};
        for (char ch : chars) budget[ch - 'a']++;      // ① 预算只统计一次

        int ans = 0;
        for (const string& w : words) {
            if (w.size() > chars.size()) continue;     // ② 长度剪枝：必然拼不出
            int avail[26];
            copy(budget, budget + 26, avail);          // ③ 每个词用独立副本
            bool ok = true;
            for (char ch : w) {
                if (--avail[ch - 'a'] < 0) {           // ④ 扣减与判定合为一步
                    ok = false;
                    break;                             // ⑤ 出现超支立刻退出
                }
            }
            if (ok) ans += (int)w.size();              // ⑥ 好串才累加长度
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countCharacters(self, words: list[str], chars: str) -> int:
        budget = [0] * 26
        for ch in chars:                    # ① 预算只统计一次
            budget[ord(ch) - 97] += 1

        ans = 0
        total = len(chars)
        for w in words:
            if len(w) > total:              # ② 长度剪枝：必然拼不出
                continue
            avail = budget[:]               # ③ 整份拷贝，天然回滚
            ok = True
            for ch in w:
                i = ord(ch) - 97
                avail[i] -= 1               # ④ 扣减
                if avail[i] < 0:            # ⑤ 超支立刻退出
                    ok = False
                    break
            if ok:
                ans += len(w)               # ⑥ 好串才累加长度
        return ans
```

> 💡 若想彻底避免 26 次拷贝，可改成"原地扣减 + 回滚"：把被扣过的字母压进一个小列表 `touched`，判完（无论好坏）再把它们逐个加回 `budget`。单词平均长度只有个位数时，这比拷贝 26 个整数更省，但**回滚必须覆盖 `break` 路径**。

## 8. 边界情况与易错点

1. **单词比 `chars` 还长**（如 `words = ["abcdef"]`, `chars = "abc"`）：长度剪枝直接判坏；即使不剪枝，逐字符扣减也一定会出现负数。
2. **某字母在 `chars` 中完全不存在**：`budget[c] = 0`，第一次扣减就得到 $-1$，必须用 `< 0` 而不是 `== 0` 来判定超支——否则会漏掉"从 0 扣到 -1"的情形。
3. **同字母重复超过预算**（`words = ["aaa"]`, `chars = "aa"`）：要到第 3 次扣减才会变负，所以"字母是否出现过"这种布尔判断是不够的，必须累计计数并允许扫到超支为止。
4. **单词与 `chars` 恰好等长且字母完全一致**（`words = ["abc"]`, `chars = "cba"`）：应计入完整长度 3，顺序无关这一点不能靠"前缀匹配"之类的位置性判断。
5. **重复的单词各算各的**：`words = ["cat","cat"]` 且 `chars` 足够时，答案应为 6 而不是 3——预算对每个词独立重置（引理 3）。
6. **污染共享预算**：把 `avail` 写成 `budget` 的引用（C++ 用 `int* p = budget`，Python 用 `avail = budget`）会让第一个词改写全局预算，是最常见的 WA。
7. **`ans` 的上界**：最坏情况 $1000 \times 100 = 10^5$，`int` 足够；Python 无溢出问题。
8. **空串不会出现**：约束保证 $\lvert \text{words}[i] \rvert \ge 1$，所以不必特判"空词算不算好串"（若真出现，按定义空串长度 0、对答案无贡献，代码也自然正确）。
