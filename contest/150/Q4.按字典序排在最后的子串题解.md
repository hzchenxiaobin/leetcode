# LeetCode 按字典序排在最后的子串 题解

## 1. 题目概述

- **标题 / 题号**：按字典序排在最后的子串（#1163，hard）
- **链接**：https://leetcode.cn/problems/last-substring-in-lexicographical-order/
- **来源**：LeetCode 第 150 场周赛 Q4
- **难度**：困难
- **标签**：双指针，字符串，Lyndon 分解

**题意**：给定字符串 $s$，在它的**全部连续子串** $s[l..r]$（$0 \le l \le r < n$）中，返回字典序最大的那一个。子串允许就是 $s$ 本身。比较规则是经典的字典序：逐位比较，先出现更小字符者更小；若一个串是另一个的真前缀，则短者更小。

**约束**：

- $1 \le \lvert s \rvert \le 4 \times 10^5$
- $s$ 仅含小写英文字母

**复杂度要求**：子串总数是 $O(n^2)$ 量级，$n = 4 \times 10^5$ 时枚举必然超时，需要 $O(n)$（或 $O(n\log n)$）的解法。

## 2. 示例

**示例 1**

```text
输入：s = "abab"
输出："bab"
解释：全部子串为 ["a","ab","aba","abab","b","ba","bab"]，其中字典序最大的是 "bab"。
```

**示例 2**

```text
输入：s = "leetcode"
输出："tcode"
解释：首字符最大的 't' 出现在下标 3；起点 0、1、2 的后缀都以 l 或 e 开头，必然更小，
      故答案只能是以 3 为起点的后缀 "tcode"。
```

**示例 3（补充）**

```text
输入：s = "ababab"
输出："babab"
解释：首字符最大的候选起点是 1、3、5，分别对应 "babab"、"bab"、"b"。
      三者互为前缀关系，"babab" 最长，故它最大。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举 $O(n^2)$ 个子串、两两比较，单次比较最坏 $O(n)$，总复杂度 $O(n^3)$。即便先做关键剪枝——只考虑后缀，$n$ 个后缀两两比较仍是 $O(n^2)$；$n = 4\times10^5$ 时约 $1.6\times10^{11}$ 次字符比较，必然超时。

后缀数组可以在 $O(n\log n)$（倍增 + 排序）或 $O(n)$（SA-IS）内把后缀排好序，取最大者即可，但代码量大、常数高、边界易错。本题存在更轻的双指针做法，核心是：**比较两条后缀时，一次失配可以同时淘汰一整段起点**。

### 3.2 核心观察：答案必是后缀

![答案必是后缀：候选从 O(n²) 降到 O(n)](images/wc150_q4_suffix_reduction.svg)

**观察 1（后缀归约）**：任意子串 $s[l..r]$ 都是后缀 $s[l..n-1]$ 的前缀。若 $r<n-1$，它是真前缀，而真前缀的字典序严格小于原串（前 $r-l+1$ 位全相同，随后前缀耗尽）。所以把候选子串一路延伸到末尾，结果只会变大或不变——**字典序最大的子串一定是某个后缀**，问题归约为「在 $n$ 个后缀中找最大者」，候选规模从 $O(n^2)$ 降到 $O(n)$。

**观察 2（整段淘汰）**：设当前候选起点为 $i$、挑战者为 $j$（$i<j$），两边已确认前 $k$ 个字符相同：

$$s[i..i+k) = s[j..j+k)$$

接下来只需比较 $s[i+k]$ 与 $s[j+k]$。若 $s[i+k] < s[j+k]$，则对任意 $0 \le m \le k$，后缀 $i+m$ 与后缀 $j+m$ 的前 $k-m$ 个字符相同（由上面的等式错位截取），第 $k-m$ 位上分别是 $s[i+k]$ 与 $s[j+k]$，故

$$s[i+m..] < s[j+m..] \qquad (0 \le m \le k)$$

也就是说 $i, i+1, \ldots, i+k$ 这 $k+1$ 个起点被 $j, j+1, \ldots, j+k$ 逐个压制，**整段出局**，可以一次跳过。$s[i+k] > s[j+k]$ 时完全对称：$[j, j+k]$ 整段出局。

> 💡 这一步是复杂度从 $O(n^2)$ 降到 $O(n)$ 的关键：一次字符比较的代价，换来 $k+1$ 个候选的永久淘汰。

### 3.3 算法流程

![双指针三分支：相等则 k+1，失配则整段跳过](images/wc150_q4_two_pointer_rules.svg)

维护三个量：候选起点 $i$、挑战者起点 $j$（始终保持 $i<j$）、已匹配长度 $k$。每轮比较 $s[i+k]$ 与 $s[j+k]$：

- **相等**：$k \leftarrow k+1$，继续对齐下一位。
- $s[i+k] < s[j+k]$：$[i, i+k]$ 出局。若 $j \le i+k$，挑战者 $j$ 自己也在出局区间内，新候选必须越过它、取 $i+k+1$；若 $j > i+k$，$j$ 就是本轮胜者，直接取 $j$。两者合起来正是 $\max(i+k+1,\ j)$，随后令 $j \leftarrow i+1$、$k \leftarrow 0$。
- $s[i+k] > s[j+k]$：$[j, j+k]$ 出局，$j \leftarrow j+k+1$，$k \leftarrow 0$。

循环条件取 $j+k < n$：保证 $s[j+k]$ 一定合法；又因 $i<j$ 蕴含 $i+k < j+k < n$，$s[i+k]$ 也不会越界。循环结束时返回 $s[i..n-1]$。

> 💡 **Lyndon 视角**：这套「对齐比较 + 失配整段剔除 + 均摊 $O(n)$」正是 Duval 算法求字典序**最小**后缀（Chen–Fox–Lyndon 分解的最后一个因子）时使用的框架，本题只是把胜负方向反过来、求**最大**后缀。但要注意「前缀更小」这条规则不随字母表翻转，因此最大后缀不能简单地"把字母表倒过来再套最小后缀算法"（见延伸思考）。

### 3.4 示例演算

![示例演算：s = "ababab" 的完整走查](images/wc150_q4_walkthrough_ababab.svg)

以 $s = \text{"ababab"}$（$n=6$）为例：

| 轮 | $i$ | $j$ | $k$（进入时） | 比较 | 动作 |
|----|-----|-----|------|------|------|
| 1 | 0 | 1 | 0 | $a<b$ | $i \leftarrow \max(1,1)=1$，$j \leftarrow 2$，$k \leftarrow 0$ |
| 2 | 1 | 2 | 0 | $b>a$ | $j \leftarrow 3$，$k \leftarrow 0$ |
| 3 | 1 | 3 | 0 | $b=b$ | $k \leftarrow 1$ |
| 4 | 1 | 3 | 1 | $a=a$ | $k \leftarrow 2$ |
| 5 | 1 | 3 | 2 | $b=b$ | $k \leftarrow 3$ |
| 停 | 1 | 3 | 3 | $j+k=6=n$ | 返回 $s[1..]=\text{"babab"}$ |

注意第 5 轮之后 $k$ 是**停住**而不是失配：$j=3$ 的后缀 `bab` 恰好是 $i=1$ 的后缀 `babab` 的真前缀，短者更小，$i=1$ 直接胜出；此时 $j+k=n$ 正是循环退出条件。

## 4. 算法细节

1. **三变量的语义**：$i$ 是「目前最好的候选起点」，$j$ 是「待检验的挑战者」，$k$ 是二者已确认相同的字符个数。任何一次跳转之后 $k$ 必须清零，因为新的候选对没有任何已知公共前缀。
2. **$i<j$ 是硬不变式**：初始 $i=0,\ j=1$；只有 $i$ 落败的分支会动 $i$，且随后立刻 $j \leftarrow i+1$，所以 $i<j$ 永远成立，$k$ 这个「偏移」也就不会错位。
3. **$\max$ 不能省**：当 $j \le i+k$ 时挑战者 $j$ 落在出局区间 $[i, i+k]$ 内，新候选必须是 $i+k+1$；当 $j > i+k$ 时 $j$ 才是胜者。写成 $i \leftarrow \max(i+k+1, j)$ 恰好同时覆盖两种情形，并保证 $i$ 严格递增。
4. **跳转宽度是 $k+1$ 而不是 $k$**：$k$ 个已匹配字符让第 $k$ 位（0-indexed）成为第一个不同处，被淘汰的起点是 $i,\ldots,i+k$ 共 $k+1$ 个。
5. **循环条件与越界**：$j+k<n$ 是唯一的下标约束；由于 $i<j$，$i+k<j+k<n$，代码里可以放心访问 $s[i+k]$ 与 $s[j+k]$，无需额外判断。
6. **答案的切出**：循环结束时 $i$ 就是答案起点，返回 $s[i..]$ 只需一次 $O(n-i)$ 的拷贝；不要把候选串一路 `substr` 存下来，否则退化成 $O(n^2)$。
7. **变量类型**：$i,j,k$ 用 `int` 足够（$n \le 4\times10^5$）；字符直接按 `char` 比较即可，无须映射成整数，C++ 的 `string::operator[]` 与 Python 的 `str` 下标都是 $O(1)$。
8. **"只挑最大字符"不够**：$s=\text{"ababab"}$ 中下标 1、3、5 都是 `b`，必须比较这些同首字符候选的后续字符；双指针的价值正是把这部分比较均摊到 $O(n)$。

## 5. 正确性证明

**定义**：称起点 $p$ 是**死的**，若存在 $q \ne p$ 使 $s[q..] > s[p..]$，即 $p$ 不可能成为最大后缀的起点。

**引理 1（后缀归约）**：字典序最大的子串必是某个后缀。

**证明**：设最大子串为 $s[l..r]$。若 $r<n-1$，则 $s[l..r]$ 是 $s[l..n-1]$ 的真前缀，由前缀规则 $s[l..r] < s[l..n-1]$，与最大性矛盾，故 $r=n-1$。∎

**引理 2（支配引理）**：设 $p$、$q$ 是两个起点，$s[p..p+k) = s[q..q+k)$，且 $s[p+k] < s[q+k]$（下标均合法）。则对每个 $t \in [p, p+k]$ 有 $s[t..] < s[t+q-p..]$。

**证明**：固定 $t$，令 $d = q-p$、$u = p+k-t$。后缀 $t$ 与后缀 $t+d$ 的前 $u$ 个字符相同（由 $s[p..p+k) = s[q..q+k)$ 错位截取），第 $u$ 位上前者是 $s[p+k]$、后者是 $s[q+k]$，而 $s[p+k] < s[q+k]$，故前者更小。∎

**引理 3（不变式）**：每轮循环开始时 $i<j$，且 $[0, j)$ 中除 $i$ 外的每个起点都是死的。

**证明**：对轮数归纳。初始 $i=0,\ j=1$，区间 $[0,1)$ 中只有 $i$，成立。设当前轮成立，逐分支检查：

- **相等分支**：$i,j$ 不变，$k$ 加一，$[0,j)$ 不变，不变式保持。
- **$i$ 落败分支**：由引理 2（取 $p=i$、$q=j$），$[i, i+k]$ 中每个 $t$ 都被 $t+(j-i)$ 压制，全是死的；$[0,i)$ 原本就死。新候选 $i' = \max(i+k+1, j)$：若 $i' = i+k+1$，则区间 $(i+k, i')$ 为空；若 $i' = j$（此时 $j > i+k$），则 $(i+k, j)$ 内的起点原本就死。故 $[0, i')$ 中除 $i'$ 外全死；再令 $j' = i'+1$，不变式保持。
- **$j$ 落败分支**：由引理 2 的对称形式（角色互换，$s[i+k] > s[j+k]$），$[j, j+k]$ 中每个 $t$ 都被 $t-(j-i)$ 压制，全是死的；$i$ 不变，$[0,j)$ 原本成立，新 $j' = j+k+1$，故 $[0, j')$ 中除 $i$ 外全死，不变式保持。

∎

**引理 4（退出状态）**：循环退出时 $j+k = n$，且 $s[j..n) = s[i..i+k)$。

**证明**：先证任何时刻 $j+k \le n$。初始 $1 \le n$。相等分支让 $j+k$ 加一，而其前提 $j+k<n$ 保证加后仍 $\le n$；$i$ 落败分支中 $i+k+1 \le n$（因 $i+k < j+k < n$）、$j \le n-1$，故新候选 $i' \le n-1$，$j' = i'+1 \le n$ 且 $k=0$；$j$ 落败分支中 $j' = j+k+1 \le n$ 且 $k=0$。故 $j+k \le n$ 恒成立，而退出条件是 $j+k \ge n$，于是 $j+k = n$。

再证 $s[i..i+k) = s[j..j+k)$ 恒成立：初始 $k=0$ 时为空；相等分支在确认 $s[i+k]=s[j+k]$ 之后才让 $k$ 加一，等式向前延一位；两个跳转分支都把 $k$ 重置为 $0$，等式空成立。取退出时刻即得 $s[j..n) = s[j..j+k) = s[i..i+k)$。∎

**定理**：循环结束时返回的 $s[i..]$ 是字典序最大的后缀，从而是字典序最大的子串。

**证明**：由引理 4，记 $L = j-i > 0$、$K = k = n-j$。任取 $p \ne i$，分两种情形：

- $p < j$：由引理 3，$p$ 是死的，即存在 $q$ 使 $s[q..] > s[p..]$，故 $s[p..]$ 不是最大。
- $p \ge j$：令 $d = p-j \ge 0$，则 $d \le n-1-j = K-1 < K$。由 $s[i..i+K) = s[j..j+K)$ 可得 $s[i+d+m] = s[j+d+m]$ 对所有 $m < K-d$ 成立，于是 $s[p..n) = s[j+d..j+K)$ 与 $s[i+d..i+K)$ 逐字符相同，即 $s[p..]$ 是 $s[i+d..]$ 的真前缀（前者长度 $K-d$，后者长度 $n-i-d = (K-d)+L > K-d$）。由前缀规则 $s[p..] < s[i+d..]$，而 $i+d = p-(j-i) \ne p$，故 $p$ 也是死的。

所以除 $i$ 外每个起点都存在严格更大的后缀，$s[i..]$ 就是最大后缀；再由引理 1，它也是字典序最大的子串。∎

## 6. 复杂度分析

- **时间**：$O(n)$ 均摊。$j$ 只增不减，除相等分支外每轮 $j$ 至少加 1；相等分支每轮让 $j+k$ 加 1 且 $j$ 不动，而一段长度为 $r$ 的连续相等比较总以「一次失配（淘汰 $r+1$ 个起点）」或「循环退出（全程至多一次）」收尾。每个起点只会被淘汰一次，故比较次数总和 $O(n)$，加上 $O(n)$ 次 $j$ 推进，总时间 $O(n)$。
- **空间**：$O(1)$ 额外空间，只有 $i,j,k$ 三个整数；返回值 $s[i..]$ 需要 $O(n-i)$ 的拷贝，这部分算在输出规模上。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <string>
using namespace std;

class Solution {
public:
    string lastSubstring(string s) {
        int n = (int)s.size();
        int i = 0, j = 1, k = 0;   // 候选 i、挑战者 j、公共前缀长度 k
        while (j + k < n) {
            if (s[i + k] == s[j + k]) {
                ++k;                            // 仍在公共前缀内，继续对齐
            } else if (s[i + k] < s[j + k]) {   // i 落败，[i, i+k] 整段出局
                i = max(i + k + 1, j);
                j = i + 1;
                k = 0;
            } else {                            // j 落败，[j, j+k] 整段出局
                j = j + k + 1;
                k = 0;
            }
        }
        return s.substr(i);                     // 最大后缀即答案
    }
};
```

### Python

```python
class Solution:
    def lastSubstring(self, s: str) -> str:
        n = len(s)
        i, j, k = 0, 1, 0           # 候选 i、挑战者 j、公共前缀长度 k
        while j + k < n:
            if s[i + k] == s[j + k]:
                k += 1                          # 仍在公共前缀内
            elif s[i + k] < s[j + k]:           # i 落败，[i, i+k] 整段出局
                i = max(i + k + 1, j)
                j = i + 1
                k = 0
            else:                               # j 落败，[j, j+k] 整段出局
                j = j + k + 1
                k = 0
        return s[i:]                            # 最大后缀即答案
```

## 8. 边界情况与易错点

1. **$n=1$**：$i=0,\ j=1$，$j+k=1=n$ 不进循环，返回 `s[0:]`，正确。
2. **全相同字符**（如 `"aaaa"`）：答案是整串而不是某个真后缀（前缀相同时长者更大）；算法在第一轮把 $k$ 推到 $n-1$ 后因 $j+k=n$ 退出，返回 `s[0:]`。
3. **只有首字符相同**：如 `"ababab"`，候选 1、3、5 首字符都是 `b`，必须继续比较后序字符，不能只挑第一个 `b`。
4. **$k$ 忘记清零**：跳转后若保留 $k$，偏移就对到了旧的候选对上，会读到错误位置甚至死循环。
5. **$\max(i+k+1, j)$ 不是可省的保险**：它把两种情形压进一个表达式——$j \le i+k$ 时取 $i+k+1$（$j$ 自己也被淘汰），$j > i+k$ 时取 $j$（$j$ 是胜者）。丢掉 $\max$ 会让新候选落进已经判死的区间，§5 的不变式随之失效；这种错误在随机对拍里未必暴露，但证明的支点已经断了。
6. **越界**：循环条件只能是 $j+k<n$；写成 $j+k \le n$ 会在最后一轮访问 $s[j+k]$ 越界。
7. **复杂度陷阱**：不要在循环里构造子串做比较（Python 的 `s[i:i+k]`、C++ 的 `s.compare(...)`），否则均摊分析失效，退化为 $O(n^2)$。
8. **答案可能只有一个字符**：如 `"aaaz"` 的答案是 `"z"`（此时 $i=n-1$），`"leetcode"` 的答案是 `"tcode"`；答案长度可以是 $1$ 到 $n$ 之间的任何值，代码里不能假设它至少两位，也不要在 `substr(i)` 之外再加偏移。
9. **输出规模**：答案长度可能接近 $n$（如 `"aaaa..."`），切出答案本身是 $O(n)$，不能把这次拷贝算进"额外空间 $O(1)$"。

**延伸思考**：

1. **最小后缀的现成结论**：$s$ 的 Chen–Fox–Lyndon 分解 $w_1 \ge w_2 \ge \cdots \ge w_m$（每个 $w_i$ 是 Lyndon 词、且按字典序非增）中，最后一个因子 $w_m$ 恰好是 $s$ 的字典序最小后缀，用 Duval 算法 $O(n)$ 即可求出。
2. **为什么最大后缀不能"取反"照搬**：把字母表倒过来只会翻转字符比较，不会翻转「前缀更小」这条规则。例如 $s=\text{"aa"}$，最大后缀是整串 `"aa"`，而倒序字母表下的最小后缀仍是下标 1 的 `"a"`，对不上。这正是本题需要单独维护双指针的原因。
3. **求第 $k$ 大**：若要「字典序第 $k$ 大的子串」，需要后缀数组配合「每个后缀贡献 $n-sa_i-lcp_i$ 个新前缀」再从前往后二分定位；本题的双指针只适合求极值，不适合求排名。
