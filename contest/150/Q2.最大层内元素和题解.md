# LeetCode 最大层内元素和 题解

## 1. 题目概述

- **标题 / 题号**：最大层内元素和（#1161，medium）
- **链接**：https://leetcode.cn/problems/maximum-level-sum-of-a-binary-tree/
- **来源**：LeetCode 第 150 场周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、二叉树

**题意**：根节点位于第 1 层，它的孩子位于第 2 层，依此类推。对每一层求「该层所有节点值之和」，返回**层和最大**的那一层的层号；若有多层并列最大，返回其中**最小**的层号。

**约束**：

- 树中节点数 $1 \le n \le 10^4$
- $-10^5 \le \text{Node.val} \le 10^5$
- 根节点固定为第 1 层，每下降一条边层号加 1
- 至少有一个节点（因此答案总是存在）

## 2. 示例

**示例 1**

```text
输入：root = [1,7,0,7,-8,null,null]
输出：2
解释：第 1 层：1                → 和 1
      第 2 层：7 + 0 = 7        → 和 7
      第 3 层：7 + (-8) = -1    → 和 -1
      最大层和是 7，位于第 2 层，返回 2。
```

**示例 2**

```text
输入：root = [989,null,10250,98693,-89388,null,null,null,-32127]
输出：2
解释：第 1 层：989
      第 2 层：10250
      第 3 层：98693 + (-89388) = 9305
      第 4 层：-32127
      四层的和依次为 989、10250、9305、-32127，最大在第 2 层。
```

> 💡 **并列情形**（题面未给示例，可自行验证）：`root = [0,0,0]` 的三层层和都是 0，此时应返回 1，而不是 3。这个细节决定了比较时该用 `>` 还是 `>=`。

## 3. 解题思路

### 3.1 暴力思路

最直白的暴力是「先求树高 $h$，再对每个层号 $k = 1..h$ 各做一次完整 DFS，收集深度为 $k$ 的节点求和」。单次 DFS 是 $O(n)$，共 $h$ 次，总 $O(nh)$：链状树（$h = n$）退化为 $O(n^2)$，$n = 10^4$ 时约 $10^8$ 次访问，而且同一批节点被反复扫了 $h$ 遍，纯属浪费。

另一类「暴力」是把节点按深度塞进二维数组再逐层求和——那其实已经是正解，剩下的问题只有一个：**怎样在遍历时顺便得到每个节点的深度**。

### 3.2 核心观察：层号就是深度，一趟遍历即可分桶

![按深度分组求和](images/wc150_q2_level_sum_model.svg)

**关键观察**：每个节点**恰好属于一层**，且层号只由「根到它的边数」决定（层号 = 边数 + 1）。设 $S_k$ 为第 $k$ 层的层和，则

$$S_k = \sum_{\text{depth}(u) = k-1} u.\text{val}$$

目标就是求 $\arg\max_k S_k$，并列时取最小的 $k$。
也就是说，本题根本不需要「先分组再求和」，只要在**一次遍历**中把每个节点的值累加到它所属层的桶里即可。

> ⚠️ 节点值可以为负，所以**层和没有单调性**：第 3 层可能远小于第 2 层（示例 1 就是 $7 \to -1$）。任何「用子树和上界剪枝」「层和递增就提前停」的想法都是错的，必须逐层实算后再比较。

接下来只需要决定遍历方式：

- **BFS（逐层快照）**：队列按层推进，天然把「同一层」放在一起，连桶数组都省了；
- **DFS**：维护 `sum[depth]` 数组，递归时把深度带下去，最后线性扫一遍。

两种写法都能做到 $O(n)$，周赛里 BFS 更不容易写错。

### 3.3 算法流程：BFS + 逐层快照

![BFS 逐层快照流程](images/wc150_q2_bfs_flow.svg)

1. 队列初始化为 `[root]`，`level = 1`，`best = -∞`，`ans = 1`。
2. 只要队列非空，就**快照**当前长度 `sz = q.size()`——这 `sz` 个节点恰好构成「当前这一层」。
3. 内层循环执行 `sz` 次：弹出一个节点，把 `node.val` 累加进 `levelSum`，再把非空的左右儿子入队（它们属于下一层）。
4. 内层循环结束后，`levelSum` 就是第 `level` 层的层和；若 `levelSum > best`，更新 `best` 与 `ans`。
5. `level += 1`，回到第 2 步；队列为空时返回 `ans`。

**并列取最小层号**这一点由「层号升序扫描 + 严格大于才更新」自动保证：先遇到的（层号更小的）最大值会一直保留，后续相等的层和不会覆盖它。

DFS 变体（同样的观察，另一种遍历顺序）：

```text
dfs(node, depth):
    if node is null: return
    if depth == len(sums): sums.append(0)
    sums[depth] += node.val
    dfs(node.left,  depth + 1)
    dfs(node.right, depth + 1)

dfs(root, 0)
ans = 1 + argmax_i sums[i]     # argmax 返回第一个最大值的下标 ⇒ 天然最小层号
```

DFS 版本要多一个 `sums` 数组，并且递归深度最大可达 $10^4$，Python 默认递归上限 1000 会直接 `RecursionError`；BFS 没有这个问题，所以参考代码以 BFS 为准。

### 3.4 示例演算

![示例 1 演算表](images/wc150_q2_walkthrough.svg)

对 `root = [1,7,0,7,-8,null,null]` 走一遍 BFS：

| 轮次（层） | 本轮队列快照 | 层和 | 比较结果 |
|------------|--------------|------|----------|
| `level = 1` | `[1]` | 1 | `1 > -∞` → `best = 1, ans = 1` |
| `level = 2` | `[7, 0]` | 7 | `7 > 1` → `best = 7, ans = 2` |
| `level = 3` | `[7, -8]` | -1 | `-1 < 7` → 不更新 |

第 3 轮结束后队列为空，返回 `ans = 2`。注意第 3 层的节点数（2 个）不比第 2 层少，但被 `-8` 拉低到 $-1$——**比较的是层和，不是节点个数**。

## 4. 算法细节

1. **层号与深度对齐**：`level` 从 1 开始，每处理完一层自增；不要写成「深度从 0 开始，最后返回 `level - 1`」又忘了偏移。
2. **`best` 的初值必须是 $-\infty$**（C++ 用 `LLONG_MIN`，Python 用 `float('-inf')`）。初值取 0 是经典错误：全负树里 `levelSum` 永远小于 0，`ans` 会一直停在初值。
3. **严格大于才更新**（`levelSum > best`，不是 `>=`），这是并列取最小层号的唯一保障。
4. **快照 `sz` 后循环 `sz` 次**。若把内层循环写成 `while (!q.empty())`，会把整棵树一次性吞掉，`level` 永远停在 1。
5. **求和使用 `long long`**：单层最坏 $10^4 \times 10^5 = 10^9$，虽然仍在 `int`（$-2^{31} \sim 2^{31}-1$）范围内，但离上界只差一倍，用 `long long` 零成本换安全；Python 整数无溢出。
6. **不需要额外存储**：BFS 版本的「层和」是滚动计算的，空间只有队列；DFS 版本才需要 `sums` 数组（长度 $O(h)$）。
7. **Python 的 BFS 用 `deque`**，`pop(0)` 是 $O(n)$，会让总复杂度退化成 $O(n^2)$；`collections.deque.popleft()` 才是 $O(1)$。

## 5. 正确性证明

**引理 1（队列即一层）**：BFS 第 $k$ 轮开始时，队列中恰好是第 $k$ 层的全部节点，且按从左到右的顺序排列。

**证明**：对 $k$ 归纳。$k = 1$ 时队列只含根，即第 1 层的全部节点，成立。设第 $k$ 轮开始时队列恰为第 $k$ 层全部节点（从左到右）。该轮内层循环执行 $sz$ 次（`sz` 为轮初队列长度），依次弹出这 $sz$ 个节点，并把每个节点的非空左右儿子按「先左后右」入队。由树的父子关系，第 $k+1$ 层的节点集合恰好是第 $k$ 层节点的儿子全体；而「按第 $k$ 层从左到右、每个节点先左后右」入队的顺序正是第 $k+1$ 层从左到右的顺序。轮末队列中只剩这些新入队节点，故第 $k+1$ 轮开始时引理成立。∎

**引理 2（层和正确）**：第 $k$ 轮结束时，`levelSum` 等于第 $k$ 层所有节点值之和。

**证明**：由引理 1，本轮队列中的节点恰为第 $k$ 层的全部节点；内层循环恰好弹出这 $sz$ 个节点各一次，每次把 `node.val` 累加进 `levelSum`。既无遗漏也无重复，故和即为该层所有节点值之和。∎

**引理 3（不变量）**：每轮循环开始时，`best` 等于第 $1..level-1$ 层层和的最大值，`ans` 等于取到该最大值的**最小**层号。

**证明**：对 `level` 归纳。`level = 1` 时已处理层集合为空，`best = -∞`，不变量空真成立。设第 `level` 轮开始时不变量成立，本轮由引理 2 得到第 `level` 层的和 $S$：

- 若 $S > best$，则 $S$ 严格大于此前所有层和，更新后 $best = S$、$ans = level$；由于 `level` 大于此前任何层号，最大值的最小层号只能是 `level`，不变量成立。
- 若 $S \le best$，最大值仍取在此前某层，`ans` 不变；又此前所有层号都小于 `level`，最小层号不受影响，不变量成立。∎

**定理**：算法返回的 `ans` 是全树层和最大层中的最小层号。

**证明**：设树高为 $H$。由引理 1，第 $H$ 轮结束时第 $H$ 层节点的儿子全为空，故队列为空、循环终止，此时恰好处理完第 $1..H$ 层（即全树）。由引理 3，返回时 `best` 是全树的最大层和、`ans` 是取到它的最小层号。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点入队一次、出队一次；出队时只做常数次操作（一次加法 + 两次判空），故内层循环总计 $O(n)$。外层 `while` 每秒掉一层，最多执行 $H \le n$ 轮，每轮除内层循环外只有 $O(1)$ 开销，合计 $O(n)$。
- **空间**：$O(w)$，$w$ 为树的最大层宽。队列中同时存在「当前层剩余节点 + 下一层已入队节点」，规模不超过 $2w$；链状树 $w = 1$ 即 $O(1)$，完全二叉树 $w \approx n/2$ 即 $O(n)$。DFS 变体额外需要 $O(h)$ 的栈空间与 `sums` 数组，最坏 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <queue>
#include <climits>
using namespace std;

// TreeNode 定义由题目给出：
// struct TreeNode { int val; TreeNode *left, *right; };

class Solution {
public:
    int maxLevelSum(TreeNode* root) {
        long long bestSum = LLONG_MIN;   // 必须比任何可能的层和都小
        int bestLevel = 1, level = 1;
        queue<TreeNode*> q;
        q.push(root);
        while (!q.empty()) {
            int sz = (int)q.size();      // 快照：本轮只处理这一层
            long long levelSum = 0;
            for (int i = 0; i < sz; ++i) {
                TreeNode* node = q.front();
                q.pop();
                levelSum += node->val;   // 累加到「本层」
                if (node->left)  q.push(node->left);
                if (node->right) q.push(node->right);
            }
            if (levelSum > bestSum) {    // 严格大于 ⇒ 并列保留更小层号
                bestSum = levelSum;
                bestLevel = level;
            }
            ++level;
        }
        return bestLevel;
    }
};
```

### Python

```python
from collections import deque
from typing import Optional

class Solution:
    def maxLevelSum(self, root: Optional[TreeNode]) -> int:
        best_sum = float('-inf')     # 全负树时初值 0 会出错
        best_level = 1
        level = 1
        q = deque([root])
        while q:
            sz = len(q)              # 快照：本轮只弹出 sz 个
            level_sum = 0
            for _ in range(sz):
                node = q.popleft()   # O(1)；list.pop(0) 是 O(n)
                level_sum += node.val
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)
            if level_sum > best_sum:  # 严格大于 ⇒ 并列取最小层号
                best_sum = level_sum
                best_level = level
            level += 1
        return best_level
```

## 8. 边界情况与易错点

1. **单节点树** `[5]`：第 1 轮 `levelSum = 5 > -∞`，返回 1；不要写「队列为空才返回」而漏掉这一层。
2. **全负树** `[-1,-2,-3,-4]`：三层层和依次为 $-1$、$-2 + (-3) = -5$、$-4$，答案是层号 1。若 `best` 初值写成 0，则没有任何层和能大于它，`ans` 会一直停在初值——初值必须取 $-\infty$；若再顺手把 `ans` 初值写成 0，全负树就直接返回 0 了。
3. **并列最大** `[0,0,0]` 或 `[2,1,1]`：必须用严格大于；改成 `>=` 会返回**最大**层号，恰好与题意相反。
4. **链状树**（只有左孩子或只有右孩子，$10^4$ 个节点）：每层宽度都是 1，队列长度恒为 1，BFS 依旧正确且只用 $O(1)$ 空间；换成递归 DFS 要先 `sys.setrecursionlimit(20000)`。
5. **负数拉低层和**：示例 1 的第 3 层有 2 个节点却是 $-1$，别被「节点多和就大」的直觉带偏；比较对象是层和。
6. **`int` 溢出的临界**：单层最多 $10^4$ 个节点、每个 $10^5$，极值 $10^9$，`int` 勉强不溢出；但一旦题目放宽到 $n = 3\times10^4$ 就会爆，统一用 `long long` 更省心。
7. **队列快照写错**：`for i in range(len(q))` 里 `q` 会变长，Python 的 `range(len(q))` 在循环开始时就固定了长度，是安全的；但写成 `while q:` 嵌套就会把下一层一起处理。C++ 必须先 `int sz = q.size()` 且循环中不要重算 `q.size()`。
