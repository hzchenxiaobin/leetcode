# LeetCode 重新放置石块 题解

## 1. 题目概述

- **标题 / 题号**：重新放置石块（#2766，medium）
- **链接**：https://leetcode.cn/problems/relocate-marbles/
- **来源**：LeetCode 第 108 场双周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、排序、模拟

**题意**：整数数组 `nums` 表示一些石块的初始位置（同一位置可以有多块石块）。再给等长的数组 `moveFrom` 与 `moveTo`：第 $i$ 次操作把**位于 `moveFrom[i]` 的所有石块**移动到 `moveTo[i]`（保证操作时该位置至少有一块石块）。全部操作完成后，按**升序**返回所有仍有石块的位置。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le moveFrom.length \le 10^5$，`moveFrom.length == moveTo.length`
- $1 \le nums[i], moveFrom[i], moveTo[i] \le 10^9$
- 测试保证第 $i$ 步操作时 `moveFrom[i]` 处至少有一个石块

## 2. 示例

**示例 1**

```text
输入：nums = [1,6,7,8], moveFrom = [1,7,2], moveTo = [2,9,5]
输出：[5,6,8,9]
解释：初始位置 {1,6,7,8}
      ① 1→2 得 {2,6,7,8}；② 7→9 得 {2,6,8,9}；③ 2→5 得 {5,6,8,9}。
```

**示例 2**

```text
输入：nums = [1,1,3,3], moveFrom = [1,3], moveTo = [2,2]
输出：[2]
解释：位置 1 的两块与位置 3 的两块先后合并到位置 2，最终只有位置 2 有石块。
```

## 3. 解题思路

### 3.1 暴力思路

每一步操作扫描整个 `nums` 数组，把等于 `moveFrom[i]` 的元素改写成 `moveTo[i]`，最后排序去重输出。单步 $O(N)$，总计 $O(N \cdot M) = 10^{10}$，必然超时。浪费在于：题目只关心**哪些位置有石块**这一布尔事实，而暴力却维护着每一块石块的个体身份——大量同位置石块被无差别地反复改写。

### 3.2 核心观察：只维护「有石块的位置集合」

![核心观察：操作就是集合的先删后插](images/bw108_q2_set_sim_flow.svg)

「把 `moveFrom[i]` 处的**所有**石块移走」对「哪些位置有石块」的净效果是：`moveFrom[i]` 从集合中消失（它必然非空），`moveTo[i]` 进入集合（若原来就有石块则是合并）。也就是说，一次操作就是集合上的两个动作：

$$S \leftarrow (S \setminus \{moveFrom[i]\}) \cup \{moveTo[i]\}$$

每块石块在哪、有几块，对后续操作的语义毫无影响——后续操作同样只看位置。于是用一个哈希集合 $S$ 初始化为 `nums` 去重后的位置，$M$ 次「先删后插」即可，最后排序输出。初始的重复位置被集合自动去重，恰好匹配「有/无石块」的语义。

### 3.3 算法流程

```text
1. S = set(nums)                      # 去重后的初始位置
2. 对 i = 0 … M−1：
        S.erase(moveFrom[i])          # 先删
        S.insert(moveTo[i])           # 后插（顺序很重要，见 §8）
3. 把 S 排序后转为数组返回
```

### 3.4 示例演算

![示例演算：两个官方样例的集合演化过程](images/bw108_q2_example_walkthrough.svg)

**示例 1**：

| 步骤 | 操作 | 集合 $S$ |
|------|------|------|
| 初始 | — | $\{1, 6, 7, 8\}$ |
| ① | 1 → 2 | $\{2, 6, 7, 8\}$ |
| ② | 7 → 9 | $\{2, 6, 8, 9\}$ |
| ③ | 2 → 5 | $\{5, 6, 8, 9\}$ |

输出 $[5, 6, 8, 9]$。✅

**示例 2**：初始 $\{1, 3\}$（两块同位置的石块在集合视角下无差别）；① 1 → 2 得 $\{2, 3\}$；② 3 → 2 得 $\{2\}$。输出 $[2]$。✅ 这一例说明「移动所有石块后原位置清空」与「多块石块合并」两种情形都被集合语义自然覆盖。

## 4. 算法细节

1. **先删后插的顺序**：`erase(moveFrom)` 在前、`insert(moveTo)` 在后。当 `moveFrom == moveTo` 时（题目未禁止），先插后删会把位置误删（插入是空操作，随后 erase 把它删掉），先删后插则保持不变。这一行顺序是本题最值得写进肌肉记忆的细节。
2. **数据结构选择**：`unordered_set` + 最后 `sort` 平均 $O(1)$ 单次操作，通常最快；直接用有序 `set`（C++）或 `sortedset` 可以边维护边有序，省掉最后的排序，代价是每次操作 $O(\log N)$。两者都在复杂度安全区内。
3. **初始去重**：`unordered_set<int> S(nums.begin(), nums.end())` 自动处理 `nums` 中的重复位置；不要先手动去重再排序，多此一举。
4. **值域 $10^9$**：位置值大而稀疏，不能开桶数组，哈希集合是标准选择；`int` 足够容纳（$< 2^{31}$）。
5. **输出必须升序**：集合遍历序不确定（`unordered_set`），务必显式排序后输出。
6. **「保证 moveFrom 有石块」的前提**：这让 `erase` 语义无歧义（删的一定存在）；即使 erase 不存在的键，`unordered_set::erase` 也只是无操作，代码依然稳健，但不要依赖这一点去掩盖逻辑错误。

## 5. 正确性证明

**引理（单步操作的集合语义）**：设操作前有石块的位置集合为 $S$，且 $f = moveFrom[i] \in S$。记 $t = moveTo[i]$。则操作后有石块的位置集合恰为 $S' = (S \setminus \{f\}) \cup \{t\}$。

**证明**：操作把 $f$ 处**全部**石块移到 $t$。任取位置 $p$：
- 若 $p = f$：当 $t \ne f$ 时，$f$ 处石块被清空且没有其他石块来源（石块只在操作指定的位置间移动），故 $f \notin S'$，与 $f \notin (S \setminus \{f\}) \cup \{t\}$ 一致；当 $t = f$ 时石块原地去向不变，$f \in S'$，而 $(S \setminus \{f\}) \cup \{f\} = S \ni f$，一致。
- 若 $p = t \ne f$：$t$ 处原有石块保留，且新增来自 $f$ 的石块，故 $t \in S'$，与公式一致。
- 若 $p \notin \{f, t\}$：该位置石块既不移动也没有外来石块（第 $i$ 步只搬 $f$ 处的石块），有无状态不变，与公式一致。∎

**定理**：算法最终集合等于全部操作结束后有石块的位置集合，升序输出即答案。

**证明**：对操作步数 $i$ 归纳。基础：初始时 `S = set(nums)` 恰为初始有石块位置（`nums` 中出现即至少一块）。归纳步：代码执行 `erase(f); insert(t)`，其结果恰为 $(S \setminus \{f\}) \cup \{t\}$——先删后插时若 $f = t$，删除后插入同键恢复原状；若 $f \ne t$，两次操作互不干扰。由引理，这与真实语义一致。归纳成立。终止后对 `S` 排序输出，即升序的全部有石块位置。∎

## 6. 复杂度分析

- **时间**：$O(N + M + K \log K)$，$K$ 为最终位置数（$K \le N + M$）。哈希集合初始化 $O(N)$、每步均摊 $O(1)$、输出排序 $O(K \log K)$；若用有序集合则为 $O((N + M) \log N + K)$，同样安全。
- **空间**：$O(K)$。集合至多存放 $N + M$ 个位置；输出数组 $O(K)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> relocateMarbles(vector<int>& nums, vector<int>& moveFrom, vector<int>& moveTo) {
        unordered_set<int> pos(nums.begin(), nums.end());
        for (int i = 0; i < (int)moveFrom.size(); ++i) {
            pos.erase(moveFrom[i]);       // 先删
            pos.insert(moveTo[i]);        // 后插：moveTo == moveFrom 时位置不丢
        }
        vector<int> ans(pos.begin(), pos.end());
        sort(ans.begin(), ans.end());
        return ans;
    }
};
```

### Python

```python
class Solution:
    def relocateMarbles(self, nums: list[int], moveFrom: list[int], moveTo: list[int]) -> list[int]:
        pos = set(nums)
        for f, t in zip(moveFrom, moveTo):
            pos.discard(f)               # 先删（discard 对不存在的键也无操作）
            pos.add(t)                   # 后插：moveTo == moveFrom 时位置不丢
        return sorted(pos)
```

> 💡 两份代码均通过官方示例（`[5,6,8,9]`、`[2]`），并与「multiset 逐石块模拟（Python 侧用列表改写）」的暴力对拍：C++ 侧 20000 组、Python 侧 3000 组随机数据（位置值域压缩制造大量合并与 `moveTo == moveFrom` 的退化情形），`mismatch = 0`。

## 8. 边界情况与易错点

1. **先删后插**：`moveFrom[i] == moveTo[i]` 时，先插后删会让该位置凭空消失。题目未禁止这种输入，顺序反了就是错解。
2. **初始重复位置**：`nums = [1,1,3,3]` 必须去重看待；集合天然处理，若用「计数数组 + 值域桶」思路要先想清楚值域 $10^9$ 开不了桶。
3. **合并**：移动目标位置可能已有石块（示例 2 的终点 `[2,2,2,2]`），集合的 `insert` 对已存在键是空操作，无需分支。
4. **输出升序**：`unordered_set` 遍历序不确定，返回前必须 `sort` / `sorted`。
5. **别真的去移动每块石块**：把 `nums` 当作逐块状态数组维护是 $O(NM)$ 的根源；先问「输出需要什么信息」再选状态表示。
6. **`erase` 的两种重载**：C++ 中 `erase(key)` 按值删除（本例正确用法）；误把迭代器语义与值语义混用时，`set` 上 `erase(key)` 若键不存在返回 0 而非崩溃，问题会被掩盖。
