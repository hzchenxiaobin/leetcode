# LeetCode 黑格子的数目 题解

## 1. 题目概述

- **标题 / 题号**：黑格子的数目（#2768，medium）
- **链接**：https://leetcode.cn/problems/number-of-black-blocks/
- **来源**：LeetCode 第 108 场双周赛 Q4
- **难度**：中等
- **标签**：数组、哈希表、枚举

**题意**：给定 $m \times n$ 网格与黑格坐标列表 `coordinates`（两两互不相同），其余格子均为白色。一个**块**是网格中 $2 \times 2$ 的子矩阵（左上角为 $(x, y)$，$0 \le x < m-1$、$0 \le y < n-1$）。返回长度为 5 的数组 `arr`，其中 `arr[i]` 是**恰好**含 $i$ 个黑格的块的数目。

**约束**：

- $2 \le m, n \le 10^5$
- $0 \le coordinates.length \le 10^4$
- $0 \le coordinates[i][0] < m$，$0 \le coordinates[i][1] < n$
- 坐标对两两互不相同

## 2. 示例

**示例 1**

```text
输入：m = 3, n = 3, coordinates = [[0,0]]
输出：[3,1,0,0,0]
解释：唯一含黑格的块是左上角 (0,0) 的块；其余 (0,1)、(1,0)、(1,1) 三个块全白。
```

**示例 2**

```text
输入：m = 3, n = 3, coordinates = [[0,0],[1,1],[0,2]]
输出：[0,2,2,0,0]
解释：块 (0,0)、(0,1) 各含 2 个黑格；块 (1,0)、(1,1) 各含 1 个黑格。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $(m-1)(n-1)$ 个块，统计每块的黑格数——数量级 $10^{10}$，仅遍历就必然超时；即便黑格判定用哈希集合 $O(1)$，乘上块数也无法承受。瓶颈的根源是**块多黑格少**：至多 $10^4$ 个黑格，却试图扫 $10^{10}$ 个块，其中绝大多数一个黑格都没有。正确方向是把统计反过来做。

### 3.2 核心观察：每个黑格向至多 4 个块「贡献」

![核心观察：一个黑格只属于至多四个块，边界处裁剪](images/bw108_q4_cell_blocks.svg)

**格 → 块**的对偶关系：黑格 $(x, y)$ 落在左上角为 $(x-1, y-1)$、$(x-1, y)$、$(x, y-1)$、$(x, y)$ 的四个块中（把这些候选裁剪到 $0 \le bx < m-1$、$0 \le by < n-1$ 的合法范围）。于是不再「遍历块找黑格」，而是「遍历黑格给块计数」：

$$\text{cnt}[B] = \#\{\,\text{黑格 } c : c \in B\,\}$$

只需要一个以块左上角为键的哈希表。全部黑格处理完后：

- `arr[i]`（$1 \le i \le 4$）= 哈希表中计数恰为 $i$ 的块数；
- `arr[0]` = 总块数 $-\ $ 被触及（哈希表非空）的块数，其中总块数 $= (m-1)(n-1)$。

每个黑格贡献 $O(1)$ 次哈希操作，总代价 $O(K)$（$K$ 为黑格数），与 $m, n$ 完全解耦——这就是「在稀疏对象上做贡献统计」的威力。

### 3.3 算法流程

![算法流程：黑格贡献 → 哈希计数 → 补集求 arr[0]](images/bw108_q4_count_flow.svg)

```text
1. cnt = 空哈希表（键：块左上角 (bx, by)，值：块内黑格数）
2. 对每个黑格 (x, y)：
        对 dx ∈ {−1, 0}、dy ∈ {−1, 0}：
            bx = x + dx，by = y + dy
            若 0 ≤ bx < m−1 且 0 ≤ by < n−1：cnt[(bx, by)] += 1
3. arr[1..4] 由 cnt 的值统计；arr[0] = (m−1)(n−1) − |cnt|
4. 返回 arr
```

### 3.4 示例演算

![示例演算：3×3 网格三个黑格对四个块的贡献](images/bw108_q4_example_walkthrough.svg)

以示例 2（$3 \times 3$，黑格 $(0,0)$、$(1,1)$、$(0,2)$）为例，全部合法块是 $(0,0)$、$(0,1)$、$(1,0)$、$(1,1)$：

| 黑格 | 候选块（裁剪后） | 贡献 |
|------|------|------|
| $(0,0)$ | $(0,0)$ | `cnt[(0,0)]++` |
| $(1,1)$ | $(0,0),(0,1),(1,0),(1,1)$ | 四个块各 `++` |
| $(0,2)$ | $(0,1)$（$(0,2)$ 因 $by = 2 \ge n-1$ 被裁掉） | `cnt[(0,1)]++` |

汇总：`cnt[(0,0)]=2`，`cnt[(0,1)]=2`，`cnt[(1,0)]=1`，`cnt[(1,1)]=1`。于是 `arr[2] = 2`、`arr[1] = 2`、`arr[0] = 4 - 4 = 0`，即 $[0,2,2,0,0]$。✅ 注意黑格 $(0,2)$ 位于网格**右边界**，它只属于 $1$ 个块而非 $4$ 个——裁剪条件是边界黑格必须处理的正确性来源。

## 4. 算法细节

1. **块键的编码**：用 `bx * n + by` 把二维左上角压成一个整数键。$bx \le m-2 < 10^5$、$n \le 10^5$，乘积达 $10^{10}$，**必须用 `long long`**（32 位 `int` 上界约 $2.1 \times 10^9$，直接溢出为负键，产生错误合并）。Python 用元组 `(bx, by)` 或同样的整数编码均可（大整数无溢出）。
2. **`arr[0]` 用补集**：总块数 $(m-1)(n-1)$ 本身就超出 `int`（达 $10^{10}$），`arr[0]` 也大，故 LeetCode 接口返回 `long[]`（C++ `vector<long long>`），`arr[1..4]` 至多 $4K$ 也不小，全数组统一 `long long`。
3. **候选循环写法**：`dx, dy ∈ {−1, 0}` 的双重循环把「四个候选」写得最不容易错；写成显式四个 `if` 时容易抄错下标。裁剪条件**合并**成 `bx >= 0 && bx < m-1 && by >= 0 && by < n-1`（注意是 `< m-1` 不是 `< m`——块的行号最大到 $m-2$）。
4. **互不相同的前提**：约束保证坐标两两不同，同一黑格不会被重复贡献；若题目允许重复，须先用 `set<pair<int,int>>` 去重再统计，否则同一黑格会给它的块重复加分。
5. **`arr[v]++` 上界**：一个块至多 4 个黑格，`cnt` 值域 $[1,4]$，数组 5 项够用；无需担心越界。
6. **空 `coordinates`**：哈希表为空，`arr = [total, 0, 0, 0, 0]`，代码无需特判。

## 5. 正确性证明

**引理 1（格与块的对偶）**：黑格 $c = (x, y)$ 属于块 $B$（左上角 $(bx, by)$）当且仅当 $bx \in \{x-1, x\}$、$by \in \{y-1, y\}$，且 $0 \le bx < m-1$、$0 \le by < n-1$。

**证明**：$B$ 的四个格子是 $(bx, by)$、$(bx+1, by)$、$(bx, by+1)$、$(bx+1, by+1)$。$c \in B$ 等价于 $bx \le x \le bx+1$ 且 $by \le y \le by+1$，即 $x - 1 \le bx \le x$、$y - 1 \le by \le y$。块本身的定义要求 $bx \in [0, m-2]$、$by \in [0, n-2]$，与上式取交即得。∎

**引理 2（计数的忠实性）**：算法结束后，对每个被触及的块 $B$，`cnt[B]` 恰等于 $B$ 内黑格数；未被触及的块不在表中（等价于 0）。

**证明**：由引理 1，遍历黑格 $c$ 时对 $B$ 的 `++` 恰发生在 $c \in B$ 时，且一次遍历每个 $(c, B)$ 至多触发一次（四个候选互异）。反之，任意 $c \in B$ 的配对都会被触发——遍历覆盖全部黑格。又因黑格两两互不相同，同一 $c$ 不会被处理两次。故 `cnt[B]` = $\#\{c \in B : c \text{ 黑}\}$。∎

**定理**：`arr[i]` = 恰含 $i$ 个黑格的块的数目（$0 \le i \le 4$），且 $\sum_{i=0}^{4} arr[i] = (m-1)(n-1)$。

**证明**：由引理 2，哈希表把全部块按黑格数分成「恰 $i$ 个（$i \ge 1$）」与「0 个（不在表中）」两类；`arr[i]`（$i \ge 1$）由表值直接统计故正确；块总数 $(m-1)(n-1)$ 减去表大小即 0 黑格块数，`arr[0]` 正确。求和式成立。∎

## 6. 复杂度分析

- **时间**：$O(K)$，$K = $ `coordinates.length` $\le 10^4$。每个黑格至多 4 次哈希表更新；哈希表大小至多 $4K$。与 $m, n$ 无关——这正是与暴力 $O(mn)$ 的分水岭。
- **空间**：$O(\min(4K,\ (m-1)(n-1))) = O(K)$，哈希表至多存 $4K$ 个块键；输出数组 $O(1)$（5 项）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<long long> countBlackBlocks(int m, int n, vector<vector<int>>& coordinates) {
        vector<long long> ans(5, 0);
        unordered_map<long long, int> cnt;          // 块左上角 (bx, by) → 黑格数
        for (const auto& c : coordinates)
            for (int dx = -1; dx <= 0; ++dx)
                for (int dy = -1; dy <= 0; ++dy) {
                    long long bx = c[0] + dx, by = c[1] + dy;
                    if (bx < 0 || bx >= m - 1 || by < 0 || by >= n - 1) continue;
                    ++cnt[bx * n + by];             // 编码成 long long 键
                }
        long long total = (long long)(m - 1) * (n - 1);
        ans[0] = total - (long long)cnt.size();     // 补集：0 黑格的块
        for (const auto& [k, v] : cnt) ans[v]++;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countBlackBlocks(self, m: int, n: int, coordinates: list[list[int]]) -> list[int]:
        cnt = {}                                    # 块左上角 (bx, by) → 黑格数
        for x, y in coordinates:
            for bx in (x - 1, x):
                for by in (y - 1, y):
                    if 0 <= bx < m - 1 and 0 <= by < n - 1:
                        cnt[(bx, by)] = cnt.get((bx, by), 0) + 1
        ans = [0] * 5
        ans[0] = (m - 1) * (n - 1) - len(cnt)       # 补集：0 黑格的块
        for v in cnt.values():
            ans[v] += 1
        return ans
```

> 💡 两份代码均通过官方示例（`[3,1,0,0,0]`、`[0,2,2,0,0]`），并与「逐块扫描统计」的 $O(mn)$ 暴力对拍：C++ 侧 4000 组、Python 侧 1200 组随机小网格（含黑格贴边、$m=2$ 或 $n=2$ 的退化），`mismatch = 0`；另以 $m = n = 10^5$、$10^4$ 个黑格做了压力测试，块数总和 $9999800001 = 99999^2$ 校验一致。

## 8. 边界情况与易错点

1. **键编码溢出**：`bx * n + by` 在 $m, n \le 10^5$ 时约 $10^{10}$，C++ 必须先转 `long long` 再乘（`(long long)bx * n + by` 或如参考代码直接用 `long long` 变量承接）；Python 无此虞。
2. **返回类型是 `long[]`**：`arr[0]` 可达约 $10^{10}$，C++ 返回 `vector<long long>`、中间 `total` 也用 `long long`；接口签名不匹配会直接提交失败。
3. **裁剪边界是 `< m-1`**：块左上角合法范围是 $[0, m-2]$，写 `< m` 会把不存在的块计入（对答案产生污染），写 `<= m-2` 等价但少有人一次写对。
4. **边界黑格块数不足 4**：贴上/下/左/右边缘乃至四角的黑格属于 $2$ 个、$1$ 个块，裁剪逻辑自动处理；漏裁剪则哈希表里出现非法键，`arr` 总和超过 $(m-1)(n-1)$。
5. **坐标互不相同的前提**：若允许重复黑格，需先 `set` 去重，否则同一格重复贡献；本题约束免除了这一步，但值得在变体中警惕。
6. **空列表**：`coordinates = []` 时返回 `[(m-1)(n-1), 0, 0, 0, 0]`，别对空输入做特殊返回。
7. **自检技巧**：$\sum arr[i]$ 必须等于 $(m-1)(n-1)$，对拍与提交前都可用它做一次快速验证。
