# LeetCode 滑动子数组的美丽值 题解

## 1. 题目概述

- **标题 / 题号**：滑动子数组的美丽值（#2653，medium）
- **链接**：https://leetcode.cn/problems/sliding-subarray-beauty/
- **来源**：LeetCode 第 342 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、滑动窗口、计数排序

**题意**：给定长度为 $n$ 的整数数组 `nums`，对**每个**长度为 $k$ 的子数组求「美丽值」：把子数组元素按非降排序（重复保留），若**第 $x$ 小**的整数是**负数**，美丽值即为该数本身，否则美丽值为 $0$。返回 $n - k + 1$ 个美丽值，依次对应以下标 $0, 1, \ldots, n-k$ 开头的窗口。

**约束**：

- $1 \le n \le 10^5$
- $1 \le k \le n$
- $1 \le x \le k$
- $-50 \le nums[i] \le 50$

> 💡 「第 $x$ 小」按**排序后的位置**计，重复值占多个位置。而本题真正的钥匙藏在约束最后一行：**值域只有 $[-50, 50]$ 共 101 种取值**——它直接决定了正解不是平衡树或堆，而是**值域计数**。

## 2. 示例

**示例 1**

```text
输入：nums = [1,-1,-3,-2,3], k = 3, x = 2
输出：[-1,-2,-2]
解释：窗口 [1,-1,-3] 排序后第 2 小是 -1；
      窗口 [-1,-3,-2] 排序后第 2 小是 -2；
      窗口 [-3,-2,3] 排序后第 2 小是 -2。
```

**示例 2**

```text
输入：nums = [-1,-2,-3,-4,-5], k = 2, x = 2
输出：[-1,-2,-3,-4]
解释：全为负数，第 2 小即每个窗口内的最大值。
```

**示例 3（第 x 小非负 → 美丽值 0）**

```text
输入：nums = [-3,1,2,-3,0,-3], k = 2, x = 1
输出：[-3,0,-3,-3,-3]
解释：窗口 [1,2] 的最小值是 2，不是负数，美丽值为 0。
```

## 3. 解题思路

### 3.1 暴力：逐窗口排序

对每个窗口复制 $k$ 个元素排序，取第 $x$ 个判断是否为负。时间 $O\big((n-k+1) \cdot k \log k\big)$：$n = 10^5$、$k \approx n/2$ 时约 $4 \times 10^{10}$ 次操作，必然超时。瓶颈在于**相邻窗口只差一个元素，却重复排序了大量重叠部分**——固定窗口查询类问题的标准解法就是滑动窗口 + 增量维护。

### 3.2 核心观察：小值域 → 桶计数找第 x 小

![美丽值定义：排序后第 x 小，负数才取](images/wc342_q3_beauty_definition.svg)

两个观察把问题化简到底：

**观察 1（第 $x$ 小 = 计数前缀和首次达标）**：设 $s(v)$ 为窗口内值 $\le v$ 的元素个数，则第 $x$ 小的数就是**最小的** $v$ 使得 $s(v) \ge x$（引理 1，证明见 §5）。于是「找第 $x$ 小」根本不需要排序，只需**从 $-50$ 往上数数**。

**观察 2（非负数与答案无关）**：第 $x$ 小是负数 $\iff$ 窗口内负数个数 $\ge x$，且此时第 $x$ 小恰好等于**第 $x$ 小的负数**（引理 2）。于是桶**只开 50 个**（$v \in [-50, -1]$），扫描也只扫负数段；扫不满 $x$ 个就直接输出 $0$。

![桶计数模型：负数桶 + 前缀和扫描](images/wc342_q3_counting_scan.svg)

窗口每次滑动只**移出一个、移入一个**元素，对计数桶都是 $O(1)$ 的加减——这正是「滑动窗口 + 值域计数」的标准配合：**窗口增量维护结构，结构上快速查询**。

### 3.3 算法流程

```text
1. 开桶 cnt[50]：cnt[v+50] 记录窗口内值为 v 的负数出现次数
2. 从左到右遍历 i = 0 … n−1：
   a. 入窗：若 nums[i] < 0，则 cnt[nums[i]+50] += 1
   b. 若 i ≥ k−1（首个窗口形成，此后每轮都是一个完整窗口）：
      - cum = 0，从 j = 0（值 −50）扫到 j = 49（值 −1）：
          cum += cnt[j]；一旦 cum ≥ x，答案 = j − 50，立即 break
      - 若扫完仍未达标（负数不足 x 个），答案 = 0
      - 出窗：左端 nums[i−k+1] 若为负，cnt[nums[i−k+1]+50] −= 1
```

### 3.4 示例演算

![示例 1 走查：滑动与负数桶的增删](images/wc342_q3_slide_walkthrough.svg)

以示例 1（`nums = [1,-1,-3,-2,3]`，$k=3$，$x=2$）走查三个窗口：

| 窗口 | 负数桶 | 扫描过程 | 美丽值 |
|------|--------|----------|--------|
| $[1,-1,-3]$ | $\{-3{:}1,\ -1{:}1\}$ | $\mathrm{cum}(-3)=1 < 2$，$\mathrm{cum}(-1)=2 \ge 2$ | $-1$ |
| $[-1,-3,-2]$ | $\{-3{:}1,\ -2{:}1,\ -1{:}1\}$ | $\mathrm{cum}(-3)=1 < 2$，$\mathrm{cum}(-2)=2 \ge 2$ | $-2$ |
| $[-3,-2,3]$ | $\{-3{:}1,\ -2{:}1\}$ | $\mathrm{cum}(-3)=1 < 2$，$\mathrm{cum}(-2)=2 \ge 2$ | $-2$ |

注意两次滑动的对比：移出 $-1$ 会让桶 $cnt[49]$ 清零，而移入 $3$（非负）**完全不碰桶**——负数桶的增删只由负数元素驱动，这正是观察 2 带来的红利。

## 4. 算法细节

1. **桶下标映射**：$v \in [-50, -1]$ 映射到下标 $v + 50 \in [0, 49]$，数组开 50 即够。**非负数一律不入桶**，判负用 `nums[i] < 0`（别写成 `<= 0`，$0$ 不是负数）。
2. **「入 → 查 → 出」三段式**：`nums[i]` 先入窗，`i >= k-1` 时先查询当前窗口答案、再移出 `nums[i-k+1]`。这样首个窗口天然在循环内形成，无需单独初始化，也规避了「先移出再查询」导致的窗口错位。
3. **提前 break**：前缀和一旦 $\ge x$ 立即停止扫描，平均远扫不满 50 步；负数不够 $x$ 个时才会扫满 50 步输出 $0$。
4. **为什么不用对顶堆 / 平衡树**：值域仅 101 种，计数法每次查询至多 $O(50)$、无堆调整与延迟删除的常数，代码还短一个量级。Python 用 `SortedList` 也能过（$O(n \log k)$），但属于杀鸡用牛刀（见方法二）。
5. **答案数组长度**为 $n - k + 1$，C++ 提前 `reserve`、Python 一次 `append` 均可，无扩容抖动之忧。

## 5. 正确性证明

**引理 1（第 $x$ 小的计数刻画）**：把窗口的 $k$ 个元素非降排序为 $a_1 \le a_2 \le \cdots \le a_k$。设 $s(v)$ 表示窗口内值 $\le v$ 的元素个数，则 $a_x = \min \{\, v : s(v) \ge x \,\}$。

**证明**：先证 $s(a_x) \ge x$：$a_1, a_2, \ldots, a_x$ 这 $x$ 个元素都 $\le a_x$，故 $s(a_x) \ge x$。再证任何 $v < a_x$ 都有 $s(v) < x$：若 $s(v) \ge x$，则窗口内至少有 $x$ 个元素 $\le v < a_x$，于是排序后第 $x$ 个元素 $\le v < a_x$，与 $a_x$ 是第 $x$ 小矛盾。又 $s$ 只在窗口出现过的取值处变化，故最小达标 $v$ 可在该集合内取到，即 $a_x$ 本身。∎

**引理 2（负数等价）**：记窗口内负数个数为 $m$，则 $a_x < 0 \iff m \ge x$；且 $m \ge x$ 时 $a_x$ 等于窗口负数中第 $x$ 小者（按重数计）。

**证明**：排序后，因负数严格小于一切非负数，$m$ 个负数恰好占据前 $m$ 个位置 $a_1, \ldots, a_m$，且同号内部保持有序。若 $m \ge x$，则 $a_x$ 落在负数段内，即负数中第 $x$ 小者，为负数；若 $m < x$，则 $a_x$ 位于第 $m+1$ 位及以后，是非负数。∎

**定理（算法正确性）**：若每轮查询时 `cnt` 恰为当前窗口负数多重集的计数数组，则算法输出的每个数等于该窗口的美丽值。

**证明**：对窗口编号做归纳，**不变量**为「查询时刻 `cnt[v+50]` = 窗口内值为 $v$ 的负数出现次数」。首个窗口形成前，每个元素入窗时各加一次桶，不变量成立。窗口从 $[i-k+1, i]$ 滑到 $[i-k+2, i+1]$ 时：本轮查询后移出 $nums[i-k+1]$（为负则相应桶减 1），下一轮先移入 $nums[i+1]$（为负则相应桶加 1），两次 $O(1)$ 增删恰好同步了窗口元素集的差集，不变量保持。

在不变量之下，扫描中维护的 $\mathrm{cum}(v) = \sum_{u=-50}^{v} cnt[u+50]$ 等于窗口内值 $\le v$ 的**负数**个数；而当 $v \le -1$ 时，窗口内值 $\le v$ 的元素必为负数，故 $\mathrm{cum}(v) = s(v)$。由引理 1，扫描中首个满足 $\mathrm{cum} \ge x$ 的 $v$ 即 $a_x$，算法输出 $v = a_x < 0$，符合美丽值定义；若扫到 $v = -1$ 仍有 $\mathrm{cum} < x$，即 $s(-1) < x$，由引理 2 得 $m < x$、$a_x \ge 0$，算法输出 $0$，同样符合定义。∎

> 💡 这套证明骨架是**滑动窗口类题目的万能模板**：先陈述「窗口 ↔ 辅助结构」的不变量，再对滑动步骤归纳证明不变量保持，最后把「查询正确性」归结为辅助结构上的数学性质（这里是引理 1 / 引理 2）。

## 6. 复杂度分析

- **时间复杂度**：$O(50n)$。每个元素一次入桶 + 一次出桶（各 $O(1)$），每个窗口查询至多扫 50 个桶；$n = 10^5$ 时约 $5 \times 10^6$ 次基本操作，远低于时限。对比暴力 $O(nk \log k)$ 与有序集合 $O(n \log k)$，小值域让计数法成为最轻量的选择。
- **空间复杂度**：辅助计数数组 $O(50)$，输出数组 $O(n - k + 1)$；不计输出即为 $O(1)$ 额外空间。

## 7. 参考代码

### 方法一：滑动窗口 + 值域计数（$O(50n)$，推荐）

### C++

```cpp
class Solution {
  public:
    vector<int> getSubarrayBeauty(vector<int>& nums, int k, int x) {
        int n = nums.size();
        int cnt[50] = {};                       // cnt[v+50]：值为 v 的负数出现次数
        vector<int> ans;
        ans.reserve(n - k + 1);
        for (int i = 0; i < n; ++i) {
            if (nums[i] < 0) cnt[nums[i] + 50]++;           // 入窗
            if (i >= k - 1) {
                int beauty = 0, cum = 0;
                for (int j = 0; j < 50; ++j) {               // 取值 j-50：-50 → -1
                    cum += cnt[j];
                    if (cum >= x) {
                        beauty = j - 50;
                        break;
                    }
                }
                ans.push_back(beauty);
                if (nums[i - k + 1] < 0) cnt[nums[i - k + 1] + 50]--;   // 出窗
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getSubarrayBeauty(self, nums: List[int], k: int, x: int) -> List[int]:
        cnt = [0] * 50                       # cnt[v+50]：值为 v 的负数出现次数
        ans = []
        for i, v in enumerate(nums):
            if v < 0:                        # 入窗：只有负数进桶
                cnt[v + 50] += 1
            if i >= k - 1:
                beauty, cum = 0, 0
                for j in range(50):          # 取值 j-50：-50 扫到 -1
                    cum += cnt[j]
                    if cum >= x:
                        beauty = j - 50
                        break
                ans.append(beauty)
                out = nums[i - k + 1]        # 出窗
                if out < 0:
                    cnt[out + 50] -= 1
        return ans
```

### 方法二：SortedList 有序集合（$O(n \log k)$，通用值域）

### Python

```python
from sortedcontainers import SortedList

class Solution:
    def getSubarrayBeauty(self, nums: List[int], k: int, x: int) -> List[int]:
        sl = SortedList()
        ans = []
        for i, v in enumerate(nums):
            sl.add(v)
            if i >= k:
                sl.remove(nums[i - k])
            if i >= k - 1:
                t = sl[x - 1]                # 窗口第 x 小
                ans.append(t if t < 0 else 0)
        return ans
```

## 8. 边界情况与易错点

1. **「非负」输出 0 而非第 $x$ 小本身**：第 $x$ 小等于 $0$ 也算非负 → 美丽值 $0$（示例 3 的窗口 $[1,2]$，$x=1$ 时最小值 $1$ 同样输出 $0$）。「是负数才取值」是本题最易背反的定义。
2. **$0$ 不是负数**：入桶判 `v < 0`；误写 `<= 0` 会把 $0$ 计入负数桶，第 $x$ 小被顶小，答案错成更小的负数。
3. **下标映射 $v + 50$**：手滑写成 `50 - v` 或 `abs(v)` 会把桶序整个反转；务必用 `nums = [-50, ...]` 与 `[-1, ...]` 两端自测。
4. **滑动顺序错位**：先移出再查询会让查询发生在窗口未对齐的时刻（首个窗口少一个元素）；「入 → 查 → 出」三段式可完全规避边界分支。
5. **重复负数按重数计**：$[-3, -3]$ 的第 1、2 小都是 $-3$——桶计数天然支持重数，任何「去重」动作都是错的。
6. **极端形态自测**：$k = n$（单窗口）、$x = k$（取窗口最大）、全部非负（输出全 0）、全部 $-50$（输出全 $-50$），建议各过一遍。
7. **C++ 桶大小**：开 `int cnt[50]`，下标 $v + 50 \in [0, 49]$；若偏移量手误（如 $v + 51$）会数组越界且编译期不报错。
