# LeetCode 计算列车到站时间 题解

## 1. 题目概述

- **标题 / 题号**：计算列车到站时间（#2651，easy）
- **链接**：https://leetcode.cn/problems/calculate-delayed-arrival-time/
- **来源**：LeetCode 第 342 场周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：给定正整数 `arrivalTime` 表示列车正点到站的小时数（24 小时制），另有正整数 `delayedTime` 表示列车延误的小时数。返回列车**实际到站**的小时数（24 小时制）。

**约束**：

- `1 <= arrivalTime < 24`
- `1 <= delayedTime <= 24`

> 💡 本题无需任何数据结构，一行取模即是全部——重点是想到「24 小时制 = 模 24 的世界」并处理好好等于 24 的边界。

## 2. 示例

**示例 1**

```text
输入：arrivalTime = 15, delayedTime = 5
输出：20
解释：15:00 正点，延误 5 小时，15 + 5 = 20（20:00）。
```

**示例 2**

```text
输入：arrivalTime = 13, delayedTime = 11
输出：0
解释：13:00 正点，延误 11 小时，13 + 11 = 24，24 小时制中表示为 00:00，返回 0。
```

**示例 3（边界补充）**

```text
输入：arrivalTime = 23, delayedTime = 24
输出：23
解释：最大输入：23 + 24 = 47，47 mod 24 = 23（次日 23:00）。
```

## 3. 解题思路

### 3.1 暴力思路

逐小时模拟：从 `arrivalTime` 出发，`delayedTime` 次每次加 1，超过 23 就回到 0。时间 `O(delayedTime)`，对本题数据范围完全够用，但完全没必要——加法和取模都是 `O(1)`。

### 3.2 核心观察：模 24 的加法

![24 小时钟面：13 + 11 = 24 → 00:00](images/train_arrival_clock_concept.svg)

24 小时制中小时数的合法范围是 `0~23`，越过 23 就折回 0（24:00 即 00:00）。这正是**模运算**的定义：

$$
\text{实际到站} = (\text{arrivalTime} + \text{delayedTime}) \bmod 24
$$

- 和 `< 24`：不越界，直接返回原值（`mod` 不影响结果）
- 和 `≥ 24`：折返，等价于减去 24

由约束，和的取值范围是 `2 <= sum <= 23 + 24 = 47 < 48`，最多越界一次，减一个 24（即 `mod 24`）必落回 `0~23`。

### 3.3 算法流程

```text
1. 读入 arrivalTime, delayedTime
2. 返回 (arrivalTime + delayedTime) % 24
```

### 3.4 示例演算

![数轴演算：15+5=20 不越界；13+11=24 折返到 0](images/train_arrival_example_walkthrough.svg)

| 示例 | arrivalTime | delayedTime | 和 | 是否 ≥ 24 | 答案 |
|------|-------------|-------------|-----|-----------|------|
| 1 | 15 | 5 | 20 | 否 | 20 |
| 2 | 13 | 11 | 24 | 是（恰为 24）| 0 |
| 3 | 23 | 24 | 47 | 是（最大和）| 23 |

## 4. 算法细节

1. **一步加法**：`arrivalTime + delayedTime`，最大 `47`，`int` 完全无溢出风险。
2. **取模**：对 24 取模。和 `< 24` 时取模不变；和在 `[24, 47]` 时取模即减 24，落回 `[0, 23]`。
3. **无需循环**：不需要逐小时模拟，也不需要 `while (t >= 24) t -= 24` 的写法——一次 `%` 覆盖所有情况。

## 5. 正确性证明

**引理 1**：24 小时制下，时刻 `h` 与 `h + 24k`（`k` 为非负整数）表示同一小时读数。

**证明**：24 小时制钟面以 24 小时为周期循环，读数函数 $f(h) = h \bmod 24$ 满足 $f(h + 24k) = f(h)$（模运算同余性质）。∎

**定理**：实际到站读数为 $(\text{arrivalTime} + \text{delayedTime}) \bmod 24$。

**证明**：正点读数 `arrivalTime` 延误 `delayedTime` 小时后，实际经过的钟面小时数为二者之和 `S = arrivalTime + delayedTime`（小时数可加性）。由引理 1，读数即 `S mod 24`。又由约束 `2 <= S <= 47 < 48`，`S mod 24 = S`（当 `S < 24`）或 `S - 24`（当 `24 <= S < 48`），恰为一次折返，结果落在 `[0, 23]` 内，为合法读数。∎

## 6. 复杂度分析

- **时间复杂度**：`O(1)`。一次加法、一次取模。
- **空间复杂度**：`O(1)`。仅常数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findDelayedArrivalTime(int arrivalTime, int delayedTime) {
        return (arrivalTime + delayedTime) % 24;
    }
};
```


## 8. 边界情况与易错点

1. **和恰为 24**：如 `13 + 11 = 24`，答案必须是 `0` 而非 `24`。若写成 `if (sum > 24) sum -= 24` 会漏掉等号，WA 在所难免——这也是本题唯一的「陷阱」。
2. **和恰为 48 不会发生**：`arrivalTime < 24` 且 `delayedTime <= 24`，最大和 47，故 `mod 24` 只需一次；但即便写成 `while` 循环减 24 也正确，只是多余。
3. **返回值域**：题目只要求小时数，答案范围 `[0, 23]`，无需格式化成 `"HH:MM"` 字符串。
4. **不需要逐小时模拟**：`delayedTime` 上限 24，模拟也不会 TLE，但 `O(1)` 公式是签到题应有的肌肉记忆。
