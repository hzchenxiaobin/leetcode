# LeetCode 转换数组 题解

## 1. 题目概述

- **标题 / 题号**：转换数组（#3379，easy）
- **链接**：https://leetcode.cn/problems/transformed-array/
- **来源**：LeetCode 第 427 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、数学

**题意**：给定一个长度为 $n$ 的循环数组 `nums`，构造同长新数组 `result`：对每个下标 $i$，若 `nums[i] > 0` 则从 $i$ 向右移动 `nums[i]` 步，若 `nums[i] < 0` 则向左移动 $|\text{nums}[i]|$ 步，把落脚下标处的值赋给 `result[i]`；若 `nums[i] == 0` 则 `result[i] = nums[i]`。循环数组中越界会回绕（右移越过末尾回到开头，左移越过开头回到末尾）。

**约束**：

- `1 <= nums.length <= 100`
- `-100 <= nums[i] <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [3,-2,1,1]
输出：[1,1,1,3]
解释：
  nums[0]=3：向右 3 步到下标 3，result[0] = 1
  nums[1]=-2：向左 2 步到下标 3，result[1] = 1
  nums[2]=1：向右 1 步到下标 3，result[2] = 1
  nums[3]=1：向右 1 步回绕到下标 0，result[3] = 3
```

**示例 2**

```text
输入：nums = [-1,4,-1]
输出：[-1,-1,4]
解释：
  nums[0]=-1：向左 1 步回绕到下标 2，result[0] = -1
  nums[1]=4：向右 4 步（超过一圈）到下标 2，result[1] = -1
  nums[2]=-1：向左 1 步到下标 1，result[2] = 4
```

## 3. 解题思路

### 3.1 暴力思路

按题面逐步模拟：对每个 $i$，从 $j = i$ 出发，重复 $|\text{nums}[i]|$ 次，每步 `j = (j + 1) % n`（右移）或 `j = (j - 1 + n) % n`（左移），最后 `result[i] = nums[j]`。

时间复杂度 $O(n \cdot \max|\text{nums}[i]|) \le 100 \times 100 = 10^4$，本题范围内能过，但循环写得繁琐；若 $n$、$|\text{nums}[i]|$ 放大到 $10^5$、$10^9$ 就会退化，不如直接用闭式公式。

### 3.2 核心观察：循环移动 = 下标取模

![循环数组移动与下标取模](images/transformed_array_circular_concept.svg)

循环数组中"向右走 $v$ 步"等价于**下标加 $v$ 后对 $n$ 取模**；"向左走 $|v|$ 步"等价于**下标减 $|v|$ 后对 $n$ 取模**（数学取模，结果非负）。两者可以统一成一个公式。

### 3.3 统一公式：三种情况一次覆盖

$$
j = \big((i + \text{nums}[i]) \bmod n + n\big) \bmod n,\qquad \text{result}[i] = \text{nums}[j]
$$

- `nums[i] > 0`：右移 $v$ 步，$j = (i + v) \bmod n$。
- `nums[i] < 0`：左移 $|v|$ 步，$j = (i - |v|) \bmod n = (i + v) \bmod n$，**与右移公式统一**。
- `nums[i] == 0`：$j = i$，`result[i] = nums[i] = 0`，题面第三条规则被天然覆盖，**无需特判**。

> ⚠️ 工程细节：C++/Java 的 `%` 对负数取模结果可能为负（如 `(-1) % 4 == -1`），而 $i + \text{nums}[i]$ 最低可到 $-100$，所以必须写成 `((i + v) % n + n) % n` 两步取模；Python 的 `%` 天然非负，可直接写 `(i + v) % n`。

### 3.4 示例演算

以 `nums = [3, -2, 1, 1]`（$n = 4$）为例：

| $i$ | nums[i] | 移动 | $j = (i + v) \bmod 4$ | result[i] |
|-----|---------|------|------------------------|-----------|
| 0 | +3 | 右 3 步 | $(0+3) \bmod 4 = 3$ | nums[3] = 1 |
| 1 | −2 | 左 2 步 | $(1-2) \bmod 4 = 3$ | nums[3] = 1 |
| 2 | +1 | 右 1 步 | $(2+1) \bmod 4 = 3$ | nums[3] = 1 |
| 3 | +1 | 右 1 步 | $(3+1) \bmod 4 = 0$ | nums[0] = 3 |

得 `result = [1, 1, 1, 3]` ✓

## 4. 算法细节

1. **新建结果数组**：`result` 与 `nums` 分离，所有下标计算只读 `nums` 原值。
2. **两步取模**：目标下标统一写 `j = ((i + nums[i]) % n + n) % n`，对正负零全部成立，规避 C++/Java 负余数问题。
3. **多圈环绕自动处理**：$|\text{nums}[i]|$ 可以远大于 $n$（如 $n=1$、$v=-100$，绕 100 圈），取模运算一步到位，无需循环走格子。

## 5. 正确性证明

**引理 1**（单步移动）：循环数组中从下标 $t$ 向右移动一步到 $(t+1) \bmod n$，向左移动一步到 $(t-1) \bmod n$。

**证明**：$0 \le t < n-1$ 时右移到 $t+1$ 显然；$t = n-1$ 时由循环定义越过末尾回到开头 $0 = (n-1+1) \bmod n$。左移对称：$t > 0$ 时到 $t-1$；$t = 0$ 时越过开头回到末尾 $n-1 = (0-1) \bmod n$。∎

**引理 2**（多步移动）：从下标 $i$ 向右移动 $v$ 步（$v \ge 0$）到达 $(i + v) \bmod n$；向左移动 $k$ 步（$k \ge 0$）到达 $(i - k) \bmod n$。

**证明**：对步数归纳。$v = 0$ 时显然。设向右移动 $v$ 步到达 $(i+v) \bmod n$，再走一步由引理 1 到 $\big((i+v) \bmod n + 1\big) \bmod n = (i+v+1) \bmod n$。左移同理。∎

**定理**：对任意 $i$，按题意移动后落在下标 $j = (i + \text{nums}[i]) \bmod n$（数学模），从而 `result[i] = nums[j]` 正确。

**证明**：记 $v = \text{nums}[i]$。若 $v > 0$，由引理 2 右移 $v$ 步到 $(i+v) \bmod n$。若 $v < 0$，记 $k = |v|$，由引理 2 左移 $k$ 步到 $(i-k) \bmod n = (i+v) \bmod n$。若 $v = 0$，则 $j = i$，`result[i] = nums[i]`，与题面第三条规则一致。三种情况的落脚下标均为 $(i + \text{nums}[i]) \bmod n$，代码中的两步取模只是该数学模的工程实现。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个下标只用一次取模计算目标位置，共 $n$ 次。
- **空间复杂度**：$O(1)$（不计返回数组），或 $O(n)$ 计入输出数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> constructTransformedArray(vector<int>& nums) {
        int n = nums.size();
        vector<int> result(n);
        for (int i = 0; i < n; i++) {
            int j = ((i + nums[i]) % n + n) % n;
            result[i] = nums[j];
        }
        return result;
    }
};
```

### Python

```python
class Solution:
    def constructTransformedArray(self, nums: List[int]) -> List[int]:
        n = len(nums)
        return [nums[(i + v) % n] for i, v in enumerate(nums)]
```

## 8. 边界情况与易错点

1. **n = 1**：无论怎么移动都回到下标 0，`result = [nums[0]]`，公式自动成立（任何数模 1 为 0）。
2. **步数远大于 n**：如 `nums = [-100]`（绕 100 圈），取模一步处理，不要写逐步模拟循环。
3. **负数取模陷阱**：C++/Java 中 `i + nums[i]` 最低 $-100$，直接 `% n` 可能得到负下标导致越界，必须 `((x % n) + n) % n`；Python 的 `%` 天然非负。
4. **nums[i] = 0 无需特判**：题面第三条规则（赋 `nums[i]` 本身）被统一公式覆盖（$j = i$，值为 0）。
5. **不要原地写回 nums**：后续下标的计算仍需读原值，原地覆盖会污染结果。
