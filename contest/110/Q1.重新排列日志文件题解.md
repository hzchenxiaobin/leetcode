# LeetCode 重新排列日志文件 题解

## 1. 题目概述

- **标题 / 题号**：重新排列日志文件（#937，medium）
- **链接**：https://leetcode.cn/problems/reorder-data-in-log-files/
- **来源**：LeetCode 第 110 场周赛 Q1
- **难度**：中等
- **标签**：数组、字符串、排序

**题意**：每条日志是空格分隔的字符串，**第一个词是标识符**（identifier），其后是内容。日志分两类：

- **字母日志**：标识符之后的**所有词**都由小写字母组成；
- **数字日志**：标识符之后的**所有词**都由数字组成。

要求按三条规则重排：

1. **字母日志全部排在数字日志之前**；
2. 字母日志之间：先按**内容**字典序比较（不含标识符）；内容完全相同时，再按**标识符**比较；
3. 数字日志之间：**保持输入中的相对顺序**（即稳定，不做任何排序）。

返回重排后的日志数组。

**约束**：

- $1 \le logs.length \le 100$
- $3 \le logs[i].length \le 100$
- 每条日志的词之间只用**单个空格**分隔，标识符之后**至少还有一个词**

> ⚠️ 注意：判断类型看的是**标识符之后**第一个词的首字符，而不是整条日志的首字符。`"0 pmz"` 的标识符是 `"0"`，但它是一条**字母日志**。

## 2. 示例

**示例 1**

```text
输入：logs = ["dig1 8 1 5 1","let1 art can","dig2 3 6","let2 own kit dig","let3 art zero"]
输出：["let1 art can","let3 art zero","let2 own kit dig","dig1 8 1 5 1","dig2 3 6"]
解释：字母日志的内容都不同，按 "art can" < "art zero" < "own kit dig" 排序；
     数字日志保持原相对顺序 "dig1 8 1 5 1"、"dig2 3 6"。
```

**示例 2**

```text
输入：logs = ["a1 9 2 3 1","g1 act car","zo4 4 7","ab1 off key dog","a8 act zoo"]
输出：["g1 act car","a8 act zoo","ab1 off key dog","a1 9 2 3 1","zo4 4 7"]
解释：字母日志 "act car" 与 "act zoo" 内容不同 → 只比内容，"a8" 排在 "g1" 之后；
     内容相同才会用到标识符比较。
```

**示例 3（补充，检验分类口径）**

```text
输入：logs = ["0 pmz","4 q j","g 89","t v p","w ugr"]
输出：["0 pmz","4 q j","w ugr","t v p","g 89"]
解释：内容是字母的四条（含 "0 pmz"，标识符以数字开头但内容是字母）按内容
     pmz < q j < ugr < v p 排序；"g 89" 的内容是数字，属数字日志，排在最后。
```

## 3. 解题思路

### 3.1 暴力思路

一种"看起来能过"的写法：对整体 `logs` 调一次 `sort`，比较器里写「字母日志 < 数字日志；同为字母则比（内容, 标识符）；同为数字则返回 `false`」。

问题出在两处：

1. **`sort` 不是稳定排序**。比较器对两条数字日志返回 `false`/`false`，它们被视为"等价"，`std::sort` 与 Python 的 `list.sort` 语义不同——前者会在分区时打乱等价元素的相对顺序，直接违反第 3 条规则。
2. 即使换成 `stable_sort`，把一个"部分有序"的规则塞进单一比较器也不易读、不易证明。

朴素穷举不可行：$n=100$ 时全排列 $100!$ 完全跑不动，且本题的答案由排序规则**唯一确定**，根本不需要搜索。

### 3.2 核心观察：稳定分区 + 只对字母日志排序

![日志排序：先分流，再各自处理](images/wc110_q1_classify_rules.svg)

题目三条规则本身就是"**分治**"结构：

- 规则 1 说的是**组间顺序**（字母组整体在数字组之前）——一次**稳定分区**即可实现；
- 规则 2 只约束**组内顺序**（字母组内部按 `(内容, 标识符)` 排序）；
- 规则 3 明确要求数字组**保持原序**——即"什么都不做"。

所以最自然的实现是：**先把两类日志分别装进两个数组，再只对字母数组排序，最后拼接**。这样数字数组天然保持输入顺序，**根本不需要依赖排序算法的稳定性**。

还有一个**关键细节**：字母日志的比较键是 `(内容, 标识符)` 二元组，而 `内容` 是"标识符之后剩下的整个子串"。C++ 里用 `a.substr(a.find(' ')+1)` 取出内容，Python 用 `a.split(' ', 1)[1]`，二者都只切**第一刀**。

### 3.3 算法流程

![reorderLogFiles 算法流程](images/wc110_q1_flow.svg)

```text
1. letters = [], digits = []
2. for log in logs:
       sp = log.find(' ')                       // 标识符结束位置
       若 isdigit(log[sp + 1])：digits.push(log) // 内容首字符是数字 => 数字日志
       否则：                 letters.push(log)
3. 对 letters 做 sort，比较键 key(log) = (内容, 标识符)
4. return letters + digits
```

### 3.4 示例演算

![示例 1 演算：拆分 → 比较键 → 拼接](images/wc110_q1_walkthrough.svg)

对示例 1 的 `logs = ["dig1 8 1 5 1","let1 art can","dig2 3 6","let2 own kit dig","let3 art zero"]`：

| 原日志 | 类型 | 内容 | 标识符 | 排序键 |
|--------|------|------|--------|--------|
| dig1 8 1 5 1 | 数字 | 8 1 5 1 | dig1 | 不参与排序 |
| let1 art can | 字母 | art can | let1 | (art can, let1) |
| dig2 3 6 | 数字 | 3 6 | dig2 | 不参与排序 |
| let3 art zero | 字母 | art zero | let3 | (art zero, let3) |
| let2 own kit dig | 字母 | own kit dig | let2 | (own kit dig, let2) |

字母日志按内容升序得 `art can < art zero < own kit dig`，三条比较都在内容层就已分出胜负，标识符没有出场机会；数字日志 `dig1`、`dig2` 保持原序。拼接即得输出。

## 4. 算法细节

1. **定位分界点**：`find(' ')` 只找**第一个**空格，返回的就是标识符末尾。C++ 用 `log.find(' ')`，Python 用 `split(' ', 1)`。
2. **类型判定**：看 `log[sp + 1]`（标识符后第一个词的首字符）是否为数字，`isdigit` 即可。因为题面保证"标识符之后至少有一个词"，这个下标一定合法。
3. **单次切分**：内容整体保留，不要按空格拆词后重新拼接——内容里的空格数量与顺序都属于内容本身。
4. **C++ 比较器**：先比 `content`，不等就直接返回；相等再比 `identifier`。这满足**严格弱序**（见 §5 引理 2），可以安全交给 `std::sort`。
5. **数字日志零处理**：绝不要对 `digits` 调用 `sort`（连 `stable_sort` 都不必），保持 `push_back` 顺序即可。
6. **Python 写法**：`letters.sort(key=lambda l: (l.split(' ', 1)[1], l.split(' ', 1)[0]))`，元组按元素依次比较，语义与 C++ 比较器完全一致。
7. **原地 vs 新数组**：题目要求返回新顺序，直接返回拼接结果，无需原地修改 `logs`。

## 5. 正确性证明

**引理 1（分类正确）**：对任意日志 `log`，算法把 `log` 放入 `letters` 当且仅当它是字母日志。

**证明**：字母日志定义为"标识符之后的所有词都由小写字母组成"，数字日志定义为"标识符之后的所有词都由数字组成"。这两类互斥且穷尽（题面保证每条日志属于其中一类），而一个串的所有词都由数字组成 $\iff$ 其第一个词的首字符是数字——因为词之间用单个空格分隔，词的字符集在整串内一致。故 `isdigit(log[sp+1])` 为真当且仅当 `log` 是数字日志。∎

**引理 2（比较器是严格弱序）**：C++ 比较器 `a < b ⟺ (content_a, id_a) < (content_b, id_b)`（字典序）是严格弱序。

**证明**：`(content, id)` 是二元字符串组，按字典序比较满足非自反性（`x<x` 为假）、传递性（字典序是线序，传递性显然）以及等价关系的传递性（不可比 $\iff$ 两个二元组完全相等，是真等价关系）。∎

**引理 3（字母组结果唯一）**：按 `(内容, 标识符)` 升序排列后，结果与排序算法的实现无关。

**证明**：由引理 2，任意两条不同日志在该键下都可比较出确定的大小关系；键完全相同的两条日志其内容与标识符都相同，而日志由"标识符 + 内容"唯一确定，故两条日志的字符串完全相同。因此不存在"键相同但字符串不同"的等价类，排序结果唯一。∎

**定理**：算法输出满足题目三条规则，且该输出唯一。

**证明**：

- 规则 1：输出为 `letters ++ digits`，所有字母日志的下标都小于所有数字日志，成立。
- 规则 2：由引理 3，`letters` 内部严格按 `(内容, 标识符)` 升序，正是"内容不同比内容、内容相同比标识符"的转写，成立。
- 规则 3：`digits` 由按输入顺序 `push_back` 构成，未做任何移动或排序，相对顺序与输入一致，成立。
- 唯一性：规则 1、3 完全确定了分组与组间、组内数字部分；规则 2 由引理 3 唯一确定字母部分。故满足全部规则的序列唯一。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$，其中 $n = logs.length$。一次分类扫描 $O(\sum \lvert log_i \rvert)$；只有字母日志参与排序，最坏全部是字母日志时 $O(n \log n)$ 次比较，单次比较需比较长度为 $O(L)$ 的内容，故严格上界为 $O(n \log n \cdot L)$，$L \le 100$。
- **空间**：$O(n)$（不计输出本身则为 $O(\sum \lvert log_i \rvert)$），两个 `vector` 存放全部日志的副本；排序栈开销 $O(\log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> reorderLogFiles(vector<string>& logs) {
        vector<string> letters, digits;
        for (auto& log : logs) {
            size_t sp = log.find(' ');
            // 标识符之后第一个字符是数字 => 数字日志
            if (isdigit((unsigned char)log[sp + 1])) digits.push_back(log);
            else letters.push_back(log);
        }
        sort(letters.begin(), letters.end(), [](const string& a, const string& b) {
            size_t sa = a.find(' '), sb = b.find(' ');
            string ca = a.substr(sa + 1), cb = b.substr(sb + 1);
            if (ca != cb) return ca < cb;              // 先比内容
            return a.substr(0, sa) < b.substr(0, sb);  // 内容相同再比标识符
        });
        letters.insert(letters.end(), digits.begin(), digits.end());
        return letters;
    }
};
```

### Python

```python
class Solution:
    def reorderLogFiles(self, logs: list[str]) -> list[str]:
        letters, digits = [], []
        for log in logs:
            ident, content = log.split(' ', 1)
            if content[0].isdigit():
                digits.append(log)      # 数字日志：按输入顺序收集，不再排序
            else:
                letters.append(log)

        def key(log: str):
            ident, content = log.split(' ', 1)
            return (content, ident)     # 先内容，后标识符

        letters.sort(key=key)
        return letters + digits
```

## 8. 边界情况与易错点

1. **类型看内容而不是标识符**：`"0 pmz"`、`"4 q j"` 都是**字母日志**（标识符可以是数字）。只判断整串首字符会全错。
2. **数字日志绝不能排序**：题目要求保持原相对顺序。顺手对 `digits` 调一次 `sort` 是最常见的 WA 来源。
3. **规则 2 的两级比较顺序不能反**：先比内容，内容完全相同才比标识符。反过来（先比标识符）在示例 2 上就会错。
4. **内容要"整体"比较**：不能把内容拆成词后逐词比再拼回去——字典序比较的边界（前缀、空格）与整串比较必须一致，直接用子串最稳。
5. **不要依赖 `sort` 的稳定性**：C++ 的 `std::sort` 不稳定，即使比较器写对，等价元素（两条数字日志）的相对顺序也没有保证。本解法靠"分组"彻底规避这一点。
6. **`find(' ')` 一定能找到**：题面保证标识符之后至少有一个词，故 `sp + 1` 合法；若自行加防御，可判断 `sp == string::npos`。
7. **Python 的 `split(' ', 1)`**：必须限制切分次数为 1，否则内容内部的空格会被切碎。
8. **返回值是新数组**：不要假设可以原地修改输入；`logs` 可能被更高层复用。
