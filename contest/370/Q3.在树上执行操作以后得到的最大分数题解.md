# LeetCode 在树上执行操作以后得到的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：在树上执行操作以后得到的最大分数（#2925，medium）
- **链接**：https://leetcode.cn/problems/maximum-score-after-applying-operations-on-a-tree/
- **来源**：LeetCode 第 370 场周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、动态规划、树形 DP

**题意**：给定一棵以 $0$ 为根、$n$ 个节点的树（`edges` 给出 $n-1$ 条无向边）和节点值数组 `values`。一次操作任选节点 $i$：把 $\text{values}[i]$ **加**进得分，同时把它**置 $0$**。全部操作结束后要求树是**健康的**——每条从根到叶子的路径上，节点值之和都**不等于 $0$**。操作次数不限，求能取得的最大得分。

**约束**：

- $2 \le n \le 2 \times 10^4$，`edges` 恰有 $n-1$ 条，保证构成合法树
- $1 \le \text{values}[i] \le 10^9$：全为**正数**，这是等价性转化的关键；总和最高 $2 \times 10^{13}$，**必须 64 位整数**

> 💡 一句话点破：**正难则反**。操作的本质是「挑一个子集收走」，健康条件翻译过来就是「**每条根→叶路径至少留一个没收走的节点**」；于是最大化得分 = 总和 − **最小保留和**。后者是树上经典的最小「路径命中集」，一遍自底向上树形 DP：$f[u] = \min(\text{values}[u],\ \sum_{c} f[c])$，叶子直接 $f = \text{values}$。

## 2. 示例

**示例 1**

```text
输入：edges = [[0,1],[0,2],[0,3],[2,4],[4,5]], values = [5,2,5,2,1,1]
输出：11
解释：收走节点 1、2、3、4、5，值变为 [5,0,0,0,0,0]，叶子是 1、3、5。
      三条根→叶路径 0→1、0→3、0→2→4→5 的和都是 5 ≠ 0，树健康；
      得分 = 2+5+2+1+1 = 11。
```

**示例 2**

```text
输入：edges = [[0,1],[0,2],[1,3],[1,4],[2,5],[2,6]], values = [20,10,9,7,4,3,5]
输出：40
解释：收走节点 0、2、3、4，值变为 [0,10,0,0,0,3,5]，叶子是 3、4、5、6。
      四条根→叶路径的和分别为 10、10、3、5，全部非零；
      得分 = 20+9+7+4 = 40。
```

**补充边界示例**

```text
输入：edges = [[0,1]], values = [4,7]
输出：7
解释：n=2 退化成链，唯一的根→叶路径是 0→1。注意根 0 只有一个邻居，
      但它不是叶子（叶子 = 无孩子的节点）；两个节点只能收一个
      （全收则路径和为 0），保留较小的 4、收走 7，得分 7。
```

## 3. 解题思路

### 3.1 暴力思路：枚举收走集合与贪心都会翻车

最直接的枚举：每个节点「收 / 不收」二选一，$2^n$ 种组合，每种再花 $O(n \times \text{路径长})$ 逐条路径验证健康性——$n = 2 \times 10^4$ 下是天文数字。而且「最小命中集」在一般集合系统上等价于 NP-hard 的集合覆盖问题，能多项式求解完全依赖**树结构**。

更隐蔽的坑是**贪心「能收就收」**（每一步收走一个仍能保持健康的节点）：

```text
链：0(1) — 1(1) — 2(100)
贪心：收 0（路径和 101 ≠ 0 ✓）→ 收 1（和 100 ≠ 0 ✓）→ 收 2？（和 = 0 ✗）停。
      得分 = 1 + 1 = 2。
最优：只保留一个 1（保留 0 也行），收走其余：得分 = 1 + 100 = 101。
```

失败原因：收走一个节点是**局部决策**，却同时威胁**所有**经过它的路径；反过来，**留下一个便宜节点能解锁整条链下游的昂贵节点**。收益与责任在树上层层纠缠，必须把「子孙的责任」逐层汇总上传——这正是树形 DP 的用武之地。

> ⚠️ 本题没有一眼贪心的捷径；比赛时想不清取舍关系，直接上树形 DP 是最稳的路线。

### 3.2 核心观察：正难则反，最大化收取 = 最小化保留

![正难则反：收走与保留的关系](images/tree_score_concept.svg)

**观察 1（操作 = 选子集）**：对已置 $0$ 的节点再操作只会加 $0$，因此任何操作序列都等价于「一次性收走某个子集 $C$」，得分 $\sum_{i \in C} \text{values}[i]$，最终 $\text{values}[i] = 0 \iff i \in C$。操作顺序、次数统统无关紧要。

**观察 2（健康 ⟺ 保留集命中每条路径）**：由 $\text{values}[i] \ge 1$，路径和 $\ne 0 \iff$ 路径上**存在没收走的节点**。记保留集 $T = V \setminus C$，则

$$\text{树健康} \iff T \text{ 与每条根}\to\text{叶路径都相交（} T \text{「命中」所有路径）}$$

**观察 3（最大化 ⇔ 最小化）**：得分 $= \sum_{i \in V} \text{values}[i] - \sum_{i \in T} \text{values}[i]$。总和固定，**最大化得分 ⟺ 最小化保留和**——把「争取收益」翻转成「付出代价」，约束立刻从模糊的「别把树搞坏」变成清晰的「命中所有根→叶路径」。

**观察 4（子树可分解）**：若保留 $u$，所有经过 $u$ 的路径一次挡住，$u$ 的**整棵子树**其余节点全收——一次决策管住全部分支；若收走 $u$，路径只能由**各个孩子子树内部**各自解决——孩子子树两两不相交，责任完全独立。最优子结构成立，树形 DP 可行。

> 💡 **可迁移的套路**：树上形如「每条根→叶路径都要满足××」的条件，几乎总能翻译成「在每条路径上选一个**守卫**」的树形 DP，状态沿「守卫设在哪一层」转移。本题的守卫要付 $\text{values}[u]$ 的工资，问最少工资（同类思想见 968 监控二叉树）。

### 3.3 算法流程：自底向上填 f[u]

![树形 DP 两选项：保留 u 或交给孩子们](images/tree_score_dp_states.svg)

对每个节点 $u$ 定义

$$f[u] = \text{subtree}(u) \text{ 内使「每条 } u \to \text{叶路径都被命中」的最小保留和}$$

注意路径是**从 $u$ 出发向下**，不含 $u$ 的祖先——祖先是否保留，由上层的选择负责，两层各管各的。转移二选一：

- **选项 A（保留 $u$）**：付 $\text{values}[u]$，所有过 $u$ 的路径一次挡住，子树其余全收；
- **选项 B（收走 $u$）**：付 $\sum_j f[c_j]$，每个孩子子树独立保命。

$$f[u] = \begin{cases} \text{values}[u] & u \text{ 是叶子（没有选项 B）} \\ \min\big(\text{values}[u],\ \sum_{j=1}^{k} f[c_j]\big) & u \text{ 有孩子 } c_1, \dots, c_k \end{cases}$$

**算法步骤**：

1. 建无向邻接表，从 $0$ 出发 DFS/BFS 定向（记父亲，防走回头路）；
2. **自底向上**计算 $f[u]$（DFS 回溯阶段，或 BFS 序倒序遍历）；
3. 叶子判定：**无孩子**（等价于非根且度数 $1$）时直接 $f[u] = \text{values}[u]$；根只有单个邻居时**不是叶子**；
4. 答案 $= \sum_i \text{values}[i] - f[0]$（根→叶路径集恰是 $f$ 定义中的路径集）。

### 3.4 示例演算

![示例 1 自底向上演算：f 表与答案](images/tree_score_walkthrough.svg)

**示例 1**（values = [5,2,5,2,1,1]）自底向上填表：

| 节点 | values | $\sum f[\text{孩子}]$ | $f[u]$ |
|------|--------|----------------------|--------|
| 5（叶） | 1 | — | 1 |
| 4 | 1 | $f[5]=1$ | $\min(1,1)=1$ |
| 2 | 5 | $f[4]=1$ | $\min(5,1)=1$ |
| 1（叶） | 2 | — | 2 |
| 3（叶） | 2 | — | 2 |
| 0 | 5 | $2+1+2=5$ | $\min(5,5)=5$ |

答案 $= 16 - 5 = 11$ ✓。注意 $f[0]$ **两侧打平**：保留 $\{0\}$（官方解释的做法）或保留 $\{1,3,4\}$ / $\{1,3,5\}$ 都最优，得分同为 11——最优方案不唯一，最优值唯一。

**示例 2** 验算：$f[3]{=}7,\ f[4]{=}4 \Rightarrow f[1]{=}\min(10,11){=}10$；$f[5]{=}3,\ f[6]{=}5 \Rightarrow f[2]{=}\min(9,8){=}8$；$f[0]{=}\min(20,18){=}18$，答案 $= 58 - 18 = 40$ ✓。

## 4. 算法细节

1. **状态语义要抠准**：$f[u]$ 管的是「$u \to$ 叶」的路径，从 $u$ 出发向下，**不含祖先**——祖先是否保留由上层选项 A/B 决定，两层各管各的，互不越界。
2. **选项 A 的代价不含 $\sum f[c_j]$**：保留 $u$ 后整棵子树收空，孩子子树无需任何守卫；把选项 A 误写成 $\text{values}[u] + \sum f[c_j]$ 是常见手误（两个选项是「二选一」，不是「叠加」）。
3. **叶子必须特判**：对叶子套用 $\min(\text{values}[u], \sum \varnothing)$ 得 $0$——错在「选项 B 对叶子不可行」：它没有孩子替它挡路径，唯一的 $u \to$ 叶路径（$u$ 自己）只能靠 $u$ 本人保留。
4. **实现选型**：C++ 用递归 DFS（深度 $\le 2 \times 10^4$，每帧很薄，安全）；Python 用 **BFS 序倒序**迭代，规避链状树的递归爆栈（见 §8）。
5. **数值类型**：$\sum \text{values} \le 2 \times 10^4 \times 10^9 = 2 \times 10^{13}$，超 `int` 上限，C++ 全程 `long long`，`values[u]` 与 `childSum` 比较前注意类型提升。
6. **边是无向给出的**：不能假设 `edges[i][0]` 是父节点（如 `[4,5]` 中父亲 4 也可能写在后面），必须建双向边再按遍历定向。

## 5. 正确性证明

**引理 1（操作模型）**：任何操作序列的效果等价于「一次性收走某个子集 $C \subseteq V$」：最终 $\text{values}'[i] = 0$（$i \in C$）或 $\text{values}[i]$（$i \notin C$），得分 $\sum_{i \in C} \text{values}[i]$。

**证明**：节点一旦被操作，值变为 $0$，之后对它再操作只会加 $0$，不改变最终状态与得分。把序列中「至少被操作过一次」的节点集合记为 $C$，则该序列与「对 $C$ 中每个节点恰好操作一次、任意顺序」的效果完全相同。∎

**引理 2（健康的刻画）**：最终状态健康 $\iff$ 保留集 $T = V \setminus C$ 与每条根→叶路径相交。

**证明**：任取根→叶路径 $p$，其和为 $\sum_{i \in p \cap T} \text{values}[i]$。若 $p \cap T \ne \varnothing$，则和 $\ge 1 > 0$；若 $p \cap T = \varnothing$，则和 $= 0$。又 $\text{values}[i] \ge 1$ 保证求和不会正负抵消，故「$p$ 的和 $\ne 0 \iff p \cap T \ne \varnothing$」，对所有路径取全称量词即得。∎

**引理 3（递推式）**：设 $m(u)$ 为 $\text{subtree}(u)$ 的子集中，命中所有「$u \to$ 子树内叶子」路径者的最小权和。则叶子 $m(u) = \text{values}[u]$；内部节点 $m(u) = \min(\text{values}[u], \sum_c m(c))$。

**证明**：按 $u$ 是否保留分类。

- **情形 A（$u \in T$）**：所有 $u \to$ 叶路径都在 $u$ 处命中。任何此情形的可行 $T$ 的代价 $= \text{values}[u] + \sum_{i \in T \setminus \{u\}} \text{values}[i] \ge \text{values}[u]$（其余各项均为正数）；而 $T = \{u\}$ 恰好可行且代价为 $\text{values}[u]$。故此情形最优值 $= \text{values}[u]$。
- **情形 B（$u \notin T$）**：若 $u$ 是叶子，唯一的 $u \to$ 叶路径只含 $u$，无法在 $u$ 之外被命中，此情形**不可行**——叶子特判由此而来。若 $u$ 有孩子 $c_1, \dots, c_k$，断言：

$$T \subseteq \text{subtree}(u) \setminus \{u\} \text{ 命中所有 } u\to\text{叶路径} \iff \forall j:\ T \cap \text{subtree}(c_j) \text{ 命中所有 } c_j \to \text{叶路径}$$

  （⇒）任取孩子 $c_j$ 的到叶路径 $p$，则 $u + p$ 是 $u \to$ 叶路径，被 $T$ 命中于某节点；该节点 $\ne u$（$u \notin T$）且只能落在 $\text{subtree}(c_j)$ 内（$p$ 整体在其中），故 $p$ 被 $T \cap \text{subtree}(c_j)$ 命中。（⇐）任取 $u \to$ 叶路径 $u + p$，$p$ 必从某个孩子 $c_j$ 出发，被 $T \cap \text{subtree}(c_j) \subseteq T$ 命中。各孩子子树两两不相交，约束相互独立，故此情形最优值 $= \sum_j m(c_j)$：一方面任意可行解按子树拆开都 $\ge \sum_j m(c_j)$；另一方面取每个子树内达到 $m(c_j)$ 的集合直接并起，既可行又取等。

两情形穷尽所有可能（$u$ 要么保留要么不保留），取最小即得递推。∎

**定理**：最大得分 $= \sum_{i \in V} \text{values}[i] - m(\text{root})$，且算法正确算出它。

**证明**：根→叶路径集恰为 $m(\text{root})$ 定义中的路径集合，由引理 2，可行方案（操作后树健康）与「$T$ 命中所有根→叶路径」一一对应，且由引理 1 得分为 $\sum_V - \sum_T$。故最大得分 $= \sum_V - \min_T \sum_{i \in T} \text{values}[i] = \sum_V - m(\text{root})$。按引理 3 的递推自底向上计算：叶子的 $m$ 直接可得；对子树高度归纳，处理 $u$ 时其孩子的 $m$ 均已算出，故 $m(\text{root})$ 被正确求出。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。建图 $O(n)$；DP 中每个节点恰好计算一次，孩子求和的工作量摊到每条边上为常数，合计 $O(n)$。输入本身有 $n$ 个值要读，$O(n)$ 已与输入规模同阶，是最优。
- **空间复杂度**：$O(n)$。邻接表 $O(n)$，定向序 / `children` / $f$ 数组各 $O(n)$；C++ 递归版另有最坏 $O(n)$ 的调用栈（链状树深约 $2 \times 10^4$ 层，每帧很薄，默认栈安全），Python 迭代版用 `order` 数组显式替代递归栈。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maximumScoreAfterOperations(vector<vector<int>>& edges, vector<int>& values) {
        int n = values.size();
        vector<vector<int>> g(n);
        for (auto& e : edges) {
            g[e[0]].push_back(e[1]);
            g[e[1]].push_back(e[0]);
        }
        // dfs(u, fa)：subtree(u) 内命中所有「u→叶」路径的最小保留和
        function<long long(int, int)> dfs = [&](int u, int fa) -> long long {
            long long childSum = 0;
            int kids = 0;
            for (int v : g[u]) {
                if (v == fa) continue;
                childSum += dfs(v, u);
                kids++;
            }
            if (kids == 0) return (long long)values[u];   // 叶子：只能保留自己
            return min((long long)values[u], childSum);  // 保留 u，或交给孩子们
        };
        long long total = accumulate(values.begin(), values.end(), 0LL);
        return total - dfs(0, -1);
    }
};
```

### Python

```python
class Solution:
    def maximumScoreAfterOperations(self, edges: List[List[int]], values: List[int]) -> int:
        n = len(values)
        g = [[] for _ in range(n)]
        for u, v in edges:
            g[u].append(v)
            g[v].append(u)

        children = [[] for _ in range(n)]
        order, seen = [0], [False] * n
        seen[0] = True
        for u in order:                      # BFS 定向（边遍历边生长），根先于孩子
            for v in g[u]:
                if not seen[v]:
                    seen[v] = True
                    children[u].append(v)
                    order.append(v)

        f = values[:]                        # 叶子：f = values（没有孩子，必须保留）
        for u in reversed(order):            # 倒序 = 自底向上（免递归爆栈）
            if children[u]:
                f[u] = min(values[u], sum(f[c] for c in children[u]))
        return sum(values) - f[0]
```

## 8. 边界情况与易错点

1. **叶子特判（本题头号坑）**：`min` 里的空和 $\sum \varnothing = 0$ 会把叶子的 $f$ 错算成 $0$；必须「无孩子 → 直接取 $\text{values}$」。相应地，根度数为 $1$（$n = 2$ 链）时根**不是叶子**，唯一路径 $0 \to 1$ 由 DP 正确处理。
2. **溢出**：总和至多 $2 \times 10^{13}$，C++ 必须全程 `long long`；`min(values[u], childSum)` 两边类型要一致（代码里已强转）。
3. **无向边 + 记父亲**：`edges[i][0]` 不一定是父节点；漏传 `fa` 会沿来路反弹回父亲，叶子判定（无孩子）也随之失效。
4. **Python 递归深度**：链状树深达 $2 \times 10^4$，默认上限 $1000$ 必爆 `RecursionError`；赛场稳写法是 BFS 序倒序迭代（C++ 递归无虞）。
5. **选项 A 别写成「保留 $u$ 还要付孩子」**：保留 $u$ 后子树全收，代价与孩子无关；两个选项是二选一，不是叠加。
6. **「健康」判的是路径和 ≠ 0**：靠 $\text{values} \ge 1$ 才等价于「路径上有保留节点」；这步等价性是整个建模的地基（若允许 $0$ 或负值会失效，见延伸思考）。
7. **操作可重复、顺序无关**：同一节点二次操作只加 $0$，无意义；不必纠结「最优操作序列长什么样」，建模时直接一步到位选子集。

**延伸思考**：若还要求**输出**具体收走方案，只需在 DP 时记录每个节点取的是 $\min$ 的哪一侧，从根回溯即可还原（示例 1 中 $f[0]$ 两侧打平恰好说明方案可以不唯一）。若放宽 $\text{values}[i] \ge 1$ 的约束——允许 $0$ 时「留一个节点」与「路径和非零」仍基本等价（保留 $0$ 值节点没有意义，命中集里只用 $\text{values} \ge 1$ 的节点即可）；但允许**负值**时路径和可能正负抵消，「留一个非零节点」不再保证「和 ≠ 0」，命中集模型失效，问题本质发生改变——这也是体会「正数约束为什么重要」的最佳角度。
