# LeetCode 驼峰式匹配 题解

## 1. 题目概述

- **标题 / 题号**：驼峰式匹配（#1023，medium）
- **链接**：https://leetcode.cn/problems/camelcase-matching/
- **来源**：LeetCode 第 131 场周赛 Q3
- **难度**：中等
- **标签**：双指针、字符串、字符串匹配、字典树

**题意**：给定查询串数组 `queries` 和模式串 `pattern`。若能在 `pattern` 的**任意位置插入若干小写字母**得到 `queries[i]`，则称二者匹配。

返回布尔数组 `answer`，其中 `answer[i]` 表示 `queries[i]` 与 `pattern` 是否匹配。

把「插入」反过来读，就是**删除**：`queries[i]` 删掉若干小写字母后能变成 `pattern`，即匹配。

**约束**：

- $1 \le pattern.length, queries.length \le 100$
- $1 \le queries[i].length \le 100$
- `queries[i]` 和 `pattern` 由英文字母组成

> 💡 三个可直接落地的推论：① `pattern` 必须**按顺序**出现在 `queries[i]` 中（子序列）；② 匹配上的字符必须**完全相同**（大小写都敏感）；③ `queries[i]` 中**没被匹配**的字符必须全是小写字母。

## 2. 示例

**示例 1**

```text
输入：queries = ["FooBar","FooBarTest","FootBall","FrameBuffer","ForceFeedBack"], pattern = "FB"
输出：[true,false,true,true,false]
解释："FooBar" = "F" + "oo" + "B" + "ar"；
      "FootBall" = "F" + "oot" + "B" + "all"；
      "FrameBuffer" = "F" + "rame" + "B" + "uffer"。
      "FooBarTest" 多出大写 T，"ForceFeedBack" 多出大写 C、F，都不匹配。
```

**示例 2**

```text
输入：queries = ["FooBar","FooBarTest","FootBall","FrameBuffer","ForceFeedBack"], pattern = "FoBa"
输出：[true,false,true,false,false]
解释："FooBar" = "Fo" + "o" + "Ba" + "r"；"FootBall" = "Fo" + "ot" + "Ba" + "ll"。
      "FrameBuffer" 里没有小写 "o"，无法匹配。
```

**示例 3**

```text
输入：queries = ["FooBar","FooBarTest","FootBall","FrameBuffer","ForceFeedBack"], pattern = "FoBaT"
输出：[false,true,false,false,false]
解释：只有 "FooBarTest" 能拼成 "Fo" + "o" + "Ba" + "r" + "T" + "est"。
```

## 3. 解题思路

### 3.1 暴力思路

按定义正向构造：枚举把 `pattern` 的 $m$ 个字符「切开」成 $m+1$ 个空隙、在每个空隙插入若干小写字母的所有方式，逐一比较。

插入长度与位置都无限制，方案数随 `queries[i].length` 指数增长；单个查询就可能产生天文数字级的候选串，必然不可行。

另一种能过但更慢的思路是 DP：设 $f(i, j)$ 表示 `query[0..i]` 能否匹配 `pattern[0..j]`，转移 $O(1)$，复杂度 $O(|q| \cdot |p|)$。它是对的，但没有利用「只有小写字母可以自由跳过」这一强结构。

### 3.2 核心观察：大写的「锚点」必须一一对齐

![双指针扫描：等则前进，不等则只能跳过小写](images/wc131_q3_two_pointer.svg)

**观察一（子序列）**：插入不改变 `pattern` 中字符的相对顺序，所以 `pattern` 必须是 `queries[i]` 的子序列。

**观察二（大写是锚点）**：插入的只能是**小写**字母，所以 `queries[i]` 里每个**大写**字符都必须出现在 `pattern` 中、且位置一一对应；`pattern` 中的小写字符也不能少。

由此得到**贪心双指针**：$i$ 扫 `queries[i]`，$j$ 指向 `pattern` 的下一个待匹配字符：

- 若 `q[i] == p[j]`：匹配，$i$、$j$ 同时前进；
- 否则若 `q[i]` 是大写：无法解释这个字符（既不是插入的，也没对上模式），**判定不匹配**；
- 否则（`q[i]` 是小写）：把它当作插入的字符跳过，$i$ 前进。

扫描结束时，还必须要求 $j = |p|$（`pattern` 全部匹配完）。

> 💡 为什么「能匹配就立刻匹配」是安全的？因为可跳过的字符集（小写）与匹配位置无关，而匹配越早，留给后续模式字符的候选后缀就越长。这是标准的**交换论证**，见 §5 引理 2。

### 3.3 算法流程

![算法流程：逐查询双指针，无需回溯](images/wc131_q3_algorithm_flow.svg)

```text
for each q in queries:
    j = 0
    ok = true
    for ch in q:
        若 j < len(pattern) 且 ch == pattern[j]:
            j += 1                     # 匹配成功
        否则若 ch 是大写:
            ok = false; break          # 大写无法被插入解释
        否则:
            继续                        # 小写：视作插入，跳过
    若 ok 且 j == len(pattern):  answer 追加 true
    否则:                       answer 追加 false
```

### 3.4 示例演算

![示例演算：pattern = "FoBaT" 与五个查询](images/wc131_q3_walkthrough.svg)

以 `pattern = "FoBaT"` 为例：

| 查询 | 扫描结果 | 结论 |
|---|---|---|
| `"FooBar"` | F,F 对 `Fo`；`o` 跳过；`B`,`a` 对 `Ba`；`r` 跳过；模式还剩 `T` | false（模式未用完） |
| `"FooBarTest"` | `Fo` 匹配、`o`/`r`/`est` 跳过、`Ba` 匹配、`T` 匹配，$j=5$ | true |
| `"FootBall"` | 同上但遇不到 `T`，$j=4$ | false |
| `"FrameBuffer"` | 第 2 个字符 `r` 是大写且不等于 `o` | false |
| `"ForceFeedBack"` | 第 3 个字符 `r` 大写，不等于 `o` | false |

再看示例 1 的 `pattern = "FB"`：`"FooBarTest"` 在 `FB` 都匹配完后还剩下大写 `T`（`j` 已越界，`q[i]` 是大写）→ 直接 false，正是「多余的大写」这一典型反例。

## 4. 算法细节

1. **大写判断**：C++ 用 `isupper(ch)` 或 `ch >= 'A' && ch <= 'Z'`；Python 用 `ch.isupper()`。只含英文字母，无国际化陷阱。
2. **`j` 越界**：当 $j = |p|$ 后，`q[i]` 只可能是「多余字符」，此时任何大写都判 false，小写则跳过。代码里用 `j < m && q[i] == p[j]` 的统一条件即可覆盖。
3. **结尾检查 `j == |p|`**：不能省。`"FooBar"` 与 `"FoBaT"` 的例子说明「查询扫完了但模式还没用完」必须判 false。
4. **不需要回溯**：贪心匹配不会把局面弄坏（引理 2），所以单次 $O(|q|)$，无需 DP。
5. **多查询共享 `pattern`**：每个查询独立扫描，`pattern` 只读，天然可并行。
6. **字典树不是必需的**：标签里有 Trie，是因为官方给出的另一类解法（把所有大写字母提出来建 Trie，按大写骨架匹配）；本题规模小，双指针更短更快。

## 5. 正确性证明

固定 `pattern` $p$（长度 $m$）与查询 $q$（长度 $n$）。

**定义（合法对齐）**：把 $p[0..k-1]$ 匹配到 $q$ 中下标 $i_1 < i_2 < \cdots < i_k$，若 $q[i_t] = p[t-1]$，且 $q$ 中所有未被选中的下标都是**小写字母**，则称这组下标是 $p[0..k-1]$ 的一个合法对齐。

**引理 1（匹配的等价刻画）**：$q$ 与 $p$ 匹配 $\iff$ $p[0..m-1]$ 在 $q$ 中存在合法对齐。

**证明**：
（$\Leftarrow$）把未被选中的字符视为「插入的小写字母」，其余字符按原顺序恰为 $p$，故 $q$ 由 $p$ 插入这些小写字母得到。
（$\Rightarrow$）若 $q$ 由 $p$ 插入小写字母得到，则 $p$ 的每个字符在 $q$ 中有唯一对应位置，构成递增序列，余下位置插入的都是小写。∎

**引理 2（左移不破坏合法性）**：设 $A$ 是 $p[0..k-1]$ 的合法对齐，$p[k]$ 被匹配在位置 $i'$；若存在 $i < i'$ 使 $q[i] = p[k]$ 且 $i$ 大于 $A$ 中 $p[k-1]$ 的匹配位置（$k = 0$ 时无此限制），则把 $p[k]$ 的匹配位置由 $i'$ 改为 $i$ 后仍是合法对齐。

**证明**：$i$ 位于 $A$ 的两个相邻匹配位置之间（或首位之前），故 $i$ 未被 $A$ 选中；$A$ 合法意味着未选中的字符都是小写，所以 $q[i]$ 是小写。修改后新未选中的位置只有 $i'$，而 $q[i'] = p[k] = q[i]$ 也是小写，仍满足「未选中者皆小写」；选中位置依旧严格递增且字符对应。故合法。∎

**引理 3（贪心即最左对齐）**：若 $q$ 中存在 $p$ 的合法对齐，则算法不会提前判 false，且算法给出的匹配位置序列是**所有合法对齐中最左**的：对每个 $k$，第 $k$ 个模式字符的匹配位置不大于任何合法对齐中它出现的位置，且算法跳过的字符全为小写。

**证明**：对 $k$ 归纳。$k = 0$ 时，算法从下标 0 起找第一个等于 $p[0]$ 的字符；若在此之前存在大写字符，它不能被跳过（否则不成合法对齐），也不能被匹配到更晚，故必然失败——这与「存在合法对齐」矛盾，所以最左出现位置之前全为小写，算法恰好匹配在该位置。设前 $k$ 个已按最左方式匹配，位置为 $j_0 < \cdots < j_{k-1}$。由引理 2，任何合法对齐都可把 $p[k]$ 左移到「$j_{k-1}$ 之后第一个 $p[k]$ 出现的位置」（若中途出现大写字符——它既不能匹配给 $p[k]$（字符不等），也不能被跳过——则该对齐本就不合法，与存在性矛盾）。因此算法扫描 $j_{k-1}+1$ 起、跳过若干小写、遇到的第一个 $p[k]$ 就是最左位置；若在此之前出现大写字符，则不存在向该方向延伸的合法对齐。∎

**定理**：算法对每个查询的输出等于题面定义的匹配结果。

**证明**：分三种终止方式。

1. **扫描完且 $j = m$**：算法记录的位置满足「匹配字符相等、跳过字符全为小写」，构成合法对齐，由引理 1 得匹配。
2. **扫描完但 $j < m$**：设存在合法对齐 $A$。由引理 3，$A$ 中 $p[j]$ 的匹配位置不小于算法扫描过的所有位置，即 $\ge n$，不存在，矛盾。故不匹配。
3. **遇大写字符 $c$ 且 $c \ne p[j]$ 而停止**：设存在合法对齐 $A$。由引理 3 的最左性，$A$ 的前 $j$ 个匹配位置就是算法给出的位置（均 $< i$）。而 $p[j]$ 在 $A$ 中的匹配位置不早于「$j$ 位置之后第一个 $p[j]$」，由于算法在 $i$ 处停止，$i$ 之前（含 $i$）没有 $p[j]$，故 $A$ 中 $p[j]$ 的位置 $> i$。于是位置 $i$ 处的 $c$ 未被 $A$ 选中，$c$ 必须是小写，与「$c$ 是大写」矛盾。故不匹配。

三种情形穷尽且互斥，结论正确。∎

## 6. 复杂度分析

- **时间**：$O\bigl(\sum_i |queries[i]|\bigr)$，每个字符摊到 $O(1)$；最坏 $100 \times 100 = 10^4$ 次比较。若用 DP 则为 $O(\sum_i |q_i| \cdot |p|)$，多一个 100 倍因子。
- **空间**：$O(1)$ 额外空间（不计输出数组）；DP 需要 $O(|p|)$ 甚至 $O(|q||p|)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<bool> camelMatch(vector<string>& queries, string pattern) {
        vector<bool> ans;
        int m = (int)pattern.size();
        for (const string& q : queries) {
            int j = 0;
            bool ok = true;
            for (char ch : q) {
                if (j < m && ch == pattern[j]) {
                    j++;                                  // 匹配模式的下一个字符
                } else if (ch >= 'A' && ch <= 'Z') {
                    ok = false;                           // 大写无法被插入解释
                    break;
                }
                // 否则是小写字母：视作插入，跳过
            }
            ans.push_back(ok && j == m);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def camelMatch(self, queries: list[str], pattern: str) -> list[bool]:
        ans = []
        m = len(pattern)
        for q in queries:
            j = 0
            ok = True
            for ch in q:
                if j < m and ch == pattern[j]:
                    j += 1                                # 匹配模式的下一个字符
                elif ch.isupper():
                    ok = False                            # 大写无法被插入解释
                    break
                # 否则是小写字母：视作插入，跳过
            ans.append(ok and j == m)
        return ans
```

## 8. 边界情况与易错点

1. **漏掉 `j == m` 检查**：`"FooBar"` 配 `"FoBaT"` 会误判为 true（模式没匹配完）。
2. **多出的大写**：`"FooBarTest"` 配 `"FB"`，`FB` 匹配完后 `T` 是大写 → false。忘记「模式已用完时大写也要拒绝」是最常见 WA。
3. **大小写敏感**：`"Fo"` 与 `"fO"` 不匹配，`==` 逐字符比较即可，不要用 `tolower`。
4. **`pattern` 里的小写必须在查询中出现**：`"FrameBuffer"` 缺小写 `o`，即使大写 `F`、`B` 都在也判 false。
5. **查询比模式短**：如 `"F"` 配 `"FB"`，扫完 `j=1 < 2` → false。
6. **`pattern` 只有一个字符**：`"F"` 匹配任何「以 F 开头且后面全小写」的串。
7. **完全相等**：`q == pattern` 应返回 true（插入 0 个字符），算法自然满足。
