# LeetCode 视频拼接 题解

## 1. 题目概述

- **标题 / 题号**：视频拼接（#1024，medium）
- **链接**：https://leetcode.cn/problems/video-stitching/
- **来源**：LeetCode 第 131 场周赛 Q4
- **难度**：中等
- **标签**：贪心、数组、动态规划、区间覆盖

**题意**：给定若干视频片段 `clips`，其中 `clips[i] = [start_i, end_i]` 表示该片段覆盖时间区间 $[start_i, end_i]$。片段可以**自由再剪辑**（例如 $[0,7]$ 可切成 $[0,1]+[1,3]+[3,7]$），也可以丢弃。

要求选出**最少**的片段，使它们（再剪辑后）能完整覆盖 $[0, time]$。若无法做到，返回 $-1$。

**约束**：

- $1 \le clips.length \le 100$
- $0 \le start_i \le end_i \le 100$
- $1 \le time \le 100$

> 💡 「可以再剪辑」等价于「片段覆盖的区间可以任意截取子区间」，于是问题变成纯粹的**区间覆盖最少个数**问题，与顺序、重叠方式无关。

## 2. 示例

**示例 1**

```text
输入：clips = [[0,2],[4,6],[8,10],[1,9],[1,5],[5,9]], time = 10
输出：3
解释：选 [0,2]、[1,9]、[8,10] 三个片段：
      [0,2] + ([1,9] 剪出的 [2,9]) + [8,10] 覆盖 [0,10]。
```

**示例 2**

```text
输入：clips = [[0,1],[1,2]], time = 5
输出：-1
解释：两个片段最多覆盖到时刻 2，无法覆盖到 5。
```

**示例 3**

```text
输入：clips = [[0,1],[6,8],[0,2],[5,6],[0,4],[0,3],[6,7],[1,3],[4,7],[1,4],[2,5],[2,6],[3,4],[4,5],[5,7],[6,9]], time = 9
输出：3
解释：选 [0,4]、[4,7]、[6,9]，覆盖 [0,9]。
```

## 3. 解题思路

### 3.1 暴力思路

对片段集合枚举子集，判断所选片段并集是否覆盖 $[0, time]$，取最小子集大小。$n \le 100$ 时 $2^{100}$ 完全不可行。

另一种思路是 DP：设 $f[t]$ 为覆盖 $[0, t]$ 所需最少片段数，转移 $f[e] = \min(f[e], f[s] + 1)$，其中 $[s, e]$ 是某片段且 $s \le$ 已覆盖的右端点。看起来可行，但需要小心处理「从任意 $s$ 转移」时的取整：写成 $f[e] = \min_{s \le e} f[s] + 1$ 并不正确，必须保证 $s$ 落在已覆盖区间内。正确做法是 DP 或贪心，见下。

### 3.2 核心观察：把片段压缩成「起点 → 最远终点」，然后跑跳跃游戏

![区间覆盖：只关心每个起点能到的最远终点](images/wc131_q4_reach_greedy.svg)

**第一步：压缩**。同一个起点 $s$ 可能对应多个片段，它们都从 $s$ 开始，显然只有**终点最大**的那个有用（更短的片段覆盖范围是它的子区间）。定义

$$reach[s] = \max\{\, end_i : start_i = s \,\}$$

没有以 $s$ 为起点的片段时 $reach[s] = 0$。

**第二步：变成跳跃游戏**。现在问题等价于：从位置 0 出发，当前已覆盖到 $cur$，下一步可以从任意 $s \le cur$ 跳到 $reach[s]$，问最少跳几次能到达 $time$。

这正是 [LeetCode 45. 跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/) 的模型，用标准贪心：

- 维护 `cur`（当前已覆盖的右端点）、`farthest`（再选一个片段能到达的最远点）、`ans`（已用片段数）；
- 扫描 $i = 0, 1, \dots, time-1$，不断更新 `farthest = max(farthest, reach[i])`；
- 当 $i = cur$ 时，「这一步能到达的极限」已经算完：若 `farthest == cur`，说明再没有片段能往外扩，返回 $-1$；否则令 `cur = farthest`，`ans++`。

> 💡 为什么贪心最优？因为每一步都取「在当前已覆盖范围内所有片段能到达的最远点」，任何方案都不可能跳得比它更远（引理 2），而「更远」在区间覆盖中永远不劣（引理 3）。

### 3.3 算法流程

![算法流程：压缩 reach → 跳跃式贪心](images/wc131_q4_algorithm_flow.svg)

```text
1. reach[0..time] 全 0
2. for [s, e] in clips:
       若 s < time:  reach[s] = max(reach[s], min(e, time))    # 超出 time 的部分截断
3. ans = 0, cur = 0, farthest = 0
4. for i = 0 .. time-1:
       farthest = max(farthest, reach[i])
       若 i == cur:
           若 farthest <= cur:  返回 -1          # 卡住，扩不出去
           cur = farthest
           ans += 1
5. 返回 ans
```

### 3.4 示例演算

![示例演算：三段拼接覆盖 [0,10]](images/wc131_q4_walkthrough.svg)

对示例 1：`clips = [[0,2],[4,6],[8,10],[1,9],[1,5],[5,9]]`，`time = 10`，压缩得

| 起点 $s$ | 0 | 1 | 4 | 5 | 8 |
|---|---|---|---|---|---|
| `reach[s]` | 2 | 9 | 6 | 9 | 10 |

贪心过程：

| 扫描 $i$ | 新纳入的 `reach[i]` | `farthest` | $i = cur$？ | 动作 |
|---|---|---|---|---|
| 0 | 2 | 2 | 是（cur=0） | `cur = 2`，`ans = 1` |
| 1 | 9 | 9 | 否（cur=2） | — |
| 2 | 0 | 9 | 是（cur=2） | `cur = 9`，`ans = 2` |
| 3..8 | 6, 9, 10 | 10 | i=8 时 cur=9，否 | — |
| 9 | 0 | 10 | 是（cur=9） | `cur = 10`，`ans = 3` |

扫描结束，`ans = 3` ✓。对应片段是 $[0,2]$、$[1,9]$、$[8,10]$。

示例 2：`reach[0]=1`、`reach[1]=2`。第 1 轮后 `cur=1`；第 2 轮 $i=1$ 时 `farthest=2`，`cur=2`，`ans=2`；第 3 轮 $i=2$ 时 `farthest=2 == cur`，返回 $-1$ ✓。

## 4. 算法细节

1. **终点截断**：片段终点可能超过 `time`，用 `min(e, time)` 截断，既不影响正确性，也让数组不必开更大。
2. **起点落在 $[0, time)$**：起点 $\ge time$ 的片段对覆盖 $[0, time]$ 毫无贡献，直接忽略（`s < time` 判断）。
3. **`reach` 长度取 $time+1$**：下标到 `time`，但循环只用到 $time-1$。
4. **循环边界**：$i$ 从 0 到 $time - 1$，因为覆盖到 $time$ 时任务已完成，不需要再扩展。
5. **`farthest <= cur` 判无解**：等号也要判——如果最远也只能到 `cur`，说明没有任何片段能越界，必然卡死。
6. **答案上界**：最多 $time$ 个片段（每段推进至少 1），`ans` 用 `int` 足够。
7. **DP 对照**：也可以写 $O(n \cdot time)$ 的 DP（$f[t]$ 表示覆盖到 $t$ 的最少片段），但贪心是 $O(n + time)$ 且常数极小。

## 5. 正确性证明

设 $reach[s]$ 如算法定义（对 $s \ge time$ 定义 $reach[s] = s$ 不影响结论）。

**引理 1（压缩不损失）**：若某方案用片段 $[s, e]$，把 $e$ 换成 $reach[s] \ge e$ 后仍是合法方案且片段数不变。

**证明**：新片段 $[s, reach[s]]$ 覆盖了原片段覆盖的一切时间点（超集），替换后并集不减，仍覆盖 $[0, time]$；片段数不变。∎

**引理 2（一轮的可达上界）**：设某方案已用 $k$ 个片段覆盖了 $[0, x]$，则它下一片段必然满足 $start \le x$，且用 $k+1$ 个片段最多覆盖到 $\max_{s \le x} reach[s]$。

**证明**：要覆盖连续区间，下一片段必须与已覆盖部分「接上」，即其起点 $s \le x$（否则区间 $[x, s)$ 断开）。它能提供的最远终点是 $reach[s]$，故 $k+1$ 个片段能覆盖的最远点是 $\max_{s \le x} reach[s]$。∎

**引理 3（覆盖更远不劣）**：若用 $k$ 个片段能覆盖 $[0, x]$，则对任意 $x' \le x$ 也能用同样多片段覆盖 $[0, x']$（截断即可）；且用 $k$ 个片段覆盖 $[0, x]$ 的方案，若能把最远覆盖推到 $x'' > x$，则同样 $k$ 个片段覆盖的方案在后续只需考虑更长的前缀。

**证明**：区间覆盖具有单调性——已覆盖前缀越长，后续可用片段的起点约束 $s \le x$ 越宽松，可行集合只会变大。故「当前覆盖得更远」不会使最优解变差。∎

**引理 4（贪心每轮的 `cur` 恰为最优可达点）**：算法第 $k$ 轮结束时，`cur` $= \max\{$ 用 $k$ 个片段能覆盖的前缀右端点 $\}$。

**证明**：对 $k$ 归纳。$k = 0$ 时 `cur` $= 0$，显然。设 $k$ 轮后 `cur` $= X_k$，本轮扫描 $i \in [X_{k-1}, X_k)$ 并累加 `reach`，得到 $X_{k+1} = \max_{s \le X_k} reach[s]$——由引理 2 这正是 $k+1$ 个片段的最远覆盖点；算法把 `cur` 设为该值。∎

**定理**：算法返回的值等于最少片段数，无法覆盖时返回 $-1$。

**证明**：由引理 4，算法第 $k$ 轮结束时的 `cur` 恰为「用 $k$ 个片段可达的最远覆盖点」，且该序列严格递增（否则算法判 $-1$ 并返回）。因此算法返回的 `ans` 是最小的 $k$ 使 `cur` $\ge time$，即最少片段数。若在某个 $i = cur$ 处 `farthest <= cur`，由引理 2 可知用任意多片段都无法突破 `cur`，而 `cur < time`，故无法覆盖，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n + time)$。压缩 `reach` 遍历一次 `clips`（$O(n)$），跳跃扫描 $O(time)$；因 $time \le 100$ 常数极小。
- **空间**：$O(time)$，`reach` 数组；不计输入时没有其他额外空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int videoStitching(vector<vector<int>>& clips, int time) {
        vector<int> reach(time + 1, 0);
        for (const auto& c : clips) {
            int s = c[0], e = c[1];
            if (s < time) reach[s] = max(reach[s], min(e, time));   // 终点截断到 time
        }

        int ans = 0, cur = 0, farthest = 0;
        for (int i = 0; i < time; i++) {
            farthest = max(farthest, reach[i]);
            if (i == cur) {                    // 当前一轮的扩展算完
                if (farthest <= cur) return -1; // 扩不出去，无解
                cur = farthest;
                ans++;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def videoStitching(self, clips: list[list[int]], time: int) -> int:
        reach = [0] * (time + 1)
        for s, e in clips:
            if s < time:
                reach[s] = max(reach[s], min(e, time))   # 终点截断到 time

        ans = cur = farthest = 0
        for i in range(time):
            farthest = max(farthest, reach[i])
            if i == cur:                    # 当前一轮的扩展算完
                if farthest <= cur:         # 扩不出去，无解
                    return -1
                cur = farthest
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **没有片段从 0 开始**：`reach[0] = 0`，第一轮就 `farthest <= cur`，返回 $-1$。不要漏判。
2. **片段终点超过 `time`**：必须截断（或允许数组越界），否则 `reach` 可能指到 `time` 之外。
3. **缝隙**：如 `[[0,1],[2,3]]`、`time=3`，第二轮 `farthest=1 == cur` → $-1$。区间覆盖必须连续，不能靠「覆盖长度之和」判断。
4. **单片段足够**：`[[0, time]]` → `reach[0]=time`，第一轮 `cur=time`，`ans=1`。
5. **`farthest <= cur` 用 `<=` 而非 `<`**：等于时已经无法推进，必须判无解。
6. **循环只到 `time-1`**：`i` 取到 `time` 没有意义（已覆盖完），还会多算一轮。
7. **重复起点**：同一 `s` 多个片段，用 `max` 合并，别只取第一个。
8. **`time` 很小**：$time = 1$ 时循环只跑 $i=0$ 一次，检查 `reach[0] >= 1` 即可，逻辑自然成立。
