# LeetCode 制造字母异位词的最小步骤数 题解

## 1. 题目概述

- **标题 / 题号**：制造字母异位词的最小步骤数（#1347，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-steps-to-make-two-strings-anagram/
- **来源**：LeetCode 第 175 场周赛 Q2
- **难度**：中等
- **标签**：哈希表，字符串，计数

**题意**：给定长度相等的两个小写字符串 $s$ 与 $t$。每一步可以挑 $t$ 中**任意一个位置**，把该位置的字符换成**另一个**字符。求最少多少步能让 $t$ 成为 $s$ 的**字母异位词**——即两串的字符多重集完全相同，排列不计。

**约束**：

- $1 \le \lvert s \rvert \le 5 \times 10^4$
- $\lvert s \rvert = \lvert t \rvert$
- `s`、`t` 只含小写英文字母

> 💡 长度相等是关键前提：替换不改变长度，所以「两个计数向量对齐」就是全部目标，不需要增删字符。

## 2. 示例

**示例 1**

```text
输入：s = "bab", t = "aba"
输出：1
解释：cntS = {a:1, b:2}，cntT = {a:2, b:1}；
      t 多了 1 个 a、少了 1 个 b，把首个 a 换成 b 得 "bba"，1 步完成。
```

**示例 2**

```text
输入：s = "leetcode", t = "practice"
输出：5
解释：t 比 s 多出 a、c、i、p、r 各 1 个（共 5 个）；
      s 比 t 多出 d、l、o 各 1 个、e 多 2 个（也共 5 个）；
      把 p、r、a、i、c 依次换成 l、o、d、e、e 即可，5 步。
```

**示例 3**

```text
输入：s = "anagram", t = "mangaar"
输出：0
解释：两串每个字母的计数完全相同（a:3, n:1, g:1, r:1, m:1），
      只是排列不同，一步都不用改。
```

## 3. 解题思路

### 3.1 暴力思路

- 最直白的做法：枚举 $s$ 的所有不同排列（至多 $n!$ 个），对每个排列数它与 $t$ 的汉明距离，取最小值。$n = 5\times10^4$ 时状态规模是天文数字，即便 $n = 10$ 也要 $3.6\times10^6$ 次比较，完全不可行。
- 常见错解一：**逐位比较** `s[i] != t[i]` 并计数。它把「排列」当成了「位置」：示例 3 的 `anagram` / `mangaar` 逐位比较会数出 5 处不同，正确输出却是 0，直接 WA。
- 常见错解二：统计「多出的」和「缺少的」时两边都算，得到 $\sum_c \lvert d_c \rvert$，答案整整翻一倍。

瓶颈在于：**答案与排列无关，只与 26 个计数有关**。

### 3.2 核心观察：盈余必须被改写，缺口正好接收

![盈余与缺口一一配对](images/wc175_q2_surplus_model.svg)

记 $\text{cntS}[c]$、$\text{cntT}[c]$ 为字符 $c$ 在两串中的出现次数，定义

$$d_c = \text{cntT}[c] - \text{cntS}[c]$$

- $d_c > 0$：$t$ 里 $c$ **多出来**了。目标态里 $c$ 只能有 $\text{cntS}[c]$ 个，所以这 $d_c$ 个位置上的 $c$ 最终必须消失，它们**必被替换**，至少动 $d_c$ 个位置。
- $d_c < 0$：$t$ 里 $c$ **缺少** $-d_c$ 个，这些缺口只能由别的位置改写成 $c$ 来填。
- 因为 $\lvert s \rvert = \lvert t \rvert$，有 $\sum_c d_c = 0$，于是

$$\sum_{d_c > 0} d_c = \sum_{d_c < 0} (-d_c) = m$$

即**盈余总数 = 缺口总数 = m**。

**一次替换恰好消掉一个盈余、补上一个缺口**：把某个多余字母的位置改写成某个缺少的字母。两侧数量相等，可以一一配对，$m$ 步后计数向量完全对齐，故

$$ans = \sum_{c} \max(0,\ d_c)$$

还有一处细节：题目要求换成「**另一个**字符」。盈余字母与缺口字母必然不同（同一个字母不可能既多又少），所以每次配对写下的字符一定不等于被换掉的字符，这个限制自动满足。

### 3.3 算法流程

![两趟计数加 26 次求和](images/wc175_q2_count_flow.svg)

1. 开一个长度 26 的整型数组 `diff`，初值全 0，下标 `ch - 'a'` 对应字母 `ch`。
2. 遍历 `t`：`diff[ch - 'a'] += 1`。
3. 遍历 `s`：`diff[ch - 'a'] -= 1`。此时 `diff[c] = cntT[c] - cntS[c]`。
4. 遍历 26 个桶，只把**正值**累加：若 `diff[c] > 0` 则 `ans += diff[c]`。
5. 返回 `ans`。

三趟线性扫描，没有排序、没有配对、也没有任何字符串构造。

### 3.4 示例演算

![示例 2 的计数表](images/wc175_q2_walkthrough.svg)

以 `s = "leetcode"`、`t = "practice"` 为例，只列出出现过的 10 个字母：

| 字母 | a | c | d | e | i | l | o | p | r | t |
|------|---|---|---|---|---|---|---|---|---|---|
| `cntS` | 0 | 1 | 1 | 3 | 0 | 1 | 1 | 0 | 0 | 1 |
| `cntT` | 1 | 2 | 0 | 1 | 1 | 0 | 0 | 1 | 1 | 1 |
| `d = cntT − cntS` | +1 | +1 | −1 | −2 | +1 | −1 | −1 | +1 | +1 | 0 |

正和 $= 1+1+1+1+1 = 5$（a、c、i、p、r），负和 $= -1-2-1-1 = -5$（d、e、l、o），两者恰好抵消。按引理 2 配对：`p→l`、`r→o`、`a→d`、`i→e`、`c→e`，5 步后 $t$ 的字母多重集变成 $\{c,d,e,e,e,l,o,t\}$，正是 `leetcode` 的多重集，与官方输出 5 一致。

## 4. 算法细节

1. **一趟加、一趟减，只用一个数组**：对 `t` 加、对 `s` 减，得到的 `diff` 直接就是「$t$ 相对 $s$ 的盈余」。反过来写（对 `s` 加、对 `t` 减）同样正确，但那时要累加**负值**，符号极易写反。
2. **答案只取正值之和**：`sum(d for d in diff if d > 0)`。不要写成 `sum(abs(d) for d in diff)`——那是 $2m$；也不必先求 $\sum\lvert d_c\rvert$ 再除 2，直接累加正值最不容易把符号写错。
3. **值域用固定数组而非哈希表**：字母只有 26 种，`int diff[26]` 的随机访问远快于 `dict` / `unordered_map`，且额外空间是常数。
4. **不要真的去构造目标串**：配对只用于证明与解释，代码里一步都不需要生成新字符串，因此也不会出现 $O(n^2)$ 的隐式拷贝。
5. **「换成另一个字符」无需特判**：由引理 3，盈余集合与缺口集合不相交，配对的字符必不相同；即使题目允许换成相同字符，那样的一步毫无意义，答案不变。
6. **长度相等是隐含前提**：替换不改变长度，若 $\lvert s \rvert \ne \lvert t \rvert$ 本题无解。若真要做不等长的版本（例如只能追加字符的 2186），答案会变成 $\sum_c \lvert d_c \rvert$。
7. **计数用 `int`**：$\lvert s \rvert \le 5\times10^4$，单个桶最大 $5\times10^4$，`int` 足够；用 `char` / `short` 会溢出（`char` 上限才 127）。

## 5. 正确性证明

**引理 1（下界）**：任何把 $t$ 变成 $s$ 的字母异位词的替换方案，步数不少于 $m = \sum_{d_c>0} d_c$。

**证明**：把每一步按「被替换位置在替换**前**的字符」分类。记 $A_c$ 为把某个 $c$ 换成非 $c$ 的步数，$B_c$ 为把某个非 $c$ 换成 $c$ 的步数，则总步数 $S = \sum_c A_c$（每步恰有一个来源字符，不会被重复计数）。

终态时字符 $c$ 的个数必须是 $\text{cntS}[c]$，而它从初态 $\text{cntT}[c]$ 出发只被这两类操作改变，故

$$\text{cntS}[c] = \text{cntT}[c] - A_c + B_c \;\Longrightarrow\; A_c = d_c + B_c \ge d_c \quad (d_c > 0)$$

对所有 $d_c > 0$ 的字母求和得 $S \ge \sum_{d_c>0} d_c = m$。∎

**引理 2（可达上界）**：存在步数恰为 $m$ 的方案。

**证明**：构造如下。由 $\sum_c d_c = 0$ 知缺口总数也是 $m$：把每个 $d_c<0$ 的字母 $c$ 复制 $-d_c$ 份，得到一个长为 $m$ 的目标序列 $L$；再把每个 $d_c>0$ 的字母 $c$ 在 $t$ 中占据的 $d_c$ 个位置列出来（同一字母的不同位置互不重复），得到长为 $m$ 的位置序列 $P$。将 $P$ 与 $L$ 任意一一配对，对每个配对 $(p,\ \ell)$ 把位置 $p$ 上的字符改写为 $\ell$。

每个位置只被改写一次，总步数恰为 $m$。改写后对任意字母 $c$：

- 若 $d_c > 0$：它被改走了恰好 $d_c$ 次，个数变为 $\text{cntT}[c] - d_c = \text{cntS}[c]$；
- 若 $d_c < 0$：它被写入恰好 $-d_c$ 次，个数变为 $\text{cntT}[c] - d_c = \text{cntS}[c]$；
- 若 $d_c = 0$：它既不出现在 $P$ 也不出现在 $L$ 中，个数保持 $\text{cntS}[c]$。

终态与 $s$ 的计数向量逐项相同，即 $t$ 已成为 $s$ 的字母异位词。∎

**引理 3（替换合法）**：上述方案中每次写入的新字符都与被改掉的字符不同，满足「替换为另一个字符」的要求。

**证明**：位置序列 $P$ 中的字符都满足 $d_c > 0$，目标序列 $L$ 中的字符都满足 $d_{\ell} < 0$。若某个字符同时满足这两条，则有 $0 < d_c < 0$，矛盾；故两个字符集合不相交，任一配对 $(c, \ell)$ 必有 $c \ne \ell$。∎

**定理**：最少步骤数为 $m = \sum_c \max(0,\ \text{cntT}[c] - \text{cntS}[c])$。

**证明**：引理 1 给出下界 $m$；引理 2 与引理 3 给出一个合法的、步数恰为 $m$ 的方案，故最优值等于 $m$。算法第 4 步逐桶累加 $\max(0, d_c)$，返回的正是 $m$。∎

## 6. 复杂度分析

- **时间**：$O(\lvert s \rvert + \lvert t \rvert + 26) = O(n)$，其中 $n = \lvert s \rvert = \lvert t \rvert$。两趟字符串扫描各 $O(n)$，每次只做一次数组下标自增；最后遍历 26 个桶是 $O(26)$，与 $n$ 无关。$n = 5\times10^4$ 时总共十万次量级操作：C++ 在微秒级，Python 实测约 10 ms（主要是解释器循环开销）。
- **空间**：$O(\lvert \Sigma \rvert) = O(26) = O(1)$，$\Sigma$ 为字母表。只有一张 26 个 `int` 的计数表，与输入规模无关；不构造子串、不存排列。若字母表放大到任意 Unicode，则退化为哈希表，空间为 $O(\lvert \Sigma \rvert)$。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    int minSteps(string s, string t) {
        int diff[26] = {0};
        for (char c : t) ++diff[c - 'a'];   // t 的计数
        for (char c : s) --diff[c - 'a'];   // 减去 s 的计数
        int ans = 0;
        for (int d : diff) {
            if (d > 0) ans += d;            // 盈余的字符必须被改写
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minSteps(self, s: str, t: str) -> int:
        diff = [0] * 26
        for ch in t:
            diff[ord(ch) - 97] += 1      # t 的计数
        for ch in s:
            diff[ord(ch) - 97] -= 1      # 减去 s 的计数
        return sum(d for d in diff if d > 0)

# 等价的紧凑写法（Counter 常数略大，但同样 O(n)）：
# from collections import Counter
# diff = Counter(t) - Counter(s)     # 只保留正差额
# return sum(diff.values())
```

## 8. 边界情况与易错点

1. **两串已是异位词但排列不同**：`s = "anagram"`、`t = "mangaar"` 时 `diff` 全 0，应返回 0。逐位比较会数出 5 处不同，若把它当答案就错了。
2. **两串完全相同**：`s = t = "xxyyzz"` 返回 0；上面代码天然成立，无需特判。
3. **公共字母很少**：`s = "friend"`、`t = "family"` 只有 `f`、`i` 重合，盈余 `a`、`m`、`l`、`y` 共 4 个，返回 4。答案最大值可以达到 $n$，绝不会超过 $n$。
4. **单字符输入**：$n = 1$ 时相同返回 0、不同返回 1；`diff` 中恰有一个 $+1$ 与一个 $-1$，逻辑不需要特判。
5. **把 $\sum\lvert d_c\rvert$ 当答案**：它等于 $2m$，示例 2 会算出 10 而不是 5，是最常见的翻倍错误。
6. **符号方向写反**：若改成「`s` 加、`t` 减」，累加条件必须换成 `d < 0`；两种约定混用必然出错。
7. **字符映射**：C++ 用 `c - 'a'`、Python 用 `ord(ch) - 97`，不要误写成 `c - '0'`；约束保证只有小写字母，26 个桶刚好够。
8. **语言细节**：C++ 的 `int diff[26] = {0}` 必须初始化，否则是随机值；Python 里用 `str.count` 数 26 次是 $O(26n)$，能过但比单趟扫描慢一倍。
9. **答案范围**：$0 \le ans \le n \le 5\times10^4$，`int` 安全，不需要 `long long`。

**延伸思考**：

1. **要输出具体方案怎么办？** 照引理 2 的配对构造即可：先把 $t$ 中盈余字母的下标按字母压栈，再按缺口字母逐份弹出并改写。时间仍是 $O(n)$，空间 $O(n)$。
2. **如果操作换成「交换 $t$ 中任意两个字符」？** 答案不再是计数问题：先把 $t$ 与 $s$ 的同字符位置配对，得到位置上的置换（同字符有重复时选使环数最多的配对），最少交换数为 $n - \text{环数}$，思路与本题完全不同。
3. **如果字母表放大到全体 Unicode？** 26 个桶换成哈希表，时间 $O(n)$、空间 $O(\lvert\Sigma\rvert)$；若字符集是固定小字母表（如 52 个大小写字母），数组仍然够用。
4. **如果只问「$k$ 步内能否做到」？** 只需判断 $m \le k$；反过来说，「最少几步」这个优化问题的答案 $m$ 已经把判定问题完全刻画了，这也是本题能 $O(n)$ 解决的深层原因。
