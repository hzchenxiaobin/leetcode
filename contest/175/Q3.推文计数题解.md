# LeetCode 推文计数 题解

## 1. 题目概述

- **标题 / 题号**：推文计数（#1348，medium）
- **链接**：https://leetcode.cn/problems/tweet-counts-per-frequency/
- **来源**：LeetCode 第 175 场周赛 Q3
- **难度**：中等
- **标签**：设计，哈希表，字符串，二分查找，有序集合，排序

**题意**：实现一个 `TweetCounts` 类，维护「推文名 → 发布时间」的多重集合，支持两种操作：

1. `recordTweet(tweetName, time)`：记下一条名为 `tweetName` 的推文，发布时刻为 `time`（秒）。
2. `getTweetCountsPerFrequency(freq, tweetName, startTime, endTime)`：把**闭区间** $[\text{startTime},\ \text{endTime}]$ 从 `startTime` 起按频率 `freq` 切成等长的块，返回每一块内该推文的条数。`freq` 为 `minute` / `hour` / `day`，对应块长 $c \in \{60,\ 3600,\ 86400\}$ 秒。

**关键语义**：第 $i$ 块是 $\bigl[\text{startTime} + i c,\ \min(\text{startTime} + (i+1)c - 1,\ \text{endTime})\bigr]$，即**块起点锚定在 `startTime`**、步长固定为 $c$，只有最后一块可能不满，并且**必须止于 `endTime`**。块的个数是

$$k = \left\lfloor \frac{\text{endTime} - \text{startTime}}{c} \right\rfloor + 1$$

**约束**：

- $0 \le \text{time},\ \text{startTime},\ \text{endTime} \le 10^9$
- $0 \le \text{endTime} - \text{startTime} \le 10^4$
- `recordTweet` 与 `getTweetCountsPerFrequency` **合计**至多 $10^4$ 次调用
- `freq ∈ {minute, hour, day}`；同一推文允许**同一秒出现多条**记录

> 💡 由第二条约束立刻得到 $k$ 的上界：`minute` 最多 $\lfloor 10^4/60 \rfloor + 1 = 167$ 块，`hour` 最多 3 块，`day` 恒为 1 块。**块数很小**，瓶颈不在「块多」，而在「每块要快速数点」。

## 3. 解题思路

### 3.1 暴力思路

**暴力 A（每块扫一遍全部记录）**：单次查询 $O(km)$，$k = 167$、$m = 10^4$ 时约 $1.67\times 10^6$，乘 $10^4$ 次查询约 $1.6\times 10^{10}$，必然超时。

**暴力 B（扫一遍记录、按块号累积）**：对每条记录算 $\bigl\lfloor (t - s)/c \bigr\rfloor$ 填桶，单次 $O(m + k)$，最坏 $10^8$ 级别，能过但每次查询都要重扫整个时间集合。**暴力 C（按时间开桶）** 也不行：时间上限 $10^9$ 开不下；即使只对出现过的时刻离散化，块边界依赖 `startTime`，每次划分都不同，预计算派不上用场。

所以瓶颈是**每次查询都重复扫描全部记录**：要让「区间内有多少条记录」缩成一次 $O(\log m)$ 查询。

### 3.2 核心观察：块划分与时间集合正交，有序数组上两次二分

![时间块切分：起点锚定 startTime，末块截断到 endTime](images/wc175_q3_time_blocks.svg)

**观察 1：块划分只由 $(\text{startTime}, \text{endTime}, c)$ 决定，与记录无关。** 因此一次查询被**精确地分解**成 $k$ 个互相独立的子问题：

$$\text{ans}[i] = \#\{\, t \in A :\ t \in B_i \,\}, \qquad B_i = \bigl[s + ic,\ \min(s + (i+1)c - 1,\ e)\bigr]$$

其中 $A$ 是该推文的时间集合，$s = \text{startTime}$，$e = \text{endTime}$；这 $k$ 个子问题**互不影响**，可以分别回答。

**观察 2：只要 $A$ 升序排列，「闭区间内有多少个元素」就能二分出来。** 设 $A = [a_0 \le a_1 \le \dots \le a_{m-1}]$，则

$$\#\{\, t \in A : \text{lo} \le t \le \text{hi} \,\} = \operatorname{upper\_bound}(\text{hi}) - \operatorname{lower\_bound}(\text{lo})$$

前一项是「第一个 $> \text{hi}$ 的下标」即 $\le \text{hi}$ 的元素个数，后一项是「第一个 $\ge \text{lo}$ 的下标」即 $< \text{lo}$ 的元素个数，两者相减正好是落在 $[\text{lo}, \text{hi}]$ 里的个数。单块 $O(\log m)$，整次查询 $O(k \log m)$；最坏 $167 \times 2 \times 14 \approx 4.7\times 10^3$ 次比较，比暴力 A 的 $1.67\times 10^6$ 小三个数量级。

**观察 3：$k$ 很小，所以「每块两次二分」划算；若 $k$ 很大（区间宽 $10^9$）反该用暴力 B。** 整个设计由此归结为**一个不变式**：每个推文的时间数组始终升序，`recordTweet` 按位置插入维护它即可。

### 3.3 算法流程

![记录进有序数组，查询时每块两次二分](images/wc175_q3_bisect_flow.svg)

**数据结构**：哈希表 `map<string, vector<int>>`，键是推文名，值是该推文全部发布时刻的**升序数组**（允许多重，同秒可重复）。

**`recordTweet(name, time)`**：

1. 取出 `a = map[name]`（不存在则新建空数组）。
2. 在 `a` 中用 `lower_bound(time)` 找到第一个 $\ge \text{time}$ 的位置，把 `time` 插入该位置，数组保持非降序。用 `lower_bound` 而不是 `upper_bound` 只是习惯；两者都能保持有序，区别只在于相等元素插在前还是后，对计数**没有影响**。

**`getTweetCountsPerFrequency(freq, name, s, e)`**：

1. `c = 60 / 3600 / 86400`（按 `freq` 查表）。
2. `k = (e - s) / c + 1`，结果数组长度即为 $k$。
3. 若 `map` 中没有 `name`，直接返回 $k$ 个 0。
4. 对 $i = 0, 1, \dots, k-1$：
   - `lo = s + i * c`；
   - `hi = min(lo + c - 1, e)`；
   - `ans[i] = upper_bound(hi) - lower_bound(lo)`。
5. 返回 `ans`。

### 3.4 示例演算

![示例演算：三次记录、三次查询](images/wc175_q3_walkthrough.svg)

| 操作 | 有序数组 $A$ | 块划分 | 输出 |
|------|--------------|--------|------|
| `recordTweet("tweet3", 0)` | $[0]$ | — | — |
| `recordTweet("tweet3", 60)` | $[0, 60]$ | — | — |
| `recordTweet("tweet3", 10)` | $[0, 10, 60]$ | — | — |
| `minute, [0, 59]` | $[0, 10, 60]$ | $[0,59]$（1 块） | $[2]$ |
| `minute, [0, 60]` | $[0, 10, 60]$ | $[0,59]$、$[60,60]$（2 块） | $[2, 1]$ |
| `recordTweet("tweet3", 120)` | $[0, 10, 60, 120]$ | — | — |
| `hour, [0, 210]` | $[0, 10, 60, 120]$ | $[0,210]$（1 块） | $[4]$ |

重点看第四、五行的差别：$e - s = 59$ 时 $k = \lfloor 59/60 \rfloor + 1 = 1$；$e - s = 60$ 时 $k = \lfloor 60/60 \rfloor + 1 = 2$——**区间长度恰好等于块长时会多出一块**，这一块只含一个时间点 `60`。第二块里 `lower_bound(60)` 返回下标 2，`upper_bound(60)` 返回下标 3，相减得 1，正是官方输出里的那个 `1`。`hour` 那次则相反：$c = 3600 > 210$，$k = 1$，`lower_bound(0) = 0`、`upper_bound(210) = 4`，四段时间全落在唯一一块里，得 4。

## 4. 算法细节

1. **频率到块长的映射用查表**：`minute → 60`、`hour → 3600`、`day → 86400`，避免写三段 `if`。注意 `day` 是 86400 秒（= 3600 × 24），不要顺手写成 3600。
2. **块数公式必须向下取整再加一**：$k = \lfloor (e-s)/c \rfloor + 1$。整数除法天然向下取整，C++ 与 Python 对非负数一致。写成 `k = (e-s+c-1)/c` 就错了——那是「向上取整」，会把末块丢掉一半的场景算少。
3. **末块上界要截断且注意加法范围**：`hi = min(lo + c - 1, e)`；若直接写 `lo + c - 1`，最后一块可能越过 `e`，把区间外的记录算进来。`lo = s + i*c` 最大约 $10^9 + 10^4$，远小于 $2^{31}-1$，32 位 `int` 够用（Python 无此问题）。
4. **计数用 `lower_bound(lo)` 与 `upper_bound(hi)` 相减**：前者是第一个 $\ge \text{lo}$ 的位置，后者是第一个 $> \text{hi}$ 的位置。若把后一项写成 `lower_bound(hi)`，等于把 $\le \text{hi}$ 改成了 $< \text{hi}$，**恰好等于 `hi` 的记录会被漏算**——示例 1 里时间 60 正好贴在第二块右端点，这种错法在样例上就会挂。
5. **未知推文必须返回 $k$ 个 0**：`getTweetCountsPerFrequency` 的返回长度由区间与频率决定，与是否命中哈希表无关。返回 `{}` / `[]` 是常见错误。C++ 里可以先建好 `vector<int> ans(k, 0)` 再取数据，天然正确。
6. **同一秒的多条记录要保留**：题目允许重复时间，所以组内是**多重集**。用 `set` / `unordered_set` 会去重；C++ 用 `vector` 或 `multiset`，Python 用 `list`（配合 `insort`）。
7. **C++ 选 `vector` 而不是 `multiset`**：`multiset` 的迭代器是双向的，`std::distance` 是 $O(\text{count})$，`ub - lb` 会退化成 $O(m)$；`vector` 迭代器随机访问，相减 $O(1)$。`multiset::count` 同样是 $O(\text{count} + \log m)$。
8. **插入用 `lower_bound` 定位再 `insert`**：插入本身 $O(m)$ 次元素移动，但 $m \le 10^4$ 且总操作数 $10^4$，最坏 $10^8$ 次 `int` 移动在 C++ 里约 0.1 秒，Python 的 `insort` 也只是 $O(m)$ 的 `memmove`，实测 0.3 秒内跑完。

## 5. 正确性证明

**引理 1（块划分正确）**：设 $c \ge 1$、$s \le e$，$k = \lfloor (e-s)/c \rfloor + 1$，$B_i = [s + ic,\ \min(s + (i+1)c - 1,\ e)]$（$0 \le i < k$）。则 $B_0, \dots, B_{k-1}$ **两两不交**且并集恰为 $[s, e]$。

**证明**：先证覆盖。任取整数 $t \in [s, e]$，令 $i = \lfloor (t - s)/c \rfloor$，则 $0 \le i \le k-1$ 是合法块号；由取整定义有 $ic \le t - s < (i+1)c$，即 $s + ic \le t \le s + (i+1)c - 1$，又有 $t \le e$，故 $t \le \min(s + (i+1)c - 1,\ e)$，即 $t \in B_i$。再证不交。设 $i < j$，则 $B_i$ 的元素 $\le s + (i+1)c - 1 < s + jc \le B_j$ 的任一元素，故 $B_i \cap B_j = \varnothing$。∎

**引理 2（计数公式正确）**：对升序数组 $A$（长度 $m$）与 $\text{lo} \le \text{hi}$，有
$$\operatorname{upper\_bound}(\text{hi}) - \operatorname{lower\_bound}(\text{lo}) = \#\{\, t \in A : \text{lo} \le t \le \text{hi} \,\}$$

**证明**：记 $L = \operatorname{lower\_bound}(\text{lo})$，它是第一个满足 $a_L \ge \text{lo}$ 的下标，由有序性，$a_0, \dots, a_{L-1} < \text{lo}$ 且 $a_L, \dots$ 中不再有小于 `lo` 的元素，故恰有 $L$ 个元素 $< \text{lo}$。记 $R = \operatorname{upper\_bound}(\text{hi})$，同理恰有 $R$ 个元素 $\le \text{hi}$。区间 $[\text{lo}, \text{hi}]$ 内的元素个数 = （$\le \text{hi}$ 的个数）−（$< \text{lo}$ 的个数）= $R - L$。∎

**引理 3（不变式）**：任意时刻，`map[name]` 都是该推文已记录时刻的一个**升序排列**，且多重性完整（同一秒的记录条数不变）。

**证明**：对操作次数归纳。初始为空数组，成立。`recordTweet` 在 `lower_bound(time)` 处插入：该位置之前的所有元素 $\le \text{time}$，之后的所有元素 $\ge \text{time}$（原本就 $\ge \text{time}$，因为它是第一个 $\ge$ 的位置），插入后仍非降序；插入没有删除任何元素，多重性只增 1，完整。查询操作只读不写，不变式显然保持。∎

**定理**：`getTweetCountsPerFrequency` 返回的数组长度为 $k$，且第 $i$ 项恰为落在第 $i$ 块内的记录条数，与题面要求一致。

**证明**：返回长度由步骤 2 构造，等于 $k = \lfloor (e-s)/c \rfloor + 1$，正是题面规定的块数（引理 1 的切分）。对第 $i$ 项：由引理 3，$A$ 是升序的完整多重集，故引理 2 适用，`ans[i]` 等于 $A$ 中落在 $[lo_i, hi_i]$ 的元素个数；又由引理 1，$[lo_i, hi_i] = B_i$ 且各块不交、覆盖整个区间，因此每块计数互不重复、也没有遗漏。若推文从未出现，$A$ 为空，所有块计数为 0，与步骤 3 的返回值一致。∎

## 6. 复杂度分析

- **时间**：
  - `recordTweet`：`lower_bound` 定位 $O(\log m)$，插入移位 $O(m)$，合计 $O(m)$，其中 $m$ 为该推文已有记录数。单条最坏 $10^4$，全部操作最坏 $O(N^2) = 10^8$ 次元素移动。
  - `getTweetCountsPerFrequency`：$k$ 块，每块两次二分 $O(\log m)$，合计 $O(k \log m)$，$k \le 167$、$m \le 10^4$，单次约 $4.7\times 10^3$ 次比较。
  - 总计 $O\bigl(N^2 + Q \cdot k \log N\bigr)$，$N, Q \le 10^4$，实测 C++ 0.11 秒、Python 0.32 秒（均为 $10^4$ 次调用的压力数据）。
- **空间**：$O(N)$。哈希表存 $N$ 个时刻（外加每个推文一个数组头），无额外辅助结构；查询结果数组 $O(k) \subseteq O(167)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class TweetCounts {
    unordered_map<string, vector<int>> data;   // 推文名 -> 升序时间数组（可重复）
public:
    TweetCounts() {}

    void recordTweet(string tweetName, int time) {
        vector<int>& a = data[tweetName];
        // 按位置插入，维持升序
        a.insert(lower_bound(a.begin(), a.end(), time), time);
    }

    vector<int> getTweetCountsPerFrequency(string freq, string tweetName,
                                           int startTime, int endTime) {
        int chunk = freq == "minute" ? 60 : (freq == "hour" ? 3600 : 86400);
        int k = (endTime - startTime) / chunk + 1;   // 块数：向下取整再加一
        vector<int> ans(k, 0);                       // 未知推文也返回 k 个 0
        auto it = data.find(tweetName);
        if (it == data.end()) return ans;
        const vector<int>& a = it->second;
        for (int i = 0; i < k; i++) {
            int lo = startTime + i * chunk;
            int hi = min(lo + chunk - 1, endTime);   // 末块截断到 endTime
            ans[i] = int(upper_bound(a.begin(), a.end(), hi) -
                         lower_bound(a.begin(), a.end(), lo));
        }
        return ans;
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right, insort
from typing import List


class TweetCounts:
    CHUNK = {"minute": 60, "hour": 3600, "day": 86400}

    def __init__(self):
        self.data = {}                      # 推文名 -> 升序时间列表（可重复）

    def recordTweet(self, tweetName: str, time: int) -> None:
        # insort 用二分找位置后插入，保持升序
        insort(self.data.setdefault(tweetName, []), time)

    def getTweetCountsPerFrequency(self, freq: str, tweetName: str,
                                   startTime: int, endTime: int) -> List[int]:
        chunk = self.CHUNK[freq]
        k = (endTime - startTime) // chunk + 1        # 块数：向下取整再加一
        ans = [0] * k                                 # 未知推文也返回 k 个 0
        a = self.data.get(tweetName)
        if not a:
            return ans
        for i in range(k):
            lo = startTime + i * chunk
            hi = min(lo + chunk - 1, endTime)         # 末块截断到 endTime
            ans[i] = bisect_right(a, hi) - bisect_left(a, lo)
        return ans
```

## 8. 边界情况与易错点

1. **区间长度恰为块长的整数倍时会多出一块**：`[0,60]` 配 `minute` 得到 2 块而不是 1 块，末块只有 `[60,60]` 一个点。凡是把块数写成 $\lceil (e-s)/c \rceil$ 的写法，都会在这里少输出一个元素。
2. **末块必须截断到 `endTime`**：`hi = min(lo + chunk - 1, endTime)`。若不截断，区间右侧之外的记录会被算进来；示例 2 的 `day` 查询里，第三块是 `[172800,172800]` 而不是不截断时的 `[172800,259199]`。
3. **未知推文要返回 $k$ 个 0**：长度由 $(\text{startTime}, \text{endTime}, \text{freq})$ 决定。返回空列表会让输出长度对不上（示例 2 的 `"y"` 那次）。
4. **同一秒的重复记录不能去重**：示例 2 里时间 0 有两条记录，`minute, [0,59]` 的输出是 2。用 `set` / `unordered_set` / `dict` 计数会得到 1。
5. **`upper_bound` 不要写成 `lower_bound`**：计数是 $\#\{\le \text{hi}\} - \#\{< \text{lo}\}$。写成 `lower_bound(hi) - lower_bound(lo)` 会漏掉恰好等于 `hi` 的记录（示例 1 的时间 60 就贴在边界上）。
6. **`startTime == endTime`**：$k = 0/c + 1 = 1$，返回单元素列表，无需特判。
7. **`freq` 是固定三个字符串**：`"minute"` / `"hour"` / `"day"`，不要写成 `"minutes"`；建议查表而不是写 `freq[0]` 之类的巧技。
8. **`endTime` 可达 $10^9$**：`lo = startTime + i*chunk` 最大约 $10^9 + 10^4$，32 位 `int` 足够（$< 2^{31}-1$），但 Python 与 C++ 都要注意别把它和「块长」混淆——块长永远只是 60/3600/86400。
9. **大量查询同一推文、区间很宽**：`minute` 时 $k = 167$，每块两次 `bisect`，单次查询约 334 次二分。若把「每块重新复制切片」写进循环，复杂度会变成 $O(k \cdot m)$ 直接崩掉。

- [LeetCode 1146. 快照数组](https://leetcode.cn/problems/snapshot-array/)：把「历史版本」压进有序数组，回答某个快照下的值。
- [LeetCode 307. 区域和检索 - 数组可修改](https://leetcode.cn/problems/range-sum-query-mutable/)：区间求和的动态版本，点更新用树状数组/线段树代替「插入后重排」。

**延伸思考**：

1. **若允许删除记录怎么办？** 有序数组的删除同样是 $O(m)$ 移位；更合适的结构是「时间坐标压缩 + 树状数组」，单点增删 $O(\log N)$、区间计数 $O(\log N)$，但要注意压缩需要先知道全部时间点（离线）。
2. **若查询次数远多于记录条数？** 例如 $10^6$ 次查询、$10^3$ 条记录，暴力 B（遍历记录按块号累加）反而更快：单次 $O(m)$ 但 $m$ 很小，且常数比二分低。**选哪种取决于 $k \log m$ 与 $m$ 的相对大小**，这正是本题「块数被 $10^4$ 的区间宽度卡住」这一约束的价值。
3. **若 `freq` 之外还要支持自定义块长？** 公式 $k = \lfloor (e-s)/c \rfloor + 1$ 与单块二分完全不变，只需把块长做成参数，代码零改动。
