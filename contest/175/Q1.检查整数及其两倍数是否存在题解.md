# LeetCode 检查整数及其两倍数是否存在 题解

## 1. 题目概述

- **标题 / 题号**：检查整数及其两倍数是否存在（#1346，easy）
- **链接**：https://leetcode.cn/problems/check-if-n-and-its-double-exist/
- **来源**：LeetCode 第 175 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、双指针、二分查找、排序

**题意**：给定整数数组 `arr`，判断是否存在**两个不同下标** $i \ne j$，使得 $arr[i] = 2 \cdot arr[j]$。注意这是一对**有方向的**关系：$arr[i]$ 必须是 $arr[j]$ 的两倍。而且 $M$ 与 $N$ 谁先出现完全任意——负数时两倍值 $2M$ 反而**更小**，值的大小顺序不能当作线索，只能靠下标区分。

**约束**：

- $2 \le arr.length \le 500$
- $-10^3 \le arr[i] \le 10^3$

数据范围很小，$O(n^2)$ 的暴力其实也能过，但本题的「配对查找」套路（一次扫描 + 哈希集合 + 双向查询）是后续很多题的地基，值得写清楚。

## 2. 示例

**示例 1**

```text
输入：arr = [10,2,5,3]
输出：true
解释：10 = 2 × 5，两个下标 0 和 2 互不相同。
```

**示例 2**

```text
输入：arr = [7,1,14,11]
输出：true
解释：14 = 2 × 7，两个下标 2 和 0 互不相同。
```

**示例 3**

```text
输入：arr = [3,1,7,11]
输出：false
解释：数组元素全是奇数，翻倍后得到 6、2、14、22，都不在数组里；它们彼此之间也不构成两倍关系。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i, j)$，$i \ne j$，检查 $arr[i] = 2 \cdot arr[j]$。比较次数是 $n(n-1)$，当 $n = 500$ 时约 $2.5 \times 10^5$，完全跑得动，这也正是本题作为签到题的宽容之处。

但暴力有两个隐患：一是数据范围一旦放大到 $10^5$ 级别就退化成 $10^{10}$，必须换法；二是**自己配自己**的边界容易被写漏——若循环写成「枚举 $i$，再枚举 $j$」却忘了 $i \ne j$，元素 $0$ 会满足 $0 = 2 \times 0$ 而误判为 true。所以「不同下标」这个条件必须显式处理，而不是靠数据的巧合。

### 3.2 核心观察：一次扫描 + 哈希集合

![一次扫描与两个查询方向](images/wc175_q1_hash_pair_model.svg)

把「在整个数组里找一对 $N = 2M$」改写为「对当前元素 $x$，问它能否与**已经扫描过的**元素配成一对」。设已扫描元素的集合为 $S$，则 $x$ 能配对当且仅当

$$2x \in S \quad \text{或} \quad \bigl(x \text{ 为偶数} \;\wedge\; x/2 \in S\bigr)$$

两个条件分别覆盖两种顺序：

- $2x \in S$：当前 $x$ 扮演 $M$（被翻倍的那个），$N = 2x$ 已经**先**出现过，例如 `arr = [14,7]`，扫到 $7$ 时 $14$ 已在集合里；
- $x/2 \in S$：当前 $x$ 扮演 $N$（两倍值），$M = x/2$ 已经**先**出现过，例如 `arr = [7,14]`，扫到 $14$ 时 $7$ 已在集合里。

> ⚠️ 「$N$ 一定比 $M$ 大」只对正数成立：$-4 = 2 \times (-2)$ 里 $-4 < -2$。所以任何基于值大小单调性的剪枝（比如排序后双指针只往一个方向找）都要重新论证，而按「已扫描集合」判定则完全不受正负影响。

因为 $S$ 只含「下标更小」的元素，一旦命中，配对的两个下标必然不同——**「不同下标」这个条件被数据结构自动满足了**，不需要额外特判。每次查询是 $O(1)$ 的哈希操作，整体 $O(n)$。

> 💡 顺序问题：`[10,2,5,3]` 中 $N = 10$ 在前、$M = 5$ 在后，必须靠「查 $x/2$」才能命中；而 `[14,7]` 这种 $N$ 在前的数组则靠「查 $2x$」兜住。只写一个方向就会漏掉一半情形。

### 3.3 算法流程

![算法流程图](images/wc175_q1_algorithm_flow.svg)

```text
1. S ← ∅（哈希集合）
2. 对 arr 从左到右的每个元素 x：
     2.1 若 2x ∈ S        → 返回 true
     2.2 若 x 是偶数且 x/2 ∈ S → 返回 true
     2.3 S.insert(x)
3. 扫完整数组仍未命中 → 返回 false
```

关键不变量：**进入第 $i$ 轮（处理 $arr[i]$）时，$S$ 恰好等于集合 $\{arr[0], \dots, arr[i-1]\}$**。因此命中时找到的搭档下标 $j < i$，天然满足 $i \ne j$。

### 3.4 示例演算

![示例走查表](images/wc175_q1_example_walkthrough.svg)

对 `arr = [10,2,5,3]`：

| $i$ | $x$ | $2x$ | $2x \in S$ | $x/2$ | $x/2 \in S$ | 动作 |
|-----|-----|------|------------|-------|--------------|------|
| 0 | 10 | 20 | 否（$S=\varnothing$） | 5 | 否 | $S = \{10\}$ |
| 1 | 2 | 4 | 否 | 1 | 否 | $S = \{10, 2\}$ |
| 2 | 5 | 10 | **是** | — | — | 返回 true（$10 = 2 \times 5$） |

再走一遍 `arr = [3,1,7,11]`：$x=3$ 只查 $6$、$x=1$ 只查 $2$（奇数不查 $x/2$）；$x=7$ 查 $14$，$7/2$ 非整数直接跳过；$x=11$ 只查 $22$。四次查询全部落空，扫完返回 false。

最后看全零的边界 `arr = [0,0]`：$i=0$ 时 $2 \times 0 = 0$ 不在空集、$0/2 = 0$ 也不在，插入 $0$；$i=1$ 时 $2 \times 0 = 0 \in S$ 命中，返回 true。而 `arr = [0,1]` 只有一次插入，查 $2 \times 0$ 时集合里没有第二个 $0$，返回 false——这正是「必须两个 0」的正确语义。

## 4. 算法细节

1. **边查边插，不能先建全量集合**：如果先把所有元素塞进集合再逐个查 $2x$，那么元素 $0$ 会与「自己」配对，`[0,1]` 会被误判为 true。一次扫描的写法里 $S$ 只含已扫描元素，语义上就对应「不同下标」。
2. **两个查询方向都要写**：$2x \in S$ 与 $x/2 \in S$ 缺一不可，前者覆盖「$N$ 先出现」，后者覆盖「$M$ 先出现」。
3. **先判偶、再做除法**：$x/2$ 只在 $x$ 为偶数时有意义。C++ 的整数除法**向零截断**（$-3/2 = -1$，集合里若恰好有 $-1$ 就会假命中），Python 的 `//` **向下取整**（$-3//2 = -2$，会凭空造出不存在的搭档）。两种语言都必须用 $x \bmod 2 = 0$ 守住除法。
4. **负数的取模**：C++ 中 $-3 \bmod 2 = -1$，所以判偶条件写成 `x % 2 == 0` 而不是 `x % 2 == 1`；后者对负奇数不成立，会漏掉奇数分支（本题该分支本来就要跳过，但写法上容易在别的题里翻车）。
5. **值域很小也不必开计数数组**：$-10^3 \le arr[i] \le 10^3$ 确实可以用长度 $2001$ 的布尔数组（下标 `v + 1000`）代替哈希表，但 $2x$ 可能达到 $2000$，查表前必须判 $2x \in [-1000, 1000]$，否则越界。哈希集合没有这个负担，代码更短。
6. **$2x$ 的溢出**：本题 $|x| \le 1000$，$2x \le 2000$，`int` 安全；若值域放宽到 $10^9$ 量级，`2 * x` 会在 `int` 上溢出，要改用 `long long` 或先判 `x > INT_MAX / 2`。
7. **提前返回**：本题只问「是否存在」，一命中就 `return true`，不需要统计对数；C++ 用 `unordered_set` 时可 `reserve(n * 2)` 减少 rehash。

## 5. 正确性证明

**引理 1（集合不变量）**：对每个 $0 \le i < n$，在处理 $arr[i]$ 之前，$S = \{arr[0], \dots, arr[i-1]\}$（重复元素按集合语义去重）。

**证明**：对 $i$ 归纳。$i = 0$ 时 $S = \varnothing$，而 $\{arr[0], \dots, arr[-1]\}$ 按约定为空集，成立。设处理 $arr[i]$ 前不变量成立：该轮只做两次查询（不改 $S$），若未返回则在末尾插入 $arr[i]$，于是处理 $arr[i+1]$ 时 $S = \{arr[0], \dots, arr[i]\}$，不变量延续。∎

**引理 2（命中即存在合法下标对）**：若算法在处理 $x = arr[i]$ 时返回 true，则存在 $j < i$ 使 $arr[i] = 2 \cdot arr[j]$ 或 $arr[j] = 2 \cdot arr[i]$，即存在满足题意的下标对。

**证明**：命中来自两条查询之一。

- 若 $2x \in S$：由引理 1，存在 $j < i$ 且 $arr[j] = 2x = 2 \cdot arr[i]$，取下标 $(j, i)$ 即满足 $arr[j] = 2 \cdot arr[i]$。
- 若 $x$ 为偶数且 $x/2 \in S$：由引理 1，存在 $j < i$ 且 $arr[j] = x/2$，即 $arr[i] = 2 \cdot arr[j]$。

两种情形都有 $j \ne i$（因为 $j < i$），故合法。∎

**引理 3（不漏解）**：若存在下标对 $i \ne j$ 使 $arr[i] = 2 \cdot arr[j]$，则算法必返回 true。

**证明**：设 $i \ne j$，令 $k = \max(i, j)$ 为较晚被扫描的下标，则 $\min(i, j) < k$，其对应元素在处理 $arr[k]$ 之前已由引理 1 进入 $S$。分两种情形：

- $k = j$（即 $j > i$）：此时 $arr[j]$ 是被翻倍的 $M$，$N = arr[i]$ 已经先出现过。处理 $arr[j]$ 时 $x = arr[j]$，有 $arr[i] \in S$，而 $arr[i] = 2 \cdot arr[j] = 2x$，故第一条查询 $2x \in S$ 命中。
- $k = i$（即 $i > j$）：此时 $arr[i]$ 是两倍值 $N$，$M = arr[j]$ 已经先出现过。处理 $arr[i]$ 时 $x = arr[i] = 2 \cdot arr[j]$，于是 $x$ 为偶数且 $x/2 = arr[j] \in S$，第二条查询命中。

两种情形算法都会在该轮返回 true。∎

**定理**：算法返回 true 当且仅当存在两个不同下标 $i \ne j$ 使 $arr[i] = 2 \cdot arr[j]$。

**证明**：充分性由引理 2（返回 true 时确有合法下标对），必要性由引理 3（有合法下标对时必返回 true）。若算法扫完返回 false，则由引理 3 的逆否命题，不存在合法下标对。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描，每轮至多两次哈希查询加一次插入，期望 $O(1)$；最坏情况（哈希退化）为 $O(n^2)$，实践中可用 `reserve` 与无碰撞的整数哈希避免。
- **空间**：$O(n)$。集合中最多保存 $n$ 个不同的值，$n \le 500$，实际占用极小。
- **对比**：暴力 $O(n^2)$ 时间 / $O(1)$ 空间；排序 + 二分 $O(n \log n)$ 时间 / $O(1)$（原地排序）或 $O(n)$ 空间，且需要额外处理「$0$ 配自己」的下标问题。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_set>
using namespace std;

class Solution {
public:
    bool checkIfExist(vector<int>& arr) {
        unordered_set<int> seen;
        seen.reserve(arr.size() * 2);
        for (int x : arr) {
            if (seen.count(2 * x)) return true;               // 2x 已出现：x 当 M
            if (x % 2 == 0 && seen.count(x / 2)) return true; // x/2 已出现：x 当 N
            seen.insert(x);
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def checkIfExist(self, arr: list[int]) -> bool:
        seen = set()
        for x in arr:
            if 2 * x in seen:                 # 之前出现过 2x：x 当 M
                return True
            if x % 2 == 0 and x // 2 in seen:  # 之前出现过 x/2：x 当 N
                return True
            seen.add(x)                       # 只把「已扫描」的元素放入集合
        return False
```

## 8. 边界情况与易错点

1. **$0$ 的自配对**：`[0,1]` 应返回 false，`[0,0]` 应返回 true。凡是「先建全量集合再查 $2x$」的写法都会把前者判成 true，必须边查边插。
2. **负数与截断除法**：`[-1,-3]` 中 $-3$ 是奇数，若 C++ 代码漏了偶数判断而直接查 `-3 / 2 = -1`，会命中集合里的 $-1$ 而误报 true。Python 里 `-3 // 2 = -2` 则可能命中幽灵值。
3. **负数两倍关系方向**：`[-4,-2]` → $-4 = 2 \times (-2)$，返回 true，命中发生在 $x=-2$（查 $2x=-4$）；`[-2,-4]` 同样返回 true，但命中发生在 $x=-4$（查 $x/2=-2$）。同一组数字换个顺序就走另一条分支，只写一个方向必然漏一半。
4. **重复元素**：`[2,2]` 返回 false —— 查 $2x=4$ 与 $x/2=1$ 都不在集合里，两个 $2$ 之间不构成两倍关系；`[2,4]` 与 `[4,2]` 都返回 true，且分别从两条不同分支命中。集合去重不影响判定，因为本题只问「是否存在」而非「有多少对」。
5. **最小规模**：$n = 2$ 的输入（如 `[1,2]`、`[0,0]`、`[3,1]`）是最容易暴露下标相等 bug 的用例，手写对拍时务必覆盖。
6. **计数数组写法的越界**：若用 $v + 1000$ 作下标，$2x = 2000$ 对应下标 $3000$，超出数组长度；查表前必须判 $2x \le 1000$ 且 $2x \ge -1000$。
7. **乘积溢出**：值域放大后 `2 * x` 可能溢出 `int`，用 `long long` 承接或先做范围判断。
