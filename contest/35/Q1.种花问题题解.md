# LeetCode 种花问题 题解

## 1. 题目概述

- **标题 / 题号**：种花问题（#605，easy）
- **链接**：https://leetcode.cn/problems/can-place-flowers/
- **来源**：LeetCode 第 35 场周赛 Q1
- **难度**：简单
- **标签**：贪心，数组

**题意**：长度为 $m$ 的花坛用数组 $flowerbed$ 表示，$0$ 是空位、$1$ 是已种花，且**已种的花互不相邻**。若再种入 $n$ 朵花后仍保持「任意两朵花不相邻」（新花不能落在已有花旁边），返回 $true$；否则返回 $false$。

**约束**：

- $1 \le m = \text{flowerbed.length} \le 2 \times 10^4$
- $flowerbed[i] \in \{0, 1\}$
- 输入保证**不存在相邻的两朵花**（即不会出现 `1,1`）
- $0 \le n \le m$

> 💡 签到题切题三句话：① 花只能种在 $0$ 上且左右都不是 $1$；② 问「能不能种够 $n$ 朵」，只关心**最大可种数**；③ $m \le 2\times 10^4$，一趟从左到右的贪心扫描就是终点。目标是两分钟零 WA，把时间留给 Q3/Q4。

## 2. 示例

**示例 1**

```text
输入：flowerbed = [1,0,0,0,1], n = 1
输出：true
解释：可以种在中间第 3 个格子（下标 2），花坛变为 [1,0,1,0,1]，仍无相邻的花。
```

**示例 2**

```text
输入：flowerbed = [1,0,0,0,1], n = 2
输出：false
解释：三个空位里最多只能新增 1 朵：下标 1 与 3 都紧贴已有的花，只有下标 2 可用。
```

**补充示例（自构造，覆盖数组边界）**

```text
输入：flowerbed = [0,0,0], n = 2
输出：true
解释：种在下标 0 与 2，得 [1,0,1]；全零数组的容量是 ⌈m/2⌉ 而非 ⌊m/2⌋。

输入：flowerbed = [0,0,1], n = 1
输出：true      （只能种下标 0，下标 1 贴着已有的花）
```

## 3. 解题思路

### 3.1 暴力思路：回溯枚举每个空位的种 / 不种

最直白的做法是回溯：对每个 $0$ 尝试「种」与「不种」，递归统计最多的合法花朵数，再与 $n$ 比较。$m = 2\times 10^4$ 时状态数是 $\Theta(\varphi^m)$ 量级，指数爆炸；而且**大量分支完全等价**——同一片连续空位里「具体种哪几个」有指数多种选择，却只对应同一个答案。这提示我们：只需求出**最大可种数**，不必枚举方案。

### 3.2 核心观察：把花坛切成零段，每段容量 = ⌈(L−b)/2⌉

![核心观察：零段容量模型](images/wc35_q1_zero_run_model.svg)

把数组按已有的花切开，得到若干个**极大连续零段**。由于输入无相邻花，两个零段之间恰好隔一朵花，因此每段的可种数相互独立，**总答案就是各段容量之和**。

对长度 $L$、两端中有 $b \in \{0,1,2\}$ 个端点紧挨着花的零段：

- 段内任意两朵新花之间至少隔一格，故新花集合在段内「隔一个取一个」；
- 贴着花的那一端的第一格/最后一格不能用，相当于可用窗口缩短 $1$；
- 于是段容量

$$\text{cap}(L,b) = \left\lceil \frac{L-b}{2} \right\rceil = \left\lfloor \frac{L-b+1}{2} \right\rfloor$$

三种形态都对得上：内部零段 $(L,b)=(3,2)$ 得 $1$；边界零段 $(2,1)$ 得 $1$；全零数组 $(3,0)$ 得 $2$。

> 💡 注意全零数组的容量是 $\lceil m/2 \rceil$（两端都没有花封路），这是本题最容易写错的公式点。

### 3.3 算法流程：贪心扫描，能种就种，种后跳 2 格

![算法流程：从左到右贪心扫描](images/wc35_q1_greedy_flow.svg)

不必真的去切段求和，一趟扫描即可：维护指针 $i$ 与已种数 $cnt$。

1. 若 $cnt \ge n$：立即返回 $true$（已经够了）；
2. 若 $i \ge m$：扫描结束，返回 $cnt \ge n$；
3. 判定第 $i$ 格能否种：$flowerbed[i] = 0$ 且左邻（或 $i=0$）为 $0$、右邻（或 $i=m-1$）为 $0$；
4. 能种则**立刻种下并写回数组**：$flowerbed[i] \gets 1$，$cnt \gets cnt+1$，然后 $i \gets i+2$——第 $i+1$ 格已被刚种的花堵死，再看只是白费；
5. 不能种则 $i \gets i+1$，继续下一格。

「能种就种」之所以不亏：把花种在更靠右的格子上，只会让它右边那格也被封死，可种数不会变多（§5 的领先引理给出严格证明）。

### 3.4 示例演算

![示例演算：flowerbed = [1,0,0,0,1]](images/wc35_q1_walkthrough.svg)

以 $flowerbed = [1,0,0,0,1]$ 走查：

| $i$ | 三格观察（左 / 本 / 右） | 判定 | 动作 | $cnt$ |
|-----|---------------------------|------|------|-------|
| 0 | $1,\ —,\ 0$ | 本身是花 | $i \gets 1$ | 0 |
| 1 | $1,\ 0,\ 0$ | 左邻是花 | $i \gets 2$ | 0 |
| 2 | $0,\ 0,\ 0$ | **可种** | 种下，$i \gets 4$ | 1 |
| 4 | $0,\ 1,\ —$ | 本身是花 | $i \gets 5$ | 1 |
| 5 | $i = m$ | 扫描结束 | 返回 $cnt \ge n$ | 1 |

种完后数组为 $[1,0,1,0,1]$，仍合法。$n=1$ 时 $1 \ge 1$ 返回 $true$（示例 1）；$n=2$ 时 $1 < 2$ 返回 $false$（示例 2）。用零段视角复核：唯一的零段是 $[1 \mid 0\,0\,0 \mid 1]$，$(L,b)=(3,2)$，容量 $\lceil 1/2 \rceil = 1$，与贪心结果一致 ✓。

## 4. 算法细节

1. **越界当成空**：判定时用 `(i == 0 || flowerbed[i-1] == 0)` 与 `(i + 1 == m || flowerbed[i+1] == 0)`，**不要**真的去访问 `flowerbed[-1]`（C++ 是未定义行为，Python 会静默取到末元素，二者都错）。等价的写法是两端各垫一个 $0$ 的哨兵数组。
2. **原地写回是关键**：种下后立刻 `flowerbed[i] = 1`，于是 $i+2$ 处的判定天然看到这朵花，无需额外状态变量；如果不允许改动输入，用一个 `prev` 记录「上一格最终是否为花」即可。
3. **跳 2 格只对「刚种下」成立**：种下后第 $i+1$ 格必被这朵花堵死，跳过它安全；但若把「不可种」也统一跳 2，就会越过一个**仍可能可种**的位置。反例 `[0,1,0,0]`：下标 0 因右邻是花而不可种，若在此跳 2 会直接漏掉唯一可种的下标 3，答案由 $true$ 变 $false$。
4. **提前返回**：`cnt >= n` 一成立就返回，最好情况 $O(1)$；另外 $n = 0$ 可在开头直接返回 $true$，省掉整趟扫描。
5. **零段计数写成一行**（不改输入的等价实现）：扫出每个零段的长度 $L$，令 $b = [i>0] + [j<m]$（$i,j$ 为段的左右开区间端点），累加 `(L - b + 1) // 2`。整数写法比浮点 `ceil` 安全，也避开了 `math.ceil` 的精度问题。
6. **上限可以提前剪枝**：全数组容量不超过 $\lceil m/2 \rceil$，若 $n > (m+1)/2$ 可直接返回 $false$（非必需，但能在极端输入上立刻收工）。
7. **不要用「数 0 的个数再除 2」这种简化**：它忽略了端点是否贴花，示例 2 与 `[1,0,1]` 都会判错——必须逐格看左右邻居。

## 5. 正确性证明

**引理 1（零段独立）**：设数组按已有的花切成极大零段 $Z_1, \dots, Z_k$。则最大可新增花数等于各段容量之和。

**证明**：两个相邻零段之间恰好隔着**一朵**已种的花（至少隔一朵由极大性保证；无相邻花保证不会隔两朵）。该花本身不能再种，且它分别封死左右两段各自紧邻的一格，两段在它两侧的可用位置互不重叠、互不约束，故一个合法方案可按段拆分，各段的最优选择可直接拼接，总数即各段最大值之和。∎

**引理 2（零段容量）**：长度 $L$、两端有 $b$ 端紧挨着花的零段内，最多新种 $\lceil (L-b)/2 \rceil$ 朵，且能取到。

**证明**：把段内位置编号 $1..L$，$b$ 端被封等价于可用窗口为形如 $[1+r_{\text{left}},\, L-r_{\text{right}}]$ 的连续整数区间，长度 $M = L-b$。设新花位置 $s_1 < \dots < s_t$，相邻新花至少隔一格，故 $s_t - s_1 \ge 2(t-1)$；又 $s_t - s_1 \le M-1$，于是 $2(t-1) \le M-1$，即 $t \le \lceil M/2 \rceil$，给出上界。取 $s = 1+r_{\text{left}},\, 3+r_{\text{left}},\, \dots$ 恰好是 $\lceil M/2 \rceil$ 个两两间隔 $2$、且都落在窗口内的位置，与已有的花也都不相邻，故上界可取到。∎

**引理 3（贪心领先）**：设贪心在某零段内种下的位置依次为 $g_1 < g_2 < \dots$，任意合法方案在该段内为 $o_1 < o_2 < \dots$，则对一切 $k$ 有 $g_k \le o_k$。

**证明**：对 $k$ 归纳。$k=1$：$g_1$ 是段内第一个合法位置，任何合法方案的首朵只能不早于它，$o_1 \ge g_1$。设 $g_{k-1} \le o_{k-1}$，则 $o_k \ge o_{k-1} + 2 \ge g_{k-1} + 2$，故 $o_k$ 距 $g_1, \dots, g_{k-1}$ 均至少 $2$，对贪心来说它也是「$g_{k-1}$ 之后、与已有花相容」的候选位置；贪心取这类位置中最靠左者，故 $g_k \le o_k$。∎

**定理（算法正确性）**：扫描结束后 $cnt \ge n$ 当且仅当可以种入 $n$ 朵花。

**证明**：*合法*：贪心只在三格皆空时落花，且从不移动已有的花，故每一步后数组仍无相邻花。*最优*：由引理 3，贪心在每个零段内种下的朵数不少于任何合法方案在该段的朵数，累加后 $cnt$ 等于总容量；再由引理 1、引理 2，总容量就是全局最大可种数。因此 $cnt \ge n$ 等价于存在合法方案种入 $n$ 朵。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m)$。指针 $i$ 严格单调递增，每格至多被判定一次（种下时跳 2 格只会更少）；提前返回可把最好情况降到 $O(1)$，最坏仍为 $O(m)$。
- **空间复杂度**：$O(1)$ 额外空间。只用了 $i$、$cnt$ 两个变量，且直接原地复用了输入数组；若题目禁止修改输入，才需要 $O(m)$ 的拷贝（或 $O(1)$ 的 `prev` 状态）。
- **常数**：每格三次比较、无函数调用与递归，$m = 2\times10^4$ 时耗时在微秒级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canPlaceFlowers(vector<int>& flowerbed, int n) {
        int m = flowerbed.size();
        if (n == 0) return true;                 // 一朵都不种，永远可行
        int cnt = 0;
        for (int i = 0; i < m; ++i) {
            if (flowerbed[i] == 1) continue;     // 本身是花：只能走 1 格
            bool leftEmpty  = (i == 0)     || flowerbed[i - 1] == 0;
            bool rightEmpty = (i + 1 == m) || flowerbed[i + 1] == 0;
            if (leftEmpty && rightEmpty) {
                flowerbed[i] = 1;                // 原地种下，后续判定可见
                if (++cnt >= n) return true;     // 够了立刻收工
                ++i;                             // 配合循环自增，共跳 2 格
            }
        }
        return cnt >= n;
    }
};
```

### Python

```python
class Solution:
    def canPlaceFlowers(self, flowerbed: List[int], n: int) -> bool:
        if n == 0:
            return True
        m, cnt, i = len(flowerbed), 0, 0
        while i < m:
            if (flowerbed[i] == 0
                    and (i == 0 or flowerbed[i - 1] == 0)
                    and (i + 1 == m or flowerbed[i + 1] == 0)):
                flowerbed[i] = 1          # 种下
                cnt += 1
                if cnt >= n:              # 提前返回
                    return True
                i += 2                    # 下一格必被堵死，跳 2 格
            else:
                i += 1
        return cnt >= n
```

## 8. 边界情况与易错点

1. **$n = 0$**：任何花坛都返回 $true$，含 `[1]`、`[1,0,1]` 这类「一朵也塞不下」的输入——忘记特判会让 `[1]` 配 $n=0$ 的用例在部分写法下判错。
2. **长度为 1**：`[0]` 配 $n=1$ 应为 $true$；若边界判定写成 `i > 0 && ...` 与 `i < m-1 && ...` 的「必须两侧都存在」形式，会漏掉这个用例。
3. **全零数组**：容量是 $\lceil m/2 \rceil$。`[0,0,0]` 能种 $2$ 朵，`[0,0]` 只能种 $1$ 朵——用 $\lfloor m/2 \rfloor$ 会少算奇数长度的情况。
4. **下标越界**：C++ 访问 `flowerbed[-1]` 是未定义行为（可能读到垃圾值而偶然 AC，也会在越界检查下崩溃）；Python 的 `flowerbed[-1]` 会静默取到最后一个元素，产生**看似合理但错误**的结果，更难查。
5. **「跳 2 格」的触发条件**：只有**刚刚种下**时才跳 2；不可种时必须老老实实走 1 格。写成「每轮固定 `i += 2`」会把 `[0,1,0,0]` 判成 $false$（正确答案是 $true$，种在下标 3）。
6. **输入被破坏**：原地修改会让同一数组无法二次调用。若评测在同一个进程里跑多组、或多个测试共享数组，应拷贝一份或改用 `prev` 状态，避免「第二问答案莫名变小」。
7. **$n$ 的规模**：约束保证 $n \le m$，但 $n$ 大于实际容量时靠 `cnt >= n` 自然返回 $false$，无需额外开数组计数。
8. **别用浮点取整**：`ceil((L - b) / 2)` 在部分语言里要先转浮点，直接用整数 `(L - b + 1) // 2` 更稳。
