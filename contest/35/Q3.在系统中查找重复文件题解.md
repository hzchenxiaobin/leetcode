# LeetCode 在系统中查找重复文件 题解

## 1. 题目概述

- **标题 / 题号**：在系统中查找重复文件（#609，medium）
- **链接**：https://leetcode.cn/problems/find-duplicate-file-in-system/
- **来源**：LeetCode 第 35 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、字符串

**题意**：给定字符串数组 `paths`，每条描述一个目录及其全部文件，格式为 `"dir f1(c1) f2(c2) ... fn(cn)"`（`dir` 与文件信息之间是**单个空格**，每个文件写成 `文件名(内容)`）。把**内容完全相同**的文件按内容分组，输出每组所有文件的完整路径 `目录/文件名`；只有一个文件的组不输出，组内与组间顺序任意。

**约束**：

- $1 \le \lvert paths \rvert \le 2\times10^4$，$1 \le \lvert paths[i] \rvert \le 3000$
- $\sum_i \lvert paths[i] \rvert \le 5\times10^5$（总字符数是本题真正的规模）
- 字符集：英文字母、数字、`/`、`.`、`(`、`)`、空格
- 同一目录内无重名文件或子目录；每条信息对应唯一目录
- 输出组内顺序、组间顺序均任意（按集合比较）

## 2. 示例

**示例 1**

```text
输入：paths = ["root/a 1.txt(abcd) 2.txt(efgh)",
              "root/c 3.txt(abcd)",
              "root/c/d 4.txt(efgh)",
              "root 4.txt(efgh)"]
输出：[["root/a/2.txt","root/c/d/4.txt","root/4.txt"],
       ["root/a/1.txt","root/c/3.txt"]]
解释：内容 efgh 被 3 个文件共享，内容 abcd 被 2 个文件共享，各自成组。
```

**示例 2**

```text
输入：paths = ["root/a 1.txt(abcd) 2.txt(efgh)",
              "root/c 3.txt(abcd)",
              "root/c/d 4.txt(efgh)"]
输出：[["root/a/2.txt","root/c/d/4.txt"],
       ["root/a/1.txt","root/c/3.txt"]]
解释：少了 root/4.txt，efgh 组只剩 2 个文件，仍然满足「至少两个」的判定。
```

**示例 3（自造边界：无重复）**

```text
输入：paths = ["root/a 1.txt(abcd) 2.txt(efgh)"]
输出：[]
解释：每个内容都只出现一次，没有任何重复组；注意返回空列表而不是 [[]]。
```

## 3. 解题思路

### 3.1 暴力思路

先解析出所有 `(路径, 内容)` 对，再两两比较内容：设文件数 $F$、单次内容比较代价 $O(L)$，总代价 $O(F^2 \cdot L)$。$F$ 由 $2\times10^4$ 条信息承载，可达数万，$F^2$ 已是 $10^8\sim10^9$ 量级，再乘字符串比较必然超时。更麻烦的是「同内容」具有传递性：若 A 与 B 相同、B 与 C 相同，三者必须合并成**一组**，两两比较后还要再做一个「合并等价类」的后处理，代码量和出错概率都高。

### 3.2 核心观察：内容就是天然的哈希键

![解析一条目录信息：目录 dir + 文件名 + 括号内内容](images/wc35_q3_parse_concept.svg)

「内容完全相同」是一个**等价关系**（自反、对称、传递）。等价关系不需要两两比较——只要用「键 → 属于该键的所有元素」的哈希表，扫描一遍就能完成分组：把 `content` 当 key、把完整路径追加进 value，结束后 value 大小 $\ge 2$ 的桶就是答案。

内容总量只有 $\sum_i \lvert paths[i] \rvert \le 5\times10^5$ 个字符，因此**直接把完整内容当 key** 完全放得下，既不用哈希摘要，也不用担心碰撞误报。

> 💡 这道题唯一的「坑」在解析而不是算法：文件名和内容都可能含空格，所以内容边界必须用括号 `(` `)` 定界，而不能用空格切分。

### 3.3 算法流程

![一次扫描完成分组：内容作 key，路径追加进 value](images/wc35_q3_hash_group_flow.svg)

1. 外层遍历 `paths` 中的每条字符串 `info`；
2. 用 `find(' ')` 定位**第一个空格**，其左即目录 `dir`（目录名不含空格）；
3. 内层从该空格出发循环：跳过空格 → 读到 `'('` 得到文件名 `name` → 读到 `')'` 得到内容 `content`；
4. 执行 `groups[content].push_back(dir + "/" + name)`；
5. 全部扫描结束后，收集所有 `size >= 2` 的桶作为答案。

内层用下标 `i` 表示「当前待跳过的空格位置」：每轮先 `i += 1`，解析完一个文件后令 `i = close + 1`，它恰好落在下一个空格或串尾，所以 `while i < n` 能自然终止。

### 3.4 示例演算

![示例 1 走查：五个文件按内容落进两个桶](images/wc35_q3_example_walkthrough.svg)

示例 1 的 5 个文件解析结果如下：

| 目录 | 文件名 | 内容 | 拼出的路径 |
|------|--------|------|------------|
| root/a | 1.txt | abcd | root/a/1.txt |
| root/a | 2.txt | efgh | root/a/2.txt |
| root/c | 3.txt | abcd | root/c/3.txt |
| root/c/d | 4.txt | efgh | root/c/d/4.txt |
| root | 4.txt | efgh | root/4.txt |

得到两个桶：`abcd → {root/a/1.txt, root/c/3.txt}`、`efgh → {root/a/2.txt, root/c/d/4.txt, root/4.txt}`，二者大小都 $\ge 2$，全部输出，与官方答案一致。

## 4. 算法细节

1. **目录边界**：第一个空格左侧一定是完整目录路径（目录与文件信息之间只有单个空格，目录名不含空格），所以 `find(' ')` 一次定位即可，不需要额外校验。
2. **内层指针推进**：`i = close + 1` 后正好指向下一个文件前的空格；若该文件是行内最后一个，`i == n`，循环退出。写成 `while (i + 1 < n)` 之类的变体容易漏掉最后一个文件。
3. **key 用完整内容**：总字符数 $\le 5\times10^5$，直接以 `std::string` / `str` 作键，空间安全且没有碰撞风险；哈希表只在解析时按内容长度做一次哈希，总代价线性。
4. **路径拼接只加一个斜杠**：`dir` 本身不以 `/` 结尾（`"root"`、`"root/a"`），统一写 `dir + "/" + name`；不要对根目录特判，也不要拼两个斜杠，否则会输出 `root//4.txt`。
5. **value 必须是容器**：同一内容可能有 3 个以上文件，必须用 `vector<string>` / `list` 追加；若只记录「首次出现的路径」，三分组会被截成两个。
6. **输出过滤**：只把 `size >= 2` 的桶放进答案；`size == 1` 的桶代表唯一文件，不属于重复文件。组内、组间顺序任意，不必排序。
7. **C++ 细节**：`unordered_map<string, vector<string>>` 配 `reserve(paths.size() * 4)` 降低 rehash；`groups[content]` 一次查找同时完成「无则插入空数组」。
8. **Python 细节**：用 `dict` + `setdefault`（或 `defaultdict(list)`）；切片 `info[i:op]` 每个字符只会被复制常数次，总代价仍为 $O(S)$。

## 5. 正确性证明

**引理 1（解析正确）**：对每个文件，算法取出的 `dir`、`name`、`content` 与其在 `info` 中的真实值一致，且所有文件被处理恰好一次。

**证明**：`info` 形如 `dir␣f1(c1)␣f2(c2)…`。第一个空格左侧只含目录字符（目录名不含空格），故 `dir` 取得完整目录。此后每个文件块都由「空格 + 文件名 + `(` + 内容 + `)`」构成：空格之后到第一个 `(` 之间的字符正是文件名（文件名不含 `(`），该 `(` 到最近的 `)` 之间的字符正是内容（内容不含 `)`——括号本身就是格式里的分隔符，否则整串无法唯一解析）。因此每轮恰好消费一个文件块，且 `i = close + 1` 指向下一块的开头空格或串尾，按序推进不重不漏。∎

**引理 2（分组精确）**：扫描结束后，对任意内容 $c$，`groups[c]` 恰好等于「内容为 $c$ 的所有文件的完整路径」构成的集合。

**证明**：由引理 1，每个文件（路径 $p$、内容 $c$）都被处理恰好一次，并执行一次 `groups[c].push_back(p)`；而 $p$ 由 `dir + "/" + name` 唯一确定（同一目录内文件名不重复 ⇒ 路径不重复）。所以 $c$ 的桶恰为 $\{p \mid \text{content}(p)=c\}$，既不缺也不多。∎

**引理 3（输出判定精确）**：算法输出的组集恰好等于题面定义的「重复文件组」集。

**证明**：
- ($\Leftarrow$) 若内容 $c$ 被至少 2 个文件共享，由引理 2 有 $\lvert \text{groups}[c] \rvert \ge 2$，该桶被收集输出。
- ($\Rightarrow$) 若某桶 `groups[c]` 因大小 $\ge 2$ 被输出，由引理 2 其中每个路径对应的文件内容都为 $c$，即组内文件两两内容完全相同、路径互不相同，符合「至少两个内容完全相同的文件」的定义。∎

**定理**：算法返回的列表恰为所有重复文件组，无遗漏、无多余、无重复。

**证明**：桶与内容一一对应（哈希表键唯一），故不同桶对应不同内容、彼此不重复；由引理 3，被输出的桶恰为重复组，未被输出的桶或大小不足 2、或本就不重复。又由引理 1、2，每个文件只入桶一次，所以组内路径不重复。综上，输出恰为全部重复文件组。∎

## 6. 复杂度分析

- **时间**：$O(S)$，其中 $S = \sum_i \lvert paths[i] \rvert \le 5\times10^5$。解析阶段每个字符只被访问常数次；哈希表对每个 `content` 计算一次哈希，所有内容长度之和 $\le S$；拼接路径、收集桶同样是线性。哈希冲突带来的额外字符串比较在期望意义下可视为摊销 $O(S)$。
- **空间**：$O(S)$。键是各文件的完整内容（总长 $\le S$），value 是各文件的完整路径（总长 $\le S$），答案直接复用这些路径字符串，没有额外的大结构。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<string>> findDuplicate(vector<string>& paths) {
        unordered_map<string, vector<string>> groups;   // content -> 路径列表
        groups.reserve(paths.size() * 4);

        for (const string& info : paths) {
            size_t sp = info.find(' ');                 // 目录与文件信息的分界
            if (sp == string::npos) continue;           // 防御：只有目录、没有文件
            string dir = info.substr(0, sp);            // 目录名不含空格

            size_t i = sp, n = info.size();
            while (i < n) {
                ++i;                                    // 跳过空格
                size_t open  = info.find('(', i);
                string name  = info.substr(i, open - i);            // 空格后 ~ '('
                size_t close = info.find(')', open);
                string content = info.substr(open + 1, close - open - 1); // '(' ~ ')'
                groups[content].push_back(dir + "/" + name);
                i = close + 1;                          // 下一个空格或串尾
            }
        }

        vector<vector<string>> ans;
        for (auto& [content, bucket] : groups)
            if (bucket.size() > 1) ans.push_back(bucket);   // 单文件不算重复
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findDuplicate(self, paths: list[str]) -> list[list[str]]:
        groups: dict[str, list[str]] = {}
        for info in paths:
            sp = info.find(' ')                 # 目录与文件信息的分界
            if sp < 0:                          # 防御：只有目录、没有文件
                continue
            directory = info[:sp]               # 目录名不含空格
            i, n = sp, len(info)
            while i < n:
                i += 1                          # 跳过空格
                op = info.find('(', i)
                name = info[i:op]               # 文件名：空格后 ~ '('
                cl = info.find(')', op)
                content = info[op + 1:cl]       # 内容：'(' ~ ')'
                groups.setdefault(content, []).append(directory + '/' + name)
                i = cl + 1                      # 下一个空格或串尾
        return [bucket for bucket in groups.values() if len(bucket) > 1]
```

## 8. 边界情况与易错点

1. **根目录拼接**：`"root 4.txt(efgh)"` 中目录就是 `root`（$m=0$），答案路径是 `root/4.txt`；若对根目录特判或重复加斜杠就会输出 `root//4.txt`。
2. **内容含空格**：`"root/a 1.txt(a b c) 2.txt(x)"` 若按空格切 token 会得到 `1.txt(a`、`b`、`c)` 三个碎片，key 全错。必须用括号定界——这是本题最容易被构造数据打穿的地方。
3. **无重复文件**：返回 `[]`，不是 `[[]]`、也不是含单元素组的列表；空内容 `name()` 也是合法 key，别假设 `content[0]` 存在。
4. **三个及以上同内容**：value 必须用数组追加，不能只保存「首次出现的路径」。
5. **不要拿文件名或整条 `info` 当 key**：key 只能是内容，否则 `a.txt(x)` 与 `b.txt(x)` 会被误判为不同，`abcd` 与 `efgh` 又会因目录相同被误合并。
6. **指针越界**：`info.find(' ')` 返回 `npos` 时若直接 `substr` 会抛异常/越界；解析循环里 `find('(')`、`find(')')` 也应假定格式合法但保留 `continue` 防御。
7. **对拍时先归一化**：组内与组间顺序任意，本地比较前要对每组排序、再对组排序，否则会被「顺序不同」的假 WA 误导。
