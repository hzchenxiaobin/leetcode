# LeetCode 标签验证器 题解

## 1. 题目概述

- **标题 / 题号**：标签验证器（#591，hard）
- **链接**：https://leetcode.cn/problems/tag-validator/
- **来源**：LeetCode 第 35 场周赛 Q4
- **难度**：困难
- **标签**：栈，字符串

**题意**：给定一段代码片段 `code`，判断它是否**恰好是一个合法闭合标签**。闭合标签形如 `<NAME>内容</NAME>`，`NAME` 只能由 1~9 个大写字母组成；内容里可以放普通文本、嵌套的合法闭合标签，以及 `<![CDATA[...]]>`。`CDATA` 内部一律按普通字符处理、不参与解析。

**约束**：

- $1 \le \lvert \texttt{code} \rvert \le 500$
- `code` 只含英文字母、数字与 `<`、`>`、`/`、`!`、`[`、`]`、`.`、空格

**两条最容易漏掉的规则**：规则 6 要求见到 `<` 或 `</` 后**直到下一个 `>` 的全部字符**整体当作 `TAG_NAME` 判定（哪怕含空格、`!`、`[`）；规则 1 要求整串**恰好**是一个闭合标签，标签外不得有任何字符（含空白），也不得有第二个根标签。

## 2. 示例

**示例 1**

```text
输入：code = "<DIV>This is the first line <![CDATA[<div>]]></DIV>"
输出：true
解释：整体被 <DIV>…</DIV> 包裹；CDATA 内的 <div> 名字非法且未闭合，但它不参与解析，故内容合法。
```

**示例 2**

```text
输入：code = "<DIV>>>  ![cdata[]] <![CDATA[<div>]>]]>]]>>]</DIV>"
输出：true
解释：CDATA 段是 <![CDATA[<div>]>]]>，其内容 "<div>]>"（第一个 ]]> 就结束）；剩余 "]]>>]" 是普通文本。
```

**示例 3**

```text
输入：code = "<A>  <B> </A>   </B>"
输出：false
解释：扫描到 </A> 时栈顶是 B，名字不同 ⇒ 交叉嵌套，非法。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是「先把 `code` 切成一堆候选标签，再回溯尝试所有嵌套解释」，最坏是指数级；即使不回溯，单纯数括号也会漏掉两类关键点：`CDATA` 内部必须整段跳过，标签名必须以 `>` 为界、不能「贪心截取大写前缀」。正则同样无能为力：规则 6 让名字边界依赖最近的 `>`，规则 7/8 又让 `CDATA` 内部失去语法意义，回溯与正则都会在这两处失控。本题真正的难点不是规模（$n \le 500$），而是**规则多且互相牵制**；正确姿势是把每条规则落成一个确定性判断，用「一遍扫描 + 栈」做到 $O(n)$。

### 3.2 核心观察：括号匹配 + 两个特例

![合法片段的语法模型](images/wc35_q4_grammar_model.svg)

把文法写出来就很清楚：

$$\text{code} = \langle name\rangle\; C\; \langle /name\rangle,\qquad C \to (\text{text} \mid \text{closed} \mid \text{cdata})^{*}$$

其中 $name \in [\text{A-Z}]^{1..9}$。三点观察决定了整个算法：

1. **嵌套 = 括号匹配**：起始标签是左括号、结束标签是右括号，是否「同名」只需和栈顶比较，交叉嵌套自然被拦住。
2. **CDATA 是黑洞**：`<![CDATA[` 到**第一个** `]]>` 之间全部跳过，所以示例 2 里的 `<div>]>` 不会污染栈，`]]>` 之后残留的 `]]>>]` 也照常当文本。
3. **名字边界由 `>` 决定**：`<` 或 `</` 之后到下一个 `>` 的字符**整体**就是 `TAG_NAME`，不合法立即 false，绝不「取前缀再试」。于是每个位置只有唯一一种解释，扫描无需回溯。

### 3.3 算法流程

![单遍扫描的四个分支](images/wc35_q4_stack_scan.svg)

用栈 `st` 保存**尚未闭合**的标签名，指针 `i` 从左到右推进：

1. 若 `code[0] != '<'`，直接返回 false（规则 1）。
2. 循环 `i < n`，**按顺序**判断四种情况：
   - **以 `<![CDATA[` 开头**：栈空则 false（规则 4：cdata 只能在标签内）；找第一个 `]]>`，令 `i` 跳到其后；找不到则 false。
   - **以 `</` 开头**：读到下一个 `>`，其间字符为名字；名字非法、或栈空、或与栈顶不同名 → false；否则弹栈。**弹栈后若栈空，必须 `i == n`**。
   - **以 `<` 开头**：读到下一个 `>` 取名字；名字非法 → false；否则入栈。
   - **其他（文本）**：栈空 → false；否则跳到下一个 `<`（没有则跳到 `n`）。
3. 循环结束，要求 `st` 为空。

判断顺序不能乱：`<![CDATA[` 必须先于 `<`，`</` 也必须先于 `<`，否则两者都会被当成「名字非法的起始标签」。

### 3.4 示例演算

![示例 2 的逐步走查](images/wc35_q4_example_walkthrough.svg)

以示例 2 为例（$n = 50$）：

| 步 | i | 片段 | 动作 | 栈 |
|----|---|------|------|----|
| 1 | 0 | `<DIV>` | 名字 `DIV` 合法 → 入栈 | `[DIV]` |
| 2 | 5 | `>>  ![cdata[]] ` | 文本，`>` 只是普通字符 → 跳到 20 | `[DIV]` |
| 3 | 20 | `<![CDATA[<div>]>]]>` | 首个 `]]>` 在下标 36 → `i = 39`，内容 `<div>]>` 是黑盒 | `[DIV]` |
| 4 | 39 | `]]>>]` | 文本 → 下一个 `<` 在下标 44 | `[DIV]` |
| 5 | 44 | `</DIV>` | 与栈顶同名 → 弹栈，`i = 50 = n` | `[]` |
| 6 | 50 | — | 栈空且串已耗尽 → 返回 `true` | `[]` |

再对照示例 3：`i` 走到 `</A>`（下标 9）时栈顶为 `B`，名字不符 → 立即 false。

## 4. 算法细节

1. **名字取到下一个 `>`**：`find('>', j)` 一次定位，中间不裁剪、不过滤，这是规则 6 的直接落地；分支顺序固定为 `<![CDATA[` → `</` → `<` → 文本，保证 `</` 不被误判为起始标签。
2. **名字合法性**：`1 <= len(name) <= 9` 且每个字符都在 `A`~`Z`。别用 Python 的 `str.isupper()`：`"1".isupper()` 为 False 看着还行，但 `"Ä".isupper()` 为 True，约束虽只给英文字母，显式区间最稳。
3. **根标签唯一性**：只在「弹栈后栈空」处检查一次 `i == n`，即可同时排除 `<A></A>x`、`<A></A><B></B>`、`x<A></A>`。
4. **CDATA 只在标签内**：文本分支和 cdata 分支都要求栈非空，这是「标签外不得有内容」的另一半。
5. **文本里的 `>`、`]`、`!` 都是普通字符**：只有 `<` 会触发解析，这是示例 2 能通过的原因。
6. **跳转用 `find` 而不是逐字符循环**：每段 token 只被扫一次，配 `i = npos ? n : pos` 收尾，避免 `npos + 1` 的越界写法；栈里只存名字，长度 ≤ 9，比较与拷贝都是常数级。

## 5. 正确性证明

**引理 1（名字提取与规则 6 一致）**：在任意扫描位置，若 `code[i] = '<'`，则算法取出的名字恰为 `<`（或 `</`）与**其后第一个** `>` 之间的全部字符。

**证明**：`read_tag` 用 `find('>', j)` 取第一个 `>`，名字即 `code[j..k)`；这正好是规则 6 要求的「直到下一个 `>` 的所有字符」。若不存在 `>`，返回失败，对应规则 6 的「`<` 未匹配」。∎

**引理 2（栈义不变式）**：循环的任意时刻，栈自底向上恰为「当前已经开启、尚未闭合」的标签名序列；且每个已闭合标签的内容都已被完整扫描。

**证明**：初始栈空，成立。起始标签分支唯一地 push 一个名字；结束标签分支只有在与栈顶同名时才 pop，说明它闭合的正是最近一个未闭合标签（后开先闭）；弹栈后该标签内容区间已被扫完。文本与 cdata 分支不改变栈。故不变式保持。∎

**引理 3（CDATA 黑洞）**：cdata 分支的行为与规则 7、8 一致——内容区间为 `<![CDATA[` 之后到第一个 `]]>` 之间的字符，且其中任何字符都不影响栈与后续判断。

**证明**：分支用 `find("]]>", i + 9)` 取第一个结束标记，正是规则 7 的定义；跳过后直接从 `]]>` 之后继续，内部字符从未进入任何判断分支，符合规则 8。∎

**引理 4（解释唯一 / 无回溯）**：对任意前缀，`i` 处的解释由 `code` 在 `i` 处的固定前缀唯一决定，算法不会做出需要撤销的选择。

**证明**：`i` 处要么以 `<![CDATA[` 开头，要么以 `</` 开头，要么以 `<` 开头，要么是普通字符，四类互斥；前三类的结束位置分别由第一个 `]]>`、第一个 `>` 唯一确定，文本的结束位置由下一个 `<` 唯一确定。故每步唯一，且 `i` 严格增大。∎

**定理**：算法返回 true 当且仅当 `code` 合法。

**证明**：（⇒）设返回 true。由引理 4 扫描全程无回溯，每个 token 都被完整消费；结束时栈空且 `i = n`，说明每个 push 都被同名 pop 成对抵消，即所有标签都闭合、且整体只有一个根标签覆盖全串（弹栈后栈空即刻要求 `i == n`）。由引理 2，嵌套满足后开先闭；由引理 1、3，名字与 cdata 的判定符合规则 3、6、7、8。文本只出现在栈非空处，故无标签外的裸文本，也未出现未匹配的 `<`（否则 `read_tag` 已判 false），逐条对照规则 1~8 均成立。（⇐）设 `code` 合法，对文法结构归纳：外层必为一对同名标签（规则 1、2），算法在 `i = 0` 处 push、在内层内容结束后遇到同名结束标签并 pop，其间内容按归纳假设被正确消费；合法内容中的文本只含非 `<` 字符或在 cdata 内，被文本 / cdata 分支整段跳过；cdata 由引理 3 处理；无标签外字符，故弹栈后 `i = n`，最终栈空返回 true。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`i` 严格递增，文本段、标签段、cdata 段互不重叠，`find` 的扫描长度总和为 $O(n)$；名字合法性检查总长度也是 $O(n)$（名字被 `>` 截断，天然有界）。
- **空间**：$O(n)$。栈最多保存 $\lfloor n/3 \rfloor$ 个名字（每个标签至少占 3 字符），每个名字长度 ≤ 9，故为 $O(n)$；其余只是若干下标变量。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
using namespace std;

class Solution {
public:
    bool isValid(string code) {
        int n = (int)code.size(), i = 0;
        vector<string> st;
        if (n == 0 || code[0] != '<') return false;
        auto validName = [](const string& s) {
            if (s.empty() || s.size() > 9) return false;
            for (char c : s)
                if (c < 'A' || c > 'Z') return false;
            return true;
        };
        // 从 j 开始到下一个 '>' 之间的全部字符即 TAG_NAME（题面规则 6）
        auto readTag = [&](size_t j, string& name, size_t& next) -> bool {
            size_t k = code.find('>', j);
            if (k == string::npos) return false;
            name = code.substr(j, k - j);
            if (!validName(name)) return false;
            next = k + 1;
            return true;
        };
        while (i < n) {
            if (code.compare(i, 9, "<![CDATA[") == 0) {
                if (st.empty()) return false;            // cdata 必须在标签内
                size_t j = code.find("]]>", i + 9);
                if (j == string::npos) return false;     // 未闭合
                i = (int)(j + 3);                        // 整段跳过，内部不解析
            } else if (code.compare(i, 2, "</") == 0) {
                string name; size_t nx;
                if (!readTag(i + 2, name, nx)) return false;
                if (st.empty() || st.back() != name) return false;
                st.pop_back();
                i = (int)nx;
                if (st.empty() && i != n) return false;  // 根标签闭合后不得再有内容
            } else if (code[i] == '<') {
                string name; size_t nx;
                if (!readTag(i + 1, name, nx)) return false;
                st.push_back(name);
                i = (int)nx;
            } else {
                if (st.empty()) return false;            // 标签外的裸文本非法
                size_t j = code.find('<', i);
                i = (j == string::npos) ? n : (int)j;
            }
        }
        return st.empty();
    }
};
```

### Python

```python
class Solution:
    def isValid(self, code: str) -> bool:
        n = len(code)
        stack = []

        def valid_name(name: str) -> bool:
            return 1 <= len(name) <= 9 and all('A' <= c <= 'Z' for c in name)

        def read_tag(j: int):
            """从 j 读到下一个 '>'，其间全部字符即 TAG_NAME（规则 6）。"""
            k = code.find('>', j)
            if k < 0: return None
            name = code[j:k]
            if not valid_name(name): return None
            return name, k + 1

        if n == 0 or code[0] != '<': return False
        i = 0
        while i < n:
            if code.startswith('<![CDATA[', i):
                if not stack: return False             # cdata 只能在标签内部
                j = code.find(']]>', i + 9)
                if j < 0: return False                 # 未闭合
                i = j + 3                              # 整段跳过，内部不解析
            elif code.startswith('</', i):
                res = read_tag(i + 2)
                if res is None: return False
                name, i = res
                if not stack or stack[-1] != name: return False   # 交叉嵌套 / 多余结束标签
                stack.pop()
                if not stack and i != n: return False  # 根标签之外还有内容
            elif code[i] == '<':
                res = read_tag(i + 1)
                if res is None: return False
                name, i = res
                stack.append(name)
            else:
                if not stack: return False             # 标签外的裸文本
                j = code.find('<', i)
                i = n if j < 0 else j

        return not stack
```

## 8. 边界情况与易错点

![合法与非法写法对照](images/wc35_q4_pitfalls.svg)

1. **空内容合法**：`<A></A>` 返回 true，不要把 TAG_CONTENT 要求成非空。
2. **根标签唯一**：`<A></A><B></B>`、`<A></A>x`、`x<A></A>` 全部 false，靠「弹栈后栈空 ⇒ `i == n`」和「文本分支要求栈非空」两处共同拦住。
3. **名字含空格或符号**：`<A >`、`<A/></A>`、`<!X>` 都是非法名字（分别是空格、`/`、`!`），必须整段判定，不能只检查首字母。
4. **名字长度上限 9**：`<AAAAAAAAA></AAAAAAAAA>` 合法，`<AAAAAAAAAA></AAAAAAAAAA>` 非法，边界取 `<= 9`。
5. **CDATA 未闭合**：`<A><![CDATA[x]]</A>` 中找不到 `]]>`，必须 false；注意 `<A><![CDATA[x</A>` 也是 false（两者都没闭合）。
6. **CDATA 的结束是第一处 `]]>`**：示例 2 的 `<div>]>` 里虽然已经有 `]>`，但只有 `]]>` 才算结束，答案是「抄近路」时最容易写错的一处。
7. **`<` 未匹配**：`<A>abc` 在文本分支跳到 `n` 后结束，栈非空 → false；`<A` 则在 `read_tag` 内找不到 `>` → false。
8. **`>` 与 `]` 在文本里合法**：`<A>>>>]]</A>` 返回 true，不要把它们当成结构字符。
