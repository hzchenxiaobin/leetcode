# LeetCode 移除字符串中的尾随零 题解

## 1. 题目概述

- **标题 / 题号**：移除字符串中的尾随零（#2710，easy）
- **链接**：https://leetcode.cn/problems/remove-trailing-zeros-from-a-string/
- **来源**：LeetCode 第 347 场周赛 Q1
- **难度**：简单
- **标签**：字符串、双指针、模拟

**题意**：给你一个字符串表示的正整数 `num`，返回去掉**尾随零**（末尾连续的 `0`）之后的字符串。全程以字符串处理，不能改变数值大小。

**约束**：

- `1 <= num.length <= 1000`
- `num` 仅由数字 `0` 到 `9` 组成
- `num` 不含前导零

> 💡 **签到题的关键点**只有两个：① 尾随零的定义是"末尾**连续**的零段"，中间的 `0`（如 `512301` 中的 `0`）不能删；② 读完约束——**正整数 + 无前导零** ⇒ 串中至少有一位非零字符，扫描必然停在合法位置，结果非空。

## 2. 示例

**示例 1**

```text
输入：num = "51230100"
输出："512301"
解释：整数 "51230100" 有 2 个尾随零，移除后返回 "512301"。
```

**示例 2**

```text
输入：num = "123"
输出："123"
解释：整数 "123" 不含尾随零，原样返回。
```

**示例 3（自拟，覆盖"内部零"与"末尾多个零"）**

```text
输入：num = "1000"
输出："1"
解释：末尾 3 个 0 全部是尾随零；首位的 '1' 之后没有别的非零字符。
```

**示例 4（自拟，覆盖"无尾零但仍含零"）**

```text
输入：num = "105"
输出："105"
解释：末位是 '5' 而非 '0'，没有任何尾随零，"10" 中间的 '0' 不能删。
```

## 3. 解题思路

### 3.1 暴力思路：转整数再转回来

直接 `stoi(num)` 转成 `int`，再转回字符串，整数的标准表示天然没有尾随零。

**问题**：`num.length` 最大 1000 位，远超 64 位整数上限（约 19 位），**大整数会溢出**；用高精度/大数库又完全是大炮打蚊子。这题从头到尾就该是**纯字符串操作**。

### 3.2 核心观察：尾随零是"末尾连续零段"，删除不改变数值

设 `num` 末尾有 $k$ 个连续的 `0`，其前缀为 $P$（$P$ 的末位非零），则：

$$\text{num} = P \times 10^k$$

删掉这 $k$ 个零得到 $P$，数值不变，且 $P$ 末位非零、不含尾随零——这正是答案。所以问题归结为一句话：**从右往左找到第一个非 `'0'` 字符的位置 `i`，返回 `num[0..i]`**。

![尾随零概念：末尾连续零段删除后数值不变](images/wc347_q1_trailing_zeros_concept.svg)

### 3.3 算法流程：从右向左扫描

![从右向左扫描找第一个非零字符的流程](images/wc347_q1_trailing_zeros_scan.svg)

```
1. 置指针 i = n − 1（最后一个字符）
2. 循环：当 i >= 0 且 num[i] == '0' 时，i = i − 1
3. 返回 num[0..i]（前 i+1 个字符）
```

由约束"正整数、无前导零"保证循环必在某个 `i >= 0` 处停下（`num[i] != '0'`），**不会把串删空**。

### 3.4 示例演算

以 `num = "51230100"`（`n = 8`）为例：

| 步骤 | i | num[i] | 是否为 '0' | 动作 |
|------|---|--------|------------|------|
| 初始 | 7 | '0' | 是 | 左移 |
| 2 | 6 | '0' | 是 | 左移 |
| 3 | 5 | '1' | **否** | 停止，返回 `num[0..5]` |

结果：`"512301"`。中间 `num[4] = '0'`（`51230` 的 `0`）从未被扫描触及，天然保留。

## 4. 算法细节

1. **扫描方向**：必须**从右往左**。尾随零的定义锚定在末尾，从左往右扫描无法知道一个 `0` 后面是否还有非零字符。
2. **停止条件**：`num[i] != '0'` 即停。此时 `num[0..i]` 是原串去掉**恰好全部**尾随零的前缀——多停一位就留了尾零，少停一位就误删了非零字符（不可能发生，因为只删 `'0'`）。
3. **各语言的现成 API**（比赛时直接用，省打字）：
   - Python：`num.rstrip('0')`——删除**右侧**全部指定字符，与题意严丝合缝；
   - C++：`num.substr(0, num.find_last_not_of('0') + 1)`——`find_last_not_of` 找最后一个非 `'0'` 位置 `i`，取前 `i+1` 个字符；
   - Java：`num.replaceAll("0+$", "")` 或手写倒序扫描。
4. **为什么不需要担心删空**：`rstrip` / 手写循环在**全零串**（如 `"000"`）上会返回空串。但本题约束排除该输入：正整数无前导零，若所有位都是 `0`，唯一可能是 `"0"`，而 `0` 不是正整数。这是**约束替我们兜住的边界**。

## 5. 正确性证明

**引理 1（无尾零表示）**：设 `num` 末尾有 $k \geq 0$ 个连续的 `0`，去掉它们后的前缀为 $P$（读数为 $P$，末位非零），则 `num` 所表示的整数 $N = P \times 10^k$，且 $P$ 正是 $N$ 的不含尾随零的十进制写法。

**证明**：`num` 的字符形态是 $P$ 的十进制串后接 $k$ 个 `0`，由十进制按位展开即得 $N = P \times 10^k$。又尾零段取极大性 ⇒ $P$ 末位非零 ⇒ $10 \nmid P$，即 $P$ 本身不含尾随零；$P$ 是把 $N$ 连续除以 $10$ 直到不再整除所得，故 $P$ 是 $N$ 的无尾零写法 □

> 💡 换句话说：题目要的不是"算出一个新数"，而是**同一整数的另一种写法**——$N = P \times 10^k$ 的无尾零写法唯一地为 $P$。

**引理 2（算法终止且结果非空）**：约束下从右往左的扫描必停在某个 `i >= 0` 且 `num[i] != '0'` 的位置。

**证明**：`num` 是正整数的无前导零写法。若所有字符均为 `'0'`，则该串要么是 `"0"`（表示零，非正整数，违反题设），要么有前导零（违反约束）。故至少存在一位非零字符，扫描至多越过末尾零段后必遇到非零字符终止，结果 `num[0..i]` 非空且末位非零 □

**定理（正确性）**：算法输出为 `num` 所表示整数的**唯一**不含尾随零的字符串表示。

**证明**：记末尾连续零段长度为 $k$（由串唯一决定，故 $k$ 唯一）。扫描恰好跨过这 $k$ 个零、停在第 $k+1$ 位的非零字符上（该位非零由连续段极大性保证），因此输出恰为前缀 $P$。由引理 1，$P$ 是同一整数的无尾零写法；由引理 2，$P$ 末位非零、首段保留，即 $P$ 不含尾随零。唯一性：若 $P'$ 是同一整数的任一无尾零写法，由十进制表示唯一性 $P' = P$（位数不同则数值不同）∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$，其中 $n = \text{num.length}$。最坏情况约一半字符是尾零（如 `"1000...0"`），扫描指针从 $n-1$ 走到第一个非零位；构造答案串 $O(n)$。$n \leq 1000$，毫秒级。
- **空间复杂度**：$O(n)$。答案串需要 $O(n)$ 空间（C++ `substr` / Python 切片都会新分配）；若语言支持原地截断（如 C++ `resize`），可做到除输出外 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string removeTrailingZeros(string num) {
        // 找最后一个非 '0' 字符的位置 i，取前 i+1 位
        int i = num.find_last_not_of('0');
        return num.substr(0, i + 1);
    }
};
```

手写倒序扫描版（等价）：

```cpp
class Solution {
  public:
    string removeTrailingZeros(string num) {
        int i = num.size() - 1;
        while (i >= 0 && num[i] == '0') {
            i--;
        }
        num.resize(i + 1); // 原地截断，除输出外 O(1) 额外空间
        return num;
    }
};
```

### Python

```python
class Solution:
    def removeTrailingZeros(self, num: str) -> str:
        return num.rstrip('0')
```

等价手写版：

```python
class Solution:
    def removeTrailingZeros(self, num: str) -> str:
        i = len(num) - 1
        while num[i] == '0':
            i -= 1
        return num[:i + 1]
```

## 8. 边界情况与易错点

1. **不要转数值类型**：`num` 最长 1000 位，任何整数类型都装不下，`int`/`long long` 直接溢出。本题是纯字符串题。
2. **只删末尾连续零，不删中间零**：`"51230100"` 中下标 4 的 `'0'` 必须保留。错误写法：`num.replace("0", "")`、`num.strip('0')`（`strip` 还会误删前导零，本题虽无前导零，但语义上仍是错的）。
3. **全零输入不存在**：正整数 + 无前导零 ⇒ 至少一位非零。Python `rstrip('0')` 对全零串会返回 `""`，但本题约束兜底；若题目改约束（允许 `num = "0"`），`rstrip` 会返回空串而出错，需特判 `return num if num.rstrip('0') == '' else ...` 这类防御。
4. **C++ `find_last_not_of` 返回 `string::npos` 的陷阱**：全零串时它返回 `npos`（极大值），`substr(0, npos + 1)` 溢出回绕后恰好取全长——碰巧不崩但逻辑错。本题约束下不触发，但要知道这个坑。
5. **返回的是同一个数，不是"数的阶乘/变化后的数"**：审题别串台成"去掉零后的数值是多少"，全程字符串进出。
6. **周赛实战**：签到题追求零调试，Python 一行 `rstrip('0')` 最稳；C++ 用 `find_last_not_of` 一行同理。
