# LeetCode 使所有字符相等的最小成本 题解

## 1. 题目概述

- **标题 / 题号**：使所有字符相等的最小成本（#2712，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-make-all-characters-equal/
- **来源**：LeetCode 第 347 场周赛 Q3
- **难度**：中等
- **标签**：贪心、字符串、动态规划

**题意**：给定下标从 0 开始、长度为 $n$ 的二进制字符串 `s`，可以任意多次执行两种操作：

1. 选下标 $i$，反转 $s[0..i]$（含两端）的所有字符，成本 $i+1$；
2. 选下标 $i$，反转 $s[i..n-1]$（含两端）的所有字符，成本 $n-i$。

返回使所有字符**相等**的**最小**总成本。

**约束**：

- $1 \le n \le 10^5$
- `s[i]` 为 `'0'` 或 `'1'`

> 💡 读题先抓两点：① 前缀翻转 × 后缀翻转可以任意叠加，直觉上「最优操作序列」难以构造；② 答案上界不小（见 §8 溢出分析），累加器别用 `int`。本题另有[每日题解 2712](../../solution/2701-2800/2712_使所有字符相等的最小成本.md)（含官方 hint 前后缀 DP 的完整代码），与本文互为印证；本文按周赛复盘主线，从「边界」视角一步到位推出贪心公式，并给出完整证明。

## 3. 解题思路

### 3.1 暴力思路：状态图最短路

把每个长度为 $n$ 的 01 串看作图上的一个点，两种操作（各 $n$ 种参数）是 $2n$ 条带权有向边，问题就是从 `s` 到「全 0 / 全 1」的单源最短路。状态数 $2^n$，$n \le 10^5$ 时是天文数字，彻底不可行。

难在**操作相互纠缠**：先翻前缀再翻后缀，中间一段被翻了两次，每一步操作都改变后续所有操作的「落点」，看不出任何最优子结构；硬要 DP，状态里至少得带着整条串，这正是 $2^n$ 的来源。而「每步挑当前最便宜的操作」这类局部贪心也没有最优性保障——除非先看到下文的**边界独立性**。

### 3.2 核心观察：把「串」压缩成「边界」

![核心观察：每种操作恰好只切换一个边界](images/wc347_q3_boundary_concept.svg)

定义**边界** $j$（$0 \le j \le n-2$）为 $s[j]$ 与 $s[j+1]$ 之间的位置，称 $s[j] \ne s[j+1]$ 的边界为**差异边界**。

**观察 1**：串均匀 $\iff$ 不存在差异边界。这就是「所有字符相等」的逐位刻画。

**观察 2（关键）**：无论当前串长什么样，一次操作**恰好切换一个边界**的好坏状态：

- 操作① 翻转 $[0..i]$：内部边界（$j < i$）两侧**同翻**、外部边界（$j > i$）两侧**都不翻**，差异状态一概不变；唯独 $j = i$ 处一侧翻一侧不翻，被切换；
- 操作② 翻转 $[i..n-1]$：同理，唯一被切换的是 $j = i-1$。

于是「切换边界 $j$」有且只有两种**单价**：操作① 取 $i = j$（花 $j+1$），或操作② 取 $i = j+1$（花 $n-j-1$）。**每个边界是一个独立的开关**，问题从「整条串上的操作序列」坍缩成「逐差异边界选便宜的开关」：

$$\text{answer} \;=\; \sum_{\substack{0 \le j \le n-2 \\ s[j] \ne s[j+1]}} \min\big(j+1,\;\; n-1-j\big)$$

> 💡 一句话：前缀/后缀翻转看似互相搅局，其实每次都只拨动**翻转端点处**的那一个开关；开关彼此独立，各自按最低价买单。

### 3.3 算法流程

![算法流程：一次遍历，逐差异边界累加最小单价](images/wc347_q3_algorithm_flow.svg)

```text
1. ans = 0
2. for j = 0 .. n-2:
3.     if s[j] != s[j+1]:  ans += min(j+1, n-1-j)
4. 输出 ans
```

### 3.4 示例演算

![示例 2 演算：逐边界取 min 累加](images/wc347_q3_example_walkthrough.svg)

以**示例 2**（`s = "010101"`，$n = 6$）为例：5 个边界全是差异边界，逐个取单价（见上图表格），总成本 $1+2+3+2+1 = 9$，与官方答案一致 ✓。注意单价呈**金字塔**——两条单价之和恒为 $n$，$\min$ 自动选短的一段：靠左的边界前缀短、靠右的边界后缀短。

## 4. 算法细节

1. **对应关系别对错下标**：切换边界 $j$ 的两种方式分别是操作①（$i = j$，成本 $j+1$）与操作②（$i = j+1$，成本 $n-j-1$）。操作②的下标是 $j+1$ 而不是 $j$——统一用边界下标 $j$ 表达成 $\min(j+1,\, n-1-j)$ 最不易错。
2. **与最终目标无关**：目标是全 0 还是全 1，需要切换的边界集合完全相同（把串按位取反，差异边界集合不变），公式无需枚举目标字符。
3. **与操作顺序无关**：由独立性，各边界互不干扰，公式直接给出总成本，无需真正构造操作序列。
4. **无需模拟翻转**：题目只问最小成本、不问方案，按公式累加即可，连翻转后的串都不用维护。
5. **溢出**：最坏情况（交替串）答案 $\approx n^2/4$，$n = 10^5$ 时约 $2.5 \times 10^9$，超过 `int` 上界 $2.1 \times 10^9$，C++ 累加器必须 `long long`（题目返回类型已经在提醒）。

## 5. 正确性证明

**引理 1（均匀的边界刻画）**：任意时刻的串 $t$ 所有字符相等，当且仅当每个边界 $j$ 都满足 $t[j] = t[j+1]$。

**证明**：若所有字符相等，则任意相邻两位相等，必要性显然。反之 $t[0]=t[1],\ t[1]=t[2],\ \dots,\ t[n-2]=t[n-1]$ 沿链传递得 $t[0]=t[1]=\dots=t[n-1]$ ∎

**引理 2（操作只切换一个边界）**：对当前串 $t$ 执行翻转区间 $[l, r]$（两端含）后，边界 $j$ 的「$t[j] \ne t[j+1]$」状态改变，当且仅当 $j = r$ 或 $j = l-1$。特别地：操作①（$l = 0$）只切换边界 $i$；操作②（$r = n-1$）只切换边界 $i-1$。

**证明**：记位置 $p$ 是否被翻转的指示量为 $f(p) \in \{0,1\}$。翻转后边界 $j$ 的差异状态改变 $\iff f(j) \ne f(j+1)$ $\iff$ $j$ 与 $j+1$ **恰有一个**落在 $[l, r]$ 内 $\iff$ 区间右端点卡在两者之间（$j = r$）或左端点卡在两者之间（$j = l-1$）。操作① $l = 0$ 时 $j = -1$ 不是合法边界，故只切换 $j = i$；操作② $r = n-1$ 时 $j = n-1$ 不是合法边界，故只切换 $j = i-1$ ∎

**定理（贪心公式最优）**：最小成本 $= \displaystyle\sum_{j:\ s[j] \ne s[j+1]} \min(j+1,\; n-1-j)$。

**证明**：

（上界）对每个初始差异边界 $j$，执行两种方式中较便宜的那个。由引理 2，这些操作恰好把各自的边界切换一次，且**不影响任何其他边界**；于是初始非差异边界保持好、差异边界全部变好，由引理 1 终串均匀。总成本即公式右端。

（下界）任取一组合法的操作序列。由引理 2，每次操作恰好切换一个边界，把序列按「被切换的边界」分组。对每个初始差异边界 $j$，由引理 1 它最终必须变好，故被切换奇数次、至少 1 次；而能切换 $j$ 的操作只有操作①（$i=j$）与操作②（$i=j+1$）两种，单次成本至少 $\min(j+1,\, n-1-j)$。分组求和，总成本 $\ge$ 公式右端。

上界与下界夹逼，得证 ∎

**推论**：答案与操作执行顺序无关；与最终目标是全 0 还是全 1 无关。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单次遍历 $n-1$ 对相邻字符，每对 $O(1)$ 判断与累加，一遍扫完。
- **空间复杂度**：$O(1)$。仅一个累加器，无任何数据结构；官方 hint 的前后缀 DP 需要 $O(n)$ 空间，贪心公式把它压成了一遍扫描。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minimumCost(string s) {
        int n = s.size();
        long long ans = 0;
        for (int j = 0; j + 1 < n; j++) {
            if (s[j] != s[j + 1]) {
                ans += min(j + 1, n - 1 - j);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, s: str) -> int:
        n = len(s)
        ans = 0
        for j in range(n - 1):
            if s[j] != s[j + 1]:
                ans += min(j + 1, n - 1 - j)
        return ans
```

## 8. 边界情况与易错点

1. **溢出（最常见 WA 点）**：交替串 `0101...` 的答案约 $n^2/4$；$n = 10^5$ 时为 $2.5 \times 10^9$，超 `int` 上界。C++ 用 `long long`，Python 天然大数无虞。
2. **n = 1**：没有边界，答案 0；循环条件 `j + 1 < n` 天然不执行，无需特判。
3. **已经全部相等**：无差异边界，答案 0，公式自动给出。
4. **操作②的下标错位**：切换边界 $j$ 对应操作②取 $i = j+1$、成本 $n-j-1$；若误写成 $\min(j+1,\, n-j)$ 会把部分成本抬高。用边界下标 $j$ 统一表达可避免。
5. **别去构造操作序列**：独立性与顺序无关意味着公式直接可算；赛场上硬去逐个模拟翻转，既费时又容易把下标翻乱。
6. **想当然的局部贪心**：不基于边界独立性、直接「每步挑当前最便宜的操作」没有最优性保障——先证独立性，贪心才立得住。
7. **不必分目标计算**：无需分别算「变全 0」「变全 1」再取 min——两者的差异边界集合相同，答案相同。
8. **赛场验证技巧**：公式没把握时，写个 $O(2^n \cdot n \log)$ 的 Dijkstra 对小 $n$（$n \le 12$）全枚举对拍，几分钟即可锁定正确性。

**延伸思考**：

- **官方 hint 的前后缀 DP**：定义 `prefix[i]` 为使 $s[0..i-1]$ 全部等于 $s[i]$ 的最小成本，则 `prefix[i] = prefix[i-1] + (s[i-1] != s[i] ? i : 0)`；后缀对称递推；答案 $= \min_i(\text{prefix}[i] + \text{suffix}[i])$。展开递推式后，每个差异边界恰好贡献一次 $\min(j+1,\, n-1-j)$，与贪心公式等价（完整代码见[每日题解 2712](../../solution/2701-2800/2712_使所有字符相等的最小成本.md)）。DP 是没看到独立性时的保底路线，贪心是它的化简。
- **变体：任意区间翻转**：若操作改为「翻转任意区间 $[l, r]$，成本 $r-l+1$」，则一次操作切换**两个**边界（$l-1$ 与 $r$，贴边时退化为一个，本题的两种操作正是贴边特例），独立性被打破，问题升级为差异边界的**配对覆盖**——最优解如何配对值得动手推一推。
- **变体：一般成本函数**：把两种单价换成任意函数 $f(j+1)$ 与 $g(n-1-j)$，独立性不变，公式仍逐边界取 $\min(f, g)$——「边界开关」模型比具体的成本形式更本质。
