# LeetCode 矩阵中严格递增的单元格数 题解

## 1. 题目概述

- **标题 / 题号**：矩阵中严格递增的单元格数（#2713，hard）
- **链接**：https://leetcode.cn/problems/maximum-strictly-increasing-cells-in-a-matrix/
- **来源**：LeetCode 第 347 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、记忆化搜索、排序、矩阵

**题意**：给定大小为 $m \times n$ 的整数矩阵 $\text{mat}$，选任一单元格作为起点。每次可以从当前单元格跳到**同一行或同一列**中的任何其他单元格，前提是目标值**严格大于**当前值；如此反复直到无路可跳。求从最优起点出发最多能访问的单元格数量。

**约束**：

- $1 \le m, n \le 10^5$
- $1 \le m \cdot n \le 10^5$
- $-10^5 \le \text{mat}[i][j] \le 10^5$

> 💡 读题先抓三点：① 「同行或同列」意味着一步可以跳到**任意远**的格子，转移天然是大范围的；② 值**严格**递增保证路径无环，天然可 DP；③ $m \cdot n \le 10^5$ 但 $m$、$n$ **各自**可达 $10^5$，任何「逐格扫整行整列」的转移都会退化到 $10^{10}$。本题另有[每日题解 2713](../../solution/2701-2800/2713_矩阵中严格递增的单元格数.md)（map 分桶 + 两阶段 DP 完整代码，附面试问答），与本文互为印证；本文按周赛复盘主线，从「建图最长路」的朴素模型出发，重点补齐**状态方向辨析**与**两阶段批量转移**的完整证明。

## 3. 解题思路

### 3.1 暴力思路：建图最长路

把每个格子看成一个节点，若格子 $y$ 与 $x$ 同行或同列且值严格更大，就连一条有向边 $x \to y$，问题是整张图的**最长路径**。

- 直接 DFS 枚举所有跳法不记忆，路径组合是指数级；
- 即使记忆化，单个格子的转移仍要**扫整行整列**找更大的格子，单格 $O(m+n)$，总计 $O\big(mn \cdot (m+n)\big)$；当 $m = 1,\ n = 10^5$ 时高达 $10^{10}$，超时；
- 显式建图更不可行：边数本身就是 $O\big(mn(m+n)\big)$ 级别，$10^{10}$ 条边连存都存不下。

难点在于：**转移范围大（同行同列任意远）**，但只允许「跳向严格更大的值」这一规则还没被利用。

### 3.2 核心观察：值严格递增 ⇒ 按值升序，转移只需行列最优

![核心观察：路径值严格递增，按值升序处理，转移只需行列最优值](images/wc347_q4_row_col_best_concept.svg)

**观察 1（按值分层，天然无环）**：任何合法路径上的值**严格递增**。把格子按值升序排序后，路径只能自小到大走——这是一个天然的 DAG，按值从小到大**顺序填表**即可，既无环也无需递归。

**观察 2（转移只需汇总值）**：定义 $g(i,j)$ 为**以** $(i,j)$ **结尾**的合法路径的最长长度。它的前驱只有两类：同行中值更小的格子、同列中值更小的格子——而转移只关心每类前驱中 $g$ 的**最大值**。于是为每行、每列各维护一个汇总变量：

- $\text{rowBest}[i]$：行 $i$ 中**已处理**格子的 $g$ 最大值；
- $\text{colBest}[j]$：列 $j$ 中**已处理**格子的 $g$ 最大值。

转移从「扫整行整列」压到 $O(1)$：

$$g(i,j) = 1 + \max\big(\text{rowBest}[i],\ \text{colBest}[j]\big)$$

**升序处理的妙处**：算到 $(i,j)$ 时，「已处理」恰好等于「值更小」恰好等于「合法前驱」，两个 best 正是它需要的全部转移信息；值更大的格子还没算，而它们本来就不该参与。

> 💡 一句话：值严格递增给了**处理顺序**（升序填表无环），「转移只取 max」给了**数据结构**（每行每列各一个变量）——两者合起来把 $O(m+n)$ 的单格转移压成 $O(1)$。

### 3.3 算法流程：等值分批、两阶段回写

![易错点：同值格子必须整批算完再整批写](images/wc347_q4_equal_value_batch.svg)

还差最后一环：题目要求**严格**大于，同值格子**不能出现在同一条路径里**。若排序后逐格「边算边写」，处理完一个值为 $v$ 的格子立即回写，同行/同列的另一个同值格就会读到刚写入的值，错误地「接上」同值前驱。正确做法是**同值整批处理、两阶段回写**：

```text
1. 把全部格子 (值, i, j) 排序：值升序，同值自然相邻成批
2. rowBest[0..m-1] = 0，colBest[0..n-1] = 0，ans = 0
3. 从小到大逐「同值批」处理：
   阶段一（算）：批内每个 (i,j) 用旧 best 求 g = 1 + max(rowBest[i], colBest[j])，顺手更新 ans
   阶段二（写）：批内全部算完后，统一回写 rowBest[i] / colBest[j]
4. 输出 ans
```

反例实测：`mat = [[1,1],[1,1]]`，两阶段得 `ans = 1` ✓；若边算边写，同行同值连环借力，会算出 `3` ✗（正确答案 1）。

### 3.4 示例演算

![示例 3 演算：按值升序逐批推进，行列汇总层层抬升](images/wc347_q4_example_walkthrough.svg)

以**示例 3**（`mat = [[3,1,6],[-9,5,7]]`）为例，六个值互不相同、每批一格：−9、1 两个最小值各自孤立得 $g=1$；3 与 5 分别接上同列/同行的历史最优得 $g=2$；6 接上行 0 的最优得 $g=3$ 并把 $\text{colBest}[2]$ 抬到 3；7 再接上得 $g=4$ ⭐。逐批演算见上图，最终答案 4，对应路径 $-9 \to 3 \to 6 \to 7$。

## 4. 算法细节

1. **状态方向辨析**：本文定义 $g$ 为「以 $(i,j)$ **结尾**」，前驱是**值更小**的格子，自然配合**升序**处理；对称地也可以定义 $f$ 为「从 $(i,j)$ **出发**」、后继是值更大的格子、按值**降序**处理——两者互为路径反转，对全体格子取 max 后答案相同。考场选「结尾 + 升序」最顺：迭代填表、无需递归。
2. **两种成批方式**：① 把 $(\text{值}, i, j)$ 排成一个扁平数组，排序后同值自然相邻，用双指针定位批（本文 C++/Python 的写法）；② 按值 `map`/`dict` 分桶再按 key 升序遍历（[每日题解 2713](../../solution/2701-2800/2713_矩阵中严格递增的单元格数.md) 的写法）。两者等价，注意**遍历容器必须按值有序**（C++ 用 `map`/排序数组而非 `unordered_map`，Python 对 `dict` 的 key 先 `sorted`）。
3. **坐标编码**：C++ 里可以把 $(i,j)$ 编码为 $i \cdot n + j$ 存进 `pair<值, 编码>`，排序一次完成；解码 `i = id / n`、`j = id % n`。
4. **best 初值为 0**：约定 $\max \varnothing = 0$，即「没有更小前驱」时 $g = 1$（只访问自己），无需特判。
5. **ans 更新时机**：在阶段一顺手 `ans = max(ans, g)`，不必等全部批结束再扫一遍。

## 5. 正确性证明

**引理 1（同值不同路）**：任何合法路径上的格子值严格递增；特别地，一条路径中每个取值至多出现一个格子。

**证明**：移动规则要求目标值严格大于当前值，沿路径归纳即得值逐位严格递增。若路径先后经过同值的两个格子，则后者须严格大于前者，与同值矛盾 ∎

**引理 2（结尾态递推）**：设 $g(i,j)$ 为以 $(i,j)$ 结尾的合法路径的最长长度，则

$$g(i,j) = 1 + \max\Big(\{0\} \cup \{\,g(i,y) : \text{mat}[i][y] < \text{mat}[i][j]\,\} \cup \{\,g(x,j) : \text{mat}[x][j] < \text{mat}[i][j]\,\}\Big)$$

且所求答案 $= \max_{i,j} g(i,j)$。

**证明**：以 $(i,j)$ 结尾的最长路径若长度为 $1$，右端空集取 $0$；若长度大于 $1$，去掉最后一格，剩余部分是以某个**同行或同列**且**值严格更小**的格子 $(i,y)$ 或 $(x,j)$ 结尾的合法路径。反之，任何以值更小的同行/同列格子结尾的合法路径都能再接上 $(i,j)$ 一步。两方向合起来，$g(i,j)$ 恰为 $1 + $（合法前驱的 $g$ 最大值）。又任何合法路径都有结尾格，答案为全体 $g$ 的最大值 ∎

**定理（两阶段批量转移的正确性）**：将全部格子按值升序排序、同值归为一批；批内先用旧 $\text{rowBest}/\text{colBest}$ 整批计算、再整批回写。如此算出的每个 $g(i,j)$ 与引理 2 的定义一致。

**证明**：对批的序号归纳。初始时 best 全为 $0$，恰为空集上的最大值。设第 $t$ 批（值为 $v$）处理之前，$\text{rowBest}[i]$、$\text{colBest}[j]$ 分别等于「值 $< v$ 的已处理格子中行 $i$、列 $j$ 上 $g$ 的最大值」（空集为 0）。批内格子 $(i,j)$ 的合法前驱只能来自值 $< v$ 的同行/同列格子——同值格互非前驱（引理 1），更大值的格子尚未处理且本就不是前驱——而它们全部属于前 $t-1$ 批且已算出真值，由归纳假设，$1 + \max(\text{rowBest}[i], \text{colBest}[j])$ 恰为引理 2 的右端。批内格子两两不能互接，故先算谁都只读旧 best；两阶段保证批内的写入不污染同批的读取。整批回写后，best 覆盖到「值 $\le v$」的全部格子，归纳推进至第 $t+1$ 批 ∎

**推论**：算法返回值 $= \max g$ = 所求最大访问单元格数。

## 6. 复杂度分析

- **时间复杂度**：$O\big(mn \log(mn)\big)$。排序 $mn$ 个格子主导；随后每个格子仅 $O(1)$ 转移与回写，全体扫一遍 $O(mn)$。
- **空间复杂度**：$O(mn)$ 存排序数组，加 $O(m+n)$ 的 `rowBest`/`colBest`；不需要显式 dp 矩阵，组内 $g$ 用临时数组即弃。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxIncreasingCells(vector<vector<int>>& mat) {
        int m = mat.size(), n = mat[0].size();
        vector<pair<int, int>> cells;                 // (值, 编码 i*n+j)
        cells.reserve((size_t)m * n);
        for (int i = 0; i < m; ++i)
            for (int j = 0; j < n; ++j)
                cells.emplace_back(mat[i][j], i * n + j);
        sort(cells.begin(), cells.end());             // 值升序，同值相邻成批

        vector<int> rowBest(m, 0), colBest(n, 0);
        int ans = 0, N = m * n;
        for (int k = 0; k < N;) {
            int t = k;                                // 定位同值批 [k, t)
            while (t < N && cells[t].first == cells[k].first) ++t;

            vector<pair<int, int>> computed;           // 阶段一：整批先用旧 best 算
            for (int p = k; p < t; ++p) {
                int i = cells[p].second / n, j = cells[p].second % n;
                int g = 1 + max(rowBest[i], colBest[j]);
                computed.emplace_back(g, cells[p].second);
                ans = max(ans, g);
            }
            for (auto& [g, id] : computed) {           // 阶段二：整批算完再统一写
                rowBest[id / n] = max(rowBest[id / n], g);
                colBest[id % n] = max(colBest[id % n], g);
            }
            k = t;
        }
        return ans;
    }
};
```

### Python

```python
from itertools import groupby

class Solution:
    def maxIncreasingCells(self, mat: List[List[int]]) -> int:
        m, n = len(mat), len(mat[0])
        cells = sorted((v, i, j) for i, row in enumerate(mat) for j, v in enumerate(row))

        row_best = [0] * m
        col_best = [0] * n
        ans = 0
        for _, group in groupby(cells, key=lambda c: c[0]):   # 按值分批
            done = []                                        # 阶段一：整批先用旧 best 算
            for _, i, j in group:
                g = 1 + max(row_best[i], col_best[j])
                done.append((g, i, j))
                ans = max(ans, g)
            for g, i, j in done:                             # 阶段二：整批算完再统一写
                if g > row_best[i]:
                    row_best[i] = g
                if g > col_best[j]:
                    col_best[j] = g
        return ans
```

## 8. 边界情况与易错点

1. **等值不分批（最高频 WA）**：排序后边算边写，同值且同行/同列的格子会互相借力。`[[1,1],[1,1]]` 会算出 `3`（本机实测），正确为 `1`。务必把「计算」与「回写」拆成两个循环。
2. **全等值 / 单格**：答案 1，`best` 初值 0 自动兜底，无需特判。
3. **单行或单列**：可跳到任意远格，答案 = 该行（列）**不同值的个数**，而非最长连续递增段——用 `[[2,1,3,2]] → 3` 校验实现对「远跳」的处理是否正确。
4. **别显式建图**：邻接边 $O\big(mn(m+n)\big)$ 条，$10^{10}$ 级别直接爆内存；转移必须隐式（读 best 汇总值）。
5. **Python 别写递归记忆化**：$mn$ 达 $10^5$，链状数据的递归深度可达 $10^5$，默认递归上限 1000 必爆栈；升序迭代填表天然无此问题。
6. **无序容器的遍历顺序**：`unordered_map`/`dict` 必须先按 key 排序再遍历，否则「已处理 = 值更小」被破坏。
7. **溢出无忧**：答案 $\le mn \le 10^5$，`int` 足够——与同场 Q3 必须开 `long long` 形成对照。
8. **状态方向别混**：定义「结尾」就配升序、前驱取更小值；定义「出发」就配降序、后继取更大值。混搭（如「结尾」配降序）会让 best 汇总到尚未处理的方向，逻辑直接崩塌。

**延伸思考**：

- **输出具体方案**：在阶段一为每个格子记录 $\arg\max$ 前驱（来自行最优还是列最优、具体哪一格），结束后从 $\arg\max_g$ 回溯即可还原路径，复杂度不变。
- **桶排优化**：值域仅 $[-10^5, 10^5]$，可用 $2 \times 10^5$ 个桶按值直接分批，把排序的 $O(mn \log mn)$ 降为 $O(mn + V)$。
- **非严格变体（≥ 且访问格互不相同）**：同值格可以互跳后，「同值批内互不借用」的前提失效——批内还需按行/列再做链式传递（同值且同行/同列的格子能互相延长），两阶段技巧不足以直接套用，值得动手重新设计。
- **记忆化 DFS 的对称写法**：定义 $f(i,j)$ 为「从 $(i,j)$ 出发」的最长访问数，按值**降序**批量处理、维护行列最优，与本文互为路径反转——可作为赛场上的交叉验证手段。
