# LeetCode 设计任务管理器 题解

## 1. 题目概述

- **标题 / 题号**：设计任务管理器（#3408，medium）
- **链接**：https://leetcode.cn/problems/design-task-manager/
- **来源**：LeetCode 第 147 场双周赛 Q2
- **难度**：中等
- **标签**：设计、哈希表、有序集合、堆（优先队列）

**题意**：维护一个任务系统，每个任务由三元组 $(\text{userId}, \text{taskId}, \text{priority})$ 描述，同一个用户可以拥有多个任务，`taskId` 全局唯一。需要支持：

- `add(userId, taskId, priority)`：新增任务（保证 `taskId` 不存在）；
- `edit(taskId, newPriority)`：修改已存在任务的优先级（保证存在）；
- `rmv(taskId)`：删除任务（保证存在）；
- `execTop()`：执行**优先级最高**的任务，优先级并列时执行 `taskId` **最大**的那个，执行后从系统中删除并返回其 `userId`；系统为空返回 $-1$。

**约束**：

- $1 \le \text{tasks.length} \le 10^5$
- $0 \le \text{userId}, \text{taskId} \le 10^5$，$0 \le \text{priority}, \text{newPriority} \le 10^9$
- `add`、`edit`、`rmv`、`execTop` 的总调用次数不超过 $2 \cdot 10^5$
- 输入保证 `taskId` 合法（不会重复 `add`、不会对不存在的任务 `edit`/`rmv`）

## 2. 示例

**示例 1**

```text
输入：
["TaskManager", "add", "edit", "execTop", "rmv", "add", "execTop"]
[[[[1,101,10],[2,102,20],[3,103,15]]], [4,104,5], [102,8], [], [101], [5,105,15], []]

输出：[null, null, null, 3, null, null, 5]

解释：
TaskManager([[1,101,10],[2,102,20],[3,103,15]])   // 初始 3 个任务
add(4,104,5)     // 用户 4 的任务 104，优先级 5
edit(102,8)      // 任务 102 的优先级 20 → 8
execTop()        // 返回 3：执行优先级 15 的任务 103
rmv(101)         // 删除任务 101
add(5,105,15)    // 用户 5 的任务 105，优先级 15
execTop()        // 返回 5：任务 105 与 102 的优先级并列时取 taskId 更大的 105
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的做法：把所有任务按 `taskId` 存进哈希表，`execTop()` 时遍历全表找"优先级最高、并列取 `taskId` 最大"的任务。单次 `execTop` 是 $O(n)$，而 `add`/`edit`/`rmv` 是 $O(1)$。

但操作总数可达 $2 \cdot 10^5$，最坏情况下每次都是 `execTop`，总复杂度 $O(n \cdot q) \approx 2 \cdot 10^{10}$，必然超时。瓶颈在于：**"取全局最优"这件事被反复从头扫描**。

### 3.2 核心观察：一份数据，两个索引

![一个任务存两份：哈希表管"按 id 定位"，有序集合管"按优先级挑"](images/bw147_q2_two_indexes.svg)

四个操作里有两种截然不同的访问模式：

- `edit` / `rmv` / `execTop` 的返回值都需要**按 `taskId` 精确命中**一个任务 —— 哈希表天然擅长；
- `execTop` 需要**全局最大**的 $(\text{priority}, \text{taskId})$ —— 需要一个按此二元组有序的结构。

于是同时维护两份数据：

| 结构 | 内容 | 用途 | 单次代价 |
|------|------|------|----------|
| 哈希表 `task` | `taskId → (userId, priority)` | 按 id 定位、取 `userId` | $O(1)$ |
| 有序集合 `heap` | 有序对 `(priority, taskId)` | 取全局最大、精确定位删除 | $O(\log n)$ |

`execTop` 只需取有序集合的**末尾元素**：`pair` 的字典序保证了"先比优先级、再比 `taskId`"，与题目裁决规则完全一致。

### 3.3 算法流程

![四个操作的维护动作与代价](images/bw147_q2_operation_flow.svg)

```text
add(u, t, p):        task[t] = (u, p);  heap.insert((p, t))
edit(t, np):         (u, p) = task[t]
                     heap.erase((p, t))          # 先摘旧键
                     task[t] = (u, np);  heap.insert((np, t))
rmv(t):              p = task[t].priority
                     heap.erase((p, t));  task.erase(t)
execTop():           若 heap 为空 → -1
                     (p, t) = 末尾元素
                     u = task[t].userId
                     heap.erase(末尾);  task.erase(t)
                     return u
```

关键在于 `edit`：优先级不是"可原地修改"的字段，因为有序集合的键会变。必须先**按旧键删除**、再**按新键插入**。

### 3.4 示例演算

![官方示例逐步演算](images/bw147_q2_example_walkthrough.svg)

| 操作 | 有序集合（升序，末尾为最优） | 返回 |
|------|------------------------------|------|
| 初始化 | (10,101) (15,103) (20,102) | null |
| add(4,104,5) | (5,104) (10,101) (15,103) (20,102) | null |
| edit(102,8) | (5,104) (8,102) (10,101) (15,103) | null |
| execTop() | 取出 (15,103) | **3** |
| rmv(101) | (5,104) (8,102) | null |
| add(5,105,15) | (5,104) (8,102) (15,105) | null |
| execTop() | 取出 (15,105) | **5** |

第 6 步很关键：任务 105 的优先级 15 与任务 102 的优先级 8 不同，此时比的是优先级；如果两个任务优先级相同，则由 `pair` 的第二维 `taskId` 决定。

## 4. 算法细节

1. **有序键的选择**：C++ 用 `set<pair<int,int>>`（`priority` 在前、`taskId` 在后）。`set` 支持 $O(\log n)$ 的**精确删除**（按值删），正好匹配 `edit`/`rmv` 的需求；`priority_queue` 只能弹出堆顶，删不掉中间元素。
2. **取末尾**：`prev(heap.end())` 取最大键，$O(1)$（`set` 是红黑树，`end()` 的前驱是常数时间）。
3. **Python 用惰性删除**：`heapq` 没有"按键删除"，于是 `edit` 直接压入新条目、`rmv` 只从字典里删；`execTop` 弹堆顶时校验 `owner[tid].priority == -negp`，不一致就丢弃重弹。
4. **返回值类型**：`priority` 最大 $10^9$ 用 `int` 足够；但若把 `(priority, taskId)` 拼成一个整数做键，需要用 `long long`，直接用 `pair` 更安全。
5. **空系统**：`execTop()` 在 `heap` 为空时返回 $-1$；注意 Python 的惰性删除要把过期条目弹干净后才判断为空。

## 5. 正确性证明

**引理 1（不变量）**：任意操作完成后，`heap` 中的键集合与 `task` 的键集合完全一致，且对每个 `taskId`，`heap` 中键的优先级等于 `task` 中记录的优先级。

**证明**：对操作次数归纳。初始为空，成立。`add` 同时向两处插入 `taskId` 且优先级相同；`edit` 按旧优先级从 `heap` 删除、再以新优先级插入，同时更新 `task`；`rmv` 与 `execTop` 都是"两边同时删除"。每个操作对两个结构的改动一一对应，故不变量保持。∎

**引理 2**：`execTop` 取出的键 $(\text{priority}^*, \text{taskId}^*)$ 满足：$\text{priority}^*$ 是当前所有任务的最大优先级，且在优先级等于 $\text{priority}^*$ 的任务中 $\text{taskId}^*$ 最大。

**证明**：`set<pair>` 按字典序升序排列，末尾元素即字典序最大者。字典序比较先看 `priority`，故 $\text{priority}^* = \max$；若存在同优先级但 `taskId` 更大的任务，它的键字典序更大，与"末尾最大"矛盾。∎

**定理**：四个操作的行为都与题目定义一致。

**证明**：`add`/`edit`/`rmv` 只做插入、改键、删除，正确性由引理 1 的键值对应直接得到。`execTop` 由引理 2 取出正确任务，返回值取自 `task` 中该 `taskId` 的 `userId`（引理 1 保证这条记录未被提前改坏），随后两边同时删除，系统状态与"执行后移除该任务"一致。空系统返回 $-1$。∎

## 6. 复杂度分析

- **时间**：初始化 $n$ 个任务，每个 $O(\log n)$，共 $O(n \log n)$；此后每个操作：`add`/`edit`/`rmv`/`execTop` 均为常数次有序集合操作，$O(\log n)$。总时间 $O((n + q)\log n)$，其中 $q$ 为操作总次数（$\le 2\cdot10^5$）。
  - Python 的惰性删除：每个过期条目最多被弹出一次，均摊到 $q$ 次操作后仍是 $O(q \log q)$。
- **空间**：$O(n + q)$。`task` 存当前存活任务，`heap` 在 Python 惰性删除下最多存 $n + q$ 个条目（C++ 精确删除则严格为存活任务数）。

## 7. 参考代码

### C++

```cpp
class TaskManager {
    unordered_map<int, pair<int, int>> task;   // taskId -> (userId, priority)
    set<pair<int, int>> heap;                  // (priority, taskId) 升序，末尾即最高优先级
public:
    TaskManager(vector<vector<int>>& tasks) {
        for (auto& t : tasks) add(t[0], t[1], t[2]);
    }

    void add(int userId, int taskId, int priority) {
        task[taskId] = {userId, priority};
        heap.insert({priority, taskId});
    }

    void edit(int taskId, int newPriority) {
        int userId = task[taskId].first;
        int old = task[taskId].second;
        heap.erase({old, taskId});             // 先摘掉旧键
        task[taskId] = {userId, newPriority};
        heap.insert({newPriority, taskId});
    }

    void rmv(int taskId) {
        int old = task[taskId].second;
        heap.erase({old, taskId});
        task.erase(taskId);
    }

    int execTop() {
        if (heap.empty()) return -1;
        auto it = prev(heap.end());            // (最大 priority, 其中最大 taskId)
        int priority = it->first, taskId = it->second;
        int userId = task[taskId].first;
        heap.erase(it);
        task.erase(taskId);
        return userId;
    }
};
```

### Python

```python
import heapq

class TaskManager:
    def __init__(self, tasks: list) -> None:
        self.owner = {}          # taskId -> (userId, priority)
        self.heap = []           # (-priority, -taskId)，惰性删除
        for u, t, p in tasks:
            self.add(u, t, p)

    def add(self, userId: int, taskId: int, priority: int) -> None:
        self.owner[taskId] = (userId, priority)
        heapq.heappush(self.heap, (-priority, -taskId))

    def edit(self, taskId: int, newPriority: int) -> None:
        userId = self.owner[taskId][0]
        self.owner[taskId] = (userId, newPriority)
        heapq.heappush(self.heap, (-newPriority, -taskId))

    def rmv(self, taskId: int) -> None:
        del self.owner[taskId]

    def execTop(self) -> int:
        while self.heap:
            negp, negt = self.heap[0]
            tid = -negt
            if tid in self.owner and self.owner[tid][1] == -negp:
                heapq.heappop(self.heap)
                return self.owner.pop(tid)[0]
            heapq.heappop(self.heap)     # 过期条目
        return -1
```

## 8. 边界情况与易错点

1. **`edit` 忘了先删旧键**：只往 `heap` 里压新优先级会让同一个任务出现两次，`execTop` 可能执行一个"已经改过优先级"的旧条目。
2. **同级并列的比较维度**：必须"优先级优先、`taskId` 次之"。用 `priority` 单独建 `multiset` 会退化成"同级内还要再比较"。
3. **`execTop` 后必须两边都删**：只删 `heap` 会让 `task` 里留下幽灵记录，后续 `execTop` 可能返回已执行任务的 `userId`。
4. **Python 惰性删除的校验条件**：必须比较"优先级是否仍相等"。只检查 `tid in owner` 不够 —— 任务被 `edit` 过之后旧条目仍然在堆里，且 `tid` 仍在 `owner` 中。
5. **`priority` 为 0 与空系统**：优先级可以是 $0$，不要用 `0` 当哨兵；空系统才返回 $-1$。
6. **同一个用户多个任务**：`rmv`/`execTop` 只按 `taskId` 删，不要按 `userId` 删。
7. **总操作次数上界**：$2 \cdot 10^5$ 次，注意 `ios::sync_with_stdio(false)` 之类的读写优化（本题主要是结构设计，输入量不大）。
