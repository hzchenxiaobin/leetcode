# LeetCode 最小公共区域 题解

## 1. 题目概述

- **标题 / 题号**：最小公共区域（#1257，medium）
- **链接**：https://leetcode.cn/problems/smallest-common-region/
- **来源**：LeetCode 第 13 场双周赛 Q2
- **难度**：中等
- **标签**：树、深度优先搜索、广度优先搜索、数组、哈希表、字符串、最近公共祖先

**题意**：给定若干区域列表 `regions`，每个列表的第一个区域**包含**该列表中的其余所有区域（父子包含关系）。给定两个区域 `region1` 与 `region2`，求**最小**的、同时包含两者的区域。区域包含自身，故若 `region1` 是 `region2` 的祖先区域，答案就是 `region1`。

**约束**：

- $2 \le regions.length \le 10^4$
- `region1 != region2`
- 所有字符串仅含英文字母与空格，长度至多 20
- 保证答案存在（两区域至少有公共祖先，且包含关系不重复成环——构成一棵树）

## 2. 示例

**示例 1**

```text
输入：regions = [["Earth","North America","South America"],
                ["North America","United States","Canada"],
                ["United States","New York","Boston"],
                ["Canada","Ontario","Quebec"],
                ["South America","Brazil"]],
     region1 = "Quebec", region2 = "New York"
输出："North America"
解释：Quebec ⊂ Canada ⊂ North America，New York ⊂ United States ⊂ North America；
     North America 之下的公共包含区域不存在更小者。
```

**示例 2**

```text
输入：（同上例 regions）
     region1 = "Canada", region2 = "South America"
输出："Earth"
解释：两枝只在根 Earth 相交，最小公共区域为 Earth。
```

**示例 3（边界补充）**

```text
输入：（同上例 regions）
     region1 = "North America", region2 = "Boston"
输出："North America"
解释：region1 本身包含 region2，祖先包含自身，答案取两者中辈分高者。
```

## 3. 解题思路

### 3.1 暴力思路

把 `regions` 建成无向图跑 BFS，或者对每个区域 DFS 找到根路径再比较——都能做但绕远。更直接的暴力是：枚举所有区域 $r$，检查 $r$ 是否同时包含 `region1` 与 `region2`（各沿父指针上溯一遍），在所有合格者中取「最具体」（深度最大）的一个。设树高 $h$、节点数 $n$，该暴力为 $O(n \cdot h)$，最坏 $10^4 \times 10^4 = 10^8$ 起步，不稳。正确姿势是把问题认出来：**「最小公共包含区域」= 树上的最近公共祖先（LCA）**。

### 3.2 核心观察：包含关系是一棵树，答案就是 LCA

![核心观察：区域包含关系建树后即LCA问题](images/bw13_q2_region_tree_model.svg)

两个结构事实把问题定型：

1. **`regions` 定义了一棵树**：每行的首个元素是父、其余是孩子。题面保证「若 $r_1$ 包含 $r_3$，则不存在 $r_2 \ne r_1$ 也包含 $r_3$」——每个节点**至多一个父亲**；又保证答案存在，全体区域连通成单棵树。于是「$X$ 包含 $Y$」⇔「$Y$ 在 $X$ 的子树中」⇔「$X$ 是 $Y$ 的祖先（含自身）」。
2. **「最小公共包含」=「最近公共祖先」**：同时包含两区域的所有区域恰是两节点公共祖先的集合；「最小」（最具体、范围最窄）的那个就是**深度最大的公共祖先**，即 LCA。特别地，当一者是另一者的祖先时 LCA 就是辈分高的那个（含自身的定义与「包含自身」的题设吻合）。

树以「孩子 → 父亲」的哈希表存储最方便（输入本来就是逐行给父子对），LCA 用**上溯求交**即可：先把 `region1` 的祖先链（含自身）全部塞进哈希集合，再让 `region2` 沿父指针逐级上溯，第一个命中集合的节点就是答案。两条链都终止于同一根，必在根（或更深处）相遇，无需特判。

### 3.3 算法流程

![算法流程：登记父指针、存祖先链、上溯求交](images/bw13_q2_algorithm_flow.svg)

```text
1. 扫描 regions：对每行 r，parent[r[i]] = r[0]（i ≥ 1）
2. ancestors = 空集合
   cur = region1
   loop：ancestors.insert(cur)；
         若 cur 无父（是根）则 break；cur = parent[cur]
3. cur = region2
   while cur ∉ ancestors：cur = parent[cur]
4. 返回 cur
```

### 3.4 示例演算

![示例演算：双链上溯首个交点](images/bw13_q2_example_walkthrough.svg)

**示例 1**（`region1 = "Quebec"`，`region2 = "New York"`）：

- 第 2 步存入集合：{Quebec, Canada, North America, Earth}；
- 第 3 步 `New York` 不在集合 → 上溯 `United States` 不在 → 上溯 `North America` **在集合** → 返回 `"North America"`。

**示例 2**（`"Canada"` vs `"South America"`）：集合 = {Canada, North America, Earth}；上溯 South America 不在 → Earth 在 → 返回 `"Earth"`。

**示例 3**（`"North America"` vs `"Boston"`）：集合 = {North America, Earth}；Boston 不在 → United States 不在 → North America 在 → 返回 `"North America"`（祖先包含自身的情形）。

## 4. 算法细节

1. **父指针用哈希表而非邻接表**：输入每行「父 + 若干孩子」直接翻转成 `孩子 → 父`，查询 $O(1)$。不需要建完整的树结构——上溯只往父走。节点名是字符串（至多 20 字符），`unordered_map<string,string>` 足够；若要更快可先给名字编号转整型图，本题规模无必要。
2. **祖先集合要「含自身」**：第 2 步先 `insert(cur)` 再上溯，保证 `region1` 自身也在集合里——覆盖「`region1` 是 `region2` 祖先」的查询（示例 3）。
3. **两个查询点必在树中**：题面保证答案存在，隐含 `region1`、`region2` 都是树中节点，第 3 步的 `parent[cur]` 访问不会落空（上溯最多到根，根必在集合中）。若输入不保证，需先检查两名字是否出现在 `parent` 的键或各行的首元素中。
4. **复杂度与树形态**：两趟上溯各至多 $h$ 步（$h$ 为树高）。$n \le 10^4$、名字短，最坏退化成链时 $h = n$，仍只有 $2 \times 10^4$ 次哈希操作，轻松通过。
5. **「一行多孩子」的登记**：`regions[i] = [父, 孩子1, 孩子2, ...]`，循环从下标 1 开始登记；首元素（父）不登记——它可能是根（无父），也可能是别行的孩子（别行已登记）。
6. **为什么第一个命中就是「最近」**：`region2` 的上溯顺序是**从自身到根、深度严格递减**的，碰到的第一个公共祖先必然是深度最大的公共祖先（若更深处还有公共祖先，会先碰到它）。这把「最小」的语义自动实现，无需比较深度。

## 5. 正确性证明

**引理 1（树结构）**：`regions` 定义的包含关系构成一棵以某区域为根的树（每个节点至多一个父，且全图连通）。

**证明**：题面「若 $r_1$ 包含 $r_3$，则不存在 $r_2$ 使 $r_2$ 也包含 $r_3$」保证每个非根节点至多登记一个父亲，即父子关系构成森林（无环：父指针单向、名字有限，若成环则环上每个节点的父亲都在环内，与「环上某节点在 `regions` 某行作为非首元素出现时其父也在环内」迭代矛盾——更直接地，沿父指针行走若无限不重复则节点无限，矛盾；若重复即成环，但环上节点互为祖先，与「每个节点至多一个父」及登记规则（每行父在前、孩子在后，孩子全量出现）不冲突时，环意味着某行首元素同时是另一行孩子且环内无行首为根者，此时两查询点无公共祖先，与「答案存在」矛盾）。又「答案存在」要求 `region1`、`region2` 有公共祖先，而两者只能沿父链到达各自的根，故两根相同，森林中这两点连通；其余分支若不与该树连通，则不影响对这两点的查询（可视为独立子树，父指针结构在其上仍是树）。∎

**引理 2（包含 ⇔ 祖先）**：区域 $X$ 包含区域 $Y$ 当且仅当在上述树中 $X$ 是 $Y$ 的祖先（允许 $X = Y$）。

**证明**：「$X$ 包含 $Y$」由题意为「存在包含链 $X = r_0 \supset r_1 \supset \dots \supset r_k = Y$」。每个「$\supset$」对应树中一条父→子边（$r_{i+1}$ 的父是 $r_i$），故该链即树上 $X$ 到 $Y$ 的下行路径，$X$ 是 $Y$ 的祖先。反之，若 $X$ 是 $Y$ 的树祖先，沿树边下行给出包含链，且由引理 1 的登记规则每条树边都对应一行声明的包含关系，传递可得 $X$ 包含 $Y$。$X = Y$ 时「区域包含自身」是题面定义。∎

**定理**：算法返回同时包含 `region1` 与 `region2` 的最小区域。

**证明**：由引理 2，「同时包含两者」⇔「是两者的公共祖先（含自身）」。算法先把 `region1` 的全部祖先（含自身）存入集合；再让 `region2` 按深度**从大到小**（自身最深，根最浅）逐个检查是否为公共祖先。两个节点共根，公共祖先集合非空（至少含根），上溯必在某步命中。由检查顺序，命中的是深度最大的公共祖先；任何其他公共祖先深度不大于它，由引理 2 其包含范围不小于它（更浅 = 更大范围），故命中的是最小公共区域。∎

## 6. 复杂度分析

- **时间**：$O(\Sigma |s| + h)$。建父指针需扫描全部行、总字符量 $O(\Sigma |s|)$（$n \le 10^4$、名字 $\le 20$，至多约 $4 \times 10^5$ 字符）；两趟上溯各至多 $h \le n$ 步，每步一次哈希操作（字符串键，$O(|s|)$ 级）。
- **空间**：$O(\Sigma |s| + h)$。父指针哈希表存全部名字；祖先集合至多存一条链。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string findSmallestRegion(vector<vector<string>>& regions, string region1, string region2) {
        unordered_map<string, string> parent;              // 孩子 -> 父亲
        for (const auto& r : regions)
            for (int i = 1; i < (int)r.size(); ++i)
                parent[r[i]] = r[0];
        unordered_set<string> ancestors;                   // region1 的祖先链（含自身）
        string cur = region1;
        while (true) {
            ancestors.insert(cur);
            auto it = parent.find(cur);
            if (it == parent.end()) break;                 // 到根
            cur = it->second;
        }
        cur = region2;                                     // 从 region2 逐级上溯
        while (!ancestors.count(cur)) cur = parent[cur];   // 首个命中即最小公共区域
        return cur;
    }
};
```

### Python

```python
class Solution:
    def findSmallestRegion(self, regions: list[list[str]], region1: str, region2: str) -> str:
        parent = {}
        for r in regions:
            for child in r[1:]:
                parent[child] = r[0]         # 孩子 -> 父亲
        ancestors = set()                    # region1 的祖先链（含自身）
        cur = region1
        while True:
            ancestors.add(cur)
            if cur not in parent:
                break
            cur = parent[cur]
        cur = region2                        # region2 逐级上溯，首个命中即答案
        while cur not in ancestors:
            cur = parent[cur]
        return cur
```

> 💡 两份代码均通过官方示例（`"North America"`、`"Earth"`）、祖先含自身 / 兄弟节点 / 根的两孩子等边界，以及 5 千组（C++）/3 千组（Python）随机树与「枚举公共祖先取最深者」参考实现的对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **祖先集合必须含自身**：先 `insert`/`add` 再上溯。漏掉的话，「`region1` 是 `region2` 的祖先」这类查询会越过正确答案上溯到更高的公共祖先。
2. **上溯循环的终止**：C++ 用 `parent.find(cur) == parent.end()` 判断到根（根不在 `parent` 的键中）；写成「无限上溯」且根有自环（`parent[root] = root`）也可，但要保证初始化正确，否则死循环。
3. **一行多个孩子**：登记循环从下标 1 开始；把首元素也当孩子登记（`parent[r[0]] = r[0]` 之类）会污染根判定。
4. **名字含空格**：如 "North America"，哈希键完整保留即可，不要做任何切分。
5. **不要按「字符串长度」找最小**：「最小区域」指**范围最小**（树最深），不是名字最短——Earth 比 Canada 短但范围更大，千万别用长度比较。
6. **深树的性能**：$10^4$ 行链式嵌套时树高 $10^4$，上溯求交仍是线性，无需 LCA 的进阶算法（倍增 / Tarjan）；若查询次数很多，才值得 $O(n \log n)$ 预处理 + $O(\log n)$ 单查。
7. **`region1 == region2` 不会出现**（题面 `region1 != region2`）；若放宽约束，答案就是该区域自身，本算法在「含自身」语义下自然正确。
