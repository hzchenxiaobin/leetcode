# LeetCode 加密数字 题解

## 1. 题目概述

- **标题 / 题号**：加密数字（#1256，medium）
- **链接**：https://leetcode.cn/problems/encode-number/
- **来源**：LeetCode 第 13 场双周赛 Q1
- **难度**：中等
- **标签**：位运算、数学、字符串

**题意**：给定非负整数 `num`，按照一张「秘密函数」对照表把它编码为字符串。对照表（题面插图）如下：

| num | 编码 | num | 编码 | num | 编码 |
|-----|------|-----|------|-----|------|
| 0 | ""（空串） | 5 | "10" | 10 | "010" |
| 1 | "0" | 6 | "11" | 11 | "011" |
| 2 | "1" | 7 | "000" | 12 | "100" |
| 3 | "00" | 8 | "001" | 13 | "101" |
| 4 | "01" | 9 | "010" | 14 | "110" |

请实现该编码函数。

**约束**：

- $0 \le num \le 10^9$

## 2. 示例

**示例 1**

```text
输入：num = 23
输出："1000"
解释：长度 4 的桶覆盖 num ∈ [15, 30]，桶内序号 23 − 15 = 8，即 8 的 4 位二进制 "1000"。
```

**示例 2**

```text
输入：num = 107
输出："101100"
解释：107 + 1 = 108 = (1101100)₂，去掉最高位得 "101100"。
```

**示例 3（边界补充）**

```text
输入：num = 0
输出：""
解释：0 编码为空串；num = 1 → "0"，num = 2 → "1"。
```

## 3. 解题思路

### 3.1 暴力思路

观察表格猜测规律需要先「看出结构」：编码按长度分组——长度 0（只有 `num = 0`）、长度 1（`num = 1, 2`）、长度 2（`num = 3..6`）、长度 3（`num = 7..14`）。暴力法是打表 `num = 0..N` 逐个比对找规律，或对每个 `num` 从长度 1 起逐桶试探落到哪个桶、再算桶内偏移。$num \le 10^9$ 时桶长最多 30 位，逐桶试也只是 $O(\log num)$ 次判断，其实已经可行；但存在一个**一步到位**的位运算刻画，更优雅也更不易错。

### 3.2 核心观察：编码 = (num + 1) 的二进制去掉最高位

![核心观察：按长度分桶的编码表与加一定位规律](images/bw13_q1_bucket_model.svg)

把非负整数按「编码长度」分桶：长度 $L$ 的桶恰好装 $2^L$ 个数，覆盖区间 $[2^L - 1,\ 2^{L+1} - 2]$，桶内从 $0$ 开始按普通二进制计数：

- $L = 0$：$\{0\}$；
- $L = 1$：$\{1, 2\}$，编码 "0"、"1"；
- $L = 2$：$\{3, 4, 5, 6\}$，编码 "00"、"01"、"10"、"11"；
- $L = 3$：$\{7, \dots, 14\}$，编码 "000"…"111"。

规律藏在「**桶起点 $2^L - 1$ 恰是 $L + 1$ 位二进制数 $100\dots0_2$ 的数值减……**」直接看结论：设 $m = num + 1$。长度 $L$ 的桶 $[2^L - 1, 2^{L+1} - 2]$ 加一后变为 $[2^L, 2^{L+1} - 1]$，正是**所有 $L + 1$ 位二进制数**（首位为 1）的取值范围！桶内序号 $num - (2^L - 1) = m - 2^L$ 的 $L$ 位二进制，恰等于 $m$ 的 $L + 1$ 位二进制**去掉最高位的 1**。

于是编码函数一步到位：

$$\text{encode}(num) = \text{bin}(num + 1) \text{ 去掉最高位}$$

验证：$num = 0 \Rightarrow m = 1 = (1)_2$，去掉最高位后为空串 ✓；$num = 23 \Rightarrow m = 24 = (11000)_2 \Rightarrow$ "1000" ✓；$num = 107 \Rightarrow m = 108 = (1101100)_2 \Rightarrow$ "101100" ✓。

### 3.3 算法流程

![算法流程：加一后逐位取余再翻转](images/bw13_q1_algorithm_flow.svg)

```text
1. m = num + 1
2. bits = []
   while m > 1:                # 最高位（值为 1）不收集
       bits.append(m & 1)      # 取最低位（低位先出）
       m >>= 1
3. reverse(bits) 并转成 '0'/'1' 字符串返回
```

`m = 1`（即 `num = 0`）时循环不执行，返回空串，边界自然成立。

### 3.4 示例演算

![示例演算：23与107的位串走查](images/bw13_q1_example_walkthrough.svg)

**示例 1**（$num = 23$）：$m = 24 = (11000)_2$。循环取位（低位先）：$0, 0, 0, 1$（$m$ 依次为 24 → 12 → 6 → 3 → 1，停止），翻转得 "1000" ✓。

**示例 2**（$num = 107$）：$m = 108 = (1101100)_2$。取位 $0, 0, 1, 1, 0, 1$，翻转得 "101100" ✓。

**边界**：$num = 0 \Rightarrow m = 1$，循环零次，输出 ""；$num = 1 \Rightarrow m = 2 = (10)_2$，去掉最高位得 "0"。

## 4. 算法细节

1. **为什么 +1 后恰好对齐**：长度 $L$ 桶的桶内计数起点是 $2^L - 1$（不是 $2^L$），因为前面 $L$ 个桶共占去 $2^0 + 2^1 + \dots + 2^{L-1} = 2^L - 1$ 个编号。「前面所有桶的容量和」正是「桶起点」的来源，而加一恰好把起点平移成 $2^L$——一个标准的「凑整」技巧。
2. **低位先收集要翻转**：`m & 1` 弹出的是最低位，收集顺序与最终串相反，最后 `reverse`。也可以用 `insert`/前插避免翻转，但复杂度变 $O(L^2)$（$L \le 30$ 无所谓），翻转版语义更清晰。
3. **循环条件 `m > 1` 而非 `m > 0`**：剩余值为 1 意味着只剩下最高位的前导 1，它不该被编码；写成 `m > 0` 会多吐一个 '1'。
4. **C++ 位串的其他写法**：`bitset<32>(m).to_string()` 后 `substr(find('1') + 1)` 亦可——`find('1')` 定位最高有效位，跳过它截取剩余部分；注意 `bitset` 固定 32 位会产生前导零，必须从第一个 '1' 之后截取。
5. **Python 一行版**：`bin(num + 1)[3:]`——`bin` 返回形如 `'0b1101100'`，去掉前缀 `'0b'` 与首位 `'1'` 共 3 个字符即可（`num = 0` 时 `bin(1) = '0b1'`，切完恰为空串）。
6. **$num \le 10^9 < 2^{30}$**：结果长度至多 29 位，任何整型与字符串操作都在常数级内完成。

## 5. 正确性证明

**引理 1（桶起点与容量）**：按题面表格归纳，编码长度为 $L$ 的 `num` 构成区间 $B_L = [2^L - 1,\ 2^{L+1} - 2]$，且 $|B_L| = 2^L$。

**证明**：对 $L$ 归纳。$L = 0$：表格中仅 $num = 0$ 编码为空串，$B_0 = [1 - 1, 2 - 2] = [0, 0]$ ✓，容量 $2^0 = 1$ ✓。设长度 $L$ 的桶为 $B_L = [2^L - 1, 2^{L+1} - 2]$ 且容量 $2^L$。长度 $L + 1$ 的编码是从 $L$ 个 '0' 到 $L$ 个 '1' 的全部 $2^{L+1}$ 个串，接续在 $B_L$ 之后，故其起点为 $(2^{L+1} - 2) + 1 = 2^{L+1} - 1$，即 $B_{L+1} = [2^{L+1} - 1, 2^{L+2} - 2]$，容量 $2^{L+1}$ ✓。∎

**引理 2（桶内偏移与位串）**：设 $num \in B_L$，$m = num + 1$。则 $m \in [2^L, 2^{L+1} - 1]$（即 $m$ 的二进制恰为 $L + 1$ 位、最高位为 1），且桶内序号 $num - (2^L - 1) = m - 2^L$ 的 $L$ 位二进制表示等于 $m$ 的 $L + 1$ 位二进制去掉最高位后的后 $L$ 位。

**证明**：区间平移：$num \in [2^L - 1, 2^{L+1} - 2] \iff m \in [2^L, 2^{L+1} - 1]$，后者恰是二进制最高位（第 $L$ 位）为 1、其余 $L$ 位任意的全部整数。写 $m = 2^L + r$，$0 \le r \le 2^L - 1$，则 $m$ 的二进制为 `1` 后接 $r$ 的 $L$ 位（补前导零）二进制；而桶内序号 $num - (2^L - 1) = (m - 1) - 2^L + 1 = m - 2^L = r$。故桶内序号的 $L$ 位二进制 = $m$ 去掉最高位后的后 $L$ 位。∎

**定理**：算法输出的字符串与对照表定义的编码一致。

**证明**：由引理 1，任何 `num` 唯一落入某桶 $B_L$，其表定义为「桶内序号的 $L$ 位二进制」。算法计算 $m = num + 1$ 的二进制并去掉最高位：由引理 2，去掉的恰是第 $L$ 位的前导 1，保留的恰是桶内序号的 $L$ 位二进制（含必要的前导零——`while m > 1` 逐位收集不丢位）。长度也对上：$m$ 为 $L + 1$ 位，去一存 $L$ 位。$num = 0$ 时 $m = 1$ 仅一位，循环零次输出空串，与表一致。∎

## 6. 复杂度分析

- **时间**：$O(\log num)$。循环次数等于 $m = num + 1$ 的二进制位数减一，至多 30 次；最后的翻转同阶。
- **空间**：$O(\log num)$。存放结果位串（输出本身即此长度）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string encode(int num) {
        string s;
        int m = num + 1;                      // 关键：先 +1
        while (m > 1) {                       // 收集除最高位以外的每一位
            s.push_back(char('0' + (m & 1)));
            m >>= 1;
        }
        reverse(s.begin(), s.end());          // 低位先收集，最后翻转
        return s;                             // num = 0 → m = 1 → 空串
    }
};
```

### Python

```python
class Solution:
    def encode(self, num: int) -> str:
        m = num + 1                          # 关键：先 +1
        bits = []
        while m > 1:                         # 收集除最高位以外的每一位
            bits.append(str(m & 1))
            m >>= 1
        return ''.join(reversed(bits))       # num=0 → 空串
```

> 💡 两份代码均通过官方示例（`"1000"`、`"101100"`）、硬编码表 `num = 0..30` 全量核对、穷举 $[0, 2 \times 10^6]$ 与「逐桶试探」参考实现的一致性、2 万组随机大数对拍及上界 $10^9$ 边界，全部一致。Python 实战中也可用一行 `bin(num + 1)[3:]`。

## 8. 边界情况与易错点

1. **`num = 0` 返回空串**：不是 "0" 也不是报错；`m = 1` 循环零次自然覆盖。若用 `bitset`/`bin` 的字符串切片法，注意 `bin(1) = '0b1'` 切完恰为空。
2. **忘记 +1 或 +1 位置错**：直接取 `bin(num)` 去最高位会把桶起点错位 1（`num = 1` 会得 "" 而非 "0"）。**先加一再取位**是整个规律的核心。
3. **循环条件写成 `m > 0`**：会把前导 1 也收进结果，所有输出末尾多一个 '1'（顺序翻转后表现为开头多 '1'）。
4. **前导零不能丢**：桶内序号不足 $L$ 位时要补前导零（如 $num = 9$ 的 "010"）。逐位收集法天然保留；字符串切片法注意别用 `strip('0')` 或整数转换把前导零吃掉。
5. **低位先出要翻转**：`m & 1` 弹最低位，忘记 `reverse` 输出成镜像串（$num = 23$ 会得 "0001"）。
6. **`bitset` 的前导零**：`bitset<32>` 恒 32 位，必须先用 `find('1')` 定位最高有效位再截取其后缀，直接 `substr(0, ...)` 会带一堆前导零。
7. **上界 $10^9$**：$2^{30} - 1 \approx 1.07 \times 10^9 > 10^9$，故结果最长 29 位，无需担心更大位数。
