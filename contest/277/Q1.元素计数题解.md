# LeetCode 元素计数 题解

## 1. 题目概述

- **标题 / 题号**：元素计数（#2148，easy）
- **链接**：https://leetcode.cn/problems/count-elements-with-strictly-smaller-and-greater-elements/
- **来源**：LeetCode 第 277 场周赛 Q1
- **难度**：简单
- **标签**：数组、计数、排序

**题意**：给定整数数组 `nums`，统计其中**同时**满足以下两个条件的**元素**个数：至少存在一个**严格小于**它的元素，且至少存在一个**严格大于**它的元素。

**约束**：

- `1 <= nums.length <= 100`
- `-10^5 <= nums[i] <= 10^5`

> 💡 本题在本仓库另有[每日题解 2148](../../solution/2101-2200/2148_元素计数.md)：主线同为「全局极值定开区间」。本篇按**周赛复盘视角**展开：给出引理-定理化的完整等价性证明、$n - c(mn) - c(mx)$ 计数公式及其在「全相等」输入上的负数陷阱、排序 + 二分的第三视角、以示例 2 与 `[6,6,6]` 为例的双视角演算，以及赛场易错清单，两篇互为印证。同场 Q2（#2149 按符号重排数组）是双指针分流题，Q4（#2151 基于陈述统计最多好人数）才是本场的主菜。

## 2. 示例

**示例 1**

```text
输入：nums = [11,7,2,15]
输出：2
解释：mn = 2，mx = 15。7 与 11 严格落在 (2, 15) 内，计入；
      2 是全局最小值（找不到更小者）、15 是全局最大值（找不到更大者），均被排除。
```

**示例 2**

```text
输入：nums = [-3,3,3,90]
输出：2
解释：两个 3 都满足——严格更小者都是 -3，严格更大者都是 90；
      题目数的是「元素个数」，同一个值出现两次就计两次。
```

**示例 3（全相等退化）**

```text
输入：nums = [6,6,6]
输出：0
解释：mn = mx = 6，任何元素都找不到严格更小或严格更大者；
      判定 mn < x < mx 对每个 x 恒假，答案自然为 0。
```

## 3. 解题思路

### 3.1 暴力思路：逐元素找「见证」

按题意直译：对每个 `nums[i]`，再扫一遍数组，检查「是否存在 `y < nums[i]`」与「是否存在 `z > nums[i]`」，两个条件都满足则计数 +1。

- **正确性**：逐元素独立判定，与题意严格一致，完全正确。
- **效率**：双重循环 $O(n^2)$，$n \leq 100$ 时约 $10^4$ 次比较，签到题直接交没有任何问题。
- **不足**：每个元素都重复扫描整个数组去找两个「见证者」，但这两个存在性问题其实**只由两个数决定**——全局最小值和全局最大值。

> ⚠️ 暴力法的根因是「逐元素视角」。把视角抬升到「整个数组只需关心两个极端值」，复杂度立刻从 $O(n^2)$ 降到 $O(n)$——这是签到题里最值得沉淀的一步。

### 3.2 核心观察：两个存在性条件，收敛为开区间 $(mn, mx)$

![核心观察：两个存在性条件收敛为开区间](images/2148_open_interval_concept.svg)

设数组最小值为 $mn$、最大值为 $mx$。对任意元素 $x$：

- **存在严格更小元素** $\iff x > mn$：只要 $x$ 不等于 $mn$，全局最小值 $mn$ 本身就是一个现成的「更小见证者」；反之若 $x = mn$，则任何元素都不小于它。
- **存在严格更大元素** $\iff x < mx$：对称地，只要 $x \neq mx$，$mx$ 就是现成的「更大见证者」。

两个条件取交集，得到逐元素等价判定：

$$\boxed{x \text{ 满足条件} \iff mn < x < mx}$$

即**严格落在开区间 $(mn, mx)$ 内**。于是问题简化为两步：一趟扫描求出 $mn$、$mx$ 这「两堵墙」，再一趟统计落在墙之间的元素个数。

> 💡 **为什么是开区间？**「严格」二字使然：等于 $mn$ 的元素找不到更小者，等于 $mx$ 的找不到更大者，两端全部排除；$mn$、$mx$ 不论重复出现多少次，都一并落在墙上被排除。这正是示例 2 中两个 3 被计入、而 $-3$ 与 $90$ 不计入的原因。

### 3.3 算法流程

![算法流程：第一趟定墙第二趟数墙之间](images/2148_min_max_flow.svg)

1. 初始化 $mn = +\infty$、$mx = -\infty$（或直接用首元素初始化）。
2. 第一趟遍历 `nums`：对每个 $x$ 更新 $mn \leftarrow \min(mn, x)$、$mx \leftarrow \max(mx, x)$。
3. 初始化 $cnt = 0$，第二趟遍历 `nums`：对每个 $x$，若 $mn < x < mx$ 则 $cnt \mathrel{+}= 1$。
4. 返回 $cnt$。

> ⚠️ **全相等无需特判**：若 $mn = mx$（所有元素相等），开区间 $(mn, mx)$ 为空，判定 $mn < x < mx$ 恒假，$cnt$ 自然为 0——判定式自带退化保护。显式特判 `mn == mx` 提前返回 0 也不错（见 §4 的公式版，那里特判是**必须**的）。

### 3.4 示例演算：判定与公式双视角

![示例走查：逐元素判定与计数公式双视角](images/2148_count_formula_walkthrough.svg)

**示例 2** `nums = [-3, 3, 3, 90]`（判定视角）：

- 第一趟：$mn = -3$，$mx = 90$。
- 第二趟逐元素判定 $-3 < x < 90$：`-3` ✗（= min）、`3` ✓、`3` ✓、`90` ✗（= max）。
- 注意两个 3 **都被计入**——数的是「元素个数」，同一个值满足条件几次就计几次。
- $cnt = 2$ ✓。

**计数公式视角**：由 §5 引理 3，$mn < mx$ 时答案 $= n - c(mn) - c(mx)$（$c(v)$ 为值 $v$ 的出现次数）：

| 用例 | $n$ | $c(mn)$ | $c(mx)$ | $n - c(mn) - c(mx)$ |
|------|-----|----------|----------|----------------------|
| `[11,7,2,15]` | 4 | 1 | 1 | 2 ✓ |
| `[-3,3,3,90]` | 4 | 1 | 1 | 2 ✓ |
| `[6,6,6]` | 3 | 3 | 3 | **−3 ✗** |

**边界** `[6,6,6]`：全相等时 $mn = mx$，「min 端」与「max 端」重合，同一批元素被扣两次，公式荒谬地给出 $-3$——必须写 $\max(0, \cdot)$ 或先特判返回 0，正确答案为 $0$。这是本题最典型的「公式陷阱」（详见 §8）。

## 4. 算法细节

1. **求极值的姿势**：C++ 用 `*min_element / *max_element` 各跑一趟，或 `minmax_element` 一趟同时拿到两个极值的迭代器；Python 直接 `min(nums)`、`max(nums)`。手写循环时哨兵初始化的方向别写反：$mn$ 从 `INT_MAX` 起降、$mx$ 从 `INT_MIN` 起升。
2. **判定条件的写法**：Python 原生支持链式比较 `mn < x < mx`；C++ 写 `mn < x && x < mx`——`mn < x < mx` 在 C++ 里**编译通过但语义错误**（实际是 `(mn < x) < mx`，bool 参与比较）。
3. **计数公式** $n - c(mn) - c(mx)$：仅当 $mn < mx$ 时成立（§5 引理 3——前两类元素此时不相交，不会重复扣除）；全相等时两端重合，须 $\max(0, \cdot)$ 或特判。
4. **排序 + 二分视角**：将数组排序后，满足判定的元素恰好占据连续区间 $[\operatorname{upper\_bound}(mn),\ \operatorname{lower\_bound}(mx))$，答案为 `bisect_left(a, mx) - bisect_right(a, mn)`，$O(n \log n)$。不如两趟扫描快，但展示了「排序把极值判定变成区间计数」的常用转化；全相等时同样减出负数，也要 $\max(0, \cdot)$ 保护。
5. **能否一趟完成？** 严格单趟（流式、$O(1)$ 额外空间）不可行：判定 $mn < x < mx$ 依赖读完全数组才能确定的两个全局量。若用值域计数数组（$V = 2 \times 10^5 + 1$ 个桶）在第一趟顺带统计频次，则第二趟可省为 $O(1)$ 直址访问——答案 $= n - \text{cnt}[mn] - \text{cnt}[mx]$，用 $O(V)$ 空间换一遍扫描。

## 5. 正确性证明

**引理 1（存在性刻画）**：设 $mn = \min(\text{nums})$，$mx = \max(\text{nums})$。对任意 $x \in \text{nums}$：

$$\big(\exists\, y \in \text{nums},\ y < x\big) \iff x > mn, \qquad \big(\exists\, z \in \text{nums},\ z > x\big) \iff x < mx.$$

**证明**：先证左式。若 $x > mn$，则 $mn \in \text{nums}$ 且 $mn < x$，即 $mn$ 本身就是一个满足条件的更小元素，存在性成立；反之若存在 $y < x$，由 $mn$ 是全局最小值有 $mn \leq y < x$，故 $x > mn$。右式对称：若 $x < mx$，则 $mx$ 本身就是满足条件的更大元素；反之若存在 $z > x$，由 $mx$ 是全局最大值有 $x < z \leq mx$，故 $x < mx$。∎

**引理 2（判定收敛）**：元素 $x$ 满足题目条件（同时存在严格更小与严格更大的元素）当且仅当 $mn < x < mx$。

**证明**：题目条件是引理 1 两个命题的合取，即 $x > mn$ 且 $x < mx$，联立即 $mn < x < mx$。∎

**引理 3（计数公式）**：记 $n = |\text{nums}|$，$c(v)$ 为值 $v$ 的出现次数。若 $mn < mx$，则答案 $= n - c(mn) - c(mx)$；若 $mn = mx$，则答案 $= 0$。

**证明**：当 $mn < mx$ 时，由 $mn \leq x \leq mx$，每个元素恰居三类之一：$x = mn$、$x = mx$、或 $mn < x < mx$，不存在第四类。由引理 2，第三类的每个元素都满足条件，前两类的每个元素都不满足（$x = mn$ 时 $x > mn$ 为假；$x = mx$ 时 $x < mx$ 为假）。三类基数分别为 $c(mn)$、$c(mx)$ 与 $n - c(mn) - c(mx)$；$mn < mx$ 保证前两类不相交，扣除不重复，故答案为 $n - c(mn) - c(mx)$。当 $mn = mx$ 时所有元素相等，$mn < x < mx$ 即 $mn < x < mn$ 恒假，答案为 $0$。∎

**定理**：两趟扫描算法（第一趟求 $mn, mx$，第二趟统计满足 $mn < x < mx$ 的元素个数）返回的正是题目所求的元素数目。

**证明**：第一趟结束后 $mn, mx$ 分别为数组的最小、最大值（对遍历顺序归纳显然：每步维护后 $mn$ 恰为已见元素的最小值、$mx$ 恰为已见元素的最大值）。第二趟中，$cnt$ 每加一当且仅当前元素满足 $mn < x < mx$；由引理 2 这恰是题目条件的逐元素等价刻画，故 $cnt$ 的终值等于满足条件的元素总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。第一趟求极值至多 $2n$ 次比较，第二趟每个元素一次链式判定，合计约 $3n$ 次比较、两趟扫描。渐近意义上已最优：$mn$、$mx$ 是全局量，任何算法至少要读完全部 $n$ 个元素（$\Omega(n)$）才能确定边界并完成计数。
- **空间复杂度**：$O(1)$，仅 $mn$、$mx$、$cnt$ 三个变量。
- **对照**：暴力判定 $O(n^2)$ / $O(1)$（$n \leq 100$ 下约 $10^4$ 次，同样通过）；排序 + 二分 $O(n \log n)$ / 视实现 $O(\log n) \sim O(n)$；值域计数数组 $O(n + V)$ 时间、$O(V)$ 空间，$V = 2 \times 10^5 + 1$。

## 7. 参考代码

### C++（两趟判定，主推）

```cpp
class Solution {
public:
    int countElements(vector<int>& nums) {
        int mn = INT_MAX, mx = INT_MIN;
        for (int x : nums) {
            mn = min(mn, x);
            mx = max(mx, x);
        }
        int cnt = 0;
        for (int x : nums) {
            if (mn < x && x < mx) ++cnt;
        }
        return cnt;
    }
};
```

### C++（一趟极值 + 计数公式）

```cpp
class Solution {
public:
    int countElements(vector<int>& nums) {
        auto [mnIt, mxIt] = minmax_element(nums.begin(), nums.end());
        if (*mnIt == *mxIt) return 0;
        int n = nums.size();
        return n - count(nums.begin(), nums.end(), *mnIt)
                 - count(nums.begin(), nums.end(), *mxIt);
    }
};
```

> 💡 `minmax_element` 单趟同时返回最小、最大元素的迭代器；公式版必须**先特判** `*mnIt == *mxIt`（引理 3 的前提），否则全相等时减出负数。

### Python（判定版）

```python
class Solution:
    def countElements(self, nums: List[int]) -> int:
        mn, mx = min(nums), max(nums)
        return sum(mn < x < mx for x in nums)
```

### Python（公式版）

```python
class Solution:
    def countElements(self, nums: List[int]) -> int:
        mn, mx = min(nums), max(nums)
        return max(0, len(nums) - nums.count(mn) - nums.count(mx))
```

> 💡 公式版用 $\max(0, \cdot)$ 把特判折叠进表达式：$mn < mx$ 时被减数不小于 0，$\max$ 不起作用；$mn = mx$ 时结果为 $\max(0, -n) = 0$，一行覆盖两种情形。

## 8. 边界情况与易错点

1. **全相等（含 $n = 1$）→ 0**：判定版天然正确（恒假自动归零）；**公式版与二分版必须修正**——`[6,6,6]` 代入 $n - c(mn) - c(mx)$ 得 $-3$，`bisect_left(a, mx) - bisect_right(a, mn)` 同样为负，须 $\max(0, \cdot)$ 或先特判。本题最典型的「两端重合扣两次」陷阱。
2. **$n = 1$**：唯一元素既是 $mn$ 又是 $mx$，被两端同时排除，答案 0，无需任何特判。
3. **重复元素计数**：满足条件的每个元素各计一次（示例 2 的两个 3 都算）；反过来 $mn$、$mx$ 重复出现时也**全部**排除——始终数「元素个数」，不是「不同值个数」。
4. **C++ 链式比较陷阱**：`mn < x < mx` 编译通过但语义为 `(mn < x) < mx`，必须写 `mn < x && x < mx`；Python 才支持链式。
5. **哨兵初始化方向写反**（$mn$ 起自 `INT_MIN`）会让 $mn$ 永远停在哨兵上、判定整体失真——或干脆用首元素初始化，少一个出错点。
6. **溢出审计**：值域 $\pm 10^5$、$n \leq 100$，`int` 绰绰有余，无溢出风险。
7. **审「严格」二字**：若题面是非严格（$\leq$ / $\geq$），任何元素以自身为见证者，答案退化为 $n$——先圈出这两个字再动笔，能避免整套判定方向性错误。
