# LeetCode 找出数组中的所有孤独数字 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的所有孤独数字（#2150，medium）
- **链接**：https://leetcode.cn/problems/find-all-lonely-numbers-in-the-array/
- **来源**：LeetCode 第 277 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums`。值 $x$ 称为**孤独数字**，当且仅当同时满足三条：① $x$ 在数组中**恰好出现一次**；② $x+1$ 不在数组中；③ $x-1$ 不在数组中。返回 `nums` 中**所有**孤独数字，**顺序任意**。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $0 \le \text{nums[i]} \le 10^6$

> 💡 本题在本仓库另有[每日题解 2150](../../solution/2101-2200/2150_找出数组中的所有孤独数字.md)：主线同为「频次表 + 邻位存在性判定」。本篇按**周赛复盘视角**展开：给出引理-定理化的判定等价证明、C++ 遍历哈希表时 `operator[]` 触发 rehash 使迭代器失效的**赛场头号深坑**、遍历键与遍历原数组的等价性论证（顺带证明值域数组版**无需去重集合**）、成对失效的完整推论，以及排序对照解，两篇互为印证。同场 Q1（#2148 元素计数）、Q2（#2149 按符号重排数组）都是「条件直译」型，Q4（#2151 基于陈述统计最多好人数）才是本场主菜。

## 2. 示例

```text
输出：[10,8]
解释：四个值各出现 1 次。
      10：9、11 缺席 → 孤独；8：7、9 缺席 → 孤独；
      5 与 6 互为邻位，互相指认对方在场 → 双双出局。
```

**示例 2**

```text
输入：nums = [1,3,5,3]
输出：[1,5]
解释：3 出现 2 次，频次条件直接否决；
      1：0、2 缺席 → 孤独；5：4、6 缺席 → 孤独。
```

**示例 3（值域下界 + 成对失效）**

```text
输入：nums = [0,1]
输出：[]
解释：0 的 x+1 是 1，1 的 x−1 是 0——两者互为邻位，

```

**示例 4（单元素边界）**

```text
输入：nums = [7]

```

## 3. 解题思路

### 3.1 暴力思路：逐元素全数组扫描

按题意直译：对每个 $x \in \text{nums}$，再扫一遍整个数组，分别数出 $x$、$x+1$、$x-1$ 的出现次数，三个条件都满足才收入答案。

- **正确性**：逐元素独立判定，与题意严格一致。
- **效率**：$O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，**必然超时**。
- **根因**：「某值出现几次」这个存在性查询被反复询问、每次都从头线性回答。三个条件全部**与下标无关、只与值频次有关**——把「按位置遍历」换成「按值聚合」，一次建表即可把每次查询压到 $O(1)$。

### 3.2 核心观察：三个条件 ⟺ 频次表的三个 O(1) 查询

![核心观察：孤独三条件即频次表三个查询，相邻值成对失效](images/2150_lonely_conditions.svg)

设 $c(v)$ 表示值 $v$ 在 `nums` 中的出现次数（频次表即 $c$ 的存储），则孤独的判定逐条翻译：

| 题面条件 | 频次表语言 |
|----------|-----------|
| $x$ 恰好出现一次 | `cnt[x] == 1` |
| $x+1$ 不在数组中 | `cnt[x+1] == 0`（缺键即 0） |
| $x-1$ 不在数组中 | `cnt[x-1] == 0`（缺键即 0） |

三条**全部**是频次表的 $O(1)$ 查询，于是算法塌缩成两趟扫描：**第一趟建表，第二趟过滤**。

> 💡 **成对失效**（上图下半）：若相邻两值 $a$、$a+1$ 都出现（无论各自频次是几），则 $a$ 违反条件②、$a+1$ 违反条件③，**双双出局**。推论：连续整数段内全灭，孤独值只能诞生在**左右邻位双双缺席的孤立单点**上，且自身频次恰 1——这解释了示例 1 中 5、6「陪葬」而 8、10 幸存（§5 引理 2）。

### 3.3 算法流程：建表 + 逐键三查

![算法流程：建频次表、逐键短路判定、operator[] 陷阱](images/2150_lonely_flow.svg)

1. **第一趟建表**：遍历 `nums`，执行 `cnt[x]++`，得到「值 → 频次」映射。
2. **第二趟过滤**：遍历 `cnt` 的每个键 $x$（记其频次为 $c$）：若 $c = 1$ **且** `cnt[x+1]` 缺键 **且** `cnt[x-1]` 缺键，则 $x$ 孤独，加入答案。判定按短路顺序排：$c \ne 1$ 时两次邻位查询全省。
3. **返回 `ans`**：顺序任意。

> ⚠️ **C++ 实现的头号陷阱**（上图底部警示）：第二趟若把邻位判定写成 `cnt[x+1] == 0`，`operator[]` 对缺键会**插入新键**——插入可能触发 rehash，使**正在遍历的迭代器失效**（未定义行为）。样例小、不 rehash 时侥幸通过，大数据下偶发 RE/UB，属「过样例但被 hacking 死」的典型。安全姿势：`cnt.count(x+1) == 0` / `cnt.find(x+1) == cnt.end()` / `cnt.contains(x+1)`（C++20）。Python 的 `Counter` 缺键只返回 0、**不落盘**，天然无此坑。细节见 §4、§8。

### 3.4 示例演算

![示例演算：建一趟表，逐键三查](images/2150_lonely_walkthrough.svg)

以示例 1（`nums = [10,6,5,8]`）走查（插图含建表与逐键过滤表，红字为击杀判定的邻位频次）：

| 键 $x$ | $\text{cnt}[x]$ | $\text{cnt}[x{+}1]$ | $\text{cnt}[x{-}1]$ | 判定 |
|--------|----------------|--------------------|--------------------|------|
| 10 | 1 | 0 | 0 | ✓ 孤独 |
| 6 | 1 | 0 | **1**（5 在场） | ✗ |
| 5 | 1 | **1**（6 在场） | 0 | ✗ |
| 8 | 1 | 0 | 0 | ✓ 孤独 |

答案 `[10, 8]`。再快速过一遍示例 2（`[1,3,5,3]`）：建表得 `{1:1, 3:2, 5:1}`；键 3 频次为 2，短路出局；键 1、5 的邻位 0/2、4/6 全部缺键 → `[1, 5]`。

## 4. 算法细节

1. **频次表选型**：值域未知时用哈希表（`unordered_map` / `Counter`）$O(n)$ 空间；本题值域 $[0, 10^6]$ 已知且不大，也可用长度 $10^6 + 3$ 的值域数组（见 §7 对照版）。
2. **C++ `operator[]` 的副作用**：`unordered_map::operator[]` 缺键时**默认构造并插入**。第二趟遍历键时用它查 `cnt[x+1]`，等于边遍历边插键——插入可能触发 rehash，**迭代器全体失效**，range-for 直接变成未定义行为。即使侥幸不 rehash，哈希表也被撑到至多 3 倍体积。判定一律用 `count` / `find` / `contains`（C++20），**只读不写**。
3. **Python `Counter` 的对照**：`Counter` 的 `__missing__` 返回 0 且**不写入**，`cnt[x+1] == 0` 这种写法在 Python 里既正确又安全——同一段判定逻辑在两种语言里安全性不同，跨语言搬运模板时要警觉。
4. **短路顺序**：先判 $c = 1$（遍历键时 $c$ 就在手边，零查询），失败立即跳过——重复值多的输入里省下大量邻位查询。
5. **第二趟遍历键还是遍历原数组？** 两者**输出完全相同**（§5 引理 3），且都**不会重复输出**（孤独值频次恰 1，怎么遍历都只被收入一次）。遍历键的优势：每个不同值只判定一次，判定次数 $O(\text{不同值数})$；遍历原数组的优势：无需访问哈希表键集，值域数组版可直接扫 `nums`（见下）。
6. **值域数组版无需去重集合**：数组本身按下标天然去重，第二趟直接遍历 `nums`（或扫一遍值域），靠引理 3 保证不重不漏——不必像直觉那样先建一个「出现过的值」的集合再判定。
7. **排序对照解**：排序后，$x$ 的同值副本与邻值 $x \pm 1$ 只可能出现在 $x$ 的**紧邻位置**，故每个位置只看左右两个邻居即可判定（§7 Python 对照版）。$O(n \log n)$ 时间，额外空间 $O(1)$（若允许原地排序），是不依赖哈希的备用解。

## 5. 正确性证明

**引理 1（判定等价）**：设 $c(v) = |\{ i : \text{nums}[i] = v \}|$（即频次表存储的内容），则 $x$ 是孤独数字 $\iff$ $c(x) = 1 \wedge c(x+1) = 0 \wedge c(x-1) = 0$。

**证明**：题面三条逐一翻译。①「$x$ 恰好出现一次」即 $c(x) = 1$（频次定义）。②「$x+1$ 在数组中出现」$\iff c(x+1) \ge 1$，取否定得「不在数组中」$\iff c(x+1) = 0$；③ 同理 $c(x-1) = 0$。三个条件以「且」连接，逐条等价故合取等价。∎

**引理 2（成对失效）**：若 $c(a) > 0$ 且 $c(a+1) > 0$，则 $a$ 与 $a+1$ 都不是孤独数字。

**证明**：对 $a$：$a+1$ 出现在数组中（$c(a+1) > 0$），违反条件②；对 $a+1$：$a$ 出现（$c(a) > 0$），违反条件③。两者无论自身频次是否为 1 均被否决。∎

**推论**：把出现过的值画在数轴上，任意两个**相邻的出现值**互毁。归纳可得：任何「连续出现段」（段内相邻值对都出现）整段全灭；孤独值只能出现在长度为 1 的孤立出现点上，且频次恰 1。

**引理 3（双遍历等价 / 无重复输出）**：第二趟无论遍历 `cnt` 的键集还是遍历原数组 `nums`，输出的多重集相同，且其中每个值恰出现一次。

**证明**：若 $x$ 孤独，则 $c(x) = 1$，即 $x$ 在 `nums` 中恰出现一次：遍历 `nums` 时 $x$ 被判定**恰一次**且判定通过；遍历键集时键 $x$ 存在（$c(x) \ge 1$）且被判定**恰一次**且通过。两种遍历各把 $x$ 加入恰一次。若 $x$ 不孤独，由引理 1 判定条件为假，两种遍历都不会加入它（重复值在遍历 `nums` 时被多次判定，但每次都失败，不产生输出）。故两种遍历输出相同且无重复。∎

**定理**：两趟算法返回的集合恰为 `nums` 中全部孤独数字。

**证明**：**可靠性**：输出的每个 $x$ 都通过了引理 1 的等价判定，故 $x$ 孤独。**完备性**：任何孤独值 $x$ 满足 $c(x) = 1 > 0$，必在键集中（也在 `nums` 中），由算法流程会被判定且通过，由引理 3 恰被加入一次、不遗漏、不重复。∎

> 💡 引理 1 说明本题是纯「条件直译」题——不存在任何搜索或贪心决策，比的是**翻译速度**与**实现稳度**；引理 2 是赛前可预制的直觉（相邻值互斥）；引理 3 直接免掉了「要不要去重」的犹豫，赛场价值是省一次 WA。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。第一趟 $n$ 次均摊 $O(1)$ 的哈希插入；第二趟至多 $\min(n, V+1)$ 个键，每键常数次 $O(1)$ 查询（短路后更少）。输出规模本身可达 $\Omega(n)$，渐近最优。
- **空间复杂度**：$O(\min(n, V+1))$，即频次表（最坏所有元素互异）。按 LeetCode 惯例返回数组不计入额外空间。值域数组版为 $O(V)$，$V = 10^6$ 时 `int` 数组约 4MB，需 `static` / 全局避免爆栈。
- **对照**：暴力 $O(n^2)$（$10^{10}$，超时）；排序版 $O(n \log n)$ / 额外 $O(1)$（可原地）；哈希版 $O(n)$ / $O(n)$，主推。

## 7. 参考代码

### C++（哈希表 + count，主推）

```cpp
class Solution {
public:
    vector<int> findLonely(vector<int>& nums) {
        unordered_map<int, int> cnt;
        cnt.reserve(nums.size());
        for (int x : nums) cnt[x]++;                 // 第一趟：建频次表

        vector<int> ans;
        for (auto& [x, c] : cnt) {                   // 第二趟：遍历键
            if (c == 1 && !cnt.count(x + 1) && !cnt.count(x - 1)) {
                ans.push_back(x);                    // count 只读，不插键不 rehash
            }
        }
        return ans;
    }
};
```

### C++（值域数组对照版）

```cpp
class Solution {
public:
    vector<int> findLonely(vector<int>& nums) {
        static int cnt[1000003];                     // 下标 = 值 + 1，覆盖 [-1, 1e6+1]
        memset(cnt, 0, sizeof(cnt));
        for (int x : nums) cnt[x + 1]++;             // 第一趟：建表（偏移 1）

        vector<int> ans;
        for (int x : nums) {                         // 第二趟：直接扫原数组，无需去重（引理 3）
            if (cnt[x + 1] == 1 && cnt[x + 2] == 0 && cnt[x] == 0) {
                ans.push_back(x);
            }
        }
        return ans;
    }
};
```

### Python（Counter）

```python
class Solution:
    def findLonely(self, nums: List[int]) -> List[int]:
        cnt = Counter(nums)                          # 第一趟：建频次表
        return [x for x, c in cnt.items()            # 第二趟：遍历键
                if c == 1 and cnt[x + 1] == 0 and cnt[x - 1] == 0]
```

### Python（排序对照版）

```python
class Solution:
    def findLonely(self, nums: List[int]) -> List[int]:
        a = sorted(nums)
        n = len(a)
        ans = []
        for i, x in enumerate(a):
            ok = True
            for j in (i - 1, i + 1):                 # 同值与邻值只可能紧邻
                if 0 <= j < n and a[j] in (x, x - 1, x + 1):
                    ok = False
                    break
            if ok:
                ans.append(x)
        return ans
```

## 8. 边界情况与易错点

1. **C++ `operator[]` 陷阱（头号坑）**：遍历哈希表时用 `cnt[x+1] == 0` 判缺键——插入新键、可能 rehash、迭代器失效、UB/偶发 RE。小样例不 rehash 时能过，隐蔽性极强；一律改用 `count` / `find` / `contains`。
2. **勿把「逻辑上等价」当「实现上等价」**：Python `Counter` 缺键返回 0 不写入；C++ `unordered_map::operator[]` 返回 0 **且插入**。同一行判定，一门语言安全、一门语言爆炸。
3. **值域边界的 ±1 查询**：$x = 0$ 查 $-1$、$x = 10^6$ 查 $10^6 + 1$。哈希表缺键即不存在，天然安全；**值域数组版**必须偏移（下标 $=$ 值 $+1$、长度 $10^6 + 3$），忘偏移直接越界——数组版高发 WA/RE 点。
4. **`[0,1]` → `[]`**：0 与 1 互为邻位成对失效（引理 2），**不要**给 0 写任何特判；`[0]` → `[0]`（−1 天然缺席）。
5. **全相同元素 `[5,5,5]` → `[]`**：频次 3 ≠ 1，短路出局；**单元素 `[7]` → `[7]`**：$n = 1$ 时它自动孤独（两邻位必然缺席）。
6. **无需去重集合**：孤独值频次恰 1，遍历键或原数组都恰收入一次（引理 3）——先建「出现过的值」集合再判定是多余开销。
7. **输出顺序任意**：题面明说 any order，别画蛇添足排序输出（白花 $O(k \log k)$）。
8. **Python 勿用 `nums.count(x)`**：单次 $O(n)$、总 $O(n^2)$，与暴力同罪；建一次 `Counter` 是唯一正解。
9. **溢出审计**：全程只做 $x \pm 1$（$\le 1000001$）与比较，`int` 富余，无溢出风险。
