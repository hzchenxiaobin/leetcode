# LeetCode 出现最频繁的偶数元素 题解

## 1. 题目概述

- **标题 / 题号**：出现最频繁的偶数元素（#2404，easy）
- **链接**：https://leetcode.cn/problems/most-frequent-even-element/
- **来源**：LeetCode 第 310 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给你一个整数数组 `nums`，返回其中出现**最频繁的偶数元素**；若频次最高的偶数有多个，返回其中**最小**的那个；若数组中不存在偶数，返回 `-1`。

**约束**：

- $1 \le \text{nums.length} \le 2000$
- $0 \le \text{nums}[i] \le 10^5$

> 💡 签到题的目标是**读题到 AC 压在 2 分钟内**。本题题面给了两把梯子：一是「频次聚合」天然可以一次遍历完成；二是**值域上界只有 $10^5$**——这意味着根本不需要哈希表，一个定长数组直接寻址即可，而「频次并列取最小」的副键比较可以完全被**升序扫描顺序**白嫖掉。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,2,2,4,4,1]
输出：2
解释：数组中的偶数元素为 0、2 和 4，其中 2 和 4 出现次数最多（各 2 次）。
      返回最小的那个，即返回 2。
```

**示例 2**

```text
输入：nums = [4,4,4,9,2,4]
输出：4
解释：4 出现 3 次，是频次最高的偶数元素（也是唯一频次超过 1 的偶数）。
```

**示例 3**（无偶数）

```text
输入：nums = [29,47,21,41,13,37,25,7]
输出：-1
解释：数组中不存在偶数元素。
```

## 3. 解题思路

### 3.1 暴力思路：逐值重扫与排序

最朴素的写法是**对每个不同的偶数值重新扫一遍数组**数出现次数：对 $v \in \{$数中的偶数$\}$，花 $O(n)$ 数一遍，再在 $(c, -v)$ 上取最。不同偶数值最多 $\min(n, 5 \times 10^4)$ 个，总复杂度 $O(n^2)$——$n \le 2000$ 时约 $4 \times 10^6$ 次比较，能 AC，但把「同一元素被反复清点」的浪费背在身上。

折中方案是**先排序再扫**：$O(n\log n)$ 排完后，等值元素相邻，扫一遍合并出每个值的频次，同时维护「频次最大、并列取最小」。比逐值重扫快，但排序本身对「只要频次」这个目标来说是多余功——频次信息在原始数组里一次线性扫描就能全部收集。

> ⚠️ 两个暴力方案都没有用到题面白送的两个条件：**值域 $\le 10^5$**（可以定长数组直接寻址）与**并列取最小**（副键恰好是「值」，与下标升序扫描同构）。用上它们，算法压缩成两遍线性扫描、一个 `if`。

### 3.2 核心观察：值域直接寻址 + 升序扫描白嫖副键

![核心观察：值域 ≤ 1e5 用 cnt 数组直接寻址；升序扫描偶下标 + 严格大于，让并列取最小的副键比较被扫描顺序免费取代](images/mfee310_value_domain_concept.svg)

**观察一（计数零成本）**：$0 \le \text{nums}[i] \le 10^5$，开一个 `cnt[100001]`，`cnt[x]++` 就是 $O(1)$ **直接寻址**——没有哈希函数、没有冲突、没有桶，连奇偶过滤都可以省（奇数下标的计数照样写入，但第二遍只读偶数下标，白计无副作用）。

**观察二（副键免费）**：答案是双键 $(\text{频次最大},\ \text{值最小})$ 上的最值。若**按下标（即值）升序**扫描偶数下标 $v = 0, 2, 4, \dots, 10^5$，并只在该值的频次**严格大于**当前最优时更新：

$$
\text{更新当且仅当}\quad \text{cnt}[v] > \text{best}
$$

那么频次并列时，后扫到的（更大的）$v$ 永远过不了严格 `>`，**先扫到的更小值天然保留**——「并列取最小」这个副键约束被扫描顺序本身满足，一个 `if` 只比频次，值序白嫖。这是「升序遍历 + 严格大于」的经典配合，与需要显式双键 `c > best || (c == best && v < ans)` 的哈希版形成对照。

### 3.3 算法流程

![算法流程：第一遍遍历 nums 执行 cnt[x]++；第二遍 v 从 0 步长 2 升序扫描，cnt[v] > best 则更新，v 超过 1e5 结束返回 ans，无偶数时 ans 保持 -1](images/mfee310_algorithm_flow.svg)

两遍扫描，零特判：

1. **第一遍（计数）**：遍历 `nums`，执行 `cnt[x]++`。奇数也照计不误——它们占据的奇数下标在第二遍永远不会被读取；
2. **第二遍（取最）**：令 `best = 0, ans = -1`，对 $v = 0, 2, 4, \dots, 10^5$ 升序扫描，若 `cnt[v] > best` 则 `best = cnt[v], ans = v`；
3. **兜底**：若数组中没有偶数，所有偶下标的 `cnt` 均为 $0$，`0 > 0` 恒假，循环空转，`ans` 保持初值 $-1$——「不存在返回 $-1$」由初值天然覆盖。

### 3.4 示例演算

![示例演算：nums=0,1,2,2,4,4,1 过滤偶数后 cnt[0]=1、cnt[2]=2、cnt[4]=2，升序扫描 v=0 更新 ans=0、v=2 更新 ans=2、v=4 因 2>2 不成立保持，最终答案 2](images/mfee310_example_walkthrough.svg)

以示例 1 `nums = [0,1,2,2,4,4,1]` 演算：

**第一步——计数**（奇数照样写入，只是从不读取）：

| 偶数值 $v$ | 0 | 2 | 4 |
|------------|---|---|---|
| 频次 $\text{cnt}[v]$ | 1 | 2 | 2 |

**第二步——升序取最**（初值 $best=0,\ ans=-1$）：

| 扫到 $v$ | 判断 | 更新后 $(best, ans)$ |
|----------|------|----------------------|
| $0$ | $1 > 0$ ✅ | $(1,\ 0)$ |
| $2$ | $2 > 1$ ✅ | $(2,\ 2)$ |
| $4$ | $2 > 2$ ✗ | $(2,\ 2)$ 不变 |

最终 $ans = 2$ ✓。值 2 与 4 频次并列（各 2 次），但 $4$ 在升序扫描中后到、过不了严格 `>`，更小的 $2$ 胜出。

- **示例 2** $[4,4,4,9,2,4]$：$\text{cnt}[4] = 4 > \text{cnt}[2] = 1$，扫到 $v=2$ 时 $(1, 2)$，扫到 $v=4$ 时 $4 > 1$ 更新为 $(4, 4)$，答案 $4$ ✓。
- **示例 3** 全奇数：偶下标 `cnt` 全 $0$，`0 > 0` 恒假，`ans` 保持 $-1$ ✓。

## 4. 算法细节

1. **数组开多大**：值域 $[0, 10^5]$ **闭区间**，且 $10^5$ 本身是偶数、$0$ 也是偶数，故数组必须开 `100001` 个格子（下标 $0 \sim 100000$），循环上界 `v <= 100000`。开成 `100000` 会恰好丢掉值 $10^5$。
2. **计数时不判奇偶**：`cnt[x]++` 对奇数也执行，正确性不受影响——第二遍只读偶数下标，奇数格子的值是死数据。若想省那几个写入，可写 `if ((x & 1) == 0) ++cnt[x];`，两者皆可，前者更短。
3. **只扫偶下标**：`for (int v = 0; v <= 100000; v += 2)`，扫描量减半（$5 \times 10^4 + 1$ 个下标）。
4. **严格 `>` 的语义**：这是「并列取最小」的全部实现。若手滑写成 `>=`，并列时更大的 $v$ 会覆盖，示例 1 将错答 $4$。
5. **初值**：`best = 0`（频次不会为负，$0$ 表示「尚未见到任何偶数」）；`ans = -1`（空偶数集的兜底返回值）。非空时首个 $\text{cnt}[v] \ge 1 > 0$ 必触发更新，免去对 $-1$ 的特殊比较。
6. **哈希版（值域无关时）**：若值域大到无法开数组，退回 `unordered_map` + 显式双键 `c > best || (c == best && v < ans)`——此时遍历无序，副键必须自己比（见本文参考代码第二版）。

## 5. 正确性证明

**引理 1**（计数正确性）：第一遍结束后，对每个下标 $v \in [0, 10^5]$，$\text{cnt}[v]$ 等于值 $v$ 在 `nums` 中的出现次数。

**证明**：初始时所有 $\text{cnt}[v] = 0$。遍历中每个元素 $x$ 恰好执行一次 $\text{cnt}[x]{+}{+}$，即恰好使其自身下标的计数加 $1$、不影响其他下标。对遍历的元素个数做归纳：处理完前 $k$ 个元素后，$\text{cnt}[v]$ 等于前 $k$ 个元素中值 $v$ 的个数。全部处理完即得结论。∎

**引理 2**（升序 + 严格 `>` 保留并列最小）：设 $C^\* = \max\{\text{cnt}[v] : v \text{ 为偶数}\}$，$S = \{v \text{ 为偶数} : \text{cnt}[v] = C^\*\}$。若 $S \ne \varnothing$，则第二遍循环结束后 $ans = \min S$，$best = C^\*$。

**证明**：设 $v_0 = \min S$。循环按升序访问偶数下标，在到达 $v_0$ 之前，所有已访问的 $v' < v_0$ 均有 $\text{cnt}[v'] < C^\*$（否则与 $v_0 = \min S$ 矛盾），故期间 `best` 只取过小于 $C^\*$ 的值（或保持初值 $0 < C^\*$，注意 $C^\* \ge 1$ 因 $S \ne \varnothing$）。到达 $v_0$ 时 $\text{cnt}[v_0] = C^\* > best$ 成立，触发更新，此后 $best = C^\*$、$ans = v_0$。对之后任何 $v > v_0$：$\text{cnt}[v] \le C^\* = best$，严格 `>` 不成立，永不覆盖。故循环结束时 $ans = v_0 = \min S$。∎

**定理**：若 `nums` 中存在偶数，算法返回「频次最高的偶数中最小的那个」；否则返回 $-1$。

**证明**：若存在偶数，则答案即 $\min\{v : v \text{ 偶},\ \text{cnt}[v] = C^\*\}$，由引理 1 计数正确、引理 2 取最正确，算法返回该值。若不存在偶数，则一切偶下标 $\text{cnt}[v] = 0$，`0 > 0` 恒假，循环体从未执行，`ans` 保持初值 $-1$ 返回。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + V)$，其中 $V = 10^5$——第一遍 $n$ 次计数（$n \le 2000$），第二遍 $\lfloor V/2 \rfloor + 1 \approx 5 \times 10^4$ 个偶下标扫描，每步 $O(1)$。本题规模下 $V$ 项主导，但也就是几万次数组读取，微秒级。
- **空间复杂度**：$O(V)$——定长计数数组 $10^5 + 1$ 个 `int`，约 $400\,\text{KB}$，静态分配无压力。
- **对照**：哈希表版 $O(n)$ 时间 / $O(n)$ 空间，值域无关、$n$ 与值域悬殊时更省；排序版 $O(n\log n)$ 时间 / $O(1)$ 空间，无需额外数组但要写合并逻辑。本题 $n \le 2000$、$V \le 10^5$，三种做法全部轻松 AC，值域版胜在**代码最短、分支最少、无哈希常数**，是签到题的最短正确路径。

## 7. 参考代码

### C++（值域直接寻址，推荐）

```cpp
class Solution {
public:
    int mostFrequentEven(vector<int>& nums) {
        vector<int> cnt(100001);
        for (int x : nums) ++cnt[x];          // 奇数照计，反正不读
        int ans = -1, best = 0;
        for (int v = 0; v <= 100000; v += 2)  // 只扫偶下标，升序
            if (cnt[v] > best) {              // 严格 >，并列留最小
                best = cnt[v];
                ans = v;
            }
        return ans;                           // 无偶数时保持 -1
    }
};
```

### C++（哈希表，值域无关的通用版）

```cpp
class Solution {
public:
    int mostFrequentEven(vector<int>& nums) {
        unordered_map<int, int> freq;
        for (int x : nums)
            if ((x & 1) == 0) ++freq[x];
        int ans = -1, best = 0;
        for (auto& [v, c] : freq)
            if (c > best || (c == best && v < ans))  // 无序遍历须显式双键
                tie(best, ans) = make_pair(c, v);
        return ans;
    }
};
```

### Python（Counter + 键函数）

```python
class Solution:
    def mostFrequentEven(self, nums: List[int]) -> int:
        cnt = Counter(x for x in nums if x % 2 == 0)
        return min(cnt, key=lambda v: (-cnt[v], v)) if cnt else -1
```

> 💡 Python 的 `min` 在键 $(-\text{cnt}[v],\ v)$ 上取最小，即「频次最大、值最小」，一行完成双键取最；空 `Counter` 单独判 `-1`。值域版写法（`cnt = [0] * 100001` + `range(0, 100001, 2)`）同样可行，但 Python 下两者性能差异可忽略，挑顺手的写。

## 8. 边界情况与易错点

1. **$0$ 是偶数**：$0 \bmod 2 = 0$，它参与计数与竞选。示例 1 中 $0$ 出现 $1$ 次、频次不敌 $2$ 和 $4$ 才落选——若在过滤时把 $0$ 一并丢掉，碰上 `nums = [0]` 这类输入会错答 $-1$。
2. **值域上界 $10^5$ 恰是偶数**：数组开 `100001`、循环写到 `v <= 100000`。开成 `100000` 个格子会把值 $10^5$ 挤出去（越界或漏计，取决于写法），这是值域法最典型的差一错误。
3. **全奇数返回 $-1$**：不需要任何 `if` 特判——`best = 0` 初值 + 严格 `>` 让循环对全零计数天然空转，`ans` 兜底返回 $-1$。特判逻辑藏在初值里，是「零分支特判」的小范例。
4. **严格 `>` 而非 `>=`**：`>=` 会让并列时更大的值覆盖，示例 1 将错答 $4$。反过来，若题目改成「并列取最大」，把扫描倒序或改成 `>=` 即可——**副键方向与扫描方向必须配套**。
5. **并列取的是「值最小」，不是「先出现」**：值域版按下标升序，两者恰好一致；但哈希版遍历无序，「先出现」毫无意义，必须显式写 `c == best && v < ans` 分支。把值域版的直觉直接搬到无序遍历上，是哈希版最常见的 WA 来源。
6. **$n = 1$**：单元素数组，`[x]` 中 $x$ 偶返回 $x$、奇返回 $-1$；特别地 `[0]` 返回 $0$ 而非 $-1$。两个初值分支天然覆盖，无需处理。
7. **签到节奏**：本题读题 $10$ 秒内应锁定「频次表 + 双键取最」，再花 $10$ 秒注意到值域 $\le 10^5$ 换直接寻址、升序扫描白嫖副键——之后就是无脑敲代码。Q1 的价值不在难度，在于**把读题到 AC 的管道磨到最短**，给后面三题留时间。
