# LeetCode 最长递增子序列 II 题解

## 1. 题目概述

- **标题 / 题号**：最长递增子序列 II（#2407，hard）
- **链接**：https://leetcode.cn/problems/longest-increasing-subsequence-ii/
- **来源**：LeetCode 第 310 场周赛 Q4
- **难度**：困难
- **标签**：线段树、动态规划、树状数组、值域分块、数组

**题意**：给定整数数组 `nums` 与整数 $k$，在 `nums` 中找一个**子序列**，使其**严格递增**且**相邻元素的差值不超过 $k$**，返回这类子序列的最大长度。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums}[i],\, k \le 10^5$

> 💡 **复盘视角**：这是 300 题（LIS）加上「相邻差值 $\le k$」的约束升级版，全场的压轴分水岭。赛点的全部难度浓缩在一处跳跃：**经典 LIS 的两大利器（$O(n \log n)$ 贪心+二分 `tails`、树状数组前缀维护）在这里双双失效**，因为约束从「前驱 $< x$ 的前缀」变成了「前驱 $\in [x-k,\, x-1]$ 的有界窗口」——前缀结构对付不了带下界的区间查询，必须请出**值域线段树**做「区间查 max + 单点更新 max」。识别出这条从「按下标 DP」到「按值域维护 DP」的迁移路径，本题就是一个 15 分钟的线段树模板题；识别不出，就会在 `tails` 的各种魔改里打转出不来。

## 2. 示例

**示例 1**

```text
输入：nums = [4,2,1,4,3,4,5,8,15], k = 3
输出：5
解释：最长子序列 [1,3,4,5,8]，相邻差 2,1,1,3 均不超过 3。
      [1,3,4,5,8,15] 不合法：15 − 8 = 7 > 3。
```

**示例 2**

```text
输入：nums = [7,4,5,1,8,12,4,7], k = 5
输出：4
解释：最长子序列 [4,5,8,12]，相邻差 1,3,4 均不超过 5。
```

**示例 3**（构造的反例：验证「太远」的强前驱接不上）

```text
输入：nums = [5,1,6,2,7], k = 1
输出：3
解释：最长子序列 [5,6,7]（相邻差恰为 1）。
      虽然前缀里有更小的 1 和 2，但 6 − 1 = 5 > 1、7 − 2 = 5 > 1，
      它们离 6/7「太远」——最优链反而从 5 起步。
```

## 3. 解题思路

### 3.1 暴力思路：朴素 DP O(n²)

延续 300 题的经典定义：$f[i]$ = 以 $\text{nums}[i]$ 结尾、满足约束的最长子序列长度。转移枚举全部前驱：

$$
f[i] \;=\; 1 + \max\bigl(\{\, f[j] : j < i,\ \text{nums}[j] < \text{nums}[i],\ \text{nums}[i] - \text{nums}[j] \le k \,\} \cup \{0\}\bigr)
$$

答案为 $\max_i f[i]$。$n = 10^5$ 时 $n^2 = 10^{10}$ 次判断，必然 TLE。瓶颈依旧是那个老问题：**为每个 $i$ 线性扫描所有候选前驱 $j$**。

### 3.2 为什么 300 题的两大利器在这里失效

**贪心 + 二分（`tails`）失效**：`tails[m]` 维护「长度为 $m+1$ 的子序列的最小末尾」，其正确性立于信条「**末尾越小，后面越好接**」。差值约束摧毁了这条信条——末尾更小可能意味着**离下一个元素太远**。用示例 3 的数据 `nums = [5,1,6,2,7], k = 1` 走一遍贪心：

| 步骤 | 元素 | 经典贪心的动作 | tails 状态 |
|------|------|----------------|-----------|
| 1 | 5 | 新增长度 1 | `[5]` |
| 2 | 1 | 1 < 5，替换——「更小的末尾更好」 | `[1]` |
| 3 | 6 | 想接长度 1：末尾是 1，但 $6-1=5 > k$，**接不上** | 卡死 |
| 4 | 2 | 同理 $2-1=1 \le k$ 接上 | `[1,2]` |
| 5 | 7 | $7-2=5 > k$，接不上 | `[1,2]` |

第 3 步的替换把唯一能承接 6 的末尾 5 永久丢掉了，贪心最终困在长度 2，而正确答案是 3（`[5,6,7]`）。**问题不在实现，在范式**：任何「每长度只留一个末尾」的压缩都会丢信息——窗口约束下，不同末尾各有各的「可达带」，谁也无法代替谁。

**树状数组（BIT）失效**：300 题家族中 673（LIS 计数）、1964 等题常用 BIT 按值域维护前缀最值，因为无约束时前驱集合是前缀 $[1, x-1]$，`query(x-1)` 一步到位。本题前驱集合是**任意区间** $[x-k,\, x-1]$，而 BIT 的区间最值需要 `query(R) - query(L-1)` 式的**减法拆解**——$\max$ 不可逆、不可减，这条路从代数上就封死了。

### 3.3 核心观察：合法前驱 = 值域上的一段连续窗口

![核心观察：数轴上 x=8、k=3 时合法前驱窗口为 [5,7]，而 300 题的 k=∞ 对应前缀 [1,7]；x=15 的窗口 [12,14] 把 8 挡在窗外](images/lis310_window_concept.svg)

**观察一（约束只看值，不看下标）**：转移条件里「$\text{nums}[j] < \text{nums}[i]$ 且 $\text{nums}[i] - \text{nums}[j] \le k$」只约束**值对**，与下标距离无关。把它翻译到数轴上：设 $x = \text{nums}[i]$，合法前驱值 $y$ 恰好构成连续区间

$$
x - k \;\le\; y \;\le\; x - 1 \quad\Longleftrightarrow\quad y \in [x-k,\ x-1].
$$

「严格递增」砍掉右端（$y < x$），「差值约束」砍掉左端（$y \ge x-k$）——**双条件夹出一段窗口**，这正是 §3.2 两条失效路线的统一病灶：窗口有下界，前缀结构（`tails`、BIT）表达不了。

**观察二（dp 从下标搬到值域）**：既然转移只看值，就把状态改键：$dp[v]$ = **当前已处理元素中**、以值 $v$ 结尾的最长合法子序列长度。转移变成

$$
dp[\text{nums}[i]] \;=\; 1 + \max_{v \in [\,\max(1,\,x-k),\; x-1\,]} dp[v],
$$

**区间最大值查询** + **单点 max 更新**——线段树的教科书级接口，各 $O(\log V)$。

**观察三（下标顺序免费获得）**：$j < i$ 的顺序约束无需显式判断——只要**按 `nums` 原顺序流式处理**，处理 $\text{nums}[i]$ 时树里装着的必然全是下标更早的元素。这是「在线数据结构 + 流式输入」的经典配合，也是值域建模成立的前提（若约束依赖下标距离，此路不通）。

**观察四（值域有界，免离散化）**：$1 \le \text{nums}[i] \le 10^5$，直接开 $O(V)$ 的线段树即可，$4V$ 个 `int` 约 1.6 MB。值域飙到 $10^9$ 时先排序去重做坐标压缩，逻辑不变。

### 3.4 算法流程

![算法流程：五步主循环（取 x、算窗口、查区间 max、cur=best+1、单点 max 更新）配合值域线段树的查询与更新路径](images/lis310_segment_tree_flow.svg)

对每个 $x = \text{nums}[i]$（$i$ 从左到右）执行五步：

1. **取值**：$x = \text{nums}[i]$；
2. **定窗**：$L = \max(1,\, x-k)$，$R = x-1$；
3. **查询**：`best` = 线段树上区间 $[L, R]$ 的最大值（$L > R$ 时 `best = 0`）；
4. **接链**：`cur = best + 1`，即以 $x$ 结尾的最长长度；
5. **更新**：单点 $dp[x] \leftarrow \max(dp[x],\, \text{cur})$，自底向上刷新祖先；同时 `ans = max(ans, cur)`。

**不变式**：处理 $\text{nums}[i]$ 之前，树上 $dp[v] = \max\{f[j] : j < i,\ \text{nums}[j] = v\}$（空集为 0）。查询窗口拿到的 `best` 必来自下标更早的元素——顺序约束由流式遍历自动满足。

### 3.5 示例演算

![示例 1 演算：九步流式处理，每步的窗口、best 来源、cur 与 dp 更新；第 5 步 dp[4] 从 2 升到 3，第 8 步 15 的窗口 [12,14] 把 8 挡在窗外](images/lis310_example_walkthrough.svg)

示例 1（`nums = [4,2,1,4,3,4,5,8,15], k = 3`，见上图）三个关键看点：

- **第 2 步**（$x = 1$）：窗口 $[\max(1, -2), 0] = [1, 0]$ 为空，`best = 0`——最小值自带「无前驱」语义，无需特判；
- **第 5 步**（第二个 $4$）：查询 $[1,3]$ 得 `best = 2`（来自 $dp[3] = 2$），`cur = 3`，把 $dp[4]$ 从 2 **升级**为 3——同值元素多次出现时单点更新取 max，保住更强的一次；
- **第 9 步**（$15$）：窗口 $[12, 14]$ 全为 0，`cur = 1`——$dp[8] = 5$ 虽强，但 $15 - 8 = 7 > k$，窗口左端 $x - k$ 把它精确排除。**窗口模型同时编码了「太小的接得上」与「太远的接不上」两种语义。**

最终 $dp[8] = 5$，对应子序列 $[1,3,4,5,8]$ ✓。

示例 2（`nums = [7,4,5,1,8,12,4,7], k = 5`）走查要点：$dp[7]{=}1 \to dp[4]{=}1 \to dp[5]{=}2 \to dp[1]{=}1 \to dp[8]{=}3 \to dp[12]{=}4 \to$ 第二个 $4$ 查 $[1,3]$ 得 $dp[1]{=}1$、`cur=2`、$dp[4]$ 升为 $2 \to$ 第二个 $7$ 查 $[2,6]$ 得 $dp[4]{=}2$、`cur=3`、$dp[7]$ 升为 $3$。答案 $4$，子序列 $[4,5,8,12]$ ✓。

## 4. 算法细节

1. **状态重键是全局的关键一步**：从「$f[i]$ 按下标」改为「$dp[v]$ 按值」，转移里的前驱集合才从「散落在各下标」变成「值域上一段连续区间」，线段树才有用武之地。判断此类迁移是否合法的试金石：**约束是否只依赖元素值**（本题是）而**不依赖下标距离**（若是「下标间隔 $\le d$」之类的约束，流式维护就不成立，得另请窗口结构）。
2. **窗口端点的两个边界**：$R = x - 1$ 体现「严格递增」（写 $x$ 就变「非递减」）；$L = \max(1, x-k)$ 防止 $x \le k$ 时窗口滑出值域下界。$x = 1$ 时 $L = 1 > R = 0$，查询需返回 0（递归版天然由 `qr < l` 分支兜住，自底向上版由 `l < r` 循环不进入兜住）。
3. **单点更新取 `max` 的语义与「其实直接赋值也对」**：`dp[x] ← max(dp[x], cur)` 对应「以值 $x$ 结尾」在已处理前缀上的历史最强。微妙之处：同值元素**后出现的**，其合法前驱集合是**先出现者的超集**（值窗口相同、可选下标更多），故 $F$ 值只会不减——直接赋值碰巧也正确。但这一论证依赖「前驱集合单调扩张」的窗口特性，取 `max` 是不依赖该论证的稳健写法，赛时不必在这里省一次比较。
4. **两种线段树实现**：C++ 用递归板子（`query(p,l,r,ql,qr)` / `update(p,l,r,i,v)`，闭区间约定），通用、不易写错；Python 用**自底向上数组版**（叶子从 $n$ 起，$n$ 为 $\ge V+1$ 的 2 的幂）——$10^5 \times 17 \times 2$ 次递归调用在 Python 里可能吃 3 秒以上，迭代版才是 Python 的赛时正解。
5. **空间账本**：递归版开 $4V$（$V = \max(\text{nums})$）个 `int`；自底向上版开 $2n \le 4V$。$V = 10^5$ 时约 0.8~1.6 MB，无压力。注意按 $V$ 而非题目上界 $10^5$ 开树，全是小值时能省则省（开满 $10^5$ 也只是 0.4 MB 的事，赛时随意）。
6. **`ans` 与树根等价**：根节点管辖整个值域，存的就是 $\max_v dp[v]$，遍历结束读根即答案。用 `ans` 变量逐元素维护的好处是语义直白、且不依赖「树根存在」（动态开点版本无实体根值），两者等价。
7. **树状数组的替代方案**：$\max$ 不可减，BIT 无法拆 $[L, R]$。真不想写线段树时的候补是**值域分块**：块大小 $B$，散块逐值扫 $O(B)$、整块查块最大值 $O(V/B)$，单点更新时块内最大值 $O(1)$ 重算，总 $O(n \cdot (B + V/B))$，取 $B = \sqrt{V}$ 约 $6 \times 10^7$ 次操作，C++ 可过、Python 勉强。官方标签里的「单调队列」即对应此类分块/离线变体——但线段树是思维与编码成本最低的主路。
8. **大值域扩展**：$\text{nums}[i]$ 升到 $10^9$ 时，排序去重离散化把 $V$ 压到 $n$，其余逻辑一字不改；$10^{18}$ 或强制在线则上动态开点线段树，每次操作 $O(\log V_{\max}) \approx 60$ 层。

## 5. 正确性证明

**引理 1**（窗口刻画）：设子序列相邻两元素为 $y$（前）与 $x$（后）。二元组 $(y, x)$ 满足「严格递增且差值 $\le k$」当且仅当 $x - k \le y \le x - 1$。

**证明**：条件组即 $y < x$ 且 $x - y \le k$。由 $y < x$ 与整数性得 $y \le x - 1$；$x - y \le k$ 即 $y \ge x - k$。两个不等式恰为 $y \in [x-k,\, x-1]$，且每步均为等价改写。∎

**引理 2**（流式不变量）：按 $i$ 从 $0$ 到 $n-1$ 处理，记 $F(i)$ 为以下标 $i$ 结尾的最长合法子序列长度。则处理 $\text{nums}[i]$ **之前**，对每个值 $v \in [1, V]$，树上 $dp[v] = \max\{ F(j) : j < i,\ \text{nums}[j] = v \}$（空集取 $0$）。

**证明**：对 $i$ 归纳。$i = 0$ 时树全 0，集合皆空，成立。设处理 $\text{nums}[i-1]$ 前不变量成立，考察第 $i-1$ 步（即处理 $\text{nums}[i-1] = x$，记 $j^\ast = i-1$）：

- **查询不改树**，仅需证更新后的树满足「处理 $\text{nums}[i]$ 前」的断言。
- 更新只触碰叶子 $dp[x]$：$dp[x] \leftarrow \max(dp_{\text{old}}[x],\, \text{cur})$，祖先仅重新聚合，其余叶子不变。由归纳假设 $dp_{\text{old}}[x] = \max\{ F(j) : j < i-1,\ \text{nums}[j] = x \}$；若归纳地已知 $\text{cur} = F(i-1)$（见定理证明），则新值 $= \max\{\max\{F(j) : j < i-1,\ \text{nums}[j] = x\},\ F(i-1)\} = \max\{ F(j) : j < i,\ \text{nums}[j] = x \}$（因 $\text{nums}[i-1] = x$）。其余值 $v \ne x$ 的集合 $\{j < i : \text{nums}[j] = v\} = \{j < i-1 : \text{nums}[j] = v\}$ 未变。∎

**引理 3**（转移刻画）：$F(i) = 1 + \max\bigl(\{ F(j) : j < i,\ \text{nums}[j] \in [x-k,\, x-1] \} \cup \{0\}\bigr)$，其中 $x = \text{nums}[i]$。

**证明**：**（$\ge$）** 取窗口内任意 $j$，其对应的最优子序列末尾元素为 $\text{nums}[j] \in [x-k, x-1]$；由引理 1，将 $x$ 追加其后得到合法子序列（$j < i$ 保序），长度 $F(j) + 1$，故 $F(i) \ge F(j) + 1$，取 max 亦然。**（$\le$）** 设 $F(i)$ 对应子序列为 $a_1, \dots, a_{F(i)}$（$a_{F(i)} = \text{nums}[i] = x$）。若 $F(i) = 1$ 显然（右边 $\le 1 + 0$）。若 $F(i) \ge 2$，去掉末尾得合法子序列 $a_1, \dots, a_{F(i)-1}$，其结尾下标 $j < i$ 且 $\text{nums}[j] = a_{F(i)-1} \in [x-k, x-1]$（引理 1），长度为 $F(i) - 1 \le F(j)$，故 $F(i) \le F(j) + 1 \le$ 右边。∎

**定理**：算法第 $i$ 步计算出的 $\text{cur} = F(i)$，且返回值 $\max_i \text{cur}_i = \max_i F(i)$ 为全局最优。

**证明**：对 $i$ 联立归纳「$\text{cur}_i = F(i)$」与引理 2。第 $i$ 步查询窗口 $[L, R] = [\max(1, x-k),\, x-1]$：由引理 2（归纳成立），`best` $= \max\{ F(j) : j < i,\ \text{nums}[j] \in [L, R] \}$——与引理 3 的窗口相比仅差 $[x-k, \max(1,x-k))$ 这段 $\le 0$ 的空值域（其中 $dp[v] = 0$ 不影响 max）。于是 $\text{cur} = \text{best} + 1 = 1 + \max(\cdots \cup \{0\}) = F(i)$（引理 3），且引理 2 所需的更新前提「$\text{cur} = F(i)$」随之成立，两个归纳互锁推进。

任何非空子序列必有结尾下标，故全局最优 $= \max_i F(i) = \max_i \text{cur}_i$，即返回值。∎

> 💡 本题的证明骨架与同场 Q3（将区间分为最少组数）同属「**归纳不变量 + 等价刻画**」谱系：Q3 用「堆大小 $\le$ 深度」的不变量夹逼出最优，本题用「树状态 = 已处理前缀的最优值封存」的流式不变量锁死转移正确性。流式不变量是所有「在线数据结构加速 DP」类问题的通用证明范式——数据结构里存什么、何时存、存的是不是恰好够下一步用，三问皆由它回答。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log V)$，$V = \max(\text{nums}) \le 10^5$——每个元素一次区间查询 + 一次单点更新，各走 $O(\log V) \approx 17$ 层；$n = 10^5$ 时约 $3.4 \times 10^6$ 次节点访问，C++ 实测 $10\,\text{ms}$ 量级。预处理 $V = \max$ 为 $O(n)$。
- **空间复杂度**：$O(V)$——递归版线段树 $4V$ 个 `int`（约 1.6 MB），自底向上版 $2n' \le 4V$；另有 $O(\log V)$ 递归栈（迭代版无）。
- **与各替代方案的对比**：朴素 DP $O(n^2) = 10^{10}$ 不可行；值域分块 $O(n\sqrt{V}) \approx 6 \times 10^7$，C++ 勉强可过但无优势；离散化线段树 $O(n \log n)$ 与本题 $O(n \log V)$ 同阶（$n$ 与 $V$ 同阶时），值域直接开树省一次排序。
- **赛时取舍**：$n$ 与 $V$ 双双 $10^5$ 且 $V$ 有明确上界，是「值域线段树」的明示信号；递归板子 30 行、自底向上 25 行，写熟后 10 分钟内可交。

## 7. 参考代码

### C++（递归线段树，赛时模板）

```cpp
class Solution {
    int n;
    vector<int> mx;
    void update(int p, int l, int r, int i, int v) {
        if (l == r) { mx[p] = max(mx[p], v); return; }
        int m = (l + r) / 2;
        i <= m ? update(2 * p, l, m, i, v) : update(2 * p + 1, m + 1, r, i, v);
        mx[p] = max(mx[2 * p], mx[2 * p + 1]);
    }
    int query(int p, int l, int r, int ql, int qr) {
        if (qr < l || r < ql) return 0;          // 不相交 → 不贡献
        if (ql <= l && r <= qr) return mx[p];    // 整段覆盖 → 直接拿
        int m = (l + r) / 2;
        return max(query(2 * p, l, m, ql, qr), query(2 * p + 1, m + 1, r, ql, qr));
    }
public:
    int lengthOfLIS(vector<int>& nums, int k) {
        int V = *max_element(nums.begin(), nums.end());
        n = V; mx.assign(4 * V, 0);
        int ans = 0;
        for (int x : nums) {
            int best = query(1, 1, V, max(1, x - k), x - 1);  // 窗口 [x-k, x-1]
            ans = max(ans, best + 1);
            update(1, 1, V, x, best + 1);                      // 单点取 max 更新
        }
        return ans;
    }
};
```

### Python（自底向上数组线段树，避开递归开销）

```python
class Solution:
    def lengthOfLIS(self, nums: List[int], k: int) -> int:
        V = max(nums)
        n = 1
        while n <= V:                  # n 为 >= V+1 的 2 的幂，叶子从下标 n 起
            n <<= 1
        tree = [0] * (2 * n)
        ans = 0
        for x in nums:
            L, R = max(1, x - k), x - 1
            best = 0
            l, r = L + n, R + n + 1    # 半开区间 [l, r) 的经典迭代查询
            while l < r:
                if l & 1:
                    best = max(best, tree[l]); l += 1
                if r & 1:
                    r -= 1; best = max(best, tree[r])
                l >>= 1; r >>= 1
            cur = best + 1
            ans = max(ans, cur)
            p = x + n                  # 单点更新：取 max 后沿祖先链重聚合
            if cur > tree[p]:
                tree[p] = cur
                p >>= 1
                while p:
                    tree[p] = max(tree[2 * p], tree[2 * p + 1])
                    p >>= 1
        return ans
```

> 💡 两版代码已对拍验证：除三个官方示例外，与 $O(n^2)$ 暴力在 3000 组随机数据（$n \le 40$，$V \le 60$，$k \le 30$）上逐组一致；C++ 版在 $n = V = 10^5$、$k = 10^5$ 的随机大数据上实测约 0.02 s。

## 8. 边界情况与易错点

1. **`tails` 贪心的尸体要绕开**（头号坑）：赛时最容易犯的不是线段树写错，而是先用 300 题模板交一发再 debug。用 `nums = [5,1,6,2,7], k = 1` 心算即可自检（贪心得 2，正解 3）——想清楚「末尾越小越好」为什么失效，再动手写线段树。
2. **窗口右端是 $x-1$ 不是 $x$**：「严格递增」要求 $y < x$。写成 $[x-k, x]$ 会把「非递减」也放进前驱，在 `nums = [4,4,4], k = 1` 这类数据上错答 3（正解 1）。
3. **窗口左端要 `max(1, x-k)`**：$x \le k$ 时 $x - k \le 0$ 越出值域下界。递归版靠 `ql ≥ 1` 的传入兜住；自底向上版若忘 clamp，`L + n` 会负数下标直接 RE。
4. **$x = 1$ 的空窗口**：$L = 1 > R = 0$。递归版 `qr < l` 返回 0、迭代版 `l ≥ r` 循环不进，都天然给出 `best = 0`——但若手工特判写反（如 `if L <= R` 分支里漏掉 else 置 0），最小值元素就会读到脏数据。
5. **单点更新忘记取 max**：直接赋值在本题碰巧也对（§4 第 3 条的「前驱集合单调扩张」论证），但那是运气不是正确性——养成取 max 的习惯，换一道题（如允许「非递减」或有删除操作的变体）就会翻车。反过来，**查询结果 +1 之后才用于更新**，别把 `best` 本身写进树里。
6. **树只开 $4V$ 而非 $4 \times 10^5$ 时注意 $V \ge 1$**：$n \ge 1$ 保证 $V \ge 1$，无除零/空树风险；但 `mx.assign(4 * V, 0)` 在 $V = 1$ 时开 4 格，递归 `update(1,1,1,...)` 直接命中叶子，路径正确。
7. **同值元素的前驱不含自身**：值 $x$ 的窗口是 $[x-k, x-1]$，天然不含 $x$——「严格递增」在值域模型里由窗口右端独自扛着，理解这点就不会误加「跳过相同值」的补丁逻辑。
8. **Python 递归版超时风险**：$3 \times 10^6$ 级递归调用在 CPython 下 3 秒开外，Python 请无脑选自底向上迭代版（或 PyPy）。C++ 递归版 17 层深度毫无压力。
9. **别把 `ans` 初始化成查询**：`ans = 0` 起步即可，$n \ge 1$ 时首个元素 `cur = 1` 必然覆盖；真正的坑在「返回树根」的等价写法里忘了树全 0 时（不可能发生，$n \ge 1$）的语义，两版都安全。
10. **赛时节奏**：读题识别「LIS + 相邻差 $\le k$」（2 分钟）→ 心算 `tails` 反例确认贪心死路（2 分钟）→ 写值域线段树（10 分钟）→ 用示例 1 第 9 步（15 的窗口）验证窗口端点（2 分钟）。全程 15 分钟内，剩余时间用来检查 $x-1$ 与 `max(1, x-k)` 两个端点。
