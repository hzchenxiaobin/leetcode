# LeetCode 子字符串的最优划分 题解

## 1. 题目概述

- **标题 / 题号**：子字符串的最优划分（#2405，medium）
- **链接**：https://leetcode.cn/problems/optimal-partition-of-string/
- **来源**：LeetCode 第 310 场周赛 Q2
- **难度**：中等
- **标签**：贪心、哈希表、字符串、位运算

**题意**：给定字符串 `s`，将其划分为若干个**连续子字符串**，要求每个子字符串内的字符**互不重复**（每个字母至多出现一次）。在满足要求的前提下，返回**最少**的划分数。划分必须覆盖原串：每个字符恰好属于一个子串。

**约束**：

- $1 \le \text{s.length} \le 10^5$
- `s` 仅由小写英文字母组成

> 💡 Q2 是本场的中档贪心题，目标**读题到 AC 压在 5 分钟内**。「段数最少 + 段内互异」的组合天然指向「每段能拉多长拉多长」。真正值得停留的只有两处：一是**切点是被重复字符强制出来的**（不是自由决策，无需搜索）；二是**切割后新段以当前字符开头**（不是空段）——后者是本题最常见的 WA 来源。

## 2. 示例

**示例 1**

```text
输入：s = "abacaba"
输出：4
解释：两种可行划分：("a","ba","cab","a") 与 ("ab","a","ca","ba")。
      注意两者都不是贪心解 —— 贪心给出 ("ab","ac","ab","a")，同为 4 段。
```

**示例 2**

```text
输入：s = "ssssss"
输出：6
解释：任何一段都不能含两个 s，只能逐字符切割 ("s","s","s","s","s","s")。
```

**示例 3**（全串互异，整串一段）

```text
输入：s = "abcdefgh"
输出：1
解释：整串字符互异，无需切割。
```

## 3. 解题思路

### 3.1 暴力思路：枚举切法与 $O(26n)$ DP

最朴素的做法是**枚举所有切法**：在 $n-1$ 个间隙中任取子集切断，验证每种切法下每段是否互异，取合法切法的最小段数。$2^{n-1}$ 种组合对 $n \le 10^5$ 完全不可行——它把切点当成自由搜索空间，完全无视切点其实被字符重复关系**强制**这层结构。

第二档是 **DP**：设 $f[i]$ 为前缀 $s[0..i-1]$ 的最少段数，则

$$
f[i] = \min_{j:\ s[j..i-1]\ \text{互异}} \bigl(f[j] + 1\bigr)
$$

正确但显笨重。不过这里藏着一个可爱的观察：**段内互异 + 字符集只有 26 个小写字母 $\Rightarrow$ 每段长度 $\le 26$**，于是合法的 $j$ 只有 $i-26 \sim i-1$ 这 $O(26)$ 个，DP 总复杂度 $O(26n) \approx 2.6 \times 10^6$，居然也能过。但 DP 的「枚举断点取 min」仍然是把全局决策背在身上——切点明明是**局部被逼**出来的，一遍扫描就能全部确定。

> ⚠️ 两个暴力档都没有用到题面的结构性红利：**切割条件是局部的**（当前字符是否与本段重复），不需要全局信息、不需要回溯、不需要取 min。识别出「切点被逼出来」后，问题从搜索坍缩成单遍扫描。

### 3.2 核心观察：切点被重复字符「逼」出来

![核心观察：扫描到本段已有字符时被迫切割，切点位置被重复字符唯一确定，贪心每段拉到最长](images/ops310_greedy_concept.svg)

**观察一（切点不自由）**：从左到右扫描、维护当前段已出现的字符集合 `seen`。当扫到字符 $c \in \text{seen}$ 时，含 $c$ 的这一步必然违法——**在 $c$ 之前必须有一个切点**。至于这个切点放在更早的位置行不行？行（示例 1 的两种划分就是证据），但**没必要**：把切点尽量右移（即当前段尽量长）不会让后面的段更难切——这是贪心的核心直觉，§5 给出严格证明。

**观察二（段长上限 26）**：段内互异 + 小写字母集 $\Rightarrow$ 每段 $\le 26$ 个字符。它解释了为什么 $O(26n)$ 的 DP 也能过，也给出了一个快速心算检验：`"ssssss"` 答案是 6 而非某个更小的数，因为每段装不下第二个 `s`。

**观察三（贪心：能拉多长拉多长）**：形式化地，贪心划分递归定义——第一段取**最长的互异前缀** $s[0..g]$，然后对剩余后缀 $s[g{+}1..]$ 递归执行。扫描算法里「遇到重复即切」恰好实现这个定义：每一段都在「下一个字符与本段重复」处被迫终止。

### 3.3 算法流程

![算法流程：初始化 ans=1、mask=0，循环取字符 c 计算 bit，若 bit 与 mask 相与非零则 ans++ 且 mask=bit（新段以 c 开头），否则 mask 并入 bit，字符耗尽返回 ans](images/ops310_algorithm_flow.svg)

一遍扫描，两个分支：

1. **初始化**：`ans = 1`（至少一段），`mask = 0`（当前段已出现字符的 26 位掩码，空集）；
2. **扫描每个字符 $c$**：计算 $\text{bit} = 1 \ll (c - a)$；
   - 若 $\text{bit} \& \text{mask} \ne 0$（$c$ 已在当前段）：**被迫切割**——`ans++`，且新段**以 $c$ 开头**：`mask = bit`（不是清零！）；
   - 否则：`mask |= bit`，$c$ 并入当前段；
3. **扫描结束**：返回 `ans`。

集合查询是 $O(1)$ 的位运算，全程无回溯、无额外数据结构。

### 3.4 示例演算

![示例演算：abacaba 逐步走查表，i=2、4、6 三次遇到重复的 a 触发切割，ans 从 1 递增至 4，最终划分 ab、ac、ab、a](images/ops310_example_walkthrough.svg)

以示例 1 `s = "abacaba"` 演算（初始 `ans = 1, seen = ∅`）：

| $i$ | $s[i]$ | 判断 | 动作 | 段内集合 | $ans$ |
|-----|--------|------|------|----------|-------|
| 0 | `a` | 新字符 | 并入当前段 | $\{a\}$ | 1 |
| 1 | `b` | 新字符 | 并入当前段 | $\{a, b\}$ | 1 |
| 2 | `a` | **重复！** | 切割，新段 | $\{a\}$ | 2 |
| 3 | `c` | 新字符 | 并入当前段 | $\{a, c\}$ | 2 |
| 4 | `a` | **重复！** | 切割，新段 | $\{a\}$ | 3 |
| 5 | `b` | 新字符 | 并入当前段 | $\{a, b\}$ | 3 |
| 6 | `a` | **重复！** | 切割，新段 | $\{a\}$ | 4 |

最终 $ans = 4$ ✓，贪心划分为 `("ab", "ac", "ab", "a")`。注意三次切割处 `seen` 都被重置为 $\{a\}$ 而非 $\varnothing$——重复的 `a` 自己正是新段的第一个字符。

- **示例 2** `"ssssss"`：每个 `s` 都与段内首个 `s` 重复，六次切割，$ans = 6$ ✓。
- **示例 3** `"abcdefgh"`：全程无重复，零次切割，$ans = 1$ ✓。

## 4. 算法细节

1. **集合的两种实现**：小写字母集只有 26 个，`bool seen[26]` 与 26 位整数位掩码均可。位掩码版一次 `&` 判重、一次 `|` 插入、一次赋值重置，常数最小；哈希 `set` 版（Python）语义最直白，$n \le 10^5$ 下性能也无压力。
2. **切割时的重置是 `mask = bit`，不是 `mask = 0`**：切点在 $c$ **之前**，$c$ 属于**新段**。若清零，新段会漏掉首字符的记录，下一个相同字符（如 `"aba"` 后再来 `'b'`）将漏判重复。这是本题 WA 率最高的一处。
3. **`ans` 初值为 1 而非 0**：非空串至少一段。等价写法是「切割次数 + 1」：`ans = 0`，每次 `++ans` 对应切割，最后 `return ans + 1`，两者只差常数归属，别混用即可。
4. **为什么不需要回溯**：切点位置被「下一字符与本段重复」唯一强制，贪心把切点推到最右（段最长）不影响后续子问题的可行性与最优性（§5 引理 2），因此一遍扫描即最优。
5. **与 763 的方向对照**：763「划分字母区间」要求**同字母必须同段**，段边界由「段内字母的最远出现位置」不断**外扩**；本题要求**同字母不得同段**，段边界由「本段重复字符」不断**截断**。一外扩一截断，集合维护正好是一体两面。

## 5. 正确性证明

**引理 1**（第一段右端点的上界）：设 $g$ 为使 $s[0..g]$ 字符互异的最大下标（$0 \le g \le n-1$）。任何合法划分的第一段右端点 $e$ 满足 $e \le g$。

**证明**：合法划分的第一段是从 $s[0]$ 起的连续子串且段内互异，即 $s[0..e]$ 互异。注意前缀互异性对缩短封闭：$s[0..x]$ 互异则一切 $x' < x$ 亦互异，故互异前缀构成连续区间 $[0, g]$，从而 $e \le g$。∎

**引理 2**（延长第一段不劣）：设 $P = (s[0..e],\ s[e{+}1..e_2],\ \dots)$ 是任一合法划分，$e \le g$。构造 $P' = (s[0..g],\ s[g{+}1..e_2],\ \dots)$（若 $g + 1 > e_2$，第二段被完全吸收而删去）。则 $P'$ 合法且 $|P'| \le |P|$。

**证明**：合法性：$s[0..g]$ 互异（$g$ 的定义）；$s[g{+}1..e_2]$ 是原第二段 $s[e{+}1..e_2]$ 的后缀，而互异性对取后缀封闭，故仍互异；其余段不变。段数：第二段或保留（段数不变）或被吸收（段数减一），故 $|P'| \le |P|$。∎

**定理**：贪心划分——第一段取最长互异前缀 $s[0..g]$，再对后缀 $s[g{+}1..]$ 递归执行——的段数是所有合法划分中的最小值；且「扫描遇重复即切」的算法产生的正是该划分。

**证明**：对串长 $n$ 归纳。$n = 0$ 时空划分段数为 $0$，显然最优。设结论对一切更短的串成立。任取合法划分 $P$，由引理 2 存在 $P'$ 以 $s[0..g]$ 为第一段且 $|P'| \le |P|$；去掉该段后 $P'$ 的剩余部分是 $s[g{+}1..]$ 的合法划分，由归纳假设，贪心在后缀上的段数不超过它。故贪心总段数 $\le |P'| \le |P|$。又「遇重复即切」的扫描算法中，每段都延伸到「下一字符与本段重复」为止，即每段恰为该起点出发的最长互异段，与递归定义一致。∎

> 💡 证明骨架就是**交换论证**：任何最优解都可以在不变差的前提下被改造成「第一段与贪心一致」的解，于是贪心的每个局部决策都能安全地钉死。这是「区间/划分类贪心」的标准证法，同场 Q3（区间分组）的贪心证明同属此谱系。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$——每个字符一次 $O(1)$ 的位运算判重与更新，无回溯无二分。$n \le 10^5$ 下远低于时限，实际耗时微秒级。
- **空间复杂度**：$O(\Sigma) = O(26)$——一个 26 位整数（或 `bool[26]`），与 $n$ 无关，可视为 $O(1)$。
- **对照**：DP 版 $O(26n)$ 时间 / $O(n)$ 空间，正确但把简单问题做重；枚举切法 $O(2^{n-1} \cdot n)$ 直接爆炸。贪心版在三者中是**代码最短、常数最小、证明最干净**的解，是本题的唯一合理落点。

## 7. 参考代码

### C++（位掩码，推荐）

```cpp
class Solution {
public:
    int partitionString(string s) {
        int ans = 1;
        unsigned mask = 0;                     // 当前段已出现字母的 26 位掩码
        for (char c : s) {
            unsigned bit = 1u << (c - 'a');
            if (mask & bit) {                  // c 已在当前段 → 被迫切割
                ++ans;
                mask = bit;                    // 新段以 c 开头，而非空集！
            } else {
                mask |= bit;                   // c 并入当前段
            }
        }
        return ans;
    }
};
```

### Python（集合，语义直白）

```python
class Solution:
    def partitionString(self, s: str) -> int:
        ans, seen = 1, set()
        for c in s:
            if c in seen:          # 被迫切割
                ans += 1
                seen = {c}         # 新段从 c 重新开始，不是 clear()！
            else:
                seen.add(c)
        return ans
```

### Python（位掩码，常数更小）

```python
class Solution:
    def partitionString(self, s: str) -> int:
        ans, mask = 1, 0
        for c in s:
            bit = 1 << (ord(c) - 97)
            if mask & bit:
                ans += 1
                mask = bit
            else:
                mask |= bit
        return ans
```

> 💡 赛时三选一即可：C++ 选手写位掩码版（5 行核心逻辑），Python 选手 `set` 版最不易错。若字符串可能混入大写或数字，把 `c - 'a'` 的定长映射换成哈希集合即可，骨架不变。

## 8. 边界情况与易错点

1. **切割后 `seen = {c}` 而非空集**：本题 WA 率第一名。切点在重复字符 $c$ **之前**，$c$ 属于新段。重置成空集会在类似 `"abab"` 的串上漏判——第二段的 `b` 不会与「理应在段内的 `a`」之外的字符判重，碰上更长的回文串即出错。
2. **`ans` 初值为 1**：非空串至少一段，初值取 0 会全盘少 1。另一种等价实现是数切割次数再 `+1`，两种口径别混。
3. **全同字符**：`"ssssss"` 每步都触发切割，答案恰为 $n$——顺手用它做心算检验。
4. **全串互异**：$n \le 26$ 时可能整串一段（答案 1）；$n > 26$ 时由抽屉原理必然超过一段，不需要特判，算法自然给出正确值。
5. **C++ 位运算优先级**：`mask & bit` 中 `&` 优先级低于 `==`，若写成 `mask & bit == 0` 会先算 `bit == 0` 恒假再与——判重条件务必带括号或写成独立的 `if (mask & bit)`。
6. **`1u` 而非 `1`**：`1 << 31` 对有符号 `int` 是未定义行为；本题只移 25 位无碍，但写成 `1u << (c - 'a')` 是一劳永逸的习惯。
7. **段与子序列**：题目要求的是**连续**子字符串，不是子序列——读题时扫一眼「子字符串/substring」的措辞，别按子序列做 DP。
8. **赛时节奏**：本题 5 分钟内的路径是——识别贪心（30 秒）→ 确认重置语义 `mask = bit`（1 分钟，可在草稿上跑一遍 `abacaba`）→ 敲代码提交（2 分钟）。把时间省给 Q3 的区间分组与 Q4 的线段树优化 LIS。
