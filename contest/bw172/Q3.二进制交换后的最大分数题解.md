# LeetCode 二进制交换后的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：二进制交换后的最大分数（#3781，medium）
- **链接**：https://leetcode.cn/problems/maximum-score-after-binary-swaps/
- **来源**：LeetCode 第 172 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、字符串、堆（优先队列）

**题意**：给定长度为 $n$ 的数组 `nums` 与等长的二进制字符串 `s`。初始分数 = 所有满足 $s[i] = \texttt{'1'}$ 的 $nums[i]$ 之和。

可以执行任意次操作：选下标 $i$（$0 \le i < n-1$）满足 $s[i] = \texttt{'0'}$ 且 $s[i+1] = \texttt{'1'}$，交换这两个字符。求能获得的**最大分数**（即让哪些位置最终为 `'1'`）。

**约束**：

- $n = nums.length = s.length$，$1 \le n \le 10^5$
- $1 \le nums[i] \le 10^9$
- $s[i] \in \{\texttt{'0'}, \texttt{'1'}\}$

> ⚠️ 注意：`'1'` 的总个数**不变**，只能改变它们的位置。

## 2. 示例

**示例 1**

```text
输入：nums = [2,1,5,2,3], s = "01010"
输出：7
解释：i=0 交换 → "10010"；i=2 交换 → "10100"。
     最终 1 在 0、2 位，得分 nums[0] + nums[2] = 2 + 5 = 7。
```

**示例 2**

```text
输入：nums = [4,7,2,9], s = "0000"
输出：0
解释：没有 '1'，无法交换，分数为 0。
```

**补充示例 3**

```text
输入：nums = [3,1,2], s = "110"
输出：4
解释：两个 1 在位置 0、1，它们只能左移，所以位置固定为 0 和 1；
     位置 2 上的 2 永远够不到。得分 = 3 + 1 = 4。
```

## 3. 解题思路

### 3.1 暴力思路

状态是长度为 $n$ 的二进制串，枚举所有可达状态并取最大分数：可达状态数量级是 $\binom{n}{m}$（$m$ 为 `'1'` 的个数），$n = 10^5$ 时不可行。即便用 BFS 也指数爆炸。

### 3.2 核心观察：`'1'` 只能向左移动，且相对顺序不变

![交换条件要求第 i 位为 0、第 i+1 位为 1，意味着 1 只能向左走一格](images/bw172_q3_ones_move_left.svg)

交换条件 `s[i] = '0'`、`s[i+1] = '1'` 后，`'1'` 从 $i+1$ 到了 $i$——**每次操作让一个 `'1'` 向左移动一格**。

由此得到可达性的完整刻画。设初始 `'1'` 的位置为 $o_1 < o_2 < \cdots < o_m$（$m$ 为 `'1'` 的个数），最终 `'1'` 的位置为 $p_1 < p_2 < \cdots < p_m$，则

$$\text{可达} \iff p_j \le o_j \ \text{对所有 } j$$

（`'1'` 不能越过彼此，所以第 $j$ 个 `'1'` 仍是第 $j$ 个；它只能左移，所以 $p_j \le o_j$。）

这个条件等价于**前缀形式**：对每个下标 $i$，前缀 $[0, i]$ 中最终 `'1'` 的个数 $\ge$ 前缀 $[0, i]$ 中初始 `'1'` 的个数。

于是问题变成：**在满足前缀约束的前提下，选出 $m$ 个位置使 $nums$ 之和最大**。

### 3.3 算法流程：从左到右扫描 + 大根堆

![从左往右扫，遇到 1 就从堆里取当前最大值](images/bw172_q3_heap_greedy.svg)

一个非常简洁的贪心：

```text
1. 大根堆 pq 为空；ans = 0
2. for i = 0 .. n-1:
       把 nums[i] 压入 pq
       若 s[i] == '1':  ans += pq.top()；pq.pop()
3. 返回 ans
```

**直觉**：从左往右扫，每遇到一个 `'1'`，说明「前缀约束」要求我们到这里为止必须已经挑出对应数量的位置；此时堆里攒着 $[0, i]$ 内**还没被选中**的所有值，取最大值即为当前最优。

**为什么「越靠左越先挑」是安全的**：靠左的 `'1'` 可选位置集合更小（它是某个前缀的子集），先把这些「选择受限」的 `'1'` 安排好，再让后面的 `'1'` 在更大的范围里挑，不会互相抢位置——这一点由 §5 的交换论证严格保证。

### 3.4 示例演算

![演算：每遇 1 就从堆里取最大值](images/bw172_q3_example_walkthrough.svg)

对示例 1：`nums = [2,1,5,2,3]`、`s = "01010"`（`'1'` 在位置 1、3）。

| i | nums[i] | 堆（降序看作最大在前） | s[i] | 动作 | ans |
|---|---------|------------------------|------|------|-----|
| 0 | 2 | {2} | 0 | — | 0 |
| 1 | 1 | {2, 1} | 1 | 取 2 | 2 |
| 2 | 5 | {5, 1} | 0 | — | 2 |
| 3 | 2 | {5, 2, 1} | 1 | 取 5 | 7 |
| 4 | 3 | {3, 2, 1} | 0 | — | 7 |

答案 7，与示例一致。注意 $i = 3$ 时堆里有 5、2、1，取 5 对应「让位置 2 上的 `'1'`（原在位置 3 的那个？不，是位置 1 的那个走到位置 2）」——本质上两个 `'1'` 分别落在位置 0 与 2（值 2 与 5）。

再看补充示例 3：`nums = [3,1,2]`、`s = "110"`（`'1'` 在 0、1）。

| i | nums[i] | 堆 | s[i] | 动作 | ans |
|---|---------|-----|------|------|-----|
| 0 | 3 | {3} | 1 | 取 3 | 3 |
| 1 | 1 | {1} | 1 | 取 1 | 4 |
| 2 | 2 | {2} | 0 | — | 4 |

答案 4。位置 2 的值 2 比 1 大，但**用不上**：两个 `'1'` 挤在最左边，谁也无法右移，最后一个 `'1'` 最远只能待在位置 1。这个例子说明「`'1'` 只能左移」这一约束有多强，也说明为什么不能简单地把 `nums` 最大的 $m$ 个值加起来。

## 4. 算法细节

1. **大根堆**：C++ 用 `priority_queue<int>`（默认大根），Python 用 `heapq` 存负数或存 `-nums[i]`。
2. **每步都入堆**：注意 `pq.push(nums[i])` 在判断 `s[i] == '1'` **之前**，这样位置 $i$ 自己也参与候选。
3. **堆中元素的语义**：堆里是「前缀 $[0, i]$ 内尚未被选中的位置的值」。因为每个位置只会被 `push` 一次、`pop` 一次，堆大小 $\le n$。
4. **取 max 的正确性前提**：前缀约束要求「$[0,i]$ 内选中数 $\ge$ `'1'` 数」，所以到第 $i$ 个 `'1'` 时必须从中选一个；堆里非空（因为 `'1'` 的个数 $\le$ 位置数）。
5. **64 位**：$nums[i] \le 10^9$、$n \le 10^5$，总和可达 $10^{14}$，C++ 用 `long long`（返回类型 metaData 是 `long`）。
6. **`'1'` 个数为 0**：循环里不会 `pop`，答案 0（示例 2）。
7. **`'1'` 个数为 $n$**：每个位置都是 `'1'`，每次都是「入堆即弹出」，相当于取自己，答案 = 全数组和（因为无法移动）。
8. **不要真的模拟交换**：模拟交换的复杂度是 $O(n^2)$，而堆贪心是 $O(n \log n)$，且不改变 `s`。

## 5. 正确性证明

**引理 1（可达性刻画）**：设初始 `'1'` 位置为 $o_1 < \cdots < o_m$，目标位置为 $p_1 < \cdots < p_m$。该目标状态可达，当且仅当对每个 $j$ 有 $p_j \le o_j$。

**证明**：
（必要性）每次操作把一个 `'1'` 从 $i+1$ 移到 $i$，位置减 1，故任何 `'1'` 的位置单调不增。又操作只在相邻位置交换，两个 `'1'` 永远不会越过对方，故第 $j$ 个 `'1'` 始终是第 $j$ 个。于是 $p_j \le o_j$。
（充分性）若 $p_j \le o_j$ 且两者都是严格递增序列，可构造性地把 `'1'` 逐个左移到位：从最右边的 `'1'` 开始（$j = m$），把它从 $o_j$ 一路左移到 $p_j$（因为 $p_j \le o_j$，且此时它左边的 `'1'` 位置都 $\le o_{j-1} \le p_{j-1} < p_j$，路径畅通），再处理 $j-1$，依此类推。每步都是合法的「`'1'` 左移一格」操作，故可达。∎

**引理 2（前缀约束等价）**：$p_j \le o_j$ 对一切 $j$ 成立，当且仅当对每个下标 $i \in [0, n-1]$，前缀 $[0,i]$ 中选中的位置数不少于前缀中初始 `'1'` 的个数。

**证明**：设 $c(i) = \#\{j : p_j \le i\}$，$o(i) = \#\{j : o_j \le i\}$。
（⇒）若 $p_j \le o_j$，取 $i$，令 $t = o(i)$（前缀内初始 `'1'` 数）。对 $j \le t$ 有 $o_j \le i$，故 $p_j \le o_j \le i$，于是 $c(i) \ge t = o(i)$。
（⇐）对某个 $j$，取 $i = o_j$。则 $o(i) \ge j$，由假设 $c(i) \ge j$，即前 $j$ 个目标位置都 $\le o_j$，故 $p_j \le o_j$。∎

**引理 3（贪心每步最优）**：把算法第 $j$ 次 `pop` 选中的位置记为 $q_j$。则对任意满足约束的选法 $p_1 < \cdots < p_m$，都有 $\sum_j nums[q_j] \ge \sum_j nums[p_j]$。

**证明**：用归纳加强命题：对每个 $j \in [0, m]$，存在一个最优解，其前 $j$ 个被选位置恰为 $q_1, \ldots, q_j$（作为集合）。
$j = 0$：平凡。设对 $j-1$ 成立，取一个与之相符的最优解 $S$（前 $j-1$ 个位置是 $q_1..q_{j-1}$）。第 $j$ 次 `pop` 发生在扫描到位置 $o_j$（第 $j$ 个 `'1'`）时，堆内是 $[0, o_j]$ 中未被选中的位置；记贪心选中 $q_j$（堆中值最大的那个）。$S$ 的第 $j$ 个选中位置 $p_j$ 也必 $\le o_j$（引理 2 的前缀约束），且 $p_j$ 不等于 $q_1..q_{j-1}$（它们是 $S$ 的前 $j-1$ 个位置，而 $p_j$ 是第 $j$ 个，严格递增），故 $p_j$ 在堆中，于是 $nums[q_j] \ge nums[p_j]$。
- 若 $q_j \in S$：$q_j$ 在 $S$ 中的序号 $t \ge j$。交换 $S$ 中位置 $q_j$ 与 $p_j$ 的角色（把第 $j$ 个选中改为 $q_j$，第 $t$ 个改为 $p_j$），所得集合不变，仍满足约束，总和不变，且前 $j$ 个现在与贪心一致。
- 若 $q_j \notin S$：令 $S' = S \setminus \{p_j\} \cup \{q_j\}$。验证约束：对任意 $i$，若 $i \ge o_j$，则 $p_j, q_j$ 都在 $[0,i]$ 内，计数不变；若 $i < o_j$，则 $S'$ 在 $[0,i]$ 内的元素包含 $S$ 的前 $j-1$ 个位置中落在 $[0,i]$ 的部分（去掉的 $p_j$ 是第 $j$ 个，不在其中；加上的 $q_j \le o_j$ 可能不在 $[0,i]$，所以计数可能减 1，但下界仍由前 $j-1$ 个位置保证）——由归纳假设，$q_1..q_{j-1}$ 构成一个大小 $j-1$ 的可行集，故 $[0,i]$ 内至少有 $\min(j-1,\ o(i))$ 个；而当 $i < o_j$ 时 $o(i) \le j-1$，故数量 $\ge o(i)$，约束仍成立。且 $nums[q_j] \ge nums[p_j]$，故 $S'$ 不劣于 $S$。
两种情形都得到「前 $j$ 个与贪心一致且不劣」的解。归纳完成。∎

**定理**：算法返回最大可得分。

**证明**：由引理 1、2，可行方案恰是满足前缀约束的 $m$ 个位置的选择。由引理 3（取 $j = m$），贪心的总和不小于任何可行方案的总和。又贪心选出的 $m$ 个位置满足前缀约束（第 $j$ 个选中位置 $\le o_j$，因为 `pop` 时堆中元素都 $\le o_j$），故它本身是可行方案。因此贪心最优。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。扫描 $n$ 次，每次一次 `push`；`'1'` 处额外一次 `pop`，最坏 $n$ 次。堆操作 $O(\log n)$。
- **空间**：$O(n)$ 的堆（最坏同时存 $n$ 个元素）。不修改输入。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maximumScore(vector<int>& nums, string s) {
        priority_queue<int> pq;
        long long ans = 0;
        int n = (int)s.size();
        for (int i = 0; i < n; i++) {
            pq.push(nums[i]);
            if (s[i] == '1') {
                ans += pq.top();
                pq.pop();
            }
        }
        return ans;
    }
};
```

### Python

```python
import heapq


class Solution:
    def maximumScore(self, nums: list[int], s: str) -> int:
        heap = []
        ans = 0
        for x, ch in zip(nums, s):
            heapq.heappush(heap, -x)
            if ch == '1':
                ans += -heapq.heappop(heap)
        return ans
```

## 8. 边界情况与易错点

1. **以为 `'1'` 能向右移**：交换条件是 `s[i]='0'`、`s[i+1]='1'`，`'1'` 在右边，交换后**左移**。若搞反方向，会把「够不到的高分位置」也算进来（补充示例 3 就会答成 5 而非 4）。
2. **直接取 `nums` 最大的 $m$ 个**：忽略了位置约束，答案偏大。必须保证选出的位置满足前缀约束（每个前缀内选中数 $\ge$ 初始 `'1'` 数）。
3. **`push` 与 `pop` 的顺序**：必须在判断 `s[i]` 之前 `push(nums[i])`；否则当前位置的值不会参与候选，答案偏小。
4. **`int` 溢出**：总和可达 $10^{14}$，`ans` 必须是 `long long`。
5. **`'1'` 个数为 0**：答案 0；循环里没有 `pop`，堆会一直增长到 $n$，注意空间但不会错。
6. **Python 的 `heapq` 是小根堆**：要存 `-x` 并在取用时取反，别写成 `heapq.heappop` 后直接用。
7. **`s` 与 `nums` 长度一致**：题面保证；若不等，`zip` 会截断，需自行校验。
8. **不需要返回方案**：只返回总和，省去记录位置的开销。
