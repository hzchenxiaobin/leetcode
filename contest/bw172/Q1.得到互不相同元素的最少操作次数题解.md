# LeetCode 得到互不相同元素的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：得到互不相同元素的最少操作次数（#3779，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-operations-to-have-distinct-elements/
- **来源**：LeetCode 第 172 场双周赛 Q1
- **难度**：中等
- **标签**：数组、哈希表

**题意**：给定整数数组 `nums`。每次操作**删除当前数组的前三个元素**（若剩余不足三个则全部删除）。重复该操作，直到数组为空**或**数组内**没有重复元素**。问最少需要多少次操作。

注意停止条件是「无重复元素」，不是「为空」——所以很可能只删一次就停。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [3,8,3,6,5,8]
输出：1
解释：删掉前三个 [3,8,3]，剩下 [6,5,8] 互不相同，停止。
```

**示例 2**

```text
输入：nums = [2,2]
输出：1
解释：一次操作删光全部元素，数组为空也满足停止条件。
```

**示例 3**

```text
输入：nums = [4,3,5,1,2]
输出：0
解释：本就互不相同，无需操作。
```

## 3. 解题思路

### 3.1 暴力思路

从 $m = 0$ 开始逐次尝试：模拟删除前 $3m$ 个元素，检查剩余后缀是否互不相同；第一个满足的 $m$ 就是答案。每次检查 $O(n)$，最坏 $m = \lceil n/3 \rceil$ 次，总 $O(n^2/3)$，$n = 10^5$ 时约 $3 \times 10^9$，超时。

### 3.2 核心观察：末尾那段「天然互不相同的最长后缀」决定一切

![答案是：从右往左找到第一个重复元素，再把它之前的部分按每 3 个一组删掉](images/bw172_q1_suffix_scan.svg)

关键结构：**操作永远从前缀删，留下的永远是原数组的一个后缀**。具体地，$m$ 次操作后剩余的是

$$nums[3m \ldots n-1]\quad(\text{若 } 3m \ge n \text{ 则为空})$$

于是只需找出「最短的合法后缀」：设 $p$ 为**最小的下标**，使 $nums[p \ldots n-1]$ 内元素互不相同。那么答案为

$$ans = \left\lceil \frac{p}{3} \right\rceil = \left\lfloor \frac{p + 2}{3} \right\rfloor$$

$p$ 怎么求？从右往左扫，用一个集合记录已见过的值：

- 遇到**没见过的值**：加入集合，继续左移；
- 遇到**已出现过的值**：立刻停止，此时 $p = i + 1$。

因为「后缀互不相同」这个性质关于后缀的起点是**单调**的：若 $nums[p..]$ 无重复，则 $nums[p+1..]$ 也无重复（子后缀）。所以从右往左扫到第一个「重复冲突」的位置就精确确定了边界。

### 3.3 算法流程

![算法流程：倒序扫描 + 一次除法](images/bw172_q1_algorithm_flow.svg)

```text
1. seen = 空集合；p = n
2. for i = n-1 down to 0:
       若 nums[i] ∈ seen:  break
       seen.add(nums[i])；p = i
3. 返回 ceil(p / 3)
```

### 3.4 示例演算

对示例 1 的 `nums = [3,8,3,6,5,8]`：

| i | nums[i] | seen（处理前） | 动作 | p |
|---|---------|----------------|------|---|
| 5 | 8 | {} | 加入 | 5 |
| 4 | 5 | {8} | 加入 | 4 |
| 3 | 6 | {8,5} | 加入 | 3 |
| 2 | 3 | {8,5,6} | 加入 | 2 |
| 1 | 8 | {8,5,6,3} | 8 已存在 → 停止 | 2 |

$p = 2$，答案 $\lceil 2/3 \rceil = 1$，与示例一致（删前 3 个后剩 `[6,5,8]`）。

对示例 3（全不同）：扫描不中断，$p = 0$，答案 0。
对示例 2 的 `[2,2]`：$i=1$ 加入，$p=1$；$i=0$ 时 2 重复 → 停止，$p=1$，答案 $\lceil 1/3 \rceil = 1$。

## 4. 算法细节

1. **哈希集合**：值域 $\le 10^5$ 也可以用 `bool` 数组或 `vector<char>` 计数，$O(V)$ 空间换常数；哈希集合更通用。
2. **倒序扫描**：正序扫描无法判断「后缀是否互不相同」，因为冲突可能出现在任意位置；倒序扫描才能利用「后缀性质单调」。
3. **`p` 的初值**：设为 $n$（表示空后缀 / 全部重复），循环中每加入一个元素就更新为 $i$。
4. **向上取整**：`(p + 2) / 3` 是整数取整的标准写法；Python 用 `(p + 2) // 3` 或 `-(-p // 3)`。
5. **不是 `n/3`**：答案取决于「最长合法后缀的起点」，不是数组长度。
6. **一次操作删 3 个但可能「删不完」**：$p$ 不被 3 整除时，最后一次操作会跨越边界（多删几个），不影响正确性——多删只会让剩余更短，仍是合法后缀。
7. **时间复杂度**：一趟 $O(n)$ + 哈希 $O(1)$ 均摊，优于暴力的 $O(n^2)$。

## 5. 正确性证明

**引理 1（操作后的形态）**：执行 $m$ 次操作（若中途未停止）后，剩余数组恰为 $nums[3m \ldots n-1]$；当 $3m \ge n$ 时为空。

**证明**：对 $m$ 归纳。$m = 0$ 时为全体。设第 $m-1$ 次后为 $nums[3(m-1) \ldots n-1]$，长度 $n - 3(m-1)$。若长度 $\ge 3$，删除前三个得 $nums[3m \ldots n-1]$；若长度不足 3，则删光为空，而 $3m = 3(m-1) + 3 \ge n$ 正好对应「区间为空」。∎

**引理 2（后缀单调性）**：若 $nums[p \ldots n-1]$ 中元素互不相同，则对任意 $p' \ge p$，$nums[p' \ldots n-1]$ 也互不相同。

**证明**：后者是前者的子序列（连续子段），子集无重复则子集的子集也无重复。∎

**引理 3（$p$ 的定义与求法）**：设 $p^\ast$ 为最小的使 $nums[p \ldots n-1]$ 互不相同的下标（全数组互不相同时 $p^\ast = 0$）。则倒序扫描在第一个「已出现过的值」处停止时，$p = p^\ast$。

**证明**：倒序扫描经过的下标集合是 $[i, n-1]$ 中的全部，且每次加入都保证不重复，故停止前的不变量是「$nums[i+1 \ldots n-1]$ 互不相同」。停止于 $i$ 时（$nums[i]$ 已在 $nums[i+1..n-1]$ 中出现），$nums[i \ldots n-1]$ 有重复，而 $nums[i+1 \ldots n-1]$ 无重复，故 $p^\ast = i+1 = p$。若扫描到 $i = -1$ 未停止，则 $nums[0 \ldots n-1]$ 无重复，$p^\ast = 0 = p$。∎

**定理**：算法返回值为最少操作次数。

**证明**：执行 $m$ 次操作后停止，当且仅当（由引理 1）$3m \ge n$（空数组）或 $nums[3m \ldots n-1]$ 互不相同。由引理 2、3，后者等价于 $3m \ge p^\ast$。故最小 $m$ 是满足 $3m \ge p^\ast$ 的最小整数，即 $\lceil p^\ast/3\rceil$，而算法返回的 `(p+2)/3` 正是该值（整数除法下 $\lceil p/3 \rceil = \lfloor (p+2)/3 \rfloor$）。∎

## 6. 复杂度分析

- **时间**：$O(n)$。倒序遍历一次，每个元素做一次哈希查找与至多一次插入，均摊 $O(1)$。
- **空间**：$O(D)$，$D$ 为最长合法后缀中不同值的个数，最坏 $O(n)$（哈希集合）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums) {
        int n = (int)nums.size();
        unordered_set<int> seen;
        int p = n;
        for (int i = n - 1; i >= 0; i--) {
            if (seen.count(nums[i])) break;
            seen.insert(nums[i]);
            p = i;
        }
        return (p + 2) / 3;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int]) -> int:
        n = len(nums)
        seen = set()
        p = n
        for i in range(n - 1, -1, -1):
            if nums[i] in seen:
                break
            seen.add(nums[i])
            p = i
        return (p + 2) // 3
```

## 8. 边界情况与易错点

1. **把停止条件写成「数组为空」**：示例 1 只需 1 次操作，写成「删到空」会得到 2 次，直接 WA。
2. **正序扫描求 $p$**：正序无法保证「后缀互不相同」，必须倒序。
3. **`p` 初值写成 0**：若数组全重复（如 `[1,1,1]`），扫描在 $i = 2$ 时不会 break（第一个元素总是不重复），会走到 $i=1$ 才 break，$p=2$，答案 1。若 `p` 初值为 0 且不更新，答案会错误地变成 0。
4. **向上取整写错**：`p / 3` 会向下取整，$p = 4$ 时正确答案是 2 而 `4/3 = 1`；必须 `(p + 2) / 3`。
5. **$n < 3$**：如 `[2,2]`，一次操作就删光；$p = 1$，`(1+2)/3 = 1` ✓。
6. **重复元素在很后面**：如 `[1,2,3,4,1]`，倒序扫到 $i=0$ 才发现 1 重复，$p=1$，答案 1（删掉前 3 个后剩 `[4,1]`，仍不同——虽然 `[1,2,3,4,1]` 的合法后缀起点是 1，即 `[2,3,4,1]`，确实互不相同）。这里容易误以为 $p$ 应该是 0。
7. **值域大时的哈希**：$nums[i] \le 10^5$ 可以用数组代替哈希，但若值域放大到 $10^9$ 就必须用哈希/离散化。
