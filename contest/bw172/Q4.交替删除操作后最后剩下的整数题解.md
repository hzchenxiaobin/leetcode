# LeetCode 交替删除操作后最后剩下的整数 题解

## 1. 题目概述

- **标题 / 题号**：交替删除操作后最后剩下的整数（#3782，hard）
- **链接**：https://leetcode.cn/problems/last-remaining-integer-after-alternating-deletion-operations/
- **来源**：LeetCode 第 172 场双周赛 Q4
- **难度**：困难
- **标签**：递归、数学

**题意**：把 $1$ 到 $n$ 从左到右排成序列，交替执行下面两种操作（从操作 1 开始），直到只剩一个整数：

- **操作 1**：从**左侧**开始，隔一个数删除一个（删第 2、4、6…个，保留第 1、3、5…个）；
- **操作 2**：从**右侧**开始，隔一个数删除一个（删倒数第 2、4、6…个，保留倒数第 1、3、5…个）。

返回最后剩下的整数。

**约束**：

- $1 \le n \le 10^{15}$

> ⚠️ $n$ 可达 $10^{15}$，**不能**真的建序列模拟（空间与时间都不允许），必须找数学规律。

## 2. 示例

**示例 1**

```text
输入：n = 8
输出：3
解释：[1..8] --操作1--> [1,3,5,7] --操作2--> [3,7] --操作1--> [3]。
```

**示例 2**

```text
输入：n = 5
输出：1
解释：[1..5] --操作1--> [1,3,5] --操作2--> [1,5] --操作1--> [1]。
```

**示例 3**

```text
输入：n = 1
输出：1
解释：序列只有一个元素，直接返回。
```

## 3. 解题思路

### 3.1 暴力思路

用链表 / 数组模拟每次删除：一轮删一半，共 $\log n$ 轮，总操作数 $O(n)$。$n = 10^{15}$ 时既存不下（$10^{15}$ 个元素）也跑不完。即便只存「当前序列」，内存也是 $O(n)$。

但注意每轮之后**元素个数减半**，只需 $O(\log n) \approx 50$ 轮。于是思路是：**不存序列，只维护「剩余序列的结构参数」**。

### 3.2 核心观察：剩余序列始终是等差数列

![每轮之后剩下的仍是等差数列：只维护首项 h、公差 s、个数 r](images/bw172_q4_ap_invariant.svg)

初始序列 $1, 2, \ldots, n$ 是一个**公差为 1、首项为 1** 的等差数列。关键观察：

- **操作 1（从左侧删）**：保留第 1、3、5… 个元素，它们仍然是等差数列，**首项不变**，公差翻倍；
- **操作 2（从右侧删）**：保留倒数第 1、3、5… 个元素，同样是等差数列，公差翻倍，但**首项可能变化**（取决于元素个数的奇偶）。

于是整个过程中剩余序列永远形如

$$\{\,h,\ h+s,\ h+2s,\ \ldots,\ h+(r-1)s\,\}$$

只需要三个数就能完全描述它：首项 $h$、公差 $s$、剩余个数 $r$。当 $r = 1$ 时，$h$ 就是答案。

### 3.3 算法流程：三个数滚动更新

![首项更新规则：从右侧删且 r 为偶数时 h 要加一个公差](images/bw172_q4_direction_update.svg)

**个数更新**：两种操作都保留约一半元素（第 1、3、5… 个），故

$$r' = \left\lceil \frac{r}{2} \right\rceil = \left\lfloor \frac{r+1}{2} \right\rfloor$$

**公差更新**：保留下来的相邻元素在原序列中隔一个，故 $s' = 2s$。

**首项更新**：

- 操作 1：保留的第 1 个就是原第 1 个，$h' = h$；
- 操作 2：保留的第 1 个（即最后剩下的最左端）是原序列的倒数第 $1, 3, 5\ldots$ 个中**最靠前**的那个：
  - $r$ 为**偶数**：保留位置 $r, r-2, \ldots, 2$，最靠前是第 **2** 个，$h' = h + s$；
  - $r$ 为**奇数**：保留位置 $r, r-2, \ldots, 1$，最靠前是第 **1** 个，$h' = h$。

```text
1. h = 1；s = 1；r = n；op = 1（1 表示操作 1，2 表示操作 2）
2. while r > 1:
       若 op == 2 且 r 为偶数:  h += s
       r = (r + 1) / 2
       s = s * 2
       op = 3 - op
3. 返回 h
```

### 3.4 示例演算

![示例演算：n = 8 的三轮更新](images/bw172_q4_example_walkthrough.svg)

对 $n = 8$：

| 轮 | 操作 | 操作前 (h, s, r) | 序列 | 首项变化 | 操作后 (h, s, r) |
|----|------|------------------|------|----------|------------------|
| 1 | 左删 | (1, 1, 8) | 1,2,…,8 | $h' = h = 1$ | (1, 2, 4) → {1,3,5,7} |
| 2 | 右删 | (1, 2, 4) | 1,3,5,7 | $r$ 偶 → $h' = h+s = 3$ | (3, 4, 2) → {3,7} |
| 3 | 左删 | (3, 4, 2) | 3,7 | $h' = h = 3$ | (3, 8, 1) → {3} |

$r = 1$，返回 $h = 3$ ✓。

对 $n = 5$：

| 轮 | 操作 | 操作前 (h, s, r) | 首项变化 | 操作后 (h, s, r) |
|----|------|------------------|----------|------------------|
| 1 | 左删 | (1, 1, 5) | $h' = 1$ | (1, 2, 3) → {1,3,5} |
| 2 | 右删 | (1, 2, 3) | $r$ 奇 → $h' = 1$ | (1, 4, 2) → {1,5} |
| 3 | 左删 | (1, 4, 2) | $h' = 1$ | (1, 8, 1) → {1} |

返回 1 ✓。

## 4. 算法细节

1. **只用三个变量**：`h`、`s`、`r` 都是 `long long`（$s$ 会翻倍约 50 次，最大 $2^{50} \approx 10^{15}$，不会溢出；$h$ 始终 $\le n$）。
2. **奇偶判断**：`r % 2 == 0`。注意此时判断的是**操作前**的 $r$，不要用更新后的。
3. **操作交替**：用布尔 `fromLeft` 或 `op = 3 - op`，别用 `r % 2` 之类混淆（那是另一道题 390 的写法）。
4. **循环条件 `r > 1`**：$r = 1$ 时序列只剩 $h$，直接返回。$n = 1$ 时循环不执行，返回 1。
5. **顺序不能乱**：必须**先**根据旧 $r$ 判断要不要 `h += s`，**再**更新 $r$ 与 $s$。
6. **整数除法**：`(r + 1) / 2` 即向上取整；C++ 中 `long long` 的 `/` 向零取整，对正数即下取整，故 `(r+1)/2 = ceil(r/2)` 成立。
7. **不需要记录被删元素**：这是本题与「模拟」的核心差别——只关心「剩余序列的首项」。
8. **为什么不用递归**：递归写法（`lastRemaining(n, fromLeft)`）需要复杂的坐标变换；迭代写法直接维护等差三元组，更直观也更快。

## 5. 正确性证明

**引理 1（等差不变式）**：每轮操作开始时，剩余序列恰好是 $\{h, h+s, \ldots, h+(r-1)s\}$，其中 $h \ge 1$、$s \ge 1$、$r \ge 1$。

**证明**：初始 $h = 1, s = 1, r = n$，命题成立。设某轮开始时命题成立。

- **操作 1（左删，删第 2、4、… 个）**：保留下标 $1, 3, 5, \ldots$（1-based）。第 $k$ 个保留元素是原第 $2k-1$ 个，值为 $h + (2k-2)s = h + (k-1)(2s)$。故新序列为 $\{h + (k-1)\cdot 2s\}_{k=1}^{r'}$，即等差、首项 $h$、公差 $2s$、个数 $r' = \lceil r/2 \rceil$。
- **操作 2（右删，删倒数第 2、4、… 个）**：保留下标（1-based）$r, r-2, r-4, \ldots$ 中 $\ge 1$ 的那些，共 $\lceil r/2 \rceil$ 个。重新按升序编号，第 $k$ 个保留元素（$k$ 从 1 起）其原下标为 $r - 2(r'-k)$，值为 $h + (r - 2r' + 2k - 1)s$。由于相邻保留元素原下标差 2，新公差为 $2s$；新首项为原下标 $r - 2(r'-1)$ 对应的值，即 $h + (r - 2r' + 1)s$。而 $r' = \lceil r/2\rceil$：
  - $r$ 偶：$r' = r/2$，$r - 2r' + 1 = 1$，故首项 $= h + s$；
  - $r$ 奇：$r' = (r+1)/2$，$r - 2r' + 1 = 0$，故首项 $= h$。
  两种情形都与算法一致。
故每轮后不变式保持。∎

**引理 2（终止性）**：循环在 $O(\log n)$ 轮后使 $r = 1$。

**证明**：每轮 $r \mapsto \lceil r/2\rceil$。当 $r \ge 2$ 时 $\lceil r/2 \rceil \le r - 1$（因为 $\lceil r/2\rceil \le r/2 + 0.5 < r$ 对 $r \ge 2$ 成立且为整数），故 $r$ 严格递减且保持 $\ge 1$，必然到达 1。轮数为 $O(\log n)$。∎

**定理**：算法返回最后剩下的整数。

**证明**：由引理 1，每轮开始时剩余集合被 $(h, s, r)$ 精确描述；由引理 2，循环终止时 $r = 1$，此时剩余集合是单元素集 $\{h\}$，即最后剩下的整数。算法每轮的更新规则已由引理 1 的证明验证与真实删除结果一致，故最终 $h$ 就是所求。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。每轮 $r$ 减半，$n \le 10^{15} < 2^{50}$，至多约 50 轮，每轮 $O(1)$ 常数运算。
- **空间**：$O(1)$。只用了 `h`、`s`、`r`、`op` 四个标量，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long lastInteger(long long n) {
        long long head = 1;
        long long step = 1;
        long long rem = n;
        bool fromLeft = true;
        while (rem > 1) {
            if (!fromLeft && rem % 2 == 0) {
                head += step;
            }
            rem = (rem + 1) / 2;
            step *= 2;
            fromLeft = !fromLeft;
        }
        return head;
    }
};
```

### Python

```python
class Solution:
    def lastInteger(self, n: int) -> int:
        head = 1
        step = 1
        rem = n
        from_left = True
        while rem > 1:
            if not from_left and rem % 2 == 0:
                head += step
            rem = (rem + 1) // 2
            step *= 2
            from_left = not from_left
        return head
```

## 8. 边界情况与易错点

1. **$n = 1$**：循环不执行，返回 1（示例 3）。若把初值写成 `head = 0` 就会错。
2. **首项更新用错了 $r$**：必须用**本轮开始时**的 $r$ 判断奇偶，`head += step` 之后再更新 $r$。顺序颠倒会得到错误答案。
3. **方向搞反**：本题操作 1「从左侧删」删的是**第 2、4、6…** 个，即**保留第一个**，所以 $h$ 不变。若误以为删第一个（那是 390 题的规则），会得到镜像的答案（$n = 8$ 会答成 6）。
4. **操作 2 的「保留最后一个」**：从右侧删是从倒数第 2 个开始删，所以**最右元素永远保留**。这也是「$r$ 为偶数时新首项是原第 2 个」的原因。
5. **`int` 溢出**：$n \le 10^{15}$，`step` 会翻倍到 $2^{50}$ 量级，`int` 早已溢出。C++ 必须全程 `long long`。
6. **用 `ceil` 浮点函数**：`ceil(r/2.0)` 在 $r$ 很大时可能有精度问题，且正整数情形下 `(r+1)/2` 更快更安全。
7. **`fromLeft` 的初值**：题目规定从操作 1（左侧）开始，初值为 `true`。
8. **交替方向**：每轮后取反，别漏掉 `fromLeft = !fromLeft`，否则会连续两次同向删除，答案完全不同。
