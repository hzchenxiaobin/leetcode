# LeetCode K 连续位的最小翻转次数 题解

## 1. 题目概述

- **标题 / 题号**：K 连续位的最小翻转次数（#995，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-k-consecutive-bit-flips/
- **来源**：LeetCode 第 124 场周赛 Q3
- **难度**：困难
- **标签**：位运算、队列、数组、前缀和、滑动窗口

**题意**：给定二进制数组 `nums` 与整数 $k$。一次操作是选取长度为 $k$ 的**连续子数组**，把其中每个 $0$ 变 $1$、每个 $1$ 变 $0$（整体异或 1）。求使数组**不含 0** 所需的最少操作次数；不可能则返回 $-1$。

**约束**：

- $1 \le nums.length \le 10^5$
- $1 \le k \le nums.length$

> 💡 关键结构：翻转同一个区间两次等于没翻，所以每个区间要么翻一次、要么不翻；而长度为 $k$ 的窗口由**左端点**唯一确定，因此整个问题等价于求一组 $x_j \in \{0,1\}$。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,0], k = 1
输出：2
解释：翻 A[0]、再翻 A[2]，共 2 次。
```

**示例 2**

```text
输入：nums = [1,1,0], k = 2
输出：-1
解释：无论怎么翻长度为 2 的区间，都无法把最后一个 0 消掉。
```

**示例 3**

```text
输入：nums = [0,0,0,1,0,1,1,0], k = 3
输出：3
解释：翻 [0,2] → [1,1,1,1,0,1,1,0]，翻 [4,6] → [1,1,1,1,1,0,0,0]，翻 [5,7] → 全 1。
```

## 3. 解题思路

### 3.1 暴力思路

从左到右扫描，遇到 0 就翻转以它为左端点的窗口，每次翻转 $O(k)$，总复杂度 $O(nk)$。$n = 10^5$、$k = n$ 时是 $10^{10}$ 次操作，必然超时。另一个暴力是枚举所有窗口组合（$2^{n-k+1}$ 种），更不可行。

### 3.2 核心观察：最左的 0 只有一种救法

![最左的 0 只有一种救法](images/wc124_q3_force_leftmost.svg)

设 $x_j \in \{0,1\}$ 表示是否翻转「以 $j$ 为左端点」的窗口（$0 \le j \le n-k$）。由于翻转可交换、且同一窗口翻两次抵消，任何解都可以写成这组 $x_j$。位置 $i$ 的最终值只取决于**覆盖它的那些窗口**：

$$\text{final}(i) = \text{nums}[i] \oplus \bigoplus_{j=\max(0, i-k+1)}^{\min(i,\, n-k)} x_j .$$

现在从左往右逐个确定 $x_i$。当处理到位置 $i$ 时，$x_0, \dots, x_{i-1}$ 已经确定，而 $x_{i+1}, x_{i+2}, \dots$ 对应的窗口左端点都 $> i$，**覆盖不到**位置 $i$。所以位置 $i$ 上唯一还没定的变量就是 $x_i$，它的取值被完全迫定：

$$x_i = 1 \iff \text{（当前 $i$ 处的实际值）} = 0 .$$

于是解要么不存在（某个 $x_i$ 需要为 1 但 $i > n-k$，窗口会越界），要么**唯一**。既然是唯一解，它自然就是最小操作数解——不存在「另一种更少」的方案。

### 3.3 算法流程

![用「翻转奇偶」变量代替真取反](images/wc124_q3_parity_diff.svg)

问题只剩「快速知道位置 $i$ 的当前值」。用一个变量 `flip` 记录**覆盖当前位置的窗口数的奇偶**：

```text
1. diff[0..n] 全 0，flip = 0，ans = 0
2. for i in 0..n-1:
       flip ^= diff[i]                    # 吸收在 i 处结束的窗口
       若 (nums[i] ^ flip) == 0:           # 当前实际是 0，必须翻
           若 i + k > n: 返回 -1          # 窗口越界，无解
           ans += 1
           flip ^= 1                      # 本窗口覆盖 i
           diff[i + k] ^= 1               # 在 i+k 处抵消
3. 返回 ans
```

`diff` 是差分数组的异或版：`diff[p] ^= 1` 表示「从 $p$ 开始，之前那次翻转的影响到此结束」。

### 3.4 示例演算

![示例 3 的三次翻转](images/wc124_q3_walkthrough.svg)

对 `nums = [0,0,0,1,0,1,1,0]`、$k = 3$：

| 步 | 位置 | 当前实际值 | 操作 |
|----|------|------------|------|
| 1 | 0 | 0 | 翻 $[0,2]$ → `1111 0 1 1 0` |
| 2 | 1 | 1 | 跳过 |
| 3 | 2 | 1 | 跳过 |
| 4 | 3 | 1 | 跳过 |
| 5 | 4 | 0 | 翻 $[4,6]$ → `1111 1 0 0 0` |
| 6 | 5 | 0 | 翻 $[5,7]$ → `1111 1111` |
| 7 | 6、7 | 1 | 跳过 |

共 3 次，与题面一致。注意第 2、3 次翻转**互相重叠**，这是允许的：重叠部分被翻两次，等价于没翻。

## 4. 算法细节

1. **`diff` 的长度**：开到 $n+1$，因为 `i + k` 最大为 $n$（当 $i = n-k$ 时），需要能写入 `diff[n]` 而不越界。
2. **`flip` 的含义**：当前下标被多少个已选窗口覆盖，取**模 2**（用异或维护）。
3. **顺序**：先 `flip ^= diff[i]`（结算在 $i$ 结束的窗口），再判断 `nums[i] ^ flip`，顺序反了会把本应结束的影响多算一位。
4. **越界判定**：`i + k > n` 时窗口无法完整放下，直接返回 $-1$；注意是 `>` 而不是 `>=`（$i + k = n$ 恰好放得下）。
5. **ans 上界**：最多 $n$ 次翻转，`int` 足够。
6. **可以用队列替代 diff**：把每个翻转窗口的右端点入队，队首 `<= i` 时出队并翻转 `flip`，效果相同、空间为 $O(k)$。差分写法更简洁。

## 5. 正确性证明

记 $x_j \in \{0,1\}$（$0 \le j \le n-k$）表示是否翻除以 $j$ 为左端点的窗口，$\text{cov}(i)$ 为覆盖 $i$ 的窗口左端点集合。

**引理 1（解的表示）**：任何操作序列都等价于某个 $x \in \{0,1\}^{n-k+1}$，且位置 $i$ 的最终值为 $\text{nums}[i] \oplus \bigoplus_{j \in \text{cov}(i)} x_j$。

**证明**：翻转操作满足交换律（逐位异或），同一窗口翻两次等于不翻（$y \oplus 1 \oplus 1 = y$），故任何序列可化简为「每个窗口至多翻一次」，即由 $x$ 刻画。位置 $i$ 被且仅被 $\text{cov}(i)$ 中的窗口覆盖，每次覆盖对它异或 1，故最终值为原值异或这些 $x_j$ 之和。∎

**引理 2（逐个被迫定）**：对 $i = 0, 1, \dots, n-1$，在 $x_0, \dots, x_{i-1}$ 已确定后，$x_i$ 的取值被「位置 $i$ 最终为 1」唯一确定，且

$$x_i = 1 \iff \Bigl(\text{nums}[i] \oplus \bigoplus_{j \in \text{cov}(i),\, j < i} x_j\Bigr) = 0 .$$

**证明**：$\text{cov}(i) \subseteq \{i-k+1, \dots, i\}$，其中 $j > i$ 的项不可能出现；故 $\text{cov}(i) = \{j : \max(0,i-k+1) \le j \le \min(i, n-k)\}$，除 $x_i$ 外全部已确定。设已知部分异或和为 $P$，则最终值 $= \text{nums}[i] \oplus P \oplus x_i$，要求它等于 1，故 $x_i$ 必须取 $\text{nums}[i] \oplus P$ 的反：当 $\text{nums}[i]\oplus P = 0$ 时 $x_i = 1$，否则 $x_i = 0$。∎

**引理 3（贪心等价）**：算法中 `flip` 恰等于 $\bigoplus_{j \in \text{cov}(i), j < i} x_j$（已确定的覆盖项），且算法赋的 $x_i$ 与引理 2 一致。

**证明**：`flip` 在进入位置 $i$ 时，等于「左端点 $< i$ 且覆盖 $i$ 的窗口个数」的奇偶——每当算法在 $j$ 处翻窗，就令 `flip ^= 1` 覆盖 $j..j+k-1$，并在 `diff[j+k]` 处打标记，使 $i \ge j+k$ 后自动抵消。这正是 $\text{cov}(i)$ 中 $j < i$ 部分的异或和。判断 `nums[i] ^ flip == 0` 即 $\text{nums}[i] \oplus P = 0$，与引理 2 的赋值条件相同。∎

**引理 4（无解判定）**：若某步需要 $x_i = 1$ 而 $i > n-k$，则不存在任何合法解。

**证明**：$x_i$ 按下标只定义到 $n-k$（更靠后的位置放不下长度为 $k$ 的窗口）。此时位置 $i$ 被强制要求为 1，但在所有 $x$ 中它已经无法改变（$\text{cov}(i)$ 的成员都已确定），矛盾。故无解。∎

**定理**：算法返回最少的 $k$ 位翻转次数，无解时返回 $-1$。

**证明**：若算法返回 $-1$，由引理 4 无解。否则算法产出的 $x$ 满足「每个位置最终为 1」（由引理 2、3 逐步保证），是一个可行解，其代价为 $\sum x_i$，即算法返回的 `ans`。另一方面，由引理 2，任何可行解的 $x_i$ 都被同样的递推唯一确定，故可行解**唯一**，其代价必然等于 `ans`，因此不存在更少的操作数。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标做常数次异或与比较，`diff` 的标记与读取都是 $O(1)$。
- **空间**：$O(n)$ 的 `diff` 数组（也可用队列压到 $O(k)$）。相比暴力的 $O(nk)$ 时间，本题的关键就是把「真翻转」换成「奇偶标记」。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minKBitFlips(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> diff(n + 1, 0);
        int flip = 0;
        int ans = 0;
        for (int i = 0; i < n; i++) {
            flip ^= diff[i];
            if ((nums[i] ^ flip) == 0) {
                if (i + k > n) return -1;
                ans++;
                flip ^= 1;
                diff[i + k] ^= 1;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minKBitFlips(self, nums: list[int], k: int) -> int:
        n = len(nums)
        diff = [0] * (n + 1)
        flip = 0
        ans = 0
        for i in range(n):
            flip ^= diff[i]
            if (nums[i] ^ flip) == 0:
                if i + k > n:
                    return -1
                ans += 1
                flip ^= 1
                diff[i + k] ^= 1
        return ans
```

## 8. 边界情况与易错点

1. **$k = 1$**：每个 0 都要单独翻一次，答案就是 0 的个数（示例 1）。
2. **$k = n$**：只能整体翻或不翻，若原数组不是全 1 也不是全 0，返回 $-1$。
3. **越界条件是 `>`**：`i + k == n` 时窗口正好放下，不能写成 `>=`。
4. **`diff` 开到 $n+1$**：`i + k` 可为 $n$，数组不够长会写越界。
5. **忘记结算 `diff[i]`**：`flip` 会一直累加，导致后面所有判断都错。
6. **重复翻同一窗口**：算法不会重复翻（每个 $x_i$ 只决定一次），但示例 3 中**重叠的不同窗口**是允许的。
7. **全 1 输入**：无需任何翻转，`ans = 0`。
8. **全 0 且 $k$ 不整除 $n$**：例如 `[0,0,0]`、$k=2$，翻 $[0,1]$ 后剩 `[0]`，再翻越界 → $-1$。
