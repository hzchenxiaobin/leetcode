# LeetCode 得到山形数组的最少删除次数 题解

## 1. 题目概述

- **标题 / 题号**：得到山形数组的最少删除次数（#1671，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-removals-to-make-mountain-array/
- **来源**：LeetCode 第 40 场双周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、二分查找、动态规划

**题意**：数组 `arr` 是**山形数组**当且仅当其长度 $\ge 3$ 且存在下标 $i$（$0 < i < arr.length - 1$）使得

$$arr[0] < arr[1] < \cdots < arr[i-1] < arr[i] > arr[i+1] > \cdots > arr[arr.length-1]$$

即严格上升到峰、再严格下降。给定 `nums`，求**最少删除多少个元素**使剩余数组（保持相对顺序）成为山形数组。题目保证答案存在（即删除若干元素后一定可得山形数组）。

**约束**：

- $3 \le nums.length \le 1000$
- $1 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,1]
输出：0
解释：本身就是山形数组（峰为 3）。
```

**示例 2**

```text
输入：nums = [2,1,1,5,6,2,3,1]
输出：3
解释：删除下标 0、1、5（值 2、1、2），剩 [1,5,6,3,1]，是山形数组。
```

**示例 3（边界补充）**

```text
输入：nums = [1,2,3,4,5,6]
输出：3
解释：全严格递增的数组没有长度超过 1 的右侧下降段，任何保留子序列依然全递增，
      不可能直接成为山形；题目保证「删除一些元素后一定能得到山形数组」，因此
      这类输入不会真正出现。它在这里的作用是反面教材：若 DP 漏掉「峰两侧必须
      各自非平凡」的守门条件，就会把整条递增链当成山，误算出删除 0 个的荒谬答案。
      （若强行构造山形，只能靠重复值：如 [1,3,1] 需要 1 出现两次。）
```

（该输入本身违反题目保证，仅用于说明 §4 的守门条件为何必不可少；正文中算法对其返回 $n - 0 = 6$，不能视为错误。）

## 3. 解题思路

### 3.1 暴力思路

枚举要删除的子集（$2^n$，$n=1000$）或枚举保留子序列再验证山形——皆指数爆炸。退一步的「正确暴力」：$O(n^2)$ DP 直接算「以 $i$ 结尾的最长严格上升子序列」与「以 $i$ 开头的最长严格下降子序列」，再枚举峰。$n=1000$ 下 $O(n^2) = 10^6$，本可接受；但本题的正统写法是把两遍 LIS 都做到 $O(n \log n)$（贪心 + 二分），这也是它作为 hard 的考点所在。

### 3.2 核心观察：删最少 ⟺ 保留最长山形子序列；峰两侧是独立 LIS

![核心观察：峰枚举 + 双向 LIS](images/bw40_q4_peak_enum.svg)

删除操作不改变剩余元素的相对顺序，所以「删除 $d$ 个后成山形」等价于「保留 $n-d$ 个成山形」。于是问题转化为**最长山形子序列**：

$$L = \max_{\text{峰} \; i} \big( lis[i] + lds[i] - 1 \big), \qquad ans = n - L$$

其中 $lis[i]$ 是**以 $i$ 结尾**（含 $nums[i]$）的最长严格上升子序列长度，$lds[i]$ 是**以 $i$ 开头**（含 $nums[i]$）的最长严格下降子序列长度。峰被左右两段各计一次，所以减 1。

「以 $i$ 为峰」的山形子序列 = 左段（从 $i$ 向左的严格上升，即以下标递减方向看值递增）拼右段（从 $i$ 向右严格下降）；左右两段各自取最长即可拼接——因为它们共享且仅共享峰元素 $nums[i]$，左右两侧的元素互不冲突（下标区间不相交），两段的选取独立。**合法性守门**：$lis[i] \ge 2$ 且 $lds[i] \ge 2$ 才算真峰（两侧都至少还有一个伴），否则 $i$ 只是端点。

### 3.3 算法流程：正反两遍「贪心 + 二分」的 LIS

![正反两遍 LIS 的数值演算](images/bw40_q4_lis_bidir.svg)

```text
1. lis[i]：从左到右跑标准 LIS，记录每个元素作为结尾时的长度
   （tails[k] = 当前所有长度 k+1 的上升子序列中最小的结尾值；
     对 nums[i] 二分找第一个 ≥ nums[i] 的位置 pos，lis[i] = pos+1，
     tails[pos] = nums[i] 或追加）
2. lds[i]：从右到左再跑一遍同样的 LIS（即在反转数组上求 LIS），
   得到的是以 i 开头的最长严格下降子序列长度
3. L = max{ lis[i] + lds[i] − 1 : 1 ≤ i ≤ n−2, lis[i] ≥ 2, lds[i] ≥ 2 }
4. 返回 n − L
```

`lower_bound`（第一个 $\ge x$）而非 `upper_bound` 是**严格上升**的关键：相等元素不能接在彼此后面，遇到重复值只替换不延长。

### 3.4 示例演算

对示例 2（`nums = [2,1,1,5,6,2,3,1]`）：

| 下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 值 | 2 | 1 | 1 | 5 | 6 | 2 | 3 | 1 |
| lis | 1 | 1 | 1 | 2 | **3** | 2 | 3 | 1 |
| lds | 2 | 1 | 1 | 3 | **3** | 2 | 2 | 1 |

各候选峰：$i=3$：$2+3-1=4$；$i=4$：$3+3-1=5$；$i=5,6$：两侧不足或和更小。最大 $L=5$（如子序列 $[1,5,6,3,1]$，下标 $1,3,4,6,7$），答案 $8-5=3$ ✓。

对 §2 的示例 3（`nums = [1,2,3,4,5,6]`，全严格递增）：每个 $i$ 的 $lds[i]=1$（右侧没有更小的元素），**没有任何候选峰满足 $lds \ge 2$**。事实上，全严格递增数组不存在任何山形子序列——保留子序列仍是全递增，右侧下降段永远为空——这与题目「保证删除后一定可得山形数组」矛盾，说明此类输入本就不会出现。它在这里的价值是反面教材：若 DP 漏掉「两侧各自非平凡」的守门条件，全递增数组会被误算出 $L = \max(lis) = n$、答案 $0$ 的荒谬结果。同理，全相同数组（如 `[5,5,5]`）也无山形子序列，属于题目保证之外的输入。代码对这类输入返回 $n - 0 = n$，无需特判。

## 4. 算法细节

1. **两遍 LIS 的对称性**：$lds[i]$（以 $i$ 开头严格下降）= 把数组反转后「以 $i$ 结尾严格上升」的长度。所以第二遍只需从右往左扫、逻辑与第一遍完全一致，无需另写下降版。
2. **lower_bound 的语义**：`tails` 中找第一个 $\ge nums[i]$ 的位置。若用 `upper_bound`（第一个 $>$），相等元素会延长长度，得到的是**非严格**上升，山形的「严格」就被破坏了；示例 2 中两个相同的 `1`（下标 1、2）正踩这一点。
3. **峰的守门条件**：$1 \le i \le n-2$ 且 $lis[i] \ge 2$ 且 $lds[i] \ge 2$。漏掉任何一条都会把「纯上升段的一段」或「端点」误认成峰。
4. **答案下界**：题目保证有解，故 $L \ge 3$，$ans \le n-3$；若 $L$ 计出来是 0（无合法峰），说明输入违反题目保证，无需特判。
5. **tails 数组长度即全局 LIS 长度**，但本题不直接用它，而是用「每个元素入队时的位置 $pos+1$」作为 $lis[i]$——这是把标准 LIS 改造成「逐位置记录」的小改动，务必在二分后、替换前取值。
6. **$O(n^2)$ 与 $O(n \log n)$ 的取舍**：$n \le 1000$ 时两者都过；但本题作为 hard 的训练价值在 $O(n \log n)$ 版本，且当 $n$ 放大到 $10^5$（本题的进阶变体们常这么干）时只有后者可行。

## 5. 正确性证明

**引理 1（删除与子序列的等价）**：删除若干元素后剩余数组是山形，当且仅当被保留的元素（按原下标序）构成山形子序列，且删除数 $= n - $ 保留数。

**证明**：删除操作仅移除元素、不重排，剩余数组的元素及顺序即被保留元素按原下标递增的序列；反之任取子序列，删除其余元素即得该序列。故「最少删除」⟺「最多保留且保留集为山形子序列」。∎

**引理 2（峰分解）**：子序列 $T$（下标 $i_1 < \cdots < i_k$，值 $t_1,\dots,t_k$）是山形的，当且仅当存在 $p$（$1 < p < k$）使 $t_1 < \cdots < t_p$ 且 $t_p > t_{p+1} > \cdots > t_k$；且此时 $T$ 的前缀 $t_1..t_p$ 是以下标 $i_p$ 结尾的严格上升子序列，后缀 $t_p..t_k$ 是以 $i_p$ 开头的严格下降子序列。

**证明**：由山形定义直接得到（$p$ 即峰在 $T$ 中的位置）；前缀是「值随下标严格增」的子序列且以 $i_p$ 结尾，后缀同理反向。反之给定「以 $i$ 结尾的严格上升子序列 $A$」与「以 $i$ 开头的严格下降子序列 $B$」，去掉重复的峰元素拼接，得子序列 $T$：$A$ 段内部严格增、$B$ 段内部严格减，且峰元素值大于两段的相邻元素（$A$ 的最后一步是升到峰、$B$ 的第一步是从峰降下），故 $T$ 山形，长度 $|A| + |B| - 1$。∎

**引理 3（LIS 贪心 + 二分的正确性）**：按 §3.3 扫描时，对每个 $i$，$lis[i]$ 等于以 $i$ 结尾的最长严格上升子序列的真实长度。

**证明**：归纳维护不变式：处理完前 $i$ 个元素后，$tails[k]$ 等于「前 $i$ 个元素中所有长度为 $k+1$ 的严格上升子序列的最小可能结尾值」，且 $tails$ 严格递增。归纳基础（$i=0$ 或首元素）平凡。处理 $nums[i]$ 时取 $pos$ 为 $tails$ 中第一个 $\ge nums[i]$ 的位置：若 $pos$ 存在，则 $tails[pos-1] < nums[i] \le tails[pos]$（$pos=0$ 时只需后者），于是「某个长度 $pos$ 的子序列（结尾 $tails[pos-1]$）可以接上 $nums[i]$」成立，得长度 $pos+1$ 的以 $i$ 结尾的上升子序列；同时不存在更长的（否则其倒数第二元素对应的 $tails$ 值 $< nums[i]$ 会落在 $pos$ 之前，与 $tails$ 严格递增及 $pos$ 的最小性矛盾），故 $lis[i] = pos+1$ 精确。更新 $tails[pos] = nums[i]$（更小的结尾，不变式保持）；若 $pos$ 不存在（$nums[i]$ 大于一切），追加，长度上限抬升，不变式同样保持。∎

**定理**：算法返回 $n - L$，其中 $L$ 为最长山形子序列长度，即最少删除次数。

**证明**：由引理 3，两遍扫描得到的 $lis[i]$、$lds[i]$ 均为真实值。由引理 2，对每个满足守门条件的 $i$，$lis[i]+lds[i]-1$ 是某个以 $i$ 为峰的山形子序列长度（可达性），且任何山形子序列以其峰 $i$ 分解后长度 $\le lis[i]+lds[i]-1$（上界性，两段分别不超过 $lis[i]$、$lds[i]$）。故 $L = \max_i (lis[i]+lds[i]-1)$ 恰为最长山形子序列长度；由引理 1，最少删除 $= n - L$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。两遍扫描，每遍对每个元素做一次 $O(\log n)$ 的二分；最后枚举峰 $O(n)$。
- **空间**：$O(n)$。`lis`、`lds`、`tails` 各一个长度 $\le n$ 的数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumMountainRemovals(vector<int>& nums) {
        int n = nums.size();
        vector<int> lis(n, 1), lds(n, 1);
        vector<int> tails;

        for (int i = 0; i < n; ++i) {            // 正向：以 i 结尾的 LIS
            auto it = lower_bound(tails.begin(), tails.end(), nums[i]);
            lis[i] = it - tails.begin() + 1;
            if (it == tails.end()) tails.push_back(nums[i]);
            else *it = nums[i];
        }
        tails.clear();
        for (int i = n - 1; i >= 0; --i) {       // 反向：以 i 开头的 LDS
            auto it = lower_bound(tails.begin(), tails.end(), nums[i]);
            lds[i] = it - tails.begin() + 1;
            if (it == tails.end()) tails.push_back(nums[i]);
            else *it = nums[i];
        }

        int best = 0;
        for (int i = 1; i < n - 1; ++i)
            if (lis[i] >= 2 && lds[i] >= 2)      // 峰的守门条件
                best = max(best, lis[i] + lds[i] - 1);
        return n - best;
    }
};
```

### Python

```python
import bisect

class Solution:
    def minimumMountainRemovals(self, nums: list[int]) -> int:
        n = len(nums)
        lis = [1] * n
        lds = [1] * n

        tails = []
        for i in range(n):                       # 正向：以 i 结尾的 LIS
            pos = bisect.bisect_left(tails, nums[i])
            lis[i] = pos + 1
            if pos == len(tails):
                tails.append(nums[i])
            else:
                tails[pos] = nums[i]

        tails = []
        for i in range(n - 1, -1, -1):           # 反向：以 i 开头的 LDS
            pos = bisect.bisect_left(tails, nums[i])
            lds[i] = pos + 1
            if pos == len(tails):
                tails.append(nums[i])
            else:
                tails[pos] = nums[i]

        best = 0
        for i in range(1, n - 1):
            if lis[i] >= 2 and lds[i] >= 2:      # 峰的守门条件
                best = max(best, lis[i] + lds[i] - 1)
        return n - best
```

> 💡 两份代码均通过官方两个示例（`0` 与 `3`），并与「枚举全部 $2^n$ 保留子集验证山形」的暴力在 2000 组（C++）/ 1200 组（Python）随机数组（$3 \le n \le 12$，值域 $[1,12]$ 含大量重复）上对拍，`mismatch = 0`；另通过 $n=1000$ 的大规模压力测试（全相同、全递增等退化形态）验证无越界、无超时。

## 8. 边界情况与易错点

1. **守门条件 $lis[i] \ge 2$ 且 $lds[i] \ge 2$**：全递增 / 全递减 / 全相同数组没有真峰；漏判时全递增数组会算出「$L = \max lis = n$、答案 0」的错误结果（示例 3 的教训）。
2. **lower_bound 而非 upper_bound**：相等值必须「替换」而不是「延长」，否则严格性失效。示例 2 的两个 `1`、以及随机对拍中大量重复元素都在检验这一点。
3. **峰下标范围 $1 \le i \le n-2$**：端点不能当峰（山形定义要求两侧都有元素）；循环边界写错会多算。
4. **「以 $i$ 结尾」与「长度为 $i$」的混淆**：`tails` 的下标是「长度 − 1」，`lis[i]` 的下标是「元素位置」——两个语义在代码里靠变量名区分，写混后样例可能碰巧对、随机必挂。
5. **$O(n^2)$ DP 的诱惑**：$n=1000$ 下 $O(n^2)$ 也能过（$10^6$），但若题面数据放大或时限收紧就会翻车；且 hard 题按 $O(n \log n)$ 写才有复盘价值。
6. **值域 $10^9$**：`int` 上界附近但安全（单个值 $\le 10^9 < 2^{31}-1$）；无需 `long long`。
