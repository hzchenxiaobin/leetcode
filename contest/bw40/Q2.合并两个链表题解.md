# LeetCode 合并两个链表 题解

## 1. 题目概述

- **标题 / 题号**：合并两个链表（#1669，medium）
- **链接**：https://leetcode.cn/problems/merge-in-between-linked-lists/
- **来源**：LeetCode 第 40 场双周赛 Q2
- **难度**：中等
- **标签**：链表

**题意**：给定链表 `list1`（$n$ 个节点）与 `list2`（$m$ 个节点），以及整数 $a, b$（$1 \le a \le b < n-1$）。要求**删除** `list1` 中下标从 $a$ 到 $b$ 的全部节点，并把整个 `list2` **接**在被删除的位置。返回结果链表的头指针。

**约束**：

- $3 \le n \le 10^4$
- $1 \le m \le 10^4$
- $1 \le a \le b < n-1$
- `list1`、`list2` 中的节点值 $0 \le val \le 10^9$

## 2. 示例

**示例 1**

```text
输入：list1 = [10,1,13,6,9,5], a = 3, b = 4, list2 = [1000000,1000001,1000002]
输出：[10,1,13,1000000,1000001,1000002,5]
解释：删除下标 3、4 的节点（值 6、9），把 list2 接在 13 与 5 之间。
```

**示例 2**

```text
输入：list1 = [0,1,2,3,4,5,6], a = 2, b = 5, list2 = [1000000,1000001,1000002,1000003,1000004]
输出：[0,1,1000000,1000001,1000002,1000003,1000004,6]
解释：删除下标 2..5（值 2,3,4,5），list2 顶上，尾巴接原下标 6。
```

## 3. 解题思路

### 3.1 暴力思路

把链表摊平成数组，删掉区间再拼回去、或逐节点重建链表——$O(n+m)$ 时间但 $O(n+m)$ 额外空间，且完全没用到「链表删除 = 改两条指针」的本质。另一类「暴力」是先走 $a-1$ 步找到 `before`，再从头走 $b+1$ 步找 `after`，两趟独立扫描；正确但多走了一段冤枉路。

### 3.2 核心观察：接缝只有两处，各走一趟指针即可

![核心观察：只改 before→list2 与 list2尾→after 两条指针](images/bw40_q2_splice_model.svg)

链表的「删除区间 + 插入链」在指针层面只需要两个锚点：

- `before`：下标 $a-1$ 的节点（保留段的最后一个），它将指向 `list2` 的头；
- `after`：下标 $b+1$ 的节点（保留段的下一个），`list2` 的尾将指向它。

连接后结果为 `list1[0..a-1] → list2[0..m-1] → list1[b+1..n-1]`。被删区间 $[a, b]$ 的节点从此不可达，无需（也无法低成本）逐个释放——题目不要求释放内存。约束 $1 \le a$ 与 $b < n-1$ 保证 `before`、`after` 都真实存在，连判空都省了。

### 3.3 算法流程：一个游标两次步行

![指针走位：先停 a−1，再多走 (b+1)−(a−1) 步](images/bw40_q2_pointer_walk.svg)

```text
1. before = list1；走 a−1 步 → before 停在下标 a−1
2. after = before；从下标 a−1 再走 (b+1)−(a−1) = b−a+2 步 → after 停在下标 b+1
3. tail2 = list2；走到 list2 的尾节点
4. before.next = list2      # 接头
   tail2.next = after       # 接尾
5. 返回 list1（头指针不变）
```

用同一个游标先停 `before` 再继续走，省掉了第二次从头出发；两段步行合计恰 $b+1$ 步。

### 3.4 示例演算

示例 2（`list1 = [0,1,2,3,4,5,6]`，$a=2$，$b=5$）：`before` 从头走 1 步停在下标 1（值 1）；`after` 从 `before` 再走 $5-2+2=5$ 步，依次越过下标 2,3,4,5,6，停在下标 6（值 6）。`tail2` 走到 `1000004`。随后 `1 → 1000000`、`1000004 → 6` 两条指针落地，结果 `0,1,1000000,…,1000004,6`，与示例输出一致。

## 4. 算法细节

1. **步数别数错**：`before` 走 $a-1$ 步；`after` 从 `before` 出发再走 $b-a+2$ 步（先到 $a$ 再数到 $b+1$）。写成「走 $b+1$ 步」从头上重新出发也对，但要重新遍历前缀。
2. **`list2` 尾节点别忘找**：接尾指针 `tail2.next = after` 是最容易漏的一步——只接了头会得到一个在 `list2` 处戛然而止的断链。
3. **返回头指针**：`list1` 的头永远不会被删（$a \ge 1$），直接返回 `list1`；不需要哑结点。加哑结点也行，但纯属习惯。
4. **内存管理**：竞赛语境下不 `delete` 被删节点；工程语境（或面试官追问）可从 `before->next` 走到 `after` 逐个 `delete`，注意先把 `after` 存下来再删，否则断链后找不到出口。
5. **下标从 0 开始**：题面「下标 $a$ 到 $b$」均为 0 基；若误用 1 基会错位一格。

## 5. 正确性证明

**引理 1（接缝等价性）**：设原 `list1` 为 $u_0 \to u_1 \to \cdots \to u_{n-1}$，`list2` 为 $v_0 \to \cdots \to v_{m-1}$。执行 §3.3 的两条指针赋值后，从 `list1` 出发沿 `next` 可达的节点序列恰为 $u_0, \dots, u_{a-1}, v_0, \dots, v_{m-1}, u_{b+1}, \dots, u_{n-1}$。

**证明**：赋值前，`before = u_{a-1}`、`after = u_{b+1}`（步行计数直接验证：从 $u_0$ 走 $a-1$ 步到 $u_{a-1}$；再走 $b-a+2$ 步到 $u_{a-1+(b-a+2)} = u_{b+1}$）。`before.next = list2` 使 $u_{a-1}$ 的后继变为 $v_0$；`tail2.next = after` 使 $v_{m-1}$ 的后继变为 $u_{b+1}$。其余节点的 `next` 未被触碰：$u_i$（$i < a-1$）仍指向 $u_{i+1}$，$v_j$（$j<m-1$）仍指向 $v_{j+1}$，$u_i$（$i > b+1$）指向不变。沿 `next` 遍历：从 $u_0$ 依次到 $u_{a-1}$（原有指针），跳到 $v_0$（新指针），依次到 $v_{m-1}$（原有指针），跳到 $u_{b+1}$（新指针），依次到 $u_{n-1}$（原有指针），$u_{n-1}$ 的 `next` 为空，遍历终止。∎

**定理**：算法返回的链表正是「删除 `list1` 下标 $a..b$ 节点、把 `list2` 接入」的结果。

**证明**：目标结果由三段拼接：保留前缀 $u_0..u_{a-1}$、完整的 `list2`、保留后缀 $u_{b+1}..u_{n-1}$，且段间以 `next` 相连。引理 1 表明算法产出的可达序列与此逐节点一致；又链表由头指针与 `next` 唯一确定，故返回的 `list1` 即目标链表。被删节点 $u_a..u_b$ 不在可达序列中，等价于删除（其内存是否释放不影响链表语义）。∎

## 6. 复杂度分析

- **时间**：$O(n + m)$。步行定位 `before`/`after` 共 $b+1 \le n$ 步，找 `list2` 尾 $m$ 步，两次指针赋值 $O(1)$。
- **空间**：$O(1)$。只用了三个指针变量，原地拼接，无新节点。

## 7. 参考代码

### C++

```cpp
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     ListNode *next;
 *     ListNode() : val(0), next(nullptr) {}
 *     ListNode(int x) : val(x), next(nullptr) {}
 *     ListNode(int x, ListNode *next) : val(x), next(next) {}
 * };
 */
class Solution {
public:
    ListNode* mergeInBetween(ListNode* list1, int a, int b, ListNode* list2) {
        ListNode* before = list1;
        for (int i = 0; i < a - 1; ++i) before = before->next;   // 下标 a-1
        ListNode* after = before;
        for (int i = a - 1; i <= b; ++i) after = after->next;    // 下标 b+1
        ListNode* tail2 = list2;
        while (tail2->next) tail2 = tail2->next;                 // list2 尾
        before->next = list2;                                    // 接头
        tail2->next = after;                                     // 接尾
        return list1;
    }
};
```

### Python

```python
# Definition for singly-linked list.
# class ListNode:
#     def __init__(self, val=0, next=None):
#         self.val = val
#         self.next = next

class Solution:
    def mergeInBetween(self, list1: ListNode, a: int, b: int, list2: ListNode) -> ListNode:
        before = list1
        for _ in range(a - 1):                  # 下标 a-1
            before = before.next
        after = before
        for _ in range(a - 1, b + 1):           # 下标 b+1
            after = after.next
        tail2 = list2
        while tail2.next:                       # list2 尾
            tail2 = tail2.next
        before.next = list2                     # 接头
        tail2.next = after                      # 接尾
        return list1
```

## 8. 边界情况与易错点

1. **$a = 1$**：`before` 停在下标 0（头节点本身），`for` 循环零次，天然正确；不需要哑结点特判。
2. **$b = n-2$**：`after` 停在最后一个节点，接尾后链表以原尾收束；`b < n-1` 的约束保证 `after` 不会越出链表。
3. **步数差一（最常见 bug）**：`after` 循环写成 `for (i = 0; i <= b; ++i)` 从 `list1` 出发则停在下标 $b$（少走一步）——从 `before`（下标 $a-1$）出发时正确写法是走 $b-a+2$ 步；两个起点两种数法混用就会差一。建议固定「`after` 从 `before` 继续」并注释清楚。
4. **`list2` 长度为 1**：`while (tail2->next)` 不进循环，`tail2` 即头即尾，正确。
5. **修改顺序**：先 `before->next = list2` 再 `tail2->next = after`，或反过来，都不影响结果（两条赋值互不读取对方写入的字段）；但若手滑把 `after` 的获取放在 `before->next` 赋值**之后**且仍从 `before` 出发走，就会走进 `list2` 而不是原链——务必先定位后缝合。
6. **不要动被删段**：遍历/释放被删段都是多余动作；把它当成「已被丢弃的内存」即可。
