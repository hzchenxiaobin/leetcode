# LeetCode 用户分组 题解

## 1. 题目概述

- **标题 / 题号**：用户分组（#1282，medium）
- **链接**：https://leetcode.cn/problems/group-the-people-given-the-group-size-they-belong-to/
- **来源**：LeetCode 第 166 场周赛 Q2
- **难度**：中等
- **标签**：贪心，数组，哈希表

**题意**：有 $n$ 个人，编号 $0 \sim n-1$。`groupSizes[i]` 表示第 $i$ 个人所在组的人数。要求把所有人划分成若干组，使得**每个人 $i$ 所在的组恰好有 `groupSizes[i]` 个人**。每个人必须出现且只出现一次；若有多解，返回任意一个。题目保证至少存在一个合法解。

**约束**：

- $1 \le n = \text{groupSizes.length} \le 500$
- $1 \le \text{groupSizes}[i] \le n$
- 输入保证存在合法分组，因此对任意值 $s$，满足 $\text{groupSizes}[i] = s$ 的人数必是 $s$ 的倍数

## 2. 示例

**示例 1**

```text
输入：groupSizes = [3,3,3,3,3,1,3]
输出：[[5],[0,1,2],[3,4,6]]
解释：第 5 人的 groupSizes[5] = 1，单独成组 [5]，长度为 1，相符；
      第 0、1、2 人的值都是 3，组成长度为 3 的组 [0,1,2]；
      第 3、4、6 人的值都是 3，组成长度为 3 的组 [3,4,6]。
      [[2,1,6],[5],[0,4,3]] 等同样是正确答案。
```

**示例 2**

```text
输入：groupSizes = [2,1,3,3,3,2]
输出：[[1],[0,5],[2,3,4]]
解释：值 1 → 只有第 1 人，单独成组；值 2 → 第 0、5 人凑成一组；
      值 3 → 第 2、3、4 人凑成一组，每组长度都等于成员的标注值。
```

**补充示例（$n = 1$ 的退化情形）**

```text
输入：groupSizes = [1]
输出：[[0]]
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是搜索所有划分：把 $0 \sim n-1$ 依次放进「已有的某个组」或「新开一个组」，最后检查每组的长度是否等于成员标注的值。$n$ 个元素的划分方案数是贝尔数 $B_n$，$B_{500}$ 是天文数字，完全不可行。

换一种「按组挑人」的写法也一样：先从剩下的人里选出若干人组成一个长度等于其标注值的组，再递归处理剩余的人，方案数是 $\prod \binom{\cdot}{\cdot}$ 量级的组合爆炸。**必须利用本题的特殊结构**：组只由「长度」定义，人与人之间没有任何别的约束。

### 3.2 核心观察：按 groupSize 分桶，桶内自由切分

![按 groupSize 分桶：同桶才能同组](images/wc166_q2_bucket_model.svg)

两条互相配合的观察：

1. **同组必同值**：若 $i$ 与 $j$ 同组且组长为 $L$，则 $\text{groupSizes}[i] = L$ 且 $\text{groupSizes}[j] = L$。所以**不同值的人永远不可能同组**。
2. **同值可任意切**：把所有值等于 $s$ 的人收进桶 $V_s$，只要把 $V_s$ 切成若干大小恰为 $s$ 的块，每块就是合法组——因为块内每个人的标注值都是 $s$，正好等于块的长度。

这两条把原问题**完全解耦**成对每个 $s$ 独立的子问题：不同桶之间互不干扰，桶内的人彼此完全等价（没有任何「谁必须和谁一组」的额外要求）。于是「怎么切」不再重要，**只需保证每块恰好 $s$ 人**。

> 💡 对比：若题目额外要求「同组的人必须互为朋友」或「组内编号连续」，桶内的人就不再等价，问题会退化成图着色 / 排序贪心（见「相关题目与扩展」中的 846）。本题之所以容易，正是因为缺少这类耦合。

### 3.3 算法流程：一次扫描 + 满员收割

![一次扫描 + 桶计数：满员即刻收割](images/wc166_q2_greedy_flow.svg)

1. 维护哈希表（或数组）`bucket`：`bucket[s]` 存放「标注值为 $s$、但还没凑够一组的人」。
2. 从左到右扫描 $i = 0 \sim n-1$，令 $s = \text{groupSizes}[i]$，把 $i$ 追加进 `bucket[s]`。
3. 若 `bucket[s]` 的长度恰好等于 $s$，立即把它作为一组写入答案，并清空该桶。
4. 扫描结束返回答案。

为什么「一满就收割」是对的：桶内所有人都标注同一个 $s$，先收谁后收谁不影响合法性；桶小等于 $s$ 时提前收割会让某些组不满 $s$ 人，桶大于 $s$ 时再收割则会超员。**恰好等于 $s$ 时收割是唯一可行的时机**。

### 3.4 示例演算

![示例 1 逐步入桶与收割](images/wc166_q2_walkthrough.svg)

对示例 1 走一遍（见上表），三个绿色行分别在 $i = 2, 5, 6$ 触发收割，得到 `[[0,1,2],[5],[3,4,6]]`。它与官方输出 `[[5],[0,1,2],[3,4,6]]` 的分组完全相同，只是组的先后顺序不同——题目允许任意顺序。

对示例 2：$s = 2$ 的桶依次收第 0、5 人，成组 `[0,5]`；$s = 1$ 的桶收到第 1 人立刻成组 `[1]`；$s = 3$ 的桶收第 2、3、4 人成组 `[2,3,4]`。

## 4. 算法细节

1. **桶的键值域很小**：$1 \le \text{groupSizes}[i] \le n \le 500$，直接用数组 `vector<vector<int>> bucket(n + 1)` 即可，省掉哈希开销；注意必须开 $n + 1$ 格，否则 $s = n$ 时越界。
2. **满员判断放在 push 之后**：先 `push_back(i)` 再比较 `size() == s`，这样 $s = 1$ 的人也能立刻成组；若先判断再 push，$s = 1$ 会漏掉整组。
3. **用 `==` 而不是 `>=`**：桶内人数永远不会超过 $s$（一到 $s$ 立刻清空），`==` 可以作为运行时不变量自检，`>=` 虽然也能过，却会掩盖逻辑漏洞。
4. **C++ 的引用与清空**：`vector<int>& bucket = buckets[s];` 之后只做 `push_back` 与 `clear`，不 `erase`，引用不会失效；若改成 `std::move` 进答案再 `erase(s)`，`bucket` 会变成悬空引用，必须重新取一次。
5. **Python 的别名陷阱**：`result.append(bucket)` 追加的是**同一个 list 对象**，之后继续 `bucket.append(...)` 会把已经输出的组改坏。正确写法是追加之后执行 `buckets[s] = []`（或 `bucket.clear()`），让旧组与新桶彻底断开。
6. **组内顺序天然升序**：按下标从小到大扫描，同一桶内先入桶的人编号更小，因此每组内部天然升序；即使题目额外要求组内升序，也无需再排序。
7. **组数可以自检**：答案的组数应等于 $\sum_s \frac{|V_s|}{s}$，元素总数应等于 $n$；调试时打印这两个值能立刻发现「漏收 / 重复收」。
8. **无需预先判整除**：题面保证有解，$|V_s|$ 必是 $s$ 的倍数；若要在「不保证有解」的变体上做判定，可先统计每个值的出现次数并检查 $\text{cnt}[s] \bmod s = 0$。

## 5. 正确性证明

**引理 1（同组同值）**：在任意合法分组中，若 $i, j$ 同属组 $G$，则 $\text{groupSizes}[i] = \text{groupSizes}[j] = |G|$。

**证明**：题意要求每个人所在的组长度等于其标注值，即 $|G| = \text{groupSizes}[i]$；对 $j$ 同理，故两者都等于 $|G|$。∎

**引理 2（桶内任意切分合法）**：设 $V_s = \{i \mid \text{groupSizes}[i] = s\}$，且 $|V_s|$ 是 $s$ 的倍数。把 $V_s$ 任意划分成 $|V_s| / s$ 个大小为 $s$ 的块，则每一块都是合法组。

**证明**：任取其中一块 $B$，有 $|B| = s$；对任意 $i \in B$，由 $i \in V_s$ 得 $\text{groupSizes}[i] = s = |B|$，满足题面要求，故 $B$ 合法。∎

**引理 3（算法输出是一次划分）**：算法输出的每个组都恰好是「某个 $s$ 的桶里连续入桶的 $s$ 个下标」，因而各组两两不交，且在对应的 $V_s$ 上构成一次划分。

**证明**：桶 `bucket[s]` 只接收满足 $\text{groupSizes}[i] = s$ 的人（3.3 节第 2 步），故桶内元素全在 $V_s$ 中。每次收割取走桶内全部 $s$ 个元素并把桶清空，此后这些下标不再被访问，故不同组两两不交；同一个 $s$ 的所有人由同一个桶依次处理，故他们在 $V_s$ 上被切成若干大小为 $s$ 的块，构成一次划分。∎

**引理 4（无遗漏）**：算法结束时所有桶为空，且每个人恰好出现在一个组中。

**证明**：固定 $s$。设 $t$ 为已处理的 $V_s$ 中的人数，$r_t$ 为此时桶内人数。初始 $r_0 = 0$。若 $r_t < s - 1$，追加一人后不满 $s$，$r_{t+1} = r_t + 1$；若 $r_t = s - 1$，追加后恰好 $s$ 人触发收割并清空，$r_{t+1} = 0$。两种情形统一写成 $r_{t+1} = (r_t + 1) \bmod s$，由归纳得 $r_t = t \bmod s$。取 $t = |V_s| = k_s s$，得 $r = 0$，即桶为空。又当 $t \bmod s = 0$ 且 $t \ge 1$ 时，第 $t$ 个入桶的人恰好随满员的桶被收割，故 $V_s$ 中每个人都被收割一次；每个下标只被扫描一次，因此每人恰好出现在一个组中。∎

**定理**：算法返回的分组是合法的，且包含每个人恰好一次。

**证明**：由引理 3，每个输出的组都形如「$s$ 个标注值为 $s$ 的人」，长度为 $s$，由引理 1、2 可知它是合法组；由引理 4，所有桶最终为空、每人恰好被收割一次，故每个人出现且仅出现一次。∎

## 6. 复杂度分析

- **时间**：$O(n)$。扫描 $n$ 个人，每人一次追加与一次长度比较，均为 $O(1)$；每次收割把 $s$ 个元素拷进答案，所有收割的拷贝量之和恰为 $\sum_s |V_s| = n$。故总时间为 $O(n)$。
- **空间**：$O(n)$。所有桶中同时存在的下标不超过 $n$ 个；用数组桶时还有 $n + 1$ 个空 `vector` 的固定开销 $O(n)$。返回答案本身占 $O(n)$，属于输出规模，不可避免。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<vector<int>> groupThePeople(vector<int>& groupSizes) {
        unordered_map<int, vector<int>> buckets;   // s -> 尚未凑够一组的人
        vector<vector<int>> result;
        for (int i = 0; i < (int)groupSizes.size(); i++) {
            int s = groupSizes[i];
            vector<int>& bucket = buckets[s];
            bucket.push_back(i);                   // 先入桶
            if ((int)bucket.size() == s) {         // 刚好满员，立刻收割
                result.push_back(bucket);
                bucket.clear();                    // 清空，同值的人另起一组
            }
        }
        return result;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def groupThePeople(self, groupSizes: List[int]) -> List[List[int]]:
        buckets = {}      # s -> 尚未凑够一组的人
        result = []
        for i, s in enumerate(groupSizes):
            bucket = buckets.setdefault(s, [])
            bucket.append(i)          # 先入桶
            if len(bucket) == s:      # 刚好满员，立刻收割
                result.append(bucket)
                buckets[s] = []       # 断开引用：新桶不能影响已输出的组
        return result
```

## 8. 边界情况与易错点

1. **Python 的 list 别名**：`result.append(bucket)` 之后若只写 `bucket = []`，`buckets[s]` 仍指向旧 list，下一次 `setdefault` 取回旧对象继续追加，已输出的组会被就地改写。必须写 `buckets[s] = []`（或 `bucket.clear()`）。
2. **$s = 1$ 的情形**：每人单独成组，「入桶即收割」。把满员判断写在 push 之前、或写成 `len(bucket) > 1`，都会漏组。
3. **数组桶的大小**：`groupSizes[i]` 最大可以等于 $n$，所以桶数组必须开 $n + 1$ 格；开 $n$ 格（下标 $0 \sim n-1$）会在 $s = n$ 时越界。
4. **C++ 的引用失效**：`vector<int>& bucket = buckets[s];` 之后若对 `buckets` 做 `erase` 会触发 rehash 使引用悬空。本解法只用 `push_back` / `clear`，安全；改写成 `move` + `erase` 时必须重新取引用。
5. **组内不能有重复下标**：按下标扫描天然保证每组内无重复且升序；若改用「先排序再切片」的写法，必须保存 `(值, 原下标)` 对，否则切片得到的是排序后的位置而不是人的编号。
6. **不要输出空组**：清空桶时不要顺手把空桶推入答案；由于 $s \ge 1$，空桶永远不会满足 `size() == s`，只要不额外 push 就不会出现空组。
7. **多解不必对齐官方顺序**：示例输出 `[[5],[0,1,2],[3,4,6]]` 只是官方答案之一，本题用 special judge 校验合法性；本地校验应检查「组数 + 每人覆盖一次 + 每组长度等于成员标注值」三项，而不是与官方输出做字符串比对。
