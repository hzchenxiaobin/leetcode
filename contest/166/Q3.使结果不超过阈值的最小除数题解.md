# LeetCode 使结果不超过阈值的最小除数 题解

## 1. 题目概述

- **标题 / 题号**：使结果不超过阈值的最小除数（#1283，medium）
- **链接**：https://leetcode.cn/problems/find-the-smallest-divisor-given-a-threshold/
- **来源**：LeetCode 第 166 场周赛 Q3
- **难度**：中等
- **标签**：数组、二分查找

**题意**：给定正整数数组 `nums` 和正整数 `threshold`，选一个正整数 $d$ 作除数，把每个元素都除以 $d$ 并**向上取整**，记

$$S(d)=\sum_{i=0}^{n-1}\left\lceil \frac{\text{nums}[i]}{d} \right\rceil$$

要求找出使 $S(d)\le \text{threshold}$ 的**最小** $d$。题目保证一定有解。

**约束**：

- $1 \le \text{nums.length} \le 5\times 10^4$
- $1 \le \text{nums}[i] \le 10^6$
- $\text{nums.length} \le \text{threshold} \le 10^6$
- $S(d)$ 最坏为 $5\times10^4 \times 10^6 = 5\times10^{10}$，**超出 32 位整数**，累加器必须用 64 位
- 只需在 $d \in [1, \max(\text{nums})]$ 内考虑：$d=\max(\text{nums})$ 时每项向上取整都是 $1$，所以 $S(d)=n\le \text{threshold}$，一定有解

> 💡 一句话本质：把「枚举除数」换成「**在单调不增的判定函数上二分**」。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,5,9], threshold = 6
输出：5
解释：d = 1 时和为 17（1+2+5+9）
      d = 4 时和为 7（1+1+2+3）
      d = 5 时和为 5（1+1+1+2）→ 第一个不超过 6 的除数
```

**示例 2**

```text
输入：nums = [2,3,5,7,11], threshold = 11
输出：3
解释：d = 2 时和为 1+2+3+4+6 = 16 > 11
      d = 3 时和为 1+1+2+3+4 = 11 ≤ 11
```

**示例 3**

```text
输入：nums = [19], threshold = 5
输出：4
解释：d = 3 时 ceil(19/3) = 7 > 5；d = 4 时 ceil(19/4) = 5 ≤ 5
```

**示例 4（官方评测样例，答案恰好等于最大值）**

```text
输入：nums = [44,22,33,11,1], threshold = 5
输出：44
解释：d = 43 时和为 2+1+1+1+1 = 6 > 5；只有 d = 44 才能让每项都变成 1
```

示例 4 提醒我们：**答案可以等于 $\max(\text{nums})$**，二分上界不能取 $\max(\text{nums})-1$。

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是把 $d$ 从 $1$ 开始逐个试：对每个 $d$ 扫一遍数组求 $S(d)$，第一个满足 $S(d)\le \text{threshold}$ 的 $d$ 就是答案。

- 单次判定 $O(n)$，枚举范围最坏 $10^6$，总时间 $O(n\cdot\max(\text{nums})) = 5\times10^{10}$，必然超时。
- 题面提示印证了这条路：先「枚举所有可能的除数」，再用「二分查找降低复杂度」。

所以问题变成：能否不真的枚举？答案是能——只要判定函数对 $d$ 具有单调性，就可以把「逐个试」换成**二分**。

### 3.2 核心观察：判定函数单调不增，可行解构成后缀

![除数越大总和越小，答案是最左可行点](images/wc166_q3_monotone_bound.svg)

固定一个元素 $x$。$d$ 变大时，$\lceil x/d\rceil$ 只会变小或不变：它衡量的是「**至少需要几个 $d$ 才能盖住 $x$**」，除数越大，需要的份数越少。把 $n$ 个这样的项加起来，$S(d)$ 就是一条**阶梯状的单调不增曲线**。

于是：

- 若 $d$ 可行（$S(d)\le\text{threshold}$），则所有 $d'\ge d$ 都可行；
- 若 $d$ 不可行，则所有 $d'\le d$ 都不可行。

**可行解在数轴上构成一个后缀 $[\text{ans}, +\infty)$**，我们要找的就是这个后缀的**左端点**。这正是「二分找下界（lower bound）」的标准形态：判定一次 $O(n)$，二分只需 $O(\log \max(\text{nums}))$ 次。

### 3.3 算法流程

![二分答案流程](images/wc166_q3_binary_search_flow.svg)

1. 令 $lo=1$，$hi=\max(\text{nums})$。由约束可知 $hi$ 一定可行。
2. 当 $lo<hi$ 时取 $mid=\lfloor (lo+hi)/2\rfloor$，扫一遍数组算 $S(mid)$。
3. 若 $S(mid)\le\text{threshold}$，说明答案不大于 $mid$（$mid$ 可行，且左边可能有更小的可行值），令 $hi=mid$。
4. 否则 $mid$ 不可行，答案严格大于 $mid$，令 $lo=mid+1$。
5. 循环结束时 $lo=hi$，返回 $lo$。

实现上的小优化：一旦累加过程中 $S$ 已经超过 `threshold`，就立刻跳出循环，不必把数组扫完——这个**早停**在 $mid$ 偏小时能省掉大量无效加法。

### 3.4 示例演算

以 `nums = [1,2,5,9]`、`threshold = 6` 为例，先列出各 $d$ 的总和：

$$S(1)=17,\ S(2)=10,\ S(3)=7,\ S(4)=7,\ S(5)=5,\ S(6..8)=5,\ S(9)=4$$

![演算走查与二分三轮收缩](images/wc166_q3_walkthrough.svg)

二分的三轮收缩：

- 第 1 轮：$lo=1,hi=9,mid=5$，$S(5)=5\le 6$，令 $hi=5$；
- 第 2 轮：$lo=1,hi=5,mid=3$，$S(3)=7>6$，令 $lo=4$；
- 第 3 轮：$lo=4,hi=5,mid=4$，$S(4)=7>6$，令 $lo=5$；
- $lo=hi=5$，返回 $5$。

注意 $S(3)=S(4)=7$ 这样的「平段」并不影响二分：我们要的是**满足条件的最左位置**，平段只会让 $hi$ 不断向左收，不会让答案越过它。

## 4. 算法细节

1. **上界取 $\max(\text{nums})$**：$d=\max(\text{nums})$ 时每个元素都变成 $1$，$S(d)=n\le\text{threshold}$，可行。比用 $10^6$ 或 $\sum\text{nums}[i]$ 更紧，直接把二分区间压到 $20$ 轮以内。
2. **向上取整的安全写法**：$\lceil x/d\rceil=\lfloor (x-1)/d\rfloor+1$（$x\ge 1$），C++ 与 Python 的整数除法都是向下取整，直接可用；也可写 $(x+d-1)/d$，但当 $x,d$ 接近 $10^9$ 量级时 $x+d-1$ 可能溢出 `int`，前者更保险。
3. **累加器用 64 位**：$S(d)$ 最大约 $5\times10^{10}$，C++ 必须 `long long`；Python 无需担心。
4. **早停**：`if (s > threshold) break;`，一旦超标立即判定「不可行」。早停不影响正确性，因为 $S$ 只会继续变大。
5. **二分不变量**：始终保证「$lo$ 左侧全部不可行，$hi$ 可行」。初始 $lo=1$、$hi=\max$ 满足；每轮按判定结果收缩，不变量保持。
6. **`mid` 的取整方向**：必须用 $\lfloor (lo+hi)/2\rfloor$（C++ `lo + (hi - lo) / 2`，避免加法溢出），配合 `hi = mid` 才能收敛；若用 `hi = mid - 1` 会在 $mid$ 恰好可行时跳过答案。
7. **接口与返回值**：函数名 `smallestDivisor`，参数顺序 `(nums, threshold)`，返回 `int`，与 `metaData` 一致。

## 5. 正确性证明

**引理 1（单调性）**：对任意固定正整数 $x$，函数 $f(d)=\lceil x/d\rceil$ 在正整数上单调不增。

**证明**：设 $d_1\le d_2$，令 $q=\lceil x/d_2\rceil$。由向上取整的定义有 $x>(q-1)d_2$（当 $q\ge 1$）。因为 $d_2\ge d_1$ 且 $q-1\ge 0$，所以 $(q-1)d_2\ge (q-1)d_1$，从而 $x>(q-1)d_1$，即 $\lceil x/d_1\rceil\ge q=\lceil x/d_2\rceil$。逐项求和即得 $S(d_1)\ge S(d_2)$，即可行集合是后缀。∎

**引理 2（判定准确）**：算法中计算的 $S(mid)=\sum_i \lfloor(\text{nums}[i]-1)/mid\rfloor+1$ 与定义 $\sum_i\lceil \text{nums}[i]/mid\rceil$ 相等。

**证明**：对正整数 $x,d$，设 $x=kd+r$，$0\le r<d$。若 $r=0$，则 $\lceil x/d\rceil=k$，而 $\lfloor (x-1)/d\rfloor+1=\lfloor k-1+(d-1)/d\rfloor+1=(k-1)+1=k$；若 $r>0$，则 $\lceil x/d\rceil=k+1$，而 $\lfloor (x-1)/d\rfloor+1=k+1$。两种情况都相等，逐项求和即得。∎

**引理 3（二分不变量）**：算法的每一轮开始与结束时都满足 $\text{ans}\in[lo,hi]$，其中 $\text{ans}$ 是最小可行除数。

**证明**：初始 $lo=1\le\text{ans}$，$hi=\max(\text{nums})\ge\text{ans}$（引理 1 与 $hi$ 可行）。设某轮开始时 $\text{ans}\in[lo,hi]$，取 $mid$。若 $S(mid)\le\text{threshold}$，则 $mid\ge\text{ans}$，令 $hi=mid$ 后仍有 $\text{ans}\in[lo,mid]$；若 $S(mid)>\text{threshold}$，则 $mid<\text{ans}$（$mid$ 不可行），令 $lo=mid+1$ 后 $\text{ans}\in[mid+1,hi]$。两种情形不变量保持。∎

**定理**：算法返回最小可行除数。

**证明**：循环条件 $lo<hi$ 且每轮区间严格缩短（$hi=mid<hi$ 或 $lo=mid+1>lo$），故循环必然终止于 $lo=hi$。由引理 3，$\text{ans}=lo$，返回值正确。∎

## 6. 复杂度分析

- **时间**：单次判定扫描数组为 $O(n)$（早停只会更快），二分轮数为 $O(\log \max(\text{nums}))\le 20$，总计 $O(n\log \max(\text{nums}))$。按上限计算约 $5\times10^4\times20=10^6$ 次运算，远低于时限。
- **空间**：只用了 $lo,hi,mid$ 和累加器几个变量，$O(1)$ 额外空间（不计输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int smallestDivisor(vector<int>& nums, int threshold) {
        int lo = 1, hi = *max_element(nums.begin(), nums.end());
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;   // 向下取整，防溢出写法
            long long s = 0;                // 最大约 5e10，必须 64 位
            for (int x : nums) {
                s += (x - 1) / mid + 1;     // 等价于 ceil(x / mid)
                if (s > threshold) break;   // 早停：已经不可行
            }
            if (s <= threshold) hi = mid;   // mid 可行，答案在 [lo, mid]
            else lo = mid + 1;              // mid 不可行，答案在 [mid+1, hi]
        }
        return lo;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        def need(d: int) -> int:
            s = 0
            for x in nums:
                s += (x - 1) // d + 1   # 等价于 ceil(x / d)
                if s > threshold:       # 早停
                    return s
            return s

        lo, hi = 1, max(nums)
        while lo < hi:
            mid = (lo + hi) // 2
            if need(mid) <= threshold:
                hi = mid
            else:
                lo = mid + 1
        return lo
```

## 8. 边界情况与易错点

1. **`threshold == n` 时答案必为 $\max(\text{nums})$**：每一项都必须取整成 $1$，所以 $d\ge\max$，而 $d=\max$ 恰好可行。示例 4 就是这种情形。若把上界写成 $\max-1$，会在这一组直接出错。
2. **单元素数组**：答案应为 $\lceil \text{nums}[0]/\text{threshold}\rceil$，例如 `[19], 5 → 4`。可以拿它当二分实现的最小回归测试。
3. **`hi = mid - 1` 是致命错误**：当 $mid$ 可行时，答案可能就是 $mid$，减一就把它排除了。可行一侧必须写 `hi = mid`，不可行一侧才写 `lo = mid + 1`。
4. **累加溢出**：$S(d)$ 的量级是 $5\times10^{10}$，C++ 用 `int` 累加会变成负数，导致「明明不可行却被判成可行」。累加器一律 `long long`。
5. **二分区间长度**：初始 $hi=\max(\text{nums})$ 时，若数组只有一个元素且 `threshold == 1`，循环一次都不执行，直接返回该元素——这条路径也要能正确返回，不能依赖循环体里的赋值。
6. **早停不能把 `s` 当成最终值去和 `threshold` 比较之外再使用**：早停后 `s > threshold`，判定为不可行即可；不要拿它做别的累计。
7. **浮点取整不可取**：`ceil(x / (double)d)` 在大数上可能因精度出现 `x/d` 恰好为整数却进位的情况，整数除法更稳。

**延伸思考**：

1. 如果要求「**最大**可行除数」（在 $S(d)\ge\text{threshold}$ 中找最大），单调性不变，只需把判定方向与收缩方向镜像过来。
2. 如果数组会被**单点修改**并多次询问最小除数，逐次二分就退化成 $O(n\log M)$ 每次。可以按值域开频次数组，利用 $\sum_i \lceil \text{nums}[i]/d\rceil$ 在调和级数上的分解 $\sum_{q} q\cdot(\text{count of } x \in ((q-1)d, qd])$，用前缀和做到单次判定 $O(M/d)$、总复杂度接近 $O(M\log M)$，修改时只需更新频次前缀。
3. 若 `threshold` 很大（比如 $10^{18}$），$S$ 的溢出风险更大，此时应改用 $128$ 位整数或提前用 $n$ 与 `threshold` 的关系做剪枝。
