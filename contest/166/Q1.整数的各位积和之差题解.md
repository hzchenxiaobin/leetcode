# LeetCode 整数的各位积和之差 题解

## 1. 题目概述

- **标题 / 题号**：整数的各位积和之差（#1281，easy）
- **链接**：https://leetcode.cn/problems/subtract-the-product-and-sum-of-digits-of-an-integer/
- **来源**：LeetCode 第 166 场周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：给定一个正整数 $n$，把它的十进制表示拆成各位数字，求「各位数字之积 $P$」减去「各位数字之和 $S$」，即返回 $P - S$。

**约束**：

- $1 \le n \le 10^5$
- $n$ 是常规十进制写法，没有前导零
- 位数最多 6 位，故 $P \le 9^5 = 59049$、$S \le 45$，$|P-S| < 6\times10^4$，`int` 足够
- 题目把 $P$ 与 $S$ 分开定义：不是「边乘边减」，而是两个聚合量各自算完之后再相减

> 💡 一句话本质：**一次十进制拆位，两个累加器同步推进**，乘积初值取 $1$、和初值取 $0$。

## 2. 示例

**示例 1**

```text
输入：n = 234
输出：15
解释：各位数之积 = 2 * 3 * 4 = 24
      各位数之和 = 2 + 3 + 4 = 9
      结果 = 24 - 9 = 15
```

**示例 2**

```text
输入：n = 4421
输出：21
解释：各位数之积 = 4 * 4 * 2 * 1 = 32
      各位数之和 = 4 + 4 + 2 + 1 = 11
      结果 = 32 - 11 = 21
```

**示例 3（补充，含 0 的情形）**

```text
输入：n = 100000
输出：-1
解释：各位数之积 = 1 * 0 * 0 * 0 * 0 * 0 = 0
      各位数之和 = 1 + 0 + 0 + 0 + 0 + 0 = 1
      结果 = 0 - 1 = -1
```

**示例 4（补充，只有一位数字）**

```text
输入：n = 9
输出：0
解释：各位数之积 = 9，各位数之和 = 9，结果 = 9 - 9 = 0
```

注意示例 3：**只要数字里出现一个 $0$，乘积立刻归零**，答案会变成负数。这不是溢出，而是题意本身允许的结果。

## 3. 解题思路

### 3.1 暴力思路

最直觉的写法有三类，正确性都没问题，差别在常数与易错点：

1. **转字符串两遍遍历**：`s = str(n)`，先 `reduce(mul, map(int, s))` 再 `sum(map(int, s))`。时间 $O(\log n)$，但额外开了 $O(\log n)$ 的字符串。
2. **`log10` 定位数再逐位取**：位数 $k = \lfloor \log_{10} n \rfloor + 1$，第 $i$ 位用 $\lfloor n / 10^i \rfloor \bmod 10$ 取。时间 $O(\log^2 n)$，但位数依赖浮点结果：在 $10^k$ 这类边界值上，若 `log10` 返回 $k-\varepsilon$（不同 libm 行为不同），截断后就会少算一位。
3. **递归拆位**：`f(n) = f(n // 10) 合并 (n % 10)`，本质和循环一样，但多一层调用开销。

三种写法在 $n \le 10^5$（最多 6 轮）下都能过，真正的收益不在于复杂度，而在于**把「求积」「求和」两次遍历合并成一次**，并且完全避开字符串与浮点。

另外要警惕一种「看起来能跳过拆位」的误解：由于乘法和加法都可交换，$P$ 与 $S$ 确实**只由数字的多重集合决定**（`234`、`243`、`324` 都得到 $15$），但**不是只由位数或数字之和决定**。例如位数相同、数字和也相同的 `234`（$15$）与 `135`（$1\cdot3\cdot5-9=6$）结果不同，所以仍然必须逐个数字读出来。

### 3.2 核心观察：取模 10 抽最低位，整除 10 丢最低位

![拆位与两个累加器](images/wc166_q1_digit_split.svg)

十进制数 $n$ 的最低位就是 $n \bmod 10$，而 $\lfloor n/10 \rfloor$ 恰好是「把最低位砍掉」后的前缀。于是

$$n = 10 \cdot \left\lfloor \frac{n}{10} \right\rfloor + (n \bmod 10)$$

每执行一次 `n % 10` + `n / 10`，就**恰好取出一位、且只取一次**；一直重复到 $n = 0$，所有位都被取下。取位的过程与「求积、求和」互不干扰，所以可以在**同一个循环体内**同时更新两个累加器：

- $P \gets P \times d$，初值必须为 $1$（乘法的单位元）；
- $S \gets S + d$，初值必须为 $0$（加法的单位元）。

初值选错是最经典的错误：若把 $P$ 初始化成 $0$，全部乘积都会是 $0$。

### 3.3 算法流程 / 状态转移

![算法流程](images/wc166_q1_algorithm_flow.svg)

```text
P ← 1，S ← 0
while n > 0:
    d ← n mod 10        # 取出当前最低位
    P ← P × d           # 累乘
    S ← S + d           # 累加
    n ← n / 10          # 丢掉最低位
return P - S
```

循环不变量（下一节会证明）：**每轮结束后，$P$ 等于「已经取出的那些位」之积，$S$ 等于它们之和，而 $n$ 是尚未处理的更高位前缀。** 循环在 $n = 0$ 时终止，此时已处理的位恰好是 $n$ 的全部数位。

$n$ 最多 6 位，循环最多执行 6 轮，无需任何额外数据结构。

### 3.4 示例演算

![逐轮走查](images/wc166_q1_walkthrough.svg)

以 $n = 234$ 为例，三位数字从低到高依次是 $4, 3, 2$：

| 轮次 | 当前 $n$ | $d = n \bmod 10$ | $P$ | $S$ | 剩余 $n$ |
|------|----------|------------------|-----|-----|----------|
| 初始 | 234 | — | 1 | 0 | 234 |
| 1 | 234 | 4 | $1\times4 = 4$ | $0+4 = 4$ | 23 |
| 2 | 23 | 3 | $4\times3 = 12$ | $4+3 = 7$ | 2 |
| 3 | 2 | 2 | $12\times2 = 24$ | $7+2 = 9$ | 0 |

循环结束，返回 $24 - 9 = 15$，与官方答案一致。

再看 $n = 4421$：取位顺序是 $1, 2, 4, 4$，$P$ 依次为 $1, 2, 8, 32$，$S$ 依次为 $1, 3, 7, 11$，答案 $32 - 11 = 21$。

最后看含 $0$ 的 $n = 100000$：取位顺序 $0, 0, 0, 0, 0, 1$，第一轮就把 $P$ 打成 $0$，$S$ 最终为 $1$，答案 $-1$。**不要在 $d = 0$ 时提前退出循环**，否则会漏掉后面参与求和的非零位。

## 4. 算法细节

1. **两个初值**：`P = 1`、`S = 0`。这是整份代码里唯一容易写反的地方；也可以写成 `P = S = 0` 再加判断，但没必要。
2. **取位顺序无关**：先 `n % 10` 再 `n /= 10`，或者用 `divmod(n, 10)` 一次拿到 `(商, 余数)`，两种都行；只要保证**同一个 $d$ 既进了乘积也进了和**，不要一处用旧值、一处用新值。
3. **循环条件用 `n > 0`**：由于 $n \ge 1$，循环至少执行一次；$n$ 为 $1$ 位数时执行一次后归零，结果 $d - d = 0$，正确。
4. **不要用 `log10` 推位数**：浮点误差在 $10^k$ 附近会把 $k$ 算少一位；若一定要按位取，用整数循环或字符串更稳。
5. **禁止提前 `break`**：`d == 0` 只是让 $P$ 归零，后续位仍要累加到 $S$，`n = 100000` 就是反例。
6. **整型选择**：$|P - S| < 6\times10^4$，`int` / `long long` 都不会溢出；若把上界放宽到 $n \le 10^{18}$（18 位全 9），$P = 9^{18} \approx 1.5\times10^{17}$ 仍在 64 位内，但会超出 32 位，那时必须用 `long long`。
7. **Python 的 `divmod` 更紧凑**：`n, d = divmod(n, 10)` 一行完成「取余 + 整除」，且天然非负（本题 $n \ge 1$，无需考虑负数取模方向）。
8. **负数不在约束内**：若把题目推广到 $n < 0$，应先取绝对值再拆位（C++ 的 `%` 对负数会给负余数，直接累乘会出错）。

## 5. 正确性证明

设输入的十进制数为 $n_0 \ge 1$，其数位从低到高记为 $d_0, d_1, \dots, d_{k-1}$（共 $k$ 位，$d_i \in [0,9]$，最高位 $d_{k-1} \ne 0$），即

$$n_0 = \sum_{i=0}^{k-1} d_i \cdot 10^i .$$

**引理 1（拆位引理）**：对任意整数 $m \ge 1$，$m \bmod 10$ 是 $m$ 的最低位数字，$\lfloor m/10 \rfloor$ 是去掉最低位后的数；且经过 $k$ 次迭代后 $\lfloor n_0 / 10^k \rfloor = 0$。

**证明**：由带余除法的唯一性，存在唯一的 $q \ge 0$ 与 $r \in [0,9]$ 使 $m = 10q + r$，其中 $q = \lfloor m/10 \rfloor$、$r = m \bmod 10$。把 $m$ 按上式展开可知 $r = d_0$、$q = \sum_{i \ge 1} d_i 10^{i-1}$，即 $q$ 正是去掉最低位后的数。反复应用得 $\lfloor n_0/10^j \rfloor = \sum_{i \ge j} d_i 10^{i-j}$；取 $j = k$ 时右端为空和 $0$，故迭代 $k$ 次后归零。∎

**引理 2（循环不变量）**：对每次循环开始（记已完成 $j$ 轮，$0 \le j \le k$），有

$$P = \prod_{i=0}^{j-1} d_i, \qquad S = \sum_{i=0}^{j-1} d_i, \qquad n = \left\lfloor \frac{n_0}{10^{j}} \right\rfloor .$$

（$j = 0$ 时约定空积为 $1$、空和为 $0$。）

**证明**：对 $j$ 归纳。$j = 0$：由初始化 $P = 1$、$S = 0$、$n = n_0$，成立。设 $j$ 轮成立，第 $j+1$ 轮由引理 1 取出 $d = n \bmod 10 = d_j$，随后 $P$ 乘上 $d_j$、$S$ 加上 $d_j$、$n$ 变为 $\lfloor n/10 \rfloor = \lfloor n_0/10^{j+1} \rfloor$，三项同时保持命题形式。∎

**定理**：算法返回的值等于 $P(n_0) - S(n_0)$，其中 $P(n_0) = \prod_{i=0}^{k-1} d_i$、$S(n_0) = \sum_{i=0}^{k-1} d_i$。

**证明**：由引理 1，循环在恰好 $k$ 轮后因 $n = 0$ 终止，故取出的数位序列是 $d_0, d_1, \dots, d_{k-1}$，既不重复也不遗漏（每轮只取当前最低位，且该位随后被整除丢掉，不可能再被取到）。把 $j = k$ 代入引理 2，得 $P = \prod_{i<k} d_i = P(n_0)$、$S = \sum_{i<k} d_i = S(n_0)$，返回的正是二者之差。∎

## 6. 复杂度分析

- **时间**：$O(\log_{10} n)$，即十进制位数 $k$。每轮做一次取模、一次整除、一次乘法、一次加法，均为 $O(1)$。$n \le 10^5$ 时 $k \le 6$，常数级。
- **空间**：$O(1)$。只用了 `P`、`S`、`d`、`n` 四个整型变量（`n` 被就地覆盖），没有数组、字符串或递归栈。
- **对比字符串解法**：时间同为 $O(k)$，但要多花 $O(k)$ 空间存字符串，且 `int` 与字符互转有额外常数；本题 $k \le 6$，差异可以忽略，但在「拆位 + 聚合」这一类题里，取模写法是更通用的模板。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int subtractProductAndSum(int n) {
        int prod = 1;   // 乘法单位元，不能初始化成 0
        int sum = 0;    // 加法单位元
        while (n > 0) {
            int d = n % 10;   // 取出最低位
            prod *= d;
            sum += d;
            n /= 10;          // 丢掉最低位
        }
        return prod - sum;
    }
};
```

### Python

```python
class Solution:
    def subtractProductAndSum(self, n: int) -> int:
        prod, total = 1, 0
        while n:
            n, d = divmod(n, 10)   # n 拿到商，d 拿到最低位
            prod *= d
            total += d
        return prod - total
```

## 8. 边界情况与易错点

1. **乘积初值写成 0**：`prod = 0` 会让所有答案变成 `-sum`，示例 1 会输出 `-9` 而不是 `15`。这是本题最高频的 WA。
2. **数字中出现 0**：如 `100000`，`prod` 归零后**不能跳过余下位的累加**，答案应为 $-1$ 而不是 $0$；同理 `101` 的答案是 $0 - 2 = -2$。
3. **单一位数**：`n = 9` 时循环只跑一轮，`prod = 9`、`sum = 9`，返回 $0$。不要加「只有一位就返回 0」的特判去遮掩，逻辑本身就对。
4. **`n = 0`（本题约束外）**：若被允许，`while (n > 0)` 一轮都不进，会返回 $1 - 0 = 1$，与「$0$ 的各位积、和都是 $0$」矛盾；正确处理是先特判 `n == 0` 返回 $0$。
5. **先除后取模顺序反了**：写成 `n /= 10; d = n % 10;` 会**丢掉最低位**，示例 1 会依次取到 $3, 2, 0$，算出 $3\times2\times0 - (3+2+0) = -5$，而不是 $15$。
6. **用 `log10` 求位数**：`int k = log10(n) + 1` 把位数交给浮点决定；一旦某个平台在 $n = 10^5$ 上返回 $4.999999\ldots$，截断后 $k = 5$，就会少拆一位。用 `while (n > 0)` 循环彻底避开这个隐患。
7. **`d` 消耗一次却用了两次不同来源**：例如先 `sum += n % 10` 再 `prod *= (n / 10) % 10`，会让乘积与和对应的「数位集合」不一致，必须用同一个 `d`。
8. **Python 里用字符串再转回整型**：`int(ch)` 对大输入稍慢，且 `str(n)` 对负数会带上 `'-'`，`int('-')` 直接抛异常；用取模法可以完全绕开。

**延伸思考**：

1. **数位和模 9 恒等式**：$n \equiv S(n) \pmod 9$，所以「各位和」可以做 $O(1)$ 校验；但「各位积」没有类似的封闭性质，这也解释了为什么本题必须真的拆位。
2. **把 $n$ 拆成若干正整数使乘积最大**：与本题方向相反——不是给定 $n$ 求积，而是求「和为 $n$ 时积最大」，经典结论是尽量用 $3$、余 $1$ 时换成 $2+2$（LeetCode 343 整数拆分）。
3. **区间统计**：若要统计 $[1, N]$ 中满足 $P(n) - S(n) = k$ 的个数，拆位循环不够用，需要**数位 DP**，状态为（当前位、积、和、是否贴合上界）；积的状态空间也可用「已含 0 / 未含 0」压缩。
4. **大数情形**：$n$ 以字符串给出、共 $10^5$ 位时，仍是一遍扫描；只要中途读到 $0$，$P$ 就恒为 $0$，答案直接是 $-S$（$S$ 若需输出可对模数取余）。全程没有 $0$ 时才需要真正的大整数乘积。
