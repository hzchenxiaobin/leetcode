# LeetCode 数组嵌套 题解

## 1. 题目概述

- **标题 / 题号**：数组嵌套（#565，medium）
- **链接**：https://leetcode.cn/problems/array-nesting/
- **来源**：LeetCode 第 34 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索，数组

**题意**：`nums` 是 $0 \sim n-1$ 的一个排列。以任意下标 $k$ 为起点，反复执行「把当前下标处的值收进集合，然后跳到 `nums[当前下标]`」，直到要收的元素已经在集合里为止，得到集合 $s[k]$。求所有起点中 $\lvert s[k]\rvert$ 的最大值。

**约束**：

- $1 \le n \le 10^5$
- $0 \le nums[i] < n$
- `nums` 中**不含重复元素**，即 `nums` 是一个排列

> 💡 关键信息藏在第三条约束里：**没有重复元素**意味着「值 $\to$ 下标」是一一映射，每个下标恰好被一个值指向，也恰好指向一个值。于是整张指针图必然是一堆互不相交的环，题目问的就是「最长的那个环有多长」。

## 2. 示例

**示例 1**

```text
输入：nums = [5,4,0,3,1,6,2]
输出：4
解释：nums[0]=5, nums[1]=4, nums[2]=0, nums[3]=3, nums[4]=1, nums[5]=6, nums[6]=2。
      取 k = 0：s[0] = {nums[0], nums[5], nums[6], nums[2]} = {5, 6, 2, 0}，长度 4；
      再取 k = 1：s[1] = {nums[1], nums[4]} = {4, 1}，长度 2；k = 3 只有 {3}。
      最长为 4。
```

**示例 2**

```text
输入：nums = [0,1,2]
输出：1
解释：每个下标都指向自己：nums[0]=0, nums[1]=1, nums[2]=2。
      任何起点 s[k] 都只有一个元素，故答案为 1。
```

**示例 3（补充，非官方）**

```text
输入：nums = [4,3,2,1,0]
输出：2
解释：三个环 (0 4)、(1 3)、(2)，长度分别是 2、2、1，答案为 2。
      三个环把 5 个下标全部覆盖（2 + 2 + 1 = 5 = n）。这条恒等式值得记住：
      各环长度之和恰好等于 n，因为每个下标只属于一个环。
```

## 3. 解题思路

### 3.1 暴力思路

按题面直译：对每个起点 $k$，开一个 `set` 模拟收元素的过程，$x = nums[k]$，只要 $x$ 不在集合里就加入并令 $x = nums[x]$，最后取集合大小。每个起点最多走 $n$ 步，总时间 $O(n^2)$，在 $n = 10^5$ 时约 $10^{10}$ 步，必然超时；而且每个起点都要重建一次集合，额外空间 $O(n)$ 反复申请，常数也很差。

更糟的是，暴力完全浪费了「`nums` 是排列」这个条件：不同的 $k$ 落在同一个环上时，$s[k]$ 其实是**同一个集合**，算一遍就够了。问题于是变成：怎么在 $O(1)$ 均摊代价内判断「这个下标属于哪个环、那个环有多长」。

### 3.2 核心观察：置换分解成互不相交的环

![核心观察：nums 是置换，沿 i → nums[i] 跳必然成环](images/wc34_q3_permutation_cycles.svg)

把每个下标看成一个点，从 $i$ 向 `nums[i]` 连一条有向边。因为 `nums` 是排列，每个点**出度为 1、入度也为 1**——这样的图只有一种形态：若干个互不相交的环，没有树、没有入度为 0 的起点、也没有尾巴。

于是从任意 $k$ 出发顺着指针走，轨迹必然是一条「先绕一圈再回到原地」的环：

$$k \to f(k) \to f^{2}(k) \to \cdots \to f^{L}(k) = k,\qquad f(i) = nums[i]$$

其中 $L$ 就是 $k$ 所在环的长度。而 $s[k]$ 收到的东西正是 $f(k), f^2(k), \dots, f^{L}(k) = k$，这 $L$ 个值互不相同（$L$ 取最小正周期），合起来恰好是**整个环的元素集合**。所以

$$\lvert s[k]\rvert = L(k)$$

即集合大小就等于 $k$ 所在环的长度。

答案就是所有环长的最大值。图 3.2 里的例子 $n = 7$ 被切成 $4 + 2 + 1$ 三个环，其中环 ① 最长，答案 4。

这一步把「集合去重」问题彻底消掉了：**不需要 `set`，只要数跳了几步**。剩下的唯一难点是不要重复统计同一个环。

### 3.3 算法流程：原地标记，每环只走一次

![算法流程：原地标记 + 顺着指针走一整环](images/wc34_q3_inplace_flow.svg)

既然每个下标只属于一个环，就可以在访问时把它**就地标记为已访问**，之后任何落到它上面的起跳都直接跳过。因为 `nums[i]` 的取值范围是 $[0, n-1]$，用 $-1$ 当哨兵不会和合法值冲突，连 `visited` 数组都省了：

1. 令 `best = 0`。
2. 依次枚举起点 `i = 0 … n-1`；若 `nums[i] == -1`，说明这个环已经数过，`continue`。
3. 置 `cnt = 0, j = i`，进入内层循环：只要 `nums[j] != -1`，就先用 `nxt = nums[j]` 记下后继，再把 `nums[j]` 改成 `-1`，令 `j = nxt`，`cnt += 1`。
4. 内层循环退出时说明刚绕完一整圈，用 `best = max(best, cnt)` 更新答案。
5. 枚举结束后返回 `best`。

三个动作的顺序（先存后继 → 再覆盖 → 最后前进）不是风格问题而是**正确性前提**：一旦先把 `nums[j]` 写成 $-1$，`j = nums[j]` 读到的就是 $-1$，既丢掉了后继又会越界。

### 3.4 示例演算

![示例演算：三个环被依次走一遍，cnt 只在环的起点累加](images/wc34_q3_example_walkthrough.svg)

以示例 1 的 `nums = [5,4,0,3,1,6,2]` 走一遍：

| 起点 `i` | 行走轨迹 | 本轮新标记 | `cnt` | `best` |
|---------|----------|-----------|-------|--------|
| 0 | 0 → 5 → 6 → 2 →（回到 0） | {0, 5, 6, 2} | 4 | 4 |
| 1 | 1 → 4 →（回到 1） | {1, 4} | 2 | 4 |
| 2 | `nums[2] = -1`，跳过 | — | — | 4 |
| 3 | 3 →（自环 `nums[3] = 3`） | {3} | 1 | 4 |
| 4, 5, 6 | 都在环 ①② 里，跳过 | — | — | 4 |

两个细节值得留意：

- 起点 0 那一行走完后，环 ① 里的 5、6、2 都变成了 $-1$，所以 `i = 2` 进来时立刻被跳过，`cnt` 不会再累加一次——这正是「每环只统计一次」的体现。
- 起点 3 是自环，`nums[3] = 3`，内层循环只执行一次：标记 3、令 `j = 3`、`cnt = 1`，然后 `nums[3] == -1` 使循环退出，得到长度 1 而不是 0。

三个环长 $4 + 2 + 1 = 7 = n$，全部下标恰好被标记一次，答案 4，与官方输出一致。

## 4. 算法细节

1. **哨兵用 $-1$ 是安全的**：题面保证 $0 \le nums[i] < n$，而 $-1$ 不在值域内，因此「格内是 $-1$」等价于「已访问」，不会和任何真实值混淆。若值域允许负数（例如变体题），就必须改用 `+n` 之类的偏移哨兵或独立 `visited` 数组。
2. **原地标记的副作用要心里有数**：提交时 `nums` 会被改坏。LeetCode 判题不检查入参，所以没问题；但在面试或工程里若要求「不修改输入」，就退化成 $O(n)$ 空间的 `vector<char> visited` 版本，逻辑完全一样，只是把 `nums[j] = -1` 换成 `visited[j] = true`。
3. **入环后必然闭合**：内层 `while` 不需要额外判断「是不是回到了起点」，因为排列保证从任何点出发最终都会回到起点，而起点在第一步就被标记了。循环退出条件 `nums[j] == -1` 同时覆盖了「回到起点」和「撞上其它已走过的环」两种情况。
4. **每个下标只被写一次 $-1$**：外层 $n$ 次判断 + 内层总步数恰为 $n$（每次迭代标记一个此前未标记的下标），所以总操作数不超过 $2n$，是严格的线性而不是「均摊看起来线性」。
5. **`cnt` 的统计口径**：`cnt` 数的是「跳了几步」，也就是被标记的格子数；因为每步都标记一个新的下标，`cnt` 天然等于环长。不要写成「跳到 $-1$ 时的下标差值」之类，容易差一。
6. **不递归**：虽然标签是「深度优先搜索」，但本题的图是入出度均为 1 的环，用 `while` 顺着指针走即可；递归反而要 $O(n)$ 的调用栈，$n = 10^5$ 时在 Python 里还有递归深度风险。
7. **答案初值取 0 即可**：$n \ge 1$ 保证至少有一个环，`best` 一定会被更新；不需要特判空数组。

## 5. 正确性证明

设 $f(i) = nums[i]$，$f^{t}$ 表示把 $f$ 复合 $t$ 次。

**引理 1（轨道必成环）**：对任意起点 $k$，存在唯一的 $L \ge 1$，使得 $f^{0}(k), f^{1}(k), \dots, f^{L-1}(k)$ 两两不同且 $f^{L}(k) = k$。

**证明**：序列 $k, f(k), f^{2}(k), \dots$ 只有 $n$ 种取值，故在前 $n+1$ 项中必存在 $0 \le a < b \le n$ 使 $f^{a}(k) = f^{b}(k)$。由于 `nums` 是排列，$f$ 是双射因而可逆，两边同时作用 $f^{-a}$ 得 $k = f^{b-a}(k)$，即存在正周期 $L = b - a$。取所有正周期中的最小值 $L$：若存在 $0 \le p < q < L$ 使 $f^{p}(k) = f^{q}(k)$，同理得 $f^{q-p}(k) = k$，与 $L$ 的最小性矛盾，故前 $L$ 项两两不同。唯一性由最小正周期唯一保证。∎

**引理 2（集合大小 = 环长）**：记 $C(k) = \{f^{0}(k), \dots, f^{L-1}(k)\}$，则 $s[k] = C(k)$ 且 $\lvert s[k]\rvert = L$。

**证明**：按题面，$s[k]$ 从 $nums[k] = f(k)$ 开始，依次追加 $f^{2}(k), f^{3}(k), \dots$，直到某个元素重复为止。由引理 1，$f^{1}(k), \dots, f^{L-1}(k)$ 两两不同且都不同于 $f^{0}(k) = k$，而 $f^{L}(k) = k$ 恰好与最早出现的 $f^{0}(k)$ 重合，所以追加到 $f^{L}(k)$ 时刚好出现第一次重复并停止，$s[k] = \{f^{1}(k), \dots, f^{L}(k)\} = \{f^{0}(k), \dots, f^{L-1}(k)\} = C(k)$，大小为 $L$。∎

**引理 3（环是等价类）**：对任意 $i, j$，「$i$ 与 $j$ 在同一个环上」是一个等价关系；若 $i, j$ 同环则 $C(i) = C(j)$，否则 $C(i) \cap C(j) = \varnothing$。

**证明**：定义 $i \sim j \iff \exists t \ge 0,\ f^{t}(i) = j$。自反性取 $t = 0$；对称性由引理 1 的周期性（$j = f^{t}(i)$ 意味着 $i = f^{L(i)-t}(j)$）；传递性由复合封闭。因此 $\sim$ 是等价关系，等价类正是各条轨道 $C(\cdot)$，不同的类互不相交。∎

**引理 4（每条环恰好被完整处理一次）**：设某轮外层的起点为 $u$ 且进入时 $nums[u] \ne -1$。则本轮内层恰好执行 $L(u)$ 次，依次标记 $f^{1}(u), f^{2}(u), \dots, f^{L(u)}(u) = u$，即标记整个 $C(u)$，退出时 `cnt = L(u)`。

**证明**：考察环 $C$ 被第一次触碰的那一轮 $r$，即起点落在 $C$ 内的轮次中最早的一轮，起点记为 $u$。任何一轮只有从 $C$ 内的点出发才可能标记到 $C$ 内的点（$f$ 把每条环映到自身，见引理 3），所以 $r$ 之前 $C$ 内没有任何标记。在 $r$ 内对 $0 \le t < L$ 归纳：进入第 $t+1$ 次迭代时 $j = f^{t}(u)$ 必未标记——$C$ 上的标记只可能来自本轮，而本轮此前标记的恰是 $f^{0}(u), \dots, f^{t-1}(u)$，由引理 1 的「前 $L$ 项两两不同」它们与 $f^{t}(u)$ 都不相同。于是迭代继续，标记 $f^{t}(u)$ 并令 $j = f^{t+1}(u)$。因此前 $L$ 次迭代各标记一个不同的点，恰好把 $C$ 全部写成 $-1$；第 $L+1$ 次进入时 $j = f^{L}(u) = u$ 已被标记，循环退出，`cnt = L(u) = L`。此后任何起点落在 $C$ 内的轮次都会在开头的哨兵判断处被跳过，故 $C$ 不会被重复处理。∎

**定理**：算法返回 $\max_{k} \lvert s[k]\rvert$。

**证明**：由引理 4，外层每一轮要么跳过、要么完整走完一条尚未处理过的环并令 `cnt` 等于该环长度；由引理 3，各环互不相交且并集是全体下标，故所有环恰好各被处理一次，`best` 等于所有环长的最大值，也就是最长环长。再由引理 2，$\lvert s[k]\rvert$ 恰为 $k$ 所在环的长度，故 $\max_k \lvert s[k]\rvert$ 等于最长环长，算法返回值与题目所求一致。终止性：内层每次迭代都把一个新的下标写成 $-1$，至多 $n$ 次；外层固定 $n$ 轮，必然终止。∎

## 6. 复杂度分析

- **时间**：$O(n)$。外层 $n$ 次「取下标 + 判哨兵」，内层总迭代次数不超过 $n$（每次迭代标记一个此前未标记的下标，而合法下标只有 $n$ 个），每轮只做常数次比较与赋值。整体不超过 $2n$ 次基本操作，与环的条数、环长分布都无关。
- **空间**：$O(1)$（不含输入）。没有 `visited` 数组、没有 `set`、没有递归栈，只用了 `cnt / j / nxt / best` 四个整型变量。若改用 `visited` 数组则额外空间为 $O(n)$ 字节级，仍是线性但常数更大。
- 对比：暴力 $O(n^2)$ 时间 + 每起点 $O(n)$ 集合；记忆化 DFS 是 $O(n)$ 但需要 $O(n)$ 的 `visited` 与递归栈；本解法在时间同阶的前提下把空间压到了常量。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int arrayNesting(vector<int>& nums) {
        int n = (int)nums.size(), best = 0;
        for (int i = 0; i < n; ++i) {
            if (nums[i] == -1) continue;   // 这个环已经被数过
            int cnt = 0, j = i;
            while (nums[j] != -1) {        // 顺着指针绕完一整环
                int nxt = nums[j];         // ① 先存后继
                nums[j] = -1;              // ② 再原地标记
                j = nxt;                   // ③ 最后前进
                ++cnt;
            }
            best = max(best, cnt);         // cnt 就是本环长度
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def arrayNesting(self, nums: list[int]) -> int:
        n, best = len(nums), 0
        for i in range(n):
            if nums[i] == -1:              # 这个环已经被数过
                continue
            cnt, j = 0, i
            while nums[j] != -1:           # 顺着指针绕完一整环
                nxt = nums[j]              # ① 先存后继
                nums[j] = -1               # ② 再原地标记
                j = nxt                    # ③ 最后前进
                cnt += 1
            best = max(best, cnt)          # cnt 就是本环长度
        return best
```

## 8. 边界情况与易错点

1. **`n = 1`**：`nums = [0]`，自环长度 1。内层先标记 0、再令 `j = nums[0] = 0`、`cnt = 1`，第二次判断发现已标记而退出，返回 1。不要因为「只有一个元素」就特判返回 0。
2. **自环（`nums[i] = i`）**：示例 2 全是自环，答案是 1。注意此时「跳一步就遇到重复」，`cnt` 必须是 1 而不是 0——标记发生在自增之前/之后要数清。
3. **覆盖顺序错误**：先写 `nums[j] = -1` 再 `j = nums[j]`，读到的 $-1$ 会让 `nums[-1]` 越界（C++ 是 UB，Python 会取到末元素造成错答或死循环）。必须先用临时变量存 `nxt`。
4. **哨兵选错**：用 $0$ 或 `n` 当哨兵会污染合法值（$0 \le nums[i] < n$ 已经用满整个值域），必须选值域外的数，例如 $-1$。
5. **忘记「跳过已访问」**：漏写 `if (nums[i] == -1) continue;` 时，内层一进去就发现已标记，`cnt = 0`。若更新写成 `best = max(best, cnt)` 还算侥幸（0 被吸收），但只要写成 `best = cnt`，后面每一个被跳过的下标都会把答案清零；而且会平白多出 $n$ 次无效判断，逻辑上也不再是「每环一次」。
6. **误用 `set` 去重**：直接照题面用集合模拟，虽然结果正确但退化到 $O(n^2)$，$n = 10^5$ 必超时；本题的环结构就是为了让你把「去重」换成「标记」。
7. **修改输入的连带影响**：如果同一份 `nums` 在调用后还要使用（例如本地对拍时反复调用），记得先 `copy`。验证脚本里我就是对每个用例传副本，否则第二次调用会读到全 $-1$。
8. **递归写法爆栈**：把内层 `while` 改写成递归 DFS 时，环长可达 $10^5$，Python 默认递归上限 1000，会直接 `RecursionError`；本题没必要递归。

1. 若把「求最长环」改成「输出最长环的全部元素」，只需在标记时把下标压进一个临时数组，答案环长时整体拷贝，时间仍是 $O(n)$。
2. 若 `nums` 只是「每个值在 $[0,n-1]$ 内但允许重复」，图会退化成一堆「带尾巴的环」（rho 形），起点不同结果不同，最长集合就不再等于最长环，需要 $O(n)$ 记忆化 DFS 求「到环的距离 + 环长」。
3. 经典的「最少交换次数把数组排好序」等价于 $n$ 减去环的条数：把 $i \to nums[i]$ 分解成环后，长度 $L$ 的环用 $L-1$ 次交换即可归位。本题的分解框架可以原样复用，只是统计量从 $\max L$ 换成 $\sum (L-1)$。
