# LeetCode 区间加法 II 题解

## 1. 题目概述

- **标题 / 题号**：区间加法 II（#598，easy）
- **链接**：https://leetcode.cn/problems/range-addition-ii/
- **来源**：LeetCode 第 34 场周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定 $m \times n$ 的全零矩阵 $M$ 与操作数组 `ops`，每条操作 `ops[i] = [a_i, b_i]` 把**左上角**的 $a_i \times b_i$ 子矩阵（即所有 $0 \le x < a_i$、$0 \le y < b_i$ 的格子）整体加 1。执行完全部操作后，返回矩阵中**最大值的出现次数**（不是最大值本身）。

**约束**：

- $1 \le m, n \le 4 \times 10^4$
- $0 \le \lvert \text{ops} \rvert \le 10^4$
- `ops[i].length == 2`，$1 \le a_i \le m$，$1 \le b_i \le n$

> 💡 签到题的题眼：矩阵规模最大可达 $1.6 \times 10^9$ 个格子，**视野里必须先排除「真的把矩阵建出来」这条路**。一旦意识到「每格的值就是覆盖它的操作条数」，整题就退化成对两个最小值取乘积。

## 2. 示例

**示例 1**

```text
输入：m = 3, n = 3, ops = [[2,2],[3,3]]
输出：4
解释：第一条操作把左上 2×2 加 1，第二条把整个 3×3 加 1，矩阵变为
      [[2,2,1],
       [2,2,1],
       [1,1,0]]
      最大值是 2，共 4 个格子取到该值，故返回 4。
```

**示例 2**

```text
输入：m = 3, n = 3,
      ops = [[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3],[2,2],[3,3],[3,3],[3,3]]
输出：4
解释：12 条操作里只有两种「尺寸」，重复执行并不改变哪块区域被全部覆盖，
      最小值仍然是 a = 2、b = 2，答案依旧是 2 × 2 = 4。
```

**示例 3**

```text
输入：m = 3, n = 3, ops = []
输出：9
解释：一条操作都没有，矩阵保持全零，「最大值」0 出现在全部 9 个格子上。
      这是本题唯一的特判入口：答案退化为 m × n。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的模拟：开一个 $m \times n$ 的二维数组，对每条操作做一次 $a_i \times b_i$ 的两重循环累加，最后统计最大值出现次数。时间是 $O\bigl(\lvert \text{ops} \rvert \cdot m n\bigr)$，最坏 $10^4 \times 1.6 \times 10^9$；而**光是矩阵本身就装不下**：$1.6 \times 10^9$ 个 `int` 约 6.4 GB，还没开始计算就已经超内存。

第二条看似「正统」的路线是**二维差分**：每条操作只改 4 个端点，更新降为 $O(1)$。但要把差分数组还原成真实值，仍然必须做一遍 $m n$ 个格子的二维前缀和，时间与空间都是 $O(m n)$，在 $m = n = 4 \times 10^4$ 时同样不可行。

两条路都卡在同一个地方：**它们都假设「必须知道每一个格子的值」**。而题目只问「最大值出现了几次」，并不关心每个格子具体是几。所以要换的问题是：能不能不枚举格子，直接算出「哪些格子被所有操作覆盖」？

### 3.2 核心观察：最大值只出现在所有操作的交集里

![核心观察：每格的值等于覆盖它的操作条数](images/wc34_q1_min_intersection.svg)

把每条操作看成它覆盖的那块矩形 $R_i = [0, a_i) \times [0, b_i)$。由于所有矩形的**左上角都钉在 $(0,0)$**，它们构成一条按尺寸单调嵌套的链：$a_i$ 越大、$b_i$ 越大，矩形就越大，小矩形必定包含在大矩形里。

于是格子 $(x,y)$ 的最终值就是覆盖它的操作条数：

$$\text{val}(x,y) = \bigl\lvert\{\, i : x < a_i \ \text{且}\ y < b_i \,\}\bigr\rvert \le \lvert \text{ops} \rvert$$

要达到上界 $\lvert \text{ops} \rvert$，必须是**每一条**操作都覆盖它，即对每个 $i$ 都有 $x < a_i$ 且 $y < b_i$，等价于

$$x < A := \min_i a_i, \qquad y < B := \min_i b_i$$

所以「取到最大值的格子」恰好就是左上角那块 $A \times B$ 的矩形——**它本身也是一条合法操作覆盖的形状**，只不过尺寸由最小的那条操作决定。这样的格子有 $A \cdot B$ 个，答案就是

$$\text{ans} = \Bigl(\min_i a_i\Bigr) \cdot \Bigl(\min_i b_i\Bigr)$$

注意这个结论把「操作条数」「操作顺序」「其余所有 $a_i, b_i$ 的具体取值」全部消掉了：**只有最紧的那一条（或几条并列最紧的）操作起作用**。示例 2 里 12 条操作给出同样的答案，原因就在这里。

### 3.3 算法流程

![算法流程：一遍扫描只保留两个最小值](images/wc34_q1_algorithm_flow.svg)

1. 初始化 `ra = m`、`rb = n`。这两条初值正是「没有任何操作时」的交集尺寸：整张矩阵。
2. 顺序遍历 `ops`，对 `[a, b]` 执行 `ra = min(ra, a)`、`rb = min(rb, b)`。
3. 遍历结束后返回 `ra * rb`。

`ops` 为空时循环体一次都不执行，直接返回 $m \cdot n$，示例 3 自动被覆盖，**不需要任何额外分支**——这是把初值设成 $m, n$ 而不是 $+\infty$ 的好处。

### 3.4 示例演算

![示例演算：两条操作如何把候选面积压缩到 2×2](images/wc34_q1_walkthrough.svg)

以示例 1（$m = n = 3$，`ops = [[2,2],[3,3]]`）走一遍：

| 步骤 | 当前 op | `ra` | `rb` | `ra × rb` |
|------|---------|------|------|-----------|
| 初始 | — | 3 | 3 | 9 |
| 第 1 条 | `[2,2]` | 2 | 2 | 4 |
| 第 2 条 | `[3,3]` | 2 | 2 | 4 |
| 结束 | — | **2** | **2** | **4** |

第 2 条操作的两个分量都不小于当前的最小值，两个 `min` 都没被改动，所以最终答案与「只执行第 1 条操作」完全相同。对应的矩阵值也与 3.2 的公式吻合：

```text
[[2,2,1],
 [2,2,1],     左上 2×2 全部等于 2（= ops 条数），其余格子至多 1
 [1,1,0]]     右下角那个格子一条操作都没覆盖，值为 0
```

再看示例 3：`ops = []`，`ra = 3`、`rb = 3` 从未被更新，返回 $3 \times 3 = 9$，与「全零矩阵里 9 个格子都是最大值 0」一致。

## 4. 算法细节

1. **不要建矩阵，连差分数组也不要建**。本题的 $m n$ 上界是 $1.6 \times 10^9$，任何 $O(m n)$ 的内存方案都会被直接判 MLE；答案只依赖两个标量。
2. **初值必须是 `m` 与 `n`**，不能是 `0` 或无穷大。设成 `0` 会让 `ops` 为空时返回 0（应为 $m n$）；设成 `INT_MAX` 虽然结果正确，但要多写一次空判断，不如直接用 $m, n$ 干净——因为 $a_i \le m$、$b_i \le n$，真实的最小值不会超过初值。
3. **只遍历一次、只比较两次**：每条操作两次 `min`，没有排序、没有分桶。`ops` 的顺序无关紧要，`min` 满足交换律与结合律。
4. **乘积的溢出边界要心里有数**：$m, n \le 4 \times 10^4$ 时 $m n \le 1.6 \times 10^9 < 2^{31} - 1$，`int` 恰好够用（返回值类型也正是 `int`）；但如果把上界放宽到 $10^5$，`int` 立刻溢出，必须换成 `long long` 或 Python 的任意精度整数。
5. **可选剪枝**：一旦 `ra == 1 && rb == 1`，答案已经锁定为 1，后续操作不可能再改小，可以 `break` 提前退出。对本题数据量是锦上添花，但对「答案极紧 + ops 极长」的造数据很有效。
6. **不需要对 `a_i, b_i` 做任何合法化处理**。题目保证 $1 \le a_i \le m$、$1 \le b_i \le n$，所以 `ra`、`rb` 天然落在 $[1, m]$、$[1, n]$，不会出现负面积或越界。

## 5. 正确性证明

**引理 1（逐格计数值）**：执行完所有操作后，格子 $(x,y)$ 的值为 $\text{val}(x,y) = \bigl\lvert\{\, i : x < a_i \ \text{且}\ y < b_i \,\}\bigr\rvert$。

**证明**：矩阵初始全零；第 $i$ 条操作当且仅当 $x < a_i$ 且 $y < b_i$ 时把该格加 1，否则不动。累加的结果就是「覆盖它的操作条数」，即该集合的大小。∎

**引理 2（取到最大值的充要条件）**：设 $A = \min_i a_i$、$B = \min_i b_i$（`ops` 非空）。则 $\text{val}(x,y) = \lvert \text{ops} \rvert$ 当且仅当 $x < A$ 且 $y < B$。

**证明**：由引理 1，$\text{val}(x,y) \le \lvert \text{ops} \rvert$，等号成立当且仅当该集合包含全部下标，即对所有 $i$ 都有 $x < a_i$ 且 $y < b_i$。而「对所有 $i$ 都 $x < a_i$」等价于「$x$ 小于这些 $a_i$ 的最小值」$x < A$；$y$ 一侧同理。故充要条件得证。∎

**引理 3（矩形计数）**：满足 $x < A$、$y < B$ 的格子 $(x,y)$（$x, y$ 取非负整数）恰有 $A \cdot B$ 个。

**证明**：$x$ 有 $A$ 种取值 $0, \dots, A-1$，$y$ 有 $B$ 种取值 $0, \dots, B-1$，且 $x$ 与 $y$ 的选择互相独立，由乘法原理共 $A \cdot B$ 个。∎

**定理**：`maxCount` 返回矩阵中最大值的出现次数。

**证明**：分两种情形。

- `ops` 非空：由引理 2，取到最大值 $\lvert \text{ops} \rvert$ 的格子集合正是 $\{(x,y) : x < A,\ y < B\}$；又因为每条操作的矩形都包含左上角 $A \times B$ 这块（$A, B$ 取自最小值，故所有 $a_i \ge A$、$b_i \ge B$），该集合非空，它的大小即最大值出现次数。由引理 3，其大小为 $A \cdot B$。算法遍历 `ops` 取到 $A = \min_i a_i$、$B = \min_i b_i$，返回 $A \cdot B$，与真实值一致。
- `ops` 为空：矩阵恒为全零，最大值为 0，出现 $m n$ 次。此时循环不执行，`ra = m`、`rb = n`，返回 $m n$，同样一致。

两种情形下返回值都正确。∎

## 6. 复杂度分析

- **时间**：$O(\lvert \text{ops} \rvert)$。只对每条操作做两次比较与赋值，与 $m, n$ 完全无关；不构造矩阵、不做前缀和。以本题上界计约 $2 \times 10^4$ 次基本操作，常数极小。
- **空间**：$O(1)$。除两个整型变量 `ra`、`rb` 外不申请任何额外空间，输入 `ops` 只读遍历一次。

对比：暴力建矩阵是 $O(\lvert \text{ops} \rvert \cdot m n)$ 时间 + $O(m n)$ 空间，二维差分是 $O(\lvert \text{ops} \rvert + m n)$ 时间 + $O(m n)$ 空间，本题解法在两项上都降到了与边界无关的量级。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxCount(int m, int n, vector<vector<int>>& ops) {
        int ra = m;                 // 当前最小覆盖高度，初值 = 整张矩阵
        int rb = n;                 // 当前最小覆盖宽度，初值 = 整张矩阵
        for (const auto& op : ops) {
            ra = min(ra, op[0]);    // op[0] = a_i，只关心最小值
            rb = min(rb, op[1]);    // op[1] = b_i，只关心最小值
        }
        return ra * rb;             // m·n ≤ 1.6e9，int 不溢出
    }
};
```

### Python

```python
class Solution:
    def maxCount(self, m: int, n: int, ops: list[list[int]]) -> int:
        ra, rb = m, n                 # 没有操作时交集就是整张矩阵
        for a, b in ops:
            ra = min(ra, a)           # 与操作顺序无关，min 即可
            rb = min(rb, b)
        return ra * rb                # Python 整数无溢出问题
```

## 8. 边界情况与易错点

1. **`ops` 为空**（示例 3）：答案是 $m \cdot n$ 而不是 0。把 `ra`、`rb` 初始化成 `m`、`n` 就自动正确；若初始化为 0 则必错。
2. **`m = n = 1`**：矩阵只有一格，任何操作都只覆盖它，答案恒为 1。此时 `ra = rb = 1`，乘积为 1，无需特判。
3. **`int` 溢出**：$40000 \times 40000 = 1.6 \times 10^9$ 距离 $2^{31} - 1 = 2.147 \times 10^9$ 只有约 25% 余量，本题安全；但若有人把约束改大到 $10^5$，`int` 会溢出成负数，此时必须用 `long long`。写题时顺手把乘积放进 64 位更保险。
4. **误建矩阵**：$4 \times 10^4 \times 4 \times 10^4$ 的 `int` 矩阵约 6.4 GB，`vector<vector<int>>` 还会因分段额外膨胀，直接 MLE；二维差分的还原同样逃不掉 $O(m n)$。
5. **误以为要排序或多重循环**：有人在 `min` 之外还想「统计有多少条并列最小的操作」，但答案与并列条数无关——重复操作不改变交集。示例 2 就是 12 条操作 vs 2 条操作同答案。
6. **只更新一个维度**：`ra` 与 `rb` 必须各自独立取最小，不能用「面积最小」的那条操作同时决定两者。例如 `ops = [[2,10],[10,2]]`（$m = n = 10$）：两条操作面积相同（都是 20），但一条把高度压到 2、另一条把宽度压到 2，交集是 $2 \times 2 = 4$；若按面积挑一条再取矩形面积，会得到 20 这种错误答案。
7. **返回值语义**：题目要的是「最大值的**个数**」，不是最大值本身（最大值恒等于 $\lvert \text{ops} \rvert$，是送分信息，不要返回它）。
