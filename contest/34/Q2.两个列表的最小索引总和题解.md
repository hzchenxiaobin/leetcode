# LeetCode 两个列表的最小索引总和 题解

## 1. 题目概述

- **标题 / 题号**：两个列表的最小索引总和（#599，easy）
- **链接**：https://leetcode.cn/problems/minimum-index-sum-of-two-lists/
- **来源**：LeetCode 第 34 场周赛 Q2
- **难度**：简单
- **标签**：数组、哈希表、字符串

**题意**：给定两个字符串数组 `list1`、`list2`（各自内部**不含重复字符串**）。若某个字符串 `name` 同时出现在两者中，称它是**公共字符串**，其代价定义为两处出现的**下标和**

$$\text{cost}(name) = i + j,\qquad \text{list1}[i] = \text{list2}[j] = name$$

返回**所有**代价最小的公共字符串，顺序任意。

**约束**：

- $1 \le \text{list1.length}, \text{list2.length} \le 1000$
- $1 \le \text{list1}[i]\text{.length}, \text{list2}[i]\text{.length} \le 30$
- 字符串仅由空格 `' '` 与英文字母组成（可能出现 `"Burger King"` 这种带空格的词）
- `list1` 内所有字符串互不相同；`list2` 内所有字符串互不相同

> 💡 关键信号：「各自唯一」意味着同一个字符串在 `list1` 中**至多出现一次**、在 `list2` 中也**至多出现一次**，因此每个公共串的下标对 $(i, j)$ 是被字符串**唯一决定**的——这直接把「在所有下标对里找最优」降级成「一次扫描算代价」。

## 2. 示例

**示例 1**

```text
输入：list1 = ["Shogun","Tapioca Express","Burger King","KFC"]
     list2 = ["Piatti","The Grill at Torrey Pines","Hungry Hunter Steakhouse","Shogun"]
输出：["Shogun"]
解释：唯一的公共字符串是 "Shogun"，索引和 = 0 + 3 = 3，无悬念。
```

**示例 2**

```text
输入：list1 = ["Shogun","Tapioca Express","Burger King","KFC"]
     list2 = ["KFC","Shogun","Burger King"]
输出：["Shogun"]
解释：公共串有三个，索引和分别为
      "KFC" = 3 + 0 = 3，"Shogun" = 0 + 1 = 1，"Burger King" = 2 + 2 = 4
      最小是 1，对应 ["Shogun"]。
```

**示例 3（并列答案）**

```text
输入：list1 = ["happy","sad","good"]
     list2 = ["sad","happy","good"]
输出：["sad","happy"]        （顺序任意）
解释："happy" = 0 + 1 = 1，"sad" = 1 + 0 = 1，"good" = 2 + 2 = 4
      最小索引和 1 由 "happy" 与 "sad" 并列分享，两者都要返回。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i, j)$，若 `list1[i] == list2[j]` 就用 $i + j$ 去更新答案：

```text
for i in 0..m-1:
    for j in 0..n-1:
        if list1[i] == list2[j]: 维护最小和与答案集
```

每次比较字符串要 $O(L)$（$L \le 30$），总时间 $O(m \cdot n \cdot L)$。$m = n = 1000$ 时是 $10^6$ 次字符串比较，C++ 能过、Python 偏紧。更要命的是**信息浪费**：$10^6$ 个下标对里，真正对应公共串的至多 $\min(m, n) \le 1000$ 个，其余全是白比较。

### 3.2 核心观察：唯一性 ⇒ 代价由字符串唯一决定

![同一个公共串在 list1 与 list2 中各出现一次，代价为两个下标之和](images/wc34_q2_index_sum_concept.svg)

因为两个列表**各自无重复**，对任意公共串 `name`：

- 它在 `list1` 中的下标 $i$ 唯一，在 `list2` 中的下标 $j$ 也唯一；
- 于是它的代价 $i + j$ 是一个**确定值**，不存在「同一个名字有多组下标对、需要挑最优」的复杂情况。

这把问题拆成两步，且第二步是**线性扫描**：

1. **建表**：一次遍历 `list1`，得到 `pos[name] = i`（字符串 → 下标）；
2. **扫描 list2**：对每个 $j$，若 `list2[j]` 在 `pos` 中，就得到一个公共串及其代价 $i + j$，与当前最优 `best` 比较。

> 💡 这本质上是「**空间换时间**」的经典套路：把「在每个 $j$ 上找匹配的 $i$」从 $O(m)$ 的线性查找压到 $O(1)$ 的哈希查找，与两数之和把 $O(n^2)$ 降到 $O(n)$ 是同一个思想。

**答案集的维护**（题目要返回**全部**并列项，这是本题唯一的坑）：

- $i + j < best$：`best ← i + j`，并**清空**答案集后放入当前字符串；
- $i + j = best$：追加到答案集；
- $i + j > best$：忽略。

### 3.3 算法流程（含剪枝）

![建表 → 扫描 list2 → 剪枝 → 三分支更新 best 与答案集](images/wc34_q2_hash_flow.svg)

```text
1. pos ← { list1[i] : i }，遍历 list1 一次
2. best ← +∞，ans ← []
3. for j = 0 .. n-1:
4.     if j > best: break            # 剪枝：i ≥ 0 ⇒ 之后任意 i+j ≥ j > best
5.     i ← pos.get(list2[j])；不存在则 continue
6.     total ← i + j
7.     if total < best:  best ← total；ans ← [list2[j]]
8.     elif total == best: ans.append(list2[j])
9. return ans
```

**剪枝为什么成立**：后续任何公共串的代价是 $i' + j'$，其中 $j' \ge j$、$i' \ge 0$，故 $i' + j' \ge j > best$，全部**不可能**改进或打平当前最优值。由于 `list2` 的下标 $j$ 单调递增，一旦越过 `best` 就可以直接停。

> ⚠️ **必须写 `j > best` 而不是 `j >= best`**：当 $j = best$ 时，若该串在 `list1` 的下标恰好是 $0$，代价 $0 + best = best$ 会**打平**当前最优，属于必须收进答案集的并列解。写成 `>=` 会漏掉这类答案。

### 3.4 示例演算

![示例 2 演算：j = 0 记录 KFC，j = 1 用 Shogun 覆盖，j = 2 触发剪枝](images/wc34_q2_walkthrough.svg)

**示例 2**：`pos = {Shogun:0, Tapioca Express:1, Burger King:2, KFC:3}`，`list2 = [KFC, Shogun, Burger King]`。

| $j$ | `list2[j]` | $i$ | $i+j$ | `best` | `ans` | 说明 |
|:---:|------------|:---:|:-----:|:------:|-------|------|
| 0 | KFC | 3 | 3 | 3 | `[KFC]` | 首个公共串，直接记录 |
| 1 | Shogun | 0 | 1 | 1 | `[Shogun]` | 更优 → 清空后覆盖 |
| 2 | Burger King | — | — | 1 | `[Shogun]` | $2 > best = 1$ → break，无需查询 |

**示例 3**（展示并列收集）：`pos = {happy:0, sad:1, good:2}`，`list2 = [sad, happy, good]`。

| $j$ | `list2[j]` | $i$ | $i+j$ | `best` | `ans` | 说明 |
|:---:|------------|:---:|:-----:|:------:|-------|------|
| 0 | sad | 1 | 1 | 1 | `[sad]` | — |
| 1 | happy | 0 | 1 | 1 | `[sad, happy]` | **打平** → 追加 |
| 2 | good | — | — | 1 | `[sad, happy]` | $2 > 1$ → break |

最终返回 `["sad","happy"]`，与官方输出一致（顺序任意）。

## 4. 算法细节

1. **建表方向**：对 `list1` 建 `pos`、扫描 `list2` 是最自然的写法。若想省一点空间，可以对**较短**的列表建表、扫描较长的列表（答案集只依赖代价，与扫描方向无关），但复杂度不变，本题 $m, n \le 1000$ 无需纠结。
2. **`best` 初值必须是 $+\infty$**：Python 用 `float('inf')`，C++ 用 `INT_MAX`。若误写 `best = 0`，则任何 $i + j \ge 0$ 都不会严格小于它，答案永远为空——这是本题最高频的 WA。
3. **三分支更新**：`<` 时**先清空再放入**（`ans = [name]`），`==` 时追加，`>` 时不动。只写「`<=` 就 append」会把更优解之前的旧答案残留在结果里。
4. **剪枝位置**：放在查表**之前**，条件 `j > best`。放后面也不影响正确性，但会白做一次哈希查找；写成 `j >= best` 则会漏掉 $i = 0$ 的并列解。
5. **哈希表选型**：C++ 用 `unordered_map<string,int>`，并 `reserve(2 * m)` 减少 rehash；Python 直接 `dict`（CPython 的 dict 对短字符串极快）。字符串长度 $\le 30$，单次哈希 $O(L)$，但均摊后整体仍是线性。
6. **不要排序、不要建 set**：下标是**原始位置**，一旦对 `list1` 排序，$i$ 的含义就被破坏了；而 `set` 会丢掉刚好需要的下标信息。
7. **返回顺序**：题目说「以任何顺序返回」，按 `list2` 扫描顺序输出即可，无需再排序；判题按集合比较。
8. **单词含空格**：`"Burger King"`、`"The Grill at Torrey Pines"` 都是**单个数组元素**。本地测试时不要用按空格切分的读入方式，Python 直接读 list、C++ 用 `vector<string>` 且用 `getline` 读整行。

## 5. 正确性证明

**引理 1（下标唯一）**：对任意公共串 `name`，存在唯一的 $i$ 与唯一的 $j$ 使 $\text{list1}[i] = \text{list2}[j] = name$；且建表后 `pos[name] = i`。

**证明**：存在性由「公共串」定义给出。唯一性：若有两个不同下标 $i \ne i'$ 都满足 $\text{list1}[i] = \text{list1}[i'] = name$，则 `list1` 中 `name` 出现两次，与「`list1` 内字符串互不相同」矛盾；$j$ 同理。建表遍历一遍 `list1`，每个字符串写入一次下标，故 `pos[name] = i`。∎

**引理 2（扫描不变式）**：设扫描到 `list2` 的前 $k$ 个元素（未触发 `break`），记 $C_k$ 为这 $k$ 个元素中所有公共串的集合，则

$$\text{best} = \min_{x \in C_k} \text{cost}(x),\qquad \text{ans} = \{\, x \in C_k : \text{cost}(x) = \text{best} \,\}$$

（$C_k = \varnothing$ 时 `best` $=+\infty$、`ans` 为空。）

**证明**：对 $k$ 归纳。$k = 0$ 时结论即初值。设结论对 $k$ 成立，处理第 $k+1$ 个元素（下标 $j = k$）：若 `list2[j]` 不是公共串，集合不变，结论保持；若是公共串，由引理 1 其代价 $t = i + j$ 唯一。分三种情况——$t < \text{best}$ 时新最小值即 $t$ 且唯一取到者只有该项，`ans` 重置为 $\{x\}$，等式两边同时成立；$t = \text{best}$ 时最小值不变、取到最小值的集合恰好多出 $x$，追加正确；$t > \text{best}$ 时最小值与取到者都不变，忽略正确。故结论对 $k+1$ 成立。∎

**引理 3（剪枝安全）**：若在某时刻 `best` $= B$ 且待处理的 `list2` 下标 $j$ 满足 $j > B$，则 `list2[j..n)` 中任何公共串都不会改变 `best` 与 `ans`。

**证明**：设 `list2[j']`（$j' \ge j$）是公共串，其在 `list1` 的下标 $i' \ge 0$，故

$$\text{cost} = i' + j' \ge j' \ge j > B$$

即代价严格大于当前最优 $B$，既不能改进也不能打平，`ans` 与 `best` 均不变。∎

**定理**：算法返回的数组恰为所有索引和最小的公共字符串。

**证明**：分两种终止方式。① 循环自然结束（遍历完整个 `list2`）：由引理 2，`C_n` 是全部公共串集合，`ans` 恰为其中代价等于最小值的全部字符串。② 在 $j$ 处 `break`：由引理 2，`ans` 已是前 $j$ 个元素中的全部最优解；由引理 3，剩余元素（下标 $\ge j$）不含任何代价 $\le \text{best}$ 的公共串，故前 $j$ 个元素的最优解就是全局最优解，`ans` 正确。两种情况下返回集合都满足题意，且引理 1 保证每个字符串只被计入一次、不会重复。∎

## 6. 复杂度分析

- **时间**：$O(m + n)$（期望）。建表遍历 `list1` 一次，$m$ 次哈希插入，每次均摊 $O(1)$（字符串哈希为 $O(L)$，$L \le 30$ 视作常数）；扫描 `list2` 至多 $n$ 次，每次一次哈希查找 + 常数次比较。剪枝生效时实际只需扫描 $\min(n,\ \text{best}+1)$ 个元素，常数更小。
- **空间**：$O(m + k)$。`pos` 表存 $m$ 个「字符串 → 下标」键值对；答案集 `ans` 至多 $k$ 个元素（$k$ 为并列最优的公共串个数，$k \le \min(m,n)$）。输入本身不计入，除此之外无额外结构。
- **与暴力对比**：暴力 $O(m \cdot n \cdot L)$ 在 $m = n = 1000$ 时约 $10^6$ 次字符串比较；哈希法把它降到 $2 \times 10^3$ 次哈希操作，快约三个量级。

## 7. 参考代码

### C++

```cpp
#include <climits>
#include <string>
#include <unordered_map>
#include <vector>
using namespace std;

class Solution {
public:
    vector<string> findRestaurant(vector<string>& list1, vector<string>& list2) {
        unordered_map<string, int> pos;
        pos.reserve(list1.size() * 2);              // 预留桶，避免 rehash
        for (int i = 0; i < (int)list1.size(); ++i) {
            pos[list1[i]] = i;                      // 唯一性保证不会覆盖有效下标
        }

        int best = INT_MAX;
        vector<string> ans;
        for (int j = 0; j < (int)list2.size(); ++j) {
            if (j > best) break;                    // 剪枝：i >= 0 ⇒ i + j >= j > best
            auto it = pos.find(list2[j]);
            if (it == pos.end()) continue;          // 不是公共串
            int total = it->second + j;
            if (total < best) {
                best = total;
                ans.assign(1, list2[j]);            // 更优：清空后覆盖
            } else if (total == best) {
                ans.push_back(list2[j]);            // 打平：追加并列解
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findRestaurant(self, list1: List[str], list2: List[str]) -> List[str]:
        pos = {name: i for i, name in enumerate(list1)}
        best = float('inf')
        ans = []
        for j, name in enumerate(list2):
            if j > best:          # 剪枝：之后的索引和只会更大
                break
            i = pos.get(name)
            if i is None:         # 不是公共串
                continue
            total = i + j
            if total < best:
                best = total
                ans = [name]      # 更优：清空后覆盖
            elif total == best:
                ans.append(name)  # 打平：追加并列解
        return ans
```

## 8. 边界情况与易错点

1. **`best` 初值**：必须取 $+\infty$（`INT_MAX` / `float('inf')`）。取 `0` 会让「更小」永远不成立，直接返回空数组。
2. **并列答案必须全部返回**：示例 3 中 `"happy"` 与 `"sad"` 并列，只返回一个即 WA。判题按集合比较，顺序不敏感。
3. **剪枝写成 `j >= best`**：会漏掉「$j = best$ 且该串在 `list1` 下标为 $0$」的并列解（代价 $0 + best = best$）。必须严格写 `>`。
4. **忘记清空答案集**：遇到更小代价时若只 `append` 不重置，旧的最优解会残留在结果里，输出多出串。
5. **无公共串**：题面中文版约束未显式保证存在公共串，此时 `best` 保持 $+\infty$、`ans` 为空数组，返回 `[]` 不会越界也不会误报——代码天然兜底。
6. **下标混用**：$i$ 来自 `list1`、$j$ 来自 `list2`，两者长度可以不同（$m \ne n$）。不要复用同一个循环变量，也不要假设 $i, j$ 上界一致。
7. **名字含空格**：`"Burger King"` 是一个元素。自己写测试脚手架时按行切分而不是按空格切分，否则会把一个名字拆成两个。
8. **`list1` 或 `list2` 只有一个元素**：若两者相同，$i = j = 0$，代价 $0$；若不公共，返回 `[]`。循环与剪枝都能自然处理，无需特判。
