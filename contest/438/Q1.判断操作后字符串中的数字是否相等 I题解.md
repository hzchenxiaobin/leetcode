# LeetCode 判断操作后字符串中的数字是否相等 I 题解

## 1. 题目概述

- **标题 / 题号**：判断操作后字符串中的数字是否相等 I（#3461，easy）
- **链接**：https://leetcode.cn/problems/check-if-digits-are-equal-in-string-after-operations-i/
- **来源**：LeetCode 第 438 场周赛 Q1
- **难度**：简单
- **标签**：数学、字符串、模拟

**题意**：给定数字字符串 `s`，反复执行收缩操作直到只剩**两位**：每一轮把所有相邻数对 `(s[i], s[i+1])` 替换为 `(s[i] + s[i+1]) mod 10`，串长每轮减 1。若最终两位**相同**返回 `true`，否则返回 `false`。

**约束**：

- $3 \le s.length \le 100$
- `s` 仅由数字组成

> 💡 **读题关键**：① 串长每轮**严格减 1**，从 $n$ 收缩到 2 恰需 $n-2$ 轮，循环必然终止、无需任何保护；② 「和模 10」让数字永远落在 $0 \sim 9$，没有进位、没有类型问题；③ $n \le 100$ ⇒ 总运算量 $O(n^2) \approx 5000$ 次加法——**题意本身就是伪代码，直接模拟就是预期解法**。本题的进阶版正是**本场 Q3**（II 版把 $n$ 放大到 $10^5$，逼你放弃模拟转向组合数学）。

## 2. 示例

**示例 1**

```text
输入：s = "3902"
输出：true
解释：第 1 轮：(3+9)%10=2, (9+0)%10=9, (0+2)%10=2 → s = "292"
      第 2 轮：(2+9)%10=1, (9+2)%10=1           → s = "11"
      "11" 两位相同，返回 true
```

**示例 2**

```text
输入：s = "34789"
输出：false
解释：第 1 轮后 s = "7157"，第 2 轮后 s = "862"，第 3 轮后 s = "48"
      '4' != '8'，返回 false
```

## 3. 解题思路

### 3.1 签到最短路径：题意即伪代码

Q1 的目标是**快速切入**：把题面两行操作描述逐字翻译成循环即可——

```text
while len(a) > 2:
    a = [(a[i] + a[i+1]) % 10 for i in 0 .. len(a)-2]
return a[0] == a[1]
```

每轮扫描当前整串，共 $n-2$ 轮，总时间 $O(n^2)$。$n \le 100$ 时全程不足五千次加法，直接提交即可。

### 3.2 核心观察：长度严格递减 + 模 10 封闭

![相邻求和金字塔：每轮长度减 1](images/c438_q1_pyramid_concept.svg)

**为什么模拟是安全的**：

- **终止性免费**：新串每一位对应旧串一对相邻数字，长度恰好 $len - 1$。从 $n$ 出发经过 $n-2$ 轮**必然**到达 2，循环条件 `len > 2` 不会被绕进死循环，也不需要额外计数器。
- **值域封闭**：两位数字之和 $\le 18$，模 10 后仍是一位数字——中间过程不需要进位处理，`int` 毫无溢出风险。
- **无中途信息**：只有长度为 2 时「两位相同」才有定义，中途的任何局部形态都不携带关于终态的单调信息（示例 1 初始首位 $3 \ne 9$ 结果却是 `true`），**不能剪枝，只能算到底**。

### 3.3 算法流程

![算法流程：逐轮收缩，n−2 轮后比较两位](images/c438_q1_algorithm_flow.svg)

| 步骤 | 动作 | 说明 |
|------|------|------|
| ① 转换 | `a = [int(c) for c in s]` | 字符转数字，避开 ASCII 相加的坑 |
| ② 收缩 | `b[i] = (a[i] + a[i+1]) % 10`，`a = b` | 每轮长度减 1 |
| ③ 循环 | `while len(a) > 2` | 恰好执行 $n-2$ 次 |
| ④ 判等 | `return a[0] == a[1]` | 终态两位比较 |

### 3.4 示例演算

![示例演算：两个金字塔逐层收缩](images/c438_q1_example_walkthrough.svg)

| 轮次 | `"3902"`（n=4） | `"34789"`（n=5） |
|------|-----------------|------------------|
| 初始 | `3 9 0 2` | `3 4 7 8 9` |
| 第 1 轮 | `2 9 2` | `7 1 5 7` |
| 第 2 轮 | `1 1` | `8 6 2` |
| 第 3 轮 | ——（停止） | `4 8` |
| 结果 | `"11"` 相同 → **true** | `"48"` 不同 → **false** |

> 💡 两个例子各花 $n-2$ 轮到达终态；注意 `"3902"` 初始没有任何相同相邻对，最终却为 `true`——再次印证「中途无信息」。

## 4. 算法细节

1. **字符转数字**：`s` 是字符串，直接 `s[i] + s[i+1]` 加的是 ASCII 码（如 `'3' + '9' = 102`）。先统一转成 `int` 数组（C++ `c - '0'`，Python `int(c)`）。
2. **新数组构造**：`b[i] = (a[i] + a[i+1]) % 10`，`i` 取 $0 \sim len(a)-2$；Python 用 `zip(a, a[1:])` 相邻配对最简洁。**不要原地覆写** `a[i]`——本位新值依赖旧的本位与下一位，覆写会污染尚未计算的数对；要么新建数组，要么从左到右只读旧数组。
3. **终止与判等**：`while` 条件用 `len(a) > 2`（长度恰为 2 时不再操作），循环退出后比较 `a[0]` 与 `a[1]`。
4. **通往 Q3 的数学视角**：收缩操作是**线性**的。对轮数归纳可得第 $k$ 轮后第 $i$ 位为 $T_k(i) = \sum_{j=0}^{k} \binom{k}{j} d_{i+j} \pmod{10}$（系数按杨辉递推 $\binom{k+1}{j} = \binom{k}{j-1} + \binom{k}{j}$ 演化）。于是终态两位有闭式：

$$L = \sum_{j=0}^{n-2} \binom{n-2}{j} d_j \pmod{10}, \qquad R = \sum_{j=0}^{n-2} \binom{n-2}{j} d_{j+1} \pmod{10}$$

   $n \le 100$ 时用 Python 大数 `math.comb` 可以 $O(n^2)$ 直接算闭式跳过全部中间轮次；但 $n$ 到 $10^5$（II 版）时模 10 是合数、逆元不存在，需要 Lucas 定理拆 mod 2 / mod 5 再 CRT 合并——那是本场 Q3 的主题。

## 5. 正确性证明

**引理 1（轮数与终止性）**：从长度 $n \ge 3$ 的串出发，第 $k$ 轮后长度为 $n - k$；算法恰在第 $n - 2$ 轮后停止。

**证明**：一轮操作把每一对 $(a_i, a_{i+1})$（共 $len - 1$ 对）收缩成一个新位，故新串长度恰为 $len - 1$。对 $k$ 归纳：第 $k$ 轮后长度为 $n - k \ge 2$。当 $n - k = 2$ 时条件 `len > 2` 不再成立，循环退出，共执行 $n - 2$ 轮。∎

**引理 2（逐轮等价）**：算法第 $k$ 轮后的数组与按题意执行 $k$ 次操作后的字符串逐位相同。

**证明**：对 $k$ 归纳。$k = 0$ 时两者都是初始数字串。设第 $k$ 轮后均为 $a_0, \dots, a_{m-1}$：算法第 $k+1$ 轮构造 $b_i = (a_i + a_{i+1}) \bmod 10$（$0 \le i \le m-2$），逐字对应题意「对每一对连续数字计算和模 10 并按原顺序替换」，即第 $k+1$ 轮后两者仍逐位相同。∎

**定理**：算法返回 `true` 当且仅当按题意操作到只剩两位时两位相同。

**证明**：由引理 1，算法恰好执行 $n - 2$ 轮后停在长度 2；由引理 2，此时数组 $(a_0, a_1)$ 就是题意定义的最终两位。故比较 $a_0 = a_1$ 与「最终两位相同」等价，返回值正确。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。共 $n - 2$ 轮，第 $i$ 轮处理 $n - i$ 个数对，总计 $\sum_{i=0}^{n-3}(n - i) \approx \frac{n^2}{2}$ 次加法与取模；$n \le 100$ 时约五千次，远低于任何限制。
- **空间复杂度**：$O(n)$。存放当前数组与新数组；若从右往左原地覆写（先算 $a_{len-2}$ 再逐位前移）可降到 $O(1)$ 额外空间，但签到题不值得为此冒险。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool hasSameDigits(string s) {
        vector<int> a;
        for (char c : s) a.push_back(c - '0');
        while (a.size() > 2) {
            vector<int> b;
            for (int i = 0; i + 1 < (int)a.size(); i++)
                b.push_back((a[i] + a[i + 1]) % 10);
            a = move(b);
        }
        return a[0] == a[1];
    }
};
```

### Python

```python
class Solution:
    def hasSameDigits(self, s: str) -> bool:
        a = [int(c) for c in s]
        while len(a) > 2:
            a = [(x + y) % 10 for x, y in zip(a, a[1:])]
        return a[0] == a[1]
```

> 💡 组合数闭式版（$O(n^2)$ 内含大数乘加，跳过全部中间轮次）：`k = len(s) - 2`，`L = sum(comb(k, j) * int(s[j]) for j in range(k + 1)) % 10`，`R` 同理对 `s[j+1]`，返回 `L == R`。本题用不上，但它是 II 版解法的第一块积木。

## 8. 边界情况与易错点

1. **ASCII 相加**：`s[i] + s[i+1]` 是字符码相加（`'3' + '9' = 102`），忘记 `- '0'` / `int()` 是本题第一大 WA 来源。
2. **忘模 10**：两数之和最大 18，不取模会把两位数混进下一轮，后续全部错位。
3. **不要原地覆写**：`a[i] = (a[i] + a[i+1]) % 10` 从左往右写会污染 `a[i+1]` 参与的下一次计算，必须新建数组（或从右往左覆写）。
4. **终止条件**：`while len(a) > 2`（长度为 2 即停）；写成 `>= 2` 会在长度 2 时多收缩成 1 位然后比较越界/错误。
5. **中途形态无信息**：`"3902"` 初始无任何相同相邻对却返回 `true`；反过来 `"992"` 初始有相同对 `(9,9)`，收缩得 `"81"` 返回 `false`——不要根据中途特征提前返回。
6. **最小规模**：$n = 3$ 只执行 1 轮（如 `"3902"` 退化版 `"347"` → `"71"`），循环体必须正确处理长度 3 → 2 这一跳。
7. **无溢出、无空串**：值域 $0 \sim 9$、$n \ge 3$ 有保证，无需特判。
