# LeetCode 提取至多 K 个元素的最大总和 题解

## 1. 题目概述

- **标题 / 题号**：提取至多 K 个元素的最大总和（#3462，medium）
- **链接**：https://leetcode.cn/problems/maximum-sum-with-at-most-k-elements/
- **来源**：LeetCode 第 438 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、矩阵、排序、堆（优先队列）

**题意**：给定 $n \times m$ 的矩阵 `grid`、长度为 $n$ 的数组 `limits` 和整数 $k$。从中提取**至多 $k$ 个元素**使总和最大，且**第 $i$ 行提取的元素个数不超过 `limits[i]`**。返回最大总和。

**约束**：

- $n = \text{grid.length} = \text{limits.length}$，$m = \text{grid}[i].\text{length}$
- $1 \le n, m \le 500$
- $0 \le \text{grid}[i][j] \le 10^5$
- $0 \le \text{limits}[i] \le m$
- $0 \le k \le \min(n \cdot m, \sum \text{limits}[i])$

> 💡 **读题关键**：两个约束悄悄保证了贪心的安全——① 元素**非负**，「至多 $k$ 个」可以当成「取满 $k$ 个」；② $k \le \sum \text{limits}[i]$，候选永远够取。同时注意规模：$n \cdot m \le 2.5\times10^5$、单元素 $\le 10^5$，总和解上界 $2.5\times10^{10}$，**C++ 必须用 `long long`**。

## 2. 示例

**示例 1**

```text
输入：grid = [[1,2],[3,4]], limits = [1,2], k = 2
输出：7
解释：从第 1 行取 4 和 3（行内 2 个，恰好等于 limits[1]=2），总和 4+3 = 7。
```

**示例 2**

```text
输入：grid = [[5,3,7],[8,2,6]], limits = [2,2], k = 3
输出：21
解释：第 0 行取 {7, 5}，第 1 行取 {8, 6}，池内前 3 大为 8+7+6 = 21。
```

**示例 3**（自造，验证行配额的拦截作用）

```text
输入：grid = [[10,9],[1,1]], limits = [1,2], k = 2
输出：11
解释：全局前 2 大是 10 和 9（和 19），但两者都在第 0 行、超过 limits[0]=1，不可行。
      正确方案：第 0 行取 10，第 1 行取 1，总和 11。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的枚举是**行间组合**：每行列举所有大小 $\le \text{limits}[i]$ 的子集（单行最多 $2^m$ 种），再在行间组合出总数 $\le k$ 的全局方案——指数级，$m = 500$ 时天文数字，完全不可行。

退一步的「朴素贪心」是**无视行配额、直接取全局前 $k$ 大**。这是错的：示例 3 里全局 top-2 $= 10 + 9 = 19$，但两个数挤在第 0 行、配额只有 1 个。**行配额会把同一行的「扎堆大数」拦腰截断**——这正是本题与普通 top-k 的本质区别，也是最快的 WA 来源。

还有一种正确但不够精的做法：把全部 $n \cdot m$ 个元素塞进大顶堆，每次弹全局最大者，若其所在行配额已满就丢弃。它正确（可交换论证），但要为所有被丢弃元素付堆操作代价，最坏 $O(nm \log(nm))$，且完全没利用「每行只需关心前 $\text{limits}[i]$ 大」这一结构。

### 3.2 核心观察：两步贪心——行内裁剪 + 跨行合并

![核心观察：全局 top-k 反例与两步贪心修正](images/c438_q2_two_step_greedy.svg)

整个问题可以拆成两步**各自贪心**，每步都有干净的证明：

**第一步（行内裁剪）：每行只需考虑前 `limits[i]` 大的元素。**

> 💡 **交换论证**：设某可行方案从第 $i$ 行取了 $x$，而同行还有更大的未取元素 $y > x$。把 $x$ 换成 $y$：每行取的个数不变（可行性不变），总和变大。于是任意最优解中，第 $i$ 行取出的必然是该行**降序排列后的一个前缀**——每行贡献给全局的候选只有前 $\text{limits}[i]$ 个，其余元素可以直接扔掉。

**第二步（跨行合并）：候选池内取前 $k$ 大之和。**

把每行留下的候选汇入一个池子（池大小 $S = \sum \text{limits}[i] \le n \cdot m$），问题退化为**不带任何约束的「取前 $k$ 大」**。两个题目约束保证了这就是答案：

1. **元素非负**（$\text{grid}[i][j] \ge 0$）：多取一个候选总和不会变小，「至多 $k$ 个」等价于「取满 $k$ 个」；
2. **$k \le \sum \text{limits}[i]$**（题目显式保证）：池里的候选永远够取满 $k$ 个。

> ⚠️ **溢出提醒**：$k$ 个元素之和上界 $2.5\times10^5 \times 10^5 = 2.5\times10^{10}$，超出 `int32` 范围。C++ 累加器必须用 `long long`（Python 天然大数无碍）。

### 3.3 算法流程

![算法流程：逐行降序排序、截取前 limits[i] 入池、池降序排序、取前 k 个累加](images/c438_q2_algorithm_flow.svg)

| 步骤 | 动作 | 说明 |
|------|------|------|
| ① 行循环 | 第 $i$ 行降序排序 | 原地 `sort(row.rbegin(), row.rend())` |
| ② 裁剪入池 | 前 $\text{limits}[i]$ 个追加进 `pool` | 其余元素永久出局 |
| ③ 池排序 | `pool` 降序排序 | 对应第二步贪心 |
| ④ 求和 | 取前 $k$ 个累加（`long long`） | $k \le \lvert\text{pool}\rvert = S$ 有保证 |

流程是纯线性的：逐行「排序 → 截取入池」，最后「池排序 → 前 $k$ 个求和」。两个排序阶段分别对应两步贪心。

### 3.4 示例演算

![示例 2 逐行裁剪入池与池内取前 k 大的走查](images/c438_q2_example_walkthrough.svg)

以示例 2 走一遍完整流程：

| 阶段 | 内容 | 结果 |
|------|------|------|
| 第 0 行 | $[5,3,7]$ 降序 $\to [7,5,3]$，`limits[0]=2` | 取 $\{7,5\}$，3 出局 |
| 第 1 行 | $[8,2,6]$ 降序 $\to [8,6,2]$，`limits[1]=2` | 取 $\{8,6\}$，2 出局 |
| 候选池 | $[7,5,8,6]$ 降序 $\to [8,7,6,5]$ | $k=3$ |
| 求和 | $8+7+6$ | $\boxed{21}$ ✓ |

被裁掉的 3、2 与池内落选的 5 永远不可能出现在任何最优解里——行内或池内总有更大的替代者。

## 4. 算法细节

1. **行内裁剪的实现**：直接对 `grid[i]` 原地降序排序，再取前 `limits[i]` 个追加进池。允许修改输入矩阵，无需拷贝。若不想动输入，可用 `nth_element`（平均 $O(m)$）把前 $\text{limits}[i]$ 大换到头部再拷出。
2. **池的规模**：$S = \sum \text{limits}[i] \le n \cdot m \le 2.5\times10^5$，一次 `sort` 毫无压力；若想省掉 $O(S\log S)$，可用 `nth_element`（C++）或 `heapq.nlargest`（Python）平均 $O(S)$ 取出前 $k$ 大。
3. **累加器类型**：C++ 用 `long long ans = 0` 初始化再累加；Python 无需关心。
4. **取前 k 个的安全性**：题目保证 $k \le \sum \text{limits}[i] = \lvert\text{pool}\rvert$，`pool[:k]` 不会越界。若写成 `pool[:min(k, len(pool))]` 则去掉该约束也稳健（变体讨论见「相关题目与扩展」）。
5. **替代实现（多路归并堆）**：行排序后每行候选是一段降序序列，可看成 $n$ 路归并取前 $k$ 个——每行只把当前头元素 `(值, 行号)` 放进大顶堆，弹一次若该行还有候选就推入下一个，堆大小至多 $n$，复杂度 $O(nm\log m + (n+k)\log n)$，$k \ll S$ 时更省。比赛中两法皆可，排序版代码最短。
6. **为什么不用「全量堆 + 配额检查」**：它把 $n \cdot m$ 个元素全部进堆，配额满的行照样弹出大量废元素，最坏 $O(nm\log(nm))$；行内裁剪先行，直接让这些元素根本不进堆。

## 5. 正确性证明

**引理 1（行内前缀性）**：任意最优方案中，第 $i$ 行取出的元素集合 $A_i$ 满足 $\min(A_i) \ge \max(B_i)$，其中 $B_i$ 是该行未取元素集合；即 $A_i$ 恰为该行前 $|A_i|$ 大的元素。

**证明**：反证。若存在 $x \in A_i$、$y \in B_i$ 且 $y > x$，将 $x$ 换成 $y$：第 $i$ 行取的个数不变（$|A_i|$ 不变，仍 $\le \text{limits}[i]$，其他行不动），方案仍可行；总和变化 $y - x > 0$，严格增大，与「最优」矛盾。∎

**引理 2（池化归约）**：原问题与「从候选池 $P$（第 $i$ 行降序前 $\text{limits}[i]$ 个元素之并，$\lvert P\rvert = S$）中取至多 $k$ 个元素求最大和」等价。

**证明**：一方面，$P$ 中任意选取方案按行分组后每行个数 $\le \text{limits}[i]$，是原问题的可行方案，故原问题最优值 $\ge$ 池问题最优值。另一方面，设原问题某最优方案各行的选取个数为 $c_i \le \text{limits}[i]$，由引理 1，第 $i$ 行取的恰为该行前 $c_i$ 大，是 $P$ 中第 $i$ 行那 $\text{limits}[i]$ 个候选的前缀，故该方案全由池元素构成，从而池问题最优值 $\ge$ 原问题最优值。两值相等。∎

**定理**：答案等于 $P$ 中前 $k$ 大元素之和。

**证明**：由 $\text{grid}[i][j] \ge 0$ 知任何方案加上池中一个未取元素后总和不减，故最优方案可设恰取 $k$ 个（池问题同样受「至多 $k$」约束）；又 $k \le S$ 保证取得到。再证「恰取 $k$ 个的最优方案必为前 $k$ 大」：设方案 $T$ 取 $k$ 个但非前 $k$ 大，则 $P \setminus T$ 中存在元素 $y > \min(T)$（否则 $T$ 已包含所有比 $\min(T)$ 大的元素、即前 $k$ 大），用 $y$ 替换 $\min(T)$ 总和严格增大，矛盾。故最优值即前 $k$ 大之和。∎

## 6. 复杂度分析

- **时间复杂度**：$O(nm\log m + S\log S)$。行排序共 $n$ 次、每次 $O(m\log m)$；池排序一次 $O(S\log S)$，其中 $S = \sum\text{limits}[i] \le nm$。粗上界 $O(nm\log(nm))$；$n, m \le 500$ 时总量不到 $10^6$ 级别，非常宽裕。用 `nth_element` / `nlargest` 可压到平均 $O(nm\log m + S)$。
- **空间复杂度**：$O(S)$。候选池至多存 $\sum \text{limits}[i] \le 2.5\times10^5$ 个元素；行排序原地完成不额外耗空间（若不允许改输入则另有 $O(nm)$ 拷贝）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long maxSum(vector<vector<int>>& grid, vector<int>& limits, int k) {
        vector<int> pool;
        for (int i = 0; i < (int)grid.size(); i++) {
            auto& row = grid[i];
            sort(row.rbegin(), row.rend());          // 行内降序（原地）
            for (int j = 0; j < limits[i]; j++) {
                pool.push_back(row[j]);              // 只留前 limits[i] 大
            }
        }
        sort(pool.rbegin(), pool.rend());            // 池内降序
        long long ans = 0;
        for (int j = 0; j < k; j++) ans += pool[j];  // k <= 池大小（题目保证）
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxSum(self, grid: List[List[int]], limits: List[int], k: int) -> int:
        pool = []
        for row, lim in zip(grid, limits):
            row.sort(reverse=True)          # 行内降序
            pool.extend(row[:lim])          # 只留前 lim 大
        pool.sort(reverse=True)             # 池内降序
        return sum(pool[:k])                # 取前 k 大（k <= len(pool)）
```

## 8. 边界情况与易错点

1. **直接全局 top-k**（最常见 WA）：无视行配额取全局前 $k$ 大，示例 3 的 `[[10,9],[1,1]]` 直接错。必须先做行内裁剪。
2. **C++ 溢出**：答案上界 $500 \times 500 \times 10^5 = 2.5\times10^{10} > 2^{31}-1 \approx 2.1\times10^9$，累加器必须 `long long`（题目签名已固定返回 `long long`，中间变量别误用 `int`）。
3. **`limits[i] = 0` 的行**：一行一个候选都不出，循环 `for j in 0..limits[i]-1` 自然跳过，无需特判；但别写成「至少取 1 个」。
4. **`k = 0`**：答案为 0；取前 0 个的循环自然为空，`sum(pool[:0]) = 0` 天然正确。
5. **池越界风险**：`pool[:k]` 依赖题目保证 $k \le \sum\text{limits}[i]$；若改题目约束或写通用模板，用 `min(k, len(pool))` 防御。
6. **排序方向**：行内和池内都要**降序**。写成升序再 `pool[len-k:]` 也行，但两处方向不一致是调试地狱，统一 `rbegin()/rend()` 最稳。
7. **全 0 矩阵 / 答案为 0**：元素可全为 0，答案 0 与 $k=0$ 共用「累加器初始化为 0」的路径，无陷阱。
8. **原地排序修改输入**：LeetCode 允许；若在工程代码中复用，记得先拷贝，避免污染调用方数据。

**延伸思考**：① 若**元素可能为负**，「至多 $k$ 个」不再等价于「取满 $k$ 个」——沿降序池累加，遇负即停；② 若允许 $k > \sum\text{limits}[i]$，池会被取空，答案即全部候选之和，取 `min(k, len(pool))` 个即可；③ 若矩阵大到内存放不下池（流式输入），「每行 top-$\text{limits}[i]$ + 多路归并堆取前 $k$」可以只持 $O(n)$ 大小的堆完成；④ 行配额换成**列配额**（每列至多取 $c_j$ 个），对称地按列裁剪即可，证明逐字迁移。
