# LeetCode 镜像频次距离 题解

## 1. 题目概述

- **标题 / 题号**：镜像频次距离（#3889，medium）
- **链接**：https://leetcode.cn/problems/mirror-frequency-distance/
- **来源**：LeetCode 第 496 场周赛 Q1
- **难度**：中等
- **标签**：哈希表、字符串、计数

**题意**：给定仅由小写英文字母和数字组成的字符串 `s`。每个字符有唯一的**镜像字符**：字母按字母表逆序配对（`'a'↔'z'`、`'b'↔'y'`，……），数字按 `'0'..'9'` 逆序配对（`'0'↔'9'`、`'1'↔'8'`，……）。设 $\mathrm{freq}(x)$ 为字符 $x$ 在 `s` 中的出现次数。对 `s` 中每个**唯一**字符 $c$，设 $m$ 为其镜像字符，计算 $|\mathrm{freq}(c) - \mathrm{freq}(m)|$。镜像对 $(c, m)$ 与 $(m, c)$ 视为同一对，只计一次。返回所有**不同镜像对**的绝对差之和。

**约束**：

- $1 \le |s| \le 5 \times 10^5$
- `s` 仅由小写英文字母和数字组成

> 💡 **审题三个坑**：① $(c, m)$ 与 $(m, c)$ 是同一对——直译枚举会重复计算，必须去重；② 只要 $c$ 出现过，**即使镜像 $m$ 一次都没出现**，$|\mathrm{freq}(c) - 0|$ 也要计入；③ 字符集总共只有 36 种（26 字母 + 10 数字），暗示枚举主体应当是"字符集"而非"字符串"。

## 2. 示例

**示例 1**

```text
输入：s = "ab1z9"
输出：3
解释：(a,z): |1-1|=0，(b,y): |1-0|=1，(1,8): |1-0|=1，(9,0): |1-0|=1，
      答案 = 0 + 1 + 1 + 1 = 3。注意 y、8、0 都不在 s 中，但所在对仍贡献 1。
```

**示例 2**

```text
输入：s = "4m7n"
输出：2
解释：(4,5): |1-0|=1，(m,n): |1-1|=0，(7,2): |1-0|=1，答案 = 2。
```

**示例 3**

```text
输入：s = "byby"
输出：0
解释：唯一涉及的对是 (b,y): |2-2|=0，答案 = 0。
```

## 3. 解题思路

### 3.1 暴力思路：直译题面 + 去重集合

按题面直译：先用哈希表统计频次；再遍历 `s` 中出现的**唯一字符** $c$，查出镜像 $m$，累加 $|\mathrm{freq}(c) - \mathrm{freq}(m)|$。问题在于以"字符串中出现的字符"为枚举主体时，$(c, m)$ 与 $(m, c)$ 必然先后各被访问一次（如 `"az"` 中 `a` 和 `z` 互相指向），必须额外维护一个 `seen` 集合，以 $(\min(c, m), \max(c, m))$ 为 key 去重。

这样写是 $O(n)$、也能通过，但去重集合纯属"防御性记账"——它在补偿**枚举主体选错了**这一事实。Q1 的目标是把从题面到代码的路径压到最短，值得多想十秒钟换一个枚举主体。

### 3.2 核心观察：36 个字符对折成 18 个互不相交的镜像对

![核心观察：36 个字符对折成 18 个互不相交的镜像对](images/wc496_q1_mirror_pairs_concept.svg)

把枚举主体从"字符串"换成"字符集"，去重问题从源头消失。记 $\mathrm{mirror}(c)$ 为镜像映射：字母下标 $i$（`a` 记 0）的镜像是 $25 - i$，数字下标 $i$ 的镜像是 $9 - i$。三步看穿结构：

**观察一：镜射是无不动点的对合。** $\mathrm{mirror}(\mathrm{mirror}(c)) = c$（对合），且 $(97+122)/2 = 109.5$、$(48+57)/2 = 52.5$ 都不是整数，即**不存在自己配自己的字符**。无不动点的对合作用在集合上，恰好把集合划分成互不相交的二元对。

**观察二：36 个字符 = 恰好 18 对，不重不漏。** 字母折成 13 对（`a↔z, b↔y, …, m↔n`），数字折成 5 对（`0↔9, 1↔8, …, 4↔5`）。每对取**左端**作代表（字母取 `a..m`，数字取 `0..4`），枚举这 18 个代表即枚举了全部镜像对，$(c, m)$ 与 $(m, c)$ 的重复问题不复存在。

**观察三：两端都未出现的对贡献 0，可以放心全加。** 题目只统计"`s` 中出现过的字符"所在的对，但若 $c$ 与 $m$ 都不在 `s` 中，$|\mathrm{freq}(c) - \mathrm{freq}(m)| = |0-0| = 0$。所以**无需判断"这对是否在 s 中出现过"**，直接把 18 对全部求和，多加的都是 0。

> ⚠️ **一个易错写法**：遍历全部 36 个字符、对每个字符查镜像再累加——每对会被对称地加两次，得到答案的 2 倍，还需再除以 2。数值上能对，但"只枚举左端代表"的写法边界更少、意图更清晰。

### 3.3 算法流程

![算法流程：一趟计数 + 18 对求和](images/wc496_q1_algorithm_flow.svg)

整个算法 = 一趟 $O(n)$ 桶计数 + 恒定 18 次加法。没有排序、没有哈希集合、没有嵌套循环。

### 3.4 示例演算

以 `s = "ab1z9"` 为例，频次表：`a=1, b=1, 1=1, z=1, 9=1`，其余字符频次为 0。

![示例演算：ab1z9 逐对求绝对差](images/wc496_q1_example_walkthrough.svg)

| 镜像对 | freq(c) | freq(m) | 绝对差 | 备注 |
|--------|---------|---------|--------|------|
| (a, z) | 1 | 1 | 0 | 两端都出现 |
| (b, y) | 1 | 0 | 1 | `y` 不在 s 中，仍计入 |
| (1, 8) | 1 | 0 | 1 | `8` 不在 s 中 |
| (0, 9) | 0 | 1 | 1 | 只有右端 `9` 出现 |
| 其余 14 对 | 0 | 0 | 0 | 双零对，白加 0 |

合计 $0 + 1 + 1 + 1 = 3$，与示例一致。

## 4. 算法细节

1. **桶编码**：定长数组 `freq[36]`——字母存 `freq[c-'a']`（下标 0..25），数字存 `freq[26 + c-'0']`（下标 26..35）。字符集固定且稠密时数组完胜哈希表：下标直达、零哈希开销、缓存友好。
2. **字符分流**：数字的 ASCII（48..57）整体小于小写字母（97..122），一行 `c <= '9'` 即可完成判断——这依赖题面"仅小写字母与数字"的保证。
3. **镜像下标公式**：字母对 $i \leftrightarrow 25 - i$（$i = 0..12$）；数字对（桶下标）$26+i \leftrightarrow 35 - i$（$i = 0..4$，即字符 $i \leftrightarrow 9-i$）。
4. **免判断求和**：双零对贡献 $|0-0| = 0$，18 对全加无需任何"是否出现"的分支。
5. **累加器类型**：18 对 × 单对最大频次差 $5 \times 10^5$，答案上界 $9 \times 10^6$，`int` 绰绰有余。
6. **两段循环**：字母 13 对与数字 5 对分别一段循环，边界独立、互不干扰；也可用 `'a'+'z'-c` 这类字符运算统一求镜像，但分开写更不易错。

## 5. 正确性证明

**引理 1**（镜射是无不动点的对合）：设 $\sigma$ 为镜像映射。对字母下标 $i$ 有 $\sigma(i) = 25 - i$，故 $\sigma(\sigma(i)) = 25 - (25 - i) = i$；对数字下标同理 $\sigma(\sigma(i)) = 9 - (9 - i) = i$。若 $\sigma(c) = c$，则需 $2i = 25$（字母）或 $2i = 9$（数字），均无整数解，故不存在不动点。∎

**引理 2**（18 对划分）：在 36 个字符上定义关系 $c \sim d \iff d = \sigma(c)$。由引理 1 的对合性，$\sim$ 是等价关系；由无不动点，每个等价类的大小恰为 2。又因镜像字符与原字符同为字母或同为数字（两类字符集在 $\sigma$ 下各自封闭），26 个字母分成 13 对、10 个数字分成 5 对，共 18 对互不相交的二元对，覆盖全部 36 个字符。∎

**引理 3**（双零对零贡献）：若 $\mathrm{freq}(c) = \mathrm{freq}(m) = 0$，则 $|\mathrm{freq}(c) - \mathrm{freq}(m)| = |0 - 0| = 0$。∎

**定理**：所求答案等于

$$\sum_{i=0}^{12} \big|\mathrm{freq}[i] - \mathrm{freq}[25-i]\big| \;+\; \sum_{i=0}^{4} \big|\mathrm{freq}[26+i] - \mathrm{freq}[35-i]\big|$$

**证明**：题目所求为"至少一端在 `s` 中出现的镜像对"的贡献之和。由引理 2，18 个左端代表（`a..m` 与 `0..4`）与全部镜像对一一对应，故上式两个和式恰好遍历每个**不同**镜像对一次，不重不漏。对至少一端出现的对，其被累加的项即 $|\mathrm{freq}(c) - \mathrm{freq}(m)|$，与题目定义一致；对两端都未出现的对，由引理 3 多加 0，不改变总和。故等式成立。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描计数为 $O(n)$，随后恒定 $13 + 5 = 18$ 次加法，总计 $O(n + 36) = O(n)$。
- **空间复杂度**：$O(36) = O(1)$。仅一个固定大小的计数桶数组，与 $n$ 无关。
- **答案上界**：$18 \times 5 \times 10^5 = 9 \times 10^6 < 2^{31} - 1$，32 位 `int` 不会溢出。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int mirrorFrequency(string s) {
        int freq[36] = {0};                 // 0~25: 'a'..'z'，26~35: '0'..'9'
        for (char c : s) {
            if (c <= '9') freq[26 + (c - '0')]++;
            else          freq[c - 'a']++;
        }
        int ans = 0;
        for (int i = 0; i < 13; ++i)        // a..m ↔ z..n，字母 13 对
            ans += abs(freq[i] - freq[25 - i]);
        for (int i = 0; i < 5; ++i)         // 0..4 ↔ 9..5，数字 5 对
            ans += abs(freq[26 + i] - freq[35 - i]);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def mirrorFrequency(self, s: str) -> int:
        freq = [0] * 36                      # 0~25: a..z，26~35: 0..9
        for c in s:
            if c.isdigit():
                freq[26 + int(c)] += 1
            else:
                freq[ord(c) - ord('a')] += 1

        ans = 0
        for i in range(13):                  # a..m ↔ z..n，字母 13 对
            ans += abs(freq[i] - freq[25 - i])
        for i in range(5):                   # 0..4 ↔ 9..5，数字 5 对
            ans += abs(freq[26 + i] - freq[35 - i])
        return ans
```

> 💡 Python 的计数部分也可用 `collections.Counter(s)` 一行完成，再按 18 个代表取 `cnt.get(chr(...), 0)`；$n = 5 \times 10^5$ 时两种写法都在几十毫秒量级，随意选择。

## 8. 边界情况与易错点

1. **镜像未出现也计入**：`freq(m) = 0` 时 $|\mathrm{freq}(c) - 0|$ 照算（示例 1 的 `b↔y`，`y` 根本不在串里）——漏掉这一点会得到错误答案 2。
2. **$(c, m)$ 与 $(m, c)$ 重复计数**：直译"遍历出现过的字符"每对会算两次；用左端代表枚举从根上避免。若坚持遍历全部 36 个字符累加，结果是答案的 2 倍，须除以 2。
3. **不要写 36×36 双重循环找对**：虽然 $36^2 = 1296$ 是常数也能过，但去重逻辑更绕、意图更模糊。
4. **分流判断依赖字符集保证**：`c <= '9'` 只在"仅小写字母与数字"前提下成立；若输入可能含大写或符号，应改用 `isdigit` 显式判断。
5. **数字镜像下标勿与字母混淆**：数字镜像的桶下标是 $35 - (26+i) = 9 - i$（桶内相对下标），别把字母的 $25 - i$ 误用到数字区。
6. **单字符输入**：`s = "a"` 时唯一涉及对 `(a, z)` 贡献 $|1-0| = 1$，返回 1，无需特判。
7. **溢出**：答案上界 $9 \times 10^6$，`int` 足够，不需要 `long long`；但把约束改成 $10^{18}$ 级别时须重新评估累加器类型。
8. **频次表别用 `map<string, int>` 之类**：字符键定长 36，定长数组是最优容器选择。
