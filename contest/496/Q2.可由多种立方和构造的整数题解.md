# LeetCode 可由多种立方和构造的整数 题解

## 1. 题目概述

- **标题 / 题号**：可由多种立方和构造的整数（#3890，medium）
- **链接**：https://leetcode.cn/problems/integers-with-multiple-sum-of-two-cubes/
- **来源**：LeetCode 第 496 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、计数、枚举、排序

**题意**：给定整数 $n$。若整数 $x$ 存在**至少两组不同的**整数对 $(a, b)$ 满足：$a, b$ 均为正整数、$a \le b$、$x = a^3 + b^3$，则称 $x$ 为**好整数**。返回所有 $\le n$ 的好整数，按升序排列。

**约束**：

- $1 \le n \le 10^9$

> 💡 **背景彩蛋**：这类数正是数论里大名鼎鼎的 **Taxicab 数**（的士数）——1917 年哈代乘出租车探望病中的拉马努金，随口说车牌号 $1729$ 很无趣，拉马努金脱口而出：**"不，它是能用两种方式写成两立方和的最小正整数。"** 本题要求的就是 $n \le 10^9$ 范围内的全部"二当面"（及以上）整数。

## 2. 示例

**示例 1**

```text
输入：n = 4104
输出：[1729, 4104]
解释：1729 = 1³ + 12³ = 9³ + 10³
      4104 = 2³ + 16³ = 9³ + 15³
```

**示例 2**

```text
输入：n = 578
输出：[]
解释：不存在小于等于 578 的好整数（最小的好整数是 1729）。
```

**示例 3**

```text
输入：n = 20000
输出：[1729, 4104, 13832]
解释：13832 = 2³ + 24³ = 18³ + 20³
```

## 3. 解题思路

### 3.1 暴力思路：逐个 x 判断

最直白的翻译：对每个 $x \in [1, n]$，枚举 $a$ 检查 $x - a^3$ 是否为立方数、统计表示组数是否 $\ge 2$。单次判断 $O(n^{1/3})$，总量 $O(n \cdot n^{1/3})$——$n = 10^9$ 时光是遍历候选 $x$ 就要 $10^9$ 步，完全不可行。

症结在于**枚举主体选错了**：值域 $[1, n]$ 里有 $10^9$ 个数，但其中绝大多数根本**不是**任何 $a^3 + b^3$（两立方和数在 $[1, x]$ 内只有 $\Theta(x^{2/3})$ 个）。逐个询问"x 是不是好整数"，等于在一片几乎全空的池子里打捞。

### 3.2 核心观察：枚举对而非枚举数，值域坍缩到 1000

![好整数：同一个数的两副立方面孔](images/wc496_q2_taxicab_concept.svg)

把枚举主体从"数 $x$"换成"对 $(a, b)$"，结构立刻改观。三步看穿：

**观察一：$a, b$ 的上界被 $n$ 钉死在 1000。** 若 $x = a^3 + b^3 \le n \le 10^9$，则 $a^3 \le x \le 10^9$，故 $a \le \lfloor n^{1/3} \rfloor \le 1000$；$b$ 同理。合法的 $(a, b)$ 全部落在 $1000 \times 1000$ 的网格内。

**观察二：$a \le b$ 把网格砍掉一半。** $(a, b)$ 与 $(b, a)$ 生成同一个和，只算一组——枚举对角线一侧即可，每个**无序对**恰好被访问一次。

**观察三：剪掉 $a^3 + b^3 > n$ 的角落后，只剩约 44 万个点。** 有效点数

$$m = \#\{(a,b) : 1 \le a \le b,\ a^3 + b^3 \le n\} = \Theta(n^{2/3})$$

（把 $a, b$ 缩放 $n^{1/3}$ 倍后区域形状固定，点数 $\sim$ 面积 $\sim n^{2/3}$）。$n = 10^9$ 时实测 $m = 441521$——从 $10^9$ 坍缩到 $4.4 \times 10^5$，直接能枚举。

![枚举空间：a ≤ b 且 a³ + b³ ≤ n 的整点](images/wc496_q2_enumeration_region.svg)

### 3.3 算法流程：让每个和"自己报到"

![算法流程：枚举对 → 哈希计数 → 收集排序](images/wc496_q2_algorithm_flow.svg)

枚举所有合法对，用**哈希表**给每个和 $s$ 计数；最后把计数 $\ge 2$ 的 $s$ 收集起来排序输出。

```text
cnt ← 空哈希表
for a = 1, 2, …（2a³ > n 时终止）:
    for b = a, a+1, …（a³+b³ > n 时 break）:
        cnt[a³+b³] += 1
ans ← 排序{ s : cnt[s] ≥ 2 }
```

> ⚠️ **计数与收集必须分开两趟**：不能在计数途中发现 $\mathrm{cnt}[s] \ge 2$ 就立刻输出——一是哈希表遍历无序，二是后续对还可能再报（如 $87539319$ 报到 3 次），"第二次出现即输出"若无集合配合会重复入列。先计数后收集，一切自然。

### 3.4 示例演算：n = 4104

枚举产生的哈希表共 **110 个**不同的和（总对数 112，其中两个和各被报到两次），绝大多数只报到一次：

| 和 $s$ | 报到的对 $(a, b)$ | $\mathrm{cnt}[s]$ | 好整数？ |
|--------|------------------|------------------|----------|
| $2$ | $(1, 1)$ | 1 | ✗ |
| $16$ | $(2, 2)$ | 1 | ✗ |
| $1729$ | $(1, 12)$、$(9, 10)$ | **2** | ✓ |
| $4104$ | $(2, 16)$、$(9, 15)$ | **2** | ✓ |
| 其余 106 个和 | 各一组 | 1 | ✗ |

收集计数 $\ge 2$ 的键并排序，得 $[1729, 4104]$，与示例 1 一致。

## 4. 算法细节

1. **外层终止条件 $2a^3 > n$**：由 $b \ge a$ 知 $s = a^3 + b^3 \ge 2a^3$，一旦 $2a^3 > n$，更大的 $a$ 不可能再产生合法对，外层直接停。
2. **内层 break 的单调性依据**：固定 $a$ 时 $s = a^3 + b^3$ 随 $b$ 严格递增，故首个 $s > n$ 的 $b$ 之后全部非法，`break` 而非 `continue`。
3. **哈希表而非数组**：$s$ 的值域到 $10^9$，定长数组开不下；键就是和本身，`unordered_map<long long, int>` / `dict` 即可。
4. **C++ 用 `long long` 做中间量**：$a^3 + b^3 \le 10^9$ 虽未超 `int`，但内层 `b` 会先自增到出界再判断（$1001^3 \approx 1.003 \times 10^9$ 仍在 `int` 内，再往上就可能溢出），统一 `long long` 免去所有边界心智负担。
5. **去重的实现位置**：收集阶段遍历哈希表的**键**，键天然互不相同——$87539319$ 计数到 3 也只进答案一次；$a \le b$ 则保证 $(a,b)$、$(b,a)$ 不被当成两组（这是正确性问题，不是优化）。
6. **排序放在最后**：好整数个数最多 $O(m)$，实测 $n = 10^9$ 时仅 1554 个，排序开销可忽略。

## 5. 正确性证明

**引理 1**（候选对有界）：若正整数对 $(a, b)$ 满足 $a \le b$ 且 $a^3 + b^3 \le n$，则 $1 \le a \le b \le \lfloor n^{1/3} \rfloor$。

**证明**：$b \ge a \ge 1$，故 $1 \le a^3 \le a^3 + b^3 \le n$，得 $a \le n^{1/3}$，即 $a \le \lfloor n^{1/3} \rfloor \le 1000$；又 $b^3 \le a^3 + b^3 \le n$，同理 $b \le \lfloor n^{1/3} \rfloor$。∎

**引理 2**（每对恰计一次）：按 "$1 \le a \le b$ 且 $a^3 + b^3 \le n$" 枚举，任意满足题意的无序对 $\{a, b\}$ 在枚举序列中恰好出现一次。

**证明**：对满足题意的对 $(a, b)$（$a \le b$），它是枚举循环 $(a, b)$ 的一个取值，至少出现一次；反之枚举的每个取值都满足 $a \le b$。交换得到的 $(b, a)$ 因 $b \ge a$ 不满足枚举条件 $a \le b$（$a \ne b$ 时），不会被枚举到；$a = b$ 时两者本来就是同一个有序对。故无序对与枚举取值一一对应，恰计一次。∎

**引理 3**（剪枝不漏）：外层条件 $2a^3 \le n$ 与内层条件 $a^3 + b^3 \le n$ 联合覆盖了全部合法对。

**证明**：合法对满足 $s = a^3 + b^3 \le n$ 且 $b \ge a$，则 $2a^3 \le a^3 + b^3 = s \le n$，故该对的 $a$ 未越过外层终止线；又 $a^3 + b^3 \le n$ 使内层在该 $b$ 处未 break。因此每个合法对都被访问。∎

**定理**：算法输出集合恰为 $\{x \le n : x \text{ 是好整数}\}$，且升序、无重复。

**证明**：

（⊆）设 $x$ 被输出，则 $\mathrm{cnt}[x] \ge 2$。由引理 2，每次计数对应一个**互不相同的**有序对 $(a_i, b_i)$，故存在至少两组不同对满足正整数、$a \le b$、和为 $x \le n$，即 $x$ 是好整数。

（⊇）设 $x \le n$ 是好整数，则存在两组不同对均满足题意与 $x = a^3 + b^3 \le n$。由引理 1 两组对都在枚举范围内，由引理 3 不会被剪枝漏掉，由引理 2 各恰好贡献一次计数，故 $\mathrm{cnt}[x] \ge 2$，$x$ 被收集。

收集遍历哈希表的键，键互异保证无重复；收集后排序保证升序。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^{2/3})$。枚举 $m = \Theta(n^{2/3})$ 个对（$n = 10^9$ 时 $m \approx 4.4 \times 10^5$），每对一次哈希计数 $O(1)$；对好整数（$n = 10^9$ 时仅 1554 个）排序 $O(g \log g)$，低于枚举开销。
- **空间复杂度**：$O(n^{2/3})$。哈希表最多存 $m$ 个不同的键。
- **实测**：Python 纯解释执行 $n = 10^9$ 约 0.14 秒，C++ 毫秒级。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> findGoodIntegers(int n) {
        unordered_map<long long, int> cnt;
        for (long long a = 1; 2 * a * a * a <= n; ++a) {
            long long a3 = a * a * a;
            for (long long b = a; a3 + b * b * b <= n; ++b)
                ++cnt[a3 + b * b * b];          // 每个和“报到”一次
        }
        vector<int> ans;
        for (auto& [s, c] : cnt)
            if (c >= 2) ans.push_back((int)s);  // 键天然去重
        sort(ans.begin(), ans.end());
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findGoodIntegers(self, n: int) -> list[int]:
        cnt = Counter()
        a = 1
        while 2 * a * a * a <= n:
            a3 = a * a * a
            b = a
            while a3 + b * b * b <= n:
                cnt[a3 + b * b * b] += 1        # 每个和“报到”一次
                b += 1
            a += 1
        return sorted(s for s, c in cnt.items() if c >= 2)
```

> 💡 Python 内层若想用 `for b in range(a, icbrt(n - a3) + 1)` 提速，注意浮点立方根 `(n - a3) ** (1/3)` 在边界可能差 1，必须做 `±1` 校正回整数；纯 `while` 写法全整数运算，稳。

## 8. 边界情况与易错点

1. **漏写 $a \le b$**：把 $(a, b)$、$(b, a)$ 当成两组不同表示，几乎所有两立方和数都会被判为好整数——这是正确性级错误，不是优化项。
2. **输出重复**：$87539319 = 167^3 + 436^3 = 228^3 + 423^3 = 255^3 + 414^3$ 有**三组**表示（$\mathrm{Ta}(3)$ 就在本题值域内！），若用"报到第二次就加入答案"的写法必须配集合去重；遍历哈希键收集则天然安全。
3. **忘记排序**：`unordered_map` / `dict` 遍历顺序无序，收集后必须 `sort`。
4. **$n < 1729$ 输出空数组**：最小好整数是 $1729$，小 $n$ 直接返回 `[]`，无需特判，循环自然为空。
5. **溢出（C++）**：中间量 `b * b * b` 在 `b` 越界一步时约 $1.003 \times 10^9$，未超 `int` 但已贴线；统一 `long long` 最稳。
6. **不要逐个 $x$ 判断**：$n = 10^9$ 时值域本身遍历不完——枚举主体必须换成 $(a, b)$ 对。
7. **内层必须 `break` 不能 `continue`**：固定 $a$ 时 $s$ 随 $b$ 单调增，越过 $n$ 后不可能回头，`continue` 会白扫到 $b \le 1000$。
8. **Python 浮点立方根精度**：`round(x ** (1/3))` 可能差 1，需整数校正；本题纯 `while` 递增即无此坑。

**延伸思考**：

- **$n$ 放大到 $10^{18}$ 怎么办**：$m = \Theta(n^{2/3}) = 10^{12}$ 不可行。注意到固定 $a$ 时 $a^3 + b^3$（$b = a, a+1, \dots$）是递增序列，共 $n^{1/3}$ 条有序流——**多路归并 / 最小堆**弹堆，相同值连弹即可发现所有重复，可把空间压到 $O(n^{1/3})$，但时间仍是 $O(n^{2/3} \log)$ 级别；更快的 Taxicab 数搜索是数论与高性能计算的经典课题。
- **Taxicab 数谱系**：$\mathrm{Ta}(2) = 1729$（拉马努金），$\mathrm{Ta}(3) = 87539319$，$\mathrm{Ta}(4) = 6963472309248$（1991 年由 N. D. Elkies 发现），$\mathrm{Ta}(5)$、$\mathrm{Ta}(6)$ 由 Caltech 团队于 2002 年前后算出——$k$ 组表示的最小数随 $k$ 指数级膨胀。
- **为什么好整数这么稀**：约 $4.4 \times 10^5$ 个和撒进 $10^9$ 的值域，平均每个值仅被击中 $0.44$ 次，"二次命中"是**生日悖论**式的小概率事件——实测 $n = 10^9$ 时恰好 1554 个，与 $m^2 / 2n \sim 10^2$ 的均匀模型同数量级偏上（小和处表示密度更高，碰撞更集中）。
- **变体练习**：把 $a^3 + b^3$ 换成 $a^2 + b^2$（两平方和定理刻画了哪些数可表示）、$a^2 + 2b^2$ 等二次型，或允许 $a = 0$，各自的重 counting 策略如何变化？
