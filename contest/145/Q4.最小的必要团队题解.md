# LeetCode 最小的必要团队 题解

## 1. 题目概述

- **标题 / 题号**：最小的必要团队（#1125，hard）
- **链接**：https://leetcode.cn/problems/smallest-sufficient-team/
- **来源**：LeetCode 第 145 场周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、动态规划、状态压缩（Bitmask DP）

**题意**：给定互不相同的需求技能清单 `req_skills`，以及 $n$ 位备选人员，`people[i]` 是第 $i$ 个人掌握的技能列表（每个技能都来自清单）。选出一个**人数最少**的人员子集，使团队掌握的技能并集覆盖清单中的**每一项**技能，返回这些人的编号（顺序任意，答案可能不唯一）。

**约束**：

- $1 \le m = \lvert req\_skills \rvert \le 16$，技能名长度 $\le 16$，互不相同
- $1 \le n = \lvert people \rvert \le 60$
- $0 \le \lvert people[i] \rvert \le 16$，同一个人的技能互不相同，且都属于 `req_skills`
- 数据保证「必要团队」一定存在

## 2. 示例

**示例 1**

```text
输入：req_skills = ["java","nodejs","reactjs"]
     people = [["java"], ["nodejs"], ["nodejs","reactjs"]]
输出：[0,2]
解释：0 号会 java，2 号会 nodejs 与 reactjs，两人覆盖三项技能；
      任何单人都不覆盖全部技能，故规模 2 最优。
```

**示例 2**

```text
输入：req_skills = ["algorithms","math","java","reactjs","csharp","aws"]
     people = [["algorithms","math","java"], ["algorithms","math","reactjs"],
               ["java","csharp","aws"],        ["reactjs","csharp"],
               ["csharp","math"],              ["aws","java"]]
输出：[1,2]
解释：1 号给 algorithms/math/reactjs，2 号给 java/csharp/aws，恰好 2 人覆盖全部 6 项；
      不存在单身能覆盖全部技能的人，故最优规模为 2。
```

**边界用例（补充自测，非官方示例）**

```text
输入：req_skills = ["a","b"], people = [[], ["a"], ["b"]]
输出：[1,2]
解释：0 号没有技能，选它只会浪费名额；必须由 1 号与 2 号各补一项。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举「人的子集」：每个人选或不选，共 $2^n$ 种方案。$n \le 60$ 时 $2^{60} \approx 10^{18}$，即使只按人数从小到大枚举组合数 $\binom{60}{k}$ 也早已爆炸。

换个角度看，答案真正关心的是**哪些技能已经被覆盖**，而不是「选了哪些人」。题目特意把技能数压到 $m \le 16$，提示我们把状态从「人的集合」换成「技能的覆盖情况」。

### 3.2 核心观察：把技能集合编码成整数掩码

![技能集合编码成位掩码](images/wc145_q4_skill_mask.svg)

给每项技能分配一个二进制位（第 $i$ 项技能对应 $1 \ll i$），那么：

- 一个人的技能表就是一个整数掩码 $\text{skill}[i]$；
- 一个团队的覆盖情况就是成员掩码的**按位或**；
- 目标状态是 $full = (1 \ll m) - 1$，即低 $m$ 位全为 $1$。

于是状态空间从 $2^{60}$ 骤降到 $2^m \le 65536$，而 $n \le 60$ 只出现在「每次转移枚举一个人」的代价里：

$$\text{转移总数} \le 2^{16} \times 60 \approx 3.9 \times 10^{6}$$

完全可行。这就是本题的**状态压缩**动机：用 $m$ 位二进制数代替「人的子集」。

### 3.3 算法流程：在掩码上做最短路式 DP

![位掩码 DP 四个步骤](images/wc145_q4_mask_dp_flow.svg)

**状态**：`dp[mask]` = 覆盖技能集合 `mask` 所需的**最少人数**。

**初值**：`dp[0] = 0`，其余为 $\infty$（不可达）。

**转移**：对当前状态 `mask` 与每个人 $i$，令 `nxt = mask | skill[i]`，则

$$\text{dp}[nxt] = \min\bigl(\text{dp}[nxt],\ \text{dp}[mask] + 1\bigr)$$

同时记录 `preMask[nxt] = mask`、`prePerson[nxt] = i`，供最后回溯重建团队。

**遍历顺序**：`mask` 从 $0$ 递增到 $full$ 单趟扫描即可。因为 `nxt` 是在 `mask` 上**只增不减**地置位，所以 $nxt \ge mask$（数值意义），任何 `nxt` 的最终值只会由更小的 `mask` 推出，数值递增天然是拓扑序，不需要 0/1 背包的逆序写法。

**答案**：从 `full` 沿 `pre` 指针一路回溯到 $0$，收集每次的 `prePerson`，再反转即得人数递增的编号序列。

### 3.4 示例演算

以示例 1 为例，$m = 3$：`java = 001`、`nodejs = 010`、`reactjs = 100`，三个人分别是 `p0 = 001`、`p1 = 010`、`p2 = 110`，目标 `full = 111`。

| mask | 已覆盖技能 | dp | 由谁转移 |
|------|------------|----|----------|
| 000 | （空） | 0 | 初始 |
| 001 | java | 1 | 000 + 0 号 |
| 010 | nodejs | 1 | 000 + 1 号 |
| 110 | nodejs, reactjs | 1 | 000 + 2 号 |
| 011 | java, nodejs | 2 | 001 + 1 号 |
| 111 | java, nodejs, reactjs | 2 | 001 + 2 号 |

![示例 1 的 DP 演算表](images/wc145_q4_walkthrough.svg)

`dp[111] = 2`，回溯链 $111 \leftarrow 001 \leftarrow 000$，得到团队 `[0, 2]`。注意从 `110` 再加 0 号同样能到 `111`（dp 也是 2），说明**最优答案不唯一**，与题目「返回任一」的约定一致。

## 4. 算法细节

1. **技能编号**：用哈希表 `idx[skill] = i` 把技能名映射到 $0 \sim m-1$；之后所有比较都只涉及整数位运算，避免字符串开销。
2. **人员掩码预处理**：对每个人遍历其技能列表，`skill[p] |= 1 << idx[s]`。预处理是 $O(\sum \lvert people[i] \rvert) \le O(16n)$，与 DP 相比可忽略。若某技能不在清单中（本题不会出现），跳过即可。
3. **空掩码与无新增位直接跳过**：若 `skill[i] == 0`，或 `(mask | skill[i]) == mask`（这个人不能带来任何新技能），则该转移只会原地打转或浪费名额，直接 `continue`。这一步不是正确性所必需，但能显著减少无效转移。
4. **可选剪枝——删除被支配的人**：若存在 $j$ 使 `skill[i] | skill[j] == skill[j]`（即 $i$ 会的技能 $j$ 都会），则 $i$ 在最优解中可以被 $j$ 顶替，直接删掉 $i$ 不改变答案。它能把 $n$ 从 60 压到更小，做法见「延伸思考」。
5. **重建方式**：`preMask` 与 `prePerson` 各开一个长度 $2^m$ 的数组，转移成功时同步写入。回溯时每步掩码的置位数严格减少，因此最多循环 $m \le 16$ 次，不会死循环。
6. **遍历顺序的严格理由**：`nxt = mask | skill[i]` 只在 `mask` 的基础上置 1，故 $nxt \ge mask$（二进制数值单调不减），且 $nxt = mask$ 的情况已被剪掉，所以每条转移都从小掩码指向大掩码——这正是拓扑序，单趟递增扫描即可收敛。
7. **位宽**：$m \le 16$ 时 `1 << 15` 等于 $32768$，$full \le 65535$，`int` 足够；不需要 `long long`，但要注意 `1 << i` 中 `i` 的类型别写成负数。

## 5. 正确性证明

**引理 1（可达状态都对应一个合法团队）**：若 $\text{dp}[mask] < \infty$，则存在规模恰为 $\text{dp}[mask]$ 的人员团队，其技能并集覆盖 $mask$。

**证明**：对转移次数归纳。$\text{dp}[0] = 0$ 由空团队实现，成立。设 $\text{dp}[mask] = k$ 由某次转移 $\text{dp}[mask'] + 1 = k$ 得到，其中 $mask = mask' \mid \text{skill}[i]$。由归纳假设，存在规模 $k-1$ 的团队 $T'$ 覆盖 $mask'$；令 $T = T' \cup \{i\}$，则 $T$ 规模为 $k$，且其并集覆盖 $mask' \mid \text{skill}[i] = mask$。∎

**引理 2（最优团队不会错过 DP 值）**：对任意覆盖 $mask$ 的团队 $T$，都有 $\text{dp}[mask] \le \lvert T \rvert$。

**证明**：对 $\lvert T \rvert$ 归纳。$\lvert T \rvert = 0$ 时 $mask = 0$，$\text{dp}[0] = 0$，成立。设 $\lvert T \rvert = k > 0$ 且 $T$ 覆盖 $mask$，取其中一人 $i$，令 $T' = T \setminus \{i\}$、$mask' = \text{OR}(T')$，则 $mask' \mid \text{skill}[i] = mask$。由归纳假设 $\text{dp}[mask'] \le k-1$；只要 $mask' \ne mask$，转移就给出 $\text{dp}[mask] \le \text{dp}[mask'] + 1 \le k$。若 $mask' = mask$，说明去掉 $i$ 后 $T'$ 仍覆盖 $mask$，即 $T$ 含冗余成员、不是最小团队；把 $T$ 换成 $T'$ 后规模更小，故对最小团队必有 $mask' \ne mask$，结论成立。∎

**引理 3（回溯链合法）**：从 $full$ 出发沿 `preMask` 指针必在有限步内到达 $0$，且沿途收集的人员编号互不相同。

**证明**：每次转移都有 $\text{preMask}[nxt] = mask$ 且 $nxt \ne mask$，而 $nxt$ 是在 $mask$ 上额外置位得到的，故 $\text{popcount}(mask) < \text{popcount}(nxt)$。回溯时置位数沿链严格递减且非负，最多 $m$ 步就到达置位数为 $0$ 的状态，即 $0$。又因为同一个人 $i$ 若被第二次选中，必然已有 $\text{skill}[i] \subseteq mask$，该转移因 $nxt = mask$ 被剪枝跳过，故一条链上编号不会重复。∎

**定理**：算法返回的团队合法（覆盖全部技能）且规模最小。

**证明**：设最优团队为 $T^*$，由引理 2 得 $\text{dp}[full] \le \lvert T^* \rvert$；由引理 1 又知存在规模 $\text{dp}[full]$ 的合法团队，故 $\lvert T^* \rvert \le \text{dp}[full]$。两者合并得 $\text{dp}[full] = \lvert T^* \rvert$，即 DP 值就是最小规模。由引理 3，回溯链在有限步内到达 $0$，且每一步都把对应人员的技能并进前驱状态，最终恰好构造出 $full$；因此返回的团队覆盖全部技能，规模等于 $\text{dp}[full]$，是最优解。∎

## 6. 复杂度分析

- **时间**：$O(2^m \cdot n)$。外层枚举 $2^m$ 个掩码，内层枚举 $n$ 个人，每次转移是常数次位运算；预处理 $O(\sum \lvert people[i] \rvert)$，回溯 $O(m)$。代入上限约为 $65536 \times 60 \approx 3.9 \times 10^{6}$ 次转移。
- **空间**：$O(2^m)$。`dp`、`preMask`、`prePerson` 三个长度 $2^m + 1$ 的数组；人员掩码数组为 $O(n)$。$m = 16$ 时约 $3 \times 65536$ 个整数，几 MB 以内。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<int> smallestSufficientTeam(vector<string>& req_skills, vector<vector<string>>& people) {
        int m = req_skills.size();
        unordered_map<string, int> idx;
        for (int i = 0; i < m; i++) idx[req_skills[i]] = i;

        // 预处理：把每个人的技能表压缩成 m 位掩码
        vector<int> skill(people.size(), 0);
        for (size_t p = 0; p < people.size(); p++)
            for (const string& s : people[p]) {
                auto it = idx.find(s);
                if (it != idx.end()) skill[p] |= 1 << it->second;
            }

        int full = (1 << m) - 1;
        const int INF = 1e9;
        vector<int> dp(full + 1, INF), preMask(full + 1, -1), prePerson(full + 1, -1);
        dp[0] = 0;

        // mask 递增即为拓扑序：nxt = mask | skill[i] >= mask
        for (int mask = 0; mask <= full; mask++) {
            if (dp[mask] == INF) continue;
            for (size_t i = 0; i < skill.size(); i++) {
                int nxt = mask | skill[i];
                if (nxt == mask) continue;          // 不带来任何新技能
                if (dp[mask] + 1 < dp[nxt]) {
                    dp[nxt] = dp[mask] + 1;
                    preMask[nxt] = mask;
                    prePerson[nxt] = (int)i;
                }
            }
        }

        // 回溯重建
        vector<int> team;
        for (int cur = full; cur > 0; cur = preMask[cur]) team.push_back(prePerson[cur]);
        reverse(team.begin(), team.end());
        return team;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def smallestSufficientTeam(self, req_skills: List[str], people: List[List[str]]) -> List[int]:
        m = len(req_skills)
        idx = {s: i for i, s in enumerate(req_skills)}

        # 预处理：每个人的技能表 -> m 位掩码
        skill = []
        for skills in people:
            mask = 0
            for s in skills:
                if s in idx:                     # 题面保证技能都来自清单，这里防御性判断
                    mask |= 1 << idx[s]
            skill.append(mask)

        full = (1 << m) - 1
        INF = 10 ** 9
        dp = [INF] * (full + 1)                  # dp[mask] = 覆盖 mask 的最少人数
        pre_mask = [-1] * (full + 1)
        pre_person = [-1] * (full + 1)
        dp[0] = 0

        for mask in range(full + 1):             # 递增遍历即拓扑序
            if dp[mask] == INF:
                continue
            for i, s in enumerate(skill):
                nxt = mask | s
                if nxt == mask:                  # 空技能 / 不带来新技能
                    continue
                if dp[mask] + 1 < dp[nxt]:
                    dp[nxt] = dp[mask] + 1
                    pre_mask[nxt] = mask
                    pre_person[nxt] = i

        team = []
        cur = full
        while cur > 0:
            team.append(pre_person[cur])
            cur = pre_mask[cur]
        team.reverse()
        return team
```

## 8. 边界情况与易错点

1. **重建循环的条件**：写成 `while cur:` 时，若某个测试数据无解（本题保证不会），`pre_mask[full]` 仍是 $-1$，`cur = -1` 为真值，会拿负下标索引数组而死循环。写成 `while cur > 0` 更安全，且不影响合法数据的语义。
2. **空技能人员**：`people[i] == []` 压缩后掩码为 $0$，应在转移前跳过。虽然 $\text{dp}[mask] + 1 < \text{dp}[mask]$ 恒不成立、它不会被真正选进团队，但它会让每个人白白多扫 $2^m$ 个状态。上面的边界用例专门覆盖这一点。
3. **答案不唯一**：多数数据存在多个最优团队（示例 1 中从 `110` 补 0 号也能得到同等规模解）。本地对拍与线上判题都只能比较**规模**与**覆盖性**，不能逐位比较输出数组。
4. **不能贪心「每次选新增技能最多的人」**：取 `req_skills = [a,b,c,d,e,f]`、`people = [[a,b,c,d],[a,b,e],[c,d,f]]`，贪心先选覆盖 4 项的 0 号，还得再补 1 号（给 e）与 2 号（给 f），共 3 人；而 1 号 + 2 号只需 2 人。集合覆盖没有贪心最优性，必须用 DP 枚举全部状态。
5. **重复选择同一人**：DP 允许从同一状态反复用同一个人，但 `nxt == mask` 的剪枝会拦掉它；即使不拦，`dp[mask] + 1 < dp[mask]` 也不成立，不会造成错误，只是白跑。
6. **位运算优先级**：`mask | skill[i] == mask` 这种写法在 C++ 里会被解析成 `mask | (skill[i] == mask)`（`==` 优先级高于 `|`），必须写成 `(mask | skill[i]) == mask`。
7. **数组大小**：$full + 1 = 2^m$，$m = 16$ 时为 $65536$；若把 `1 << m` 写成 `1 << (m + 1)` 之类会浪费一半空间但不会错，真正的坑是 $m = 0$（本题 $m \ge 1$）时 $full = 0$、答案为空数组。

**延伸思考**：

1. **被支配人员的剪枝**：若 `skill[i] | skill[j] == skill[j]`，则任何含 $i$ 的团队把 $i$ 换成 $j$ 仍然合法且人数不变，因此可以删掉 $i$。实现上对每对人做一次 $O(n^2)$ 检查，把 $n$ 从 60 降到有效人数，DP 常数更小。
2. **字典序最小的最优团队**：把 `dp` 换成「先比人数、再比编号序列字典序」的二元组比较，或按编号从大到小枚举人员并优先保留小编号，即可在同样复杂度内得到确定性的最小解。
3. **人数上限版本**：若题目改成「最多 $k$ 人能否覆盖全部技能」，只需把 `dp[mask]` 换成「恰好用 $j$ 人的可达掩码集合」，即多一维 $O(k \cdot 2^m)$ 的布尔 DP。
