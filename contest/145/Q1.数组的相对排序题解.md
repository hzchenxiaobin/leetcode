# LeetCode 数组的相对排序 题解

## 1. 题目概述

- **标题 / 题号**：数组的相对排序（#1122，easy）
- **链接**：https://leetcode.cn/problems/relative-sort-array/
- **来源**：LeetCode 第 145 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数排序、排序

**题意**：给定 `arr1` 与 `arr2`，其中 `arr2` 的元素**互不相同**，且 `arr2` 的每个元素都出现在 `arr1` 中。要求重排 `arr1`，使得：出现在 `arr2` 中的元素**按 `arr2` 的顺序**成段排列（同一个值出现多次要连在一起），没在 `arr2` 中出现的元素**按升序**全部放在末尾。

**约束**：

- $1 \le \lvert \text{arr1} \rvert, \lvert \text{arr2} \rvert \le 1000$
- $0 \le \text{arr1}[i],\ \text{arr2}[i] \le 1000$
- `arr2` 中元素互不相同
- `arr2[i]` 一定出现在 `arr1` 中

> 💡 值域只有 $0 \sim 1000$，而长度也只有 $1000$：这题**任何 $O(n \log n)$ 的做法都能过**，但值域这么小，正确姿势是**计数**——把「排序」问题降级成「按值查表」。

## 2. 示例

**示例 1**

```text
输入：arr1 = [2,3,1,3,2,4,6,7,9,2,19], arr2 = [2,1,4,3,9,6]
输出：[2,2,2,1,4,3,3,9,6,7,19]
解释：arr2 规定顺序 2 → 1 → 4 → 3 → 9 → 6；
      2 出现 3 次、3 出现 2 次，同值必须连成一段；
      7、19 不在 arr2 中，升序追加到末尾。
```

**示例 2**

```text
输入：arr1 = [28,6,22,8,44,17], arr2 = [22,28,8,6]
输出：[22,28,8,6,17,44]
解释：前段严格按 arr2 的 22→28→8→6 排列，
      剩余 17、44 升序排在后面。
```

**示例 3**（边界，可自测）

```text
输入：arr1 = [3,3,3], arr2 = [3]
输出：[3,3,3]
解释：arr2 覆盖了 arr1 的全部取值，尾部为空。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的模拟：对 `arr2` 中每个值 $x$，把 `arr1` 从头扫一遍收集所有等于 $x$ 的元素；扫完 `arr2` 后，把剩下的元素排序追加。时间 $O(nm + n\log n)$，$n,m \le 1000$ 时约 $10^6$ 次操作，能过，但要做一次「删除/标记」处理，且完全没有利用「值域极小」这个条件。

另一条常见写法是**自定义比较器**：先建立 `rank[x]`（$x$ 在 `arr2` 中的下标），再对 `arr1` 排序，键为

$$
\text{key}(x) = \begin{cases} \bigl(0,\ \text{rank}[x]\bigr), & x \in \text{arr2} \\ \bigl(1,\ x\bigr), & x \notin \text{arr2} \end{cases}
$$

按这个键升序排序即可，时间 $O(n \log n)$。它是对的，但在周赛签到的场景下，**比较器排序是杀鸡用牛刀**，而且排序是「比较两个元素」的框架，本题真正需要的其实是「按值分桶、按桶输出」。

### 3.2 核心观察：按值分桶——用计数排序取代比较排序

![核心观察：前段看 arr2 的名次，后段看数值大小](images/wc145_q1_rank_bucket.svg)

把 `arr1` 的元素按「是否出现在 `arr2` 中」分成两类：

- **A 类**（在 `arr2` 中）：`arr2` 给每个值指定了唯一的名次 $\text{rank}[x]$（因为 `arr2` 元素互不相同）。输出里，A 类必须按名次由小到大排；同一个值出现多次时，这些相同的值彼此没有区别，必然连成一段。
- **B 类**（不在 `arr2` 中）：题目只要求它们**按升序**排在 A 类之后，不关心别的。

于是答案的形态完全确定：先按 `arr2` 的顺序，把每个值重复「它的出现次数」次；再把 B 类的值按数值升序接上。**整个过程与 `arr1` 的原始顺序毫无关系**，只需要知道「每个值出现了几次」。

而「每个值出现几次」用一张长度 $1001$ 的**计数表**就能在 $O(n)$ 内统计完；之后按 `arr2` 顺序查表，再从 $0$ 扫到 $1000$ 补齐尾部即可。排序彻底消失，只剩两次顺序扫描。

### 3.3 算法流程

![算法流程：一次计数 + 两趟输出](images/wc145_q1_counting_flow.svg)

1. **计数**：开 `cnt[0..1000]` 全零，对 `arr1` 中每个元素 `cnt[x] += 1`。
2. **A 类输出**：按 `arr2` 的顺序遍历 $x$，把 $x$ 追加 `cnt[x]` 次，然后**立刻置 `cnt[x] = 0`**（这一步是防重复的关键）。
3. **B 类输出**：$v$ 从 $0$ 枚举到 $1000$，若 `cnt[v] > 0` 就追加 `cnt[v]` 个 $v$。下标天然递增，故这段**自动升序**。
4. 返回结果数组，其长度恰好是 `arr1` 的长度。

> ⚠️ 第 2 步的清零不能省。若只把元素输出而不清零，第 3 步又会把 A 类的元素按数值顺序再吐一遍，答案长度直接翻倍。

### 3.4 示例演算

![示例 1 演算](images/wc145_q1_example_walkthrough.svg)

对示例 1，`arr1 = [2,3,1,3,2,4,6,7,9,2,19]`、`arr2 = [2,1,4,3,9,6]`，计数结果为

| 值 | 1 | 2 | 3 | 4 | 6 | 7 | 9 | 19 |
|----|---|---|---|---|---|---|---|----|
| 次数 | 1 | 3 | 2 | 1 | 1 | 1 | 1 | 1 |

第 2 步按 `arr2` 顺序输出，得到前段

```text
2 2 2 | 1 | 4 | 3 3 | 9 | 6
```

第 3 步从 $0$ 扫到 $1000$，只剩 $7$ 与 $19$ 未被清零，得到尾段 `7 19`。拼起来正是 `[2,2,2,1,4,3,3,9,6,7,19]`。

## 4. 算法细节

1. **计数表大小**：值域上界是 $1000$，数组开 $1001$（下标 $0 \sim 1000$），不要写成 $1000$ 而在输入含 $1000$ 时越界。
2. **清零时机**：输出完 `arr2` 的元素后立刻 `cnt[x] = 0`，而不是在循环外统一清；循环外清需要额外记住哪些值处理过。
3. **尾部扫描范围**：从 $0$ 开始扫，因为 `arr1[i]` 可取 $0$。不能用「$0$ 表示空桶」的哨兵写法，只能看 `cnt[v] > 0`。
4. **输出方式**：C++ 用 `res.reserve(arr1.size())` 预分配，避免多次扩容；Python 用 `res.extend([x] * cnt[x])` 批量追加，比在循环里 `append` 更快。
5. **不要写 `while (cnt[x]-- > 0)`**：循环结束时 `cnt[x]` 会变成 $-1$，如果后面漏了清零、或想复用计数表，就会读到负数次数直接出错。写成 `for (int k = 0; k < cnt[x]; k++)` 更安全。
6. **`arr2` 元素一定存在**：题目保证每个 `arr2[i]` 都在 `arr1` 中，所以 `cnt[x] >= 1` 恒成立；但代码不必依赖这一点，写法对 `cnt[x] == 0` 也安全。
7. **结果长度校验**：最终长度应为 $\lvert \text{arr1} \rvert$，可作为本地自测的不变量。

## 5. 正确性证明

**引理 1（A 类有序）**：算法输出中，A 类（出现在 `arr2` 中的元素）的相对顺序与它们在 `arr2` 中的顺序一致。

**证明**：A 类的全部元素只在第 2 步产生，且是按照 `arr2` 的下标顺序依次追加的；同一个值 $x$ 的所有副本在同一轮里连续追加，彼此相同、不破坏顺序。于是对 `arr2` 中任意两个值，若 $x$ 排在 $y$ 之前，则输出中所有 $x$ 都排在所有 $y$ 之前。∎

**引理 2（B 类升序且都在末尾）**：算法输出中，不在 `arr2` 中的元素按数值升序排列，且整体位于 A 类之后。

**证明**：B 类元素只可能在第 3 步被输出——第 2 步只追加 `arr2` 中的值，而进入第 3 步时这些值对应的桶已被清零，因此第 3 步不会重复输出任何 A 类元素。第 3 步按 $v = 0,1,\dots,1000$ 递增枚举，故输出中 B 类值单调不减；又第 3 步整体在第 2 步之后执行，故 B 类全部在 A 类之后。∎

**引理 3（元素守恒）**：算法输出恰好包含 `arr1` 的所有元素，每个元素出现次数与 `arr1` 中相同。

**证明**：第 1 步后 $\sum_v \text{cnt}[v] = \lvert \text{arr1} \rvert$，且 `cnt[v]` 等于 $v$ 在 `arr1` 中的出现次数（计数排序的标准性质）。第 2 步对每个 $x \in \text{arr2}$ 输出 `cnt[x]` 个 $x$ 后清零，恰好取走 A 类的全部副本；第 3 步对剩下的每个 $v$ 输出 `cnt[v]` 个 $v$，恰好取走 B 类的全部副本。故每个值被输出的次数等于它的原始次数。∎

**定理**：算法输出的数组满足题目的全部要求。

**证明**：由引理 3，输出是 `arr1` 的一个重排；由引理 1，A 类按 `arr2` 顺序排列；由引理 2，B 类升序且位于末尾。三条要求全部满足。∎

**推论（答案唯一）**：满足题意的排列是唯一的，因为 A 类的顺序与每个值的个数都被固定，B 类必须升序且接在最后，没有任何自由度。

## 6. 复杂度分析

- **时间**：$O(n + m + V)$。统计频次遍历 `arr1` 一次，$O(n)$；按 `arr2` 输出遍历 `arr2` 一次、每个值的副本总数为 $n$ 的一部分，$O(n + m)$；尾部扫描 $V + 1 = 1001$ 个桶，$O(V)$。没有比较排序，也就没有 $\log$ 因子。
- **空间**：$O(V + n)$。计数表 $1001$ 个整数，$O(V)$；结果数组长度 $n$，$O(n)$。若不计输出，额外空间是 $O(V)$，与输入规模无关。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> relativeSortArray(vector<int>& arr1, vector<int>& arr2) {
        const int MAXV = 1000;
        vector<int> cnt(MAXV + 1, 0);
        for (int x : arr1) cnt[x]++;              // ① 计数

        vector<int> res;
        res.reserve(arr1.size());
        for (int x : arr2) {                      // ② 按 arr2 的名次成段输出
            for (int k = 0; k < cnt[x]; k++) res.push_back(x);
            cnt[x] = 0;                           // 用完清零，防止 ③ 重复输出
        }

        for (int v = 0; v <= MAXV; v++) {         // ③ 剩余元素按值域升序补尾
            for (int k = 0; k < cnt[v]; k++) res.push_back(v);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def relativeSortArray(self, arr1: list[int], arr2: list[int]) -> list[int]:
        MAXV = 1000
        cnt = [0] * (MAXV + 1)
        for x in arr1:                 # ① 计数
            cnt[x] += 1

        res = []
        for x in arr2:                 # ② 按 arr2 的名次成段输出
            res.extend([x] * cnt[x])
            cnt[x] = 0                 # 用完清零，防止 ③ 重复输出

        for v in range(MAXV + 1):      # ③ 剩余元素按值域升序补尾
            if cnt[v]:
                res.extend([v] * cnt[v])
        return res
```

> 💡 若不想依赖值域，也可用 `res.sort(key=lambda x: (rank.get(x, 10**9), x))`，其中 `rank = {v: i for i, v in enumerate(arr2)}`；时间复杂度 $O(n \log n)$，代码更短但没有利用本题「值域小」的特点。

## 8. 边界情况与易错点

1. **`arr2` 覆盖 `arr1` 全部取值**（如 `arr1 = [3,3,3], arr2 = [3]`）：第 3 步什么都不输出，尾部为空，结果长度仍是 $n$。
2. **值 $0$ 合法**：`arr1[i]` 可以等于 $0$，所以尾扫必须从 $v = 0$ 开始，也不能拿 $0$ 当「桶为空」的标记。
3. **值 $1000$ 合法**：计数表长度必须是 $1001$，写下标时用 `cnt[x]` 而不是 `cnt[x - 1]` 之类的偏移。
4. **忘记清零**：第 2 步输出后不清零，答案会把 A 类元素再输出一遍，长度变成 $n + |A|$，是最常见的 WA。
5. **`while (cnt[x]-- > 0)` 的副作用**：循环退出后 `cnt[x] == -1`；若后续复用该表（例如想再统计一次）就会出错。
6. **返回长度**：必须恰好等于 `arr1` 的长度；可用 `assert len(res) == len(arr1)` 在本地自查。
7. **输入顺序无关**：`arr1` 是乱序还是有序不影响答案，不要花时间先排序。
