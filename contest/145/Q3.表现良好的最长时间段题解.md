# LeetCode 表现良好的最长时间段 题解

## 1. 题目概述

- **标题 / 题号**：表现良好的最长时间段（#1124，medium）
- **链接**：https://leetcode.cn/problems/longest-well-performing-interval/
- **来源**：LeetCode 第 145 场周赛 Q3
- **难度**：中等
- **标签**：栈、数组、哈希表、前缀和、单调栈

**题意**：`hours[i]` 是员工第 $i$ 天的工时。工时**严格大于 8** 的一天叫「劳累的一天」，否则叫「不劳累的一天」。如果一个连续天数区间内「劳累天数严格多于不劳累天数」，就称它为一个「表现良好的时间段」。求所有表现良好时间段中的**最大长度**，一个都没有时返回 `0`。

**约束**：

- $1 \le n = \text{hours.length} \le 10^4$
- $0 \le \text{hours}[i] \le 16$

> 💡 两个容易看错的点：条件是「严格大于 8」而不是「大于等于」；答案允许为 `0`（示例 2 全是 6，任何区间都不合法）。

## 2. 示例

**示例 1**

```text
输入：hours = [9,9,6,0,6,6,9]
输出：3
解释：最长的表现良好时间段是 [9,9,6]：
      劳累 2 天、不劳累 1 天，2 > 1，长度 3。
```

**示例 2**

```text
输入：hours = [6,6,6]
输出：0
解释：每天都不劳累，任何区间内不劳累天数都多于劳累天数（0 天），
      不存在表现良好的时间段，返回 0。
```

**补充示例（非官方，用于说明答案可以不从 0 开始）**

```text
输入：hours = [6,6,9,9,9,6,6]
输出：5
解释：[6,9,9,9,6]（下标 1..5）中劳累 3 天、不劳累 2 天，长度 5；
      整体 7 天劳累 3 天、不劳累 4 天，并不合法。
```

## 3. 解题思路

### 3.1 暴力思路

先把每天折成 $A[i] = +1$（劳累）或 $-1$（不劳累），那么区间 $[l, r]$ 合法当且仅当

$$\sum_{i=l}^{r} A[i] > 0$$

最朴素的做法枚举左右端点再逐项累加，$O(n^3)$；配上前缀和可以做到 $O(n^2)$：固定左端点 $l$，向右扫 $r$ 并累加，一旦 $s > 0$ 就更新答案。$n = 10^4$ 时 $O(n^2) = 10^8$ 次加法，常数稍大就会超时。

更关键的是：**滑窗、二分长度这些常见套路在这里全部失效**，因为合法性对长度不单调：

- `hours = [9, 6, 9]`：整段长度 3 合法（$+1-1+1 = +1$），但长度 2 的两个区间 `[9,6]`、`[6,9]` 和都是 $0$，并不合法。于是「存在长度 $L$ 的合法区间」推不出「存在长度 $L-1$ 的合法区间」，二分答案不成立。
- 左端点右移时区间和可能变好（移走 $-1$）也可能变差（移走 $+1$），右端点同理，双指针的单调性同样不成立。

### 3.2 核心观察：前缀和 + 「首次出现」

![把 hours 变成 ±1，再把区间合法转化为前缀和的严格上升](images/wc145_q3_prefix_mapping.svg)

定义前缀和 $S_0 = 0$、$S_j = \sum_{i=0}^{j-1} A[i]$，则区间 $(i, j]$ 的和为 $S_j - S_i$，于是

$$\text{区间 } (i, j] \text{ 合法} \iff S_i < S_j, \qquad \text{长度} = j - i$$

问题变成：求 $\max\{ j - i : 0 \le i < j \le n,\ S_i < S_j \}$。对每个 $j$，我们想要**满足 $S_i < S_j$ 的最小下标 $i$**。一般前缀和需要二维偏序结构，但这里 $A[i] \in \{+1, -1\}$，前缀和**每步只变 1**，是一条「一步一台阶」的折线，于是有极强的结构：

- 若 $S_j > 0$：$i = 0$ 就合法（$S_0 = 0 < S_j$），而长度不可能超过 $j$，所以**直接取 $i = 0$，答案就是 $j$**。
- 若 $S_j \le 0$：任一合法左端点都满足 $S_i \le S_j - 1 < 0$。从 $S_0 = 0$ 一路下降到 $S_i$ 的折线必定穿过区间 $[S_i, 0]$ 里的每个整数值，其中就包含 $S_j - 1$，故 **$S_j - 1$ 一定在前 $i$ 个前缀值里出现过**。取它的首次出现位置 $f(S_j - 1)$，则 $f \le i$；又 $S_{f} = S_j - 1 < S_j$ 说明 $f$ 本身也合法，所以**最小的合法左端点恰为 $f(S_j - 1)$**。

于是每个 $j$ 只需要一次查表：$S_j - 1$ 第一次出现在哪个下标。表里存「前缀值 → 首次出现的下标（前缀长度）」，遍历时边查边登记即可。

### 3.3 算法流程 / 状态转移

![算法流程：s > 0 直接取整段，否则查 first[s − 1]](images/wc145_q3_algorithm_flow.svg)

1. 初始化 $s = 0$、$ans = 0$，哈希表只放 `first[0] = 0`。
2. 依次处理 $i = 0 \dots n-1$，令 $s \leftarrow s + (hours[i] > 8\ ?\ +1 : -1)$，此时 $s = S_{i+1}$。
3. 若 $s > 0$：$ans \leftarrow i + 1$（$i = 0$ 合法，长度取到上界）。
4. 否则若 $first$ 中存在键 $s - 1$：$ans \leftarrow \max(ans,\ (i+1) - first[s-1])$。
5. 若 $first$ 中还没有键 $s$：登记 $first[s] = i + 1$（只记首次，之后的更晚出现不会给出更长区间）。
6. 遍历结束返回 $ans$。

### 3.4 示例演算

![补充示例走查表：hours = [6,6,9,9,9,6,6] 的每一步](images/wc145_q3_walkthrough.svg)

先看官方示例 1：`hours = [9,9,6,0,6,6,9]`，$A = [+1,+1,-1,-1,-1,-1,+1]$，前缀和 $0,1,2,1,0,-1,-2,-1$。前三天 $S_j = 1,2,1$ 全都 $> 0$，每轮直接取整段，到 $j = 3$ 时 $ans = 3$，对应 `[9,9,6]`。之后 $S_j \le 0$，需要查 $f(S_j - 1)$：$S_4 = 0$ 要查的 $f(-1)$ 尚未出现，$S_5$、$S_6$ 同理；直到 $j = 7$ 才命中 $f(-2) = 6$，长度 $7 - 6 = 1$，超不过 3。可见本例的答案由 $s > 0$ 分支给出。

为了看清查表如何决定答案，再看补充示例 `[6,6,9,9,9,6,6]`（上图）：$A = [-1,-1,+1,+1,+1,-1,-1]$，$S = 0,-1,-2,-1,0,1,0,-1$。

- $j = 1, 2$：$S_j$ 一路下行，要查的 $f(-2)$、$f(-3)$ 都不存在，`ans` 保持 0；
- $j = 3$：$S_3 = -1$，$f(-2) = 2$，候选长度 $3 - 2 = 1$（区间 `[9]`），`ans = 1`；
- $j = 4$：$S_4 = 0$，$f(-1) = 1$，候选长度 $4 - 1 = 3$（区间 `[6,9,9]`），`ans = 3`；
- $j = 5$：$S_5 = 1 > 0$，直接取整段长度 5（区间 `[6,6,9,9,9]`），`ans = 5`；
- $j = 6, 7$：分别查 $f(-1) = 1$、$f(-2) = 2$，长度都是 5，答案封顶于 5。

第 5 步走的是 $s > 0$ 分支而不是查表分支；若省掉这个分支、只查 $f(s-1)$，那么 `hours = [9,9]` 在 $j = 2$ 会查到 $f(1) = 1$ 而得到长度 1，正确答案却是 2——这就是两个分支都必须保留的原因。

## 4. 算法细节

1. **$\pm 1$ 映射的语义**：$s$ 就是「劳累天数 $-$ 不劳累天数」，$s > 0$ 等价于当前前缀本身合法，是最容易漏掉的分支。
2. **$s > 0$ 时不要再查表**：此时 $f(s-1)$ 可能远大于 $0$（如 `[9,9]` 在 $s = 2$ 时 $f(1) = 1$），照查会得到更短的长度，必须用 $\max$ 或者直接走 $s > 0$ 分支。
3. **$s \le 0$ 才满足引理 2 的前提**：引理 2 用到了「$S_j \le 0$ 时折线必然从 0 下穿到 $S_i$」这一事实；$s > 0$ 时最小合法左端点是 0 而不是 $f(s-1)$，引用结论时不能丢掉前提。
4. **只记首次出现**：同一个前缀值出现得更晚时，$j - i$ 只会更小，不可能贡献更优答案，所以 `if` 保护住「未登记才写入」。
5. **两种容器**：Python 用 `dict`；C++ 因值域是 $[-n, n]$，用 `vector<int> first(2n+3, -1)` 加偏移 `off = n + 1` 更快。注意 $s - 1$ 最小到 $-n - 1$，偏移量必须取 $n + 1$（取 $n$ 会越界，这是本题最容易踩的 UB）。
6. **登记写在最后**：本轮写入的是 $first[s] = i + 1$，与查询用的键 $s - 1$ 一定不同，所以顺序无歧义；但写在最后更贴近「先决策、后登记」的语义，也不会让读者误以为会出现 $i = j$ 的零长区间。
7. **下标对齐**：$S_j$ 代表前 $j$ 天，表中的值也是「前缀长度」，所以长度直接是 $(i+1) - first[s-1]$，不要再 $+1/-1$ 修正。

## 5. 正确性证明

**引理 1（区间合法性判定）**：对 $0 \le i < j \le n$，区间 $[i, j-1]$ 是表现良好时间段 $\iff S_i < S_j$。

**证明**：区间内「劳累天数 $-$ 不劳累天数」$=\sum_{k=i}^{j-1} A[k] = S_j - S_i$，表现良好即该值 $> 0$，等价于 $S_i < S_j$。∎

**引理 2（$S_j \le 0$ 时的最小合法左端点）**：设 $S_j \le 0$ 且存在 $i < j$ 使 $S_i < S_j$。则值 $S_j - 1$ 必出现在 $S_0, \dots, S_{j-1}$ 中，其首次出现位置 $f$ 满足：$f \le i$ 对每个合法左端点 $i$ 成立，且 $f$ 自身合法。

**证明**：任取合法左端点 $i$，即 $S_i < S_j$，分两种情形。

- 若 $S_i = S_j - 1$：由 $f$ 是首次出现即得 $f \le i$。
- 若 $S_i \le S_j - 2$：因 $S_j \le 0$，有 $S_j - 1 \le -1$，从而 $S_i < S_j - 1 < 0$。前缀和序列从 $S_0 = 0$ 出发、每步变化恰为 $1$，下降到 $S_i < 0$ 的途中必然取遍 $[S_i, 0]$ 内的所有整数，其中包含 $S_j - 1$；而这些下标都 $\le i$，故 $f \le i$。

两种情形都得到 $f \le i$。又 $S_f = S_j - 1 < S_j$ 且 $f \le i < j$，由引理 1 知区间 $[f, j-1]$ 合法。于是 $f$ 自身合法且不大于任何合法左端点，正是最小合法左端点，并且 $S_j - 1$ 确实出现过。∎

**引理 3（$S_j > 0$ 时的最优性）**：若 $S_j > 0$，则以 $j$ 结尾的最长合法区间长度为 $j$。

**证明**：$i = 0$ 满足 $S_0 = 0 < S_j$，故 $[0, j-1]$ 合法，长度 $j$；而任何以 $j$ 结尾的区间长度 $j - i \le j$，故 $j$ 即最优。∎

**定理**：算法返回的 $ans$ 等于最长表现良好时间段的长度。

**证明**：对每个 $j \in [1, n]$，算法在引理 3 的情形取到以 $j$ 结尾的最优长度；在 $S_j \le 0$ 的情形，若存在合法左端点，由引理 2 的最小性，$first[S_j - 1]$ 就是最小合法左端点，候选值 $j - first[S_j-1]$ 正是以 $j$ 结尾的最长合法长度，若不存在合法左端点则 $first$ 中无此键、不更新——由引理 2 的「必出现」可知此时确实没有合法左端点，跳过是正确的。$ans$ 取遍所有 $j$ 的最大值，故等于全局最长长度；若无任何合法区间，$ans$ 保持初值 $0$，符合约定。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标做一次 $\pm 1$ 累加、至多一次哈希表查询与一次插入，均为 $O(1)$ 均摊；数组实现则严格 $O(1)$。
- **空间**：$O(n)$。哈希表/数组最多记录 $2n+1$ 个不同前缀值；C++ 数组版为 $2n+3$ 个 `int`。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int longestWPI(vector<int>& hours) {
        int n = hours.size();
        // 前缀和 s ∈ [-n, n]，s - 1 ∈ [-n-1, n-1]：偏移量取 n + 1，数组开 2n + 3
        const int off = n + 1;
        vector<int> first(2 * n + 3, -1);   // first[s + off] = 值 s 首次出现的前缀长度
        first[0 + off] = 0;

        int s = 0, ans = 0;
        for (int i = 0; i < n; ++i) {
            s += (hours[i] > 8 ? 1 : -1);   // 此刻 s = S_{i+1}
            if (s > 0) {
                ans = i + 1;                // i = 0 就合法，长度达到上界
            } else if (first[s - 1 + off] != -1) {
                ans = max(ans, (i + 1) - first[s - 1 + off]);
            }
            if (first[s + off] == -1) first[s + off] = i + 1;  // 只记首次出现
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def longestWPI(self, hours: list[int]) -> int:
        first = {0: 0}          # 前缀和 -> 首次出现的下标（前缀长度）
        s = ans = 0
        for i, h in enumerate(hours):
            s += 1 if h > 8 else -1          # 劳累 +1，不劳累 -1
            if s > 0:
                ans = i + 1                  # 从 0 开始整段合法，必然最长
            elif s - 1 in first:
                ans = max(ans, i + 1 - first[s - 1])
            first.setdefault(s, i + 1)       # 仅登记首次出现
        return ans
```

## 8. 边界情况与易错点

1. **全部不劳累**（示例 2）：$s$ 一路递减，$first[s-1]$ 始终不存在，`ans` 保持 0，正好符合「不存在则返回 0」。
2. **全部劳累**：$s$ 单调递增，每轮走 $s > 0$ 分支，返回 $n$，不会因为查表而变短。
3. **$n = 1$**：`[9]` 返回 1，`[6]` 返回 0；注意此时前缀和只到 $\pm 1$，C++ 数组偏移若取 $n$ 就会访问 `first[-1]`。
4. **C++ 数组越界**：$s - 1$ 的最小值是 $-n - 1$，偏移必须用 $off = n + 1$、长度 $2n + 3$；用 `unordered_map` 则无此问题，但多一层哈希开销。
5. **只在 $s \le 0$ 时查 `first[s-1]`**：$s > 0$ 时最小合法左端点是 0，而不是 $f(s-1)$；若把这一步换成无条件查表，会得到偏小的答案（`hours = [9,9]` 会算出 1 而不是 2）。
6. **不要把严格不等式写成非严格**：区间和必须 $> 0$，即 $S_i < S_j$；若写成 $S_i \le S_j$（和 $\ge 0$），`[9,6]` 这种和为零的区间会被误判为合法。
7. **只登记首次出现**：若每轮都覆盖写入，查到的可能是更晚的下标，长度偏小。
8. **`first[0] = 0` 实际是冗余的**：因为只在 $s \le 0$ 时查表，查询键 $s - 1 \le -1$，永远查不到 0；保留它只是为了与「空前缀」的语义一致，删掉不影响正确性（可用随机对拍验证）。
