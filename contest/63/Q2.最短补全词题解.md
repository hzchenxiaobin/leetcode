# LeetCode 最短补全词 题解

## 1. 题目概述

- **标题 / 题号**：最短补全词（#748，easy）
- **链接**：https://leetcode.cn/problems/shortest-completing-word/
- **来源**：LeetCode 第 63 场周赛 Q2
- **难度**：简单
- **标签**：数组，哈希表，字符串

**题意**：给定字符串 $licensePlate$ 与候选词数组 $words$。把 $licensePlate$ 中的**数字和空格丢掉**、字母统一转成小写，得到一个字母**多重集**；若某个候选词里每个字母的出现次数都**不少于**这个多重集中的次数，它就是「补全词」。要求返回 $words$ 中**最短**的补全词，长度并列时返回 $words$ 里**最先出现**的那个。数据保证答案存在。

**约束**：

- $1 \le \lvert licensePlate \rvert \le 7$，只含数字、大小写字母、空格
- $1 \le \lvert words \rvert \le 1000$
- $1 \le \lvert words[i] \rvert \le 15$，且只含小写字母

> 💡 先估量级：车牌最多 7 个字符，所以需求侧有效字母**最多 7 个**；候选词最多 1000 个、每个最多 15 个字母，字符总量不到 $2\times10^4$。因此**任何逐字母核销的写法都能过**——本题真正的考点是「把判定写成什么形态」，以及怎样让「最短 + 最先出现」这条件自动成立。

## 2. 示例

**示例 1**

```text
输入：licensePlate = "1s3 PSt", words = ["step", "steps", "stripe", "stepple"]
输出："steps"
解释：车牌含字母 s、p、s（忽略大小写）和 t，即需要 2 个 s、1 个 p、1 个 t。
      "step"   有 t、p，但只有 1 个 s，不达标；
      "steps"  有 t、p 和 2 个 s，达标，长度 5；
      "stripe" 只有 1 个 s，不达标；
      "stepple" 只有 1 个 s，不达标。
      唯一达标者就是 "steps"。
```

**示例 2**

```text
输入：licensePlate = "1s3 456", words = ["looks", "pest", "stew", "show"]
输出："pest"
解释：车牌只含字母 s，四个词都达标；
      "pest"、"stew"、"show" 长度同为 4，最短；
      三者中 "pest" 在 words 里最先出现，故返回它。
```

**示例 3（补充，非官方）**

```text
输入：licensePlate = "12 34", words = ["abc", "zz", "de"]
输出："zz"
解释：车牌没有任何字母，需求为空，所有词都是补全词；
      "zz" 与 "de" 长度同为 2，最短；"zz" 在 words 里更靠前，故选它。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是「逐字母核销」：对每个候选词，把它的字母装进一个字符池，然后拿车牌里每个有效字母去池子里找、找到就删掉；全部找到即为补全词。

- 单次判定 $O(\lvert w \rvert \cdot \lvert licensePlate \rvert)$，最坏 $15 \times 7 = 105$ 次操作；
- 全部 $1000$ 个词走一遍约 $10^5$ 次操作，**能过**。

但它有两个别扭之处：一是每次判定都要重建字符池、做线性 `find`/`erase`，常数大且代码啰嗦；二是「最短 + 最先出现」还需要额外处理——常见写法是按长度 `stable_sort` 后再取第一个达标者，这要求比较函数**只比长度**、且排序**必须稳定**，一旦写成普通 `sort` 或比较函数里顺手比了字典序，并列时的次序就被破坏，静默出错。

另一条朴素路线是枚举长度：从下界 $\sum need[c]$ 到 $15$，每层重扫 $words$。它正确，但要跑 $15$ 趟，且每趟都在重复统计同一批词的字母数。

### 3.2 核心观察：需求是一个 26 维计数向量

![把车牌压成 26 维需求向量](images/wc63_q2_need_vector.svg)

车牌信息真正被用到的部分只有「每个字母要几个」，与字母在车牌里的**位置、顺序、大小写、夹杂的数字和空格**全都无关。于是先把车牌**压成一次**：

$$need[c] = \#\{\,x \in licensePlate : \mathrm{lower}(x) = c\,\},\qquad c \in [a, z]$$

这一步做完，判定一个词 $w$ 是否达标就只剩一句：

$$\forall c \in [a, z]:\quad cnt_w[c] \ge need[c]$$

其中 $cnt_w$ 是 $w$ 的字母计数。原来的「删字符核销」被换成「逐位比大小」，判定与字母出现在哪里彻底解耦。

再看第二个诉求：**最短优先、并列取最先出现**。这两件事正好可以被「顺序扫描 + 只接受严格更短」同时满足——遍历 $words$ 时维护当前最优 $best$，只有 $w$ 严格短于 $best$ 时才覆盖它。因为覆盖条件是严格小于：

- 先到的词先把 $best$ 占住，后到的同长词无法覆盖它，**「最先出现」自动成立**；
- 只有更短的词能覆盖，所以最终的 $best$ 一定是所有补全词里最短的。

顺带得到一个几乎免费的剪枝：既然长度 $\ge \lvert best \rvert$ 的词永远无法刷新答案，那么它们**连字母都不用数**，直接跳过。

### 3.3 算法流程

![算法流程图](images/wc63_q2_scan_flow.svg)

1. **建需求表**：初始化 $need[26] = 0$，遍历车牌，遇到字母就 $need[\mathrm{lower}(x)] \mathrel{+}= 1$；数字与空格跳过。
2. **顺序扫描**：按 $words$ 原顺序取词 $w$。
3. **长度剪枝**：若 $best$ 已非空（表示已有答案）且 $\lvert w \rvert \ge \lvert best \rvert$，直接跳过本轮。
4. **建计数表**：$cnt[26] = 0$，遍历 $w$ 的每个字符累加。
5. **逐位比较**：对 $c \in [a, z]$ 检查 $cnt[c] \ge need[c]$，一旦某位不足即判为不达标。
6. **更新答案**：达标就执行 $best \leftarrow w$（能走到这一步，说明 $best$ 为空或 $\lvert w \rvert < \lvert best \rvert$，因此这次更新必定严格更短）。
7. **扫描结束**，返回 $best$。

其中第 2～6 步对每个词只做一次，全程**不回看、不排序**。

### 3.4 示例演算

![两组示例走查](images/wc63_q2_walkthrough.svg)

**示例 1**：车牌 `"1s3 PSt"` 去掉数字与空格、统一小写后是 `s`、`p`、`s`、`t`，故 $need = \{s{:}2,\ p{:}1,\ t{:}1\}$。

| 词 | 长度 | $cnt$（s, p, t） | 达标 | 动作 |
|---------|------|------------------|------|------|
| `step` | 4 | 1, 1, 1 | 否（缺 1 个 s） | 跳过 |
| `steps` | 5 | 2, 1, 1 | 是 | $best \leftarrow$ `steps` |
| `stripe` | 6 | 1, 1, 1 | —（未判定） | 长度 $6 \ge 5$，剪枝 |
| `stepple` | 7 | 1, 1, 1 | —（未判定） | 长度 $7 \ge 5$，剪枝 |

`step` 检查时 $best$ 仍是空串（表示还没有答案），所以**不做**长度剪枝，必须真正数一遍字母；`steps` 达标后 $best$ 长度变为 5，后面两个更长的词连计数都省了。即使不剪枝，`stripe`、`stepple` 也都只有 1 个 `s`，结论同样不变——剪枝只影响常数。

**示例 2**：$need = \{s{:}1\}$。

| 词 | 长度 | $cnt$（s） | 达标 | 动作 |
|---------|------|-----------|------|------|
| `looks` | 5 | 1 | 是 | $best \leftarrow$ `looks` |
| `pest` | 4 | 1 | 是 | $4 < 5$，$best \leftarrow$ `pest` |
| `stew` | 4 | 1 | —（未判定） | 长度 $4 \ge 4$，剪枝 |
| `show` | 4 | 1 | —（未判定） | 长度 $4 \ge 4$，剪枝 |

这里正是并列规则的体现：`pest`、`stew`、`show` 都能达标且长度相同，但 `stew`、`show` 只可能以「长度不占优」被挡住，`best` 停在最先出现的 `pest` 上。

## 4. 算法细节

1. **用定长数组而不是哈希表**：字母表只有 26 个键，`int[26]` 的下标访问比 `unordered_map` 快一个量级，也不会有哈希开销与迭代顺序问题。Python 同理用 `list`，不用 `Counter`（`Counter` 的比较要写 `>=` 的重载语义，反而不直观）。
2. **大小写归一只能做一次**：车牌里的字母先 `tolower` 再记账，词里全是小写所以不用转换；如果反过来对每个词都 `lower()` 一遍，会白白多出 $O(\sum \lvert w \rvert)$ 的字符串拷贝。
3. **`isalpha` 要防负字符**：C++ 的 `char` 可能是有符号的，把 `0x80` 以上的字节直接喂给 `isalpha` / `tolower` 是未定义行为。本题车牌只含 ASCII，但写成 `isalpha((unsigned char)c)` 是零成本的保险。更稳的写法是直接判 `('a' <= c && c <= 'z') || ('A' <= c && c <= 'Z')`。
4. **哨兵不能用 `""` 的长度**：空串的 $\lvert best \rvert = 0$，若把剪枝条件写成 $\lvert w \rvert \ge \lvert best \rvert$ 而不先判断「$best$ 是否为空」，那么第一个词就会被当成「长度不占优」剪掉，全流程一个词都不数，最终返回空串。必须用 `best.empty()` / `best is None` 把「未初始化」和「长度 0」区分开。
5. **覆盖条件必须是严格小于**：写成 $\lvert w \rvert \le \lvert best \rvert$ 的话，同长的后到者会覆盖先到者，示例 2 会返回 `show`。这一点和第 4 条的剪枝条件恰好互补：剪枝用 $\ge$（挡掉不可能变优的），更新用严格更短（保证并列不换人）。
6. **可达的下界是 $\sum_c need[c]$**：补全词至少要包含车牌要求的全部字母，所以长度不可能低于 $need$ 的总和。若某个时刻 $\lvert best \rvert$ 已等于这个下界，它已是理论上最优，可以立即 `break`，不必扫完剩下的词。
7. **空需求的退化行为**：车牌全是数字与空格时 $need$ 全 0，判定恒真，算法退化为「找最短且最先出现的词」，与题意一致，不需要特判。示例 3 即此情形。

## 5. 正确性证明

设 $need$ 为车牌的需求计数向量，$cnt_w$ 为词 $w$ 的字母计数，$n = \lvert words \rvert$，用 $s(w)$ 表示 $w$ 在 $words$ 中的下标。

**引理 1（判定引理）**：$w$ 是补全词 $\iff$ 对任意字母 $c$ 都有 $cnt_w[c] \ge need[c]$。

**证明**：「补全词」的定义是 $w$ 含车牌中所有字母，且重复字母的出现次数不少于车牌中的次数。车牌中字母 $c$ 出现 $need[c]$ 次，因此该要求等价于 $w$ 中至少有 $need[c]$ 个 $c$，即 $cnt_w[c] \ge need[c]$；对每个字母都成立即得结论。反之若所有位都满足，则 $w$ 的字母多重集包含车牌的多重集，$w$ 是补全词。∎

**引理 2（扫描不变式）**：记处理完前 $k$ 个词后 $best$ 的值为 $B_k$（可能为空）。则对每个 $k \in [0, n]$：

- 若前缀 $words[0..k-1]$ 中不存在补全词，则 $B_k$ 为空；
- 否则 $B_k$ 是前缀中**最短**的补全词，且在这些最短者中下标**最小**。

**证明**：对 $k$ 归纳。$k = 0$ 时前缀为空，$B_0$ 为空，成立。

设 $k$ 时成立，考察第 $k$ 个词 $w = words[k]$。

- 若 $w$ 不达标（引理 1 的某位不足），或命中长度剪枝（$B_k$ 非空且 $\lvert w \rvert \ge \lvert B_k \rvert$），$B_{k+1} = B_k$。前一种情况 $w$ 不是补全词，前缀的可选集合不变；后一种情况 $\lvert w \rvert \ge \lvert B_k \rvert$，而 $s(w) = k$ 大于 $B_k$ 中任何词的下标，故 $w$ 既不会成为更短的最优、也不会在并列中更靠前，最小值与最小下标均不变。
- 否则 $B_{k+1} = w$。剪枝未命中意味着「$B_k$ 为空」或「$\lvert w \rvert < \lvert B_k \rvert$」。前者说明前缀 $words[0..k-1]$ 中原本没有补全词，$w$ 是新的前缀里**唯一**的补全词，最短性与最小下标都成立。后者下，由归纳假设 $B_k$ 已是前缀中最短者，故 $\lvert w \rvert < \lvert B_k \rvert$ 说明 $w$ 严格短于前缀中任何补全词，直接成为唯一最短者；再看并列：若前缀中存在与 $w$ 等长的补全词 $w'$，则不变式给出 $\lvert B_k \rvert \le \lvert w' \rvert = \lvert w \rvert$，与 $\lvert w \rvert < \lvert B_k \rvert$ 矛盾，所以不存在这样的 $w'$，无须比较下标。

故 $B_{k+1}$ 满足不变式。∎

**定理**：算法返回 $words$ 中最短的补全词；若有多个，返回其中下标最小者。

**证明**：算法结束时 $k = n$，前缀即整个 $words$。由于题目保证答案存在，引理 2 的第二分支成立，$B_n$ 是全体补全词中长度最小的、且并列中下标最小的那个，算法正是返回 $B_n$。∎

**推论（剪枝不改变结果）**：被长度剪枝跳过的词 $w$ 满足 $\lvert w \rvert \ge \lvert B_k \rvert$ 且 $s(w) > s(B_k)$；由引理 1 无论它是否达标，都不可能严格优于 $B_k$，因此跳过它不影响定理的结论。∎

## 6. 复杂度分析

- **时间**：建需求表 $O(\lvert licensePlate \rvert)$；对每个词做一次 $O(\lvert w \rvert)$ 的计数与一次 $O(26)$ 的逐位比较，剪枝命中的词只花 $O(1)$。合计 $O\bigl(\lvert licensePlate \rvert + \sum_i \lvert words[i] \rvert + 26n\bigr)$。在给定约束下约为 $1.5\times10^4 + 2.6\times10^4$ 次基本操作，远低于任何时间限制。
- **空间**：$O(1)$，只有两个长度 26 的定长数组（$need$ 与 $cnt$）和一个指向答案的引用；不复制 $words$、不排序、不建哈希表。返回的字符串本身不计入辅助空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string shortestCompletingWord(string licensePlate, vector<string>& words) {
        int need[26] = {0};
        for (char c : licensePlate)
            if (isalpha((unsigned char)c))              // 数字与空格自然被过滤
                need[tolower((unsigned char)c) - 'a']++;

        string best;                                    // 空串 = 还没有答案
        int lowerBound = accumulate(need, need + 26, 0); // 任何补全词的长度下界

        for (const string& w : words) {
            if (!best.empty() && (int)w.size() >= (int)best.size())
                continue;                               // 长度不占优，连计数都省了

            int cnt[26] = {0};
            for (char c : w) cnt[c - 'a']++;

            bool ok = true;
            for (int i = 0; i < 26; ++i)
                if (cnt[i] < need[i]) { ok = false; break; }

            if (ok) {                                    // 能到这里必是严格更短
                best = w;
                if ((int)best.size() == lowerBound) break; // 已到理论最优
            }
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def shortestCompletingWord(self, licensePlate: str, words: list[str]) -> str:
        need = [0] * 26
        for ch in licensePlate:
            if ch.isalpha():                 # 数字与空格被跳过
                need[ord(ch.lower()) - ord('a')] += 1

        best = None                          # None = 还没有答案，不能用 '' 当哨兵
        for w in words:
            if best is not None and len(w) >= len(best):
                continue                     # 长度不占优，直接跳过

            cnt = [0] * 26
            for ch in w:
                cnt[ord(ch) - ord('a')] += 1

            if all(cnt[i] >= need[i] for i in range(26)):
                best = w                     # 严格更短才会走到这里

        return best
```

## 8. 边界情况与易错点

1. **车牌里没有任何字母**（如 `"1s3 456"` 的退化版 `"123 456"`）：$need$ 全 0，一切词都达标，答案应是 $words$ 中最短且最先出现的那个。算法无需特判就能给出正确结果，但若把剪枝条件写成「$best$ 为空时也跳过」，就会返回空串。
2. **忘记判断「还没有答案」**：空串的 $\lvert best \rvert = 0$ 与「真正的答案是空串」在类型上无法区分，只要剪枝里漏写 `!best.empty()`（Python 里漏写 `best is not None`），第一个词就会被判成「长度不占优」而跳过，结果返回空串。C++ 用空串作哨兵本身没问题（答案必定非空），前提是那个空判断一个都不能少；Python 用 `None` 语义更直白。
3. **大小写混排**（`"A 1 A"`）：两个 `A` 都要算成 `a`，要求 2 个 `a`。若只 `lower()` 未做，或用 `isupper()` 判反，条件就会错位。
4. **同一字母重复出现**（`"zzz"`）：要求至少 3 个 `z`，只含 1 个或 2 个 `z` 的词都不能选。这里应当是**逐字母计数比较**，而不是「包含关系」，用集合 `set` 会丢掉次数信息。
5. **并列必须取最先出现的那个**（示例 2 的 `pest`/`stew`/`show`）：覆盖条件若写成 $\le$，答案会变成最后一个同长词；先按长度排序再取第一个则要求 `stable_sort`，用普通 `sort` 会静默出错。
6. **词比需求还短**：需求可能有 7 个字母而词只有 1 个字母，此时必然不达标。不要用「词长 $\ge$ 需求总和」之类的判断代替逐位比较——它只能否决、不能确认。
7. **`isalpha` / `tolower` 传负 `char`**：在 `char` 为有符号的平台上，把非 ASCII 字节直接传入是未定义行为。本题数据是纯 ASCII，但按 `(unsigned char)` 强转或手写区间判断是零成本的正确写法。
8. **返回引用的生命周期**：C++ 中 `best = w` 是拷贝（`w` 是 `const string&`，指向 `words` 内部元素，拷贝后才安全）；若图省事写成引用 `const string* best`，返回时记得解引用，别返回悬垂指针。

**延伸思考**：把并列规则换成「等长时取字典序最小」，扫描式更新就不再够用——因为后到的等长词可能字典序更小。此时要么把比较键扩成 $(\text{长度}, \text{字典序}, \text{下标})$ 三元组，要么把候选按该三元组排序后取首项；若只顾「长度 + 字典序」而丢掉下标，就会与「最先出现」互斥，不变式必须重新推导。另一个方向是把它变成在线问题：若 $words$ 持续追加、查询不断到来，能否做到 $O(26)$ 单次查询？答案是「最小长度层里第一个达标者」，因此可以对每个长度维护该层所有词的逐位最大值上界，从而快速排除整层，这正是「计数向量作为单调特征」的可扩展之处。
