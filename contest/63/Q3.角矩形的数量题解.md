# LeetCode 角矩形的数量 题解

## 1. 题目概述

- **标题 / 题号**：角矩形的数量（#750，medium）
- **链接**：https://leetcode.cn/problems/number-of-corner-rectangles/
- **来源**：LeetCode 第 63 场周赛 Q3
- **难度**：中等
- **标签**：数组，数学，动态规划，矩阵

**题意**：给定一个只含 $0/1$ 的网格，统计其中「角矩形」的个数。一个角矩形是网格里**四个互不相同的 1**，它们恰好落在一个**轴对齐**矩形的四个角上；矩形内部的格子取什么值完全不管。求这样的四元组总数。

换句话问：有多少组 $(r_1, r_2, c_1, c_2)$ 满足 $r_1 < r_2$、$c_1 < c_2$，且 $\text{grid}[r_1][c_1]$、$\text{grid}[r_1][c_2]$、$\text{grid}[r_2][c_1]$、$\text{grid}[r_2][c_2]$ 全为 $1$。

**约束**：

- $1 \le R, C \le 200$（$R$、$C$ 分别为行数、列数）
- $\text{grid}[i][j] \in \{0, 1\}$
- 网格中 $1$ 的总个数不超过 $6000$

> 💡 量级先算清：$R,C$ 各 $200$，若按「两行两列」暴力枚举就是 $O(R^2 C^2) \approx 4\times10^{8}$ 次判定，卡在时限边缘；而 $1$ 只有 $6000$ 个，说明可行套路必然只与「$1$ 的分布」成正比，而不是与格点总数成正比。

## 2. 示例

**示例 1**

```text
输入：grid = [[1,0,0,1,0],
              [0,0,1,0,1],
              [0,0,0,1,0],
              [1,0,1,0,1]]
输出：1
解释：唯一的一个角矩形以 grid[1][2]、grid[1][4]、grid[3][2]、grid[3][4] 为四角。
      网格共 6 个 1：行 0 在列 0、3，行 1 在列 2、4，行 2 在列 3，行 3 在列 0、2、4。
      逐对检查「共同为 1 的列」：(0,1) 无、(0,2) 只有列 3、(0,3) 只有列 0、
      (1,2) 无、(2,3) 只有列 3，都凑不出两列；只有 (1,3) 有列 2、4 两列 ⇒ 1 个矩形。
```

**示例 2**

```text
输入：grid = [[1,1,1],
              [1,1,1],
              [1,1,1]]
输出：9
解释：4 个 2×2、4 个 2×3 或 3×2、1 个 3×3，合计 9。

```

**示例 3**


## 3. 解题思路

### 3.1 暴力思路

最直白的做法是按定义枚举：四重循环取 $r_1<r_2$、$c_1<c_2$，检查四个角是否都为 $1$，为真就计数。

- 判定次数 $\binom{R}{2}\binom{C}{2}$，$R=C=200$ 时约为 $1.99\times10^{4} \times 1.99\times10^{4} \approx 4\times10^{8}$；
- 每次判定 4 次访存，总访存超过 $1.5\times10^{9}$，C++ 勉强、Python 必定超时。

另一条朴素路线是「枚举四个 1」：从 $6000$ 个 1 里取 4 个，$\binom{6000}{4} \approx 5.4\times10^{13}$，直接爆炸。可见**必须把「四个角」这个 4 维约束降到 2 维**。

### 3.2 核心观察：按「列对」分桶，桶内只需数行数

![固定一对列，把矩形按列对分桶](images/wc63_q3_column_pair_bucket.svg)

关键问题不是「怎么找四个 1」，而是「**一个矩形由什么唯一确定**」。答案是：**一对行 + 一对列**。

固定两列 $j<k$，把所有「在这两列上同时为 $1$」的行收集起来，设共有 $m$ 行。只要从这 $m$ 行里任选两行，四个角就全是 $1$——因为列已固定、行也来自这个集合，四个角天然满足条件。于是：

$$\text{列对 }(j,k)\text{ 贡献 } \binom{m_{jk}}{2} \text{ 个矩形},\qquad ans=\sum_{j<k}\binom{m_{jk}}{2}$$

这一下把「选两行」从**枚举**变成了**组合计数**：不需要知道是哪两行，只需要知道有几行。

更进一步，$m_{jk}$ 不必扫两遍网格去数，可以**边扫边累积**：设 $cnt[j][k]$ 表示「在已经处理过的行中，$j$、$k$ 两列同时为 $1$ 的行数」。那么扫到第 $i$ 行时，若 $j,k$ 在这一行都为 $1$，它就和此前那 $cnt[j][k]$ 行各配出一个新矩形，直接把这 $cnt[j][k]$ 加到答案里，再把计数加一即可。这正是官方提示所说的「新行贡献 = 旧行里同时为 1 的次数」。

### 3.3 算法流程 / 状态转移

![算法流程：行内配对 + 跨行累积](images/wc63_q3_dp_flow.svg)

**状态定义**：$cnt[j][k]$（仅对 $j<k$ 有意义）＝ 处理到当前行为止，在列 $j$、$k$ 上**同时**为 $1$ 的行数。

**转移**：设第 $i$ 行值为 $1$ 的列号集合为 $S_i$。对 $S_i$ 中每一对 $j<k$：

$$ans \mathrel{+}= cnt[j][k],\qquad cnt[j][k] \mathrel{+}= 1$$

流程：

1. 初始化 $C \times C$ 的计数表 $cnt$ 全 $0$，答案 $ans=0$。
2. 逐行扫描 $i = 0 \dots R-1$，把本行所有值为 $1$ 的列号收进列表 $ones$。
3. 在 $ones$ 内做双重循环，枚举每一对 $j<k$。
4. 先执行 $ans \mathrel{+}= cnt[j][k]$（把新行与旧行的配对一次结算），
5. 再执行 $cnt[j][k] \mathrel{+}= 1$（把本行登记进计数表）。
6. 全部行扫完，返回 $ans$。

**为什么「先加后增」恰好等于 $\binom{m}{2}$**？因为组合数满足

$$\binom{x+1}{2}-\binom{x}{2}=\frac{(x+1)x-x(x-1)}{2}=x$$

也就是说，计数从 $x$ 涨到 $x+1$ 时，矩形数正好增加 $x$ 个，而 $x$ 就是自增前的 $cnt[j][k]$。所以每次自增前把旧值加进答案，累加结果自动等于 $\binom{m_{jk}}{2}$，无需任何组合数计算。

**为什么只枚举 $S_i$ 里的列对**？若 $j$ 或 $k$ 在本行为 $0$，则该行的 $cnt[j][k]$ 永远不涨，它对答案的贡献恒为 $0$，跳过它不丢任何矩形——这一步把复杂度从 $O(R \cdot C^2)$ 降到 $O(\sum_i k_i^2)$，$k_i = \lvert S_i \rvert$。

### 3.4 示例演算

![示例 1 走查](images/wc63_q3_walkthrough.svg)

**示例 1**：网格 $4 \times 5$，各行 $1$ 的列号依次为 $\{0,3\}$、$\{2,4\}$、$\{3\}$、$\{0,2,4\}$。

| 行 | $ones$ | 列对动作 | 答案 |
|------|-----------|-----------------------------|------|
| $r_0$ | $\{0,3\}$ | $cnt[0][3]: 0 \to 1$ | 0 |
| $r_1$ | $\{2,4\}$ | $cnt[2][4]: 0 \to 1$ | 0 |
| $r_2$ | $\{3\}$ | 不足两列，无列对 | 0 |
| $r_3$ | $\{0,2,4\}$ | $(0,2){:}\,0\to1$；$(0,4){:}\,0\to1$；$(2,4){:}\,ans \mathrel{+}= 1$ | **1** |

行 $r_3$ 枚举到列对 $(2,4)$ 时，$cnt[2][4]$ 已经是 $1$（由行 $r_1$ 登记），于是 $ans \mathrel{+}= 1$，对应矩形 $(r_1,r_3)\times(c_2,c_4)$，四角正是 `grid[1][2]`、`grid[1][4]`、`grid[3][2]`、`grid[3][4]`。其余列对都是首次出现，旧值为 $0$，不加任何东西。

**示例 2**：$3 \times 3$ 全 $1$，三个列对 $(0,1),(0,2),(1,2)$ 每行都被枚举到。

| 行 | 每个列对的旧值 | 每个列对新增 | 该行合计 |
|------|----------------|--------------|----------|
| $r_0$ | 0 | $+0$ | 0 |
| $r_1$ | 1 | $+1$ | 3 |
| $r_2$ | 2 | $+2$ | 6 |

累计 $0+3+6=9$，与 $\binom{3}{2}\times\binom{3}{2}=9$ 一致。示例 3 只有一行，$r_0$ 登记完就结束，答案是 $0$。

## 4. 算法细节

1. **二维计数表只存上三角**：$cnt[j][k]$ 只对 $j<k$ 有定义，枚举时也永远按 $j<k$ 写入，因此既不会漏也不会重复。若改成「对称地同时写 $cnt[j][k]$ 与 $cnt[k][j]$」，很容易在某一侧漏加，或把同一个矩形算两次。
2. **顺序不能反**：第 3.3 节的第 4、5 步一旦写反（先自增再累加），本行就会与**自己**配对。示例 2 会输出 $18$ 而不是 $9$——因为 $3$ 行全 $1$ 时每个列对都被多算了一遍自身行。
3. **只枚举 `ones` 内的列对**：这一剪枝不是「优化」，而是把复杂度从与 $C^2$ 成正比改成与 $1$ 的分布成正比。含 $0$ 的列对 $cnt$ 恒为 $0$，跳过它们对答案零影响。
4. **用「引用/行指针」减少寻址**：内层固定 $j$ 后把 $cnt[j]$ 取出来（C++ 用 `int* row = cnt[j].data()`，Python 用 `row = cnt[j]`），避免 $O(1)$ 的二级下标运算重复做 $O(k_i^2)$ 次。
5. **答案用 `long long` 累加**：本题约束下最大值约 $8.77\times10^{6}$（$R=75,C=80$ 全 $1$ 时 $\binom{75}{2}\binom{80}{2}=8\,769\,000$），`int` 其实装得下；但代价为零的 `long long` 能让代码在放宽约束后依然正确，属于防御性写法。
6. **行的列号收集只做一次**：若在双重循环里反复判断 `grid[i][j]`，每行要花 $O(k_i \cdot C)$ 而不是 $O(C)$，虽然仍是多项式级别，但白白多一次全行扫描。
7. **可以按方向转置**：$\sum_i k_i^2 \le \max_i k_i \cdot \sum_i k_i \le 200 \times 6000$。把网格转置后 $\{k_i\}$ 变成原来的列计数，若某一维的 1 分布更稀疏，转置能让这个上界更小。本题两种方向都足够快，属可选项。

## 5. 正确性证明

设 $R, C$ 为网格行列数，$m_{jk}=\#\{\,r : \text{grid}[r][j]=\text{grid}[r][k]=1\,\}$（$j<k$），算法返回值为 $ans$。

**引理 1（行列对与矩形一一对应）**：网格中的角矩形与「四角皆 $1$ 的有序对 $(r_1<r_2,\; c_1<c_2)$」一一对应。

**证明**：任取一个角矩形，它的四个角的最小行坐标、最大行坐标确定唯一的 $r_1<r_2$，最小列坐标、最大列坐标确定唯一的 $c_1<c_2$，且该角矩形完全由 $(r_1,r_2,c_1,c_2)$ 决定。反之给定满足四角皆 $1$ 的 $(r_1,r_2,c_1,c_2)$，因为 $r_1 \ne r_2$、$c_1 \ne c_2$，四个角互不相同，构成轴对齐矩形的四个顶点。不同四元组要么行对不同、要么列对不同，四个角的集合必然不同，故该映射是双射。∎

**引理 2（按列对分桶）**：角矩形总数为 $\sum_{j<k}\binom{m_{jk}}{2}$。

**证明**：由引理 1，可以按矩形所用的列对把全体矩形分类。固定列对 $(j,k)$，矩形还差「选哪两行」，而合法的行必须同时在这两列上为 $1$，恰有 $m_{jk}$ 个，从中任选两个即为一个矩形，共 $\binom{m_{jk}}{2}$ 个。不同列对给出的矩形列对不同，因此不重不漏，求和即总数。∎

**引理 3（扫描不变式）**：处理完前 $i$ 行后，对任意 $j<k$ 有

$$cnt[j][k]=\#\{\,r<i : \text{grid}[r][j]=\text{grid}[r][k]=1\,\},\qquad ans=\sum_{j<k}\binom{cnt[j][k]}{2}$$

**证明**：对 $i$ 归纳。$i=0$ 时 $cnt$ 全 $0$、$ans=0$，两边成立。

设 $i$ 时成立，考察第 $i$ 行。对任一列对 $(j,k)$：

- 若 $j,k$ 都在 $S_i$ 中（本行两列皆为 $1$），则真实计数从 $x=cnt[j][k]$ 变为 $x+1$；算法把 $x$ 加进 $ans$，而 $\binom{x+1}{2}-\binom{x}{2}=x$，故 $ans$ 的增量恰好等于组合数的增量，随后 $cnt[j][k]$ 自增为 $x+1$；
- 若 $j$ 或 $k$ 不在 $S_i$ 中，本行不满足条件，真实计数不变，而算法根本不枚举这个列对，$cnt$ 与 $ans$ 都不动。

两种情形下不变式在 $i+1$ 都成立。∎

**定理**：算法返回的值等于网格中角矩形的数量。

**证明**：算法扫完全部 $R$ 行，由引理 3，此时 $cnt[j][k]=\#\{r<R : \text{grid}[r][j]=\text{grid}[r][k]=1\}=m_{jk}$，且 $ans=\sum_{j<k}\binom{cnt[j][k]}{2}=\sum_{j<k}\binom{m_{jk}}{2}$，再由引理 2 即所求数量。∎

## 6. 复杂度分析

- **时间**：收集每行的 $1$ 需要 $O(RC)$；枚举列对需要 $\sum_i \binom{k_i}{2} \le \frac{1}{2}\sum_i k_i^2 \le \frac{1}{2}\cdot \max_i k_i \cdot \sum_i k_i \le \frac{1}{2}\times 200 \times 6000 = 6\times10^{5}$ 次配对操作。合计 $O\bigl(RC + \sum_i k_i^2\bigr)$，在约束下不超过 $6.4\times10^{5}$ 次基本操作，实测（$200\times30$ 全 $1$、$6000$ 个 $1$，含输入解析）整体约 $4$ 毫秒。
- **空间**：计数表 $cnt$ 占用 $O(C^2)$，$C=200$ 时为 $4\times10^{4}$ 个 `int`（约 $160$ KB）；$ones$ 缓冲 $O(C)$。不复制网格、不建哈希表。返回值为标量，不计入辅助空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countCornerRectangles(vector<vector<int>>& grid) {
        int R = grid.size(), C = grid[0].size();
        // cnt[j][k]: 已经处理过的行里，第 j、k 两列同时为 1 的行数（只用 j < k）
        vector<vector<int>> cnt(C, vector<int>(C, 0));
        long long ans = 0;

        for (int i = 0; i < R; ++i) {
            vector<int> ones;                       // 本行值为 1 的列号
            ones.reserve(C);
            for (int j = 0; j < C; ++j)
                if (grid[i][j] == 1) ones.push_back(j);

            int k = ones.size();
            for (int a = 0; a < k; ++a) {
                int j = ones[a];
                int* row = cnt[j].data();           // 固定 j，减少一次寻址
                for (int b = a + 1; b < k; ++b) {
                    int c = ones[b];
                    ans += row[c];                  // 与旧行配对：新增 row[c] 个矩形
                    ++row[c];                       // 再把本行登记进计数表
                }
            }
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def countCornerRectangles(self, grid: list[list[int]]) -> int:
        R, C = len(grid), len(grid[0])
        cnt = [[0] * C for _ in range(C)]     # cnt[j][k]：此前 j、k 两列同时为 1 的行数
        ans = 0

        for i in range(R):
            ones = [j for j in range(C) if grid[i][j] == 1]
            k = len(ones)
            for a in range(k):
                j = ones[a]
                row = cnt[j]                   # 固定 j，内层只做一次下标
                for b in range(a + 1, k):
                    c = ones[b]
                    ans += row[c]              # 先结算与旧行的配对
                    row[c] += 1                # 再登记本行

        return ans
```

## 8. 边界情况与易错点

1. **只有一行（或一列）**：矩形必须跨两行两列，$r_1<r_2$ 取不出来，答案必为 $0$。示例 3 即此情形。此时算法只是登记了若干 $cnt$，从不累加，天然输出 $0$，无需特判。
2. **先自增后累加**：把 `ans += row[c]` 与 `row[c] += 1` 交换顺序，同一行就会与自身配对。示例 2 会从 $9$ 变成 $18$，恰好翻倍——这是最隐蔽的错误，因为小规模上它看起来「只是多了一点」。
3. **含 $0$ 的列对被误枚举**：若为了图省事在内层用 `for c in range(C)` 而不是遍历 `ones`，仍然正确（这些列对 $cnt$ 恒 $0$），但每行退化成 $O(C^2)$，在 $200 \times 200$ 上多出一个数量级的常数；反过来若错把「只枚举 $ones$」当成「等价于跳过整行」，就真的会漏。
4. **对称写入重复计数**：如果同时维护 $cnt[j][k]$ 和 $cnt[k][j]$ 并在两个方向都累加，同一个矩形会被算两次。只维护 $j<k$ 的上三角最省心。
5. **要求四角互不相同**：题目明确四个 $1$ 必须互异。行列各取两个不同下标已保证这一点，因此**不要**对「同一行内两个 $1$」去配对本行的 $cnt$——那正是第 2 条错误。
6. **内部格子可以为 $0$**：本题只检查四个角；若误以为「矩形内部也必须是 $1$」，那就变成了另一道题（统计全 $1$ 子矩形），答案会偏小。
7. **空网格的防御**：约束保证 $R \ge 1$、$C \ge 1$，所以 `grid[0].size()` 是安全的；若把函数挪用到可能为空的场景，应在开头补 `if (grid.empty() || grid[0].empty()) return 0;`。
8. **答案规模**：约束下最大约 $8.77\times10^{6}$，`int` 够用；但若去掉「$1$ 的总数不超过 $6000$」这一条，$200\times200$ 全 $1$ 的答案是 $\binom{200}{2}^2 = 3.96\times10^{8}$，仍在 `int` 范围内，一旦维度放宽到 $10^3$ 就必须换 `long long`。

**延伸思考**：当网格变得稠密时，$\sum_i k_i^2$ 的瓶颈就回落到 $R \cdot C^2$。此时可以把每一列压成一个 bitset，对每个列对求交后取 `popcount`，单次操作从 $C$ 次访存降到 $R/64$ 个字，总代价 $O(C^2 \cdot R/64)$——$200$ 列时约 $6\times10^{4}$ 个机器字，比逐行枚举还快，而且不依赖「$1$ 的个数 $6000$」这条约束。更进一步，若题目变成「动态地逐格翻转 $0/1$ 并随时查询矩形数」，本篇的 $cnt$ 表就是天然的增量数据结构：翻转 $(r,c)$ 只影响包含该点的 $O(C)$ 个列对的 $cnt$ 值，可以做到 $O(C)$ 更新——这类「把二维计数摊到一维状态上」的思路，在矩形计数类问题里反复出现。
