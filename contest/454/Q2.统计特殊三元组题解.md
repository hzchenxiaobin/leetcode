# LeetCode 统计特殊三元组 题解

## 1. 题目概述

- **标题 / 题号**：统计特殊三元组（#3583，medium）
- **链接**：https://leetcode.cn/problems/count-special-triplets/
- **来源**：LeetCode 第 454 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums`，统计满足 $0 \le i < j < k < n$、$nums[i] = nums[j] \times 2$ 且 $nums[k] = nums[j] \times 2$ 的下标三元组 $(i, j, k)$（**特殊三元组**）的个数。答案可能很大，返回对 $10^9 + 7$ 取余后的结果。

**约束**：

- $3 \le n = |\mathrm{nums}| \le 10^5$
- $0 \le nums[i] \le 10^5$

## 2. 示例

**示例 1**

```text
输入：nums = [6,3,6]
输出：1
解释：唯一的三元组 (0,1,2)：nums[0] = 6 = 2×3，nums[2] = 6 = 2×3。
```

**示例 2**

```text
输入：nums = [0,1,0,0]
输出：1
解释：唯一的三元组 (0,2,3)：三个位置都是 0，满足 0 = 2×0。
      下标 1 的 1 既当不了中间点（数组里没有 2），也当不了两端
      （不存在值为 0.5 的中间点）。
```

**示例 3**

```text
输入：nums = [8,4,2,8,4]
输出：2
解释：(0,1,3)：nums[0] = nums[3] = 8 = 2×nums[1]；
      (1,2,4)：nums[1] = nums[4] = 4 = 2×nums[2]。
```

## 3. 解题思路

### 3.1 暴力思路

三重循环枚举 $(i,j,k)$ 逐一检验是 $O(n^3)$；退一步，只枚举中间点 $j$、向两侧线性扫描统计 $2 \cdot nums[j]$ 的出现次数，也是 $O(n^2)$。$n = 10^5$ 时 $O(n^2) \approx 10^{10}$ 次操作，任何语言都过不了。瓶颈在于"**两侧各有多少个 $2 \cdot nums[j]$**"这个查询是线性扫的——把它降到 $O(1)$ 就赢了。

### 3.2 核心观察：枚举中间点 + 前后缀计数

![核心观察：固定中间 j，左右独立计数](images/wc454_q2_core_idea.svg)

两个条件都锚定在**中间元素** $nums[j]$ 上，这是全题最关键的结构：

1. **固定 $j$ 后，$i$ 与 $k$ 完全独立**：$i$ 只要求"在左侧且值等于 $2v$"，$k$ 只要求"在右侧且值等于 $2v$"（$v = nums[j]$），两组约束互不干扰，任取合法 $i$ 与合法 $k$ 拼起来必然满足 $i < j < k$。由**乘法原理**，固定 $j$ 的贡献为

$$\text{left}_j[2v] \times \text{right}_j[2v]$$

其中 $\text{left}_j$ / $\text{right}_j$ 是**严格左 / 右两侧**的值计数。整体答案就是对所有 $j$ 求和。

2. **计数可以增量维护**：$j$ 从左往右移动时，每前进一格"左侧多一个元素、右侧少一个元素"——用两个计数数组各做一次 $+1$ / $-1$ 即可 $O(1)$ 转移，查询 $O(1)$。

> 💡 这是「枚举中间点」套路的标准形态：与 2909. 山形三元组（维护两侧前缀 / 后缀**最小值**）同构，只是把 min 换成了 count，再把"两侧取值"用乘法原理组合起来。

### 3.3 算法流程

![算法流程：一次遍历，左右计数器此消彼长](images/wc454_q2_flow.svg)

```text
1. right[x] 初始化为整个数组的值计数；left 全 0；ans = 0
2. for j = 0 .. n-1:
     v = nums[j]
     right[v] -= 1                  # 摘掉自己 → right 恰为 j 右侧计数
     t = 2 * v
     ans += left[t] * right[t]      # 乘法原理：固定 j 的贡献
     left[v] += 1                   # 收进自己 → left 恰为 j 左侧计数
3. 返回 ans mod (10^9 + 7)
```

三步的**顺序不能乱**：先把自己从 `right` 里摘出去，再查询，最后把自己收进 `left`——这保证查询时刻的两个计数器恰好描述严格两侧（见 §5 引理 2 的循环不变式）。

### 3.4 示例演算

![示例 3 逐个 j 的演算表](images/wc454_q2_walkthrough.svg)

以示例 3 `nums = [8,4,2,8,4]` 走一遍完整流程（见上图）：$j = 1$ 与 $j = 2$ 各贡献 1，$j = 0, 3$ 因两侧凑不出 $16$ 贡献 0，$j = 4$ 左侧虽有 2 个 8 但右侧为空、乘积为 0——合计 **2**，与期望一致。特别地，$j = 4$ 展示了乘法原理的"自动屏蔽"：任何一侧为 0，乘积就是 0，**不需要特判**。

## 4. 算法细节

1. **计数结构的选择**：值域 $0 \le nums[i] \le 10^5$，查询目标 $t = 2v \le 2 \times 10^5$，开两个长度 $2\max(nums) + 1$ 的 `int` 数组最快；若值域很大或含负数，换成 `unordered_map` / `dict`，思路与复杂度（均摊）不变。
2. **一次遍历同时维护两侧**：`right` 初始为全量计数、`left` 初始为空，处理每个元素时"摘右 → 查询 → 收左"。这样只用一趟循环，无需真的预处理出前后缀表。
3. **乘法用 64 位**：单个贡献上界约为 $\left(\frac{n}{2}\right)^2 = 2.5 \times 10^9$，超出 `int32`；C++ 里必须转 `long long` 再乘。
4. **取模时机**：总和上界为全 0 数组时的 $\binom{n}{3} \approx 1.67 \times 10^{14}$，`long long` 放得下，逐项取模或最后取模均可；Python 大整数无溢出，最后取一次即可。
5. **j 的有效范围**：真正可能有贡献的是 $1 \le j \le n-2$，但让 $j$ 跑满 $[0, n)$ 更简洁——两侧计数为 0 时贡献自然为 0。

## 5. 正确性证明

**引理 1**：固定中间下标 $j$，满足条件的 $(i,k)$ 对数恰为 $L_j \cdot R_j$，其中 $L_j = |\{\, i < j : nums[i] = 2\,nums[j] \,\}|$，$R_j = |\{\, k > j : nums[k] = 2\,nums[j] \,\}|$。

**证明**：合法 $i$ 的约束（$i < j$ 且取值）与合法 $k$ 的约束（$k > j$ 且取值）定义在互不相干的下标集合上，相互独立；且任取合法 $i$、$k$ 必有 $i < j < k$，自动满足 $i < k$。由乘法原理，配对数为 $L_j \cdot R_j$。∎

**引理 2**（循环不变式）：算法在处理 $j$ 的查询语句处，`left` 恰为 $nums[0..j-1]$ 的值计数，`right` 恰为 $nums[j+1..n-1]$ 的值计数。

**证明**：对 $j$ 归纳。$j = 0$：`left` 初始为空；`right` 初始为全量计数，执行 `right[nums[0]]--` 后恰为 $nums[1..n-1]$ 的计数，成立。设第 $j$ 轮查询时不变式成立：本轮末尾执行 `left[nums[j]]++`，故第 $j+1$ 轮查询前 `left` 为 $nums[0..j]$ 的计数；第 $j+1$ 轮先执行 `right[nums[j+1]]--`，`right` 由 $nums[j+1..n-1]$ 的计数变为 $nums[j+2..n-1]$ 的计数，不变式保持。∎

**定理**：算法返回值等于特殊三元组总数对 $10^9 + 7$ 取余的结果。

**证明**：全体特殊三元组按中间下标 $j$ 划分为两两不相交的类，类 $j$ 的大小由引理 1 为 $L_j \cdot R_j$。由引理 2，算法在处理 $j$ 时查询到的 `left[t]`、`right[t]`（$t = 2\,nums[j]$）恰为 $L_j$、$R_j$，故累加和恰为三元组总数。每步对 $10^9+7$ 取模不改变模意义下的值（或：总和不超过 $1.67 \times 10^{14}$，最后取模等价）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + V)$，其中 $V = 2\max(nums) \le 2 \times 10^5$。初始化 `right` 一次 $O(n)$，主循环每步 $O(1)$ 共 $O(n)$；计数数组按 $V$ 分配与清零。（用哈希表则为期望 $O(n)$。）
- **空间复杂度**：$O(V)$。两个计数数组共 $2(V+1)$ 个整数，约 1.6 MB，远低于限制。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int specialTriplets(vector<int>& nums) {
        constexpr long long MOD = 1'000'000'007;
        int maxV = *max_element(nums.begin(), nums.end());
        int m = 2 * maxV;
        vector<int> left(m + 1), right(m + 1);
        for (int x : nums) right[x]++;
        long long ans = 0;
        for (int v : nums) {
            right[v]--;
            int t = 2 * v;
            ans = (ans + (long long)left[t] * right[t]) % MOD;
            left[v]++;
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def specialTriplets(self, nums: List[int]) -> int:
        MOD = 10 ** 9 + 7
        m = 2 * max(nums)
        left = [0] * (m + 1)
        right = [0] * (m + 1)
        for x in nums:
            right[x] += 1
        ans = 0
        for v in nums:
            right[v] -= 1
            ans += left[2 * v] * right[2 * v]
            left[v] += 1
        return ans % MOD
```

## 8. 边界情况与易错点

1. **0 是自己的两倍**：$0 = 2 \times 0$ 成立，0 可以同时充当 $j$ 和两端；全 0 数组的答案是 $\binom{n}{3}$（$n = 10^5$ 时约 $1.67 \times 10^{14}$），**必须取模**。计数法天然正确，千万不要对 0 写特判分支。
2. **乘法溢出**：`left[t] * right[t]` 上界约 $2.5 \times 10^9$，超 `int32`；C++ 中必须转 `long long` 再乘（Python 无此问题）。
3. **计数数组开小**：查询目标是 $2v$ 而非 $v$，数组长度要开 $2\max + 1$；开成 $\max + 1$ 会越界（WA 或 RE）。
4. **三步顺序写反**：必须"先 `right[v]--`、再查询、最后 `left[v]++`"。顺序乱了会把 $j$ 自己算进某一侧，例如全 0 数组上会把答案算大。
5. **j 跑到边界**：$j = 0$ 时左侧空、$j = n-1$ 时右侧空，贡献为 0，无需特判跳过；这同时覆盖了 $n = 3$ 的最小规模。
6. **负数 / 大值域的变体**：本题 $0 \le nums[i] \le 10^5$ 才能用数组；若值可达 $10^9$ 或为负，改用哈希表，框架一字不改。
