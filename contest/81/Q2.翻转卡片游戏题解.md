# LeetCode 翻转卡片游戏 题解

## 1. 题目概述

- **标题 / 题号**：翻转卡片游戏（#822，medium）
- **链接**：https://leetcode.cn/problems/card-flipping-game/
- **来源**：LeetCode 第 81 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表

**题意**：桌上有 $n$ 张卡片，第 $i$ 张正面写着 `fronts[i]`、背面写着 `backs[i]`。允许先翻转**任意多张**卡片（可以一张都不翻），然后再指定一张卡片：若它此刻朝下的数字 $x$ 与**所有**卡片朝上的数字都不相同，则 $x$ 是一个「好数字」。求所有翻转方案下能得到的**最小**好数字；一个好数字都凑不出来时返回 $0$。

关键点是「翻转」只是一个**选择朝向**的自由度：每张卡片独立地二选一，翻或不翻互不干涉。

**约束**：

- $n = \text{fronts.length} = \text{backs.length}$，$1 \le n \le 1000$
- $1 \le \text{fronts}[i], \text{backs}[i] \le 2000$

## 2. 示例

**示例 1**

```text
输入：fronts = [1,2,4,4,7], backs = [1,3,4,1,3]
输出：2
解释：翻转下标 1 的卡片后，朝上的数是 [1,3,4,4,7]，朝下的数是 [1,2,4,1,3]。
      选下标 1 的卡片，它的背面是 2，且 2 不出现在任何卡片的朝上一面 → 2 是好数字。
      可以证明 2 是所有可行方案里最小的好数字。
```

**示例 2**

```text
输入：fronts = [1], backs = [1]
输出：0
解释：唯一一张卡片两面都是 1，怎么翻都有 1 朝上，因此没有任何好数字。
```

**示例 3（补充）**

```text
输入：fronts = [5,5,5], backs = [6,5,6]
输出：6
解释：下标 1 的卡片两面都是 5 → 5 被「封锁」；把 6 朝下的那两张保持不动即可，
      此时朝上恒为 5，朝下有 6 → 好数字只有 6。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是**枚举翻转方案**：每张卡片翻或不翻，共 $2^n$ 种组合；对每种组合统计朝上集合 $U$ 与朝下集合 $D$，答案取 $\min(D \setminus U)$。单次统计 $O(n)$，总复杂度 $O(2^n \cdot n)$。$n = 1000$ 时 $2^{1000}$ 是天方夜谭。

退一步，**枚举候选值** $x$（候选只可能来自 $2n$ 个数字），再花 $O(n)$ 判断「$x$ 能否成为好数字」，总复杂度 $O(n^2) = 10^6$，其实已经能过。但还能再降：判断过程会被大量重复计算，把它抽象成两个「标记」后，两遍线性扫描即可，而且不需要真的模拟任何翻转。

### 3.2 核心观察：两面同数 = 一票否决

![封锁判定：两面同数的卡片](images/wc81_q2_blocked_card_model.svg)

记**封锁集合**

$$S = \bigl\{\, \text{fronts}[i] \;\bigm|\; \text{fronts}[i] = \text{backs}[i] \,\bigr\}$$

即「某张卡片正反两面印着同一个数」时，那个数组成的集合。结论是：

$$x \text{ 能成为好数字} \iff x \text{ 至少在某个面上出现过，且 } x \notin S$$

- **必要性（封锁）**：若某张卡片 $i$ 有 $\text{fronts}[i] = \text{backs}[i] = x$，那么这张卡无论翻不翻，朝上的都是 $x$。于是 $x$ 永远「朝上」，永远不满足「与所有朝上的数字都不同」。
- **充分性（构造）**：若 $x$ 出现过且 $x \notin S$，按下面的规则翻转：**正面是 $x$ 的卡片全部翻过来，其余卡片一律不动**。这样每张卡片朝上的数都不是 $x$（正面是 $x$ 的翻完朝上变成背面数 $\ne x$，因为否则 $x \in S$；正面不是 $x$ 的朝上数本来就是 $\ne x$），而 $x$ 至少在某张卡片上朝下。

![构造方案：以 x = 2 为例](images/wc81_q2_flip_construction.svg)

> 💡 **一句话记忆**：「两面同数」是一票否决，因为它把 $x$ 焊死在朝上那一面，翻转只能交换同一张卡的两面，救不回来。

### 3.3 算法流程

![算法流程：扫一遍卡片，再扫一遍值域](images/wc81_q2_algorithm_flow.svg)

```text
第 1 遍（扫卡片，O(n)）：
    present[fronts[i]] = present[backs[i]] = true
    若 fronts[i] == backs[i]：blocked[fronts[i]] = true

第 2 遍（扫值域，O(V)，V = 2000）：
    v 从 1 递增到 2000
    若 present[v] 且 not blocked[v]：立即返回 v
    扫完仍未命中：返回 0
```

两个细节让第二遍特别省事：值域只有 $2000$，可以用**桶数组**代替哈希集合；而**按值从小到大**扫，第一个命中的 $v$ 天然就是最小值，不必再求 `min`。

### 3.4 示例演算

![示例演算：值视角逐个数判定](images/wc81_q2_walkthrough.svg)

以示例 1 为例（`fronts = [1,2,4,4,7]`，`backs = [1,3,4,1,3]`）：

| 卡片 | 正面 | 背面 | 是否封锁 | 记入 `blocked` |
|------|------|------|----------|----------------|
| 0 | 1 | 1 | 是（两面同数） | `blocked[1] = true` |
| 1 | 2 | 3 | 否 | — |
| 2 | 4 | 4 | 是（两面同数） | `blocked[4] = true` |
| 3 | 4 | 1 | 否 | — |
| 4 | 7 | 3 | 否 | — |

得到 $S = \{1, 4\}$，出现过的数为 $\{1, 2, 3, 4, 7\}$，候选为 $\{2, 3, 7\}$，最小值是 $2$，与预期一致。具体的翻法就是刚才的构造：只有下标 1 的卡片正面是 $2$，把它翻过来，于是朝上变成 `[1,3,4,4,7]`、朝下变成 `[1,2,4,1,3]`。

再看示例 3（`fronts = [5,5,5]`，`backs = [6,5,6]`）：下标 1 两面都是 $5$，故 $S = \{5\}$；候选只剩 $\{6\}$，答案为 $6$。这说明答案未必是「最小的数」——被封锁的数再小也用不上。

## 4. 算法细节

1. **封锁只由「同一张卡两面同数」触发**，与「某个数在正面出现过」毫无关系。$4$ 在示例 1 的正面出现了两次，但真正让 $4$ 出局的是下标 2 的卡片两面都是 $4$；如果那张卡是 $(4,5)$，$4$ 就仍可能当好数字（把它翻过去即可）。
2. **必须限制在「出现过的数」里**。如果偷懒只求「不在 $S$ 中的最小正整数」，那么 $S$ 里没有 $1$ 时会直接返回 $1$——可 $1$ 可能根本没印在任何卡片上，谈不上「朝下」。用 `present` 桶把范围锁死在真正出现过的数字上。
3. **答案可能只出现在 `fronts` 里**。$x$ 朝下有两种来源：未翻卡片的背面，或翻转后卡片的正面。例如 `fronts = [3,4]`、`backs = [4,5]`，答案是 $3$（翻下标 0 的卡片，朝上 $[4,4]$、朝下 $[3,5]$），而 $3$ 只出现在 `fronts` 中。只扫 `backs` 的写法会漏掉这类情况。
4. **值域桶优于排序**。$V = 2000$ 是常数级的，`vector<char>` 标记 + 顺序扫描是 $O(n + V)$；排序再找第一个可行值要 $O(n \log n)$，反而更慢，还多一份排序代码。
5. **循环边界要含上界**。值域是 $1 \le v \le 2000$，桶要开 `MAXV + 1` 个位置、循环写 `v <= MAXV`。写成 `v < MAXV` 时，像 `fronts = [1, 2, …, 999, 2000]`、`backs = [1, 2, …, 999, 999]` 这样的数据（前 $999$ 张卡两面同数、把 $1 \sim 999$ 全封锁，只剩 $2000$ 可当答案）会被错判成 $0$。
6. **不需要真的模拟翻转**。翻转只用于**证明可行性**；代码里全部是集合/桶的标记与查询，因此没有 $2^n$ 的枚举，也不存在「翻几次」的计数问题。
7. **重复数值无副作用**。同一个数在多张卡片上出现，`present` / `blocked` 只被置位一次，重复标记是幂等的；用哈希集合写法时 `set` 天然去重。
8. **`0` 可安全作为无解哨兵**。所有卡片数字都 $\ge 1$，$0$ 不可能是好数字，所以「返回 $0$」与「返回某个好数字」不会混淆。

## 5. 正确性证明

**引理 1（封锁的数一定不行）**：若存在卡片 $i$ 使 $\text{fronts}[i] = \text{backs}[i] = x$，则 $x$ 不是好数字。

**证明**：该卡片的两面都写着 $x$，翻转只是交换这两面，因此无论翻或不翻，它朝上的数字恒为 $x$。好数字要求 $x$ 不出现在任何朝上的位置，矛盾。∎

**引理 2（未封锁的数一定行）**：若 $x$ 出现在某张卡片的某一面上，且 $x \notin S$，则存在一种翻转方案使 $x$ 成为好数字。

**证明**：采用构造：对每张卡片 $i$，若 $\text{fronts}[i] = x$ 则翻转，否则不翻。

- 先证存在卡片使 $x$ 朝下。$x$ 出现在某张卡片 $i$ 上：若 $\text{fronts}[i] = x$，该卡被翻转，$x$ 转到朝下；若 $\text{backs}[i] = x$ 而 $\text{fronts}[i] \ne x$，该卡不翻，$x$ 原本就朝下；若两面都是 $x$，则 $x \in S$，与前提矛盾。三种情况至少命中其一，故 $x$ 确实在某张卡片上朝下。
- 再证没有卡片朝 $x$。任取卡片 $i$：若 $\text{fronts}[i] = x$，被翻转后朝上的数是 $\text{backs}[i]$，由 $x \notin S$ 知 $\text{backs}[i] \ne x$；若 $\text{fronts}[i] \ne x$，则不翻转，朝上的数就是 $\text{fronts}[i] \ne x$。两种情况下朝上数都不等于 $x$。

于是翻转完成后 $x$ 朝下且处处不朝上，是好数字。∎

**引理 3（候选集合恰为全部好数字）**：设 $P$ 为所有在 `fronts` 或 `backs` 中出现过的数，则「好数字之集」$= P \setminus S$。

**证明**：($\subseteq$) 好数字 $x$ 必须朝下于某张卡片，故 $x$ 必在某个面上出现过，即 $x \in P$；又由引理 1，$x \notin S$。( $\supseteq$ ) 对任意 $x \in P \setminus S$，引理 2 直接给出可行方案。∎

**定理**：算法返回的值等于最小可能好数字；当且仅当不存在好数字时返回 $0$。

**证明**：由引理 3，候选集合 $P \setminus S$ 恰好等于全部好数字之集。算法第二遍按 $v = 1, 2, \dots, 2000$ 递增扫描，返回第一个满足 `present[v] && !blocked[v]` 的 $v$——这既是好数字，又是所有好数字中的最小值。若扫描结束仍无命中，说明 $P \setminus S = \varnothing$，即不存在好数字，此时返回 $0$ 符合题意，且由第 4 节第 8 条，$0$ 不与任何真答案冲突。∎

## 6. 复杂度分析

- **时间**：$O(n + V)$，其中 $V = \max(\text{值域}) = 2000$。第一遍遍历 $n$ 张卡片，每张做常数次桶标记；第二遍最多扫描 $V$ 个值。由于 $V$ 是题目给定的常数，等价于 $O(n)$。哈希集合写法把第二遍换成遍历至多 $2n$ 个不同的数求最小值，期望 $O(n)$。
- **空间**：$O(V)$。两个长度 $2001$ 的 `char` 桶（`present` 与 `blocked`），约 $4$ KB；哈希写法为 $O(n)$ 的集合。均与 $n$ 同阶或更小。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int flipgame(vector<int>& fronts, vector<int>& backs) {
        const int MAXV = 2000;                    // 值域上界
        vector<char> blocked(MAXV + 1, 0);        // 两面同数 → 一票否决
        vector<char> present(MAXV + 1, 0);        // 是否在某个面上出现过
        int n = (int)fronts.size();
        for (int i = 0; i < n; ++i) {
            present[fronts[i]] = 1;
            present[backs[i]] = 1;
            if (fronts[i] == backs[i]) blocked[fronts[i]] = 1;
        }
        for (int v = 1; v <= MAXV; ++v) {         // 从小到大扫，首个命中即最小
            if (present[v] && !blocked[v]) return v;
        }
        return 0;                                 // 无好数字
    }
};
```

### Python

```python
class Solution:
    def flipgame(self, fronts: list[int], backs: list[int]) -> int:
        blocked = {f for f, b in zip(fronts, backs) if f == b}
        cand = [v for v in set(fronts) | set(backs) if v not in blocked]
        return min(cand) if cand else 0
```

## 8. 边界情况与易错点

1. **所有卡片两面同数**：如 `fronts = [1,2,3]`、`backs = [1,2,3]`，候选为空，必须返回 $0$，而不是返回某个「看起来没被封锁」的数。
2. **只有一张卡片且两面不同**：如 `fronts = [1]`、`backs = [2]`，翻转后朝上 $2$、朝下 $1$，答案是 $1$（较小的那个），不是 `backs` 里的 $2$。
3. **答案只出现在 `fronts` 中**：如 `fronts = [3,4]`、`backs = [4,5]`，答案是 $3$。误以为「答案一定来自某个背面」是本题最常见的错误。
4. **把「出现」误当成「封锁」**：某个数只要在正面出现过就排除，会漏掉大量可行答案（示例 1 中的 $2$ 就出现在正面）。
5. **忘记 `present` 过滤**：只求「不在 $S$ 中的最小正整数」时，未出现过的 $1$ 会被当答案返回，例如 `fronts = [5]`、`backs = [6]` 正确答案是 $5$。
6. **值域上界写成 `2000` 以外**：桶要开 $2001$ 个元素、循环要 `<= 2000`；`2000` 本身是合法取值，漏掉会让个别数据返回 $0$。
7. **以为需要真的翻转**：翻法是存在性证明的一部分，代码只需集合运算；若按 $2^n$ 枚举会直接超时。
8. **Python 注解兼容性**：`list[int]` 需要 Python 3.9+（LeetCode 判题环境满足）；若在更老的解释器上跑，去掉注解或改用 `List[int]`。
