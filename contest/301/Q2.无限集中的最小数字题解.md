# LeetCode 无限集中的最小数字 题解

## 1. 题目概述

- **标题 / 题号**：无限集中的最小数字（#2336，medium）
- **链接**：https://leetcode.cn/problems/smallest-number-in-infinite-set/
- **来源**：LeetCode 第 301 场周赛 Q2
- **难度**：中等
- **标签**：设计、有序集合、堆（优先队列）、哈希表

**题意**：维护一个初始包含**所有正整数** $\{1, 2, 3, \ldots\}$ 的集合，支持两种操作：`popSmallest()` **移除并返回**集合中的最小整数；`addBack(num)` 当且仅当 `num` **不在**集合中时，将一个 `num` **加回**集合。

**约束**：

- $1 \le \text{num} \le 1000$
- `popSmallest` 与 `addBack` **共计**至多调用 $1000$ 次

## 2. 示例

**示例 1**

```text
输入：
["SmallestInfiniteSet", "addBack", "popSmallest", "popSmallest", "popSmallest", "addBack", "popSmallest", "popSmallest", "popSmallest"]
[[], [2], [], [], [], [1], [], [], []]
输出：
[null, null, 1, 2, 3, null, 1, 4, 5]

解释：
addBack(2)     // 2 尚在集合中（还没弹出过任何数），无变化
popSmallest()  // 返回 1，集合变为 {2,3,4,...}
popSmallest()  // 返回 2，集合变为 {3,4,5,...}
popSmallest()  // 返回 3，集合变为 {4,5,6,...}
addBack(1)     // 1 已被弹出且不在集合中，加回，集合变为 {1,4,5,6,...}
popSmallest()  // 返回 1（最小值来自加回的 1），集合变为 {4,5,6,...}
popSmallest()  // 返回 4，集合变为 {5,6,7,...}
popSmallest()  // 返回 5，集合变为 {6,7,8,...}
```

**示例 2**（乱序加回，考察弹出顺序与「无操作」）

```text
输入：
["SmallestInfiniteSet","popSmallest","popSmallest","popSmallest","addBack","addBack","addBack","addBack","popSmallest","popSmallest","popSmallest"]
[[],[],[],[],[3],[1],[2],[5],[],[],[]]
输出：
[null,1,2,3,null,null,null,null,1,2,3]

解释：

addBack(5)：5 ≥ 4，5 仍在集合中，无操作
后三次 pop 依次返回 1、2、3 —— 加回的数必须按从小到大弹出
```

**示例 3**（重复加回同一个数）

```text

[[],[],[1],[1],[],[]]

解释：
popSmallest 返回 1；两次 addBack(1) 只有第一次生效（第二次时 1 已在集合中）；
```

## 3. 解题思路

### 3.1 暴力思路：布尔数组 + 线性扫描

维护布尔数组 `present[i]`（初值全 `true`，表示 $i$ 在集合中）：

- `popSmallest`：从 $1$ 开始**线性扫描**，找到第一个 `present[i] == true` 的 $i$，置 `false` 并返回；
- `addBack(num)`：直接 `present[num] = true`（若 `num` 已在集合中，这次赋值是**幂等**的，无副作用）。

由于至多 $1000$ 次调用，`popSmallest` 的返回值恒 $\le 1000$（§5 推论给出严格论证），数组开 $1001$ 即可。单次 `popSmallest` 最坏扫 $O(1000)$，总计约 $10^6$ 次基本操作，稳过。

> ⚠️ 暴力的问题不在超时，而在**把无限集显式存成了有限数组**：空间 $O(U)$，且「无限主体只需 $O(1)$ 表示」这一结构性质被完全掩盖。赛时当保底可以，复盘时应升华。

### 3.2 核心观察：连续尾指针 cur + 回收堆 S

![核心观察：连续尾压成指针 cur，加回元素进回收堆 S](images/infinite_set_threshold_model.svg)

**观察一：主干弹出永远有序。** `popSmallest` 每次取全局最小，所以从「主干」上弹掉的数恰是前缀 $1, 2, \ldots, \text{cur}-1$；主干剩余部分永远是**连续尾** $[\text{cur}, \text{cur}+1, \ldots, \infty)$——一个 `int` 指针 `cur` 就是主干的全部信息，**无需存储**。

**观察二：addBack 是唯一的离散偏差来源。** 被加回的 `num` 必然已被弹出（否则不需要加回），即 $\text{num} < \text{cur}$。这类数个数少、位置离散，用一个**有序集合** $S$（回收堆）单独收容。

两者拼起来，无限集被压缩为：

$$\text{集合} = S \cup \{\text{cur},\ \text{cur}+1,\ \text{cur}+2,\ \ldots\}, \qquad S \text{ 中元素全部} < \text{cur}$$

- `popSmallest` $= \min\big(\min S,\ \text{cur}\big)$：$S$ 非空先弹堆顶，否则返回 `cur` 并自增；
- `addBack(num)`：仅当 $\text{num} < \text{cur}$ 且 $\text{num} \notin S$ 时插入 $S$，其余情形无操作。

> 💡 这是「**理想连续态 + 少量偏差**」的压缩范式：主体压成 $O(1)$ 指针，只显式存偏差。空间与「偏离连续的程度」成正比，与集合的无限规模无关。

### 3.3 算法流程

![算法流程：popSmallest 与 addBack 的两路决策](images/infinite_set_ops_flow.svg)

1. **初始化**：`cur = 1`，$S$ 为空——对应「全体正整数都在集合中」；
2. **popSmallest**：若 $S$ 非空，弹出并返回 $\min S$；否则返回 `cur` 并令 `cur += 1`（吃掉连续尾最前端）；
3. **addBack(num)**：若 $\text{num} < \text{cur}$ 且 $\text{num} \notin S$，插入 $S$（回收）；若 $\text{num} \ge \text{cur}$（仍在连续尾中）或 $\text{num} \in S$（已被回收），无操作；
4. 两个操作都不遍历无限集，$O(\log |S|)$ 收工。

### 3.4 示例演算

![示例演算：8 次操作下 cur 与 S 的联动](images/infinite_set_walkthrough.svg)

对示例 1 的 8 次操作逐步走查（初始 `cur = 1`，`S = ∅`）：

| 步骤 | 操作 | cur（前→后） | S（前→后） | 返回 |
|------|------|--------------|------------|------|
| 1 | `addBack(2)` | 1 → 1 | { } | `null` |
| 2 | `popSmallest` | 1 → 2 | { } | `1` |
| 3 | `popSmallest` | 2 → 3 | { } | `2` |
| 4 | `popSmallest` | 3 → 4 | { } | `3` |
| 5 | `addBack(1)` | 4 → 4 | { } → {1} | `null` |
| 6 | `popSmallest` | 4 → 4 | {1} → { } | `1` |
| 7 | `popSmallest` | 4 → 5 | { } | `4` |
| 8 | `popSmallest` | 5 → 6 | { } | `5` |

注意**步骤 1**：`2 ≥ cur = 1`，2 还在连续尾里，加回是「无操作」；**步骤 6**：`cur = 4` 原地不动，最小值来自回收堆顶的 $1$（$1 < 4$），返回 $1$ 而非 $4$；步骤 7 才轮到 `cur` 自增取 $4$。两路来源在此交替。

## 4. 算法细节

1. **两个部件各司其职**：`cur`（`int`，初始 1）表示连续尾起点，**只增不减**；`S`（C++ `std::set<int>`）收容被加回的数。
2. **C++ 选 `std::set` 的理由**：一个容器同时提供「有序（`*begin()` 即最小）」与「去重（重复 `insert` 幂等）」。若用 `priority_queue` 必须再配一个 `unordered_set` 判重，否则重复 `addBack` 会让同一个数被弹出两次（见 §8 第 2 条）。
3. **`popSmallest` 只需判空，无需比较大小**：由不变式「$S$ 中元素恒 $< \text{cur}$」，$S$ 非空时 $\min S$ 必是全局最小，直接弹出即可。
4. **`addBack` 一行覆盖三种情形**：写 `if (num < cur) S.insert(num);`——`num ≥ cur` 时自然跳过；`num < cur` 且已在 $S$ 时 `insert` 幂等；只有真正缺席的数才入堆。
5. **数值上界**：`popSmallest` 至多 1000 次 ⇒ `cur` 至多增长到 1001；`num ≤ 1000`。全程 `int` 足够，无溢出风险。

## 5. 正确性证明

**引理（表示不变式）**：程序全程保持

- (I) 真实集合 $= S \cup \{n \in \mathbb{Z}^+ : n \ge \text{cur}\}$；
- (II) $S$ 中每个元素都 $< \text{cur}$。

**证明**：对操作次数归纳。初始 $S = \varnothing$、$\text{cur} = 1$，真实集合为全体正整数，(I)(II) 成立。设某次操作前 (I)(II) 成立，分情形考察：

1. `popSmallest` 且 $S \ne \varnothing$：由 (II) 知 $\min S < \text{cur}$，结合 (I)，$\{n \ge \text{cur}\}$ 部分的元素均 $\ge \text{cur} > \min S$，故全局最小元为 $\min S$。程序从 $S$ 删除 $\min S$ 并返回，真实集合恰移除 $\min S$，(I) 保持；`cur` 不变且 $S$ 只减不增，(II) 保持。
2. `popSmallest` 且 $S = \varnothing$：由 (I) 最小元为 `cur`。程序返回 `cur` 并令 `cur ← cur+1`，$\{n \ge \text{cur}\}$ 变为 $\{n \ge \text{cur}+1\}$，真实集合恰移除 `cur`；$S$ 仍为空，(I)(II) 保持。
3. `addBack(num)`：
   - $\text{num} \ge \text{cur}$：由 (I)，`num` 已在集合中，题意要求无操作，程序正确地无操作；
   - $\text{num} < \text{cur}$ 且 $\text{num} \in S$：`num` 已在集合中，`insert` 幂等，无实际变化；
   - $\text{num} < \text{cur}$ 且 $\text{num} \notin S$：由 (I)，`num` 既不属于 $\{n \ge \text{cur}\}$（因 $\text{num} < \text{cur}$）也不属于 $S$，确为缺席，插入 $S$ 与题意一致，且插入后仍满足 (II)。

三种情形均保持 (I)(II)，归纳完成。∎

**定理（正确性）**：对任意至多 1000 次的调用序列，每次 `popSmallest` 返回并移除的恰是当前集合的最小元，每次 `addBack` 恰在 `num` 缺席时插入——与题意完全一致。

**证明**：由引理，(I)(II) 全程成立；而引理证明的三个情形中已逐一验证每次操作的返回值与集合变更均符合题意。∎

**推论（暴力版的数组边界）**：`popSmallest` 的返回值恒 $\le 1000$。

**证明**：返回值要么是 $\min S \le 1000$（约束 $\text{num} \le 1000$），要么是 `cur`，而 `cur` 只在 `popSmallest` 的空堆分支自增，故返回 `cur` 时 $\text{cur} \le$ 此前 `popSmallest` 的调用次数 $+ 1 \le 1000$。因此布尔数组下标 $1 \sim 1000$ 已覆盖所有会被触碰的位置。∎

## 6. 复杂度分析

- **时间复杂度**：单次操作 $O(\log |S|)$。`popSmallest` 与 `addBack` 各只做一次有序集合的插入 / 删除 / 取最小，$|S| \le 1000$，单次约 $O(\log 1000) \approx 10$；总计 $O(q \log q)$，$q \le 1000$。暴力版单次 `popSmallest` 最坏 $O(1000)$、总计 $O(10^6)$，同样能过但更粗糙。
- **空间复杂度**：$O(|S|) \le O(1000)$。只存「偏差」不存主体——连续尾被压缩成一个 `int`，空间与集合的无限规模无关；对照暴力版必须开 $O(1001)$ 布尔数组，本方案在去掉 $\text{num} \le 1000$ 限制后依然成立。

## 7. 参考代码

### C++（std::set + 连续尾指针）

```cpp
class SmallestInfiniteSet {
    int cur = 1;      // 连续尾 [cur, ∞) 的起点，只增不减
    set<int> s;       // 回收堆：被 addBack 加回的数，全部 < cur

public:
    SmallestInfiniteSet() {}

    int popSmallest() {
        if (!s.empty()) {           // 堆非空 ⇒ 堆顶 < cur，必是全局最小
            int x = *s.begin();
            s.erase(s.begin());
            return x;
        }
        return cur++;               // 否则吃掉连续尾最前端
    }

    void addBack(int num) {
        if (num < cur) {            // num ≥ cur 时仍在连续尾中，无操作
            s.insert(num);          // set 自动去重，重复加回幂等
        }
    }
};
```

### Python（heapq + set 判重）

```python
import heapq


class SmallestInfiniteSet:

    def __init__(self):
        self.cur = 1           # 连续尾起点
        self.heap = []         # 回收堆（最小堆）
        self.in_heap = set()   # 与 heap 同步的成员表，用于判重

    def popSmallest(self) -> int:
        if self.heap:                  # 堆非空 ⇒ 堆顶 < cur
            x = heapq.heappop(self.heap)
            self.in_heap.remove(x)
            return x
        x = self.cur
        self.cur += 1
        return x

    def addBack(self, num: int) -> None:
        if num < self.cur and num not in self.in_heap:
            self.in_heap.add(num)
            heapq.heappush(self.heap, num)
```

### Python（布尔数组暴力，保底写法）

```python
class SmallestInfiniteSet:

    def __init__(self):
        self.present = [True] * 1001   # 下标 1..1000 已够，见 §5 推论

    def popSmallest(self) -> int:
        for i in range(1, 1001):
            if self.present[i]:
                self.present[i] = False
                return i

    def addBack(self, num: int) -> None:
        self.present[num] = True       # 幂等：已在集合中时无实际效果
```

## 8. 边界情况与易错点

1. **`num ≥ cur` 时必须忽略**：此时 `num` 仍在连续尾中，本就存在。若误入堆——尤其 `num == cur` 时——堆顶与 `cur` 相等，`popSmallest` 会先从堆弹出 `cur`、再从尾弹出同一个 `cur`，**同一个数被返回两次**。
2. **重复 `addBack` 同一个数**：C++ `set::insert` 天然幂等；Python 若只 `heappush` 不判重，堆中会积累重复元素，同样导致重复返回，必须配 `in_heap` 集合。
3. **先判空再取堆顶**：`popSmallest` 先判断 $S$ 非空再 `*begin()` / `heappop()`，顺序写反会在空容器上触发未定义行为 / 抛异常。
4. **不必比较堆顶与 `cur`**：不变式保证堆顶恒 $< \text{cur}$，判空即可；保留防御性的 `*s.begin() < cur` 检查不影响正确性，但属冗余分支。
5. **「无限集」≠ 开大数组**：决定资源上界的是**调用次数**（≤ 1000 ⇒ `cur ≤ 1001`、返回值 ≤ 1000），不是 `num` 的上界；初始化 $\{1, \ldots, 10^9\}$ 之类的写法纯属浪费。
6. **构造函数无需显式工作**：`cur = 1`、`S = ∅` 即初始状态，默认成员初始化即可完成。
