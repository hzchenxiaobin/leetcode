# LeetCode 移动片段得到字符串 题解

## 1. 题目概述

- **标题 / 题号**：移动片段得到字符串（#2337，medium）
- **链接**：https://leetcode.cn/problems/move-pieces-to-obtain-a-string/
- **来源**：LeetCode 第 301 场周赛 Q3
- **难度**：中等
- **标签**：双指针、字符串

**题意**：给定长度均为 $n$ 的字符串 `start` 与 `target`，只含 `'L'`、`'R'`、`'_'` 三种字符。`'L'` 片段当且仅当**左侧紧邻空位**时可向**左**移动一格；`'R'` 片段当且仅当**右侧紧邻空位**时可向**右**移动一格。每次移动一个片段、次数不限，判断 `start` 能否变成 `target`。

**约束**：

- $n = \text{start.length} = \text{target.length}$，$1 \le n \le 10^5$
- 两个串均只由 `'L'`、`'R'`、`'_'` 组成

## 2. 示例

**示例 1**

```text
输入：start = "_L__R__R_", target = "L______RR"
输出：true
解释：
- 第一个片段 L 向左一步：  "_L__R__R_" -> "L___R__R_"
- 最后一个片段 R 向右一步："L___R__R_" -> "L___R___R"
- 第二个片段 R 向右三步：  "L___R___R"  -> "L______RR"
```

**示例 2**

```text
输入：start = "R_L_", target = "__LR"
输出：false
解释：start 中的 R 只能右移一步得到 "_RL_"，随后无片段可动，永远得不到 "__LR"。
```

**示例 3**

```text
输入：start = "_R", target = "R_"
输出：false
解释：R 不能向左移动，而 target 中 R 的位置（0）在 start 中 R 的位置（1）左侧。
```

## 3. 解题思路

### 3.1 暴力思路：BFS 搜索所有可达状态

把每个字符串配置看成图上的一个节点，从 `start` 出发 BFS：每步枚举所有可移动的 `L`/`R` 滑入相邻空位生成新状态，看能否到达 `target`。但长度 $n$ 的串每个位置 3 种字符，状态数高达 $3^n$（精确地是 $\binom{n}{m} \cdot 2^m$，$m$ 为片段数），$n = 10^5$ 时完全不可行，记忆化、双向 BFS 也救不回来。

> ⚠️ 本题**只需判定可达性、不需要构造移动序列**——正确姿势是找一组**可快速验证的充要条件**，把"过程问题"变成"性质问题"。

### 3.2 核心观察：顺序不变，方向锁定位移

![核心观察：顺序不变，方向锁定位移](images/wc301_q3_direction_concept.svg)

**观察一（顺序不变）**：一次合法移动 = **片段与相邻空位交换**。片段从不与片段换位，因此把串中所有 `'_'` 抹掉后得到的 `L/R` 序列在整个过程中**一字不变**。于是 `start` 与 `target` 的去空位序列必须**完全相同**（片段数量、种类、次序全一致），且双方的第 $k$ 个片段天然一一配对。

**观察二（方向锁死位移）**：`L` 的每次移动使其下标恰好减 1，且**从不增加**；`R` 恰好加 1，从不减少。设第 $k$ 个片段在 `start` 中的下标为 $i_k$、在 `target` 中为 $j_k$：

- 配对是 `L`：只能向左走 ⇒ 必须 $i_k \ge j_k$（相等即已就位）；
- 配对是 `R`：只能向右走 ⇒ 必须 $i_k \le j_k$。

> 💡 直觉：`L` 全往左挤、`R` 全往右挤，方向**背道而驰**、互不挡路——只要每块各自"方向对"，就一定能各自滑到位；任一块方向不对，就永远无解。这一直觉的严格版本（必要性 + 充分性）见 §5。

### 3.3 算法流程：双指针逐对验证

![双指针判定流程](images/wc301_q3_two_pointer_flow.svg)

指针 `i` 走 `start`、`j` 走 `target`，每一轮：

1. 双方**跳过连续的 `'_'`**；
2. 若一方到末尾：返回 $i = n$ 且 $j = n$（恰一方耗尽 = 片段数不等 ⇒ `false`）；
3. 检查**身份**：`start[i] != target[j]` ⇒ `false`；
4. 检查**方向位置**：`L` 且 $i < j$、或 `R` 且 $i > j$ ⇒ `false`；
5. `i++`、`j++`，这一对配对成功，进入下一对。

循环自然退出（双方同时耗尽）⇒ 返回 `true`。

### 3.4 示例演算

![示例 1 演算](images/wc301_q3_walkthrough.svg)

对示例 1（`start = "_L__R__R_"`，`target = "L______RR"`）逐对走查：

| 配对 | 片段 | start 位 $i$ | target 位 $j$ | 判据 | 结果 |
|------|------|--------------|--------------|------|------|
| 1 | L | 1 | 0 | $i \ge j$ | ✓ 需左移 1 步 |
| 2 | R | 4 | 7 | $i \le j$ | ✓ 需右移 3 步 |
| 3 | R | 7 | 8 | $i \le j$ | ✓ 需右移 1 步 |

去空位序列双方均为 `LRR`，三对片段的方向位置全部合法 ⇒ 返回 `true`。

反例对照：示例 2 去空位序列 `RL` vs `LR`，第 1 对身份就不符；示例 3 序列同为 `R`，但 $i = 1 > j = 0$，`R` 无法向左 ⇒ `false`。

## 4. 算法细节

1. **外层循环条件**用 `i < n || j < n`：只要任一方还没比对完就继续；双方同时耗尽时循环自然退出、返回 `true`。
2. **末尾同步检查一行两用**：跳空位后若 `i == n || j == n`，返回 `i == n && j == n`——恰好一方耗尽说明**片段数不等**（`false`），双方同时耗尽说明**全部配对成功**（`true`，如 `start = target = "____"`）。
3. **身份检查** `start[i] != target[j]` 拦截片段种类或次序不一致（如 `RL` vs `LR`）；片段数量不等则由第 2 点的末尾检查拦截。
4. **方向检查**只查"越界方向"：`L` 且 $i < j$（需要向右）、`R` 且 $i > j$（需要向左）才返回 `false`；$i = j$ 表示已就位，合法。
5. **实现选型**：也可以先把两个串各自提取成 `(字符, 下标)` 列表再逐项比对，$O(n)$ 时间但 $O(n)$ 附加空间；双指针把附加空间压到 $O(1)$，且只扫一遍。
6. **判定与构造分离**：算法只验证三条性质，完全不模拟移动——§5 的构造性证明保证性质成立时移动序列必然存在。

## 5. 正确性证明

将片段按其在串中出现的顺序编号 $k = 1, \ldots, m$；$i_k$、$j_k$ 分别为第 $k$ 个片段在 `start`、`target` 中的下标（去空位序列相同时编号一一对应）。

**引理 1（必要性）**：若 `start` 可经若干次移动变为 `target`，则

- (a) 两串抹掉所有 `'_'` 后的 `L/R` 序列相同；
- (b) 对每个 $k$：片段为 `L` 时 $i_k \ge j_k$，为 `R` 时 $i_k \le j_k$。

**证明**：(a) 一次合法移动仅交换**片段与相邻空位**，非空字符组成的子序列在移动前后逐位相同，故任意可达配置的去空位序列与 `start` 的相同，`target` 作为可达配置亦然。(b) `L` 的每次移动使其下标恰减 1 且从不增加，故其下标随时间**单调不增**，终值不超过初值，即 $j_k \le i_k$；`R` 对称。∎

**引理 2（推进引理）**：某时刻的配置中第 $k$ 个片段位于 $c_k$，满足 (i) 片段序列与 `target` 的一致；(ii) 每个片段满足 `L`: $c_k \ge j_k$、`R`: $c_k \le j_k$。若存在错位片段（$c_k \ne j_k$），则**最左的错位 `L` 左侧一格必为空位**，**最右的错位 `R` 右侧一格必为空位**。

**证明**：证前半（后半对称）。设 $b$ 为最左的错位 `L`，由 (ii) 与错位知 $c_b > j_b$，故 $j_b \le c_b - 1$ 且 $c_b \ge 1$。若 $b = 1$：其余片段都在 $c_b$ 右侧，$c_b - 1$ 为空。若 $b > 1$：由顺序，能占据 $c_b - 1$ 的至多是第 $b-1$ 个片段，分两种情形——

- 第 $b-1$ 个片段**已就位**：它位于 $j_{b-1} < j_b \le c_b - 1$，严格在 $c_b - 1$ 的左侧，不占据；
- 第 $b-1$ 个片段**错位**：由 $b$ 的最左性它只能是错位 `R`，于是 $c_{b-1} < j_{b-1} < j_b \le c_b - 1$；若它恰在 $c_b - 1$，则 $c_{b-1} = c_b - 1 \ge j_b > j_{b-1} > c_{b-1}$，矛盾。

故 $c_b - 1$ 为空位。∎

**定理（充要性）**：`start` 可变为 `target` $\iff$ 条件 (a)、(b) 同时成立。

**证明**：⇒ 即引理 1。⇐ 设条件成立，对总偏差 $D = \sum_{k=1}^{m} |c_k - j_k|$ 作强归纳（初始 $c_k = i_k$）。$D = 0$ 时所有片段就位，配置即 `target`。$D > 0$ 时存在错位片段：若存在错位 `L`，取最左者，由引理 2 其左侧一格为空，令其左移一格——新配置仍满足 (i)（与空位交换不改变片段序列）与 (ii)（移动后仍有 $c_b - 1 \ge j_b$），且 $D$ 恰减 1；若不存在错位 `L`，则必存在错位 `R`，对称地移动最右者。每步 $D$ 严格减 1 且保持归纳前提，经 $D$ 步后 $D = 0$，到达 `target`。∎

> 💡 引理 2 的证明是典型的**"阻挡者分析"**：想动的那一格若被占，占据者要么已就位（待在目标处，而其目标在你的必经之路之外），要么是同向错位者（被"最左 / 最右"的选取排除）。这一技巧在许多构造题中反复出现。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`i`、`j` 各自单调前进，总步数不超过 $2n$；每轮的末尾 / 身份 / 方向三查均为 $O(1)$。
- **空间复杂度**：$O(1)$。只使用两个下标（不计输入串本身），远优于 BFS 的指数级状态空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canChange(string start, string target) {
        int n = start.size();
        int i = 0, j = 0;
        while (i < n || j < n) {
            while (i < n && start[i] == '_') i++;           // 跳过 start 的空位
            while (j < n && target[j] == '_') j++;          // 跳过 target 的空位
            if (i == n || j == n) return i == n && j == n;  // 片段数必须相等
            if (start[i] != target[j]) return false;        // 身份与顺序必须一致
            if (start[i] == 'L' && i < j) return false;     // L 只能左移
            if (start[i] == 'R' && i > j) return false;     // R 只能右移
            i++, j++;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canChange(self, start: str, target: str) -> bool:
        n = len(start)
        i = j = 0
        while i < n or j < n:
            while i < n and start[i] == '_':
                i += 1                       # 跳过 start 的空位
            while j < n and target[j] == '_':
                j += 1                       # 跳过 target 的空位
            if i == n or j == n:
                return i == n and j == n     # 片段数必须相等
            if start[i] != target[j]:
                return False                 # 身份与顺序必须一致
            if start[i] == 'L' and i < j:
                return False                 # L 只能左移
            if start[i] == 'R' and i > j:
                return False                 # R 只能右移
            i += 1
            j += 1
        return True
```

## 8. 边界情况与易错点

1. **片段数不等**：跳空位后恰好一方到末尾（如 `"_L"` vs `"L_"` 是 `true`，`"_L"` vs `"L__"` 不会出现——长度恒相等，但 `"_L"` vs `"R_"` 这类要靠身份检查拦截）。末尾检查必须写成 `return i == n && j == n`，不能无脑 `return true` / `false`——该表达式同时覆盖"单边耗尽（`false`）"与"双边同时耗尽（`true`）"。
2. **方向判据写反**：`L` 要求 $i \ge j$、`R` 要求 $i \le j$，赛时紧张极易颠倒，建议用示例 3（`"_R"` vs `"R_"`）自测。
3. **内层跳空位的越界保护**：`while (i < n && start[i] == '_')` 中的 `i < n` 不可省略，否则全空串会越界。
4. **全空串**：`start = target = "____"` 应返回 `true`，走"双边同时耗尽"分支。
5. **$i = j$ 是合法状态**：表示该片段已就位、无需移动，不要误判为非法。
6. **别去模拟移动**：BFS / 逐步模拟在 $n \le 10^5$ 下必然超时，本题是判定题不是构造题。
7. **序列相同 ≠ 可达**：即使去空位序列相同，仍要逐对检查方向位置——示例 3 就是"序列相同但位置非法"的典型。
