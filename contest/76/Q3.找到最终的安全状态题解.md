# LeetCode 找到最终的安全状态 题解

## 1. 题目概述

- **标题 / 题号**：找到最终的安全状态（#802，medium）
- **链接**：https://leetcode.cn/problems/find-eventual-safe-states/
- **来源**：LeetCode 第 76 场周赛 Q3
- **难度**：中等
- **标签**：深度优先搜索，广度优先搜索，图，拓扑排序，Kosaraju 算法，Tarjan 强连通分量算法

**题意**：给定 $n$ 个点的有向图，`graph[i]` 列出节点 $i$ 的全部出边终点。出度为 $0$ 的点称为**终端节点**；如果从 $u$ 出发的**每一条**路径都最终停在终端节点上，则 $u$ 是**安全节点**。返回所有安全节点，按编号**升序**排列。

**约束**：

- $n = \lvert\text{graph}\rvert$，$1 \le n \le 10^4$
- 边的总数在 $[1,\,4\times 10^4]$ 内，`graph[i]` 严格递增，允许自环
- 朴素地枚举路径是指数级的，必须做到 $O(n+m)$ 量级

## 2. 示例

**示例 1**

```text
输入：graph = [[1,2],[2,3],[5],[0],[5],[],[]]
输出：[2,4,5,6]
解释：节点 5、6 没有出边，是终端节点；
      2 → 5、4 → 5，2 与 4 的路径全部停在终端；
      而 0 → 1 → 3 → 0 构成环，0、1、3 都能走到环，都不安全。
```

**示例 2**

```text
输入：graph = [[1,2,3,4],[1,2],[3,4],[0,4],[]]
输出：[4]
解释：全图只有 4 是终端节点；0 → 1 → 2 → 3 → 0 构成环，
      节点 1 还带一条自环，0、1、2、3 都能走到环，因此只有 4 安全。
```

**补充（自环）**

```text
输入：graph = [[0]]
输出：[]
解释：节点 0 有一条指向自己的边，路径 0 → 0 → 0 → … 永不停止。
```

## 3. 解题思路

### 3.1 暴力思路

按定义做「记忆化搜索 + 反复松弛」：先标记所有终端节点安全，然后不断扫描全图，把「所有出边终点都已安全」的点也标成安全，直到某一轮不再有变化。

单轮扫描 $O(n+m)$，但最坏要 $O(n)$ 轮（安全状态像波纹一样一层层向内传播），总复杂度 $O(nm)=4\times10^8$，常数大、实现也容易写错；如果按定义真的去枚举每条路径，更是指数级。

另一个常见的错误直觉是「能到达终端节点就安全」。示例 1 中 $0 \to 1 \to 3 \to 0$ 成环，但 $0$ 也能通过 $0 \to 2 \to 5$ 走到终端——**存在**一条到终端的路径并不够，必须**所有**路径都到终端。

### 3.2 核心观察：安全 ⟺ 走不到环

![安全与环的关系](images/wc76_q3_safe_vs_cycle.svg)

把「所有路径都终止」翻译成图的局部性质，关键在于：**环是不安全的唯一来源**。

- 若 $u$ 能到达某个环上的点 $c$，那么沿 $u \to \cdots \to c$ 再在环上无限绕圈，就是一条永不终止的路径，$u$ 不安全。
- 若 $u$ 到不了任何环，则从 $u$ 出发的路径不会重复经过同一个点（重复即意味着路径内部已经成环），长度至多 $n-1$，必然停在某个终端节点上，$u$ 安全。

于是答案就是「走不到环」的点集。再补上一个关键等价：**$u$ 安全 $\iff$ $u$ 的每个出边终点都安全**（终端节点出边为空，是全称命题的真空成立情形）。这条等价让判定可以像拓扑排序一样**自终端节点向内逐层剥离**：把出度看作「还有多少条出边没有确认安全」，某点出度被清零的瞬间，它就被确认安全。

### 3.3 算法流程：反向图上的 Kahn

![反向拓扑剥离流程](images/wc76_q3_reverse_kahn_flow.svg)

1. 建**反图** `radj`：对每条 $u \to v$，把 $u$ 加入 `radj[v]`。
2. 出度计数器 `deg[u] = len(graph[u])`，即 $u$ 的出边条数。
3. 所有 `deg[u] == 0` 的点（终端节点）入队。
4. 反复取出队首 $u$，标记 `safe[u] = true`；对 `radj[u]` 中每个前驱 $p$ 执行 `deg[p] -= 1`（等价于删掉边 $p \to u$），若 `deg[p]` 恰好变成 $0$，则 $p$ 入队。
5. 队列空后，从未入队、`deg` 仍大于 $0$ 的点正是「环上或能走到环」的点。最后升序扫描 $0 \sim n-1$ 收集答案。

### 3.4 示例演算

![示例 1 走查](images/wc76_q3_walkthrough.svg)

对示例 1，初始 `deg = [2,2,1,1,1,0,0]`，队列为 $\{5,6\}$：

| 出队 | 前驱 | 结果 |
|------|------|------|
| 5 | 2, 4 | `deg[2]`、`deg[4]` 清零，2、4 入队 |
| 6 | 无 | 没有前驱，跳过 |
| 2 | 0, 1 | `deg[0]`、`deg[1]` 从 2 减到 1，不清零 |
| 4 | 无 | 跳过 |

结束时队列为空，残留的 `deg = [1,1,0,1,0,0,0]` 中为 $1$ 的正是 0、1、3，它们被 $0 \to 1 \to 3 \to 0$ 这个环互相支撑，永远不会清零。答案 `[2,4,5,6]`，与官方输出一致。

## 4. 算法细节

1. **反图只存前驱**：`radj[v]` 中放所有满足 $u \to v$ 的 $u$，这样剥离时才能「沿着边的反方向」找到受影响的点；正向的 `graph` 本身已经够用，不必再复制一份。
2. **用计数器代替真正删边**：直接修改邻接表会破坏输入，且删除操作的常数更大；`deg[p] -= 1` 与「删掉一条边」语义完全一致。
3. **入队条件写成 `--deg[p] == 0`**：因为每个节点至多出队一次、每条边只被处理一次，`deg` 单调递减且不会减到负数；若出现负数说明同一前驱被重复入队，是代码 bug 的信号。
4. **输出要升序，不能直接返回出队顺序**：出队顺序是拓扑序的一种（例如 `5,6,2,4`），题目要求按编号升序，所以最后必须再扫一遍 `0..n-1`。
5. **自环天然被覆盖**：`deg[u]` 把自环也算进出度，自环的边永远不会被「删除」（因为 $u$ 自己永远不可能出队），因此自环点以及能走到它的点都保持 `deg > 0`。
6. **等价的 DFS 三色写法**：`0` 未访问、`1` 在当前递归栈上、`2` 已确认安全。从 $u$ 出发时置 `1`，若某条出边指向状态 `1` 的点，说明路径内部成环，$u$ 不安全；否则回溯时置 `2`。它的复杂度同为 $O(n+m)$，但递归深度可达 $10^4$，Python 需要 `sys.setrecursionlimit` 或改写成显式栈，本解选择 BFS 就是为了规避这个坑。

## 5. 正确性证明

**引理 1（环判据）**：节点 $u$ 安全当且仅当从 $u$ 出发不可能到达任何有向环。

**证明**：若存在路径 $u \to \cdots \to c$ 且 $c$ 在环 $C$ 上，则沿环无限绕行得到一条永不终止的路径，它不到达任何终端节点，故 $u$ 不安全。反之，若 $u$ 到不了任何环，任取从 $u$ 出发的一条路径：路径上不会出现重复节点，否则重复点之间的片段就是一个从 $u$ 可达的环，矛盾；因此路径长度不超过 $n-1$，必然终止于某个出度为 $0$ 的终端节点，故 $u$ 安全。∎

**引理 2（计数器语义）**：算法运行期间，`deg[u]` 始终等于「$u$ 的尚未出队的出边终点个数」；每个节点至多入队一次。

**证明**：初始 `deg[u]` 等于出边总数，尚无节点出队，成立。每当 $v$ 出队，其对每个前驱 $p$ 的贡献恰好被减去一次，且 $v$ 只会出队一次（入队时出度计数器已降为 $0$，而它单调不增，不可能再次降到 $0$），归纳即得。∎

**引理 3（出队集 = 安全集）**：算法结束时，已出队的节点恰好是全部安全节点。

**证明**：先证「出队 $\Rightarrow$ 安全」，对出队顺序归纳。终端节点没有出边，任何路径长度为 $0$ 就终止，安全。若 $u$ 出队是因为它的全部后继都已出队，由归纳假设这些后继都安全，则从 $u$ 出发的任意路径第一步落到某个后继 $v$，其后的后缀从 $v$ 出发，由 $v$ 安全必然停在终端节点，故 $u$ 安全。

再证「安全 $\Rightarrow$ 出队」，反设安全点未出队，记未出队点集为 $U \neq \varnothing$。对任意 $u \in U$，由引理 2，若结束时 $\mathrm{deg}[u] = 0$ 则 $u$ 必已入队，矛盾，故 $\mathrm{deg}[u] \ge 1$，即至少存在一个后继 $v \notin$ 已出队集，也就是 $v \in U$。于是从任一 $u_0 \in U$ 出发，可以不断选出一个仍在 $U$ 中的后继，得到无限路径 $u_0, u_1, u_2, \dots$；$U$ 有限，路径中必有重复点，重复片段构成一个环 $C \subseteq U$，且 $C$ 从 $u_0$ 可达，由引理 1，$u_0$ 不安全，与 $u_0$ 安全矛盾。故所有安全点都出队。∎

**定理**：算法返回的数组恰好是图中全部安全节点，且按编号升序。

**证明**：由引理 3，`safe[u]` 为真的点与安全点集完全一致；第 5 步按 $0 \sim n-1$ 顺序扫描并收集，输出天然严格升序。∎

## 6. 复杂度分析

- **时间**：建反图遍历所有边一次，$O(n+m)$；初始化队列 $O(n)$；每个节点至多入队、出队一次，每条边在反图中至多被松弛一次，$O(n+m)$；最后升序扫描 $O(n)$。合计 $O(n+m)$，在 $n \le 10^4$、$m \le 4\times10^4$ 下不足 $10^5$ 次操作。
- **空间**：反图存放 $m$ 条边的另一份端点，$O(n+m)$；`deg`、`safe`、队列各 $O(n)$；不修改输入图。总计 $O(n+m)$。
- 若改用 DFS 三色法，额外需要 $O(n)$ 的递归栈（最坏深度 $n$），时间空间同阶。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> eventualSafeNodes(vector<vector<int>>& graph) {
        int n = graph.size();
        vector<vector<int>> radj(n);   // 反图：radj[v] = 所有指向 v 的前驱
        vector<int> deg(n);            // deg[u] = 尚未确认安全的出边条数
        for (int u = 0; u < n; ++u) {
            deg[u] = (int)graph[u].size();
            for (int v : graph[u]) radj[v].push_back(u);
        }

        queue<int> q;
        for (int u = 0; u < n; ++u)
            if (deg[u] == 0) q.push(u);   // 终端节点天然安全

        vector<char> safe(n, 0);
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            safe[u] = 1;
            for (int p : radj[u]) {
                if (--deg[p] == 0) q.push(p);   // p 的全部出边都安全
            }
        }

        vector<int> ans;
        for (int u = 0; u < n; ++u)
            if (safe[u]) ans.push_back(u);      // 升序
        return ans;
    }
};
```

### Python

```python
from collections import deque


class Solution:
    def eventualSafeNodes(self, graph: list[list[int]]) -> list[int]:
        n = len(graph)
        radj = [[] for _ in range(n)]
        deg = [0] * n
        for u in range(n):
            deg[u] = len(graph[u])
            for v in graph[u]:
                radj[v].append(u)

        q = deque(u for u in range(n) if deg[u] == 0)
        safe = [False] * n
        while q:
            u = q.popleft()
            safe[u] = True
            for p in radj[u]:
                deg[p] -= 1
                if deg[p] == 0:
                    q.append(p)

        return [u for u in range(n) if safe[u]]
```

## 8. 边界情况与易错点

1. **自环**：`graph[u]` 含 $u$ 时，$u$ 的出度里就有这条自环，它永远删不掉，$u$ 与所有能到达 $u$ 的点都不会出队——正是正确答案，不要为自环写特判。
2. **全图成环、没有终端节点**：初始队列为空，答案就是空数组，循环体一次都不执行，不能因为「队列为空」就误判为死循环或提前返回。
3. **单节点无出边**：`graph = [[]]` 返回 `[0]`；注意约束保证边数至少为 1，但 `graph[i]` 允许为空，不要假设一定存在出边。
4. **输出顺序**：出队顺序是拓扑序（例如 `5,6,2,4`），直接返回会得到错误答案，必须按编号升序重扫。
5. **「存在路径到终端」不等于安全**：只要有一条出边指向环上的点，该点就不安全，判定必须用「所有后继都安全」。
6. **不要就地删边**：`graph` 是调用方的数据，删除邻接表元素会污染后续调用；用 `deg` 计数器代替。
7. **改用 DFS 时的递归深度**：$n = 10^4$ 的链状图会让 Python 默认递归深度（1000）栈溢出，需要 `sys.setrecursionlimit(20000)` 或直接写成 BFS。

**延伸思考**：

1. 若把问题放宽成「**存在**一条路径到达终端节点」，只需从终端节点出发在**反图**上做一次可达性 BFS，$O(n+m)$ 即可。此时示例 1 的答案会膨胀成 $[0,1,2,3,4,5,6]$——连处在环上的 0、1、3 也会入选，因为 0 能经 2 走到 5，可见两种问题的最优解结构完全不同。
2. 若在每个安全节点上再问「它到终端节点的**最长**路径长度」，可以在剥离的拓扑序上倒着做 DP，`len[u] = 1 + max(len[v])`，终端节点为 0；由于安全子图无环，这个 DP 是良定义的。
3. 若把目标改成「删掉最少的点使剩余子图无环」，那是反馈点集问题（NP-hard），本题的线性剥离算法无法直接推广——这也是为什么题目只问「哪些点安全」。
