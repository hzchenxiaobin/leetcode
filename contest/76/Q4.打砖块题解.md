# LeetCode 打砖块 题解

## 1. 题目概述

- **标题 / 题号**：打砖块（#803，hard）
- **链接**：https://leetcode.cn/problems/bricks-falling-when-hit/
- **来源**：LeetCode 第 76 场周赛 Q4
- **难度**：困难
- **标签**：并查集、数组、矩阵

**题意**：有一个 $m \times n$ 的 0/1 网格，`1` 是砖块。一块砖**稳定**当且仅当它直接位于第 0 行，或它与某块稳定的砖四邻接（稳定性沿「稳定砖块链」向顶部传递）。按 `hits` 的顺序逐次消除指定位置的砖块（该位置可能是空白），每次消除后所有**因这次消除而失去稳定**的砖块立即掉落并从网格中消失（不会落到别的砖块上）。求每次消除对应掉落的砖块数。

**约束**：

- $1 \le m, n \le 200$，格子总数 $mn \le 4 \times 10^4$
- $\texttt{grid}[i][j] \in \{0,1\}$
- $1 \le \lvert \texttt{hits} \rvert \le 4 \times 10^4$，所有 $(x_i,y_i)$ 互不相同
- 消除可能打在一个空白格上，此时没有砖块掉落

## 2. 示例

**示例 1**

```text
输入：grid = [[1,0,0,0],[1,1,1,0]]，hits = [[1,0]]
输出：[2]
解释：初始稳定砖块为 (0,0)、(1,0)、(1,1)、(1,2) 共 4 块。
      消除 (1,0) 后，(1,1) 不再与顶部相连，(1,2) 只连着 (1,1)，
      两块一起失去稳定并掉落，故 result[0] = 2。
```

**示例 2**

```text
输入：grid = [[1,0,0,0],[1,1,0,0]]，hits = [[1,1],[1,0]]
输出：[0,0]
解释：消除 (1,1) 后 (1,0) 仍直接连在 (0,0) 下方，没有砖块失去稳定；
      再消除 (1,0)，(0,0) 依旧直接连接顶部，仍然什么都不掉。
```

## 3. 解题思路

### 3.1 暴力思路

每次消除后从第 0 行做一遍 BFS/DFS 求出当前稳定集合，用「消除前后的稳定集合之差」作为本次掉落数，把掉落的砖块从网格里抹掉，再继续下一次消除。单次 $O(mn)$，总计 $O(Hmn) = 4\times10^4 \times 4\times10^4 \approx 1.6\times10^9$ 次格子访问，必然超时。

更本质的困难是：**删砖相当于拆连通块**，而并查集只支持合并、不支持拆分，无法直接套用。

### 3.2 核心观察：把「删砖」倒放成「加砖」

![正向删砖与逆向加砖的对比](images/wc76_q4_forward_vs_reverse.svg)

既然「删除」不能合并，就**离线倒着做**：先把 `hits` 中所有位置上的砖块全部预先删掉，得到「最终局面」；在这个局面上一次性建好并查集；再**倒序**遍历 `hits`，把每块砖重新加回网格。

倒序过程中网格里的砖只增不减、连通块只合并不分裂，正好是并查集的用武之地。并且每加回一块砖，**稳定砖块数只可能变大**，新增的那部分正是「正序时这一次消除会被打掉的砖」，只差被恢复的那一块砖本身。

把天花板也放进并查集：开一个虚拟节点 `top`，让第 0 行的砖块全部与 `top` 合并，于是

$$\text{稳定砖块数} = \bigl|\text{top 所在连通块}\bigr| - 1,\qquad \texttt{ans}[i] = \max\bigl(0,\ \text{after} - \text{before} - 1\bigr)$$

其中 `before` / `after` 是恢复第 $i$ 块砖前、后 `top` 连通块的大小（已扣掉虚拟节点）。减去 1 是因为被恢复的那块砖自己被算进了增量，但它是「被打掉」而不是「掉落」。

### 3.3 算法流程

![并查集逆序处理流程](images/wc76_q4_union_find_flow.svg)

1. **预删**：拷贝 `g = grid`，对每个 `hit = (r,c)`，若 `g[r][c] == 1` 则置 `0`。原件 `grid` 保持不变，后面要用它判断「这个位置原本有没有砖」。
2. **虚拟天花板**：节点 `0 … mn-1` 对应格子，`top = mn`；`parent[i] = i`，`size[i] = 1`。
3. **建图**：扫描 `g`，第 0 行的砖块与 `top` 合并；每个砖块与其**右、下**相邻的砖块合并（等价于处理全部四邻接，且不重复）。
4. **倒序加砖**：`i` 从 $H-1$ 递减到 $0$：若 `grid[r][c] == 0`（原本是空白）则 `ans[i] = 0`；否则读 `before = size(find(top)) - 1`，把 `g[r][c]` 置回 1，`r == 0` 时与 `top` 合并，再与四个方向上现存的砖块合并；最后读 `after` 并令 `ans[i] = max(0, after - before - 1)`。
5. **返回** `ans`。答案虽在倒序时算出，但按下标 $i$ 写入，与正序顺序一致。

### 3.4 示例演算

![示例 1 的逆向走查](images/wc76_q4_walkthrough.svg)

以示例 1 为例（`grid = [[1,0,0,0],[1,1,1,0]]`，`hits = [[1,0]]`）：预删 `(1,0)` 后顶部连通块只有 $\{(0,0)\}$，`before = 1`；逆序恢复 `(1,0)` 后它同时接上 `(0,0)` 与 `(1,1)`，顶部连通块变成 $\{(0,0),(1,0),(1,1),(1,2)\}$，`after = 4`，于是 `ans[0] = max(0, 4-1-1) = 2` ✓。

示例 2 同理：预删 `(1,1)`、`(1,0)` 后只剩 `(0,0)`（稳定数 1）；逆序 `i=1` 恢复 `(1,0)` 后稳定数 2，`ans[1] = 0`；逆序 `i=0` 恢复 `(1,1)` 后稳定数 3，`ans[0] = 0`，得 `[0,0]` ✓。

一个必须靠 `max(0, ·)` 兜底的例子：`grid = [[1],[1],[1]]`、`hits = [[1,0],[2,0]]`。预删两块后只剩 `(0,0)`，稳定数 1；逆序恢复 `(2,0)` 时它上方为空、接不到天花板，稳定数仍是 1，`after-before-1 = -1` —— 这块砖其实**在更早的消除中就已经掉了**，正序这次消除什么都不会掉，钳到 0；再恢复 `(1,0)` 时把 `(2,0)` 一起救活，稳定数 3，`ans[0] = 1`，最终 `[1,0]` ✓。

## 4. 算法细节

1. **必须拷贝网格**：C++ 的 `grid` 是引用、Python 的 `list` 是可变对象，预删会污染入参；而逆序时要用**原始** `grid[r][c]` 判断「这里原本有没有砖」，两者不能共用同一个数组。
2. **`top` 的大小要扣掉**：`size[top]` 初值为 1，读稳定数统一写成 `size[find(top)] - 1`，忘记减 1 会让答案整体偏大。
3. **读数时机**：`before` 必须在任何 `union` 之前读，`after` 必须在恢复砖块并完成全部 `union` 之后读；中途读会让增量统计出错。
4. **`r == 0` 的特判**：恢复的砖块若在第 0 行，要额外与 `top` 合并；建图和逆序两处都得写，漏一处首行砖块就会「消失」。
5. **只补新边**：建图阶段一次性加入所有现存砖块之间的边，逆序时只补「被恢复砖块与四邻接」的边，不要每次重建并查集，否则退化回 $O(Hmn)$。
6. **并查集实现**：路径压缩 + 按大小合并即可；不必额外维护「是否连顶部」的标记——把 `top` 当普通节点合并进去，连通性天然正确。
7. **展平编号与整数范围**：`(r,c)` 编号为 `r * n + c`，与 `top = m * n` 不冲突；乘数是列数 `n`，写成 `m` 会串行。单次掉落数不超过 $mn \le 4\times10^4$，`int` 足够。

## 5. 正确性证明

记初始网格为 $G$，第 $i$ 次消除的位置为 $h_i=(r_i,c_i)$、该位置的初始砖块为 $b_i$（可能不存在）；记 $S_i$ 为正序处理完前 $i$ 次消除后**仍然存在且稳定**的砖块集合（$S_0$ 为 $G$ 的稳定砖块集），$f_i$ 为第 $i$ 次消除的掉落数。记 $R_i$ 为「在 $G$ 上把 $h_i,\dots,h_{H-1}$ 位置的砖块全部删掉」的网格，则 $R_0 = G$，$R_H$ 是预删完的最终局面，且 $R_i = R_{i+1} \cup \{b_i\}$。

**引理 1（稳定 ⇔ 与天花板连通）**：砖块 $x$ 稳定 $\iff$ 网格中存在一条完全由砖块组成的四邻接路径从 $x$ 通到第 0 行。故加入虚拟节点 `top`、把第 0 行砖块与之合并后，稳定砖块数恰为 $\bigl|\text{top 的连通块}\bigr|-1$。

**证明**：题面的稳定定义本身就是归纳式的——直接连顶部是基本情形，与稳定砖块相邻则把路径延长一条边，这正是「存在通往顶部的砖块路径」的归纳刻画；反之沿这样的路径从顶部归纳即知每块都稳定。并查集把每对相邻砖块、以及第 0 行砖块与 `top` 都合并，故其连通分量与网格连通分量一致。∎

**引理 2（单调性与逆向稳定集）**：若 $B \subseteq A$，则在 $A$ 中不稳定的砖块在 $B$ 中也不稳定；并且对每个 $i$，$R_i$ 的稳定砖块集合恰为 $S_i$。

**证明**：前半显然——$B$ 中的砖块路径也是 $A$ 中的砖块路径。

后半先证 $S_i \subseteq \operatorname{stab}(R_i)$：被 $h_0..h_{i-1}$ 删除的砖块都不在 $S_i$ 中，故 $S_i \subseteq R_i$；正序第 $i$ 步的网格是 $R_i$ 再挖掉更早掉落的砖块，是 $R_i$ 的子网格，$S_i$ 在其中稳定，由前半的逆否命题知它在超集 $R_i$ 中同样稳定。

再证 $\operatorname{stab}(R_i) \subseteq S_i$：设 $x \in R_i$ 在 $R_i$ 中稳定。$x$ 没被 $h_0..h_{i-1}$ 删除，故 $x \notin S_i$ 只有两种可能。(a) $x$ 在某次消除 $j<i$ 中掉落：那么 $x$ 在「$h_0..h_j$ 已删除、更早掉落的砖块尚未移除」的网格 $T_j$ 中不稳定，而 $R_i$ 只删了 $h_0..h_{i-1}$（包含 $h_0..h_j$），故 $R_i \subseteq T_j$，由前半知 $x$ 在 $R_i$ 中不稳定，矛盾。(b) $x$ 在 $G$ 中就不稳定：由 $R_i \subseteq G$ 同样矛盾。故 $\operatorname{stab}(R_i) = S_i$。∎

**引理 3（差值恒等式）**：设 `before`、`after` 为恢复 $b_i$ 前、后 `top` 连通块大小减 1，则 $f_i = \max(0,\ \text{after} - \text{before} - 1)$。

**证明**：分三种情形。（1）$\texttt{grid}[r_i][c_i] = 0$：$b_i$ 不存在，$R_i = R_{i+1}$ 即 `after = before`，正序时该位置是空的，$f_i = 0 = \max(0,-1)$。（2）$b_i$ 存在且 $b_i \in S_i$：正序第 $i$ 步删掉 $b_i$、再移除掉落的 $f_i$ 块，剩下的正是 $S_{i+1}$；被移除的砖块必然原本属于 $S_i$（只有稳定的砖才谈得上「失去」稳定），故 $|S_i| = |S_{i+1}| + 1 + f_i$，由引理 2 即得 $f_i = \text{after} - \text{before} - 1 \ge 0$。（3）$b_i$ 存在但 $b_i \notin S_i$：由引理 2，$b_i$ 在 $R_i$ 中也不稳定，加回它不会让任何砖块新连到 `top`，故 `after = before`；正序时该位置在本次消除前已经空了，$f_i = 0 = \max(0,-1)$。∎

**定理（算法正确性）**：算法输出等于各次消除的掉落砖块数。

**证明**：由引理 3，第 $i$ 次逆序迭代写入 `ans[i]` 的值等于 $f_i$，且答案写在下标 $i$ 而非追加到末尾，故输出顺序与正序一致。又因建图涵盖了 $R_H$ 的全部相邻关系、逆序每次只补新增的边，对 $i$ 从 $H$ 递减归纳可知任意时刻并查集的连通分量就等于当前网格 $R_i$ 的连通分量，引理 2、3 的前提始终成立。∎

## 6. 复杂度分析

- **时间**：$O\bigl((mn + H)\,\alpha(mn)\bigr)$。预删 $O(H)$；建图对 $mn$ 个格子做 $O(mn)$ 次合并；逆序最多 $H$ 块砖、每块常数次合并，并查集单次操作 $\alpha \le 5$。取 $mn = H = 4\times10^4$ 时操作量约 $10^5$ 量级。
- **空间**：$O(mn)$。`parent`、`size` 各 $mn+1$ 个整数，网格拷贝一份 $mn$ 个整数，答案数组 $O(H)$，其余为常数。

## 7. 参考代码

### C++

```cpp
class Solution {
    vector<int> parent, sz;

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];        // 路径压缩
            x = parent[x];
        }
        return x;
    }

    void unite(int a, int b) {
        a = find(a), b = find(b);
        if (a == b) return;
        if (sz[a] < sz[b]) swap(a, b);            // 按大小合并
        parent[b] = a, sz[a] += sz[b];
    }

public:
    vector<int> hitBricks(vector<vector<int>>& grid, vector<vector<int>>& hits) {
        int m = grid.size(), n = grid[0].size(), H = hits.size();
        vector<vector<int>> g = grid;             // 拷贝，保留原网格
        for (auto& h : hits)                      // ① 预先删掉所有被击中的砖块
            if (g[h[0]][h[1]] == 1) g[h[0]][h[1]] = 0;

        int top = m * n;                          // 虚拟天花板节点
        parent.resize(top + 1);
        iota(parent.begin(), parent.end(), 0);
        sz.assign(top + 1, 1);

        for (int r = 0; r < m; r++)               // ② 在最终局面上建并查集
            for (int c = 0; c < n; c++) {
                if (g[r][c] != 1) continue;
                int id = r * n + c;
                if (r == 0) unite(id, top);
                if (r + 1 < m && g[r + 1][c] == 1) unite(id, id + n);
                if (c + 1 < n && g[r][c + 1] == 1) unite(id, id + 1);
            }

        vector<int> ans(H, 0);
        for (int i = H - 1; i >= 0; i--) {        // ③ 倒序把砖块加回去
            int r = hits[i][0], c = hits[i][1];
            if (grid[r][c] == 0) continue;        // 原本就是空白，无砖可掉
            int before = sz[find(top)] - 1;
            g[r][c] = 1;
            int id = r * n + c;
            if (r == 0) unite(id, top);
            const int dr[4] = {1, -1, 0, 0}, dc[4] = {0, 0, 1, -1};
            for (int k = 0; k < 4; k++) {
                int nr = r + dr[k], nc = c + dc[k];
                if (nr >= 0 && nr < m && nc >= 0 && nc < n && g[nr][nc] == 1)
                    unite(id, nr * n + nc);
            }
            ans[i] = max(0, sz[find(top)] - 1 - before - 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def hitBricks(self, grid: list[list[int]], hits: list[list[int]]) -> list[int]:
        m, n = len(grid), len(grid[0])
        g = [row[:] for row in grid]              # 拷贝，保留原网格
        for r, c in hits:                         # ① 预先删掉所有被击中的砖块
            if g[r][c] == 1:
                g[r][c] = 0

        top = m * n                               # 虚拟天花板节点
        parent = list(range(top + 1))
        size = [1] * (top + 1)

        def find(x: int) -> int:
            while parent[x] != x:
                parent[x] = parent[parent[x]]     # 路径压缩
                x = parent[x]
            return x

        def union(a: int, b: int) -> None:
            ra, rb = find(a), find(b)
            if ra == rb:
                return
            if size[ra] < size[rb]:
                ra, rb = rb, ra                   # 按大小合并
            parent[rb] = ra
            size[ra] += size[rb]

        for r in range(m):                        # ② 在最终局面上建并查集
            for c in range(n):
                if g[r][c] != 1:
                    continue
                if r == 0:
                    union(r * n + c, top)
                if r + 1 < m and g[r + 1][c] == 1:
                    union(r * n + c, (r + 1) * n + c)
                if c + 1 < n and g[r][c + 1] == 1:
                    union(r * n + c, r * n + c + 1)

        ans = [0] * len(hits)
        for i in range(len(hits) - 1, -1, -1):    # ③ 倒序把砖块加回去
            r, c = hits[i]
            if grid[r][c] == 0:                   # 原本就是空白，无砖可掉
                continue
            before = size[find(top)] - 1
            g[r][c] = 1
            if r == 0:
                union(r * n + c, top)
            for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                nr, nc = r + dr, c + dc
                if 0 <= nr < m and 0 <= nc < n and g[nr][nc] == 1:
                    union(r * n + c, nr * n + nc)
            ans[i] = max(0, size[find(top)] - 1 - before - 1)
        return ans
```

## 8. 边界情况与易错点

1. **消除位置原本是空白**：必须用原始 `grid` 判断后直接填 0。若用预删后的 `g`，就把「原本没有砖」和「有砖但已被预删」混为一谈，答案全错。
2. **砖块更早掉落**：恢复的砖块可能接不到天花板，此时 `after == before`、`after - before - 1 = -1`，**必须与 0 取 max**，否则输出负数（`[[1],[1],[1]]` 配 `hits=[[1,0],[2,0]]` 可复现）。
3. **第 0 行**：建图与恢复两处都要处理 `r == 0` 时与 `top` 合并；只写一处会让首行砖块在逆序阶段统计丢失。
4. **单行 / 单列网格**：$m=1$ 没有下方邻居、$n=1$ 没有右邻，建图的 `r + 1 < m`、`c + 1 < n` 判断不能省，否则越界。
5. **不要就地改 `grid`**：C++ 的 `vector<vector<int>>&` 与 Python 的 `list` 都是引用语义，预删会污染入参，逆序时就读不到「原本有没有砖」。
6. **不要每次重建并查集**：预删 + 一次建图 + 逆序补边才是线性；逆序重建会退回 $O(Hmn)$。

**延伸思考**：若把「掉落消失」改成「掉落后堆叠在其他砖块上」，砖块位置会变化，本题「前后稳定数之差」不再成立，需要逐列模拟重力；若 `hits` 必须**在线**回答（不能先读完整个序列再离线倒放），就要支持删点的动态连通性，可用**线段树分治 + 可撤销并查集**：把每条「相邻砖块边」的存活区间挂到时间轴上，$O((mn+H)\log H\,\alpha)$ 即可；若只问「每次消除后还剩多少块稳定砖」，逆序同样只需在恢复前读一次 `before`，连减法都省了。
