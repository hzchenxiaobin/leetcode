# LeetCode 十-二进制数的最少数目 题解

## 1. 题目概述

- **标题 / 题号**：十-二进制数的最少数目（#1689，medium）
- **链接**：https://leetcode.cn/problems/partitioning-into-minimum-number-of-deci-binary-numbers/
- **来源**：LeetCode 第 219 场周赛 Q2
- **难度**：中等
- **标签**：贪心、字符串、数学

**题意**：**十-二进制数（deci-binary）**指十进制书写下每一位都是 $0$ 或 $1$ 的正整数（如 $101$、$1100$；$112$、$3001$ 不是）——十进制的外壳、二进制的数位。给定表示正整数的字符串 $n$（可长达 $10^5$ 位），返回和恰好等于 $n$ 的十-二进制数的**最少数目**（同一数可重复使用）。

**约束**：

- $1 \le |n| \le 10^5$，$n$ 仅由数字字符组成，无前导零，恒表示正整数。

> 💡 一句话心法：竖式加法**逐列**看，每个数在每一列至多贡献 $1$，于是**最大数位**就是瓶颈——答案是 $d^* = \max_i x_i$，一行 `max` 收工。本题难点不在写代码，而在识破「数值思维」的陷阱（$n$ 有 $10^5$ 位）并给出严谨的两边夹证明。

```text
解释：最大数位是 8；11111 + 11111 + 10111 + 10101 + 10100 + 10100 + 10100 + 10000 = 82734。
```

## 3. 解题思路

### 3.1 暴力思路：一切「数值思维」都撞墙

$n$ 长达 $10^5$ 位，数值本身远超任何 64 位类型：

- **转整数**：C++/Java 直接溢出或抛异常；Python 大整数能转，但后续任何按数值分解的做法都已跑偏。
- **搜索 / 最短路**：从 $n$ 出发每步减一个十-二进制数（每个候选的每一位独立选 $0/1$，呈 $2^{|n|}$ 指数级），状态是天文数字，不可行。
- **贪心减「不超过剩余的最大十-二进制数」**：看似合理，实则又慢又错——如 $82734$ 反复减 $11111$（$7$ 次）再依次转 $1111$、$111$、$11$、$1$，最终要 $24$ 个数，而正确答案是 $8$。错因：它把「多列**同时**各降 $1$」误当成「找数值上最大的一个数」，各数位没有对齐地一起消耗。

正确的模拟是**逐层剥离**：每一轮在**所有剩余值非零的数位上同时放 $1$**（即减去「非零数位处为 $1$、其余为 $0$」的数），$O(d^* \cdot |n|)$ 内清零。模拟几轮就会发现：**轮数恰好等于最大数位**——这就是通往一行解的桥。

### 3.2 核心观察：竖式逐列独立，瓶颈是最大数位

![核心观察：竖式逐列看，每个数在每列至多贡献 1](images/1689_column_addition_concept.svg)

把 $k$ 个十-二进制数**右对齐竖式相加**，逐列考察：

- 每个数在每一列的数字只能是 $0$ 或 $1$，即**每个数在每列至多贡献 $1$**；
- 若每列的列和都不超过 $9$，竖式**永不进位**，于是和的每一位**恰等于该列中 $1$ 的个数**（第 5 节引理 1）。

于是双向都清楚了：

- **下界**：设最大数位 $d^* = \max_i x_i$ 出现在位置 $p$。要让和的第 $p$ 位达到 $d^*$，该列必须有 $d^*$ 个数在此放 $1$，故 $k \ge d^*$；
- **上界**：存在只用 $d^*$ 个数的构造（见 3.3）。

两边一夹，答案就是 $d^*$。例如 $32 = 10 + 11 + 11$：十位列 $1+1+1=3$、个位列 $0+1+1=2$，最大数位 $3$ 恰好就是数的个数。

### 3.3 构造：数位是积木塔，逐层剥离 $d^*$ 轮必清零

![构造：数位画成积木塔，每轮横切一层](images/1689_block_peeling_construction.svg)

把每个数位 $x_i$ 画成一座高 $x_i$ 的**积木塔**，第 $t$ 层（自底向上）对应第 $t$ 个数 $b_t$：位置 $i$ 的第 $t$ 层格子存在，当且仅当 $x_i \ge t$。规则即

$$b_t \text{ 的第 } i \text{ 位} = \bigl[\,x_i \ge t\,\bigr] \in \{0, 1\}, \qquad t = 1, 2, \dots, d^*.$$

- 每个 $b_t$ 的数字全在 $\{0,1\}$，是合法的十-二进制数，且 $b_t \ge 1$（最大数位位置全程有格子）；
- 每列的列和满足**层饼恒等式** $\sum_{t=1}^{d^*} [x_i \ge t] = x_i$（高为 $x_i$ 的塔恰被切走 $x_i$ 层），由引理 1 无进位，故 $\sum_t b_t$ 与 $n$ **逐位相等**；
- $d^*$ 轮后所有塔清零，且不可能更早——最高那座塔必须削 $d^*$ 层。

以 $n = 324$ 为例：塔高 $3, 2, 4$，四层切片分别是 $111, 111, 101, 001$，验证 $111 + 111 + 101 + 1 = 324$，用 $4$ 个数 $=$ 最大数位 $4$。

**算法流程**由此坍缩成一次扫描：

```text
ans ← 0
for c in n:             # 遍历数字字符
    ans ← max(ans, c)   # 字符序即数值序
return ans − '0'        # 最大数位
```

### 3.4 示例演算

![示例演算：n = 82734 的逐层剥离走查](images/1689_peeling_walkthrough_82734.svg)

以官方示例 2 的 $n = 82734$（数位 $8,2,7,3,4$，$d^* = 8$）走查逐层剥离（见上表）：第 1、2 轮所有数位非零，连取两个 $11111$；千位第 2 轮后归零，此后取数依次变为 $10111 \to 10101 \to 10100$；万位这座「最高塔」撑满全部 $8$ 轮，最后一轮取 $10000$ 清零。共 $8$ 个数，且 $11111 \times 2 + 10111 + 10101 + 10100 \times 3 + 10000 = 82734$。轮数被万位（$= 8 = d^*$）卡死，正是「瓶颈列决定答案」的直观体现。

## 4. 算法细节

1. **只需求最大数位**：一次扫描 `ans = max(ans, n[i] - '0')`；利用数字字符的字典序与数值序一致，整个串的最大字符即最大数位——C++ 写 `*max_element(n.begin(), n.end()) - '0'`，Python 的 `max(n)` 返回的就是最大数字字符。
2. **全程按字符串处理**：$|n| \le 10^5$，任何 `stoi` / `parseInt` / `int(n)` 都是错误方向（前两者直接爆，后者无必要）；比较与计数都发生在字符层面。
3. **构造方案（若变体要求输出方案）**：按 3.3 的层饼规则生成 $d^*$ 个串，$O(d^* |n|)$；生成的串可能带前导零（如 `001`），作为**数值**仍是合法十-二进制数，输出时去前导零即可，且每个串至少含一个 $1$（最大数位位置全程在层内）。
4. **无进位的隐藏红利**：$d^* \le 9$ 自动保证每列列和 $\le 9 < 10$，竖式不进位——这是「列和即数位」成立的结构性原因；推广到 $b$ 进制（$b > 10$）时，同样论证对 $d^* \le b-1$ 依然成立。
5. **「减 repunit」的坑**：逐层剥离减的**不是**定长的 $111\cdots1$，而是「非零数位处为 $1$」的动态 mask；若在已为 $0$ 的数位上继续减，会引发借位，模拟结果全错。

## 5. 正确性证明

**引理 1**（列和无进位）：将 $k$ 个非负整数右对齐做竖式加法。若每一列的列和都不超过 $9$，则全过程不产生进位，和的每个数位恰等于对应列的列和。

**证明**：对数位位置从低到高归纳。个位列没有进位输入，列和 $\le 9 < 10$，故该位结果为列和本身且不产生进位；设第 $j$ 列没有进位输入，则其列和 $\le 9 < 10$，该位结果同样为列和且不进位。归纳遍历所有列。∎

**引理 2**（下界）：设 $n$ 的数位为 $x_{L-1} \cdots x_0$，最大数位 $d^* = \max_i x_i \ge 1$。若 $k$ 个十-二进制数之和为 $n$，则 $k \ge d^*$。

**证明**：$d^* \le 9$。若 $k \ge 9$，则 $k \ge d^*$ 已成立；下设 $k \le 8$。将这 $k$ 个数与 $n$ 右对齐（$n$ 高位视作补零），竖式相加时每列至多 $k$ 个 $1$，列和 $\le k \le 8 \le 9$，由引理 1 全程无进位，故和的每个数位恰等于该列中 $1$ 的个数，至多 $k$。设 $d^*$ 位于 $n$ 的位置 $p$，则和的第 $p$ 位 $\le k < d^*$，与「和 $= n$（第 $p$ 位为 $d^*$）」矛盾。∎

**引理 3**（上界 / 构造）：存在 $d^*$ 个十-二进制数之和恰为 $n$。

**证明**：对 $t = 1, \dots, d^*$，令 $b_t$ 的第 $i$ 位为 $[\,x_i \ge t\,]$。每位取值属于 $\{0,1\}$，故 $b_t$ 是十-二进制数；取满足 $x_p = d^*$ 的位置 $p$，则对所有 $t \le d^*$ 均有 $x_p \ge t$，即 $b_t$ 在位置 $p$ 为 $1$，故 $b_t \ge 10^p \ge 1$。对任意列 $i$，列和为 $\sum_{t=1}^{d^*} [x_i \ge t] = x_i \le 9$（满足 $1 \le t \le x_i$ 的 $t$ 恰有 $x_i$ 个），由引理 1 无进位，$\sum_t b_t$ 的每个数位恰为 $x_i$，故 $\sum_{t=1}^{d^*} b_t = n$。∎

**定理**：和为 $n$ 的十-二进制数的最少数目为 $d^* = \max_i x_i$，即 $n$ 的最大数位。

**证明**：由引理 2，任何可行方案中数的个数 $k \ge d^*$；由引理 3，$k = d^*$ 可行。故最小值恰为 $d^*$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(|n|)$——单次扫描取最大数位，$|n| \le 10^5$。
- **空间复杂度**：$O(1)$——仅常数个变量（不计输入串本身）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minPartitions(string n) {
        // 数字字符的字典序 = 数值序，最大字符即最大数位
        return *max_element(n.begin(), n.end()) - '0';
    }
};
```

### Python

```python
class Solution:
    def minPartitions(self, n: str) -> int:
        return max(map(int, n))   # 或直接 max(n)：字符序即数值序
```

两版均为一次扫描 $O(|n|)$；显式循环 `ans = max(ans, c - '0')` 与之等价。

## 8. 边界情况与易错点

1. **千万别把 $n$ 转成数值**：$10^5$ 位下 C++ `stoi/stoll` 抛异常或溢出、Java `parseInt` 抛 `NumberFormatException`；Python `int(n)` 能转但纯属多余。全程序只做字符比较。
2. **「减最大十-二进制数」的贪心是错的**：$82734$ 按该贪心需 $24$ 个数（$11111 \times 7$ 后转 $1111 \times 4$、$111 \times 4$、$11 \times 6$、$1 \times 3$），远多于 $8$。正确心法是「每列同时剥一层」（mask 对齐所有非零数位），不是「挑数值最大的一个数」。
3. **0 数位提前完工**：某列归零后，后续轮次该位放 $0$（如 $82734$ 的千位第 2 轮后恒为 $0$）；若每轮盲减等长 $111\cdots1$，会在 $0$ 位产生借位，模拟直接崩坏。
4. **答案与「位数 / 非零数位个数」无关**：`"222"` 的答案是 $2$ 不是 $3$；`"100"` 的答案是 $1$。读题先盯「最大数位」。
5. **单字符与全 1 串**：`"1"`–`"9"` 答案即该数字；`n = "111…1"` 答案为 $1$。扫描写法天然覆盖，无需特判。
6. **答案范围 $[1,9]$**：$n$ 无前导零 $\Rightarrow$ 首位 $\ge 1 \Rightarrow$ 至少一个数；数位上界 $9$。返回 `int` 绰绰有余，不要数组、不要 DP。
7. **构造串的前导零**：按层饼规则生成的 $b_t$ 可能形如 `001`，作为数值合法（写作 $1$）；题目只约束 $n$ 无前导零，加数按数值理解即可。
