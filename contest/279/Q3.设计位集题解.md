# LeetCode 设计位集 题解

## 1. 题目概述

- **标题 / 题号**：设计位集（#2166，medium）
- **链接**：https://leetcode.cn/problems/design-bitset/
- **来源**：LeetCode 第 279 场周赛 Q3
- **难度**：中等
- **标签**：设计、数组、位运算

**题意**：
实现 `Bitset` 类，维护一个长度为 `size` 的 01 串（初始全 `0`）：`fix(idx)` / `unfix(idx)` 将单点置 `1` / 置 `0`（已处于目标值则不变），`flip()` **整体翻转**每一位，`all()` / `one()` / `count()` 查询「是否全 1 / 是否存在 1 / 1 的个数」，`toString()` 输出整串（第 $i$ 个字符对应第 $i$ 位）。

**约束**：

- $1 \le \text{size} \le 10^5$
- $0 \le \text{idx} \le \text{size} - 1$
- 至多调用 `fix`、`unfix`、`flip`、`all`、`one`、`count`、`toString` **总共** $10^5$ 次
- 至少调用 `all`、`one`、`count`、`toString` 方法一次
- **至多调用 `toString` 方法 $5$ 次**

> 💡 本题在本仓库另有[每日题解 2166](../../solution/2101-2200/2166_设计位集.md)：主线同为「懒惰翻转标志」。本篇按**周赛复盘视角**展开：以两条不变量为纲的引理–定理证明链、`fix`/`unfix`「翻译规则」的统一推导、双哈希集合 `swap` 的替代实现，以及镜像视角漂移、双重修正等赛场易错清单。同场 Q1（#2164）是奇偶下标分组排序的签到题，Q2（#2165）是数位贪心，Q3 换成设计题考**摊还思想**，Q4（#2286）是前后缀 DP——本场从 Q3 开始上强度。

## 3. 解题思路

### 3.1 暴力思路：直接维护位数组

开一个 0/1 数组照字面实现：`fix`/`unfix` 单点赋值 $O(1)$；`all`/`one`/`count` 用一个 `ones` 计数变量也能 $O(1)$；但 `flip()` 要**改变每一个位**，只能逐位 `bits[i] ^= 1`，单次 $O(n)$。

总调用 $\le 10^5$ 次、$n \le 10^5$，最坏 $\tfrac{10^5}{2} \times 10^5 = 5 \times 10^9$ 次位写，必然 TLE。瓶颈**唯一且显眼**：`flip`。反过来细读约束会发现出题人留的活路：`toString` 被特殊限定**至多 5 次**——整串遍历级别的 $O(n)$ 操作被刻意豁免，而 `flip` 没有这种豁免，必须找到 $O(1)$ 的替代语义。

### 3.2 核心观察：懒惰翻转——逻辑视图 = 物理位 ⊕ flipped

![核心：flip() 只翻一个标志，物理数组一字不动](images/2166_bitset_lazy_flip_concept.svg)

关键洞察：`flip()` 真正改变的只有「当前是否处于反转视角」这一事实。引入布尔标志 `flipped`（初值 `false`），数组 `bits[]` 始终存**物理状态**，用户看到的**逻辑状态**为

$$\text{logical}[i] = \text{bits}[i] \oplus \text{flipped}$$

于是 `flip()` 只需 `flipped = !flipped`，$O(1)$ 完成，物理数组一个字节都不用动；`ones`（逻辑 1 的个数）同步重算——翻转使逻辑 1 与逻辑 0 整体互换，故 $\text{ones} \leftarrow n - \text{ones}$，仍是 $O(1)$。

> 💡 可把 `flipped = true` 理解为**镜像世界**：0/1 互换、`fix` 与 `unfix` 的语义互换。这是**懒惰标记（lazy tag）**的最朴素形态——不立即执行昂贵操作，只记一个标记，把代价摊到后续每次单点访问的 $O(1)$ 翻译里；线段树的区间翻转 lazy propagation 是它的区间版正统形态（见「相关题目与扩展」）。

### 3.3 算法流程：一条翻译规则统一 fix / unfix

![算法流程：物理目标 = 逻辑目标 ⊕ flipped，判与写同源](images/2166_bitset_flip_fix_flow.svg)

`fix`/`unfix` 的难点在于：用户给的是**逻辑语义**（「把逻辑位设为 1/0」），而我们要写**物理数组**。由 $\text{logical} = \text{bits} \oplus \text{flipped}$ 反解得统一翻译规则：

$$\text{物理目标 target} = \text{逻辑目标} \oplus \text{flipped}$$

- `fix(idx)`：逻辑目标 $1$ → `target = 1 ^ flipped`；
- `unfix(idx)`：逻辑目标 $0$ → `target = 0 ^ flipped = flipped`；
- **判定当前逻辑值**也用同一条规则：$\text{bits}[idx] \oplus \text{flipped}$。写与判必须同源，否则 `flipped` 切换后状态错乱；
- 只有 `bits[idx] != target`（等价于「当前逻辑值确需改变」）时才写数组并 `ones ± 1`，天然保证幂等。

查询类全部退化为读 `ones`：`all() ⇔ ones == n`、`one() ⇔ ones > 0`、`count() = ones`；`toString()` 逐位输出 `bits[i] ^ flipped`，$O(n)$，至多 5 次。

### 3.4 示例演算

![示例演算：size=5 的十一步状态表，物理数组只在 fix/unfix 时才动](images/2166_bitset_walkthrough.svg)

以题面示例逐步演算（$n = 5$，初始 `bits = 00000`、`flipped = false`、`ones = 0`）：

| 步骤 | 操作 | bits（物理） | flipped | ones | 逻辑视图 |
|------|------|-------------|---------|------|---------|
| 0 | init | 00000 | F | 0 | 00000 |
| 1 | fix(3) | 00010 | F | 1 | 00010 |
| 2 | fix(1) | 01010 | F | 2 | 01010 |
| 3 | flip() | **01010** | **T** | **3** | 10101 |
| 4 | all() | 01010 | T | 3 | → false（3 ≠ 5） |
| 5 | unfix(0) | **11010** | T | 2 | 00101 |
| 6 | flip() | **11010** | **F** | **3** | 11010 |
| 7 | one() | 11010 | F | 3 | → true |
| 8 | unfix(0) | 01010 | F | 2 | 01010 |
| 9 | count() | 01010 | F | 2 | → 2 |
| 10 | toString() | 01010 | F | 2 | → "01010" |

三个关键步：

- **第 3 步 `flip()`**：物理数组一字未动（`01010 → 01010`），只翻标志并 `ones ← 5 − 2 = 3`；
- **第 5 步镜像下的 `unfix(0)`**：逻辑位 0 当前 $= \text{bits}[0] \oplus 1 = 1$，需清零；物理目标 $= 0 \oplus \text{flipped} = 1$，故物理上反而把 `bits[0]` 从 0 写成 1，`ones` 由 3 减到 2；
- **第 6 步再 `flip()`**：回到正常视角，`ones ← 5 − 2 = 3`，逻辑视图恢复物理原貌 `11010`。

## 4. 算法细节

1. **状态三元组**：内部只维护 $(\text{bits},\ \text{flipped},\ \text{ones})$，靠两条不变量黏合（§5）：**表示不变量**（逻辑位 = 物理位 ⊕ 标志）与**计数不变量**（`ones` = 逻辑 1 的个数）。所有方法都是对这三者的局部维护。
2. **fix/unfix 的对称实现**：先算 `target = 逻辑目标 ^ flipped`，再比较 `bits[idx]` 与 `target`——把「逻辑值是否已是目标」的判定转化成「物理值是否已是 target」，避免单独读逻辑值的分支；`fix` 与 `unfix` 只有逻辑目标（1/0）与 `ones` 增减方向两处差别。
3. **flip 的复合维护**：`flipped ← ¬flipped` 与 `ones ← n − ones` 必须成对出现。另有另一派实现：flip 只翻标志，查询时按 `flipped ? n − ones : ones` 翻译——两派各自自洽，**切忌混用**（flip 时重算又查询时翻译 = 双重修正，见 §8）。
4. **toString 的免死金牌**：$O(n)$ 整串重建只在至多 5 次调用里发生，总代价 $\le 5n$；C++ 先 `reserve(n)` 防反复扩容，Python 用生成器 + `''.join` 一次拼接。
5. **替代实现：双哈希集合 swap**：用 `ones_set` / `zeros_set` 分别存**逻辑** 1 / 逻辑 0 的下标（构造时 `zeros_set` 装满 $[0, n)$）。`fix`：`zeros → ones`；`unfix`：`ones → zeros`；`flip`：**交换两个集合的句柄**，$O(1)$；`count = ones_set.size()`；`toString` 按 `ones_set` 涂 `1`。优点是物理即逻辑、无需翻译规则；代价是初始化 $O(n)$、哈希常数与内存都更大——赛场求稳选标志版，求不易错选集合版。
6. **类型审计**：$n \le 10^5$，`ones ∈ [0, n]`，`int` 充足；C++ 中 `bits[idx] ^ flipped` 的 `bool` 操作数提升为 `int` 后异或结果仍是 0/1，可直接 `'0' + (...)` 转字符。

## 5. 正确性证明

**约定**：$L_t[i]$ 表示第 $t$ 次操作后题目语义（逻辑）下位 $i$ 的值；内部状态 $S_t = (\text{bits}_t,\ \text{flipped}_t,\ \text{ones}_t)$；$n = \text{size}$。

**引理 1（表示不变量）**：对任意时刻 $t$ 与任意下标 $i$：$L_t[i] = \text{bits}_t[i] \oplus \text{flipped}_t$。

**证明**：对 $t$ 归纳。$t = 0$：`bits` 全 0、`flipped = 0`，$L_0[i] = 0$ 成立。设某次操作前不变量成立，逐类检查：

- `fix(idx)`：代码在 $\text{bits}[idx] \ne 1 \oplus \text{flipped}$ 时置 $\text{bits}[idx] \leftarrow 1 \oplus \text{flipped}$，操作后 $\text{bits}[idx] \oplus \text{flipped} = (1 \oplus \text{flipped}) \oplus \text{flipped} = 1$；其余位与 `flipped` 均不变，对应 $L$ 亦不变；
- `unfix(idx)`：对称地置 $\text{bits}[idx] \leftarrow 0 \oplus \text{flipped}$，操作后 $\text{bits}[idx] \oplus \text{flipped} = \text{flipped} \oplus \text{flipped} = 0$；
- `flip()`：$\text{flipped}' = \neg\text{flipped}$、`bits` 不动，则对任意 $i$：$\text{bits}[i] \oplus \text{flipped}' = \neg(\text{bits}[i] \oplus \text{flipped})$，恰是逐位取反；
- 查询操作不改变状态。

各类操作后不变量均保持。∎

**引理 2（计数不变量）**：$\text{ones}_t = \left|\{\, i : L_t[i] = 1 \,\}\right|$。

**证明**：对 $t$ 归纳。$t = 0$：`ones = 0` 且 $L_0 \equiv 0$。归纳步：

- `fix(idx)`：仅当 $\text{bits}[idx] \ne 1 \oplus \text{flipped}$ 时写数组并 `ones++`。由引理 1 的代换，该条件等价于 $L[idx] \ne 1$，即逻辑位恰从 0 变 1——正是计数加一的唯一来源；其余位 $L$ 不变，等式保持。`unfix` 对称（`ones−−` 对应逻辑位 1 → 0）；
- `flip()`：新逻辑位逐位取反，故 $\{\, i : L'[i] = 1 \,\} = \{\, i : L[i] = 0 \,\}$，大小为 $n - \text{ones}$；代码恰好执行 $\text{ones} \leftarrow n - \text{ones}$。∎

**定理 1（正确性）**：各方法的副作用与返回值符合题目规格。

**证明**：由引理 1 的归纳步骤，`fix`/`unfix`/`flip` 分别实现「逻辑置 1 / 逻辑置 0 / 全体取反」，且天然幂等（`bits[idx]` 已等于 `target` 时不写、`ones` 不动，逻辑值本已是目标）。由引理 2：`all() ⇔ ones == n`（全部逻辑位为 1）、`one() ⇔ ones > 0`（至少一个逻辑 1）、`count() = ones`；`toString()` 第 $i$ 个字符 $= \text{bits}[i] \oplus \text{flipped} = L[i]$，与「第 $i$ 个字符对应第 $i$ 位」的规格一致。∎

**定理 2（复杂度）**：单次 `fix` / `unfix` / `flip` / `all` / `one` / `count` 均为 $O(1)$，单次 `toString` 为 $O(n)$；$q$ 次调用总时间 $O(q + 5n)$。

**证明**：前六个方法每者只做常数次下标访问与算术运算；`toString` 遍历整串一次为 $O(n)$，调用次数 $\le 5$ 由约束给出。∎

## 6. 复杂度分析

- **时间复杂度**：除 `toString` 外所有操作 $O(1)$；`toString` 至多 5 次、每次 $O(n)$。总计 $O(q + 5n) \approx 10^6$ 量级（$q, n \le 10^5$），对比朴素实现的 $O(q \cdot n) = 10^{10}$，**加速约 $n$ 倍**。双集合版 `fix`/`unfix` 为均摊 $O(1)$（哈希），`flip` 交换句柄严格 $O(1)$。
- **空间复杂度**：标志版 $O(n)$（物理数组）+ $O(1)$ 标量；双集合版 $O(n)$（两个集合合计恰好 $n$ 个下标）。

## 7. 参考代码

### C++

```cpp
// 写法一：懒惰翻转标志 —— 翻译规则 target = 逻辑目标 ⊕ flipped
class Bitset {
    vector<int> bits;          // 物理存储：flip 从不碰它
    int n, ones = 0;           // ones = 逻辑 1 的个数（计数不变量）
    bool flipped = false;      // 反转视角标志（表示不变量）

  public:
    Bitset(int size) : bits(size, 0), n(size) {}

    void fix(int idx) {
        int target = 1 ^ flipped;            // 逻辑 1 翻译成物理目标
        if (bits[idx] != target) {           // 等价于：当前逻辑位是 0
            bits[idx] = target;
            ++ones;
        }
    }

    void unfix(int idx) {
        int target = 0 ^ flipped;            // 即 flipped
        if (bits[idx] != target) {           // 等价于：当前逻辑位是 1
            bits[idx] = target;
            --ones;
        }
    }

    void flip() {
        flipped = !flipped;                  // 只翻标志，O(1)
        ones = n - ones;                     // 逻辑 1/0 整体互换
    }

    bool all() { return ones == n; }
    bool one() { return ones > 0; }
    int count() { return ones; }

    string toString() {                      // 至多 5 次调用，O(n) 无妨
        string s;
        s.reserve(n);
        for (int i = 0; i < n; ++i)
            s.push_back('0' + (bits[i] ^ flipped));
        return s;
    }
};
```

```cpp
// 写法二：双哈希集合 swap —— 物理即逻辑，flip 只换句柄
class Bitset {
    unordered_set<int> ones, zeros;          // 分别存逻辑 1 / 逻辑 0 的下标
    int n;

  public:
    Bitset(int size) : n(size) {
        for (int i = 0; i < size; ++i) zeros.insert(i);
    }

    void fix(int idx) {
        if (zeros.count(idx)) {
            zeros.erase(idx);
            ones.insert(idx);
        }
    }

    void unfix(int idx) {
        if (ones.count(idx)) {
            ones.erase(idx);
            zeros.insert(idx);
        }
    }

    void flip() {
        swap(ones, zeros);                   // 交换内部桶句柄，O(1)
    }

    bool all() { return (int)ones.size() == n; }
    bool one() { return !ones.empty(); }
    int count() { return ones.size(); }

    string toString() {
        string s(n, '0');
        for (int i : ones) s[i] = '1';
        return s;
    }
};
```

### Python

```python
# 写法一：懒惰翻转标志
class Bitset:
    def __init__(self, size: int):
        self.bits = [0] * size
        self.n = size
        self.ones = 0
        self.flipped = False

    def fix(self, idx: int) -> None:
        target = 1 ^ self.flipped            # bool 参与异或按 0/1 处理
        if self.bits[idx] != target:
            self.bits[idx] = target
            self.ones += 1

    def unfix(self, idx: int) -> None:
        target = 0 ^ self.flipped
        if self.bits[idx] != target:
            self.bits[idx] = target
            self.ones -= 1

    def flip(self) -> None:
        self.flipped = not self.flipped      # 两次赋值，O(1)
        self.ones = self.n - self.ones

    def all(self) -> bool:
        return self.ones == self.n

    def one(self) -> bool:
        return self.ones > 0

    def count(self) -> int:
        return self.ones

    def toString(self) -> str:
        f = int(self.flipped)
        return ''.join(str(b ^ f) for b in self.bits)
```

```python
# 写法二：双集合 swap —— Python 元组解包交换引用，O(1)
class Bitset:
    def __init__(self, size: int):
        self.n = size
        self.ones = set()
        self.zeros = set(range(size))

    def fix(self, idx: int) -> None:
        if idx in self.zeros:
            self.zeros.remove(idx)
            self.ones.add(idx)

    def unfix(self, idx: int) -> None:
        if idx in self.ones:
            self.ones.remove(idx)
            self.zeros.add(idx)

    def flip(self) -> None:
        self.ones, self.zeros = self.zeros, self.ones

    def all(self) -> bool:
        return len(self.ones) == self.n

    def one(self) -> bool:
        return len(self.ones) > 0

    def count(self) -> int:
        return len(self.ones)

    def toString(self) -> str:
        s = ['0'] * self.n
        for i in self.ones:
            s[i] = '1'
        return ''.join(s)
```

## 8. 边界情况与易错点

1. **镜像视角漂移**（最高频 WA）：`flipped = true` 时 `fix` 物理写 0、`unfix` 物理写 1，方向与直觉相反。防御法：永远走统一翻译规则 `target = 逻辑目标 ^ flipped`，不要在两个视角下各写一套赋值逻辑。
2. **双重修正**：`flip` 时已做 `ones ← n − ones`，查询时又写 `flipped ? n − ones : ones`——修正被应用两次，计数全错。「flip 时重算」与「查询时翻译」两派只能选一派并贯彻到底。
3. **幂等性**：`fix` 已是 1（`bits[idx] == target`）时不得再 `ones++`，否则计数漂移。判定条件必须是「物理值 ≠ 目标值」，而不是无脑赋值加计数。
4. **写与判不同源**：判定当前逻辑值用 `bits[idx] ⊕ flipped`，写目标值却忘了异或（或反之），`flipped` 切换后状态错乱。统一改成比较 `bits[idx]` 与 `target` 可同时消掉这两个坑——该比较本身就等价于逻辑判定（§5 引理 2 的证明中给出等价式）。
5. **`toString` 别忘翻译**：直接输出物理数组会在 `flipped = true` 时整体反相。它的 $O(n)$ 依赖「至多 5 次」的约束豁免；朴素实现的 `flip` 没有这种豁免，这是读题时就要抓出的信号。
6. **双重 flip 抵消**：连续两次 `flip` 后 `flipped` 回 `false`、`ones` 回原值（$n - (n - x) = x$），无需特判；但别把中间态的 `all()`/`one()` 结果缓存成长期结论。
7. **`size = 1` 边界**：`fix(0)` 后 `all() == true`；`flip` 后 `one() == false`、`count() == 0`、`toString() == "0"`。
8. **双集合版的两个坑**：初始化必须把 `zeros` 装满 $[0, n)$（漏装则首次 `flip` 后 `count` 虚高）；`flip` 必须**交换引用**（Python 元组解包、C++ `std::swap`），写成集合复制是 $O(n)$，最坏同样 $10^{10}$。
9. **C++ 细节**：`bits[i] ^ flipped` 中 `bool` 提升后结果是 0/1，`'0' + (...)` 得到正确字符；`unordered_set::swap` 为 $O(1)$；`count()` 返回 `size_t`，与 `int` 比较注意符号（本题同向无碍）。

**延伸思考**：

- **Python 大整数一行流**：用一个大整数 `x` 当位集，`flip` 即 `x ^= (1 << n) - 1`，`fix`/`unfix` 是 `x |= 1 << idx` / `x &= ~(1 << idx)`，`count` 用 `x.bit_count()`，`toString` 用 `f"{x:0{n}b}"`——代价是 mask 异或与计数均为 $O(n / w)$（$w$ 为机器字长），常数极小但非严格 $O(1)$。
- **区间推广**：若 `fix`/`unfix` 带区间参数 `fix(l, r)`，单点翻译规则失效，需升级为线段树 + 区间赋值/翻转懒惰标记——本题即「全局版 lazy tag」。
- **`toString` 次数无上限**：需要可增量维护的字符串表示（如分块 + 平衡结构拼接），或接受每次 $O(n)$；本题的 5 次上限正是为了让「懒惰标志 + 偶发整串重建」成为标准答案。
- **双解法对偶**：标志版是「物理层 + 观察透镜」，集合版是「逻辑层直接存储」；前者省内存、后者省心智，能主动对比两者已是面试加分项。
