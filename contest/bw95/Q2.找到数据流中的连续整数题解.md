# LeetCode 找到数据流中的连续整数 题解

## 1. 题目概述

- **标题 / 题号**：找到数据流中的连续整数（#2526，medium）
- **链接**：https://leetcode.cn/problems/find-consecutive-integers-from-a-data-stream/
- **来源**：LeetCode 第 95 场双周赛 Q2
- **难度**：中等
- **标签**：设计、队列、哈希表、计数、数据流

**题意**：实现一个数据结构 `DataStream`，构造时给定目标值 `value` 和窗口长度 `k`。之后每次调用 `consec(num)` 会把 `num` 追加到整数流末尾，并回答：**流中最后 $k$ 个整数是否都等于 `value`**。流中不足 $k$ 个整数时条件不满足，返回 `false`。

**约束**：

- $1 \le value, num \le 10^9$
- $1 \le k \le 10^5$
- `consec` 至多被调用 $10^5$ 次

## 2. 示例

**示例 1（官方）**

```text
输入：
["DataStream", "consec", "consec", "consec", "consec"]
[[4, 3],      [4],      [4],      [4],      [3]]
输出：[null, false, false, true, false]
解释：DataStream(4, 3) 初始化，value = 4, k = 3。
consec(4)：流为 [4]，不足 3 个 → false
consec(4)：流为 [4,4]，仍不足 → false
consec(4)：流为 [4,4,4]，最后 3 个都是 4 → true
consec(3)：流为 [4,4,4,3]，最后 3 个为 [4,4,3] → false
```

**示例 2（边界补充：$k = 1$）**

```text
输入：["DataStream", "consec", "consec", "consec", "consec"]
     [[7, 1],      [3],      [7],      [7],      [8]]
输出：[null, false, true, true, false]
解释：k = 1 时只看最新一个数是否等于 value。
```

## 3. 解题思路

### 3.1 暴力思路

每次 `consec` 后检查流中最后 $k$ 个数是否都等于 `value`：把整个流存进 `vector`，每次调用扫最后 $k$ 个元素。单次调用 $O(k)$，总复杂度 $O(qk)$，最坏 $10^5 \times 10^5 = 10^{10}$，会超时。更聪明的暴力是「记录上一个不等于 `value` 的位置」：设 `lastBad` 为最近一次 `num != value` 的下标，当前下标为 `cnt_total`，则答案为 `cnt_total - lastBad >= k`，单次 $O(1)$——这其实已经是正解的另一种表述。

### 3.2 核心观察：只维护「尾部连续命中长度」

![核心观察：一个计数器替代定长窗口](images/bw95_q2_window_model.svg)

「最后 $k$ 个数都等于 `value`」等价于「以最新元素结尾、连续等于 `value` 的最长尾巴长度 $\ge k$」。而**尾部连续命中长度** `cnt` 可以增量维护，无需保存任何历史：

- 新来的 `num == value`：尾巴延长，`cnt += 1`；
- 新来的 `num != value`：尾巴被彻底打断，`cnt = 0`。

于是既不需要 $O(k)$ 的队列，也不需要哈希表计数——一个整型计数器就是全部状态。

> 💡 为什么不需要真的存窗口？因为判定条件只关心「等于 / 不等于」这一位信息，而 `value` 是**固定**的。窗口内是哪些具体数字无关紧要，只要出现一个异类，这个窗口以及之后所有与它重叠的窗口都必然是 `false`；这个"归零"动作恰好被 `cnt = 0` 完整编码。

### 3.3 算法流程

```text
初始化：value, k 存下；cnt = 0
consec(num)：
  1. 若 num == value：cnt ← cnt + 1
     否则：          cnt ← 0
  2. 返回 cnt >= k
```

### 3.4 示例演算

![示例演算：官方用例的计数器变化轨迹](images/bw95_q2_example_walkthrough.svg)

以官方示例（`value = 4, k = 3`）走一遍：

| 调用 | num | num == value? | cnt | cnt ≥ 3? | 返回 |
|------|-----|---------------|-----|----------|------|
| 1 | 4 | 是 | 0 → 1 | 否 | false |
| 2 | 4 | 是 | 1 → 2 | 否 | false |
| 3 | 4 | 是 | 2 → 3 | 是 | true |
| 4 | 3 | 否 | 3 → 0 | 否 | false |

注意第 4 行：哪怕此前 `cnt` 已达到 3，一个异类数字立刻把尾巴清零——这正对应「最后 $k$ 个数为 $[4,4,3]$」不满足。

## 4. 算法细节

1. **状态只有一个 `cnt`**：空间 $O(1)$，与 $k$ 无关；相比之下「存最近 $k$ 个数」的队列做法是 $O(k)$ 空间，虽然也能过，但完全没有必要。
2. **更新与查询的顺序**：先把 `num` 的效果并入 `cnt`（新数属于"最后 $k$ 个"之内），再用 `cnt >= k` 判定。若先判后更，会把新数漏在窗口外，`k = 1` 时必然出错。
3. **`cnt >= k` 而非 `cnt == k`**：连续命中可以超过 $k$（例如 $k = 3$，连续 5 个 `value`），等号会漏判。
4. **计数器溢出**：调用次数最多 $10^5$，`cnt` 上界 $10^5$，32 位整数足够。
5. **类名与接口**：按 metaData 设计题签名，类名 `DataStream`，构造器 `DataStream(int value, int k)`，查询 `bool consec(int num)`。

## 5. 正确性证明

**引理 1（尾部长度的递推）**：设流为 $a_1, a_2, \dots, a_t$（$t \ge 1$），定义 $L_t$ 为最大的 $\ell \in [0, t]$ 使得 $a_{t-\ell+1}, \dots, a_t$ 全部等于 $value$（$\ell = 0$ 表示 $a_t \ne value$）。则

$$L_t = \begin{cases} L_{t-1} + 1, & a_t = value \\ 0, & a_t \ne value \end{cases}$$

**证明**：若 $a_t \ne value$，任何以 $a_t$ 结尾的非空段都不全等于 $value$，故 $L_t = 0$。若 $a_t = value$：一方面 $a_{t-L_{t-1}}, \dots, a_t$ 中前 $L_{t-1}$ 个是 $a_{t-1}$ 结尾的最长命中段、全部等于 $value$，加上 $a_t = value$，得到长度 $L_{t-1}+1$ 的命中段，故 $L_t \ge L_{t-1}+1$；另一方面若存在更长的命中段 $a_{t-\ell}, \dots, a_t$（$\ell > L_{t-1}+1$），则其前 $\ell - 1 \ge L_{t-1}+1$ 个元素构成以 $a_{t-1}$ 结尾、长度超过 $L_{t-1}$ 的命中段，与 $L_{t-1}$ 的最大性矛盾。故 $L_t = L_{t-1} + 1$。∎

**定理**：算法中变量 `cnt` 在每次 `consec` 返回前等于 $L_t$（$t$ 为当前流的长度），且返回值等于「最后 $k$ 个整数都等于 `value`」的真值。

**证明**：对调用次数归纳。初始 $t = 0$，`cnt` $= 0 = L_0$（定义空流尾长为 0）。归纳步：设某次调用前 `cnt` $= L_{t-1}$，新来 $a_t$。算法按引理 1 的递推更新 `cnt`，得 `cnt` $= L_t$。再证查询语义：流长 $t < k$ 时不存在"最后 $k$ 个"，题目规定返回 `false`，而 $L_t \le t < k$，`cnt >= k` 为假，一致；流长 $t \ge k$ 时，"最后 $k$ 个都等于 $value$" ⟺ 以 $a_t$ 结尾的长度为 $k$ 的段全命中 ⟺ $L_t \ge k$ ⟺ `cnt >= k`。两种情形下返回值都与定义一致。∎

## 6. 复杂度分析

- **时间**：初始化 $O(1)$；每次 `consec` 为 $O(1)$（一次比较、一次更新、一次比较）。总计 $O(q)$，$q$ 为调用次数（$q \le 10^5$）。
- **空间**：$O(1)$。只保存 `value`、`k`、`cnt` 三个标量，与 $k$ 和流长无关——比队列做法的 $O(k)$ 更省。

## 7. 参考代码

### C++

```cpp
class DataStream {
public:
    DataStream(int value, int k) : value(value), k(k), cnt(0) {}

    bool consec(int num) {
        cnt = (num == value) ? cnt + 1 : 0;   // 尾部连续等于 value 的长度
        return cnt >= k;
    }

private:
    int value, k, cnt;
};
```

### Python

```python
class DataStream:

    def __init__(self, value: int, k: int):
        self.value = value
        self.k = k
        self.cnt = 0            # 尾部连续等于 value 的长度

    def consec(self, num: int) -> bool:
        if num == self.value:
            self.cnt += 1
        else:
            self.cnt = 0
        return self.cnt >= self.k
```

> 💡 两份代码均通过官方调用序列回放（`false, false, true, false`）、$k=1$ 边界、$k=10^5$ 且全程命中后插入异类的长序列，以及 3000 组（C++）/ 2000 组（Python）随机流与「保存全流、逐次检查最后 $k$ 个」朴素实现对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **先更新后判定**：`num` 必须先并入窗口再回答。若把顺序反过来，$k = 1$ 时 `consec(value)` 会错误返回 `false`（第一次调用永远在旧状态上判断）。
2. **用 `>=` 而非 `==`**：连续命中段可以长于 $k$，`==` 只在恰好第 $k$ 次命中时返回 `true`，之后第 $k+1$ 个命中又变回 `false`，明显违背题意。
3. **不足 $k$ 个必须返回 `false`**：即使前几个数都是 `value`（如示例 1 前两次调用），`cnt < k` 自动覆盖了这一情况，无需特判流长度。
4. **异类清零而非减一**：一个 `num != value` 打断的不仅是自己，而是把所有包含它的窗口全部判负——所以是 `cnt = 0`。若误写成"滑动计数"（减一），等于把异类也当成部分命中，会输出错误的 `true`。
5. **数据范围**：`value, num` 高达 $10^9$，用 `int` 存即可（$< 2^{31}$），但别用 `char`/`short` 之类的窄类型承接。
6. **别存整个流**：$q$ 与 $k$ 均到 $10^5$，存全流是 $10^5$ 个 `int` 尚可接受，但每次扫描 $O(k)$ 的做法在 $q = k = 10^5$ 时是 $10^{10}$ 次操作，必然超时。
