# LeetCode 查询带键的排列 题解

## 1. 题目概述

- **标题 / 题号**：查询带键的排列（#1409，medium）
- **链接**：https://leetcode.cn/problems/queries-on-a-permutation-with-key/
- **来源**：LeetCode 第 184 场周赛 Q2
- **难度**：中等
- **标签**：树状数组、数组、模拟、分块

**题意**：给定整数 $m$ 与查询数组 `queries`（元素取值 $1 \sim m$）。初始有排列 $P = [1, 2, \dots, m]$，按顺序处理每个查询 $v = \text{queries}[i]$：

1. 报告 $v$ 在**当前** $P$ 中的下标（从 0 开始），作为本次查询结果；
2. 把 $v$ **移动到 $P$ 的开头**，其余元素相对顺序不变。

返回所有查询结果组成的数组。本质上是一组「**查询即置顶**」操作上的**动态排名**问题。

**约束**：

- $1 \le m \le 10^3$
- $1 \le \text{queries.length} \le m$
- $1 \le \text{queries}[i] \le m$

## 2. 示例

**示例 1**

```text
输入：queries = [3,1,2,1], m = 5
输出：[2,1,2,1]
解释：
- i=0: P=[1,2,3,4,5]，3 在下标 2 → 置顶后 P=[3,1,2,4,5]
- i=1: P=[3,1,2,4,5]，1 在下标 1 → P=[1,3,2,4,5]
- i=2: P=[1,3,2,4,5]，2 在下标 2 → P=[2,1,3,4,5]
- i=3: P=[2,1,3,4,5]，1 在下标 1 → P=[1,2,3,4,5]
```

**示例 2**

```text
输入：queries = [4,1,2,2], m = 4
输出：[3,1,2,0]
解释：最后一次查询 2 时它已在队首，答案为 0，P 保持不变。
```

**示例 3**

```text
输入：queries = [7,5,5,8,3], m = 8
输出：[6,5,0,7,5]
```

## 3. 解题思路

### 3.1 暴力思路：数组模拟（赛时足够）

最直观的做法是真实维护排列 $P$：每次线性找到 $v$ 的下标记入答案，再把它删掉插到头部。

```python
class Solution:
    def processQueries(self, queries: List[int], m: int) -> List[int]:
        P, ans = list(range(1, m + 1)), []
        for v in queries:
            idx = P.index(v)
            ans.append(idx)
            P.pop(idx)
            P.insert(0, v)
        return ans
```

每次查询「线性查找 $O(m)$ + 删除/前插 $O(m)$」，总计 $O(n \cdot m) \le 10^6$，本题 $m \le 10^3$ 稳过。**赛时建议直接交这版保底**。

> ⚠️ 瓶颈在「前插」：把一个元素提到队首，意味着它后面所有元素的位次集体 $+1$，若真实维护排列就要整段平移。$m$ 放大到 $10^5$ 时 $O(nm)$ 达 $10^{10}$ 必然超时。破局思路：**不搬移任何元素，只维护每个元素的「逻辑坐标」**，让「查位次」与「前插」都降到 $O(\log)$。

### 3.2 核心观察：前插 = 换个位置打标记

![核心观察：前插不搬元素，扩展下标空间换位打标](images/wc184_q2_bit_concept.svg)

三个环环相扣的观察：

1. **位次 = 前缀计数**。$v$ 的下标 = 排在它前面的元素个数。若让每个元素在一条「位置轴」上各占一格，则 $v$ 的位次就是 $\text{pos}[v]$ 左侧的占据格数——「单点修改 + 前缀求和」，正是树状数组（BIT）的看家本领。
2. **前插 = 换位置打标记**。把 $v$ 提到队首不需要平移任何人：在一条**更靠左**的新坐标上给 $v$ 重新打标记，同时抹掉旧标记，「队首」语义自动成立。
3. **预留递减落点，避免负坐标**。令 $n = \text{queries.length}$，把位置轴从 $[1, m]$ 扩展到 $[1, n+m]$：数值 $v$ 初始占据 $n + v$；第 $i$ 次查询的落点定为 $n - i$，即 $n, n-1, \dots, 1$ **单调递减**——新队首永远在上一任队首左边，且坐标始终为正。

于是任何时刻「按坐标升序读出占据标记」都等于真实排列 $P$，但没有任何元素被真正移动过。

### 3.3 算法流程：每次查询三步走

![算法流程：初始化加每次查询三步，各对数复杂度](images/wc184_q2_query_flow.svg)

1. **初始化**：BIT 容量 $N = n + m$（1-indexed）；对 $v \in [1, m]$ 置 `pos[v] = n + v`、`update(n + v, +1)`。
2. **第 $i$ 次查询**（$v = \text{queries}[i]$）：
   - **查位次**：`ans[i] = query(pos[v]) - 1`；
   - **清旧位**：`update(pos[v], -1)`；
   - **置新位**：`pos[v] = n - i`，`update(pos[v], +1)`。
3. 全部处理完后返回 `ans`。

一次 $O(m)$ 的整段平移，就这样被拆成两次 $O(\log N)$ 的单点修改。

### 3.4 示例演算

以示例 1 为例：$n = 4$，位置轴 $[1, 9]$，数值 $1 \sim 5$ 初始占据 $5, 6, 7, 8, 9$。

![示例演算：queries等于3,1,2,1且m等于5的逐步走查](images/wc184_q2_walkthrough.svg)

| $i$ | $v$ | 旧 $\text{pos}[v]$ | $\text{query}(\text{pos})-1$ | 新落点 $n-i$ | 占据位变化 | 升序读出（= 真实 $P$） |
|---|---|---|---|---|---|---|
| 0 | 3 | 7 | $3-1=\mathbf{2}$ | 4 | 清 7 → 置 4 | $[3,1,2,4,5]$ |
| 1 | 1 | 5 | $2-1=\mathbf{1}$ | 3 | 清 5 → 置 3 | $[1,3,2,4,5]$ |
| 2 | 2 | 6 | $3-1=\mathbf{2}$ | 2 | 清 6 → 置 2 | $[2,1,3,4,5]$ |
| 3 | 1 | 3 | $2-1=\mathbf{1}$ | 1 | 清 3 → 置 1 | $[1,2,3,4,5]$ |

答案 $[2,1,2,1]$ ✓。注意「升序读出」列与 §2 示例 1 中暴力模拟的 $P$ 逐位一致——坐标轴忠实还原了排列，却从未搬移任何元素。

## 4. 算法细节

1. **BIT 容量与下标**：$N = n + m$，**1-indexed**，数组开 $N + 1$。`update(p, d)` 单点加、`query(p)` 前缀和，均靠 `lowbit(x) = x & (-x)` 在树形索引上跳跃。
2. **pos 是「数值 → 坐标」映射**：按数值索引（`pos[v]`，$v \in [1, m]$，开 $m + 1$），与查询下标 $i$ 无关，不要顺手写成按 $i$ 索引。
3. **落点公式 $n - i$**：$i$ 是当前查询的序号（从 0 起）。因 $i \le n-1$，最小落点为 $1$，恰好用满预留区且永不触碰 0 号位；若误写成 $n - i - 1$，最后一次查询落点为 0，BIT 越界。
4. **三步顺序固定**：参考代码采用「先查（减 1）→ 清旧位 → 置新位」。也存在等价写法「先清旧位再查」——此时前缀和已不含自身，答案应直接取 `query(pos[v])` 不再减 1。两种顺序各自配套，**混用必错**。
5. **初始化的两种写法**：$m$ 次 `update` 共 $O(m \log N)$；或先把初值直接填进数组再 $O(N)$ 自底向上 build（`bit[i + lowbit(i)] += bit[i]`）。本题规模两者皆可。

## 5. 正确性证明

记位置轴为 $[1, N]$（$N = n + m$），任意时刻每个数值恰占据一个坐标，$S$ 为占据坐标集合（$|S| = m$）。定义**轴上排列** $P'$：按坐标升序读出 $S$ 中各坐标上的数值得到的序列。

**引理 1（一致性）**：任意时刻，轴上排列 $P'$ 等于真实排列 $P$（暴力模拟所得）。

**证明**：对已处理查询次数归纳。

- **基础**：初始数值 $v$ 占据 $n + v$，升序读出 $1, 2, \dots, m$，即 $P_0 = [1, \dots, m]$。
- **归纳步**：设查询 $v$ 前二者一致。真实操作把 $P$ 变为 $[v] + (P \setminus \{v\})$。坐标轴上执行「清 $\text{pos}[v]$，置 $n - i$」。断言新落点 $n - i$ 严格小于 $S$ 中所有**其他**坐标：初始占据坐标均 $\ge n + 1 > n - i$；第 $j$ 次（$j < i$）查询的落点为 $n - j > n - i$。故清旧位、置新位后，$v$ 的新坐标是全部 $m$ 个占据坐标中最小者，升序读出时排在首位；其余 $m - 1$ 个数值坐标未动、相对次序不变，读出恰为 $P \setminus \{v\}$ 保持原序。故 $P' = [v] + (P \setminus \{v\})$。∎

**引理 2（位次公式）**：查询 $v$ 时，$\text{query}(\text{pos}[v]) - 1$ 等于 $v$ 在当前排列中的 0-indexed 下标。

**证明**：`query(pos[v])` 统计 $[1, \text{pos}[v]]$ 内的占据坐标数。由引理 1，占据坐标与排列元素一一对应且保序，故该计数 = 「$v$ 自身及其之前的元素个数」= 下标 $+\ 1$。∎

**定理**：算法输出与暴力模拟输出完全一致。

**证明**：由引理 2，每次报告的位次正确；由引理 1，坐标轴状态始终忠实追踪真实排列。对查询次数归纳，即得输出逐项一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n + m) \log(n + m))$。初始化 $m$ 次 `update` 为 $O(m \log N)$（或 $O(N)$ build）；$n$ 次查询各 1 次 `query` + 2 次 `update`，为 $O(n \log N)$。
- **空间复杂度**：$O(n + m)$，即 BIT 数组（$N + 1$）与 `pos` 数组（$m + 1$）。
- **与暴力对照**：数组模拟 $O(nm)$ 时间、$O(m)$ 空间。本题 $m \le 10^3$ 两者皆过；$m \sim 10^5$ 时只剩 BIT（或平衡树、分块）可行——这也是本题被归入树状数组标签的原因。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> processQueries(vector<int>& queries, int m) {
        int n = queries.size();
        int N = n + m;
        vector<int> bit(N + 1, 0);

        auto lowbit = [](int x) { return x & (-x); };
        auto update = [&](int p, int d) {
            for (; p <= N; p += lowbit(p)) bit[p] += d;
        };
        auto query = [&](int p) {
            int s = 0;
            for (; p > 0; p -= lowbit(p)) s += bit[p];
            return s;
        };

        vector<int> pos(m + 1);
        for (int v = 1; v <= m; v++) {
            pos[v] = n + v;
            update(n + v, 1);
        }

        vector<int> ans(n);
        for (int i = 0; i < n; i++) {
            int v = queries[i];
            ans[i] = query(pos[v]) - 1;
            update(pos[v], -1);
            pos[v] = n - i;
            update(pos[v], 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def processQueries(self, queries: List[int], m: int) -> List[int]:
        n, N = len(queries), len(queries) + m
        bit = [0] * (N + 1)

        def update(p: int, d: int) -> None:
            while p <= N:
                bit[p] += d
                p += p & (-p)

        def query(p: int) -> int:
            s = 0
            while p > 0:
                s += bit[p]
                p -= p & (-p)
            return s

        pos = [0] * (m + 1)
        for v in range(1, m + 1):
            pos[v] = n + v
            update(n + v, 1)

        ans = []
        for i, v in enumerate(queries):
            ans.append(query(pos[v]) - 1)
            update(pos[v], -1)
            pos[v] = n - i
            update(pos[v], 1)
        return ans
```

## 8. 边界情况与易错点

1. **三步顺序与减 1 配套**（最常见 WA 点）：「先查后改」必须减 1；「先改后查」不能再减 1。混用会系统性偏 1。
2. **落点公式是 $n - i$**：用查询序号 $i$（0 起）。误写成 $n - i - 1$ 会在最后一次查询落点 0 导致 BIT 越界；不按 $i$ 递减分配落点则破坏「新队首在上一任队首左边」的性质。
3. **查询元素已在队首**：答案 0，无需特判——统一执行「清旧位 + 置新位」仍正确（新落点只会更靠左，仍居最前）。示例 2 最后一次查询 2 即此情形。
4. **BIT 必须 1-indexed**：容量 $N = n + m$，数组开 $N + 1$；`query(0) == 0` 是天然边界，落点最小为 1。
5. **pos 索引方向**：`pos[v]` 按**数值**索引而非查询下标，开 $m + 1$。
6. **$m = 1$**：排列仅 $[1]$，所有答案为 0；$N = n + 1$，数值 1 初始在 $n + 1$，算法自动正确。
7. **重复查询同一元素**：第二次查询时 `pos[v]` 已是上次的新落点，前缀计数天然反映其最新位次（示例 1 中 1 被查询两次），无需任何去重逻辑。
