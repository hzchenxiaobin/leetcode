# LeetCode 数组中的字符串匹配 题解

## 1. 题目概述

- **标题 / 题号**：数组中的字符串匹配（#1408，easy）
- **链接**：https://leetcode.cn/problems/string-matching-in-an-array/
- **来源**：LeetCode 第 184 场周赛 Q1
- **难度**：简单
- **标签**：数组、字符串、字符串匹配

**题意**：给定字符串数组 `words`，每个元素是一个单词。返回**所有**「是其他某个单词的**子字符串**」的单词，顺序任意。子串要求**连续**，且「其他」不含自身。

**约束**：

- $1 \le \text{words.length} \le 100$
- $1 \le \text{words}[i].\text{length} \le 30$
- `words[i]` 仅含小写英文字母
- 题目保证所有单词**互不相同**

## 2. 示例

**示例 1**

```text
输入：words = ["mass","as","hero","superhero"]
输出：["as","hero"]
解释："as" 是 "mass" 的子串，"hero" 是 "superhero" 的子串。
["hero","as"] 也是有效答案（顺序任意）。
```

**示例 2**

```text
输入：words = ["leetcode","et","code"]
输出：["et","code"]
解释："et" 与 "code" 都是 "leetcode" 的子串。
```

**示例 3**

```text
输入：words = ["blue","green","bu"]
输出：[]
解释："bu" 不是 "blue" 的子串——子串要求连续，b 与 u 之间隔着 l。
```

## 3. 解题思路

### 3.1 暴力思路：两两配对子串查找（赛时最短路径）

签到题，数据规模极小（$n \le 100$、$L \le 30$），直接双重循环：对每个 `words[i]`，遍历所有 $j \ne i$，判断 `words[i]` 是否为 `words[j]` 的子串，命中即收、跳出。

```python
class Solution:
    def stringMatching(self, words: List[str]) -> List[str]:
        return [w for w in words if any(w != u and w in u for u in words)]
```

配对 $O(n^2)$ 对，每对朴素查找 $O(L^2)$，总计 $O(n^2 L^2) \le 100^2 \times 30^2 \approx 9 \times 10^6$，毫秒级通过。比赛时到此收工即可。

> ⚠️ 两个必须写对的小细节：① `w != u` 排除自身（也可用下标 $j \ne i$）；② 命中后及时 `break` / 短路，避免重复收集。

### 3.2 核心观察：拼接长串 + find/rfind 双向探测

暴力法要写两层循环并小心排除自身，而本题有一个近乎一行代码的优雅写法：**把所有单词拼成一个长串，每个单词只需探测两次**。

![核心观察：拼接串 + find/rfind 双向探测](images/strmatch_concat_trick.svg)

三个关键事实：

1. **每个单词在拼接串中至少出现一次**——就在它自己的段里；
2. **「是别人的子串」⟺「在拼接串中出现至少两次」**——多出来的那次出现必然落在包含它的那个单词内部；
3. `find` 给出**首次**出现位置，`rfind` 给出**末次**出现位置，**两者不等 ⟺ 出现至少两次**。

于是整个判定浓缩成一行 `joined.find(w) != joined.rfind(w)`，$n^2$ 次两两查找变成 $2n$ 次单向查找，且**天然排除自身匹配**。

> 💡 **分隔符不可省略**：拼接时必须用不在字母表中的字符（如 `#`）隔开，否则单词可能「跨段拼出」一个假匹配——这是本题最大的坑，详见 §8 与配图。

### 3.3 算法流程

1. **拼接**：`joined = "#".join(words)`（`#` 不属于小写字母表）；
2. **逐词探测**：对每个 `w`，比较 `joined.find(w)` 与 `joined.rfind(w)`；
3. **收集**：两者不等则将 `w` 收入答案；按任意顺序返回。

### 3.4 示例演算

以示例 1 为例，`joined = "mass#as#hero#superhero"`：

| w | find(w) | rfind(w) | 出现位置解读 | 收入? |
|---|---------|----------|--------------|-------|
| mass | 0 | 0 | 仅自身段出现一次 | ✗ |
| as | 1（mass 内） | 5（自身段） | 出现两次 → 是 "mass" 的子串 | ✓ |
| hero | 8（自身段） | 18（superhero 内） | 出现两次 → 是 "superhero" 的子串 | ✓ |
| superhero | 13 | 13 | 仅自身段出现一次 | ✗ |

答案 `["as","hero"]`，与示例一致 ✓

![示例演算：拼接串上的 find/rfind 双向探测](images/strmatch_example_walkthrough.svg)

## 4. 算法细节

1. **拼接**：C++ 中 `joined += w + '#'`（每词后追加，允许尾随 `#`，不影响判定）；Python 用 `"#".join(words)`。分隔符只要**不属于小写字母**即可（`#`、`,`、空格均可）。
2. **find / rfind 语义**：分别返回首次/末次出现的下标，未找到时 C++ 返回 `string::npos`、Python 返回 `-1`。本题中 `w` 必然在 `joined` 中出现（至少在自身段），未找到的情况不会发生；即便发生，两侧同为 `npos` / `-1` 也相等，会被正确排除。
3. **自身匹配的排除**：暴力法需要显式 `j != i`；拼接法**天然排除**——自身段长度恰为 $|w|$，`w` 在自身段内只有唯一一次出现（§5 引理 1），「匹配到自己」不会被误算成第二次出现。
4. **无重复保证**：题目保证单词互异，每个 `w` 只被判定一次，答案无需去重。
5. **不排序、不剪枝**：与「按长度排序后短串只查更长串」的剪枝（等长互异串不可能互含）不同，拼接法对顺序完全不敏感，两遍线性扫描即结束。

## 5. 正确性证明

设 $T$ 为用分隔符 `#` 连接全部单词得到的拼接串，每个单词对应 $T$ 中一个**段**（两侧被 `#` 或串端界定的区间）。

**引理 1（自身段唯一性）**：单词 $w$ 在其自身段内恰好出现一次。

**证明**：设 $w$ 的段为 $T[a..a+|w|-1]$，长度恰为 $|w|$。若 $w$ 的某次出现完整落在自身段内且起点为 $p$，则需 $a \le p$ 且 $p + |w| \le a + |w|$，故 $p = a$；而 $T[a..a+|w|-1] = w$ 确实匹配成功。故恰好一次。∎

**引理 2（不跨段）**：$w$ 仅含小写字母、不含 `#`，故 $w$ 在 $T$ 中的任一次出现都完整落在某个段内，不会跨越两个单词。

**证明**：任一次出现的匹配区间内所有字符都等于 $w$ 的字符，均为小写字母。若该区间跨过某条 `#`，则区间内含字符 `#`，与「区间内字符全为小写字母」矛盾。∎

**定理**：$w$ 是 `words` 中其他某单词的子串 $\iff$ `T.find(w) != T.rfind(w)`。

**证明**：

- （⇒）若 $w$ 是另一个单词 $u$ 的子串，由引理 2，该次匹配完整落在 $u$ 的段内；再加上自身段的一次出现（引理 1）。两次出现位于**不同段**，起点必不同，故 $w$ 至少出现两次，`find < rfind`，两者不等。
- （⇐）若 `find(w) != rfind(w)`，则 $w$ 至少出现两次。由引理 1，其中至多一次在自身段，故至少一次完整落在其他某个单词 $u$ 的段内（引理 2），即 $w$ 是 $u$ 的连续子串。∎

**推论**：算法输出的集合恰为所求（顺序无关，判题按集合比较）。

## 6. 复杂度分析

- **时间复杂度**：拼接 $O(T)$，其中 $T = \sum (|w_i| + 1) \le n(L+1) \approx 3100$；每个单词做两次朴素查找，每次最坏 $O(T \cdot L)$，总计 $O(n \cdot T \cdot L) \approx O(n^2 L^2)$，约 $2 \times 10^7$ 次字符比较，与暴力同阶、毫秒级。
- **空间复杂度**：$O(T)$ 存拼接串（约 3KB）；答案数组不计入。

> 💡 若配 KMP / Z 函数，每次查找降到 $O(T + L)$，总计 $O(nT) = O(n^2 L)$；本题规模下无必要，仅作理论延伸。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<string> stringMatching(vector<string>& words) {
        string joined;
        for (const string& w : words) {
            joined += w + '#';
        }
        vector<string> ans;
        for (const string& w : words) {
            if (joined.find(w) != joined.rfind(w)) {
                ans.push_back(w);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def stringMatching(self, words: List[str]) -> List[str]:
        joined = "#".join(words)
        return [w for w in words if joined.find(w) != joined.rfind(w)]
```

## 8. 边界情况与易错点

1. **分隔符绝对不能省**（本题最大的坑）：`"".join(words)` 会产生**跨段假阳性**。反例 `words = ["ab","cd","bc"]`：拼接串 `"abcdbc"` 中 `"bc"` 的 `find = 1`（跨 `ab|cd` 边界拼出来的假匹配）、`rfind = 4`（自身段），两者不等导致 `"bc"` 被误判收入，而正确答案是 `[]`。

![易错点：省略分隔符导致跨段假阳性](images/strmatch_no_sep_pitfall.svg)

2. **自身不算**：暴力法必须排除 $j = i$；拼接法由引理 1 天然排除，这也是它比暴力法更不容易写错的原因。
3. **子串 vs 子序列**：子串要求**连续**。`"bu"` 不是 `"blue"` 的子串（b、u 之间隔着 l），示例 3 返回空数组正是此考点。
4. **n = 1**：单个单词无「其他单词」，返回 `[]`；此时拼接串中 `find == rfind` 恒成立，算法自动正确。
5. **答案顺序任意**：题目明确按任意顺序返回均可，按 `words` 原顺序输出即可，无需排序。
6. **单词互异的保证**：若题目不保证互异，重复单词会互相「包含」造成误判，需先去重再判定。本题无需处理。
