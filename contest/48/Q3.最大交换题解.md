# LeetCode 最大交换 题解

## 1. 题目概述

- **标题 / 题号**：最大交换（#670，medium）
- **链接**：https://leetcode.cn/problems/maximum-swap/
- **来源**：LeetCode 第 48 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数学

**题意**：给定一个非负整数，**至多**允许交换其中任意两位数字一次，返回交换后能得到的最大整数。两位数字可以不相邻；交换两个相同的数字等于没换；也可以一次都不交换。

**约束**：

- $0 \le num \le 10^8$
- 至多一次交换（"至多"包含零次）
- 交换的下标任意，不要求相邻

> 💡 上限 $10^8$ 意味着最多 9 位，$(i,j)$ 枚举只有 $C_9^2 = 36$ 种，暴力其实能过。本题真正的价值是 $O(n)$ 贪心：它同样适用于位数上万的大数（字符串形式），也是"字典序最大化"类贪心的模板。

## 2. 示例

**示例 1**

```text
输入：num = 2736
输出：7236
解释：交换数字 2 和 7（下标 0 与 1），得到 7236。
```

**示例 2**

```text
输入：num = 9973
输出：9973
解释：数字已按非递增排列，任何交换都不会变大，选择不交换。
```

**示例 3（补充）**

```text
输入：num = 98368
输出：98863
解释：交换下标 2 的 3 与下标 4 的 8（右侧最靠右的 8），得到 98863。
```

**示例 4（补充）**

```text
输入：num = 1999
输出：9991
解释：右侧有三个 9，必须换最右边那个（下标 3），得 9991；
      换下标 1 得 9199，换下标 2 得 9919，都更小。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i,j)$、$i<j$ 共 $O(n^2)$ 组，每组交换后重建整数需 $O(n)$：总计 $O(n^3)$。$n\le 9$ 时最多 $C_9^2 = 36$ 组，毫无压力，但

- 一旦把题目看作"$n$ 位十进制数"的通用问题（$n$ 可达 $10^4$），$O(n^3)$ 与"每次复制整个数字"都会爆；
- 暴力不解释**为什么**答案是那个数，写不出可迁移的结论。

所以下面推一个 $O(n)$、一趟扫描的贪心。

### 3.2 核心观察：最靠左的可提升位 + 最靠右的最大数字

![贪心的两条规则](images/wc48_q3_greedy_concept.svg)

把数字看成字符数组 $d_0 d_1 \dots d_{n-1}$。交换 $(i,j)$（$i<j$）后，**前 $i$ 位完全不变**，第 $i$ 位从 $d_i$ 变成 $d_j$，第 $j$ 位变成 $d_i$。由此得到两条规则：

**规则①（位置越靠左越好）**：若 $d_i < \max_{k>i} d_k$，称 $i$ 为**可提升位**（这一位能通过交换变大）。在所有可提升位中取**最靠左**的 $i^{*}$，因为高位的权重严格大于其后所有位之和：

$$d_{i^{*}} \cdot 10^{\,n-1-i^{*}} \;\text{的一次提升} \;>\; \sum_{k>i^{*}} 9 \cdot 10^{\,n-1-k}$$

**规则②（同值取最靠右）**：右侧可能有多个等于 $\max_{k>i^{*}} d_k$ 的位置，必须换**最靠右**的那个。

设 $i^{*} < p < q$ 且 $d_p = d_q = M = \max_{k>i^{*}} d_k$。比较"换到 $p$"与"换到 $q$"两个结果：前 $i^{*}$ 位相同、第 $i^{*}$ 位都是 $M$，而在 $p$ 处前者是 $d_{i^{*}}$、后者仍是 $M$，所以**换 $q$ 更大**。直观地说：把最大的数字换到最前面之后，剩下的几个 $M$ 当然留在越前面越好。

### 3.3 算法流程：从右往左一趟扫描

![从右往左扫描的流程](images/wc48_q3_algorithm_flow.svg)

维护两个量：`maxDigit` = 当前位**右侧**的最大数字，`maxIdx` = 该最大值**最靠右**的下标；再用 $(u,v)$ 记录待交换的一对下标。

1. 初始 `maxDigit = '0'`、`maxIdx = -1`、$(u,v)=(-1,-1)$；
2. $i$ 从 $n-1$ 递减到 $0$：
   - 若 $d_i > \text{maxDigit}$：更新 `maxDigit = d_i`、`maxIdx = i`；
   - 若 $d_i < \text{maxDigit}$：令 $(u,v) = (i, \text{maxIdx})$，**直接覆盖旧记录**；
   - 若 $d_i = \text{maxDigit}$：什么也不做（保留更靠右的下标，这正是规则②）。
3. 扫描结束后若 $u \ne -1$，交换 $d_u,d_v$，转回整数返回。

"覆盖旧记录"是 $O(1)$ 空间的关键：扫描方向从右到左，后写入的 $u$ 一定更小（更靠左），所以循环结束时留下的正是**最靠左的可提升位**，不需要回头再找。

### 3.4 示例演算

![num = 2736 的走查](images/wc48_q3_example_walkthrough.svg)

以 $num = 2736$ 为例（$d = [2,7,3,6]$）：

| $i$ | $d_i$ | maxDigit | maxIdx | 动作 |
|-----|-------|----------|--------|------|
| 3 | 6 | 6 | 3 | $6 > 0$，初始化最大值 |
| 2 | 3 | 6 | 3 | $3<6$，记 $(u,v)=(2,3)$ |
| 1 | 7 | 7 | 1 | $7>6$，更新最大值 |
| 0 | 2 | 7 | 1 | $2<7$，覆盖为 $(0,1)$ |

最终交换下标 $0,1$：$2736 \to 7236$。注意 $i=1$ 时最大值从 6 换成了 7，所以 $i=0$ 的交换对象变成下标 1 的 7——这正是"最靠左可提升位 + 后缀最大数"的体现。

再看 $num = 98368$：$i=3,2$ 依次记下 $(3,4)$、$(2,4)$（发生覆盖）；$i=1$ 的 $8$ 与 `maxDigit` 相等，**不更新**，`maxIdx` 仍是 4；$i=0$ 的 9 更新了最大值，但它已在最高位、无处可换。最终交换 $(2,4)$ 得 $98863$。

## 4. 算法细节

1. **转成字符数组再操作**：`to_string(num)` / `str(num)` 后直接比较字符，'0'~'9' 的 ASCII 序与数值序一致，无需反复取模除 10。
2. **初始值取 `maxDigit = '0'`、`maxIdx = -1`**：任何数字都不小于 '0'，因此第一个被扫描的位（最右位）必然触发更新，`maxIdx` 立即变成合法下标；$-1$ 只是"尚未初始化"的占位。
3. **等值分支必须显式排除**：$d_i = \text{maxDigit}$ 时既不能更新 `maxIdx`（会破坏"最靠右"），也不能记入 $(u,v)$（交换不产生收益）。
4. **不要提前 `break`**：一旦命中 $d_i < \text{maxDigit}$ 就返回，$2736$ 会得到 $2763$ 这类错误答案；必须扫完，让更靠左的位置覆盖记录。
5. **最后统一转回整数**：只在末尾做一次 `stoi` / `int(''.join(d))`，避免在循环里构造整数；结果在 `int` 范围内，C++ 里也不必用 `long long`。
6. **另一条等价实现**：从左往右找第一个可提升位，再预计算"后缀最大值的下标表"，同样正确，但需要 $O(n)$ 辅助数组；从右往左一趟扫描只要 $O(1)$ 额外空间，代码也更短。
7. **允许不交换**：没有可提升位时 $(u,v)$ 保持 $(-1,-1)$，直接跳过交换返回原值，避免"必须换一次"的误解。

## 5. 正确性证明

**引理 1（同值取最靠右更优）**：设 $i$ 是可提升位，$M=\max_{k>i} d_k$，且 $i<p<q$、$d_p=d_q=M$。则交换 $(i,q)$ 的结果严格大于交换 $(i,p)$ 的结果。

**证明**：两个结果的前 $i$ 位都是 $d_0\dots d_{i-1}$，第 $i$ 位都是 $M$；在 $i$ 与 $p$ 之间的位上两者也相同（只改动了 $p$、$q$ 两位，其中 $q>p$）。第一个不同的位置是 $p$：交换 $(i,p)$ 时该位为 $d_i$，交换 $(i,q)$ 时该位仍为 $M$。由 $d_i<M$，后者更大。∎

**引理 2（最靠左的可提升位是最优首位）**：若存在可提升位，设 $i^{*}$ 为最靠左的一个，$j^{*}$ 为其右侧最大数字的最右下标。则任何使结果增大的交换 $(a,b)$ 都满足 $a=i^{*}$，且 $b=j^{*}$ 时结果最大。

**证明**：设交换 $(a,b)$ 使结果增大，则必有 $d_b>d_a$，即 $a$ 是可提升位。

- 若 $a<i^{*}$：由 $i^{*}$ 的最小性，$a$ 不可能是可提升位，矛盾。
- 若 $a>i^{*}$：交换 $(a,b)$ 不改变第 $i^{*}$ 位，该位仍为 $d_{i^{*}}$；而交换 $(i^{*},j^{*})$ 把该位变成 $M=\max_{k>i^{*}}d_k>d_{i^{*}}$，更靠左的位两者完全相同，故后者更大。
- 于是 $a=i^{*}$；首位确定后，由引理 1 取 $b=j^{*}$ 最优。∎

**定理**：算法返回的是"至多交换一次"所能得到的最大数。

**证明**：若存在可提升位，由引理 2，任何使结果增大的交换首位必为 $i^{*}$、次位必为 $j^{*}$，即算法构造的交换就是最优交换，算法恰好执行它，返回最大值。若不存在可提升位，则对任意 $a<b$ 有 $d_a\ge d_b$，交换后第 $a$ 位不增、更靠左的位不变，结果不超过原值，故原值即最大；算法不交换、返回原值，同样最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次十进制拆位 $O(n)$、一趟从右往左扫描 $O(n)$、一次拼接转回 $O(n)$；$n\le 9$（一般情形 $n$ 为位数），实际是常数时间。
- **空间**：$O(n)$ 存放字符数组（$n\le 9$ 时可视为 $O(1)$）；扫描本身只用 `maxDigit`、`maxIdx`、$(u,v)$ 四个变量，额外空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maximumSwap(int num) {
        string d = to_string(num);
        int n = d.size();
        char maxDigit = '0';          // 当前位右侧的最大数字
        int maxIdx = -1;              // 该最大值最靠右的下标
        int swapI = -1, swapJ = -1;   // 待交换的下标对

        for (int i = n - 1; i >= 0; --i) {
            if (d[i] > maxDigit) {        // 遇到更靠左的更大数字
                maxDigit = d[i];
                maxIdx = i;
            } else if (d[i] < maxDigit) { // 这一位可提升，覆盖旧记录
                swapI = i;
                swapJ = maxIdx;
            }
            // d[i] == maxDigit：保留更靠右的下标，什么也不做
        }
        if (swapI != -1) swap(d[swapI], d[swapJ]);
        return stoi(d);
    }
};
```

### Python

```python
class Solution:
    def maximumSwap(self, num: int) -> int:
        d = list(str(num))
        max_digit = '0'        # 当前位右侧的最大数字
        max_idx = -1           # 该最大值最靠右的下标
        swap_i = swap_j = -1   # 待交换的下标对

        for i in range(len(d) - 1, -1, -1):
            if d[i] > max_digit:
                max_digit, max_idx = d[i], i
            elif d[i] < max_digit:      # 可提升位，覆盖旧记录 ⇒ 留下最靠左的
                swap_i, swap_j = i, max_idx

        if swap_i != -1:
            d[swap_i], d[swap_j] = d[swap_j], d[swap_i]
        return int(''.join(d))
```

## 8. 边界情况与易错点

1. **一位数 / 0**：`num = 0` → `"0"`，循环里 `'0' > '0'` 与 `'0' < '0'` 都不成立，`swap_i` 保持 $-1$，原样返回 0。
2. **数字已非递增**（如 9973、100、10）：不存在可提升位，必须返回原值；若按"交换最大最小"之类的直觉硬换，反而会变小。
3. **相等最大值必须取最右**：1999 中 9 在下标 1、2、3，换最左的 9 得 9199，比正确的 9991 小；这正是 $d_i=\text{maxDigit}$ 时**不更新** `maxIdx` 的原因。
4. **不能提前返回**：2736 在 $i=2$ 已记录 $(2,3)$，若此处直接返回会把答案写成 2763；必须扫到 $i=0$ 覆盖为 $(0,1)$。
5. **不要把 0 换到高位**：前导 0 会减少位数，一定不是最优；算法只在"右侧有更大数字"时动作，天然不会把 0 提到前面（`num = 100` 保持 100）。
6. **$10^8$ 是 9 位数**：100000000 没有可提升位，返回原值；最大结果在 99999999 量级，`int` 足够。
7. **"至多一次"不是"恰好一次"**：交换相同数字等于没换，结果不变，因此不必为"必须换一次"做特判。
