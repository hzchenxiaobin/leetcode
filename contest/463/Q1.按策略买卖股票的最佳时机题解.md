# LeetCode 按策略买卖股票的最佳时机 题解

## 1. 题目概述

- **标题 / 题号**：按策略买卖股票的最佳时机（#3652，medium）
- **链接**：https://leetcode.cn/problems/best-time-to-buy-and-sell-stock-using-strategy/
- **来源**：LeetCode 第 463 场周赛 Q1
- **难度**：中等
- **标签**：数组、前缀和、滑动窗口

**题意**：给定两个长度相同的数组 `prices` 与 `strategy`：`prices[i]` 是第 $i$ 天的股价，`strategy[i] ∈ {−1, 0, 1}$` 分别表示当天**买入**一单位、**持有**、**卖出一单位**。**利润**定义为 $\sum_i \text{strategy}[i] \times \text{prices}[i]$。再给定**偶数** $k$，允许对 `strategy` 做**最多一次**修改：选恰好 $k$ 个**连续**元素，把前 $k/2$ 个改成 $0$、后 $k/2$ 个改成 $1$。求可获得的最大利润（无预算与持仓限制，一切操作合法）。

**约束**：

- $2 \le n = \text{prices.length} = \text{strategy.length} \le 10^5$
- $1 \le \text{prices}[i] \le 10^5$
- $-1 \le \text{strategy}[i] \le 1$
- $2 \le k \le n$，且 $k$ 为偶数

> 💡 **赛时快速切入**：本题题面长但结构干净——修改是"**最多**一次"且**模式写死**（前半恒 0、后半恒 1）。一眼定位为「**原始利润 base + 定长窗口增益**」的前缀和/滑窗题，与 1052 爱生气的书店老板同构。

## 2. 示例

**示例 1**

```text
输入：prices = [4,2,8], strategy = [-1,0,1], k = 2
输出：10
解释：修改下标 [0,1] 这一段（前 1 个改 0、后 1 个改 1），
      strategy 变为 [0,1,1]，利润 = 0×4 + 1×2 + 1×8 = 10。
```

**示例 2**

```text
输入：prices = [5,4,3], strategy = [1,1,0], k = 2
输出：9
解释：任何修改都不优——不修改时利润 = 5 + 4 + 0 = 9 已是最大值。
```

## 3. 解题思路

### 3.1 暴力思路

枚举每个窗口起点 $l$（共 $n-k+1$ 个），把窗口替换成「前半 0、后半 1」后**重算整个数组**的利润，与不修改的 `base` 一起取最大。单窗口重算 $O(n)$，总计 $O(n^2)$——$n = 10^5$ 时约 $10^{10}$ 次运算，必然超时。

瓶颈在于：**窗口外的贡献每次都被重复计算**。窗外每一项 $s_i p_i$ 在修改前后逐项不变，重算纯属浪费。

### 3.2 核心观察：利润 = base − old + cur

![核心观察：一次修改只改变窗口内的贡献](images/stock_strategy_window_split.svg)

**观察一（影响局部化）**：把总利润按「窗口外 / 窗口内」拆开，一次修改只改写下标在 $[l, l+k)$ 内的策略值：

$$\text{利润}(l) = \underbrace{\sum_{i \notin [l,\,l+k)} s_i p_i}_{=\ \text{base}} \;-\; \underbrace{\sum_{i=l}^{l+k-1} s_i p_i}_{\text{old：原窗口贡献}} \;+\; \underbrace{\sum_{i=l+k/2}^{l+k-1} p_i}_{\text{cur：新窗口贡献}}$$

**观察二（新贡献与原策略无关）**：替换规则把前 $k/2$ 个位置硬编码为 $0$（贡献 $0 \times p = 0$）、后 $k/2$ 个硬编码为 $1$（贡献 $p$），所以新窗口贡献就是**后 $k/2$ 天的价格和**——窗口里原来的策略是什么完全不重要。这是本题最容易被忽略的简化点。

**观察三（两组前缀和 $O(1)$ 查询）**：

- $A[i] = \sum_{j<i} s_j p_j$（加权和前缀），则 $\text{old}(l) = A[l+k] - A[l]$；
- $B[i] = \sum_{j<i} p_j$（价格前缀），则 $\text{cur}(l) = B[l+k] - B[l+k/2]$。

于是：

$$\text{ans} = \max\Big(\text{base},\ \max_{0 \le l \le n-k}\ \big(\text{base} - \text{old}(l) + \text{cur}(l)\big)\Big)$$

> ⚠️ **溢出**：总利润可达 $n \cdot \max p \le 10^5 \times 10^5 = 10^{10}$ 量级，超出 32 位 `int`，C++ 全程用 `long long`。

### 3.3 算法流程

![算法流程：前缀和 + 枚举定长窗口](images/stock_strategy_prefix_flow.svg)

| 步骤 | 操作 | 说明 |
|------|------|------|
| ① 算 base | $\text{base} = \sum s_i p_i$ | 不修改时的原始利润 |
| ② 建前缀 | $A$（$s \cdot p$ 前缀）、$B$（$p$ 前缀） | 一趟 $O(n)$ |
| ③ 保底 | `ans = base` | 「最多一次」修改 ⇒ 不改也是候选 |
| ④ 枚举窗口 | $l$ 从 $0$ 到 $n-k$ | 共 $n-k+1$ 个定长窗口 |
| ⑤ O(1) 查询 | $\text{old} = A[l{+}k]-A[l]$，$\text{cur} = B[l{+}k]-B[l{+}k/2]$ | 两组前缀和各查一次 |
| ⑥ 收答案 | $\text{ans} = \max(\text{ans},\ \text{base} - \text{old} + \text{cur})$ | 遍历完返回 `ans` |

### 3.4 示例演算

![示例1演算：抹掉亏钱买入并白赚一次卖出](images/stock_strategy_example_walkthrough.svg)

**示例 1**（$k=2$，答案 10）：$\text{base} = (-1){\times}4 + 0{\times}2 + 1{\times}8 = 4$：

| 窗口 $[l, l+k)$ | old（原窗口贡献） | cur（后 $k/2$ 天价格和） | base − old + cur |
|---|---|---|---|
| $[0, 2)$ | $(-1){\times}4 + 0{\times}2 = -4$ | $p_1 = 2$ | $4 + 4 + 2 = \mathbf{10}$ |
| $[1, 3)$ | $0{\times}2 + 1{\times}8 = 8$ | $p_2 = 8$ | $4 - 8 + 8 = 4$ |

$\text{ans} = \max(4, 10, 4) = 10$ ✓——窗口 $[0,2)$ 把亏钱的「第 0 天买入」抹成持有，同时把第 1 天改成卖出，白赚 $p_1 = 2$。

**示例 2**（$k=2$，答案 9）：$\text{base} = 5 + 4 + 0 = 9$；窗口 $[0,2)$ 给出 $9 - 9 + 4 = 4$，窗口 $[1,3)$ 给出 $9 - 4 + 3 = 8$，全部不超过 base，**不改就是最优**——这正是「最多一次」而非「恰好一次」的意义。

## 4. 算法细节

1. **两组前缀和的分工**：$A$ 服务 `old`（原策略加权和的区间和），$B$ 服务 `cur`（价格的区间和）。窗口内"替换成固定模式"使得两个查询的区间**不同**：`old` 查 $[l, l+k)$，`cur` 只查后一半 $[l+k/2,\ l+k)$。
2. **中点下标**：令 $h = k/2$，则 $\text{cur} = B[l+k] - B[l+h]$。$l+h$ 是「后一半的起点」。
3. **保底初始化**：`ans` 初值直接取 `A[n]`（即 base），天然覆盖「不修改」分支，无需特判。
4. **$O(1)$ 空间变体**：窗口右移时 `old` 与 `cur` 均可增量维护——$\text{old}(l{+}1) = \text{old}(l) - s_l p_l + s_{l+k} p_{l+k}$，$\text{cur}(l{+}1) = \text{cur}(l) - p_{l+h} + p_{l+k}$。赛时建议先写前缀和版本保正确，有余力再优化。

## 5. 正确性证明

**引理 1（影响局部化）**：设修改窗口为 $[l, l+k)$，修改后策略数组为 $s'$，则 $s'_i = s_i$ 对所有 $i \notin [l, l+k)$ 成立，且

$$\sum_i s'_i p_i - \sum_i s_i p_i = \sum_{i \in [l,\,l+k)} (s'_i - s_i)\, p_i.$$

**证明**：修改操作只改写下标在 $[l, l+k)$ 内的 `strategy` 值（前 $k/2$ 个写 $0$、后 $k/2$ 个写 $1$）。窗外下标处 $s'_i = s_i$，逐项差为 $0$，求和时全部相消，只剩下窗口内的差。∎

**引理 2（新窗口贡献闭式）**：修改窗口 $[l, l+k)$ 后，窗口内的贡献为

$$\text{cur}(l) = \sum_{i=l+k/2}^{l+k-1} p_i,$$

与原策略 $s$ 在窗口内的取值无关。

**证明**：窗口内前 $k/2$ 个位置被写为 $0$，贡献 $0 \cdot p_i = 0$；后 $k/2$ 个位置被写为 $1$，贡献 $1 \cdot p_i = p_i$。逐项求和即得，表达式中只出现 $p$。∎

**定理**：算法返回所有可行方案利润的最大值。

**证明**：可行方案集为 $\{\text{不修改}\} \cup \{[l, l+k) : 0 \le l \le n-k\}$。不修改的利润为 $\text{base} = A[n]$，算法以 `ans` 初值覆盖之。对任一修改方案 $[l, l+k)$，记其修改后利润为 $P(l)$。由引理 1，

$$P(l) = \text{base} - \underbrace{\sum_{i=l}^{l+k-1} s_i p_i}_{\text{old}(l)} + \text{cur}(l),$$

其中窗口内新贡献由引理 2 给出。由前缀和定义，$\text{old}(l) = A[l+k] - A[l]$，$\text{cur}(l) = B[l+k] - B[l+k/2]$，均可 $O(1)$ 精确计算。算法对所有 $l \in [0, n-k]$ 枚举候选并与 `base` 取最大，候选集与可行方案集一一对应且计算无误，故返回值即最大利润。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟建两组前缀和 $O(n)$；枚举 $n-k+1$ 个窗口，每个窗口两次 $O(1)$ 前缀查询。对比暴力 $O(n^2)$，把「重算全数组」拆成「常量 base + 两个区间和」是前缀和最典型的用法。
- **空间复杂度**：$O(n)$。两个长度 $n+1$ 的前缀数组；改用增量维护可降到 $O(1)$（见 §4 第 4 点）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long maxProfit(vector<int>& prices, vector<int>& strategy, int k) {
        int n = prices.size();
        vector<long long> A(n + 1), B(n + 1);   // A: s*p 前缀和, B: p 前缀和
        for (int i = 0; i < n; ++i) {
            A[i + 1] = A[i] + 1LL * strategy[i] * prices[i];
            B[i + 1] = B[i] + prices[i];
        }
        long long ans = A[n];                   // 不修改的保底
        int h = k / 2;
        for (int l = 0; l + k <= n; ++l) {
            long long old = A[l + k] - A[l];    // 原窗口贡献
            long long cur = B[l + k] - B[l + h];// 新窗口贡献 = 后 k/2 天价格和
            ans = max(ans, A[n] - old + cur);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxProfit(self, prices: List[int], strategy: List[int], k: int) -> int:
        n = len(prices)
        A = [0] * (n + 1)   # A[i] = 前 i 天 strategy[j]*prices[j] 之和
        B = [0] * (n + 1)   # B[i] = 前 i 天 prices[j] 之和
        for i, (p, s) in enumerate(zip(prices, strategy)):
            A[i + 1] = A[i] + s * p
            B[i + 1] = B[i] + p

        ans = A[n]          # 不修改的保底
        h = k // 2
        for l in range(n - k + 1):
            old = A[l + k] - A[l]            # 原窗口贡献
            cur = B[l + k] - B[l + h]        # 新窗口贡献 = 后 k/2 天价格和
            ans = max(ans, A[n] - old + cur)
        return ans
```

## 8. 边界情况与易错点

1. **「最多一次」≠「恰好一次」**：`ans` 初值必须取 `base`。若所有窗口的增益 $\text{cur} - \text{old}$ 均为负，强行修改反而亏，答案回落到 base（示例 2 正是如此）。
2. **溢出**：$|\text{利润}| \le n \cdot \max p \le 10^{10}$，超出 `int`。C++ 中前缀数组、`ans`、返回值都用 `long long`，乘法写 `1LL * strategy[i] * prices[i]` 防中间结果按 `int` 溢出；Python 无此问题。
3. **`cur` 的中点下标**：查询的是 $B[l+k] - B[l+k/2]$，其中 $l + k/2$ 是**后一半的起点**。误写成 $l + k/2 - 1$（左闭右开写错）或 $k/2$（忘了加 $l$）是本题最高频的 WA 点。
4. **$k = n$**：唯一窗口 $[0, n)$，循环条件 `l + k <= n` 自然只跑一次，前缀数组开 $n+1$ 长即可安全访问 $A[n]$、$B[n]$。
5. **旧贡献可能为负**：`old` 是 $s_i p_i$ 的和，可以小于 0（连续买入）。此时 $-\text{old} > 0$ 是纯增益，不要假设窗口修改一定"换掉正贡献"。
6. **$k$ 为偶数**由题目保证，`k / 2` 整数除法无取整歧义；若赛时不确定，可用 `k >> 1` 显式表达。
