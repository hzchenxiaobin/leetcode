# LeetCode 边界上的蚂蚁 题解

## 1. 题目概述

- **标题 / 题号**：边界上的蚂蚁（#3028，easy）
- **链接**：https://leetcode.cn/problems/ant-on-the-boundary/
- **来源**：LeetCode 第 383 场周赛 Q1
- **难度**：简单
- **标签**：数组、前缀和、模拟

**题意**：把「边界」看作数轴原点，蚂蚁从原点出发，按顺序执行 `nums` 中的每条指令：正数向右移动对应单位，负数向左移动对应单位。**每条指令走完后**检查一次位置，若恰好停在原点，则计一次「返回」。途中穿过边界不算，出发时的起点也不算。求蚂蚁返回边界上的总次数。

**约束**：

- $1 \le \text{nums.length} \le 100$
- $-10 \le \text{nums}[i] \le 10$，且 $\text{nums}[i] \ne 0$

> 💡 读题三个关键点：① 位置是**带符号**的（右正左负）；② 检查只发生在**每步移动完毕后**的停点，途中穿过不算；③ 蚂蚁**起点就在边界**上，但那不算「返回」。把这三点翻译成一个变量，答案就出来了。

## 2. 示例

**示例 1**

```text
输入：nums = [2,3,-5]
输出：1
解释：位置依次为 2 → 5 → 0。
第 3 步恰好停在边界上，计 1 次。
```

**示例 2**

```text
输入：nums = [3,2,-3,-4]
输出：0
解释：位置依次为 3 → 5 → 2 → −2。
第 4 步从 +2 一步移动到 −2，途中穿过边界但不停留，不计。
蚂蚁从未停在边界上，答案为 0。
```

**示例 3（补充：多次返回）**

```text
输入：nums = [1,-1,1,-1]
输出：2
解释：位置依次为 1 → 0 → 1 → 0。
第 2、4 步两次停在边界上——返回后模拟继续，不能提前退出。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的模拟：对每个下标 $i$，从头累加前 $i+1$ 个元素得到总位移，再判断是否为 $0$：

```python
ans = 0
for i in range(len(nums)):
    if sum(nums[: i + 1]) == 0:   # 每步重新求和
        ans += 1
```

正确性没有问题，$n \le 100$ 时 $O(n^2)$ 也能过。但第 $i$ 步的总位移与第 $i-1$ 步只差一个 $\text{nums}[i]$，从头累加等于把同样的加法重复做了 $n$ 遍——这个被浪费的递推关系正是优化的入口。

另一种常见的绕路写法是维护「距边界的距离 + 当前方向」两个变量，按正负分支讨论。能做对，但把一个**带符号数轴**问题拆成了两个无符号量，分支多、易错——方向本来就该由符号承担。

### 3.2 核心观察：位置 = 前缀和，返回边界 ⇔ 前缀和归零

![核心概念：蚂蚁位置就是前缀和，停点为 0 才计数](images/ant_boundary_prefix_sum_concept.svg)

把边界设为**原点**，向右为正、向左为负，则每一步的移动量恰是 $\text{nums}[i]$ 本身（负数自带方向）。于是第 $i$ 步结束时的位置就是**前缀和**：

$$S_i = \text{nums}[0] + \text{nums}[1] + \cdots + \text{nums}[i]$$

题面的三个细节被前缀和**一次性全部编码**：

1. **返回边界 ⇔ $S_i = 0$**：停在原点，当且仅当前缀和归零；
2. **穿过不算**：一步之内从 $S_{i-1}$ 连续移动到 $S_i$，中途不停留，$S_i$ 只记录**停点**——从 $+2$ 一步移到 $-2$ 途中路过 $0$，但 $S_i = -2 \ne 0$，天然不计数；
3. **起点不算**：初始 $S = 0$ 发生在任何移动**之前**，只要把判零写在累加之后，起点永远不会被检查。

### 3.3 算法流程：滚动前缀和 + 停点判零

![算法流程：滚动累加，停点为 0 才计数](images/ant_boundary_algorithm_flow.svg)

1. 初始化位置 `pos = 0`、答案 `ans = 0`；
2. 顺序读取每个元素 `x`：`pos += x`（滚动前缀和，$S_i = S_{i-1} + \text{nums}[i]$，$O(1)$ 更新）；
3. 移动完成后判零：若 `pos == 0`，则 `ans += 1`；
4. 所有元素处理完，返回 `ans`。

注意**计数后不提前退出**：示例 3 中蚂蚁两次回到边界，循环必须走完。

### 3.4 示例演算

![示例演算：三组输入逐步滚动 pos，停点为 0 才计数](images/ant_boundary_walkthrough.svg)

| 输入 | pos 逐步变化 | 停点归零 | 答案 |
|------|--------------|----------|------|
| `[2,3,-5]` | $2 \to 5 \to 0$ | 第 3 步 ✓ | $1$ |
| `[3,2,-3,-4]` | $3 \to 5 \to 2 \to -2$ | 无（第 4 步跨过 $0$ 不停留） | $0$ |
| `[1,-1,1,-1]` | $1 \to 0 \to 1 \to 0$ | 第 2、4 步 ✓ | $2$ |

## 4. 算法细节

1. **滚动变量代替前缀和数组**：只依赖当前前缀 $S_i$，无需存历史，一个变量 `pos` 滚动更新即可，空间 $O(1)$。
2. **判定顺序即语义**：`if pos == 0` 必须写在 `pos += x` **之后**且位于循环体内——这同时保证「起点不计」（初始值从未被检查）与「每步移动后检查」（与题面时机一致）。
3. **计数后继续循环**：返回边界不是终止条件，多次返回要多次计数。
4. **单变量带符号建模**：右正左负，方向由符号承担；不要拆成「距离 + 方向」双变量引入额外分支。

## 5. 正确性证明

**引理 1**（位置 = 前缀和）：对每个 $i \in [0, n)$，第 $i$ 步移动结束后蚂蚁的位置为 $S_i = \sum_{k=0}^{i} \text{nums}[k]$。

**证明**：对 $i$ 归纳。移动前蚂蚁位于原点，即 $S_{-1} = 0$。设第 $i-1$ 步后位置为 $S_{i-1}$。第 $i$ 步向右（$\text{nums}[i] > 0$）或向左（$\text{nums}[i] < 0$）移动 $|\text{nums}[i]|$ 单位，新位置为 $S_{i-1} + \text{nums}[i] = S_i$。∎

**引理 2**（判零的正确性）：蚂蚁在第 $i$ 步后位于边界上，当且仅当 $S_i = 0$；「途中穿过边界」的步骤不会使判定成立。

**证明**：边界即原点，位置为原点当且仅当 $S_i = 0$。一步移动是连续的：蚂蚁从 $S_{i-1}$ 沿数轴走到 $S_i$，中途不停留，而检查只发生在移动完成后的停点。若 $S_{i-1}$ 与 $S_i$ 异号（如 $+2 \to -2$），途中确实经过原点，但停点 $S_i \ne 0$，判定 `pos == 0` 为假，天然不计数。∎

**定理**：算法返回的 `ans` 等于蚂蚁返回边界的次数。

**证明**：循环体对每个 $i$ 恰好执行一次「累加 → 判零」，与题面「每步移动完成后检查」一一对应。由引理 1、2，`ans` 恰好数出所有满足 $S_i = 0$ 的下标，即每次真正停回边界的时刻。初始 $S_{-1} = 0$ 发生在首次累加之前，不处于任何检查点上，起点不计；每个满足条件的下标独立计数、循环不提前退出，多次返回均被计入。故 `ans` 既不多计也不少计。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素处理一次：一次加法 + 一次判等，均为 $O(1)$。
- **空间复杂度**：$O(1)$。仅用 `pos`、`ans` 两个变量；前缀和滚动更新，无需数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int returnToBoundaryCount(vector<int>& nums) {
        int pos = 0, ans = 0;
        for (int x : nums) {
            pos += x;             // 滚动前缀和：本步移动后的位置
            if (pos == 0) ans++;  // 停点恰好在边界才计数（穿过/起点不触发）
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def returnToBoundaryCount(self, nums: List[int]) -> int:
        pos = ans = 0
        for x in nums:
            pos += x
            if pos == 0:
                ans += 1
        return ans
```

> 💡 函数式一行版：`return sum(p == 0 for p in accumulate(nums))`——`itertools.accumulate` 逐项吐出前缀和，布尔值直接被 `sum` 计数。

## 8. 边界情况与易错点

1. **起点不计**：判零必须写在累加之后。若把 `if pos == 0` 放在累加之前（或循环外先判一次初始值），任何输入都会凭空多计 1 次。
2. **穿过不算**：`pos == 0` 只在停点判断。`[3,2,-3,-4]` 第 4 步从 $+2$ 到 $-2$ 途中路过 $0$，但停点是 $-2$，不计数。
3. **计数后不 break**：`[1,-1,1,-1]` 两次返回，答案为 2；见到 `pos == 0` 就退出会把答案算成 1。
4. **别用「距离 + 方向」双变量**：符号已编码方向，双变量写法分支多，易在「先移动还是先更新方向」上出错。
5. **溢出无忧**：$|\text{pos}| \le 100 \times 10 = 1000$，`int` 绰绰有余（核对数据范围的习惯仍要保留）。
6. **$\text{nums}[i] \ne 0$ 的作用**：保证每步必动，检查时机良定义。若允许 $0$，「移动 0 单位后仍停在边界算不算返回」将成为题意歧义——约束替出题人把坑填了。
