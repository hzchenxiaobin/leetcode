# LeetCode K 周期字符串需要的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：K 周期字符串需要的最少操作次数（#3137，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-operations-to-make-word-k-periodic/
- **来源**：LeetCode 第 396 场周赛 Q2
- **难度**：中等
- **标签**：哈希表，字符串，计数

**题意**：给定长度为 $n$ 的字符串 `word` 和整数 $k$（$k$ 整除 $n$）。一次操作可以选择**都被 $k$ 整除**的下标 $i, j$，用子串 `word[j..j+k-1]` 整体替换子串 `word[i..i+k-1]`。求使 `word` 成为 **K 周期字符串**的最少操作次数——即存在长度为 $k$ 的串 $s$，使 `word` 等于 $s$ 重复 $n/k$ 次（如 `"ababab"` 是 $s = \text{"ab"}$ 的 2 周期串）。

**约束**：

- $1 \le n = \mathrm{word.length} \le 10^5$
- $1 \le k \le n$，且 $k \mid n$
- `word` 仅由小写英文字母组成

> 💡 读题关键信号：**「$i, j$ 都是 $k$ 的倍数」+「替换长度恰为 $k$」**两条合起来，意味着操作永远是**整块搬运**——把 `word` 按 $k$ 切成 $m = n/k$ 个块后，块的**槽位**永远对齐不动，动的只是槽里的内容。于是「使 word 成为周期串」被翻译成「$m$ 个块统一成同一个串 $s$」，最少操作数就是一场**投票计数**：保留出现次数最多的块，其余块各抄一次。

## 2. 示例

**示例 1**

```text
输入：word = "leetcodeleet", k = 4
输出：1
解释：块为 leet / code / leet。选择 i = 4、j = 0，把 "code" 换成 "leet"，
      得到 "leetleetleet"，是 s = "leet" 的 4 周期串。
```

**示例 2**

```text
输入：word = "leetcoleet", k = 2
输出：3
解释：块为 le / et / co / le / et。保留出现最多的块（le、et 并列各 2 次），
      官方操作序列 (i=0,j=2)、(i=4,j=0)、(i=6,j=0)：
      "leetcoleet" → "etetcoleet" → "etetetleet" → "etetetetet"。
```

**补充示例**

```text
输入：word = "aaaa", k = 4
输出：0
解释：单块（m = 1）天然是周期串；全部块相同时也一样，公式 m − max cnt 自动给出 0。
```

两个官方示例恰好覆盖「并列最大频率」与「一步到位」两种形态，赛场上先在脑内把块切出来再动手，比直接盯字符串本身快得多。

## 3. 解题思路

### 3.1 暴力思路：枚举周期候选，逐块比较

终态必形如 $s^m$（$s$ 重复 $m$ 次）。自然的暴力是**枚举周期候选 $s$，数有多少块 $\ne s$**，取最小值。

候选 $s$ 似乎是任意长 $k$ 的小写串（$26^k$ 种，$k$ 可达 $10^5$，完全不可行），但其实**只需枚举现有的 $m$ 个块**：全新串的代价是 $m$，而任何现有块「自己那一块免费」、代价至多 $m-1$，永远不劣（严格论证见 §5 引理 3）。

```python
def brute(word, k):
    n, m = len(word), len(word) // k
    blocks = [word[i:i + k] for i in range(0, n, k)]
    return min(sum(b != s for b in blocks) for s in blocks)
```

- 正确性没有问题（枚举覆盖了最优 $s$），但每对块比较 $O(k)$，总计 $O(m^2 k) = O(n \cdot m)$：$n = 10^5$、$k = 1$ 时 $m = 10^5$，约 $10^{10}$ 次字符比较，必超时。
- 暴力的价值在于把问题**翻译**清楚了：答案 $= \min_s (m - \mathrm{cnt}[s]) = m - \max_s \mathrm{cnt}[s]$。剩下的事只是把「逐块比较」换成「哈希归桶」。

> ⚠️ 更朴素的 BFS（对每个可达字符串状态搜最短路）完全不可行——状态空间 $26^n$ 级别。本题的突破口在**计数**，不在搜索。

### 3.2 核心观察：分块计数，保留最大频率的块

![核心概念：按 k 切块归桶计数，保留出现最多的块](images/kperiodic_blocks_concept.svg)

**观察一（块结构不变式）**：$i, j$ 均为 $k$ 的倍数、替换又恰好长 $k$，所以每次操作只是把**某个槽位的当前内容整体换成另一个槽位的当前内容**。$m$ 个块槽位（起点 $0, k, 2k, \dots$）自始至终不动，动的是槽里的字符串。

**观察二（一次操作恰好改写一个块）**：块的内容只有被选作 $i$ 才会改写。于是要把全部块统一成 $s$，每个初始 $\ne s$ 的块至少消耗一次操作，且不同块所需的操作互不相同：

$$\text{操作数} \;\ge\; m - \mathrm{cnt}[s]$$

**观察三（保留谁？票数最多的）**：上式对任意 $s$ 成立，取反方向的最大值即得

$$\boxed{\text{ans} = m - \max_t \mathrm{cnt}[t] = \frac{n}{k} - \max_t \mathrm{cnt}[t]}$$

一句话：**「保留谁」是一场选举**——留 $s$ 的代价是 $m - \mathrm{cnt}[s]$，票数（出现次数）最高的候选人兼职成本最低，哈希表就是开票器。

### 3.3 算法流程

![算法流程：一遍扫描计数，顺手维护最大频率](images/kperiodic_algorithm_flow.svg)

一遍扫描：$i$ 从 $0$ 步进 $k$，取块 `word[i..i+k-1]` 计入哈希表并**顺手维护最大频率** `best`；扫描结束返回 `m - best`。若还需输出操作序列：固定最大频率块的**第一个出现位置** $p$ 作「母版」，对每个 $\ne s^*$ 的块执行一次 $(i = \text{块起点},\ j = p)$。

### 3.4 示例演算

![示例演算：leetcoleet 三步操作与 leetcodeleet 一步操作](images/kperiodic_example_walkthrough.svg)

**例 2**（`word = "leetcoleet"`，$k = 2$）：块 `le / et / co / le / et`，$m = 5$、最大频率 $2$（`le`、`et` 并列），答案 $5 - 2 = 3$。固定 slot 1 的 `et` 为母版，三步 $(0,2), (4,2), (6,2)$ 全部对齐；官方操作序列 $(0,2), (4,0), (6,0)$ 在第一步后把**源**换成了已改写的 slot 0——只要源块当前内容是 $s^*$ 就合法，两种方案步数相同，固定母版的写法更便于证明（母版全程不动，见 §5）。

**例 1**（`word = "leetcodeleet"`，$k = 4$）：块 `leet / code / leet`，最大频率 $2$，答案 $3 - 2 = 1$，一步 $(i=4, j=0)$ 搞定。

## 4. 算法细节

1. **切块**：`i` 以 `k` 为步长遍历（`range(0, n, k)`），由 $k \mid n$ 保证恰好 $m$ 块、无零头。
2. **计数 + 求最大合并**：C++ 里 `++cnt[s]` 的返回值是自增后的计数，直接 `best = max(best, ++cnt[...])`，把「计数」与「求最大」折叠进一趟循环，免掉对哈希表的二次扫描。
3. **键的选择**：键为长 $k$ 的子串，`substr(i, k)` 每块拷贝 $O(k)$，总计 $O(n)$ 已达标；追求常数可用 `string_view` 零拷贝（本题只读安全，详见文末每日题解）。
4. **答案公式**：`m - best`，其中 `m = n // k`。不要把 $n$ 直接带进去。
5. **并列最大频率**：无需关心保留**谁**，答案只依赖 $\max \mathrm{cnt}$ 的**值**。

## 5. 正确性证明

**引理 1**（块结构不变式）：任何时刻，`word` 由 $m$ 个长度恰为 $k$ 的块拼接而成，块起点恒为 $0, k, \dots, (m-1)k$。

**证明**：对操作次数归纳。初始时由 $k \mid n$ 显然成立。设某时刻成立，则一次合法操作的 $i, j$ 均为块起点，替换只是把第 $i/k$ 个块的内容整体换成第 $j/k$ 个块的当前内容，块的划分与起点均不变。∎

**引理 2**（块值改变当且仅被选作 $i$）：一个块的内容发生变化，当且仅当某次操作选它作为 $i$。

**证明**：一次操作只写入区间 $[i, i+k)$，由引理 1 该区间恰为一个完整块，其余块只读不写。故从未被选作 $i$ 的块内容恒为初始值。∎

**引理 3**（候选只需现有块）：存在最优方案，其目标周期 $s^*$ 是某个初始块。

**证明**：对固定目标 $s$，所需操作数不少于 $m - \mathrm{cnt}_0[s]$（见定理下界部分），其中 $\mathrm{cnt}_0$ 为初始计数。取 $\mathrm{cnt}_0$ 最大的初始块 $s^*$，则 $\mathrm{cnt}_0[s^*] \ge 1$（$m \ge 1$），代价至多 $m - 1$；而任何非初始块的串 $s$ 有 $\mathrm{cnt}_0[s] = 0$、代价 $m$。故 $s^*$ 不劣于一切非初始块。∎

**定理**：使 `word` 成为 K 周期串的最少操作数为 $m - \max_t \mathrm{cnt}_0[t]$。

**证明**：

- **下界**：设某方案共 $T$ 次操作，终态周期为 $s$。终态每个块都等于 $s$；每个初始 $\ne s$ 的块若从未被选作 $i$，由引理 2 其内容恒为初始值 $\ne s$，与终态矛盾，故它至少被选作 $i$ 一次。又因一次操作的 $i$ 唯一，不同块所需的操作互不相同，故
  $$T \;\ge\; \#\{\text{初始} \ne s \text{ 的块}\} \;=\; m - \mathrm{cnt}_0[s] \;\ge\; m - \max_t \mathrm{cnt}_0[t]$$
- **上界（构造）**：取 $s^*$ 为最大频率块、$p$ 为其第一个出现位置。对每个内容 $\ne s^*$ 的块执行一次 $(i = \text{块起点},\ j = p)$。$p$ 从不被选作 $i$，由引理 2 其内容恒为 $s^*$，故每次抄到的都是 $s^*$；所有 $i, j$ 均为 $k$ 的倍数，合法。共 $m - \mathrm{cnt}_0[s^*] = m - \max_t \mathrm{cnt}_0[t]$ 次操作后每个块都为 $s^*$。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。$m = n/k$ 个块，每块切片 $O(k)$、哈希插入需读完整键 $O(k)$，合计 $O(mk) = O(n)$；顺手维护 `best` 不增加量级。
- **空间复杂度**：$O(n)$。哈希表至多存 $m$ 个互异的块，键的字符总量 $\le n$。
- **为什么不可能更优**：输出前至少要把每个字符读一遍，$\Omega(n)$ 是天然的读入下界，哈希计数一步到位。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumOperationsToMakeKPeriodic(string word, int k) {
        int n = word.size(), m = n / k, best = 0;
        unordered_map<string, int> cnt;
        for (int i = 0; i < n; i += k) {
            best = max(best, ++cnt[word.substr(i, k)]);
        }
        return m - best;
    }
};
```

### Python

```python
from collections import Counter

class Solution:
    def minimumOperationsToMakeKPeriodic(self, word: str, k: int) -> int:
        m = len(word) // k
        cnt = Counter(word[i:i + k] for i in range(0, len(word), k))
        return m - max(cnt.values())
```

> 💡 `++cnt[...]` 返回自增后的值，配合 `max` 把「计数 + 求最大」合并成一趟循环；$k = n$（单块）与全部块相同这两种零答案情形公式天然覆盖，**无需特判**。

## 8. 边界情况与易错点

1. **$k = n$（单块）**：$m = 1$、`best = 1`，答案 0；**全部块相同**：`best = m`，答案 0。两者都不要特判，公式天然覆盖，画蛇添足反而易错。
2. **并列最大频率**：留哪个都行，答案只看 $\max \mathrm{cnt}$ 的**值**，与保留谁无关。
3. **$j$ 也必须是 $k$ 的倍数**：示例 2 的 $j = 2$ 指向块 1（`word[2..3]`），不是「任取一个位置」。构造操作序列时若 $j$ 没对齐块边界，方案非法。
4. **Python 切片写法**：`word[i:i+k]` 不能「优化」成 `word[i::k]`——后者是「从 $i$ 起每隔 $k$ 取一个字符」，语义完全不同，是最容易手滑的点。
5. **答案用 $m$ 不是 $n$**：`return n - best` 是典型笔误，正确为 `m - best`。
6. **别为「源块被覆盖」担心**：固定母版的第一个出现位置、全程不把它选作 $i$ 即可，操作顺序无关紧要；反之，官方序列那种「抄已改写的块」也合法——只要源块**当前**内容是 $s^*$。
7. **别多乘 $\log$**：排序块再扫频也能做，但多一个排序因子；纯哈希计数是最优工具，赛场上别绕远路。
