# LeetCode 同位字符串连接的最小长度 题解

## 1. 题目概述

- **标题 / 题号**：同位字符串连接的最小长度（#3138，medium）
- **链接**：https://leetcode.cn/problems/minimum-length-of-anagram-concatenation/
- **来源**：LeetCode 第 396 场周赛 Q3
- **难度**：中等
- **标签**：哈希表，字符串，计数

**题意**：给定字符串 `s`，已知它由某个字符串 $t$ 与**若干** $t$ 的**同位字符串**（anagram，字母重排）首尾拼接而成。求 $t$ 的**最小**可能长度。

**约束**：

- $1 \le n = \mathrm{s.length} \le 10^5$
- `s` 只包含小写英文字母

> 💡 读题关键信号：**重排不改变长度、也不改变字母多重集**。于是「$t$ 与若干 $t$ 的同位字符串连接」翻译成结构语言就是：**$s$ 被切成 $k$ 个等长的块，每块的 26 维计数向量全等**，要求的是最小块长。与同场 Q2 对照：那边块必须**完全相同**（哈希开票），这边放松为**同多重集**（计数向量）——条件一放松，工具跟着换，但「等长分块」的骨架不变。

## 2. 示例

**示例 1**

```text
输入：s = "abba"
输出：2
解释：t = "ba"，s = "ab" + "ba"，两块互为重排。
```

**示例 2**

```text
输入：s = "cdef"
输出：4
解释：t = "cdef"。t 可以等于 s 本身（单块天然合法）。
```

**示例 3**

```text
输入：s = "abcbcacabbaccba"
输出：3
解释：t = "abc"，五块 abc | bca | cab | bac | cba 计数全等。
```

**补充示例（陷阱）**

```text
输入：s = "aabb"
输出：4
解释：总计数 {a:2, b:2} 与 "abba" 完全相同，但切成 2 块得 "aa" | "bb"，
      计数不等——答案只能是 4。整除筛选骗不了它（见 §3.4）。
```

## 3. 解题思路

### 3.1 暴力思路：枚举块长，逐块数字母

先把判定条件写清楚：块长 $L$ 合法 ⟺ $L \mid n$ 且 $n/L$ 个块的计数向量全等。暴力就是**从小到大枚举每个 $L$**：

```python
def brute(s):
    n = len(s)
    for L in range(1, n + 1):
        if n % L:
            continue
        blocks = [s[i:i + L] for i in range(0, n, L)]
        base = Counter(blocks[0])
        if all(Counter(b) == base for b in blocks[1:]):
            return L
```

- 正确性没问题，但几乎每个 $L$ 都要扫过至少一块才能判死，单个 $L$ 校验 $O(n)$，总计 $O(n^2)$：$n = 10^5$ 时约 $10^{10}$ 次字符操作，**必超时**；
- 暴力的价值是把「合法」翻译成了两句话：**等长 + 计数向量全等**。剩下的事是让候选死得更快——能不碰字符串就不碰。

### 3.2 核心观察：块数视角——最小 L ⟺ 最大 k，候选全藏在 gcd 里

![核心观察：每块计数全等，总计数被 k 均分，块数 k 只能取 g 的约数](images/anagram_concat_blocks_concept.svg)

**观察一（块长必整除 $n$）**：重排不改变长度，$k$ 块各长 $L$，故 $n = kL$。候选从 $[1, n]$ 锐减到 $n$ 的约数（$n \le 10^5$ 时至多 $\tau(n) \le 128$ 个，最毒的 $n = 83\,160$ 也才 128 个），复杂度立刻降到 $O(n \cdot \tau(n))$，**已经能过**——这是本题的及格线。

**观察二（anagram ⟺ 计数向量相同）**：互为重排 ⟺ 26 维计数向量相同（242 的经典等价）。块内顺序完全无关——这是「同位字符串」给的最大善意。

**观察三（块数 $k$ 必整除 $g = \gcd_c \mathrm{cnt}[c]$）**：每块计数向量相同，则每个字符的总数被 $k$ **均分**：

$$k \cdot \mathrm{need}[c] = \mathrm{cnt}[c] \quad\Longrightarrow\quad k \mid \mathrm{cnt}[c]\ \ \forall c \quad\Longrightarrow\quad k \mid g$$

而 $g$ 整除每个计数，自然整除它们的和 $n$——**$g \mid n$ 恒成立**，$g$ 的约数自动都是 $n$ 的约数。于是合法块数全部藏在 $g$ 的约数里，且 $g$ 往往比 $n$ 小得多：`"cdef"` 的 $g = 1$，候选只剩 $k = 1$ 一个，一次校验都不用做。

**对偶视角**：$L = n/k$ 是「合法块长」与「合法块数」之间的一一对应（引理 1），于是

$$\boxed{\min |t| = \frac{n}{k_{\max}}, \qquad k_{\max} = \max\{\, k : k \mid g \ \text{且}\ k\ \text{块计数全等} \,\}}$$

**把「最小化 $L$」换成「最大化 $k$」**：降序枚举 $g$ 的约数，**首个通过校验的 $k$ 即答案**。

> ⚠️ 观察三只是**必要条件**：$k \mid g$ 通过筛选后仍须逐块校验——`"aabb"` 与 `"abba"` 计数全同、$g$ 全同，答案却一新一旧（§3.4）。整除筛得掉「数量不够分」的候选，筛不掉「数量够分但边界切错」的候选。

### 3.3 算法流程

![算法流程：降序枚举 g 的约数，逐块计数校验](images/anagram_concat_check_flow.svg)

一遍扫描统计总计数 $\mathrm{cnt}$，求 $g = \gcd_c \mathrm{cnt}[c]$；降序枚举 $g$ 的约数 $k$：令 $L = n/k$、$\mathrm{need} = \mathrm{cnt}/k$（整除性已由 $k \mid g$ 保证，**无需再做预检**），逐块数一遍与 $\mathrm{need}$ 比较，首个全部通过的 $k$ 给出答案 $n/k$。$k = 1$（整串一块）永远合法，循环必然终止。

### 3.4 示例演算：整除不充分——同计数，不同答案

![示例演算：aabb 与 abba 计数全同，答案却不同](images/anagram_concat_counterexample.svg)

**例 3 快通道**（`s = "abcbcacabbaccba"`）：$\mathrm{cnt} = \{a{:}5, b{:}5, c{:}5\}$，$g = 5$（且 $5 \mid 15$），候选降序 $\{5, 1\}$。$k = 5$：$L = 3$，$\mathrm{need} = \{a{:}1, b{:}1, c{:}1\}$，五块 `abc | bca | cab | bac | cba` 计数全等 ✓ → **答案 3**，一次校验命中。

**例 1 与陷阱对照**：`"abba"` 与 `"aabb"` 的总计数都是 $\{a{:}2, b{:}2\}$，$g = 2$，候选都是 $\{2, 1\}$。前者 $k = 2$：`ab | ba` 计数全等 ✓ → 答案 2；后者 $k = 2$：`aa | bb` 计数不等 ✗，退到 $k = 1$ → 答案 4。**数量上分得匀不匀，与边界上切得对不对，是两回事**——后者只能靠逐块校验把关。

**例 2**（`"cdef"`）：四种字母各 1 个，$g = 1$，唯一候选 $k = 1$ → 答案 4，$t$ 只能是 $s$ 自己。

## 4. 算法细节

1. **求 $g$**：`reduce(gcd, cnt.values())`（Python）或对 26 维数组循环 `g = gcd(g, cnt[c])`；$\gcd(0, x) = x$，缺席字符的 0 计数不干扰。$g \mid n$ 自动成立（引理 2），无需再与 $n$ 取 gcd。
2. **约数枚举**：试除到 $\sqrt{g}$，成对收 $i$ 与 $g/i$，$O(\sqrt g)$；**降序排序**——枚举对象是块数 $k$，块数从大到小对应块长从小到大。
3. **$\mathrm{need}$ 免预检**：$k \mid g$ 已保证 $\mathrm{cnt}[c]/k$ 为整数；且出现过的字符 $\mathrm{cnt}[c] \ge k \Rightarrow \mathrm{need}[c] \ge 1$，**没有零值键**，字典比较语义干净。
4. **逐块校验 + 早退**：`all(Counter(s[i:i+L]) == need for i in range(0, n, L))` 传生成器，首个坏块即停；C++ 里 `cur != need` 对 `array<int, 26>` 逐位比较，首坏块置 `ok = false` 跳出。
5. **兜底**：$k = 1$ 是 $g$ 的约数（$g \ge 1$），整串一块天然合法，循环最迟在 $k = 1$ 返回；末尾 `return n` 只是形式保险。

## 5. 正确性证明

**引理 1（块长整除）**：若长度 $L$ 的 $t$ 合法，则 $L \mid n$。

**证明**：$s$ 由 $k$ 段长均为 $L$ 的块拼成，故 $n = kL$。∎

**引理 2（计数均分）**：若块数 $k$ 合法，则对每个字符 $c$，$\mathrm{cnt}[c] = k \cdot \mathrm{need}[c]$（$\mathrm{need}$ 为单块计数向量）；从而 $k \mid \mathrm{cnt}[c]$ 对一切 $c$ 成立，$k \mid g$；又 $g \mid \sum_c \mathrm{cnt}[c] = n$。

**证明**：$k$ 块互为重排 ⟺ 计数向量全等，记共同向量为 $\mathrm{need}$；各块互不重叠且覆盖全串，按字符逐个累加即得 $\mathrm{cnt}[c] = k \cdot \mathrm{need}[c]$。$g$ 整除每个 $\mathrm{cnt}[c]$，故整除其和 $n$。∎

**引理 3（合并封闭）**：若 $k$ 合法且 $k' \mid k$，则 $k'$ 合法。

**证明**：把 $k$ 个块按原顺序每 $k/k'$ 个合并为一大块，共得 $k'$ 个长 $kL/k'$ 的大块；每个大块的计数向量都是 $\mathrm{need}$ 的 $k/k'$ 倍，故 $k'$ 块计数全等，$k'$ 合法。∎

**定理**：算法返回 $t$ 的最小可能长度。

**证明**：

1. **对应关系**：由引理 1，合法 $t$ 长度与合法块数经 $L = n/k$ 一一对应，故 $\min|t| = n / k_{\max}$；
2. **候选完备**：一切合法 $k$ 都整除 $g$（引理 2），算法枚举 $g$ 的全部约数，$k_{\max}$ 必在候选中；$k = 1$ 恒合法（单块自相等）且 $1 \mid g$，候选集非空；
3. **判定等价**：「$k$ 块计数向量全等」⟺「$s$ 是 $k$ 个互为同位字符串的等长块的连接」——每块都是同一多重集，任取一块作 $t$，其余块皆是 $t$ 的重排（计数向量相等在同位关系下自反、对称、传递）；
4. 降序枚举下**首个通过判定的 $k$ 即 $k_{\max}$**，返回值 $n/k_{\max}$ 即最小长度。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(n \cdot \tau(g) + 26 \cdot \sigma(g) + \sqrt{g}\big)$。预处理 $O(n + 26)$；候选仅 $g$ 的约数，$\tau(g) \le \tau(n) \le 128$（$n \le 10^5$）；每个候选 $k$ 的校验至多 $O(n + 26k)$（数完全部块 $O(n)$，逐块 26 维比较共 $26k$）。由 $g \mid n$ 得 $\sigma(g) \le \sigma(n) < 4.2n$，最坏约 $2 \times 10^7$ 次基本操作，轻松通过；早退让坏候选死在第一个坏块，实际远快于上界。
- **空间复杂度**：$O(26)$。总计数、目标向量、当前块向量三套 26 维数组（Python 为 `Counter`，至多 26 键）。
- **与及格线的差距**：只靠观察一（升序枚举 $n$ 的约数 + 整除预检，即每日题解的主解法）已是 $O(n \cdot \tau(n))$ 可过；gcd 视角的增益在**候选更少**（$g$ 的约数常远少于 $n$ 的约数）与**免预检**，量级不变——属于「同样能过、更优雅」的打磨。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minAnagramLength(string s) {
        int n = s.size();
        array<int, 26> cnt{};
        for (char c : s) cnt[c - 'a']++;

        int g = 0;
        for (int v : cnt) g = gcd(g, v);        // g 自动整除 n（引理 2）

        vector<int> ks;                          // g 的约数
        for (int i = 1; i * i <= g; ++i)
            if (g % i == 0) {
                ks.push_back(i);
                if (i * i != g) ks.push_back(g / i);
            }
        sort(ks.begin(), ks.end(), greater{});   // 块数从大到小 → L 从小到大

        for (int k : ks) {
            int L = n / k;
            array<int, 26> need{};
            for (int c = 0; c < 26; ++c) need[c] = cnt[c] / k;
            bool ok = true;
            for (int i = 0; i < n && ok; i += L) {
                array<int, 26> cur{};
                for (int j = i; j < i + L; ++j) cur[s[j] - 'a']++;
                if (cur != need) ok = false;     // 首个坏块即淘汰
            }
            if (ok) return L;                    // 首个通过 = 最大 k = 最小 L
        }
        return n;                                // k = 1 兜底，不可达
    }
};
```

### Python

```python
from math import gcd, isqrt
from functools import reduce
from collections import Counter

class Solution:
    def minAnagramLength(self, s: str) -> int:
        n = len(s)
        cnt = Counter(s)
        g = reduce(gcd, cnt.values())            # g 必整除 n

        ks = []                                  # g 的约数
        for i in range(1, isqrt(g) + 1):
            if g % i == 0:
                ks.append(i)
                if i * i != g:
                    ks.append(g // i)
        ks.sort(reverse=True)                    # 块数从大到小 → L 从小到大

        for k in ks:
            L = n // k
            need = {c: v // k for c, v in cnt.items()}
            if all(Counter(s[i:i + L]) == need   # 逐块校验，生成器天然早退
                   for i in range(0, n, L)):
                return L                         # 首个通过 = 最大 k = 最小 L
        return n                                 # k = 1 兜底，不可达
```

> 💡 两个实现都**没有整除预检分支**——$k \mid g$ 在候选生成时就已保证，$\mathrm{need}$ 直接整除得出；也没有 $n \bmod L$ 检查——$k \mid g \mid n$ 传递保证 $L = n/k$ 为整数。把必要条件前置进候选集，主循环只剩「校验」一件事。

## 8. 边界情况与易错点

1. **$n = 1$ / 全同字符**：$g = n$，$k = n$（$L = 1$）第一轮命中，无需特判。
2. **$g = 1$**（如 `"cdef"`、`"ab"`）：候选只剩 $k = 1$，答案 $n$——$t$ 只能是 $s$ 自己。
3. **整除 ≠ 充分**：`"aabb"` 通过 $k = 2$ 的整除筛选但块计数不等。**通过筛选的每个 $k$ 都必须逐块校验**，这是本题最容易翻车的心理关。
4. **降序枚举的是 $k$ 不是 $L$**：`sort(reverse=True)` 排的是约数列表（块数）；$k$ 降 ⟺ $L$ 升，最终返回的是 $L$，别把两者搅在一起。
5. **别画蛇添足再取 $\gcd(n, g)$**：$g \mid n$ 恒成立（引理 2），多写一步虽不出错，但暴露没想透。
6. **Python 切片语义**：块起点用 `range(0, n, L)` 配 `s[i:i+L]`；`s[i::L]` 是「从 $i$ 起每隔 $L$ 取一个字符」，同场 Q2 已踩过的坑，这里原样埋着。
7. **C++ 细节**：`i * i <= g` 在 $g \le 10^5$ 时 `int` 安全（$i \le 317$）；`array<int, 26>` 的 `!=` 即逐元素比较，正是「计数向量逐位相等」的语义，缺席字符计数为 0 天然对齐。
8. **`need` 无零值键**：出现过的字符 $\mathrm{cnt}[c] \ge k$（因 $k \mid \mathrm{cnt}[c]$ 且 $\mathrm{cnt}[c] \ge 1$），故 `Counter(block) == need` 的两侧键集可比，比较语义安全。
