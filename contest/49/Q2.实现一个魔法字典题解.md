# LeetCode 实现一个魔法字典 题解

## 1. 题目概述

- **标题 / 题号**：实现一个魔法字典（#676，medium）
- **链接**：https://leetcode.cn/problems/implement-magic-dictionary/
- **来源**：LeetCode 第 49 场周赛 Q2
- **难度**：中等
- **标签**：深度优先搜索、设计、字典树、哈希表、字符串

**题意**：用一组**互不相同**的单词建立一个「魔法字典」。对每次查询的 `searchWord`，判断能否把其中**恰好一个**字母换成**另一个**字母，使新单词恰好是字典中的某个单词；能则返回 `true`，否则返回 `false`。

两个限定词是本题的全部难点：

- **恰好一个**：一个字母都不改（查询词本身就在字典里）**不算**；
- **另一个**：替换后的字母必须与原字母不同，于是「新词与查询词**恰好一个位置不同**」成了唯一判据。

**约束**：

- $1 \le \text{dictionary.length} \le 100$，$1 \le |\text{dictionary}[i]| \le 100$；
- 字典中的单词只含小写英文字母，且**互不相同**；
- $1 \le |\text{searchWord}| \le 100$，`buildDict` 只在 `search` 之前调用一次，`search` 至多被调用 $100$ 次。

## 2. 示例

**示例 1**（官方）

```text
输入
["MagicDictionary", "buildDict", "search", "search", "search", "search"]
[[], [["hello", "leetcode"]], ["hello"], ["hhllo"], ["hell"], ["leetcoded"]]
输出
[null, null, false, true, false, false]
解释
search("hello")     // false：与字典词 "hello" 完全相同，一个字母都没改
search("hhllo")     // true ：第 2 位 h 改成 e，得到 "hello"
search("hell")      // false：长度 4，字典里没有长度 4 的词
search("leetcoded") // false：长度 9，同样没有同长词
```

**示例 2**（查询词本身在字典中，仍可能为 true）

```text
输入：dictionary = ["hello", "hellp"]
search("hello") → true    把最后的 o 改成 p，得到 "hellp"
search("hellp") → true    把最后的 p 改成 o，得到 "hello"
search("qellq") → false   与两个词都至少差 2 位
```

**示例 3**（单字符字典，最容易写反的边界）

```text
输入：dictionary = ["a", "b"]
search("c") → true    把 c 改成 a（或 b）
search("a") → true    把 a 改成 b —— 不能返回自己
```

## 3. 解题思路

### 3.1 暴力思路：逐词比对失配位

对每次查询，遍历字典里的所有单词：

1. 长度不同直接跳过（换一个字母不改变长度）；
2. 长度相同则数一数两词**失配的位置数**，恰好为 $1$ 就返回 `true`。

单次查询 $O(NL)$，本题 $N, L \le 100$，即 $10^4$ 次字符比较；$100$ 次查询总共 $10^6$，**完全能过**。但它的开销随字典规模线性增长：若字典扩到 $10^4$ 个词、查询 $10^4$ 次，就是 $10^{10}$。更要紧的是，它把「所有单词的公共前缀」反复重算了 $N$ 遍，而「前缀对齐」恰恰是这道题真正的结构。

### 3.2 核心观察：恰好一位不同 = 一次「改道」

![一位不同等价于 Trie 上一次改道](images/wc49_q2_one_detour_insight.svg)

设查询词为 $w$、字典词为 $d$，$|w| = L$。「$w$ 与 $d$ 恰好一位不同」等价于：存在唯一的分界点 $p \in [0, L)$，使得

$$w[0..p) = d[0..p), \qquad w[p] \ne d[p], \qquad w[p+1..L) = d[p+1..L)$$

也就是「**前缀完全一致 + 中间一位不同 + 后缀完全一致**」。两条推论直接落地：

- **长度必须相等**：否则两词根本无法逐位对齐，$p$ 不存在；
- **匹配被 $p$ 切成两段**：改道前后都必须逐位相同。这正好是 Trie 擅长的事——把「前缀对齐」压缩成一次 $O(1)$ 的子节点查找。

于是 `search(w)` 变成：从根出发沿 $w$ 的字符走，沿途**允许且仅允许一次**走到「非当前字符」的子节点；到达 $w$ 末尾时，若改道已经发生、且当前节点是词尾，就是 `true`。一次查询只与树高（即 $L$）有关，与字典词数 $N$ **无关**。

### 3.3 算法流程

![算法流程](images/wc49_q2_algorithm_flow.svg)

**建树 `buildDict`**：把每个单词逐字符插入 Trie，节点保存 26 个子指针与词尾标记 `end`；总节点数不超过 $\sum_i |d_i| \le 10^4$。

**查询 `search(w)`**：递归 `dfs(node, pos, changed)`，`changed` 表示「是否已经改过一位」。

1. 若 `pos == len(w)`：返回 `changed && node.end` —— 必须改过，且必须停在某个单词的结尾；
2. 分支一：若 `node.next[w[pos]]` 存在，`dfs(child, pos+1, changed)` 为真则返回 `true`；
3. 分支二：若 `changed == false`，枚举所有满足 `c ≠ w[pos]` 且 `node.next[c]` 存在的子节点，`dfs(child, pos+1, true)` 为真则返回 `true`；
4. 两条分支都失败，返回 `false`。

第 3 步的 `c ≠ w[pos]` 与第 1 步的 `changed &&` 是同一件事的两端：前者保证「要改就改成不同字母」，后者保证「必须真的改过一次」。两个条件都必须显式写出来，缺一个就会在示例 1 或示例 2 上翻车。

### 3.4 示例演算

![示例演算](images/wc49_q2_example_walkthrough.svg)

以 `dictionary = ["hello", "leetcode"]` 为例，四次查询在 Trie 上的实际走法：

| 查询 | 长度 | Trie 上实际路径 | 改道 | 结果 |
|---|---|---|---|---|
| `hhllo` | 5 | `h` → **改道 e** → `l` → `l` → `o` | `pos 1: h → e` | **true** |
| `hello` | 5 | `h → e → l → l → o`，走到词尾 | 未改道 | false |
| `hell` | 4 | `h → e → l → l`，停在非词尾节点 | — | false |
| `leetcoded` | 9 | `l→e→e→t→c→o→d→e` 之后无子节点 | — | false |

`hhllo` 只花一次改道就命中；`hello` 虽然完整走到了词尾，但 `changed` 仍是 `false`，被第 1 步挡住；后两次则连长度这一层都过不去。

## 4. 算法细节

1. **节点结构**：C++ 用 `struct Node { Node* next[26]; bool end; }`；Python 用嵌套 `dict`，以键 `'#'` 标记词尾。遍历子节点时必须跳过 `'#'`，否则会把词尾标记当成一个可以「改道」进去的字母。
2. **词尾判定只在末尾做**：`pos == len(w)` 时才看 `end`，并且要与 `changed` 取合取。漏掉 `changed` 会把 `hello` 判成 `true`；漏掉 `end` 会把某个单词的前缀误当成单词。
3. **排除「改成自己」**：分支二必须显式写 `c != w[pos]`。若改成「枚举所有存在的子节点并把 `changed` 置真」，走 `w[pos]` 这条边也会置真，等于把「零次修改」偷渡成「一次修改」——示例 1 的 `search("hello")` 立刻错判。
4. **改道后不再分支**：`changed == true` 之后只保留分支一，后续字符必须逐位相等。这从结构上保证「恰好一次」，而不仅是「至少一次」。
5. **长度无需特判**：Trie 天然处理长度差异——查询词更短会停在 `end` 为假的中间节点，更长则在某一步没有子节点可走，两种情况都返回 `false`。
6. **先同后异、尽早短路**：分支一优先且命中即返回，既贴合「多数查询前缀基本对齐」的分布，也避免无谓枚举 25 个兄弟节点。
7. **递归深度**：至多 $L \le 100$ 层，栈安全；C++ 用 `const string&` 传参，避免每层复制字符串。

> 💡 另一种等价写法：把每个单词的每一位替换成通配符，得到 $L$ 个模式串，存成 `pattern -> 该位置上出现过的字母集合`。查询时枚举 $L$ 个模式，只要集合中存在与 $w[p]$ 不同的字母即为 `true`。预处理 $O(\sum_i |d_i|^2)$、单次查询 $O(L)$ 次哈希，是 Trie 之外的另一条标准路线。

## 5. 正确性证明

**引理 1（DFS 语义）**：设 `node` 是 Trie 中深度为 `pos` 的节点、对应前缀串 $q$。则 `dfs(node, pos, changed)` 返回 `true`，当且仅当存在字典词 $d$，满足 $|d| = L$、$q = w[0..pos)$，且：`changed == false` 时 $w[0..pos) = d[0..pos)$ 而 $d[pos..L)$ 与 $w[pos..L)$ 恰好一位不同；`changed == true` 时 $w$ 与 $d$ 在 $[0, pos)$ 内恰好一位不同而 $d[pos..L) = w[pos..L)$。

**证明**：对 $L - pos$ 归纳。

*基础（$pos = L$）*：`changed == true` 时返回 `node.end`，即存在字典词 $d = q$，其长度 $L = pos$，由前提 $w$ 与 $d$ 在 $[0, L)$ 内恰好一位不同，后缀为空，条件成立；`changed == false` 时返回 `false`，而空后缀上不存在任何失配位，「恰好一位不同」必然为假，两侧一致。

*归纳步*：设 $pos < L$，记 $c = w[pos]$。

- `changed == true`：函数只走 $c$ 的子节点，返回值等价于 `dfs(child, pos+1, true)`。由归纳假设，它成立等价于存在 $d$ 使 $d[pos+1..L) = w[pos+1..L)$、$d[pos] = c$，且 $[0, pos)$ 内已有一处不同；合并得 $d[pos..L) = w[pos..L)$ 且 $[0, pos)$ 一处不同。
- `changed == false`：函数尝试了 $d[pos] = c$ 与 $d[pos] = c' \ne c$ 两类子节点。前者由归纳假设要求 $d[pos+1..L)$ 与 $w[pos+1..L)$ 恰好一处不同，拼上全同前缀得 $[0, L)$ 一处不同；后者要求 $d[pos+1..L) = w[pos+1..L)$，加上 $d[pos] = c' \ne c = w[pos]$，同样得 $[0, L)$ 一处不同。反过来，任何使 $[0, L)$ 恰好一处不同的 $d$，按 $d[pos]$ 是否等于 $c$ 必落入这两类之一（互斥且穷尽），故两侧等价。∎

**引理 2（词尾判定）**：当 $pos = L$ 且 `changed == false` 时，`dfs` 必返回 `false`。

**证明**：直接取自引理 1 的基础情形：空后缀上不可能存在失配位。∎

**定理**：`search(w)` 返回 `true` 当且仅当存在字典词 $d$，使 $|d| = |w|$ 且 $d$ 与 $w$ 恰好一位不同。

**证明**：

- **（⇒）** 设 `search(w)` 返回 `true`。初始调用是 `dfs(root, 0, false)`，`root` 对应空前缀。由引理 1 的 `changed == false` 情形，存在字典词 $d$ 使 $d[0..L)$ 与 $w[0..L)$ 恰好一位不同，即 $|d| = L = |w|$。
- **（⇐）** 设这样的 $d$ 存在，唯一不同位置为 $p$。DFS 沿 $d$ 的路径前进：$[0, p)$ 内 $d[i] = w[i]$，走分支一，`changed` 保持 `false`；第 $p$ 位 $d[p] \ne w[p]$，走分支二，`changed` 置为 `true`；$(p, L)$ 内又逐位相等，继续走分支一。最终到达深度 $L$ 的节点，它正是 $d$ 的词尾，且 `changed == true`，故返回 `true`。∎

**推论**：退化情形被正确排除——若 $w$ 本身在字典中、但不存在与它恰好一位不同的字典词，则 `search(w) = false`（示例 1 的 `hello`）。

## 6. 复杂度分析

- **`buildDict` 时间**：$O(\sum_i |d_i|) \le 10^4$，每个字符一次子节点转移。
- **`buildDict` 空间**：$O(\sum_i |d_i|)$ 个节点，每节点 26 个指针（Python 用哈希表只存实际存在的孩子，更省），上界 $10^4$ 个节点。
- **`search` 时间**：与字典词数 $N$ 无关，只与词长 $L$ 有关。最坏情形是每个位置都展开至多 25 条「改道」分支、每条改道分支再走完剩余 $L - pos$ 层，约 $O(25L^2/2)$ 次节点访问；由于改道后一旦失配立即回溯，实际远小于该上界，常见情形接近 $O(L)$。$L \le 100$ 时上界约 $1.2 \times 10^5$，$100$ 次查询仍远低于 $10^7$。
- **总空间**：$O(\sum_i |d_i| + L)$，其中 $L$ 为递归栈深度。

## 7. 参考代码

### C++

```cpp
class MagicDictionary {
    struct Node {
        Node* next[26];
        bool end;
        Node() : end(false) { fill(next, next + 26, nullptr); }
    };
    Node* root;

    bool dfs(Node* node, const string& w, int pos, bool changed) {
        if (!node) return false;
        if (pos == (int)w.size()) return changed && node->end;   // 必须改过且停在词尾
        int i = w[pos] - 'a';
        // 分支一：这一位不变
        if (node->next[i] && dfs(node->next[i], w, pos + 1, changed)) return true;
        // 分支二：这一位改成别的字母（只能用掉一次）
        if (!changed) {
            for (int j = 0; j < 26; ++j) {
                if (j == i) continue;                             // 必须换成另一个字母
                if (node->next[j] && dfs(node->next[j], w, pos + 1, true)) return true;
            }
        }
        return false;
    }

public:
    MagicDictionary() { root = new Node(); }

    void buildDict(vector<string> dictionary) {
        for (const string& w : dictionary) {
            Node* cur = root;
            for (char c : w) {
                int i = c - 'a';
                if (!cur->next[i]) cur->next[i] = new Node();
                cur = cur->next[i];
            }
            cur->end = true;
        }
    }

    bool search(string searchWord) { return dfs(root, searchWord, 0, false); }
};
```

### Python

```python
class MagicDictionary:
    def __init__(self):
        self.trie = {}

    def buildDict(self, dictionary: list[str]) -> None:
        for w in dictionary:
            node = self.trie
            for ch in w:
                node = node.setdefault(ch, {})
            node['#'] = True                 # '#' 标记词尾

    def search(self, searchWord: str) -> bool:
        def dfs(node: dict, pos: int, changed: bool) -> bool:
            if pos == len(searchWord):
                return changed and '#' in node
            ch = searchWord[pos]
            # 分支一：这一位不改
            if ch in node and dfs(node[ch], pos + 1, changed):
                return True
            # 分支二：这一位改成另一个字母（只能用掉一次）
            if not changed:
                for c, nxt in node.items():
                    if c != '#' and c != ch and dfs(nxt, pos + 1, True):
                        return True
            return False

        return dfs(self.trie, 0, False)
```

## 8. 边界情况与易错点

1. **查询词本身就在字典中**：不能直接返回 `true`，必须另找一位不同的词（示例 1 的 `hello` 为 `false`，示例 2 的 `hello`/`hellp` 互为一对则为 `true`）。
2. **「改成另一个字母」**：分支二必须排除 `c == w[pos]`，否则零次修改会被当成一次修改，`search("hello")` 立刻错判。
3. **长度必须相等**：`hell`（4）与 `leetcoded`（9）在长度为 $\{5, 8\}$ 的字典里都应立刻为 `false`；Trie 会在词尾或空子节点处自然失败，不必显式比较长度。
4. **单字符字典**：`dictionary = ["a"]` 时 `search("a")` 为 `false`（唯一候选是它自己）、`search("b")` 为 `true`；$L = 1$ 时最容易把两个条件写反。
5. **字典词互为前缀**：如 `["a", "ab"]`，`search("b")` 应为 `true`（`b`→`a`）；词尾判定必须看是否已到 `len(w)`，不能「遇到 `end` 就停」。
6. **Python 的 `'#'` 词尾键**：枚举子节点时若把 `'#'` 当作字母用于改道，会走进一条并非单词的伪路径，务必过滤。
7. **改道后仍可能失败**：把唯一一次改道花在前缀上（如把 `h` 改成 `x`）之后，后面任何一位对不齐都必须回溯，不能「改过就算成功」。

**延伸思考**：

1. **通配符哈希 vs Trie**：前者预处理 $O(\sum |d_i|^2)$ 空间、查询 $O(L)$ 且常数稳定；后者空间只有 $O(\sum |d_i|)$，查询最坏 $O(25L^2)$ 但有前缀剪枝。若查询次数远多于建树次数、且内存宽裕，通配符哈希更稳；若字典很大而查询零散，Trie 更省。
2. **允许修改 $k$ 次**：把 `changed` 换成剩余次数 `cnt`，分支二在 `cnt > 0` 时展开，复杂度约 $O(25^k L)$；$k$ 稍大就该换思路——或用位掩码通配（枚举 $\binom{L}{k}$ 个失配位置集合），或用「Trie 节点 × 剩余次数」的 DP。
3. **要求返回具体单词或字典序最小的匹配**：DFS 需要记录路径并按字母序枚举子节点，短路性质随之消失，代价从「首个命中即返回」变成「枚举全部候选」。
