# LeetCode 最长递增子序列的个数 题解

## 1. 题目概述

- **标题 / 题号**：最长递增子序列的个数（#673，medium）
- **链接**：https://leetcode.cn/problems/number-of-longest-increasing-subsequence/
- **来源**：LeetCode 第 49 场周赛 Q4
- **难度**：中等
- **标签**：树状数组，线段树，数组，动态规划，最长上升子序列

**题意**：给定未排序的整数数组 $nums$，统计**严格递增**子序列中，长度等于最长递增子序列（LIS）长度的那些子序列共有多少条。下标序列不同即视为不同子序列（即使取值完全相同），同一组下标只算一次。

**约束**：

- $1 \le n \le 2000$，其中 $n$ 为数组长度
- $-10^6 \le nums[i] \le 10^6$
- 答案保证在 32 位有符号整数范围内

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,5,4,7]
输出：2
解释：LIS 长度为 4，共有两条：
      [1,3,5,7]（下标 0,1,2,4）与 [1,3,4,7]（下标 0,1,3,4）。
```

**示例 2**

```text
输入：nums = [2,2,2,2,2]
输出：5
解释：数组严格递增的最长子序列长度为 1，任何单个元素都满足；
      按下标区分共有 5 条，因此答案为 5。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举全部 $2^n$ 个子序列，逐个判断是否严格递增并记录最大长度与条数，复杂度 $O(n \cdot 2^n)$。$n \le 2000$ 时完全不可行。

退一步：先按经典 DP 求出 LIS 长度 $L$，再数「长度为 $L$ 的递增子序列」——但数数本身仍需枚举，没有变简单。问题的本质是：**长度好求、条数难数**，必须在求长度的同一遍里把条数一并算出来。

### 3.2 核心观察：把「长度」和「条数」绑成一个二元组

![计数型 DP：length 与 count 两个状态量](images/wc49_q4_dp_model.svg)

对每个下标 $i$，维护两个量：

- $length[i]$：以 $nums[i]$ **结尾**的最长严格递增子序列长度；
- $cnt[i]$：长度恰为 $length[i]$、且以 $nums[i]$ 结尾的子序列**条数**。

$length[i]$ 的含义比「前 $i+1$ 个元素的 LIS」更强：它**强制以 $i$ 结尾**。这样任何一条递增子序列都能唯一地落在一个结尾下标上，条数才能按结尾位置无交地切分。

转移的对象是所有满足 $j < i$ 且 $nums[j] < nums[i]$ 的前驱（严格小于是关键，相等元素不能接在后面）。把 $nums[i]$ 接到以 $j$ 结尾的链上，新长度是 $length[j]+1$，与当前的 $length[i]$ 相比只有三种关系：

- **更长**（$length[j]+1 > length[i]$）：之前统计的链都不再是最长的，计数**全部作废**，改为 $cnt[i] = cnt[j]$；
- **等长**（$length[j]+1 = length[i]$）：这是另一条并列的最长链，计数**相加** $cnt[i] \mathrel{+}= cnt[j]$；
- **更短**：接上去也够不到最长，直接忽略。

> 💡 一句话记住合并规则：**「更长的覆盖、等长的累加、更短的忽略」**。这是所有「计数型 DP」题（数方案、数路径、数序列）的通用模板。

为什么累加不会重复计数？每条以 $i$ 结尾的最长链，倒数第二个元素的位置 $j$ 是唯一的；不同的 $j$ 把方案集合切成互不相交的若干块，块内由 $cnt[j]$ 计数，块间按 $j$ 区分。这一点会在§5 用双射严格证明。

### 3.3 算法流程 / 状态转移

![算法流程：双重循环与三路分支](images/wc49_q4_algorithm_flow.svg)

外层枚举结尾 $i$，内层枚举前驱 $j$，三路分支如上图；每个 $i$ 内层结束后立刻与全局最优结算，伪代码如下：

```text
for i in [0, n):
    length[i] = 1, cnt[i] = 1
    for j in [0, i):
        if nums[j] < nums[i]:
            if length[j] + 1 > length[i]:   length[i] = length[j] + 1; cnt[i] = cnt[j]
            elif length[j] + 1 == length[i]: cnt[i] += cnt[j]
    if length[i] > bestLen:  bestLen = length[i]; ans = cnt[i]
    elif length[i] == bestLen: ans += cnt[i]
return ans
```

**注意「i 结算」的位置**：必须放在内层 $j$ 循环结束之后。$length[i]$ 在内层里是动态变化的，中途结算会把同一个 $i$ 重复计入答案。

### 3.4 示例演算

![示例演算：数组 1 3 5 4 7 的逐格填表](images/wc49_q4_walkthrough.svg)

对 $nums = [1,3,5,4,7]$ 逐格走查：

| $i$ | $nums[i]$ | 合法前驱 $j$ | $length[i]$ | $cnt[i]$ |
|-----|-----------|--------------|-------------|----------|
| 0 | 1 | 无 | 1 | 1 |
| 1 | 3 | 0（$length=1$） | 2 | 1 |
| 2 | 5 | 0、1（$length$ 均为 2） | 3 | 1 |
| 3 | 4 | 0、1（5 比 4 大，排除） | 3 | 1 |
| 4 | 7 | 2、3（$length$ 均为 3） | 4 | 2 |

到 $i=4$ 时，$j=2$ 让 $length[4]=4$ 并置 $cnt[4]=1$；接着 $j=3$ 给出同样长度，触发「等长累加」，$cnt[4]=2$。全局最长长度 $L=4$，只有 $i=4$ 达到，答案即 $cnt[4]=2$，对应 $[1,3,5,7]$ 与 $[1,3,4,7]$。

这里正好体现了为什么 5 与 4 不会互相累加：$nums[2]=5$ 接不到 4 后面，$nums[3]=4$ 也接不到 5 后面，二者是**平行**的两条支路，只在下标 4 处汇合。

## 4. 算法细节

1. **单遍转移，不要两遍**：先求 $length[i]=\max$ 再回头统计的方案需要额外一遍内层循环；单遍写法靠「覆盖时清零」保证 $cnt[i]$ 始终与当前 $length[i]$ 对齐，省一半常数。
2. **严格递增条件**：判断必须写成 $nums[j] < nums[i]$。写成 $\le$ 会把相等元素接成链，$[2,2,2]$ 会错答成 $6$（正确为 $3$）。
3. **初值语义**：$length[i]=1$、$cnt[i]=1$ 表示「只含 $nums[i]$ 自己的长度 1 子序列，恰好 1 条」。若把 $cnt$ 初始化为 0，则从未被任何前驱更新的位置（严格递减数组、全相等数组）计数会变成 0，答案错误。
4. **结算时机**：$bestLen$ 与 $ans$ 的更新放在 $i$ 的内层循环之后；若放在 $j$ 循环体内，同一个 $i$ 会被累加多次。
5. **计数用 64 位**：题面只保证最终答案在 32 位内，但 $length[i]$ 较小（不是全局最长）的位置，其 $cnt[i]$ 可能超过 `int`；C++ 中 $cnt$ 与 $ans$ 都用 `long long`，返回时再转 `int`。
6. **不建值域桶、不离散化**：$n \le 2000$，$O(n^2)$ 只需约 $2\times10^6$ 次比较，$nums[i]$ 取到 $\pm 10^6$ 也不影响，直接比较数值即可。
7. **下标从 0 或 1 开始均可**：唯一约束是前驱集合为 $\{j < i\}$，与下标基准无关。

## 5. 正确性证明

**引理 1（$length$ 正确）**：对每个 $i$，$length[i]$ 等于以 $nums[i]$ 结尾的最长严格递增子序列长度。

**证明**：对 $i$ 归纳。若以 $i$ 结尾的子序列长度 $\ge 2$，取其倒数第二个元素所在下标 $j$，则 $j<i$ 且 $nums[j]<nums[i]$，去掉末尾后是以 $j$ 结尾的递增子序列，长度不超过 $length[j]$，故整条长度不超过 $length[j]+1$，从而不超过 $1+\max_{j}length[j]$。反之，取使 $length[j]$ 最大的合法 $j$，在其最优链后接上 $nums[i]$，得到长度 $1+\max$ 的合法链。两边夹逼即得转移公式，其中「无合法前驱」时取 $1$。∎

**引理 2（$cnt$ 不重不漏）**：对每个 $i$，$cnt[i]$ 等于以 $nums[i]$ 结尾、长度恰为 $length[i]$ 的递增子序列条数。

**证明**：对 $i$ 归纳，假设所有 $j<i$ 成立。记合法前驱集合 $P_i=\{j<i: nums[j]<nums[i],\ length[j]=length[i]-1\}$。

- 由引理 1，任何合法 $j$ 都有 $length[j]+1 \le length[i]$；等号成立当且仅当 $j \in P_i$。因此转移中触发「等长累加」的恰好是 $P_i$ 中的元素，触发「更长覆盖」的是首次出现的最大者，最终 $cnt[i]$ 等于 $\sum_{j \in P_i} cnt[j]$（无前驱时 $cnt[i]=1$）。
- 建立映射：任取以 $i$ 结尾、长度 $length[i]$ 的链，删去末尾的 $nums[i]$，得到以某个 $j \in P_i$ 结尾、长度 $length[j]$ 的链；反向地，任取 $j\in P_i$ 的一条长度 $length[j]$ 的链，接上 $nums[i]$ 即得合法链。两个方向互逆，构成双射。
- 按 $j$ 划分后各块不交：不同 $j$ 对应的链倒数第二个下标不同，故链本身不同，不会有一条链被数两次。块 $j$ 的大小由归纳假设为 $cnt[j]$。相加即得结论。∎

**引理 3（扫描不变量）**：处理完前 $i+1$ 个位置后，$bestLen=\max_{k\le i}length[k]$，且 $ans=\sum_{k\le i,\ length[k]=bestLen}cnt[k]$。

**证明**：$i=0$ 时 $bestLen=length[0]$、$ans=cnt[0]$，成立。设对 $i-1$ 成立，处理 $i$ 时若 $length[i]>bestLen$，则旧的 $ans$ 全部作废（它统计的是更短长度），置 $ans=cnt[i]$；若相等则并入；若更小则不动。三种情况都与不变量一致。∎

**定理**：算法返回的正是最长递增子序列的条数。

**证明**：由引理 1，$n\ge 1$ 时 $bestLen=\max_i length[i]$ 就是 LIS 长度。每条递增子序列有唯一的结尾下标 $i$，其长度为 $L$ 时必有 $length[i]=L$（引理 1 的上界与可达性），且它属于「以 $i$ 结尾、长度 $length[i]$ 的链」这一集合，大小为 $cnt[i]$（引理 2）。按结尾下标划分互不相交，由引理 3 扫描结束时 $ans$ 恰为这些 $cnt[i]$ 之和，故答案正确。∎

## 6. 复杂度分析

- **时间**：$O(n^2)$。外层 $n$ 次，内层累计 $\frac{n(n-1)}{2}$ 次「比较 + 常数次赋值/加法」，$n=2000$ 时约 $2\times10^6$ 次操作；$i$ 结算为 $O(1)$。无排序、无离散化。
- **空间**：$O(n)$。仅两个长度 $n$ 的数组（$length$、$cnt$）与若干标量，没有二维表、没有桶。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findNumberOfLIS(vector<int>& nums) {
        int n = nums.size();
        vector<int> length(n, 1);          // 以 i 结尾的最长递增子序列长度
        vector<long long> cnt(n, 1);       // 该长度的子序列条数（防中间溢出）
        int bestLen = 0;
        long long ans = 0;

        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < i; ++j) {
                if (nums[j] < nums[i]) {   // 严格递增，不能写成 <=
                    if (length[j] + 1 > length[i]) {        // 更长 → 覆盖
                        length[i] = length[j] + 1;
                        cnt[i] = cnt[j];
                    } else if (length[j] + 1 == length[i]) { // 等长 → 累加
                        cnt[i] += cnt[j];
                    }
                    // 更短 → 忽略
                }
            }
            if (length[i] > bestLen) {      // i 结算：全局最优
                bestLen = length[i];
                ans = cnt[i];
            } else if (length[i] == bestLen) {
                ans += cnt[i];
            }
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def findNumberOfLIS(self, nums: list[int]) -> int:
        n = len(nums)
        length = [1] * n        # 以 i 结尾的最长递增子序列长度
        cnt = [1] * n           # 该长度的子序列条数
        best_len, ans = 0, 0

        for i in range(n):
            for j in range(i):
                if nums[j] < nums[i]:          # 严格递增
                    if length[j] + 1 > length[i]:      # 更长 → 覆盖
                        length[i] = length[j] + 1
                        cnt[i] = cnt[j]
                    elif length[j] + 1 == length[i]:   # 等长 → 累加
                        cnt[i] += cnt[j]
            if length[i] > best_len:           # i 结算
                best_len, ans = length[i], cnt[i]
            elif length[i] == best_len:
                ans += cnt[i]
        return ans
```

## 8. 边界情况与易错点

1. **单元素**：$[1]$ → $1$。循环不动，$bestLen=1$、$ans=1$。
2. **全部相等**：$[2,2,2,2,2]$ → $5$。没有任何严格前驱，每个位置都停在 $length=1$，每个 $cnt=1$，答案为 $n$。这是最容易写成 1 的用例。
3. **严格递减**：$[5,4,3,2,1]$ → $5$，理由同上（每个单元素都是长度 1 的最长子序列）。递减数组的答案不是 1，是 $n$。
4. **严格递增**：$[1,2,3,4,5]$ → $1$。最长链唯一，只有一个位置达到 $bestLen$。
5. **重复值夹在中间**：$[1,2,4,3,5,4,7,2]$ → $3$。条件若写成 $\le$，末尾的 $2$ 会接上前缀的 $2$，整棵计数树都被污染。
6. **覆盖分支漏清空**：「更长」分支必须写成 $cnt[i]=cnt[j]$（重置），若写成 $cnt[i]\mathrel{+}=cnt[j]$（继续累加），旧短链的计数会残留。实测 $[1,3,5,4,7]$ 的 $cnt[4]$ 会被累到 $12$，答案错成 $12$。
7. **中间计数溢出**：$cnt[i]$ 用 `int` 在极端数据下可能溢出；答案本身虽保证 32 位内，中间量不是，故统一用 `long long`。
8. **结算位置错误**：把 $bestLen/ans$ 的更新写进 $j$ 循环，同一个 $i$ 会被统计 $i$ 次，答案偏大。

**延伸思考**：本题 $n \le 2000$ 允许 $O(n^2)$，但标签里的「树状数组 / 线段树」提示了更快的做法。把数值离散化到 $[1,m]$（$m \le n$），用树状数组维护「以某个值结尾的最优二元组 $(len, cnt)$」，其合并算子定义为：$len$ 更大者胜出，$len$ 相等则 $cnt$ 相加。查询时取前缀 $[1, \text{rank}(nums[i])-1]$ 的聚合结果，再把 $(len+1, cnt)$ 更新到 $\text{rank}(nums[i])$ 处，总复杂度降到 $O(n\log n)$，可支持 $n=10^5$。若题目改为「非严格递增」，只需把前缀区间换成 $[1, \text{rank}(nums[i])]$（含相等）即可，其余不变。
