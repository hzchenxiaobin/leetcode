# LeetCode 为高尔夫比赛砍树 题解

## 1. 题目概述

- **标题 / 题号**：为高尔夫比赛砍树（#675，hard）
- **链接**：https://leetcode.cn/problems/cut-off-trees-for-golf-event/
- **来源**：LeetCode 第 49 场周赛 Q3
- **难度**：困难
- **标签**：广度优先搜索，数组，矩阵，堆（优先队列）

**题意**：给定 $m \times n$ 的矩阵 `forest`：`0` 是障碍（不可触碰），`1` 是空地，大于 `1` 的值表示一棵高为该值的树。你从 $(0,0)$ 出发，每步可上下左右移动一格；站在有树的格子上时可以（也可以不）把树砍倒，砍完后该格变成 `1`。**必须严格按树高从小到大**砍完全部树，求最小总步数；砍不完返回 `-1`。

**约束**：

- $1 \le m, n \le 50$
- $0 \le \text{forest}[i][j] \le 10^9$
- 没有两棵树高度相同；至少有一棵树

> 💡 关键语义：树格（`>1`）**始终可以通行**，砍树只是把值改成 `1`，并不改变可达性——这一点决定了整张图是**静态**的。

## 2. 示例

**示例 1**

```text
输入：forest = [[1,2,3],[0,0,4],[7,6,5]]
输出：6
解释：起点 (0,0) 是空地，依次砍 2→3→4→5→6→7，每棵都正好走 1 步，共 6 步。
```

**示例 2**

```text
输入：forest = [[1,2,3],[0,0,0],[7,6,5]]
输出：-1
解释：中间一整行是障碍，最下面一行（7、6、5）完全不可达，无法砍完。
```

**示例 3**

```text
输入：forest = [[2,3,4],[0,0,5],[8,7,6]]
输出：6
解释：(0,0) 处本身有一棵高 2 的树，直接砍掉，不计步数；
      之后沿与示例 1 相同的路径走 6 步砍完 3→4→5→6→7→8。
```

## 3. 解题思路

### 3.1 暴力思路

「求最小步数」的第一反应是在状态 $(r, c, \text{mask})$ 上做 BFS：`mask` 记录哪些树已经被砍，每次可以移动，或在满足「它是最小的未砍树」时原地砍树（0 代价）。这是**完全正确**的搜索，但状态数是 $O(mn \cdot 2^{k})$，$k$ 最坏可到 $2500$（$50 \times 50$ 全是树），状态数爆炸，完全不可行。病根在于**把顺序当成了需要搜索的决策**，而题目里顺序其实是被给定的。

### 3.2 核心观察：砍伐顺序唯一 ⇒ 问题分解成 $k$ 段最短路

![按高度排序后各段独立求最短路](images/wc49_q3_order_fixed.svg)

两个观察合起来就把问题拆开了：

1. **顺序唯一**：所有树高度互不相同，所以「从矮到高」给出的是一个**确定的排列** $p_1, p_2, \dots, p_k$（$p_i$ 是第 $i$ 矮的树所在格子）。方案没有任何排序自由度，$k!$ 种顺序里只有 1 种合法。
2. **分段独立**：任何合法方案都可以在「砍下第 $i$ 棵树」的时刻切成 $k$ 段行走，第 $i$ 段的起点是 $p_{i-1}$（$p_0 = (0,0)$）、终点是 $p_i$。段与段之间没有耦合——因为**树格一直可通行**，图是静态的，走到 $p_i$ 的最短路不会因为「哪些树已砍」而改变。

于是总步数 $T = \sum_{i=1}^{k} t_i$，其中 $t_i \ge \operatorname{dist}(p_{i-1}, p_i)$ 是第 $i$ 段的实际步数。下界由「每段至少走最短路」给出，而**逐段走最短路**同时达到所有下界，故

$$T_{\min} = \sum_{i=1}^{k} \operatorname{dist}(p_{i-1}, p_i)$$

其中 `dist` 是只把 `0` 当作障碍的四方向无权最短路，用 BFS 求。任一 `dist` 为 $\infty$ 则返回 `-1`。

> 💡 一句话：**顺序是题面给的，不是我们要选的**；把「选顺序」这个想法删掉，题目就从 $O(2^k)$ 塌缩成 $k$ 遍 BFS。

### 3.3 算法流程

![算法流程图](images/wc49_q3_bfs_flow.svg)

1. 扫描全图，把所有 `forest[i][j] > 1` 的格子收进列表，按高度升序排序（用堆也可以，即标签里的「优先队列」）。
2. 令 `cur = (0, 0)`、`ans = 0`。
3. 依次取出排好序的树 $p$：以 `cur` 为源做 BFS，只走 `forest != 0` 的格子，求到 $p$ 的最短距离 $d$。
4. 若 $p$ 不可达，直接返回 `-1`；否则 `ans += d`、`cur = p`。
5. 所有树都处理完，返回 `ans`；特别的，`forest[0][0] == 0` 时起点是障碍，一步都出不去，直接 `-1`。

## 4. 算法细节

1. **收集与排序**：把 `(高度, 行, 列)` 三元组入数组后 `sort`；高度最大 $10^9$，`int` 足够（$< 2^{31}-1$），Python 无需考虑类型。用优先队列（小顶堆）逐个弹出等价，代码稍长但省一次排序。
2. **静态图假设**：BFS 只把 `forest == 0` 视为不可通行，**未砍的树格也允许通过**（题面允许「站上去而不砍」）。若误把树格当障碍，示例 1 会算成不可达。
3. **BFS 早停**：一旦弹出或扩展到目标格就返回距离，避免跑满整张图；同时在入队时判重（`dist != -1` / `visited`），每个格子只入队一次。
4. **距离数组复用**：每段 BFS 都要一个 $50\times50$ 的 `dist`，直接重新申请 $k$ 次也才 $2500 \times 2500$ 次初始化，可接受；若要极致常数，可用「时间戳」技巧：`vis[i][j] == stamp` 代替清空。
5. **起点与终点重合**：先判 `(sr, sc) == (tr, tc)` 返回 $0$，否则 BFS 永远不会「走到」目标自身，会误报不可达（示例 3 正是这种情况）。
6. **不可达的处理**：BFS 返回 $-1$ 立刻整体返回 $-1$，**不要**累加后继续跑（会白做 $k$ 遍 BFS）。
7. **规模与取舍**：单段最短路 $\le mn-1 \le 2499$、段数 $k \le 2500$，总和 $\le 6.25\times10^{6}$，`int` 够用；也不必做「树与树两两之间」的 $k^2$ 次 BFS（那才是 $O(k^2 mn)$），顺序固定意味着只需 $k$ 次。

## 5. 正确性证明

**引理 1（顺序唯一）**：任意合法方案中，树的砍伐次序都等于按高度升序的排列 $(p_1, \dots, p_k)$。
**证明**：题面要求「按高度从低到高」砍。若某方案某一步砍的不是当前剩余树中最矮者，就违反了约束；高度两两不同使「剩余树中最矮者」唯一，故合法次序唯一。∎

**引理 2（图是静态的）**：任意时刻可通行格子集合恒为 $\{(i,j) \mid \text{forest}[i][j] \ne 0\}$。
**证明**：砍树只把值从 $>1$ 改成 $1$，两种情况下该格都非 0、可通行；障碍格 `0` 永不可通行。故该集合在整个过程中不变。∎

**引理 3（分段可加下界）**：任意合法方案的总步数 $T \ge \sum_{i=1}^{k} \operatorname{dist}(p_{i-1}, p_i)$，其中 $p_0=(0,0)$。
**证明**：按「砍下第 $i$ 棵树」的时刻把方案的行走切成 $k$ 段，第 $i$ 段从 $p_{i-1}$ 走到 $p_i$，长度 $t_i \ge \operatorname{dist}(p_{i-1},p_i)$；由引理 2，各段的可通行集合与静态图一致，该比较有效。求和即得 $T \ge \sum \operatorname{dist}$。∎

**引理 4（BFS 正确）**：BFS 首次到达某格时的层数即最短距离；队列耗尽仍未到达则该格不可达。
**证明**：BFS 按距离非降序扩展，归纳可得弹出时距离已是最小值；不可达时与源连通的所有格子都被访问过，目标不在其中。∎

**定理（主结论）**：算法返回值等于最小总步数；若存在 $i$ 使 $\operatorname{dist}(p_{i-1},p_i)=\infty$，则必须返回 $-1$。
**证明**：由引理 1 顺序唯一、引理 3 任何方案总步数 $\ge \sum \operatorname{dist}$；而算法输出正是该和且**可达**——逐段拼接每段最短路即得一条总长等于该和的合法行走（每段终点正好是下一棵待砍树，走到即砍；段内路过的树不砍也不违规）。故输出等于最小值。若某段不可达（引理 4 判定精确），该树轮到它时无法到达，任何方案都不能砍完，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：收集与排序 $O(mn + k\log k)$；共做 $k$ 次 BFS，每次 $O(mn)$（每格入队至多一次），合计 $O(k \cdot mn) \le O(m^2 n^2) = 6.25 \times 10^6$，在 $m,n \le 50$ 时极轻。对照状态压缩 BFS 的 $O(mn \cdot 2^k)$：本解法把 $k$ 从指数搬到线性因子。
- **空间**：树列表 $O(k)$、单次 BFS 的距离数组与队列各 $O(mn)$，总计 $O(mn)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <array>
#include <queue>
#include <utility>
#include <vector>
using namespace std;

class Solution {
public:
    int cutOffTree(vector<vector<int>>& forest) {
        int m = forest.size(), n = forest[0].size();
        if (forest[0][0] == 0) return -1;            // 起点是障碍，无法出发

        vector<array<int, 3>> trees;                 // {高度, 行, 列}
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (forest[i][j] > 1) trees.push_back({forest[i][j], i, j});
        sort(trees.begin(), trees.end());            // 砍伐顺序被高度唯一确定

        const int dr[4] = {1, -1, 0, 0}, dc[4] = {0, 0, 1, -1};

        // 从 (sr,sc) 到 (tr,tc) 的最短路，只把 0 当障碍；不可达返回 -1
        auto bfs = [&](int sr, int sc, int tr, int tc) -> int {
            if (sr == tr && sc == tc) return 0;
            vector<vector<int>> dist(m, vector<int>(n, -1));
            queue<pair<int, int>> q;
            dist[sr][sc] = 0;
            q.push({sr, sc});
            while (!q.empty()) {
                auto [r, c] = q.front();
                q.pop();
                for (int k = 0; k < 4; k++) {
                    int nr = r + dr[k], nc = c + dc[k];
                    if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
                    if (dist[nr][nc] != -1 || forest[nr][nc] == 0) continue;
                    dist[nr][nc] = dist[r][c] + 1;
                    if (nr == tr && nc == tc) return dist[nr][nc];   // 早停
                    q.push({nr, nc});
                }
            }
            return -1;
        };

        int total = 0, cr = 0, cc = 0;
        for (auto& t : trees) {
            int d = bfs(cr, cc, t[1], t[2]);
            if (d < 0) return -1;                    // 这棵树永远到不了
            total += d;
            cr = t[1];
            cc = t[2];
        }
        return total;
    }
};
```

### Python

```python
from collections import deque


class Solution:
    def cutOffTree(self, forest: list[list[int]]) -> int:
        m, n = len(forest), len(forest[0])
        if forest[0][0] == 0:                       # 起点是障碍，一步都走不出去
            return -1

        trees = []                                   # (高度, 行, 列)
        for i in range(m):
            for j in range(n):
                if forest[i][j] > 1:
                    trees.append((forest[i][j], i, j))
        trees.sort()                                 # 顺序由高度唯一确定

        def bfs(sr: int, sc: int, tr: int, tc: int) -> int:
            if (sr, sc) == (tr, tc):
                return 0                             # 站在树上，直接砍，不计步数
            seen = [[False] * n for _ in range(m)]
            seen[sr][sc] = True
            q = deque([(sr, sc, 0)])
            while q:
                r, c, d = q.popleft()
                for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
                    nr, nc = r + dr, c + dc
                    if 0 <= nr < m and 0 <= nc < n and not seen[nr][nc] and forest[nr][nc] != 0:
                        if (nr, nc) == (tr, tc):
                            return d + 1             # 早停
                        seen[nr][nc] = True
                        q.append((nr, nc, d + 1))
            return -1                                # 不可达

        total, cr, cc = 0, 0, 0
        for _, tr, tc in trees:
            d = bfs(cr, cc, tr, tc)
            if d < 0:
                return -1
            total += d
            cr, cc = tr, tc
        return total
```

## 8. 边界情况与易错点

1. **起点是障碍**：`forest[0][0] == 0` 时不能站在起点，直接 `-1`。很多写法漏掉这个特判，会从障碍格出发 BFS 得到错误的正数。
2. **起点就是树**：`(0,0)` 的高度是最小的树时，距离为 `0` 而不是 `1`——BFS 必须先判「起点终点重合」，示例 3 就是这个陷阱。
3. **树格可通行**：BFS 判断障碍只能写 `forest[nr][nc] == 0`，不能写 `!= 1` 或 `> 1`，否则未砍的树会被当成墙，示例 1 直接变成 `-1`。
4. **不可达要立刻返回**：发现某段 `dist = -1` 就整体 `-1`，不要继续累加（否则返回的数没有意义，甚至可能因为后续段可达而漏判）。
5. **整数范围**：高度可达 $10^9$，读入用 `int`/Python 原生整数均可，别用 `short`；答案上限约 $6.25\times10^6$，`int` 不会溢出。
6. **重复高度**：题面保证高度互不相同；若数据不遵守，排序后 `sort` 的次序任意，此时用 `(height, r, c)` 三元组稳定比较即可避免不确定行为。
7. **单棵树**：$k=1$ 时答案就是起点到它的距离（可能为 `0`），循环与常规情形一致，无需特判。

**延伸思考**：

1. 若取消「按高度递增」的约束（可任意顺序砍），问题立刻变成 $k$ 个必访点上的**度量旅行商问题**：先做 $k$ 次 BFS 建出距离矩阵，再在 $k \le 20$ 时用状压 DP $O(2^k k^2)$ 求解；$k$ 更大时已是 NP-hard。**顺序约束正是本题可多项式求解的全部原因**。
2. 若把移动代价改成「树格代价为 2、空地为 1」，分段结构依然成立，只需把 BFS 换成 Dijkstra，复杂度 $O(k\,mn\log(mn))$；若再要求「走过的树必须顺手砍掉」，静态图引理（引理 2）不再成立，只能回到状态搜索。
