# LeetCode 最长连续递增序列 题解

## 1. 题目概述

- **标题 / 题号**：最长连续递增序列（#674，easy）
- **链接**：https://leetcode.cn/problems/longest-continuous-increasing-subsequence/
- **来源**：LeetCode 第 49 场周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定一个无序整数数组 `nums`，求最长的「连续递增子序列」并返回其长度。这里「连续」指**下标连续**，「递增」指**严格递增**：区间 $[l,r]$ 合法当且仅当对每个 $l \le i < r$ 都有 $nums[i] < nums[i+1]$。注意是取一段连续区间内部全部元素，不能跳着挑（这与 #300 最长递增子序列完全不同）。

**约束**：

- $1 \le nums.length \le 10^4$
- $-10^9 \le nums[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,5,4,7]
输出：3
解释：最长连续递增序列是 [1,3,5]，长度为 3。
      [1,3,5,7] 虽是升序子序列，但 5 与 7 被 4 隔开，不连续，故不算。
```

**示例 2**

```text
输入：nums = [2,2,2,2,2]
输出：1
解释：所有元素相等，不存在严格递增的相邻对，最长只能取单个元素。
```

> 💡 **补充自测用例**（题面只给了上面两组）：`nums = [1,3,5,4,2,3,4,5]` 的答案是 4 —— 后半段 `[2,3,4,5]` 长度为 4，前半段 `[1,3,5]` 长度为 3，取较大者。它专门用来验证「扫描中途多次重置 `cur`」的情形。

## 3. 解题思路

### 3.1 暴力思路

枚举所有区间 $[l,r]$，再逐对检查 $nums[i] < nums[i+1]$：共 $O(n^2)$ 个区间、每次检查 $O(n)$，总计 $O(n^3)$。稍作优化的写法是固定左端点 $l$，把 $r$ 一路右移并沿途判断，遇到不满足就停：$O(n^2)$。当 $n = 10^4$ 时约 $5 \times 10^7$ 到 $10^8$ 次比较，常数稍大就会超时，且完全没有必要——区间之间大量信息是重复计算的。

关键浪费在于：对每个 $l$ 都从头开始数。而实际上「从 $l$ 出发能延伸多远」这件事，在扫描到 $l$ 时我们已经知道了。

### 3.2 核心观察：数组被「断点」切成互不相交的递增游程

![连续递增序列即严格递增的连续段（游程）](images/wc49_q1_run_concept.svg)

定义下标 $i$（$1 \le i \le n-1$）为**断点**，若 $nums[i] \le nums[i-1]$。断点把整个数组切成若干段**极大**的严格递增段，称为**游程**（run）。例如 `[1,3,5,4,7]` 在 $i=3$ 处有断点（$4 \le 5$），于是分成游程 `[1,3,5]` 与 `[4,7]`。

两个直接结论：

1. 任何合法的连续递增子序列都不可能跨越断点——一旦跨过断点，区间内就出现了一对 $nums[i-1] \ge nums[i]$ 的相邻元素；
2. 每个游程内部都不含断点，因此游程本身就是一个合法的连续递增子序列。

于是问题从「枚举所有区间」变成「找最长的游程」，只需一次遍历、一个计数器。

### 3.3 算法流程 / 状态转移

![一次遍历维护 cur 与 best](images/wc49_q1_scan_flow.svg)

把它写成最朴素的 DP。设 $cur_i$ 为**以 $i$ 结尾**的最长连续递增序列长度，则

$$
cur_i =
\begin{cases}
cur_{i-1} + 1, & nums[i] > nums[i-1] \\
1, & nums[i] \le nums[i-1]
\end{cases}
\qquad cur_0 = 1
$$

答案是 $best = \max_{0 \le i < n} cur_i$。由于 $cur_i$ 只依赖 $cur_{i-1}$，状态可以**滚动成一个变量**，额外空间为 $O(1)$。

算法：`cur = 1, best = 1`；从 $i = 1$ 扫到 $n-1$，若 $nums[i] > nums[i-1]$ 则 `cur += 1`，否则 `cur = 1`；每步用 `cur` 更新 `best`；最后返回 `best`。

> 💡 一句话记法：**上升就加一，断了就归零为一，全程记最大**。整道题就这三行。

### 3.4 示例演算

![数组 1,3,5,4,7 的逐元素走查表](images/wc49_q1_walkthrough.svg)

对 `nums = [1,3,5,4,7]`：

| $i$ | 相邻比较 | 递增？ | $cur_i$ | $best$ |
|-----|----------|--------|---------|--------|
| 1 | $3 > 1$ | 是 | 2 | 2 |
| 2 | $5 > 3$ | 是 | 3 | 3 |
| 3 | $4 > 5$ | 否 | 1 | 3 |
| 4 | $7 > 4$ | 是 | 2 | 3 |

走完全程 $best = 3$，与示例一致。注意 $i=3$ 处 `cur` 归 1 后，`best` 保持不变——这正是「历史最大值」与「当前游程」两个变量分工的意义。

## 4. 算法细节

1. **初值**：`cur = 1`、`best = 1`。长度为 1 的序列本身合法（示例 2 的答案就是 1），因此初值不能取 0，否则纯递减数组会返回 0。
2. **严格递增用 `>`**：判断写成 `nums[i] > nums[i-1]`，绝不能写 `>=`。`[2,2,2]` 若用 `>=` 会得到 3，而正确答案是 1。
3. **循环下界从 1 开始**：每次要访问 `nums[i-1]`，从 $i = 1$ 起步可避免越界；也无需为 $i = 0$ 单独补一次 `max`，因为初值已经覆盖。
4. **更新时机放在循环体内**：`best = max(best, cur)` 必须写在循环内部每轮执行，而不是循环结束后只取一次——后面的游程可能在更靠前的位置就已经达到峰值。
5. **不必要的复杂度都不要引入**：本题不需要排序（排序会破坏下标连续性）、不需要哈希表、不需要二分。判题数据 $n \le 10^4$ 只是为了让 $O(n^2)$ 的暴力写法不至于秒过。
6. **值域与溢出**：$nums[i]$ 可到 $\pm 10^9$，但实现只做**比较**、不做加减，因此不会溢出，用 `int` 完全安全。
7. **Java/C++ 的边界**：`nums` 保证非空；若要在更宽松的接口下健壮，可在函数开头 `if (nums.empty()) return 0;`。
8. **只求长度**：若题目改为要求返回区间下标，则需额外记录 `bestStart`，在 `cur` 刷新 `best` 时同步写入 `i - cur + 1`。

## 5. 正确性证明

**引理 1（状态语义）**：对每个 $0 \le i < n$，扫描到 $i$ 时 `cur` 的值等于以 $i$ 结尾的最长连续递增子序列的长度 $cur_i$。

**证明**：对 $i$ 归纳。$i = 0$ 时以 0 结尾的序列只能是 `[nums[0]]`，长度 1，与初值相符。

设结论对 $i-1$ 成立，考虑 $i$。若 $nums[i] > nums[i-1]$：设 $[l, i]$ 是任一以 $i$ 结尾的合法区间，则 $l \le i-1$，且去掉 $nums[i]$ 后 $[l, i-1]$ 仍是合法区间（其内部相邻对全部满足严格递增），由归纳假设 $i-1-l+1 \le cur_{i-1}$，故区间长度 $i-l+1 \le cur_{i-1}+1$；又 $[i-1-cur_{i-1}+1, i]$ 本身合法（前缀合法且 $nums[i] > nums[i-1]$），长度恰为 $cur_{i-1}+1$，故 $cur_i = cur_{i-1}+1$。若 $nums[i] \le nums[i-1]$：任何长度 $\ge 2$ 的以 $i$ 结尾的区间其内部都含相邻对 $(i-1, i)$，被此条件否决，故只能取长度 1，即 $cur_i = 1$。两种情形均与算法的赋值一致。∎

**引理 2（游程结构）**：任一合法的连续递增子序列必完全落在某个极大递增游程内；反之每个游程都是合法的连续递增子序列。

**证明**：设 $[l,r]$ 合法。若存在断点 $i$ 满足 $l < i \le r$，则 $nums[i-1] \ge nums[i]$，与 $[l,r]$ 内部严格递增矛盾；故 $[l,r]$ 内部无断点，它含于包含它的那个极大递增段。反之，游程内部按定义不含断点，即对任意相邻下标都有 $nums[i-1] < nums[i]$，故合法。∎

**定理**：算法返回的值等于最长连续递增子序列的长度。

**证明**：由引理 2，答案等于所有极大游程长度的最大值 $\max_j |R_j|$。在扫描过程中，$cur$ 在游程内部逐格加一、在断点处重置为 1（引理 1），因此当扫描到某个游程的末元素 $e$ 时 $cur_e = |R|$；而 `best` 每轮取 $\max(best, cur)$，故结束时 $best = \max_i cur_i \ge \max_j |R_j|$。另一方面每个 $cur_i$ 都是某个合法区间的长度，故 $best \le$ 答案。两端夹逼得 $best = \max_j |R_j|$，即所求。∎

## 6. 复杂度分析

- **时间**：$O(n)$。只做一次从 $i=1$ 到 $n-1$ 的线性扫描，每轮一次比较、一次赋值、一次取最大值，均为 $O(1)$；无排序、无重复扫描。
- **空间**：$O(1)$。只有 `cur`、`best` 两个整型变量（DP 的滚动数组优化到极致），不随 $n$ 增长；输入数组本身不计入额外空间。
- **对比**：暴力 $O(n^2)$ 时间 / $O(1)$ 空间；本题正解在时间上降了一个量级，代价为零。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int findLengthOfLCIS(vector<int>& nums) {
        int best = 1, cur = 1;                 // 长度 1 的序列总是合法
        for (size_t i = 1; i < nums.size(); ++i) {
            if (nums[i] > nums[i - 1]) ++cur;  // 严格递增：接上一段
            else cur = 1;                      // 遇到断点：重新开始
            if (cur > best) best = cur;        // 每轮刷新历史最大值
        }
        return best;
    }
};
```

### Python

```python
class Solution:
    def findLengthOfLCIS(self, nums: list[int]) -> int:
        best = cur = 1
        for i in range(1, len(nums)):
            if nums[i] > nums[i - 1]:
                cur += 1
            else:
                cur = 1
            if cur > best:
                best = cur
        return best
```

## 8. 边界情况与易错点

1. **全相等数组**：`[2,2,2,2,2]` 答案是 1。把判定写成 `nums[i] >= nums[i-1]` 会得到 5，是最常见的 WA。
2. **严格递减数组**：`[5,4,3,2,1]` 答案是 1，考察初值 `best = 1` 是否到位；若初值为 0 会返回 0。
3. **单元素数组**：`[7]` 答案是 1，循环体一次都不执行，靠初值返回，说明初值即答案基线。
4. **极值相邻**：`[-1000000000, 1000000000]` 答案是 2。只做比较、不做减法，故 $10^9$ 量级不涉及溢出；若用「差值 $>0$」判断则需注意 `nums[i] - nums[i-1]` 在 `int` 下的溢出风险。
5. **峰值出现在中间**：`[1,2,3,4,1,2]` 答案是 4，且 `best` 的更新必须在循环内完成，否则循环结束时 `cur = 2` 会覆盖掉真实的 4。
6. **断点在末尾**：`[1,2,3,1]` 答案是 3；最后一步 `cur` 归 1 不影响已记录的 `best`。
7. **题意误解**：本题不是 #300 的 LIS，不能跳过元素取子序列；也不是「连续非递减」，相等必须打断游程。
8. **题面表述**：题干用 $l < r$ 描述区间，只覆盖了长度 $\ge 2$ 的情形；长度 1 的序列按示例 2 视为合法，实现中以 1 为初值即可，无需特判。
