# LeetCode 寻找数组的中心下标 题解

## 1. 题目概述

- **标题 / 题号**：寻找数组的中心下标（#724，easy）
- **链接**：https://leetcode.cn/problems/find-pivot-index/
- **来源**：LeetCode 第 58 场周赛 Q1
- **难度**：简单
- **标签**：数组，前缀和

**题意**：给定整数数组 `nums`，若下标 $i$ 满足「严格左侧所有元素之和」等于「严格右侧所有元素之和」，则称 $i$ 为**中心下标**。下标在左端时左侧和视为 $0$，在右端时右侧和视为 $0$（即 `nums[i]` 本身不计入任何一侧）。若存在多个中心下标，返回**最左**的那个；不存在则返回 $-1$。

**约束**：

- $1 \le \lvert \text{nums} \rvert \le 10^4$
- $-1000 \le \text{nums}[i] \le 1000$
- 数组元素可以为负，因此前缀和**不单调**，不能用二分或双指针收缩

## 2. 示例

**示例 1**

```text
输入：nums = [1, 7, 3, 6, 5, 6]
输出：3
解释：左侧和 = 1 + 7 + 3 = 11，右侧和 = 5 + 6 = 11，二者相等；
      下标 3 是唯一的中心下标。
```

**示例 2**

```text
输入：nums = [1, 2, 3]
输出：-1
解释：total = 6，三个下标对应的判定值 2·left + nums[i] 依次为 1、4、9，
      没有一个等于 6，故不存在中心下标。
```

**示例 3**

```text
输入：nums = [2, 1, -1]
输出：0
解释：左侧和 = 0（下标 0 左侧无元素），右侧和 = 1 + (-1) = 0；
      下标 0 即为中心下标。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$，分别用一层循环求 `nums[0..i-1]` 与 `nums[i+1..n-1]` 的和，相等就返回 $i$。两次累加合计 $O(n)$，外层再套 $n$ 个下标，总复杂度 $O(n^2)$。$n = 10^4$ 时约 $10^8$ 次加法，C++ 勉强擦边、Python 必然超时。

更要紧的是：这个写法在算 $i+1$ 的左侧和时，**把 $i$ 已经算好的结果整段丢掉了**，从零重新累加。真正需要优化的只是「如何复用左侧和」，而不是换什么高深数据结构。

### 3.2 核心观察：用总和把「右侧和」消掉

![把总和拆成左、我、右三段](images/wc58_q1_balance_condition.svg)

记 $S = \sum \text{nums}$，$L_i = \sum_{k<i} \text{nums}[k]$，$R_i = \sum_{k>i} \text{nums}[k]$。由于 $i$ 把数组切成互不相交的三段，恒有

$$L_i + \text{nums}[i] + R_i = S \quad\Longrightarrow\quad R_i = S - L_i - \text{nums}[i]$$

题目要求 $L_i = R_i$，代入上式即得**只含已知量**的等价条件：

$$2 L_i + \text{nums}[i] = S$$

这一步的意义在于：**右侧和不必再单独维护**，只要提前算出总和 $S$、再在扫描中维护一个左侧和 $L$，每个下标都是 $O(1)$ 判定。而 $L$ 的递推是标准的

$$L_{i+1} = L_i + \text{nums}[i]$$

一次加法即可从上一个下标「接力」过来，正好补上暴力做法的短板。

> 💡 **为什么从 0 往右扫就自动满足「最左」**：命中即返回，第一个被命中的下标左边不存在任何中心下标。

### 3.3 算法流程

![一次扫描 + 前缀和增量维护](images/wc58_q1_algorithm_flow.svg)

1. 第一趟求总和：`total = sum(nums)`；
2. 初始化左侧和 `left = 0`；
3. 第二趟从 $i = 0$ 到 $n-1$：若 $2 \cdot \text{left} + \text{nums}[i] = \text{total}$，立即返回 $i$；否则 `left += nums[i]`，继续；
4. 全部扫完仍无命中，返回 $-1$。

注意第 3 步的顺序是**先判定、后累加**：进入下标 $i$ 时 `left` 必须恰好等于 `nums[0..i-1]` 之和，一旦写成「先加后判」，`nums[i]` 就被重复算进了左侧。

### 3.4 示例演算

![示例 1 的逐步判定表](images/wc58_q1_walkthrough.svg)

对 `nums = [1, 7, 3, 6, 5, 6]`，`total = 28`：

| $i$ | `nums[i]` | `left`（进入前） | $2\cdot\text{left}+\text{nums}[i]$ | 与 28 比较 |
|-----|-----------|------------------|------------------------------------|------------|
| 0 | 1 | 0 | 1 | 不等，继续 |
| 1 | 7 | 1 | 9 | 不等，继续 |
| 2 | 3 | 8 | 19 | 不等，继续 |
| 3 | 6 | 11 | **28** | 相等，返回 3 |
| 4 | 5 | — | — | 已返回，不再扫描 |
| 5 | 6 | — | — | 已返回，不再扫描 |

命中时 `left = 11`，而右侧 $5 + 6 = 11$，两侧确实相等。另外两组示例同理：`[1,2,3]` 的判定值为 $1,4,9$，全不等于 $6$，返回 $-1$；`[2,1,-1]` 在下标 $0$ 处 $2\cdot 0 + 2 = 2 = S$，立即返回 $0$（此时 `total = 2`）。

## 4. 算法细节

1. **必须两趟**：总和 $S$ 是判定式的常数项，得先完整读一遍数组；想「边读边判」是做不到的，因为后面元素的和在扫描到 $i$ 时还未知。
2. **判定式只写一次减法**：$2L + x = S$ 只用到 `total` 与 `left` 两个变量，无需 `sumLeft` / `sumRight` 两个数组，也省掉了「右侧和 = 总和 − 左侧和 − 当前值」的重复计算。
3. **`left` 的更新位置固定在判定之后**：这是本题唯一容易写错的地方，顺序错了会在 $i$ 处把自身算进左侧，导致答案整体右移或漏判。
4. **命中就 `return`**：题目要最左，扫描方向已经保证这一点；不要收集全部答案再取 `min`，那会白费一次遍历和 $O(n)$ 空间。
5. **整数范围**：$\lvert \text{nums}[i] \rvert \le 1000$、$n \le 10^4$，故 $\lvert S \rvert \le 10^7$，$2L + x$ 的量级是 $2 \times 10^7$，`int` 完全够；C++ 里仍写成 `long long` 属于零成本的保险，若约束放宽到 $10^9$ 量级则必须用 64 位。
6. **无需前缀和数组**：本题只查询「整个前缀」而从不查询任意区间，所以一个滚动变量就够了，空间 $O(1)$。只有当题目变成「多次询问任意区间和」时才需要前缀和数组。
7. **接口按 `metaData`**：函数名为 `pivotIndex`，参数 `vector<int>& nums` / `list[int]`，返回 `int`，与官方签名保持一致。

## 5. 正确性证明

**引理 1（判定式等价）**：对任意下标 $i$，$2L_i + \text{nums}[i] = S$ 当且仅当 $i$ 左侧元素之和等于右侧元素之和。

**证明**：由三段不交分解，$R_i = S - L_i - \text{nums}[i]$。于是

$$L_i = R_i \iff L_i = S - L_i - \text{nums}[i] \iff 2L_i + \text{nums}[i] = S$$

每一步都是等式两边同加同减，等价变形可逆，故命题成立。边界下标同样成立：$i=0$ 时 $L_0 = 0$，判定式化为 $\text{nums}[0] = S$，即右侧和 $=0$；$i=n-1$ 时 $R_{n-1} = 0$，判定式化为 $2(S - \text{nums}[n-1]) + \text{nums}[n-1] = S$，同样等价于左侧和 $=0$。∎

**引理 2（不变式）**：循环进入下标 $i$ 时，变量 `left` 恰等于 $\sum_{k<i} \text{nums}[k]$。

**证明**：对 $i$ 归纳。$i = 0$ 时 `left = 0`，而空和定义为 $0$，成立。设进入 $i$ 时不变式成立，若未命中则执行 `left += nums[i]`，此后 `left` $= \sum_{k<i}\text{nums}[k] + \text{nums}[i] = \sum_{k \le i}\text{nums}[k]$，正是进入 $i+1$ 时所需的值，不变式保持。∎

**定理**：算法返回最左的中心下标；若不存在中心下标则返回 $-1$。

**证明**：若算法在下标 $i$ 返回，则判定式 $2L_i + \text{nums}[i] = S$ 成立，由引理 1 知 $i$ 是中心下标；又循环从 $0$ 递增扫描，$i$ 之前的所有下标都判定失败、不可能是中心下标，故 $i$ 是最左的中心下标。反之，若存在中心下标 $j$，则扫描到 $j$ 时（由引理 2 的 `left` 正确性、引理 1 的等价性）判定必然成立并返回，不可能出现「存在却返回 $-1$」的情况；因此返回 $-1$ 当且仅当不存在中心下标。∎

## 6. 复杂度分析

- **时间**：$O(n)$。第一趟求和 $n$ 次加法；第二趟 $n$ 次「乘 2 + 加法 + 比较 + 累加」。总运算量约 $4n$，$n = 10^4$ 时是 $4 \times 10^4$ 级，远低于时限。
- **空间**：$O(1)$。只用了 `total`、`left`、循环变量三个标量，没有前缀和数组、没有哈希表；输入数组本身不计入。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int pivotIndex(vector<int>& nums) {
        long long total = 0;
        for (int x : nums) total += x;      // 第一趟：总和

        long long left = 0;
        for (int i = 0; i < (int)nums.size(); ++i) {
            if (2 * left + nums[i] == total) {
                return i;                   // 命中即返回，天然最左
            }
            left += nums[i];                // 先判后加：维护左侧和
        }
        return -1;
    }
};
```

### Python

```python
class Solution:
    def pivotIndex(self, nums: list[int]) -> int:
        total = sum(nums)          # 第一趟：总和，把「右侧和」消掉
        left = 0                   # 进入下标 i 前，nums[0..i-1] 之和
        for i, x in enumerate(nums):
            if 2 * left + x == total:
                return i           # 从左往右扫，首次命中即最左
            left += x              # 先判后加，避免把 nums[i] 算进左侧
        return -1
```

## 8. 边界情况与易错点

1. **单元素数组**：`[5]` → $0$。$L_0 = 0$、$R_0 = 0$，判定式 $2 \cdot 0 + 5 = 5 = S$ 成立。若忘记「左端左侧和为 0」的约定，很容易错判成 $-1$。
2. **全零数组**：`[0,0,0]` → $0$，而不是 $1$。每个下标都是中心下标，扫描顺序决定了返回最左的那个，所以必须「命中即返回」而不是覆盖式更新。
3. **负元素与负总和**：`[-1,-1,-1]` → $1$（$S = -3$，$i = 1$ 时 $2 \cdot (-1) + (-1) = -3$）。判定式对负值完全成立，不要额外加「前缀和非负」之类的假设，也不要试图用双指针/二分来「收缩」。
4. **总和为 0 时容易漏解**：`[2,-2,0]` → $2$（左侧和 $2 + (-2) = 0$，右侧为空和 $0$）。若把判定写成「$L = S - L - x$ 且要求 $S > 0$」就会漏掉这类答案。
5. **先加后判的经典 bug**：把 `left += x` 写到 `if` 之前，判定式就变成了 $2L_i + 3\text{nums}[i] = S$，`[1,7,3,6,5,6]` 由此返回 $-1$（漏掉正确答案 3）；把两行顺序换回来即可。
6. **无解要能干净地返回 $-1$**：`[1,2,3]` → $-1$。注意此时 `total = 6`，$i = 2$ 的判定值是 $9$，不要因为「$9 > 6$ 就提前退出」——前缀和不单调，后面的下标仍可能命中。
7. **空数组**：约束保证 $n \ge 1$；若被外部传入空数组，`sum` 为 $0$、循环不执行、返回 $-1$，行为安全，不需要额外特判。
8. **Python 的类型注解**：`list[int]` 需要 3.9+，LeetCode 当前环境支持；若在更老的解释器里跑，改成 `List[int]` 或直接去掉注解。
