# LeetCode 原子的数量 题解

## 1. 题目概述

- **标题 / 题号**：原子的数量（#726，hard）
- **链接**：https://leetcode.cn/problems/number-of-atoms/
- **来源**：LeetCode 第 58 场周赛 Q3
- **难度**：困难
- **标签**：栈、哈希表、字符串、排序

**题意**：给定一个合法的化学式字符串 `formula`，统计其中每种原子的最终个数。语法只有三条规则——

1. 原子名以**一个大写字母**开头，后接**任意个小写字母**（如 `H`、`Mg`、`Na`、`Cl`）；
2. 原子名后若跟数字，表示该原子在本层的个数；不跟数字等价于个数 1（`H2O` 合法，`H1O2` 不合法）；
3. 括号包起来的片段是一个整体，括号后的数字会把**整段**里的所有原子个数乘上去，且括号可以任意嵌套。

最终按**原子名字典序**拼接输出，个数为 1 时省略数字。

**约束**：

- $1 \le \lvert \text{formula} \rvert \le 1000$
- `formula` 只含英文字母、数字、`'('`、`')'`
- `formula` 一定是一个合法的化学式

## 2. 示例

**示例 1**

```text
输入：formula = "H2O"
输出："H2O"
解释：原子数量为 {H: 2, O: 1}；O 的个数是 1，输出时省略数字。
```

**示例 2**

```text
输入：formula = "Mg(OH)2"
输出："H2MgO2"
解释：原子数量为 {H: 2, Mg: 1, O: 2}；
      括号后的 2 同时作用于 H 和 O，而 Mg 保持不变。
```

**示例 3**

```text
输入：formula = "K4(ON(SO3)2)2"
输出："K4N2O14S4"
解释：原子数量为 {K: 4, N: 2, O: 14, S: 4}；
      O 来自 (ON…) 的 1 个（×2→2）与 (SO3) 的 3 个（×2×2→12），合计 14。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的暴力是**先完全展开再统计**：反复找到最内层的 `(...)`，把里面每个原子的个数乘以括号后的倍数，写回字符串，直到没有括号，最后扫描一遍统计。这样在真实数据上通常也能跑过（长度只有 1000），但有两个隐患：

- 展开后的**中间串可能远长于输入**：`(A)9` 嵌套 100 层，个数是 $9^{100}$，展开成字符会直接爆炸；
- 每次字符串重写都要复制整串，最坏 $O(n^2)$ 的字符搬运。

所以正确方向不是「展开成原子」，而是「**边解析边合并**」：括号里的内容算完后，**直接把计数表乘倍率加进上一层**，中间结果始终只有「元素 → 个数」这一张表，规模不超过元素种类数（最多 118 种）。

### 3.2 核心观察：括号 = 乘法作用域

![括号构成乘法作用域](images/wc58_q3_nesting_scope_model.svg)

一个原子的最终数量，等于它**所在每一层括号的倍数连乘**，再乘上它自己后面的数字。例如 `K4(ON(SO3)2)2` 中的 `S`：

- 它在第 2 层括号 `(SO3)` 里，该层倍数 2；
- 该层又被第 1 层括号 `(ON(...)2)` 包住，倍数 2；
- 自己后面没有数字，倍数 1；

于是 $S = 1 \times 2 \times 2 = 4$。关键点是：**倍数只对「作用域内」的原子生效**。这提示我们用**栈**来表达嵌套——遇到 `(` 就压入一张新的空计数表，遇到 `)` 就弹出这张表、整表乘以括号后的倍数、再累加回上一层。栈的深度恰好等于当前括号嵌套深度。

### 3.3 算法流程：递归解析（与显式栈等价）

![算法流程图](images/wc58_q3_algorithm_flow.svg)

写成递归更简洁。定义

$$\text{parse}(i) = \big(\text{cnt},\ j\big)$$

其中 `cnt` 是「从下标 $i$ 开始、到本层结束为止」这段子式的原子计数表，`j` 是**本层结束时停下的下标**（也就是与之配对的 `)` 的位置，或者串尾 $n$）。主循环：

- `formula[i]` 是**大写字母**：往后吞掉所有小写字母得到元素名；再吞掉连续数字得到倍率 `mul`（没有数字取 1）；`cnt[name] += mul`，`i` 前移。
- `formula[i] == '('`：递归 `parse(i+1)` 拿到子表 `sub` 与位置 `j`；`i = j + 1` 跳过 `)`；再读紧随其后的数字作为本层倍率 `mul`；对 `sub` 中每个元素执行 `cnt[k] += v * mul`。
- `formula[i] == ')'`：本层结束，返回 `(cnt, i)`。
- `i == n`：返回 `(cnt, n)`。

显式栈版本把「递归帧」换成 `vector<map<string,long long>>`：入 `(` 时 `push` 一张空表，出 `)` 时 `pop` 并按上面的方式回填。两者结构完全一致，只是一个用函数调用栈、一个用容器栈。

### 3.4 示例演算

![示例演算表](images/wc58_q3_walkthrough.svg)

以 `formula = "K4(ON(SO3)2)2"` 走一遍：

| 读入 | 动作 | 栈顶计数表变化 |
|------|------|----------------|
| `K` | 元素 K，倍数缺省 1 | `{K:1}` |
| `4` | K 的倍数 4 | `{K:4}` |
| `(` | 压栈，开启层 1 | `{}` |
| `ON` | O、N 各 1 次 | `{O:1, N:1}` |
| `(` | 压栈，开启层 2 | `{}` |
| `SO3` | S 计 1，O 计 3 | `{S:1, O:3}` |
| `)2` | 弹层 2，整层 ×2 并回层 1 | `{O:7, N:1, S:2}` |
| `)2` | 弹层 1，整层 ×2 并回层 0 | `{K:4, N:2, O:14, S:4}` |
| 结束 | 按字典序拼接 | `K4N2O14S4` |

注意 `O` 在层 1 里本来有 1 个，加上从层 2 回填的 $3 \times 2 = 6$，再整体乘上外层 2，得到 $(1+6)\times 2 = 14$——**先合并再乘**和**先乘再合并**结果一致，这正是可以在任意时刻回填的原因。

## 4. 算法细节

1. **元素名的词法边界**：大写字母必是名字开头，紧随其后的连续小写字母都属于同一个名字。`Mg(OH)2` 里 `Mg` 是一个元素，绝不能拆成 `M` 和 `g`；这也是「按字符逐个判断」最容易踩的坑。
2. **数字可能有多位**：`Be32` 是 1 个 Be 还是 32 个 Be？答案是 **32 个**，所以要一直吞到非数字字符为止，不能用单个字符当倍率。
3. **`mul` 的缺省值是 1**：`(H2O)` 与 `(H2O)1` 等价，读数字时用「指针是否前移」来判断有没有读到数字，而不是判断字符是否为 `'0'`。
4. **返回下标的语义要统一**：`parse(i)` 返回「停下的位置」，若因 `)` 停下，则调用方执行 `i = j + 1` 跳过它；若因串尾停下，`j = n`，调用方自然收敛。写递归时最容易在这里差一位而陷入死循环。
5. **计数表选型**：C++ 用 `map<string, long long>`，天然按字典序，省掉最后排序；Python 用 `dict` + `sorted(cnt)`。若追求常数优化可用 `unordered_map` 再排序，但本题 $n \le 1000$，没必要。
6. **倍率与计数用 64 位**：括号倍数相乘可能超出 32 位（如 `(X)999` 嵌两层就是 $999^2$），中间量统一用 `long long` / Python 原生大整数。
7. **递归深度**：最坏的合法输入是 `((((...H...))))`，深度约 $n/2 = 500$ 层，远小于默认栈深度，无需担心爆栈；若坚持不用递归，显式栈写法等价。

## 5. 正确性证明

**引理 1（终止位置正确）**：对任意 $i$，若 `formula[i:]` 的合法前缀在本层结束，则 `parse(i)` 返回的位置 $j$ 满足：$j = n$，或 `formula[j] == ')'` 且它是与「本层起点」配对的那个右括号。

**证明**：对递归深度归纳。主循环每次只消费一个**完整的语法单元**：大写字母开头的一段名字 + 可选数字，或一对完整括号 + 可选数字；消费长度都 $\ge 1$，故循环必然终止。终止只有两种情形：`i == n`（串尾），或 `formula[i] == ')'`——而由于进入本层时（主调用 $i=0$，或跳过了一个 `(`）尚未消费任何右括号，此刻遇到的第一个 `)` 正是本层的收尾括号。∎

**引理 2（计数表正确）**：设子式 $F$ 是 `formula[i:j]` 对应的本层内容，则 `parse(i)` 返回的表中每个元素 $e$ 的值，等于 $F$ 完全展开后 $e$ 的出现次数。

**证明**：对子式的结构归纳。

- **原子项** `name` + 可选数字 $m$：表中 `name` 累加 $m$（缺省 1），与展开定义一致。
- **拼接** $F = F_1 F_2$：主循环先处理完 $F_1$ 再处理 $F_2$，两次累加在同一张表上，由归纳假设各自正确，合并后即 $F$ 的计数。
- **括起项** $F = (G)\,m$：递归给出 $G$ 的计数表（归纳假设），再对每个元素执行 `cnt[k] += v * m`，即把 $G$ 的每个原子放大 $m$ 倍后并入，与 $(G)m$ 的展开定义一致。∎

**定理**：算法返回的字符串是题目要求的答案。

**证明**：由引理 1，`parse(0)` 恰好在串尾结束，其计数表覆盖整个化学式；由引理 2，表中每个元素的值就是该元素的真实个数。最终按字典序遍历（`map` 的迭代序 / Python 的 `sorted`），对个数 $>1$ 的元素追加十进制数字、个数 $=1$ 的省略，与题目要求的格式逐字一致。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。扫描每个字符恰好一次，共 $O(n)$ 次词法操作；每次「出栈合并」遍历的是当前层的元素种类数（至多 118），总合并量为 $O(n)$ 次表操作，每次 `map` 操作 $O(\log 118)$，可视为常数；最后的遍历输出为 $O(k \log k)$，$k$ 为不同元素数。若用哈希表实现，可退化为 $O(n + k \log k)$。
- **空间**：$O(n)$。递归深度最坏 $\Theta(n/2)$（每层只放一个 `(`），每层一张表，每张表的元素种类数不超过该层出现的元素种类数，总计 $O(n)$；输出串长度为 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <map>
#include <cctype>
#include <utility>
using namespace std;

class Solution {
public:
    string s;
    int n;

    // 解析 [i, ...) 直到本层的 ')' 或串尾，返回 {本层计数表, 停下的下标}
    pair<map<string, long long>, int> parse(int i) {
        map<string, long long> cnt;
        while (i < n && s[i] != ')') {
            if (s[i] == '(') {
                auto [sub, j] = parse(i + 1);          // C++17 结构化绑定
                i = j + 1;                             // 跳过 ')'
                int p = i;
                while (p < n && isdigit((unsigned char)s[p])) ++p;
                long long mul = (p > i) ? stoll(s.substr(i, p - i)) : 1;
                i = p;
                for (auto &[k, v] : sub) cnt[k] += v * mul;
            } else {                                   // 大写字母开头
                int p = i + 1;
                while (p < n && islower((unsigned char)s[p])) ++p;
                string name = s.substr(i, p - i);
                int q = p;
                while (q < n && isdigit((unsigned char)s[q])) ++q;
                long long mul = (q > p) ? stoll(s.substr(p, q - p)) : 1;
                i = q;
                cnt[name] += mul;
            }
        }
        return {cnt, i};
    }

    string countOfAtoms(string formula) {
        s = formula;
        n = (int)s.size();
        auto [cnt, _] = parse(0);                      // map 迭代序即字典序
        string ans;
        for (auto &[name, num] : cnt) {
            ans += name;
            if (num > 1) ans += to_string(num);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countOfAtoms(self, formula: str) -> str:
        n = len(formula)

        def parse(i: int):
            """解析 [i, ...) 直到本层的 ')' 或串尾，返回 (计数表, 停下的下标)"""
            cnt = {}
            while i < n and formula[i] != ')':
                if formula[i] == '(':
                    sub, i = parse(i + 1)
                    i += 1                              # 跳过 ')'
                    j = i
                    while j < n and formula[j].isdigit():
                        j += 1
                    mul = int(formula[i:j]) if j > i else 1
                    i = j
                    for k, v in sub.items():
                        cnt[k] = cnt.get(k, 0) + v * mul
                else:                                   # 大写字母开头
                    j = i + 1
                    while j < n and formula[j].islower():
                        j += 1
                    name = formula[i:j]
                    k = j
                    while k < n and formula[k].isdigit():
                        k += 1
                    mul = int(formula[j:k]) if k > j else 1
                    i = k
                    cnt[name] = cnt.get(name, 0) + mul
            return cnt, i

        cnt, _ = parse(0)
        return ''.join(name + (str(cnt[name]) if cnt[name] > 1 else '')
                       for name in sorted(cnt))
```

## 8. 边界情况与易错点

1. **单个原子无数字**：`"H"` → `"H"`；`"Na"` → `"Na"`。注意 `Na` 是一个元素，不是 `N` + 1 个 `a`。
2. **多位数字**：`"Be32"` → `"Be32"`，必须循环读取连续数字；把倍率写成单个字符会把 32 读成 3。
3. **括号后没有数字**：`"(H2O)"` → `"H2O"`，缺省倍率为 1，别写成 0 或漏乘。
4. **个数为 1 不输出数字**：`"Mg(OH)2"` → `"H2MgO2"` 而不是 `"H2Mg1O2"`。
5. **括号嵌套的倍数要累乘而非累加**：`"((H)2)3"` → `"H6"`（$1\times2\times3$）。
6. **连续括号**：`"((K)2)3"` 里出现相邻的 `(`，递归要能处理「进入本层后立刻又遇到 `(`」；主循环的终止条件要先看是否已到 `)` 或串尾、再看当前是不是 `(`，否则会把括号误当成元素名。
7. **计数溢出**：题目没有限制总数的大小，深嵌套 `×999` 会让计数指数增长；Python 大整数天然安全，C++ 的 `long long` 足以覆盖官方数据，若真要应对指数级构造则需换成大整数实现。
8. **字典序直接比较字符串即可**：`C < Ca < Cl`，`map` / `sorted` 的迭代序恰好就是题目要求的顺序，不要按出现顺序输出。
