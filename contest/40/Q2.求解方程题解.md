# LeetCode 求解方程 题解

## 1. 题目概述

- **标题 / 题号**：求解方程（#640，medium）
- **链接**：https://leetcode.cn/problems/solve-the-equation/
- **来源**：LeetCode 第 40 场周赛 Q2
- **难度**：中等
- **标签**：数学、字符串、模拟、线性代数

**题意**：给定一个一元一次方程的字符串，例如 `x+5-3+x=6+x-2`。串中只含整数、变量 \(x\)、`+`、`-`，以及**恰好一个** `=`。要求解出 \(x\)，并把结果拼成 `"x=#"` 返回；若方程**无解**返回 `"No solution"`，若**有无限多解**返回 `"Infinite solutions"`。题面保证：当方程只有一个解时，该解是**整数**。

**约束**：

- \(3 \le \lvert \text{equation} \rvert \le 1000\)
- 方程中恰好有一个 `'='`
- 出现的整数绝对值在 \([0, 100]\) 内，且**无前导零**
- 题面保证「唯一解 ⇒ 解为整数」，因此**不必处理分数**

## 2. 示例

**示例 1**

```text
输入：equation = "x+5-3+x=6+x-2"
输出："x=2"
解释：左式 = 2x+2，右式 = x+4，移项得 (2-1)x = 4-2，即 x = 2。
```

**示例 2**

```text
输入：equation = "x=x"
输出："Infinite solutions"
解释：两侧都是 1x+0，移项得 0x = 0，任何 x 都满足。
```

**示例 3**

```text
输入：equation = "2x=x"
输出："x=0"
解释：移项得 1x = 0，故 x = 0（0 是合法解，不是"无解"）。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是**枚举 \(x\) 的候选值**，逐个代入方程两侧比较：对每个候选值扫描一遍方程、求出左右两侧的值，相等就是一个解。这个思路有两个硬伤：

1. **候选范围无法确定**：每侧至多几百项、每项系数至多 100，解的量级能到 \(10^4\)，枚举上界写不出来，写大了直接超时。
2. **区分不了后两类**：枚举只能找到"能取到的解"，而"无解"与"无限多解"在数值上是同一种表现（一个都没枚举到 / 枚举到的全相等），必须额外做代数分析才能分开。

另一条"聪明但绕"的路是代入 \(x=0\) 与 \(x=1\)：左侧 \(a_1x+b_1\)、右侧 \(a_2x+b_2\)，两次求值即可反解出 \(a_1-a_2\) 与 \(b_1-b_2\)。数学上成立，但要求先写一个能代入求值的表达式求值器，代码量远大于本题所需，还得自己处理 \(a_1=a_2\) 的除零。

> 💡 真正的突破口是**不要去"求值"，而要去"收集"**：把每侧表达式压成一个二元组 \((a,b)\)，方程就塌缩成一个数学习题。

### 3.2 核心观察：线性归约

![线性归约：两侧各压成 (a,b)，移项得 a·x = b](images/wc40_q2_linear_form.svg)

方程两侧都只是形如 \(a x + b\) 的**一次式**（\(x\) 是唯一未知量，其余全是常数）。于是设

$$
\text{左式} = a_1 x + b_1,\qquad \text{右式} = a_2 x + b_2
\quad\Longrightarrow\quad
(a_1 - a_2)\,x = b_2 - b_1
$$

**关键**：一个含 \(x\) 的线性表达式，其全部信息就是两个数——\(x\) 的系数和常数项。所以整道题只剩两件事：**扫描**（把字符串变成 \((a,b)\)）和**分类**（按 \(a=0\) 与否讨论）。整个过程是 \(O(n)\) 的一遍扫描，没有任何迭代试错。

三种情形由 \((a,b)\) 完全决定：

$$
\begin{cases}
a \ne 0 & \Rightarrow x = b/a \ \text{（唯一解）}\\
a = 0,\ b = 0 & \Rightarrow \text{无限多解}\\
a = 0,\ b \ne 0 & \Rightarrow \text{无解}
\end{cases}
$$

### 3.3 算法流程

![扫描流程：符号 → 数字 → 是否带 x → 累加，最后三分支输出](images/wc40_q2_scan_flow.svg)

1. 用 `'='` 把方程切成 `left` 与 `right` 两段，各调用一次 `parse`，得到 \((a_1,b_1)\) 与 \((a_2,b_2)\)。
2. `parse` 是**一次线性扫描**，维护三个变量：当前符号 `sign`、读到的数字 `num`、是否真的读到数字 `hasNum`。
   - 遇到 `'+'` / `'-'`：更新 `sign`，指针后移；
   - 读一段连续数字填进 `num`（可能一个都没有）；
   - 看**下一个字符**是不是 `'x'`：是则该数进系数（没有数字就记 \(1\)），否则该数进常数项。
3. 合并：\(a = a_1 - a_2\)，\(b = b_2 - b_1\)。
4. 分类输出：先判 \(a = 0\)（此时再看 \(b\)），否则返回 `"x=" + (b/a)`。

**为什么只扫一遍就够**：每个项的形状只有三种——`+kx`、`x`、`±c`。扫描时"数字 + 一个字符的前瞻"就能唯一定位它是哪一种，不需要回退、不需要正则、不需要栈。

### 3.4 示例演算

![示例逐项演算：两侧各累加出 (a,b)，再移项求 x](images/wc40_q2_walkthrough.svg)

对 `x+5-3+x=6+x-2` 逐项走一遍：

| 项 | 读到的数字 | 含 \(x\)？ | 累加动作 |
|----|-----------|-----------|----------|
| `x` | 没有 → 记 1 | 是 | \(coef\) 加 \(1\) |
| `+5` | 5 | 否 | \(const\) 加 \(5\) |
| `-3` | 3 | 否 | \(const\) 减 \(3\) |
| `+x` | 没有 → 记 1 | 是 | \(coef\) 加 \(1\) |

左式小计 \((a_1,b_1) = (2,2)\)；同理右式三项 `6`、`+x`、`-2` 得 \((a_2,b_2) = (1,4)\)。

于是

$$
a = 2-1 = 1,\qquad b = 4-2 = 2,\qquad x = \frac{2}{1} = 2
$$

返回 `"x=2"`，与官方输出一致。再看 `x=x`：两侧都得 \((1,0)\)，于是 \(a=0\)、\(b=0\)，落到"无限多解"分支。

## 4. 算法细节

1. **首项符号**：不必先给字符串补一个 `'+'`，把 `sign` 初始化成 \(+1\) 即可；只有真正遇到 `+`/`-` 才更新它。
2. **`hasNum` 是必需的**：不能用 `num == 0` 判断"没读到数字"。`x` 的系数是 \(1\)，而 `0x` 的系数是 \(0\)，两者数字部分都是 0，只有 `hasNum` 能把它们分开（`"0x=0"` 是无限解，不是 `x=1`）。
3. **项的三种形状统一处理**：`±kx`、`±x`、`±c` 共用同一段代码——先无条件读数字、再看下一个字符是否为 `x`，避免写三套分支。
4. **符号的作用域**：`sign` 表示"当前项整体符号"，读完数字后**不清零**，要等下一次遇到 `+`/`-` 才更新；否则 `x+5` 里的 5 会丢掉符号。
5. **移项方向**：把 \(x\) 集中到左边、常数集中到右边，得到 \(a = a_1 - a_2\)、\(b = b_2 - b_1\)。写成 \(b_1 - b_2\) 会得到相反数，是最常见的抄错点。
6. **判空顺序**：必须先判 \(a = 0\)（其中再判 \(b = 0\)），只有 \(a \ne 0\) 时才允许做除法，天然规避除零。
7. **整除兜底**：题面保证唯一解是整数，但代码里仍保留 $b \bmod a \ne 0$ 的检查，返回 `"No solution"` 而不是引入浮点除法。
8. **不要用浮点**：系数与常数都是整数且上界很小（\(\le 100 \times 1000 = 10^5\)），整型运算足够，用 `double` 反而会出现 `-0`、`2.9999999` 之类的输出格式问题。

## 5. 正确性证明

**引理 1（单侧解析正确）**：`parse(expr)` 返回的 \((coef, const)\) 满足：对任意有理数 \(x\)，该侧表达式的值等于 \(coef \cdot x + const\)。

**证明**：对表达式中的项数归纳。每个循环体恰好消耗一个完整项（可选的符号、可选的连续数字、可选的字符 `x`）：若该项含 `x`，其值为 \(sign \cdot num \cdot x\)（无数字时 \(num\) 取 \(1\)），代码把它累加到 `coef`；若不含 `x`，其值为常数 \(sign \cdot num\)，代码把它累加到 `const`。两种情形都保持一次式形式，且循环只在项的分界处（`+`/`-` 或串尾）推进，故所有项被不重不漏地累加一次。∎

**引理 2（归约等价）**：\(a_1x+b_1 = a_2x+b_2\) 当且仅当 \((a_1-a_2)x = b_2-b_1\)。

**证明**：由等式性质，两边同时减去 \((a_2x + b_1)\)，左边变为 \((a_1-a_2)x\)、右边变为 \(b_2-b_1\)，该变换可逆，故等价。∎

**引理 3（三分支完备且互斥）**：记 \(a = a_1-a_2\)、\(b = b_2-b_1\)，则 \(a \ne 0\) 时方程在有理数范围内恰有一个解 \(x = b/a\)；\(a = 0\) 且 \(b = 0\) 时任意有理数都是解；\(a = 0\) 且 \(b \ne 0\) 时没有解。

**证明**：方程为 \(a x = b\)。\(a \ne 0\) 时两边乘 \(a^{-1}\) 得唯一解；\(a = 0\) 时退化为 \(0 = b\)，与 \(x\) 无关，故 \(b = 0\) 恒成立、\(b \ne 0\) 恒不成立。三种情形按 \((a,b)\) 的取值划分，覆盖全部可能且两两不交。∎

**定理**：算法返回的字符串与题面对"唯一解 / 无解 / 无限解"的定义完全一致。

**证明**：由引理 1，两侧的值由各自的 \((coef, const)\) 唯一刻画，扫描没有信息损失；由引理 2，原方程与 \(ax=b\) 同解；由引理 3，按 \((a,b)\) 的三类取值分类完备且互斥，而代码的三个分支一一对应，输出串与题面规定一致。唯一解分支上题面保证解为整数，整除校验必然通过。∎

## 6. 复杂度分析

- **时间**：\(O(n)\)，其中 \(n = \lvert \text{equation} \rvert\)。`left` 与 `right` 两段合起来被扫描一次，每个字符只做常数次判断与整数运算；合并与分类是 \(O(1)\)。\(n \le 1000\)，实际运行在微秒级。
- **空间**：\(O(1)\) 额外空间（除输入串本身）。C++ 中 `substr` 会额外拷贝两段 \(O(n)\) 的字符串；若要严格 \(O(1)\)，可在原串上用双指针区间遍历，或直接把 `'='` 当作"切换目标累加器"的哨兵扫一遍。
- **数值范围**：每侧至多约 250 项（每项至少 2 个字符），系数上界 \(100 \times 250 = 2.5\times 10^4\)，常数项同量级，`int` 足够。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <utility>
#include <cctype>
using namespace std;

class Solution {
public:
    string solveEquation(string equation) {
        // 把一段表达式压成 (x 的系数, 常数项)
        auto parse = [](const string& e) {
            int coef = 0, cons = 0, sign = 1;
            size_t i = 0, n = e.size();
            while (i < n) {
                if (e[i] == '+' || e[i] == '-') {
                    sign = (e[i] == '+') ? 1 : -1;
                    ++i;
                    continue;
                }
                int num = 0; bool hasNum = false;
                while (i < n && isdigit((unsigned char)e[i])) {
                    num = num * 10 + (e[i] - '0');
                    hasNum = true;
                    ++i;
                }
                if (i < n && e[i] == 'x') {           // 该项是系数项
                    coef += sign * (hasNum ? num : 1);
                    ++i;
                } else {                              // 该项是常数项
                    cons += sign * num;
                }
            }
            return make_pair(coef, cons);
        };

        size_t eq = equation.find('=');
        auto left = parse(equation.substr(0, eq));
        auto right = parse(equation.substr(eq + 1));
        int a = left.first - right.first;             // x 集中到左边
        int b = right.second - left.second;           // 常数集中到右边
        if (a == 0) return b == 0 ? "Infinite solutions" : "No solution";
        if (b % a != 0) return "No solution";         // 题面保证不会触发，兜底
        return "x=" + to_string(b / a);
    }
};
```

### Python

```python
class Solution:
    def solveEquation(self, equation: str) -> str:
        def parse(expr: str):
            coef = const = 0
            sign, i, n = 1, 0, len(expr)
            while i < n:
                if expr[i] in '+-':
                    sign = 1 if expr[i] == '+' else -1
                    i += 1
                    continue
                num, has_num = 0, False
                while i < n and expr[i].isdigit():
                    num = num * 10 + int(expr[i])
                    has_num = True
                    i += 1
                if i < n and expr[i] == 'x':
                    coef += sign * (num if has_num else 1)   # 'x' 的系数是 1
                    i += 1
                else:
                    const += sign * num
            return coef, const

        left, right = equation.split('=')
        (a1, b1), (a2, b2) = parse(left), parse(right)
        a, b = a1 - a2, b2 - b1          # 移项：x 在左，常数在右
        if a == 0:
            return "Infinite solutions" if b == 0 else "No solution"
        if b % a != 0:
            return "No solution"         # 题面保证唯一解为整数，兜底
        return "x=" + str(b // a)        # 负数直接用 // 会向下取整，故先排除余数
```

## 8. 边界情况与易错点

1. **无限多解**：`"x=x"`、`"0x=0"`、`"x+0=0"` 都得 \((a,b) = (0,0)\)，返回 `"Infinite solutions"`。注意 `"0x=0"` 里 `0x` 的系数确实是 0，不能被误判成 `x`（系数 1）。
2. **无解**：`"0x+1=2"` 得 \(a=0,\ b=1\)，返回 `"No solution"`；不要因为"解不出来"就返回空串或 `"x=0"`。
3. **解恰好是 0**：`"2x=x"` → \(x=0\)，输出 `"x=0"`。不要把 0 当作"没有解"的哨兵。
4. **负解**：`"2x=x-3"` → \(x=-3\)，输出 `"x=-3"`。拼接时不要额外写 `+`，也不要让 `-0` 出现。
5. **双重取负**：`"-x=-2"` → 两侧各是 \((-1,0)\) 与 \((0,-2)\)，得 \(-1 \cdot x = -2\)，即 \(x=2\)；符号只要按上面规则逐项累加就不会错。
6. **系数省略**：`"x"` 的系数省略等于 1，`"-x"` 等于 \(-1\)，只有 `hasNum` 为假时才取 1——这是本题最容易写错的一行。
7. **输出格式严格**：必须是 `x=2` 这种形式，不能有空格、不能写 `x=+2`、大小写也要与 `"No solution"` / `"Infinite solutions"` 完全一致（判题是字符串比对）。
8. **Python 的 `//`**：对负数向下取整（`-3 // 2 == -2`），因此必须先用 `b % a != 0` 挡掉非整除的情况，再放心用 `//`。

**延伸思考**：

1. 若题面不再保证唯一解是整数，答案应返回 `"x=p/q"`（约分后）还是 `"No solution"`？此时把整型换成 `Fraction` / `__gcd` 约分即可，分类逻辑（引理 3）完全不变——**归约把"解析"和"求解"彻底解耦**，这正是它比"枚举代入"更值钱的地方。

3. 一次方程的解集只有"空 / 单点 / 全体"三种，正是引理 3 的三个分支；把这一分类推广到二次方程就是判别式符号讨论——结构上仍是"先归约、再按系数分类"。
