# LeetCode 大礼包 题解

## 1. 题目概述

- **标题 / 题号**：大礼包（#638，medium）
- **链接**：https://leetcode.cn/problems/shopping-offers/
- **来源**：LeetCode 第 40 场周赛 Q3
- **难度**：中等
- **标签**：位运算、记忆化搜索、数组、动态规划、回溯、状态压缩、背包问题、完全背包

**题意**：商店有 $n$ 种物品，第 $i$ 种单买价格 $price[i]$；另有若干大礼包 $special[k]$，前 $n$ 个数是礼包内各种物品的件数，最后一个数是整包售价。购物清单 $needs[i]$ 要求第 $i$ 种物品**恰好**买 $needs[i]$ 件。礼包可以买任意多次，也可以一个都不买，但**不允许买超**清单上的数量（哪怕买超更便宜）。求恰好凑齐清单的最低总花费。

**约束**：

- $n = price.length = needs.length$，且 $1 \le n \le 6$
- $0 \le price[i] \le 10$，$0 \le needs[i] \le 10$
- $1 \le special.length \le 100$，$special[i].length = n+1$，$0 \le special[i][j] \le 50$
- 每个礼包至少有一件物品的件数非零

## 2. 示例

**示例 1**

```text
输入：price = [2,5], special = [[3,0,5],[1,2,10]], needs = [3,2]
输出：14
解释：单买 3A + 2B 要 3×2 + 2×5 = 16；
      ¥10 买礼包 2（1A + 2B）后再 ¥4 单买 2 个 A，合计 14；
      ¥5 买礼包 1（3A）后只剩 2 个 B，合计 5 + 10 = 15。取 14。
```

**示例 2**

```text
输入：price = [2,3,4], special = [[1,1,0,4],[2,2,1,9]], needs = [1,2,1]
输出：11
解释：礼包 2（2A+2B+1C）只要 ¥9，比单买 1A+2B+1C 的 ¥12 还便宜，但它含 2 个 A 而清单只要 1 个 A，
      超量购买不被允许，因此只能 ¥4 买礼包 1（1A+1B），再 ¥3 单买 1 个 B、¥4 单买 1 个 C。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举「每个礼包买几份」。第 $k$ 个礼包最多能买 $\min_{i:\,special[k][i]>0}\bigl\lfloor needs[i]/special[k][i]\bigr\rfloor$ 份，于是方案数是

$$\prod_{k}\Bigl(1 + \min_i \bigl\lfloor \tfrac{needs[i]}{special[k][i]} \bigr\rfloor\Bigr)$$

礼包最多 100 个、每个最多 10 份，这个数达到 $11^{100}$ 量级，完全不可枚举。另一条思路是把「已买件数」压成一维做完全背包，但礼包是**打包捆绑**的：买了 5 件不等于买到了清单要的那 5 件，一维状态会丢失「买了哪些种类」的信息，答案会错。

### 3.2 核心观察：需求向量就是完整状态

![需求向量的状态模型](images/wc40_q3_state_vector_concept.svg)

关键事实只有一句：**之后还能怎么买，只取决于「每种物品还差多少」，与「已经买过什么、按什么顺序买」完全无关**。因为礼包之间没有先后约束，整包价格也不随组合变化，所以把「还剩多少」记为向量 $r$，就能把整个搜索空间压成一张以向量为结点的图。

由此得到三个直接推论：

1. 状态是 $n$ 维向量 $r$，$0 \le r_i \le needs[i]$，状态总数不超过 $\prod_i (needs[i]+1) \le 11^6 \approx 1.8\times10^6$；
2. 不同的购买顺序会走到同一个 $r$，这是**重复子问题**，用记忆化把它们合并；
3. 「剩余需求全部单买」永远合法，因此每个状态都有一个天然上界兜底值，搜索不需要处理「凑不出来」的情况。

再补一条无损剪枝：若某个礼包的价格 $c_k \ge \sum_i s_{k,i}\cdot price[i]$，把它拆成单买同样满足清单且不更贵，所以这种礼包可以从候选里删掉，只留下「真正便宜」的礼包。

### 3.3 算法流程与状态转移

![带记忆化的 DFS 流程](images/wc40_q3_dfs_memo_flow.svg)

设 $f(r)$ 为恰好凑齐剩余需求 $r$ 的最低花费，$s_k$ 为第 $k$ 个礼包的物品向量，$c_k$ 为其价格，$s_k \le r$ 表示逐维不超过。则

$$f(r)=\min\Bigl(\ \underbrace{\sum_{i} r_i\cdot price[i]}_{\text{全部单买兜底}},\ \ \min_{k:\ s_k \le r}\bigl(c_k + f(r - s_k)\bigr)\Bigr)$$

边界 $f(\mathbf{0}) = 0$，答案即 $f(needs)$。实现上是自顶向下的记忆化搜索：

1. 若 $r$ 已在 `memo` 中，直接返回；
2. 令 $best \leftarrow \sum_i r_i \cdot price[i]$（单买兜底）；
3. 对每个剪枝后的礼包 $k$：逐维算 $r - s_k$，只要出现负数就跳过；否则 $best \leftarrow \min(best,\ c_k + f(r-s_k))$；
4. 把 $best$ 写入 `memo[r]` 并返回。

### 3.4 示例演算

![示例 1 的搜索与比较](images/wc40_q3_example_walkthrough.svg)

对示例 1（$price=[2,5]$，礼包 $[3,0,5]$、$[1,2,10]$，$needs=[3,2]$），根状态只有三种选择：

| 选择 | 剩余向量 $r'$ | 子问题最优 $f(r')$ | 总价 |
|------|---------------|--------------------|------|
| 全部单买 | — | — | $3\times2+2\times5 = 16$ |
| 礼包 1（¥5） | $(0,2)$ | $2\times5 = 10$（两个礼包都超量） | $5+10 = 15$ |
| 礼包 2（¥10） | $(2,0)$ | $2\times2 = 4$（两个礼包都超量） | $10+4 = 14$ |

于是 $f(3,2)=\min(16,15,14)=14$。注意这里**不能贪心**：礼包 1 的折扣率看起来更猛（¥5 换 ¥6 的货），但它的物品结构与清单不匹配，真正最优的是礼包 2。

## 4. 算法细节

1. **先剪枝再搜索**：遍历 $special$ 时，只要 $c_k \ge \sum_i s_{k,i}\cdot price[i]$ 就丢弃。判断用严格小于 —— 价格相等时留着也不算错，但纯属浪费；剪枝后还顺带保证每个保留礼包至少含一件物品，为终止性提供依据。
2. **状态表示**：Python 用 `tuple`（`list` 不可哈希，必须先转），C++ 用 11 进制编码成 `int`（$needs[i] \le 10$，所以底数必须取 11 及以上），既省内存又比 `map<vector<int>,int>` 快一个量级。
3. **兜底值初始化**：`best` 从「全部单买」开始而不是从 `INT_MAX` 开始，这样天然覆盖了「一个礼包都不买」，也避免了「所有礼包都超量」时忘记更新导致返回无穷大。
4. **超量检查要逐维做**：`nxt[i] = cur[i] - sp[i]`，任一维为负立即 `break`，不能只比较总件数 —— 示例 2 里礼包 2 总件数 5 不小于清单的 4，但 A 维超了，仍然非法。
5. **写入时机**：`memo[r] = best` 必须放在「遍历完所有礼包之后」，写入的值是完整算好的 $f(r)$；如果中途写入，别的路径可能读到半成品。
6. **复用临时数组**：C++ 版本把 `nxt` 声明在循环外复用，避免每层每包都分配一次 `vector`；这不是必需优化，但在状态多时能减少常数。
7. **递归深度有硬上界**：每进入一层，剩余总件数至少减少 1，因此深度不超过 $\sum_i needs[i] \le 60$，不会爆栈，也不需要显式改写成迭代。
8. **不要为了「用上礼包」而破坏恰好约束**：题目要求恰好满足，多买一律非法；也就不存在「先买超再退」之类的操作，状态只能单调下降。

## 5. 正确性证明

**引理 1（折扣剪枝无损）**：若礼包 $k$ 满足 $c_k \ge \sum_i s_{k,i}\cdot price[i]$，则对任意剩余需求 $r$，存在一个不购买礼包 $k$ 的最优方案。

**证明**：任取 $r$ 的一个可行方案 $T$，设其中礼包 $k$ 出现 $t \ge 1$ 次。把每份礼包 $k$ 替换为对各物品单买 $s_{k,i}$ 件：原方案合法说明 $t\cdot s_{k,i} \le r_i$，替换后仍然不超量；替换带来的花费是 $t\sum_i s_{k,i}\cdot price[i] \le t\,c_k$ 不超过原来，故 $T$ 可改成不含 $k$、价格不增的方案。反复替换即得结论。∎

**引理 2（最优子结构）**：设 $K'$ 为剪枝后保留的礼包集合，则对任意 $r$，

$$f(r)=\min\Bigl(\sum_i r_i\cdot price[i],\ \min_{k\in K',\ s_k\le r}\bigl(c_k+f(r-s_k)\bigr)\Bigr)$$

**证明**：记右端为 $V$。由引理 1，存在只使用 $K'$ 中礼包的最优方案。

- $f(r) \le V$：右端的两类候选都对应 $r$ 的真实可行方案 —— 全单买显然可行；对每个满足 $s_k \le r$ 的 $k$，把一份礼包 $k$ 与 $r-s_k$ 的最优方案拼起来，件数上界恰为 $r$，故可行，价格正是 $c_k + f(r-s_k)$。所以最小值 $f(r)$ 不超过这些价格，即 $f(r)\le V$。
- $f(r) \ge V$：设 $T$ 为最优方案。若 $T$ 不含礼包，则花费为 $\sum_i r_i\cdot price[i] \ge V$。否则取 $T$ 中的一份礼包 $k$，删去它后剩下的部分恰是 $r-s_k$ 的可行方案，其花费 $\ge f(r-s_k)$，于是 $T$ 的花费 $\ge c_k + f(r-s_k) \ge V$。∎

**引理 3（终止性与无环性）**：$K'$ 中每个礼包都至少含一件物品，因此每一步递归都让 $\sum_i r_i$ 严格下降，递归深度不超过 $\sum_i needs[i]\le 60$，状态图无环。

**证明**：$k \in K'$ 意味着 $c_k < \sum_i s_{k,i}\cdot price[i]$ 且 $c_k \ge 0$，故右端正数，存在某个 $i$ 使 $s_{k,i}\cdot price[i] > 0$，从而 $s_{k,i} > 0$、$s_k \ne \mathbf{0}$。转移后 $\sum_i (r-s_k)_i = \sum_i r_i - \sum_i s_{k,i} < \sum_i r_i$，单调下降的量不可能形成环，深度受 $\sum_i needs[i]$ 限制。∎

**定理**：`dfs(needs)` 返回最低总花费 $f(needs)$。

**证明**：对 $t=\sum_i r_i$ 作归纳。$t=0$ 时基准值为 $0=f(\mathbf 0)$。设所有 $t'<t$ 的状态都正确。`dfs(r)` 先取单买价、再枚举所有满足 $s_k \le r$ 的 $k$ 并递归；由引理 3 每个 $r-s_k$ 的总件数严格小于 $t$，归纳假设保证递归返回的正是 $f(r-s_k)$；因此 `dfs(r)` 计算的恰是引理 2 右端的最小值，等于 $f(r)$。记忆化只是把已算好的 $f(r)$ 缓存复用，不改变任何值。∎

## 6. 复杂度分析

- **时间**：$O(S \cdot m' \cdot n)$。其中 $S$ 为从初始需求可达的状态数，$S \le \prod_i (needs[i]+1) \le 11^6 \approx 1.8\times 10^6$；$m'$ 为剪枝后保留的礼包数（$\le 100$）；每状态对每个礼包做 $O(n)$ 的向量减法。剪枝前的 $O(m\cdot n)$ 预处理可忽略。
- **空间**：$O(S\cdot n)$ 用于 `memo`（Python 的 key 是长度 $n$ 的元组，C++ 只存一个 `int` 编码，实际是 $O(S)$），另有 $O(\sum_i needs[i])$ 的递归栈（$\le 60$ 层）与 $O(n)$ 的临时向量。
- **实际表现**：官方数据远达不到上界。实测 $n=6$、$needs$ 全为 10、10 个互相不可替代的礼包时，Python 版约 0.26 s；常规用例在毫秒级。若遇到刻意构造的「上百个互不支配的小礼包 + 满需求」数据，可再加一层支配剪枝（见延伸思考）把 $m'$ 压小。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    int shoppingOffers(vector<int>& price, vector<vector<int>>& special, vector<int>& needs) {
        n_ = price.size();
        price_ = price;
        offers_.clear();
        for (auto& sp : special) {
            int cost = sp[n_], single = 0;
            for (int i = 0; i < n_; i++) single += sp[i] * price[i];
            if (cost < single) offers_.push_back(sp);   // 只保留真正便宜的礼包
        }
        memo_.clear();
        return dfs(needs);
    }

private:
    int n_;
    vector<int> price_;
    vector<vector<int>> offers_;
    unordered_map<int, int> memo_;

    int encode(const vector<int>& v) {
        int code = 0;
        for (int x : v) code = code * 11 + x;    // needs[i] <= 10，用 11 进制
        return code;
    }

    int dfs(const vector<int>& cur) {
        int code = encode(cur);
        auto it = memo_.find(code);
        if (it != memo_.end()) return it->second;

        int best = 0;
        for (int i = 0; i < n_; i++) best += cur[i] * price_[i];   // 兜底：全部单买

        vector<int> nxt(n_);
        for (auto& sp : offers_) {
            bool ok = true;
            for (int i = 0; i < n_; i++) {
                nxt[i] = cur[i] - sp[i];
                if (nxt[i] < 0) { ok = false; break; }   // 任一维超量即非法
            }
            if (ok) best = min(best, sp[n_] + dfs(nxt));
        }
        memo_[code] = best;      // 全部候选算完后才落表
        return best;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def shoppingOffers(self, price: List[int], special: List[List[int]], needs: List[int]) -> int:
        n = len(price)
        offers = []
        for sp in special:
            items, cost = sp[:n], sp[n]
            single = sum(items[i] * price[i] for i in range(n))
            if cost < single:                 # 只保留真正便宜的礼包
                offers.append((items, cost))

        memo = {}

        def dfs(cur):
            if cur in memo:
                return memo[cur]
            best = sum(cur[i] * price[i] for i in range(n))   # 兜底：全部单买
            for items, cost in offers:
                nxt = tuple(cur[i] - items[i] for i in range(n))
                if min(nxt) >= 0:             # 逐维检查，不许超量
                    cand = cost + dfs(nxt)
                    if cand < best:
                        best = cand
            memo[cur] = best                  # 全部候选算完后才落表
            return best

        return dfs(tuple(needs))               # list 不可哈希，先转 tuple
```

## 8. 边界情况与易错点

1. **清单为空**：$needs$ 全为 0 时基准和为 0，任何礼包都超量，返回 0，不需要特判。
2. **价格为 0**：若所有 $price[i]=0$，单买总价恒为 0，全部礼包因 $c_k \ge 0$ 被剪掉，答案 0，正确（花费不可能为负）。若只有部分物品免费，剪枝仍按完整单买价比较，被删礼包确实可用等价单买替换，不会误删。
3. **超量陷阱**：示例 2 的 ¥9 礼包是本场最常见的错误来源，必须逐维比较 $s_k \le r$，只比总件数就会错答成 9。
4. **进制选错会撞码**：$needs[i]$ 上限是 10，编码底数必须 $\ge 11$；用 10 进制会把 $(1,0)$ 与 $(0,10)$ 之类的不同状态映射到同一个 key。
5. **元组与列表**：Python 里 `list` 不可哈希，`memo` 的 key 必须是 `tuple`；忘记转换会直接抛 `TypeError`。
6. **礼包在部分维度为 0 不代表可以跳过检查**：某些礼包在某几维上是 0（如 $[3,0,5]$ 不含 B），它仍然计价，并且必然不改变 B 维的剩余量；按统一公式做逐维减法即可，不要为这类礼包写特殊分支。
7. **别忘了「不买礼包」也是解**：所有礼包都被剪掉或都超量时，答案就是单买总价；把 `best` 初始化为 `INT_MAX` 又漏掉单买项，就会返回错误的大数。
8. **重复礼包**：输入里可能出现完全相同的礼包，或一个礼包被另一个支配；这不影响正确性，只是浪费常数，可用支配剪枝去掉。

**延伸思考**：

1. **支配剪枝**：若存在另一个礼包 $k'$ 满足 $s_{k'} \le s_k$ 且 $c_{k'} \le c_k$（至少一处严格），则 $k$ 永远不会被选，可删去。它不改变状态数 $S$，但把每状态的候选数 $m'$ 压小，实现只需 $O(m^2 n)$ 的预处理。
2. **查询多个清单**：若要在同一组 $price/special$ 上回答 $10^5$ 个不同清单，记忆化搜索就不划算了；可以把状态按 $\sum_i r_i$ 分层做自底向上 DP，或对每个清单单独跑一次（状态少时反而更快）。
3. **允许买超**：如果改成「至少满足清单」，则超量部分可以丢弃，状态需要额外记录「已超量」的维度集合，问题会复杂不少。
4. **礼包可拆分**：若礼包能按比例拆开买，问题退化为线性规划，最优解必然只用一个「性价比最高」的礼包组合，与本题的整数约束有本质差异。
