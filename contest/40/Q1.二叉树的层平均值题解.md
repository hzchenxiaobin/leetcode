# LeetCode 二叉树的层平均值 题解

## 1. 题目概述

- **标题 / 题号**：二叉树的层平均值（#637，easy）
- **链接**：https://leetcode.cn/problems/average-of-levels-in-binary-tree/
- **来源**：LeetCode 第 40 场周赛 Q1
- **难度**：简单
- **标签**：树、深度优先搜索、广度优先搜索、二叉树

**题意**：给定一棵**非空**二叉树的根节点 `root`，根位于第 $0$ 层。返回一个浮点数组，第 $d$ 项是第 $d$ 层所有节点值的**算术平均**，即

$$avg_d = \frac{1}{\lvert L_d \rvert}\sum_{u \in L_d} u$$

答案与真实值相差 $10^{-5}$ 以内即被接受。

**约束**：

- 节点数在 $[1, 10^4]$ 之间
- $-2^{31} \le Node.val \le 2^{31} - 1$

> 💡 **审题关键**：这题的字面陷阱全在三个词上。(1) **每一层**——不是全树平均，分母随层变化；(2) **平均值**——分母是该层**节点个数**，不是树的节点总数 $n$；以示例 2 为例，全树平均是 $30/5 = 6$，而答案的第三项是 $22/2 = 11$，两者毫无关系。(3) **容差 $10^{-5}$**——只要求浮点精度，不要把结果四舍五入成固定小数位后再提交（那样反而可能引入误差）。签到的正确姿势是：确认"按层分组"这个唯一难点，然后直接写 BFS。

## 2. 示例

**示例 1**

```text
输入：root = [3,9,20,null,null,15,7]
输出：[3.00000,14.50000,11.00000]
解释：第 0 层 [3]        → 3 / 1  = 3
      第 1 层 [9, 20]    → 29 / 2 = 14.5
      第 2 层 [15, 7]    → 22 / 2 = 11
```

**示例 2**

```text
输入：root = [3,9,20,15,7]
输出：[3.00000,14.50000,11.00000]
解释：树形状与示例 1 不同（9 有了两个孩子、20 没有），
      但"哪些节点在同一层"完全相同，故平均值数组完全相同。
```

**补充示例（边界自测用）**

```text
输入：root = [5]
输出：[5.00000]
解释：单节点树，只有第 0 层。

输入：root = [2147483647,2147483647,2147483647]
输出：[2147483647.00000,2147483647.00000]
解释：节点值取 int 上界，验证求和是否溢出（3 × (2^31−1) 已超 int）。
```

## 3. 解题思路

### 3.1 暴力思路

"按层"这个要求，最朴素的两种落地方式都不够干净：

- **按深度扫全树**：先求树高 $h$，再对每个深度 $d$ 从头 DFS 一遍，只收集深度为 $d$ 的节点。每个节点被访问 $h$ 次，总代价 $O(nh)$；链状树 $h = n = 10^4$，退化成 $10^8$ 次访问，白白浪费。
- **按深度存整层**：用 `map<int, vector<int>>` 把每个节点塞进自己那一层，最后逐层求平均。每节点只访问一次，但为了求一个平均值就存下整层所有值，空间从 $O(w)$ 膨胀到 $O(n)$（$w$ 为最宽层）。

两种写法都错在同一个地方：**它们把"分层"当成需要额外记录的信息**。而在 BFS 里，分层根本不用记——队列的位置本身就把层切好了。

### 3.2 核心观察：BFS 的队列天然按层分段

![核心观察：队列天然按层分段，每层只要和与个数](images/wc40_q1_level_model.svg)

三个环环相扣的观察：

- **观察 1（队列里最多两层的深度）**：BFS 按"到根的边数"递增扩展。任何时刻队列中的节点深度只有 $d$ 与 $d+1$ 两种，且所有深度 $d$ 的节点都排在深度 $d+1$ 的节点**之前**——队列被一个分界点切成两段。
- **观察 2（快照定界）**：本轮开始时队列里只有第 $d$ 层，长度 `size` 就是该层的节点数。弹掉 `size` 个之后，队首恰好越过第 $d$ 层，剩下的全是第 $d+1$ 层。于是"层宽"不需要预先知道，它在每轮开头被**读一次**就够了。
- **观察 3（只需两个量）**：求平均值只需该层的**和**与**个数**，不需要保存该层的任何节点值。个数就是 `size`，和在内层循环里累加。

> 💡 观察 3 还有一个隐含好处：**加法可交换**，所以同一层内先左后右、先右后左都不影响结果。这也是示例 1 与示例 2 形状不同却答案相同的原因——答案只取决于"哪些节点落在同一层"，与树的局部形态无关。

### 3.3 算法流程

![算法流程：外层按层、内层弹 size 个](images/wc40_q1_bfs_flow.svg)

1. `ans = []`，队列 `q = [root]`；
2. 当 `q` 非空时循环：
   - 取快照 `size = |q|`，令 `sum = 0`；
   - **重复 `size` 次**：出队一个节点 `p`，`sum += p.val`，把 `p` 的非空左右孩子依次入队；
   - 把 `sum / size` 追加到 `ans`；
3. 返回 `ans`。

**为什么 `size` 必须先存成变量**：内层循环的终止条件是"本层弹完了"，而这个信息只存在于快照里。看着下面的队列演化就更清楚：

![为什么要快照 size：队列里同时躺着两层](images/wc40_q1_queue_snapshot.svg)

第 2 轮中途，队列是 $\langle 20 \mid 15, 7\rangle$——左边蓝格 `20` 属于本层，右边橙格 `15`、`7` 已经属于下一层。此刻若去问"队列还有几个元素"，答案是 $3$，而本层只剩 $1$ 个还没处理。在 C++ 里把循环条件写成 `for (int i = 0; i < q.size(); i++)` 就会踩这个坑：队列一边弹一边长，`q.size()` 每轮重算，`size` 的门槛被不断推高，几乎可以无限循环下去。**正确写法是先 `int size = q.size();`，再用 `i < size`。**

**等价的 DFS 写法**（同样 $O(n)$，不需要预先求树高）：递归时把深度当参数传下去，`sums[depth] += val`、`cnts[depth] += 1`，最后逐层相除。它与 BFS 的差别只是"层号从哪来"：BFS 的层号是**循环轮次**，DFS 的层号是**递归参数**。本题选 BFS 的实际理由有二：其一不用递归，链状树（深度可达 $10^4$）不会撞上 Python 默认 $1000$ 的递归深度上限；其二不需要按深度开桶，天然适配"不知道树有多高"的输入。

### 3.4 示例演算

![示例演算：root = [3,9,20,15,7]](images/wc40_q1_example_walkthrough.svg)

对示例 2 的 `root = [3,9,20,15,7]` 走一遍：

| 轮次 | 队列快照 $q$ | 本轮弹出 | `sum` | `size` | `sum / size` |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 1 | $\langle 3 \rangle$ | 3 | 3 | 1 | 3.00 |
| 2 | $\langle 9, 20 \rangle$ | 9，20 | 29 | 2 | 14.50 |
| 3 | $\langle 15, 7 \rangle$ | 15，7 | 22 | 2 | 11.00 |
| 4 | $\langle \ \rangle$ | — | — | — | 结束 |

第 1 轮弹出 `3` 时把 `9`、`20` 入队，它们正好构成第 2 轮的队列；第 2 轮弹出 `9` 时把 `15`、`7` 入队，但它们**要等到第 3 轮**才被弹出——这正是 `size` 快照在保护的东西。第 4 轮队列为空，循环退出，答案 `[3.00, 14.50, 11.00]`。

## 4. 算法细节

1. **快照 `size`**：每轮开头读一次队列长度，内层循环用它计数，绝不在循环条件里重新求队列长度。这是本题唯一的实现陷阱。
2. **`sum` 用 64 位**：最坏情况一层有 $10^4$ 个节点、每个取 $2^{31}-1$，和约 $2.1 \times 10^{13}$，远超 `int` 上限 $2.1\times10^9$。C++ 必须 `long long`；Python 大整数天然无虞。
3. **先转 `double` 再除**：C++ 写 `(double)sum / size`，写成 `sum / size` 会做整数除法被截断（示例 2 的 $29/2$ 会变成 $14$）。Python 的 `/` 恒为真除法，无需转换，但别误用 `//`。
4. **入队前判空**：只把非空的左右孩子入队。若把 `nullptr` 也塞进队列，`size` 会统计进空节点，平均值分母偏大。
5. **队列选型**：C++ 用 `std::queue<TreeNode*>`（或 `deque`）；Python 用 `collections.deque`，**不要用 `list`**——`list.pop(0)` 是 $O(n)$，整体会退化到 $O(n^2)$。
6. **不需要树高**：BFS 层号由轮次隐式给出，省掉一次求高度的遍历；`ans.reserve()` 可以不写，`vector` 的均摊追加足够快。
7. **负值照常处理**：节点值可为负，层平均值也可为负。用 `0` 初始化 `sum` 是对的，但不要用"`sum > 0` 才有意义"之类的哨兵判断。

## 5. 正确性证明

**引理 1（分层不变量）**：每轮循环开始时，队列恰按从左到右的顺序存放第 $d$ 层的全部节点，不含其他层的节点。

**证明**：对轮次 $d$ 归纳。$d = 0$ 时队列为 `[root]`，即 $L_0$ 全体，成立。设第 $d$ 轮开始时队列恰为 $L_d$（从左到右），则快照 `size = |L_d|`，内层循环恰好把 $L_d$ 的全部节点各弹出一次，队列被清空；同时每个被弹出的节点把自己的非空孩子入队。由二叉树的定义，$L_{d+1}$ 恰为 $L_d$ 中所有节点的非空孩子之集合，且按"父节点从左到右、每父节点先左后右"入队，故入队顺序正是 $L_{d+1}$ 从左到右的顺序。于是第 $d+1$ 轮开始时队列为 $L_{d+1}$。∎

**引理 2（求和与求平均正确）**：第 $d$ 轮内层循环结束后，`sum` $= \sum_{u \in L_d} u$，`size` $= \lvert L_d \rvert$，因此该轮追加的 `sum / size` 恰为 $avg_d$。

**证明**：由引理 1，内层循环弹出的正是 $L_d$ 的每个节点且各一次，故 `sum` 累加 $L_d$ 全体节点值；`size` 在弹出**之前**取值为 $\lvert q \rvert = \lvert L_d \rvert$，且浮点除法得到算术平均。∎

**定理**：算法返回的数组长度为树高 $h$，且第 $d$ 项等于第 $d$ 层节点值的平均值。

**证明**：设树高为 $h$（最深节点在第 $h-1$ 层）。由引理 1 归纳可得，第 $h$ 层满足 $L_h = \varnothing$，故第 $h$ 轮开始时队列为空、循环终止，共执行 $h$ 轮，返回数组长度恰为 $h$。由引理 2，第 $d$ 项为 $avg_d$。故结论成立。∎

**推论**：答案与同层节点的处理顺序、与树的整体形状均无关，只由"哪些节点位于同一层"决定——这解释了示例 1 与示例 2 输出相同。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。外层循环执行 $h$ 轮，内层循环总共执行 $n$ 次；每个节点入队一次、出队一次，每次 $O(1)$（`std::queue` 与 `deque.popleft` 都是均摊 $O(1)$）。合计 $O(n + h) = O(n)$。相比 $O(nh)$ 的"按深度扫全树"，省掉的正是"每个节点被重复访问 $h$ 次"这一项浪费。
- **空间复杂度**：$O(w)$，$w$ 为最宽层的节点数（$w \le n$）。队列中同时存在的节点数不超过 $\lvert L_d \rvert + \lvert L_{d+1} \rvert \le 2w$；递归 DFS 的等价写法则是 $O(h)$ 的栈深。返回数组占用 $O(h)$，通常单独计入返回值而不算辅助空间。相较"按深度存整层"的 $O(n)$，BFS 只花 $O(w)$。

## 7. 参考代码

### C++

```cpp
#include <queue>
#include <vector>

struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *l, TreeNode *r) : val(x), left(l), right(r) {}
};

class Solution {
  public:
    vector<double> averageOfLevels(TreeNode *root) {
        vector<double> ans;
        if (!root) return ans;              // 题目保证非空，防御性保留

        queue<TreeNode *> q;
        q.push(root);
        while (!q.empty()) {
            int size = q.size();            // 关键：先快照层宽，循环条件只认它
            long long sum = 0;              // 最坏 1e4 * (2^31-1) ≈ 2.1e13，必须 64 位
            for (int i = 0; i < size; i++) {
                TreeNode *cur = q.front();
                q.pop();
                sum += cur->val;
                if (cur->left) q.push(cur->left);    // 只入队非空孩子
                if (cur->right) q.push(cur->right);
            }
            ans.push_back((double)sum / size);       // 先转 double 再除，避免截断
        }
        return ans;
    }
};
```

### Python

```python
from collections import deque
from typing import List, Optional


class TreeNode:
    def __init__(self, val=0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Solution:
    def averageOfLevels(self, root: Optional[TreeNode]) -> List[float]:
        ans = []
        q = deque([root])            # 用 deque：list.pop(0) 是 O(n)
        while q:
            size = len(q)            # 关键：先快照层宽
            total = 0
            for _ in range(size):    # range(size) 在进入循环时就固定了
                node = q.popleft()
                total += node.val    # Python 整数无溢出
                if node.left:
                    q.append(node.left)
                if node.right:
                    q.append(node.right)
            ans.append(total / size)  # "/" 是真除法，得到 float
        return ans
```

## 8. 边界情况与易错点

1. **`sum` 溢出**：最坏 $10^4$ 个节点取 $2^{31}-1$，层和约 $2.1\times10^{13}$，`int` 直接溢出成负数。C++ 用 `long long`（单个值虽然装得下 `int`，但同一层只要累加 2 个 $2^{31}-1$ 就溢出），Python 无此问题。
2. **`size` 实时求值**：`for (int i = 0; i < q.size(); i++)` 是经典错误——队列边弹边长，`q.size()` 每轮重算，子节点被算进本层，层宽错乱甚至死循环。必须先 `int size = q.size();`。
3. **除数错位**：若在循环**结束后**才用 `q.size()` 当除数，最后一层会变成除以 $0$（此时队列已空）；即便不崩，除数也已经是下一层的宽度。除数永远是快照 `size`。
4. **整型除法**：`sum / size` 两边都是整数时结果被截断（$29/2 \to 14$），必须 `(double)sum / size`。Python 里与之对应的是误写 `//`。
5. **单节点树**：`root = [5]` → 返回 `[5.0]`；`size = 1` 时内层循环跑一次、队列变空、下一轮退出，不会多出空层。
6. **深链爆栈**：链状树深度可达 $10^4$，Python 递归默认上限 $1000$，递归版 DFS 会 `RecursionError`；BFS 是迭代的，天然免疫。若要写 DFS，需 `sys.setrecursionlimit` 或改显式栈。
7. **负值层**：节点值可为负，层平均值也可为负（如 $[-1,-2]$ → $-1.5$）。不要假设"平均值 ≥ 0"来做剪枝或初始化。
8. **不要手动四舍五入**：题目按 $10^{-5}$ 误差判等，直接输出 `double`/`float` 即可；用 `printf("%.5f")` 之类格式化成字符串再转回反而多此一举（若确实要格式化，注意别丢精度到 $10^{-5}$ 以下）。

**延伸思考**：

- **换成每层最大/最小值**：把 `sum` 换成 `mx` 即可，结构与本题完全同构，$O(n)$ 不变。
- **换成每层中位数**：必须保存整层才能求中位数，空间回到 $O(w)$ 且需要排序（$O(w\log w)$ 每层）；BFS 仍然是自然的选择，因为层边界最重要。
- **换成每层方差**：需要 $S_1 = \sum u$ 与 $S_2 = \sum u^2$。注意 $S_2$ 的量级是 $10^4 \times (2^{31})^2 \approx 4.6\times10^{22}$，**远超 `long long` 上限 $9.2\times10^{18}$**，必须用 `double`（或 `__int128` 后转浮点）。这是本题"和要 64 位"的加强版陷阱：平方再求和，位数需求翻倍还多。
- **在线数据流版本**：若节点值逐层"流入"而无法同时入队，可用 Welford 增量法维护均值与方差，边读边更新，空间 $O(1)$。
