# LeetCode 统计整数数目 题解

## 1. 题目概述

- **标题 / 题号**：统计整数数目（#2719，hard）
- **链接**：https://leetcode.cn/problems/count-of-integers/
- **来源**：LeetCode 第 348 场周赛 Q4
- **难度**：困难
- **标签**：数位 DP、动态规划、字符串、数学

**题意**：给定两个**数字字符串** `num1`、`num2` 与两个整数 `min_sum`、`max_sum`。整数 $x$ 是**好整数**当且仅当：

- $num1 \le x \le num2$；
- $min\_sum \le \text{digit\_sum}(x) \le max\_sum$（$\text{digit\_sum}(x)$ 为 $x$ 各位数字之和）。

返回好整数的数目，对 $10^9 + 7$ 取模。

**约束**：

- $1 \le num1 \le num2 \le 10^{22}$（`num2` 最长 **23 位**）
- $1 \le min\_sum \le max\_sum \le 400$

> ⚠️ 两个关键信号：**上界 $10^{22}$ 远超 `long long`**（$\approx 9.2 \times 10^{18}$，仅 19 位）——必须全程按**字符串**处理、按**数位**做 DP，逐数值枚举彻底无缘；而 **$max\_sum \le 400$ 极小**，正好充当数位 DP 的状态维度。「统计区间内满足数位约束的数的个数」是数位 DP 的定式题面，认出套路后本题就是一道模板默写题。

## 2. 示例

**示例 1**

```text
输入：num1 = "1", num2 = "12", min_sum = 1, max_sum = 8
输出：11

解释：1 到 12 中数位和落在 [1, 8] 的有 1,2,3,4,5,6,7,8,10,11,12，共 11 个。
      注意 9 的数位和为 9 > 8，被排除。
```

**示例 2**

```text
输入：num1 = "1", num2 = "5", min_sum = 1, max_sum = 5
输出：5

解释：1 到 5 的数位和全在 [1, 5] 中，共 5 个。
```

**补充示例（自构造，覆盖「借位减一」与「跨位数」）**

```text
输入：num1 = "999", num2 = "1001", min_sum = 1, max_sum = 27
输出：3

解释：999（数位和 27）、1000（数位和 1）、1001（数位和 2）全部合法，共 3 个。
      计算 f(num1−1) 时要做字符串借位减法："999" − 1 = "998"，
      且区间恰好跨越 3 位 → 4 位的位数分界，检验补零处理是否正确。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法：枚举 $x \in [num1, num2]$，逐个累加数位判断。但区间长度可达 $10^{22}$ 量级，即使每个数 $O(1)$ 也远跑不完。转成整数再枚举更是无从谈起——`num2` 连 `long long` 都装不下。

> 💡 **换主轴**：既然每个数由若干位十进制数字组成，而约束「数位和」只依赖**每一位填了什么**，就把主轴从「值」换成「位」：从高到低逐位填数字、同步累计数位和。这就是**数位 DP**。

### 3.2 核心观察一：区间化前缀差，交给数位 DP

![前缀差与三状态数位 DP 模型](images/wc348_q4_prefix_diff_concept.svg)

数位 DP 天然处理「$\le$ 某个上界」，而本题是双端闭区间。标准动作是**前缀差**：令

$$f(s) = \bigl|\{\, x \in [1,\ s] :\ min\_sum \le \text{digit\_sum}(x) \le max\_sum \,\}\bigr|,$$

则

$$ans = f(num2) - f(num\_1 - 1).$$

直观正确性：$[1, num2]$ 切成 $[1, num1-1]$ 与 $[num1, num2]$ 两段，前段在相减中被**恰好扣掉一次**。其中 $num1 - 1$ 要用**字符串借位减法**实现（`"1000"` → `"999"`，`"1"` → `"0"`）。

而 $f(s)$ 用数位 DP 计算：从高到低逐位填数，只需三个状态——

| 状态 | 含义 | 规模 |
|------|------|------|
| `pos` | 填到第几位 | $L \le 23$ |
| `sum` | 已填位的数位和 | $0 \dots max\_sum \le 400$，**超过 $max\_sum$ 即剪枝** |
| `tight` | 是否仍贴住 $s$ 的前缀 | `True` / `False` |

**剪枝时机**：数位和沿路径**只增不减**，一旦 $sum > max\_sum$，再填低位只会更大，整条分支必死，立即砍掉；而 $min\_sum$ 只在**填完全部位后**判定——中途 $sum$ 可能还没涨够，提前判下界会误杀。

### 3.3 核心观察二：前导零贡献 0，`started` 状态整个省掉

![前导零不改变数位和，省掉 started 状态](images/wc348_q4_leading_zero_insight.svg)

通用数位 DP 模板（如 [2376. 统计特殊整数](https://leetcode.cn/problems/count-special-integers/)、[356 场周赛 Q4 步进数字](../356/Q4.统计范围内的步进数字数目题解.md)）通常带第四个状态 `started`（是否已填过非零位），用来管前导零——因为「各位互异」「相邻差为 1」这类约束在前导零处会失真。

但本题的约束是**数位和**，而**前导零对数位和的贡献恰好是 0**：

$$\text{digit\_sum}(\texttt{"007"}) = 0 + 0 + 7 = 7 = \text{digit\_sum}(\texttt{"7"}).$$

于是「位数更短的数」可以直接看作「高位补 0 的同长串」走同一条 DP，`started` 整个省掉，只剩三状态 $dfs(pos,\ sum,\ tight)$。两条保障兜住正确性：

1. **$x = 0$ 不会误计**：全零路径到叶子时 $sum = 0 < min\_sum$（约束 $min\_sum \ge 1$），天然排除——所以 $f("0") = 0$，`dec("1") = "0"` 无需任何特判；
2. **大小关系不乱**：补零只会在高位加 0，值**只小不小**，同长度字符串的字典序即数值序，`tight` 语义不受干扰。

> 💡 本站[每日题解 2719](../../solution/2701-2800/2719_统计整数数目.md) 采用带 `started` 的通用四状态写法；本篇利用「约束是数位和」这一题设特性把模板**砍薄一层**。两种写法都对，赛场上想少一个状态就少一分出错面——但要知道**为什么能省**（见第 5 节引理 1）。

### 3.4 算法流程

```text
dec(s)：字符串大数减一（s ≥ 1）
    从末位起借位：遇 '0' 变 '9' 继续借，遇非 '0' 减一停步；再去前导零
    例："1000" → "999"，"1" → "0"

count_le(s)：即 f(s)，三状态记忆化搜索
    dfs(pos, sm, tight)：
        若 pos == L：返回 1 若 sm ≥ min_sum，否则 0
        up = s[pos] 若 tight，否则 9
        ans = 0
        对 d = 0 .. up（从小到大）：
            若 sm + d > max_sum：break      ← d 递增，后面只会更超
            ans += dfs(pos+1, sm+d, tight 且 d == up)
        返回 ans mod p

ans = (count_le(num2) − count_le(dec(num1))) mod p
```

### 3.5 示例演算

![示例演算：f("12") 的搜索树](images/wc348_q4_example_tree.svg)

以示例 1 求 $f(\texttt{"12"})$（$min\_sum=1,\ max\_sum=8$）为例，$s = \texttt{"12"}$，$L = 2$，从根 $(pos{=}0,\ sum{=}0,\ tight)$ 出发，首位上界 $up = s[0] = 1$：

- **$d=0$（前导零支）** → $(pos{=}1,\ sum{=}0,\ \text{自由})$，$up = 9$，对应一位数 $0 \dots 9$：
  - $d=0$：即 $x=0$，$sum = 0 < 1$，不计 ✗；
  - $d=1 \dots 8$：$sum = 1 \dots 8$ 全部落入 $[1, 8]$ → **8 个** ✓；
  - $d=9$：$sum = 9 > 8$，剪枝 ✗。
- **$d=1$（贴界支）** → $(pos{=}1,\ sum{=}1,\ \text{贴界})$，$up = s[1] = 2$，对应 $x \in \{10, 11, 12\}$：
  - $d=0$ → $x=10$，$sum=1$ ✓；$d=1$ → $x=11$，$sum=2$ ✓；$d=2$ → $x=12$，$sum=3$ ✓ → **3 个**。

合计 $f(\texttt{"12"}) = 8 + 3 = 11$；而 $num1 = \texttt{"1"} \Rightarrow num1 - 1 = \texttt{"0"}$，$f(\texttt{"0"}) = 0$（唯一路径全零，$sum=0 < 1$）。故 $ans = 11 - 0 = 11$ ✓。

## 4. 算法细节

1. **字符串大数减一 `dec`**：从末位借位——遇 `'0'` 置 `'9'` 继续向左，遇非 `'0'` 减一停步（$num1 \ge 1$ 保证停得住），最后 `lstrip('0')`；若结果为空串则返回 `"0"`。`"1000"` → `"0999"` → `"999"`。
2. **剪枝写 `break` 不写 `continue`**：`d` 从小到大枚举，`sm + d` 随 `d` 单调不减，第一个超界即可终止整层循环。
3. **记忆化维度**：状态 $(pos, sum, tight)$，其中 `sum ∈ [0, max_sum]`（剪枝保证不超界），故 `memo[24][401][2]` 即可（$L \le 23$）。`tight = true` 的状态只出现在**唯一的贴界路径**及其分叉上，数量极少，一并缓存无妨。
4. **缓存不能跨上界复用**：两次 `count_le` 的上界字符串不同，`tight = true` 的记忆化条目依赖 $s$，必须每次清空——C++ 里对 `memo` 整体 `memset(-1)`；Python 把 `dfs` 连同 `lru_cache` 定义在 `count_le` 内部，随每次调用自然重建。
5. **取模与防负**：两个模意义下的计数相减可能为负，C++ 写 `(f2 - f1 + MOD) % MOD`；Python 的 `%` 天然非负。

## 5. 正确性证明

**引理 1（补零表示）**：设 $s$ 为长度 $L$ 的数字串，值 $S = \mathrm{int}(s)$。每个 $x \in [0, S]$ 的 $L$ 位零填充表示 $\bar{x}$ 满足：

1. $x \mapsto \bar{x}$ 是 $[0, S]$ 到「长度为 $L$、按位不超 $s$ 的串」的**双射**；
2. $\text{digit\_sum}(\bar{x}) = \text{digit\_sum}(x)$（前导零贡献 0）；
3. 同长度字符串的字典序与数值序一致，故 $\bar{x} \le_{\text{lex}} s \iff x \le S$。

**证明**：零填充是「值 → 定长串」的标准双射，前导 0 不改变各位之和；两个等长十进制串比较从最高位起逐位进行，与数值比较完全同构。∎

**引理 2（前缀差）**：$ans = f(num2) - f(num\_1 - 1)$，其中 $f$ 如 3.2 节定义（计 $[1, s]$）。

**证明**：$[1, num2] = [1, num1-1] \,\dot\cup\, [num1, num2]$（$num1 \ge 1$ 保证两段不交且并集完整）。好整数条件 $min\_sum \le \text{digit\_sum} \le max\_sum$ 与区间条件独立，故 $f(num2) = f(num\_1 - 1) + |\{\text{好整数}\}|$，移项即得。∎

**引理 3（三状态计数正确）**：$dfs(0, 0, \text{true})$ 返回

$$\bigl|\{\, t :\ |t| = L,\ t \text{ 逐位} \le s,\ min\_sum \le \text{digit\_sum}(t) \le max\_sum \,\}\bigr| \pmod{10^9+7}.$$

**证明**（对 `pos` 自 $L$ 向 $0$ 归纳）：

- **边界** `pos == L`：一条路径唯一确定串 $t$，累计和即 $\text{digit\_sum}(t)$；返回 `1` 当且仅当 $sum \ge min\_sum$（$sum \le max\_sum$ 由转移时的剪枝保证）。
- **归纳步**：`tight = true` 时枚举 $d \in [0, s[pos]]$，$d < s[pos]$ 的分支转入自由态（此后任意后缀合法），$d = s[pos]$ 保持贴界——按最高位差异分类，恰不重不漏地覆盖所有逐位 $\le s$ 的串；`tight = false` 时枚举 $d \in [0, 9]$，对应剩余位全自由。
- **剪枝安全**：设某分支填入 $d$ 后 $sum' = sum + d > max\_sum$。沿任何后继路径数位和只增不减，终态和 $\ge sum' > max\_sum$ 必不合法，砍掉的分支对计数贡献为 0。
- 取模在每层转移处进行，不影响计数值的同余性。∎

**定理**：算法返回值 $\equiv$ 好整数的个数 $\pmod{10^9 + 7}$。

**证明**：由引理 1，引理 3 计的串集合与 $\{x \in [0, S]\}$ 双射且数位和相同；又 $min\_sum \ge 1$ 排除 $x = 0$（全零串数位和为 0），故 `count_le(s)` 恰为 $f(s)$。再由引理 2，`count_le(num2) − count_le(dec(num1))` 恰为 $[num1, num2]$ 中好整数的个数。两层差分中每个好整数在 $f(num2)$ 计一次、在 $f(num\_1 - 1)$ 计零次，不重不漏。∎

## 6. 复杂度分析

- **时间复杂度**：$O(L \cdot max\_sum \cdot 10)$，$L \le 23$
  - 有效状态数 $\le L \cdot (max\_sum + 1) \cdot 2 \approx 23 \times 401 \times 2 \approx 1.8 \times 10^4$；
  - 每个状态枚举至多 10 个数字；
  - `count_le` 调用两次，总计约 $2 \times 10^5$ 次基本运算——相比暴力 $10^{22}$ 次是**指数级压缩**：值域的大小被「位数 × 数位和」两个小维度取代。
- **空间复杂度**：$O(L \cdot max\_sum)$
  - 记忆化表 $24 \times 401 \times 2 \approx 1.9 \times 10^4$ 项；
  - 递归栈深 $O(L)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int count(string num1, string num2, int min_sum, int max_sum) {
        const long long MOD = 1e9 + 7;
        string a = dec(num1);                        // num1 - 1（字符串大数减一）
        long long f2 = countLe(num2, min_sum, max_sum);
        long long f1 = countLe(a, min_sum, max_sum);
        return (int)((f2 - f1 + MOD) % MOD);         // 防负数
    }

  private:
    // 字符串大整数减一（num1 >= 1，结果 >= 0）
    static string dec(const string& s) {
        string a = s;
        int i = (int)a.size() - 1;
        while (i >= 0 && a[i] == '0') { a[i] = '9'; --i; }   // 末尾 0 借位变 9
        a[i] -= 1;                                           // num1 >= 1 故 i >= 0
        int k = 0;
        while (k < (int)a.size() - 1 && a[k] == '0') ++k;    // 去前导零
        return a.substr(k);
    }

    // f(s)：[1, s] 中数位和落在 [min_sum, max_sum] 的整数个数（三状态数位 DP）
    static long long countLe(const string& s, int min_sum, int max_sum) {
        int n = (int)s.size();
        static long long memo[24][401][2];   // [pos][sum][tight]，sum <= max_sum <= 400
        memset(memo, -1, sizeof(memo));      // 两次调用之间必须清空
        function<long long(int, int, int)> dfs = [&](int pos, int sm, int tight) -> long long {
            if (pos == n) return sm >= min_sum ? 1 : 0;   // max_sum 已由剪枝保证
            long long& res = memo[pos][sm][tight];
            if (res != -1) return res;
            int up = tight ? (s[pos] - '0') : 9;
            long long ans = 0;
            for (int d = 0; d <= up; ++d) {
                if (sm + d > max_sum) break;              // d 递增，后面只会更超
                ans = (ans + dfs(pos + 1, sm + d, tight && (d == up))) % (1000000007LL);
            }
            return res = ans;
        };
        return dfs(0, 0, 1);
    }
};
```

### Python

```python
from functools import lru_cache

class Solution:
    def count(self, num1: str, num2: str, min_sum: int, max_sum: int) -> int:
        MOD = 10 ** 9 + 7

        def dec(s: str) -> str:
            # 字符串大数减一（num1 >= 1，结果 >= 0）
            a = list(s)
            i = len(a) - 1
            while i >= 0 and a[i] == '0':      # 末尾 0 借位变 9
                a[i] = '9'
                i -= 1
            a[i] = chr(ord(a[i]) - 1)          # num1 >= 1 故 i >= 0
            res = ''.join(a).lstrip('0')       # 去前导零
            return res if res else "0"

        def count_le(s: str) -> int:
            # f(s)：[1, s] 中数位和落在 [min_sum, max_sum] 的整数个数
            @lru_cache(None)
            def dfs(pos: int, sm: int, tight: bool) -> int:
                if pos == len(s):
                    return 1 if sm >= min_sum else 0   # max_sum 已由剪枝保证
                up = int(s[pos]) if tight else 9
                ans = 0
                for d in range(up + 1):
                    if sm + d > max_sum:               # d 递增，后面只会更超
                        break
                    ans += dfs(pos + 1, sm + d, tight and d == up)
                return ans % MOD

            return dfs(0, 0, True) % MOD

        return (count_le(num2) - count_le(dec(num1))) % MOD
```

## 8. 边界情况与易错点

1. **不要转整型**：$num2 \le 10^{22}$ 有 23 位，超出 `long long`（19 位）与 `unsigned long long`（20 位）——全程字符串，包括 $num1 - 1$ 的减法。
2. **`dec` 的三个坑**：借位（`"1000"` → `"0999"`）、去前导零（→ `"999"`）、退化到 `"0"`（`num1 = "1"` 时）。`f("0") = 0` 由「全零路径 $sum = 0 < min\_sum$」自动成立，无需特判。
3. **`min_sum` 过大时答案为 0**：$[1, 10^{22}]$ 内最大数位和是 $198$（22 个 9），若 $min\_sum \ge 199$（约束允许到 400）则无解——DP 走不到任何满足下界的叶子，**自然返回 0**，同样无需特判，但别误以为是 bug。
4. **判界时机**：$max\_sum$ 在**转移中**剪枝（上界单调可提前砍），$min\_sum$ 只在**叶子**判定（中途未涨够，提前判会误杀）——两者对称却不可混用。
5. **剪枝写 `break` 依赖枚举顺序**：`d` 必须从小到大，若倒序枚举则只能写 `continue`（仍正确，略慢）。
6. **`tight` 传递**：必须 `tight && (d == up)`——漏掉 `tight` 会把「自由支凑巧取到 9」误判为贴界，多数或少数都错。
7. **C++ 两次调用之间清 `memo`**：`tight = true` 的条目依赖上界 $s$，跨上界复用会污染；Python 的 `lru_cache` 随 `count_le` 闭包每次重建，天然安全。
8. **负余数**：C++ 中 `(f2 - f1) % MOD` 可能为负，须 `+ MOD` 再取模；Python `%` 天然非负。

**延伸思考**：

- 若放宽为 $min\_sum = 0$（允许 $x = 0$ 算好整数），三状态版本还对吗？——仍然对：$f$ 会把 0 计入，但 $num1 \ge 1$ 时 $0 \in [0, num1-1]$，前缀差恰好把它减掉，结论不变；真正会出问题的是 $num1 = 0$ 的输入（需另行特判 0 的归属）。
- 若上界放宽到 $10^{100}$（如 2801）：模板原封不动，只是 `pos` 维开到 100+，`sum` 维相应放大到 $9 \times 100$。
- 若约束换成「各位互异」或「模 $p$ 余 $r$」：分别加 `mask`（$\le 2^{10}$）或余数维（$\le p$）——数位 DP 的状态维由**约束的信息量**决定，本题「数位和」只需一维 `sum`，是最朴素的形态。
