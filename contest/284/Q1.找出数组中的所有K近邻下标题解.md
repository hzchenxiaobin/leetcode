# LeetCode 找出数组中的所有 K 近邻下标 题解

## 1. 题目概述

- **标题 / 题号**：找出数组中的所有 K 近邻下标（#2200，easy）
- **链接**：https://leetcode.cn/problems/find-all-k-distant-indices-in-an-array/
- **来源**：LeetCode 第 284 场周赛 Q1
- **难度**：简单
- **标签**：数组、双指针

**题意**：给定下标从 0 开始的整数数组 `nums` 和整数 `key`、`k`。下标 `i` 是 **K 近邻下标**，当且仅当存在某个下标 `j` 满足 $|i - j| \le k$ 且 `nums[j] == key`。按递增顺序返回所有 K 近邻下标。

**约束**：

- `1 <= nums.length <= 1000`
- `1 <= nums[i] <= 1000`
- `key` 是数组 `nums` 中的一个整数
- `1 <= k <= nums.length`

## 2. 示例

**示例 1**

```text
输入：nums = [3,4,9,1,3,9,5], key = 9, k = 1
输出：[1,2,3,4,5,6]
解释：nums[2] == key 且 nums[5] == key。
下标 0 到 2、5 的距离都超过 k，不是答案；其余下标均在某个 key 的 1 格范围内。
```

**示例 2**

```text
输入：nums = [2,2,2,2,2], key = 2, k = 2
输出：[0,1,2,3,4]
解释：所有元素都是 key，任意下标都落在某个 key 的 2 格范围内。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 `i`，检查窗口 $[i-k,\ i+k]$ 内是否存在 `nums[j] == key`：

- 时间复杂度 $O(n \cdot k)$，最坏 $O(n^2)$（$n, k \le 1000$，最多 $10^6$ 次判断，实际能过）。
- 但这是「正着做」——每个 `i` 都要重新找 `j`，做了大量重复扫描，不是签到题的最短路径。

### 3.2 核心观察：反向视角——key 下标照亮区间

![核心观察：key 下标照亮区间](images/kdistant_cover_concept.svg)

把条件**反过来**：与其对每个 `i` 找 `j`，不如对每个满足 `nums[j] == key` 的 `j`，它直接"照亮"连续区间 $[\,j-k,\ j+k\,]$。答案就是所有被照亮区间的**并集**。

> 💡 一句话：正着是「每个点找光源」，反着是「每个光源照一段」——后者天然按区间批量出答案。

### 3.3 算法流程：区间合并去重

![区间合并流程与去重](images/kdistant_interval_merge.svg)

按 `j` 从小到大遍历，维护 `right` = 下一个尚未输出的下标：

1. 遇到 `nums[j] == key` 时，计算有效区间 $[\,\max(\text{right},\ j-k),\ \min(n-1,\ j+k)\,]$；
2. 依次输出区间内所有下标，并更新 `right = min(n-1, j+k) + 1`。

由于 `j` 递增 ⇒ 区间右端 `j+k` 递增 ⇒ `right` 单调右移，输出**天然递增且不重复**，一趟扫描完成。

> ⚠️ 比赛最短路径：若不想推区间合并，直接开 `bool` 标记数组，对每个 key 下标把 $[j-k, j+k]$ 涂色，最后按下标序收集。$O(n \cdot k)$ 但 $n \le 1000$ 稳过，写起来零思考成本。

### 3.4 示例演算

![示例演算：两段区间拼接](images/kdistant_walkthrough.svg)

以示例 1（`nums = [3,4,9,1,3,9,5]`，`key = 9`，`k = 1`）走查：

| 步骤 | key 下标 j | left = max(right, j−k) | right = min(n−1, j+k)+1 | 输出 |
|------|-----------|------------------------|--------------------------|------|
| ① | 2 | max(0, 1) = 1 | min(6, 3)+1 = 4 | 1, 2, 3 |
| ② | 5 | max(4, 4) = 4 | min(6, 6)+1 = 7 | 4, 5, 6 |

两段区间 $[1,3]$ 与 $[4,6]$ 恰好拼接，最终答案 `[1,2,3,4,5,6]` ✓

## 4. 算法细节

1. **反向枚举光源**：只关心 `nums[j] == key` 的 `j`，每个 `j` 贡献一段连续区间，把「判定问题」变成「区间并集问题」。
2. **单调性去重**：`j` 递增时 `j-k` 与 `j+k` 均递增，故新区间左端用 `max(right, j-k)` 裁掉已被覆盖的部分，不会重复输出。
3. **边界裁剪**：区间右端用 `min(n-1, j+k)` 防止越界（左端因 `right >= 0` 天然不越界）。
4. **标记法备选**：`bool mark[n]` 涂色 + 顺序收集，代码更无脑，代价是 $O(n)$ 额外空间与最坏 $O(n \cdot k)$ 时间。
5. **数据结构选择**：仅一个 `right` 整型指针，无需排序、无需哈希表——答案有序性由遍历顺序保证。

## 5. 正确性证明

**引理 1**：$|i - j| \le k \iff j \in [i-k,\ i+k]$。

**证明**：绝对值不等式的标准等价改写。∎

**引理 2**（区间覆盖刻画）：`i` 是 K 近邻下标 $\iff$ $i \in \bigcup_{j:\ \texttt{nums[j]==key}} [j-k,\ j+k]$。

**证明**：由引理 1，存在 `j` 使 $|i-j|\le k$ 且 `nums[j]==key` $\iff$ 存在这样的 `j` 落在 $[i-k, i+k]$ 中 $\iff$ `i` 落在某个 key 下标 `j` 的 $[j-k, j+k]$ 中（$|i-j|\le k$ 是对称的）。∎

**引理 3**（不重不漏）：设 key 下标按序为 $j_1 < j_2 < \cdots < j_m$，算法第 $t$ 步输出区间 $I_t = [\max(r_{t-1},\ j_t-k),\ \min(n-1,\ j_t+k)]$，其中 $r_t = \min(n-1,\ j_t+k)+1$。则各 $I_t$ 互不相交、按序排列，且 $\bigcup_t I_t = \bigcup_t [j_t-k,\ j_t+k] \cap [0, n-1]$。

**证明**：对 $t$ 归纳。$r_t = \min(n-1, j_t+k)+1$ 关于 $t$ 单调不减（因 $j_t$ 递增）。$I_t$ 的左端 $\ge r_{t-1}$，而 $r_{t-1}$ 是已输出部分的右边界+1，故 $I_t$ 与之前输出不相交；若 $[j_t-k,\ j_t+k]$ 中有下标 $< r_{t-1}$，它们必落在某个更早的 $I_s$（$s < t$）内——因为 $r_{t-1}$ 之前的位置均已被覆盖——故并集不变，只是避免了重复。右端裁剪到 $n-1$ 保证不越界。∎

**定理**：算法按递增顺序输出所有 K 近邻下标，无重复、无遗漏。

**证明**：由引理 2，答案集合 = 诸区间之并；由引理 3，算法恰以递增顺序输出该并集每个元素一次。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。外层遍历 `j` 共 $n$ 步；内层每个下标至多被输出一次（`right` 只进不退），总计输出不超过 $n$ 个。
- **空间复杂度**：$O(1)$ 额外空间（不计返回的答案数组）；标记法为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> findKDistantIndices(vector<int>& nums, int key, int k) {
        int n = nums.size();
        vector<int> ans;
        int right = 0;  // 下一个尚未输出的下标
        for (int j = 0; j < n; j++) {
            if (nums[j] != key) continue;
            int left = max(right, j - k);
            right = min(n - 1, j + k) + 1;
            for (int i = left; i < right; i++) {
                ans.push_back(i);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def findKDistantIndices(self, nums: List[int], key: int, k: int) -> List[int]:
        n = len(nums)
        ans = []
        right = 0  # 下一个尚未输出的下标
        for j, x in enumerate(nums):
            if x != key:
                continue
            left = max(right, j - k)
            right = min(n - 1, j + k) + 1
            ans.extend(range(left, right))
        return ans
```

标记法（比赛最短路径，直接涂色）：

```python
class Solution:
    def findKDistantIndices(self, nums: List[int], key: int, k: int) -> List[int]:
        n = len(nums)
        mark = [False] * n
        for j, x in enumerate(nums):
            if x == key:
                for i in range(max(0, j - k), min(n - 1, j + k) + 1):
                    mark[i] = True
        return [i for i, ok in enumerate(mark) if ok]
```

## 8. 边界情况与易错点

1. **区间越界**：`j + k` 可能超过 `n-1`，必须 `min(n-1, j+k)` 裁剪（否则越界/输出非法下标）。
2. **区间重叠**：相邻两个 key 下标距离 $\le 2k$ 时区间重叠，若不取 `max(right, j-k)` 会**重复输出**下标——本题最经典的 WA 点。
3. **输出必须递增**：区间合并法天然有序；若用标记法，务必按下标 `0..n-1` 顺序收集，不要按"发现顺序"输出。
4. **key 保证存在**：约束说明 `key` 一定在数组中，答案非空；但代码无需特判（不存在时自然返回空列表）。
5. **k 很大**：`k >= n` 时整个数组都是答案，`min` 裁剪自动处理，无需特判。
6. **无溢出风险**：$n, k \le 1000$，`j + k` 最大 2000，`int` 足够。
7. **双指针写法的坑**：若先收集 key 下标列表再用双指针，注意指针推进条件是 `js[p] < i - k`（严格小于），判断存在性是 `js[p] <= i + k`，边界符号易错。
