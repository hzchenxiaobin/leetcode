# LeetCode 统计可以提取的工件 题解

## 1. 题目概述

- **标题 / 题号**：统计可以提取的工件（#2201，medium）
- **链接**：https://leetcode.cn/problems/count-artifacts-that-can-be-extracted/
- **来源**：LeetCode 第 284 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、模拟

**题意**：给定 $n \times n$ 的网格与若干**互不重叠**的矩形工件，`artifacts[i] = [r1, c1, r2, c2]` 描述第 $i$ 个工件占据的子矩形。再给定挖掘列表 `dig`，其中每个元素 $(r, c)$ 表示挖开该单元格。一个工件**所有**覆盖的格子都被挖开时才能提取，求可提取的工件数目。

**约束**：

- `1 <= n <= 1000`
- `1 <= artifacts.length, dig.length <= min(n², 10⁵)`
- `0 <= r1i, c1i, r2i, c2i, ri, ci <= n - 1`，且 `r1i <= r2i`、`c1i <= c2i`
- 不存在重叠的两个工件
- **每个工件最多只覆盖 4 个单元格**
- `dig` 中的元素互不相同

> 💡 本题在本仓库另有[每日题解 2201](../../solution/2201-2300/2201_统计可以提取的工件.md)：主线为「一维编码 $r \cdot n + c$ 进 `unordered_set` + 逐工件查全挖」，附编码唯一性、容器选型与二维前缀和扩展的面试问答。本篇按**周赛复盘视角**展开，补上反向计数版（工件染色 + `cnt/tot` 比对）、引理-定理化的正确性证明与赛场易错清单，两篇互为印证。

```text
      蓝色工件 B 占 (0,1),(1,1)，其中 (1,1) 未挖 → 不可提取。
```


```text
输出：0
解释：1×4 横条只挖了首尾 2 格，中间 (1,1),(1,2) 未挖，不可提取。
```

## 3. 解题思路

### 3.1 暴力思路

对每个工件的每个格子，**线性扫描** `dig` 列表判断是否被挖：

- 单次判定 $O(d)$，总时间 $O(4m \cdot d)$，$m, d \le 10^5$ 时约 $4 \times 10^{10}$，必然超时。
- 瓶颈在于「某格是否被挖」这一查询太贵——每次都重新扫一遍 `dig`。

### 3.2 核心观察：把「查询被挖」降到 O(1)

![核心观察：工件可提取的条件](images/wc284_q2_artifact_dig_concept.svg)

1. **挖掘是集合语义**：`dig` 元素互不相同，「某格是否被挖」是纯粹的**存在性查询**。把 `dig` 预处理成哈希集合（或 $n \times n$ 的二维布尔数组），单次查询降为 $O(1)$。
2. **工件极小**：每个工件最多覆盖 4 个格子（$1\times1$、$1\times2$、$2\times2$、$1\times4$ 等形状），逐工件枚举矩形内所有格子的总代价只有 $O(4m)$。
3. **判定互相独立**：工件互不重叠，挖空格子（不属于任何工件的 `dig` 元素）对任何工件判定无影响，逐个判定再计数即可。

> 💡 一句话：`dig` 打标记 + 工件逐格验收，两步都是线性——这是「批量查询」型模拟题的标准套路：**先花线性时间把查询变 O(1)，再无脑枚举判定**。

### 3.3 算法流程：标记 + 逐工件验收

![算法流程图](images/wc284_q2_artifact_flow.svg)

1. 遍历 `dig`，置 `dug[r][c] = true`（哈希集合亦可）；
2. 遍历每个工件 $(r_1, c_1, r_2, c_2)$，枚举子矩形内所有格子（至多 4 个）；
3. 若所有格子均被标记，`ans++`；
4. 返回 `ans`。

**反向计数版**（与 Q1 的"反向照亮"异曲同工）：也可以不给 `dig` 建集合，而是先给**工件的格子染色**（记录归属编号与总数 `tot[i]`），再遍历 `dig` 对落在工件上的格子累加 `cnt[i]`，最后统计 `cnt[i] == tot[i]` 的工件数。两条路完全等价，正向版更好写，反向版省掉哈希查询。

### 3.4 示例演算

![示例演算：tot 与 cnt 比对](images/wc284_q2_artifact_walkthrough.svg)

以示例 2 走查（`n = 2`，`dig = [(0,0),(0,1),(1,1)]`）：

| 工件 | 覆盖格子 | tot | 被挖格 | 判定 |
|------|----------|-----|--------|------|
| A = [0,0,0,0] | (0,0) | 1 | 1 | ✓ 可提取 |
| B = [0,1,1,1] | (0,1), (1,1) | 2 | 2 | ✓ 可提取 |

空格 (1,0) 未挖但不属于任何工件，不影响判定；最终答案 `2` ✓

## 4. 算法细节

1. **标记结构选择**：$n \le 1000$ ⇒ 二维布尔数组仅 $10^6$ 字节级，查询 $O(1)$ 且常数最小；哈希集合 `set<pair<int,int>>`（或编码 $r \cdot n + c$ 后的 `unordered_set<int>`）也可，但常数偏大，C++ 下 `set` 有超时风险。
2. **矩形枚举**：工件形状覆盖 $1\times1$ 到 $2\times2$、$1\times4$、$4\times1$，务必**双重循环** $r \in [r_1, r_2]$、$c \in [c_1, c_2]$ 完整枚举，不要假设形状。
3. **反向计数的实现**：`id[r][c]` 存工件编号（初始 $-1$），染色时同时累加 `tot[i]`；遍历 `dig` 时 `id >= 0` 才 `cnt[id]++`。由「工件不重叠」保证一格只属于一个工件，计数不串。
4. **提前剪枝**：正向验收一旦发现未挖格子即可 `break`，单工件平均检查量更小。
5. **坐标一维化**（可选）：$r \cdot n + c \le 999 \times 1000 + 999 < 10^6$，`int` 足够，无溢出风险。

## 5. 正确性证明

**引理 1**（提取条件的集合刻画）：工件 $i$ 可提取 $\iff$ $[r_1^i, r_2^i] \times [c_1^i, c_2^i]$ 中每个格子 $(r, c)$ 都出现在 `dig` 中。

**证明**：题意即「工件的所有部分都裸露 ⇔ 可提取」，而某部分裸露 ⇔ 该格被挖 ⇔ 该格在 `dig` 中。全体部分都裸露 ⇔ 全体覆盖格都在 `dig` 中。∎

**引理 2**（检查量上界）：工件 $i$ 的覆盖格数为 $(r_2^i - r_1^i + 1)(c_2^i - c_1^i + 1) \le 4$。

**证明**：由约束「每个工件最多只覆盖 4 个单元格」直接给出。∎

**引理 3**（判定独立性）：任一工件的提取判定只依赖其自身覆盖格与 `dig`，与其他工件、与 `dig` 中落在其外的格子无关。

**证明**：由引理 1，判定条件只涉及该工件矩形内的格子。工件互不重叠 ⇒ 其他工件的覆盖格不在该矩形内；`dig` 中落在矩形外的格子不出现在判定条件中。∎

**定理**：算法返回的 `ans` 恰为可提取工件数。

**证明**：算法对每个工件 $i$ 逐一检验引理 1 的等价条件（矩形内全格被标记，标记集即 `dig` 集合），检验结果与「可提取」逐工件等价；由引理 3 各判定互不干扰，计数无重无漏。由引理 2，算法在有限时间内终止。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 + d + m)$。二维标记数组初始化 $O(n^2)$（哈希集合版无此项）；`dig` 打标记 $O(d)$；工件验收 $\sum_i (\text{覆盖格数}) \le 4m$。$n \le 1000$、$d, m \le 10^5$，总量约 $2 \times 10^6$。
- **空间复杂度**：$O(n^2)$（二维标记数组）或 $O(d + m)$（哈希集合 + 计数数组）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int digArtifacts(int n, vector<vector<int>>& artifacts, vector<vector<int>>& dig) {
        vector<vector<bool>> dug(n, vector<bool>(n, false));
        for (auto& d : dig) {
            dug[d[0]][d[1]] = true;
        }
        int ans = 0;
        for (auto& a : artifacts) {
            bool ok = true;
            for (int r = a[0]; r <= a[2] && ok; r++) {
                for (int c = a[1]; c <= a[3]; c++) {
                    if (!dug[r][c]) {
                        ok = false;
                        break;
                    }
                }
            }
            ans += ok;
        }
        return ans;
    }
};
```

反向计数版（工件染色 + `cnt/tot` 比对）：

```cpp
class Solution {
public:
    int digArtifacts(int n, vector<vector<int>>& artifacts, vector<vector<int>>& dig) {
        int m = artifacts.size();
        vector<vector<int>> id(n, vector<int>(n, -1));
        vector<int> tot(m, 0), cnt(m, 0);
        for (int i = 0; i < m; i++) {
            for (int r = artifacts[i][0]; r <= artifacts[i][2]; r++) {
                for (int c = artifacts[i][1]; c <= artifacts[i][3]; c++) {
                    id[r][c] = i;
                    tot[i]++;
                }
            }
        }
        for (auto& d : dig) {
            int i = id[d[0]][d[1]];
            if (i >= 0) cnt[i]++;
        }
        int ans = 0;
        for (int i = 0; i < m; i++) {
            ans += (cnt[i] == tot[i]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def digArtifacts(self, n: int, artifacts: List[List[int]], dig: List[List[int]]) -> int:
        dug = set(map(tuple, dig))
        ans = 0
        for r1, c1, r2, c2 in artifacts:
            if all((r, c) in dug for r in range(r1, r2 + 1) for c in range(c1, c2 + 1)):
                ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **「至少挖到」≠「全部挖到」**：本题最经典的 WA 点——只检查工件的一个角格（如只查 `(r1,c1)`）就计数，漏掉 1×2、2×2、1×4 等多格工件。
2. **别只枚举行向量**：工件可能是 $2\times2$、$4\times1$ 等，必须双重循环完整枚举矩形。
3. **1×1 工件**：`tot = 1`，挖到即提取，两版代码均自然覆盖。
4. **挖空格子**：`dig` 可能包含不属于任何工件的格子，正向版天然忽略；反向版必须判 `id >= 0` 再计数。
5. **C++ 容器选择**：`set<pair<int,int>>` 单次查询 $O(\log d)$，$4 \times 10^5$ 次查询虽通常能过，但 `vector<vector<bool>>` / `unordered_set` 更稳。
6. **n 与 m 的量级错觉**：`artifacts.length <= min(n², 10⁵)`，工件数可达 $10^5$；好在每件至多 4 格（引理 2），否则若无此约束，正向验收最坏 $O(n^2 m)$，须改反向计数或二维前缀和。
7. **无需排序**：答案只求个数，工件处理顺序无关；不必对 `dig` 排序去重（已保证互异）。
