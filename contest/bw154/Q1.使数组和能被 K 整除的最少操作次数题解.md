# LeetCode 使数组和能被 K 整除的最少操作次数 题解

## 1. 题目概述

- **标题 / 题号**：使数组和能被 K 整除的最少操作次数（#3512，easy）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-array-sum-divisible-by-k/
- **来源**：LeetCode 第 154 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 `nums` 和正整数 $k$。每次操作可以任选一个下标 $i$，把 `nums[i]` 替换为 `nums[i] - 1`。求使**数组元素之和能被 $k$ 整除**所需的最少操作次数。操作次数不限，但只能做减法。

**约束**：

- $1 \le nums.length \le 1000$
- $1 \le nums[i] \le 1000$
- $1 \le k \le 100$

> 💡 所有元素都是正数、且只能减不能加，所以「把总和往上凑到下一个 $k$ 的倍数」这条路是不存在的。

## 2. 示例

**示例 1**

```text
输入：nums = [3,9,7], k = 5
输出：4
解释：总和 19，19 mod 5 = 4。对 nums[1] = 9 做 4 次操作得 [3,5,7]，
      总和 15 能被 5 整除。4 次即最少。
```

**示例 2**

```text
输入：nums = [4,1,3], k = 4
输出：0
解释：总和 8 已经能被 4 整除，不需要任何操作。
```

**示例 3**

```text
输入：nums = [3,2], k = 6
输出：5
解释：总和 5，5 mod 6 = 5。把两个数各减到 0（3 次 + 2 次），
      总和 0，0 也是 6 的倍数，共 5 次操作。
```

**示例 4（自造，验证余数为 0 的边界）**

```text
输入：nums = [1], k = 1
输出：0
解释：任何整数都能被 1 整除，答案为 0。
```

## 3. 解题思路

### 3.1 暴力思路

直接枚举「总操作次数」$t = 0, 1, 2, \dots$，检查 $\big(\sum nums\big) - t$ 能否被 $k$ 整除，第一个满足的 $t$ 就是答案。这显然正确，但最坏要枚举到 $S$（$S \le 10^6$），而且完全没有必要——答案只与 $S$ 的余数有关。

另一种常见误区是「模拟」：反复对某个元素减 1 直到整除。这样写也能过，但循环次数是答案本身，且要额外判断「减到 0 之后不能再减」。

### 3.2 核心观察：一次操作 = 总和减 1，答案就是余数

![只做减法：把总和减到 k 的倍数](images/bw154_q1_modulo.svg)

两个事实：

1. **每次操作让总和恰好减少 1**（不管作用在哪个下标），所以做 $t$ 次操作后总和必为 $S - t$。
2. **「减到哪个下标上」完全不影响可行性**：只要 $0 \le t \le S$，总能把这 $t$ 次减法摊到各元素上（比如先减第一个元素直到 0，再减第二个……），因为元素都是正数且总和足够。题目没有「元素必须为正」的额外限制，减到 0 也允许。

因此问题等价于：求最小的 $t \ge 0$ 使 $S - t \equiv 0 \pmod{k}$，即 $t \equiv S \pmod{k}$。最小的非负解就是 $t = S \bmod k$。

由于 $S \bmod k < k \le S$（当 $S \ge k$ 时），$t$ 一定不超过 $S$，可行性自动满足；$S < k$ 时 $S \bmod k = S$，恰好把总和减到 0。

### 3.3 算法流程

```text
1. S ← sum(nums)
2. 返回 S mod k
```

就这两行。真正的难点是把「怎么摊操作」这件事想清楚（见 §5 的可行性引理）。

### 3.4 示例演算

![三个示例：答案就是 sum(nums) % k](images/bw154_q1_walkthrough.svg)

| `nums` | $k$ | $S$ | $S \bmod k$ | 答案 |
|---|---|---|---|---|
| `[3,9,7]` | 5 | 19 | 4 | 4 |
| `[4,1,3]` | 4 | 8 | 0 | 0 |
| `[3,2]` | 6 | 5 | 5 | 5 |

第三个例子值得多看一眼：$S = 5 < k = 6$，答案是 5 而不是 1（$5 - 1 = 4$ 不是 6 的倍数）。把总和减到 0 是唯一选择，正好验证了「只能减」这一约束。

## 4. 算法细节

1. **只需求和再取模**：不需要真的去改数组，也不需要知道操作落在哪个下标。
2. **求和用 `int` 足够**：最大 $1000 \times 1000 = 10^6$。
3. **余数即答案**：$S \bmod k \in [0, k-1]$，故答案不超过 99。
4. **不要写 `(k - S % k) % k`**：那是「可以加」时的公式。本题只能减，正确写法是 `S % k`。
5. **不必特判 $S$ 是否为 0**：$S \bmod k = 0$ 时答案自然是 0。
6. **可行性无需额外检查**：见引理 2，余数总是不超过总和的。

## 5. 正确性证明

设 $S = \sum nums$，记答案为 $t^\*$。

**引理 1（操作即减一）**：执行 $t$ 次操作后，数组元素之和必为 $S - t$。

**证明**：对 $t$ 归纳。$t = 0$ 时和为 $S$。设 $t$ 次后和为 $S - t$，第 $t+1$ 次操作把某个 `nums[i]` 减 1，总和变为 $(S - t) - 1 = S - (t+1)$。∎

**引理 2（可行性）**：对任意整数 $t$ 满足 $0 \le t \le S$，都存在一组合法的操作序列，恰好做 $t$ 次操作。

**证明**：把 `nums` 的元素依次「消耗」：从第一个元素开始减，减到 0 再减下一个。因为元素初始均为正、总和为 $S \ge t$，这个过程在累计减了 $t$ 次时一定还没耗尽所有元素，故 $t$ 次操作全部合法（每次操作时被减的元素 $> 0$）。∎

**引理 3（余数刻画）**：$S - t$ 能被 $k$ 整除 $\iff t \equiv S \pmod{k}$。

**证明**：$k \mid (S - t) \iff S - t = qk \iff t = S - qk \iff t \equiv S \pmod{k}$。∎

**定理**：最少操作次数 $t^\* = S \bmod k$。

**证明**：

- *下界*：设做了 $t$ 次操作后总和能被 $k$ 整除。由引理 1 总和为 $S - t$，由引理 3 得 $t \equiv S \pmod k$，故 $t \ge (S \bmod k)$。
- *可达*：取 $t = S \bmod k$。因为 $S \bmod k \le S$，由引理 2 存在恰好 $t$ 次操作的序列；由引理 3，此时 $S - t \equiv 0 \pmod k$。

故最小值就是 $S \bmod k$。∎

## 6. 复杂度分析

- **时间**：$O(n)$，只需一次遍历求和；取模为 $O(1)$。
- **空间**：$O(1)$，只用一个累加变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums, int k) {
        int sum = 0;
        for (int x : nums) sum += x;
        // 只能做减法：总和减 r 后能被 k 整除，最少就是减 r 次
        return sum % k;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int], k: int) -> int:
        # 只能做减法：总和减 r 后能被 k 整除，最少就是减 r 次
        return sum(nums) % k
```

## 8. 边界情况与易错点

1. **写成「凑到下一个倍数」**：`(k - S % k) % k` 是允许加法时的答案，本题只能减，会全线错位（示例 1 会输出 1 而不是 4）。
2. **忘记「0 也是 $k$ 的倍数」**：示例 3 的答案是 5（把总和减到 0），若认为「必须保持正数」就会无解或算错。
3. **$k = 1$**：任何和都能被 1 整除，答案恒为 0。
4. **$S < k$**：答案就是 $S$，即把所有元素减到 0；不需要特判，公式自动成立。
5. **$S$ 已整除**：答案 0，不要因为「必须操作」而输出 $k$。
6. **操作合法性**：虽然形式上是「减 1」，但元素减到 0 后不能再减；由于 $t = S \bmod k \le S$，可把减法摊到多个元素上，不会出现「减负数」的问题（引理 2）。

**延伸思考**：

1. 若允许**加 1 或减 1**，答案变为 $\min(S \bmod k,\; k - S \bmod k)$——此时「往上凑」也可行。
2. 若每次操作必须作用在**不同下标**上，则 $t$ 不能超过 $n$，问题会变成「是否存在 $t \le n$ 次操作使和整除」，需要在余数与下标数之间做匹配。
3. 若要求操作后**所有元素仍为正**，则 $t$ 的上界变成 $S - n$，当 $S \bmod k > S - n$ 时无解——这是把「可行性引理」加强后的自然变体。
