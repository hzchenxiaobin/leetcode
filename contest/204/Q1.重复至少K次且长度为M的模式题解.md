# LeetCode 重复至少 K 次且长度为 M 的模式 题解

## 1. 题目概述

- **标题 / 题号**：重复至少 K 次且长度为 M 的模式（#1566，easy）
- **链接**：https://leetcode.cn/problems/detect-pattern-of-length-m-repeated-k-or-more-times/
- **来源**：LeetCode 第 204 场周赛 Q1
- **难度**：简单
- **标签**：数组、枚举、计数

**题意**：给定正整数数组 `arr` 与整数 `m`、`k`。**模式**是 `arr` 中一段长度为 `m` 的子数组；若存在某个模式在 `arr` 中**连续且不重叠**地重复了至少 $k$ 次——即存在下标 $s$，使得 $arr[s..s+m-1]$、$arr[s+m..s+2m-1]$、…、$arr[s+(k-1)m..s+km-1]$ 这 $k$ 段完全相同——返回 `true`，否则返回 `false`。

**约束**：

- $2 \le arr.length \le 100$
- $1 \le arr[i] \le 100$
- $1 \le m \le 100$
- $2 \le k \le 100$

> 💡 签到题。$n \le 100$，暴力枚举 $O(n \cdot m \cdot k) \le 10^6$ 稳过；但题面背后藏着一个优雅的等价观察——**$k$ 个全等块 ⇔ 连续 $m \times (k-1)$ 个位置满足 $arr[i] = arr[i+m]$**，可一遍扫描 $O(n)$ 解决。

## 2. 示例

**示例 1**

```text
输入：arr = [1,2,4,4,4,4], m = 1, k = 3
输出：true
解释：模式 (4) 长度为 1，连续重复 4 次 ≥ 3 次。重复次数允许超过 k。
```

**示例 3**

```text
输入：arr = [1,2,1,2,1,3], m = 2, k = 3
输出：false
解释：模式 (1,2) 长度为 2，但只连续重复 2 次，第 3 段是 (1,3) ≠ (1,2)。
```

**示例 4**

```text
输入：arr = [1,2,3,1,2], m = 2, k = 2
输出：false
解释：(1,2) 出现 2 次但中间被 (3,2) 打断，不算"连续"重复。
```

**示例 5**

```text
输入：arr = [2,2,2,2], m = 2, k = 3
输出：false
解释：长度为 2 的模式只有 (2,2)，不重叠地最多连续重复 2 次；
从起点 1 重叠着数不能凑第 3 次。
```

## 3. 解题思路

### 3.1 暴力思路：枚举起点 + 逐块比较

枚举模式起点 $s$（$0 \le s \le n - mk$），检查以 $s$ 开头的 $k$ 个长度为 $m$ 的块是否全部相同：

```text
for s in 0 .. n - m*k:            # 枚举模式起点
    ok = true
    for j in 1 .. k-1:            # 逐块比较
        for t in 0 .. m-1:        # 块内逐位比较
            if arr[s + j*m + t] != arr[s + t]:
                ok = false
    if ok: return true
return false
```

- 时间 $O(n \cdot m \cdot k) \le 100^3 = 10^6$，本题数据规模下完全够用，比赛时先写暴力保底。
- 缺点：相邻起点 $s$ 与 $s+1$ 的检查大量重叠——同一个位置被反复比较，三重循环冗余。

### 3.2 核心观察：k 个全等块 ⇔ m×(k−1) 个连续位置匹配

![核心观察：k 个全等块等价于连续 m×(k−1) 个位置满足 arr[i]==arr[i+m]](images/wc204_q1_block_equiv.svg)

把"块相等"**降维到位置层面**：

1. **相邻两块相等** ⇔ 块内 $m$ 个对应位置分别相等，即 $m$ 个连续的 $i$ 都满足 $arr[i] = arr[i+m]$；
2. **$k$ 个块全等**只需 **$k-1$ 对相邻块相等**（传递性：块0 = 块1、块1 = 块2 ⇒ 块0 = 块2）。

两者结合：

$$k \text{ 个全等块} \iff \text{连续 } m \times (k-1) \text{ 个位置满足 } arr[i] = arr[i+m]$$

于是判定问题变成**最长连续匹配段**问题：一遍扫描，维护计数器 `count`——$arr[i] = arr[i+m]$ 则 `count++`，否则 `count = 0`；一旦 `count ≥ m×(k−1)` 立即返回 `true`。

> ⚠️ **阈值是 $m \times (k-1)$ 而不是 $m \times k$**：$k$ 个块只需要 $k-1$ 对相邻相等。若误用 $m \times k$，会多要求一组 $m$ 个匹配，把"恰好重复 $k$ 次"的合法答案（如示例 1）漏判成 `false`。

> 💡 **失配为什么清零而不是减 $m$？** 失配说明当前位置 $i$ 处 $arr[i] \ne arr[i+m]$，即某个块的第 $(i \bmod m)$ 位与下一块对不上，块链在此断裂——从此前任何位置出发都无法再拼出 $k$ 个全等块，之前累积的匹配全部作废，必须从 0 重新计数。

### 3.3 算法流程：单次扫描计数

![算法流程：单次扫描计数，O(n) 判定](images/wc204_q1_scan_flow.svg)

单层循环，每步只做一次比较：范围检查 `i + m < n` → 比较 $arr[i]$ 与 $arr[i+m]$ → 相等则 `count++` 并检查阈值（达到即短路返回 `true`），不等则 `count = 0` → `i++` 回到循环条件。循环耗尽仍未命中则返回 `false`。

### 3.4 示例演算

![示例演算：示例 3 的失配清零与示例 5 的重叠陷阱](images/wc204_q1_walkthrough.svg)

**示例 3**（`arr = [1,2,1,2,1,3]`，`m = 2`，`k = 3`，target = 4）：

| i | arr[i] | arr[i+m] | 匹配 | count |
|---|--------|----------|------|-------|
| 0 | 1 | 1 | ✓ | 1 |
| 1 | 2 | 2 | ✓ | 2 |
| 2 | 1 | 1 | ✓ | 3 |
| 3 | 2 | 3 | ✗ | **0（清零）** |

$i = 4$ 时 $i + m = 6$ 越界，循环结束。`count` 峰值 3 < 4 → `false`：模式 (1,2) 只连续重复了 2 次。

**示例 5**（`arr = [2,2,2,2]`，`m = 2`，`k = 3`，target = 4）：`i = 0, 1` 均匹配，`count` 峰值仅 2 < 4 → `false`。2 个连续匹配 = 恰好 2 个全等块（起点 0 的 [2,2]、[2,2]）；若允许从起点 1 重叠着数可凑出第 3 次，但**题目要求不重叠**。

## 4. 算法细节

1. **阈值**：`target = m * (k - 1)`，由"$k$ 块只需 $k-1$ 对相邻相等、每对需 $m$ 个位置匹配"直接推出；约束 $k \ge 2$、$m \ge 1$ 保证 `target ≥ 1`。
2. **扫描范围**：`i ∈ [0, n-1-m]`（循环条件 `i + m < n`），保证 `arr[i + m]` 不越界。
3. **计数器含义**：`count` 是"以当前位置 $i$ 结尾的最长连续匹配段长度"——匹配则延伸，失配则清零。
4. **短路返回**：`count ≥ target` 立即返回 `true`，不必扫完全程。
5. **无需特判**：$m \ge n$ 时循环体一次都不执行；$m \times k > n$ 时 `count` 至多为 $n - m < m \times (k-1)$。两种情形都自然返回 `false`，不需要任何 `if` 前置判断。

## 5. 正确性证明

**引理 1（块相等的位置分解）**：以下标 $s$ 为起点的第 $j$ 块 $B_j = arr[s+jm .. s+(j+1)m-1]$ 与第 $j+1$ 块相等，当且仅当对每个 $t \in [0, m)$ 都有 $arr[s+jm+t] = arr[s+(j+1)m+t]$。

**证明**：两块长度均为 $m$，对应位下标恰好相差 $m$：$B_j$ 的第 $t$ 位是 $arr[s+jm+t]$，$B_{j+1}$ 的第 $t$ 位是 $arr[s+(j+1)m+t]$。两个长度为 $m$ 的序列相等 ⇔ 每个对应位相等。∎

**引理 2（匹配窗口 ⇒ 全等块链）**：若区间 $[s,\ s+m(k-1)-1]$ 内**所有**位置 $i$ 都满足 $arr[i] = arr[i+m]$，则以 $s$ 为起点的 $k$ 个块 $B_0, \dots, B_{k-1}$ 全部相等，且不重叠地覆盖 $arr[s..s+km-1]$。

**证明**：对任意 $j \in [0, k-2]$ 与 $t \in [0, m)$，位置 $s + jm + t$ 落在 $[s, s + m(k-1) - 1]$ 内，故 $arr[s+jm+t] = arr[s+(j+1)m+t]$。由引理 1 得 $B_j = B_{j+1}$；再由相等关系的传递性，$B_0 = B_1 = \cdots = B_{k-1}$。这 $k$ 块首尾相接、互不重叠。∎

**定理（算法正确性）**：算法返回 `true`，当且仅当 `arr` 中存在长度为 $m$ 的模式连续（不重叠）重复至少 $k$ 次。

**证明**：

（⇒）返回 `true` 时存在位置 $i$ 使 `count ≥ m(k-1)`，即区间 $[i - m(k-1) + 1,\ i]$（记 $s = i - m(k-1) + 1$）内全部位置匹配。由引理 2，从 $s$ 出发的 $k$ 个块全等，即该模式重复了 $k$ 次。

（⇐）反之，设模式在 $s$ 处连续重复 $k$ 次，即对 $j \in [0, k-1]$、$t \in [0, m)$ 有 $arr[s+jm+t] = arr[s+t]$。则对每个 $i = s + jm + t \in [s, s + m(k-1) - 1]$：

$$arr[i] = arr[s+jm+t] = arr[s+t], \qquad arr[i+m] = arr[s+(j+1)m+t] = arr[s+t]$$

故 $arr[i] = arr[i+m]$ 在该窗口内处处成立——扫描窗口内没有任何失配，计数器不发生清零，扫到 $i = s + m(k-1) - 1$ 时 `count` 已累计到 $m(k-1)`，算法返回 `true`。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描，每个位置 $i$ 仅做一次 `arr[i]` 与 `arr[i+m]` 的比较。相比暴力的 $O(n \cdot m \cdot k)$，消除了相邻起点之间的重复比较。
- **空间复杂度**：$O(1)$。只维护 `target`、`count` 两个整数变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool containsPattern(vector<int>& arr, int m, int k) {
        int n = arr.size();
        int target = m * (k - 1);   // k 个全等块只需 k-1 对相邻块相等
        int count = 0;              // 以 i 结尾的连续匹配段长度
        for (int i = 0; i + m < n; ++i) {
            if (arr[i] == arr[i + m]) {
                if (++count >= target) return true;
            } else {
                count = 0;          // 块链断裂，重新计数
            }
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def containsPattern(self, arr: List[int], m: int, k: int) -> bool:
        target = m * (k - 1)   # k 个全等块只需 k-1 对相邻块相等
        count = 0              # 以 i 结尾的连续匹配段长度
        for i in range(len(arr) - m):
            if arr[i] == arr[i + m]:
                count += 1
                if count >= target:
                    return True
            else:
                count = 0      # 块链断裂，重新计数
        return False
```

## 8. 边界情况与易错点

1. **阈值误写成 $m \times k$**：本题最经典的错法。$k$ 块只需 $k-1$ 对相邻相等，多算一组 $m$ 个匹配会把"恰好重复 $k$ 次"的合法答案判成 `false`（示例 1 即被卡住）。
2. **忽略"连续"**（示例 4）：模式出现多次但中间被打断不算连续重复；失配清零正是对这一约束的建模。
3. **忽略"不重叠"**（示例 5）：重叠着数会虚高重复次数；位置匹配计数天然按不重叠的块计数，$[2,2,2,2]$ 只能凑出 2 个块。
4. **数组越界**：比较对象是 `arr[i + m]`，循环条件必须保证 `i + m < n`（Python 的 `range(len(arr) - m)` 天然满足）。
5. **不要画蛇添足特判 $m \times k > n$**：循环范围与计数上限天然给出 `false`，前置 `if` 判断是多余的。
6. **比赛策略**：$n \le 100$，暴力三重循环几分钟写完稳过，适合保底；$O(n)$ 计数法更优雅、可迁移（见延伸），赛后值得沉淀为模板。
