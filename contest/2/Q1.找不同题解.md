# LeetCode 找不同 题解

## 1. 题目概述

- **标题 / 题号**：找不同（#389，easy）
- **链接**：https://leetcode.cn/problems/find-the-difference/
- **来源**：LeetCode 第 2 场周赛 Q1
- **难度**：简单
- **标签**：位运算，哈希表，字符串，排序

**题意**：给定两个只含小写字母的字符串 $s$ 与 $t$。$t$ 的构造方式是「把 $s$ 随机重排，再在随机位置插入一个字母」，因此 $|t| = |s| + 1$，且 $t$ 恰好比 $s$ 多一个字符。请找出这个**被添加的字母**。

题目保证答案存在且唯一。注意它并不要求我们真的把 $t$ 重排回 $s$ 的顺序——只要求出「多出来的那个字符是哪一个」。

**约束**：

- $0 \le |s| \le 1000$
- $|t| = |s| + 1$
- $s$ 与 $t$ 只包含小写英文字母

数据规模很小，$O(n^2)$ 甚至 $O(n \log n)$ 都能通过；但本题是「异或（XOR）抵消」这一技巧最经典的入门题，值得把 $O(n)$ 时间、$O(1)$ 空间的写法当作模板记住。

## 2. 示例

**示例 1**

```text
输入：s = "abcd", t = "abcde"
输出："e"
解释：
    'e' 就是被添加的字母。t 恰好在 s 的末尾多了一个 'e'。
```

**示例 2**

```text
输入：s = "", t = "y"
输出："y"
解释：
    s 为空串，t 只比它多一个字符，被添加的字母就是 'y'。
    这是 n = 0 的边界：此时 s 的循环一次都不执行。
```

**补充示例（非官方，用于说明易错点）**

```text
输入：s = "a", t = "aa"
输出："a"
解释：
    t 里有两个 'a'，s 里有一个 'a'，被添加的是 'a' 本身。
    注意：这类输入会让「取两串字符集合的对称差」的写法失效——
    'a' 在 t 的字符集合里也存在，集合差为空。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「枚举 + 删掉验证」：对 $t$ 的每个下标 $i$，删除 $t[i]$，把剩下的串与 $s$ 比较（排序后逐位比或统计频次）。单次比较 $O(n)$，共 $n$ 个候选，$O(n^2)$；若每次都排序则是 $O(n^2 \log n)$。

另一个常见方向是**排序**：两串各自排序后双指针同步走，第一个错位处就是答案，$O(n \log n)$。

在 $|s| \le 1000$ 的范围内这两种做法都能过，但都「浪费」了题目结构：题目已经告诉我们 $t$ 只比 $s$ 多**一个**字符，多元素比较、排序都是不必要的。而且它们都需要额外的比较/排序开销，没有利用「只有一个字符不同」这个强约束。

> 💡 真正的信息量在「多一个」这三个字上：这是一个**集合求差（多一个元素）**问题，而不是字符串匹配问题。

### 3.2 核心观察：异或让相同字符两两抵消

![异或抵消：多出的字母必然落单](images/wc2_q1_xor_concept.svg)

把 $s$ 与 $t$ 的所有字符**混在一起**看：除了被添加的字母 $c$ 出现奇数次，其余每个字母都出现偶数次（在 $s$ 里出现的次数记作 $k$，在 $t$ 里就是 $k$，合计 $2k$）。而对异或来说：

$$x \oplus x = 0, \qquad x \oplus 0 = x, \qquad x \oplus y = y \oplus x, \qquad (x \oplus y) \oplus z = x \oplus (y \oplus z)$$

于是只要把两串的所有字符依次异或起来，成对的字符全部抵消为 $0$，**唯一留下的就是落单的 $c$**：

$$\bigoplus_{ch \in s} ch \;\oplus\; \bigoplus_{ch \in t} ch = c$$

这个观察带来两个直接好处：

1. **与顺序无关**：异或可交换、可结合，所以完全不需要知道 $t$ 是怎么重排的，甚至连「对齐」都不需要。
2. **不需要容器**：不用哈希表、不用计数数组，一个整数累加器就够了，额外空间 $O(1)$。

### 3.3 算法流程

![算法流程：一个累加器扫完两串](images/wc2_q1_xor_flow.svg)

1. 令累加器 `ans` 取异或的单位元 $0$；
2. 遍历 `s`，对每个字符执行 `ans ^= code(ch)`；
3. 遍历 `t`，同样执行 `ans ^= code(ch)`；
4. `ans` 即被添加字母的编码，转回字符返回。

两段循环结构完全对称，可以合并成一个「先 s 后 t」的遍历。整个过程没有任何分支判断，也没有提前返回。

### 3.4 示例演算

![示例演算：s = "abcd"，t = "abcde"](images/wc2_q1_walkthrough.svg)

为了看清数字，把 `a`~`e` 依次编码为 $1$~$5$（实际代码用 ASCII 码，相消规律完全相同）。逐字符累积：

| 扫描 | 字符 | 编码 | `ans` 累积 |
|------|------|------|------------|
| s | `a` | 1 | $0 \oplus 1 = 1$ |
| s | `b` | 2 | $1 \oplus 2 = 3$ |
| s | `c` | 3 | $3 \oplus 3 = 0$ |
| s | `d` | 4 | $0 \oplus 4 = 4$ |
| t | `a` | 1 | $4 \oplus 1 = 5$ |
| t | `b` | 2 | $5 \oplus 2 = 7$ |
| t | `c` | 3 | $7 \oplus 3 = 4$ |
| t | `d` | 4 | $4 \oplus 4 = 0$ |
| t | `e` | 5 | $0 \oplus 5 = 5$ |

最终 `ans` 收敛到 $5$，还原为 `'e'`，与官方输出一致。表中 $3$、$5$、$7$ 这些中间值只是暂态，**没有任何语义**——异或的过程中不会「部分地」得到答案，只有全部扫完才坍缩成正确结果。这一点常让初学者误以为要维护某种「候选集合」。

另外两个示例的走查：

| 输入 | 处理过程 | 结果 |
|------|----------|------|
| `s = ""`，`t = "y"` | 第一段循环零次，`ans` 仍为 $0$；第二段只剩 `'y'`：$0 \oplus 121 = 121$ | `'y'` |
| `s = "a"`，`t = "aa"` | $97 \oplus 97 \oplus 97 = 97$（两个 $97$ 抵消，剩一个） | `'a'` |

## 4. 算法细节

1. **字符即整数**：小写字母的 ASCII 码在 $[97, 122]$ 内，直接参与按位异或即可。C++ 中 `char` 会先做整型提升再异或，结果仍是 `int`，返回时隐式窄化回 `char`；由于值 $<128$，不会触发有符号 `char` 的符号扩展问题。
2. **Python 必须先 `ord`**：Python 没有字符类型，`'a' ^ 'b'` 会直接抛 `TypeError`。累加器存整数，返回前用 `chr(ans)` 转回单字符字符串（LeetCode 的 Python3 签名声明返回 `str`）。
3. **求和法同样优雅但有前提**：`sum(ord(c) for c in t) - sum(ord(c) for c in s)` 就是答案编码。它的正确性来自「多重集差」，与异或同理，但需要保证累加器是 `int`：$|t| \le 1001$、编码 $\le 122$，总和不超过 $122122$，`int` 足够；若图省事用 `char` 或 Java 的 `byte` 充当累加器，和一旦超过 $127$ 就会溢出。
4. **计数法（哈希表 / 26 数组）**：对 $t$ 加一、对 $s$ 减一，最后取计数为 $1$ 的那个字母。注意判定条件必须是「**差值**为 $1$」，而不是「在 $t$ 中出现次数为 $1$」——后者在 `s = "a", t = "aa"` 上会找不到候选。
5. **排序法的收尾**：排序后双指针同进，一旦 `s[i] != t[i]` 立刻返回 `t[i]`；若循环跑完还没返回，说明多出的字符排在 `t` 的末尾（长度差 $1$ 保证它只能是最后一个），返回 `t.back()`。
6. **不要用集合运算**：`set(t) - set(s)` 丢掉的是「字符种类」的差，而题目要的是「重数」的差，两者在字符重复时完全不同（见上面的补充示例）。
7. **常数对比**：异或法只需 $2n$ 次按位运算，没有内存分配；计数法 $n$ 次自增 + $26$ 次线性扫描；排序法 $O(n \log n)$ 且有额外空间。$n$ 很小时差异可忽略，但异或法的代码最短、最不容易错。
8. **与顺序无关的一个推论**：既然结果只依赖「字符的重数」，那么 $s$、$t$ 内部怎么排都不影响答案。这解释了为什么本题不需要（也无法）利用字符串顺序信息——它是披着字符串外衣的多重集问题。

## 5. 正确性证明

**引理 1（异或的抵消性）**：对任意多重集 $M$，把其中所有元素依次异或，结果等于 $M$ 中**出现奇数次**的元素的异或；出现偶数次的元素整体贡献 $0$。

**证明**：由交换律与结合律，可以把相同元素重排到一起，把 $M$ 写成 $\{x_1^{k_1}, x_2^{k_2}, \dots\}$（$x_j^{k_j}$ 表示 $k_j$ 个 $x_j$）。于是

$$\bigoplus M = \underbrace{x_1 \oplus \cdots \oplus x_1}_{k_1 \text{ 个}} \oplus \cdots = \bigoplus_{j:\,k_j \text{ 为奇}} x_j,$$

因为 $k_j$ 为偶数时该组可两两配成 $x_j \oplus x_j = 0$，而 $k_j$ 为奇数时剩下一个 $x_j$；再用 $y \oplus 0 = y$ 逐个去掉零项即可。∎

**引理 2（差集只留下被添加的字母）**：设被添加的字母为 $c$，$cnt_S(d)$、$cnt_T(d)$ 分别表示字母 $d$ 在 $s$、$t$ 中的出现次数，则

$$\bigoplus_{ch \in s} ch \;\oplus\; \bigoplus_{ch \in t} ch \;=\; c.$$

**证明**：对任一字母 $d$，它在两串共出现 $cnt_S(d) + cnt_T(d)$ 次，由引理 1，它在总异或中的贡献为 $d$（若该和为奇数）或 $0$（若为偶数）。分两类讨论：

- $d = c$：$cnt_T(c) = cnt_S(c) + 1$，故和为 $2\,cnt_S(c) + 1$，是奇数，贡献 $c$；
- $d \ne c$：$t$ 是由 $s$ 重排并插入一个 $c$ 得到的，除 $c$ 外各字母重数不变，$cnt_T(d) = cnt_S(d)$，故和为 $2\,cnt_S(d)$，是偶数，贡献 $0$。

于是总异或 $= c \oplus 0 \oplus \cdots \oplus 0 = c$。∎

**定理**：算法返回的字符恰为被添加的字母 $c$。

**证明**：算法按定义计算了 $\bigoplus_{ch \in s} ch \oplus \bigoplus_{ch \in t} ch$（C++ 中是 `char` 的整型提升，Python 中是 `ord` 后的整数，二者都与字符编码一致）。由引理 2，该值等于 $c$ 的编码；把它转回字符（C++ 隐式窄化，Python 用 `chr`），得到的就是 $c$。题面保证 $c$ 唯一存在，故返回值正确且唯一。∎

## 6. 复杂度分析

- **时间**：$O(n)$，其中 $n = |t| = |s| + 1$。第一段循环 $|s|$ 次、第二段 $|t|$ 次，每次只做一次按位异或与一次循环推进，常数极小，总操作数为 $|s| + |t| = 2n - 1$。作为对照，本文讨论过的排序法是 $O(n \log n)$，计数法与求和法同为 $O(n)$，但异或法在常数与空间上都最省。
- **空间**：$O(1)$。只用一个整型累加器，与输入规模无关；不需要哈希表、计数数组或排序用的副本（计数法是 $O(26) = O(1)$，排序法在 Python 中要 $O(n)$ 的临时列表）。
- **对比**：「枚举删除 + 比较」是 $O(n^2)$，排序法是 $O(n \log n)$，异或法与计数法、求和法同为 $O(n)$；其中异或法额外空间最小。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    char findTheDifference(string s, string t) {
        char ans = 0;
        for (char ch : s) ans ^= ch;   // s 内部成对的字符先自我抵消
        for (char ch : t) ans ^= ch;   // t 与 s 相同的字符把结果抵消回去
        return ans;                    // 只剩被添加的那个字母
    }
};
```

### Python

```python
class Solution:
    def findTheDifference(self, s: str, t: str) -> str:
        ans = 0
        for ch in s:                   # s 内部成对的字符先自我抵消
            ans ^= ord(ch)
        for ch in t:                   # t 与 s 相同的字符把结果抵消回去
            ans ^= ord(ch)
        return chr(ans)                # 只剩被添加的那个字母
```

## 8. 边界情况与易错点

1. **$s$ 为空**：`s = ""`，`t = "y"`。第一段循环不执行，`ans` 保持 $0$，对 `t` 异或后得到 `'y'`。不能因为「$s$ 为空就不处理」而直接返回空字符。
2. **被添加的字母在 $s$ 中已存在**：`s = "a"`，`t = "aa"` 的答案是 `'a'`。凡是「求字符种类差」的写法（`set` 差、`Counter` 键差、`in` 判断唯一字符）都会在这里返回错误结果，必须比较**重数**。
3. **`char` 累加求和会溢出**：求和法里若用 `char sum` 或 `int8_t`，$|t| = 1001$ 个 `'z'` 的和是 $122122$，远超 $127$，会得到负数或错误编码。要么用 `int` 求和，要么用异或（异或在 $[97,122]$ 内按位进行，结果始终落在同一区间）。
4. **Python 直接对字符异或**：`'a' ^ 'b'` 是 `TypeError`。必须 `ord(ch)`，返回前 `chr(ans)`；漏掉 `chr` 会返回整数，与签名 `-> str` 不符。
5. **返回值类型**：C++ 返回 `char` 而不是 `int`；`return ans` 时不要把累加器声明成 `int` 再返回（会隐式截断，虽然本题数值安全，但语义不清晰）。
6. **排序法越界**：双指针版本必须在循环结束后补上 `return t.back()`，否则当多出的字符排在末尾时函数没有返回值（C++ 中属未定义行为，常见表现为返回随机字符）。
7. **误以为要还原顺序**：题目问的是「哪个字母」，不是「插入在哪个位置」，也不是「重排方案」。任何试图恢复排列的做法都偏离了题意，也是把简单题做复杂的典型来源。

**延伸思考**：

- **若 $t$ 比 $s$ 多 $k$ 个字符**：异或只能消掉偶数次，此时要么改用计数法（$O(n + 26)$），要么对每个字母统计重数差，异或法不再直接可用。
- **若要求返回所有多出的字符**：答案不再是一个值，哈希表/计数法是唯一自然的选择；异或的「折叠成一个数」正是它只能返回单值的代价。
- **若字符集扩展到任意 Unicode**：异或与求和依然成立（只要编码是整数），但排序法与数组计数法需要改成哈希表；此时「按位异或」的语义不变，因为抵消性只依赖 $x \oplus x = 0$。
- **位运算的第二层用途**：本题也说明了「用运算的代数性质代替数据结构」这一思路——当操作满足交换律、结合律、且存在自反元素时，往往能把「统计集合」压缩成一个标量。类似的还有用乘积判断排列、用加减法做多重集差。
