# LeetCode 消除游戏 题解

## 1. 题目概述

- **标题 / 题号**：消除游戏（#390，medium）
- **链接**：https://leetcode.cn/problems/elimination-game/
- **来源**：LeetCode 第 2 场周赛 Q2
- **难度**：中等
- **标签**：递归、数学

**题意**：`arr` 是 $[1, n]$ 的全部整数按严格递增排列。反复做两步：先**从左到右**删掉第 $1, 3, 5, \dots$ 个数；再**从右到左**删掉最右边的数以及此后每隔一个的数；两个方向交替进行，直到只剩一个数，返回它。

**约束**：

- $1 \le n \le 10^9$

$n$ 达到 $10^9$，任何「真的把数组建出来」的做法都会先被内存击败。

## 2. 示例

**示例 1**

```text
输入：n = 9
输出：6
解释：
arr = [1, 2, 3, 4, 5, 6, 7, 8, 9]
arr = [2, 4, 6, 8]        ← 从左删掉 1, 3, 5, 7, 9
arr = [2, 6]              ← 从右删掉 8, 4
arr = [6]                 ← 从左删掉 2
```

**示例 2**

```text
输入：n = 1
输出：1
解释：列表只有一个元素，无需删除，直接返回。
```

## 3. 解题思路

### 3.1 暴力思路

按题意维护数组：第一轮留下下标为奇数的元素（0-based），第二轮从右往左留下间隔的元素，如此反复，每轮长度减半，总时间 $O(n)$、空间 $O(n)$。

$n = 10^9$ 时数组本身就要 4 GB（`int`）或 8 GB（`long long`），内存直接爆掉；即使改为逐元素判断「这个数还在不在」，$10^9$ 次操作在多数评测机上也逼近时限。必须换一个**只描述结构、不描述元素**的视角。

### 3.2 核心观察：剩下的数永远是一个等差数列

![等差数列不变量](images/wc2_q2_ap_model.svg)

记当前剩余序列的首项为 $head$、公差为 $step$、长度为 $rem$，则它恰好是

$$head,\ head+step,\ head+2\,step,\ \dots,\ head+(rem-1)\,step$$

**为什么？** 「隔一个删一个」等价于**只保留原序列的一个奇偶子序列**，而等差数列的等间隔子序列仍是等差数列，公差恰好翻倍、长度减半。所以整局游戏只需要四个量就能完整描述：

$$(head,\ step,\ rem,\ \text{方向})$$

**首项会不会被删？** 这是唯一需要判断的事，而判据极简：

![首项移动的奇偶判据](images/wc2_q2_parity_rule.svg)

- **从左到右**：第一个数一定被删（题面第一句就是「删除第一个数字」），与 $rem$ 的奇偶无关，故 $head \leftarrow head + step$。
- **从右到左**：删的是第 $rem, rem-2, rem-4, \dots$ 个。
  - $rem$ 为**偶数**：删的位置全是偶数位，第 1 个（即 $head$）幸存，$head$ 不变；
  - $rem$ 为**奇数**：删的位置包含第 1 个，$head$ 被删，$head \leftarrow head + step$。

两种情况都满足「新公差 $= 2\,step$、新长度 $= \lfloor rem/2 \rfloor$」。合并成一条更新式：

$$head \leftarrow head + step \cdot \bigl[\ \text{left} \;\lor\; (rem \bmod 2 = 1)\ \bigr]$$

其中方括号是示性函数（条件成立取 1，否则取 0），$left$ 表示本轮是否从左到右。

### 3.3 算法流程

![算法流程图](images/wc2_q2_flow.svg)

用 $head = 1,\ step = 1,\ rem = n$、$left = \text{true}$ 初始化，然后循环：

```text
while rem > 1:
    if left or rem % 2 == 1:
        head += step            # 首项被删
    rem  = rem / 2              # 长度减半
    step = step * 2             # 公差翻倍
    left = not left             # 换方向
return head
```

注意三件事：判断用的是**本轮的** $rem$ 与 $step$；更新完三个量才翻转方向；$rem = 1$ 时唯一剩下的数就是 $head$。

### 3.4 示例演算

![n = 9 演算表](images/wc2_q2_trace_n9.svg)

以 $n = 9$ 为例，四个状态量的走查：

| 轮次 | 方向 | 本轮开始的序列 | 删除后序列 | $head$ | $step$ | $rem$ |
| :--: | :--: | :------------- | :--------- | :----: | :----: | :---: |
| 0 | — | $[1,2,\dots,9]$ | — | 1 | 1 | 9 |
| 1 | L→R | $[1,2,\dots,9]$ | $[2,4,6,8]$ | 2 | 2 | 4 |
| 2 | R→L | $[2,4,6,8]$ | $[2,6]$ | 2 | 4 | 2 |
| 3 | L→R | $[2,6]$ | $[6]$ | 6 | 8 | 1 |

第 2 轮 $rem = 4$ 为偶数，首项 2 幸存，所以 $head$ 停在 2；第 3 轮从左删，$head = 2 + 4 = 6$。循环在 $rem = 1$ 结束，返回 6。

再验一个 $n = 10$（第一轮后长度为奇数）：$[1..10] \to [2,4,6,8,10] \to [4,8] \to [8]$。用状态量看：$(1,1,10) \to (2,2,5) \to (4,4,2) \to (8,8,1)$，其中第 2 轮 $rem = 5$ 为奇数，$head = 2 + 2 = 4$，与手算一致。

## 4. 算法细节

1. **状态设计**：四元组 $(head, step, rem, left)$ 完整刻画局面，序列由 $head + k \cdot step$ 生成，永远不落地成数组。
2. **左删必动首项**：$left = \text{true}$ 时无需看 $rem$，直接 $head \mathrel{+}= step$，这是题目定义决定的。
3. **右删看奇偶**：$left = \text{false}$ 时只有 $rem$ 为奇数才 $head \mathrel{+}= step$；写成 `if (left || rem % 2 == 1)` 一次覆盖两种方向。
4. **更新顺序**：先用**本轮**的 $rem$ 与 $step$ 更新 $head$，再执行 `rem /= 2`、`step *= 2`。若先 `step *= 2`，$head$ 会多走一个公差（$n = 9$ 得 11）；若先 `rem /= 2` 再判奇偶，$n = 10$ 的第 2 轮会把 $rem = 5$（奇，需要移动）误读成 2（偶，不移动），最终得 6 而非 8。
5. **终止条件**：`while (rem > 1)`。$n = 1$ 时循环一次都不进，直接返回 $head = 1$，无需特判。
6. **轮数上界**：第 $k$ 轮后 $rem = \lfloor n/2^k \rfloor$，故最多 $\lceil \log_2 n \rceil \le 30$ 轮，$n = 10^9$ 也只跑 30 次。
7. **整数范围**：当 $rem \ge 2$ 时序列末项 $head + (rem-1)\,step \le n$，故 $head + step \le n$，`int` 足够；但仍建议用 `long long`，把范围放宽到 $10^{18}$ 也不用改代码。
8. **等价递归式**：$f(1) = 1$，$f(n) = 2\bigl(1 + \lfloor n/2 \rfloor - f(\lfloor n/2 \rfloor)\bigr)$，可作为第二种实现或对拍参考（本解未使用，仅作交叉验证）。

## 5. 正确性证明

**引理 1（结构保持）**：设当前序列为 $A_k = head + k \cdot step$（$0 \le k < rem$，$rem > 1$）。则一轮删除后：

- 新长度恒为 $\lfloor rem/2 \rfloor$，新公差恒为 $2\,step$；
- 从左到右删时新首项为 $head + step$；
- 从右到左删时，$rem$ 为偶数则新首项为 $head$，$rem$ 为奇数则为 $head + step$。

**证明**：从左到右删除 1-based 位置 $1, 3, 5, \dots$，即删除下标 $k$ 为偶数的项，保留下标 $k$ 为奇数的项：$head+step,\ head+3step,\ head+5step, \dots$。这是首项 $head+step$、公差 $2\,step$ 的等差数列，项数 $\lfloor rem/2 \rfloor$。

从右到左删除 1-based 位置 $rem, rem-2, rem-4, \dots$，保留位置 $rem-1, rem-3, \dots$。若 $rem$ 为偶数，保留位置均为奇数，最小者为 1，对应首项 $head$；若 $rem$ 为奇数，保留位置均为偶数，最小者为 2，对应 $head + step$。相邻保留位置相差 2，故公差为 $2\,step$，项数仍为 $\lfloor rem/2 \rfloor$。∎

**引理 2（循环不变量）**：每次进入循环体时，剩余序列恰为 $head, head+step, \dots, head+(rem-1)step$。

**证明**：初始 $head = 1,\ step = 1,\ rem = n$，正是 $[1, n]$，成立。设某轮开始时成立，由引理 1，删除后仍是等差数列且首项、公差、长度与代码的更新式一致（左删无条件加 $step$，右删仅 $rem$ 为奇数时加 $step$，长度除以 2，公差乘 2），故下一轮开始时仍成立。∎

**引理 3（必然终止）**：$rem > 1$ 时 $\lfloor rem/2 \rfloor \le rem - 1 < rem$，故 $rem$ 严格递减；第 $k$ 轮后 $rem = \lfloor n/2^k \rfloor$，至多 $\lceil \log_2 n \rceil$ 轮后 $rem = 1$。

**证明**：$rem \ge 2$ 时 $\lfloor rem/2 \rfloor \le rem - 1$，严格递减；反复取整可交换，得 $rem_k = \lfloor n/2^k \rfloor$，取 $k = \lceil \log_2 n \rceil$ 即 $rem_k = 1$。∎

**定理**：算法返回的值就是 $arr$ 最后剩下的数字。

**证明**：由引理 2，循环退出时（$rem = 1$）剩余序列为单项 $head$，即最后剩下的数字；由引理 3，循环必然在有限轮后退出。$n = 1$ 时循环不执行，$head = 1$ 同样正确。∎

## 6. 复杂度分析

- **时间**：$O(\log n)$。每轮只做常数次加减乘除与一次判断，$rem$ 每轮减半，共 $\lceil \log_2 n \rceil \le 30$ 轮；$n = 10^9$ 时约 30 次迭代。
- **空间**：$O(1)$。只用 $head$、$step$、$rem$、$left$ 四个标量，与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int lastRemaining(int n) {
        long long head = 1;   // 当前序列首项
        long long step = 1;   // 当前公差
        long long rem = n;    // 当前剩余个数
        bool left = true;     // 本轮是否从左到右

        while (rem > 1) {
            // 左删必删首项；右删仅在剩余个数为奇数时删到首项
            if (left || rem % 2 == 1) head += step;
            rem /= 2;         // 长度减半
            step *= 2;        // 公差翻倍
            left = !left;     // 换方向
        }
        return (int)head;
    }
};
```

### Python

```python
class Solution:
    def lastRemaining(self, n: int) -> int:
        head, step, rem = 1, 1, n
        left = True                  # 第一轮从左到右
        while rem > 1:
            # 左删必删首项；右删仅在剩余个数为奇数时删到首项
            if left or rem % 2 == 1:
                head += step
            rem //= 2                # 长度减半
            step *= 2                # 公差翻倍
            left = not left          # 换方向
        return head
```

## 8. 边界情况与易错点

1. **$n = 1$**：循环不进入，返回 1。不要写成 `while rem > 0`，否则会把唯一的数也删掉。
2. **首轮方向**：`left` 初值必须是 `true`。反例 $n = 2$：正确过程是 $[1,2] \to [2]$，答案 2；若首轮按从右到左处理会得到 1。
3. **判据是「当前 $rem$ 的奇偶」而不是「$n$ 的奇偶」**：$n = 9$ 时第 2 轮 $rem = 4$ 为偶数，而 $n$ 是奇数。用 $n$ 的奇偶判断会把 $head$ 错移成 4，最终得到 8。
4. **更新顺序不能反**：先判 $head$、再改 $rem$ 与 $step$。若先执行 `step *= 2`，`head` 会多走一个公差；若先执行 `rem /= 2` 再判断奇偶，$n = 10$ 的第 2 轮会把 $rem = 5$ 误读成 2，输出 6 而非 8。
5. **别真的建数组**：$n = 10^9$ 时内存直接爆；即便用 `vector<char>` 也要 1 GB。本题的状态量与 $n$ 无关。
6. **删除位置的理解**：左删删的是 1-based 第 $1,3,5,\dots$ 个，对应 0-based 下标 $0,2,4,\dots$；右删删的是 1-based 第 $rem, rem-2, \dots$ 个。把两者记反会得到「保留偶数位」的错误结论。
7. **整除**：C++ 中 `rem` 非负，`rem /= 2` 即下取整；Python 必须用 `//`，用 `/` 会得到浮点数并在 $n$ 较大时丢失精度。
8. **类型**：虽然可证明 $head + step \le n$，仍建议用 `long long`；若把约束放宽到 $10^{18}$，`int` 会溢出。
