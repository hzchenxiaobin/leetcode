# LeetCode 环和杆 题解

## 1. 题目概述

- **标题 / 题号**：环和杆（#2103，easy）
- **链接**：https://leetcode.cn/problems/rings-and-rods/
- **来源**：LeetCode 第 271 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串、位运算

**题意**：`n` 个环（红 `R`、绿 `G`、蓝 `B` 三色）穿在编号 `0` ~ `9` 的 10 根杆上。给定长度 `2n` 的字符串 `rings`，每两个字符描述一个环：偶数位是颜色，奇数位是杆号。返回**同时集齐全部三种颜色环**的杆的数量。

**约束**：

- `rings.length == 2 * n`，`1 <= n <= 100`
- 偶数下标是 `'R'` / `'G'` / `'B'`，奇数下标是 `'0'` ~ `'9'`

## 2. 示例

**示例 1**

```text
输入：rings = "B0B6G0R6R0R6G9"
输出：1
解释：
- 杆 0：B、G、R → 三色齐全 ✓
- 杆 6：B、R、R → 只有红蓝两种 ✗
- 杆 9：G → 只有一种 ✗
答案为 1。
```

**示例 2**

```text
输入：rings = "B0R0G0R9R0B0G0"
输出：1
解释：
- 杆 0：B、R、G、R、B、G 共 6 个环，重复颜色不影响，三色齐全 ✓
- 杆 9：仅 R
答案为 1。
```

**示例 3**

```text
输入：rings = "G4"
输出：0
解释：只有一个环，不可能集齐三色。
```

## 3. 解题思路

### 3.1 暴力思路：每根杆一个颜色集合

签到题最短路径：开 10 个集合 `sets[rod]`，遍历字符串把颜色 `add` 进对应杆的集合，最后数大小为 3 的集合个数。时间 `O(n)`、空间 `O(n)`，能过。但注意到两个**定常约束**——颜色只有 3 种、杆只有 10 根——每个"颜色集合"都可以压成 3 个比特，用 10 个整数代替 10 个集合。

### 3.2 核心观察：位掩码编码三色存在性

![位掩码统计：解析颜色对并累积到 mask 数组](images/rings_rods_bitmask_stats.svg)

- `R` → `1`（`0b001`），`G` → `2`（`0b010`），`B` → `4`（`0b100`）
- 每根杆维护 `mask[rod]`，遇到颜色就 `mask[rod] |= bit`
- **按位或天然去重**：同色环套多次，对应位只被置 1 一次（幂等操作），等价于集合的 `add`
- 杆 `d` 三色齐全 ⟺ `mask[d] == 7`（`0b111`，三位全 1）

> 💡 判满集必须写 `mask == 7`，不能写 `mask & 7`——后者只要任一位为 1 就非零，会把只有 1~2 色的杆也判真。

### 3.3 算法流程

1. 遍历 `rings`，步长为 2：`rings[i]` 是颜色，`rings[i+1]` 是杆号
2. 解析 `(color, rod)`，执行 `mask[rod] |= bit(color)`
3. 终统计：数有多少个 `d` 满足 `mask[d] == 7`

### 3.4 示例演算

![示例 1 的杆上环分布与逐杆判定](images/rings_rods_example_rods.svg)

对 `rings = "B0B6G0R6R0R6G9"` 逐对演算（`R=001, G=010, B=100`）：

| 颜色对 | 位 | 杆 | mask 变化 |
|--------|------|----|-----------|
| B0 | 100 | 0 | `mask[0]`: 000 → 100 |
| B6 | 100 | 6 | `mask[6]`: 000 → 100 |
| G0 | 010 | 0 | `mask[0]`: 100 → 110 |
| R6 | 001 | 6 | `mask[6]`: 100 → 101 |
| R0 | 001 | 0 | `mask[0]`: 110 → 111 ✓ |
| R6 | 001 | 6 | `mask[6]`: 101 → 101（不变） |
| G9 | 010 | 9 | `mask[9]`: 000 → 010 |

终态：`mask[0] = 111`，`mask[6] = 101`，`mask[9] = 010`，其余杆均为 `000`。只有杆 0 满足 `== 7`，答案为 `1`。

## 4. 算法细节

1. **颜色到位的映射**：`R=1`、`G=2`、`B=4` 是三个互不重叠的比特位，Python 用字典、C++ 用条件表达式实现
2. **定长数组代替哈希**：杆号仅 `0..9`，`mask[10]` 直接以 `rings[i+1] - '0'` 为下标，无需动态结构
3. **幂等累加**：`|=` 保证重复颜色对无副作用，无需判重逻辑
4. **满集判定的等价写法**：`mask == 7`、`mask == 0b111`、`popcount(mask) == 3` 三者等价；推广到 `k` 种颜色时用 `mask == (1 << k) - 1` 最自然

## 5. 正确性证明

**引理 1**：处理完所有颜色对后，`mask[d]` 的第 `k` 位为 1，当且仅当第 `k` 种颜色至少出现在某个 `(颜色, d)` 对中。

**证明**：对已处理的对数归纳。初始 `mask[d] = 0`，所有位为 0。设处理若干对后结论成立，再处理一对 `(c, d')`：若 `d' ≠ d`，`mask[d]` 不变；若 `d' = d`，按位或只会把 `c` 对应的位从 0 变 1（已是 1 则不变），其余位不受影响，结论仍成立。∎

**定理**：算法返回集齐全部三种颜色环的杆的数量。

**证明**：`mask[d] == 7` 即三个比特位全为 1。由引理 1，这等价于 `R`、`G`、`B` 三种颜色都曾在杆 `d` 上出现，即杆 `d` 集齐三色。终统计遍历 `d = 0..9`，恰好计入且仅计入所有这样的杆。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n)`。遍历 `n` 个颜色对各 `O(1)`，终统计扫描 10 根杆。
- **空间复杂度**：`O(1)`。仅用长度 10 的定长整数数组，与 `n` 无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countPoints(string rings) {
        int mask[10] = {0};
        for (int i = 0; i + 1 < (int)rings.size(); i += 2) {
            int bit = rings[i] == 'R' ? 1 : (rings[i] == 'G' ? 2 : 4);
            mask[rings[i + 1] - '0'] |= bit;
        }
        int ans = 0;
        for (int d = 0; d < 10; ++d) ans += (mask[d] == 7);
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countPoints(self, rings: str) -> int:
        mask = [0] * 10
        bit = {'R': 1, 'G': 2, 'B': 4}
        for i in range(0, len(rings), 2):
            mask[int(rings[i + 1])] |= bit[rings[i]]
        return sum(m == 7 for m in mask)
```

## 8. 边界情况与易错点

1. **单环输入**（`n = 1`，如 `"G4"`）：不可能集齐三色，答案恒为 0，算法自然覆盖，无需特判
2. **重复颜色对**（示例 2 的杆 0 有 6 个环）：`|=` 幂等，重复置位无副作用；不要改用"环数 == 3"之类的判定，会数重
3. **满集判定写 `== 7` 而非 `& 7`**：`mask & 7` 非零只说明"至少一色"，部分匹配与全匹配要区分
4. **下标语义别颠倒**：偶数位是颜色、奇数位是杆号，步长 2 遍历时 `rings[i]` 取色、`rings[i+1]` 取杆
5. **循环边界**：长度保证为偶数，C++ 中写 `i + 1 < rings.size()` 更稳健
6. **答案上界**：只有 10 根杆，答案不超过 10，`int` 足够
