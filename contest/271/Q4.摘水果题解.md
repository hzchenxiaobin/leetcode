# LeetCode 摘水果 题解

## 1. 题目概述

- **标题 / 题号**：摘水果（#2106，hard）
- **链接**：https://leetcode.cn/problems/maximum-fruits-harvested-after-at-most-k-steps/
- **来源**：LeetCode 第 271 场周赛 Q4
- **难度**：困难
- **标签**：数组、二分查找、前缀和、滑动窗口

**题意**：无限数轴上分布着若干水果，`fruits[i] = [position_i, amount_i]` 表示 `position_i` 处有 `amount_i` 个水果，**已按位置升序排列且位置互不相同**。从 `startPos` 出发，每步向左或向右移动一个单位，**总共最多走 $k$ 步**；每到一个位置就把该位置水果**全部摘光**。求能摘到的最大总数。

**约束**：

- $1 \le \text{fruits.length} \le 10^5$
- $0 \le \text{startPos},\ \text{position}_i \le 2 \times 10^5$，位置严格递增
- $1 \le \text{amount}_i \le 10^4$
- $0 \le k \le 2 \times 10^5$

> 💡 约束的隐藏含义：水果总数上界 $10^5 \times 10^4 = 10^9$，恰在 `int32` 上限之内但几乎没有余量（本场 Q2 就是溢出重灾区）；$n$ 高达 $10^5$，$O(n^2)$ 区间枚举约 $10^{10}$ 次不可行，必须利用单调性把一端做成 $O(\log n)$ 甚至均摊 $O(1)$。

> 💡 本题在本仓库另有[每日题解 2106](../../solution/2101-2200/2106_摘水果.md)：以滑动窗口 $O(n)$ 为主线，配面试问答。本篇按**周赛复盘视角**重写：侧重**赛时建模链**（从 $2^k$ 种走法压缩到「选区间」）、**枚举 + 二分**这一赛时主流写法、形状分解变体的陷阱，以及每日版只一笔带过的**引理-定理完整证明链**（足迹区间性 → 两侧下界 → 代价公式 → 单调性 → 枚举完整性）。两篇互为印证。

## 3. 解题思路

### 3.1 赛时破题：从 $2^k$ 种走法到「选区间」

乍看是路径搜索题：每步两个方向，$k$ 步有 $2^k$ 种走法，$k$ 高达 $2 \times 10^5$，搜索空间天文数字。赛时破题的第一问不是「怎么走」，而是「**摘到多少由什么决定**」——答案：只由「**去过哪些位置**」决定，与到达顺序无关（水果摘了就消失，但每个位置只摘一次，顺序不影响总量）。

于是走法细节全部坍缩：我们只关心足迹的**范围**。接下来两步观察把问题彻底转成「选区间」：

1. **足迹是连续区间**（单位步移动的连续性）——不用记录形状，只用一对端点 $[L, R]$；
2. **代价有闭式**（至多一次转弯）——覆盖 $[L, R]$ 的最少步数是 $\min(2a+b,\ a+2b)$。

朴素枚举区间：水果位置有序，区间端点取在水果上（$O(n^2)$ 对）+ 前缀和 $O(1)$ 查和，共 $O(n^2)$——$10^{10}$ 量级，仍不可行。还差最后一步：**固定一端时，代价关于另一端单调**——这一步把 $O(n^2)$ 砍成 $O(n \log n)$（二分）乃至 $O(n)$（滑窗）。

### 3.2 核心观察：足迹 = 含 startPos 的区间，先走的一侧要走两遍

![核心观察：足迹区间与两种折返形状的代价](images/wc271_q4_interval_cost_concept.svg)

**观察一（区间性）**：每步移动一个单位，所以任意路线的**足迹**（访问过的位置集合）是连续区间 $[L, R]$，且**必含起点** $s = \text{startPos}$。摘到的水果恰好是 $[L, R]$ 内的全部水果——一颗不多（外面没到过）、一颗不少（路过即摘光）。

**观察二（代价公式）**：要同时碰到分居 $s$ 两侧的 $L$ 和 $R$，必有一侧被完整走过两遍（去 + 回）。记 $a = s - L$、$b = R - s$：

| 路径形状 | 步数 | 说明 |
|---------|------|------|
| 先左后右 | $2a + b$ | 左侧走两遍，右侧一遍 |
| 先右后左 | $a + 2b$ | 右侧走两遍，左侧一遍 |

覆盖 $[L, R]$ 的最少步数 $= \min(2a+b,\ a+2b)$——**先走短的一侧更划算**。单侧退化无需特判：$b = 0$ 时 $\min(2a,\ a) = a$（只向左），$a = 0$ 时 $\min(b,\ 2b) = b$（只向右），公式自动涵盖。

至此问题归约为：**在有序水果数组上选一段连续区间，使代价 $\le k$，最大化区间内水果总数**（前缀和 $O(1)$ 查询）。

### 3.3 算法流程：枚举左端 + 二分最大右端

![算法流程：枚举左端与二分右端](images/wc271_q4_binary_search_flow.svg)

水果区间用下标 $[i, j]$ 表示（位置 $p_i \le p_j$），定义**代价函数**（$O(1)$ 计算）：

$$
\text{cost}(i, j) = \begin{cases} s - p_i & p_j \le s \quad(\text{整段在左：向左走到底})\\[2pt] p_j - s & p_i \ge s \quad(\text{整段在右：向右走到底})\\[2pt] \min(2a + b,\ a + 2b) & p_i < s < p_j \quad(\text{跨两侧}) \end{cases}
$$

其中 $a = s - p_i$、$b = p_j - s$。三个分支在交界处（$p_j = s$ 或 $p_i = s$）取值一致，是一个无缝的整体函数。

**关键单调性**：固定左端 $i$，$\text{cost}(i, j)$ 关于 $j$ **单调不减**——左区（$p_j \le s$）恒为 $a$；越过 $s$ 之后 $\min(2a+b,\ a+2b) \ge a$ 且随 $b$ 递增；$p_i \ge s$ 时就是 $p_j - s$ 直接递增。于是可行的 $j$ 是 $[i, n-1]$ 的一段**前缀**，「判定为真」随 $j$ 增大单调转假——**二分合法**。

又因 $\text{amount} \ge 1$，区间和随 $j$ 严格增，每个 $i$ 只需二分出**最大**可行 $j$，取 $\text{prefix}[j+1] - \text{prefix}[i]$ 更新答案即可。整体 $O(n \log n)$。

> ⚠️ **形状分解变体（赛时另一主流写法）及其陷阱**：分别枚举两种形状的最远右界——先左后右 $R_1 = s + k - 2a$（需 $2a \le k$）；先右后左 $R_2 = s + \lfloor (k-a)/2 \rfloor$（需 $a \le k$），各自二分水果位置取和。注意两点：**纯向左**（$a$ 介于 $k/2$ 与 $k$）不被 $R_1$ 覆盖、恰好被 $R_2$ 覆盖（$R_2 \ge s$，窗口 $[p_i, R_2] \supseteq [p_i, s]$）；而 $p_i > s$ 的下标若把负的 $a$ 直接代入 $R_1 = s + k - 2a$，会把预算虚增 $2|a|$、得到**不可达的远边界**——必须 clamp $a = 0$。统一三分支 $\text{cost}$ 函数从根上免疫这两类分支漏洞，这也是本篇选它作主线的原因。

### 3.4 示例演算

![示例 2 完整演算](images/wc271_q4_walkthrough.svg)

对示例 2（$s = 5$，$k = 4$）逐个左端走查：

| $i$ | $p_i$ | 情形与关键量 | 二分最大 $j$ | 候选区间和 |
|-----|-------|-------------|--------------|-----------|
| 0 | 0 | 整段在左，$a = 5 > k$ | 无（$\text{cost}(0,0)=5$） | 跳过 |
| 1 | 4 | 跨两侧，$a = 1$ | $j = 4$：$\text{cost}(1,4) = \min(4,5) = 4 \le 4$；$j=5$ 时 $\min(7,11) = 7$ ✗ | $1+7+2+4 = \mathbf{14}$ |
| 2 | 5 | $p_i = s$（$a = 0$） | $j = 4$：$2 \le 4$；$j=5$ 时 $5$ ✗ | $7+2+4 = 13$ |
| 3 | 6 | 整段在右 | $j = 4$：$2 \le 4$；$j=5$ 时 $5$ ✗ | $2+4 = 6$ |
| 4 | 7 | 整段在右 | $j = 4$：$2 \le 4$ | $4$ |
| 5 | 10 | 整段在右，太远 | 无（$\text{cost}(5,5)=5$） | 跳过 |

答案 $14$，路径还原：$5$（摘 7）$\to$ 左 $4$（摘 1）$\to$ 右 $6$（摘 2）$\to$ $7$（摘 4），共 $1 + 3 = 4$ 步，与官方解释一致。三个看点：**①** $i = 0$ 行展示「左端自身不可达即整体跳过」（$a = 5$ 超预算，任何 $j$ 都救不回来）；**②** $i = 1$ 行 $j$ 从 $4$ 推到 $5$ 时代价跳到 $7$——右端越过可达边界后**单调转假**，二分正是吃这个性质；**③** $i = 2$ 行 $p_i = s$ 落在「整段在右」分支（$a = 0$），无需任何特判。示例 1 同法得 $9$（右侧 $6..8$，代价 $3$）；示例 3 所有 $i$ 全部跳过，答案自然为 $0$。

## 4. 算法细节

1. **前缀和**：$\text{prefix}[i+1] = \text{prefix}[i] + \text{amount}_i$，区间和 $\text{sum}(i..j) = \text{prefix}[j+1] - \text{prefix}[i]$；`fruits` 题面保证已按位置升序，**无需再排序**。
2. **代价函数三分支**：见 §3.3 公式。分支条件用 $\le$ 还是 $<$ 均可——在 $p_j = s$ 处第一分支给 $a$、第三分支给 $\min(2a + 0,\ a + 0) = a$，取值一致，函数在交界连续，不会因等号归属产生缝隙。
3. **二分写法**：`lo = i, hi = n-1, j = -1`，标准「找最后一个满足条件的位置」；若 `cost(i, i) > k` 则 `j` 保持 `-1`，用 `j >= i` 判定跳过。判定谓词 $P(j) = [\text{cost}(i, j) \le k]$ 前真后假（引理 5），二分不动式成立。
4. **每个 $i$ 只查最大 $j$ 的正确性**：$\text{amount} \ge 1 > 0$ 使区间和随 $j$ 严格增，故固定 $i$ 的最优 $j$ 必是可行前缀的最右端——把内层从「枚举所有 $j$」压成「一次二分」的关键。
5. **溢出审计**：$2a + b \le 2 \cdot (2 \times 10^5) + 2 \times 10^5 = 6 \times 10^5$，`int` 安全；答案上界 $10^9$ 贴着 `int32` 上限 $2147483647$，`prefix` 与 `ans` 直接用 `long long`（C++）一步到位，杜绝「恰好装下但没有余量」的惊险（对比本场 Q2 的 $10^{15}$ 必须 `long long`，本题属于「能过但不该赌」）。Python 无此虑。
6. **复杂度**：外层 $n$ 次枚举，内层一次 $O(\log n)$ 二分，$\text{cost}$ 每次 $O(1)$——总 $O(n \log n)$、空间 $O(n)$。赛后优化：用引理 5 的同一单调性把二分换成**双指针滑动窗口**即 $O(n)$（[每日版 2106](../../solution/2101-2200/2106_摘水果.md)主线，代价函数与本篇完全相同）；形状分解变体同为 $O(n \log n)$。

## 5. 正确性证明

**引理 1（足迹区间性）**：任意行走路线的足迹是一个包含 $s$ 的连续区间 $[L, R]$（可退化为一点）；摘到的水果恰为位置在 $[L, R]$ 内的全部水果。

**证明**：设 $L$、$R$ 为足迹的最小 / 最大位置，则 $s \in [L, R]$。对任意 $x \in [L, R]$，取访问 $L$ 的时刻 $t_1$ 与访问 $R$ 的时刻 $t_2$（$t_1 \ne t_2$，不妨 $t_1 < t_2$）：从 $t_1$ 的位置 $L$ 到 $t_2$ 的位置 $R$，每步移一个单位，由介值性必经过 $x$，故 $x$ 在足迹中——足迹 $\supseteq [L, R]$；又由 $L$、$R$ 定义足迹 $\subseteq [L, R]$，故相等。摘取规则「每到一位置摘光」且水果不可再生：位置在 $[L, R]$ 内的水果全部被摘，区间外的一颗未摘。∎

**引理 2（两侧下界）**：从 $s$ 出发、既访问 $L < s$ 又访问 $R > s$ 的任意路线，步数 $\ge \min(2a + b,\ a + 2b)$，其中 $a = s - L \ge 0$、$b = R - s \ge 0$。

**证明**：路线必先到达 $L, R$ 之一。若先到 $L$：从 $s$ 到 $L$ 至少 $a$ 步（每步移一单位），其后从 $L$ 到 $R$ 至少 $R - L = a + b$ 步，合计 $\ge 2a + b$；先到 $R$ 对称地 $\ge b + (a + b) = a + 2b$。两种情形必居其一，故步数 $\ge \min(2a+b,\ a+2b)$。∎

**引理 3（代价公式）**：覆盖区间 $[L, R]$（$L \le s \le R$，$a = s - L$、$b = R - s$）的最少步数为 $\min(2a + b,\ a + 2b)$；退化为单侧（$b = 0$ 或 $a = 0$）时公式自动给出 $a$ 或 $b$。

**证明**：上界——「先左后右」折线 $s \to L \to R$ 恰走 $a + (a + b) = 2a + b$ 步且覆盖 $[L, R]$；「先右后左」同理 $a + 2b$ 步。下界——$a, b > 0$ 时由引理 2；$b = 0$ 时覆盖 $[L, s]$ 至少要到达 $L$，从 $s$ 出发已需 $a$ 步（$a = 0$ 对称）。上界与下界夹逼即得。∎

**引理 4（问题归约）**：原问题的答案等于 $\max\{\,\text{sum}(i..j) : \text{cost}(i, j) \le k\,\}$，其中 $\text{cost}(i, j)$ 按 §3.3 三分支定义（对水果段 $i..j$ 的**有效区间** $[\min(p_i, s),\ \max(p_j, s)]$ 取引理 3 的最小步数）。

**证明**：任一 $\le k$ 步的可行路线，由引理 1 其足迹 $[L, R] \ni s$，摘到的水果是 $[L, R]$ 内全部水果，即水果数组的连续段 $[i..j]$（$p_i$ 为 $[L, R]$ 内最小水果位置、$p_j$ 为最大），且有效区间 $[\min(p_i, s), \max(p_j, s)] \subseteq [L, R]$；步数 $\ge$ 引理 3 于 $[L, R]$ 的值 $\ge$ 于有效区间的值（区间更小代价不增），即 $\text{cost}(i, j) \le k$。反向，任一满足 $\text{cost}(i, j) \le k$ 的段，按引理 3 上界对应的折线路线走（有效区间的覆盖路线自动经过 $p_i$ 与 $p_j$ 之间每个位置），$\le k$ 步摘到 $\text{sum}(i..j)$。两个方向的收益一致，取最大即等价。∎

**引理 5（单调性）**：固定 $i$，$\text{cost}(i, j)$ 关于 $j \in [i, n-1]$ 单调不减；因此 $\{\, j : \text{cost}(i, j) \le k \,\}$ 是 $[i, n-1]$ 的前缀（可能为空）。

**证明**：分三段。若 $p_i \ge s$：$\text{cost}(i, j) = p_j - s$ 随 $j$ 严格递增。若 $p_i < s$，记 $a = s - p_i$：当 $p_j \le s$ 时 $\text{cost} = a$ 恒定；当 $p_j > s$ 时 $\text{cost} = \min(2a + b,\ a + 2b) \ge a$（因 $a, b \ge 0$）且 $b = p_j - s$ 随 $j$ 递增使两个变元都递增，$\min$ 不减。段间衔接处由 $\ge a$ 保证不下降。整体单调不减，与阈值 $k$ 比较即得前缀性。∎

**定理**：算法返回的 `ans` 等于可摘到的最大水果总数。

**证明**：**（ans ≤ OPT）** 算法每轮只对满足 $\text{cost}(i, j) \le k$ 的 $(i, j)$ 累计 $\text{sum}(i..j)$，由引理 4 反向，每个这样的段都对应一条真实可行的 $\le k$ 步路线，故任何被计入的值 $\le$ OPT。**（ans ≥ OPT）** 设最优路线摘到 $\text{OPT}$ 个水果，由引理 4 正向，其水果段 $[i^\*, j^\*]$ 满足 $\text{cost}(i^\*, j^\*) \le k$；由引理 5 该 $j^\*$ 落在 $i^\*$ 的可行前缀内，故二分所得 $j_{\max}(i^\*) \ge j^\*$，再由 $\text{amount} \ge 1$ 知 $\text{sum}(i^\*, j_{\max}(i^\*)) \ge \text{sum}(i^\*, j^\*) = \text{OPT}$，这一项会被算法计入。两个不等式夹逼，`ans` = OPT。∎

## 6. 复杂度分析

- **时间复杂度 $O(n \log n)$**
  - 前缀和预处理 $O(n)$；
  - 外层枚举左端 $n$ 次，每次内层二分 $O(\log n)$、代价函数与区间和均为 $O(1)$；
  - 赛后把二分换成滑动窗口双指针（左右端各至多推进 $n$ 次）可到 $O(n)$，见每日版主线——两者共用引理 1–3 的全部建模与引理 5 的单调性。
- **空间复杂度 $O(n)$**：前缀和数组；其余为 $O(1)$ 标量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxTotalFruits(vector<vector<int>>& fruits, int startPos, int k) {
        int n = fruits.size();
        vector<long long> prefix(n + 1);
        for (int i = 0; i < n; ++i) prefix[i + 1] = prefix[i] + fruits[i][1];

        // cost(i, j)：摘光水果 i..j 的最少步数（有效区间 [min(p_i,s), max(p_j,s)]）
        auto cost = [&](int i, int j) -> long long {
            int L = fruits[i][0], R = fruits[j][0];
            if (R <= startPos) return (long long)startPos - L;  // 整段在左：向左走到底
            if (L >= startPos) return (long long)R - startPos;  // 整段在右：向右走到底
            long long a = startPos - L, b = R - startPos;       // 跨两侧：先走的一侧算两次
            return min(2 * a + b, a + 2 * b);
        };

        long long ans = 0;
        for (int i = 0; i < n; ++i) {
            // 固定 i，cost(i, j) 随 j 单调不减：二分最后一个 cost <= k 的 j
            int lo = i, hi = n - 1, j = -1;
            while (lo <= hi) {
                int mid = lo + (hi - lo) / 2;
                if (cost(i, mid) <= k) { j = mid; lo = mid + 1; }
                else hi = mid - 1;
            }
            if (j >= i) ans = max(ans, prefix[j + 1] - prefix[i]);
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maxTotalFruits(self, fruits: List[List[int]], startPos: int, k: int) -> int:
        n = len(fruits)
        prefix = [0] * (n + 1)
        for i in range(n):
            prefix[i + 1] = prefix[i] + fruits[i][1]

        def cost(i: int, j: int) -> int:
            L, R = fruits[i][0], fruits[j][0]
            if R <= startPos:
                return startPos - L      # 整段在左：向左走到底
            if L >= startPos:
                return R - startPos      # 整段在右：向右走到底
            a, b = startPos - L, R - startPos
            return min(2 * a + b, a + 2 * b)

        ans = 0
        for i in range(n):
            lo, hi, j = i, n - 1, -1
            while lo <= hi:
                mid = (lo + hi) // 2
                if cost(i, mid) <= k:
                    j = mid
                    lo = mid + 1
                else:
                    hi = mid - 1
            if j >= i:
                ans = max(ans, prefix[j + 1] - prefix[i])
        return ans
```

> 💡 两份实现均通过三个官方示例（9 / 14 / 0）与 5000 轮随机数据对拍（枚举原始位置区间 $[L, R]$、独立计算覆盖代价的暴力 oracle，零失配）。

## 8. 边界情况与易错点

1. **单侧窗口套错公式（头号陷阱）**：区间整段在左（$p_j \le s$）的正确代价是 $s - p_i$；若误用跨两侧公式且把 $b = p_j - s < 0$ 代入 $\min(2a+b,\ a+2b)$，会算出**偏小甚至为负**的代价，把不可达区间当成可达——WA 于「全部水果在起点一侧」的测试点（如 `fruits=[[0,5]], startPos=5, k=5` 应得 5，误算代价 $\min(2 \cdot 5 - 5, 5 - 10) = -5 \le 5$ 会「通过」但 `fruits=[[0,5]], k=4` 时误得 5）。三分支 `cost` 从根上免疫。
2. **形状分解的 clamp**：见 §3.3 警告框——$p_i > s$ 时负的 $a$ 代入 $R_1 = s + k - 2a$ 虚增预算；纯向左（$k/2 < a \le k$）只有 $R_2$ 覆盖。写形状分解务必自测这两个点。
3. **不必回到 startPos**：「先左后右」代价是 $2a + b$ 而非 $2a + 2b$——终点任意是题面原文（问的是摘取总数，不是回路）。多算 $b$ 会漏掉恰好压线的解（示例 2 的 $k = 4 = 2 \cdot 1 + 2$ 正是压线解）。
4. **起点即水果 / k = 0**：`startPos` 处有水果时 0 步即可摘（$p_i = s$ 落在「整段在右」分支，$\text{cost}(i, i) = 0$）；$k = 0$ 时其余全部跳过，答案自然正确，无需特判。
5. **起点在所有水果同一侧**：枚举天然覆盖（全左走「向左走到底」分支、全右走「向右走到底」分支），无需特判；注意此时也不需要「先走到最近水果」的附加步数——走过的路上没水果，步数直接按端点距离算即可。
6. **二分落空**：`j` 初始化 `-1`、循环后用 `j >= i` 过滤；`cost(i, i) > k`（左端自身不可达）时整行跳过——漏判会把 `prefix[0]` 之类错误值计入。
7. **答案上界 $10^9$ 与 `int`**：`n · max(amount) = 10^9 < 2147483647`，`int` 恰好装下但没有余量；C++ 中 `prefix`、`ans` 统一 `long long`，返回前再转 `int`（本题安全，但养成「先估上界再定类型」的习惯——本场 Q2 的 $10^{15}$ 就是反面教材）。
8. **别枚举步数**：步数空间 $2 \times 10^5$ 且每个步数不携带独立信息；正确状态空间是**水果区间端点**（有序、可前缀和、有单调性）。同理别建 $2 \times 10^5$ 长的位置数组做 DP——$O(k)$ 位置 DP 虽可过（$k$ 与 $n$ 同阶），但既多空间又多代码量，赛时性价比远低于本解法。
9. **重复排序**：题面已保证 `fruits` 按 `position` 升序且互不相同，排序是纯浪费（虽不致错）。

**延伸思考**：

- **恰好走 $k$ 步**（必须走满）：答案不变——只要 $\text{cost} \le k$，多出的步数总可消耗在覆盖区间内的来回抖动（如终点少走 / 多走一格再折返，$+1$ 与 $+2$ 步都可构造），不影响摘取量；若 $\min \text{cost} > k$ 则无解为 $0$。
- **限制至多两次转弯**：足迹变成至多两个分离区间的并——问题升维为「选至多两段区间」，需按转折点 DP 或枚举分割点 + 前缀最优化，$O(n)$ 或 $O(n \log n)$ 仍可解，但引理 1 的「单一区间」不再成立，整套建模要重推。
- **二维网格版**（四方向移动）：足迹非凸、也不再是区间，$[L, R]$ 端点模型彻底失效，需回到 BFS / 状压 DP 类方法——这正是「单位步 + 一维」两个前提各自承担的角色。
