# LeetCode 子数组范围和 题解

## 1. 题目概述

- **标题 / 题号**：子数组范围和（#2104，medium）
- **链接**：https://leetcode.cn/problems/sum-of-subarray-ranges/
- **来源**：LeetCode 第 271 场周赛 Q2
- **难度**：中等
- **标签**：栈、数组、单调栈、贡献计数

**题意**：给定整数数组 `nums`。子数组的**范围**（range）定义为子数组中**最大元素与最小元素的差值**（$\max-\min$）。返回 `nums` 中**所有**子数组范围的**总和**。子数组是连续非空的元素序列。

**约束**：

- $1 \le \text{nums.length} \le 1000$
- $-10^9 \le \text{nums[i]} \le 10^9$

**进阶**：你能设计一种时间复杂度为 $O(n)$ 的解决方案吗？

> 💡 本题在本仓库另有[每日题解 2104](../../solution/2101-2200/2104_子数组范围和.md)：以「贡献计数 + 单调栈的模板直觉、实现细节与面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时复杂度决策**（$n \le 1000$ 时滚动维护 $O(n^2)$ 即正解，先拿分再谈进阶）、**滚动极值的归纳不变式**、**归属刻画 → 单调栈引理 → 不重不漏定理**的完整证明链，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3]
输出：4
解释：6 个子数组的范围分别为：
  [1]     → 1-1 = 0
  [2]     → 2-2 = 0
  [3]     → 3-3 = 0
  [1,2]   → 2-1 = 1
  [2,3]   → 3-2 = 1
  [1,2,3] → 3-1 = 2
  和 = 0+0+0+1+1+2 = 4
```

解释：6 个子数组的范围：0, 0, 0, 2, 0, 2，和 = 4。
注意两个 3 相等——这正是后文「一侧严格、一侧含等号」讨论的伏笔。
```

输入：nums = [4,-2,-3,4,1]

```

## 3. 解题思路

### 3.1 赛时第一反应：滚动维护，O(n²) 直接拿分

读完题先看数据范围：$n \le 1000$，子数组共 $\frac{n(n+1)}{2} \approx 5\times10^5$ 个。**Q2 的定位就是送分题**——$O(n^2)$ 完全在时限内，赛时的正确决策是立刻写暴力、把时间留给 Q3/Q4。

朴素暴力有一个隐坑：若对每个子数组 $[i..j]$ 都重新扫描一遍求 max/min，是 $O(n^3) \approx 1.7\times10^8$ 次比较，C++ 勉强擦边、毫无必要。**一行优化**：固定左端点 $i$、右端点 $j$ 右移时**增量维护**最值——新信息只有 `nums[j]` 一个元素，它要么刷新最值、要么不动。内层降到 $O(1)$，总计 $O(n^2) \approx 5\times10^5$，瞬间跑完：

```text
ans = 0
for i in 0..n-1:
    mn = mx = nums[i]          # 子数组 [i..i] 的最值
    for j in i..n-1:           # j 每右移一格
        mn = min(mn, nums[j])  # 只有新元素可能改变最值
        mx = max(mx, nums[j])
        ans += mx - mn         # 恰是子数组 [i..j] 的范围
```

> ⚠️ 「每个子数组从零重算」到「固定一端、滚动维护」是把 $O(n^3)$ 压到 $O(n^2)$ 的通用范式：**增量信息只有一个新元素**，聚合值（min / max / 和 / 集合）随右端点单调演化。[2913. 子数组不同元素数目的平方和](../../solution/2901-3000/2913_子数组不同元素数目的平方和I.md)是同一手感的近亲——那里滚动维护的是集合大小。

$O(n^2)$ 时间、$O(1)$ 空间，在本题数据范围下就是正解。但题目**进阶追问 $O(n)$**——赛后复盘值得把这条线走通，因为同族题（907、2281）把 $n$ 抬到 $10^5$ 时，$O(n^2)$ 直接出局。

### 3.2 核心观察：拆和 + 贡献计数

**第一步，拆和**。对「差」求和，先拆成两个独立的「极值求和」：

$$\sum_{S}(\max S-\min S)=\sum_{S}\max S-\sum_{S}\min S=\text{sumMax}-\text{sumMin}$$

于是只剩一个原型问题：**所有子数组最大值之和**（sumMax）；最小值版本是它的完全镜像。

**第二步，贡献计数**。不枚举子数组，而是对每个元素问：**你是多少个子数组的最大值？** 设答案为 $\text{cnt}[i]$，则

$$\text{sumMax}=\sum_i \text{nums}[i]\cdot \text{cnt}[i]$$

**cnt[i] 怎么算？** 子数组以 `nums[i]` 为最大值，当且仅当它包含 $i$ 且不含比 `nums[i]` 更大的元素。相等元素带来归属歧义（`[1,3,3]` 里有两个 3），约定**归属给最右的最大值**，则边界定义为：

- $L_i$：$i$ 左侧第一个**严格大于** `nums[i]` 的下标（不存在则 $-1$）；
- $R_i$：$i$ 右侧第一个**大于等于** `nums[i]` 的下标（不存在则 $n$）。

于是左端点可取 $L_i{+}1 .. i$ 共 $(i-L_i)$ 个、右端点可取 $i .. R_i{-}1$ 共 $(R_i-i)$ 个，乘法原理：

$$\text{cnt}[i]=(i-L_i)\cdot(R_i-i)$$

![核心观察：拆和与贡献计数](images/wc271_q2_contribution_concept.svg)

> ⚠️ **重复元素是本题头号 WA 点**：两侧都严格 `>` 会把含两个相等最大值的子数组**数两遍**；两侧都用 `≥` 则**一遍都不数**（漏项甚至能把答案算成负数）。必须**一侧严格、一侧含等号**——本文固定「左严格、右含等号」，让每个子数组**唯一归属**到最右极值位置。用 `[1,3,3]` 自测：正确答案 4，两侧都严格时算出 7，两侧都含等号时算出 $-2$（详见 §8 的 WA 对照表）。

### 3.3 算法流程：单调栈一次扫描同时求出 L 和 R

$L_i$、$R_i$ 正是「两侧下一个更大元素」——单调栈的看家本领。以 sumMax 为例，维护**值严格递减**的栈（存下标），`i` 从左到右扫：

1. **弹栈结算**：只要栈非空且 `nums[top] <= nums[i]`，弹出 `j`——此刻 `i` 正是 $j$ 的右边界 $R_j$（右侧第一个 $\ge$ `nums[j]` 者），而弹出后的**新栈顶**正是 $j$ 的左边界 $L_j$（左侧第一个 $>$ 者）。**出栈瞬间**累加 `nums[j] * (j - left) * (right - j)`。
2. **入栈**：弹完剩下的都严格大于 `nums[i]`，把 `i` 压入，递减性保持。
3. **哨兵**：外层循环写到 `i == n` 才结束（把 `nums[n]` 视作 $+\infty$），强制清空栈，给右侧无更大者的元素结算 $R=n$。

每个下标入栈一次、出栈一次，总 $O(n)$。

![单调栈一次扫描流程与结算表](images/wc271_q2_monotonic_stack_flow.svg)

> 💡 一次扫描能同时拿到两边，是因为**一个弹栈动作敲定两个元素的边界**：弹出 `j` 的这一刻，`i` 定下了 `j` 的**右**界；而留在栈里的新栈顶，早在 `i` 入栈时就是 `i` 的**左**界。sumMin 完全镜像——递减栈换递增栈、弹 `<=` 换弹 `>=`，其余一字不改。

### 3.4 示例演算

以 `nums = [4, -2, -3, 4, 1]`（示例 3，答案 59）为例，逐元素计算贡献：

![示例演算：逐元素贡献表](images/wc271_q2_walkthrough.svg)

| `i` | 值 | max：$L, R \to$ cnt | 贡献 | min：$L, R \to$ cnt | 贡献 | 净贡献 |
|-----|----|--------------------|------|--------------------|------|--------|
| 0 | 4 | $-1,\,3 \to 1{\cdot}3 = 3$ | $+12$ | $-1,\,1 \to 1{\cdot}1 = 1$ | $+4$ | $+8$ |
| 1 | -2 | $0,\,3 \to 1{\cdot}2 = 2$ | $-4$ | $-1,\,2 \to 2{\cdot}1 = 2$ | $-4$ | $0$ |
| 2 | -3 | $1,\,3 \to 1{\cdot}1 = 1$ | $-3$ | $-1,\,5 \to 3{\cdot}3 = 9$ | $-27$ | $+24$ |
| 3 | 4 | $-1,\,5 \to 4{\cdot}2 = 8$ | $+32$ | $2,\,4 \to 1{\cdot}1 = 1$ | $+4$ | $+28$ |
| 4 | 1 | $3,\,5 \to 1{\cdot}1 = 1$ | $+1$ | $2,\,5 \to 2{\cdot}1 = 2$ | $+2$ | $-1$ |

- sumMax $= 12-4-3+32+1 = \mathbf{38}$
- sumMin $= 4-4-27+4+2 = \mathbf{-21}$
- **ans $= 38-(-21) = \mathbf{59}$** ✓

三个看点：**①** `i=2` 的 $-3$ 是全局最小，$3\times3=9$ 个子数组的 min 全归它，负值乘大计数放大出 $-27$——sumMin 为负是正常现象，但 $\max \ge \min$ 保证最终差非负。**②** 两个 4 相等：`i=0` 的 $R=3$（右侧首个 $\ge 4$ 恰是另一个 4），含双 4 的子数组全部归属给 `i=3`（其 $L=-1$，左侧无严格更大），不重不漏。**③** 暴力要枚举 15 个子数组各算一次 max/min，贡献法只算 5 行——子数组层求和降到元素层，正是 $O(n^2) \to O(n)$ 的视角翻转。

## 4. 算法细节

1. **两遍扫描、两个函数**：`subArrayRanges = sumOfMax(nums) - sumOfMin(nums)`。拆成两个独立函数比一遍双栈可读性高、可调试性好；复杂度同阶，常数差异可忽略（追求极致可合并为单次遍历双栈，见「延伸思考」）
2. **哨兵合并进弹栈条件**：`while (!st.empty() && (i == n || nums[st.top()] <= nums[i]))`——把 `i == n` 当作 $+\infty$ 触发清栈，省掉收尾循环。注意 `i == n` 必须放在 `nums[st.top()]` **之前**（短路求值防越界）
3. **结算公式**：`total += (long long)nums[j] * (j - left) * (right - j)`，其中 `left = st.empty() ? -1 : st.top()`（弹出 `j` 后的新栈顶）、`right = i`
4. **栈存下标不存值**：边界与计数都要用**位置**做乘法
5. **sumMin 的唯一差别**：弹栈条件 `<=` 换 `>=`（递增栈），$L/R$ 语义同步换成「更小」
6. **溢出**：$|\text{nums}[i]| \le 10^9$ 而 $\text{cnt} \le \lceil n/2\rceil^2 \approx 2.5\times10^5$，单个贡献可达 $\approx 2.5\times10^{14}$，答案上界 $\approx 10^{15}$——C++ 必须 `long long`，且转型必须发生在**第一个乘数**上（先在 `int` 里乘完再转，中间结果早已溢出）；Python 天然免疫

## 5. 正确性证明

**约定**：子数组的**归属最大值位置**定义为其**最右**最大值下标（每个子数组存在且唯一）。$L_i$、$R_i$ 按 3.2 节定义（左严格更大、右含等号）。

**引理 1（滚动不变式）**：$O(n^2)$ 算法中，内层第 $j$ 轮累加时，`mn`、`mx` 分别等于 $\min/\max(\text{nums}[i..j])$。

**证明**：对 $j$ 归纳。$j=i$ 时初始化 `mn = mx = nums[i]`，成立。设第 $j-1$ 轮后结论成立，第 $j$ 轮只并入新元素 `nums[j]`：区间 $[i..j]$ 的最值要么仍是 $[i..j-1]$ 的最值、要么被 `nums[j]` 刷新，一次 `min/max` 恰好覆盖两种情形。故每轮累加的 `mx - mn` 恰为子数组 $[i..j]$ 的范围。∎

**引理 2（拆分恒等）**：$\sum_S(\max S-\min S)=\sum_S \max S-\sum_S \min S$。

**证明**：有限多项求和的线性性，逐项重排即得。∎

**引理 3（管辖刻画）**：子数组 $S=[a,b]$ 以 $i$ 为归属最大值 $\iff L_i < a \le i \le b < R_i$。

**证明**：（$\Rightarrow$）若 $a \le L_i$，则 $\text{nums}[L_i] > \text{nums}[i]$ 落在 $S$ 内，$i$ 连最大值都不是，矛盾。若 $b \ge R_i$，则 $\text{nums}[R_i] \ge \text{nums}[i]$ 且 $R_i > i$ 落在 $S$ 内——要么严格更大（$i$ 非最大），要么相等但在右侧（$i$ 非最右最大），均矛盾。
（$\Leftarrow$）任取 $x \in [a,b]$。若 $x \in (L_i, i)$：由 $L_i$ 的**最近性**，$(L_i, i)$ 内所有值 $\le \text{nums}[i]$（严格更大者已被 $L_i$ 拦下）。若 $x \in (i, R_i)$：由 $R_i$ 的最近性，$(i, R_i)$ 内所有值 $< \text{nums}[i]$（$\ge$ 者已被 $R_i$ 拦下）。于是 $S$ 内无更大元素、且 $i$ 右侧无相等元素，$\text{nums}[i]=\max S$ 且为最右出现。∎

**引理 4（不重不漏）**：$\displaystyle\sum_S \max S=\sum_i \text{nums}[i]\cdot(i-L_i)(R_i-i)$。

**证明**：每个子数组的归属位置存在且唯一；由引理 3，归属到 $i$ 的子数组恰为左端点 $\in (L_i, i]$、右端点 $\in [i, R_i)$ 的全部组合，共 $(i-L_i)(R_i-i)$ 个（两端独立，乘法原理）。按 $i$ 分桶，每桶恰计一次、每子数组恰入一桶。∎

**引理 5（单调栈结算正确）**：扫描中每个下标 $j$ 被弹出时，`right = i` 恰为 $R_j$，`left =` 弹出后的新栈顶（空则 $-1$）恰为 $L_j$。

**证明**：先证**栈不变式**——任意时刻栈内下标自底向顶递增、对应值严格递减：`i` 入栈前所有值 $\le \text{nums}[i]$ 的栈顶已被弹净，新栈顶（若有）必 $> \text{nums}[i]$；下标按序压入，天然递增。

（**右界**）设 $j$ 在 $i$ 时刻被弹出。反设存在 $x \in (j, i)$ 使 $\text{nums}[x] \ge \text{nums}[j]$：$x$ 入栈时 $j$ 已在栈中（$j$ 直到 $i$ 才被弹出），而 $j$ 上方的元素值都 $< \text{nums}[j] \le \text{nums}[x]$（栈严格递减），弹栈会自顶向下依次清空它们并命中 $j$——即 $j$ 在 $x$ 到来时就被弹掉，矛盾。故 $(j,i)$ 内值全 $< \text{nums}[j]$，即 $i = R_j$。

（**左界**）栈是 LIFO，$j$ 在栈期间其下方元素不变，故「弹出后的新栈顶」=「$j$ 入栈时的栈顶」$t$，且 $\text{nums}[t] > \text{nums}[j]$。反设存在 $x \in (t, j)$ 使 $\text{nums}[x] > \text{nums}[j]$，取**最靠右**的 $x$：由于 $j$ 存活至今，任何 $y > j$ 的到来要先弹掉压在 $x$ 上方的 $j$ 才够得着 $x$，故弹出 $x$ 的 $y$ 必满足 $x < y \le j$。而 $y = j$ 不可能（弹 $x$ 需 $\text{nums}[x] \le \text{nums}[j]$，与假设矛盾），于是 $y \in (x, j)$ 且 $\text{nums}[y] \ge \text{nums}[x] > \text{nums}[j]$，与 $x$ 的最右性矛盾。故 $t = L_j$。

哨兵 $i = n$ 把剩余元素全部弹出并结算 $R = n$；每个下标恰入栈、出栈各一次，每项贡献恰被累加一次。∎

**定理**：`sumOfMax` 返回 $\sum_S \max S$，且 `ans = sumOfMax - sumOfMin` 返回所有子数组范围之和。

**证明**：由引理 5，栈在出栈瞬间逐项实现 $(i-L_i)(R_i-i)$ 的计数；由引理 4，其总和即 $\sum_S \max S$。sumMin 论证完全对偶（更大换更小、归属最右最小值），同理得 $\sum_S \min S$。再由引理 2 相减即得所求。∎

## 6. 复杂度分析

**赛时 $O(n^2)$ 版**：

- **时间**：$O(n^2)$。$n=1000$ 时内层共约 $5\times10^5$ 次 $O(1)$ 的比较与累加，远低于时限
- **空间**：$O(1)$。只用常数个变量

**进阶 $O(n)$ 版**：

- **时间**：$O(n)$。sumMax、sumMin 各扫一遍；每遍中每个下标入栈、出栈各一次（均摊分析：嵌套 `while` 的总弹出次数 $\le n$），两遍合计仍是线性
- **空间**：$O(n)$。单调栈最坏存满 $n$ 个下标（如求 sumMax 遇到严格递减输入 `[5,4,3,2,1]`，全程无弹出）

## 7. 参考代码

### C++（赛时提交：滚动维护 O(n²)）

```cpp
class Solution {
public:
    long long subArrayRanges(vector<int>& nums) {
        int n = nums.size();
        long long ans = 0;
        for (int i = 0; i < n; ++i) {
            int mn = nums[i], mx = nums[i];
            for (int j = i; j < n; ++j) {
                mn = min(mn, nums[j]);
                mx = max(mx, nums[j]);
                ans += (long long)(mx - mn);
            }
        }
        return ans;
    }
};
```

### C++（进阶：单调栈 + 贡献计数 O(n)）

```cpp
class Solution {
public:
    long long subArrayRanges(vector<int>& nums) {
        return sumOfMax(nums) - sumOfMin(nums);
    }

private:
    long long sumOfMax(const vector<int>& nums) {   // 递减栈，弹 <=
        int n = nums.size();
        stack<int> st;
        long long total = 0;
        for (int i = 0; i <= n; ++i) {
            while (!st.empty() && (i == n || nums[st.top()] <= nums[i])) {
                int j = st.top(); st.pop();
                int left = st.empty() ? -1 : st.top();
                total += (long long)nums[j] * (j - left) * (i - j);
            }
            if (i < n) st.push(i);
        }
        return total;
    }

    long long sumOfMin(const vector<int>& nums) {   // 递增栈，弹 >=
        int n = nums.size();
        stack<int> st;
        long long total = 0;
        for (int i = 0; i <= n; ++i) {
            while (!st.empty() && (i == n || nums[st.top()] >= nums[i])) {
                int j = st.top(); st.pop();
                int left = st.empty() ? -1 : st.top();
                total += (long long)nums[j] * (j - left) * (i - j);
            }
            if (i < n) st.push(i);
        }
        return total;
    }
};
```

### Python（进阶：单调栈 + 贡献计数 O(n)）

```python
class Solution:
    def subArrayRanges(self, nums: List[int]) -> int:
        return self._sum(nums, lambda a, b: a <= b) - self._sum(nums, lambda a, b: a >= b)

    def _sum(self, nums: List[int], pop_when) -> int:
        n = len(nums)
        st, total = [], 0
        for i in range(n + 1):                  # i = n 为哨兵
            while st and (i == n or pop_when(nums[st[-1]], nums[i])):
                j = st.pop()
                left = st[-1] if st else -1
                total += nums[j] * (j - left) * (i - j)
            if i < n:
                st.append(i)
        return total
```

> 💡 Python 赛时版照抄 C++ 第一段的双层循环即可（`ans += mx - mn`，无溢出之忧）。进阶版把 max / min 两侧的唯一差别——弹栈比较方向——抽成 `pop_when` 谓词：`a <= b` 求 sumMax（递减栈），`a >= b` 求 sumMin（递增栈）。

## 8. 边界情况与易错点

1. **重复元素的方向性（头号 WA）**：两侧比较必须**一严格一含等号**，否则重算或漏算。用 `[1,3,3]`（正确答案 4）自测：

   | 写法 | sumMax | sumMin | 输出 | 症状 |
   |------|--------|--------|------|------|
   | 左严格、右含等号（正确） | 16 | 12 | **4** ✓ | — |
   | 两侧都严格 `>` / `<` | 22 | 15 | 7 | 含相等极值的子数组被数两遍 |
   | 两侧都含等号 `≥` / `≤` | 10 | 12 | $-2$ | 含相等极值的子数组一遍都不数，甚至算出负数 |

2. **溢出**：答案上界 $\approx 2\times10^9 \times 5\times10^5 = 10^{15}$，`int` 必炸。更隐蔽的是**中间乘积**：`(int)nums[j] * (j-left) * (right-j)` 单项可达 $2.5\times10^{14}$，`(long long)` 转型必须放在**第一个乘数**上。另外 `mx - mn` 本身 $\le 2\times10^9$，恰好卡在 `int` 上界（$2^{31}-1 \approx 2.147\times10^9$）之内——属于「贴脸飞行」，累加前就该转 `long long`
3. **哨兵别漏**：外层循环必须写到 `i == n`（C++ 的 `i <= n` / Python 的 `range(n + 1)`），否则栈内残留元素（右侧无更大 / 更小者）永远不结算。典型症状：`[1,2,3]` 求 sumMax 时漏掉栈底的 3，sumMax 只得 5（正确 14），整体输出 5 ≠ 4
4. **短路顺序**：`i == n` 必须写在 `nums[st.top()]` **之前**，否则哨兵轮直接数组越界
5. **sumMax / sumMin 为负都正常**：负数数组里最大值也可能是负的（示例 3 的 sumMin $= -21$）；但 $\text{ans} = \sum(\max-\min) \ge 0$ 恒成立，可作提交前自检
6. **n = 1**：唯一子数组范围 0，答案 0，两种算法均自然覆盖，无需特判
7. **全等数组**（如 `[3,3,3]`）：所有范围 0、答案 0；它是「严格 / 含等号」方向错误的照妖镜——写错的版本在此类输入也会给出非 0
8. **赛时别贪 O(n)**：$n \le 1000$ 时 $O(n^2)$ 稳过且三分钟写完；单调栈的「一侧严格一侧含等号」在比赛高压下极易写反，性价比最高的路线是暴力 + 样例自测先锁分数，复盘时再补 $O(n)$
