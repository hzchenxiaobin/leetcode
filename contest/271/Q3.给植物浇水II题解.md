# LeetCode 给植物浇水II 题解

## 1. 题目概述

- **标题 / 题号**：给植物浇水II（#2105，medium）
- **链接**：https://leetcode.cn/problems/watering-plants-ii/
- **来源**：LeetCode 第 271 场周赛 Q3
- **难度**：中等
- **标签**：数组、双指针、模拟

**题意**：$n$ 株植物排成一行（下标 $0 \ldots n-1$），Alice 从最左、Bob 从最右**同时**开始浇水，各沿自己的方向逐株推进。每人一个水罐（初始是满的），规则如下：

- 水罐中的水**足以完全灌溉**时**必须**直接浇；不足时**首先（立即）重新装满**，然后浇——灌满不占时序；
- 无论需水多少，每株浇水耗时**相同**；
- 两人到达**同一株**时，**当前水量更多**的人浇这株，平手则 Alice 浇。

返回全程**重新灌满水罐的总次数**。

**约束**：

- $n == \text{plants.length}$，$1 \le n \le 10^5$
- $1 \le \text{plants}[i] \le 10^6$
- $\max(\text{plants}[i]) \le \text{capacityA},\ \text{capacityB} \le 10^9$

> 💡 约束的隐藏含义：**两人满罐都必能浇动任意一株**（$\max(\text{plants}) \le \min(\text{capA}, \text{capB})$）——每株每人至多触发一次灌满，且水量 $a$、$b$ 永不为负。

> 💡 本题在本仓库另有[每日题解 2105](../../solution/2101-2200/2105_给植物浇水II.md)：以「审题四要点、双指针两种写法对照、与 2079 折返模型的对比及面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时决策**（识破接口名 `minimumRefill` 的 "minimum" 烟雾弹——过程完全确定，无需任何优化算法）、**规则到代码的清单化映射**、「锁步推进 → 全覆盖 → 单步守恒 → 确定性」的完整证明链，以及每日版没有的两个观察：**平手规则其实不影响答案**、**「水多者浇」恰好就是最优仲裁**。两篇互为印证。

- Alice 浇植物 1（a：3→1）；Bob 的 2 单元水浇不动植物 2（需 3），
  先重新装满（第 1 次）再浇（b：5→2）。

```

输出：2
解释：
- 第一轮后 a=1、b=1。
- 第二轮 Alice、Bob 的水都不够，各重新装满一次再浇（共 2 次）。
```

## 3. 解题思路

### 3.1 赛时第一反应：这是「规则转译」题，不是优化题

接口名 `minimumRefill` 里的 **minimum** 是本题最大的烟雾弹：乍看像「决策谁浇哪株，使灌满次数最少」的优化题，实际题面把每一步都**规定死了**——够水必须浇、不够立即灌满再浇、相遇比当前水量、平手归 Alice。整个过程是输入的**确定函数**（§5 引理 4），答案唯一，没有任何决策空间，赛时被带偏去找 DP / 贪心就是纯丢时间。正确姿势：**直接模拟**。

数据范围也印证这一点：$n \le 10^5$，一次遍历 $O(n)$ 已是读入下界 $\Omega(n)$，无更优复杂度可追求。本题真正的门槛不在算法而在**审题与实现细节**——相遇判定、平手规则、灌满计数，区分度体现在 WA 次数而非用时。

### 3.2 核心观察：灌水瞬时 ⇒ 锁步推进 ⇒ 相遇只由奇偶决定

![核心观察：双指针锁步推进与奇偶相遇](images/wc271_q3_two_pointers_concept.svg)

两条题面规则撑起整个模型：

**观察一（锁步推进）**：灌满「立即」完成（不占时序）且每株浇水耗时相同，所以第 $r$ 轮 Alice 必在植物 $r$、Bob 必在植物 $n-1-r$——**灌满与否不影响任何人的位置与节奏**。对比 [2079. 给植物浇水](../../solution/2001-2100/2079_给植物浇水.md)（灌水要折返河边、快慢随时变化），本题把时间线完全抹平，只剩位置。

**观察二（奇偶相遇）**：

| $n$ 奇偶 | Alice 浇 | Bob 浇 | 相遇 |
|---------|---------|--------|------|
| 偶数 | $0 \ldots \frac n2 - 1$ | $\frac n2 \ldots n-1$ | 无，擦肩而过 |
| 奇数 | $0 \ldots \lfloor \frac n2 \rfloor - 1$ | $\lfloor \frac n2 \rfloor + 1 \ldots n-1$ | 中间株 $\lfloor \frac n2 \rfloor$ |

于是问题被解耦为：**两条独立的单人水流**（各自「够则浇、不够灌满再浇」）+ **至多一次相遇仲裁**（$a \ge b$ → Alice 浇，否则 Bob 浇）。双指针一遍扫完。

### 3.3 算法流程

![算法流程：双指针一遍扫描与相遇仲裁](images/wc271_q3_meeting_flow.svg)

1. 初始化 `i = 0`、`j = n-1`、`a = capacityA`、`b = capacityB`、`refills = 0`
2. **当 `i < j`**（尚未相遇）：Alice 处理 `plants[i]`、Bob 处理 `plants[j]`，各自「不够先灌满并计数，再浇水」，然后 `i++`、`j--`
3. **若 `i == j`**（奇数 $n$ 的中间株）：比较**当前水量**，多者浇这株（平手 Alice），同样「不够先灌满并计数」
4. 返回 `refills`

> ⚠️ 循环条件 `i < j` 与循环后的 `i == j` 判定是**配套**的：偶数 $n$ 最后一轮后 $i$ 与 $j$ 擦肩而过（$i = \frac n2 > \frac n2 - 1 = j$），`i == j` 为假自然跳过相遇分支；奇数 $n$ 恰好停在中间株。若把循环写成 `i <= j`，偶数 $n$ 会重复浇灌已浇过的植物。

### 3.4 示例演算

官方三个示例里唯一的相遇是 $n=1$（开局即相遇，水量 = 容量），没有「沿途消耗后再比水量」的场景。自定义一个**奇数 $n$** 的例子补上这条分支：`plants = [2,3,3,3,2]`，`capacityA = capacityB = 5`：

![示例演算：奇数n相遇平手](images/wc271_q3_walkthrough.svg)

| 阶段 | Alice | $a$ 变化 | Bob | $b$ 变化 | refills |
|------|-------|---------|-----|---------|---------|
| 轮 1 | 浇 `plants[0]=2`（够） | 5→3 | 浇 `plants[4]=2`（够） | 5→3 | 0 |
| 轮 2 | 浇 `plants[1]=3`（恰好够） | 3→0 | 浇 `plants[3]=3`（恰好够） | 3→0 | 0 |
| 相遇 | 浇 `plants[2]=3`（平手归 Alice） | 0<3：**灌满**后 5→2 | —（不浇） | 0（不动） | +1 |

输出 `refills = 1`。三个看点：**①** 相遇比较的是**当前水量**（$a=0$ vs $b=0$），不是容量；**②** 平手归 Alice，且她不够水仍要灌满并计数；**③** 未中选的 Bob 水量**保持不动**——不清零、也不补满。

再用示例 2（偶数 $n$）对照：`[2,2,3,3]`，`capA=3`，`capB=4`。轮 1：$a: 3\to1$、$b: 4\to1$；轮 2：Alice 浇 2（$1<2$ 灌满，$3\to1$）、Bob 浇 3（$1<3$ 灌满，$4\to1$）；随后 $i=2>j=1$ 擦肩而过，无相遇分支。$\text{refills} = 2$ ✓

## 4. 算法细节

**规则 → 代码清单化映射**（赛时防 WA 的核心手段）：

| 题面规则 | 代码 |
|---------|------|
| Alice 左→右、Bob 右→左、同时浇水 | 双指针 `i++` / `j--` 每轮各一步 |
| 够则必须浇；不够先立即灌满再浇 | `if (cur < need) { cur = cap; ++refills; } cur -= need;` |
| 每株耗时相同、灌满立即完成 | 无需时钟模拟——相遇由 `i == j` 判定 |
| 相遇：当前水多者浇、平手 Alice | `a >= b ? Alice : Bob` |
| 问灌满次数 | 计数器 `refills` |

1. **状态**：$(i, j, a, b, \text{refills})$ 五个标量；`a`、`b` 是**当前水量**（初值 = 满容量，灌满即恢复为容量）
2. **原子操作**：「先判后扣」顺序不能反；判定用**严格小于**——`cur == need` 恰好够、直接浇不灌满
3. **不变式** $a, b \ge 0$：由 $\text{cap} \ge \max(\text{plants})$，灌满后必够，扣完不为负
4. **相遇株只浇一次**：中选者执行同样的原子操作；另一人水量不动。相遇分支里的 `cur -= need` 其实是死代码（相遇是最后一株，浇完即返回），保留只为与原子操作统一
5. **无额外数据结构**：数组只读，$O(1)$ 空间
6. **数值范围**：$\text{cap} \le 10^9$、$w \le 10^6$、$\text{refills} \le n \le 10^5$——全部在 32 位 `int` 内，C++ 无需 `long long`（比本场 Q2 温柔得多）

## 5. 正确性证明

**引理 1（锁步推进）**：灌满立即完成（不占时序）且每株浇水耗时相同，故第 $r$ 轮（$r = 0, 1, \ldots$）Alice 位于植物 $r$、Bob 位于植物 $n-1-r$，与灌水历史无关。

**证明**：对 $r$ 归纳。$r=0$ 时两人各自从端点出发，成立。设第 $r$ 轮成立：该轮两人各完成一次浇水，耗时相同故**同时**结束；灌满是浇水前「立即」完成的动作，不产生时间差，也不改变逐株推进的顺序。故第 $r+1$ 轮 Alice 位于 $r+1$、Bob 位于 $n-2-r$。∎

**引理 2（全覆盖、不重复）**：模拟把每株植物恰好浇一次；相遇当且仅当 $n$ 为奇数，发生在中间株 $m = \lfloor n/2 \rfloor$，由当前水量多者浇（平手 Alice）。

**证明**：循环 `while (i < j)` 每轮浇 `plants[i]`、`plants[j]` 两个**不同**下标（$i < j$），并使 $i$ 增 1、$j$ 减 1；第 $k$ 轮后 $i = k$、$j = n-1-k$。若 $n$ 为偶数：轮 $0 \ldots \frac n2 - 1$ 均满足 $i < j$，共浇 $n$ 个下标；历轮中 $i$ 严格递增、$j$ 严格递减且每轮 $i < j$，任意两轮的四个下标两两不同，恰为 $[0, n-1]$ 全体；随后 $i = \frac n2 > \frac n2 - 1 = j$，退出且 `i == j` 为假。若 $n$ 为奇数：轮 $0 \ldots \frac{n-1}{2}-1$ 后 $i = j = m$，进入相遇分支浇一次，共 $\frac{n-1}{2} \times 2 + 1 = n$ 株，互不相同且恰为全体。∎

**引理 3（单步守恒）**：对任一株需水 $w$ 与浇水者当前水量 $\text{cur}$、容量 $\text{cap}$，规则「够则浇、不够先灌满再浇」等价于 `if (cur < w) { cur = cap; ++refills; } cur -= w;`，且结果 $\text{cur} - w \ge 0$。

**证明**：题面是二分支：足以完全灌溉则直接浇（不灌满、不计数），否则先恢复满容量再浇。`cur < w` 恰为「不足以完全灌溉」（$=$ 是足够）。灌满后 $\text{cur} = \text{cap} \ge \max(\text{plants}) \ge w$，浇水必然可行且 $\text{cur} - w \ge 0$——每株至多触发一次灌满，不存在连灌两次。∎

**引理 4（过程确定性）**：从初始状态起，每一步「谁浇哪株、是否灌满」由当前状态唯一决定。

**证明**：未相遇时规则**强制**两人各浇指针所指株（「必须」浇），是否灌满由引理 3 唯一决定；相遇时浇灌者由 $a, b$ 的大小关系唯一决定（平手归 Alice 是题面明文）。对轮数归纳，全过程是输入的确定函数。∎

**推论 1（"minimum" 无实际意义）**：过程确定 ⇒ 灌满次数取值唯一，不存在「最小化」的自由度，`minimumRefill` 中的 minimum 只是命名烟雾弹。

**推论 2（平手规则不影响答案）**：相遇时若 $a = b$，则 $a < w \iff b < w$，两人「够不够」必然一致——无论谁浇，灌满要么各触发一次（计入 +1）、要么都不触发。又相遇株是**最后一株**（引理 2），其后水量不再被读取。故平手归谁只影响展示，不影响 `refills`。（按题意写 `a >= b` 仍是正解，别靠这个巧合偷懒。）

**推论 3（题给仲裁恰为最优）**：若把相遇株「给谁浇」当成自由决策，最优是交给**够水的一方**。而「水多者浇」正是这一最优：若水多者够水（$w \le \max(a,b)$），中选即省一次灌满；若水多者都不够（$w > \max(a,b) \ge \min(a,b)$），另一方必然也不够，给谁都 +1。再配上单人流「只在不足时灌满」本就不劣于任何主动提前灌满（提前灌满最多把一次必灌的灌满挪早，省不掉），**题给规则的过程本身就是最少次数**——`minimumRefill` 名副其实，只是不需要搜索就能得到。

**定理**：模拟程序返回的 `refills` 等于题目定义过程的灌满总次数（且由推论 3，该数也是所有可行浇法中的最小值）。

**证明**：由引理 2，浇灌分工与题意一致且每株恰一次；由引理 3，每株的灌满判定与计数正确；由引理 4，规则无歧义地确定全过程。三者分别覆盖「分工、单步、无歧义」，合并即得。∎

## 6. 复杂度分析

- **时间 $O(n)$**：相遇前每轮处理两株、双指针共推进两格，共 $\lceil n/2 \rceil$ 轮，每轮 $O(1)$；相遇分支 $O(1)$。达到读入下界 $\Omega(n)$
- **空间 $O(1)$**：五个标量，数组只读，无额外结构

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumRefill(vector<int>& plants, int capacityA, int capacityB) {
        int n = plants.size();
        int i = 0, j = n - 1;
        int a = capacityA, b = capacityB;
        int refills = 0;
        while (i < j) {
            if (a < plants[i]) { a = capacityA; ++refills; }
            a -= plants[i]; ++i;
            if (b < plants[j]) { b = capacityB; ++refills; }
            b -= plants[j]; --j;
        }
        if (i == j) {
            int& cur = a >= b ? a : b;
            int cap  = a >= b ? capacityA : capacityB;
            if (cur < plants[i]) { cur = cap; ++refills; }
            cur -= plants[i];
        }
        return refills;
    }
};
```

### Python

```python
class Solution:
    def minimumRefill(self, plants: List[int], capacityA: int, capacityB: int) -> int:
        n = len(plants)
        i, j = 0, n - 1
        a, b = capacityA, capacityB
        refills = 0
        while i < j:
            if a < plants[i]:
                a = capacityA
                refills += 1
            a -= plants[i]
            i += 1
            if b < plants[j]:
                b = capacityB
                refills += 1
            b -= plants[j]
            j -= 1
        if i == j:
            if a >= b:
                if a < plants[i]:
                    a = capacityA
                    refills += 1
                a -= plants[i]
            else:
                if b < plants[i]:
                    b = capacityB
                    refills += 1
                b -= plants[i]
        return refills
```

> 💡 **写法要点**：① 相遇分支用 `int& cur = a >= b ? a : b` 把「选中谁」收敛成一行（Python 无引用，展开成对称 if/else）；② `a >= b` 的 `=` 承接平手规则；③ 灌满判定一律严格 `<`；④ 相遇分支的 `cur -= plants[i]` 是死代码（最后一株），保留以维持原子操作统一。

## 8. 边界情况与易错点

1. **`while (i < j)` 与 `if (i == j)` 配套**：循环写成 `i <= j` 会让偶数 $n$ 把已浇过的植物再浇一遍、灌满次数虚高；漏掉循环后的 `i == j` 判定则奇数 $n$ 漏浇中间株
2. **相遇比「当前水量」，不是容量**（头号陷阱）。反例：`plants = [4,4,3,1,1]`，`capA = 6`，`capB = 5`——相遇时 $a=2 < b=3$，Bob 浇 3 恰好够，答案 **1**；若误比容量（$6>5$ 选 Alice），$a=2<3$ 触发灌满，答案错成 **2**
3. **相遇仲裁本身不可省略**（不能无脑让 Alice 浇）：`plants = [1,1,3,1,1]`，`capA = 3`，`capB = 5`——相遇时 $a=1 < b=3$，必须 Bob 浇（$b=3 \ge 3$，答案 **0**）；固定 Alice 浇则 $a=1<3$ 灌满，答案错成 **1**
4. **平手写 `a >= b`**：`a > b` 会把平手推给 Bob。虽然推论 2 表明平手不影响答案，但按题意实现才是正解
5. **灌满判定用严格 `<`**：`cur == need` 恰好够，直接浇、不计数
6. **相遇分支别漏 `refills++`**：中选者不够时同样要灌满计数——相遇「长得不像正常浇水」，最容易漏
7. **`n = 1`**：跳过循环直接相遇，比水量后一人浇（示例 3：Alice 浇，0 次）
8. **无需 `long long`**：$\text{cap} \le 10^9$、$w \le 10^6$、$\text{refills} \le 10^5$，32 位 `int` 全程安全（对比本场 Q2 必须 `long long`）
9. **别被 `minimumRefill` 带偏**：过程完全确定（引理 4），任何「优化」都是屠龙之技——赛时在它身上花的每一分钟都是净亏

- [LeetCode 881. 救生艇](https://leetcode.cn/problems/boats-to-save-people/)：双指针从两端向中间收缩配对的经典范式

**延伸思考**：

- **去掉约束 $\max(\text{plants}) \le \min(\text{capA}, \text{capB})$**：某人满罐也浇不动某株——该株只能由另一人浇，相遇规则需改为可行性判定，甚至可能无解；引理 3 的「灌满后必够」失效，需要重新设计
- **回归 2079 模型**（灌满需折返河边）：节奏不再锁步，相遇点依赖两人灌水历史，「位置由下标决定」失效，需要时间线模拟——这正是每日版「扩展」一节展开的对比
- **若允许自由决策**谁浇每株（不锁方向）：问题变成两人「区间划分 + 各自装箱」的联合优化；推论 3 说明题给规则的损耗恰好在相遇处为零，自由度并不带来收益
