# LeetCode 反转单词前缀 题解

## 1. 题目概述

- **标题 / 题号**：反转单词前缀（#2000，easy）
- **链接**：https://leetcode.cn/problems/reverse-prefix-of-word/
- **来源**：LeetCode 第 258 场周赛 Q1
- **难度**：简单
- **标签**：字符串、双指针、模拟

**题意**：给定下标从 0 开始的字符串 `word` 和字符 `ch`。找出 `ch` **第一次出现**的下标 `i`，反转 `word` 中从下标 `0` 到下标 `i`（**含两端**）的字符段；若 `ch` 不存在，则不做任何操作。返回结果字符串。

**约束**：

- `1 <= word.length <= 250`
- `word` 由小写英文字母组成
- `ch` 是一个小写英文字母

## 2. 示例

**示例 1**

```text
输入：word = "abcdefd", ch = 'd'
输出："dcbaefd"
解释："d" 第一次出现在下标 3，反转 [0, 3] 这段字符，得 "dcbaefd"。
```

**示例 2**

```text
输入：word = "xyxzxe", ch = 'z'
输出："zxyxxe"
解释："z" 首次（也是唯一一次）出现在下标 3，反转 [0, 3] 得 "zxyxxe"。
```

**示例 3**

```text
输入：word = "abcd", ch = 'z'
输出："abcd"
解释："z" 不存在于 word 中，无需操作，原样返回。
```

## 3. 解题思路

### 3.1 暴力思路

签到题，"暴力"即正解：直接按题意模拟，分两步——**定位** `ch` 首次出现的位置，**反转**前缀。线性扫描一遍找下标，再花线性时间反转，总代价 `O(n)`，对 `n ≤ 250` 绰绰有余，无需任何优化。

唯一容易写错的不是复杂度，而是**边界**：找的是"第一次出现"（不是任意一次），反转的是**闭区间** `[0, i]`（长度是 `i + 1` 不是 `i`），`ch` 不存在时要原样返回。

### 3.2 核心观察：定位 + 一次反转

![反转单词前缀：定位 ch + 逆转前缀](images/wc258_q1_reverse_prefix_concept.svg)

- **定位**：`word.find(ch)` 返回 `ch` 首次出现的最小下标 `i`；不存在时 C++ 返回 `string::npos`、Python 返回 `-1`。
- **反转**：只需反转**前缀** `[0, i]`，后缀 `[i+1, n-1]` 原封不动。
- **不存在**：直接返回原串，这一步必须特判。

### 3.3 算法流程：双指针原地反转

![双指针原地交换演算](images/wc258_q1_reverse_prefix_walkthrough.svg)

反转一段连续区间是双指针的经典模板：

1. 令 `l = 0`，`r = i`（`i` 为 `ch` 首次出现的下标）。
2. 当 `l < r` 时：交换 `word[l]` 与 `word[r]`，然后 `l++`、`r--`。
3. `l >= r` 时指针相遇（或交错），反转完成。

实战中无需手写循环，标准库一步到位：

- C++：`reverse(word.begin(), word.begin() + i + 1)`
- Python：`word[:i+1][::-1] + word[i+1:]`

### 3.4 示例演算

以 `word = "abcdefd"`，`ch = 'd'` 为例：

| 步骤 | l | r | 操作 | 当前串 |
|------|---|---|------|--------|
| 定位 | — | — | `'d'` 首次出现在下标 3 | `abcdefd` |
| ① | 0 | 3 | 交换 `a` ↔ `d` | `dbcaefd` |
| ② | 1 | 2 | 交换 `b` ↔ `c` | `dcbaefd` |
| ③ | 2 | 1 | `l ≥ r`，停止 | `dcbaefd` |

后缀 `efd` 全程未动，最终返回 `"dcbaefd"` ✓

## 4. 算法细节

1. **`find` 的语义**：返回的是**最小**下标。示例 1 中 `'d'` 出现两次（下标 3 和 6），必须用下标 3；标准库 `find` / `str.find` 天然满足。
2. **闭区间的 `+1`**：反转区间含下标 `i` 本身，C++ 写 `word.begin() + i + 1`（右开区间端点），Python 切片写 `word[:i+1]`。漏掉 `+1` 是最常见错误。
3. **不存在的特判**：`find` 失败时 C++ 得到 `string::npos`，直接拿去算 `begin() + npos + 1` 是未定义行为，必须先判断再反转。
4. **原地 vs 拷贝**：C++ 对 `string` 原地 `reverse`，零额外拷贝；Python 字符串不可变，切片拼接会生成新串，写起来反而更短。

## 5. 正确性证明

**引理 1**：双指针循环结束时，区间 `[0, i]` 恰好变为原序列的逆序。

**证明**：对交换轮数归纳。每轮把当前最外层未定的一对 `(word[l], word[r])` 交换到位：位置 `l` 得到原 `word[r]`，位置 `r` 得到原 `word[l]`。逆序序列中，下标 `k` 处应放原下标 `i - k` 处的字符。第 `t` 轮（`t` 从 0 计）恰好固定 `k = t` 与 `k = i - t` 两个位置，两指针每轮各向中间推进 1，至 `l >= r` 时所有下标对均已交换。当区间长度为奇数时，正中间元素自交换，保持不变。∎

**引理 2**：`word.find(ch)` 返回的 `i` 满足 `word[i] == ch`，且对所有 `j < i` 有 `word[j] != ch`。

**证明**：`find` 自左向右扫描，返回首个匹配位置，即满足条件的最小下标。∎

**定理**：算法返回题面要求的结果字符串。

**证明**：分两种情况。若 `ch` 不在 `word` 中，由引理 2 扫描无匹配，算法特判后原样返回 `word`，符合"无需进行任何操作"。若 `ch` 存在，设首次出现下标为 `i`，由引理 2 算法定位到正确的 `i`；由引理 1 前缀 `[0, i]` 被反转为逆序，下标 `> i` 的字符未被任何交换触及，保持原值。故输出恰为"反转 `[0, i]` 后的 `word`"。∎

## 6. 复杂度分析

- **时间复杂度**：`O(n)`，其中 `n = word.length()`。`find` 最多扫描一遍（`O(n)`），反转至多进行 `⌈n/2⌉` 次交换（`O(n)`），总计线性。
- **空间复杂度**：C++ 原地反转，`O(1)` 额外空间；Python 因字符串不可变需拼接新串，`O(n)`。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string reversePrefix(string word, char ch) {
        size_t i = word.find(ch);
        if (i != string::npos) {
            reverse(word.begin(), word.begin() + i + 1);
        }
        return word;
    }
};
```

### Python

```python
class Solution:
    def reversePrefix(self, word: str, ch: str) -> str:
        i = word.find(ch)
        if i == -1:
            return word
        return word[:i + 1][::-1] + word[i + 1:]
```

## 8. 边界情况与易错点

1. **`ch` 不存在**：必须特判。C++ 中 `npos + 1` 溢出后作迭代器偏移是未定义行为；Python 中 `i = -1` 会让切片 `word[:0]` 悄悄变味，同样必须先判。
2. **`+1` 边界**：区间是闭区间 `[0, i]`，反转长度为 `i + 1`，`reverse(word.begin(), word.begin() + i)` 或 `word[:i][::-1]` 都会漏掉 `ch` 本身。
3. **`ch` 多次出现**：只用**第一次**出现的下标（如示例 1 中 `'d'` 出现在下标 3 和 6，取 3）。
4. **`ch == word[0]`**：反转 `[0, 0]` 长度为 1，结果与原串相同，无需单独处理。
5. **`ch` 在末尾**：整个字符串反转，是本算法的反转上限，模板天然覆盖。
6. **长度为 1 的 `word`**：无论 `ch` 是否匹配都正确——匹配时反转 `[0,0]` 不变，不匹配时原样返回。
