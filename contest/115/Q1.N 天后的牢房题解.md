# LeetCode N 天后的牢房 题解

## 1. 题目概述

- **标题 / 题号**：N 天后的牢房（#957，medium）
- **链接**：https://leetcode.cn/problems/prison-cells-after-n-days/
- **来源**：LeetCode 第 115 场周赛 Q1
- **难度**：中等
- **标签**：位运算、数组、哈希表、数学、Floyd 判圈算法

**题意**：监狱里有 **8** 间牢房排成一排，用长度为 8 的 0/1 数组 `cells` 表示（1 表示占用）。每天同时按下面的规则更新：

- 若一间牢房的**左右两个邻居**状态相同（都占用或都空），则它变为**占用**；
- 否则变为**空置**；
- 位于两端的第 0、7 间牢房**没有两个邻居**，每天都会变为**空置**。

求 $n$ 天后监狱的状态。

**约束**：

- $cells.length = 8$，$cells[i] \in \{0,1\}$
- $1 \le n \le 10^9$

## 3. 解题思路

### 3.1 暴力思路

按规则逐天模拟：用两个数组（或一份拷贝）同步计算每天的新状态，循环 $n$ 次。

- 时间 $O(8n)$：$n = 10^9$ 时约 $8\times10^9$ 次基本操作，C++ 也要几十秒，Python 更是完全不可行；
- 空间 $O(1)$。瓶颈完全在 $n$ 上。

### 3.2 核心观察：状态只有 256 种，序列必然周期

![状态只由 8 位 0/1 决定：第一天后两端必定归零](images/wc115_q1_state_space.svg)

**观察 1（状态空间极小）**：整座监狱的状态就是一个 8 位二进制数，总共只有 $2^8 = 256$ 种。更进一步，第 0、7 间牢房在**任意一天之后**必然是 0（它们没有两个邻居），所以从第 1 天起状态只可能有

$$2^6 = 64$$

种。

**观察 2（转移是确定的）**：给定今天的 `state`，明天的状态由 `nextState(state)` **唯一确定**，与历史无关。对这样的确定性有限状态序列，从初始状态出发必然会**在有限步内进入一个环**：因为状态数有限，某个状态迟早重复出现。

**观察 3（首次重复即可跳过）**：设状态 $s_0$ 在第 $d_0$ 天第一次出现，之后又在第 $d_1$ 天出现（$d_1 > d_0$），则

$$s_{d_0} = s_{d_1} \implies s_{d_0+k} = s_{d_1+k}\ \text{对一切 } k \ge 0,$$

即从 $d_0$ 起序列以 $p = d_1 - d_0$ 为周期。于是要求第 $n$ 天的状态，只需算出

$$(n - d_1) \bmod p$$

再模拟这么多次即可——把 $10^9$ 步压缩到至多 64 步。

![算法流程：模拟 + 哈希表记录首次出现时刻 + 取模跳周期](images/wc115_q1_cycle_flow.svg)

> 💡 **一句话总结**：确定性有限状态机的轨道一定是"一条尾巴 + 一个环"，用哈希表记录每个状态首次出现的天数，遇到重复就按周期取模。

### 3.3 算法流程

```text
1. state = 把 cells 压成 8 位二进制
2. firstSeen[0..255] = -1，day = 0
3. while day < n 且 firstSeen[state] == -1:
       firstSeen[state] = day
       state = nextState(state)
       day += 1
4. 若 day < n（说明找到了环）:
       period = day - firstSeen[state]
       rest = (n - day) % period
       重复 rest 次:  state = nextState(state)
5. 把 state 拆回 8 位数组返回
```

### 3.4 示例演算

![示例 1：逐日状态与第 4、6 天的循环迹象](images/wc115_q1_walkthrough.svg)

对示例 1 的 `cells = [0,1,0,1,1,0,0,1]`、`n = 7`：

| 天 | 状态（二进制） | 说明 |
|----|----------------|------|
| 0 | 0101 1001 | 初始 |
| 1 | 0110 0000 | 两端归零，第 1 位左右都是 0 → 1 |
| 2 | 0000 1110 | 第 4、5、6 位被"点亮" |
| 3 | 0110 0100 | 逐位按"左右相同"计算 |
| 4 | 0000 0100 | |
| 5 | 0111 0100 | |
| 6 | 0010 1100 | |
| 7 | **0011 0000** | 与示例输出 `[0,0,1,1,0,0,0,0]` 一致 |

本题的 $n$ 很小（7），直接走到第 7 天即可；但若 $n = 10^9$，算法会在某一天发现状态重复（本题序列的周期实际为 14），然后一次取模就把剩余天数消掉。

## 4. 算法细节

1. **状态压缩**：`state |= 1 << i`，用整数表示整排牢房，比较/存储都是 $O(1)$，也方便放进长度 256 的数组做"首次出现"表。
2. **转移只算中间 6 位**：第 0、7 位永远为 0，所以 `nextState` 只需 `for i = 1..6`，天然满足"两端没有两个邻居"。
3. **必须用旧状态算新状态**：规则是"同时"更新的。若原地修改数组，后面的牢房会用到已经被改过的邻居，逻辑就错了（代码里用一份新的 `int t` 累加，天然避免这个问题）。
4. **`firstSeen` 用数组而不是哈希表**：状态空间只有 256，`array<int,256>` 初始化成 -1 后查询是纯数组访问，比 `unordered_map` 快。
5. **天数的类型**：$n$ 可达 $10^9$，`day`、`period`、`rest` 建议用 `long long`（虽然 $10^9$ 在 `int` 内，但取模后计算更安心）。
6. **循环条件里要带 `day < n`**：当 $n$ 很小、还没进入环时，循环会因 `day == n` 正常结束，此时**不能**再做取模。
7. **第 0 天的状态也要登记**：首次出现表记录的是"到达该状态的那一天"，初始状态在 `day = 0` 就登记，若第一天就回到自己（周期 1），也能正确得到 `period = 1`。
8. **位运算版转移（可选）**：`newState = ~((state << 1) ^ (state >> 1)) & 0x7E`，一次异或就能算出"左右是否相同"，代码更短但可读性稍差。

## 5. 正确性证明

把一天的变化看成一个函数 $f: \{0,1\}^8 \to \{0,1\}^8$，其中 $f(s)_i = [s_{i-1} = s_{i+1}]$（下标越界视为没有邻居，直接取 0）。

**引理 1（一天后两端必为 0）**：对任意 $s$，$f(s)_0 = f(s)_7 = 0$；因此 $f(s) \in \{0,1\}^6$ 只有 64 种可能（把两端空位固定后只看中间 6 位）。

**证明**：第 0、7 间牢房没有两个邻居，按规则一律变空置。∎

**引理 2（轨道必然进入周期）**：存在 $0 \le d_0 < d_1 \le 64$ 使 $s_{d_0} = s_{d_1}$，其中 $s_k = f^k(s_0)$。

**证明**：由引理 1，$s_1, s_2, \dots$ 全部落在至多 64 个状态里。序列 $s_0, s_1, \dots, s_{64}$ 有 65 个状态，其中至少两个相同（抽屉原理），取最先出现重复的一对即为 $d_0 < d_1$。∎

**引理 3（周期性）**：若 $s_{d_0} = s_{d_1}$，则对一切 $k \ge 0$ 有 $s_{d_0 + k} = s_{d_1 + k}$。

**证明**：对 $k$ 归纳。$k = 0$ 即题设。设 $s_{d_0+k} = s_{d_1+k}$，两边同施 $f$ 得 $s_{d_0+k+1} = s_{d_1+k+1}$（$f$ 是函数，相同输入给出相同输出）。∎

**引理 4（取模跳步正确）**：设算法在 `day = d_1` 处发现 `firstSeen[state] = d_0`，`period = d_1 - d_0`。则对任意 $n \ge d_1$，从 $s_{d_1}$ 再走 $(n - d_1) \bmod period$ 步即得 $s_n$。

**证明**：由引理 3，$s_{d_1 + k} = s_{d_0 + k}$ 对所有 $k$ 成立，且 $s_{d_0 + period} = s_{d_1} = s_{d_0}$，故 $s_{d_0}$ 是周期为 $period$ 的循环节起点，$s_{d_1 + k} = s_{d_1 + (k \bmod period)}$。取 $k = n - d_1$ 即得结论。∎

**定理**：算法返回的数组恰为 $n$ 天后监狱的状态。

**证明**：循环不变式：每次进入循环体时 `state` 等于 $s_{day}$（初始 `day = 0`、`state = s_0`；每轮执行 `state = f(state); day++` 后仍成立）。

- 若循环因 `day == n` 结束：`state = s_n`，直接返回正确。
- 若循环因 `firstSeen[state] != -1` 结束：此时 `state = s_day`，`day = d_1`，`firstSeen[state] = d_0`，由引理 4 再做 $(n - d_1)\bmod period$ 步即得 $s_n$。

两种情形返回的都是 $s_n$；最后按位拆回数组只是一次编码转换。∎

## 6. 复杂度分析

- **时间**：$O(\min(n,\ 64)\cdot 8)$。循环每天做一次 $O(8)$ 的转移，且最多重复 64 次就会因状态重复而退出；取模跳步后剩下的模拟不超过 `period ≤ 64` 步。所以无论 $n$ 多大，实际工作量都被常数上界封住，约 $10^3$ 次运算。
- **空间**：$O(256)$，即 `firstSeen` 数组（也可用哈希表，状态数上限同样是 256），与 $n$ 无关。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <array>

using namespace std;

class Solution {
public:
    vector<int> prisonAfterNDays(vector<int>& cells, int n) {
        int state = 0;
        for (int i = 0; i < 8; i++)
            if (cells[i]) state |= 1 << i;

        array<int, 256> firstSeen;
        firstSeen.fill(-1);

        long long day = 0;
        while (day < n && firstSeen[state] == -1) {
            firstSeen[state] = (int)day;      // 记录该状态首次出现的天
            state = nextState(state);
            day++;
        }

        if (day < n) {                        // 发现环：跳过整数个周期
            long long period = day - firstSeen[state];
            long long rest = (n - day) % period;
            for (long long k = 0; k < rest; k++) state = nextState(state);
        }

        vector<int> res(8, 0);
        for (int i = 0; i < 8; i++) res[i] = (state >> i) & 1;
        return res;
    }

private:
    int nextState(int s) {
        int t = 0;
        for (int i = 1; i <= 6; i++) {
            int l = (s >> (i - 1)) & 1;
            int r = (s >> (i + 1)) & 1;
            if (l == r) t |= 1 << i;          // 左右邻居相同 → 占用
        }
        return t;                             // 两端保持 0
    }
};
```

### Python

```python
class Solution:
    def prisonAfterNDays(self, cells: list[int], n: int) -> list[int]:
        def step(s: int) -> int:
            t = 0
            for i in range(1, 7):
                if ((s >> (i - 1)) & 1) == ((s >> (i + 1)) & 1):
                    t |= 1 << i              # 左右邻居相同 → 占用
            return t                          # 两端保持 0

        state = 0
        for i, v in enumerate(cells):
            if v:
                state |= 1 << i

        first = {}                            # 状态 -> 首次出现的天
        day = 0
        while day < n and state not in first:
            first[state] = day
            state = step(state)
            day += 1

        if day < n:                           # 发现环：跳过整数个周期
            period = day - first[state]
            for _ in range((n - day) % period):
                state = step(state)

        return [(state >> i) & 1 for i in range(8)]
```

## 8. 边界情况与易错点

1. **"同时更新"语义**：必须用旧状态一次性算出新状态。原地按序修改会让相邻牢房读到新值，结果完全错误。
2. **两端必须归零**：第一天的第 0、7 位一定是 0；忘记处理会让状态空间变成 256 且结果偏差。
3. **$n$ 很大时不能真模拟**：$10^9$ 次循环必有 TLE；必须用"首次重复 + 取模"。
4. **$n$ 很小、还没进环**：循环因 `day == n` 退出，此时若仍执行取模分支会算错（`firstSeen[state]` 尚未赋值），代码中的 `if (day < n)` 正是这个保护。
5. **周期从 $d_0$ 起算而不是从 0 起算**：本题的轨道可能带一段"尾巴"（前若干天不重复），取模必须用 $d_1$ 作为起点，而不是用 0。
6. **`period` 可能为 1**：若某天状态与前一天相同（不动点/2-循环），也要能正常处理；`(n - day) % 1 = 0` 自然正确。
7. **位下标的顺序**：`1 << i` 与输出 `(state >> i) & 1` 必须使用同一套下标约定，否则会得到镜像的结果。
8. **数组初始化**：C++ 的 `array<int,256>` 若不 `fill(-1)`，会读到未定义值，导致"首次出现"判断失效。
