# LeetCode 找到最长的半重复子字符串 题解

## 1. 题目概述

- **标题 / 题号**：找到最长的半重复子字符串（#2730，medium）
- **链接**：https://leetcode.cn/problems/find-the-longest-semi-repetitive-substring/
- **来源**：LeetCode 第 106 场双周赛 Q2
- **难度**：中等
- **标签**：字符串、滑动窗口

**题意**：给定只含数字字符 `0`~`9` 的字符串 `s`。若字符串 $t$ 中**至多有一对**相邻字符相等，则称 $t$ 是**半重复的**（例如 `"54944"` 是：只有 `44` 一对；`"00101022"` 不是：`00` 与 `22` 两对）。返回 `s` 中最长**半重复子字符串**的长度。

**约束**：

- $1 \le s.length \le 50$
- $s[i]$ 是数字字符

## 2. 示例

**示例 1**

```text
输入：s = "52233"
输出：4
解释：最长半重复子字符串是 "5223"（"22" 一对）；整个串 "52233" 有 "22"、"33" 两对，超额。
```

**示例 2**

```text
输入：s = "5494"
输出：4
解释：s 本身没有相邻相等对，整个串即答案。
```

**示例 3**

```text
输入：s = "1111111"
输出：2
解释：任何长度 ≥ 3 的子串都有至少两对相邻相等（"11" 出现在两个位置），最长只能取 "11"。
```

## 3. 解题思路

### 3.1 暴力思路

枚举全部 $O(n^2)$ 个子串，对每个子串数一遍相邻相等对，取满足"对数 $\le 1$"的最长者——$O(n^3)$，$n = 50$ 时约 $10^5$ 次操作，能过但难看。真正的考点是识别出"**至多一次违规**"这一形态，套上滑动窗口把复杂度压到 $O(n)$。

### 3.2 核心观察：把"相邻相等对"当窗口计数，超限就收缩

![约束刻画：窗口内相等对 ≤ 1 才合法](images/bw106_q2_window_model.svg)

定义窗口 $[left, right]$ 内的**相等对计数** `pairs`：统计所有满足 $s[k] = s[k+1]$ 的 $k \in [left, right-1]$。则：

$$\text{子串合法} \iff pairs \le 1$$

这是一个"**窗口内违规次数受上限约束**"的经典滑动窗口模型：

- 右端扩张一步，若 $s[right] = s[right-1]$ 则 `pairs += 1`（新纳入的对以 `right-1, right` 为端点，完全落在窗口内）；
- 一旦 `pairs > 1`，从左端收缩：若被移出的相邻对 $s[left] = s[left+1]$ 成立则 `pairs -= 1`，`left += 1`，直到恢复 `pairs ≤ 1`。

收缩到"刚好只剩一对"时窗口不再扩大也没关系——最优点一定在某个 `right` 扩张后、收缩刚完成时被记录（`ans = max(ans, right - left + 1)`）。**合法性关于窗口端点单调**：大窗口合法则其子窗口必合法（相等对只会更少），这正是滑动窗口正确性的根基。

### 3.3 算法流程

![算法流程：扩张计数、超限收缩、记录窗口长度](images/bw106_q2_window_flow.svg)

```text
1. left = 0, pairs = 0, ans = 1（单字符即半重复）
2. for right = 1 .. n−1:
       若 s[right] == s[right−1]：pairs += 1
       while pairs > 1:
           若 s[left] == s[left+1]：pairs −= 1     # 左端的相等对移出窗口
           left += 1
       ans = max(ans, right − left + 1)
3. 返回 ans
```

### 3.4 示例演算

![示例演算：52233 四步窗口滑动，答案 4](images/bw106_q2_walkthrough.svg)

以 `s = "52233"` 逐步走查：

| right | 新字符判定 | pairs | left | 窗口 | ans |
|-------|-----------|-------|------|------|-----|
| 1 | $2 \ne 5$ | 0 | 0 | "52" | 2 |
| 2 | $2 = 2$ ✓ | 1 | 0 | "522" | 3 |
| 3 | $3 \ne 2$ | 1 | 0 | "5223" | **4** |
| 4 | $3 = 3$ ✓ | 2 → 1 | 0 → 2 | "233" | 4 |

`right = 4` 时两对相等并存，触发收缩：`left` 先跳过 `5`（$5 \ne 2$ 不减计数），再移出 `22` 这一对（$s[1] = s[2]$，`pairs` 回到 1），窗口落到下标 $[2..4]$ 的 `"233"`，长度 3 不超过 4。最终答案 4 ✓。对照 `"1111111"`：每一步扩张都恰好顶到 `pairs = 1`，收缩一格后窗口宽度稳定在 2，答案 2 ✓。

## 4. 算法细节

1. **`pairs` 的增量维护**：扩张时只看**跨越新右端点**的一对（$s[right-1], s[right]$），收缩时只看**跨越旧左端点**的一对（$s[left], s[left+1]$）——窗口内其他对不受端点移动影响，这正是计数能 $O(1)$ 增减的原因。
2. **收缩是"步进"而非"跳到"**：虽然可以记录"上一次相等对的位置"直接把 `left` 跳过去，但逐步 `left += 1` 的总代价是 $O(n)$（左端单调右移、全程至多走 $n$ 步），无需优化。
3. **初始 `ans = 1`**：$n = 1$ 时循环不执行，单字符即答案；同时保证任何情况下 `ans ≥ 1`。
4. **窗口何时记录**：先收缩、后记录——若把 `ans = max(...)` 写在 `while` 之前，会把非法窗口的长度计入答案。
5. **相等对计数的语义边界**：`pairs` 统计的是**窗口内部的相邻对**，端点处的判定 `s[left] == s[left+1]` 在 `left` 自增**之前**执行，顺序颠倒会漏减。
6. **值域与字符集无关**：数字字符只是噪声，算法对任意字符集成立；比较的是字符相等而非数值。

## 5. 正确性证明

**引理 1（计数的增量正确性）**：设 $P(l, r) = \#\{k \in [l, r-1] : s[k] = s[k+1]\}$。按算法流程维护的 `pairs` 在每次扩张/收缩结束时等于 $P(left, right)$。

**证明**：归纳。初始 $left = 0, right = 0$（或首次扩张前），$P = 0 = $ `pairs`。扩张 $right \to right+1$ 时，$P(left, right+1) - P(left, right) = [s[right] = s[right+1]]$，新增的 $k = right$ 是唯一跨越新端点的对，算法的 `pairs += 1` 恰与之对应。收缩 $left \to left+1$ 时，$P(left+1, right) - P(left, right) = -[s[left] = s[left+1]]$，被删除的 $k = left$ 是唯一被移出的对，算法的 `pairs -= 1` 对应。∎

**引理 2（合法窗口的单调性）**：若 $[l, r]$ 合法（$P(l, r) \le 1$），则任意子窗口 $[l', r'] \subseteq [l, r]$ 合法；若 $[l, r]$ 非法，则任意包含它的窗口非法。

**证明**：$P$ 关于区间单调不减：$[l', r'] \subseteq [l, r]$ 时 $P(l', r') \le P(l, r) \le 1$；包含时 $P \ge P(l, r) > 1$。∎

**定理**：算法返回的 `ans` 等于最长半重复子串的长度 $OPT$。

**证明**：分两点。(1) **记录皆合法**：每次执行 `ans = max(ans, ...)` 时 `while` 已结束，`pairs ≤ 1`，由引理 1 该计数即 $P(left, right)$，故被记录的窗口都是合法半重复子串，`ans ≤ OPT`。(2) **最优被记录**：先证不变量——**对每个 `right`，本轮结束时算法的 `left` 恰为使 $P(l, right) \le 1$ 的最小左端点**。归纳：维护"循环条件每次求值时 `pairs` $= P(left, right)$"（扩张更新与收缩更新各只动端点处的一对，由引理 1 的增量式保证）。于是 `while` 跳过的每个左端点 $l'$ 在被跳过时刻都有 $P(l', right) > 1$（非法），停在首个合法左端点。归纳传递：设 `right` 轮结束时 `left` 最小合法；`right+1` 轮扩张后，对一切 $l' < left$ 有 $P(l', right+1) \ge P(l', right) > 1$（区间加长只会增多相等对），仍非法，故从当前 `left` 起继续收缩所得仍是全局最小合法左端点。因此每轮记录的长度 $right - left + 1$ 恰是**以 `right` 为右端点的最长合法子串**长度。任取全局最优子串 $[l^*, r^*]$（其右端点为某个 $r^*$），有 $OPT = r^* - l^* + 1 \le r^* - left(r^*) + 1 \le ans$。与 (1) 合并得 `ans = OPT`。∎

## 6. 复杂度分析

- **时间**：$O(n)$。`right` 走 $n-1$ 步；`left` 单调不减、全程至多前进 $n$ 步，均摊后每步常数。
- **空间**：$O(1)$，仅 `left`、`pairs`、`ans` 三个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int longestSemiRepetitiveSubstring(string s) {
        int n = s.size(), left = 0, pairs = 0, ans = 1;
        for (int right = 1; right < n; ++right) {
            if (s[right] == s[right - 1]) ++pairs;    // 新纳入一对相邻相等
            while (pairs > 1) {                        // 相等对超过 1：收缩
                if (s[left] == s[left + 1]) --pairs;    // 左端相等对移出窗口
                ++left;
            }
            ans = max(ans, right - left + 1);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def longestSemiRepetitiveSubstring(self, s: str) -> int:
        left = pairs = 0
        ans = 1                                   # 单字符即半重复
        for right in range(1, len(s)):
            if s[right] == s[right - 1]:          # 新纳入一对相邻相等
                pairs += 1
            while pairs > 1:                      # 相等对超过 1：收缩
                if s[left] == s[left + 1]:        # 左端相等对移出窗口
                    pairs -= 1
                left += 1
            ans = max(ans, right - left + 1)
        return ans
```

> 💡 两份代码均通过官方示例（`4`、`4`、`2`）与 $n=1$、全同字符等边界，并与"枚举全部子串逐个计数"的暴力对拍 2513 组随机数据（$n \le 50$，字符集含全 0/1、全数字、单一字符等定向构造），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：循环不执行，靠初始 `ans = 1` 兜底；初始化成 0 会返回错误答案。
2. **全相同字符**（`"1111111"`）：窗口被"顶"在宽度 2 上——每扩张一次就得收缩一次，答案恰为 2，可用于快速自检。
3. **收缩时判定的下标**：`s[left] == s[left+1]` 必须在 `left += 1` **之前**执行；写反会拿新左端的对去减计数，造成 `pairs` 偏小、窗口虚假合法。
4. **`pairs` 的阈值是 1 不是 2**：允许**恰好一对**相等；`while (pairs >= 2)` 与 `while (pairs > 1)` 等价，但笔误成 `>= 1` 会把合法窗口也收缩掉。
5. **记录答案的位置**：必须在 `while` 收缩**之后**；放前面会把非法长度计入。
6. **连续相等段长于 2**（如 `"0000"`）：段内相邻对有多对（3 对），窗口最多容纳段中 2 个字符——计数按"对"不按"段"，天然正确，无需对段做特殊处理。
