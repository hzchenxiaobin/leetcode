# LeetCode 找到稳定山的下标 题解

## 1. 题目概述

- **标题 / 题号**：找到稳定山的下标（#3285，easy）
- **链接**：https://leetcode.cn/problems/find-indices-of-stable-mountains/
- **来源**：LeetCode 第 139 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：$n$ 座山排成一列，`height[i]` 是第 $i$ 座山的高度，另有阈值 `threshold`。对下标 $i \ge 1$ 的山，若它**左侧相邻**的山足够高——即 $height[i-1] > threshold$——则称第 $i$ 座山是**稳定**的；下标 $0$ 的山没有左邻，规定**永远不稳定**。返回所有稳定山的下标，顺序任意。

**约束**：

- $2 \le n = height.length \le 100$
- $1 \le height[i] \le 100$
- $1 \le threshold \le 100$

## 2. 示例

**示例 1**

```text
输入：height = [1,2,3,4,5], threshold = 2
输出：[3,4]
解释：下标 3 稳定，因为 height[2] = 3 > 2；
     下标 4 稳定，因为 height[3] = 4 > 2。
```

**示例 2**

```text
输入：height = [10,1,10,1,10], threshold = 3
输出：[1,3]
解释：下标 1 的左邻是 10 > 3；下标 3 的左邻是 10 > 3；
     下标 2、4 的左邻都是 1，不满足；下标 0 恒不稳定。
```

**示例 3**

```text
输入：height = [10,1,10,1,10], threshold = 10
输出：[]
解释：阈值抬到 10 后，「严格大于 10」没有任何山能做到，答案为空。
```

三个示例已经覆盖了全部判定分支：**左邻够高 → 稳定**、**左邻不够高 → 淘汰**、**阈值过高 → 空答案**。

## 3. 解题思路

### 3.1 暴力思路

最自然的写法是：对每个下标 $i \in [1, n-1]$，取出它的左邻 `height[i-1]`，与 `threshold` 比一次大小，成立就把 $i$ 收进答案。这就是 $O(n)$ 的一遍扫描。

这里唯一容易走偏的地方是**把「左侧相邻」误读成「左侧任意」**：如果理解成需要检查左侧所有山，就会退化成 $O(n^2)$ 的双重循环，虽然 $n \le 100$ 也能过，但完全是多余的。题意只关心紧挨着的那一座，因为「稳定」是对**相邻两座山**的直接比较，不涉及任何传递性。

所以本题的「暴力」与「最优」其实是同一个写法，工作量全在把题意准确翻译成一次循环。

### 3.2 核心观察：判定彼此独立，只依赖一个前驱

![稳定判定：只与左侧相邻的那一座山有关](images/bw139_q1_stable_rule.svg)

- **无状态**：第 $i$ 座山是否稳定，只取决于 `height[i-1]` 与 `threshold`，与更左边的山、与右边的山、与前面已经判定了多少座**统统无关**。
- **无副作用**：判定不会修改数组，也不会因为某个下标稳定而影响下一个下标，因此可以**顺序扫描、边走边收**。
- **边界固定**：$i=0$ 被题意直接排除，循环从 $1$ 开始是唯一需要记住的下标偏移。

于是判定式可以写成一行：

$$i \text{ 稳定} \iff i \ge 1 \ \wedge\ height[i-1] > threshold$$

### 3.3 算法流程

![示例演算：一次线性扫描填一张判定表](images/bw139_q1_example_walkthrough.svg)

```text
1. ans = 空列表
2. for i = 1 .. n-1:
       若 height[i-1] > threshold:  ans 追加 i
3. 返回 ans
```

没有排序、没有哈希表、没有任何辅助结构——扫描结束后 `ans` 里下标的自然顺序即升序。

### 3.4 示例演算

对示例 1 的 `height = [1,2,3,4,5]`、`threshold = 2`：

| 下标 $i$ | $height[i]$ | 左邻 $height[i-1]$ | 左邻 $> 2$？ | 结论 |
|---|---|---|---|---|
| 0 | 1 | 无 | — | 恒不稳定 |
| 1 | 2 | 1 | 否 | 淘汰 |
| 2 | 3 | 2 | 否（**等于**不算） | 淘汰 |
| 3 | 4 | 3 | 是 | 稳定 ✓ |
| 4 | 5 | 4 | 是 | 稳定 ✓ |

答案为 $[3,4]$。注意下标 $2$ 是本题最隐蔽的陷阱：左邻恰好等于阈值，而条件要求**严格大于**，所以它不稳定。

## 4. 算法细节

1. **起点是 1**：循环变量从 $1$ 开始，既是题目规定（下标 0 不稳定），也避免访问 `height[-1]`。
2. **严格大于**：判定用 `>`，不能用 `>=`。示例 1 的下标 2、示例 3 的全部下标都靠这条区分。
3. **不排序**：题目说「任意顺序返回」，而顺序扫描天然给出升序，无需额外处理。
4. **不修改输入**：只读 `height`，返回新数组，符合 LeetCode 对参数语义的默认约定。
5. **答案可能为空**：阈值高于所有山时返回空列表，不要特判成 `-1` 或补默认值。

## 5. 正确性证明

**引理 1（判定等价）**：对任意下标 $i \ge 1$，算法把 $i$ 放入 `ans` 当且仅当第 $i$ 座山是稳定的。

**证明**：由题意，$i \ge 1$ 稳定 $\iff$「其左侧相邻山的高度严格大于 `threshold`」，而左侧相邻山正是 `height[i-1]`。算法的循环体判断条件恰为 `height[i-1] > threshold`，与定义逐字对应，故充要。∎

**引理 2（下标 0 不被误收）**：算法输出中不含 $0$。

**证明**：循环从 $i=1$ 开始，循环体只在 $i \ge 1$ 时执行，因此 $0$ 从未进入候选集。∎

**定理**：算法返回的数组恰为全部稳定山的下标集合。

**证明**：由引理 2 与引理 1，算法对每个 $i \in [1, n-1]$ 恰好判定一次，判定为真时恰好收集一次、为假时不收集；而 $i=0$ 按题意本就不稳定。故 `ans` 与稳定下标集合互为子集，二者相等。又因扫描顺序递增，输出还是升序的合法顺序。∎

## 6. 复杂度分析

- **时间**：$O(n)$。循环 $n-1$ 次，每次一次整数比较与一次（可能的）追加，均为 $O(1)$。
- **空间**：$O(1)$ 额外空间（不计答案数组）。答案数组最多 $n-1$ 个元素，属于输出本身的开销。
- **下界**：任何算法都必须读入整个数组，故 $\Omega(n)$ 是时间下界，本解已达最优。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> stableMountains(vector<int>& height, int threshold) {
        vector<int> ans;
        for (int i = 1; i < (int)height.size(); i++) {
            if (height[i - 1] > threshold) ans.push_back(i);
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def stableMountains(self, height: List[int], threshold: int) -> List[int]:
        return [i for i in range(1, len(height)) if height[i - 1] > threshold]
```

## 8. 边界情况与易错点

1. **严格大于写成大于等于**：`>=` 会让示例 1 多出下标 2、示例 3 多出全部下标，是最常见的 WA 来源。
2. **漏掉「下标 0 恒不稳定」**：若循环从 $0$ 开始并访问 `height[-1]`，C++ 会越界读内存，Python 会绕到数组末尾（负下标），结果错得毫无提示。
3. **把「左侧相邻」读成「左侧任意」**：会写成 $O(n^2)$ 的双重循环，虽然小数据能过，但对「左侧所有山都大于阈值」这种理解是错的。
4. **阈值大于所有高度**：如示例 3，必须返回空数组 `[]`，而不是返回 `[0]` 或 `-1`。
5. **$n = 2$ 的最小规模**：此时只有下标 1 需要判定，答案是 `[]` 或 `[1]`，不要写死长度假设。
6. **输出顺序**：题目允许任意顺序，但顺序扫描天然升序，没必要为了「任意」去洗牌。
