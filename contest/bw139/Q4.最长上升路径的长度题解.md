# LeetCode 最长上升路径的长度 题解

## 1. 题目概述

- **标题 / 题号**：最长上升路径的长度（#3288，hard）
- **链接**：https://leetcode.cn/problems/length-of-the-longest-increasing-path/
- **来源**：LeetCode 第 139 场双周赛 Q4
- **难度**：困难
- **标签**：数组、二分查找、排序、最长上升子序列

**题意**：给定 $n$ 个两两不同的二维点 `coordinates` 与下标 $k$。若点序列 $(x_1,y_1),\dots,(x_m,y_m)$ 满足

1. 对每个 $i < m$ 都有 $x_i < x_{i+1}$ **且** $y_i < y_{i+1}$（两个坐标都严格递增）；
2. 序列中的每个点都来自 `coordinates`，

则称它是一个长度为 $m$ 的**上升序列**。要求返回**包含** `coordinates[k]` 的最长上升序列的长度（点可以按任意顺序挑选，不要求下标连续）。

**约束**：

- $1 \le n \le 10^5$
- $0 \le coordinates[i][0], coordinates[i][1] \le 10^9$
- `coordinates` 中元素互不相同
- $0 \le k \le n-1$

## 2. 示例

**示例 1**

```text
输入：coordinates = [[3,1],[2,2],[4,1],[0,0],[5,3]], k = 1
输出：3
解释：包含 (2,2) 的最长上升路径是 (0,0) → (2,2) → (5,3)，长度 3。
```

**示例 2**

```text
输入：coordinates = [[2,1],[7,0],[5,6]], k = 2
输出：2
解释：包含 (5,6) 的最长上升路径是 (2,1) → (5,6)，长度 2。
     (7,0) 的 y 更小、x 更大，与 (5,6) 无法共存于同一条上升链。
```

## 3. 解题思路

### 3.1 暴力思路

朴素做法是「先求全体点的最长二维上升链，再想办法把 $k$ 塞进去」，但「最终链必须含 $k$」这个约束会把问题从「求全局最优」变成「求过指定点的最优」，直接套全局 DP 无法保证 $k$ 出现在链上。

若退化为枚举所有链、再筛选含 $k$ 的链：$n=10^5$ 时链的数量指数级，完全不可行。即使只做 $O(n^2)$ 的二维 DP（$f[i]$ = 以 $i$ 结尾的最长链），$10^{10}$ 次转移也超时。

### 3.2 核心观察：$k$ 把问题切成两个互不干扰的象限

![过 k 的上升路径 = 左下最长链 + k + 右上最长链](images/bw139_q4_before_after.svg)

设基准点为 $P_k = (x_k, y_k)$。一条含 $P_k$ 的上升链，按 $x$ 递增排列后 $P_k$ 必然位于某个位置，于是：

- $P_k$ **之前**的点必须满足 $x < x_k$ **且** $y < y_k$——即严格落在 $P_k$ 的**左下**区域；这些点之间的先后关系仍由二维严格上升约束描述，构成一个标准的二维严格 LIS 子问题。
- $P_k$ **之后**的点必须满足 $x > x_k$ **且** $y > y_k$——严格落在**右上**区域，同样是一个二维严格 LIS。
- 其余点（$x$ 比 $k$ 小但 $y$ 更大，或反之）**不可能**与 $P_k$ 共存于同一条上升链，直接丢弃。

于是

$$\text{答案} = L_{\text{左下}} + 1 + L_{\text{右上}}$$

其中 $L_{\text{左下}}$、$L_{\text{右上}}$ 分别是两个区域内二维严格上升链的最大长度，而「$1$」是 $P_k$ 自己。两个子问题**完全独立**（左下所有点的 $x < x_k$，右上所有点的 $x > x_k$，拼接后 $x$ 与 $y$ 仍严格递增），可以分别求最长再相加。

### 3.3 算法流程：二维严格 LIS 的排序技巧

![二维严格 LIS：x 升序 + 同 x 时 y 降序](images/bw139_q4_lis_2d.svg)

二维严格 LIS 的标准做法是「排序 + 一维 LIS」：

1. 把区域内的点按 $x$ **升序**排序；$x$ 相同时按 $y$ **降序**排序。
2. 取出排序后的 $y$ 序列，对它求**严格递增**的 LIS（耐心排序 + `lower_bound`），其长度即为答案。

同 $x$ 时按 $y$ 降序是整套技巧的关键：严格递增 LIS 不可能同时选中两个 $y$ 递减的元素，因此**不会把两个 $x$ 相同的点连进同一条链**，恰好实现了「$x$ 严格递增」。若按 $y$ 升序，就会出现 $y$ 也递增、被 LIS 误选的情况，答案偏大。

```text
1. kx, ky = coordinates[k]
2. lower = 所有满足 x < kx 且 y < ky 的点
   upper = 所有满足 x > kx 且 y > ky 的点
3. L1 = 严格二维 LIS(lower)
   L2 = 严格二维 LIS(upper)
4. 返回 1 + L1 + L2
```

严格 LIS 的实现：维护 `tails`，`tails[t]` 表示「长度为 $t+1$ 的严格递增子序列」的最小结尾值；对每个 $y$，用 `lower_bound` 找到第一个 $\ge y$ 的位置并替换，找不到就追加。`lower_bound`（而非 `upper_bound`）保证等值元素只能替换、不能延长，从而得到**严格**递增的长度。

### 3.4 示例演算

以示例 1 为例，$k=1$、基准点 $(2,2)$：

![示例演算：一个过滤条件把点分成三堆](images/bw139_q4_example_walkthrough.svg)

| 点 | $x < 2$ 且 $y < 2$？ | $x > 2$ 且 $y > 2$？ | 去向 |
|---|---|---|---|
| $(3,1)$ | 否 | 否（$y=1$ 不满足） | 丢弃 |
| $(2,2)$ | — | — | $k$ 本身 |
| $(4,1)$ | 否 | 否 | 丢弃 |
| $(0,0)$ | 是 | 否 | 左下集合 |
| $(5,3)$ | 否 | 是 | 右上集合 |

- 左下集合 $\{(0,0)\}$：只有 $1$ 个点，$L_1 = 1$；
- 右上集合 $\{(5,3)\}$：$L_2 = 1$；
- 答案 $= 1 + 1 + 1 = 3$，对应路径 $(0,0) \to (2,2) \to (5,3)$。

## 4. 算法细节

1. **严格不等**：两个过滤条件都必须是严格不等号。任何「$x$ 相等但 $y$ 不等」或「$y$ 相等」的点都不能与 $P_k$ 同链（题目要求 $x$、$y$ 都严格递增）。
2. **排序的 tie-break 是正确性的一部分**：$x$ 相同按 $y$ **降序**。写反（升序）会让两个同 $x$ 点同时入选，答案偏大。这是本题最容易错的地方。
3. **严格 LIS 用 `lower_bound`**：`tails` 中第一个 $\ge y$ 的位置被替换。若用 `upper_bound`，等值元素会被当作「可以接上」，长度偏大。
4. **两段分别求、最后相加**：不要试图先合并两个集合再一次求 LIS——中间夹着 $P_k$，合并后排序会让不同象限的点被错误连接。
5. **数值范围**：坐标可达 $10^9$，用 `long long` 存点坐标，避免比较时溢出（`int` 在本题够用，但 `long long` 更稳）。
6. **$k$ 本身不进入任一侧**：两个过滤条件都排除 $(x_k,y_k)$ 自身，故不会重复计数。
7. **返回至少为 1**：单点本身构成长度 1 的上升序列。

## 5. 正确性证明

**引理 1（必要分割）**：设 $Q = (q_1, q_2, \dots, q_m)$ 是一条含 $P_k$ 的上升序列（按 $x$ 递增排列）。则 $P_k$ 之前的每个点 $q$ 满足 $q.x < x_k$ 且 $q.y < y_k$；$P_k$ 之后的每个点满足 $q.x > x_k$ 且 $q.y > y_k$。

**证明**：设 $P_k = q_t$。对 $s < t$：上升序列的相邻条件取传递闭包得 $q_s.x < x_k$；按链顺序 $y$ 也严格递增，故 $q_s.y < y_k$。对 $s > t$ 同理得 $q_s.x > x_k$、$q_s.y > y_k$。∎

**引理 2（两段可独立拼接）**：设 $A$ 是左下集合中的一条二维严格上升链，$B$ 是右上集合中的一条二维严格上升链。则把 $A$ 的点按 $x$ 递增、接着 $P_k$、再接 $B$ 的点按 $x$ 递增排列，得到的序列仍是上升序列。

**证明**：链内严格递增由假设保证。跨段部分：$A$ 的所有点 $x < x_k$、$y < y_k$，$B$ 的所有点 $x > x_k$、$y > y_k$，因此「$A$ 的末点 → $P_k$」与「$P_k$ → $B$ 的首点」在 $x$、$y$ 上都严格递增。∎

**引理 3（二维严格 LIS 的排序写法正确）**：把区域内的点按 $(x$ 升序, $y$ 降序$)$ 排序后，对 $y$ 序列求严格递增 LIS，其长度等于该区域内二维严格上升链的最大长度。

**证明**：
（$\ge$）任取一条二维严格上升链，把它的点按 $x$ 递增排列。由于链上 $x$ 严格递增，这些点在排序序列中的位置也严格递增（同 $x$ 的点不会出现在同一条链里，排序的 tie-break 不影响相对顺序）；又链上 $y$ 严格递增，故对应位置的 $y$ 构成一个严格递增子序列，其长度不超过 LIS 长度。
（$\le$）任取一个严格递增的 $y$ 子序列，对应排序序列中位置递增的一组点。排序保证 $x$ 非降；若其中两点 $x$ 相同，则它们在同 $x$ 组内按 $y$ **降序**排列，$y$ 严格递增不可能同时取到（后面的 $y$ 更小），矛盾；故这些点的 $x$ 严格递增。$y$ 严格递增由子序列定义。于是它们构成二维严格上升链，长度不超过最长链长。
两侧夹逼得等号。∎

**定理**：算法返回的值等于包含 `coordinates[k]` 的最长上升路径长度。

**证明**：（上界）任取一条含 $P_k$ 的上升序列，由引理 1 其 $P_k$ 之前的点都在左下集合内、之后的点都在右上集合内，故长度 $\le L_1 + 1 + L_2$。（下界）取左下集合的最长链与右上集合的最长链，由引理 2 可拼接成长度恰为 $L_1 + 1 + L_2$ 的合法上升序列。二者相等，再由引理 3，$L_1, L_2$ 正是算法算出的两个 LIS 长度。∎

## 6. 复杂度分析

- **时间**：过滤一遍 $O(n)$；两段各自排序 $O(n_1 \log n_1) + O(n_2 \log n_2) \le O(n\log n)$；每段 LIS 为 $O(n_i \log n_i)$。总计 $O(n \log n)$，$n = 10^5$ 时约 $1.7\times 10^6$ 次比较，毫秒级。
- **空间**：$O(n)$ 存两个过滤后的点集与 `tails` 数组，$n=10^5$ 时约数 MB。
- **对比**：$O(n^2)$ 的二维 DP 在 $n=10^5$ 时需要 $10^{10}$ 次转移，是本题被优化的主要部分。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxPathLength(vector<vector<int>>& coordinates, int k) {
        long long kx = coordinates[k][0], ky = coordinates[k][1];
        auto longestChain = [](vector<pair<long long, long long>>& pts) -> int {
            sort(pts.begin(), pts.end(), [](const auto& a, const auto& b) {
                if (a.first != b.first) return a.first < b.first;
                return a.second > b.second;
            });
            vector<long long> tails;
            for (auto& p : pts) {
                auto it = lower_bound(tails.begin(), tails.end(), p.second);
                if (it == tails.end()) tails.push_back(p.second);
                else *it = p.second;
            }
            return (int)tails.size();
        };
        vector<pair<long long, long long>> lower, upper;
        for (int i = 0; i < (int)coordinates.size(); i++) {
            long long x = coordinates[i][0], y = coordinates[i][1];
            if (x < kx && y < ky) lower.push_back({x, y});
            else if (x > kx && y > ky) upper.push_back({x, y});
        }
        return longestChain(lower) + 1 + longestChain(upper);
    }
};
```

### Python

```python
from typing import List
from bisect import bisect_left

class Solution:
    def maxPathLength(self, coordinates: List[List[int]], k: int) -> int:
        kx, ky = coordinates[k]

        def longest_chain(pts):
            pts.sort(key=lambda p: (p[0], -p[1]))
            tails = []
            for _, y in pts:
                i = bisect_left(tails, y)
                if i == len(tails):
                    tails.append(y)
                else:
                    tails[i] = y
            return len(tails)

        lower = [(x, y) for x, y in coordinates if x < kx and y < ky]
        upper = [(x, y) for x, y in coordinates if x > kx and y > ky]
        return longest_chain(lower) + 1 + longest_chain(upper)
```

## 8. 边界情况与易错点

1. **同 $x$ 按 $y$ 升序排序**：会让「$x$ 相同」的点被纳入同一条链，答案偏大。必须降序。
2. **`upper_bound` 与 `lower_bound` 混用**：求**严格**递增 LIS 用 `lower_bound`；换成 `upper_bound` 会把相等元素接上，长度偏大。
3. **过滤条件用了 `<=`**：$x$ 或 $y$ 相等时两点不能同链，必须严格不等；用 `<=` 会把同列/同行的点错误计入。
4. **$n = 1$**：两个集合都为空，答案为 $1$，代码需自然返回 $1$ 而不是 $0$。
5. **$k$ 是极端点**：$P_k$ 是全体最小点或最大点时，只有一侧非空，答案 $= 1 + $ 单侧 LIS，无需特判。
6. **`tails` 的单调性**：`tails` 是非降的（对严格 LIS 实际严格递增），二分时依赖这一性质，不要在替换时做多余的去重。
7. **漏算 $P_k$ 自己**：不要写成 $L_1 + L_2$；中间的 $+1$ 是基准点。
