# LeetCode 求出数组中最大序列值 题解

## 1. 题目概述

- **标题 / 题号**：求出数组中最大序列值（#3287，hard）
- **链接**：https://leetcode.cn/problems/find-the-maximum-sequence-value-of-array/
- **来源**：LeetCode 第 139 场双周赛 Q3
- **难度**：困难
- **标签**：位运算、数组、动态规划

**题意**：给定整数数组 `nums` 和正整数 $k$。对长度为 $2x$ 的序列 `seq`，定义其**值**为「前半段按位或」与「后半段按位或」的异或：

$$\bigl(seq[0] \,\vert\, seq[1] \,\vert\, \cdots \,\vert\, seq[x-1]\bigr) \;\oplus\; \bigl(seq[x] \,\vert\, seq[x+1] \,\vert\, \cdots \,\vert\, seq[2x-1]\bigr)$$

求 `nums` 中**所有长度为 $2k$ 的子序列**的值的最大值。

**约束**：

- $2 \le nums.length \le 400$
- $1 \le nums[i] < 2^7$
- $1 \le k \le nums.length / 2$

注意 `nums[i] < 2^7`，即所有元素与所有按位或的结果都落在 $[0, 127]$，只有 **128 种取值**。这个极小的值域是本题的突破口。

## 2. 示例

**示例 1**

```text
输入：nums = [2,6,7], k = 1
输出：5
解释：长度 2 的子序列共 3 个：
     [2,6] → 2 ⊕ 6 = 4；[2,7] → 2 ⊕ 7 = 5；[6,7] → 6 ⊕ 7 = 1。
     最大值为 5（子序列 [2,7]）。
```

**示例 2**

```text
输入：nums = [4,2,5,6,7], k = 2
输出：2
解释：长度为 4 的子序列中，[4,5,6,7] 的值最大：
     (4 | 5) ⊕ (6 | 7) = 5 ⊕ 7 = 2。其他子序列的值都不超过 2。
```

## 3. 解题思路

### 3.1 暴力思路

直接枚举所有长度为 $2k$ 的子序列：数量为 $\binom{n}{2k}$。$n=400$、$k=2$ 时就有 $\binom{400}{4} \approx 1.06\times 10^9$ 个，$k$ 更大时更是天文数字；每个还要花 $O(k)$ 求两次或，完全不可行。

退一步：能不能只枚举「两个或值」？或值只有 $128$ 种，两两组合 $128^2 = 16384$ 种，代价可以接受——**难点在于判断某个组合 $(a,b)$ 是否真能被某个长度为 $2k$ 的子序列实现**。这提示我们：把「能否造出或值 $v$」做成可查询的表。

### 3.2 核心观察：按分割点解耦，前后缀各管一半

![核心解耦：用分割点把「前 k 个」和「后 k 个」切开](images/bw139_q3_split_dp.svg)

设选中的下标为 $i_1 < i_2 < \cdots < i_{2k}$，令**分割点** $i = i_k + 1$。于是：

- 前 $k$ 个元素全部取自 `nums[0..i-1]`，贡献或值 $a$；
- 后 $k$ 个元素全部取自 `nums[i..n-1]`，贡献或值 $b$。

两侧的取值**互不干扰**，只通过分割点 $i$ 耦合。于是定义两个集合族：

$$pre[i][j] = \{\text{从 } nums[0..i-1] \text{ 中选 } j \text{ 个元素能得到的全部或值}\}$$
$$suf[i][j] = \{\text{从 } nums[i..n-1] \text{ 中选 } j \text{ 个元素能得到的全部或值}\}$$

答案即为

$$\max_{k \le i \le n-k} \;\max_{a \in pre[i][k],\, b \in suf[i][k]} (a \oplus b)$$

$i$ 的下界 $k$ 保证左边够选 $k$ 个，上界 $n-k$ 保证右边够选 $k$ 个。

### 3.3 算法流程与状态转移

![集合 DP 的转移：不选或选（并上当前元素）](images/bw139_q3_set_transition.svg)

$pre$ 的转移是经典的「选或不选」：

$$pre[i][j] = pre[i-1][j] \;\cup\; \{\, v \mid nums[i-1] \;:\; v \in pre[i-1][j-1] \,\}$$

含义：要么不用 `nums[i-1]`（直接继承 $pre[i-1][j]$），要么用上它（在「选 $j-1$ 个」的每个或值上按位或）。$suf$ 完全对称，从右往左推：

$$suf[i][j] = suf[i+1][j] \;\cup\; \{\, v \mid nums[i] \;:\; v \in suf[i+1][j-1] \,\}$$

初始化 $pre[0][0] = \{0\}$、$suf[n][0] = \{0\}$（选 $0$ 个元素的或值是 $0$）。

```text
1. 递推 pre[i][j]（i = 1..n，j = 1..min(k, i)）
2. 递推 suf[i][j]（i = n-1..0，j = 1..min(k, n-i)）
3. ans = 0
4. for i = k .. n-k:
       for a in pre[i][k]:
           for b in suf[i][k]:
               ans = max(ans, a ^ b)
5. 返回 ans
```

因为值域只有 $128$，每个集合都可以用一个 $128$ 位 bitset 存：转移时枚举 $v \in pre[i-1][j-1]$ 做一次按位或，单次转移 $O(128)$；最后枚举分割点做 $128 \times 128$ 的配对。

### 3.4 示例演算

以示例 2 的 `nums = [4,2,5,6,7]`、$k=2$ 为例，只需关心 $j=2$ 那一列：

| $i$ | $pre[i][2]$ | 说明 |
|---|---|---|
| 2 | $\{6\}$ | 只有 $\{4,2\}$，$4\vert2 = 6$ |
| 3 | $\{5,6,7\}$ | 加入 $5$：$4\vert5=5$、$2\vert5=7$、$5\vert6=7$，并保留 $6$ |
| 4 | $\{5,6,7\}$ | 加入 $6$：$4\vert6=6$、$2\vert6=6$、$5\vert6=7$，集合已饱和 |
| 5 | $\{5,6,7\}$ | 加入 $7$ 后或值仍是 $7$，不产生新值 |

| $i$ | $suf[i][2]$ | 说明 |
|---|---|---|
| 5 | 不存在（右侧不足 2 个） | $n-i = 0 < 2$ |
| 4 | 不存在 | |
| 3 | $\{7\}$ | $\{6,7\}$ 中取两个：$6\vert7 = 7$ |
| 2 | $\{7\}$ | $\{5,6,7\}$ 任取两个，或值都是 $7$ |

可用的分割点只有 $i \in [2, 3]$：

![示例 2 演算：两个分割点、一组 128 内的配对](images/bw139_q3_example_walkthrough.svg)

| 分割点 $i$ | $pre[i][2]$ | $suf[i][2]$ | 两两异或的最大值 |
|---|---|---|---|
| 2 | $\{6\}$ | $\{7\}$ | $6 \oplus 7 = 1$ |
| 3 | $\{5,6,7\}$ | $\{7\}$ | $\max(5\oplus7, 6\oplus7, 7\oplus7) = 2$ |

故答案为 $2$，对应的子序列是 $[4,5,6,7]$：$4\vert5 = 5$，$6\vert7 = 7$，$5 \oplus 7 = 2$。示例 1 同理：$k=1$ 时分割点 $i \in [1,2]$，$pre[1][1]=\{2\}$ 与 $suf[1][1]=\{6,7\}$ 配对得到 $2\oplus7 = 5$，已是最大值。

## 4. 算法细节

1. **值域压缩**：`nums[i] < 2^7` 保证所有或值 $< 128$。C++ 用 `bitset<128>`，Python 用 `set`，两者都只需要 128 个位置。
2. **两维边界**：$pre[i][j]$ 只在 $j \le i$ 时存在，$suf[i][j]$ 只在 $j \le n-i$ 时存在；递推时用 `min(k, i)` / `min(k, n-i)` 截断，避免写出越界的空集合。
3. **$j=0$ 的语义**：空选取的或值是 $0$。必须显式置 $pre[i][0]=\{0\}$，否则递推无法从「选 0 个」起步。
4. **分割点范围**：$i \in [k, n-k]$。若 $n = 2k$ 则只有 $i=k$ 一个分割点，退化为「恰好分成前后两半」。
5. **答案初值取 0**：异或结果非负，$0$ 是合法下界（例如所有元素相同、或值相等时）。
6. **递推顺序**：$pre$ 按 $i$ 递增，$suf$ 按 $i$ 递减；两表互不依赖，可先后计算。$pre[i][j]$ 只依赖 $i-1$ 行，空间上可滚动，但 $n \times k \times 128$ 位（约 $10^7$ 位）本来就很小，直接开满更省心。

## 5. 正确性证明

**引理 1（$pre$ 的含义）**：对任意 $0 \le i \le n$、$0 \le j \le \min(k,i)$，$pre[i][j]$ 恰为「从 `nums[0..i-1]` 中选 $j$ 个元素（保序）所能得到的全部按位或值」。

**证明**：对 $i$ 归纳。$i=0$ 时只能选 $0$ 个，$pre[0][0]=\{0\}$ 正确。设对 $i-1$ 成立，考虑 $pre[i][j]$：任何从 `nums[0..i-1]` 选 $j$ 个的方案，要么不含 `nums[i-1]`（或值属于 $pre[i-1][j]$），要么含 `nums[i-1]`（其余 $j-1$ 个从 `nums[0..i-2]` 选，或值属于 $pre[i-1][j-1]$，整体为 $v \mid nums[i-1]$）。两种情形正好对应转移式右端的两项，故无遗漏；反向，转移式右端的每个值都有对应的选取方案，故无多算。∎

**引理 2（$suf$ 对称成立）**：$suf[i][j]$ 恰为「从 `nums[i..n-1]` 中选 $j$ 个元素所能得到的全部或值」。证明与引理 1 对称（从右往左归纳）。∎

**引理 3（覆盖：任意子序列都被某个分割点捕获）**：对任意长度为 $2k$ 的子序列，其下标 $i_1 < \cdots < i_{2k}$，取 $i = i_k+1$，则前 $k$ 个元素取自 `nums[0..i-1]`、后 $k$ 个取自 `nums[i..n-1]`，且

$$\bigl(\,\mathrm{OR}(i_1..i_k),\; \mathrm{OR}(i_{k+1}..i_{2k})\,\bigr) \in pre[i][k] \times suf[i][k]$$

**证明**：由 $i = i_k + 1$ 得 $i_k = i-1 < i$，故前 $k$ 个下标都 $\le i-1$；又 $i_{k+1} > i_k = i-1$，即 $i_{k+1} \ge i$，故后 $k$ 个下标都 $\ge i$。由引理 1、2，两侧的或值分别属于对应集合。同时 $i \ge i_k \ge k$（前 $k$ 个下标至少占 $k$ 个位置）、$n - i \ge 2k - k = k$（后 $k$ 个下标都在 $[i, n-1]$），故 $i \in [k, n-k]$，落在算法枚举范围内。∎

**引理 4（可达：枚举出的每个组合都能实现）**：对任意 $i \in [k, n-k]$、$a \in pre[i][k]$、$b \in suf[i][k]$，存在长度为 $2k$ 的子序列，其值为 $a \oplus b$。

**证明**：由引理 1，存在下标集合 $A \subseteq [0, i-1]$、$|A| = k$ 使 $\mathrm{OR}(A) = a$；由引理 2，存在 $B \subseteq [i, n-1]$、$|B| = k$ 使 $\mathrm{OR}(B) = b$。把 $A$、$B$ 的元素按升序拼成 $2k$ 个下标：因 $A$ 中每个下标 $< i \le B$ 中每个下标，拼接后整体严格递增，确为合法子序列；其前后两半分别取自 $A$、$B$，值恰为 $a \oplus b$。∎

**定理**：算法返回的值等于所有长度为 $2k$ 的子序列的值的最大值。

**证明**：记 $\mathcal{S}$ 为全部长度 $2k$ 子序列的值的集合，$\mathcal{T}$ 为算法枚举的全部 $a \oplus b$。由引理 3，$\mathcal{S} \subseteq \mathcal{T}$，故 $\max \mathcal{S} \le \max \mathcal{T}$；由引理 4，$\mathcal{T} \subseteq \mathcal{S}$，故 $\max \mathcal{T} \le \max \mathcal{S}$。两侧夹逼得 $\max \mathcal{T} = \max \mathcal{S}$，算法返回的正是后者。∎

## 6. 复杂度分析

- **时间**：
  - 递推 $pre$：$O(n k \cdot 128)$，每个状态枚举 $128$ 个或值；
  - 递推 $suf$：同样 $O(n k \cdot 128)$；
  - 枚举分割点与配对：$O((n - 2k + 1) \cdot 128^2)$。
  
  取 $n=400$、$k=200$ 的量级：$2 \times 400 \times 200 \times 128 \approx 2.0 \times 10^7$，配对部分 $400 \times 16384 \approx 6.5\times 10^6$，均可轻松通过。
- **空间**：$O(n k \cdot 128)$ 位；C++ 的 `bitset<128>` 每个 $16$ 字节，$401 \times 201 \times 16 \approx 1.3$ MB（两张表约 $2.6$ MB），Python 的集合版本约数十 MB，仍在限制内。
- **瓶颈**：配对部分的 $128^2$ 与状态数无关，是固定开销；真正随 $n, k$ 增长的是 $O(nk \cdot 128)$ 的集合合并。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxValue(vector<int>& nums, int k) {
        int n = nums.size();
        vector<vector<bitset<128>>> pre(n + 1, vector<bitset<128>>(k + 1));
        vector<vector<bitset<128>>> suf(n + 1, vector<bitset<128>>(k + 1));
        pre[0][0].set(0);
        for (int i = 1; i <= n; i++) {
            pre[i][0].set(0);
            for (int j = 1; j <= k && j <= i; j++) {
                pre[i][j] = pre[i - 1][j];
                for (int v = 0; v < 128; v++) {
                    if (pre[i - 1][j - 1].test(v)) pre[i][j].set(v | nums[i - 1]);
                }
            }
        }
        suf[n][0].set(0);
        for (int i = n - 1; i >= 0; i--) {
            suf[i][0].set(0);
            for (int j = 1; j <= k && j <= n - i; j++) {
                suf[i][j] = suf[i + 1][j];
                for (int v = 0; v < 128; v++) {
                    if (suf[i + 1][j - 1].test(v)) suf[i][j].set(v | nums[i]);
                }
            }
        }
        int ans = 0;
        for (int i = k; i + k <= n; i++) {
            for (int a = 0; a < 128; a++) {
                if (!pre[i][k].test(a)) continue;
                for (int b = 0; b < 128; b++) {
                    if (suf[i][k].test(b)) ans = max(ans, a ^ b);
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxValue(self, nums: List[int], k: int) -> int:
        n = len(nums)
        pre = [[set() for _ in range(k + 1)] for _ in range(n + 1)]
        suf = [[set() for _ in range(k + 1)] for _ in range(n + 1)]
        pre[0][0] = {0}
        for i in range(1, n + 1):
            pre[i][0] = {0}
            for j in range(1, min(k, i) + 1):
                cur = set(pre[i - 1][j])
                for v in pre[i - 1][j - 1]:
                    cur.add(v | nums[i - 1])
                pre[i][j] = cur
        suf[n][0] = {0}
        for i in range(n - 1, -1, -1):
            suf[i][0] = {0}
            for j in range(1, min(k, n - i) + 1):
                cur = set(suf[i + 1][j])
                for v in suf[i + 1][j - 1]:
                    cur.add(v | nums[i])
                suf[i][j] = cur
        ans = 0
        for i in range(k, n - k + 1):
            for a in pre[i][k]:
                for b in suf[i][k]:
                    ans = max(ans, a ^ b)
        return ans
```

## 8. 边界情况与易错点

1. **分割点范围写成 $[0, n]$**：$i < k$ 时左侧不够 $k$ 个、$i > n-k$ 时右侧不够 $k$ 个，正确范围是 $[k, n-k]$。放宽范围不会算错（不合法一侧的集合为空，配对自然为空），但会让人误以为 $i$ 可以任取，也让 Python 版本白白跑大量空集配对；更重要的是，此时 `pre[i][k]` 根本**没有被计算过**，换一种实现（例如把集合换成定长数组并直接取行）就会读到未定义内容。
2. **忘了 $j=0$ 初始化**：$pre[i][0]$、$suf[i][0]$ 必须含 $0$，否则第一层的「选 1 个」无法递推。
3. **值域假设写死**：`nums[i] < 2^7` 才保证或值 $<128$。若把 `bitset` 维度写成 `1<<6`（即 64），$nums[i] \ge 64$ 时会越界。
4. **异或结果当或值用**：目标是 $\mathrm{OR}_1 \oplus \mathrm{OR}_2$，不是再取或；示例 2 中 $5 \oplus 7 = 2$ 说明异或会让数值变小，不能用单调性剪枝。
5. **$n = 2k$**：只有一个分割点 $i=k$，此时答案就是「前半恰好 $k$ 个、后半恰好 $k$ 个」的值，别让循环条件 `i + k <= n` 漏掉。
6. **答案下界**：异或可能为 $0$（如两个或值相同），`ans` 初值取 $0$ 即可，不要初始化为 $-1$ 之后再特判。
7. **Python 集合的规模**：因为或值单调只增，集合大小上限为 $128$，不会爆；但若把 `cur = set(pre[i-1][j])` 写成 `cur = pre[i-1][j]` 再原地 `add`，会污染上一层，答案出错。
