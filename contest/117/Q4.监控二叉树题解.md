# LeetCode 监控二叉树 题解

## 1. 题目概述

- **标题 / 题号**：监控二叉树（#968，hard）
- **链接**：https://leetcode.cn/problems/binary-tree-cameras/
- **来源**：LeetCode 第 117 场周赛 Q4
- **难度**：困难
- **标签**：树、深度优先搜索、动态规划、二叉树、树形 DP

**题意**：给定一棵二叉树，可以在某些节点上安装摄像头。每个摄像头能监视**它的父节点、它自己、以及它的直接子节点**。求监视树中**所有**节点所需的最少摄像头数量。

**约束**：

- 节点数在 $[1, 1000]$ 内
- 每个节点的值都是 0

## 2. 示例

**示例 1**

```text
输入：[0,0,null,0,0]
输出：1
解释：        root
            /
           0
          / \
         0   0
      在中间那个节点（root 的左孩子）装一个摄像头，
      即可覆盖它的父节点、自身、两个子节点 —— 全部 4 个节点。
```

**示例 2**

```text
输入：[0,0,null,0,null,0,null,null,0]
输出：2
解释：树是一条链：root → A → B → C →（C 的右孩子）D。
      最少需要 2 个摄像头，例如装在 C 和 root 上。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举"哪些节点装摄像头"的全部子集（$2^n$），对每个子集检查是否覆盖所有节点，取最小。

- 时间 $O(2^n \cdot n)$：$n = 1000$ 时完全不可行；
- 即使改用树形 DP 的三状态递推，也是 $O(n)$，但需要处理较多状态转移；本题有一个非常干净的**贪心**做法。

### 3.2 核心观察：后序遍历 + 三状态贪心

![三种状态：未覆盖 / 有摄像头 / 已覆盖](images/wc117_q4_states.svg)

自底向上（后序）处理，每个节点向上返回一个状态：

| 状态 | 含义 |
|------|------|
| **0** | 该节点**未被覆盖**（子树内其余节点都已覆盖） |
| **1** | 该节点**装了摄像头** |
| **2** | 该节点**已被覆盖**，但没有摄像头 |

空节点（`null`）视为状态 **2**（已覆盖，因为它不需要被覆盖）。

对节点 $u$（已拿到左右孩子的状态 $l, r$），按下面的顺序决策：

1. **若 $l = 0$ 或 $r = 0$**：有孩子未被覆盖，而该孩子唯一的"外部救命稻草"就是 $u$（它的孩子都在其子树内、且状态 0 意味着它们没有摄像头）。所以**必须在 $u$ 装摄像头**：`ans++`，返回状态 1。
2. **否则若 $l = 1$ 或 $r = 1$**：孩子里有摄像头，$u$ 已被覆盖。贪心地**不装**摄像头（留给父节点），返回状态 2。
3. **否则**（两个孩子都是 2 或空）：$u$ 没有被覆盖，返回状态 0，把希望交给父节点。

最后单独检查根节点：若根返回 0（没人覆盖它），再补一个摄像头（`ans++`）。

![贪心流程：后序遍历 + 三状态决策](images/wc117_q4_flow.svg)

> 💡 **直觉**：摄像头应该**尽量往上放**。放在 $u$ 上，能同时覆盖 $u$ 的父、$u$、$u$ 的两个孩子；放在 $u$ 的孩子上，覆盖范围明显更小。所以"发现孩子没被覆盖时，在父节点补摄像头"是划算的；而"已经能被孩子的摄像头覆盖时就不装、把机会留给父节点"同样划算。

### 3.3 算法流程

```text
1. ans = 0
2. dfs(u):
       若 u 为空:  return 2                      // 空节点视为已覆盖
       l = dfs(u.left), r = dfs(u.right)
       若 l == 0 或 r == 0:  ans += 1;  return 1   // 孩子未覆盖 → 自己装
       若 l == 1 或 r == 1:  return 2             // 孩子有摄像头 → 自己已覆盖
       return 0                                  // 自己未覆盖，交给父节点
3. 若 dfs(root) == 0:  ans += 1                  // 根无人覆盖 → 补一个
4. return ans
```

### 3.4 示例演算

![示例 2 的链式结构：自底向上决策](images/wc117_q4_walkthrough.svg)

对示例 2 的链 `root → A → B → C → D`（$D$ 是 $C$ 的右孩子），自底向上：

| 节点 | 孩子状态 | 判定 | 动作 | 返回状态 | ans |
|------|----------|------|------|----------|-----|
| D（叶子） | 空、空 | 都不是 0/1 | 不装，交给父节点 | 0 | 0 |
| C | 左空（2）、右 D（0） | 有孩子未覆盖 | **装摄像头** | 1 | 1 |
| B | 左 C（1）、右空（2） | 孩子有摄像头 | 不装，已被覆盖 | 2 | 1 |
| A | 左 B（2）、右空（2） | 孩子都已覆盖但无摄像头 | 不装，自己未覆盖 | 0 | 1 |
| root | 左 A（0）、右空（2） | 有孩子未覆盖 | **装摄像头** | 1 | 2 |

根返回 1（已装），不需要补，答案 2 ✓。

示例 1：两个叶子都返回 0，根因此装 1 个摄像头，根返回 1，答案 1 ✓。

## 4. 算法细节

1. **状态判定的顺序不能换**：必须先判"有孩子未覆盖"（要装），再判"有孩子有摄像头"（已覆盖），最后才是"都覆盖但无摄像头"（未覆盖）。顺序换错会把该装摄像头的情况漏掉。
2. **空节点返回 2**：空节点不需要被覆盖，若返回 0 会诱使父节点多装摄像头。
3. **根节点的收尾**：根没有父节点，若它返回 0 说明没人覆盖它，必须再补一个；若返回 1 或 2 则不用。
4. **计数器用成员变量或引用传递**：递归中累加 `ans`，不要试图通过返回值同时传递"状态"和"数量"。
5. **递归深度**：$n \le 1000$，链状树深度 1000，递归不会爆栈（C++ 默认栈足够；若上限放大到 $10^5$ 需改迭代或手动栈）。
6. **摄像头可以覆盖"父、自身、直接子"三代**：这正是状态设计只区分"被覆盖/未覆盖/有摄像头"的原因——不需要知道更远的信息。
7. **不需要区分左右孩子**：两个孩子的状态同等对待，判定时用 `或` 合并即可。
8. **不必真的放摄像头**：只需要计数，所有决策都可以在递归返回值中体现。

## 5. 正确性证明

**记号**：对节点 $u$，记 $T_u$ 为以 $u$ 为根的子树。称一个方案**覆盖** $T_u$，若 $T_u$ 中每个节点都被某个摄像头（可以位于 $T_u$ 内，也可以是 $u$ 的父节点）覆盖。

**引理 1（唯一的外部耦合）**：$T_u$ 中除 $u$ 以外的节点，只能被 $T_u$ 内部的摄像头或 $u$ 的摄像头覆盖；$u$ 的父节点及其它外部摄像头与这些节点的距离都 $\ge 2$。

**证明**：任意节点 $v \in T_u$，$v \ne u$，则 $v$ 与 $T_u$ 外部任意节点的路径都要经过 $u$ 再到 $u$ 的父节点，距离至少为 2（当 $v$ 是 $u$ 的孩子时）。摄像头只覆盖距离 $\le 1$ 的节点，故外部摄像头（除 $u$ 自己外）无法覆盖 $v$。∎

**引理 2（交换引理）**：设算法在某次调用中对 $u$ 做出的决策为 $d$（装或不装，以及返回的状态）。则存在一个覆盖全树的最优方案，它在 $T_u$ 内的摄像头集合与算法在 $T_u$ 内已放置的摄像头集合完全相同。

**证明**：对 $u$ 的高度归纳（自底向上）。由归纳假设，对 $u$ 的两个孩子 $v$ 各自存在最优方案与算法在 $T_v$ 内一致；把两个孩子的方案合并，得到 $T_u$ 内除 $u$ 外各决策一致的方案 $O$。下面按算法在 $u$ 的三种情形讨论：

1. **算法在 $u$ 装了摄像头**（某个孩子 $v$ 返回 0）。由状态定义，$v$ 未被覆盖且 $v$ 自身无摄像头；由引理 1，$v$ 只能由 $v$ 的孩子（都在 $T_v$ 内且已无摄像头，否则 $v$ 会被覆盖）或 $u$ 覆盖。因此任何覆盖 $T_u$ 的方案都必须在 $u$ 或 $v$ 装摄像头。若最优方案装在 $v$ 上，改装在 $u$ 上：$v$ 仍被 $u$ 覆盖（$v$ 是 $u$ 的孩子），$v$ 的孩子们在 $O$ 中已由各自子树覆盖（因为 $v$ 状态为 0 意味着 $v$ 没有摄像头，其孩子们只能被更深层覆盖），$u$ 及其父、另一个孩子也因此被覆盖，覆盖率不降低、数量不变。故存在与算法一致的最优方案。
2. **算法不在 $u$ 装、返回 2**（某个孩子有摄像头）。$u$ 已被该摄像头覆盖。若最优方案在 $u$ 装了摄像头，把它移到 $u$ 的父节点 $p$（若 $u$ 是根则直接删除）：$p$ 及其父被覆盖，$u$ 仍被孩子的摄像头覆盖，$u$ 的孩子们由归纳假设已被各自子树覆盖，覆盖不丢、数量不增。故存在与算法一致的最优方案。
3. **算法不在 $u$ 装、返回 0**（两个孩子都已覆盖且无摄像头）。$u$ 未被覆盖。任何覆盖方案必须让 $u$ 或 $u$ 的父节点装摄像头。若最优方案在 $u$ 装，同样移到 $p$ 即可（$u$ 由 $p$ 覆盖，$u$ 的孩子由各自子树覆盖），覆盖不丢、数量不增。故存在不含 $u$ 摄像头的最优方案，与算法一致。

三种情形都成立，归纳完成。∎

**引理 3（算法放置的摄像头是必要的）**：算法每次 `ans += 1` 都对应一个"无论如何都至少需要 1 个摄像头"的局部需求，且不同次的加 1 互不重叠（各自负责互不相交的节点集合）。

**证明**：第 1 类加 1 对应某个返回 0 的孩子 $v$，由引理 1 的论证，$v$ 必须由 $u$ 或 $v$ 覆盖，且这些 $v$ 分属不同的子树分支（每个 $u$ 至多触发一次），需求互不重叠。根节点的收尾加 1 对应根自身无人覆盖。∎

**定理**：算法返回的摄像头数是最小的。

**证明**：由引理 2，存在最优方案与算法的全部决策一致，故算法得到的方案可行（覆盖全树）且其数量等于该最优方案的数量；又由引理 3，任何方案都至少需要这么多个摄像头。故算法的数量恰为最小值。∎

## 6. 复杂度分析

- **时间**：$O(n)$，每个节点访问一次，转移是 $O(1)$ 的分支判断。
- **空间**：$O(h)$，递归栈深度等于树高；最坏（链状）$O(n)$，最好（平衡）$O(\log n)$。除栈外没有额外空间。

## 7. 参考代码

### C++

```cpp
#include <algorithm>

using namespace std;

class Solution {
public:
    int minCameraCover(TreeNode* root) {
        ans = 0;
        if (dfs(root) == 0) ans++;    // 根无人覆盖 → 补一个
        return ans;
    }

private:
    int ans = 0;

    // 返回值：0 = 未覆盖，1 = 有摄像头，2 = 已覆盖且无摄像头
    int dfs(TreeNode* node) {
        if (!node) return 2;          // 空节点视为已覆盖

        int l = dfs(node->left);
        int r = dfs(node->right);

        if (l == 0 || r == 0) {       // 有孩子未覆盖 → 必须在此装摄像头
            ans++;
            return 1;
        }
        if (l == 1 || r == 1) return 2;   // 孩子有摄像头 → 自己已覆盖
        return 0;                          // 自己未覆盖，交给父节点
    }
};
```

### Python

```python
class Solution:
    def minCameraCover(self, root: "TreeNode") -> int:
        ans = 0

        # 返回值：0 = 未覆盖，1 = 有摄像头，2 = 已覆盖且无摄像头
        def dfs(node) -> int:
            nonlocal ans
            if node is None:
                return 2                       # 空节点视为已覆盖

            l = dfs(node.left)
            r = dfs(node.right)

            if l == 0 or r == 0:               # 有孩子未覆盖 → 必须在此装摄像头
                ans += 1
                return 1
            if l == 1 or r == 1:               # 孩子有摄像头 → 自己已覆盖
                return 2
            return 0                           # 自己未覆盖，交给父节点

        if dfs(root) == 0:                     # 根无人覆盖 → 补一个
            ans += 1
        return ans
```

## 8. 边界情况与易错点

1. **单节点树**：根是叶子，返回 0，最后补 1，答案 1（必须给根的自身装摄像头）。
2. **忘记根节点的收尾**：若根返回 0 而不再补一个，根将永远不被覆盖。这是本题最常见的 WA。
3. **空节点返回 0**：会让父节点误以为孩子未覆盖而多装摄像头（例如 `[0,0]` 会得到 2 而不是 1）。
4. **判定顺序写反**：先判"孩子有摄像头"再判"孩子未覆盖"，会把"必须装"的情形误判成"已覆盖"，导致漏覆盖。
5. **两个孩子的状态处理**：只要有一个是 0 就必须装；只要有一个是 1 就已覆盖；两者都不满足才是"未覆盖"。不要只检查左孩子。
6. **摄像头覆盖三代**：父、自身、直接子。不要误以为是"整棵子树"或"只覆盖自身"。
7. **递归深度**：$n \le 1000$ 时链状树深度 1000，递归安全；若题目放大规模，应改为显式栈的后序遍历。
8. **状态的语义要统一**：本实现里 0 表示"未覆盖"而不是"空"，与"空节点返回 2"配合才能自洽；若把 0 当作"空"会导致整棵树恒返回 0。

**延伸思考**：本题也可以写成标准的三状态树形 DP：设 $A(u)$ 为"$u$ 装摄像头且子树全覆盖"的最小数量、$B(u)$ 为"$u$ 被覆盖但不装"的最小数量、$C(u)$ 为"$u$ 未覆盖、子树其余全覆盖"的最小数量，转移为 $A(u) = 1 + \sum\min(A,B,C)$、$B(u) = \sum\min(A,B)$ 且至少一个孩子取 $A$、$C(u) = \sum\min(A,B)$，最后答案为 $\min(A(root), B(root))$。贪心本质上是这个 DP 的一个特例，因为它只需要区分"必须装/不必装/来不及覆盖"三种情形；若给每个摄像头加上不同的费用（加权版本），贪心不再最优，必须回到 DP。
