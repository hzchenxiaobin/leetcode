# LeetCode 元音拼写检查器 题解

## 1. 题目概述

- **标题 / 题号**：元音拼写检查器（#966，medium）
- **链接**：https://leetcode.cn/problems/vowel-spellchecker/
- **来源**：LeetCode 第 117 场周赛 Q3
- **难度**：中等
- **标签**：数组、哈希表、字符串

**题意**：给定单词表 `wordlist` 与若干查询 `queries`，对每个查询按下面的**优先级**返回纠正后的单词：

1. **完全匹配**（区分大小写）：若 `query` 与 `wordlist` 中某个单词完全相同，返回它本身；
2. **大小写错误**：若忽略大小写后与 `wordlist` 中某词相同，返回 `wordlist` 中**第一个**这样的单词（保留其原始大小写）；
3. **元音错误**：若把 `query` 中的元音（`a`、`e`、`i`、`o`、`u`）替换成任意元音、并忽略大小写后，能与 `wordlist` 中某词相同，返回 `wordlist` 中**第一个**这样的单词；
4. 都不满足则返回空串 `""`。

**约束**：

- $1 \le wordlist.length,\ queries.length \le 5000$
- $1 \le$ 每个单词的长度 $\le 7$
- `wordlist[i]`、`queries[i]` 只包含英文字母

## 2. 示例

**示例 1**

```text
输入：wordlist = ["KiTe","kite","hare","Hare"]
     queries = ["kite","Kite","KiTe","Hare","HARE","Hear","hear","keti","keet","keto"]
输出：["kite","KiTe","KiTe","Hare","hare","","","KiTe","","KiTe"]
解释：
  "kite" 完全匹配 → "kite"
  "Kite" 忽略大小写匹配到 "KiTe"（它在 wordlist 中更靠前）→ "KiTe"
  "KiTe" 完全匹配 → "KiTe"
  "Hare" 完全匹配 → "Hare"
  "HARE" 忽略大小写匹配到 "hare" → "hare"
  "Hear"/"hear" 元音归一化后是 "haar"，wordlist 中没有 → ""
  "keti"/"keto" 元音归一化后是 "kata"，匹配到 "KiTe" → "KiTe"
  "keet" 归一化后是 "kaat"，无匹配 → ""
```

**示例 2**

```text
输入：wordlist = ["yellow"], queries = ["YellOw"]
输出：["yellow"]
解释：忽略大小写匹配到唯一单词 "yellow"，返回它原始的大小写形式。
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询，按优先级遍历整个 `wordlist` 做比较：

- 第一级：直接字符串比较；
- 第二级：统一转小写再比较；
- 第三级：转小写后把元音统一替换成同一个字符，再比较。

时间 $O(\lvert queries\rvert \cdot \lvert wordlist\rvert \cdot L)$，其中 $L \le 7$：$5000 \times 5000 \times 7 \approx 1.75\times10^8$ 次字符操作。C++ 勉强、Python 必然超时。而且每一级都要重复扫描，浪费了大量工作。

### 3.2 核心观察：三个"归一化键"各建一张哈希表

![三级匹配对应三种键：原词、小写、元音归一化](images/wc117_q3_three_keys.svg)

三级规则其实都是"把词映射成某个键后查表"：

| 优先级 | 匹配方式 | 键的构造 |
|--------|----------|----------|
| 1 | 完全匹配 | 原词本身 |
| 2 | 忽略大小写 | `lower(w)` |
| 3 | 忽略大小写 + 元音等价 | `lower(w)` 中把所有元音替换成 `'a'`（任意固定元音） |

于是预处理 `wordlist`，建立三张哈希表：

- `exact[w] = w`
- `lower[lower(w)] = w`
- `vowel[devowel(lower(w))] = w`

**关键细节**：同一个键只保留**第一次**出现的单词（插入时若键已存在就不覆盖），这样查到的正是"`wordlist` 中第一个匹配项"。

查询时按优先级依次查表：命中就返回、否则落到下一级，都没命中返回 `""`。总时间降为

$$O\big((\lvert wordlist\rvert + \lvert queries\rvert)\cdot L\big).$$

![查询流程：按优先级依次查三张表](images/wc117_q3_lookup.svg)

> 💡 **一句话总结**：把"逐词比较"换成"按规则归一化成键 + 哈希查表"，每一级都变成 $O(L)$。

### 3.3 算法流程

```text
1. 建三张空表 exact / lower / vowel
2. for w in wordlist:                       // 顺序遍历，先到先得
       exact.putIfAbsent(w, w)
       lw = lower(w)
       lower.putIfAbsent(lw, w)
       vw = devowel(lw)                     // 元音 → 'a'
       vowel.putIfAbsent(vw, w)
3. for q in queries:
       若 exact 含 q:            ans.append(q)                 // 完全匹配
       否则若 lower 含 lower(q):  ans.append(lower[lower(q)])
       否则若 vowel 含 devowel(lower(q)):  ans.append(vowel[...])
       否则 ans.append("")
```

### 3.4 示例演算

对示例 1 的 `wordlist = ["KiTe","kite","hare","Hare"]`，建表（先到先得）：

| 键 | `lower` 键 | `vowel` 键 | 值 |
|----|-----------|-----------|-----|
| `KiTe` | `kite` | `kata` | `KiTe` |
| `kite` | `kite`（已存在，不覆盖） | `kata`（已存在，不覆盖） | — |
| `hare` | `hare` | `hara` | `hare` |
| `Hare` | `hare`（已存在，不覆盖） | `hara`（已存在，不覆盖） | — |

于是：

| 查询 | 命中级别 | 结果 |
|------|----------|------|
| `kite` | 1（完全匹配） | `kite` |
| `Kite` | 2（`kite`） | `KiTe` |
| `KiTe` | 1 | `KiTe` |
| `Hare` | 1 | `Hare` |
| `HARE` | 2（`hare`） | `hare` |
| `Hear` / `hear` | 归一化 `haar`，无 | `""` |
| `keti` / `keto` | 归一化 `kata` | `KiTe` |
| `keet` | 归一化 `kaat`，无 | `""` |

与示例输出完全一致。

## 4. 算法细节

1. **"第一次出现"用 putIfAbsent**：C++ 用 `map.emplace(key, value)`（键存在则不覆盖）或先 `count` 再插入；Python 用 `dict.setdefault(key, w)`。若直接赋值，后出现的词会覆盖前面的，违反"返回第一个匹配"。
2. **先小写再元音归一化**：大小写必须先处理，否则 `KiTe` 与 `kite` 的归一化键不同（`K` 不会被替换成元音，但大小写仍不同）。
3. **元音集合是 `a e i o u`**：**不包含 `y`**，也不包含其它字母；把 `y` 当元音是常见错误。
4. **归一化的"代表字符"任选**：把元音统一替换成 `'a'`、`'0'` 或 `'*'` 都可以，只要保证不会与真正的辅音冲突（用 `'a'` 是安全的，因为元音位置本来就允许任意元音）。
5. **第 1 级可以直接返回 `q`**：完全匹配说明 `q` 本身就在 `wordlist` 里，返回 `q` 与返回表中的值等价。
6. **字符长度只有 7**：哈希键很短，字符串哈希开销可控；用 `unordered_map<string,string>` 足够，不必手写哈希。
7. **查询可能命中不同级别**：必须严格按 1 → 2 → 3 的顺序短路，不能先查元音表（否则 `KiTe` 这类完全匹配会被元音匹配"抢走"）。
8. **大小写转换**：只涉及英文字母，`tolower`/`lower()` 都安全；不要用 locale 相关的转换。

## 5. 正确性证明

对单词 $w$ 记 $l(w)$ 为其小写形式，$v(w)$ 为把 $l(w)$ 中所有元音替换成 `'a'` 的结果。

**引理 1（三种键刻画三种匹配）**：对任意查询 $q$ 与单词 $w$：

- $q = w$ ⟺ 键相同（第 1 级）；
- $l(q) = l(w)$ ⟺ $q$ 与 $w$ 忽略大小写相同（第 2 级）；
- $v(q) = v(w)$ ⟺ 存在把 $q$ 的每个元音替换为某个元音、并统一大小写后得到 $w$ 的方案（第 3 级）。

**证明**：

- 第 1、2 级是字符串相等与小写形式相等的直接改写。
- 第 3 级：若 $v(q) = v(w)$，则 $l(q)$ 与 $l(w)$ 长度相同；在非元音位置，$v$ 不改变字符，故 $l(q)$ 与 $l(w)$ 的对应字符相同；在元音位置（$v$ 记为 `'a'`），两词该位置的字符都是元音（否则 $v$ 会保留原字符，与两边都变成 `'a'` 矛盾），因此可以把 $q$ 该位置的元音替换为 $w$ 该位置的元音，逐位匹配。反之，若存在这样的逐位替换，则两词在非元音位置相同、在元音位置都被 $v$ 归为 `'a'`，故 $v(q) = v(w)$。∎

**引理 2（表值是第一个匹配项）**：对每个键 $K$，表中存的值是 `wordlist` 中**第一个**满足"归一化后等于 $K$"的单词。

**证明**：建表时按 `wordlist` 顺序遍历，键不存在才插入（`emplace`/`setdefault` 语义）。因此键 $K$ 第一次被插入时对应的是顺序上第一个单词，后续同键单词不会覆盖它。∎

**定理**：对每个查询，算法返回的字符串符合题面的优先级规则。

**证明**：设查询为 $q$。

- 若存在完全匹配的单词，则 $q$ 本身在 `wordlist` 中，`exact` 表含键 $q$，算法返回 $q$，符合优先级 1（且这是最高优先级）。
- 否则若存在忽略大小写匹配的单词，由引理 1，`lower` 表含键 $l(q)$，由引理 2 表中值为 `wordlist` 中第一个此类单词，算法返回它，符合优先级 2（且不存在更高优先级的匹配）。
- 否则若存在元音容错匹配，同理 `vowel` 表含键 $v(q)$ 且值为第一个匹配项，返回之，符合优先级 3。
- 若三者都不存在，返回空串，符合规则 4。

且算法按 1 → 2 → 3 顺序短路，一旦命中高优先级就不会再考虑低优先级，故优先级顺序也正确。∎

## 6. 复杂度分析

- **时间**：$O\big((\lvert wordlist\rvert + \lvert queries\rvert)\cdot L\big)$，$L \le 7$ 为单词长度。建表时每个单词做 3 次 $O(L)$ 的键构造与 $O(1)$ 摊还的哈希插入；每个查询做至多 3 次 $O(L)$ 的键构造与查找。总计约 $10^4 \times 7$ 次字符操作。
- **空间**：$O\big((\lvert wordlist\rvert)\cdot L\big)$，三张表各存至多 $\lvert wordlist\rvert$ 个长度 $\le 7$ 的字符串；答案数组 $O(\lvert queries\rvert \cdot L)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <string>
#include <unordered_map>
#include <cctype>

using namespace std;

class Solution {
public:
    vector<string> spellchecker(vector<string>& wordlist, vector<string>& queries) {
        unordered_map<string, string> exact, lower, vowel;

        for (const string& w : wordlist) {
            exact.emplace(w, w);                    // 键已存在则不覆盖 → 保留第一个

            string lw = toLower(w);
            lower.emplace(lw, w);

            string vw = devowel(lw);
            vowel.emplace(vw, w);
        }

        vector<string> ans;
        ans.reserve(queries.size());
        for (const string& q : queries) {
            if (exact.count(q)) {
                ans.push_back(q);                   // 1. 完全匹配
                continue;
            }
            string lq = toLower(q);
            auto it = lower.find(lq);
            if (it != lower.end()) {
                ans.push_back(it->second);          // 2. 忽略大小写
                continue;
            }
            auto it2 = vowel.find(devowel(lq));
            if (it2 != vowel.end()) {
                ans.push_back(it2->second);         // 3. 元音容错
                continue;
            }
            ans.push_back("");                      // 4. 无匹配
        }
        return ans;
    }

private:
    static string toLower(const string& s) {
        string r = s;
        for (char& c : r) c = (char)tolower((unsigned char)c);
        return r;
    }

    static string devowel(string s) {
        for (char& c : s) {
            if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u') c = 'a';
        }
        return s;
    }
};
```

### Python

```python
class Solution:
    def spellchecker(self, wordlist: list[str], queries: list[str]) -> list[str]:
        def devowel(w: str) -> str:
            return "".join("a" if c in "aeiou" else c for c in w.lower())

        def low(w: str) -> str:
            return w.lower()

        exact, lower, vowel = {}, {}, {}
        for w in wordlist:
            exact.setdefault(w, w)              # 键已存在则不覆盖 → 保留第一个
            lower.setdefault(low(w), w)
            vowel.setdefault(devowel(w), w)

        ans = []
        for q in queries:
            if q in exact:                       # 1. 完全匹配
                ans.append(q)
            elif low(q) in lower:                # 2. 忽略大小写
                ans.append(lower[low(q)])
            elif devowel(q) in vowel:            # 3. 元音容错
                ans.append(vowel[devowel(q)])
            else:                                # 4. 无匹配
                ans.append("")
        return ans
```

## 8. 边界情况与易错点

1. **`y` 不是元音**：元音集合只有 `a e i o u`；把 `y` 当元音会让 `my` 与 `mi` 之类的词误判。
2. **"第一个匹配"不能被子覆盖**：必须用 `emplace`/`setdefault`；用普通赋值会返回最后一个匹配项，示例 1 的 `Kite` 就会变成 `kite` 而不是 `KiTe`。
3. **优先级必须短路**：`KiTe` 既是完全匹配也是元音匹配，必须优先返回 `KiTe`；如果先查元音表就会出现"正确的词被替换成另一个"。
4. **`wordlist` 中的重复词**：如 `["kite","kite"]`，两次插入同键，保留第一个即可，结果相同。
5. **`wordlist` 中的大小写变体**：示例 1 的 `KiTe` 与 `kite` 共享 `lower` 键与 `vowel` 键，只有先出现的 `KiTe` 会被记住。
6. **全元音词**：如 `"aeiou"` 归一化成 `"aaaaa"`，与 `"uoiea"` 等词同键；这正是题面"元音可以互相替换"的语义，不要误以为需要保留元音的位置信息。
7. **查询词全不匹配**：返回空串 `""`（长度为 0 的字符串），不是 `null` 或原词。
8. **大小写归一化的时机**：必须先转小写再做元音替换（`devowel` 内部先 `lower()`），顺序反了会导致大写元音 `A`、`E` 未被替换。
