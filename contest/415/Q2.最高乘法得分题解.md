# LeetCode 最高乘法得分 题解

## 1. 题目概述

- **标题 / 题号**：最高乘法得分（#3290，medium）
- **链接**：https://leetcode.cn/problems/maximum-multiplication-score/
- **来源**：LeetCode 第 415 场周赛 Q2
- **难度**：中等
- **标签**：数组、动态规划

**题意**：给定大小恒为 4 的整数数组 `a`，和大小**至少**为 4 的整数数组 `b`。从 `b` 中选 4 个**严格递增**的下标 $i_0 < i_1 < i_2 < i_3$，得分为 $a[0] \cdot b[i_0] + a[1] \cdot b[i_1] + a[2] \cdot b[i_2] + a[3] \cdot b[i_3]$，返回能取得的**最大**得分。4 个系数必须**全部**用上，且与选出的 `b` 的**子序列**按序一一配对。

**约束**：

- `a.length == 4`
- $4 \le \text{b.length} \le 10^5$
- $-10^5 \le a[i], b[i] \le 10^5$

> 💡 读题抓三个信号：① 「下标严格递增 + 按序配对」是**双序列按序匹配**结构（LCS 家族），决定了 DP 而非贪心；② 4 个系数**必须配满**，答案可能是负数——状态里必须有「配满与否」的维度；③ 得分绝对值上界 $4 \times 10^{10}$，`int` 必爆，**全程 64 位**。

## 2. 示例

**示例 1**

```text
输入：a = [3,2,5,6], b = [2,-6,4,-5,-3,2,-7]
输出：26
解释：选择下标 0, 1, 2 和 5。得分为 3*2 + 2*(-6) + 5*4 + 6*2 = 26。
```

**示例 2**

```text
输入：a = [-1,4,5,-2], b = [-5,-1,-3,-2,-4]
输出：-1
解释：选择下标 0, 1, 3 和 4。得分为 (-1)*(-5) + 4*(-1) + 5*(-2) + (-2)*(-4) = -1。
```

**示例 3（自造：负系数想要更小的值）**

```text
输入：a = [-1,-1,-1,-1], b = [-5,-1,-3,-2,-4]
输出：14
解释：选下标 0, 2, 3, 4。得分为 (-1)*(-5) + (-1)*(-3) + (-1)*(-2) + (-1)*(-4) = 5+3+2+4 = 14。
```

示例 3 说明「挑大值配大值」的贪心直觉彻底失效：系数为负时反而要挑**最小**的 `b` 值，正负号交错让任何单调配对规则都无法成立。

## 3. 解题思路

### 3.1 暴力思路

四重循环枚举 $i_0 < i_1 < i_2 < i_3$ 的全部组合，共 $\binom{n}{4} \approx \dfrac{n^4}{24} \approx 4 \times 10^{18}$ 种（$n = 10^5$），天文数字。即便做两层优化——最内层按 $a[3]$ 的符号用后缀最大/最小值 $O(1)$ 得出，也只降到 $O(n^3) \approx 10^{15}$，仍不可行；再套后缀最值压到 $O(n^2) \approx 10^{10}$，依旧超时。

同时注意：**不能排序后按「绝对值大配大」贪心**。一是乘积正负交错（负系数配大正数反而亏、负负得正），不存在单调的配对规则；二是排序会破坏「下标严格递增」的位置约束。子序列型最值问题，结构上只能靠 DP 覆盖所有有序匹配方案。

### 3.2 核心观察：按序匹配 = 常数阶段的线性 DP

![核心观察：按序匹配与状态设计](images/max_mult_score_dp_model.svg)

- **观察 1（阶段化）**：约束 $i_0 < i_1 < i_2 < i_3$ 把决策天然切成 4 个阶段——先定 $a[0]$ 配哪个 `b` 元素，再在其**右侧**定 $a[1]$ 配谁，依此类推。每个阶段只在「上一阶段选中位置的右侧」做选择。
- **观察 2（无后效性）**：推进到某个位置时，之前**具体**选了哪些下标并不影响未来，唯一有约束力的是「配对已推进到第几个系数」与「已扫描到 `b` 的哪里」。于是「前 $k$ 个系数已在扫描过的前缀内全部配对」的最优得分可以用**一个数**概括。
- **观察 3（阶段数是常数）**：`a` 的长度恒为 4，阶段维只有 $0 \sim 4$ 共 5 档——不需要 LCS 那样的 $O(nm)$ 二维表，一维滚动数组即可，空间 $O(1)$。

定义状态：

$$f[k] = \text{在已扫描的 } b \text{ 前缀内，把 } a[0..k-1] \text{ 全部按序配对的最大得分}$$

其中 $f[0] \equiv 0$（空配对方案永远可行、得分为 0），$f[1..4]$ 初始为 $-\infty$（「还没配满」的非法状态）。对每个新来的元素 $x = b[j]$，只有两种选择：**不配给任何人**（所有 $f$ 不变），或**配给 $a[k-1]$**（此时 $a[0..k-2]$ 必须已在 $x$ 之前配好）：

$$f[k] \leftarrow \max\bigl(f[k],\ f[k-1] + a[k-1] \cdot x\bigr)$$

### 3.3 算法流程：倒序转移

![算法流程：一遍顺扫加倒序转移](images/max_mult_score_flow.svg)

主循环只有一层：从左到右扫 `b`，每个元素 $x$ 触发一轮转移。**内层 $k$ 必须 $4 \to 1$ 倒序**，原因与 01 背包一维滚动完全同构：

- **若正序**（$k = 1, 2, 3, 4$）：更新 $f[1]$ 用的 $f[0]$……以此类推，$f[k-1]$ 可能**刚刚吃过**当前 $x$，同一个 $b[j]$ 被多个阶段重复消费，等价于允许 $i_0 = i_1$，违反下标**严格**递增。
- **倒序**：更新 $f[k]$ 时读到的 $f[k-1]$ 还是上一轮（不含 $x$）的旧值——每个 $x$ 至多喂给一个阶段。

> 💡 一维滚动数组中，**更新顺序本身就是「元素可否复用」的语义开关**：倒序 = 01 背包（每件至多一次），正序 = 完全背包（可重复选）。若本题变体改为 $i_0 \le i_1 \le i_2 \le i_3$，把倒序改成正序即可。

### 3.4 示例演算

![示例演算：f 数组逐步变化](images/max_mult_score_walkthrough.svg)

以示例 1（`a = [3,2,5,6]`，`b = [2,-6,4,-5,-3,2,-7]`）走一遍，`f` 数组随每个元素逐步演化（$-\infty$ 表示该阶段尚未配满）：

| $x = b[j]$ | $f[0]$ | $f[1]$ | $f[2]$ | $f[3]$ | $f[4]$ |
|-----------|--------|--------|--------|--------|--------|
| 初始 | 0 | $-\infty$ | $-\infty$ | $-\infty$ | $-\infty$ |
| 2 | 0 | 6 | $-\infty$ | $-\infty$ | $-\infty$ |
| −6 | 0 | 6 | −6 | $-\infty$ | $-\infty$ |
| 4 | 0 | **12** | **14** | **14** | $-\infty$ |
| −5 | 0 | 12 | 14 | 14 | −16 |
| −3 | 0 | 12 | 14 | 14 | −4 |
| 2 | 0 | **16** | **24** | **26** | **26** |
| −7 | 0 | 12 | 16 | 24 | 26 |

关键看第 7 行（$x = 2$，自右向左倒序更新，读到的都是上一行旧值）：

- $f[4] \leftarrow f[3]_{\text{旧}} + 6 \times 2 = 14 + 12 = 26$：即下标 $0,1,2,5$ 的方案 $3 \times 2 + 2 \times (-6) + 5 \times 4 + 6 \times 2$，与官方解释一致；
- $f[3] \leftarrow f[2]_{\text{旧}} + 5 \times 2 = 14 + 10 = 24$（下标 $0,2,5$，留给 $a[3]$ 继续在右侧找）；
- $f[2] \leftarrow f[1]_{\text{旧}} + 2 \times 2 = 12 + 4 = 16$（下标 $2,5$）。

最终 $f[4] = \mathbf{26}$。示例 2 同法演算：全程最优值均为负（初始时 $f[1..4] = -\infty$ 逐渐被「不得不配」的方案填满），最终 $f[4] = \mathbf{-1}$——这正是「必须配满 4 个」不能用 0 初始化的体现。

## 4. 算法细节

1. **状态设计**：取 5 个状态 $f[0..4]$，$f[0] \equiv 0$ 恒成立、**不参与更新**。另一种常见写法是 4 个状态 `dp[0..3]`、把 $\max(dp[0],\ a[0] \cdot x)$ 单独写在循环里——两者完全等价，5 状态版把「空配对」显式化为 $f[0]$，转移统一为一条公式，不易漏写。
2. **倒序更新**：内层 $k = 4, 3, 2, 1$。这是本题为数不多的「写错就 WA」的点：正序会让同一个 $b[j]$ 被多个系数复用。
3. **哨兵设计**：「未配满」用 $-\infty$ 表示。C++ 中取 `NEG = LLONG_MIN / 2` 而非 `LLONG_MIN`——后者直接参与加法是未定义行为；转移前加 `if (f[k-1] != NEG)` 守卫，保证哨兵永不进入运算。Python 用 `float("-inf")`，$-\infty +$ 有限数 $= -\infty$，非法状态自动保持，无需守卫。
4. **64 位与转换时机**：单项 $|a[k] \cdot b[j]| \le 10^{10}$，四项和上界 $4 \times 10^{10}$，超出 `int32` 约 20 倍。C++ 中必须在乘法**前**把其中一个操作数转成 `(long long)`——`int * int` 的中间结果已经溢出；函数返回类型也是 `long long`。
5. **常数优化**：内层只有 4 次转移，可手写展开成 4 行（`f4 = max(f4, f3 + a3*x)` … `f1 = max(f1, f0 + a0*x)`），省去循环开销与哨兵判断（$f[0] = 0$ 恒有效，4 行全可安全计算），$n = 10^5$ 时二者都轻松通过。

## 5. 正确性证明

记 $n = \mathrm{len}(b)$。定义 $F(j, k)$（$0 \le j \le n$，$0 \le k \le 4$）为：**仅用** $b[0..j-1]$ 内 $k$ 个严格递增下标、与 $a[0..k-1]$ 按序配对的最大得分；不可行时为 $-\infty$。

**引理 1（转移方程）**：对 $j \ge 1$、$k \ge 1$，

$$F(j,k) = \max\bigl(F(j-1,\,k),\ F(j-1,\,k-1) + a[k-1] \cdot b[j-1]\bigr)$$

且 $F(j, 0) = 0$ 对一切 $j$ 成立，$F(0, k) = -\infty$ 对 $k \ge 1$ 成立。

**证明**：$F(j,0) = 0$：空配对（什么都不选）唯一且得分 0。$F(0,k) = -\infty$：前 0 个元素配不出 $k \ge 1$ 个严格递增下标。对一般情形，按「是否使用 $b[j-1]$」对可行方案分类：

- **不用 $b[j-1]$**：方案完全落在前 $j-1$ 个元素内，其得分的最大值恰为 $F(j-1, k)$（前缀扩大不产生新约束，$F(j-1,k)$ 的最优方案也是 $(j,k)$ 的可行方案，反之亦然）。
- **用 $b[j-1]$**：所选 $k$ 个下标严格递增、均 $< j$，故 $b[j-1]$ 是最大下标，而按序配对下最大下标必然配给**最后一个**系数 $a[k-1]$；其余 $k-1$ 个下标落在前 $j-1$ 个元素内、与 $a[0..k-2]$ 按序配对，构成 $(j-1, k-1)$ 的可行方案。故此类最大值 $= F(j-1, k-1) + a[k-1] \cdot b[j-1]$。

两类取最大即得。∎

**引理 2（倒序滚动的正确性）**：设数组 $f[0..4]$ 初始为 $f[k] = F(0, k)$。对 $j = 1, \dots, n$ 依次执行第 $j$ 轮：按 $k = 4, 3, 2, 1$ 的顺序就地更新 $f[k] \leftarrow \max\bigl(f[k],\ f[k-1] + a[k-1] \cdot b[j-1]\bigr)$（$f[k-1]$ 为 $-\infty$ 时跳过）。则每轮结束后 $f[k] = F(j, k)$ 对所有 $k$ 成立。

**证明**：对 $j$ 归纳。$j = 0$ 时由初始化成立。设第 $j-1$ 轮末 $f[k] = F(j-1, k)$。第 $j$ 轮中，由于按 $k$ **从大到小**更新，处理 $f[k]$ 时本轮已写过的下标仅为 $4, \dots, k+1$，均大于 $k$，故读到的 $f[k]$ 与 $f[k-1]$ 都还是上一轮末的值 $F(j-1, k)$ 与 $F(j-1, k-1)$；而 $-\infty$ 哨兵被守卫跳过（等价于 $\max$ 中 $-\infty$ 永不获胜）。于是本轮结束后

$$f[k] = \max\bigl(F(j-1,k),\ F(j-1,k-1) + a[k-1]\cdot b[j-1]\bigr) = F(j,k)$$

（最后一步用引理 1），$f[0] = 0 = F(j, 0)$ 未被触碰。∎

> ⚠️ 若改为正序更新，处理 $f[k]$ 时 $f[k-1]$ 已含本轮的 $b[j-1]$，归纳论证失效——同一元素可被多个系数消费，得到的不再是 $F$ 而是「允许下标相等」变体的最优值。

**定理**：算法返回值等于题目所求的最大得分。

**证明**：题目的可行方案集与 $F(n, 4)$ 的定义域完全一致（在 $b[0..n-1]$ 内选 4 个严格递增下标、与 $a[0..3]$ 按序配对）。由 $n \ge 4$，下标 $0, 1, 2, 3$ 总是可行方案，故 $F(n,4)$ 为有限值；由引理 2，$n$ 轮后 $f[4] = F(n,4)$，算法返回它。∎

## 6. 复杂度分析

- **时间复杂度**：$O(4n) = O(n)$。外层顺扫 `b` 一遍，每个元素触发常数 4 次转移（比较 + 乘加）；$n = 10^5$ 时约 $4 \times 10^5$ 次基本运算，远低于时限。读入本身 $\Omega(n)$，已是最优阶。
- **空间复杂度**：$O(1)$。仅 5 个滚动变量（及哨兵常数），不随 $n$ 增长；对比朴素二维表 $F[j][k]$ 的 $O(n)$ 空间，靠「$j$ 维顺扫可滚动 + $k$ 维是常数」压掉。
- **对比暴力**：$O\bigl(\binom{n}{4}\bigr) \approx 4 \times 10^{18}$；即使两层后缀最值优化也只到 $O(n^2) \approx 10^{10}$，均不可行。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    long long maxScore(vector<int>& a, vector<int>& b) {
        const long long NEG = LLONG_MIN / 2;
        long long f[5] = {0, NEG, NEG, NEG, NEG};
        for (int x : b) {
            for (int k = 4; k >= 1; k--) {
                if (f[k - 1] != NEG) {
                    f[k] = max(f[k], f[k - 1] + (long long)a[k - 1] * x);
                }
            }
        }
        return f[4];
    }
};
```

### Python

```python
class Solution:
    def maxScore(self, a: List[int], b: List[int]) -> int:
        f = [0] + [float("-inf")] * 4
        for x in b:
            for k in range(4, 0, -1):
                f[k] = max(f[k], f[k - 1] + a[k - 1] * x)
        return f[4]
```

Python 版无需哨兵守卫：$-\infty$ 参与加法仍是 $-\infty$，`max` 中永不胜出，非法状态自动保持。

## 8. 边界情况与易错点

1. **`f[1..4]` 初始化必须是 $-\infty$ 而非 0**：4 个系数必须配满，0 会引入「配不满也算合法」的假方案。示例 2 答案是 $-1 < 0$，初始化成 0 会直接输出错误的 0。反之 **`f[0]` 必须是 0** 而非 $-\infty$——空配对永远合法。
2. **64 位溢出**：单项 $|a[k] \cdot b[j]| \le 10^{10}$、总和上界 $4 \times 10^{10}$，`int` 必爆；C++ 乘法两个 `int` 操作数要先 `(long long)` 转换，且返回类型为 `long long`。
3. **哨兵参与加法是 UB**：`LLONG_MIN + 任意数` 在 C++ 中未定义行为，哨兵取 `LLONG_MIN / 2` 留余量、或加守卫跳过转移，二选一（不可都省）。
4. **内层倒序别写成正序**：正序等价于允许 $i_0 = i_1 = i_2 = i_3$（同一元素复用），在 `b` 元素全同或 `a` 全正时会得到偏大的错误答案。
5. **$n = 4$ 最小规模**：只有唯一方案（全部选上），答案恒为 $\sum a[k] \cdot b[k]$，算法自然覆盖，无需特判。
6. **不要排序 `b`**：排序破坏「下标严格递增」约束；也不要按「绝对值大配大」贪心——负系数想配更小的值（示例 3）。
7. **答案可为负**：全程可能没有任何正贡献组合（示例 2），不要对最终结果与 0 取 `max`。
