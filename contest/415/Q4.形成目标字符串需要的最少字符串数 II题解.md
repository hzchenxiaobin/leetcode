# LeetCode 形成目标字符串需要的最少字符串数 II 题解

## 1. 题目概述

- **标题 / 题号**：形成目标字符串需要的最少字符串数 II（#3292，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-valid-strings-to-form-target-ii/
- **来源**：LeetCode 第 415 场周赛 Q4
- **难度**：困难
- **标签**：贪心、Z 函数、字符串哈希、二分查找、动态规划

**题意**：给定字符串数组 `words` 与字符串 `target`。若 $x$ 是 `words` 中**任意**一个字符串的**前缀**（长度 $\ge 1$），则 $x$ 是「有效字符串」。有效字符串可**重复取用**，要求用尽可能少的有效字符串首尾相接拼成 `target`，返回最少段数；拼不出返回 $-1$。

**约束**：

- $1 \le \text{words.length} \le 100$，$1 \le \text{words[i].length} \le 5 \times 10^4$，$\sum \text{words[i].length} \le 10^5$
- $1 \le \text{target.length} \le 5 \times 10^4$，均只含小写英文字母

> 💡 **读题信号**：与[本场 Q3（3291）](Q3.形成目标字符串需要的最少字符串数%20I题解.md)题意一字不差，变的只有数据范围——`target` 长度与单个 `word` 长度上限各 ×10（$5\times10^3 \to 5\times10^4$），而 $W \le 100$、$\sum|w| \le 10^5$ 纹丝不动。这是 I/II 成对题的标准打开方式：**框架照抄，引擎换代**——Q3 的「$\mathrm{mn}[]$ + 区间转移」框架原样成立，报废的是求 $\mathrm{mn}$ 的 Trie 引擎与 $O(n^2)$ DP，前者换成 Z 函数 / 前缀哈希 + 二分，后者换成 $O(n)$ 分层贪心。

输出：3
解释："aa"（aaaaa 的前缀）+ "bcd"（bcdef 的前缀）+ "abc"（abc 的前缀）。
```

**示例 2**

```

**示例 3**

```text
输入：words = ["abcdef"], target = "xyz"
输出：-1
解释：'x' 不是任何 word 前缀的开头，第一个字符就无从下手。
```

## 3. 解题思路

沿用 Q3 的记号 $\mathrm{mn}[i] = \max_{w}\ \mathrm{LCP}\big(w,\ \text{target}[i:]\big)$（从 $i$ 出发的最长匹配长度），整个解法 = **求 $\mathrm{mn}$** + **由 $\mathrm{mn}$ 求最少段数**两步。

### 3.1 暴力思路：Q3 的两步走，II 下步步超时

Q3（3291）的完整解法分两步：① 所有 word 建一棵 Trie，从每个起点 $i$ 沿 `target[i..]` 行走到失配，代价 $O(n \cdot L_{\max})$；② 区间转移 DP $dp[j] \leftarrow \min(dp[j],\ dp[i]+1),\ j \in (i,\ i+\mathrm{mn}[i]]$，朴素实现 $O(n^2)$。

II 把前者的两个因子同时 ×10：$n \cdot L_{\max} = 5\times10^4 \times 5\times10^4 = 2.5\times10^9$；DP 同为 $2.5\times10^9$——双双超时，C++ 也救不回来。死因都是**结构性**的：Trie 行走对每个起点「从根重走一遍」，同一条前缀路径被反复验证（**重复劳动**）；DP 逐个敲定 $dp[j]$，无视了「同一层可以一起结算」的结构。于是两处都要换引擎：

| 部件 | Q3（3291） | Q4（3292） | 复杂度变化 |
|------|-----------|-----------|-----------|
| 求 $\mathrm{mn}$ | Trie 逐起点行走 | **Z 函数 / 前缀哈希 + 二分** | $O(n L_{\max}) \approx 2.5\times10^9 \;\to\; O(\sum\lvert w\rvert + Wn) \approx 5\times10^6$ |
| 求最少段数 | 区间 DP | **分层贪心（跳跃游戏 II）** | $O(n^2) \to O(n)$ |

### 3.2 核心观察一：换匹配引擎——一遍线性扫描，LCP 批量出厂

![Z 函数拼接：target 段的 z 值就是 LCP](images/min_valid_strings_ii_zfunction.svg)

对每个 word $w$ 拼接 $s = w + \# + \text{target}$（`'#'` 不在小写字母表，作**哨兵**），求 Z 数组：$z[i] = \mathrm{LCP}(s,\ s[i:])$。当 $i$ 落在 target 段（$i \ge |w|+1$）时，$s[i:]$ 恰是 $\text{target}[j:]$（$j = i - |w| - 1$），于是

$$z[i] = \mathrm{LCP}\big(w,\ \text{target}[j:]\big)$$

且 $z[i]$ **天然 $\le |w|$**——匹配想越过 $w$ 的边界，就要拿 $s[|w|]$ 上的 `'#'` 与 target 段的小写字母硬碰，必然失配。对全部 word 逐位取 max 即得 $\mathrm{mn}$。

**Z 为什么是线性的**：算法维护最右 Z-box $[l, r)$（满足 $s[l..r) = s[0..r-l)$）；新位置 $i$ 落在框内时，$z[i]$ 的初值直接复用 $z[i-l]$（框内的对应关系早已验证过），只有试探冲出 $r$ 才需要逐字符比较，而每次成功比较都把 $r$ 右推、$r$ 全程只右移 $|s|$ 次——总比较次数 $O(|s|)$。**信息复用**战胜了 Trie 的**重复劳动**。

**复杂度账单**：每个 word 一遍 $O(|w| + n)$，总计 $O\big(\sum|w| + W \cdot n\big) \approx 10^5 + 5\times10^6$。注意账单里乘的是 $W \le 100$——它没被数据加强放大，被 ×10 的 $L_{\max}$ 只出现在加法项里。

> 💡 **同级别的另一台引擎：前缀哈希 + 二分**（本题标签 Binary Search / Rolling Hash、官方 hints 的路线）。把每个 word 的**每个前缀**的哈希按长度分桶存入集合 $S[l]$（长度相同的 word 前缀至多 $W$ 条，共 $\sum|w| \le 10^5$ 条），再对 `target` 预处理前缀哈希；对每个起点 $i$，由**前缀封闭性**（长度 $\ell$ 可行 $\Rightarrow$ $1 \sim \ell-1$ 全可行，见引理 1）可**二分**最大 $\ell$ 使 $\text{target}[i..i+\ell)$ 的哈希 $\in S[\ell]$，单起点 $O(\log L_{\max})$。本文 C++ 用 Z 函数（免哈希碰撞、确定性），Python 用哈希二分（约 $10^6$ 次运算，常数更小；Z 版 Python 实现见[每日题解](../../solution/3201-3300/3292_形成目标字符串需要的最少字符串数II.md)）。

![前缀哈希按长度分桶 + 二分最大可行长度](images/min_valid_strings_ii_hash_bsearch.svg)

### 3.3 核心观察二：换收尾引擎——分层贪心取代区间 DP

![分层贪心：R 的逐层扩张](images/min_valid_strings_ii_greedy_levels.svg)

由前缀封闭性，从 $i$ 出发的一段可以把**下一段起点**推到 $[i+1,\ i+\mathrm{mn}[i]]$ 中任意位置——[45. 跳跃游戏 II](https://leetcode.cn/problems/jump-game-ii/) 的模型。定义「$\le k$ 段能到达的最远边界」

$$R_0 = 0, \qquad R_{k+1} = \max_{0 \le i \le R_k}\big(i + \mathrm{mn}[i]\big)$$

**首个 $R_k \ge n$ 的 $k$ 就是答案**；某轮 $R_{k+1} = R_k < n$ 即卡死，返回 $-1$（正确性见 §5 引理 2、定理 1——关键是「可达边界没有洞」，一层一个标量就够了）。

> ⚠️ **「每步跳到 $i + \mathrm{mn}[i]$」的朴素贪心必错**。反例：`words = ["abc","bcdefa"]`, `target = "abcdef"`（$\mathrm{mn} = [3,5,0,0,0,0]$）：朴素贪心第 0 段取最长 "abc" 落在位置 3，而位置 3 是死点，得 $-1$；正确解是 "a" + "bcdef" 共 **2** 段（$0 \to 1 \to 6$）。分层贪心看的是**整窗最大**：$R_1 = 3$ 后，窗口 $[0, 3]$ 内 $\max(i + \mathrm{mn}[i]) = 1 + 5 = 6 = n$。与 Q3 §3.3 的反例同款教训：**贪心的对象是层，不是步**。

实现是 $O(n)$ 单趟扫描：`end` 维护当前层右端 $R_k$，`farthest` 维护扫描过程中的 $\max(i + \mathrm{mn}[i])$；当 $i$ 扫到 `end` 时结算一层。

### 3.4 示例演算

![示例 1 演算：z 贡献 → mn → 分层扩张](images/min_valid_strings_ii_walkthrough.svg)

以示例 1（`words = ["abc","aaaaa","bcdef"]`, `target = "aabcdabc"`）走查——三个 word 各自的 Z 贡献（target 段）：

| word | 拼接串 | 各起点贡献 |
|------|--------|-----------|
| `"aaaaa"` | `aaaaa#aabcdabc` | $[2,1,0,0,0,1,0,0]$ |
| `"abc"` | `abc#aabcdabc` | $[1,3,0,0,0,3,0,0]$ |
| `"bcdef"` | `bcdef#aabcdabc` | $[0,0,3,0,0,0,2,0]$ |

逐位取 max 得 $\mathrm{mn} = [2,3,3,0,0,3,2,0]$（位置 3、4、7 是死点）。分层扩张：

$$R_0 = 0 \;\xrightarrow{\;0+2\;}\; R_1 = 2 \;\xrightarrow{\;2+3\;}\; R_2 = 5 \;\xrightarrow{\;5+3\;}\; R_3 = 8 \ge n$$

答案 $\mathbf{3}$，切分 `aa | bcd | abc`——死点 3、4、7 全被绕开。

示例 2：$\mathrm{mn} = [5,4,3,2,1,5,4,3,2,1]$，$R:\ 0 \to 5 \to 10$，答案 $\mathbf{2}$。示例 3：$\mathrm{mn} = [0,0,0]$，结算首层即 $R_1 = R_0 = 0$ 卡死，返回 $\mathbf{-1}$。

## 4. 算法细节

1. **Z 函数模板**：维护最右 Z-box $[l, r)$。`if (i < r) z[i] = min(r - i, z[i - l])` 复用框内信息；`while (i + z[i] < m && s[z[i]] == s[i + z[i]]) z[i]++` 向外试探；成功则右推 `l = i, r = i + z[i]`。$z[0]$ 不使用（只读 target 段，下标 $\ge |w|+1 \ge 2$）。
2. **哨兵 `'#'`**：必须不在小写字母表内（`'0'`、`'.'` 均可）。它同时保证两件事：z 值 $\le |w|$（无需再取 `min`）、$w$ 不会把 target 段的字符「借」过来虚报 LCP。
3. **峰值空间**：Z 数组逐 word 重建，大小 $\le L_{\max} + n + 1$；全局只需保留 $\mathrm{mn}$（$O(n)$）。
4. **哈希二分细节**：基底用 `random` 随机选取、模梅森素数 $2^{61} - 1$，防碰撞也防构造数据卡固定基底；二分上界取 $\min(n - i,\ L_{\max})$——漏夹 $n-i$ 会越界取子串，漏夹 $L_{\max}$ 会访问不存在的桶 `S[mid]`。
5. **分层贪心实现**：`i == end` 时先判 `farthest == end`（原地踏步 ⟹ $R$ 永久停滞，返回 $-1$），否则 `end = farthest, ans++`；`end >= n` 立即返回 `ans`。循环后的 `return -1` 是防御性兜底（定理 1 的论证表明实际到不了）。
6. **可选常数优化**：互为前缀的 words 只保留最长者（短者的贡献被长者的前缀覆盖）；哈希版可只插入长度 $\le n$ 的前缀。均不影响正确性。

## 5. 正确性证明

**引理 1（转移区间）**：对任意 $0 \le i < n$：(a) $\text{target}[i..i+\ell)$ 是有效字符串 $\iff 1 \le \ell \le \mathrm{mn}[i]$；(b) $\mathrm{mn}[i] \le n - i$。

**证明**：(a)「$\Leftarrow$」设 $\mathrm{mn}[i] = \mathrm{LCP}(w, \text{target}[i:]) \ge \ell$，则 $\text{target}[i..i+\ell) = w[0..\ell)$ 是 $w$ 的前缀。「$\Rightarrow$」若 $\text{target}[i..i+\ell)$ 等于某 $w$ 的前 $\ell$ 个字符，则 $\mathrm{LCP}(w, \text{target}[i:]) \ge \ell$，故 $\mathrm{mn}[i] \ge \ell$。(b) LCP 不超过参与比较的较短一方，而 $\text{target}[i:]$ 长 $n - i$。∎

**引理 2（可达集是前缀区间）**：设 $S_k$ 为用 $\le k$ 段能拼出的**划分边界**位置之集合，$R_k = \max S_k$（规定 $S_0 = \{0\}$，$R_0 = 0$）。则 $S_k = \{0, 1, \dots, R_k\}$，且 $R_{k+1} = \max_{0 \le i \le R_k}\big(i + \mathrm{mn}[i]\big)$。

**证明**：对 $k$ 归纳。$k = 0$ 时 $S_0 = \{0\}$ 成立。设 $S_k = [0, R]$。最优解中的每段非空（空段只会徒增段数，最优解中必不出现），故边界严格递增；新边界只能从旧边界 $i \in [0, R]$ 出发、由引理 1(a) 落在 $[i+1,\ i+\mathrm{mn}[i]]$ 中，即

$$S_{k+1} = [0, R] \;\cup\; \bigcup_{i=0}^{R} [i+1,\ i+\mathrm{mn}[i]]$$

记 $M = \max_{0 \le i \le R}(i + \mathrm{mn}[i])$（由引理 1(b)，$M \le n$；又 $M \ge R + \mathrm{mn}[R] \ge R$）。对任意 $q \in (R, M]$：取达到 $M$ 的 $i^*$，则 $i^* \le R < q \le i^* + \mathrm{mn}[i^*]$，故 $q \in [i^*+1,\ i^*+\mathrm{mn}[i^*]]$；而 $(M, n]$ 中的位置不在任何 $[i+1,\ i+\mathrm{mn}[i]]$（$i \le R$）内。故 $S_{k+1} = [0, M]$。∎

> 💡 引理 2 是整个贪心的心脏：**可达边界没有洞**——$(R_k, R_{k+1}]$ 中每个位置都可达，所以一「层」可以用一个标量 $R_k$ 代表，逐层扩张只需看窗口内的最大 $i + \mathrm{mn}[i]$。这也是朴素 DP（逐位置敲定 $dp[j]$）可以坍缩成单趟扫描的原因。

**定理 1（分层贪心的正确性）**：贪心返回 $\min\{k : R_k \ge n\}$；当且仅当 $n$ 不可达时返回 $-1$。

**证明**：扫描中 `farthest` 是已扫位置 $i' \le i$ 的 $\max(i' + \mathrm{mn}[i'])$ 的运行最大值。归纳证明：每次结算（$i =$ `end`）时 `farthest` $= R_{k+1}$、结算后 `end` $= R_{k+1}$、`ans` $= k+1$。初始 `end` $= R_0 = 0$；归纳步骤中，当 $i$ 扫到 `end` $= R_k$ 时（`farthest` 已吸收 $i' \le R_k$ 的全部位置），`farthest` $= \max_{i' \le R_k}(i' + \mathrm{mn}[i']) = R_{k+1}$，与引理 2 的递推一致。于是：

- 结算时若 `farthest` $\ge n$：由引理 1(b)，$R_{k+1} \le n$，故 $R_{k+1} = n$；此时 `ans` $= k+1$ 且上一轮未触发返回（$R_k < n$），即 $\min\{k : R_k \ge n\} = k+1$，返回值正确。
- 结算时若 `farthest` $=$ `end` $< n$：即 $R_{k+1} = R_k$，则 $R_{k+2} = \max_{i' \le R_{k+1}}(i' + \mathrm{mn}[i'])$ 与 $R_{k+1}$ 在同一区间上取最大，相等——$R$ 永久停滞在 $< n$ 处，$n$ 不可达，返回 $-1$ 正确。
- 结算后 `end` $=$ `farthest` $> i$ 且 $\le n$：若 $= n$ 已返回，否则 $i$ 每轮 $+1$，必再次追上 `end` 触发结算。故算法必在循环内返回，尾部 `return -1` 仅为防御，不影响正确性。∎

**引理 3（Z 值即 LCP）**：设 $s = w + \# + \text{target}$，`'#'` 不在小写字母表内。对 target 段位置 $i = |w| + 1 + j$（$0 \le j < n$），有 $z[i] = \mathrm{LCP}(w,\ \text{target}[j:]) \le |w|$。

**证明**：$s[i:]$ 恰为 $\text{target}[j:]$（$i$ 之后到串尾全是 target 段）。逐字符比较 $s[0..]$ 与 $\text{target}[j..]$：前 $|w|$ 个位置比较的是 $w$ 与 $\text{target}[j..j+|w|)$。若在 $|w|$ 之前失配，$z[i]$ 即 $\mathrm{LCP}(w, \text{target}[j:])$；若前 $|w|$ 个全匹配（此时 $j + |w| \le n$），下一步比较 $s[|w|] = \# $ 与 $\text{target}[j + |w|]$（存在且为小写字母），失配，$z[i] = |w|$。两种情况均得 $z[i] = \mathrm{LCP} \le |w|$。∎

**定理 2（整体正确性）**：Z 引擎由引理 3 逐位算出正确的 $\mathrm{mn}$；哈希引擎由引理 1(a) 的单调性保证二分收敛到最大可行长度（随机基底下，一对长度 $\le L_{\max}$ 的不同串哈希相等的概率 $\le L_{\max} / 2^{61}$，对全部 $O(n \log L_{\max})$ 次查询、每次至多 $W$ 条桶内哈希做并集界，失败概率约 $10^{-6}$，可忽略）。再由引理 1、2 与定理 1，算法返回最少段数或正确的 $-1$。∎

## 6. 复杂度分析

- **时间复杂度**：
  - C++（Z 引擎）：$O\big(\sum|w| + W \cdot n\big) \approx 10^5 + 100 \times 5\times10^4 = 5.1\times10^6$——每个 word 一遍 $O(|w| + n)$；分层贪心 $O(n)$。
  - Python（哈希引擎）：$O\big(\sum|w| + n \log L_{\max}\big) \approx 10^5 + 8\times10^5$——建桶 $\sum|w|$ 条哈希、每个起点 $\le \lceil\log_2 5\times10^4\rceil = 16$ 次查询；分层贪心 $O(n)$。
- **空间复杂度**：Z 版 $O(L_{\max} + n)$（Z 数组逐 word 重建）+ $\mathrm{mn}$ 数组 $O(n)$；哈希版 $O\big(\sum|w|\big)$ 的分桶集合 + $O(n)$ 前缀哈希与幂表。

## 7. 参考代码

### C++（Z 函数 + 分层贪心）

```cpp
class Solution {
  public:
    int minValidStrings(vector<string>& words, string target) {
        int n = target.size();
        vector<int> mn(n, 0);

        // ①② 换匹配引擎：逐 word 求 s = w + '#' + target 的 Z 数组，
        //     target 段的 z 值 = LCP(w, target[j:])，哨兵保证 z <= |w|
        for (string& w : words) {
            string s = w + '#' + target;
            int m = s.size();
            vector<int> z(m, 0);
            for (int i = 1, l = 0, r = 0; i < m; i++) {
                if (i < r) z[i] = min(r - i, z[i - l]); // 落在 Z-box 内：复用
                while (i + z[i] < m && s[z[i]] == s[i + z[i]]) z[i]++;
                if (i + z[i] > r) l = i, r = i + z[i];  // 右推最右 Z-box
            }
            int base = w.size() + 1;                    // target 段起点
            for (int j = 0; j < n; j++)
                mn[j] = max(mn[j], z[base + j]);
        }

        // ③ 换收尾引擎：分层贪心（跳跃游戏 II），O(n)
        int end = 0, farthest = 0, ans = 0;
        for (int i = 0; i < n; i++) {
            farthest = max(farthest, i + mn[i]);
            if (i == end) {                      // 当前层扫完，结算 R_{k+1}
                if (farthest == end) return -1;  // 原地踏步：R 永久停滞
                end = farthest;
                ans++;
                if (end >= n) return ans;        // 抵达位置 n
            }
        }
        return -1;                               // 防御性兜底（到不了这里）
    }
};
```

### Python（前缀哈希 + 二分 + 分层贪心）

```python
import random

class Solution:
    def minValidStrings(self, words: List[str], target: str) -> int:
        MOD = (1 << 61) - 1                     # 梅森素数：防碰撞、防卡
        BASE = random.randrange(256, MOD - 1)   # 随机基底

        n = len(target)
        pw = [1] * (n + 1)                      # 幂表
        th = [0] * (n + 1)                      # target 前缀哈希
        for i, c in enumerate(target):
            pw[i + 1] = pw[i] * BASE % MOD
            th[i + 1] = (th[i] * BASE + ord(c)) % MOD

        def sub_hash(l, r):                     # target[l:r] 的哈希，O(1)
            return (th[r] - th[l] * pw[r - l]) % MOD

        # S[l]：长度恰为 l 的 word 前缀哈希集合（每 word 贡献一条）
        max_len = max(len(w) for w in words)
        S = [set() for _ in range(max_len + 1)]
        for w in words:
            h = 0
            for i, c in enumerate(w):
                h = (h * BASE + ord(c)) % MOD
                S[i + 1].add(h)

        # 二分求 mn[i]：长度 l 可行 ⟺ target[i:i+l] 的哈希 ∈ S[l]
        mn = [0] * n
        for i in range(n):
            lo, hi = 1, min(n - i, max_len)     # 两个上界都别漏
            while lo <= hi:
                mid = (lo + hi) // 2
                if sub_hash(i, i + mid) in S[mid]:
                    mn[i] = mid
                    lo = mid + 1
                else:
                    hi = mid - 1

        # 分层贪心（跳跃游戏 II），O(n)
        end = farthest = ans = 0
        for i in range(n):
            farthest = max(farthest, i + mn[i])
            if i == end:                        # 当前层扫完，结算 R_{k+1}
                if farthest == end:
                    return -1                   # 原地踏步：R 永久停滞
                end = farthest
                ans += 1
                if end >= n:
                    return ans                  # 抵达位置 n
        return -1                               # 防御性兜底（到不了这里）
```

## 8. 边界情况与易错点

1. **朴素贪心必错**：每步跳到 $i + \mathrm{mn}[i]$ 会掉进死点（§3.3 反例：`["abc","bcdefa"]` / `"abcdef"`，朴素得 $-1$，正确为 2；Q3 §3.3 的 `["abc","cdef"]` 同款）。必须按「层」贪心：结算窗口 $[0, R_k]$ 内的 $\max(i + \mathrm{mn}[i])$。
2. **$\mathrm{mn}[i] = 0$ 不等于无解**：死点可以被绕过——示例 1 有 3 个死点（位置 3、4、7）照样答案 3；但 $\mathrm{mn}[0] = 0$ 必然 $-1$（首层即停滞）。$-1$ 的判据是「分层停滞 $R_{k+1} = R_k < n$」，不是「存在死点」。
3. **哨兵别忘拼、别用字母表内字符**：不拼 `'#'`，z 会把 target 段的字符「借」给 $w$ 用，虚报超过 $|w|$ 的 LCP；用小写字母当哨兵同理穿帮。
4. **z 值无需 `min(|w|, ·)`**：哨兵已保证 $z \le |w|$，再取 `min` 只是冗余防御（取了也不错）。
5. **哈希二分的两个上界**：`hi = min(n - i, max_len)`。漏 $n - i$ → 子串哈希越界；漏 `max_len` → `S[mid]` 索引越界（桶数组只开到 $L_{\max}+1$）。
6. **哈希安全**：固定基底 + 小模数会被构造数据卡；随机基底 + $2^{61}-1$ 是底线。C++ 若走哈希路线，乘法需 `__int128`（或转 `unsigned long long` 溢出式双哈希）。
7. **溢出**：Z 版全程下标与 $i + \mathrm{mn}[i] \le n \le 5\times10^4$，`int` 足够；这也是引理 1(b) 的直接推论——边界永远「恰好落在 $n$」而不会跳过。
8. **重复 / 互为前缀的 words**：Z 逐 word 幂等，无害；想省常数可去重并只留最长者。
9. **别把所有 word 拼成一整条再求一次 Z**：哨兵只挡得住单个 word 的边界，整条拼接算出的是「与拼接串的 LCP」，语义完全不同——必须逐 word 独立。
