# LeetCode 交替组 III 题解

## 1. 题目概述

- **标题 / 题号**：交替组 III（#3245，hard）
- **链接**：https://leetcode.cn/problems/alternating-groups-iii/
- **来源**：LeetCode 第 409 场周赛 Q4
- **难度**：困难
- **标签**：树状数组、有序集合、数据结构、环

**题意**：`colors` 是一个由红（$0$）蓝（$1$）瓷砖组成的**环**。环上一段连续瓷砖若**相邻两两异色**，称为一个**交替组**。需在线处理两类查询：

- `[1, size]`：统计大小**恰好为** `size` 的交替组数量（环上所有起点各算一个）；
- `[2, index, color]`：单点改色 `colors[index] = color`（可能与原色相同）。

按顺序返回所有类型 1 查询的答案。

**约束**：

- $4 \le n \le 5 \times 10^4$，$1 \le \mathrm{queries.length} \le 5 \times 10^4$
- 类型 1 查询：$3 \le \mathrm{size} \le n - 1$
- 类型 2 查询：$0 \le \mathrm{index} < n$，$0 \le \mathrm{color} \le 1$（**允许改成原色**）

> 💡 **读题关键**：$n, q$ 同为 $5 \times 10^4$，宣告「每次统计都从头扫描」不可行；而「环」+「在线改色」的组合，逼我们把**统计**也做成增量维护——这是本题全部难度的来源，也是「树状数组 + 有序集合」标签的出处。

## 2. 示例

**示例 1**

```text
输入：colors = [0,1,1,0,1], queries = [[2,1,0],[1,4]]
输出：[2]

解释：
查询 [2,1,0]：colors[1] 由 1 改为 0，colors 变为 [0,0,1,0,1]；
查询 [1,4]：大小为 4 的交替组有 [1,2,3,4]（颜色 0,1,0,1）与
           [2,3,4,0]（颜色 1,0,1,0），共 2 个。
```

**示例 2**

```text
输入：colors = [0,0,1,0,1,1], queries = [[1,3],[2,3,0],[1,5]]
输出：[2,0]

解释：
查询 [1,3]：交替组 [0,1,2] 与 [3,4,5]，共 2 个；
查询 [2,3,0]：colors[3] 已是 0，无变化；
查询 [1,5]：不存在大小为 5 的交替组，答案 0。
```

> ⚠️ 示例 2 的第二条查询是命题人埋的提示：**改色可能不改变任何东西**。实现时若不做「同色跳过」或在边状态未翻转时照常增删数据结构，就会当场翻车。

## 3. 解题思路

### 3.1 暴力思路：每次统计全量扫描

最朴素的实现：类型 2 查询 $O(1)$ 改色；类型 1 查询枚举全部 $n$ 个起点，逐一检查长度 $L$ 窗口内的 $L-1$ 个相邻对是否异色：

| 方案 | 单次统计代价 | 总代价（$n, q \le 5\times10^4$） | 判断 |
|------|--------------|----------------------------------|------|
| 逐起点逐对检查 | $O(nL)$ | $O(qnL) \approx 10^{14}$ | 超时 |
| 递推相邻对再前缀和 | $O(n)$ | $O(qn) \approx 2.5\times10^9$ | 仍超时 |
| **段计数 + 增量维护（本文）** | $O(\log n)$ | $O((n+q)\log n) \approx 3\times10^6$ | ✓ |

瓶颈不在检查方式，而在「**每次统计都重扫全环**」。突破口是把「大小恰为 $L$ 的交替组数量」改写成**只依赖段长分布的公式**，再用数据结构在线维护段长分布。

### 3.2 核心观察：坏边切环，计数坍缩成段长统计

![坏边切环成交替段](images/alt_groups_iii_segments.svg)

给「边」编号：边 $e_i$ 连接瓷砖 $i$ 与瓷砖 $(i+1) \bmod n$。称 $e_i$ 为**坏边**当且仅当 $colors[i] = colors[(i+1) \bmod n]$（相邻同色），否则为**好边**。四个层层递进的观察：

- **观察 1（窗口判定）**：一个长度 $L$ 的窗口是交替组，当且仅当它内部的 $L-1$ 条边**全是好边**——交替组的判定与瓷砖颜色本身无关，只与边的「好坏」有关。
- **观察 2（极长交替段）**：把环沿所有坏边剪开，得到若干条**链**，每条链内部相邻两两异色，称为**极长交替段**（下文简称**段**）。段由坏边集合唯一决定。
- **观察 3（段贡献公式）**：长为 $\mathrm{len}$ 的段内部，长度恰为 $L$ 的交替组恰有 $\max(0, \mathrm{len} - L + 1)$ 个（链上滑动窗口）；又因为任何交替组必然完整落在某个段内（它内部没有坏边），**不同段的贡献互不重叠、恰好覆盖全部交替组**。于是

$$\mathrm{answer}(L) \;=\; \sum_{\mathrm{len} \,\ge\, L} \mathrm{cnt}[\mathrm{len}] \cdot (\mathrm{len} - L + 1),$$

  其中 $\mathrm{cnt}[\mathrm{len}]$ 是长度为 $\mathrm{len}$ 的段的个数。**统计从此不再触碰环，只问段长分布。**

- **观察 4（环的特例）**：若环上**没有坏边**（整环交替），则 $n$ 个起点全部合法，$\mathrm{answer}(L) = n$——**不是**「一个长 $n$ 的段」贡献的 $n - L + 1$。链上的窗口不跨越自身，环却可以让首尾相接，这正是环与链的分野。另外，恰有 **1 条坏边**时公式无需特判：唯一段的长度是 $n$（从坏边一侧绕整圈回到另一侧），贡献 $n - L + 1$ 恰好正确。

> 💡 一句话直觉：**交替组 = 好边的连续 run**。把「数窗口」翻译成「数段长」，统计对象从 $O(n)$ 个窗口坍缩成 $O(\text{坏边数})$ 个段——剩下的全部问题，只是如何在线维护 $\mathrm{cnt}[\cdot]$。

### 3.3 算法流程：单点改色 → 两条边翻转 → 分裂 / 合并

![分裂与合并流程](images/alt_groups_iii_split_merge.svg)

改色 `colors[index] = color` 只影响**两条边**：$e_L = (\mathrm{index}-1+n) \bmod n$ 与 $e_R = \mathrm{index}$。每条边的好坏可能翻转，对应段集合的两种局部手术：

- **好变坏（分裂）**：向有序集合 $S$（坏边集）插入 $e$。设插入后 $e$ 在环上的前驱、后继坏边为 $\mathrm{prv}, \mathrm{nxt}$，则 $e$ 原来所在的段 $[\mathrm{prv}+1 \dots \mathrm{nxt}]$ 断成两段，长度分别为 $l_1 = (e - \mathrm{prv}) \bmod n$ 与 $l_2 = (\mathrm{nxt} - e) \bmod n$。**旧段长恰为 $l_1 + l_2$**——这个加法公式对「$S$ 原本只有 1 条坏边」的整环段同样成立，绕开了环绕取模的坑。
- **坏变好（合并）**：从 $S$ 删除 $e$，被 $e$ 隔开的两段 $[\mathrm{prv}+1 \dots e]$（长 $l_1$）与 $[e+1 \dots \mathrm{nxt}]$（长 $l_2$）拼接成长 $l_1 + l_2$ 的一段。

每次手术更新 $\mathrm{cnt}[\cdot]$ 三个值。查询侧，把观察 3 的公式展开：

$$\mathrm{answer}(L) = \underbrace{\sum_{\mathrm{len} \ge L} \mathrm{cnt}[\mathrm{len}]\,(\mathrm{len}+1)}_{\mathrm{BIT}_2\ \text{后缀和}} \;-\; L \cdot \underbrace{\sum_{\mathrm{len} \ge L} \mathrm{cnt}[\mathrm{len}]}_{\mathrm{BIT}_1\ \text{后缀和}}$$

用**两棵树状数组**分别维护 $\mathrm{cnt}[\mathrm{len}]$ 与 $\mathrm{cnt}[\mathrm{len}] \cdot (\mathrm{len}+1)$ 的前缀和（后缀 = 全和 − 前缀），查询 $O(\log n)$。整环交替（$S$ 为空）时直接回答 $n$。

### 3.4 示例演算

![示例 1 演算](images/alt_groups_iii_walkthrough.svg)

以示例 1（$n = 5$）演算，重点看一次改色引发的「先分裂、后合并」连环手术：

| 阶段 | 操作 | 坏边集 $S$ | 段长分布 $\mathrm{cnt}[\cdot]$ |
|------|------|-----------|-------------------------------|
| 初始 | — | $\{e_1\}$ | $\mathrm{cnt}[5]=1$（整环除 $e_1$ 外一段） |
| ① 分裂 $e_0$ | 查询 $[2,1,0]$：$colors[1]$ 由 1 改 0，左邻边 $e_0$：$(0,1)\to(0,0)$ 好变坏 | $\{e_0, e_1\}$ | $\mathrm{cnt}[4]=1, \mathrm{cnt}[1]=1$（段 $5 \to 4+1$） |
| ② 合并 $e_1$ | 同一改色的右邻边 $e_1$：$(1,1)\to(0,1)$ 坏变好 | $\{e_0\}$ | $\mathrm{cnt}[5]=1$（段 $1+4 \to 5$） |
| ③ 查询 $[1,4]$ | $L=4$，whole = false | $\{e_0\}$ | $\mathrm{cnt}[5] \cdot (5-4+1) = 2$ ✓ |

值得盯的细节：第 ①② 两步的 $\mathrm{prv} = \mathrm{nxt}$ 都是那条**唯一的另一条坏边**，环距公式 $l_1 = (e - \mathrm{prv}) \bmod n$ 自动给出 $4 + 1 = 5$ 的整环段拆分——「一个坏边时段长为 $n$」的情形无需任何 if 分支。

## 4. 算法细节

1. **边的坐标约定**：边 $e_i$ 连接瓷砖 $i$ 与 $(i+1) \bmod n$，$i \in [0, n)$。环距 $(x - y) \bmod n \in [1, n-1]$（$x \ne y$ 时）。段 $[\mathrm{prv}+1 \dots \mathrm{nxt}]$ 的长度是 $(\mathrm{nxt} - \mathrm{prv}) \bmod n$——但**不要单独用它**，统一走 $l_1 + l_2$ 加法公式（见下）。
2. **加法公式规避取模坑**：分裂时旧段长取 $l_1 + l_2$、合并时新段长取 $l_1 + l_2$，其中 $l_1 = (e - \mathrm{prv}) \bmod n$、$l_2 = (\mathrm{nxt} - e) \bmod n$。它对三类情形（普通段、跨 0 段、$S$ 只剩/原有 1 条坏边的整环段）**一律正确**；若改用 $(\mathrm{nxt} - \mathrm{prv}) \bmod n$，在 $\mathrm{prv} = \mathrm{nxt}$ 时会算出 $0$ 而非 $n$，这是本题最隐蔽的 bug。
3. **双树状数组**：$\mathrm{BIT}_1$ 在位置 $\mathrm{len}$ 存 $\mathrm{cnt}[\mathrm{len}]$，$\mathrm{BIT}_2$ 存 $\mathrm{cnt}[\mathrm{len}] \cdot (\mathrm{len}+1)$。查询 $L$ 时取全和减去前缀 $(L-1)$ 得后缀，代入 §3.3 展开式。段长取值范围 $[1, n]$，BIT 开 $n+1$。
4. **整环标志 `whole`**：$S$ 为空时（整环交替）查询直接回答 $n$；分裂进入空集时置 true、合并清空时置 false。注意 $S$ 只剩 1 条坏边**不是** whole——此时唯一段长为 $n$，公式自动正确。
5. **两条边先后处理**：一次改色让 $e_L, e_R$ 先后翻转，**顺序执行、互不协调**。处理 $e_L$ 后 $S$ 与 $\mathrm{cnt}$ 已是合法中间态，$e_R$ 在此基础上继续手术。示例 1 的「分裂再合并」正是两步各自独立、结果正确。
6. **环上前驱后继**：C++ `set` 中 `e` 的环向后继是 `next(it)` 或 `*S.begin()`（到尾环绕），前驱是 `prev(it)` 或 `*S.rbegin()`（到头环绕）；Python `SortedList` 用 `index` / `bisect_left` 定位后同样环绕。合并时先 `erase` 再定位，找的是**删除后** $e$ 位置的邻居。
7. **同色改色必须跳过**：`colors[index] == color` 时直接 continue（示例 2）。即便不跳过，边状态不翻转也不会触发手术，但显式跳过省去两次 $O(\log n)$ 的状态检查，更稳妥。

## 5. 正确性证明

**引理 1（窗口判定）**：环上从起点 $i$ 出发、长为 $L$ 的连续窗口（瓷砖 $i, i+1, \dots, i+L-1$，下标模 $n$）是交替组，当且仅当边 $e_i, e_{i+1}, \dots, e_{i+L-2}$ 全为好边。

**证明**：窗口内相邻瓷砖对恰为 $(i+j, i+j+1)$，$j = 0, \dots, L-2$，对应边 $e_{i+j}$。「相邻两两异色」即「每条对应边为好边」。∎

**引理 2（段贡献公式）**：设坏边集 $S \ne \emptyset$，段为坏边切环所得的链。则大小为 $L$ 的交替组总数为 $\sum_{\text{段}} \max(0, \mathrm{len} - L + 1)$。

**证明**：先证**覆盖**：任一交替组 $W$ 内部无坏边（引理 1），把 $W$ 的起点沿环延伸至两侧最近的坏边为止，得到包含 $W$ 的唯一段——$W$ 恰属于一个段（$S \ne \emptyset$ 保证段是链而非整环）。再证**段内计数**：长 $\mathrm{len}$ 的段是链，其内长 $L$ 的连续子段恰 $\max(0, \mathrm{len} - L + 1)$ 个，且每个都无坏边、由引理 1 是交替组。二者合并即得公式。∎

**引理 3（手术不变量）**：设手术前坏边集为 $S$。若 $e \notin S$ 且执行分裂（插入 $e$），或 $e \in S$ 且执行合并（删除 $e$），则手术后 $S' = S \cup \{e\}$ 或 $S \setminus \{e\}$，且 $\mathrm{cnt}$ 的改变量恰等于「按 $S'$ 重新切环」所得段长分布与「按 $S$ 切环」之差。

**证明**：分裂情形，设插入后 $e$ 的环上前驱、后继为 $\mathrm{prv}, \mathrm{nxt}$（$S = \emptyset$ 时 $S' = \{e\}$，唯一段为整环除 $e$ 外的链，算法对 $\mathrm{cnt}[n]$ 加 1，正是 $S' $ 的切分结果）。$S \ne \emptyset$ 时，开区间 $(\mathrm{prv}, \mathrm{nxt})$（环序）内无 $S$ 的元素，$e$ 落在其中，故 $e$ 原所在段为瓷砖序列 $\mathrm{prv}+1, \dots, \mathrm{nxt}$（沿环序），其长度：沿环从 $\mathrm{prv}+1$ 到 $e$ 共 $l_1 = (e - \mathrm{prv}) \bmod n$ 块，从 $e+1$ 到 $\mathrm{nxt}$ 共 $l_2 = (\mathrm{nxt} - e) \bmod n$ 块，两段无交且并集为原段，故原段长 $= l_1 + l_2$（**加法式自动涵盖了 $\mathrm{prv} = \mathrm{nxt}$ 即原段为整环段、长度为 $n$ 的情形**——此时 $l_1 + l_2 = n$）。算法删 $\mathrm{cnt}[l_1 + l_2]$、加 $\mathrm{cnt}[l_1], \mathrm{cnt}[l_2]$，与 $S'$ 重新切环的结果一致。合并情形对称：删除 $e$ 后 $\mathrm{prv}, \mathrm{nxt}$ 为 $S'$ 中 $e$ 位置的环上前驱后继，被 $e$ 隔开的两段长 $l_1, l_2$（同上式），拼接为长 $l_1 + l_2$ 的一段，算法的三个 $\mathrm{cnt}$ 更新与之逐项一致。∎

**定理（算法正确）**：对每个类型 1 查询（$L \in [3, n-1]$），算法输出的正是当前 `colors` 下大小为 $L$ 的交替组数量。

**证明**：对查询数归纳，不变量为「$S$ 恰为当前 `colors` 的坏边集，且 $\mathrm{cnt}$ 等于 $S$ 切环的段长分布」——初始构建直接成立；每次类型 2 查询改色后，$e_L, e_R$ 之外所有边的好坏不变（它们的端点颜色未动），而 $e_L, e_R$ 各自按引理 3 手术，不变量保持。查询时：若 $S = \emptyset$（整环交替），所有 $n$ 条边为好边，任意起点由引理 1 合法，答案 $n$；否则由引理 2，答案为 $\sum_{\mathrm{len} \ge L} \mathrm{cnt}[\mathrm{len}] (\mathrm{len} - L + 1)$，代数展开：

$$\sum_{\mathrm{len} \ge L} \mathrm{cnt}[\mathrm{len}]\,(\mathrm{len} + 1) \;-\; L \sum_{\mathrm{len} \ge L} \mathrm{cnt}[\mathrm{len}],$$

即 $\mathrm{BIT}_2$ 与 $L \cdot \mathrm{BIT}_1$ 的两个后缀和之差，与算法输出一致。∎

> ⚠️ `whole` 特判与「1 条坏边」的区别是本题正确性的分水岭：$S = \emptyset$ 时**环使首尾相接**，$n$ 个起点全合法，答案是 $n$；$|S| = 1$ 时坏边真实存在，环绕它的整环段只是一条**链**，贡献仍是 $n - L + 1$。把两者混为一谈（或反之），示例级别的数据就能击穿。

## 6. 复杂度分析

- **时间复杂度**：$O((n + q) \log n)$。初始构建：一次 $O(n)$ 扫描坏边 + $O(n)$ 建段 + $O(n \log n)$ 灌 BIT；每条类型 2 查询至多 2 次边翻转，每次 $O(\log n)$（有序集合定位 + 3 次 BIT 单点更新）；每条类型 1 查询 4 次 BIT 前缀和，$O(\log n)$。$n = q = 5\times10^4$ 时约 $3 \times 10^6$ 次基本操作。
- **空间复杂度**：$O(n)$——`same` 数组、有序集合、两棵树状数组；返回数组不计。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> numberOfAlternatingGroups(vector<int>& colors, vector<vector<int>>& queries) {
        const int n = colors.size();
        vector<long long> bit1(n + 1, 0), bit2(n + 1, 0);  // Σcnt[len] 与 Σcnt[len]*(len+1)
        auto add = [&](vector<long long>& b, int i, long long v) {
            for (; i <= n; i += i & (-i)) b[i] += v;
        };
        auto pre = [&](vector<long long>& b, int i) {       // 前缀和 [1..i]
            long long s = 0;
            for (; i > 0; i -= i & (-i)) s += b[i];
            return s;
        };
        auto addSeg = [&](int len, int v) {
            add(bit1, len, v);
            add(bit2, len, (long long)v * (len + 1));
        };

        vector<int> same(n);
        set<int> S;                                         // 坏边集
        for (int i = 0; i < n; i++) {
            same[i] = (colors[i] == colors[(i + 1) % n]);
            if (same[i]) S.insert(i);
        }
        bool whole = S.empty();
        if (!whole) {
            if (S.size() == 1) addSeg(n, 1);                // k=1：整环一段长 n
            else for (int a : S) {                          // 相邻坏边之间的段
                auto nx = S.upper_bound(a);
                int b = (nx != S.end()) ? *nx : *S.begin();
                addSeg((b - a + n) % n, 1);
            }
        }

        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            if (q[0] == 1) {
                int L = q[1];
                if (whole) ans.push_back(n);                // 无坏边：n 个起点全合法
                else {
                    long long c1 = pre(bit1, n) - pre(bit1, L - 1);  // #{len ≥ L}
                    long long c2 = pre(bit2, n) - pre(bit2, L - 1);  // Σ cnt[len]*(len+1)
                    ans.push_back((int)(c2 - (long long)L * c1));
                }
            } else {
                int idx = q[1], c = q[2];
                if (colors[idx] == c) continue;             // 同色改色：跳过
                colors[idx] = c;
                int es[2] = {(idx - 1 + n) % n, idx};       // 受影响的两条边
                for (int e : es) {
                    int ns = (colors[e] == colors[(e + 1) % n]);
                    if (ns == same[e]) continue;            // 好坏未翻转
                    same[e] = ns;
                    if (ns) {                               // 好变坏：分裂
                        S.insert(e);
                        if (S.size() == 1) { whole = false; addSeg(n, 1); }
                        else {
                            auto it = S.find(e);
                            int prv = (it != S.begin()) ? *prev(it) : *S.rbegin();
                            int nxt = (next(it) != S.end()) ? *next(it) : *S.begin();
                            int l1 = (e - prv + n) % n, l2 = (nxt - e + n) % n;
                            addSeg(l1 + l2, -1); addSeg(l1, 1); addSeg(l2, 1);
                        }
                    } else {                                // 坏变好：合并
                        S.erase(e);
                        if (S.empty()) { whole = true; addSeg(n, -1); }
                        else {
                            auto it = S.lower_bound(e);     // 删除后 e 的环向后继
                            int nxt = (it != S.end()) ? *it : *S.begin();
                            int prv = (it != S.begin()) ? *prev(it) : *S.rbegin();
                            int l1 = (e - prv + n) % n, l2 = (nxt - e + n) % n;
                            addSeg(l1, -1); addSeg(l2, -1); addSeg(l1 + l2, 1);
                        }
                    }
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
from sortedcontainers import SortedList

class Solution:
    def numberOfAlternatingGroups(self, colors: List[int], queries: List[List[int]]) -> List[int]:
        n = len(colors)
        bit1 = [0] * (n + 1)              # Σ cnt[len]
        bit2 = [0] * (n + 1)              # Σ cnt[len] * (len + 1)

        def add(b, i, v):
            while i <= n:
                b[i] += v
                i += i & (-i)

        def pre(b, i):
            s = 0
            while i > 0:
                s += b[i]
                i -= i & (-i)
            return s

        def add_seg(l, v):
            add(bit1, l, v)
            add(bit2, l, v * (l + 1))

        same = [colors[i] == colors[(i + 1) % n] for i in range(n)]
        bad = SortedList(i for i in range(n) if same[i])
        whole = not bad
        if bad:
            if len(bad) == 1:                              # k=1：整环一段长 n
                add_seg(n, 1)
            else:
                for j, a in enumerate(bad):                # 相邻坏边之间的段
                    add_seg((bad[(j + 1) % len(bad)] - a) % n, 1)

        ans = []
        for t, *rest in queries:
            if t == 1:
                L = rest[0]
                if whole:
                    ans.append(n)
                else:
                    c1 = pre(bit1, n) - pre(bit1, L - 1)   # #{len ≥ L}
                    c2 = pre(bit2, n) - pre(bit2, L - 1)   # Σ cnt[len]*(len+1)
                    ans.append(c2 - L * c1)
            else:
                idx, c = rest
                if colors[idx] == c:
                    continue                               # 同色改色：跳过
                colors[idx] = c
                for e in ((idx - 1) % n, idx):             # 受影响的两条边
                    ns = colors[e] == colors[(e + 1) % n]
                    if ns == same[e]:
                        continue                           # 好坏未翻转
                    same[e] = ns
                    if ns:                                 # 好变坏：分裂
                        bad.add(e)
                        if len(bad) == 1:
                            whole = False
                            add_seg(n, 1)
                        else:
                            pos = bad.index(e)
                            prv = bad[pos - 1]
                            nxt = bad[pos + 1] if pos + 1 < len(bad) else bad[0]
                            l1, l2 = (e - prv) % n, (nxt - e) % n
                            add_seg(l1 + l2, -1)
                            add_seg(l1, 1)
                            add_seg(l2, 1)
                    else:                                  # 坏变好：合并
                        bad.remove(e)
                        if not bad:
                            whole = True
                            add_seg(n, -1)
                        else:
                            pos = bad.bisect_left(e)
                            nxt = bad[pos] if pos < len(bad) else bad[0]
                            prv = bad[pos - 1]
                            l1, l2 = (e - prv) % n, (nxt - e) % n
                            add_seg(l1, -1)
                            add_seg(l2, -1)
                            add_seg(l1 + l2, 1)
        return ans
```

> 💡 两份代码的分裂 / 合并共享同一个加法公式 $l_1 + l_2$，没有一个针对「整环段」的特判分支——`whole` 之外的所有环上情形都被代数式统一吸收，这是把正确性押在引理 3 上的红利。

## 8. 边界情况与易错点

1. **整环交替（最大坑）**：$S = \emptyset$ 时答案是 $n$，不是 $n - L + 1$。环上窗口首尾相接、$n$ 个起点全部合法，而「长 $n$ 的链」只有 $n - L + 1$ 个窗口。忘写 `whole` 特判，`0101…` 型数据必挂。
2. **恰 1 条坏边时段长是 $n$**：直接算 $(\mathrm{nxt} - \mathrm{prv}) \bmod n$ 会得到 $0$。用 $l_1 + l_2$ 加法公式规避；初始构建时 $|S| = 1$ 也要单独给 $\mathrm{cnt}[n]$ 加 1。
3. **同色改色跳过**：`[2, i, colors[i]]` 是合法输入（示例 2），不跳过虽不至于出错（边状态不变、无手术触发），但白付两次定位；真正致命的是「未比较 `same` 就动手述」——那是数据结构当场错乱的快车道。
4. **一次改色动两条边**：$e_L$ 与 $e_R$ 都要检查，漏掉 $e_L = (\mathrm{index}-1+n) \bmod n$（`index = 0` 时环绕到 $n-1$）是最常见的漏改。
5. **合并先删后找邻居**：前驱后继必须在 `erase` 之后的集合里取；分裂则先插入再取。两者的「环绕」（`begin`/`rbegin`）方向别搞反。
6. **BIT 下标与值域**：段长 $\mathrm{len} \in [1, n]$，BIT 开 $n + 1$；$L \in [3, n-1]$，故 `pre(L-1)` 的参数在 $[2, n-2]$，无越界。
7. **溢出**：$\mathrm{cnt}[\mathrm{len}] \cdot (\mathrm{len} + 1)$ 单值最大约 $n+1$，总和不超过 $2n \approx 10^5$，其实 `int` 也够——但树状数组中间层求和习惯上用 `long long` 更稳（若换成「段长平方」类权值则必须 64 位）。
8. **初始构建别忘环**：$|S| \ge 2$ 时最后一段是坏边最大值绕回最小值，`(b - a + n) % n` 的 `+n` 不能省。
9. **答案上界 sanity check**：任意时刻 $\sum_{\text{段}} \mathrm{len} = n$（$S \ne \emptyset$），故答案 $\le n$；若输出出现 $> n$ 的值，必是段长重复计入（手术更新数不对）。

**延伸思考**：
