# LeetCode 设计相邻元素求和服务 题解

## 1. 题目概述

- **标题 / 题号**：设计相邻元素求和服务（#3242，easy）
- **链接**：https://leetcode.cn/problems/design-neighbor-sum-service/
- **来源**：LeetCode 第 409 场周赛 Q1
- **难度**：简单
- **标签**：设计、数组、哈希表、矩阵、模拟

**题意**：给定一个 $n \times n$ 的二维数组 `grid`，其中元素是 $[0, n^2-1]$ 内互不相同的整数。要求实现 `NeighborSum` 类：

- `NeighborSum(grid)`：初始化对象；
- `adjacentSum(value)`：返回与 `value` **上下左右**相邻的元素之和；
- `diagonalSum(value)`：返回与 `value` **对角**相邻（左上、右上、左下、右下）的元素之和。

越界的"邻居"不存在，自然不计入和。

**约束**：

- $3 \le n = \text{grid.length} = \text{grid[0].length} \le 10$
- $0 \le \text{grid}[i][j] \le n^2 - 1$，且所有值互不相同
- 查询的 `value` 一定在 $[0, n^2-1]$ 内（即一定存在于 `grid` 中）
- `adjacentSum` 与 `diagonalSum` 总调用次数最多 $2n^2$ 次

> 💡 **关键前提**：$n \times n$ 个格子、值互异且全部落在大小为 $n^2$ 的值域 $[0, n^2-1]$ 内，所以 `grid` 恰好是 $0 \sim n^2-1$ 的一个**排列**——这为"值当下标"的直接寻址创造了条件。

## 2. 示例

**示例 1**

```text
输入：

[[[[0,1,2],[3,4,5],[6,7,8]]], [1], [4], [4], [8]]

输出：[null, 6, 16, 16, 4]

解释：
grid = 0 1 2
       3 4 5
       6 7 8
adjacentSum(1)：1 在角落 (0,1) 的邻居是 0、2、4 → 6
adjacentSum(4)：4 在中心，邻居是 1、3、5、7 → 16
diagonalSum(4)：对角是 0、2、6、8 → 16
diagonalSum(8)：8 在角落 (2,2)，只有左上角 4 在网格内 → 4
```

**示例 2**

```text
输入：
["neighborSum", "diagonalSum"]

解释：
```

## 3. 解题思路

### 3.1 暴力思路：每次查询全表扫描

最朴素的做法：每次查询都扫描整个 `grid` 找到 `value` 所在位置 $(x, y)$，再累加邻居。单次查询 $O(n^2)$，总代价 $O(q \cdot n^2)$（$q \le 2n^2$）。

由于 $n \le 10$，这个暴力在周赛里**完全能过**（最多约 $2 \times 10^4$ 次基本操作）。但本题标签是**设计**——考察点正是"把重复查询的开销一次性摊到预处理里"，让每次查询变成 $O(1)$。这是签到题里最值得沉淀的套路。

### 3.2 核心观察：倒排索引，值即下标

**关键观察**：`grid` 是 $0 \sim n^2-1$ 的排列，**值域恰好等于下标域**。

- 预处理一张"倒排表" `pos[value] = (x, y)`，把"按值找位置"从 $O(n^2)$ 的扫描降为 $O(1)$ 的数组访问；
- 因为值就是下标，连哈希函数都不需要——**直接寻址数组**即可，比 `unordered_map` 更快更省；
- 邻居关系是固定的 8 个方向（4 正向 + 4 对角），用**方向数组**枚举 + 边界检查即可。

![5×5 网格中相邻邻居与对角邻居的方向示意](images/nbr_sum_directions.svg)

### 3.3 算法流程

1. **构造函数**：双重循环扫描 `grid`，记录 `pos[grid[i][j]] = (i, j)`，共 $n^2$ 次；
2. **查询**：取 $(x, y) = \text{pos[value]}$，枚举 4 个方向偏移 $(dx, dy)$，令 $nx = x + dx$、$ny = y + dy$，若 $(nx, ny)$ 在网格内则累加 `grid[nx][ny]`；
3. `adjacentSum` 与 `diagonalSum` 只是**方向数组不同**，可共用一个私有辅助函数。

![查询流程图：值定位、方向枚举与边界判断](images/nbr_sum_pos_lookup.svg)

### 3.4 示例演算

以示例 1 的 `grid = [[0,1,2],[3,4,5],[6,7,8]]` 为例：

- `adjacentSum(4)`：`pos[4] = (1,1)`，四个正向邻居 1、3、5、7 全部在网格内，和为 $16$；
- `diagonalSum(8)`：`pos[8] = (2,2)` 在角落，四个对角方向中只有 $(1,1)$ 即 4 在网格内，其余 3 个越界跳过，和为 $4$。

![示例演算：adjacentSum(4) 与 diagonalSum(8)](images/nbr_sum_walkthrough.svg)

## 4. 算法细节

1. **直接寻址数组**：`pos` 开成大小 $n^2$ 的数组而非哈希表。依据是"值域 $=$ 下标域"这一排列性质（见约束），省去哈希开销，也避免哈希冲突的讨论。
2. **方向数组**：
   - 正向：$(-1,0), (1,0), (0,-1), (0,1)$；
   - 对角：$(-1,-1), (-1,1), (1,-1), (1,1)$。
   两组方向都是**不重不漏**的 4 个偏移，写错任何一个都会出错。
3. **边界检查**：$0 \le nx < n$ 且 $0 \le ny < n$。注意是**四个不等式缺一不可**——越行不越列、越列不越行都要拦住。
4. **代码复用**：`adjacentSum` / `diagonalSum` 共用一个 `cal(value, dirs)` 辅助函数，把"差异"收敛到方向数组这一个参数上，这是方向数组技巧的标准用法。
5. **grid 的保存**：查询时要读邻居的值，构造时把 `grid` 存为成员（引用或拷贝均可，LeetCode 保证 `grid` 在对象生命周期内有效）。

## 5. 正确性证明

**引理 1（位置唯一性）**：每个 `value` 在 `grid` 中恰好出现一次，因此 `pos[value]` 唯一确定其所在单元格。

**证明**：`grid` 有 $n^2$ 个单元格，元素互不相同且都取自大小恰为 $n^2$ 的集合 $[0, n^2-1]$。由抽屉原理，$[0, n^2-1]$ 中每个值恰好出现一次。∎

**引理 2（邻居枚举的完备性）**：与单元格 $(x, y)$ 上下左右相邻的单元格集合为 $\{(x\pm1, y), (x, y\pm1)\} \cap \text{网格}$；对角相邻的集合为 $\{(x\pm1, y\pm1)\} \cap \text{网格}$。

**证明**：由"相邻 / 对角相邻"的定义直接验证：相邻要求两格行或列恰一个相差 1 且另一个相等；对角相邻要求行、列同时相差 1。∎

**定理**：对任意合法查询 `value`，算法返回的 `adjacentSum(value)` / `diagonalSum(value)` 正确。

**证明**：由引理 1，`pos[value]` 给出 `value` 的唯一位置 $(x, y)$。由引理 2，枚举对应 4 个偏移并过滤越界后，恰好**不重不漏**地遍历所有在网格内的邻居；边界检查保证只累加真实存在的单元格。累加结果即为所求。又因邻居格互不相同（偏移互异且 $(x,y)$ 自身不在其中），无重复计数。∎

## 6. 复杂度分析

- **时间复杂度**：构造 $O(n^2)$（扫描全网格建倒排表）；单次查询 $O(1)$（一次寻址 + 4 次偏移与边界判断）。设总查询次数为 $q \le 2n^2$，整体 $O(n^2 + q)$。
- **空间复杂度**：$O(n^2)$，即倒排表 `pos`（若把 `grid` 拷贝为成员，则另加 $O(n^2)$，量级不变）。

## 7. 参考代码

### C++

```cpp
class NeighborSum {
  public:
    NeighborSum(vector<vector<int>>& grid) : grid(grid), n(grid.size()) {
        // 值域 [0, n^2-1] 恰为排列，直接寻址表即可
        pos.resize(n * n);
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                pos[grid[i][j]] = {i, j};
    }

    int adjacentSum(int value) {
        static constexpr int dirs[4][2] = {{-1, 0}, {1, 0}, {0, -1}, {0, 1}};
        return cal(value, dirs);
    }

    int diagonalSum(int value) {
        static constexpr int dirs[4][2] = {{-1, -1}, {-1, 1}, {1, -1}, {1, 1}};
        return cal(value, dirs);
    }

  private:
    int cal(int value, const int dirs[4][2]) {
        auto [x, y] = pos[value];
        int s = 0;
        for (const auto& d : dirs) {
            int nx = x + d[0], ny = y + d[1];
            if (nx >= 0 && nx < n && ny >= 0 && ny < n)
                s += grid[nx][ny];
        }
        return s;
    }

    vector<vector<int>> grid;
    vector<pair<int, int>> pos;
    int n;
};
```

### Python

```python
class NeighborSum:
    ADJ = ((-1, 0), (1, 0), (0, -1), (0, 1))
    DIAG = ((-1, -1), (-1, 1), (1, -1), (1, 1))

    def __init__(self, grid: List[List[int]]):
        self.grid = grid
        self.n = len(grid)
        # 直接寻址表：pos[v] = (i, j)
        self.pos = [None] * (self.n * self.n)
        for i, row in enumerate(grid):
            for j, v in enumerate(row):
                self.pos[v] = (i, j)

    def adjacentSum(self, value: int) -> int:
        return self._cal(value, self.ADJ)

    def diagonalSum(self, value: int) -> int:
        return self._cal(value, self.DIAG)

    def _cal(self, value: int, dirs) -> int:
        x, y = self.pos[value]
        return sum(
            self.grid[x + dx][y + dy]
            for dx, dy in dirs
            if 0 <= x + dx < self.n and 0 <= y + dy < self.n
        )
```

## 8. 边界情况与易错点

1. **角落 / 边缘单元格邻居不足 4 个**：边界检查不能漏。官方样例 `diagonalSum(8) = 4` 就是对角落单元格的考察——只有 1 个对角邻居在网格内。
2. **方向数组写错**：对角偏移是 $(\pm1, \pm1)$ 的全部 4 种组合，多写、少写或写错符号（如漏掉 $(1,-1)$）都会 WA。
3. **别把两类邻居混在一起**：`adjacentSum` 与 `diagonalSum` 的邻居集**互不相交**（一个曼哈顿方向、一个对角方向），不要贪图省事枚举全部 8 个方向再区分。
4. **用数组而非哈希表**：`pos` 直接开 $n^2$ 的数组即可（值即下标）；如果条件反射地写 `unordered_map`，不仅慢，还容易忽略"值域恰好连续"这个题目送的性质。
5. **查询值必存在**：题目保证 `value` 在 $[0, n^2-1]$ 内且 `grid` 是排列，所以 `pos[value]` 一定有效，无需判空。若题目不保证，需先检查再访问。
6. **和的最大值**：邻居最多 4 个、每个值 $\le n^2 - 1 \le 99$，和不超过 396，`int` 毫无溢出风险；但若数据范围放大，累加变量要换成 `long long`。
