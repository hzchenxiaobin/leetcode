# LeetCode 新增道路查询后的最短距离 II 题解

## 1. 题目概述

- **标题 / 题号**：新增道路查询后的最短距离 II（#3244，hard）
- **链接**：https://leetcode.cn/problems/shortest-distance-after-road-addition-queries-ii/
- **来源**：LeetCode 第 409 场周赛 Q3
- **难度**：困难
- **标签**：贪心、图、有序集合、均摊

**题意**：$n$ 座城市 $0 \sim n-1$ 排成一条链：初始只有单向链边 $i \to i+1$。依次处理 `queries`，每条查询 $[u, v]$ 新建一条**单向**边 $u \to v$（保证 $u < v$、$v - u \ge 2$、无重边），**每加一条立刻回答**：当前从 $0$ 到 $n-1$ 的最短路长度（边数）。`answer[i]` 对应前 $i+1$ 条查询处理完后的距离。

与 Q2（#3243）题面几乎逐字相同，只有两处变化：

- **规模放大 200 倍**：$n, q \le 10^5$（Q2 是 $500$）；
- **多一条灵魂保证**：不存在两条查询 $i \ne j$ 满足 $u_i < u_j < v_i < v_j$——**新增边两两不交叉**。

**约束**：

- $3 \le n \le 10^5$，$1 \le \mathrm{queries.length} \le 10^5$
- $0 \le u < v < n$ 且 $v - u \ge 2$
- 无重复道路；**任意两条查询不交叉**（见下方读题关键）

> 💡 **读题关键**：规模宣判了「每查询重算」的死刑；不交叉保证则是命题人递过来的梯子——本题全部解法灵感都藏在这一句话里。读约束时多问一句「这条保证替我消灭了什么坏情况」，往往就是整道题的题眼。

## 2. 示例

**示例 1**

```text
输入：n = 5, queries = [[2,4],[0,2],[0,4]]
输出：[3,2,1]

解释：
加 (2,4) 后最短路 0→1→2→4，长 3；
加 (0,2) 后最短路 0→2→4，长 2；
加 (0,4) 后最短路 0→4，长 1。
```

**示例 2**

```text
输入：n = 4, queries = [[0,3],[0,2]]
输出：[1,1]

解释：
加 (0,3) 后 0→3 直达，长 1；
再加 (0,2) 后最短路仍是 0→3，长 1 —— 第二条边被第一条「吃掉」了。
```

> ⚠️ 示例 2 是理解本题的钥匙：$(0,2)$ 嵌套在 $(0,3)$ **内部**，对答案毫无贡献。Q2 里我们还能硬着头皮全量重算；本题规模下，必须把这种「大吃小」翻译成可增量维护的结构。

## 3. 解题思路

### 3.1 暴力思路：照搬 Q2 的逐查询重算

Q2 的正解是「加一条边，$O(n+q)$ 一趟递推重算」，直接搬过来：

| 方案 | 总代价（$n, q \le 10^5$） | 判断 |
|------|---------------------------|------|
| Q2 全量重算 | $O(q(n+q)) \approx 2 \times 10^{10}$ | 超时 |
| Q2 剪枝（$\mathrm{dist}[u]+1 \ge \mathrm{dist}[v]$ 时跳过整趟） | 最坏仍 $O(nq)$：每条新边都能小幅拉低一整段 | 不可靠 |
| **删点增量（本文）** | 均摊 $O((n+q)\log n)$ | ✓ |

规模逼我们放弃「每步重算」、转向**增量维护**；而增量维护必须有结构性质兜底——兜底的正是「不交叉」。

### 3.2 核心观察：不交叉 ⇒「大吃小」，最优化坍缩成计数

![区间两两嵌套或不相交](images/road_add_ii_laminar.svg)

把每条新增边 $(u, v)$ 看做一个**区间** $[u, v]$，记它一步跨越、相对走路省下的步数为

$$\mathrm{save}(u, v) = v - u - 1 \quad(\ge 1).$$

四个层层递进的观察：

- **观察 1（laminar 族）**：不交叉保证 ⇒ 任意时刻，已加入的边两两**要么嵌套、要么不相交**（端点相接算不相交），不存在「半重叠」。这样的区间族在数学上叫 **laminar（层叠）族**。
- **观察 2（路径只用不相交的边）**：图中所有边都指向更大编号，路径顶点序列严格递增——一条路径若先后使用两条边，前一条必然整体在后一条左侧。**嵌套的两条边永远无法被同一条路径使用**：外层一跳就把内层整个跨过去了。
- **观察 3（长度公式）**：任何一条 $0 \to n-1$ 路径的长度都是

$$L = (n-1) \;-\; \sum_{e \,\in\, \text{路径使用的新边}} \mathrm{save}(e).$$

  走链边一步前进 1；用边 $(u,v)$ 一步前进 $v-u$、省下 $v-u-1$。
- **观察 4（大吃小）**：把**不被其他边包含的边**称为**极大边**。极大边两两不相交（观察 1：若相交必嵌套，嵌套则小者非极大）。而一条极大边内部随便怎么挑互不相交的边，省下的总步数也不会超过它自己——互不相交区间的长度之和不超过容器长度。于是**最优策略就是全选极大边**：

$$\mathrm{answer} = (n-1) \;-\; \sum_{r \,\in\, \text{极大边}} \mathrm{save}(r).$$

最优化问题就此坍缩成**计数问题**：只需在线维护「极大边集合」，答案就是对 $\mathrm{save}$ 求和的补。

> 💡 一句话直觉：**嵌套时「大的吃掉小的」——选包含者永远不亏；相离时互不干扰——可以全都要。** 两类关系都不产生「二选一」的抉择，最优化自然退化成维护一个集合再求和。

### 3.3 算法流程：把「维护极大边」换成「删存活点」

直接维护极大边集合需要「包含判定 + 吸收删除」，能做但易错。有个漂亮的等价改写：

**维护「存活点集」$A$ = 当前最短路的顶点集。** 初始 $A = \{0, 1, \dots, n-1\}$（整条链）。此后每条查询 $(u, v)$ 只做一个动作：

- **若 $(u,v)$ 不被任何已有边包含**：最短路改道，$(u,v)$ 内部的路径点不再被经过——**从 $A$ 中删掉开区间 $(u, v)$ 内的所有存活点**；
- **若 $(u,v)$ 被某条大边包含**：$(u,v)$ 落在那条极大边内部，那里的点**早已死透**——删除循环一个点都碰不到，**自动空操作**。

两种情形共享同一段代码，每步 `answer = |A| − 1`。全程**零特判**：不写包含检测、不维护极大边、不碰 dist 数组。

### 3.4 示例演算

![示例 1 的存活点收缩过程](images/road_add_ii_walkthrough.svg)

以示例 1（$n = 5$）演算：

| 阶段 | 新增道路 | 开区间内存活点 | 删除后 $A$ | answer |
|------|----------|----------------|------------|--------|
| 初始 | — | — | $\{0,1,2,3,4\}$ | 4 |
| ① | $(2,4)$ | $\{3\}$ | $\{0,1,2,4\}$ | **3** |
| ② | $(0,2)$ | $\{1\}$ | $\{0,2,4\}$ | **2** |
| ③ | $(0,4)$ | $\{2\}$ | $\{0,4\}$ | **1** |

两个值得盯的细节：

- **查询 ③ 的「吸收」**：加入 $(0,4)$ 时，小边 $(0,2)$、$(2,4)$ 被整体吞并——它们各自跳过的点 $1, 3$ 早已不在 $A$ 里，本次只需删 $2$。新边省 $3$ 步，两条旧边合计省 $2$ 步，答案净减 $1$。
- **空操作（示例 2）**：$n = 4$，先加 $(0,3)$（存活 $\{0,3\}$，答案 1），再加 $(0,2)$：开区间 $(0,2)$ 内的点 $1$ 早已死透，循环空转，答案保持 1。

## 4. 算法细节

1. **数据结构**：C++ 用 `std::set<int>`，Python 用 `sortedcontainers.SortedList`。定位 `lower_bound(u+1)` 即「第一个严格大于 $u$ 的存活点」，从此向右删到 `< v` 为止——精确对应**开区间** $(u, v)$。
2. **均摊**：每个点至多被删除一次（删了就不复活），全部删除操作总计 $O(n\log n)$；每条查询另付一次 $O(\log n)$ 定位。总 $O((n+q)\log n)$。换「并查集跳点」还能压到近线性（见延伸思考）。
3. **answer 即 `size()−1`**：存活点按升序恰是当前最短路的顶点序列——相邻存活点之间必有边（链边或跳边），故最短路长 = 存活点数 − 1。`std::set::size()` 与 `len()` 都是 $O(1)$。
4. **零特判的代价转移**：正确性全部押在不变量上（见 §5），代码里没有一个策略分支——被包含、端点相接、空区间共享同一段删除循环。比赛中这种「无分支」实现最难写错。
5. **删除的是开区间**：$u$ 与 $v$ 本身必须存活——$v$ 是改道后路径的必经点；用 `lower_bound(u+1)` 而非 `lower_bound(u)`，就是在守住这一点。
6. **与 Q2 思路一脉相承**：Q2 结尾预告的「增量传播」维护的是整个 dist 数组、只传播变化；本文更激进——最短路的形态完全由「极大边骨架」决定，干脆只维护骨架（存活点），把 $O(n)$ 的传播压成 $O(\text{真正被删的点数})$。

## 5. 正确性证明

**引理 1（边族 laminar）**：任意时刻，已加入的两条边 $(a,b)$、$(c,d)$（不妨 $a \le c$）满足：要么 $c \ge b$（不相交，端点相接可），要么 $d \le b$（$(c,d)$ 嵌套于 $(a,b)$）。

**证明**：反设 $c < b$ 且 $d > b$。若 $a = c$，两边同起点，短者嵌套于长者，与反设矛盾；故 $a < c$，此时 $a < c < b < d$ 恰是题面保证中排除的交叉模式，矛盾。∎

**引理 2（路径不使用嵌套边对）**：任何 $0 \to n-1$ 路径使用的两条新边必不相交（作为区间）。

**证明**：所有边都指向更大编号，路径顶点序列 $x_0 < x_1 < \cdots$ 严格递增。若路径先后使用 $(a,b)$、$(c,d)$，则两者都是序列中的相邻对且前者在前，故 $b \le c$，即两区间不相交。∎

**引理 3（长度公式）**：任何 $0 \to n-1$ 路径 $P$ 满足 $|P| = (n-1) - \sum_{e \in P} \mathrm{save}(e)$，其中求和遍历 $P$ 使用的新边。

**证明**：对路径顶点序列 $0 = x_0 < x_1 < \cdots < x_L = n-1$，每步或走链边（$x_{i+1} - x_i = 1$）或用新边 $(x_i, x_{i+1})$。对每步累加跨度得 $\sum (x_{i+1} - x_i) = n-1$；链边步「1 步跨 1」省 0，新边步「1 步跨 $v-u$」省 $\mathrm{save} = v-u-1$。故 $L = (n-1) - \sum \mathrm{save}$。∎

**引理 4（全选极大边即最优）**：设 $R$ 为当前极大边集合，则最短路长度恰为 $(n-1) - \sum_{r \in R} \mathrm{save}(r)$。

**证明**：$R$ 中边两两不相交：若相交，由引理 1 必一条嵌套另一条，与两者都极大矛盾。于是「沿链直行 + 依次使用 $R$ 全部边」是合法路径，长度恰为该值（引理 3），故最短路 $\le$ 该值。

反之任取路径 $P$：它的每条新边 $e$ 都被某条极大边包含（沿「被包含」关系向上追溯，有限步必达极大；若 $e$ 自身极大则取自身）。把 $P$ 的新边按所属极大边分组：组内边两两不相交（引理 2）且都含于该极大边 $r$ 的区间内，故每组 $\sum \mathrm{save} \le (v_r - u_r) - \text{组内边数} \le \mathrm{save}(r)$（组空时 $0 \le \mathrm{save}(r)$）。不同组对应的极大边互不相同（$R$ 两两不相交，所属唯一），求和得 $\sum_{e \in P} \mathrm{save}(e) \le \sum_{r \in R} \mathrm{save}(r)$，代入引理 3 得 $|P| \ge (n-1) - \sum_R \mathrm{save}$。两个方向夹逼，结论成立。∎

**定理（删点算法正确）**：算法全程维护不变量——**存活点集 $A$ 按升序构成一条最短路，且 $|A| - 1 = (n-1) - \sum_{r \in R} \mathrm{save}(r)$**。因而每步输出的 $|A| - 1$ 即为正确答案。

**证明**：对查询数归纳。初始 $A = \{0,\dots,n-1\}$、$R = \emptyset$，链即最短路，成立。

设不变量成立，加入新边 $e = (u, v)$。先记录一个结构事实：**每个已删点都落在某条极大边的内部**——点 $x$ 被删的那一刻落在某条新极大边的内部；该边之后即使被更大的边吸收，$x$ 仍在那条更大极大边的内部。

- **情形 1（$e$ 被某条已有边包含）**：则 $e$ 被某条极大边 $m \supseteq e$ 包含，$R$ 与 $\sum_R \mathrm{save}$ 均不变。而开区间 $(u,v) \subseteq (u_m, v_m)$ 内没有任何存活点（$A$ 是「链 + 极大边」路径的顶点集，路径从 $u_m$ 直接跳到 $v_m$）——删除循环空转，$A$ 不变，不变量保持。
- **情形 2（$e$ 不被任何已有边包含）**：$e$ 成为新极大边；由引理 1，与 $e$ 内部相交的原极大边只能嵌套于 $e$，设为 $r_1, \dots, r_k$（它们退出 $R$）。先证 $u, v \in A$：若 $u \notin A$，则 $u$ 落在某极大边 $m$ 的内部，$m$ 与 $e$ 相交，由引理 1 只能嵌套——$m \subset e$ 需要 $u_m \ge u$，与 $u_m < u$ 矛盾，故必 $e \subset m$，与前提矛盾；$v \notin A$ 同理（$m \subset e$ 需 $v_m \le v$，与 $v < v_m$ 矛盾）。于是 $u, v$ 都在路径上，$(u,v)$ 内部的存活点恰是路径上 $u$ 到 $v$ 之间的中间点，全部换成一跳 $u \to v$ 后，$A' = A \setminus (u, v)$ 按升序仍构成合法路径。计数：$(u,v)$ 内部共 $v - u - 1$ 个点，其中已死点恰是 $\bigcup_i (u_{r_i}, v_{r_i})$ 的元素（$r_i$ 两两不相交、内部都含于 $(u,v)$，合计 $\sum_i \mathrm{save}(r_i)$ 个），故本次删除了 $v - u - 1 - \sum_i \mathrm{save}(r_i)$ 个点；另一方面 $\sum_{R'} \mathrm{save} = \sum_{R} \mathrm{save} - \sum_i \mathrm{save}(r_i) + \mathrm{save}(e)$。两式相减，$|A'| - 1 = (n-1) - \sum_{R'} \mathrm{save}$ 精确保持。

由引理 4，两种情形下 $|A| - 1$ 都等于当前最短路长度，归纳完成。∎

> ⚠️ 注意「不交叉」保证是**承重墙**：若允许交叉（如 $n = 7$，`queries = [[0,4],[2,6]]`），删点法会输出 $[3, 1]$，而正确答案是 $[3, 3]$——$(2,6)$ 的起点 $2$ 已死，删点法却误把 $4, 5$ 当作可跳过的点。引理 1 在交叉输入下根本不成立。

## 6. 复杂度分析

- **时间复杂度**：$O((n + q) \log n)$——每个点至多删除一次，全部删除合计 $O(n \log n)$；每条查询另付 $O(\log n)$ 定位与 $O(1)$ 计数。
- **空间复杂度**：$O(n)$，即存活点集合；返回数组不计。
- **对照**：Q2 式重算 $O(q(n+q)) \approx 2 \times 10^{10}$，本文快了约 5 个数量级；并查集跳点变体还能再省掉 $\log$ 因子。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> shortestDistanceAfterQueries(int n, vector<vector<int>>& queries) {
        set<int> alive;                          // 存活点 = 当前最短路的顶点集
        for (int i = 0; i < n; i++) alive.insert(i);
        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            int u = q[0], v = q[1];
            // 删除开区间 (u,v) 内的存活点；被包含时循环自动空转
            for (auto it = alive.lower_bound(u + 1); it != alive.end() && *it < v;)
                it = alive.erase(it);
            ans.push_back((int)alive.size() - 1);
        }
        return ans;
    }
};
```

### Python

```python
from sortedcontainers import SortedList

class Solution:
    def shortestDistanceAfterQueries(self, n: int, queries: List[List[int]]) -> List[int]:
        alive = SortedList(range(n))             # 存活点 = 当前最短路的顶点集
        ans = []
        for u, v in queries:
            i = alive.bisect_right(u)             # 第一个 > u 的存活点
            j = alive.bisect_left(v)              # 第一个 >= v 的存活点
            del alive[i:j]                        # 删除开区间 (u,v) 内的存活点
            ans.append(len(alive) - 1)            # 被包含时 i == j，自动空操作
        return ans
```

> 💡 两个实现都没有一个策略分支——包含判定、吸收、空操作全部统一进删除循环，这是把正确性全押在不变量证明上的红利。

## 8. 边界情况与易错点

1. **删除必须是开区间 $(u,v)$**：`lower_bound(u+1)` 起步守住左端，`*it < v` 停步守住右端。误删 $v$ 破坏「$v$ 是必经点」；误删 $u$ 同样出错——例如先 $(0,2)$ 再 $(2,4)$，点 $2$ 必须存活（它既是前者的终点又是后者的起点）。
2. **C++ 迭代器失效**：循环删除务必写 `it = alive.erase(it)`，不要先 `erase(it)` 再 `it++`。
3. **被包含的边是空操作，别画蛇添足**：手动加「包含检测」反而容易在端点相接的嵌套（先 $(0,4)$ 再 $(0,2)$）上把判定写错。
4. **端点相接是合法输入**：$(0,2)$ 与 $(2,4)$ 不算交叉（题面模式要求四个不等号全部成立），两条都该生效。
5. **第一条查询可能就是 $(0, n-1)$**：一次删光中间所有点，答案直接变 1。
6. **答案单调不增、发生删除时严格递减**：可用来对拍 sanity check；若输出出现「变大」，必是删错了区间。
7. **不交叉保证是生命线**：交叉反例见 §5 末尾。考场上若对保证有疑虑，先拿 `[[0,4],[2,6]]` 自测。
8. **别用数组模拟删除**：`vector` 按值搬移是每趟 $O(n)$，总量回到 $O(nq)$ 超时；必须有序结构（$O(\log n)$）或并查集（近常数均摊）。
9. **无溢出风险**：答案不超过 $n - 1 \le 10^5 - 1$，`int` 足够。

- [LeetCode 435. 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/)：不相交区间的贪心调度，与「极大边两两不相交」互为表里。

**延伸思考**：

- **近线性优化**：把 `set` 换成「并查集跳点」——`fa[x] ≠ x` 表示点 $x$ 已死，`find(x)` 返回右侧第一个存活点，路径压缩后总复杂度 $O((n+q)\,\alpha(n))$，还免掉容器开销。它与本文是同一过程的两种视角：一个维护「点」，一个维护「区间」。
- **「每点至多删一次」是通用套路**：任何「只删除、不复活」的在线维护（区间并、扫描线、删点跳点）都可用有序集合或并查集做均摊——识别出这种单调性，复杂度就有了下界保障。
- **若去掉不交叉保证**：极大边可能相交，「全选极大边」失效（§5 反例），问题退回「动态 DAG 最短路」的本行——把链压缩到 $O(q)$ 个查询端点、做增量松弛，是另一个量级的难题；Q2 的小数据正是为一般形态准备的练手。
