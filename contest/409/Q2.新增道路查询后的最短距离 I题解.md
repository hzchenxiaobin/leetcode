# LeetCode 新增道路查询后的最短距离 I 题解

## 1. 题目概述

- **标题 / 题号**：新增道路查询后的最短距离 I（#3243，medium）
- **链接**：https://leetcode.cn/problems/shortest-distance-after-road-addition-queries-i/
- **来源**：LeetCode 第 409 场周赛 Q2
- **难度**：中等
- **标签**：图、广度优先搜索、动态规划、拓扑序

**题意**：$n$ 座城市编号 $0 \sim n-1$，初始只有一条链——每个城市 $i$ 有一条**单向**道路通向 $i+1$。依次处理 `queries`：每条查询 $[u, v]$ 新建一条**单向**道路 $u \to v$，并且**每加完一条就要立刻回答**：从城市 $0$ 到城市 $n-1$ 的最短路径长度（边数）。返回答案数组 `answer`，`answer[i]` 对应前 $i+1$ 条查询处理完后的距离。

**约束**：

- $3 \le n \le 500$
- $1 \le \text{queries.length} \le 500$
- $0 \le u < v < n$，且 $v - u \ge 2$（新边不会与链边重合，也无自环）
- 查询中没有重复的道路

> 💡 **关键前提**：所有边——链边 $i \to i+1$ 与新边 $u \to v$（保证 $u < v$）——都从**小编号指向大编号**。这个"单调向前"的结构是本题一切优化的根基。

## 2. 示例

**示例 1**

```text
输入：n = 5, queries = [[2,4],[0,2],[0,4]]
输出：[3,2,1]

解释：
加 (2,4) 后最短路 0→1→2→4，长 3；
加 (0,2) 后最短路 0→2→4，长 2；
加 (0,4) 后最短路 0→4，长 1。
```

**示例 2**

```text
输入：n = 4, queries = [[0,3],[0,2]]
输出：[1,1]

解释：
加 (0,3) 后 0→3 直达，长 1；
再加 (0,2) 后仍走 0→3，长 1。
```

> ⚠️ 示例 2 的第二条查询值得注意：新边 $(0,2)$ 确实把 $\mathrm{dist}[2]$ 从 2 拉低到 1，但 $\mathrm{dist}[3]$ 走 $0 \to 3$ 直达仍是 1——**新边改变了中间点，却没改变终点答案**。

## 3. 解题思路

### 3.1 暴力思路：加一条边，重算一次最短路

框架是显然的：**加边 → 重算 $0 \to n-1$ 最短路 → 记录答案**。真正的问题是选哪个最短路工具：

| 工具 | 单次代价 | 总代价（$q \le 500$） | 判断 |
|------|----------|----------------------|------|
| Floyd | $O(n^3)$ | $\approx 6 \times 10^{10}$ | 超时，且全源纯属浪费 |
| Dijkstra（堆） | $O(m \log n)$ | $\approx 4.5 \times 10^6$ | 能过，但杀鸡用牛刀 |
| BFS | $O(n + m)$ | $O(q(n+q)) \approx 5 \times 10^5$ | 无权图标配，正确且够快 |

边权全为 1 的图求单源最短路，BFS 就是理论最优量级的工具——逐条查询重跑 BFS 在本题规模下**轻松通过**，是保底正解。

### 3.2 核心观察：编号即拓扑序，一趟递推就是最短路

![所有边都指向更大编号，编号即拓扑序](images/road_add_dag_concept.svg)

三个层层递进的观察：

- **观察一（图只增不减）**：查询只会加边、从不删边。边集可以**增量维护**——往 `into[v]` 里追加 $u$ 即可，不用每次重建图。
- **观察二（编号即拓扑序）**：链边 $i \to i+1$、新边 $u \to v$ 全部"向前"，所以序列 $0, 1, \dots, n-1$ 就是图的一个**拓扑序**——图是 DAG，而且**不用做拓扑排序**，编号天然有序。
- **观察三（DAG 正序递推）**：拓扑序上的单源最短路不需要队列、不需要 visited，一个 for 循环搞定：

$$\mathrm{dist}[i] = \min\big(\mathrm{dist}[i-1] + 1,\ \min_{u \in \mathrm{into}[i]} (\mathrm{dist}[u] + 1)\big)$$

其中 `into[i]` 存所有以 $i$ 为**终点**的新增边起点。计算 $\mathrm{dist}[i]$ 时，它的全部前驱（$i-1$ 与 `into[i]` 里的各个 $u$，编号都小于 $i$）已经定稿。

与 BFS 相比复杂度同阶（每条查询 $O(n+q)$），但代码更短、常数更小；而且这个递推**天然支持边权不为 1** 的推广——BFS 在带权图上直接失效。

### 3.3 算法流程

![算法流程图：登记新边、一趟递推、记录答案](images/road_add_dp_flow.svg)

1. 开一个长度为 $n$ 的数组 `into`（**按终点分桶**的邻接表）；
2. 对每条查询 $[u, v]$：`into[v].push(u)`；
3. $i$ 从 $1$ 到 $n-1$ **从左到右一趟递推**，原地写 `dist`；
4. `answer` 追加 `dist[n-1]`。

### 3.4 示例演算

![示例 1 的三阶段 dist 演算](images/road_add_walkthrough.svg)

以示例 1（$n = 5$）演算，绿色格子为相对上一阶段发生变化的位置：

| 阶段 | 新增道路 | dist[0..4] | answer |
|------|----------|------------|--------|
| 初始 | — | $[0,1,2,3,4]$ | — |
| 查询① | $(2,4)$ | $[0,1,2,3,\mathbf{3}]$ | **3** |
| 查询② | $(0,2)$ | $[0,1,\mathbf{1},\mathbf{2},\mathbf{2}]$ | **2** |
| 查询③ | $(0,4)$ | $[0,1,1,2,\mathbf{1}]$ | **1** |

两个值得盯的细节：

- **查询② 只加了一条 $(0,2)$，却把 $\mathrm{dist}[2..4]$ 全拉低了**——单点改动的收益会沿链向右传导。既然影响面难以局部圈定，干脆每次**完整重算一趟**，最省心也最难写错；
- $\mathrm{dist}[3]$ 与最终答案无关，它只是递推的中间产物——顺手算出来而已。

## 4. 算法细节

1. **按终点分桶存边**：转移要枚举"谁指向我"，所以 `into[v]` 存的是**终点为 $v$** 的边的起点列表。链边 $i-1 \to i$ 甚至不用存——递推式里的 $\mathrm{dist}[i-1] + 1$ 就是它。
2. **原地更新是安全的**：计算 $\mathrm{dist}[i]$ 时，其全部前驱（$i-1$ 与 `into[i]` 中的 $u$）编号都小于 $i$，在本趟中已经定稿，覆盖写不会读到陈旧值——这正是拓扑序送给我们的红利。
3. **每条查询完整重算**而非增量维护：新边的影响会向右连锁传导（见 3.4），本题规模下重算一趟 $O(n+q)$ 毫无压力；增量化留给加强版（见延伸思考）。
4. **`dist` 无需初始化为 $i$**：每趟都从 $\mathrm{dist}[0] = 0$ 开始完整递推，结果自洽（当然第 0 条查询前 $\mathrm{dist}[i] = i$ 恰好成立，可用于对拍）。
5. **同一终点挂多条边都要参与 $\min$**：`into[v]` 里可能积累多个不同起点的边，不能只保留"当前最优"的一条——各起点的 $\mathrm{dist}$ 会随后续加边变化。

## 5. 正确性证明

**引理 1（编号即拓扑序）**：任意时刻，图中所有有向边均由编号较小的城市指向编号较大的城市；因而 $0, 1, \dots, n-1$ 是图的一个拓扑序，图是 DAG。

**证明**：链边为 $i \to i+1$，满足 $i < i+1$；新增边由约束 $0 \le u < v < n$ 保证 $u < v$。两类边都"向前"，故结论成立。∎

**引理 2（一趟递推求出 DAG 单源最短路）**：设 $\mathrm{dist}[0] = 0$，按 $i$ 从 $1$ 到 $n-1$ 依次计算

$$\mathrm{dist}[i] = \min\big(\mathrm{dist}[i-1] + 1,\ \min_{u \in \mathrm{into}[i]} (\mathrm{dist}[u] + 1)\big),$$

则 $\mathrm{dist}[i]$ 等于 $0$ 到 $i$ 的最短路长度。

**证明**：对 $i$ 归纳。$i = 0$ 时显然。设结论对一切编号 $< i$ 的城市成立。注意 $i$ 在图中的**前驱集合**恰为 $\{i-1\} \cup \mathrm{into}[i]$（只有链边 $i-1 \to i$ 和若干新增边指向 $i$）。

- **下界**：任取一条 $0 \to i$ 的路径 $P$，设其倒数第二个点是 $p$，则 $p$ 是 $i$ 的前驱，且 $|P| = |P_{\text{前缀}}| + 1 \ge \mathrm{dist}[p] + 1 \ge \mathrm{dist}[i]$（递推式对所有前驱取了 $\min$，而归纳假设保证 $\mathrm{dist}[p]$ 是真实最短路长度）。
- **可达**：设递推式的最小值在 $p^\*$ 处取到。由归纳假设，存在一条长为 $\mathrm{dist}[p^\*]$ 的真实路径到达 $p^\*$；把边 $p^\* \to i$（链边或新增边，确实存在）接到其后，得到一条长为 $\mathrm{dist}[i]$ 的真实路径。

两个方向合起来，$\mathrm{dist}[i]$ 恰为最短路长度。∎

**定理**：算法对每条查询输出的 `answer[i]` 是"处理完前 $i+1$ 条查询后"$0 \to n-1$ 的最短路长度。

**证明**：处理第 $i$ 条查询时，算法先把边 $(u, v)$ 登记进 `into[v]`，此时图中边集恰为全部链边与前 $i+1$ 条查询边。由引理 1，编号仍是该图的拓扑序；随后按引理 2 的一趟递推重算 `dist`，输出 $\mathrm{dist}[n-1]$ 即为所求。∎

## 6. 复杂度分析

- **时间复杂度**：每条查询一趟递推，代价 $O(n + \text{当前新增边数})$；新增边总数不超过 $q$，故总计 $O\big(q\,(n+q)\big) \le 500 \times 1000 = 5 \times 10^5$。
- **空间复杂度**：$O(n + q)$——`into` 共存 $q$ 条新增边，`dist` 占 $O(n)$，`answer` 占 $O(q)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<int> shortestDistanceAfterQueries(int n, vector<vector<int>>& queries) {
        // into[v]：所有新增边 u -> v 的起点列表（按终点分桶）
        vector<vector<int>> into(n);
        vector<int> dist(n);
        vector<int> ans;
        ans.reserve(queries.size());

        for (const auto& q : queries) {
            into[q[1]].push_back(q[0]);      // 图只增不减，直接追加
            for (int i = 1; i < n; i++) {    // 编号即拓扑序，一趟从左到右
                int d = dist[i - 1] + 1;     // 链边 i-1 -> i
                for (int u : into[i])
                    d = min(d, dist[u] + 1); // 新增边 u -> i
                dist[i] = d;
            }
            ans.push_back(dist[n - 1]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def shortestDistanceAfterQueries(self, n: int, queries: List[List[int]]) -> List[int]:
        into = [[] for _ in range(n)]   # into[v]：指向 v 的新增边起点
        dist = [0] * n
        ans = []
        for u, v in queries:
            into[v].append(u)           # 图只增不减，直接追加
            for i in range(1, n):       # 编号即拓扑序，一趟从左到右
                d = dist[i - 1] + 1     # 链边 i-1 -> i
                for s in into[i]:
                    d = min(d, dist[s] + 1)
                dist[i] = d
            ans.append(dist[n - 1])
        return ans
```

## 8. 边界情况与易错点

1. **有向边的方向别搞反**：题目保证 $u < v$，建图必须 $u \to v$。若方向建反（或当成无向边），"编号即拓扑序"的前提被破坏，一趟递推会读到尚未更新的右侧值，直接出错。
2. **先加边、再求值**：`answer[i]` 对应"前 $i+1$ 条查询处理完"，顺序颠倒了会整体偏移一位。
3. **新边可能只改变中间量、不改变答案**（示例 2 第二条 $(0,2)$ 把 $\mathrm{dist}[2]$ 拉到 1，答案仍是 1）。判断"要不要重算"**不能只看 $\mathrm{dist}[n-1]$**；正确的跳过条件是 $\mathrm{dist}[u] + 1 \ge \mathrm{dist}[v]$——此时新边对任何城市的距离都无影响（对 $i$ 归纳即可证明），可直接沿用上次答案。
4. **同一终点挂多条边都要保留**：不同起点对同一终点的边会随图演化轮流成为"最优前驱"，只留一条会 WA。
5. **`into` 按终点分桶**，不是按起点。转移需要枚举"谁指向我"，按起点存的话内层就要扫全部 $q$ 条边，复杂度退化成 $O(nq)$ 每趟。
6. **最小规模与答案界**：$n$ 最小为 3；第一条查询就可能是 $(0, n-1)$ 直接给出答案 1。答案下界为 1（$0 \ne n-1$，至少走一条边）、上界为 $n-1$（链长），且随查询**单调不增**——这三个性质可用来对拍 sanity check。
7. **无溢出风险**：距离不超过 $n - 1 \le 499$，`int` 绰绰有余。

**延伸思考**：

- **剪枝**：当 $\mathrm{dist}[u] + 1 \ge \mathrm{dist}[v]$ 时跳过整趟重算，直接沿用上一次的 `dist[n-1]`（正确性见第 8 节第 3 条）。
- **增量化**：新边真正缩短 $\mathrm{dist}[v]$ 时，令 $\mathrm{dist}[v] = \mathrm{dist}[u] + 1$ 后只需从 $v$ 向右传播；由于距离只减不增且每次传播都要求"严格变小"，可用势能摊还分析或有序集合维护，做到近线性——这正是 II 的考法。
- **边权推广**：把递推式中的 $+1$ 换成 $+w_i$，正序递推对任意**非负边权**的 DAG 单源最短路依然成立，而 BFS 则彻底失效。
