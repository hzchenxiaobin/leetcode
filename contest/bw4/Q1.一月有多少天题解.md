# LeetCode 一月有多少天 题解

## 1. 题目概述

- **标题 / 题号**：一月有多少天（#1118，easy）
- **链接**：https://leetcode.cn/problems/number-of-days-in-a-month/
- **来源**：LeetCode 第 4 场双周赛 Q1
- **难度**：简单
- **标签**：数学

**题意**：给定一个年份 $Y$ 和一个月份 $M$，返回该月有多少天。整个问题唯一的考点是**闰年判定**——除了 2 月之外，每个月的天数是固定的，直接查表；而 2 月有 28 天还是 29 天，取决于 $Y$ 是不是**闰年**（leap year）。

**约束**：

- $1583 \le Y \le 2100$
- $1 \le M \le 12$

> 💡 下界 $1583$ 不是随手写的：1582 年 10 月罗马教皇格里高利十三世颁行**格里高利历**（公历），当年 10 月 4 日的次日直接是 10 月 15 日。此后闰年规则才固定为「四年一闰、百年不闰、四百年再闰」，所以题目把范围限定在规则生效之后，不需要处理历史上的特殊年份。

## 2. 示例

**示例 1**

```text
输入：Y = 1992, M = 7
输出：31
解释：7 月是大月，与闰平年无关，直接查表得 31 天。
```

**示例 2**

```text
输入：Y = 2000, M = 2
输出：29
解释：2000 能被 400 整除，是闰年（四百年再闰），2 月有 29 天。
```

**示例 3**

```text
输入：Y = 1900, M = 2
输出：28
解释：1900 能被 4 整除、也能被 100 整除，但不能被 400 整除，
     是平年（百年不闰），2 月只有 28 天。
```

三个示例恰好覆盖了闰年判定的三条分支：普通闰年（1992）、400 倍数的闰年（2000）、100 倍数但非 400 倍数的平年（1900）。出题人把最容易翻车的 $1900$ 放进了样例，算是仁慈的提醒。

## 3. 解题思路

### 3.1 暴力思路

如果完全不背「大小月」的规律，可以调用标准库（如 Python 的 `calendar.monthrange(Y, M)[1]`）一行拿到答案；C++ 标准库没有现成的公历接口，仍需自己实现。另一类「暴力」是写一大串 `if (month == 1) return 31; else if (month == 2) ...`——正确但冗长易错。本题数据范围极小，任何写法都能通过，但签到题的价值在于把**月天数表**与**闰年判定**沉淀成可复用的模板，后面做「一年中的第几天」（#1154）等日期题时直接搬。

### 3.2 核心观察：只有 2 月依赖年份，其余月份查表 O(1)

![核心观察：闰年判定流程——四年一闰、百年不闰、四百年再闰](images/bw4_q1_leap_year_flow.svg)

两个事实把问题压缩到 $O(1)$：

1. **月天数是常量表**：除 2 月外，各月天数固定为 $31,28,31,30,31,30,31,31,30,31,30,31$，用一个长度 13 的数组（下标 1–12，下标 0 填 0 占位）即可 $O(1)$ 查询；
2. **年份只影响 2 月**：闰年时 2 月从 28 天变成 29 天，判定只需三个取模：

$$\text{isLeap}(Y) = (Y \bmod 4 = 0 \wedge Y \bmod 100 \ne 0) \vee (Y \bmod 400 = 0)$$

即「**能被 4 整除且不能被 100 整除**，或者**能被 400 整除**」。按顺序检查：先看 $Y \bmod 4$，不整除直接平年；整除再看 $Y \bmod 100$，不整除是闰年；整除最后看 $Y \bmod 400$，整除才是闰年。流程图里三个菱形依次排除，$1900$ 在第二个菱形被拦下，$2000$ 一路通过第三个菱形。

> ⚠️ 顺序不能乱：必须**先判 4，再判 100，最后判 400**。若先判 $Y \bmod 400$ 再判 $Y \bmod 4$ 倒也无妨（逻辑等价），但若只写 `Y % 4 == 0` 一个条件，就会把 $1900、2100$ 错判成闰年——这是本题最经典的坑。

### 3.3 算法流程

![算法流程：十二个月的天数表与大小月口诀](images/bw4_q1_month_days_table.svg)

```text
1. 建表 days = [0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]
2. 若 M == 2 且 isLeap(Y)：返回 29
3. 否则返回 days[M]
```

其中 `isLeap(Y)` 为上节的三条件判定。查表 + 一次特判，没有任何循环。

大小月不用死记：口诀「一三五七八十腊，三十一天永不差；四六九冬三十日，唯有二月二十八」中「腊」是 12 月、「冬」是 11 月；也可以用**拳头记忆法**——拳峰是大月、指缝是小月，数到 7 月后折返再数 8 月，正好解释了 7、8 月是连续两个大月这个反直觉的事实。

### 3.4 示例演算

![示例演算：7 月查表得 31，2000/2 闰年得 29，1900/2 平年得 28](images/bw4_q1_example_walkthrough.svg)

| 输入 | isLeap 判定链 | 2 月特判? | 查表 | 输出 |
|------|--------------|-----------|------|------|
| $1992, 7$ | $1992 \bmod 4 = 0$，$\bmod 100 = 92 \ne 0$ → 闰 | 否（7 月） | days[7] = 31 | 31 |
| $2000, 2$ | $2000 \bmod 400 = 0$ → 闰 | 是 | 28 → 29 | 29 |
| $1900, 2$ | $\bmod 100 = 0$ 且 $\bmod 400 = 300 \ne 0$ → 平 | 否 | days[2] = 28 | 28 |

注意第一行：$1992$ 虽是闰年，但询问的是 7 月，闰年信息完全用不上——**先看月份再判闰年**能少做无用功，也让代码路径更清晰。

## 4. 算法细节

1. **表的构造**：`days` 数组长度取 13，下标 0 填 0 占位，让下标与月份 $1 \sim 12$ 直接对应，避免 `days[M-1]` 的错位心智负担。
2. **特判顺序**：先判 `month == 2` 再判闰年，用短路求值保证非 2 月时连三次取模都不做。
3. **isLeap 的写法**：`(y % 4 == 0 && y % 100 != 0) || (y % 400 == 0)`。两种逻辑等价的形式——三菱形顺序判定（3.2 流程图）或这一个布尔表达式——任选其一，后者更短，前者更好讲。
4. **数值范围**：$Y \le 2100$，`int` 完全够用，无溢出风险。
5. **为什么范围从 1583 开始**：见 1 节的注。若题目允许 $Y < 1583$，需按儒略历（每 4 年一闰、无百年规则）判定，本题不涉及。

## 5. 正确性证明

**引理 1（月天数表）**：在格里高利历中，除 2 月外每个月的天数与年份无关，且如 3.3 的 `days` 表所示。

**证明**：格里高利历的历法规则直接规定了各月长度：1、3、5、7、8、10、12 月为 31 天，4、6、9、11 月为 30 天，2 月平年 28 天、闰年 29 天。这些长度是历法定义的一部分，不随年份变化（1583–2100 范围内无规则修订）。∎

**引理 2（闰年判定）**：$Y$（$1583 \le Y \le 2100$）是闰年当且仅当 $(Y \bmod 4 = 0 \wedge Y \bmod 100 \ne 0) \vee (Y \bmod 400 = 0)$。

**证明**：由格里高利历规则，$Y$ 是闰年当且仅当「被 4 整除且不被 100 整除」或「被 400 整除」。（⇒）设 $Y$ 闰。规则只有两种触发情形，分别对应两个析取支。（⇐）若 $Y \bmod 4 \ne 0$，两种情形都不满足，$Y$ 是平年；若 $Y \bmod 4 = 0$ 且 $Y \bmod 100 \ne 0$，落入第一种情形，闰；若 $Y \bmod 100 = 0$，则是否闰完全取决于 $Y \bmod 400$ 是否为 0，与析取式一致。∎

**定理**：算法对任意合法输入 $(Y, M)$ 返回该月天数。

**证明**：若 $M \ne 2$，返回 `days[M]`，由引理 1 正确。若 $M = 2$：当 $Y$ 闰时由引理 1 返回 29 正确；当 $Y$ 平时返回 `days[2] = 28` 正确，其中闰平判定由引理 2 保证。∎

## 6. 复杂度分析

- **时间**：$O(1)$。最多三次取模加一次数组访问，与输入无关。
- **空间**：$O(1)$。月天数表是固定 13 个元素的常量表。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int numberOfDays(int year, int month) {
        static const int days[13] = {0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};
        if (month == 2 && isLeap(year)) return 29;   // 只有 2 月依赖年份
        return days[month];
    }
private:
    bool isLeap(int y) {
        // 四年一闰，百年不闰，四百年再闰
        return (y % 4 == 0 && y % 100 != 0) || (y % 400 == 0);
    }
};
```

### Python

```python
class Solution:
    def numberOfDays(self, year: int, month: int) -> int:
        days = (0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31)
        if month == 2 and ((year % 4 == 0 and year % 100 != 0) or year % 400 == 0):
            return 29
        return days[month]
```

> ⚠️ Python 里 `and` 优先级高于 `or`，但**括号仍然要写全**：`month == 2 and (year % 4 == 0 and year % 100 != 0) or year % 400 == 0` 这种省括号写法会被解析成 `(month == 2 and ...) or (year % 400 == 0)`，导致 $2000$ 年 7 月错误地返回 29。上面的参考代码把整个闰年判定包在一层括号里，杜绝此类事故。

## 8. 边界情况与易错点

1. **1900 / 2100 陷阱**：能被 100 整除但不能被 400 整除的年份是平年。只判 `Y % 4 == 0` 会在 $M = 2$ 时错答 29。
2. **2000 不能漏**：能被 400 整除的年份是闰年，写成「不被 100 整除才是闰」会错杀 $2000$。
3. **非 2 月不看年份**：$1992$ 年 7 月返回 31 而与闰年无关；把闰年判定放在月份判定之前不仅浪费，还容易在梳理逻辑时把自己绕晕。
4. **Python 运算符优先级**：`and`/`or` 混用必须把闰年判定整体加括号（见上文 ⚠️），这是本场双周赛真实的翻车点之一。
5. **表的下标对齐**：用长度 13 的表 + 0 号位占位，避免 `M - 1` 错位；若用字符串/切片实现，务必用 12 个值逐一核对。
6. **自检手段**：对任意年份把 12 个月的天数加起来，闰年应为 366、平年应为 365。验证脚本对 $2000 / 1900 / 1992 / 2100$ 四个年份跑过此项检查，全部吻合。

**延伸思考**：如果把判定条件抽象成「闰年当且仅当 $Y$ 被 $x$ 整除且不被 $y$ 整除，或被 $z$ 整除」，格里高利历取 $(x, y, z) = (4, 100, 400)$，平均年长 $\left(365 + \tfrac{1}{4} - \tfrac{1}{100} + \tfrac{1}{400}\right) = 365.2425$ 天，与回归年 365.2422 天每 3300 年才差 1 天——这正是「百年不闰、四百年再闰」在数学上的精妙之处。另有**儒略历**（只有四年一闰）与提议中的**世界历**，可作为历法计算的兴趣延伸。
