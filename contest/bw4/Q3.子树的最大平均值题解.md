# LeetCode 子树的最大平均值 题解

## 1. 题目概述

- **标题 / 题号**：子树的最大平均值（#1120，medium）
- **链接**：https://leetcode.cn/problems/maximum-average-subtree/
- **来源**：LeetCode 第 4 场双周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、二叉树

**题意**：给定一棵二叉树的根 `root`，找出**所有子树**中**平均值最大**的那个，返回该平均值。这里「子树」指**任意节点及其全部后代**构成的树（即以树中每个节点为根的完整子树），「平均值」= 子树权值和 ÷ 子树节点数。节点总数 $n$ 在 $1$ 到 $5000$ 之间，节点权值在 $0$ 到 $100000$ 之间，答案误差 $10^{-5}$ 内视为正确。

**约束**：

- $1 \le n \le 5000$
- $0 \le \text{val} \le 100000$
- 答案与正确值误差在 $10^{-5}$ 内即被接受

## 2. 示例

**示例 1**

```text
输入：root = [5,6,1]
输出：6.00000
解释：值 = 5 的节点：平均值 (5+6+1)/3 = 4；
     值 = 6 的节点：平均值 6/1 = 6；
     值 = 1 的节点：平均值 1/1 = 1。
     最大值是 6。
```

**示例 2**

```text
输入：root = [0,null,1]
输出：1.00000
解释：整棵树的平均值是 (0+1)/2 = 0.5；以 1 为根的单点子树平均值是 1，
     答案取 1。
```

两个示例共同说明一件事：**最优子树未必是整棵树，也未必在根附近**——节点 0 会把整棵树的平均值拉低，答案藏在一个叶子单点子树里。因此必须对**每个节点**都算一次以其为根的子树平均值，任何一个都不能漏。

## 3. 解题思路

### 3.1 暴力思路

对每个节点 $u$，单独遍历以 $u$ 为根的子树，累加权值和、数节点个数，得到平均值；所有节点取最大。设树高为 $h$，单次遍历 $O(\text{size}(u))$，总计最坏 $O(n \cdot h)$——链状树上是 $O(n^2) = 5000^2 = 2.5 \times 10^7$，其实也能过。但 $O(n^2)$ 的做法把同一批节点反复累加了几千遍，浪费明显：子树之间是**嵌套**的，儿子算过的和，父亲不该再算一遍。这是典型的「自底向上聚合」信号。

### 3.2 核心观察：后序 DFS 一趟同时返回 (sum, cnt)

![核心观察：后序 DFS 自底向上汇报 (sum, cnt)](images/bw4_q3_postorder_model.svg)

定义 $\mathrm{dfs}(u)$ 返回二元组 $(\mathrm{sum}_u, \mathrm{cnt}_u)$——以 $u$ 为根的子树权值和与节点数。**左右子树的信息足以 $O(1)$ 合成父亲的信息**：

$$\mathrm{sum}_u = \mathrm{sum}_l + \mathrm{sum}_r + \text{val}_u, \qquad \mathrm{cnt}_u = \mathrm{cnt}_l + \mathrm{cnt}_r + 1$$

这正是**后序遍历**的天然结构：先递归左右儿子拿到 $(s_l, c_l)$ 与 $(s_r, c_r)$，再合成自己的 $(\mathrm{sum}_u, \mathrm{cnt}_u)$，顺手用 $\mathrm{sum}_u / \mathrm{cnt}_u$ 更新全局最优 $\mathrm{best}$。递归到空节点返回 $(0, 0)$，合成公式依然成立。

这样每个节点**只被访问一次**，全部 $n$ 个子树的平均值都在「合并处」免费产出，时间从 $O(n^2)$ 降到 $O(n)$。「一次遍历同时维护多个聚合量并在回溯时合并」是树形 DP 的最小雏形，值得作为模板沉淀。

> 💡 与之对照的**错误优化**是只返回平均值——平均值**不可合并**：$(a_1+a_2)/(c_1+c_2) \ne (a_1/c_1 + a_2/c_2)/2$。必须携带**可加的量**（和与个数），平均只在叶子信息合成后局部计算。

### 3.3 算法流程

![算法流程：dfs(node) 的递归骨架](images/bw4_q3_algorithm_flow.svg)

```text
best = −∞
dfs(node):
    若 node 为空: 返回 (0, 0)
    (ls, lc) = dfs(node.left)       # 左子树汇报
    (rs, rc) = dfs(node.right)      # 右子树汇报
    sum = ls + rs + node.val        # 合并：可加量相加
    cnt = lc + rc + 1
    best = max(best, sum / cnt)     # 以 node 为根的子树平均值登场
    返回 (sum, cnt)
从 root 开始调用 dfs，返回 best
```

流程图里有两个值得强调的细节：`best` 是**全局变量**（由外层重置，不随递归传递，避免参数语义混乱）；空节点返回 $(0,0)$ 而不是 $(0, \infty)$ 之类的哨兵，使合并公式在**任意形态**（单侧孩子、叶子、满树）下都无需特判。

### 3.4 示例演算

![示例演算：两个官方示例的子树账本](images/bw4_q3_example_walkthrough.svg)

| 示例 | 节点 | 子树内容 | (sum, cnt) | 平均值 |
|------|------|---------|-----------|--------|
| 1 | 5（整棵） | {5,6,1} | (12, 3) | 4.0 |
| 1 | 6 ★ | {6} | (6, 1) | **6.0 ← best** |
| 1 | 1 | {1} | (1, 1) | 1.0 |
| 2 | 0（整棵） | {0,1} | (1, 2) | 0.5 |
| 2 | 1 ★ | {1} | (1, 1) | **1.0 ← best** |

后序顺序下，示例 1 的实际计算轨迹是：先到节点 6 得 $(6,1)$、更新 best 为 6；再到节点 1 得 $(1,1)$、best 不动；最后回到节点 5 合并 $(12,3)$、平均值 4 小于 best——答案 6.0 在**最早访问的那个叶子**处就已定格，根节点只是完成了信息汇总。

## 4. 算法细节

1. **返回值的类型**：C++ 用 `pair<long long,int>` 或结构体。虽然本题 $5000 \times 100000 = 5 \times 10^8 < 2^{31}-1 \approx 2.1 \times 10^9$，`int` 勉强安全，但边界只差 4 倍，换 `long long` 是零成本的保险（若 $n$ 或值域翻倍就溢出了）。
2. **best 的初值**：权值非负 ⇒ 任意平均值 $\ge 0$，初值取 $-1$ 即可；但取 $-10^{18}$ 这类极小哨兵更通用（权值若可为负也不出错）。C++ 里注意它必须是**成员变量并在入口重置**，LeetCode 会复用同一个 `Solution` 实例跑多个测试点，不重置会带上一个用例的残值。
3. **除法精度**：`sum / cnt` 用 `double`（53 位尾数 $\approx 9 \times 10^{15}$，远超 $5 \times 10^8$ 的整数和），商可被精确到误差 $< 2^{-53}$，远好于题目允许的 $10^{-5}$，无精度之忧。
4. **递归深度**：最坏链状 $n = 5000$ 层。C++ 默认栈深足够（每帧几十字节）；Python 默认递归上限 1000，**必须**在开头 `sys.setrecursionlimit(10000)` 之上（LeetCode 判题机对树题已放宽上限，本地测试则要手动调）。
5. **树的遍历方式不拘**：本题信息只依赖「孩子先于父亲」，后序递归最自然；迭代版可用显式栈做「先压父亲、弹二次结算」的后序模拟，或 Morris 遍历，但都会显著增加代码量，$n = 5000$ 下没有收益。

## 5. 正确性证明

**引理 1（合并公式）**：对任意节点 $u$，设其左右孩子为 $l, r$（可能为空，约定空子树 $\mathrm{sum} = 0, \mathrm{cnt} = 0$），则

$$\mathrm{sum}_u = \mathrm{sum}_l + \mathrm{sum}_r + \text{val}_u, \qquad \mathrm{cnt}_u = \mathrm{cnt}_l + \mathrm{cnt}_r + 1.$$

**证明**：以 $u$ 为根的子树的节点集等于 $u$ 自身、$l$ 子树节点集与 $r$ 子树节点集的不相交并（二叉树每个节点至多一个父亲，三部分两两无交且并起来恰为全部）。权值和与计数都是**集合可加函数**，在无交并上等于各部分之和；空孩子对应空集，贡献 $0$。∎

**引理 2（DFS 返回正确值）**：调用 $\mathrm{dfs}(u)$ 返回 $(\mathrm{sum}_u, \mathrm{cnt}_u)$。

**证明**：对子树大小归纳。大小 $0$（空节点）时返回约定的 $(0,0)$，成立。设结论对更小的子树成立：$\mathrm{dfs}(u)$ 先递归得到 $(\mathrm{sum}_l, \mathrm{cnt}_l)$ 与 $(\mathrm{sum}_r, \mathrm{cnt}_r)$（$l, r$ 子树均严格小于 $u$ 子树），再按合并公式计算并返回。由引理 1，返回值即 $(\mathrm{sum}_u, \mathrm{cnt}_u)$。∎

**引理 3（候选无遗漏）**：树中每个节点 $u$ 的子树平均值 $\mathrm{sum}_u/\mathrm{cnt}_u$ 都会在某次 `best = max(best, sum/cnt)` 中与 best 比较。

**证明**：$\mathrm{dfs}(u)$ 在合并出 $(\mathrm{sum}_u, \mathrm{cnt}_u)$ 后、返回前必执行一次该更新语句，用的是 $u$ 子树自身的和与个数（引理 2）。从 `root` 出发的递归会到达树中每个节点（每个节点都有唯一的父链连向 root），故每个节点都触发一次比较。∎

**定理**：算法返回 $\max_{u} \mathrm{sum}_u/\mathrm{cnt}_u$，即所有子树平均值中的最大值。

**证明**：由引理 3，best 的候选集合包含全部 $n$ 个子树平均值；又每次更新取 `max`，best 始终等于已比较过的候选中的最大值。初始 best $= -\infty$ 小于一切候选（平均值 $\ge 0 > -\infty$），且 $n \ge 1$ 保证至少一次比较。故最终 best 恰为全体子树平均值的最大值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个节点恰好进出递归各一次，每次 $O(1)$ 合并 + $O(1)$ 更新；相比暴力的 $O(n^2)$（链状）快了一个数量级——本题 $n=5000$ 时差距尚不明显，值域规模放大后是质变。
- **空间**：$O(h)$，$h$ 为树高，递归栈深度。满/完全二叉树 $h = O(\log n)$；最坏链状 $h = O(n)$。若用迭代后序可把栈显式化，最坏空间不变，仍 $O(h)$。

## 7. 参考代码

### C++

```cpp
class Solution {
    double best = -1e18;                      // 极小哨兵：权值可为 0，不能取 0 当初值
    // 返回 {子树权值和, 子树节点数}；long long 防临界溢出（5e8 距 2^31 仅 4 倍）
    pair<long long, int> dfs(TreeNode* node) {
        if (node == nullptr) return {0, 0};   // 空子树：合并公式的零元
        auto [ls, lc] = dfs(node->left);      // 后序：先拿左右子树的汇报
        auto [rs, rc] = dfs(node->right);
        long long sum = ls + rs + node->val;  // 可加量直接相加
        int cnt = lc + rc + 1;
        best = max(best, (double)sum / cnt);  // 以 node 为根的子树平均值
        return {sum, cnt};
    }
public:
    double maximumAverageSubtree(TreeNode* root) {
        best = -1e18;                         // 实例复用时重置全局状态
        dfs(root);
        return best;
    }
};
```

### Python

```python
import sys

class Solution:
    def maximumAverageSubtree(self, root: TreeNode) -> float:
        sys.setrecursionlimit(10000)          # 链状 5000 层，本地跑必须放宽
        self.best = float("-inf")

        def dfs(node):
            if node is None:
                return 0, 0                   # 空子树：(sum, cnt) = (0, 0)
            ls, lc = dfs(node.left)           # 后序：先递归左右
            rs, rc = dfs(node.right)
            s, c = ls + rs + node.val, lc + rc + 1
            self.best = max(self.best, s / c) # 合并处顺手更新答案
            return s, c

        dfs(root)
        return self.best
```

两份代码均在验证脚本中通过：官方两示例（6.00000 / 1.00000）、满二叉树 `[1,2,3,4,5,6,7]`（7.00000）、单节点 `[7]`（7.00000）、5000 节点全 100000 的链（100000.00000），并与 $O(n^2)$ 暴力在 200 棵随机树上逐一对拍全一致。

## 8. 边界情况与易错点

1. **单节点树**：答案就是该节点权值本身，$n \ge 1$ 保证了 dfs 至少结算一次，无需特判。
2. **best 初值**：不要写 `best = 0` 然后指望它被覆盖——权值全 0 时答案恰为 0，初值 0 碰巧也对，但权值若有负（变体题）就会错；极小哨兵 + 入口重置最稳。
3. **成员变量要重置**：LeetCode 复用 `Solution` 实例，`best` 若不在公共入口函数里重置，第二个测试点会带上第一个的答案。
4. **平均值不可合并**：递归若只传平均值，合并时要重新算加权平均且丢失权重信息——必须携带 (sum, cnt) 二元组，这是本题最核心的设计点。
5. **整数和的溢出边界**：$5000 \times 100000 = 5 \times 10^8$，`int` 未溢但仅 4 倍余量；C++ 用 `long long`、Python 天然大整数，均可高枕无忧。
6. **Python 递归深度**：链状 5000 层超过默认上限 1000，`setrecursionlimit(10000)` 必不可少（判题环境虽已放宽，自测时会在本地炸栈）。
7. **「子树」的语义**：本题的子树是「节点 + 全部后代」的完整子树，不含「任意连通片段」；若理解成后者，问题就变成了另一道更难的「最优连通块」题。
