# LeetCode 大于等于顺序前缀和的最小缺失整数 题解

## 1. 题目概述

- **标题 / 题号**：大于等于顺序前缀和的最小缺失整数（#2996，easy）
- **链接**：https://leetcode.cn/problems/smallest-missing-integer-greater-than-sequential-prefix-sum/
- **来源**：LeetCode 第 121 场双周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、排序

**题意**：给定整数数组 `nums`。若前缀 `nums[0..i]` 满足：对每个 $1 \le j \le i$ 都有 $\textit{nums}[j] = \textit{nums}[j-1] + 1$，则称它是**顺序前缀**（只含 `nums[0]` 的前缀也算顺序前缀）。设**最长**顺序前缀的元素之和为 $S$，求最小的整数 $x$，满足 $x \ge S$ 且 $x$ 没有在 `nums` 中出现过。

**约束**：

- $1 \le \textit{nums.length} \le 50$
- $1 \le \textit{nums}[i] \le 50$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,2,5]
输出：6
解释：最长顺序前缀是 [1,2,3]（下标 3 处的 2 ≠ 3+1，前缀到此为止），
      S = 1 + 2 + 3 = 6，6 不在 nums 中 → 答案 6。
```

**示例 2**

```text
输入：nums = [3,4,5,1,12,14,13]
输出：15
解释：最长顺序前缀是 [3,4,5]（1 ≠ 5+1），S = 12；
      12、13、14 都在 nums 里，15 不在 → 答案 15。
```

**示例 3（边界补充）**

```text
输入：nums = [1,2,3]
输出：6
解释：整个数组都是顺序前缀，S = 6，6 不在数组中 → 答案 6。
```

## 3. 解题思路

### 3.1 暴力思路

最容易写错的地方不是「找前缀」，而是「找缺失」。最直白的枚举是：让 $x$ 从 $1$ 开始逐个判断是否在 `nums` 中，直到找到第一个缺失值——但题目要求 $x \ge S$，从 $1$ 枚举既浪费又容易漏掉「$S$ 本身就在数组中」的情况。

把枚举起点改成 $S$：单次判定用 $O(n)$ 扫描，最多试 $n+1$ 个候选值，总复杂度 $O(n^2)$。$n \le 50$ 时约 $2500$ 次比较，当然是够的。真正值得保留的优化只有一步：**用哈希集合把单次判定降到 $O(1)$**，整题变成 $O(n)$。

### 3.2 核心观察：前缀只管「续接」，缺失只管「从 S 起往上试」

![最长顺序前缀的续接与断点，以及从前缀和起查找缺失整数](images/bw121_q1_prefix_scan.svg)

两件事彼此独立：

1. **最长顺序前缀唯一**：它必须从下标 $0$ 开始，逐项满足步长为 $1$。一旦某个位置断开，任何更长的前缀都会包含这个断点，因此都不合法——所以「扫描到第一个断点就停」得到的就是最长顺序前缀，不需要比较所有前缀（对比 LIS 那类需要 DP 的问题，这里简单得多）。
2. **缺失值只需从 $S$ 起往上试**：定义要求 $x \ge S$，比 $S$ 小的数一律不合法，根本没有枚举的必要。

为什么往上试不会无限试下去？区间 $[S,\,S+n]$ 一共 $n+1$ 个整数，而 `nums` 只有 $n$ 个元素，即使全部互不相同也只能覆盖其中 $n$ 个，**至少有一个落在区间里的整数不在 `nums` 中**。所以循环最多迭代 $n+1$ 次必然停下。

> 💡 一句话概括：**前缀用「续接」定下来，答案用「从 S 起的最小缺失」定下来，两趟线性扫描即可**。

### 3.3 算法流程

![算法流程：续接前缀求和，再用哈希集合逐个试缺失](images/bw121_q1_algorithm_flow.svg)

```text
1. S = nums[0]，i = 1
2. while i < n 且 nums[i] == nums[i-1] + 1:
       S += nums[i]，i += 1
3. 把 nums 全部放进哈希集合 seen
4. x = S
   while x 在 seen 中: x += 1
5. 返回 x
```

第 2 步结束时 $S$ 就是最长顺序前缀之和；第 4 步的循环次数上界为 $n+1$（见 §5 引理 2）。

### 3.4 示例演算

![示例 2 演算：前缀和为 12，12、13、14 都在数组中，15 缺失](images/bw121_q1_walkthrough.svg)

以示例 2（`nums = [3,4,5,1,12,14,13]`）为例：

| 步骤 | 说明 | 结果 |
|------|------|------|
| 续接 | $4 = 3+1$ ✓，$5 = 4+1$ ✓，$1 \ne 5+1$ ✗ 停 | 顺序前缀 `[3,4,5]` |
| 求和 | $3+4+5$ | $S = 12$ |
| 试缺失 | $12 \in \textit{nums}$ ✓ → 试 13 | 13 ∈ nums |
| 试缺失 | $13 \in \textit{nums}$ ✓ → 试 14 | 14 ∈ nums |
| 试缺失 | $14 \in \textit{nums}$ ✓ → 试 15 | $15 \notin \textit{nums}$ → 返回 15 |

注意 12 既是前缀和、又是数组元素，这正是本题最容易踩的坑：**不能直接返回 $S$**。

## 4. 算法细节

1. **续接条件写 `+ 1`**：`nums[i] == nums[i-1] + 1`。写成 `nums[i] > nums[i-1]` 会退化成「递增前缀」，`[1,3,5]` 这种步长不为 $1$ 的会被误当成顺序前缀；写成 `nums[i] >= nums[i-1]` 则连相等的 `[1,1,2]` 也放行。两种写法都错。
2. **前缀必须从下标 0 起**：`[3,4,5,1,12,14,13]` 里尾部的 `12,14,13` 虽然局部递增，但不是前缀，不参与计算。
3. **求和范围**：$n \le 50$、$\textit{nums}[i] \le 50$，最长顺序前缀若为 $1,2,\dots,50$，和为 $1275$，`int` 绰绰有余。但「前缀和可达 $O(n \cdot \max \textit{nums})$」这个量级意识要保留——若 $n$ 放大到 $10^5$、值域放大到 $10^9$，就必须换 `long long`。
4. **哈希集合 vs 排序**：题目标签里给了「排序」，排序后从 $S$ 起双指针扫描也是 $O(n\log n)$ 的正确做法；但集合写法更短、更快，且不需要破坏原数组顺序（续接阶段要先扫一遍前缀）。
5. **循环上界**：`while x in seen: x += 1` 不需要额外计数，最多 $n+1$ 次必然退出（§5 引理 2）。
6. **重复元素无副作用**：集合天然去重，`nums` 里有重复值不影响判断。

## 5. 正确性证明

**引理 1（最长顺序前缀唯一且由「扫到第一个断点」给出）**：设
$$k = \max\{\,i \ge 0 : \forall j \in [1, i],\ \textit{nums}[j] = \textit{nums}[j-1] + 1\,\},$$
则 $k$ 唯一存在，且 `nums[0..k]` 就是最长顺序前缀。

**证明**：由定义，$i = 0$ 永远合法，故集合非空，$k$ 存在且唯一（有限集合的最大值）。若 $i = k$ 合法而 $i = k+1$ 不合法，则 $\textit{nums}[k+1] \ne \textit{nums}[k] + 1$。对任意 $i' > k$，前缀 `nums[0..i']` 同样要满足 $j = k+1$ 处的条件，故也不合法。因此满足条件的下标集合恰为 $\{0, 1, \dots, k\}$，$k$ 即最长长度。算法在第一个断点处停止，返回的正是 $k$。∎

**引理 2（答案不超过 $S + n$）**：记 $x^* = \min\{v \ge S : v \notin \textit{nums}\}$，则 $x^* \le S + n$，从而第 4 步循环至多迭代 $n+1$ 次。

**证明**：区间 $[S, S+n]$ 含 $n+1$ 个互不相同的整数；`nums` 至多提供 $n$ 个不同的值，故区间内至少有一个整数不属于 `nums`。该整数 $\ge S$，满足可行条件，于是 $x^* \le S+n$。算法从 $S$ 起严格递增地检查，检查到 $x^*$ 时必然命中并退出，检查过的候选值个数不超过 $n+1$。∎

**定理**：算法返回 $x^*$。

**证明**：算法第 2 步得到的 $S$ 是引理 1 意义下的最长顺序前缀和，与题面定义一致。第 4 步从 $S$ 开始，按 $S, S+1, S+2, \dots$ 的顺序检查，遇到第一个不在 `nums` 中的数就返回——这恰好是集合 $\{v \ge S : v \notin \textit{nums}\}$ 的最小元，即 $x^*$。由引理 2，循环必然终止，返回值存在。∎

## 6. 复杂度分析

- **时间**：$O(n)$。续接前缀一趟 $O(n)$；建集合 $O(n)$；试缺失至多 $n+1$ 次、每次 $O(1)$ 的期望（哈希表），合计 $O(n)$。
- **空间**：$O(n)$，哈希集合存放至多 $n$ 个不同值。（若改用排序，则时间升到 $O(n\log n)$，额外空间取决于排序实现，为 $O(1)$～$O(n)$。）

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int missingInteger(vector<int>& nums) {
        int n = (int)nums.size();
        int sum = nums[0];
        int i = 1;
        while (i < n && nums[i] == nums[i - 1] + 1) {   // 续接最长顺序前缀
            sum += nums[i];
            ++i;
        }
        unordered_set<int> seen(nums.begin(), nums.end());
        int x = sum;
        while (seen.count(x)) ++x;                      // 从前缀和起找最小缺失整数
        return x;
    }
};
```

### Python

```python
class Solution:
    def missingInteger(self, nums: list[int]) -> int:
        n = len(nums)
        total = nums[0]
        i = 1
        while i < n and nums[i] == nums[i - 1] + 1:   # 续接最长顺序前缀
            total += nums[i]
            i += 1
        seen = set(nums)
        x = total
        while x in seen:                              # 从前缀和起找最小缺失整数
            x += 1
        return x
```

> 💡 两份代码均通过官方示例（`6`、`15`）与补充边界（`[1]` → `2`、`[1,2,3]` → `6`、`[2,1]` → `3`），并与 $O(n^2)$ 的朴素枚举（从 1 开始逐个判定）在 2 万组随机数组上对拍（值域 $[1,50]$、长度 $[1,50]$，含大量重复与整体递增情形），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：`nums = [1]` 时顺序前缀只有 `[1]`，$S = 1$，而 $1$ 在数组中，答案为 $2$。循环不能写成「前缀非空就返回 $S$」。
2. **答案可能大于 $S$**：示例 2 中 $S = 12$ 却被数组包含，必须继续往上试。这是本题最主要的失分点。
3. **前缀可能只有第一个元素**：`[2,1]` 的顺序前缀只有 `[2]`（$1 \ne 3$），$S = 2$，$2$ 在数组中，答案 $3$。别把 `1` 也加进去。
4. **顺序前缀 ≠ 递增前缀**：必须是**逐项恰加 1**。`[1,3,4]` 的最长顺序前缀是 `[1]`，不是 `[1,3,4]`。
5. **前缀必须从下标 0 开始**：数组后段即使出现连续的 `k, k+1, k+2` 也无关。
6. **重复值**：`[1,1,2,3]` 的顺序前缀只有 `[1]`（$1 \ne 2$，续接要求恰好加 $1$），$S = 1$；而 $1, 2, 3$ 都出现在数组中，于是一路试到 $4$ 才停，答案是 $4$。
7. **值域下界**：$\textit{nums}[i] \ge 1$，所以缺失值不可能是 $0$，无需从 $0$ 试起；但若题目改成允许 $0$，只要把循环起点仍固定在 $S$（$S \ge 0$）逻辑不变。
8. **数据规模换档**：若把 $n$ 放大到 $10^5$，$O(n^2)$ 的朴素判定会超时，必须用集合；若值域也放大，$S$ 可能溢出 `int`，需 `long long`。
