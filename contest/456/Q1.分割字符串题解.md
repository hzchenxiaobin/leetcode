# LeetCode 分割字符串 题解

## 1. 题目概述

- **标题 / 题号**：分割字符串（#3597，medium）
- **链接**：https://leetcode.cn/problems/partition-string/
- **来源**：LeetCode 第 456 场周赛 Q1
- **难度**：中等
- **标签**：哈希表、字符串、模拟、字典树

**题意**：给定字符串 $s$，按如下过程把它切分成若干**互不相同**的段：从下标 0 开始构建当前段；逐字符向右扩展，一旦当前段**之前未曾出现过**（与已切出的段都不同），就立即将它切出、标记为已出现，并从下一下标开始构建新段。扫描结束后返回切出的段数组 `segments`。注意：若扫到串尾当前段仍是重复段（始终没能变得唯一），它**不会**出现在结果中。

**约束**：

- $1 \le s.length \le 10^5$
- `s` 仅包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "abbccccd"
输出：["a","b","bc","c","cc","d"]
解释：下标 2 处 "b" 与已切出的 "b" 重复，吸收 c 变成 "bc" 后首次唯一，切分；
     下标 5 处 "c" 重复，吸收 c 变成 "cc" 后首次唯一，切分。
```

**示例 2**

```text
输入：s = "aaaa"
输出：["a","aa"]
解释：下标 3 起的 "a" 直到扫描结束仍是重复段（残留），不进结果。
```

**示例 3（自拟，覆盖跨字符扩展）**

```text
输入：s = "abab"
输出：["a","b","ab"]
解释："a"、"b" 直接切出；下标 2 起 "a" 重复，吸收 b 得 "ab" 首次唯一，切出；
     三个段恰好覆盖整个字符串。
```

## 3. 解题思路

### 3.1 暴力思路

题目把切分过程**一步一步定义死了**：每一步只有一个分叉——「当前段是否之前出现过」。因此不存在「选哪种切法」的搜索空间，**照题意模拟就是正解**。

唯一要选的是「已出现段」用什么数据结构存：

- 用数组/列表存，每次 `cur in list` 都要线性扫已切出的段并逐个比较字符串，单次代价 $O(k \cdot L)$（$k$ 为段数、$L$ 为段长），总量没有好上界，可能退化到平方级以上；
- 用**哈希集合**存，每次查询只需 $O(|cur|)$ 哈希整段字符串——这是本题的标准做法。

### 3.2 核心观察：首次唯一即落刀

![核心观察概念图](images/partition_string_greedy_concept.svg)

维护当前段 `cur` 与已出现集合 `seen`，从左到右单趟扫描：

- 每读一个字符就 `cur += c`，然后查询 `cur ∈ seen ?`；
- **是（重复）** → 不切分，`cur` 继续吸收下一个字符，段向右生长；
- **否（首次唯一）** → 立即落刀：加入答案、加入 `seen`、`cur` 清空；
- 扫描结束后，残留的 `cur`（若有）必是重复段，直接丢弃。

> 💡 这是「哈希字典 + 贪心切分」模板：**见新词落刀，见旧词续写**。与 [2405. 子字符串的最优划分](https://leetcode.cn/problems/optimal-partition-of-string/) 的贪心骨架同款，只是判重对象从「段内字符」换成了「整段字符串」。

### 3.3 算法流程

![模拟算法流程图](images/partition_string_flow.svg)

流程只有两个循环出口：字符读完（返回 `ans`）与当前段变唯一（切分后继续）。**末尾残留段为何能直接丢**：若它首次变唯一，早在那一刻就已被切分；走到串尾仍是重复段，按过程定义它不属于任何「创建的段」（示例 2 的 `"aaaa"` 正是如此）。

## 4. 算法细节

1. **数据结构**：`unordered_set<string>`（C++）/ `set`（Python）存已切出的段，查询与插入均摊 $O(|cur|)$。
2. **段的构建**：`cur` 增量拼接。C++ 的 `cur += c` 均摊 $O(1)$；Python 的 `cur += c` 为 $O(|cur|)$，但总量与哈希开销同级，不影响复杂度。也可只记起点 `start`，用切片 `s[start:i+1]` 判重，二者等价。
3. **残留段**：循环结束后 `cur` 非空则一定是重复段（若唯一早在变唯一的瞬间就切出了），**不要**把它补进答案——这是本题最典型的 WA 点。
4. **为什么不会超时**：段长有上界 $O(\sqrt n)$（引理 2），共 $n$ 次哈希查找、每次 $O(\sqrt n)$，总时间 $O(n\sqrt n)$。$n = 10^5$、全同字符最坏时约 $3 \times 10^7$ 字符级操作，轻松通过。
5. **想严格线性？** 把 `seen` 换成 **Trie**：把每个切出的段沿树插入并标记终点；扫描时 `cur` 逐字符沿树下行，若节点不存在或未标记终点 → 首次唯一。每字符 $O(1)$，总时间严格 $O(n)$，空间 $O(26n)$。本题哈希版已足够快。

## 5. 正确性证明

**引理 1（前缀封闭性）**：任一段 $w$ 的每个真前缀都是比 $w$ 更早切出的段。

**证明**：按过程定义，$w$ 从空串起逐字符扩展；对每个 $j < |w|$，长度为 $j$ 的前缀在扩展过程中曾被判定为「已出现过」，即它等于某个更早切出的段。∎

**引理 2（段长上界）**：若某段长度为 $L$，则 $\frac{L(L-1)}{2} \le n$，故 $L = O(\sqrt n)$。

**证明**：由引理 1，$w$ 的长度为 $1, 2, \dots, L-1$ 的前缀都是段，且长度互不相同因而两两不同；所有段是 $s$ 中**互不重叠**的子串，故 $\sum_{j=1}^{L-1} j \le n$。∎

**定理（模拟正确性）**：算法输出的段序列与题目定义过程产生的段序列完全一致。

**证明**：对已处理的下标数做归纳，维护不变量：**`seen` 恰等于过程已切出的段集合，`cur` 恰等于过程当前在建的段**。初始（处理下标 0 前）二者均为空，成立。设处理 $s[i]$ 前不变量成立：算法执行 `cur += s[i]` 与过程「扩展当前段」一致；随后两者都查询「当前段是否在已出现集合中」，由不变量该查询结果一致——若重复则双双继续扩展（不变量保持）；若唯一则双双切出该段、并入集合、另起新段（不变量保持）。归纳完成。循环终止时若 `cur` 非空，则最后一步查询结果为「重复」，即该段到串尾仍未唯一，按定义不属于任何创建的段，算法不输出它，与过程一致。∎

**推论**：输出的段两两不同（每段切出时都验证过不在 `seen` 中）。∎

## 6. 复杂度分析

- **时间复杂度**：最坏 $O(n\sqrt n)$。共 $n$ 次哈希查找（每字符一次），每次哈希/拼接代价 $O(|cur|)$，由引理 2 知 $|cur| = O(\sqrt n)$。最坏输入为全同一字符（$s = $ "aaa…a"），此时段长 $1, 2, 3, \dots$ 递增，$n = 10^5$ 时约 $3 \times 10^7$ 字符级操作；一般输入远快于此。
- **空间复杂度**：$O(n)$。`seen` 与答案中所有段互不重叠，总字符数不超过 $n$（不计哈希表常数开销）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<string> partitionString(string s) {
        vector<string> ans;
        unordered_set<string> seen;
        string cur;
        for (char c : s) {
            cur += c;
            if (!seen.count(cur)) {
                seen.insert(cur);
                ans.push_back(cur);
                cur.clear();
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def partitionString(self, s: str) -> List[str]:
        seen = set()
        ans = []
        cur = ""
        for c in s:
            cur += c
            if cur not in seen:
                ans.append(cur)
                seen.add(cur)
                cur = ""
        return ans
```

## 8. 边界情况与易错点

1. **残留段不要输出**：`s = "aaaa"` 末尾的 `"a"` 是重复段，答案为 `["a","aa"]` 而非补上它。循环后直接 `return ans`，绝不追加 `cur`。
2. **重复 ≠ 重置**：`cur` 重复时是**继续扩展**（保留已有字符、吸收下一个字符），不是清空重来。清空会导致死循环或答案错误。
3. **`seen` 必须用哈希集合**：用 `list` 判重是线性扫描，最坏退化到平方级以上；哈希集合把单次判重降到 $O(|cur|)$。
4. **输出的是段字符串本身**，不是下标区间或长度。
5. **性能错觉**：看似「每步哈希整段、单段最长 $O(n)$」会到 $O(n^2)$，实际上引理 2 保证段长 $O(\sqrt n)$，无需担心；若追求严格线性可换 Trie。
6. **C++ 细节**：`unordered_set<string>` 的 `count/insert` 会对字符串做哈希与拷贝，但插入总字符量 $\le n$，可放心使用；`cur.clear()` 保留已分配容量，后续 `+=` 均摊 $O(1)$。
