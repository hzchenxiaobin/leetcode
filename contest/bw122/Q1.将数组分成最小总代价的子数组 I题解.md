# LeetCode 将数组分成最小总代价的子数组 I 题解

## 1. 题目概述

- **标题 / 题号**：将数组分成最小总代价的子数组 I（#3010，easy）
- **链接**：https://leetcode.cn/problems/divide-an-array-into-subarrays-with-minimum-cost-i/
- **来源**：LeetCode 第 122 场双周赛 Q1
- **难度**：简单
- **标签**：数组、枚举、排序

**题意**：数组的**代价**定义为它的**第一个元素**。给定长度为 $n$ 的整数数组 `nums`，要求把它分成 **3 个连续、互不相交、非空**的子数组，求三个子数组代价之和的最小值。

**约束**：

- $3 \le \textit{nums.length} \le 50$
- $1 \le \textit{nums}[i] \le 50$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,12]
输出：6
解释：最优切法是 [1]、[2]、[3,12]，代价 1 + 2 + 3 = 6。
      其他切法：[1]、[2,3]、[12] → 15；[1,2]、[3]、[12] → 16。
```

**示例 2**

```text
输入：nums = [5,4,3]
输出：12
解释：只有一种切法 [5]、[4]、[3]，代价 5 + 4 + 3 = 12。
```

**示例 3**

```text
输入：nums = [10,3,1,1]
输出：12
解释：最优切法是 [10,3]、[1]、[1]，代价 10 + 1 + 1 = 12。
```

## 3. 解题思路

### 3.1 暴力思路

「分成 3 段」等价于「选 2 个切点」，切点组合数只有 $\binom{n-1}{2} < 1225$（$n \le 50$）。直接双重循环枚举两个切点、每次 $O(1)$ 算出总代价，总复杂度 $O(n^2)$——这已经是本题的合格解法，也是 $n$ 变大之前最稳的写法。

不过只要把「代价」拆开看，就会发现枚举是多余的：**三个代价里有两个其实可以自由挑**，答案能直接写出来。

### 3.2 核心观察：`nums[0]` 必付，另两段各挑一个下标

![三段的代价只取决于段首元素，nums[0] 固定，另两个可任选](images/bw122_q1_cut_model.svg)

设切分为 `nums[0..i₁-1]`、`nums[i₁..i₂-1]`、`nums[i₂..n-1]`，其中 $1 \le i_1 < i_2 \le n-1$。三段的首元素分别是

$$\textit{nums}[0],\quad \textit{nums}[i_1],\quad \textit{nums}[i_2],$$

于是

$$\text{总代价} = \textit{nums}[0] + \textit{nums}[i_1] + \textit{nums}[i_2].$$

三点观察：

1. **`nums[0]` 是常数**：第一段必然从下标 $0$ 开始，它的代价无法优化，直接加上即可。
2. **$i_1, i_2$ 只要不同即可**：题面只要求 $i_1 < i_2$，而这只是一种**命名约定**——任取两个不同的下标 $a, b \in [1, n-1]$，令 $i_1 = \min(a,b)$、$i_2 = \max(a,b)$，就得到一个合法切分。所以「可选的下标对」其实就是「`nums[1..n-1]` 中任取两个不同位置」。
3. **因此最优解 = `nums[0]` 加上 `nums[1..n-1]` 中最小的两个元素**。

$$\text{答案} = \textit{nums}[0] + \min_1 + \min_2,$$

其中 $\min_1, \min_2$ 是 `nums[1..n-1]` 的**两个最小元素**（按下标取，重复值算两个不同位置）。

> 💡 一句话：**第一段代价白送，后两段各挑一个「最便宜」的位置当段首，一趟扫描维护两个最小值即可**。

### 3.3 算法流程

两条路线都对，按数据规模选：

```text
【写法 A：一趟扫描，O(n)】—— 推荐
1. m1 = m2 = +∞
2. for i = 1 .. n-1:
       if nums[i] < m1:  m2 = m1, m1 = nums[i]
       elif nums[i] < m2: m2 = nums[i]
3. 返回 nums[0] + m1 + m2
```

```text
【写法 B：枚举切点，O(n²)】—— 最直观，可作对拍基准
1. ans = +∞
2. for i = 1 .. n-2:
       for j = i+1 .. n-1:
           ans = min(ans, nums[0] + nums[i] + nums[j])
3. 返回 ans
```

写法 A 的维护逻辑与「找数组第二大」相同：新元素比当前最小还小，就把原最小顺延成第二小；否则只需与第二小比较。

### 3.4 示例演算

![示例 3 演算：三组下标对的总代价](images/bw122_q1_walkthrough.svg)

以示例 3（`nums = [10,3,1,1]`）为例，固定项 `nums[0] = 10`，可选下标为 $\{1,2,3\}$（值分别为 $3,1,1$），三组下标对：

| $(i_1, i_2)$ | 三段 | 总代价 |
|--------------|------|--------|
| $(1,2)$ | `[10]`、`[3]`、`[1,1]` | $10+3+1 = 14$ |
| $(1,3)$ | `[10]`、`[3,1]`、`[1]` | $10+3+1 = 14$ |
| $(2,3)$ | `[10,3]`、`[1]`、`[1]` | $10+1+1 = \mathbf{12}$ |

最小值 $12$，对应「取 `nums[1..3] = [3,1,1]` 中最小的两个 $1,1$」，与写法 A 的结论一致。

再看示例 1（`nums = [1,2,3,12]`）：`nums[1..3] = [2,3,12]` 中最小两个是 $2,3$，答案 $1+2+3=6$ ✓。

## 4. 算法细节

1. **只扫 `nums[1..]`**：`nums[0]` 不能参与「挑最小的两个」——它已经作为第一段段首被计费，再选一次就重复了。
2. **两个最小值的初始化**：`m1 = m2 = +∞`，然后一趟更新。$n \ge 3$ 保证 `nums[1..]` 至少 2 个元素，两个最小值一定存在。
3. **重复值要算两次**：`[3,1,1]` 的两个最小值是 $1,1$（不同下标），`m1/m2` 的写法天然支持。
4. **比较符用严格小于**：`if v < m1` / `elif v < m2`。若写成 `<=`，相等时会把同一个位置「当成两个」吗？不会（因为每个 $v$ 只进入一个分支一次），但语义上容易看错，保持严格小于更清晰。
5. **返回类型**：$n$ 小、值小，`int` 足够；若把值域放大到 $10^9$、$k$ 放大到 $10^5$，就要 `long long` 并改用堆（见同场 Q4）。
6. **与 Q4 的关系**：本题是 Q4 在 $k = 3$ 时的特例，且没有 `dist` 约束；Q4 需要「滑动窗口内取最小的 $k-2$ 个之和」，是本题的多路推广。

## 5. 正确性证明

**引理 1（切分与下标对双射）**：`nums` 分成 3 个连续非空子数组的方案，与满足 $1 \le i_1 < i_2 \le n-1$ 的下标对 $(i_1, i_2)$ 一一对应。

**证明**：给定切分，第二段的首下标记为 $i_1$、第三段的首下标记为 $i_2$，由「三段非空且连续」得 $1 \le i_1 < i_2 \le n-1$。反之给定这样的 $(i_1, i_2)$，三段 `nums[0..i₁-1]`、`nums[i₁..i₂-1]`、`nums[i₂..n-1]` 都非空（分别至少有 $i_1 \ge 1$、$i_2 - i_1 \ge 1$、$n - i_2 \ge 1$ 个元素），且覆盖整个数组、互不相交，是一个合法切分。两个方向的映射互为逆，故为双射。∎

**引理 2（代价分解）**：任一合法切分的总代价等于 $\textit{nums}[0] + \textit{nums}[i_1] + \textit{nums}[i_2]$。

**证明**：三段的第一个元素下标分别是 $0$、$i_1$、$i_2$（见引理 1 的构造），按代价定义相加即得。∎

**引理 3（最优下标对就是两个最小值）**：设 `nums[1..n-1]` 中两个最小的元素（按多重集计，取不同位置）为 $a \le b$，则对任意 $1 \le i_1 < i_2 \le n-1$ 有 $\textit{nums}[i_1] + \textit{nums}[i_2] \ge a + b$。

**证明**：从 `nums[1..n-1]` 中取任意两个不同位置，其值构成一个二元多重集 $\{u, v\}$。由于 $a, b$ 是该数组中最小的两个元素，把 $\{u,v\}$ 排序为 $u' \le v'$，则 $u' \ge a$（$a$ 是最小元素）且 $v' \ge b$（去掉一个 $\ge a$ 的元素后，$b$ 仍是剩余元素中的最小值，故 $v' \ge b$）。两式相加即得。∎

**定理**：算法返回最小总代价。

**证明**：由引理 2，最小总代价 $= \textit{nums}[0] + \min_{i_1<i_2}\big(\textit{nums}[i_1] + \textit{nums}[i_2]\big)$。由引理 3，内层最小值恰为 $a + b$；又因为可以取到这两个位置（它们下标不同，排序后即得合法 $(i_1,i_2)$，由引理 1 对应一个合法切分），该下界可达。算法正是计算 $\textit{nums}[0] + a + b$，故返回值就是最小总代价。∎

## 6. 复杂度分析

- **时间**：写法 A 为 $O(n)$，一趟扫描维护两个最小值；写法 B 为 $O(n^2)$，枚举 $\binom{n-1}{2}$ 个下标对。$n \le 50$ 时两者都在万次运算以内。
- **空间**：$O(1)$，只用了常数个变量（写法 B 也不需要额外空间）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumCost(vector<int>& nums) {
        // 另两段的首元素可取 nums[1:] 中任意两个不同下标，故取最小的两个
        int m1 = INT_MAX, m2 = INT_MAX;
        for (int i = 1; i < (int)nums.size(); ++i) {
            if (nums[i] < m1) {
                m2 = m1;
                m1 = nums[i];
            } else if (nums[i] < m2) {
                m2 = nums[i];
            }
        }
        return nums[0] + m1 + m2;
    }
};
```

### Python

```python
class Solution:
    def minimumCost(self, nums: list[int]) -> int:
        # 另两段的首元素可取 nums[1:] 中任意两个不同下标，故取最小的两个
        m1 = m2 = float("inf")
        for v in nums[1:]:
            if v < m1:
                m1, m2 = v, m1
            elif v < m2:
                m2 = v
        return nums[0] + m1 + m2
```

> 💡 两份代码均通过官方示例（`6`、`12`、`12`）与边界（$n = 3$ 的 `[7,7,7]` → `21`），并与 $O(n^2)$ 枚举全部下标对的暴力在 2 万组随机数组上对拍（长度 $[3,50]$、值域 $[1,50]$，含大量重复值），`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 3$**：只有一种切分，答案是 `nums[0] + nums[1] + nums[2]`。两个最小值就是 `nums[1]`、`nums[2]`，写法 A 自然正确。
2. **不要把 `nums[0]` 算进「两个最小值」**：它已经作为第一段代价计过一次。这是本题最容易犯的错，尤其在 `nums[0]` 恰好是全数组最小值时（如示例 1）会少算。
3. **下标必须不同**：`[10,3,1,1]` 的两个最小值是下标 2、3 的 `1,1`，不能把同一个位置用两次。`m1/m2` 的一趟扫描天然保证取的是两个不同位置。
4. **重复值**：`[5,4,3]` 中 `nums[1..]` 是 `[4,3]`，直接返回 $5+4+3=12$；重复值同理，不需要去重。
5. **子数组必须非空**：切点 $i_1 \ge 1$ 与 $i_2 \le n-1$ 正是「三段都非空」的体现。若允许空段，$i_2$ 可以取到 $n$，答案会变小，那是另一个问题。
6. **返回类型**：本题 `int` 足够（$\le 3 \times 50 = 150$）；同场 Q4 中 $k$ 与值域都放大，必须 `long long`，直接从本题照搬会溢出。
7. **切分顺序无所谓**：$i_1 < i_2$ 只是命名，任选两个位置都能排出这个顺序，不要因为「必须先小后大」而漏掉某些组合。
