# LeetCode 通过操作使数组长度最小 题解

## 1. 题目概述

- **标题 / 题号**：通过操作使数组长度最小（#3012，medium）
- **链接**：https://leetcode.cn/problems/minimize-length-of-array-using-operations/
- **来源**：LeetCode 第 122 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、数学、数论

**题意**：给定只含正整数的数组 `nums`。一次操作：

1. 选择两个不同下标 $i \ne j$，满足 $\textit{nums}[i] > 0$ 且 $\textit{nums}[j] > 0$；
2. 把 $\textit{nums}[i] \bmod \textit{nums}[j]$ 追加到数组末尾；
3. 删除下标 $i$ 与 $j$ 处的两个元素。

可以执行任意次（含 $0$ 次）操作，求操作后数组可能达到的**最小长度**。

**约束**：

- $1 \le \textit{nums.length} \le 10^5$
- $1 \le \textit{nums}[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums = [1,4,3,1]
输出：1
解释：最小值为 1 且出现 2 次，⌈2/2⌉ = 1，可以缩到只剩一个元素。
```

**示例 2**

```text
输入：nums = [5,5,5,10,5]
输出：2
解释：最小值为 5 且出现 4 次，⌈4/2⌉ = 2。
      一种过程：[5,5,5,10,5] →(5 % 10 = 5) [5,5,5,5] →(5 % 5 = 0) [5,5,0] →(5 % 5 = 0) [0,0]。
```

**示例 3**

```text
输入：nums = [2,3,4]
输出：1
解释：3 % 2 = 1 造出了新的最小值 1（且只出现一次），之后可以一路缩到 1 个元素。
```

**示例 4（补充）**

```text
输入：nums = [3,3]
输出：1
解释：3 % 3 = 0，删掉两个 3、插入 0，数组变成 [0]，长度 1。
```

## 3. 解题思路

### 3.1 暴力思路

「任意次操作、求最小长度」看起来像搜索题，但状态是多重集、每步有 $O(n^2)$ 种选法，状态空间爆炸，直接 BFS 只能处理 $n \le 5$ 的小数据（实际上它确实是绝佳的对拍工具）。必须先把操作的效果抽象出来。

### 3.2 核心观察：长度每步恰好减一，问题等价于「能操作多少次」

![三种情形：答案只可能是 1 或 ⌈cnt/2⌉](images/bw122_q3_cases.svg)

先看长度的变化：每次操作删除 **2** 个元素、插入 **1** 个元素，

$$L \;\longleftarrow\; L - 2 + 1 = L - 1 .$$

所以 **最小化长度 ⟺ 最大化操作次数**，而且长度永远不会降到 $0$（只剩 1 个元素时没有两个正数可选）。于是目标就是「把这个数组尽可能多消几轮」。

设

$$mn = \min(\textit{nums}), \qquad cnt = \#\{i : \textit{nums}[i] = mn\}.$$

关键在于两件事：**取模会造出什么样的新数**，以及 **$mn$ 这个「最小原料」会被消耗多快**。

- **取模的结果必小于除数**：$a \bmod b < b$。所以若拿一个**不是** $mn$ 倍数的 $v$ 去除 $mn$，会得到 $r = v \bmod mn \in (0, mn)$——一个严格更小的数。
- **$mn$ 与自己取模必然得 $0$**：$mn \bmod mn = 0$，而 $0$ 不满足「$>0$」，从此无法再参与操作，等于「报废」。

由此分出三种情形：

**情形 A：存在某个 $v$ 使 $v \bmod mn \ne 0$。** 执行一次 $(v, mn)$，得到新元素 $r = v \bmod mn$，它满足 $0 < r < mn$。此时 $r$ 成了数组里**严格且唯一**的最小值（其它元素都 $\ge mn > r$）。

**情形 B：$mn$ 只出现一次。** 任取另一个元素 $y > mn$，执行 $(mn, y)$：由于 $mn < y$，有 $mn \bmod y = mn$，于是「删掉 $y$、留下 $mn$」——$mn$ 一个不少，其它元素少一个。如此重复，其它元素被逐个吃掉，最后只剩 $mn$，长度 $1$。

**情形 C：既不满足 A，也不满足 B**，即**所有元素都是 $mn$ 的倍数，且 $cnt \ge 2$。** 此时任何取模的结果都是 $mn$ 的倍数或 $0$，正元素的最小值永远是 $mn$；而每一次「消灭 $mn$」的操作都会同时产出一个 $0$（$mn \bmod mn = 0$，或 $y \bmod mn = 0$），$0$ 从此不再参与任何操作。于是能做的只是把这 $cnt$ 个 $mn$ 逐步消耗掉，最终长度为

$$\text{答案} = \left\lceil \frac{cnt}{2} \right\rceil .$$

三种情形合起来，答案只有两种取值：

$$\text{答案} = \begin{cases} 1, & \exists v,\ v \bmod mn \ne 0 \quad\text{（情形 A）}\\[2pt] \left\lceil \dfrac{cnt}{2} \right\rceil, & \text{所有元素都是 } mn \text{ 的倍数（情形 B、C）}\end{cases}$$

注意情形 B 已被公式吞掉：$cnt = 1$ 时 $\lceil 1/2 \rceil = 1$，正是情形 B 的结论。

![全是 mn 的倍数时，两个 mn 换成 0，长度只减一](images/bw122_q3_pairing.svg)

### 3.3 算法流程

```text
1. mn = min(nums)，cnt = count(mn)
2. for v in nums:
       if v % mn != 0: return 1        # 情形 A
3. return (cnt + 1) // 2               # 情形 B、C 的统一公式
```

一趟扫描即可，$O(n)$ 时间、$O(1)$ 额外空间。

### 3.4 示例演算

![示例 2 演算：三步把长度从 5 缩到 2](images/bw122_q3_walkthrough.svg)

以示例 2（`nums = [5,5,5,10,5]`）为例：$mn = 5$、$cnt = 4$，且 $10 \bmod 5 = 0$、$5 \bmod 5 = 0$，所有元素都是 $5$ 的倍数 → 答案 $\lceil 4/2 \rceil = 2$。

| 步骤 | 操作 | 数组 | 长度 |
|------|------|------|------|
| 0 | — | `[5,5,5,10,5]` | 5 |
| 1 | $(5, 10)$：$5 \bmod 10 = 5$ | `[5,5,5,5]` | 4 |
| 2 | $(5, 5)$：$5 \bmod 5 = 0$ | `[5,5,0]` | 3 |
| 3 | $(5, 5)$：$5 \bmod 5 = 0$ | `[0,0]` | 2 |

剩下两个 $0$ 无法再参与操作，长度固定为 $2$。第一步的作用是「把 10 这种多余的倍数吃掉、换成一个新的 5」，之后才能两两配对——这也是情形 C 的构造思路（先吃掉所有非 $mn$ 元素，再两两配对）。

## 4. 算法细节

1. **一趟扫描同时求 $mn$ 与 $cnt$**：写成一个循环，避免两趟（虽然两趟也是 $O(n)$）。
2. **除法判定的顺序无所谓**：只要有元素不整除就直接返回 $1$，不必等 $cnt$ 统计完。
3. **`v % mn` 的数值安全**：$mn \ge 1$，不会出现除零；$v, mn \le 10^9$，`int` 足够。
4. **`(cnt + 1) // 2` 就是上取整**：C++ 写成 `(cnt + 1) / 2`，注意别写成 `cnt / 2`（会少算一半的奇数情形）。
5. **$0$ 的处理**：题面明确操作要求两个元素都 $> 0$，所以生成的 $0$ 是「死元素」——它既不能被选为 $i$，也不能被选为 $j$，这正是情形 C 下长度无法继续压缩的根本原因。
6. **答案的上界**：$\lceil cnt/2 \rceil \le \lceil n/2 \rceil = 5\times10^4$，`int` 足够。
7. **不要尝试贪心模拟**：虽然上面的构造是可执行的，但题目只问长度，直接套公式即可，无需真的做 $O(n)$ 次操作（每次还要找配对）。
8. **构造的可执行性**：情形 A 里「$v \bmod mn$」需要 $v > mn$ 或 $v < mn$ 都行——只要 $v$ 不是 $mn$ 的倍数，$v \bmod mn \in (0, mn)$ 一定成立，与大小关系无关。

## 5. 正确性证明

**引理 1（长度单调递减且不小于 1）**：每次操作使数组长度恰好减少 $1$；任何时刻长度都 $\ge 1$，且长度等于 $1$ 时无法继续操作。

**证明**：操作删 2 插 1，长度 $-1$，故不会出现负数。长度不会变成 $0$：从 $L$ 出发每次减 $1$，减到 $1$ 时已无可删除的两个正元素（需要 $i \ne j$ 两个正数），操作无法进行。∎

**引理 2（情形 A）**：若存在 $v \in \textit{nums}$ 使 $v \bmod mn \ne 0$，则答案为 $1$。

**证明**：因 $v$ 不是 $mn$ 的倍数，$0 < v \bmod mn < mn$（$mn \ge 1$，取模结果严格小于除数且非零）。执行一次操作 $(v, mn)$，删除 $v$ 与一个 $mn$，插入 $r = v \bmod mn$。此时数组的最小值是 $r$，且它**只出现一次**（其它元素都 $\ge mn > r$，而唯一的 $r$ 刚刚被插入）。由引理 3（下证），唯一最小值的情形可以达到长度 $1$，而由引理 1 长度不能小于 $1$，故最优值为 $1$。∎

**引理 3（唯一最小值 → 答案 1）**：若当前数组的最小值 $x$ 只出现一次，则答案为 $1$。

**证明**：取该最小值所在下标为 $j$，任取另一个元素 $y$（存在，因为 $L \ge 2$）。由 $x$ 是唯一最小值知 $y > x$，于是 $x \bmod y = x$：操作后删除 $y$ 与那个 $x$、插入新的 $x$，数组长度 $-1$，而 $x$ 仍然存在且唯一（新插入的就是它，其它元素都没变）。反复执行直到只剩一个元素，长度变为 $1$。由引理 1 不可能更小。∎

**引理 4（情形 C 的上界）**：若所有元素都是 $mn$ 的倍数，则可以用 $\lceil cnt/2 \rceil$ 的长度达成。

**证明**：先处理非 $mn$ 元素：对每个 $y > mn$（必为 $mn$ 的倍数），执行 $(mn, y)$，得 $mn \bmod y = mn$，即「吃掉 $y$、保留 $mn$」。所有非 $mn$ 元素被逐个吃掉后，数组恰为 $cnt$ 个 $mn$。再把它们两两配对执行 $(mn, mn)$，每次得到 $0$ 并消耗两个 $mn$。共做 $\lfloor cnt/2 \rfloor$ 次，剩 $cnt \bmod 2$ 个 $mn$ 与 $\lfloor cnt/2 \rfloor$ 个 $0$，长度为

$$\lfloor cnt/2 \rfloor + (cnt \bmod 2) = \lceil cnt/2 \rceil . \qquad \blacksquare$$

**引理 5（情形 C 的下界）**：若所有元素都是 $mn$ 的倍数，则任何操作序列结束时的长度 $L$ 都满足 $L \ge \lceil cnt/2 \rceil$。

**证明**：先注意一个不变式：所有正元素始终是 $mn$ 的倍数（两个 $mn$ 的倍数取模，结果是 $mn$ 的倍数或 $0$），并且正元素的最小值始终是 $mn$（取模结果要么是 $0$，要么是 $\ge mn$ 的 $mn$ 的倍数）。

设过程结束（无法再操作）时，数组有 $p$ 个正元素与 $z$ 个 $0$，则 $L = p + z$，且 $p \le 1$（否则还能继续操作）。设结束时还剩 $c_f$ 个 $mn$，显然 $c_f \le p$。

对每次操作定义两个量：$e$ = 该次操作消耗的「值等于 $mn$」的元素个数（$0, 1, 2$），$q$ = 该次操作是否产出一个 $mn$（$0$ 或 $1$）。按操作数的取值分三种情况：

- $e = 2$：两个操作数都是 $mn$，结果为 $mn \bmod mn = 0$，$q = 0$，$e - q = 2$；
- $e = 1$：一个操作数是 $mn$、另一个是 $y > mn$。若写成 $mn \bmod y$，结果为 $mn$（$q = 1$，$e - q = 0$）；若写成 $y \bmod mn$，结果为 $0$（$q = 0$，$e - q = 1$）；
- $e = 0$：不消耗 $mn$，$e - q \le 0$。

归纳起来：**只要 $e \ge 1$，该次操作要么产出 $mn$（此时必为 $e = q = 1$，贡献 $e - q = 0$、且不产生 $0$），要么产出一个 $0$（此时 $e - q$ 为 $1$ 或 $2$）。**

设「$e \ge 1$ 且产出 $0$」的操作中，$e = 2$ 的有 $z_2$ 次、$e = 1$ 的有 $z_1$ 次，并记 $z' = z_1 + z_2$。则

$$c_0 - c_f = \sum (e - q) \le 2z_2 + z_1 \le 2(z_1 + z_2) = 2z' \le 2z,$$

最后一个不等号成立是因为**每个产出的 $0$ 都不会再被消耗**（操作要求两个操作数都 $> 0$），故结束时数组里的 $z$ 个 $0$ 包含了所有被产出的 $0$，即有 $z \ge z'$。

于是

$$z \;\ge\; \frac{c_0 - c_f}{2} \;\ge\; \frac{c_0 - p}{2},$$

从而

$$L = p + z \;\ge\; p + \frac{c_0 - p}{2} = \frac{c_0 + p}{2} \;\ge\; \frac{c_0}{2}.$$

$L$ 是整数，故 $L \ge \lceil c_0/2 \rceil$。∎

**定理**：算法返回最小可能长度。

**证明**：若存在 $v$ 使 $v \bmod mn \ne 0$，由引理 2 答案为 $1$，算法第 2 步返回 $1$。否则所有元素都是 $mn$ 的倍数，由引理 4 可达到 $\lceil cnt/2 \rceil$，由引理 5 不可能更小，故答案为 $\lceil cnt/2 \rceil = (cnt+1)/2$，与算法第 3 步一致。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟扫描求 $mn$ 与 $cnt$，再一趟检查整除性。
- **空间**：$O(1)$，只用常数个变量，不修改输入数组。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumArrayLength(vector<int>& nums) {
        int mn = *min_element(nums.begin(), nums.end()), cnt = 0;
        for (int v : nums) {
            if (v % mn != 0) return 1;   // 出现非最小值的倍数 → 能造出更小的新最小值
            if (v == mn) ++cnt;
        }
        return (cnt + 1) / 2;            // 全是 mn 的倍数 → 只剩 ⌈cnt/2⌉ 个
    }
};
```

### Python

```python
class Solution:
    def minimumArrayLength(self, nums: list[int]) -> int:
        mn = min(nums)
        cnt = 0
        for v in nums:
            if v % mn != 0:        # 出现非 mn 的倍数 → 能造出更小的新最小值
                return 1
            if v == mn:
                cnt += 1
        return (cnt + 1) // 2      # 全是 mn 的倍数 → 只剩 ⌈cnt/2⌉ 个
```

> 💡 两份代码均通过官方示例（`1`、`2`、`1`）与补充示例（`[3,3]` → `1`），并与「多重集状态上的全状态 BFS」暴力对拍：值域 $[1,8]$、长度 $\le 4$ 的**全部 494 个多重集**逐一比对，外加 3000 组随机用例（$n \le 4$、值域 $[1,9]$），`mismatch = 0`；$n = 10^5$ 的重复值用例（`[7] * 100000` → `50000`）也验证了线性耗时与答案上界。

## 8. 边界情况与易错点

1. **$n = 1$**：无法操作，答案就是 $1$。公式给出 $(1+1)/2 = 1$，一致。
2. **全部元素相等**：$mn = cnt$ 情形，答案 $\lceil n/2 \rceil$。例如 `[7,7,7]` → $2$、`[7,7]` → $1$。
3. **数组里有 $1$**：$1$ 整除所有数，一定走「全是倍数」分支，答案为「$1$ 的个数的上取整」；不要因为「$mn = 1$ 时 $v \bmod 1 = 0$ 恒成立」而误以为答案为 $n$。
4. **上取整写成下取整**：`cnt / 2` 会在 $cnt$ 为奇数时少算一半，是最常见的失分点。务必 `(cnt + 1) / 2`。
5. **$0$ 不能再参与**：生成的 $0$ 不满足「$>0$」，既不能当被除数也不能当除数。忘记这一点会得到「可以无限消到 0 个」的错误结论。
6. **不要漏判情形 A**：`[2,3,4]` 的答案是 $1$（靠 $3 \bmod 2 = 1$），若只按 $mn$ 的个数算会得到 $\lceil 1/2 \rceil = 1$ —— 恰好也对，但 `[2,2,3]` 就必须靠情形 A 才能得到 $1$（$mn = 2$、$cnt = 2$，公式给 $1$，其实也对；`[2,2,2,3]` 公式给 $2$，而正确答案是 $1$）。**所以整除性检查不能省。**
7. **不要真的模拟**：虽然构造可执行，但模拟需要 $O(n)$ 次操作且每次找配对，纯属浪费。
8. **数值范围**：$\textit{nums}[i] \le 10^9$，取模运算安全；若放大到 $10^{18}$ 需注意 Python 无溢出问题、C++ 需 `long long`。
