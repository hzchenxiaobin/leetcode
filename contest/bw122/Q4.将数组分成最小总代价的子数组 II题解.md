# LeetCode 将数组分成最小总代价的子数组 II 题解

## 1. 题目概述

- **标题 / 题号**：将数组分成最小总代价的子数组 II（#3013，hard）
- **链接**：https://leetcode.cn/problems/divide-an-array-into-subarrays-with-minimum-cost-ii/
- **来源**：LeetCode 第 122 场双周赛 Q4
- **难度**：困难
- **标签**：数组、哈希表、滑动窗口、堆（优先队列）

**题意**：数组的**代价**定义为它的**第一个元素**。给定长度为 $n$ 的数组 `nums` 和正整数 $k$、`dist`，要求把 `nums` 分成 $k$ 个连续、互不相交、非空的子数组，切分为

$$\textit{nums}[0..(i_1-1)],\ \textit{nums}[i_1..(i_2-1)],\ \dots,\ \textit{nums}[i_{k-1}..(n-1)],$$

并额外满足 **$i_{k-1} - i_1 \le \textit{dist}$**（第二个子数组与第 $k$ 个子数组的首元素下标距离不超过 `dist`）。求总代价的最小值。

**约束**：

- $3 \le n \le 10^5$
- $1 \le \textit{nums}[i] \le 10^9$
- $3 \le k \le n$
- $k - 2 \le \textit{dist} \le n - 2$

## 2. 示例

**示例 1**

```text
输入：nums = [1,3,2,6,4,2], k = 3, dist = 3
输出：5
解释：切成 [1,3]、[2,6,4]、[2]，i₁ = 2、i₂ = 5，i₂ − i₁ = 3 ≤ dist，
      总代价 = nums[0] + nums[2] + nums[5] = 1 + 2 + 2 = 5。
```

**示例 2**

```text
输入：nums = [10,1,2,2,2,1], k = 4, dist = 3
输出：15
解释：切成 [10]、[1]、[2]、[2,2,1]，i₁ = 1、i₃ = 3，差 2 ≤ 3，
      总代价 = 10 + 1 + 2 + 2 = 15。
      注意 [10]、[1]、[2,2,2]、[1] 不合法：i₃ − i₁ = 5 − 1 = 4 > 3。
```

**示例 3**

```text
输入：nums = [10,8,18,9], k = 3, dist = 1
输出：36
解释：切成 [10]、[8]、[18,9]，i₁ = 1、i₂ = 2，差 1 ≤ 1，代价 10 + 8 + 18 = 36。
```

## 3. 解题思路

### 3.1 暴力思路

分成 $k$ 段等价于从 $\{1, 2, \dots, n-1\}$ 中选 $k-1$ 个切点，方案数 $\binom{n-1}{k-1}$，$n = 10^5$ 时是天文数字。即便只枚举「合法」的方案，也没有可利用的单调结构——必须换一个视角。

### 3.2 核心观察：代价只落在「切点」上，约束只涉及首尾

![枚举第二段起点 s，其余 k−2 个切点落在窗口内](images/bw122_q4_window_model.svg)

第一段的代价永远是 $\textit{nums}[0]$；其余 $k-1$ 段的代价就是它们各自首元素，也就是切点上的值。于是

$$\text{总代价} = \textit{nums}[0] + \sum_{t=1}^{k-1} \textit{nums}[i_t], \qquad 1 \le i_1 < i_2 < \cdots < i_{k-1} \le n-1 .$$

再看那条麻烦的约束 $i_{k-1} - i_1 \le \textit{dist}$：它**只涉及第一个和最后一个切点**，与中间的切点无关。这提示我们：

> **枚举第一个切点 $s = i_1$。** 一旦 $s$ 定下来，其余 $k-2$ 个切点就只需落在区间 $(s,\ s + \textit{dist}]$ 内（且不超过 $n-1$），并且为了总代价最小，应当在这个窗口里挑 **值最小的 $k-2$ 个**。

形式化地，记 $W_s = \{s+1, s+2, \dots, \min(s + \textit{dist},\ n-1)\}$，则

$$\text{答案} = \textit{nums}[0] + \min_{1 \le s \le n-1}\Big( \textit{nums}[s] + \operatorname{sum\_of\_smallest}_{k-2}(W_s) \Big),$$

其中「最小的 $k-2$ 个之和」只在 $|W_s| \ge k-2$ 时才有定义。

两点说明：

- **枚举 $s$ 不遗漏最优解**：任何合法方案的 $i_1$ 都会被枚举到，它剩余的切点都在自己的窗口内，所以「窗口内最小的 $k-2$ 个」之和不大于该方案中间那些代价之和。
- **窗口内的选择一定合法**：窗口里的下标都 $> s$ 且 $\le s + \textit{dist}$，把它们排序后作为 $i_2, \dots, i_{k-1}$，则 $i_{k-1} - i_1 \le \textit{dist}$ 自动满足，且严格递增——是一个真正的合法切分。

> 💡 为什么不用单调队列？单调队列擅长维护**窗口极值**（最大/最小），而这里要的是「窗口内前 $k-2$ 小之和」，需要**有序结构**（多重集 / 堆）才能动态维护。这是本题与常规滑动窗口题的关键差别。

### 3.3 算法流程：滑动窗口 + 对顶堆

![对顶堆：low 存窗口内最小的 need 个，high 存其余](images/bw122_q4_two_heaps.svg)

让 $s$ 从 $1$ 递增到 $n-1$。窗口 $W_s$ 的左端是 $s+1$（随 $s$ 单调右移），右端是 $\min(s + \textit{dist}, n-1)$（同样单调不减），所以窗口整体是**滑动**的：每次右移时左端弹出一个元素、右端可能加入一个元素。

记 $\textit{need} = k - 2$，用两个有序容器维护「窗口内最小的 $\textit{need}$ 个」：

- `low`：存放窗口内最小的 $\textit{need}$ 个元素（C++ 用 `multiset`，Python 用大顶堆），同时维护它们的和 `lowSum`；
- `high`：存放窗口内其余元素（Python 用小顶堆）。

**插入 $v$**：

- `low` 还没装满 $\textit{need}$ 个 → 直接进 `low`；
- 否则若 $v < \max(\textit{low})$ → 把 `low` 的最大值挪到 `high`，$v$ 进 `low`；
- 否则 $v$ 进 `high`。

**删除 $v$**：

- 若 $v$ 在 `low` 中 → 从 `low` 删掉、`lowSum` 减去 $v$，再从 `high` 里补一个最小值进 `low`（维持 `low` 的大小为 $\textit{need}$）；
- 否则从 `high` 中删掉 $v$（Python 用惰性删除）。

**统计答案**：对每个 $s$，若当前 `low` 恰好装满 $\textit{need}$ 个（即窗口够大），则用 $\textit{nums}[0] + \textit{nums}[s] + \textit{lowSum}$ 更新答案。

```text
1. need = k − 2，r = min(1 + dist, n − 1)          # s = 1 时窗口为 [2, r]
2. for p in [2, r]: insert(nums[p])
3. ans = +∞
4. for s = 1 .. n−1:
       若 low 的大小 == need：ans = min(ans, nums[0] + nums[s] + lowSum)
       若 s+1 ≤ n−1：erase(nums[s+1])                # 左端离开
       nr = min(s + 1 + dist, n − 1)
       若 nr > r：insert(nums[nr])，r = nr            # 右端进入
5. 返回 ans
```

每个元素最多被插入、删除各一次，单次代价 $O(\log n)$，总复杂度 $O(n \log n)$。

## 4. 算法细节

1. **$\textit{need} = k - 2 \ge 1$**：$k \ge 3$，故 `need` 至少为 1，不需要处理「窗口为空」的特判；但仍需判断窗口内元素个数是否够 `need`，即 `low` 是否装满。
2. **窗口右端单调不减**：$r = \min(s + \textit{dist},\ n-1)$ 随 $s$ 单调不减，所以右端只会「扩张」，不会收缩。这让「加入新元素」的条件可以简化为 `nr > r`。
3. **初始窗口**：$s = 1$ 时窗口是 $[2, \min(1+\textit{dist},\ n-1)]$，**不要**把下标 0 或 1 放进去（下标 1 是 $\textit{nums}[s]$ 本身，切点必须严格递增，不能重复计费）。
4. **`low` 的大小恒为 $\min(\textit{need}, |W_s|)$**：插入时未满就直接进 `low`；删除时若从 `low` 扣掉一个，就从 `high` 补一个最小值回来。这个不变式是正确性的核心。
5. **重复值**：同一数值可能多次出现在窗口中，删除时只删「一份」。C++ 的 `multiset::find` 定位到某一个副本即可；Python 用「计数 + 惰性删除标记」区分副本。
6. **惰性删除**：Python 的 `heapq` 不支持任意删除，于是被删除的元素只做标记，等它冒到堆顶时再真正弹出。`in_low[v]` 记录「值 $v$ 在 `low` 中的逻辑份数」，避免把新插入的副本误删。
7. **可行性判定用 `low` 的大小**：`low` 装满 `need` 个 ⇔ 窗口内至少有 `need` 个元素。$s$ 太靠右（$n-1-s < \textit{need}$）时窗口必然不够，直接跳过。
8. **答案范围**：$k$ 项、每项 $\le 10^9$，总和 $\le 10^{14}$，必须 `long long`（Python 无此问题）。

## 5. 正确性证明

**引理 1（切分与切点集双射）**：把 `nums` 分成 $k$ 个连续非空子数组的方案，与满足 $1 \le i_1 < i_2 < \dots < i_{k-1} \le n-1$ 的下标集合一一对应；该方案的总代价为 $\textit{nums}[0] + \sum_{t=1}^{k-1}\textit{nums}[i_t]$。

**证明**：给定切分，$i_t$ 是第 $t+1$ 段的起始下标，非空性给出 $i_1 \ge 1$、$i_{t+1} > i_t$、$i_{k-1} \le n-1$。反之给定这样的下标集合即确定唯一的切分。代价按定义为各段首元素之和，即 $\textit{nums}[0], \textit{nums}[i_1], \dots, \textit{nums}[i_{k-1}]$。∎

**引理 2（固定 $s$ 时的最优）**：设 $s \in [1, n-1]$，$W_s = \{s+1, \dots, \min(s+\textit{dist}, n-1)\}$，且 $|W_s| \ge k-2$。则在所有以 $i_1 = s$ 的合法切分中，总代价的最小值为

$$\textit{nums}[0] + \textit{nums}[s] + \big(\text{$W_s$ 中最小的 $k-2$ 个值之和}\big).$$

**证明**：任一以 $i_1 = s$ 的合法切分，其 $i_2, \dots, i_{k-1}$ 满足 $s < i_2 < \dots < i_{k-1} \le s + \textit{dist}$，故都落在 $W_s$ 中，且互不相同（共 $k-2$ 个）。由「$k-2$ 个不同位置上的值之和不小于最小的 $k-2$ 个值之和」，该切分代价 $\ge$ 上式。另一方面，取 $W_s$ 中值最小的 $k-2$ 个位置排序后作为 $i_2, \dots, i_{k-1}$，则严格递增、都 $\le s+\textit{dist}$，由引理 1 构成合法切分，代价恰好等于上式。故该式即为最小值。∎

**引理 3（枚举完备）**：设 $\mathrm{OPT}$ 为原问题最优值，$A$ 为算法输出，则 $A = \mathrm{OPT}$。

**证明**：

- $A \le \mathrm{OPT}$：设最优方案的首切点为 $s^*$，由引理 2，该方案代价 $\ge \textit{nums}[0] + \textit{nums}[s^*] + (\text{$W_{s^*}$ 中最小 $k-2$ 个之和})$，而算法在 $s = s^*$ 处（窗口足够，因为该方案存在）恰好计算了这个值并取最小值，故 $A \le \mathrm{OPT}$。
- $A \ge \mathrm{OPT}$：算法在某个 $s$ 处取到最小值，由引理 2，该值等于「以 $i_1 = s$ 的最优合法方案」的代价，它本身就是一个合法方案的代价，故 $\ge \mathrm{OPT}$。

两者夹逼得 $A = \mathrm{OPT}$。∎

**引理 4（容器不变式）**：在上述插入 / 删除规则下，任意时刻 `low` 恰为当前窗口内最小的 $\min(\textit{need}, |W|)$ 个元素（按多重集计），`lowSum` 为其元素之和。

**证明**：对操作次数归纳。初始时窗口由空逐步插入，`low` 未满就直接进 `low`，仍是「最小的若干」；满了以后只在 $v < \max(\textit{low})$ 时才让 $v$ 替换最大值，故 `low` 始终是窗口前缀中最小的 `need` 个。删除一个元素时：若它属于 `low`，扣掉后 `low` 少一个，从 `high`（其余元素）取最小者补入，仍保持「最小 `need` 个」；若它属于 `high`，直接从 `high` 移除（惰性标记），`low` 不受影响。∎

**定理**：`minimumCost` 返回最小总代价。

**证明**：由引理 4，`lowSum` 正确维护了窗口内最小的 `need = k-2` 个之和；由引理 3，对所有 $s$ 取最小即得最优值。算法遍历了全部 $s \in [1, n-1]$（窗口不足者跳过，由引理 2 的条件它们确实无解），故输出正确。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。$s$ 走 $n-1$ 步；每步至多一次删除、一次插入，每次在有序容器/堆上 $O(\log n)$（惰性删除的清理均摊到每个元素 $O(\log n)$ 一次）；每步还做一次 $O(1)$ 的答案更新。
- **空间**：$O(n)$。两个容器合计存放窗口内至多 $\textit{dist}+1$ 个元素（$\le n$）；惰性删除的计数表也是 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minimumCost(vector<int>& nums, int k, int dist) {
        int n = (int)nums.size(), need = k - 2;
        multiset<long long> low, high;   // low 存窗口内最小的 need 个，high 存其余
        long long lowSum = 0;

        auto insert = [&](long long v) {
            if ((int)low.size() < need) {
                low.insert(v);
                lowSum += v;
            } else if (v < *low.rbegin()) {          // 比 low 的最大值更小才值得进来
                long long mx = *low.rbegin();
                low.erase(prev(low.end()));
                lowSum -= mx;
                high.insert(mx);
                low.insert(v);
                lowSum += v;
            } else {
                high.insert(v);
            }
        };
        auto erase = [&](long long v) {
            auto it = low.find(v);
            if (it != low.end()) {
                low.erase(it);
                lowSum -= v;
                if (!high.empty()) {                 // 从 high 补一个最小值
                    auto jt = high.begin();
                    low.insert(*jt);
                    lowSum += *jt;
                    high.erase(jt);
                }
            } else {
                high.erase(high.find(v));
            }
        };

        int r = min(1 + dist, n - 1);                // s = 1 时窗口为 [2, r]
        for (int p = 2; p <= r; ++p) insert(nums[p]);

        long long ans = LLONG_MAX;
        for (int s = 1; s < n; ++s) {
            if ((int)low.size() == need)
                ans = min(ans, (long long)nums[0] + nums[s] + lowSum);
            // 窗口右移：删去离开的 s+1，加入新进入的 nr
            if (s + 1 <= n - 1) erase(nums[s + 1]);
            int nr = min(s + 1 + dist, n - 1);
            if (nr > r) {
                insert(nums[nr]);
                r = nr;
            }
        }
        return ans;
    }
};
```

### Python

```python
import heapq
from collections import defaultdict

class Solution:
    def minimumCost(self, nums: list[int], k: int, dist: int) -> int:
        n = len(nums)
        need = k - 2                     # 除 nums[0] 与 nums[s] 外还要挑几个切点
        low, high = [], []               # low: 大顶堆(存负值)，窗口内最小的 need 个
        in_low = defaultdict(int)        # 逻辑上仍在 low 中的某值的份数
        dl, dh = defaultdict(int), defaultdict(int)   # 惰性删除标记
        low_sum = 0                      # low 中元素之和
        low_cnt = 0                      # low 的逻辑大小

        def clean_low():
            while low and dl[-low[0]] > 0:
                v = -heapq.heappop(low)
                dl[v] -= 1

        def top_low():
            clean_low()
            return -low[0]

        def pop_low():
            nonlocal low_sum, low_cnt
            clean_low()
            v = -heapq.heappop(low)
            in_low[v] -= 1
            low_sum -= v
            low_cnt -= 1
            return v

        def pop_high():
            while high and dh[high[0]] > 0:
                v = heapq.heappop(high)
                dh[v] -= 1
            return heapq.heappop(high)

        def push_low(v):
            nonlocal low_sum, low_cnt
            heapq.heappush(low, -v)
            in_low[v] += 1
            low_sum += v
            low_cnt += 1

        def insert(v):
            if low_cnt < need:
                push_low(v)
            elif v < top_low():          # 比 low 的最大值更小才值得进来
                heapq.heappush(high, pop_low())
                push_low(v)
            else:
                heapq.heappush(high, v)

        def erase(v):
            nonlocal low_sum, low_cnt
            if in_low[v] > 0:            # v 在 low 中：直接扣掉并从 high 补位
                dl[v] += 1
                in_low[v] -= 1
                low_sum -= v
                low_cnt -= 1
            else:
                dh[v] += 1
            while low_cnt < need:
                while high and dh[high[0]] > 0:
                    u = heapq.heappop(high)
                    dh[u] -= 1
                if not high:
                    break
                push_low(pop_high())

        r = min(1 + dist, n - 1)         # s = 1 时窗口为 [2, r]
        for p in range(2, r + 1):
            insert(nums[p])
        ans = float("inf")
        for s in range(1, n):
            if low_cnt == need:          # 窗口内元素够 k-2 个才是一个合法方案
                ans = min(ans, nums[0] + nums[s] + low_sum)
            if s + 1 <= n - 1:           # 窗口右移：删去离开的 s+1
                erase(nums[s + 1])
            nr = min(s + 1 + dist, n - 1)
            if nr > r:                   # 加入新进入的 nr
                insert(nums[nr])
                r = nr
        return ans
```

> 💡 两份代码维护的是同一个抽象结构（`low` = 窗口内最小 `need` 个、`high` = 其余），只是实现手段不同：C++ 直接有 `multiset` 这种支持按值删除的有序容器，Python 没有内置同类结构，于是用**双堆 + 惰性删除**模拟（`in_low` 计数区分同值副本，`dl/dh` 记录待清理的堆顶）。

> 💡 均通过官方示例（`5`、`15`、`36`），并与「枚举全部 $\binom{n-1}{k-1}$ 个切点集」的暴力对拍：2000 组小值域用例（$n \le 10$、值 $\le 12$）+ 1000 组大值域用例（值 $\le 10^9$）+ 800 组「$\textit{dist} = k-2$ 与 $\textit{dist} = n-2$ 的极端形状」用例，`mismatch = 0`；$n = 10^5$ 的多种 $(k, \textit{dist})$ 组合（$k=3$、$k=n$、$k$ 居中）均在 0.2 秒内返回，验证了 $O(n\log n)$ 的复杂度。

## 8. 边界情况与易错点

1. **`need = k - 2` 可能很大**：$k = n$ 时 $\textit{need} = n-2$，窗口必须容纳几乎整个后缀；此时 $\textit{dist} \ge n-2$ 的约束保证 $s = 1$ 的窗口就够用。代码里靠「`low` 是否装满」统一处理，无需特判。
2. **$\textit{dist} = k-2$ 时窗口恰好够大**：$|W_s| = \textit{need}$ 时窗口里每个元素都必须选，等价于「定长窗口求和」，此时答案退化为「选连续 $k-1$ 个切点」，可以拿来交叉验证。
3. **$s$ 太靠右**：$n - 1 - s < \textit{need}$ 时窗口元素不足，`low` 装不满 `need`，必须跳过（否则会把「不存在的切点」也算进代价）。
4. **$\textit{nums}[0]$ 只能算一次**：第一段代价恒为 $\textit{nums}[0]$，加在答案里一次即可；`low` 的窗口要**从 $s+1$ 开始**，不能包含 $s$ 或 $0$。
5. **重复值删除**：`[2,2,2]` 这类窗口里同一个值出现多次，删除时必须只删一份。用 `multiset::find` 或「计数 + 惰性标记」，不要一删全删。
6. **惰性删除的清理时机**：只有在需要读取堆顶（求最大值 / 补位）时才清理，`lowSum` 的扣减必须在「逻辑删除」的那一刻做，而不是等真正弹出——否则 `lowSum` 会与实际窗口不一致。
7. **从 `low` 删除后补位**：补位要用 `high` 的**最小值**（它才是剩下元素里最小的），不是任意一个。
8. **溢出**：$k$ 项、每项 $\le 10^9$，答案可达 $10^{14}$，C++ 必须 `long long` 累加（`lowSum`、`ans` 都是）；`(long long)nums[0] + nums[s] + lowSum` 的强转别漏。
9. **窗口移动顺序**：先统计当前 $s$ 的答案，再删左端、加右端。顺序颠倒会用到错误的窗口。
10. **$n = k$ 且 $\textit{dist} = n-2$**：唯一合法切分是 $1, 2, \dots, n-1$（所有元素各成一段），答案就是 `nums` 的总和，可作快速自检。

**延伸思考**：本题的解法是「**枚举一个边界变量，把剩下的选择压成一个窗口内的静态最优化问题**」——这正是滑动窗口类 hard 题的通用套路：先找出「随某个变量单调移动的区间」，再用合适的数据结构维护该区间的某个统计量。这里的统计量是「前 $k-2$ 小之和」，故需要有序容器；若统计量换成「区间第 $k$ 小」「区间众数」等，就要换成树状数组套值域、主席树或莫队。另一条思路是把「前 $k$ 小之和」用**树状数组 + 二分**（按值域维护计数与前缀和，$O(\log V)$ 求 $k$ 小之和）实现，代码量比双堆略多但不需要惰性删除，也是常见的替代方案。若把约束从「首尾切点距离」改成「任意相邻切点距离」，问题就变成带状态的分段 DP，$O(nk)$ 或斜率优化，难度会再上一个台阶。
