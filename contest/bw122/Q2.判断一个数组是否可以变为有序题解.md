# LeetCode 判断一个数组是否可以变为有序 题解

## 1. 题目概述

- **标题 / 题号**：判断一个数组是否可以变为有序（#3011，medium）
- **链接**：https://leetcode.cn/problems/find-if-array-can-be-sorted/
- **来源**：LeetCode 第 122 场双周赛 Q2
- **难度**：中等
- **标签**：位运算、数组、排序

**题意**：给定全为正整数的数组 `nums`。一次操作中，若**相邻**两个元素二进制表示中 `1` 的个数（下称 `popcount`）**相同**，则可以交换它们。可以执行任意次（含 $0$ 次）操作，问能否使数组变为**非降序**。

**约束**：

- $1 \le \textit{nums.length} \le 100$
- $1 \le \textit{nums}[i] \le 2^8 = 256$

## 2. 示例

**示例 1**

```text
输入：nums = [8,4,2,30,15]
输出：true
解释：popcount 依次为 1,1,1,4,4。
      前三者可任意互换（都是 1 个 1），后两者可互换（都是 4 个 1）。
      于是 [8,4,2 | 30,15] → [2,4,8 | 15,30]，非降序 → true。
```

**示例 2**

```text
输入：nums = [1,2,3,4,5]
输出：true
解释：本身已非降序，0 次操作即可。
```

**示例 3**

```text
输入：nums = [3,16,8,4,2]
输出：false
解释：popcount 依次为 2,1,1,1,1。3 自成一段，无法与后面的元素交换；
      3 又比后面所有元素都大，永远排在首位 → 不可能非降。
```

## 3. 解题思路

### 3.1 暴力思路

「能通过相邻交换变成有序」的搜索空间是 $n!$ 级别的排列，$n = 100$ 时完全不可行；即便用「排列可达性」来判，也要面对 $\binom{n}{k}$ 种分布。必须找到**不变量**，把可达状态刻画清楚。

### 3.2 核心观察：popcount 是位置的不变量，段内可任意置换

![按 popcount 切出的连续段，段内可自由置换](images/bw122_q2_segment_model.svg)

先看操作本身：交换的是**相邻且 popcount 相同**的两个元素。交换只改变「值在哪个位置」，不改变「每个位置的值具有什么 popcount」，于是立刻得到两条结论：

1. **位置 $p$ 上的值的 popcount 永远等于初始 $\textit{nums}[p]$ 的 popcount**。这就像每个位置都贴了一个标签，标签不能改。
2. 因此，一个值只可能在「与它 popcount 相同的那些位置」之间移动；而这些位置若被 popcount 不同的位置隔开，值就**跨不过去**。

把数组按「连续且 popcount 相同」切成若干**极长段**，第 $r$ 段就是一段连续的下标区间 $[l_r, r_r]$。上面两条说明：**段 $r$ 里的元素永远待在段 $r$ 里**。

再看段内：段中任意两个相邻位置的 popcount 相同（这正是极长段的定义），所以它们的元素随时可以交换。而「相邻交换」是生成对称群的经典工具——任何排列都能用若干次相邻交换实现（冒泡排序就是算法）。于是

> **段内元素可以任意重排；跨段一步也走不了。**

![段内相邻交换可实现任意置换，跨段则完全不可达](images/bw122_q2_swap_insight.svg)

至此问题变成：能否把每段**各自内部排好序**，使得拼起来的整体非降？由于段的位置区间也是固定的，这等价于

$$\max(\text{段 } r) \;\le\; \min(\text{段 } r+1) \qquad \text{对所有相邻段成立},$$

也就是「把每段排序后，整体非降」。

### 3.3 算法流程

![两个例子：一个能变有序，一个不能](images/bw122_q2_walkthrough.svg)

```text
1. i = 0，prevMax = −∞
2. while i < n:
       记 pc = popcount(nums[i])
       j = i，lo = hi = nums[i]
       while j+1 < n 且 popcount(nums[j+1]) == pc:      # 扩张极长段
           j += 1
           lo = min(lo, nums[j])，hi = max(hi, nums[j])
       if lo < prevMax: return false                    # 本段最小值比前段最大值还小
       prevMax = hi
       i = j + 1
3. return true
```

注意这里**根本不需要真的排序**：只要知道每段的 min 与 max，就能判断「前段最大值 ≤ 后段最小值」。这样整题是 $O(n)$ 的（`popcount` 视为 $O(1)$）。

### 3.4 示例演算

**示例 1**（`nums = [8,4,2,30,15]`）：

| 分段 | 元素 | popcount | 段内 min | 段内 max | 检查 |
|------|------|----------|----------|----------|------|
| 段 1 | 8, 4, 2 | 1, 1, 1 | 2 | 8 | `prevMax = −∞`，通过 |
| 段 2 | 30, 15 | 4, 4 | 15 | 30 | $15 \ge 8$ ✓，通过 |

两段分别排序得 `[2,4,8 | 15,30]`，整体非降 → `true`。

**示例 3**（`nums = [3,16,8,4,2]`）：

| 分段 | 元素 | popcount | 段内 min | 段内 max | 检查 |
|------|------|----------|----------|----------|------|
| 段 1 | 3 | 2 | 3 | 3 | 通过 |
| 段 2 | 16, 8, 4, 2 | 1, 1, 1, 1 | 2 | 16 | $2 < 3$ ✗ |

段 2 的最小值 $2$ 小于前段最大值 $3$，而 $3$ 又无法离开段 1，故永远做不到非降 → `false`。

## 4. 算法细节

1. **`popcount` 的写法**：C++ 用 `__builtin_popcount`，Python 用 `bin(x).count("1")`（或 `int.bit_count()`，Python 3.10+）。$\textit{nums}[i] \le 256 < 2^9$，9 位足够，32 位版本绰绰有余。
2. **「极长段」的判定**：段是**连续**的，必须写成「与**前一个位置**的 popcount 相同就继续扩张」。用「收集所有相同 popcount 的元素」是错的——那会跨越中间不同 popcount 的障碍。
3. **只需 min/max，无需排序**：整体的「非降」条件逐段分解后只剩相邻比较，故每段维护 $(\min, \max)$ 即可，复杂度从 $O(n\log n)$ 降到 $O(n)$。
4. **`prevMax` 的初值**：取 $-\infty$（C++ 里可用 `-1`，因为 $\textit{nums}[i] \ge 1$），保证第一段无条件通过。
5. **比较方向**：判定是 `lo >= prevMax`（本段最小值不小于前段最大值），不是反过来。相等是允许的（非降序）。
6. **早退**：一旦某段的最小值小于前段最大值，后面再怎么排都救不回来，可以立即返回 `false`。
7. **等价写法**：真排序（每段 `sort` 后整体扫一遍是否非降）也对，代码更好写、也便于对拍；只是多花一个 $\log$。

## 5. 正确性证明

**引理 1（popcount 标签不变量）**：任意次操作后，对每个下标 $p$，位置 $p$ 上的值的 popcount 仍等于初始的 $\operatorname{pc}(\textit{nums}[p])$。

**证明**：对操作次数归纳。$0$ 次时显然成立。设某次操作交换了相邻位置 $p, p+1$，由操作前提 $\operatorname{pc}(\textit{nums}[p]) = \operatorname{pc}(\textit{nums}[p+1])$，交换后这两个位置上的 popcount 都没有变化；其余位置不受影响。故不变量保持。∎

**引理 2（跨段不可达）**：设极长段为 $[l_r, r_r]$，则段 $r$ 的初始元素在任意时刻仍占据 $[l_r, r_r]$ 这些位置，且这些位置上的元素始终来自该段。

**证明**：由引理 1，位置 $p \in [l_r, r_r]$ 上的值的 popcount 恒为 $\operatorname{pc}(\textit{nums}[p])$。而段内相邻位置 popcount 相同、段边界两侧不同，故任何元素要离开 $[l_r, r_r]$，必须经过某个边界位置——但边界的两个位置 popcount 不同，它们的值永远不能交换（引理 1 说明这两个位置上的 popcount 始终不同，故永远不满足交换前提）。因此元素无法越界，位置集合与元素集合都保持不变。∎

**引理 3（段内可实现任意排列）**：段 $r$ 内的元素可以达到该段的任意排列。

**证明**：段内任意相邻两位置的 popcount 相同（极长段的定义），故任意相邻交换都合法。而任意排列都可由 $O(k^2)$ 次相邻交换实现（例如冒泡排序：把目标排列的元素依次「冒」到正确位置）。∎

**定理**：`canSortArray` 返回 `true` 当且仅当可以通过操作使 `nums` 非降。

**证明**：

（充分性）若所有相邻段满足 $\max(\text{段 } r) \le \min(\text{段 } r+1)$，则由引理 3，把每段内部排成升序（有重复值时排成非降）是可达的。拼接后，段内非降、段间由条件保证非降，故整体非降。

（必要性）设某次可达的非降状态存在。由引理 2，每个段的位置区间 $[l_r, r_r]$ 上放着的仍是该段的元素集合；整体非降推出该区间内部非降，故该区间上的元素序列必是该段元素集合的升序排列。于是对相邻两段，段 $r$ 的所有元素都排在段 $r+1$ 的所有元素之前，非降性要求 $\max(\text{段 } r) \le \min(\text{段 } r+1)$。若该条件被破坏（存在 $r$ 使 $\max(\text{段 } r) > \min(\text{段 } r+1)$），则段 $r$ 中那个最大值所在位置必在段 $r+1$ 中那个最小值所在位置之前，违反非降。矛盾。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素被访问常数次（分段扫描一次），每段只做 min/max 更新；`popcount` 在固定字长下为 $O(1)$。若改用「每段排序」则为 $O(n \log n)$。
- **空间**：$O(1)$ 额外空间（原地扫描；若采用排序写法则为 $O(1)$ 或 $O(n)$，取决于是否复制）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool canSortArray(vector<int>& nums) {
        int n = (int)nums.size(), i = 0, prevMax = -1;
        while (i < n) {
            int pc = __builtin_popcount(nums[i]);
            int j = i, mn = nums[i], mx = nums[i];
            while (j + 1 < n && __builtin_popcount(nums[j + 1]) == pc) {
                ++j;
                mn = min(mn, nums[j]);
                mx = max(mx, nums[j]);
            }
            // 段内可任意置换 → 该段最小值必须不小于前一段的最大值
            if (mn < prevMax) return false;
            prevMax = mx;
            i = j + 1;
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def canSortArray(self, nums: list[int]) -> bool:
        n = len(nums)
        prev_max = -1
        i = 0
        while i < n:
            pc = bin(nums[i]).count("1")
            j = i
            lo = hi = nums[i]
            while j + 1 < n and bin(nums[j + 1]).count("1") == pc:
                j += 1
                lo = min(lo, nums[j])
                hi = max(hi, nums[j])
            # 段内可任意置换 → 该段最小值必须不小于前一段的最大值
            if lo < prev_max:
                return False
            prev_max = hi
            i = j + 1
        return True
```

> 💡 两份代码均通过官方示例（`true`、`true`、`false`），并与「在排列图上做 BFS、判断能否到达有序排列」的暴力在 4000 组随机数组（$n \le 6$，值域 $[1,40]$）上对拍；另用 1000 组「边界值」（$1,2,3,4,7,8,15,16,31,32,63,64,127,128,255,256$）专门覆盖 popcount 变化处，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$n = 1$**：没有任何可执行的操作，但单个元素本身非降 → 返回 `true`。代码中循环会正常走完一段并返回 `true`。
2. **全部元素 popcount 相同**：整个数组是一段，可以任意重排 → 一定能排序成功，返回 `true`。别误判成「必须原地有序」。
3. **`prevMax` 初值**：必须取一个比所有可能值都小的数。用 `0` 也可以（因为 $\textit{nums}[i] \ge 1$），但用 $-1$ 更明确。
4. **非降 ≠ 严格递增**：判定用 `lo >= prevMax`，相等合法。若写成 `>`，`[1,2,3,4,5]` 之外的重复值用例会误判。
5. **段必须连续**：`[3,16,8,4,2]` 中 popcount 为 1 的元素出现在下标 $1..4$，但它们必须被 `3`（popcount 2）挡住，不能与 3 交换。用「按 popcount 分组」而不是「切连续段」会得到错误答案。
6. **值域上限 256**：$256 = (1\,0000\,0000)_2$，popcount 为 1。不要以为「值域 256 意味着 8 位」就手动取模，直接用内建函数即可。
7. **正数保证**：$\textit{nums}[i] \ge 1$，故 popcount 至少为 1，不存在「全 0 段」的特殊处理（即便出现 0，逻辑也照样成立）。
8. **不要真的模拟交换**：判断「能否」只需要不变量与分段条件，模拟交换既慢又容易死循环。
