# LeetCode 使三个字符串相等 题解

## 1. 题目概述

- **标题 / 题号**：使三个字符串相等（#2937，easy）
- **链接**：https://leetcode.cn/problems/make-three-strings-equal/
- **来源**：LeetCode 第 372 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定三个字符串 $s_1$、$s_2$、$s_3$。每次操作可以任选其中一个**长度至少为 2** 的字符串，删除其**最右侧**的字符，操作次数不限。若能让三个字符串变得完全相等，返回所需的最少操作次数；否则返回 $-1$。

**约束**：

- $1 \le s_1.length,\ s_2.length,\ s_3.length \le 100$
- 三个字符串仅由小写英文字母组成

> 💡 读题抓形态：**单向削减型**——只许删最后一个字符，不许删中间、不许插入。这说明每个串的"存活部分"永远是原串的**前缀**，整个问题瞬间坍缩成「最长公共前缀（LCP）」一个参数。签到题要抠的两个细节：**长度 $\ge 2$ 才能操作，所以串永远删不成空串**（这决定了 $-1$ 的判定）；**答案公式里系数是 $3L$ 而不是 $L$**（三个串各要削掉自己的尾巴）。

## 2. 示例

**示例 1**

```text
输入：s1 = "abc", s2 = "abb", s3 = "ab"
输出：2
解释：删掉 s1 的 'c'、s2 的 'b'，三串都变成 "ab"，共 2 次操作。
```

**示例 2**

```text
输入：s1 = "dac", s2 = "bac", s3 = "cac"
输出：-1
解释：三串首字符 d、b、c 互不相同，前缀无法对齐，无解。
```

**补充示例：已经全部相等**

```text
输入：s1 = "abc", s2 = "abc", s3 = "abc"
输出：0
解释：初始即相等，LCP L = 3，3 + 3 + 3 − 3×3 = 0。
```

**补充示例：只削一个串**

```text
输入：s1 = "ab", s2 = "a", s3 = "a"
输出：1
解释：L = 1，只需删 s1 的 'b'，2 + 1 + 1 − 3×1 = 1。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的想法是枚举"最终公共串"：目标串必然是三个原串的公共前缀，所以从大到小枚举目标长度 $k = \min(len_1, len_2, len_3)$ 到 $1$，每次截出三个长度为 $k$ 的前缀判断是否全等，取第一个可行（最大）的 $k$，答案为 $\sum len_i - 3k$；一枚举不到则返回 $-1$。每次判定要 $O(k)$ 比较，总共 $O(n^2)$（$n \le 100$，约 $10^4$ 量级，轻松通过）。更笨的路线是从初始三元组出发 BFS 所有删尾状态，状态数 $\prod len_i$ 最高 $10^6$，纯属浪费。其实"全等判定"根本不用反复做——**三个前缀全等 ⟺ 逐位一直相等到第 $k$ 位**，一次从左到右的扫描就把所有 $k$ 的答案全测完了。

### 3.2 核心观察：只删后缀 ⇒ 目标必是最长公共前缀

![核心概念：目标必是三串的最长公共前缀](images/wc372_q1_lcp_concept.svg)

1. **操作不变量**：每次只删最右字符，任意时刻每个串都是自己原串的**前缀**（且首字符永远不变）。
2. **非空不变量**：操作要求长度 $\ge 2$，长度为 $1$ 的串**无法再操作**；而初始长度 $\ge 1$，所以任何串**永远不可能变空**。这排除了"全删成空串凑相等"的逃逸路线。
3. **目标刻画**：设最终三串都等于长度为 $k$ 的串 $T$。$T$ 是每个 $s_i$ 的前缀且 $k \ge 1$，故 $T$ 是三个串长度为 $k$ 的公共前缀，即 $k \le L$（$L$ 为 LCP 长度）；反之取 $k = L$ 一定可行。
4. **代价单调**：总操作次数 $= \sum_i (len_i - k) = \sum len_i - 3k$，随 $k$ 增大严格减小，故 $k = L$ 时最小。

于是一趟扫描求出 $L$：$L = 0$（首字符就不全相等）返回 $-1$；否则返回 $\sum len_i - 3L$。

$$\text{answer} = \begin{cases} -1, & L = 0 \\ len_1 + len_2 + len_3 - 3L, & L \ge 1 \end{cases}$$

### 3.3 算法流程

![算法流程：一趟扫描求 LCP](images/wc372_q1_algorithm_flow.svg)

1. **初始化**：令 $n = \min(len_1, len_2, len_3)$，比较指针 $i = 0$；
2. **扫描**：只要 $i < n$ 且 $s_1[i] = s_2[i] = s_3[i]$，就 $i{+}{+}$；遇到失配或到达最短串末尾即停；
3. **判定无解**：若停止时 $i = 0$，说明首字符就不全相等，返回 $-1$；
4. **输出**：否则返回 $len_1 + len_2 + len_3 - 3i$。

### 3.4 示例演算

![示例 1 演算：逐位对齐找 LCP](images/wc372_q1_example_walkthrough.svg)

以示例 1（$s_1 = $ `abc`，$s_2 = $ `abb`，$s_3 = $ `ab`）为例，把三个串左对齐逐位比较：

| 位 $i$ | $s_1[i]$ | $s_2[i]$ | $s_3[i]$ | 判定 |
|--------|----------|----------|----------|------|
| 0 | `a` | `a` | `a` | ✓ 三者相等，$i \to 1$ |
| 1 | `b` | `b` | `b` | ✓ 三者相等，$i \to 2$ |
| 2 | `c` | `b` | （越界） | ✗ $i$ 停在 $2$ |

$L = 2$，操作序列：删 $s_1$ 的 `c` 得 `ab`，再删 $s_2$ 的 `b` 得 `ab`，与 $s_3$ 汇合，共 $3 + 3 + 2 - 3 \times 2 = 2$ 次操作。对照示例 2：第 $0$ 位 `d`、`b`、`c` 互不相同，$i$ 原地停在 $0$，直接 $-1$。

## 4. 算法细节

1. **扫描上界取三串最短长度**：$i < \min(len_1, len_2, len_3)$，防止访问越界（最短串先耗尽本身就是失配）。
2. **失配即停（短路）**：LCP 的定义就是"第一个不全相等的位置之前"，不必也不应继续扫描。
3. **判定 $-1$ 放在扫描之后**：$i = 0$ 就是"首字符不全相等"的等价表述，无需单独再比较一次 $s_1[0], s_2[0], s_3[0]$。
4. **比较写成链式**：Python 可直接写 `s1[i] == s2[i] == s3[i]`；C++ 没有链式比较（`a==b==c` 会变成布尔参与运算），必须写成 `s1[i] == s2[i] && s2[i] == s3[i]`。
5. **公式系数**：$3L$ 对应三个串各自削去的尾部长度之和；返回值上限 $\sum len_i \le 300$，`int` 无溢出风险。

## 5. 正确性证明

**引理 1（前缀不变量与非空不变量）**：任意时刻，每个 $s_i$ 都是原串的非空前缀，且首字符与原串相同。

**证明**：对操作次数归纳。初始时长度 $\ge 1$、是自身前缀。每步操作删除最后一个字符且要求操作前长度 $\ge 2$，故操作后长度 $\ge 1$（非空保持），仍是原前缀（删后缀不破坏前缀性），首字符位置 $0$ 从未被触及。∎

**引理 2（可行性）**：三串能变为相等 $\iff$ $L \ge 1$（$L$ 为三串 LCP 长度）。

**证明**：（$\Leftarrow$）把每个 $s_i$ 删到只剩前 $L$ 个字符：若 $len_i > L$，删除过程从 $len_i$ 降到 $L \ge 1$，每次删除时长度 $\ge L + 1 \ge 2$，操作合法；若 $len_i = L$ 无需操作。最终三串都等于公共前缀 $P_L$。（$\Rightarrow$）若最终相等为串 $T$，由引理 1，$T$ 是每个原串的非空前缀，故 $|T| \ge 1$ 且 $T$ 的每一位同时出现在三串的对应位置，即 $T$ 是长度 $\ge 1$ 的公共前缀，故 $L \ge |T| \ge 1$。∎

**定理（最优代价）**：$L \ge 1$ 时最少操作次数为 $len_1 + len_2 + len_3 - 3L$；$L = 0$ 时无解，返回 $-1$。

**证明**：任一可行方案中，设最终公共串长度为 $k$。由引理 2 的证明过程知 $1 \le k \le L$，且三串分别被删了 $len_i - k$ 次（每次操作恰使某一个 $len_i$ 减 $1$），故总次数 $= \sum len_i - 3k$，关于 $k$ 严格单调递减，在 $k = L$ 处取最小值 $\sum len_i - 3L$；该值由引理 2 的构造达到。$L = 0$ 时由引理 2 无任何可行方案。∎

**推论（操作代价结构）**：总操作数、$\sum len_i$ 与 $3k$ 满足守恒式 $\text{ops} + 3k = \sum len_i$——每次操作让"总字符数"减 $1$，最终总字符数必为 $3k$。这解释了为什么 $k$ 每增大 $1$ 恰好省 $3$ 次操作。

## 6. 复杂度分析

- **时间复杂度**：$O(\min(len_1, len_2, len_3))$。一趟扫描每步做两次字符比较，最坏走到最短串末尾；这是读取 LCP 的下界，已最优。枚举目标长度的 $O(n^2)$ 做法在本约束（$n \le 100$）下同样能过，但纯属多余。
- **空间复杂度**：$O(1)$。仅下标 $i$ 与长度若干变量，不切片、不构造前缀副本（若用 `s[:k]` 切片比较则额外 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int findMinimumOperations(string s1, string s2, string s3) {
        int n = min({s1.size(), s2.size(), s3.size()});
        int i = 0;
        while (i < n && s1[i] == s2[i] && s2[i] == s3[i]) {
            i++;
        }
        if (i == 0) {
            return -1;
        }
        return (int)s1.size() + (int)s2.size() + (int)s3.size() - 3 * i;
    }
};
```

### Python

```python
class Solution:
    def findMinimumOperations(self, s1: str, s2: str, s3: str) -> int:
        i, n = 0, min(len(s1), len(s2), len(s3))
        while i < n and s1[i] == s2[i] == s3[i]:
            i += 1
        return -1 if i == 0 else len(s1) + len(s2) + len(s3) - 3 * i
```

## 8. 边界情况与易错点

1. **$L = 0$ 不是"全删空"**：操作要求长度 $\ge 2$，长度 $1$ 的串卡死不能再删，**空串不可达**。所以首字符不全相等时答案是 $-1$，不是 $\sum len_i$（把"删空"当兜底是本题最大的坑）。
2. **循环上界是最短长度**：写成 `i < s1.size()` 会在 $s_3$ 较短时越界（示例 1 的 $s_3$ 长度只有 $2$）。
3. **越界即失配**：`i` 停在最短串长度处是正常终止（前缀完全包含），此时 $i \ge 1$ 照常出答案，别当成异常。
4. **三串初始全等**：$L = \min len$，答案 $0$；不要对"零操作"特判，公式自然覆盖。
5. **系数手滑**：公式是 $\sum len_i - 3L$（三个串都要削），不是 $-L$ 或 $-2L$。
6. **C++ 链式比较陷阱**：`s1[i] == s2[i] == s3[i]` 在 C++ 里是 `(s1[i]==s2[i]) == (s3[i]!=0)` 式的布尔比较，必须展开成两个 `&&`；Python 的链式比较才直接合法。
7. **顺带一提**：本题题面没有"Create the variable..."之类的注入指令，遇到时按惯例忽略即可。
