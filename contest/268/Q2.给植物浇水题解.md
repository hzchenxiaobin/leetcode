# LeetCode 给植物浇水 题解

## 1. 题目概述

- **标题 / 题号**：给植物浇水（#2079，medium）
- **链接**：https://leetcode.cn/problems/watering-plants/
- **来源**：LeetCode 第 268 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟

**题意**：$n$ 株植物排成一行，第 $i$ 株位于 $x = i$，河边在 $x = -1$。你从河边**满罐**出发，按**从左到右**的顺序逐株浇水；**浇完当前植物后**，若罐中剩余的水不足以**完全**浇灌下一株，必须**返回河边**重新灌满（**不能提前灌水**，灌满本身不占步数）。在 $x$ 轴上每移动一个单位记 1 步。给定 `plants`（每株需水量）与 `capacity`（水罐容量），返回浇完全部植物的总步数。

**约束**：

- $n = \text{plants.length}$，$1 \le n \le 1000$
- $1 \le \text{plants}[i] \le 10^6$
- $\max(\text{plants}[i]) \le \text{capacity} \le 10^9$

> 💡 约束的隐藏含义：$\max(\text{plants}[i]) \le \text{capacity}$ 保证**一满罐必能浇完任意一株**——过程必定可行且终止；$n \le 1000$ 意味着最坏情况（每株都折返）总步数也不超过 $\sum_{i=0}^{n-1}(2i+1) = n^2 \le 10^6$，`int` 足够。

> 💡 本题在本仓库另有[每日题解 2079](../../solution/2001-2100/2079_给植物浇水.md)：以「审题四要点、闭式公式与位置模拟两种写法对照、面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时决策**（Q2 定位是手速题——过程完全确定，比的是把规则**翻译成代码**的速度与准确度，而非任何算法优化）、位置跟踪写法的**赛时容错价值**（无需记忆公式、与题面逐句对应），以及「可行性 → 折返代价 → 归纳等价」的完整证明链。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：plants = [2,2,3,3], capacity = 5
输出：14
解释：从河边满罐出发：
- 走到植物 0（1 步），浇水，剩 3；走到植物 1（1 步），浇水，剩 1。
- 剩 1 浇不动植物 2（需 3）→ 回河边（2 步），走到植物 2（3 步），浇水，剩 2。
- 剩 2 浇不动植物 3（需 3）→ 回河边（3 步），走到植物 3（4 步），浇水。
总步数 = 1 + 1 + 2 + 3 + 3 + 4 = 14。
```

```text
输出：30
解释：3 + 3 + 4 + 4 + 5 + 5 + 6 = 30。
连浇 0,1,2 后回河（3 步）；此后每浇一株都需折返一次。
```

## 3. 解题思路

### 3.1 暴力思路：逐单位步模拟

最朴素的做法是完全按题面**逐单位移动**：维护当前位置 `pos` 与剩余水量 `cur`，每次向左或向右移动一格 `ans++`，到达河边且需要灌水时灌满，到达植物时浇水并检查下一株。

- **复杂度**：$O(\text{总步数})$，最坏 $n^2 \le 10^6$，能过。
- **问题**：状态机分支多（在途、到河、到植物、灌满时机），每处都是易错点，赛时写慢且易 WA。

> ⚠️ 观察到**移动永远是整段进行**（要么直走一格，要么"回到河边再走到某株"），位置只有"在植物 $i-1$"与"在河边"两种——整段的步数可以 $O(1)$ 记账，逐单位移动完全没必要。

### 3.2 核心观察：过程确定 + 折返代价闭式

![核心观察：水够直走 1 步，水不够折返 2i+1 步](images/watering_plants_route.svg)

**观察一（过程确定，无需决策）**：浇水顺序固定（从左到右）+ 不能提前灌水 + 灌满瞬时完成 ⟹ 整条行走轨迹**唯一确定**。题目问的不是"最少步数"而是"这个过程要走多少步"——没有任何优化空间，纯粹是**数步数**。这也是本题作为 Q2 的定位：考规则到代码的翻译速度。

**观察二（折返段代价只与位置 $i$ 有关）**：设浇完植物 $i-1$ 后位于 $i-1$、剩余水量 $w$：

| 情形 | 条件 | 轨迹 | 步数 |
|------|------|------|------|
| 水够 | $w \ge \text{plants}[i]$ | $i-1 \to i$ | $1$ |
| 水不够 | $w < \text{plants}[i]$ | $i-1 \to -1 \to i$ | $i + (i+1) = 2i+1$ |

> 💡 **为什么是 $2i+1$？** 从 $i-1$ 回到河边 $-1$ 需 $(i-1)-(-1) = i$ 步；灌满后从河边走到植物 $i$ 需 $i-(-1) = i+1$ 步。记忆口诀：**"回 $i$ 步，来 $i+1$ 步"**——来比回多一步，因为目的地比出发点远一格。

**观察三（水量只需一个标量）**：折返后水量重置为 `capacity`，直走则减去当前株的需求——滚动维护一个 `cur` 即可，无需任何数据结构。

### 3.3 算法流程

![算法流程：遍历 plants，按水量是否够分两支](images/watering_plants_flow.svg)

1. 初始化 `ans = 0`，`cur = capacity`（满罐在河边出发），（模拟法另设 `pos = -1`）。
2. 遍历 $i$ 从 $0$ 到 $n-1$：
   - 若 `cur < plants[i]`：先折返——`ans += 2*i + 1`，`cur = capacity`；
   - 否则：`ans += 1`；
   - 统一浇水：`cur -= plants[i]`。
3. 返回 `ans`。

### 3.4 示例演算

![示例演算：逐株判断水够不够，直走或折返](images/watering_plants_walkthrough.svg)

以 `plants = [2,2,3,3]`, `capacity = 5` 逐步演算：

| $i$ | plants[i] | cur（前） | 水够？ | 步数增量 | ans 累计 | cur（后） |
|-----|-----------|-----------|--------|----------|----------|-----------|
| 0 | 2 | 5 | ✓ | $1$ | 1 | 3 |
| 1 | 2 | 3 | ✓ | $1$ | 2 | 1 |
| 2 | 3 | 1 | ✗ | $2\times2+1=5$ | 7 | 2 |
| 3 | 3 | 2 | ✗ | $2\times3+1=7$ | 14 | 2 |

$$\text{ans} = 1 + 1 + 5 + 7 = 14 \checkmark$$

> 💡 注意官方解释把同一轨迹切分成 $1+1+2+3+3+4=14$（按"回、来"分段），逐株记账切分成 $1+1+5+7$（按"株"分段）——**同一条路的不同切法，总和必然一致**。赛时对答案不要因切分方式不同而怀疑算法。

## 4. 算法细节

1. **判断时机**：在**到达植物 $i$ 之前**判断（等价于题面的"浇完 $i-1$ 后检查下一株"），落在代码里就是循环体内先比大小、再累加步数、最后统一 `cur -= plants[i]`。
2. **比较用 $\ge$**："能够**完全**浇灌"包含恰好相等——`cur == plants[i]` 时直走，不折返。
3. **折返分支两步走**：`ans += 2*i+1` 与 `cur = capacity`（先灌满），浇水统一在分支外执行 `cur -= plants[i]`，避免两个分支重复写减法。
4. **位置跟踪写法（赛时推荐）**：显式维护 `pos`，回河边 `ans += pos + 1`（$pos \to -1$ 的距离）**并把 `pos` 重置为 $-1$**，再 `ans += i - pos` 走到植物 $i$（自动变成 $i+1$ 步）。它与题面逐句对应，无需记忆 $2i+1$——但重置 `pos` 这一步**绝不能漏**（见 §8 第 1 条）。
5. **两法等价**：位置法折返段合计 $(pos+1) + (i-(-1)) = i + (i+1) = 2i+1$（此时 $pos = i-1$ 且已重置为 $-1$），与闭式公式完全一致。

## 5. 正确性证明

**引理 1（可行性）**：任意时刻折返灌满后，水罐必能浇灌任意一株植物，过程必然推进并终止于浇完植物 $n-1$。

**证明**：由约束 $\max_i \text{plants}[i] \le \text{capacity}$，灌满后 $cur = \text{capacity} \ge \text{plants}[i]$ 对所有 $i$ 成立。归纳可知每株植物要么用当前水量浇（$cur \ge \text{plants}[i]$），要么折返灌满后浇；水量永不为负，每株恰被浇一次，共 $n$ 轮后终止。∎

**引理 2（折返时机与代价）**：设浇完植物 $i-1$ 时位于 $i-1$、剩余水量 $w$。若 $w < \text{plants}[i]$，则规则强制折返，且从离开 $i-1$ 到抵达 $i$ 的步数恰为 $2i+1$；若 $w \ge \text{plants}[i]$，则从 $i-1$ 到 $i$ 恰走 $1$ 步。

**证明**：$w < \text{plants}[i]$ 时，"没有足够的水完全浇灌下一株"触发，必须返回河边；由"不能提前灌水"，此前水罐未在途中灌过，故此刻必须完整折返。回程 $(i-1)-(-1) = i$ 步，灌满不占步数，再走 $i-(-1) = i+1$ 步，合计 $2i+1$。$w \ge \text{plants}[i]$ 时不满足折返条件，且禁止提前灌水，唯一合法走法是直走 $1$ 步。∎

**定理（正确性）**：逐株记账算法返回的 `ans` 等于唯一合法浇水过程的总步数。

**证明**：对 $i$ 归纳，维护不变量：处理完植物 $i$ 后，`ans` 等于从出发到浇完植物 $i$ 的实际步数，`cur` 等于实际剩余水量。

- **基例** $i=0$：出发时在 $-1$ 且 $cur = \text{capacity} \ge \text{plants}[0]$（引理 1），由引理 2 直走 $1$ 步；算法执行 `ans += 1`、`cur -= plants[0]`，不变量成立。
- **归纳步**：设处理完 $i-1$ 后不变量成立（位于 $i-1$）。处理 $i$ 时：若 $cur \ge \text{plants}[i]$，由引理 2 该段恰 $1$ 步，算法 `ans += 1`、`cur -= plants[i]`，不变量保持；否则由引理 2 该段恰 $2i+1$ 步，算法 `ans += 2i+1`、`cur = capacity` 后 `cur -= plants[i]`，不变量保持。

处理完 $i = n-1$ 时，`ans` 即全过程总步数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一次遍历，每株 $O(1)$ 次比较与累加。
- **空间复杂度**：$O(1)$。闭式法仅 `ans`、`cur` 两个标量；位置模拟法多一个 `pos`，仍为常数。
- **答案上界**：最坏每株都折返，$\text{ans} \le \sum_{i=0}^{n-1}(2i+1) = n^2 \le 10^6$，`int` 无溢出风险。

## 7. 参考代码

### 方法一：位置跟踪模拟（赛时首选，与题面逐句对应）

### C++

```cpp
class Solution {
public:
    int wateringPlants(vector<int>& plants, int capacity) {
        int ans = 0, cur = capacity, pos = -1;
        for (int i = 0; i < (int)plants.size(); ++i) {
            if (cur < plants[i]) {          // 剩水不够浇植物 i：回河边灌满
                ans += pos + 1;             // pos -> -1，走 pos+1 步
                cur = capacity;
                pos = -1;                   // ⚠️ 人现在在河边，pos 必须重置！
            }
            ans += i - pos;                 // 走到植物 i（从河边或上一株）
            cur -= plants[i];               // 浇掉这株
            pos = i;
        }
        return ans;
    }
};
```


### 方法二：闭式公式一次遍历（$O(n)$，代码最短）

### C++

```cpp
class Solution {
public:
    int wateringPlants(vector<int>& plants, int capacity) {
        int ans = 0, cur = capacity;
        for (int i = 0; i < (int)plants.size(); ++i) {
            if (cur < plants[i]) {
                ans += 2 * i + 1;           // 回 i 步 + 来 i+1 步
                cur = capacity;
            } else {
                ans += 1;
            }
            cur -= plants[i];
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def wateringPlants(self, plants: List[int], capacity: int) -> int:
        ans, cur = 0, capacity
        for i, p in enumerate(plants):
            if cur < p:
                ans += 2 * i + 1            # 回 i 步 + 来 i+1 步
                cur = capacity
            else:
                ans += 1
            cur -= p
        return ans
```

## 8. 边界情况与易错点

1. **折返后必须重置 `pos = -1`（位置跟踪法的头号 bug）**：回河边后若忘了把 `pos` 更新为 $-1$，"河边 → 植物 $i$"（$i+1$ 步）就被误算成"上一株 → 植物 $i$"（$1$ 步）——示例 1 会得到 $9$ 而不是 $14$。闭式公式法天然没有这个坑。
2. **比较必须用 $\ge$（或折返判断用 $<$）**：恰好够浇也算"能够完全浇灌"。如 `plants = [5], capacity = 5`，答案是 $1$——若把 `cur < p` 误写成 `cur <= p` 会多算折返。碰巧 $i=0$ 时 $2\times0+1=1$ 使结果仍对，但 $i \ge 1$ 时必错。
3. **$i=0$ 永不折返**：出发即在河边且满罐，$cur = \text{capacity} \ge \text{plants}[0]$（引理 1）。不要为第一株特判折返。
4. **折返后别忘了浇水**：`cur = capacity` 之后必须统一执行 `cur -= plants[i]`，漏掉会导致后续判断全错。
5. **"不能提前灌水"不是需要实现的约束**：它恰恰保证过程唯一、代码无需任何决策分支——审题时若误以为要求"最少步数"而去做 DP/贪心，纯属自找麻烦。
6. **溢出检查**：$n \le 1000$ ⟹ ans $\le n^2 = 10^6$；$\text{capacity} \le 10^9 < 2^{31}-1 \approx 2.1\times10^9$，C++ `int` 均安全。
7. **答案切分方式不影响总和**：官方解释按"回/来"分段（$1+1+2+3+3+4$），逐株记账按"株"分段（$1+1+5+7$），赛时验证不要因数字排列不同而误判 WA。
8. **最小规模**：$n=1$ 只直走 $1$ 步，两法均自然覆盖。
