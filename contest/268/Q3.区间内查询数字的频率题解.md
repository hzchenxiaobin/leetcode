# LeetCode 区间内查询数字的频率 题解

## 1. 题目概述

- **标题 / 题号**：区间内查询数字的频率（#2080，medium）
- **链接**：https://leetcode.cn/problems/range-frequency-queries/
- **来源**：LeetCode 第 268 场周赛 Q3
- **难度**：中等
- **标签**：设计、哈希表、二分查找、数组

**题意**：给定一个**构造后不可变**的下标从 0 开始的整数数组 `arr`，设计数据结构 `RangeFreqQuery`：

- `RangeFreqQuery(arr)`：用 `arr` 构造实例（只调用一次）；
- `query(left, right, value)`：返回**子数组** `arr[left...right]`（含两端）中值等于 `value` 的元素个数，可调用多达 $10^5$ 次。

**约束**：

- $1 \le n = \text{arr.length} \le 10^5$
- $1 \le \text{arr}[i], \text{value} \le 10^4$
- $0 \le \text{left} \le \text{right} < n$
- `query` 的调用次数 $q \le 10^5$

> 💡 **赛时审题三要点**：① 数组**不可变** → 放心做一次性预处理，这是「离线预处理换在线查询」的明确信号；② $n$ 与 $q$ **同阶**（都到 $10^5$）→ 单次查询必须做到 $O(\log n)$ 级别，逐元素扫描必超时；③ 值域虽只有 $10^4$，但 $10^4$ 份「每值前缀和」共 $10^9$ 空间 → 直接排除（见 §3.1）。

> 💡 本题在本仓库另有[每日题解 2080](../../solution/2001-2100/2080_区间内查询数字的频率.md)：以「结构推导、与每值前缀和的对比、面试问答」展开。本篇按**周赛复盘视角**重写：侧重**赛时决策链**（暴力 → 前缀和 → 正解的取舍应在两分钟内走完）、值域桶的**常数优化**、以及「有序列表三分段」的完整证明链。两篇互为印证。

## 2. 示例

["RangeFreqQuery", "query", "query"]
[[[12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]], [1, 2, 4], [0, 11, 33]]
输出：
[null, 1, 2]

解释：

query(1, 2, 4)    → 子数组 [33, 4]，4 出现 1 次
query(0, 11, 33)  → 整个数组，33 出现 2 次
```

解释：子数组 arr[2..6] = [4, 56, 22, 2, 34]，不含 33。

```

**补充示例 3（value 从未出现）**

## 3. 解题思路

### 3.1 暴力思路与两步排除

**暴力**：每次 `query` 线性扫描 `arr[left..right]` 计数。单次 $O(n)$，总计 $O(nq) = 10^{10}$，**超时**——浪费在于每个查询都把同一批元素重扫一遍。

**看似更优的每值前缀和**：为每个 `value` 维护出现次数前缀和 `pre[value][i]`，查询 $O(1)$。但值域 $V = 10^4$，空间 $n \times V = 10^9$，**爆空间**——前缀和把信息按「值 × 位置」二维铺开，而每个值平均只出现 $n/V = 10$ 次，绝大部分格子是零。

> ⚠️ 赛时决策链「暴力超时 → 前缀和爆空间 → ?」应在一两分钟内走完：既不能逐元素重扫（时间不够），也不能按值铺满（空间不够），出路是**按值分组、组内只存非零位置**——哈希表 + 有序下标列表。

### 3.2 核心观察：值 → 升序下标列表 + 二分计数

![核心观察：值映射到升序下标列表，两次二分计数](images/rfq268_concept.svg)

**第一步（构造）**：用哈希表 `pos` 把每个 `value` 映射到它的**全部出现下标**。构造时按下标 $i = 0, 1, \dots, n-1$ 递增遍历、逐个尾部追加，列表**天然升序**，无需排序：

$$\text{pos}[v] = [\,i_1, i_2, \dots, i_k\,], \quad i_1 < i_2 < \dots < i_k$$

**第二步（查询）**：`value` 在 `arr[left..right]` 中的频数，等于其出现下标落在 $[\text{left}, \text{right}]$ 内的次数。在升序列表 `idx = pos[value]` 上两次二分：

- `lo = lower_bound(idx, left)`：首个 $\ge \text{left}$ 的**列表位置**；
- `hi = upper_bound(idx, right)`：首个 $> \text{right}$ 的**列表位置**。

则 $[\text{lo}, \text{hi})$ 内的元素下标**恰好**落在 $[\text{left}, \text{right}]$ 内，频数 $= \text{hi} - \text{lo}$。

> 💡 **一句话**：两次二分把升序列表切成三段——$< \text{left}$、$[\text{left}, \text{right}]$、$> \text{right}$，中段长度就是答案。`value` 不存在或区间内无该值时中段为空，`hi − lo = 0` 天然正确，无需特判。

> ⚠️ **右端必须用 `upper_bound`**：区间**含** `right`，下标恰为 `right` 的出现应被计入；`upper_bound` 找首个**严格大于** `right` 的位置，正好把它留在中段。误用 `lower_bound(right)` 会漏数一次（见 §8 第 1 条）。

### 3.3 算法流程

![算法流程：构造 O(n)，单次查询 O(log n)](images/rfq268_flow.svg)

**构造 `RangeFreqQuery(arr)`**：

1. 建立空哈希表（或值域大小的桶数组）`pos`；
2. 顺序遍历 `arr`，执行 `pos[arr[i]].append(i)`；
3. 完毕后每个 `pos[v]` 即升序下标列表，所有列表长度之和恰为 $n$。

**查询 `query(left, right, value)`**：

1. 取 `idx = pos[value]`，若不存在（或为空）直接返回 0；
2. `lo = bisect_left(idx, left)`，`hi = bisect_right(idx, right)`；
3. 返回 `hi − lo`。

### 3.4 示例演算

![示例演算：三次查询的 lo / hi 与频数](images/rfq268_walkthrough.svg)

构造 `arr = [12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]` 后的关键条目：

| value | 下标列表 idx |
|-------|--------------|
| 33    | [1, 7]       |
| 4     | [2]          |
| 22    | [4, 8]       |
| 34    | [6, 10]      |
| 56    | [3, 11]      |
| 12    | [0, 9]       |

| 查询 | idx | lo | hi | hi − lo | 校验 |
|------|-----|----|----|---------|------|
| `query(1, 2, 4)` | [2] | 0 | 1 | **1** | [33, 4] 中 4 出现 1 次 ✓ |
| `query(0, 11, 33)` | [1, 7] | 0 | 2 | **2** | 全数组 33 出现 2 次 ✓ |
| `query(2, 6, 33)` | [1, 7] | 1 | 1 | **0** | [4,56,22,2,34] 无 33 ✓ |

> 💡 第三行是**值出现过但区间内没有**的情形：`lower_bound([1,7], 2)` 停在下标 7（列表位置 1），`upper_bound([1,7], 6)` 也停在下标 7（列表位置 1），两端夹出**空段**，$1 - 1 = 0$。这正是三分段切分「中段为空」的自然结果，无需任何特判。

## 4. 算法细节

1. **天然升序免排序**：构造按下标递增遍历、尾部追加，列表自动升序——省去每个列表 $O(k \log k)$ 的排序，是「按出现顺序收集」带来的免费性质。
2. **二分对象是「列表位置」**：`lo`、`hi` 是 `idx` **内部**的位置（C++ 中为迭代器减 `idx.begin()`），`hi − lo` 直接就是**个数**，与数组下标本身的数值无关，不要把两者混在一起做减法。
3. **桶数组替代哈希表（本题专属提速）**：值域 $1 \le \text{arr}[i] \le 10^4$ 很小，可用 `vector<vector<int>> pos(10001)`（Python 用 `[[] for _ in range(10001)]`）代替 `unordered_map`——省去哈希函数与再哈希开销，构造和查询的常数都更小。值域大时才退回哈希表。
4. **缺值短路**：查询前先判 `value` 是否在 `pos` 中，不在直接返回 0。即使不判，空列表上两个二分都返回 0，`hi − lo = 0` 仍正确——显式短路是常数优化与可读性，不是正确性必需（桶数组版则必须先判 `value` 是否越界值域，见 §8 第 4 条）。
5. **C++ 用 `find` 不用 `[]`**：`pos.find(value)` 拿到迭代器后直接引用 `it->second`，避免 `pos[value]` 的二次哈希查找，后者还可能**意外插入**空键。
6. **Python 用 `.get()` 不用 `[]`**：`defaultdict` / `dict[]` 查询不存在的键会**插入**空键，$10^5$ 次不存在的查询能让表平白膨胀（本题无碍但是坏习惯）；`self.pos.get(value)` 返回 `None`，`if not idx: return 0` 一并拦下 `None` 与空列表。

## 5. 正确性证明

**引理 1（完备性与有序性）**：对任意值 $v$，`pos[v]` 恰为 $v$ 在 `arr` 中**全部**出现下标的升序排列。

**证明**：构造遍历 $i = 0, 1, \dots, n-1$，当且仅当 $\text{arr}[i] = v$ 时把 $i$ 追加到 `pos[v]` 尾部——每个满足条件的下标恰被追加一次（完备、无重复），且追加时表中已有元素均来自更小的 $i$，故任意时刻表中元素严格递增。∎

**引理 2（三分段切分）**：设 `idx` 为升序列表，$\text{lo} = \text{lower\_bound}(\text{idx}, L)$，$\text{hi} = \text{upper\_bound}(\text{idx}, R)$，则对任意列表位置 $j$：

$$\text{idx}[j] \in [L, R] \iff \text{lo} \le j < \text{hi}$$

**证明**：由 `lower_bound` 的定义，$j < \text{lo} \Rightarrow \text{idx}[j] < L$，而 $j \ge \text{lo}$（且 $j$ 在表内）时 $\text{idx}[j] \ge \text{idx}[\text{lo}] \ge L$；由 `upper_bound` 的定义，$j < \text{hi} \Rightarrow \text{idx}[j] \le R$，而 $j \ge \text{hi}$ 时 $\text{idx}[j] > R$。于是 $j \in [\text{lo}, \text{hi})$ 当且仅当 $\text{idx}[j] \ge L$ 且 $\text{idx}[j] \le R$，即 $\text{idx}[j] \in [L, R]$。∎

**定理（查询正确性）**：对任意合法查询 `(left, right, value)`，算法返回值等于 `arr[left..right]` 中 `value` 的出现次数。

**证明**：`value` 在 `arr[left..right]` 中出现一次，当且仅当它某次出现的下标 $i$ 满足 $\text{left} \le i \le \text{right}$。由引理 1，`value` 的全部出现下标恰为 `idx = pos[value]` 的全部元素（`value` 从未出现时 `idx` 为空，频数为 0，算法同样返回 0）；由引理 2（取 $L = \text{left}$、$R = \text{right}$），其中下标落在 $[\text{left}, \text{right}]$ 内的元素恰为 `idx[lo..hi−1]`，共 $\text{hi} − \text{lo}$ 个。故返回 `hi − lo` 即所求频数。∎

## 6. 复杂度分析

- **构造时间**：$O(n)$。一次遍历，每个下标尾部追加摊还 $O(1)$。
- **单次查询时间**：$O(\log k)$，$k$ 为 `value` 的出现次数（$k \le n$，最坏 $O(\log n)$）——二分只在**该值自己的列表**上进行，与其它值的出现位置无关。
- **总时间**：$O(n + q\log n)$。$n, q \le 10^5$ 时约 $10^5 + 10^5 \times 17 \approx 1.8 \times 10^6$ 次基本操作，轻松通过。
- **空间**：$O(n)$（哈希版）——所有下标列表长度之和恰为 $n$；桶数组版额外 $O(V) = 10^4$ 个空桶，即 $O(n + V)$。

## 7. 参考代码

### 方法一：哈希表 + 二分（通用写法，值域大时也适用）

### C++

```cpp
class RangeFreqQuery {
    unordered_map<int, vector<int>> pos;   // value -> 升序下标列表
public:
    RangeFreqQuery(vector<int>& arr) {
        for (int i = 0; i < (int)arr.size(); ++i) {
            pos[arr[i]].push_back(i);      // 下标递增追加，天然升序
        }
    }

    int query(int left, int right, int value) {
        auto it = pos.find(value);
        if (it == pos.end()) return 0;     // 值从未出现
        const vector<int>& idx = it->second;
        int lo = lower_bound(idx.begin(), idx.end(), left)  - idx.begin();
        int hi = upper_bound(idx.begin(), idx.end(), right) - idx.begin();
        return hi - lo;                    // 中段长度 = 区间内频数
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right
from collections import defaultdict


class RangeFreqQuery:
    def __init__(self, arr: List[int]):
        self.pos = defaultdict(list)
        for i, v in enumerate(arr):
            self.pos[v].append(i)          # 下标递增追加，天然升序

    def query(self, left: int, right: int, value: int) -> int:
        idx = self.pos.get(value)          # 不用 []，避免插入空键
        if not idx:
            return 0
        return bisect_right(idx, right) - bisect_left(idx, left)
```

### 方法二：值域桶数组 + 二分（本题 $1 \le \text{arr}[i] \le 10^4$，赛时提速）

### C++

```cpp
class RangeFreqQuery {
    vector<vector<int>> pos;               // pos[v] = v 的升序下标列表
public:
    RangeFreqQuery(vector<int>& arr) : pos(10001) {
        for (int i = 0; i < (int)arr.size(); ++i) {
            pos[arr[i]].push_back(i);
        }
    }

    int query(int left, int right, int value) {
        if (value < 1 || value > 10000) return 0;   // 防御，约束内不会触发
        const vector<int>& idx = pos[value];
        int lo = lower_bound(idx.begin(), idx.end(), left)  - idx.begin();
        int hi = upper_bound(idx.begin(), idx.end(), right) - idx.begin();
        return hi - lo;
    }
};
```

### Python

```python
from bisect import bisect_left, bisect_right


class RangeFreqQuery:
    def __init__(self, arr: List[int]):
        self.pos = [[] for _ in range(10001)]
        for i, v in enumerate(arr):
            self.pos[v].append(i)

    def query(self, left: int, right: int, value: int) -> int:
        if not (1 <= value <= 10000):
            return 0
        idx = self.pos[value]
        return bisect_right(idx, right) - bisect_left(idx, left)
```

> 💡 方法二省掉哈希开销，构造约快数倍；代价是要防御值域外的 `value`（约束保证 $1 \le \text{value} \le 10^4$，实际不会触发）。两法复杂度同阶，赛时任选其一都能过——**选定一种写完就好，别在两种写法间反复横跳浪费时间**。

## 8. 边界情况与易错点

1. **右端二分用错（头号 bug）**：`hi` 必须取 `upper_bound(right)`（首个**严格大于** `right` 的位置）。误用 `lower_bound(right)` 会漏数下标恰为 `right` 的出现——示例 1 中因 33 的下标是 1、7（远离 11）而不受影响，属于**隐性 WA**：小数据过了，构造出「该值恰在区间右端」的数据必错。
2. **`lo`、`hi` 是列表位置不是数组下标**：直接 `hi − lo` 即个数；若误写成 `idx[hi-1] − idx[lo]` 之类按下标数值做差，得到的是「下标跨度」，完全错误。
3. **Python 查询误用 `[]` 触发插入**：`self.pos[value]` 对不存在的键会插入空列表（`defaultdict` 尤甚），既污染结构又拖慢后续查询；应使用 `.get(value)` 并对 `None` / 空列表统一 `return 0`。
4. **桶数组版的值域防御**：`value` 越界时 C++ `pos[value]` 是**未定义行为**、Python 直接抛 `IndexError`——取桶前必须判断（约束内不会发生，但防御成本为零）。
5. **`left == right` 单元素区间**：合法输入，两次二分自然处理（中段长 0 或 1），无需特判。
6. **全数组同值**：如 `arr` 为 $10^5$ 个 7，`pos[7]` 长度 $10^5$，单次查询仍只需 $O(\log 10^5) \approx 17$ 步二分——这正是对数复杂度的意义，不必担心列表过长。
7. **构造只做一次**：不要在 `query` 里惰性建表或重扫数组——$q$ 次 $O(n)$ 必超时；预处理全部放进构造函数。
8. **溢出**：`hi − lo ≤ n ≤ 10^5`，`int` 无风险。
