# LeetCode 子数组最大平均数 II 题解

## 1. 题目概述

- **标题 / 题号**：子数组最大平均数 II（#644，hard）
- **链接**：https://leetcode.cn/problems/maximum-average-subarray-ii/
- **来源**：LeetCode 第 41 场周赛 Q3
- **难度**：困难
- **标签**：数组、二分查找、前缀和

**题意**：给定长度为 $n$ 的整数数组 $\textit{nums}$ 和整数 $k$，在所有长度 **大于等于** $k$ 的连续子数组中，求**最大的平均值**，返回这个平均值。

与同场 Q1「子数组最大平均数 I」的唯一差别是：Q1 的子数组长度被钉死为 $k$，一次滑动窗口即可；本题长度不固定，候选区间从 $O(n)$ 个暴涨到 $O(n^2)$ 个，这正是难度所在。

**约束**：

- $1 \le k \le n \le 10^4$
- $-10^4 \le \textit{nums}[i] \le 10^4$
- 与标准答案误差小于 $10^{-5}$ 即判为正确

## 2. 示例

**示例 1**

```text
输入：nums = [1,12,-5,-6,50,3], k = 4
输出：12.75000
解释：长度 4 时最大平均值为 (12-5-6+50)/4 = 12.75；
      长度 5 时最大平均值为 (12-5-6+50+3)/5 = 10.8；
      长度 6 时只有整个数组，平均值为 55/6 ≈ 9.16667。
      因此答案为 12.75。
```

**示例 2**

```text
输入：nums = [5], k = 1
输出：5.00000
解释：只有一个长度 1 的子数组，平均值为 5。
```

**补充示例**（负数情形，官方题面未给出）

```text
输入：nums = [-1,-2,-3], k = 2
输出：-1.50000
解释：候选为 [-1,-2]（平均 -1.5）、[-2,-3]（-2.5）、[-1,-2,-3]（-2），
      最大值为 -1.5 —— 注意答案可以是负数。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有长度 $\ge k$ 的区间：起点 $i$、终点 $j$，用前缀和 $O(1)$ 求平均，共 $\frac{(n-k+1)(n-k+2)}{2}$ 个候选，复杂度 $O(n^2)$。$n = 10^4$ 时约有 $5\times 10^7$ 个候选区间，C++ 也许能卡着过，Python 必挂；更重要的是它完全没利用「**平均值**」这个目标函数的结构。

换个角度：平均值是「和 ÷ 长度」，比较两个候选需要除法，没有可加性。但如果先**猜一个答案** $x$，问「是否存在平均值 $\ge x$ 的子数组」，问题就变成纯粹的**加法**判定——这是本题的突破口。

### 3.2 核心观察：判定函数单调 ⇒ 对答案二分

![check(x) 单调不增，对答案二分](images/wc41_q3_monotone_binary_search.svg)

定义谓词

$$\text{check}(x) = \Bigl[\exists\, i < j\ \text{且}\ j - i \ge k:\ \frac{1}{j-i}\sum_{t=i}^{j-1}\textit{nums}[t] \ge x\Bigr]$$

**单调性**：若 $\text{check}(x)$ 为真，那么对任意 $y < x$，$\text{check}(y)$ 也一定为真——因为让 $x$ 成立的那个子数组，其平均值同样 $\ge x > y$，直接拿来用即可。

于是 $\text{check}$ 在实数轴上是一条「先真后假」的阶梯：分界点恰好就是**最大的可行 $x$**，也就是题目要的答案。既然谓词单调，就可以二分：

- 搜索区间 $[\min(\textit{nums}),\ \max(\textit{nums})]$：任何子数组的平均值都不会越出这个范围，答案一定落在其中。
- 每轮取中点 $\textit{mid}$，若 $\text{check}(\textit{mid})$ 为真说明答案 $\ge \textit{mid}$，令 $\textit{lo} = \textit{mid}$；否则 $\textit{hi} = \textit{mid}$。
- 解空间是**实数**而非整数，不需要离散化，靠固定迭代次数收敛即可。

剩下的唯一问题是：如何在 $O(n)$（而不是 $O(n^2)$）内判定 $\text{check}(x)$。

### 3.3 算法流程：O(n) 判定 check(x)

![判定 check(x)：前缀和 + 滚动维护最小前缀](images/wc41_q3_check_prefix_min.svg)

把「平均 $\ge x$」改写成「和 $\ge x \cdot \text{长度}$」，再整体平移 $b[t] = \textit{nums}[t] - x$，则

$$\tfrac{1}{j-i}\sum_{t=i}^{j-1}\textit{nums}[t] \ge x \iff \sum_{t=i}^{j-1} b[t] \ge 0 \iff \textit{pre}[j] - \textit{pre}[i] \ge 0$$

其中 $\textit{pre}[0]=0$，$\textit{pre}[j]=\sum_{t<j} b[t]$。于是判定变成：**是否存在 $i \le j-k$ 使得 $\textit{pre}[j] \ge \textit{pre}[i]$**。固定右端点 $j$ 时，左端点的可用集合是前缀区间 $[0,\ j-k]$，只关心其中的**最小值**：

1. 线性扫描算出 $\textit{pre}[0..n]$，复杂度 $O(n)$。
2. 令 $\textit{minPre} = 0$（等于 $\textit{pre}[0]$）。$j$ 从 $k$ 扫到 $n$，每轮先把 $\textit{pre}[j-k]$ 并入 $\textit{minPre}$，此时 $\textit{minPre} = \min\{\textit{pre}[0..j-k]\}$。
3. 若 $\textit{pre}[j] - \textit{minPre} \ge 0$，说明存在合法左端点，直接返回 `true`。
4. 扫完仍未命中则返回 `false`。

一次判定 $O(n)$，外层固定迭代 100 轮，于是总复杂度为 $O\bigl(n \cdot \log\frac{\max-\min}{\varepsilon}\bigr)$ —— 实测 $n=10^4$、100 轮迭代时约 $2\times10^6$ 次浮点运算，Python 也只要 0.15 s。

### 3.4 示例演算

![示例演算：check(12.75) 在 j = 5 处命中](images/wc41_q3_example_walkthrough.svg)

对 `nums = [1,12,-5,-6,50,3]`、$k = 4$，二分区间为 $[-6, 50]$：

| 轮次 | mid | check(mid) | 区间更新 |
|------|-----|-----------|----------|
| 1 | 22 | 假 | $[-6, 22]$ |
| 2 | 8 | 真 | $[8, 22]$ |
| 3 | 15 | 假 | $[8, 15]$ |

继续收缩最终稳定在 $12.75$。取 $x = 12.75$ 手算判定：$b = [-11.75,-0.75,-17.75,-18.75,37.25,-9.75]$，$\textit{pre} = [0,-11.75,-12.5,-30.25,-49,-11.75,-21.5]$。

- $j = 4$：窗口 $\textit{pre}[0..0]$ 的最小值 $0$，$\textit{pre}[4] - 0 = -49 < 0$，假；
- $j = 5$：窗口 $\textit{pre}[0..1]$ 的最小值 $-11.75$，$\textit{pre}[5] - (-11.75) = 0 \ge 0$，**命中**；
- 该命中对应下标区间 $[1,4]$，即子数组 `[12,-5,-6,50]`，和 $51$、长度 $4$，平均值恰为 $51/4 = 12.75$。

## 4. 算法细节

1. **二分区间必须包含负数**：$\textit{lo}$ 取 $\min(\textit{nums})$ 而不是 $0$。全负数数组的答案可能是负值，若把 $\textit{lo}$ 设成 $0$ 就会返回一个不可行的值。
2. **用固定迭代次数而不是 `while (hi - lo > eps)`**：100 次迭代后区间长度不超过 $20000 / 2^{100}$，远小于 $10^{-5}$；固定次数既不会死循环，也不受浮点相等判断的影响。$\log_2(20000/10^{-5}) \approx 31$，所以 60 轮就足够，写 100 轮纯属保险。
3. **判定用「减 $x$ 的前缀和」**：先构造 $b[t] = \textit{nums}[t]-x$ 再累加，判定就退化成比较两个数；若保留原始前缀和，每步还要多做一次 $x\cdot(j-i)$ 的乘法，常数更大。两种写法数学上等价（都是两个 $10^8$ 量级的数相减），所以真正的精度关口在下一档的比较容差上。
4. **`minPre` 的更新顺序**：必须先用 $\textit{pre}[j-k]$ 更新 `minPre`，再比较 $\textit{pre}[j]$。初始值 `minPre = pre[0] = 0` 对应唯一合法左端点 $i = 0$（此时长度恰为 $k$）。
5. **浮点比较不要写成 `== 0`**：理论差值为 $0$ 时，浮点可能算出 $-10^{-16}$，判定会翻成假。好在 $10^{-16}$ 量级的偏差会被外层二分的 $10^{-5}$ 容差吸收，不必为此加 epsilon；反之若加一个与容差同量级的 epsilon（如 `1e-6`），就会把 `ans + 1e-6` 判成可行，最终误差顶到容差上限，属于典型的「越修越偏」。
6. **前缀数组必须保留**：判定时需要 $\textit{pre}[j]$ 与 $\textit{pre}[j-k]$ 同时在场，无法只用两个滚动变量，所以空间是 $O(n)$；若真要 $O(1)$ 空间，只能每轮重新累加，复杂度不变但常数更大。
7. **无解不存在的特判**：$n \ge k \ge 1$ 保证了长度 $\ge k$ 的子数组一定存在（整个数组就是），因此二分不需要任何空集特判。

## 5. 正确性证明

**引理 1（判定等价）**：对任意实数 $x$，$\text{check}(x)$ 为真当且仅当存在长度 $\ge k$ 的子数组平均 $\ge x$。

**证明**：设区间为 $[i, j)$，长度 $j-i \ge k$。有

$$\frac{1}{j-i}\sum_{t=i}^{j-1}\textit{nums}[t] \ge x \iff \sum_{t=i}^{j-1}\bigl(\textit{nums}[t]-x\bigr) \ge 0 \iff \textit{pre}[j] - \textit{pre}[i] \ge 0$$

三步都是等价变形：第二式由两边同乘正数 $j-i$ 得到，第三式由 $\textit{pre}$ 的定义直接展开。故判定条件与「存在平均值 $\ge x$ 的合法子数组」完全等价。∎

**引理 2（单调性）**：若 $\text{check}(x)$ 为真，则对任意 $y < x$，$\text{check}(y)$ 也为真。

**证明**：设使 $\text{check}(x)$ 成立的子数组为 $[i,j)$，其平均值为 $\mu \ge x > y$，故同一个子数组也使 $\text{check}(y)$ 成立。∎

**引理 3（扫描正确）**：对固定 $x$，扫描算法返回 `true` 当且仅当存在 $j \in [k, n]$ 与 $i \le j-k$，使 $\textit{pre}[j] \ge \textit{pre}[i]$。

**证明**：对 $j$ 归纳可证，第 $j$ 轮比较之前 $\textit{minPre} = \min\{\textit{pre}[0..j-k]\}$：$j=k$ 时只并入 $\textit{pre}[0]$，成立；之后每轮并入新增的那一个 $\textit{pre}[j-k]$，最小值只可能保持不变或变小，归纳成立。于是 $\textit{pre}[j] - \textit{minPre} \ge 0$ 等价于 $\textit{pre}[j] \ge \min\{\textit{pre}[0..j-k]\}$，即区间内存在 $i$ 满足 $\textit{pre}[j] \ge \textit{pre}[i]$。∎

**定理（误差界）**：设答案为 $\mu^*$，算法迭代 $t$ 轮后的返回值为 $\textit{lo}_t$，则 $\textit{lo}_t \le \mu^*$ 且 $\mu^* - \textit{lo}_t \le \dfrac{\max(\textit{nums}) - \min(\textit{nums})}{2^{t}}$。

**证明**：维护不变量 $\textit{lo} \le \mu^* \le \textit{hi}$。初始时 $\textit{lo} = \min(\textit{nums}) \le \mu^*$ 显然（整个数组的平均值不小于最小元素，且整个数组是合法候选）；$\textit{hi} = \max(\textit{nums}) \ge \mu^*$ 也显然（任何平均值不超过最大元素）。

每轮取 $\textit{mid} = (\textit{lo}+\textit{hi})/2$：若 $\text{check}(\textit{mid})$ 为真，由引理 1 存在平均值 $\ge \textit{mid}$ 的候选，故 $\mu^* \ge \textit{mid}$，令 $\textit{lo} = \textit{mid}$ 不变量保持；若为假，则任何 $y \ge \textit{mid}$ 都不可行——否则 $\text{check}(y)$ 为真，由引理 2 立刻推出 $\text{check}(\textit{mid})$ 也为真，矛盾——故 $\mu^* < \textit{mid}$，令 $\textit{hi} = \textit{mid}$ 不变量保持。每轮区间长度减半，$t$ 轮后 $\textit{hi}_t - \textit{lo}_t = (\max-\min)/2^t$，结合 $\textit{lo}_t \le \mu^* \le \textit{hi}_t$ 即得结论。∎

取 $t = 100$、$\max-\min \le 2\times 10^4$，误差不超过 $2\times10^4/2^{100} \ll 10^{-5}$，满足题目精度要求。

## 6. 复杂度分析

- **时间**：$O(n \log(\frac{\max-\min}{\varepsilon}))$。每轮判定先 $O(n)$ 建前缀和、再 $O(n)$ 扫描，共 $O(n)$；迭代次数固定为 100（与精度需求的对数成正比，与 $n$ 无关）。$n = 10^4$ 时约 $2\times10^6$ 次浮点运算。
- **空间**：$O(n)$。判定需要一个长度 $n+1$ 的前缀和数组；其余变量均为常数。递归栈无开销。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    bool check(const vector<int>& nums, int k, double x) {
        int n = nums.size();
        vector<double> pre(n + 1, 0.0);
        for (int i = 0; i < n; i++) {
            pre[i + 1] = pre[i] + (nums[i] - x);   // 先平移再累加，误差最小
        }
        double minPre = 0.0;                        // 即 min(pre[0..j-k])
        for (int j = k; j <= n; j++) {
            minPre = min(minPre, pre[j - k]);       // 先并入新候选
            if (pre[j] - minPre >= 0.0) return true; // 再判断是否命中
        }
        return false;
    }

    double findMaxAverage(vector<int>& nums, int k) {
        double lo = *min_element(nums.begin(), nums.end());
        double hi = *max_element(nums.begin(), nums.end());
        for (int iter = 0; iter < 100; iter++) {
            double mid = (lo + hi) / 2.0;
            if (check(nums, k, mid)) lo = mid;
            else hi = mid;
        }
        return lo;
    }
};
```

### Python

```python
class Solution:
    def findMaxAverage(self, nums: list[int], k: int) -> float:
        n = len(nums)

        def check(x: float) -> bool:
            pre = [0.0] * (n + 1)
            for i in range(n):
                pre[i + 1] = pre[i] + nums[i] - x
            min_pre = 0.0                      # min(pre[0..j-k])，初值为 pre[0]
            for j in range(k, n + 1):
                min_pre = min(min_pre, pre[j - k])
                if pre[j] - min_pre >= 0.0:
                    return True
            return False

        lo, hi = float(min(nums)), float(max(nums))
        for _ in range(100):
            mid = (lo + hi) / 2.0
            if check(mid):
                lo = mid
            else:
                hi = mid
        return lo
```

## 8. 边界情况与易错点

1. **$n = k$**：合法候选只有整个数组一个，答案就是 $\text{sum}/n$。判定退化为「$\textit{pre}[n] \ge \textit{pre}[0]$」，二分依然正确，无需特判。
2. **全为负数**：答案可能为负，$\textit{lo}$ 必须从 $\min(\textit{nums})$ 起步。若写成 `lo = 0.0`，`[-1,-2,-3], k=2` 会返回 $0$，直接 WA。
3. **$n = k = 1$**：$\min = \max$，二分区间长度恒为 $0$，100 轮空转后返回该元素，结果正确；这也说明不能把「区间长度为 0」当成异常。
4. **全零数组**：答案 $0.0$，输出 `0.00000`；别把 $\textit{lo}$ 写成「$-1$ 哨兵」之类，否则全零时二分区间跨过 $0$，虽仍收敛但白跑一轮且易在别处埋下符号错误。
5. **浮点相等陷阱**：不要用 `hi - lo == 0` 或 `pre[j] - minPre == 0` 作为终止/命中条件；固定迭代次数 + `>= 0` 判断最稳。
6. **精度与迭代次数不匹配**：若只迭代 20 轮，误差约 $2\times10^4/2^{20} \approx 0.02$，远超 $10^{-5}$ 容差；至少要 40 轮，建议 60～100 轮。
7. **警惕整数除法**：C++ 里 `nums[i] - x` 因为 $x$ 是 `double` 会正常提升为浮点；但若有人写成 `pre[j] / (j - i)` 来求平均，两侧都是整数就会截断。本题全程只用比较、不做除法，反而更安全。
8. **不要每轮重新分配大数组**（可选优化）：C++ 中可把 `pre` 提到 `check` 外部复用，避免 100 次 $O(n)$ 内存分配；逻辑不变。

**延伸思考**：

1. 若把长度限制改成**恰好落在 $[L, R]$** 内，判定时左端点集合变成滑动窗口 $[j-R,\ j-L]$，用单调队列维护窗口最小值即可，仍是 $O(n)$ 一轮。
2. 若要求**长度必须是奇数**（网格分割类问题常见），则按 $j$ 的奇偶分别开两个单调队列，分别维护偶数下标与奇数下标的最小前缀。
3. 本题的判定函数是「分段线性凹/凸」结构，理论上可以用 **Dinkelbach 迭代**（每次令 $x \leftarrow$ 当前最优子数组的平均值）以超线性速度收敛，实践中 5～10 轮就到 $10^{-10}$，但最坏复杂度不如二分稳定。
4. 若把「平均值」换成「中位数」「第 $p$ 分位数」，判定函数不再可加，本方法失效，需改用别的结构（例如中位数可用「$\ge x$ 记 $+1$、否则 $-1$ 的区间和」技巧，思路与本篇的平移完全一致）。
