# LeetCode 函数的独占时间 题解

## 1. 题目概述

- **标题 / 题号**：函数的独占时间（#636，medium）
- **链接**：https://leetcode.cn/problems/exclusive-time-of-functions/
- **来源**：LeetCode 第 41 场周赛 Q2
- **难度**：中等
- **标签**：栈、数组

**题意**：单核 CPU 上运行编号 $0 \sim n-1$ 的函数，同一时刻至多一个函数执行。调用记录在调用栈上：`start` 压栈、`end` 弹栈，**栈顶即当前执行者**。日志 `logs[i]` 形如 `id:start:t` / `id:end:t`，且两端语义**不对称**：`start:t` 表示从第 $t$ 个时间单位**开头**开始执行，`end:t` 表示在第 $t$ 个单位**末尾**结束（单位 $t$ 也算执行）。函数可递归调用自己，因此同一 id 可能在栈中出现多次。求每个函数真正占用 CPU 的时间单位总数，被它调用的子函数占用的时间不计入。

**约束**：

- $1 \le n \le 100$
- $2 \le \text{logs.length} \le 500$
- $0 \le \text{function\_id} < n$，$0 \le \text{timestamp} \le 10^9$
- 同一时间戳不会出现两个 `start`，也不会出现两个 `end`
- 每个 `start` 日志都有配对的 `end` 日志，日志按时间戳升序给出

> 💡 时间戳可达 $10^9$ 而日志只有 500 条：必须在**事件处**结算，不能逐单位扫时间轴。

## 2. 示例

**示例 1**

```text
输入：n = 2, logs = ["0:start:0","1:start:2","1:end:5","0:end:6"]
输出：[3,4]
解释：函数 0 占单位 0~1（2 个）与单位 6（1 个），共 3；函数 1 占单位 2~5，共 4。
```

**示例 2**

```text
输入：n = 1, logs = ["0:start:0","0:start:2","0:end:5","0:start:6","0:end:6","0:end:7"]
输出：[8]
解释：函数 0 递归调用自己，四段执行 2 + 4 + 1 + 1 = 8。
```

**示例 3**

```text
输入：n = 2, logs = ["0:start:0","0:start:2","0:end:5","1:start:6","1:end:6","0:end:7"]
输出：[7,1]
解释：函数 0 得 2 + 4 + 1 = 7；函数 1 只占单位 6 这一个单位。
```

## 3. 解题思路

### 3.1 暴力思路

把时间轴按单位展开成数组 `owner[0..maxT]`：遇到 `start:t` 入栈，遇到 `end:t` 就在栈顶实例的区间内逐单位标记执行者，最后统计每个 id 的单位数。

标记成本按区间长度计，总时间 $O(\text{maxT} \times \text{实例数})$。`maxT` 可达 $10^9$，光遍历一遍时间轴就超时。暴力失败的原因很直接：**时间轴被切成 $10^9$ 个单位，而真正发生事件的只有不超过 500 个位置**。

### 3.2 核心观察：栈顶即执行者 + 区间一次性结算

![时间轴按整数单位切分，start 占左端、end 占右端](images/wc41_q2_interval_settlement.svg)

三条观察把问题压到线性：

1. **栈 = 调用链**。`start` 压栈代表"新实例抢到 CPU、调用方挂起"，`end` 弹栈代表"当前实例结束、调用方恢复"。栈顶永远是当前执行的实例；递归调用只会让同一 id 在栈里出现多次，处理方式不变。
2. **相邻两条日志之间没有事件**，这一整段时间都归栈顶实例所有。维护游标 `prev` = "下一个尚未结算的时间单位"，在每条日志处把一段区间一次性结算掉，总开销只与日志条数有关。
3. **`start` 与 `end` 的语义不对称**，这是本题唯一的坑：
   - `start:t`：新实例从单位 $t$ 开头执行，旧实例只占到 $t-1$，贡献 $t - \text{prev}$（不含 $t$）；之后 `prev ← t`。
   - `end:t`：当前实例执行到单位 $t$ 末尾，单位 $t$ 也算它的，贡献 $t - \text{prev} + 1$（含 $t$）；之后 `prev ← t + 1`，调用方从 $t+1$ 恢复。

统一写成闭区间长度：

$$ \text{贡献} = \begin{cases} t - \text{prev}, & \text{日志是 start} \\ t - \text{prev} + 1, & \text{日志是 end} \end{cases} $$

> 💡 一句话记忆：`prev` 是"下一个待结算单位"，`start` 把它推到 $t$，`end` 把它推到 $t+1$；`+1` 与 `t+1` 必须成对出现。

### 3.3 算法流程

![算法流程：解析日志 → 判断 start/end → 结算并移动 prev](images/wc41_q2_algorithm_flow.svg)

1. 初始化 `res = [0] * n`、空栈 `st`、`prev = 0`。
2. 顺序读入每条日志，按 `:` 切成 `id / type / t`。
3. `start`：若栈非空，`res[st.top()] += t - prev`；然后 `st.push(id)`、`prev = t`。
4. `end`：`res[st.top()] += t - prev + 1`；然后 `st.pop()`、`prev = t + 1`。
5. 全部日志处理完，返回 `res`。

### 3.4 示例演算

![例 3 走查表：栈状态、prev 与 res 的逐步变化](images/wc41_q2_example_walkthrough.svg)

例 3 的逐步状态（栈列是**处理该条日志之前**的栈，`res` 列是处理之后）：

| 日志 | 栈（底→顶） | prev | 本步结算 | res |
|------|-------------|------|----------|-----|
| `0:start:0` | `[]` | 0 | 栈空，不结算 | `[0,0]` |
| `0:start:2` | `[0]` | 0 | `res[0] += 2 - 0 = 2` | `[2,0]` |
| `0:end:5` | `[0,0]` | 2 | `res[0] += 5 - 2 + 1 = 4` | `[6,0]` |
| `1:start:6` | `[0]` | 6 | `res[0] += 6 - 6 = 0` | `[6,0]` |
| `1:end:6` | `[0,1]` | 6 | `res[1] += 6 - 6 + 1 = 1` | `[6,1]` |
| `0:end:7` | `[0]` | 7 | `res[0] += 7 - 7 + 1 = 1` | `[7,1]` |

三点值得盯：

- 第 3 行的栈是 `[0,0]`——函数 0 递归自己，弹出的是**内层实例**；
- 第 4、5 行共用时间戳 6：`start:6` 让内层实例从单位 6 开始，`end:6` 又让它在单位 6 结束，恰好 1 个单位；
- `prev` 全程单调不减，这正是"结算区间互不重叠"的来源。

## 4. 算法细节

1. **日志解析**：id 与时间戳都可能多位，统一按两个冒号切分。C++ 用两次 `find` 加 `stoi`，Python 直接 `split(':')`；不要按固定列宽截取字段。
2. **`prev` 的初值**：取 0。程序开始前的空闲段不属于任何函数，而首条日志必然是 `start`（此时栈空、不结算），这段自然被跳过。
3. **`start` 分支的顺序**：先结算旧栈顶，再压栈，最后 `prev = t`。顺序颠倒会把这段时间记到错误实例上。
4. **`end` 分支的配对**：`res[st.top()] += t - prev + 1` 与 `prev = t + 1` 是一个整体：只写 `+1` 不改 `prev`，调用方会重复吃单位 $t$；只改 `prev` 而漏 `+1`，结束实例少算一个单位。
5. **用栈顶还是用日志 id**：合法数据中 `st.top() == id`，两种写法等价。推荐用栈顶（Python 用 `st.pop()` 的返回值），它直接对应"当前实例"，递归时也不会混淆。
6. **统一端点技巧（可选）**：把 `start:t` 映射到坐标 $2t$、`end:t` 映射到 $2t+1$，任意区间长度 = $\frac{\text{右端点} - \text{左端点} + 1}{2}$，两种日志共用一个公式，可彻底消除 `+1` 的不对称。
7. **数值范围**：单个函数的独占时间不超过程序总时长 $10^9+1 < 2^{31}$，`int` 足够；若时间戳放宽到 $10^{18}$ 则必须换 `long long`。
8. **不需要排序**：题目保证日志按时间戳升序。若要自行排序，同一时间戳必须 `start` 在前（内层实例先进入），与示例 2 的 `start:6 → end:6` 一致。

## 5. 正确性证明

记处理完前 $k$ 条日志后栈内容为 $S_k$（底→顶）、游标为 $p_k$。

**引理 1（栈不变量）**：对每个 $k$，$S_k$ 自底向上恰为当时活跃的调用链（最外层 → 最内层），栈顶即 CPU 当前执行的实例；且 $p_k$ 等于"下一个尚未被结算的时间单位"。

**证明**：对 $k$ 归纳。$k=0$ 时栈空、$p_0=0$，程序尚未开始、所有单位待结算，成立。设 $k$ 时成立，看第 $k+1$ 条日志（时间戳 $t$）：

- 若为 `start`：旧栈顶实例（栈空时无旧实例）在 $[p_k, t-1]$ 上独占执行后被挂起，新实例从单位 $t$ 开始执行；压栈后栈顶正是新实例，$p_{k+1}=t$ 即下一个待结算单位，不变量保持。
- 若为 `end`：栈顶实例在 $[p_k, t]$ 上执行后结束并弹出，栈顶回退为调用方，调用方从 $t+1$ 恢复，$p_{k+1}=t+1$，不变量保持。∎

**引理 2（结算区间恰好划分时间轴）**：算法结算的各整数区间互不相交，并集恰为程序运行过的全部时间单位；且每个区间内执行者恒为结算时的栈顶。

**证明**：由引理 1，第 $k+1$ 条日志结算的区间是 $[p_k, t-1]$（`start`）或 $[p_k, t]$（`end`）。它们的左端点恰是上一次结算的终点加一，故相邻区间首尾相接、互不相交；又 $p$ 单调不减并推进到 $t$ 或 $t+1$，最终覆盖 $[0, \max t]$，并集完整。区间内部不含任何日志事件（$t$ 是下一条日志的时间戳），故执行者在区间内不会改变，恒为当时的栈顶。∎

**定理**：算法返回的 `res` 满足 `res[f]` 等于函数 $f$ 的独占时间。

**证明**：独占时间的定义是"$f$ 的所有调用实例在 CPU 上执行的时间单位之和"。由引理 2，每个单位被结算且仅被结算一次，归属当时真正执行的实例；而该实例所属函数就是当时栈顶的值，累加进 `res` 的正是它。故 `res[f]` 恰为 $f$ 全部实例的执行单位数之和。∎

**推论**：若首条日志从单位 0 开始，则 $\sum_f \text{res}[f]$ 等于"最后一条日志的时间戳 $+1$"，可作为对拍时的自检恒等式。

## 6. 复杂度分析

- **时间**：$O(L)$，$L$ 为日志条数。每条日志一次切分 + 常数次算术与栈操作，与时间戳上限 $10^9$ 无关。
- **空间**：$O(n + L)$。结果数组 $O(n)$；栈深度上界是同时活跃的实例数，最坏为 `start` 日志条数 $O(L)$（深递归时同一 id 可重复入栈），一般 $O(n)$ 量级。
- **对比**：逐单位模拟 $O(\max t)$ 最坏 $10^9$，本做法 $O(500)$，相差六个数量级。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> exclusiveTime(int n, vector<string>& logs) {
        vector<int> res(n, 0), st;
        st.reserve(logs.size());
        int prev = 0;                      // 下一个尚未结算的时间单位
        for (const string& log : logs) {
            size_t c1 = log.find(':');
            size_t c2 = log.find(':', c1 + 1);
            int id = stoi(log.substr(0, c1));
            int t  = stoi(log.substr(c2 + 1));
            if (log[c1 + 1] == 's') {      // start：旧栈顶让出单位 t
                if (!st.empty()) res[st.back()] += t - prev;
                st.push_back(id);
                prev = t;
            } else {                       // end：栈顶吃掉单位 t
                res[st.back()] += t - prev + 1;
                st.pop_back();
                prev = t + 1;
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def exclusiveTime(self, n: int, logs: list[str]) -> list[int]:
        res = [0] * n
        st = []
        prev = 0                        # 下一个尚未结算的时间单位
        for log in logs:
            fid_s, typ, t_s = log.split(':')
            fid, t = int(fid_s), int(t_s)
            if typ == 'start':
                if st:                  # 栈空时程序还没开始，不结算
                    res[st[-1]] += t - prev
                st.append(fid)
                prev = t
            else:
                res[st.pop()] += t - prev + 1
                prev = t + 1
        return res
```

> 💡 两份代码逐行对应：切分 → 判类型 → 结算栈顶 → 更新栈与 `prev`。C++ 用 `log[c1 + 1]` 判断 `s`/`e`，避免额外构造子串。

## 8. 边界情况与易错点

1. **`start` 漏判空栈**：首条日志时栈为空，直接取 `st.top()` 会越界（Python 抛 `IndexError`），必须先 `if st`。
2. **`end` 的 `+1` 与 `prev = t + 1` 被拆开**：两者必须同时出现。示例 1 中 `1:end:5` 若漏掉 `+1`，函数 1 会算成 3 而不是 4；若把 `prev` 误写成 `t` 而非 `t + 1`，函数 0 会多算单位 5、变成 4 而不是 3。
3. **对栈去重**：不能用 `set` 记录"栈中的函数"，递归调用下同一 id 有多个实例，栈必须允许重复（示例 2 的栈就出现 `[0,0]`，递归三层则是 `[0,0,0]`）。
4. **同一时间戳既 `start` 又 `end`**：题面只保证"两个 `start` 不同时间戳、两个 `end` 不同时间戳"，`start:6` 与 `end:6` 可以共存（示例 2）。此时 $t - \text{prev} + 1 = 1$，公式自然成立，不要特判。
5. **未出现过的函数**：`res[f]` 保持 0；返回数组长度固定为 `n`，不能只返回出现过的 id。
6. **大时间戳**：`t - prev` 全程不超过 $10^9+1$，`int` 够用；但绝不能写逐单位循环，那是 $O(10^9)$。
7. **日志解析**：id 与时间戳都可能多位，不要用 `log[0]`、`log[2]` 取字段；也不要用 `sscanf("%d:%s:%d")`，`%s` 会把 `start:2` 整段吞掉。
8. **调试期断言**：可在 `end` 分支断言 `st.top() == id`，一旦日志顺序有误会立刻暴露；提交时可去掉。

**延伸思考**：

- **抢占式调度**：若 CPU 可被任意打断，日志会变成 `switch` 事件而不再是严格的 `start/end` 配对，此时要按"每次切换结算上一执行者"处理，并记录被抢占实例的剩余时间。
- **输出每个实例的区间**：把栈元素从"函数 id"改成 `(id, 起始时间)`，弹栈时即可得到该实例的 `[start, end]`；本题只求总和，所以省掉了这个字段。
- **乱序日志**：本题保证有序。若要支持乱序，排序后同一时间戳必须 `start` 在前（内层先进入、后退出），否则会出现负数增量。
- **统一端点公式**：把 `start:t` 记作 $2t$、`end:t` 记作 $2t+1$，所有区间都成为整数端点，长度公式统一为 $\frac{r-l+1}{2}$，从根本上避免 `+1` 归属错误。
