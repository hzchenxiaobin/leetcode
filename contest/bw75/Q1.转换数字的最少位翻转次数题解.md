# LeetCode 转换数字的最少位翻转次数 题解

## 1. 题目概述

- **标题 / 题号**：转换数字的最少位翻转次数（#2220，easy）
- **链接**：https://leetcode.cn/problems/minimum-bit-flips-to-convert-number/
- **来源**：LeetCode 第 75 场双周赛 Q1
- **难度**：简单
- **标签**：位运算

**题意**：一次「位翻转」指把整数二进制表示中的某一位取反（$0 \to 1$ 或 $1 \to 0$，包含没有显示出来的前导 $0$）。给定整数 `start` 与 `goal`，求把 `start` 变成 `goal` 所需的最少翻转次数。

**约束**：

- $0 \le start, goal \le 10^9$（不足 30 位二进制，前导 0 可翻转）
- 本题与 461. 汉明距离 完全同构（两数二进制下不同位的个数）

## 2. 示例

**示例 1**

```text
输入：start = 10, goal = 7
输出：3
解释：10 = 1010₂，7 = 0111₂，有 3 个位不同（从右数第 1、3、4 位），
     逐一翻转这 3 位即可，且不可能更少。
```

**示例 2**

```text
输入：start = 3, goal = 4
输出：3
解释：3 = 011₂，4 = 100₂，三个二进制位全部不同，至少需要 3 次翻转。
```

**示例 3（边界补充）**

```text
输入：start = 0, goal = 0
输出：0
解释：两数相等，0 次翻转。
```

## 3. 解题思路

### 3.1 暴力思路

逐位比较：把两个数各按位右移 30 次，每一位比较是否相同，统计不同位数。时间 $O(\log \max(start, goal))$，对 $10^9$ 级别就是约 30 次比较，其实已经很快——但在比赛中更快、更不易错的是直接利用**异或**一步到位。

### 3.2 核心观察：异或把「不同的位」标成 1

![核心观察：异或标出不同的位](images/bw75_q1_xor_concept.svg)

位运算的基本恒等式：$x \oplus y$ 的第 $i$ 位为 $1$ 当且仅当 $x$ 与 $y$ 的第 $i$ 位**不同**。于是：

$$start \oplus goal = \text{所有「必须翻转」的位组成的掩码}$$

再把掩码里 $1$ 的个数（popcount）数出来就是答案。

> 💡 每一位的翻转互相独立：不同位之间翻转顺序无关、互不影响；相同位根本不用翻。所以「最少次数」恰等于不同位的个数，不存在更聪明的组合操作。

### 3.3 算法流程

```text
1. mask = start XOR goal        # 1 的位置 = 两数不同的位
2. 返回 mask 的二进制中 1 的个数（popcount）
```

一行核心逻辑。C++ 用 `__builtin_popcount`，Python 用 `bin(x).count("1")`（Python 3.10+ 也可 `int.bit_count()`）。

### 3.4 示例演算

![示例演算：10 → 7 的三步翻转](images/bw75_q1_walkthrough.svg)

以 `start = 10, goal = 7` 为例：

| 步骤 | 值 | 说明 |
|------|-----|------|
| 异或 | $1010_2 \oplus 0111_2 = 1101_2$ | 三个 1，即三个不同位 |
| 翻转① | 最右位 $0 \to 1$ | $1010 \to 1011$ |
| 翻转② | 第三位 $0 \to 1$ | $1011 \to 1111$ |
| 翻转③ | 最高位 $1 \to 0$ | $1111 \to 0111 = 7$ |

恰好翻转让异或掩码中为 1 的那 3 个位，不多不少。

## 4. 算法细节

1. **为什么每位独立**：翻转第 $i$ 位只改变该位的值，不影响其他位；要使所有位相等，不同的位**必须**至少翻一次（翻一次就够），相同的位**一次都不能翻**（翻了还得翻回去）。
2. **前导 0 的处理是自动的**：题目允许翻转「没有显示的前导 0」。例如 `start = 7, goal = 8`：$0111_2$ 与 $1000_2$，第 4 位（前导位）不同也会被异或自然捕捉到，无需特判。
3. **popcount 的实现选择**：
   - C++：`__builtin_popcount(unsigned)` 为一条 `popcnt` 指令（编译器开 `-mpopcnt` 时）；本题数据范围 `int` 足够。
   - Python：`bin(x).count("1")` 简单直观；Python 3.10+ 推荐 `x.bit_count()`，无字符串开销。
4. **注意本题与 461. 汉明距离 的关系**：汉明距离是「两个等长二进制串对应位不同的数量」，形式化后同样是 $popcount(x \oplus y)$，可一并掌握。

## 5. 正确性证明

**引理 1（下界）**：设 $d = popcount(start \oplus goal)$，则任何翻转方案至少需要 $d$ 次。

**证明**：每次位翻转只改变一个二进制位的值。对于 $start$ 与 $goal$ 不同的某一位 $i$，该位的值必须发生变化才能从 $start$ 的状态变到 $goal$ 的状态，而一次翻转只作用于一个位，故每一位不同的位至少消耗一次翻转。不同位共有 $d$ 个，翻转次数 $\ge d$。∎

**定理（最优性）**：逐个翻转 $start \oplus goal$ 中为 1 的位，恰好 $d$ 次把 $start$ 变为 $goal$，且 $d$ 是最小次数。

**证明**：翻转第 $i$ 位等价于令 $start \leftarrow start \oplus 2^i$。设掩码 $M = start \oplus goal$，对 $M$ 中每个为 1 的位 $i_1, \dots, i_d$ 各翻转一次，则

$$start \oplus 2^{i_1} \oplus 2^{i_2} \oplus \cdots \oplus 2^{i_d} = start \oplus M = start \oplus (start \oplus goal) = goal,$$

即 $d$ 次确实可行；结合引理 1 的下界，$d$ 为最小次数。∎

## 6. 复杂度分析

- **时间**：$O(1)$（严格说是 $O(B)$，$B$ 为位数；`popcount` 在现代 CPU 上是单指令）。
- **空间**：$O(1)$，只用了几个整型变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minBitFlips(int start, int goal) {
        return __builtin_popcount(start ^ goal);
    }
};
```

### Python

```python
class Solution:
    def minBitFlips(self, start: int, goal: int) -> int:
        return bin(start ^ goal).count("1")
```

> 💡 两份代码均通过官方示例（`3`、`3`）以及 30 万组（C++）/ 20 万组（Python）随机数据（含 $start = goal$、含 0 的边界）与独立逐位比较实现的**暴力对拍**，`mismatch = 0`。

## 8. 边界情况与易错点

1. **$start = goal$**：异或为 0，popcount 为 0，正确返回 0，无需特判。
2. **含 0 的输入**：$start = 0$ 时 $goal$ 的所有 1 位都要翻（等价于 popcount(goal)）；同理 $goal = 0$。
3. **前导 0 翻转**：题目明确允许，异或天然覆盖（如 $start=7, goal=8$ 需要 4 次而非 3 次——第 4 位的前导差异会被算进去）。若误以为「只比有效位」会得到错误答案。
4. **不要用 `abs(start - goal)` 之类的数值差**：位翻转的代价与数值差毫无关系（如 7→8 数值差 1 却要 4 次翻转）。
5. **C++ 移位实现 popcount 的坑**：若手写 `while (x) { ans += x & 1; x >>= 1; }`，注意 `x` 为非负数时右移安全；本题范围 $10^9 < 2^{31}$ 无符号问题。

**延伸思考**：若「一次操作」改为翻转**连续的一段位**（区间翻转），最少次数就变成「异或掩码中连续 1 段的个数」——这是另一类贪心模型。更广泛地，$popcount(x \oplus y)$ 度量的「汉明距离」是编码理论（纠错码）的基础度量，当操作集合改变（如允许加减、交换）时距离函数也随之改变。
