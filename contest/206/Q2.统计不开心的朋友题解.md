# LeetCode 统计不开心的朋友 题解

## 1. 题目概述

- **标题 / 题号**：统计不开心的朋友（#1583，medium）
- **链接**：https://leetcode.cn/problems/count-unhappy-friends/
- **来源**：LeetCode 第 206 场周赛 Q2
- **难度**：中等
- **标签**：数组、模拟、预处理

**题意**：$n$ 位朋友（$n$ 为偶数）两两配对，`pairs[i] = [xi, yi]` 表示 $x_i$ 与 $y_i$ 互为搭档。每人有一份偏好表 `preferences[i]`：按**亲近程度从高到低**列出其余 $n-1$ 位朋友。在 $x$ 与 $y$ 配对、$u$ 与 $v$ 配对的前提下，若**同时**满足：

1. $x$ 更喜欢 $u$ 胜过 $y$；
2. $u$ 更喜欢 $x$ 胜过 $v$；

则 $x$ **不开心**。返回不开心的朋友数目。

**约束**：

- $2 \le n \le 500$，$n$ 为偶数
- `preferences.length == n`，`preferences[i].length == n - 1`，不含 $i$ 本身且值互不相同
- `pairs.length == n / 2`，每位朋友恰好出现在一对中

## 2. 示例

**示例 1**

```text
输入：n = 4, preferences = [[1,2,3],[3,2,0],[3,1,0],[1,2,0]], pairs = [[0,1],[2,3]]
输出：2
解释：
朋友 1 不开心：1 与 0 配对，但 1 更喜欢 3，且 3 更喜欢 1（胜过 3 的搭档 2）。
朋友 3 不开心：3 与 2 配对，但 3 更喜欢 1，且 1 更喜欢 3（胜过 1 的搭档 0）。
朋友 0、2 开心：各自的搭档已是偏好表第一名。
```

**示例 2**

```text
输入：n = 2, preferences = [[1],[0]], pairs = [[1,0]]
输出：0
解释：只有一对朋友，不存在「别的配对」，两人必开心。
```

**示例 3**

```text
输入：n = 4, preferences = [[1,3,2],[2,3,0],[1,3,0],[0,2,1]], pairs = [[1,3],[0,2]]
输出：4
解释：0↔3、1↔2 互相更亲近，四个人全部不开心。
```

## 3. 解题思路

### 3.1 暴力思路：每次比较都现扫偏好表

对每个朋友 $x$（设搭档为 $y$），枚举其余每位朋友 $u$（搭档 $v$）：判定「$x$ 更喜欢 $u$ 胜过 $y$」需要在 `preferences[x]` 里找 $u$ 与 $y$ 的下标再比较，一次 $O(n)$；判定「$u$ 更喜欢 $x$ 胜过 $v$」又要扫一遍 `preferences[u]`。总共 $n \times n \times O(n) = O(n^3)$，$n = 500$ 时约 $1.25 \times 10^8$ 次扫描，Python 必然超时，C++ 也得赌常数。

> 💡 瓶颈在「比较亲近程度」这个高频操作。只要把它降为 $O(1)$，整体就能降到 $O(n^2)$。

### 3.2 核心观察：rank 矩阵 + match 数组

![核心观察：rank 位次与 match 配对把判定降到 O(1)](images/wc206_unhappy_rank_match.svg)

两个预处理结构把所有判定变为 $O(1)$：

1. **`rank[x][u]`**：$u$ 在 `preferences[x]` 中的下标，**越小越亲近**。于是「$x$ 更喜欢 $u$ 胜过 $y$」$\iff \text{rank}[x][u] < \text{rank}[x][y]$，一次整数比较。
2. **`match[x]`**：$x$ 的搭档。遍历 `pairs` 双向赋值即可，$O(1)$ 查询任意人的配对者。

于是 $x$ 的判定变得极简：令 $y = \text{match}[x]$，**偏好表中排在 $y$ 之前的每个 $u$** 自动满足条件①（这正是「$x$ 更喜欢的人」的全体）；对每个候选 $u$ 令 $v = \text{match}[u]$，验证 $\text{rank}[u][x] < \text{rank}[u][v]$（条件②）即可。任何一个候选通过，$x$ 就不开心，立即 `break`。

> 💡 与本场 Q1 的行和/列和预处理同属一个范式：**一趟 $O(n^2)$ 预处理，把之后所有判定压到 $O(1)$**。

### 3.3 算法流程

![算法流程：预处理 rank 与 match 后逐人逐候选判定](images/wc206_unhappy_judge_flow.svg)

1. **建 `rank`**：双重循环，`rank[x][preferences[x][r]] = r`
2. **建 `match`**：遍历 `pairs`，`match[xi] = yi`、`match[yi] = xi`
3. **逐人判定**：对每个 $x$，取 $y = \text{match}[x]$，枚举 $r \in [0, \text{rank}[x][y])$ 的候选 $u = \text{preferences}[x][r]$
4. **验证条件②**：$v = \text{match}[u]$，若 $\text{rank}[u][x] < \text{rank}[u][v]$，则 `ans++` 并 `break`
5. 返回 `ans`

### 3.4 示例演算

![示例 1 演算：rank 表、match 与逐人判定](images/wc206_unhappy_walkthrough.svg)

以示例 1 为例，先建 `rank` 表（对角线无意义记 `—`）与 `match`，再逐人判定：

| x | y = match[x] | 排在 y 之前的候选 u | 验证条件② | 结果 |
|---|--------------|---------------------|-----------|------|
| 0 | 1 | 无（y 已是第 1 名） | — | 开心 |
| 1 | 0 | 3, 2 | $u=3$：$\text{rank}[3][1]=0 < \text{rank}[3][2]=1$ ✓ | 不开心 |
| 2 | 3 | 无 | — | 开心 |
| 3 | 2 | 1 | $u=1$：$\text{rank}[1][3]=0 < \text{rank}[1][0]=2$ ✓ | 不开心 |

> 💡 朋友 1 与 3 互相触发不开心（见 §5 引理 3 的对称性），但 `ans` 按**人头**计，各加一次，最终 `ans = 2`。朋友 0、2 的搭档已是偏好表第一名，候选集为空，天然开心。

## 4. 算法细节

1. **`rank` 的建立**：`rank[x][preferences[x][r]] = r` 一趟双重循环 $O(n^2)$；对角线 `rank[x][x]` 永远不会被赋值（偏好表不含自身），也不参与任何比较
2. **`match` 双向赋值**：配对是无向的，只写 `match[xi] = yi` 会让查询 $y_i$ 的搭档时读到默认值，导致误判
3. **候选剪枝**：内层只枚举 `preferences[x][0 .. rank[x][y]-1]`，天然排除不满足条件①的 $u$，也自动跳过 $y$ 与 $x$ 自身
4. **早停**：条件②一旦通过，$x$ 已确定不开心，`break` 跳过剩余候选
5. **每人只判一次**：内层判的是「$x$ 是否不开心」，$u$ 的开心与否留给外层轮到 $u$ 时自判，不会重复计数
6. **等价写法**：也可以枚举每一对 `pairs` 的组合 $(x,y)$ 与 $(u,v)$，分别检查 $x, y$ 是否被 $u, v$ 触发（共 4 个判定），复杂度同为 $O(n^2)$；逐人判定版更贴近定义、更不易写错

## 5. 正确性证明

**引理 1（位次等价）**：对朋友 $x$ 及两个不同朋友 $a, b$，「$x$ 更喜欢 $a$ 胜过 $b$」当且仅当 $\text{rank}[x][a] < \text{rank}[x][b]$。

**证明**：`preferences[x]` 是 $x$ 对其余 $n-1$ 人的严格全序，$\text{rank}[x][a]$ 恰为 $a$ 在其中的下标，两两不同。下标小 $\iff$ 排名靠前 $\iff$ 更喜欢。∎

**引理 2（判定的等价形式）**：设 $y = \text{match}[x]$，则 $x$ 不开心当且仅当存在 $u$ 使得 $\text{rank}[x][u] < \text{rank}[x][y]$ 且 $\text{rank}[u][x] < \text{rank}[u][\text{match}[u]]$。

**证明**：题面中 $x$ 不开心需存在另一对 $(u, v)$ 使 $x$ 更喜欢 $u$ 胜过 $y$、$u$ 更喜欢 $x$ 胜过 $v$。由引理 1，两个条件分别等价于上述两个 rank 不等式；又每位朋友恰在一对中，$v = \text{match}[u]$，反之每个满足不等式的 $u$ 都连同其搭档构成题面中的一个见证。注意 $u \ne x$（偏好表不含自身）与 $u \ne y$（否则 $\text{rank}[x][y] < \text{rank}[x][y]$ 矛盾）被自动排除。∎

**引理 3（对称性）**：$x$ 因 $u$ 不开心（引理 2 的两个不等式同时成立）当且仅当 $u$ 因 $x$ 不开心。

**证明**：「$u$ 因 $x$ 不开心」的判定条件是 $\text{rank}[u][x] < \text{rank}[u][\text{match}[u]]$ 且 $\text{rank}[x][u] < \text{rank}[x][\text{match}[x]]$——与引理 2 的两个不等式逐字相同。∎

> 💡 推论：不开心总是**互相触发**的；但同一个人可能与多位朋友互相触发，所以答案可以是奇数，不能按「互相不开心对数 $\times 2$」统计（反例见 §8 第 5 条）。

**定理**：算法返回的 `ans` 恰为不开心的朋友数。

**证明**：外层对每个 $x$ 恰好判定一次，命中即 `ans++` 并 `break`，每人至多计入一次（不重）。内层枚举的 $u$ 恰是 `preferences[x]` 中排在 $y$ 之前的全体朋友——由引理 1，这正是满足条件①的全部候选；对每个候选以 $O(1)$ 验证条件②。由引理 2，$x$ 不开心当且仅当存在候选通过验证，故每个不开心的人都会被计入（不漏）。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$。建 `rank` 一趟 $O(n^2)$；判定阶段外层 $n$ 人、内层至多 $n-1$ 个候选、每次验证 $O(1)$，合计 $O(n^2)$。$n = 500$ 时约 $2.5 \times 10^5$ 次基本操作，轻松通过。
- **空间复杂度**：$O(n^2)$。`rank` 矩阵 $500 \times 500$ 个 `int` 约 1 MB；`match` 数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int unhappyFriends(int n, vector<vector<int>>& preferences,
                       vector<vector<int>>& pairs) {
        vector<vector<int>> rank(n, vector<int>(n));
        for (int x = 0; x < n; ++x)
            for (int r = 0; r < n - 1; ++r)
                rank[x][preferences[x][r]] = r;

        vector<int> match(n, -1);
        for (const auto& p : pairs) {
            match[p[0]] = p[1];
            match[p[1]] = p[0];
        }

        int ans = 0;
        for (int x = 0; x < n; ++x) {
            int y = match[x];
            for (int r = 0; r < rank[x][y]; ++r) {
                int u = preferences[x][r];
                int v = match[u];
                if (rank[u][x] < rank[u][v]) {
                    ++ans;
                    break;
                }
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def unhappyFriends(self, n: int, preferences: List[List[int]],
                       pairs: List[List[int]]) -> int:
        rank = [[0] * n for _ in range(n)]
        for x in range(n):
            for r, u in enumerate(preferences[x]):
                rank[x][u] = r

        match = [0] * n
        for x, y in pairs:
            match[x] = y
            match[y] = x

        ans = 0
        for x in range(n):
            y = match[x]
            for r in range(rank[x][y]):
                u = preferences[x][r]
                v = match[u]
                if rank[u][x] < rank[u][v]:
                    ans += 1
                    break
        return ans
```

## 8. 边界情况与易错点

1. **`n = 2` 最小规模**：只有一对，不存在「别的配对」，答案必为 0；候选区间为空，代码自然处理，无需特判
2. **`match` 忘记双向赋值**：只写 `match[xi] = yi` 会让查询 $y_i$ 搭档时读到默认值（0 或 −1），导致越界或误判
3. **内层上界多取一个**：合法范围是 $r \in [0, \text{rank}[x][y])$；写成 $\le$ 会把 $y$ 本人当候选，条件②退化为对 $y$ 的无意义比较
4. **命中后不 `break`**：同一人的多个触发 $u$ 会被重复计入 `ans`
5. **误以为答案总是偶数**：由引理 3，「不开心」成对互相出现，但一人可与多人互相触发。构造反例：$n=6$，配对 $(0,1),(2,3),(4,5)$，令 0 与 2 互相更亲近、2 与 4 也互相更亲近（如 `preferences[0] = [2,1,…]`、`preferences[2] = [0,4,3,…]`、`preferences[4] = [2,5,…]`，其余位次任意），则不开心集合为 $\{0, 2, 4\}$，答案为 **3**（奇数）
6. **顺手给 `u` 计数**：内层验证的是 $x$，不要顺手给 $u$ 也 `ans++`——外层自会轮到 $u$（由引理 3 它必然不开心，但计数必须发生在它自己的轮次）
7. **数据范围**：$n \le 500$，`rank` 矩阵约 1 MB，`int` 足够，无溢出风险

**延伸思考**：本题判定「当前配对是否有人不开心」，正是稳定匹配理论中 **blocking pair（阻塞对）** 的概念——一对互相更亲近的 $(x, u)$ 恰是一个阻塞对，本题统计的即是至少被一个阻塞对覆盖的人数。延伸问题：若允许重新配对，如何构造让所有人开心的**稳定匹配**？这正是经典 Gale-Shapley 稳定婚姻算法解决的问题（$O(n^2)$）。另一变体：统计阻塞对的数量——枚举所有 $(x, u)$ 检查两个 rank 不等式即可，同为 $O(n^2)$。
