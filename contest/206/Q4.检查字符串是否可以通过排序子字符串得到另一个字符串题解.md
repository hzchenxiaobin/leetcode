# LeetCode 检查字符串是否可以通过排序子字符串得到另一个字符串 题解

## 1. 题目概述

- **标题 / 题号**：检查字符串是否可以通过排序子字符串得到另一个字符串（#1585，hard）
- **链接**：https://leetcode.cn/problems/check-if-string-is-transformable-with-substring-sort-operations/
- **来源**：LeetCode 第 206 场周赛 Q4
- **难度**：困难
- **标签**：贪心、字符串、排序、不变量、队列

**题意**：给定两个**长度相同**、只含数字 `'0'`–`'9'` 的字符串 `s` 和 `t`。每次操作可以任选 `s` 的一个非空**子字符串**，把其中的字符**就地升序排序**，操作次数不限。问能否把 `s` 变成 `t`。

**约束**：

- $1 \le s.length = t.length \le 10^5$：排除一切 $O(n^2)$ 起步的模拟与搜索
- `s`、`t` 只含 `'0'`–`'9'`：字符集大小 $|\Sigma| = 10$，这是把判定做到近线性的关键

## 2. 示例

**示例 1**

```text
输入：s = "84532", t = "34852"
输出：true
解释："84[53]2" → "84[35]2"   （排序下标 2~3 的子串）
      "[843]52" → "[348]52"   （排序下标 0~2 的子串）
```

**示例 2**

```text
输入：s = "34521", t = "23415"
输出：true
解释："[3452]1" → "[2345]1"
      "234[51]" → "234[15]"
```

**示例 3**

```text
输入：s = "12345", t = "12435"
输出：false
解释：1、2 已就位后，t[2] = '4'，但 s 中 3 位于 4 的左边且更小，
      4 永远无法越过 3。
```

**示例 4**

```text
输入：s = "1", t = "2"
输出：false（排序不改变字符组成，两串组成不同）
```

## 3. 解题思路

### 3.1 暴力思路：为什么不能模拟

两个朴素切入点都走不通：

- **搜索状态空间**：每个中间状态有 $O(n^2)$ 种子串可选，状态总数是天文数字，BFS/DFS 无从谈起。
- **直接构造**：对着 `s` 反复挑子串排序去逼近 `t`，单次排序 $O(n \log n)$、最坏需要 $O(n)$ 次，$O(n^2 \log n)$ 在 $10^5$ 下必然超时；更糟的是「该排哪一段」本身就缺乏直接线索。

> 💡 正确的姿势不是问「能做什么」，而是问「**什么永远做不到**」——找到操作无法破坏的**不变量**，用不变量刻画全部可达的串。

### 3.2 核心观察：排序子串 = 交换相邻逆序对

![核心观察：排序子串等价于交换相邻逆序对](images/wc206_transform_invariant.svg)

**第一步改写**：对长度为 2 的子串排序，效果就是「交换一对相邻的逆序对」——左边数字严格大于右边时，小者上前一位。反过来看，对**任意长度**的子串排序，等价于在子串内部做若干次这样的相邻交换（这正是冒泡排序的过程，见上图）。于是原问题等价于：

> 可以**任意多次**交换相邻的严格逆序对 $(x, y)$（$x$ 在左且 $x > y$）。

**第二步读出不变量**：交换只发生在「左大右小」的相邻对上，因此：

- 任何数字都可以**一步步向左冒泡**，穿过任意多个**严格大于它**的数字；
- 任何数字都**永远无法向左穿过 $\le$ 它的数字**——更小的数字一旦出现在左边，就是一辈子的路障；相等的数字之间也永不换位。

**判定框架**：从左到右逐个确定 `t` 的字符。处理 $t[i] = d$ 时，让 `s` 中**最靠左的未使用**的 $d$ 来供给这个位置：若它左边存在未使用的更小数字，则被永久挡住，返回 `false`；否则消耗掉它，继续处理下一字符。

### 3.3 算法流程：10 条位置队列

![算法流程：10 条位置队列与逐字符判定](images/wc206_transform_flow.svg)

实现上完全不需要碰字符串：为每个数字 $d \in \{0..9\}$ 建一条**位置队列** `pos[d]`（按出现顺序递增），配一个读取指针 `idx[d]` 模拟出队。对 `t` 的每个字符 `d`：

1. 取队首 $p = pos[d][idx[d]]$（最左未用的 $d$）；队列已空说明 `t` 的 $d$ 比 `s` 多，返回 `false`；
2. 检查每个更小数字 $c < d$：若 `pos[c]` 未耗尽且队首 $q < p$，说明 $c$ 挡在左边，返回 `false`；
3. `++idx[d]`，消耗掉这个 $d$。

全程通过则返回 `true`。

### 3.4 示例演算

![示例演算：例 1 全程通过，例 3 第 3 步被挡](images/wc206_transform_walkthrough.svg)

例 1 中值得注意的细节：处理 $t[2] = '8'$（$p = 0$）时，更小的 `2`、`5` 都在 $p$ 的**右边**——它们不挡路，因为「挡路」的定义是**位于 $d$ 左边**。这正是例 3 失败而例 1 成功的区别所在。

## 4. 算法细节

1. **数据结构**：`pos[0..9]` 每条是递增下标队列；`idx[0..9]` 是读取指针，`pos[d][idx[d]]` 即队首，`++idx[d]` 即出队，无需真的删除元素。
2. **为何取最左未用的 d**：相等数字彼此不能穿过，所以 `t` 中第 $k$ 个 $d$ 只能由 `s` 中第 $k$ 个 $d$ 供给（引理 2），「最左未用」正是按序供给；同时它左边的未用字符最少、最不容易被挡——若它被位置 $q$ 的 $c < d$ 挡住，更右的 $d$ 也被同一个 $c$ 挡住（$q$ 更小，$q < p < p'$）。
3. **多重集校验是免费的**：若 `t` 中某数字比 `s` 中多，队列耗尽直接返回 `false`（示例 4），无需单独写计数比较。
4. **只需检查 $0..d-1$**：更大的数字在左边不挡路（能被 $d$ 向左穿过）；相等的数字不挡路（取的就是最左的）。
5. 队列合计只存 $n$ 个下标，`int` 足够，无溢出风险。

## 5. 正确性证明

**引理 1（操作改写）**：对任意子串的一次升序排序，可改写为若干次「交换相邻严格逆序对」；反之，每次这样的交换都是合法操作。两类操作可达的字符串集合完全相同。

**证明**：交换相邻的 $x > y$ 即排序长度为 2 的子串，是合法操作。另一方向，子串 $s[l..r]$ 升序排序的结果可由其内部的冒泡排序逐步得到，而冒泡的每一步交换的都恰是子串内部一对相邻严格逆序对，每步本身合法，依次执行即得排序结果。∎

**推论（核心不变量）**：若某时刻数字 $c < d$ 位于 $d$ 左侧，则此后任何时刻 $c$ 仍在 $d$ 左侧。

**证明**：两者的左右关系翻转，当且仅当某次操作交换了相邻的它们，而交换要求左侧严格大于右侧；$c < d$ 且 $c$ 在左时 $(c, d)$ 不是逆序对，永不交换。∎

**引理 2（按序供给）**：若 $s$ 可变换为 $t$，则存在稳定的字符追踪方式（排序时相等字符保持内部先后），使 $t$ 中第 $k$ 次出现的 $d$ 恰由 $s$ 中第 $k$ 次出现的 $d$ 演变而来。

**证明**：相等字符不可分辨，追踪方式可任取；取稳定追踪后，任意两个相等字符的相对顺序在任何操作下不变（相等不是逆序对，永不交换），故 $s$ 中第 $k$ 个 $d$ 的归宿只能是 $t$ 中第 $k$ 个 $d$。∎

**定理**：$s$ 可变换为 $t$，当且仅当上述贪心判定全程通过。

**证明**：

（必要性）设判定在 $t[i] = d$ 处失败：$p$ 是 $s$ 中第 $a$ 个 $d$ 的位置，数字 $c < d$ 的第 $r+1$ 次出现位于 $q < p$，其中 $r$ 为 $t[0..i-1]$ 中 $c$ 的个数（前 $r$ 个 $c$ 已被消耗）。反设变换存在，取引理 2 的稳定追踪，则 $t[i]$ 由第 $a$ 个 $d$（位置 $p$）供给。由推论，位置 $q$ 的 $c$（$c < d$，$q < p$）在一切后续串中都在该 $d$ 左侧，故其最终位置 $< i$。但最终位置落在 $t[0..i-1]$ 内的 $c$ 恰有 $r$ 个，且由引理 2 它们是 $s$ 的前 $r$ 个 $c$——与「第 $r+1$ 个 $c$ 也结束在位置 $< i$」矛盾。∎

（充分性）设判定全程通过，显式构造操作。维护不变式：**当前串 = 已锁定的 $t[0..i-1]$ 前缀 + 未使用字符按 $s$ 原顺序排成的后缀**（初始时显然成立）。处理 $t[i] = d$ 时，设供给源为最左未用的 $d$（原位置 $p$）。由不变式，当前在它左侧的未使用字符恰是原位置 $< p$ 的未使用字符；由判定，它们都 $\ge d$，又因它是未用 $d$ 中最左的，它们全部严格大于 $d$。于是把它向左冒泡：每当左侧紧邻字符 $x > d$，就排序长度为 2 的子串完成一次交换，直至到达位置 $i$ 后锁定。途中其余字符的相对顺序不变，不变式保持。$n$ 步之后得到 $t$。∎

> 💡 充分性的构造只用到**长度为 2 的排序**：判定可行时，甚至只靠「交换相邻逆序对」这一种原始操作就能完成整个变换。

## 6. 复杂度分析

- **时间复杂度**：$O(|\Sigma| \cdot n) = O(10n)$。建队列一趟 $O(n)$；处理 `t` 的每个字符至多检查 9 个更小数字的队首，常数级。
- **空间复杂度**：$O(n)$。10 条队列合计存储 $n$ 个下标；指针数组 $O(10)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    bool isTransformable(string s, string t) {
        vector<int> pos[10];
        for (int i = 0; i < (int)s.size(); ++i)
            pos[s[i] - '0'].push_back(i);

        int idx[10] = {};
        for (char c : t) {
            int d = c - '0';
            if (idx[d] >= (int)pos[d].size()) return false;
            int p = pos[d][idx[d]];
            for (int smaller = 0; smaller < d; ++smaller)
                if (idx[smaller] < (int)pos[smaller].size()
                    && pos[smaller][idx[smaller]] < p)
                    return false;
            ++idx[d];
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def isTransformable(self, s: str, t: str) -> bool:
        pos = [[] for _ in range(10)]
        for i, ch in enumerate(s):
            pos[int(ch)].append(i)

        idx = [0] * 10
        for ch in t:
            d = int(ch)
            if idx[d] >= len(pos[d]):
                return False
            p = pos[d][idx[d]]
            for smaller in range(d):
                if idx[smaller] < len(pos[smaller]) and pos[smaller][idx[smaller]] < p:
                    return False
            idx[d] += 1
        return True
```

## 8. 边界情况与易错点

1. **字符组成不同**：如 `s = "1"`, `t = "2"`。队列耗尽（`idx[d] >= pos[d].size()`）自然返回 `false`，不需要单独的多重集预检查。
2. **只检查严格更小的数字**：把「更大的数字在左边」也当成障碍是常见手误——例如 `s = "21"`, `t = "12"` 应为 `true`（1 可以穿过 2），多查会误判为 `false`。
3. **必须取最左未用的 d，不能任意取**：相等数字不能互相穿过（按序供给），且「最左被挡 ⇒ 更右也被挡」，两者共同决定了唯一正确的选择。
4. **复杂度陷阱**：对每个字符重新扫描整个 `s` 是 $O(n^2)$，$10^5$ 必然超时；必须利用「只有 10 种数字」把检查降为常数。
5. **`s == t`、`n = 1`**：算法自然返回 `true`，无需特判。
6. C++ 中 `pos` 可用 `vector<int> pos[10]` 或 `array<vector<int>, 10>`；下标用 `int` 即可。
