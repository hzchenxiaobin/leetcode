# LeetCode 字符串转换后的长度 I 题解

## 1. 题目概述

- **标题 / 题号**：字符串转换后的长度 I（#3335，medium）
- **链接**：https://leetcode.cn/problems/total-characters-in-string-after-transformations-i/
- **来源**：LeetCode 第 421 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、数学、字符串、动态规划、计数

**题意**：给定字符串 `s` 和转换次数 $t$。每次**转换**同时替换 `s` 中每个字符：`'z'` 替换为 `"ab"`（一个变两个），其余字符替换为字母表的**下一个**字符（`'a'→'b'`，…，`'y'→'z'`）。返回恰好 $t$ 次转换后字符串的**长度**，对 $10^9+7$ 取模。

**约束**：

- $1 \le \textit{s.length} \le 10^5$
- `s` 仅由小写英文字母组成
- $1 \le t \le 10^5$

## 2. 示例

**示例 1**

```text
输入：s = "abcyy", t = 2
输出：7
解释："abcyy" → "bcdzz" → "cdeabab"，最终长度 7。
第 2 轮里两个 'z' 各分裂为 "ab"，是长度从 5 涨到 7 的唯一原因。
```

**示例 2**

```text
输入：s = "azbk", t = 1
输出：5
解释："azbk" → "babcl"，'z' 一分为二，长度 4 + 1 = 5。
```

**示例 3**

```text
输入：s = "z", t = 26
输出：3
解释："z" → "ab" → "bc" → … → "yz"（t=25）→ "zab"（t=26），长度 3。
注意 t=25 时字符串已是 "yz"——含 'z' 不等于已分裂，分裂发生在「成为 z 之后的那一轮」。
```

## 3. 解题思路

### 3.1 暴力思路：真把字符串滚 t 轮

每轮遍历当前字符串重建：`'z'` 拼上 `"ab"`，其余字符加一：

```python
for _ in range(t):
    s = ''.join('ab' if c == 'z' else chr(ord(c) + 1) for c in s)
return len(s) % (10**9 + 7)
```

小 $t$ 完全正确，死因在**长度的增长方式**：唯一增长源是 `'z'` 的分裂，而一个 `'z'` 走完约 26 轮后，它分裂出的 `'a'`、`'b'` 又会先后走回 `'z'` 再次分裂——单字符长度满足 $L(j) = L(j-26) + L(j-25)$（推导见 §4），是**斐波那契型指数增长**，约每 25~26 轮翻一番。粗算：$t = 1000$ 时单个 `'z'` 已繁衍出约 $2^{39} \approx 5.5 \times 10^{11}$ 个字符（≈ 0.5 TB）；$t = 10^5$ 时长度约为 $10^{1180}$——一个 1181 位的十进制数。内存与时间双双爆炸。

> ⚠️ 暴力真正的死因不是「慢」，而是**状态本身是天文数字**。优化方向因此明确：别存字符串，存**能推出长度的最小信息**。

### 3.2 核心观察：字符独立 ⇒ 26 个计数器

![丢掉顺序：字符串压缩为26维频率向量](images/transform_length_count_model.svg)

**观察一（顺序无关）**：替换规则**逐字符独立**——每个字符变成什么只取决于它自己，与邻居无关。最终长度 = 各字符独立演化长度之和。于是 $O(n)$ 把字符串压缩成 26 维频率向量 $\textit{cnt}[0..25]$（`cnt[i]` = 字母 $i$ 的个数），顺序信息可以整体丢弃。

**观察二（一轮 = 右移 + 分裂）**：非 `'z'` 字母统一「进一格」，对应 $\textit{cnt}$ 整体右移；`'z'` 一分为二，一份进 `'a'`、一份进 `'b'`。转移方程：

$$\textit{cnt}'[i+1] \mathrel{+}= \textit{cnt}[i]\ (0 \le i \le 24), \qquad \textit{cnt}'[0] \mathrel{+}= \textit{cnt}[25], \qquad \textit{cnt}'[1] \mathrel{+}= \textit{cnt}[25]$$

**观察三（增量不变式）**：右移不改变总量，唯有分裂让总数每轮恰好增加 $\textit{cnt}[25]$。这一个不变式同时解释了 3.1 的指数爆炸与本题必须取模的原因。

本质上这是一个 **26 维线性递推 DP**：状态是频率向量，转移是固定线性映射，跑 $t$ 轮后求和。转移只含加法，全程 $\bmod\ 10^9+7$ 安全无坑。

### 3.3 算法流程：t 轮计数转移

![计数转移算法流程图](images/transform_length_flow.svg)

三步走：① 扫一遍 `s` 建频率；② 循环 $t$ 次，每次**先暂存** $z = \textit{cnt}[25]$，再倒序搬移 $\textit{cnt}[i] = \textit{cnt}[i-1]$（$i$ 从 25 到 1），最后 $z$ 回灌 $\textit{cnt}[0]$、$\textit{cnt}[1]$；③ 求和取模输出。倒序搬移实现**原地**完成——写 $\textit{cnt}[i]$ 读 $\textit{cnt}[i-1]$，被覆盖的位置本轮不再被读，无需辅助数组。

### 3.4 示例演算

![示例abcyy两轮演算表](images/transform_length_walkthrough.svg)

以 $\textit{s} = \text{"abcyy"},\ t = 2$ 走完全流程（只列非零列）：

| 状态 | a | b | c | d | e | y | z | 总长 |
|------|---|---|---|---|---|---|---|------|
| 初始 | 1 | 1 | 1 | – | – | 2 | – | 5 |
| $t=1$ | – | 1 | 1 | 1 | – | – | 2 | 5 |
| $t=2$ | **2** | **2** | 1 | 1 | 1 | – | – | **7** |

第 1 轮 `y` 右移成 `z`、`abc` 进成 `bcd`，$\textit{cnt}[25]=0$ 无分裂，总长不变；第 2 轮 `z×2` 分裂回灌 `a`、`b`（加粗），其余继续右移，总长 $5+2=7$ ✓。与真实字符串 `"abcyy" → "bcdzz" → "cdeabab"` 逐列吻合；示例 2 同法验证 $4+1=5$ ✓。注意演算表里每一格都是**计数器**而非字符——从头到尾无需展开字符串。

## 4. 算法细节

1. **频率压缩**：`cnt[ord(c)-97] += 1`，$O(n)$。丢掉顺序的合法性由引理 1（逐字符独立）保证。
2. **原地倒序搬移**：先暂存 $z = \textit{cnt}[25]$（否则第一步就被 $\textit{cnt}[24]$ 覆盖），再 `for i in range(25, 0, -1): cnt[i] = cnt[i-1]`，最后 `cnt[0] = z; cnt[1] = (cnt[1] + z) % MOD`。$\textit{cnt}[1]$ 是唯一「搬移 + 分裂」**叠加位**，必须 `+=`。
3. **取模时机**：计数本身随长度一起指数增长，几轮后就会超出 64 位整数，C++ **必须每轮取模**；取模后两个计数相加 $< 2 \times (10^9+7) \approx 2 \times 10^9$，勉强不超 `int32` 上限（$2.147 \times 10^9$）但毫无余量，统一用 `long long` 稳妥。Python 大整数不溢出，但取模让数值保持小、运算更快。
4. **矩阵视角（通往同场 Q4 的钥匙）**：转移是固定线性映射，写成 $26 \times 26$ 矩阵 $M$（$M[i+1][i] = 1$，$0 \le i \le 24$；$M[0][25] = M[1][25] = 1$；其余为 0），则 $\textit{cnt}_t = M^t \cdot \textit{cnt}_0$。本题 $t \le 10^5$ 逐轮模拟即可；姊妹题 3337（同场 Q4）把 $t$ 放大到 $10^9$，用矩阵快速幂 $O(26^3 \log t)$ 加速。
5. **单字符长度 =「跳步斐波那契」**：初始字母编号 $i$、剩余 $t$ 轮，长度只依赖 $j = i + t$：$j \le 25$ 时字符尚未越过 `'z'`，长度恒 1；第 $26-i$ 轮分裂为 `"ab"`，此后 `'a'` 分量对应下标 $j-26$、`'b'` 分量对应 $j-25$，于是

   $$L(j) = 1\ (j \le 25), \qquad L(j) = L(j-26) + L(j-25)\ (j \ge 26)$$

   答案即 $\sum_{c \in s} L(\textit{pos}(c) + t) \bmod (10^9+7)$。这个视角把每轮 26 步的循环降为 $O(n + t)$，也直接解释了 3.1 的指数增长本质：斐波那契把「+1 岁生一个」改成「走完 26 步生一个」。

## 5. 正确性证明

**引理 1（逐字符独立性）**：设 $\varphi$ 为单轮转换在字符串上的作用，则对任意字符串 $u, v$ 有 $\varphi(uv) = \varphi(u)\,\varphi(v)$；从而 $\varphi^t(s) = \varphi^t(s_1)\varphi^t(s_2)\cdots\varphi^t(s_n)$，且 $|\varphi^t(s)| = \sum_{i=1}^{n} |\varphi^t(s_i)|$。

**证明**：转换规则逐字符定义、各位同时替换且互不影响：$u$ 中每个字符的替换结果只由该字符决定，与拼接对象无关，$v$ 同理，故先替换后拼接 = 先拼接后替换。对 $t$ 归纳：$\varphi^{t+1}(uv) = \varphi^t(\varphi(uv)) = \varphi^t(\varphi(u)\varphi(v)) = \varphi^{t+1}(u)\varphi^{t+1}(v)$。长度是拼接可加的，取长度即得末式。∎

**引理 2（计数转移）**：若字符串 $w$ 的频率向量为 $\textit{cnt}$，则 $\varphi(w)$ 的频率向量 $\textit{cnt}'$ 满足：$\textit{cnt}'[j] = \sum_{i} \textit{cnt}[i] \cdot m_{j,i}$，其中 $m_{i+1,i} = 1$（$0 \le i \le 24$）、$m_{0,25} = m_{1,25} = 1$、其余为 0。

**证明**：由引理 1，$\varphi(w)$ 是各位替换结果的拼接。逐字符清点贡献：字母 $i \le 24$ 替换为单个字母 $i+1$，向 $\textit{cnt}'[i+1]$ 贡献 $\textit{cnt}[i]$；字母 $25$（`'z'`）替换为 `"ab"`，向 $\textit{cnt}'[0]$ 与 $\textit{cnt}'[1]$ 各贡献 $\textit{cnt}[25]$。各目标格的贡献互不相扰（不同 $i$ 落入不同格，唯 $\textit{cnt}'[1]$ 同时接收 $i=0$ 的搬移与 $i=25$ 的分裂），求和即得。∎

**定理**：算法在 $t$ 轮转移后输出的 $\sum_j \textit{cnt}_t[j]$ 满足 $\sum_j \textit{cnt}_t[j] \equiv |\varphi^t(s)| \pmod{10^9+7}$。

**证明**：对 $k$ 归纳断言「$\textit{cnt}_k$ 是 $\varphi^k(s)$ 的频率向量」：$k=0$ 时即统计所得；若 $\textit{cnt}_k$ 是 $\varphi^k(s)$ 的频率向量，则 $\varphi^{k+1}(s) = \varphi(\varphi^k(s))$，由引理 2，一步转移后的 $\textit{cnt}_{k+1}$ 是它的频率向量。故 $\textit{cnt}_t$ 是 $\varphi^t(s)$ 的频率向量，其分量和 $= |\varphi^t(s)|$。算法全程只做整数加法与取模，而 $x \bmod p$ 与加法可交换（$(a+b) \bmod p = ((a \bmod p) + (b \bmod p)) \bmod p$），故模意义下的逐轮结果与先算精确值再取模一致。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + 26t)$。频率统计 $O(n)$；每轮转移固定 26 次搬移 + 2 次回灌，共 $t$ 轮。$n = t = 10^5$ 时约 $2.7 \times 10^6$ 次操作，远低于时限。采用 §4 第 5 点的 $L(j)$ 递推可降到 $O(n + t)$。
- **空间复杂度**：$O(26)$。一个频率数组，倒序搬移原地完成，常数空间（$L(j)$ 版本需 $O(t)$ 存递推表，也可滚动至 $O(26)$）。

## 7. 参考代码

### C++（计数模拟，原地倒序搬移）

```cpp
class Solution {
  public:
    int lengthAfterTransformations(string s, int t) {
        constexpr long long MOD = 1'000'000'007;
        long long cnt[26] = {0};
        for (char c : s) ++cnt[c - 'a'];      // ① 频率压缩：丢顺序
        while (t--) {
            long long z = cnt[25];            // ② 先暂存旧 z，防覆盖
            for (int i = 25; i >= 1; --i)     // ③ 倒序整体右移一格
                cnt[i] = cnt[i - 1];
            cnt[0] = z;                       // ④ z 分裂：一份进 a
            cnt[1] = (cnt[1] + z) % MOD;      //    另一份进 b（叠加位，取模）
        }
        long long ans = 0;
        for (int i = 0; i < 26; ++i) ans = (ans + cnt[i]) % MOD;
        return (int)ans;
    }
};
```

### Python（同思路）

```python
class Solution:
    def lengthAfterTransformations(self, s: str, t: int) -> int:
        MOD = 10**9 + 7
        cnt = [0] * 26
        for c in s:                           # ① 频率压缩：丢顺序
            cnt[ord(c) - 97] += 1
        for _ in range(t):
            z = cnt[25]                       # ② 先暂存旧 z，防覆盖
            for i in range(25, 0, -1):        # ③ 倒序整体右移一格
                cnt[i] = cnt[i - 1]
            cnt[0] = z                        # ④ z 分裂：一份进 a
            cnt[1] = (cnt[1] + z) % MOD       #    另一份进 b（叠加位，取模）
        return sum(cnt) % MOD
```

### Python（跳步斐波那契视角，O(n + t)）

```python
class Solution:
    def lengthAfterTransformations(self, s: str, t: int) -> int:
        MOD = 10**9 + 7
        L = [1] * 26                          # L[j] = 单字符经 j 轮后的长度
        for j in range(26, 26 + t):
            L.append((L[j - 26] + L[j - 25]) % MOD)
        return sum(L[ord(c) - 97 + t] for c in s) % MOD
```

实测：三份代码在两组官方示例与示例 3 上分别得 $7 / 5 / 3$；与字符串暴力对拍随机数据（$|s| \le 8$、$t \le 60$）全部一致；极限数据（$|s| = 10^5$ 全 `'z'`、$t = 10^5$）Python 约 0.1 s。

## 8. 边界情况与易错点

1. **别真去模拟字符串**：长度约每 25~26 轮翻一番，$t = 10^5$ 时是 1181 位数——不是超时问题，是状态本身存不下。
2. **暂存 z 的时机**：必须在倒序搬移**之前**，否则旧 $\textit{cnt}[25]$ 第一步就被 $\textit{cnt}[24]$ 覆盖，分裂量丢失。
3. **搬移方向必须是倒序**：正序 `i = 1..25` 会把刚写入的值连锁右移，一轮等效于「整体移多位」，示例 1 当场出错。
4. **`cnt[1]` 是叠加位**：既接收 `cnt[0]` 的搬移又接收 z 的分裂，必须 `+=`；`cnt[0]` 只接收 z，直接赋值。写反必错。
5. **C++ 溢出**：计数随长度指数增长，**每轮取模是必需**而非优化；取模后两个计数相加 $\approx 2 \times 10^9$，贴着 `int32` 上限，全程用 `long long`。
6. **搬移循环边界**：`i` 从 25 到 1 共 25 次，`cnt[0]` 不参与搬移（它只被回灌赋值）。
7. **「含 z」≠「已分裂」**：$t = 25$ 时 `"z"` 恰好走成 `"yz"`，分裂发生在下一轮。用 $L(j)$ 递推时注意 $j \le 25$ 恒为 1、$j = 26$ 才首次分裂（值 2）。
8. **温和数据可做 sanity check**：`s` 全 `'a'` 且 $t < 25$ 时无 `'z'` 产生，答案就是 $|s|$；`t = 1` 且 `s` 无 `'z'` 时长度不变。
9. **`z → "ab"` 的顺序对长度无影响**：只有题目要求输出字符串本身时才需要在意（本题不需要）。
