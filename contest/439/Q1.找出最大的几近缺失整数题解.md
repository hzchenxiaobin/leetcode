# LeetCode 找出最大的几近缺失整数 题解

## 1. 题目概述

- **标题 / 题号**：找出最大的几近缺失整数（#3471，easy）
- **链接**：https://leetcode.cn/problems/find-the-largest-almost-missing-integer/
- **来源**：LeetCode 第 439 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `nums` 和整数 `k`。若整数 `x` **恰好仅出现在一个**大小为 `k` 的**子数组**中，则称 `x` 是 `nums` 中的**几近缺失**（almost missing）整数。返回 `nums` 中最大的几近缺失整数；不存在则返回 `-1`。

「出现」按**值**判断：只要某个子数组内含有至少一个 `x`，就算 `x` 出现在该子数组中；`x` 在同一子数组里出现多次，也只算「出现在这一个」子数组。

**约束**：

- `1 <= nums.length <= 50`
- `0 <= nums[i] <= 50`
- `1 <= k <= nums.length`

## 2. 示例

**示例 1**

```text
输入：nums = [3,9,2,1,7], k = 3
输出：7
解释：大小为 3 的子数组共 3 个：[3,9,2]、[9,2,1]、[2,1,7]。
      3 与 7 恰好只出现在其中一个子数组中，最大者为 7。
```

**示例 2**

```text
输入：nums = [3,9,7,2,1,7], k = 4
输出：3
解释：3 只出现在 [3,9,7,2] 一个子数组中。
      7 在 [7,2,1,7] 中出现两次，但该子数组只计 1 次，
      7 共被 3 个子数组覆盖，不满足「恰好一个」。
```

**示例 3**

```text
输入：nums = [0,0], k = 1
输出：-1
解释：两个长度为 1 的子数组 [0]、[0] 均含 0，覆盖数为 2，无合法整数。
```

## 3. 解题思路

签到题，关键在**把「几近缺失」的定义忠实翻译成计数**，不急着优化。

### 3.1 暴力思路

大小为 $k$ 的子数组由起点 $s \in [0, n-k]$ 唯一决定，共 $n-k+1 \le 50$ 个。最直接的做法是逐值枚举：对每个出现过的值 $x$，扫描全部 $n-k+1$ 个子数组，统计包含 $x$ 的个数是否恰为 1。总操作约 $O(V \cdot n \cdot k)$（$V \le 51$ 为值域），$n \le 50$ 时不超过 $10^5$ 量级，完全可过——但**枚举窗口而非枚举值**可以一次窗口扫描同时服务所有值，更简洁。

### 3.2 核心观察：覆盖数计数 + 值域桶

**观察 1（计数目标）**：题目问的不是「$x$ 出现多少次」，而是「**含有 $x$ 的子数组有多少个**」。定义**覆盖数**

$$cnt[x] = \#\{\, s \in [0, n-k] : x \text{ 出现在子数组 } nums[s \ldots s+k-1] \text{ 中}\,\}$$

则 $x$ 几近缺失 $\iff cnt[x] = 1$。

**观察 2（值域桶）**：$0 \le nums[i] \le 50$，值域极小——用长度 51 的**桶数组**代替哈希表，每个窗口再用一个布尔数组 `seen[0..50]` 先**去重**，然后把 `seen` 中为真的值各计 1 次覆盖。

![核心观察：几近缺失即恰好被 1 个窗口覆盖](images/almost_missing_windows_concept.svg)

### 3.3 算法流程

```text
cnt[0..50] ← 0
for s in 0 … n-k:                    # 枚举窗口起点
    seen[0..50] ← false              # 每个窗口重置
    for j in s … s+k-1: seen[nums[j]] ← true
    for x in 0 … 50: if seen[x]: cnt[x] ← cnt[x] + 1
ans ← -1
for x in 0 … 50: if cnt[x] = 1: ans ← x    # 正序扫，最后命中的即最大
return ans
```

### 3.4 示例演算

以**示例 2**（`nums = [3,9,7,2,1,7]`，`k = 4`，`n = 6`）走查：窗口共 3 个，$W0=[3,9,7,2]$、$W1=[9,7,2,1]$、$W2=[7,2,1,7]$。

| 值 $x$ | $W0$ | $W1$ | $W2$ | $cnt[x]$ | 判定 |
|---|---|---|---|---|---|
| 3 | ✓ | · | · | 1 | ✓ 几近缺失 |
| 9 | ✓ | ✓ | · | 2 | ✗ |
| 7 | ✓ | ✓ | ✓ | 3 | ✗ |
| 2 | ✓ | ✓ | ✓ | 3 | ✗ |
| 1 | · | ✓ | ✓ | 2 | ✗ |

注意 7 在 $W2$ 中出现**两次**，去重后该窗口仍只计 1，故 $cnt[7] = 3$ 而非 4。合法值仅有 $\{3\}$，答案 `3`。

## 4. 算法细节

1. **窗口枚举**：起点 $s$ 从 $0$ 到 $n-k$（含），循环条件写成 `s + k <= n` 防止 off-by-one；窗口为 `nums[s..s+k-1]`。
2. **两级计数**：`seen` 解决「**同一窗口内**重复出现只计一次」，`cnt` 解决「**跨窗口**累计覆盖数」，二者缺一不可。
3. **取最大**：值域只有 0~50，正序扫一遍 `x = 0 … 50`，最后一次满足 `cnt[x] == 1` 的 `x` 即最大候选。
4. **无需特判** `k == n`（唯一窗口即整个数组，所有出现过的值覆盖数均为 1）与 `k == 1`（`cnt[x]` 退化为 `x` 的总频次）：暴力按定义模拟，两类边界天然正确，正确性证明见下节。

## 5. 正确性证明

**引理 1**（窗口与起点一一对应）：大小为 $k$ 的子数组与起点 $s \in [0, n-k]$ 一一对应，故共有 $n-k+1$ 个。

**证明**：$s$ 合法当且仅当 $0 \le s$ 且 $s+k-1 \le n-1$，即 $s \in [0, n-k]$；子数组连续，由起点唯一确定，不同起点给出不同子数组。∎

**引理 2**（去重计数的正确性）：算法结束时，$cnt[x]$ 恰等于「含有 $x$ 的大小为 $k$ 的子数组个数」。

**证明**：对固定窗口 $W_s$（起点 $s$），算法标记 `seen[x] = true` 当且仅当 $x$ 在下标区间 $[s, s+k-1]$ 内**至少出现一次**，即 $W_s$ 含有 $x$。累加循环对每个这样的 $x$ 在本窗口恰加 1（先去重、后累加），故 $cnt[x] = \sum_{s=0}^{n-k} [W_s \text{ 含 } x]$，即含 $x$ 的窗口个数。∎

**定理**：算法输出 `nums` 中最大的几近缺失整数；不存在时输出 `-1`。

**证明**：由引理 2，$cnt[x] = 1 \iff x$ 恰好仅出现在一个子数组中；且 $cnt[x] \ge 1$ 蕴含 $x$ 确实在 `nums` 中出现过（每个被计数的窗口都真实含有 $x$），故不会把未出现过的值误判为几近缺失。设 $S = \{x : cnt[x] = 1\}$。若 $S = \varnothing$，`ans` 保持初始值 $-1$；若 $S \ne \varnothing$，正序扫描使 `ans` 最终等于 $\max S$，即所求的最大几近缺失整数。∎

## 6. 复杂度分析

- **时间复杂度**：`O((n-k+1) · (k+V))`，其中 `V = 51` 为值域大小。共 $n-k+1$ 个窗口，每个窗口 `O(k)` 去重标记 + `O(V)` 累加；`n <= 50` 时总量不超过 `50 × (50+51) ≈ 5×10³`，瞬间完成。
- **空间复杂度**：`O(V)`，仅 `seen` 与 `cnt` 两个长度 51 的数组。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int largestInteger(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> cnt(51, 0);
        for (int s = 0; s + k <= n; s++) {
            vector<bool> seen(51, false);      // 窗口内去重
            for (int j = s; j < s + k; j++) seen[nums[j]] = true;
            for (int x = 0; x <= 50; x++)
                if (seen[x]) cnt[x]++;
        }
        int ans = -1;
        for (int x = 0; x <= 50; x++)          // 正序扫，最后命中即最大
            if (cnt[x] == 1) ans = x;
        return ans;
    }
};
```

### Python

```python
class Solution:
    def largestInteger(self, nums: List[int], k: int) -> int:
        n = len(nums)
        cnt = [0] * 51
        for s in range(n - k + 1):
            for x in set(nums[s:s + k]):       # 切片转 set，天然窗口内去重
                cnt[x] += 1
        ans = -1
        for x in range(51):
            if cnt[x] == 1:
                ans = x                        # 正序扫，最后命中即最大
        return ans
```

## 8. 边界情况与易错点

1. **窗口内去重是最大陷阱**：同一值在同一窗口出现多次只计 1 次。示例 2 中 7 在 `[7,2,1,7]` 出现两次，若不去重会得到「出现 4 次」之类的错误统计。**覆盖数按「窗口个数」而非「出现次数」计**。
2. **`k = n`**：唯一窗口即整个数组，答案就是 `max(nums)`。暴力按定义模拟天然正确，无需特判。
3. **`k = 1`**：每个元素自成窗口，`cnt[x]` 退化为 `x` 的总频次，答案为频次恰为 1 的最大值。同样无需特判。
4. **`0` 是合法答案**：约束 `nums[i] >= 0`，答案可以为 `0`（如 `nums = [0], k = 1`），故哨兵必须取 `-1`，不能用 `0`。
5. **未出现的值自动落选**：`cnt[x] >= 1` 蕴含 `x` 出现过，反之未出现过的值恒有 `cnt[x] = 0`，不会误判，无需额外存在性检查。
6. **起点边界**：`s` 的范围是 `[0, n-k]` 共 `n-k+1` 个窗口，循环条件 `s + k <= n` 最不易写错。

**延伸思考**：

- **能否做到 `O(n + V)`？** 可以。当 $1 < k < n$ 时，覆盖下标 $i$ 的起点区间为 $[\max(0, i-k+1),\ \min(i, n-k)]$，内部下标（$1 \le i \le n-2$）的该区间长度 $\ge 2$，至少被 2 个窗口覆盖，必然出局；因此候选仅剩 `nums[0]` 与 `nums[n-1]`（且需在全数组中频次恰为 1）。$k = n$ 时答案即 $\max(nums)$；$k = 1$ 时答案为频次恰为 1 的最大值。三类情况一趟频次统计即可覆盖。本题 $n \le 50$，暴力已足够，追求线性解属于赛后加练。
- **推广「恰好出现在 $m$ 个子数组」**：把值 $x$ 的每个出现位置 $p$ 映射成起点数轴上的禁区间 $[p, p+k-1]$，对 $[0, n-k]$ 做区间并计数，即可在 $O(n \log n)$ 内对任意 $m$ 求解；本题的分类结论正是 $m = 1$ 的手算特例。
