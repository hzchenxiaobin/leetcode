# LeetCode 至多 K 次操作后的最长回文子序列 题解

## 1. 题目概述

- **标题 / 题号**：至多 K 次操作后的最长回文子序列（#3472，medium）
- **链接**：https://leetcode.cn/problems/longest-palindromic-subsequence-after-at-most-k-operations/
- **来源**：LeetCode 第 439 场周赛 Q2
- **难度**：中等
- **标签**：字符串、动态规划、区间 DP

**题意**：给定字符串 `s` 与整数 `k`。一次操作可以把**任意一个位置**上的字符替换为字母表中**相邻**的字符，字母表是**循环**的（`'z'` 的下一个字母是 `'a'`，`'a'` 的上一个字母是 `'z'`）。至多 `k` 次操作后，返回 `s` 的**最长回文子序列**的长度。

**约束**：

- `1 <= s.length <= 200`
- `1 <= k <= 200`
- `s` 仅由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：s = "abced", k = 2
输出：3
解释：把 s[1] 的 'b' 与 s[4] 的 'd' 各挪一步变成 'c'，得到 "accec"，
      取下标 1、2、4 得到回文子序列 "ccc"。
```

**示例 2**

```text
输入：s = "aaazzz", k = 4
输出：6
解释：三对端点 (0,5)、(1,4)、(2,3) 每对的 'a' 与 'z' 只需跨过环口挪 1 步即可相等，
      总代价 3 ≤ 4，整个字符串可变成回文 "zaaaaz"。
```

**示例 3（自造：验证循环距离）**

```text
输入：s = "zb", k = 1
输出：1
解释：d('z', 'b') = min(24, 26 - 24) = 2 > 1，两端配不起，只能取单字符。

输入：s = "zb", k = 2
输出：2
解释：'z' 与 'b' 沿环相向各挪一步（或一侧挪两步）即可相等，长度 2。
```

## 3. 解题思路

经典最长回文子序列（LPS）是区间 DP；本题在此基础上多了一层「花钱改字符」。关键在于把「操作」翻译成**配对代价**，再把**预算**塞进状态。

### 3.1 暴力思路

最直接的暴力：枚举每个位置的**最终字符**（26 种选择，代价 = 与原字符的环距离），舍去总代价超过 `k` 的方案，对每个最终串跑一遍经典 LPS 取最大值。方案数 $26^n$，$n = 200$ 时是天文数字。

这条暴力也暗示了两个正确方向：操作只该花在**被选进子序列的位置**上；而每个位置的最终字符怎么选，本质上由「它要和谁配对」决定。

### 3.2 核心观察：嵌套配对 + 独立代价 + 预算维度

**观察 1（回文子序列 = 嵌套配对 + 免费中心）**：长度为 $m$ 的回文子序列由 $\lfloor m/2 \rfloor$ 对**嵌套**的位置对构成——第 $r$ 个字符与第 $m+1-r$ 个字符配对；$m$ 为奇数时剩一个孤立的**中心字符**。每个下标至多落入一对。中心字符单枪匹马就是回文，**一次操作都不用花**；被丢弃的位置更不值得花操作。

**观察 2（单对代价 = 环上最短距离）**：把一对端点字符 $a$、$b$ 变成相同的最少操作数，恰为 26 字母环上的距离

$$d(a,b) = \min\bigl(|a-b|,\ 26-|a-b|\bigr) \in [0, 13]$$

可以只挪一侧 $d$ 步，也可以两侧沿短弧**相向**而行（总步数仍是 $d$）；而每次操作至多让两字符的环距离变化 $1$，所以 $d$ 步一步也省不掉，也无需多花。

**观察 3（代价独立可加）**：配对位置互不重叠，各对的操作互不干扰，总代价 = 诸对代价之和。于是全部自由度就是「**选哪些嵌套配对**」，预算可以整体作为一维塞进区间 DP：

$$dp[i][j][b] = s[i..j]\ \text{在至多}\ b\ \text{次操作内的最长回文子序列长度}$$

![循环字母表与配对代价](images/lpsk_cyclic_distance.svg)

### 3.3 算法流程

```text
预处理 c(i,j) = d(s[i], s[j])
dp[i][i][b] ← 1                       # 单字符，零代价
dp[i][j][b] ← 0                       # i > j，空区间
for i = n-2 … 0:                       # 左端点从右往左
    for j = i+1 … n-1:                 # 右端点向右扩
        c ← d(s[i], s[j])
        for b = 0 … k:
            dp[i][j][b] ← max( dp[i+1][j][b],           # 不用 s[i]
                               dp[i][j-1][b],           # 不用 s[j]
                               2 + dp[i+1][j-1][b-c] )  # 配对 (i,j)，需 c ≤ b
return dp[0][n-1][k]
```

三个分支恰好穷尽「最优解是否使用 $s_i$、$s_j$」的所有情形：若两端都被使用，它们必然是最外层配对，花代价 $c$；否则弃掉一端，问题缩到更短的区间。

![区间 DP 的三个来源](images/lpsk_interval_dp_decisions.svg)

### 3.4 示例演算

**示例 1**（`s = "abced"`，`k = 2`）：最优结构是配对 $(1, 4)$——$d(\texttt{b}, \texttt{d}) = 2$，恰好花光预算；内区间 $[2, 3]$ 里取 $s_2 = \texttt{c}$ 作免费中心，长度 $2 + 1 = 3$。两步操作 `b→c`、`d→c` 后得 `"accec"`，取下标 1、2、4 即 `"ccc"`。顺带一提，`k = 1` 时答案已是 3：配对 $(2, 4)$ 只需 $d(\texttt{c}, \texttt{d}) = 1$，中心 $\texttt{e}$ 免费；而想配 $(0, 4)$ 要 $d(\texttt{a}, \texttt{d}) = 3 > 2$，配不起。

**示例 2**（`s = "aaazzz"`，`k = 4`）：三对嵌套 $(0,5)$、$(1,4)$、$(2,3)$，每对 $d(\texttt{a}, \texttt{z}) = 1$（跨过环口！），总代价 $1+1+1 = 3 \le 4$，长度 6。官方解释用 3 步得到 `"zaaaaz"`，其实 3 步就是最优——$k = 3$ 时答案同样是 6。

![两个示例的配对与代价演算](images/lpsk_example_walkthrough.svg)

## 4. 算法细节

1. **环距离**：`c = min(|a-b|, 26-|a-b|)`，现算 $O(1)$，无需预处理。
2. **循环顺序**：$i$ 自 $n-2$ 向 $0$、$j$ 自 $i+1$ 向右，保证 $dp[i+1][\cdot]$ 与 $dp[i][j-1]$ 先于 $dp[i][j]$ 就绪；$b$ 维在最内层 $0..k$。
3. **空内区间**：$j = i+1$ 时 $dp[i+1][j-1] = dp[i+1][i]$ 表示空区间，取 0，配对分支恰得 2。三维数组里这一项从未被赋值、天然为 0；滚动实现里行 $i+1$ 中下标小于 $i+1$ 的列同样保持 0，均无需特判。
4. **预算语义取「至多 $b$」**：配对分支给内侧留 $b - c$ 而非 $b$；没用完的预算直接作废——把操作浪费在未选中的位置永远不更优（见引理 2），无需建模。
5. **空间**：朴素三维 $O(n^2 k) \approx 8 \times 10^6$ 个 int（C++ 约 32 MB）可直接开；由于 $dp[i][\cdot]$ 只依赖第 $i+1$ 行与本行左侧，可两行滚动压到 $O(nk)$。Python 参考实现即用滚动行，并把 $b$ 维整行交给切片与 `zip` 推导式更新。

## 5. 正确性证明

**引理 1（单对最小代价）**：设两位置的初始字符分别为 $a$、$b$，经若干操作后都变成 $t$，两位置上分别落了 $p$、$q$ 次操作，则 $p + q \ge d(a,b)$；且存在恰好用 $d(a,b)$ 次操作的方案。

**证明**：把 26 个字母看作环 $C_{26}$，两字符间的环距离 $\rho$ 是环上最短路，满足三角不等式；一次操作恰把一个字符挪到环上相邻点，故两字符间的 $\rho$ 每次操作至多变化 $1$。初始 $\rho(a, b) = d(a,b)$，终态 $\rho(t, t) = 0$，故 $p + q \ge d(a,b)$。反之，沿长度为 $d := d(a,b)$ 的短弧，让 $a$ 前进 $x$ 步、$b$ 后退 $d - x$ 步（$0 \le x \le d$），两端在弧上相遇，恰用 $d$ 次。∎

**引理 2（结构与操作互化）**：称一组嵌套位置对 $(i_1,j_1) \supset (i_2,j_2) \supset \cdots$（可附带一个未被配对覆盖的中心位置）为一个**结构**，其代价为 $\sum_r d(s[i_r], s[j_r])$，其值为 $2 \times \text{对数} + [\text{配对收缩后内区间非空}]$。则：(a) 至多 $k$ 次操作后的任何串中、任何长 $m$ 的回文子序列，都对应一个代价 $\le k$、值恰为 $m$ 的结构；(b) 任何代价 $\le k$ 的结构都能以 $\le k$ 次操作实现，得到长度等于其值的回文子序列。

**证明**：(a) 设 $P$ 为最终串 $t$ 中长 $m$ 的回文子序列，把 $P$ 的第 $r$ 个与第 $m+1-r$ 个字符所在位置配对（$m$ 偶；$m$ 奇时中间位置孤立，充当中心）。删去作用在 $P$ 之外位置上的操作不影响 $P$ 的字符，故可设所有操作都落在 $P$ 的位置上，总数 $\le k$。对每对 $(i,j)$：设位置 $i$、$j$ 上分别落了 $n_i$、$n_j$ 次操作，每次操作至多挪一步，故 $n_i \ge \rho(s[i], t[i])$、$n_j \ge \rho(t[j], s[j])$；由三角不等式与 $t[i] = t[j]$，

$$d(s[i],s[j]) = \rho(s[i],s[j]) \le \rho(s[i],t[i]) + \rho(t[i],t[j]) + \rho(t[j],s[j]) \le n_i + n_j$$

对诸对求和即结构代价 $\le k$。$m$ 奇时中心恰为收缩后剩下的位置，值 $= m$；$m$ 偶时诸对恰耗尽 $P$ 的位置，值 $= m$。(b) 对每对按引理 1 的方案花恰好 $d(s[i_r], s[j_r])$ 次操作使两端相等，总代价 $\le k$；从外到内取出各对共 $2 \times \text{对数}$ 个字符即回文，若内区间非空再任取一个字符作中心（无需操作）。∎

**定理**：对一切 $i \le j$、$0 \le b \le k$，$dp[i][j][b]$ 等于 $s[i..j]$ 上代价 $\le b$ 的结构的最大值（记 $OPT(i,j,b)$）；从而 $dp[0][n-1][k]$ 为题目答案。

**证明**：对区间长度 $\ell = j - i + 1$ 归纳。$\ell = 1$：唯一结构是「零对 + 中心」，代价 0、值 1，与基态 $dp[i][i][b] = 1$ 一致。$\ell \ge 2$：先证上界。取最优结构 $S$：

- **$S$ 同时含 $i$ 与 $j$**：若 $S$ 至少有一对，则 $i$、$j$ 是 $S$ 的最小、最大下标，嵌套性迫使最外层配对恰为 $(i, j)$；去掉它，剩下是 $[i+1, j-1]$ 上代价 $\le b - c$ 的结构（$c = d(s[i], s[j]) \le b$），且值恰好少 2（中心可用性不变），故 $OPT(i,j,b) \le 2 + OPT(i+1, j-1, b-c)$。若 $S$ 零对，值为 1，而 $OPT(i+1, j, b) \ge 1$（区间非空总有单字符结构）。
- **$S$ 不含 $i$**：$S$ 是 $[i+1, j]$ 上代价 $\le b$ 的结构，$OPT(i,j,b) \le OPT(i+1, j, b)$；不含 $j$ 同理得 $OPT(i,j,b) \le OPT(i, j-1, b)$。

再证下界：三个分支各自的结构原封不动也是 $[i, j]$ 上的合法结构（弃掉端点不增代价），配对分支则是「外层加一对 $(i,j)$、值恰加 2」，故 $OPT(i,j,b)$ 不小于三者之 max。由归纳假设，更短区间上 $dp = OPT$，而 $dp[i][j][b]$ 的转移恰取三者之 max，故 $dp[i][j][b] = OPT(i,j,b)$。结合引理 2，$OPT(0, n-1, k)$ 即题目所求的最大长度。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2 k)$。$n = k = 200$ 时约 $200 \times 200 \times 201 \approx 8 \times 10^6$ 个状态、每状态 $O(1)$ 转移，C++ 毫秒级；Python 需把 $b$ 维整行交给切片与 `zip` 推导式（见参考代码），避免逐状态的解释器循环。
- **空间复杂度**：朴素三维 $O(n^2 k)$，int 约 32 MB；按 $i$ 滚动两行后 $O(nk) \approx 4 \times 10^4$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int longestPalindromicSubsequence(string s, int k) {
        int n = s.size();
        // dp[i][j][b]：s[i..j] 至多 b 次操作下的最长回文子序列
        vector<vector<vector<int>>> dp(
            n, vector<vector<int>>(n, vector<int>(k + 1, 0)));
        for (int i = 0; i < n; i++)
            for (int b = 0; b <= k; b++) dp[i][i][b] = 1;  // 单字符零代价
        for (int i = n - 2; i >= 0; i--) {
            for (int j = i + 1; j < n; j++) {
                int x = s[i] - 'a', y = s[j] - 'a';
                int c = min((x - y + 26) % 26, (y - x + 26) % 26);  // 环距离
                for (int budget = 0; budget <= k; budget++) {
                    int best = max(dp[i + 1][j][budget], dp[i][j - 1][budget]);
                    if (c <= budget)
                        best = max(best, dp[i + 1][j - 1][budget - c] + 2);
                    dp[i][j][budget] = best;
                }
            }
        }
        return dp[0][n - 1][k];
    }
};
```

### Python

```python
class Solution:
    def longestPalindromicSubsequence(self, s: str, k: int) -> int:
        n = len(s)
        B = k + 1
        # nxt[j][b] = dp[i+1][j][b]，cur 为第 i 行；滚动两行省内存
        nxt = [[0] * B for _ in range(n)]
        nxt[n - 1] = [1] * B                  # 第 n-1 行：仅对角线为 1
        for i in range(n - 2, -1, -1):
            cur = [[0] * B for _ in range(n)]
            cur[i] = [1] * B
            for j in range(i + 1, n):
                d = abs(ord(s[i]) - ord(s[j]))
                d = min(d, 26 - d)            # 环距离
                row = [x if x > y else y for x, y in zip(nxt[j], cur[j - 1])]
                inner = nxt[j - 1]            # j = i+1 时是全 0 的空区间
                if d == 0:
                    row = [x if x > t + 2 else t + 2 for x, t in zip(row, inner)]
                elif d <= k:
                    row[d:] = [x if x > t + 2 else t + 2
                               for x, t in zip(row[d:], inner)]
                cur[j] = row
            nxt = cur
        return nxt[n - 1][k]
```

## 8. 边界情况与易错点

1. **循环方向是头号陷阱**：$d(\texttt{a}, \texttt{z}) = 1$ 而非 25；忘了 $\min(d, 26-d)$，示例 2 会直接算错。
2. **空内区间**：$j = i+1$ 时配对值恰为 2（内区间取 0）。若实现把 $i > j$ 的空区间与 $i = j$ 的单字符混在一起（比如滚动行的列下标算错），会平白多算 1。
3. **预算传 $b - c$ 而非 $b$**：给内侧留的是扣掉配对代价后的余额；写成 $b$ 等于让同一份预算花两遍。
4. **「至多」而非「恰好」**：剩余预算直接作废；把操作浪费在未选中的位置永远不优（引理 2），无需建模。
5. **别先跑经典 LPS 再补钱**：最优配对结构本身随预算变化——可能弃掉一对昂贵的外层、改用两对便宜的内层，局部修补不成立，必须把预算放进状态从头 DP。
6. **$n = 1$**：答案恒为 1（单字符自成回文），基态直接覆盖，无需特判。
7. **内存**：三维 int 在 $n = k = 200$ 时约 32 MB，若内存吃紧改两行滚动 $O(nk)$；Python 慎用三层嵌套列表（内存与速度都吃亏），按行滚动 + 切片赋值。
8. **Python 性能**：$8 \times 10^6$ 个纯解释器循环状态易超时；参考代码把 $b$ 维整行交给 `zip` 推导式与切片赋值，把内层循环下放到 C 级。

**延伸思考**：

- **操作改为「替换成任意字母，代价 1」**：配对代价退化为 $[s_i \ne s_j]$，仍是同一个三维 DP 套路。

- **更省的状态**：$d \le 13$ 且配对数 $\le \lfloor n/2 \rfloor$，预算超过 $13\lfloor n/2 \rfloor$ 的部分必然闲置，可把 $b$ 维截断到 $\min(k,\ 13\lfloor n/2 \rfloor)$，对大 $k$ 小 $n$ 的用例有实际收益。
