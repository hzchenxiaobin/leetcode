# LeetCode 重排完成顺序 题解

## 1. 题目概述

- **标题 / 题号**：重排完成顺序（#3668，easy）
- **链接**：https://leetcode.cn/problems/restore-finishing-order/
- **来源**：LeetCode 第 465 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表

**题意**：给定长度为 $n$ 的数组 `order`，它是 $1 \sim n$ 的一个排列，`order[i]` 表示第 $i$ 个完成比赛的参赛者 ID。再给定数组 `friends`（严格递增，按 ID 排序）。要求返回朋友们的 ID 按**完成顺序**排列的数组。

**约束**：

- `1 <= n == order.length <= 100`
- `order` 包含 $1 \sim n$ 每个整数且恰好出现一次
- `1 <= friends.length <= min(8, n)`
- `1 <= friends[i] <= n`，`friends` 严格递增

> 💡 关键读题点：`friends` 是**按 ID 递增**给出的，与完成顺序无关；答案必须按 `order` 中的出现顺序输出。

## 2. 示例

**示例 1**

```text
输入：order = [3,1,2,5,4], friends = [1,3,4]
输出：[3,1,4]
解释：完成顺序是 [3, 1, 2, 5, 4]，其中朋友是 3、1、4，按完成先后排列即 [3, 1, 4]。
```

**示例 2**

```text
输入：order = [1,4,5,3,2], friends = [2,5]
输出：[5,2]
解释：5 在第 3 位完成，2 在第 5 位完成，故 [5, 2]。
```

**示例 3（全部参赛者都是朋友）**

```text
输入：order = [1,2,3], friends = [1,2,3]
输出：[1,2,3]
解释：所有人都是朋友，答案就是 order 本身。
```

## 3. 解题思路

### 3.1 暴力思路

对 `order` 中每个元素，线性扫描 `friends` 判断是否是朋友，是则追加到答案。时间复杂度 $O(n \cdot m)$，其中 $m$ = `friends.length`。本题 $n \le 100$、$m \le 8$，最多 800 次比较，完全可以接受，但逐个线性查找不够优雅。

### 3.2 核心观察：答案是 order 的子序列（哈希集合过滤）

答案只是**保持 `order` 的相对顺序、筛选出属于 `friends` 的元素**——一次遍历 + $O(1)$ 集合查询即可。把 `friends` 存入**哈希集合**，再按 `order` 顺序扫描，命中就收集。

![核心思路：按 order 的顺序筛出朋友](images/restore_finishing_order_concept.svg)

**为什么不能直接返回 `friends`**：`friends` 按 ID 递增（示例 1 中是 `[1,3,4]`），而答案按完成顺序（`[3,1,4]`），两者排序依据不同。

### 3.3 算法流程

1. 把 `friends` 全部放入哈希集合 `st`。
2. 从左到右遍历 `order`：
   - 若 `x ∈ st`，把 `x` 追加到结果数组 `res`；
   - 否则跳过。
3. 返回 `res`。

### 3.4 示例演算

以 `order = [3,1,2,5,4]`、`friends = {1,3,4}` 为例：

| 步骤 | 当前 x | 是否朋友 | 结果 res |
|------|--------|----------|----------|
| 1 | 3 | ✓ 是 | [3] |
| 2 | 1 | ✓ 是 | [3, 1] |
| 3 | 2 | ✗ 否 | [3, 1] |
| 4 | 5 | ✗ 否 | [3, 1] |
| 5 | 4 | ✓ 是 | [3, 1, 4] |

![示例演算：逐个扫描 order 并收集朋友](images/restore_finishing_order_example.svg)

## 4. 算法细节

1. **哈希集合构建**：`unordered_set<int> st(friends.begin(), friends.end())`（C++）或 `set(friends)`（Python），建集合 $O(m)$，此后每次查询均摊 $O(1)$。
2. **顺序保持**：遍历的是 `order` 而不是 `friends`，天然保持了完成顺序，无需任何排序。
3. **替代实现（更快的常数）**：由于 ID 范围是 $1 \sim n$，可用长度 $n+1$ 的 `bool` 数组代替哈希集合，`isFriend[x] = true` 标记朋友，查询严格 $O(1)$ 且无哈希开销。
4. **另一等价做法**：先遍历 `order` 记录每个朋友的**名次** `pos[x]`，再对 `friends` 按 `pos` 排序，复杂度 $O(n + m\log m)$。当 $m \ll n$ 时与过滤法同为线性级别，但写法更绕，签到题没必要。

## 5. 正确性证明

**引理 1**：`order` 中元素的出现顺序就是完成名次顺序，即对任意两个 ID $a, b$：$a$ 在 `order` 中先于 $b$ 出现 $\iff$ $a$ 比 $b$ 先完成。

**证明**：题面定义 `order` 为"参赛者按照完成顺序的 ID"，直接得证。∎

**引理 2**：`friends` 中每个 ID 恰在 `order` 中出现一次。

**证明**：`order` 是 $1 \sim n$ 的排列（每个整数恰好出现一次），而 `friends` 中每个 ID 都保证出现在 `order` 中且 `friends` 内无重复（严格递增），故每个朋友 ID 在 `order` 中恰被扫描到一次。∎

**定理**：过滤法输出的数组恰为朋友们按完成顺序排列的结果。

**证明**：由引理 2，遍历 `order` 时每个朋友 ID 恰好命中一次，故输出包含 `friends` 的全部元素、无遗漏无重复；由算法按 `order` 从左到右收集，再由引理 1，输出中元素的先后即完成名次的先后。两个性质合起来恰是题目所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。建哈希集合 $O(m)$，遍历 `order` 一次 $O(n)$，每次查询均摊 $O(1)$。
- **空间复杂度**：$O(m)$。哈希集合存 $m$ 个朋友 ID（输出数组不计入额外空间；若用 bool 数组则为 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> recoverOrder(vector<int>& order, vector<int>& friends) {
        unordered_set<int> st(friends.begin(), friends.end());
        vector<int> res;
        for (int x : order) {
            if (st.count(x)) {
                res.push_back(x);
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def recoverOrder(self, order: List[int], friends: List[int]) -> List[int]:
        st = set(friends)
        return [x for x in order if x in st]
```

## 8. 边界情况与易错点

1. **最大陷阱：直接返回 `friends`**。`friends` 按 ID 递增而非完成顺序，示例 1 中返回 `[1,3,4]` 即 WA。
2. **遍历对象搞反**：应对 `order` 遍历、对 `friends` 建集合；若对 `friends` 遍历、对 `order` 建集合，还得额外记录位置再排序，多此一举。
3. **全部参赛者都是朋友**：答案就是 `order` 本身（示例 3），过滤法天然正确。
4. **只有一个朋友**：`friends.length == 1`，答案是单元素数组。
5. **输出长度**：答案长度恒等于 `friends.length`，可用作提交前自检。
6. **数据范围极小**：$n \le 100$、$m \le 8$，任何 $O(n \cdot m)$ 以内的做法都能过，重点是写对而非写快。
