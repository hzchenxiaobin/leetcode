# LeetCode 循环数组中相邻元素的最大差值 题解

## 1. 题目概述

- **标题 / 题号**：循环数组中相邻元素的最大差值（#3423，easy）
- **链接**：https://leetcode.cn/problems/maximum-difference-between-adjacent-elements-in-a-circular-array/
- **来源**：LeetCode 第 148 场双周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：给定一个**循环**数组 `nums`，求相邻元素之间的**绝对差值**的最大值。循环的含义是：最后一个元素与第一个元素也被视为相邻。

**约束**：

- $2 \le \text{nums.length} \le 100$
- $-100 \le \text{nums}[i] \le 100$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,4]
输出：3
解释：循环意义下有 3 条相邻边：|1−2| = 1、|2−4| = 2、|4−1| = 3，
      最大的是首尾那条，答案 3。
```

**示例 2**

```text
输入：nums = [-5,-10,-5]
输出：5
解释：|−5 − (−10)| = 5、|−10 − (−5)| = 5、|−5 − (−5)| = 0，答案 5。
```

## 3. 解题思路

### 3.1 暴力思路

"最大差值"的一个诱人错误做法是：取全部元素的最大值减最小值。它在本题是**错的**，因为差值必须在**相邻**元素之间取。反例 `nums = [0, 50, 100, 51]`：四条相邻边的差分别是 $50, 50, 49, 51$，答案是 $51$；而 `max − min = 100`。注意"最大值与最小值恰好相邻"只是巧合，不能当成通用做法。

真正的暴力就是"枚举所有相邻对"，共 $n$ 条边（含首尾那条），逐个取绝对值后求最大值，复杂度 $O(n)$ —— 这已经是本题的最优解。

### 3.2 核心观察：循环 = 下标取模

![循环数组：把下标 (i+1) % n 当作"下一个"](images/bw148_q1_circular_adjacency.svg)

$n$ 个元素的循环数组恰好有 $n$ 条相邻边：

$$(0,1),\ (1,2),\ \dots,\ (n-2,n-1),\ (n-1,0)$$

前 $n-1$ 条是线性相邻，最后一条是"绕回起点"的边。用一个下标取模就能统一表达：

$$\text{ans} = \max_{0 \le i < n} \bigl|\text{nums}[i] - \text{nums}[(i+1) \bmod n]\bigr|$$

$i = n-1$ 时 $(i+1) \bmod n = 0$，自动覆盖首尾边，无需单独处理。

### 3.3 算法流程

```text
ans = 0
for i = 0 .. n-1:
    j = (i + 1) % n
    ans = max(ans, |nums[i] - nums[j]|)
返回 ans
```

三行代码，一个循环。关键只有两点：**取绝对值**、**下标取模**。

### 3.4 示例演算

![两个示例的逐边走查](images/bw148_q1_walkthrough.svg)

示例 1 的三条边与差值：

| 边 | 绝对差 |
|----|--------|
| `nums[0]` 与 `nums[1]` | $\lvert 1 - 2\rvert = 1$ |
| `nums[1]` 与 `nums[2]` | $\lvert 2 - 4\rvert = 2$ |
| `nums[2]` 与 `nums[0]` | $\lvert 4 - 1\rvert = 3$ ← 首尾边 |

答案 $3$。示例 2 则是 $5, 5, 0$，答案 $5$。两个例子里"最大值"分别出现在首尾边与线性边，说明两种边都不能漏。

## 4. 算法细节

1. **下标取模**：`(i + 1) % n`。也可以把数组复制一份接在后面、只扫前 $n$ 条边，效果相同但多花 $O(n)$ 空间。
2. **绝对值**：C++ 用 `abs(int)`（`<cstdlib>`/`<cmath>`），Python 用内置 `abs`。切记不要写成有符号差。
3. **答案初值**：取 $0$ 即可 —— 绝对差非负，且 $n \ge 2$ 时至少有一条边。
4. **循环的最后一条边**：靠取模自动处理，不要写两段循环（容易漏）。

## 5. 正确性证明

**引理 1**：循环数组 `nums` 的相邻元素对恰好是 $\{(i, (i+1) \bmod n) : 0 \le i < n\}$。

**证明**：循环数组中"相邻"定义为"下标相差 1（模 $n$）"。对每个 $i$，$(i, (i+1) \bmod n)$ 是一对相邻元素；又 $i$ 遍历 $0..n-1$ 时 $(i+1) \bmod n$ 遍历 $1,2,\dots,n-1,0$，所以这 $n$ 对互不相同且穷尽了所有相邻关系。∎

**定理**：算法返回循环数组中相邻元素绝对差的最大值。

**证明**：由引理 1，算法枚举的正是全部相邻元素对；对每一对计算绝对差并取最大，故返回值等于 $\max$ 定义。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一趟扫描，每次做一次取模、一次减法、一次绝对值、一次比较，常数极小。
- **空间**：$O(1)$，只用了一个答案变量（不计输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxAdjacentDistance(vector<int>& nums) {
        int n = (int)nums.size();
        int ans = 0;
        for (int i = 0; i < n; i++) {
            int j = (i + 1) % n;            // 循环：最后一个元素和第一个元素也相邻
            ans = max(ans, abs(nums[i] - nums[j]));
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def maxAdjacentDistance(self, nums: list) -> int:
        n = len(nums)
        return max(abs(nums[i] - nums[(i + 1) % n]) for i in range(n))
```

## 8. 边界情况与易错点

1. **漏掉首尾边**：只扫 $i = 0..n-2$ 是最常见的错法，示例 1 的答案正好落在漏掉的那条边上。
2. **负数差值**：不取绝对值时，`[-5,-10,-5]` 会算出 $-5, 5, 0$ 混在一起，`max` 直接错。
3. **`n = 2`**：循环数组退化为两个元素，两条边是同一个差值算两次，结果正确（不需要特判）。
4. **不要用 `max − min`**：它算的是"最远两元素"的差，`[0,50,100,51]` 就是反例（正确答案 51）。
5. **`ans` 初值**：用 $0$ 安全（绝对差非负）；若用 `INT_MIN` 也不影响，但要注意 $n \ge 2$ 保证至少一次更新。
6. **数组元素范围**：$|nums[i]| \le 100$，差值绝对值 $\le 200$，`int` 足够，不需要 64 位。
