# LeetCode 将数组变相同的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：将数组变相同的最小代价（#3424，medium）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-make-arrays-identical/
- **来源**：LeetCode 第 148 场双周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：给定两个等长数组 `arr`、`brr` 与整数 $k$。可以对 `arr` 反复执行两类操作：

1. 把 `arr` 分割成若干**连续**子数组并按任意顺序重排，代价为 $k$（每次执行都付 $k$）；
2. 选 `arr` 中任一元素加/减一个正整数 $x$，代价为 $x$。

求把 `arr` 变成 `brr` 的**最小总代价**。

**约束**：

- $1 \le \text{arr.length} = \text{brr.length} \le 10^5$
- $0 \le k \le 2 \cdot 10^{10}$
- $-10^5 \le \text{arr}[i], \text{brr}[i] \le 10^5$

$k$ 可以大到 $2 \cdot 10^{10}$，答案需要用 64 位整数。

## 2. 示例

**示例 1**

```text
输入：arr = [-7,9,5], brr = [7,-2,-5], k = 2
输出：13
解释：花 2 把 arr 重排成 [9,5,-7]，再逐位调整：
      |9 - 7| = 2、|5 - (-2)| = 7、|-7 - (-5)| = 2，合计 11，总代价 2 + 11 = 13。
      （不重排的方案要 14 + 11 + 10 = 35。）
```

**示例 2**

```text
输入：arr = [2,1], brr = [2,1], k = 0
输出：0
解释：数组本来就相同，两个方案都是 0。
```

## 3. 解题思路

### 3.1 暴力思路

把操作 1 看成"可以任意置换 `arr`，付一次 $k$"（理由见 3.2），于是问题变成：在"最多使用一次置换"的约束下最小化 $\sum |a_i - b_i|$。暴力做法是枚举 $n!$ 种置换，$O(n! \cdot n)$，完全不可行。即便只看"用一次置换"的子问题，也需要一个最优配对的结构性结论。

### 3.2 核心观察：方案只有两种

![只有两条路：要么完全不重排，要么花一次 k 把顺序彻底打散](images/bw148_q2_two_plans.svg)

- **操作 1 一次就够**：把 `arr` 拆成 $n$ 个长度为 1 的连续子数组，再按任意顺序放回，就实现了**任意排列**，代价只付一次 $k$。所以"用操作 1"的最优策略就是付一次 $k$，之后顺序完全自由。
- **操作 2 的代价可加**：把 $a_i$ 调成 $b_i$ 的最小代价正是 $|a_i - b_i|$（加/减 1 记 1），且各位置独立。

于是答案只可能是下面两者之一：

$$\text{cost}_0 = \sum_{i} |\text{arr}[i] - \text{brr}[i]|, \qquad \text{cost}_1 = k + \sum_{i} |a'_i - b'_i|$$

其中 $a'$ 是 `arr` 排序后的结果、$b'$ 是 `brr` 排序后的结果。

### 3.3 算法流程

![重排后最优配对 = 排序配对：交叉一定比不交叉更差](images/bw148_q2_sorted_matching.svg)

```text
1. cost0 = Σ |arr[i] − brr[i]|
2. a′ = sort(arr)，b′ = sort(brr)
   cost1 = k + Σ |a′[i] − b′[i]|
3. 返回 min(cost0, cost1)
```

关键在于 $\text{cost}_1$ 里"排序后同位置配对最优"这一结论 —— 它来自**重排不等式**（交换论证）：

> 若 $a_1 \le a_2$、$b_1 \le b_2$，则 $|a_1 - b_1| + |a_2 - b_2| \le |a_1 - b_2| + |a_2 - b_1|$。

因此任何"交叉"的配对都能被交换成"不交叉"而总代价不增，反复交换即得排序配对。

### 3.4 示例演算

![示例 1 演算](images/bw148_q2_example_walkthrough.svg)

| 方案 | 配对方式 | 逐位代价 | 合计 |
|------|----------|----------|------|
| A（不重排） | $(-7,7), (9,-2), (5,-5)$ | $14, 11, 10$ | $35$ |
| B（重排） | $a' = [-7,5,9]$ 与 $b' = [-5,-2,7]$ | $2, 7, 2$ | $k + 11 = 13$ |

$\min(35, 13) = 13$，与官方输出一致。示例 2 中 $k = 0$ 且两数组相同，两个方案都是 $0$。

## 4. 算法细节

1. **两条分支都要算**：即使 $k = 0$，"不重排"仍可能是更优解（此时两者必然相等或方案 B 更好，取 min 最安全）。
2. **64 位**：$n \le 10^5$、$|a_i| \le 10^5$，$\text{cost}_0$ 最坏 $2 \cdot 10^{10}$，而 $k$ 本身就能到 $2 \cdot 10^{10}$，累加用 `long long`。
3. **不要拷贝原数组**：C++ 里对 `arr` 排序会修改入参，可以传值或先拷贝；Python 的 `sorted()` 天然返回新列表。
4. **排序配对的位置无关性**：`arr` 与 `brr` 是两组独立的多重集合，"同位置配对"只是一种枚举顺序，与原始下标无关 —— 这正是重排带来的自由。
5. **$k$ 很大时**：$\text{cost}_1$ 可能溢出 `int`，但不影响取 min 的正确性（用 64 位即可）。

## 5. 正确性证明

**引理 1（一次重排即任意置换）**：对任意排列 $\pi$，存在一次操作 1 把 `arr` 变成 $[\text{arr}[\pi_0], \text{arr}[\pi_1], \dots]$，且代价恰为 $k$。

**证明**：把 `arr` 分割为 $n$ 个单元素子数组 $[\text{arr}[0]], \dots, [\text{arr}[n-1]]$，这些子数组是连续的且覆盖整个数组；按 $\pi$ 的顺序把它们首尾相接，得到 $[\text{arr}[\pi_0], \dots]$。整个过程中只执行了一次操作 1，代价 $k$。∎

**引理 2（重排不等式）**：设 $a_1 \le a_2$、$b_1 \le b_2$，则

$$|a_1 - b_1| + |a_2 - b_2| \le |a_1 - b_2| + |a_2 - b_1|.$$

**证明**：用恒等式 $|u| + |v| = \max\bigl(|u+v|,\ |u-v|\bigr)$ 把两边都展开。记

$$X = \bigl|(a_1 + a_2) - (b_1 + b_2)\bigr|, \qquad A = a_1 - a_2 \le 0, \quad B = b_1 - b_2 \le 0 .$$

则

$$|a_1-b_1| + |a_2-b_2| = \max\bigl(X,\ |A - B|\bigr), \qquad |a_1-b_2| + |a_2-b_1| = \max\bigl(X,\ |A + B|\bigr).$$

因为 $A, B \le 0$，有 $|A + B| = |A| + |B| \ge \bigl||A| - |B|\bigr| = |A - B|$，于是

$$\max\bigl(X, |A+B|\bigr) \ \ge\ \max\bigl(X, |A-B|\bigr),$$

这正是要证的不等式。∎

> 💡 直观解释：两个区间 $[a_1,a_2]$ 与 $[b_1,b_2]$ 若"交叉配对"，同一段距离会被重复计算；同向配对不会。

**引理 3（排序配对最优）**：对任意两组实数 $a_1..a_n$ 与 $b_1..b_n$，若把两者都升序排列，则 $\sum_i |a_i - b_i|$ 在所有配对中最小。

**证明**：对逆序对个数归纳。若最优配对中存在 $i < j$ 与配对后的 $b$ 位置反序（即 $a_i \le a_j$ 而配给 $a_i$ 的 $b$ 大于配给 $a_j$ 的 $b$），由引理 2 交换这两个配对的总代价不增。交换一次减少一个逆序对，故最终得到无逆序的配对 —— 即排序配对，代价不超过原最优，因此它也是最优。∎

**定理**：算法返回把 `arr` 变成 `brr` 的最小总代价。

**证明**：任一策略若从未使用操作 1，则每个位置必须独立地从 `arr[i]` 调到 `brr[i]`，最小代价为 $\sum |\text{arr}[i] - \text{brr}[i]| = \text{cost}_0$（操作 2 的加减代价满足三角不等式，逐位独立最优）。若使用了操作 1，则至少付 $k$；由引理 1，任意置换只需一次操作即可达成，故最优策略是用一次操作 1 后再调整，最小代价为 $k + \min_\pi \sum_i |\text{arr}[\pi_i] - \text{brr}[i]|$；由引理 3 该最小值为 $k + \sum_i |a'_i - b'_i| = \text{cost}_1$。两类穷尽所有策略，故答案为 $\min(\text{cost}_0, \text{cost}_1)$。∎

## 6. 复杂度分析

- **时间**：计算 $\text{cost}_0$ 为 $O(n)$；两次排序各 $O(n \log n)$；计算 $\text{cost}_1$ 为 $O(n)$。总计 $O(n \log n)$，$n = 10^5$ 时排序是瓶颈。
- **空间**：$O(n)$ 存放排序后的副本（C++ 可原地排序输入副本，Python 的 `sorted` 需要 $O(n)$）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long minCost(vector<int>& arr, vector<int>& brr, long long k) {
        int n = (int)arr.size();
        // 方案一：一次重排都不用，逐位调整
        long long cost0 = 0;
        for (int i = 0; i < n; i++) cost0 += llabs((long long)arr[i] - brr[i]);

        // 方案二：花 k 把 arr 彻底重排（拆成 n 个单元素子数组），再逐位调整
        vector<int> a = arr, b = brr;
        sort(a.begin(), a.end());
        sort(b.begin(), b.end());
        long long cost1 = k;
        for (int i = 0; i < n; i++) cost1 += llabs((long long)a[i] - b[i]);

        return min(cost0, cost1);
    }
};
```

### Python

```python
class Solution:
    def minCost(self, arr: list, brr: list, k: int) -> int:
        cost0 = sum(abs(x - y) for x, y in zip(arr, brr))
        cost1 = k + sum(abs(x - y) for x, y in zip(sorted(arr), sorted(brr)))
        return min(cost0, cost1)
```

## 8. 边界情况与易错点

1. **$k = 0$**：此时方案 B 白送，但两方案可能相等；直接取 min 无需特判。
2. **$n = 1$**：没有"重排"的意义，$\text{cost}_1 = k + |a_1 - b_1| \ge \text{cost}_0$，min 自动选对。
3. **数组已相同**：$\text{cost}_0 = 0$，答案必为 0（示例 2）。
4. **溢出**：$k$ 可达 $2 \cdot 10^{10}$，$\text{cost}_0$ 可达 $2 \cdot 10^{10}$，必须 `long long`/Python 大整数。
5. **误以为要多次重排**：一次就能实现任意置换，多次只会白花钱。
6. **误用"贪心逐位配对"**：重排后必须**两边都排序**再配对；只排一边不构成最优配对。
7. **修改了入参**：C++ 若直接 `sort(arr)` 会破坏调用方的数据；本解法先拷贝，安全。
