# LeetCode 解码字母到整数映射 题解

## 1. 题目概述

- **标题 / 题号**：解码字母到整数映射（#1309，easy）
- **链接**：https://leetcode.cn/problems/decrypt-string-from-alphabet-to-integer-mapping/
- **来源**：LeetCode 第 170 场周赛 Q1
- **难度**：简单
- **标签**：字符串

**题意**：给定一个只含数字和 `'#'` 的字符串 `s`，它按如下规则编码了小写字母：

- `'a'`–`'i'` 用 `'1'`–`'9'` 表示（**一位**）；
- `'j'`–`'z'` 用 `'10#'`–`'26#'` 表示（**两位数字 + 一个 `#`**）。

要求把 `s` 还原成原来的小写字母串。题目保证**映射唯一**，即 `s` 的切分方式不会出现歧义。

**约束**：

- $1 \le \lvert s \rvert \le 1000$
- `s` 只由数字 `'0'`–`'9'` 和 `'#'` 组成
- `s` 一定可解（存在且唯一存在一种合法解码）

## 2. 示例

**示例 1**

```text
输入：s = "10#11#12"
输出："jkab"
解释："j" -> "10#"，"k" -> "11#"，"a" -> "1"，"b" -> "2"
```

**示例 2**

```text
输入：s = "1326#"
输出："acz"
解释："1" -> "a"，"3" -> "c"，"26#" -> "z"
```

**示例 3（补充边界）**

```text
输入：s = "123456789"
输出："abcdefghi"
解释：没有 '#'，9 个字符各自是一位码。

输入：s = "26#"
输出："z"
解释：'#' 前恰好两位数字，整体是一个 token。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的想法是**枚举切分**：$s$ 有 $n-1$ 个可能的切分点，每个切分点选或不选共 $2^{n-1}$ 种切分方式，逐一检查每段是否为合法编码，最后取那条合法的切分。$n = 1000$ 时 $2^{999}$ 是天量，完全不可接受。

另一种常见写法是从左往右逐位扫描、遇到 `'#'` 再把前两位合并成一位字母。这个方向**能做对**，但需要在取一位码之前先偷看 $s[i+2]$ 是不是 `'#'`，还要额外处理「末尾不足三位」等边界，写起来更绕。

而且题面已经保证解码唯一，我们**根本不需要枚举**——只需要一种能确定「每个 token 从哪开始、到哪结束」的扫描方式。

### 3.2 核心观察：`'#'` 就是 token 的右边界

![两种 token 与 '#' 的位置](images/wc170_q1_code_table.svg)

把编码表当成一个**变长码**来看：

- 一位码：`1`–`9`，长度 1，**不含** `#`；
- 三位码：`10#`–`26#`，长度 3，**必然**以 `#` 结尾。

于是 token 长度只有 1 和 3 两种可能，而且 `'#'` 这个字符**只可能出现在三位码的末尾**。这带来一个非常强的结论：

> 看到 `'#'` 在位置 $i$，它所在的那段编码就**只能是** `s[i-2] s[i-1] '#'`，即 token 的右端点被 `'#'` 钉死了。

反过来，把 $i$ 看作「尚未处理部分的**最后一个字符**」时，$s[i]$ 是不是 `'#'` 就直接决定了这个 token 的长度：是 `'#'`，token 必为 $s[i-2..i]$；不是 `'#'`，token 长度只能是 1——因为长度 3 的 token 末位必为 `'#'`。

所以**从右往左扫**是最省事的方向：最右边的字符一定是**最后一个 token 的末尾**，而判断 token 长度只需要看当前这一个字符，不需要任何前瞻。每一步我们只需要回答一个问题：

$$
s[i] \;=\; \# \quad ?
$$

- 是：取走 `s[i-2..i]`，两位数字 $v$，输出 $\text{chr}(97 + v - 1)$，令 $i \leftarrow i-3$；
- 否：`s[i]` 单独成码，$v = s[i]$，输出 $\text{chr}(97 + v - 1)$，令 $i \leftarrow i-1$。

### 3.3 算法流程

![从右向左扫描的流程](images/wc170_q1_reverse_scan.svg)

```text
res = []
i = n - 1
while i >= 0:
    if s[i] == '#':
        v = (s[i-2] - '0') * 10 + (s[i-1] - '0')   # 10 <= v <= 26
        res.append(chr(96 + v))
        i -= 3
    else:
        v = s[i] - '0'                             # 1 <= v <= 9
        res.append(chr(96 + v))
        i -= 1
反转 res，返回
```

两点值得强调：

1. **不需要回溯**：每个位置的处理方式是**被字符本身决定的**，只有一条路可走；
2. **输出天然是逆序**：从右往左读出的字母是倒着的，所以先 `append`、最后整体 `reverse` 一次即可，比每次头插（$O(n^2)$）快得多。

数值 $v \in [1, 26]$ 到字符的映射就是一个平移：

$$
\text{ch}(v) = \text{chr}(97 + v - 1) = \text{chr}(96 + v)
$$

### 3.4 示例演算

以 `s = "10#11#12"`（$n = 8$）为例，从 $i = 7$ 开始：

![逐字符演算表](images/wc170_q1_walkthrough.svg)

| 步骤 | $i$ | `s[i]` | 判定 | 取出 token | 追加 | 新 $i$ |
|------|-----|--------|------|------------|------|--------|
| 1 | 7 | `'2'` | 非 `#`，一位码 | `"2"` $=2$ | `'b'` | 6 |
| 2 | 6 | `'1'` | 非 `#`，一位码 | `"1"` $=1$ | `'a'` | 5 |
| 3 | 5 | `'#'` | 是 `#`，三位码 | `"11#"` $=11$ | `'k'` | 2 |
| 4 | 2 | `'#'` | 是 `#`，三位码 | `"10#"` $=10$ | `'j'` | $-1$ |
| 结束 | $-1$ | — | 退出循环 | — | `res = "bakj"` | 反转得 `"jkab"` |

第 3 步是本题的关键：$i=5$ 是 `#`，于是直接取 `s[3..5] = "11#"` 得到 $11 \to k$，指针一次跨过 3 个字符；如果按一位码硬拆，`"1"`、`"1"`、`"#"` 根本无解。最后 `res` 是 `"bakj"`，反转后 `"jkab"` 与官方输出一致。

## 4. 算法细节

1. **指针步长**：`i` 每次减 3（三位码）或减 1（一位码），严格单调下降，循环一定在有限步内到达 $i < 0$。
2. **不要用 `substr` + `stoi`**：两位数字直接在原串上算 `(s[i-2]-'0')*10 + (s[i-1]-'0')`，避免每次构造临时子串；Python 里同理，`ord(s[i-2]) - 48` 比 `int(s[i-2:i])` 少一次切片。
3. **结果容器**：C++ 用 `string::push_back` 并 `reserve(n)`（结果长度不会超过 $n$），最后 `reverse`；Python 用 `list.append` 后 `res.reverse()` 再 `''.join`。**不要**用 `res = ch + res`，那是 $O(n^2)$。
4. **字符映射**：`'a' + v - 1`（即 `chr(96 + v)`）。写成 `'a' + v` 会让所有字母后移一位，`"1"` 变成 `'b'`——这是最常见的一处 off-by-one。
5. **不用判越界的理由**：题面保证 `s` 可解，因此每个 `#` 前面必然恰有两位数字；防御性写法可以在取 `s[i-2]`、`s[i-1]` 前加 `i >= 2` 判断（越界只可能来自非法输入）。
6. **循环条件用 `i >= 0`**：因为 `i` 可能一次减 3 直接跨到 $-1$ 或 $-2$，用 `for` 循环遍历下标反而要额外处理步长，`while` 更自然。
7. **结果长度**：输出长度等于 token 个数，$1 \le m \le n$，因此 `reserve(n)` 不会溢出。

## 5. 正确性证明

先明确一个定义：**合法切分**是把 `s` 划分成若干连续不重叠的片段 $t_1 t_2 \cdots t_m$（按顺序拼接恰为 `s`），使得每个 $t_j$ 或是一位数字 `'1'`–`'9'`，或是 `"dd#"` 形式的两位数字加 `#`，且其数值 $v \in [10, 26]$。题面保证这样的切分**存在且唯一**。

**引理 1（token 长度与 `#` 的位置）**：在任意合法切分中，每个 token 的长度为 1 或 3；长度 3 的 token 以 `'#'` 结尾，长度 1 的 token 不含 `'#'`。

**证明**：由编码规则，一位码是单个数字字符，三位码是「数字 + 数字 + `#`」。两种码的字符集不相交（`'#'` 只出现在三位码末位），故长度只能是 1 或 3，且 `'#'` 只作为三位码的最后一个字符出现。∎

**引理 2（`#` 钉死右边界）**：若 $s[i] = \#$，则在任意合法切分中包含位置 $i$ 的 token 恰为 $s[i-2..i]$。

**证明**：由引理 1，含 `'#'` 的 token 只能是三位码且 `'#'` 在其末位，故该 token 的右端点就是 $i$，长度为 3，于是左端点为 $i-2$，token 即 $s[i-2..i]$。∎

**引理 3（末位非 `#` 则长度 1）**：在任意合法切分中，若某个 token 的末位字符不是 `'#'`，则该 token 的长度为 1。

**证明**：由引理 1，token 长度只能是 1 或 3，且长度为 3 时末位必为 `'#'`。若该 token 长度为 3，则末位是 `'#'`，与「末位不是 `'#'`」矛盾。故长度为 1。∎

**引理 4（不变量：$i$ 恒为某 token 的末位）**：设 $n = \lvert s \rvert$。右向左扫描的过程中，每次进入循环时，位置 $i$ 都恰是某个合法切分中某个 token 的末尾，且 $s[i+1..n-1]$ 已被唯一确定地切分完毕。

**证明**：对循环次数归纳。初始 $i = n-1$：任意合法切分的最后一个 token 必以 $n-1$ 结尾，且其后为空，成立。

归纳步：设进入循环时 $i$ 是某 token 的末位。若 $s[i] = \#$，由引理 2 该 token 就是 $s[i-2..i]$，取走后有 $i' = i-3$；由于切分不重叠且连续，$i'$ 是前一个 token 的末位（若 $i' < 0$ 则切分恰好结束），且 $s[i'+1..n-1]$ 已被切分。若 $s[i] \ne \#$，因 $s[i]$ 正是该 token 的末位，由引理 3 该 token 长度为 1，即 $s[i]$ 单独成码，取走后 $i' = i-1$ 是前一个 token 的末位。两种情况不变量都保持。∎

**定理（算法输出正确）**：上述从右向左的贪心扫描输出的字符串，就是 `s` 的唯一合法解码。

**证明**：由引理 4，每一步取出的 token 与唯一合法切分中对应位置的 token 完全相同（长度与内容都由字符本身强制决定，无选择余地）；又 $i$ 每步至少减 1，循环必终止且恰好覆盖 $s$ 的全部位置，故取出的 token 序列与该切分完全一致。每个 token 经 $\text{chr}(96+v)$ 映射到唯一字母，而扫描顺序是从右向左，因此 `res` 是正确解码的**逆序**；最后一次整体反转即得正序解码。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每次循环 $O(1)$（两次字符运算 + 一次追加），而 $i$ 每轮至少减 1，故循环最多执行 $n$ 次；最后反转 `res` 为 $O(m) \le O(n)$。总计 $O(n)$，$n \le 1000$ 时不到一万次基本操作。
- **空间**：$O(n)$，全部用于存放输出串。除输出外只用了常数个变量（指针 `i`、临时整数 $v$），额外空间 $O(1)$（Python 的 `list` 与 `''.join` 需要 $O(n)$ 的临时存放，但同样与输出同阶）。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <algorithm>
using namespace std;

class Solution {
public:
    string freqAlphabets(string s) {
        string res;
        res.reserve(s.size());              // 结果长度不超过 n
        int i = (int)s.size() - 1;
        while (i >= 0) {
            if (s[i] == '#') {
                // 题面保证可解，故 i >= 2 且 s[i-2]、s[i-1] 均为数字
                int v = (s[i - 2] - '0') * 10 + (s[i - 1] - '0');
                res.push_back(char('a' + v - 1));
                i -= 3;
            } else {
                int v = s[i] - '0';
                res.push_back(char('a' + v - 1));
                i -= 1;
            }
        }
        reverse(res.begin(), res.end());    // 逆序拼接，最后整体反转
        return res;
    }
};
```

### Python

```python
class Solution:
    def freqAlphabets(self, s: str) -> str:
        res = []
        i = len(s) - 1
        while i >= 0:
            if s[i] == '#':
                # 直接用 ASCII 码算两位数字，避免切片与 int() 的开销
                v = (ord(s[i - 2]) - 48) * 10 + (ord(s[i - 1]) - 48)
                res.append(chr(96 + v))
                i -= 3
            else:
                v = ord(s[i]) - 48
                res.append(chr(96 + v))
                i -= 1
        res.reverse()
        return ''.join(res)
```

## 8. 边界情况与易错点

1. **全是一位码**：`s = "123456789"` → 全程走 `else` 分支，输出 `"abcdefghi"`；不要误以为 `'#'` 一定出现。
2. **全是三位码**：`s = "10#10#10#"` → `i` 依次为 8、5、2，最后一步减 3 到 $-1$，恰好退出；若 $n$ 不是 3 的倍数，左侧剩余的数字按一位码处理（如 `"10#1"`）。
3. **忘记反转**：`"10#11#12"` 会输出 `"bakj"` 而不是 `"jkab"`；这是本题最容易踩的坑，务必在返回前 `reverse`。
4. **映射偏移一位**：写成 `char('a' + v)` 会让 `"1"` 解出 `'b'`，全部答案整体错位；正确写法是 `'a' + v - 1`。
5. **字符串头插导致 $O(n^2)$**：`res = ch + res` 每轮复制整串，$n = 1000$ 时约 $10^6$ 次字符拷贝，虽然能过但属于坏习惯。
6. **`i - 2` 下标的防御**：题面保证合法，`#` 前必有两位数字；若要对非法输入健壮，取 `s[i-2]`、`s[i-1]` 前应加 `i >= 2` 判断，否则 C++ 中是未定义行为。
7. **`'0'` 不会进入一位码分支**：合法编码中不存在值为 0 的 token，`'0'` 只可能作为 `10#`、`20#` 的第二位出现，而那个位置在右扫时已被 `'#'` 分支整段消费掉；若 `'0'` 单独出现在一位码分支，说明输入非法（会解出 `chr(96)`，即反引号）。
