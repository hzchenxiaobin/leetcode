# LeetCode 子数组异或查询 题解

## 1. 题目概述

- **标题 / 题号**：子数组异或查询（#1310，medium）
- **链接**：https://leetcode.cn/problems/xor-queries-of-a-subarray/
- **来源**：LeetCode 第 170 场周赛 Q2
- **难度**：中等
- **标签**：位运算，数组，前缀和

**题意**：给定正整数数组 `arr` 与查询数组 `queries`，其中 `queries[i] = [L, R]`。对每个查询求

$$\text{arr}[L] \oplus \text{arr}[L+1] \oplus \cdots \oplus \text{arr}[R]$$

并按查询顺序返回所有结果组成的数组。

**约束**：

- $1 \le \lvert \text{arr} \rvert,\ \lvert \text{queries} \rvert \le 3 \times 10^4$
- $1 \le \text{arr}[i] \le 10^9$
- `queries[i].length == 2`，$0 \le L \le R < \lvert \text{arr} \rvert$

规模上 $n \times q$ 最坏是 $9 \times 10^8$，因此**必须**把「一次查询」的代价压到 $O(1)$，预算里只允许一次线性预处理。

## 2. 示例

**示例 1**

```text
输入：arr = [1,3,4,8], queries = [[0,1],[1,2],[0,3],[3,3]]
输出：[2,7,14,8]
解释：元素二进制为 1=0001, 3=0011, 4=0100, 8=1000
      [0,1] = 1 xor 3           = 2  (0010)
      [1,2] = 3 xor 4           = 7  (0111)
      [0,3] = 1 xor 3 xor 4 xor 8 = 14 (1110)
      [3,3] = 8                 = 8  (1000)
```

**示例 2**

```text
输入：arr = [4,8,2,10], queries = [[2,3],[1,3],[0,0],[0,3]]
输出：[8,0,4,4]
解释：[1,3] = 8 xor 2 xor 10 = 0，整段异或退化为 0（每位 1 都是偶数个）
```

**示例 3**

```text
输入：arr = [7,7,7], queries = [[0,2],[0,0],[1,2]]
输出：[7,7,0]
解释：三个 7 异或 = 7；单点查询取到自身；两个 7 异或抵消为 0
```

## 3. 解题思路

### 3.1 暴力思路

对每个查询 `[L, R]`，从 `L` 循环到 `R` 逐项异或。单次代价 $O(R-L+1)$，最坏 $O(n)$。

- **时间**：$O(nq)$，$3\times10^4 \times 3\times10^4 = 9\times10^8$ 次异或，C++ 也大概率超时；
- **空间**：$O(1)$（不计返回数组）。

注意 `arr[i] <= 10^9` 说明**值域很小**（$< 2^{30}$），单次异或不会溢出，瓶颈纯粹是次数太多。所以要找的是「让多次区间查询共享同一份预计算」的结构。

### 3.2 核心观察：异或的自逆性 + 前缀异或

![前缀异或模型](images/wc170_q2_prefix_xor_model.svg)

异或运算满足三条性质，缺一不可：

1. **交换律 / 结合律**：$a \oplus b = b \oplus a$，$(a \oplus b) \oplus c = a \oplus (b \oplus c)$，所以「一段区间的异或」与运算顺序无关；
2. **自逆**：$x \oplus x = 0$，即同一个数异或两次等于没算；
3. **单位元**：$x \oplus 0 = x$。

定义**前缀异或**

$$\text{pre}[0] = 0,\qquad \text{pre}[k] = \text{arr}[0] \oplus \text{arr}[1] \oplus \cdots \oplus \text{arr}[k-1]$$

于是 $\text{pre}[R+1]$ 是「前 $R+1$ 项」，$\text{pre}[L]$ 是「前 $L$ 项」。两者异或时，下标 $< L$ 的每一项都出现了两次、按性质 2 抵消，只剩下 $[L, R]$ 这一段：

$$\text{pre}[R+1] \oplus \text{pre}[L] = \text{arr}[L] \oplus \cdots \oplus \text{arr}[R]$$

这正是「前缀和求区间和」的异或版本，区别在于**加法用减法还原，异或用它自己还原**——所以公式里两侧都是 `pre`，没有减法。

> 💡 一句话记忆：区间异或 = 大前缀异或 小前缀，因为重叠部分自己把自己消掉了。

### 3.3 算法流程

![算法流程](images/wc170_q2_scan_flow.svg)

1. 开 `pre` 数组，长度 $n+1$，`pre[0] = 0`（哨兵）；
2. 从左到右一遍 `pre[i+1] = pre[i] ^ arr[i]`，$O(n)$ 建表；
3. 对每个查询 `[L, R]` 直接取 `ans = pre[R+1] ^ pre[L]`，$O(1)$；
4. 返回 `ans` 数组。

注意查询之间**互不影响、无需排序、无需合并**，因此在线式（来一个答一个）和离线式都可以，代码里就是一个 `for` 循环。

### 3.4 示例演算

![示例演算](images/wc170_q2_walkthrough.svg)

以 `arr = [1, 3, 4, 8]` 为例，先建表：

| i | arr[i] | pre[i] | pre[i+1] |
|---|--------|--------|----------|
| 0 | 1 | 0 | 1 |
| 1 | 3 | 1 | 2 |
| 2 | 4 | 2 | 6 |
| 3 | 8 | 6 | 14 |

再逐个查询：

| queries[i] | pre[R+1] | pre[L] | 结果 |
|------------|----------|--------|------|
| [0,1] | pre[2] = 2 | pre[0] = 0 | 2 |
| [1,2] | pre[3] = 6 | pre[1] = 1 | 7 |
| [0,3] | pre[4] = 14 | pre[0] = 0 | 14 |
| [3,3] | pre[4] = 14 | pre[3] = 6 | 8 |

第二个示例 `arr = [4, 8, 2, 10]` 的 `pre = [0, 4, 12, 14, 4]`，恰好说明「前缀相同 ⇒ 区间异或为 0」：查询 `[1,3] = pre[4] ^ pre[1] = 4 ^ 4 = 0`。

## 4. 算法细节

1. **哨兵不可省**：`pre` 长度必须是 $n+1$，`pre[0] = 0`。查询 `L = 0` 时公式要用到 `pre[0]`；若只开 $n$ 个位置，就得为 `L = 0` 单独写分支，容易出错。
2. **右端一定写 `R+1`**：`arr[R]` 要留在区间内，前缀必须取到「前 $R+1$ 项」。写成 `pre[R]` 是本题最常见的 off-by-one，`[3,3]` 这类单点查询会立刻暴露。
3. **建表顺序**：只能是 `pre[i+1] = pre[i] ^ arr[i]`（从左往右）。因为异或虽然可交换，但「前缀」的定义依赖顺序，乱序累加得不到区间信息。
4. **值域与溢出**：`arr[i] < 2^30`，而异或按位运算不会进位，所以任意区间异或仍 $< 2^{30}$，落在 32 位有符号 `int` 内，无需 `long long`。
5. **结果数组预分配**：C++ 里 `ans.reserve(queries.size())` 避免多次扩容；参数用 `const vector<int>&`（LeetCode 签名是非 const 引用，可直接用，但不修改即可）。
6. **按位视角（可选的心智模型）**：把每个数拆成 30 个二进制位，异或等价于**逐位做模 2 加法**，即「区间内该位 1 的个数是奇数还是偶数」。因此 `pre[k]` 的第 $b$ 位就是前 $k$ 项里第 $b$ 位 1 的个数的奇偶性——前缀和在这里退化为「前缀奇偶」。
7. **顺序扫描的常数**：整个过程只有 $n$ 次建表异或 + $q$ 次查询异或（外加 $2q$ 次数组访问），$n = q = 3\times10^4$ 时约 $9\times10^4$ 次运算，属于「随便写都能过」的量级，不需要任何额外优化。

## 5. 正确性证明

**引理 1（前缀展开）**：对任意 $0 \le k \le n$，$\text{pre}[k] = \text{arr}[0] \oplus \text{arr}[1] \oplus \cdots \oplus \text{arr}[k-1]$（$k=0$ 时为空异或，值为 $0$）。

**证明**：对 $k$ 归纳。$k=0$ 由定义 `pre[0] = 0` 成立；若对 $k$ 成立，则 `pre[k+1] = pre[k] ^ arr[k]` 恰好是前 $k+1$ 项的异或，归纳成立。∎

**引理 2（抵消）**：对任意 $0 \le L \le R < n$，有 $\text{pre}[R+1] \oplus \text{pre}[L] = \text{arr}[L] \oplus \cdots \oplus \text{arr}[R]$。

**证明**：由引理 1，

$$\text{pre}[R+1] = \bigl(\text{arr}[0] \oplus \cdots \oplus \text{arr}[L-1]\bigr) \oplus \bigl(\text{arr}[L] \oplus \cdots \oplus \text{arr}[R]\bigr) = \text{pre}[L] \oplus X$$

其中 $X = \text{arr}[L] \oplus \cdots \oplus \text{arr}[R]$。对等式两边同时异或 $\text{pre}[L]$，左边得 $\text{pre}[R+1] \oplus \text{pre}[L]$，右边由 $x \oplus x = 0$ 与 $0 \oplus X = X$ 得 $X$，即为所证。∎

**定理**：算法输出的 `ans[i]` 等于第 $i$ 个查询 `[L, R]` 的区间异或。

**证明**：由引理 1，`pre` 建表完成后正是题目要求的前缀异或定义；由引理 2，循环体里算出的 `pre[R+1] ^ pre[L]` 精确等于 `arr[L] ^ ... ^ arr[R]`；每个查询只被写入一次 `ans[i]`，故返回数组与真实答案逐位相同。∎

## 6. 复杂度分析

- **时间**：$O(n + q)$。建表一次线性扫描共 $n$ 次异或；每个查询只做 2 次数组访问 + 1 次异或；没有任何内层循环。
- **空间**：$O(n)$。`pre` 数组占 $n+1$ 个整数；返回的 `ans` 数组是 $q$ 个整数，属于必须的输出。除此外只有常数个临时变量，递归栈深度 $O(1)$。

对比暴力：$O(nq) \to O(n + q)$，在 $n = q = 3\times10^4$ 时约 $9\times10^8 \to 9\times10^4$，提速四个数量级。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<int> xorQueries(vector<int>& arr, vector<vector<int>>& queries) {
        int n = arr.size();
        vector<int> pre(n + 1, 0);                 // pre[0] = 0 哨兵
        for (int i = 0; i < n; ++i) {
            pre[i + 1] = pre[i] ^ arr[i];          // 前缀异或
        }
        vector<int> ans;
        ans.reserve(queries.size());
        for (const auto& q : queries) {
            ans.push_back(pre[q[1] + 1] ^ pre[q[0]]);  // 右端 +1，别写错
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def xorQueries(self, arr: List[int], queries: List[List[int]]) -> List[int]:
        n = len(arr)
        pre = [0] * (n + 1)                 # pre[0] = 0，pre[i+1] = arr[0..i] 的异或
        for i, v in enumerate(arr):
            pre[i + 1] = pre[i] ^ v
        return [pre[r + 1] ^ pre[l] for l, r in queries]
```

## 8. 边界情况与易错点

1. **`L = 0` 的查询**：一定要靠 `pre[0] = 0` 兜住，`pre` 长度取 $n+1$。若数组只开 $n$ 位，`pre[0]` 会被当成 `arr[0]`，整题错位。
2. **`R = n-1` 的查询**：`R+1 = n` 是合法下标，正因为 `pre` 多开了一位，不会越界；反过来若把 `pre` 开成 $n$ 位，这里必然 RE。
3. **右端写成 `pre[R]`**：`[3,3]` 会算成 `pre[3] ^ pre[3] = 0`（正确是 8），用单点查询自测即可发现。
4. **单点查询**：`L = R` 时公式给出 `pre[L+1] ^ pre[L] = arr[L]`，天然正确，不需要特判。
5. **区间异或为 0**：`arr = [5,5]` 查 `[0,1]` 得 0；答案里出现 0 是正常结果，不要误当作「无效查询」跳过。
6. **溢出**：`arr[i] <= 10^9 < 2^30`，异或不会进位，`int` 足够；但如果先做累加再取模之类的多余操作反而可能溢出，本题不需要。
7. **返回数组顺序**：必须与 `queries` 一一对应。查询可以乱序给出，**不要**排序或去重后返回。
