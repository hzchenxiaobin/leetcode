# LeetCode 获取你好友已观看的视频 题解

## 1. 题目概述

- **标题 / 题号**：获取你好友已观看的视频（#1311，medium）
- **链接**：https://leetcode.cn/problems/get-watched-videos-by-your-friends/
- **来源**：LeetCode 第 170 场周赛 Q3
- **难度**：中等
- **标签**：广度优先搜索、图、数组、哈希表、排序

**题意**：有 $n$ 个人，编号 $0 \sim n-1$。`watchedVideos[i]` 是第 $i$ 个人看过的视频（可重复出现同一部片），`friends[i]` 是他的好友列表（关系对称，即无向图）。给定你的编号 `id`，把所有与你的**最短距离恰好等于 `level`** 的人看过的视频收集起来，按**观看频次升序**返回；频次相同的视频按**字典序升序**排列。

关键词是「**恰好**」：不是「`level` 步之内能走到的人」，而是「最短路长度恰为 `level` 的人」。这一点决定了必须做 BFS，而不是随便走 `level` 步。

**约束**：

- $n = \text{watchedVideos.length} = \text{friends.length}$，$2 \le n \le 100$
- $1 \le \text{watchedVideos}[i]\text{.length} \le 100$，视频名长度 $1 \sim 8$（大写字母加数字）
- $0 \le \text{friends}[i]\text{.length} < n$，且 $0 \le \text{friends}[i][j] < n$
- $0 \le \text{id} < n$，$1 \le \text{level} < n$
- 若 `friends[i]` 含 `j`，则 `friends[j]` 含 `i`（好友关系对称）

数据规模很小（$n \le 100$），意味着 $O(n^2)$ 甚至 $O(n^3)$ 都能过；但正解 $O(n + E + V\log V)$ 反而更好写，也更值得作为模板背下来。

## 2. 示例

**示例 1**

```text
输入：watchedVideos = [["A","B"],["C"],["B","C"],["D"]]
     friends = [[1,2],[0,3],[0,3],[1,2]], id = 0, level = 1
输出：["B","C"]
解释：你（0 号）的好友是 1 号和 2 号；
      1 号看过 C，2 号看过 B、C；
      频次：B → 1，C → 2，按频次升序即 ["B","C"]。
```

**示例 2**

```text
输入：watchedVideos = [["A","B"],["C"],["B","C"],["D"]]
     friends = [[1,2],[0,3],[0,3],[1,2]], id = 0, level = 2
输出：["D"]
解释：好友的好友只有 3 号一个人（0→1→3 或 0→2→3，长度都是 2），
      他看过 D，所以答案为 ["D"]。
      注意 0 号自己虽然能通过 0→1→0 走回自己，但距离 0 ≠ 2，不算。
```

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是「从 `id` 出发，沿着好友边往下走 `level` 步，把走到的所有人看过的视频收集起来」。这个做法在两个方面同时出错：

1. **走法爆炸**：允许回头的话，长度为 `level` 的链最多有 $n^{\text{level}}$ 条，随便一张完全图就能让搜索树炸掉；而对「已访问点」剪枝虽然压住了规模，却把判据变成了「存在一条长度为 `level` 的链」，于是掉进下一点的坑。
2. **层次错误**：链长恰好为 `level` 的人，**不一定是**最短距离为 `level` 的人。例如 0 的邻居 1 也满足 0→2→0→1 这条长度为 3 的链，凭链长会把它算进第 3 层，而它的真实距离是 1。

另一种退路是把距离算全：Floyd 求两两最短路是 $O(n^3)$，$n = 100$ 时约 $10^6$ 次操作，能过但纯属浪费；只在 `id` 这一个源点上做 Bellman–Ford（$n$ 轮松弛）则是 $O(nE)$，同样比 BFS 贵。

真正的需求只有一句话：**在无权无向图上，求 `id` 到每个人的最短距离，然后取距离为 `level` 的那一层**。这正是 BFS 一次遍历就能给出的东西。

### 3.2 核心观察：BFS 的层号就是最短距离

![BFS 分层：level 等于最短距离](images/wc170_q3_bfs_layers.svg)

在**边权全为 1** 的图上，从 `id` 出发做 BFS，第 $k$ 层（距离为 $k$ 的那些点）恰好是「最短距离等于 $k$」的点集。用 `dist[i]` 记录第一次被访问时的层号，就同时拿到了最短距离和「是否访问过」两个信息：

$$\text{dist}[v] = 1 + \min_{u \in \text{friends}[v]} \text{dist}[u]$$

这个最小值在 BFS **第一次扫到** $v$ 时就已经到手，之后不会再被改写。

因为入队时就已经把 `dist` 写死，之后再遇到 $v$ 的边（例如 0→1→0 里的 0）会看到 `dist[v] != -1` 而被跳过，所以**每个人只属于一层**，不会重复计数，也自动满足「恰好」二字。

> 💡 一句话记忆：**层号 = 最短路长度；先标记再入队，就不会有人串层。**

### 3.3 算法流程

![四步流程：BFS → 取层 → 计数 → 排序](images/wc170_q3_bfs_flow.svg)

1. **建距离数组**：`dist` 全部置 $-1$，`dist[id] = 0`，队列压入 `id`。
2. **BFS 分层**：弹出队首 $u$，枚举 $v \in \text{friends}[u]$；若 `dist[v] == -1`，置 `dist[v] = dist[u] + 1` 并入队；否则跳过。
3. **取第 `level` 层**：扫描 $u = 0 \sim n-1$，把 `dist[u] == level` 的人标记为本层成员。
4. **计数 + 排序**：对本层每个人，把 `watchedVideos[u]` 里的每个视频名写进哈希表 `cnt` 并 $+1$；最后按 $(\text{cnt}[w], w)$ 升序排序输出。

### 3.4 示例演算

![示例走查：dist 与频次表](images/wc170_q3_walkthrough.svg)

以示例 1 的图（边 0-1、0-2、1-3、2-3 共四条边）为例，从 `id = 0` 出发：

| 人 $u$ | `dist[u]` | 是否第 1 层 | `watchedVideos[u]` | 计入 `cnt` |
|--------|-----------|-------------|--------------------|------------|
| 0 | 0 | 否（自己） | `["A","B"]` | — |
| 1 | 1 | 是 | `["C"]` | `C + 1` |
| 2 | 1 | 是 | `["B","C"]` | `B + 1, C + 1` |
| 3 | 2 | 否（差 2 层） | `["D"]` | — |

得到 `cnt = {B:1, C:2}`，按频次升序排序后输出 `["B","C"]`。

若 `level = 2`，则本层只有 3 号，`cnt = {D:1}`，输出 `["D"]`。0 号通过 0→1→0 回到自己，但 `dist[0] = 0 ≠ 2`，不会被计入——这正是「恰好」语义被 `dist` 天然守住的地方。

## 4. 算法细节

1. **邻接表直接复用 `friends`**：它已经是对称的邻接表，不必重建；图可能不连通，BFS 结束后仍为 `-1` 的点说明从 `id` 不可达。
2. **`dist` 兼任 `visited`**：不要用 `bool visited[]` 加层号两套数组，容易忘记同步；一个 `-1` 初始化的 `int dist[]` 足够，且能直接支撑「距离恰好为 `level`」的判定。
3. **入队前必须赋值**：`if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }` 是唯一正确顺序。若等到出队时才赋值，同一层的点会被多次入队，最坏把复杂度从 $O(n+E)$ 抬到 $O(n^2)$。
4. **收集阶段不要依赖队内「层边界」**：同一层的点会连续出队，但队列里没有现成的层标记，靠出队计数去卡边界很容易错位；统一在 BFS 结束后扫一遍 `dist`，逻辑最直白，代价只有 $O(n)$。
5. **视频名比较用默认的字典序**：题目的「字母顺序」就是 ASCII 序（视频名只含大写字母与数字），C++ 的 `std::string::operator<` 与 Python 的字符串比较都与之相符。
6. **双关键字排序**：C++ 需把 `cnt` 的 key 取出来放进 `vector<string>`，再用 lambda 先比 `cnt[a]` 再比 `a`；Python 直接 `sorted(cnt, key=lambda w: (cnt[w], w))`，注意不要写成 `sorted(cnt)`（那会只按名字排）。
7. **频次统计的是「条目数」**：对第 `level` 层每个人的每个视频条目累加；同一个人列表里若出现两个同名视频，会计两次（题目未保证互异，按「观看次数」理解最自然）。

## 5. 正确性证明

**引理 1（BFS 距离正确）**：对无权无向图，BFS 结束时对每个从 `id` 可达的点 $u$，`dist[u]` 等于 `id` 到 $u$ 的最短距离；不可达时 `dist[u] = -1`。

**证明**：先用一个观察：任何一次赋值 `dist[x] = dist[w] + 1` 都对应图中一条从 `id` 到 $x$ 的长度为 `dist[w] + 1` 的路径，因此赋值结果**永远不小于** $x$ 的最短距离。

对最短距离 $d$ 归纳。$d = 0$ 只有 `id` 本身，`dist[id] = 0`，成立。设所有最短距离 $< d$ 的点都已被正确赋值，取最短距离为 $d$ 的点 $u$，它必有最短距离为 $d-1$ 的邻居 $p$（沿最短路取倒数第二个点）。BFS 的出队顺序按 `dist` 非降序，故 $p$ 一定排在所有 `dist ≥ d` 的点之前被处理；而由归纳假设 `dist[p] = d-1`。$p$ 出队时枚举邻居会看到 $u$：若 `dist[u]` 仍为 $-1$，就把它赋成 $d$；若早已被赋值，则那个值来自更早的处理、是某条路径的长度，由上段观察它 $\ge d$，同时它 $\le \text{dist}[p] + 1 = d$（早于 $p$ 出队的点 `dist` 不超过 $d-1$），于是它恰为 $d$。两种情况下 `dist[u] = d` 都成立。不可达的点永远不会被枚举到，保持 $-1$。∎

**引理 2（分层的精确性）**：`dist[u] == level` 当且仅当 $u$ 与 `id` 的最短距离恰为 `level`；并且每个点最多被计入一个层。

**证明**：由引理 1，`dist[u]` 就是最短距离，故判定条件与「最短距离恰为 `level`」等价。又因为 `dist[u]` 只在首次访问时被赋值一次、之后不再修改，每个 $u$ 的 `dist` 值唯一，故它最多落在一个层里。∎

**引理 3（频次正确）**：算法结束时 `cnt[w]` 等于第 `level` 层所有人观看 $w$ 的条目总数。

**证明**：算法恰好遍历一次所有 `dist[u] == level` 的人（引理 2），对每个人的 `watchedVideos[u]` 逐条 `+1`，故 `cnt[w]` 是这些条目中等于 $w$ 的个数，与定义一致。∎

**定理**：算法返回值恰为题目要求的视频序列。

**证明**：设 $S$ 为第 `level` 层的所有人，$W = \bigcup_{u \in S} \text{watchedVideos}[u]$ 为其看过的视频集合。由引理 3，`cnt` 在 $W$ 上给出正确频次，且不含 $W$ 之外的键（因为没有别的条目被累加）；由引理 2，$S$ 与题面要求的「最短距离恰为 `level` 的人」一致。于是返回值就是 $W$ 的全部元素，并按 $(\text{cnt}[w], w)$ 升序排列，与题目的「频次升序、同频字典序」完全一致。若 $S = \emptyset$，返回空列表，亦符合要求。∎

## 6. 复杂度分析

- **时间**：$O(n + E + M + V \log V)$。BFS 中每个点入队至多一次、每条边被检查两次，故 $O(n + E)$，其中 $E = \sum_i \lvert \text{friends}[i] \rvert$；收集层成员扫描 $O(n)$；统计频次需要 $O(M)$，$M$ 是第 `level` 层所有人的视频条目总数；排序 $O(V \log V)$，$V$ 是该层不同视频的个数。由于 `friends[i].length < n`，最坏 $E < n^2 = 10^4$，整体在 $10^4 \sim 10^5$ 量级。
- **空间**：$O(n + E + V)$。`dist` 数组与队列各 $O(n)$；哈希表存 $V$ 个键、每个键是最长 8 的字符串；排序结果 $O(V)$。输入 `friends` 本身占 $O(n + E)$，不额外复制。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <vector>
#include <queue>
#include <unordered_map>
#include <algorithm>
using namespace std;

class Solution {
public:
    vector<string> watchedVideosByFriends(vector<vector<string>>& watchedVideos,
                                          vector<vector<int>>& friends,
                                          int id, int level) {
        int n = (int)friends.size();
        vector<int> dist(n, -1);              // dist 兼任 visited
        dist[id] = 0;
        queue<int> q;
        q.push(id);
        while (!q.empty()) {
            int u = q.front();
            q.pop();
            for (int v : friends[u]) {
                if (dist[v] == -1) {          // 先标记，再入队
                    dist[v] = dist[u] + 1;
                    q.push(v);
                }
            }
        }

        unordered_map<string, int> cnt;       // 第 level 层视频 -> 观看次数
        for (int u = 0; u < n; u++) {
            if (dist[u] != level) continue;
            for (const string& w : watchedVideos[u]) cnt[w]++;
        }

        vector<string> ans;
        ans.reserve(cnt.size());
        for (auto& kv : cnt) ans.push_back(kv.first);
        sort(ans.begin(), ans.end(), [&](const string& a, const string& b) {
            if (cnt[a] != cnt[b]) return cnt[a] < cnt[b];   // 频次升序
            return a < b;                                   // 同频字典序
        });
        return ans;
    }
};
```

### Python

```python
from collections import deque, Counter


class Solution:
    def watchedVideosByFriends(self, watchedVideos: list[list[str]],
                               friends: list[list[int]],
                               id: int, level: int) -> list[str]:
        n = len(friends)
        dist = [-1] * n
        dist[id] = 0
        q = deque([id])

        while q:
            u = q.popleft()
            for v in friends[u]:
                if dist[v] == -1:
                    dist[v] = dist[u] + 1
                    q.append(v)

        cnt = Counter()
        for u in range(n):
            if dist[u] == level:
                cnt.update(watchedVideos[u])

        return sorted(cnt, key=lambda w: (cnt[w], w))
```

## 8. 边界情况与易错点

1. **`level` 层没有人**：例如图不连通、`level` 超过最大深度。此时 `cnt` 为空，必须返回空列表 `[]`；C++ 里 `vector<string>{}` 直接返回即可，不要返回 `{"null"}` 之类的哨兵值。
2. **把自己算进去**：`dist[id] = 0`，而 `level ≥ 1`，所以自己永远不会被选。若误写成 `dist[u] <= level`，就会把第 $0 \sim \text{level}-1$ 层的人（包括自己）全都算进来，示例 1 的答案会变成 `["A","B","C"]`。
3. **「恰好」被写成「至多」**：题目要求最短距离恰为 `level`，不是「走 `level` 步能到的人」。示例 2 中 0→1→0 这类回边提醒我们：只有 `dist` 判定才是可靠的，链长不是。
4. **同层重复入队**：`if (dist[v] == -1)` 必须与赋值在同一处完成。若先 `push` 再在出队时判断，同一层的点可能进队多次，虽然答案常常仍然正确，但复杂度退化，遇到稠密图容易 TLE。
5. **自环与重复好友**：约束没有禁止 `friends[i]` 含 `i` 本身或重复元素；BFS 的 `dist` 判定天然免疫——`dist[i]` 早已是 0 或已被赋值，重复的边只会被多检查几次。
6. **排序键写错**：`sorted(cnt)` 只按名字排；必须用 `key=lambda w: (cnt[w], w)`。C++ 里若直接 `sort(cnt.begin(), cnt.end())` 会连频次都不看，同样错。
7. **频次的语义**：同一个人列表内若有重复视频（题面未保证互异），本解法按「条目数」计频；若按「观看人数」计，则需先对每个人去重再累加。本题数据中两者一致。
