# LeetCode 获得分数的方法数 题解

## 1. 题目概述

- **标题 / 题号**：获得分数的方法数（#2585，hard）
- **链接**：https://leetcode.cn/problems/number-of-ways-to-earn-points/
- **来源**：LeetCode 第 335 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、背包问题、多重背包、前缀和

**题意**：考试中有 $n$ 种类型的题目，第 $i$ 种有 $\text{count}_i$ 道、每道 $\text{marks}_i$ 分。同类型题目**不可区分**（选第 1、2 道与选第 1、3 道算同一种方法）。返回**恰好**得到 $\text{target}$ 分的方法数，对 $10^9+7$ 取余。

**约束**：

- $1 \le \text{target} \le 1000$
- $1 \le n = \text{types.length} \le 50$
- $1 \le \text{count}_i, \text{marks}_i \le 50$

> 📚 本题在本仓库另有[每日题解 2585](../../solution/2501-2600/2585_获得分数的方法数.md)：以多重背包建模、「恰好 / 至多」初始化对照与二进制拆分优化为主线，含面试问答；本篇侧重赛时切入路径、**分组背包视角 + 同余类前缀和滑窗把单组转移压到 $O(\text{target})$**，以及方案计数不重不漏的完整证明。

> 💡 **赛时定位**：本场 Q3、Q4 双双挂困难（少见），但两道成色截然不同——Q3 是数论扫描（分水岭），Q4 却是教科书级的**多重背包求方案数**模板题。「若干种物品、每种有限件、凑恰好 target、数方案」四要素齐了就直接写背包，认出模型即稳拿。赛时朴素三重循环 $O(n \cdot \text{target} \cdot \overline{c}) \approx 2.5 \times 10^6$ 完全够用；本篇复盘再把它优化到 $O(n \cdot \text{target})$。

## 3. 解题思路

### 3.1 暴力思路：枚举每种题型做几道

对每种类型独立决定做 $k_i$ 道（$0 \le k_i \le \text{count}_i$），枚举全部组合共 $\prod_i (\text{count}_i + 1) \le 51^{50}$ 种，逐一检查 $\sum k_i \cdot \text{marks}_i = \text{target}$——指数级爆炸，$n=50$ 时天文数字。瓶颈结构很清晰：**组合爆炸在「各类型的数量互相独立」上，而求和目标只有 target 一个维度**。把「按类型逐个决策、维护当前部分和」组织成阶段化 DP，部分和相同的中间状态合并计数，就是背包计数。写成记忆化搜索 $(i, j)$（前 $i$ 种、已凑 $j$ 分）同样得到 $O(n \cdot \text{target} \cdot \overline{c})$，是赛中的等价替补。

### 3.2 核心观察：同类型不可区分 ⇒ 方案 = 数量向量（分组背包）

![核心观察：每种题型是一个组，组内互斥选一个数量 k；方案由数量向量唯一决定](images/earn_points_group_knapsack.svg)

「同类型题目无法区分」这句话是本题的题眼：它规定了**两个方法相同 ⟺ 每种类型做的道数对应相等**。于是方法与向量

$$\mathbf{k} = (k_1, k_2, \dots, k_n), \qquad 0 \le k_i \le \text{count}_i, \qquad \sum_{i=1}^{n} k_i \cdot \text{marks}_i = \text{target}$$

一一对应（引理 1 严格证明）。「选哪几道」的 $\binom{c}{k}$ 种下标选法全部坍缩成一种——**不要**在转移里乘组合数。这正是一个**分组背包**：每种题型是一个「组」，组内 $k = 0 \dots \text{count}_i$ 互斥选一个；$\text{count}_i = 1$ 退化为 [0-1 背包](https://leetcode.cn/problems/target-sum/)，$\text{count}_i$ 无上限是[完全背包](https://leetcode.cn/problems/coin-change-ii/)，本题介于两者之间，即**多重背包**。

**状态定义**（一维滚动，`dp[j]` = 已处理完若干题型后恰好凑出 $j$ 分的方法数）：

- **初始化**：「恰好装满」语义 ⇒ $dp[0] = 1$（空集得 0 分，唯一起点），$dp[j > 0] = 0$；
- **答案**：$dp[\text{target}]$；
- **转移**（处理题型 $(c, m)$，**倒序** $j$，内层枚举 $k = 1 \dots \min(c, \lfloor j/m \rfloor)$）：

$$dp[j] \;\longleftarrow\; dp[j] + \sum_{k=1}^{\min(c,\;\lfloor j/m \rfloor)} dp[\,j - k \cdot m\,]$$

赛时核心循环不过五行（完整版见[每日题解](../../solution/2501-2600/2585_获得分数的方法数.md)）：

```cpp
for (const auto& t : types) {
    int c = t[0], m = t[1];
    for (int j = target; j >= 0; --j)          // 倒序：读到旧值
        for (int k = 1; k <= c && k * m <= j; ++k)
            dp[j] = (dp[j] + dp[j - k * m]) % MOD;
}
```

> ⚠️ **$j$ 为什么倒序**：转移读的 $dp[j - k\cdot m]$（$k \ge 1$）下标更小。升序会让这些位置在本轮已被当前题型更新过，相当于同一题型「滚雪球」反复计入、突破 $\text{count}_i$ 件上限；倒序保证读到的恒是上一轮旧值。这与 0-1 背包是同一套机制。

### 3.3 算法流程：把内层 $k$ 循环压掉——同余类定长滑窗

![算法流程：按 j mod m 分组、取旧值、前缀和、差分回写 ndp](images/earn_points_residue_window.svg)

朴素版单组转移是 $O(\text{target} \cdot c)$。复盘提升点：转移本质是**同余类上的定长窗口和**。固定题型 $(c, m)$ 与余数 $r \in [0, m)$，把同余类的容量排成序列 $j_t = r + t\cdot m$（$t = 0, 1, \dots$），则

$$dp'[\,r + t\cdot m\,] \;=\; \sum_{s=\max(0,\;t-c)}^{t} dp[\,r + s\cdot m\,] \;=\; \text{pre}[t+1] - \text{pre}[\max(0,\,t-c)]$$

窗口恰是旧值序列上长度至多 $c+1$ 的连续段（引理 4 证明）。流程四步：

1. **分组**：按 $j \bmod m$ 把 $[0, \text{target}]$ 分成 $\min(m, \text{target}+1)$ 个同余类；
2. **取旧值**：每类读出旧序列 $a[0..L-1]$（$L = \lfloor (\text{target}-r)/m \rfloor + 1$）；
3. **前缀和**：$\text{pre}[i+1] = \text{pre}[i] + a[i]$；
4. **差分回写**：$ndp[r + t\cdot m] = \text{pre}[t+1] - \text{pre}[\max(0, t-c)]$（注意 $+\, \text{MOD}$ 修负）。

每个容量被读一次、写一次，单组转移 $O(\text{target})$，全程 $O(n \cdot \text{target})$。**必须写进独立数组 $ndp$**：后续窗口还要引用旧值，原地覆盖会串轮（见 §8 第 3 条）。

> 💡 **与二进制拆分的比较**：拆分版 $O(n \cdot \text{target} \cdot \log c)$（[每日题解](../../solution/2501-2600/2585_获得分数的方法数.md)展开）介于朴素 $O(\text{target} \cdot c)$ 与滑窗 $O(\text{target})$ 之间，胜在只改 0-1 背包两行；滑窗是理论最优，代价是要按余数类重组循环结构。本题数据范围下三者都过，差异只在常数与代码量。

### 3.4 示例演算

![示例 1 演算：dp 表经三种题型演化，dp[6] 沿 0→1→4→7 收敛到答案](images/earn_points_dp_walkthrough.svg)

以示例 1 走查 $dp[0..6]$ 的演化（滑窗版每步结果与朴素版完全一致）：

| 处理题型 | dp[0] | dp[1] | dp[2] | dp[3] | dp[4] | dp[5] | dp[6] | 说明 |
|----------|-------|-------|-------|-------|-------|-------|-------|------|
| 初始 | 1 | 0 | 0 | 0 | 0 | 0 | 0 | 仅空集 |
| (6, 1) | 1 | 1 | 1 | 1 | 1 | 1 | 1 | 1 分题 6 道，凑 0..6 分各 1 法 |
| (3, 2) | 1 | 1 | 1 | 2 | 3 | 3 | 4 | 叠加「选 1..3 道 2 分题」 |
| (2, 3) | 1 | 1 | 1 | 3 | 4 | 4 | **7** | 叠加「选 1..2 道 3 分题」 |

两步关键转移（都读**上一行**的旧值）：

- $(3,2)$ 步：$dp[6] = dp[6] + dp[4] + dp[2] + dp[0] = 1+1+1+1 = 4$（做 0..3 道 2 分题，剩余分交给 1 分题）；
- $(2,3)$ 步：$dp[6] = dp[6] + dp[3] + dp[0] = 4+2+1 = 7$（做 0..2 道 3 分题）。✓

用滑窗视角看最后一步：$m=3$、$r=0$ 的同余类是 $j = 0, 3, 6$，旧值 $a = [1, 2, 4]$，前缀和 $\text{pre} = [0,1,3,7]$；$j=6$ 即 $t=2$，窗口 $[\max(0, 2-2), 2] = [0,2]$，$dp'[6] = \text{pre}[3] - \text{pre}[0] = 7$。示例 3 则是「窗口够不着」的极端：总分上限恰好 18，只有全做一种。

## 4. 算法细节

1. **滚动数组的「旧值纪律」**：朴素版靠 $j$ 倒序保证只读旧值；滑窗版改为**整组换新**——前缀和扫的是完整旧数组，回写进 $ndp$，组处理完 `swap(dp, ndp)`。两者禁止混用：滑窗若原地覆盖，后续窗口引用的 $a[s]$ 已被污染。
2. **同余类的参数**：$r$ 上界取 $\min(m, \text{target}+1) - 1$——保证 $r \le \text{target}$、$L \ge 1$。类长 $L = \lfloor (\text{target}-r)/m \rfloor + 1$，前缀和数组长 $L+1$（$\text{pre}[0] = 0$ 为空和）。
3. **窗口左端的截断**：$\text{lo} = \max(0, t - c)$。$t < c$ 时窗口触底取 $[0, t]$，对应「$j$ 不足以做满 $c$ 道，$k \le \lfloor j/m \rfloor$」自动成立——朴素版的内层上界 `k * m <= j` 被窗口截断天然编码，无需显式判断。
4. **取模减法修负**：$\text{pre}[t+1] - \text{pre}[\text{lo}]$ 理论非负，但两个已取模值相减可能为负，必须 $(x - y + \text{MOD}) \bmod \text{MOD}$。
5. **C++ 的 int 上界**：`pre` 累加时两数均 $< \text{MOD} < 2^{30}$，和 $< 2 \times 10^9$ 恰在 `int` 上限内；差分 $x - y + \text{MOD} < 2 \times 10^9$ 同理贴线安全。求稳可全用 `long long`，本题 `int` 每步都严格有界，验证后可用。
6. **读旧值的另一姿势（倒序原地）**：同余类内按 $t$ **降序**处理也可原地——窗口 $[t-c, t]$ 只含下标 $\le t$ 的位置，写 $j_t$ 时更小的 $t'$ 尚未动过。但前缀和法需要完整旧序列，故与 `ndp` 版二选一，不要拼装成「前缀和 + 原地」的杂交写法。

## 5. 正确性证明

**引理 1（数量向量刻画）**：方法数等于集合 $\{\mathbf{k} = (k_1,\dots,k_n) : 0 \le k_i \le \text{count}_i,\ \sum_i k_i \cdot \text{marks}_i = \text{target}\}$ 的大小。

**证明**：一个「方法」是一组具体做题的集合。按题意同类型题目不可区分，两个方法相同当且仅当每种类型做的道数相等，故方法与其数量向量一一对应；一个方法凑出 target 分当且仅当其向量满足加权和约束。因此方法与满足约束的向量一一对应。∎

**引理 2（分阶段不变量）**：记 $dp_i[j]$ 为满足 $\sum_{t \le i} k_t \cdot \text{marks}_t = j$、$0 \le k_t \le \text{count}_t$ 的部分向量 $(k_1, \dots, k_i)$ 的个数，则 $dp_0[0] = 1$、$dp_0[j>0] = 0$，且

$$dp_i[j] = \sum_{k=0}^{\min(\text{count}_i,\;\lfloor j / \text{marks}_i \rfloor)} dp_{i-1}[\,j - k \cdot \text{marks}_i\,]$$

**证明**：初值即空向量（引理 1 中 $n=0$ 的特例）。转移按**最后一维** $k_i = k$ 的取值把部分向量分类：对固定 $k$，$(k_1,\dots,k_{i-1},k)$ 合法当且仅当 $(k_1,\dots,k_{i-1})$ 是凑出 $j - k\cdot\text{marks}_i$ 的合法部分向量，个数恰为 $dp_{i-1}[j - k\cdot\text{marks}_i]$。$k$ 的可取范围是 $[0, \min(\text{count}_i, \lfloor j/\text{marks}_i\rfloor)]$（负容量无解），各类互不相交且穷尽所有可能，求和即得。∎

**引理 3（倒序滚动的等价性）**：朴素版在同一个数组上倒序 $j$、内层 $k \ge 1$ 执行引理 2 的转移，结束时数组等于 $dp_i[\cdot]$。

**证明**：归纳于写入顺序。倒序处理 $j = \text{target} \dots 0$ 时，写 $dp[j]$ 读的是 $dp[j - k\cdot m]$（$k \ge 1$，下标严格更小），这些位置尚未被本轮写入，仍是 $dp_{i-1}$ 的值；$k = 0$ 项即 $dp[j]$ 自身未动，亦为 $dp_{i-1}[j]$。故每格写入值恰为引理 2 右端。∎

**引理 4（滑窗等价性）**：固定题型 $(c, m)$ 与余数 $r \in [0, m)$，$L = \lfloor (\text{target}-r)/m \rfloor + 1$，$a[s] = dp[\,r + s\cdot m\,]$，$\text{pre}[0] = 0$、$\text{pre}[i+1] = \text{pre}[i] + a[i]$。则对 $0 \le t < L$，

$$\sum_{k=0}^{\min(c,\;\lfloor (r+t\cdot m)/m \rfloor)} dp[\,r + t\cdot m - k\cdot m\,] \;=\; \text{pre}[t+1] - \text{pre}[\max(0,\,t-c)]$$

**证明**：$j = r + t\cdot m$ 时 $\lfloor j/m \rfloor = t$（因 $0 \le r < m$），故左端求和范围是 $k \in [0, \min(c, t)]$，被加项为 $a[t-k]$，即 $a[\max(0, t-c) \dots t]$ 的连续段和。由前缀和定义，该段和 $= \text{pre}[t+1] - \text{pre}[\max(0, t-c)]$。$ndp$ 版本中 $a$ 全程取自旧数组，等价于引理 2 的 $dp_{i-1}$。∎

**定理**：算法返回 $dp[\text{target}] \bmod (10^9+7)$，恰为答案对 $10^9+7$ 取余。

**证明**：由引理 3 / 引理 4，滚动或滑窗实现的每步转移与引理 2 的 $dp_i$ 逐格相等，故终态 $dp[\cdot] = dp_n[\cdot]$。由引理 2，$dp_n[\text{target}]$ 是满足约束的完整向量个数，由引理 1 即方法数。所有加法与差分均在模 $10^9+7$ 下进行，同余类上加减保持同余，故返回值为答案的模意义值。∎

## 6. 复杂度分析

- **时间复杂度**：滑窗版 $O(n \cdot \text{target})$——每个题型对每个容量恰读一次（做前缀和）、写一次（差分回写），本题即 $50 \times 1000 = 5 \times 10^4$ 量级；朴素版 $O(n \cdot \text{target} \cdot \overline{c}) \le 2.5 \times 10^6$，赛时同样从容。
- **空间复杂度**：$O(\text{target})$——`dp` 与 `ndp` 两个长度 $\text{target}+1$ 的数组，加上同余类前缀和 $O(\text{target})$ 分摊复用。
- **对照**：暴力 $O(\prod(\text{count}_i+1)) \le 51^{50}$ 指数级；记忆化搜索与朴素 DP 同阶但带递归常数。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int waysToReachTarget(int target, vector<vector<int>>& types) {
        const int MOD = 1000000007;
        vector<int> dp(target + 1, 0), ndp(target + 1, 0);
        dp[0] = 1;                                        // 恰好装满：空集得 0 分
        for (const auto& t : types) {
            int c = t[0], m = t[1];
            for (int r = 0; r < min(m, target + 1); ++r) { // 同余类 r（保证 r ≤ target）
                int L = (target - r) / m + 1;
                vector<int> pre(L + 1, 0);
                for (int i = 0; i < L; ++i)
                    pre[i + 1] = (pre[i] + dp[r + i * m]) % MOD;
                for (int j = r, tt = 0; tt < L; j += m, ++tt) {
                    int lo = max(0, tt - c);               // 窗口 [tt-c, tt]
                    ndp[j] = (pre[tt + 1] - pre[lo] + MOD) % MOD;
                }
            }
            swap(dp, ndp);                                 // 整组换新，旧值纪律
        }
        return dp[target];
    }
};
```

### Python

```python
class Solution:
    def waysToReachTarget(self, target: int, types: List[List[int]]) -> int:
        MOD = 10**9 + 7
        dp = [0] * (target + 1)
        dp[0] = 1                                          # 恰好装满：空集得 0 分
        for c, m in types:
            ndp = [0] * (target + 1)
            for r in range(min(m, target + 1)):            # 同余类 r
                a = dp[r::m]                               # 该类全部旧值
                pre = [0] * (len(a) + 1)
                for i, v in enumerate(a):
                    pre[i + 1] = (pre[i] + v) % MOD
                for t, _ in enumerate(a):
                    lo = max(0, t - c)                     # 窗口 [t-c, t]
                    ndp[r + t * m] = (pre[t + 1] - pre[lo]) % MOD
            dp = ndp                                       # 整组换新
        return dp[target]
```

> 💡 两版均对拍验证：官方三示例，以及数百组随机小规模数据（$n \le 6$、$\text{target} \le 60$）对比「枚举全组合的暴力」与「朴素倒序三重循环」，三方逐例一致。

## 8. 边界情况与易错点

1. **初始化是「恰好装满」**：$dp[0]=1$、其余 $0$。误用「至多装满」的全 0 初始化会把不满 target 的方案计入；反过来求最值的「恰好」语义还要配 $-\infty$，本题计数不用。
2. **别乘组合数**：同类型不可区分 ⇒ 组内只看数量 $k$。若误加 $\binom{\text{count}_i}{k}$，示例 1 会把 7 算成几十——那是「同类型可区分」变体的做法（见延伸思考）。
3. **朴素版 $j$ 倒序、滑窗版写 $ndp$**：两套「旧值纪律」不可混搭。滑窗前缀和需要完整旧序列，原地覆盖必错；朴素版升序 $j$ 则同一题型滚雪球。
4. **余数上界 $\min(m, \text{target}+1)$ 在 C++ 不是可选优化**：若放任 $r > \text{target}$，$(\text{target}-r)/m$ 在 C++ 向零截断得 $0$，$L$ 算成 1，接着 $dp[r]$ **数组越界**（Python 地板除得 $-1$、$L=0$ 恰好无害——同一份逻辑跨语言要重新审边界）。
5. **取模减法修负**：$\text{pre}[t+1]-\text{pre}[\text{lo}]$ 两边都已取模，直接相减可能为负，必须 $+\text{MOD}$ 再取模。
6. **无解输出 0 即可**：如 target 大于总分上限（示例 3 恰好卡满 18 分，仅 1 法），$dp[\text{target}]$ 自然为 0，无需特判。
7. **`marks` 可能为 0 吗**：本题 $1 \le \text{marks}_i$，不用处理；若推广到 0 分题，同余类 $r=0$ 会出现 $m=0$ 除零，需单独讨论（0 分题不影响可达性但影响方案数，每道「做/不做」二选一）。

**延伸思考**：① **同类型可区分变体**：方法数变为 $\sum \prod_i \binom{\text{count}_i}{k_i}$，转移改为 $dp'[j] = \sum_k \binom{c}{k} \cdot dp[j - k\cdot m]$，滑窗外再乘组合数即可，复杂度不变；② **单调队列版滑窗**：把前缀和换成「入窗加、出窗减」的增量维护，同余类可原地倒序处理，省掉 $ndp$，是多重背包最优解的通用写法（最值与计数通用）；③ **阈值判断**：$\text{target}$ 与 $c$ 同阶增大时朴素 $O(\text{target}\cdot c)$ 退化为 $O(\text{target}^2)$，滑窗的 $O(\text{target})$ 优势才真正拉开——本题范围小，三种写法是「都对但要知道为什么」的关系。
