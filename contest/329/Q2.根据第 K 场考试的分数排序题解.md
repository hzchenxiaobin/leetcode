# LeetCode 根据第 K 场考试的分数排序 题解

## 1. 题目概述

- **标题 / 题号**：根据第 K 场考试的分数排序（#2545，medium）
- **链接**：https://leetcode.cn/problems/sort-the-students-by-their-kth-score/
- **来源**：LeetCode 第 329 场周赛 Q2
- **难度**：中等
- **标签**：数组、矩阵、排序

**题意**：班里有 $m$ 位学生、$n$ 场考试。给定下标从 0 开始的 $m \times n$ 整数矩阵 `score`，第 $i$ 行是第 $i$ 位学生的成绩单，`score[i][j]` 表示第 $i$ 位学生在第 $j$ 场考试的分数，矩阵中所有整数**互不相同**。再给定整数 $k$，要求按**第 $k$ 场考试分数从高到低**对学生（矩阵的行）排序，返回排序后的矩阵。

**约束**：

- $m = \text{score.length}$，$n = \text{score}[i].\text{length}$
- $1 \le m, n \le 250$
- $1 \le \text{score}[i][j] \le 10^5$
- `score` 由**不同**的整数组成
- $0 \le k < n$

> 💡 一句话建模：每行是一位学生的成绩单，题目要求**以第 $k$ 列为关键字、对行做降序排序**。行内元素不许改动，只在行与行之间交换位置——这是「按列排序矩阵行」的招牌模板。

## 2. 示例

**示例 1**

```text
输入：score = [[10,6,9,1],[7,5,11,2],[4,8,3,15]], k = 2
输出：[[7,5,11,2],[10,6,9,1],[4,8,3,15]]
解释：第 2 场考试分数依次为 9、11、3。
11 最高 → 原#1 行居首；9 次之 → 原#0 行居中；3 最低 → 原#2 行居末。
```

**示例 2**

```text
输入：score = [[3,4],[5,6]], k = 0
输出：[[5,6],[3,4]]
解释：第 0 场考试分数依次为 3、5。5 > 3，故原#1 行在前、原#0 行在后。
```

**补充示例（边界：单行单列）**

```text
输入：score = [[5]], k = 0
输出：[[5]]
解释：只有一位学生、一场考试，排序前后不变。
```

## 3. 解题思路

### 3.1 暴力思路：选择排序逐轮挑最大

最朴素的做法是**选择排序**：每轮在剩余行中扫描第 $k$ 列最大值对应的行，把它加入结果，并在剩余集合中剔除；重复 $m$ 轮。

```text
result = []
剩余 = {0, 1, ..., m-1}
重复 m 次：
    在「剩余」中找第 k 列最大值所在的行 r
    result 追加 score[r]；剩余.remove(r)
```

时间 $O(m^2)$（每轮 $O(m)$ 扫描、共 $m$ 轮）。$m \le 250$ 时 $m^2 \approx 6.25 \times 10^4$，可以通过，但每轮都从零扫描，做了大量重复比较——明明**一次比较就能定两行先后**，却被拆成相互独立的轮次。周赛里这题是节奏题，正确姿势是直接归约到一次比较排序。

### 3.2 核心观察：第 k 列构成行的严格全序

![核心观察：两行的先后只由第 k 列的一个标量决定](images/wc329_q2_sort_by_column.svg)

**关键直觉**：比较任意两行 $a, b$ 时，**只需看 `score[a][k]` 与 `score[b][k]` 这两个标量**。题面保证矩阵所有整数互不相同，因此第 $k$ 列的 $m$ 个值两两不同，配上整数的大小关系正好构成行的**严格全序**：

- 任意两行的先后**唯一**确定，不存在并列；
- 比较器只需 `a[k] > b[k]` **一个分支**，写不出歧义；
- 行序唯一 ⇒ 稳定性（stable sort 与否）无关紧要。

于是「对 $m$ 行排序」被化简为「对 $m$ 个标量关键字排序」，任意 $O(m \log m)$ 比较排序直接套用。

> ⚠️ **不要逐元素比较整行**：两行只在第 $k$ 列上分高下，其它列的值不影响行序。把比较器写成整行字典序，语义完全变了（见 §8 易错点 3）。

### 3.3 算法流程：一次排序解决

![算法流程：取键、降序比较排序、返回](images/wc329_q2_algorithm_flow.svg)

三步线性流程：

1. **取关键字**：`key[i] = score[i][k]`，每行抽一个标量，$O(m)$。本题关键字**现成可读**，无需任何预处理；
2. **按键降序排序**：以第 $k$ 列为比较依据排序行，比较只读两个标量、每次 $O(1)$，共 $O(m \log m)$ 次比较；
3. **返回**：行按新顺序返回。行交换是**整行整体搬动**（C++ 交换 `vector` 内部指针，$O(1)$），不逐个拷贝成绩。

> 💡 与 3.1 的对照：选择排序 $O(m^2)$ 次比较，比较排序 $O(m \log m)$ 次。$m = 250$ 时约 $2000$ 对 $6.25 \times 10^4$，快约 30 倍——但两者在本题规模下都能过，本题真正考的是**把行排序归约为标量排序**的建模，而非压复杂度。

### 3.4 示例演算

![示例 1 演算：按第 k=2 列降序重排行](images/wc329_q2_example_walkthrough.svg)

- **示例 1**：第 $k=2$ 列的值为 $[9, 11, 3]$（对应行号 $[\#0, \#1, \#2]$）；降序排列得 $[11, 9, 3]$ → 行号 $[\#1, \#0, \#2]$；按此顺序整行取回 → `[[7,5,11,2],[10,6,9,1],[4,8,3,15]]` ✓。
- **示例 2**：第 0 列 $[3, 5]$ → 降序 $[5, 3]$ → 行号 $[\#1, \#0]$ → `[[5,6],[3,4]]` ✓。
- **边界 $m = n = 1$**：唯一元素即关键字，排序前后不变，原样返回。

## 4. 算法细节

1. **比较器只含一个分支**：`return a[k] > b[k];`。互不相同的键保证这是严格弱序（反对称、传递），`std::sort` 不会触发未定义行为。
2. **行交换为何 $O(1)$**：C++ 中 `vector<vector<int>>` 的两行交换，实际交换的是内层 `vector` 的头指针/长度/容量（常数个字），**不拷贝** $n$ 个成绩。因此排序复杂度与列数 $n$ 无关，$n$ 只决定输出矩阵的大小。
3. **Python 用 `key=` 而非 `cmp`**：`sorted(score, key=lambda r: r[k], reverse=True)` 属于**装饰-排序-去装饰**（Schwartzian transform）——每行只调用一次 `r[k]` 抽键并缓存，比较时只比标量。本题 `r[k]` 是 $O(1)$ 下标读取，两写法同阶；但 `key=` 语义更清晰，且对昂贵关键字天然友好。
4. **降序的三种等价写法**：比较器 `a[k] > b[k]`；`reverse=True`；数值键取负 `key=lambda r: -r[k]`。任选其一，不要叠加两种导致方向又反回去。
5. **原地 vs 拷贝**：C++ `std::sort` 原地重排后直接返回 `score`；Python `sorted` 返回行引用组成的新列表，行数据同样不拷贝。两种实现 LeetCode 都接受。

## 5. 正确性证明

**引理 1**：第 $k$ 列的 $m$ 个值两两不同。

**证明**：题设矩阵中所有整数互不相同，第 $k$ 列的值是其中 $m$ 个，故任意 $i \ne j$ 有 $\text{score}[i][k] \ne \text{score}[j][k]$。∎

**引理 2**：「按第 $k$ 场分数从高到低」的行排列唯一存在。

**证明**：由引理 1，$\{\text{score}[i][k]\}$ 是 $m$ 个两两不同的整数，将其降序排列得到的排列唯一；设为 $v_1 > v_2 > \dots > v_m$，取 $i_t$ 满足 $\text{score}[i_t][k] = v_t$，则行序 $i_1, i_2, \dots, i_m$ 唯一，且满足题意要求的 $\text{score}[i_1][k] > \text{score}[i_2][k] > \dots > \text{score}[i_m][k]$。∎

**定理**：以 `score[i][k]` 为关键字对行做降序比较排序，返回的矩阵恰为题目所求。

**证明**：`std::sort` / `sorted` 的语义保证输出按比较器（等价地，按关键字）严格降序，即输出行序满足引理 2 中的唯一行序 $i_1, \dots, i_m$。排序过程中行只被整体移动、行内元素不被修改，故结果矩阵第 $t$ 行与原矩阵第 $i_t$ 行逐元素相同，即为题目要求的排序结果。∎

> 💡 证明的核心是**归约的正确性**：比较排序本身的正确性是标准库既定语义，我们只需论证「题目要求的行序」与「按第 $k$ 列降序的行序」是同一个东西——这正是引理 1（无并列）在起作用。若允许并列，两个行序不再一一对应，就需要稳定性或次关键字来补（见延伸思考）。

## 6. 复杂度分析

- **时间复杂度**：$O(m \log m)$。比较排序共 $O(m \log m)$ 次比较，每次只读第 $k$ 列两个标量、$O(1)$；元素移动 $O(m \log m)$ 次，每次行交换 $O(1)$。列数 $n$ **不进入**排序复杂度，只决定输出矩阵大小。$m = 250$ 时约 $2000$ 次比较，远低于暴力选择排序的 $6.25 \times 10^4$。
- **空间复杂度**：$O(\log m)$（C++ 原地 `std::sort` 的递归栈）/ $O(m)$（Python `sorted` 的键数组与新列表引用）。暴力选择排序为 $O(m^2)$ 时间、$O(1)$~$O(m)$ 空间。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<vector<int>> sortTheStudents(vector<vector<int>>& score, int k) {
        sort(score.begin(), score.end(),
             [&](const vector<int>& a, const vector<int>& b) {
                 return a[k] > b[k];
             });
        return score;
    }
};
```

> 💡 比较器按引用捕获 `k`，每次比较只读 `a[k]`、`b[k]` 两个标量；`std::sort` 原地重排，行交换 $O(1)$。

### Python

```python
class Solution:
    def sortTheStudents(self, score: List[List[int]], k: int) -> List[List[int]]:
        return sorted(score, key=lambda r: r[k], reverse=True)
```

> 💡 `key=` 对每行只抽一次键；`reverse=True` 降序。返回的是行引用的新列表，行数据不拷贝。

## 8. 边界情况与易错点

1. **单行 / 单列**（$m = 1$ 或 $n = 1$）：排序后不变，代码无需特判；$k = 0$ 是合法输入（$0 \le k < n$），比较器下标不会越界。
2. **升降序搞反**：题目要求「从高到低」，漏写 `reverse=True` 或把比较器写成 `<` 是最常见的一发 WA，样例 1 即可暴露。
3. **不带比较器直接 sort**：C++ `sort(score.begin(), score.end())` 默认按**整行字典序升序**，与「按第 $k$ 列降序」完全是两回事，样例 1 会直接错。
4. **逐列比较整行**：比较器写成从第 0 列起的字典序比较，语义错误；两行只该在第 $k$ 列上分高下。
5. **比较器写 `>=`**：本题因键互不相同，`>=` 与 `>` 在该输入上恰好等价、不会出错；但若键可能相等，`>=` 违反严格弱序，会触发 `std::sort` 未定义行为。习惯上比较器永远写 `>` / `<`，把「并列怎么办」留给稳定性或次关键字处理。
6. **别把矩阵转置或按列排序**：排序对象是**行**，第 $k$ 列只提供关键字，列内元素不参与移动。
