# LeetCode 拆分数组的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：拆分数组的最小代价（#2547，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-split-an-array/
- **来源**：LeetCode 第 329 场周赛 Q4
- **难度**：困难
- **标签**：动态规划、数组、哈希表、计数

**题意**：给定整数数组 `nums` 与整数 $k$。把 `nums` 拆成若干**非空连续子数组**，总**代价**等于各子数组**重要性**之和。子数组的 trimmed 特征是移除其中所有**仅出现一次**的数字（出现 $\ge 2$ 次的数字连同全部出现保留），**重要性** $= k + \text{trimmed}.\text{length}$。返回所有可行拆分方案中的最小代价。

**约束**：

- $1 \le n = \text{nums.length} \le 1000$
- $0 \le \text{nums}[i] < n$
- $1 \le k \le 10^9$

> 📚 本题在本仓库另有[每日题解 2547](../../solution/2501-2600/2547_拆分数组的最小代价.md)：以固定右端、左端左移时 trimmed 长度的 $+0/+2/+1$ 三分支增量为主线，含面试问答；本篇是周赛复盘视角，侧重**「孤值种数」的计数刻画**（importance $= k + L - U$）、赛时从模板识别到实现的切入路径，以及分段 DP 的完整正确性证明与边界复盘。

> 💡 **赛时定位**：本场 Q1 签到数学、Q2 排序模拟、Q3 位运算不变量（观察题，容易卡壳），Q4 反而是四题里**最"模板"**的一题——「序列切段、段代价求和取最值」与 132/139/1043 一脉相承，是标准的**区间划分 DP** 骨架。唯一门槛是把段代价 $\text{cost}(j,i)$ 做到 $O(1)$；$n \le 1000$ 的范围等于明示 $O(n^2)$。识别出模板后，这题的写出率反而高于 Q3。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,1,2,1,3,3], k = 2
输出：8
解释：拆成 [1,2] 与 [1,2,1,3,3]。
[1,2]：两个值都只出现 1 次，trimmed=[]，重要性 = 2 + 0 = 2。
[1,2,1,3,3]：值 1 出现 2 次、3 出现 2 次、2 出现 1 次；
trimmed=[1,1,3,3]，重要性 = 2 + 4 = 6。总代价 2 + 6 = 8。
```

解释：拆成 [1,2] 与 [1,2,1]。后者 trimmed=[1,1]，重要性 = 2 + 2 = 4；

## 3. 解题思路

### 3.1 暴力思路：枚举切分方案

$n-1$ 个间隙每个切/不切，共 $2^{n-1}$ 种方案，每种再花 $O(n)$ 统计各段 trimmed——$n=1000$ 时天文数字。瓶颈在「在哪切」的组合爆炸：切分本是序列前缀上的逐步决策，不同方案大量共享同一前缀却被当成独立整体重复计算。把「前缀的最小代价」提炼成状态，指数就能折叠成多项式。

### 3.2 核心观察：区间划分 DP + importance 的孤值计数刻画

![核心概念：importance = k + L − U，U 为窗口内孤值种数，删的是「种」不是「份」](images/mincost_split_singleton_formula.svg)

**第一步（模板识别）**：总代价 = 各段重要性之和，且「前缀怎么切」与「最后一段是什么」互不影响——典型的**区间划分 DP**。定义

$$\text{dp}[i] = \text{把 } \text{nums}[0..i-1] \text{ 切成若干子数组的最小代价}$$

按最后一段 $\text{nums}[j..i-1]$ 分类（引理 2 证明不重不漏）：

$$\text{dp}[i] = \min_{0 \le j < i}\;\Big\{\text{dp}[j] + \text{cost}(j,i)\Big\}, \qquad \text{dp}[0]=0,\ \text{答案}=\text{dp}[n]$$

**第二步（代价刻画）**：按定义算 $\text{cost}(j,i)$ 要整段频次统计，$O(n^2)$ 对 $(j,i)$ 共 $O(n^3)$，$n=1000$ 会超时。改用**计数刻画**：设子数组长度为 $L$、其中**恰好出现一次的不同值**有 $U$ 种（下称**孤值**），则

$$\text{trimmed}.\text{length} = L - U \quad\Longrightarrow\quad \text{cost}(j,i) = k + (i-j) - U(j,i)$$

道理：$L$ 份元素按值分组，孤值各贡献 1 份且全被删；其余值出现 $\ge 2$ 次、全部保留。被删的份数恰为孤值**种数** $U$——按"种"计而非按"份"计，因为孤值本来就只有 1 份。

**第三步（增量维护）**：固定右端 $i$、左端 $j$ 从 $i-1$ 递减到 $0$，窗口每步只在左边多进一个元素 $v=\text{nums}[j]$，只有 $v$ 的频次 $c \to c+1$，其余值的孤值状态全部不动：

| 加入前频次 $c$ | 加入后 | 对 $U$ 的影响 | 直觉 |
|---|---|---|---|
| $0$ | $1$ | $U \to U+1$ | $v$ 成为新孤值 |
| $1$ | $2$ | $U \to U-1$ | $v$ 从孤值「毕业」，两份都进 trimmed |
| $\ge 2$ | $c+1$ | 不变 | $v$ 早已计入 trimmed，只多 1 份 |

每步 $O(1)$，单轮 $i$ 内层 $O(n)$，总计 $O(n^2)$。

> 💡 **为什么赛时优先维护 $U$ 而不是 trimmed 长度**：trimmed 的增量是 $+0/+2/+1$ 的不规则跳变（$c=1$ 时要"补回"原来那份再加新增份），而 $U$ 的增量是干净的 $+1/-1/0$，且与「长度 $i-j$」天然解耦——代价公式 $k + (i-j) - U$ 里两项各自维护，心智负担最小、最不易写错。两种维护完全等价（每日题解取 trimmed 版）。

### 3.3 算法流程

![算法流程：固定右端 i、左端 j 左移、三分支维护 ones、松弛 dp[i]](images/mincost_split_ones_increment.svg)

```text
dp[0] = 0；dp[1..n] = +∞
for i = 1 .. n:                          # 计算 dp[i]
    freq[0..n-1] = 0; ones = 0           # 每轮重置频次表与孤值计数
    for j = i-1 ↓ 0:                     # 窗口 [j..i-1] 向左扩张
        c = freq[nums[j]]                # 读加入前的旧频次
        if   c == 0: ones += 1
        elif c == 1: ones -= 1           # c >= 2 时 ones 不变
        freq[nums[j]] = c + 1
        dp[i] = min(dp[i], dp[j] + k + (i-j) - ones)
return dp[n]
```

三个实现要点：① `freq` 用长度 $n$ 的**数组**而非哈希表——约束把值域压到 $[0,n)$，直接下标访问零哈希常数；② **先**加入 $\text{nums}[j]$ 更新 `ones`、**再**松弛——此时窗口恰为 $[j..i-1]$，$(i-j)-\text{ones}$ 正是这段的 trimmed；③ 外层 $i$、内层 $j$ 的顺序保证读到的 $\text{dp}[j]$ 均已定型。

### 3.4 示例演算

![示例 1 演算：dp 表收敛与末步 i=7 的 j 扫描明细](images/mincost_split_contest_walkthrough.svg)

对示例 1（$n=7$）逐列递推得 dp 表：

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| $\text{dp}[i]$ | 0 | 2 | 2 | 4 | 4 | 6 | 6 | **8** |

末步 $i=7$ 的 $j$ 扫描（窗口 $[j..6]$ 逐次左扩，`ones` 为该步的孤值种数）：

| $j$ | 窗口 | ones | $L$ | $\text{trimmed}=L-U$ | $\text{dp}[j]$ | 候选 $\text{dp}[j]+k+\text{trimmed}$ |
|---|---|---|---|---|---|---|
| 6 | $[3]$ | 1 | 1 | 0 | 6 | $6+2+0=8$ |
| 5 | $[3,3]$ | 0 | 2 | 2 | 6 | $6+2+2=10$ |
| 4 | $[1,3,3]$ | 1 | 3 | 2 | 4 | $4+2+2=8$ |
| 3 | $[2,1,3,3]$ | 2 | 4 | 2 | 4 | $4+2+2=8$ |
| **2** | $[1,2,1,3,3]$ | **1** | **5** | **4** | **2** | $2+2+4=\mathbf{8}$ ← 命中最优切分 |
| 1 | $[2,1,2,1,3,3]$ | 0 | 6 | 6 | 2 | $2+2+6=10$ |
| 0 | $[1,2,1,2,1,3,3]$ | 0 | 7 | 7 | 0 | $0+2+7=9$ |

$\text{dp}[7]=8$。$j=2$ 恰对应官方切分：前缀 $[1,2]$（代价 2）+ 末段 $[1,2,1,3,3]$（重要性 $2+4=6$）。注意 $j$ 越左窗口越长：$L$ 每步 $+1$，而 $U$ 最多小几——**段拉长多背的 trimmed 会吃掉省下的 $k$**，这正是 DP 在枚举中自动权衡的取舍（示例 3 里 $k$ 大到怎么切都不划算，整段最优）。

## 4. 算法细节

1. **状态与初值**：`dp[0]=0`（空前缀代价 0），`dp[i>0]=+∞`；答案 `dp[n]`。转移只依赖更小下标，一维数组即可。
2. **频次表选数组不选哈希**：$0 \le \text{nums}[i] < n$，长度 $n$ 的 `int` 数组直接下标访问，无哈希/装箱常数。
3. **每轮重置**：窗口内容随 $i$ 整体变化，`freq` 与 `ones` 必须每轮清零重来；清零 $O(n) \times n$ 轮 $= O(n^2)$，与主循环同阶不涨复杂度。
4. **一步内的顺序敏感**：读旧频次 `c` → 更新 `ones` → 写回 `freq` → 松弛 `dp[i]`。若先松弛后加入，窗口就缺了 $\text{nums}[j]$，$L$ 与 `ones` 对不上。
5. **整数类型**：$k \le 10^9$，候选值上界 $2k+n < 2^{31}$（§8 第 1 条给出推导），`int` 恰好安全；求稳可全程 `long long`，代价可忽略。

## 5. 正确性证明

**引理 1（孤值刻画）**：对长度为 $L$ 的子数组 $S$，设 $U(S)$ 为 $S$ 中恰好出现一次的不同值种数，则 $\text{trimmed}(S).\text{length} = L - U(S)$。

**证明**：把 $S$ 的 $L$ 份元素按值分组。恰好出现一次的值有 $U(S)$ 种、各贡献 1 份，全部被 trimmed 移除，共删 $U(S)$ 份；出现 $\ge 2$ 次的值连同全部出现保留。故保留份数为 $L - U(S)$。∎

**引理 2（递推的正确性）**：$\text{dp}[0]=0$；对 $i \ge 1$，前 $i$ 个元素的最小代价 $= \min_{0\le j<i}\{\text{dp}[j] + \text{cost}(j,i)\}$，其中 $\text{cost}(j,i)=k+(i-j)-U(\text{nums}[j..i-1])$。

**证明**：对前 $i$ 个元素的任一合法拆分，其最后一段是非空子数组 $\text{nums}[j..i-1]$（$0 \le j \le i-1$），去掉它剩下前 $j$ 个元素的合法拆分。于是全部方案按最后一段起点 $j$ 划分为互不相交且穷尽的类；类内代价 $=$ 前缀代价 $+ \text{cost}(j,i) \ge \text{dp}[j]+\text{cost}(j,i)$，且取 $\text{dp}[j]$ 对应的最优前缀拼上该末段即可达到此下界。对 $i$ 归纳即得递推式。∎

**引理 3（增量维护的不变量）**：固定右端 $i$，当内层处理完左端 $j$（即 $\text{nums}[j..i-1]$ 全部加入）时，`ones` $= U(\text{nums}[j..i-1])$。

**证明**：归纳于内层步数。窗口从 $[i-1..i-1]$ 起步，加入唯一元素后其频次为 1、`ones`=1，基例成立。设窗口 $[j+1..i-1]$ 时不变量成立，加入 $v=\text{nums}[j]$：仅 $v$ 的频次 $c \to c+1$。$c=0$：$v$ 由未出现变为孤值，$U$ 增 1，与 `ones += 1` 一致；$c=1$：$v$ 由孤值变为非孤值，$U$ 减 1，与 `ones -= 1` 一致；$c\ge 2$：$v$ 维持非孤值，$U$ 不变，与分支一致。∎

**定理**：算法返回 $\text{dp}[n]$，即所求最小代价。

**证明**：由引理 3，内层处理 $j$ 时的 $(i-j)-\text{ones}$ 恰为末段 trimmed 长度（引理 1），故每次松弛的候选就是 $\text{dp}[j]+\text{cost}(j,i)$；一轮结束取遍全部 $j \in [0,i)$，$\text{dp}[i]$ 满足引理 2 的递推。对 $i$ 归纳，每个 $\text{dp}[i]$ 都是前 $i$ 个元素的最小代价，$i=n$ 即答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n^2)$——外层 $n$ 轮，每轮内层 $j$ 扫 $O(n)$ 步、每步一次数组访问加常数分支；`freq` 每轮清零共 $O(n^2)$，同阶。$n=1000$ 时约 $10^6$ 次操作，远低于时限。
- **空间复杂度**：$O(n)$——`dp` 与 `freq` 各一个长度 $n+1$ / $n$ 的数组。
- **对照**：暴力 $O(2^{n-1}\cdot n)$；先枚举全部 $(j,i)$ 再逐对 $O(n)$ 重算频次的三重循环是 $O(n^3)=10^9$ 也会超时——增量维护省掉的正是这最后一个 $n$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minCost(vector<int>& nums, int k) {
        int n = nums.size();
        vector<int> dp(n + 1, INT_MAX);
        dp[0] = 0;
        vector<int> freq(n, 0);                    // 值域 [0,n)，数组当频次表
        for (int i = 1; i <= n; ++i) {
            fill(freq.begin(), freq.end(), 0);      // 每轮重置
            int ones = 0;                           // 孤值种数 U
            for (int j = i - 1; j >= 0; --j) {      // 窗口 [j..i-1] 左扩
                int c = freq[nums[j]]++;
                if (c == 0)      ++ones;            // 成为新孤值
                else if (c == 1) --ones;            // 孤值毕业：两份进 trimmed
                dp[i] = min(dp[i], dp[j] + k + (i - j) - ones);
            }
        }
        return dp[n];
    }
};
```

### Python

```python
class Solution:
    def minCost(self, nums: List[int], k: int) -> int:
        n = len(nums)
        dp = [0] + [float('inf')] * n
        for i in range(1, n + 1):
            freq = [0] * n                        # 每轮重置频次表
            ones = 0                              # 孤值种数 U
            for j in range(i - 1, -1, -1):        # 窗口 [j..i-1] 左扩
                v = nums[j]
                c = freq[v]
                if c == 0:
                    ones += 1
                elif c == 1:
                    ones -= 1
                freq[v] = c + 1
                cand = dp[j] + k + (i - j) - ones
                if cand < dp[i]:
                    dp[i] = cand
        return dp[n]
```

> 💡 两版均对拍验证：官方三示例；另以 $2^{n-1}$ 枚举切分的暴力在数千组随机数据（$n \le 11$）上逐例一致，并与 trimmed 直接增量版（每日题解写法）在 $n \le 40$、$k \le 10^9$ 的随机数据上交叉一致。

## 8. 边界情况与易错点

1. **整数溢出的精确界**：候选 $= \text{dp}[j] + k + \text{trimmed}$。关键在 $\text{dp}[j] \le k + j$——前 $j$ 个元素**整段不切**永远是合法方案，代价 $\le k+j$；又 $\text{trimmed} \le i-j$。故候选 $\le (k+j)+k+(i-j) = 2k+i \le 2k+n \le 2\times 10^9 + 1000 < 2^{31}-1$，`int` 恰不溢。但论证依赖"整段方案给出上界"，赛中稍不留意就会误判；用 `long long` 可完全绕开心智负担。
2. **每轮忘记重置 `freq` / `ones`**：窗口内容随 $i$ 整体变化，上一轮的频次残留会让 `ones` 完全失真——这是本写法最容易犯的错。
3. **先松弛后更新**：把松弛放在加入 `nums[j]` 之前，窗口缺当前元素，$L$ 与 `ones` 不匹配，示例 1 即错。
4. **三分支漏写 $c\ge 2$**：`ones` 不变的那支不写不会报错，但长窗口上计数会漂移。
5. **$n=1$**：单元素即孤值，trimmed 为空，答案就是 $k$——递推自然覆盖（$j=0$、$L-U=1-1=0$），无需特判。
6. **别把 trimmed 当"去重长度"**：出现 3 次的值保留 3 份而非 1 份。示例 3 中 $[1,2,1,2,1]$ 的 trimmed 长度是 5 不是 2。
7. **$k$ 极大时用于 sanity check**：$k \ge n$ 时整段必最优（见延伸思考 ①），可作对拍校验点。
