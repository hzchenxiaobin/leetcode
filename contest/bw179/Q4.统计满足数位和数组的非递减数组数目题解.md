# LeetCode 统计满足数位和数组的非递减数组数目 题解

## 1. 题目概述

- **标题 / 题号**：统计满足数位和数组的非递减数组数目（#3883，hard）
- **链接**：https://leetcode.cn/problems/count-non-decreasing-arrays-with-given-digit-sums/
- **来源**：LeetCode 第 179 场双周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、前缀和

**题意**：给定长度为 $n$ 的数组 `digitSum`。称长度同样为 $n$ 的数组 $arr$ 是**有效**的，若同时满足：

1. $0 \le arr[i] \le 5000$；
2. $arr$ **非递减**（每个元素不小于前一个）；
3. $arr[i]$ 的**数位和**恰好等于 `digitSum[i]`。

返回不同有效数组的个数，对 $10^9+7$ 取模。

**约束**：

- $1 \le n \le 1000$
- $0 \le digitSum[i] \le 50$

## 2. 示例

**示例 1**

```text
输入：digitSum = [25,1]
输出：6
解释：数位和为 25 且在 [0,5000] 内、又能不超过它的「数位和为 1 的数」只有 1000，
      而数位和为 25 且 ≤ 1000 的数有 799、889、898、979、988、997 共 6 个，
      于是 6 个形如 [x, 1000] 的有效数组。
```

**示例 2**

```text
输入：digitSum = [1]
输出：4
解释：数位和为 1 的数在 [0,5000] 内有 1、10、100、1000 共 4 个，长度 1 的数组自动非递减。
```

**示例 3**

```text
输入：digitSum = [2,49,23]
输出：0
解释：[0,5000] 内最大的数位和是 4+9+9+9 = 31（例如 4999），不存在数位和 49 的数，故答案为 0。
```

## 3. 解题思路

### 3.1 暴力思路

对每个位置枚举 $[0,5000]$ 里所有满足数位和的数，再枚举所有组合并检查非递减，复杂度约为 $5001^n$，完全不可行。

即使只在「候选集合」里组合，候选数最多 365 个（数位和 15、16 时），$365^n$ 仍然爆炸。必须用 DP 复用子问题的结果。

### 3.2 核心观察：把「取值」离散成「候选列表」，并对候选做 DP

![预处理：把 0…5000 按数位和分组，组内天然升序](images/bw179_q4_groups.svg)

**观察 1：每个位置的可选值是一个很小的有序列表。** 把所有 $0 \le x \le 5000$ 按「数位和」分到 51 个组里（数位和 $0 \sim 50$）。因为 $x$ 是从小到大遍历的，**每个组内部天然升序**。于是第 $i$ 个位置只能取 `groups[digitSum[i]]` 里的值——一个升序数组，最多 365 个元素。若某个组为空（如数位和 49、50），答案直接是 0。

**观察 2：非递减约束只与「上一个取的是哪个候选」有关。** 设上一组候选为 $P$、当前组候选为 $C$（都升序）。若上一个位置取了 $P[k]$，当前要取 $C[j]$，合法性条件是 $P[k] \le C[j]$；由于 $P$ 升序，满足条件的 $k$ 恰好是**前 $cnt(j) = \#\{k : P[k] \le C[j]\}$ 个**。

**观察 3：于是转移可以批量完成。** 记 `dp[k]` 为「以 $P[k]$ 结尾的方案数」，`pre` 为 `dp` 的前缀和。对每个 $C[j]$，

$$\text{dp\_new}[j] = \sum_{k < cnt(j)} \text{dp}[k] = \text{pre}[\,cnt(j)\,]$$

而 $cnt(j)$ 就是对升序数组 $P$ 做一次 `upper_bound`（二分）。整组转移只需 $O(|C| \log |P|)$，比双重循环的 $O(|C||P|)$ 快一个量级（虽然 $365^2$ 也不算大，但二分写法更干净）。

![转移：用上一组的前缀和 + 二分，一次算出所有 dp_new](images/bw179_q4_dp.svg)

**观察 4：初始状态。** 第一个位置没有「前一个数」的约束，所以 `dp[k] = 1`（每个候选各构成 1 个方案）。最后答案是最后一组所有 `dp[j]` 之和。

### 3.3 算法流程

![示例演算：digitSum 依次为 25 和 1 时答案 6](images/bw179_q4_walkthrough.svg)

```text
1. 预处理 groups[0..50]：for x in 0..5000: groups[digitSumOf(x)].append(x)     # 组内升序
2. prev = None, dp = None
3. for ds in digitSum:
4.     cand = groups[ds]
5.     若 cand 为空: 返回 0
6.     若 prev 为空: dp = [1] * len(cand)                # 第一个位置
7.     否则:
8.         pre[0] = 0; pre[t+1] = (pre[t] + dp[t]) % MOD
9.         dp_new[j] = pre[ upper_bound(prev, cand[j]) ]  # 对所有 j
10.        dp = dp_new
11.    prev = cand
12. 返回 sum(dp) % MOD
```

### 3.4 示例演算

对示例 1 的 `digitSum = [25, 1]`：

- `groups[25]` 共 80 个元素，其中 $\le 1000$ 的正是 $799, 889, 898, 979, 988, 997$，其余（$1699, 1789, \dots$）都大于 1000；
- `groups[1]` 共 4 个元素：$1, 10, 100, 1000$。

| 位置 | 候选 | dp |
|------|------|----|
| 0 | 799, 889, 898, 979, 988, 997（及更大的 74 个） | 每个候选各 1（共 80 个 1） |
| 1 | 1, 10, 100, 1000 | `upper_bound` 后：$1,10,100$ 在 `prev` 里的位置都是 0 → dp = 0；$1000$ 的位置是 6（前 6 个候选 $\le 1000$）→ dp = `pre[6]` = 6 |

末组求和 $0+0+0+6 = 6$ ✓。注意 `prev` 里那 74 个大于 1000 的候选虽然 dp 值为 1，但只有 $\le 1000$ 的前 6 个能被 `upper_bound` 计入，所以不会影响结果。

## 4. 算法细节

1. **预处理只做一次**：$5001$ 个数各算一次数位和（$O(5000 \log 5000)$），分组结果可复用。C++ 里可以放在函数内的 `static` 变量里，避免重复计算。
2. **前缀和下标**：`pre` 长度 `len(dp)+1`，`pre[0]=0`、`pre[t] = dp[0]+…+dp[t-1]`，这样 `pre[cnt]` 正好是「前 cnt 个 dp 之和」，与 `upper_bound` 返回的「≤ 当前值的个数」完美对应。
3. **二分**：C++ `upper_bound(prev.begin(), prev.end(), cand[j])`，Python `bisect_right(prev, cand[j])`。注意是 `_right`（即 `upper_bound`）——要找「≤ 当前值」的个数，用 `lower_bound` 会漏掉等于的情况。
4. **首位置**：`dp` 全 1。也可以理解为「有一个虚拟的 $-1$ 前缀，任何候选都 ≥ 它」。
5. **空组**：直接返回 0。示例 3 中 `groups[49]` 为空，一步就能判定。
6. **取模**：前缀和与 dp 都要取模；C++ 用 `long long` 存中间值。
7. **状态规模**：`dp` 长度最多 365，`n ≤ 1000`，转移 $O(365 \log 365)$，总量约 $3\times10^5$ 次操作。

## 5. 正确性证明

**引理 1（分组正确且有序）**：`groups[s]` 恰为 $\{x \in [0,5000] : \text{digitSum}(x) = s\}$，且按升序排列。

**证明**：外层循环 $x$ 从 0 到 5000 递增，把 $x$ 追加到 `groups[digitSum(x)]` 末尾。由追加顺序，每组内元素严格递增；由遍历完备性，每个满足条件的 $x$ 恰好被追加一次。∎

**引理 2（`dp` 语义）**：设处理完第 $i$ 个位置后，`prev` 恰为 `groups[digitSum[i]]`，`dp[k]` 等于「前 $i+1$ 个位置已经安排完毕、且第 $i$ 个位置取值恰好为 `prev[k]`」的有效方案数。

**证明**：对 $i$ 归纳。

- $i = 0$：只有第 0 个位置，取 `prev[k]` 即构成唯一方案（无前缀约束），`dp[k] = 1` ✓。
- 设对 $i-1$ 成立。第 $i$ 个位置取 `cand[j]` 时，任何以 `prev[k]` 结尾（$i-1$ 位置的取值）的合法前缀都可以接上，当且仅当 `prev[k] ≤ cand[j]`。由引理 1，`prev` 升序，满足条件的 $k$ 恰为前 $cnt = $ `upper_bound(prev, cand[j])` 个，故方案数为 $\sum_{k<cnt} dp[k] = pre[cnt]$，与算法第 9 行一致。∎

**引理 3（候选即全部合法取值）**：$arr[i]$ 取 `groups[digitSum[i]]` 中的值，当且仅当它满足「$0 \le arr[i] \le 5000$ 且数位和等于 `digitSum[i]`」。

**证明**：由引理 1 的定义直接得到。∎

**定理**：算法返回有效数组的个数（模 $10^9+7$）。

**证明**：有效数组与「每个位置从对应候选组中选一个值、且序列非递减」的选择方案一一对应（引理 3）。任何有效数组都被唯一地表示成这样的选择，故计数相同。算法的 `dp` 按「最后一个位置的取值」对方案做了划分：由引理 2，`dp[j]` 是「前 $n$ 个位置已安排、且末位取第 $j$ 个候选」的方案数；这些集合按末位取值互不相交且覆盖全部非递减方案，求和即得总数。取模不改变计数在模意义下的值。∎

## 6. 复杂度分析

- **时间**：预处理 $O(5000 \log 5000)$（数位和逐个求）；DP 部分对每个位置做一次前缀和 $O(|prev|)$ 与 $|cand|$ 次二分 $O(\log |prev|)$，总量 $O\big(n \cdot C \log C\big)$，其中 $C \le 365$（最大组大小），约 $10^6$ 次基本操作。
- **空间**：$O(5000)$ 存放分组（加上 51 个向量的开销），DP 只用两个长度为 $C$ 的数组，额外 $O(C)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countArrays(vector<int>& digitSum) {
        const long long MOD = 1000000007LL;
        vector<vector<int>> groups(51);
        for (int x = 0; x <= 5000; x++) {
            int s = 0, t = x;
            while (t > 0) {
                s += t % 10;
                t /= 10;
            }
            groups[s].push_back(x);
        }

        vector<long long> dp;
        vector<int> prev;
        bool first = true;
        for (int ds : digitSum) {
            const vector<int>& cand = groups[ds];
            if (cand.empty()) return 0;
            if (first) {
                dp.assign(cand.size(), 1);
                first = false;
            } else {
                vector<long long> pre(dp.size() + 1, 0);
                for (size_t i = 0; i < dp.size(); i++) pre[i + 1] = (pre[i] + dp[i]) % MOD;
                vector<long long> ndp(cand.size(), 0);
                for (size_t j = 0; j < cand.size(); j++) {
                    size_t cnt = upper_bound(prev.begin(), prev.end(), cand[j]) - prev.begin();
                    ndp[j] = pre[cnt];
                }
                dp.swap(ndp);
            }
            prev = cand;
        }

        long long ans = 0;
        for (long long v : dp) ans = (ans + v) % MOD;
        return (int)ans;
    }
};
```

### Python

```python
from bisect import bisect_right

class Solution:
    def countArrays(self, digitSum: list[int]) -> int:
        MOD = 10 ** 9 + 7
        groups = [[] for _ in range(51)]
        for x in range(5001):
            s = 0
            t = x
            while t:
                s += t % 10
                t //= 10
            groups[s].append(x)

        prev = None
        dp = None
        for ds in digitSum:
            cand = groups[ds]
            if not cand:
                return 0
            if prev is None:
                dp = [1] * len(cand)
            else:
                pre = [0] * (len(dp) + 1)
                for i, v in enumerate(dp):
                    pre[i + 1] = (pre[i] + v) % MOD
                ndp = [0] * len(cand)
                for j, val in enumerate(cand):
                    cnt = bisect_right(prev, val)
                    ndp[j] = pre[cnt]
                dp = ndp
            prev = cand
        return sum(dp) % MOD
```

## 8. 边界情况与易错点

1. **空组**：`digitSum[i]` 在 $[0,5000]$ 内无解（如 32 以上的多数值），必须立刻返回 0，否则会在空数组上做前缀和/二分。
2. **`upper_bound` vs `lower_bound`**：要求「前一个数 ≤ 当前数」，所以统计的是「≤ 当前值」的个数，必须用 `upper_bound` / `bisect_right`。用 `lower_bound` 会漏掉「相等」的情况，答案偏小。
3. **前缀和的下标偏移**：`pre` 长度为 `len(dp)+1` 且 `pre[0] = 0`。若写成 `pre[t] = dp[0]+…+dp[t]`（长度相同），`pre[cnt]` 就会错位一格。
4. **首位置**：`dp` 必须全 1，而不是只有第一个候选为 1。第一个位置可以取组内任意值。
5. **数位和 0**：`groups[0]` 只有 $\{0\}$，所以 `digitSum[i] = 0` 时该位置只能取 0，会强制后面的位置都 ≥ 0（自动满足）。
6. **取模**：前缀和累加与 dp 赋值都要取模，否则 Python 无所谓但 C++ 会溢出（`long long` 也可能在多次累加前溢出，好在每步都取模）。
7. **`n = 1`**：答案就是该组的大小（示例 2 的 4）。代码无需特判。
8. **组大小差异**：不同位置的候选组大小可能差别很大（如 365 与 1），前缀和与二分的长度要用**上一组**的，不要用当前组的。
