# LeetCode 通过投票对团队排名 题解

## 1. 题目概述

- **标题 / 题号**：通过投票对团队排名（#1366，medium）
- **链接**：https://leetcode.cn/problems/rank-teams-by-votes/
- **来源**：LeetCode 第 178 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、字符串、计数、排序

**题意**：给定投票数组 `votes`，每张票是全体团队的一个严格排名（如 `"ACB"` 表示 A 第一、C 第二、B 第三）。最终名次按多级规则确定：先比「排位第一」的票数，多者靠前；并列则比「排位第二」的票数；以此类推；若所有位置的票数都相同，按团队字母升序。返回排序后的名次串。

**约束**：

- `1 <= votes.length <= 1000`（投票人数 $n$）
- `1 <= votes[i].length <= 26`（团队数 $m$，每票是全体团队的一个排列，各票使用同一字母集合）
- `votes[i][j]` 为互异大写英文字母

## 2. 示例

**示例 1**

```text
输入：votes = ["ABC","ACB","ABC","ACB","ACB"]
输出："ACB"
解释：
  A 拿到全部 5 张「排位第一」的票，直接夺冠；
  B 与 C 的「排位第一」票数都是 0，进入下一级比较；
  「排位第二」：B 2 票、C 3 票 → C 第二、B 第三。
```

**示例 2**

```text
输入：votes = ["WXYZ","XYZW"]
输出："XWYZ"
解释：X、W 的「排位第一」票数并列（1:1），
  「排位第二」X 有 1 票、W 为 0 → X 在前。
```

**示例 3**

```text
输入：votes = ["ZMNAGUEDSJYLBOPHRQICWFXTVK"]
输出："ZMNAGUEDSJYLBOPHRQICWFXTVK"
解释：只有一个投票者，名次即其意愿（各位置票数互异，逐位即分胜负）。
```

## 3. 解题思路

### 3.1 暴力思路

两条直觉路线，先排雷再优化：

- **加权计分（错误直觉）**：给排位 $p$ 赋权 $m-p$，按总分排序——像球赛的积分制。**反例**：`votes = ["ABC","ABC","ABC","BCA","BCA"]` 时正确答案是 `"ABC"`（A 的「排位第一」票数 $3 > 2$，多级规则下 A 必须压过 B），但加权计分下 $B = 2\times 2 + 3\times 1 = 7 > A = 3\times 2 = 6$，会错误输出 `"BAC"`。多级平票规则**无法被任何线性加权和表达**——高位票数是「一票定生死」的优先级，不是可累加的分数。
- **逐对打擂台（正确但笨）**：先 $O(nm)$ 统计各队各位置票数（这一步无论如何省不掉），然后不排序，每轮从剩余队伍中按规则逐位比较选出当前名次最高的队，共 $O(m^2)$ 场对决、每场 $O(m)$，总 $O(m^3)$。$m \le 26$ 也能通过，但代码冗长、循环边界多。

> ⚠️ 本题最大的坑就是把「多级平票」误当成「加权计分」。规则的本质是**逐级字典序**：第 1 位的一票优先于第 2 位的全部票，等价于位与位之间的权重差是「无穷大」，任何有限权重的加权和都无法刻画。

### 3.2 核心观察：每队抽出一个「票数向量」，规则 = 字典序比较

![核心观察：多级平票规则就是票数向量的字典序比较](images/wc178_q2_rank_vector_concept.svg)

统计出 `cnt[团队][排位]` 后，每支球队对应一个 $m$ 维**票数向量** $\mathrm{cnt}(t) = (c_0, c_1, \ldots, c_{m-1})$。题目的规则翻译成向量语言：

> X 排在 Y 前 ⟺ 存在首个不同位 $p$ 使 $c_p(X) > c_p(Y)$；所有位相同 ⟺ 按字母升序。

这正是**元组的字典序比较**（票多者为「小」），最后一级字母序仍是字典序。于是「谁排前面」被压缩成**一次元组比较**，整个排名交给排序库一次完成：$O(m \log m)$ 次比较，每次 $O(m)$。

> 💡 竞赛里见到「并列时继续比下一级」的题面，条件反射应该是：**给每个实体造一个多级关键字元组，直接排序**。

### 3.3 算法流程

![算法流程：统计票数 → 比较器排序 → 拼接输出](images/wc178_q2_sort_flow.svg)

四步流水线：

1. **统计**：遍历 $n$ 张票，执行 `cnt[votes[i][p]][p]++`，$O(nm)$；
2. **取队伍集合**：每票都是全体团队的排列，故队伍集合即 `votes[0]` 的字母；
3. **排序**：比较器从第 0 位起找首个不同位，票多者在前；$m$ 位全同则按字母升序兜底；
4. **拼接**：按排序后的顺序连接字母，即答案串。

### 3.4 示例演算

![示例 1 演算：票数矩阵与逐级比较得到 ACB](images/wc178_q2_walkthrough.svg)

以示例 1 为例，票数矩阵：

| 队伍 | 第 1 位 | 第 2 位 | 第 3 位 |
|------|---------|---------|---------|
| A    | 5       | 0       | 0       |
| B    | 0       | 2       | 3       |
| C    | 0       | 3       | 2       |

- **冠军**：A 第 1 位 5 票 vs 其他队 0 票，首位即分胜负，A 锁定第 1 名；
- **第 2 名**：B vs C 第 1 位 $0 = 0$ 平局 → 下探第 2 位 $2 < 3$，C 胜；
- 输出 `"ACB"` ✓。

## 4. 算法细节

1. **数据结构**：`cnt[26][m]` 二维数组（行 = 字母、列 = 排位），字母仅 26 个、$m \le 26$，无需哈希表；C++ 直接开 `int cnt[26][26] = {}`。
2. **队伍集合**：题目保证每票都是全体团队的一个排列，`votes[0]` 的字符集就是全部队伍，无需扫描取并集，也不会有「只在部分票中出现的字母」。
3. **C++ 比较器**：`for p in [0, m)` 找首个 `cnt[a][p] != cnt[b][p]` 的位，返回该位的 `>`；循环走完返回 `a < b`。单次比较 $O(m)$，且构成严格弱序（§5 引理 1），满足 `std::sort` 的前置条件。
4. **Python 排序键**：`key = tuple(-c for c in cnt[t]) + (t,)`——每位票数**取负**，把「票多在前」折叠成元组**升序**；末尾拼上字母 $t$ 自身，天然处理最后一级平票，一行完成排序。
5. **输出**：排序顺序即名次，按序拼接字母即返回值，无需额外结构。

## 5. 正确性证明

**引理 1（元组字典序是全序）**：设各分量集合上均有全序，则由这些分量组成的等长元组按字典序比较构成全序（任意两元组恰有 $<$、$=$、$>$ 三种关系之一）。

**证明**：对元组长度 $k$ 归纳。$k = 1$ 时即分量自身的全序。设结论对 $k-1$ 成立，比较两个 $k$ 元组 $x, y$：先比第一分量，若不等，由分量全序的三分性立得 $x < y$ 或 $y < x$；若相等，则整体关系归结为后 $k-1$ 个分量的关系，由归纳假设三种关系恰成立其一。∎

**引理 2（并列必然被字母打破）**：定义 $\mathrm{key}(t) = (-c_0(t),\, -c_1(t),\, \ldots,\, -c_{m-1}(t),\, t)$，则任意两个不同团队 $t_1 \ne t_2$ 的关键字必不相同。

**证明**：前 $m$ 个分量是两队的票数（可能完全相同），但最后一个分量是团队字母本身，$t_1 \ne t_2$ 时必不同，故整条元组不等。∎

**定理**：按 $\mathrm{key}$ 升序排序后依次拼接的字符串，就是题目规则确定的唯一排名。

**证明**：先证比较关系等价。规则判定「X 排在 Y 前」当且仅当下列之一成立：

- ① 存在最小 $p$ 使 $c_p(X) \ne c_p(Y)$ 且 $c_p(X) > c_p(Y)$；
- ② 所有位置票数相同且 $X < Y$（字母序）。

情形 ①：两条 key 的前 $p$ 个分量相等，第 $p+1$ 个分量满足 $-c_p(X) < -c_p(Y)$，故 $\mathrm{key}(X) < \mathrm{key}(Y)$；反之若 $\mathrm{key}(X) < \mathrm{key}(Y)$ 且前 $p$ 个分量相等，则第 $p+1$ 个分量严格更小，即 $c_p(X) > c_p(Y)$，回到情形 ①。情形 ②：两条 key 的前 $m$ 个分量相等，第 $m+1$ 个分量即字母本身，$X < Y$ 等价于 $\mathrm{key}(X) < \mathrm{key}(Y)$。

故「$\mathrm{key}(X) < \mathrm{key}(Y)$」⟺「规则判定 X 在 Y 前」。由引理 1 该关系是全序，由引理 2 任意两队关键字互异（无并列），$m$ 支队伍的排序结果唯一确定，拼接即为所求。∎

## 6. 复杂度分析

- **时间复杂度**：$O(nm + m^2 \log m)$。统计票数遍历 $n \le 1000$ 张票、每票 $m \le 26$ 位，约 $2.6 \times 10^4$ 步；排序 $O(m \log m) \approx 122$ 次比较、每次最坏 $O(m)$，合计约 $3.2 \times 10^3$ 步。总量级 $3 \times 10^4$，远在时限内；相比逐对打擂台的 $O(nm + m^3)$（$m = 26$ 时约 $4.4 \times 10^4$），优势主要在代码更短、更不易写错。
- **空间复杂度**：$O(26 \cdot m)$。票数矩阵至多 $26 \times 26$ 个整数，另有队伍串 $O(m)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    string rankTeams(vector<string>& votes) {
        int m = votes[0].size();
        int cnt[26][26] = {};
        for (const string& v : votes)
            for (int p = 0; p < m; p++)
                cnt[v[p] - 'A'][p]++;

        string teams = votes[0];
        sort(teams.begin(), teams.end(), [&](char a, char b) {
            for (int p = 0; p < m; p++)
                if (cnt[a - 'A'][p] != cnt[b - 'A'][p])
                    return cnt[a - 'A'][p] > cnt[b - 'A'][p];
            return a < b;
        });
        return teams;
    }
};
```

### Python

```python
class Solution:
    def rankTeams(self, votes: List[str]) -> str:
        m = len(votes[0])
        cnt = {t: [0] * m for t in votes[0]}
        for vote in votes:
            for p, t in enumerate(vote):
                cnt[t][p] += 1
        return "".join(sorted(cnt, key=lambda t: tuple(-c for c in cnt[t]) + (t,)))
```

## 8. 边界情况与易错点

1. **禁用加权计分**：`votes = ["ABC","ABC","ABC","BCA","BCA"]` 正确输出 `"ABC"`，加权计分（权重 $m-p$）会错误输出 `"BAC"`。多级平票是字典序优先级，不是分数累加。
2. **最后一级字母序别漏**：`votes = ["AB","BA"]` 时 A、B 的票数向量都是 $(1, 1)$，必须靠字母升序输出 `"AB"`；漏掉这一级时向量全同的两队顺序不确定。
3. **Python 键的符号方向**：票数取负 + 元组升序；字母本身**不取负**（升序兜底）。任何一处方向写反都会输出反序串。
4. **C++ 比较器须为严格弱序**：首个不同位返回严格的 `>`，全同返回 `a < b`；若误写 `>=` 或混入等号，`std::sort` 是未定义行为（可能越界崩溃）。
5. **`m = 1`（单团队）**：票长为 1 时只有一支队伍，比较器循环不执行、直接返回该字母，无需特判。
6. **队伍集合以 `votes[0]` 为准**：不要用 26 个字母全集排序——未出现的字母票数全 0，会混进结果串。
7. **统计的行列别写反**：`cnt[v[p]-'A'][p]` 是「行 = 字母、列 = 排位」；`26×26` 的数组写反行列仍能编译，但示例 1 会输出错序（如 `"ABC"`），属于隐蔽 bug。
