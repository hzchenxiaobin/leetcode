# LeetCode 有多少小于当前数字的数字 题解

## 1. 题目概述

- **标题 / 题号**：有多少小于当前数字的数字（#1365，easy）
- **链接**：https://leetcode.cn/problems/how-many-numbers-are-smaller-than-the-current-number/
- **来源**：LeetCode 第 178 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数排序、排序

**题意**：给定数组 `nums`，对其中每个元素 `nums[i]`，统计数组中**严格小于它**的数字个数，即满足 `j != i` 且 `nums[j] < nums[i]` 的下标 `j` 的数目，以数组形式返回所有结果。

**约束**：

- `2 <= nums.length <= 500`
- `0 <= nums[i] <= 100`

## 2. 示例

**示例 1**

```text
输入：nums = [8,1,2,2,3]
输出：[4,0,1,1,3]
解释：
  nums[0]=8：比它小的有 1,2,2,3 共 4 个
  nums[1]=1：没有比它小的数
  nums[2]=2：比它小的只有 1
  nums[3]=2：比它小的只有 1
  nums[4]=3：比它小的有 1,2,2 共 3 个
```

**示例 2**

```text
输入：nums = [6,5,4,8]
输出：[2,1,0,3]
```

**示例 3**

```text
输入：nums = [7,7,7,7]
输出：[0,0,0,0]
解释：严格小于 7 的数不存在，重复的 7 互不计入。
```

## 3. 解题思路

### 3.1 暴力思路

对每个 `nums[i]` 再扫一遍整个数组，数出满足 `nums[j] < nums[i]` 的 `j` 的个数：

- 双重循环，时间 $O(n^2)$；
- $n \le 500$ 时总比较次数约 $2.5 \times 10^5$，比赛里稳过；
- 但完全没用到「值域只有 $[0,100]$ 共 101 种取值」这一结构信息——签到题也应顺手写出更优解。

### 3.2 核心观察：值域极小 → 频次数组 + 前缀和

![核心观察：值域 0..100 极小，频次桶 + 前缀和，查表代替两两比较](images/wc178_q1_counting_concept.svg)

**关键等价**：「比 `nums[i]` 小的元素个数」=「值落在 $[0,\ nums[i]-1]$ 内的元素总数」。若已知每个值的出现频次 `count[v]`，则后者就是 $count[0] + count[1] + \cdots + count[v-1]$，即频次数组的**前缀和** `smaller[v]`。

于是 $O(n^2)$ 的两两比较被拆成三步线性扫描：

1. **统计频次**：遍历 `nums`，执行 `count[v]++`；
2. **前缀和**：$smaller[v] = smaller[v-1] + count[v-1]$，含义是「严格小于 $v$ 的元素总数」；
3. **查表**：$answer[i] = smaller[nums[i]]$，每个元素 $O(1)$。

> 💡 相同的值共享同一个 `smaller[v]`：示例 1 中两个 `2` 都查 `smaller[2] = 1`，只需算一次。这是查表比逐个比较快的根源。

### 3.3 算法流程

![算法流程：统计频次 → 前缀和 → 查表，总时间 O(n+k)](images/wc178_q1_prefix_sum_flow.svg)

三阶段耗时分别为 $O(n)$、$O(k)$、$O(n)$，其中 $k = 101$ 为值域大小，总计 $O(n + k)$。$n = 500$ 时约 1100 步，比暴力的 $2.5 \times 10^5$ 步少两个数量级。

### 3.4 示例演算

以示例 1 的 `nums = [8,1,2,2,3]` 为例（值域只画 `0..8`）：

![示例演算：count → smaller → 查表填 answer](images/wc178_q1_example_walkthrough.svg)

**阶段 ① 频次**：`count[1]=1, count[2]=2, count[3]=1, count[8]=1`，其余为 0。

**阶段 ② 前缀和**：`smaller[2] = smaller[1] + count[1] = 0+1 = 1`，`smaller[3] = 1+2 = 3`，`smaller[8] = 4`。

**阶段 ③ 查表**：`8→4, 1→0, 2→1, 2→1, 3→3`，得 `answer = [4,0,1,1,3]` ✓

## 4. 算法细节

1. **数组开 101 格**：值域 $[0,100]$ 含两端，`count` 与 `smaller` 均为长度 101 的数组，下标直接用值。
2. **递推式用 `count[v-1]`**：题目要求严格小于，`count[v]`（等于 $v$ 的个数）不能计入；递推累加的恰好是 $[0, v-1]$ 的频次。
3. **`smaller[0] = 0` 为天然基准**：非负数中不存在比 0 小的值，无需特判。
4. **`j != i` 条件无需显式处理**：`nums[j] < nums[i]` 蕴含 `j != i`（自己不会小于自己），统计严格小于的个数时该条件自动满足。
5. **替代解法（值域无界时）**：排序后每个值**首次出现的下标**即比它小的元素个数，用哈希表记录 `值 → 首次下标` 再查表，$O(n \log n)$，不依赖值域大小。

## 5. 正确性证明

**引理 1（答案只依赖值）**：对任意下标 $i, i'$，若 $nums[i] = nums[i']$，则 $answer[i] = answer[i']$。

**证明**：$answer[i]$ 是集合 $\{\,j : nums[j] < nums[i]\,\}$ 的大小，只与值 $nums[i]$ 有关，与下标位置无关。∎

**引理 2（前缀和正确）**：对一切 $v \in [0,100]$，$smaller[v] = \left|\{\,j : nums[j] < v\,\}\right| = \sum_{u=0}^{v-1} count[u]$。

**证明**：对 $v$ 归纳。$v = 0$：非负数中无小于 0 的值，两侧均为 0。设结论对 $v-1$ 成立。由于元素值均为整数，$\{\,j : nums[j] < v\,\}$ 可拆为两个不相交集合之并：$\{\,j : nums[j] < v-1\,\} \cup \{\,j : nums[j] = v-1\,\}$，后者大小恰为 $count[v-1]$。故 $\left|\{\,j : nums[j] < v\,\}\right| = smaller[v-1] + count[v-1]$，即递推式的值。∎

**定理**：算法输出满足题意，即 $answer[i] = \left|\{\,j : j \ne i \wedge nums[j] < nums[i]\,\}\right|$。

**证明**：算法置 $answer[i] = smaller[nums[i]]$。由引理 2（取 $v = nums[i]$），$smaller[nums[i]] = \left|\{\,j : nums[j] < nums[i]\,\}\right|$。又 $nums[j] < nums[i]$ 蕴含 $j \ne i$，故该集合与 $\{\,j : j \ne i \wedge nums[j] < nums[i]\,\}$ 相同。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + k)$。阶段 ① 遍历数组 $O(n)$；阶段 ② 递推整个值域 $O(k)$（$k = 101$ 为常数）；阶段 ③ 再遍历查表 $O(n)$。$n = 500$ 时约 1100 步。
- **空间复杂度**：$O(k)$。`count` 与 `smaller` 各 101 格（不计输出数组的 $O(n)$）。
- **对比**：暴力 $O(n^2)$ 在本题数据范围（$2.5 \times 10^5$ 次比较）内也能通过；排序 + 哈希 $O(n \log n)$ 通用但不利用值域结构，$k \ll n \log n$ 时计数法更优。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> smallerNumbersThanCurrent(vector<int>& nums) {
        int count[101] = {0};
        for (int v : nums) count[v]++;

        int smaller[101] = {0};
        for (int v = 1; v <= 100; v++) {
            smaller[v] = smaller[v - 1] + count[v - 1];
        }

        vector<int> answer;
        answer.reserve(nums.size());
        for (int v : nums) answer.push_back(smaller[v]);
        return answer;
    }
};
```

### Python

```python
class Solution:
    def smallerNumbersThanCurrent(self, nums: list[int]) -> list[int]:
        count = [0] * 101
        for v in nums:
            count[v] += 1

        smaller = [0] * 101
        for v in range(1, 101):
            smaller[v] = smaller[v - 1] + count[v - 1]

        return [smaller[v] for v in nums]
```

## 8. 边界情况与易错点

1. **全相同元素**：`[7,7,7,7]` 中严格小于 7 的数为 0，答案全 0；频次 `count[7]=4` 不影响 `smaller[7]=0`。
2. **最小值 0**：`smaller[0]` 恒为 0，递推基准天然正确，无需特判。
3. **严格小于 vs 小于等于**：递推用 `count[v-1]` 而非 `count[v]`；若误用会把与 `nums[i]` 相同的元素也计入，导致 `[7,7,7,7]` 输出 `[3,3,3,3]` 而非全 0。
4. **`j != i` 不需特判**：`nums[j] < nums[i]` 自动排除自身（自己不小于自己），无需在计数时减 1。
5. **数组长度 101 而非 100**：值 100 合法，开 101 格防止 `smaller[100]` 越界。
6. **比赛策略**：$n \le 500$ 暴力可过，但计数法代码量相当、复杂度更优，签到阶段直接写最优解更稳。
