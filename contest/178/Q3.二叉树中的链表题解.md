# LeetCode 二叉树中的链表 题解

## 1. 题目概述

- **标题 / 题号**：二叉树中的链表（#1367，medium）
- **链接**：https://leetcode.cn/problems/linked-list-in-binary-tree/
- **来源**：LeetCode 第 178 场周赛 Q3
- **难度**：中等
- **标签**：树、深度优先搜索、链表、二叉树

**题意**：给定一棵以 `root` 为根的二叉树和一条以 `head` 为首的链表。判断树中是否存在一条**一直向下的路径**（从某个节点出发，每步走向其左孩子或右孩子），使得路径上各节点的值与链表各节点的值**从头到尾一一对应**。存在返回 `true`，否则返回 `false`。

**约束**：

- 树和链表的每个节点值均满足 $1 \le \text{node.val} \le 100$
- 链表长度 $1 \le m \le 100$
- 二叉树节点数 $1 \le n \le 2500$

> 💡 本题规模很小（$n \cdot m \le 2.5 \times 10^5$），任何 $O(n \cdot m)$ 的做法都稳过。真正的考点不是复杂度优化，而是把「起点任意」与「只能向下」两个条件**干净地组织成两个互相调用的递归**，并避开「携带部分匹配状态」的贪心陷阱（见 §8.1）。

## 2. 示例

**示例 1**

```text
输入：head = [4,2,8], root = [1,4,4,null,2,2,null,1,null,6,8,null,null,null,null,1,3]
输出：true
解释：根的右子树中，路径 4 → 2 → 8 与链表 [4,2,8] 一一对应。
```

**示例 2**

```text
输入：head = [1,4,2,6], root = [1,4,4,null,2,2,null,1,null,6,8,null,null,null,null,1,3]
输出：true
解释：路径 1 → 4 → 2 → 6（根 → 右 4 → 左 2 → 左 6）与链表 [1,4,2,6] 一一对应。
```

**示例 3**

```text
输入：head = [1,4,2,6,8], root = [1,4,4,null,2,2,null,1,null,6,8,null,null,null,null,1,3]
输出：false
解释：所有「开头对得上」的路径都在第 4 步或链表末尾断裂（见 §3.4 演算）。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法：把树中**所有向下路径**物化成数组，再逐条与链表比对。向下路径的条数最坏 $O(n \cdot H)$（$H$ 为树高，链状树时 $H = n$），全部展开再比对的代价是 $O(n \cdot H^2)$ 量级——链状树 2500 个节点时约 $10^9$，还要额外存下路径本身，笨重且容易爆。

另一条岔路：注意到**每条向下路径都是某条「根到叶」路径的连续段**，于是收集所有根到叶路径、拼成字符串，再对链表串做子串查找。思路看似优雅，但有个隐蔽的坑：值域是 $1 \sim 100$ 的整数，直接转十进制字符串会让 `[1,4]` 错误匹配 `"14"`，必须加分隔符编码；且文本总长最坏 $O(n \cdot H)$，配上朴素子串查找依然不便宜。

两条路都能做对，但要么爆量、要么绕远。仔细观察，问题其实只含两个**互相独立**的决策维度，可以直接映射成两个简单递归。

### 3.2 核心观察：起点与匹配是两个正交维度

![核心观察：枚举起点与向下匹配两个正交维度，双递归各管一个](images/wc178_q3_dual_dfs_concept.svg)

把问题拆开看：

- **起点维度**：链表可能从树中**任何节点**开始匹配——「换起点」的枚举恰好就是「遍历每个树节点」的自然递归；
- **匹配维度**：一旦定下起点，匹配过程**只能一路向下**——树指针与链表指针**同步前进**：值相等则各进一步，树先到空或值不等则失败，链表到空则成功，这又是一个天然的递归。

两个维度**正交**：换起点时不关心上次匹配到哪（绝不「续传」），匹配时也不关心其他起点。于是整个算法坍缩成**两个各自只有几行的递归函数**：

$$\text{isSubPath}(v) \;=\; \text{match}(v,\,\text{head}) \;\lor\; \text{isSubPath}(v.\text{left}) \;\lor\; \text{isSubPath}(v.\text{right})$$

而它的代价有硬保证：每对（树节点，链表位置）至多被计算一次（§5 引理 2），总运算量 $O(n \cdot m) \le 2.5 \times 10^5$，毫无压力。

> ⚠️ 反面教材是「贪心携带状态」：DFS 时只带一个「已匹配长度」，失配就重置。这是**错误**的（§8.1 有反例）——失败后的正确重启位置可能在链表中段，朴素重置覆盖不了，这正是 KMP 失配指针要解决的问题。双 DFS 用「每个起点完全重来」换掉了这整个坑，代价（$O(n \cdot m)$）在本题规模下可以忽略。

### 3.3 算法流程：两个递归的分工

![算法流程：主递归枚举起点，匹配递归向下对齐，短路或连接](images/wc178_q3_match_recursion.svg)

**主递归 `isSubPath(v)`（枚举起点）**：

1. $v$ 为空 → 返回 `false`（空树没有路径）；
2. 以 $v$ 为起点调用匹配递归 `match(v, head)`，成功 → 返回 `true`；
3. 否则对左右子树递归 `isSubPath`，任一成功即返回 `true`（`||` 短路）。

**匹配递归 `match(t, l)`（向下对齐）**：

1. $l$ 为空 → 返回 `true`：链表耗尽，此前的值全部对上，**命中**；
2. $t$ 为空，或 $t.\text{val} \ne l.\text{val}$ → 返回 `false`：树先尽或失配；
3. 否则值相等，树、链表各进一步：`match(t.left, l.next) || match(t.right, l.next)`。

### 3.4 示例演算：示例 3 为什么是 false

![示例 3 演算：三条开头对得上的路径全部断裂](images/wc178_q3_example_walkthrough.svg)

以示例 3（`head = [1,4,2,6,8]`）走查所有「开头对得上」的候选路径：

| 候选路径 | 逐位比对 | 结局 |
|----------|----------|------|
| 1→4→2→6（右侧） | $1{=}1,\ 4{=}4,\ 2{=}2,\ 6{=}6$ | 6 是**叶子**，链表还剩 8 → 失败 |
| 1→4→2→8（右侧） | $1{=}1,\ 4{=}4,\ 2{=}2,\ 8{\ne}6$ | 第 4 位失配 → 失败 |
| 1→4→2→1（左侧） | $1{=}1,\ 4{=}4,\ 2{=}2,\ 1{\ne}6$ | 第 4 位失配 → 失败 |

三条候选全部断裂；树中另两个值为 1 的节点（左侧叶子、8 的左孩子）也都是叶子，容纳不下 5 个节点的链表，同样失败，故返回 `false`。对照示例 1：链表换成 `[4,2,8]` 时路径 4→2→8 恰好完整走完，返回 `true`。

## 4. 算法细节

1. **判空顺序**：`match` 里必须**先判 `l` 再判 `t`**。链表恰好在某个真实节点处耗尽时，递归会以 `match(空孩子, null)` 进入——此时 `l == null` 先命中返回 `true` 是**合法命中**；若先判 `t == null` 返回 `false`，会把「链表在叶子上刚好用完」的解误杀。
2. **短路求值**：两处 `||` 都依赖短路——匹配一旦成功、或某棵子树已有答案，后续调用不再展开。
3. **无需记忆化**：状态空间虽然是（树节点 × 链表下标）共 $n \cdot m$ 格，但每格至多被调用**一次**（§5 引理 2，由「树中任意两节点间路径唯一」保证），天然去重，加 `memo` 纯属浪费。
4. **参数设计**：`match` 直接传链表节点指针 `l` 而非下标，无需哈希或下标换算；两个函数都是纯递归，无回溯、无撤销、无额外数据结构。
5. **递归深度**：`isSubPath` 栈深为树高 $H \le n$；`match` 在其上至多再叠 $\min(m, H)$ 层。链状树时总深度约 $n + m \le 2600$，C++ 无压力；Python 注意 §8.5。

## 5. 正确性证明

**引理 1（匹配递归的刻画）**：`match(t, l)` 返回 `true`，当且仅当存在一条以 $t$ 为起点的向下路径（允许长度为 0），其值序列恰好等于 $l$ 起始的链表后缀。

**证明**：对 $l$ 起始后缀的长度 $k$ 归纳。$k = 0$（$l$ 为空）：递归第一步即返回 `true`，而空后缀与长度为 0 的路径（哪怕 $t$ 是递归产生的虚拟空孩子）平凡匹配，两个方向均成立。$k \ge 1$：递归返回 `true` 当且仅当 $t \ne \text{null}$、$t.\text{val} = l.\text{val}$ 且 `match(t.left, l.next) || match(t.right, l.next)`。若 $t = \text{null}$，不存在任何非空向下路径，返回 `false` 正确；若 $t.\text{val} \ne l.\text{val}$，任何从 $t$ 出发的非空路径首值即失配，返回 `false` 正确；否则由归纳假设，`match(t.c, l.next)` 为真 ⟺ 从孩子 $c$ 出发存在匹配 $\text{l.next}$ 后缀的路径，把 $t$ 拼到该路径头部，恰得以 $t$ 为起点、匹配 $l$ 后缀的路径；反之拆掉路径头节点亦归结为归纳假设。∎

**引理 2（每对状态至多算一次）**：将链表节点编号 $l_0 = \text{head}, l_1, \ldots, l_{m-1}$。对任意树节点 $u$ 与下标 $i$，`match(u, l_i)` 至多被调用一次。

**证明**：对 $i$ 归纳。$i = 0$：`match` 的递归调用总是传入 `l.next`（下标 $\ge 1$），故 `match(u, l_0)` 只可能来自 `isSubPath(u)`，而主递归对每个树节点至多调用一次。$i \ge 1$：`match(u, l_i)` 只可能来自某次 `match(parent(u), l_{i-1})` 对其两个孩子的递归（$u$ 是其中之一，且每次父调用至多发起一次，`||` 短路还可能更少）；由归纳假设父调用至多一次，故 `match(u, l_i)` 至多一次。∎

**定理**：`isSubPath` 返回 `true`，当且仅当树中存在匹配整条链表的向下路径。

**证明**：（⇐）设路径 $u \to c_1 \to \cdots \to c_{m-1}$ 匹配链表。主递归遍历每个树节点，必到达 $u$；由引理 1，`match(u, head)` 返回 `true`，短路使 `isSubPath(u)` 为真，并沿调用链向上传播为真。（⇒）对子树大小归纳：`isSubPath(v)` 为真的来源只有两种——`match(v, head)` 为真，由引理 1 存在以 $v$ 为起点的匹配路径；或某个孩子的 `isSubPath` 为真，由归纳假设该子树内存在匹配路径。两种情况都给出整树中的匹配路径。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \cdot m)$。主递归恰好访问 $n$ 个节点各一次；由引理 2，`match` 的总调用次数不超过 $n \cdot m$（更精确地是 $\sum_u \min(m, \text{depth}(u) + 1)$），每次调用 $O(1)$。代入上限 $2500 \times 100 = 2.5 \times 10^5$，毫秒级完成。
- **空间复杂度**：$O(H + m)$，即递归栈——主递归深度为树高 $H \le n = 2500$，匹配递归至多再叠 $m = 100$ 层。除此之外没有任何辅助结构。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isSubPath(ListNode* head, TreeNode* root) {
        if (root == nullptr) return false;
        return match(root, head)
            || isSubPath(head, root->left)
            || isSubPath(head, root->right);
    }

private:
    bool match(TreeNode* t, ListNode* l) {
        if (l == nullptr) return true;
        if (t == nullptr || t->val != l->val) return false;
        return match(t->left, l->next) || match(t->right, l->next);
    }
};
```

### Python

```python
class Solution:
    def isSubPath(self, head: Optional[ListNode], root: Optional[TreeNode]) -> bool:
        if root is None:
            return False
        return (self.match(root, head)
                or self.isSubPath(head, root.left)
                or self.isSubPath(head, root.right))

    def match(self, t: Optional[TreeNode], l: Optional[ListNode]) -> bool:
        if l is None:
            return True
        if t is None or t.val != l.val:
            return False
        return self.match(t.left, l.next) or self.match(t.right, l.next)
```

## 8. 边界情况与易错点

1. **贪心携带「已匹配长度」是错的**：反例——链表 `[1,2,1,2,5]`，树中存在向下路径值序列 `[1,2,1,2,1,2,5]`（其第 3–7 位就是完整匹配，正确答案 `true`）。逐位贪心：前 4 位对上后，第 5 位 $1 \ne 5$ 失配，朴素重置为「已匹配 1」（因为 $1$ 恰等于链表首值），随后 $2$ 接上、$5$ 又接不上，最终误报 `false`。失败后的正确重启位置可能在链表中段——这正是 KMP `next` 数组存在的意义；双 DFS「每个起点完全重来」则彻底绕开此坑。
2. **`match` 判空顺序**：先 `l` 后 `t`。链表恰好在叶节点处耗尽是合法命中；判反了会把这类解误杀（见 §4.1）。
3. **不要在 `match` 里「就地换起点」**：失配后从头再试是主递归的职责。若在匹配递归内部重启，既重复计算，正确性也难以推理。
4. **起点可以是任何节点**：包括叶子（链表长为 1 时，树中出现该值即 `true`）；不要只在根节点匹配，也不要只沿某一条链走。
5. **Python 递归深度**：链状树深 2500 超过默认递归上限（约 1000），本地自测会 `RecursionError`，需 `sys.setrecursionlimit(10**4)` 或改显式栈迭代版；C++ 无此顾虑。
6. **链表比树高更长**：`match` 在树先到空时自然返回 `false`，无需特判；全同值（如全 1）是最坏性能用例，$O(n \cdot m) = 2.5 \times 10^5$ 依然轻松。
7. **走字符串岔路须加分隔符**：若把路径转字符串做子串查找，`[1,4]` 会错误匹配 `"14"`，必须用逗号等分隔符编码。

- [28. 找出字符串中第一个匹配项的下标](https://leetcode.cn/problems/find-the-index-of-the-first-occurrence-in-a-string/)：链表 = 模式串、向下路径 = 文本串，本题即串匹配的「树上推广」；§8.1 的贪心反例正是「不用 KMP 会错」的树上翻版。

**延伸思考**：把链表视作**模式串**、根到叶路径视作**文本串**，可升级为**树上 KMP**——预处理模式的失配数组，DFS 只携带「已匹配长度 $j$」这一个整数状态，每进入一个子节点按值转移（失配沿 `next` 回退），$j = m$ 即命中。状态是单个整数，分叉与回溯时天然可复制，均摊每条边 $O(1)$，总量 $O(n + m)$ 级，同时自动修复 §8.1 的贪心反例。再往后还能换 Aho-Corasick 自动机（多模式匹配）或树哈希（$O(n + m)$ 判定），不过在本题 $n \cdot m \le 2.5 \times 10^5$ 的规模下，双 DFS 的简洁与 KMP 的效率都是满分答案，取舍只在「想多快写完」与「想练多少模板」。
