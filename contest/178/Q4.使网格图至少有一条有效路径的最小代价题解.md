# LeetCode 使网格图至少有一条有效路径的最小代价 题解

## 1. 题目概述

- **标题 / 题号**：使网格图至少有一条有效路径的最小代价（#1368，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-make-at-least-one-valid-path-in-a-grid/
- **来源**：LeetCode 第 178 场周赛 Q4
- **难度**：困难
- **标签**：广度优先搜索、图、数组、矩阵、最短路、Dijkstra 算法、堆（优先队列）、0-1 BFS

**题意**：`m × n` 的网格中，`grid[i][j] ∈ {1,2,3,4}` 表示从该格出发的**唯一**一步方向（1 右、2 左、3 下、4 上），数字可能指向网格外（此时该方向不可走）。你可以花代价 1 把某一格的数字改成**任意**方向，每格最多改一次。求最小的总代价，使得从 `(0,0)` 出发、每步都沿当前格数字所指方向走，能到达 `(m-1,n-1)`；`(0,0)` 与 `(m-1,n-1)` 可以重合。路径不必最短，也允许重复经过格子。

**约束**：

- $1 \le m, n \le 100$，格数至多 $10^4$
- $grid[i][j] \in \{1,2,3,4\}$，可能指向界外
- 修改只影响「**离开**这一格」的方向；到达终点后不再移动，故**终点的箭头无关**
- 每格至多改一次；最优路径可假定为简单路径，故该限制不构成额外难点（见 §5 引理 1 与 §3.2 的说明）

## 2. 示例

**示例 1**

```text
输入：grid = [[1,1,1,1],[2,2,2,2],[1,1,1,1],[2,2,2,2]]
输出：3
解释：第 0、2 行全指向右，第 1、3 行全指向左，只能「右到底 → 下一行 → 左到底」蛇形前进；
      需要在 (0,3)、(1,0)、(2,3) 三处把方向改成「下」，总代价 3。
```

**示例 2**

```text
输入：grid = [[1,1,3],[3,2,2],[1,1,4]]
输出：0
解释：(0,0)→(0,1)→(0,2)→(1,2)→(2,2)，全程顺箭头，无需修改。
```

**示例 3**

```text
输入：grid = [[1,2],[4,3]]
输出：1
解释：顺箭头 (0,0)→(0,1)，再把 (0,1) 的 2 改成 3（向下）即可到 (1,1)；
      而 0 代价只能走到 (0,1)、(1,0) 这两个「死胡同」，所以下界也是 1。
```

**示例 4**

```text
输入：grid = [[2,2,2],[2,2,2]]
输出：3
解释：所有格子都指向左，最左列再往左就越界；从 (0,0) 到 (1,2) 至少要「下、右、右」三步，
      每一步出发格都不是右/下方向，故至少改 3 次，且 3 次足够。
```

> 另有极小用例 `grid = [[4]]`：起点即终点，答案为 `0`，见 §8.1。

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**枚举修改哪些格子**：子集共 $2^{mn}$ 个，对每个子集再花 $O(mn)$ 验证是否存在有效路径，$m=n=100$ 时是天文数字，完全不可行。

稍微聪明一点：注意到「改格子」之间互不影响，问题其实是「**从起点走到终点，每走一步要么免费（顺箭头）要么付 1（改方向）**」。一旦这样看，指数枚举就没有必要了——它是一张**带权有向图上的最短路**。

### 3.2 核心观察：0/1 边权的最短路

![把改方向翻译成 0/1 边权：顺箭头 0，其余方向 1](images/wc178_q4_weighted_edges.svg)

**建图**：每个格子是一个节点。对格子 $u=(i,j)$ 的四个相邻格 $v$，建一条有向边 $u \to v$（越界的方向不建边），边权为

$$w(u,v) = \begin{cases} 0, & \text{grid}[i][j] \text{ 正好指向 } v \\ 1, & \text{否则（需要把 } u \text{ 改成指向 } v）\end{cases}$$

于是：

- 一条从 $(0,0)$ 到 $(m-1,n-1)$ 的路径，其**边权和**恰好等于「路径上离开方向与 grid 不符」的格子个数，也就是需要的修改次数；
- 反过来，任何一套使网格存在有效路径的修改方案，都对应一条边权和不超过修改次数的路径。

所以**答案就是这张图上从 $(0,0)$ 到 $(m-1,n-1)$ 的最短路径长度**。两个容易忽略的细节：

1. 代价记在「**离开**的格子」上，而不是「进入的格子」——终点的箭头永远不参与计算（示例 1 的终点指向左，答案仍是 3）；
2. 边权只有 $0$ 和 $1$，不需要堆：**0-1 BFS** 用一个双端队列就能做到 $O(mn)$。

> 💡 为什么「每格只能改一次」不会带来麻烦？因为所有边权非负，最短路一定可以取成**简单路径**（不重复经过格子），此时每个格子只被离开一次，一套修改方向与路径一一对应。若一条路径重复经过某格却想用两个不同方向离开，那本来就需要改这个格子两次，而题面禁止——但这样的走法绝不会比简单路径更优，可以直接不考虑。

### 3.3 算法流程：0-1 BFS

![0-1 BFS：0 权边入队首、1 权边入队尾，出队即定型](images/wc178_q4_zero_one_bfs.svg)

1. `dist` 全部初始化为 $+\infty$，`dist[0][0] = 0`；双端队列中放入 $(0,0)$；
2. 每次**从队首**取出 $u$，若 $u$ 已定型则跳过，否则标记 $u$ 定型；
3. 枚举 $u$ 的四个相邻格 $v$：越界则跳过；令 $w = 0$ 当且仅当 `grid[u]` 恰指向 $v$；若 `dist[u] + w < dist[v]`，更新 `dist[v]`，并把 $v$ **压入队首**（$w=0$）或**压入队尾**（$w=1$）；
4. 队列为空时，`dist[m-1][n-1]` 即答案。

关键在于**队列的单调性**：任意时刻，双端队列中的 `dist` 从队首到队尾**非降，且至多取两个相邻的值** $d$ 与 $d+1$。因此从队首弹出的点，其距离已经不可能再被改进，与 Dijkstra 的「出堆即定型」完全同构，只是把堆换成了双端队列，代价从 $O(\log(mn))$ 降到 $O(1)$。

> 若不想专门写 0-1 BFS，用 `priority_queue` 跑 Dijkstra 也完全正确，复杂度 $O(mn \log(mn))$；再退一步，还可以按「代价层」做集合 BFS（第 $k$ 层 = 用不超过 $k$ 次修改可达的格子集合），最多 $m+n-1$ 层、每层 $O(mn)$，也能过题但更慢。

### 3.4 示例演算

![示例 1 演算：dist[i][j] = i，答案 3](images/wc178_q4_example_walkthrough.svg)

对示例 1 跑 0-1 BFS，四行恰好对应四个距离层（同一行内方向一致，行内移动全部免费）：

| 层 $k$ | 可达格子 | 到达方式 |
|--------|----------|----------|
| 0 | 第 0 行全部 | 全指向右，一路顺箭头 |
| 1 | 第 1 行全部 | 在 $(0,3)$ 改成「下」，进入 $(1,3)$ 后全行指向左，免费走到 $(1,0)$ |
| 2 | 第 2 行全部 | 在 $(1,0)$ 改成「下」，进入 $(2,0)$ 后全行指向右，免费走到 $(2,3)$ |
| 3 | 第 3 行全部 | 在 $(2,3)$ 改成「下」进入 $(3,3)$（终点），到达即结束 |

即 `dist[i][j] = i`，答案是 `dist[3][3] = 3`。三个需要修改的格子是 $(0,3)$、$(1,0)$、$(2,3)$，正好三次。

再看示例 3（`[[1,2],[4,3]]`）：$k=0$ 层从 $(0,0)$ 出发，顺箭头只能走 $(0,0) \to (0,1)$ 与 $(1,0) \to (0,0)$，故 $k=0$ 可达集合是 $\{(0,0),(0,1),(1,0)\}$，不含终点；$k=1$ 层从 $(0,1)$ 向下即达 $(1,1)$，答案为 $1$。这也说明 0 权边构成的环（$(0,0) \leftrightarrow (0,1)$）不会让 BFS 死循环，`dist` 判优保证每个格子至多定型一次。

## 4. 算法细节

1. **方向数组与编码对齐**：取 `dirs = [(0,1), (0,-1), (1,0), (-1,0)]`，下标 $k=0..3$ 对应 grid 编码 $k+1$（右、左、下、上），于是边权可写成一行：`w = (grid[i][j] == k + 1) ? 0 : 1`。写错映射是本题最常见的 WA 来源。
2. **用出发格判方向**：松弛 $u \to v$ 时看的是 `grid[u]`，绝不能看 `grid[v]`。代价属于「离开 $u$」这一步。
3. **出队才定型**：用 `done` 数组在**弹出队首时**标记，入队时不标记。0-1 BFS 中一个点可能被多次改进、多次入队，只有第一次弹出时的距离才是最终值。
4. **入队条件是严格改进**：`nd < dist[v]` 才更新并入队；`nd == dist[v]` 时不必入队，否则队列会无谓膨胀。
5. **越界方向直接跳过**：题面明确允许数字指向网格外，这类边在图中不存在；不要为了「凑四个方向」而给越界边赋权。
6. **`INF` 取足够大**：答案上界是 $m+n-2 \le 198$（只走右/下的单调路径，每步最多改一次），`1e9` 足够，且 `dist[u] + w` 不会溢出。
7. **可以提前返回**：当弹出的队首恰为 $(m-1,n-1)$ 时直接返回它的 `dist`，语义与「跑完再取」一致，能省一点常数。

## 5. 正确性证明

**引理 1（路径代价 = 修改次数）**：设 $P$ 是从 $(0,0)$ 到 $(m-1,n-1)$ 的任意一条简单路径，则 $c(P)=\sum_{e \in P} w(e)$ 等于「使 $P$ 成为有效路径」所需修改的格子数；且任何使某条路径 $Q$ 有效的修改方案的代价不小于 $c(Q)$。

**证明**：前半：对 $P$ 上每个「离开方向与 `grid` 不同」的格子，把它改成该离开方向，其余格子不动。每格只离开一次，故修改次数恰为 $P$ 中权为 1 的边数，即 $c(P)$，改完 $P$ 上每一步都顺箭头，$P$ 有效。
后半：设修改集合为 $S$，路径 $Q$ 在 $S$ 下有效。$Q$ 中每一步从某格 $u$ 离开、走向 $v$；若该步方向与 `grid[u]` 不同，则 $u$ 必须已被修改，即 $u \in S$，这一步的边权为 1。把「权为 1 的步」映射到它的出发格；当 $Q$ 为简单路径时该映射是单射，一般地出发格可能被重复计数，故 $c(Q) \le |S|$。∎

**引理 2（出队即定型）**：在 0-1 BFS 执行过程中，双端队列内各点的 `dist` 从队首到队尾非降，且至多取两个相邻的整数值；并且每次从队首弹出的点 $u$，其 `dist[u]` 已等于最短距离。

**证明**：单调性与「至多两值」对操作次数归纳。初始队列只有起点，距离为 0，成立。设当前队首距离为 $d$，则队列中所有值属于 $\{d, d+1\}$。弹出队首后，剩余值仍属于 $\{d, d+1\}$；松弛 $0$ 权边得到的新值 $d$ 压入队首，队列仍非降且值域为 $\{d,d+1\}$；松弛 $1$ 权边得到 $d+1$ 压入队尾，值域仍是 $\{d,d+1\}$，非降性保持。
定型性用 Dijkstra 的截断论证。先注意两点：任何 `dist` 被减小的点都必然在队列里（只有定型操作会把点从队列里移走）；而队列非降，所以**队首的点就是所有未定型点中 `dist` 最小的**。设 $u$ 被弹出，$P^*$ 是到 $u$ 的最短路，取 $P^*$ 上第一个未定型点 $x$，其前驱 $p$ 已定型。$p$ 定型时松弛过边 $(p,x)$，故 $\text{dist}[x] \le \text{dist}[p] + w(p,x) = P^*$ 上到 $x$ 的前缀长度 $\le \text{dist}^*(u)$；由「队首最小」又有 $\text{dist}[u] \le \text{dist}[x]$。结合 $\text{dist}[u] \ge \text{dist}^*(u)$（`dist` 始终是某条实际路径的长度），得 $\text{dist}[u] = \text{dist}^*(u)$。此后 $u$ 的距离不会再被改进：若某次松弛给出更小的值，说明存在更短路径，与 $\text{dist}[u]$ 已是最短距离矛盾。∎

**定理**：算法返回的值等于使网格至少存在一条有效路径的最小代价。

**证明**：由引理 1，任一修改方案 $S$ 对应一条权和不大于 $|S|$ 的路径，故最短路长 $\le$ 最小代价；反之任一简单路径 $P$ 按引理 1 前半构造出的修改方案代价恰为 $c(P)$，故最小代价 $\le$ 最短路长。又因为所有边权非负，任一 walk 去掉环后得到权和不增的简单路径，所以「最短路」可只在简单路径上取到。两侧夹逼得最小代价 = 最短路长。由引理 2，0-1 BFS 结束时 `dist[m-1][n-1]` 就是最短路长，故算法输出正确。∎

## 6. 复杂度分析

- **时间**：$O(mn)$。每个格子最多定型一次；定型时检查 4 条出边，共 $4mn$ 次 $O(1)$ 松弛；每次成功松弛至多入队一次，故双端队列操作总数 $O(mn)$，全部为 $O(1)$。
- **空间**：$O(mn)$。`dist` 与 `done` 各 $mn$，双端队列最坏同时存 $O(mn)$ 个下标。相比 Dijkstra 省掉了堆的 $O(\log(mn))$ 因子。

## 7. 参考代码

### C++

```cpp
#include <deque>
#include <utility>
#include <vector>
using namespace std;

class Solution {
public:
    int minCost(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        const int INF = 1e9;
        vector<vector<int>> dist(m, vector<int>(n, INF));
        vector<vector<char>> done(m, vector<char>(n, 0));
        deque<pair<int, int>> dq;

        // 下标 0..3 对应 grid 编码 1..4：右、左、下、上
        const int di[4] = {0, 0, 1, -1};
        const int dj[4] = {1, -1, 0, 0};

        dist[0][0] = 0;
        dq.push_front({0, 0});

        while (!dq.empty()) {
            auto [i, j] = dq.front();
            dq.pop_front();
            if (done[i][j]) continue;
            done[i][j] = 1;

            for (int k = 0; k < 4; k++) {
                int x = i + di[k], y = j + dj[k];
                if (x < 0 || x >= m || y < 0 || y >= n) continue;
                int w = (grid[i][j] == k + 1) ? 0 : 1;  // 顺箭头免费，否则改一次
                int nd = dist[i][j] + w;
                if (nd < dist[x][y]) {
                    dist[x][y] = nd;
                    if (w == 0) dq.push_front({x, y});
                    else dq.push_back({x, y});
                }
            }
        }
        return dist[m - 1][n - 1];
    }
};
```

### Python

```python
from collections import deque
from typing import List


class Solution:
    def minCost(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])
        INF = 10 ** 9
        dist = [[INF] * n for _ in range(m)]
        done = [[False] * n for _ in range(m)]
        # 下标 1..4 与 grid 编码一一对应：1 右、2 左、3 下、4 上
        dirs = [(0, 1), (0, -1), (1, 0), (-1, 0)]

        dist[0][0] = 0
        dq = deque([(0, 0)])
        while dq:
            i, j = dq.popleft()
            if done[i][j]:
                continue
            done[i][j] = True
            d = dist[i][j]
            for k, (di, dj) in enumerate(dirs, start=1):
                x, y = i + di, j + dj
                if not (0 <= x < m and 0 <= y < n):
                    continue
                w = 0 if grid[i][j] == k else 1
                nd = d + w
                if nd < dist[x][y]:
                    dist[x][y] = nd
                    if w == 0:
                        dq.appendleft((x, y))
                    else:
                        dq.append((x, y))
        return dist[m - 1][n - 1]
```

## 8. 边界情况与易错点

1. **$1 \times 1$ 网格**：起点即终点，答案应为 `0`。若把「起点格本身也要改方向」或「终点的箭头」计入代价，`[[4]]` 会错答成 `1`。
2. **终点箭头无关**：示例 1 的 $(3,3)$ 是 `2`（指向左），答案仍是 3。BFS 中松弛用的是出发格 `grid[i][j]`，天然满足这一点；若把方向判定挪到目的格（看 `grid[v]` 是否指回 `u`），代价就被算到「进入」而非「离开」上，答案会错：示例 2 从 0 变 1，示例 4 从 3 变 1。
3. **入队时不要标记 `done`**：0-1 BFS 允许同一格被更优距离再次入队。反例 `grid = [[1,1,1],[1,4,1],[3,2,3],[1,2,3]]`：`(3,2)` 先经 `(3,1)` 以距离 3 入队，随后 `(2,2)` 用 0 权边把它改进为 2；若在 `push` 时就标 `visited`，这次改进会被丢弃，答案错成 3（正确为 2）。
4. **方向映射写反**：`dirs` 的下标必须与 `grid` 编码 1..4 对齐（右、左、下、上）。写成「上下左右」会让示例 2 的 0 代价路径消失，答案从 0 变成 3。
5. **全指向左的网格**（如 `[[2,2,2],[2,2,2]]`）：0 权边把人往界外推，必须依赖 1 权边才能前进；这类输入最能暴露「只把 0 权边入队」的实现错误（会直接死循环或漏解）。
6. **单行 / 单列**：`m=1` 时只需看右/左两个方向，`n=1` 时只需看下/上；越界判断要同时覆盖 `x,y` 两个维度，漏一个会越界访问。
7. **`dist[u] + w` 的溢出**：`INF = 1e9` 加 1 不会溢出 `int`，但不要在 `INF` 上再累加多轮（本题只加一次，安全）。
8. **重复入队不影响复杂度**：只有成功松弛才入队，入队次数是 $O(mn)$ 级；同一格即使被多次入队，出队时的 `done` 判重也保证它只展开一次，总代价保持线性。

**延伸思考**：若每格修改代价改为任意非负整数 $c[i][j]$（不同格子价格不同），0-1 BFS 不再适用，需回到 Dijkstra 的堆，复杂度 $O(mn \log(mn))$；若要求输出具体修改方案，则在松弛成功时记录前驱，最后沿前驱回溯即可。若把问题改成「恰好修改 $k$ 次」，则要把状态扩成 $(i, j, \text{已改次数})$ 做分层 BFS；若改成「一次修改可以把一整行/一整列的方向统一改掉」，最短路模型失效，需要重新设计状态——这类「先建模、再选最短路算法」的套路，正是本题最值得迁移的部分。
