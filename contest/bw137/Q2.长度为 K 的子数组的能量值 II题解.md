# LeetCode 长度为 K 的子数组的能量值 II 题解

## 1. 题目概述

- **标题 / 题号**：长度为 K 的子数组的能量值 II（#3255，medium）
- **链接**：https://leetcode.cn/problems/find-the-power-of-k-size-subarrays-ii/
- **来源**：LeetCode 第 137 场双周赛 Q2
- **难度**：中等
- **标签**：数组、滑动窗口

**题意**：与同场 Q1 的判据完全相同——长度为 $k$ 的子数组若所有元素**依次连续且上升**（$nums[j] + 1 = nums[j+1]$），能量值为其中的**最大元素**，否则为 $-1$；要求返回全部 $n-k+1$ 个窗口的能量值。

区别只在数据范围：本题 $n \le 10^5$，Q1 的 $O(n^2)$ 逐窗口检查会超时，需要把"每个窗口重新判定"改造成"一次扫描复用历史信息"。

**约束**：

- $1 \le n = nums.length \le 10^5$
- $1 \le nums[i] \le 10^6$
- $1 \le k \le n$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,3,2,5], k = 3
输出：[3,4,-1,-1,-1]
解释：[1,2,3] → 3，[2,3,4] → 4，其余三个窗口都含断点 → -1。
```

**示例 2**

```text
输入：nums = [2,2,2,2,2], k = 4
输出：[-1,-1]
解释：相邻差恒为 0，不存在长度为 4 的连续上升窗口。
```

**示例 3**

```text
输入：nums = [3,2,3,2,3,2], k = 2
输出：[-1,3,-1,3,-1]
解释：只有 [2,3] 这种恰为 +1 的窗口合法，能量值为 3。
```

## 3. 解题思路

### 3.1 暴力思路

沿用 Q1：对每个窗口扫一遍相邻对，时间 $O\big((n-k+1)k\big) \le O(n^2)$。$n = 10^5$ 时最坏切到 $10^{10}$ 次比较，必然超时。需要避免"窗口之间重复检查"。

### 3.2 核心观察：以每个位置结尾的连续递增段长度

![run 数组：接续加一、断点重置](images/bw137_q2_runlen_model.svg)

定义 $run[i]$ 为**以 $i$ 结尾的最长"逐个 $+1$ 递增段"的长度**，则

$$run[i] = \begin{cases} run[i-1] + 1, & nums[i] = nums[i-1] + 1 \\ 1, & \text{否则} \end{cases}$$

关键在于：**窗口 $[i-k+1, i]$ 合法 $\iff run[i] \ge k$**。因为 $run[i] \ge k$ 说明 $i-k+1, \dots, i$ 这一整段都满足相邻差为 $+1$；反之若窗口合法，则该段（长度为 $k$）本身就落在以 $i$ 结尾的递增段内，故 $run[i] \ge k$。

合法时能量值就是 $nums[i]$（理由同 Q1：严格递增，末元素即最大元素），于是每个窗口只需 $O(1)$ 判定。

### 3.3 算法流程

![一次扫描：边更新 run 边输出](images/bw137_q2_flow.svg)

```text
1. run = 1，results = 空数组
2. for i = 0 .. n - 1:
       if i > 0:
           run = (nums[i] == nums[i-1] + 1) ? run + 1 : 1
       if i >= k - 1:
           results 追加 (run >= k ? nums[i] : -1)
3. 返回 results
```

注意 $run$ 的值本身就携带了"最近一次断点在哪里"的信息：断点之后的第 $t$ 个元素 $run = t$，于是"以 $i$ 结尾、长度 $k$ 的窗口是否跨过断点"被压缩成一个整数比较。

### 3.4 示例演算

![示例走查：run 与输出同步推进](images/bw137_q2_walkthrough.svg)

对示例 1 的 `nums = [1,2,3,4,3,2,5]`、`k = 3`：

| i | nums[i] | 是否接续 $nums[i-1]+1$ | run[i] | 输出 |
|---|---------|----------------------|--------|------|
| 0 | 1 | 起点 | 1 | — |
| 1 | 2 | 是 | 2 | — |
| 2 | 3 | 是 | 3 | 3 |
| 3 | 4 | 是 | 4 | 4 |
| 4 | 3 | 否（$3 \ne 5$） | 1 | −1 |
| 5 | 2 | 否（$2 \ne 4$） | 1 | −1 |
| 6 | 5 | 否（$5 \ne 3$） | 1 | −1 |

输出 `[3, 4, -1, -1, -1]`，与示例一致。

## 4. 算法细节

1. **`run` 的初值与更新位置**：初始化为 $1$（单个元素自成一段），在 $i \ge 1$ 时先更新、再用它判定，保证 $run[i]$ 已包含 $nums[i]$。
2. **输出时机**：只有 $i \ge k-1$ 才开始输出，这样恰好产出 $n-k+1$ 个结果，且每个结果的窗口起点是 $i-k+1$。
3. **不需要额外数组**：只保留"上一个 $run$"这一个整数，空间 $O(1)$；若保留整个 $run$ 数组也可以，但无必要。
4. **判定用 `>=` 而非 `==`**：$run[i] > k$ 表示窗口落在更长递增段的尾部，同样合法。
5. **首元素不参与断点判断**：$i = 0$ 时不存在 $nums[i-1]$，必须跳过更新，否则会访问下标 $-1$。

## 5. 正确性证明

**引理 1（run 的语义）**：对每个 $i$，$run[i]$ 等于最大的 $t \le i+1$，使得区间 $[i-t+1, i]$ 内所有相邻差均为 $+1$（即最长的合法后缀长度）。

**证明**：对 $i$ 归纳。$i = 0$ 时单个元素没有相邻对，最长合法后缀长度为 $1 = run[0]$。设对 $i-1$ 成立：若 $nums[i] = nums[i-1] + 1$，则以 $i$ 结尾的合法后缀可以接上以 $i-1$ 结尾的最长合法后缀，长度恰为 $run[i-1] + 1$，不可能更长（否则去掉末元素会得到比 $run[i-1]$ 更长的、以 $i-1$ 结尾的合法后缀，矛盾）；若 $nums[i] \ne nums[i-1] + 1$，则任何长度 $\ge 2$ 的后缀都包含这个断点，故最长合法后缀长度为 $1$。两种情况都与转移式一致。∎

**引理 2（窗口判定的等价性）**：窗口 $[i-k+1, i]$ 合法 $\iff run[i] \ge k$。

**证明**：由引理 1，$run[i] \ge k$ 等价于区间 $[i-k+1, i]$ 内所有相邻差都是 $+1$，这正是题目对合法窗口的定义（窗口内相邻差全为 $+1$）；反之若窗口合法，则区间内相邻差全为 $+1$，说明以 $i$ 结尾的合法后缀长度至少为 $k$，即 $run[i] \ge k$。∎

**引理 3（合法窗口的最大值）**：若窗口 $[i-k+1, i]$ 合法，则 $nums[i]$ 是窗口内最大元素。

**证明**：由引理 2，窗口内相邻差恒为 $+1$，故 $nums[i-k+1] < nums[i-k+2] < \dots < nums[i]$，末元素严格最大。∎

**定理**：算法输出数组的第 $i-k+1$ 项等于子数组 $nums[i-k+1..i]$ 的能量值。

**证明**：当算法处理到下标 $i \ge k-1$ 时，由归纳与引理 1，$run[i]$ 已正确计算。若 $run[i] \ge k$，由引理 2 窗口合法，算法输出 $nums[i]$，由引理 3 它等于窗口最大值，符合能量值定义；若 $run[i] < k$，由引理 2 窗口不合法，算法输出 $-1$，同样符合定义。算法对每个 $i \ge k-1$ 输出一次，共 $n-k+1$ 项，覆盖全部窗口。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个下标恰好被处理一次，$run$ 的更新与输出判定均为 $O(1)$；相比 Q1 的 $O(n^2)$ 把"窗口内的重复检查"全部摊还掉了。
- **空间**：$O(1)$ 额外空间（不含长度 $n-k+1$ 的输出数组）。若显式保存 $run$ 数组则为 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> resultsArray(vector<int>& nums, int k) {
        int n = (int)nums.size();
        vector<int> res;
        int run = 1;
        for (int i = 0; i < n; i++) {
            if (i > 0) run = (nums[i] == nums[i - 1] + 1) ? run + 1 : 1;
            if (i >= k - 1) res.push_back(run >= k ? nums[i] : -1);
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def resultsArray(self, nums: list[int], k: int) -> list[int]:
        res = []
        run = 1
        for i, x in enumerate(nums):
            if i:
                run = run + 1 if x == nums[i - 1] + 1 else 1
            if i >= k - 1:
                res.append(x if run >= k else -1)
        return res
```

## 8. 边界情况与易错点

1. **`k == 1`**：所有窗口合法，`run >= 1` 恒成立，输出原数组。
2. **断点紧邻窗口起点**：如 `nums = [5,1,2,3]`、`k = 2`，$run[2] = 3$ 表示 $[1,2,3]$ 是合法段，窗口 $[2,3]$ 合法而 $[5,1]$ 不合法——用 $run[i] \ge k$ 一次比较即可区分。
3. **$i = 0$ 时不要访问 `nums[-1]`**：C++ 中这是未定义行为，Python 中会取到末元素造成隐蔽错误。
4. **输出个数**：必须是 $n-k+1$，`i >= k - 1` 这个条件不能写成 `i > k - 1`。
5. **不要把 `run` 写成"当前窗口内相邻差个数"**：那样又退化成逐窗口检查；`run` 必须跨窗口延续。
6. **大值域**：$nums[i] \le 10^6$，只做加一与比较，不会溢出；若题目要求输出和值则需 `long long`。
7. **与 Q1 的差异**：两题判据完全相同，唯一区别是 $n$ 的范围；I 版直接暴力即可，II 版必须 $O(n)$，不要交错了版本。

**延伸思考**：本题的 $run[i]$ 只回答了"最长合法后缀"，若把条件改成"窗口内相邻差绝对值不超过 $d$"，则断点判定变为 $|nums[i] - nums[i-1]| \le d$，$run$ 的转移形式不变，仍是 $O(n)$。可见这类题的核心不是"窗口"而是"**可延续性**"：只要约束能用一个标量刻画"从某个断点之后一直成立"，就能压成一次扫描。
