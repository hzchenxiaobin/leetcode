# LeetCode 构成整天的下标对数目 I 题解

## 1. 题目概述

- **标题 / 题号**：构成整天的下标对数目 I（#3184，easy）
- **链接**：https://leetcode.cn/problems/count-pairs-that-form-a-complete-day-i/
- **来源**：LeetCode 第 402 场周赛 Q1
- **难度**：简单
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `hours`，每个元素表示一段以小时为单位的时间。统计满足 $i < j$ 且 $hours[i] + hours[j]$ 是 $24$ 的整数倍（即构成**整天**）的下标对 $(i, j)$ 的数目。

**约束**：

- $1 \le hours.length \le 100$
- $1 \le hours[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：hours = [12,12,30,24,24]
输出：2
解释：构成整天的下标对是 (0, 1) 和 (3, 4)。
      12 + 12 = 24，24 + 24 = 48 = 2 × 24。
```

**示例 2**

```text
输入：hours = [72,48,24,3]
输出：3
解释：构成整天的下标对是 (0, 1)、(0, 2) 和 (1, 2)。
      72 + 48 = 120 = 5 × 24，72 + 24 = 96 = 4 × 24，48 + 24 = 72 = 3 × 24。
```

**示例 3（边界）**

```text
输入：hours = [13, 11]
输出：1
解释：13 + 11 = 24，恰好一个整天。注意 11 并不等于 24 − 13 的"原数"，
      但余数 13 mod 24 = 13 与 11 mod 24 = 11 相加恰为 24。
```

## 3. 解题思路

### 3.1 暴力思路

双重循环枚举所有下标对 $(i, j)$（$i < j$），判断 $(hours[i] + hours[j]) \bmod 24$ 是否为 $0$：

```python
ans = 0
for i in range(len(hours)):
    for j in range(i + 1, len(hours)):
        if (hours[i] + hours[j]) % 24 == 0:
            ans += 1
```

- 时间复杂度 $O(n^2)$，空间 $O(1)$。
- 本题 $n \le 100$，最多 $\binom{100}{2} = 4950$ 对，**暴力完全可以通过**——比赛现场直接写暴力是最快的签到方式。
- 但同场的 Q2（#3185）是本题的加强版（$n$ 放大到 $10^5$），$O(n^2)$ 会达到 $10^{10}$ 次判断而超时。既然 $O(n)$ 写法只多花两分钟，签到时就值得直接写优化版。

### 3.2 核心观察：mod 24 余数配对 + 计数

![核心观察：余数配对](images/complete_day_mod_pairing.svg)

**两个数之和是 24 的倍数，只取决于它们除以 24 的余数**：

$$24 \mid (a + b) \iff (a \bmod 24 + b \bmod 24) \bmod 24 = 0$$

由于 $a \bmod 24,\ b \bmod 24 \in [0, 23]$，余数之和落在 $[0, 46]$ 内，模 24 为 0 只有两种可能：

- 两余数之和为 $24$：即余数 $r$ 与**互补余数** $24 - r$ 配对（如 $12 \leftrightarrow 12$、$6 \leftrightarrow 18$）；
- 两余数之和为 $0$：即两者余数均为 $0$（$0 \leftrightarrow 0$，自配）。

于是问题转化为：**统计余数互补的元素对个数**。余数只有 $0 \sim 23$ 共 24 种，用一个长度为 24 的计数数组即可。

### 3.3 算法流程：单趟遍历

![单趟遍历流程](images/complete_day_one_pass_flow.svg)

从左到右遍历数组，维护计数数组 `cnt[0..23]`（初始全 0）与答案 `ans`。处理到下标 $j$、元素 $h = hours[j]$ 时：

1. 计算 $r = h \bmod 24$；
2. `ans += cnt[(24 − r) mod 24]`——左边（下标 $< j$）有多少个余数互补的元素，就新增多少对；
3. `cnt[r] += 1`——把当前元素记入余数表，供后续元素配对。

**先查后记**的顺序天然保证了 $i < j$：处理 $j$ 时 `cnt` 里只装着下标更小的元素，不会把 $j$ 自己或右边的元素算进去。

### 3.4 示例演算

![示例走查](images/complete_day_walkthrough.svg)

以 `hours = [12, 12, 30, 24, 24]` 为例：

| $j$ | $hours[j]$ | $r$ | 查 $cnt[(24-r) \bmod 24]$ | $ans$ | 更新后 $cnt$ |
|-----|-----------|-----|--------------------------|-------|--------------|
| 0 | 12 | 12 | $cnt[12] = 0$ | 0 | $\{12{:}1\}$ |
| 1 | 12 | 12 | $cnt[12] = 1 \Rightarrow +1$ | 1 | $\{12{:}2\}$ |
| 2 | 30 | 6 | $cnt[18] = 0$ | 1 | $\{12{:}2,\ 6{:}1\}$ |
| 3 | 24 | 0 | $cnt[0] = 0$ | 1 | $\{12{:}2,\ 6{:}1,\ 0{:}1\}$ |
| 4 | 24 | 0 | $cnt[0] = 1 \Rightarrow +1$ | 2 | $\{12{:}2,\ 6{:}1,\ 0{:}2\}$ |

最终 $ans = 2$，对应下标对 $(0, 1)$ 与 $(3, 4)$，与示例一致。

## 4. 算法细节

1. **同余转化**：判断"和是 24 的倍数"不需要真的算出和，只需比较两余数。$hours[i]$ 可达 $10^9$，但余数永远在 $[0, 23]$，与数值大小无关。
2. **互补余数统一公式**：$(24 - r) \bmod 24$。当 $r = 0$ 时结果是 $0$（自配），当 $r \in [1, 23]$ 时结果是 $24 - r$，无需分类讨论，也避免了 $r = 0$ 时下标越界到 24。
3. **先查后记**：第 2、3 步顺序不能颠倒。若先 `cnt[r]++` 再查询，当 $r$ 的互补余数恰好等于 $r$（即 $r = 0$ 或 $r = 12$）时会把元素和自己配成一对，多算。
4. **数据结构选择**：余数值域只有 24，用定长数组比哈希表更快更省事；若模数很大（如延伸到任意 $k$），换成 `unordered_map` / `dict` 即可。
5. **答案类型**：本题 $n \le 100$，答案上限 $\binom{100}{2} = 4950$，接口返回 `int` 足够；Q2 加强版 $n \le 10^5$ 时答案可达约 $5 \times 10^9$，必须用 `long long`。

## 5. 正确性证明

**引理 1**：对任意非负整数 $a$、$b$，$24 \mid (a + b)$ 当且仅当 $(a \bmod 24 + b \bmod 24) \bmod 24 = 0$。

**证明**：由同余的基本性质，$a \equiv a \bmod 24$、$b \equiv b \bmod 24 \pmod{24}$，故
$$a + b \equiv (a \bmod 24) + (b \bmod 24) \pmod{24}.$$
于是 $24 \mid (a+b) \iff $ 右侧两余数之和 $\equiv 0 \pmod{24}$。∎

**引理 2**：算法处理下标 $j$ 时，`cnt[(24−r_j) mod 24]` 恰等于满足 $i < j$ 且 $hours[i] + hours[j]$ 构成整天的下标 $i$ 的个数。

**证明**：处理 $j$ 之前，`cnt` 只被下标 $< j$ 的元素更新，每次 `cnt[r]++` 恰对应一个左侧元素，故 `cnt[r]` 等于左侧余数为 $r$ 的元素个数。由引理 1，左侧元素 $i$ 与 $j$ 构成整天 $\iff$ $r_i \equiv -r_j \pmod{24}$，而 $[0, 23]$ 内满足该同余的余数唯一，即 $(24 - r_j) \bmod 24$。因此查询结果恰为所求个数。∎

**定理**：算法返回值等于满足 $i < j$ 且构成整天的下标对总数。

**证明**：对每个合法对 $(i, j)$，由引理 2，它恰在处理 $j$ 时被统计一次（$i$ 在左侧）；由 $i < j$ 严格小于，任何非法对（$i \ge j$、或不互补）都不会被统计——$j$ 自身尚未记入 `cnt`，右侧元素尚未遍历。所有合法对不重不漏各计一次，求和即得返回值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素做一次取模、一次数组查询、一次计数更新，均为 $O(1)$。
- **空间复杂度**：$O(24) = O(1)$。仅使用一个长度为 24 的计数数组和常数个变量。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countCompleteDayPairs(vector<int>& hours) {
        int cnt[24] = {0};
        int ans = 0;
        for (int h : hours) {
            int r = h % 24;
            ans += cnt[(24 - r) % 24];
            cnt[r]++;
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countCompleteDayPairs(self, hours: List[int]) -> int:
        cnt = [0] * 24
        ans = 0
        for h in hours:
            r = h % 24
            ans += cnt[(24 - r) % 24]
            cnt[r] += 1
        return ans
```

## 8. 边界情况与易错点

1. **$r = 0$ 的互补余数是 0 而不是 24**：必须写 $(24 - r) \bmod 24$。若直接写 `cnt[24 - r]`，$r = 0$ 时下标 24 越界（C++ 中是未定义行为）。
2. **先查后记不能颠倒**：$r = 0$ 或 $r = 12$ 时互补余数等于自身，先记后查会把元素与自己配对，多算（例如单个 24 会凭空产生一对）。
3. **$n = 1$ 答案为 0**：单个元素无配对，算法自然给出 0，无需特判。
4. **求和接近 int 上限但不越界**：暴力写法中 $hours[i] + hours[j]$ 最大 $2 \times 10^9$，仍小于 `INT_MAX`（约 $2.147 \times 10^9$），勉强安全；但养成"先取模再相加"的习惯更稳妥，且是 $O(n)$ 解法的必经之路。
5. **别把"互补"理解成数值互补**：$13$ 与 $11$ 互补（余数 $13 + 11 = 24$），而不是要求 $hours[j] = 24 - hours[i]$（那会漏掉 $30$ 与 $18$ 这类和为 $48$ 的对）。
6. **答案类型**：本题 `int` 够用；直接照搬到 Q2（$n \le 10^5$）时记得把 `ans` 改成 `long long` 并用接口给定的返回类型。
