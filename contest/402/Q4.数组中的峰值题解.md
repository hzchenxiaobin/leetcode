# LeetCode 数组中的峰值 题解

## 1. 题目概述

- **标题 / 题号**：数组中的峰值（#3187，hard）
- **链接**：https://leetcode.cn/problems/peaks-in-array/
- **来源**：LeetCode 第 402 场周赛 Q4
- **难度**：困难
- **标签**：树状数组、线段树、数组

**题意**：数组中**严格大于**左右相邻元素的元素称为**峰值**元素。给定整数数组 `nums` 与查询数组 `queries`，处理两类操作：`[1, l, r]` 求子数组 `nums[l..r]` 内峰值的数目；`[2, index, val]` 把 `nums[index]` 改为 `val`。按序返回所有类型 1 操作的答案。注意**子数组的首、尾元素都不是峰值**——哪怕它在整个数组里确实比邻居高。

**约束**：

- $3 \le \text{nums.length} \le 10^5$
- $1 \le \text{nums[i]} \le 10^5$
- $1 \le \text{queries.length} \le 10^5$
- 查询满足 $0 \le l \le r \le n-1$；修改满足 $0 \le \text{index} \le n-1$，$1 \le val \le 10^5$

> 💡 **周赛现场策略**：看到「单点修改 + 区间计数」的组合应条件反射出**树状数组/线段树**——这是 [307. 区域和检索 - 数组可变](https://leetcode.cn/problems/range-sum-query-mutable/) 定下的经典命题。本题的全部新意在于把"数峰值"这个**逐点局部性质**翻译成 0/1 数组上的**区间和**，剩下的就是 BIT 板板。卡壳点通常有两处：查询是**开区间** $(l, r)$（端点不算），修改会**波及 idx±1 的峰值状态**——两个 off-by-one 都在下标里。

## 2. 示例

**示例 1**

```text
输入：nums = [3,1,4,2,5], queries = [[2,3,4],[1,0,4]]
输出：[0]
解释：先把 nums[3] 改为 4，nums = [3,1,4,4,5]；
      再查询整个数组——两个 4 相邻相等，「严格大于」不成立，峰值数为 0。
```

**示例 2**

```text
输入：nums = [4,1,4,2,1,5], queries = [[2,2,4],[1,0,2],[1,0,4]]
输出：[0,1]
解释：nums[2] 改为 4（原本就是 4，无变化）；
      查询 [4,1,4]：长度 3，只有中间位置可判峰，1 不是峰，答案 0；
      查询 [4,1,4,2,1]：第二个 4 严格大于两侧（1 和 2），是峰，答案 1。
```

**示例 3（边界自查：短区间与端点排除）**

```text
输入：nums = [2,6,4,5,1,3], queries = [[1,0,5],[1,3,5],[1,4,5]]
输出：[2,0,0]
解释：查询 [0,5]：峰在下标 1（2<6>4）与 3（4<5>1），共 2 个；
      查询 [3,5]：区间 [5,1,3]，中间只有下标 4，5>1<3 非峰，答案 0；
      查询 [4,5]：区间长度 2，开区间为空，答案 0。
```

## 3. 解题思路

### 3.1 暴力思路：每个查询现扫一遍

操作 2 直接赋值；操作 1 从 $l+1$ 扫到 $r-1$ 逐个判定 `nums[j] > nums[j-1] && nums[j] > nums[j+1]` 计数。单次查询 $O(r-l)$ 最坏 $O(n)$，总计 $O(nq) = 10^{10}$ 量级，必然超时。

静态前缀和也救不了：操作 2 的修改会**反复作废**任何静态统计——上一秒还是峰的位置，下一秒可能就被削平（示例 1 正是如此）。**带修改的区间和**，标准答案是树状数组或线段树。

### 3.2 核心观察：峰值 0/1 化，查询变开区间和

![峰值 0/1 化与开区间查询](images/peaks_in_array_flag_concept.svg)

**观察一（峰值可以 0/1 化）**：定义指示数组

$$p[i] = \big[\, \text{nums}[i] > \text{nums}[i-1] \ \wedge\ \text{nums}[i] > \text{nums}[i+1] \,\big], \quad 1 \le i \le n-2$$

（$[\cdot]$ 为 Iverson 括号；两端 $p[0] = p[n-1] = 0$。）峰值是**逐点局部性质**——只依赖长度为 3 的窗口——于是"数区间里的峰"变成"数区间里有多少个 1"，**计数问题归约为区间和问题**。

**观察二（子数组峰 ⇔ 全局峰）**：查询 $[l, r]$ 时，位置 $i \in (l, r)$ 的左右邻居 $i-1, i+1$ 仍落在 $[l, r]$ 内，判定所用的比较与全局**是同一对元素**；端点又被题面直接排除。所以

$$\text{answer}(l, r) = \sum_{i=l+1}^{r-1} p[i]$$

一个全局维护的 $p$ 数组就能回答**所有**查询，无需按查询区间重新判定。

**观察三（修改只动摇 3 个峰位）**：$p[j]$ 只依赖窗口 $\text{nums}[j-1..j+1]$。把 $\text{nums}[idx]$ 改成新值，可能变化的只有窗口覆盖 $idx$ 的三个位置 $p[idx-1],\ p[idx],\ p[idx+1]$——各 $O(1)$ 重算，差值 $\Delta = p_{\text{新}} - p_{\text{旧}}$ 做单点加即可。

**操作集归纳**：至多 3 次单点加（$\pm 1$）+ 一次前缀和相减。**和是可减信息**，这正是**树状数组**的甜区——比起「区间加 + 区间 max」那种必须上懒标记线段树的题，本题一个 40 行的 BIT 就够。

### 3.3 算法流程：BIT 维护峰值指示数组

![单点修改的局部性与 BIT 操作](images/peaks_in_array_update_locality.svg)

1. **初始化**：扫一遍 $j \in [1, n-2]$ 计算 $p[j]$，峰位写入树状数组（$p[i]$ 存 BIT 的 $i+1$ 位，规避开 0 号位）；
2. **查询 $[1, l, r]$**：若 $r - l < 2$（开区间为空）直接答 0；否则返回 $\text{pre}(r) - \text{pre}(l+1)$，即 $i \in [l+1, r-1]$ 的 $p$ 之和；
3. **更新 $[2, idx, val]$**：赋值 $\text{nums}[idx] = val$，对 $j \in \{idx-1,\ idx,\ idx+1\}$ 各做一次 `refresh(j)`——重算 $p[j]$，若变化则向 BIT 单点加差值。

每个操作都是一次或三次 $O(\log n)$ 的 BIT 操作。

### 3.4 示例演算

![示例演算：改值削平唯一的峰](images/peaks_in_array_walkthrough.svg)

以示例 1（`nums = [3,1,4,2,5]`）走一遍完整流程：

| 操作 | 动作 | nums | $p[1..3]$ | BIT 变化 | 输出 |
|------|------|------|-----------|----------|------|
| 初始 | 建树 | [3,1,4,2,5] | 0, **1**, 0 | add(3, +1) | — |
| [2,3,4] | nums[3]=4 | [3,1,4,4,5] | 0, **0**, 0 | refresh(2)：$4>4$ 不成立 → add(3, −1)；refresh(3)：不变；refresh(4)：端点跳过 | — |
| [1,0,4] | pre(4)−pre(1) | [3,1,4,4,5] | 0, 0, 0 | — | **0** |

再看示例 2（`nums = [4,1,4,2,1,5]`）：初始 $p[2] = 1$（$4>1$ 且 $4>2$），其余为 0。`[2,2,4]` 赋值后三个 `refresh` 全部无差值（值没变）；`[1,0,2]`：$r-l=2$，$\text{pre}(2)-\text{pre}(1) = p[1] = 0$；`[1,0,4]`：$\text{pre}(4)-\text{pre}(1) = p[1]+p[2]+p[3] = 1$。输出 `[0, 1]` ✓。

## 4. 算法细节

1. **下标映射**：BIT 从 1 号位开始，把 $p[i]$ 存在 BIT 的 $i+1$ 位。查询目标 $i \in [l+1, r-1]$ 对应 BIT 位 $[l+2, r]$，按「右端保留、左端减一」翻译成前缀和相减 $\text{pre}(r) - \text{pre}(l+1)$。
2. **空开区间特判**：$r - l < 2$ 时开区间 $(l, r)$ 为空，直接答 0——不让前缀和算出「负数个峰」。
3. **refresh 的边界一并处理**：`0 < j < n-1` 一石二鸟——既挡住 $j = -1$ 或 $j = n$ 的数组越界（当 $idx = 0$ 或 $idx = n-1$ 时循环会碰出来），又把全局端点挡在维护之外（端点在任何查询里都不可能是峰，天然无需维护）。
4. **为什么 BIT 够、不用线段树**：操作集是「单点加 + 区间和」。和**可减**，前缀差即可得任意区间和，BIT 的最小能力集恰好覆盖；线段树（叶子存 $p$、`push_up` 求和）也能过，代码量约两倍且常数更大。判据一句话：**先看信息可不可减，再决定上 BIT 还是线段树**。
5. **中间量极小**：$p$ 只取 0/1，区间和上界 $n < 10^5$，`int` 绰绰有余，无需 64 位。
6. **`p` 数组要留一份在 BIT 之外**：`refresh` 需要知道 $p[j]$ 的旧值才能算差值，只存 BIT 会退化成 $O(\log n)$ 的单点查询——不如直接留一份 0/1 数组。

## 5. 正确性证明

**引理 1（子数组峰 ⇔ 全局峰）**：对查询 $[l, r]$ 与位置 $i$（$l < i < r$）：$i$ 是子数组 $\text{nums}[l..r]$ 内的峰值，当且仅当 $p[i] = 1$。

**证明**：子数组内 $i$ 的相邻元素仍是 $\text{nums}[i-1]$ 与 $\text{nums}[i+1]$（由 $l < i < r$ 知二者都落在 $[l, r]$ 内），故「子数组内判定式」与「全局判定式 $p[i]$」是**同一对比较**，二者等价；端点 $i = l$ 或 $i = r$ 被题面规定排除，不计入。于是答案恰为 $\sum_{i=l+1}^{r-1} p[i]$。∎

**引理 2（修改局部性）**：将 $\text{nums}[idx]$ 改为 $val$ 后，$p[j]$ 可能改变当且仅当 $j \in \{idx-1,\ idx,\ idx+1\}$。

**证明**：$p[j]$ 是窗口 $(\text{nums}[j-1], \text{nums}[j], \text{nums}[j+1])$ 的函数。该窗口包含下标 $idx$ 当且仅当 $j - 1 \le idx \le j + 1$，即 $idx - 1 \le j \le idx + 1$。若 $|j - idx| \ge 2$，窗口不含 $idx$，三个元素原封不动，$p[j]$ 不变；若 $j \in \{idx-1, idx, idx+1\}$，窗口含 $idx$，$p[j]$ 可能改变。故修改后只需 `refresh` 这三个位置。∎

**定理（算法正确性）**：若初始建树正确，则按 §3.3 处理每个操作后，BIT 始终维护当前 $p$ 的前缀和，且每个类型 1 操作返回的恰为该时刻 $\sum_{i=l+1}^{r-1} p[i]$。

**证明**：对已处理的操作数归纳。基础：初始循环对每个 $j \in [1, n-2]$ 执行 `refresh`，$p$ 初值全 0，每次 `refresh` 把差值 $p_{\text{新}} - p_{\text{旧}}$ 单点加进 BIT，建树后 BIT 的前缀和与 $p$ 逐位一致。归纳步：设某操作前 BIT 与 $p$ 一致。若该操作是修改 $\text{nums}[idx] = val$，由引理 2，可能变化的 $p[j]$ 恰是 $j \in \{idx-1, idx, idx+1\}$ 中落在 $[1, n-2]$ 内的那些，算法对这三处逐一 `refresh`——每次把新旧差值补进 BIT，其余位置的 $p$ 与 BIT 内容不变，一致性保持。若该操作是查询 $[l, r]$：$r - l < 2$ 时开区间空，答案 0 正确；否则由引理 1，正确答案为 $\sum_{i=l+1}^{r-1} p[i]$，由 BIT 一致性，$\text{pre}(r) - \text{pre}(l+1) = \sum_{i \le r-1} p[i] - \sum_{i \le l} p[i] = \sum_{i=l+1}^{r-1} p[i]$，返回值正确。归纳完成。∎

## 6. 复杂度分析

- **时间复杂度**：$O((n+q)\log n)$。建树 $n - 2$ 次 `refresh`；每个类型 1 查询一次前缀和相减（两次 $O(\log n)$）；每个类型 2 修改至多 3 次 `refresh`（各一次 $O(\log n)$ 单点加）。
- **空间复杂度**：$O(n)$。树状数组 $n+1$ 个 `int` + 峰值标记数组 $p$ 一份；`nums` 原地修改不额外复制。

## 7. 参考代码

### C++（树状数组）

```cpp
class Solution {
    int n;
    vector<int> tree;                        // 树状数组：单点加 + 前缀和

    void add(int i, int v) {                 // BIT 位 i 单点加 v
        for (; i <= n; i += i & -i) tree[i] += v;
    }
    int pre(int i) {                         // 前缀和：Σ p[0..i-1]
        int s = 0;
        for (; i > 0; i &= i - 1) s += tree[i];
        return s;
    }

  public:
    vector<int> countOfPeaks(vector<int>& nums, vector<vector<int>>& queries) {
        n = nums.size();
        tree.assign(n + 1, 0);
        vector<int> p(n, 0);                 // p[i]：i 当前是否为峰（端点恒 0）

        auto refresh = [&](int j) {          // 重算 p[j]，差值写入 BIT
            if (j <= 0 || j >= n - 1) return;      // 越界或端点，不可能是峰
            int f = nums[j] > nums[j - 1] && nums[j] > nums[j + 1];
            if (f != p[j]) { add(j + 1, f - p[j]); p[j] = f; }
        };

        for (int j = 1; j < n - 1; ++j) refresh(j);   // 初始建树

        vector<int> ans;
        for (auto& q : queries) {
            if (q[0] == 1) {                 // 数开区间 (l, r) 内的峰
                int l = q[1], r = q[2];
                ans.push_back(r - l >= 2 ? pre(r) - pre(l + 1) : 0);
            } else {
                nums[q[1]] = q[2];           // 改值，至多动摇 3 个峰位
                for (int j = q[1] - 1; j <= q[1] + 1; ++j) refresh(j);
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countOfPeaks(self, nums: List[int], queries: List[List[int]]) -> List[int]:
        n = len(nums)
        tree = [0] * (n + 1)

        def add(i: int, v: int) -> None:      # BIT 位 i 单点加 v
            while i <= n:
                tree[i] += v
                i += i & -i

        def pre(i: int) -> int:               # 前缀和：Σ p[0..i-1]
            s = 0
            while i > 0:
                s += tree[i]
                i &= i - 1
            return s

        p = [0] * n                           # p[i]：i 当前是否为峰

        def refresh(j: int) -> None:          # 重算 p[j]，差值写入 BIT
            if 0 < j < n - 1:                 # 越界或端点不可能是峰
                f = 1 if nums[j - 1] < nums[j] > nums[j + 1] else 0
                if f != p[j]:
                    add(j + 1, f - p[j])
                    p[j] = f

        for j in range(1, n - 1):
            refresh(j)                        # 初始建树

        ans = []
        for t, a, b in queries:
            if t == 1:                        # 数开区间 (a, b) 内的峰
                ans.append(pre(b) - pre(a + 1) if b - a >= 2 else 0)
            else:
                nums[a] = b                   # 改值，至多动摇 3 个峰位
                for j in (a - 1, a, a + 1):
                    refresh(j)
        return ans
```

## 8. 边界情况与易错点

1. **查询的 off-by-one 是头号 WA 源**：答案是 $\text{pre}(r) - \text{pre}(l+1)$ 而非 $\text{pre}(r) - \text{pre}(l)$——开区间左端 $l$ 本身必须被减掉；写成 $\text{pre}(r-1) - \text{pre}(l)$ 也对（等价变形），但混用两种写法必错其一。
2. **空开区间要特判 0**：$r - l < 2$（区间长度 1 或 2）时开区间为空。不特判的话 $\text{pre}(r) - \text{pre}(l+1)$ 在 $r = l+1$ 时恒为 0 尚属侥幸，在 $r = l$ 时会算出负数。
3. **修改只 refresh idx 自己、漏掉 idx±1**：$p[idx]$ 的邻居峰位同样依赖 $\text{nums}[idx]$，漏刷会留脏数据到后续查询——本题最隐蔽的 WA。
4. **idx 在端点时的越界**：$idx = 0$ 时 $j = -1$、$idx = n-1$ 时 $j = n$，`refresh` 的 `0 < j < n-1` 保护必须先于数组访问。
5. **「严格大于」**：判定写 `>` 而非 `>=`，示例 1 的 $[3,1,4,4,5]$（相邻相等）就是为此设的陷阱。
6. **端点不算峰的双保险**：即使查询端点本身是全局峰（如对示例 2 查询 $[2,5]$ 时的 `nums[2]`），也不计入——开区间收缩已把它排除，无需额外判断。
7. **改值前后相同**（示例 2 的 `[2,2,4]`）：三个 `refresh` 的差值全为 0，BIT 不动，自然正确，无需特判。
