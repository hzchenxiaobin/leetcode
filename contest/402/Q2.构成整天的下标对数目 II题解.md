# LeetCode 构成整天的下标对数目 II 题解

## 1. 题目概述

- **标题 / 题号**：构成整天的下标对数目 II（#3185，medium）
- **链接**：https://leetcode.cn/problems/count-pairs-that-form-a-complete-day-ii/
- **来源**：LeetCode 第 402 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、计数

**题意**：给定整数数组 `hours`（单位：小时），统计满足 $i < j$ 且 $hours[i] + hours[j]$ 是 $24$ 的整数倍（构成**整天**）的下标对 $(i, j)$ 的数目。题面与本场 Q1（#3184）完全相同，**唯一区别是数据范围**。

**约束**：

- $1 \le hours.length \le 5 \times 10^5$
- $1 \le hours[i] \le 10^9$

> 💡 **周赛现场策略**：Q1 与 Q2 同题面、只放大 $n$，是典型的"复杂度阶梯"出题。比赛时看到 Q2 秒认出是 Q1 加强版，最优策略是**直接写 $O(n)$ 余数计数版**，一份代码过两题（只需改返回类型）。在 Q1 上先交 $O(n)$ 验证正确性，Q2 粘贴过来把 `int` 换 `long long` 即可——这正是"签到时多花两分钟写优化版"的回报时刻。

## 2. 示例

**示例 1**

```text
输入：hours = [12,12,30,24,24]
输出：2
解释：构成整天的下标对是 (0, 1) 和 (3, 4)。
      12 + 12 = 24，24 + 24 = 48 = 2 × 24。
```

**示例 2**

```text
输入：hours = [72,48,24,3]
输出：3
解释：构成整天的下标对是 (0, 1)、(0, 2) 和 (1, 2)。
      72 + 48 = 120，72 + 24 = 96，48 + 24 = 72，均为 24 的倍数。
      注意前三个数 mod 24 余数全为 0，是"自配对"的情形。
```

**示例 3（答案规模）**

```text
输入：hours = [24] * 500000（5×10⁵ 个 24）
输出：124999750000
解释：所有余数均为 0，两两互配，答案 = C(5×10⁵, 2) ≈ 1.25×10¹¹，
      远超 32 位 int 上限（约 2.1×10⁹），必须用 64 位整数累加。
```

## 3. 解题思路

### 3.1 暴力思路：$O(n^2)$ 数得对但数不完

双重循环枚举所有下标对 $(i, j)$（$i < j$），判断 $(hours[i] + hours[j]) \bmod 24$ 是否为 $0$。逻辑完全正确——Q1（$n \le 100$）就是这么过的。

但 Q2 算一笔账：$n = 5 \times 10^5$ 时要判定 $\binom{n}{2} \approx 1.25 \times 10^{11}$ 对。即使每次判定只要 1 纳秒，也要跑约 **125 秒**，超出时限四个数量级。结论：必须换掉"配对枚举"本身，而不是优化它的常数。

![Q1到Q2的数据规模跃迁](images/complete_day_ii_scale_gap.svg)

> ⚠️ C++ 还有一个擦边坑：暴力判定中 $hours[i] + hours[j]$ 最大 $2 \times 10^9$，虽恰好未超 `INT_MAX`（$\approx 2.147 \times 10^9$），但已属危险飞行。正解先取模再运算，所有中间量不超过 23，彻底告别溢出。

### 3.2 核心观察：同余缩域 + 余数配对

![24个余数桶的配对结构](images/complete_day_ii_pair_structure.svg)

**第一步：判定只依赖余数。** 由模运算的可加性：

$$24 \mid (h_i + h_j) \iff (h_i \bmod 24 + h_j \bmod 24) \bmod 24 = 0$$

$10^9$ 的值域瞬间缩到 $0 \sim 23$ 共 24 个桶，与数值大小彻底无关。

**第二步：配对结构。** 设 $r = h \bmod 24$，则"搭档"是**补集余数** $(24 - r) \bmod 24$。24 个桶分成两类：

| 类型 | 余数 | 配对方式 | 贡献 |
|------|------|----------|------|
| **自配对** | $r = 0$、$r = 12$ | 桶内自己配自己 | $\binom{cnt}{2}$ |
| **互补对** | $r = 1 \ldots 11$ 配 $24 - r$ | 两桶交叉配 | $cnt[r] \times cnt[24-r]$ |

$(24 - r) \bmod 24$ 中的 $\bmod\ 24$ **不可省略**：$r = 0$ 时 $24 - r = 24$ 会数组越界；而 $r = 12$ 的补集恰是自身——一个公式无分支地统一了自配对与互补对。

**第三步：把 $i < j$ 编码进时间顺序。** 从左到右扫描，处理到 $j$ 时在"**已入桶的历史元素**"里查补集余数的出现次数——这些元素下标天然全部小于 $j$。**先查表、后入桶**的顺序同时实现了"不与自己配对"（查表时自己还不在表里）和"不重复计数"（每对只在右端点时刻被数一次）。

### 3.3 算法流程：单趟扫描

1. 初始化计数数组 `cnt[0..23] = 0`，答案 `ans = 0`（**必须 `long long`**）；
2. 从左到右遍历每个 $h$：计算 $r = h \bmod 24$；
3. **查表**：`ans += cnt[(24 - r) % 24]`——左边有多少个能凑整天的元素，就新增多少对；
4. **入桶**：`cnt[r] += 1`——把当前元素留给后面的元素配对；
5. 遍历结束返回 `ans`。

### 3.4 示例演算

![示例走查表](images/complete_day_ii_walkthrough.svg)

以 `hours = [12,12,30,24,24]` 逐行推进（命中行高亮）：

| $j$ | $hours[j]$ | $r$ | 查 $cnt[(24-r)\%24]$ | $ans$ | 入桶后 $cnt$ |
|-----|-----------|-----|----------------------|-------|--------------|
| 0 | 12 | 12 | $cnt[12] = 0$ | 0 | $\{12{:}1\}$ |
| 1 | 12 | 12 | $cnt[12] = 1 \Rightarrow +1$ | 1 | $\{12{:}2\}$ |
| 2 | 30 | 6 | $cnt[18] = 0$ | 1 | $\{12{:}2,\ 6{:}1\}$ |
| 3 | 24 | 0 | $cnt[0] = 0$ | 1 | $\{12{:}2,\ 6{:}1,\ 0{:}1\}$ |
| 4 | 24 | 0 | $cnt[0] = 1 \Rightarrow +1$ | 2 | $\{12{:}2,\ 6{:}1,\ 0{:}2\}$ |

最终 $ans = 2$ ✓。示例 2 `hours = [72,48,24,3]` 同法：前三个数余数全为 0，两两自配对贡献 $\binom{3}{2} = 3$；最后的 $3$ 需要补集 $21$，此前未出现，贡献 $0$，合计 $3$ ✓。

## 4. 算法细节

1. **同余转化**：判断"和是 24 的倍数"不需要算出和，只看两余数。$hours[i]$ 可达 $10^9$，余数永远在 $[0, 23]$。
2. **补集统一公式**：$(24 - r) \bmod 24$。$r = 0$ 时结果为 $0$（自配），$r \in [1, 23]$ 时为 $24 - r$，无分类讨论、无越界。
3. **先查后记**：查表与入桶的顺序不能颠倒，否则 $r = 0$ 或 $r = 12$ 时当前元素会与自己配对，当场多算。
4. **答案类型**：上界 $\binom{5 \times 10^5}{2} \approx 1.25 \times 10^{11}$，接口返回 `long long`；Python 天然大整数无此虑。
5. **数据结构**：值域仅 24，定长数组就是最快最省的哈希表；若模数推广到大 $k$，换 `unordered_map` / `dict`。
6. **两趟组合数写法（备选）**：先扫一遍统计 `cnt`，再按 §3.2 的配对结构结算：$ans = \binom{cnt[0]}{2} + \binom{cnt[12]}{2} + \sum_{r=1}^{11} cnt[r] \times cnt[24-r]$。同样 $O(n)/O(1)$，但需显式分类、且 $cnt[r] \times cnt[24-r]$ 是两个 `int` 相乘（最大约 $6.25 \times 10^{10}$），必须先转 64 位再乘，见 §7 的备选代码。

## 5. 正确性证明

**引理 1**：对非负整数 $a$、$b$，$24 \mid (a + b)$ 当且仅当 $(a \bmod 24 + b \bmod 24) \bmod 24 = 0$。

**证明**：由同余性质 $a \equiv a \bmod 24$、$b \equiv b \bmod 24 \pmod{24}$，故 $a + b \equiv (a \bmod 24) + (b \bmod 24) \pmod{24}$。于是 $24 \mid (a+b)$ 当且仅当右侧两余数之和 $\equiv 0 \pmod{24}$。∎

**引理 2**：处理下标 $j$ 时，`cnt[(24−r_j) mod 24]` 恰等于满足 $i < j$ 且 $hours[i] + hours[j]$ 构成整天的下标 $i$ 的个数。

**证明**：处理 $j$ 之前 `cnt` 只被下标 $< j$ 的元素更新，故 `cnt[r]` 等于左侧余数为 $r$ 的元素个数。由引理 1，左侧元素 $i$ 与 $j$ 构成整天 $\iff r_i \equiv -r_j \pmod{24}$；$r_i \in [0, 23]$ 内满足该同余的值唯一，即 $(24 - r_j) \bmod 24$。故查询结果恰为所求个数。∎

**定理 1**：单趟算法的返回值等于满足 $i < j$ 且构成整天的下标对总数。

**证明**：每个合法对 $(i, j)$ 由引理 2 恰在处理 $j$ 时被统计一次；反之，处理 $j$ 时查到的每个计数都对应一个真实合法对（$i < j$ 且余数互补），且 $j$ 自身尚未入桶、右侧元素尚未遍历，任何非法对均不会被统计。合法对不重不漏各计一次。∎

**定理 2**：两趟组合数写法返回相同结果。

**证明**：所有合法对按右端点余数分类互不相交。余数 $0$ 与 $12$ 的桶内元素两两配对，个数为 $\binom{cnt}{2}$；对 $r \in [1, 11]$，合法对恰由余数 $r$ 桶与 $24 - r$ 桶的元素交叉组成，个数为 $cnt[r] \times cnt[24-r]$，且 $r$ 只枚举到 $11$ 保证每对互补桶只结算一次。三类求和即总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单次线性扫描，每个元素做一次取模、一次 $O(1)$ 数组查询、一次自增；相比暴力，优化的本质是**枚举右端点 + 批量询问左端点统计量**，把 $O(n)$ 的内层循环压成一次桶查询。
- **空间复杂度**：$O(24) = O(1)$。仅一个长度 24 的计数数组与常数个变量，与输入规模无关。

## 7. 参考代码

### C++（单趟扫描，推荐）

```cpp
class Solution {
public:
    long long countCompleteDayPairs(vector<int>& hours) {
        long long ans = 0;
        int cnt[24] = {};
        for (int h : hours) {
            int r = h % 24;                // 10^9 先缩到 0..23
            ans += cnt[(24 - r) % 24];     // 先查：补集余数的历史出现次数
            cnt[r]++;                      // 后插：保证配到的都是 i < j
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countCompleteDayPairs(self, hours: List[int]) -> int:
        cnt = [0] * 24
        ans = 0
        for h in hours:
            r = h % 24
            ans += cnt[(24 - r) % 24]
            cnt[r] += 1
        return ans
```

### C++（两趟组合数结算，备选）

```cpp
class Solution {
public:
    long long countCompleteDayPairs(vector<int>& hours) {
        long long cnt[24] = {};
        for (int h : hours) ++cnt[h % 24];
        long long ans = cnt[0] * (cnt[0] - 1) / 2      // 余数 0 自配对
                      + cnt[12] * (cnt[12] - 1) / 2;   // 余数 12 自配对
        for (int r = 1; r < 12; ++r)                   // 11 组互补对
            ans += cnt[r] * cnt[24 - r];
        return ans;
    }
};
```

> 💡 单趟版无分支、流式友好（数据来一个处理一个），配对结构全部融进 `(24 - r) % 24` 一个公式；两趟版结构显式、直接展示对配对结构的理解，但要小心 $r$ 的枚举范围（只到 11）与乘法溢出（`cnt` 须为 `long long` 数组）。两版都值得掌握。

## 8. 边界情况与易错点

1. **答案溢出是本题最大的坑**：全同类余数时答案可达 $\binom{5\times10^5}{2} \approx 1.25 \times 10^{11}$，`int` 累加器直接爆负数。把 Q1 的代码搬过来时，`ans` 与返回类型都要换 `long long`——本题函数签名已约定返回 `long long`，照抄签名即可躲过。
2. **两趟版的乘法溢出更隐蔽**：`cnt[r] * cnt[24 - r]` 两个 `int` 相乘最大约 $6.25 \times 10^{10}$，即使最终累加器是 `long long` 也会在乘法处截断；须将 `cnt` 声明为 `long long` 数组，或写 `(long long)cnt[r] * cnt[24 - r]`。
3. **$r = 0$ 的补集是 0 而不是 24**：必须写 $(24 - r) \bmod 24$，否则下标 24 越界（C++ 未定义行为，哈希表则配错到不存在的键）。
4. **先查后记不能颠倒**：$r = 0$ 或 $r = 12$ 时补集等于自身，先插后查会把元素与自己配对（单个 24 凭空多出一对）。
5. **$n = 1$ 答案为 0**：算法自然给出 0，无需特判。
6. **别把"互补"理解成数值互补**：$13$ 与 $11$ 互补（余数和为 24），而不是要求 $hours[j] = 24 - hours[i]$（那会漏掉 $30$ 与 $18$ 这类和为 $48$ 的对）。
7. **$r$ 枚举范围只到 11**：两趟版若枚举到 23，每个互补对会被算两遍。
