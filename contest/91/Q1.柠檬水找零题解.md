# LeetCode 柠檬水找零 题解

## 1. 题目概述

- **标题 / 题号**：柠檬水找零（#860，easy）
- **链接**：https://leetcode.cn/problems/lemonade-change/
- **来源**：LeetCode 第 91 场周赛 Q1
- **难度**：简单
- **标签**：贪心、数组

**题意**：柠檬水每杯 5 美元，顾客按 `bills` 的顺序依次付款，每人只买一杯，付 5、10 或 20 美元。摊主**一开始没有任何零钱**，必须对每位顾客都正确找零，使每笔净交易恰好为 5 美元。问能否服务完所有顾客。

真正需要维护的只有一件事：**手上有几张 5 元、几张 10 元**。20 美元钞票永远找不出去，收进来等于废纸，因此不必计数。

**约束**：

- $1 \le \text{bills.length} \le 10^5$
- $bills[i] \in \{5, 10, 20\}$

## 2. 示例

**示例 1**

```text
输入：bills = [5,5,5,10,20]
输出：true
解释：前 3 位顾客各付 5 元，手上有 3 张 5 元；
     第 4 位付 10 元，找零 5 元，剩下 2 张 5 元、1 张 10 元；
     第 5 位付 20 元，找零 10 + 5 元，正好凑齐。
```

**示例 2**

```text
输入：bills = [5,5,10,10,20]
输出：false
解释：前两位付 5 元，第三、四位各付 10 元各找 5 元，
     此时手上是 0 张 5 元、2 张 10 元；
     最后一位付 20 元，需要 15 元，两张 10 元无法凑出，失败。
```

**示例 3（补充）**

```text
输入：bills = [5,5,10,20,20]
输出：false
解释：第 4 位顾客用 10 + 5 找零后手上清零，
     第 5 位顾客再付 20 元时已无零钱可找。
```

## 3. 解题思路

### 3.1 暴力思路

把每位顾客的找零方式都当作一次选择：收到 5 元没有选择，收到 10 元必须给 1 张 5 元，收到 20 元则有两种给法（10 + 5 或 5 + 5 + 5）。于是可以搜索所有分支，最坏 $O(2^n)$，$n = 10^5$ 显然不可行。

也可以写成记忆化搜索，状态为 $(i, f, t)$（处理到第 $i$ 位顾客、手上 $f$ 张 5 元与 $t$ 张 10 元），但状态数是 $O(n^2)$ 级别，同样过不了。

瓶颈在于「把 20 元的两种找零方式当成了真正等价的选择」。事实上它们**不等价**，一手好牌应该有明确的优先级。

### 3.2 核心观察：贪心地先花 10 元

![柠檬水找零：三种面额的处理策略，20 元优先用 10 + 5](images/wc91_q1_greedy_pay20.svg)

两种钞票的「通用性」完全不同：

- **5 元是硬通货**：10 元顾客要它，20 元顾客也要它，缺一张就崩。
- **10 元很挑食**：它唯一的用途是陪同一张 5 元去找给 20 元顾客；没有 5 元时它就是废物。

所以在收到 20 元时，只要手上同时有 10 元和 5 元，就**优先用 10 + 5**，把 5 元尽量省下来。理由很直白：用 10 + 5 与用 5 + 5 + 5 都能凑出 15 元，但前者额外消耗的是那张「反正也派不上别的用场」的 10 元。

### 3.3 算法流程

设 $f$、$t$ 为手上 5 元与 10 元的张数，初始 $f = t = 0$，顺序扫描 `bills`：

```text
对每张钞票 b：
    b == 5  : f += 1
    b == 10 : 需要 1 张 5 元；f == 0 则失败，否则 f -= 1、t += 1
    b == 20 : 优先 10 + 5（t > 0 且 f > 0）：t -= 1、f -= 1
              否则 5 + 5 + 5（f >= 3）：f -= 3
              两者都不可行则失败
全部处理完 ⇒ 返回 true
```

### 3.4 示例演算

![示例演算：付款序列 5、5、5、10、20 的逐位走查](images/wc91_q1_example_walkthrough.svg)

对示例 1 的 `bills = [5,5,5,10,20]`：

| 顾客 | 付款 | 找零动作 | f | t |
|------|------|----------|---|---|
| 开始 | — | 手头没有零钱 | 0 | 0 |
| 1 | 5 | 收下 | 1 | 0 |
| 2 | 5 | 收下 | 2 | 0 |
| 3 | 5 | 收下 | 3 | 0 |
| 4 | 10 | 找 5：$f-1$、$t+1$ | 2 | 1 |
| 5 | 20 | 优先 10 + 5：$t-1$、$f-1$ | 1 | 0 |

五笔交易全部完成，返回 `true`。若把第 5 位的找零换成 5 + 5 + 5，也照样能成功，但会把 10 元砸在手里——这说明贪心至少不比它差，而反过来的场景（示例 2、3）贪心严格更优。

## 4. 算法细节

1. **状态压缩到两个整数**：只需 $f$ 与 $t$；20 元钞票不计数，因为它永远不可能被找零出去。
2. **顺序必须严格**：找零只能使用**当前之前**收到的钞票，所以必须按 `bills` 的下标顺序处理，不能预先统计总量。
3. **先查再扣**：`b == 10` 时先判断 $f = 0$ 就返回 `false`，避免扣成负数。
4. **20 元的两个分支有先后**：先尝试 10 + 5，失败再试 5 + 5 + 5，顺序不能反。
5. **5 元张数上界**：最多 $10^5$，`int` 足够，无需长整型。
6. **提前失败**：任何一步无法找零即返回 `false`，不必继续扫描。

## 5. 正确性证明

先形式化「哪种零钱状态更强」。记状态 $(f, t)$ 表示手上 $f$ 张 5 元、$t$ 张 10 元。

**引理 1（支配关系）**：若 $f_1 \ge f_2$ 且 $f_1 + 2t_1 \ge f_2 + 2t_2$，则对任意后续账单序列，只要 $(f_2, t_2)$ 能全部服务，$(f_1, t_1)$ 也能全部服务。

**证明**：对剩余账单长度做归纳。设当前账单为 $b$。

- $b = 5$：两边都无需找零，$(f_i, t_i) \to (f_i + 1, t_i)$，两个不等式各自加 1 后仍成立。
- $b = 10$：需要一张 5 元。由 $f_1 \ge f_2 \ge 1$，状态 1 也能付。转移后 $f_i' = f_i - 1$、$t_i' = t_i + 1$，则 $f_1' \ge f_2'$，且 $f_1' + 2t_1' = (f_1 + 2t_1) + 1 \ge (f_2 + 2t_2) + 1 = f_2' + 2t_2'$，条件保持。
- $b = 20$：状态 2 能付，说明它满足 $f_2 \ge 1, t_2 \ge 1$ 或 $f_2 \ge 3$。分情况。
  - 若 $t_1 \ge 1$ 且 $f_1 \ge 1$，状态 1 用 10 + 5 支付，两边各减一个 10 与一个 5，两个不等式同时减 3，保持。
  - 若 $t_1 = 0$：由 $f_1 = f_1 + 2t_1 \ge f_2 + 2t_2$ 且 $t_2 \ge 1$（状态 2 能付 20 且若 $t_2 = 0$ 则 $f_2 \ge 3$ 也无妨，此时 $f_1 \ge f_2 \ge 3$），都有 $f_1 \ge 3$，状态 1 用 5 + 5 + 5 支付，$f_1' = f_1 - 3 \ge f_2 - 1 = f_2'$（因 $f_1 \ge f_2 + 2$），且 $f_1' + 2t_1' = f_1 - 3 \ge f_2 + 2t_2 - 3$，条件保持。

三种账单下不变式都保持，归纳成立。∎

**引理 2（贪心选择不劣）**：在状态 $(f, t)$ 收到 20 元、且 $f \ge 1, t \ge 1$ 时，贪心转移后的状态 $(f-1, t-1)$ 支配另一分支的状态 $(f-3, t)$（后者要求 $f \ge 3$）。

**证明**：$f - 1 \ge f - 3$；又 $(f-1) + 2(t-1) = f + 2t - 3 = (f-3) + 2t$，两个不等式均成立，由引理 1 得支配。∎

**定理**：算法返回 `true` 当且仅当存在一种找零方案能服务完所有顾客。

**证明**：5 元与 10 元账单的找零方式是唯一的（分别无需找零、必须付 1 张 5 元），任何方案在此都没有选择空间；20 元账单处贪心总取支配状态（引理 2），若另一分支可行则贪心状态也能行（引理 1）。故按账单顺序归纳可知：贪心在第 $i$ 步的状态支配任意可行方案在第 $i$ 步的状态。于是若某方案能走完全程，贪心也能（引理 1）；反之贪心若失败，说明它已无钱可找，而被它支配的所有状态只会更穷，任何方案同样失败。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个账单只做常数次加减与比较，$n = \text{bills.length}$。
- **空间**：$O(1)$。只用两个计数器，与输入规模无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool lemonadeChange(vector<int>& bills) {
        int five = 0, ten = 0;
        for (int b : bills) {
            if (b == 5) {
                five++;
            } else if (b == 10) {
                if (five == 0) return false;
                five--;
                ten++;
            } else {
                if (ten > 0 && five > 0) {
                    ten--;
                    five--;
                } else if (five >= 3) {
                    five -= 3;
                } else {
                    return false;
                }
            }
        }
        return true;
    }
};
```

### Python

```python
class Solution:
    def lemonadeChange(self, bills: list[int]) -> bool:
        five = ten = 0
        for b in bills:
            if b == 5:
                five += 1
            elif b == 10:
                if five == 0:
                    return False
                five -= 1
                ten += 1
            else:
                if ten > 0 and five > 0:
                    ten -= 1
                    five -= 1
                elif five >= 3:
                    five -= 3
                else:
                    return False
        return True
```

## 8. 边界情况与易错点

1. **第一位就是 10 或 20**：$f = 0$ 直接失败，代码里必须先判空再扣减，否则计数器变负、后面反而「算得通」。
2. **20 元不能用 20 元找零**：20 美元钞票不能拆开，收进来后对手上的 $f$、$t$ 没有任何贡献，所以既不计数也不参与找零。
3. **两个分支的顺序不能反**：若先试 5 + 5 + 5，示例 1 仍能通过，但示例 2 的变体（如 `[5,5,5,10,20,20]`）会错误地失败或错误地通过。
4. **不要预先统计总量**：找零只依赖「此前」收到的钞票，`[20]` 与 `[5,5,5,5,20]` 的区别正在于此。
5. **别漏了「恰好三次 5 元」的判定**：只剩 2 张 5 元时不能付 20 元账单，判定要用 `f >= 3` 而不是 `f >= 2`。
6. **提前返回**：一旦失败立即 `return false`，不要继续累加状态。
