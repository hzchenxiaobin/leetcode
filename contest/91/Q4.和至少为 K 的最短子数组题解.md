# LeetCode 和至少为 K 的最短子数组 题解

## 1. 题目概述

- **标题 / 题号**：和至少为 K 的最短子数组（#862，hard）
- **链接**：https://leetcode.cn/problems/shortest-subarray-with-sum-at-least-k/
- **来源**：LeetCode 第 91 场周赛 Q4
- **难度**：困难
- **标签**：队列、数组、二分查找、前缀和、滑动窗口、单调队列、堆（优先队列）

**题意**：给定整数数组 `nums`（**可能含负数**）和整数 $k$，求所有「元素和 $\ge k$」的非空连续子数组中最短的长度；不存在则返回 $-1$。

题面特意标注了负数，这是本题的一切难点所在：**正数数组上的滑动窗口在这里会失效**。

**约束**：

- $1 \le \text{nums.length} \le 10^5$
- $-10^5 \le \text{nums}[i] \le 10^5$
- $1 \le k \le 10^9$

注意 $k \ge 1$，所以空子数组（和恒为 0）永远不满足条件，「非空」这一限制在判定时可以自然满足。

## 2. 示例

**示例 1**

```text
输入：nums = [1], k = 1
输出：1
解释：唯一的子数组和为 1 ≥ 1，长度 1。
```

**示例 2**

```text
输入：nums = [1,2], k = 4
输出：-1
解释：最大子数组和是 3 < 4，不存在满足条件的子数组。
```

**示例 3**

```text
输入：nums = [2,-1,2], k = 3
输出：3
解释：整个数组和为 3，但它的任意真子数组和都 < 3：长度为 2 的子数组和分别为 1 和 1。
     这正是负数导致「窗口缩不动」的典型场景。
```

**示例 4（补充）**

```text
输入：nums = [84,-37,32,40,95], k = 167
输出：3
解释：子数组 [32,40,95] 的和为 167 ≥ 167，长度 3；不存在长度为 2 的答案。
```

## 3. 解题思路

### 3.1 暴力思路

用前缀和 $pre[0]=0$、$pre[j]=\sum_{t<j}nums[t]$，子数组 $nums[i..j-1]$ 的和就是 $pre[j]-pre[i]$。暴力枚举所有 $(i, j)$ 对，$O(n^2)$。$n = 10^5$ 时是 $10^{10}$ 次比较，不可行。

另一个诱人的想法是滑动窗口：右端扩张、和 $\ge k$ 时收缩左端。它在「元素全为正」时完全正确（窗口和随右端扩张单调增大、随左端收缩单调减小），但本题有负数。

### 3.2 核心观察：前缀和之差 + 单调队列

![为什么滑动窗口失效：含负数后「和」不再单调](images/wc91_q4_why_window_fails.svg)

滑动窗口的本质是在维护一个**单调性**：右端右移让和变大、左端右移让和变小。负数一出现，这两条都断了——示例 3 中窗口 $[2,-1,2]$ 的和是 3，左端右移一格后和变成 1，直接跌破 $k$，但再往右扩展又可能达标。也就是说「左端点随右端点单调右移」不再成立。

换一个视角看同一个式子：

$$pre[j] - pre[i] \ge k \iff pre[i] \le pre[j] - k \quad (i < j)$$

对固定的右端点 $j$，要最小化 $j - i$，等价于**最大化**满足 $pre[i] \le pre[j] - k$ 的 $i$。于是问题变成：在 $pre[0..j-1]$ 中，找出「值不超过某阈值」的**最靠右**的下标——这是一类典型的单调队列查询。

队列里维护一批「仍然有希望成为最优左端点」的下标，并保持它们的 $pre$ 值严格递增：

![单调队列维护「前缀和递增」的候选左端点](images/wc91_q4_prefix_deque.svg)

- **入队前弹队尾**：若 $pre[j] \le pre[\text{队尾}]$，则队尾彻底作废。因为 $j$ 比队尾更靠右、$pre$ 值更小或相等——以后任何能让队尾达标的右端点，也一定能让 $j$ 达标，而且长度更短。
- **出队时弹队首**：若 $pre[j] - pre[\text{队首}] \ge k$，队首就是一个合法的左端点，记下长度并弹出。它已经给出「以 $j$ 结尾」的最短答案；对更靠后的右端点，再用它只会得到更长的子数组，所以可以安全丢弃。

### 3.3 算法流程

```text
1. 计算前缀和 pre[0..n]，pre[0] = 0
2. dq = 空双端队列（存下标），ans = n + 1
3. for j = 0 .. n:
       while dq 非空 且 pre[j] - pre[dq.front] >= k:
           ans = min(ans, j - dq.front)
           dq.pop_front()
       while dq 非空 且 pre[j] <= pre[dq.back]:
           dq.pop_back()
       dq.push_back(j)
4. 若 ans 仍为 n + 1 则返回 -1，否则返回 ans
```

顺序很关键：**先用 $j$ 去弹队首（结算答案），再把 $j$ 入队**，这样不会出现 $i = j$ 的非法空子数组作为候选。

### 3.4 示例演算

![示例演算：nums 为 2、-1、2，k 等于 3](images/wc91_q4_walkthrough.svg)

对示例 3 的 `nums = [2,-1,2]`、$k = 3$，前缀和为 $pre = [0, 2, 1, 3]$：

| $j$ | $pre[j]$ | $pre[j] - pre[\text{队首}]$ | 弹出队尾 | 队列（下标） | ans |
|-----|----------|------------------------------|----------|----------------|-----|
| 0 | 0 | 空队列，不判定 | — | [0] | 4 |
| 1 | 2 | $2 - 0 = 2 < 3$ | 无（$2 > 0$） | [0, 1] | 4 |
| 2 | 1 | $1 - 0 = 1 < 3$ | 弹出 1（$pre=2 > 1$） | [0, 2] | 4 |
| 3 | 3 | $3 - 0 = 3 \ge 3$ ✓ | 弹出队首 0 | [2, 3] | 3 |

最终 ans $=3$，对应的子数组是 $nums[0..2] = [2,-1,2]$，与示例输出一致。第 3 步中下标 1 被弹出，是因为 $pre[2] = 1 < pre[1] = 2$：下标 2 更靠右、前缀和更小，全面优于下标 1。

## 4. 算法细节

1. **前缀和用 64 位**：$n \le 10^5$、$|nums[i]| \le 10^5$，前缀和绝对值可达 $10^{10}$，C++ 必须用 `long long`（`int` 会溢出成负数，判定全乱）。
2. **$k$ 也用 64 位比较**：$k \le 10^9$，与 `long long` 前缀和比较时避免隐式截断。
3. **哨兵值**：`ans` 初始化为 $n+1$（不可能的长度），最后判断是否仍是它来决定返回 `-1`。
4. **队首弹完再判队尾**：两个 while 的顺序不能颠倒。如果先把 $j$ 入队再弹队首，会因为 $pre[j] - pre[j] = 0 < k$ 而安全，但一旦 $k$ 允许 0 就会误判空子数组；保持「先结算、后入队」最稳。
5. **一次 $j$ 可以弹出多个队首**：每弹一个都更新答案，最后一个弹出的下标最大、长度最短，`min` 会自动保留最优。
6. **单调查询的等价写法**：也可以对每个 $j$ 在队列上二分查找最后一个满足条件的下标，得到 $O(n \log n)$；或者用线段树/堆维护 $(pre[i], i)$，同样 $O(n \log n)$。单调队列是其中最优的 $O(n)$。

## 5. 正确性证明

记 $pre[0] = 0$，$pre[j] = \sum_{t=0}^{j-1} nums[t]$。记

$$\text{OPT} = \min\{\, j - i \;:\; 0 \le i < j \le n,\ pre[j] - pre[i] \ge k \,\},$$

若集合为空则 $\text{OPT} = \infty$（对应返回 $-1$）。

**引理 1（子数组和的前缀表示）**：对任意 $0 \le i < j \le n$，$nums[i..j-1]$ 的和等于 $pre[j] - pre[i]$。

**证明**：$pre[j] - pre[i] = \sum_{t<j}nums[t] - \sum_{t<i}nums[t] = \sum_{i \le t < j} nums[t]$，正是该子数组之和。∎

**引理 2（队列不变式）**：算法任意时刻的双端队列中，下标严格递增、$pre$ 值严格递增。

**证明**：下标只在尾部追加且严格递增，故递增性保持；入队前循环弹出所有 $pre[\text{队尾}] \ge pre[j]$ 的元素，因此追加 $j$ 后 $pre$ 仍严格递增。∎

**引理 3（队尾弹出的安全性）**：若在时刻 $t$ 因 $pre[t] \le pre[i]$ 弹出下标 $i$（$i < t$），则 $i$ 不可能是任何 $j > t$ 的「最优左端点」，且不弹出它会得到不更短的结果。

**证明**：设 $j > t$ 且 $pre[j] - pre[i] \ge k$。由 $pre[t] \le pre[i]$ 得 $pre[j] - pre[t] \ge pre[j] - pre[i] \ge k$，故 $(t, j)$ 也是合法子数组，而长度 $j - t < j - i$ 更短。所以对任何用到 $i$ 的候选都存在更优的替代，删除 $i$ 不影响最优值。∎

**引理 4（队首结算的完备性）**：处理 $j$ 时，队列中满足 $pre[i] \le pre[j] - k$ 的下标恰好是队列的一个前缀；算法弹出的每个下标都给出一个合法子数组，且当该前缀非空时，最后一次弹出得到的长度等于 $j - i^*(j)$，其中 $i^*(j)$ 是当前队列中满足条件的最大下标。

**证明**：由引理 2，队列中 $pre$ 严格递增，而条件 $pre[i] \le pre[j] - k$ 关于 $pre[i]$ 单调，所以满足条件的集合是队列的前缀。弹出这些下标时循环条件正是 $pre[j] - pre[i] \ge k$（引理 1 说明这等价于子数组和 $\ge k$），且 $i < j$ 保证非空，故每个候选合法。弹出的顺序是从队首向后，下标递增，因此最后一个弹出的下标最大、长度 $j - i^*(j)$ 最小，`ans` 取最小值即得该结果。∎

**定理**：算法返回的值等于 $\text{OPT}$（集合为空时返回 $-1$）。

**证明**：分两个方向。

- **算法结果 $\ge \text{OPT}$**：算法每次写入 `ans` 的都是某个真实合法子数组的长度（引理 4 已证合法且非空），而 `OPT` 是所有合法长度的最小值，故 `ans` $\ge$ `OPT`。
- **算法结果 $\le \text{OPT}$**：取达到 `OPT` 的一对 $(i^\*, j^\*)$，即 $i^\* = i^*(j^\*)$ 且 `OPT` $= j^\* - i^\*$。考察算法处理 $j^\*$ 的时刻：
  - 若 $i^\*$ 仍在队列中，由引理 4，它必被弹出，且当时写入的 `ans` $\le j^\* - i^\* = \text{OPT}$。
  - 若 $i^\*$ 已被队尾弹出，由引理 3 存在长度更短的合法子数组，与 `OPT` 的最小性矛盾，故这种情况不会发生。
  - 若 $i^\*$ 已在某个 $j_0 \le j^\*$ 时刻被队首弹出，则当时写入的 `ans` $\le j_0 - i^\* < j^\* - i^\* = \text{OPT}$，同样矛盾或更优。

  故总有 `ans` $\le \text{OPT}$。

结合两个方向，`ans` $=$ `OPT`；`ans` 未被更新时说明没有任何合法子数组，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。前缀和一遍 $O(n)$；随后每个下标最多入队一次、出队一次，两个 while 循环的总迭代次数不超过 $2(n+1)$，故主循环 $O(n)$。
- **空间**：$O(n)$。前缀和数组 $n+1$ 个 `long long`，双端队列最多存 $n+1$ 个下标。若把前缀和也压进队列（存 $pre$ 值而非下标），空间仍是 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int shortestSubarray(vector<int>& nums, int k) {
        int n = nums.size();
        vector<long long> pre(n + 1, 0);
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];
        deque<int> dq;
        int ans = n + 1;
        for (int j = 0; j <= n; j++) {
            while (!dq.empty() && pre[j] - pre[dq.front()] >= k) {
                ans = min(ans, j - dq.front());
                dq.pop_front();
            }
            while (!dq.empty() && pre[j] <= pre[dq.back()]) dq.pop_back();
            dq.push_back(j);
        }
        return ans == n + 1 ? -1 : ans;
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def shortestSubarray(self, nums: list[int], k: int) -> int:
        n = len(nums)
        pre = [0] * (n + 1)
        for i, x in enumerate(nums):
            pre[i + 1] = pre[i] + x
        dq = deque()
        ans = n + 1
        for j in range(n + 1):
            while dq and pre[j] - pre[dq[0]] >= k:
                ans = min(ans, j - dq.popleft())
            while dq and pre[j] <= pre[dq[-1]]:
                dq.pop()
            dq.append(j)
        return -1 if ans == n + 1 else ans
```

## 8. 边界情况与易错点

1. **32 位溢出**：这是本题最致命的坑。$n=10^5$ 且值域 $10^5$ 时前缀和可达 $10^{10}$，C++ 用 `int` 会溢出成负值，导致单调性判断和答案全部错误。
2. **只考虑「正数滑窗」**：示例 3 会直接给出错误答案（滑窗会得到 2 或 -1），必须用前缀和 + 单调队列。
3. **`ans` 初值**：用 $n+1$ 而不是 `INT_MAX`，避免 `j - dq.front()` 与哨兵比较时出现无意义的大数；最后用「是否仍等于 $n+1$」判断无解。
4. **弹出顺序**：先弹队首结算、再弹队尾维护单调，最后入队。顺序错乱会把 $i=j$ 的空子数组算进去（当 $k$ 允许 0 时必错）。
5. **同一个 $j$ 弹多个队首**：漏写 while 只弹一个，会漏掉更短的最优解。
6. **全为正数也要正确**：`nums = [1,1,1]`、$k=2$ 应返回 2；全为负时必然返回 -1。
7. **单元素数组**：$n=1$ 时答案只能是 1 或 -1，前缀和数组长度为 2，循环边界 `0..n` 不能写成 `0..n-1`。
