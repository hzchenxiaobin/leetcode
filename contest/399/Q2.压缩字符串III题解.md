# LeetCode 压缩字符串 III 题解

## 1. 题目概述

- **标题 / 题号**：压缩字符串 III（#3163，medium）
- **链接**：https://leetcode.cn/problems/string-compression-iii/
- **来源**：LeetCode 第 399 场周赛 Q2
- **难度**：中等
- **标签**：字符串、双指针、模拟、游程编码（RLE）

**题意**：给定字符串 `word`，从空串 `comp` 开始反复执行：取 `word` 开头**由同一字符 `c` 连续组成的最长前缀，但长度至多 9**，把「段长（一位数字）+ 字符 `c`」追加到 `comp`，直到 `word` 被吃空。返回 `comp`。本质上就是**游程编码（RLE）的封顶变体**：每段长度不许超过 9，超长游程必须拆成多段。

**约束**：

- $1 \le word.length \le 2 \times 10^5$
- `word` 仅由小写英文字母组成

> 💡 **读题关键**：与普通 RLE 的全部区别就在「最多 9」三个字——14 个连续 `a` 不能写成 `"14a"`（两位数字破坏「数字+字符」的成对格式），只能拆成 `"9a" + "5a"`。比赛时的正确反应：一次线性扫描 + 计数器封顶冲刷，纯模拟题，考点在**边界与实现细节**而非算法设计。

## 2. 示例

**示例 1**

```text
输入：word = "abcde"
输出："1a1b1c1d1e"
解释：5 次操作分别取 "a"、"b"、"c"、"d"、"e"，每段长度都是 1。
```

**示例 2**

```text
输入：word = "aaaaaaaaaaaaaabb"（14 个 a + 2 个 b）
输出："9a5a2b"
解释：3 次操作分别取 "aaaaaaaaa"（9 个）、"aaaaa"（5 个）、"bb"（2 个）。
```

**示例 3（自造，覆盖「整 9 + 余 1」的临界切分）**

```text
输入：word = "dddddddddd"（恰好 10 个 d）
输出："9d1d"
解释：第 1 段吃满 9 个触发封顶，剩下 1 个 d 单独成段。
      若误写成 "10d" 就是两位数字，格式直接损坏。
```

## 3. 解题思路

### 3.1 暴力思路：照题意「真切片」模拟

题面本身就是操作说明书，最直接的翻译是：每轮统计开头游程长度 $k = \min(9, \text{游程长})$，执行 `comp = comp + str(k) + c`，再 `word = word[k:]` 移除前缀。逻辑完全正确，但有两个性能坑：

- `word = word[k:]`：每次切片**拷贝剩余整个串**，最坏（全同字符、$2 \times 10^5$ 长度，每轮切 9 个）约 $\frac{n}{9} \approx 22000$ 轮、每轮拷 $O(n)$，总量 $\approx 2 \times 10^9$ 字符；
- `comp = comp + s`（Python）：同理，每次拼接重建整个 `comp`。

两者都是 $O(n^2)$，$n = 2 \times 10^5$ 时必然超时。修正方式是同一句话：**别真的动 `word`，用下标 `i` 标记「虚拟剩余串」的开头；`comp` 用可变缓冲（C++ `string` 尾插 / Python `list` + `join`）**。每个字符只被读一次，总时间回到 $O(n)$。

### 3.2 核心观察：游程封顶 9 的贪心切段

![核心概念：长度 L 的游程贪心切成 ⌈L/9⌉ 段](images/wc399_q2_greedy_chunk.svg)

把「反复取最长前缀」翻译成**游程视角**：设某个游程（同一字符连续出现）长度为 $L$，则它被切成的段依次为 $9, 9, \dots, 9, r$——前面 $\lfloor L/9 \rfloor$ 段每段恰好 9，最后可能余一段长度 $r = L \bmod 9$（$r > 0$ 时）。三个要点：

- **段数恰为 $\lceil L/9 \rceil$**：这是「每段 $\le 9$」约束下的**下界**，贪心「先切满 9」恰好取到（证明见 §5），所以按题意操作得到的 `comp` 不仅唯一，而且段数最少；
- **封顶的本质是一位数字**：段长编码只有一个字符位，$10$ 装不下——`"10a"` 按定长 2 的「数字+字符」成对解码会立即错位。计数器**到 9 必须立即冲刷清零**，不能攒到字符切换一起算；
- **同一字符的相邻两段合法**：`"9a5a"` 是正确输出，比赛时任何「合并相邻同字符段」或「判重」的念头都是多余的。

### 3.3 算法流程：双指针一次扫描

![算法流程：双指针一次扫描，触发即冲刷](images/wc399_q2_scan_flow.svg)

外层 `while i < n` 每轮产出一段；内层用 `j` 从 `i` 出发「吃」字符，退出内层即冲刷：

1. 记 `c = word[i]`，`j = i`；
2. 内层循环：只要 `j < n` 且 `word[j] == c` 且 `j − i < 9`，就 `j += 1`；
3. 内层退出于三种触发之一——**封顶**（$j - i = 9$）、**字符切换**（$word[j] \ne c$）、**到达末尾**（$j = n$），无论哪种都立即追加 `(j − i)` 与 `c`，并令 `i = j` 跳到下一段开头；
4. `i = n` 时循环自然结束，返回缓冲区。

不变式：**每轮冲刷时 $len = j - i \in [1, 9]$ 恒成立**（`word` 非空保证内层至少吃 1 个，`len < 9` 条件保证至多吃 9 个），所以代码里不存在 `len = 0` 或 `len = 10` 的分支，无需任何特判。

### 3.4 示例演算

![示例演算：三段走查与 abcde 对照](images/wc399_q2_example_trace.svg)

对示例 2（`"aaaaaaaaaaaaaabb"`）走查：第 1 轮从 `i = 0` 吃 9 个 `a` 触发封顶，追加 `"9a"`；第 2 轮从 `i = 9` 吃 5 个 `a`，遇到字符切换 `a → b`，追加 `"5a"`；第 3 轮吃 2 个 `b` 到达末尾，追加 `"2b"`。最终 `comp = "9a5a2b"`，`a` 游程 2 段 + `b` 游程 1 段，与 $\lceil 14/9 \rceil + \lceil 2/9 \rceil = 3$ 吻合。对照示例 1（`"abcde"`）：5 个长 1 游程全靠字符切换触发，输出 $2n$ 个字符——**压缩不保证变短，最坏反而翻倍**。

## 4. 算法细节

1. **内层三个条件的短路顺序**：`j < n` 必须写在 `word[j] == c` 之前，否则越界访问；`j − i < 9` 放最后，语义是「至多吃 9 个」；
2. **计数与指针合一**：`len = j − i`，不必单独维护计数器，少一个变量也少一处不同步的隐患；
3. **输出缓冲**：C++ 用 `string` 尾插并 `reserve(2 * n)`（输出长度上界 $2n$，全互异字符取到），Python 用 `list.append` + `''.join`——两边都要避开逐次整体拼接的 $O(n^2)$ 陷阱；
4. **数字拼装**：`len ∈ [1, 9]` 保证是一位数字，C++ 可直接 `char('0' + len)`，Python 用 `str(len)`；
5. **等价变体（刷子模式）**：单循环扫一遍，维护 `prev` 与 `cnt`，遇 `c != prev || cnt == 9` 就先冲刷再开新段，末尾补一次冲刷——与双指针版完全等价，且天然支持**流式输入**（一个字符一个字符来也能做）；
6. **groupby 版（Python）**：`itertools.groupby` 先切出游程、按 $\lfloor L/9 \rfloor$ 个整 9 段 + 余数段展开，代码最短，适合当「可读性参考答案」。

## 5. 正确性证明

**引理 1（最长前缀的显式表示）**：设 `word` 从下标 $i$ 起的首字符为 $c$，其游程剩余长度为 $R = \max\{r : word[i..i+r) \text{ 全为 } c\} \ge 1$，则「最长单字符前缀（长度 $\le 9$）」的长度为 $\min(9, R)$。

**证明**：前缀须由单一字符组成，故长度不超过 $R$；又受题设上界 9 约束。两者同时取到即 $\min(9, R)$。∎

**引理 2（游程切分公式）**：长度为 $L$ 的游程被题意操作切成的段长依次为 $9, \dots, 9, r$（$\lfloor L/9 \rfloor$ 个 9，$r = L \bmod 9$，$r > 0$ 时再添一段 $r$），段数为 $\lceil L/9 \rceil$。

**证明**：对剩余量归纳。令 $R_0 = L$，每步由引理 1 切去 $\min(9, R_t)$。当 $R_t \ge 9$ 时切去 9，故经过 $\lfloor L/9 \rfloor$ 步后剩余 $L \bmod 9 < 9$；此时游程未尽（若 $L \bmod 9 > 0$）则一次性切去全部余量 $r$，游程耗尽、前推进到下一游程。段数 $= \lfloor L/9 \rfloor + [L \bmod 9 > 0] = \lceil L/9 \rceil$。∎

**定理（算法与题意等价）**：双指针扫描输出的 `comp` 等于按题意操作得到的 `comp`。

**证明**：算法按 `word` 的游程依次处理，对每个游程由引理 2 的公式切段输出；`i = j` 使下一轮恰好从下一游程开头（或串尾）开始。对游程个数归纳：已处理游程的输出与题意操作逐段一致，处理新游程时由引理 2 两边切分相同，故追加内容相同。归纳至所有游程，二者输出完全一致。∎

**推论（最优性注记）**：题意操作产生的段数 $2\sum_i \lceil L_i/9 \rceil$ 是输出长度的下界——任何合法切法每段 $\le 9$，覆盖游程 $L_i$ 至少需 $\lceil L_i / 9 \rceil$ 段，而每段固定输出 2 个字符、不同字符的段不能合并。本题虽不要求最短，但题意操作天然取到该下界。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`i`、`j` 都单调不回退，每个字符恰好被内层比较一次；缓冲区尾插摊还 $O(1)$；
- **空间复杂度**：$O(n)$，全部花在输出上——输出长度 $2\sum_i \lceil L_i/9 \rceil$，最短约 $2\lceil n/9 \rceil$（全同字符），最长 $2n$（全互异）；辅助变量仅 `i / j / c` 等常数个，辅助空间 $O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string compressedString(string word) {
        int n = word.size(), i = 0;
        string comp;
        comp.reserve(2 * n);                          // 输出长度上界 2n（全互异时取到）
        while (i < n) {
            char c = word[i];
            int len = 0;
            while (i < n && word[i] == c && len < 9) {  // 同字符且未满 9 → 继续吃
                i++, len++;
            }
            comp += char('0' + len);                  // len ∈ [1,9]，一位数字直接拼
            comp += c;
        }
        return comp;
    }
};
```

### Python

```python
class Solution:
    def compressedString(self, word: str) -> str:
        parts = []
        i, n = 0, len(word)
        while i < n:
            c = word[i]
            j = i
            while j < n and word[j] == c and j - i < 9:  # 吃满 9 个或吃到游程尽头
                j += 1
            parts.append(str(j - i))
            parts.append(c)
            i = j
        return ''.join(parts)
```

> 💡 两份代码同一逻辑。Python 亦可写成 `itertools.groupby` 版：对每个游程总长 $L$，输出 `['9', c] * (L // 9)`，余数 `L % 9 > 0` 时再补一段——两行完成「整 9 段 + 余数段」的展开。**共同红线**：不要用 `comp += s`（或切片 `word[k:]`）逐次操作，$n = 2 \times 10^5$ 时最坏 $O(n^2)$。

## 8. 边界情况与易错点

1. **封顶条件写成 `<=`**：内层若写 `len <= 9` 会吃进 10 个字符，输出 `"10a"`——两位数字直接破坏格式，WA 而非 TLE，更难肉眼发现。口诀：**至多吃 9，条件是 `< 9`**；
2. **短路顺序**：`j < n` 必须放在 `word[j] == c` 前面，否则最后一轮越界读；
3. **Python 的 $O(n^2)$ 陷阱**：`comp = comp + s` 每次重建整个串；必须 `list` + `''.join`。同理不要用 `word = word[k:]` 真切片，用下标虚拟消费；
4. **全同字符的规模**：$n = 2 \times 10^5$ 个相同字符时输出长 $2\lceil n/9 \rceil = 44446$，C++ `reserve(2n)` 一次分配足够，中途不会反复扩容拷贝；
5. **相邻同字符段不要合并**：`"9a5a"` 就是答案的一部分，任何「同字符段合并成一段」的后处理都会破坏定长 2 格式；
6. **最小输入**：$n = 1$ 时输出 `"1x"`（`x` 为该字符），由「内层至少吃 1 个」自然覆盖，无需特判；
7. **没有空段**：`word` 非空保证每轮 `len ≥ 1`，不存在输出 `"0a"` 的可能；
8. **压缩可能变长**：全互异字符时输出 $2n$，别在本地测试时被「压缩串比原串长」吓到，这是正确行为。

**延伸思考**：

- **封顶值推广**：若把 9 换成任意 $k$（段长 $\le k$，计数仍一位数字则 $k \le 9$；若允许多位数字则回到 443 格式），只需把内层条件 `len < 9` 换成 `len < k`，段数公式变为 $\lceil L/k \rceil$，复杂度不变；
- **流式压缩**：若字符逐个到达（在线算法），双指针版需要随机访问，改用 §4 的「刷子模式」——维护 `prev / cnt`，字符切换或封顶即冲刷，天然一遍流式；
- **最优压缩视角**：本题输出长度恒为 $2\sum_i \lceil L_i/9 \rceil$（题意操作已取到下界）。若改成「返回最短的合法压缩」且允许自由选择切法，答案不变——因为每段定长 2、段数有下界且贪心取到；但若格式换成 443 的变长计数（如 `"14a"` 占 3 字符），最优切法就变成 DP 问题，正是 1531 的考点。
