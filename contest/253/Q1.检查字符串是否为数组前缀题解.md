# LeetCode 检查字符串是否为数组前缀 题解

## 1. 题目概述

- **标题 / 题号**：检查字符串是否为数组前缀（#1961，easy）
- **链接**：https://leetcode.cn/problems/check-if-string-is-a-prefix-of-array/
- **来源**：LeetCode 第 253 场周赛 Q1
- **难度**：简单
- **标签**：字符串、数组、双指针

**题意**：给定字符串 `s` 和字符串数组 `words`，判断 `s` 是否为 `words` 的**前缀字符串**：即存在正整数 $k \le words.length$，使得 `words` 的**前 $k$ 个字符串按顺序相连**恰好等于 `s`。是则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le words.length \le 100$
- $1 \le words[i].length \le 20$
- $1 \le s.length \le 1000$
- `words[i]` 和 `s` 仅由小写英文字母组成

> 💡 本题在本仓库另有[每日题解 1961](../../solution/1901-2000/1961_检查字符串是否为数组前缀.md)：那边侧重「审题三关键」、游标推进与整串拼接两种写法对照、以及面试问答。本篇按周赛复盘视角，聚焦**签到题从题面到 AC 的最短路径**——「长度是唯一的进度条」这一观察如何把三类判定合并成一个出口、四个返回出口的完整枚举，以及引理-定理化的严格证明。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：s = "iloveleetcode", words = ["i","love","leetcode","apples"]
输出：true
解释：s 可以由 "i"、"love" 和 "leetcode" 相连得到（前 3 个词）。
```

**示例 2**

```text
输入：s = "iloveleetcode", words = ["apples","i","love","leetcode"]
输出：false
解释：数组的前缀相连无法得到 s（第 1 个词首字符即失配）。
```

**示例 3**（自造，覆盖最易错情况）

```text
输入：s = "ilo", words = ["ilove"]
输出：false
解释：逐字符比对 i、l、o 全部通过，但 s 停在 "ilove" 的中间——
      s 只是「前 1 词拼接结果的前缀」，而不是「前 k 个词的拼接」，返回 false。
```

## 3. 解题思路

### 3.1 赛场直觉：逐词拼接 + 整串比较

最直觉的签到写法：维护空串 `prefix`，把 $words[0], words[1], \dots$ 逐个拼上去，每拼完一个词就比较一次 `prefix == s`，相等即 `true`。

问题在于**何时可以停**：

- 不做任何剪枝，会一直拼到最后一个词——本题 $L = \sum |words[i]| \le 2000$ 无所谓，但「拼到什么时候一定没戏了」是一个值得沉淀的观察；
- 更隐蔽的风险是**检查时机**：若只在循环结束后比较一次，会漏掉「中间某个词的词末恰好等于 $s$」的情形（见 §8 易错点 2），词末检查必须每词一次。

### 3.2 核心观察：词界对齐 + 长度是唯一的进度条

![词界对齐概念图：命中情形与词中间耗尽情形对比](images/wc253_q1_word_boundary_concept.svg)

记前 $k$ 个词的拼接长度为 $L(k) = \sum_{j=1}^{k} |words[j-1]|$，$n = |s|$。两个观察合起来就是全部：

**观察 1（词界对齐）**：$s$ 是「前 $k$ 个词的拼接」，不是「拼接结果的前缀」。因此 $s$ 必须恰好落在**某个词的末尾**用尽——长度 $n$ 必须等于某个 $L(k)$。示例 3 中 $n = 3$ 卡在 "ilove" 中间（$L(0) = 0 < 3 < 5 = L(1)$），无论 $k$ 取多少都不行。

**观察 2（长度单调）**：约束保证每词非空（$|words[i]| \ge 1$），故 $L(k)$ 随 $k$ **严格递增**。于是拼接长度一旦**达到或超过** $n$，胜负立判，之后的词一个都不用看：

$$\text{每拼完一个词：}\quad |\text{prefix}| \ge n \ \Longrightarrow\ \text{return prefix} == s$$

这一行同时完成了两类判定——长度**恰好等于** $n$ 时看整串是否相等（词末命中出口），长度**超过** $n$ 时必然 `false`（词中间耗尽出口）。一石二鸟，且最多拼到「长度刚跨过 $n$」的那个词为止，拼接总量 $\le n + 20$。

> 💡 **一句话总结**：盯住长度这一个量——每词非空使 $L(k)$ 严格递增，`len(prefix) >= n` 即见分晓；而 $n$ 必须落在词界上，是「拼接等于 $s$」与「拼接的前缀是 $s$」的唯一区别。

### 3.3 算法流程

```text
1. prefix = ""，n = |s|
2. 对 words 中每个词 w：
     prefix += w
     若 |prefix| >= n：                 ← 长度刚到或刚过 n，判定时机
         return prefix == s             ← == ：词末恰好命中 → true
                                          >  ：词中间耗尽 → false
3. words 用尽仍未达标：return false       ← s 比全部拼接还长（出口 4）
```

四个返回出口一览：

| 出口 | 触发条件 | 返回 | 对应情形 |
|------|----------|------|----------|
| 1 词末命中 | 词末 $i = n$ 且逐段相等 | `true` | $s$ = 前 $k$ 词拼接 |
| 2 逐段失配 | $s$ 对应段与某词不等 | `false` | 任何包含该词的拼接都错位 |
| 3 词中间耗尽 | $i \ge n$ 但词未完 | `false` | $n$ 卡在词中间 |
| 4 词尽长度不足 | 全部拼完 $i < n$ | `false` | $s$ 比全部拼接还长 |

（游标版把出口 2、3 放在字符循环内逐字符判定；拼接版把出口 1、3 合并成 `prefix == s` 一次比较。）

### 3.4 示例演算

![示例演算：词末命中、首字失配、词中间耗尽三个出口](images/wc253_q1_example_walkthrough.svg)

- **示例 1**（出口 1）：游标随 "i"、"love"、"leetcode" 推进 $0 \to 1 \to 5 \to 13$，第 3 词词末恰好 $13 = n$ → `true`，剩余 "apples" 不再消费。
- **示例 2**（出口 2）：第 1 词 "apples" 首字符 'a' 与 $s[0] = $ 'i' 失配 → 一次比较即 `false`。
- **示例 3**（出口 3）：i、l、o 比对通过后游标已达 $3 = n$，比对 'v' 时触发越界保护 → `false`。

## 4. 算法细节

1. **提前终止一石二鸟**：`len(prefix) >= n → return prefix == s` 同时关闭「词末命中」与「词中间耗尽」两个出口。写 `>=` 而非 `>`——长度恰好等于 $n$ 正是唯一可能的判定时机，此时比较整串即分辨 true / false。
2. **拼接版只需在长度达标时比较一次**：长度未达 $n$ 时 `prefix == s` 必为假（长度都不同），无需每词比较；这把比较开销压缩到最终一次 $O(n)$。
3. **游标版（$O(1)$ 空间）**：不构造 `prefix`，维护游标 $i$ 指向 $s$ 的待匹配位置，逐词逐字符比对 `s[i]`；先判 $i \ge n$（越界保护）再取 `s[i]`，词末检查 $i == n$ 即命中。
4. **拼接总量有上界**：提前终止保证实际拼接长度 $\le n + \max|words[i]| \le n + 20$，C++ 的 `string +=` 与 Python 的 `str +=` 都不会产生可观开销（本题规模下无需 `join` 优化）。
5. **k 的唯一性**：由 $L(k)$ 严格递增，满足 $L(k) = n$ 的 $k$ 至多一个，命中即可无条件 `return true`，不存在多解或漏解。

## 5. 正确性证明

记 $m = words.length$，$L(0) = 0$，$L(k) = \sum_{j=1}^{k} |words[j-1]|$，$n = |s|$。以游标版叙述（拼接版的 `prefix` 即游标的镜像，同理）。

**引理 1（长度严格递增）**：$L(k)$ 关于 $k$ 严格递增；从而若存在 $k \in [1, m]$ 使 $L(k) = n$，则 $k$ 唯一。

**证明**：$L(k) - L(k-1) = |words[k-1]| \ge 1$，故严格递增；严格递增序列中 $n$ 至多出现一次。∎

**引理 2（循环不变式）**：算法开始处理第 $j$ 个词（$1 \le j \le m$）且尚未返回时，必有 $L(j-1) < n$，且 $s[0..L(j-1))$ 与前 $j-1$ 个词的拼接完全一致（游标 $i = L(j-1)$）。

**证明**（对 $j$ 归纳）：$j = 1$ 时 $L(0) = 0 < n$（约束 $n \ge 1$），空串一致，成立。设处理第 $j$ 词时不变式成立：逐字符比对中若失配或 $i$ 达到 $n$ 即返回（不变式无需延续）；若词 "words[j-1]" 全部比对通过且词末 $i < n$，则 $i = L(j-1) + |words[j-1]| = L(j) < n$ 且 $s[0..L(j))$ 与前 $j$ 词拼接一致，不变式对 $j+1$ 成立。∎

**定理**：算法返回 `true` 当且仅当存在 $k \in [1, m]$ 使 $s$ 等于前 $k$ 个词的拼接。

**证明**：

（⇐）设 $s$ 为前 $k$ 词拼接，由引理 1 该 $k$ 唯一。对 $j = 1, \dots, k$ 归纳（引理 2 同款推理）：算法处理第 $j \le k$ 词时不变式成立且 $L(j-1) < n$（因 $L(k) = n$ 与严格递增）；处理第 $k$ 词时 $s$ 的区间 $[L(k-1), L(k))$ 恰为 $words[k-1]$，逐字符全部通过，词末 $i = L(k) = n$ → 返回 `true`。

（⇒）返回 `true` 只在词末 $i = n$ 处触发；由引理 2，此时 $i = L(j)$ 且 $s[0..L(j))$ 与前 $j$ 词拼接一致，故 $s$ 即前 $j$ 词拼接，$k = j$。

（`false` 侧的三个出口均正确）：

- **失配出口**：处理第 $j$ 词时某字符失配。对 $k < j$：由引理 2 知 $L(j-1) < n$，而 $L(k) \le L(j-1) < n$，长度不足；对 $k \ge j$：前 $k$ 词拼接在区间 $[L(j-1), L(j))$ 的第 $j$ 段是 $words[j-1]$，与 $s$ 对应位置不一致。故一切 $k$ 都不可行，`false` 正确。
- **越界出口**（词中间耗尽）：此时 $L(j-1) < n < L(j)$。对 $k \le j-1$：$L(k) \le L(j-1) < n$；对 $k \ge j$：$L(k) \ge L(j) > n$。由引理 1，任何 $L(k) \ne n$，`false` 正确。
- **词尽出口**：$L(m) < n$，对一切 $k$ 有 $L(k) \le L(m) < n$，长度不足，`false` 正确。

综上，定理成立。∎

## 6. 复杂度分析

- **时间复杂度**：$O(\min(L, n))$，其中 $L = \sum |words[i]|$。游标版逐字符比对至多 $\min(L, n) + 1$ 次；拼接版拼接总量 $\le n + 20$、长度达标时整串比较一次 $O(n)$。失配 / 越界 / 命中均提前返回，最坏情况也不超过一轮扫描。
- **空间复杂度**：拼接版 $O(n + 20)$ 存储 `prefix`；游标版仅游标 $i$ 与长度 $n$ 两个变量，$O(1)$ 额外空间。

本题 $n \le 1000$、$L \le 2000$，任何写法都瞬时返回；差异只在「避免无谓拼接」的工程习惯。

## 7. 参考代码

### C++（拼接 + 提前终止：赛场最短路径）

```cpp
class Solution {
  public:
    bool isPrefixString(string s, vector<string>& words) {
        string prefix;
        for (const string& w : words) {
            prefix += w;
            if (prefix.size() >= s.size()) return prefix == s;
        }
        return false;
    }
};
```

### Python（拼接版 + 游标版）

```python
class Solution:
    def isPrefixString(self, s: str, words: List[str]) -> bool:
        prefix = ""
        for w in words:
            prefix += w
            if len(prefix) >= len(s):
                return prefix == s
        return False
```

```python
class Solution:
    def isPrefixString(self, s: str, words: List[str]) -> bool:
        i, n = 0, len(s)
        for w in words:
            for c in w:
                if i >= n or s[i] != c:
                    return False
                i += 1
            if i == n:
                return True
        return False
```

> 💡 游标版「越界保护 + 失配返回 + 词末检查」三要素的逐步展开与面试问答，见[每日题解 1961](../../solution/1901-2000/1961_检查字符串是否为数组前缀.md)；周赛现场追求提交速度，拼接版五行即可 AC。

## 8. 边界情况与易错点

1. **方向搞反（最致命）**：判「拼接结果的前缀是 $s$」（即 `t.startswith(s)`）是错的——那会把示例 3 的 "ilo" 误判为 `true`。必须判「$s$ 恰好等于前 $k$ 词的拼接」，即 $n$ 落在词界上。
2. **漏词末检查**：只在循环结束后比较一次 `prefix == s`，会漏掉「中间某词词末恰好等于 $s$」的情形。反例：`s = "i"`, `words = ["i","love"]`——循环外比较得 "ilove" ≠ "i" 返回 `false`，正确答案应为 `true`。检查必须发生在**每个词拼完之后**。
3. **`>=` 而非 `>`**：长度恰好等于 $n$ 时正是判定时机。若只写 `> n return false` 而无相等检查，会漏 `true`；统一写成 `>= n → return prefix == s` 最不易错。
4. **k 为正数**：至少拼一个词。本题 $n \ge 1$ 且每词非空，无需空串特判；若放宽约束允许 $n = 0$，也**不能**返回 `true`（$k$ 为正数，拼接至少 1 个字符）。
5. **$s$ 比全部拼接还长**：出口 4，别忘了循环外 `return false`。
6. **游标版短路顺序**：`i >= n || s[i] != c` 中越界判断必须在前，颠倒会越界访问 `s[n]`（C++ 未定义行为 / Python 抛 IndexError）。
