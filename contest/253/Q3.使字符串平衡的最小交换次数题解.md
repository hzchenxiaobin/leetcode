# LeetCode 使字符串平衡的最小交换次数 题解

## 1. 题目概述

- **标题 / 题号**：使字符串平衡的最小交换次数（#1963，medium）
- **链接**：https://leetcode.cn/problems/minimum-number-of-swaps-to-make-the-string-balanced/
- **来源**：LeetCode 第 253 场周赛 Q3
- **难度**：中等
- **标签**：贪心、栈、双指针、字符串、括号序列

**题意**：给定下标从 0 开始、长度为偶数 $n$ 的字符串 $s$，它**恰好**由 $n/2$ 个 `'['` 与 $n/2$ 个 `']'` 组成（平衡即经典括号匹配：空串平衡；$s = AB$ 与 $s = [C]$ 由平衡子串拼接/包裹亦平衡）。可交换**任意**两个下标对应的括号**任意**多次，求使 $s$ 变成平衡串的**最少交换次数**。

**约束**：

- $2 \le n \le 10^6$，$n$ 为偶数 —— 排除「真正模拟交换」的反复扫描 $O(n^2)$，必须单趟 $O(n)$ 计数
- $s_i \in \{[\,,\,]\}$，两种括号各 $n/2$ 个 —— 字符多重集恒定不变，答案必定存在且只由「错位程度」决定

> 💡 本题在本仓库另有[每日题解 1963](../../solution/1901-2000/1963_使字符串平衡的最小交换次数.md)：那边主打「balance 跌负即交换、就地 $+2$ 修正」的贪心扫描与面试问答。本篇按周赛复盘视角，主打**残形归约**——先抵消一切可配对括号，把任意原串压缩成规范残形 $]^k[^k$，问题的本质参数只剩一个 $k$，答案即 $\lceil k/2 \rceil$；并以引理-定理结构完整证明下界（前缀盈余每次交换至多降 2）与上界（首尾配对交换的归纳构造），复盘「计数 $k$」与「数跌负次数」两套易混的计数器。两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路：真正执行交换

最直觉的做法是把交换**真做出来**：反复扫描找到使 balance 跌负的位置，把它与后面某个 `[` 交换、计数加一，直到全串平衡。正确性没问题——每次消除一个「超前 `]`」，最终所有前缀满足 $\#[\, \ge \#]$ 即平衡。

- **效率**：每轮扫描 $O(n)$、最多约 $n/4$ 轮交换，整体 $O(n^2)$；$n = 10^6$ 时约 $2.5 \times 10^{11}$ 次字符操作，**超时**。若用 BFS 在状态空间里搜最少步数更是天方夜谭——状态数 $\binom{n}{n/2}$ 指数级。
- **浪费所在**：题面只要**次数**，不要方案。真正执行交换、维护字符串全程都是无用功——我们需要的只是把「错位程度」压缩成一个数。

### 3.2 核心观察：抵消配对，残形归约为 $]^k[^k$

![核心观察：抵消配对后残形为 ]^k[^k，首尾配对交换每轮消掉两个错位](images/wc253_q3_residual_form_concept.svg)

用栈消配对（遇 `[` 计数 $+1$，遇 `]` 且计数 $>0$ 则 $-1$）把所有能配对的括号全部抵消，原串被压缩成规范**残形**：

$$\underbrace{]\,]\,\cdots\,]}_{k\ \text{个超前 ]}}\ \underbrace{[\,[\,\cdots\,[}_{k\ \text{个未闭 [}}$$

**观察 1（残形唯一参数）**：由两种括号总数相等，未匹配 `]` 数恒等于未匹配 `[` 数，记为 $k$。原串长得再花哨（错位括号中间可以夹任意平衡段），抵消后的**骨架**只由 $k$ 决定。

**观察 2（一次交换修复两处）**：交换一个超前 `]` 与一个未闭 `[`，两处同时归位——新的 `[` 就地与旁边的超前 `]` 配对，新的 `]` 与旁边的未闭 `[` 配对。$k$ 为偶数时每轮恰好 $-2$；$k$ 为奇数时最后一轮剩一对 `][`，交换后直接平衡。

$$\boxed{\text{答案} = \left\lceil \frac{k}{2} \right\rceil \qquad k = \text{栈消配对后剩余的未匹配括号数}}$$

> 💡 **一句话总结**：括号序列题的万能第一步是「**抵消 → 残形 → 公式**」——先消掉一切合法配对，让问题的本质参数现形。921（残形 → 插 $k_\text{闭} + k_\text{开}$ 个）、1249（残形 → 删同样多个）都是这个骨架；本题的特殊之处在于**交换一次能同时修两处**，所以答案从 $k$ 折半成 $\lceil k/2 \rceil$。

### 3.3 算法流程：单趟扫描计数 + 公式

![算法流程：单趟栈计数器扫描，终值 k 套公式 (k+1)/2](images/wc253_q3_scan_count_flow.svg)

```text
1. open ← 0（栈深计数器：当前未配对的 [ 数）
2. 逐字符扫描 s：
      c = '['  → open++            （入栈）
      c = ']'  → open > 0 则 open--（配对消去）
                 open = 0 则跳过    （超前 ]，属于残形左半，不入栈）
3. 扫描结束，open 即 k（未匹配 [ 数 = 未匹配 ] 数）
4. 返回 (k + 1) / 2
```

**为什么 `open = 0` 时不能 `open--`**：超前 `]` 遇到空栈，它属于残形左半；若让计数变负，`open` 就混杂了「栈深」与「超前数」两种语义，终值不再等于 $k$。让超前 `]` 直接跳过，$k$ 自然等于扫完后仍在「栈上」的 `[` 数。

### 3.4 示例演算

![示例演算：]]][[[ 的 balance 跌至 −3，两次首尾交换归位](images/wc253_q3_example_walkthrough.svg)

以**示例 2** `s = "]]][[["` 演算（balance = 前缀 $\#[\, - \#]$）：

| $i$ | 字符 | balance | 栈计数器 open | 事件 |
|-----|------|---------|---------------|------|
| 0 | `]` | −1 | 0 | 超前 ]（未匹配 #1） |
| 1 | `]` | −2 | 0 | 超前 ]（未匹配 #2） |
| 2 | `]` | −3 | 0 | 超前 ]（未匹配 #3） |
| 3 | `[` | −2 | 1 | 入栈 |
| 4 | `[` | −1 | 2 | 入栈 |
| 5 | `[` | 0 | 3 | 入栈，扫描结束 |

$k = \text{open} = 3$（亦即 $-\min \text{balance} = 3$），答案 $(3+1)/2 = 2$ ✓。

构造性方案（首尾配对交换）：未匹配 `]` 在下标 $\{0,1,2\}$、未匹配 `[` 在 $\{3,4,5\}$——

```text
]]][[[   交换 (0, 5)：最左未匹配 ] ↔ 最右未匹配 [
[]][[]   交换 (2, 3)：新一对未匹配 ] ↔ [（k: 3 → 1）
[][][]   平衡！k → 0，共 2 次 ✓
```

**示例 1** `"][]["`：$k = 1$，答案 $1$，交换 $(0, 3)$ 得 `[[]]`。**示例 4** `"[]]][][["`：首部 `[]` 与中部 `[]` 抵消，残形为 $]^2[^2$（即 `]][[`），$k = 2$，答案 $1$，交换 $(2, 7)$ 得 `[][][][]` ✓。**示例 3** `"[]"`：$k = 0$，答案 $0$。

> ⚠️ 注意示例 2 中两次交换修掉 $3$ 个超前 `]`：第一次交换顺带把第 2 个超前 `]`「救活」（它与换来的 `[` 配对）。这正是答案 $\ne k$ 的原因——**别把答案写成超前 `]` 总数**。

## 4. 算法细节

1. **两套计数器，别混写**：「跌负计数」版（每日题解主推）扫到 balance $< 0$ 就 `swaps++` 并就地 `balance += 2`，计的是**交换次数本身**；本篇「栈计数」版只维护 `open`，终值套公式 $\lceil k/2 \rceil$。两者等价（跌负只发生在残形 $]^k$ 的第 $1, 3, 5, \dots$ 个 `]` 上，触发次数恰为 $\lceil k/2 \rceil$），但**变量语义不同**，混在同一份代码里必然出错。
2. **`k` 的另一种等价读法**：$k = -\min_p \text{balance}(p)$（前缀 balance 的最低点取负，见 §5 引理 2③）。用 `minBalance` 维护同样一趟可得 $k$，与栈计数互为印证——调参时可以对着拍。
3. **上取整写法**：`(k + 1) / 2`（C++ / Python 整数除法下取整，$+1$ 恰好把 $\lceil \cdot \rceil$ 做对）；等价写法 `k / 2 + k % 2`。$k$ 为奇数时漏掉上取整会少算一次。
4. **若题目还要求输出具体交换方案**：用**首尾双指针**模拟 §5 定理的构造——左指针找最左未匹配 `]`（左向 balance 首次跌负处）、右指针找最右未匹配 `[`（右向逆 balance 首次跌负处），交换后两侧计数器各就地 $+2$ 继续扫。两指针各自单调向中间移动，总复杂度 $O(n)$；简单起见也可每轮整串重扫（$O(kn)$，仅演示用，见 §7 构造版）。
5. **C++ 性能**：$n = 10^6$，`for (char c : s)` 顺序遍历 `std::string` 即可（实测毫秒级）；无需真的开栈数组存字符或下标——单括号种类的栈可压缩成一个 `int` 计数器。
6. **别修改原串**：交换次数与「谁和谁换」无关（§5 只用计数），全程只读扫描，$O(1)$ 辅助空间。

## 5. 正确性证明

**引理 1（平衡的逐前缀判定）**：设 $s$ 中 `[` 与 `]` 总数相等，则 $s$ 平衡 $\Leftrightarrow$ $s$ 的每个前缀满足 $\#] \le \#[$。

**证明**：（$\Rightarrow$）对平衡的递归定义做结构归纳：空串平凡；$s = AB$ 时，$s$ 的前缀或为 $A$ 的前缀（归纳假设），或为 $A$ 拼上 $B$ 的前缀——由 $A$ 两类括号总数相等（对平衡定义归纳易得），后者盈余与 $B$ 的对应前缀相同，仍非负；$s = [C]$ 时，前缀或为 `[`（盈余 $-1 \le 0$）、或为 `[` 加 $C$ 的前缀（盈余 $= -1 + C$ 的前缀盈余 $\le -1$，归纳假设）、或为整个 $[C]$（盈余 $0$）。（$\Leftarrow$）对 $n$ 归纳：首字符必为 `[`（否则首前缀盈余 $1 > 0$）。设 $m$ 为 balance 首次回到 $0$ 的位置（存在：全程 balance $\ge 0$ 且末尾为 $0$），则 $s = [A]B$，其中 $1 \le m \le n-1$。对 $1 \le p < m$ 有 $\text{balance}(p) \ge 1$（首次归零在 $m$），故 $A$ 的每个前缀 balance $= \text{balance}(p+1) - 1 \ge 0$ 且 $A$ 总量平衡，归纳得 $A$ 平衡；$B$ 的前缀 balance 与 $s$ 中对应前缀相同，同理平衡。故 $s = [A]B$ 平衡。∎

**引理 2（残形结构与参数 $k$）**：栈消配对后，记未匹配 `]` 的位置 $u_1 < \cdots < u_k$、未匹配 `[` 的位置 $v_1 < \cdots < v_k$。则：① $u_k < v_1$（所有超前 `]` 都在所有未闭 `[` 之前）；② $s$ 可分解为

$$s = A_0\,]\,A_1\,]\,\cdots\,]\,A_{k-1}\,]\,C\,[\,D_1\,[\,\cdots\,[\,D_{k-1}\,[\,D_k$$

其中 $A_0$ 在 $u_1$ 之前、$A_i$ 夹在 $u_i, u_{i+1}$ 之间、$C$ 夹在 $u_k, v_1$ 之间、$D_i$ 夹在 $v_i, v_{i+1}$ 之间、$D_k$ 在 $v_k$ 之后，且**它们都是平衡串**；③ $k = -\min_p \text{balance}(p)$，最低点在 $p = u_k$ 处取得。

**证明**：① 反证：设未匹配 `[` 位置 $v <$ 未匹配 `]` 位置 $u$。栈扫描到 $u$ 时，$v$ 自入栈起从未被弹出（它未匹配），仍在栈中，故栈非空，$u$ 处的 `]` 应弹栈配对而非未匹配，矛盾。② 关键是「**未匹配括号是配对的屏障**」。以 $C$ 段为例：$C$ 内某 `[` 若与 $C$ 后的 `]` 配对，则栈中位于其上的所有字符（含 $v_1$——它在 $C$ 之后入栈且永不弹出）必须先被弹出，矛盾，故 $C$ 内 `[` 的配对者都在 $C$ 内；又 $C$ 起于栈空（$u_k$ 处栈被清空），$C$ 内 `]` 只能弹 $C$ 内入栈的 `[`（否则遇空栈成为又一个超前 `]`，与未匹配集恰为 $\{u_i\}$ 矛盾）。故 $C$ 内部自配对且配对合法，是平衡串。$A_i$ 段（两端栈空）、$D_i$ 段（下方有永不弹出的 $v_i$ 挡底、上方被 $v_{i+1}$ 挡住）同理。③ 恒等式 $\text{balance}(p) = \text{栈深}(p) - \#(\text{超前 } ] \text{ 在 } p \text{ 前})$：前缀内完整配对的 `[` 与 `]` 贡献相消，栈上「已入未弹」的 `[`（含跨界配对者与前方的未匹配 `[`）各贡献 $+1$，超前 `]` 各贡献 $-1$。在 $p = u_k$ 处栈空（① 保证此前无未匹配 `[`）且超前 `]` 恰有 $k$ 个，故 $\text{balance}(u_k) = -k$；而任意 $p$ 处栈深 $\ge 0$、超前数 $\le k$，$\text{balance}(p) \ge -k$。∎

**引理 3（单次交换的杠杆率）**：交换两个位置 $i < j$ 上的字符后，任一固定前缀位置集 $P$ 的盈余（$\#] - \#[$）改变量属于 $\{-2, 0, +2\}$。

**证明**：交换相同的字符不改变任何东西。设交换 `[` 与 `]`：若 $i, j$ 同在 $P$ 内或同在 $P$ 外，$P$ 的字符多重集不变，盈余不变；若 `]` 在 $P$ 内而 `[` 在 $P$ 外（或反之），$P$ 以一换一，盈余变化 $\mp 2$。∎

**定理（答案 $= \lceil k/2 \rceil$）**：使 $s$ 平衡的最少交换次数恰为 $\lceil k/2 \rceil$。

**证明**：

**下界**。取 $P$ 为前缀 $[0, u_k]$（引理 2② 中 $u_k$ 及其之前的位置）。由引理 2③，$P$ 的初始盈余为 $k$。终态是平衡串，由引理 1 其每个前缀（含 $P$）盈余 $\le 0$。由引理 3，每次交换至多把 $P$ 的盈余降低 $2$，故至少需要 $\lceil k/2 \rceil$ 次交换。

**上界（归纳构造）**。对 $k$ 归纳：$k = 0$ 时 $s$ 已平衡（引理 1，总量相等），$0$ 次。$k \ge 1$ 时，交换 $u_1$（最左超前 `]`）与 $v_k$（最右未闭 `[`）。在引理 2② 的分解式上重跑栈算法：新 `[`（原 $u_1$ 处）入栈后穿过平衡段 $A_1$，被 $u_2$ 处的 `]` 弹出——$u_1, u_2$ 连同 $A_1$ 组成平衡块 $[A_1]$；新 `]`（原 $v_k$ 处）把 $v_{k-1}$ 处的 `[` 弹出——$v_{k-1}, v_k$ 连同 $D_{k-1}$ 组成平衡块 $[D_{k-1}]$。于是新串的未匹配集为 $\{u_3, \dots, u_k\}$ 与 $\{v_1, \dots, v_{k-2}\}$，各 $k - 2$ 个，且仍满足引理 2 的全部结构（①②③ 对新串成立）。若 $k \ge 2$，由归纳假设再需 $\lceil (k-2)/2 \rceil$ 次，总计 $1 + \lceil (k-2)/2 \rceil = \lceil k/2 \rceil$；若 $k = 1$，残形为 $A_0\,]\,C\,[\,D_1$，一次交换直接得 $A_0\,[\,C\,]\,D_1$——三个平衡串的拼接，平衡（引理 1），总计 $1 = \lceil 1/2 \rceil$。∎

> 💡 **证明的骨架**是「**残形归约 + 杠杆率上下界夹逼**」：抵消把任意串压成 $]^k[^k$（引理 2），一次交换对固定前缀盈余的杠杆率至多为 2（引理 3）给出下界，首尾配对交换每轮实打实消掉两个错位（归纳构造）给出匹配的上界。任何「交换/移动修复括号」类问题都可以先做残形归约，再看**单次操作的杠杆率**定公式——对照 921 的「插入杠杆率 1 → 答案 $k_\text{闭} + k_\text{开}$」与本题的「交换杠杆率 2 → 答案 $\lceil k/2 \rceil$」。

## 6. 复杂度分析

- **时间复杂度**：$O(n)$——单趟顺序扫描，每字符 $O(1)$ 分支（入栈 / 配对 / 跳过），最后 $O(1)$ 套公式。$n = 10^6$ 时实测毫秒级（本机 Python 0.09s、C++ 更快），对比暴力 $O(n^2) \approx 2.5 \times 10^{11}$ 快约五个数量级。
- **空间复杂度**：$O(1)$——仅 `open`（或 `balance`）一个整型计数器加常数个标量；不修改原串、不建栈数组。$k \le n/2 \le 5 \times 10^5$，`int` 足够。

## 7. 参考代码

### C++（栈计数器 + 公式）

```cpp
class Solution {
  public:
    int minSwaps(string s) {
        int open = 0; // 栈深计数器：当前未配对的开括号数
        for (char c : s) {
            if (c == '[') {
                ++open;          // 入栈
            } else if (open > 0) {
                --open;          // 与最近的未配对 [ 消去
            }
            // else：超前 ]，不入栈——它属于残形 ]^k[^k 的左半
        }
        return (open + 1) / 2;   // open = k，上取整除以 2
    }
};
```

### Python（栈计数器 + 公式）

```python
class Solution:
    def minSwaps(self, s: str) -> int:
        open_ = 0 # 栈深计数器：当前未配对的开括号数
        for c in s:
            if c == '[':
                open_ += 1        # 入栈
            elif open_ > 0:
                open_ -= 1        # 配对消去
            # else：超前 ]，跳过
        return (open_ + 1) // 2   # open_ = k
```

### Python（构造版：首尾双指针模拟真实交换）

```python
class Solution:
    def minSwaps(self, s: str) -> int:
        s = list(s)
        swaps = 0
        while True:
            b = p = 0
            for i, c in enumerate(s):        # 左起找最左未匹配 ]（balance 首跌负）
                b += 1 if c == '[' else -1
                if b < 0:
                    p = i
                    break
            else:
                return swaps                 # 全程未跌负 → 已平衡
            b = 0
            for i in range(len(s) - 1, -1, -1):  # 右起找最右未匹配 [
                b += 1 if s[i] == ']' else -1
                if b < 0:
                    q = i
                    break
            s[p], s[q] = s[q], s[p]          # 首尾配对交换（§5 定理的构造）
            swaps += 1
```

> 💡 **写法对照**：①② 计数版是提交首选——$O(n)$ 时间、$O(1)$ 空间、只读不写；③ 构造版每轮整串重扫是 $O(kn)$，仅为演示定理的交换方案（若题目追问「输出每次交换的下标」，把 `p, q` 记录下来即可；两指针单调内移，增量维护可收紧到 $O(n)$）。与[每日题解 1963](../../solution/1901-2000/1963_使字符串平衡的最小交换次数.md) 的「跌负即交换 $+2$ 修正」版对照：计数对象不同（跌负次数 vs 未配对数 $k$），殊途同归于 $\lceil k/2 \rceil$。

## 8. 边界情况与易错点

1. **答案不是超前 `]` 的总数 $k$**：一次交换同时修复两处，答案是 $\lceil k/2 \rceil$。`]]][[[` 有 3 个超前 `]`，答案却是 2——第一次交换顺带救活了相邻的超前 `]`。把公式写成 `k` 或漏掉上取整是最高频的 WA 点。
2. **`open > 0` 的判断不能省**：遇 `]` 无脑 `open--` 会让计数变负，终值混杂「栈深」与「超前数」两种语义；超前 `]` 必须直接跳过，$k$ 才等于扫完后仍在栈上的 `[` 数。
3. **别把「跌负计数」与「栈计数」混写**：两套计数器变量语义不同（§4 第 1 条），一份代码里只留一套。
4. **$k$ 的两种读法要分清**：栈计数终值 = 未匹配 `[` 数；$-\min\text{balance}$ = 最大前缀盈余。两者相等（引理 2③），但对拍调试时别拿 $-\text{balance}(n-1)$（恒为 0）当 $k$。
5. **极端输入**：`[]`（$k=0$，答案 0）；$]^{n/2}[^{n/2}$（$k = n/2$ 最坏，答案 $n/4$，如 $n = 10^6$ 时答案 $25 \times 10^4$）；交错型 `][][`（$k=1$，答案 1）。
6. **性能红线**：$n \le 10^6$ 时反复扫描模拟交换 $O(n^2)$ 必超时；真开 `stack<char>` 存字符也是无谓的 $O(n)$ 空间——单括号种类把栈压缩成一个计数器即可（与 921 的退化技巧同源）。
7. **溢出检查**：$k \le n/2 \le 5 \times 10^5$，`int` 全程够用，无需 `long long`（Python 无此问题）。

**延伸思考**：

- 若只允许**交换相邻**两个字符，答案还由 $k$ 决定吗？（提示：不再只由 $k$ 决定，还依赖错位括号的距离。对极端残形 $]^k[^k$：终态第 $j$ 个 `[` 至多落在第 $2j-1$ 位（引理 1 的逐前缀约束），它原在第 $k+j$ 位，左移量 $\ge k-j+1$，求和得下界 $k(k+1)/2$；直接配对逐一搬运恰可达到。对比任意交换的 $\lceil k/2 \rceil$，体会「操作粒度决定杠杆率」。）
- 若两种括号数目**不保证相等**？先判无解（交换不改变多重集），再对残形 $]^{k_1}[^{k_2}$ 讨论——此时没有任何交换方案能补齐差值。
- 若还要求**输出具体交换序列**且严格 $O(n)$？把 §7 构造版改成增量式：左右两个扫描指针各自单调内移、交换后就地给两个 balance 计数器 $+2$，总移动量 $2n$。
- 「抵消 → 残形 → 公式」还能推广到**多种括号**（`()`、`[]`、`{}`）吗？（提示：多类括号的未匹配结构不再是一维残形——`([)]` 抵消后无未匹配却不平衡，栈深信息压缩失效，这是单类括号独有的红利。）
