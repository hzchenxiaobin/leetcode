# LeetCode 移除石子使总数最小 题解

## 1. 题目概述

- **标题 / 题号**：移除石子使总数最小（#1962，medium）
- **链接**：https://leetcode.cn/problems/remove-stones-to-minimize-the-total/
- **来源**：LeetCode 第 253 场周赛 Q2
- **难度**：中等
- **标签**：贪心、数组、堆（优先队列）

**题意**：给定数组 `piles`（`piles[i]` 为第 $i$ 堆石子数）与整数 $k$，执行下述操作**恰好** $k$ 次：任选一堆 `piles[i]`，从中移除 $\lfloor \text{piles}[i] / 2 \rfloor$ 颗石子（可对同一堆多次操作）。返回 $k$ 次操作后剩余石子的**最小**总数。

**约束**：

- $1 \le \text{piles.length} \le 10^5$
- $1 \le \text{piles}[i] \le 10^4$
- $1 \le k \le 10^5$

> 💡 本题在本仓库另有[每日题解 1962](../../solution/1901-2000/1962_移除石子使总数最小.md)：那边侧重审题关键（操作等价于 $p \to \lceil p/2 \rceil$）、Python 两版写法对照与面试问答。本篇按周赛复盘视角，聚焦套路沉淀——把「每轮取最大 + 衰减变换 + 推回」抽象为**堆独立的边际收益递减分配问题（凸贪心）**，给出名额分配视角下的严格引理-定理证明，并复盘赛场上最容易踩的两个直觉陷阱（均分名额、排序后轮流）。两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：piles = [5, 4, 9], k = 2
输出：12
解释：
- 对第 2 堆操作：移除 ⌊9/2⌋ = 4，piles = [5, 4, 5]
- 对第 0 堆操作：移除 ⌊5/2⌋ = 2，piles = [3, 4, 5]
- 剩余总数 = 3 + 4 + 5 = 12
```

**示例 2**

```text
输入：piles = [4, 3, 6, 7], k = 3
输出：12
解释：
- 对第 3 堆操作：移除 3，piles = [4, 3, 6, 4]
- 对第 2 堆操作：移除 3，piles = [4, 3, 3, 4]
- 对第 0 堆操作：移除 2，piles = [2, 3, 3, 4]
- 剩余总数 = 2 + 3 + 3 + 4 = 12
```

**示例 3**（自造，覆盖名额远多于所需的情况）

```text
输入：piles = [7], k = 10
输出：1
解释：7 → 4 → 2 → 1 只需 3 次有效操作（分别移除 3、2、1），
      之后 ⌊1/2⌋ = 0，剩余 7 次操作移除量为 0，总数保持 1。
```

## 3. 解题思路

### 3.1 赛场直觉与两个陷阱

最小化剩余总数 $\Leftrightarrow$ 最大化 $k$ 次操作的总移除量。这题是标准套路题，但赛场上有两个直觉陷阱值得复盘：

**陷阱 1：把 $k$ 次操作「均分」给各堆。** 反例 `piles = [100, 1, 1, 1], k = 4`：均分（每堆一次）得 $50 + 1 + 1 + 1 = 53$；正确做法是 4 次全砸最大的堆（$100 \to 50 \to 25 \to 13 \to 7$），得 $7 + 3 = 10$。名额应该流向「边际收益」高的堆，而不是平均主义。

**陷阱 2：排序后从大到小轮流操作一遍。** 反例 `piles = [8, 1], k = 2`：轮流（$8 \to 4$、$1 \to 1$，移除 0）得 5；正确做法是连续操作最大堆（$8 \to 4 \to 2$），得 3。排序只反映**初始**大小——操作后最大值会变化（例 1 中 9 变 5 后与原 5 并列最大），静态排序无法跟踪。

排除陷阱后的朴素正确做法：每轮线性扫描找当前最大堆再操作，总计 $O(nk)$；本约束下 $n, k \le 10^5$，约 $10^{10}$ 次基本操作，**TLE**。瓶颈只有一个——**动态最大值的维护**，这正是堆的招牌场景。

### 3.2 核心观察：堆独立 + 边际收益递减（凸贪心）

![核心观察：堆独立与边际收益递减，逐名额摘走当前最大边际](images/wc253_q2_marginal_greedy_concept.svg)

**观察 1（堆独立）**：操作只作用于**单一堆**，堆与堆之间没有任何交互。因此一个策略的最终结果只由「每堆被操作了多少次」决定——$k$ 次操作就是 $k$ 个**名额**的分配方案 $(c_1, \dots, c_n)$，$\sum_i c_i = k$，剩余总数为 $\sum_i f^{(c_i)}(p_i)$，其中 $f(p) = p - \lfloor p/2 \rfloor = \lceil p/2 \rceil$ 是单堆一次操作的效果。

**观察 2（边际收益递减）**：对初值为 $p$ 的堆，第 $c{+}1$ 次操作的移除量（边际）为 $\delta_c = \big\lfloor f^{(c)}(p)/2 \big\rfloor$。由于操作让堆值不增（$f(p) \le p$），边际序列 $\delta_0 \ge \delta_1 \ge \delta_2 \ge \cdots$ **单调递减**——第一刀最肥，越割越瘦。

于是问题变成经典的**边际递减分配问题**：$k$ 个名额逐个发出，每个名额应给「当前边际最大」的堆。由 $\lfloor p/2 \rfloor$ 关于 $p$ 单调，「当前边际最大」$\Leftrightarrow$「**当前值最大**」——名额永远给当前最大堆。这就是**凸贪心**（marginal analysis）：不需要反悔、不需要 DP，因为已摘走的边际都是当时的全局最大，而未摘走的边际只会更小。

$$\boxed{\text{每轮：取当前最大 } t,\quad t \leftarrow t - \lfloor t/2 \rfloor,\quad \text{重复 } k \text{ 次}}$$

> 💡 **一句话总结**：「取最大 + 衰减变换 + 推回」能贪心的本质是**衰减变换单调 + 值域压缩**带来边际递减；这个框架在 2558（开方）、2530（取 $\lceil p/3 \rceil$）等题中反复出现，是周赛堆贪心的第一套路。

### 3.3 算法流程

![算法流程：建大根堆，k 轮摘堆顶减半推回，同步维护 sum](images/wc253_q2_algorithm_flow.svg)

```text
1. pq ← 将 piles 建成大根堆（O(n)）；sum ← Σ piles
2. 重复 k 次（堆顶为 1 时可提前终止：后续移除量恒为 0）：
      t ← 堆顶（当前最大）
      sum −= ⌊t/2⌋            ← 同步扣减，免最后求和
      堆顶替换为 t − ⌊t/2⌋     ← pop + push，或 heapreplace 一步完成
3. 返回 sum
```

**求和技巧**：不最后清空堆求和（C++ `priority_queue` 不支持遍历，逐个 pop 是 $O(n \log n)$），而是初始化 `sum = Σ piles`，每轮 `sum -= ⌊t/2⌋`——$O(1)$ 维护，返回时直接可用。

### 3.4 示例演算

![示例演算：两道官方示例的堆顶动态变化与 sum 扣减](images/wc253_q2_example_walkthrough.svg)

以**示例 1** `piles = [5, 4, 9], k = 2` 演算（堆内按从大到小排列）：

| 轮次 | 堆（堆顶加粗） | 堆顶 $t$ | 移除 $\lfloor t/2 \rfloor$ | sum |
|------|--------------|----------|--------------------------|-----|
| 初始 | **9**, 5, 4 | — | — | 18 |
| 第 1 次 | **5**, 5, 4 | 9 | 4 | 14 |
| 第 2 次 | **5**, 4, 3 | 5 | 2 | 12 |

- 第 1 次：堆顶 9，移除 4 → 9 变 5，与原 5 **并列最大**——印证「操作后最大值会变，必须堆动态维护」。
- 第 2 次：堆顶 5（两个并列任取其一），移除 2 → 变 3。$k$ 用尽，返回 12 ✓

**示例 2** `piles = [4, 3, 6, 7], k = 3`：堆顶依次为 $7 \to 6 \to 4$，移除 $3 + 3 + 2 = 8$，$20 - 8 = 12$ ✓。注意值最小的堆 3 **全程未被操作**——名额自动流向大堆，无需任何调度逻辑。

## 4. 算法细节

1. **堆的选型**：C++ `priority_queue<int>` 默认大根堆，用迭代器区间构造（`priority_queue<int> pq(v.begin(), v.end())`）是 $O(n)$ 建堆，优于逐个 `push` 的 $O(n \log n)$。Python `heapq` 只有小根堆，惯例**取负**模拟大根堆：存 $-p$，堆顶 $-p_{\max}$ 对应最大 $p$。
2. **减半写法**：正整数下 C++ `t / 2` 与 Python `t // 2` 均为 floor 除法，故更新统一写 `t -= t / 2`（即 $t \leftarrow \lceil t/2 \rceil$），移除量即 `t / 2`（更新前的值）。先算 `r = t / 2` 再 `t -= r`，两处不要算错顺序。
3. **同步维护 sum**：`sum` 初始化为 `accumulate(piles)`，每轮 `sum -= t / 2`。比「最后清堆求和」少一个 $O(n \log n)$ 阶段，代码也更短。
4. **一步替换**：Python 用 `heapreplace(h, val)` 一次完成「弹堆顶 + 推新值」，比 `heappop` + `heappush` 少一次堆调整；注意它**先弹后推**，语义恰合本题「取走堆顶再放回衰减值」。
5. **提前终止**：堆顶为 1 时 $\lfloor 1/2 \rfloor = 0$，本轮及后续所有操作的移除量都是 0（其余元素 $\le$ 堆顶），可直接 `break`。不写也正确（白转几轮，sum 不变），写了可以把复杂度收紧到 $O\big(n + \min(k,\ \sum_i \lceil \log_2 p_i \rceil) \cdot \log n\big)$。
6. **有效操作数上界**：初值 $\le 10^4$ 的堆最多 14 次有效操作（$10^4 \to 5000 \to \cdots \to 1$）即降到 1，全局有效操作 $\le 14n \approx 1.4 \times 10^6$，与 $k \le 10^5$ 取小后循环总量很小，性能无忧。

## 5. 正确性证明

记单堆操作函数 $f(p) = p - \lfloor p/2 \rfloor = \lceil p/2 \rceil$，$f^{(c)}$ 为其 $c$ 次迭代（$f^{(0)}(p) = p$）。

**引理 1（操作的基本性质）**：对一切 $p \ge 1$：① $f(p) \le p$，且 $p \ge 2$ 时 $f(p) < p$；② $f(1) = 1$（即值为 1 的堆操作移除 0）；③ $p \le p'$ 蕴含 $f(p) \le f(p')$（单调非降）。

**证明**：① $\lceil p/2 \rceil \le p$ 对 $p \ge 1$ 成立，$p \ge 2$ 时严格；② $\lceil 1/2 \rceil = 1$；③ $p \le p'$ 时 $\lfloor p/2 \rfloor \le \lfloor p'/2 \rfloor$，故 $p - \lfloor p/2 \rfloor \le p' - \lfloor p'/2 \rfloor$。∎

**引理 2（边际收益递减）**：固定堆初值 $p$，第 $c{+}1$ 次操作的移除量 $\delta_c = \big\lfloor f^{(c)}(p)/2 \big\rfloor$ 满足 $\delta_0 \ge \delta_1 \ge \delta_2 \ge \cdots \ge 0$。

**证明**：由引理 1①，$f^{(c+1)}(p) = f\big(f^{(c)}(p)\big) \le f^{(c)}(p)$；再由 $\lfloor \cdot/2 \rfloor$ 的单调性，$\delta_{c+1} = \big\lfloor f^{(c+1)}(p)/2 \big\rfloor \le \big\lfloor f^{(c)}(p)/2 \big\rfloor = \delta_c$。∎

**定理（凸分配贪心最优）**：策略「每步操作当前值最大的堆」执行 $k$ 步后的剩余总数，不超过任何策略执行 $k$ 步后的剩余总数。

**证明**：

**第一步（名额分配重述）**。操作仅作用于单一堆且各堆独立；对同一堆共 $c$ 次操作的效果是 $f^{(c)}$，与这些操作在全局序列中的穿插位置无关（同一映射的迭代彼此可交换）。又由引理 1②，作用在值为 1 的堆上的操作移除量为 0。因此任一策略的剩余总数仅由名额分配 $\mathbf{c} = (c_1, \dots, c_n)$（$\sum_i c_i = k$，$c_i \ge 0$）决定：

$$\text{剩余}(\mathbf{c}) = \sum_{i=1}^{n} f^{(c_i)}(p_i), \qquad \text{总移除}(\mathbf{c}) = \sum_{i=1}^{n} \sum_{c=0}^{c_i - 1} \delta_c^{(i)}$$

其中 $\delta_c^{(i)} = \big\lfloor f^{(c)}(p_i)/2 \big\rfloor$ 是堆 $i$ 的边际序列。

**第二步（贪心的分配刻画）**。由引理 1③，当前值最大的堆下一次操作的移除量最大（「值最大 $\Leftrightarrow$ 边际最大」）。而堆 $i$ 的当前值恰为 $f^{(c_i)}(p_i)$（已分得 $c_i$ 个名额）。故「每步操作当前值最大的堆」等价于「逐名额地把下一次操作分给当前边际 $\delta_{c_i}^{(i)}$ 最大的堆」。

**第三步（归纳）**。对 $k$ 归纳，命题 $P(k)$：「对任意初始状态，逐名额贪心的 $k$ 名额分配总移除量最大」。$P(0)$ 平凡。设 $P(k-1)$ 成立，证 $P(k)$（$k \ge 1$）。设堆 $a$ 为当前值最大的堆。

（i）*存在给堆 $a$ 至少一个名额的最优分配*。任取最优分配 $\mathbf{c}$，若 $c_a \ge 1$ 已得；否则 $c_a = 0$，因 $k \ge 1$ 可取某堆 $b$ 使 $c_b \ge 1$。构造 $\mathbf{c}'$：$c'_b = c_b - 1$，$c'_a = 1$，其余不变。总移除量变化为 $\delta_0^{(a)} - \delta_{c_b - 1}^{(b)}$。由引理 2，$\delta_{c_b-1}^{(b)} \le \delta_0^{(b)} = \lfloor p_b/2 \rfloor \le \lfloor p_a/2 \rfloor = \delta_0^{(a)}$（末步用 $p_a \ge p_b$ 与单调性）。故 $\mathbf{c}'$ 不劣于 $\mathbf{c}$，仍最优且 $c'_a \ge 1$。

（ii）*归纳收尾*。贪心的第一个名额恰给堆 $a$，之后 $k-1$ 步是在「$p_a \to f(p_a)$、其余堆不变」的新状态上继续逐名额贪心。由（i）可设最优分配 $\mathbf{c}$ 满足 $c_a \ge 1$；将 $\mathbf{c}$ 中对 $a$ 的一个名额去掉，得到新状态上的一个 $k-1$ 名额分配 $\mathbf{c}^{\circ}$，其总移除量 $= \text{总移除}(\mathbf{c}) - \delta_0^{(a)}$。由 $P(k-1)$，新状态上贪心 $k-1$ 步的总移除量 $\ge \text{总移除}(\mathbf{c}^{\circ})$，于是

$$\text{贪心 } k \text{ 步总移除} = \delta_0^{(a)} + \text{新状态贪心 } (k{-}1) \text{ 步总移除} \ge \delta_0^{(a)} + \text{总移除}(\mathbf{c}^{\circ}) = \text{总移除}(\mathbf{c})$$

即贪心不劣于最优分配。故 $P(k)$ 成立。∎

**推论**：算法（大根堆实现「每步操作当前最大堆」）返回的 `sum` 即最小剩余总数。∎

> 💡 **证明的骨架**是「凸性 + 交换 + 归纳」三段式：堆独立把策略折叠成名额分配（第一步），边际递减保证「把名额从边际小处挪到边际大处不亏」（引理 2 驱动 (i) 的交换），归纳把多步决策化归为单步（(ii)）。任何「取最大 + 单调衰减变换 + 推回」的堆贪心题都可以套用这套骨架验证正确性。

## 6. 复杂度分析

- **时间复杂度**：$O(n + k \log n)$——迭代器建堆 $O(n)$；$k$ 轮循环各一次堆顶替换（pop + push 或 heapreplace），每次 $O(\log n)$；`sum` 为 $O(1)$ 维护。配合提前终止可收紧为 $O\big(n + \min(k, 14n) \log n\big)$。本约束下约 $10^5 \times 17 \approx 1.7 \times 10^6$ 次堆操作，远低于时限。
- **空间复杂度**：$O(n)$——堆存储全部 $n$ 个元素，另有常数个标量（`sum`、`t`、`k`）。

## 7. 参考代码

### C++（大根堆 + 同步维护 sum）

```cpp
class Solution {
  public:
    int minStoneSum(vector<int>& piles, int k) {
        priority_queue<int> pq(piles.begin(), piles.end());
        int sum = accumulate(piles.begin(), piles.end(), 0);
        while (k > 0 && pq.top() > 1) {
            int t = pq.top();
            pq.pop();
            sum -= t / 2;
            pq.push(t - t / 2);
            --k;
        }
        return sum;
    }
};
```

### Python（取负模拟大根堆 + heapreplace）

```python
class Solution:
    def minStoneSum(self, piles: List[int], k: int) -> int:
        h = [-p for p in piles]
        heapq.heapify(h)
        s = sum(piles)
        while k and -h[0] > 1:
            t = -h[0]
            heapq.heapreplace(h, -(t - t // 2))
            s -= t // 2
            k -= 1
        return s
```

> 💡 两版都内置了「堆顶为 1 即提前终止」；去掉该判断、纯循环 `k` 次也同样正确（见 §8 第 1 条）。更多写法对照（`heappop` + `heappush` 标准版、清堆求和版）见[每日题解 1962](../../solution/1901-2000/1962_移除石子使总数最小.md)。

## 8. 边界情况与易错点

1. **「恰好 k 次」与浪费名额**：值为 1 的堆操作移除 0，故「恰好 $k$ 次」与「至多 $k$ 次」等价——堆顶为 1 时提前 `break` 安全；反之不 `break` 也正确，只是空转。切勿因「移除 0 无意义」而在逻辑上少算次数（本题两者结果一致，但审题时要意识到这一点）。
2. **不要排序后轮流操作**：静态排序无法跟踪操作后的最大值变化（§3.1 陷阱 2 的 `[8, 1]` 反例）；也不要均分名额（陷阱 1 的 `[100,1,1,1]` 反例）。必须用堆**动态**维护最大值。
3. **溢出检查**：$n \le 10^5$、$p_i \le 10^4$，总和 $\le 10^9$，在 `int` 范围内但已占约一半——若约束放宽到 $p_i \le 10^9$，`sum` 必须改 `long long`。Python 无此问题。
4. **Python 取负要成对**：存入 `-p`、读堆顶 `-h[0]`、推回 `-(t - t // 2)`，三处取负缺一不可；漏掉第三处会把负数越堆越大。
5. **`heapreplace` 的语义**：先弹堆顶再推入新值，等价于「取走当前最大 + 放回衰减值」，恰合题意；不能在空堆上调用（本题 $n \ge 1$ 保证非空）。
6. **floor 语义**：C++ / Python 的正整数除法天然向下取整，无需 `math.floor`；本题值恒正，不涉及负数取整的语言差异。
7. **求和方式**：C++ `priority_queue` 不可遍历，逐个 pop 求和是 $O(n \log n)$ 且破坏堆；推荐 §3.3 的 `sum` 同步扣减写法。

- [280 场周赛 Q3. 拿出最少数目的魔法豆](../280/Q3.拿出最少数目的魔法豆题解.md)：另一种「拉平大堆」的贪心（排序 + 前缀和处理），对照体会「堆逐名额拉平」与「排序整体拉平」两种风味。

**延伸思考**：

- 若变换改为 $p \to p - \lfloor p/2 \rfloor - 1$（每刀多割一颗），贪心还成立吗？（提示：只要变换**单调非降且值域压缩**（$f(p) \le p$），引理 1、2 即成立，凸贪心骨架照用——$\lfloor p/2 \rfloor$ 的具体形式无关紧要。）
- 名额分配视角还给出另一种实现：把每堆看成一个**边际递减的流**，全局前 $k$ 大边际之和即总移除量——这正是「$n$ 路归并取前 $k$ 大」，与堆贪心等价，却在 $k \gg n$ 时可结合「二分第 $k$ 大边际 + 每堆二分配额」做到 $O(n \log p \cdot \log(np))$ 而不依赖 $k$。
- 若规定**同一堆不能连续操作两次**，名额分配带上约束，交换论证的 (i) 步还能照搬吗？（提示：约束只限制相邻名额的归属——堆数 $\ge 2$ 时最优值不变，可从「相邻两次操作可交换顺序」入手。）
