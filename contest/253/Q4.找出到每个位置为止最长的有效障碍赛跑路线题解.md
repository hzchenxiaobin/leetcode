# LeetCode 找出到每个位置为止最长的有效障碍赛跑路线 题解

## 1. 题目概述

- **标题 / 题号**：找出到每个位置为止最长的有效障碍赛跑路线（#1964，hard）
- **链接**：https://leetcode.cn/problems/find-the-longest-valid-obstacle-course-at-each-position/
- **来源**：LeetCode 第 253 场周赛 Q4
- **难度**：困难
- **标签**：树状数组、数组、二分查找、最长上升子序列

**题意**：给定下标从 0 开始、长度为 $n$ 的整数数组 `obstacles`，`obstacles[i]` 是第 $i$ 个障碍的高度。对每个下标 $i$，求满足以下条件的最长障碍路线长度 `ans[i]`：

- 只能选下标 $0$ 到 $i$ 之间的障碍，且**必须包含第 $i$ 个**；
- 障碍按在数组中的**出现顺序**布置；
- 除第一个障碍外，每个高度都必须与前一个**相同或更高**（非严格递增）。

一句话：求**以每个位置 $i$ 结尾的最长非严格递增子序列长度**——LIS 的「逐位置在线」+「非严格」双变体。

**约束**：

- $1 \le n \le 10^5$ —— 排除 $O(n^2)$ 朴素 DP，必须 $O(n \log n)$
- $1 \le \text{obstacles}[i] \le 10^7$ —— 值域很大，值域类数据结构（树状数组）必须**离散化**

> 💡 本题在本仓库另有[每日题解 1964](../../solution/1901-2000/1964_找出到每个位置为止最长的有效障碍赛跑路线.md)：那边侧重「严格 / 非严格一字之差」的对照、在线 LIS 通用模板与面试问答。本篇按周赛复盘视角，给出赛场上两条 $O(n \log n)$ 优化路线——**贪心 + 二分（耐心排序）**与**值域树状数组（前缀 max）**，以引理-定理结构完整证明主解的正确性，并复盘两个高频翻车点：谓词用错（`lower_bound`）与 C++ 迭代器失效。

## 3. 解题思路

### 3.1 暴力思路：逐位向前找最佳前驱的 $O(n^2)$ DP

设 `dp[i]` 为以 `obstacles[i]` 结尾的最长非严格递增子序列长度，转移就是题面的直译——在前驱里挑一个「高度不超过自己」的最优者接上：

$$\text{dp}[i] = 1 + \max\big\{\, \text{dp}[j] \;\big|\; 0 \le j < i,\ \text{obstacles}[j] \le \text{obstacles}[i] \,\big\}$$

（候选集为空时 $\max$ 取 0。）

```text
for i in 0..n-1:
    best = 0
    for j in 0..i-1:
        if obstacles[j] <= obstacles[i]:
            best = max(best, dp[j])
    dp[i] = best + 1
```

- **正确性**：忠实枚举所有合法前驱，必含第 $i$ 个障碍的路线去掉末尾后恰是一个合法前驱路线。
- **效率**：$O(n^2)$，$n = 10^5$ 时约 $10^{10}$ 次比较，**超时**（约需数十秒）。

> 💡 **复盘视角**：这个转移是一个「**二维偏序查询**」——$j < i$ 由扫描顺序天然保证，真正费时的是「值 $\le x$ 的最大 dp」。两条 $O(n \log n)$ 优化路线由此分岔：
>
> - **路线 A（贪心 + 二分）**：不直接维护 dp 的值域，而是抽象出「**每个长度的最小末尾**」这个一维单调量，把前驱查询变成在单调数组里**二分**；
> - **路线 B（值域树状数组）**：把高度**离散化**后用树状数组直接维护「值 $\le x$ 的最大 dp」，前缀 max 查询 $O(\log n)$。

### 3.2 核心观察：非严格递增——upper_bound「放行相等」

路线 A 是 300 题 LIS 贪心（耐心排序）的直接改造。维护数组 `tails`：

$$\text{tails}[k] = \text{长度为 } k+1 \text{ 的非严格递增子序列的最小末尾}$$

`tails` 非严格递增，来一个新障碍 $x$ 时**二分找「第一个 $> x$ 的下标」pos**（`upper_bound` / `bisect_right`）：

- `pos == len(tails)`：没有谁比 $x$ 高，$x$ 接得上所有子序列 → **追加**，长度 +1；
- 否则：`tails[pos] > x`，即长度 `pos+1` 的门槛比 $x$ 高，但 `tails[0..pos-1]` 都 $\le x$ → 用 $x$ **替换** `tails[pos]`，让该长度未来更容易被接上。

两分支统一记 `ans[i] = pos + 1`。

与 300 题（严格递增）唯一的区别在**谓词**：

| 题型 | 递增要求 | 破坏规则的第一人 | 谓词 | 相同元素 |
|------|---------|----------------|------|---------|
| 300 LIS | 严格 $<$ | 第一个 $\ge x$ | `lower_bound` / `bisect_left` | 替换自己，长度不增 |
| **1964 本题** | **非严格 $\le$** | **第一个 $> x$** | **`upper_bound` / `bisect_right`** | **追加，长度 +1** |

全等数组 $[2,2,2]$ 是两种谓词的试金石，一「替」一「接」结果天差地别：

![核心观察：非严格递增用 upper_bound，全等数组见分晓](images/wc253_q4_bound_compare_concept.svg)

> ⚠️ **赛场上最容易翻车的点**：背了 300 题模板直接抄 `lower_bound`，全等输入 $[2,2,2]$ 会输出 $[1,1,1]$（正确为 $[1,2,3]$），而官方样例里恰好没有全等输入，很容易「样例过了、提交挂了」。记忆口诀：**二分找的是「破坏递增规则的第一人」——严格（$<$）中 $\ge x$ 即破坏，非严格（$\le$）中 $> x$ 才破坏**。

### 3.3 算法流程

![算法流程：耐心排序 + upper_bound，统一出口 ans[i] = pos + 1](images/wc253_q4_algorithm_flow.svg)

**完整步骤**：

1. 初始化 `tails = []`，`ans = []`。
2. 依次处理每个障碍 $x = \text{obstacles}[i]$：
   - `pos = upper_bound(tails, x)`（第一个 $> x$ 的下标）；
   - 若 `pos == len(tails)`：`tails` 末尾追加 $x$（$x$ 能接在所有子序列后面，长度 +1）；
   - 否则：`tails[pos] = x`（长度 `pos+1` 的门槛换成更矮的 $x$）；
   - `ans[i] = pos + 1`（**两个分支的统一出口**：追加分支新长度恰为 `pos+1`）。
3. 全部处理完，返回 `ans`。

> 💡 注意替换分支不会改动 `tails[pos]` 之后的内容——`tails` 的**长度只在追加时增长**，替换只是「把某个长度的门槛降低」，这正是它不影响已输出答案、却让未来受益的原因（§5 引理 2 严格化）。

### 3.4 示例演算

用自造用例 $[5, 2, 4, 4, 3]$ 演算（四种操作形态齐全：追加 / 头替换 / **相等追加** / 中间替换）：

![示例演算：[5,2,4,4,3] 四种操作形态全程走查](images/wc253_q4_example_walkthrough.svg)

| 步骤 | $i$ | $x$ | 处理前 tails | upper_bound | 操作 | 处理后 tails | ans[i] |
|------|-----|-----|--------------|-------------|------|--------------|--------|
| 1 | 0 | 5 | 空 | pos = 0 = len | 追加 | `[5]` | 1 |
| 2 | 1 | 2 | `[5]` | pos = 0（5 > 2） | 替换头 | `[2]` | 1 |
| 3 | 2 | 4 | `[2]` | pos = 1 = len | 追加 | `[2,4]` | 2 |
| 4 | 3 | 4 | `[2,4]` | pos = 2 = len（4 并不 > 4） | **相等追加** | `[2,4,4]` | **3** |
| 5 | 4 | 3 | `[2,4,4]` | pos = 1（4 > 3） | 中间替换 | `[2,3,4]` | 2 |

最终 `ans = [1,1,2,3,2]`，与暴力 DP 对拍一致。步骤 4 是全题灵魂：`x=4` 与 `tails` 里已有的 4 **相等**，`upper_bound` 找「第一个 $> 4$」越过了它落到表尾 → 追加而非替换；若误用 `lower_bound`（第一个 $\ge 4$），会在这一步替换掉那个 4，`ans[3]` 错成 2。

## 4. 算法细节

1. **二分谓词的精确语义**

   | 语言 | 非严格递增（本题） | 严格递增（300 题） |
   |------|--------------------|--------------------|
   | C++ | `upper_bound(tails.begin(), tails.end(), x)` | `lower_bound(...)` |
   | Python | `bisect.bisect_right(tails, x)` | `bisect.bisect_left(tails, x)` |

   两者返回的都是**插入位置下标** `pos`，语义是「`tails[0..pos-1]` 都放行、`tails[pos..]` 都拒绝」。放行边界恰好就是递增规则允许的边界。

2. **为什么 ans[i] = pos + 1**：`pos` 左边的 `tails` 都 $\le x$，说明存在长度为 `pos` 的子序列末尾 $\le x$，接上 $x$ 得到长度 `pos+1`；而 `tails[pos] > x` 说明长度 `pos+1` 的现存门槛都超过 $x$，接不上（§5 引理 3 证明这也是「以 $x$ 结尾」能达到的最大长度，不只是「能接上」）。两分支统一出口：追加后 `len(tails)` 恰好变成 `pos + 1`。

3. **替换为什么「无损」**：被替换的旧末尾从未在已输出的 `ans` 里被引用——`ans[i]` 在每步当场结算。`tails` 只是一张「门槛表」，替换让**未来**的同长度子序列有更矮的门槛，不追溯历史。另注意 `tails` 本身**不是**一条合法子序列，它的**长度**才是全局最长长度，内容只有门槛意义。

4. **另一条路：值域树状数组（前缀 max）**。DP 转移 $\text{dp}[i] = 1 + \max\{\text{dp}[j] : j < i,\ h_j \le x\}$ 中，扫描顺序已保证 $j < i$，剩下的就是「值 $\le x$ 的最大 dp」——把高度**离散化**（排序去重，$m \le n$ 个 rank）后，这恰好是树状数组上的**前缀 max 查询**；算完 `dp[i]` 再把「rank $r$ 处的 dp 值」**单点 chmax** 写回去。

   ![另解：值域树状数组前缀 max，把转移做成一次 query + 一次 update](images/wc253_q4_bit_prefix_max.svg)

   max 版树状数组只需「单点 chmax + 前缀查询」两件套，天然合法（max 只需单调性、不需要逆运算，所以不做减法撤销也没关系）。实现要点：

   - **离散化**：$10^7$ 值域直接开树要 40MB，必须压到 $m \le n$；
   - **先 query 后 update**：先查「$\le x$」的前缀 max（此时自己还没写入），再把自己 chmax 进去；顺序反了会把自己也算进前缀，凭空 +1；
   - 泛化能力比二分强：把查询区间从 $[1, \text{rank}(x)]$ 换成 $[\text{rank}(x)-k,\ \text{rank}(x)-1]$ 就能处理 2407 题的「严格递增且相邻差 $\le k$」——那需要**区间 max**，得上值域线段树（见相关题目）。

## 5. 正确性证明

对主解（耐心排序 + `upper_bound`）给出完整证明。记 $f_i(k)$ 为「`obstacles[0..i]` 中长度为 $k+1$ 的非严格递增子序列的最小末尾」（不存在则记 $+\infty$，下标从 0 计）。

**引理 1（tails 的单调性）**：算法任意时刻 `tails` 非严格递增。

**证明**：对操作次数归纳。初始 `tails` 为空，平凡成立。设某次操作前 `tails` 非严格递增，处理新元素 $x$，`pos` 为其中第一个 $> x$ 的下标（于是 `tails[0..pos-1]` 全部 $\le x$）。

- 若 `pos = len`：所有元素都 $\le x$，末尾追加 $x$ 后仍非严格递增；
- 若 `pos < len`：替换后有界不等式 `tails[pos-1] ≤ x`（左侧，pos=0 时无左邻）与 $x < \text{tails}[\text{pos}] \le \text{tails}[\text{pos}+1]$（右侧，用替换前的单调性），单调性保持。∎

**引理 2（不变量）**：处理完前 $i$ 个障碍后，`tails[k] = f_i(k)` 对一切有效下标 $k$ 成立；且 $f_i$ 关于 $k$ 非严格递增。

**证明**：先证 $f_i$ 非严格递增：把一条长度 $k+2$ 的子序列去掉末尾元素，就得到一条长度 $k+1$、末尾 $\le$ 原末尾的子序列，故 $f_i(k) \le f_i(k+1)$。

再对 $i$ 归纳。$i=-1$（尚未处理任何元素）时 `tails` 为空，成立。设处理完前 $i-1$ 个障碍后归纳命题成立。考察 $x = \text{obstacles}[i]$。按定义拆分「长度 $k+1$ 的子序列」为「不以 $x$ 结尾」与「以 $x$ 结尾」两类，后者存在 $\Leftrightarrow$ 存在长度 $k$、末尾 $\le x$ 的子序列 $\Leftrightarrow f_{i-1}(k-1) \le x$（取到最小末尾的那条必能接上 $x$），此时该类子序列的最小末尾就是 $x$。于是

$$f_i(k) = \min\big(f_{i-1}(k),\;\; x \cdot \mathbb{1}[\,f_{i-1}(k-1) \le x\,]\big)$$

（$k=0$ 时约定第二项恒取 $x$，即 $x$ 总能单独成一条长度 1 的路线）。由归纳假设与引理 1，`tails` 非严格递增，故「第一个 $> x$ 的下标 pos」给出刻画：$f_{i-1}(k) \le x \Leftrightarrow k \le \text{pos}-1$。代入上式分三类：

- $k \le \text{pos}-1$：两候选都在，但 $x \ge f_{i-1}(k)$，$\min$ 取 $f_{i-1}(k)$，**不变**；
- $k = \text{pos}$：$f_{i-1}(\text{pos}-1) \le x$ 且 $x < f_{i-1}(\text{pos})$，故 $f_i(\text{pos}) = x$——`pos < len` 时是**替换**，`pos = len` 时是**追加新长度**；
- $k \ge \text{pos}+1$：$f_{i-1}(k-1) \ge \text{tails}[\text{pos}] > x$（单调性），以 $x$ 结尾的该长度子序列不存在，**不变**。

三类操作与算法行为逐点吻合：除 `pos` 一处外全部不动，`pos` 处写入 $x$。∎

**引理 3（每步输出的正确性）**：`ans[i] = pos + 1` 恰为「以 `obstacles[i]` 结尾的最长非严格递增子序列」的长度。

**证明**：处理第 $i$ 个障碍时 `tails` 还是 $f_{i-1}$（引理 2 的归纳前提）。以 $x$ 结尾、长度为 $L$ 的子序列存在 $\Leftrightarrow$ 存在长度 $L-1$、末尾 $\le x$ 的子序列（前者去尾即得后者；后者接上 $x$ 即得前者）$\Leftrightarrow f_{i-1}(L-2) \le x$，其中 $L=1$ 恒存在。由 $f_{i-1}$ 非严格递增，满足 $f_{i-1}(k) \le x$ 的 $k$ 恰是 $k \le \text{pos}-1$，最大可用前驱长度为 $\text{pos}$，故 $L_{\max} = \text{pos}+1$。∎

**定理**：算法对每个 $i$ 输出的 `ans[i]` 均为所求最长有效障碍路线长度。

**证明**：对 $i$ 归纳。引理 2 的归纳步骤表明每步「二分 + 追加/替换」恰把 `tails` 从 $f_{i-1}$ 更新到 $f_i$；引理 3 表明该步输出 `pos + 1` 正确。两引理随归纳成立，定理得证。∎

> 💡 **证明的骨架**是「**不变量归纳**」：给 `tails` 找一个精确语义（每长度的最小末尾 $f$），证明每一步操作与语义的演化（$\min$ 更新）逐点等价，输出正确性便成为语义的直接推论。这套「先定义不变量、再证明操作保不变量」的流程同样适用于 300、354、2111 等一整族 LIS 题的贪心正确性验证。树状数组路线则不需要这份证明——它直接实现了 DP 定义，正确性由 DP 方程自明，代价是实现更重。

## 6. 复杂度分析

- **时间复杂度**：$O(n \log n)$——主解每个障碍一次二分查找 $O(\log n)$，追加 / 替换均 $O(1)$，共 $n$ 次；树状数组路线离散化排序 $O(n \log n)$，每步 query 与 update 各 $O(\log n)$。$n = 10^5$ 时约 $10^5 \times 17 \approx 1.7 \times 10^6$ 次基本操作，对比暴力 $O(n^2) \approx 10^{10}$ 快约四个数量级。
- **空间复杂度**：$O(n)$——`tails` 最长可达 $n$（输入本身非严格递增时每个元素都追加），答案数组 $O(n)$ 不可避免；树状数组路线另需 $O(n)$ 的离散化表与树数组。

## 7. 参考代码

### C++（主解：耐心排序 + upper_bound）

```cpp
class Solution {
  public:
    vector<int> longestObstacleCourseAtEachPosition(vector<int>& obstacles) {
        int n = obstacles.size();
        vector<int> ans(n);
        vector<int> tails; // tails[k]：长度 k+1 的非严格递增子序列的最小末尾
        for (int i = 0; i < n; ++i) {
            int x = obstacles[i];
            // 第一个 > x 的下标（与 300 题 lower_bound 一字之差）
            int pos = upper_bound(tails.begin(), tails.end(), x) - tails.begin();
            if (pos == (int)tails.size()) {
                tails.push_back(x); // x 接得上所有子序列，开新长度
            } else {
                tails[pos] = x; // 长度 pos+1 的门槛换成更矮的 x
            }
            ans[i] = pos + 1; // 两个分支的统一出口
        }
        return ans;
    }
};
```

### Python（主解：bisect_right）

```python
import bisect

class Solution:
    def longestObstacleCourseAtEachPosition(self, obstacles: List[int]) -> List[int]:
        tails = []  # tails[k]：长度 k+1 的非严格递增子序列的最小末尾
        ans = []
        for x in obstacles:
            pos = bisect.bisect_right(tails, x)  # 第一个 > x 的插入位置
            if pos == len(tails):
                tails.append(x)
            else:
                tails[pos] = x
            ans.append(pos + 1)
        return ans
```

### Python（另解：离散化 + 树状数组前缀 max）

```python
class Solution:
    def longestObstacleCourseAtEachPosition(self, obstacles: List[int]) -> List[int]:
        vals = sorted(set(obstacles))               # 离散化：10^7 值域压到 m 个 rank
        rank = {v: i + 1 for i, v in enumerate(vals)}
        m = len(vals)
        tree = [0] * (m + 1)                       # 1-indexed，前缀 max 树状数组

        def query(i):                              # max{dp[j] : rank[obstacles[j]] <= i}
            best = 0
            while i > 0:
                if tree[i] > best:
                    best = tree[i]
                i -= i & (-i)
            return best

        def update(i, v):                          # 单点 chmax
            while i <= m:
                if v > tree[i]:
                    tree[i] = v
                i += i & (-i)

        ans = []
        for x in obstacles:
            best = query(rank[x])                  # 必须先查后更
            update(rank[x], best + 1)
            ans.append(best + 1)
        return ans
```

> 💡 **写法对照**：C++ 的 `upper_bound` 返回迭代器，本篇刻意先折算成下标 `pos` 再操作——若先保存迭代器再 `push_back`，扩容会使迭代器失效（实测输出乱值，见 §8 第 3 条）；Python 的 `bisect_right` 直接返回插入位置，无此问题。`query(rank[x])` 覆盖所有值 $\le x$ 的 rank，天然放行相等高度——谓词差异在这里体现为「是否含端点」，比二分路线更不容易写错。

## 8. 边界情况与易错点

1. **全等输入是谓词试金石**：`[2,2,2]` 用 `lower_bound` / `bisect_left` 会得 `[1,1,1]`，正确答案 `[1,2,3]`（`upper_bound` / `bisect_right`）。官方三个样例都没有全等输入，此错样例发现不了。
2. **`ans[i]` 误记成 `len(tails)`**：那是「全局最长」，不是「以 $i$ 结尾」；正确写法是两分支统一的 `pos + 1`（追加分支 `pos + 1` 恰等于新 `len`）。
3. **C++ 迭代器失效**：`it = upper_bound(...)` 之后 `tails.push_back(x)` 可能触发扩容，再用 `it - tails.begin()` 就是未定义行为（实测输出随机值）。先算下标 `pos` 再追加/替换，或每次重新求 `begin()` 差值。
4. **树状数组先 query 后 update**：先把自己 chmax 进去再查 `rank(x)` 前缀，会把自己的 dp 算进前驱，`ans` 凭空 +1 且错误向后传播。
5. **值域离散化**：$10^7$ 直接开树状数组要 40MB 空间，会 MLE；排序去重压到 $m \le n$。查询含端点 `rank(x)`（放行相等），严格版则是 `rank(x) - 1`。
6. **极端输入**：$n=1$ 输出 `[1]`；严格递减输入 `tails` 恒长 1（每次都替换头），`ans` 全 1；输入本身非严格递增时 `tails` 涨满 $n$——空间预算别按常数估。
7. **溢出检查**：$n \le 10^5$、值 $\le 10^7$、`ans` 值 $\le n$，`int` 全程够用，无需 `long long`（Python 无此问题）。

**延伸思考**：

- 若还要求**还原具体路线**（输出每组所选障碍的下标）？提示：在 `tails` 里同步存「该末尾对应的下标」，替换/追加时记录前驱下标，最后沿链回溯——`ans[i]` 与链头信息一起，即可 $O(n)$ 重构每组方案。
- 若把「相同或更高」改成「**严格更高**」？二分路线换回 `lower_bound` 即可；树状数组路线把查询端点从 `rank(x)` 改成 `rank(x) - 1`——两处都只改一个「是否放行相等」的端点，对照体会谓词位置。
