# LeetCode 范围内总波动值 II 题解

## 1. 题目概述

- **标题 / 题号**：范围内总波动值 II（#3753，hard）
- **链接**：https://leetcode.cn/problems/total-waviness-of-numbers-in-range-ii/
- **来源**：LeetCode 第 170 场双周赛 Q4
- **难度**：困难
- **标签**：数学、动态规划

**题意**：与同场 Q2 的波动值定义完全一致（内部数位严格大于两侧为**峰**、严格小于两侧为**谷**，首尾不算，少于 3 位为 0），但区间上界从 $10^5$ 放大到 $10^{15}$，逐个枚举已不可能，必须用**数位 DP** 求出 $[1, N]$ 的波动值总和，再做前缀差分。

**约束**：

- $1 \le num1 \le num2 \le 10^{15}$（至多 16 位）

## 2. 示例

**示例 1**

```text
输入：num1 = 120, num2 = 130
输出：3
解释：120、121、130 各贡献 1（中间位 2、2、3 是峰）。
```

**示例 2**

```text
输入：num1 = 198, num2 = 202
输出：3
解释：198（峰 9）、201（谷 0）、202（谷 0）各贡献 1。
```

**示例 3**

```text
输入：num1 = 4848, num2 = 4848
输出：2
解释：4848 的 8 是峰、4 是谷，波动值 2。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 $[num1, num2]$ 内每个数、逐位判峰谷。区间长度可达 $10^{15}$，即便每个数只要 $O(16)$ 也会超时 $10^{10}$ 倍。必须把「枚举数字」换成「枚举数位前缀 + 计数」。

### 3.2 核心观察：贡献是局部的，可以边填边加

![波动值只依赖连续三位：填第 k 位时就能结算第 k−1 位的贡献](images/bw170_q4_local_contribution.svg)

波动值的定义有一个非常关键的性质：**每个内部位的贡献只依赖它和左右相邻两位**。也就是说，当我们自左向右逐位填数时，一旦填好第 $k$ 位（$k \ge 2$），第 $k-1$ 位的左右邻居都确定了，它的峰 / 谷身份就可以**当场结算**，之后再也不影响。

于是数位 DP 的状态只需要记住「最近填的两位」：

$$\text{state} = (\text{pos},\ \text{prev2},\ \text{prev1},\ \text{tight},\ \text{started})$$

- `pos`：当前要填第几位（0-based）；
- `prev2`、`prev1`：上一位、上上位的数字（用 $10$ 表示「还不存在」）；
- `tight`：是否仍然贴着上界 $N$ 的前缀；
- `started`：是否已经开始（用于跳过前导零）。

填一个新数字 $d$ 时，若 `started && prev2 != NONE`，则 `prev1` 成为内部位，结算：

$$\text{add} = [\,(prev1 > prev2 \wedge prev1 > d) \ \vee\ (prev1 < prev2 \wedge prev1 < d)\,]$$

### 3.3 算法流程：返回「个数 + 总和」的 DP

![DP 转移：同时维护方案数与累计波动值和](images/bw170_q4_dp_transition.svg)

DP 的返回值是一个二元组 $(\text{cnt}, \text{sum})$：

- `cnt`：该状态下能填出的数字个数；
- `sum`：这些数字的波动值总和。

合并时，若当前位的贡献是 `add`，则子问题的 `sum` 要整体上移 `add` 个「每个数字贡献 add」：

$$\text{sum} \mathrel{+}= \text{sub.sum} + \text{add} \times \text{sub.cnt}$$

```text
dfs(pos, prev2, prev1, tight, started) -> (cnt, sum)
  若 pos == 位数: 返回 (1, 0)
  若 !tight 且已记忆: 直接返回
  hi = tight ? N[pos] : 9
  for d = 0 .. hi:
      add = 0
      若 !started 且 d == 0:
          # 仍是前导零，状态不变
          (c, s) = dfs(pos+1, prev2, prev1, tight && d==hi, false)
      否则若 !started:
          # 第一个非零位，不结算
          (c, s) = dfs(pos+1, NONE, d, tight && d==hi, true)
      否则:
          add = 峰/谷判定(prev2, prev1, d)（prev2 存在时）
          (c, s) = dfs(pos+1, prev1, d, tight && d==hi, true)
      cnt += c;  sum += s + add * c
  记忆并返回 (cnt, sum)

F(x) = dfs(0, NONE, NONE, true, false).sum
答案 = F(num2) − F(num1 − 1)
```

### 3.4 示例演算

![示例演算：4848 的逐位结算](images/bw170_q4_example_walkthrough.svg)

以 $4848$ 为例，只看这一条路径：

| 步 | 填入 | prev2 | prev1 | add（结算的是 prev1） | 累计 |
|----|------|-------|-------|------------------------|------|
| 0 | 4 | NONE | 4 | 0（首位不结算） | 0 |
| 1 | 8 | 4 | 8 | 0（prev2 不存在） | 0 |
| 2 | 4 | 8 | 4 | $8 > 4$ 且 $8 > 4$ → 8 是峰，+1 | 1 |
| 3 | 8 | 4 | 8 | $4 < 8$ 且 $4 < 8$ → 4 是谷，+1 | 2 |

末位 8 在 `pos == 4` 时结束，**不结算**（它没有右邻），正是「末位不能是峰谷」。答案 2，与示例一致。

## 4. 算法细节

1. **状态压缩**：`prev` 用 $0 \sim 9$ 表示数字，$10$ 表示「不存在」。C++ 用 `int[20][11][11][2][2]`，Python 用 `@lru_cache`。
2. **`tight` 的含义**：只有 `tight == true` 时当前位的上限才是 $N$ 的对应位；一旦某位填得比上界小，后续位就自由（上限 9），但也因此失去记忆化价值——所以只对 `!tight` 的状态做记忆。
3. **`started` 与前导零**：数字没有前导零（如 `0123` 应视作 `123`）。若 `!started && d == 0`，说明这一位属于前导零，**不**推进 `prev` 也不结算；一旦填入非零位就置 `started = true`。
4. **结算时机**：结算的是 `prev1`（不是刚填的 `d`），因为 `d` 的右邻还没填。这个 off-by-one 是本题最容易写错的地方。
5. **`NONE` 判定**：`prev2 == NONE` 时不能结算（此时 `prev1` 是首位，没有左邻）。
6. **两次调用**：`F(num2) - F(num1 - 1)`，注意 `num1 = 1` 时 `F(0)` 要返回 0（避免 `to_string(0)` 引入一位数字 "0"）。
7. **64 位**：$N \le 10^{15}$，数字个数约 $10^{15}$，每个波动值 $\le 14$，总和上界约 $1.4 \times 10^{16}$，`long long` 足够（$9.2 \times 10^{18}$）；Python 无溢出问题。
8. **记忆化的键**：把 `tight` 也放进键里会导致状态数翻倍且复用率低，惯例是只在 `!tight` 时记忆；本文代码即如此。

## 5. 正确性证明

**引理 1（贡献可加）**：设数字的十进制串为 $d_0 \cdots d_{L-1}$，则其波动值 $W = \sum_{i=1}^{L-2} [\,d_i \text{ 是峰或谷}\,]$，每一项只依赖 $(d_{i-1}, d_i, d_{i+1})$。

**证明**：波动值定义为峰与谷的总数，而峰 / 谷的定义本身就是对内部下标 $i \in [1, L-2]$ 的逐位判定，每位至多贡献 1。∎

**引理 2（结算时机正确）**：在 DFS 填到第 $k$ 位并填入 $d$、且 `started` 为真、`prev2` 存在时，结算的 `prev1` 恰好是原数字中「下标为 $k-1$ 的内部位」，且其左右邻居分别是 `prev2` 与 $d$。

**证明**：`started` 为真表示已经填了连续的非前导零位，`prev2`、`prev1` 分别是紧邻当前位的前两位（按填数顺序）。填入 $d$ 后，`prev1` 的左邻是 `prev2`、右邻是 $d$，三者在下标上连续，故 `prev1` 是内部位且邻居正确。而 `prev1` 在之前从未被结算过（它上一轮还是 `d` 的位置，本轮才成为 `prev1`），故不会重复计数。∎

**引理 3（前导零处理正确）**：设数字实际位数为 $L' \le L$，则跳过前导零后，DP 结算的正是这 $L'$ 位数字的全部内部位，且首位 / 末位不被结算。

**证明**：跳过前导零时 `started` 保持 false、`prev` 保持 `NONE`，故前导零不产生任何结算也不影响后续邻居关系。第一个非零位置 `started = true`、`prev2 = NONE`、`prev1 = d`，此后每个新位的结算都要求 `prev2 != NONE`，因此第一个非零位（真正的首位）永不结算。当填完最后一位（`pos == L`）时，最后一位作为 `prev1` 留在状态里，**没有**被结算，因此末位也永不结算。故只有 $L' \ge 3$ 时的内部位被结算，与引理 1 一致。∎

**引理 4（DP 求和正确）**：DFS 返回的 `sum` 等于该状态下所有合法后缀所构成数字的波动值之和，`cnt` 等于这些数字的个数。

**证明**：对剩余位数归纳。`pos == L` 时只有一个数字（空前缀），贡献 0，返回 $(1,0)$ ✓。设子调用正确，则对每个合法数字 $d$，子问题给出 $c$ 个后缀、贡献和 $s$；当前位为 `prev1` 结算出 `add`，这 $c$ 个数字每个都多了 `add`，合计 $s + \text{add}\cdot c$。对所有 $d$ 求和即得当前状态的 `sum`，`cnt` 同理。∎

**定理**：算法返回值等于 $\sum_{x=num1}^{num2} W(x)$。

**证明**：`tight` 机制保证 DFS 枚举的正是 $[0, N]$ 的全部整数且每个恰好一次（标准数位 DP 的上界约束），`started` 保证前导零不产生额外数字（同一整数只有一种非前导零表示）。由引理 4，`F(N)` 等于 $[0,N]$ 全部数字的波动值之和；其中 $0$ 的波动值为 $0$，不影响结果。于是 $F(num2) - F(num1-1) = \sum_{x \in [0,num2]} W(x) - \sum_{x \in [0,num1-1]} W(x) = \sum_{x=num1}^{num2} W(x)$。∎

## 6. 复杂度分析

- **时间**：状态数 $O(D \cdot 11 \cdot 11 \cdot 2)$（$D \le 16$，`tight` 状态不记忆但只有 $O(D)$ 条路径），每个状态转移 $10$ 次，故单次 `F` 为 $O(D \cdot 10^3)$ 量级，约 $2 \times 10^4$ 次运算；两次调用仍是常数级耗时。
- **空间**：记忆表 $O(D \cdot 11 \cdot 11 \cdot 2)$ 个二元组（约 $7744$ 项），递归深度 $O(D)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    long long totalWaviness(long long num1, long long num2) {
        return prefixSum(num2) - prefixSum(num1 - 1);
    }

private:
    static const int NONE = 10;
    string digits;
    long long memoCnt[20][11][11][2];
    long long memoSum[20][11][11][2];
    bool vis[20][11][11][2];

    long long prefixSum(long long x) {
        if (x <= 0) return 0;
        digits = to_string(x);
        memset(vis, 0, sizeof(vis));
        return dfs(0, NONE, NONE, true, false).second;
    }

    pair<long long, long long> dfs(int pos, int prev2, int prev1, bool tight, bool started) {
        if (pos == (int)digits.size()) return {1, 0};
        if (!tight && vis[pos][prev2][prev1][started]) {
            return {memoCnt[pos][prev2][prev1][started], memoSum[pos][prev2][prev1][started]};
        }
        long long cnt = 0, sum = 0;
        int hi = tight ? digits[pos] - '0' : 9;
        for (int d = 0; d <= hi; d++) {
            bool ntight = tight && (d == hi);
            long long add = 0;
            int np2 = prev2, np1 = prev1;
            bool nstarted = started;
            if (!started && d == 0) {
                // 仍是前导零，状态保持不变
            } else if (!started) {
                np2 = NONE;
                np1 = d;
                nstarted = true;
            } else {
                if (prev2 != NONE) {
                    if ((prev1 > prev2 && prev1 > d) || (prev1 < prev2 && prev1 < d)) {
                        add = 1;
                    }
                }
                np2 = prev1;
                np1 = d;
            }
            auto sub = dfs(pos + 1, np2, np1, ntight, nstarted);
            cnt += sub.first;
            sum += sub.second + add * sub.first;
        }
        if (!tight) {
            vis[pos][prev2][prev1][started] = true;
            memoCnt[pos][prev2][prev1][started] = cnt;
            memoSum[pos][prev2][prev1][started] = sum;
        }
        return {cnt, sum};
    }
};
```

### Python

```python
from functools import lru_cache


class Solution:
    def totalWaviness(self, num1: int, num2: int) -> int:
        NONE = 10

        def prefix_sum(x: int) -> int:
            if x <= 0:
                return 0
            d = str(x)
            L = len(d)

            @lru_cache(maxsize=None)
            def dfs(pos: int, prev2: int, prev1: int, tight: bool, started: bool):
                if pos == L:
                    return (1, 0)
                hi = int(d[pos]) if tight else 9
                cnt = 0
                total = 0
                for dig in range(hi + 1):
                    ntight = tight and (dig == hi)
                    add = 0
                    np2, np1, nstarted = prev2, prev1, started
                    if not started and dig == 0:
                        pass
                    elif not started:
                        np2, np1, nstarted = NONE, dig, True
                    else:
                        if prev2 != NONE:
                            if (prev1 > prev2 and prev1 > dig) or (prev1 < prev2 and prev1 < dig):
                                add = 1
                        np2, np1 = prev1, dig
                    c, s = dfs(pos + 1, np2, np1, ntight, nstarted)
                    cnt += c
                    total += s + add * c
                return (cnt, total)

            return dfs(0, NONE, NONE, True, False)[1]

        return prefix_sum(num2) - prefix_sum(num1 - 1)
```

## 8. 边界情况与易错点

1. **结算错位**：结算的必须是 `prev1`（上一轮填的位），不是本轮填的 `d`。写成结算 `d` 会让最后一位被错误计入，答案偏大。
2. **首位被结算**：`prev2 == NONE` 时必须跳过，否则首位会被当成峰 / 谷（例如 `198` 的 1 会被「$1 >$ 假想 0」误判）。
3. **末位被结算**：递归到 `pos == L` 直接返回，不再结算 `prev1`，否则末位也会被算成峰谷。
4. **前导零推进了 `prev`**：若在 `!started && d == 0` 时也设 `prev1 = 0`，则 `12` 会被当成 `0012` 来算，首位 1 会因为左邻 0 被误判成峰。
5. **`tight` 更新**：`ntight = tight && (d == hi)`。当 `!tight` 时 hi 恒为 9，`ntight` 应为 false；用上式天然满足（`tight` 为 false 时短路）。
6. **`F(num1 - 1)` 的 0 值**：`prefix_sum(0)` 必须返回 0。若直接 `to_string(0)` 会生成一位数字 "0"，虽波动值仍为 0，但会浪费状态并可能引入 off-by-one 隐患。
7. **溢出**：$\sum W$ 上界约 $1.4 \times 10^{16}$，`long long` 安全；若用 `int` 必然溢出。
8. **`memset` 清零 `vis`**：两次调用 `prefixSum` 之间必须清空记忆表，否则第二次会用第一次（上界不同）的缓存，结果错误。
9. **递归深度**：$\le 16$，无需担心爆栈。
