# LeetCode 重新排序得到 2 的幂 题解

## 1. 题目概述

- **标题 / 题号**：重新排序得到 2 的幂（#869，medium）
- **链接**：https://leetcode.cn/problems/reordered-power-of-2/
- **来源**：LeetCode 第 93 场周赛 Q2
- **难度**：中等
- **标签**：哈希表、数学、计数、枚举、排序

**题意**：给定正整数 $n$，允许把 $n$ 的十进制各位数字**任意重排**（也可以保持原顺序），但要求重排后的数**首位不能是 $0$**。问是否存在一种重排方式，使得到的数恰好是 $2$ 的幂（$1, 2, 4, 8, 16, 32, \ldots$）。存在返回 `true`，否则返回 `false`。

**关键点**：重排不改变「每个数字出现了几次」，所以问题等价于——**$n$ 的数字多重集，是否与某个 $2$ 的幂的数字多重集相同**。

**约束**：

- $1 \le n \le 10^9$
- 重排结果的位数与 $n$ 相同（不允许前导零），因此候选的 $2$ 的幂也必须是同样位数

## 2. 示例

**示例 1**

```text
输入：n = 1
输出：true
解释：1 = 2^0，不需要任何重排。
```

**示例 2**

```text
输入：n = 10
输出：false
解释：10 的重排只有 10 和 01，后者前导零不合法；
     而 10 与 1 都不是 2 的幂（01 即是 1，但首位为 0 被禁止）。
```

**示例 3**（补充，验证正向情形）

```text
输入：n = 821
输出：true
解释：821 重排可得 128 = 2^7，且 128 首位非零，合法。
```

## 3. 解题思路

### 3.1 暴力思路

直接枚举 $n$ 的所有数字排列：最坏 $10! = 3\,628\,800$ 种，对每种排列判断是否为 $2$ 的幂（判断 `x & (x-1) == 0` 是 $O(1)$）。$n \le 10^9$ 有 10 位时，$10!$ 量级在极限边上，且还要处理前导零与去重，写起来又慢又容易错。

换个方向想：**合法的重排结果（2 的幂）只有几十个**。$n \le 10^9 < 2^{30}$，但重排后位数不变，候选只需覆盖到 $10$ 位数字，即 $2^0$ 到 $2^{33}$（$2^{33} \approx 8.6 \times 10^9$，$2^{34} \approx 1.7 \times 10^{10}$ 已是 11 位）。候选规模是**常数级**，枚举候选远比枚举排列聪明。

### 3.2 核心观察：数字签名（计数向量）

![枚举候选 + 签名比较](images/wc93_q2_enumeration_flow.svg)

定义整数 $x$ 的**数字签名** $\mathrm{sig}(x)$ 为长度 $10$ 的计数向量：

$$\mathrm{sig}(x)[d] = \text{数字 } d \text{ 在 } x \text{ 的十进制表示中出现的次数}, \quad d = 0,1,\ldots,9$$

两个数可以互相重排 $\iff$ 它们的签名完全相同。于是：

$$n \text{ 可以重排成 } 2 \text{ 的幂} \iff \exists k \ge 0,\ \mathrm{sig}(2^k) = \mathrm{sig}(n)$$

**为什么不用管前导零？** 若 $\mathrm{sig}(2^k) = \mathrm{sig}(n)$，则 $2^k$ 本身就是 $n$ 的一个合法重排（它首位当然不是 $0$），所以只要签名相等就一定能构造出合法重排；反过来若存在合法重排等于 $2^k$，签名必然相等。前导零的限制在「存在性」判断中被自动满足。

签名相同的另一个好处：位数自动相同（总计数相等），不需要额外比较长度。

### 3.3 算法流程

```text
1. target = sig(n)
2. p = 1
3. 当 p <= 10^10 时循环：
   3.1 若 sig(p) == target：返回 true
   3.2 p <<= 1
4. 返回 false
```

枚举上界取 $10^{10}$ 是为了覆盖「$n$ 有 10 位」的情况：$2^{33}$ 已是 10 位，$2^{34}$ 是 11 位，与 $n$ 签名不同，多枚举几个也不会误判，只是浪费一点常数时间。

### 3.4 示例演算

以 `n = 821` 为例：

| $p$ | $p$ 的十进制 | $\mathrm{sig}(p)$ 非零项 | 与 $\mathrm{sig}(821)=\{1{:}1,2{:}1,8{:}1\}$ 比较 |
|-----|------------|------------------------|------------------------------------------|
| $2^0=1$ | 1 | $\{1{:}1\}$ | 位数不同，≠ |
| $2^1=2$ | 2 | $\{2{:}1\}$ | ≠ |
| $2^3=8$ | 8 | $\{8{:}1\}$ | ≠ |
| $2^6=64$ | 64 | $\{6{:}1,4{:}1\}$ | ≠ |
| $2^7=128$ | 128 | $\{1{:}1,2{:}1,8{:}1\}$ | **相等，返回 `true`** |

再以 `n = 10` 为例：$\mathrm{sig}(10) = \{1{:}1, 0{:}1\}$。所有 $2$ 的幂中只有 $2^{10}=1024$、$2^{20}=1048576$ 等含数字 $0$，但它们的非零项远多于两项，签名永不相等，最终返回 `false`。

## 4. 算法细节

1. **签名的表示**：C++ 用 `array<int,10>`（可直接 `==` 比较），Python 用 `tuple`（可哈希、可比较）。不要用排序后的字符串，虽然也能判等，但每次比较 $O(\log_{10} p)$ 且要多一次排序。
2. **取数位不要用 `to_string` 再统计**：`while (x > 0) { c[x % 10]++; x /= 10; }` 更快，且不受字符串分配影响。
3. **枚举上界**：$p$ 用 `long long` 递增。上界取 $10^{10}$ 时 $2^{33}$ 与 $2^{34}$ 仍会被检查，前者合法、后者位数更多，签名不可能相等，因此不会造成误判。
4. **`p` 从 $2^0=1$ 开始**：$n=1$ 时答案应为 `true`，从 $2$ 开始会漏掉。
5. **不判前导零**：如 §3.2 所述，签名相等即存在合法排列，无需额外判定；但如果把思路改成「枚举全排列」，前导零必须显式排除。
6. **签名相等 ⇒ 位数相同**：所以不必先比较位数，比较位数只是更快的短路优化。

## 5. 正确性证明

**引理 1（签名是重排的完全不变量）**：对任意两个正整数 $x, y$，$x$ 的数字可以重排成 $y$ $\iff$ $\mathrm{sig}(x) = \mathrm{sig}(y)$。

**证明**：
（$\Rightarrow$）若 $y$ 是 $x$ 的数字重排，则 $y$ 的每一位都来自 $x$ 的某一位，且是双射，故每个数字 $d$ 在 $y$ 中的出现次数与在 $x$ 中相同，即 $\mathrm{sig}(x)=\mathrm{sig}(y)$。
（$\Leftarrow$）若 $\mathrm{sig}(x)=\mathrm{sig}(y)$，把 $x$ 的各位数字按 $y$ 的顺序重新排列，得到的数逐位与 $y$ 相同，即等于 $y$，故 $y$ 是 $x$ 的一个重排。∎

**引理 2（候选集合足够）**：若 $n$ 存在合法重排等于某个 $2$ 的幂 $2^{k}$，则 $2^{k} \le 10^{10}$。

**证明**：$n \le 10^9$，即 $n$ 至多 10 位。重排不改变位数（首位非零），故 $2^k$ 也至多 10 位，即 $2^k < 10^{10}$。而 $2^{33} = 8\,589\,934\,592 < 10^{10}$、$2^{34} = 17\,179\,869\,184 > 10^{10}$，故 $k \le 33$，枚举 $p \le 10^{10}$ 覆盖全部可能。∎

**定理**：算法返回 `true` 当且仅当 $n$ 的数字存在一种首位非零的重排，使其成为 $2$ 的幂。

**证明**：
（充分性）设算法返回 `true`，则存在 $p = 2^k$ 使 $\mathrm{sig}(p)=\mathrm{sig}(n)$，由引理 1，$p$ 是 $n$ 的一个重排；又 $p \ge 1$ 的首位非零，故 $n$ 存在合法重排等于 $2$ 的幂。
（必要性）设 $n$ 存在合法重排 $2^k$，由引理 2 该 $2^k \le 10^{10}$ 必在枚举范围内，且由引理 1 $\mathrm{sig}(2^k)=\mathrm{sig}(n)$，算法在 $p=2^k$ 处即返回 `true`，不会走到最后的 `false`。∎

## 6. 复杂度分析

- **时间**：$O(\log_{10} n \cdot K)$，其中 $K$ 为候选个数。$K \le 34$（$2^0 \sim 2^{33}$），每个候选求签名 $O(\log_{10} p) \le 11$ 次除法，总计约 $34 \times 11 \approx 374$ 次常数运算，可视为 $O(1)$；形式上写作 $O(K \log n)$，$K=34$。
- **空间**：$O(1)$。签名是固定长度 $10$ 的计数数组，与 $n$ 规模无关。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool reorderedPowerOf2(int n) {
        array<int, 10> target = signature(n);
        for (long long p = 1; p <= 10000000000LL; p <<= 1) {
            if (signature(p) == target) return true;
        }
        return false;
    }
private:
    array<int, 10> signature(long long x) {
        array<int, 10> c{};
        while (x > 0) { c[x % 10]++; x /= 10; }
        return c;
    }
};
```

### Python

```python
class Solution:
    def reorderedPowerOf2(self, n: int) -> bool:
        def sig(x: int) -> tuple:
            c = [0] * 10
            while x > 0:
                c[x % 10] += 1
                x //= 10
            return tuple(c)

        target = sig(n)
        p = 1
        while p <= 10 ** 10:
            if sig(p) == target:
                return True
            p <<= 1
        return False
```

## 8. 边界情况与易错点

1. **$n = 1$**：$2^0 = 1$，答案 `true`。枚举必须从 $p=1$ 开始。
2. **前导零陷阱**：`n = 10` 时 `"01"` 看似是 $2^0=1$，但首位为 $0$ 不合法；这也是本题唯一的「合法性」约束。用签名法时它自动被排除（$\mathrm{sig}(10) \ne \mathrm{sig}(1)$），无需特判。
3. **签名必须比长度**：$\{1{:}1\}$（即 1）与 $\{1{:}1, 0{:}1\}$（即 10）看着都「像一个 1」，但计数向量长度相同、内容不同，不会误判。
4. **枚举上界别写 30 次**：$n$ 可能是 $10$ 位数（如 $n = 10^9$），只枚举 $2^0 \sim 2^{29}$ 会漏掉 $10$ 位的 $2^{30} \sim 2^{33}$。
5. **`int` 溢出**：C++ 中 $2^{31}$ 起会溢出 `int`，循环变量必须用 `long long`。
6. **重复数字**：如 `n = 112`（$\mathrm{sig}=\{1{:}2,2{:}1\}$），候选里没有签名相同的 $2$ 的幂，应返回 `false`；若用「枚举排列 + 判幂」的写法，要记得去重，否则会重复计算但不影响正确性，只是更慢。
