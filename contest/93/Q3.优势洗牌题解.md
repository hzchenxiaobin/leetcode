# LeetCode 优势洗牌 题解

## 1. 题目概述

- **标题 / 题号**：优势洗牌（#870，medium）
- **链接**：https://leetcode.cn/problems/advantage-shuffle/
- **来源**：LeetCode 第 93 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、双指针、排序

**题意**：给定两个等长数组 `nums1` 与 `nums2`（长度 $n$）。`nums1` 相对 `nums2` 的**优势**，定义为满足 `nums1[i] > nums2[i]` 的下标个数。可以任意重排 `nums1`（`nums2` 不动），要求返回**任意一个**使优势最大的排列。

**关键点**：`nums1` 可以随便排，`nums2` 的位置是固定的——所以「对手」是定死的，我们只是给每个位置分配一张牌。

**约束**：

- $1 \le n \le 10^5$
- $0 \le nums1[i], nums2[i] \le 10^9$

## 2. 示例

**示例 1**

```text
输入：nums1 = [2,7,11,15], nums2 = [1,10,4,11]
输出：[2,11,7,15]
解释：逐位比较 2>1 ✓、11>10 ✓、7>4 ✓、15>11 ✓，优势 = 4（最大可能值）。
```

**示例 2**

```text
输入：nums1 = [12,24,8,32], nums2 = [13,25,32,11]
输出：[24,32,8,12]
解释：24>13 ✓、32>25 ✓、8>32 ✗、12>11 ✓，优势 = 3。
     nums2 中的 32 无法被战胜（nums1 最大也只有 32），只能放弃这一位，把最小的 8 送上去。
```

## 3. 解题思路

### 3.1 暴力思路

枚举 `nums1` 的所有排列，对每个排列统计优势并取最大：$O(n! \cdot n)$，$n \le 10^5$ 时完全不可行。

一个看似合理、实则**错误**的贪心是「同序配对」：`nums1` 升序、`nums2` 升序，逐位比较。反例：`nums1 = [2,3,9]`、`nums2 = [1,4,10]`。同序配对得到 $2>1$ ✓、$3>4$ ✗、$9>10$ ✗，只有 $1$ 场胜利；但把 9 调去对付 4：$[2,9,3]$ 得到 $2>1$ ✓、$9>4$ ✓、$3>10$ ✗，有 $2$ 场胜利。问题出在**配对顺序**——大牌应该去打「打得过的最强对手」，而不是被最强的对手白白消耗。

### 3.2 核心观察：两指针「能赢就硬碰，赢不了就送最小的」

![示例演算：牺牲最小的 8 去打无法战胜的 32](images/wc93_q3_walkthrough.svg)

把 `nums1` **升序**排好为 $a_0 \le a_1 \le \cdots \le a_{n-1}$，把 `nums2` 的下标按**降序**排好，即从最难打的对手开始处理。维护两个指针：

- `lo` 指向 $a$ 中还没派出的**最小**牌，`hi` 指向**最大**牌。
- 当前要对付的对手是 `nums2[idx]`（从最大的对手开始）：
  - 若 $a_{hi} > nums2[idx]$：**连最大的都能赢**，说明这张大牌能拿下这个对手，直接硬碰，`hi--`。
  - 否则：最大的牌都赢不了它，那么 $a$ 中**没有任何牌**能赢这个对手——这一位必输。既然必输，就派**最小**的牌去送，把好牌留给后面更弱的对手，`lo++`。

**为什么从最强的对手开始处理？** 关键在「必输」这一步：只有当对手是**当前最强**时，「最大的牌都赢不了它」才能推出「剩余没有任何牌能赢它」（引理 1）。若从弱对手开始处理，大牌可能已经被消耗在别处，等最强的对手出现时既无法判定必输，也不知道该牺牲哪张牌。按对手从强到弱处理，每一轮要么确定性地赢下一场，要么确定性地放弃一场，不留模糊地带。

更细的直觉是：`hi` 上那张牌是「万能牌」，只要它能赢就赢下来**不会亏**（它迟早要出场，用在最强的可胜对手上最划算）；而它赢不了时，这场注定要输，用最小的牌去输，等于把「万能牌」完整地保留给后面的弱对手。

### 3.3 算法流程

```text
1. a = sorted(nums1)；order = nums2 的下标按 nums2 值降序
2. lo = 0，hi = n - 1，ans = 长度 n 的数组
3. for idx in order：
   3.1 若 a[hi] > nums2[idx]：ans[idx] = a[hi]；hi -= 1
   3.2 否则：ans[idx] = a[lo]；lo += 1
4. 返回 ans
```

由于 `lo` 与 `hi` 从两端出发、每次必有一个移动，循环 $n$ 次后恰好用完所有牌，`ans` 的每个位置都被填一次。

### 3.4 示例演算

以示例 2 为例：`nums1 = [12,24,8,32]`、`nums2 = [13,25,32,11]`。

- 升序 $a = [8,12,24,32]$；对手降序处理顺序为位置 $2(32) \to 1(25) \to 0(13) \to 3(11)$。

| 处理位置 | 对手 | $a_{hi}$ | 判定 | 派出的牌 | 指针变化 |
|---------|------|---------|------|---------|---------|
| 2 | 32 | 32 | $32 > 32$ 不成立 | 8（牺牲） | `lo: 0→1` |
| 1 | 25 | 32 | $32 > 25$ ✓ | 32 | `hi: 3→2` |
| 0 | 13 | 24 | $24 > 13$ ✓ | 24 | `hi: 2→1` |
| 3 | 11 | 12 | $12 > 11$ ✓ | 12 | `hi: 1→0` |

填回原位置得 `ans = [24, 32, 8, 12]`，优势为 $3$，与示例一致。

## 4. 算法细节

1. **不要真的排序 `nums2`**：`nums2` 的位置是有意义的，只能排序**下标**（`iota` + 按值降序的比较器，或 Python 的 `sorted(range(n), key=lambda i: -nums2[i])`），最后按原下标填回答案。
2. **`lo` 与 `hi` 不会交叉**：每次迭代恰好消耗一张牌（要么 `hi--` 要么 `lo++`），$n$ 次后 $lo > hi$，不会出现同一张牌被派两次。
3. **等号的处理**：优势要求**严格大于**，所以判定必须是 $a_{hi} > nums2[idx]$；写成 $\ge$ 会把平局当胜利，答案偏大。
4. **排序的稳定性无关紧要**：`nums1` 中相等的牌可互换，`nums2` 中相等的对手可互换，任意一种顺序都得到同样大小的优势。
5. **答案不唯一**：题目接受任意最优排列，所以无需与示例输出逐位相同；本文的写法在示例上恰好也复现了官方输出。
6. **复杂度由排序主导**：两次排序 $O(n \log n)$，扫描 $O(n)$。

## 5. 正确性证明

把 `nums1` 升序记为 $a_0 \le a_1 \le \cdots \le a_{n-1}$，把 `nums2` 降序记为 $b_1 \ge b_2 \ge \cdots \ge b_n$（降序只是重排对手，配对方案与「赢场数」都不受影响）。贪心依次处理 $b_1, b_2, \ldots, b_n$，每次用当前剩余牌的**最大**或**最小**回应。

**引理 1（必输判定）**：处理 $b_t$ 时，若当前剩余最大牌 $a_{hi} \le b_t$，则剩余的任何牌都赢不了 $b_t$。

**证明**：$a_{hi}$ 是剩余牌的最大值，对剩余任意牌 $a_j$ 有 $a_j \le a_{hi} \le b_t$，即 $a_j > b_t$ 不成立。∎

**引理 2（硬碰不亏）**：若 $a_{hi} > b_t$（$b_t$ 是当前最强的对手），则存在一个最优方案把 $a_{hi}$ 配给 $b_t$。

**证明**：取任一最优方案 $O$。若 $O$ 中 $a_{hi}$ 已配给 $b_t$，结论成立。否则设 $O$ 中 $b_t$ 配给 $a_j$（$j \ne hi$）、$a_{hi}$ 配给 $b_s$。交换这两张牌的对手得到 $O'$：$a_{hi}$ 对 $b_t$、$a_j$ 对 $b_s$。只需比较这两场（其余配对不变）的赢场数。

交换后 $a_{hi}$ 对 $b_t$ 必胜（前提 $a_{hi} > b_t$）。交换前这两场赢了几场分两种情形：

- $a_{hi}$ 赢过 $b_s$：则 $a_{hi} > b_s$。若 $a_j$ 也赢过 $b_t$，即 $a_j > b_t$，则 $a_j > b_t \ge b_s$（$b$ 降序、$s > t$），交换后 $a_j$ 对 $b_s$ 仍赢，两场全胜，与交换前持平；若 $a_j$ 输给 $b_t$，交换前只有 $1$ 胜，交换后至少 $1$ 胜（$a_{hi}$ 那场），不减。
- $a_{hi}$ 输给 $b_s$：则 $a_{hi} \le b_s \le b_t$，与 $a_{hi} > b_t$ 矛盾，此情形不可能出现。

故 $O'$ 的赢场数不少于 $O$；而 $O$ 已是最优，所以 $O'$ 也是最优，且把 $a_{hi}$ 配给了 $b_t$。∎

**引理 3（牺牲不亏）**：若 $a_{hi} \le b_t$，则存在一个最优配对方案把当前最小的 $a_{lo}$ 配给 $b_t$。

**证明**：由引理 1，任何方案在 $b_t$ 处都必输，所以这一位的收益恒为 $0$。取任一最优方案 $O$，设 $b_t$ 配给 $a_j$，$a_{lo}$ 配给 $b_s$。交换二者：$a_{lo}$ 去输给 $b_t$（收益 $0$，与原来相同），$a_j$ 去对 $b_s$；由于 $a_j \ge a_{lo}$，若原来 $a_{lo}$ 能赢 $b_s$（即 $a_{lo} > b_s$），则 $a_j \ge a_{lo} > b_s$ 也能赢；若原来输，则 $a_j$ 至多也是输，赢场数不减。故交换后的方案仍最优且把 $a_{lo}$ 配给 $b_t$。∎

**定理**：贪心算法输出的排列取得最大可能优势。

**证明**：对剩余待配对的元素个数 $m$ 归纳。$m = 0$ 时显然。设 $m \ge 1$，当前最强对手为 $b_t$、剩余牌为 $a_{lo..hi}$：

- 若 $a_{hi} > b_t$，由引理 2 存在最优方案把 $a_{hi}$ 配给 $b_t$，贪心正是如此；删去这对后剩余 $m-1$ 个元素上的子问题，由归纳假设贪心在子问题上最优，故整体最优。
- 若 $a_{hi} \le b_t$，由引理 3 存在最优方案把 $a_{lo}$ 配给 $b_t$，贪心正是如此；同样删去这对后由归纳假设得整体最优。

两种情形下贪心的本轮选择都被某个最优方案包含，且剩余子问题同构，故贪心输出的优势等于最优值。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。`nums1` 排序 $O(n \log n)$；`nums2` 下标排序 $O(n \log n)$；双指针扫描 $O(n)$。
- **空间**：$O(n)$。下标数组、答案数组、`nums1` 的副本各 $O(n)$；若允许原地修改 `nums1` 可省去副本。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    vector<int> advantageCount(vector<int>& nums1, vector<int>& nums2) {
        int n = nums1.size();
        vector<int> a = nums1;
        sort(a.begin(), a.end());
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int i, int j) { return nums2[i] > nums2[j]; });
        vector<int> ans(n);
        int lo = 0, hi = n - 1;
        for (int idx : order) {
            if (a[hi] > nums2[idx]) ans[idx] = a[hi--];   // 能赢就硬碰
            else ans[idx] = a[lo++];                      // 必输就送最小的
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def advantageCount(self, nums1: list[int], nums2: list[int]) -> list[int]:
        a = sorted(nums1)
        n = len(nums1)
        order = sorted(range(n), key=lambda i: -nums2[i])
        ans = [0] * n
        lo, hi = 0, n - 1
        for idx in order:
            if a[hi] > nums2[idx]:
                ans[idx] = a[hi]
                hi -= 1
            else:
                ans[idx] = a[lo]
                lo += 1
        return ans
```

## 8. 边界情况与易错点

1. **把 `nums2` 排序后忘记还原**：`nums2` 的位置固定，只能排序下标；直接排 `nums2` 会让答案错位。
2. **等号写错**：优势要求严格大于。`a[hi] >= nums2[idx]` 会把平局算成胜利，优势虚高。
3. **牺牲时派了 `a[hi]`**：必输的位置要送**最小**的牌；送最大的会让后面能赢的场次丢掉。
4. **`lo` / `hi` 更新方向**：`hi` 是「已派出的最大牌」游标，只能左移；`lo` 只能右移。写反会重复派牌或越界。
5. **`nums1` 全小于 `nums2`**：每轮都走牺牲分支，`lo` 一路右移，最终答案恰为升序排列，优势 $0$，正确。
6. **极端值**：$nums1[i]=0$ 与 $nums2[i]=0$ 时 $0>0$ 不成立，不算优势；值域到 $10^9$，比较无需担心溢出（C++ 中两个 `int` 相减才可能溢出，本题只做比较）。
7. **长度为 1**：只循环一次，两分支必择其一，结果正确。
