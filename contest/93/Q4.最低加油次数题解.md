# LeetCode 最低加油次数 题解

## 1. 题目概述

- **标题 / 题号**：最低加油次数（#871，hard）
- **链接**：https://leetcode.cn/problems/minimum-number-of-refueling-stops/
- **来源**：LeetCode 第 93 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、动态规划、堆（优先队列）

**题意**：一辆车从起点 $0$ 出发，目的地距起点 `target` 英里。油箱**容量无限**，初始有 `startFuel` 升油，每行驶 $1$ 英里消耗 $1$ 升。沿途有若干加油站，`stations[i] = [position_i, fuel_i]` 表示第 $i$ 个加油站在 $position_i$ 处、储油 $fuel_i$ 升，到达时可以**选择**把该站全部油加入车中（也可以不加）。求到达目的地所需的最少加油次数；无法到达则返回 `-1`。

**关键点**：

- 油箱没有容量上限，所以「加油的总量」和「加油的时机」可以解耦——只要总量够、且任何时刻油不为负即可。
- 题目允许「到达加油站时剩余油量为 $0$ 仍可加油」「到达目的地时剩余油量为 $0$ 仍算到达」。

**约束**：

- $1 \le target, startFuel \le 10^9$
- $0 \le stations.length \le 500$
- $1 \le position_i < position_{i+1} < target$（位置严格递增、且都严格小于目标）
- $1 \le fuel_i < 10^9$

## 2. 示例

**示例 1**

```text
输入：target = 1, startFuel = 1, stations = []
输出：0
解释：一脚油门直达，无需加油。
```

**示例 2**

```text
输入：target = 100, startFuel = 1, stations = [[10,100]]
输出：-1
解释：油只够跑 1 英里，连 10 英里处的加油站都到不了，更不可能到 100。
```

**示例 3**

```text
输入：target = 100, startFuel = 10, stations = [[10,60],[20,30],[30,30],[60,40]]
输出：2
解释：在 10 英里处加 60（油变 60），开到 60 英里处（耗 50，剩 10）再加 40，
     油变 50，再开 40 英里到终点（剩 10）。共加油 2 次。
     若在 20、30 英里处各加 30，也能到终点，但那是 2 次之外的其它组合；
     最优是 2 次，且无法只用 1 次到达。
```

## 3. 解题思路

### 3.1 暴力思路

- **枚举子集**：$2^{|stations|}$ 种「在哪些站加油」的组合，逐个模拟是否可达，$|stations| \le 500$ 时不可行（$2^{500}$）。
- **动态规划**：令 $dp[i]$ 表示「加油 $i$ 次能到达的最远距离」，初值 $dp[0] = startFuel$，转移时对每个站 $s$：若 $dp[i] \ge position_s$，则 $dp[i+1] = \max(dp[i+1], dp[i] + fuel_s)$。这是 $O(n^2)$ 的可行解（$n \le 500$ 时 $2.5\times 10^5$ 次运算），但本题存在 $O(n \log n)$ 的贪心，且 DP 的写法需要二重循环、还要扫描答案，不够优雅。

### 3.2 核心观察：延迟决策 + 大顶堆

![扫描 + 大顶堆：油不够时才补记一次「取最大」的加油](images/wc93_q4_heap_flow.svg)

先只考虑「一路不加，能开多远」。设当前累计油量为 `fuel`，扫描到第 $i$ 个加油站时先扣掉从上一处到这儿的油耗。如果 `fuel < 0`，说明用目前的油到不了这里——**必须**在之前路过的某个站加过油。

关键观察有两条：

1. **油箱无限 ⇒ 加油顺序无关**。在站 $A$ 加 60 升和在站 $B$ 加 30 升，对「最终能跑多远」的贡献只是数值相加；影响可行性的只有「在每个位置时累计油量是否非负」。因此可以**先假设不加**，等油不够时再「回头」从已路过的站里挑一个加油——这在真实行驶中是合法的（车确实经过了那些站），只是把决策推迟了。
2. **次数最少 ⇒ 每次加油都要尽可能大**。既然迟早要加 $k$ 次油，那么让这 $k$ 次的总油量尽可能大，就能撑得最远。于是油不够时，从**已路过且尚未使用**的加油站里取**油量最大**的那个。

这就是「**延迟决策 + 大顶堆**」：堆里存的是「已经路过、但还没决定要加」的油量，油不够时弹出堆顶并计数，相当于说「其实我在那个站加过油」。

### 3.3 算法流程

```text
1. fuel = startFuel，prev = 0，ans = 0，heap = 空大顶堆
2. for (pos, gas) in stations（按位置升序）：
   2.1 if pos >= target: break            // 目标之后的站无用
   2.2 fuel -= pos - prev                 // 从上一处开到这里
   2.3 while fuel < 0 且 heap 非空：
           fuel += 弹出堆顶；ans += 1     // 补记一次加油
   2.4 if fuel < 0: return -1             // 补完也到不了 → 无解
   2.5 把 gas 入堆；prev = pos            // 路过了，先记下
3. fuel -= target - prev                 // 最后一段直冲终点
4. while fuel < 0 且 heap 非空：fuel += 弹出堆顶；ans += 1
5. return fuel >= 0 ? ans : -1
```

### 3.4 示例演算

对示例 3（`target=100, startFuel=10`，站点 `[10,60] [20,30] [30,30] [60,40]`）：

![示例演算：四次补记机会，最终 ans = 2](images/wc93_q4_walkthrough.svg)

| 处理 | pos / gas | fuel 变化 | 堆内油量 | ans |
|------|-----------|-----------|---------|-----|
| 站 1 | 10 / 60 | $10-10=0$ | $\{60\}$ | 0 |
| 站 2 | 20 / 30 | $0-10=-10$，弹出 60 → 50 | $\{30\}$ | 1 |
| 站 3 | 30 / 30 | $50-10=40$ | $\{30,30\}$ | 1 |
| 站 4 | 60 / 40 | $40-30=10$ | $\{40,30,30\}$ | 1 |
| 终点 | 100 | $10-40=-30$，弹出 40 → 10 | $\{30,30\}$ | 2 |

最后 `fuel = 10 ≥ 0`，返回 `2`。回看这 2 次补记：**在 10 英里处加了 60**、**在 60 英里处加了 40**——与示例解释完全一致。

## 4. 算法细节

1. **为什么先扣油再入堆**：到达站点 $pos$ 时油箱里的油是「到站后」的量，这个站自己的油此刻还没加；把它入堆表示「以后可以回头补记」。若先入堆再扣油，会把「还没决定加的油」误当成已加，导致能开到的距离被高估。
2. **`while` 而不是 `if`**：在同一个站可能需要连续补记多次（比如一次性差很多油）。例如 `startFuel=1`、站点 `[2,1] [3,1] [4,100]` 在某站会连续弹出多份油。
3. **`pos >= target` 时跳出**：题目保证 $position_i < target$，但写上 `break` 更稳健（若数据违约也不会多算）。
4. **`fuel` 用 `long long`**：$target \le 10^9$、$fuel_i < 10^9$、$n \le 500$，加油总量可达 $5 \times 10^{11}$，`int` 必溢出。
5. **堆里可以存重复值**：不同站的油量可能相同，`priority_queue<int>` 天然支持。
6. **终点也算一次「站」**：把最后一段单独处理，避免在 `stations` 末尾 `push` 一个假的 `[target, 0]` 造成「给终点加 0 升油」的混淆；两种写法等价。

## 5. 正确性证明

**定义**：一个「加油方案」是若干加油站构成的集合 $S$（每个站至多选一次），把 $S$ 按位置排序为 $s_1 < s_2 < \cdots < s_k$。方案可行，当且仅当对每个 $j$ 有

$$startFuel + \sum_{i<j} fuel_{s_i} \ge position_{s_j}, \qquad startFuel + \sum_{i \le k} fuel_{s_i} \ge target$$

**引理 1（回溯合法）**：贪心每次「补记」的加油站，在真实行驶中都可以到达；因此贪心构造的方案是一个可行方案。

**证明**：贪心在第 $i$ 站「卡住」（`fuel < 0`）时做的补记，选取的站 $s$ 满足 $position_s \le$ 当前已可达的最远位置 $D$。构造真实路线：按位置顺序依次经过 $s_1, s_2, \ldots$（贪心的补记集合按位置排序），在每个 $s_j$ 处加油。我们需要说明到 $s_j$ 时油量非负：贪心扫描到 $s_j$ 时尚未「卡住」（否则会在更早处补记），说明用此前的油可以开过 $s_j$；而把后续补记的油按时间顺序前移只可能让更早的位置油量更充足（油量是同一个前缀和，只是被提前计入）。更形式化地，贪心维护的 `fuel` 恰为「已补记油量之和 − 已行驶距离」，扫描时它始终 $\ge 0$ 直到下一次卡住，故按位置顺序加油的路线在每个站处油量非负。∎

**引理 2（取大优先不劣）**：设在某次「卡住」时，已路过且未使用的加油站中油量最大者为 $g$。若某个可行方案在这一步记录的是某个油量 $f < g$ 的站，则把它替换成取到 $g$ 的那个站，方案仍然可行，且之后每个位置的累计油量不减。

**证明**：两个候选站都已经被路过（位置不超过当前可达距离），替换不改变「能否到达这些站」；替换后该步的加油量由 $f$ 变为 $g > f$，而后续所有位置的累计油量都是「$startFuel +$ 已加油量之和 $-$ 已行驶距离」，只增不减，故仍处处非负，可行性保持。∎

**引理 3（必要性）**：贪心第 $j$ 次补记时，任何只加了 $j-1$ 次油的方案都无法越过该时刻所在的位置。

**证明**：对 $j$ 归纳。$j=1$：贪心在位置 $p_1$ 处油为负，即 $startFuel < p_1$，而不加油只能开 $startFuel$ 英里，故无法越过 $p_1$。设命题对 $j$ 成立（任何 $j-1$ 次加油都越不过 $p_j$）。考虑任意加 $j$ 次油的可行方案：它的第 $j$ 次加油必须发生在位置 $\le p_j$ 处（否则它要用前 $j-1$ 次油越过 $p_j$，与归纳假设矛盾）。于是它的第 $j$ 次加油的候选站与贪心第 $j$ 次补记的候选站同属「位置 $\le$ 贪心当时可达距离」，由引理 2，贪心取到了这组候选中的最大油量，故贪心前 $j$ 次补记的累计油量不小于该方案前 $j$ 次加油的累计油量。而贪心在第 $p_{j+1}$ 处累计油量为负（否则不会触发第 $j+1$ 次补记），故该方案在 $p_{j+1}$ 处累计油量也为负，无法越过 $p_{j+1}$。归纳成立。∎

**定理**：算法返回的 `ans` 是最少加油次数；无解时返回 `-1`。

**证明**：由引理 1，贪心方案可行，故 `ans` 是一个可行方案的加油次数。由引理 3（取 $j = ans$），任何只用 $ans-1$ 次加油的方案都无法到达终点，故 `ans` 不可能更小。当堆空仍油量不足时，说明「所有已路过且可到达的站都已加过油，仍跑不到下一处」，由引理 3 的论证同样可知不存在可行方案，返回 `-1` 正确。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。扫描 $n$ 个站，每个站至多入堆一次、出堆一次，堆操作 $O(\log n)$；总计 $O(n \log n)$。
- **空间**：$O(n)$。大顶堆最多存 $n$ 个元素。

对比 DP 解法：$O(n^2)$ 时间、$O(n)$ 空间。$n \le 500$ 两者都能通过，但堆解法的复杂度更低、代码更短。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minRefuelStops(int target, int startFuel, vector<vector<int>>& stations) {
        priority_queue<int> heap;          // 路过的加油站的油量（大顶堆）
        int ans = 0, prev = 0;
        long long fuel = startFuel;
        for (auto& st : stations) {
            int pos = st[0], gas = st[1];
            if (pos >= target) break;
            fuel -= pos - prev;            // 开到该站
            while (fuel < 0 && !heap.empty()) {   // 油不够：补记一次加油
                fuel += heap.top(); heap.pop(); ans++;
            }
            if (fuel < 0) return -1;
            heap.push(gas);                // 记录本站的油，先不加
            prev = pos;
        }
        fuel -= target - prev;             // 最后一段直冲终点
        while (fuel < 0 && !heap.empty()) {
            fuel += heap.top(); heap.pop(); ans++;
        }
        return fuel >= 0 ? ans : -1;
    }
};
```

### Python

```python
import heapq

class Solution:
    def minRefuelStops(self, target: int, startFuel: int, stations: list[list[int]]) -> int:
        heap = []          # 大顶堆（存负数）：已路过但还没加的油
        ans = 0
        fuel = startFuel
        prev = 0
        for pos, gas in stations:
            if pos >= target:
                break
            fuel -= pos - prev                     # 驶到该站
            while fuel < 0 and heap:               # 油不够：补记加油
                fuel += -heapq.heappop(heap)
                ans += 1
            if fuel < 0:
                return -1                          # 补完也到不了
            heapq.heappush(heap, -gas)             # 记录本站的油，先不加
            prev = pos
        fuel -= target - prev                      # 最后一段：直冲终点
        while fuel < 0 and heap:
            fuel += -heapq.heappop(heap)
            ans += 1
        return ans if fuel >= 0 else -1
```

## 8. 边界情况与易错点

1. **`startFuel >= target`**：`stations` 可能为空，第一次扣油就足以直达，返回 `0`。
2. **`int` 溢出**：加油总量可达 $500 \times 10^9 = 5\times 10^{11}$，`fuel` 必须用 `long long`。这是本题最常见的 WA 原因之一。
3. **`while` 写成 `if`**：一次卡住可能需要连加多次油。例如 `target=10, startFuel=1, stations=[[2,1],[3,1],[4,100]]` 会在 4 英里处连弹两次。
4. **先入堆再扣油**：会把本站的油错误地算进「开到本站」的油量里，导致能到达的距离被高估（甚至无解被判成有解）。
5. **终点处理**：若忘了最后一段 `fuel -= target - prev`，会漏掉「最后一站到终点」的消耗；若把这最后一段写进循环内部，则终点没有对应的加油站，容易越界。
6. **堆空但仍缺油**：此时必须立刻返回 `-1`，不能继续往后扫——后面的站更远，更到不了。
7. **`stations` 已按位置升序**：题目保证 `position_i < position_{i+1}`，不要额外排序，也不要打乱顺序扫描。
