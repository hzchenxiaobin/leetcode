# LeetCode 字符串中的第一个唯一字符 题解

## 1. 题目概述

- **标题 / 题号**：字符串中的第一个唯一字符（#387，easy）
- **链接**：https://leetcode.cn/problems/first-unique-character-in-a-string/
- **来源**：LeetCode 第 1 场周赛（Warm-Up Contest） Q2
- **难度**：简单
- **标签**：队列、哈希表、字符串、计数

**题意**：给定一个只含小写字母的字符串 $s$，找出**第一个只出现一次的字符**，返回它的**下标**；若不存在这样的字符，返回 $-1$。这里的「第一个」指**下标最小**，与字符的字典序无关。

**约束**：

- $1 \le |s| \le 10^5$
- $s$ 只包含小写英文字母

## 2. 示例

**示例 1**

```text
输入：s = "leetcode"
输出：0
解释：下标 0 的 'l' 在整个串中只出现一次，且它是最靠前的唯一字符。
```

**示例 2**

```text
输入：s = "loveleetcode"
输出：2
解释：'l'（0、4）与 'o'（1、9）都重复；下标 2 的 'v' 只出现一次，故答案为 2。
```

**示例 3**

```text
输入：s = "aabb"
输出：-1
解释：'a' 出现 2 次、'b' 出现 2 次，不存在唯一字符。
```

## 3. 解题思路

### 3.1 暴力思路

对每个下标 $i$，把整个串再扫一遍，统计 $s[i]$ 出现了几次：

$$O(n) \times O(n) = O(n^2)$$

$n = 10^5$ 时约 $10^{10}$ 次字符比较，必然超时。另一类常见写法是对每个下标调用 `find` / `rfind`（或 `indexOf` / `lastIndexOf`）判断是否唯一，最坏同样是 $O(n^2)$；即使改成「对 26 个字母各调用一次 `count` 与 `find`，再取最小下标」，虽然能过（C 层实现，实际是 $26n$ 次扫描），但本质上是把同一段前缀重复扫了 26 遍，写法也更绕。

问题的本质是：**我们只需要知道每个字符的总出现次数，而这件事与扫描顺序无关。** 暴力把「数频次」和「找位置」这两件事重复做了 $n$ 遍。

### 3.2 核心观察：把「唯一性」与「最小下标」解耦

![唯一性是全局属性：先数频次，再按下标找](images/wc1_q2_two_pass_concept.svg)

**关键观察**：判定一个字符是否唯一，只需要它的**全局频次** $cnt[c]$；而「第一个」这一要求只与**下标顺序**有关。两个条件互不依赖，于是可以拆成两遍独立的线性扫描：

- 第一遍：遍历 $s$，把 $s[i]$ 所属字母的计数器加 1，得到每个字母的出现总次数；
- 第二遍：**仍从下标 0 开始**遍历，第一个满足 $cnt[s[i]] = 1$ 的下标就是答案。

**为什么单遍扫描不行？** 读到下标 $i$ 时，$s[i+1..n)$ 还没被读入，我们无法预知 $s[i]$ 是否还会出现（示例 1 中读到 `'l'` 时就必须往后看，才能确认它唯一）。这不是“实现不够聪明”，而是**信息不完备**：任何在 $i$ 处就下结论的算法，都存在一个把 $s[i]$ 再放到末尾的输入让它出错。所以必须先把整串的频次数完。

答案可以写成：

$$\text{ans} = \min\{\, i \mid cnt[s[i]] = 1 \,\}$$

若该集合为空则返回 $-1$。由于第二遍严格按下标递增的顺序检查，**第一次**命中的下标天然就是这个集合的最小元素，不需要额外比较。

### 3.3 算法流程

![算法流程：两次线性扫描定答案](images/wc1_q2_count_flow.svg)

1. 开一个长度 26 的计数数组 $cnt$，初值全为 0；
2. **第一遍**：`for ch in s: cnt[ch - 'a'] += 1`；
3. **第二遍**：`for i in 0..n-1`，若 `cnt[s[i] - 'a'] == 1` 则立即 `return i`；
4. 第二遍结束仍未返回，说明没有任何唯一字符，`return -1`。

两遍都是纯粹的线性扫描，没有嵌套循环、没有排序，也没有任何回溯。

### 3.4 示例演算

![示例演算：loveleetcode](images/wc1_q2_walkthrough.svg)

以 `s = "loveleetcode"`（$n = 12$）为例，第一遍得到的非零频次为：`l:2`、`o:2`、`v:1`、`e:4`、`t:1`、`c:1`、`d:1`（其余 19 个字母为 0）。第二遍按下标推进：

| $i$ | $s[i]$ | $cnt[s[i]]$ | 判定 |
|-----|--------|-------------|------|
| 0 | `l` | 2 | 不唯一，跳过 |
| 1 | `o` | 2 | 不唯一，跳过 |
| 2 | `v` | 1 | 唯一，立即返回 **2** |

对照另外两个官方示例：

| 字符串 | 频次要点 | 第二遍结果 |
|--------|----------|------------|
| `"leetcode"` | `l:1`、`e:3`、`t:1`、`c:1`、`o:1`、`d:1` | 第一步 $i=0$ 即命中，返回 0 |
| `"aabb"` | `a:2`、`b:2` | 四个下标都不满足，返回 −1 |

## 4. 算法细节

1. **用数组而非哈希表**：字符集只有 26 个小写字母，`int cnt[26]` 是最优结构——一次数组寻址即可完成自增与查询；C++ 里它省掉了 `unordered_map` 的哈希计算与冲突探测，也不会因扩容触发 rehash（Python 侧的常数比较见第 7 条）。
2. **两遍的顺序不可交换**：必须先统计完再查找。若在统计过程中判断 $cnt = 1$ 就返回，读到的是「到此为止」的局部频次，后面的重复还没被计入，必然误判。
3. **提前返回保证下标最小**：第二遍从左到右扫描，第一次命中就 `return`，因此不需要维护 `best = min(best, i)`。循环外的 `return -1` 是唯一的兜底出口。
4. **下标换算**：C++ 写 `ch - 'a'`，Python 写 `ord(ch) - 97`，两者等价。字符本身即 ASCII 码，不要用 `hash(ch) % 26` 之类的写法——哈希碰撞会把两个不同字母混成同一个桶，直接导致错误答案。
5. **空间是 $O(1)$ 而非 $O(n)$**：只开 26 个计数器，与 $n$ 无关。也**不要**为每个字符维护下标列表（`map<char, vector<int>>`）：那是 $O(n)$ 空间，而本题只需要「首次出现」这一个信息，向量中的其余元素全部浪费。
6. **位运算压常数（可选）**：若追求极致，可用两个 32 位整数代替计数数组：`twice |= once & bit; once |= bit;`，最终 `once & ~twice` 的 1 位就表示「恰好出现一次的字母」。但注意**位图仍然救不了单遍扫描**——它只告诉你「哪些字符唯一」，告诉不了「哪个下标最先」，所以第二遍扫描依旧不可省。
7. **Python 侧的常数差异**：CPython 的 `collections.Counter` 把计数下沉到 C 层的 `_count_elements`，实测比手写 `for` 循环快约 1.7 倍；而「对每个出现过的字母调用一次 `s.count(ch)` 判断是否唯一、再用 `s.find(ch)` 取下标」在本机 $|s| = 10^5$ 时更快（约 2 ms，手写循环约 14 ms）。三者都是 $O(n)$ 级，差别只在常数放在解释器还是 C 层。竞赛仍推荐显式两遍 + 26 数组：逻辑最直白，也最容易移植到 C++ / Java。
8. **该写法不依赖 $n$ 的大小**：第一遍 $n$ 次自增、第二遍最坏 $n$ 次比较，共 $2n$ 次基本操作，跑到 $|s| = 10^5$ 也在毫秒级。

## 5. 正确性证明

**引理 1（频次正确）**：第一遍扫描结束后，对任意字母 $c$，$cnt[c]$ 等于 $c$ 在 $s$ 中的出现总次数。

**证明**：$cnt$ 初值全为 0；第一遍对 $s$ 的每个字符恰好访问一次，并只对「该字符对应的那一个」计数器加 1。设 $c$ 出现 $k$ 次，则其计数器被加 1 恰好 $k$ 次，其余操作不影响它，故 $cnt[c] = k$。∎

**引理 2（首个命中即最小下标）**：设 $i_0 = \min\{\, i \mid cnt[s[i]] = 1 \,\}$ 且该集合非空。则第二遍扫描恰好在 $i = i_0$ 处首次返回，且返回值就是 $i_0$。

**证明**：由 $i_0$ 的最小性，对所有 $j < i_0$ 都有 $cnt[s[j]] \ne 1$，即频次至少为 2，因此第二遍在 $j < i_0$ 处不会返回；而在 $i = i_0$ 处有 $cnt[s[i_0]] = 1$，条件成立，算法在此处返回 $i_0$。又由引理 1，$cnt[s[i_0]] = 1$ 意味着 $s[i_0]$ 在整串中只出现一次。∎

**定理**：算法输出 $i_0$（当唯一字符集合非空）或 $-1$（当集合为空），即题面所要求的答案。

**证明**：

- 集合非空时，由引理 2，第二遍在 $i_0$ 处返回，且 $i_0$ 是唯一字符中的最小下标；对任意 $j < i_0$，$s[j]$ 的频次 $\ge 2$，故 $i_0$ 之前不存在唯一字符，答案正确。
- 集合为空时，对每个 $i$ 都有 $cnt[s[i]] \ge 2$，第二遍的判定条件处处不成立，循环正常结束并返回 $-1$；由引理 1，此时全串确实没有唯一字符，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。第一遍对每个字符做一次自增（$n$ 次）；第二遍最坏检查 $n$ 个下标、每次一次数组查询，命中即返回，故实际不超过 $2n$ 次常数操作。计数数组长度 26 是常数，不随 $n$ 增长。
- **空间**：$O(1)$，严格说是 $O(26)$。只有 26 个整型计数器，与输入长度无关；不计入输入字符串本身占用的空间。
- 与「每遇到一个字符就往后找是否重复」的 $O(n^2)$ 相比，这里把重复的信息一次性前置统计，用一次线性代价换取第二遍每次判定 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    int firstUniqChar(string s) {
        int cnt[26] = {0};
        for (char ch : s) cnt[ch - 'a']++;          // 第一遍：统计全局频次
        for (int i = 0; i < (int)s.size(); ++i)     // 第二遍：按下标找第一个唯一字符
            if (cnt[s[i] - 'a'] == 1) return i;
        return -1;                                  // 没有唯一字符
    }
};
```

### Python

```python
class Solution:
    def firstUniqChar(self, s: str) -> int:
        cnt = [0] * 26
        for ch in s:                       # 第一遍：统计全局频次
            cnt[ord(ch) - 97] += 1
        for i, ch in enumerate(s):         # 第二遍：按下标找第一个唯一字符
            if cnt[ord(ch) - 97] == 1:
                return i
        return -1                          # 没有唯一字符
```

## 8. 边界情况与易错点

1. **长度为 1**：`s = "a"` → 频次为 1，第二遍第一步命中，返回 0。不需要特判，但要保证空串不会被传入（题面保证 $|s| \ge 1$）；若扩展到空串，应返回 $-1$。
2. **全部字符都重复**：`"aabb"` → $-1$。最常见的错误是「没找到就返回 0」或返回 `n`，必须显式 `return -1`。
3. **唯一字符在末尾**：`"aabbc"` → 4。提前返回只发生在命中处，不能写成「返回最后检查的下标」，也不能把 `return -1` 写进循环体。
4. **字符集假设**：题面限定小写字母。若输入混入大写、数字或其他符号，`ch - 'a'` 可能是负数、也可能超过 25，C++ 中对 `cnt` 的越界写入是未定义行为，可能直接破坏栈上其他变量；扩展字符集时数组要开到 128 / 256，并改用 `(unsigned char)ch` 作下标。
5. **在第一遍里就返回**：这是本题最高频的 WA 来源。统计尚未结束时的 $cnt[c] = 1$ 只是「目前唯一」，后面的重复会让它失效。
6. **返回值是下标而非字符**：题目要的是 `int` 下标；`return s[i]` 会在 C++ 中隐式转成 ASCII 码，看似“差不多”，实则错误。
7. **Python 的字符码**：`ord(ch) - 97` 与 `ord(ch) - ord('a')` 等价，但不要用 `s.find(ch, i + 1)` / `s.index(ch)` 逐个判断「后面还有没有」，那才是 $O(n^2)$；`find` 只在「已确认该字符唯一、取它的唯一下标」时才是安全的 $O(n)$ 用法。

**延伸思考**：

- **恰好出现 $k$ 次**：把「$cnt = 1$」换成「$cnt = k$」即可，两遍结构完全不变。
- **真正的单遍扫描（队列版）**：标签里的「队列」来自这个变体——维护候选下标的队列，某字符计数涨到 2 时把它标记为「已重复」，然后不断弹出队首的已重复下标，最后队首即答案：

  ```python
  from collections import deque

  class Solution:
      def firstUniqChar(self, s: str) -> int:
          cnt, q = [0] * 26, deque()
          for i, ch in enumerate(s):
              c = ord(ch) - 97
              cnt[c] += 1
              if cnt[c] == 1:
                  q.append(i)
              while q and cnt[ord(s[q[0]]) - 97] > 1:
                  q.popleft()
          return q[0] if q else -1
  ```

  每个下标最多入队、出队各一次，仍是 $O(n)$，只是把「第二遍」摊还到了第一遍里。
- **字符集扩大**：若字符集是全体 Unicode，26 长度的数组要换成哈希表，时间 $O(n)$、空间 $O(\sigma)$（$\sigma$ 为不同字符数），两遍扫描的正确性论证保持不变。
