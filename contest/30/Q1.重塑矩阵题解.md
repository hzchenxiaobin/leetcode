# LeetCode 重塑矩阵 题解

## 1. 题目概述

- **标题 / 题号**：重塑矩阵（#566，easy）
- **链接**：https://leetcode.cn/problems/reshape-the-matrix/
- **来源**：LeetCode 第 30 场周赛 Q1
- **难度**：简单
- **标签**：数组、矩阵、模拟

**题意**：给定一个 $m \times n$ 的二维数组 `mat`，以及目标行数 $r$、列数 $c$。若能把 `mat` 的**全部元素**按原来的**行优先顺序**（先第一行从左到右、再第二行……）重新填进一个 $r \times c$ 的矩阵，输出这个新矩阵；若形状凑不齐（元素个数对不上），则**原样返回** `mat`。

**约束**：

- $m$ = `mat.length`，$n$ = `mat[i].length`
- $1 \le m, n \le 100$
- $-1000 \le \text{mat}[i][j] \le 1000$
- $1 \le r, c \le 300$

> 💡 签到题的题眼：**reshape 从不改变元素的先后次序，只改变「每行放几个」**。因此本题不是模拟题，而是一道「找对下标映射」的映射题；唯一的判断是 $m \cdot n = r \cdot c$ 是否成立。

## 2. 示例

**示例 1**

```text
输入：mat = [[1,2],[3,4]], r = 1, c = 4
输出：[[1,2,3,4]]
解释：mat 的行优先序列是 [1,2,3,4]；r × c = 1 × 4 只需一行，依次填入即可。
```

**示例 2**

```text
输入：mat = [[1,2],[3,4]], r = 2, c = 4
输出：[[1,2],[3,4]]
解释：m·n = 4，而 r·c = 8，元素个数不守恒，reshape 无解，按规定返回原矩阵。
```

**补充示例（非官方，覆盖 3 × 2 与单列退化）**

```text
输入：mat = [[1,2,3],[4,5,6]], r = 3, c = 2
输出：[[1,2],[3,4],[5,6]]
解释：6 个元素按行优先序 a₀…a₅ = 1,2,3,4,5,6，每 2 个一行切开：
      第 1 行由源第 0 行末元素 3 与源第 1 行首元素 4 拼成。

输入：mat = [[1,2,3,4]], r = 4, c = 1
输出：[[1],[2],[3],[4]]
解释：c = 1 时 k % c 恒为 0，所有元素落在第 0 列，等价于「竖起来」。
```

## 3. 解题思路

### 3.1 暴力思路

最朴素的两条路线都能过题，但都做了多余的工作：

1. **先展平再切块**：`flat = [x for row in mat for x in row]`，再每 $c$ 个切片拼成新矩阵。时间 $O(mn)$，但额外占用 $O(mn)$ 的展平数组，等于**把每个元素搬运了两次**。
2. **队列模拟**：把元素按行序压入队列，再逐格 `pop` 填进 $r \times c$ 的新矩阵（这正是官方提示的方向）。时间 $O(mn)$、额外空间 $O(mn)$，常数还更大。

还有一条看似更快的「整行搬运」写法：若 $c \mid n$，直接把源矩阵的每行切成 $\frac{n}{c}$ 段依次摆放。它在 $c$ 与 $n$ 有整除关系时成立，但**一旦目标的一行横跨源的两行就会错位**（见下方概念图：$c = 2$ 时目标第 1 行由 3、4 组成，而 3 在源第 0 行、4 在源第 1 行）。所以必须回到**元素级**的下标映射，而不能按行整块拷贝。

$m n \le 10^4$，复杂度并不是本题的瓶颈。真正的考点只有两个：**可行性判定**、**下标换算的方向别写反**。

### 3.2 核心观察：行优先序是唯一的不变量

![核心观察：同一串行优先序列，两种形状只是重新切分](images/wc30_q1_row_major_mapping.svg)

把矩阵按行优先展开成一维序列 $a_0, a_1, \dots, a_{mn-1}$，其中

$$a_k = \text{mat}\left[\left\lfloor \frac{k}{n} \right\rfloor\right]\left[k \bmod n\right]$$

矩阵只是这 $mn$ 个元素的一种「容器形状」。reshape 要求「所有元素以相同的行遍历顺序填充」，意思是：**目标矩阵按行优先展开后，恰好也是同一条序列**。于是同一个下标 $k$ 在两个形状里各有坐标：

$$\underbrace{\left(\left\lfloor \frac{k}{n} \right\rfloor,\ k \bmod n\right)}_{\text{源坐标}} \quad \Longleftrightarrow \quad \underbrace{\left(\left\lfloor \frac{k}{c} \right\rfloor,\ k \bmod c\right)}_{\text{目标坐标}}$$

两边共用同一个 $k$，整个 reshape 退化为「$k$ 走一遍，两边各自除模」。形状只是除数的差别：**源用列数 $n$ 当除数，目标用列数 $c$ 当除数**。

顺带得到可行性判据：$r \times c$ 的容器能装下且只装下 $m n$ 个元素，当且仅当 $m \cdot n = r \cdot c$。这也解释了为什么不可行时要返回原矩阵——题目规定「不能重塑就给回原样」，而不是报错或补零。

### 3.3 算法流程

![算法流程：先判可行性，再用一次 k 循环落位](images/wc30_q1_algorithm_flow.svg)

```text
1. if m·n ≠ r·c:  return mat              # 不可行，原样返回（O(1) 判定）
2. ans ← r 行 c 列的全 0 矩阵
3. for k = 0, 1, …, m·n − 1:
4.     (i, j) ← (k / n, k % n)           # 源坐标
5.     (x, y) ← (k / c, k % c)           # 目标坐标
6.     ans[x][y] ← mat[i][j]
7. return ans
```

第 3 行只有**一层循环**：$k$ 单调递增的次序就是行优先序，读取与写入天然同步，不需要额外的展平数组来暂存。

等价写法是维护一对游标 $(n_r, n_c)$：每写一格 `n_c++`，当 `n_c == c` 时 `n_c = 0, n_r++`。两种写法复杂度相同，除模版更短、更不易错，游标版少两次整数除法。第 3.4 节的走查会显示：$k = 2, 3$ 这两个**连续**元素分别落到 `ans[1][0]` 与 `ans[1][1]`，即目标的一行可以由源的两行拼接而成——这正是「不能整行搬运」的直接证据。

### 3.4 示例演算

![示例演算：2 × 3 → 3 × 2 的逐元素走查表](images/wc30_q1_walkthrough.svg)

对 `mat = [[1,2,3],[4,5,6]]`（$m = 2, n = 3$）、$r = 3, c = 2$，逐个 $k$ 走查：

| $k$ | 源坐标 $(k/3,\ k\%3)$ | 元素 | 目标坐标 $(k/2,\ k\%2)$ | 写入 |
|-----|------------------------|------|--------------------------|------|
| 0 | $(0, 0)$ | 1 | $(0, 0)$ | `ans[0][0] = 1` |
| 1 | $(0, 1)$ | 2 | $(0, 1)$ | `ans[0][1] = 2` |
| 2 | $(0, 2)$ | 3 | $(1, 0)$ | `ans[1][0] = 3` |
| 3 | $(1, 0)$ | 4 | $(1, 1)$ | `ans[1][1] = 4` |
| 4 | $(1, 1)$ | 5 | $(2, 0)$ | `ans[2][0] = 5` |
| 5 | $(1, 2)$ | 6 | $(2, 1)$ | `ans[2][1] = 6` |

6 个元素各写一次、无重复无遗漏，得到 `[[1,2],[3,4],[5,6]]`，与补充示例一致。

再看不可行分支：`mat = [[1,2],[3,4]]`、$r = 2$、$c = 4$ 时 $m n = 4 \ne 8 = r c$，第 1 行判定不通过，直接返回原矩阵 `[[1,2],[3,4]]`——**不是空矩阵，也不是补零到 $2 \times 4$**。

## 4. 算法细节

1. **判据放在最前面**：$m \cdot n \ne r \cdot c$ 时立即返回，此时连 `ans` 都不必分配；漏掉这条会在 `ans[x][y]` 处越界（$r c > m n$）或漏写元素（$r c < m n$）。
2. **乘积不会溢出**：$m n \le 100 \times 100 = 10^4$、$r c \le 300 \times 300 = 9 \times 10^4$，`int` 绰绰有余，不需要 `long long`；代码里两处都写 `m * n`（也可提成 `total` 变量复用），但**两处必须是同一个量**，否则会漏元素或越界。
3. **除模方向不能反**：行下标是 $k / c$、列下标是 $k \bmod c$（「除以列数得行号」）。写成 `ans[k % c][k / c]` 在 C++ 里会数组越界（未定义行为），Python 里可能静默返回错位的结果。
4. **输出预分配，不要 `push_back` 拼**：C++ 用 `vector<vector<int>> ans(r, vector<int>(c));`；Python 用 `[[0] * c for _ in range(r)]`。写成 `[[0] * c] * r` 会让 $r$ 行共享同一个列表对象，改一行等于改全部，是 Python 最经典的矩阵初始化坑。
5. **单层 $k$ 循环优于双层**：`for k in range(m*n)` 直接把「行优先序」显式写出来，$k/n$、$k\%n$ 与 $k/c$、$k\%c$ 四者的对应关系一目了然；双层 `for i, for j` 再算 `k = i*n + j` 等价，但多了一次手工换算，反而更容易写反。
6. **同址覆盖也安全**：若真把结果写回 `mat` 自己的内存（只有 $r = m$ 且 $c = n$ 时才谈得上），$k$ 递增时「读第 $k$ 个、写第 $k$ 个」落在同一位置，读写严格对齐，不会覆盖尚未读取的数据。实际提交时返回类型是值，直接新建 `ans` 更直观。
7. **接口按 `metaData` 写**：C++ 为 `vector<vector<int>> matrixReshape(vector<vector<int>>& mat, int r, int c)`（注意 `mat` 是引用，别复制），Python 为 `matrixReshape(self, mat: List[List[int]], r: int, c: int) -> List[List[int]]`。

## 5. 正确性证明

**引理 1（行优先编码是双射）**：映射 $\varphi(i, j) = i \cdot n + j$ 是集合 $\{0,\dots,m-1\} \times \{0,\dots,n-1\}$ 到 $\{0,\dots,mn-1\}$ 的双射，其逆映射为 $\varphi^{-1}(k) = (\lfloor k/n \rfloor,\ k \bmod n)$。

**证明**：先证像落在值域内：$0 \le i n + j \le (m-1)n + (n-1) = mn - 1$。再证单射：若 $i n + j = i' n + j'$ 且 $0 \le j, j' < n$，则 $n \mid (j - j')$，而 $\lvert j - j' \rvert < n$，故 $j = j'$，进而 $i = i'$。定义域与值域的元素个数同为 $mn$，单射即为双射。最后验证逆映射：把 $k = i n + j$ 代入，$k \bmod n = j$、$\lfloor k / n \rfloor = i + \lfloor j/n \rfloor = i$，故 $\varphi^{-1}(\varphi(i,j)) = (i,j)$。∎

**引理 2（可行性判据）**：存在一个 $r \times c$ 的矩阵容纳且仅容纳 `mat` 的全部元素，当且仅当 $m \cdot n = r \cdot c$。

**证明**：两个矩阵的元素个数分别是 $m n$ 与 $r c$。(⇒) 若 reshape 存在，则两边元素个数相同，得 $m n = r c$。(⇐) 若 $m n = r c$，记 $\varphi_n$、$\varphi_c$ 为引理 1 中以 $n$、$c$ 作列数的编码，对每个 $k \in [0, mn)$ 把 $\text{mat}[\varphi_n^{-1}(k)]$ 放到 $\text{ans}[\varphi_c^{-1}(k)]$：由引理 1，$k$ 取遍 $[0, mn)$ 时右侧遍历 `ans` 的 $r c = m n$ 个位置、左侧遍历 `mat` 的全部 $m n$ 个元素，均不重不漏，故这样的矩阵存在（且唯一）。∎

**引理 3（第 $k$ 个元素落位正确）**：对任意 $0 \le k < mn$，算法的第 $k$ 轮把源矩阵行优先序中的第 $k$ 个元素写入目标矩阵行优先序中的第 $k$ 个位置，且该位置此前未被写过。

**证明**：第 $k$ 轮读取 `mat[k/n][k%n]`，由引理 1 这正是源序列的第 $k$ 个元素；写入 `ans[k/c][k%c]`，同理是目标序列的第 $k$ 个位置。位置互不重复由引理 1 的单射性给出（不同 $k$ 对应不同坐标对）。∎

**定理**：算法返回的矩阵满足题意：$m n = r c$ 时是元素按行优先序重排后的 $r \times c$ 矩阵，否则是原矩阵 `mat`。

**证明**：分两种情形。若 $m n \ne r c$，第 1 行判定为假，算法原样返回 `mat`，恰是题目对「不可行」的规定输出。若 $m n = r c$，由引理 2 该 reshape 存在且唯一；由引理 3，$k$ 取遍 $[0, mn)$ 时目标矩阵的每个格子恰好被写入一次、且写入的正是行优先序中对应位置的元素，故输出的矩阵与题目要求的唯一结果逐元素相同。∎

## 6. 复杂度分析

- **时间**：$O(m n)$。可行性判定是一次乘法，$O(1)$；主体循环执行 $m n$ 轮，每轮两次整数除法 + 两次取模 + 一次内存写入，平均每个元素常数次操作。不可行时只需 $O(1)$ 判断（返回值若按值返回还要 $O(m n)$ 拷贝，见下）。
- **空间**：除输出外 $O(1)$。算法只用了 `k`、坐标等常数个变量，没有展平数组、没有队列；对照 3.1 的两条暴力路线各自需要 $O(m n)$ 额外空间。
- **输出开销**：必须构造 $r \times c$ 的结果，$O(r c)$ 无法避免。注意 C++ 中 `return mat;`（返回类型是值）会触发一次 $O(m n)$ 的深拷贝，与新建矩阵同阶，因此不可行分支并没有额外变慢。

## 7. 参考代码

### C++

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    vector<vector<int>> matrixReshape(vector<vector<int>>& mat, int r, int c) {
        int m = mat.size(), n = mat[0].size();
        if (m * n != r * c) return mat;              // 元素个数不守恒：原样返回

        vector<vector<int>> ans(r, vector<int>(c));  // 预分配 r 行 c 列
        for (int k = 0; k < m * n; ++k) {            // k 递增即行优先序
            ans[k / c][k % c] = mat[k / n][k % n];   // 目标下标 / 源下标
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def matrixReshape(self, mat: List[List[int]], r: int, c: int) -> List[List[int]]:
        m, n = len(mat), len(mat[0])
        if m * n != r * c:                  # 凑不齐就原样返回，不补零不报错
            return mat

        ans = [[0] * c for _ in range(r)]   # 注意：不能写成 [[0] * c] * r
        for k in range(m * n):              # k 从 0 递增就是行优先序
            ans[k // c][k % c] = mat[k // n][k % n]
        return ans
```

## 8. 边界情况与易错点

1. **不可行时必须原样返回**：`mat = [[1,2],[3,4]]`、$r = 2$、$c = 4$ 返回 `[[1,2],[3,4]]`。返回空列表、补零到 $2 \times 4$、或只取前 4 个元素都是错的——题目对无解有明确规定。
2. **单行 / 单列的退化**：$c = 1$ 时 $k \bmod 1 \equiv 0$，所有元素落在第 0 列，结果是竖排；$r = 1$ 时 $k / c \equiv 0$，所有元素在同一行。这两种情况不需要特判，除模公式自动成立，但写 `if` 分支时容易把 $c = 1$ 当成除零而误加保护（$c \ge 1$，不会除零）。
3. **形状完全相同**：$r = m$ 且 $c = n$（示例 2 之外的常见情形）时答案与输入逐元素相同，判定通过、循环照走一遍，结果仍正确；不要为了「优化」先判等再返回，那样两条分支的语义差异会让代码更难读（返回哪一个都是对的，但别混淆）。
4. **Python 二维初始化别名**：`[[0] * c] * r` 生成的是 $r$ 个指向**同一行列表**的引用，于是 `ans[0][0] = x` 会让每一行的第 0 个元素同时变成 $x$（等价于「改一列」）。必须用列表推导 `[[0] * c for _ in range(r)]`。
5. **除模方向写反**：`ans[k % c][k / c]` 是最常见的错误。`ans` 的维度是 $r$ 行 $c$ 列，写反后行下标取值变成 $[0, c)$、列下标变成 $[0, r)$：只要 $c > r$，行下标就会越过 $r$；只要 $r > c$，列下标就会越过 $c$。C++ 里是数组越界（未定义行为，本地可能「碰巧过」、提交后 RE），Python 里抛 `IndexError`。
6. **把元素个数当成 `r * c` 去遍历源**：若写 `for k in range(r*c)` 再访问 `mat[k/n][k%n]`，在 $r c > m n$ 时会越界。循环上界必须是 $m n$（此时 $r c = m n$，两者等价；但不可行分支已经提前 return，别把判定删掉）。
7. **负数元素与重复值无影响**：本题不做比较、不做哈希，$-1000$ 与 $0$ 走的是同一条路径，不必特殊处理；也**不要**用 `set` 去「判断能不能重塑」——元素可以重复，集合会丢掉个数，判据只能是元素总数。

**延伸思考**：在真实的张量库（NumPy、PyTorch）里，reshape 往往是 **zero-copy 的视图**：只改 `shape` 与 `stride`，一块连续内存被重新解释，复杂度 $O(\text{维度})$ 而非 $O(mn)$。所谓 `stride` 就是本题的推广——第 $d$ 维走一步要跨多少个元素，行优先下 $s_{d} = \prod_{d' > d} n_{d'}$。只有当内存**不连续**（例如先转置再 reshape）时才必须真正拷贝一次，这也是 `contiguous()` / `ascontiguousarray()` 的价值所在。换个角度：若题目要求「列优先（Fortran order）」，只需把两个除数同时换成行数；若要求「凑不齐就补零」，则先扩容再 reshape，$k$ 的上界改为 $r c$；若数据量大到放不进内存，reshape 就是一次带下标换算的分块 I/O，行优先序恰好保证顺序读，这也是它成为默认存储顺序的原因。
