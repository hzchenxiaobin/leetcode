# LeetCode 最大休假天数 题解

## 1. 题目概述

- **标题 / 题号**：最大休假天数（#568，hard）
- **链接**：https://leetcode.cn/problems/maximum-vacation-days/
- **来源**：LeetCode 第 30 场周赛 Q4
- **难度**：困难
- **标签**：数组、动态规划、矩阵

**题意**：有 $N$ 座城市（编号 $0 \sim N-1$），你要在其中度过 $K$ 周。`flights[i][j] = 1` 表示可以**从城市 i 直飞城市 j**（有向图，`flights[i][i] = 0`）。第 0 周周一早晨你固定在城市 0；此后每个周一早晨，你要么留在当前城市，要么飞往一个有直飞航班的城市，**每周至多飞一次**。飞到目的地的那一天算作**目的地城市**的休假。`days[i][j]` 表示第 $j$ 周待在城市 $i$ 时最多能休的天数。求 $K$ 周累计最多能休多少天。

**约束**：

- $1 \le N, K \le 100$
- `flights[i][j]` 只取 0 或 1，且 `flights[i][i] = 0`
- `days[i][j]` 的取值范围是 $[0, 7]$
- 在城市待超过 `days[i][j]` 天也没关系，多出的日子上班，不计入休假

> 💡 结算口径很简单：**第 $w$ 周待在哪座城市，就拿 `days[c][w]` 天**；飞行不额外扣假。

## 2. 示例

**示例 1**

```text
输入：flights = [[0,1,1],[1,0,1],[1,1,0]], days = [[1,3,1],[6,0,3],[3,3,3]]
输出：12
解释：最优策略是
      第 1 周：从城市 0 飞往城市 1，休 6 天；
      第 2 周：从城市 1 飞往城市 2，休 3 天；
      第 3 周：留在城市 2，休 3 天；合计 6 + 3 + 3 = 12。
```

输出：3
解释：没有任何航班，只能一直待在城市 0，每周休 1 天，共 3 天。
```

**示例 3**

输入：flights = [[0,1,1],[1,0,1],[1,1,0]], days = [[7,0,0],[0,7,0],[0,0,7]]
输出：21
解释：第 1 周留在城市 0，第 2 周飞往城市 1，第 3 周飞往城市 2，每周都休满 7 天。
```

## 3. 解题思路

### 3.1 暴力思路

枚举「每周落在哪座城市」的完整序列：第 0 周至多 $N$ 种落脚点，之后每周至多 $N$ 种走法，总日程数 $O(N^K)$（示例 1 只有 $3^3 = 27$ 条）。但 $N = K = 100$ 时是 $100^{100}$，完全无法枚举。

关键是暴力里存在**大量重叠子问题**：两条不同的前缀日程只要在第 $w$ 周到达了同一座城市，后续可选的城市与能拿到的休假就完全一样。于是「历史」可以压缩成一个状态。

### 3.2 核心观察：以「周」为阶段的分层 DAG

![按周分层建图](images/wc30_q4_dp_layers.svg)

把第 $w$ 周待在城市 $c$ 记成一个节点 $(w, c)$，则：

- **阶段**：时间 $w = 0,1,\dots,K-1$，天然有序；
- **边**：$(w, p) \to (w+1, c)$，当且仅当 $c = p$（原地不动）或 `flights[p][c] = 1`（周一早晨飞过去）；
- **点权**：节点 $(w, c)$ 贡献 `days[c][w]` 天休假。

于是问题变成：在这张**分层 DAG** 上，求从第 0 层任意起点到第 $K-1$ 层任意终点的**最大权路径**，答案为所有终点中的最大值。

因为边只从第 $w$ 层指向第 $w+1$ 层，不存在环、也没有后效性，按层做 DP 即可。

### 3.3 状态转移

![逐周递推流程](images/wc30_q4_dp_flow.svg)

定义 $dp[w][c]$ 为「第 $w$ 周结束时待在城市 $c$」的合法前缀日程中最大的累计休假天数，不可达记 $-\infty$（实现用 $-1$）。

**第 0 周**（起点固定为城市 0）：

$$dp[0][c] = \begin{cases} days[c][0], & c = 0 \ \text{或}\ flights[0][c] = 1 \\ -\infty, & \text{否则} \end{cases}$$

**逐周推进**：

$$dp[w+1][c] = \max_{\substack{p \in [0, N) \\ p = c \ \text{或}\ flights[p][c] = 1}} \Bigl( dp[w][p] + days[c][w+1] \Bigr)$$

**收尾**：

$$\text{answer} = \max_{c} dp[K-1][c]$$

由于 $dp$ 只依赖上一周，用两行滚动即可，空间从 $O(NK)$ 降到 $O(N)$。

### 3.4 示例演算

![示例 1 的 dp 表递推](images/wc30_q4_walkthrough.svg)

以示例 1（$N = K = 3$，三元组按城市 0/1/2 书写）走一遍：

| 阶段 | 转移说明 | $dp$ 行向量 |
|------|----------|-------------|
| 第 0 周 | 城市 0 起步，可飞 1、2 | $(1,\ 6,\ 3)$ |
| 第 1 周 | 由 $\max(dp[0][p] + days[c][1])$ 得到 | $(9,\ 6,\ 9)$ |
| 第 2 周 | 由 $\max(dp[1][p] + days[c][2])$ 得到 | $(10,\ 12,\ 12)$ |

例如 $dp[1][2] = 9$ 来自 $p = 1$：$dp[0][1] + days[2][1] = 6 + 3 = 9$（第 1 周在城市 1，第 2 周飞往城市 2）。最终 $\max\{10, 12, 12\} = 12$，与官方答案一致。

## 4. 算法细节

1. **预建可达矩阵**：先算 `reach[p][c] = (p == c) || flights[p][c] == 1`，把「原地不动」并入转移条件。内层循环里少一个分支，也避免把 `p == c` 漏写成只允许飞行。
2. **哨兵值取 $-1$**：因为 `days[i][j] >= 0`，任何可达状态的 $dp$ 都 $\ge 0$，所以 $-1$ 严格小于一切真实值；**不能**用 $0$ 当「不可达」，否则会把不可达状态当成得分 0 的状态继续转移。
3. **第 0 周单独初始化**：起点是**城市 0**，只能原地留或 `flights[0][c] == 1` 时飞过去；注意方向是 `flights[0][c]` 而不是 `flights[c][0]`。
4. **滚动数组**：`dp` 只被上一周用到，用 `ndp` 承接本周再 `swap`（Python 直接重新绑定）；初始化 `ndp` 为全 $-1$，最后 `max(dp)` 即答案。
5. **方向性易错**：`flights[p][c]` 表示 $p \to c$ 的单向航班。转移必须按「上一周 $p$、本周 $c$」枚举；本题多数样例的 `flights` 恰是对称矩阵，写反了也能过样例，但会在非对称数据上 WA。
6. **飞行日不扣假**：飞到城市 $c$ 的那一周直接拿 `days[c][w]`，不要写成 `days[c][w] - 1` 或按 6 天计。
7. **遍历顺序自由**：层与层之间是 DAG，内层先枚举 $p$ 还是先枚举 $c$ 都不影响结果；C++ 里建议把 `reach` 转成邻接表以跳过无效的 $p$，常数更小。
8. **规模足够小**：$N, K \le 100$ 时 $K \cdot N^2 = 10^6$，无需任何优化，两重循环即可。

## 5. 正确性证明

**引理 1（日程与路径一一对应）**：一份合法的休假日程等价于一条从第 $0$ 层到第 $K-1$ 层的路径 $c_0, c_1, \dots, c_{K-1}$，满足 $c_0 = 0$ 或 `flights[0][c_0] = 1`，且对每个 $0 \le w < K-1$ 有 $c_{w+1} = c_w$ 或 `flights[c_w][c_{w+1}] = 1`；该日程的休假总天数是 $\sum_{w=0}^{K-1} days[c_w][w]$。

**证明**：由题目规则，第 0 周周一早晨你在城市 0，只能留在原地或飞往 `flights[0][c] = 1` 的城市，故 $c_0$ 的取值集合正确；之后每个周一早晨都在上一周的城市 $c_w$，同样只能原地或沿一条直飞航班移动，得到 $c_{w+1}$ 的约束。又因为「第 $w$ 周待在城市 $x$ 就休 `days[x][w]` 天，飞行当天计入目的地城市」，每周的收益只由当周所在城市决定，累加即得总天数。反向地，任一条满足约束的城市序列都能按规则执行（每周至多飞一次、只沿存在的航班飞），因此是合法日程。∎

**引理 2（DP 值刻画）**：按 §3.3 递推得到的 $dp[w][c]$，等于「第 $w$ 周位于城市 $c$ 的所有合法前缀日程」的最大累计休假天数；不可达时为 $-\infty$。

**证明**：对 $w$ 归纳。基 $w = 0$：前缀只有一周，合法当且仅当 $c = 0$ 或 `flights[0][c] = 1`（引理 1），此时得分恰为 `days[c][0]`，与初始化一致。

归纳步：设结论对所有 $w$ 成立，考察 $dp[w+1][c]$ 的定义集合。任一第 $w+1$ 周位于 $c$ 的合法前缀，限制在前 $w$ 周是一份以某城市 $p$ 结尾的合法日程，且由引理 1 有 $p = c$ 或 `flights[p][c] = 1`；由归纳假设其前 $w$ 周得分不超过 $dp[w][p]$，故该前缀总分不超过 $dp[w][p] + days[c][w+1]$，从而不超过递推式右端的最大值。反之，对每个满足 $p = c$ 或 `flights[p][c] = 1` 的 $p$，取一份达到 $dp[w][p]$ 的合法前缀（若 $dp[w][p] \neq -\infty$），在其后接上「第 $w+1$ 周待在城市 $c$」，由引理 1 仍是合法日程，得分恰为 $dp[w][p] + days[c][w+1]$。因此递推式右端的每个候选值都可达，取最大值后等于定义值。∎

**定理（算法正确性）**：算法输出的 $\max_c dp[K-1][c]$ 等于 $K$ 周内能获得的最大休假天数。

**证明**：设 $\sigma$ 是任一合法完整日程，其最后一周所在城市为 $c_\ast$。由引理 2，$\sigma$ 的总得分不超过 $dp[K-1][c_\ast] \le \max_c dp[K-1][c]$，所以算法输出是上界。另一方面，取达到最大值的城市 $c^\ast$，由引理 2 的归纳构造（每步都取到 $dp$ 值的那个前驱）可以回溯出一条以 $c^\ast$ 结尾的合法日程，其得分正好是 $dp[K-1][c^\ast]$，所以该上界可达。两者相等，答案正确。∎

## 6. 复杂度分析

- **时间**：$O(K \cdot N^2)$。共 $K-1$ 轮递推，每轮枚举 $N$ 个上一周城市与 $N$ 个本周城市，转移 $O(1)$；$N = K = 100$ 时约 $10^6$ 次基本运算。
- **空间**：$O(N)$。只需两行 $dp$ / $ndp$（若额外存 `reach` 矩阵则是 $O(N^2)$，可省略直接判断 `flights`）。
- **常数层面**：把 `reach` 建成邻接表后，每轮只遍历真实存在的转移（含 $N$ 条自环），稀疏航班图下更快。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maxVacationDays(vector<vector<int>>& flights, vector<vector<int>>& days) {
        int n = days.size(), k = days[0].size();
        vector<int> dp(n, -1);                 // -1 表示第 0 周不可达
        for (int c = 0; c < n; c++)
            if (c == 0 || flights[0][c] == 1) dp[c] = days[c][0];

        for (int w = 1; w < k; w++) {
            vector<int> ndp(n, -1);
            for (int p = 0; p < n; p++) {
                if (dp[p] < 0) continue;       // 上周都到不了，跳过
                for (int c = 0; c < n; c++)
                    if (c == p || flights[p][c] == 1)
                        ndp[c] = max(ndp[c], dp[p] + days[c][w]);
            }
            dp.swap(ndp);                      // 滚动
        }
        return *max_element(dp.begin(), dp.end());
    }
};
```

### Python

```python
from typing import List

class Solution:
    def maxVacationDays(self, flights: List[List[int]], days: List[List[int]]) -> int:
        n, k = len(days), len(days[0])
        reach = [[p == c or flights[p][c] == 1 for c in range(n)] for p in range(n)]

        dp = [-1] * n                          # -1 表示第 0 周不可达
        for c in range(n):
            if c == 0 or flights[0][c] == 1:
                dp[c] = days[c][0]

        for w in range(1, k):
            ndp = [-1] * n
            for p in range(n):
                if dp[p] < 0:
                    continue
                base = dp[p]
                for c in range(n):
                    if reach[p][c] and base + days[c][w] > ndp[c]:
                        ndp[c] = base + days[c][w]
            dp = ndp

        return max(dp)
```

## 8. 边界情况与易错点

1. **$N = 1$**：`flights = [[0]]`，没有航班可飞，只能原地不动，答案就是 `sum(days[0])`。此时 `max(dp)` 只作用于一个元素，代码天然正确。
2. **$K = 1$**：只有一周，递推循环 `for w in range(1, k)` 一次都不执行，直接返回 `max(dp)`，也就是 `days[0][0]`（第 0 周只能待在城市 0）；不要误写成「任意城市起步取最大」。
3. **完全无航班**：`flights` 全 0 时只能待在城市 0（示例 2），答案是 $\sum_w days[0][w]$；若把「原地不动」漏掉（只允许 `flights[p][c] == 1`），$dp$ 会在第 1 周全变成 $-1$，最终返回 $-1$。
4. **`days` 全为 0**：所有可达状态得分为 0，此时必须用 $-1$（或 `INT_MIN`）作不可达哨兵；用 0 当哨兵会让不可达状态「复活」，在 `flights` 稀疏时算出偏大甚至错误的结果。
5. **方向写反**：把判断写成 `flights[c][p] == 1` 而不是 `flights[p][c] == 1`，在对称矩阵样例上能过、在非对称数据上必错；转换时默念「从上一周的 $p$ 飞向本周的 $c$」。
6. **起点不自由**：第 0 周的城市集合是 $\{0\} \cup \{c \mid flights[0][c] = 1\}$，不是全部城市；把第 0 周当成「任意城市可达」会在 `flights[0][c] = 0` 的数据上多算。
7. **飞行周不扣假**：飞过去的当周依旧拿满 `days[c][w]`，不要减 1；题目中「飞行时间可忽略」就是为这条规则服务的。
8. **返回值规模**：最大 $100 \times 7 = 700$，`int` 完全够用，不需要 `long long`。
