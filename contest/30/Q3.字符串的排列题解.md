# LeetCode 字符串的排列 题解

## 1. 题目概述

- **标题 / 题号**：字符串的排列（#567，medium）
- **链接**：https://leetcode.cn/problems/permutation-in-string/
- **来源**：LeetCode 第 30 场周赛 Q3
- **难度**：中等
- **标签**：哈希表、双指针、字符串、滑动窗口

**题意**：给定两个字符串 `s1` 与 `s2`，判断 `s2` 中是否存在一个**连续子串**，它是 `s1` 的某个**排列**（即字符多重集与 `s1` 完全一致）。是则返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \lvert s1 \rvert, \lvert s2 \rvert \le 10^4$
- `s1`、`s2` 仅由小写英文字母组成，字母表大小 $\sigma = 26$，可以用定长数组代替哈希表

## 2. 示例

**示例 1**

```text
输入：s1 = "ab", s2 = "eidbaooo"
输出：true
解释：s2 的下标 3~4 是 "ba"，它正是 s1 的一个排列。
```

**示例 2**

```text
输入：s1 = "ab", s2 = "eidboaoo"
输出：false
解释：窗口依次为 ei / id / db / bo / oa / ao / oo，没有一个的频次与 "ab" 相同。
```

**示例 3（补充边界）**

```text
输入：s1 = "abc", s2 = "ab"  →  输出：false（|s1| > |s2|，连一个合法窗口都没有）
```

## 3. 解题思路

### 3.1 暴力思路

三条朴素路线，逐条看为什么不行（或为什么能行）：

1. **枚举 `s1` 的全部排列**再在 `s2` 中查找：排列数是 $m!$，$m = 10^4$ 时是天文数字，且大量排列字符重复、纯属重复枚举，直接排除。
2. **枚举窗口 + 排序比较**：枚举 $n-m+1$ 个起点，把窗口排序后与排序后的 `s1` 比较，复杂度 $O\bigl(n \cdot m\log m\bigr)$，最坏 $10^4 \times 10^4 \times 14 \approx 1.4\times 10^{9}$，超时。
3. **枚举窗口 + 每次重算 26 格计数**：$O(26n) \approx 2.6\times10^{5}$，能过题，但每个窗口都要从头扫 26 个字母。

真正关键的是换个「比较对象」：不比较字符串本身，而比较**字符频次向量**。这样每个窗口的判定只需要一次 $O(1)$ 的差分更新。

### 3.2 核心观察：排列 ⇔ 长度相同且计数向量相同

![排列等价于长度相同的计数向量相同](images/wc30_q3_freq_vector.svg)

**观察**：设 $t$ 是 `s2` 中某个长度为 $m = \lvert s1\rvert$ 的子串。则

$$t \text{ 是 } s1 \text{ 的排列} \iff \forall c \in \Sigma:\ \mathrm{cnt}_t(c) = \mathrm{cnt}_{s1}(c)$$

理由是双向的：若 $t$ 是 `s1` 的排列，它只是 `s1` 字符的重新排列，多重集不变；反过来，两个**长度相同**且**每个字母出现次数都相同**的串必定互为重排——因为每个字母可用的个数完全一致，把 `s1` 的字符按位置重新分配即可得到 $t$。

于是问题从「在 `s2` 里搜 $m!$ 个模式」变成「在 `s2` 里搜 1 个长度为 26 的计数向量」：把定长窗口沿 `s2` 滑动，比较两个 26 维向量即可。这正是**定长滑动窗口**（窗口长度恒为 $m$，不伸缩）。

### 3.3 算法流程：定长窗口 + diff 计数器

![定长窗口滑动与 diff 增量更新](images/wc30_q3_slide_diff.svg)

维护三个量：

- `need[26]`：`s1` 的字符频次；
- `win[26]`：当前窗口 `s2[i-m .. i-1]` 的字符频次；
- $\mathrm{diff} = \left|\{\, c : \mathrm{need}[c] \ne \mathrm{win}[c] \,\}\right|$：两个频次表**不相等的字母个数**。

**判定**：`diff == 0` $\iff$ 两张频次表逐格相同 $\iff$ 当前窗口是 `s1` 的排列。

**滑窗更新**：窗口从 $[i-m,\,i)$ 右移到 $[i-m+1,\,i+1)$，只有两个字母的计数发生变化——移出 `s2[i-m]`、移入 `s2[i]`。对每个被改动的字母 $c$，只要考察它「改动前后与 `need[c]` 是否相等」：

若改动前相等、改动后不等，则 `diff += 1`；若改动前不等、改动后相等，则 `diff -= 1`；其余情况 `diff` 不变。

一次滑动只涉及 2 个字母、至多 4 次相等性判断与 2 次 $\pm 1$ 修正，故为 $O(1)$。实现上写成统一模板：**先判断当前是否相等（相等则 diff+1），改计数，再判断是否相等（相等则 diff-1）**，对「移出」「移入」各套一次。

### 3.4 示例演算

对 `s1 = "ab"`、`s2 = "eidbaooo"`（$m=2$，`need` 中 `a`、`b` 各为 1，其余为 0）：

![示例逐窗口演算表](images/wc30_q3_walkthrough.svg)

| 起点 $i$ | 窗口 | `cnt_a` | `cnt_b` | `diff` | 判定 |
|----------|------|---------|---------|--------|------|
| 0 | `"ei"` | 0 | 0 | 4 | false（a、b 缺，e、i 多） |
| 1 | `"id"` | 0 | 0 | 4 | false |
| 2 | `"db"` | 0 | 1 | 2 | false（a 缺、d 多） |
| 3 | `"ba"` | 1 | 1 | **0** | **true** |
| 4 | `"ao"` | 1 | 0 | 2 | —（$i=3$ 已返回） |

$i=3$ 时两张频次表一致，返回 `true`。可以验证 $i=3 \to 4$ 的增量：移出 `b`（$\mathrm{cnt}_b:1\to0$，与 `need` 由相等变不等，`diff+1`），移入 `o`（$\mathrm{cnt}_o:0\to1$，由相等变不等，`diff+1`），故 `diff = 2`，与上表一致。

## 4. 算法细节

1. **长度先验**：若 $m > n$ 立即返回 `false`，否则后续所有下标都安全。
2. **首窗口初始化**：先累加 `need`（$O(m)$），再扫 `s2[0..m)` 建 `win`（$O(m)$），最后花 $O(26)$ 统计 `diff` 初值。
3. **diff 更新模板**（对每个被改动的字母 $c$、增量 $d \in \{+1,-1\}$）：

   ```text
   if win[c] == need[c]:  diff += 1     # 原本相等，改动后必然不等
   win[c] += d
   if win[c] == need[c]:  diff -= 1     # 改动后变相等
   ```

   这个模板只依赖「改动前后是否相等」两个布尔量，不依赖 $d$ 的正负，因此移出、移入可以共用。
4. **移出与移入的字母可能相同**：当 `s2[i-m] == s2[i]` 时，窗口内容根本没变。此时按模板先减后加，两次状态变化恰好抵消，`diff` 保持不变——正确性无需额外特判，但**若为了省事只写一半（比如直接 `win[rem]--; win[add]++` 后不管 diff），就会出错**。
5. **用定长数组而非哈希表**：字母表只有 26 个字符，`int need[26]`、`int win[26]` 的寻址比 `unordered_map` 快一个数量级；Python 里用 `list` + `ord(ch) - 97`。
6. **提前返回**：首窗口 `diff == 0` 要单独判一次（循环里只处理后续窗口），此处是最容易漏的分支。
7. **只改两个计数**：不要在每个窗口里重新扫描 $m$ 个字符，否则退化为 $O(nm)$。

## 5. 正确性证明

**引理 1（频次判等）**：设 $t$ 与 `s1` 长度相同，则 $t$ 是 `s1` 的排列 $\iff$ 对每个字母 $c$ 有 $\mathrm{cnt}_t(c) = \mathrm{cnt}_{s1}(c)$。

**证明**：

- ($\Rightarrow$) 排列只是把 `s1` 的字符重新排列，每个字母的个数不变，故频次相等。
- ($\Leftarrow$) 设两串长度同为 $m$ 且频次逐一相等。对任意字母 $c$，在 `s1` 中出现 $\mathrm{cnt}_{s1}(c)$ 次，在 $t$ 中也出现同样多次。把 $t$ 的字符按字母顺序重排、`s1` 也按字母顺序重排，得到的两个「排序后串」逐位相同，故 $t$ 是 `s1` 的一个重排，即排列。∎

**引理 2（diff 语义不变式）**：循环的每一步结束时，`win` 恰为当前窗口 `s2[i-m .. i-1]` 的频次表，且 $\mathrm{diff} = \left|\{ c : \mathrm{need}[c] \ne \mathrm{win}[c] \}\right|$。

**证明**：初始时 `win` 由首窗口逐字符累加而来，`diff` 由逐格比较得出，成立。归纳步：设窗口右移一格，真实频次表的变化为「`s2[i-m]` 减 1、`s2[i]` 加 1」，与算法执行的两处更新一致，故 `win` 仍是真实频次表。对 `diff`：被改动的字母只有 $p = s2[i-m]$ 与 $q = s2[i]$。

- 若 $p \ne q$：对 $p$，更新只令 $\mathrm{win}[p]$ 减少 1，若原先 $\mathrm{win}[p] = \mathrm{need}[p]$ 则变为不等（贡献 $+1$），若原先不等则需分情况——由于只变一格且变化量 1，若原先不等、更新后恰好相等则贡献 $-1$，否则贡献 $0$；模板恰好实现了这两种情形（先判相等 $+1$，改后判相等 $-1$，若两者均不成立则不变）。同理对 $q$。
- 若 $p = q$：两次更新落在同一格，$\mathrm{win}[p]$ 先减 1 再加 1 复原。模板在减 1 前若相等则 $+1$、减 1 后若相等则 $-1$ 的净效果与加 1 阶段相消，`diff` 不变，与真实情况（频次表未变）一致。

故不变式在每步后保持。∎

**引理 3（窗口完备）**：算法考察了 `s2` 中**全部**长度为 $m$ 的子串，且每个恰被考察一次。

**证明**：合法起点为 $0 \le i \le n-m$，共 $n-m+1$ 个。首窗口对应 $i=0$；循环从 $i=m$ 到 $i=n-1$ 执行 $n-m$ 次，第 $k$ 次（$k = 1..n-m$）对应起点 $k$。故全部覆盖且不重复。∎

**定理**：`checkInclusion(s1, s2)` 返回 `true` 当且仅当 `s2` 包含 `s1` 的某个排列作为连续子串。

**证明**：

- ($\Leftarrow$) 设 `s2` 的窗口 `s2[j .. j+m-1]` 是 `s1` 的排列。由引理 3 该窗口会被考察；由引理 1 其频次与 `need` 相同，由引理 2 此时 `diff = 0`，算法返回 `true`。
- ($\Rightarrow$) 算法返回 `true` 只可能发生在某次 `diff == 0` 的判断处。由引理 2，此时 `win` 是当前窗口的真实频次且与 `need` 逐格相同；由引理 1，该窗口是 `s1` 的排列，即 `s2` 含有 `s1` 的排列作为子串。∎

## 6. 复杂度分析

- **时间**：$O(m + \sigma + n)$，其中 $m = \lvert s1 \rvert$、$n = \lvert s2 \rvert$、$\sigma = 26$。具体为：建 `need` 扫 $m$ 个字符；建首窗口扫 $m$ 个字符；统计初始 `diff` 扫 26 格；之后 $n - m$ 次滑动，每次只做常数次整数比较与自增。由于 $\sigma$ 是常数，整体即 $O(n)$。
- **空间**：$O(\sigma) = O(1)$。只用了两张 26 格的定长计数表与若干个下标变量，与输入规模无关。

## 7. 参考代码

### C++

```cpp
#include <string>

class Solution {
public:
    bool checkInclusion(std::string s1, std::string s2) {
        int m = (int)s1.size(), n = (int)s2.size();
        if (m > n) return false;

        int need[26] = {0}, win[26] = {0};
        for (char c : s1) need[c - 'a']++;
        for (int i = 0; i < m; i++) win[s2[i] - 'a']++;

        // diff = 与 need 不相等的字母个数
        int diff = 0;
        for (int c = 0; c < 26; c++)
            if (need[c] != win[c]) diff++;
        if (diff == 0) return true;              // 首窗口即答案

        for (int i = m; i < n; i++) {
            int add = s2[i] - 'a';               // 移入窗口的字符
            int rem = s2[i - m] - 'a';           // 移出窗口的字符

            if (win[rem] == need[rem]) diff++;   // 原本相等 -> 改动后不等
            win[rem]--;
            if (win[rem] == need[rem]) diff--;   // 改动后变相等

            if (win[add] == need[add]) diff++;
            win[add]++;
            if (win[add] == need[add]) diff--;

            if (diff == 0) return true;          // 频次表一致，命中
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        m, n = len(s1), len(s2)
        if m > n:
            return False

        need = [0] * 26
        win = [0] * 26
        for ch in s1:
            need[ord(ch) - 97] += 1
        for i in range(m):
            win[ord(s2[i]) - 97] += 1

        # diff = 与 need 不相等的字母个数
        diff = sum(1 for c in range(26) if need[c] != win[c])
        if diff == 0:
            return True                      # 首窗口即答案

        for i in range(m, n):
            add = ord(s2[i]) - 97            # 移入窗口的字符
            rem = ord(s2[i - m]) - 97        # 移出窗口的字符

            if win[rem] == need[rem]:        # 原本相等 -> 改动后不等
                diff += 1
            win[rem] -= 1
            if win[rem] == need[rem]:        # 改动后变相等
                diff -= 1

            if win[add] == need[add]:
                diff += 1
            win[add] += 1
            if win[add] == need[add]:
                diff -= 1

            if diff == 0:
                return True                  # 频次表一致，命中

        return False
```

## 8. 边界情况与易错点

1. **`s1` 比 `s2` 长**：如 `s1 = "abc"`、`s2 = "ab"`，必须最先判 `m > n` 返回 `false`，否则后面的取下标全部越界。
2. **长度相等**：`m == n` 时只有 0 号窗口，循环体一次都不执行，**必须在进入循环前单独判断首窗口的 `diff == 0`**，这是最常见的漏判。
3. **`s1` 有重复字母**：如 `s1 = "aab"`，`need` 中 `a` 为 2。频次比较天然支持重字母，但若写成「用集合去重 + 判断包含」，就会把 `s2 = "ab"` 误判为 `true`。
4. **移出与移入是同一个字母**：`s2[i-m] == s2[i]` 时窗口内容不变，`diff` 必须保持不变。按 §4 模板写（先判相等、改计数、再判相等）会自动抵消；若图省事把两个计数都改完、最后只比较一次相等性，在 `rem == add` 时会漏掉中间状态，把本应不变的 `diff` 改错。
5. **忘记 `diff` 初值要统计 26 格**：只统计 `need` 中出现的字母会漏掉「窗口里多出来的字母」（如 `s2` 首窗口为 `"ei"`、`s1 = "ab"`，`e`、`i` 的差异必须计入，否则 `diff` 错误地变成 2 而不是 4）。
6. **循环上界**：起点最大为 $n-m$，对应代码里 `i` 从 `m` 到 `n-1`（窗口右端点），若写成 `i <= n` 会越界访问 `s2[n]`。
7. **计数类型**：C++ 里 `int` 足够（单字符计数不超过 $10^4$），不要用 `char`/`uint8_t`，以免 255 处回绕。

**延伸思考**：

1. 若要求「`s2` 中存在一个子串，它是 `s1` 的**子序列**」（不要求连续），问题性质会彻底改变——变成在 `s2` 中按顺序匹配 `s1` 的字符，双指针 $O(n+m)$ 即可，与本篇的频次模型无关。
2. 若允许**至多 $k$ 处字符替换**后成为排列，可以把判定条件放宽为 $\sum_c \max\bigl(0, \mathrm{cnt}_{win}(c) - \mathrm{need}(c)\bigr) \le k$，仍是 $O(1)$ 增量维护（多维护一个「超额字符总数」即可），窗口保持定长。
3. 若字母表扩大到 Unicode，26 格数组要换成 `HashMap`，时间仍是 $O(n)$，但常数与空间随不同字符数增长，此时 `diff` 的维护逻辑完全不变。
