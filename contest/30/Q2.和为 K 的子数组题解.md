# LeetCode 和为 K 的子数组 题解

## 1. 题目概述

- **标题 / 题号**：和为 K 的子数组（#560，medium）
- **链接**：https://leetcode.cn/problems/subarray-sum-equals-k/
- **来源**：LeetCode 第 30 场周赛 Q2
- **难度**：中等
- **标签**：数组、哈希表、前缀和

**题意**：给定整数数组 `nums` 与整数 `k`，统计**和恰好等于 `k`** 的连续非空子数组有多少个。注意 `nums` 允许**负数与 0**，这正是本题与「滑动窗口类子数组题」的分水岭。

**约束**：

- $1 \le \text{nums.length} \le 2 \times 10^4$
- $-1000 \le \text{nums}[i] \le 1000$
- $-10^7 \le k \le 10^7$
- 数组中元素可为负 ⟹ 前缀和**不单调**，双指针 / 滑动窗口失效

## 2. 示例

**示例 1**

```text
输入：nums = [1,1,1], k = 2
输出：2
解释：和为 2 的子数组为 nums[0..1] = [1,1] 与 nums[1..2] = [1,1]。
```

**示例 2**

```text
输入：nums = [1,2,3], k = 3
输出：2
解释：两个子数组 [1,2]（下标 0..1）与 [3]（下标 2..2）的和都是 3。
```

**示例 3**（自构造：覆盖「含负数 / 含 0 / k = 0」这一最易翻车的情形）

```text
输入：nums = [1,-1,0], k = 0
输出：3
解释：合法子数组为 [1,-1]、[1,-1,0]、[0]。
      前缀和为 0、1、0、0，值 0 出现了 3 次（P0、P2、P3），
      两两配对 C(3,2) = 3 恰好就是答案——滑动窗口在负数上已无法判断伸缩方向。
```

## 3. 解题思路

### 3.1 暴力思路

枚举左端点 $i$，右端点 $j$ 从左往右累加并随时判等：$O(n^2)$。$n = 2\times10^4$ 时约有 $\frac{n(n+1)}{2} \approx 2\times10^8$ 次累加，C++ 勉强、Python 必超时。

那么能不能上双指针？不能。滑动窗口的正确性依赖「窗口内和关于右端点单调」，而 `nums` 含负数后，前缀和忽大忽小，右端点右移可能让和变小、左端点右移也可能让和变大，**没有单调性可以做取舍**。所以必须换一种「不依赖顺序」的计数思路。

### 3.2 核心观察：子数组和 = 两个前缀和之差

![核心观察：子数组和等于两个前缀和之差](images/wc30_q2_prefix_diff_concept.svg)

定义前缀和

$$P[0] = 0, \qquad P[j] = \sum_{t=0}^{j-1} \text{nums}[t] \quad (1 \le j \le n)$$

则任何连续子数组的和都能**一次减法**得到：

$$\text{sum}(\text{nums}[i..j-1]) = P[j] - P[i]$$

于是「找和为 $k$ 的子数组」被改写成「找一对下标 $0 \le i < j \le n$ 使 $P[j] - P[i] = k$」，即

$$P[i] = P[j] - k$$

这是一个**两数之差定值**的配对计数问题，与「两数之和」母题只差一个符号。关键转化在于：**扫描到 $j$ 时，所有 $i < j$ 的前缀和都已经见过**，只要用哈希表记录「每个前缀和值出现过几次」，就能 $O(1)$ 查出有多少个 $i$ 满足条件：

$$\text{cnt}[v] = \#\{\, i < j : P[i] = v \,\}, \qquad \text{ans} \mathrel{+}= \text{cnt}[P[j] - k]$$

这样把 $O(n^2)$ 的配对枚举压成了**一次扫描 + 每次一次哈希查询**。

> 💡 **一句话记忆**：子数组和问题一律先转前缀和；「和 = k」转「两前缀和之差 = k」；「计数」用哈希表存**频次**，「求最长」则存**最早下标**。

### 3.3 算法流程

![算法流程：一次遍历加哈希表查历史前缀和](images/wc30_q2_algorithm_flow.svg)

1. 初始化哈希表 $\text{cnt} \leftarrow \{0{:}1\}$（对应空前缀 $P[0]=0$），$pre \leftarrow 0$，$ans \leftarrow 0$；
2. 从左到右遍历 `nums` 中的每个 $x$：① $pre \mathrel{+}= x$，得到 $P[j]$；② **先查询** $ans \mathrel{+}= \text{cnt}[pre - k]$（键缺失记 0）；③ **后插入** $\text{cnt}[pre] \mathrel{+}= 1$；
3. 遍历结束，返回 $ans$。

「先查询后插入」这个顺序是整道题的胜负手——它保证查询时哈希表里只有 $P[0..j-1]$ 这 $j$ 个历史前缀和，即 $i < j$ 恒成立，子数组**必然非空**。若写反，$k = 0$ 时每个 $j$ 都会把「空子数组」自己也数进去，答案凭空多出 $n$。

### 3.4 示例演算

![示例演算：三个 1 与 k 为 2 的逐轮走查](images/wc30_q2_hash_walkthrough.svg)

以示例 1（`nums = [1,1,1]`，`k = 2`）逐轮走查，重点看 `cnt` 里「值 → 次数」的变化：

| $j$ | $pre = P[j]$ | $pre-k$ | $\text{cnt}[pre-k]$ | $ans$ | 插入后 cnt |
|-----|--------------|---------|---------------------|-------|------------|
| 0 | 0（初始） | — | — | 0 | $\{0{:}1\}$ |
| 1 | 1 | $-1$ | 0 | 0 | $\{0{:}1,\ 1{:}1\}$ |
| 2 | 2 | 0 | **1** ✔ | 1 | $\{0{:}1,\ 1{:}1,\ 2{:}1\}$ |
| 3 | 3 | 1 | **1** ✔ | 2 | $\{0{:}1,\ 1{:}1,\ 2{:}1,\ 3{:}1\}$ |

两次命中分别对应 $i=0$（子数组 `nums[0..1]`）与 $i=1$（子数组 `nums[1..2]`），返回 2。

再对示例 2（`nums = [1,2,3]`，`k = 3`）走一遍，验证「命中值不一定是 0」：

| $j$ | $pre$ | $pre-k$ | $\text{cnt}[pre-k]$ | $ans$ | 命中对应的子数组 |
|-----|-------|---------|---------------------|-------|------------------|
| 1 | 1 | $-2$ | 0 | 0 | — |
| 2 | 3 | 0 | **1** ✔ | 1 | $i=0$，`[1,2]` |
| 3 | 6 | 3 | **1** ✔ | 2 | $i=2$，`[3]` |

## 4. 算法细节

1. **`cnt` 的初值必须是 $\{0{:}1\}$**，它代表空前缀 $P[0]=0$。漏掉这一条，所有「从下标 0 开始」的子数组（如示例 1 的 `[1,1]`）都统计不到。
2. **严格「先查后插」**：查询用的是 $i < j$ 的历史前缀和，插入的 $P[j]$ 在下一轮才可用。两行顺序不可交换，这是排除空子数组的唯一手段。
3. **`cnt` 存频次而非下标**：同一个前缀和值可能在不同位置反复出现（`[0,0,0]` 的 $P$ 是 $0,0,0,0$），必须以「值 → 出现次数」存储，累加的是次数而不是命中/未命中的布尔值。
4. **数值类型**：$|P[j]| \le 2\times10^7$，$pre-k$ 落到 $[-3\times10^7, 3\times10^7]$，`int` 够用但仍建议 `long long`；答案上界为 $\frac{n(n+1)}{2} = 200010000 < 2^{31}-1$，`int` 刚好安全（`n` 再大就要 `long long`）。
5. **哈希表容量**：C++ 先 `reserve(n * 2 + 1)`，避免 $2\times10^4$ 次插入过程中反复 rehash；Python 的 `dict` 无需预处理。
6. **Python 取值用 `cnt.get(pre - k, 0)`**，不要写 `cnt[pre - k]`，避免键不存在时抛 `KeyError`；计数更新同理写 `cnt[pre] = cnt.get(pre, 0) + 1`。
7. **不要回头改写成双指针**：本题允许负数，前缀和不单调，任何「右端点右移则和必增」的假设都失效——示例 3 就是反例。

## 5. 正确性证明

**引理 1（前缀和刻画）**：对任意 $0 \le i < j \le n$，有 $\text{sum}(\text{nums}[i..j-1]) = P[j] - P[i]$；且 $n$ 个元素的所有连续非空子数组与所有下标对 $(i,j)$（$0 \le i < j \le n$）构成**双射**。

**证明**：由定义 $P[j] - P[i] = \sum_{t=0}^{j-1}\text{nums}[t] - \sum_{t=0}^{i-1}\text{nums}[t] = \sum_{t=i}^{j-1}\text{nums}[t]$，即子数组 `nums[i..j-1]` 的和。反过来，任一非空连续子数组由起点 $l$、终点 $r$（$l \le r$）唯一确定，取 $i = l,\ j = r+1$ 即有 $i < j$，且映射 $(l,r) \mapsto (l, r+1)$ 是双射。∎

**引理 2（扫描不变式）**：在第 $j$ 轮循环（处理 $\text{nums}[j-1]$）开始之前，对任意值 $v$ 有 $\text{cnt}[v] = \#\{\, i : 0 \le i < j,\ P[i] = v \,\}$。

**证明**：对 $j$ 归纳。$j = 1$ 时 $\text{cnt} = \{0{:}1\}$，而满足 $0 \le i < 1$ 的只有 $i = 0$，$P[0] = 0$，成立。设第 $j$ 轮开始前成立。该轮只做两件事：先查询（不改表），再把 $\text{cnt}[P[j]]$ 加 1。故第 $j+1$ 轮开始前 $\text{cnt}[v] = \#\{\,i < j : P[i] = v\,\} + [\,v = P[j]\,] = \#\{\,i < j+1 : P[i] = v\,\}$，不变式保持。∎

**引理 3（单轮贡献）**：第 $j$ 轮中 $\text{ans}$ 的增量 $\text{cnt}[P[j]-k]$ 恰等于「以 $\text{nums}[j-1]$ 结尾、且和为 $k$」的子数组个数。

**证明**：由引理 1，以 $\text{nums}[j-1]$ 结尾的子数组可写成 `nums[i..j-1]`（$0 \le i < j$），其和为 $k$ $\iff$ $P[j] - P[i] = k$ $\iff$ $P[i] = P[j] - k$。由引理 2，查询时 $\text{cnt}[P[j]-k]$ 正是满足 $0 \le i < j$ 且 $P[i] = P[j]-k$ 的 $i$ 的个数，即这些子数组的个数。∎

**定理**：算法返回的 $ans$ 等于和为 $k$ 的连续非空子数组总数。

**证明**：由引理 3，每轮累加的是「以该位置结尾」的合法子数组个数。$j$ 从 $1$ 取到 $n$，对应的结尾下标 $j-1$ 恰好覆盖 $0,1,\dots,n-1$ 全部位置，无一遗漏。由引理 1，每个连续非空子数组的结尾位置唯一，故不同轮次统计的子数组互不相同，计数**不重不漏**，总和即为所求总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一次线性扫描，每轮做两次哈希操作（一次查询、一次自增），均摊 $O(1)$；前缀和递推 $O(1)$。不存在排序或二次遍历。
- **空间复杂度**：$O(n)$。哈希表最多存 $n+1$ 个不同的前缀和值（全部互不相同时最坏），其余变量均为常数。若前缀和高度重复（如全 0 数组）则实际只用 1 个键，但上界仍是 $O(n)$。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        unordered_map<long long, int> cnt;      // 前缀和值 → 出现次数
        cnt.reserve(nums.size() * 2 + 1);       // 预留桶，避免反复 rehash
        cnt[0] = 1;                             // P[0] = 0，空前缀

        long long pre = 0;
        int ans = 0;
        for (int x : nums) {
            pre += x;                           // 当前前缀和 P[j]
            auto it = cnt.find(pre - k);        // 先查询：只统计 i < j
            if (it != cnt.end()) ans += it->second;
            ++cnt[pre];                         // 后插入：P[j] 下一轮才可用
        }
        return ans;
    }
};
```

### Python

```python
from typing import List


class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        cnt = {0: 1}                            # P[0] = 0，空前缀
        pre = 0
        ans = 0
        for x in nums:
            pre += x                            # 当前前缀和 P[j]
            ans += cnt.get(pre - k, 0)          # 先查询：只统计 i < j
            cnt[pre] = cnt.get(pre, 0) + 1      # 后插入：P[j] 下一轮才可用
        return ans
```

## 8. 边界情况与易错点

1. **漏掉 `cnt = {0: 1}`**：示例 1 会退化成 1 而不是 2——所有「从下标 0 开始」的子数组全部丢失。
2. **把「先查后插」写成「先插后查」**：$k = 0$ 时每轮都会把空子数组算进去，答案偏大 $n$（`[0,0,0]`、$k=0$ 会得 9 而不是 6）。
3. **`cnt` 存下标而不是频次**：遇到重复前缀和（`[0,0,0]` 的 $P = 0,0,0,0$）时只能记到一次命中，答案偏小。
4. **全 0 数组 + $k=0$**：答案是 $\frac{n(n+1)}{2} = 200010000$，仍能塞进 32 位有符号 `int`，但已非常接近上限；换语言或放宽数据范围时要立刻改用 64 位。
5. **试图用滑动窗口**：`nums` 含负数时前缀和不单调，窗口该伸还是该缩没有依据，示例 3（`[1,-1,0]`、$k=0$）会直接算错。
6. **`pre - k` 为负**：这不是异常，而是「此前缀和从未出现过」的正常信号，查表返回 0 即可，**不要提前 `break` 或跳过**。
7. **C++ 键类型**：若把 `pre` 声明成 `int` 而 `cnt` 用 `unordered_map<int,int>`，在本题范围内不会溢出；但若题目把 $|\text{nums}[i]|$ 或 $n$ 放大，$P[j]$ 会溢出，统一用 `long long` 更稳。

**延伸思考**：若要求「和 $\ge k$ 的子数组个数」且数组含负数，前缀和数组无序，$P[i] \le P[j] - k$ 的计数需要**离散化 + 树状数组 / 归并排序**，复杂度升到 $O(n \log n)$；若要求「和 $\le k$ 的最大子矩阵」，则枚举行区间 $O(n^2)$ 后对列前缀和再用有序容器求最接近值，退化到本题的一维计数内核。反过来，只要保证所有元素**非负**，滑动窗口立刻复活，$O(n)$ 双指针即可——「能否双指针」的唯一判据就是前缀和的单调性。
