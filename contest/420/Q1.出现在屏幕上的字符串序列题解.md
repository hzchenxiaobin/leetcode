# LeetCode 出现在屏幕上的字符串序列 题解

## 1. 题目概述

- **标题 / 题号**：出现在屏幕上的字符串序列（#3324，medium）
- **链接**：https://leetcode.cn/problems/find-the-sequence-of-strings-appeared-on-the-screen/
- **来源**：LeetCode 第 420 场周赛 Q1
- **难度**：中等
- **标签**：字符串、模拟、贪心

**题意**：Alice 要在一块**只有两个按键**的特殊键盘上输入字符串 `target`：

- **按键 1**：在屏幕上字符串的末尾追加字符 `'a'`；
- **按键 2**：把屏幕上字符串的**最后一个**字符改成英文字母表中的**下一个**字符（`'c'` 变 `'d'`，`'z'` 绕回 `'a'`）。

屏幕初始为空串 `""`（没有「最后一位」可改，第一步只能按按键 1）。在**按键次数最少**的前提下，按出现顺序返回输入过程中屏幕上**出现过的所有字符串**。

**约束**：

- $1 \le \text{target.length} \le 400$
- `target` 仅由小写英文字母组成

> 💡 **读题关键**：① 答案要的是「屏幕快照序列」——**每按一次键**就把当前屏幕记下来；②「按键次数最少」看似最优化问题，实则最优方案**唯一**（见 §5 证明），不存在分支与选择——这正是本题作为签到题的送分点。

## 2. 示例

**示例 1**

```text
输入：target = "abc"
输出：["a","aa","ab","aba","abb","abc"]
解释：按键 1 → "a"；按键 1 → "aa"；按键 2 → "ab"；
     按键 1 → "aba"；按键 2 → "abb"；按键 2 → "abc"。
```

**示例 2**

```text
输入：target = "he"
输出：["a","b","c","d","e","f","g","h","ha","hb","hc","hd","he"]
```

**边界用例（自造）**

```text
输入：target = "aaa"
输出：["a","aa","aaa"]
解释：每个字符都是 'a'，追加后即到位，转轮一次都不用按。
```

## 3. 解题思路

### 3.1 暴力思路：把「最少按键」当最短路搜

把每个可能的屏幕状态看作节点、两种按键各看作一条单位边，从空串出发 BFS，第一次到达 `target` 时的路径就是最少按键序列。不动脑子的 BFS 状态空间指数膨胀（每步两种后继、串长不断增长）；即便反应过来**可达状态**形如「`target` 的某个前缀 + 任意末位字母」，状态也只有 $O(26n)$ 个、BFS 也能过——但这条路从第一步就走歪了：

> ⚠️ **先问「有没有选择」，再问「怎么搜」**。两个按键的分工决定了每一步都**别无选择**——根本不存在需要搜索的分支。

### 3.2 核心观察：两个按键各管一摊，过程完全被「逼定」

![核心观察：按键 1 只追加 'a'，按键 2 只改末位，前缀逐位锁定](images/screen_seq_keyboard_concept.svg)

三条观察环环相扣：

**观察一：按键 1 只会追加 `'a'`。** 位置 $i$ 上无论要写什么字符，都只能「先按一次按键 1 让 `'a'` 落地，再用按键 2 一格格转上去」——不存在第二种产生方式。

**观察二：按键 2 只作用于最后一位。** 一旦位置 $i+1$ 的 `'a'` 被追加进来，位置 $i$ 就**永远不会再被修改**——前缀逐位锁定，各位置的代价互相独立，问题天然可以逐字符处理。

**观察三：绕回分支永不触发。** 每个位置都从 `'a'` 起步，正向转到任意目标字符 $c$ 至多 $\operatorname{ord}(c) - 97 \le 25$ 步，中途不会越过 `'z'`；题面里「`'z'` 变为 `'a'`」只是按键 2 的语义补全，与最优解无关。

于是算法就是**照抄贪心**：对 `target` 的每个字符 $c$——按一次按键 1（追加 `'a'`，记录快照），再按 $\operatorname{ord}(c) - 97$ 次按键 2（每按一次记录一次快照），直到末位等于 $c$。

**输出规模**（打消超时疑虑）：快照个数 $= n + \sum_i\big(\operatorname{ord}(c_i) - 97\big) \le 26n \le 10400$；总字符数 $\le 26n \cdot n \approx 4.2 \times 10^6$（$n = 400$）。直接模拟毫无压力。

### 3.3 算法流程

![算法流程：逐字符 → 追加 'a' → 转轮到 c → 每键记录快照](images/screen_seq_algorithm_flow.svg)

外层 `for` 逐字符、内层 `while` 把末位转到位为止；**每次按键后立即**把当前串快照进答案——「先按键、后记录」的顺序别写反。

### 3.4 示例演算

![示例演算：target = "abc" 的 6 次按键与 6 张快照](images/screen_seq_example_walkthrough.svg)

以 `target = "abc"` 完整走一遍：敲 `'a'` 花 $1+0=1$ 次按键，敲 `'b'` 花 $1+1=2$ 次，敲 `'c'` 花 $1+2=3$ 次，共 **6 次按键 → 6 个字符串**，与示例 1 完全一致。两个细节：第一个快照**恒为 `"a"`**（空屏只能按按键 1）；某位置一旦转到位，之后所有快照里该位置纹丝不动。

## 4. 算法细节

1. **维护当前屏幕**：用可变字符串（C++ 的 `string` / Python 的 `list`）保存当前串。按键 1 即 `s += 'a'`；按键 2 即末位自增 `s.back()++` / `s[-1] = chr(ord(s[-1]) + 1)`。
2. **快照时机**：**每按一次键**（无论按键 1 还是按键 2）就立刻把当前串复制进答案——漏掉按键 1 之后那一次是最常见的错。
3. **内层循环条件**：`s.back() != c`。当 $c = \text{'a'}$ 时循环体一次都不执行，追加即到位。
4. **不取模也安全**：内层循环在末位等于 $c$（$\le \text{'z'}$）时停下，`+1` 永远不会越过 `'z'`；写成 `(x + 1 - 'a') % 26 + 'a'` 的防御版也能过，但会掩盖「绕回不触发」这一关键观察。
5. **答案自检**：输出个数恰等于按键总数 $n + \sum_i(\operatorname{ord}(c_i) - 97)$；首元素恒为 `"a"`、末元素恰为 `target` 本身。

## 5. 正确性证明

**引理 1**：任何以 `target` 为终态的合法输入过程，按键 1 恰好被按 $n$ 次。

**证明**：屏幕长度初始为 0，按键 1 使长度加一，按键 2 不改变长度；终态长度为 $n$，故按键 1 恰好 $n$ 次，且第 $i$ 次按键 1 使位置 $i$ 落地。∎

**引理 2**：位置 $i$ 的字符只能在「第 $i$ 次按键 1 之后、第 $i+1$ 次按键 1 之前」的窗口内被修改，此后永远不变。

**证明**：按键 2 仅作用于当前末位。第 $i+1$ 次按键 1 之后，末位变成位置 $i+1$，位置 $i$ 不再是末位；而两个按键都无法修改非末位字符，故位置 $i$ 从此定格。∎

**定理**：最少按键总数为 $n + \sum_i \big(\operatorname{ord}(c_i) - 97\big)$，且达到该下界的按键序列**唯一**；贪心模拟产生的快照序列即为所求答案。

**证明**：由引理 2，落在位置 $i$ 窗口内的按键 2 次数 $k_i$ 必须满足 $\text{'a'} + k_i \equiv c_i \pmod{26}$，其最小非负解为 $k_i = \operatorname{ord}(c_i) - 97$（因 $0 \le \operatorname{ord}(c_i) - 97 \le 25$）。于是任意合法过程的总按键数

$$n + \sum_i k_i \ \ge\ n + \sum_i \big(\operatorname{ord}(c_i) - 97\big),$$

而贪心在每个位置恰好取 $k_i = \operatorname{ord}(c_i) - 97$，达到该下界。唯一性：窗口内若按按键 1，会立即开启位置 $i+1$、终结位置 $i$ 的修改权，与「位置 $i$ 终值为 $c_i$」矛盾，故窗口内只能按按键 2，且每按一次末位严格加一、没有任何排列自由度 $\Rightarrow$ 按键序列唯一 $\Rightarrow$ 屏幕快照序列唯一。∎

## 6. 复杂度分析

- **时间复杂度**：$O(26 n^2)$。输出至多 $26n$ 个字符串、每个长度至多 $n$；每次按键做一次 $O(n)$ 的快照拷贝，总时间即为输出总字符数（$n = 400$ 时约 $4.2 \times 10^6$）。
- **空间复杂度**：$O(26 n^2)$，即答案本身的大小；若不计输出，辅助空间仅 $O(n)$（当前串）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    vector<string> stringSequence(string target) {
        vector<string> res;
        string s;                        // 当前屏幕
        for (char c : target) {
            s += 'a';                    // 按键 1：追加 'a'
            res.push_back(s);            // 快照
            while (s.back() != c) {      // 按键 2：末位转到 c 为止
                ++s.back();              // 不会越过 'z'（观察三）
                res.push_back(s);        // 快照
            }
        }
        return res;
    }
};
```

### Python

```python
class Solution:
    def stringSequence(self, target: str) -> List[str]:
        res, s = [], []
        for c in target:
            s.append('a')                    # 按键 1
            res.append(''.join(s))           # 快照
            while s[-1] != c:                # 按键 2：转轮到 c
                s[-1] = chr(ord(s[-1]) + 1)  # 循环必在 'z' 前停下
                res.append(''.join(s))       # 快照
        return res
```

## 8. 边界情况与易错点

1. **首元素恒为 `"a"`**：空屏没有「最后一位」，第一次只能按按键 1。
2. **`target[i] == 'a'`**：内层转轮零次，追加即到位；如 `"aaa"` 只有 3 个快照，别多转 26 步绕一圈。
3. **`'z'` 无需特判**：正向从 `'a'` 出发至多 25 步，绕回分支永不触发；写 `% 26` 防御式代码不算错，但说明没看穿观察三。
4. **输出规模不是 $n$**：快照个数是 $n + \sum_i(\operatorname{ord}(c_i) - 97)$，最坏全 `'z'` 时 $26n = 10400$ 个、总字符约 $4.2 \times 10^6$——别因「输出比输入大两个数量级」而慌。
5. **快照时机**：按键 1 之后也要记录；「先按键、后记录」共 $n + \sum_i k_i$ 次。
6. **自检不变量**：答案最后一个元素应恰为 `target` 本身。
