# LeetCode N 次操作后的最大分数和 题解

## 1. 题目概述

- **标题 / 题号**：N 次操作后的最大分数和（#1799，hard）
- **链接**：https://leetcode.cn/problems/maximize-score-after-n-operations/
- **来源**：LeetCode 第 48 场双周赛 Q4
- **难度**：困难
- **标签**：位运算、数组、数学、动态规划、回溯、位掩码、数论

**题意**：给定大小为 $2n$ 的正整数数组 `nums`，执行恰好 $n$ 次操作。第 $i$ 次操作（编号从 1 开始）：从当前数组中选两个元素 $x, y$ 删除，获得分数 $i \times \gcd(x, y)$。求 $n$ 次操作后能获得的**分数总和最大值**。

**约束**：

- $1 \le n \le 7$
- `nums.length == 2n`
- $1 \le nums[i] \le 10^6$

## 2. 示例

**示例 1**

```text
输入：nums = [1,2]
输出：1
解释：只有一种配对：1 × gcd(1, 2) = 1。
```

**示例 2**

```text
输入：nums = [3,4,6,8]
输出：11
解释：(1 × gcd(3,6)) + (2 × gcd(4,8)) = 3 + 8 = 11。
```

**示例 3**

```text
输入：nums = [1,2,3,4,5,6]
输出：14
解释：(1 × gcd(1,5)) + (2 × gcd(2,4)) + (3 × gcd(3,6)) = 1 + 4 + 9 = 14。
```

## 3. 解题思路

### 3.1 暴力思路

一次完整方案 = 把 $2n$ 个数划分成 $n$ 个无序对，再决定每对在第几轮删除。配对方式数是 $(2n-1)!! = 13 \times 11 \times \dots \times 1 = 135135$（$n=7$ 时），配上轮次的全排列 $7! = 5040$，直接搜是 $6.8 \times 10^8$ 量级，纯 DFS 会非常勉强。观察到一个**减负事实**（重排不等式）：固定一种配对后，把 $n$ 个 gcd 升序排列、乘数 $1..n$ 升序分配就是该配对下的最优轮次安排——即只需枚举配对（$135135$ 种）、各自排序求和取最大。这已经可写，但状态指数级重复（大量配对共享"已删除前缀"），正是**状压 DP** 的舞台。

### 3.2 核心观察一：状态 = 已删除元素的集合，轮次由 popcount 唯一确定

![状态设计：mask 记录已删元素，轮次乘数由 popcount 唯一确定](images/bw48_q4_bitmask_dp_model.svg)

$2n \le 14$，一个 14 位掩码 `mask` 就能表示"**已经被删掉的那些元素**"。设 $dp[mask]$ 为：恰好删掉 `mask` 中这些元素（在前 $\mathrm{popcount}(mask)/2$ 轮里以某种顺序两两删除）所能取得的最大分数和。那么下一个要删的对子乘数是

$$\text{round} = \mathrm{popcount}(mask) / 2 + 1$$

只由 `mask` 决定——**状态天然携带了轮次信息**，不需要把轮次塞进状态。转移时从 `mask` 出发，任选两个**未删除**的元素 $i, j$：

$$dp[\,mask \mid (1{\ll}i) \mid (1{\ll}j)\,] = \max\big(\cdot,\ dp[mask] + \text{round} \times g[i][j]\big)$$

其中 $g[i][j] = \gcd(nums[i], nums[j])$ 预计算。初始 $dp[0] = 0$，答案 $dp[2^{2n} - 1]$。

### 3.3 核心观察二（最大陷阱）：不能只枚举「最低空闲位」的配对！

![易错点警示：只枚举最低空闲位配对在本题是错的](images/bw48_q4_transition_warning.svg)

配对型状压 DP 有个流传很广的剪枝："每轮固定让**下标最小的空闲元素**参与配对，只枚举它的搭档"。这个剪枝在**不计顺序**的配对计数/划分问题里合法（任何完美匹配都能规范化成"最小元素先配"）；但在本题**是错的**——因为**乘数依赖轮次**：最优方案可能需要让下标最小的元素留到最后一轮吃大乘数。把顺序强行规范化，等于砍掉了大量"先删别的、后删低位元素"的方案。

> ⚠️ 实测反例：`nums = [26, 7, 4, 16, 1, 29, 27, 13]`。真值为 $67 = 1{\times}1 + 2{\times}1 + 3{\times}4 + 4{\times}13$（大 gcd 对 $(26,13)$ 必须留到第 4 轮）；而"最低位先配"的错误 DP 只能得 $55$。更阴险的是，**本题三个官方示例恰好都不触发这个 bug**（最优方案里下标 0 都在第 1 轮被删），只跑样例完全发现不了——本题代码必须与"逐轮枚举全部配对"的暴力对拍才算可靠。

正确做法：每个状态**枚举全部空闲点对** $(i < j)$。状态数不变（$2^{14}$），转移数从每状态 $O(n)$ 升到 $O(n^2)$，总量约 $7.5 \times 10^5$，毫无压力。

### 3.4 示例演算

![示例演算：数组 3,4,6,8 的 gcd 表与两条转移路径](images/bw48_q4_walkthrough.svg)

以 `nums = [3,4,6,8]` 为例：$g[0][2] = \gcd(3,6) = 3$、$g[1][3] = \gcd(4,8) = 4$。路径 ①：先删 $(3,6)$ 得 $1 \times 3$，再删 $(4,8)$ 得 $2 \times 4$，$dp[1111_2] = 11$；路径 ②：先删 $(3,4)$ 得 $1$，再删 $(6,8)$ 得 $2 \times 2$，只有 5。DP 取最大，答案 11。也可以从重排不等式看：配对 $\{3,4\},\{6,8\}$ 的 gcd 序列 $(1, 2)$ 配乘数 $(1,2)$ 得 5，而配对 $\{3,6\},\{4,8\}$ 的 gcd 序列 $(3,4)$ 得 $3 + 8 = 11$——两对四种"轮次安排"里 DP 自动挑出了最优的那种。

## 4. 算法细节

1. **gcd 预计算**：$g[i][j]$（$i < j$）共 $\binom{14}{2} = 91$ 个，`std::gcd` / `math.gcd` 直接算，DP 中零 gcd 计算。
2. **只遍历偶数 popcount 的状态**：`mask` 的位数必为偶数（成对删除），奇数位状态不可达，直接 `continue`，省一半状态。
3. **枚举全部空闲对**：`i` 从 0 到 $2n-1$ 找 `mask` 外的位，`j` 从 $i+1$ 起找，构成 $O(n^2)$ 内层循环。**不要**用 `ctz(~mask)` 取最低空闲位后只枚举搭档（见 §3.3）。
4. **转移方向**：`mask` 单调递增（只会加位），按 `mask` 从小到大遍历即完成拓扑序，无需显式记忆化。
5. **乘数与分数上界**：`round = popcount(mask) / 2 + 1`。单轮分数 $\le 7 \times 10^6$，总分上界 $\sum_{i=1}^{7} i \times 10^6 = 2.8 \times 10^7$，`int` 安全，无需 64 位。
6. **重排不等式作为理解工具**：固定配对下"gcd 升序配乘数升序最优"，说明 DP 的 `max` 在同一配对不同轮次安排间自动选优；这也解释了为什么转移里不需要任何排序动作。

## 5. 正确性证明

**引理 1（方案与路径一一对应）**：一个完整的操作方案（$n$ 个有序的、互不相交的元素对）与状态转移路径 $0 = m_0 \to m_1 \to \dots \to m_n = 2^{2n}-1$（$m_t = $ 前 $t$ 轮删除元素之并）一一对应，且第 $t$ 轮的乘数恰为 $t$。

**证明**：给定方案，令 $m_t$ 为前 $t$ 轮删除元素的并集，则 $m_{t} \supsetneq m_{t-1}$ 恰增两位（第 $t$ 轮删的两元素），且第 $t$ 步转移的 `round` $= \mathrm{popcount}(m_{t-1})/2 + 1 = (2(t-1))/2 + 1 = t$，与方案得分逐轮一致。反之，任一路径的每步取"新增的两位"为该轮删除的对，得到合法方案。两方向构造互逆。∎

**引理 2（DP 值的刻画）**：按上述转移从小到大填表后，$dp[mask]$ 等于"所有把 `mask` 中元素在前 $\mathrm{popcount}(mask)/2$ 轮内两两删除的方案"的得分最大值。

**证明**：对 `mask` 归纳。$dp[0] = 0$ 正确（空方案 0 分）。设小于 `mask` 的状态均正确。`mask` 的最优方案的最后一轮删除某对 $(i, j)$（即从 $mask' = mask \setminus \{i, j\}$ 转移而来），其得分为 $dp^\ast[mask'] + \text{round} \times g[i][j]$；DP 枚举了**全部**空闲对 $(i, j)$（含这一对），且 $mask' < mask$ 已归纳正确，故 $dp[mask] \ge$ 最优值。另一方面 DP 的每个转移都对应一个真实方案（引理 1），故 $dp[mask] \le$ 最优值。两者相等。∎

**定理**：算法返回 $dp[2^{2n} - 1]$ 为 $n$ 次操作得分总和的最大值。

**证明**：$2^{2n} - 1$ 是所有元素被删的终态，其 popcount 为 $2n$，由引理 2，$dp[2^{2n}-1]$ 是所有完整方案的最大得分；由引理 1，所有完整方案与题目的操作方案一一对应。∎

**推论（为何"最低位先配"错误）**：引理 2 的证明要求转移枚举"最后一轮的**全部**可能对子"。若限定最低空闲位必须参与，则某些方案（其最后一轮不含该位元素）对应的路径被剪掉；由 §3.3 的反例，被剪方案中存在全局最优，故该剪枝不保正确性。∎

## 6. 复杂度分析

- **时间**：$O\big(2^{2n} \cdot n^2\big)$。$n \le 7$ 时状态 $2^{14} = 16384$ 个，每状态内层至多 $\binom{14}{2} = 91$ 对，总量约 $7.5 \times 10^5$；gcd 预计算 $O(n^2 \log V)$ 忽略不计。实测 $n = 7$、值域 $10^6$ 随机数据 C++ 约 4ms、Python 约 87ms。
- **空间**：$O(2^{2n} + n^2)$。DP 数组 $2^{14}$ 个整数，gcd 表 $14 \times 14$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maxScore(vector<int>& nums) {
        int m = (int)nums.size();
        vector<vector<int>> g(m, vector<int>(m, 0));     // gcd 预计算
        for (int i = 0; i < m; ++i)
            for (int j = i + 1; j < m; ++j)
                g[i][j] = g[j][i] = std::gcd(nums[i], nums[j]);

        int full = (1 << m) - 1;
        vector<int> dp(full + 1, 0);                      // dp[mask]：已删元素集合恰为 mask 的最大得分
        for (int mask = 0; mask < full; ++mask) {
            int used = __builtin_popcount(mask);
            if (used & 1) continue;                       // 只从「删了偶数个元素」的状态转移
            int round = used / 2 + 1;                     // 本次操作的编号（乘数）
            for (int i = 0; i < m; ++i) {                 // 枚举下一对被删除的空闲元素
                if (mask >> i & 1) continue;
                for (int j = i + 1; j < m; ++j) {
                    if (mask >> j & 1) continue;
                    int nmask = mask | (1 << i) | (1 << j);
                    dp[nmask] = max(dp[nmask], dp[mask] + round * g[i][j]);
                }
            }
        }
        return dp[full];
    }
};
```

### Python

```python
from math import gcd

class Solution:
    def maxScore(self, nums: list[int]) -> int:
        m = len(nums)
        g = [[0] * m for _ in range(m)]          # gcd 预计算
        for i in range(m):
            for j in range(i + 1, m):
                g[i][j] = g[j][i] = gcd(nums[i], nums[j])

        full = (1 << m) - 1
        dp = [0] * (full + 1)                    # dp[mask]：已删元素集合恰为 mask 的最大得分
        for mask in range(full):
            used = bin(mask).count('1')
            if used % 2 == 1:                    # 只从删了偶数个元素的状态转移
                continue
            rnd = used // 2 + 1                  # 本次操作编号
            for i in range(m):
                if mask >> i & 1:
                    continue
                for j in range(i + 1, m):
                    if mask >> j & 1:
                        continue
                    nmask = mask | (1 << i) | (1 << j)
                    cand = dp[mask] + rnd * g[i][j]
                    if cand > dp[nmask]:
                        dp[nmask] = cand
        return dp[full]
```

> 💡 两份代码均通过官方 3 组示例；并与「逐轮递归枚举全部配对顺序」的纯暴力 DFS 对拍 **1500 组随机数据**（$m \in \{2,4,6,8\}$、值域 3/6/12/30），`mismatch = 0`。顺带一提：最初版本曾采用"最低空闲位先配"的剪枝，正是这套对拍抓住了它——反例 `[26,7,4,16,1,29,27,13]` 上错误版得 55、正确版 67（真值 67），三个官方示例全部查不出问题。

## 8. 边界情况与易错点

1. **「最低空闲位先配」剪枝是本题最大的坑**（§3.3）：乘数依赖轮次，配对顺序不可规范化。样例全过 ≠ 正确，务必与暴力对拍。
2. **奇数 popcount 状态要跳过**：从奇数位状态出发 `round` 的计算会错（$used/2$ 向下取整），虽然不影响最终答案的正确性（这些状态的 dp 值本就无意义），但会产生无意义的转移浪费，且语义混乱。
3. **gcd 表对称填充**：$g[i][j] = g[j][i]$ 都要填，转移枚举 $i < j$ 时不越界。
4. **乘数从 1 开始**：`used / 2 + 1` 在 `mask = 0` 时得 1，别写成 `used / 2`（会把所有轮次错位）。
5. **$n = 1$**：只有两个数、一轮操作，$dp[11_2] = \gcd$，正确；`full = 3` 的边界循环 `mask < full` 不会漏。
6. **重复元素**：`gcd` 对相同值照样正确（如两个 6 的 gcd 是 6），无需去重。
7. **分数上界**：$n = 7$、$nums[i] \le 10^6$ 时总分 $\le (1+2+\dots+7) \times 10^6 = 2.8 \times 10^7$，`int` 安全。
8. **想清楚再优化**：利用重排不等式可以把 DP 改成"只枚举配对、分数按 gcd 排序加权"的形式（状态含序、实现复杂），或者反向定义 $dp[mask]$ 为"剩余元素为 mask 的最优"，都可以做，但正确性论证都要重新过一遍；比赛时 $O(2^{2n} n^2)$ 是最不容易写错的选择。

**延伸思考**：配对型状压 DP 的通用形态是"代价 = $w(i,j) \times \pi(\text{轮次})$"。当 $\pi$ 是常数（如 1879）时可规范化剪枝到 $O(2^{m} m)$；当 $\pi$ 与顺序相关（本题乘数递增）时一般需要全对枚举，或者按重排不等式把"轮次安排"外提：先枚举配对集合再对 gcd 排序赋权，可将复杂度压到 $O((2m-1)!! \cdot n \log n)$ 与 $O(2^{2n} n^2)$ 之间取优。再往外走一步，"每对代价还依赖删除顺序"的问题（如代价与前一轮删的对相关）连重排结构都没有，只能回到全排列搜索 + 强剪枝——分辨这三档结构，是这类题快速定策的关键。
