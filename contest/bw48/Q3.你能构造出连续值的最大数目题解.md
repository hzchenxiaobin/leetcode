# LeetCode 你能构造出连续值的最大数目 题解

## 1. 题目概述

- **标题 / 题号**：你能构造出连续值的最大数目（#1798，medium）
- **链接**：https://leetcode.cn/problems/maximum-number-of-consecutive-values-you-can-make/
- **来源**：LeetCode 第 48 场双周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、排序

**题意**：给定长度为 $n$ 的整数数组 `coins`，第 $i$ 枚硬币面值为 `coins[i]`。从这些硬币中**选出一个子集**，其和为 $x$ 则称你可以**构造出** $x$（空集构造出 0）。返回从 0 开始（**包括 0**）最多能构造出多少个**连续**整数。

**约束**：

- $1 \le n \le 4 \times 10^4$
- $1 \le coins[i] \le 4 \times 10^4$

## 2. 示例

**示例 1**

```text
输入：coins = [1,3]
输出：2
解释：可构造 0（空集 []）、1（[1]）；2 无法构造，故连续段为 {0,1}，共 2 个。
```

**示例 2**

```text
输入：coins = [1,1,1,4]
输出：8
解释：0,1,2,3 由三个 1 组合，4 用 [4]，5,6,7 = 4 + {1,2,3}，共 8 个连续整数。
```

**示例 3**

```text
输入：coins = [1,4,10,3,1]
输出：20
```

## 3. 解题思路

### 3.1 暴力思路

$n \le 4 \times 10^4$ 时子集有 $2^n$ 个，逐个枚举显然不可行；即便用**子集和背包**（布尔 DP，容量上限 $\sum coins \le 1.6 \times 10^9$）也开不起数组、时间也不允许。注意题目并不要求构造出很大的值，只关心**从 0 开始的连续段长度**——这个"连续性"的结构正是突破口。

### 3.2 核心观察：覆盖区间 [0, x] 的无缝扩展

![核心观察：c ≤ x+1 时覆盖区间无缝扩展，否则出现缺口](images/bw48_q3_coverage_extension.svg)

维护变量 $x$，含义是**不变量**：**用当前已处理的硬币可以构造出 $[0, x]$ 中的每一个整数**（初始 $x = 0$，空集构造 0）。设下一枚（按从小到大排序后）硬币面值为 $c$：

- **若 $c \le x + 1$**：原有构造集合覆盖 $[0, x]$，把 $c$ 加进任何一个子集就覆盖 $[c, c + x]$。由于 $c \le x + 1$，两段区间 $[0, x]$ 与 $[c, c+x]$ **相接或重叠**，无缝合并成 $[0, x + c]$——不变量扩展。
- **若 $c > x + 1$**：整数 $x + 1$ 无法构造——已处理硬币的子集和最多到 $x$，未处理硬币每一枚都 $\ge c > x + 1$，任何包含它们的非空子集之和都超过 $x + 1$。于是 $x + 1$ 是**永远补不上的缺口**，答案就此封顶（严格论证见 §5 引理 2）。

因此算法出奇地短：**排序后从小到大扫，能吃就吃，吃不动就停**。

### 3.3 算法流程

![算法流程：排序后从小到大吃硬币](images/bw48_q3_greedy_flow.svg)

```text
1. coins 升序排序
2. x = 0                    # 已能构造 [0, x]
3. 对每枚硬币 c（从小到大）：
4.     若 c > x + 1：break   # 缺口 x+1 补不上，后面的硬币更大更不可能
5.     x += c               # 覆盖扩展为 [0, x+c]
6. 返回 x + 1               # 0..x 共 x+1 个连续整数
```

### 3.4 示例演算

![示例演算：[1,1,1,4] 的覆盖区间逐步扩展](images/bw48_q3_walkthrough.svg)

以示例 2 `coins = [1,1,1,4]`（已升序）演算：$x=0 \to$ 吃第 1 枚 1（$1 \le 1$）得 $x=1$，覆盖 $\{0,1\}$；吃第 2 枚 1（$1 \le 2$）得 $x=2$，覆盖 $\{0,1,2\}$；吃第 3 枚 1（$1 \le 3$）得 $x=3$；吃 4（$4 \le 4$）得 $x=7$，覆盖 $[0,7]$。返回 $7 + 1 = 8$。对照示例 1：吃 1 后 $x=1$，下一枚 3 满足 $3 > 2$，停止，返回 2。

## 4. 算法细节

1. **必须先排序**：不排序时"下一枚更大"的前提不成立，提前 `break` 就会误判。排序把"暂时吃不下"升级成"永远吃不下"。
2. **`break` 与 `continue` 等价但 break 更快**：升序后一旦 $c > x+1$，后面全部更大，直接终止；写成 `continue` 也正确（后续每枚都过不了检查），只是白扫一遍。
3. **返回值是 $x + 1$**：题目"从 0 开始包括 0"，$[0, x]$ 含 $x+1$ 个整数，别把 0 忘了。
4. **不用去重、不用贪心选不选**：算法里没有"选择"——每枚硬币是否"被用"是由覆盖扩展自动蕴含的（吃进 $x$ 的硬币未必每枚都必要，但这不影响不变量的正确性，见证明）。
5. **整型范围**：$x$ 最大为 $\sum coins \le 4 \times 10^4 \times 4 \times 10^4 = 1.6 \times 10^9$，贴近 `int` 上界 $2.1 \times 10^9$——C++ 里 $x$ 与返回值建议直接用 `long long` 防御（本题实际约束下 `int` 恰好够，但边界感要有）；Python 无此问题。
6. **复杂度来源只有排序**：$O(n \log n)$ 排序 + $O(n)$ 扫描。

## 5. 正确性证明

**引理 1（扩展引理）**：设硬币子集 $A$ 的可构造集合（全部子集和）覆盖 $[0, x]$，硬币 $c \notin A$ 且 $c \le x + 1$，则 $A \cup \{c\}$ 的可构造集合覆盖 $[0, x + c]$。

**证明**：$A \cup \{c\}$ 的子集分两类：不含 $c$ 的，其和覆盖 $[0, x]$（假设）；含 $c$ 的，其和为 $c + (\text{A 的子集和})$，覆盖 $[c, c + x]$。由 $c \le x + 1$ 得 $c \le x + 1 < x + 2$，即区间 $[0, x]$ 与 $[c, c+x]$ 满足 $c \le x + 1$，相邻无缺口（$c = x+1$ 时恰相接），两段并集覆盖 $[0, x + c]$。∎

**引理 2（缺口阻断引理）**：设贪心已吃入的硬币全体为 $A$，其面值总和恰为 $x$；未吃入的每枚硬币面值都 $> x + 1$。则用全部硬币也无法构造 $x + 1$。

**证明**：考察任一子集 $S$：若 $S$ 含有未吃入的某枚硬币 $c$，则 $S$ 的和 $\ge c > x + 1$；否则 $S \subseteq A$，其和 $\le \sum_{a \in A} a = x < x + 1$。两种情形都取不到 $x + 1$，故 $x + 1$ 不可构造。∎

**定理（贪心正确性）**：排序后依次执行"若 $c \le x+1$ 则 $x \gets x + c$，否则终止"的过程，最终返回的 $x + 1$ 恰为从 0 开始可构造的最大连续整数个数。

**证明**：先证**可达性**（真答案 $\ge$ 返回值）：对已处理硬币数归纳，不变量"已处理硬币的可构造集合覆盖 $[0, x]$"始终成立——基础为空集时 $x = 0$，每步由引理 1 保持。故 $[0, x]$ 中每个整数都可构造，真答案至少为 $x + 1$。再证**上界**（真答案 $\le$ 返回值）：过程终止有两种情形。（i）某枚 $c > x + 1$ 触发终止：$x$ 由各枚吃入硬币逐次累加而得，故已吃入硬币总和恰为 $x$，且未处理硬币每枚 $> x + 1$，引理 2 的条件全部满足，$x + 1$ 不可构造，真答案至多 $x + 1$。（ii）全部硬币吃入：所有硬币总和为 $x$，任何子集和 $\le x$，而由归纳可构造集合覆盖 $[0, x]$，于是 $x + 1$ 超过总和不可构造，真答案恰为 $x + 1$。两情形合并得真答案 $= x + 1$，即返回值。∎

> 💡 证明的枢纽在于注意到**已吃入硬币的总和恰等于 $x$**——这把"覆盖 $[0,x]$"补成了"构造集合被夹在 $[0,x]$ 里"，上界论证才闭合。

## 6. 复杂度分析

- **时间**：$O(n \log n)$，排序主导；随后的一趟扫描 $O(n)$。
- **空间**：$O(1)$ 额外（原地排序），Python 的 `sort` 亦为原地。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int getMaximumConsecutive(vector<int>& coins) {
        sort(coins.begin(), coins.end());
        long long x = 0;                    // 已能构造 [0, x]
        for (int c : coins) {
            if (c > x + 1) break;           // 缺口 x+1 补不上，后面的硬币更大
            x += c;                         // 覆盖区间扩展为 [0, x + c]
        }
        return (int)(x + 1);                // 0..x 共 x+1 个连续整数
    }
};
```

### Python

```python
class Solution:
    def getMaximumConsecutive(self, coins: list[int]) -> int:
        coins.sort()
        x = 0                             # 已能构造 [0, x]
        for c in coins:
            if c > x + 1:                 # 缺口 x+1 补不上
                break
            x += c
        return x + 1                      # 0..x 共 x+1 个
```

> 💡 两份代码均通过官方 3 组示例；另与「枚举全部 $2^n$ 个子集求可达和、再数连续段」的暴力对拍 **1500 组随机数据**（$n \le 14$、面值 $\le 15$、含全 1 与大面值结构），`mismatch = 0`；$n = 4 \times 10^4$ 满规模实测 C++ 约 40ms、Python 约 37ms。

## 8. 边界情况与易错点

1. **别忘了返回 $x+1$**：0 本身算一个可构造值，直接返回 $x$ 会把答案少 1（示例 1 返回 2 而不是 1）。
2. **必须排序**：`[4,1,1,1]` 不排序先遇 4 就停，错答 1；排序后才能吃出 8。
3. **条件是 $c \le x + 1$ 不是 $c \le x$**：$c = x+1$ 时两段区间恰好相接，合法（示例 2 中 $4 \le 3+1$ 正是关键一步）。
4. **"最小面值不是 1"**：如 `coins = [2,2]`，第一枚 2 就有 $2 > 0 + 1$，立即停止，答案为 1（只能构造 0）。
5. **溢出防御**：总和理论上可达 $1.6 \times 10^9$，C++ 中 `x` 用 `long long` 累加最稳（`int` 在本题约束下恰好不溢出，但只差一个数量级，养成习惯）。
6. **贪心方向别搞反**：是"从小到大"吃。有人想"从大到小"先吃大硬币，那既破坏了"未处理硬币更大"的阻断前提，也会在小硬币补缺时漏解。
7. **别把本题做成背包**：$O(n \cdot \sum)$ 的子集和 DP 在 $10^9$ 容量下不可行，也不必要。
