# LeetCode 匹配模式数组的子数组数目 II 题解

## 1. 题目概述

- **标题 / 题号**：匹配模式数组的子数组数目 II（#3036，hard）
- **链接**：https://leetcode.cn/problems/number-of-subarrays-that-match-a-pattern-ii/
- **来源**：LeetCode 第 384 场周赛 Q4
- **难度**：困难
- **标签**：数组、字符串匹配、KMP（前缀函数）、哈希函数、滚动哈希

**题意**：给定长度为 $n$ 的整数数组 `nums` 和长度为 $m$ 的模式数组 `pattern`（元素只含 $-1, 0, 1$）。一个大小为 $m+1$ 的子数组 `nums[i..i+m]` 匹配 `pattern`，当且仅当对每个 $k \in [0, m)$：

- `pattern[k] == 1` 时 `nums[i+k+1] > nums[i+k]`；
- `pattern[k] == 0` 时 `nums[i+k+1] == nums[i+k]`；
- `pattern[k] == -1` 时 `nums[i+k+1] < nums[i+k]`。

返回匹配 `pattern` 的子数组**数目**（可重叠）。

**约束**：

- $2 \le n = nums.length \le 10^6$
- $1 \le nums[i] \le 10^9$
- $1 \le m = pattern.length < n$，$-1 \le pattern[i] \le 1$

> 💡 题意与同场 Q2（#3034 匹配模式数组的子数组数目 I）**完全一致**，仅 $n$ 从 $100$ 放大到 $10^6$。Q2 的 $O(nm)$ 逐窗口暴力在这里最坏约 $5 \times 10^{11}$ 次比较，彻底失效——必须给出 $O(n+m)$ 的线性算法。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4,5,6], pattern = [1,1]
输出：4
解释：模式 [1,1] 表示找长度为 3 且严格上升的子数组。
      [1,2,3]、[2,3,4]、[3,4,5]、[4,5,6] 均匹配，共 4 个。
```

**示例 2**

```text
输入：nums = [1,4,4,1,3,5,5,3], pattern = [1,0,-1]
输出：2
解释：[1,4,4,1]（升、平、降）与 [3,5,5,3] 均匹配，共 2 个。
```

**补充示例（强调可重叠）**

```text
输入：nums = [4,5,6,7], pattern = [1,1]
输出：2
解释：cmp = [1,1,1]，两个可重叠窗口 [4,5,6]、[5,6,7] 均匹配。
      若统计方式不允许重叠（如 str.count），会错误地只数出 1 个。
```

## 3. 解题思路

### 3.1 暴力思路及其在 10^6 下的崩溃

沿用 Q2 的做法：对每个窗口起点 $i \in [0, n-m-1]$ 逐位比较。本题 $n \le 10^6$、$m$ 可达 $n-1$，最坏情况（如 `nums` 全相等、`pattern` 全 0，或 `nums` 严格递增、`pattern` 全 1）每个窗口都要完整比较 $m$ 位才判定成功或失败，总操作量 $\Theta(nm) \approx 5 \times 10^{11}$，远超时限。

**浪费的根源**：相邻窗口重叠 $m-1$ 个字符，暴力在右移一位后把已比较过的信息**全部丢弃**、从窗口头重新比较。突破口在于让"已匹配的前缀信息"**跨窗口保留**——这正是 KMP 的用武之地。

### 3.2 核心观察：符号化降维 + KMP 失配不回头

![核心观察：失配不回头，用 border 跳过重复比较](images/wc384_q4_kmp_concept.svg)

**第一步（继承 Q2）**：`pattern` 约束的只是相邻元素的**大小关系**，定义符号数组

$$cmp[i] = \mathrm{sign}\big(nums[i+1] - nums[i]\big) \in \{-1, 0, 1\}, \quad i \in [0, n-2]$$

则「子数组 `nums[i..i+m]` 匹配 `pattern`」$\iff$「`cmp[i..i+m-1]` 与 `pattern` 逐位相等」。问题降维为：**统计模式串 `pattern`（字符集 $\{-1,0,1\}$）在文本 `cmp` 中可重叠出现的次数**。

**第二步（本题新意）**：用 KMP 在 $O(n+m)$ 内完成匹配计数。KMP 扫描文本时维护**已匹配长度** $j$（当前文本后缀与 `pattern` 前缀的最长匹配长度）：

- 命中（`cmp[i] == pattern[j]`）：$j$ 加一；
- 失配：$j$ 沿前缀函数链回跳 $j \leftarrow \pi[j-1]$——这相当于把 `pattern` 一次性右移到「已匹配段的 **border**（最长相等真前后缀）」对齐的位置，跳过的部分**无需再比**；
- $j$ 达到 $m$：发现一次完整匹配，计数后令 $j = \pi[m-1]$（而不是 $0$！），保住**重叠**匹配的续接信息。

文本指针 $i$ **永不回退**，这是突破 $O(nm)$ 的关键。

### 3.3 算法流程

![算法流程：符号化 + KMP 计数](images/wc384_q4_kmp_flow.svg)

1. 一遍扫描构建 `cmp`（长度 $n-1$），$O(n)$；
2. 对 `pattern` 求前缀函数 $\pi$：$\pi[i]$ 为 `pattern[0..i]` 最长相等真前后缀的长度，$O(m)$；
3. 双指针扫描 `cmp`：失配则 $j$ 沿 $\pi$ 链回跳后重试；命中则 $j{+}{+}$；
4. $j = m$ 时 `ans++`，并令 $j = \pi[m-1]$ 继续扫描（支持重叠计数）；
5. 扫描结束返回 `ans`。

### 3.4 示例演算

![示例演算与重叠陷阱](images/wc384_q4_kmp_walkthrough.svg)

以示例 2 为例，`nums = [1,4,4,1,3,5,5,3]`，`pattern = [1,0,-1]`：

| 步骤 | 内容 | 结果 |
|------|------|------|
| 1 | 相邻差取符号 | cmp = [1, 0, −1, 1, 1, 0, −1] |
| 2 | 求 pattern 的 π | π = [0, 0, 0]（[1,0,−1] 无 border） |
| 3 | 扫描 i=0..2 | 三连命中，j=3=m → ans=1，j 回跳 π[2]=0 |
| 4 | 扫描 i=3..4 | i=3 命中 j=1；i=4 失配回跳 j=0 后再命中，j=1 |
| 5 | 扫描 i=5..6 | 两连命中，j=3=m → ans=2，j 回跳 0 |
| 6 | 汇总 | ans = 2 ✓ |

演算图下半部分给出**重叠陷阱**的对照实验：`cmp = [1,1,1,1]`、`pattern = [1,1]`（$\pi = [0,1]$），正确做法得 $3$，若完整匹配后把 $j$ 重置为 $0$ 则只得 $2$——漏掉重叠窗口。这是本题实现中最致命的易错点。

## 4. 算法细节

1. **符号函数三值化**：`cmp[i] = (d > 0) - (d < 0)`，其中 `d = nums[i+1] - nums[i]`。这一步把「比较语义」编码成与 `pattern` 同值域的整数，使 KMP 可直接在整数数组上运行（无需映射成字符）。
2. **前缀函数的计算**：对 `pattern` 自匹配——`pi[i]` 由 `pi[i-1]` 出发，失配时沿 `pi[pi[j-1]-1]` 链回跳。$j$ 每轮至多增加 1，回跳严格递减，均摊 $O(m)$。
3. **匹配计数循环**：`j` 语义为「`cmp[0..i-1]` 的后缀与 `pattern` 前缀的最长相等长度」。失配回跳后重试同一 `cmp[i]`；命中则 `j++`；当 `j == m` 时**必须先计数再回跳** `j = pi[m-1]`，这样下一轮进入循环时 `j < m`，`pattern[j]` 访问天然不越界。
4. **重叠计数的正确姿势**：`j = pi[m-1]` 恰是「既是 `pattern` 前缀、又是刚匹配成功的文本后缀」的最长续接长度（见证明引理 2/3），它让下一个可重叠匹配不从头开始。
5. **均摊分析（为什么是线性）**：扫描过程中 $j$ 每处理一个字符至多增加 1，总增量 $\le n-1$；每次回跳 $j$ 严格减小且 $j \ge 0$，故回跳总次数 $\le$ 总增量。整体 $O(n)$。
6. **替代方案一：Z 函数拼接**。构造 $s = pattern + [2] + cmp$（分隔符 $2$ 不在 $\{-1,0,1\}$ 中，防止误匹配），求 Z 函数后统计 $z[i] = m$ 的位置数即为答案，同为 $O(n+m)$。
7. **替代方案二：滚动哈希**（官方标签）。把 $-1, 0, 1$ 映射到 $1, 2, 3$ 避免零值，双模数多项式哈希分别计算 `pattern` 与 `cmp` 每个长度为 $m$ 的窗口的哈希值，相等即计数。$O(n+m)$，但**单模数可被对抗数据卡掉**，建议双模数；无哈希冲突顾虑的 KMP 是更稳的选择。
8. **Python 性能**：纯 Python 的 KMP 循环约 $10^6$ 次迭代，LeetCode 的 Python 时限下可通过；把 `pattern`、`pi` 绑定为局部变量、避免切片可再快一截。**不要**用 `str.count`——它统计的是**非重叠**出现次数，本题会漏解。

## 5. 正确性证明

**引理 1（符号化等价）**：对任意起点 $i$，子数组 `nums[i..i+m]` 匹配 `pattern` $\iff$ 对每个 $k \in [0, m)$ 都有 $cmp[i+k] = pattern[k]$。

**证明**：`pattern[k]` 的三条规则分别要求相邻差 $d_k = nums[i+k+1] - nums[i+k]$ 为正、为零、为负，而 $\mathrm{sign}$ 恰把三者一一映射到 $1, 0, -1$，故「规则 $k$ 成立 $\iff cmp[i+k] = pattern[k]$」。对 $m$ 条规则取交即得。∎

**引理 2（border 链刻画）**：记 $B(j)$ 为「`pattern[0..j-1]` 的相等真前后缀长度」集合（含 $0$），则 $B(j) = \{j\} \cup B(\pi[j-1])$ 递归展开，即失配回跳链 $j \to \pi[j-1] \to \pi[\pi[j-1]-1] \to \cdots \to 0$ 恰按严格递减次序枚举 $B(j)$ 的全部元素。

**证明**：对 $\ell < j$，`pattern[0..ℓ-1]` 是 `pattern[0..j-1]` 的相等真前后缀 $\iff$ $\ell$ 是其 border 长度。对 border 长度 $\ell$，有 $\ell \le \pi[j-1]$（$\pi[j-1]$ 为最长）；反之任取 $\ell \in B(\pi[j-1])$，由前后缀的传递性（`pattern[0..ℓ-1]` 既是 `pattern[0..π[j-1]-1]` 的前缀，而后者是 `pattern[0..j-1]` 的前缀，故前者也是其前缀；后缀方向同理），$\ell$ 也是 `pattern[0..j-1]` 的 border。故 $B(j)$ 中 $< j$ 的部分恰为 $B(\pi[j-1])$，递归展开即得。∎

**引理 3（扫描不变量）**：设 $L(i) = \{\ell : pattern[0..\ell-1] = cmp[i-\ell+1..i]\}$（与文本后缀相等的 pattern 前缀长度集合，含 $\ell = 0$）。算法处理完文本位置 $i$ 后，$j = \max L(i)$。

**证明**：对 $i$ 归纳。$i = -1$ 时 $j = 0$ 成立。设处理完 $i-1$ 后 $j' = \max L(i-1)$。处理位置 $i$ 时，回跳循环从 $j'$ 出发沿 $\pi$ 链枚举 $B(j')$ 中元素，停在**最大**的满足 `pattern[ℓ] == cmp[i]` 的 $\ell \le j'$（若无则 $\ell = 0$），随后 $j = \ell + 1$。一方面 `pattern[0..ℓ] = cmp[i-ℓ..i]`，故 $j \in L(i)$；另一方面，若存在 $\ell'' \in L(i)$ 且 $\ell'' > j$，则 $\ell'' - 1 \in L(i-1)$ 且 `pattern[ℓ''-1] == cmp[i]`，由归纳 $j' = \max L(i-1) \ge \ell'' - 1 \ge j \ge \ell$，回跳链按递减序完整枚举了 $B(j') \supseteq L(i-1)$ 中所有 $< j'$ 的候选（引理 2），不可能跳过满足条件的 $\ell'' - 1$，矛盾。若 $j = m$（即 $m \in L(i)$），算法计数后置 $j = \pi[m-1]$：由引理 2 的传递性可证 $\pi[m-1] \in L(i)$，且 $L(i)$ 中介于 $\pi[m-1]$ 与 $m$ 之间的长度（若存在）是 `pattern` 的 border 长度，与 $\pi[m-1]$ 的最大性矛盾，故 $\pi[m-1] = \max(L(i) \setminus \{m\})$，对后续位置的归纳由此继续成立。∎

**定理**：算法返回值恰为匹配 `pattern` 的子数组数目。

**证明**：由引理 2 的窗口对应（长度 $m+1$ 的子数组与 `cmp` 中长度 $m$ 的窗口一一对应，起点集均为 $\{0, \ldots, n-m-1\}$）及引理 1，「子数组匹配」$\iff$「`cmp` 中对应窗口与 `pattern` 逐位相等」，即 `pattern` 在 `cmp` 中以该起点出现。由引理 3，每当某次匹配的结束位置 $i$（满足 $m \in L(i)$）被处理时，$j$ 恰达到 $m$，触发一次且仅一次计数；反之每次计数时 $j = m$ 意味着 `cmp[i-m+1..i] = pattern`，对应一个真实匹配。不同的结束位置互不相同，计数互不重复。故 `ans` 等于（可重叠）出现次数，即匹配子数组数目。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n + m)$。构建 `cmp` 为 $O(n)$；求 $\pi$ 均摊 $O(m)$；扫描 `cmp` 均摊 $O(n)$（$j$ 的总增量 $\le n-1$，回跳总量不超过增量）。$n = 10^6$ 时总计约 $2 \times 10^6$ 次基本操作。
- **空间复杂度**：$O(n)$。`cmp` 占 $n-1$ 个整数、$\pi$ 占 $m$ 个整数；C++ 下约 8 MB，符合题目内存限制。若追求 $O(m)$ 额外空间，可在扫描时现场计算 `sign` 而不显式存 `cmp`（一遍流式处理）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countMatchingSubarrays(vector<int>& nums, vector<int>& pattern) {
        int n = nums.size(), m = pattern.size();

        vector<int> cmp(n - 1);                       // 符号化：只保留大小关系
        for (int i = 0; i + 1 < n; i++) {
            int d = nums[i + 1] - nums[i];
            cmp[i] = (d > 0) - (d < 0);
        }

        vector<int> pi(m);                             // pattern 的前缀函数
        for (int i = 1; i < m; i++) {
            int j = pi[i - 1];
            while (j && pattern[i] != pattern[j]) j = pi[j - 1];
            if (pattern[i] == pattern[j]) j++;
            pi[i] = j;
        }

        int ans = 0;
        for (int i = 0, j = 0; i < n - 1; i++) {      // j：已匹配长度
            while (j && cmp[i] != pattern[j]) j = pi[j - 1];
            if (cmp[i] == pattern[j]) j++;
            if (j == m) {                             // 完整匹配一次
                ans++;
                j = pi[j - 1];                        // 关键：回跳到 border，支持重叠
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def countMatchingSubarrays(self, nums: List[int], pattern: List[int]) -> int:
        n, m = len(nums), len(pattern)
        cmp_arr = [(nums[i + 1] > nums[i]) - (nums[i + 1] < nums[i]) for i in range(n - 1)]

        pi = [0] * m
        j = 0
        for i in range(1, m):
            while j and pattern[i] != pattern[j]:
                j = pi[j - 1]
            if pattern[i] == pattern[j]:
                j += 1
            pi[i] = j

        ans = 0
        j = 0
        for c in cmp_arr:
            while j and c != pattern[j]:
                j = pi[j - 1]
            if c == pattern[j]:
                j += 1
            if j == m:
                ans += 1
                j = pi[j - 1]        # 回跳到 border，支持重叠
        return ans
```

## 8. 边界情况与易错点

1. **完整匹配后 `j = pi[m-1]`，绝不能重置为 0**：`cmp = [1,1,1,1]`、`pattern = [1,1]` 正确答案为 3，重置 0 只会得到 2（漏掉重叠窗口）。这是本题最致命的实现错误（见演算图对照实验）。
2. **先计数再回跳的顺序**：`j == m` 分支中先 `ans++` 再 `j = pi[j-1]`，保证下一轮 `j < m`，循环里 `pattern[j]` 的访问永不越界；若顺序颠倒或漏掉回跳，轻则越界、重则 WA。
3. **不要拿差值直接比较 `pattern`**：`nums[i+k+1] - nums[i+k] == pattern[k]` 是典型错误（差值可为 $\pm 5$ 等），必须先取符号（同 Q2）。
4. **Python 勿用 `str.count` / 勿迷信 `find` 循环**：`count` 统计非重叠出现，必漏重叠解；反复 `find(p, pos+1)` 在「文本与模式高度同值」的极端数据下也会退化（如全 1 配全 1）。
5. **溢出与答案类型**：$1 \le nums[i] \le 10^9$，相邻差绝对值 $< 10^9$，`int` 安全；答案上界 $n - m < 10^6$，`int` 足够——这与同场 385 Q4（对数高达 $5 \times 10^9$ 需要 `long long`）形成对比。
6. **内存**：`cmp` 与 `pi` 共约 $10^6$ 个整数，C++ 约 8 MB 无压力；Python 列表开销更大，若卡内存可改用数组逐段处理或现场计算符号。
7. **Z 函数拼接法的分隔符**：若用 `s = pattern + [2] + cmp`，分隔符必须取 $\{-1, 0, 1\}$ 之外的值（如 2），否则可能产生虚假匹配。
8. **哈希法防卡**：单模数滚动哈希可被构造数据针对，用双模数（组合超过 $10^{17}$ 量级）或直接用 KMP。
9. **$m < n$ 由题设保证**：`cmp` 至少长度 1，不存在空文本；`m = n - 1` 时仅一个窗口，扫描循环边界 `i < n - 1` 自然正确。
