# LeetCode 一手顺子 题解

## 1. 题目概述

- **标题 / 题号**：一手顺子（#846，medium）
- **链接**：https://leetcode.cn/problems/hand-of-straights/
- **来源**：LeetCode 第 87 场周赛 Q3
- **难度**：中等
- **标签**：贪心、数组、哈希表、排序

**题意**：给定整数数组 `hand`（`hand[i]` 是第 $i$ 张牌上的数字）与整数 `groupSize`。判断能否把全部牌重新排列成若干组，使得每组恰好 `groupSize` 张牌、且组内牌面是**连续整数**。

**约束**：

- $1 \le hand.length \le 10^4$
- $0 \le hand[i] \le 10^9$
- $1 \le groupSize \le hand.length$

> ⚠️ 题面末尾注明「此题目与 1296 重复」，两题解法完全一致，本文同样适用于 [1296. 划分数组为连续数字的集合](https://leetcode.cn/problems/divide-array-in-sets-of-k-consecutive-numbers/)。

## 2. 示例

**示例 1**

```text
输入：hand = [1,2,3,6,2,3,4,7,8], groupSize = 3
输出：true
解释：可以分成 [1,2,3]、[2,3,4]、[6,7,8] 三组，每组 3 张连续牌。
```

**示例 2**

```text
输入：hand = [1,2,3,4,5], groupSize = 4
输出：false
解释：5 张牌无法按每组 4 张分完（5 % 4 != 0），自然不可能。
```

**补充示例**

```text
输入：hand = [1,2,3,4,5], groupSize = 3
输出：false
解释：个数 5 不是 3 的倍数，先被数量整除性一票否决。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的想法是「枚举分组方案」：每次任选 `groupSize` 张牌，检查它们是否连续，递归下去。分支数是组合数量级，$n = 10^4$ 时完全不可行。即使只枚举「以某张牌为起点」的连续区间，也要面对「同一数值有多张副本、选哪一张」的排列组合。

真正的问题是：分组方案看起来有大量选择，是否存在一个**不需要搜索**的确定性构造？

### 3.2 核心观察：最小牌只能当「组内起点」

![最小的牌只能当组内起点，分组方式因此唯一](images/wc87_q3_greedy_concept.svg)

设当前剩余的牌中最小值为 $x$（出现 $c$ 次）。考察任意一个可行分组方案：

- 取其中包含某张 $x$ 的那一组 $G$；
- $G$ 内所有牌的值都 $\ge x$，且互不相同（连续整数），所以 $x$ 是 $G$ 的**最小值**，即 $x$ 必须是 $G$ 的起点；
- $G$ 由 `groupSize` 个连续整数组成且最小值为 $x$，于是

$$G = \{x,\ x+1,\ \dots,\ x+groupSize-1\}$$

**分组方式是唯一的**：$x$ 不能「搭便车」成为别人组里更大的牌，因为比它小的牌根本不存在。因此可以放心地贪心：每次取最小牌 $x$，强行扣掉 $x, x+1, \dots, x+g-1$ 各一张，重复直到牌用完；中途任何一张缺失就说明无解。

若 $x$ 有 $c$ 张副本，则可以一次性扣掉 $c$ 组（每张 $x$ 各领一组），减少重复扫描。

### 3.3 算法流程

![贪心流程：取最小剩余牌，批量扣减一整段连续值](images/wc87_q3_consume_flow.svg)

```text
1. 若 n % groupSize != 0：返回 false
2. 统计每个值的张数 cnt[x]（有序 map，或计数后对键排序）
3. 按值升序遍历 x（跳过 cnt[x] == 0）：
4.     c = cnt[x]
5.     对 k = 0 .. g-1：
6.         y = x + k
7.         若 y 不存在或 cnt[y] < c：返回 false
8.     对 k = 0 .. g-1：cnt[x+k] -= c      // 一次性扣掉 c 组
9. 所有值处理完：返回 true
```

### 3.4 示例演算

![示例演算：hand = [1,2,3,6,2,3,4,7,8]，groupSize = 3](images/wc87_q3_example_walkthrough.svg)

初始计数：

| 值 | 1 | 2 | 3 | 4 | 6 | 7 | 8 |
|----|---|---|---|---|---|---|---|
| 剩余张数 | 1 | 2 | 2 | 1 | 1 | 1 | 1 |

| 步骤 | 最小剩余 $x$ | $c$ | 扣减的值 | 扣减后剩余 | 结论 |
|------|--------------|-----|----------|-----------|------|
| 1 | 1 | 1 | 1, 2, 3 | 0,1,1,1,1,1,1 | 继续 |
| 2 | 2 | 1 | 2, 3, 4 | 0,0,0,0,1,1,1 | 继续 |
| 3 | 6 | 1 | 6, 7, 8 | 0,0,0,0,0,0,0 | true |

三步恰好对应示例中的三组 `[1,2,3]`、`[2,3,4]`、`[6,7,8]`。若把 `8` 换成 `9`（手牌 `6,7,9`），第 3 步检查 `6,7,8` 时发现 `8` 不存在，立即返回 `false`。

## 4. 算法细节

1. **批量扣减**：`cnt[x] = c` 时，$x$ 必须领 $c$ 组，于是 `x..x+g-1` 各减去 $c$。若逐张循环「找一次最小值扣一组」，最坏会变成 $O(n \cdot g)$ 次查找；批量扣减把每个起点的开销压成一次 $O(g)$ 的区间检查。
2. **有序性**：`std::map` 按 key 升序，Python 用 `Counter` 后对 `sorted(cnt)` 遍历。哈希表 + 排序亦可，但值域 $10^9$ 不能开桶数组。
3. **跳过已扣空的值**：扣减后 `cnt[x]` 会变成 0，遍历时必须跳过，否则会拿 0 做起点白跑一轮（`c = 0` 时逻辑上无害，但多花时间；C++ 用迭代器自动跳过更干净）。
4. **整除性先行**：`n % groupSize != 0` 必然无解，这一步 $O(1)$ 直接省掉大量无谓计算。
5. **值域与溢出**：`hand[i]` 最大 $10^9$，`x + k` 在 `int` 范围内（最多 $10^9 + 10^4$），无需 64 位；但如果题目把值域放大到 `INT_MAX`，就要改用 `long long`。
6. **与 1296 完全等价**：1296 要求分成「大小 $k$ 的连续数字集合」，本题要求「每组 $groupSize$ 张连续牌」，一字不差。

## 5. 正确性证明

**引理 1（最小值必为组内最小元素）**：设 $x$ 是当前剩余多重集的最小值，$G$ 是任意包含一张 $x$ 的组，则 $x = \min G$。

**证明**：$G$ 的每个元素都来自剩余牌，故都 $\ge x$；又 $G$ 内元素互不相同（连续整数），所以 $x$ 是其中唯一的严格最小值。∎

**引理 2（组内容唯一）**：若 $x = \min G$ 且 $|G| = g$、$G$ 为连续整数集合，则 $G = \{x, x+1, \dots, x+g-1\}$。

**证明**：$G$ 是 $g$ 个互不相同的连续整数，最小值为 $x$，故最大值只能是 $x+g-1$，中间不能跳过任何整数，于是 $G$ 恰为这条连续区间。∎

**引理 3（贪心扣除保持可行性）**：设 $x$ 为剩余多重集 $M$ 的最小值且 $M$ 中存在 $x..x+g-1$ 各至少一张。则 $M$ 可被划分为若干组当且仅当 $M' = M \setminus \{x, \dots, x+g-1\}$ 可被划分。

**证明**：

- （$\Leftarrow$）若 $M'$ 有合法划分，把 $\{x,\dots,x+g-1\}$ 作为额外一组加入，即得 $M$ 的合法划分。
- （$\Rightarrow$）若 $M$ 有合法划分 $\mathcal{P}$，取其中包含一张 $x$ 的组 $G$。由引理 1、2，$G = \{x,\dots,x+g-1\}$。从 $\mathcal{P}$ 中删去 $G$，剩下的组恰好构成 $M'$ 的合法划分。

∎

**引理 4（缺失即无解）**：若剩余多重集最小值为 $x$，但某个 $x+k$（$0 \le k < g$）不存在，则 $M$ 不可划分。

**证明**：反设 $M$ 可划分。包含 $x$ 的组 $G$ 由引理 1、2 必为 $\{x,\dots,x+g-1\}$，于是 $x+k \in G \subseteq M$，与「$x+k$ 不存在」矛盾。∎

**定理**：算法返回 `true` 当且仅当 `hand` 能被划分成若干连续组。

**证明**：

- **必要性**（返回 `true` 必有解）：算法每成功扣减一段 $x..x+g-1$，就相当于在构造方案里加入一组；由引理 3 的「$\Leftarrow$」方向，这些组加上剩余空集构成 `hand` 的一个合法划分。
- **充分性**（有解必返回 `true`）：若 `hand` 有解，归纳使用引理 3 的「$\Rightarrow$」方向：每一步都从某个合法划分中「摘掉」包含当前最小值的组，剩余多重集仍可划分。既然始终可划分，引理 4 保证任何一步都不会遇到缺失值，算法不会提前返回 `false`，且每步至少消耗 `groupSize` 张牌，最终必然处理完并返回 `true`。

两部分合起来即得结论。∎

> 说明：批量扣减 $c$ 组是引理 3 连续应用 $c$ 次的结果——每次扣减后最小值仍是 $x$（因为还剩 $c-1$ 张），故可一次性扣完。

## 6. 复杂度分析

- **时间**：$O(n \log n)$。计数建表 $O(n)$；若用 `map`，插入是 $O(n \log n)$；遍历各值并检查区间，内层总共执行 $\sum g \cdot (\text{起点数})$ 次。由于每个起点至少领走一组，起点数不超过 $n/g$，故内层总次数不超过 $n$，每次查找 $O(\log n)$，合计 $O(n \log n)$。
- **空间**：$O(D)$，$D$ 为不同牌面数量（$D \le n$）；另需返回/遍历用的有序键列表 $O(D)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool isNStraightHand(vector<int>& hand, int groupSize) {
        int n = (int)hand.size();
        if (n % groupSize != 0) return false;
        map<int, int> cnt;
        for (int x : hand) cnt[x]++;
        for (auto it = cnt.begin(); it != cnt.end(); ) {
            int c = it->second;
            if (c == 0) { ++it; continue; }
            int start = it->first;
            for (int k = 0; k < groupSize; k++) {
                auto jt = cnt.find(start + k);
                if (jt == cnt.end() || jt->second < c) return false;
                jt->second -= c;
            }
            while (it != cnt.end() && it->second == 0) ++it;
        }
        return true;
    }
};
```

### Python

```python
from collections import Counter

class Solution:
    def isNStraightHand(self, hand: list[int], groupSize: int) -> bool:
        n = len(hand)
        if n % groupSize != 0:
            return False
        cnt = Counter(hand)
        for x in sorted(cnt):
            c = cnt[x]
            if c == 0:
                continue
            for k in range(groupSize):
                y = x + k
                if cnt.get(y, 0) < c:
                    return False
                cnt[y] -= c
        return True
```

## 8. 边界情况与易错点

1. **`groupSize = 1`**：任何手牌都能每组一张，必然返回 `true`。代码中内层只检查 `cnt[x] >= c`（即自身），自然成立，不需要特判。
2. **`groupSize = n`**：只能分成一组，要求所有牌恰好是连续且互不相同；重复牌会在区间检查时露馅（例如 `[1,1,2]` 检查时 `cnt[1] = 2` 而其他值不足）。
3. **数量不整除**：如示例 2，`5 % 4 != 0`，必须先判，否则贪心可能在扣减中途误判。
4. **最小牌附近缺值**：`hand = [1,2,4]`、`g = 3` 时检查 `1,2,3` 发现 `3` 缺失 → `false`；`hand = [1,3,4]` 检查 `1,2,3` 发现 `2` 缺失 → `false`。
5. **重复牌过多**：`hand = [1,1,2,2,3]`、`g = 3`：$x=1, c=2$，需要 `1,2,3` 各两张，但 `3` 只有一张 → `false`。批量扣减的 `cnt[y] < c` 判定正是为此。
6. **值域大**：`hand[i]` 可达 $10^9$，不能开桶数组；必须哈希或 `map`。
7. **不要逐张扣减**：每次都重新找最小值会让复杂度退化到 $O(n^2 \log n)$，$n = 10^4$ 时明显变慢。
8. **扣减后指针推进**：C++ 用迭代器时，扣减会把 `it` 指向的值清零，必须连同后续被清零的键一起跳过，否则会在 0 上反复空转。
