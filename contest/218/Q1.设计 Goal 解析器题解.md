# LeetCode 设计 Goal 解析器 题解

## 1. 题目概述

- **标题 / 题号**：设计 Goal 解析器（#1678，easy）
- **链接**：https://leetcode.cn/problems/goal-parser-interpretation/
- **来源**：LeetCode 第 218 场周赛 Q1
- **难度**：简单
- **标签**：字符串、模拟

**题意**：字符串 `command` 由 `"G"`、`"()"`、`"(al)"` 三种 **token** 按某种顺序拼接而成（输入保证合法）。解析规则：`"G"` 解释为 `"G"`，`"()"` 解释为 `"o"`，`"(al)"` 解释为 `"al"`。把各 token 的解释结果**按原顺序连接**成一个字符串，返回它。

**约束**：

- $1 \le n \le 100$，其中 $n$ 为 `command` 的长度
- `command` 由 `"G"`、`"()"` 和/或 `"(al)"` 按某种顺序组成，**保证合法，无需判错**

> 💡 签到题的两条路：赛时最短路径是 `replace` 链一行收工；更值得沉淀的是「**首字符分发 + 1 个前瞻字符**」的单遍扫描——它正是编译原理里 lexer（词法分析器）的最小雏形。

## 2. 示例

**示例 1**

```text
输入：command = "G()(al)"
输出："Goal"
解释：G -> G，() -> o，(al) -> al，按原顺序连接得 "Goal"。
```

**示例 2**

```text
输入：command = "G()()()()(al)"
输出："Gooooal"
解释：4 个 "()" 各贡献一个 "o"。
```

**示例 3**

```text
输入：command = "(al)G(al)()()G"
输出："alGalooG"
```

**示例 4**（自拟，最小输入）

```text
输入：command = "G"
输出："G"
解释：单 token 情形，i 步进 +1 后越过末尾自然结束。
```

## 3. 解题思路

### 3.1 朴素思路：replace 链替换

按「字面 → 解释」逐个整体替换是最贴近题面的写法：

```python
command.replace("()", "o").replace("(al)", "al")
```

它之所以安全，依赖两个隐藏前提：

1. **token 互不包含**：合法串里每个 `(` 都是某个 token 的开头，`"()"` 只能作为完整的 `"()"` token 出现（`"(al)"` 内部与跨 token 边界都拼不出 `(` 紧跟 `)`）；
2. **替换产物不含括号**：`"o"`、`"al"` 不会再拼出新的 pattern。

于是两条 `replace` **顺序可换、互不干扰**，每条扫一遍即得答案。缺点是逻辑藏在库里、扫了两遍，而且上述前提一旦不成立就会连环误替换（见 §8）。

### 3.2 核心观察：首字符分发 + 1 个前瞻字符，token 唯一确定

三种 token 的**首字符即分流**：

- 首字符是 `G` → 只能是 `"G"`（另两种 token 均以 `(` 开头）；
- 首字符是 `(` → 再**前瞻 1 个字符**：是 `)` → `"()"`；是 `a` → `"(al)"`。

![首字符分发与前瞻判定](images/wc218_q1_token_dispatch_concept.svg)

关键在于这组 token **互不为前缀**：看清首字符 + 至多 1 个前瞻字符，当前 token 就唯一确定。于是下标 `i` **只前进、不回溯**，一个 `while` 循环加常数个分支就是全部逻辑——这就是把"整体替换"升级为"逐 token 翻译"的单遍扫描。

### 3.3 算法流程

![单遍扫描算法流程](images/wc218_q1_parse_flow.svg)

1. 置 `i = 0`，`ans` 为空；
2. 每轮看 `command[i]`：
   - `G` → 追加 `"G"`，`i += 1`；
   - `(` → 看 `command[i + 1]`：是 `)` → 追加 `"o"`，`i += 2`；是 `a` → 追加 `"al"`，`i += 4`；
3. `i` 越过末尾（$i \ge n$）时结束，返回 `ans`。

### 3.4 示例演算

![示例逐 token 演算](images/wc218_q1_walkthrough.svg)

以示例 1 的 `"G()(al)"` 与示例 3 的 `"(al)G(al)()()G"` 逐 token 走查：每一步消费一个 token、追加一段解释，`i` 按步长 $1/2/4$ 前进，恰好一遍扫完整串；6 个 token 的输入也是一遍结束，步进序列 $+4,+1,+4,+2,+2,+1$ 恰好加到 $n$。

## 4. 算法细节

1. **分支顺序**：先判 `G`（单字符、无前瞻、无越界风险），再进 `(` 分支做前瞻，写起来最短、最不容易错。
2. **前瞻的安全性**：合法性保证 `(` 不会是最后一个字符，故 `command[i + 1]` 必然在界内；若输入不保证合法，需先判 `i + 1 < n`。
3. **步进与 token 对应**：`"G"` → $+1$、`"()"` → $+2$、`"(al)"` → $+4$，步长恰为 token 长度，这是"消费一个 token"的直接体现。
4. **字符串拼接**：C++ 的 `ans += 'G'`（单字符）与 `ans += "al"`（字符串）要区分引号；Python 用列表暂存再 `"".join`，避免反复构造中间串（本题 $n \le 100$ 无所谓，属通用习惯）。
5. **别在 `for` 循环里改下标**：Python 的 `for i in range(n)` 中对 `i` 的赋值不影响迭代，必须用 `while`（见 §8）。

## 5. 正确性证明

**引理 1（起点匹配唯一性）**：对任意位置 $p$，`"G"`、`"()"`、`"(al)"` 三者中至多有一个能从 $p$ 开始匹配 `command`。

**证明**：`"()"` 与 `"(al)"` 均以 `(` 开头、`"G"` 以 `G` 开头。若 `command[p] == 'G'`，仅 `"G"` 可能匹配；若 `command[p] == '('`，`"()"` 要求 `command[p+1] == ')'` 而 `"(al)"` 要求 `command[p+1] == 'a'`，两条件互斥，至多一个成立；其他字符则全部不匹配。∎

**引理 2（token 分解唯一）**：合法的 `command` 划分为 token 序列的方式唯一。

**证明**：设存在两个划分 $T$ 与 $T'$，对 $k$ 归纳证明二者的前 $k$ 个 token 逐字相同、消费长度相同。$k = 0$ 平凡。设前 $k$ 个相同，则两划分的下一个 token 起点相同，记为 $p$。由 $T$ 合法，其第 $k{+}1$ 个 token 从 $p$ 开始匹配；由引理 1，从 $p$ 能匹配的 token 唯一，故 $T'$ 的第 $k{+}1$ 个 token 与之相同，消费长度亦相同。归纳完成。∎

**定理**：单遍扫描算法的输出恰为各 token 的解释按原顺序连接的结果，即题目所求。

**证明**：对循环轮数归纳：算法每轮处于当前起点 $p$，由引理 1 的判定规则恰好识别并消费唯一分解中从 $p$ 开始的那个 token，追加其解释串；归纳可知算法消费的 token 序列就是引理 2 的唯一分解。`i` 每轮严格增加且总增量为 $n$，循环必终止，且终止时恰好消费整串。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。`i` 只前进，每轮 $O(1)$ 分支判断与追加，总前进量恰为 $n$；`replace` 链做法扫两遍，仍为 $O(n)$。
- **空间复杂度**：除输出外 $O(1)$；输出本身 $O(n)$（`"G"` 原样保留、`"()"` 压成 `"o"`、`"(al)"` 压成 `"al"`，输出不超过 $n$）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    string interpret(string command) {
        string ans;
        int i = 0, n = command.size();
        while (i < n) {
            if (command[i] == 'G') {
                ans += 'G';
                i += 1;
            } else if (command[i + 1] == ')') {
                ans += 'o';
                i += 2;
            } else {
                ans += "al";
                i += 4;
            }
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def interpret(self, command: str) -> str:
        ans = []
        i, n = 0, len(command)
        while i < n:
            if command[i] == "G":
                ans.append("G")
                i += 1
            elif command[i + 1] == ")":
                ans.append("o")
                i += 2
            else:
                ans.append("al")
                i += 4
        return "".join(ans)
```

附（赛时一行版，依赖 §3.1 的"无重叠"前提）：

```python
class Solution:
    def interpret(self, command: str) -> str:
        return command.replace("()", "o").replace("(al)", "al")
```

## 8. 边界情况与易错点

1. **replace 顺序陷阱**：本题两条 `replace` 顺序可换（token 互不包含、产物 `"o"`/`"al"` 不含括号）。但一般情形下替换结果可能拼出新 pattern（例如把 `"()"` 替换成 `"(a)"`），replace 链就会连环误替换——可迁移的场景请用单遍扫描兜底。
2. **前瞻越界**：`command[i + 1]` 在 `(` 恰为最后一个字符时越界。本题合法性保证 `(` 不在串尾，可以放心；若输入不保证合法，须先判 `i + 1 < n`。
3. **步进写错**：`"(al)"` 消费 4 个字符，误写 `i += 2` 会把 `al)` 当作后续 token，轻则错解、重则死循环；三种步长 $1/2/4$ 与 token 一一对应。
4. **单字符输入**：`"G"` 一轮分支后 `i = 1` 越界结束，循环条件用 `i < n` 即可，无需特判。
5. **Python 的 for 循环改不了下标**：`for i in range(n)` 内部 `i += 4` 不影响下一次迭代取值，会重复处理中间字符，必须用 `while`。
6. **合法输入红利**：题目保证合法，所以三个分支是"二选一"而非"三选一"——`(` 分支看完 `command[i+1]` 即可二择其一。若放宽合法性，还需一个"都不匹配则报错"的兜底分支。
