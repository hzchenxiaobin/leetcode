# LeetCode 最小不兼容性 题解

## 1. 题目概述

- **标题 / 题号**：最小不兼容性（#1681，hard）
- **链接**：https://leetcode.cn/problems/minimum-incompatibility/
- **来源**：LeetCode 第 218 场周赛 Q4
- **难度**：困难
- **标签**：状态压缩、动态规划、位运算、子集枚举

**题意**：给定整数数组 `nums` 和整数 `k`（`n = len(nums)` 是 `k` 的倍数），把数组划分成 `k` 个**大小相同**（各 `m = n/k` 个）的子集，要求**同一个子集内不能有两个相同的元素**。每个子集的**不兼容性**定义为其中最大值与最小值之差。求所有子集不兼容性之和的**最小值**；无法划分时返回 `-1`。

**约束**：

- $1 \le k \le \text{nums.length} \le 16$
- `nums.length` 能被 `k` 整除
- $1 \le \text{nums}[i] \le \text{nums.length}$

> ⚠️ **赛时定位**：$n \le 16$ 是教科书级的**状压甜区**信号——$2^{16} = 65536$ 个状态随便枚举。本题的门槛在于能不能在赛时快速完成两步转化：**「已分配元素集合」编码为位掩码**、**「装一个完整的组」作为一步转移**。第二点没想到，就容易陷进逐元素 DFS 的泥潭。本场前三题都是模拟/套路题，Q4 的分差基本就落在这条观察上。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,1,4], k = 2
输出：4
解释：最优分配为 [1,2] 和 [1,4]，不兼容性和 = (2-1) + (4-1) = 4。
      [1,1] 和 [2,4] 的和更小，但第一个子集有重复元素，不可行。
```

**示例 2**

```text
输入：nums = [6,3,8,1,3,1,2,2], k = 4
输出：6
解释：最优分配为 [1,2]、[2,3]、[6,8]、[1,3]，
      不兼容性和 = (2-1) + (3-2) + (8-6) + (3-1) = 6。
```

**示例 3**

```text
输入：nums = [5,3,3,6,3,3], k = 3
输出：-1
解释：值 3 出现 4 次 > k = 3，无论怎么分都有一组含两个 3。
```

## 3. 解题思路

### 3.1 暴力思路：逐元素放组

最直接的搜索：把元素一个个放进 $k$ 个组之一，组满 $m$ 个封组，最终检查每组的值互异性并统计代价。搜索树最坏 $k^n$（不去重同构空组时）；即使利用「每组恰 $m$ 个」的约束剪枝，有序分组方案数也有

$$
\frac{n!}{(m!)^k} \;=\; \frac{16!}{(4!)^4} \approx 6.3 \times 10^7
$$

再乘上每组查重与算 $\max - \min$ 的开销，C++ 赛时勉强、Python 基本无望；而且同一「组集合」会被以多种装入顺序反复访问，大量重复劳动。

> 💡 转机在于换一个**原子操作**：不去想「一个元素放进哪个组」，而是「下一步**整个装满一个组**」。组内约束（大小 $m$、值互异、代价 $\max-\min$）只关乎组本身，与组外的世界无关——完全可以**预处理**出所有合法组，DP 时整组搬进搬出。

### 3.2 核心观察：位掩码编码 + 合法组整组装填

![核心观察：mask 编码已分配元素 + 一步填一个合法组](images/wc218_q4_bitmask_group_concept.svg)

**状态**：用 $n$ 位整数 `mask` 表示「已分配到某组的元素集合」——第 $i$ 位为 1 表示 `nums[i]` 已入组。设

$$
dp[\text{mask}] = \text{将 mask 中的元素分配完毕，已产生的最小不兼容性和}
$$

**合法组**：一个下标集合 $g$，满足 $|g| = m$ 且 $\{\text{nums}[i] : i \in g\}$ 互不相同；其代价 $\text{inc}[g] = \max - \min$ 可在预处理时一并算好。

**转移**：从 `mask` 出发，选一个与已分配元素不冲突的合法组 $g$（$g \cap \text{mask} = \emptyset$），则

$$
dp[\text{mask} \cup g] \;=\; \min\big(dp[\text{mask} \cup g],\;\; dp[\text{mask}] + \text{inc}[g]\big)
$$

> ⚠️ **去重关键：固定最低未选位**。若对每个 `mask` 枚举所有不冲突的合法组，同一个划分会被按 $k!$ 种组序重复展开。解决办法：取 $b = \text{ctz}(\lnot\text{mask})$（**最低的未分配下标**），只枚举**包含 $b$** 的合法组。$b$ 是剩余元素中最小的下标，任何划分中它必属于某个组——「下一个组必须含 $b$」不漏掉任何划分，同时把每种划分的展开顺序唯一化。
>
> 顺带一提：`min` 语义下重复展开本来也不会算错答案，只是白费时间；固定低位砍掉的是 $k!$ 倍的重复枚举，属于「提速不救命、但不提速容易 TLE」的优化。**不漏**才是正确性的命门，而这一点由「$b$ 必属某组」保证。

### 3.3 算法流程：预处理分桶 + 状压扫描

![算法流程：预处理合法组分桶 → 低位固定状压 DP](images/wc218_q4_dp_flow.svg)

**第 0 步 · 无解剪枝（充要）**：统计每个值的出现次数，若某值超过 $k$ 次，由鸽笼原理必有组含重复，直接返回 `-1`。

**阶段一 · 预处理合法组**：枚举所有大小为 $m$ 的下标子集，用 `seen` 位掩码查组内值重复，合法者计算 $\text{inc} = \max - \min$，并**按组内最低位分桶**存入 `groups[b]`。

**阶段二 · 状压 DP**：`dp[0] = 0`，其余为 $\infty$。`mask` 从 $0$ 递增扫到 $2^n - 1$：

1. 跳过 $dp[\text{mask}] = \infty$ 的不可达状态；
2. 求最低未选位 $b = \text{ctz}(\lnot\text{mask})$，只看桶 `groups[b]`；
3. 遍历桶内的 $(g, \text{inc})$，若 $g \,\&\, \text{mask} = 0$ 则更新 $dp[\text{mask} \cup g]$。

最终返回 $dp[2^n - 1]$；若仍为 $\infty$（无合法划分），返回 `-1`。

> 💡 **实际状态远少于 $2^n$**：可达 `mask` 的 popcount 必为 $m$ 的倍数（每次恰好装 $m$ 个元素）。以 $n=16, k=4$ 为例，可达状态仅 $C(16,0)+C(16,4)+C(16,8)+C(16,12)+C(16,16) \approx 1.7 \times 10^4$ 个。

### 3.4 示例演算

![示例 1 演算：合法组表与 DP 转移链](images/wc218_q4_walkthrough.svg)

取示例 1 `nums = [1,2,1,4], k = 2`（$n=4, m=2$）。

**预处理**（$C(4,2)=6$ 个候选组）：

| 下标对 | 值 | 判定 | inc | 桶 b |
|--------|-----|------|-----|------|
| {0,1} | {1,2} | 合法 | 1 | 0 |
| {0,2} | {1,1} | **重复，剔除** | — | — |
| {0,3} | {1,4} | 合法 | 3 | 0 |
| {1,2} | {2,1} | 合法 | 1 | 1 |
| {1,3} | {2,4} | 合法 | 2 | 1 |
| {2,3} | {1,4} | 合法 | 3 | 2 |

**DP 演化**：

| mask | dp | 最低未选位 b | 枚举组 g | 更新 |
|--------|-----|-------------|----------|------|
| 0000 | 0 | 0 | {0,1}，inc=1 | dp[0011] = 1 |
| 0000 | 0 | 0 | {0,3}，inc=3 | dp[1001] = 3 |
| 0011 | 1 | 2 | {2,3}，inc=3 | dp[1111] = 1+3 = 4 |
| 1001 | 3 | 1 | {1,2}，inc=1 | dp[1111] = min(4, 3+1) = 4 |
| 1001 | 3 | 1 | {1,3}，inc=2 | $g \,\&\, \text{mask} \ne 0$，**跳过**（下标 3 已用） |

其余 12 个 mask 全程 $\infty$。最终 $dp[1111] = 4$ ✓。

## 4. 算法细节

1. **`seen` 位掩码查重**：约束保证 $1 \le \text{nums}[i] \le n \le 16$，用整数的第 $v$ 位表示值 $v$ 是否已在组内：`seen & (1 << v)` 判重、`seen |= 1 << v` 标记，单次 $O(1)$，无需哈希表。
2. **按组内最低位分桶**：合法组 $g$ 存入 `groups[ctz(g)]`。DP 时由「最低未选位 $b$」直取桶 `groups[b]`，天然满足「组必须包含 $b$」——组 $g$ 的最低位是 $b$ 且 $g$ 与 mask 不交，恰是「含 $b$ 的可用组」的完整刻画。
3. **`ctz` 的两处使用要区分**：预处理时 `ctz(g)` 是**组的最低位**（决定进哪个桶）；DP 时 `ctz(rest)` 是**剩余元素的最低位**（决定看哪个桶）。两者语义不同、恰好对齐。
4. **`rest == 0` 要显式跳过**：`mask = full` 时无剩余元素，且 `__builtin_ctz(0)` 是**未定义行为**，这一行 `continue` 同时挡住逻辑死角与 UB。
5. **INF 与返回值**：`dp` 初值取 $10^9$；更新量级 $\le 15 \times 16 = 240$，`int` 毫无溢出风险。返回前判 `dp[full] >= INF` 则输出 `-1`（频次剪枝漏掉的情形由它兜底——事实上剪枝已充要，兜底只是防御式写法）。
6. **C++ 预处理的枚举方式**：直接 `for g in [0, 2^n)` 过滤 `popcount(g) == m`，总量 $2^{16} \times 16 \approx 10^6$，无需 `next_permutation` 或 DFS 生成组合；Python 端用 `itertools.combinations(range(n), m)` 更直观，两者等价。

## 5. 正确性证明

**引理 1（无解判定的充要性）**：存在合法划分 $\iff$ 每个值的出现次数 $\le k$。

**证明**：（$\Rightarrow$）$k$ 个组、每组内某值至多出现一次，故任何值至多出现 $k$ 次。（$\Leftarrow$）将全部元素按值排序，第 $i$ 个（从 0 计）放入组 $i \bmod k$。同一值的 $c \le k$ 个元素排序后占据连续位置，其下标模 $k$ 在连续 $c \le k$ 个值上**互不相同**，故落入不同组；又轮转使每组恰得 $n/k$ 个元素。构造合法。∎

**引理 2（规范序的存在性与唯一性）**：设 `mask` 可被一组互斥合法组 $\{g_1, \dots, g_t\}$ 装满。将组按**各自最小元素**升序排列，则该序列 $g_{(1)}, \dots, g_{(t)}$ 满足：装完前 $i-1$ 组后，剩余元素的最小元恰为 $\min g_{(i)}$。

**证明**：组两两不交，其最小元素互不相同，升序排列唯一。装完 $g_{(1)} \cup \cdots \cup g_{(i-1)}$ 后，剩余为 $g_{(i)} \cup \cdots \cup g_{(t)}$，其最小元 $= \min_{j \ge i} \min g_{(j)} = \min g_{(i)}$（升序保证）。∎

**引理 3（不重不漏的枚举）**：算法从每个可达 `mask` 只枚举含 $b = \text{ctz}(\lnot\text{mask})$ 的组，则每个「装满 full 的组集合划分」恰被算法沿其规范序生成一次，且每次更新 $dp[\text{mask} \cup g] \gets dp[\text{mask}] + \text{inc}[g]$ 中 $g$ 与 mask 的拼合都对应一个真实的划分前缀。

**证明**：由引理 2，规范序的每一步「下一个组」都含当时的最低未选位，故该序列确实在算法的枚举范围内；反之，算法的每一步都强制含最低未选位，由引理 2 的唯一性，任何生成序列都是某个组集合的规范序。两个方向合起来：组集合划分与算法生成序列一一对应。∎

**定理**：算法终止时，$dp[\text{full}]$ 等于最小不兼容性和；无合法划分时 $dp[\text{full}] = \infty$，算法返回 `-1`。

**证明**：对装入组数 $t$ 归纳，声称：对每个可由 $t$ 个互斥合法组装满的 mask，$dp[\text{mask}]$ 等于其最小总代价；对其余 mask，$dp[\text{mask}] = \infty$。

$t = 0$：仅 mask $= 0$，$dp[0] = 0$ 成立。

$t \ge 1$：设 mask 的最优划分为 $\{g_{(1)}, \dots, g_{(t)}\}$（规范序），前缀 $P_{t-1} = g_{(1)} \cup \cdots \cup g_{(t-1)}$。

- **可达性（$\le$ 方向）**：由归纳假设 $dp[P_{t-1}]$ 等于 $P_{t-1}$ 的最小代价。算法处理 $P_{t-1}$ 时最低未选位为 $\min g_{(t)}$（引理 2），枚举到组 $g_{(t)}$，且 $g_{(t)} \cap P_{t-1} = \emptyset$、$g_{(t)}$ 的桶号即其最低位 $\min g_{(t)}$，更新被执行，故 $dp[\text{mask}] \le dp[P_{t-1}] + \text{inc}[g_{(t)}]$。
- **最优性（$\ge$ 方向）**：$dp[\text{mask}]$ 的任何一次更新来自 $dp[\text{mask}'] + \text{inc}[g]$，其中 mask $= \text{mask}' \cup g$。由归纳，$dp[\text{mask}']$ 对应 mask $'$ 的一个真实划分，添上 $g$ 得 mask 的真实划分，代价恰为更新值，故 $dp[\text{mask}] \ge$ 最优。
- 两方向合并，再由引理 1，无解时任何 mask $=$ full 均不可达，$dp[\text{full}] = \infty$。∎

> 💡 **代价可加性是整个 DP 的地基**：总代价 $= \sum_g \text{inc}[g]$ 只依赖组集合本身，与组的装入顺序、组的名义编号都无关——所以「前缀最优 + 最后一组」的分解才是无损的。

## 6. 复杂度分析

- **时间复杂度**：$O\!\big(2^n \cdot \binom{n-1}{m-1}\big)$
  - 预处理：枚举 $2^n$ 个掩码、每个 $O(n)$ 检查，共 $O(2^n \cdot n) \approx 10^6$；
  - DP：每个可达 mask 只访问桶 `groups[b]`，桶大小至多 $\binom{n-1}{m-1}$（含固定最低位 $b$ 的 $m$ 元组数）；
  - 最坏参数是 $k = 2, m = 8$：可达状态 $1 + \binom{16}{8} + 1 = 12872$ 个，每状态至多枚举 $\binom{15}{7} = 6435$ 组，上界约 $8 \times 10^7$；考虑到 `g & mask ≠ 0` 的快速跳过与桶实际规模，真实运算量远低于上界，C++ 轻松、Python 可过。
- **空间复杂度**：$O\!\big(2^n + \binom{n}{m}\big)$——dp 数组 $2^n$，所有合法组共 $\binom{n}{m}$ 个（$n = 16$ 时至多 $12870$ 个）。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minimumIncompatibility(vector<int>& nums, int k) {
        int n = nums.size(), m = n / k;

        // 第 0 步：某值出现 > k 次，鸽笼上必有组含重复，直接无解
        int cnt[17] = {};
        for (int x : nums) cnt[x]++;
        for (int v = 1; v <= n; v++)
            if (cnt[v] > k) return -1;

        const int INF = 1e9;
        int full = (1 << n) - 1;
        vector<int> dp(1 << n, INF);
        dp[0] = 0;

        // 阶段一：预处理大小 m、值互异的合法组，按组内最低位分桶
        vector<vector<pair<int,int>>> groups(n);   // groups[b] = {(组掩码, inc)}
        for (int g = 0; g <= full; g++) {
            if (__builtin_popcount(g) != m) continue;
            int seen = 0, mn = n + 1, mx = 0;      // seen：值查重位掩码
            bool ok = true;
            for (int i = 0; i < n && ok; i++) {
                if (!(g >> i & 1)) continue;
                int v = nums[i];
                if (seen >> v & 1) ok = false;     // 组内值重复，整组作废
                else {
                    seen |= 1 << v;
                    mn = min(mn, v);
                    mx = max(mx, v);
                }
            }
            if (ok) groups[__builtin_ctz(g)].push_back({g, mx - mn});
        }

        // 阶段二：低位固定的状压 DP
        for (int mask = 0; mask <= full; mask++) {
            if (dp[mask] >= INF) continue;          // 不可达状态，跳过
            int rest = full ^ mask;
            if (rest == 0) continue;                // 已装满；也避开 ctz(0) 的 UB
            int b = __builtin_ctz(rest);            // 最低未选位：下一组必须含它
            for (auto& [g, inc] : groups[b]) {
                if (g & mask) continue;             // 组内元素已被用过
                dp[mask | g] = min(dp[mask | g], dp[mask] + inc);
            }
        }
        return dp[full] >= INF ? -1 : dp[full];
    }
};
```

### Python

```python
class Solution:
    def minimumIncompatibility(self, nums: List[int], k: int) -> int:
        n = len(nums)
        m = n // k

        # 第 0 步：某值出现 > k 次，直接无解
        if max(Counter(nums).values()) > k:
            return -1

        full = (1 << n) - 1
        INF = float('inf')
        dp = [INF] * (1 << n)
        dp[0] = 0

        # 阶段一：预处理合法组，按组内最低位分桶
        groups = defaultdict(list)                 # groups[b] = [(组掩码, inc)]
        for combo in combinations(range(n), m):    # combo 按下标升序
            vals = {nums[i] for i in combo}
            if len(vals) == m:                     # 值互异才是合法组
                g = 0
                for i in combo:
                    g |= 1 << i
                groups[combo[0]].append((g, max(vals) - min(vals)))

        # 阶段二：低位固定的状压 DP
        for mask in range(1 << n):
            if dp[mask] == INF:
                continue
            rest = full ^ mask
            if rest == 0:
                continue
            b = (rest & -rest).bit_length() - 1    # 最低未选位，等价 ctz
            for g, inc in groups[b]:
                if g & mask == 0:
                    nm = mask | g
                    if dp[mask] + inc < dp[nm]:
                        dp[nm] = dp[mask] + inc

        return dp[full] if dp[full] < INF else -1
```

## 8. 边界情况与易错点

1. **$k = n$（$m = 1$）**：每组单元素，恒无重复，所有 inc $= 0$，答案必为 $0$；代码无需特判，预处理自动产出 $n$ 个单元素组。
2. **$k = 1$（$m = n$）**：全数组是一组，要求所有元素互异；不满足时被频次剪枝拦下（某值出现 $\ge 2 > 1$ 次）。
3. **无解兜底**：不写第 0 步剪枝也能对——DP 结束时 $dp[\text{full}] = \infty$，返回 `-1`。剪枝的意义是省时间与提前退出，正确性不依赖它。
4. **`ctz(0)` 是 UB**：C++ 中 `rest == 0` 必须先 `continue`；Python 的 `(rest & -rest).bit_length() - 1` 在 `rest = 0` 时同样无意义，逻辑上必须先挡。
5. **桶号与锚点混用**：预处理 `ctz(g)`（组的最低位）与 DP `ctz(rest)`（剩余的最低位）是两个概念，写反或混用会导致枚举不全、答案偏大。
6. **忘记「大小恰为 $m$」**：预处理过滤 `popcount(g) == m` 是组合法性的第一半，漏了会拼出大小不齐的「划分」。
7. **查重位掩码的值域前提**：`1 << v` 依赖 $1 \le \text{nums}[i] \le n \le 16$；若值域放大（本题不会），需换哈希查重。
8. **INF 判别**：C++ 里用 `>= INF` 而非 `== INF` 更防御（防止将来把 INF 初值改动后判别失效）；更新量 $\le 240$，`int` 无溢出之忧。
9. **dp 数组开 $1 \ll n$ 而非 $1 \ll 16$**：$n$ 更小时省内存，也让循环边界自洽。

- [LeetCode 1655. 分配重复整数](https://leetcode.cn/problems/distribute-repeating-integers/)：同款子集状压，`mask` 编码的是「已满足的顾客集合」，与本题同构不同向。
- [LeetCode 2305. 公平分发饼干](https://leetcode.cn/problems/fair-distribution-of-cookies/)：逐人装填的状压 DP，可与本题对照「装组」与「装箱」两种视角。
- 本仓库 `solution/1601-1700/` 内有本题的每日题解版本，偏面试视角（含贪心反例、DFS 回溯对照），可与本文的证明线互补。

**延伸思考**：

- **$O(3^n)$ 写法**：也可不预处理合法组，直接 $dp[\text{mask}] = \min_{s}$（$s \subseteq \text{mask}$，$|s| = m$，值互异，$s \ni \text{ctz}(\text{mask})$）$dp[\text{mask} \setminus s] + \text{inc}(s)$，用子集枚举实现，总量 $3^{16} \approx 4.3 \times 10^7$。与分桶法本质相同，分桶法把「枚举子集」离线成了桶，常数更小。
- **值域放大**：若 $1 \le \text{nums}[i] \le 10^9$，`seen` 位掩码查重失效，预处理改用排序/哈希即可，DP 部分不受影响——位掩码只编码**下标**，不编码**值**。
- **输出具体方案**：dp 增记前驱 $(\text{mask}, g)$，回溯 $dp[\text{full}]$ 即得每组元素；状压题通用的改法。
- **m = 2 特例**：每组恰两个互异值、代价为差。排序后相邻配对直觉上最优，但重复值的存在使配对必须跨「值段」错开，正确性需要交换论证——可作为一个不错的练习：先猜结论，再找反例或证明。
