# LeetCode 寻找重复的子树 题解

## 1. 题目概述

- **标题 / 题号**：寻找重复的子树（#652，medium）
- **链接**：https://leetcode.cn/problems/find-duplicate-subtrees/
- **来源**：LeetCode 第 43 场周赛 Q1
- **难度**：中等
- **标签**：树、深度优先搜索、哈希表、二叉树

**题意**：给定一棵二叉树的根 `root`，返回所有**重复的子树**。若两棵子树**结构完全相同**（对应位置的孩子是否存在一致）且**对应结点的值完全相同**，就称二者重复。同一个重复等价类里有多个根结点时，只返回其中任意**一个**即可，答案不能出现两个同类的代表。

**约束**：

- 结点数 $1 \le n \le 5000$
- $-200 \le Node.val \le 200$

> 💡 作为周赛第一题，快速切入的路径是：题目问的是「哪些子树彼此相同」，那么第一件事就是给「一棵子树」设计一个**可比较的指纹**。指纹设计得好，判重就从「两两比对」退化成「一次哈希」。

## 2. 示例

**示例 1**

```text
输入：root = [1,2,3,4,null,2,4,null,null,4]
输出：[[2,4],[4]]
解释：根 1 的左孩子是 2（挂着孩子 4）；右孩子 3 的左孩子同样是「2 挂着孩子 4」，
      这两棵子树结构与值完全相同，重复；值为 4 的叶子一共出现 3 次，也重复。
      答案为两个代表：一棵「2 挂着 4」，一个叶子 4。
```

**示例 2**

```text
输入：root = [2,1,1]
输出：[[1]]
解释：两个叶子 1 构成同一个重复等价类，只需返回其中一个（返回哪一个都算对）。
```

**示例 3**

```text
输入：root = [2,2,2,3,null,3,null]
输出：[[2,3],[3]]
解释：根的两个孩子都是「2 带一个左孩子 3」，两棵子树结构与值完全相同；
      两个值为 3 的叶子也重复。根部那个 2 带着两个孩子，和只带一个孩子的 2 并不相同。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是「两两比较」：枚举所有结点对 $(u, v)$，写一个 `same(u, v)` 递归判断两棵子树是否相同。$O(n^2)$ 对结点，每对最坏要走到 $O(n)$ 层，总复杂度 $O(n^3)$；$n = 5000$ 时约 $1.25\times10^{11}$ 次访问，完全不可行。

退一步的「次优解」是给每棵子树做**字符串序列化**（如 `(2(4)(#))`），再用哈希表统计频次。思路已经对了，但每次拼接字符串的代价等于子树大小：链状树上第 $i$ 层要拼长度 $i$ 的串，总代价 $O(n^2)$，$n = 5000$ 时约 $1.25\times10^7$ 个字符，既慢又吃内存，而且在 C++ 里还要小心字符串比较的开销。

> 关键痛点：我们不需要知道两棵子树「长什么样」，只需要知道它们「是否一样」。**把子树压缩成一个整数**，比较就变成 $O(1)$ 的整数比较。

### 3.2 核心观察：子树 = 三元组 (val, 左子树编号, 右子树编号)

![把整棵子树压成一个整数编号](images/wc43_q1_subtree_key.svg)

**观察**：一棵子树由三件事完全决定——根的值、左子树、右子树。如果左、右子树**各自已经有了一个整数编号**，那么三元组

$$\text{key} = (\text{val},\ \text{id}(\text{left}),\ \text{id}(\text{right}))$$

就唯一确定了这棵子树。于是可以维护一张字典「三元组 → 编号」，遇到同样的三元组就复用旧编号，否则分配一个新编号：

- 空子树统一用**编号 0**（哨兵，天然表示「不存在」）；
- 编号相同 $\iff$ 子树结构与结点值都相同，判别只剩一次整数比较；
- 这与编译原理里的 **hash-consing（结构驻留）** 是同一个技巧，也叫「树哈希 / 结构指纹」。

因为要先知道左右子树的编号，所以遍历顺序必须是**后序**：孩子先处理完，再处理自己。

> ⚠️ 常见误区：用「结点值」或「子树高度」当指纹。值相同的子树可能结构不同（示例 3 里根部的 2 与它孩子那两个 2 就不是同一棵子树）；高度相同的更多。指纹必须**递归地包含整棵子树的信息**。

### 3.3 算法流程

![算法流程：一次后序遍历 + 一张字典](images/wc43_q1_postorder_flow.svg)

1. 字典 `ids` 保存「三元组 → 编号」，数组 `cnt` 记录每个编号出现的次数，`cnt[0]` 空闲不用（0 号是空子树）。
2. 后序 DFS：`dfs(node)` 返回以 `node` 为根的子树的编号。
3. 进入结点后先递归两个孩子（空结点直接返回 0），拿到左右子树的编号 `lid`、`rid`。
4. 组装 `key = (node.val, lid, rid)`，在 `ids` 里查：没有就分配新编号 `id = len(cnt)` 并登记；有就取出旧编号。
5. `cnt[id] += 1`，若恰好变成 **2**，说明这是该等价类第二次出现，把当前结点加入答案。
6. DFS 结束返回 `id`，最终返回答案列表。

### 3.4 示例演算

![示例 1 的后序编号与收集过程](images/wc43_q1_example_walkthrough.svg)

以示例 1 的树 `[1,2,3,4,null,2,4,null,null,4]` 为例，后序访问顺序是 `4, 2, 4, 2, 4, 3, 1`：

| 步 | 值 | 键 | 编号 | 计数 | 动作 |
|----|----|----|------|------|------|
| 1 | 4 | (4, #0, #0) | #1 | 1 | 分配 |
| 2 | 2 | (2, #1, #0) | #2 | 1 | 分配 |
| 3 | 4 | (4, #0, #0) | #1 | 2 | **收集** |
| 4 | 2 | (2, #1, #0) | #2 | 2 | **收集** |
| 5 | 4 | (4, #0, #0) | #1 | 3 | 跳过 |
| 6 | 3 | (3, #2, #1) | #3 | 1 | 分配 |
| 7 | 1 | (1, #2, #3) | #4 | 1 | 分配 |

第 3、4 步分别触发两个等价类的第二次出现，答案 `[[2,4],[4]]`；第 5 步的 `#1` 已经是第三次出现，**不能再收集**，否则会重复输出。

## 4. 算法细节

1. **顺序必须是后序**：三元组里的两个编号来自孩子，孩子没编号完就没法组装自己的键。前序 / 中序都会拿到「尚未计算」的孩子编号。
2. **编号 0 作哨兵**：空子树不需要真的建结点，统一映射到 0，`cnt` 的下标 0 保留不用；这样叶子结点的键自然是 `(val, 0, 0)`，省掉所有空指针特判。
3. **只在 `cnt[id] == 2` 时收集**：用 `== 2`（而不是 `>= 2`）保证每个等价类只被收集一次，同时天然满足「每个重复类返回任意一棵」的要求。
4. **键的两种写法**：Python 直接拿元组 `(val, lid, rid)` 当字典键；C++ 用 `unordered_map` 时可以把三元组打包成一个 `long long`：编号 $\le n \le 5000 < 8192$，值 $+200$ 后落在 $[0,400]$，取 $B = 8192 > 5000$ 就有
   $$\text{key} = \bigl((\text{val}+200)\cdot B + \text{lid}\bigr)\cdot B + \text{rid},$$
   该映射是**单射**：$B$ 大于编号最大值，低位不会进位串位，不同三元组不会撞成同一个键（最大约 $2.7\times10^{10}$，`long long` 富余）。
5. **不要真的建树 / 不要真的拼串**：编号方案里每个结点只做一次常数规模的字典操作，不存在任何长度与子树规模相关的拷贝。
6. **递归深度**：$n \le 5000$，链状树深度可达 5000，Python 默认递归上限 1000 会 `RecursionError`，必须 `sys.setrecursionlimit(10000)`；C++ 的栈一般够用，但也可以用显式栈的迭代后序更稳。
7. **答案里放的是结点**：`ans.append(node)` 存的是原结点指针，不是编号；最后按题目要求返回 `TreeNode*` 列表，顺序任意。

## 5. 正确性证明

**引理 1（编号是子树的完备指纹）**：对任意两个结点 $u, v$，`dfs` 返回的编号相同 $\iff$ 以 $u$ 为根的子树与以 $v$ 为根的子树结构和结点值都相同。

**证明**：对子树高度归纳（约定空子树高度为 $-1$，叶子高度为 $0$）。高度为 $-1$ 时两边编号都是 0，都为空，成立。设高度 $< h$ 时命题成立，取高度为 $h$ 的 $u, v$：其孩子的子树高度都 $< h$，由归纳假设，`lid` 相等 $\iff$ 左子树相同，`rid` 相等 $\iff$ 右子树相同。

- ($\Leftarrow$) 若两棵子树相同，则根值相同、左右子树分别相同，由归纳假设孩子编号对应相等，故三元组相同；三元组相同必然命中同一个字典条目，返回同一编号。
- ($\Rightarrow$) 若返回编号相同，则二者由同一个三元组生成（字典里一个编号只对应一个键），即根值相同、左右孩子编号相同；再由归纳假设左右子树相同，故整棵子树相同。∎

**引理 2（编号与等价类一一对应）**：字典 `ids` 中每个键只分配一次编号，不同键的编号互不相同，因此「编号」与「子树等价类」构成双射。

**证明**：编号只在 `ids.find(key)` 失败时按 `len(cnt)` 递增分配并立即登记，同一个键第二次不会再分配；不同键分配时取到的 `len(cnt)` 各不相同，故编号互异。结合引理 1 即得双射。∎

**引理 3（收集的时机与唯一性）**：后序遍历中，某个等价类的编号第 2 次被 `+= 1` 时，当前结点就是该类的一个代表；且该类只在此刻被收集一次。

**证明**：`cnt[id]` 是编号 `id` 在后序遍历中已被访问的次数，每次访问恰好加 1，故它从 1 开始严格递增，`cnt[id] == 2` 恰好在第二次出现时成立一次，此后永远 $>2$，不会再次触发收集。被收集的结点确实属于该类（它本次访问的编号就是 `id`）。∎

**定理**：算法返回的列表恰好包含每个重复子树等价类的一个代表，且不含非重复子树。

**证明**：设等价类 $C$ 的结点数 $k \ge 2$，由引理 2 它有唯一编号，由引理 3 它在第 2 次出现时被收集且仅收集一次，收集的结点属于 $C$，故 $C$ 恰好贡献一个代表，且返回的结点确实重复。反之，返回的结点其编号计数达到过 2，说明该类至少有两个结点，确为重复。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$（期望）。每个结点访问一次，做两次递归调用、一次三元组查表 / 插入、一次计数与比较；哈希表操作期望 $O(1)$。最坏情况（哈希碰撞退化）为 $O(n^2)$，但键的取值空间是 $O(n^3)$ 量级且分布均匀，实际不可能触发。
- **空间复杂度**：$O(n)$。字典至多 $n+1$ 个条目（含空子树），`cnt` 数组同规模，答案列表至多 $n/2$ 项，递归栈深度最坏 $O(n)$（链状树）。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    vector<TreeNode*> findDuplicateSubtrees(TreeNode* root) {
        unordered_map<long long, int> ids;   // 三元组 -> 子树编号
        vector<int> cnt(1, 0);               // cnt[id]；0 号留给空子树
        vector<TreeNode*> ans;
        ids.reserve(8192);
        dfs(root, ids, cnt, ans);
        return ans;
    }

private:
    int dfs(TreeNode* node, unordered_map<long long, int>& ids,
            vector<int>& cnt, vector<TreeNode*>& ans) {
        if (!node) return 0;                       // 空子树固定编号 0
        int lid = dfs(node->left, ids, cnt, ans);  // 后序：先拿孩子编号
        int rid = dfs(node->right, ids, cnt, ans);
        const long long B = 8192;                  // B > 最大编号 5000
        long long key = ((long long)(node->val + 200) * B + lid) * B + rid;

        auto it = ids.find(key);
        int id;
        if (it == ids.end()) {                     // 第一次见到这种子树
            id = (int)cnt.size();
            ids[key] = id;
            cnt.push_back(0);
        } else {
            id = it->second;                       // 复用旧编号
        }
        if (++cnt[id] == 2) ans.push_back(node);    // 第二次出现：收集
        return id;
    }
};
```

### Python

```python
import sys


class Solution:
    def findDuplicateSubtrees(self, root: Optional[TreeNode]) -> List[Optional[TreeNode]]:
        sys.setrecursionlimit(10000)      # n <= 5000，链状树会超过默认深度
        ids = {}                          # (val, lid, rid) -> 子树编号
        cnt = [0]                         # cnt[id]，0 号固定代表空子树
        ans = []

        def dfs(node):
            if node is None:
                return 0                  # 空子树编号 0
            lid = dfs(node.left)
            rid = dfs(node.right)
            key = (node.val, lid, rid)    # 后序：孩子编号已就绪
            i = ids.get(key)
            if i is None:                 # 新形态，分配编号
                i = len(cnt)
                ids[key] = i
                cnt.append(0)
            cnt[i] += 1
            if cnt[i] == 2:               # 第二次出现，收集且只收集一次
                ans.append(node)
            return i

        dfs(root)
        return ans
```

## 8. 边界情况与易错点

1. **没有重复**：单结点 `[1]` 或所有子树形态各异时返回空列表，不要返回 `[None]` 或把根结点塞进去。
2. **值相同但不等价**：`[1,1,null,1,null,1,null]` 这种同值链，每条子树长度不同、互不相同，答案应为空列表；只用结点值当指纹会误判成重复。
3. **`cnt == 2` 而非 `>= 2`**：示例 1 中叶子 4 出现 3 次，若写成 `>= 2` 会重复收集，输出里出现两个 `[4]`，答案条数不符。
4. **递归深度**：$n = 5000$ 的链状树深度可达 5000，Python 必须抬高递归上限；若评测环境限制栈，改写显式栈的后序迭代（压栈时记录访问标记）。
5. **键的打包必须单射**：C++ 取 $B = 8192$，正是因为编号最大只有 5000；若图省事取 $B = 1000$，$(\text{val}, 2, 1010)$ 与 $(\text{val}, 3, 10)$ 会算出同一个键——`rid` 一旦超过 $B$，进位就会串位。取值上界变了必须同步调大 $B$。
6. **返回值类型**：题目要的是结点指针列表而不是编号列表；收集时保存 `node`，注意不要保存局部的编号或拷贝出来的值。
7. **字典只增不减**：不同形态的子树至多 $n+1$ 种，编号空间有限，不需要清理；`reserve` 一次可避免 rehash。

**延伸思考**：

- 若要求返回**所有**出现位置（不只每个类一个代表），只需把 `cnt[id] == 2` 改成把结点按编号分组，最后输出每个编号的完整结点列表。
- 若要求「恰好出现 $k$ 次的子树」，收集条件改为 `cnt[id] == k` 即可，复杂度不变。
- 若把「结构相同」放宽为**同构**（允许左右孩子互换），三元组方案失效，需要改用 AHU 算法：先把子树按「孩子编号排序后的多重集」规范化，再取最小表示，仍是 $O(n \log n)$ 级别。
- $n$ 放到 $10^5$ 时递归会爆栈，改成显式栈的迭代后序遍历；字典换成手写哈希表可以进一步压常数。
