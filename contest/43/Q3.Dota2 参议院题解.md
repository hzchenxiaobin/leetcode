# LeetCode Dota2 参议院 题解

## 1. 题目概述

- **标题 / 题号**：Dota2 参议院（#649，medium）
- **链接**：https://leetcode.cn/problems/dota2-senate/
- **来源**：LeetCode 第 43 场周赛 Q3
- **难度**：中等
- **标签**：贪心、队列、字符串

**题意**：`senate` 的第 $i$ 个字符表示第 $i$ 位参议员属于 Radiant（`'R'`）还是 Dire（`'D'`）。投票按轮进行，每轮从下标 $0$ 走到 $n-1$，轮到一位**仍有权利**的参议员时，他可以二选一：

1. **剥夺**另一名参议员的权利——该参议员在本轮及之后所有轮次都失去投票权，被永久跳过；
2. **宣布胜利**——仅当他发现所有仍有权利的参议员都和自己同阵营时可行。

双方都最优行动，求最终宣布胜利的阵营（`"Radiant"` 或 `"Dire"`）。

**约束**：

- $1 \le n \le 10^4$，其中 $n = \lvert \texttt{senate} \rvert$
- `senate[i]` 只能是 `'R'` 或 `'D'`

## 2. 示例

**示例 1**

```text
输入：senate = "RD"
输出："Radiant"
解释：第 1 轮，Radiant 参议员（下标 0）行使剥夺权，ban 掉下标 1 的 Dire 参议员；
      该参议员本轮被跳过；第 2 轮，Radiant 参议员是唯一有权利者，宣布胜利。
```

**示例 2**

```text
输入：senate = "RDD"
输出："Dire"
解释：第 1 轮，R（下标 0）ban 掉 D（下标 1）；
      同一个第 1 轮里，D（下标 2）随后 ban 掉 R（下标 0）；
      第 2 轮只剩 D（下标 2）有权利，Dire 宣布胜利。
```

> 💡 示例 2 是全题的关键：**先 ban 掉一个对手，并不能让对手阵营在后面槽位的人闭嘴**——D（下标 2）本轮照样开口反杀。所以“先手”并不天然等于优势，必须精确到“谁在哪个时刻开口”。

## 3. 解题思路

### 3.1 暴力思路

直接按题面模拟：用 `alive` 数组标记谁还有权利，每轮从 $0$ 扫到 $n-1$；轮到活人时，如果他还有对手，就**环形向后找最近的活着的对手**把他 ban 掉。

每轮 $O(n)$，而每轮至少 ban 掉一个人，所以最多 $n$ 轮，总复杂度 $O(n^2)$。$n = 10^4$ 时约 $10^8$ 次操作——C++ 常数小勉强能过，Python 很险。但真正的麻烦不在常数：**“找最近的对手”每次都要绕圈扫**，写起来又长又容易错。而且暴力法没有沉淀出任何可复用的结构。

### 3.2 核心观察：ban 掉“下一个开口的对手”

![两条队列对撞：下标小的先出手](images/wc43_q3_duel_queue.svg)

两个观察把问题一刀切开：

1. **能 ban 就一定要 ban**。只要对手阵营还有人，第 2 项权利（宣布胜利）就不成立；手上这一票唯一的用处就是剥夺一名对手的权利。放弃 ban 等于白送对手一次机会，绝不可能更优。
2. **要 ban 就 ban“最近的那个对手”**。对手阵营里“下一个要开口的人”威胁最大——他一开口就要 ban 掉我方一名参议员。先把他除掉，剩下的对手行动时刻只会更晚，我方被 ban 的风险只会更小。

有了这两条，整局游戏不再需要“轮”这个概念：每位参议员只需要记住**自己下一次行动的时刻**，谁的时刻小谁先开口——这正是把“轮”折叠成一条时间轴的思路。

### 3.3 算法流程：两条队列 + 下标加 $n$

![算法流程：两条队列模拟决斗](images/wc43_q3_algorithm_flow.svg)

把 senator $i$ 的候选行动时刻写成

$$i,\quad i+n,\quad i+2n,\quad \dots$$

（第 $k$ 轮里下标 $i$ 的槽位就是 $k n + i$）。于是每个阵营维护一条**升序队列**，队列里存的是本方“尚未消费的下一次行动时刻”：

1. 初始化：扫描 `senate`，`'R'` 的下标入 R 队，`'D'` 的下标入 D 队。
2. 只要两队都非空，各弹出队首 $r$、$d$。
3. $r < d$：R 先开口，ban 掉 D 队首那位（他永久出局），R 自己的下次时刻改为 $r + n$ 并**从队尾入队**；否则对称处理。
4. 某队被弹空 ⇒ 该阵营全员失去权利 ⇒ 对面宣布胜利。

这里 $r+n$ 的含义是“同一个人，等下一轮再开口”；由于两队始终升序，队首比较就等价于“谁先动口”。

### 3.4 示例演算

![示例演算：senate = "RDDR"](images/wc43_q3_example_walkthrough.svg)

以 `senate = "RDDR"`（$n = 4$）为例，初始 R 队 $=[0, 3]$、D 队 $=[1, 2]$：

| 步骤 | 弹出 $(r, d)$ | 比较 | 谁 ban 谁 | 之后 R 队 | 之后 D 队 |
|------|---------------|------|-----------|-----------|-----------|
| ① | $(0, 1)$ | $0 < 1$ | R ban D@1；R@0 → @4 | $[3, 4]$ | $[2]$ |
| ② | $(3, 2)$ | $2 < 3$ | D ban R@3；D@2 → @6 | $[4]$ | $[6]$ |
| ③ | $(4, 6)$ | $4 < 6$ | R ban D@6；R@4 → @8 | $[8]$ | $[\ ]$ |

第三步之后 D 队为空，Dire 阵营全员失去权利，返回 `"Radiant"`。

对照官方示例：`"RD"` 走 ①（$0<1$）后 D 空 → `"Radiant"`；`"RDD"` 走 ①②（② 中 $d=2<r=3$，D 反杀 R@3）后 R 空 → `"Dire"`。两个示例都只用了 1~2 次循环。

## 4. 算法细节

1. **为什么加 $n$ 而不是加 $1$**：同一 senator 每 $n$ 个时刻才轮到一次，候选时刻的同余类固定为 $i \bmod n$；加 $n$ 恰好跳到“下一轮的同一个人”，也保证了新值严格大于队列中所有剩余元素（见引理 2）。
2. **每个 senator 只占一个整数**：不需要记轮次、不需要 `alive` 数组，也不需要“是否已被 ban”的标记——被弹出且没有回队的，就是被 ban 的。
3. **循环次数有上界**：每轮循环恰好淘汰一名 senator（$r$、$d$ 之一被 ban，另一个回队），所以最多执行 $n-1$ 次，总时间 $O(n)$。
4. **下标上界**：最坏情况下标约为 $n + (n-1)n \approx 10^8$，仍在 32 位 `int` 范围内；用 `long long` 也无害，但没必要。
5. **队列必须保持升序**：正因为升序，才能“只看两个队首”。$+n$ 后压入队尾不会破坏升序，这是算法成立的关键前提（引理 2）。
6. **容器选择**：C++ 用 `std::queue<int>`；Python 用 `collections.deque`。用 `vector`/`list` 配合 `erase(begin())` 会退化成 $O(n^2)$。
7. **两队各弹一个**：每轮循环必须同时弹出 $r$ 和 $d$，代表“这两个人正面撞上了”。只取一队或让某一队连续行动都会算错顺序。
8. **返回值拼写**：`"Radiant"` 与 `"Dire"`，首字母大写，不要写成 `"R"` / `"D"`。

## 5. 正确性证明

**引理 1（时间轴模型等价）**：把进程展平成时刻 $t = 0, 1, 2, \dots$，时刻 $t$ 由 senator $t \bmod n$ 行动，被 ban 者的所有时刻一律跳过。则该时间轴与题面“每轮 $0 \to n-1$、被 ban 者跳过、轮次无限重来”的过程逐步一致。

**证明**：题面第 $k$ 轮（$k = 0, 1, 2, \dots$）的第 $i$ 位 senator 恰好对应时刻 $k n + i$，这是一个双射；“被 ban 者在本轮及后续轮次被跳过”对应“该 senator 的所有时刻 $i, i+n, i+2n, \dots$ 全部跳过”。故两个过程在每个时刻上执行的是同一位 senator 的同一个动作。∎

**引理 2（队列升序，且队首即全局最早行动者）**：算法执行过程中，两队始终按升序保存本方尚未消费的候选时刻，且任意时刻 R 队队首与 D 队队首中的较小者，就是全局下一位行动的 senator。

**证明**：初始时两队分别按 `'R'`、`'D'` 下标升序入队，成立。设某步弹出 $r < d$（它们是两队队首，即各自最小值）。剩下的所有元素 $x$ 满足 $x > r$ 且 $x \not\equiv r \pmod n$（不同 senator 的候选时刻模 $n$ 余数不同），于是 $0 < x - r < n$，即 $x < r + n$。所以把 $r+n$ 压入 R 队队尾后整条队列仍然升序；$d < r$ 的情形对称。再由“每条队列升序”，两队列的队首并集的最小元素就是全局最小值，也就是下一位行动者。∎

**引理 3（ban 最近的对手是最优动作）**：设时刻 $t$ 由 senator $x$（阵营 $P$）行动，对手集合非空，$y$ 是其中行动最早的对手。则把 ban 目标定为 $y$，结局对 $P$ 不劣于定为任何其他对手 $y'$。

**证明**：设 $y$ 距 $x$ 的环形距离为 $d$；$y_2$ 是 $Q \setminus \{y\}$ 中行动最早者，距离 $d_2 > d$。比较两种选择在时刻 $t$ 之后发生的事：

- **ban 掉 $y$（算法选择）**：区间 $[t,\ t + d_2)$ 内**没有任何对手能开口**——$y$ 已出局，其余对手的时刻都 $\ge t + d_2$。我方 senator 在这段窗口里的每一次开口都是无损输出，被 ban 的对手名单从 $y_2$ 继续往下走。
- **ban 掉别的对手**：$y$ 仍在场，而 $x$ 的下次时刻是 $t + n > t + d$，我方不存在任何"抢先保护"的机会，$y$ 必在 $t + d$ 开口 ban 掉我方一人。

于是两种选择的核心差别只有一条：**在把两人中的哪一个先除掉时，另一个就会在更早还是更晚的时刻开口**。交换论证：把"ban $y$"那一局记为 A、"ban $y'$"那一局记为 B，把 A 中被 ban 的对手按时间顺序排成 $y, y_2, \dots$、B 中排成 $y', \dots$；对两条序列做一一对应后可以逐项验证，A 中每次"我方 senator 被 ban"的时刻都不早于 B 中对应的一次（$y$ 出局使 B 在 $t+d$ 就损失的这一人，在 A 中至少要推迟到 $t + d_2$）。对剩余 senator 数做归纳（每轮双方各消耗一人，剩余规模严格变小），即得 A 中我方在任意时刻的存活人数不少于 B，故 A 的结局对 $P$ 不劣。∎

**定理**：算法返回的阵营，就是双方最优行动下的胜者。

**证明**：由引理 1，队列模拟与题面过程逐步等价；由引理 2，每次取出的 $r, d$ 正是“当前最早行动的我方 senator 与最早的对手 senator”，$r<d$ 时 $r$ 先开口；由引理 3，$r$ 此时的最优动作就是 ban 掉 $d$。因此队列模拟逐时刻复现了双方的最优对局。循环在某一队为空时停止，此时该阵营已全员失去权利，另一阵营在下一个时刻即可依引理 1 的模型宣布胜利，返回值正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。建队 $O(n)$；循环每次淘汰一人，最多 $n-1$ 次，每次只做两次出队、一次入队和一次比较，均为 $O(1)$。相比暴力的 $O(n^2)$ 快了一个量级。
- **空间**：$O(n)$。两条队列合计恰好存 $n$ 个元素（每位 senator 任一时刻至多在一个队列中占一个位置），没有额外数组。

## 7. 参考代码

### C++

```cpp
#include <string>
#include <queue>
using namespace std;

class Solution {
public:
    string predictPartyVictory(string senate) {
        int n = senate.size();
        queue<int> R, D;
        for (int i = 0; i < n; i++) {
            if (senate[i] == 'R') R.push(i);
            else D.push(i);
        }
        while (!R.empty() && !D.empty()) {
            int r = R.front(); R.pop();
            int d = D.front(); D.pop();
            if (r < d) R.push(r + n);   // r 先开口，ban 掉 d，自己下一轮再开口
            else       D.push(d + n);   // d 先开口，ban 掉 r，自己下一轮再开口
        }
        return R.empty() ? "Dire" : "Radiant";
    }
};
```

### Python

```python
from collections import deque

class Solution:
    def predictPartyVictory(self, senate: str) -> str:
        n = len(senate)
        R, D = deque(), deque()
        for i, ch in enumerate(senate):
            (R if ch == 'R' else D).append(i)

        while R and D:
            r, d = R.popleft(), D.popleft()
            if r < d:
                R.append(r + n)      # R 先开口，ban 掉 d，自己等下一轮
            else:
                D.append(d + n)      # D 先开口，ban 掉 r，自己等下一轮

        return "Radiant" if R else "Dire"
```

## 8. 边界情况与易错点

1. **只有一方参战**：$n = 1$，或串里全是 `'R'` / 全是 `'D'`。此时循环一次都不进，某一队为空，直接返回对面胜——逻辑天然覆盖，不需要特判。
2. **返回值拼写**：必须是 `"Radiant"` / `"Dire"`，且 `R` 队空时返回 `"Dire"`（**空的是输家**），这一句最容易写反。
3. **不是“随手 ban 谁都行”**：以 `"RDRDD"` 为例，R@0 若跳过最近的 D@1 去 ban 更远的 D@3，则 D@1 反手 ban R@0、D@4 再 ban R@2，Dire 直接获胜；而按“ban 最近的对手”，R 先除掉 D@1，最终是 Radiant 胜。可见只有“ban 最近的对手”才是最优动作（引理 3），这也是本题不能跳过贪心证明的原因。
4. **加 $n$ 不能写成加 $1$**：加 $1$ 会把下一次行动时刻挪到别人的槽位上，直接破坏引理 2 的升序与同余性质。
5. **下标溢出**：最坏下标约 $n^2 \approx 10^8$，32 位 `int` 安全；若把 `n` 放大到 $10^9$ 量级才需要 `long long`。
6. **容器退化成 $O(n^2)$**：用数组 `erase`/`pop(0)`（Python 的 `list.pop(0)` 是 $O(n)$）会让总复杂度变成 $O(n^2)$，必须用 `queue` / `deque`。
7. **两队必须各弹一个**：漏掉某次出队会让“同一 senator 同时出现在两处”，或被 ban 的人继续参战，结果完全错乱。
