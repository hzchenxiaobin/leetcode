# LeetCode 使所有元素都可以被 3 整除的最少操作数 题解

## 1. 题目概述

- **标题 / 题号**：使所有元素都可以被 3 整除的最少操作数（#3190，easy）
- **链接**：https://leetcode.cn/problems/find-minimum-operations-to-make-all-elements-divisible-by-three/
- **来源**：LeetCode 第 133 场双周赛 Q1
- **难度**：简单
- **标签**：数组、数学

**题意**：给定整数数组 $nums$，一次操作可以把**任意一个**元素加 1 或减 1。求让所有元素都是 3 的倍数所需的最少操作次数。

**约束**：

- $1 \le nums.length \le 50$
- $1 \le nums[i] \le 50$
- 每个元素可以独立地被加 1 或减 1，不要求结果非负（但最优解自然不会走到负数）

**关键点**：操作只作用在单个元素上，元素之间**互不影响**，因此「总次数最少」等价于「每个元素各自用最少次数」。而一个整数 $x$ 只需看它除以 3 的余数，距离最近的 3 的倍数最多 1 步。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3,4]
输出：3
解释：1 → 0（减 1）、2 → 3（加 1）、4 → 3（减 1），共 3 次；3 本身已是 3 的倍数。
```

**示例 2**

```text
输入：nums = [3,6,9]
输出：0
解释：全部已满足条件，无需任何操作。
```

**示例 3（边界补充）**

```text
输入：nums = [1]
输出：1
解释：1 减 1 变成 0，0 能被 3 整除（0 % 3 == 0），因此 1 次足够。
```

## 3. 解题思路

### 3.1 暴力思路

对每个元素，可以试 $-2,-1,+1,+2$ 五种改动方向，取最小的可行操作数——这其实就是正解的一个笨拙写法。真正「暴力」的做法是对整个数组做搜索（例如 BFS 枚举所有可能的加减小序列），但由于元素之间可交换、彼此独立，搜索树会带来大量重复，毫无必要。本题是标准的**签到题**：一旦看出独立性，答案就是逐元素求和，$O(n)$ 一遍扫完。

### 3.2 核心观察：代价只由余数决定

![余数决定代价：非 3 的倍数都只花 1 次](images/bw133_q1_remainder_cost.svg)

记 $r = x \bmod 3$，则 $r \in \{0,1,2\}$：

- $r = 0$：$x$ 已经是 3 的倍数，代价 $0$。
- $r = 1$：$x$ 减 1 得到 $x-1 \equiv 0$，代价 $1$；也可以加 2（代价 $2$）。取小者 $1$。
- $r = 2$：$x$ 加 1 得到 $x+1 \equiv 0$，代价 $1$；也可以减 2（代价 $2$）。取小者 $1$。

统一写成

$$\text{cost}(x) = \min\left(r,\ 3 - r\right) = \begin{cases} 0, & r = 0 \\ 1, & r \ne 0 \end{cases}$$

也就是说：**每个不是 3 的倍数的元素恰好贡献 1 次操作，是 3 的倍数的元素贡献 0 次**。于是答案就是「不是 3 的倍数的元素个数」。

### 3.3 算法流程

```text
ans = 0
for x in nums:
    r = x mod 3
    ans += min(r, 3 − r)      # 等价于 ans += (r != 0)
return ans
```

注意 `min(r, 3 − r)` 与 `r != 0 ? 1 : 0` 在这道题里完全等价，但前者的写法更有信息量——它直接体现了「距离最近的 3 的倍数有多远」，换成分母 5、7 或加上「只能加不能减」的限制时依然成立。

### 3.4 示例演算

![示例走查：1,2,3,4 分别加减 1 后求和](images/bw133_q1_example_walk.svg)

以 $nums = [1,2,3,4]$ 为例：

| 元素 | 余数 $r$ | 最近的 3 的倍数 | 操作 | 代价 |
|------|----------|-----------------|------|------|
| 1 | 1 | 0 | 减 1 | 1 |
| 2 | 2 | 3 | 加 1 | 1 |
| 3 | 0 | 3 | 不动 | 0 |
| 4 | 1 | 3 | 减 1 | 1 |

总代价 $1 + 1 + 0 + 1 = 3$，与示例输出一致。

## 4. 算法细节

1. **余数用 `x % 3` 就够**：本题 $nums[i] \ge 1$，不存在负数取模的歧义。若把题目放宽到负整数，C++ 的 `%` 会给出非正余数（如 `-1 % 3 == -1`），此时要先 `r = (x % 3 + 3) % 3` 再套公式。
2. **`3 - r` 的含义**：把 $x$ 往上补到下一个 3 的倍数需要的步数。与 `r`（往下退）取较小值，就是「上下两个方向里更近的那个」。
3. **不需要真的修改数组**：只统计代价，不关心最终数组长什么样，省去一次写回。
4. **累加变量用 `int` 足够**：$n \le 50$，最坏答案是 50，远不会溢出。
5. **可一行写完**：`accumulate` + lambda，或 Python 的生成器求和；但面试/比赛中显式循环更易读。

## 5. 正确性证明

**引理 1（单个元素的下界）**：对任意整数 $x$，使其成为 3 的倍数至少需要 $\min(r, 3-r)$ 次加 1 或减 1 操作，其中 $r = x \bmod 3$。

**证明**：设共做 $k$ 次操作，其中加 1 共 $a$ 次、减 1 共 $b$ 次，则 $k = a + b$，最终值为 $x + a - b$。要求 $x + a - b \equiv 0 \pmod 3$，即 $a - b \equiv -r \pmod 3$，等价于 $b - a \equiv r \pmod 3$。若 $r = 0$，$k = 0$ 可行，且 $k \ge 0$ 显然，故下界为 0。若 $r = 1$，则 $b - a \equiv 1 \pmod 3$；若 $k = 0$ 则 $b - a = 0$，不可能；若 $k = 1$，则 $(a,b)$ 为 $(0,1)$ 或 $(1,0)$，前者给出 $b - a = 1 \equiv 1$，可行。故下界为 1。若 $r = 2$，同理 $k=0$ 不行，而 $k=1$ 取 $a=1,b=0$ 得 $b - a = -1 \equiv 2 \pmod 3$，可行，故下界为 1。三种情况的界都等于 $\min(r, 3-r)$。∎

**引理 2（构造可达）**：$r = 1$ 时减 1 一次、$r = 2$ 时加 1 一次，即可让 $x$ 变成 3 的倍数。

**证明**：$r = 1$ 时 $(x-1) \bmod 3 = 0$；$r = 2$ 时 $(x+1) \bmod 3 = 3 \bmod 3 = 0$。两种情况都恰好用了 $\min(r, 3-r) = 1$ 次操作，与引理 1 的下界吻合，故该元素的最优代价恰为 $\min(r, 3-r)$。∎

**引理 3（元素间独立）**：一次操作只改变一个元素的值，因此任意操作序列的总次数等于各元素被操作次数之和，且每个元素的最终取值只取决于作用在它身上的操作。

**证明**：操作定义为「选择任意一个元素，加 1 或减 1」，作用域是单点。把整个操作序列按目标元素分组，各组之间互不干扰；每个元素的可行性只由它自己的操作子序列决定。∎

**定理**：算法输出的 $\sum_i \min(r_i, 3 - r_i)$ 是题目要求的最少操作次数。

**证明**：由引理 3，总次数 $= \sum_i k_i$，其中 $k_i$ 是作用在第 $i$ 个元素上的操作次数。由引理 1，$k_i \ge \min(r_i, 3-r_i)$，故任何合法方案的总次数不少于 $\sum_i \min(r_i, 3-r_i)$。由引理 2，对每个元素独立地使用「减 1 / 加 1」一次即可达标，这些操作拼起来是一个合法方案，总次数恰为 $\sum_i \min(r_i, 3-r_i)$。下界可达，故算法最优。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素做一次取模和一次比较，常数时间；$n \le 50$，实际运行时间可忽略。
- **空间**：$O(1)$。只用一个累加变量，未开辟额外数组（也不修改输入）。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        int ans = 0;
        for (int x : nums) {
            int r = x % 3;            // 余数只可能是 0 / 1 / 2
            ans += min(r, 3 - r);     // r == 0 花 0 次，否则花 1 次
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minimumOperations(self, nums: list[int]) -> int:
        ans = 0
        for x in nums:
            r = x % 3
            ans += min(r, 3 - r)      # r == 0 花 0 次，否则花 1 次
        return ans
```

> 💡 两段代码与官方示例（`3`、`0`）以及 $nums = [1]$、$nums = [2]$、$nums = [50]$ 等边界一致；并与「逐个元素枚举加减方向」的暴力实现做过 300 组随机对拍，`mismatch = 0`。

## 8. 边界情况与易错点

1. **答案是 0 也要正常返回**：全部元素都是 3 的倍数时循环体只会累加 0，不要写「至少 1 次」之类的兜底。
2. **`min(r, 3 - r)` 不要写成 `min(r, 3) - r`**：后者在 $r = 2$ 时得到 $-1$，完全错误。写完后用 $r=1, r=2$ 各代一遍。
3. **减到 0 是合法的**：$1 \to 0$ 只花 1 次，而「必须保持正整数」的直觉会让人误以为要加 2 次（$1 \to 3$）。题面只要求能被 3 整除，0 满足条件。
4. **负数取模**（若题目未来放宽数据范围）：C++/Java 的 `%` 结果符号跟随被除数，务必先规整到 $[0,2]$ 再套公式。
5. **不要真的去改数组**：本题只问次数，改数组既浪费又容易在取最小值时把已改过的值再次计入。
6. **返回值类型**：题目返回 `int`，$n \le 50$ 时答案不超过 50，无需 `long long`；若数据范围放大到 $10^9$ 个元素才需要考虑溢出。

**延伸思考**：如果一次操作允许把元素加/减**任意** $d$，那么单个元素的代价变成 $\min(r \bmod d,\ d - (r \bmod d))$，答案的「求和」结构不变——这正是本题可迁移的模板：**当操作只影响单个对象且目标可分解时，全局最优 = 局部最优之和**。反过来，只要操作的影响范围跨越多个对象（如区间翻转、区间加），就必须重新审视是否还能独立决策。
