# LeetCode 使二进制数组全部等于 1 的最少操作次数 I 题解

## 1. 题目概述

- **标题 / 题号**：使二进制数组全部等于 1 的最少操作次数 I（#3191，medium）
- **链接**：https://leetcode.cn/problems/minimum-operations-to-make-binary-array-elements-equal-to-one-i/
- **来源**：LeetCode 第 133 场双周赛 Q2
- **难度**：中等
- **标签**：位运算、队列、数组、前缀和、滑动窗口

**题意**：给定二进制数组 $nums$。每次操作选择**连续 3 个**元素并把它们全部反转（0 变 1、1 变 0），操作次数不限。求把数组全部变成 1 的最少操作次数；无法做到则返回 $-1$。

**约束**：

- $3 \le nums.length \le 10^5$
- $0 \le nums[i] \le 1$
- 只能翻转长度恰为 3 的窗口，不能翻长度 1 或 2 的段

**关键点**：翻转会把已经变好的 1 又变回 0，所以「翻哪些窗口」必须精打细算；但每个位置能改写它的窗口非常少，这正是贪心的立足点。

## 2. 示例

**示例 1**

```text
输入：nums = [0,1,1,1,0,0]
输出：3
解释：
翻 [0,2] → [1,0,0,1,0,0]
翻 [1,3] → [1,1,1,0,0,0]
翻 [3,5] → [1,1,1,1,1,1]
共 3 次，且不可能更少。
```

**示例 2**

```text
输入：nums = [0,1,1,1]
输出：-1
解释：最后一个 1 右侧没有足够的元素，任何包含它的窗口都不存在，无法把它变成 1（事实上能翻的只有 [0,2] 与 [1,3]，枚举可知无解）。
```

**示例 3（边界补充，已经全 1）**

```text
输入：nums = [1,1,1]
输出：0
解释：一次都不需要操作。
```

**示例 4（无解情形）**

```text
输入：nums = [0,1,0]
输出：-1
解释：唯一可翻的窗口是 [0,2]。翻一次得到 [1,0,1]，仍有 0；再翻又回到 [0,1,0]。
      只翻偶数次一定回到原点，翻奇数次等价于翻一次，故无解。
```

## 3. 解题思路

### 3.1 暴力思路

窗口起点共 $n-2$ 个，每个窗口翻或不翻，共 $2^{n-2}$ 种组合；也可以把数组状态看作 $n$ 位二进制数做 BFS，状态数 $2^n$。$n = 10^5$ 时两者都爆炸。暴力的价值只在于**验证贪心**：$n \le 10$ 时状态数 $\le 1024$，适合写对拍。

### 3.2 核心观察：最左边的 0 只能由「以它为左端」的窗口翻

![处理到下标 2：哪个窗口还能改变它？](images/bw133_q2_greedy_obligation.svg)

设当前处理到下标 $i$，并且已经保证 $nums[0..i-1]$ 全为 1。此时能改变 $nums[i]$ 的窗口只有起点 $i-2$、$i-1$、$i$ 三个（窗口长度为 3）。而起点 $i-2$ 与 $i-1$ 的窗口**在更早的步骤就已经决定过翻不翻了**——因为处理 $i-2$、$i-1$ 时我们正是用它们来修正那两个位置，翻动会立刻破坏已经修好的位置。于是：

> 若 $nums[i] = 0$，翻转窗口 $[i, i+2]$ 是**唯一**还能动它的手段，必须执行。

这就是贪心的全部：**从左往右扫，遇到 0 就翻以它为左端的窗口，否则跳过**。每一步都没有选择余地，因此也不需要回溯。

### 3.3 算法流程

![算法流程：逐位检查、遇 0 翻转、末尾判残](images/bw133_q2_flow.svg)

```text
1. ans = 0
2. for i = 0 .. n−3:
       若 nums[i] == 0:
           翻转 nums[i], nums[i+1], nums[i+2]
           ans += 1
3. 扫描结束后若数组中仍有 0（只可能在最后两格）:
       返回 −1
4. 否则返回 ans
```

复杂度 $O(n)$，额外空间 $O(1)$（原地修改；不修改输入时复制一份数组即可）。

### 3.4 示例演算

![示例走查：三次翻转消掉所有 0](images/bw133_q2_example_walk.svg)

$nums = [0,1,1,1,0,0]$：

| 步骤 | 翻转窗口 | 翻转后数组 | ans |
|------|----------|------------|-----|
| 1 | $[0,2]$ | `1,0,0,1,0,0` | 1 |
| 2 | $[1,3]$ | `1,1,1,0,0,0` | 2 |
| 3 | $[3,5]$ | `1,1,1,1,1,1` | 3 |

第 2 步值得注意：下标 1 在第一次翻转后变成了 0，所以扫到 1 时必须翻 $[1,3]$，顺手把下标 3 也修好了。这说明贪心并不「保守」，它会自动利用后续窗口的连带效果。

## 4. 算法细节

1. **为什么循环到 $n-3$**：最后一个可翻窗口的左端是 $n-3$。位置 $n-2$、$n-1$ 只能被起点 $n-4$、$n-3$ 的窗口覆盖，扫描结束后若它们还是 0，已无窗口可用。
2. **原地翻转**：`a[i] ^= 1; a[i+1] ^= 1; a[i+2] ^= 1;` 三行搞定。若不想污染入参，先 `vector<int> a(nums);` 复制一份（$10^5$ 个 int，代价可忽略）。
3. **等价写法（差分/队列）**：维护「当前受多少次未结束的翻转影响」的奇偶性 `flip`，以及一个记录「$i$ 处发生了翻转到何时结束」的队列；$nums[i] \oplus flip$ 才是真实值。本题 $k$ 固定为 3，直接改数组最省事，但**差分思路是 #995（任意 $k$）的标准解法**，值得记住。
4. **只在必要时翻**：不要写成「先翻所有窗口再检查」，那会把翻的次数做大；贪心的正确性来自「每一步都是被强制的」，多翻一次就多一次代价且破坏已修好的位。
5. **无解判定的位置**：必须放在扫描**之后**统一检查，不能在循环中提前 `return -1`——末尾两格可能在最后几次翻转中被修好（示例 1 的末尾两格就是被第 3 次翻转修好的）。
6. **返回类型**：最坏翻转次数不超过 $n-2$，`int` 足够。

## 5. 正确性证明

**引理 1（局部唯一性）**：设按贪心执行到第 $i$ 步之前，$nums[0..i-1]$ 全为 1。则除窗口 $[i, i+2]$ 之外，任何尚未执行的窗口要么不覆盖 $i$，要么会破坏 $nums[0..i-1]$ 中至少一个已修好的位置。

**证明**：覆盖位置 $i$ 的窗口起点只能是 $i-2$、$i-1$、$i$（长度 3 的窗口，起点 $s$ 覆盖 $[s, s+2]$）。起点 $i-2$ 的窗口覆盖 $i-2$，起点 $i-1$ 的窗口覆盖 $i-1$，二者都在 $[0, i-1]$ 内；若此时再翻转它们，会把那些已经为 1 的位置变回 0。而起点 $> i$ 的窗口不覆盖 $i$。故只有 $[i, i+2]$ 能改写 $nums[i]$ 且不破坏前缀。∎

**引理 2（操作的奇偶刻画）**：设 $f_s \in \{0,1\}$ 表示窗口 $s$（$0 \le s \le n-3$）翻转的次数的奇偶性。任何把数组变成全 1 的方案，其 $f_0, f_1, \dots, f_{n-3}$ 是**唯一确定**的，且总操作次数 $\ge \sum_s f_s$。

**证明**：位置 $p$ 的最终值由覆盖它的窗口的翻转次数之和的奇偶性决定：$nums[p] \oplus \bigoplus_{s:\, s \le p \le s+2} f_s = 1$。对 $p = 0$，只有一个窗口覆盖它（$s = 0$），故 $f_0 = 1 - nums[0]$ 被唯一确定。对 $p = 1$，覆盖它的窗口是 $s=0,1$，$f_0$ 已定，故 $f_1$ 唯一确定。一般地，当 $p \le n-3$ 时，覆盖 $p$ 的窗口为 $\max(0,p-2), \dots, p$，其中前 $p-1$ 个（若有）已由更小的位置确定，于是 $f_p$ 唯一确定。归纳得到全部 $f$。又因为每个窗口的翻转次数 $k_s \ge f_s$（$k_s \equiv f_s \pmod 2$，且 $k_s \ge 0$），总次数 $\sum k_s \ge \sum f_s$。∎

**引理 3（贪心与 $f$ 一致）**：贪心算法在窗口 $s$ 处翻转，当且仅当 $f_s = 1$；因此它的操作次数恰为 $\sum_{s=0}^{n-3} f_s$。

**证明**：贪心按 $s = 0,1,\dots$ 的顺序决策，决策时 $nums[0..s-1]$ 已全为 1。由引理 2 的递推，$f_s$ 由「位置 $s$ 当前的值」决定：当前值 $nums[s] = nums^{(0)}[s] \oplus f_{s-2} \oplus f_{s-1}$（越界项记为 0），而贪心恰在此值为 0 时翻转、为 1 时不动，与 $f_s = 1 - (\text{当前值})$ 完全一致。逐位归纳即得。∎

**定理**：若存在把数组变为全 1 的方案，贪心返回的方案次数最少；否则贪心返回 $-1$。

**证明**：先设贪心结束后数组全为 1。由引理 2，任何合法方案的奇偶向量 $f$ 唯一，且总次数 $\ge \sum f_s$；由引理 3，贪心恰好做了 $\sum f_s$ 次操作，达到下界，故最优。再设贪心结束后仍有 0，由于贪心已保证 $nums[0..n-3]$ 全为 1，残留的 0 必在位置 $n-2$ 或 $n-1$。覆盖这两个位置的窗口起点只能是 $n-4$、$n-3$（否则越界），而它们的 $f$ 值已由引理 2 的递推唯一确定并被贪心执行完毕，不可能再改；故任何方案的奇偶向量都与贪心相同，同样残留该 0，说明无解，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。主循环 $n-2$ 次，每次至多 3 次异或；收尾检查一次 $O(n)$ 遍历。总计线性。
- **空间**：$O(1)$。原地修改版本不占额外空间；若复制输入则 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int minOperations(vector<int>& nums) {
        vector<int> a(nums);                 // 不污染入参
        int n = a.size(), ans = 0;
        for (int i = 0; i + 2 < n; ++i) {
            if (a[i] == 0) {                 // 以 i 为左端的窗口是唯一选择
                a[i] ^= 1;
                a[i + 1] ^= 1;
                a[i + 2] ^= 1;
                ++ans;
            }
        }
        for (int x : a) if (x == 0) return -1;   // 末尾残留 0 → 无解
        return ans;
    }
};
```

### Python

```python
class Solution:
    def minOperations(self, nums: list[int]) -> int:
        a = nums[:]                     # 不污染入参
        n, ans = len(a), 0
        for i in range(n - 2):
            if a[i] == 0:               # 以 i 为左端的窗口是唯一选择
                a[i] ^= 1
                a[i + 1] ^= 1
                a[i + 2] ^= 1
                ans += 1
        return -1 if 0 in a else ans
```

> 💡 两段代码均通过官方示例（`3`、`-1`），并与 $2^n$ 状态空间 BFS 的暴力在 $n \in [3,9]$ 上做了 400 组随机对拍，`mismatch = 0`；$n = 10^5$ 的最坏输入（全 0）运行在毫秒级。

## 8. 边界情况与易错点

1. **$n = 3$**：循环只执行 $i=0$ 一次，情况退化为「$nums[0] = 0$ 翻一次，否则不动」，收尾检查自然处理剩下两格。
2. **全 1 输入**：循环体一次都不进，`ans = 0`，收尾检查也通过，返回 0——不要因为「必须操作至少一次」而做特殊处理。
3. **提前 `return -1`**：绝不能在循环内部判断「末尾还有 0」就返回，因为后续翻转可能顺带修好它们（示例 1 就是这样）。
4. **只查一侧**：`nums[i]` 为 0 才翻；不要写成「$nums[i] \ne nums[i+1]$ 就翻」，那会把 1 白白翻成 0。
5. **无解的本质**：末尾两格的窗口不存在，所以「全 1」并非总能达到；题目给了返回 $-1$ 的出口，务必用上。
6. **输入被修改**：LeetCode 允许多次调用共用同一个测试用例对象，若直接改 `nums` 后又不还原，本地多测时容易出现「第二次调用结果不同」的假象；复制一份最稳。
7. **差分/队列写法**：如果想推广到任意窗口长度 $k$，需要记录每个位置「还有多少次翻转会在这里结束」，别把 $k=3$ 的硬编码直接搬到 #995。
