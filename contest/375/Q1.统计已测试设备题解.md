# LeetCode 统计已测试设备 题解

## 1. 题目概述

- **标题 / 题号**：统计已测试设备（#2960，easy）
- **链接**：https://leetcode.cn/problems/count-tested-devices-after-test-operations/
- **来源**：LeetCode 第 375 场周赛 Q1
- **难度**：简单
- **标签**：数组、计数、模拟

**题意**：$n$ 台设备排成一排，`batteryPercentages[i]` 是第 $i$ 台的电池百分比。**从左到右**逐台测试设备 $i$：若其**当前电量大于 0**，已测试计数 +1，并把 $j \in [i+1,\ n-1]$ 的每台电量减 1（不会低于 0，即 clamp）；否则什么都不做。返回最终**已测试设备**的数量。

**约束**：

- $1 \le n = batteryPercentages.length \le 100$
- $0 \le batteryPercentages[i] \le 100$

> 💡 读题先定性：测试**顺序写死**、每步成败完全由数组当前状态决定——**没有决策空间**，不是贪心也不是 DP，是纯模拟。真正的考点只有一个：把「每次成功后**后缀整体 $-1$**」的 $O(n^2)$ 逐个减，压缩成「维护一个成功计数器」的 $O(n)$ 一趟扫描。

## 2. 示例

**示例 1**

```text
输入：batteryPercentages = [1,1,2,1,3]
输出：3
解释：设备 0 成功（计数 1），数组变为 [1,0,1,0,2]；设备 1 电量 0 跳过；
设备 2 成功（计数 2），数组变为 [1,0,1,0,1]；设备 3 电量 0 跳过；
设备 4 成功（计数 3）。答案是 3。
```

## 3. 解题思路

### 3.1 暴力思路

照题面逐字模拟：从左到右枚举设备 $i$，若当前 $batteryPercentages[i] > 0$ 就计数 +1，再用内层循环把 $[i+1,\ n-1]$ 逐个执行 $b[j] = \max(0,\ b[j]-1)$。

时间 $O(n^2)$：$n \le 100$ 时至多 $10^4$ 次操作，签到稳过。但注意一个**结构性特征**——每次修改都是「后缀整体 $-1$」，**均匀且同型**：对右侧每个位置的减量完全一样。这种修改没必要逐个做，可以攒起来一次性算。

### 3.2 核心观察：后缀整体 −1 ⇒ 一个计数器全包

![核心概念：后缀整体减一，一个计数器全包](images/wc375_q1_suffix_counter_concept.svg)

三点观察把 $O(n^2)$ 压到 $O(n)$：

1. **减量来源唯一**：轮到设备 $i$ 时，它承受过的所有减法都来自**左侧**的成功测试——每次成功恰使 $i$ 减 1，共 $tested$ 次（$j > i$ 的测试还没发生，$j = i$ 的测试不作用于自身）。
2. **clamp 与减法可交换**：$\max(0, \max(0, x - a) - b) = \max(0, x - a - b)$，归纳可得任意多轮。所以「中途被截断在 0」不丢账，设备 $i$ 的**当前有效电量**就是
   $$\max\bigl(0,\ batteryPercentages[i] - tested\bigr)$$
3. **判定收敛为一个比较**：$\max(0,\ b[i] - tested) > 0 \iff b[i] > tested$。

$$\boxed{\ \text{设备 } i \text{ 测试成功} \iff batteryPercentages[i] > tested\ }$$

> 💡 一句话：**不要问「数组现在长什么样」，只问「已经成功了几次」**——后缀整体 $-1$ 是均匀修改，均匀的修改不必逐个做，攒进计数器即可。

顺带一个**单调性**：$tested$ 只增不减，判定门槛逐台抬高——原值追不上成功次数的设备注定测不了。这解释了为什么答案可能远小于正数个数：示例 1 中 5 台正电设备只测出 3 台，示例 3 中 3 台正电只测出 1 台。

### 3.3 算法流程

![算法流程：一趟扫描，每台设备一次比较](images/wc375_q1_algorithm_flow.svg)

1. **初始化**：`tested = 0`，从 $i = 0$ 出发；
2. **判定**：若 `batteryPercentages[i] > tested`，则 `tested++`；
3. **推进**：$i$ 右移一位，未到数组末尾则回到第 2 步；
4. **收尾**：返回 `tested`。

> ⚠️ 最常见手误：把判定写成 `batteryPercentages[i] > 0`——等于无视左侧成功测试带来的减量。示例 1 会被误判成 5 台全测成功（正确答案 3）。

### 3.4 示例演算

![示例 1 演算：计数视角逐步判定](images/wc375_q1_example_walkthrough.svg)

以示例 1（`batteryPercentages = [1,1,2,1,3]`）为例：

| $i$ | $b[i]$ | 判定前 `tested` | $b[i] > tested$ ? | `tested` | 数组实况（暴力对照） |
|-----|--------|----------------|-------------------|----------|----------------------|
| 0 | 1 | 0 | $1 > 0$ ✓ | **1** | `[1,0,1,0,2]` |
| 1 | 1 | 1 | $1 > 1$ ✗ | 1 | （不变） |
| 2 | 2 | 1 | $2 > 1$ ✓ | **2** | `[1,0,1,0,1]` |
| 3 | 1 | 2 | $1 > 2$ ✗ | 2 | （不变） |
| 4 | 3 | 2 | $3 > 2$ ✓ | **3** | `[1,0,1,0,1]` |

最右列是暴力模拟的数组状态，用来交叉验证计数视角：设备 2 判定前数组为 `[1,0,1,0,2]`，下标 2 处的 $1$ 恰是 $\max(0, 2 - 1)$——两个视角完全吻合。返回 `tested = 3` ✓。

## 4. 算法细节

1. **`tested` 的一变量双身份**：既是「已成功台数」（要返回的答案），又是「右侧设备待承受的减量」（判定门槛）。判定与修改共用一个变量，正是 $O(n^2)$ 能折叠成 $O(n)$ 的根。
2. **判定不必显式 clamp**：$\max(0, b[i] - tested) > 0 \iff b[i] > tested$，直接比较原值即可，连 `max` 调用都省了。
3. **不修改原数组**：按值遍历（`for (int x : ...)` / `for x in ...`），判定与自增在同一个 `if` 里一步完成。
4. **每台设备摊还 $O(1)$**：一次比较 + 至多一次自增，没有任何内层循环。

## 5. 正确性证明

**引理 1（clamp 与减法可交换）**：对任意整数 $x$ 与非负整数 $a, b$，
$$\max\bigl(0,\ \max(0, x - a) - b\bigr) = \max(0,\ x - a - b).$$

**证明**：分两种情况。若 $x \ge a$：内层 $\max(0, x - a) = x - a$，左边化为 $\max(0, x - a - b)$，与右边相同。若 $x < a$：内层为 $0$，左边 $= \max(0, -b) = 0$（$b \ge 0$）；右边因 $x - a - b < -b \le 0$ 也为 $0$。∎

**推论**：对 $x$ 相继做 $t$ 次「clamp 减 1」，结果为 $\max(0, x - t)$。对 $t$ 归纳：$t = 0$ 平凡；$t \Rightarrow t + 1$ 由引理 1 取 $a = t,\ b = 1$ 即得。∎

**引理 2（有效值公式）**：轮到设备 $i$ 被判定时，其电量为 $\max(0,\ b[i] - t_i)$，其中 $t_i$ 是 $[0, i-1]$ 中成功测试的台数。

**证明**：测试按 $0, 1, \dots, n-1$ 顺序进行，轮到 $i$ 时只有 $j < i$ 的测试已发生；其中成功的每次对 $i$ 施加一次「clamp 减 1」，共 $t_i$ 次（$j = i$ 的测试若成功只作用于 $j > i$，不影响自身）。由引理 1 的推论，$t_i$ 次操作后 $i$ 的电量为 $\max(0, b[i] - t_i)$。∎

**定理**：设备 $i$ 测试成功 $\iff b[i] > t_i$；且算法返回值等于按题面模拟的成功测试总数。

**证明**：前半由引理 2 立得：设备 $i$ 成功 $\iff \max(0, b[i] - t_i) > 0 \iff b[i] - t_i > 0 \iff b[i] > t_i$。再对 $i$ 归纳证明「算法遍历到设备 $i$ 时 `tested` $= t_i$」：$i = 0$ 时两者均为 0；设遍历到 $i$ 时相等，则算法的判定条件 $b[i] > tested$ 与模拟的成败条件 $b[i] > t_i$ 是**同一个比较**，二者同时成功或同时失败——成功时 `tested++` 与 $t_{i+1} = t_i + 1$ 同步，失败时均不变。归纳完成，扫描结束时 `tested` 即成功总数。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。一趟扫描，每台设备一次比较、至多一次自增。$\Omega(n)$ 也是读取下界——未读到的设备都可能被测，任何 $o(n)$ 算法都会漏判。
- **空间复杂度**：$O(1)$。仅一个计数器。暴力模拟同为 $O(1)$ 空间，但时间是 $O(n^2)$——约束放大到 $n \le 10^6$ 时暴力直接超时，计数器版依旧秒过。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int countTestedDevices(vector<int>& batteryPercentages) {
        int tested = 0;
        for (int x : batteryPercentages) {
            if (x > tested) {
                tested++;
            }
        }
        return tested;
    }
};
```

### Python

```python
class Solution:
    def countTestedDevices(self, batteryPercentages: List[int]) -> int:
        tested = 0
        for x in batteryPercentages:
            if x > tested:
                tested += 1
        return tested
```

> 💡 语言细节：两版都按值遍历、不修改原数组；循环体就是判定条件 $\boxed{b[i] > tested}$ 的逐字翻译——这正是签到题想要的「从题面到代码的最短路径」。

## 8. 边界情况与易错点

1. **判定写成 `b[i] > 0`（最高频手误）**：无视左侧成功测试的减量，示例 1 会误判 5 台全成功（正确 3）。判定对象是**有效电量**，不是初始电量。
2. **减量只作用于 $j \in [i+1, n-1]$**：设备自身与左侧不受影响 ⇒ 判定用的是**本轮自增前**的 `tested`，`if` 里「先比较、后自增」的顺序不能反。
3. **大电量 ≠ 多测**：`[100, 1]` 的答案是 1——设备 0 成功后设备 1 直接归零；`tested` 门槛只升不降，正数再多也可能只测出一台。
4. **最小规模与全零**：$n = 1$ 时单台设备，$b[0] > 0$ 即答案 1，代码自然覆盖；全 0 数组答案为 0，`tested` 恒为 0，无需特判。
5. **别把 $O(n)$ 写回 $O(n^2)$**：有人习惯「真减一遍数组再判 $\max(0, \cdot) > 0$」——与计数器等价，但平白多一层内层循环，约束放大即超时。
6. **无溢出风险**：$n \le 100$、$b[i] \le 100$，`int` 足够，本题无需 `long long`、也无需取模。
