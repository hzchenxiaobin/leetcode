# LeetCode 字符频次唯一的最小删除次数 题解

## 1. 题目概述

- **标题 / 题号**：字符频次唯一的最小删除次数（#1647，medium）
- **链接**：https://leetcode.cn/problems/minimum-deletions-to-make-character-frequencies-unique/
- **来源**：LeetCode 第 214 场周赛 Q2
- **难度**：中等
- **标签**：贪心、哈希表、字符串、排序

**题意**：若字符串 $s$ 中**不存在两个不同字符的频次相同**，则称 $s$ 为「优质字符串」（频次 = 出现次数；频次为 0 的字符视为不存在，不参与比较）。每次操作可以删除 $s$ 中任意一个字符，返回使 $s$ 变为优质字符串的**最少删除次数**。

**约束**：

- $1 \le |s| \le 10^5$——统计频次必须一趟 $O(n)$ 完成
- $s$ 仅含小写英文字母——字符集 $|\Sigma| = 26$：频次表只有 26 项，排序与遍历都是常数开销；同时**正频次槽位至多 26 个**

> 💡 读题第一步是**翻译**：删除一个字符只会让该字符的频次减一，**只降不升**。于是每个字符的最终频次只能从 $[0, f(c)]$ 里挑——问题等价于「给每个字符挑一个不超过原频次的槽位，正槽位互不相同，让留在槽里的字符尽量多」。从「删除字符」到「分配槽位」的这步等价改写，是本题全部贪心结构的来源。
>
> 本题在本仓库另有[每日题解 1647](../../solution/1601-1700/1647_字符频次唯一的最小删除次数.md)：侧重「哈希集合写法对比与面试问答」。本篇按周赛复盘视角，聚焦「槽位模型的等价改写、支配论证的完整证明与赛场易错清单」，两篇互为印证。

## 3. 解题思路

### 3.1 暴力思路

最直觉的做法是枚举「每个字符各删几个」：字符 $c$ 可以删 $0 \sim f(c)$ 个，组合数为 $\prod_c (f(c)+1)$，最坏 $(n/26+1)^{26}$，指数级。

退一步想 DP：按 26 个字符逐个决策终频次，但合法性取决于「已占用的频次集合」，频次值域高达 $n = 10^5$，状态数天文数字；就算把已用频次压成 bitset 也无法承受值域规模。

卡壳的根源在于没有利用问题的结构：**删除代价由每个字符独立的终频次决定，字符之间只通过「频次不能撞车」耦合**。这种「独立决策 + 全局互斥」的形态，正是贪心（或建模成流/匹配）的招牌场景。

### 3.2 核心观察：只降不升 + 槽位互斥 + 降序占位

![核心观察：正频次槽位互不相同——降序贪心压成阶梯](images/wc214_q2_staircase_concept.svg)

**观察 1（删除 = 终频次只降不升）**：删字符只能让频次变小，故每个字符 $c$ 的终频次 $g(c)$ 只能取 $[0, f(c)]$ 内的整数，代价恰为 $f(c) - g(c)$。删除方案之间唯一的区别就是这组终频次——删哪些位置完全无关紧要。

**观察 2（槽位互斥，0 是安全区）**：优质条件只约束**出现**的字符：所有正的 $g(c)$ 必须两两不同。$g(c) = 0$ 意味着字符 $c$ 从串中消失，多个字符同时归零不违反定义——0 不是槽位，是「退出局」。

**观察 3（降序贪心：大频次先占高槽）**：把频次**降序排列** $f_1 \ge f_2 \ge \cdots$，从大到小依次处理：第一个频次原样保留；之后每个 $f_i$ 若与前面撞车，就压到 $\text{prev} - 1$（前一个字符所占档位的**下一档**），压到负数则整字符删光。大频次先占高槽、每个冲突只压「恰好不冲突」的一格，一格都不多删。

> 💡 **为什么大频次优先？** 频次大的字符「下探空间」大，频次小的字符挪起来便宜；让先来的（更大的）频次站在原位，后来的（更小的）往下让，总比反过来（小频次占高位、大频次被迫大砍）划算。直觉如此，严格证明见 §5 的支配论证。

### 3.3 算法流程

![算法流程：降序排频次，逐个压进不重复的槽](images/wc214_q2_greedy_flow.svg)

```text
1. freq[26] ← 一趟统计 s 中每个字母的出现次数          # O(n)
2. 将 freq 降序排序（0 自然沉底，遇 0 即可停止）
3. prev ← +∞，deletions ← 0
4. 对每个非零频次 f（从大到小）：
     target ← max(0, min(f, prev − 1))     # 冲突就压到前一个的下一档
     deletions ← deletions + (f − target)  # 压多少删多少
     prev ← target                         # 槽位只降不升
5. 返回 deletions
```

> ⚠️ **两处纪律**：`prev` 初值必须是 $+\infty$（或首个频次 + 1），否则最大的频次会被无端压低；`target` 压到负数必须截断为 0——0 表示「字符整个删光」，此后 prev 钉在 0，后续字符全部整段删除。

### 3.4 示例演算

![示例演算：aaabbbcc 与 ceabaacb 的降序压槽过程](images/wc214_q2_walkthrough.svg)

以示例 2 `s = "aaabbbcc"` 走查，频次降序 $[3, 3, 2]$（字符 a、b、c）：

| 步 | 字符 | $f$ | prev（处理前） | target | 删除 |
|----|------|-----|---------------|--------|------|
| ① | a | 3 | $+\infty$ | 3 | 0 |
| ② | b | 3 | 3 | 2 | 1 |
| ③ | c | 2 | 2 | 1 | 1 |

总删除 $= 0 + 1 + 1 = 2$，终频次 $\{3, 2, 1\}$ 互不相同 ✓。

再用示例 3 `s = "ceabaacb"` 验证**压穿 0**：频次降序 $[3, 2, 2, 1]$（字符 a、b、c、e）：

| 步 | 字符 | $f$ | prev（处理前） | target | 删除 | 说明 |
|----|------|-----|---------------|--------|------|------|
| ① | a | 3 | $+\infty$ | 3 | 0 | 最大频次免检 |
| ② | b | 2 | 3 | 2 | 0 | $2 < 3 - 1$，不冲突原地保留 |
| ③ | c | 2 | 2 | 1 | 1 | 撞 2 档，压到 1 |
| ④ | e | 1 | 1 | **0** | 1 | 压穿 0：e 整个消失，不占槽 |

总删除 $= 2$，终频次 $\{3, 2, 1\}$ ✓。第 ④ 步是「频次为 0 的字符忽略不计」的准确含义：**归零不是占了一个叫 0 的槽，而是退出比较**。

把「压穿 0」推到极端的自查用例 `s = "aabbcc"`（频次 $[2,2,2]$）：target 依次 $2, 1, 0$，删除 $0 + 1 + 2 = 3$。

## 4. 算法细节

1. **26 桶计数，排序常数**：频次表只有 26 项，`sort` 是 $O(26 \log 26)$；降序排列后 0 全部沉底，循环里 `if (f == 0) break;` 即可提前收工。
2. **target 公式的三种情形**：$target = \max\big(0,\ \min(f,\ \text{prev} - 1)\big)$——
   - $f < \text{prev} - 1$：不冲突，原地保留，prev 直接跳到 $f$（**跳跃式下滑**，比逐格减一更快）；
   - $0 \le \text{prev} - 1 \le f$：撞车，压到 $\text{prev} - 1$；
   - $\text{prev} - 1 < 0$：截断为 0，该字符全部删除。
3. **prev 单调不增**：每一步 prev 要么跳到更小的 $f$、要么减一、要么钉在 0，故「阶梯」只会越搭越低；**一旦 prev 归 0，其后所有字符的 target 恒为 0**（整段删光），无须特判。
4. **与哈希集合写法等价**：另一常见写法是维护 `seen` 集合，对每个频次 `while (f > 0 && seen.count(f)) f--;`。它与降序贪心给出同一答案：每次递减相当于往下探一格空槽。均摊分析：`while` 每递减一次恰对应 `deletions` 加一，总递减次数 $\le \sum f = n$，故均摊 $O(n)$，并不比排序版慢出量级。
5. **为什么必须降序**：反例频次 $[3, 3, 2]$——降序删 $0+1+1 = 2$；升序处理则 $2 \to 2$、$3 \to 1$、$3 \to 0$，删 $0+2+3 = 5$。升序让小频次抢占高槽，大频次被迫大砍。
6. **只数数，不构造**：题目只要次数，统计完频次后就是纯粹的数字游戏——不要去模拟删除过程或重建字符串。

## 5. 正确性证明

**引理 1（删除方案的刻画）**：设 $f(c)$ 为字符 $c$ 的初始频次。任何删除方案唯一确定一组终频次 $\{g(c)\}$，满足 $0 \le g(c) \le f(c)$；反之，任何满足该不等式组的 $g$ 都可实现（把 $c$ 删去 $f(c) - g(c)$ 个即可，删哪些位置不影响频次）。方案合法当且仅当所有**正值** $g(c)$ 互不相同；方案代价为 $\sum_c \big(f(c) - g(c)\big)$。

**证明**：删除一个 $c$ 使 $f(c)$ 减少 1 且不改变其他字符的频次，故终频次 = 初始频次 − 该字符被删个数，各字符完全独立；「不存在两个不同字符频次相同」按定义只约束**出现**（$g > 0$）的字符，$g(c) = 0$ 即 $c$ 不存在于终串，不参与比较。∎

**引理 2（可行终频次被初始频次逐位压制）**：将初始频次降序排列 $f_1 \ge f_2 \ge \cdots \ge f_k > 0$（$k \le 26$ 为出现过的字符数）。设 $g$ 为任一可行方案的终频次，把 $g$ 在这 $k$ 个字符上的取值降序排列为 $g_1 \ge g_2 \ge \cdots \ge g_k$（不足补 0）。则对一切 $1 \le i \le k$ 有 $g_i \le f_i$。

**证明**：固定 $i$。取携带 $g_1, \dots, g_i$ 的 $i$ 个字符，每个字符 $c$ 满足 $f(c) \ge g(c) \ge g_i$，故至少有 $i$ 个字符的初始频次 $\ge g_i$。若 $f_i < g_i$，则由 $f$ 降序知至多 $i - 1$ 个初始频次 $\ge g_i$，矛盾。故 $f_i \ge g_i$。∎

**引理 3（贪心目标逐位支配一切可行解）**：定义 $t_0 = +\infty$，$t_i = \max\big(0,\ \min(f_i,\ t_{i-1} - 1)\big)$。则对任意可行终频次 $g$（按引理 2 对齐降序后），有 $t_i \ge g_i$ 对一切 $1 \le i \le k$ 成立。

**证明**：对 $i$ 归纳。$i = 1$：$t_1 = \max(0, \min(f_1, +\infty)) = f_1 \ge g_1$（引理 2）。设 $t_{i-1} \ge g_{i-1}$。若 $g_i = 0$，由 $t_i \ge 0$ 直接得证；若 $g_i \ge 1$，则 $g_{i-1} \ge 1$，由 $g$ 的正值互不相同且降序得 $g_{i-1} \ge g_i + 1$，于是由 $f_i \ge g_i$（引理 2）与 $t_{i-1} - 1 \ge g_{i-1} - 1 \ge g_i$：

$$t_i \;\ge\; \min\big(f_i,\ t_{i-1} - 1\big) \;\ge\; \min\big(g_i,\ g_i\big) \;=\; g_i,$$

且 $\max(0, \cdot)$ 截断不会把结果压到 $g_i \ge 0$ 之下。∎

**定理（贪心最优性）**：贪心序列 $t$ 自身可行，且其代价 $\sum_i (f_i - t_i)$ 是一切可行方案代价的最小值。

**证明**：先证可行，逐条验证引理 1 的两个条件：(a) $t_i = \max(0, \min(f_i, \cdot)) \le f_i$，可经删除 $f_i - t_i$ 个该字符达到；(b) 正值互不相同——设 $i < j$ 且 $t_j > 0$，则 $t_{j-1} \ge 1$（否则 $t_j = 0$），从而 $t_j \le t_{j-1} - 1$；递归可得从 $i$ 到 $j$ 链上每项 $\ge 1$ 且 $t_j \le t_i - (j - i) < t_i$。再证最优：对任意可行 $g$，由引理 3 知 $t_i \ge g_i$ 逐位成立，故

$$\sum_{i=1}^{k} \big(f_i - t_i\big) \;\le\; \sum_{i=1}^{k} \big(f_i - g_i\big),$$

即贪心代价不超过任何可行方案；结合可行性即最优。∎

## 6. 复杂度分析

- **时间复杂度**：$O\big(n + |\Sigma| \log |\Sigma|\big)$，其中 $|\Sigma| = 26$。统计频次一趟 $O(n)$；排序 $O(26 \log 26)$ 与单趟遍历 $O(26)$ 均为常数，整体由计数主导。哈希集合写法为均摊 $O(n + |\Sigma|)$（每次 while 递减对应一次删除，总递减 $\le n$）。
- **空间复杂度**：$O(|\Sigma|) = O(26)$。仅频次数组（或哈希表，大小 $\le 26$）与几个标量。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int minDeletions(string s) {
        int freq[26] = {0};
        for (char c : s) freq[c - 'a']++;

        sort(freq, freq + 26, greater<int>());   // 降序，0 沉底

        int deletions = 0;
        int prev = INT_MAX;                      // 槽位上限：首个频次免检
        for (int f : freq) {
            if (f == 0) break;                   // 后面全是 0
            int target = min(f, prev - 1);
            if (target < 0) target = 0;          // 压穿 0：字符整个删光
            deletions += f - target;
            prev = target;
        }
        return deletions;
    }
};
```

### Python

```python
class Solution:
    def minDeletions(self, s: str) -> int:
        freq = sorted(Counter(s).values(), reverse=True)  # 0 不入表

        deletions = 0
        prev = float('inf')                      # 槽位上限：首个频次免检
        for f in freq:
            target = max(0, min(f, prev - 1))    # 压穿 0：字符整个删光
            deletions += f - target
            prev = target
        return deletions
```

## 8. 边界情况与易错点

1. **`prev` 初值**：必须是 $+\infty$（或首个频次 + 1、$n + 1$）。初始化成 0 或 1 会把最大的频次也压低，白删字符。C++ 用 `INT_MAX` 时 `min(f, prev - 1)` 无溢出（`INT_MAX - 1` 安全）；更稳妥可写 `prev = (int)s.size() + 1`。
2. **负数截断**：`prev = 0` 时 `prev - 1 = -1`，target 必须 `max(0, ·)`。漏掉截断会算出 `f − (−1) = f + 1`，多删一个。
3. **频次 0 不占槽**：多个字符同时归零合法——0 意味着字符不存在。哈希集合写法的 while 条件必须带 `f > 0`，否则两个归零字符会误判冲突。
4. **必须降序**：升序反例频次 $[3, 3, 2]$：升序删 5、降序删 2。看到「频次」先想降序，是本题最快的赛场切入。
5. **溢出对照**：答案 $\le n \le 10^5$，`int` 足够；同场 Q4 才需要 `long long` + 取模，别惯性照抄。
6. **无需构造方案**：题目只要次数。统计完频次就是数字游戏，模拟删除过程纯属浪费。
7. **全同字符 / $n = 1$**：频次表只有一个正数，天然唯一，返回 0；上述代码无须特判。
8. **排序对象是频次值**：冲突发生在频次值上，与字符本身无关——对「字符」排序没有意义。
