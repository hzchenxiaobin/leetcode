# LeetCode 获取生成数组中的最大值 题解

## 1. 题目概述

- **标题 / 题号**：获取生成数组中的最大值（#1646，easy）
- **链接**：https://leetcode.cn/problems/get-maximum-in-generated-array/
- **来源**：LeetCode 第 214 场周赛 Q1
- **难度**：简单
- **标签**：数组、模拟、动态规划

**题意**：给定整数 `n`，按下述规则生成长度为 $n+1$ 的数组 `nums`，返回其中的**最大值**：

- `nums[0] = 0`，`nums[1] = 1`
- 当 $2 \le 2i \le n$ 时，`nums[2i] = nums[i]`
- 当 $2 \le 2i+1 \le n$ 时，`nums[2i+1] = nums[i] + nums[i+1]`

**约束**：

- $0 \le n \le 100$

> 💡 签到题的关键是**从题面到代码的最短路径**：本题的「最短路径」在于识破递推结构——每条规则依赖的都是更小的下标，一趟正向填表即可，无需任何搜索或记忆化。

## 2. 示例

**示例 1**

```text
输入：n = 7
输出：3
解释：nums = [0,1,1,2,1,3,2,3]，最大值为 3。
```

**示例 2**

```text
输入：n = 2
输出：1
解释：nums = [0,1,1]，最大值为 1。
```

**示例 3**

```text
输入：n = 3
输出：2
解释：nums = [0,1,1,2]，最大值为 2。
```

## 3. 解题思路

### 3.1 暴力思路：照题面枚举 i

照题面字面模拟：外层枚举源头 `i`，内层分别给 `2i` 与 `2i+1` 两个位置赋值。写法正确且 $n \le 100$ 显然能过，但「一个源头管两个目标」导致分支冗长：要分别判断 $2i \le n$、$2i+1 \le n$ 是否成立，循环上界还得取 $i \le n/2$，赛场上容易在边界判断上出小错。

### 3.2 核心观察：视角从「源头 i」切换到「目标 j」

![核心概念：按目标下标 j 重写递推，奇偶分流](images/genmax_concept.svg)

把递推按**目标下标** $j$ 重写（$j = 2i$ 或 $j = 2i+1$），每个待填位置恰好对应一条规则，由奇偶性决定：

- $j$ 为偶数：$\text{nums}[j] = \text{nums}[j/2]$（复制一半处的值）
- $j$ 为奇数：$\text{nums}[j] = \text{nums}[j/2] + \text{nums}[j/2+1]$（相邻两值之和）

两条规则依赖的下标 $j/2$、$j/2+1$ 都**严格小于** $j$（见 §5 引理 1），所以**按 $j$ 从小到大**一趟正向扫描，被依赖的格子天然已填好——无需递归、无需记忆化，这就是最简的「按拓扑序填表」。

> 💡 既然要的是 $\max(\text{nums})$，不必填完表再扫第二趟：每写入一个 `nums[j]` 就顺手 `ans = max(ans, nums[j])`，把填表与求最大合并成一趟。

### 3.3 算法流程

![算法流程：一趟正扫 + 奇偶分流](images/genmax_flow.svg)

```text
1. 若 n == 0：返回 0（数组只有 nums[0] = 0）
2. 初始化 nums[0] = 0, nums[1] = 1, ans = 1
3. for j = 2 .. n:
     a. 若 j 为奇数：nums[j] = nums[j/2] + nums[j/2 + 1]
     b. 若 j 为偶数：nums[j] = nums[j/2]
     c. ans = max(ans, nums[j])
4. 返回 ans
```

### 3.4 示例演算

![示例演算：n = 7 一趟正扫](images/genmax_walkthrough.svg)

以 $n = 7$ 为例，逐步填表并跟踪 `ans`：

| j | 奇偶 | 计算 | nums[j] | ans |
|---|------|------|---------|-----|
| 0 | 初始 | `nums[0]=0` | 0 | — |
| 1 | 初始 | `nums[1]=1` | 1 | 1 |
| 2 | 偶 | `nums[2]=nums[1]` | 1 | 1 |
| 3 | 奇 | `nums[3]=nums[1]+nums[2]=1+1` | 2 | 2 |
| 4 | 偶 | `nums[4]=nums[2]` | 1 | 2 |
| 5 | 奇 | `nums[5]=nums[2]+nums[3]=1+2` | 3 | 3 ← 峰值 |
| 6 | 偶 | `nums[6]=nums[3]` | 2 | 3 |
| 7 | 奇 | `nums[7]=nums[3]+nums[4]=2+1` | 3 | 3 |

扫描结束得 `nums = [0,1,1,2,1,3,2,3]`，返回 `ans = 3` ✓。注意 `j=5` 处 `ans` 首次达到 3，随后 `j=7` 虽也填出 3，但 `max` 不再变化。

## 4. 算法细节

1. **特判 $n=0$**：数组仅 `[0]`，`nums[1]` 不存在，直接返回 0，避免初始化越界。
2. **初始化**：`nums[0]=0`、`nums[1]=1`、`ans=1`。`ans` 初值必须取 1（覆盖 `nums[0]`、`nums[1]` 两格的最大者），因为循环从 $j=2$ 开始，这两格永远不会进入 `max` 更新。
3. **奇偶分流**：`j & 1` 判奇偶，`j >> 1` 取半（非负整数下等价于 $j/2$）。奇数位依赖 $h=\lfloor j/2 \rfloor$ 与 $h+1$ 两格，偶数位只依赖 $h$ 一格。
4. **边填边 max**：每写入一项立即 `ans = max(ans, nums[j])`，省去第二趟 $O(n)$ 扫描。
5. **可选统一式**：利用「偶数位时 $h+1$ 那项应贡献 0」，两分支可合并为 $\text{nums}[j] = \text{nums}[h] + (j \bmod 2)\cdot \text{nums}[h+1]$，乘 0/1 系数自动完成分流，代价是牺牲一点与题面的直观对应。

## 5. 正确性证明

**引理 1（依赖严格靠前）**：对任意 $j \ge 2$，计算 $\text{nums}[j]$ 只依赖下标严格小于 $j$ 的表项。

**证明**：若 $j$ 为偶数，$\text{nums}[j] = \text{nums}[j/2]$，而 $j/2 < j$；若 $j$ 为奇数（此时 $j \ge 3$），$\text{nums}[j] = \text{nums}[(j-1)/2] + \text{nums}[(j+1)/2]$，其中 $(j-1)/2 < j$ 显然，且 $(j+1)/2 \le j-1 \iff j \ge 3$ 成立，故两个依赖也都严格小于 $j$。∎

**引理 2（规则覆盖且不重叠）**：题面两条规则的触发条件 $2 \le 2i \le n$ 与 $2 \le 2i+1 \le n$，恰好把目标下标集合 $\{2, 3, \dots, n\}$ 按奇偶划分为不重叠的两部分——每个 $j \in [2, n]$ 恰好被一条规则赋值一次。

**证明**：$j$ 偶时可令 $i = j/2 \ge 1$，条件化为 $2 \le j \le n$；$j$ 奇时可令 $i = (j-1)/2 \ge 1$，条件化为 $3 \le j \le n$。两者并集恰为 $[2, n]$ 且无交集。∎

**定理**：算法返回 $\max_{0 \le j \le n} \text{nums}[j]$。

**证明**：对 $j$ 施强归纳。$j = 0, 1$ 为初值；$j \ge 2$ 时由引理 1，所依赖的下标均严格小于 $j$，扫描顺序保证它们已按定义填好，结合引理 2 知每个 $j$ 被且仅被正确赋值一次，故填出的表与递归定义一致。$n = 0$ 时特判直接返回 0 正确；$n \ge 1$ 时 `ans` 初值 1 覆盖 $j \le 1$ 的两格，此后每个 $\text{nums}[j]$（$j \ge 2$）在被写入的瞬间纳入 `max`，扫描结束时 `ans` 恰为全表最大值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n)$。单趟扫描 $j = 2 \dots n$，每步仅奇偶判断与 $O(1)$ 赋值、取最大。
- **空间复杂度**：$O(n)$。需长度 $n+1$ 的 `nums` 数组。由于规则依赖**任意更小下标**（如 `nums[7]` 依赖 `nums[3]`、`nums[4]`，并非仅依赖前一项），无法像爬楼梯类一维 DP 那样滚动压缩到 $O(1)$——保留整表是必要的。$n \le 100$ 下两者开销均可忽略。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int getMaximumGenerated(int n) {
        if (n == 0) return 0;
        vector<int> nums(n + 1);
        nums[0] = 0;
        nums[1] = 1;
        int ans = 1;
        for (int j = 2; j <= n; ++j) {
            if (j & 1) nums[j] = nums[j >> 1] + nums[(j >> 1) + 1];
            else       nums[j] = nums[j >> 1];
            ans = max(ans, nums[j]);
        }
        return ans;
    }
};
```

### Python

```python
class Solution:
    def getMaximumGenerated(self, n: int) -> int:
        if n == 0:
            return 0
        nums = [0] * (n + 1)
        nums[1] = 1
        ans = 1
        for j in range(2, n + 1):
            if j & 1:
                nums[j] = nums[j >> 1] + nums[(j >> 1) + 1]
            else:
                nums[j] = nums[j >> 1]
            ans = max(ans, nums[j])
        return ans
```

## 8. 边界情况与易错点

1. **n = 0**：数组仅 `[0]`，必须提前返回 0；不特判就初始化 `nums[1]` 会越界。
2. **n = 1**：循环不执行，全靠 `ans` 初值 1 返回——所以 **`ans` 初值不能取 0**，否则 `n=1` 会错返 0（循环从 `j=2` 开始，`nums[1]` 永远不会进入 `max` 更新）。
3. **照题面枚举 `i` 时**：循环上界是 $i \le n/2$（由 $2i \le n$），且写 `2i+1` 前要单独判 `2i+1 <= n`，两处越界判断漏一处就越界写。
4. **奇数规则方向**：是 `nums[i] + nums[i+1]`（源头与它的**下一项**），别写成 `nums[i] + nums[i-1]`。
5. **值域**：$n \le 100$ 时表内最大值仅 21（$n=100$），`int` 足够，无溢出风险。
6. **递归 + 记忆化**也可做但完全没必要：依赖严格靠前（引理 1）说明正序填表已是最简实现。
