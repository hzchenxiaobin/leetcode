# LeetCode 通过指令创建有序数组 题解

## 1. 题目概述

- **标题 / 题号**：通过指令创建有序数组（#1649，hard）
- **链接**：https://leetcode.cn/problems/create-sorted-array-through-instructions/
- **来源**：LeetCode 第 214 场周赛 Q4
- **难度**：困难
- **标签**：树状数组、线段树、数组、二分查找

**题意**：给定整数数组 `instructions`，初始有空的有序数组 `nums`，从左到右依次将每个元素 $x$ 插入 `nums` 并保持有序。每次插入的**代价**（对插入前的 `nums` 而言）是以下两者的较小值：

- `nums` 中**严格小于** $x$ 的数字数目；
- `nums` 中**严格大于** $x$ 的数字数目。

返回将所有元素插入完毕后的**总代价**，由于答案很大，对 $10^9 + 7$ 取余后返回。

**约束**：

- $1 \le n \le 10^5$——单步必须是 $O(\log)$ 级别，任何 $O(n)$ 的单步操作累计即超时
- $1 \le \text{instructions}[i] \le 10^5$——元素全为正整数且值域紧凑，可直接作桶下标，免离散化

> 💡 读题第一步是**翻译**：代价只由「已插入元素中比 $x$ 小 / 大的个数」决定，题面从未指定插入到哪个位置——维护数组的「形态」是多余的，需要的只是一个支持「插入一个值 + 查询两侧计数」的**在线计数结构**。值域 $[1, 10^5]$ 直接做下标，树状数组（BIT）一步到位。
>
> 本题在本仓库另有[每日题解 1649](../../solution/1601-1700/1649_通过指令创建有序数组.md)：侧重「BIT 模板细节、与 315 题的对照和面试问答」。本篇按周赛复盘视角，聚焦「插入代价 → 纯计数问题」的翻译、重复值的两侧排除、$O(n^2)$ 级答案的溢出论证与赛场易错清单，两篇互为印证。

## 2. 示例

**示例 1**

```text
输入：instructions = [1,5,6,2]
输出：1
解释：
  插入 1，代价 min(0, 0) = 0，nums = [1]
  插入 5，代价 min(1, 0) = 0，nums = [1,5]
  插入 6，代价 min(2, 0) = 0，nums = [1,5,6]
  插入 2，代价 min(1, 2) = 1，nums = [1,2,5,6]
  总代价 = 0 + 0 + 0 + 1 = 1
```

**示例 2**

```text
输入：instructions = [1,2,3,6,5,4]
输出：3
解释：只有插入 5（代价 1）与插入 4（代价 2）付费，1+2 = 3。
```

**示例 3**

```text
输入：instructions = [1,3,3,3,2,4,2,1,2]
输出：4
解释：付费的三步为插入 2（代价 1）、再插 2（代价 1）、插第 3 个 2（代价 2）。
  连续插入三个 3 的代价全为 0——重复值两侧都不计数。
```

## 3. 解题思路

### 3.1 暴力思路：真的去维护有序数组

最直觉的做法是把「创建有序数组」当真：维护有序数组 `nums`，每步二分找位再插入。两条路都死在 $O(n^2)$ 上：

- **有序数组 + `insert`**：二分找位 $O(\log n)$，但中间插入要整体搬移后续元素，单步 $O(n)$，总计 $O(n^2)$ 次移动；
- **只数不插**：每步对已插入元素逐个比较数出两侧个数，单步仍 $O(n)$，总计约 $10^{10}$ 次比较。

瓶颈定位清晰：**$n$ 次查询 × 每次查询 $O(n)$，且每次查询后紧跟一次插入**。要让「按值计数」与「插入」都降到 $O(\log)$，就需要一个频次结构——这正是树状数组（BIT）的招牌场景。

### 3.2 核心观察：只数不插——值域频次 + 前缀和

![核心观察：代价只与两侧计数有关，翻译为值域频次的前缀和](images/wc214_q4_insert_cost_concept.svg)

**观察 1（代价与位置无关）**：题面把代价定义为插入**之前**整个 `nums` 的两个全局计数的 $\min$，与插入到哪个位置无关。因此无需维护数组形态，只需对每个新元素 $x$ 回答两个关于「已插入多重集 $S$」的计数问题。

**观察 2（计数 → 前缀和）**：值域 $[1, 10^5]$ 紧凑，直接开频次桶 $\text{freq}[1..V]$（$V = \max(\text{instructions})$），记前缀和 $P(t) = \sum_{u=1}^{t} \text{freq}[u]$，则

$$\text{less} = \#\{v \in S : v < x\} = P(x-1), \qquad \text{greater} = \#\{v \in S : v > x\} = \text{total} - P(x)$$

其中 $\text{total} = |S|$ 用普通变量 $O(1)$ 维护。**等于 $x$ 的元素被两侧同时排除**——重复值不付任何代价，这正是示例 3 连插三个 3 每次代价都是 0 的原因，也解释了 $\text{greater}$ 为什么用 $\text{total} - P(x)$（减去 $\le x$ 的）而不是 $\text{total} - P(x-1)$（只减去 $< x$ 的）。

**观察 3（交替的单点加与前缀查）**：每轮固定「两查一插」：两次前缀查询 $P(x-1)$、$P(x)$ 与一次单点 $+1$。这种「单点更新 ⇄ 前缀求和」的交替正是 BIT 的标准操作对，各 $O(\log V)$；$V \le 10^5$ 时 $\log V \approx 17$，总计约 $5 \times 10^6$ 次数组访问。

> 💡 为什么不用「有序数组 + 二分」？二分查询虽 $O(\log n)$，但插入需搬移 $O(n)$；BIT 反其道而行——**不做位置维护，只做频次统计**，插与查都是 $O(\log V)$。「需要按值计数」而不是「需要有序序列」时，BIT 几乎总是更轻的选择。

### 3.3 算法流程

![算法流程：每个 x 一轮「两查、取 min、一插」](images/wc214_q4_bit_flow.svg)

```text
1. 初始化：V ← max(instructions)，BIT 开 V+1 个桶（1-indexed）
   cost = 0，total = 0
2. 按 instructions 顺序取每个 x：
     less    ← query(x − 1)            # 严格小于 x 的个数
     greater ← total − query(x)         # 严格大于 x 的个数
     cost    ← cost + min(less, greater)
     update(x, +1)，total ← total + 1   # 插入 x
3. 返回 cost mod (10⁹ + 7)
```

> ⚠️ **顺序纪律：先两查、后一插**。若先 `update(x)` 再查询，$x$ 自己会被数进前缀 $P(x)$，`greater` 直接少 1，从第一步起就失真。

### 3.4 示例演算

![示例演算：instructions = [1,5,6,2] 逐轮两查一插](images/wc214_q4_bit_walkthrough.svg)

以示例 1 `instructions = [1,5,6,2]` 走查（$V = 6$）：

| 步 | $x$ | 插入前 nums | less $=P(x{-}1)$ | greater $=\text{total}{-}P(x)$ | cost |
|----|-----|-------------|------------------|-------------------------------|------|
| ① | 1 | $[]$ | $P(0) = 0$ | $0 - P(1) = 0$ | 0 |
| ② | 5 | $[1]$ | $P(4) = 1$ | $1 - P(5) = 0$ | 0 |
| ③ | 6 | $[1,5]$ | $P(5) = 2$ | $2 - P(6) = 0$ | 0 |
| ④ | 2 | $[1,5,6]$ | $P(1) = 1$ | $3 - P(2) = 2$ | **1** |

总代价 $= 0+0+0+1 = 1$ ✓。**步 ④ 是精髓**：此刻频次表为 $\text{freq}[1]=1$、$\text{freq}[5]=\text{freq}[6]=1$，故 $P(1) = 1$（只有 1 比 2 小）、$P(2) = 1$（值 $\le 2$ 的仍只有 1），$\text{greater} = 3 - 1 = 2$。取 $\min(1, 2) = 1$。

再用示例 3 `instructions = [1,3,3,3,2,4,2,1,2]` 验证**重复值零成本**：

| 步 | $x$ | less | greater | cost | 说明 |
|----|-----|------|---------|------|------|
| ① | 1 | 0 | 0 | 0 | 最小值白嫖 |
| ② | 3 | 1 | 0 | 0 | |
| ③ | 3 | 1 | 0 | 0 | 与已有 3 相等，两侧都不计 |
| ④ | 3 | 1 | 0 | 0 | 同上 |
| ⑤ | 2 | 1 | 3 | **1** | $\min(1,3)$ |
| ⑥ | 4 | 5 | 0 | 0 | 最大值白嫖 |
| ⑦ | 2 | 1 | 4 | **1** | |
| ⑧ | 1 | 0 | 6 | 0 | 新最小值 |
| ⑨ | 2 | 2 | 4 | **2** | $\min(2,4)$ |

总代价 $= 4$ ✓。三步插 3 的代价全为 0——**相等的值既不落入 $P(x-1)$ 也不被 $\text{total} - P(x)$ 数到**，重复值是本题最便宜的插入。

## 4. 算法细节

1. **值域即下标，免离散化**：$V = \max(\text{instructions}) \le 10^5$，且 $\text{instructions}[i] \ge 1$ 天然满足 BIT 的 1-indexed 约定（下标 0 弃用）。若值域达 $10^9$ 或含负数，需先排序去重做保序离散化（`instructions` 全量预知，可离线完成）。
2. **两条查询的方向差一格**：`less = query(x−1)`（值 $\le x-1$ 即 $< x$），`greater = total − query(x)`（减去值 $\le x$ 的部分）。等号归 `greater` 一侧的公式处理，重复值无须任何特判。
3. **total 与 BIT 并行维护**：`total` 就是一棵「已插入总数」，用普通变量随插入 $+1$，绝不用树去求和；BIT 只负责值域频次。
4. **先查后改**：每轮必须先算 `less`、`greater` 再 `update(x)`，否则 $x$ 会被数进 $P(x)$。
5. **溢出控制**：每步 $\min(\text{less}, \text{greater}) \le (i-1)/2$，总代价上界 $\sum_{i}(i-1)/2 = \frac{n(n-1)}{4} \approx 2.5 \times 10^9$，超过 32 位 `int`（约 $2.1 \times 10^9$）。C++ 用 `long long` 全程累加、**最后统一取模**；Python 原生大整数无此问题。
6. **操作配额固定**：每轮两次 `query` + 一次 `update`，均 $O(\log V)$，无任何隐藏的线性开销——这是本解法通过 $n = 10^5$ 的全部底气。

## 5. 正确性证明

**引理 1（代价的计数表示）**：设某步插入 $x$ 之前，已插入元素构成多重集 $S$，$|S| = m$，频次 $\text{freq}[u] = \#\{v \in S : v = u\}$，前缀和 $P(t) = \sum_{u=1}^{t} \text{freq}[u]$（约定 $P(0) = 0$）。则该步代价为 $\min\big(P(x-1),\; m - P(x)\big)$。

**证明**：值严格小于 $x$ 的元素，其值恰好取遍 $[1, x-1]$ 内出现过的值，故 $\#\{v \in S : v < x\} = \sum_{u=1}^{x-1} \text{freq}[u] = P(x-1)$。$S$ 中每个元素要么 $v \le x$ 要么 $v > x$，两类不重不漏，故 $\#\{v \in S : v > x\} = m - \#\{v \le x\} = m - P(x)$。由题意，代价为二者之 $\min$。∎

**引理 2（BIT 维护前缀和）**：BIT 在值域 $[1, V]$ 上初始化为全零。执行任意次 `update(i)`（使 $\text{freq}[i] \mathrel{+}= 1$）后，对一切 $t \in [0, V]$，`query(t)` $= P(t)$。

**证明**：BIT 节点 $j$ 覆盖区间 $(j - \mathrm{lowbit}(j),\ j]$。一方面，`update(i)` 沿 $i \to i + \mathrm{lowbit}(i) \to \cdots$ 访问的节点恰是全部覆盖 $i$ 的节点且各一次：若 $j$ 覆盖 $i$，则 $i$ 位于 $(j - \mathrm{lowbit}(j), j]$ 内，从 $i$ 出发逐次加当前 lowbit 必经 $j$（标准 BIT 性质）；链外节点不覆盖 $i$，值不变。另一方面，`query(t)` 沿 $t \to t - \mathrm{lowbit}(t) \to \cdots$ 取的节点覆盖区间两两不交且并为 $[1, t]$。因此对 `update` 次数归纳：任一时刻每个节点的值等于其覆盖区间内的频次之和，从而 `query(t)` 读到的和恰为 $\sum_{u=1}^{t} \text{freq}[u] = P(t)$；$t = 0$ 时循环不执行返回 0，与 $P(0) = 0$ 一致。∎

**定理（算法正确性）**：算法返回 $\sum_{i=1}^{n} c_i \bmod (10^9 + 7)$，其中 $c_i$ 为按题意第 $i$ 步的插入代价。

**证明**：对 $i$ 归纳证明不变式：**第 $i$ 步开始时，BIT 的隐含频次表恰为前 $i-1$ 个元素的多重集频次，且 $\text{total} = i - 1$**。$i = 1$ 时两者皆空，成立。设第 $i$ 步开始时成立，记 $x = \text{instructions}[i]$。算法先查询：由引理 2，$\text{query}(x-1) = P(x-1)$、$\text{query}(x) = P(x)$（均针对当前频次表）；由引理 1，$\text{cost}$ 的增量 $\min\big(P(x-1), (i-1) - P(x)\big)$ 恰为 $c_i$。随后算法执行 `update(x)` 与 $\text{total} \mathrel{+}= 1$，频次表恰变为前 $i$ 个元素的多重集频次、$\text{total} = i$，不变式延续到第 $i+1$ 步。归纳完成，累加值 $\sum c_i$ 正确。又每步 $c_i \le (i-1)/2$，故 $\sum c_i \le \frac{n(n-1)}{4} < 2.5 \times 10^9 \ll 2^{63}$，`long long` 累加无溢出，最后一次取模即得题意答案。∎

## 6. 复杂度分析

- **时间复杂度**：$O(n \log V)$。遍历 $n$ 个元素，每轮两次前缀查询 + 一次单点更新，各 $O(\log V)$；$V = \max(\text{instructions}) \le 10^5$，$\log V \approx 17$，总计约 $5 \times 10^6$ 次基本操作。
- **空间复杂度**：$O(V)$。BIT 数组 $V + 1$ 个桶；`total`、`cost` 等仅 $O(1)$ 附加。若值域过大需离散化，空间变为 $O(n)$、时间变为 $O(n \log n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
  public:
    int createSortedArray(vector<int>& instructions) {
        const int MOD = 1'000'000'007;
        int m = *max_element(instructions.begin(), instructions.end());
        vector<int> tree(m + 1);                    // 1-indexed 频次 BIT

        auto update = [&](int i) {
            for (; i <= m; i += i & -i) tree[i]++;
        };
        auto query = [&](int i) {                   // 值 <= i 的累计频次
            int s = 0;
            for (; i > 0; i -= i & -i) s += tree[i];
            return s;
        };

        long long cost = 0;
        int total = 0;
        for (int x : instructions) {
            int less = query(x - 1);               // 严格小于 x
            int greater = total - query(x);        // 严格大于 x
            cost += min(less, greater);
            update(x);                              // 先查后改
            ++total;
        }
        return cost % MOD;
    }
};
```

### Python

```python
class Solution:
    def createSortedArray(self, instructions: List[int]) -> int:
        MOD = 10**9 + 7
        m = max(instructions)
        tree = [0] * (m + 1)                        # 1-indexed 频次 BIT

        def update(i: int) -> None:
            while i <= m:
                tree[i] += 1
                i += i & -i

        def query(i: int) -> int:                    # 值 <= i 的累计频次
            s = 0
            while i > 0:
                s += tree[i]
                i -= i & -i
            return s

        cost = 0
        total = 0
        for x in instructions:
            less = query(x - 1)                      # 严格小于 x
            greater = total - query(x)               # 严格大于 x
            cost += min(less, greater)
            update(x)                               # 先查后改
            total += 1
        return cost % MOD
```

## 8. 边界情况与易错点

1. **`int` 溢出（本题最经典的坑）**：交替插入极值的顺序（如 $1, n, 2, n-1, \dots$）每步都能让两侧计数接近对半，总代价逼近 $\frac{n(n-1)}{4} \approx 2.5 \times 10^9 > 2^{31} - 1 \approx 2.1 \times 10^9$。C++ 必须用 `long long` 累加、最后取模；Python 大整数天然安全。
2. **`greater` 公式的等号**：必须用 $\text{total} - \text{query}(x)$（减去 $\le x$ 的）。误写成 $\text{total} - \text{query}(x-1)$ 会把等于 $x$ 的元素算进「更大」，重复值多的数据直接 WA——试金石：$[1,1,1]$ 正确答案 0，错误公式返回 $0 + 1 + 2 = 3$。
3. **先查后改**：先 `update(x)` 再查询会把 $x$ 自己数进 $P(x)$，`greater` 恒少 1。
4. **`query(0)` 天然安全**：$x = 1$ 时 `query(x-1) = query(0)`，循环条件 `i > 0` 不成立直接返回 0，无须特判最小值。
5. **取模时机**：`min` 必须在取模**之前**算（本题每步代价远小于模，可全程 `long long` 累加最后一次性取模）；若每步取模则要小心别对取模后的值做比较。
6. **别真的去维护有序数组**：`vector::insert` / `list` 中间插入的搬移让「二分 + 插入」退回 $O(n^2)$——「有序」只是题面包装，需求其实是频次统计。
7. **BIT 大小与下标**：桶数取 $\max(\text{instructions}) + 1$（下标 0 弃用）；本题值域从 1 开始，若含 0 或负数需先平移或离散化。
8. **$n = 1$**：唯一的插入代价为 0，返回 0；上述流程无需特判即可正确处理。
