# LeetCode 将石头分散到网格图的最少移动次数 题解

## 1. 题目概述

- **标题 / 题号**：将石头分散到网格图的最少移动次数（#2850，medium）
- **链接**：https://leetcode.cn/problems/minimum-moves-to-spread-stones-over-grid/
- **来源**：LeetCode 第 362 场周赛 Q3
- **难度**：中等
- **标签**：状态压缩、动态规划、回溯、位运算、矩阵

**题意**：给一个 $3 \times 3$ 的矩阵 `grid`，`grid[i][j]` 表示格子 $(i, j)$ 里的石头数，全图恰好 9 块（一个格子可以有多块）。一次移动可以把一块石头移到与当前格子**至少共享一条边**的相邻格子。要让每个格子恰好 1 块石头，返回最少移动次数。

**约束**：

- `grid.length == grid[i].length == 3`
- `0 <= grid[i][j] <= 9`
- `grid` 中元素之和为 9

> 💡 读题关键：石头之间互不阻挡、格子中途可以堆叠——因此每块石头的移动**彼此独立**，总代价只由「哪块石头从哪格走到哪格」决定。又因为石头总数 $9$ = 格子数 $9$，「多余」的石头数恰好等于空格数，天然形成一对一的**分配问题**。

## 2. 示例

**示例 1**

```text
输入：grid = [[1,1,0],[1,1,1],[1,2,1]]
输出：3
解释：(2,1) 有 2 块石头，(0,2) 是空格：把多出的一块经 (2,2)、(1,2) 送到 (0,2)，共 3 步。
```

**示例 2**

```text
输入：grid = [[1,3,0],[1,0,0],[1,0,3]]
输出：4
解释：(0,1) 与 (2,2) 各多 2 块；4 个空格 (0,2)、(1,1)、(1,2)、(2,1) 各收 1 块，
每块都只走 1 步，共 4 步。
```

**示例 3（已满足边界）**

```text
输入：grid = [[1,1,1],[1,1,1],[1,1,1]]
输出：0
解释：每格恰好 1 块，无需移动；此时空格数 m = 0，算法应直接返回 0。
```

## 3. 解题思路

### 3.1 暴力思路：把整个网格当状态 BFS

最直接的想法是把「9 个格子的石子数分布」整体当成状态：从初态出发，每步枚举「哪个格子的哪块石头往哪个方向挪」，BFS 到每格恰好 1 块的状态。状态数即「把 9 个石子放进 9 个带标号格子」的方案数 $\binom{17}{8} = 24310$，每个状态至多 $9 \times 4$ 种转移——BFS 完全能过，但要写状态编码、哈希去重，比赛里性价比很低。

真正的突破口是注意到：**一次移动只影响一块石头**。对整张网格做联动搜索，浪费了这份独立性。

### 3.2 核心观察：多余石头 → 空格的最小权完美匹配

![核心观察：cnt>1 的格子发货、cnt=0 的格子收货，答案是最小权完美匹配](images/wc362_q3_matching_concept.svg)

按石子数把格子分成三类：

- $\text{cnt} = 1$：不**发货**也不**收货**，原地不动（引理 2 保证这样不亏）；
- $\text{cnt} > 1$：发出 $\text{cnt} - 1$ 块多余石头，同一格子的多块石头视为**互不相同的源**；
- $\text{cnt} = 0$：收下恰好 1 块。

由 $\sum \text{cnt} = 9 = $ 格子数，**发货总量 = 收货总量**，两侧个数相等，记为 $m \le 8$（最坏一个格子堆满 9 块）。又因四连通网格中一块石头从 $a$ 走到 $b$ 至少要 $|\Delta r| + |\Delta c|$ 步、且恰好可以达成（引理 1），问题变成：

$$\text{最少步数} \;=\; \min_{\text{完美匹配 } M} \;\sum_{(s,\,t)\,\in\,M} \Bigl( |r_s - r_t| + |c_s - c_t| \Bigr)$$

一个规模至多 $8 \times 8$ 的**最小权完美匹配**（边权 = 曼哈顿距离）。

### 3.3 算法流程：状压 DP（或等价的回溯枚举排列）

![算法流程：状压 DP 四步，mask 与 popcount 对齐](images/wc362_q3_bitmask_dp_flow.svg)

匹配规模太小，用不上 KM 算法 / 费用流，两条比赛友好路线任选其一：

**状压 DP**：把 $m$ 个空格编号为 $0 \sim m-1$（记为 $t_0, \dots, t_{m-1}$），源按任意固定顺序排成序列 $s_0, s_1, \dots, s_{m-1}$。设 $\text{dp}[\text{mask}]$ = 已填好 mask 中的空格、用掉前 $\text{popcount(mask)}$ 份源的最少步数，则

$$\text{dp}[\text{mask} \mid 1 \ll j] \;\leftarrow\; \min\Bigl(\,\cdot\,,\;\; \text{dp}[\text{mask}] + \text{dist}\bigl(s_{\text{popcount(mask)}},\; t_j\bigr)\Bigr), \qquad j \notin \text{mask}$$

「mask 里已有几个 1」与「已消耗几份源」自动对齐，是这类分配型状压 DP 的标准技巧。

**回溯**：本质相同——按序给第 $k$ 份源挑一个还没被占用的空格，枚举全部配对方案，$m! \le 8! = 40320$，同样瞬间跑完。

### 3.4 示例演算

![示例演算：示例 1 与示例 2 的最短路匹配](images/wc362_q3_example_walkthrough.svg)

以示例 2 为例：src = (0,1), (0,1), (2,2), (2,2)，dst = (0,2), (1,1), (1,2), (2,1)。最优分配是「就近配对」——(0,1) 的两块分别去 (0,2) 和 (1,1)，(2,2) 的两块分别去 (1,2) 和 (2,1)，每块恰好走 1 步，总步数 $4$，与官方答案一致。示例 1 只有一份源：从 (2,1) 到空格 (0,2)，$d = 2 + 1 = 3$。

注意「就近」只是直觉，不构成证明：交换论证（引理 2）+ 匹配下界（定理）才是正确性的来源——DP / 回溯帮我们在 $m!$ 种配对里**取到全局最优**，而不是贪心。

## 4. 算法细节

1. **源要按份数展开**：$\text{cnt} = 3$ 的格子要向 src 追加 **2** 份（每份都是一块独立的石头），漏乘会把匹配规模算错，WA 而非 TLE，非常隐蔽。
2. **popcount 对齐**：转移消耗的是第 $\text{popcount(mask)}$ 份源（0 起）——mask 每多一个 1 就意味着多消耗一份源，下标天然同步，无需额外记录「用了哪些源」。
3. **初始化与答案**：$\text{dp}[0] = 0$，答案 $\text{dp}[(1 \ll m) - 1]$；$m = 0$（初始即目标）时数组大小为 1，直接返回 0。
4. **距离 O(1) 计算**：曼哈顿距离 $= |r_1 - r_2| + |c_1 - c_2|$，无需 BFS 预处理——网格无障碍、中途无容量限制。
5. **两侧规模必相等**：源总数 $= \sum_{\text{cnt} > 1} (\text{cnt} - 1) = $ 空格数（由总和为 9 保证），写代码时可以 `assert` 一份保险。

## 5. 正确性证明

**引理 1**（单块石头的代价）：一块石头从格子 $a$ 走到格子 $b$，最少移动次数恰为 $d(a,b) = |r_a - r_b| + |c_a - c_b|$。

**证明**：每步移到四连通相邻格，行、列坐标中恰有一个变化 $\pm 1$，故曼哈顿距离每步至多减少 1，步数 $\ge d(a,b)$。反之，先沿行对齐、再沿列对齐（任意单调路径），恰好 $|\Delta r| + |\Delta c|$ 步可达——途径格子的石子数没有上限，不会被卡住 ∎

**引理 2**（留守不变性）：存在一个最优方案，使得初始时位于「恰好 1 块石头」格子里的石头全程不动。

**证明**：在所有最优方案中，取「移动的留守石头」数量最少的一个。反设该方案中留守石头 $x$ 从格子 $c$ 移到 $d$，则必有一块石头 $y$ 最终停入 $c$，设 $y$ 来自 $e \ne c$（$c$ 初始只有 $x$）。把两段行程改为：$x$ 原地不动、$y$ 从 $e$ 直达 $d$。由三角不等式 $\text{dist}(e, d) \le \text{dist}(e, c) + \text{dist}(c, d)$，新方案总步数不增，但「移动的留守石头」数严格减少，与最小性矛盾 ∎

**定理**：最少总移动次数 = 多余石头与空格之间以曼哈顿距离为权的最小权完美匹配。

**证明**：
（≥）任一合法方案给每块石头一条轨迹，由引理 1，每块石头的步数 $\ge$ 其起点到终点的曼哈顿距离；终局每格恰 1 块，故全部轨迹的终点构成「石头 → 格子」的双射。由引理 2 可设留守石头起点 = 终点（贡献 0），于是仍在移动的石头恰是从各「多余格子」发出的 $\text{cnt} - 1$ 块，其终点恰是全部空格——即一个完美匹配。因此总步数 $\ge$ 该匹配的权 $\ge$ 最小匹配权。
（≤）给定任一匹配，令每块多余石头沿最短路独立走到配对空格、其余石头不动：各石头的移动可任意交错执行、互不阻挡（引理 1 的可达性），总步数 = 匹配权；对最小权匹配取等。
两边夹逼得证 ∎

## 6. 复杂度分析

- **时间复杂度**：$O(2^m \cdot m)$，$m \le 8$，至多约 $2 \times 10^3$ 次转移，加上收集源 / 汇的 $O(9)$；回溯版 $O(m!) \le 40320$，同样可忽略不计。
- **空间复杂度**：$O(2^m)$——dp 数组至多 256 个整数；回溯版只需 $O(m)$ 递归栈与位标记。

## 7. 参考代码

### C++（状压 DP）

```cpp
class Solution {
  public:
    int minimumMoves(vector<vector<int>>& grid) {
        vector<pair<int, int>> src, dst;
        for (int i = 0; i < 3; i++) {
            for (int j = 0; j < 3; j++) {
                if (grid[i][j] > 1) {
                    src.insert(src.end(), grid[i][j] - 1, make_pair(i, j));
                } else if (grid[i][j] == 0) {
                    dst.push_back({i, j});
                }
            }
        }
        int m = dst.size(), full = (1 << m) - 1;
        const int INF = 1e9;
        vector<int> dp(1 << m, INF);
        dp[0] = 0;
        for (int mask = 0; mask <= full; mask++) {
            if (dp[mask] == INF) continue;
            int k = __builtin_popcount(mask);
            for (int j = 0; j < m; j++) {
                if (mask >> j & 1) continue;
                int cost = abs(src[k].first - dst[j].first)
                         + abs(src[k].second - dst[j].second);
                dp[mask | 1 << j] = min(dp[mask | 1 << j], dp[mask] + cost);
            }
        }
        return dp[full];
    }
};
```

### Python（回溯枚举配对）

```python
class Solution:
    def minimumMoves(self, grid: List[List[int]]) -> int:
        src, dst = [], []
        for i in range(3):
            for j in range(3):
                if grid[i][j] > 1:
                    src += [(i, j)] * (grid[i][j] - 1)
                elif grid[i][j] == 0:
                    dst.append((i, j))
        n = len(dst)

        def dfs(k: int, used: int) -> int:
            if k == len(src):
                return 0
            best = float('inf')
            for j in range(n):
                if used >> j & 1:
                    continue
                d = abs(src[k][0] - dst[j][0]) + abs(src[k][1] - dst[j][1])
                best = min(best, d + dfs(k + 1, used | 1 << j))
            return best

        return dfs(0, 0)
```

## 8. 边界情况与易错点

1. **距离是曼哈顿，不是切比雪夫**：本题只能移到「共享一条边」的格子，对角线一步非法。同场 Q2（#2849 判断能否在给定时间到达单元格）的相邻定义是共享角的 **8 方向**、答案与切比雪夫距离比较——两题挨着做极易串味，动笔前先看清「共享边」还是「共享角」。
2. **多份源别漏乘**：cnt=3 要提供 2 份源、cnt=9 要提供 8 份；按 1 份写不会 TLE，只会 WA，调试时优先怀疑这里。
3. **m = 0 直接返回 0**：已是目标状态时 dp 数组大小为 1，返回 dp[0]；回溯版在 `k == len(src)` 处返回 0。
4. **popcount 对齐别写反**：转移消耗的是第 popcount(mask) 份源（从 0 数起）；C++ 用 `__builtin_popcount`，Python 用 `bin(mask).count('1')`。
5. **回溯必须标记已用空格**：`used` 位掩漏掉会把同一空格填两次，答案偏小。
6. **不要把 cnt=1 的格子拉进匹配**：由引理 2 它们原地不动；硬加进去要枚举 $9! \approx 3.6 \times 10^5$ 种排列，白白放大状态还毫无收益。
7. **别贪心「就近填」**：局部就近可能整体次优（贪心不满足交换性质），必须老老实实 DP / 回溯求全局最优。
