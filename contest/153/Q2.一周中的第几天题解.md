# LeetCode 一周中的第几天 题解

## 1. 题目概述

- **标题 / 题号**：一周中的第几天（#1185，easy）
- **链接**：https://leetcode.cn/problems/day-of-the-week/
- **来源**：LeetCode 第 153 场周赛 Q2
- **难度**：简单
- **标签**：数学

**题意**：给定三个整数 $day$、$month$、$year$，表示一个公历日期，返回该日期是星期几。返回值必须是 `"Sunday"`、`"Monday"`、`"Tuesday"`、`"Wednesday"`、`"Thursday"`、`"Friday"`、`"Saturday"` 之一（完整英文单词、首字母大写）。题目额外给出一个锚点：**1971 年 1 月 1 日是星期五**。

**约束**：

- 给出的日期一定是 $1971$ 到 $2100$ 年之间的**合法日期**
- 只需处理公历（格里历），不需要考虑 1582 年的历法切换
- 返回字符串必须与给定的 7 个单词完全一致（不能返回 `"Sat"` 之类的缩写）

## 2. 示例

**示例 1**

```text
输入：day = 31, month = 8, year = 2019
输出："Saturday"
解释：2019 年 8 月 31 日是星期六。
```

**示例 2**

```text
输入：day = 18, month = 7, year = 1999
输出："Sunday"
解释：1999 年 7 月 18 日是星期日。
```

**示例 3**

```text
输入：day = 15, month = 8, year = 1993
输出："Sunday"
解释：1993 年 8 月 15 日是星期日。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是**逐日模拟**：从 1971-01-01 出发，每走一天让星期指针加一，一直走到目标日期。

这种做法完全正确，但把「日期与星期的换算」这件本质是**线性函数**的事情，藏进了一个循环里：

- 1971 到 2100 之间共有 $47482$ 天，最坏要循环近 5 万次；本次数据量下能过，但只要年份上界稍微放大（比如到 $10^9$ 年）就立刻爆炸；
- 另一种「捷径」是调用语言内置的日期库（C++ 的 `tm` + `mktime`、Python 的 `datetime`），但它们有年份偏移（`tm_year` 从 1900 起算）、时区依赖、平台差异等一堆坑，比赛里既不可控也不可移植。

所以目标很明确：找出一个**与年份范围无关的常数时间闭式**。

### 3.2 核心观察：把日期折算成「距锚点的天数」，闰年个数有闭式

![三段天数分解：整年 + 整月 + 当月](images/wc153_q2_days_breakdown.svg)

**观察一：星期只取决于「走过的天数」。** 日期每往后一天，星期就在那 7 个词的循环里前进一格。既然 1971-01-01 是星期五（在「Sunday 开头」的表中索引 5），那么

$$\text{idx}(day, month, year) = \bigl(f(day, month, year) + 5\bigr) \bmod 7$$

其中 $f$ 是从 1971-01-01 到目标日期**经过**的天数（目标当天不计）。

**观察二：$f$ 可以拆成三段，每段都能 $O(1)$ 求和。** 把半开区间 $[1971\text{-}01\text{-}01,\ day/month/year)$ 切成互不相交的三块：

1. **整年**：完整的 $1971, \dots, year-1$ 共 $year-1971$ 年，每年 365 天，闰年再多 1 天；
2. **整月**：$year$ 年内，1 月到 $month-1$ 月；
3. **当月**：本月 1 日到 $day-1$ 日，共 $day-1$ 天。

第二、三段的长度都是常数级累加（月份最多 12 个）；真正需要技巧的只有第一段里的**闰年个数**。而它恰好有一个漂亮的容斥闭式：

$$L(x) = \left\lfloor \frac{x}{4} \right\rfloor - \left\lfloor \frac{x}{100} \right\rfloor + \left\lfloor \frac{x}{400} \right\rfloor$$

$L(x)$ 统计 $[1, x]$ 中的闰年个数（4 的倍数，扣掉 100 的倍数，再补回 400 的倍数），于是区间 $[1971,\ year-1]$ 内的闰年个数就是差分 $L(year-1) - L(1970)$。

> 💡 这三段划分正是官方提示的三条（先加整年、处理闰年、再加各月天数），只是用一个 $O(1)$ 公式取代了逐年累加。

### 3.3 算法流程

![算法流程：闰年判定 → 三段累加 → 取模 → 查表](images/wc153_q2_algorithm_flow.svg)

1. 预处理两张常量表：星期名 `names[7]`（Sunday 打头）、各月天数 `mdays[1..12]`（2 月按 28 天）。
2. 判定 $year$ 是否为闰年：$year$ 是 4 的倍数且不是 100 的倍数，或者 $year$ 是 400 的倍数。
3. 计算整年天数 $365 \times (year - 1971)$，加上闰年个数 $L(year-1) - L(1970)$。
4. 累加 1 到 $month-1$ 月的月长；累加时若某月是 2 月且 $year$ 是闰年，该月按 29 天。
5. 加上 $day - 1$，得到 $total = f$。
6. 返回 `names[(total + 5) % 7]`。

### 3.4 示例演算

![示例演算：2019-08-31 → Saturday](images/wc153_q2_walkthrough.svg)

以示例 1 的 $2019$ 年 8 月 31 日为例：

| 步骤 | 计算 | 天数 |
|------|------|------|
| 整年 | $365 \times (2019-1971) = 365 \times 48$ | $17520$ |
| 闰年 | $L(2018) - L(1970) = 489 - 477 = 12$（1972、1976、…、2016） | $+12$ |
| 整月 | 1–7 月：$31+28+31+30+31+30+31$（2019 非闰年，2 月 28 天） | $+212$ |
| 当月 | $day - 1 = 31 - 1$ | $+30$ |
| 合计 | $17520 + 12 + 212 + 30$ | $17774$ |
| 取模 | $(17774 + 5) \bmod 7 = 17779 \bmod 7 = 6$ | `"Saturday"` |

另外两组官方示例同样对得上：$1999$ 年 7 月 18 日得 $total = 365 \times 28 + (L(1998)-L(1970)) + 181 + 17 = 10220 + 7 + 181 + 17 = 10425$，$(10425+5) \bmod 7 = 0$，索引 0 即 `"Sunday"`；$1993$ 年 8 月 15 日得 $total = 8030 + 6 + 212 + 14 = 8262$，$(8262+5) \bmod 7 = 0$，同样是 `"Sunday"`。

## 4. 算法细节

1. **闰年判定顺序不能反**：先看 `y % 4 == 0 && y % 100 != 0`，再 `|| y % 400 == 0`。若写成 `y % 4 == 0 || y % 400 == 0` 就会把 2100 误判成闰年（2100 是 100 的倍数但不是 400 的倍数，不是闰年）。
2. **闰年计数用差分而非循环**：$L(x)$ 的公式对 $x \ge 0$ 均成立，区间个数 $L(year-1) - L(1970)$ 无需特判 1970 是否闰年（1970 不是，但差分形式本来就不依赖这一点）。
3. **偏移量 $+5$ 的来源**：`names` 以 Sunday 为索引 0，则 Friday 的索引是 5；$total = 0$ 对应 1971-01-01，故 $(0+5) \bmod 7 = 5$ 必须返回 `"Friday"`。写完后用这个锚点自检一遍，能第一时间发现「偏移写成 4 或 6」的低级错误。
4. **月前缀用哨兵**：把 `mdays` 存成 13 项并令 `mdays[0] = 0`，循环 `for m in 1..month-1: total += mdays[m]`，省去下标平移，也不容易越界。
5. **闰日只补一次**：2 月的额外一天只在「2 月已经完整走完」时才计入，即 `m == 2 && isLeap(year)`。因为循环上界是 $month-1$，当 $month = 1$ 或 $2$ 时循环根本不会碰到 2 月，天然不会多加。
6. **整数范围**：$total \le 47481$，`int` 完全够用；但仍建议用 `long long`（Python 无此问题），这样把年份上界改成 $10^9$ 时不会溢出。
7. **不要在代码里出现年月日以外的分支**：整个算法没有分支依赖输入规模，也不做字符串拼接，7 个答案串直接由常量表给出，避免拼写/大小写错误。

## 5. 正确性证明

**引理 1（天数决定星期）**：设 $f(D)$ 为从 1971-01-01 到日期 $D$ 经过的天数（$D$ 当天不计），则 $D$ 的星期索引（Sunday 为 0）等于 $(f(D) + 5) \bmod 7$。

**证明**：对 $f(D)$ 归纳。$f(D) = 0$ 时 $D$ 就是 1971-01-01，已知为星期五，而 $(0+5) \bmod 7 = 5$ 正是 `names[5]` 对应的 `"Friday"`，成立。设对 $f(D) = k$ 成立，令 $D'$ 为 $D$ 的后一天，则 $f(D') = k+1$；公历中连续两天的星期名在 7 天循环里相邻，故索引加一后取模，得 $((k+5)+1) \bmod 7 = (f(D')+5) \bmod 7$，命题对 $k+1$ 成立。由归纳法，对所有合法日期成立。∎

**引理 2（三段分解）**：设 $len(m, y)$ 为 $y$ 年第 $m$ 月的天数，则

$$f(day, month, year) = 365(year - 1971) + c(1971, year-1) + \sum_{m=1}^{month-1} len(m, year) + (day - 1)$$

其中 $c(1971, year-1)$ 是区间 $[1971, year-1]$ 内的闰年个数。

**证明**：半开区间 $[1971\text{-}01\text{-}01,\ D)$ 可按时间顺序唯一拆成三段互不相交的部分：(i) 完整年份 $1971, \dots, year-1$ 的全部日子；(ii) $year$ 年内 1 月到 $month-1$ 月的全部日子；(iii) $year$ 年 $month$ 月 1 日到 $day-1$ 日。每段长度分别为 $365(year-1971) + c$（平年 365 天、闰年 366 天，差额恰由闰年个数补齐）、$\sum len(m, year)$、$day-1$。三段互不重叠且并起来正好是整个区间，故求和即为 $f$。∎

**引理 3（闰年前缀闭式）**：$L(x) = \lfloor x/4 \rfloor - \lfloor x/100 \rfloor + \lfloor x/400 \rfloor$ 等于 $[1, x]$ 内的闰年个数，且 $c(1971, year-1) = L(year-1) - L(1970)$。

**证明**：公历闰年定义为「4 的倍数中排除 100 的倍数，但补回 400 的倍数」。$[1,x]$ 内 4 的倍数有 $\lfloor x/4 \rfloor$ 个，其中 100 的倍数有 $\lfloor x/100 \rfloor$ 个，其中 400 的倍数有 $\lfloor x/400 \rfloor$ 个且被上一步误删，故按容斥原理加上，恰得 $L(x)$。又区间计数满足前缀差分，故 $[1971, year-1]$ 的个数为 $L(year-1) - L(1970)$。∎

**定理**：上述算法返回的字符串就是给定日期的正确星期名。

**证明**：由引理 3 算出闰年个数 $c$，由引理 2 算出经过天数 $f$（代码中累加的三段与引理 2 的公式逐项对应：整年、整月的 `mdays` 前缀和、以及 $day-1$；其中 2 月按 $year$ 是否为闰年取 28 或 29，与 $len(2, year)$ 的定义一致），再由引理 1 得索引 $(f+5) \bmod 7 \in [0,6]$。`names` 表的 7 个元素按顺序恰好是 Sunday 到 Saturday，与索引一一对应，且都在题目允许的取值集合内，故返回值为正确星期名。∎

## 6. 复杂度分析

- **时间**：$O(1)$。闰年判定、$L(x)$ 的两次求值、12 次以内的月份循环、一次取模，全部是常数次算术运算，与年份跨度无关（即便把上界从 2100 改到 $10^{9}$ 也是同样快）。
- **空间**：$O(1)$。只有两张长度 7 与 13 的常量表、几个整型变量，没有随输入增长的存储。

## 7. 参考代码

### C++

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string dayOfTheWeek(int day, int month, int year) {
        static const string names[7] = {"Sunday", "Monday", "Tuesday", "Wednesday",
                                        "Thursday", "Friday", "Saturday"};
        // mdays[0] 为哨兵，下标 1..12 对应 1..12 月的天数（2 月按平年 28 天）
        static const int mdays[13] = {0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};

        auto isLeap = [](int y) {
            return (y % 4 == 0 && y % 100 != 0) || y % 400 == 0;
        };
        // [1, x] 内的闰年个数
        auto leapsUpto = [](int x) { return x / 4 - x / 100 + x / 400; };

        long long total = 365LL * (year - 1971) + (leapsUpto(year - 1) - leapsUpto(1970));
        for (int m = 1; m < month; m++) {
            total += mdays[m];
            if (m == 2 && isLeap(year)) total += 1;   // 2 月已走完才补闰日
        }
        total += day - 1;

        return names[(int)((total + 5) % 7)];         // 1971-01-01 是周五 → 偏移 5
    }
};
```

### Python

```python
class Solution:
    def dayOfTheWeek(self, day: int, month: int, year: int) -> str:
        names = ["Sunday", "Monday", "Tuesday", "Wednesday",
                 "Thursday", "Friday", "Saturday"]
        mdays = [0, 31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31]

        def is_leap(y: int) -> bool:
            return (y % 4 == 0 and y % 100 != 0) or y % 400 == 0

        def leaps_upto(x: int) -> int:              # [1, x] 内的闰年个数
            return x // 4 - x // 100 + x // 400

        total = 365 * (year - 1971) + (leaps_upto(year - 1) - leaps_upto(1970))
        for m in range(1, month):
            total += mdays[m]
            if m == 2 and is_leap(year):
                total += 1
        total += day - 1

        return names[(total + 5) % 7]
```

## 8. 边界情况与易错点

1. **锚点自检**：`(1, 1, 1971)` 必须返回 `"Friday"`，`total` 必须为 0。任何偏移量写错都会在这一组上暴露。
2. **世纪闰年**：2000 年是闰年（400 的倍数），`(29, 2, 2000)` 合法且答案为 `"Tuesday"`；而 2100 年**不是**闰年，2 月只有 28 天，`2100-12-31` 仍是 `"Friday"`。
3. **$month \le 2$ 时不补闰日**：1 月、2 月的计算尚未跨过 2 月 29 日，若写成「只要闰年就无条件 +1」会让 1 月、2 月的日期全部晚一天。
4. **返回值格式**：必须是完整英文单词且首字母大写，`"Saturday"` 不能写成 `"Saturday "`、`"saturday"` 或 `"Sat"`。
5. **不要用 `tm` / `mktime` / 时间戳**：`tm_year` 从 1900 起算、`tm_mon` 从 0 起算，还受时区与 32 位 `time_t` 的 2038 年问题影响，跨平台不可靠。
6. **越界风险**：月份循环用 `mdays[m]`（哨兵 + 1 基），上界是 `month - 1`，绝不能用 `mdays[month]` 或 `mdays[month-1]` 混用两种下标风格。
7. **不要用逐日循环凑**：虽然本题数据量能过，但它不是 $O(1)$ 解，遇到「年份可达 $10^{9}$」的加强版会直接超时。

**延伸思考**：本题用「前缀闰年闭式」把整年段压成 $O(1)$。若想连月份循环也省掉，可以改用 **Sakamoto 公式**：令 $t = [0,3,2,5,0,3,5,1,4,6,2,4]$，若 $month < 3$ 则 $year$ 减一，则 $(year + \lfloor year/4 \rfloor - \lfloor year/100 \rfloor + \lfloor year/400 \rfloor + t[month-1] + day) \bmod 7$ 直接给出以 Sunday 为 0 的索引。它与 **Zeller 同余**本质等价，都是把「年、月、日」三段天数合并成一个多项式后取模。进一步地，若日期落在 1582-10-15 之前（儒略历），闰年规则只需把「4 的倍数」这一条留下，此时把 $L(x)$ 中的后两项去掉即可——这套「前缀差分 + 取模」的框架对两种历法都成立。
