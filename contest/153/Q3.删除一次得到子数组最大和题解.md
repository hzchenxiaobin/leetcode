# LeetCode 删除一次得到子数组最大和 题解

## 1. 题目概述

- **标题 / 题号**：删除一次得到子数组最大和（#1186，medium）
- **链接**：https://leetcode.cn/problems/maximum-subarray-sum-with-one-deletion/
- **来源**：LeetCode 第 153 场周赛 Q3
- **难度**：中等
- **标签**：数组，动态规划

**题意**：给定整数数组 `arr`，先选出一个**非空**的连续子数组，再决定是否从中删掉一个元素（至多删一次；删完剩下的部分必须非空）。求剩余元素之和的最大值。

**约束**：

- $1 \le \text{arr.length} \le 10^5$
- $-10^4 \le \text{arr}[i] \le 10^4$
- 删除可以不做，但删除后子数组**不能为空**，所以答案至少是某个单元素的值

$n$ 达到 $10^5$，而元素之和的绝对值不超过 $10^9$，仍在 32 位有符号整数内；但复杂度必须是 $O(n)$ 或 $O(n \log n)$，$O(n^2)$ 的枚举会到 $10^{10}$ 级别，必然超时。

## 2. 示例

**示例 1**

```text
输入：arr = [1,-2,0,3]
输出：4
解释：选出整个数组 [1,-2,0,3]，删掉 -2，得到 [1,0,3]，和为 4。
```

**示例 2**

```text
输入：arr = [1,-2,-2,3]
输出：3
解释：删掉一个 -2 后仍有另一个 -2 拖累总和（1+(-2)+3 = 2），
      不如什么都不删、直接取 [3]。
```

**示例 3**

```text
输入：arr = [-1,-1,-1,-1]
输出：-1
解释：不能把 [-1] 里唯一的元素删掉换成空数组（和为 0），
      所以答案停在 -1。
```

## 3. 解题思路

### 3.1 暴力思路

照题面模拟：枚举子数组左右端点 $[l, r]$，再枚举删掉哪一个元素（或一个都不删），求和取最大。端点数 $O(n^2)$、删除点 $O(n)$，总复杂度 $O(n^3)$；即使先算出前缀和、并在枚举过程中增量维护段内最小值，把「删哪个」降到 $O(1)$，整体仍是 $O(n^2)$——$n = 10^5$ 时是 $10^{10}$ 次操作。

关键在于：**子数组是连续的**，而「删掉一个元素」只会把这段连续区间打出一个洞。洞的位置一旦固定，剩下的部分就是两段**互不相邻**的连续区间——这提示我们把「洞」当作一种状态，而不是枚举的对象。

### 3.2 核心观察：两状态 Kadane

![最优解的形状与两状态模型](images/wc153_q3_two_state_model.svg)

**观察 1（解的形状）**：任何一个可行方案，都是「区间 $[l,r]$ 的和」减去「其中至多一个元素」。删除是选做的，所以「整段求和」始终是合法候选。

**观察 2（把删除变成状态）**：从左往右扫过被选中的这段区间时，每个位置只有两种选择：把它**接上**，或者（至多一次）把它**扔掉**。于是整段扫描过程天然分成两段：**洞之前**（一次都没扔）和**洞之后**（已经扔过一次）。只要在状态里记录「扔了没有」，就不必去枚举洞的位置。

**观察 3（端点上的洞是多余的）**：如果洞落在区间的左端点 $l$，剩下的 $[l+1, r]$ 本身就是一段连续子数组；如果洞落在右端点 $r$，剩下的 $[l, r-1]$ 也一样。这两种情况完全等价于「选一段更短的区间、一个都不删」——也就是普通的最大子段和。所以**只需要认真处理洞在内部的情形**，而这正是「已删」状态在往后接元素时干的事。

> 💡 另一条等价思路：枚举「删掉 $arr[k]$」，答案是「以 $k-1$ 结尾的最大子段和」+「以 $k+1$ 开头的最大子段和」，正反两遍 Kadane 预处理即可，同样 $O(n)$。思路直观，但要额外处理 $k$ 在两端、以及完全不删的边界。下面的两状态写法把这些情况统一进转移里，无需分支。

### 3.3 算法流程与状态转移

![两状态滚动更新的流程图](images/wc153_q3_dp_flow.svg)

定义两个状态，**都以当前元素 $i$ 结尾**（子数组必须包含 $arr[i]$）：

- $keep_i$：子数组 $[l, i]$ 中**一个元素都没删**时的最大和；
- $dele_i$：子数组 $[l, i]$ 中**恰好删掉一个**元素、且剩余部分非空时的最大和。

转移只有两条，对应「洞什么时候挖」：

$$keep_i = \max\bigl(keep_{i-1} + arr[i],\ arr[i]\bigr)$$

- 前一项：把 $arr[i]$ 接到上一段未删区间的右边；
- 后一项：从 $arr[i]$ 重新开一段。这一项同时兜住了「洞在左端点」的全部情形。

$$dele_i = \max\bigl(dele_{i-1} + arr[i],\ keep_{i-1}\bigr)$$

- 前一项：洞早就挖好了（$dele_{i-1}$ 里已经删过一个），把 $arr[i]$ 接在洞的右边；
- 后一项：**就在这一步把 $arr[i]$ 删掉**，左边原样保留 $keep_{i-1}$。因为 $keep_{i-1}$ 对应非空区间，删掉 $arr[i]$ 后剩下的部分一定非空，正好满足题目要求。

初值（$i = 0$）：

$$keep_0 = arr[0], \qquad dele_0 = -\infty$$

$dele_0$ 取 $-\infty$ 是因为「只看第一个元素」时不可能已经删过一次，这个状态**不可达**，必须显式排除，否则会让「删掉唯一元素得到空段」混进答案。

最终答案是所有位置、所有状态的最大值：

$$ans = \max_{0 \le i < n}\ \max\bigl(keep_i,\ dele_i\bigr)$$

注意不能只取最后一个位置的 $\max$：最优子段可能在中途结束（示例 2 的 `[3]` 就是如此）。

流程上只有三步，扫一遍数组即可：

```text
1. keep = arr[0];  dele = -INF;  ans = arr[0]
2. 对 i = 1 .. n-1，令 x = arr[i]：
     dele = max(dele + x, keep)      # 必须先算：这里用的是上一轮的 keep
     keep = max(keep + x, x)
     ans  = max(ans, keep, dele)
3. 返回 ans
```

### 3.4 示例演算

![arr = [1,-2,0,3] 的逐位置更新表](images/wc153_q3_walkthrough.svg)

以 `arr = [1,-2,0,3]` 为例走一遍。记 $k'$ 为本轮更新**之前**的 $keep$（上一轮的值），$x$ 为当前元素：

| $i$ | $x$ | $k'$（旧 keep） | $dele_i = \max(dele + x,\ k')$ | $keep_i = \max(k' + x,\ x)$ | $ans$ |
|-----|-----|-----------------|--------------------------------|-----------------------------|-------|
| 0 | 1 | 初始 | $-\infty$ | 1 | 1 |
| 1 | −2 | 1 | $\max(-\infty,\ 1) = 1$ | $\max(1-2,\ -2) = -1$ | 1 |
| 2 | 0 | −1 | $\max(1+0,\ -1) = 1$ | $\max(-1+0,\ 0) = 0$ | 1 |
| 3 | 3 | 0 | $\max(1+3,\ 0) = 4$ | $\max(0+3,\ 3) = 3$ | **4** |

第 1 行读法：$dele = 1$ 表示「删掉 $-2$、只保留 $[1]$」；第 3 行 $dele = 4$ 表示「上一轮已经挖过洞的段（值 1，洞在 $-2$ 处）再扩上 $3$」，也就是 $[1, 0, 3]$ 挖掉 $-2$ 的方案，答案更新为 4。

再看 `arr = [1,-2,-2,3]`：到 $i = 3$ 时 $dele_3 = \max(-1 + 3,\ -2) = 2$，而 $keep_3 = \max(-2+3,\ 3) = 3$。$dele$ 里保留着一个真实存在的洞，反而拖累了总和，所以「什么都不删」的 $keep$ 分支胜出，答案 3——这就是删除可选的意义。

## 4. 算法细节

1. **状态的结尾语义**：$keep_i$、$dele_i$ 都要求子数组**以 $i$ 结尾**（类似 Kadane 的 $f[i]$），不是「前 $i$ 个元素内的最优值」。只有强制结尾，转移才能做到 $O(1)$ 局部化；全局最优再用一个 $ans$ 变量边扫边收集。
2. **更新顺序不能反**：$dele_i$ 的第二个分支用的是**上一轮**的 $keep$。如果先更新 $keep$，就会把「删掉 $arr[i]$ 之后还能继续往右接」这种不可能的操作混进转移（等价于删了却仍带着 $arr[i]$）。代码里必须先写 $dele$，或者用临时变量缓存旧 $keep$。
3. **答案逐位置收集**：每个位置算完都要 $ans = \max(ans, keep, dele)$。放在循环结束后再取，等于要求子数组必须在最后一个位置结尾。
4. **不可达状态用 $-10^{18}$ 表示**：$dele$ 的初值不能用 $0$（会假装「删掉 $arr[0]$ 得到空段、和为 0」），也不能用 `INT_MIN` 直接参与加法（有符号下溢是未定义行为）。C++ 里用 `long long` 配 `-(long long)1e18`，Python 里用整数 $-10^{18}$，加法之后依然远小于任何真实候选值，比较是安全的。
5. **删除可选 ⇒ 单元素永远是候选**：$keep$ 转移里的 $\max(\cdot,\ arr[i])$ 保证任意时刻都能「只取当前这一个元素」。这就是示例 3 全负数时答案停在 $-1$ 而非 $0$ 的原因。
6. **空间压到 $O(1)$**：$keep$、$dele$、$ans$ 三个变量滚动即可；$10^5$ 的规模下连数组都不用开（$arr$ 本身是入参）。
7. **端点处的洞不必特判**：洞在 $l$ 的情形由 $keep$ 的「重新开一段」覆盖，洞在 $r$ 的情形由 $dele$ 的「删掉 $arr[i]$」覆盖。这一条能省掉大量边界分支，也是这套写法比「左右各跑一遍 Kadane」更短的原因。

## 5. 正确性证明

**引理 1（$keep$ 状态可达且最优）**：对每个 $i$，$keep_i$ 恰等于「所有以 $i$ 结尾、未删除任何元素的子数组」之和的最大值。

**证明**：对 $i$ 归纳。$i = 0$ 时以 $0$ 结尾的子数组只有 $[0]$，值 $arr[0]$，与初值一致。设 $i \ge 1$，任一以 $i$ 结尾的未删子数组 $[l, i]$：若 $l = i$ 则值为 $arr[i]$；若 $l < i$，则 $[l, i-1]$ 是以 $i-1$ 结尾的未删子数组，其值 $\le keep_{i-1}$（归纳假设），于是 $[l,i]$ 的值 $\le keep_{i-1} + arr[i]$。两类上界分别由两个分支取到（$[i]$ 与「$keep_{i-1}$ 对应的子数组并上 $i$」都可实现），故 $keep_i$ 等于最大值。∎

**引理 2（$dele$ 状态可达且最优）**：对每个 $i$，$dele_i$ 恰等于「所有以 $i$ 结尾、恰好删掉一个元素且剩余非空」的方案之和的最大值。

**证明**：对 $i$ 归纳。$i = 0$：以 $0$ 结尾的区间只有 $[0]$，删掉唯一元素后为空，没有合法方案，$dele_0 = -\infty$ 正确。设 $i \ge 1$，考察任一合法方案：设它选的是 $[l, i]$ 并删掉 $arr[k]$（$l \le k \le i$）。

- 若 $k = i$：剩余部分是 $[l, i-1]$，非空意味着 $l \le i-1$，它是未删的、以 $i-1$ 结尾的子数组，值 $\le keep_{i-1}$；而 $keep_{i-1}$ 对应的方案删掉 $arr[i]$ 后同样合法，故该分支恰好覆盖这一类。
- 若 $k < i$：剩余部分是「$[l, i-1]$ 删掉 $arr[k]$」再并上 $arr[i]$，其值 $\le dele_{i-1} + arr[i]$（归纳假设），且 $dele_{i-1}$ 对应的方案并上 $arr[i]$ 后剩余部分仍非空，故该分支恰好覆盖这一类。

两类穷尽了所有删除位置，取 $\max$ 即得结论。∎

**引理 3（覆盖性）**：任一可行方案的值不超过 $ans$。

**证明**：设方案选的区间为 $[l, r]$。若一个元素都不删，其值为 $[l,r]$ 之和，由引理 1 不超过 $keep_r \le ans$。若删掉 $arr[k]$（$l \le k \le r$，删后非空），由引理 2 其值不超过 $dele_r \le ans$。∎

**定理**：算法返回值等于题目所求的最大和。

**证明**：一方面，由引理 1、2，每个 $keep_i$、$dele_i$ 都对应一个合法方案（$dele_i = -\infty$ 时不对应任何方案，也不影响取最大），故 $ans$ 不超过最优值；另一方面，由引理 3，最优值不超过 $ans$。两者相等，算法正确。∎

## 6. 复杂度分析

- **时间**：$O(n)$。每个元素只处理一次，转移里是两次加法 + 三次取最大，常数极小；$n = 10^5$ 时约 $10^5$ 轮循环。
- **空间**：$O(1)$ 额外空间（$keep$、$dele$、$ans$ 三个变量），不依赖 $n$；数组本身由输入提供。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maximumSum(vector<int>& arr) {
        const long long NEG = -(long long)1e18;   // 不可达的「已删」状态
        long long keep = arr[0];   // 以当前元素结尾、一次都没删
        long long dele = NEG;      // 以当前元素结尾、恰好删掉一个元素
        long long ans  = arr[0];   // 删除是可选的，至少能只取一个元素

        for (int i = 1; i < (int)arr.size(); i++) {
            long long x = arr[i];
            dele = max(dele + x, keep);   // 先用旧 keep，再更新 keep
            keep = max(keep + x, x);      // Kadane：接上 x，或从 x 另起一段
            ans  = max(ans, max(keep, dele));
        }
        return (int)ans;
    }
};
```

### Python

```python
class Solution:
    def maximumSum(self, arr: list[int]) -> int:
        NEG = -10**18                 # 不可达的「已删」状态
        keep = arr[0]                 # 以当前元素结尾、一次都没删
        dele = NEG                    # 以当前元素结尾、恰好删掉一个元素
        ans = arr[0]                  # 删除是可选的，至少能只取一个元素

        for x in arr[1:]:
            dele = max(dele + x, keep)   # 必须先用旧 keep
            keep = max(keep + x, x)      # Kadane
            ans = max(ans, keep, dele)

        return ans
```

## 8. 边界情况与易错点

1. **全负数**：`[-1,-1,-1,-1]` 的答案是 $-1$。若把 $dele$ 的初值写成 $0$，或让「删掉唯一元素、剩下空数组」这种非法方案参与比较，就会错答 $0$。
2. **数组长度为 1**：只能返回 $arr[0]$。此时 $dele$ 始终保持 $-\infty$，$ans$ 只可能来自 $keep$；代码里若不初始化 $ans = arr[0]$（而是 $-\infty$ 又漏算），会返回错误的哨兵值。
3. **最优子段在中间结束**：`[1,-2,-2,3]` 的答案 3 来自最后一个位置，但 `[4,-10,3,-10,7]` 的最优值 7 来自中间的 `[7]`。$ans$ 必须边扫边取，不能只返回循环结束时的 $\max(keep, dele)$。
4. **更新顺序写反**：若先更新 $keep$ 再更新 $dele$，$dele$ 的第二个分支读到的就是**已经含 $arr[i]$** 的新 $keep$，等价于「删掉 $arr[i]$ 之后又把 $arr[i]$ 加了回来」，答案会系统性偏大。
5. **哨兵与溢出**：$dele$ 的初值用 `INT_MIN` 直接加 $arr[i]$ 会下溢（C++ 中是未定义行为），必须用足够小的有限值（如 $-10^{18}$）配合 64 位整数。本题元素之和绝对值不超过 $10^9$，最终答案可以安全转回 `int`。
6. **误以为「删除一定更优」**：删除只在洞里的元素为负时才有收益。示例 2 中强行删一个 $-2$ 反而只剩 2，正确答案 3 来自「什么都不删」。
7. **只想删最小值就够了吗**：对**固定区间**而言，删掉最小值确实最优；但区间选择与删除位置是耦合的——删掉一个负值会让整段由亏转盈，从而值得把区间扩得更长。所以不能全局只找最小值，仍需 DP 把「洞在哪、区间到哪」一起交给状态。

**延伸思考**：如果允许删除**至多 $k$** 个元素（删后非空），状态就要扩成 $dele[i][j]$ = 以 $i$ 结尾、已删 $j$ 个的最大和，转移为 $dele[i][j] = \max\bigl(dele[i-1][j] + arr[i],\ dele[i-1][j-1]\bigr)$，复杂度 $O(nk)$；若 $k$ 不小于负数个数，直接删掉所有负数即最优，退化成一趟前缀和扫描；当 $k$ 与 $n$ 同阶时 $O(nk)$ 会退化成 $O(n^2)$，此时换个视角——删掉的 $k$ 个元素把保留部分切成至多 $k+1$ 段连续区间——可以按「段数」重做一次分段型 DP。如果要求**恰好**删一次，则答案只能取 $\max_i dele_i$，并且要额外保证删后非空——全负数数组会逼你处理「删掉唯一元素」的非法情形。若把「删一个元素」换成「把一段连续区间整段丢弃」，则问题变成「最多两段子数组的最大和」，属于同一类「分段状态机」DP。
