# LeetCode 公交站间的距离 题解

## 1. 题目概述

- **标题 / 题号**：公交站间的距离（#1184，easy）
- **链接**：https://leetcode.cn/problems/distance-between-bus-stops/
- **来源**：LeetCode 第 153 场周赛 Q1
- **难度**：简单
- **标签**：数组

**题意**：环形路线上有 $n$ 个站，编号 $0$ 到 $n-1$。`distance[i]` 是站 $i$ 与站 $(i+1) \bmod n$ 之间那一段路的长度。公交车两个方向都能开，求从 `start` 到 `destination` 的**最短距离**。

换一种说法：把环形路线看成一张有 $n$ 个点、$n$ 条边的无向环图，每条边有权重，问两点间最短路。

**约束**：

- $1 \le n \le 10^4$，且 $n = \text{distance.length}$
- $0 \le \text{start}, \text{destination} < n$
- $0 \le \text{distance}[i] \le 10^4$，即整圈周长不超过 $10^8$

> 💡 Q1 的定位是签到题。本题的暴力（BFS / 两个方向各走一遍）本来就是 $O(n)$，也能过；真正值得沉淀的是**把「两条路」压成一个恒等式**，让正解只剩两行：一次求和、一次区间求和、一次减法。

## 2. 示例

**示例 1**

```text
输入：distance = [1,2,3,4], start = 0, destination = 1
输出：1
解释：0 与 1 相邻，顺时针走 1 段，长度 1；
      逆时针要绕 4 + 3 + 2 = 9，取小者为 1。
```

**示例 2**

```text
输入：distance = [1,2,3,4], start = 0, destination = 2
输出：3
解释：顺时针 0→1→2 长度 1 + 2 = 3；
      逆时针 0→3→2 长度 4 + 3 = 7，取小者为 3。
```

**示例 3**

```text
输入：distance = [1,2,3,4], start = 0, destination = 3
输出：4
解释：顺时针 0→1→2→3 长度 1 + 2 + 3 = 6；
      逆时针 0→3 直接相邻，长度 4，反而更近，取小者为 4。
```

三个示例的起点都是 $0$，但结论并不一致：示例 1、2 里顺时针更短，示例 3 里反而是逆时针更短。这正是本题最容易写反的地方——**方向不能写死**，必须两边都算再取 $\min$。

## 3. 解题思路

### 3.1 暴力思路

两条最直白的路线，复杂度都不比正解好：

- **建图跑最短路**：把 $n$ 个站建成无向环图，边 $(i, (i+1) \bmod n)$ 权重 `distance[i]`，从 `start` 跑 Dijkstra 或 BFS。时间 $O(n \log n)$、空间 $O(n)$，代码量是正解的十倍以上，收益为零。
- **两个方向分别模拟行走**：顺时针用 `cur = (cur + 1) % n` 一步步走并累加 `distance[cur]`；逆时针用 `prev = (cur - 1 + n) % n`，累加 `distance[prev]`。仍是 $O(n)$，但要维护两个取模方向，`start == destination` 或 $n = 1$ 时稍不留神就写成死循环或漏加一段。

它们的共同问题不是"太慢"，而是**把一条封闭的环当成开放的路去走**。一旦意识到两条路的长度之和恒等于整圈周长，模拟就彻底不必要了。

### 3.2 核心观察：两条弧互补，另一条用减法得到

![环上两条弧互补，取较短的一条](images/wc153_q1_two_arcs.svg)

环上取定两个不同的站，从 `start` 走到 `destination` 只有两条本质不同的路线：

- **顺时针弧**：沿 $i \to (i+1) \bmod n$ 走，经过的边是下标区间 $[\text{start}, \text{destination})$ 上的那些 `distance`；
- **逆时针弧**：沿 $i \to (i-1+n) \bmod n$ 走，经过的边恰好是补集。

记顺时针弧长为 $\text{cw}$、逆时针弧长为 $\text{ccw}$。两条弧互不重叠、合起来正好是整圈，于是

$$\text{cw} + \text{ccw} = \sum_{i=0}^{n-1} \text{distance}[i] = \text{total}$$

所以只需要求出顺时针那一条，逆时针弧长用 $\text{total} - \text{cw}$ 一次减法就能得到，模型从"在环上找路"变成"在数组上求一段区间和"。

### 3.3 算法流程

![四步 O(n)：归一化、总长、区间和、取较小](images/wc153_q1_algorithm_flow.svg)

1. **归一化**：若 $\text{start} > \text{destination}$ 就交换两者。这样顺时针弧对应的下标区间一定是 $[\text{start}, \text{destination})$，不需要处理"跨过 $n$ 再绕回 0"的环形区间。
2. **求整圈周长**：一次遍历累加所有 `distance[i]` 得到 `total`。
3. **求顺时针弧长**：在 $i \in [\text{start}, \text{destination})$ 上累加 `distance[i]` 得到 `cw`。
4. **补集即另一条弧**：$\text{ccw} = \text{total} - \text{cw}$，不必再扫一遍数组。
5. **返回** $\min(\text{cw}, \text{total} - \text{cw})$。

第 2、3 步可以合进同一个循环：边累加 `total`，边判断当前下标是否落在 $[\text{start}, \text{destination})$ 里。下面的参考代码拆成两遍写，是为了让"周长"和"一段弧"这两个量各自独立，读起来与上面的公式一一对应。

### 3.4 示例演算

![示例走查表](images/wc153_q1_walkthrough.svg)

以 $\text{distance} = [1,2,3,4]$ 为例（下表记 $d = \text{distance}$），$\text{total} = 10$ 恒定不变，变的只是区间端点：

| 组 | start | destination | 顺时针 $\text{cw}$ | $\text{total} - \text{cw}$ | 答案 |
|----|-------|-------------|-------------------|---------------------------|------|
| ① | 0 | 1 | $d[0] = 1$ | 9 | **1** |
| ② | 0 | 2 | $d[0] + d[1] = 3$ | 7 | **3** |
| ③ | 0 | 3 | $d[0] + d[1] + d[2] = 6$ | 4 | **4** |
| ④ | 2 | 2 | 区间为空，$\text{cw} = 0$ | 10 | **0** |
| ⑤ | 3 | 1 | 交换后 $d[1] + d[2] = 5$ | 5 | **5** |

第 ③ 行是反例高发点：$\text{cw} = 6$ 已经超过一半，补集 $4$ 才是答案，说明**不能想当然地返回顺时针弧长**。第 ④ 行说明起点终点相同时区间为空、答案为 $0$，代码不需要特判。第 ⑤ 行说明交换端点不会改变代码求和的下标集合（§5 引理 2），而 $\min$ 只看两条弧的长度、与"哪条被叫作 cw"无关（§5 引理 1），所以答案依然正确。

## 4. 算法细节

1. **归一化必须在区间求和之前做**，且只需一次。写法可以是 `if (start > destination) swap(start, destination);`，也可以用 `int l = min(start, destination), r = max(start, destination);`。后者不改动入参语义，更不容易顺带误改别的逻辑。
2. **区间是左闭右开**：$[\text{start}, \text{destination})$，循环条件写 `i < destination`。写成 `i <= destination` 会把终点站后面那一段也算进来，答案系统性偏大。
3. **两条弧都是实际可走的路线**，所以 $\min$ 一定可以取到；不需要像有些题那样先判断"是否存在可行路径"。这也是本题比一般最短路题省事的地方：候选解只有两个，且都可显式构造。
4. **整数范围**：$n \le 10^4$、$\text{distance}[i] \le 10^4$，故 $\text{total} \le 10^8$，远小于 `int` 上限 $2.1 \times 10^9$，`int` 足够，不必开 `long long`；Python 无溢出问题。这个界在写其他题时也值得顺手估一遍。
5. **原地合并写法**：若想把两遍扫描压成一遍，可写
   `for (int i = 0; i < n; ++i) { total += distance[i]; if (start <= i && i < destination) cw += distance[i]; }`
   效果等价，常数更小，但把"周长"与"某段弧"混在同一行，可读性下降，周赛现场按习惯取舍即可。
6. **Python 切片**：`sum(distance[start:destination])` 只创建一个长度至多 $n$ 的临时列表，$O(n)$ 时间、$O(n)$ 额外空间，对 $n = 10^4$ 完全可接受；若在意这点内存，就用 `for` 循环累加。
7. **不要修改输入**：本题不需要动 `distance`。若在函数里排序或就地交换元素，会让下标与站点编号的对应关系错位——`distance[i]` 的 $i$ 有物理含义，不能被重排。
8. **环形前缀和的通用写法**（多查询时有用）：令 $P[k] = \sum_{i<k} \text{distance}[i]$，则从 $s$ 到 $t$ 的顺时针弧长为 $(\text{total} - P[s] + P[t]) \bmod \text{total}$。本题只有一次查询，直接累加即可，不必建前缀和数组。

## 5. 正确性证明

**引理 1（两弧互补）**：设两端点为 $s, t$，顺时针弧长为 $\text{cw}$、逆时针弧长为 $\text{ccw}$，则 $\text{cw} + \text{ccw} = \text{total}$。

**证明**：环上的边集恰为 $n$ 条边 $\{e_i\}$，其中 $e_i$ 连接 $i$ 与 $(i+1) \bmod n$，权重 $\text{distance}[i]$。归一化后 $s < t$，顺时针弧取边集 $E_1 = \{e_i : s \le i < t\}$，逆时针弧取 $E_2 = \{e_i : i < s \ \text{或}\ i \ge t\}$。显然 $E_1 \cap E_2 = \varnothing$ 且 $E_1 \cup E_2$ 是全部 $n$ 条边，故两者权重和相加恰为 $\text{total}$。当 $s = t$ 时 $E_1 = \varnothing$、$E_2$ 为全部边，$\text{cw} = 0$、$\text{ccw} = \text{total}$，等式依然成立。∎

**引理 2（交换端点不改变计算结果）**：交换 `start` 与 `destination` 后，代码求和的下标集合与交换前完全相同，因此 `cw` 不变、答案不变。

**证明**：设输入为 $s = \text{start}$、$t = \text{destination}$。代码执行完第一行后恒有 $\text{start} = \min(s,t)$、$\text{destination} = \max(s,t)$，因此求和区间始终是 $[\min(s,t), \max(s,t))$——它只由端点集合决定，与两个参数的先后顺序无关。故 `cw` 不变，$\min(\text{cw}, \text{total} - \text{cw})$ 也不变。∎

**引理 3（绕整圈不会更优）**：任何从 `start` 出发、沿环行进并到达 `destination` 的路线，其长度不小于 $\min(\text{cw}, \text{total} - \text{cw})$。

**证明**：把路线按时间顺序经过的边记成序列。由于每次移动都是沿环前进一或后退一格，路线可以分解为"若干完整整圈 + 最后一小段从 `start` 到 `destination` 的弧"（把首尾相接的整圈消去即得）。因此路线长度形如 $k \cdot \text{total} + L$，其中 $k \ge 0$、$L$ 是两条弧之一的长度，即 $L \in \{\text{cw}, \text{total} - \text{cw}\}$。又因所有 $\text{distance}[i] \ge 0$，有 $\text{total} \ge 0$，故 $k \cdot \text{total} + L \ge L \ge \min(\text{cw}, \text{total} - \text{cw})$。∎

**定理**：算法返回 $\min(\text{cw}, \text{total} - \text{cw})$，它等于 `start` 到 `destination` 的最短距离。

**证明**：一方面，两条弧都是实际可走的路线（公交车双向行驶），长度分别为 $\text{cw}$ 与 $\text{total} - \text{cw}$，故最短距离不超过 $\min(\text{cw}, \text{total} - \text{cw})$。另一方面，由引理 3，任何路线长度都不小于这个值，故最短距离不小于它。两者夹逼，最短距离恰为 $\min(\text{cw}, \text{total} - \text{cw})$；由引理 2，代码里先交换端点不影响这个值。∎

## 6. 复杂度分析

- **时间**：$O(n)$。归一化 $O(1)$；求 `total` 遍历 $n$ 个元素；求 `cw` 遍历至多 $n-1$ 个元素（起点与终点相同时循环体一次不执行）；没有排序、没有建图、没有重复扫描。若合并成单循环，总常数更小，渐进不变。
- **空间**：$O(1)$。只用了 `total`、`cw` 两个整数变量（不计入输入本身）。Python 切片写法会在求和时临时生成至多 $n$ 个元素的列表，额外 $O(n)$ 空间；改写成 `for` 累加即可降为 $O(1)$。

## 7. 参考代码

### C++

```cpp
#include <algorithm>
#include <vector>
using namespace std;

class Solution {
public:
    int distanceBetweenBusStops(vector<int>& distance, int start, int destination) {
        if (start > destination) swap(start, destination);  // ① 归一化，让顺时针对应 [start, destination)

        int total = 0;
        for (int d : distance) total += d;                  // ② 整圈周长

        int cw = 0;
        for (int i = start; i < destination; ++i) {
            cw += distance[i];                              // ③ 左闭右开的区间和
        }

        return min(cw, total - cw);                         // ④ 两条弧取较短
    }
};
```

### Python

```python
from typing import List


class Solution:
    def distanceBetweenBusStops(self, distance: List[int], start: int, destination: int) -> int:
        if start > destination:                       # ① 归一化
            start, destination = destination, start

        total = sum(distance)                         # ② 整圈周长
        cw = sum(distance[start:destination])         # ③ 左闭右开区间
        return min(cw, total - cw)                    # ④ 两条弧取较短
```

> 💡 若想避免切片产生的临时列表，把 ③ 换成 `cw = 0` 加一个 `for i in range(start, destination): cw += distance[i]`，两种写法在本题数据范围下都能轻松通过。

## 8. 边界情况与易错点

1. **`start == destination`**：区间 $[\text{start}, \text{destination})$ 为空，$\text{cw} = 0$，返回 $\min(0, \text{total}) = 0$。答案正确且**不需要特判**；但若是用"两个方向模拟行走"的写法，这里不写 `if (start == destination) return 0;` 就会原地打转、死循环。
2. **`start > destination`**：不交换直接切片，Python 会得到空列表、返回 $0$；C++ 的 `for (int i = start; i < destination; ++i)` 一次也不执行，同样返回 $0$。这类"静默错误"不会报错，只会悄悄 WA，所以归一化这一步不能省。
3. **$n = 1$**：只有一个站，`start` 与 `destination` 都只能是 $0$，答案 $0$；`distance` 只有一个元素，`total` 就是它的值。正解天然正确，模拟法要小心 `(cur + 1) % 1` 永远停在原地。
4. **答案不是 `cw`**：示例 3 中 $\text{cw} = 6$ 而答案是 $4$。凡是只在示例 1、2 上验证过的代码，都容易漏掉"补集更短"这一半。
5. **区间写成闭区间**：`i <= destination` 会多算一段边，示例 1 上会得到 $1 + 2 = 3$ 这类明显错误；这类 off-by-one 在左闭右开的写法下最容易自查。
6. **全 0 权重**：`distance = [0,0,0]` 时答案为 $0$，不要写 `if (!cw) return total - cw;` 之类把 $0$ 当成"无效值"的判断。
7. **误以为必须走相邻站**：题目没有"必须经过某一站"的限制，两条弧就是全部候选，任何额外绕行由引理 3 保证不会更优。
8. **返回类型**：函数返回 `int`，`total - cw` 也在 $[0, 10^8]$ 内，不会出现负数；若把 `min` 的参数顺序写反成 `total - cw` 与 `cw`，结果不变，但别把 `total - cw` 误写成 `total - ccw`（那就等于又算了一遍 `cw`）。
