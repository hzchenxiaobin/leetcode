# LeetCode 使数组严格递增 题解

## 1. 题目概述

- **标题 / 题号**：使数组严格递增（#1187，hard）
- **链接**：https://leetcode.cn/problems/make-array-strictly-increasing/
- **来源**：LeetCode 第 153 场周赛 Q4
- **难度**：困难
- **标签**：数组, 二分查找, 动态规划, 排序, 最长上升子序列

**题意**：给定整数数组 `arr1`、`arr2`。一次**操作**是挑一对下标 $0 \le i < \lvert arr1 \rvert$、$0 \le j < \lvert arr2 \rvert$，执行 `arr1[i] = arr2[j]`。求使 `arr1` **严格递增**所需的最少操作数；若做不到返回 $-1$。

两点前提：`arr2` 里的值可以反复取用，但 `arr1` 严格递增意味着最终数组各元素互不相同（同一个值不可能出现在两个位置，也不可能在同一位置出现两次）；对同一位置替换两次只会多记一次操作、最终值却只取决于最后一次，因此**每个位置至多替换一次**。

**约束**：

- $1 \le \lvert arr1 \rvert, \lvert arr2 \rvert \le 2000$
- $0 \le arr1[i], arr2[i] \le 10^9$
- 值域极大、长度只有 $2000$，说明复杂度应与**长度**相关，而不是与值域相关

## 2. 示例

**示例 1**

```text
输入：arr1 = [1,5,3,6,7], arr2 = [1,3,2,4]
输出：1
解释：用 2 替换 5，得到 [1,2,3,6,7]，严格递增，只需 1 次操作。
```

**示例 2**

```text
输入：arr1 = [1,5,3,6,7], arr2 = [4,3,1]
输出：2
解释：用 3 替换 5、用 4 替换 3，得到 [1,3,4,6,7]，共 2 次操作。
```

**示例 3**

```text
输入：arr1 = [1,5,3,6,7], arr2 = [1,6,3,3]
输出：-1
解释：arr2 去重后只有 {1,3,6}，其中大于 1 的只有 3 和 6。无论下标 1、2 怎么填，
      最终都会被迫需要一个严格大于 6 的 arr2 值（下标 3 的 6 无法保留），而 b 中没有
      这样的值，故无解。
```

## 3. 解题思路

### 3.1 暴力思路

最直白的做法是逐位枚举：每个位置要么保留 `arr1[i]`，要么换成 `arr2` 中的某个值，搜索树规模 $(\lvert arr2 \rvert + 1)^{\lvert arr1 \rvert}$，完全不可行。

稍好一点的 DP 是「位置 + 取值」：设 $f[i][v]$ 表示处理到第 $i$ 位、第 $i$ 位取值 $v$ 时的最少操作数，其中 $v$ 取 $arr1[i]$ 或 $arr2$ 中任一元素。状态数 $O(n \cdot m)$，但转移要枚举下一位的取值，总复杂度 $O(n \cdot m^2)$。$n = m = 2000$ 时约 $8 \times 10^9$，仍然超时。

真正的浪费在于：**我们根本不需要知道末元素"是哪个值"，只需要知道它"有多小"**。

### 3.2 核心观察：末元素越小越好

![每个位置只有保留或替换两种选择](images/wc153_q4_two_choices.svg)

三个递进的观察：

1. **可行性只依赖末值**：严格递增是局部约束——下一位只要**大于**当前末值即可，前面的历史不再影响判断。
2. **占优关系**：固定"处理到第 $i$ 位、已经用掉 $c$ 次操作"这个状态，末值更小的方案**永远不会更差**。因为两个转移条件（保留要求 $arr1[i] >$ 末值，替换要求存在 $arr2$ 元素 $>$ 末值）都随末值变小而**放宽**，可行选择集合只增不减。
3. **替换取最小可用值**：既然末值越小越好，替换时就没必要试 $arr2$ 里所有大于末值的候选，取**严格大于末值的最小值**即可——它支配其它所有候选。

于是状态被压缩成一维数组：

$$dp[c] = \text{用恰好 } c \text{ 次替换、处理完当前前缀后，末元素能取到的} \textbf{最小值}$$

长度只有 $n+1$（$c$ 最多到 $n$，因为每个位置至多替换一次）。答案就是**最小的使 $dp[c]$ 有穷的 $c$**。

### 3.3 算法流程 / 状态转移

![dp 状态转移与 upper_bound](images/wc153_q4_dp_transition.svg)

预处理：$b = \text{sort}(\text{unique}(arr2))$，去重后排序，便于二分。

初始化 $dp[0] = -1$，其余为 $+\infty$。这里的 $-1$ 是**哨兵**：题面保证所有值 $\ge 0$，所以 $-1$ 小于一切候选值，第一位既不需要特判、也自然允许"保留"和"替换"两条分支。

对 $i = 0,1,\dots,n-1$ 依次处理 $x = arr1[i]$，用 $ndp$ 承接新一层：

$$
\begin{aligned}
\text{① 保留 } x：&\quad \text{若 } x > dp[c]\text{，则 } ndp[c] \leftarrow \min(ndp[c],\, x)\\
\text{② 替换 } x：&\quad k = \operatorname{upperBound}(b,\, dp[c])\text{，若 } k < m\text{，则 } ndp[c+1] \leftarrow \min(ndp[c+1],\, b[k])
\end{aligned}
$$

其中 $k$ 是 $b$ 中第一个 $> dp[c]$ 的下标，$b[k]$ 就是第 3 条观察中的"最小可用值"。一层的所有 $c$ 处理完后执行 $dp \leftarrow ndp$。

最后从 $c = 0$ 开始扫描，第一个满足 $dp[c] \ne +\infty$ 的 $c$ 即答案；全部为 $+\infty$ 则返回 $-1$。

### 3.4 示例演算

![示例 1 的 dp 表逐层演算](images/wc153_q4_walkthrough.svg)

对示例 1：$arr1 = [1,5,3,6,7]$，$b = [1,2,3,4]$，逐层填表（行 = 处理完第 $i$ 位，列 = 已用替换次数）：

| 处理到 | $c=0$ | $c=1$ | $c=2$ | $c=3$ | $c=4$ |
|--------|-------|-------|-------|-------|-------|
| $i=0$，$x=1$ | 1 | 1 | ∞ | ∞ | ∞ |
| $i=1$，$x=5$ | 5 | **2** | 2 | ∞ | ∞ |
| $i=2$，$x=3$ | ∞ | 3 | 3 | 3 | ∞ |
| $i=3$，$x=6$ | ∞ | 6 | 4 | 4 | 4 |
| $i=4$，$x=7$ | ∞ | **7** | 7 | 7 | 7 |

关键几格怎么来：

- $i=0$：保留得 $dp[0]=1$；替换时 $\operatorname{upperBound}(b,-1)$ 命中 $b[0]=1$，得 $dp[1]=1$（"1 换成 1"虽然没意义，但状态本身合法，不影响最优性）。
- $i=1$：$dp[1]=2$ 来自替换（$5 \to 2$，$2$ 是 $b$ 中 $>1$ 的最小值）；$dp[0]=5$ 来自保留。
- $i=2$：$dp[0]$ 变 ∞——$arr1[2]=3$ 不大于末值 $5$，且 $b$ 中没有 $>5$ 的值，这一格被彻底放弃；$dp[2]=3$ 来自 $dp[1]=2$ 的替换（$3$ 是 $b$ 中 $>2$ 的最小值）。
- 最终行最小的有限列是 $c=1$，答案 $1$，对应方案 $[1,2,3,6,7]$。

## 4. 算法细节

1. **`INF` 必须严格大于 $10^9$**：取值上界正好是 $10^9$，若用 `INF = 1e9`，合法的末值 $10^9$ 会被误判成"不可达"，输入 `arr1 = [1000000000]` 就会错误返回 $-1$。用 `INT_MAX` 或 `2e9`。
2. **必须去重**：`arr2` 中重复的值对严格递增毫无用处（同一位置不会用两次，不同位置用同一个值会破坏严格性），去重后二分边界更干净，也让"最小可用值"唯一。
3. **必须滚动更新**：`ndp` 每层整体重置，禁止原地改 $dp$——否则同一个位置会被反复替换，$c$ 的含义被污染。
4. **$c$ 的上界**：处理第 $i$ 位时 $c \le i$，因为前 $i$ 个位置最多替换 $i$ 次；写 `for (c = 0; c <= i; c++)` 同时保证 $c+1 \le n$ 不越界。
5. **严格递增用 `>` 而非 `>=`**：`upper_bound` 天然是"严格大于"，与判定条件一致；若误用 `lower_bound` 会允许"换成与末值相等的值"，产出非严格递增。
6. **不需要记录"用过的 $arr2$ 元素"**：最终数组严格递增 ⇒ 所有位置取值互不相同，同一个 $arr2$ 值不可能被用两次，因此不必维护已用集合（这是本题最容易被想复杂的地方）。
7. **二分实现**：C++ 用 `upper_bound(b.begin(), b.end(), last)`，Python 用 `bisect_right(b, last)`，两者语义都是"第一个 $> last$ 的位置"。

## 5. 正确性证明

**引理 1（占优引理）**：设两个方案都处理完了前 $i+1$ 个元素、都用掉恰好 $c$ 次替换，末元素分别为 $u$ 与 $v$ 且 $u \le v$。若末值为 $v$ 的方案能继续补完剩余位置，则末值为 $u$ 的方案也能补完，且替换次数相同。

**证明**：补完剩余位置只依赖两类判断：保留 $arr1[j]$ 需 $arr1[j] >$ 末值；替换需存在 $b$ 中元素 $>$ 末值。把末值从 $v$ 换成更小的 $u$，两个条件都只是被放宽（$arr1[j] > v \Rightarrow arr1[j] > u$；$b$ 中存在 $> v$ 的元素 $\Rightarrow$ 存在 $> u$ 的元素）。故原方案的后续决策逐位照抄即可行，替换次数不变。∎

**引理 2（替换取最小值最优）**：若 $dp[c] = last$ 可达，令 $v = b[k]$ 为 $b$ 中严格大于 $last$ 的最小值，则用 $v$ 替换得到的 $ndp[c+1] \le$ 任何其它合法替换值得到的末值。

**证明**：任何合法替换值 $v' \in b$ 满足 $v' > last$，由 $v$ 的最小性有 $v \le v'$，直接由定义 $ndp[c+1] = \min(\cdot, v)$ 即得。∎

**引理 3（DP 不变量）**：处理完前 $i+1$ 个元素后，$dp[c]$ 恰为"前 $i+1$ 个元素严格递增、恰好使用 $c$ 次替换"时末元素的最小可能值（不可达记 $+\infty$）。

**证明**：对 $i$ 归纳。$i=-1$ 时只有 $dp[0]=-1$，对应空前缀，成立。设对 $i-1$ 成立，考虑第 $i$ 位：任何合法方案的末元素要么是 $arr1[i]$（该位保留），要么是某个 $b$ 中元素（该位替换）。

- 保留：由归纳假设，前 $i$ 个元素的末值最小为 $dp[c]$；方案可行 $\iff arr1[i] >$ 该末值，而由引理 1 取最小末值不损失一般性，故 $ndp[c] = \min(ndp[c], arr1[i])$ 恰覆盖所有保留型方案的最小末值。
- 替换：同理最小前驱末值为 $dp[c]$，由引理 2 只需考虑 $b[k]$，故 $ndp[c+1] = \min(ndp[c+1], b[k])$ 恰覆盖替换型方案的最小末值。

反向，每个被写入的 $ndp$ 值都由"前 $i$ 个元素的合法方案 + 一次合法保留/替换"构造出来，故不会出现凭空可达的状态。∎

**定理**：算法返回值等于最少操作数；无解时返回 $-1$。

**证明**：由引理 3，使 $arr1$ 严格递增且用 $c$ 次替换的方案存在 $\iff dp[c] \ne +\infty$。故最小操作数 $=\min\{c : dp[c] \ne +\infty\}$，正是线性扫描取到的第一个有限列。若所有列皆 $+\infty$，则任何操作数都无解，返回 $-1$ 正确。∎

## 6. 复杂度分析

- **时间**：$O(n^2 \log m)$。排序去重 $O(m \log m)$；共 $n$ 轮，第 $i$ 轮枚举 $i+1$ 个 $c$，每个 $c$ 做一次 `upper_bound`（$O(\log m)$）与两次 $O(1)$ 比较，合计 $\sum_{i}(i+1) = O(n^2)$ 次二分。$n = 2000$ 时约 $2 \times 10^6$ 次二分，C++ 在毫秒级，Python 约 $0.7$ 秒。
- **空间**：$O(n + m)$。$dp$、$ndp$ 各 $n+1$ 个整数；$b$ 占 $m$ 个。与值域无关。

## 7. 参考代码

### C++

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int makeArrayIncreasing(vector<int>& arr1, vector<int>& arr2) {
        vector<int> b = arr2;
        sort(b.begin(), b.end());
        b.erase(unique(b.begin(), b.end()), b.end());   // 去重：重复值对严格递增无用

        int n = arr1.size();
        const int INF = 2000000000;      // 必须严格大于 1e9，否则 1e9 会被误判为不可达
        vector<int> dp(n + 1, INF), ndp(n + 1, INF);
        dp[0] = -1;                      // 哨兵：尚未放置元素，小于一切候选值

        for (int i = 0; i < n; i++) {
            fill(ndp.begin(), ndp.end(), INF);          // 必须整体重置，不能原地更新
            for (int c = 0; c <= i; c++) {
                int last = dp[c];
                if (last == INF) continue;              // 该状态不可达
                if (arr1[i] > last)                     // ① 保留 arr1[i]
                    ndp[c] = min(ndp[c], arr1[i]);
                auto it = upper_bound(b.begin(), b.end(), last);   // ② 替换为最小可用值
                if (it != b.end())
                    ndp[c + 1] = min(ndp[c + 1], *it);
            }
            dp.swap(ndp);
        }

        for (int c = 0; c <= n; c++)                     // 最小的可行操作数
            if (dp[c] != INF) return c;
        return -1;
    }
};
```

### Python

```python
from bisect import bisect_right
from typing import List


class Solution:
    def makeArrayIncreasing(self, arr1: List[int], arr2: List[int]) -> int:
        b = sorted(set(arr2))                 # 去重 + 排序，供二分查找最小可用值
        n = len(arr1)
        INF = 2 * 10 ** 9                     # 必须严格大于 1e9
        dp = [INF] * (n + 1)
        dp[0] = -1                            # 哨兵：尚未放置元素

        for i, x in enumerate(arr1):
            ndp = [INF] * (n + 1)             # 每层重置，滚动更新
            for c in range(i + 1):
                last = dp[c]
                if last == INF:
                    continue                  # 该状态不可达
                if x > last and x < ndp[c]:   # ① 保留 arr1[i]
                    ndp[c] = x
                k = bisect_right(b, last)     # ② 替换为 b 中 > last 的最小值
                if k < len(b) and b[k] < ndp[c + 1]:
                    ndp[c + 1] = b[k]
            dp = ndp

        for c in range(n + 1):                # 最小的可行操作数
            if dp[c] != INF:
                return c
        return -1
```

## 8. 边界情况与易错点

1. **`INF` 取 $10^9$ 会被合法值击穿**：`arr1 = [1000000000]` 的正确输出是 $0$，但若 `INF = 1e9`，末值 $10^9$ 与 `INF` 相等，会被当作不可达而错误返回 $-1$。这是本题最隐蔽的坑。
2. **数组已严格递增**：答案为 $0$，代码应自然得到（$dp[0]$ 一路有限），无需特判。
3. **单个元素**：$n = 1$ 时答案恒为 $0$（空约束天然满足），哨兵 $-1$ 保证第一位不会被判定失败。
4. **无解**：如示例 3，所有列在某一层之后全变 $+\infty$，最后扫描失败返回 $-1$；不要忘记这个分支。
5. **严格 vs 非严格**：判定必须写 `>` 而不是 `>=`。`arr1 = [2,2]`、`arr2 = [2]` 的正确输出是 $-1$（换成 $2$ 仍相等，换成别的又无从可选）；按非严格递增处理会错答 $0$。
6. **原地更新**：若直接在 $dp$ 上写 `dp[c+1] = min(dp[c+1], b[k])`，同一位元素会被重复替换，$c$ 与实际操作数脱节，答案偏小。
7. **替换成相同值不必特判**：`arr2` 中可能出现与 `arr1[i]` 相等的值，"替换成同一个值"是合法但多记一次操作的选择；DP 把它记在 $dp[c+1]$ 这一列，不会污染 $dp[c]$，因此无需专门过滤。
8. **`arr2` 全小于当前值**：`upper_bound` 越界时直接跳过替换分支，而不是写入 `INF` 之外的值（C++ 里对 `b.end()` 解引用是 UB）。

**延伸思考**：

1. **LIS 视角的等价刻画**：若保留位置集合 $P$（其余位置替换），设相邻保留位 $i < j$，则需要 $\lvert b \cap (arr1[i], arr1[j]) \rvert \ge j - i - 1$ 才能把中间空隙填满；首个保留位 $j$ 需要 $b$ 中小于 $arr1[j]$ 的元素不少于 $j$ 个；末尾同理。于是可以令 $g[j] = $ 以保留 $arr1[j]$ 结尾的最大保留数，转移 $g[j] = 1 + \max\{g[i]\}$（$i < j$、$arr1[i] < arr1[j]$ 且空隙可填），答案 $= n - \max g[j]$，用树状数组可做到 $O(n \log n \log m)$。
2. **若 `arr2` 中每个值至多使用一次**：问题变成"带容量约束的填空"，贪心不再成立（可能出现争抢），需要匹配/网络流。
3. **若要求"至多 $k$ 次操作"**：只需截断 $dp$ 的列到 $k+1$，复杂度降为 $O(nk \log m)$。
