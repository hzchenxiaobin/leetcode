# LeetCode 执行乘法运算的最大分数 题解

## 1. 题目概述

- **标题 / 题号**：执行乘法运算的最大分数（#1770，hard）
- **链接**：https://leetcode.cn/problems/maximum-score-from-performing-multiplication-operations/
- **来源**：LeetCode 第 229 场周赛 Q3
- **难度**：困难
- **标签**：数组、动态规划

**题意**：给定长度为 $n$ 的数组 `nums` 和长度为 $m$ 的数组 `multipliers`（$n \ge m$）。初始分数为 $0$，需要执行**恰好** $m$ 步操作。每一步：从 `nums` 的**开头或末尾**选一个整数 $x$，获得「当前乘子 $\times x$」的分并累加，然后把 $x$ 从 `nums` 中移除。第 $i$ 步（从 $1$ 计数）使用的乘子是 `multipliers[i]`，即 0 下标的 `mult[i-1]`。返回 $m$ 步后的**最大**总分数。

**约束**：

- $1 \le m \le 10^3$
- $m \le n \le 10^5$
- $-1000 \le \text{nums}[i], \text{multipliers}[i] \le 1000$

> 💡 **关键约束**：$m \le 10^3$ 而 $n \le 10^5$——**乘子数远小于数组长度**。操作只从两端摘除元素，`nums` 中间的大片元素从头到尾不会被触及，因此「数组还剩什么」不需要完整记录，局面只与两端各取了多少个有关。$m$ 才是状态空间的瓶颈，这决定了正确的 DP 状态设计。

## 2. 示例

**示例 1**

```text
输入：nums = [1,2,3], multipliers = [3,2,1]
输出：14
解释：三步全取末尾 → 3×3 + 2×2 + 1×1 = 9 + 4 + 1 = 14。
```

**示例 2**

```text
输入：nums = [-5,-3,-3,-2,7,1], multipliers = [-10,-5,3,4,6]
输出：102
解释：取左、左、左、右、右
      (−10)(−5) + (−5)(−3) + 3×(−3) + 4×1 + 6×7 = 50 + 15 − 9 + 4 + 42 = 102。
```

**示例 3（自造：贪心反例）**

```text
输入：nums = [-1,-2,-3], multipliers = [1,2,3]
输出：-10
解释：每步取当前乘积更大的一端：第 1 步取左（−1 > −3）、第 2 步取左（−4 > −6）、第 3 步得 −9，总分 −14；
      最优解是第 1 步先取右端 −3（眼前更差的一步），再依次取走 −2、−1：−3 − 4 − 3 = −10。
```

负数让「眼前亏」成为必经之路：小乘子先消耗绝对值大的负数，把绝对值小的留给大乘子——这种跨步权衡正是贪心做不到、DP 擅长的。

## 3. 解题思路

### 3.1 暴力思路：枚举 $2^m$ 条取法路径

每步只有「取左 / 取右」两种选择，$m$ 步共 $2^m$ 条路径。DFS 枚举每条路径、累加得分取最大：

$$\text{ans} = \max_{\text{路径}} \sum_{k=0}^{m-1} \text{mult}[k] \times x_k$$

时间 $O(2^m \cdot m)$：$m = 10^3$ 时路径数约 $10^{301}$，完全不可行。

> ⚠️ **症结**：把「取法序列」当成状态，但**不同的取法序列会到达同一个局面**。比如「先左后右」与「先右后左」两步之后，都处于「左取 1 个、右取 1 个」的局面——剩余数组与剩余乘子完全相同，只是得分不同。这正是**重叠子问题**：同一局面被不同路径反复到达，理应只算一次并取最优。

### 3.2 核心观察：操作只触及两端，状态 = (步数 k, 左取数 i)

![核心观察：两端取数后剩余区间由 (k, i) 唯一确定](images/wc229_q3_state_concept.svg)

**局面由什么唯一确定？** 设已执行 $k$ 步，其中从左端取了 $i$ 个、右端取了 $j$ 个。由于每次都从**两端**摘除：

- 已消失的元素恰是前缀 $\text{nums}[0..i-1]$ 与后缀 $\text{nums}[n-j..n-1]$；
- 剩余元素恰为连续区间 $\text{nums}[i .. n-1-j]$——**只由 $(i, j)$ 决定，与取的顺序无关**；
- 剩余乘子为 $\text{mult}[k..m-1]$，只由 $k$ 决定。

于是局面由 $(k, i, j)$ 刻画。又因为每步恰取走一个元素，$k = i + j$ 恒成立，$j = k - i$ 是冗余的——**两维 $(k, i)$ 就够了**：

$$\boxed{\ \text{dp}[k][i]：\text{已执行 } k \text{ 步、左取 } i \text{ 个时，能获得的最大累计分数}\ }$$

$i \in [0, k]$，第 $k$ 层只有 $k+1$ 个状态，全程共 $\sum_{k=0}^{m}(k+1) = O(m^2)$ 个——$m = 10^3$ 时约 $5 \times 10^5$，完全可承受。

> ⚠️ **别用区间端点做状态**：经典区间 DP 会想到 $\text{dp}[l][r]$（剩余区间左右端点），但 $l, r$ 的取值域是 $[0, n)$，状态表 $O(n^2) = 10^{10}$ 直接爆炸。究其原因，$l$ 只有 $i \in \{0..m\}$ 这 $m+1$ 种**可达取值**、$r$ 同理，多数 $(l, r)$ 组合根本不可达。用 $(k, i)$ 参数化恰好只枚举可达状态，$n$ 退化为 $O(1)$ 下标访问。

### 3.3 算法流程：按 k 滚动的一维 DP

![算法流程：外层按步数 k 滚动，内层对每个可达状态推送两个转移](images/wc229_q3_dp_flow.svg)

**状态转移**（从第 $k$ 层推向第 $k+1$ 层，乘子用 $\text{mult}[k]$，下标均为 0 起）：

- **取左端**（下一个左端元素是 $\text{nums}[i]$，左取数 $+1$）：

$$\text{dp}[k+1][i+1] \leftarrow \max\bigl(\text{dp}[k+1][i+1],\ \text{dp}[k][i] + \text{mult}[k] \times \text{nums}[i]\bigr)$$

- **取右端**（已从右取 $k-i$ 个，下一个右端元素是 $\text{nums}[n-1-(k-i)] = \text{nums}[n-1-k+i]$，左取数不变）：

$$\text{dp}[k+1][i] \leftarrow \max\bigl(\text{dp}[k+1][i],\ \text{dp}[k][i] + \text{mult}[k] \times \text{nums}[n-1-k+i]\bigr)$$

**实现要点**：

1. $\text{dp}[k]$ 只依赖 $\text{dp}[k-1]$ → **滚动数组**：`dp` 保存上一层的 $i \in [0,k]$，`ndp` 保存本层，整轮算完再整体替换；
2. 采用 **push（推送）式**转移：内层遍历 $i \in [0, k]$——这些 `dp[i]` **全部可达**，向 `ndp[i+1]` 与 `ndp[i]` 两个方向推送，天然不会读取 $-\infty$ 哨兵，避开 `INT_MIN + 负数` 的下溢陷阱；
3. **边界**：$\text{dp}[0][0] = 0$（0 步 0 分）；**答案** $= \max_{0 \le i \le m} \text{dp}[m][i]$。

### 3.4 示例演算：负数场景的 DP 三角表

以示例 2（$n=6, m=5$）为例，`dp[k][i]` 逐层演化如下（空白 = 该层不存在的状态）：

![示例演算：示例 2 的 DP 逐层演化与最优路径回溯](images/wc229_q3_walkthrough.svg)

| $k$（刚消耗的乘子） | $i=0$ | $i=1$ | $i=2$ | $i=3$ | $i=4$ | $i=5$ |
|---|---|---|---|---|---|---|
| $k=0$（—） | $0$ | | | | | |
| $k=1$（−10） | $-10$ | $50$ | | | | |
| $k=2$（−5） | $-45$ | $45$ | $65$ | | | |
| $k=3$（3） | $-51$ | $66$ | $68$ | $56$ | | |
| $k=4$（4） | $-63$ | $58$ | $96$ | $60$ | $48$ | |
| $k=5$（6） | $-81$ | $40$ | $84$ | $\mathbf{102}$ | $54$ | $90$ |

几个关键转移：

- **$k=0 \to 1$（mult = −10）**：从 $(0,0)$ 出发，取左得 $0 + (-10) \times (-5) = 50$（负负得正！），取右得 $0 + (-10) \times 1 = -10$；
- **重叠子问题现场**：$\text{dp}[2][1] = 45$ 由两条历史汇入取 max——「先右后左」$-10 + (-5) \times (-5) = 15$ 与「先左后右」$50 + (-5) \times 1 = 45$。它们在 $(k=2, i=1)$ 处合并，后续只需算一次；
- **最后一步**：$\text{dp}[5][3] = \max(96 + 6 \times (-3),\ 60 + 6 \times 7) = \max(78, 102) = 102$——把右端的 $7$ 留给最大的乘子 $6$。

**最优路径回溯**：$102 \leftarrow (4,3)=60 \leftarrow (3,3)=56 \leftarrow (2,2)=65 \leftarrow (1,1)=50 \leftarrow (0,0)$，即「左、左、左、右、右」，与示例解释完全一致。注意前三步乘子为负，**负负得正**让取左端的负数反而赚分——这是贪心难以正确处理的典型场景。

## 4. 算法细节

1. **状态参数化**：选 $(k, i)$ 而非 $(i, j)$ 或区间端点 $(l, r)$。$j = k - i$ 冗余；而 $(l, r)$ 的取值域是 $O(n^2)$，只有 $O(m^2)$ 可达（§3.2 的 ⚠️）。
2. **右端下标推导**：第 $k$ 步开始时已取 $k$ 个（左 $i$ + 右 $k-i$），右端已消失 $\text{nums}[n-1], \ldots, \text{nums}[n-(k-i)]$，故下一个右端是 $\text{nums}[n-1-(k-i)] = \text{nums}[n-1-k+i]$。**速记：左取越多，下一个右端越靠右**。特例自检：$i=0$（全取右）$\to \text{nums}[n-1-k]$，随 $k$ 从右往左收；$i=k$（全取左）$\to \text{nums}[n-1]$，始终未被触碰。
3. **push 式转移**：只遍历可达状态 $\text{dp}[0..k]$ 并向外推送，读到的永远是有限值。对比 pull 式（对每个目标格检查两个来源）需要处理 $-\infty + x$ 的下溢——C++ 中 `INT_MIN` 参与加法是未定义行为。
4. **滚动与替换时机**：`ndp` 每轮开头**整体重置**为不可达，算完一整轮才 `swap(dp, ndp)`。同一格 `ndp[i]` 会被「取右」来源写入、`ndp[i+1]` 会被「取左」来源写入，若试图就地更新同一数组，读写交织极易污染，双数组最稳。
5. **数值范围**：$|\text{得分}| \le m \cdot \max|\text{mult}| \cdot \max|\text{nums}| = 10^3 \cdot 10^3 \cdot 10^3 = 10^9 < 2^{31} - 1 \approx 2.15 \times 10^9$，`int` 恰好够用但已贴近上限，求稳可用 `long long`（Python 无此虑）。
6. **自顶向下等价性**：记忆化 DFS `dfs(k, i)` 与上述递推一一对应，状态数同为 $O(m^2)$；但 Python 默认递归上限为 $1000$，$m = 10^3$ 时递归深度贴线，需调大上限或直接写自底向上。

## 5. 正确性证明

**引理 1（剩余区间的确定性）**：执行若干步后，设从左端取了 $i$ 个、右端取了 $j$ 个（$i + j = k \le m \le n$），则剩余元素恰为区间 $\text{nums}[i .. n-1-j]$，与取数顺序无关。

**证明**：对 $k$ 归纳。$k = 0$ 时 $i = j = 0$，剩余为整个数组，结论成立。设结论对 $k$ 成立，考虑第 $k+1$ 步之前的局面：由归纳假设剩余为 $\text{nums}[i..n-1-j]$，其左端元素为 $\text{nums}[i]$、右端为 $\text{nums}[n-1-j]$。若本步取左，新计数为 $(i+1, j)$，对应剩余 $\text{nums}[i+1..n-1-j]$，恰为原剩余去掉左端；取右同理。又 $i + j \le m \le n$ 保证已取走的前缀与后缀不重叠，归纳完成。∎

**引理 2（无后效性）**：从某局面出发能获得的**后续**最大分数，只依赖于该局面的剩余区间与剩余乘子，与到达该局面的路径及历史得分无关。

**证明**：后续每一步的候选操作与得分仅由「剩余区间的两个端点元素」与「下一个乘子」决定；由引理 1，二者被 $(k, i)$ 完全确定。历史得分是与后续决策无关的常数——对任意两条后续方案，加上同一常数不改变大小关系，故后续的最优选择与历史无关。∎

**定理（转移方程与答案）**：设 $\text{dp}[k][i]$ 为已执行 $k$ 步、左取 $i$ 个的所有路径的最大累计分数（不存在路径时为 $-\infty$），则按 §3.3 两条转移递推、初始 $\text{dp}[0][0] = 0$、答案 $= \max_{0 \le i \le m} \text{dp}[m][i]$ 是正确的。

**证明**：对 $k$ 归纳，证明「$\text{dp}[k][i]$ = 到达 $(k, i)$ 的所有路径的最大分数」。

- **基例**：$k=0$ 时唯一路径为空路径，$\text{dp}[0][0] = 0$；$(0, i)$（$i > 0$）无路径到达，为 $-\infty$。
- **归纳步**：考虑到达 $(k+1, i+1)$ 的任意路径，其最后一步必为「取左」。由引理 1，该步取走的元素是 $\text{nums}[i]$、得分贡献 $\text{mult}[k] \times \text{nums}[i]$，而前缀是一条到达 $(k, i)$ 的路径。故此类路径的分数 $\le \text{dp}[k][i] + \text{mult}[k] \times \text{nums}[i]$；反之，把 $(k, i)$ 的最优前缀接上这一步即取到该值（由引理 2，前缀的历史不影响后续可行性）。对 $(k+1, i)$ 同理（最后一步取右 $\text{nums}[n-1-k+i]$）。两类候选分别对应两条转移，取 max 后恰为全部路径的最值。
- **答案**：执行完 $m$ 步后左取数 $i \in [0, m]$，且 $(m, i)$ 两维完全刻画路径集合的终点，故最大值为第 $m$ 层的最大值。∎

## 6. 复杂度分析

- **时间复杂度**：$O(m^2)$。外层 $k$ 从 $0$ 到 $m-1$，第 $k$ 轮内层 $k+1$ 个可达状态、每个 $O(1)$ 推送两个转移；总计 $\sum_{k=0}^{m-1}(k+1) = \frac{m(m+1)}{2} \approx 5 \times 10^5$ 次转移（$m = 10^3$）。
- **空间复杂度**：$O(m)$。仅 `dp` / `ndp` 两个长度 $m+1$ 的一维数组；对比完整二维表 $O(m^2)$（约 4MB）更省且缓存友好。
- **$n$ 不出现在复杂度中**：`nums` 只被 $O(1)$ 下标访问，$10^5$ 的长度无关紧要——这是本题状态设计最大的红利。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    int maximumScore(vector<int>& nums, vector<int>& multipliers) {
        int n = nums.size(), m = multipliers.size();
        vector<int> dp(m + 1, INT_MIN), ndp(m + 1, INT_MIN);
        dp[0] = 0;                                   // 0 步 0 分
        for (int k = 0; k < m; ++k) {
            fill(ndp.begin(), ndp.end(), INT_MIN);   // 每轮重置为不可达
            for (int i = 0; i <= k; ++i) {           // dp[0..k] 全部可达
                int cur = dp[i];
                ndp[i + 1] = max(ndp[i + 1], cur + multipliers[k] * nums[i]);          // 取左
                ndp[i] = max(ndp[i], cur + multipliers[k] * nums[n - 1 - k + i]);      // 取右
            }
            swap(dp, ndp);
        }
        return *max_element(dp.begin(), dp.end());
    }
};
```

### Python

```python
class Solution:
    def maximumScore(self, nums: List[int], multipliers: List[int]) -> int:
        n, m = len(nums), len(multipliers)
        dp = [float('-inf')] * (m + 1)
        dp[0] = 0
        for k in range(m):
            ndp = [float('-inf')] * (m + 1)
            for i in range(k + 1):                   # dp[0..k] 全部可达
                cur = dp[i]
                ndp[i + 1] = max(ndp[i + 1], cur + multipliers[k] * nums[i])           # 取左
                ndp[i] = max(ndp[i], cur + multipliers[k] * nums[n - 1 - k + i])       # 取右
            dp = ndp
        return max(dp)
```

## 8. 边界情况与易错点

1. **必须恰好执行 $m$ 步**：即使乘子为负、两端乘积为负，也不能「跳过」——所有 $2^m$ 条路径长度都是 $m$，DP 无需特判自然正确；但手写贪心或剪枝时容易误入「跳过更优」的歧途。
2. **右端下标写错**（最高频 WA）：正确为 $n-1-k+i$；常见错写 $n-1-i$（漏 $k$）或 $n-1-k$（漏 $i$）。用 $i=0$ / $i=k$ 两个特例自检（§4 第 2 点）。
3. **就地更新污染**：同一目标格会被不同来源写入、读写下标交织，务必 `ndp` 整轮算完后整体替换（§4 第 4 点）。
4. **$-\infty$ 参与运算**：pull 式写法若把 `INT_MIN` 直接加负数会下溢（C++ UB）。push 式只读可达状态从根源规避；若坚持 pull 式，哨兵改用 `INT_MIN / 2` 或 `long long`。
5. **`int` 上限**：最坏 $|\text{答案}| \approx 10^9$，贴着 $2^{31}-1$；若有极端构造的测试，`long long` 更稳。
6. **$m = n$ 与 $m < n$**：$m = n$ 时恰好把 `nums` 取空，可验证 $n-1-k+i \ge i$ 恒成立不越界；$m < n$ 时中间剩 $n - m$ 个元素永远不进状态，属正常现象而非漏算。
7. **贪心陷阱**：见示例 3——乘积的两个因子（乘子、端点值）都在随选择变化，局部最优无法权衡跨步影响。
8. **Python 记忆化递归深度**：$m = 10^3$ 逼近默认递归上限 $1000$，递归栈深约 $m+1$，需要 `sys.setrecursionlimit` 或改写自底向上。
