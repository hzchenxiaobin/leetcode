# LeetCode 亲密字符串 题解

## 1. 题目概述

- **标题 / 题号**：亲密字符串（#859，easy）
- **链接**：https://leetcode.cn/problems/buddy-strings/
- **来源**：LeetCode 第 90 场周赛 Q1
- **难度**：简单
- **标签**：哈希表、字符串

**题意**：给定两个字符串 `s` 与 `goal`。若能用**恰好一次**交换把 `s` 中的两个字符（下标 $i \ne j$，取 $s[i]$ 与 $s[j]$ 互换）变成 `goal`，返回 `true`，否则返回 `false`。

**约束**：

- $1 \le \text{s.length}, \text{goal.length} \le 2 \times 10^4$
- 两串均由小写英文字母组成

## 2. 示例

**示例 1**

```text
输入：s = "ab", goal = "ba"
输出：true
解释：交换 s[0] 与 s[1]，得到 "ba"，与 goal 相等。
```

**示例 2**

```text
输入：s = "ab", goal = "ab"
输出：false
解释：只能交换成 "ba"，得不到 "ab"；两个字符也不相同，无法「换个相同的」蒙混过关。
```

**示例 3**

```text
输入：s = "aa", goal = "aa"
输出：true
解释：交换两个 'a' 相当于什么也没变，恰好一次交换后仍是 "aa"。
```

**示例 4**

```text
输入：s = "abcd", goal = "badc"
输出：false
解释：失配位有 4 个（0、1、2、3），一次交换最多修好 2 个位置。
```

## 3. 解题思路

### 3.1 暴力思路

枚举所有下标对 $(i, j)$（共 $O(n^2)$ 个），逐个交换后与 `goal` 比较，复杂度 $O(n^3)$。$n = 2 \times 10^4$ 时约为 $8 \times 10^{12}$ 次字符比较，完全不可行。

即使用哈希把「比较」降到 $O(1)$，$O(n^2)$ 的枚举在 $n = 2\times 10^4$ 时也是 $4 \times 10^8$ 级别，仍然危险——而且这题根本不需要枚举，因为**一次交换能改变的位置极少**。

### 3.2 核心观察：一次交换只影响两个位置

![先把所有情形枚举干净，答案只有四类](images/wc90_q1_case_split.svg)

交换 $(i, j)$ 只改变位置 $i$ 与 $j$ 上的字符，其余位置原封不动。因此要让交换后等于 `goal`，**失配位的数量**必须先被限定住：

1. **长度不同**：交换不改变长度，直接 `false`。
2. **`s == goal`（0 个失配位）**：此时唯一可能的「一次交换」必须让字符串**保持不变**，这只有当存在某个字符出现了至少 2 次（交换这两个相同字符）时才可能。于是退化成「检查是否有重复字符」。
3. **恰好 2 个失配位 $i < j$**：一次交换恰好可以修正这两个位置，但必须**交叉相等**：$s[i] = \text{goal}[j]$ 且 $s[j] = \text{goal}[i]$。
4. **其余情况**（1 个或 ≥ 3 个失配位）：一次交换最多改变两个位置，必然无解。

![情形 ③：两个失配位必须「交叉相等」](images/wc90_q1_diff_pair.svg)

第 3 条的条件写成代码就是 $s[i] == \text{goal}[j]\ \&\&\ s[j] == \text{goal}[i]$，本质上是「$i,j$ 上的字符恰好互换」。

![情形 ②：s 与 goal 完全相同，必须存在重复字符](images/wc90_q1_same_string.svg)

第 2 条常被忽略：很多人写「`s == goal` 就返回 `true`」，但 `s = goal = "ab"` 时任何一次交换都会得到 `"ba"`，答案是 `false`。只有「存在重复字符」才能靠交换两个相同字符做到**不改变字符串**。

### 3.3 算法流程

```text
1. 若 len(s) != len(goal)：返回 false
2. diff = [i for i in 0..n-1 if s[i] != goal[i]]
3. 若 len(diff) == 2：
       i, j = diff
       return s[i] == goal[j] and s[j] == goal[i]
4. 若 len(diff) == 0：
       统计 s 中每个字母出现次数，只要有任何一个 >= 2 就返回 true，否则 false
5. 其余（len(diff) == 1 或 >= 3）：返回 false
```

### 3.4 示例演算

| 输入 | 失配位 | 判定分支 | 结果 |
|------|--------|----------|------|
| `"ab"` / `"ba"` | $\{0, 1\}$ | $s[0]=\text{goal}[1]=$ `a` ✓，$s[1]=\text{goal}[0]=$ `b` ✓ | true |
| `"ab"` / `"ab"` | $\varnothing$ | 无重复字符 | false |
| `"aa"` / `"aa"` | $\varnothing$ | `a` 出现 2 次 | true |
| `"abcd"` / `"badc"` | $\{0,1,2,3\}$ | 失配位 4 个 > 2 | false |
| `"abab"` / `"abab"` | $\varnothing$ | `a`、`b` 都出现 2 次 | true |

## 4. 算法细节

1. **先判长度**：长度不同时连失配位都没法一一对应，直接返回，避免后续越界。
2. **失配位只需要存前两个**：第 3 条分支只用 `diff[0]`、`diff[1]`，第 4 条只用「是否为 0」。所以可以只记前两个失配位，空间从 $O(n)$ 降到 $O(1)$（本文代码为可读性保留了完整的 `diff` 列表）。
3. **重复字符的判定用 26 桶**：小写字母固定 26 个，开一个长度 26 的计数数组，边扫边判 `++cnt[c] > 1` 即可提前返回。
4. **`s == goal` 也可以用「集合大小」判**：`len(set(s)) < len(s)` 等价于「存在重复字符」。Python 版用了这一写法，C++ 版用计数数组。
5. **不要用 `s.count(c) > 1` 逐个字符判**：那是 $O(26n)$，虽然也能过，但一遍扫描即可完成。
6. **下标必须不同（$i \ne j$）**：这正是情形 ② 需要「重复字符」的原因——没有重复字符就没有合法的 $i \ne j$ 组合能让字符串保持不变。

## 5. 正确性证明

**引理 1**：若 $\lvert s \rvert \neq \lvert \text{goal} \rvert$，则答案为 `false`。

**证明**：交换任意两个字符不改变字符串长度，故 `s` 的任何一次交换结果长度都是 $\lvert s \rvert$，不可能等于 `goal`。∎

**引理 2**：设失配位集合 $D = \{i : s[i] \neq \text{goal}[i]\}$，$\lvert D \rvert = 2$，$D = \{i, j\}$。则存在一次交换使 `s` 变成 `goal` $\iff$ $s[i] = \text{goal}[j]$ 且 $s[j] = \text{goal}[i]$。

**证明**：

（$\Leftarrow$）交换 $i$、$j$ 后，位置 $i$ 上是原 $s[j] = \text{goal}[i]$，位置 $j$ 上是原 $s[i] = \text{goal}[j]$，其余位置本来就与 `goal` 相同且未被改动，故结果恰为 `goal`。

（$\Rightarrow$）设交换 $(a, b)$ 后得到 `goal`。因为交换只改动 $a, b$ 两个位置，而 $D$ 之外的位置必须保持正确，所以 $D \subseteq \{a, b\}$；又 $\lvert D \rvert = 2$，故 $\{a, b\} = \{i, j\}$。交换后位置 $i$ 上的字符是原 $s[j]$，必须等于 $\text{goal}[i]$，即 $s[j] = \text{goal}[i]$；同理 $s[i] = \text{goal}[j]$。∎

**引理 3**：若 $s = \text{goal}$，则存在一次交换使 `s` 保持不变 $\iff$ `s` 中存在某个字符出现至少 2 次。

**证明**：

（$\Leftarrow$）设字符 $c$ 在位置 $p \ne q$ 都出现，交换 $(p, q)$ 后两处仍是 $c$，字符串不变，等于 `goal`。

（$\Rightarrow$）设交换 $(i, j)$（$i \ne j$）后字符串不变。位置 $i$ 上的字符由 $s[i]$ 变成 $s[j]$，不变意味着 $s[i] = s[j]$，即该字符出现了至少 2 次。∎

**引理 4**：若 $\lvert D \rvert = 1$ 或 $\lvert D \rvert \ge 3$，则答案为 `false`。

**证明**：

- $\lvert D \rvert \ge 3$：一次交换只改变两个位置，交换后与 `goal` 相同的位置数最多增加 2，故失配位数至少还有 $\lvert D \rvert - 2 \ge 1$，不可能变成 0。
- $\lvert D \rvert = 1$：设唯一的失配位是 $i$。`s` 与 `goal` 只在 $i$ 处不同，说明两个字符串的字符多重集不同（其余位置逐一对应相同），而交换不改变字符多重集，故永远无法相等。∎

**定理**：算法返回值等于题目所求的布尔答案。

**证明**：算法按 $\lvert D \rvert$ 的取值分支，四类情形互斥且覆盖全部可能：

- $\lvert s \rvert \ne \lvert \text{goal} \rvert$：由引理 1 返回 `false` 正确；
- $\lvert D \rvert = 2$：由引理 2，返回「交叉相等」的判定正确；
- $\lvert D \rvert = 0$：由引理 3，返回「存在重复字符」的判定正确；
- $\lvert D \rvert = 1$ 或 $\ge 3$：由引理 4 返回 `false` 正确。

故算法在每一类输入上输出的都是正确答案。∎

## 6. 复杂度分析

- **时间**：$O(n)$。一次线性扫描收集失配位；`s == goal` 分支再做一次线性扫描统计字符（C++ 一遍即可完成，Python 的 `set(count)` 也是 $O(n)$）。
- **空间**：$O(n)$（本文代码保存了完整失配位列表）。若只保留前两个失配位，可降到 $O(1)$；C++ 的 26 桶计数是 $O(1)$，Python 的 `set(s)` 最坏 $O(\min(n, 26)) = O(1)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    bool buddyStrings(string s, string goal) {
        if (s.size() != goal.size()) return false;
        vector<int> diff;
        for (int i = 0; i < (int)s.size(); i++) {
            if (s[i] != goal[i]) diff.push_back(i);
        }
        if ((int)diff.size() == 2) {
            int i = diff[0], j = diff[1];
            return s[i] == goal[j] && s[j] == goal[i];
        }
        if (diff.empty()) {
            vector<int> cnt(26, 0);
            for (char c : s) {
                if (++cnt[c - 'a'] > 1) return true;
            }
            return false;
        }
        return false;
    }
};
```

### Python

```python
class Solution:
    def buddyStrings(self, s: str, goal: str) -> bool:
        if len(s) != len(goal):
            return False
        diff = [i for i in range(len(s)) if s[i] != goal[i]]
        if len(diff) == 2:
            i, j = diff
            return s[i] == goal[j] and s[j] == goal[i]
        if len(diff) == 0:
            return len(set(s)) < len(s)
        return False
```

## 8. 边界情况与易错点

1. **`s == goal` 不能直接返回 `true`**：`"ab"` / `"ab"` 必须返回 `false`。这是本题最大的坑，只有存在重复字符时才是 `true`。
2. **长度不同先排除**：`s = "ab"`, `goal = "abc"`，若不先判长度，失配位遍历会越界或漏判。
3. **失配位数必须是 0 或 2**：1 个失配位意味着两串字符多重集不同（永远不可能相等），≥ 3 个则一次交换修不好，都返回 `false`。
4. **交叉相等而非「相同」**：写法是 `s[i] == goal[j] && s[j] == goal[i]`，只写 `s[i] == goal[i] || s[j] == goal[j]` 是错的（那是没失配的情况）。
5. **重复字符的情形只属于 `s == goal`**：若 `s != goal` 但存在重复字符，仍然必须按失配位判定，不能因为「有重复」就返回 `true`。
6. **下标必须不同**：交换两个不同位置的字符，题目不允许原地交换同一个位置，这也是情形 ② 存在和不存在重复字符的分水岭。
7. **`n = 1`**：若两串相等（都为同一字符）→ 没有重复字符 → `false`（无法选出 $i \ne j$）；若不等 → 长度相同但字符不同 → 失配位 1 个 → `false`。两种情况都正确。

**延伸思考**：若把「恰好一次交换」放宽成「至多一次交换」，那么 `s == goal` 时答案恒为 `true`（不交换即可），其余分支不变。若放宽成「恰好 $k$ 次交换」，问题会与字符串的置换环结构挂钩：设把 `s` 变成 `goal` 所需的置换有 $n - c$ 个逆序（$c$ 为环数），则最少交换次数是 $n - c$，而「恰好 $k$ 次」还需要考虑 $k$ 与 $n - c$ 的奇偶性与剩余可交换对数。若允许交换的是**任意两个位置上的相同字符**之外的字符对，则判定会退化成「多重集 + 失配位配对」的组合问题。
