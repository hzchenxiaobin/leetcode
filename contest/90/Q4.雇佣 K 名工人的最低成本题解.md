# LeetCode 雇佣 K 名工人的最低成本 题解

## 1. 题目概述

- **标题 / 题号**：雇佣 K 名工人的最低成本（#857，hard）
- **链接**：https://leetcode.cn/problems/minimum-cost-to-hire-k-workers/
- **来源**：LeetCode 第 90 场周赛 Q4
- **难度**：困难
- **标签**：贪心、数组、排序、堆（优先队列）

**题意**：有 $n$ 名工人，第 $i$ 人的**工作质量**为 `quality[i]`，**最低期望工资**为 `wage[i]`。要雇佣恰好 $k$ 人组成一个「工资组」，并按如下规则发薪：

1. 组内每人按自己的**工作质量**等比例拿钱（即存在统一的「单价」$r$，第 $i$ 人拿 $r \cdot \text{quality}[i]$）；
2. 每人拿到的钱不低于他的最低期望工资。

求组成满足条件的小组所需的**最小总金额**（与标准答案误差 $10^{-5}$ 以内视为正确）。

**约束**：

- $n = \text{quality.length} = \text{wage.length}$，$1 \le k \le n \le 10^4$
- $1 \le \text{quality}[i], \text{wage}[i] \le 10^4$

## 2. 示例

**示例 1**

```text
输入：quality = [10,20,5], wage = [70,50,30], k = 2
输出：105.00000
解释：雇佣 0 号（q=10）与 2 号（q=5），单价取 70/10 = 7，
     两人分别拿 70 与 35，合计 105。这正是 0 号的最低期望，
     所以不能再便宜。
```

**示例 2**

```text
输入：quality = [3,1,10,10,1], wage = [4,8,2,2,7], k = 3
输出：30.66667
解释：雇佣 0、2、3 号，单价取 4/3 ≈ 1.3333，
     三人分别拿 4、13.33333、13.33333，合计 30.66667。
```

## 3. 解题思路

### 3.1 暴力思路

最直接的做法是枚举所有 $\binom{n}{k}$ 个大小为 $k$ 的子集：对每个子集算出所需的最小总金额，取最小值。

$n = 10^4$、$k = n/2$ 时子集数量是天文数字（$\binom{10^4}{5000}$），完全不可行。即使 $k = 2$ 也有 $5 \times 10^7$ 个子集，已经超时。

所以要换思路：能不能**按某个一维关键字排序**，把「子集枚举」降成「扫描 + 维护最优的 $k$ 个」？

### 3.2 核心观察：单价由「组内最高比率」决定

![按 w / q 升序排序，逐个把当前工人当成「组内最高单价」](images/wc90_q4_ratio_order.svg)

**第一步：把「按质量比例支付」写成公式。** 设组内统一单价为 $r$，则第 $i$ 人拿 $r \cdot q_i$。约束是

$$r \cdot q_i \ge w_i \quad\Longleftrightarrow\quad r \ge \frac{w_i}{q_i} \qquad (\forall i \in S).$$

总成本为 $r \sum_{i \in S} q_i$，关于 $r$ 单调递增，所以最优取

$$r = R(S) := \max_{i \in S} \frac{w_i}{q_i}, \qquad \text{成本}(S) = R(S) \cdot \sum_{i \in S} q_i.$$

**第二步：$R(S)$ 一定等于组内某个人的比率。** 于是可以**枚举这个「瓶颈工人」**：把所有人按 $w_i / q_i$ 升序排序，依次假设当前工人就是组内比率最大者。

**第三步：固定比率后，只需挑 quality 最小的 $k$ 人。** 当瓶颈是第 $i$ 人（比率 $r_i$）时，组内其他人必须来自「比率 $\le r_i$」的已扫描工人；在这个集合里，总成本 $= r_i \sum q$ 只与质量之和有关，所以挑 **quality 最小的 $k$ 人** 最省。

这样问题变成：**动态维护「已扫描工人中 quality 最小的 $k$ 个」，并求它们之和** —— 一个 $k$ 大小的大顶堆即可完成。

![大顶堆维护「已扫描工人中最小的 k 个 quality」](images/wc90_q4_heap_flow.svg)

### 3.3 算法流程

```text
1. 用交叉相乘把工人按 wage[i] / quality[i] 升序排序（避免浮点比较）
2. 大顶堆 heap（存 quality）、sumQ = 0、ans = +∞
3. for i in 排序后的工人下标：
       heap.push(quality[i]);  sumQ += quality[i]
       若 heap.size > k：
            sumQ -= heap.top();  heap.pop()      // 弹掉最大的 quality
       若 heap.size == k：
            ans = min(ans, sumQ * wage[i] / quality[i])
4. 返回 ans
```

注意第 4 步用的是**当前工人** `i` 的比率 $w_i/q_i$，而不是堆内最大值 —— 但由排序保证，堆内所有人的比率都 $\le r_i$，所以按 $r_i$ 支付是合法的（可能略贵于最优，但会被后续更合适的瓶颈覆盖）。

### 3.4 示例演算

![示例 1 演算：quality = [10,20,5]、wage = [70,50,30]、k = 2](images/wc90_q4_walkthrough.svg)

`k = 2`，三人的比率分别是 $70/10 = 7$、$50/20 = 2.5$、$30/5 = 6$，升序排序为 **1 号(2.5) → 2 号(6) → 0 号(7)**：

| 工人 | $w/q$ | quality | 堆与 $\sum q$ | 本轮成本 | 当前最优 |
|------|-------|---------|----------------|----------|----------|
| 1 号 | 2.5 | 20 | $\{20\}$，和 20 | 不足 $k=2$ 人 | — |
| 2 号 | 6.0 | 5 | $\{20, 5\}$，和 25 | $25 \times 6 = 150$ | 150 |
| 0 号 | 7.0 | 10 | 入堆后 35，弹掉最大 20 → $\{10, 5\}$，和 15 | $15 \times 7 = 105$ | **105** |

答案是 105，与示例一致。可见「加入质量更小的人、踢掉质量最大的人」能让总质量骤降，从而用更高的单价换到更低的总价。

## 4. 算法细节

1. **排序必须用交叉相乘**：比较 $\frac{w_a}{q_a} < \frac{w_b}{q_b}$ 时写成 `wage[a] * quality[b] < wage[b] * quality[a]`，全整数、无精度问题。乘积上界 $10^4 \times 10^4 = 10^8$，`int` 都够，但仍建议 `long long`。
2. **堆里存 quality，且是大顶堆**：要维护「最小的 $k$ 个」，用大顶堆把**最大**的顶出去。C++ 的 `priority_queue<int>` 默认就是大顶堆；Python 的 `heapq` 是小顶堆，所以存 `-quality`。
3. **`sumQ` 同步维护**：`push` 时加、弹出时减，避免每次重新求和（那会多一个 $O(k)$ 的因子）。
4. **只在 `size == k` 时结算**：人不够时无法组队，不能产生候选。
5. **结算用的比率**：用当前工人的 `wage[i] / quality[i]`。由排序，堆内所有人的比率都 $\le$ 它，因此按它支付一定满足所有人的最低期望（合法），并且这正是「以 $i$ 为瓶颈」时能取到的最低单价。
6. **`ans` 的初值用足够大的浮点数**（如 `1e18`），因为 $k \le n$ 时至少会结算一次，`ans` 必被赋值。
7. **精度**：答案要求误差 $10^{-5}$，用 `double` 完全够；`sumQ` 最大 $10^8$、比率最大 $10^4$，乘积 $10^{12}$ 仍在 `double` 的精确整数范围（$2^{53} \approx 9 \times 10^{15}$）内。
8. **Python 的比较器排序**：用 `functools.cmp_to_key` 显式写交叉相乘比较，避免 `wage[i] / quality[i]` 的浮点键在大数据下产生细微的顺序错误（虽然本题值域小、影响概率极低，但写成整数比较是更好的习惯）。

## 5. 正确性证明

**引理 1（固定组的最优单价）**：给定大小为 $k$ 的组 $S$，满足条件的最小总成本为

$$\text{cost}(S) = \Big(\max_{i \in S} \frac{w_i}{q_i}\Big) \cdot \sum_{i \in S} q_i.$$

**证明**：设统一单价为 $r$，则第 $i$ 人拿 $p_i = r q_i$。条件「每人至少拿到最低期望」即 $r q_i \ge w_i \Leftrightarrow r \ge w_i/q_i$ 对一切 $i \in S$ 成立，等价于 $r \ge R := \max_i w_i/q_i$。总成本 $\sum p_i = r \sum q_i$ 是 $r$ 的严格增函数（$q_i \ge 1$），故在 $r = R$ 处取得最小值，即 $\text{cost}(S) = R \sum q_i$。∎

**引理 2（瓶颈枚举的完备性）**：设按 $w/q$ 升序处理后，扫描到第 $i$ 个工人时的候选值为 $c_i = r_i \cdot Q_i$，其中 $r_i = w_i / q_i$，$Q_i$ 为「已扫描工人（比率 $\le r_i$）中 quality 最小的 $k$ 个之和」（不足 $k$ 人时不计）。则

$$\min_i c_i \le \text{OPT},$$

其中 $\text{OPT}$ 为全局最优成本。

**证明**：设最优组为 $S^{*}$，其比率为 $R^{*} = \max_{i \in S^{*}} w_i/q_i$（由引理 1）。取 $S^{*}$ 中比率为 $R^{*}$ 的某个工人 $i^{*}$（排序中该比率的最后一个出现者即可）。

扫描到 $i^{*}$ 时，所有 $S^{*}$ 的成员都已被扫描（它们的比率都 $\le R^{*} = r_{i^{*}}$），且 $S^{*}$ 恰好 $k$ 个，故已扫描人数 $\ge k$，$Q_{i^{*}}$ 有定义，且

$$Q_{i^{*}} = \min\{\textstyle\sum_{j \in T} q_j : |T| = k,\ T \subseteq \{\text{已扫描}\}\} \le \sum_{j \in S^{*}} q_j.$$

于是

$$c_{i^{*}} = r_{i^{*}} Q_{i^{*}} = R^{*} Q_{i^{*}} \le R^{*} \sum_{j \in S^{*}} q_j = \text{cost}(S^{*}) = \text{OPT}.$$

故 $\min_i c_i \le c_{i^{*}} \le \text{OPT}$。∎

**引理 3（候选值可行）**：每个候选值 $c_i$ 都对应一个满足全部条件的工资组，因此 $c_i \ge \text{OPT}$。

**证明**：候选 $c_i$ 对应的组是「已扫描工人中 quality 最小的 $k$ 个」，记为 $T_i$。由于已扫描意味着 $w_j / q_j \le r_i$ 对一切 $j \in T_i$ 成立，取单价 $r_i$ 支付时每人拿 $r_i q_j \ge w_j$，满足最低期望；同时组内单价统一为 $r_i$，自动满足「按质量等比例」的要求。故 $T_i$ 是合法工资组，其成本 $c_i = r_i \sum_{j \in T_i} q_j$ 不小于最优值 $\text{OPT}$。∎

**引理 4（堆的不变式）**：扫描到第 $i$ 个工人并完成「push + 必要时 pop」之后，堆中保存的恰是「已扫描工人中 quality 最小的 $\min(k, \text{已扫描人数})$ 个」，且 `sumQ` 等于它们的和。

**证明**：对扫描进度归纳。设处理完第 $i-1$ 个工人后不变式成立。

加入第 $i$ 个工人后堆大小变为 $s+1$（$s = \min(k, i-1)$）。若 $s + 1 \le k$，则这 $s+1$ 个正是已扫描全部工人的 quality，仍是最小的 $s+1$ 个。若 $s + 1 = k + 1$，则集合中有 $k+1$ 个元素，弹出其中最大者后剩下 $k$ 个元素恰为「最小的 $k$ 个」（标准结论：从 $k+1$ 个元素中删除最大值即得最小的 $k$ 个）。`sumQ` 在 push 时加、pop 时减，故始终等于堆内元素之和。∎

**定理**：算法返回的 `ans` 等于所求的最小总金额 $\text{OPT}$。

**证明**：

- 由引理 4，每次结算时堆内确实是「已扫描工人中 quality 最小的 $k$ 个」，`sumQ` 是它们的质量之和；由引理 3，每个候选值都是某个合法工资组的成本，故 `ans` 是若干个合法方案成本的最小值，$\text{ans} \ge \text{OPT}$。
- 由引理 2，$\min_i c_i \le \text{OPT}$，而 `ans` 正是所有 $c_i$ 的最小值，故 $\text{ans} \le \text{OPT}$。

两者合并得 $\text{ans} = \text{OPT}$。∎

## 6. 复杂度分析

- **时间**：$O(n \log n)$。排序 $O(n \log n)$；随后扫描 $n$ 个工人，每人至多一次入堆（$O(\log k)$）和一次出堆（$O(\log k)$），合计 $O(n \log k) \le O(n \log n)$。
- **空间**：$O(n)$。堆最多存 $k$ 个元素（$O(k)$），排序用的下标数组 $O(n)$。

## 7. 参考代码

### C++

```cpp
class Solution {
public:
    double mincostToHireWorkers(vector<int>& quality, vector<int>& wage, int k) {
        int n = (int)quality.size();
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        sort(order.begin(), order.end(), [&](int a, int b) {
            return (long long)wage[a] * quality[b] < (long long)wage[b] * quality[a];
        });

        priority_queue<int> heap;
        long long sumQ = 0;
        double ans = 1e18;
        for (int i : order) {
            heap.push(quality[i]);
            sumQ += quality[i];
            if ((int)heap.size() > k) {
                sumQ -= heap.top();
                heap.pop();
            }
            if ((int)heap.size() == k) {
                ans = min(ans, sumQ * (double)wage[i] / quality[i]);
            }
        }
        return ans;
    }
};
```

### Python

```python
from functools import cmp_to_key
import heapq


class Solution:
    def mincostToHireWorkers(self, quality: list[int], wage: list[int], k: int) -> float:
        n = len(quality)

        def cmp(i: int, j: int) -> int:
            left, right = wage[i] * quality[j], wage[j] * quality[i]
            return -1 if left < right else (1 if left > right else 0)

        order = sorted(range(n), key=cmp_to_key(cmp))
        heap = []
        sum_q = 0
        ans = float('inf')
        for i in order:
            heapq.heappush(heap, -quality[i])
            sum_q += quality[i]
            if len(heap) > k:
                sum_q += heapq.heappop(heap)
            if len(heap) == k:
                ans = min(ans, sum_q * wage[i] / quality[i])
        return ans
```

## 8. 边界情况与易错点

1. **$k = 1$**：只能雇一个人，单价取其 $w_i/q_i$，总成本就是 $w_i$，答案应为 `min(wage)`。算法在第一个（比率最小的）工人处就会结算，得到最小的比率乘以它自己的质量，但要注意：最小的比率不一定是「最小的工资」—— 由于 $k=1$ 时成本 $= r_i q_i = w_i$，扫描全部工人取最小值，最终仍是 `min(wage)`，正确。
2. **相等比率**：排序时比率为相等的人顺序任意，但由引理 2 的证明，取「该比率的最后一个出现者」总能覆盖最优组，故顺序不影响正确性。
3. **`sumQ` 用 `long long`**：$k$ 可达 $10^4$、`quality` 可达 $10^4$，和最大 $10^8$；虽然 `int` 勉强装得下，但 `sumQ * ratio` 会放大到 $10^{12}$ 量级，务必用 `long long` / `double` 承接。
4. **`ans` 初值**：用 `1e18` 或 `float('inf')`；`0` 会让 `min` 永远返回 0。
5. **结算时机**：必须 `size == k` 才结算，`size < k` 时组不成工资组；`size > k` 的瞬间就要弹出，否则堆里会留下多于 $k$ 个元素、`sumQ` 也偏大。
6. **不要用「堆内最大比率」**：有人会误以为结算时该用堆内最大的 $w/q$。其实堆里存的是 quality，没有比率信息；而按排序，用当前工人的 $r_i$ 就是该组的可行最高单价。
7. **浮点误差**：答案与标准值允许 $10^{-5}$ 的误差；`double` 计算 $10^8 \times 10^4$ 级别的值相对误差约 $10^{-16}$，远小于容差。不要用 `float`。
8. **质疑「为什么不选 quality 最小的 $k-1$ 个人 + 自己」**：算法并不强制包含自己（自己可能被弹出），这没关系 —— 引理 2 只要求「存在某个瓶颈工人使候选不超过最优」，而被弹出的情形同样被覆盖。
